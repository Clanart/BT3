### Title
DataLayer SSRF via unauthenticated on-chain mirror URLs fetched automatically during subscription sync - (File: chia/data_layer/data_layer.py)

### Summary
Chia's DataLayer subscription/mirror system lets any wallet publish "mirror" coins that advertise arbitrary URLs for any store's `launcher_id`. These mirror URLs are pulled unconditionally into a node's local subscription table and then fetched server-side over plain HTTP with no validation of the target host, mirroring the Lemmy og:image SSRF pattern: a security-sensitive fetch target is taken from attacker-controlled, permissionless data and used directly as an outbound request URL.

### Finding Description
The mirror coin puzzle used to publish mirror URLs is a fixed, unauthenticated puzzle: [1](#0-0) 

`get_mirror_info()` extracts the target `launcher_id` and URL list purely from the `CREATE_COIN` memo of any coin spend into that puzzle hash — there is no check that the spender owns, controls, or is otherwise authorized to publish mirrors for that `launcher_id`: [2](#0-1) 

`DataLayerWallet.create_new_mirror()` simply creates a coin with this puzzle and arbitrary memo content (`launcher_id`, URLs) for any fee-paying wallet — no ownership gate: [3](#0-2) 

Any node's DataLayer service periodically resyncs subscriptions by pulling mirror URLs for a subscribed `store_id` from the wallet and inserting them as trusted subscription servers, without validating the URLs at all: [4](#0-3) [5](#0-4) 

`update_subscription()` runs this sync step and then immediately calls `fetch_and_validate()`, which randomly selects one of these attacker-suppliable servers and issues an outbound HTTP GET: [6](#0-5) [7](#0-6) 

The actual fetch is performed by `http_download()`, which issues an unrestricted `aiohttp` GET to `server_info.url + "/" + filename` with no allowlist/denylist for internal or loopback/link-local addresses: [8](#0-7) 

This mirrors the Lemmy bug class exactly: the top-level, explicitly user-managed action (`subscribe` to a `store_id`, `chia data subscribe`) is a deliberate, presumably-trusted operation, but the actual outbound fetch target is silently substituted with second-hop data (mirror URLs) sourced from unauthenticated, permissionless on-chain content that any party can forge for any `launcher_id`.

### Impact Explanation
Any user can pay a fee to create a mirror coin advertising a `launcher_id` belonging to any public/well-known DataLayer store together with an internal-network URL (e.g. `http://127.0.0.1:<port>/`, cloud metadata endpoints, or other internal-only services reachable from the victim's DataLayer host). Any other node that subscribes to that store (a normal, expected DataLayer client action) will automatically, without further user interaction, perform outbound HTTP requests to that internal target during its periodic `update_subscription()` cycle. This is a server-side request forgery that can be used to probe/exfiltrate data from internal-only services reachable from the DataLayer host, matching the CWE-918 class and the Medium severity of the referenced advisory.

### Likelihood Explanation
Likelihood is moderate-to-high: creating a mirror coin only requires spending a small amount of XCH plus a fee and is fully permissionless (no relationship to the actual store owner is checked). Any node that subscribes to a public/shared store — an intentional and common DataLayer workflow — will pull in these attacker-controlled URLs during its normal periodic sync loop (`periodically_manage_data` → `update_subscription`), with no additional user action or privilege required beyond having subscribed to the store.

### Recommendation
- Validate/allowlist mirror URLs at the point they are consumed for HTTP fetches in `download_data.py`'s `http_download()`/`download_file()` (and the plugin `/download` path), rejecting loopback, link-local, and private/internal address ranges by default, similar to `enforce_https`/hostname checks already used for pool URLs in `chia/farmer/farmer.py`.
- Consider requiring mirror coins to be created/authorized by (or otherwise cryptographically tied to) the actual DataLayer store owner rather than accepting arbitrary third-party mirror memos for any `launcher_id`.
- Add configuration to require operator opt-in/allowlisting of mirror hosts before they're inserted into `subscriptions` via `update_subscriptions_from_wallet()`.

### Proof of Concept
1. Attacker wallet spends into `create_mirror_puzzle()` (`P2_PARENT.curry(1)`), setting memo `[victim_launcher_id, "http://127.0.0.1:<internal-port>"]` via `DLNewMirror`/`create_new_mirror`, as any unprivileged wallet user (`chia data add_mirror -i <victim_launcher_id> -u http://127.0.0.1:<internal-port>`).
2. A victim node that already tracks/subscribes to `victim_launcher_id` (common for public stores) runs its normal `periodically_manage_data()` loop, calling `update_subscription()`.
3. `update_subscriptions_from_wallet()` reads the forged mirror and inserts `http://127.0.0.1:<internal-port>` into the victim's local `subscriptions` table (`chia/data_layer/data_store.py:1668-1704`).
4. `fetch_and_validate()` selects this server and `insert_from_delta_file()`/`download_file()`/`http_download()` issue a GET request to `http://127.0.0.1:<internal-port>/<delta-filename>`, causing the victim's DataLayer process to make an SSRF request against its own internal network on the attacker's behalf.

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
    async def update_subscriptions_from_wallet(self, store_id: bytes32, new_urls: list[str]) -> None:
        async with self.db_wrapper.writer() as writer:
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 1 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            old_urls = [row["url"] async for row in cursor]
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 0 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            from_subscriptions_urls = {row["url"] async for row in cursor}
            additions = {url for url in new_urls if url not in old_urls}
            removals = [url for url in old_urls if url not in new_urls]
            for url in removals:
                await writer.execute(
                    "DELETE FROM subscriptions WHERE url == :url AND tree_id == :tree_id",
                    {
                        "url": url,
                        "tree_id": store_id,
                    },
                )
            for url in additions:
                if url not in from_subscriptions_urls:
                    await writer.execute(
                        "INSERT INTO subscriptions(tree_id, url, ignore_till, num_consecutive_failures, from_wallet) "
                        "VALUES (:tree_id, :url, 0, 0, 1)",
                        {
                            "tree_id": store_id,
                            "url": url,
                        },
                    )
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
