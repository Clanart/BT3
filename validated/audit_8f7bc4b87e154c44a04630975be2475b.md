Audit Report

## Title
Per-IP `TokenBucket` clones inherit a stale zero `last_update` checkpoint relative to a shared `base_time`, causing every newly-seen IP to be granted a full `max_burst` token allowance instead of the configured throttled starting allotment - ([File: net-utils/src/token_bucket.rs])

## Summary
`TokenBucket::new` sets `last_update = 0` against a freshly captured `base_time = Instant::now()` [1](#0-0) , but `Clone` copies both `base_time` and `last_update` verbatim from the prototype instead of resetting them for the new instance [2](#0-1) . `KeyedRateLimiter::consume_tokens` creates a bucket for every new/evicted key purely by cloning the never-touched `prototype_bucket` [3](#0-2) , so the very first `update_state` call on that bucket computes `elapsed = now - 0`, which, once the limiter has been alive long enough, mints far more tokens than intended and saturates the bucket to `max_tokens` via `add_tokens`'s `.min(self.max_tokens)` [4](#0-3) .

## Finding Description
`ConnectionRateLimiter::new(limit_per_minute, max_burst, num_shards)` constructs the prototype bucket with `initial_tokens = limit_per_minute` and `max_tokens = max_burst`, intending each new IP to start throttled at the sustained rate and only reach `max_burst` by accruing tokens over time [5](#0-4) . Because the prototype bucket object itself is never passed into `consume_tokens`/`current_tokens` — it is only ever `.clone()`d — its internal `last_update` atomic remains `0` for the lifetime of the limiter while `base_time` is fixed at limiter/prototype construction time. Every subsequent clone (for a brand-new key, or for a key re-created after LRU eviction in `maybe_shrink`) inherits that stale `base_time`/`last_update` pair verbatim [2](#0-1) [6](#0-5) . On the clone's first touch, `time_us()` returns a large `now` (elapsed since the long-past `base_time`), `update_state` computes `elapsed = now - last(0)`, and mints `elapsed * new_tokens_per_us` tokens, which `add_tokens` clamps to `max_tokens` [7](#0-6) . The initial-tokens seeding is thus overridden by an unintended full top-up the moment enough wall-clock time has passed since limiter startup — no race condition or attacker precision is required.

The existing test `test_keyed_rate_limiter` does not catch this because it calls `consume_tokens` immediately after limiter construction, when `elapsed` since `base_time` is only microseconds — too small to mint a full extra token batch, masking the defect [8](#0-7) .

## Impact Explanation
`ConnectionRateLimiter` gates QUIC/TPU connection admission per source IP via `register_connection`, which is invoked in `quic.rs` to reject connections when the limiter denies tokens [9](#0-8) . Once the limiter/validator has been running long enough (a realistic condition for any live validator), every newly observed attacker-controlled IP's bucket is silently pre-filled to `max_burst` instead of the intended throttled `limit_per_minute` starting allotment. An unprivileged remote attacker rotating source IPs can therefore burst connections at the higher `max_burst` ceiling on each new/re-created IP bucket, weakening a non-RPC remote resource-exhaustion defense on the QUIC/TPU ingest path — consistent with the "QUIC/TPU ... non-RPC remote exhaustion/crash" impact category. The exact corrupted value is the per-IP `TokenBucket.tokens` resource-bound counter, which is set to `max_tokens` (`max_burst`) instead of the caller-configured `initial_tokens` (`limit_per_minute`).

## Likelihood Explanation
The trigger condition is purely a function of elapsed wall-clock time since limiter/process startup and requires no privileged access, no race, and no special timing — any IP first observed after the limiter has run for roughly `(max_burst - limit_per_minute) / (limit_per_minute/60)` seconds will hit this path deterministically. This is trivially reachable by an unprivileged remote attacker sending a QUIC connection from a fresh or LRU-evicted-and-reconnecting IP against any validator that has been running past that short warm-up window, making it highly likely to occur both by natural IP churn and by deliberate attacker exploitation.

## Recommendation
When cloning a `TokenBucket` for a new key (in `KeyedRateLimiter::consume_tokens`'s `Entry::Vacant` branch) or when a bucket is recreated after LRU eviction, reset the clone's `base_time` to `Instant::now()` and its `last_update` to `0` relative to that fresh `base_time`, rather than copying the prototype's `base_time`/`last_update` fields as-is in `impl Clone for TokenBucket`. Alternatively, track `last_update` as an absolute monotonic instant per bucket instead of an offset from a shared distant `base_time`, so a newly created bucket's first `update_state` call always sees `elapsed ≈ 0`.

## Proof of Concept
1. Construct `let prototype = TokenBucket::new(60, 600, 1.0); let rl = KeyedRateLimiter::new(cap, prototype, shards);` (mirrors `ConnectionRateLimiter::new(60, 600, shards)`).
2. Sleep/advance time such that `Instant::now() - base_time` exceeds `(600 - 60) / (60.0/60.0) = 540` seconds (or use the `shuttle-test` time override to fast-forward `time_us_override` without a real sleep).
3. Call `rl.consume_tokens(new_ip, 1)` for an IP never seen before — this hits the `Entry::Vacant` branch in `KeyedRateLimiter::consume_tokens`, cloning `prototype_bucket`.
4. Immediately call `rl.current_tokens(new_ip)` and observe the bucket's token count is `600` (== `max_tokens`) rather than the expected `60` (== `initial_tokens`), confirming the checkpoint bug allows an immediate full-burst allowance instead of the throttled starting allotment.

    fn update_state(&self, now: u64) {
        // fetch last update time
        let last = self.last_update.load(Ordering::SeqCst);

        // If time has not advanced, nothing to do.
        if now <= last {
            return;
        }

        // Try to claim the interval [last, now].
        // If we can not claim it, someone else will claim [last..some other time] when they
        // touch the bucket.
        // If we can claim interval [last, now], no other thread can credit tokens for it anymore.
        // If [last, now] is too short to mint any tokens, spare time will be preserved in credit_time_us.
        match self.last_update.compare_exchange(
            last,
            now,
            Ordering::AcqRel,  // winner publishes new timestamp
            Ordering::Acquire, // loser observes updates
        ) {
            Ok(_) => {
                // This thread won the race and is responsible for minting tokens
                let elapsed = now.saturating_sub(last);

                // also add leftovers from previous conversion attempts.
                // we do not care about who uses the spare_time_us, so relaxed is ok here.
                let elapsed =
                    elapsed.saturating_add(self.credit_time_us.swap(0, Ordering::Relaxed));

                let new_tokens_f64 = elapsed as f64 * self.new_tokens_per_us;

                // amount of full tokens to be minted
                let new_tokens = new_tokens_f64.floor() as u64;

                let time_to_return = if new_tokens >= 1 {
                    // Credit tokens, saturating at max_tokens
                    self.add_tokens(new_tokens);
                    // Fractional remainder of elapsed time (not enough to mint a whole token)
                    // that will be credited to other minters
                    (new_tokens_f64.fract() / self.new_tokens_per_us) as u64
                } else {
                    // No whole tokens minted → return whole interval
                    elapsed
                };
                // Save unused elapsed time for other threads
                self.credit_time_us
                    .fetch_add(time_to_return, Ordering::Relaxed);
            }
            Err(_) => {
                // Another thread advanced last_update first → nothing we can do now.
            }
        }
    }

    #[allow(clippy::arithmetic_side_effects)]
    fn maybe_shrink(&self) {
        let mut actual_len = 0;
        let target_shard_size = self.target_capacity / self.data.shards().len();
        if target_shard_size == 0 {
            return;
        }
        let mut entries = Vec::with_capacity(target_shard_size * 2);
        for shardlock in self.data.shards() {
            let mut shard = shardlock.write();

            if shard.len() <= target_shard_size * 3 / 2 {
                actual_len += shard.len();
                continue;
            }
            entries.clear();
            entries.extend(
                shard.drain().map(|(key, value)| {
                    (key, value.get().last_update.load(Ordering::SeqCst), value)
                }),
            );

            entries.select_nth_unstable_by_key(target_shard_size, |(_, last_update, _)| {
                Reverse(*last_update)
            });

            shard.extend(
                entries
                    .drain(..)
                    .take(target_shard_size)
                    .map(|(key, _last_update, value)| (key, value)),
            );
            debug_assert!(shard.len() <= target_shard_size);
            actual_len += shard.len();
        }
        self.approx_len.store(actual_len, Ordering::Relaxed);
    }

    #[test]
    fn test_keyed_rate_limiter() {
        let prototype_bucket = TokenBucket::new(100, 100, 1000.0);
        let rl = KeyedRateLimiter::new(8, prototype_bucket, 2);
        let ip1 = IpAddr::V4(Ipv4Addr::from_bits(1234));
        let ip2 = IpAddr::V4(Ipv4Addr::from_bits(4321));
        assert_eq!(rl.current_tokens(ip1), None, "Initially no buckets exist");
        rl.consume_tokens(ip1, 50)
            .expect("Bucket is initially full");
        rl.consume_tokens(ip1, 50)
            .expect("We should still have >50 tokens left");
        rl.consume_tokens(ip1, 50)
            .expect_err("There should not be enough tokens now");
        rl.consume_tokens(ip2, 50)
            .expect("Bucket is initially full");
        rl.consume_tokens(ip2, 50)
            .expect("We should still have >50 tokens left");
        rl.consume_tokens(ip2, 50)
            .expect_err("There should not be enough tokens now");
        std::thread::sleep(Duration::from_millis(50));
        assert!(
            rl.current_tokens(ip1).unwrap() > 40,
            "We should be refilling at ~1 token per millisecond"
        );
        assert!(
            rl.current_tokens(ip1).unwrap() < 70,
            "We should be refilling at ~1 token per millisecond"
        );
        rl.consume_tokens(ip1, 40)
            .expect("Bucket should have enough for another request now");
        thread::sleep(Duration::from_millis(120));
        assert_eq!(
            rl.current_tokens(ip1),
            Some(100),
            "Bucket should not overfill"
        );
        assert_eq!(
            rl.current_tokens(ip2),
            Some(100),
            "Bucket should not overfill"
        );

        rl.consume_tokens(ip2, 100).expect("Bucket should be full");
        // go several times over the capacity of the TB to make sure old record
        // is erased no matter in which bucket it lands
        for ip in 0..64 {
            let ip = IpAddr::V4(Ipv4Addr::from_bits(ip));
            rl.consume_tokens(ip, 50).unwrap();
        }
        assert_eq!(
            rl.current_tokens(ip1),
            None,
            "Very old record should have been erased"
        );
        rl.consume_tokens(ip2, 100)
            .expect("New bucket should have been made for ip2");
    }
