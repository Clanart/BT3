Based on my research, I found a valid SSRF analog in the DataLayer mirror/subscription mechanism.

### Title
DataLayer mirror-driven SSRF via unvalidated mirror/subscription URLs triggered from on-chain coin memos - (File: `chia/data_layer/data_layer_wallet.py`, `chia/data_layer/data_layer.py`, `chia/data_layer/download_data.py`)

### Summary
Any unprivileged actor who can get a coin created with the DataLayer mirror puzzle hash on chain (via a normal spend bundle, e.g. spending their own coins with `CREATE_COIN` to `create_mirror_puzzle().get_tree_hash()` and a memo list containing an arbitrary URL) can cause every full-node/wallet/DataLayer service that tracks that `store_id` to register that URL as a "mirror server" and later issue outbound HTTP GET/POST requests to it, with no validation that the URL points to a public, non-internal endpoint.

### Finding Description
`DataLayerWallet.coin_added()` watches for coins whose puzzle hash equals `create_mirror_puzzle().get_tree_hash()` [1](#0-0) . When such a coin is seen, it calls `get_mirror_info()`, which decodes the memos attached to the `CREATE_COIN` condition of the parent spend into a `launcher_id` and a list of raw URL strings, with no scheme/host validation of any kind [2](#0-1) . These URLs are stored via `dl_store.add_mirror(...)` as long as the `launcher_id` is already tracked, regardless of who created the mirror coin [3](#0-2) .

The DataLayer service periodically calls `update_subscriptions_from_wallet()`, which pulls these mirror URLs straight from wallet RPC and stores them as `ServerInfo` entries associated with the store id, again without any validation [4](#0-3) . Later, `fetch_and_validate()` randomly selects one of these server URLs and passes it into `insert_from_delta_file()` → `download_file()` → `http_download()`, which performs a plain `aiohttp` GET request built by string-concatenating the attacker-supplied URL with a filename (`server_info.url + "/" + filename`) [5](#0-4) . There is no allow-list, no restriction on internal/loopback/link-local addresses, and no scheme restriction beyond what `aiohttp` itself does. The `get_downloader()` path similarly performs a `session.post` to plugin URLs derived from the same untrusted mirror registry [6](#0-5) .

The `.cursor/context/data-layer.md` documentation explicitly flags this as a known trust boundary: "Plugin and mirror URLs are external trust inputs. Downloaded data must continue to be verified against wallet-advertised roots..." [7](#0-6) , but that verification only protects the *content* returned; it does nothing to stop the outbound request itself from reaching an attacker-chosen internal address (e.g. cloud metadata endpoints, other localhost RPC ports, internal admin services).

### Impact Explanation
This allows an unprivileged party — anyone able to broadcast a normal spend bundle creating a coin with the mirror puzzle hash and a URL memo — to force any node/wallet that is subscribed to (or that owns/tracks) the corresponding DataLayer store to make server-side HTTP requests to attacker-chosen destinations. This can be used to probe or attack internal network services reachable from the node/wallet host (localhost RPC ports, internal metadata services, other DataLayer plugin ports), matching the SSRF bug class in the reported CVE. It does not directly cause coin-set divergence or fund theft, but it is a genuine server-side request forgery reachable purely from a submitted spend bundle/on-chain event, consistent with a Medium-severity network-reachable SSRF.

### Likelihood Explanation
Likelihood is moderate-to-high for nodes that run DataLayer with subscriptions/mirrors enabled: creating a mirror coin only requires a standard coin spend (no special permissions), and the URL is taken verbatim from spend memos without validation. The main constraint is that the victim node must be tracking/subscribed to the specific `store_id`, and DataLayer background sync must be enabled and running.

### Recommendation
Validate mirror/subscription URLs before persisting or using them for outbound requests: enforce an allow-list of schemes (e.g. `http`/`https`/`s3` only where already expected), reject URLs resolving to loopback/link-local/private IP ranges (or resolve DNS and re-check before connecting, to avoid rebinding), and consider requiring explicit user opt-in/config to trust externally-advertised mirror URLs rather than auto-registering anything seen on chain in `coin_added()` / `update_subscriptions_from_wallet()`.

### Proof of Concept
1. Attacker crafts and broadcasts a standard spend bundle that spends any of their own coins with a `CREATE_COIN` condition to puzzle hash `create_mirror_puzzle().get_tree_hash()`, including memos `[launcher_id, b"http://169.254.169.254/latest/meta-data/"]` (or any internal target URL), where `launcher_id` is the store id of a store the victim is known to track/subscribe to.
2. Once confirmed, the victim's `DataLayerWallet.coin_added()` observes the mirror coin, decodes the URL via `get_mirror_info()`, and calls `dl_store.add_mirror(...)` for the tracked `launcher_id`.
3. On the next DataLayer sync cycle, `update_subscriptions_from_wallet()` pulls this URL into the subscription's `ServerInfo` list, and `fetch_and_validate()`/`http_download()` issues an outbound HTTP GET to the attacker-controlled URL — completing the SSRF.

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
    async def get_downloader(self, store_id: bytes32, url: str) -> PluginRemote | None:
        request_json = {"store_id": store_id.hex(), "url": url}
        for d in self.downloaders:
            async with aiohttp.ClientSession() as session:
                try:
                    async with session.post(
                        d.url + "/handle_download",
                        json=request_json,
                        headers=d.headers,
                        timeout=self.client_timeout,
                    ) as response:
                        res_json = await response.json()
                        if res_json["handle_download"]:
                            return d
                except Exception as e:
                    self.log.error(f"get_downloader could not get response: {type(e).__name__}: {e}")
        return None
```
