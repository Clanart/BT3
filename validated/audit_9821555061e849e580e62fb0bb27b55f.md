### Title
Diff-header parsing in `extract_file_paths_from_diff`/`parse_diff_into_files` silently drops or truncates attacker-controlled filenames, letting malicious code changes bypass the security-guidance LLM review - (File: `plugins/security-guidance/hooks/gitutil.py`)

### Summary
`extract_file_paths_from_diff` and `parse_diff_into_files` parse raw `git diff` text with an unanchored string split and a naive regex that assumes every `diff --git a/<path> b/<path>` header is unquoted and on a line by itself. Because the diff text that feeds this parser is produced from files whose content is fully attacker/repo-controlled, both assumptions can be broken, causing genuine source changes to be dropped from (or silently reattributed away from) the set of files sent to the security LLM reviewer.

### Finding Description
Two independent parsing weaknesses exist in `extract_file_paths_from_diff` (and the structurally identical `parse_diff_into_files`): [1](#0-0) 

1. **Unquoted-header assumption / unicode filenames dropped.** `get_git_diff` builds its `git diff` command from `GIT_CMD`, which only sets `core.fsmonitor=false` and `core.hooksPath=/dev/null` — it does **not** set `core.quotePath=false` the way the sibling helpers `_git_name_only` and `_git_status_porcelain` explicitly do. [2](#0-1) [3](#0-2) 
With git's default `core.quotePath=true`, any file whose path contains non-ASCII bytes or other "unusual" characters is rendered as a quoted, octal-escaped header line, e.g. `diff --git "a/caf\303\251.py" "b/caf\303\251.py"`. The regex `^a/(.+?) b/(.+)$` never matches a line beginning with `"a/`, so `header_match` is `None` and the file is silently `continue`d past — it never enters `paths` and its diff content never reaches `parse_diff_into_files`. An attacker who creates or edits a unicode-named source file gets that entire change excluded from review with no error surfaced.

2. **Unanchored `"diff --git "` split allows header spoofing from file content.** `diff_output.split("diff --git ")` matches the literal substring anywhere in the text, not just at the start of a diff-header line. If a reviewed file's *added content* (a comment, string literal, docstring, etc.) contains the literal text `diff --git a/<x> b/<y>`, the split fires there too, cutting the real file's diff hunk into two synthetic "file" chunks. The second chunk's first line (`a/<x> b/<y>...`) is fed to the same header regex; if `<y>` doesn't resolve to a name accepted by `_is_reviewable_source` (e.g. `.txt`, or the match absorbs trailing punctuation so the extension check fails), that whole chunk — including any dangerous code lines that happen to follow the injected marker inside the same file — is dropped by `_is_reviewable_source` and never appended to `paths` or included in the diff content built by `parse_diff_into_files`. [4](#0-3) 

Both flaws are reachable purely from ordinary repository content flowing through the documented diff pipeline (`get_git_diff` → `extract_file_paths_from_diff` / `parse_diff_into_files` → `analyze_code_security`/`agentic_review`), which is exactly the "reviewable-source filtering" invariant `security_reminder_hook.py` relies on for its Stop-hook and commit/push review gates. [5](#0-4) 

### Impact Explanation
The security-guidance plugin's entire value proposition is that the Stop-hook/commit-review LLM scan sees every changed source line and forces Claude to fix flagged issues (`sys.exit(2)`). Both parsing gaps let attacker-influenced content (a unicode filename, or a crafted comment/string inside an otherwise-legitimate file) cause dangerous code to be silently excluded from that scan. This does not itself execute code, but it defeats the review/deny mechanism the plugin exists to enforce — dangerous shell/exec/auth changes can be smuggled past the LLM reviewer and Claude proceeds without the intended warning/blocking behavior, i.e. an approval/deny-control bypass for locally-executed changes.

### Likelihood Explanation
No special privilege is needed: any repo content (a file with a non-ASCII name, or a line of text resembling a diff header inside a modified file) triggers this during normal Claude Code usage, since `get_git_diff`'s output is unconditionally reparsed by these two functions on every Stop/commit/push review. The unicode-filename case requires no crafting at all — it fires for any legitimately unicode-named source file. The header-spoofing case requires the attacker to place one exact-looking line but nothing beyond ordinary file editing.

### Recommendation
- Pass `-c core.quotePath=false` (and ideally `-z`/NUL-delimited parsing, as already done in `_git_name_only`/`_git_status_porcelain`) to the `git diff` invocation used in `get_git_diff`, and update `extract_file_paths_from_diff`/`parse_diff_into_files` to handle the unquoted form robustly (or switch entirely to `git diff --name-only -z` plus `git show`/hunk extraction per path instead of text-splitting the combined diff).
- Anchor the file-boundary split to the start of a line (`re.split(r'(?m)^diff --git ', ...)` or match `^diff --git a/.+ b/.+$` with `re.MULTILINE`) so file content that merely contains the substring `diff --git ` cannot fabricate a file boundary.

### Proof of Concept
Unit test additions to a test file exercising `gitutil.extract_file_paths_from_diff` / `parse_diff_into_files`:

1. **Unicode filename dropped**: build a diff string using git's actual quoted-path format, e.g.
```
diff --git "a/caf\303\251.py" "b/caf\303\251.py"
index e69de29..4b825dc 100644
--- "a/caf\303\251.py"
+++ "b/caf\303\251.py"
@@ -0,0 +1 @@
+os.system(user_input)
```
Assert `extract_file_paths_from_diff(diff)` returns `[]` (bug) instead of `["café.py"]`, and `parse_diff_into_files(diff)` returns `[]`, i.e. `os.system(user_input)` never reaches the reviewer.

2. **Header-spoofing content**: build a diff for `real.py` where an added line is `+comment = "diff --git a/notes.txt b/notes.txt"` followed by `+dangerous_call()`:
```
diff --git a/real.py b/real.py
index e69de29..4b825dc 100644
--- a/real.py
+++ b/real.py
@@ -0,0 +1,2 @@
+comment = "diff --git a/notes.txt b/notes.txt"
+dangerous_call()
```
Assert that `parse_diff_into_files(diff)`'s returned content for `real.py` does NOT contain `dangerous_call()` (it gets misattributed to a dropped `notes.txt` chunk), demonstrating that a real, in-scope code change is excluded from the security reviewer's input.

def _is_reviewable_source(file_path):
    # Normalize for component matching: a path like `.next/x.js` or
    # `pkg/node_modules/y.ts` should both be excluded; matching against
    # `'/' + path` lets each pattern be checked as `'/' + p in '/' + path`
    # without false-positiving on `rebuild/` matching `build/`.
    norm = "/" + file_path.replace("\\", "/")
    if any(("/" + p) in norm for p in SKIP_PATH_PATTERNS):
        return False
    if file_path.endswith(SKIP_FILE_SUFFIXES):
        return False
    ext = os.path.splitext(file_path)[1].lower()
    if ext in SOURCE_CODE_EXTENSIONS:
        return True
    base = os.path.basename(file_path).lower()
    # Accept dot-suffixed variants too: `Dockerfile.dev`, `Makefile.am`,
    # `Jenkinsfile.release`. splitext gives ext='.dev'/'.am' for these so they
    # miss both the extension check and the exact-basename check otherwise.
    if base in SOURCE_CODE_BASENAMES \
            or base.split(".", 1)[0] in SOURCE_CODE_BASENAMES:
        return True
    # Extensionless files default to reviewable unless they're known
    # plain-text metadata or dotfiles. Covers shebang scripts under bin/ or
    # scripts/ (`deploy`, `run-canary`, `entrypoint`) which carry
    # shell-injection surface but were previously filtered out — the largest
    # remaining false-negative class for extensionless files. Dotfiles (`.gitignore`,
    # `.nvmrc`, `.env`) are config, not code; `.bashrc`-style runnables are
    # rare in repos and not worth the noise. The deny-list is prefix-aware on
    # `-`/`_` so dual-license / i18n variants (`LICENSE-MIT`, `README-CN`)
    # don't fall through as source.
    if ext == "" and not base.startswith("."):
        if any(base == x or base.startswith(x + "-") or base.startswith(x + "_")
               for x in NON_SOURCE_EXTENSIONLESS_BASENAMES):
            return False
        return True
    return False
```

def extract_file_paths_from_diff(diff_output):
    """
    Extract file paths from unified diff output (without content).
    Only includes files with source code extensions.
    Returns a list of file paths.
    """
    if not diff_output or not diff_output.strip():
        return []

    paths = []
    file_diffs = diff_output.split("diff --git ")

    for file_diff in file_diffs:
        if not file_diff.strip():
            continue
        lines = file_diff.split('\n')
        header_match = re.match(r'^a/(.+?) b/(.+)$', lines[0])
        if not header_match:
            continue
        file_path = header_match.group(2) or header_match.group(1) or ''
        if not _is_reviewable_source(file_path):
            continue
        paths.append(file_path)

    return paths
```
