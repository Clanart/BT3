## Analog Found: Missing Bounds Check in CLVM Canonical-Encoding Validator (`is_atom_canonical`/`is_clvm_canonical`)

### Summary
`chia/full_node/mempool_manager.py`'s `is_atom_canonical` and `is_clvm_canonical` walk an attacker-supplied CLVM byte buffer and index into it based on length-prefix bits parsed from the buffer itself, without ever checking that `offset` stays within `len(clvm_buffer)`. This mirrors the CVE-2020-0182 bug class: a length/tag byte drives further reads with no bounds validation against the buffer's actual size.

### Finding Description
`is_atom_canonical` reads `clvm_buffer[offset]` to determine how many additional length-prefix bytes (`prefix_len`, up to 5) to consume, then loops `offset += 1; atom_len |= clvm_buffer[offset]` with no check that `offset < len(clvm_buffer)` at any point: [1](#0-0) 

`is_clvm_canonical` drives this in a `while True` loop, advancing `offset` by `atom_len` or `1` per token with no per-step bound check either, relying solely on `tokens_left` reaching zero or an eventual final `offset == len(clvm_buffer)` comparison — but any out-of-range index during the loop body itself (in `is_atom_canonical` or the `clvm_buffer[offset]` read at line 199) will raise before that final check is reached: [2](#0-1) 

A crafted CLVM buffer whose final atom's length-prefix tag byte (e.g. `0b11111100`/`0b11111110`, requiring 4-5 trailing bytes) appears at or near the end of the buffer causes `clvm_buffer[offset]` to index past the buffer's end.

### Impact Explanation
In C (the original exif-entry.c bug), an out-of-bounds read like this can leak adjacent heap memory. In this Python codebase, `bytes.__getitem__` on an out-of-range index raises `IndexError` instead of reading adjacent memory — so information disclosure is not directly reproducible. However, if this uncaught `IndexError` propagates from a code path that processes attacker-submitted spend bundles or block generators without a surrounding `try/except`, it would abort that specific validation task, which could function as a spend-triggered halt of mempool/transaction processing for the affected bundle. I was not able to fully trace, within the available iterations, the exact call site(s) that feed an attacker-controlled `clvm_buffer` into `is_clvm_canonical` (grep confirmed additional references exist in `mempool_manager.py` beyond the definitions, and corresponding tests exist in `chia/_tests/core/mempool/test_mempool_manager.py`, but I could not view the specific call site and its exception handling before the iteration limit was reached).

### Likelihood Explanation
Given the two functions are defined directly in the mempool admission module and covered by dedicated tests (`test_mempool_manager.py` references `is_clvm_canonical`/`is_atom_canonical` 8 times), it is plausible this validator runs on solutions/generators arriving from submitted spend bundles — a path reachable by any unprivileged spend-bundle submitter. Without confirming whether the call site wraps this in exception handling or how the crash (if any) propagates, I cannot confidently claim a concrete "spend-triggered transaction-processing halt" impact per the validation rules.

### Recommendation
Add explicit length checks in `is_atom_canonical` (e.g., `if offset + prefix_len >= len(clvm_buffer): return ..., False` or raise a well-defined error) before indexing, and add a bound check in `is_clvm_canonical`'s main loop (`if offset >= len(clvm_buffer): return False`) so malformed/truncated buffers fail gracefully rather than raising `IndexError`. Confirm and audit all call sites of `is_clvm_canonical` to ensure `IndexError` (or any other exception from these functions) cannot escape mempool/full-node processing loops uncaught.

### Proof of Concept
Conceptually: construct a CLVM buffer ending in a byte matching the 5-byte-prefix pattern `0b11111110` (mask `0b00000001`) with fewer than 5 bytes remaining after it, e.g. `bytes([0b11111110])` alone, then call `is_clvm_canonical(buf)` — the inner loop in `is_atom_canonical` will attempt `clvm_buffer[offset]` beyond the buffer length and raise `IndexError`. I could not confirm, within the available tool budget, the exact production call path that would deliver such a buffer from a submitted spend bundle, so this should be verified against the actual caller(s) before being treated as a confirmed exploitable path.

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

```python
def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
