### Title
Reward forfeiture in `vlMGPBaseRewarder`/`mWOMSVBaseRewarder` is computed from the *current* lock/cooldown ratio instead of being checkpointed as it changes, letting users retroactively avoid forfeiting rewards they should have lost - (File: rewards/vlMGPBaseRewarder.sol)

### Summary
`vlMGPBaseRewarder` (and the structurally identical `mWOMSVBaseRewarder`) accrues rewards to a user continuously based on their `balanceOf` share of the pool [1](#0-0) , and only assesses how much of that accrued amount is "rewardable" vs "forfeited" once, at the moment `getReward`/`getRewards` is called, using whatever `vlMGP.getRewardablePercentWAD(_account)` returns *at that exact block* [2](#0-1) . This is the same root-cause pattern as H-14: a parameter that should be checkpointed incrementally as a user's state changes (there, leverage/margin; here, the locked-vs-cooldown ratio) is instead applied lazily, in full, to a balance that accrued over a long historical period during which the parameter had different values.

### Finding Description
`getRewardablePercentWAD` in `VLMGP.sol` computes the *current* fraction of a user's vlMGP that is "fully locked" vs "in cooldown/expired-unlocked", including a time-decay factor for slots that have passed their `endTime` without being finalized [3](#0-2) . `_calExpireForfeit` in `vlMGPBaseRewarder` multiplies this single, point-in-time percentage against `userRewards[_rewardToken][_account]`, the *entire* accrued-but-unclaimed reward balance, to decide how much is paid out and how much is forfeited and redistributed to other stakers via `_queueNewRewardsWithoutTransfer` [4](#0-3) .

Crucially, `balanceOf()` used for reward accrual counts the user's total staked amount in MasterMagpie regardless of lock/cooldown state [1](#0-0) , so rewards keep accruing at the full rate throughout any cooldown or post-expiry idle period. The penalty for having let a cooldown slot expire without acting (`cancelUnlock`, `unlock`, or `forceUnLock`) is only reflected in `getRewardablePercentWAD` for as long as that state persists. A user can call `cancelUnlock()` on an expired-but-unresolved slot, which zeroes `amountInCoolDown` and restores the tokens to "fully locked" status instantly [5](#0-4) , and then immediately call `getReward`. Because forfeiture is computed only from the state at call time, the entire reward balance that accrued during the (now erased) expired/idle period is paid out as if the user had been fully locked the whole time, exactly mirroring how in H-14 a trader adjusts leverage right before closing a position so the whole historical borrowing-fee accrual is billed at the newly-favorable rate instead of the rate that was actually in effect while it accrued.

### Impact Explanation
The forfeited portion of rewards is not burned — it is redistributed to the remaining honest, fully-locked stakers via `_queueNewRewardsWithoutTransfer`, which increases `rewardPerTokenStored` for everyone else [6](#0-5) . By manipulating the lock/cooldown state immediately before harvesting, a user can avoid forfeitures they should legitimately incur, directly reducing the yield that would otherwise flow to compliant long-term lockers. This is a theft of unclaimed yield that rightfully belongs to other stakers, reachable by any ordinary wallet holding vlMGP/mWomSV with no privileged role required.

### Likelihood Explanation
The exploit requires only standard, permissionless user actions available to any vlMGP/mWomSV holder: `lock`, `startUnlock`, `cancelUnlock`, and claiming rewards through `MasterMagpie`. No admin, oracle, or external-protocol dependency is needed, and the sequence can be executed in ordinary transactions at any time a user wants to harvest, making this straightforward and repeatable.

### Recommendation
Checkpoint the rewardable/forfeit split incrementally whenever a user's lock/cooldown state changes (similarly to how `rewardPerTokenPaid` is checkpointed on every interaction), rather than applying a single current-time percentage to the entire historically-accrued balance at claim time. Alternatively, snapshot `getRewardablePercentWAD` at the time reward is accrued into `userRewards` (each time `_updateFor` runs due to a lock/unlock state change) instead of only when `_sendReward` executes.

### Proof of Concept
1. Alice locks a large amount of MGP into `VLMGP`, which stakes into `MasterMagpie` and begins accruing rewards in `vlMGPBaseRewarder` per `balanceOf` [1](#0-0) .
2. Alice calls `startUnlock` for the full amount, then lets the cooldown period pass its `endTime` without calling `unlock()`. Per `getRewardablePercentWAD`, the longer she waits past `endTime`, the more the "expired" credit decays [7](#0-6) , meaning if she harvested now she would forfeit a growing share of her rewards, which is deposited into the pool for other users.
3. Instead of harvesting now, Alice calls `cancelUnlock(slotIndex)`, which zeroes `amountInCoolDown` and restores her tokens to "fully locked" state with no forfeiture-relevant history retained [5](#0-4) .
4. Alice immediately calls `getReward`, which computes `_calExpireForfeit` using the now-restored 100% "fully locked" `getRewardablePercentWAD`, so all of the reward accrued during her expired-cooldown period is paid out in full with zero forfeiture [2](#0-1) .
5. Alice repeats `startUnlock` → wait → `cancelUnlock` → `getReward` indefinitely, permanently avoiding the forfeiture mechanism that should reduce the yield diverted to other honest lockers.

    function _queueNewRewardsWithoutTransfer(uint256 _amountReward, address _rewardToken) internal
    {
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards = rewardInfo.historicalRewards + _amountReward;
        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**vlMGPDecimal) / totalStaked();
        }
        emit ForfeitRewardAdded(_amountReward, _rewardToken);
    }

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalVlmgp = fullyInLock + inCoolDown;
        if (userTotalVlmgp == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalVlmgp;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalVlmgp / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalVlmgp;
                }

            }
        }

        return percent;
    }
