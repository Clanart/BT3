### Title
Unvalidated empty aggregate Schnorr signatures verify successfully - ([File: crypto/schnorr/src/aggregate.rs])

### Summary
`SchnorrAggregate::read` accepts an aggregate containing zero `R` values, and `SchnorrAggregate::verify` accepts an empty `keys_and_challenges` list, causing the verifier to reduce to checking only `-sG == identity`. [1](#0-0) [2](#0-1) 

### Finding Description
The deserializer reads a 32-bit count and permits that count to be zero, then reads only the scalar `s`. [3](#0-2)  During verification, the implementation only rejects a length mismatch between `Rs` and `keys_and_challenges`; it does not reject the case where both lengths are zero. [4](#0-3)  With no signatures queued, the only multiexp pair is `(-s, G)`, so an attacker-supplied scalar `s = 0` makes the expression evaluate to the identity and returns `true`. [5](#0-4)  The aggregator’s own constructor path explicitly refuses to emit an empty aggregate, indicating that an empty aggregate is not a valid signature state. [6](#0-5) 

### Impact Explanation
An unprivileged party can submit serialized bytes representing an empty aggregate signature and have them accepted as valid verification for an empty statement set. [1](#0-0) [2](#0-1)  If callers interpret successful aggregate verification as proof that required signatures existed, the missing cardinality check converts an absent signature into an accepted signature. [2](#0-1) 

### Likelihood Explanation
The attacker only needs to control bytes passed to `SchnorrAggregate::read` and cause verification against an empty expected-signature list. [1](#0-0) [4](#0-3)  Exploitation depends on a caller exposing or reaching the zero-statement edge case, but no private key, valid signer participation, or malformed cryptographic encoding is required. [7](#0-6) [8](#0-7) 

### Recommendation
Reject empty aggregates in `SchnorrAggregate::verify`, `SchnorrAggregate::read`, or both, and add a regression test asserting that a serialized empty aggregate with `s = 0` fails verification even when `keys_and_challenges` is empty. [1](#0-0) [2](#0-1) 

### Proof of Concept
For a ciphersuite whose canonical scalar encoding is 32 bytes, construct the byte string:

```rust
let mut malicious = vec![0, 0, 0, 0]; // zero R values
malicious.extend(C::F::ZERO.to_repr().as_ref()); // s = 0

let aggregate = SchnorrAggregate::<C>::read(&mut malicious.as_slice()).unwrap();
assert!(aggregate.verify(b"domain-separator", &[]));
```

The four-byte count creates an empty `Rs` vector, while the zero scalar satisfies `s = 0`. [1](#0-0)  The empty verifier input passes the length check, produces only `(-0)G`, and `multiexp_vartime` returns the identity. [2](#0-1)
