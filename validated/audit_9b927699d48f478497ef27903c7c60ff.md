### Title
Unsanitized attacker-controlled URLs in DataLayer mirror coins enable blind SSRF via `fetch_and_validate()` / `http_download()` - (File: chia/data_layer/download_data.py)

### Summary
DataLayer mirror coins let any spend-bundle submitter attach arbitrary URL strings to *any* store's launcher id, with no scheme/host validation. Nodes that subscribe to that store id ingest the URLs and later have their DataLayer service issue outbound HTTP(S) requests (or plugin-relay requests) to those attacker-chosen URLs, mirroring the eyoucms `saveRemote()` blind-SSRF bug class: unsanitized user-supplied URL flows straight into a server-side outbound request.

### Finding Description
`create_mirror_puzzle()` and `get_mirror_info()` in [1](#0-0)  define a fixed, public puzzle hash (`P2_PARENT` curried with `1`). Anyone can spend their own coin(s) with a `CREATE_COIN` condition to this puzzle hash and put an arbitrary `launcher_id` plus an arbitrary list of URL byte-strings in the memos — this is a completely unauthenticated, self-funded standard-wallet spend (no permission from the store owner is required).

When any node that already tracks that `launcher_id` observes such a coin, `DataLayerWallet.coin_added()` extracts the memo-provided URLs and stores them verbatim with no validation of scheme, host, or format: [2](#0-1) 

These stored URLs later feed `DataLayer.update_subscriptions_from_wallet()`, which merges them into the subscription's server list without any filtering: [3](#0-2) 

During sync, `DataLayer.fetch_and_validate()` randomly picks one of these attacker-influenced server URLs and passes it into `insert_from_delta_file()` / `download_file()`: [4](#0-3) 

`download_file()` in turn calls `http_download()`, which performs an unauthenticated outbound `aiohttp` GET straight to `server_info.url + "/" + filename` with no scheme/host allow-list, no private-IP/loopback/link-local blocking, and no destination validation: [5](#0-4) 

If a plugin downloader is configured, the raw attacker-controlled URL is instead relayed via `session.post(downloader.url + "/download", json=request_json, ...)` where `request_json["url"]` is the untrusted mirror URL: [6](#0-5) 

This is functionally the same bug class as CVE-2021-39497: a user-supplied string that is meant to be a "resource pointer" is not sanitized before being used to make a server-side HTTP request, allowing SSRF against internal services, cloud metadata endpoints, or other hosts reachable from the DataLayer node — reachable purely by submitting a normal spend bundle that creates a mirror coin for a store id the victim node subscribes to.

### Impact Explanation
A victim node's DataLayer service can be coerced into making arbitrary outbound HTTP(S)/plugin-relay requests to attacker-chosen hosts (e.g., internal admin APIs, cloud metadata services, other local ports including the node's own RPC endpoints) merely by getting the victim to subscribe to (or already be subscribed to) a store id and then publishing a mirror coin. Depending on network placement this can expose internal services, enable port scanning, or be chained with other bugs (e.g., an RPC without authentication) for further compromise. It does not directly forge coin identity or move funds, but it is a concrete spend-triggered, unauthenticated remote request against infrastructure the operator did not intend to expose, satisfying the "coin/transaction-processing" reachability requirement via a wallet/Data-Layer client path.

### Likelihood Explanation
High likelihood of reachability: creating a mirror coin requires no special privilege — any wallet holder can spend their own coin to the fixed `create_mirror_puzzle()` puzzle hash with arbitrary memo URLs and any `launcher_id`, including ids for stores they do not own, and get it accepted into the mempool as an ordinary standard-wallet spend. The only precondition is that the target node is subscribed to (tracking) that `launcher_id`, which is common for DataLayer participants who subscribe to third-party stores for offers/proof verification. No signature over the URL content beyond the normal coin spend is required, and there is no URL/scheme/host validation anywhere in the ingestion or download path.

### Recommendation
Validate and restrict mirror URLs at ingestion (`coin_added()`/`dl_store.add_mirror`) and again before use (`http_download`, plugin `download_file`): enforce `http/https` scheme only, resolve and block loopback/link-local/private/reserved IP ranges (SSRF-safe resolution), and consider an explicit user opt-in / allow-list for mirror servers rather than trusting on-chain memo data implicitly. Apply the same validation to plugin-relay requests where the raw URL is forwarded to a plugin service.

### Proof of Concept
1. Attacker crafts a standard coin spend with a `CREATE_COIN` condition to `create_mirror_puzzle().get_tree_hash()`, amount arbitrary, memos = `[victim_store_launcher_id, b"http://169.254.169.254/latest/meta-data/", ...]` and broadcasts it as a normal spend bundle (per `create_new_mirror()`/`DLNewMirror` wire format in [7](#0-6) ).
2. Once confirmed, any node tracking that launcher id ingests the mirror via `coin_added()` with the malicious URL, unvalidated.
3. On the next sync cycle, `DataLayer.fetch_and_validate()`/`update_subscription()` may select this malicious server and `http_download()` issues a GET to `http://169.254.169.254/latest/meta-data/.../<filename>` from the victim's DataLayer process, or (if a downloader plugin is configured) POSTs the raw URL to the plugin's `/download` endpoint, causing the plugin/service to fetch it.
4. Response bodies/errors are observable indirectly via file-write success/failure and log lines (`log.debug(f"Downloading delta file {filename}...")`), providing blind-SSRF style feedback per the CVE-2021-39497 bug class.

def create_mirror_puzzle() -> Program:
    return P2_PARENT.curry(Program.to(1))


MIRROR_PUZZLE_HASH = create_mirror_puzzle().get_tree_hash()


def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
