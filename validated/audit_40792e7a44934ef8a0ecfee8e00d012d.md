### Title
SSRF: DataLayer node auto-fetches attacker-chosen URLs from on-chain mirror coins with no host/scheme restriction - ([File: chia/data_layer/data_layer.py])

### Summary
`DataLayer.fetch_and_validate()` reads mirror server URLs from `DataStore.get_available_servers_for_store()` and issues outbound HTTP requests to them via `http_download()`/`download_file()` in `chia/data_layer/download_data.py`, with the URL fully controlled by whoever creates a `mirror` coin on chain, and no validation of scheme/host/IP range before the request is made.

### Finding Description
Any wallet owner can create a "mirror" coin for a DataLayer store by calling `DataLayerWallet.create_new_mirror()`, which spends XCH to a `create_mirror_puzzle()` puzzle hash and encodes an arbitrary list of URL strings into the coin's memos: [1](#0-0) 

This does not require ownership of the target store's singleton — it is a public, unauthenticated action reachable via `chia data add_mirror` / `dl_new_mirror` RPC: [2](#0-1) [3](#0-2) 

When any peer's wallet observes this mirror coin for a launcher it is already tracking (which happens automatically for any store a user has subscribed to, including public/third-party stores), it decodes the URLs and stores them unvalidated: [4](#0-3) 

The DataLayer service then periodically calls `update_subscriptions_from_wallet()` to pull these mirror URLs into its subscription table, and `fetch_and_validate()` shuffles and iterates over them, making outbound HTTP requests via `insert_from_delta_file()` → `download_file()` → `http_download()`: [5](#0-4) [6](#0-5) [7](#0-6) 

`http_download()` performs `session.get(server_info.url + "/" + filename, ...)` with no scheme allowlist, no DNS/IP filtering (no blocking of `169.254.169.254`, loopback, or private ranges), and no authentication of the mirror. If the request errors, exception text (including response bodies via `aiohttp.ClientError`) is logged and surfaced through `fetch_and_validate`'s exception handler: [8](#0-7) 

This mirrors the reported bug class precisely: an unauthenticated/unprivileged party supplies a `url` value that is later fetched server-side by another party's process with no host restriction, and error/response content can leak back into logs reachable indirectly by the store's downstream RPC callers/log consumers.

### Impact Explanation
An unprivileged attacker (any wallet holding a small amount of XCH, or even a spend bundle spending existing self-owned coins to the mirror puzzle) can force any peer's DataLayer node that subscribes to the same store to issue outbound HTTP GET requests to attacker-chosen internal targets — including cloud metadata endpoints (`http://169.254.169.254/...`), internal RPC services, or other locally-reachable hosts on the DataLayer host's network. Depending on deployment (e.g., cloud-hosted DataLayer nodes), this can leak instance credentials or reach internal-only services, and can also be used to make many peers simultaneously request attacker infrastructure (aiding further denial-of-service or internal reconnaissance). This satisfies "Medium" severity network-reachable server-side request forgery from a coin-spend-driven, unprivileged action.

### Likelihood Explanation
Likelihood is moderate-to-high in any deployment where DataLayer nodes subscribe to publicly shared stores (the intended DataLayer use case) since mirror coins are a first-class, unauthenticated on-chain publication mechanism by design — no permission check ties mirror creation to store ownership, and URL content is never validated against SSRF-sensitive targets.

### Recommendation
Validate mirror/server URLs before performing any outbound fetch: enforce an allow-listed scheme (`http`/`https` only), reject loopback/link-local/private/metadata IP ranges (via resolving and checking the destination, not just the URL text), and consider requiring resolved-address checks at connection time (e.g. via `aiohttp` connector callback) to defend against DNS rebinding. Apply this validation both when mirrors are created/tracked into `DataStore.update_subscriptions_from_wallet()` and immediately before any `session.get()`/`session.post()` call in `chia/data_layer/download_data.py`.

### Proof of Concept
1. Attacker wallet calls `dl_new_mirror` (or `chia data add_mirror`) for a `launcher_id` that a victim node is subscribed to, setting `urls=["http://169.254.169.254/latest/meta-data/iam/security-credentials/"]` and a minimal `amount`/`fee`.
2. The transaction confirms on chain; any peer tracking that launcher (e.g., a subscriber to the public store) picks up the mirror via `DataLayerWallet.coin_added()` and persists it via `DataLayerStore.add_mirror()`.
3. On the victim's next `periodically_manage_data()` cycle, `update_subscriptions_from_wallet()` copies the attacker URL into `DataStore` subscription servers, and `fetch_and_validate()` calls `insert_from_delta_file()` → `http_download()`, causing the victim node to issue an outbound GET to the attacker-chosen internal/metadata URL.
4. Any error/response detail is written to the DataLayer node's logs, which can be exfiltrated by anyone with log or monitoring access, or observed indirectly through timing/behavioral side effects.

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
