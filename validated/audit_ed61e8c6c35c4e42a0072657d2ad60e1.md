### Title
Missing zero-value check on `GasTarget` governance parameter causes division-by-zero panic in KIP-71 base fee calculation - (File: params/kip71_config.go)

### Summary
The `Kip71GasTarget` governance parameter, which is voted on/set via the `kaiax/gov` module and consumed by `KIP71Config.NextMagmaBlockBaseFee`, has no non-zero format check, unlike its sibling `Kip71BaseFeeDenominator`. When `GasTarget` is 0, `NextMagmaBlockBaseFee` performs `big.Int.Div` by zero, which panics in Go, crashing any node that validates or produces a header past the divide.

### Finding Description
`Kip71BaseFeeDenominator`'s `FormatChecker` explicitly enforces `v != 0` [4](#0-3) , and `NextMagmaBlockBaseFee` even has a defensive runtime fallback for a zero `BaseFeeDenominator` ("To avoid panic, set the fluctuation range small") [5](#0-4) .

However, `Kip71GasTarget` uses `noopFormatChecker`, which performs no validation at all: [6](#0-5) . If governance sets `GasTarget` to 0, `parentGasUsed > gasTarget` will be true for any block with `GasUsed > 0`, and the code computes `gasUsedDelta = parentGasUsed - gasTarget`, then divides `x` by `gasTarget` (0): [7](#0-6) . `big.Int.Div` panics on division by zero in Go, so this call panics rather than reverting gracefully.

`NextMagmaBlockBaseFee` is called from `VerifyMagmaHeader`, which is invoked unconditionally for every block on a Magma-forked chain (i.e., essentially all mainnet blocks) inside `BlockValidator.validateHeader`: [3](#0-2) . It's also used in fee estimation (`feehistory.go`) and gas price suggestion paths (`gasprice.go`), and in block building (`work/worker.go`), meaning any header/block validated by any node — consensus or endpoint — would panic once `GasTarget` becomes 0.

### Impact Explanation
A panic during header validation, invoked for every incoming block header on Magma-enabled chains, would crash the node process (or at minimum halt chain processing for that node), constituting a chain-wide denial of service once triggered by a bad governance value. Since `GasTarget` is a governance-settable value with no bounds check enforced at the parameter layer, a single malicious or erroneous governance vote setting `GasTarget=0` propagates into every node's block validation and effectively halts the network — an availability-breaking condition analogous to the reported Olympus Price `observationFrequency` DoS.

### Likelihood Explanation
Reaching this requires a governance vote/parameter change to set `Kip71GasTarget` to 0, which is gated by whatever governance authorization exists in the `kaiax/gov` module (e.g., governing node or council vote), not a plain unprivileged transaction. This lowers the likelihood versus a fully permissionless trigger, but the complete absence of a format-check (in contrast to the deliberate check on the analogous `BaseFeeDenominator` parameter) indicates this is an oversight, and any governance actor (single governing node in `"single"` governance mode, or a majority-vote a council) could trigger a node-wide panic/DoS with a single vote.

### Recommendation
Add a non-zero `FormatChecker` for `Kip71GasTarget` analogous to `Kip71BaseFeeDenominator`'s, e.g. `func(cv any) bool { v, ok := cv.(uint64); return ok && v != 0 }`, in `kaiax/gov/param.go`. Additionally, as defense-in-depth, add a zero-guard/fallback for `gasTarget` inside `NextMagmaBlockBaseFee` in `params/kip71_config.go`, mirroring the existing `BaseFeeDenominator == 0` fallback, so that even a misconfigured chain config cannot cause a panic during header validation.

### Proof of Concept
1. Governance sets `Kip71GasTarget` (or the chain-config equivalent `Governance.KIP71.GasTarget`) to `0` via a valid governance vote (no format check blocks this, per `noopFormatChecker` at [6](#0-5) ).
2. Once the parameter activates at the next epoch/governance-effective block, any subsequent block with `GasUsed > 0` is proposed.
3. During header validation, `BlockValidator.validateHeader` calls `govParamSet.ToKip71Config().VerifyMagmaHeader(...)` [3](#0-2) , which calls `NextMagmaBlockBaseFee`.
4. Inside `NextMagmaBlockBaseFee`, since `parentGasUsed (>0) > gasTarget (0)`, the code executes `y := x.Div(x, new(big.Int).SetUint64(gasTarget))` with `gasTarget == 0` [7](#0-6) , causing a Go runtime panic ("division by zero") in every node validating that block — crashing consensus nodes, endpoint nodes, and RPC-serving nodes alike.
