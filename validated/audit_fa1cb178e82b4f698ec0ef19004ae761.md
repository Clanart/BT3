## Analysis

The M-31 pattern — treating one token's amount as directly interchangeable with another token's amount via decimal scaling alone, silently assuming 1:1 price parity — has a direct analog in `BandwidthManager.purchase()`.

### Title
Bandwidth tier pricing assumes 1:1 fee-token/USD parity with no price conversion, letting purchasers over/under-pay relative to the governance-intended USD price - (File: `evm/src/apps/BandwidthManager.sol`)

### Summary
`BandwidthManager.purchase()` converts a governance-set, USD-denominated 18-decimal `tierPrice` into the host's configurable `feeToken` using only `IERC20Metadata.decimals()` scaling [1](#0-0) . There is no oracle or exchange-rate lookup anywhere in the contract — the scale factor is purely `10 ** (18 - dec)`, which is only a correct USD-equivalent conversion if one unit of `feeToken` is worth exactly $1. This is the same missing-price-conversion pattern as the M-31 report: a value denominated in one unit (USD-pegged "price") is used as if it were already denominated in another unit (`feeToken` raw amount) without any market-price correction.

### Finding Description
Governance sets tier prices in 18-decimal USD terms via the `SetTiers` action, which the pallet dispatches and the manager stores verbatim in `tierPrice[tier]` [2](#0-1) . At purchase time, the contract does:
```
uint256 total18d = price18d * months;
uint8 dec = IERC20Metadata(feeToken).decimals();
uint256 scale = 10 ** (18 - dec);
uint256 amount = total18d / scale;
``` [3](#0-2) 

This is documented explicitly as pure decimal rebasing, not price conversion: "Tier prices are stored as 18-decimal values on the manager... so the contract scales at purchase time" [4](#0-3) . The `feeToken` itself is admin-configurable and only "usually" a stablecoin — the docs state the host "stores a configurable `feeToken` address that governance can update without a redeploy" [5](#0-4) . Nowhere in `purchase()` or `onAccept()` is there any Chainlink/AMM price check comparable to what `SimplexPaymaster` does for gas payment (`_tokenPrice` pulling a live oracle rate) [6](#0-5) .

Consequently, whenever the actual market value of `feeToken` diverges from exactly $1 — which is a normal, recurring event for "stablecoins" (e.g. USDC/DAI depegs) — the amount pulled from `msg.sender` no longer represents the USD price governance intended for that tier. Any unprivileged caller of `purchase()` benefits or is harmed purely as a function of the prevailing feeToken/USD rate at call time, with zero code path enforcing equivalence.

### Impact Explanation
If `feeToken` trades below its intended $1 value, every unprivileged buyer permanently underpays the USD-denominated tier price the pallet/manager pair was configured for — effectively extracting bandwidth service (a metered, billable resource escrowed against real treasury proceeds) below its governance-set price, with the discount magnitude equal to the depeg size. Conversely, if `feeToken` trades above $1, every buyer is systematically overcharged relative to the intended USD price, i.e. real value is silently extracted from users on every purchase with no way to detect or prevent it on-chain. Both directions are variants of the "loss of funds" / "logic attack" impact class: a static decimal-only scale factor is substituted for a real price and the resulting monetary flow diverges from the amount that was actually authorized in USD terms — same failure mode, same consequence category as the M-31 finding.

### Likelihood Explanation
No privileged actor, relayer, or malicious peer is required — any account can call `purchase()` at any time [7](#0-6) . The only precondition is that the configured `feeToken`'s market price diverges from $1, which is a routine market condition for stablecoins (temporary depegs have happened repeatedly to major stablecoins) and does not require compromising any protocol component.

### Recommendation
Do not treat `feeToken` decimals as a proxy for its USD value. Either (a) restrict `feeToken` to assets with an enforced hard peg and a governance-monitored deviation circuit-breaker, or (b) integrate a price oracle (mirroring the pattern already used in `SimplexPaymaster._tokenPrice`) so `purchase()` converts the 18-decimal USD tier price into `feeToken` units using the token's live USD price, not merely its decimal count.

### Proof of Concept
1. Governance configures `TierOne` at `tierPrice[1] = 1e18` (intended: $1/month) and the host's `feeToken` is a stablecoin currently trading at $1.
2. `feeToken` depegs to $0.80 (a real, recorded market event for major stablecoins).
3. A buyer calls `purchase(app, 1, 1, chain)`. `BandwidthManager` computes `amount = 1e18 / 10**(18-dec)` — i.e. exactly 1 unit of `feeToken` in its native decimals, unchanged by the depeg [1](#0-0) .
4. The buyer pays real value of only ~$0.80 for a bandwidth tier priced by governance at $1, while `pallet-bandwidth` unconditionally credits the full tier allowance on `on_accept` [8](#0-7)  — no code path anywhere corrects for the price gap.

    function purchase(bytes calldata app, uint256 tier, uint256 months, bytes calldata chain)
        external
        returns (bytes32 commitment)
    {
        if (app.length == 0 || chain.length == 0 || months == 0) revert InvalidPurchase();
        uint256 price18d = tierPrice[tier];
        if (price18d == 0) revert UnknownTier();

        uint256 total18d = price18d * months;
        address feeToken = IDispatcher(_host).feeToken();
        uint8 dec = IERC20Metadata(feeToken).decimals();
        uint256 scale = 10 ** (18 - dec);
        if (total18d % scale != 0) revert PriceNotRepresentable();
        uint256 amount = total18d / scale;

        IERC20(feeToken).safeTransferFrom(msg.sender, address(this), amount);

    /// @dev Returns the token to charge and its price relative to native gas.
    ///
    ///      PaymasterERC20 computes `erc20Cost = weiCost * tokenPrice / 1e18`,
    ///      so tokenPrice must be token base units per wei, scaled by 1e18:
    ///        tokenPrice = (nativeUsd * 10^tokenDecimals) / tokenUsd
    ///      e.g. BNB at $600, USDC at $1 with 6 decimals: 0.001 BNB (1e15 wei)
    ///      should cost 0.60 USDC (600000 units), giving tokenPrice = 6e8, which
    ///      is exactly (600e8 * 1e6) / 1e8. Markup is applied on top.
    function _fetchDetails(
        PackedUserOperation calldata userOp,
        bytes32 /* userOpHash */
    ) internal view override returns (uint256 validationData, IERC20 token, uint256 tokenPrice) {
        bytes calldata data = userOp.paymasterData();
        if (data.length < 21) revert InvalidPaymasterData(data.length);

        uint8 mode = uint8(data[0]);
        if (mode > 0x01) revert InvalidMode(mode);

        address tokenAddr = address(bytes20(data[1:21]));

        TokenConfig memory cfg = tokenConfigs[tokenAddr];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(tokenAddr);
        if (!cfg.active) revert TokenNotActive(tokenAddr);

        tokenPrice = _tokenPrice(cfg);
        token = IERC20(tokenAddr);
        validationData = 0; // no time-range restriction
    }

		fn on_accept(&self, request: PostRequest) -> Result<Weight, anyhow::Error> {
			let manager = BandwidthManager::<T>::get(&request.source).ok_or_else(|| {
				anyhow::anyhow!(format!("no bandwidth manager registered for {:?}", request.source))
			})?;

			if request.from != manager.0.to_vec() {
				return Err(anyhow::anyhow!(format!(
					"purchase from unauthorised sender on {:?}: expected {:x?}, got {:x?}",
					request.source, manager.0, request.from
				)));
			}

			let msg = PurchaseMessage::try_from(request.body.as_slice())?;
			let tier = TierIndex::try_from(msg.tier)
				.map_err(|_| anyhow::anyhow!(format!("unknown tier discriminant {}", msg.tier)))?;
			let cfg = Tiers::<T>::get(tier)
				.ok_or_else(|| anyhow::anyhow!(format!("tier {:?} is not configured", tier)))?;

			let bytes = cfg.bytes.saturating_mul(msg.months as u128);
			let duration = cfg.duration_secs.saturating_mul(msg.months as u64);

			let key = AppKey::truncate_from(msg.app);
			let expires_at = Self::push_subscription(&msg.chain, &key, tier, bytes, duration);

			Self::deposit_event(Event::BandwidthCredited {
				app_chain: msg.chain,
				app: key,
				paid_from: request.source,
				tier,
				bytes,
				expires_at,
			});

			Ok(Weight::zero())
		}
