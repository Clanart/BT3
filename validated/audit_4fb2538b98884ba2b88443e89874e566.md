### Title
Missing value bounds check on deserialized `ReceivedOutput` enables reporting unspendable/overstated funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput::read` deserializes a `TxOut` via `TxOut::consensus_decode` and accepts its `value` field without any sanity bound — no check against `Amount::MAX_MONEY` (21M BTC), no minimum/dust check, and no verification that the claimed `outpoint` actually carries that value on-chain. This mirrors the audit finding's bug class: an externally supplied numeric value is consumed downstream (input-sum/fee/change math in `SignableTransaction::new`) without min/max validation, producing incorrect economic results.

### Finding Description
`ReceivedOutput::read` (networks/bitcoin/src/wallet/mod.rs:122-134) reads an offset scalar, then consensus-decodes a `TxOut` and an `OutPoint` directly from the reader:

```rust
output = TxOut::consensus_decode(&mut buf_r)...
outpoint = OutPoint::consensus_decode(&mut buf_r)...
Ok(ReceivedOutput { offset, output, outpoint })
```

The `value` inside the `TxOut` is trusted implicitly. `value()` (line 116-118) returns it verbatim, and `SignableTransaction::new` (networks/bitcoin/src/wallet/send.rs:175) computes `input_sat` as the sum of these attacker-controlled values, then checks `input_sat < payment_sat + needed_fee` (line 215) and computes change as `input_sat - payment_sat - fee` (line 228). An inflated `value` therefore inflates every downstream accounting decision. Additionally, `Scanner::scan_transaction` (mod.rs:199-214) matches only `script_pubkey` and performs no minimum-value/dust check before reporting a `ReceivedOutput`, so the same missing-minimum-bound weakness exists on the chain-scanning path.

### Impact Explanation
An unprivileged party who feeds crafted bytes to `ReceivedOutput::read` (a listed untrusted-bytes entry point), or who sends a real Bitcoin transaction, can cause the wallet to treat funds as received at an arbitrary claimed amount. The result is "funds reported received that are not spendable": `SignableTransaction::new` will construct and the FROST `TransactionMachine` will sign (via `Prevouts::All` sighash committing to the fabricated prevout values, send.rs:375-386) a transaction whose stated inputs exceed what the outpoints hold, or which spends dust outputs uneconomical to redeem. The analogous loss to the oracle report — computing claimable/spendable amounts higher than reality, causing loss — is the signature ceremony producing a transaction that is either consensus-invalid or economically wasteful.

### Likelihood Explanation
Reachable whenever untrusted peers exchange serialized `ReceivedOutput`s (e.g., multisig participants sharing detected inputs) or whenever an attacker sends a below-dust payment to a scanned address — both are public-input paths requiring no key material, no malicious validator, and no broken RPC.

### Recommendation
In `ReceivedOutput::read`, validate `output.value` against `bitcoin::Amount::MAX_MONEY` (reject values above the supply cap) and reject sub-`DUST` values. Optionally provide a checked constructor that verifies the claimed `outpoint`/`TxOut` against a fetched transaction. In `Scanner::scan_transaction`, skip outputs below `DUST` so uneconomical outputs are never reported as spendable funds.

### Proof of Concept
```rust
// Craft a ReceivedOutput claiming an inflated value for an outpoint
// holding far less on-chain.
let mut bytes = Vec::new();
bytes.extend(Scalar::ZERO.to_bytes());            // offset
let fake = TxOut {
  value: Amount::from_sat(21_000_000_0000_0000u64.min(u64::MAX)), // inflated
  script_pubkey: p2tr_script_buf(key).unwrap(),
};
bytes.extend(serialize(&fake));
bytes.extend(serialize(&OutPoint::new(real_txid, 0)));
let forged = ReceivedOutput::read(&mut bytes.as_slice()).unwrap(); // accepted

// input_sat now reflects the forged value; the check passes and the
// multisig signs a tx whose signatures commit to false prevout values,
// which consensus will reject — value was used without any bounds check.
let tx = SignableTransaction::new(vec![forged], &payments, change, None, fee);
```
