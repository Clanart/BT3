### Title
Forged `WWW-Authenticate` realm from an attacker-controlled remote spoofs "GitHub Enterprise" classification, bypassing real host verification - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
Similar to the Balancer flash-loan report, the bug class here is **trusting an unauthenticated signal from an external/attacker-controlled callback as if it were a validated identity**. In the Solidity case, `receiver` is set from `msg.sender` before an external call and consumed by an unguarded callback. In GitHub Desktop's git-credential-helper trampoline, `getEndpointKind()` classifies a remote host as a trusted `'enterprise'` (GitHub Enterprise Server) endpoint based on a `WWW-Authenticate` header value that Git forwards verbatim from whatever HTTP server it is talking to — with no cryptographic or network verification that the server is actually a GitHub product.

### Finding Description
`getEndpointKind` in [1](#0-0)  determines how a remote endpoint should be treated by the credential helper. Before doing any real verification, it inspects credential fields prefixed `wwwauth[` — which Git populates from the HTTP response's `WWW-Authenticate` header sent by the remote server — and if the value contains `realm="GitHub"`, immediately classifies the endpoint as `'enterprise'`: [2](#0-1) 

This check runs *before* the actual network-based verification `isGitHubHost(endpoint)`, which is only reached as a fallback: [3](#0-2) 

The remote endpoint's identity (the credential URL/host) as well as the `WWW-Authenticate` header content are both fully controlled by whatever server the user's git operation talks to — i.e. an attacker-controlled git remote the user has added or cloned, or a plain HTTP(S) server a `.gitmodules` submodule/LFS endpoint points to. There is no requirement that the header actually originate from `github.com`/GHE; the string match `realm="GitHub"` is a self-reported, unauthenticated claim.

Once classified as `'enterprise'`, `getCredential()` treats the host as GitHub-affiliated and, if no existing account matches, invokes the sign-in prompt flow for that arbitrary attacker endpoint: [4](#0-3) 

This mirrors the report's root cause exactly: a piece of state (`receiver` in the Solidity example, `endpointKind`/trust classification here) is derived from data supplied by an external, attacker-influenced actor during a callback (`receiveFlashLoan` there, the credential-helper trampoline callback here), and is consumed without validating that the actual "initiator" is who it claims to be.

### Impact Explanation
An attacker who controls a git remote (or a proxy/MITM position, or an HTTPS server referenced from `.gitmodules`/LFS config in a repo the victim clones or fetches) can serve a `401` response containing `WWW-Authenticate: Basic realm="GitHub"`. This causes Desktop to:
1. Misclassify the attacker's arbitrary host as a legitimate GitHub Enterprise instance, skipping the genuine `isGitHubHost` network probe.
2. Surface a "Sign in to GitHub Enterprise" prompt bound to the attacker's endpoint via `ui.promptForGitHubSignIn(endpoint)`.
3. If the user completes that sign-in flow (device flow / PAT entry) believing it is a legitimate corporate GHES prompt, the resulting credential is fed back to Git's credential protocol for that host and sent as Basic Auth to the attacker's server — an unauthorized OAuth/PAT capture and exfiltration to attacker infrastructure, triggered purely by an unprivileged, attacker-controlled remote response.

This satisfies the valid-impact criteria: attacker controls a git remote/proxy response, result is unauthorized OAuth/credential capture — no local access, admin rights, or prior malware required.

### Likelihood Explanation
Requires the victim to interact with a git remote the attacker controls (add remote, clone/fetch a repo with a malicious submodule/LFS URL) and to complete a sign-in prompt Desktop presents — which is exactly the kind of "unprompted" UI Desktop itself initiates in response to the forged header, so it is not classic social engineering; the trigger condition is purely server-response controlled. Likelihood is moderate: it depends on the victim proceeding through a sign-in dialog, but the dialog itself is spawned automatically by the spoofed classification, with no indication to the user that the "GitHub Enterprise" designation was self-asserted by the remote server rather than verified.

### Recommendation
- Do not trust the `wwwauth[...] realm="GitHub"` header as sufficient proof of a GitHub-affiliated host. At minimum, always perform the authoritative `isGitHubHost(endpoint)` network check before offering a GitHub/GHE-specific sign-in flow, and only use the header as a weak hint to decide whether to *attempt* the real check, not to bypass it.
- Before initiating `promptForGitHubSignIn` for a previously-unknown endpoint, clearly surface to the user which host is requesting sign-in and require that the host correspond to a positively verified GitHub product endpoint.

### Proof of Concept
1. Attacker sets up an HTTP(S) git server (or points a `.gitmodules` submodule/LFS URL to it) at `https://attacker.example`.
2. Attacker configures the server to respond to Git's credential probe with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
3. Victim adds/clones a repository referencing that remote in GitHub Desktop and triggers a fetch/clone (including submodule/LFS recursion).
4. Git forwards the `wwwauth[...]` field to Desktop's credential helper trampoline; `getEndpointKind` (`app/src/lib/trampoline/trampoline-credential-helper.ts:153-165`) classifies `attacker.example` as `'enterprise'` without ever calling `isGitHubHost`.
5. `getCredential` invokes `ui.promptForGitHubSignIn('https://attacker.example')`; if the victim completes the flow, the resulting token/credentials are handed back to Git and transmitted to `attacker.example` as Basic Auth.

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
