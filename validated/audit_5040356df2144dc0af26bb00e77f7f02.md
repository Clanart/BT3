### Title
Double `end_round` Call in `PayoutCheckerTask` Skips a Round and Permanently Burns Kickoff Connectors, Blocking Operator Reimbursement - (File: core/src/task/payout_checker.rs)

### Summary

`PayoutCheckerTask::run_once` calls `self.operator.end_round()` unconditionally after `handle_finalized_payout`. However, `handle_finalized_payout` itself also calls `end_round` internally when the current round's kickoff connectors are exhausted. This double invocation advances `current_round_index` by 2 instead of 1, burns all unused kickoff connectors in the skipped round, and permanently prevents the operator from using those connectors for future deposit reimbursements.

### Finding Description

`PayoutCheckerTask::run_once` processes one unhandled payout per invocation. After calling `handle_finalized_payout`, it unconditionally calls `end_round`:

```rust
// core/src/task/payout_checker.rs lines 72-106
let kickoff_txid = self.operator.handle_finalized_payout(...).await?;
// ...
#[cfg(feature = "automation")]
self.operator.end_round(&mut dbtx).await?;   // <-- unconditional
self.db.mark_payout_handled(...).await?;
```

Inside `handle_finalized_payout`, when all kickoff connectors in the current round are already used, the function also calls `end_round` to advance to the round where the first available connector lives:

```rust
// core/src/operator.rs lines 868-884
#[cfg(feature = "automation")]
if current_round_index != round_idx {
    if current_round_index.next_round() != round_idx {
        return Err(...);
    }
    self.end_round(dbtx).await?;   // <-- first end_round
}
```

`end_round` always advances `current_round_index` by exactly one:

```rust
// core/src/operator.rs lines 1219-1222
self.db
    .update_current_round_index(Some(dbtx), current_round_index.next_round())
    .await?;
```

When both calls execute in the same transaction, the sequence is:

1. `handle_finalized_payout`: `end_round` → `current_round` advances from N → N+1; assigns kickoff connector in round N+1 for deposit A; marks it used with `kickoff_txid`.
2. `PayoutCheckerTask`: `end_round` → `current_round` advances from N+1 → N+2; iterates all connectors in round N+1 and calls `mark_kickoff_connector_as_used(..., None)` for any connector not already in `used_kickoff_connectors`. Because `mark_kickoff_connector_as_used` uses `ON CONFLICT DO NOTHING`, deposit A's connector (already inserted with a real `kickoff_txid`) is preserved, but every other connector in round N+1 is permanently burned with `kickoff_txid = NULL`.

After this, `get_unused_and_signed_kickoff_connector` filters `ds.round_idx >= cr.round_idx` (current round N+2), so all connectors in round N+1 are permanently inaccessible for future deposits.

```sql
-- core/src/database/operator.rs lines 908-929
AND ds.round_idx >= cr.round_idx   -- round N+1 < N+2, forever excluded
```

### Impact Explanation

Every time a payout arrives when the current round is full (a normal operational condition), the round index advances by 2 and one entire round's worth of kickoff connectors is burned. With `num_round_txs` rounds available, the operator exhausts usable rounds at twice the expected rate. Once all rounds are consumed, `get_unused_and_signed_kickoff_connector` returns `None` for every new deposit, `handle_finalized_payout` returns `BridgeError::DatabaseError(RowNotFound)`, and the operator can no longer initiate kickoffs. Any BTC the operator fronted for withdrawals that have not yet been reimbursed is permanently unrecoverable — the operator cannot send the kickoff transaction required to claim the vault funds.

### Likelihood Explanation

The trigger is entirely normal operation: it fires whenever the current round's `num_kickoffs_per_round` connectors are all consumed before a new payout arrives. With a small `num_kickoffs_per_round` (a protocol parameter) and a busy bridge, this condition is routine. No adversarial action is required; the bug is self-inflicted by the automation loop.

### Recommendation

Remove the unconditional `end_round` call from `PayoutCheckerTask::run_once`. The round advancement is already handled inside `handle_finalized_payout` when needed. Alternatively, have `handle_finalized_payout` return a boolean indicating whether it already advanced the round, and only call `end_round` in `PayoutCheckerTask` when it did not.

```rust
// core/src/task/payout_checker.rs  -- remove or guard this call
#[cfg(feature = "automation")]
self.operator.end_round(&mut dbtx).await?;  // DELETE or condition on handle_finalized_payout result
```

### Proof of Concept

Setup: `num_kickoffs_per_round = 1`, `num_round_txs = 3` (rounds 0, 1, 2). Two deposits D1 and D2 both have kickoff connectors in rounds 0, 1, 2.

1. Current round = Round(0). D1 payout arrives. Round 0 has one free connector.
   - `handle_finalized_payout`: `current_round_index (0) == round_idx (0)` → no internal `end_round`. Assigns connector (round=0, kickoff=0) to D1.
   - `PayoutCheckerTask`: `end_round` → current round = Round(1). Burns no connectors (round 0's connector is already used by D1).

2. Current round = Round(1). D2 payout arrives. Round 1 has one free connector.
   - `handle_finalized_payout`: `current_round_index (1) == round_idx (1)` → no internal `end_round`. Assigns connector (round=1, kickoff=0) to D2.
   - `PayoutCheckerTask`: `end_round` → current round = Round(2). Burns no connectors.

3. A third deposit D3 payout arrives. Current round = Round(2). Round 2 has one free connector.
   - `handle_finalized_payout`: assigns connector (round=2, kickoff=0) to D3.
   - `PayoutCheckerTask`: `end_round` → current round = Round(3) (beyond `num_round_txs`).

4. A fourth deposit D4 payout arrives. `get_unused_and_signed_kickoff_connector` returns `None` (no round >= 3 exists). `handle_finalized_payout` returns `RowNotFound`. D4 can never be reimbursed.

Now consider the double-advance scenario: if round 0 is already full when D1 arrives:

1. Current round = Round(0), round 0 connector already used.
   - `handle_finalized_payout`: `current_round_index (0) != round_idx (1)` → internal `end_round` → current round = Round(1). Assigns connector (round=1, kickoff=0) to D1.
   - `PayoutCheckerTask`: `end_round` → current round = Round(2). Burns round 1's remaining connectors (none here, but round index is now 2).

2. D2 payout arrives. Current round = Round(2). Round 1 connector for D2 is inaccessible (round 1 < 2). Uses round 2 connector.
   - `PayoutCheckerTask`: `end_round` → current round = Round(3).

3. D3 arrives. `get_unused_and_signed_kickoff_connector` returns `None`. D3 is permanently blocked. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4)

    pub async fn mark_kickoff_connector_as_used(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        round_idx: RoundIndex,
        kickoff_connector_idx: u32,
        kickoff_txid: Option<Txid>,
    ) -> Result<(), BridgeError> {
        let query = sqlx::query(
            "INSERT INTO used_kickoff_connectors (round_idx, kickoff_connector_idx, kickoff_txid)
             VALUES ($1, $2, $3)
             ON CONFLICT (round_idx, kickoff_connector_idx) DO NOTHING;",
        )
        .bind(round_idx.to_index() as i32)
        .bind(
            i32::try_from(kickoff_connector_idx)
                .wrap_err("Failed to convert kickoff connector idx to i32")?,
        )
        .bind(kickoff_txid.map(TxidDB));

        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
