## Finding

### Title
Trampoline credential helper trusts an attacker-controlled `WWW-Authenticate` header to classify a git remote as a GitHub/Enterprise host, bypassing independent verification - (`app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
This is a real structural analog to the reported class of bug: a security-relevant classification decision is made by trusting a single value supplied by an untrusted, attacker-influenceable party (in GMX's case, the AMM-derived price; here, the HTTP response header returned by the remote git server), instead of relying on (or cross-checking against) the app's own independent, trusted verification mechanism.

### Finding Description
`getEndpointKind()` decides whether a git remote should be treated as `'generic'`, `'github.com'`, or `'enterprise'`. This classification gates two security-relevant behaviors in the credential trampoline: whether GitHub/GHE-style credential flows are used vs. generic credential storage, and whether the user is funneled into the "Sign in to GitHub"/OAuth prompt.

The function's normal, trustworthy fallback path is to make its own network request and verify a GitHub-specific signal: [1](#0-0) 

However, before doing that independent check, the function short-circuits based solely on a `WWW-Authenticate` header value that Git captured from the remote server's own HTTP response and forwarded into the credential helper's stdin: [2](#0-1) 

The comment itself acknowledges the header is treated as "a happy-path to determine if the host is a GitHub host **without having to resort to making a request ourselves**" — i.e., the code deliberately substitutes an attacker-suppliable value for its own trusted verification, exactly mirroring the GMX pattern of trusting a manipulable oracle instead of validating against Chainlink.

Any HTTP(S) git server — including a malicious/compromised remote the app is attempting to fetch/push/clone against, or a MITM/corporate proxy response — fully controls the `WWW-Authenticate` response header on a 401, and can set `realm="GitHub"` to force `getEndpointKind` to return `'enterprise'` for that request.

### Impact Explanation
Once `endpointKind !== 'generic'` is forced by the spoofed header:
- `storeCredential` / `eraseCredential` silently no-op instead of persisting or clearing the user's generic username/password for that host: [3](#0-2) 
- `getCredential` skips the generic-auth prompt path and instead calls `ui.promptForGitHubSignIn(endpoint)`, which begins a full "Sign in to GitHub Enterprise" / OAuth popup flow keyed to the attacker's host: [4](#0-3) [5](#0-4) 

Actual GitHub.com/GHE token lookups remain gated by exact-origin matching in `findGitHubTrampolineAccount`, so I could not confirm that an existing token for a different, legitimate account is exfiltrated to the spoofed host — that specific guard does appear to hold. What is confirmed is: (1) the app's own trust decision is overridden by attacker-controlled data instead of by its own verification step, and (2) this causes silent failure to persist/erase the user's typed generic git credentials, and unconditionally routes the user into a "GitHub sign-in" UI flow for a host that has not been independently verified to be GitHub at all.

### Likelihood Explanation
Any git server the app talks to over HTTPS (a cloned/added repository's remote, a malicious fork remote, or a network intermediary) can trigger this by returning a 401 with a crafted `WWW-Authenticate: Basic realm="GitHub"` header — no special privileges, local access, or social engineering of the user's git usage pattern are required beyond having Desktop attempt an authenticated operation (fetch/push/pull) against the attacker-controlled or MITM'd remote.

### Recommendation
Do not let a self-declared `WWW-Authenticate` realm value short-circuit the classification. At minimum, require the independent `isGitHubHost()` network verification (which checks for the `x-github-request-id` response header from a `/meta` request) before trusting a header-based "GitHub" claim, mirroring the fix applied for `exchangeFromExactBase()`: prefer the app's own trusted verification over the counterparty-supplied value, and only use the header as a hint to *skip a redundant future check*, never as the sole basis for a security decision.

### Proof of Concept
Not independently executable from the code index alone (would require running the credential-helper trampoline against a live/mock HTTPS git server). Conceptually:
1. Add a remote (`git remote add evil https://attacker.example/repo.git`) or accept a repository whose remote points to an attacker-controlled HTTPS host.
2. Perform a fetch/pull/push; Git sends a request, the attacker's server responds `401 Unauthorized` with header `WWW-Authenticate: Basic realm="GitHub"`.
3. Git forwards this as a `wwwauth[...]` credential field to Desktop's credential helper.
4. `getEndpointKind` matches `realm="GitHub"` at [6](#0-5)  and returns `'enterprise'` without ever calling `isGitHubHost()`.
5. `getCredential` routes to `ui.promptForGitHubSignIn(endpoint)` for `attacker.example`, and any credential the user previously stored for `attacker.example` via the generic flow is no longer stored/erased through `setGenericCredential`/`deleteGenericCredential`.

Given the residual origin-matching guard in `findGitHubTrampolineAccount`, I cannot confirm this achieves outright token exfiltration; I'm flagging it as a broken-invariant/trust-boundary defect matching the reported bug class, with confirmed impact limited to credential-storage bypass and unwarranted GitHub sign-in prompting for an unverified host, rather than confirmed exfiltration of an existing token.

  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'

  // assume that this is not a GitHub host.

/** Implementation of the 'store' git credential helper command */
async function storeCredential(cred: Credential, store: Store, token: string) {
  if ((await getEndpointKind(cred, store)) !== 'generic') {
    return
  }

  return useExternalCredentialHelper()
    ? storeExternalCredential(cred, token)
    : setGenericCredential(
        urlWithoutCredentials(getCredentialUrl(cred)),
        forceUnwrap(`credential missing username`, cred.get('username')),
        forceUnwrap(`credential missing password`, cred.get('password'))
      )
}

const storeExternalCredential = (cred: Credential, token: string) => {
  const path = getTrampolineEnvironmentPath(token)
  return approveCredential(cred, path, getGcmEnv(token))
}

/** Implementation of the 'erase' git credential helper command */
async function eraseCredential(cred: Credential, store: Store, token: string) {
  if ((await getEndpointKind(cred, store)) !== 'generic') {
    return
  }

  return useExternalCredentialHelper()
    ? eraseExternalCredential(cred, token)
    : deleteGenericCredential(
        urlWithoutCredentials(getCredentialUrl(cred)),
        forceUnwrap(`credential missing username`, cred.get('username'))
      )
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
