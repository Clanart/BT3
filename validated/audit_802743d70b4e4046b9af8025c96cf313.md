### Title
Consensus-incentive rewards are computed at the *current* `cost_per_block` applied retroactively to an unbounded backlog, allowing an outsized one-shot treasury payout - ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
This is the local analog of the BendDAO finding: a rate parameter (`cost_per_block`) can change without the accrual state being settled at the rate that was actually in effect while the un-rewarded span accumulated. In BendDAO the effect was interest still computed at the *stale* rate; here it's the mirror image and more severe — the reward is computed at whatever `cost_per_block` is *current* when the payout is finally triggered, applied over the entire backlog of heights that piled up while payouts were stalled, none of which necessarily accrued at that rate.

### Finding Description
`pallet-consensus-incentives::calculate_reward` computes:
```
reward = (latest_height - baseline) * StateMachinesCostPerBlock::get(state_machine_id)
``` [1](#0-0) 

`baseline` is `LastRewardedHeight`, which is **only** advanced inside `process_message` after a reward transfer *succeeds*: [2](#0-1) 

Crucially, the underlying state-machine height (`LatestStateMachineHeight`/`PreviousStateMachineHeight`) is advanced unconditionally by `pallet-ismp`'s message pipeline via `store_latest_commitment_height`, completely independent of whether the incentives pallet ever gets to run or succeeds: [3](#0-2) 

So the chain height and the reward watermark can drift apart with no cap, in two realistic, non-malicious scenarios:
1. Governance calls `remove_incentives` (sets `cost_per_block` to `None`) for a period — `process_message`'s `if let Some(block_cost)` guard skips entirely, so `LastRewardedHeight` never advances even though the chain keeps progressing: [4](#0-3) 
2. A reward transfer fails (`RewardTransferFailed`, e.g. treasury temporarily underfunded) — `process_message` returns `Err` before updating `LastRewardedHeight`, so the un-rewarded span keeps growing across every subsequent consensus update until the treasury is refilled: [5](#0-4) 

When `cost_per_block` is later (re)configured via `update_cost_per_block` — an ordinary governance action, not an attack — the very next consensus message from **any unprivileged relayer** triggers `calculate_reward`, which multiplies the *entire accumulated backlog* by the *new* `cost_per_block`, not the rate that was in force while those blocks were actually produced: [6](#0-5) 

The existing test confirms the calculation faithfully sums the whole unpaid span times a single fixed rate with no historical rate tracking: [7](#0-6) 

### Impact Explanation
Any permissionless relayer that is first to submit the reactivating consensus proof captures the full backlog reward at whatever rate is current, directly draining `TreasuryAccount` for an amount disproportionate to the work actually incentivized at the time it happened. This is a direct fund-loss/logic-attack vector against the treasury, reachable by an ordinary relayer with no need for a malicious admin, prover, or collusion — governance simply performing a normal rate update or the treasury temporarily running low are both plausible production events that this design turns into an exploitable payout window.

### Likelihood Explanation
Medium: it requires one of two realistic conditions (a temporary `remove_incentives`/reconfiguration, or a period of insufficient treasury balance causing `RewardTransferFailed`) followed by a rate change or refill — both are normal operational events, not attacker-controlled preconditions. Once either condition occurs, exploitation is trivial and requires only being the first (unprivileged) relayer to submit the next consensus message.

### Recommendation
Settle (or checkpoint) any pending reward at the rate in effect immediately before `update_cost_per_block`/`remove_incentives` changes it, e.g. call `process_message`/advance `LastRewardedHeight` to the current height using the *old* rate before applying the new one, or track and sum reward per rate-segment rather than a single flat rate over the whole unpaid span. Additionally, bound the maximum backlog span payable in one call to prevent unbounded accumulation while rewards are failing or disabled.

### Proof of Concept
1. Governance sets `cost_per_block = 10` for a state machine.
2. Treasury balance is drawn down (or governance calls `remove_incentives`) so that either `RewardTransferFailed` occurs repeatedly, or no reward processing happens, while the chain's actual `LatestStateMachineHeight` keeps advancing by thousands of blocks through normal consensus updates (`store_latest_commitment_height` runs every time regardless).
3. Treasury is refilled / governance calls `update_cost_per_block(state_machine_id, 10_000)`.
4. Any relayer submits the next consensus message; `calculate_reward` computes `(latest_height - stale_baseline) * 10_000`, paying out the entire multi-thousand-block backlog at the new rate in a single transaction — mirroring the mechanics already exercised in `reward_covers_only_unpaid_heights_after_rollback`, but with the rate bumped between accrual and payout instead of held constant. [8](#0-7)

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

	fn store_latest_commitment_height(&self, height: StateMachineHeight) -> Result<(), Error> {
		let previous_height = LatestStateMachineHeight::<T>::get(height.id).unwrap_or_default();
		PreviousStateMachineHeight::<T>::insert(height.id, previous_height);
		LatestStateMachineHeight::<T>::insert(height.id, height.height);
		Ok(())
	}

				state_machine_id,
				cost_per_block,
			});

#[test]
fn reward_covers_only_unpaid_heights_after_rollback() {
	let mut ext = new_test_ext();
	ext.execute_with(|| {
		const BLOCK_COST: u128 = 100;
		let host = Ismp::default();
		let state_machine_id = setup_state_machine();
		let treasury_account: AccountId32 = PalletId(*b"treasury").into_account_truncating();

		pallet_consensus_incentives::Pallet::<Test>::update_cost_per_block(
			RuntimeOrigin::root(),
			state_machine_id,
			BLOCK_COST,
		)
		.unwrap();

		let (consensus_message, relayer_account) = setup_host_and_message(&host);
		let message = MessageWithWeight { message: consensus_message, weight: Weight::zero() };
		let updated = |height: u64| {
			vec![IsmpEvent::StateMachineUpdated(StateMachineUpdated {
				state_machine_id,
				latest_height: height,
			})]
		};

		// The chain has already advanced to 1025 and every block up to it has been rewarded once.
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1024 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1024,
		})
		.unwrap();
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1025 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1025,
		})
		.unwrap();

		let treasury_before_first = Balances::balance(&treasury_account);
		<pallet_consensus_incentives::Pallet<Test> as FeeHandler>::on_executed(
			vec![message.clone()],
			updated(1025),
		)
		.unwrap();

		assert_eq!(Balances::balance(&treasury_account), treasury_before_first - BLOCK_COST);
		assert_eq!(
			pallet_consensus_incentives::LastRewardedHeight::<Test>::get(state_machine_id),
			Some(1025)
		);

		// The previous-height pointer references an older height whose commitment is no longer
		// retained in the bounded map.
		pallet_ismp::PreviousStateMachineHeight::<Test>::insert(state_machine_id, 1);

		// Deleting the latest commitment rolls the latest height back to that previous pointer.
		host.delete_state_commitment(StateMachineHeight { id: state_machine_id, height: 1025 })
			.unwrap();
		assert_eq!(host.latest_commitment_height(state_machine_id).unwrap(), 1);

		// The next honest consensus update advances to 1030, carrying the stale pointer forward as
		// the new previous height.
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1030 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1030,
		})
		.unwrap();
		assert_eq!(host.previous_commitment_height(state_machine_id), Some(1));

		let treasury_before_second = Balances::balance(&treasury_account);
		<pallet_consensus_incentives::Pallet<Test> as FeeHandler>::on_executed(
			vec![message],
			updated(1030),
		)
		.unwrap();

		// The real advance is 1025 -> 1030, so only the 5 new blocks are paid rather than the full
		// span back to the previous pointer.
		assert_eq!(Balances::balance(&treasury_account), treasury_before_second - 5 * BLOCK_COST);
		assert_eq!(
			pallet_consensus_incentives::LastRewardedHeight::<Test>::get(state_machine_id),
			Some(1030)
		);
	})
}
