### Title
Uncontrolled Python recursion depth when parsing nested outer-puzzle layers ("also" chain) from an untrusted offer/spend bundle - (File: chia/wallet/outer_puzzles.py, chia/wallet/trading/offer.py)

### Summary
The ParquetSharp advisory is about an attacker-controlled "width" value driving an unbounded stack allocation (`stackalloc`) during untrusted file parsing, causing a stack overflow / crash (CWE-789, uncontrolled memory allocation tied to attacker input). The closest reachable analog in this codebase is not a native `stackalloc`, but the same bug class expressed in Python: **uncontrolled recursion depth driven by an attacker-supplied puzzle structure**, reached when a wallet parses an untrusted `Offer`/spend bundle's puzzle reveals.

### Finding Description
`chia.wallet.outer_puzzles.match_puzzle()`, `get_inner_puzzle()`, `get_inner_solution()`, `construct_puzzle()`, and `solve_puzzle()` dispatch to per-asset-type driver classes (`CATOuterPuzzle`, `SingletonOuterPuzzle`, `OwnershipOuterPuzzle`, `MetadataOuterPuzzle`, `CROuterPuzzle`) that all implement layering via a `constructor.also()` chain [1](#0-0) . Each of these drivers recurses into itself (or a peer driver) once per detected "also" layer with **no maximum-depth check**, e.g. `CATOuterPuzzle.match()`/`get_inner_puzzle()` [2](#0-1) , `OwnershipOuterPuzzle` [3](#0-2) , `SingletonOuterPuzzle` [4](#0-3) , and `CROuterPuzzle` [5](#0-4) . `PuzzleInfo.also()`/`check_type()` recurse the same way with no bound [6](#0-5) .

These functions are exercised on **untrusted, attacker-supplied puzzle reveals** as soon as a wallet receives an `Offer` from a counterparty: `Offer.from_spend_bundle()` calls `match_puzzle()` on every coin spend's puzzle reveal [7](#0-6) , and `Offer._get_offered_coins()` (used by summary/UI/validation paths) additionally calls `get_inner_puzzle()`/`get_inner_solution()` recursively over the same layer chain [8](#0-7) . Unlike CLVM tree-hashing, which was deliberately made **iterative** to avoid exactly this class of bug (`chia/types/blockchain_format/tree_hash.py`, explicitly documented as avoiding "blowing out the python stack") [9](#0-8) , the outer-puzzle driver "also" chain has no equivalent protection or depth cap.

A malicious offer-maker can construct a puzzle reveal that curries a deeply nested sequence of recognized outer-puzzle layers (CAT-wrapping-CAT-wrapping-ownership-wrapping-CR, etc.), each layer adding only a small, fixed amount of CLVM bytecode. Because this parsing occurs in the wallet before/without full CLVM execution-cost gating (it is Python-side puzzle structure matching, not mempool cost-metered CLVM execution), an attacker can make the byte overhead per layer cheap relative to the number of Python recursion frames it forces.

### Impact Explanation
When the counterparty's wallet parses such an offer (e.g., to display a summary, validate it, or decide whether to take it), the unbounded recursion can exhaust the Python call stack and raise `RecursionError`, which is unhandled in these paths. This can crash or hang the wallet process/RPC call that is inspecting the malicious offer, denying that wallet's ability to process offers (and potentially other wallet RPC calls if the exception propagates into a shared event loop worker). This is a "spend-triggered transaction-processing halt" against the offer-counterparty's wallet, matching the requested impact category, and is a direct analog of the ParquetSharp CWE-789 stack-exhaustion bug class, translated to Python (RecursionError-driven service interruption instead of native stack overflow).

### Likelihood Explanation
Likelihood is moderate: this requires only that a malicious actor construct an offer file (or spend bundle presented as an offer) with a deeply layered, recognized outer-puzzle structure and get a counterparty's wallet to inspect it (e.g., via `get_offer_summary`/`check_offer_validity`/taking the offer), which is a normal part of the offer workflow reachable by any offer counterparty without special privileges. The main uncertainty is the exact number of layers needed to exhaust Python's default recursion limit and how much larger a puzzle reveal of that depth would be versus practical transaction/offer size limits — this was not fully verified against a concrete recursion-limit calculation in the time available.

### Recommendation
Add an explicit maximum-depth guard when walking `PuzzleInfo.also()` chains and when recursing through outer-puzzle drivers (`match_puzzle`, `get_inner_puzzle`, `get_inner_solution`, `construct_puzzle`, `solve_puzzle`), raising a clear, catchable error (e.g., `ValueError`) once a reasonable layer limit is exceeded, similar to the iterative approach already used in `sha256_treehash`. Alternatively, convert the "also" traversal to an iterative loop instead of recursive calls so that arbitrarily deep, attacker-controlled layer chains cannot exhaust the Python call stack. Ensure offer-summary/validation RPC handlers catch `RecursionError` (or the new bounded error) and return a normal RPC failure rather than crashing the request.

### Proof of Concept
Not independently executed. Conceptually: construct a `Program` that curries `N` nested recognized outer-puzzle layers (e.g., alternating `CAT_MOD`/ownership/`SINGLETON_TOP_LAYER_MOD` structures matched by `match_cat_puzzle`, `match_ownership_layer_puzzle`, `match_singleton_puzzle`) as a coin's `puzzle_reveal`, embed it in a `WalletSpendBundle`, wrap it as an `Offer` via `Offer.from_spend_bundle()`, and have a counterparty wallet call `Offer._get_offered_coins()` (e.g., via `summary()`/`get_pending_amounts()`/`get_offer_summary` RPC) on the received offer bytes; with sufficiently large `N` (bounded chiefly by Python's default recursion limit, ~1000, and manageable puzzle-reveal size), this is expected to raise an unhandled `RecursionError` in the wallet process.

        offered_coins: dict[bytes32 | None, list[Coin]] = {}

        cost_left = INFINITE_COST
        for parent_spend in self._bundle.coin_spends:
            coins_for_this_spend: list[Coin] = []

            parent_puzzle: UnknownPuzzle = UnknownPuzzle(known_program=parent_spend.puzzle_reveal)
            parent_solution = Program.from_serialized(parent_spend.solution)
            additions: list[Coin] = self._additions[parent_spend.coin]

            puzzle_driver = match_puzzle(parent_puzzle)
            if puzzle_driver is not None:
                asset_id = create_asset_id(puzzle_driver)
                inner_puzzle: Program | None = get_inner_puzzle(puzzle_driver, parent_puzzle, parent_solution)
                inner_solution: Program | None = get_inner_solution(puzzle_driver, parent_solution)
                assert inner_puzzle is not None and inner_solution is not None

                # We're going to look at the conditions created by the inner puzzle
                puzzle_cost, conditions = inner_puzzle.run_with_cost(cost_left, inner_solution)
                assert cost_left >= puzzle_cost
                cost_left -= puzzle_cost
                expected_num_matches: int = 0
                offered_amounts: list[int] = []
                for condition in conditions.as_iter():
                    if condition.first() == 51 and condition.rest().first() == OFFER_MOD_HASH:
                        expected_num_matches += 1
                        offered_amounts.append(condition.rest().rest().first().as_int())

                # Start by filtering additions that match the amount
                matching_spend_additions = [a for a in additions if a.amount in offered_amounts]

                if len(matching_spend_additions) == expected_num_matches:
                    coins_for_this_spend.extend(matching_spend_additions)
                # We didn't quite get there so now lets narrow it down by puzzle hash
                else:
                    # If we narrowed down too much, we can't trust the amounts so start over with all additions
                    if len(matching_spend_additions) < expected_num_matches:
                        matching_spend_additions = additions
                    matching_spend_additions = [
                        a
                        for a in matching_spend_additions
                        if a.puzzle_hash == construct_puzzle(puzzle_driver, OFFER_MOD).get_tree_hash()
                    ]
                    if len(matching_spend_additions) == expected_num_matches:
                        coins_for_this_spend.extend(matching_spend_additions)
                    else:
                        raise ValueError("Could not properly guess offered coins from parent spend")

    @classmethod
    def from_spend_bundle(cls, bundle: WalletSpendBundle) -> Offer:
        # Because of the `to_spend_bundle` method, we need to parse the dummy CoinSpends as `requested_payments`
        requested_payments: dict[bytes32 | None, list[NotarizedPayment]] = {}
        driver_dict: dict[bytes32, PuzzleInfo] = {}
        leftover_coin_spends: list[CoinSpend] = []
        for coin_spend in bundle.coin_spends:
            driver = match_puzzle(UnknownPuzzle(known_program=coin_spend.puzzle_reveal))
            if driver is not None:
                asset_id = create_asset_id(driver)
                assert asset_id is not None
                driver_dict[asset_id] = driver
            else:
                asset_id = None
            if coin_spend.coin.parent_coin_info == bytes32.zeros:
                notarized_payments: list[NotarizedPayment] = []
                for payment_group in Program.from_serialized(coin_spend.solution).as_iter():
                    nonce = bytes32(payment_group.first().as_atom())
                    payment_args_list = payment_group.rest().as_iter()
                    notarized_payments.extend(
                        [NotarizedPayment.from_condition_and_nonce(condition, nonce) for condition in payment_args_list]
                    )

                requested_payments[asset_id] = notarized_payments
            else:
                leftover_coin_spends.append(coin_spend)

        return cls(
            requested_payments, WalletSpendBundle(leftover_coin_spends, bundle.aggregated_signature), driver_dict
        )
