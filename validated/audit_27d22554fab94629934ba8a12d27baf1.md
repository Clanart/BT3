### Title
Malicious signing participant can crash Bitcoin signing via an identity aggregate nonce - ([File: networks/bitcoin/src/crypto.rs](networks/bitcoin/src/crypto.rs))

### Summary
`TransactionSignMachine::read_preprocess` accepts attacker-controlled FROST nonce commitments as canonical group elements without rejecting the identity element. A malicious signer can therefore submit `E = identity` and select `D` so that the aggregate FROST nonce `R` becomes the point at infinity. During Bitcoin Schnorr signing, `Hram::hram` calls `x(R)`, which unconditionally expects an x-coordinate and panics on infinity. This turns an invalid preprocess into a process crash instead of a `FrostError`.

### Finding Description
The preprocess parser reads two commitment points for each required nonce generator and accepts any canonical group encoding: [1](#0-0) [2](#0-1) 

For Bitcoin transactions, `TransactionSignMachine::read_preprocess` exposes this parser to each participant’s serialized preprocess: [3](#0-2) 

During `sign`, FROST transcript-binds all participant preprocesses, calculates the binding factors, and aggregates each participant’s `D + rho * E` contribution into `Rs`: [4](#0-3) 

The Bitcoin Schnorr algorithm then calls `Hram::hram` with `nonce_sums[0][0]`: [5](#0-4) 

`Hram::hram` passes that aggregate nonce to `x`, which calls `encoded.x().expect("point at infinity")`; therefore an identity aggregate nonce panics: [6](#0-5) [7](#0-6) 

Because `read_G` permits a canonical identity encoding and the preprocess is attacker-controlled, the malicious participant can make the aggregate nonce identity by setting `E` to identity and setting `D` to the negation of the sum of all other participants’ bound nonce commitments. The participant can calculate that value because the binding-factor transcript commits to the public group key, message hash, and serialized preprocesses before deriving each `rho`.

### Impact Explanation
A participant able to submit a preprocess for a Bitcoin transaction-signing session can crash the local signing task or process when the honest signer calls `sign`. This bypasses the intended `Result<_, FrostError>` error path and denies service to the signing operation.

### Likelihood Explanation
The attacker only needs the ability to participate in a signing session and send a malformed preprocess. The required points are public and deterministic once the message, participant set, and preprocesses are known, so no private key material or protocol violation beyond sending the crafted preprocess is required.

### Recommendation
Reject identity points in `Ciphersuite::read_G`, or reject identity commitments and identity aggregate nonces in FROST before calling `sign_share`. At minimum, `Hram::hram` and `x_only` should return an error or `Option` rather than panic when passed the point at infinity.

### Proof of Concept
For a one-generator Schnorr preprocess, each malicious contribution has the form:

```text
R_i = D_i + rho_i * E_i
```

The attacker calculates the honest aggregate contribution `R_h` from the public preprocesses and submits:

```text
E_i = identity
D_i = -R_h
```

Then:

```text
R = R_h + D_i + rho_i * E_i
  = R_h - R_h + rho_i * identity
  = identity
```

When `AlgorithmSignMachine::sign` reaches `Schnorr::sign_share`, `Hram::hram(&identity, ...)` calls `x(&identity)`, which panics at `encoded.x().expect("point at infinity")`.

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
