The `appName` and `description` fields on `IRefCheck` originate from `apiCheckRunToRefCheck` [1](#0-0)  and are only ever consumed in two ways in this codebase:

1. As a string comparison key for UI grouping (`checkRun.appName === 'GitHub Code Scanning'`) [2](#0-1) , which is a pure in-memory comparison, not serialization.
2. As React text content rendered via `{description}` inside a `<div>` in `CICheckRunListItem.renderCheckRunName` [3](#0-2) , which React escapes/renders as a text node, not raw HTML or a shell/file write.

A repo-wide search for `appName` shows only two other unrelated usages in `app/src/lib/auth.ts` and `app/src/lib/ssh/ssh-credential-storage.ts`, which are distinct identifiers (application name for OAuth/SSH keychain, not related to `IRefCheck.appName`) [4](#0-3) . There is no code path where `IRefCheck.appName` or `.description` is written to `.git/config`, any other config file, or passed as an argument to a spawned process (e.g., via `GitProcess`/`spawn`). The value never leaves the render tree.

This does not meet the "Valid Impact" criteria (no file write, no process argv corruption, no credential exfiltration, no IPC escape) — it's a pure display-only data flow.
