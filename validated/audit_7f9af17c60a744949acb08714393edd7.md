### Title
Hookify `conditions` list parser silently drops the `field:` key on malformed indentation, causing block/deny rules to never match — silent bypass of `rm -rf`-style guardrails ([File: plugins/hookify/core/config_loader.py])

### Summary
`extract_frontmatter`'s hand-rolled indentation state machine uses a fragile `indent > 2` heuristic to decide whether a line continues the current `conditions` dict item. When the `field:` sub-key of a condition is written on a continuation line with indentation ≤2 chars (e.g. a single tab, or 1–2 spaces instead of ≥3), the line matches none of the parser's branches and is silently dropped, leaving `Condition.field == ''`. This causes `RuleEngine._extract_field` to return `None` and `_check_condition` to always return `False`, so the rule (even one written to `action: block` on `rm -rf`) never fires, with no error, warning, or load failure surfaced anywhere.

### Finding Description
`extract_frontmatter` in `plugins/hookify/core/config_loader.py` parses `conditions:` list items with three branches keyed purely on raw character-count indentation and line prefix: [1](#0-0) 

- A dash-prefixed line (`- field: command`) is always parsed correctly regardless of indentation, because the branch condition is `stripped.startswith('-') and in_list` (no indent check).
- A **continuation** line (a sub-key placed on its own line under a dash item, e.g. `    field: command` written under a bare `-` or after `- pattern: rm -rf`) is only merged into the current dict if `indent > 2` (character count via `len(line) - len(line.lstrip())`, not visual width): [2](#0-1) 

If that continuation line uses a single tab (character count = 1) or only 1–2 spaces instead of ≥3, it satisfies none of the three branches (`indent==0` is false, it doesn't start with `-`, and `indent > 2` is false), so the line is discarded entirely — no error, no warning, no exception.

Concretely, a rule file such as:
```yaml
conditions:
  - operator: regex_match
	field: command
    pattern: rm -rf
```
(where the `field:` line uses one leading tab) produces `current_dict = {'operator': 'regex_match', 'pattern': 'rm -rf'}` with `field` missing. `Condition.from_dict` then defaults the missing key to `''`: [3](#0-2) 

In `RuleEngine._extract_field`, an empty `field` string matches none of the lookup branches (`tool_input` keys, Stop-event fields `reason`/`transcript`/`user_prompt`, or the Bash `command` special-case), so it falls through to `return None`: [4](#0-3) 

`_check_condition` treats `field_value is None` as an immediate non-match: [5](#0-4) 

and `_rule_matches` requires **all** conditions to match, so the whole rule permanently never fires: [6](#0-5)  `load_rule_file` loads this malformed-but-syntactically-valid rule successfully (no exception is raised, since `current_dict` remains a dict), so `hookify.*.local.md` load with zero diagnostics: [7](#0-6) 

This is a genuinely silent failure: the rule file, its `name`, its message text, and its apparent `field: command` / `pattern: rm -rf` intent all look correct to a human reviewer, but the guardrail is inert. `.claude/hookify.*.local.md` rule files are ordinary repository content (documented as being authored via the `/hookify` slash command and skill guidance [8](#0-7) ), so an attacker contributing such a rule file in a PR (e.g. framed as "adds a safety rule to block `rm -rf`") can plant a rule that a maintainer believes protects them, while it never actually blocks anything once merged and loaded by `plugins/hookify/hooks/pretooluse.py`/`posttooluse.py`.

### Impact Explanation
This defeats a user-configured safety guardrail (a `block`-action Hookify rule) with no observable indication of failure — the rule shows up as "enabled" in `/hookify list`, and no error/warning is ever printed. The practical impact is that a dangerous command (e.g. `rm -rf`) the victim believes is blocked by their own guardrail passes straight through PreToolUse/PostToolUse enforcement and executes. This matches a trust-boundary/guardrail-bypass class of impact: an intended enforcement mechanism (block on dangerous command) is silently disabled by attacker-supplied repository content (a crafted rule file), enabling unauthorized command execution the user explicitly tried to prevent.

### Likelihood Explanation
Preconditions: the attacker must get a `.claude/hookify.*.local.md` file (or a modification to one) with subtly broken indentation (a single tab or 1–2-space continuation line) merged into the target repository — e.g., via a PR contributing "additional safety rules." Because the bug produces zero diagnostics and the rule file otherwise reads as intentional and correct, it is plausible to slip past normal code review, especially since tabs/spaces mixing is visually indistinguishable in many editors/diff viewers. This is a purely content-based attack (no privilege escalation, no admin access, no secrets) reachable through ordinary repository/PR content, matching the allowed attack surface. Repeatability is deterministic: the same malformed file always produces the same silent non-match behavior.

### Recommendation
Replace the hand-rolled `extract_frontmatter` indentation state machine with a real YAML parser (e.g. `yaml.safe_load`) for the frontmatter block, eliminating tab/indent-count ambiguity entirely. If a lightweight parser must be retained, at minimum: (1) normalize/reject tabs in frontmatter, (2) track indentation relative to the parent list item's column rather than an absolute magic constant (`> 2`), and (3) raise a hard error (not a silent skip) when a line under `in_list`/`in_dict_item` context doesn't match any recognized continuation form, so `load_rule_file` surfaces a warning and the rule is not silently treated as valid-but-inert. Additionally, `Condition.from_dict`/`Rule.from_dict` should validate that required fields (`field`, `pattern`) are non-empty and reject/warn on a `block`-action rule whose conditions can never match a non-empty field.

### Proof of Concept
Unit test in `plugins/hookify/core/` test suite (or ad hoc script) exercising `extract_frontmatter` + `Rule.from_dict` + `RuleEngine`:

```python
from hookify.core.config_loader import extract_frontmatter, Rule
from hookify.core.rule_engine import RuleEngine

malformed_rule = (
    "---\n"
    "name: block-dangerous-rm\n"
    "enabled: true\n"
    "event: bash\n"
    "action: block\n"
    "conditions:\n"
    "  - operator: regex_match\n"
    "\tfield: command\n"          # single tab -> indent==1, silently dropped
    "    pattern: rm -rf\n"
    "---\n"
    "Blocked dangerous rm -rf command.\n"
)

fm, msg = extract_frontmatter(malformed_rule)
rule = Rule.from_dict(fm, msg)

# BUG: field is silently empty instead of "command"
assert rule.conditions[0].field == ''  # should be 'command'
assert rule.conditions[0].pattern == 'rm -rf'  # pattern survived

engine = RuleEngine()
result = engine.evaluate_rules([rule], {
    "hook_event_name": "PreToolUse",
    "tool_name": "Bash",
    "tool_input": {"command": "rm -rf /"}
})

# BUG: rule never blocks the dangerous command, despite action: block
assert result == {}
```

Differential-fuzz extension: generate randomized indentation (tabs, 1–2 spaces, mixed) for the `field:`/`pattern:`/`operator:` continuation lines of `conditions` entries, parse with both `extract_frontmatter` and `yaml.safe_load`, and assert that every resulting `Condition(field, operator, pattern)` triple is identical between the two parsers for all shipped block rules (`rm -rf`, `.env` writes, etc.); flag any input where `extract_frontmatter` silently drops a key that PyYAML correctly parses.

def load_rule_file(file_path: str) -> Optional[Rule]:
    """Load a single rule file.

    Returns:
        Rule object or None if file is invalid.
    """
    try:
        with open(file_path, 'r') as f:
            content = f.read()

        frontmatter, message = extract_frontmatter(content)

        if not frontmatter:
            print(f"Warning: {file_path} missing YAML frontmatter (must start with ---)", file=sys.stderr)
            return None

        rule = Rule.from_dict(frontmatter, message)
        return rule

    except (IOError, OSError, PermissionError) as e:
        print(f"Error: Cannot read {file_path}: {e}", file=sys.stderr)
        return None
    except (ValueError, KeyError, AttributeError, TypeError) as e:
        print(f"Error: Malformed rule file {file_path}: {e}", file=sys.stderr)
        return None
    except UnicodeDecodeError as e:
        print(f"Error: Invalid encoding in {file_path}: {e}", file=sys.stderr)
        return None
    except Exception as e:
        print(f"Error: Unexpected error parsing {file_path} ({type(e).__name__}): {e}", file=sys.stderr)
        return None

    def _extract_field(self, field: str, tool_name: str,
                      tool_input: Dict[str, Any], input_data: Dict[str, Any] = None) -> Optional[str]:
        """Extract field value from tool input or hook input data.

        Args:
            field: Field name like "command", "new_text", "file_path", "reason", "transcript"
            tool_name: Tool being used (may be empty for Stop events)
            tool_input: Tool input dict
            input_data: Full hook input (for accessing transcript_path, reason, etc.)

        Returns:
            Field value as string, or None if not found
        """
        # Direct tool_input fields
        if field in tool_input:
            value = tool_input[field]
            if isinstance(value, str):
                return value
            return str(value)

        # For Stop events and other non-tool events, check input_data
        if input_data:
            # Stop event specific fields
            if field == 'reason':
                return input_data.get('reason', '')
            elif field == 'transcript':
                # Read transcript file if path provided
                transcript_path = input_data.get('transcript_path')
                if transcript_path:
                    try:
                        with open(transcript_path, 'r') as f:
                            return f.read()
                    except FileNotFoundError:
                        print(f"Warning: Transcript file not found: {transcript_path}", file=sys.stderr)
                        return ''
                    except PermissionError:
                        print(f"Warning: Permission denied reading transcript: {transcript_path}", file=sys.stderr)
                        return ''
                    except (IOError, OSError) as e:
                        print(f"Warning: Error reading transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
                    except UnicodeDecodeError as e:
                        print(f"Warning: Encoding error in transcript {transcript_path}: {e}", file=sys.stderr)
                        return ''
            elif field == 'user_prompt':
                # For UserPromptSubmit events
                return input_data.get('user_prompt', '')

        # Handle special cases by tool type
        if tool_name == 'Bash':
            if field == 'command':
                return tool_input.get('command', '')

        elif tool_name in ['Write', 'Edit']:
            if field == 'content':
                # Write uses 'content', Edit has 'new_string'
                return tool_input.get('content') or tool_input.get('new_string', '')
            elif field == 'new_text' or field == 'new_string':
                return tool_input.get('new_string', '')
            elif field == 'old_text' or field == 'old_string':
                return tool_input.get('old_string', '')
            elif field == 'file_path':
                return tool_input.get('file_path', '')

        elif tool_name == 'MultiEdit':
            if field == 'file_path':
                return tool_input.get('file_path', '')
            elif field in ['new_text', 'content']:
                # Concatenate all edits
                edits = tool_input.get('edits', [])
                return ' '.join(e.get('new_string', '') for e in edits)

        return None
