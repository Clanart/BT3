### Title
Unvalidated attacker-controlled `bypassURL` from git push error output opened via `shell.openExternal` - (File: `app/src/ui/dispatcher/error-handlers.ts`, `app/src/ui/lib/link-button.tsx`)

### Summary
The external report's bug class is "an attacker/protocol-controlled parameter is consumed without any validation or bounds check, letting it drive unsafe downstream behavior." The closest real analog in GitHub Desktop is the secret-scanning push-protection flow: the `bypassURL` value is extracted via regex directly from the git remote's rejection message (`stderr`) with no format/host/scheme validation, then handed unmodified to `shell.openExternal()` when the "Bypass" link is clicked.

### Finding Description
When a push is rejected, Desktop's `secretScanningPushProtectionErrorHandler` calls `extractSecretScanningResults(remoteMessage)`, which regex-parses the raw `stderr` text returned by the git remote to build `ISecretScanResult` objects, including a `bypassURL` field taken verbatim from the message: [1](#0-0) [2](#0-1) 

There is no validation that `bypassURL` (or `id`, derived from `bypassURL.split('/').pop()`) is an `https://github.com/...` (or configured GHE endpoint) URL — any string matching the loose regex is accepted as-is: [3](#0-2) [4](#0-3) 

When `secret.requiresApproval` is true, the UI renders this untrusted `bypassURL` as a clickable link: [5](#0-4) 

`LinkButton` unconditionally forwards whatever `uri` it is given to `shell.openExternal(uri)` on click, with no scheme allow-list (e.g. restricting to `http:`/`https:`) or host check: [6](#0-5) 

Because `remoteMessage` originates from the git server's push response, an attacker who controls (or MITMs / proxies) the git remote — a threat actor explicitly in-scope per the "attacker controls ... a git remote/proxy response" impact criterion — can craft a fake secret-scanning rejection message that satisfies `secretsRegex`/`locationsRegex` and embeds an arbitrary URL/URI as the "bypass" link, which Desktop will present as a legitimate GitHub "Bypass" action.

### Impact Explanation
Unlike the token-award report's issue (an out-of-range timestamp merely delaying a repurchase), this path allows a malicious git remote to fully control a value that is later passed unsanitized to the OS-level `shell.openExternal`. Electron's `shell.openExternal` can invoke arbitrary registered URL-scheme handlers (not just `http/https`), so a hostile remote could point `bypassURL` at another custom protocol handler registered on the user's machine, or at a convincing phishing page masquerading as GitHub's push-protection bypass approval UI, to harvest credentials or session tokens — satisfying the "link ... the user clicks" and "credential/token exfiltration" impact classes. There is no analog of the `MinimumInterval`/upper-bound-style guard present in `background-fetcher.ts` for this URL; existing guards (regex "shape" matching) do not constrain the resulting string to a safe scheme or origin.

### Likelihood Explanation
Requires the user to push to a repository whose remote (or a MITM/compromised proxy in front of it) is attacker-controlled, and to click the resulting "Bypass" link — a plausible scenario for anyone cloning/adding a malicious or compromised remote, consistent with the allowed "attacker controls ... a git remote/proxy response" threat model, and requires only a single natural click on a UI element that looks like part of the normal GitHub Desktop workflow.

### Recommendation
Validate `bypassURL` (and any URL derived from git server output) against an allow-list of expected origins (the account's GitHub.com/GHE endpoint) and scheme (`https:` only) before storing it in `ISecretScanResult` or handing it to `LinkButton`/`shell.openExternal`. Consider adding the same defensive validation used elsewhere in the codebase (e.g., `isValidBYOKBaseUrl` pattern) to `extractSecretScanningResults`, rejecting or stripping any `bypassURL` that does not match the expected GitHub secret-scanning bypass URL shape/host.

### Proof of Concept
1. Set up (or MITM/proxy) a git remote so that a `git push` is rejected with a crafted `stderr` payload shaped to match `secretsRegex`/`locationsRegex` in `extractSecretScanningResults`, but with `bypassURL` replaced by an attacker-chosen URL/URI (e.g., a phishing page mimicking GitHub, or another registered custom protocol handler).
2. Push from GitHub Desktop against this remote; `secretScanningPushProtectionErrorHandler` parses the fake rejection and opens the `PushProtectionError` dialog with `requiresApproval: true` for the crafted secret.
3. The dialog renders a "Bypass" `LinkButton` with `uri={secret.bypassURL}` (the attacker's URL).
4. The user clicks "Bypass"; `LinkButton.onClick` calls `shell.openExternal(uri)` unconditionally, opening the attacker-controlled URL/handler instead of a genuine GitHub bypass-approval page.

```typescript
function extractSecretScanningResults(
  remoteMessage: string
): ReadonlyArray<ISecretScanResult> {
  const secretsRegex =
    /—— (?<description>.*?) —+[\s\S]*?locations:(?<locationsGroup>(?:\s+- commit: [a-f0-9]{40}\s+path: [\s\S]*?)+).*?(?<bypassURL>https[\s\S]*?) /g

  const matches = [...remoteMessage.matchAll(secretsRegex)]

  const secrets: Array<ISecretScanResult> = []
  if (matches.length === 0) {
    return secrets
  }

  for (const match of matches) {
    if (match.groups === undefined || match.index === undefined) {
      continue
    }

    const { bypassURL, description, locationsGroup } = match.groups

    const locationsRegex =
      /- commit: (?<commitSha>[a-f0-9]{40})\s+path: (?<path>.*?):(?<lineNumber>\d+)/g
    const locationMatches = [...locationsGroup.matchAll(locationsRegex)]

    const locations: ISecretLocation[] = []

    locationMatches.forEach(locationMatch => {
      if (locationMatch.groups === undefined) {
        return
      }
      const { commitSha, path, lineNumber } = locationMatch.groups
      locations.push({
        commitSha,
        path,
        lineNumber: parseInt(lineNumber, 10),
      })
    })

    secrets.push({
      id: bypassURL.split('/').pop() || '',
      description,
      bypassURL,
      locations,
      requiresApproval: !!match.at(0)?.includes('request an exemption'),
    })
  }

  return secrets
```

```typescript
export async function secretScanningPushProtectionErrorHandler(
  error: Error,
  dispatcher: Dispatcher
) {
  const e = asErrorWithMetadata(error)
  if (!e) {
    return error
  }

  const gitError = asGitError(e.underlyingError)
  if (gitError?.result.gitError !== DugiteError.PushWithSecretDetected) {
    return error
  }

  const remoteMessage = getRemoteMessage(coerceToString(gitError.result.stderr))
  const secrets = extractSecretScanningResults(remoteMessage)

  dispatcher.incrementMetric('pushBlockedBySecretScanningCount')
  dispatcher.incrementMetric('secretsDetectedOnPushCount', secrets.length)

  dispatcher.showPopup({
    type: PopupType.PushProtectionError,
    secrets,
  })

  return null
}
```
