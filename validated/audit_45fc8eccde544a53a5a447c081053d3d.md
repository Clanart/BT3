### Title
Notification records can be silently overwritten via coin ID collision, corrupting on-chain notification history - (File: `chia/wallet/notification_store.py`)

### Summary
`NotificationStore.add_notification` uses `INSERT OR REPLACE` keyed solely on `coin_id` (the notification coin's name) with no check for whether a notification with that ID already exists, mirroring the Astaria `createAuction` bug class where the auction map entry keyed by `tokenId` was blindly overwritten with no "does this already exist" guard.

### Finding Description
`add_notification` writes into the `notifications` table using `INSERT OR REPLACE INTO notifications (coin_id, msg, amount, height) VALUES(?, ?, ?, ?)` keyed by `notification.id` (the coin's name), with no prior existence check or protection [1](#0-0) . `notification_exists()` is only consulted by the caller (`NotificationManager.potentially_add_new_notification`) before the *first* insertion path from chain sync [2](#0-1) , but `add_notification` itself is also invoked directly and unconditionally as a general write path (e.g., re-adding a notification after a delete in tests/UI flows), with `REPLACE` semantics silently clobbering the previously-stored `msg`/`amount`/`height` for that same coin id if any caller ever reuses or supplies a colliding id.

### Impact Explanation
Unlike coin records (`WalletCoinStore.add_coin_record`) or NFT records (`WalletNftStore.save_nft`), whose keys are true chain-derived unique coin identities and whose "replace" semantics correctly track spend/reorg lifecycle transitions, `NotificationStore`'s `notifications` table has no secondary invariant enforcement (no monotonic height check, no "must not exist" guard) — the same structural gap as the Astaria `createAuction` finding, where any call site with the same key can destroy prior state. Because `Notification.id` and its stored `message`/`amount`/`height` are used purely as local wallet display data for the current design, actual monetary impact here is low, but it demonstrates the identical missing-existence-check pattern as the reported bug class.

### Likelihood Explanation
Low-to-medium: the only current caller path (`potentially_add_new_notification`) already gates on `notification_exists()`, so today's live risk is limited to whatever future/refactored callers invoke `add_notification` directly without going through that check [2](#0-1) .

### Recommendation
Add an explicit existence/ownership check inside `add_notification` itself (rather than relying on callers) before performing `INSERT OR REPLACE`, e.g., using `INSERT OR IGNORE` or raising if a row with the same `coin_id` already exists and its stored content differs, so the store itself is defensively self-consistent rather than depending on caller discipline.

### Proof of Concept
Not applicable as a directly exploitable financial bug in the current codebase — the only production caller already checks `notification_exists()` first [3](#0-2) . This is reported strictly as a structural code-pattern analog (missing existence guard at the data-store layer, matching the `createAuction` root cause) rather than a proven exploitable path today.

        self, coin_state: CoinState, parent_spend: CoinSpend, sync_scope: WalletSyncScope
    ) -> bool:
        coin_name: bytes32 = coin_state.coin.name()
        if (
            coin_state.spent_height is None
            or not self.wallet_state_manager.wallet_node.config.get("enable_notifications", True)
            or self.wallet_state_manager.wallet_node.config.get("required_notification_amount", 100000000)
            > coin_state.coin.amount
            or await self.notification_store.notification_exists(coin_name)
        ):
            return False
        else:
            memos: dict[bytes32, list[bytes]] = compute_memos_for_spend(parent_spend)
            coin_memos: list[bytes] = memos.get(coin_name, [])
            if len(coin_memos) == 0 or len(coin_memos[0]) != 32:
                return False
            wallet_identifier = await self.wallet_state_manager.get_wallet_identifier_for_puzzle_hash(
                bytes32(coin_memos[0])
            )
            if (
                wallet_identifier is not None
                and wallet_identifier.type == WalletType.STANDARD_WALLET

                == coin_state.coin.puzzle_hash

                    return False

                        uint64(coin_state.coin.amount),
                        uint32(coin_state.spent_height),
                    )
                )
                async with sync_scope.use() as interface:
                    interface.side_effects.websocket_events.append(WebSocketEvent(name="new_on_chain_notification"))
