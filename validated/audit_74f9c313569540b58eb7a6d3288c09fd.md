### Title
Unrecovered panic in CW→ERC pointer registration crashes/reverts on attacker-controlled contract responses - (File: precompiles/pointer/pointer.go)

### Summary
The `pointer` precompile's `AddCW20`, `AddCW721`, and `AddCW1155` handlers perform unchecked type assertions (`formattedRes["name"].(string)`, `formattedRes["symbol"].(string)`) on JSON returned by an arbitrary, attacker-controlled CosmWasm contract's smart query, without validating the field types or presence first.

### Finding Description
`AddCW20` calls `p.wasmdKeeper.QuerySmartSafe(ctx, cwAddress, []byte("{\"token_info\":{}}"))` against a CosmWasm contract address supplied directly by the caller (`args[0].(string)`), unmarshals the raw JSON response into `map[string]interface{}{}`, and then does: [3](#0-2) 
If the target contract is not an actual CW20 contract but any wasm contract crafted by the attacker (any user can deploy such a contract via CosmWasm), the `"token_info"` query can return arbitrary JSON. If the JSON omits `"name"`/`"symbol"`, or returns non-string types (numbers, objects, null), `formattedRes["name"]` is `nil` (or a non-string `interface{}`), and the bare type assertion `.(string)` panics with `interface conversion: interface {} is nil, not string` (or similar). The identical pattern exists in `AddCW721` [4](#0-3)  and `AddCW1155` [5](#0-4) , all reachable by any unprivileged CosmWasm/EVM user calling `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` on the pointer precompile, or via `MsgRegisterPointer` handled in `x/evm/keeper/msg_server.go`, against a contract they themselves deployed.

Critically, the call path for this precompile is `DynamicGasPrecompile.RunAndCalculateGas`, whose only panic-handling defer calls `HandlePrecompileError`, which merely records metrics and does not call `recover()`: [1](#0-0) [2](#0-1) . This is in contrast to several other precompiles (`addr`, `oracle`, `solo`) which explicitly wrap their `Execute` with `defer recover()` specifically to "catch gas meter panics" and convert them to reverts, e.g. [6](#0-5) . The `pointer` precompile's current `Execute` has no such guard [7](#0-6) .

This mirrors the CVE-2026-52022 bug class: an unbounded/unvalidated parse of attacker-influenced registration data causing a crash in the registration-handling code path, without proper bounds/type checking before use.

### Impact Explanation
If the panic propagates past `RunAndCalculateGas` without being caught by a Cosmos SDK-level ABCI recovery wrapper, it can crash the node processing the transaction (validator halting mid-block if hit during `DeliverTx`, or crashing a public RPC node during `eth_call`/`eth_estimateGas` simulation). Even if caught by an outer ABCI recovery handler, this represents a fragile, un-vetted panic path that an unprivileged user fully controls via a self-deployed CosmWasm contract, which is inconsistent with the defensive pattern used elsewhere in the same precompile family (`addr`, `oracle`, `solo`).

### Likelihood Explanation
High — deploying a malicious CW20/CW721/CW1155-look-alike contract that returns non-string or missing `name`/`symbol` fields from `token_info`/`contract_info` queries is trivial and requires no special privileges; the attacker only needs a wasm store/instantiate transaction and a subsequent pointer-registration call, both of which are permissionless.

### Recommendation
Replace the bare type assertions in `AddNative`... `AddCW1155` with safe, checked extraction (e.g., `name, ok := formattedRes["name"].(string); if !ok { return nil, 0, fmt.Errorf(...) }`), and/or add the same `defer recover()` guard used in `addr`/`oracle`/`solo` precompiles to `pointer.Execute` (and more broadly to `DynamicGasPrecompile.RunAndCalculateGas`) so any executor panic is converted into a reverted transaction rather than an unhandled panic.

### Proof of Concept
1. Deploy a CosmWasm contract whose `token_info` query handler returns `{"name": 12345, "symbol": null}` (or omits the fields).
2. Call the EVM `pointer` precompile's `addCW20Pointer(cwAddress)` (address `0x000000000000000000000000000000000000100b`), or send `MsgRegisterPointer{PointerType: ERC20, ErcAddress: <that contract>}`.
3. `QuerySmartSafe` succeeds and returns the crafted JSON; `json.Unmarshal` succeeds into `map[string]interface{}`; `formattedRes["name"].(string)` panics because the value is not a string.
4. Observe whether the panic is silently caught (turning into a failed tx, in which case severity is lower) or propagates and disrupts block processing / crashes the RPC node — this needs empirical verification in a running devnet, which was not possible from static code inspection alone.
