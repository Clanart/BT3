### Title
PlotNFT melt permanently strands unclaimed pool rewards - (File: chia/pools/plotnft_drivers.py)

### Summary
`PlotNFT.melt()` allows destroying (melting) a plotnft singleton via the standard Chialisp `-113` melt condition once it is not pooling. Pool rewards paid to the plotnft's `p2_singleton` puzzle hash (`RewardPuzzle`/`PoolReward`, keyed by `singleton_id`) can only be swept into the wallet by `PlotNFT2Wallet.claim_rewards()`, which requires spending the live plotnft singleton to send the authorizing `SEND_MESSAGE`/receive to the reward coin's `SingletonMember` puzzle. If the owner melts the singleton while unclaimed reward coins still exist at that `p2_singleton_puzzle_hash`, there is no longer a live singleton to authorize the claim spend, and those reward coins become permanently unspendable.

### Finding Description
`PlotNFT.melt()` only checks `self.pooling` before allowing the melt: [1](#0-0) 

It builds a delegated spend containing `CREATE_COIN (0 -113)` — the canonical singleton melt condition — with no check for outstanding, unclaimed `PoolReward` coins tracked for this `plotnft_id` (see `wallet_state_manager.plotnft2_store.get_pool_rewards`, used by `claim_rewards`): [2](#0-1) 

The reward puzzle a farming reward is paid to is a `SingletonMember` restriction requiring proof that the current plotnft singleton with matching `inner_puzzle_hash` is being spent in the same transaction: [3](#0-2) 

Once melted, the singleton coin no longer exists on-chain (its `SINGLETON_MOD` never re-creates an odd child), as confirmed by singleton-layer tests distinguishing normal spends (must create exactly one odd child) from melting (creates only even/no odd children intentionally): [4](#0-3) 

With the singleton gone, `claim_rewards()`'s dependency on `get_current_plotnft()` and `plotnft.claim_pool_rewards()` (which builds a `singleton_action_spend` to authorize each reward's `SingletonMember` solve) can never again be satisfied, because the required current-singleton spend cannot be produced.

### Impact Explanation
Any farming rewards paid to `p2_singleton_puzzle_hash` for a plotnft that have not yet been claimed at the moment the owner (or anyone who can trigger the melt path via the exposed RPC/CLI, since only `self.pooling` is checked) calls `melt()` become permanently locked, unspendable coins — a direct, irreversible loss of funds with no owner-only emergency recovery path, matching the reported bug class (funds locked with no rescue mechanism once the controlling entity — here the singleton, there the NFT — is destroyed). This is a Medium-severity fund-lock issue: it requires unclaimed rewards to exist at melt time, but users farming to a plot NFT can easily overlook pending, unclaimed reward coins before melting.

### Likelihood Explanation
Likelihood is moderate: any plotnft owner who calls `pw_absorb_rewards`/`claim_rewards` infrequently relative to farming (e.g., self-custody farming plots for a while before syncing/claiming) and then decides to melt the plotnft (e.g., to reclaim the 1-mojo coin or exit the pooling system entirely) will trigger this. `melt()` itself contains no guard checking `plotnft2_store.get_pool_rewards()` for outstanding rewards, so nothing in the driver or wallet layer prevents this footgun.

### Recommendation
Before allowing `PlotNFT.melt()` (or the corresponding wallet/RPC entry point) to proceed, check `wallet_state_manager.plotnft2_store.get_pool_rewards(plotnft_id)` for this plotnft and refuse (or force-claim) if any unclaimed reward coins are still pending, similar to how `claim_rewards()` already validates `pooling` state. Alternatively, warn/require an explicit confirmation in the CLI (`chia plotnft melt`) and RPC handler when outstanding rewards exist so users don't inadvertently strand funds.

### Proof of Concept
1. Create a `PlotNFT2Wallet` in self-custody (non-pooling) mode via `PlotNFT2Wallet.create_new` — [5](#0-4) .
2. Farm one or more blocks to `p2_singleton_puzzle_hash` so `PoolReward` coins accumulate, as exercised in `test_plotnft_self_custody_claim` — [6](#0-5) .
3. Instead of calling `claim_rewards`, call `plotnft.melt()` — [1](#0-0)  — and push the resulting spend bundle, destroying the singleton.
4. Attempt `claim_rewards()`/`claim_pool_rewards()` for the still-unspent `PoolReward` coins — this now fails permanently because `get_current_plotnft()` can no longer produce a live singleton coin to authorize the `SingletonMember` solve, leaving those reward coins forever unspendable.

@dataclass(kw_only=True, frozen=True)
class RewardPuzzle:
    singleton_id: bytes32

    @property
    def singleton_member(self) -> SingletonMember:
        return SingletonMember(singleton_id=self.singleton_id)

    def puzzle_with_restrictions(self) -> PuzzleWithRestrictions:
        return PuzzleWithRestrictions(nonce=0, restrictions=[], puzzle=self.singleton_member)

    def puzzle(self) -> Program:
        return self.puzzle_with_restrictions().puzzle_reveal()

    def puzzle_hash(self) -> bytes32:
        return self.puzzle().get_tree_hash()

    def solve(
        self, singleton_inner_puzzle_hash: bytes32, delegated_puzzle_and_solution: DelegatedPuzzleAndSolution
    ) -> Program:
        return self.puzzle_with_restrictions().solve(
            [],
            [],
            self.singleton_member.solve(singleton_inner_puzzle_hash),
            delegated_puzzle_and_solution,
        )

# PlotNFT claims pooling rewards while self custody
@pytest.mark.anyio
async def test_plotnft_self_custody_claim(cost_logger: CostLogger) -> None:
    async with sim_and_client() as (sim, sim_client):
        plotnft = await mint_plotnft(sim=sim, sim_client=sim_client, desired_state="self_custody")
        reward = await mint_reward(sim=sim, sim_client=sim_client, singleton_id=plotnft.singleton_struct.launcher_id)

        with pytest.raises(
            ValueError, match=re.escape("Cannot forward pool reward while self pooling. Try `claim_pool_rewards`")
        ):
            plotnft.forward_pool_reward(reward=reward)

        with pytest.raises(
            ValueError,
            match=re.escape("Number of rewards and delegated puzzles and solutions must match"),
        ):
            plotnft.claim_pool_rewards(rewards_to_claim=[reward], reward_delegated_puzzles_and_solutions=[])

        reward_dpuz_and_sol = DelegatedPuzzleAndSolution(
            puzzle=ACS, solution=Program.to([CreateCoin(bytes32.zeros, uint64(1)).to_program()])
        )
        coin_spends = plotnft.claim_pool_rewards(
            rewards_to_claim=[reward], reward_delegated_puzzles_and_solutions=[reward_dpuz_and_sol]
        )
        result = await sim_client.push_tx(
            cost_logger.add_cost(
                "Claim Pool Reward",
                WalletSpendBundle(
                    coin_spends,
                    sign_spend(coin_spends, sim.defaults.AGG_SIG_ME_ADDITIONAL_DATA),
                ),
            )
        )
        assert result == (MempoolInclusionStatus.SUCCESS, None)
        await sim.farm_block()

        # Make sure the pooling reward did what it was supposed to
        assert len(await sim_client.get_coin_records_by_puzzle_hash(bytes32.zeros)) == 1
