### Title
Unvalidated `foldername` RPC parameter allows arbitrary filesystem write via DataLayer `add_missing_files` - (File: chia/data_layer/data_layer_rpc_api.py)

### Summary
The DataLayer RPC endpoint `add_missing_files` accepts a caller-supplied `foldername` string and converts it directly into a `Path` object with no validation (no restriction to `server_files_location`, no canonicalization/containment check, no rejection of absolute paths or `..` traversal). That path is passed through to `DataLayer.add_missing_files()`, which then writes Merkle full-tree/delta `.dat` files to that arbitrary location on disk, mirroring the mechanics of CVE-2020-13941 where Solr's replication `location` parameter was used unchecked for backup/restore file writes.

### Finding Description
`DataLayerRpcApi.add_missing_files` reads `foldername` straight from the JSON RPC request and wraps it in `Path()`: [1](#0-0) 

That value flows into the service layer unchanged, where it becomes the target directory used for constructing full/delta file paths: [2](#0-1) 

The actual write happens in `write_files_for_root`, which builds file paths from the `foldername` argument, creates parent directories (`mkdir(parents=True, exist_ok=True)`), and opens files for writing without any check that the resolved path stays inside a permitted server-files directory: [3](#0-2) 

Unlike the DataLayer static HTTP server (`file_handler`/`folder_handler`), which validates filenames via `is_filename_valid()` before serving files, there is no equivalent validation on the `foldername` write path — the filename component is derived from the internal store id/hash/generation (safe), but the *directory* component is fully attacker/caller controlled and can point anywhere the daemon process has write access to (e.g., outside the DataLayer root, into other config/plugin directories, or via `..` traversal on the directory string). [4](#0-3) 

### Impact Explanation
Any caller with access to the DataLayer RPC (a local/unprivileged RPC caller, consistent with the "local RPC caller" reachability class named in the review rules) can direct `add_missing_files` to overwrite (with `overwrite=true`) or create files at attacker-chosen filesystem locations reachable by the DataLayer process, similar in class to the Solr replication `location` parameter allowing arbitrary read/write. This can be used to write files outside the intended `server_files_location` sandbox, potentially corrupting other service state or planting files in directories the DataLayer/S3 plugin processes later trust (e.g., other stores' folders, or paths reused by `insert_from_delta_file`/`add_missing_files` plugin flows), which can affect DataLayer state consistency.

### Likelihood Explanation
The `foldername` parameter is directly exposed on the `add_missing_files` RPC method with no path validation, and the RPC client itself passes an arbitrary caller-provided string (`str(foldername)`) with no sanitation, as seen in `chia/data_layer/data_layer_rpc_client.py` (`add_missing_files`) and the CLI wrapper `chia/cmds/data_funcs.py`. Any process capable of calling the DataLayer RPC (subject to normal daemon/keychain RPC authorization) can trigger this without further conditions.

### Recommendation
Validate and canonicalize `foldername` in `DataLayerRpcApi.add_missing_files` before use: resolve the path and require it be contained within an allow-listed base directory (e.g., `server_files_location` or a small set of explicitly configured locations), rejecting absolute/relative traversal outside that root, mirroring the strict filename validation already used by `is_filename_valid()` for the read path in `data_layer_server.py`.

### Proof of Concept
1. Start `chia data_layer` service and its RPC.
2. Call the `add_missing_files` RPC with a JSON body such as `{"ids": ["<owned store id>"], "overwrite": true, "foldername": "/tmp/attacker_dir"}` (or a relative path with `..` segments) instead of the default `server_files_location`.
3. Observe that `.dat` files are written under `/tmp/attacker_dir` (or the traversal target) rather than the sandboxed DataLayer server files directory, confirming the RPC caller controls an arbitrary write location. [1](#0-0) [2](#0-1) [3](#0-2)

async def write_files_for_root(
    data_store: DataStore,
    store_id: bytes32,
    root: Root,
    foldername: Path,
    full_tree_first_publish_generation: int,
    overwrite: bool = False,
    group_by_store: bool = False,

    if root.node_hash is not None:
        node_hash = root.node_hash
    else:
        node_hash = bytes32.zeros  # todo change

    filename_full_tree = get_full_tree_filename_path(foldername, store_id, node_hash, root.generation, group_by_store)
    filename_diff_tree = get_delta_filename_path(foldername, store_id, node_hash, root.generation, group_by_store)
    filename_full_tree.parent.mkdir(parents=True, exist_ok=True)

    written = False
    mode: Literal["wb", "xb"] = "wb" if overwrite else "xb"

    written_full_file = False
    if root.generation >= full_tree_first_publish_generation:

            await data_store.write_tree_to_file(root, node_hash, store_id, True, writer)
        written = True
    except FileExistsError:
        pass
