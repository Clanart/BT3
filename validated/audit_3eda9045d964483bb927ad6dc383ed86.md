### Title
TextFormat's `Any` bracket-notation printer emits attacker-controlled `type_url` bytes unescaped, enabling text-output structure injection/spoofing - ([File: src/google/protobuf/text_format.cc])

### Summary
The .NET advisory (CWE-116, "Improper Encoding or Escaping of Output") describes an SMTP client that fails to escape attacker-influenced content before embedding it in a structured output stream, letting the attacker forge/"spoof" message structure that a downstream consumer misinterprets. The Protobuf analog is `TextFormat::Printer::PrintAny` (C++) and `TextFormat.Printer.printAny` (Java): both print the `Any.type_url` string field **verbatim, unquoted, and unescaped** inside the `[...]` bracket construct used to represent expanded `Any` values, while every other string field in TextFormat output is quoted and escaped (`CEscape`/`TextFormatEscaper`). Since `type_url` is an ordinary attacker-controlled string field decoded from bounded binary/ProtoJSON input, an attacker can inject raw `]`, `{`, `}`, quotes, or newlines into the printed debug/text representation, forging fields that were never present in the original message when that text output is consumed by any downstream tool that treats it as structured data (logs re-parsed by TextFormat, audit pipelines, SIEM rules, etc.).

### Finding Description
`TextFormat::Printer::PrintAny` (`src/google/protobuf/text_format.cc:2527-2574`) resolves the `type_url`/`value` fields of an `Any` message, and if the value payload parses successfully against the registered type, prints:
```cpp
generator->PrintLiteral("[");
generator->PrintString(type_url);      // <-- raw, unescaped
generator->PrintLiteral("]");
``` [1](#0-0) 

Compare this to how every other STRING-typed field value is printed, via `FastFieldValuePrinter::PrintString`, which always quotes and conditionally `CEscape`s the content:
```cpp
generator->PrintLiteral("\"");
if (!val.empty()) {
  if (ABSL_PREDICT_FALSE(ContainsCharactersToCEscape(val))) {
    generator->PrintString(absl::CEscape(val));
  } else {
    generator->PrintString(val);
  }
}
generator->PrintLiteral("\"");
``` [2](#0-1) 

The same gap exists in the Java implementation, `TextFormat.Printer.printAny`:
```java
generator.print("[");
generator.print(typeUrl);   // <-- raw, unescaped
generator.print("]");
``` [3](#0-2) 
and this path is entered unconditionally whenever a message's full name is `google.protobuf.Any` (no opt-in flag), unlike C++ which is gated behind `expand_any_`:
```java
if (message.getDescriptorForType().getFullName().equals("google.protobuf.Any")
    && printAny(message, generator)) {
  return;
}
``` [4](#0-3) 

The failed invariant: TextFormat guarantees that every printed value is structurally quoted/escaped so the text stream cannot be reinterpreted as containing fields/values that weren't actually present. `PrintAny` violates this invariant for `type_url`.

The missing check: neither `internal::GetAnyFieldDescriptors` nor `internal::ParseAnyTypeUrl` (`src/google/protobuf/any_lite.cc:72-84`) constrain the character set of `type_url`. `ParseAnyTypeUrl` only requires a `/` character and returns everything before it as `url_prefix`:
```cpp
size_t pos = type_url.find_last_of('/');
if (pos == std::string::npos || pos + 1 == type_url.size()) return false;
if (url_prefix) *url_prefix = std::string(type_url.substr(0, pos + 1));
*full_type_name = std::string(type_url.substr(pos + 1));
``` [5](#0-4) 
There is no allow-list applied to `url_prefix` on the *printing* side. This is asymmetric with the TextFormat *parser* side, which does validate the prefix strictly (only URL characters, validated percent-encoding, identifier-only type name) in `ConsumeAnyTypeUrlOrFullTypeName` (`src/google/protobuf/text_format.cc:1384-1458`) — the printer never applies an equivalent check, nor does it fall back to quoting/escaping.

The attacker-controlled value: `type_url` is set directly from ordinary bounded binary protobuf (or ProtoJSON) sent to a public parse API — it is a plain proto3 `string` field, and protobuf's UTF-8 validation for `string` fields permits control characters, quotes, brackets, and newlines (only invalid UTF-8 byte sequences are rejected). The attacker only needs: (1) `type_url` to end in `/` + a fully-qualified name of a type present in the process's registered `TypeRegistry`/descriptor pool (attacker can pick any well-known trusted type, e.g. `google.protobuf.Empty`), and (2) the `value` bytes to parse successfully against that type (trivially satisfied by an empty byte string for a message with no required fields).

### Impact Explanation
This is an integrity/spoofing issue (CWE-116 class, matching the referenced CVE), not a memory-safety bug: an attacker who controls the *content* of a message that an application converts to TextFormat for logging, auditing, debugging, or inter-service diagnostic exchange can forge additional "fields" or premature message terminators in that textual representation. Any downstream consumer that treats the emitted TextFormat string as trustworthy structured data (e.g., feeding debug logs back through `TextFormat::Parse`, log-scraping tools that key off field names/values, SIEM detection rules) can be spoofed into observing fabricated field/value pairs that were never in the original message, or into having the visible message boundary closed early. This mirrors the SMTP advisory's "spoof messages during message routing" impact: the downstream routing/consuming logic is not fooled by binary bit corruption, but by unescaped attacker text riding inside a supposed-quoted/delimited slot.

### Likelihood Explanation
Requires only: (a) an application that logs/prints attacker-influenced messages containing an `Any` field via `TextFormat::PrintToString`/`DebugString` (a very common debugging/audit pattern) with `expand_any_`/Any-expansion enabled (unconditional in Java, opt-in in C++ but commonly enabled for readability of Any fields), (b) the attacker being able to choose the `Any.type_url` and provide a `value` that parses against some registered, trusted type. No privileged access or schema tampering is needed — the attacker simply crafts an ordinary binary protobuf payload through a supported public parse API. This is a Medium-severity, narrowly scoped analog: it's real and reachable, but its exploitability depends on the specific downstream consumer treating printed text as machine-parsed structured data, which is an application-level assumption outside Protobuf's control.

### Recommendation
Escape (or at minimum quote) the `type_url` value the same way ordinary STRING fields are escaped before writing it between `[` and `]` in `TextFormat::Printer::PrintAny` (C++, `text_format.cc:2564-2566`) and `TextFormat.Printer.printAny` (Java, `TextFormat.java:459-461`), or reject/refuse Any-expansion when `type_url` contains characters outside the URL character set validated by the TextFormat parser (`ConsumeAnyTypeUrlOrFullTypeName`). Apply the same fix to any other language binding that implements bracket-notation Any printing (Python's `_TryPrintAsAnyMessage` in `text_format.py:429-444` has the identical unescaped `'%s[%s]%s '` pattern and should be checked/fixed as well).

### Proof of Concept
Construct a binary-encoded `google.protobuf.Any` message where:
- `type_url` = `type.googleapis.com/x] injected_field: "PWNED"\n[google.protobuf.Empty` (contains an embedded `]`, newline, and a fabricated field/value, followed by a valid trailing type name segment `google.protobuf.Empty` after the last `/`)
- `value` = empty byte string (a valid, trivially-parseable serialization of `google.protobuf.Empty`)

When an application decodes this `Any` from untrusted binary input and calls `TextFormat::PrintToString`/`DebugString` (C++) or `TextFormat.printer().printToString(...)` (Java) with Any-expansion enabled, `PrintAny` resolves `google.protobuf.Empty` successfully (satisfying `internal::ParseAnyTypeUrl` and `finder_->FindAnyType`), and emits:
```
[type.googleapis.com/x] injected_field: "PWNED"
[google.protobuf.Empty] {
}
```
which contains an attacker-forged `injected_field: "PWNED"` line and an extra premature `]` — text that did not exist as an actual field in the original message and that a naive downstream text-based consumer would interpret as legitimate structured content. I was not able to execute this against a live build in this environment; this is a source-level trace confirming the missing-escape code path (`text_format.cc:2564-2566`, `TextFormat.java:459-461`) and the unconstrained `ParseAnyTypeUrl` (`any_lite.cc:72-84`), not a verified runtime reproduction — a Devin session with repository access would be needed to compile and run the exact PoC.

bool ParseAnyTypeUrl(absl::string_view type_url,
                     std::string* PROTOBUF_NULLABLE url_prefix,
                     std::string* PROTOBUF_NONNULL full_type_name) {
  size_t pos = type_url.find_last_of('/');
  if (pos == std::string::npos || pos + 1 == type_url.size()) {
    return false;
  }
  if (url_prefix) {
    *url_prefix = std::string(type_url.substr(0, pos + 1));
  }
  *full_type_name = std::string(type_url.substr(pos + 1));
  return true;
}
