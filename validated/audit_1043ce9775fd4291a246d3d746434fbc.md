## Title
Unauthorized minting of native coins via self-reported `balanceOf` on malicious permissionlessly-registered native ERC20 tokens - (File: `x/erc20/keeper/msg_server.go`)

### Summary
The `x/erc20` module allows any account to permissionlessly register an arbitrary externally-deployed ERC20 contract as a "native ERC20" token pair, and then convert that ERC20 balance into freshly-minted native Cosmos coins. The conversion logic in `convertERC20IntoCoinsForNativeToken` verifies that tokens were "escrowed" purely by re-querying the same untrusted contract's own `balanceOf()` (via `BalanceOf`) before and after calling its `transfer()` method, rather than relying on any independent, module-tracked accounting of the contract's true token movement. A malicious contract can trivially fabricate its `balanceOf()`/`transfer()` responses to make this self-consistency check pass without ever escrowing real value, letting the attacker mint unlimited native Cosmos coins.

### Finding Description
This is the same root-cause class as the reported GigaNameNFT issue: the caller-controlled/contract-controlled data (token IDs assumed to equal supply, or here, ERC20 `balanceOf`/`transfer` return values) is trusted as the source of truth for supply/escrow accounting instead of an independent invariant enforced by the privileged module.

Flow:
1. Any account can call `RegisterERC20` to register an arbitrary contract address as a token pair when `PermissionlessRegistration` is enabled (default-permitted path) [1](#0-0) . Registration only queries the contract's declared name/symbol/decimals via `CreateCoinMetadata`/`QueryERC20`, with no bytecode validation beyond ABI compliance [2](#0-1) .
2. The attacker calls `ConvertERC20` with this contract, which routes to `convertERC20IntoCoinsForNativeToken` [3](#0-2) .
3. Inside `convertERC20IntoCoinsForNativeToken`, the "escrow" check only compares the module address's ERC20 `balanceOf()` before and after invoking the contract's own `transfer()` function [4](#0-3) . Since the ERC20 contract is entirely attacker-supplied bytecode, `balanceOf()` and `transfer()` can be implemented to always report the exact expected post-transfer balance regardless of whether real tokens moved.
4. Once this self-reported check "passes," the keeper unconditionally mints native coins with `k.bankKeeper.MintCoins` and sends them to the receiver [5](#0-4) .

There is no module-side ledger (e.g., an independently tracked escrowed-token counter per token pair) that is enforced against the untrusted contract's self-reported state — mirroring the GigaNameNFT bug where supply/ID assumptions were trusted from an untrusted or improperly-tracked source instead of a keeper-maintained `totalSupply`/escrow accounting.

### Impact Explanation
An unprivileged attacker can mint unlimited native Cosmos coins (bank module `MintCoins`) for any denomination created through this ERC20-to-coin conversion path, with no real backing value ever escrowed. This directly corrupts the 1:1 accounting invariant between "escrowed" ERC20 tokens and minted native coins, enabling unauthorized minting of spendable value — a Critical impact per the allowed impact gate (unauthorized minting / accounting corruption of spendable user value across native balances / token-pair-backed balances).

### Likelihood Explanation
Likelihood is high: registering a native ERC20 token pair is permissionless (`PermissionlessRegistration`) and requires only deploying an ordinary EVM contract implementing a few crafted view/transfer functions — no privileged role, validator collusion, or governance action is required. The attacker fully controls the ERC20 contract's bytecode, so faking `balanceOf`/`transfer` responses is trivial.

### Recommendation
Do not derive escrow/supply proofs solely from the untrusted contract's own `balanceOf`/`transfer` return values. Instead:
- Independently verify token movement using EVM `Transfer` event logs emitted by the actual token contract (validating `from`, `to`, and `amount` match expectations) rather than trusting a second self-reported `balanceOf` call to the same untrusted contract.
- Consider restricting native ERC20 registration to a governance-vetted allowlist, or requiring bytecode/behavior verification (e.g., diffing against a known-safe reference implementation like the bundled `ERC20MinterBurnerDecimalsContract`) before permissionless registration is allowed.
- Maintain an internal, keeper-tracked escrow ledger per token pair as the authoritative record backing native coin minting, instead of relying exclusively on live queries into arbitrary contract code.

### Proof of Concept
1. Deploy a malicious ERC20 contract where `balanceOf(moduleAddress)` always returns `priorBalanceOf + amountRequested` (regardless of actual transfers) and `transfer()` always returns `true` without actually moving tokens.
2. Call `MsgRegisterERC20` with this contract address (permissionless registration enabled by default) — see `RegisterERC20`/`registerERC20` at [1](#0-0)  and [2](#0-1) .
3. Call `MsgConvertERC20` requesting a large `amount` for this contract; `convertERC20IntoCoinsForNativeToken`'s balance-invariance check at [6](#0-5)  passes because it only re-queries the same malicious contract.
4. `bankKeeper.MintCoins`/`SendCoinsFromModuleToAccount` at [5](#0-4)  mints and delivers native coins to the attacker with no real ERC20 tokens ever escrowed.

// RegisterERC20 implements the gRPC MsgServer interface. Any account can permissionlessly
// register a native ERC20 contract to map to a Cosmos Coin.
func (k *Keeper) RegisterERC20(goCtx context.Context, req *types.MsgRegisterERC20) (*types.MsgRegisterERC20Response, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	params := k.GetParams(ctx)

	if !params.PermissionlessRegistration {
		if err := k.validateAuthority(req.Signer); err != nil {
			return nil, err
		}
	}

	// Check if the conversion is globally enabled
	if !k.IsERC20Enabled(ctx) {
		return nil, types.ErrERC20Disabled.Wrap("registration is currently disabled by governance")
	}

	for _, addr := range req.Erc20Addresses {
		if !common.IsHexAddress(addr) {
			return nil, errortypes.ErrInvalidAddress.Wrapf("invalid ERC20 contract address: %s", addr)
		}

		pair, err := k.registerERC20(ctx, common.HexToAddress(addr))
		if err != nil {
			return nil, err
		}

// RegisterERC20 creates a Cosmos coin and registers the token pair between the
// coin and the ERC20
func (k Keeper) registerERC20(
	ctx sdk.Context,
	contract common.Address,
) (*types.TokenPair, error) {
	// Check if ERC20 is already registered
	if k.IsERC20Registered(ctx, contract) {
		return nil, errorsmod.Wrapf(
			types.ErrTokenPairAlreadyExists, "token ERC20 contract already registered: %s", contract.String(),
		)
	}

	metadata, err := k.CreateCoinMetadata(ctx, contract)
	if err != nil {
		return nil, errorsmod.Wrap(
			err, "failed to create wrapped coin denom metadata for ERC20",
		)
	}

	pair := types.NewTokenPair(contract, metadata.Name, types.OWNER_EXTERNAL)
	err = k.SetToken(ctx, pair)
	if err != nil {
		return nil, err
	}
	return &pair, nil
}
