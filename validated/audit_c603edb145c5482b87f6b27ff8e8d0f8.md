### Title
Spoofed host-identity heuristics in the git credential helper cause GitHub Enterprise sign-in (and PAT/OAuth token submission) to attacker-controlled remotes - (File: app/src/lib/trampoline/trampoline-credential-helper.ts)

### Summary
GitHub Desktop's git credential helper decides whether a remote Git host is a trusted "GitHub" endpoint (`github.com`, `ghe.com`, or "enterprise") using several **unauthenticated, attacker-influenced heuristics** rather than a cryptographically verified identity. When it misclassifies a non-GitHub, attacker-controlled remote as `enterprise`, it opens Desktop's built-in GitHub sign-in flow pointed at that attacker's host, causing the user's Personal Access Token or OAuth code exchange to be sent to the attacker.

### Finding Description
`getEndpointKind` in [1](#0-0)  classifies a remote as `'enterprise'` using signals fully controlled by the remote/response:

1. The `WWW-Authenticate` header's `realm` value, forwarded verbatim by git into the credential helper's stdin: any server returning `realm="GitHub"` is trusted as `'enterprise'` with no further check [2](#0-1) .
2. A hostname regex fallback in `isGitHubHost`, `/(^|\.)(github)\./.test(hostname)`, which returns `true` for any attacker-registered hostname merely containing a `github.` label (e.g. `github.attacker-cdn.example`), before any network request is even made [3](#0-2) .

This is directly analogous to the oracle bug's broken invariant: a cheap, spoofable proxy signal (WBTC's peg claim / a header string or hostname substring) is trusted as equivalent to the real, verified identity (BTC price / an actual GitHub server), with no fallback safety check when the proxy is wrong.

Once `getEndpointKind` returns `'enterprise'` for the attacker's endpoint and no existing account matches it, `getCredential` calls `ui.promptForGitHubSignIn(endpoint)` [4](#0-3) . This function feeds the attacker-supplied `endpoint` straight into Desktop's real Enterprise sign-in machinery: `dispatcher.beginEnterpriseSignIn(cb)` followed by `dispatcher.setSignInEndpoint(origin)` [5](#0-4) . From the user's perspective this is presented as Desktop's normal, trusted "Sign in to GitHub Enterprise" dialog — but the endpoint/origin driving the OAuth authorize URL and PAT verification requests (`getOAuthAuthorizationURL`, `requestOAuthToken`, both built from `getHTMLURL(endpoint)`) is the attacker's host [6](#0-5) . Whatever credential the user supplies (PAT) or whatever OAuth code/state round-trips through the browser is sent to the attacker's server.

### Impact Explanation
This satisfies the "credential/token exfiltration" and "unauthorized OAuth" impact categories. A user cloning/fetching from any untrusted remote — the standard, unprivileged attacker capability of "controls a git remote/proxy response" — can have Desktop present a legitimate-looking, first-party sign-in prompt whose destination is actually the attacker's server, exfiltrating the user's PAT or OAuth authorization code/token. No existing guard validates the endpoint's authenticity before it's threaded into the sign-in flow: `isGitHubHost`'s own doc comment admits it is "a best-effort attempt" [7](#0-6) , and the WWW-Authenticate realm check is explicitly described as a "happy-path" shortcut that skips the discovery request entirely [8](#0-7) .

### Likelihood Explanation
Triggering this requires only that the victim add/clone/fetch a repository from an attacker-controlled remote (HTTPS), which is a routine, unprivileged Desktop workflow — no local access, no prior compromise, and no unnatural steps beyond signing in when Desktop's own dialog prompts for it. The attacker fully controls both preconditions: they can register a hostname matching the `github.` substring regex, or simply serve a `401` response with `WWW-Authenticate: Basic realm="GitHub"`.

### Recommendation
Do not trust unauthenticated signals (`WWW-Authenticate` realm string, hostname substring matching) as sufficient to classify a host as a genuine GitHub endpoint for the purpose of opening the sign-in flow. Require the affirmative `isGitHubHost` network verification path (checking for `x-github-request-id`/known GitHub response fingerprints over TLS) before ever invoking `promptForGitHubSignIn`, and always surface the raw, unmodified hostname prominently in the sign-in dialog so users can visually confirm they are not being redirected to a look-alike domain — mirroring the recommended "double oracle" pattern of cross-checking a fast heuristic signal against a stronger verification step before acting on it.

### Proof of Concept
1. Attacker stands up an HTTPS git server at `https://github.totally-legit-mirror.example/foo/bar.git` (matches `/(^|\.)(github)\./`), or any HTTPS host that responds `401 Unauthorized` with header `WWW-Authenticate: Basic realm="GitHub"` on a git-http-backend info/refs request.
2. Victim, in GitHub Desktop, clones or adds this remote and triggers a fetch/push that requires auth.
3. Git invokes Desktop's credential helper; `getEndpointKind` returns `'enterprise'` via either the regex match in `isGitHubHost` ( [3](#0-2) ) or the `realm="GitHub"` happy-path ( [9](#0-8) ).
4. Since no account exists for the attacker's endpoint, `promptForGitHubSignIn(endpoint)` is invoked and Desktop opens its native "Sign in to GitHub Enterprise" dialog pointed at the attacker's origin ( [10](#0-9) ).
5. Victim enters a PAT (or completes a browser OAuth flow) believing it's a legitimate GHE sign-in; the token/OAuth code is sent to the attacker's server via `requestOAuthToken`/API calls built from the spoofed endpoint.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

export function getOAuthAuthorizationURL(
  endpoint: string,
  state: string
): string {
  const urlBase = getHTMLURL(endpoint)
  const scope = encodeURIComponent(oauthScopes.join(' '))

  return new window.URL(
    `/login/oauth/authorize?client_id=${ClientID}&scope=${scope}&state=${state}`,
    urlBase
  ).toString()
}

export async function requestOAuthToken(
  endpoint: string,
  code: string
): Promise<string | null> {
  try {
    const urlBase = getHTMLURL(endpoint)
    const response = await request(
      urlBase,
      null,
      'POST',
      'login/oauth/access_token',
      {
        client_id: ClientID,
        client_secret: ClientSecret,
        code: code,
      }
    )
    tryUpdateEndpointVersionFromResponse(endpoint, response)

    const result = await parsedResponse<IAPIAccessToken>(response)
    return result.access_token
  } catch (e) {
    log.warn(`requestOAuthToken: failed with endpoint ${endpoint}`, e)
    return null
  }
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
