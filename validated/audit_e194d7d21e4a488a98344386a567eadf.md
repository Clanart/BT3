### Title
Unauthenticated aggregator gRPC access to `InternalGetEmergencyStopTx` when `client_verification` is disabled - ([File: core/src/rpc/interceptors.rs])

### Summary
The `Internal*` gRPC method family (including `internal_get_emergency_stop_tx`) is only restricted to the aggregator/self identity via the `OnlyAggregatorAndSelf` interceptor, which is exclusively applied when `config.client_verification == true`. When `client_verification` is `false`, `create_grpc_server` wires the service with the `Noop` interceptor, which performs zero identity checks on any method, "Internal"-prefixed or not. Because move-to-vault txids are public once confirmed on Bitcoin, any network-reachable, unauthenticated caller can invoke `InternalGetEmergencyStopTx(move_to_vault_txid)` for every deposit and receive the fully signed emergency-stop transaction.

### Finding Description
The intended binding is: `recipient_of_decrypted_emergency_stop_tx == aggregator_or_self`, enforced by `only_aggregator_and_self` in [1](#0-0) , which checks `is_internal(&req)` (i.e., methods whose `grpc-method` header starts with `"Internal"`) against the caller's leaf TLS certificate.

This check is only ever installed when `config.client_verification` is true. In `create_grpc_server`, the `InterceptedService` is constructed with `OnlyAggregatorAndSelf` only in the `client_verification == true` branch; otherwise it uses `Noop`, which passes every request through unconditionally regardless of method name: [2](#0-1) .

`Noop`'s `call` implementation simply returns `Ok(req)` for any request: [3](#0-2) .

`create_aggregator_grpc_server` only logs a warning when `client_verification` is enabled, and otherwise proceeds identically with `Noop`: [4](#0-3) .

Since `move_to_vault_txid` is derived from a confirmed, publicly observable Bitcoin transaction, an attacker requires no privileged information to construct the request — they only need TCP/TLS-level connectivity to the aggregator's gRPC port (the aggregator's own server certificate still terminates TLS, but no *client* certificate/identity is checked when `client_verification` is off). The `Internal*` method naming convention exists specifically to restrict these RPCs to the aggregator calling itself, but that restriction is entirely a function of the `OnlyAggregatorAndSelf` interceptor, and is fully absent under `Noop`.

### Impact Explanation
Under `client_verification == false`, any unauthenticated caller can retrieve the fully-signed emergency-stop transaction for any deposit whose `move_to_vault_txid` they observe on-chain. Since Bitcoin move-to-vault transactions are public by construction, this is a class-wide exposure across every deposit processed by that aggregator instance, not a single deposit. Depending on what the emergency-stop transaction spends/authorizes (an N-of-N pre-signed transaction that acts on the vault UTXO), extraction and broadcast by an unauthorized party could result in a move-to-vault UTXO being frozen/stopped outside of the intended emergency governance process, matching the Critical impact category of "a move-to-vault UTXO permanently frozen." The blast radius scales with the number of deposits handled while `client_verification` is disabled.

### Likelihood Explanation
This requires the operator/aggregator to run with `client_verification = false`, a supported, non-test configuration flag exposed via `BridgeConfig` and set in deployment config files (e.g., `bridge_config.toml`). If that flag is set in a live deployment, the attack costs nothing beyond observing a confirmed Bitcoin transaction and issuing a single unauthenticated gRPC call — fully repeatable for every deposit and requiring no keys, collateral, or special role.

### Recommendation
Do not rely solely on `client_verification` to gate `Internal*` methods. Enforce the self/aggregator-only restriction for methods matching `is_internal` unconditionally (i.e., even under `Noop`), for example by always requiring mTLS/peer-certificate validation for internal RPCs regardless of the general `client_verification` setting, or by moving `internal_get_emergency_stop_tx` (and other `Internal*` RPCs) off the externally reachable listener entirely (e.g., a loopback-only or Unix-socket-only internal service).

fn only_aggregator_and_self(
    req: Request<()>,
    our_cert: &CertificateDer<'static>,
    aggregator_cert: &CertificateDer<'static>,
) -> Result<Request<()>, Status> {
    let Some(peer_certs) = req.peer_certs() else {
        if cfg!(test) {
            // Test mode, we don't need to verify peer certificates
            return Ok(req);
        } else {
            // If we're not in test mode, we need to check peer certificates
            return Err(Status::unauthenticated(
                "Failed to verify peer certificate, is TLS enabled?",
            ));
        }
    };

    // IMPORTANT: Only check the leaf (end-entity) certificate, which is always the first
    // certificate in the chain. The leaf is the only certificate whose private key the peer
    // proved possession of during the TLS handshake. Checking anywhere else in the chain
    // would allow identity spoofing: an attacker could include a pinned cert as an
    // intermediate in their chain without possessing its private key.
    let Some(leaf_cert) = peer_certs.first() else {
        return Err(Status::unauthenticated("Peer certificate chain is empty"));
    };

    if is_internal(&req) {
        if leaf_cert == our_cert {
            Ok(req)
        } else {
            Err(Status::unauthenticated(
                "Unauthorized call to internal method (not self)",
            ))
        }
    } else if leaf_cert == aggregator_cert || leaf_cert == our_cert {
        Ok(req)
    } else {
        Err(Status::unauthenticated(
            "Unauthorized call to method (not aggregator or self)",
        ))
    }

pub async fn create_aggregator_grpc_server(
    config: BridgeConfig,
) -> Result<(std::net::SocketAddr, oneshot::Sender<()>), BridgeError> {
    let addr: std::net::SocketAddr = format!("{}:{}", config.host, config.port)
        .parse()
        .wrap_err("Failed to parse address")?;
    let aggregator_server = AggregatorServer::new(config.clone()).await?;
    aggregator_server.start_background_tasks().await?;

    let svc = ClementineAggregatorServer::new(aggregator_server)
        .max_encoding_message_size(config.grpc.max_message_size)
        .max_decoding_message_size(config.grpc.max_message_size);

    if config.client_verification {
        tracing::warn!("Client verification is enabled on aggregator gRPC server",);
    }

    let (server_addr, shutdown_tx) =
        create_grpc_server(addr.into(), svc, "Aggregator", &config).await?;

    match server_addr {
        ServerAddr::Tcp(socket_addr) => Ok((socket_addr, shutdown_tx)),
        _ => Err(BridgeError::ConfigError("Expected TCP address".into())),
    }
}
