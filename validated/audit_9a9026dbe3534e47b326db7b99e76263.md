### Title
`MsgChangeAdmin.ValidateBasic()` rejects empty `NewAdmin`, making it impossible to renounce tokenfactory denom admin via a normal transaction - (File: x/tokenfactory/types/msgs.go)

### Summary
The tokenfactory module's design and documentation explicitly support "renouncing" admin control of a denom by setting the admin to an empty string, which the `ChangeAdmin` keeper logic accepts and treats as "no admin." However, `MsgChangeAdmin.ValidateBasic()` unconditionally requires `NewAdmin` to parse as a valid bech32 address, and this validation is invoked for every submitted transaction before the message ever reaches the keeper. As a result, a denom admin can never actually renounce/burn admin rights through the standard transaction path, mirroring the RCFactory `uberOwner` bug where a defensive zero-address check blocks the documented renunciation mechanism.

### Finding Description
The tokenfactory README states that `ChangeAdmin` allows "setting it to `""`, meaning no account has admin privileges of the asset" [1](#0-0) , and the `AuthorityMetadata` field is documented as allowing an empty admin: "Can be empty for no admin, or a valid sei address" [2](#0-1) . The keeper's `ChangeAdmin` handler and `setAdmin` function impose no restriction preventing an empty `NewAdmin` from being written to state [3](#0-2) [4](#0-3) .

However, `MsgChangeAdmin.ValidateBasic()` requires both `Sender` and `NewAdmin` to successfully parse via `sdk.AccAddressFromBech32`, returning `ErrInvalidAddress` otherwise [5](#0-4) . `sdk.AccAddressFromBech32("")` errors on empty input in the standard cosmos-sdk address parsing logic used here [6](#0-5) .

Critically, `ValidateBasic()` is called on every message unconditionally before `RunMsgs` executes the keeper handler, for both `CheckTx` and `DeliverTx`: `validateBasicTxMsgs(msgs)` is invoked at the very start of `runTx`, prior to the ante handler and message routing [7](#0-6) [8](#0-7) . This means any real transaction attempting `MsgChangeAdmin{NewAdmin: ""}` is rejected at the `ValidateBasic` stage and never reaches `msgServer.ChangeAdmin`.

The existing unit tests that demonstrate "renouncing" to `""` succeeding (`TestAdminMsgs`, `TestChangeAdminDenom`) call `suite.msgServer.ChangeAdmin(...)` directly, bypassing `ValidateBasic()` entirely [9](#0-8) . This masks the fact that the feature is unreachable through the actual transaction/ante pipeline that every public-RPC-submitted or CLI-submitted transaction goes through, exactly analogous to how RCFactory's `changeUberOwner` zero-address check made renouncing unreachable despite the design intent.

### Impact Explanation
Denom creators/admins who intend to permanently relinquish admin control over a tokenfactory denom (e.g., to establish trust that no future minting/burning/metadata changes or admin reassignment can occur) cannot do so. The admin key remains a permanent, unrenounceable single point of control/trust, meaning users cannot obtain the trust guarantees that a "renounced" (adminless) denom is supposed to provide, and the admin retains capabilities (mint, burn, transfer via bank, further admin changes) indefinitely. This is a functional/trust-model correctness issue affecting all tokenfactory denom admins reachable via a standard `MsgChangeAdmin` transaction.

### Likelihood Explanation
Any account holding admin rights over a tokenfactory denom can attempt this at any time by submitting a normal `change-admin` transaction with an empty `new-admin-address`; the CLI command builds the message directly without pre-filtering empty strings [10](#0-9) . The failure occurs deterministically for every such transaction, since `ValidateBasic` is unconditionally enforced by `baseapp` for both `CheckTx` and `DeliverTx`.

### Recommendation
Relax `MsgChangeAdmin.ValidateBasic()` to explicitly allow an empty `NewAdmin` string (treating it as "no admin"), rather than requiring it to always parse as a valid bech32 address — mirroring how the keeper (`setAdmin`) and documentation already treat an empty admin as a valid, intentional state. For example, only invoke `sdk.AccAddressFromBech32(m.NewAdmin)` when `m.NewAdmin != ""`.

### Proof of Concept
1. Create a tokenfactory denom as `admin` (`MsgCreateDenom`), becoming its admin.
2. Submit `seid tx tokenfactory change-admin <denom> "" --from admin ...` (or construct `MsgChangeAdmin{Sender: admin, Denom: denom, NewAdmin: ""}` directly).
3. `baseapp.runTx` calls `validateBasicTxMsgs`, which calls `MsgChangeAdmin.ValidateBasic()` [7](#0-6) .
4. `ValidateBasic()` calls `sdk.AccAddressFromBech32(m.NewAdmin)` with `m.NewAdmin == ""`, which errors, causing the transaction to fail with `ErrInvalidAddress` before ever reaching `msgServer.ChangeAdmin` [11](#0-10) .
5. The admin can never be set to `""` through any real transaction, despite the keeper (`setAdmin`) and documentation supporting it as the intended renunciation mechanism.

func (server msgServer) ChangeAdmin(goCtx context.Context, msg *types.MsgChangeAdmin) (*types.MsgChangeAdminResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	authorityMetadata, err := server.GetAuthorityMetadata(ctx, msg.Denom)
	if err != nil {
		return nil, err
	}

	if msg.Sender != authorityMetadata.GetAdmin() {
		return nil, types.ErrUnauthorized
	}

	// Validate new admin we change to should be different from current admin
	if msg.NewAdmin == authorityMetadata.GetAdmin() {
		return nil, types.ErrAdminAlreadyExists
	}

	err = server.setAdmin(ctx, msg.Denom, msg.NewAdmin)
	if err != nil {
		return nil, err
	}
	ctx.EventManager().EmitEvents(sdk.Events{
		sdk.NewEvent(
			types.TypeMsgChangeAdmin,
			sdk.NewAttribute(types.AttributeDenom, msg.GetDenom()),
			sdk.NewAttribute(types.AttributeNewAdmin, msg.NewAdmin),
		),
	})

	return &types.MsgChangeAdminResponse{}, nil
}

// validateBasicTxMsgs executes basic validator calls for messages.
func validateBasicTxMsgs(msgs []sdk.Msg) error {
	if len(msgs) == 0 {
		return sdkerrors.Wrap(sdkerrors.ErrInvalidRequest, "must contain at least one message")
	}

	for _, msg := range msgs {
		err := msg.ValidateBasic()
		if err != nil {
			return err
		}
	}

	return nil
}

func NewChangeAdminCmd() *cobra.Command {
