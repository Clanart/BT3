### Title
Quadratic Lagrange interpolation in `ThresholdKeys::new` enables CPU-exhaustion DoS via crafted `ThresholdKeys::read` bytes - (File: crypto/dkg/src/lib.rs)

### Summary
`ThresholdKeys::<C>::read` accepts an attacker-controlled `n` (u16) and `Lagrange` interpolation flag, then `ThresholdKeys::new` derives the group key by evaluating `interpolation_factor` for every participant `1..=t`. Each Lagrange `interpolation_factor` call iterates over all `t` included participants, making group-key derivation O(t²) field operations. With `t = n = 65535` this is ~4.3×10⁹ field multiplications/inversions triggered by only ~2 MB of untrusted input — an asymmetric CPU-consumption DoS analogous to CVE-2016-3092's long-boundary-string CPU blowup.

### Finding Description
`ThresholdKeys::read` (crypto/dkg/src/lib.rs:574) reads `t`, `n`, `i` directly from the stream with no upper bound beyond u16, then reads `n` scalars or sets `Interpolation::Lagrange` (lines 604-616), reads `n` verification-share points (lines 620-623), and calls `ThresholdKeys::new` (line 625). In `ThresholdKeys::new` (lines 376-378), `group_key` is computed as `Σ verification_shares[i] * interpolation_factor(i, t)` for `i in 1..=t`. For `Interpolation::Lagrange`, `interpolation_factor` (lines 229-247) loops over every element of `included` performing a field multiplication each iteration — O(t) per factor, O(t²) total, plus a field inversion per participant. The same quadratic path is re-triggered in `ThresholdKeys::view` (lines 500-506), which calls `interpolation_factor` once per included signer over the whole `included` list — so every signing view over a large crafted `n` re-pays the O(n²) cost.

### Impact Explanation
An unprivileged party who can cause a node/validator to deserialize `ThresholdKeys` bytes (the rules explicitly list `ThresholdKeys::read` as a reachable target for untrusted bytes) can force billions of scalar multiplications and ~65k point decompressions plus inversions from a single small message (~`n * 64` bytes ≈ 4 MB for ed25519/Ristretto). This is availability loss via CPU exhaustion, matching the CWE-20/DoS class of the reference advisory. Impact is availability only — no secret leakage — but it is reachable, unbounded by any transaction/size limit inside the library, and quadratic rather than linear.

### Likelihood Explanation
Reachability depends on the integrator feeding untrusted bytes to `ThresholdKeys::read`; within the crate the math is deterministic and unconditional — `ThresholdParams::new` accepts any `t <= n <= 65535` (lines 166-179) and `Interpolation::Lagrange` requires no consistency check against `t` (line 373). No signature or proof-of-work gates the computation; the cost is incurred during deserialization before any validation could reject the input. Medium likelihood: it requires an integration path that reads adversarial `ThresholdKeys`, but where reachable it is trivially exploitable with a single message.

### Recommendation
- Bound `n`/`t` at deserialization time to the maximum validator-set size actually supported (e.g., reject `n` above a protocol constant in `ThresholdKeys::read`).
- Cache or batch-compute Lagrange factors: compute all `interpolation_factor`s via a single O(t) prefix/suffix product pass instead of t independent O(t) loops.
- Alternatively, derive `group_key` with a multi-scalar multiplication over precomputed O(t) denominators rather than per-participant inversion.

### Proof of Concept
```rust
// Attacker-controlled bytes fed to ThresholdKeys::<Ristretto>::read:
//   id_len/id for Ristretto, then t = 65535, n = 65535, i = 1,
//   interpolation = 1 (Lagrange), secret_share, then n point encodings.
let n: u16 = u16::MAX;
let mut buf = vec![];
buf.extend((Ristretto::ID.len() as u32).to_le_bytes());
buf.extend(Ristretto::ID);
buf.extend(n.to_le_bytes());        // t
buf.extend(n.to_le_bytes());        // n
buf.extend(1u16.to_le_bytes());     // i
buf.push(1);                        // Interpolation::Lagrange
buf.extend(Scalar::ONE.to_repr());  // secret_share
for _ in 0 .. n {
  buf.extend(RistrettoPoint::generator().to_bytes()); // verification_shares
}
// Triggers O(n^2) ≈ 4.3e9 field muls inside ThresholdKeys::new -> group_key
let _keys = ThresholdKeys::<Ristretto>::read(&mut buf.as_slice());
```
