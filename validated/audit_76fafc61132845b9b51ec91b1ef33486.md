### Title
`GaslessModule.IsModuleTx()` does not check `IsDisabled()`, allowing gasless bundle transactions to bypass normal tx pool rules even when the gasless module is administratively disabled - ([File: kaiax/gasless/impl/tx_pool.go])

### Summary
This mirrors the reported IronBank bug class: a capability/eligibility function (`maxFlashLoan()` in the analog report) fails to check a "paused/disabled" flag that a related state-changing function does check, causing wrong decisions downstream. In Kaia's gasless module, `IsModuleTx()` classifies a transaction as a gasless approve/swap tx purely based on `IsApproveTx`/`IsSwapTx` pattern matching, without consulting `GaslessModule.IsDisabled()` [1](#0-0) , even though `IsDisabled()` exists specifically to represent the module's disabled/paused state [2](#0-1) .

### Finding Description
`IsDisabled()` returns `g.GaslessConfig.Disable`, which is set either via CLI flag or automatically by `Init()` when a consensus node's balance is insufficient to act as a lender [3](#0-2) . This flag is meant to fully turn off gasless-transaction handling. Only the JSON-RPC-facing `GaslessAPI` (`IsGaslessTx`/`GaslessInfo`) surfaces `IsDisabled()` [4](#0-3) ; the transaction-pool-facing entry points (`PreAddTx`, `IsModuleTx`, `GetCheckBalance`, `IsReady`) never call it [5](#0-4) [6](#0-5) .

`IsModuleTx` is the gatekeeper the core tx pool (`blockchain/tx_pool.go`) uses to decide whether a `TxPoolModule` should apply its special bundle-ordering, queue-limit (`PreAddTx`), and promotion (`IsReady`) logic to a transaction instead of standard tx pool rules [7](#0-6) . Because `IsModuleTx` is purely pattern-based (matching `approve`/`swapForGas` calldata to whitelisted `swapRouter`/`allowedTokens`), a submitted approve+swap bundle continues to be recognized and processed as a gasless bundle — subject to `GetMaxBundleTxsInPending`/`GetMaxBundleTxsInQueue` flow control and sequential-nonce promotion via `IsReady` — even after the operator (or the automatic insufficient-lender-balance guard in `Init`) has disabled the module.

This is directly analogous to the reported bug: `maxFlashLoan()` failed to check `isBorrowPaused()`, which the actual `borrow()` function does check, producing an inconsistency between the "capability check" and the "state-changing" enforcement. Here, `IsModuleTx`/`IsReady`/`PreAddTx` (the eligibility/inclusion path) never checks `IsDisabled()`, while the intent of `Disable` is that the whole module should stop functioning.

### Impact Explanation
If the gasless module is disabled (e.g., automatically disabled because the CN's lender balance dropped below `GaslessLenderMinBal`, per `kaiax/gasless/impl/init.go:87-94`), any unprivileged submitter can still submit an approve+swap "gasless bundle" transaction pair. `IsModuleTx` will still classify it as a module tx, so the tx pool continues to apply gasless-specific bundle admission/promotion rules (`PreAddTx`, `IsReady`) instead of rejecting/ignoring it as a plain, unrelated pair of transactions. Since the disable flag was introduced specifically to stop the module from processing gasless bundles (notably to protect the lender when it lacks balance to fund `swapForGas` repayments), continuing to treat such transactions as valid gasless bundles risks bundle execution/settlement attempts by a lender that is known to be insufficiently funded, or otherwise causes tx-pool behavior (queue slot consumption reserved for gasless bundles, promotion ordering) to diverge from the intended "disabled" semantics. This can lead to unauthorized consumption of gasless-bundle capacity/settlement resources and inconsistent tx-pool state across nodes with different config or balance conditions (some nodes auto-disable, others don't), a state-divergence risk.

### Likelihood Explanation
Any public RPC caller / unprivileged transaction sender can trigger this by submitting a normal approve+swap-shaped transaction pair that matches the whitelisted `swapRouter`/`allowedTokens` patterns — no special privilege is required. The condition (module disabled by low lender balance or explicit `gasless.disable` flag) is a normal, reachable operational state, not a rare edge case, making the likelihood of encountering the inconsistency moderate to high on any node where the module transitions to disabled at runtime.

### Recommendation
Add an explicit `IsDisabled()` check at the entry points that gate special gasless tx-pool treatment, mirroring the RPC-layer check already present in `GaslessAPI.IsGaslessTx`:
- `IsModuleTx` (`kaiax/gasless/impl/tx_pool.go:55`) should return `false` immediately if `g.IsDisabled()`.
- `PreAddTx` and `IsReady` should likewise short-circuit (or rely on `IsModuleTx` returning `false`) when disabled, so disabled-module transactions are treated as ordinary transactions subject to normal tx pool rules only.

### Proof of Concept
Conceptual reproduction (concrete PoC would require constructing signed approve/swap transactions similar to `kaiax/gasless/impl/tx_pool_test.go`):
1. Configure/observe a node where `GaslessConfig.Disable == true` (either via `gasless.disable=true` or by having the CN's lender balance fall below `GaslessLenderMinBal` at `Init()`, see `kaiax/gasless/impl/init.go:86-94`).
2. As an unprivileged sender, submit an `approve(spender=swapRouter, amount=MaxUint256)` tx followed by a `swapForGas(token, amountIn, minAmountOut, amountRepay)` tx to a whitelisted token/router, matching the shapes checked by `isApproveTx`/`isSwapTx` (`kaiax/gasless/impl/getter.go:74-96`).
3. Observe that `IsModuleTx` still returns `true` for both transactions (no `IsDisabled()` check in `kaiax/gasless/impl/tx_pool.go:55-60`), so `PreAddTx`/`IsReady` continue to apply gasless-bundle-specific queue/promotion logic instead of treating them as unrelated standard transactions — contrary to the intended fully-disabled state.

Note: I could not fully trace how `node/cn/backend.go` wires `IsDisabled`/module registration into the live `blockchain/tx_pool.go` `RegisterTxPoolModule` call within the available context (index truncation), so the exact end-to-end effect on tx-pool internals should be verified with a live Devin session that can read the complete files. func (g *GaslessModule) PreAddTx(tx *types.Transaction, local bool) error {
	g.knownTxsMu.RLock()
	defer g.knownTxsMu.RUnlock()

	if knownTx, ok := g.knownTxs.get(tx.Hash()); ok && knownTx.elapsedPromotedOrAddedTime() < KnownTxTimeout {
		return ErrUnableToAddKnownBundleTx
	}

	if g.IsBundleTx(tx) {
		if uint(g.knownTxs.numQueue()) >= g.GetMaxBundleTxsInQueue() {
			return ErrBundleTxQueueFull
		}
		g.knownTxs.add(tx, TxStatusQueue)
	}
	return nil
}

func (g *GaslessModule) IsModuleTx(tx *types.Transaction) bool {
	if tx == nil {
		return false
	}
	return g.IsApproveTx(tx) || g.IsSwapTx(tx)
}

func (g *GaslessModule) IsReady(txs map[uint64]*types.Transaction, next uint64, ready types.Transactions) bool {
	g.knownTxsMu.Lock()
	defer g.knownTxsMu.Unlock()

	tx, ok := txs[next]
	if !ok {
		return false
	}

	if !g.isReady(txs, next, ready) {
		return false
	}

	if g.IsBundleTx(tx) {
		// If prev tx is bundle tx, there's no need to check the knownTxs limit because it has been checked in the previous `IsReady()` execution.
		isPrevTxBundleTx := len(ready) != 0 && g.IsBundleTx(ready[len(ready)-1])
		if isPrevTxBundleTx {
			g.knownTxs.add(tx, TxStatusPending)
			return true
		}

		maxBundleTxsInPending := g.GetMaxBundleTxsInPending()
		if maxBundleTxsInPending != math.MaxUint64 {
			numExecutable := uint(g.knownTxs.numExecutable())

			numSeqTxs := uint(1)
			for i := next + 1; i < next+uint64(len(txs)); i++ {
				if tx, ok := txs[i]; ok && g.IsBundleTx(tx) {
					numSeqTxs++
				} else {
					break
				}
			}

			// false if there is possibility of exceeding max bundle tx num
			if numExecutable+numSeqTxs > maxBundleTxsInPending {
				logger.Trace("Not promoting a tx because of exceeding max bundle tx num", "tx", tx.Hash().String(), "numExecutable", numExecutable, "maxBundleTxsInPending", maxBundleTxsInPending)
				return false
			}
		}

		g.knownTxs.add(tx, TxStatusPending)
	}

	return true
}

func (s *GaslessAPI) GaslessInfo() *GaslessInfoResult {
	s.b.gaslessInfoMu.RLock()
	defer s.b.gaslessInfoMu.RUnlock()

	at := []common.Address{}
	for addr := range s.b.allowedTokens {
		at = append(at, addr)
	}
	return &GaslessInfoResult{
		IsDisabled:    s.b.IsDisabled(),
		SwapRouter:    s.b.swapRouter,
		AllowedTokens: at,
		MaxBundleTxs:  s.b.GetMaxBundleTxsInPending(),
	}
}
