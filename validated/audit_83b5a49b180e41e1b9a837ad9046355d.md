### Title
Missing Signature Malleability Check in `VALIDATE_SENDER` Precompile Enables Potential AccountKey Multisig Threshold Bypass - (File: `blockchain/vm/contracts.go`)

### Summary
The `VALIDATE_SENDER` precompiled contract, reachable by any transaction/contract call, recovers public keys from attacker-supplied signatures using `crypto.Ecrecover` directly, without first calling `crypto.ValidateSignatureValues` to reject malleable (high-`s`) signatures. This is inconsistent with every other signature-recovery path in the same codebase (transaction signing, auction bid signatures, personal_ecRecover), all of which call `crypto.ValidateSignatureValues` before recovery.

### Finding Description
`validateSender()` in `blockchain/vm/contracts.go` parses an address, a message, and a variable number of 65-byte signatures, then recovers a public key per signature and feeds the set of recovered public keys into `accountkey.ValidateAccountKey` to check that the transaction's `from` address's registered `AccountKey` (e.g. `AccountKeyWeightedMultiSig`) is satisfied: [1](#0-0) 

Unlike `recoverPlainCommon` in `blockchain/types/transaction_signing.go`, which calls `crypto.ValidateSignatureValues(V, R, S, homestead)` before calling `crypto.Ecrecover`: [2](#0-1) 

and unlike `getSigner()` in `kaiax/auction/bid.go`, which also validates signature values before recovery: [3](#0-2) 

the `validateSender` precompile skips this check entirely, calling `crypto.Ecrecover(msg, ptr[0:common.SignatureLength])` directly on caller-controlled bytes: [4](#0-3) 

`crypto.Ecrecover` (both cgo and non-cgo implementations) performs no `s`-range check — it only validates the recovery-id byte, then recovers whatever public key the `(r, s, v)` triple maps to: [5](#0-4) 

Because `secp256k1` signatures are malleable (for any valid `(r, s, v)` there is a second valid `(r, n-s, 1-v)` that recovers to the *same* address), an attacker holding a single private key can produce **two distinct 65-byte signature blobs that both recover to the same public key/address**, without needing the private key twice, and without ever having produced the second "legitimate" one.

### Impact Explanation
`VALIDATE_SENDER` is exposed to any transaction or contract call (it is a standard EVM precompile), and is designed specifically to check `AccountKey` role satisfaction (e.g., `AccountKeyWeightedMultiSig`, `AccountKeyRoleBased`) via `accountkey.ValidateAccountKey(currentBlockNumber, from, k, pubs, accountkey.RoleTransaction)`. This is the AccountKey-authorization pathway explicitly in scope. If the downstream `ValidateAccountKey` threshold logic counts satisfied "weight" per supplied signature/public key without additionally deduplicating on recovered address, an attacker controlling only a subset of the keys required by a weighted multisig account could submit both the canonical and the malleable-twin signature for a key they already control to inflate the number of "signatures" presented toward the threshold, potentially satisfying an N-of-M multisig requirement with fewer than N independent keys. Even absent full threshold bypass, the missing check represents acceptance of computationally distinct signature bytes as equally valid proof-of-authorization for the same key, contrary to the canonical form enforced everywhere else in the codebase — a direct parallel to the reported bug class (multiple valid signatures for one message).

### Likelihood Explanation
Exploitation only requires crafting a standard 65-byte ECDSA signature blob with `s' = n - s` and flipped recovery bit — a purely local, no-privilege computation any transaction sender can perform. The precompile is directly callable from any transaction. The main uncertainty (not verifiable from the indexed sources reviewed) is whether `accountkey.ValidateAccountKey`'s threshold-matching logic already deduplicates by recovered address/key index; if it does not, the bypass is directly exploitable.

### Recommendation
Add a `crypto.ValidateSignatureValues(v, r, s, true)` check (matching the pattern used in `recoverPlainCommon` and `kaiax/auction/bid.go`'s `getSigner`) inside `validateSender()` in `blockchain/vm/contracts.go` before calling `crypto.Ecrecover` for each signature segment, so malleable/non-canonical signatures are rejected outright. Additionally, confirm/enforce in `accountkey.ValidateAccountKey` that each recovered public key/address is only counted once toward a role's threshold.

### Proof of Concept
1. Attacker holds one private key `k` registered as one of several keys in an `AccountKeyWeightedMultiSig` account, where the threshold requires signatures from ≥2 distinct keys.
2. Attacker signs `msg` with `k` to get canonical signature `(r, s, v)`.
3. Attacker computes the malleable twin `(r, n-s, 1-v)`, which is a distinct 65-byte blob but recovers to the same public key as `k`.
4. Attacker calls the `VALIDATE_SENDER` precompile (`blockchain/vm/contracts.go:865-924`) supplying both `(r,s,v)` and `(r,n-s,1-v)` as the two required signature slots.
5. Both segments pass `crypto.Ecrecover` (no malleability check present) and yield the same public key twice; if `accountkey.ValidateAccountKey` does not dedupe recovered keys, the threshold check is satisfied using only one real private key, incorrectly returning success/`[]byte{1}` from `Run()` at `blockchain/vm/contracts.go:865-873`.

func recoverPlainCommon(sighash common.Hash, R, S, Vb *big.Int, homestead bool) ([]byte, error) {
	if Vb.BitLen() > 8 {
		return []byte{}, ErrInvalidSig
	}
	V := byte(Vb.Uint64() - 27)
	if !crypto.ValidateSignatureValues(V, R, S, homestead) {
		return []byte{}, ErrInvalidSig
	}
	// encode the snature in uncompressed format
	r, s := R.Bytes(), S.Bytes()
	sig := make([]byte, crypto.SignatureLength)
	copy(sig[32-len(r):32], r)
	copy(sig[64-len(s):64], s)
	sig[crypto.RecoveryIDOffset] = V
	// recover the public key from the snature
	pub, err := crypto.Ecrecover(sighash[:], sig)
	if err != nil {
		return []byte{}, err
	}

// Ecrecover returns the uncompressed public key that created the given signature.
func Ecrecover(hash, sig []byte) ([]byte, error) {
	if len(sig) != SignatureLength {
		return nil, errors.New("invalid signature")
	}
	if len(hash) != DigestLength {
		return nil, fmt.Errorf("hash is required to be exactly %d bytes (%d)", DigestLength, len(hash))
	}
	// Enforce canonical Ethereum recovery id v ∈ {0, 1}.
	if sig[RecoveryIDOffset] >= 2 {
		return nil, errors.New("invalid signature recovery id")
	}
	return secp256k1.RecoverPubkey(hash, sig)
}
