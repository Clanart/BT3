### Title
Automatic silent rewrite of the local `origin` remote URL from an untrusted GitHub API response, without user confirmation - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
The original report's broken invariant is: an external, attacker-influenceable value (AMM pool share ratio) is consumed by a state-changing function (`deposit`/`withdraw`) without any bound check or user confirmation, so the caller ends up committing to a result they never approved. The closest Desktop analog is `updateRemoteUrl()`, which silently rewrites the user's local `origin` remote to whatever `clone_url` GitHub's API returns for the repo's `owner/name`, with no confirmation dialog and no verification that the returned repository is still the *same* repository the user originally added.

### Finding Description
`repositoryWithRefreshedGitHubRepository()` derives `owner`/`name` purely by parsing the *current* git remote URL string via `matchGitHubRepository()`: [1](#0-0) 

It then fetches the repository object from the GitHub API using that owner/name and passes the raw API object straight into `updateRemoteUrl()`: [2](#0-1) 

`updateRemoteUrl()` compares the API's `clone_url` to the locally configured remote and, if the protocol matches and the previously cached GitHub `cloneURL` still equals the current remote, it calls `gitStore.setRemoteURL(...)` to overwrite the local `origin` URL - with no user prompt, diff, or identity check beyond a string comparison of owner/name/hostname: [3](#0-2) 

The matching primitive `urlMatchesRemote`/`urlsMatch` only compares `hostname + owner + name` strings, never a stable repository identifier (e.g. GitHub's numeric repo ID), so two entirely different repositories that happen to share an `owner/name` pair (e.g. after the original repo/owner is deleted and the name is reclaimed - a classic "repo-jacking" scenario) are indistinguishable to this code: [4](#0-3) 

This path is not gated behind any explicit user action - it runs on ordinary repository selection: [5](#0-4) 
and when adding a repository: [6](#0-5) 

Unlike other risky-operation paths in Desktop (e.g. force-push, which has an explicit confirmation dialog), there is no equivalent "are you sure the remote should change?" guard here: [7](#0-6) 

### Impact Explanation
If an attacker manages to have GitHub's API return a `clone_url` for the same `owner/name` pair that points to an attacker-controlled repository (e.g. the original repository owner/name combination becomes available and is reclaimed by an attacker, or a compromised/renamed upstream is used to redirect the identifier), Desktop will **silently rewrite the user's `origin` remote** the next time the app refreshes GitHub metadata for that repository - which happens routinely on app start / repository selection, with no user awareness. Subsequent `git push` operations (which read `state.remote` populated from this rewritten config) will send the user's commits to the attacker's repository instead of the intended one, and subsequent fetch/pull could merge attacker-supplied history into the user's local branch. This matches the requested impact classes: theft of code/IP pushed to the wrong destination, and silent corruption of what the user commits or pushes, without any local access, admin rights, or social engineering step beyond the normal use of the app.

### Likelihood Explanation
The precondition (owner/name reuse or repository transfer on the GitHub side) is a known real-world "repo-jacking" pattern and does not require compromising Desktop or the user's machine - only causing the GitHub API to legitimately return a different `clone_url` for the previously-known `owner/name`. Desktop's matching logic performs no stronger identity check (no repo ID pinning) and applies the change automatically on ordinary background refreshes, so the likelihood of the vulnerable code path being reached is high whenever the API-side precondition occurs; the main uncertainty is how often that precondition is achievable in practice, which is outside the scope of static code review.

### Recommendation
- Pin repository identity by GitHub's immutable numeric repository `id` (already available on `IAPIRepository`) rather than relying solely on `owner/name` string matching, and refuse to auto-update the remote if the `id` differs from the previously stored one.
- When a mismatch/rename is detected, surface an explicit confirmation dialog to the user (mirroring the existing `ConfirmForcePush` pattern) before mutating the `origin` remote URL, rather than mutating it silently in `updateRemoteUrl()`.

### Proof of Concept
Conceptual PoC (network/API-level, no local/admin access required):
1. User adds/clones `https://github.com/victim-owner/project.git` in Desktop; Desktop stores `GitHubRepository.cloneURL` for that owner/name.
2. Later, the `victim-owner/project` identity becomes available for reuse on GitHub (e.g., original account/repo deleted or renamed away), and an attacker registers `victim-owner/project` as a new, unrelated repository they control.
3. On the user's next Desktop launch or repository selection, `repositoryWithRefreshedGitHubRepository()` calls `api.fetchRepository('victim-owner', 'project')`, which now returns the attacker's repository object with a `clone_url` pointing at the same string identity. [8](#0-7) 
4. `updateRemoteUrl()` finds `protocolsMatch && remoteUrlUnchanged && !urlsMatch` all satisfied (the raw URL text differs slightly, e.g. different casing/redirect target) and calls `gitStore.setRemoteURL(...)`, rewriting `origin` to the attacker's URL without any prompt. [9](#0-8) 
5. The user's next `git push` in Desktop now pushes to the attacker-controlled remote.

export function matchGitHubRepository(
  accounts: ReadonlyArray<Account>,
  remote: string
): IMatchedGitHubRepository | null {
  for (const account of accounts) {
    const htmlURL = getHTMLURL(account.endpoint)
    const { hostname } = URL.parse(htmlURL)
    const parsedRemote = parseRemote(remote)

    if (parsedRemote !== null && hostname !== null) {
      if (parsedRemote.hostname.toLowerCase() === hostname.toLowerCase()) {
        return { name: parsedRemote.name, owner: parsedRemote.owner, account }
      }
    }
  }

  return null
}

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

  public async confirmOrForcePush(repository: Repository) {
    const { askForConfirmationOnForcePush } = this.appStore.getState()

    const { branchesState } = this.repositoryStateManager.get(repository)
    const { tip } = branchesState

    if (tip.kind !== TipState.Valid) {
      log.warn(`Could not find a branch to perform force push`)
      return
    }

    const { upstream } = tip.branch

    if (upstream === null) {
      log.warn(`Could not find an upstream branch which will be pushed`)
      return
    }

    if (askForConfirmationOnForcePush) {
      this.showPopup({
        type: PopupType.ConfirmForcePush,
        repository,
        upstreamBranch: upstream,
      })
    } else {
      await this.performForcePush(repository)
    }
  }
