### Title
Unvalidated `ReceivedOutput` deserialization permits phantom or unspendable wallet inputs - ([File: `networks/bitcoin/src/wallet/mod.rs`])

### Summary
`ReceivedOutput::read` accepts an offset, `TxOut`, and `OutPoint` without validating that the outpoint exists or actually contains the supplied output. [1](#0-0) 

### Finding Description
Scanner-derived outputs establish the missing relationship by extracting both the matching offset and the claimed output from a confirmed transaction. [2](#0-1)  In contrast, deserialized outputs are accepted as three independent fields with no provenance or consistency check. [1](#0-0)  `SignableTransaction::new` then trusts the embedded `TxOut` value and embeds the attacker-controlled outpoint in the spend. [3](#0-2)  `multisig` checks only that the supplied offset produces a key matching the supplied `TxOut`, not that the referenced UTXO contains that `TxOut`. [4](#0-3) 

### Impact Explanation
A caller that receives serialized `ReceivedOutput` values as wallet inventory can report an arbitrary amount as received, then construct and threshold-sign a transaction referencing a nonexistent or mismatched UTXO. [5](#0-4)  The resulting transaction is not spendable when the embedded prevout differs from the actual prevout committed by Bitcoin's sighash. [6](#0-5)  This is a Medium-severity integrity failure because it can inject phantom wallet funds and produce invalid spends, but it does not by itself reveal key material. [1](#0-0) 

### Likelihood Explanation
The malformed input consists only of public serialization bytes accepted by `ReceivedOutput::read`. [1](#0-0)  Exploitation requires a caller to persist, relay, or otherwise trust serialized `ReceivedOutput` values instead of deriving them exclusively through `Scanner::scan_transaction`. [7](#0-6) 

### Recommendation
Treat `ReceivedOutput::read` as decoding an unauthenticated claim rather than a received coin. [1](#0-0)  Before accounting for or spending a deserialized output, fetch the referenced outpoint and require its on-chain `TxOut` to equal the supplied output, while independently recalculating the expected offset through `Scanner`. [2](#0-1) 

### Proof of Concept
```rust
// networks/bitcoin/src/wallet/mod.rs
// Let group_key be the wallet's Taproot-adjusted group key and script its P2TR
// script. Encode a ReceivedOutput whose outpoint is nonexistent or references a
// different transaction output.
let mut encoded = Scalar::ZERO.to_bytes().to_vec();
encoded.extend(bitcoin::consensus::serialize(&TxOut {
    value: Amount::from_sat(100_000),
    script_pubkey: p2tr_script_buf(group_key).unwrap(),
}));
encoded.extend(bitcoin::consensus::serialize(&OutPoint {
    txid: arbitrary_txid,
    vout: 0,
}));

let forged =
    ReceivedOutput::read(&mut encoded.as_slice()).unwrap();

// The forged object reports 100,000 sats and passes SignableTransaction's local
// key/script check, even though arbitrary_txid:0 need not contain that output.
assert_eq!(forged.value(), 100_000);
assert!(SignableTransaction::new(
    vec![forged],
    &[(payment_script, DUST)],
    None,
    None,
    1,
)
.unwrap()
.multisig(&keys)
.is_some());
```
