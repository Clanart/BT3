### Title
PedPoP registers attacker-supplied encryption keys without rejecting the identity point, making encrypted secret shares publicly decryptable - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
The Jenkins bug class is a missing permission check that lets a low-privilege user reach a sensitive function with attacker-specified parameters. The Serai analog is a missing validation check: `Decryption::register` accepts the per-participant ECDH encryption key (`enc_key`) from the broadcast `EncryptionKeyMessage` with no identity/validity check beyond point canonicity in `read_G`. A participant who registers the identity point causes every secret share addressed to them to be encrypted under a publicly-known ECDH output (the identity point), so any observer of the ciphertext can decrypt it and recover that participant's DKG secret share.

### Finding Description
Each participant broadcasts an `EncryptionKeyMessage` carrying `enc_key: C::G`, parsed in `EncryptionKeyMessage::read` via `C::read_G` (canonical point, but identity is a canonical, valid point) [1](#0-0) . `register` stores it unconditionally [2](#0-1) . When others encrypt shares to that participant, `ecdh(key, to)` computes `to * key` [3](#0-2) , and the shared point is fed into `cipher` as `shared_key` to derive the ChaCha20 key [4](#0-3) .

If `to` is the identity point, `ecdh` returns identity for every per-message `key`, so the cipher key is a deterministic public function of `context` alone (`transcript("DKG Encryption v0.2") || context || identity_bytes`). Anyone who obtains the `EncryptedMessage` ciphertext can recompute the keystream and decrypt the `SecretShare` plaintext. The recipient-side `KeyMachine::calculate_share` then decrypts the same way and cannot detect that the confidentiality was void [5](#0-4) . The PoP signature in `EncryptedMessage` only binds `key` (the per-message ephemeral key), not `enc_key`, and there is no check anywhere that `enc_key` is non-identity.

### Impact Explanation
An unprivileged DKG participant who registers `enc_key = identity` receives validly-formed shares but with zero confidentiality. Since these `EncryptedMessage` ciphertexts are routed through authenticated-but-public channels (coordinator/tributary relay), every observer learns the secret share `f_i(l)` each sender `i` computed for participant `l`, and hence `l`'s final secret share (sum of the `f_i(l)`). The result is public disclosure of a threshold secret share that the protocol is explicitly designed to keep private — `calculate_share` sums the decrypted shares into `self.secret` [6](#0-5) . A leaked participant share reduces the effective secrecy threshold of the resulting `ThresholdKeys` and, combined with even one additional share compromise, enables full group key recovery and forgery of FROST signatures.

### Likelihood Explanation
Requires only that a single participant submit identity as `enc_key` in their round-1 message — no collusion, no control of other parties. The message passes `Commitments::read`, `verify_r1` (the PoK covers `commitments[0]`, unrelated to `enc_key`), and `register` without error [7](#0-6) . Exploitation is passive observation of the relayed ciphertext.

### Recommendation
In `Decryption::register` (or `EncryptionKeyMessage::read`), reject `enc_key.is_identity()` and any non-prime-order/torsion point where applicable. Alternatively, derive the cipher from `ecdh` plus both public keys so an identity `enc_key` still yields a key bound to the per-message secret — but an explicit identity rejection in `register` is the minimal fix.

### Proof of Concept
1. Malicious participant `l` runs `KeyGenMachine::generate_coefficients` but publishes an `EncryptionKeyMessage` whose trailing `enc_key` field is the 32-byte identity encoding (`RistrettoPoint::identity().compress()`, i.e. `0x00..00` / identity bytes accepted by `read_G` since identity serializes canonically).
2. Honest senders call `generate_secret_shares`, which invokes `encrypt(rng, l, share_bytes)` → `ecdh(&key, identity) = identity` → `cipher(context, identity)` — a key computable by anyone knowing `context` (public session context).
3. Observer reads the relayed `EncryptedMessage` for `l`, recomputes `ChaCha20` from `transcript.append_message(b"shared_key", identity_bytes)`, applies the keystream to `msg`, obtaining `SecretShare` bytes; `F::from_repr` succeeds since the plaintext was a valid share.
4. Summing all decrypted shares yields `l`'s secret share in the clear, while `calculate_share` on `l`'s machine completes normally — the protocol succeeds yet the share is public.

fn cipher<C: Ciphersuite>(context: [u8; 32], ecdh: &Zeroizing<C::G>) -> ChaCha20 {
  // Ideally, we'd box this transcript with ZAlloc, yet that's only possible on nightly
  // TODO: https://github.com/serai-dex/serai/issues/151
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"encryption_key");

  let mut ecdh = ecdh.to_bytes();
  transcript.append_message(b"shared_key", ecdh.as_ref());
  ecdh.as_mut().zeroize();

  let zeroize = |buf: &mut [u8]| buf.zeroize();

  let mut key = Cc20Key::default();
  let mut challenge = transcript.challenge(b"key");
  key.copy_from_slice(&challenge[.. 32]);
  zeroize(challenge.as_mut());

  // Since the key is single-use, it doesn't matter what we use for the IV
  // The issue is key + IV reuse. If we never reuse the key, we can't have the opportunity to
  // reuse a nonce
  // Use a static IV in acknowledgement of this
  let mut iv = Cc20Iv::default();
  // The \0 is to satisfy the length requirement (12), not to be null terminated
  iv.copy_from_slice(b"DKG IV v0.2\0");

  // ChaCha20 has the same commentary as the transcript regarding ZAlloc
  // TODO: https://github.com/serai-dex/serai/issues/151
  let res = ChaCha20::new(&key, &iv);
  zeroize(key.as_mut());
  res
