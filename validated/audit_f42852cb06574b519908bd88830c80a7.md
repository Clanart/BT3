### Title
DataLayer mirror/subscription URLs trigger unauthenticated SSRF via `http_download` - ([File: chia/data_layer/download_data.py])

### Summary
Any wallet user can publish arbitrary mirror URLs for a DataLayer store via the `add_mirror` RPC, and any node that tracks/subscribes to that store (including automatically, via `update_subscriptions_from_wallet`) will later have its local DataLayer service issue outbound HTTP requests to those attacker-controlled URLs with no scheme/host/IP validation, mirroring the SSRF bug class described in CVE-2018-18646.

### Finding Description
`DataLayer.add_mirror()` accepts a caller-supplied list of URL strings and only checks that the list is non-empty before publishing them on-chain through the wallet RPC (`dl_new_mirror`): [1](#0-0) 

The RPC-facing handler performs no additional validation of the URL contents (scheme, host, or target IP range) before forwarding to the service: [2](#0-1) 

These mirror URLs are subsequently pulled from wallet state and merged into the local subscriptions table for a store id without any filtering: [3](#0-2) [4](#0-3) 

During the periodic sync loop, `fetch_and_validate()` selects one of these server URLs and calls `insert_from_delta_file()` → `download_file()` → `http_download()`, which performs an `aiohttp` GET directly against `server_info.url + "/" + filename` with no scheme allow-listing, no DNS/IP resolution check, and no rejection of loopback/link-local/private addresses: [5](#0-4) [6](#0-5) 

The same untrusted URL is also passed into `get_downloader()`/`get_uploaders()`, which POST JSON payloads (including the store id) to plugin URLs configured locally, but the mirror URL itself flows unchecked into the direct HTTP path when no downloader plugin claims it. Any node that subscribes to a store (explicitly via the `subscribe` RPC, or implicitly because it owns the store and gets pseudo-subscribed, per `update_subscription()`) will fetch from whatever URL the store owner published on-chain: [7](#0-6) 

### Impact Explanation
This lets any unprivileged DataLayer store owner (a normal wallet user, no special permission required) force other participants' local DataLayer services to make outbound HTTP requests to attacker-chosen destinations — e.g., internal-network services, loopback-bound admin/RPC endpoints, or cloud metadata endpoints (`169.254.169.254`) — from the victim's own network position. This is the same bug class as CVE-2018-18646 (SSRF): the request path is entirely attacker-controlled and unauthenticated by the requesting service. Depending on deployment (cloud host, containerized farm, etc.), this can be used for internal network reconnaissance, interacting with otherwise-unreachable local-only services, or exfiltrating response data indirectly through log messages (e.g., `Downloading delta file` logs, or failure states surfaced via RPC).

### Likelihood Explanation
Likelihood is high for triggering the request: adding a mirror is a normal, unprivileged wallet/DataLayer RPC action (`add_mirror`), and any peer who subscribes to that store (a normal, expected DataLayer usage flow) will automatically attempt to fetch from the published URL during the background sync loop with no operator interaction required. No cryptographic or consensus barrier prevents publishing a hostile URL.

### Recommendation
- Validate mirror/server URLs before accepting them in `add_mirror()` / `DataStore.subscribe()` / `update_subscriptions_from_wallet()`: enforce `http(s)` scheme only, resolve and reject requests to loopback, link-local, private, and multicast address ranges (equivalent to a standard SSRF-safe URL fetcher / DNS-rebinding-safe resolver), and consider an explicit user-configurable allow-list for outbound mirror hosts.
- Apply the same validation in `http_download()` (`chia/data_layer/download_data.py`) immediately before the `aiohttp` request, since that is the actual point of outbound traffic and the last defensive checkpoint regardless of how the URL entered the subscriptions table.
- Consider disabling automatic following of mirror URLs by default and requiring explicit user confirmation/opt-in per store/host.

### Proof of Concept
1. Attacker creates a DataLayer store and calls `add_mirror` with `urls=["http://169.254.169.254/latest/meta-data/", ]` (or `http://127.0.0.1:<internal-port>/...`) via the DataLayer RPC:
   `data_rpc_api.add_mirror({"id": store_id.hex(), "urls": ["http://169.254.169.254/latest/meta-data/"], "amount": 1, "fee": 1})` [2](#0-1) 
2. This is published on-chain via `dl_new_mirror`, visible to any node that later subscribes to `store_id` (e.g. via `data subscribe` CLI or `dl_track_new`/`subscribe` RPC).
3. On the victim node, `update_subscriptions_from_wallet()` pulls this URL into the local subscriptions table, and the periodic `update_subscription()` background job calls `fetch_and_validate()` → `insert_from_delta_file()` → `download_file()` → `http_download()`, causing the victim's process to issue `GET http://169.254.169.254/latest/meta-data/.../<filename>.dat`, from the victim's network context, with no destination restriction. [6](#0-5)

            old_urls = [row["url"] async for row in cursor]

                {
                    "tree_id": store_id,
                },
            )
            from_subscriptions_urls = {row["url"] async for row in cursor}
            additions = {url for url in new_urls if url not in old_urls}
            removals = [url for url in old_urls if url not in new_urls]

                    "DELETE FROM subscriptions WHERE url == :url AND tree_id == :tree_id",

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
