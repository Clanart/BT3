### Title
Suspended validators are excluded from committee/consensus duties but still receive full staking rewards - ([File: kaiax/staking/impl/getter.go], [File: kaiax/valset/types.go])

### Summary
The `Suspended` flag on a validator node is enforced only in the `kaiax/valset` module's committee/proposer selection path, but is never consulted by the `kaiax/staking` and `kaiax/reward` modules when computing reward eligibility and staking-reward shares. A validator that is `ValActive` and `Suspended` therefore cannot sign or propose blocks, yet continues to receive its full proportional staking reward every block — the exact "restricted for one role, unrestricted for another role" pattern described in the source report (suspended for partyA duties but still permitted to act as partyB).

### Finding Description
`NodeMap.Committee()` explicitly excludes suspended nodes from the set eligible to sign/propose blocks: [1](#0-0) 

This exclusion is also applied when computing `QualifiedValidators`/committee with a safety fallback: [2](#0-1) 

However, reward eligibility is computed independently by the staking module using `NodeState.IsRewardEligible()`, which checks **only** the state, never the `Suspended` field: [3](#0-2) 

This is exactly the function used to filter which AddressBookV2 profiles are kept in `StakingInfo` for the permissionless staking path: [4](#0-3) 

The resulting `StakingInfo` (which contains no `Suspended` information at all) is then consumed directly by the reward module to compute each validator's staking-reward share, again with no suspension check: [5](#0-4) 

Confirmed by the existing test that documents "Suspended is informational, not a violation exemption" only in the context of *further demotion/violation escalation* — it says nothing about reward eligibility, and no test or code path exists that excludes suspended nodes from `StakingInfo` or reward computation: [6](#0-5) 

### Impact Explanation
A validator that has been suspended (e.g., due to fault detection / PFS violations, per the violation-transition logic) is stripped of its consensus role — it cannot be selected for the committee, cannot sign committed seals, and cannot be proposer — but its staking amount remains counted in `StakingInfo.ConsolidatedNodes()`, so it keeps earning its full proportional share of the KIP-82/Flex staking reward pool every block until it is eventually fully demoted (`ValExiting`) via the separate, slower demotion machinery. This misdirects reward funds that are meant to compensate validators for performing consensus work to a validator that is contributing nothing to consensus, diluting rewards for the honestly-participating committee members and undermining the economic penalty that suspension is intended to represent.

### Likelihood Explanation
High likelihood of occurring in practice: suspension is triggered automatically by the protocol's fault-detection (PFS) mechanism, not by any attacker action, and per the violation-transition tests, suspended-but-`ValActive` nodes can persist in that state for a window of blocks before being moved to `ValExiting`. During that entire window, every single block finalization pays out staking rewards to the suspended validator, with no special-casing anywhere in the staking/reward pipeline to prevent it.

### Recommendation
Propagate the `Suspended` status into `StakingInfo` (or filter it in the `kaiax/reward` module) so that suspended `ValActive` nodes are excluded from `ConsolidatedNodes()`/`assignStakingRewards`/`assignStakingRewardsFlex`, consistent with their exclusion from `Committee()`. Concretely, either (a) have `IsRewardEligible()` also require `!Suspended`, or (b) have `parsePermissionlessCallResult` cross-reference the valset module's suspended list before building `StakingInfo`, ensuring reward eligibility and consensus eligibility use the same definition of "active validator."

### Proof of Concept
Not directly demonstrable as a standalone PoC since this is a systemic state-computation inconsistency rather than a single malicious transaction; the exposure is verified purely via code inspection of the disjoint eligibility checks:
1. `Committee()` excludes `Suspended` nodes: [1](#0-0) 
2. `IsRewardEligible()` (used to build `StakingInfo`) does not check `Suspended`: [3](#0-2)  and [7](#0-6) 
3. Reward distribution (`assignStakingRewards`) consumes this `Suspended`-blind `StakingInfo`: [5](#0-4) 

Note: I was unable to fully verify whether there is downstream logic elsewhere (e.g., in a hardfork-gated code path not surfaced by search) that filters `Suspended` before reward computation; the index does not show any such check, but a full-repository trace via a Devin session with complete file access would be needed to rule this out with certainty.

// committeeWithFallback returns the committee at the given block.
// Committee = {VA} - {Suspended}.
//
// Safety fallback: when len(committee)=0 due to {ValActive} ⊆ SuspendedSet, fallback to all VA.
func committeeWithFallback(nodes valset.NodeMap) (committee valset.NodeMap, fellBack bool) {
	committee = nodes.Committee()
	if len(committee) > 0 {
		return committee, false
	}

	// ignore SuspendedSet
	return nodes.FilterByState(valset.ValActive), true
}

// getQualifiedValidators: qualified = committee = {VA} − {Suspended} (with safety fallback).
func (v *ValsetModule) getQualifiedValidators(num uint64) (*valset.AddressSet, error) {
	nodes, err := v.getNodes(num)
	if err != nil {
		return nil, err
	}
	committee, fellBack := committeeWithFallback(nodes)
	if fellBack && v.lastSuspendFallbackLog != num {
		logger.Warn("all ValActive are suspended, ignoring suspended set for committee", "num", num)
		v.lastSuspendFallbackLog = num
	}
	return valset.NewAddressSet(committee.Addresses()), nil
}

// parsePermissionlessCallResult converts ABv2 multicall results into StakingInfo,
// keeping only reward-eligible nodes (KIP-286); amounts are effective stake (KIP-287).
func parsePermissionlessCallResult(num uint64, profiles []multicall.Profile, amounts []*big.Int, kefAddr, kifAddr, kpfAddr common.Address, clRes clRegistryResult) (*staking.StakingInfo, error) {
	if len(profiles) == 0 {
		return emptyStakingInfo(num), nil
	}
	if len(profiles) != len(amounts) {
		logger.Error("length of profiles and amounts differ", "sourceNum", num, "profileLen", len(profiles), "amountLen", len(amounts))
		return nil, staking.ErrAddressBookResult
	}
	if len(clRes.NodeIds) != len(clRes.ClPools) || len(clRes.NodeIds) != len(clRes.StakingAmounts) {
		logger.Error("length of CL registry result fields differ", "sourceNum", num, "nodeLen", len(clRes.NodeIds), "poolLen", len(clRes.ClPools), "amountLen", len(clRes.StakingAmounts))
		return nil, staking.ErrCLRegistryResult
	}

	nodeIds := make([]common.Address, 0, len(profiles))
	stakingContracts := make([]common.Address, 0, len(profiles))
	rewardAddrs := make([]common.Address, 0, len(profiles))
	stakingAmounts := make([]uint64, 0, len(profiles))
	for i, p := range profiles {
		if !valset.NodeState(p.State).IsRewardEligible() {
			continue
		}
		nodeIds = append(nodeIds, p.NodeId)
		stakingContracts = append(stakingContracts, p.StakingContract)
		rewardAddrs = append(rewardAddrs, p.RewardAddress)
		stakingAmounts = append(stakingAmounts, new(big.Int).Div(amounts[i], big.NewInt(params.KAIA)).Uint64())
	}

// assignStakingRewards assigns staking rewards to stakers according to their staking amounts.
// Returns the allocation and the remainder.
func assignStakingRewards(config *reward.RewardConfig, stakersReward *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		cns               = si.ConsolidatedNodes()
		minStake          = config.MinimumStake.Uint64()
		totalExcessInt    = uint64(0) // sum of excess stakes (the amount over minStake) over all stakers
		cnTotalStakingMap = make(map[common.Address]uint64)
		isPrague          = config.Rules.IsPrague
	)
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it.
		if cn.StakingAmount >= minStake {
			// Calculate total staking amount once
			cnTotalStakingAmount := cn.StakingAmount
			if isPrague && cn.CLStakingInfo != nil {
				cnTotalStakingAmount += cn.CLStakingInfo.CLStakingAmount
			}
			totalExcessInt += cnTotalStakingAmount - minStake
			cnTotalStakingMap[cn.RewardAddr] = cnTotalStakingAmount
		}
	}

	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(stakersReward)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		cnTotalStakingAmount := cnTotalStakingMap[cn.RewardAddr]
		if cnTotalStakingAmount > minStake {
			// The KAIA unit will cancel out:
			// reward (kei) = excess (KAIA) * stakersReward (kei) / totalExcess (KAIA)
			excess := new(big.Int).SetUint64(cnTotalStakingAmount - minStake)
			if reward := new(big.Int).Div(new(big.Int).Mul(excess, stakersReward), totalExcess); reward.Sign() > 0 {
				if isPrague && cn.CLStakingInfo != nil {
					// The remaining amount will be added to the cnAmount.
					cnAmount, clAmount := cn.Split(reward)
					alloc[cn.RewardAddr] = cnAmount
					alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
				} else {
					alloc[cn.RewardAddr] = reward
				}
				remaining.Sub(remaining, reward)
			}
		}
	}
	return alloc, remaining

// TestApplyViolationTransition_SuspendedNotExempt verifies that suspended
// ValActive validators are subject to the same violation rules as non-suspended
// ones — Suspended is informational, not a violation exemption.
func TestApplyViolationTransition_SuspendedNotExempt(t *testing.T) {
	m := NodeMap{
		addr1: {State: ValActive, StakingAmount: belowMinStake, Suspended: true},  // minStake violation
		addr2: {State: ValActive, StakingAmount: aboveMinStake, Suspended: true},  // PFS severe
		addr3: {State: ValActive, StakingAmount: aboveMinStake, Suspended: false}, // no violation
	}
	ctx := violationCtx(t, ctxOpts{
		PfsThreshold:     2,
		MaxSlotAvailable: noSlotLimit,
		MinActiveCount:   noMinActive,
		PFS:              map[common.Address]uint64{addr2: 3},
		PfReport:         []common.Address{addr1},
	})
	out := ctx.applyViolationTransition(m)
	assert.Equal(t, ValExiting, out[addr1].State, "suspended + low staking → ValExiting")
	assert.Equal(t, ValExiting, out[addr2].State, "suspended + PFS severe → ValExiting")
	assert.Equal(t, ValActive, out[addr3].State, "non-suspended, no violation → unchanged")
