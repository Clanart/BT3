### Title
Direct ERC20 donation of `stakingToken` to `MasterMagpie` inflates `BaseRewardPool.totalStaked()`, permanently diluting `rewardPerTokenStored` and freezing a portion of every future reward deposit - ([File: rewards/BaseRewardPool.sol], [File: rewards/BaseRewardPoolV2.sol])

### Summary
`BaseRewardPool.totalStaked()` reads the raw ERC20 balance of `stakingToken` held by `MasterMagpie` (`operator`), rather than the sum of individually tracked user stakes. Any unprivileged address can `transfer()` `stakingToken` directly to `MasterMagpie` without calling `deposit()`, inflating this denominator while their own `balanceOf()` (backed by `IMasterMagpie.stakingInfo`) stays zero, which permanently reduces the `rewardPerTokenStored` increment computed in `_provisionReward` for every subsequent reward distribution.

### Finding Description
`totalStaked()` and `balanceOf()` use two different, inconsistent sources of truth:
- `totalStaked()` = `IERC20(stakingToken).balanceOf(operator)` — the raw token balance of `MasterMagpie`. [1](#0-0) 
- `balanceOf(_account)` = `IMasterMagpie(operator).stakingInfo(stakingToken, _account)` — the internally tracked `user.amount` in `MasterMagpie`. [2](#0-1) 

`MasterMagpie._deposit` only increments `user.amount`/`user.available` when tokens arrive through `deposit`/`depositFor`, via `safeTransferFrom`. [3](#0-2) 

Nothing prevents an attacker from calling `IERC20(stakingToken).transfer(masterMagpie, amount)` directly. This raises `IERC20(stakingToken).balanceOf(operator)` (and thus `totalStaked()`) without incrementing any `userInfo[_stakingToken][_account].amount`, so the attacker's own `balanceOf()` (and everyone else's individually tracked balances) remains unchanged while the aggregate denominator grows.

The impact surfaces in `_provisionReward`, called from `queueNewRewards` (manager-only) or `donateRewards` (fully permissionless):
```
rewardInfo.rewardPerTokenStored =
    rewardInfo.rewardPerTokenStored +
    (_amountReward * 10**stakingDecimals()) /
    this.totalStaked();
``` [4](#0-3) 
The identical pattern exists in the V2 pool. [5](#0-4) 

Because the denominator `totalStaked()` is inflated by the donated, unattributed tokens, the numerator increment (`rewardInfo.rewardPerTokenStored`) is computed smaller than it should be relative to the actually staked principal. `rewardPerTokenStored` is a monotonically increasing global accumulator used by every user's `earned()` calculation, so this understatement is baked in permanently — it is never corrected by later events. The reward tokens transferred into the pool via `safeTransferFrom` in `_provisionReward` physically sit in the contract, but the fraction corresponding to the dilution can never be claimed by any staker's `earned()`, because no user's tracked balance accounts for the donated `stakingToken`. `donateRewards` has no restriction on the caller. [6](#0-5) 

No modifier, receipt-token accounting, or reward-index safeguard prevents this: `totalStaked()` trusts raw ERC20 balance rather than a strictly-incremented internal counter, and no reconciliation exists between `balanceOf(operator)` and the sum of `stakingInfo` across all stakers.

### Impact Explanation
This is a permanent freezing of unclaimed yield: a portion of every reward token deposited via `queueNewRewards`/`donateRewards` after the donation becomes permanently unclaimable by any staker, because `rewardPerTokenStored` under-accrues relative to actual reward tokens custodied by the pool. The effect compounds with every subsequent reward distribution as long as the donated balance remains un-attributed, and it is irreversible without a privileged/manual fix (e.g., manager sweeping and re-crediting, which is outside attacker's unprivileged path). This matches the "theft or permanent freezing of unclaimed yield" impact class.

### Likelihood Explanation
The attack requires only a plain ERC20 `transfer` call to `MasterMagpie`'s address by any holder of the relevant `stakingToken` — no special role, contract deployment tricks, or governance access needed. It is capital-costly for the attacker (they donate real tokens they cannot reclaim) but requires no cooperation from privileged roles: the damage manifests automatically the next time a manager performs the normal, expected `queueNewRewards` action, or immediately if the attacker (or anyone) calls the permissionless `donateRewards`. It is fully repeatable against every pool that reuses this `BaseRewardPool`/`BaseRewardPoolV2` totalStaked pattern.

### Recommendation
Track `totalStaked()` as an internally incremented/decremented counter (updated only in `_deposit`/`_withdraw` paths) instead of reading the raw ERC20 balance of `operator`, so direct token transfers cannot influence the reward-per-token denominator. Alternatively, have `MasterMagpie` expose an aggregate "sum of tracked user.amount" view for each `stakingToken` that `BaseRewardPool.totalStaked()` calls into.

### Proof of Concept
Foundry test outline:
1. Deploy `MasterMagpie`, `BaseRewardPool` (or V2), and a mock `stakingToken`/reward token; register the pool.
2. Legitimate staker `A` deposits `100e18` `stakingToken` via `MasterMagpie.deposit`. Confirm `BaseRewardPool.totalStaked() == 100e18` and `balanceOf(A) == 100e18`.
3. Attacker (no staking, no roles) calls `stakingToken.transfer(address(masterMagpie), 100e18)` directly (not through `deposit`). Confirm `BaseRewardPool.totalStaked() == 200e18` while `balanceOf(attacker) == 0` and `balanceOf(A)` unchanged.
4. Reward manager calls `queueNewRewards(1000e18, rewardToken)` (or any unprivileged caller uses `donateRewards`). Compute expected `rewardPerTokenStored` if `totalStaked` were `100e18` (undiluted) vs. actual result with `totalStaked() == 200e18`; assert the stored value is exactly half of the undiluted expectation.
5. Assert `A.earned(rewardToken)` equals only `500e18` instead of the full `1000e18` that was transferred into the pool, and that this `500e18` gap is permanently unclaimable by any account (no other staker exists to claim it), demonstrating frozen yield.

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (this.totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingDecimals()) /
                this.totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
    }
