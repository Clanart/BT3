### Title
Unbounded canonical-CLVM length-prefix parsing causes out-of-bounds read / crash on submitted spend bundles - (File: chia/full_node/mempool_manager.py)

### Summary
`is_atom_canonical()` and `is_clvm_canonical()` in [1](#0-0)  parse the attacker-supplied `puzzle_reveal`/`solution` bytes of every coin spend in a submitted `SpendBundle` to decide DEDUP eligibility, mirroring the class of bug in the reported GPAC `abst_box_read` CVE: a size/length field read from untrusted input is used to advance a read cursor with no check that the cursor stays inside the buffer.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` decodes a variable-length (1–6 byte) size prefix and then reads `clvm_buffer[offset]` repeatedly, incrementing `offset` for each prefix byte, without ever checking `offset < len(clvm_buffer)`: [2](#0-1) 
Its caller, `is_clvm_canonical`, loops reading `b = clvm_buffer[offset]` and calls `is_atom_canonical`, again with no bounds check before dereferencing the buffer, only validating `offset == len(clvm_buffer)` once `tokens_left` naturally reaches zero: [3](#0-2) 

This is called directly on attacker-controlled bytes for every coin spend in `validate_spend_bundle()`: [4](#0-3) 

A crafted `puzzle_reveal` or `solution` whose final atom declares a multi-byte length prefix that is truncated at the end of the buffer (e.g., a multi-byte length-prefix byte such as `0xF8` placed as the very last byte, or one that encodes an atom length extending past the buffer) causes `offset` to run past `len(clvm_buffer)`, triggering an unhandled `IndexError` when `clvm_buffer[offset]` is next dereferenced — this is the Python analog of the out-of-bounds read/write in `abst_box_read` (both stem from trusting a length field to be consistent with actual remaining buffer size).

`validate_spend_bundle()` is invoked from `add_spend_bundle()` with no surrounding `try/except`: [5](#0-4) 

Contrast this with every other binary parser in the codebase (`full_block_utils.py`'s `skip_list`/`skip_bytes`/`generator_from_block`, and the tested rejections in `test_full_block_utils.py`) which explicitly check that a declared length/count does not exceed the remaining buffer before slicing, e.g.: [6](#0-5) 
`is_atom_canonical`/`is_clvm_canonical` lack this equivalent bounds check.

### Impact Explanation
If the `IndexError` is not caught anywhere above `add_spend_bundle()` (I could not fully trace every RPC/network call site in the time available — this needs verification against the full call chain from `full_node/full_node.py`'s tx-receive handler and RPC `push_tx`), a single crafted, otherwise cheap and unsigned-looking `SpendBundle` submitted to a node's mempool could raise an unhandled exception during mempool admission, which is a spend-triggered transaction-processing disruption. If it is caught somewhere generically (e.g., a broad `except Exception` in the network message handler), the practical impact is reduced to a rejected transaction rather than a halt, which would not meet this scan's severity bar.

### Likelihood Explanation
Reachability is straightforward and unprivileged: any spend-bundle submitter controls `puzzle_reveal`/`solution` bytes for a coin spend, and DEDUP-eligibility checking runs unconditionally on every coin spend in mempool admission before other validation completes.

### Recommendation
Add explicit remaining-buffer-length checks to `is_atom_canonical` (before each `offset += 1`/`clvm_buffer[offset]` access) and to `is_clvm_canonical`'s main loop (`offset < len(clvm_buffer)` before dereferencing), returning `False`/raising a handled `ValueError` instead of allowing `IndexError` to propagate, consistent with the bounds-checked pattern already used in `full_node/full_block_utils.py`.

### Proof of Concept
Construct a `CoinSpend` whose `solution` (or `puzzle_reveal`) bytes end with a truncated multi-byte atom length prefix, e.g. a buffer ending in `\xf8` (declares a 5-byte-extended length prefix per `is_atom_canonical`'s `0b11111100` branch) with fewer than 5 trailing bytes actually present, then submit it in a `SpendBundle` via `add_spend_bundle()`/mempool admission; `is_atom_canonical` will attempt to read `clvm_buffer[offset]` past the end of the buffer, raising an uncaught `IndexError` inside `validate_spend_bundle()`.

**Note on confidence**: I was not able to fully verify, within the available iterations, whether a higher-level `except Exception` handler around the full transaction-receipt/RPC call path catches this `IndexError` before it can disrupt node processing — this is a mitigating factor that would need confirmation by reading `chia/full_node/full_node.py`'s spend-bundle intake path and the RPC `push_tx` handler, which I did not have iterations remaining to inspect.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value


def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)

def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
