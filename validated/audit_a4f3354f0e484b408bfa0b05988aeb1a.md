## Analysis

Confirmed: `CallDispatcher.dispatch(bytes memory params)` is declared `external` with **no access-control modifier whatsoever** [1](#0-0) , and its interface explicitly documents it as dispatching "untrusted call(s)" [2](#0-1) . `IntentGatewayV2` treats the deployed `CallDispatcher` as a single shared, persistent instance stored in `_params.dispatcher` and reused across every user's `placeOrder`/`fillOrder` call for predispatch/postdispatch execution [3](#0-2) [4](#0-3) .

### Title
Unauthenticated `CallDispatcher.dispatch` Lets Anyone Grant Infinite Approvals / Steal Any Balance Held by the Shared Dispatcher - (File: evm/src/utils/CallDispatcher.sol)

### Summary
The seed report flags `BellumFactory` granting `type(uint256).max` ERC20 approvals to external routers it doesn't control, creating a standing drain vector if the router is ever compromised. Hyperbridge's `IntentGatewayV2` intent-fill flow uses the identical unrestricted-approval pattern intentionally (order calldata can call `approve(router, type(uint256).max)` on the shared `CallDispatcher`, as shown in the protocol's own tests and docs) [5](#0-4) . The local analog is materially worse: the contract that holds these approvals and any transient token/ETH balances — `CallDispatcher` — exposes its `dispatch()` entrypoint to **anyone**, not just the `IntentGatewayV2` gateway that is supposed to be its sole caller.

### Finding Description
`CallDispatcher` is a single, persistent, shared contract referenced by `_params.dispatcher` in `IntentGatewayV2` [6](#0-5) . During `placeOrder` (predispatch) and order fill (postdispatch/`_execute`), the gateway:
1. Transfers real user/solver funds (ERC20 or native) into the `CallDispatcher` [7](#0-6) .
2. Calls `ICallDispatcher(dispatcher).dispatch(order.predispatch.call)` / `order.output.call`, which executes attacker/user-supplied `Call[]` including `approve(...)` calls with `type(uint256).max` allowances to arbitrary routers [8](#0-7) .
3. Sweeps back only the balances of tokens explicitly listed in `order.inputs`/`order.output.assets` [9](#0-8) ; any other token touched by intermediate multi-hop swap calldata (e.g. WETH in a USDC→WETH→DAI route) is **never swept** and remains stranded on `CallDispatcher`.

Because `dispatch()` has zero caller restriction [10](#0-9) , any unprivileged address can call `CallDispatcher.dispatch()` directly, bypassing `IntentGatewayV2` entirely, and encode its own `Call[]` to:
- Pull out any ERC20 balance currently sitting on the dispatcher via `transfer`, or
- Exploit a previously-planted infinite approval (an attacker can place their own order whose predispatch/postdispatch calldata does `approve(attackerContract, type(uint256).max)` on any token, which persists in that token's on-chain allowance mapping for `CallDispatcher` indefinitely).

Since `CallDispatcher` is the same shared instance used by every order on the gateway, once an attacker plants a standing approval for a token to a contract they control, any balance of that token that later transits or lingers on `CallDispatcher` (stray/dust balances from unswept intermediate tokens in other users' multi-hop postdispatch calldata, or accidental direct transfers to the well-known dispatcher address) becomes drainable by the attacker without any relayer, prover, admin, or governance involvement — an ordinary user crafting an order is sufficient.

### Impact Explanation
This directly matches the required impact classes: unauthorized execution (anyone can execute arbitrary calls through `CallDispatcher.dispatch`) and unauthorized transfer/loss of funds (any token balance transiently or accidentally held by the dispatcher — including funds mid-flight through another user's swap calldata or dust from partial fills — can be stolen by an attacker who either calls `dispatch()` directly or exploits a self-planted infinite approval). Because the dispatcher is shared across the entire `IntentGatewayV2` deployment, a single exploit affects all users routing calldata-bearing orders through it, mirroring the "impact multiple tokens/users simultaneously" concern in the seed report.

### Likelihood Explanation
High for the access-control gap itself: `dispatch()` is a plain public function with no `onlyGateway`/`msg.sender` check [1](#0-0) , so exploitability requires only that `CallDispatcher` hold or transiently receive a nonzero balance of some token — which is guaranteed by design during predispatch/postdispatch execution (`order.predispatch.assets` are pushed to the dispatcher before `dispatch()` runs) [7](#0-6) , and by the documented fact that only the declared input/output token set is swept back, leaving other tokens touched by calldata (or a stray direct transfer) unrecovered [11](#0-10) .

### Recommendation
Restrict `CallDispatcher.dispatch` to be callable only by its designated `IntentGatewayV2`/host caller (an `onlyGateway` modifier or constructor-bound immutable caller check), and additionally sweep/verify that no residual balance of *any* token remains on the dispatcher after each `dispatch()` invocation, not only the tokens declared in `order.inputs`/`order.output.assets`.

### Proof of Concept
1. Attacker deploys `AttackerSink` (any contract with code, satisfying the `extcodesize` check in `CallDispatcher.dispatch`).
2. Attacker calls `CallDispatcher.dispatch(abi.encode(calls))` directly (not through `IntentGatewayV2`) with `calls = [{to: TOKEN_X, value: 0, data: approve(AttackerSink, type(uint256).max)}]`. This succeeds because `dispatch()` performs no caller check [1](#0-0) .
3. Attacker separately places a benign-looking order whose `output.call` performs a multi-hop swap (e.g., USDC→WETH→DAI) via legitimate `CallDispatcher.dispatch` calls issued by `IntentGatewayV2._execute` [8](#0-7) ; WETH is an intermediate hop not listed in `order.output.assets`, so it is never swept back [11](#0-10) , leaving a nonzero WETH balance on `CallDispatcher`.
4. Attacker's `AttackerSink`, holding the standing approval from step 2 (approved for WETH, or for any token attacker anticipates will transit the dispatcher), calls `WETH.transferFrom(CallDispatcher, AttackerSink, balance)` to drain the stranded funds — no relayer, prover, or admin action required.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
