### Title
Unverified external-call target in the CosmWasm→EVM `CallEvm` bridge lets any CW contract be tricked into draining ERC20/pointer approvals granted to its own EVM address - (File: x/evm/keeper/evm.go)

### Summary
The Unizen exploit stemmed from a DEX aggregator that forwarded an attacker-chosen `target` + `calldata` to a low-level `call()` using the aggregator's own (approved) identity, with no whitelist on the call target. Sei-chain's CosmWasm→EVM bridge exposes the equivalent primitive: `MsgInternalEVMCall`, handled by `HandleInternalEVMCall`, executes an EVM call to an arbitrary `to` address with arbitrary `data`, using the *calling CW contract's own associated EVM address* as `from` — with **no validation of the destination contract**, unlike the sibling `MsgInternalEVMDelegateCall` path which explicitly restricts the target to a registered pointer contract.

### Finding Description
`HandleInternalEVMCall` in [1](#0-0)  takes `req.To` and `req.Data` verbatim from the `MsgInternalEVMCall` (built via the `CallEvm` CosmWasm binding, see `EncodeCallEVM` in [2](#0-1) ) and executes it with `from = k.GetEVMAddressOrDefault(ctx, senderAddr)`, i.e. the associated EVM address of the CW contract itself, via `CallEVM` in [3](#0-2) .

Contrast this with `HandleInternalEVMDelegateCall`, which enforces `"only pointer contract can make delegatecalls"` by checking that `to` matches the contract's registered pointer before allowing the call: [4](#0-3) . The plain-call path has no analogous restriction — any `to`/`data` the CW contract chooses to emit is executed as that contract's own EVM identity.

This mirrors the Unizen root cause exactly: a privileged/trusted identity (there, the aggregator; here, a CW contract's associated EVM address) executes attacker-influenced `(target, calldata)` without verifying the target is a legitimate, expected counterpart. If a CW contract (e.g., a vault, router, or aggregator-style contract built on Sei) ever forwards user-supplied parameters into a `CallEvm` custom message — a natural pattern for building swap/aggregator functionality on top of ERC20/CW20 pointers — and that contract's EVM address holds an ERC20/pointer `allowance` from users (e.g., because users `approve()`'d it to pull funds for a swap), an attacker can invoke that contract's proxy/execute function with `to = <the pointer/ERC20 contract>` and `data = transferFrom(victim, attacker, amount)`. The resulting `CallEVM` executes with `from` = the vulnerable contract's EVM address as `msg.sender`, and since the ERC20/pointer contract sees the call as coming from the approved spender, it happily transfers the victim's tokens to the attacker — an "unverified external call" drain of approvals, structurally identical to Unizen.

### Impact Explanation
Any CW contract deployed on Sei that builds a generic proxy/aggregator pattern around `CallEvm` and accumulates ERC20/CW20-pointer allowances from its users is exposed to unauthorized transfer of those approved funds, since the underlying precompile/bridge layer performs no target validation on plain (non-delegate) internal EVM calls. This is a direct, unauthorized-transfer-via-pointer/precompile class of impact (concrete fund loss for any user who has an outstanding `approve()` on such a contract).

### Likelihood Explanation
Exploitation requires a CW contract to exist that (a) exposes an execute message letting a caller supply/influence the EVM call target and calldata for a `CallEvm` message, and (b) holds token allowances from other users (a common design for swap/aggregator/vault-style contracts, exactly the class of protocol that was hit in the Unizen incident). The chain-level bridge itself does nothing to prevent this pattern — the missing check is structural and lives in the base `x/evm` module (`HandleInternalEVMCall`), not something a contract author would obviously realize needs additional whitelisting, since the sibling delegatecall path implies pointer-style restriction is "handled" at this layer.

### Recommendation
Add the same target-authorization discipline used in `HandleInternalEVMDelegateCall` to `HandleInternalEVMCall`, or at minimum document/enforce that CW contracts building `CallEvm` messages must never forward attacker-controlled `to`/`data` pairs when the contract's EVM address can hold token allowances. Consider restricting plain internal EVM calls from CW contracts to a pre-registered allow-list of targets (mirroring the pointer check), or requiring contracts to explicitly acknowledge/opt into unrestricted call forwarding only for non-custodial use cases.

### Proof of Concept
1. Deploy (or identify) a CW contract `V` on Sei whose execute handler builds `CosmosMsg::Custom(EvmMsg::CallEvm { to, value, data })` (per the `CallEvm` binding wired through `EncodeCallEVM`, [2](#0-1) ) from caller-supplied `to`/`data`, as part of a generic "execute arbitrary swap step" feature.
2. A victim user calls `approve(V_evm_address, amount)` on an ERC20/CW20-pointer token, trusting `V` to only use the allowance for its intended swap logic.
3. Attacker calls `V`'s execute entrypoint with `to = <token address>`, `data = transferFrom(victim, attacker, amount)`.
4. `V` emits `MsgInternalEVMCall{Sender: V's account, To: token, Data: transferFrom(...)}`, which is routed to `HandleInternalEVMCall` ( [1](#0-0) ) and executed via `CallEVM` with `from = V`'s EVM address — no check that `to` is an expected/whitelisted contract.
5. The token contract executes `transferFrom` treating `V` as `msg.sender` (the approved spender), transferring the victim's approved balance to the attacker.

func (k *Keeper) HandleInternalEVMCall(ctx sdk.Context, req *types.MsgInternalEVMCall) (*sdk.Result, error) {
	var to *common.Address
	if req.To != "" {
		addr := common.HexToAddress(req.To)
		to = &addr
	}
	senderAddr, err := sdk.AccAddressFromBech32(req.Sender)
	if err != nil {
		return nil, err
	}
	ret, err := k.CallEVM(ctx, k.GetEVMAddressOrDefault(ctx, senderAddr), to, req.Value, req.Data)
	if err != nil {
		return nil, err
	}
	return &sdk.Result{Data: ret}, nil
}

func (k *Keeper) HandleInternalEVMDelegateCall(ctx sdk.Context, req *types.MsgInternalEVMDelegateCall) (*sdk.Result, error) {
	var to *common.Address
	if req.To != "" {
		addr := common.HexToAddress(req.To)
		to = &addr
	} else {
		return nil, errors.New("cannot use a CosmWasm contract to delegate-create an EVM contract")
	}
	addr, _, exists := k.GetAnyPointerInfo(ctx, types.PointerReverseRegistryKey(common.BytesToAddress([]byte(req.FromContract))))
	if !exists || common.BytesToAddress(addr).Cmp(*to) != 0 {
		return nil, errors.New("only pointer contract can make delegatecalls")
	}

func (k *Keeper) CallEVM(ctx sdk.Context, from common.Address, to *common.Address, val *sdk.Int, data []byte) (retdata []byte, reterr error) {
	if ctx.IsEVM() && !ctx.EVMEntryViaWasmdPrecompile() {
		return nil, errors.New("sei does not support EVM->CW->EVM call pattern")
	}
	if to == nil && len(data) > params.MaxInitCodeSize {
		return nil, fmt.Errorf("%w: code size %v, limit %v", core.ErrMaxInitCodeSizeExceeded, len(data), params.MaxInitCodeSize)
	}
	if to != nil && to.Cmp(common.HexToAddress(solo.SoloAddress)) == 0 {
		return nil, errors.New("cannot call Solo precompile via CosmWasm")
	}
	value := utils.Big0
	if val != nil {
		if val.IsNegative() {
			return nil, sdkerrors.ErrInvalidCoins
		}
		value = val.BigInt()
	}
	// This call was not part of an existing StateTransition, so it should trigger one
	executionCtx := ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx)).WithEVMEntryViaWasmdPrecompile(false)
	stateDB := state.NewDBImpl(executionCtx, k, false)
	gp := k.GetGasPool()
	evmMsg := &core.Message{
		Nonce:     stateDB.GetNonce(from), // replay attack is prevented by the AccountSequence number set on the CW transaction that triggered this call
		GasLimit:  k.getEvmGasLimitFromCtx(ctx),
		GasPrice:  utils.Big0, // fees are already paid on the CW transaction
		GasFeeCap: utils.Big0,
		GasTipCap: utils.Big0,
		To:        to,
		Value:     value,
		Data:      data,
		From:      from,
	}
	// should not increment nonce since this isn't a transaction
	res, err := k.applyEVMMessage(ctx, evmMsg, stateDB, gp, false)
	if err != nil {
		return nil, err
	}
	k.consumeEvmGas(ctx, res.UsedGas)
	if res.Err != nil {
		return nil, res.Err
	}

func EncodeCallEVM(rawMsg json.RawMessage, sender sdk.AccAddress, info wasmvmtypes.MessageInfo) ([]sdk.Msg, error) {
	encodedCallEVM := bindings.CallEVM{}
	if err := json.Unmarshal(rawMsg, &encodedCallEVM); err != nil {
		return []sdk.Msg{}, err
	}
	decodedData, err := base64.StdEncoding.DecodeString(encodedCallEVM.Data)
	if err != nil {
		return []sdk.Msg{}, err
	}
	internalCallEVMMsg := types.MsgInternalEVMCall{
		Sender: sender.String(),
		To:     encodedCallEVM.To,
		Value:  encodedCallEVM.Value,
		Data:   decodedData,
	}
	return []sdk.Msg{&internalCallEVMMsg}, nil
}
