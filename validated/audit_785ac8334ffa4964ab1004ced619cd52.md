### Title
Scanner reports immature coinbase outputs as spendable, letting any miner poison the wallet's spendable-output set - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_block` iterates over `block.txdata` including `txdata[0]` (the coinbase transaction) and emits `ReceivedOutput`s for it. Coinbase outputs are consensus-unspendable for 100 blocks, yet `ReceivedOutput` carries no maturity information and is documented as "A spendable output". Any downstream consumer that feeds these outputs into `SignableTransaction::new` / `SignMachine` will construct a transaction spending an immature coinbase, which is rejected by the network — i.e., funds are reported received that are not spendable.

### Finding Description
In `networks/bitcoin/src/wallet/mod.rs`, `scan_block` calls `scan_transaction` on every transaction in the block:

```rust
pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
}
``` [1](#0-0) 

`scan_transaction` matches purely on `output.script_pubkey` and wraps each match in a `ReceivedOutput` with `offset`, `output`, and `outpoint` — no block height, no coinbase flag, no maturity:

```rust
if let Some(offset) = self.scripts.get(&output.script_pubkey) {
    res.push(ReceivedOutput { offset: *offset, output: output.clone(),
        outpoint: OutPoint::new(tx.compute_txid(), vout) });
}
``` [2](#0-1) 

This is the same bug class as the reference report: a value-accruing action (here, output discovery) is taken without accounting for pending state (the 100-block coinbase maturity), producing an entitlement (`ReceivedOutput`, explicitly documented at line 88 as "A spendable output") that is not actually exercisable. Once such a `ReceivedOutput` is stored, nothing downstream distinguishes it: `SignableTransaction::new` happily consumes it as an input (`inputs.iter().map(|input| TxIn { previous_output: input.outpoint, ... })`), and `TransactionSignMachine::sign` produces a valid-looking signed transaction that commits to it via `Prevouts::All` and `taproot_key_spend_signature_hash`. The transaction is then consensus-invalid (`bad-txns-premature-spend-of-coinbase`) and can never confirm.

### Impact Explanation
A miner (or anyone controlling a coinbase payout) can send a coinbase output paying to the wallet's scanned script (the external `Scalar::ZERO` script or any registered offset). The scanner reports it as a normal spendable `ReceivedOutput`. Any wallet flow that treats `scan_block` results as spendable inputs will build transactions that are permanently unbroadcastable until maturity, and in an automated signer loop this either stalls all spends built on that input set or crashes the publisher (`publish_completion` panics on RPC rejection). Impact: reported-received funds are not spendable, and transaction construction/signing is poisoned by an attacker-supplied input.

### Likelihood Explanation
Medium. Exploitation requires a miner to direct a coinbase payout to the target's scriptPubKey — cheap for any miner already producing blocks, and coinbase outputs are otherwise a normal way to receive funds. The only mitigation is a doc comment telling callers to skip `txdata[0]` themselves; the API itself returns the tainted output indistinguishably, so any integrator using the natural `scan_block` entry point is affected.

### Recommendation
In `Scanner::scan_block`, skip the coinbase transaction (`block.txdata[1 ..]`), or thread maturity metadata through `ReceivedOutput` so consumers can gate spendability. If coinbase scanning is retained, `ReceivedOutput` should expose whether the funding transaction is a coinbase and the block height at which it was found so `SignableTransaction::new` callers can filter immature inputs.

### Proof of Concept
```rust
// Conceptual PoC against networks/bitcoin/src/wallet/mod.rs
// A miner builds a block whose coinbase pays to the scanner's script:
let mut scanner = Scanner::new(group_key).unwrap();
let our_script = p2tr_script_buf(group_key).unwrap();

// coinbase tx paying `our_script`
let coinbase = Transaction {
    version: Version(2),
    lock_time: LockTime::ZERO,
    input: vec![TxIn {
        previous_output: OutPoint::null(), // coinbase marker
        script_sig: ScriptBuf::builder().push_slice([0x01]).into(),
        sequence: Sequence::MAX,
        witness: Witness::from_slice(&[vec![0xaa; 32]]),
    }],
    output: vec![TxOut { value: Amount::from_sat(25_0000_0000), script_pubkey: our_script }],
};

let block = Block { header: dummy_header, txdata: vec![coinbase] };

// The immature coinbase output is reported as a spendable ReceivedOutput
let outputs = scanner.scan_block(&block);
assert_eq!(outputs.len(), 1); // BUG: reported despite consensus-unspendable for 100 blocks

// Any downstream use builds an invalid transaction
let tx = SignableTransaction::new(outputs, &[(payment_script, DUST)], None, None, 1).unwrap();
// tx is signed successfully but rejected with bad-txns-premature-spend-of-coinbase
```
