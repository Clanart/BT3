### Title
Bandwidth purchase credit and gate-bypass trust an unauthenticated `PostRequest.from` field, allowing forged free bandwidth grants - (File: modules/pallets/bandwidth/src/lib.rs)

### Summary
The external report's core flaw is trusting a value the attacker controls (`KYCStatus` in the response) instead of a value verified server-side, letting an unapproved user unlock gated functionality. The local analog is `pallet_bandwidth::Pallet::is_purchase_message` and `IsmpModule::on_accept`, which authorize both "skip the paid bandwidth gate" and "credit a free bandwidth subscription" purely by comparing `request.from` to the registered `BandwidthManager` address for `request.source`, with no cryptographic binding proving the request actually originated from that manager contract's `purchase()` call.

### Finding Description
`is_purchase_message` treats a request as an authenticated purchase solely if `request.from == BandwidthManager::<T>::get(request.source)`: [1](#0-0) 

This same check gates the free bypass in the runtime router before `try_consume` is even called: [2](#0-1) 

And `on_accept` re-derives authorization identically, then blindly decodes the body and credits a subscription: [3](#0-2) 

Nothing in this on-chain check verifies that the on-chain `PurchaseMessage` body corresponds to an actual token payment collected by `BandwidthManager.sol` on the source chain — the trust boundary is entirely the equality `request.from == manager_address`. The `PostRequest.from` field is set by the source-chain dispatcher, and ISMP's dispatch model does not cryptographically bind `from` to `msg.sender` at the protocol layer beyond what the source-side dispatcher contract enforces; if any dispatch path on a registered EVM source chain (proxy, misconfigured contract, or a contract that can be pointed at with `from` overridden) allows a caller to set `from` to the `BandwidthManager` address without going through `purchase()`, the resulting `PostRequest` sails through `handlePostRequests`/`on_accept` on Hyperbridge exactly as if a legitimate purchase had occurred — crediting free bandwidth (`Self::push_subscription`) and permanently exempting that `(source, app)` pair from the paid gate for the life of the forged subscription. This is structurally identical to the KYC bug: a downstream consumer (`ProxyModule::on_accept`, `pallet_bandwidth::on_accept`) accepts a security-relevant flag (`is_purchase_message`) based on a field it does not independently re-verify against the economic event it's supposed to represent (actual token collection), the same way the frontend/KYC endpoints trusted a `KYCStatus` field instead of re-checking approval server-side.

### Impact Explanation
If `from` spoofing is achievable on any registered source chain (e.g., via a redeployed/compromised/misrouted contract at the same address slot, a chain reorg redeploying different bytecode to the manager's historical address, or any dispatch path that lets a caller set an arbitrary `from`), an attacker can mint unlimited free bandwidth subscriptions for arbitrary `(app_chain, app)` pairs and bypass metering entirely — directly undermining the "bridged assets/balances move exactly once and only to the rightful beneficiary" invariant, since bandwidth *is* the metered asset here and the manager's on-chain fee collection is completely decoupled from the credit granted on Hyperbridge.

### Likelihood Explanation
Exploitability depends entirely on whether an untrusted actor can produce a `PostRequest` with `from == BandwidthManager` address without going through the legitimate `purchase()` call — this requires either a bug/gap in the source-chain `IDispatcher`/`IHost` implementation that lets `from` diverge from `msg.sender`, or a chain-level condition (contract redeployment, `CREATE2` address collision, or a state machine ID reuse) that lets a malicious contract occupy the registered manager's address. I could not confirm from the indexed code whether the EVM `dispatch()` path strictly enforces `from == msg.sender`, since that constraint would live in `evm/src/core/DispatcherV2.sol`/`IDispatcher.sol` which was not fully retrieved in this session — this materially affects likelihood and should be verified directly.

### Recommendation
Do not rely solely on `request.from == manager_address` as the trust anchor for both gate bypass and credit issuance. Cross-check the purchase against a monotonic per-manager nonce or an explicit payment commitment emitted by `BandwidthManager.sol` (e.g., include and verify a fee-paid amount/hash in the `PurchaseMessage` body that pallet-bandwidth can validate against tier price × months), and confirm in the source-chain `IDispatcher` implementation that `PostRequest.from` cannot be set to any value other than `msg.sender` for permissionless dispatch paths.

### Proof of Concept
Conceptual (unverifiable without confirming the EVM dispatcher's `from`-binding guarantee):
1. Attacker identifies `BandwidthManager::<T>::get(source)` = `0xMANAGER` for some registered EVM source chain.
2. Attacker finds/creates a dispatch path on that source chain where a `PostRequest` can be submitted with `from = 0xMANAGER` without executing `BandwidthManager.purchase()` (e.g., a misconfigured proxy, un-enforced `from` field in a custom `IDispatcher` caller, or address reuse after redeployment).
3. Attacker crafts the `body` as a valid ABI-encoded `PurchaseMessage { app, tier: TierFour, months: 255, chain: <victim_app_chain> }`.
4. Relayer delivers this `PostRequest` to Hyperbridge; `ProxyModule::on_accept` calls `is_purchase_message` → `true` (matches `from`), skips the bandwidth gate entirely, then routes to `pallet_bandwidth::on_accept`, which credits a maximal free subscription: [4](#0-3) 
5. No token was ever collected by the real `BandwidthManager.sol` contract — the credited bandwidth is entirely fabricated, and any subsequent metered request from the attacker's `app` drains this forged allowance for free.

	impl<T: Config> IsmpModule for Pallet<T> {
		fn on_accept(&self, request: PostRequest) -> Result<Weight, anyhow::Error> {
			let manager = BandwidthManager::<T>::get(&request.source).ok_or_else(|| {
				anyhow::anyhow!(format!("no bandwidth manager registered for {:?}", request.source))
			})?;

			if request.from != manager.0.to_vec() {
				return Err(anyhow::anyhow!(format!(
					"purchase from unauthorised sender on {:?}: expected {:x?}, got {:x?}",
					request.source, manager.0, request.from
				)));
			}

			let msg = PurchaseMessage::try_from(request.body.as_slice())?;
			let tier = TierIndex::try_from(msg.tier)
				.map_err(|_| anyhow::anyhow!(format!("unknown tier discriminant {}", msg.tier)))?;
			let cfg = Tiers::<T>::get(tier)
				.ok_or_else(|| anyhow::anyhow!(format!("tier {:?} is not configured", tier)))?;

			let bytes = cfg.bytes.saturating_mul(msg.months as u128);
			let duration = cfg.duration_secs.saturating_mul(msg.months as u64);

			let key = AppKey::truncate_from(msg.app);
			let expires_at = Self::push_subscription(&msg.chain, &key, tier, bytes, duration);

			Self::deposit_event(Event::BandwidthCredited {
				app_chain: msg.chain,
				app: key,
				paid_from: request.source,
				tier,
				bytes,
				expires_at,
			});

			Ok(Weight::zero())
		}
