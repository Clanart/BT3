### Title
Unchecked short-calldata slicing in legacy precompile `RequiredGas`/`Prepare` causes a panic reachable from any EVM transaction - ([File: precompiles/common/legacy/v552/precompiles.go])

### Summary
The reported CVE-2019-10895 is a data-validation bug class: a parser (Wireshark's NetScaler reader) slices/derefs untrusted input without first validating its length, causing a crash. Sei-chain's legacy precompile helper package contains the same bug-class pattern: `RequiredGas` unconditionally slices the raw EVM calldata at a fixed offset before validating its length, and this helper is embedded by many precompile implementations that any EVM caller can invoke with attacker-controlled `input`.

### Finding Description
`Precompile.RequiredGas` in the legacy common-precompile package does: [1](#0-0) 

`argsBz := input[4:]` is executed with no prior check that `len(input) >= 4`. Contrast this with `ExtractMethodID`, used by `Prepare` in the same file, which does perform the length check before slicing: [2](#0-1) 

Because `RequiredGas` does not go through `ExtractMethodID`, any embedding precompile inherits an unguarded `input[4:]` slice. This same unguarded pattern is duplicated verbatim across many legacy precompile-version packages (`v555`, `v562`, `v575`, `v580`, `v600`, `v605`, `v606`, `v610`, `v614`, `v620`, `v630`, `v640`, `v65`, `v66`, `v67`) as well as the current `precompiles/common/precompiles.go`, and is embedded by concrete precompiles such as `addr`, `bank`, `oracle`, `wasmd`, `distribution`, `params`, `auth`, and `authz` across their respective legacy version directories.

`RequiredGas(input, isTransaction)` is the EVM's gas-estimation entry point for a precompiled contract call and is invoked with the raw calldata bytes supplied by the caller in the transaction (or `eth_call`/`eth_estimateGas` request) before any other validation such as `ExtractMethodID`'s length check runs. If a caller sends calldata shorter than 4 bytes (including empty calldata, `0x`) to one of these precompile addresses, `input[4:]` triggers a Go runtime "slice bounds out of range" panic.

### Impact Explanation
A panic raised inside `RequiredGas` during EVM execution, if not caught by a `recover()` at every point along the call path (block-processing goroutine, RPC `eth_call`/`eth_estimateGas` handler, or gas-estimation-only code paths), will crash the goroutine handling that request. Depending on whether recovery exists in the specific call path (block execution vs. RPC-only), this can manifest as: a crash of a public JSON-RPC node servicing `eth_call`/`eth_estimateGas` against a precompile address with short calldata, or — if the same unguarded call is reached during block/tx processing without a `recover()` — a validator halt. This matches the accepted impact categories (crash of default-configuration RPC nodes; validator halt).

### Likelihood Explanation
The trigger requires only sending a normal EVM transaction or RPC call (`eth_call`/`eth_estimateGas`) with `to` set to one of the affected precompile addresses and `data` shorter than 4 bytes — no privileged access, special contract state, or unusual gas/config settings are needed. This is trivially reachable by any unprivileged EVM transaction sender or public-RPC client.

### Recommendation
Add a length check (`len(input) < 4`) at the top of every legacy `RequiredGas` implementation (and the current `precompiles/common/precompiles.go` variant) before slicing `input[4:]`, mirroring the existing `ExtractMethodID` guard, and return a deterministic gas value/error instead of panicking. Alternatively, route `RequiredGas` through `ExtractMethodID` so the validation is centralized and cannot be bypassed by any embedding precompile.

### Proof of Concept
1. Deploy/target any precompile address whose Go type embeds `v552.Precompile` (or the equivalent from `v555`–`v67`, or `precompiles/common/precompiles.go`), e.g. the `addr`, `bank`, `oracle`, or `wasmd` precompile.
2. Submit an EVM transaction (or `eth_estimateGas`/`eth_call`) with `to` = that precompile address and `data` = `0x` (empty) or any payload of length < 4.
3. The EVM engine calls `RequiredGas(input, isTransaction)` on the precompile before dispatching to `Run`; `input[4:]` panics with "slice bounds out of range [4:0]" (or similar), crashing the handling goroutine/node unless recovered elsewhere in the stack. [1](#0-0) [2](#0-1)

func (p Precompile) RequiredGas(input []byte, isTransaction bool) uint64 {
	argsBz := input[4:] // first four bytes are method ID

	if isTransaction {
		return storetypes.KVGasConfig().WriteCostFlat + (storetypes.KVGasConfig().WriteCostPerByte * uint64(len(argsBz)))
	}

	return storetypes.KVGasConfig().ReadCostFlat + (storetypes.KVGasConfig().ReadCostPerByte * uint64(len(argsBz)))
}
