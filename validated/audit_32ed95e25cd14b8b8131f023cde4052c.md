## Finding

### Title
Payout OP_RETURN operator attribution is unsigned, letting anyone rebroadcast a competing payout tx to steal or void operator reimbursement credit - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary
`create_payout_txhandler` builds the operator's peg-out ("payout") transaction with the user's withdrawal input signed under `SIGHASH_SINGLE | SIGHASH_ANYONECANPAY`, which only commits to input 0 and the output at the *same index* (output 0, the user's payout). The anchor output (index 1) and, critically, the `OP_RETURN` output (index 2) carrying the operator's x-only pubkey used later to attribute reimbursement credit are **not covered by the signature at all**. Because the signature and the (public, Citrea-committed) input outpoint are the only things needed to construct a valid alternative transaction, anyone who observes the pending payout transaction (e.g., in the Bitcoin mempool before confirmation) can build and broadcast their own competing transaction that reuses the same signed input+output, funds it with their own capital, and substitutes an arbitrary `OP_RETURN` value.

### Finding Description
`create_payout_txhandler` [1](#0-0)  constructs the payout transaction with:
1. input 0: the user's withdrawal UTXO (committed on Citrea, signature given to operators off-chain),
2. output 0: the user's payout,
3. output 1: CPFP anchor,
4. output 2: `OP_RETURN` containing `operator_xonly_pk` (op_return_txout embeds the *broadcasting* operator's key, not anything chosen/verified by the user).

The user's signature type is strictly enforced to be `SinglePlusAnyoneCanPay` [2](#0-1) , and `calculate_pubkey_spend_sighash`/`calculate_script_spend_sighash` implement standard BIP-341 semantics where `SINGLE` only commits the output at the signed input's index, and `ANYONECANPAY` lets any additional inputs be attached without invalidating the signature [3](#0-2) . This means output 1 (anchor) and output 2 (`OP_RETURN`, the operator attribution) are entirely unconstrained by the user's signature.

`Operator::withdraw` builds this tx from the caller-supplied `in_signature`/`in_outpoint`, verifies only the input-0 signature, funds it via RBF, signs, and broadcasts it — with no check that a competing spend of the same input isn't already in-flight [4](#0-3) .

Downstream, reimbursement attribution depends entirely on this unsigned `OP_RETURN`: `update_finalized_payouts` parses the confirmed payout tx's `OP_RETURN` to derive `operator_xonly_pk` and persists it as `payout_payer_operator_xonly_pk` [5](#0-4) , `get_first_unhandled_payout_by_operator_xonly_pk` looks up unhandled payouts strictly by that stored key [6](#0-5) , and `is_kickoff_malicious` requires the kickoff's operator key to match this stored attribution or treats the kickoff as malicious [7](#0-6) .

**Binding broken:** `payout_payer_operator_xonly_pk (credited operator) == actual funder of the payout's added inputs (party that paid)`. Since the `OP_RETURN` is unsigned, an unprivileged party who sees the pending transaction (mempool-visible before confirmation) can rebroadcast a rival transaction reusing the same signed input/output-0 pair, funding it themselves, while writing any `OP_RETURN` value they like (their own key, a different real operator's key, or an invalid one).

### Impact Explanation
- If the attacker inserts a legitimate but different operator's key, that operator is later credited/reimbursed for a payout it never actually funded (Critical: "an operator reimbursed for a payout it never funded").
- If the attacker inserts no valid operator key (or their own unregistered key), the honest operator who actually intended to front the withdrawal is permanently unable to claim reimbursement for it, since `is_kickoff_malicious` will reject any real operator's later kickoff against this withdrawal, and `get_first_unhandled_payout_by_operator_xonly_pk` will never surface it for the correct operator (Critical: "an honest operator permanently unable to be reimbursed").
- Either way, the on-chain attribution binding used throughout the reimbursement machinery is broken by a party who never needed any bridge-privileged role.

### Likelihood Explanation
Any operator's `withdraw()` broadcast necessarily reveals the signed input and `SinglePlusAnyoneCanPay` signature on the public Bitcoin P2P network before confirmation. No verifier/operator/aggregator role, key compromise, or majority hashrate is required to observe this and race a replacement transaction with different added inputs and a different `OP_RETURN`; only ordinary mempool visibility and enough capital to fund output 0 are needed. Success only requires the attacker's transaction to be the one that gets mined first (fee-bump/first-seen race), a realistic bar given widespread full-RBF mempool policies.

### Recommendation
Bind the `OP_RETURN` (and ideally the anchor output) to the signature that authorizes spending the withdrawal input — e.g., require `SIGHASH_ALL` (or otherwise commit to all outputs) for the user-provided withdrawal signature, or have the user themselves sign/commit to the intended operator's x-only pubkey as part of the withdrawal request so it can be checked deterministically rather than trusted from an unauthenticated output in the broadcast transaction.

### Proof of Concept
1. Operator A calls `withdraw()`, producing a payout tx: input = withdrawal UTXO (user-signed, `SinglePlusAnyoneCanPay`), output0 = user payout, output1 = anchor, output2 = `OP_RETURN(A_xonly_pk)`; funds it via `fund_raw_transaction`/`sign_raw_transaction_with_wallet`, and broadcasts (`core/src/operator.rs:620-691`).
2. Attacker (no bridge role) observes this unconfirmed tx in the mempool, extracts `(in_outpoint, in_signature)` — both remain valid for any output-1+ configuration since `SinglePlusAnyoneCanPay` only binds input0/output0.
3. Attacker crafts a new transaction with the same input0/output0, their own funding inputs (`ANYONECANPAY` permits arbitrary extra inputs), and `OP_RETURN(operator_B_xonly_pk)` or garbage bytes, then broadcasts it with a higher fee.
4. If the attacker's transaction confirms first, `update_finalized_payouts` records `payout_payer_operator_xonly_pk = B` (or `None`) instead of `A` (`core/src/verifier.rs:2312-2350`), permanently misattributing/erasing reimbursement rights for the withdrawal that Operator A actually intended to front.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }
