### Title
Attacker can self-sandwich the internal `busd→mgp` swap in `_bullMGP` to mint an inflated `vlMGP` lock via slippage manipulation - ([File: wombat/ArbWomUp2.sol])

### Summary
`incentiveDeposit(_amount, _minMGPRec, true)` lets the caller pass an arbitrary `_minMGPRec` and then internally calls `_bullMGP`, which swaps the user's fixed `busdReward` for `mgp` on `ROUTER.swapExactTokensForTokens` using the *live spot price* of the `busd/mgp` pool, with no TWAP/oracle check. Because the swap output `amounts[1]` directly and linearly determines `mgpAmountToLcok = amounts[1] * (DENOMINATOR + bullBonusRatio) / DENOMINATOR` that gets locked into `vlMGP` for the caller, an attacker can atomically depress the pool price immediately before the call and restore it immediately after, within a single transaction, to inflate the amount of MGP that gets locked to their benefit.

### Finding Description
`incentiveDeposit` is externally callable by any unprivileged holder of WOM: [1](#0-0) . When `_bullMode == true`, it forwards the user's already-fixed `rewardToSend` (`busdReward`, determined only by their WOM-deposit tier, not by anything price-related) to `_bullMGP`: [2](#0-1) 

The swap uses `ROUTER.swapExactTokensForTokens(_busdAmount, _minRec, path, address(this), block.timestamp)`, i.e. the raw spot price of the `busd/mgp` AMM pool at execution time, with `_minRec` fully controlled by the caller (`_minMGPRec` from `incentiveDeposit`). There is no TWAP, no oracle sanity check, and no cap comparing `amounts[1]` to a fair-value reference price.

Because `mgpAmountToLcok` is a linear function of `amounts[1]`, and `amounts[1]` is directly manipulable by anyone who can move the same pool's reserves before the call, an attacker can:
1. Push the `busd/mgp` pool price down (sell `mgp` into the pool, or otherwise skew reserves) with a preceding swap in the same transaction — funded by their own capital or a flash loan.
2. Call `incentiveDeposit(_amount, lowMinRec, true)` with `_minMGPRec` set low enough to tolerate the price the attacker themselves created, so the internal swap does not revert.
3. Because the pool is temporarily depressed, the internal `busd→mgp` swap in `_bullMGP` returns an inflated `amounts[1]`, which is further multiplied by `(DENOMINATOR + bullBonusRatio)/DENOMINATOR` and locked via `vlMGP.lockFor` — note this requires `ArbWomUp2` to hold/approve MGP beyond what it just received from the swap (the bonus portion), meaning the excess minted lock is funded from the contract's pre-funded MGP reserve, not created out of thin air.
4. Reverse the initial swap to restore the pool price and realize/limit their manipulation cost (or repay the flash loan).

`nonReentrant` only blocks reentrant calls back into `incentiveDeposit` itself; it does not prevent the attacker from performing ordinary sequential swap calls on `ROUTER` before and after `incentiveDeposit` within the same transaction. `whenNotPaused` and the `_checkAmount` modifier do not address price-manipulation. There is no slippage floor enforced by the protocol (it is caller-supplied), and no check that the swap price is within a reasonable band of a trusted reference.

### Impact Explanation
This is theft of unclaimed yield: the attacker receives a `vlMGP` lock (`mgpAmountToLcok`) larger than the fair-value MGP entitlement their `busdReward` should produce, at the expense of the protocol's `mgp` reserve held in `ArbWomUp2` (used to cover `bullBonusRatio` on top of swap output) and/or the `busd/mgp` pool's liquidity providers. This matches Immunefi's "theft of unclaimed yield" / "protocol insolvency (partial)" impact class, since the locked-MGP bonus mechanism is designed around a fair swap price, not an attacker-controlled one.

### Likelihood Explanation
Feasible for any unprivileged actor with capital to move the `busd/mgp` pool (or via flash loan, effectively zero net capital), as long as:
- The pool has thin-enough liquidity that a single-transaction price swing is affordable relative to `bullBonusRatio` and the size of `busdReward`.
- The attacker holds/borrows enough WOM to trigger a non-trivial `busdReward` (or repeats the attack across multiple small deposits/tiers).

This is fully repeatable per transaction and requires no privileged role, matching the "unprivileged attacker, flash-loanable" precondition in the prompt.

### Recommendation
- Do not size `mgpAmountToLcok`/reward eligibility off a same-block spot AMM swap the attacker controls the slippage for. Use a TWAP/oracle-derived reference price to sanity-bound `amounts[1]`, or enforce a protocol-owned minimum-output check (not caller-supplied `_minMGPRec`) tightly bounded to a trusted price feed.
- Alternatively, decouple the `bullBonusRatio` bonus from the manipulable swap output — e.g., compute `mgpAmountToLcok` from `busdReward` divided by an oracle/TWAP price rather than multiplying the router's realized `amounts[1]`.
- Consider capping per-transaction price impact allowed for this internal swap (e.g., checking pool reserves before/after against expected bounds).

### Proof of Concept
Foundry fork test against BSC (or wherever `ArbWomUp2` is deployed) mainnet state:
1. Fork at a block where `ArbWomUp2` is configured (`busd`, `mgp`, `vlMGP`, `bullBonusRatio`, `ROUTER` set) and holds sufficient `busd`/`mgp` reserves.
2. Baseline: call `incentiveDeposit(amount, fairMinRec, true)` directly (no manipulation) from a fresh test address with sufficient WOM deposited to have a non-zero `busdReward`; record `mgpAmountToLcok` from the `VLMGPRewarded` event as `baselineLock`.
3. Reset fork state. Deploy an attacker contract that, in a single transaction:
   a. Flash-borrows `busd` (or uses `mgp` it already holds) and swaps on `ROUTER` to depress the `mgp` price in the `busd/mgp` pool.
   b. Calls `incentiveDeposit(amount, lowMinRec, true)` with the same `amount` as baseline and an artificially low `_minMGPRec`.
   c. Immediately reverses the swap to restore the pool price and repay the flash loan.
4. Assert: `mgpAmountToLcok` emitted in step (3b) > `baselineLock`, and that the attacker's net cost (fees + slippage + flash loan fee) is less than the value of the extra locked MGP obtained — demonstrating a profitable, protocol-funded exploit of the reward formula.

    function incentiveDeposit(
        uint256 _amount, uint256 _minMGPRec, bool _bullMode
    ) external _checkAmount(_amount) whenNotPaused nonReentrant {
        if (_amount == 0) return;

        uint256 rewardToSend = this.getRewardAmount(_amount, msg.sender);
        _deposit(_amount);
        claimedReward[msg.sender] += rewardToSend;
        
        if (_bullMode) {
            _bullMGP(rewardToSend, _minMGPRec, msg.sender);
        } else {
            IERC20(busd).transfer(msg.sender, rewardToSend);
            emit BUSDRewarded(msg.sender, rewardToSend);
        }
    }

    function _bullMGP(uint256 _busdAmount, uint256 _minRec, address _account) internal {
        IERC20(busd).safeApprove(address(ROUTER), _busdAmount);
        
        address[] memory path = new address[](2);
        path[0] = busd;
        path[1] = mgp;
        uint256[] memory amounts = ROUTER.swapExactTokensForTokens(
            _busdAmount,
            _minRec,
            path,
            address(this),
            block.timestamp
        );

        uint256 mgpAmountToLcok = amounts[1] * (DENOMINATOR + bullBonusRatio) / DENOMINATOR; // get bull mode bonus
        IERC20(mgp).approve(address(vlMGP), mgpAmountToLcok);
        vlMGP.lockFor(mgpAmountToLcok, _account);

        emit VLMGPRewarded(_account, _busdAmount, mgpAmountToLcok);
    }
