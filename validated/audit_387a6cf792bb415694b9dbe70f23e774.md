### Title
Authentication bypass via pre-populated `Derived` field lets an attacker submit an EVM transaction as any address without a valid signature - (File: x/evm/ante/preprocess.go)

### Summary
`MsgEVMTransaction` carries an optional `Derived` field (`SenderEVMAddr`, `SenderSeiAddr`, `PubKey`) that is normally computed by the ante pipeline from a cryptographic ECDSA signature check over the raw Ethereum transaction. However, if a submitted transaction already has `Derived` populated with a non-nil `PubKey`, the preprocessing logic treats the message as "already preprocessed" and skips the actual signature recovery/verification entirely, trusting the attacker-supplied sender identity.

### Finding Description
`PreprocessUnpacked` short-circuits real signature verification whenever `Derived` is already set with a non-nil `PubKey`: [1](#0-0) 

The only gate that exists is `MsgEVMTransaction.ValidateBasic()`, which rejects the message only when `Derived != nil && Derived.PubKey == nil` — it never checks that `PubKey`/`SenderEVMAddr`/`SenderSeiAddr` actually correspond to a valid signature over the embedded Ethereum tx data: [2](#0-1) 

`EVMNoCosmosFieldsDecorator`/`ValidateNoCosmosTxFields`, which runs before `EVMPreprocessDecorator` in the ante chain, only checks Cosmos wrapper fields (memo, timeout height, extension options, signer infos, fee, signatures) and never touches or clears `msg.Derived`: [3](#0-2) 

`EVMPreprocessDecorator.AnteHandle` then blindly consumes `msg.Derived.SenderSeiAddr` / `SenderEVMAddr` as the transaction's authenticated identity, and if that Sei address is already associated (the common case for any active account), it takes the no-op branch and proceeds to `next(...)`, i.e. it fully accepts the tx as sent by that account: [4](#0-3) 

Crucially, the subsequent decorator that is supposed to be the signature check, `EVMSigVerifyDecorator`, never re-verifies any cryptographic signature at all — it only reads `Derived.SenderEVMAddr` (already attacker-controlled) and checks the nonce: [5](#0-4) 

The same bypass pattern exists on the DeliverTx and legacy-ABCI CheckTx code paths, which likewise trust a pre-set `Derived` field instead of recomputing it from the actual signature: [6](#0-5) [7](#0-6) 

`Derived` is a genuine protobuf field (wire tag 2) on `MsgEVMTransaction`: [8](#0-7) 

No code path was found in the ante pipeline that strips or resets `msg.Derived` before `EVMPreprocessDecorator` runs on an externally submitted transaction, so a client that crafts a raw tx with `Derived` already populated can skip `CheckAndDecodeSignature` (the function that actually recovers the sender address from `V, R, S` and the tx hash) entirely: [9](#0-8) 

This is directly analogous to CVE-2016-0733: Apache Ranger's Admin UI accepted an authentication request that omitted the password and trusted the claimed username without validating the credential. Here, the ante pipeline accepts a transaction whose "credential" (the ECDSA signature proving control of the sender's key) is replaced by an attacker-supplied `Derived` struct claiming a victim's address, and trusts that claim without ever validating it against the actual signature bytes in the transaction.

### Impact Explanation
If reachable from an unprivileged client (i.e., `Derived` round-trips through the public tx-submission/CheckTx decoding path unmodified), this allows an attacker to submit an EVM transaction that the chain will execute as if signed by any already-associated victim Sei/EVM address, without possessing that address's private key. Because `EVMSigVerifyDecorator` performs no cryptographic check and only validates nonce, and downstream execution uses `Derived.SenderEVMAddr`/`SenderSeiAddr` as the authoritative sender, this could let an attacker drain funds, transfer tokens, or otherwise act as the victim — a critical unauthorized-transfer / fund-loss vulnerability.

### Likelihood Explanation
The likelihood assessment is bounded by uncertainty I could not fully resolve in this session: I was unable to locate and inspect the generated `Unmarshal` method for `MsgEVMTransaction` to conclusively confirm that the `derived` wire field (tag 2) is preserved end-to-end from a raw `broadcast_tx`/CheckTx submission through to the point `EVMPreprocessDecorator` reads it, as opposed to being reconstructed/overwritten server-side before ante processing on every external entry point. The struct tag on the generated type indicates it is a normal proto3 field that would decode from arbitrary wire bytes, and no stripping logic was found in the ante chain, but full confirmation would require tracing the exact tx-decoding entry points (gRPC broadcast, CheckTx, mempool) end to end.

### Recommendation
Never trust a pre-populated `Derived` field from an externally-submitted transaction. Either (a) always recompute `Derived` from `CheckAndDecodeSignature` internally and reject/strip any inbound `Derived` value at decode time before it reaches the ante handlers, or (b) if `Derived` must be trusted as a precomputed-signature optimization, cryptographically bind it to the transaction (e.g., verify that the derived `PubKey` actually produced the `V,R,S` in the tx data) rather than accepting it as opaque, unverified input.

### Proof of Concept
1. Construct an `ethtx.TxData` (e.g., a `LegacyTx`) with arbitrary/garbage `V, R, S` values (no real signature by the victim).
2. Wrap it in a `MsgEVMTransaction` and manually set `Derived = &derived.Derived{SenderEVMAddr: <victim EVM addr>, SenderSeiAddr: <victim Sei addr>, PubKey: <any non-nil pubkey bytes>, Version: derived.Cancun, IsAssociate: false}`.
3. Submit this as a raw Cosmos tx (single `MsgEVMTransaction`, no Cosmos auth fields, matching `ValidateNoCosmosTxFields`).
4. `MsgEVMTransaction.ValidateBasic()` passes because `Derived.PubKey != nil`.
5. `EVMPreprocessDecorator.AnteHandle` → `Preprocess`/`PreprocessUnpacked` sees `Derived != nil && Derived.PubKey != nil` and returns immediately without calling `CheckAndDecodeSignature`, i.e., without ever validating `V, R, S` against the victim's actual key.
6. `EVMSigVerifyDecorator` only checks the nonce against `Derived.SenderEVMAddr` (the attacker-claimed victim address) — no signature check occurs.
7. If the victim's Sei address is already associated on-chain (the common case), the transaction proceeds through the ante pipeline and is executed as originating from the victim, without the attacker ever presenting a valid signature from the victim's key. [1](#0-0) [5](#0-4)

func (p *EVMPreprocessDecorator) AnteHandle(ctx sdk.Context, tx sdk.Tx, simulate bool, next sdk.AnteHandler) (sdk.Context, error) {
	msg := evmtypes.MustGetEVMTransactionMessage(tx)
	if err := Preprocess(ctx, msg, p.evmKeeper.ChainID(ctx), p.evmKeeper.EthBlockTestConfig.Enabled); err != nil {
		return ctx, err
	}

	// use infinite gas meter for EVM transaction because EVM handles gas checking from within
	ctx = ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx))

	derived := msg.Derived
	seiAddr := derived.SenderSeiAddr
	evmAddr := derived.SenderEVMAddr
	ctx.EventManager().EmitEvent(sdk.NewEvent(evmtypes.EventTypeSigner,
		sdk.NewAttribute(evmtypes.AttributeKeyEvmAddress, evmAddr.Hex()),
		sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, seiAddr.String())))
	pubkey := derived.PubKey
	isAssociateTx := derived.IsAssociate
	associateHelper := helpers.NewAssociationHelper(p.evmKeeper, p.evmKeeper.BankKeeper(), p.accountKeeper)
	_, isAssociated := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if isAssociateTx && isAssociated {
		return ctx, sdkerrors.Wrap(sdkerrors.ErrInvalidRequest, "account already has association set")
	} else if isAssociateTx {
		// check if the account has enough balance (without charging)
		if !p.IsAccountBalancePositive(ctx, seiAddr, evmAddr) {
			assocErr := evmtypes.NewAssociationMissingErr(seiAddr.String())
			evmAnteMetrics.associationError.Add(ctx.Context(), 1, otelmetric.WithAttributes(attribute.String("scenario", "associate_tx_insufficient_funds"), attribute.String("type", assocErr.AddressType())))
			return ctx, sdkerrors.Wrap(sdkerrors.ErrInsufficientFunds, "account needs to have at least 1 wei to force association")
		}
		if err := associateHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false); err != nil {
			return ctx, err
		}

		return ctx.WithPriority(antedecorators.EVMAssociatePriority), nil // short-circuit without calling next
	} else if isAssociated {
		// noop; for readability
	} else {
		// not associatedTx and not already associated
		if err := associateHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false); err != nil {
			return ctx, err
		}
		if p.evmKeeper.EthReplayConfig.Enabled {
			p.evmKeeper.PrepareReplayedAddr(ctx, evmAddr)
		}
	}

// ValidateNoCosmosTxFields rejects Cosmos wrapper fields that EVM txs must not use.
func ValidateNoCosmosTxFields(tx sdk.Tx) error {
	if txProto, ok := tx.(protoTxProvider); ok {
		pt := txProto.GetProtoTx()
		if pt != nil {
			if pt.Body != nil {
				if pt.Body.Memo != "" {
					return sdkerrors.Wrap(sdkerrors.ErrInvalidRequest, "memo must be empty for EVM txs")
				}
				if pt.Body.TimeoutHeight != 0 {
					return sdkerrors.Wrap(sdkerrors.ErrInvalidRequest, "timeout_height must be zero for EVM txs")
				}
				if len(pt.Body.ExtensionOptions) > 0 || len(pt.Body.NonCriticalExtensionOptions) > 0 {
					return sdkerrors.Wrap(sdkerrors.ErrInvalidRequest, "extension options must be empty for EVM txs")
				}
			}
			if pt.AuthInfo != nil {
				if len(pt.AuthInfo.SignerInfos) > 0 {
					return sdkerrors.Wrap(sdkerrors.ErrInvalidRequest, "signer_infos must be empty for EVM txs")
				}
				if pt.AuthInfo.Fee != nil {
					if len(pt.AuthInfo.Fee.Amount) > 0 {
						return sdkerrors.Wrap(sdkerrors.ErrInvalidRequest, "fee amount must be empty for EVM txs")
					}
					if pt.AuthInfo.Fee.Payer != "" || pt.AuthInfo.Fee.Granter != "" {
						return sdkerrors.Wrap(sdkerrors.ErrInvalidRequest, "fee payer and granter must be empty for EVM txs")
					}
				}
			}
			if len(pt.Signatures) > 0 {
				return sdkerrors.Wrap(sdkerrors.ErrInvalidRequest, "signatures must be empty for EVM txs")
			}
		}
		return nil

func CheckAndDecodeSignature(ctx sdk.Context, txData ethtx.TxData, chainID *big.Int, isBlockTest bool) (common.Address, sdk.AccAddress, cryptotypes.PubKey, derived.SignerVersion, error) {
	ethTx := ethtypes.NewTx(txData.AsEthereumData())
	if ethTx.Type() != ethtypes.LegacyTxType {
		chainID = ethTx.ChainId()
	}
	chainCfg := evmtypes.DefaultChainConfig()
	ethCfg := chainCfg.EthereumConfig(chainID)
	version := evmante.GetVersion(ctx, ethCfg)
	signer := evmante.SignerMap[version](chainID)
	if !evmante.IsTxTypeAllowed(version, ethTx.Type()) {
		return common.Address{}, sdk.AccAddress{}, nil, 0, ethtypes.ErrInvalidChainId
	}

	var txHash common.Hash
	V, R, S := ethTx.RawSignatureValues()
	if ethTx.Protected() {
		V = helpers.AdjustV(V, ethTx.Type(), ethCfg.ChainID)
		txHash = signer.Hash(ethTx)
	} else {
		if isBlockTest {
			// need to allow unprotected legacy txs in blocktest
			// to not lose coverage for other parts of the code
			txHash = ethtypes.FrontierSigner{}.Hash(ethTx)
		} else {
			return common.Address{}, sdk.AccAddress{}, nil, 0, errors.New("unsupported tx type: unsafe legacy tx")
		}
	}
	evmAddr, seiAddr, seiPubkey, err := helpers.GetAddresses(V, R, S, txHash)
	if err != nil {
		return common.Address{}, sdk.AccAddress{}, nil, 0, sdkerrors.ErrInvalidChainID
	}
	return evmAddr, seiAddr, seiPubkey, version, nil
}
