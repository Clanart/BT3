### Title
`Scanner::scan_transaction` / `SignableTransaction::new` accept outputs of any value with no profitability check — an attacker can flood the multisig with sub-cost inputs that are credited as received yet cost more to spend than they are worth - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The Serai Bitcoin wallet scans for *any* output paying to a registered script and `SignableTransaction::new` treats every scanned output's full value as usable input value, checking only that `input_sat >= payment_sat + needed_fee` (where `needed_fee` covers the outputs' weight only). There is no check that an input's value exceeds the marginal fee cost of spending it, and `Scanner::scan_transaction` accepts even outputs below Bitcoin's dust/relay minimum. This is the same bug class as the OpenQ report: a "deposit" is validated/recorded without checking the value actually usable (analogous to checking `_volume` while the real value is `msg.value == 0`), letting an unprivileged party create many zero/net-negative-value entries that get counted as received funds and must later be iterated/spent.

### Finding Description
`Scanner::scan_transaction` pushes a `ReceivedOutput` for every `TxOut` whose `script_pubkey` matches a registered script, with no check on `output.value`: [1](#0-0) 

The only minimum-value constant defined in the wallet is `DUST = 546` (the bare relay minimum), and it is applied only to *payments*, never to inputs: [2](#0-1) [3](#0-2) 

In `SignableTransaction::new`, `input_sat` sums the full value of every input and `payment_sat`/`needed_fee` are computed for the outputs, but no input is ever rejected for being unprofitable: [4](#0-3) [5](#0-4) 

Each input adds ~230 weight units (~58 vbytes) of witness+input data per `calculate_weight_vbytes`, so at even modest fee rates an input worth less than a few hundred-to-thousand sats is net-negative. The codebase's own `Network::DUST` contract acknowledges this: "For any received output, there's the cost to spend the output. This value MUST exceed the cost to spend said output" (`processor/src/networks/mod.rs`) — but that filter lives in the processor (`processor/src/multisigs/scanner.rs:564`) and nothing in `networks/bitcoin/src/wallet` enforces it. The `ReceivedOutput`s returned by `scan_transaction`/`scan_block` carry no indication of spendability, so any consumer using the wallet crate directly will treat dust outputs as fully spendable balance.

An unprivileged attacker can send thousands of transactions paying 546-sat (or sub-`DUST`-margin) outputs to the public Serai multisig key or to a registered offset script (`register_offset` scripts are just tweaked versions of the public key and are derivable/identifiable on-chain). Every such output is returned by `scan_block` as a "received" balance. When `SignableTransaction::new` later consolidates or spends, these inputs inflate `input_sat` on paper while their spend cost exceeds their value — the analog of zero-`msg.value` deposits inflating `deposits[]`. If change + fee consume the apparent balance, `checked_sub` at line 228 silently drops the change output, and the entire remainder (including what callers believed was residual value) is burned as the fee, since `fee()` computes `sum(inputs) - sum(outputs)`: [6](#0-5) [7](#0-6) 

### Impact Explanation
An attacker can force the multisig wallet to report funds as received that are not economically spendable (each input's marginal spend cost exceeds its value). Signing a transaction over these inputs wastes real funds: fees equal to `sum(inputs) - sum(outputs)` are paid for inputs contributing net-negative value, and when the change branch is skipped due to `checked_sub`/`DUST`, the full leftover is burned as fee. Repeated dust deposits also grow the input set until `MAX_STANDARD_TX_WEIGHT` is hit, producing `TooLargeTransaction` and preventing legitimate payments from being constructed — the same "list grows until the function that must iterate it fails" DoS shape as the OpenQ finding, reachable purely by sending ordinary Bitcoin transactions to a public address.

### Likelihood Explanation
The multisig's P2TR script is public on-chain; anyone can send dust outputs to it at a cost of ~546 sat per output plus their own fee. No Serai-side cooperation, validator misbehavior, or leaked key is needed. Every such output is unconditionally emitted by `scan_transaction`/`scan_block` (both exported APIs of the wallet crate) and unconditionally summed into `input_sat` by `SignableTransaction::new`.

### Recommendation
Enforce the "received value MUST exceed its spend cost" invariant inside the wallet crate itself: either have `Scanner::scan_transaction`/`scan_block` drop outputs whose value is below a profitability bound derived from the input's marginal weight (~230 wu) and the current fee rate, or have `SignableTransaction::new` filter inputs whose value is below `fee_per_vbyte * marginal_input_vbytes` (or at minimum below `DUST`). Additionally, when the change branch fails `checked_sub`, error rather than silently dropping the change and burning the remainder as fee, or assert `self.fee()` stays within a bounded multiple of `needed_fee`.

let payments = vec![(dest_script, 1000)];
let tx = SignableTransaction::new(inputs.clone(), &payments, None, None, FEE);
// input_sat counts every dust output at full face value; needed_fee is computed
// only from outputs' weight. Each input adds ~230 wu ≈ 58 vb of cost.
// At FEE = 10 sat/vb each 546-sat input costs ~580 sat to spend => net-negative,
// yet it is included and counted. With enough dust inputs the tx hits
// MAX_STANDARD_TX_WEIGHT -> TooLargeTransaction, DoS-ing payment construction,
// or the change-drop branch burns sum(inputs) - sum(payments) entirely as fee.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
