### Title
PlotNFT melt permanently strands unclaimed pool rewards sent to its p2-singleton address - ([File: chia/pools/plotnft_drivers.py])

### Summary
`PlotNFT.melt()` allows the owner to permanently terminate (melt) their self-custody Plot NFT singleton at any time, but nothing checks whether pool rewards have already been paid to that launcher's `RewardPuzzle` (p2-singleton) address and not yet claimed. After the melt, the singleton no longer exists, so those reward coins can never be authorized for spend, permanently locking the funds — analogous to the reported "owner can't claim prize because the claiming mechanism depends on ownership of an object the user can unilaterally destroy" bug class.

### Finding Description
Claiming a farmed pool reward requires the live PlotNFT singleton to send an authorizing on-chain `SEND_MESSAGE` to the `RewardPuzzle` coin. This is implemented via `PlotNFT.claim_pool_rewards()`, which curries a `SendMessage` condition into the singleton's inner solution: [1](#0-0) 

The reward coin's own puzzle is a `SingletonMember` (`RewardPuzzle.singleton_member`), which can only be spent by verifying a message that was sent by the currently-live singleton coin identified by `singleton_id` (the launcher id): [2](#0-1) 

`RewardPuzzle`/`PoolReward` bind the reward coin's spend authority to this same `SingletonMember`: [3](#0-2) 

`PlotNFT.melt()` lets the owner destroy the singleton (a `CREATE_COIN` with the melt sentinel amount `-113`) whenever the plot NFT is in self-custody — exactly the state in which pool rewards are claimable — and it only blocks melting while actively pooling. It performs no check for outstanding/unclaimed reward coins at the corresponding `RewardPuzzle` puzzle hash: [4](#0-3) 

Once the melt spend confirms, the singleton coin is gone; there is no longer any live coin that can produce the required `SEND_MESSAGE` with `sender=puzzle_hash_committed=<singleton full puzzle hash>` to authorize spending the pre-existing `RewardPuzzle` coin. Any reward that was farmed to that p2-singleton address but not yet swept via `claim_pool_rewards()`/`claim_rewards()` before the melt becomes permanently unspendable.

### Impact Explanation
This is a direct, irrecoverable loss-of-funds bug: XCH that was legitimately farmed and paid to the user's own p2-singleton reward address becomes permanently stuck once the user melts their Plot NFT, with no code path (including try/catch or alternate spend path) to recover it. Unlike the LooksRare report, which is bounded to the value of a specific prize, here the amount at risk is farming rewards, potentially recurring and compounding for any user who melts while rewards are pending.

### Likelihood Explanation
Reachable purely through normal, unprivileged wallet actions available to any Plot NFT owner: farm/receive a pool reward, then call `melt_plotnft` (exposed via `PlotNFT2Wallet.melt_plotnft` / RPC `plotnft_melt` / CLI `chia plotnft melt`) before calling `claim_rewards`. No adversarial party or special privilege is required — this can happen accidentally as an ordering mistake by any self-custody farmer: [5](#0-4) [6](#0-5) 

### Recommendation
Before allowing `melt_plotnft`/`PlotNFT.melt()` to proceed, check `plotnft2_store.get_pool_rewards()` (or the on-chain unspent coin records at `p2_singleton_puzzle_hash`) for any unclaimed reward coins tied to the launcher id, and either refuse to melt until they are claimed or automatically batch a `claim_rewards` spend ahead of the melt spend in the same transaction. Add a wallet-level warning/hard-stop analogous to the existing `"Cannot melt a pooling PlotNFT"` guard in [7](#0-6) .

### Proof of Concept
1. Create a self-custody Plot NFT (`desired_state="self_custody"`), as in `test_plotnft_self_custody_claim` [8](#0-7) .
2. Farm a pool reward to its `RewardPuzzle` address via `mint_reward()` [9](#0-8) , but do not call `claim_pool_rewards()`.
3. Call `plotnft.melt()` [4](#0-3)  and push the resulting spend bundle; the singleton coin is destroyed (melted).
4. Attempt to spend the previously-farmed `RewardPuzzle` coin: there is no longer any live singleton coin with `singleton_id == launcher_id` able to produce the required `SEND_MESSAGE`, so `SingletonMember`'s solve requirement in [10](#0-9)  can never be satisfied again — the reward coin is permanently stuck.

class SingletonMember:
    singleton_id: bytes32
    singleton_mod_hash: bytes32 = SINGLETON_TOP_LAYER_MOD_HASH
    singleton_launcher_hash: bytes32 = SINGLETON_LAUNCHER_PUZZLE_HASH

    def memo(self, nonce: int) -> Program:
        return Program.to(0)

    def puzzle(self, nonce: int) -> Program:
        singleton_struct = (self.singleton_mod_hash, (self.singleton_id, self.singleton_launcher_hash))
        return SINGLETON_MEMBER_MOD.curry(singleton_struct)

    def puzzle_hash(self, nonce: int) -> bytes32:
        return self.puzzle(nonce).get_tree_hash()

    def solve(self, singleton_inner_puzzle_hash: bytes32) -> Program:
        return Program.to([singleton_inner_puzzle_hash])
