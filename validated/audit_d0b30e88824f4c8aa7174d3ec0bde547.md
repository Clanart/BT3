### Title
Unclaimed self-custody plot-NFT pool rewards become permanently unclaimable if the PlotNFT singleton is melted first - ([File: chia/pools/plotnft_drivers.py])

### Summary
`PlotNFT.claim_pool_rewards()` and `PlotNFT.melt()` are two mutually exclusive actions on the same PlotNFT singleton coin. Pool-reward p2 coins are locked with a `SingletonMember` puzzle that can only be spent in the same transaction as a live spend of the corresponding PlotNFT singleton (via a paired `SEND_MESSAGE`/`RECEIVE_MESSAGE` announcement). If a user melts their PlotNFT (ending the singleton lineage, `-113` `MELT_CONDITION`) while unclaimed pool-reward coins still exist for that `launcher_id`, there is no longer any live singleton coin to pair a claim spend with, and those reward coins can never be spent again. This mirrors the reported bug class: an unprivileged action ("burn"/"melt" your own position) irreversibly forfeits rewards that were rightfully claimable, because the claim mechanism depends on a live token/coin that the user's own prior action destroyed.

### Finding Description
- Pool rewards for a self-custody PlotNFT are paid to p2 coins locked with `RewardPuzzle`/`PoolReward`, whose puzzle is `PuzzleWithRestrictions(nonce=0, restrictions=[], puzzle=SingletonMember(singleton_id=self.plotnft_id))`. [1](#0-0) 
- `SingletonMember.puzzle()` curries the singleton struct for the PlotNFT's `launcher_id`, and `SingletonMember.solve()` only takes a `singleton_inner_puzzle_hash`; on-chain enforcement (confirmed in `test_singleton_member`) requires a `SEND_MESSAGE`/`RECEIVE_MESSAGE` pair between the reward coin's spend and an actual spend of the live singleton coin in the same block/bundle. [2](#0-1) [3](#0-2) 
- `PlotNFT.claim_pool_rewards()` builds the claim spend as a `singleton_action_spend()` on the current PlotNFT coin plus one spend per reward coin, using `SendMessage`/paired approvals so the reward coins and the singleton spend are provably linked. [4](#0-3) 
- `PlotNFT.melt()` also performs a `singleton_action_spend()`, but with the `MELT_CONDITION`-equivalent `(51 () -113)` output, which ends the singleton lineage and creates no successor coin. [5](#0-4) 
- Once melted, the PlotNFT coin is permanently spent with no singleton child; `claim_rewards()`/`pw_absorb_rewards` require fetching `get_current_plotnft()` to build a new `singleton_action_spend`, but no such live coin exists any more. [6](#0-5) [7](#0-6) 
- There is no fallback path (e.g., a standalone spend of the p2 reward coin that doesn't require a live singleton, or a way to "cash out" pending rewards as part of the melt spend itself) evident in `plotnft_drivers.py`/`plotnft_wallet.py`, so any reward coin whose singleton parent has been melted becomes unspendable forever — its value is stranded on-chain, unlike the CVG report where `claimRewards` merely reverts but state is otherwise intact. Here the underlying puzzle lock genuinely can no longer be satisfied.

### Impact Explanation
This is a Medium-severity finding: an unprivileged wallet user, acting entirely on their own PlotNFT, can permanently and irreversibly lose XCH pool rewards they were entitled to simply by melting/exiting their plot-NFT before claiming outstanding rewards. This is a real, coin-level, unauthorized-loss condition (the coin's value becomes permanently unspendable/burned), fitting "concrete unsigned or unauthorized coin movement"/asset stranding under the validation criteria. It does not require any malicious peer, network condition, or privileged actor — only the user's own sequencing mistake, exactly analogous to the reported `LockingPositionService`/`YsDistributor` bug class.

### Likelihood Explanation
Likelihood is realistic: any self-custody plot-NFT operator who lets pool rewards accumulate and then decides to exit/melt their plot-NFT (e.g., to reclaim the locked 1 mojo or exit pooling permanently) without first calling `claim_rewards`/`pw_absorb_rewards` will trigger this. There is no on-chain or wallet-side guard preventing `melt()` while `plotnft2_store.get_pool_rewards()` shows pending, unclaimed rewards.

### Recommendation
- In `PlotNFT2Wallet`/`plotnft_wallet.py`, before allowing a melt operation, check `plotnft2_store.get_pool_rewards(plotnft_id=...)` for outstanding, unclaimed reward coins and either force a combined claim+melt spend bundle, or block the melt (with a clear error) until all pending rewards have been claimed.
- Alternatively, redesign the reward-claim CLVM path so it does not strictly require a live singleton in the same transaction (e.g., allow reward coins to also be claimed against a final/melt spend of the singleton, or against a cached proof of prior ownership), so rewards remain claimable after melt.

### Proof of Concept
1. Create a self-custody `PlotNFT2Wallet` (`PlotNFT.launch` → self-custody `PoolConfig=None`) and farm several pool-reward coins to its `p2_singleton_puzzle_hash` (`RewardPuzzle(singleton_id=plotnft_id).puzzle_hash()`), as done in `chia/_tests/pools/test_plotnft_v2_drivers.py::test_plotnft_self_custody_claim`. [8](#0-7) 
2. Instead of calling `claim_rewards`/`claim_pool_rewards` on those reward coins, call `PlotNFT.melt()` and push the resulting `singleton_action_spend` bundle, which spends the PlotNFT singleton coin with `(51 () -113)` and produces no successor singleton coin. [5](#0-4) 
3. Attempt to claim the previously farmed reward coins via `claim_pool_rewards`/`claim_rewards`: this requires `self.get_current_plotnft()` to build a fresh `singleton_action_spend`, but the singleton lineage has ended — there is no unspent PlotNFT coin left to pair the `SEND_MESSAGE` approval with, so the `SingletonMember`-locked reward coins can never satisfy their puzzle and remain permanently unspendable. [6](#0-5)

class RewardPuzzle:
    singleton_id: bytes32

    @property
    def singleton_member(self) -> SingletonMember:
        return SingletonMember(singleton_id=self.singleton_id)

    def puzzle_with_restrictions(self) -> PuzzleWithRestrictions:
        return PuzzleWithRestrictions(nonce=0, restrictions=[], puzzle=self.singleton_member)

    def puzzle(self) -> Program:
        return self.puzzle_with_restrictions().puzzle_reveal()

    def puzzle_hash(self) -> bytes32:
        return self.puzzle().get_tree_hash()

    def solve(
        self, singleton_inner_puzzle_hash: bytes32, delegated_puzzle_and_solution: DelegatedPuzzleAndSolution

            [],

@dataclass(kw_only=True, frozen=True)
class SingletonMember:
    singleton_id: bytes32
    singleton_mod_hash: bytes32 = SINGLETON_TOP_LAYER_MOD_HASH
    singleton_launcher_hash: bytes32 = SINGLETON_LAUNCHER_PUZZLE_HASH

    def memo(self, nonce: int) -> Program:
        return Program.to(0)

    def puzzle(self, nonce: int) -> Program:
        singleton_struct = (self.singleton_mod_hash, (self.singleton_id, self.singleton_launcher_hash))
        return SINGLETON_MEMBER_MOD.curry(singleton_struct)

    def puzzle_hash(self, nonce: int) -> bytes32:
        return self.puzzle(nonce).get_tree_hash()

    def solve(self, singleton_inner_puzzle_hash: bytes32) -> Program:
        return Program.to([singleton_inner_puzzle_hash])

    async def pw_absorb_rewards(
        self,
        request: PWAbsorbRewards,
        action_scope: WalletActionScope,
        extra_conditions: tuple[Condition, ...] = tuple(),
    ) -> PWAbsorbRewardsResponse:
        """Perform a sweep of the p2_singleton rewards controlled by the pool wallet singleton"""
        wallet = self.service.wallet_state_manager.wallets[request.wallet_id]

        if isinstance(wallet, PoolWallet):
            async with self.service.wallet_state_manager.lock:
                await wallet.claim_pool_rewards(request.fee, request.max_spends_in_tx, action_scope)
                state: PoolWalletInfo = await wallet.get_current_state()
        elif isinstance(wallet, PlotNFT2Wallet):
            await wallet.claim_rewards(action_scope=action_scope, fee=request.fee, extra_conditions=extra_conditions)
            state = await wallet.get_current_state()
        else:
            raise ValueError("`pw_absorb_rewards` called on a non-pooling wallet")

        return PWAbsorbRewardsResponse(
            unsigned_transactions=[],
            transactions=[],
            state=state,
            transaction=REPLACEABLE_TRANSACTION_RECORD,
            fee_transaction=REPLACEABLE_TRANSACTION_RECORD,
        )
