## Analysis Result

### Title
Uncontrolled Resource Consumption in `auction_submitBid` RPC Handler via Missing Rate Limiting on Bid Signature Verification - (File: `kaiax/auction/impl/api.go`, `kaiax/auction/impl/bid_pool.go`)

### Summary
The Kaia auction module (`kaiax/auction`) implements two independent ingestion paths for KIP-249 bids: a P2P gossip path (`BidPool.HandleBid`) and a direct JSON-RPC path (`AuctionAPI.SubmitBid` → `BidPool.AddBid`). The P2P path is explicitly protected by a per-peer token-bucket rate limiter (`checkRateLimit`, 300 bids/sec/peer), but the RPC path that any auction bidder can call directly bypasses this limiter entirely and goes straight into `validateBid`, which performs expensive ECDSA signature-recovery operations before any pool-size or throttling gate is applied.

### Finding Description
`AuctionAPI.SubmitBid` [1](#0-0)  is a public RPC entry point that decodes the target transaction, forwards it to the tx pool, and then calls `api.a.bidPool.AddBid(bid)` directly — with no rate limiting of any kind.

`BidPool.AddBid` immediately invokes `bp.validateBid(bid)` [2](#0-1) , which performs cheap checks (duplicate hash, sender-winner conflict, block-number range, bid>0, data-size, gas-limit) and only afterward calls `bp.validateBidSigs(bid)` [3](#0-2) , which recovers both the searcher and auctioneer ECDSA signatures via `crypto.SigToPub` [4](#0-3) . Crucially, the `maxBidPoolSize` bound (`ErrBidPoolFull`) is only enforced later in `insertBid` [5](#0-4)  — after the two costly signature recoveries have already run — so a full or even disabled-acceptance bid pool provides no protection against repeated signature-verification cost.

By contrast, the P2P ingestion path `BidPool.HandleBid` explicitly checks a per-peer rate limiter *before* any bid ever reaches `validateBid`/`AddBid` [6](#0-5) , and the codebase's own tests document this asymmetry is a deliberate DoS mitigation ("HandleBid must not block the p2p worker that delivered the bid: the queue is shared, so one blocked sender stalls every peer's bid ingress") [7](#0-6) . No equivalent limiter (`checkRateLimit`, `bidsPerSecondPerPeer`, or any per-caller/per-IP throttle) exists on the `AuctionAPI.SubmitBid` code path, meaning any client permitted to call `auction_submitBid` (an "auction bidder" per the in-scope actor list) can invoke it in an unbounded, unthrottled loop, forcing the node to perform two ECDSA signature recoveries plus RLP decoding and a full transaction-pool admission call (`api.a.Backend.SendTx`) for every single request, with no cap on request rate.

This mirrors the CWE-400 pattern in the reference advisory (GHSA-pmqc-57g8-c22c): a webhook/RPC-style handler that performs non-trivial per-request work (there: request/message handling; here: RLP decode + tx-pool admission + dual ECDSA recovery) without a resource-consumption gate before the expensive work is performed.

### Impact Explanation
An attacker with the ability to call `auction_submitBid` (a searcher/bidder, which the auction module's threat model already anticipates as an external actor) can flood a Consensus Node (CN) with a high rate of RPC calls containing syntactically-valid-length signatures and garbage bytes. Each call forces the node to execute `Backend.SendTx` (full tx-pool validation) and two costly ECDSA public-key recovery operations before being rejected, with no queueing/rate-limit backpressure comparable to the P2P path. Sustained abuse can consume CPU on the CN's RPC-handling goroutines, degrading the node's ability to process legitimate bids, transactions, and block production duties — an availability (CWE-400/DoS) impact against a consensus-critical component, matching the "Medium" severity classification of the CVSS vector `AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:L` in the reference advisory.

### Likelihood Explanation
Likelihood is high for reachability: the vulnerable RPC method requires no special privilege beyond access to the `auction` JSON-RPC namespace, and the request format is fully documented and public in the module's own README (`auction_submitBid`) [8](#0-7) . The attack requires no protocol-breaking payloads — only repeated, well-formed but crypto-invalid bids, which are cheap for the attacker to generate (fixed-size random bytes) but non-trivial for the node to reject (public-key recovery), yielding an asymmetric cost advantage. The existing rate-limit design on the P2P path but its total absence on the RPC path (verified above) confirms the resource-consumption gate was not carried over consistently.

### Recommendation
Apply the same (or an RPC-appropriate) per-caller rate limit to `AuctionAPI.SubmitBid` before it reaches `bidPool.AddBid`/`validateBid`, e.g., reuse `checkRateLimit`/a dedicated limiter keyed by RPC client/connection, and move any inexpensive bound checks (pool-full / duplicate / block-range) ahead of the two ECDSA recovery calls in `validateBid` so rejected or throttled bids never pay the signature-verification cost. Consider capping total in-flight `SubmitBid` calls the same way generic JSON-RPC batch/pending-request limits are enforced elsewhere in `networks/rpc` [9](#0-8) .

### Proof of Concept
1. Obtain (or be granted) access to a CN's `auction` RPC namespace (as the module's own documentation shows is expected for the `Auctioneer`/bidder role).
2. Repeatedly call `auction_submitBid` in a tight loop with a valid-length but bogus `searcherSig`/`auctioneerSig` (65 random bytes each) and a syntactically valid `targetTxRaw`.
3. Each call triggers `toTx` RLP decode, `Backend.SendTx` tx-pool admission, `bp.validateBid`'s cheap checks, and then two `crypto.SigToPub` ECDSA recoveries in `validateBidSigs` — all before any pool-size or rate limit rejects the request, since no rate limiter exists on this call path (only present on `BidPool.HandleBid`, the p2p ingestion path).
4. Sustained flooding consumes CPU cycles on the CN with no throttling, unlike the identical scenario over the p2p `HandleBid` path where `checkRateLimit` (300/sec/peer) bounds the cost.

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)

func (bp *BidPool) AddBid(bid *auction.Bid) (common.Hash, error) {
	if atomic.LoadUint32(&bp.running) == 0 {
		return common.Hash{}, auction.ErrAuctionPaused
	}

	if err := bp.validateBid(bid); err != nil {
		return common.Hash{}, err
	}

	if err := bp.insertBid(bid); err != nil {
		return common.Hash{}, err
	}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}

func (bp *BidPool) HandleBid(peerID string, bid *auction.Bid) {
	if atomic.LoadUint32(&bp.running) == 0 || bid == nil {
		return
	}

	// Check rate limit for this peer
	if !bp.checkRateLimit(peerID) {
		logger.Trace("Rate limit exceeded for peer", "peerID", peerID)
		return
	}

	select {
	case bp.bidMsgCh <- bid:
	default:
		logger.Trace("Bid queue is full, dropping bid", "peerID", peerID)
	}
}

func (b *Bid) ValidateSearcherSig(chainId *big.Int, verifyingContract common.Address, version string) error {
	if chainId == nil {
		return ErrNilChainId
	}

	if common.EmptyAddress(verifyingContract) {
		return ErrNilVerifyingContract
	}

	digest := b.GetHashTypedData(chainId, verifyingContract, version)

	recoveredSender, err := getSigner(b.SearcherSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover searcher sig: %v", err)
	}

	if recoveredSender != b.Sender {
		return fmt.Errorf("invalid searcher sig: expected %v, calculated %v", b.Sender.String(), recoveredSender.String())
	}

	return nil
}

func (b *Bid) ValidateAuctioneerSig(auctioneer common.Address) error {
	digest := b.GetEthSignedMessageHash()

	recoveredAuctioneer, err := getSigner(b.AuctioneerSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover auctioneer sig: %v", err)
	}

	if recoveredAuctioneer != auctioneer {
		return fmt.Errorf("invalid auctioneer sig: expected %v, calculated %v", auctioneer.String(), recoveredAuctioneer.String())
	}

	return nil
}

func TestBidPool_HandleBidDropsWhenQueueFull(t *testing.T) {

	atomic.StoreUint32(&pool.running, 1)

	for range cap(pool.bidMsgCh) {
		pool.bidMsgCh <- testBids[0]
	}

	go func() {
		pool.HandleBid("flooding-peer", testBids[0])

	case <-time.After(5 * time.Second):
