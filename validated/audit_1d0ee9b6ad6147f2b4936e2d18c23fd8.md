### Title
Sending native token value to non‑payable precompile methods (staking `delegate`/`undelegate`, distribution, gov `deposit`, bank, etc.) permanently strands the transferred coins - ([File: precompiles/staking/tx.go])

### Summary
The reported IOTA-Heroes bug is a class of "attached value is silently accepted but never reconciled against the intended amount, and the surplus becomes unrecoverable." The Cosmos EVM analog is in the stateful precompiles (staking, distribution, gov, bank, etc.) that expose Solidity functions declared `nonpayable` in their interfaces but are backed by the same generic precompile dispatch path (`common.Precompile.RunNativeAction` / `SetupABI`) used by the `werc20` precompile. Unlike `werc20.Deposit`, which explicitly reads `contract.Value()` and forwards it back to the caller via `BankKeeper.SendCoins` (`precompiles/werc20/tx.go` lines 28-56), functions like `staking.Delegate` (`precompiles/staking/tx.go` lines 143-186) never inspect `contract.Value()` at all — they only use the explicit `amount` argument supplied in calldata to build the `MsgDelegate`.

### Finding Description
EVM `CALL`/low-level calls are not constrained by the "payable" keyword at the opcode level — that check is only enforced by the Solidity compiler for calls made through a statically-typed interface. A user (or a malicious/careless contract) can issue a raw `CALL` to a precompile address (e.g. the staking precompile at `0x...800`) with `value > 0` on a method whose ABI says `nonpayable`, such as `delegate`, `undelegate`, `redelegate`, `editValidator`, `createValidator`, or `gov.deposit`. Because these precompiles are invoked through the same generic `vm.Contract` execution path as any other contract, the EVM's standard value-transfer step (moving `msg.value` from the caller's balance to the destination address's balance in the StateDB before `Run()` is invoked) is not special-cased or blocked for precompile destinations.

The relevant handlers (`precompiles/staking/tx.go` `Delegate`, `Undelegate`, `EditValidator`, and the analogous `gov.Deposit` in `precompiles/gov/tx.go`) construct their SDK message strictly from the explicit function arguments and never call `contract.Value()`, never validate that `contract.Value()` is zero, and never forward/refund any attached value. This is in stark contrast to `werc20.Deposit`, the one precompile in the codebase that correctly handles `contract.Value()` by sending it back to the caller.

As a result, once the EVM-level transfer credits the precompile's address with the attached native value, that balance is now held by a system/module address that has no corresponding withdrawal, sweep, or refund entry point exposed to users. The funds are effectively locked forever, mirroring exactly the "extra ether sent to Factory.sol cannot be recovered" bug class from the seed report.

### Impact Explanation
This meets the Critical impact bar for "permanent freezing/locking/theft of user funds": an unprivileged user, through an ordinary (if mistaken, or attacker-crafted for griefing/social-engineering) low-level call, can have native EVM token balance irreversibly and unrecoverably transferred out of their spendable balance with no compensating state change (no delegation increase, no deposit increase, no refund) and no method exists in these precompiles to reclaim it.

### Likelihood Explanation
The likelihood depends on whether a caller (EOA via crafted raw transaction, or an intermediary smart contract with a bug) sends `value` alongside calldata for one of these nonpayable methods. Standard use through the published Solidity interfaces (`StakingI.sol`, `IGov.sol`) prevents this because the interfaces mark these functions `nonpayable`, so *normal* usage via `ethers`/`web3` bound to the interface won't produce this. However, any low-level call (`address(precompile).call{value: x}(abi.encodeWithSelector(...))`), a proxy/relayer contract forwarding `msg.value` indiscriminately, or a wallet/dApp bug can trigger it. This is analogous to the original report where the vulnerability requires slightly non-standard (but entirely foreseeable and user-controlled) call patterns.

### Recommendation
- In every stateful precompile's non-payable transaction handlers (staking, distribution, gov, slashing, bank, evidence, etc.), explicitly check `contract.Value().Sign() == 0` at the top of `Execute`/`Run` dispatch (in `common.Precompile.RunNativeAction` or in each `Execute` method) and revert if a non-payable method receives value — mirroring how Solidity enforces `nonpayable` for high-level calls, but at the EVM opcode/precompile dispatch layer.
- Alternatively/complementarily, add a generic guard in `SetupABI`/`RunNativeAction` (`precompiles/common/precompile.go`) that rejects any call with `contract.Value() > 0` targeting a method whose ABI `StateMutability` is not `payable`.
- For any legitimately payable precompile method, follow the `werc20.Deposit` pattern and explicitly reconcile/refund `contract.Value()`.

### Proof of Concept
1. Deploy or use a helper contract that performs a raw low-level call:
```solidity
(bool ok, ) = address(0x0000000000000000000000000000000000000800).call{value: 1 ether}(
    abi.encodeWithSignature(
        "delegate(address,string,uint256)",
        msg.sender,
        validatorAddr,
        0 // amount = 0, but value = 1 ether attached
    )
);
```
2. The EVM state-transition transfers 1 ether worth of native coin balance from the caller to the staking precompile address before `Precompile.Run` executes.
3. `staking.Delegate` (`precompiles/staking/tx.go` lines 143-186) ignores `contract.Value()` entirely, builds `MsgDelegate` with `Amount = 0`, and the delegation either fails on `amount=0` validation or succeeds with zero effect — in either case the 1 ether transferred at the EVM layer is never returned, never delegated, and never accounted for, permanently increasing the precompile module address's balance with no path back to the user. // Deposit handles the payable deposit function. It retrieves the deposited amount
// and sends it back to the sender using the bank keeper.
func (p Precompile) Deposit(
	ctx sdk.Context,
	contract *vm.Contract,
	stateDB vm.StateDB,
) ([]byte, error) {
	caller := contract.Caller()
	depositedAmount := contract.Value()

	callerAccAddress := sdk.AccAddress(caller.Bytes())
	precompileAccAddr := sdk.AccAddress(p.Address().Bytes())

	// Send the coins back to the sender
	if err := p.BankKeeper.SendCoins(
		ctx,
		precompileAccAddr,
		callerAccAddress,
		sdk.NewCoins(sdk.Coin{
			Denom:  evmtypes.GetEVMCoinExtendedDenom(),
			Amount: math.NewIntFromBigInt(depositedAmount.ToBig()),
		}),
	); err != nil {
		return nil, err
	}

	if err := p.EmitDepositEvent(ctx, stateDB, caller, depositedAmount.ToBig()); err != nil {
		return nil, err
	}

	return nil, nil

// Delegate performs a delegation of coins from a delegator to a validator.
func (p *Precompile) Delegate(
	ctx sdk.Context,
	contract *vm.Contract,
	stateDB vm.StateDB,
	method *abi.Method,
	args []interface{},
) ([]byte, error) {
	bondDenom, err := p.stakingKeeper.BondDenom(ctx)
	if err != nil {
		return nil, err
	}
	msg, delegatorHexAddr, err := NewMsgDelegate(args, bondDenom, p.addrCdc)
	if err != nil {
		return nil, err
	}

	p.Logger(ctx).Debug(
		"tx called",
		"method", method.Name,
		"args", fmt.Sprintf(
			"{ delegator_address: %s, validator_address: %s, amount: %s }",
			delegatorHexAddr,
			msg.ValidatorAddress,
			msg.Amount.Amount,
		),
	)

	msgSender := contract.Caller()
	if msgSender != delegatorHexAddr {
		return nil, fmt.Errorf(cmn.ErrRequesterIsNotMsgSender, msgSender.String(), delegatorHexAddr.String())
	}

	// Execute the transaction using the message server
	if _, err = p.stakingMsgServer.Delegate(ctx, msg); err != nil {
		return nil, err
	}

	// Emit the event for the delegate transaction
	if err = p.EmitDelegateEvent(ctx, stateDB, msg, delegatorHexAddr); err != nil {
		return nil, err
	}

	return method.Outputs.Pack(true)
}

// SetupABI runs the initial setup required to run a transaction or a query.
// It returns the ABI method, initial gas and calling arguments.
func SetupABI(
	api abi.ABI,
	contract *vm.Contract,
	readOnly bool,
	isTransaction func(name *abi.Method) bool,
) (method *abi.Method, args []interface{}, err error) {
	// NOTE: This is a special case where the calling transaction does not specify a function name.
	// In this case we default to a `fallback` or `receive` function on the contract.

	// Simplify the calldata checks
	isEmptyCallData := len(contract.Input) == 0
	isShortCallData := len(contract.Input) > 0 && len(contract.Input) < 4
	isStandardCallData := len(contract.Input) >= 4

	switch {
	// Case 1: Calldata is empty
	case isEmptyCallData:
		method, err = emptyCallData(api, contract)

	// Case 2: calldata is non-empty but less than 4 bytes needed for a method
	case isShortCallData:
		method, err = methodIDCallData(api)

	// Case 3: calldata is non-empty and contains the minimum 4 bytes needed for a method
	case isStandardCallData:
		method, err = standardCallData(api, contract)
	}

	if err != nil {
		return nil, nil, err
	}

	// return error if trying to write to state during a read-only call
	if readOnly && isTransaction(method) {
		return nil, nil, vm.ErrWriteProtection
	}

	// if the method type is `function` continue looking for arguments
	if method.Type == abi.Function {
		argsBz := contract.Input[4:]
		args, err = method.Inputs.Unpack(argsBz)
		if err != nil {
			return nil, nil, err
		}
	}

	return method, args, nil
}
