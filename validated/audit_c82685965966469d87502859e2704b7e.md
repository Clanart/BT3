### Title
Unauthenticated TxSender JSON-RPC `send_tx` Endpoint Allows Arbitrary Transaction Injection and Fee-Payer UTXO Drain — (`crates/clementine-tx-sender/src/jsonrpc/server.rs`)

### Summary
The standalone `clementine-tx-sender` JSON-RPC server exposes a `send_tx` method with zero authentication. When configured to bind on `0.0.0.0`, any network-reachable attacker can submit arbitrary Bitcoin transactions with caller-controlled `fee_paying_type`, `cancel_outpoints`, and `cancel_txids` parameters. This is the direct Clementine analog of the external bug: just as anyone could call `rebalance()` with arbitrary parameters and corrupt the pool state, anyone can call `send_tx` with arbitrary parameters and corrupt the tx-sender's queue state, drain its fee-payer UTXOs, or suppress legitimate bridge transactions.

### Finding Description

`start_jsonrpc_server` in `crates/clementine-tx-sender/src/jsonrpc/server.rs` registers the `send_tx` method on a plain `jsonrpsee` HTTP server with no authentication layer:

```rust
module
    .register_async_method("send_tx", |params, client, _| async move {
        let req: InsertTryToSendParams = params.one().map_err(jsonrpc_err)?;
        // ... no auth check ...
        let try_to_send_id = client
            .insert_try_to_send(
                &mut dbtx,
                req.tx_metadata,
                &signed_tx,
                req.fee_paying_type,      // attacker-controlled
                req.rbf_signing_info,
                &req.cancel_outpoints,    // attacker-controlled
                &req.cancel_txids,        // attacker-controlled
                &req.activate_txids,
                &req.activate_outpoints,
            )
            .await
            .map_err(jsonrpc_err)?;
``` [1](#0-0) 

The bind address is explicitly allowed to be `0.0.0.0` by the configuration parser:

```rust
if bind != "127.0.0.1" && bind != "0.0.0.0" {
    return Err(...);
}
``` [2](#0-1) 

The default in the provided `run.sh` smoke-test script is `TX_SENDER_JSONRPC_BIND=127.0.0.1`, but the code explicitly permits `0.0.0.0` with no compensating authentication mechanism anywhere in the server code.

By contrast, every gRPC endpoint in `clementine-core` is protected by the `OnlyAggregatorAndSelf` mTLS interceptor that validates the leaf certificate of the peer: [3](#0-2) 

The JSON-RPC server has no equivalent guard.

**Attack vector 1 — CPFP fee-payer drain:**
An attacker submits a valid but low-fee Bitcoin transaction (spending UTXOs the attacker controls) with `fee_paying_type: CPFP`. The tx-sender's loop calls `try_to_send_unconfirmed_txs`, detects the fee is below the current rate, and creates a CPFP child transaction spending one of its own fee-payer UTXOs to bump the attacker's transaction. Repeating this exhausts the tx-sender's fee-payer UTXO pool. Legitimate bridge transactions (kickoff, challenge, reimburse, disprove) that also require CPFP fee bumping can no longer be bumped and become stuck in the mempool. [4](#0-3) 

**Attack vector 2 — cancel-outpoint state poisoning:**
The attacker submits a transaction with `cancel_outpoints` or `cancel_txids` pointing to legitimate bridge UTXOs (e.g., a kickoff UTXO, a reimburse connector, or a challenge UTXO). If the attacker's transaction confirms on-chain, the tx-sender marks those bridge UTXOs as cancelled in its internal DB state, suppressing the corresponding legitimate bridge transactions even though the bridge UTXOs remain unspent on-chain. [5](#0-4) 

### Impact Explanation

The tx-sender is the sole automated broadcaster for all time-sensitive bridge transactions: `Kickoff`, `Challenge`, `ChallengeTimeout`, `Reimburse`, `Disprove`, `AssertTimeout`, `WatchtowerChallengeTimeout`, and `LatestBlockhash`. All of these have on-chain timelocks. [6](#0-5) 

Draining the fee-payer UTXO pool or poisoning the cancel-outpoint state causes these transactions to miss their timelocks. Concretely:
- A `Challenge` or `Disprove` transaction that misses its timelock allows a malicious operator to escape punishment and claim reimbursement for an invalid withdrawal, resulting in theft of bridged BTC from the vault.
- A `Reimburse` transaction that misses its timelock permanently locks the operator's collateral.

Both outcomes are within the stated allowed impact scope: "theft, loss, permanent lock, or slashable exposure of bridged BTC, operator collateral, reimbursement outputs, bridge-controlled UTXOs, or tx-sender-managed balances."

### Likelihood Explanation

- The `json-rpc` feature is a first-class production feature with its own crate (`crates/clementine-tx-sender`), a dedicated `run.sh` smoke-test, and a published `JsonRpcTxSenderClient` in `crates/tx-sender-jsonrpc-client`. [7](#0-6) 
- The configuration explicitly permits `0.0.0.0` binding, which is the natural choice in containerized or cloud deployments where the tx-sender runs as a sidecar.
- No authentication token, API key, IP allowlist, or TLS is required or even available on the JSON-RPC server.
- The CPFP drain attack requires only that the attacker control some Bitcoin UTXOs (a trivially low bar for a motivated adversary targeting a live bridge).

### Recommendation

1. **Add authentication to the JSON-RPC server.** At minimum, require a shared secret (bearer token or HTTP Basic Auth) that must be set via environment variable before the server starts. Reject all requests that do not present the correct token.
2. **Restrict the bind address to `127.0.0.1` by default and remove `0.0.0.0` as a permitted value**, or document that `0.0.0.0` requires an external network-level access control (firewall rule, VPC security group, etc.) and enforce this with a startup warning.
3. **Validate submitted transactions against a whitelist of known bridge transaction patterns** (e.g., only accept transactions whose inputs are known bridge UTXOs) before queuing them.
4. **Rate-limit** the `send_tx` endpoint to prevent queue flooding.

fn only_aggregator_and_self(
    req: Request<()>,
    our_cert: &CertificateDer<'static>,
    aggregator_cert: &CertificateDer<'static>,
) -> Result<Request<()>, Status> {
    let Some(peer_certs) = req.peer_certs() else {
        if cfg!(test) {
            // Test mode, we don't need to verify peer certificates
            return Ok(req);
        } else {
            // If we're not in test mode, we need to check peer certificates
            return Err(Status::unauthenticated(
                "Failed to verify peer certificate, is TLS enabled?",
            ));
        }
    };

    // IMPORTANT: Only check the leaf (end-entity) certificate, which is always the first
    // certificate in the chain. The leaf is the only certificate whose private key the peer
    // proved possession of during the TLS handshake. Checking anywhere else in the chain
    // would allow identity spoofing: an attacker could include a pinned cert as an
    // intermediate in their chain without possessing its private key.
    let Some(leaf_cert) = peer_certs.first() else {
        return Err(Status::unauthenticated("Peer certificate chain is empty"));
    };

    if is_internal(&req) {
        if leaf_cert == our_cert {
            Ok(req)
        } else {
            Err(Status::unauthenticated(
                "Unauthorized call to internal method (not self)",
            ))
        }
    } else if leaf_cert == aggregator_cert || leaf_cert == our_cert {
        Ok(req)
    } else {
        Err(Status::unauthenticated(
            "Unauthorized call to method (not aggregator or self)",
        ))
    }

    pub async fn insert_try_to_send(
        &self,
        dbtx: &mut crate::TxSenderTransaction,
        tx_metadata: Option<TxMetadata>,
        signed_tx: &Transaction,
        fee_paying_type: FeePayingType,
        rbf_signing_info: Option<RbfSigningInfo>,
        cancel_outpoints: &[OutPoint],
        cancel_txids: &[Txid],
        activate_txids: &[ActivatedWithTxid],
        activate_outpoints: &[ActivatedWithOutpoint],
    ) -> Result<u32, BridgeError> {
        let txid = signed_tx.compute_txid();

        // do not add duplicate transactions to the txsender
        let tx_exists = self
            .db
            .check_if_tx_exists_on_txsender(Some(dbtx), txid)
            .await?;
        if let Some(try_to_send_id) = tx_exists {
            return Ok(try_to_send_id);
        }

        tracing::info!(
            "Added tx {} with txid {} to the queue",
            tx_metadata
                .as_ref()
                .map(|data| format!("{:?}", data.tx_type))
                .unwrap_or("N/A".to_string()),
            txid
        );

        let try_to_send_id = self
            .db
            .save_tx(
                dbtx,
                tx_metadata,
                signed_tx,
                fee_paying_type,
                txid,
                rbf_signing_info,
            )
            .await?;

//! JSON-RPC client for the tx-sender service.

use jsonrpsee::core::client::ClientT as _;
use jsonrpsee::core::client::Error as JsonRpcError;
use jsonrpsee::http_client::{HttpClient, HttpClientBuilder};
use jsonrpsee::rpc_params;

#[cfg(feature = "clementine")]
use bitcoin::{consensus, OutPoint, Transaction, Txid};
#[cfg(feature = "citrea")]
pub use tx_sender_types::citrea::InsertCitreaRawTxParams;
#[cfg(feature = "citrea")]
pub use tx_sender_types::CitreaTxRequest;
#[cfg(feature = "clementine")]
pub use tx_sender_types::{
    ActivatedWithOutpoint, ActivatedWithTxid, FeePayingType, InsertTryToSendParams, RbfSigningInfo,
    RbfSigningSpendPath, TxMetadata,
};

#[derive(Debug, Clone)]
pub struct JsonRpcTxSenderClient {
    inner: HttpClient,
}

impl JsonRpcTxSenderClient {
    pub fn new(url: &str) -> Result<Self, JsonRpcError> {
        let inner = HttpClientBuilder::default().build(url)?;
        Ok(Self { inner })
    }

    #[cfg(feature = "clementine")]
    #[allow(clippy::too_many_arguments)]
    pub async fn insert_try_to_send(
        &self,
        tx_metadata: Option<TxMetadata>,
        signed_tx: &Transaction,
        fee_paying_type: FeePayingType,
        rbf_signing_info: Option<RbfSigningInfo>,
        cancel_outpoints: &[OutPoint],
        cancel_txids: &[Txid],
        activate_txids: &[ActivatedWithTxid],
        activate_outpoints: &[ActivatedWithOutpoint],
    ) -> Result<u32, JsonRpcError> {
        let signed_tx_hex = consensus::encode::serialize_hex(signed_tx);

        let req = InsertTryToSendParams {
            tx_metadata,
            signed_tx_hex,
            fee_paying_type,
            rbf_signing_info,
            cancel_outpoints: cancel_outpoints.to_vec(),
            cancel_txids: cancel_txids.to_vec(),
            activate_txids: activate_txids.to_vec(),
            activate_outpoints: activate_outpoints.to_vec(),
        };

        self.inner
            .request::<u32, _>("send_tx", rpc_params![req])
            .await
    }
