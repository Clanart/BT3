### Title
Reward-per-token sandwiching around permissionless `WombatStaking::harvest()` allows theft of accrued LP staking rewards - (File: wombat/WombatStaking.sol)

### Summary
`WombatStaking::harvest()` is a fully permissionless function that pulls accumulated WOM/bonus rewards from MasterWombat and immediately converts them into an instantaneous, permanent increase of `rewardPerTokenStored` in the corresponding `BaseRewardPool`. Because staking (via `WombatPoolHelper::deposit`/`depositLP`) and unstaking are also unprivileged, an attacker can deposit LP tokens immediately before calling `harvest()`, capture a pro-rata share of rewards that accrued over time to other stakers, and withdraw right after — the exact "sandwich the reward-claim" pattern described in the Sherlock M-3 report (there: `claimDelayedWithdrawals()`; here: `harvest()`).

### Finding Description
`WombatStaking::harvest()` has no caller restriction — only `whenNotPaused` and `_onlyActivePool(_lpToken)`, which merely checks the pool is active, not who calls it: [1](#0-0) [2](#0-1) 

`harvest()` calls `_toMasterWomAndSendReward`, which withdraws pending WOM (and bonus token) rewards accrued in MasterWombat since the last interaction and forwards them via `_sendRewards` to `queueNewRewards`/`_provisionReward` on the pool's `BaseRewardPool`: [3](#0-2) 

`_provisionReward` immediately folds the entire batch of newly harvested rewards into `rewardPerTokenStored`, scaled by the **current** `totalStaked()`: [4](#0-3) 

Reward accounting for any account is anchored at `userRewardPerTokenPaid` at the moment of the last `_updateFor` call (e.g. on stake/unstake), and `earned()` computes the delta between the current `rewardPerTokenStored` and that anchor, multiplied by the user's current balance: [5](#0-4) 

Staking/unstaking is fully permissionless through `WombatPoolHelper` (or `AnkrBNBPoolHelper`), which route to `MasterMagpie::depositFor`/`withdrawFor` and `WombatStaking::deposit`/`withdraw`: [6](#0-5) [7](#0-6) 

Because a fresh depositor's `userRewardPerTokenPaid` is set to the pool's `rewardPerTokenStored` *before* `harvest()` is called, and `harvest()` then raises `rewardPerTokenStored` based on `totalStaked()` that now includes the attacker's freshly-deposited LP, the attacker captures a share of rewards that accrued to other stakers over the whole period since the last harvest — despite having staked for essentially zero time. This directly mirrors the reported bug class: a permissionless, delayed reward-realization call that can be sandwiched by mint→claim→withdraw to siphon rewards from long-term stakers.

### Impact Explanation
This results in direct theft of unclaimed yield from honest long-term LPs by an unprivileged attacker, diluting the reward-per-token accrued to legitimate stakers proportionally to the attacker's temporarily inflated share of `totalStaked()`. The magnitude scales with the size of the pending harvest batch and the fraction of `totalStaked()` the attacker can acquire, similar to the referenced report's classification (Medium severity, direct fund diversion via reward-per-share manipulation).

### Likelihood Explanation
High likelihood: `harvest()` is a public, unauthenticated function that anyone can call at will (e.g., after observing pending rewards on MasterWombat via view functions), and deposit/withdraw through the pool helpers are equally permissionless with no lockup preventing immediate withdrawal after a single block. No privileged role, oracle, or governance action is required — only three ordinary user transactions (deposit, harvest, withdraw) that can be executed atomically or across consecutive blocks/MEV bundles.

### Recommendation
Do not let a single `harvest()` call instantly convert the entire pending reward batch into `rewardPerTokenStored` based on the current `totalStaked()`. Instead, stream/vest rewards over time (e.g., accrue per-second similar to `MultiRewarderPerSec`), or require a minimum staking duration/cooldown before newly staked balances become eligible for a pending reward batch, so an attacker cannot capture rewards accrued before their deposit.

### Proof of Concept
1. Pool has stakers A and B with LP staked for a long period; MasterWombat accumulates pending WOM rewards for the pool over time (no `harvest()` called yet).
2. Attacker calls `WombatPoolHelper::deposit()` → `WombatStaking::deposit()` → `MasterMagpie::depositFor()`, staking a large LP amount right before harvest. This sets the attacker's `userRewardPerTokenPaid` to the pool's stale, pre-harvest `rewardPerTokenStored` value [8](#0-7) .
3. Attacker (or anyone) calls `WombatStaking::harvest(lpToken)` [9](#0-8) , which pulls all pending WOM rewards and calls `_provisionReward`, raising `rewardPerTokenStored` based on `totalStaked()` that now includes the attacker's freshly staked LP [10](#0-9) .
4. Attacker immediately calls `withdraw()` (via `WombatPoolHelper::withdraw`), which triggers `_updateFor`/`earned()` crediting the attacker a share of the just-harvested rewards proportional to their large stake, despite having staked for effectively one block [11](#0-10) .
5. Attacker claims rewards via `getReward`, netting a portion of rewards that should have accrued only to A and B, diluting their `earned()` payouts.

        uint256 bonusTokensLength = bonusTokens.length;

        uint256 womBeforeBalance = IERC20(wom).balanceOf(address(this));

        uint256 womRewards = IERC20(wom).balanceOf(address(this)) - womBeforeBalance;
        _sendRewards(_lpToken, wom, poolInfo.rewarder, womRewards);

        for (uint256 i; i < bonusTokensLength; i++) {

            if (bonusBalanceDiff > 0) {
                _sendRewards(_lpToken, bonusTokens[i], poolInfo.rewarder, bonusBalanceDiff);
            }
        }

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (this.totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingDecimals()) /
                this.totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
    }
