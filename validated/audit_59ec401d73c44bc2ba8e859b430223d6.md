### Title
Server-Side Request Forgery via unrestricted DataLayer mirror URLs - (File: chia/data_layer/download_data.py)

### Summary
Any wallet user can register arbitrary, attacker-chosen mirror URLs for a DataLayer store via `add_mirror`, and any DataLayer node that later subscribes to that store id will have its `DataLayer` service issue outbound HTTP GET requests to those attacker-controlled URLs with no scheme, host, or address validation — allowing network enumeration/SSRF against the victim's internal network, cloud metadata endpoints, or other local services.

### Finding Description
`DataLayer.add_mirror()` accepts a list of user-supplied `urls` and only checks that the list is non-empty before publishing them on-chain via `dl_new_mirror`: [1](#0-0) 

The RPC entrypoint passes the request straight through without validating URL scheme or target host: [2](#0-1) 

Any peer subscribing to the same store id later reads these mirror URLs from the wallet/chain (`update_subscriptions_from_wallet`) and stores them as candidate download servers: [3](#0-2) 

During `fetch_and_validate()`, the DataLayer service iterates these server URLs and issues outbound network requests to them via `insert_from_delta_file` → `download_file` → `http_download`, with no allow-list, no scheme restriction (beyond implicit HTTP/HTTPS), and no protection against private/loopback/link-local addresses: [4](#0-3) [5](#0-4) 

There is no host/IP validation anywhere in this path — `is_filename_valid()` only validates the requested *filename* shape, not the destination URL: [6](#0-5) 

Because the mirror-owning peer does not need to own or control the store being subscribed to by others (only the on-chain mirror coin), and any DataLayer client can subscribe to any public store id, an attacker can cause any victim node running DataLayer to make outbound HTTP requests to attacker-chosen internal or third-party addresses (e.g. `http://169.254.169.254/latest/meta-data/`, `http://127.0.0.1:<internal-port>/...`, or internal LAN hosts), and observe success/failure/log output (e.g. "Server {url} unavailable" vs successful download proceeding to file parsing) as an oracle for network/service enumeration. This directly mirrors the reported IBM Concert SSRF class: an authenticated actor causing the system to issue requests to arbitrary attacker-chosen destinations.

### Impact Explanation
An authenticated DataLayer client (unprivileged relative to other nodes) can force victim DataLayer nodes to originate outbound HTTP requests toward internal infrastructure, enabling network/service enumeration, port-scanning of internal services, or interaction with cloud metadata endpoints, potentially facilitating further attacks (e.g., credential leakage via metadata services). This matches CVSS AV:N/AC:L/PR:L/UI:N/C:L classification of the reference CVE. It does not directly cause fund loss or consensus divergence, keeping it at Medium impact.

### Likelihood Explanation
Likelihood is fairly high for any environment running DataLayer with subscriptions enabled: creating a mirror is a normal, low-cost on-chain action (pay a fee, publish a coin with arbitrary `urls`), and any node that subscribes to that store id (which is by design meant to allow arbitrary third parties to replicate data) will automatically attempt outbound requests to those URLs during its periodic `periodically_manage_data()` / `fetch_and_validate()` loop without operator intervention.

### Recommendation
- Validate mirror URLs at `add_mirror`/`DataLayerRpcApi.add_mirror` time (and again before use in `fetch_and_validate`/`http_download`): enforce `http`/`https` scheme, and reject/deny-list requests to loopback, link-local, private, and multicast address ranges (including DNS resolution checks to prevent rebinding to internal IPs).
- Consider requiring subscription-time opt-in confirmation with the resolved destination shown to the operator before any file fetch, and add an explicit configuration option (default-deny) to allow internal-network mirror fetches only when explicitly enabled.

### Proof of Concept
1. Attacker creates a DataLayer store and adds a mirror pointing at an internal target, e.g. `add_mirror(store_id, urls=["http://169.254.169.254/latest/meta-data/"], amount=1, fee=1)` via `DataLayerRpcApi.add_mirror` / `chia/data_layer/data_layer.py:965`.
2. Victim node runs DataLayer with subscriptions enabled and subscribes to (or is auto-pseudo-subscribed to, if it also owns) the same store id.
3. During the victim's periodic sync, `update_subscriptions_from_wallet()` pulls the attacker's mirror URL and stores it as a candidate server (`chia/data_layer/data_layer.py:979-985`).
4. `fetch_and_validate()` calls `insert_from_delta_file` → `download_file` → `http_download`, causing the victim's DataLayer process to issue an HTTP GET to `http://169.254.169.254/...` (`chia/data_layer/download_data.py:298-324`), with success/failure observable through logs/behavior — confirming SSRF.

```python
def is_filename_valid(filename: str, group_by_store: bool = False) -> bool:
    if group_by_store:
        if filename.count("/") != 1:
            return False
        filename = filename.replace("/", "-")

    split = filename.split("-")

    try:
        raw_store_id, raw_node_hash, file_type, raw_generation, raw_version, *rest = split
        store_id = bytes32(bytes.fromhex(raw_store_id))
        node_hash = bytes32(bytes.fromhex(raw_node_hash))
        generation = int(raw_generation)
    except ValueError:
        return False

    if len(rest) > 0:
        return False

    # TODO: versions should probably be centrally defined
    if raw_version != "v1.0.dat":
        return False

    if file_type not in {"delta", "full"}:
        return False

    generate_file_func = get_delta_filename if file_type == "delta" else get_full_tree_filename
    reformatted = generate_file_func(
        store_id=store_id, node_hash=node_hash, generation=generation, group_by_store=False
    )

    return reformatted == filename
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
