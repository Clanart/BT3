## Analysis: Unbounded recursion DoS in Offer/puzzle-driver parsing

The Play Framework advisory (GHSA-v8x6-59g4-5g3w) is about unbounded recursive parsing of attacker-controlled nested structures leading to stack/heap exhaustion. The corresponding pattern exists in the Chia wallet's offer/puzzle-driver matching code, which recursively descends into nested curried puzzle layers with no depth limit, and is reachable simply by a wallet user parsing an offer received from an untrusted counterparty.

### Title
Unbounded recursion in outer-puzzle driver matching allows an offer counterparty to crash a wallet via deeply nested puzzle reveal - (File: `chia/wallet/outer_puzzles.py`, `chia/wallet/trading/offer.py`)

### Summary
`Offer.from_bech32`/`Offer.from_bytes` unconditionally calls `Offer.from_spend_bundle`, which calls `match_puzzle()` on every coin spend's `puzzle_reveal`. `match_puzzle` dispatches to outer-puzzle drivers (CAT, singleton, metadata, ownership, credential-restricted) whose `.match()` methods recursively call `self._match()` on the puzzle's inner curried argument with no depth bound. `PuzzleInfo.also()`/`check_type()` mirror this recursive pattern on the resulting driver dict. A malicious offer with an artificially deep chain of nested curry layers (e.g., CAT-in-CAT-in-CAT... thousands deep) drives unbounded Python recursion the moment any wallet user opens/examines/takes the offer.

### Finding Description
- `match_puzzle()` iterates `driver_lookup` and calls `driver.match(puzzle)` [1](#0-0) .
- Each outer-puzzle driver's `match()` recurses into its inner puzzle without any depth check, e.g. CAT: [2](#0-1) , metadata layer: [3](#0-2) , ownership layer: [4](#0-3) , singleton layer: [5](#0-4) , and credential-restricted layer: [6](#0-5) .
- `PuzzleInfo.also()`/`check_type()` build a fresh `PuzzleInfo` recursively for each `"also"` level with no bound: [7](#0-6) .
- The entry point is triggered simply by parsing any offer: `Offer.from_spend_bundle` calls `match_puzzle` for every coin spend in the bundle [8](#0-7) , and `Offer.from_bech32`/`try_offer_decompression`/`from_bytes` are the standard, unauthenticated deserialization path for any offer string a counterparty hands to a wallet [9](#0-8) .
- This parsing path fires automatically in normal usage: `TakeOffer.parsed_offer` is a cached property that calls `Offer.from_bech32(self.offer)` [10](#0-9) , and the `take_offer` RPC endpoint (and CLI `--examine-only` flow, and `get_offer_summary`) invoke it before the user takes any action [11](#0-10) .
- There is no `sys.setrecursionlimit` guard, no explicit `RecursionError` handling, and no depth cap anywhere in this call chain (confirmed by search across the repo).

Unlike the data-layer file-import path, which was recently hardened against deep binary Merkle trees with an explicit `chia_rs.datalayer.RecursionDepthExceededError` [12](#0-11) , no equivalent protection exists for the offer/puzzle-driver matching path.

### Impact Explanation
An offer counterparty (a normal, unprivileged actor who merely shares a `.offer` file/bech32 string with a victim) can craft a `puzzle_reveal` with an arbitrarily deep chain of nested curried layers matching one of the recognized outer-puzzle types (CAT/singleton/metadata/ownership/CR). Simply parsing (not even accepting) this offer — via `take_offer` (examine-only), `get_offer_summary`, `check_offer_validity`, or the CLI — drives unbounded Python-level recursion mixed with calls into `chia_rs`/`clvm` native code for uncurrying. This can raise an uncaught `RecursionError` (denying that RPC call) or, because native-extension call frames also consume C stack that Python's own recursion counter does not fully account for, potentially crash the wallet service process outright. This matches CWE-400 (resource-exhaustion DoS) and is reachable purely from a spend-bundle/offer artifact supplied by an untrusted counterparty, satisfying the "spend-triggered transaction-processing halt" criterion.

### Likelihood Explanation
High likelihood: no privileged access, no signature, and no valid consensus-level puzzle hash is required — the attacker only needs curry-structural validity (`puzzle.mod == CAT_MOD` etc. and `curried_args is not None`) at each nesting level, which is trivial to construct programmatically with `construct_cat_puzzle`/`puzzle_for_singleton`/etc. in a loop. The victim wallet performs this parsing automatically as part of normal offer-viewing UX, without any confirmation step.

### Recommendation
Add an explicit maximum recursion/nesting depth check in `match_puzzle`/each outer-puzzle driver's `.match()` (and in `PuzzleInfo.also()`/`check_type()`), rejecting offers whose puzzle_reveal exceeds a small, sane layer count (e.g., matching the maximum number of outer puzzle types Chia actually composes, with a safety margin). Alternatively, convert the recursive traversal into an explicit iterative stack-based algorithm (as already done for `sha256_treehash` in `chia/types/blockchain_format/tree_hash.py`) so that native-extension call depth cannot compound with Python recursion depth, and raise a clear `ValueError`/`OfferParsingError` instead of allowing unbounded recursion.

### Proof of Concept
1. Programmatically build a `Program` puzzle by repeatedly wrapping `construct_cat_puzzle(CAT_MOD, tail, inner)` (or `puzzle_for_singleton`, ownership/metadata layer constructors) around itself N times (N in the thousands), producing a single `puzzle_reveal`.
2. Construct a `CoinSpend` with `parent_coin_info == bytes32.zeros` (marking it as a requested-payment placeholder per `Offer.from_spend_bundle`) using this puzzle_reveal, and wrap it in a `WalletSpendBundle`/`Offer`.
3. Encode via `Offer.to_bech32()` and send the resulting string to a victim as a normal offer file.
4. Victim runs `chia wallet take_offer <file> --examine-only` (or the wallet UI calls `take_offer`/`get_offer_summary`), which calls `Offer.from_bech32` → `Offer.from_spend_bundle` → `match_puzzle`, recursing N levels deep and raising `RecursionError` or crashing the wallet RPC process.

    def from_spend_bundle(cls, bundle: WalletSpendBundle) -> Offer:
        # Because of the `to_spend_bundle` method, we need to parse the dummy CoinSpends as `requested_payments`
        requested_payments: dict[bytes32 | None, list[NotarizedPayment]] = {}

                assert asset_id is not None
                driver_dict[asset_id] = driver
            else:
                asset_id = None
            if coin_spend.coin.parent_coin_info == bytes32.zeros:
                notarized_payments: list[NotarizedPayment] = []

                    payment_args_list = payment_group.rest().as_iter()
                    notarized_payments.extend(
                        [NotarizedPayment.from_condition_and_nonce(condition, nonce) for condition in payment_args_list]
                    )

                requested_payments[asset_id] = notarized_payments
            else:
                leftover_coin_spends.append(coin_spend)

@pytest.mark.anyio
@pytest.mark.parametrize("depth", [1000, 100_000])
async def test_insert_into_data_store_from_file_line_graph_depth(
    data_store: DataStore,
    store_id: bytes32,
    tmp_path: Path,
    depth: int,
) -> None:
    # Binary "line graph":
    #   1 -> leaf_1, 2
    #   2 -> leaf_2, 3
    #   ...
    #   depth -> leaf_depth, leaf_end
    #
    # This stresses depth/stack handling while staying strictly binary.
    #
    # Node IDs:
    # - internal nodes: 1..depth
    # - per-level leaf nodes: (depth+1)..(2*depth)
    # - final leaf: (2*depth+1)
    internal_first = 1
    internal_last = depth
    leaf_base = internal_last + 1
    leaf_end = (2 * depth) + 1

    edges: list[tuple[int, int]] = []
    for i in range(internal_first, internal_last):
        # Order matters: first edge is left child, second edge is right child.
        edges.append((i, leaf_base + (i - internal_first)))  # unique leaf for this internal node
        edges.append((i, i + 1))  # next internal node

    # last internal points to its leaf and a final leaf
    edges.append((internal_last, leaf_base + (internal_last - internal_first)))
    edges.append((internal_last, leaf_end))

    filename = tmp_path / f"line_graph_depth_{depth}.dat"
    root_hash = create_graph_util(filename, edges)

    with pytest.raises(chia_rs.datalayer.RecursionDepthExceededError):
        await data_store.insert_into_data_store_from_file(store_id, root_hash, filename)
