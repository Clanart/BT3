### Title
Unauthenticated `send_citrea_tx` JSON-RPC endpoint allows any network-reachable attacker to drain operator Bitcoin wallet via forced commit+reveal transactions — (`crates/clementine-tx-sender/src/jsonrpc/server.rs`)

---

### Summary

The `send_citrea_tx` JSON-RPC method is registered with no authentication, no caller verification, and no IP-level enforcement at the application layer. When the server is bound to `0.0.0.0` — an explicitly supported and validated configuration — any network-reachable attacker can submit arbitrary DA payloads. The tx-sender task loop automatically picks up every queued row, funds a Bitcoin commit transaction from the operator's wallet, signs it, broadcasts it, and then broadcasts a reveal transaction. This drains the operator's Bitcoin balance through fee payment for attacker-controlled garbage data.

---

### Finding Description

**Unauthenticated handler registration:**

The `send_citrea_tx` method is registered via `ServerBuilder::default()` with no middleware, no token check, and no IP allowlist enforcement at the code level: [1](#0-0) [2](#0-1) 

The handler immediately calls `client.send_citrea_tx(req.citrea_tx_request)` with no caller identity check of any kind.

**`0.0.0.0` is an explicitly accepted bind address:**

The config parser validates that `TX_SENDER_JSONRPC_BIND` is either `127.0.0.1` or `0.0.0.0`, making the latter a first-class supported deployment option: [3](#0-2) 

When bound to `0.0.0.0`, the server is reachable from any network interface with no authentication gate.

**Automatic downstream spending from operator wallet:**

Every row inserted into `tx_sender_citrea_raw_tx_queue` is unconditionally processed by `sync_citrea_txs` on the next poll cycle. For each pending row, the task calls `fund_raw_transaction` (spending from the operator's Bitcoin wallet), signs the commit transaction, and broadcasts it on-chain. A reveal transaction is then created and broadcast: [4](#0-3) [5](#0-4) 

The attacker's payload bytes are embedded verbatim in the reveal script and broadcast on-chain, funded entirely by the operator.

**No deduplication protection against flooding:**

The `body_hash` uniqueness constraint only deduplicates identical payloads. An attacker can submit an unbounded number of distinct payloads (each up to `MAX_JSONRPC_REQUEST_BODY_SIZE` = 50 MB), each generating a separate commit+reveal pair: [6](#0-5) 

---

### Impact Explanation

The operator's Bitcoin wallet (tx-sender-managed balance) is drained through fee payment for commit and reveal transactions that carry attacker-controlled garbage data. Each request causes at minimum two on-chain Bitcoin transactions (commit + reveal) funded from the operator's wallet. A sustained flood of distinct payloads can exhaust the operator's UTXO set, halting legitimate bridge operations (deposit finalization, payout, reimbursement) that also depend on the same tx-sender queue and wallet.

---

### Likelihood Explanation

Exploitability is conditional on the server being bound to `0.0.0.0`. This is an explicitly supported and documented configuration option. In any deployment where the tx-sender is exposed beyond localhost (e.g., containerized environments, cloud VMs with the port exposed, or multi-service deployments where the Citrea bridge actor runs on a separate host), the endpoint is reachable with no credentials required. The attack requires only the ability to send HTTP POST requests to the JSON-RPC port.

---

### Recommendation

1. **Add mandatory authentication** to the JSON-RPC server. At minimum, require a shared secret (bearer token or HMAC-signed request) validated in a Tower middleware layer before any method handler is invoked.
2. **Restrict `send_citrea_tx` to localhost-only** by rejecting `0.0.0.0` as a valid bind address for the Citrea endpoint, or by adding a separate listener for Citrea-specific methods that only binds to `127.0.0.1`.
3. **Add a rate limit and queue depth cap** on `tx_sender_citrea_raw_tx_queue` to bound the worst-case wallet drain even if auth is bypassed.

    pub async fn sync_citrea_txs(&self, fee_rate: FeeRateKvb) -> Result<(), eyre::Report> {
        // First, check existing commit txids for eviction.
        self.check_evicted_commit_txs().await?;

        // First get all citrea rows (except aggregate tx) with commit_outpoint IS NULL.
        // For all of these we will try to fund and create a tx that creates commit utxos.
        let citrea_rows = self
            .db
            .get_citrea_txs_with_null_commit_outpoint(None)
            .await?;

        // Group rows by insertion_id since all chunk rows share the same eventual commit tx/outpoint.
        let mut by_insertion_id: BTreeMap<i64, Vec<CitreaRawTxRow>> = BTreeMap::new();

        for row in citrea_rows {
            by_insertion_id
                .entry(row.insertion_id)
                .or_default()
                .push(row);
        }

        if !by_insertion_id.is_empty() {
            tracing::info!(
                "Found {} pending non-aggregate citrea rows across {} insertion_id groups",
                by_insertion_id.values().map(|v| v.len()).sum::<usize>(),
                by_insertion_id.len()
            );
        }

        // For each insertion_id group, create a single commit tx/outpoint shared by all rows.
        for (insertion_id, rows) in by_insertion_id {
            tracing::debug!(insertion_id, group_len = rows.len(), "Pending citrea group");

            // Build reveal scripts and collect commit addresses for all rows in this group.
            let mut rows_with_scripts = Vec::with_capacity(rows.len());

            for row in rows {
                let signing_data = self.create_reveal_script(row.transaction_kind, &row.body);
                rows_with_scripts.push((row, signing_data));
            }

            let _ = self
                .create_commit_outpoints_for_rows(fee_rate, insertion_id, rows_with_scripts)
                .await?;
        }
