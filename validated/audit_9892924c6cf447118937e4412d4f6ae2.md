### Title
mWOMSVBaseRewarder never applies cooldown forfeiture, always paying 100% of rewards regardless of mWomSV.getRewardablePercentWAD - (File: rewards/mWOMSVBaseRewarder.sol)

### Summary
`mWOMSVBaseRewarder._calExpireForfeit` is supposed to mirror `vlMGPBaseRewarder._calExpireForfeit`, which reduces a user's payout based on `vlMGP.getRewardablePercentWAD(_account)` for tokens still in cooldown. In `mWOMSVBaseRewarder.sol`, the equivalent call to `mWOMSV.getRewardablePercentWAD(_account)` is missing entirely, so `rewardableAmount` is always set equal to `_amount` and `forfeitAmount` is always `0`.

### Finding Description
`vlMGPBaseRewarder._calExpireForfeit` computes the forfeited share of rewards using the locker's cooldown-aware percentage: [1](#0-0) 

`mWomSV.getRewardablePercentWAD` correctly implements the analogous cooldown-based rewardable percentage, discounting amounts that are in cooldown but not yet fully unlocked: [2](#0-1) 

However, `mWOMSVBaseRewarder._calExpireForfeit` never calls `mWOMSV.getRewardablePercentWAD(_account)` — it simply sets `rewardableAmount = _amount`, making `forfeitAmount` always `0`: [3](#0-2) 

A grep across the codebase confirms `getRewardablePercentWAD` is referenced only in `VLMGP.sol`, `vlMGPBaseRewarder.sol`, and `wombat/mWomSV.sol` — it is never referenced in `mWOMSVBaseRewarder.sol`. Because `getReward`/`getRewards` route through `_sendReward` → `_calExpireForfeit`, any account holding mWomSV shares in cooldown (via `startUnlock`) receives its full accrued bonus reward with no forfeiture, even though `mWomSV.getRewardablePercentWAD` simultaneously reports that the account is not fully "rewardable" (percent < 1e18) due to being mid-cooldown: [4](#0-3) [5](#0-4) 

The forfeiture mechanism (`_queueNewRewardsWithoutTransfer`, which is supposed to redistribute the forfeited amount to remaining/fully-locked stakers) is therefore dead code for `mWOMSVBaseRewarder` — `forfeitAmount` is structurally always `0`, so that branch never executes.

### Impact Explanation
This is a real, quantifiable divergence: a user with mWomSV in cooldown state is intended (per the mirrored vlMGP design and per `mWomSV.getRewardablePercentWAD`) to forfeit part of their bonus reward proportional to their cooldown fraction. Because the rewarder omits the check, that forfeited amount is never clawed back and never redistributed to the pool of fully-locked stakers via `_queueNewRewardsWithoutTransfer`. This constitutes theft/misallocation of unclaimed yield: fully-locked, honest stakers who should receive the redistributed forfeited rewards permanently lose that yield to users who partially/fully unstaked into cooldown and yet still draw full rewards. This matches the "theft or permanent freezing of unclaimed yield" Immunefi impact class.

However, the specific framing in the question — that some hypothetical "external distributor" queries `mWomSV.getRewardablePercentWAD` to gate MGP disbursement and thereby causes a literal "double payment" — is speculative; no such downstream consumer of `getRewardablePercentWAD` other than `mWOMSVBaseRewarder` (which should call it but doesn't) was found in the codebase. That portion of the claim is unsupported and out of scope per the "reject speculative/external protocol dependency" rule. The concrete, in-scope bug is the missing forfeiture enforcement itself, which dilutes yield owed to other stakers.

### Likelihood Explanation
This requires no special privileges: any unprivileged holder of mWomSV can call `startUnlock` to place part of their balance in cooldown, let bonus rewards accrue, and then call `getReward`/`getRewards` (routed permissionlessly through `MasterMagpie`) to receive 100% of accrued rewards with zero forfeiture. This is trivially and repeatably exploitable by any staker with capital already in the system, with no flash loans or advanced timing needed — every cooldown participant benefits from this bug on every claim.

### Recommendation
Update `mWOMSVBaseRewarder._calExpireForfeit` in `rewards/mWOMSVBaseRewarder.sol` to mirror `vlMGPBaseRewarder._calExpireForfeit` exactly: call `mWOMSV.getRewardablePercentWAD(_account)` (via `ILocker`/an appropriate interface extension exposing this function) and compute `rewardableAmount = _amount * rewardablePercentWAD / 1e18` before deriving `forfeitAmount`, so cooldown users are correctly penalized and forfeited rewards are queued back into the pool via `_queueNewRewardsWithoutTransfer`.

### Proof of Concept
Foundry test plan:
1. Deploy `mWomSV`, `MasterMagpie`, and `mWOMSVBaseRewarder`; register a reward token and fund rewards via `queueNewRewards`.
2. User A locks a mWom amount into `mWomSV` (`lock`), accrues reward-per-token via `queueNewRewards`.
3. User A calls `startUnlock` for half their balance, moving it into cooldown (`endTime = now + coolDownInSecs`).
4. Advance time partway through cooldown (not past `endTime`).
5. Assert `mWomSV.getRewardablePercentWAD(userA) < 1e18` (confirms partial forfeiture should apply).
6. Call `mWOMSVBaseRewarder.calExpireForfeit(userA, rewardToken)` and assert it returns `0` (no forfeiture applied) despite step 5, proving `_calExpireForfeit` ignores `getRewardablePercentWAD`.
7. Call `getReward(userA, userA)` through `MasterMagpie` and assert the full `earned(userA, rewardToken)` amount is transferred with no reduction, and that `rewards[rewardToken].rewardPerTokenStored` was never incremented via `_queueNewRewardsWithoutTransfer` (no forfeited amount was redistributed to remaining stakers).

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalmWomSV = fullyInLock + inCoolDown;
        if (userTotalmWomSV == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalmWomSV;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalmWomSV / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalmWomSV;
                }

            }
        }

        return percent;
    }

        uint256 forfeitAmount = _calExpireForfeit(_account, userRewards[_rewardToken][_account]);
        uint256 toSend = userRewards[_rewardToken][_account] - forfeitAmount;


        userRewards[_rewardToken][_account] = 0;
