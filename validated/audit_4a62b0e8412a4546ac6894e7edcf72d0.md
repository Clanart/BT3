### Title
Anyone can inflate/misclassify the multisig's scanned outputs by paying to internal offset addresses (Branch/Change/Forwarded), which are indistinguishable from real internal outputs - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner` matches received outputs by `script_pubkey` alone (`networks/bitcoin/src/wallet/mod.rs:205`), and the set of recognized scripts includes the deterministic internal offsets (Branch, Change, Forwarded) registered in `processor/src/networks/bitcoin.rs:324-344` via `Secp256k1::hash_to_F(KEY_DST, ...)`. These internal scripts are publicly derivable from the group key. An unprivileged sender can therefore broadcast a transaction paying the Branch/Change/Forwarded addresses, and `Scanner::scan_transaction` / `get_outputs` (`processor/src/networks/bitcoin.rs:686-700`) will emit an `Output` classified as an internal `OutputType` with no corresponding legitimate accounting event — the same asymmetry as the Teller bug where `totalPrincipalTokensRepaid` was inflated without a matching `totalPrincipalTokensLended`. ### Finding Description
`register_offset` maps `key + G*offset` → script, and scanning is a pure `HashMap<ScriptBuf, Scalar>` lookup. The `kinds` map then labels any matching output `External`, `Branch`, `Change`, or `Forwarded`. Because offsets are surjective (`register_offset` increments until an even point), the internal script set is fixed and publicly computable. There is no proof-of-origin or contextual check: any transaction on-chain paying to one of these scripts produces a `ReceivedOutput`/`Output` indistinguishable from one the protocol itself created. In the downstream processor this enters the output/accounting pipeline as an internally-classified output (and can additionally set `presumed_origin`/`data` per `get_outputs`), inflating tracked wallet funds without any corresponding deposit instruction — mirroring the unbacked `totalPrincipalTokensRepaid`/`totalInterestCollected` inflation and enabling "funds reported received" that were never accounted for as deposits, plus potential bricking when the accounting is reconciled (e.g., `panic!("scanned an output multiple times")`-style invariants downstream).

### Impact Explanation
An attacker can make the system report internal-kind outputs that do not correspond to any legitimate protocol action, corrupting the ledger: unbacked funds appear spendable/creditable, causing mis-accounting, incorrect change/fee handling, or denial of service when invariants are enforced. Analogous to the Teller finding, the asymmetry between a unilateral on-chain action and internal accounting produces loss-of-funds/bricking conditions.

### Likelihood Explanation
Only requires sending a Bitcoin transaction to a publicly derivable script_pubkey — reachable by any unprivileged party with trivial cost (a dust output).

### Recommendation
Bind internal-kind outputs to protocol-created context: require an `InInstruction`/expected-data marker or a registered plan before classifying an output as `Branch`/`Change`/`Forwarded`, or exclude unexpected internal-kind outputs from accounting rather than crediting them. At minimum, treat unsolicited payments to internal offsets as `External` or ignore them.

### Proof of Concept
1. Compute `key + G*hash_to_F(KEY_DST, b"change")` (adjusting for parity per `register_offset`), derive its p2tr script via `p2tr_script_buf`.
2. Broadcast a transaction paying that script.
3. `get_outputs` returns an `Output { kind: OutputType::Change, .. }` for an output the protocol never created — inflated internal balance with no matching accounting entry.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

// Always construct the full scanner in order to ensure there's no collisions
fn scanner(
  key: ProjectivePoint,
) -> (Scanner, HashMap<OutputType, Scalar>, HashMap<Vec<u8>, OutputType>) {
  let mut scanner = Scanner::new(key).unwrap();
  let mut offsets = HashMap::from([(OutputType::External, Scalar::ZERO)]);

  let zero = Scalar::ZERO.to_repr();
  let zero_ref: &[u8] = zero.as_ref();
  let mut kinds = HashMap::from([(zero_ref.to_vec(), OutputType::External)]);

  let mut register = |kind, offset| {
    let offset = scanner.register_offset(offset).expect("offset collision");
    offsets.insert(kind, offset);

    let offset = offset.to_repr();
    let offset_ref: &[u8] = offset.as_ref();
    kinds.insert(offset_ref.to_vec(), kind);
  };

  register(
    OutputType::Branch,
    *BRANCH_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"branch")),
  );
  register(
    OutputType::Change,
    *CHANGE_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"change")),
  );
  register(
    OutputType::Forwarded,
    *FORWARD_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"forward")),
  );

  (scanner, offsets, kinds)
}
