### Title
Permissionless `multiclaimFor` lets an attacker force premature vlMGP reward forfeiture on a victim, redistributing the victim's yield to all vlMGP stakers including the attacker - ([File: rewards/MasterMagpie.sol, rewards/vlMGPBaseRewarder.sol])

### Summary
`MasterMagpie.multiclaimFor` has no access control restricting who may trigger a claim `_account` — any address can call it with an arbitrary `_account`. When the claimed pool is `vlmgp`, this reaches `vlMGPBaseRewarder.queueMGP`, which computes `_calExpireForfeit` purely from the target account's own current lock/cooldown state via `VLMGP.getRewardablePercentWAD`. An attacker can call `multiclaimFor` on a victim precisely while the victim has an expired/uncured unlock slot, forcing crystallization of the forfeiture before the victim has a chance to `cancelUnlock`/relock and restore a higher rewardable percentage, and the forfeited MGP is redistributed pro-rata to all vlMGP stakers, including the attacker.

### Finding Description
`multiclaimFor` is `external whenNotPaused` with no restriction tying `msg.sender` to `_account`, and it sets both the reward "owner" and "receiver" to the attacker-supplied `_account`: [1](#0-0) 

Inside `_multiClaim`, MGP accrued for the `vlmgp` staking pool is routed through `_sendMGPForVlMGPPool`, which calls `queueMGP` on `vlMGPBaseRewarder`: [2](#0-1) 

`queueMGP` computes `forfeitAmount = _calExpireForfeit(_account, _amount)`; the "rewardable" remainder is sent to the victim, but the forfeited amount is queued as bonus reward to the pool via `_queueNewRewardsWithoutTransfer`, which increases `rewardPerTokenStored` for every current vlMGP staker (including the attacker): [3](#0-2) [4](#0-3) 

`_calExpireForfeit` derives the forfeited fraction from `VLMGP.getRewardablePercentWAD(_account)`, which is purely a function of the target's own lock/cooldown state at the moment of the call — not something the caller of `multiclaimFor` needs to have any relationship to: [5](#0-4) [6](#0-5) 

Because `getRewardablePercentWAD` decays for expired-but-unrelocked cooldown slots (the fraction shrinks as `timeNow - startTime` grows), a victim who has an expired unlock slot and intends to fix their ratio (e.g., via `cancelUnlock` or additional `lock`) before voluntarily claiming can be front-run: the attacker calls `multiclaimFor([vlmgp], ..., victim)` first, forcing the forfeiture calculation to run against the victim's currently unfavorable state and permanently converting that share of the victim's pending MGP into a bonus pool payout shared by all current stakers. The same mechanism applies to bonus-token forfeiture via `_sendReward` for `getRewards`/`getReward` (also reachable only through `_multiClaim`). No modifier in `multiclaimFor`, `_multiClaim`, or `queueMGP` prevents an unrelated address from being the trigger; `queueMGP`'s `onlyManager` check only restricts the caller to `MasterMagpie`, which itself imposes no restriction on who calls `multiclaimFor`.

### Impact Explanation
This matches the "theft or permanent freezing of unclaimed yield" impact class. The attacker cannot redirect the payout — funds always flow to `_account` (the victim) as receiver — but the attacker can force the forfeiture computation to run at a time chosen to be worst for the victim, permanently diverting a portion of the victim's pending MGP into the shared bonus pool, of which the attacker (as a vlMGP holder) captures a pro-rata share. The victim loses the ability to remediate their rewardable percentage (e.g. via `cancelUnlock`/relock) before the forfeiture is realized.

### Likelihood Explanation
Requires only: (1) attacker holds any nonzero vlMGP stake (to receive a share of the forfeited bonus pool), and (2) victim currently has an expired/uncured `userUnlockings` slot with pending unclaimed MGP in the `vlmgp` pool of `MasterMagpie`. No special privileges, capital, or timing races beyond monitoring on-chain state for victims with stale expired-cooldown slots are needed; the call `multiclaimFor` is a plain, ungated external call.

### Recommendation
Restrict `multiclaimFor` (or at minimum the forfeiture-triggering path for the `vlmgp`/base-rewarder pools) so that forfeiture realization can only be initiated by the account itself, an explicitly authorized operator, or gated behind a mechanism that lets the account first adjust its lock state (e.g., snapshot `getRewardablePercentWAD` at accrual time rather than at claim time, or require `msg.sender == _account` for any code path that can trigger `_calExpireForfeit`).

### Proof of Concept
Foundry test outline:
1. Deploy `VLMGP`, `MasterMagpie`, `vlMGPBaseRewarder`, register the `vlmgp` pool.
2. Victim locks MGP, accrues MGP rewards in the `vlmgp` pool over time (increase `mgpPerSec`/warp time), then calls `startUnlock` on part of their stake and lets the cooldown fully expire without calling `cancelUnlock`/relocking — this lowers `getRewardablePercentWAD(victim)` below 100%.
3. Attacker locks a small amount of MGP to obtain nonzero vlMGP stake, then calls `masterMagpie.multiclaimFor([vlmgp], [[]], victim)`.
4. Assert: `queueMGP` was invoked with `forfeitAmount > 0` (via `MGPHarvested`/`ForfeitRewardAdded` events), victim received less MGP than `earned` before the call, and attacker's `vlMGPBaseRewarder.earned(attacker, MGP)` increased after the forced call relative to before, despite the attacker performing no new accrual-generating action of their own.

```text
    function queueMGP(uint256 _amount, address _account, address _receiver) override external onlyManager nonReentrant returns (bool) {
        IERC20(vlMGP.MGP()).safeTransferFrom(msg.sender, address(this), _amount);
        
        uint256 forfeitAmount = _calExpireForfeit(_account, _amount);
        uint256 rewardableAmount = _amount - forfeitAmount;
        
        if (forfeitAmount > 0)
            _queueNewRewardsWithoutTransfer(forfeitAmount, address(vlMGP.MGP()));

        if (rewardableAmount > 0) {
            IERC20(vlMGP.MGP()).safeTransfer(_receiver, rewardableAmount);
            emit MGPHarvested(_account, rewardableAmount, forfeitAmount);
        }

        return true;
    }
```

```text
    function _queueNewRewardsWithoutTransfer(uint256 _amountReward, address _rewardToken) internal
    {
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards = rewardInfo.historicalRewards + _amountReward;
        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**vlMGPDecimal) / totalStaked();
        }
        emit ForfeitRewardAdded(_amountReward, _rewardToken);
    }
```

```text
    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }
```

```text
    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalVlmgp = fullyInLock + inCoolDown;
        if (userTotalVlmgp == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalVlmgp;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalVlmgp / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalVlmgp;
                }

            }
        }

        return percent;
    }
```
