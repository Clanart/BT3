### Title
Schnorr verification against the identity ("zero") public key silently succeeds, enabling universal signature forgeries - ([File: crypto/schnorr/src/lib.rs](crypto/schnorr/src/lib.rs))

### Summary
The reported bug class is an external call dispatched to `address(0)` that returns success instead of reverting: the "unset"/zero target is treated as a valid destination and the operation completes silently. The Serai analog is Schnorr signature verification against the identity group element — the group's equivalent of the zero address. `SchnorrSignature::verify` and `batch_statements` perform no identity check on `public_key` or `R`, and the base `Ciphersuite::read_G` accepts the identity encoding, so a forged `(R, s)` pair verifies under the identity public key for any challenge, and the verification "succeeds" rather than being rejected.

### Finding Description
`SchnorrSignature::verify` reduces to `R + c·A − s·G == identity` [1](#0-0) . When `public_key` is the identity element, the `c·A` term vanishes for *every* challenge `c`, so verification degenerates to `R − s·G == 0` [2](#0-1) . Any `r` produces a valid signature `(R = r·G, s = r)` under the identity key — no secret knowledge, no challenge control required. Neither `verify` nor `SchnorrSignature::read` rejects identity `R` or an identity `s` [3](#0-2) , and `Ciphersuite::read_G` — used when parsing untrusted keys — only enforces canonical encoding, not non-identity [4](#0-3) . The identity-rejecting `read_G` exists only in the FROST `Curve` trait [5](#0-4) , so any caller using the plain `Ciphersuite` API (e.g., `coordinator/tributary`'s `Signed::read`, which parses `signer` via `Ristretto::read_G` [6](#0-5) ) can feed an identity public key into `verify`. The same hole exists in `SchnorrAggregate::verify`, which applies caller-supplied keys without an identity check [7](#0-6) .

### Impact Explanation
An unprivileged party can forge a Schnorr signature that verifies under the identity public key for an arbitrary message/challenge. This is exploitable wherever an identity key can occupy a key slot parsed from untrusted bytes: a deserialized `ThresholdKeys`/view with an identity group key or verification share, a `signed` payload whose `signer` field encodes the identity, or a registry/registration that accepts a canonical identity encoding. In such contexts the forged signature is accepted as authentic, and downstream code proceeds as if a valid holder signed — the exact analogue of "the call to the unset account executes and does not revert." Severity is Medium: it is a real verifier-side formula gap reachable via `read_G`/`verify`, but full exploitation additionally requires a path that slots the identity key in as a trusted key, which I could not fully confirm within the in-scope crates (e.g., whether tributary ever accepts an identity `signer` is checked outside the cryptographic verification itself).

### Likelihood Explanation
Serializing the identity element is trivial — every prime-group encoding admits it canonically, so `C::read_G` accepts it. Producing the forgery requires no interaction with any honest party. The constraint is reachability: the identity key must reach `verify` as the `public_key`, which happens wherever keys are parsed with `Ciphersuite::read_G` rather than `Curve::read_G` and not separately validated against a known key set.

### Recommendation
Reject the identity element in `SchnorrSignature::verify`/`batch_verify` for both `public_key` and `self.R` (return `false` on `is_identity()`), mirroring the sanity check `Curve::read_G` already performs [8](#0-7)  — the Schnorr crate's own "strict" contract and the tributary `Signed` reader's explicit `signature.R.is_identity()` rejection show the invariant is intended but not enforced in `verify` itself [9](#0-8) . Apply the same check to keys in `SchnorrAggregate::verify`.

### Proof of Concept
```rust
// Any ciphersuite C; demonstrates forgery under the identity public key.
let identity = C::G::identity();
// Attacker picks any scalar r.
let r = C::hash_to_F(b"forgery", b"r");
let forged = SchnorrSignature::<C> { R: C::generator() * r, s: r };
// Holds for EVERY challenge, since c * identity == identity:
let c = C::hash_to_F(b"challenge", b"arbitrary message");
// R + c*identity - s*G = rG - rG = identity -> verify returns true
assert!(forged.verify(identity, c));
// Identity key parses cleanly through the non-strict reader:
let bytes = identity.to_bytes();
let parsed = C::read_G(&mut bytes.as_ref()).unwrap(); // Ok(identity)
assert!(bool::from(parsed.is_identity()));
```
