Based on the code I found in [1](#0-0) , there is a real local analog of the signature-recycling bug class in the BEEFY consensus verifier's authority-signature counting logic.

### Title
BEEFY consensus verifier accepts duplicate authority-index signatures toward the 2/3 supermajority threshold, enabling false finality/state acceptance - (File: `modules/consensus/beefy/verifier/src/lib.rs`)

### Summary
The `UserOpMultiSigVerifier` bug counted a repeated owner address (appearing at multiple indices) as multiple independent signers toward the multisig threshold. The same broken invariant — "one real signer counted multiple times toward a quorum threshold" — exists in Hyperbridge's BEEFY consensus proof verifier, which is the trust anchor that lets remote-chain state commitments be accepted as final.

### Finding Description
In `verify_mmr_update_proof`, the verifier iterates over `mmr.signed_commitment.signatures` and, for each entry, recovers the signer, pushes `authority_leaves` and `authority_indices`, and counts `signatures_length` for the threshold check: [2](#0-1) 

The threshold check is: [3](#0-2) 

which calls `check_participation_threshold(signatures_length, authority_set.len)` — a simple `len >= (2*total)/3 + 1` count of *entries in the submitted signature list*, not of distinct authorities. Nowhere in this loop, or before the merkle multi-proof verification, is there a check that `sig.index` values are unique. An attacker constructing the `ConsensusMessage` can duplicate one genuine `(index, signature)` pair from a single honest authority multiple times in `mmr.signed_commitment.signatures`. This:
1. Inflates `signatures_length`, satisfying `check_participation_threshold` even though the number of *distinct* signing authorities is below the real 2/3+1 supermajority.
2. Does not fail the subsequent merkle multi-proof verification, since `authority_indices`/`authority_leaves` simply re-verify the same already-valid `(index, leaf)` pair redundantly — duplicate entries do not invalidate a merkle multiproof.

This mirrors the external report precisely: the code prevents reusing the *same index* for signature/session tracking style protections, but the actual protection needed — uniqueness of the underlying signer/authority — is missing here as well, since duplicate `(index, signature)` tuples are never deduplicated before being counted toward the quorum.

### Impact Explanation
This allows false remote consensus state / parachain header commitments to be accepted as trusted by the light client (`ConsensusState.latest_beefy_height`, `current_authorities`/`next_authorities` get updated per `verify_mmr_update_proof`, lines 179-186), even when the real number of distinct BEEFY authorities that actually signed is below the required supermajority. Once an illegitimate MMR root / parachain header is accepted as finalized, all downstream ISMP request/response/proof verification that depends on this consensus state (state commitments, state proofs) can be spoofed — directly enabling false state acceptance, which the bounty pivots explicitly call out as a top-priority impact ("Consensus proofs, state proofs, challenge periods, and state commitments must never let false remote state become trusted").

### Likelihood Explanation
The BEEFY consensus update message (`ConsensusMessage`) is submitted through a permissionless update path (no privileged relayer/governance origin is required to submit a consensus proof update to the ISMP host) so it is reachable by any unprivileged actor who can obtain (or already has) one valid authority signature over a commitment (e.g., replaying a genuine partial signature set that didn't itself reach quorum). No additional trust assumption on a malicious relayer, prover, or validator is required — the attacker only needs to duplicate entries already present in a legitimately produced (but insufficiently-signed) commitment.

### Recommendation
Deduplicate `sig.index` (and/or recovered authority addresses) before counting `signatures_length` and before building `authority_indices`/`authority_leaves`. E.g., collect indices into a set and reject the message (or only count once) if any index appears more than once. Enforce this uniqueness check prior to computing/checking `check_participation_threshold`, analogous to the fix recommended in the referenced report (dedup by unique signer/index, or require indices to be provided in strictly ascending order).

### Proof of Concept
1. Obtain a real `SignedCommitment` for some block where fewer than `2/3*total + 1` authorities actually signed (e.g., a stalled/partial round), containing `k` valid `SignatureWithAuthorityIndex` entries where `k < required`.
2. Duplicate one or more `(index, signature)` entries in `mmr.signed_commitment.signatures` until `signatures_length >= required`.
3. Submit this crafted `ConsensusMessage` via `verify_mmr_update_proof`.
4. `check_participation_threshold(signatures_length, authority_set.len)` passes despite fewer than `required` distinct authorities signing; the merkle multiproof still verifies since the duplicated entries reference already-valid `(index, leaf)` pairs.
5. `trusted_state` (including `latest_beefy_height` and authority sets) is updated based on this under-signed commitment — false state gets trusted. [4](#0-3)

pub fn verify_mmr_update_proof<H: Keccak256 + EcdsaRecover + Send + Sync>(
	mut trusted_state: ConsensusState,
	mmr: MmrProof,
) -> Result<(ConsensusState, H256), Error> {
	let signatures_length = mmr.signed_commitment.signatures.len();
	let latest_height = mmr.signed_commitment.commitment.block_number;

	if trusted_state.latest_beefy_height >= latest_height {
		return Err(Error::StaleHeight {
			trusted_height: trusted_state.latest_beefy_height,
			current_height: latest_height,
		});
	}

	let commitment = mmr.signed_commitment.commitment.clone();

	// Pick the authority set the commitment claims to be signed under, then judge
	// participation against that set alone.
	let authority_set = if commitment.validator_set_id == trusted_state.current_authorities.id {
		&trusted_state.current_authorities
	} else if commitment.validator_set_id == trusted_state.next_authorities.id {
		&trusted_state.next_authorities
	} else {
		return Err(Error::UnknownAuthoritySet { id: commitment.validator_set_id });
	};

	if !check_participation_threshold(signatures_length as u32, authority_set.len) {
		return Err(Error::SuperMajorityRequired);
	}

	let mmr_root_data = commitment
		.payload
		.get_raw(&MMR_ROOT_PAYLOAD_ID)
		.ok_or(Error::MmrRootHashMissing)?;

	if mmr_root_data.len() != 32 {
		return Err(Error::InvalidMmrRootHashLength { len: mmr_root_data.len() });
	}
	let mmr_root = H256::from_slice(mmr_root_data);

	let commitment_hash = H::keccak256(&commitment.encode());
	let mut authority_leaves: Vec<[u8; 32]> = Vec::new();
	let mut authority_indices = Vec::new();

	for sig in mmr.signed_commitment.signatures.iter() {
		let uncompressed = H::secp256k1_recover(&commitment_hash.0, &sig.signature)
			.map_err(|_| Error::FailedToRecoverPublicKey)?;

		let hashed_uncompressed = H::keccak256(&uncompressed);

		let mut eth_address = [0u8; 20];
		eth_address.copy_from_slice(&hashed_uncompressed.as_ref()[12..]);

		let authority_address_hash = H::keccak256(&eth_address);

		authority_leaves.push(authority_address_hash.into());
		authority_indices.push(sig.index as usize);
	}

	let merkle_proof = MerkleProof::<MerkleHasher<H>>::new(mmr.authority_proof.clone());

	let valid = merkle_proof.verify(
		authority_set.keyset_commitment.into(),
		&authority_indices,
		&authority_leaves,
		authority_set.len as usize,
	);

	if !valid {
		Err(Error::InvalidAuthoritiesProof)?;
	}

	verify_mmr_leaf::<H>(&mmr, mmr_root)?;

	if mmr.latest_mmr_leaf.beefy_next_authority_set.id > trusted_state.next_authorities.id {
		trusted_state.current_authorities = trusted_state.next_authorities.clone();
		trusted_state.next_authorities = mmr.latest_mmr_leaf.beefy_next_authority_set.clone();
	}

	trusted_state.latest_beefy_height = latest_height;

	Ok((trusted_state, mmr.latest_mmr_leaf.leaf_extra))
}
