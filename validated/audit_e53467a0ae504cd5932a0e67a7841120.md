### Title
`SignableTransaction::new` omits OP_RETURN data from fee sizing, producing signed transactions below the intended feerate - ([File: networks/bitcoin/src/wallet/send.rs](networks/bitcoin/src/wallet/send.rs))

### Summary
The transaction constructor appends an attacker-controlled `OP_RETURN` output but calculates transaction weight, minimum relay fee, requested fee, change amount, and maximum standard weight using only the payment outputs and optional change output. [1](#0-0)  This arithmetic omission is analogous to the auction-duration miscalculation: a component belonging in the computed result is omitted, causing the committed result to differ from the intended calculation. [2](#0-1) 

### Finding Description
`calculate_weight_vbytes` builds an estimated transaction exclusively from `inputs`, `payments`, and optional `change`. [3](#0-2)  `SignableTransaction::new` first appends the `OP_RETURN` output to `tx_outs`, but then calls `calculate_weight_vbytes(tx_ins.len(), payments, None)` without any representation of that output. [4](#0-3) 

The resulting `vbytes` drives the minimum-relay-fee check, requested `needed_fee`, and the funds-sufficiency check. [5](#0-4)  When change is requested, the second estimate likewise excludes the already-added `OP_RETURN`, so `fee_with_change` and the change value are calculated from an undersized transaction. [6](#0-5)  The returned transaction nevertheless contains the full `tx_outs`, including the `OP_RETURN`. [7](#0-6) 

Signing commits to the final, larger transaction through the Taproot sighash, while the paid fee remains based on the smaller estimate. [8](#0-7) 

### Impact Explanation
An unprivileged caller can supply up to 80 bytes through the public `data` argument, adding approximately 92 serialized bytes to the transaction while paying none of the corresponding requested fee. [9](#0-8) [10](#0-9) 

With a change output, the excess transaction size does not become an additional fee; instead, the change output absorbs the residue so the actual fee remains the underestimated `fee_with_change`. [6](#0-5)  At the boundary accepted by the internal minimum-fee check, the signed transaction can therefore fall below Bitcoin’s default relay requirement for its real virtual size and fail normal propagation. [11](#0-10)  More generally, every transaction carrying `data` is signed at a lower effective sat/vbyte rate than the caller-specified `fee_per_vbyte`. [2](#0-1) 

### Likelihood Explanation
The bug is deterministic whenever `data` is `Some`, and the caller does not need validator privileges because `data` is an ordinary public argument to `SignableTransaction::new`. [12](#0-11)  The strongest reliability impact requires change to be enabled or the input amount to be tight; without change, all leftover input value becomes fee, so the transaction may still exceed the underestimated target. [13](#0-12) [6](#0-5) 

### Recommendation
Include the eventual `OP_RETURN` output in both calls to `calculate_weight_vbytes`, either by passing the already-constructed `tx_outs` or an explicit data-output parameter. [4](#0-3)  The change calculation must use the same complete output set as the final transaction before deriving `fee_with_change` and the change amount. [6](#0-5)  A regression test should assert `tx.fee() >= fee_per_vbyte * final_tx.vsize()` and the default relay minimum for nonzero `data`. [14](#0-13) 

### Proof of Concept
```rust
// Conceptual public-API PoC.

let input = scanned_spendable_output();      // value selected below
let change = scanner_owned_change_script();
let data = vec![0x42; 80];                   // public caller-controlled bytes
let fee_rate = 1;                            // 1 sat/vbyte

let signable = SignableTransaction::new(
  vec![input],
  &[],
  Some(change),
  Some(data),
  fee_rate,
).unwrap();

let tx = signable.transaction();

// Internal calculation:
//   needed_fee == fee_rate * estimated_vbytes_without_op_return
// Final transaction:
//   actual_vbytes == estimated_vbytes_without_op_return + ~92

assert_eq!(signable.fee(), signable.needed_fee());
assert!(tx.vsize() > signable.needed_fee() as usize);
```

The `OP_RETURN` output is added before the estimate, but the estimator receives only `payments` and `change`, so its output list cannot contain that output. [15](#0-14)  With `fee_rate = 1`, the internal minimum check compares the underestimated fee against the underestimated size, while the signed transaction is roughly 92 vbytes larger. [16](#0-15)  The signing path then commits to the complete transaction containing the omitted output. [17](#0-16)
