### Title
Unchecked type assertion on CW20/CW721/CW1155 query response in pointer precompile causes an unrecovered panic - (File: precompiles/pointer/pointer.go)

### Summary
The `AddCW20`, `AddCW721`, and `AddCW1155` methods of the pointer precompile (`0x000000000000000000000000000000000000100b`) query a CosmWasm contract's `token_info`/`contract_info` and blindly type-assert the `"name"` and `"symbol"` JSON fields to `string` with `formattedRes["name"].(string)` and `formattedRes["symbol"].(string)`, without the two-value `, ok` form. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
This mirrors the class of bug in the iwlwifi CVE: trusting the shape/format of externally supplied data (there, a firmware TLV string; here, a CW contract's JSON response) without validating it before consuming it, leading to an out-of-bounds/invalid access. In Go, a failed type assertion of this single-value form panics rather than returning a zero value. Any CosmWasm contract that a caller points at via `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` fully controls the JSON body returned from `token_info`/`contract_info` (e.g., it could omit `name`/`symbol`, or return them as numbers/objects/null). Because the contract address is attacker-supplied (`cwAddr := args[0].(string)`), an unprivileged EVM caller can deploy a minimal CW contract that returns `{"name": 1, "symbol": null}` (or omits the fields entirely, making the map values `nil`) and then call the pointer precompile against it. [4](#0-3) 

### Impact Explanation
Whether this is exploitable as a node-crashing DoS depends entirely on whether a `recover()` exists somewhere between the EVM precompile dispatch and this call. I found that `precompiles/common/precompiles.go` does contain `recover()` calls (3 matches), which strongly suggests panics from precompile execution are caught and converted into reverted calls (as is typical for the `p256` precompiles, which use `defer recover()` around signature verification). If pointer's execution path is wrapped by the same generic dynamic-gas precompile recovery, the panic is turned into a reverted transaction, and the impact is limited to a wasted transaction rather than a chain-halting crash — in which case this would not meet the required "crash of default-configuration RPC nodes" or "block delay beyond 2.5 seconds" bar. I was not able to fully confirm within the available tool budget whether `pcommon.NewDynamicGasPrecompile`'s call path recovers panics specifically from `AddCW20`/`AddCW721`/`AddCW1155`, or whether recovery is only present in `chargeDecodeGas` (which only wraps gas-metering, not the executor body). [5](#0-4) 

### Likelihood Explanation
If the panic is not recovered before reaching the EVM interpreter's precompile call site, any unprivileged CosmWasm deployer/EVM caller could trivially trigger it by deploying a trivial CW contract with a crafted query response and invoking the pointer precompile — a single, cheap, always-reproducible transaction. If it is recovered (likely, given the pattern seen elsewhere), the likelihood of a chain-halting event is low and this reduces to, at most, an unhandled-error/UX bug (out of scope per the rules).

### Recommendation
Regardless of whether an outer recover() exists, `AddCW20`, `AddCW721`, and `AddCW1155` should validate the JSON response defensively, e.g.:
```go
name, ok := formattedRes["name"].(string)
if !ok {
    return nil, 0, fmt.Errorf("cw contract returned invalid or missing name field")
}
symbol, ok := formattedRes["symbol"].(string)
if !ok {
    return nil, 0, fmt.Errorf("cw contract returned invalid or missing symbol field")
}
```
This closes the gap without needing to rely on an upstream recover() guard.

### Proof of Concept
1. Deploy a CosmWasm contract whose `token_info` (for CW20) or `contract_info` (for CW721/CW1155) query handler returns JSON such as `{"name": 123, "symbol": null}` or omits both fields.
2. From any account, call the EVM pointer precompile at `0x000000000000000000000000000000000000100b` method `addCW20Pointer` (or `addCW721Pointer`/`addCW1155Pointer`) with `args[0]` set to the bech32 address of that contract.
3. Execution reaches `formattedRes["name"].(string)` / `formattedRes["symbol"].(string)`; since the underlying value is not a string, the single-value type assertion panics.

// chargeDecodeGas charges the (already-installed) gas meter for decoding the
// calldata, before it is decoded: a length-proportional scan cost that also
// bounds the DecodeGasCost scan, then the string-copy surcharge from
// DecodeGasCost. Its out-of-gas / overflow recovery is deliberately scoped to
// just these charges — a call that cannot afford the decode reverts here, while
// an executor that later exhausts its gas keeps its normal propagating
// out-of-gas semantics. Anything other than a gas-meter panic is re-raised.
func (d DynamicGasPrecompile) chargeDecodeGas(ctx sdk.Context, method *abi.Method, input []byte) (err error) {
	defer func() {
		if r := recover(); r != nil {
			switch r.(type) {
			case sdk.ErrorOutOfGas, sdk.ErrorGasOverflow:
				err = fmt.Errorf("%v", r)
			default:
				panic(r)
			}
		}
	}()
	scanCost := DefaultGasCost(input, false)
	ctx.GasMeter().ConsumeGas(scanCost, fmt.Sprintf("%s precompile calldata scan", d.name))
	decodeCost, ok := DecodeGasCost(method.Inputs, input)
	if !ok {
		// Calldata is structurally invalid (Unpack would reject it too); reject
		// now, without attempting the decode.
		return fmt.Errorf("invalid calldata encoding for %s", d.name)
	}
	// DecodeGasCost already includes scanCost; charge only the remaining
	// (string-copy) portion so the decode is priced exactly once.
	ctx.GasMeter().ConsumeGas(decodeCost-scanCost, fmt.Sprintf("%s precompile calldata decode", d.name))
	return nil
}
