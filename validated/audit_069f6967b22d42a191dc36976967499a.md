### Title
Just-in-time vote front-running lets an attacker snipe a disproportionate share of freshly-queued bribes in `BribeRewardPool` - (File: `wombat/WombatBribeManager.sol`, `rewards/BaseRewardPoolV2.sol`)

### Summary
`BribeRewardPool`/`BaseRewardPoolV2` distribute bribes via an instantaneous `rewardPerTokenStored` bump (`_provisionReward`) rather than a time-streamed rate, and `WombatBribeManager.vote()` lets any vlMGP holder instantly reallocate votes (and thus staked balance in the rewarder) with no epoch delay or minimum holding period. An attacker who observes a pending `castVotes()`/`harvestSinglePool()` call in the mempool (which triggers `queueNewRewards` with a large harvested bribe) can front-run it with `vote()` to shift a large vlMGP delta into the target pool immediately before the bribe lands, then `claimBribe` and `unvote`/withdraw right after, capturing bribe yield accrued over the whole prior voting period without having contributed any real staking duration.

### Finding Description
`WombatBribeManager.vote()` calls `IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, uint256(delta))` synchronously and immediately increases `_balances[_for]` in `BribeRewardPool.stakeFor` [1](#0-0) , [2](#0-1) .

The `updateRewards` modifier correctly snapshots the account's *old* balance before crediting it against the previous `rewardPerTokenStored`, so the freshly added stake starts with `userRewardPerTokenPaid == rewardPerToken` at the moment of staking [3](#0-2) . This part is *not* exploitable by itself — the early-`continue` optimization is harmless because it only skips redundant recomputation when nothing changed.

The actual root cause is that bribe injection is **instantaneous, not time-streamed**: `queueNewRewards` → `_provisionReward` bumps `rewardPerTokenStored` by the *entire* newly harvested bribe amount divided by the *current* `totalStaked()` in a single step [4](#0-3) . There is no `periodFinish`/`rewardRate` streaming (unlike Synthetix-style pools), so any address holding a balance at the exact block the bribe is queued is retroactively entitled to a full proportional share of that bribe, regardless of how long they held that balance.

Because `WombatBribeManager.vote()` has no epoch delay, cooldown, or minimum-holding-period, and simply reallocates already-locked vlMGP between pools at zero cost [5](#0-4) , an attacker can:
1. Watch the mempool for a pending `castVotes()`/`harvestSinglePool()` call, which will call `wombatStaking.vote()` → `voter.vote()` (harvests external Wombat bribes) → `queueNewRewards()` on the target pool's rewarder [6](#0-5) , [7](#0-6) .
2. Front-run with `vote()` moving a large positive delta into that pool, instantly inflating `_balances[attacker]` in the rewarder before the bribe lands.
3. Once `queueNewRewards` executes, `rewardPerTokenStored` jumps and the attacker's `earned()` reflects a full proportional share of the just-harvested bribe.
4. Call `claimBribe`/`claimAllBribes` to collect the reward [8](#0-7) , then `unvote`/`withdrawFor` to pull the vlMGP back out for reuse elsewhere.

No existing check (modifier, reward-index update, or access control) prevents this, because none of them account for staking *duration* — they only track cumulative `rewardPerToken` snapshots.

### Impact Explanation
This is a theft of unclaimed yield from long-term voters: the bribe pool for pool X is meant to be split among vlMGP holders proportional to their voting weight over the accrual period, but a same/adjacent-block "vote-then-unvote" attacker can capture a share of that bribe with effectively zero exposure time, diluting/stealing yield that should have accrued to genuine long-term voters of pool X. This matches "theft of unclaimed yield" in the impact taxonomy.

### Likelihood Explanation
- Requires only vlMGP already locked by the attacker (no privileged role) — vote reallocation itself costs no additional capital beyond gas.
- Requires public mempool visibility of `castVotes()`/`harvestSinglePool()` calls, both of which are permissionless and callable by anyone, making the harvest event/bribe size largely predictable ahead of time.
- Fully repeatable every time a sizeable bribe is about to be harvested/queued for a pool, as long as the attacker holds/borrows enough vlMGP voting power to make a meaningful move.
- Feasible on any chain with a public mempool (front-running); even without perfect mempool visibility, an attacker can periodically pre-position votes ahead of predictable `castVotes` cadence.

### Recommendation
Introduce time-weighted reward accrual instead of instant `rewardPerTokenStored` bumps — e.g., stream newly queued rewards over a fixed duration (`rewardRate`/`periodFinish`, Synthetix-style) so newly added stake only starts earning going forward at the same rate as everyone else, rather than being retroactively entitled to bribes harvested for a full prior period. Alternatively, enforce a minimum vote-lock/cooldown period (an epoch system) between `vote()` and being eligible to receive/claim bribes for a given cast, and/or checkpoint balances used for reward calculation to the block prior to the harvest so same-block or same-epoch stake changes can't affect that harvest's distribution.

### Proof of Concept
Foundry test plan:
1. Deploy `WombatBribeManager`, `WombatStaking`, and a `BribeRewardPool` for pool X with two long-term voters, `Alice` and `Bob`, each having voted a fixed delta for pool X many blocks/epochs earlier (simulate real bribe accrual over time via multiple prior `castVotes` calls without changing votes).
2. Simulate a pending large external bribe for pool X becoming harvestable (mock `voter.vote()`/`IWombatBribe` to return a large `rewardAmounts[i][j]`).
3. Before calling `castVotes()`/`harvestSinglePool([X])`, have `Attacker` (holding vlMGP but with zero prior vote history on pool X) call `vote([X], [largeDelta])` in the same block.
4. Execute `castVotes()`/`harvestSinglePool([X])`, triggering `queueNewRewards` and the `rewardPerTokenStored` jump.
5. Have `Attacker` call `claimBribe([X])` and then `unvote(X)` in the same or next block.
6. Assert: `Attacker.earned(rewardToken)` after step 5 is greater than a time-weighted-fair share (e.g., `largeDelta * bribeAmount / totalStaked * (attackerHoldingBlocks/totalAccrualBlocks)` ≈ 0 given near-zero holding duration), while it actually receives `largeDelta / totalStaked_after * bribeAmount` — proving disproportionate capture relative to `Alice`/`Bob`'s multi-epoch-long exposure.

    function vote(address[] calldata _lps, int256[] calldata _deltas) override public {
        if (_lps.length != _deltas.length)
            revert LengthMismatch();

        uint256 length = _lps.length;
        int256 totalUserVote;

        for (uint256 i; i < length; i++) {
            Pool storage pool = poolInfos[_lps[i]];
            if (!pool.isActive)
                revert PoolNotActive();
            int256 delta = _deltas[i];
            totalUserVote += delta;
            if (delta != 0) {
                if (delta > 0) {
                    pool.totalVoteInVlmgp += uint256(delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] += uint256(delta);
                    IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, uint256(delta));
                } else {
                    pool.totalVoteInVlmgp -= uint256(-delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] -= uint256(-delta);
                    IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(-delta), false);
                }
            }
        }

        if (msg.sender != delegatedPool) {
            if (totalUserVote > 0) {
                userTotalVotedInVlmgp[msg.sender] += uint256(totalUserVote);
                totalVlMgpInVote += uint256(totalUserVote);

                totalVlMgpInVote -= uint256(-totalUserVote);
            }
        }

        if (userTotalVotedInVlmgp[msg.sender] > getUserVotable(msg.sender))
            revert NotEnoughVote();
    }

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;

        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingTokenDecimals) /
                totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
    }
