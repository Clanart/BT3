### Title
Unchecked `u64` input aggregation permits overflow and signing of invalid Bitcoin transactions - ([File: networks/bitcoin/src/wallet/send.rs](networks/bitcoin/src/wallet/send.rs))

### Summary
`SignableTransaction::new` sums all attacker-controlled `ReceivedOutput` values with `sum::<u64>()` without an overflow check. Serialized outputs accepted through `ReceivedOutput::read` can encode arbitrary unsigned 64-bit `TxOut` values. Two impossible values can wrap `input_sat` to a small positive amount, bypassing the solvency check and producing a FROST-signable transaction whose claimed inputs do not exist on Bitcoin.

### Finding Description
`ReceivedOutput::read` accepts a scalar offset, consensus-decoded `TxOut`, and consensus-decoded `OutPoint` from untrusted bytes. [1](#0-0)  `SignableTransaction::new` then calculates `input_sat` as an unchecked `u64` sum of every supplied output value. [2](#0-1) 

The funds check compares that potentially wrapped total against `payment_sat + needed_fee`. [3](#0-2)  `payment_sat` and `fee_per_vbyte * vbytes` are also unchecked `u64` operations. [4](#0-3) 

The resulting `SignableTransaction` retains the supplied outputs as `prevouts` and creates a transaction spending their outpoints. [5](#0-4)  `multisig` only checks that each offset-adjusted group key corresponds to the supplied prevout script; it does not establish that the prevout exists or has the encoded value. [6](#0-5)  Signing commits to the supplied prevouts through `Prevouts::All` and produces signatures for the malformed transaction. [7](#0-6) 

### Impact Explanation
An attacker who can supply serialized `ReceivedOutput` values can cause a threshold signer to authorize a transaction committing to fabricated Bitcoin input values. In release builds, wrapping arithmetic can make two impossible outputs appear to provide a modest valid balance, causing the transaction-construction logic to accept a spend it should reject.

The completed transaction is not validly spendable on Bitcoin because its encoded input values cannot correspond to real outputs. The security impact is therefore unauthorized threshold signing of an unintended transaction and loss of liveness/signing capacity, rather than direct theft of existing UTXOs.

### Likelihood Explanation
The vulnerable path is reachable wherever untrusted serialized outputs are fed to `ReceivedOutput::read` and subsequently passed to `SignableTransaction::new`. [1](#0-0)  Triggering it requires control of the encoded output values and a script that passes the later key/script check; it does not require compromising a validator or learning secret shares.

The attack depends on release-style wrapping integer semantics. In debug builds or configurations with overflow checks enabled, the unchecked sums panic instead of producing the malformed signable transaction.

### Recommendation
Use checked arithmetic for every amount accounting step:

```rust
let input_sat = inputs
  .iter()
  .try_fold(0u64, |sum, input| sum.checked_add(input.output.value.to_sat()))
  .ok_or(TransactionError::AmountOverflow)?;

let payment_sat = payments
  .iter()
  .try_fold(0u64, |sum, payment| sum.checked_add(payment.1))
  .ok_or(TransactionError::AmountOverflow)?;

let needed_fee = fee_per_vbyte
  .checked_mul(vbytes)
  .ok_or(TransactionError::AmountOverflow)?;

let required = payment_sat
  .checked_add(needed_fee)
  .ok_or(TransactionError::AmountOverflow)?;
```

Apply the same pattern at `networks/bitcoin/src/wallet/send.rs:228`, where `payment_sat + fee_with_change` remains unchecked. Reject decoded `TxOut` values exceeding Bitcoin's maximum money supply before constructing `ReceivedOutput`, and add a regression test with two serialized outputs whose values sum past `u64::MAX`.

### Proof of Concept

```rust
// Conceptual reproduction against networks/bitcoin.

// ReceivedOutput::read layout:
//   32-byte scalar offset
//   consensus TxOut:
//     8-byte little-endian value
//     compact-size script length
//     script bytes
//   consensus OutPoint:
//     32-byte txid
//     4-byte little-endian vout

let script = p2tr_script_buf(group_key).unwrap();

let encoded_a = received_output_bytes(
    Scalar::ZERO,
    u64::MAX - 10_000,
    script.clone(),
    outpoint_a,
);

let encoded_b = received_output_bytes(
    Scalar::ZERO,
    20_000,
    script,
    outpoint_b,
);

let a = ReceivedOutput::read(&mut encoded_a.as_slice()).unwrap();
let b = ReceivedOutput::read(&mut encoded_b.as_slice()).unwrap();

// u64::MAX - 10_000 + 20_000 wraps to 9_999.
let tx = SignableTransaction::new(
    vec![a, b],
    &[(destination_script, 546)],
    None,
    None,
    fee_rate,
).unwrap();

// The threshold machines accept the fake prevouts if the supplied
// scripts correspond to their offset-adjusted group keys.
let signed = complete_threshold_signing(tx);
assert_eq!(signed.input.len(), 2);
```

The two fabricated prevout values exceed any valid Bitcoin UTXO and collectively wrap `input_sat`, while the resulting transaction still reaches per-input Taproot sighash generation. [8](#0-7)
