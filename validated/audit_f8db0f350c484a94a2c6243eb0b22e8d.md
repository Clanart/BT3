### Title
Bank Precompile `sendNative` Bypasses `SendEnabled` Governance Control - (File: precompiles/bank/bank.go)

### Summary
The `x/bank` module lets governance disable transfers of the native `usei` denom via the `DefaultSendEnabled`/`SendEnabled` params, enforced only inside `msgServer.Send`/`MultiSend`. The EVM `sendNative` precompile method transfers native usei/wei directly through `BankKeeper.SendCoinsAndWei` without going through the bank `MsgServer`, so the `SendEnabled` check is never performed for EVM-originated native transfers.

### Finding Description
`msgServer.Send` explicitly gates transfers with `k.IsSendEnabledCoins(ctx, msg.Amount...)` before calling `k.SendCoins` [1](#0-0) . However, `BaseSendKeeper.SendCoinsAndWei` (used for the usei/wei bridge) performs no such check anywhere in its body [2](#0-1) . The `bank` precompile's `sendNative` method converts EVM `value` into usei/wei and calls `p.bankKeeper.SendCoinsAndWei(ctx, senderSeiAddr, receiverSeiAddr, usei, wei)` directly, with no `IsSendEnabledCoins` check anywhere in the precompile file [3](#0-2) . This mirrors the reported bug pattern: an admin/governance-controlled `enabled` flag (`is_staking_enabled` in the analog) exists but is only enforced on one code path (the msg-server `Send`), while a second reachable path (the EVM `sendNative` precompile) performs the same fund-moving effect and omits the flag check entirely.

By contrast, the ordinary EVM ERC20 `send` precompile method does route through `p.bankMsgServer.Send(...)` [4](#0-3) , so only the `sendNative` (native usei value-transfer / `msg.value`) path is affected.

### Impact Explanation
If governance ever disables sending of the base denom (`usei`) — e.g., during an incident response, an exploit mitigation, or a compliance freeze enacted via a `SendEnabled` param change proposal — any EVM transaction that sends native value (a plain `value`-carrying call to the `0x1001` bank precompile, or any contract using `sendNative`) would still succeed and move funds, defeating the governance-enforced freeze. This is a fund-transfer control bypass: value that governance intended to be frozen/blocked continues to move via the EVM entry point, which qualifies as unauthorized transfer / fund-loss-adjacent impact under the freeze scenario.

### Likelihood Explanation
Reachable by any unprivileged EVM caller — no special permissions are required to call the `sendNative` method on the bank precompile with non-zero `msg.value`. The only precondition is that a chain governance proposal has disabled sending of `usei` (or the default is disabled), which is an intended, reachable operational control, not an attacker-controlled state.

### Recommendation
Add an `IsSendEnabledCoins` (or equivalent) check for `sdk.MustGetBaseDenom()` inside `sendNative` in `precompiles/bank/bank.go` before invoking `SendCoinsAndWei`, mirroring the check performed in `msgServer.Send`. Alternatively, move the `IsSendEnabledCoins` check into `BaseSendKeeper.SendCoinsAndWei`/`SendCoins` itself so all callers (msg server and precompiles alike) are protected uniformly.

### Proof of Concept
1. Governance passes a param-change proposal setting `DefaultSendEnabled = false` (or explicitly disabling `usei` in `SendEnabled`).
2. A user calls the bank precompile's `sendNative(receiver)` method at `0x0000000000000000000000000000000000001001` with non-zero `msg.value`.
3. `PrecompileExecutor.sendNative` computes `usei`/`wei` via `HandlePaymentUseiWei` and calls `p.bankKeeper.SendCoinsAndWei(ctx, senderSeiAddr, receiverSeiAddr, usei, wei)` directly [3](#0-2) .
4. Because `SendCoinsAndWei` never calls `IsSendEnabledCoins`, the transfer succeeds despite `SendEnabled` being false, while an equivalent Cosmos-side `MsgSend` for the same denom would be rejected by `msgServer.Send` [1](#0-0) .

func (k BaseSendKeeper) SendCoinsAndWei(ctx sdk.Context, from sdk.AccAddress, to sdk.AccAddress, amt sdk.Int, wei sdk.Int) error {
	if err := k.SubWei(ctx, from, wei); err != nil {
		return err
	}
	if err := k.AddWei(ctx, to, wei); err != nil {
		return err
	}
	ctx.EventManager().EmitEvents(sdk.Events{
		sdk.NewEvent(
			types.EventTypeWeiTransfer,
			sdk.NewAttribute(types.AttributeKeyRecipient, to.String()),
			sdk.NewAttribute(types.AttributeKeySender, from.String()),
			sdk.NewAttribute(sdk.AttributeKeyAmount, wei.String()),
		),
	})
	if amt.GT(sdk.ZeroInt()) {
		return k.SendCoinsWithoutAccCreation(ctx, from, to, sdk.NewCoins(sdk.NewCoin(sdk.MustGetBaseDenom(), amt)))
	}
	return nil
}
