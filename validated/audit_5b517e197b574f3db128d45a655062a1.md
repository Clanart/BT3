### Title
Unpriced cross-chain bandwidth purchase lets any caller evict a victim app's paid subscriptions via FIFO griefing - (File: `modules/pallets/bandwidth/src/lib.rs`)

### Summary

### Finding Description
`pallet-bandwidth`'s `on_accept` handler processes purchase messages from any registered `BandwidthManager` on any source chain and credits a subscription keyed by `(msg.chain, msg.app)` — fields decoded straight from the attacker-supplied message body, deliberately decoupled from `request.source` to support "sponsorship" (crediting an app on a different chain than the payer): [1](#0-0) 

`push_subscription` appends to a FIFO `SubscriptionList` capped at `MAX_SUBSCRIPTIONS` (1024); once full, it unconditionally evicts index `0` — the oldest entry by insertion time — regardless of its `remaining_bytes` or `expires_at`: [2](#0-1) 

Because `app_chain`/`app` are caller-chosen and any registered manager's `purchase()` call reaches this path, an attacker can target an arbitrary victim `(app_chain, app)` pair they do not own and repeatedly buy the cheapest configured tier (smallest `bytes`/`duration_secs`) to push 1024 low-value entries into the victim's list. Each push evicts the oldest entry first — which, in steady state, is a large, still-live, previously-paid subscription belonging to the legitimate app — destroying paid-for, unconsumed bandwidth (`SubscriptionEvicted.lost_bytes`) that the victim can never reclaim.

This is the direct analog of the esFLUO bug: an unprivileged caller supplies an arbitrary "victim" identity (here, `(app_chain, app)` instead of a `user` address) to a state-mutating entrypoint, and the resulting mutation (FIFO push/evict) silently destroys the victim's existing accounted balance (`remaining_bytes` on a live subscription) rather than the attacker's own.

### Impact Explanation
This is loss of funds/value in production: apps pay real fee-token amounts to `BandwidthManager.purchase()` for guaranteed message-bandwidth allowance over a fixed duration. A griefer can permanently destroy a competitor's or any target's already-paid allowance for the cost of 1024 minimum-tier purchases, causing that app's genuine ISMP messages to be rejected by `BandwidthGate::try_consume` (`GateError::NoAllowance`/`Insufficient`) even though it paid for capacity, effectively a denial-of-service plus stranded/lost payment for the victim — matching the bounty's "logic attacks" / "loss of funds" categories, reachable by any unprivileged EVM caller of the registered manager contract.

### Likelihood Explanation
No privileged role, relayer, or governance action is required — only a call to an already-deployed, registered `BandwidthManager.purchase()` with attacker-chosen `chain`/`app` fields in the payload and payment of the cheapest tier price. The eviction is deterministic FIFO-by-insertion-order, so the attack is reliable and cheap relative to the value destroyed if the victim's subscription was a high-tier, long-duration, mostly-unconsumed purchase.

### Recommendation
Bind eviction to economic value rather than pure insertion order — e.g., evict the entry with the least `remaining_bytes` or soonest `expires_at`, or refuse the push (reject the purchase) once the list is full instead of silently evicting, and/or authenticate that only the app itself (or its designated relayer/manager) may credit its own `(app_chain, app)` bucket rather than allowing arbitrary third parties to target any app.

### Proof of Concept
1. Governance configures `TierOne = { bytes: 1, duration_secs: 1 }` (or any minimal tier) and registers a `BandwidthManager` for some source chain.
2. Victim app buys a large, long-duration subscription for `(EVM-X, victim_app)` via a legitimate `purchase()` call, which appends a subscription with large `remaining_bytes` at the front of an otherwise-empty list.
3. Attacker calls `BandwidthManager.purchase()` 1024 times from any account, each time setting the purchase payload's `chain = EVM-X`, `app = victim_app`, `tier = TierOne`, `months = 1` — the cheapest possible cost.
4. Each purchase reaches `pallet_bandwidth::on_accept` → `push_subscription`; once the list of `victim_app` hits 1024 entries, each subsequent attacker purchase evicts index `0`, i.e., the victim's original large subscription is evicted after enough churn, emitting `SubscriptionEvicted { lost_bytes: <victim's paid allowance> }`.
5. Victim's app now has zero/insufficient live bandwidth despite having paid for it; its subsequent ISMP dispatches fail the `BandwidthGate::try_consume` check in the router (`GateError::NoAllowance`). [3](#0-2)

impl<T: Config> BandwidthGate for Pallet<T> {
	fn try_consume(
		source: &ismp::host::StateMachine,
		app: &[u8],
		bytes: u32,
	) -> Result<(), GateError> {
		let key = AppKey::truncate_from(app.to_vec());
		if Allowlist::<T>::contains_key(source, &key) {
			return Ok(());
		}

		let need: u128 = bytes.into();
		let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();

		let total = pallet::Allowance::<T>::mutate(source, &key, |list| {
			// Sweep expired in-place. Order-preserving.
			list.retain(|s| s.expires_at > now);

			if list.is_empty() {
				return Err(GateError::NoAllowance);
			}

			let total: u128 = list.iter().map(|s| s.remaining_bytes).sum();
			if total < need {
				return Err(GateError::Insufficient { remaining: total, required: need });
			}

			// Drain from the front in insertion order. Once a sub is
			// fully consumed, pop it and continue with the next.
			// `get_mut` defends against a malformed list that satisfies
			// the `total >= need` precheck but is structurally empty;
			// we'd otherwise panic via `list[0]`.
			let mut left = need;
			while left > 0 {
				let Some(head) = list.get_mut(0) else {
					return Err(GateError::NoAllowance);
				};
				let take = head.remaining_bytes.min(left);
				head.remaining_bytes = head.remaining_bytes.saturating_sub(take);
				left = left.saturating_sub(take);
				if head.remaining_bytes == 0 {
					list.remove(0);
				}
			}

			Ok(total)
		})?;

		Self::deposit_event(Event::BandwidthConsumed {
			source: *source,
			app: key,
			bytes: need,
			remaining: total - need,
		});
		Ok(())
	}
