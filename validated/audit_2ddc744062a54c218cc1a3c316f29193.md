### Title
Homoglyph colon in `action: block` line is silently dropped by `extract_frontmatter`, causing enforcement to default to `warn` - ([File: plugins/hookify/core/config_loader.py])

### Summary
`extract_frontmatter` decides whether a line is a top-level YAML key only by testing literal ASCII `':' in line` and `line.strip().startswith('-')`. If the colon in an `action: block` line is replaced with a visually identical Unicode homoglyph (e.g. fullwidth colon U+FF1A `：`), the line fails every branch of the parser and is silently skipped, so the `action` key never enters the returned `frontmatter` dict. `Rule.from_dict` then falls back to its default `action = "warn"`, meaning a rule file that visually reads as enforcing `block` is actually loaded as a non-blocking `warn` rule.

### Finding Description
`extract_frontmatter` classifies a line as a top-level key/value pair with: [1](#0-0) 
The check `indent == 0 and ':' in line` uses the ASCII colon literal. A line such as `action：block` (using U+FF1A FULLWIDTH COLON, which renders visually almost identically to `:` in most fonts/terminals) does not contain the ASCII `:` character, so it fails this condition. It also does not start with `-`, and indent is `0` so it does not satisfy the dict-item-continuation branch either (`indent > 2`). The line is therefore silently dropped without error.

Downstream, `Rule.from_dict` reads the action with a default: [2](#0-1) 
Since `frontmatter` never contains the key `action`, `frontmatter.get('action', 'warn')` resolves to `'warn'` instead of the intended `'block'`. `load_rule_file` calls `extract_frontmatter` then `Rule.from_dict` directly, with no cross-check that the raw text visually promised blocking behavior: [3](#0-2) 
`load_rules` loads all such files with no additional validation before using `rule.action` for enforcement decisions elsewhere in the hookify hook logic. No exception is raised anywhere in this path, so this is a pure silent-downgrade bug, not a crash.

### Impact Explanation
A `.claude/hookify.*.local.md` rule file that a human reviewer (or automated diff review) reads as unambiguously blocking a dangerous command (`action: block`) can be crafted with a homoglyph colon so that the parser actually loads it as `action: warn`. This lets an attacker who can contribute or modify rule files (e.g. via a PR merged by a maintainer who visually reviews the diff) stealthily disable a blocking security control repo-wide while the source text still appears to enforce blocking — a classic "Trojan-Source"-style review-evasion bypass of the hookify enforcement mechanism.

### Likelihood Explanation
Exploitation only requires the ability to place or modify a rule file under `.claude/` with content containing a single substituted Unicode character that is visually indistinguishable from `:` in common editors/diff viewers — a low-effort, fully repeatable manipulation with no crash risk, making the bug hard to catch in code review and easy to reproduce deterministically.

### Recommendation
Normalize/validate frontmatter lines against a restricted ASCII character set (or explicitly reject/flag non-ASCII confusable punctuation in structural positions like `:` and `-`) before parsing; alternatively replace the hand-rolled parser with a real YAML parser (e.g. `yaml.safe_load`) that treats malformed/lookalike delimiters as parse errors rather than silently skipping the line, and fail closed (reject the rule file) rather than defaulting `action` to `"warn"` when frontmatter parsing yields no recognized keys for lines that contain colon-like characters.

### Proof of Concept

def load_rule_file(file_path: str) -> Optional[Rule]:
    """Load a single rule file.

    Returns:
        Rule object or None if file is invalid.
    """
    try:
        with open(file_path, 'r') as f:
            content = f.read()

        frontmatter, message = extract_frontmatter(content)

        if not frontmatter:
            print(f"Warning: {file_path} missing YAML frontmatter (must start with ---)", file=sys.stderr)
            return None

        rule = Rule.from_dict(frontmatter, message)
        return rule
