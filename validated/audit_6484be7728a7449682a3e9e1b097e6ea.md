## Title
`isGitHubHost` trusts an unexpired, unauthenticated `x-github-enterprise-version` cache to permanently classify a remote host as GitHub Enterprise - ([File: app/src/lib/endpoint-capabilities.ts])

### Summary
The wstETH oracle bug is "accept a price at face value without checking `updatedAt` freshness." The direct Desktop analog is `getEndpointVersion()` in `app/src/lib/endpoint-capabilities.ts`, which is used by `isGitHubHost()` in `app/src/lib/api.ts` as a fast-path trust signal. Once any HTTP response from a host has ever contained an `x-github-enterprise-version` header, the parsed version is cached in an in-memory `Map` and mirrored into `localStorage` with **no timestamp, no TTL, and no re-validation** — exactly the missing "freshness" check from the oracle finding, applied to a security-relevant host-identity decision instead of a price feed. [1](#0-0) [2](#0-1) 

### Finding Description
`getEndpointVersion(endpoint)` looks the value up in `versionCache`, falling back to `localStorage.getItem(key)` — a value that persists indefinitely across app restarts and network changes, with no `updatedAt`/expiry check analogous to the oracle's `updatedAt`. [3](#0-2) 

`isGitHubHost()` in `app/src/lib/api.ts` uses the mere presence of a cached version as a shortcut to skip the actual live discovery probe:
```
if (getEndpointVersion(endpoint) !== null) {
  return true
}
``` [4](#0-3) 

`updateEndpointVersion` is invoked from `tryUpdateEndpointVersionFromResponse`, which reads the `x-github-enterprise-version` header off arbitrary HTTP responses (including the very "discovery" request made inside `isGitHubHost` itself) and writes it into the permanent cache without recording *when* it was observed: [5](#0-4) [6](#0-5) 

This cached "is-GitHub" belief is then consumed by the trampoline git-credential-helper to decide how to treat a remote host for the purposes of credential handling: [7](#0-6) 

If `getEndpointKind` resolves to `'enterprise'`/`'github.com'` and no signed-in account matches that endpoint, Desktop actively prompts the user to sign in via GitHub OAuth for that host instead of treating it as a generic git credential target: [8](#0-7) 

The broken invariant: a single, unauthenticated, non-expiring header observation is treated as permanent proof that a host is (or remains) a legitimate GitHub Enterprise instance — with no re-check for staleness, no re-verification when the host's IP/ownership could have changed (dynamic DNS, decommissioned GHES box repurposed, DNS takeover, MITM proxy that stripped/forged the header once), and no revocation path exposed to the user. This mirrors the oracle bug precisely: a value is consumed at face value forever, without checking when it was last confirmed accurate.

### Impact Explanation
Because the classification flips the credential-handling path from "generic" (prompt for a normal username/password, or use OS credential manager for any host) to "GitHub/enterprise" (prompt for GitHub OAuth sign-in), an attacker who can get one response with a spoofed `x-github-enterprise-version` header past Desktop for a given hostname (e.g. a compromised/rotated domain, a corporate proxy that used to sit in front of a real GHES box and is now repurposed, or an attacker-controlled server the header is trivially attacker-controlled since it's just an HTTP response header) can cause that hostname to be durably (across restarts, indefinitely) treated as a trusted GitHub Enterprise endpoint. This routes future git operations against that host through GitHub Desktop's OAuth sign-in prompt for what the user believes is an enterprise GitHub instance, and gates the app's differing credential-handling logic (`getEndpointKind` -> `enterprise`) rather than the safer generic-credential path. This is an unauthorized/incorrect host-trust decision driven purely by a stale, unauthenticated cache entry — a "silent corruption" of a security decision Desktop makes without user awareness or a real-time recheck.

### Likelihood Explanation
Medium-low but concrete: exploitation requires the attacker to control (or have controlled, even transiently) an HTTP(S) endpoint that Desktop probes and to have it emit the `x-github-enterprise-version` header once. This is realistic for scenarios such as domains that are later re-pointed, DNS-takeover of a decommissioned internal GHES hostname, or an on-path proxy for enterprise users. No local access, no admin rights, and no leaked credentials are required — only a single crafted/observed HTTP response, matching the "no-privilege attacker controlling a remote/proxy response" criterion.

### Recommendation
Store a timestamp alongside the cached version (both in the in-memory `versionCache`/`rawVersionCache` and in `localStorage`), and enforce a bounded freshness window (e.g., re-validate after N hours/days) before `isGitHubHost` or `endpointSatisfies` trust the cached value. Do not let `getEndpointVersion(endpoint) !== null` alone short-circuit `isGitHubHost`; require a recent successful discovery response, and clear/expire entries when they age out, exactly as the wstETH fix recommends checking `updatedAt` before trusting an oracle price.

### Proof of Concept
1. Attacker controls (or briefly compromises/mediates) `https://legacy-ghes.example.com`, an endpoint the victim's Desktop has previously (or is currently) probing (e.g., via `isGitHubHost` discovery fetch to `/meta`, or any other API call routed through `tryUpdateEndpointVersionFromResponse`).
2. The response includes a forged `x-github-enterprise-version: 3.9.0` header. `updateEndpointVersion('https://legacy-ghes.example.com', '3.9.0')` persists this into `localStorage` under key `endpoint-version:https://legacy-ghes.example.com` — permanently, with no timestamp. [9](#0-8) 
3. Domain ownership/routing later changes (DNS takeover, repurposed box, or MITM removed). The header will never be sent again by the real current owner of the host.
4. Weeks/months later, the user adds a git remote pointing at that same hostname, or Desktop's trampoline credential helper is invoked for a request to that host. `isGitHubHost` short-circuits to `true` purely because `getEndpointVersion(...)` still returns the stale, months-old cached SemVer — the live "x-github-request-id" verification network probe is skipped entirely. [4](#0-3) 
5. `getEndpointKind` in the credential helper classifies the host as `'enterprise'`, and since no matching signed-in account exists, `getCredential` triggers `ui.promptForGitHubSignIn(endpoint)`, presenting the user with a GitHub Enterprise sign-in flow for a host that is, in present reality, no longer verified to be a genuine GitHub instance. [10](#0-9) 

**Uncertainty:** I could not fully trace, within the available index, every call site in `app/src/lib/api.ts` that invokes `tryUpdateEndpointVersionFromResponse` (grep found 6 matches in that file but I was only able to view the two most relevant snippets), so I cannot confirm the complete set of HTTP request paths (e.g., whether truly arbitrary/generic non-GitHub-classified hosts pass through this code, or only hosts already believed to be enterprise). This affects precise likelihood but not the core finding: the cache itself is confirmed to have no freshness/expiry field, and `isGitHubHost` is confirmed to trust it unconditionally. A Devin session with full file access would be needed to enumerate every caller of `tryUpdateEndpointVersionFromResponse`/`updateEndpointVersion` to fully bound the attack surface.

export function getEndpointVersion(endpoint: string) {
  const key = endpointVersionKey(endpoint)
  const cached = versionCache.get(key)

  if (cached !== undefined) {
    return cached
  }

  const raw = localStorage.getItem(key)
  const parsed = raw === null ? null : semver.parse(raw)

  if (parsed !== null) {
    versionCache.set(key, parsed)
  }

  return parsed
}

/**
 * Update the known version number for a given endpoint
 */
export function updateEndpointVersion(endpoint: string, version: string) {
  const key = endpointVersionKey(endpoint)

  if (rawVersionCache.get(key) !== version) {
    const parsed = semver.parse(version)
    localStorage.setItem(key, version)
    rawVersionCache.set(key, version)
    versionCache.set(key, parsed)
  }
}

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
