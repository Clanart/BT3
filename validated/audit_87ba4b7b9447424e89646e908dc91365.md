## Analysis

Reducing the external report to its core broken invariant: **a success path pays out value but fails to clear the state record that permits a second, different payout path to fire on the same commitment.** In the liquidation bug, `_userInfo.liquidated` should have been flipped after a successful liquidation to block a second liquidation. The Hyperbridge analog is in the EVM GET-request fee lifecycle: on a successful `GetResponse` delivery, the relayer fee is paid out of `_requestCommitments[commitment]`, but that record is never deleted — leaving it available for the GET-timeout path to pay out the *same* fee a second time to a different party.

### Title
Unset `_requestCommitments` entry after a successful GET response allows the same relayer fee to be paid twice (response relayer + timeout refund) - ([File: evm/src/core/EvmHost.sol])

### Summary
`EvmHost.dispatchIncoming(GetResponse, address)` pays the relayer fee from `_requestCommitments[commitment].fee` on successful delivery of a `GetResponse`, but never deletes/clears `_requestCommitments[commitment]` afterward. `EvmHost.dispatchTimeOut(GetRequestTimeout, ...)` independently reads the same `_requestCommitments[commitment]` and refunds `meta.fee` to `meta.sender` whenever a caller can produce a non-membership proof, at a height of their choosing, that `_responseReceipts[commitment]` was unset. Because old state-machine heights remain queryable in `_stateCommitments` indefinitely, a relayer/attacker can supply an early height (before the response was recorded) to satisfy the timeout's non-membership check even though the response was already delivered and paid for at a later height, causing the same escrowed fee to be paid out twice.

### Finding Description
- On successful `GetResponse` delivery: [1](#0-0) . The fee is transferred to `relayer` from `_requestCommitments[commitment].fee`, but the `_requestCommitments[commitment]` entry is left untouched — contrast this with the POST/GET timeout handlers, which explicitly `delete _requestCommitments[commitment]` for replay protection: [2](#0-1) .
- `handleGetResponses` in the handler contract performs no local timeout check at all, deferring entirely to Hyperbridge: [3](#0-2) .
- `handleGetRequestTimeouts` re-reads the same `_requestCommitments[commitment]` (`meta.sender == address(0)` gate) and only requires a non-membership proof of `_responseReceipts[commitment]` at a *caller-chosen* historical height: [4](#0-3) . It then calls `dispatchTimeOut`, which refunds `meta.fee` to `meta.sender` on success: [5](#0-4) .
- Historical state commitments for a state machine are stored per-height and are not pruned as new heights arrive: [6](#0-5) , so a proof against an *older* height (recorded before the response was delivered) remains available to satisfy the non-membership check even after the response has already been paid for.

Because `_requestCommitments[commitment]` is never cleared on the successful-response path, the fee metadata (`sender`, `fee`) it holds remains valid input for a *second*, independent payout: the timeout refund. The two guards (`_responseReceipts` non-membership proof and `_requestCommitments` presence) are checked against two different, decoupled facts — a caller-selected historical height vs. a persistent, never-invalidated fee record — so neither guard is aware of the other payout having already occurred.

### Impact Explanation
This is a direct loss-of-funds bug in the bridge's fee-escrow logic: the same `feeToken` amount escrowed for one GET request can be released twice — once to the relayer that delivered the `GetResponse`, and again refunded to the original `sender` via a timeout claim built against an earlier, pre-response state commitment. This drains the host's fee-token balance beyond what was ever collected for that request, harming either the protocol's fee reserves or other users' pending fee balances that share the same pool. It requires no relayer/prover/admin collusion — an ordinary permissionless caller of `handleGetRequestTimeouts` with a legitimate historical proof can trigger it.

### Likelihood Explanation
Likelihood is moderate to high wherever GET requests are used with non-trivial fees and consensus updates are pushed at multiple heights before a response lands (a routine occurrence, since consensus/BEEFY updates run independently of application-level GET/response traffic). Any actor who can construct a valid non-membership proof against an already-committed, older height — a state commitment Hyperbridge stores and preserves — can trigger the double payout without needing to influence delivery ordering or any privileged role.

### Recommendation
Delete (or otherwise permanently invalidate, e.g. zero out the `fee` field and mark consumed) `_requestCommitments[commitment]` in `dispatchIncoming(GetResponse, address)` immediately after a successful `onGetResponse` callback, mirroring what `dispatchTimeOut` already does for replay protection. Additionally, `handleGetRequestTimeouts`/`dispatchTimeOut` for GET requests should reject timeouts if `_responseReceipts[commitment]` is set *at the current/latest known state*, not merely absent at an arbitrary caller-chosen historical height, or require the proof height to be the *latest* available commitment for that state machine.

### Proof of Concept
1. User dispatches a `GetRequest` on chain A with `fee = F`, `sender = S`; `_requestCommitments[commitment] = {sender: S, fee: F}` is recorded on `EvmHost`.
2. Hyperbridge tracks chain A's own state and stores a state commitment at height `H1` (timestamp `t1`), before the response is ever delivered — at `H1`, `_responseReceipts[commitment]` is unset.
3. Later, a relayer `R` submits a valid state proof deriving `GetResponse` and calls `handleGetResponses` → `dispatchIncoming(GetResponse, R)`. `onGetResponse` succeeds; `EvmHost` pays fee `F` to `R` from `_requestCommitments[commitment].fee`; `_requestCommitments[commitment]` is left intact.
4. `request.timeout()` has since elapsed and `t1 > request.timeout()` (chosen at step 2 to already satisfy the timeout condition).
5. Any caller submits `handleGetRequestTimeouts` using height `H1` and a non-membership proof (valid, since at `H1` the receipt genuinely wasn't set yet) → `dispatchTimeOut(GetRequestTimeout, meta, commitment)` refunds `F` to `S`.
6. Net effect: `F` was paid out twice (to `R` and to `S`) for a single escrowed fee `F`, draining the `feeToken` balance held by `EvmHost` by the duplicated amount. [1](#0-0) [5](#0-4) [4](#0-3)

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function handleGetResponses(IHost host, GetResponseMessage calldata message) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(message.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 responsesLength = message.responses.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](responsesLength);

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // don't check for timeouts because it's checked on Hyperbridge

            // known request? also serves as source check
            FeeMetadata memory meta = host.requestCommitments(leaf.response.request.hash());
            if (meta.sender == address(0)) revert UnknownMessage();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.response.hash());
        }

        bytes32 root = host.stateMachineCommitment(message.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, message.proof.multiproof, leaves, message.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // duplicate response?
            if (host.responseReceipts(leaf.response.request.hash()).relayer != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.response, _msgSender());
        }
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
