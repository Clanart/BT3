## Title
Front-runnable permissionless `harvest()` allows diverting protocol fees away from a newly-set fee recipient - (File: `wombat/WombatStaking.sol`)

### Summary
`WombatStaking.harvest()` is a fully permissionless, unprivileged function that anyone can call to trigger harvesting and immediate distribution of protocol fees to the addresses stored in `feeInfos`. Because fee-recipient changes (`setFee`, `addFee`, `removeFee`) are separate owner transactions that take effect only once mined, any wallet can front-run such a change by calling `harvest()` first, forcing all currently-accrued rewards/fees to be flushed to the stale (old) recipient before the new recipient is set.

### Finding Description
`harvest()` has no caller restriction beyond pool state: [1](#0-0) 

It calls `_toMasterWomAndSendReward`, which in turn calls `_sendRewards`, which iterates `feeInfos` and transfers/queues each fee's cut directly to `feeInfo.to`: [2](#0-1) 

The recipient address (`feeInfo.to`) for a given fee slot is only mutable by the owner via `setFee`/`addFee`/`removeFee`: [3](#0-2) 

Because there is no accrual/checkpoint step that segregates "already pending" fees from future ones tied to a specific recipient, any unprivileged address can observe a pending `setFee(...)` transaction in the mempool that changes `feeInfo.to` to a new recipient, and front-run it with a plain `harvest(_lpToken)` call. This forces the entire currently un-distributed WOM/bonus-token reward balance to be fee-swept and sent to the *old* `feeInfo.to` before the owner's update lands, so the new recipient receives nothing for that harvest cycle.

### Impact Explanation
This diverts protocol fee revenue that was intended for the new fee recipient to the old one, permanently (the funds are transferred out immediately via `safeTransfer`/`queueNewRewards`, not merely accounted for). This is a direct, irreversible misdirection of protocol yield/fees, matching a "theft or permanent freezing of unclaimed yield" impact — the new recipient permanently loses that batch of fees with no recovery path.

### Likelihood Explanation
`harvest()` is callable by literally any wallet with no access control (only requires the target pool be active and the contract unpaused), and calling it is cheap. Any address monitoring the mempool for the owner's `setFee`/`addFee`/`removeFee` calls can trivially front-run with a `harvest()` call, so likelihood of exploitation whenever a fee-recipient rotation occurs is high.

### Recommendation
- Snapshot/settle pending fees for the current recipient before allowing a fee-recipient change (e.g., force an internal harvest/flush as part of `setFee`/`removeFee` itself, atomically, before switching `feeInfo.to`), or
- Accrue fees into a per-recipient claimable balance instead of push-transferring on every harvest, so a recipient change cannot silently redirect already-accrued-but-unclaimed amounts.

### Proof of Concept
1. Owner submits a transaction calling `setFee(index, value, newRecipient, ...)` to rotate the recipient of a fee slot from `oldRecipient` to `newRecipient`.
2. An attacker observes this pending transaction in the mempool and submits `harvest(_lpToken)` with higher gas, which executes first.
3. `harvest` → `_toMasterWomAndSendReward` → `_sendRewards` computes `feeAmount` from the currently accrued WOM rewards and transfers it to `feeInfo.to`, which is still `oldRecipient` at this point.
4. The owner's `setFee` transaction then executes, updating `feeInfo.to` to `newRecipient`, but the fees for that harvest cycle have already been irreversibly sent to `oldRecipient`.

    /// @dev the value must be between the min and the max specified when registering the fee
    /// @dev the value must match the max fee requirements
    /// @param _index the index of the fee in the fee list
    /// @param _value the new value of the fee
    function setFee(uint256 _index, uint256 _value, address _to,
        bool _isMWOM, bool _isAddress, bool _isActive) external onlyOwner {
        if (_value >= DENOMINATOR)
            revert InvalidFee();        

        Fees storage fee = feeInfos[_index];
        fee.to = _to;
        fee.isMWOM = _isMWOM;
        fee.isAddress = _isAddress;
        fee.isActive = _isActive;

        totalFee = totalFee - fee.value + _value;
        fee.value = _value;

        emit SetFee(fee.to, _value);
    }

    /// @param _rewardToken the address of the reward token to send
    /// @param _rewarder the rewarder that will get the rewards
    /// @param _amount the initial amount of rewards after harvest

    function _sendRewards(
        address _lpToken,
        address _rewardToken,
        address _rewarder,
        uint256 _amount
    ) internal {
        if (_amount == 0) return;
        uint256 originalRewardAmount = _amount;

        if (!isPoolFeeFree[_lpToken]) {
            for (uint256 i = 0; i < feeInfos.length; i++) {
                Fees storage feeInfo = feeInfos[i];

                if (feeInfo.isActive) {
                    address rewardToken = _rewardToken;
                    uint256 feeAmount = (originalRewardAmount * feeInfo.value) / DENOMINATOR;
                    _amount -= feeAmount;
                    uint256 feeTosend = feeAmount;

                    if (feeInfo.isMWOM && rewardToken == wom) {
                        if (smartWomConverter != address(0)) {
                            IERC20(wom).safeApprove(smartWomConverter, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IConverter(smartWomConverter).smartConvert(feeAmount, 0);
                            rewardToken = mWom;
                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
                        } else {
                            IERC20(wom).safeApprove(mWom, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IMWom(mWom).deposit(feeAmount);
                            rewardToken = mWom;
                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
                        }
                    }

                    if (!feeInfo.isAddress) {
                        IERC20(rewardToken).safeApprove(feeInfo.to, 0);
                        IERC20(rewardToken).safeApprove(feeInfo.to, feeTosend);
                        IBaseRewardPool(feeInfo.to).queueNewRewards(feeTosend, rewardToken);
                    } else {
                        IERC20(rewardToken).safeTransfer(feeInfo.to, feeTosend);
                        emit RewardPaidTo(feeInfo.to, rewardToken, feeTosend);
                    }
                }
            }
        }
