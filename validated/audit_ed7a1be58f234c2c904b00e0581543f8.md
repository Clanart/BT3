### Title
Untrusted `ReceivedOutput` deserialization accepts inconsistent offset/script pairs, causing deposits to be attributed to unspendable keys - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
`ReceivedOutput::read` deserializes an offset, `TxOut`, and `OutPoint` independently without checking that the output's Taproot script equals the contextual base key plus the serialized offset. [1](#0-0)  Scanner-constructed outputs maintain this invariant by mapping a script to a registered offset. [2](#0-1)  Direct deserialization bypasses that invariant, so hostile bytes can report a Bitcoin output under an incorrect key while making it fail transaction-machine construction. [3](#0-2) [4](#0-3) 

### Finding Description
`ReceivedOutput::read` accepts any canonical secp256k1 scalar as `offset`, any consensus-valid `TxOut`, and any `OutPoint`, then returns the combined object without semantic validation. [1](#0-0)  The legitimate construction path is `Scanner::scan_transaction`, which only creates a `ReceivedOutput` when `output.script_pubkey` is present in the scanner's script-to-offset map. [5](#0-4)  That map is populated only after `register_offset` computes the P2TR script for `key + offset * G`. [6](#0-5)  The deserializer therefore creates objects that cannot arise through scanning: the encoded offset can be changed while retaining the original script and value. [7](#0-6) 

### Impact Explanation
The processor derives the attributed base key as `script_key - offset * G`, so changing the serialized offset changes the multisig key that supposedly received the funds. [3](#0-2)  Its `balance()` still reports the attacker-selected `TxOut` value. [8](#0-7)  When the transaction is subsequently constructed, `SignableTransaction::multisig` checks that `keys.offset(offset).group_key()` produces the previous output's script and returns `None` when it does not. [4](#0-3)  Thus a forged serialized deposit can be reported as received under a Serai-controlled-looking output record while being unusable by the corresponding threshold keys. [7](#0-6) 

### Likelihood Explanation
This requires an untrusted party to supply or alter serialized `ReceivedOutput`/`Output` bytes rather than merely broadcasting a Bitcoin transaction. [9](#0-8)  The attack does not require solving a discrete logarithm because mutating the offset immediately creates an inconsistent script/key relationship. [3](#0-2)  The exploitability boundary is narrower than direct chain scanning because the normal scanner already enforces the script-to-offset invariant. [5](#0-4) 

### Recommendation
Do not expose `ReceivedOutput::read` as a context-free trusted constructor; either require the expected base key and verify `p2tr_script_buf(base_key + offset * G) == output.script_pubkey`, or restrict this deserializer to internally generated scanner output. [2](#0-1)  `processor::networks::bitcoin::Output::read` should additionally reject non-P2TR scripts, malformed SCALE values, and output kinds inconsistent with the contextual scanner registration rather than accepting or unwrapping decoded fields. [9](#0-8) 

### Proof of Concept
```rust
// ReceivedOutput::serialize writes: offset || TxOut || OutPoint.
let mut encoded = received_from_scanner.serialize();

// A scanner-produced zero-offset output can be changed to offset 1 while
// preserving the original P2TR script and value.
encoded[.. 32].copy_from_slice(&Scalar::ONE.to_bytes());
let forged = ReceivedOutput::read(&mut encoded.as_slice()).unwrap();

// The processor now derives base_key - G instead of base_key.
assert_ne!(forged.key(), original.key());
assert_eq!(forged.value(), original.value());

// Transaction signing rejects it because key + 1*G no longer matches the
// unchanged script_pubkey, leaving the reported output unspendable.
assert!(signable.multisig(&threshold_keys).is_none());
```
The first mutation succeeds because `read` has no consistency check, while `multisig` later performs the missing script/key comparison and refuses to build a signing machine. [7](#0-6) [4](#0-3)

  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  /// Write a ReceivedOutput to a generic satisfying Write.
  pub fn write<W: Write>(&self, w: &mut W) -> io::Result<()> {

    w.write_all(&serialize(&self.outpoint))
  }

    let mut res = Vec::new();

  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }
