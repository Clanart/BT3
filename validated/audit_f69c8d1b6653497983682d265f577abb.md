### Title
Cross-Program Invocation signer-PDA derivation via `translate_signers` is not separately CU-metered, allowing SHA256 hashing work to be amplified far beyond the flat `invoke_units` charge - (File: `program-runtime/src/cpi.rs`)

### Summary
`cpi_common` charges only the flat `invoke_units` cost (946 CU by default) per CPI call and then calls `translate_signers`, which performs one `Pubkey::create_program_address` (SHA256-based) hash per signer-seed-set, each with up to `MAX_SEEDS` seeds. Unlike the standalone `sol_create_program_address`/`sol_try_find_program_address` syscalls, which explicitly charge `create_program_address_units` (1500 CU) per hash, this internal signer-derivation path is not metered at all beyond the flat CPI charge.

### Finding Description
`cpi_common` in `program-runtime/src/cpi.rs` consumes the flat `invoke_units` cost once per CPI: [1](#0-0) 
and then calls `translate_signers`, which is fully attacker controlled via `signers_seeds_addr`/`signers_seeds_len`: [2](#0-1) 

`translate_signers` iterates over up to `MAX_SIGNERS` signer-seed-sets, and for each set calls `Pubkey::create_program_address` (a SHA256-based PDA derivation) over up to `MAX_SEEDS` seeds: [3](#0-2) 

No additional compute is consumed for this loop of hashing operations - the only charge paid for the entire CPI (including however many `create_program_address` calls are triggered by the signer seeds) is the single flat `invoke_units` amount consumed before `translate_signers` is even invoked.

Contrast this with the explicit `sol_create_program_address` syscall, which charges `create_program_address_units` (1500 CU) for a *single* hash operation: [4](#0-3) 

An attacker deploying arbitrary sBPF bytecode can invoke CPI (`sol_invoke_signed`) repeatedly, each time supplying `MAX_SIGNERS` signer-seed-sets, each with `MAX_SEEDS` seeds of up to `MAX_SEED_LEN` bytes, forcing the runtime to perform up to `MAX_SIGNERS` SHA256-based PDA derivations per CPI call while paying only the flat `invoke_units` cost (946 CU), which is less than even one `create_program_address_units` charge (1500 CU) that the same underlying operation costs when invoked via the direct syscall.

### Impact Explanation
This is a case of materially underpriced compute: the actual SHA256 hashing work performed inside `translate_signers` during CPI signer verification scales with `MAX_SIGNERS × MAX_SEEDS × MAX_SEED_LEN` per call, but the CU charge (`invoke_units`, flat 946) does not scale with any of these attacker-controlled parameters. Repeated/looped CPI calls (bounded only by the overall compute budget of `MAX_COMPUTE_UNIT_LIMIT` = 1,400,000 and `invoke_units` per call) let an attacker force far more real SHA256 hashing work per unit of paid compute than the explicit `create_program_address_units`-priced syscall would allow for equivalent hashing, which can distort validator execution-time-per-CU assumptions used for block packing and could be leveraged to slow down transaction/block processing relative to declared CU cost.

### Likelihood Explanation
Fully attacker-controlled and requires no privileges: an unprivileged program can call `sol_invoke_signed` with maximal `signers_seeds_len` (`MAX_SIGNERS`) and maximal per-signer seed counts/lengths (`MAX_SEEDS`, `MAX_SEED_LEN`), repeated in a loop within the transaction's compute budget. No existing guard limits or prices the number of `create_program_address` calls performed inside `translate_signers`; only `MAX_SIGNERS` and `MAX_SEEDS` bound the per-call amplification, and there is no per-hash CU charge as there is for the direct syscall equivalent.

### Recommendation
Charge compute units for each `Pubkey::create_program_address` invocation performed inside `translate_signers` (e.g., `sha256_base_cost + sha256_byte_cost * total_seed_bytes`, or reuse `create_program_address_units` per signer-seed-set), consumed via `invoke_context.compute_meter.consume_checked(...)` before/while iterating signer seeds, so the CPI's total charged cost scales with the number of signer sets and seed bytes actually hashed, matching the pricing model already applied to the standalone `sol_create_program_address`/`sol_try_find_program_address` syscalls.
