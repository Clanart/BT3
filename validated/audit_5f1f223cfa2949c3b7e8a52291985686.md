### Title
Unchecked slice bounds in gzip/wasm magic-byte detection can panic on short/empty CosmWasm bytecode - (File: sei-wasmd/x/wasm/ioutils/utils.go)

### Summary
`IsGzip` and `IsWasm` in `sei-wasmd/x/wasm/ioutils/utils.go` slice the caller-supplied byte buffer (`input[:3]` / `input[:4]`) to compare against magic-byte identifiers, without first checking that `len(input)` is large enough. [1](#0-0) 
This mirrors the CVE-2017-2904 bug class: a file-format loader reads/derefs a fixed-size header region of attacker-controlled input before validating that the input is long enough to contain that header, producing an out-of-bounds access. In Go this manifests as a runtime slice-bounds panic (`slice bounds out of range`) rather than a classic C buffer overflow, since Go bounds-checks slices, but the reachable effect — an unvalidated-length header read on attacker-supplied binary data — is the same root cause.

### Finding Description
`IsGzip`/`IsWasm` are used to sniff whether submitted CosmWasm bytecode is gzip-compressed or a raw wasm binary before further processing (decompression / validation). The functions are called from multiple reachable paths that accept arbitrary caller-supplied byte slices:
- `precompiles/wasmd/wasmd.go` (and its versioned copies under `precompiles/wasmd/legacy/v5xx..v67`), which back the `Wasmd` EVM precompile invoked by any EVM contract/EOA calling into CosmWasm from the EVM side. [2](#0-1) 
- `x/evm/keeper/msg_server.go`, part of the EVM message-handling path for transactions submitted by any user. [3](#0-2) 
- `evmrpc/simulate.go`, part of the public JSON-RPC surface (`eth_call`/simulation), reachable by any unauthenticated RPC client. [4](#0-3) 

If any of these call sites pass through a byte slice shorter than 3 (for `IsGzip`) or 4 (for `IsWasm`) bytes — e.g., an empty byte array, or a 1–3 byte "code" payload — the slicing expression `input[:3]`/`input[:4]` panics with an out-of-range index, because neither function validates `len(input)` first.

### Impact Explanation
A panic triggered inside consensus-critical message processing (store-code / EVM message handling) is normally caught by the Cosmos SDK's `runTx` deferred recover in `BaseApp`, converting it into a failed transaction rather than crashing the node — so on the `MsgStoreCode`/EVM-tx path the primary effect is likely "transaction always reverts/panics-and-recovers" rather than validator halt. However, if the same unguarded call is reached from the public JSON-RPC/query surface (`evmrpc/simulate.go`) outside of a panic-recovering middleware, an unauthenticated RPC client could crash the serving RPC node process by submitting a short/empty byte code payload to a simulate/estimate-gas call path that reaches `IsGzip`/`IsWasm`, satisfying the "crash of default-configuration RPC nodes" impact criterion. I was not able to fully confirm, within the available tool budget, whether `evmrpc/simulate.go`'s call site is wrapped by a recover middleware — this needs direct verification.

### Likelihood Explanation
Triggering this requires only submitting a very short or empty byte array as "code" to any of the reachable entry points (EVM `Wasmd` precompile call, EVM message handling, or RPC simulate/estimate path) — no privileged access, special gas conditions, or complex crafting is needed, making it trivially reachable by any transaction sender or RPC client.

### Recommendation
Add explicit length guards at the top of both functions before slicing, e.g.:
```go
func IsGzip(input []byte) bool {
    return len(input) >= 3 && bytes.Equal(input[:3], gzipIdent)
}

func IsWasm(input []byte) bool {
    return len(input) >= 4 && bytes.Equal(input[:4], wasmIdent)
}
```
Additionally, audit all call sites (`precompiles/wasmd/*`, `x/evm/keeper/msg_server.go`, `evmrpc/simulate.go`, CLI/REST tx builders) to confirm panics from this code path are always caught by a recover boundary before reaching the RPC server's request-handling goroutine, closing the crash vector on the public RPC surface.

### Proof of Concept
1. Craft an EVM transaction (or RPC `eth_call`/simulate request) that routes into the CosmWasm `Wasmd` precompile / `MsgStoreCode` path with a `code` argument of length 0–3 bytes (e.g., `[]byte{}` or `[]byte{0x00}`).
2. The handler calls `ioutils.IsWasm(code)` (or `IsGzip`) to sniff the format before further processing. [5](#0-4) 
3. Because `len(code) < 4`, `input[:4]` panics with `slice bounds out of range [:4] with capacity <4`.
4. Depending on whether the specific call path is behind BaseApp's `runTx` recover or an unguarded RPC handler goroutine, this either aborts just the transaction or crashes the serving node process.
