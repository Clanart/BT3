### Title
Fixed-gas-stipend Ether transfer in the canonical WSEI contract causes permanent freezing of wrapped SEI for contract holders - (File: `contracts/src/WSEI.sol`)

### Summary
The canonical "Wrapped Sei" (WSEI) contract, whose bytecode is compiled and shipped as a first-class chain artifact and deployable via the `seid tx evm deploy-wsei` CLI command, implements `withdraw()` using the legacy `payable(msg.sender).transfer(wad)` pattern, which forwards only a fixed 2300-gas stipend to the receiver.

### Finding Description
`contracts/src/WSEI.sol` defines the WSEI token contract whose compiled bytecode is embedded in the chain binary at `x/evm/artifacts/wsei/WSEI.bin`/`artifacts.go` and can be deployed on-chain via `CmdDeployWSEI` in `x/evm/client/cli/tx.go`. [1](#0-0) 

The `withdraw()` function debits the caller's WSEI balance and then attempts to pay out native SEI using `.transfer()`:
```solidity
function withdraw(uint wad) public {
    require(balanceOf[msg.sender] >= wad);
    balanceOf[msg.sender] -= wad;
    payable(msg.sender).transfer(wad);
    emit Withdrawal(msg.sender, wad);
}
```
`.transfer()` (and `.send()`) hard-code a 2300 gas stipend for the receiver's fallback/`receive()` execution. Since the Istanbul/Berlin gas-repricing changes (e.g., `SLOAD` cost increases under EIP-1884/EIP-2929), 2300 gas is frequently insufficient for any receiving contract that touches storage in its `receive()`/fallback (e.g., emitting events, updating accounting, or forwarding calls), causing the transfer to revert with an out-of-gas error.

Because `balanceOf[msg.sender] -= wad` executes *before* the transfer and there is no alternate/fallback withdrawal mechanism (e.g., a pull-payment pattern or `call{value: ...}` with a `require`), any smart-contract account (a DAO treasury, a Sei EVM pointer contract, a multisig, a DeFi vault, etc.) that unwraps WSEI is permanently unable to retrieve its native SEI: the state has already been debited, and the `.transfer()` call will keep reverting on every retry deterministically, since the gas stipend is fixed regardless of retries.

### Impact Explanation
This meets the "permanent freezing of funds" bar: any smart contract acting as a WSEI holder whose receiving code exceeds 2300 gas will have its wrapped SEI irrecoverably stuck in the WSEI contract — the balance is decremented, but the native value can never be paid out through `withdraw()`, and no alternate exit path exists in the contract. Given WSEI is intended as the canonical wrapped-native-asset contract for the Sei EVM ecosystem (analogous to WETH on Ethereum), this is broadly reachable by any contract-based caller (DeFi protocols, multisigs, pointer/bridge contracts) interacting with WSEI as part of normal usage.

### Likelihood Explanation
Likelihood is high in practice: many production smart contracts (proxies, multisigs, vaults) implement non-trivial `receive()`/fallback logic that costs more than 2300 gas, and Sei's EVM inherits post-Berlin gas costs where 2300 gas is even tighter than pre-Istanbul assumptions. Any unprivileged contract account calling `withdraw()` on WSEI can trigger this permanently, with no privileged access required.

### Recommendation
Replace the `.transfer()` call with the low-level `.call{value: wad}("")` pattern combined with a `require(success, ...)` check, and follow checks-effects-interactions with reentrancy protection if needed:
```solidity
(bool success, ) = payable(msg.sender).call{value: wad}("");
require(success, "WSEI: ETH transfer failed");
```
This removes the fixed 2300-gas stipend limitation and prevents permanent balance lock-up for contract-based holders.

### Proof of Concept
1. Deploy a helper contract `Locker` whose `receive()` function writes to a storage slot (e.g., increments a counter) — any operation costing more than 2300 gas.
2. From `Locker`, call `WSEI.deposit{value: X}()` to wrap SEI, receiving `X` WSEI.
3. From `Locker`, call `WSEI.withdraw(X)`.
4. Observe: `balanceOf[Locker] -= X` executes, but `payable(msg.sender).transfer(X)` reverts due to out-of-gas in `Locker.receive()`, reverting the whole transaction (so balance is restored) — but every subsequent retry deterministically reverts the same way, since it will always cost the same gas in `receive()`; the WSEI held by `Locker` can never be withdrawn, permanently locking `X` SEI's worth of value inside the WSEI contract for that address. package wsei

import (
	"embed"
	"encoding/hex"
	"strings"

	"github.com/ethereum/go-ethereum/accounts/abi"
)

const CurrentVersion uint16 = 1

//go:embed WSEI.abi
//go:embed WSEI.bin
var f embed.FS

var cachedBin []byte
var cachedABI *abi.ABI

func GetABI() []byte {
	bz, err := f.ReadFile("WSEI.abi")
	if err != nil {
		panic("failed to read WSEI contract ABI")
	}
	return bz
}

func GetParsedABI() *abi.ABI {
	if cachedABI != nil {
		return cachedABI
	}
	parsedABI, err := abi.JSON(strings.NewReader(string(GetABI())))
	if err != nil {
		panic(err)
	}
	cachedABI = &parsedABI
	return cachedABI
}

func GetBin() []byte {
	if cachedBin != nil {
		return cachedBin
	}
	code, err := f.ReadFile("WSEI.bin")
	if err != nil {
		panic("failed to read WSEI contract binary")
	}
	bz, err := hex.DecodeString(string(code))
	if err != nil {
		panic("failed to decode WSEI contract binary")
	}
	cachedBin = bz
	return bz
}
