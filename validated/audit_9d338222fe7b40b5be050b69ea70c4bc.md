## Analysis

The Gondi bug's core broken invariant: a **delta calculation** (`shareRate` change / `timestamp` change) that used a wrongly-initialized zero baseline instead of the true reference point, producing an incorrect result that bypassed a downstream validation check.

The closest local analog is in `pallet-consensus-incentives`, where a relayer reward is computed as a **delta between two height watermarks**, and one of those watermarks can silently default to `0` instead of the correct starting reference.

### Title
Zero-defaulted baseline height in relayer reward calculation allows first-update reward inflation - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`Pallet::calculate_reward` computes a relayer's payout as `(latest_height - baseline) * block_cost`. `baseline` is meant to be either the persisted `LastRewardedHeight` watermark or, on the very first reward for a state machine, `host.previous_commitment_height(...)`. When that call returns `None`/errors (no prior committed height exists — e.g., a state machine's first-ever consensus update, or after the state machine's commitment history is reset/re-registered), `.unwrap_or_default()` silently substitutes `0` rather than a meaningful starting height.

### Finding Description [1](#0-0) 

```rust
let previous_height =
    host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

// Use the rewarded watermark as the baseline and fall back to the previous height until
// the first reward is recorded for this chain...
let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

let blocks = latest_height.saturating_sub(baseline);
let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
let reward = blocks_as_balance.saturating_mul(block_cost);
```

This mirrors the Gondi pattern exactly: a "should-be-current" reference value is defaulted to `0` instead of the true prior state, so a subsequent delta (`latest_height - baseline`) is computed against the wrong anchor. In the Gondi case the zero baseline inflated the *denominator* (time span), deflating the APR; here the zero baseline inflates the *numerator* (`blocks`), inflating the reward. Both stem from the identical root cause: a fallback-to-zero substitution for a value that should reflect "the state at initialization/registration," used directly in an unguarded arithmetic delta that feeds a fund-moving calculation.

`process_message` is invoked automatically from `FeeHandler::on_executed` [2](#0-1)  every time a `StateMachineUpdated` event is produced by ordinary consensus-proof processing — there is no privileged gate on who can trigger this path; any relayer submitting a valid consensus proof for a state machine reaches it.

### Impact Explanation
If `host.previous_commitment_height` has no value for a given `state_machine_id` (first-ever update after the chain is registered, or after any reset of its commitment history), `baseline` resolves to `0`, so `blocks = latest_height` — the reward pays out for the **entire historical height span** of the state machine in a single call instead of only the span actually advanced by that proof. `T::Currency::transfer` then moves `blocks_as_balance * block_cost` out of the treasury account to the relayer [3](#0-2) , which for chains with any meaningful height and non-trivial `block_cost` is a drastically oversized, one-shot treasury drain — a direct fund-loss impact.

### Likelihood Explanation
This does not require a malicious relayer, prover, or admin — it fires under normal, permissionless message processing the first time a state machine's reward baseline is unset, which is guaranteed to occur once per newly configured `StateMachinesCostPerBlock` entry (governance sets a cost, then the very next ordinary consensus update triggers the inflated calculation). Any relayer that happens to deliver that first proof collects the oversized reward without any special access.

### Recommendation
Never let `previous_height`/`baseline` default to `0` when no prior commitment/watermark exists. On first reward for a state machine, initialize `LastRewardedHeight` to the state machine's registration height (or `latest_height` itself, paying `0` for the initial catch-up) rather than falling through to a numeric default that participates in `saturating_sub`.

### Proof of Concept
1. Governance calls `update_cost_per_block` to set a non-zero `block_cost` for a `state_machine_id` whose light client has already advanced to a high `latest_commitment_height` (e.g., after a long relayer-driven sync from genesis).
2. Any relayer submits the next consensus proof; `on_executed` → `process_message` runs.
3. `LastRewardedHeight` is `None` (first reward) and `host.previous_commitment_height` returns `None`/errors for this state machine (no prior recorded commitment height tracked by that accessor at this point) → `baseline = 0`.
4. `blocks = latest_height - 0 = latest_height`; `reward = latest_height * block_cost`, transferred in full from `TreasuryAccount` to the relayer in one extrinsic — vastly more than the single block-span the proof actually advanced.

```rust
	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}
```

```rust
impl<T: Config> FeeHandler for Pallet<T>
where
	<T as frame_system::Config>::AccountId: From<[u8; 32]>,
{
	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}

		// Return with actual weight information
		// We use Pays::No to indicate that someone (the message sender) doesn't pay for this
		// operation, though we're using this mechanism to reward relayers rather than charge fees
		Ok(PostDispatchInfo { actual_weight: None, pays_fee: Pays::No })
	}
```
