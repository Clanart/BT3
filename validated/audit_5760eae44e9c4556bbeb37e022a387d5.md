### Title
Unrestricted, near-zero-cost DL mirror injection allows any spend-bundle submitter to spam/poison a Data Layer store's mirror list - ([File: chia/data_layer/data_layer_wallet.py])

### Summary
`DataLayerWallet.coin_added()` accepts *any* coin on chain whose puzzle hash matches `create_mirror_puzzle()` and whose memo encodes a `launcher_id` that the local wallet already tracks, and unconditionally records it into the wallet's `mirrors` table — with no check on who created the coin, and no minimum/non-zero amount requirement. This mirrors the reported ERC20 bug class ("array can be manipulated via zero/low-cost operations, causing DoS or state corruption") but in Chia's Data Layer mirror-tracking list.

### Finding Description
`create_new_mirror()` lets *anyone* create a coin with puzzle hash `create_mirror_puzzle().get_tree_hash()` and a memo `[launcher_id, *urls]`, for **any `amount`, including 0** — the CLI even defaults `--amount` to `0`: [1](#0-0) [2](#0-1) 

When any node observes such a coin, `DataLayerWallet.coin_added()` decodes the memo and, if the `launcher_id` is one that the wallet is already tracking (i.e., the store owner or any subscriber/client of that store), it inserts the mirror into the DB **without verifying that the sender is the store owner or has any authority over the store, and without checking `amount`**: [3](#0-2) 

The DB layer stores mirrors keyed only by `coin_id` (not by sender or launcher-scoped uniqueness limits), so an attacker can create an unbounded number of distinct coins — each with a fresh `coin_id` — that all reference the *same* victim `launcher_id`: [4](#0-3) [5](#0-4) 

`get_mirrors()` simply returns every stored mirror whose `urls` list is non-empty, with no filtering by `ours`, no dedup by origin, and no cap: [6](#0-5) 

These attacker-controlled URLs are then propagated into `update_subscriptions_from_wallet()`, which merges all mirror URLs (regardless of origin) into the DataLayer's active subscription URL list for that store: [7](#0-6) 

Because `amount` may be `0`, the attacker only pays the mempool/CLVM fee to create an ephemeral standard-coin spend that outputs a `create_mirror_puzzle()` coin with amount 0 and a crafted memo — there is no economic cost proportional to the number of mirrors created (unlike normal use where `amount` funds the mirror and can later be reclaimed via `delete_mirror`, which for a 0-amount mirror is essentially free to spam repeatedly).

### Impact Explanation
Any unprivileged spend-bundle submitter can, at negligible fee cost:
1. Flood a target Data Layer store's mirror table with an unbounded number of near-zero-value coins, causing unbounded growth of the `mirrors` table and `get_mirrors`/`dl_get_mirrors` RPC responses (DoS analogous to the "holders array" bloat in the referenced report).
2. Inject attacker-chosen URLs into `update_subscriptions_from_wallet`, causing DataLayer clients/subscribers of that store to add malicious/arbitrary mirror URLs to their fetch/subscription list — a mirror-poisoning vector that can redirect data fetches to attacker-controlled hosts.

This matches the accepted impact classes: coin-set/state divergence and spend-triggered resource exhaustion/DoS against Data Layer clients, reachable purely from a submitted spend bundle with no special privilege.

### Likelihood Explanation
High. No signature or ownership check ties mirror creation to the store owner; only knowledge of the public `launcher_id` (visible on-chain) is required. The cost per spam coin is effectively just a transaction fee, since `amount` can be `0`. Any wallet user, offer counterparty, or arbitrary spend-bundle submitter can perform this repeatedly against any Data Layer store id they choose.

### Recommendation
- Require mirror coins to carry a non-zero `amount` (mirror `amount` should represent a real value stake, not be allowed to be `0`), and validate this in `coin_added()`/`create_new_mirror()` before inserting into the mirror store.
- Track and expose `ours`/sender identity so `get_mirrors()`/RPC consumers can filter out or clearly flag mirrors not created by the store owner.
- Consider limiting the number of mirrors stored/returned per `launcher_id`, or require some form of authorization (e.g., only mirrors created by coins whose parent lineage traces back to the store owner) before including a URL in `update_subscriptions_from_wallet`.

### Proof of Concept
1. Attacker identifies the `launcher_id` of a target Data Layer store (public information).
2. Attacker repeatedly submits standard-coin spends that create a `create_mirror_puzzle()` coin with `amount=0` and memo `[launcher_id, b"http://attacker.example/malicious"]`, paying only the minimum mempool fee each time.
3. Each such spend, once confirmed, is picked up by any node tracking that `launcher_id` via `DataLayerWallet.coin_added()` and inserted into the local `mirrors` table (`dl_wallet_store.add_mirror`) — no ownership check is performed.
4. Repeating this thousands of times inflates the store's mirror list arbitrarily cheaply, and the injected `http://attacker.example/malicious` URL propagates through `data_layer.update_subscriptions_from_wallet()` into the DataLayer's subscription/fetch URL list for that store.

Note: I could not execute this against a live simulator within the available tools; the analysis is based on static code tracing of `create_new_mirror`, `coin_added`, `dl_wallet_store.add_mirror`, `get_mirrors`, and `update_subscriptions_from_wallet`. A live PoC (via `chia data add_mirror --amount 0 ...` from an unrelated wallet) would be needed to confirm exact DB growth and RPC-return behavior end-to-end.

    async def add_mirror(self, mirror: Mirror) -> None:
        """
        Add a mirror coin to the DB
        """

        async with self.db_wrapper.writer_maybe_transaction() as conn:
            await conn.execute_insert(
                "INSERT OR REPLACE INTO mirrors VALUES (?, ?, ?, ?, ?)",
                (
                    mirror.coin_id,
                    mirror.launcher_id,
                    mirror.amount.stream_to_bytes(),
                    b"".join(
                        [uint16(len(url)).stream_to_bytes() + url for url in Mirror.encode_urls(mirror.urls)]
                    ),  # prefix each item with a length
                    1 if mirror.ours else 0,
                ),
            )

        mirrors: list[Mirror] = (await self.wallet_rpc.dl_get_mirrors(DLGetMirrors(launcher_id=store_id))).mirrors
        urls: list[str] = []
