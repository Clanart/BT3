### Title
Tokenfactory denom `AllowList` transfer restriction can be bypassed via the EVM bank precompile calling `SendCoins` directly - ([File: precompiles/bank/legacy/v600/bank.go])

### Summary
The tokenfactory `AllowList` mechanism is designed to restrict which addresses may send or receive a given `factory/...` denom. This restriction is enforced only in the Cosmos SDK message handlers `Send`/`MultiSend` [1](#0-0) , but several legacy versions of the EVM bank precompile's `send` function invoke `p.bankKeeper.SendCoins(...)` directly, skipping the `MsgSend`-level `IsInDenomAllowList` checks entirely.

### Finding Description
`IsInDenomAllowList` is the function that actually enforces the allow-list restriction, and it is called from `k msgServer Send` and `k msgServer MultiSend` before invoking the underlying `SendCoins`/`InputOutputCoins` keeper calls [2](#0-1) . The core `BaseSendKeeper.SendCoins` implementation itself does not perform this check — it is purely the responsibility of the caller (`msgServer`) to invoke it [3](#0-2) .

Multiple legacy versions of the EVM `bank` precompile's `send` handler (e.g. `v600`, `v580`) call `p.bankKeeper.SendCoins` directly with the sender/receiver derived from the EVM call arguments, entirely bypassing `msgServer.Send` and therefore the allow-list check: [4](#0-3) 

By contrast, the current/non-legacy bank precompile (and some other legacy versions such as `v605`, `v610`, `v630`, `v640`, `v67`) correctly route through `p.bankMsgServer.Send(...)`, which does perform the `IsInDenomAllowList` check: [5](#0-4) 

This is structurally identical to the Arrakis analog: a protective restriction (allow list / mint restriction) is enforced at one privileged entry point (`MsgSend` / router) but a second, independently reachable entry point (`SendCoins` called from the EVM precompile / `burn()` called directly) reaches the same underlying resource and bypasses the restriction.

### Impact Explanation
If a tokenfactory admin creates a denom with a `DenomAllowList` intending to restrict transfers to a curated set of addresses (e.g., for compliance, KYC, or a controlled distribution), any EVM user calling the affected legacy bank precompile version's `send` function can move allow-listed tokens to or from addresses that are not on the allow list. This defeats the security guarantee the allow list is meant to provide and can result in unauthorized transfer of restricted tokens to disallowed parties — a direct violation of an intended access-control invariant on fund movement.

### Likelihood Explanation
Reachability requires only that (a) the chain still exposes/uses one of the vulnerable legacy precompile versions (`v580`/`v600` or similar that call `SendCoins` directly) for the `send` method, and (b) a tokenfactory denom has an allow list configured. Any EVM account holding the allow-listed denom can trigger this via a normal transaction to the bank precompile address — no privileged access, governance, or validator collusion required.

### Recommendation
Ensure every code path that can move an allow-listed tokenfactory denom — including all precompile versions still reachable in production and any other internal caller of `SendCoins`/`InputOutputCoins` — invokes `IsInDenomAllowList` (and the corresponding `BlockedAddr` check) before transferring funds, or move the allow-list enforcement into `BaseSendKeeper.SendCoins`/`InputOutputCoins` itself so it cannot be bypassed by any caller, matching the fix suggested in the original report (align the restriction check with all functions that can move the restricted asset, not just the primary entry point).

### Proof of Concept
1. Admin creates a tokenfactory denom `factory/<admin>/restricted` and sets `SetDenomAllowList` to only include address `A`.
2. Account `A` holds the denom balance.
3. An EVM caller invokes the `send` method on the (vulnerable legacy) bank precompile, with `from = A`, `to = B` (an address not on the allow list), `denom = factory/<admin>/restricted`.
4. Because this precompile version calls `p.bankKeeper.SendCoins` directly (e.g. [6](#0-5) ) rather than `p.bankMsgServer.Send`, the `IsInDenomAllowList` check performed in `msgServer.Send` [2](#0-1)  is never executed, and the transfer succeeds despite `B` not being permitted to receive the restricted denom.

// IsInDenomAllowList checks if the given address is allowed to send the given coins.
// The check is performed only fot token factory denoms. For each token factory denom,
// it checks if there is allow list for the given denom. If there is no allow list,
// the address is allowed to send the coins. If there is an allow list, the address is
// allowed to send the coins only if it is in the allow list.
func (k BaseSendKeeper) IsInDenomAllowList(ctx sdk.Context, addr sdk.AccAddress, coins sdk.Coins, cache map[string]AllowedAddresses) bool {
	for _, coin := range coins {
		// Skip if denom does not contain the token factory prefix
		if !strings.HasPrefix(coin.Denom, TokenFactoryPrefix) {
			continue
		}

		allowedAddresses := k.getAllowedAddresses(ctx, cache, coin.Denom)
		// skip if there is no allow list for the denom
		if len(allowedAddresses.set) == 0 {
			continue
		}

		if !allowedAddresses.contains(addr) {
			return false
		}
	}
	return true
}

func (p PrecompileExecutor) send(ctx sdk.Context, caller common.Address, method *abi.Method, args []interface{}, value *big.Int, readOnly bool) ([]byte, error) {
	if readOnly {
		return nil, errors.New("cannot call send from staticcall")
	}
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, err
	}
	denom := args[2].(string)
	if denom == "" {
		return nil, errors.New("invalid denom")
	}
	pointer, _, exists := p.evmKeeper.GetERC20NativePointer(ctx, denom)
	if !exists || pointer.Cmp(caller) != 0 {
		return nil, fmt.Errorf("only pointer %s can send %s but got %s", pointer.Hex(), denom, caller.Hex())
	}
	amount := args[3].(*big.Int)
	if amount.Cmp(utils.Big0) == 0 {
		// short circuit
		return method.Outputs.Pack(true)
	}
	senderSeiAddr, err := p.accAddressFromArg(ctx, args[0])
	if err != nil {
		return nil, err
	}
	receiverSeiAddr, err := p.accAddressFromArg(ctx, args[1])
	if err != nil {
		return nil, err
	}

	if err := p.bankKeeper.SendCoins(ctx, senderSeiAddr, receiverSeiAddr, sdk.NewCoins(sdk.NewCoin(denom, sdk.NewIntFromBigInt(amount)))); err != nil {
		return nil, err
	}

	return method.Outputs.Pack(true)
}
