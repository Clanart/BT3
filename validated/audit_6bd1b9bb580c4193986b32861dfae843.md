### Title
Bank precompile's `sendNative` bypasses `SendEnabled` pause and `BlockedAddr` protections enforced by `MsgServer.Send` - (File: `precompiles/bank/bank.go`)

### Summary
The EVM `bank` precompile's `send` path enforces the same restrictions as the native Cosmos `MsgSend` path, but its `sendNative` path (triggered by sending EVM `value` to the precompile address) transfers `usei`/`wei` directly via `SendCoinsAndWei`, completely skipping the `SendEnabled` check and the `BlockedAddr` check that `MsgSend` performs. This mirrors the reported bug class: a "pause"/restriction mechanism blocks one transfer path (native `MsgSend`) but leaves an equivalent path (EVM value transfer through the precompile) open.

### Finding Description
`precompiles/bank/bank.go`'s `send()` method forwards to `p.bankMsgServer.Send(...)`, which internally runs: [1](#0-0) 

This enforces `IsSendEnabledCoins` (the network-wide/per-denom "pause" for transfers) and `BlockedAddr`/`IsInDenomAllowList` checks before any coins move: [2](#0-1) [3](#0-2) 

However, the same precompile's `sendNative()` method — reachable by any EVM caller sending `value` to the precompile address — calls `p.bankKeeper.SendCoinsAndWei` directly, with no call to `IsSendEnabledCoins` or `BlockedAddr`: [4](#0-3) 

This same pattern (checked `send`, unchecked `sendNative`) repeats across every legacy precompile version: [5](#0-4) [6](#0-5) 

Because `sendNative` never runs `IsSendEnabledCoins(ctx, usei-coin)` nor `BlockedAddr(receiver)`, an unprivileged EVM caller can:
1. Continue moving `usei` value through the precompile even after governance/operators disable sending of `usei` via `x/bank` params (a "pause"), exactly analogous to the reported issue where a paused state failed to stop `transfer()`.
2. Send funds directly to a "blocked" address (typically a module account), which the `x/bank` docs explicitly warn against: "If these addresses receive funds outside the expected rules of the state machine, invariants are likely to be broken and could result in a halted network." [3](#0-2) 

### Impact Explanation
- Bypassing `SendEnabled` defeats an operator/governance-controlled transfer pause intended to be a critical incident-response lever (e.g., freezing `usei` movement during an active exploit); any EVM contract can keep moving value while the chain believes sends are halted.
- Bypassing `BlockedAddr` allows depositing funds directly into module accounts outside the state machine's expected bookkeeping, which per the bank module's own documentation can break invariants and halt the network — this is a direct path to a chain halt / invariant break, a High-severity consequence for a public, unprivileged EVM caller.

### Likelihood Explanation
Any address holding EVM-associated `usei`/`wei` can trigger `sendNative` simply by sending a transaction with nonzero `value` to the bank precompile address — no special privilege, precompile allow-list, or contract deployment is required. The bug is present in every precompile version examined (`bank.go` and all `legacy/vXXX/bank.go` variants), so it is broadly reachable regardless of activation height.

### Recommendation
Route `sendNative`'s coin movement through the same `bankMsgServer.Send`/`SendCoins` code path (or explicitly call `IsSendEnabledCoins` and `BlockedAddr`/`IsInDenomAllowList` before calling `SendCoinsAndWei`) so that the EVM native-value transfer path is subject to the identical `SendEnabled` and blocklist checks enforced for native `MsgSend` transactions.

### Proof of Concept
1. Governance/operator sets `x/bank` `SendEnabled` to `false` for `usei` (or disables sends generally) as an incident-response pause.
2. Verify a native `MsgSend` of `usei` is rejected with `ErrSendDisabled` (per `IsSendEnabledCoins` in `sei-cosmos/x/bank/keeper/send.go`).
3. From any EVM account, call the bank precompile's `sendNative(receiver)` payable method with nonzero `value`.
4. Observe the transfer succeeds — `SendCoinsAndWei` moves the balance despite `SendEnabled=false`, because `sendNative` never calls `IsSendEnabledCoins`.
5. Repeat sending `value` to a known blocked/module address; observe the transfer succeeds despite `BlockedAddr` returning `true`, which would have been rejected had the request gone through `MsgServer.Send`.

func (k msgServer) Send(goCtx context.Context, msg *types.MsgSend) (*types.MsgSendResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	if err := k.IsSendEnabledCoins(ctx, msg.Amount...); err != nil {
		return nil, err
	}

	from, err := sdk.AccAddressFromBech32(msg.FromAddress)
	if err != nil {
		return nil, err
	}
	to, err := sdk.AccAddressFromBech32(msg.ToAddress)
	if err != nil {
		return nil, err
	}

	allowListCache := make(map[string]AllowedAddresses)
	if !k.IsInDenomAllowList(ctx, from, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to send funds", msg.FromAddress)
	}

	if k.BlockedAddr(to) || !k.IsInDenomAllowList(ctx, to, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", msg.ToAddress)
	}

// IsSendEnabledCoins checks the coins provide and returns an ErrSendDisabled if
// any of the coins are not configured for sending.  Returns nil if sending is enabled
// for all provided coin
func (k BaseSendKeeper) IsSendEnabledCoins(ctx sdk.Context, coins ...sdk.Coin) error {
	for _, coin := range coins {
		if !k.IsSendEnabledCoin(ctx, coin) {
			return sdkerrors.Wrapf(types.ErrSendDisabled, "%s transfers are currently disabled", coin.Denom)
		}
	}
	return nil
}

func (p PrecompileExecutor) sendNative(ctx sdk.Context, method *abi.Method, args []interface{}, caller common.Address, callingContract common.Address, value *big.Int, readOnly bool, hooks *tracing.Hooks, evm *vm.EVM) ([]byte, uint64, error) {
	if readOnly {
		return nil, 0, errors.New("cannot call sendNative from staticcall")
	}
	if ctx.EVMPrecompileCalledFromDelegateCall() {
		return nil, 0, errors.New("cannot delegatecall sendNative")
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	if value == nil || value.Sign() == 0 {
		return nil, 0, errors.New("set `value` field to non-zero to send")
	}

	senderSeiAddr, ok := p.evmKeeper.GetSeiAddress(ctx, caller)
	if !ok {
		return nil, 0, errors.New("invalid addr")
	}

	receiverAddr, ok := (args[0]).(string)
	if !ok || receiverAddr == "" {
		return nil, 0, errors.New("invalid addr")
	}

	receiverSeiAddr, err := sdk.AccAddressFromBech32(receiverAddr)
	if err != nil {
		return nil, 0, err
	}

	usei, wei, err := pcommon.HandlePaymentUseiWei(ctx, p.evmKeeper.GetSeiAddressOrDefault(ctx, p.address), senderSeiAddr, value, p.bankKeeper, p.evmKeeper, hooks, evm.GetDepth())
	if err != nil {
		return nil, 0, err
	}

	if err := p.bankKeeper.SendCoinsAndWei(ctx, senderSeiAddr, receiverSeiAddr, usei, wei); err != nil {
		return nil, 0, err
	}
	accExists := p.accountKeeper.HasAccount(ctx, receiverSeiAddr)
