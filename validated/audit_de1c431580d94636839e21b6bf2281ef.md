### Title
Gasless module's SwapTx deadline check is enforced only once at mempool admission, not re-validated before block inclusion, allowing stale-deadline swaps to execute - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The `kaiax/gasless` module lets a Kaia public-RPC caller submit a fee-delegation-free `SwapTx` that is routed to `GaslessSwapRouter.swapForGas(token, amountIn, minAmountOut, amountRepay, deadline)` [1](#0-0)  . The only place that validates `tx.deadline >= currentTimestamp` is `checkBalanceForSwap`, invoked from `GetCheckBalance` [2](#0-1) [3](#0-2)  . Per the `TxPoolModule` interface documentation, `GetCheckBalance` "is mainly used on checking if module transaction be appended to queue" [4](#0-3)  — i.e., it is a one-time admission-time check, not re-run when the tx is promoted from queue to pending, nor immediately before the block-proposer actually executes it.

### Finding Description
`checkBalanceForSwap` decodes the `swapForGas` call and enforces several invariants including the deadline check, but this function is only wired into `GetCheckBalance`, which the base tx pool calls when a transaction is appended to the queue [5](#0-4)  . The companion `IsReady` function, which governs promotion from queued to pending/executable, only checks bundle/knownTxs bookkeeping — it does not re-invoke `checkBalanceForSwap` or otherwise re-check the deadline [6](#0-5)  . Nothing in the block-assembly path (`work/worker.go`'s `commitTransaction`) re-validates the gasless-specific deadline before executing the transaction on-chain either [7](#0-6)  .

Consequently, a `SwapTx` that is nonce-gapped (sitting in the queue awaiting a preceding tx) or simply delayed in getting mined can have its `deadline` value pass while it still sits in the pool. Because the deadline is validated only once — at the moment of queue admission — the transaction remains eligible for promotion and inclusion in a later block even though its `deadline` has already expired relative to the block it ends up in. This is functionally the same bug class as the reported issue: a slippage/deadline parameter, once bound into the calldata, is not defended against staleness at the time of actual execution, allowing MEV searchers to sandwich the stale, pending swap.

### Impact Explanation
If a stale `SwapTx` reaches inclusion despite its deadline having elapsed, its `minAmountOut` slippage protection reflects prices computed against an outdated exchange rate. An attacker (a public block-builder/searcher, or the block proposer itself given `kaiax/auction`'s bundling capability) can sandwich the swap for extractable value, directly harming the gasless-swap user's realized token output — this is fee-delegation/gasless value abuse reachable purely from a single submitted transaction, matching the required impact bar (unauthorized value extraction / gasless settlement theft).

### Likelihood Explanation
Likelihood is moderate: it requires either (a) a nonce gap causing the SwapTx to sit queued while its deadline elapses, or (b) network congestion/mempool backlog long enough for the deadline to lapse between admission and mining, both of which are realistic and attacker-triggerable/observable conditions (an attacker can deliberately front the target with a conflicting-nonce tx to delay it, or simply wait for congestion) without requiring any privileged access.

### Recommendation
Re-validate `SwapArgs.Deadline` against the current block time inside `IsReady` (or immediately before/при block inclusion in `commitTransaction`/`ApplyTransactions`), not just once in `GetCheckBalance` at queue admission, so that stale deadlines are dropped from the pending pool rather than silently executed.

### Proof of Concept
1. Submit `approveTx` then a `swapForGas` `SwapTx` with `nonce = N+1` while `nonce = N` is still unconfirmed (i.e., the SwapTx lands in the queue, not pending), with `deadline = now + 300`.
2. `checkBalanceForSwap` passes at admission time since `deadline >= currentBlock.Time()` [3](#0-2)  .
3. Delay confirmation of the `nonce = N` transaction (e.g., resubmit it with low gas price, or via network congestion) until more than 300 seconds have elapsed.
4. Once the `N` tx confirms, the queued SwapTx becomes ready via `IsReady`, which performs no deadline re-check [6](#0-5)  , and it can be included/mined with an already-expired `deadline`, executing at stale/sandwichable pricing.

func (g *GaslessModule) GetCheckBalance() func(tx *types.Transaction) error {
	return func(tx *types.Transaction) error {
		if approveArgs, ok := decodeApproveTx(tx, g.signer); ok {
			return g.checkBalanceForApprove(approveArgs)
		}
		if swapArgs, ok := decodeSwapTx(tx, g.signer); ok {
			return g.checkBalanceForSwap(swapArgs, tx.Nonce())
		}
		return errors.New("not a gasless transaction") // should not happen because IsModuleTx is called before GetCheckBalance
	}
}

// Check promotion condition and enforce pending pool flow control.
func (g *GaslessModule) IsReady(txs map[uint64]*types.Transaction, next uint64, ready types.Transactions) bool {
	g.knownTxsMu.Lock()
	defer g.knownTxsMu.Unlock()

	tx, ok := txs[next]
	if !ok {
		return false
	}

	if !g.isReady(txs, next, ready) {
		return false
	}

	if g.IsBundleTx(tx) {
		// If prev tx is bundle tx, there's no need to check the knownTxs limit because it has been checked in the previous `IsReady()` execution.
		isPrevTxBundleTx := len(ready) != 0 && g.IsBundleTx(ready[len(ready)-1])
		if isPrevTxBundleTx {
			g.knownTxs.add(tx, TxStatusPending)
			return true
		}

		maxBundleTxsInPending := g.GetMaxBundleTxsInPending()
		if maxBundleTxsInPending != math.MaxUint64 {
			numExecutable := uint(g.knownTxs.numExecutable())

			numSeqTxs := uint(1)
			for i := next + 1; i < next+uint64(len(txs)); i++ {
				if tx, ok := txs[i]; ok && g.IsBundleTx(tx) {
					numSeqTxs++
				} else {
					break
				}
			}

			// false if there is possibility of exceeding max bundle tx num
			if numExecutable+numSeqTxs > maxBundleTxsInPending {
				logger.Trace("Not promoting a tx because of exceeding max bundle tx num", "tx", tx.Hash().String(), "numExecutable", numExecutable, "maxBundleTxsInPending", maxBundleTxsInPending)
				return false
			}
		}

		g.knownTxs.add(tx, TxStatusPending)
	}

	return true
}

func (env *Task) commitTransaction(tx *types.Transaction, bc BlockChain, nodeAddr common.Address, vmConfig *vm.Config) (error, []*types.Log) {
	snap := env.state.Snapshot()

	receipt, _, err := bc.ApplyTransaction(env.config, &nodeAddr, env.state, env.header, tx, &env.header.GasUsed, vmConfig)
	if err != nil {
		if err != vm.ErrInsufficientBalance && err != vm.ErrTotalTimeLimitReached {
			tx.MarkUnexecutable(true)
		}
		env.state.RevertToSnapshot(snap)
		return err, nil
	}

	env.tcount++
	env.txs = append(env.txs, tx)
	env.receipts = append(env.receipts, receipt)
	env.size += uint64(tx.Size())
	if tx.Type() == types.TxTypeEthereumBlob {
		env.blobs += len(tx.BlobHashes())
		*env.header.BlobGasUsed += tx.BlobGas()
	}

	return nil, receipt.Logs
}
