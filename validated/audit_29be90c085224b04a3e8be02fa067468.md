## Title
DataLayer mirror-URL SSRF: unauthenticated mirror coin data drives unvalidated outbound HTTP requests during store sync - (File: `chia/data_layer/download_data.py`)

### Summary
Chia's DataLayer replication mechanism lets any wallet user publish an on-chain "mirror" coin containing arbitrary URL strings tied to *any* DataLayer store `launcher_id` — not just stores the publisher owns. Peers that track that launcher via `dl_wallet.py`'s `coin_added()` will import those URLs into their local mirror/subscription tables with no host/scheme validation. The `DataLayer` service later dereferences these URLs with `aiohttp` during routine sync (`fetch_and_validate()` → `insert_from_delta_file()` → `download_file()` → `http_download()`), performing outbound GET requests to attacker-chosen hosts including loopback, private, or link-local addresses. This mirrors the Lemmy Webmention SSRF pattern: a user-controlled URL field is only shape/decode-checked, never checked for internal-address exposure, before triggering a server-side HTTP request.

### Finding Description
A mirror coin is created via `DataLayerWallet.create_new_mirror()`: [1](#0-0) 

This spends the caller's own XCH to create a coin at `create_mirror_puzzle()`'s puzzle hash, memoizing an arbitrary `launcher_id` plus a list of raw URL bytes. Critically, there is no check that `launcher_id` belongs to the caller — any low-privileged wallet holder can mint a mirror coin that references *someone else's* store id with attacker-chosen URLs, exposed via the RPC/CLI surface: [2](#0-1) [3](#0-2) 

Any node that is tracking that launcher id ingests the coin via `coin_added()`, decoding the URLs straight from the parent solution with zero URL validation: [4](#0-3) 

The DataLayer service periodically pulls these mirror URLs into its local subscription table: [5](#0-4) 

During the sync loop, `fetch_and_validate()` randomly selects one of these attacker-controlled server URLs and passes it straight into the download pipeline: [6](#0-5) 

`insert_from_delta_file()` → `download_file()` → `http_download()` issue an actual `aiohttp` GET request built directly from `server_info.url`: [7](#0-6) 

No component in this chain (`data_layer_wallet.py`, `data_layer.py`, `data_store.py`, `download_data.py`, `data_layer_util.py`) parses the URL scheme/host or rejects loopback/private/link-local targets — confirmed by the absence of any `urlparse`/scheme/private-range checks across the DataLayer module (only the unrelated `s3_plugin_service.py` contains scheme-like matches). This is structurally identical to the Lemmy bug: `is_valid_url()` there only checked scheme, never destination; here there is no check at all.

### Impact Explanation
Any user capable of submitting a normal spend bundle (creating a mirror coin costs only a small XCH amount and fee) can force other DataLayer-tracking full nodes/wallets to issue outbound HTTP requests to attacker-chosen internal or loopback addresses. This is a blind SSRF primitive against any Chia node running the DataLayer service, exposing internal network reachability and internal HTTP endpoints (e.g., local RPC ports, other services on `127.0.0.1`), without needing the target to have any relationship to the attacker beyond running DataLayer and tracking the referenced store id (which itself can be attacker-chosen/attacker-created). This satisfies the "SSRF primitive" impact class analogous to the Lemmy advisory (CWE-918), reachable purely through normal, unprivileged coin-spend / DataLayer RPC actions.

### Likelihood Explanation
Likelihood is Medium: the attacker needs the victim node to be running the DataLayer service and to be tracking (subscribed/interested in) the target `launcher_id` — which is a normal condition for any DataLayer store consumer, offer counterparty, or mirror-following participant. The attacker-side actions (creating a mirror coin, publishing arbitrary URLs) require nothing more than a funded wallet and are fully unprivileged, matching the report's requirement of a low-privileged actor triggering the sink through ordinary content submission.

### Recommendation
Validate mirror/subscription URLs before they are persisted or dereferenced: enforce `https`/`http` scheme allow-listing plus resolution/host filtering to reject loopback, private (RFC1918), link-local, and other non-routable/internal address ranges, both at mirror-coin ingestion time (`DataLayerWallet.coin_added()`/`dl_wallet_store.add_mirror`) and at the point `DataLayer.update_subscriptions_from_wallet()`/`fetch_and_validate()`/`http_download()` consume `server_info.url`. Consider also enforcing ownership or reputation checks on which launcher ids a mirror coin is allowed to reference, or at minimum warn/require operator opt-in before dereferencing third-party-supplied mirror URLs.

### Proof of Concept
1. Attacker wallet creates a DataLayer mirror coin referencing a `launcher_id` of a store that the victim node tracks/subscribes to, with `urls=["http://127.0.0.1:8081/"]` (or any internal address reachable from the victim), via `dl_new_mirror` RPC:
   ```
   client.dl_new_mirror(DLNewMirror(launcher_id=<victim-tracked store id>, amount=1000, urls=["http://127.0.0.1:8081/"], fee=..., push=True), tx_config)
   ```
   (see test usage) [8](#0-7) 
2. Farm the transaction so the mirror coin confirms on-chain.
3. Victim's `DataLayerWallet.coin_added()` on any node tracking that launcher imports the URL into its mirrors table.
4. Victim's `DataLayer.update_subscriptions_from_wallet()` copies the URL into local subscriptions; the periodic sync loop's `fetch_and_validate()` picks the malicious server and calls `insert_from_delta_file()`.
5. `download_file()`/`http_download()` issues `GET http://127.0.0.1:8081/<generated-filename>` from the victim node, observable on the attacker's internal listener — confirming outbound SSRF triggered purely by an on-chain mirror-coin spend.

        action_scope: WalletActionScope,
        extra_conditions: tuple[Condition, ...] = tuple(),
    ) -> DLNewMirrorResponse:
        """Add a new on chain message for a specific singleton"""

        dl_wallet = await self.service.wallet_state_manager.get_dl_wallet()

                request.launcher_id,
                request.amount,
                Mirror.encode_urls(request.urls),
                action_scope,
                fee=request.fee,
                extra_conditions=extra_conditions,

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
