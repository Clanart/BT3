### Title
Identity public keys permit universal Schnorr signature forgery - ([File: crypto/schnorr/src/lib.rs](crypto/schnorr/src/lib.rs))

### Summary
`SchnorrSignature::verify` accepts the group identity as both a public key and nonce commitment, making `(R = identity, s = 0)` valid for every challenge. `Ciphersuite::read_G` checks only canonical encoding and does not reject identity, so attacker-controlled bytes can deserialize this forgery. The MuSig key aggregation path also does not reject identity keys, allowing an identity-valued aggregate public key when malicious participants supply identity shares.

### Finding Description
`SchnorrSignature::read` deserializes `R` and `s` through `read_G` and `read_F` without semantic restrictions. [1](#0-0)  `read_G` requires a successful canonical point decoding, but does not reject the identity point. [2](#0-1) 

Verification checks `R + cA - sG == 0`. [3](#0-2)  If `A = identity`, `R = identity`, and `s = 0`, every term is identity for every challenge `c`. The signature therefore verifies without knowledge of a private key.

`check_keys` in MuSig validates only that the list is nonempty, fits in `u16`, and has no duplicate encodings; it does not reject identity public keys. [4](#0-3)  The aggregated key is calculated from those caller-supplied points without an identity check. [5](#0-4) 

### Impact Explanation
An attacker who can register or supply an identity public key can produce a universally valid Schnorr signature under that key. This bypasses the intended proof of possession and permits forged signatures for protocols that accept the resulting identity-valued public key or aggregate key.

### Likelihood Explanation
The attack requires an upstream protocol to accept an attacker-supplied identity public key or to aggregate an attacker-supplied identity share. The in-scope MuSig aggregation functions expose such a path because they do not exclude identity keys, making the issue reachable with public protocol inputs. Severity is Medium where key admission is otherwise constrained, and High in any context where the identity aggregate key is accepted for authorization.

### Recommendation
Reject identity and other non-prime-order or semantically invalid points in `Ciphersuite::read_G` or add explicit nonzero/non-identity validation to every public-key admission path. At minimum, `SchnorrSignature::verify`, `check_keys`, `musig_key`, `musig`, and other verifier entry points should reject `public_key.is_identity()` and identity nonce commitments. The requirements should also be documented for callers constructing keys directly rather than deserializing them.

### Proof of Concept
For any `C: Ciphersuite` and any verifier-supplied challenge, including a challenge that correctly binds the public key and message:

```rust
use ciphersuite::group::Group;
use schnorr::SchnorrSignature;

let public_key = C::G::identity();
let forged = SchnorrSignature::<C> {
  R: C::G::identity(),
  s: C::F::ZERO,
};

assert!(forged.verify(public_key, arbitrary_challenge));
```

The same result is reachable through untrusted bytes: encode `C::G::identity().to_bytes()` followed by the canonical encoding of scalar zero, pass it to `SchnorrSignature::<C>::read`, and call `verify` with an identity public key. [6](#0-5)

fn check_keys<C: Ciphersuite>(keys: &[C::G]) -> Result<u16, MusigError<C>> {
  if keys.is_empty() {
    Err(MusigError::NoKeysProvided)?;
  }

  let keys_len = u16::try_from(keys.len())
    .map_err(|_| MusigError::TooManyKeysProvided { max: u16::MAX, provided: keys.len() })?;

  let mut set = HashSet::with_capacity(keys.len());
  for key in keys {
    let bytes = key.to_bytes().as_ref().to_vec();
    if !set.insert(bytes) {
      Err(MusigError::DuplicatedParticipant(*key))?;
    }
  }

  Ok(keys_len)
}

fn musig_key_multiexp<C: Ciphersuite>(
  context: [u8; 32],
  keys: &[C::G],
) -> Result<Vec<(C::F, C::G)>, MusigError<C>> {
  let keys_len = check_keys::<C>(keys)?;
  let transcript = binding_factor_transcript::<C>(context, keys_len, keys);
  let mut multiexp = Vec::with_capacity(keys.len());
  for i in 1 ..= keys_len {
    multiexp.push((binding_factor::<C>(transcript.clone(), i), keys[usize::from(i - 1)]));
  }
  Ok(multiexp)
}
