## Title
Unauthenticated spend bundle can crash mempool validation via out-of-bounds read in CLVM canonical-encoding checker - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_atom_canonical()` / `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` parse the length-prefix byte sequence of a CLVM-serialized atom without validating that the declared prefix length actually fits within the remaining buffer. This mirrors the libarchive `mtree` `readline` bug class (CVE-2015-8925): a hand-crafted, short trailing byte sequence causes the parser to walk past the end of the buffer, raising an unhandled `IndexError` instead of a controlled parse failure.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` at [1](#0-0)  decodes the CLVM atom length-prefix encoding. Based on the high bits of the first byte, it computes a `prefix_len` (0–5 additional bytes) and then loops `prefix_len` times reading `clvm_buffer[offset]` after incrementing `offset`, with **no bounds check** that `offset` stays within `len(clvm_buffer)`:

```
atom_len = b & mask
for i in range(prefix_len):
    atom_len <<= 8
    offset += 1
    atom_len |= clvm_buffer[offset]
```

If the buffer ends before all `prefix_len` bytes are present (e.g. a single trailing byte `0xF8` claiming a 5-byte-extended length prefix at the very end of the puzzle reveal or solution), `clvm_buffer[offset]` raises `IndexError`.

This function is called directly on attacker-controlled, unsigned-at-this-point bytes from every submitted spend bundle in `MempoolManager.validate_spend_bundle()`:

```
if not is_clvm_canonical(bytes(coin_spend.puzzle_reveal)) or not is_clvm_canonical(
    bytes(coin_spend.solution)
):
    return Err.INVALID_COIN_SOLUTION, None, []
``` [2](#0-1) 

`is_clvm_canonical()` itself also indexes `clvm_buffer[offset]` in its main loop without bounds checking beyond the top-level `assert clvm_buffer != b""` [3](#0-2) , so a crafted pair-opener (`0xFF`) at the last byte of the buffer, or a truncated atom-length prefix, reaches the same unguarded indexing and raises `IndexError`.

Unlike the rest of the codebase's parsers — which explicitly validate remaining-buffer length before indexing (e.g. `skip_bytes`/`skip_list` in `chia/full_node/full_block_utils.py` [4](#0-3) , or the streamable `parse_bytes`/`parse_list` helpers in `chia/util/streamable.py` [5](#0-4) ) — the canonical-CLVM checker performs raw indexing with an implicit trust that any declared length prefix is backed by enough bytes.

This check runs on every coin spend of every incoming spend bundle, before signature/consensus validation completes, making it reachable by any unprivileged party who can submit a spend bundle to a full node (wallet RPC, peer transaction relay, or local RPC submission).

### Impact Explanation
An `IndexError` raised inside `validate_spend_bundle()` is not caught by any surrounding exception handler visible in the mempool admission path shown (`add_spend_bundle()` simply awaits `validate_spend_bundle()` and branches on its return value, with no try/except around the `is_clvm_canonical` call) [6](#0-5) . Whether this crashes the whole mempool-processing task, is swallowed at a higher call layer in `full_node.py`, or surfaces as a request failure could not be fully confirmed from the excerpts retrieved (the outer caller in `chia/full_node/full_node.py` that invokes `add_spend_bundle`/`add_transaction` was located but its exception-handling wrapper was not inspected before the tool budget ran out). At minimum this is a per-request failure (denial of service for that submission path); if the exception propagates out of the mempool's async task without a catch-all handler, it could disrupt transaction processing for the node, which matches the "spend-triggered transaction-processing halt" impact class in the CVE analog.

### Likelihood Explanation
High: no signature check, no proof-of-space, no special privilege is required. Any party able to submit a `SpendBundle` (via wallet RPC `push_tx`, full-node peer transaction protocol, or local RPC) can supply an arbitrarily crafted `puzzle_reveal`/`solution` byte sequence ending in a truncated atom-length prefix, which is fed straight into `is_clvm_canonical()` prior to any other validation.

### Recommendation
Add explicit remaining-buffer-length checks in `is_atom_canonical()` before each `clvm_buffer[offset]` access (i.e., verify `offset < len(clvm_buffer)` for each of the `prefix_len` reads), and in `is_clvm_canonical()`'s main loop before indexing `clvm_buffer[offset]`, returning `False` (non-canonical) instead of raising an exception on truncated/malformed input. Additionally wrap the call site in `validate_spend_bundle()` to convert any unexpected parsing exception into `Err.INVALID_COIN_SOLUTION` as defense in depth.

### Proof of Concept
A `puzzle_reveal` or `solution` byte string ending in a byte matching the "5+8+8+8+8+8-bit" extended atom prefix pattern (`0xF8`–`0xF9`, i.e. `(b & 0b11111110) == 0b11111100`) with fewer than 5 trailing bytes triggers the bug, e.g.:

```python
from chia.full_node.mempool_manager import is_clvm_canonical
is_clvm_canonical(b"\xf8")        # raises IndexError instead of returning False
is_clvm_canonical(b"\xff\xf8")    # pair + truncated atom prefix -> IndexError
```

Submitting a `CoinSpend` whose `solution` (or `puzzle_reveal`) ends with such a truncated sequence and packaging it into a `SpendBundle` sent to `add_spend_bundle()`/`validate_spend_bundle()` reaches the unguarded `is_atom_canonical`/`is_clvm_canonical` code path shown above.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
```
