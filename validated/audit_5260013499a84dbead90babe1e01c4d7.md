### Title
Ed448 accepts low-order points, enabling Schnorr signatures to be forged under malformed public keys - ([File: crypto/ed448/src/point.rs](crypto/ed448/src/point.rs))

### Summary
`Point::is_torsion_free` computes `(-P) + P`, which is always the identity and therefore accepts every structurally valid Ed448 point, including points outside the prime-order subgroup. [1](#0-0)  `Ciphersuite::read_G` relies on `GroupEncoding::from_bytes` for subgroup validation and otherwise enforces only canonical encoding. [2](#0-1)  Consequently, attacker-controlled bytes can deserialize to a low-order Ed448 public key or nonce and pass the strict decoding boundary. [2](#0-1) 

### Finding Description
The intended subgroup check is tautological:

```rust
fn is_torsion_free(&self) -> Choice {
  ((*self * (Scalar::ZERO - Scalar::ONE)) + self).is_identity()
}
```

`Scalar::ZERO - Scalar::ONE` is `-1`, so the expression is `-P + P`, which is always identity. [1](#0-0)  `Point::from_bytes` treats this result as proof that the recovered point is torsion-free. [3](#0-2) 

`SchnorrSignature::read` accepts any point accepted by `C::read_G`, and `verify` accepts the equation `R + cA - sG = identity`. [4](#0-3) [5](#0-4)  For a malformed public key `A` of order two, choosing `R = A` and `s = 0` satisfies that equation whenever the challenge is odd, because `A + A = identity`; choosing `R = identity` satisfies it whenever the challenge is even. [6](#0-5) 

The challenge API expects callers to bind the challenge to the nonce, public key, and message, but even a correctly constructed Fiat–Shamir challenge has approximately a one-half chance of matching one of those two candidate nonces for each tried message. [7](#0-6)  The attacker can therefore vary the message or associated context until the parity of the challenge matches the selected malformed nonce. [7](#0-6) 

### Impact Explanation
A verifier that accepts an attacker-supplied Ed448 public key can be convinced by a forged Schnorr signature for a chosen message after testing a small number of challenge/message variants. [5](#0-4)  The same decoding flaw also admits identity and other low-order points into any in-scope protocol object routed through `Ciphersuite::read_G`, including signatures, proofs, and threshold-key material. [2](#0-1) 

This is not merely a malformed-input rejection issue: the verifier equation itself is correct, but the advertised `PrimeGroup` precondition is violated because subgroup membership is never actually checked. [8](#0-7) [1](#0-0) 

### Likelihood Explanation
The attack requires the victim to accept a malformed Ed448 public key or point supplied through public input, which is within the permitted reachability model for `read_G`, `SchnorrSignature::read`, and `verify`. [2](#0-1) [4](#0-3)  Once such a key is accepted, producing a matching forged nonce is computationally trivial because an order-two public key reduces the challenge-dependent term to a parity condition. [1](#0-0) [9](#0-8) 

No private key, threshold compromise, validator collusion, or malformed caller is required; the key bytes themselves are valid canonical Ed448 encodings and are admitted by the library’s own decoder. [10](#0-9) [2](#0-1) 

### Recommendation
Replace the tautological check with an actual prime-subgroup membership test for Ed448, such as checking multiplication by the prime subgroup order using a representation that can express that order outside the scalar field. [1](#0-0)  Alternatively, reject all known non-prime-order/low-order encodings during `Point::from_bytes`, and reject the identity at decoding boundaries where a nonzero prime-order element is required. [10](#0-9) [11](#0-10) 

Add regression tests that deserialize the order-two point `(0, -1)`, the identity, and the other low-order Ed448 encodings and assert that all are rejected by `Ed448::read_G`. [10](#0-9) [2](#0-1) 

### Proof of Concept
The compressed Ed448 encoding for the order-two point `(0, -1)` is 57 bytes: `y = p - 1` in little-endian form, with the sign bit clear because `x = 0`. The following pseudocode demonstrates the accepted malformed key and the two candidate forged signatures:

```rust
use ciphersuite::Ciphersuite;
use ed448::{Ed448, Scalar};
use schnorr::SchnorrSignature;

// p = 2^448 - 2^224 - 1.
// y = p - 1, encoded little-endian, with the 57th byte's sign bit clear.
let mut order2 = [0xff; 57];
order2[0] = 0xfe;
order2[28] = 0xfe;
order2[56] = 0x00;

let public_key =
  <Ed448 as Ciphersuite>::read_G(&mut order2.as_slice()).unwrap();

// For an odd challenge c:
let forged = SchnorrSignature::<Ed448> {
  R: public_key,
  s: Scalar::ZERO,
};

assert!(forged.verify(public_key, Scalar::from(3)));
```

For an odd challenge, `c * public_key = public_key`, so the verifier evaluates `public_key + public_key - 0G = identity`. [6](#0-5)  For an even challenge, the same attack uses the identity point as `R`; both points pass the defective subgroup check. [1](#0-0)
