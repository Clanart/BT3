### Title
`ReceivedOutput::read` over-reads the input stream via an internal `BufReader`, silently corrupting all bytes that follow a `ReceivedOutput` in a shared reader - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
Like CVE-2021-47293 (`act_skbmod` assumes every packet is Ethernet and silently corrupts non-Ethernet packets), `ReceivedOutput::read` assumes the passed `Read` contains *only* the bytes of one `ReceivedOutput`. It wraps the caller's reader in a `BufReader`, decodes `TxOut` and `OutPoint` through it, and drops the wrapper — discarding any bytes the `BufReader` speculatively prefetched. When a `ReceivedOutput` is parsed from a stream containing subsequent protocol data, those trailing bytes are silently swallowed, corrupting whatever is decoded next.

### Finding Description
`ReceivedOutput::read` performs:

```rust
let offset = Secp256k1::read_F(r)?;
let mut buf_r = BufReader::with_capacity(0, r);
output = TxOut::consensus_decode(&mut buf_r)...;
outpoint = OutPoint::consensus_decode(&mut buf_r)...;
``` [1](#0-0) 

`BufReader` satisfies `read()` calls by issuing one large `read` on the underlying reader into its internal buffer. `TxOut::consensus_decode` and `OutPoint::consensus_decode` consume only the exact bytes they need (8-byte amount + varint-prefixed script; 32-byte txid + 4-byte vout), but the `BufReader` may already have pulled *far more* than that from `r` — e.g., when `r` is a `&[u8]` or socket-backed stream, a single `fill_buf` drains all remaining bytes. Those extra buffered bytes are dropped when `buf_r` goes out of scope. The stream position seen by the caller is now ahead of where it should be, and the intervening bytes are lost — silent corruption exactly analogous to `skbmod` mangling packets of an unexpected shape.

The unit test only round-trips `outputs[0].serialize()` as a standalone buffer ( [2](#0-1) ), so the over-read is invisible there.

### Impact Explanation
An unprivileged counterparty feeds the bytes that get parsed through `read_*` APIs. `ReceivedOutput` is the carrier of funds into `SignableTransaction::new` / `multisig` ( [3](#0-2) ). In any protocol framing where a `ReceivedOutput` is followed by additional fields (commitments, shares, more outputs) on the same reader — precisely the pattern used by `TransactionSignMachine::read_preprocess`/`read_share`, which read multiple objects sequentially from one reader ( [4](#0-3) ) — deserialization of everything after the `ReceivedOutput` is misaligned or truncated. A peer can exploit this to corrupt subsequent `Preprocess`/`SignatureShare`/`ThresholdKeys` fields, producing wrong scalars/points mid-protocol, aborting multisig completion, or deserializing attacker-influenced garbage where honest data was expected. Because the corruption is silent (no error at the point of loss), the failure surfaces far downstream, matching the "silently corrupts all the packets" character of the CVE.

### Likelihood Explanation
Reachable whenever `ReceivedOutput::read` is given a reader that is not exhausted after the record — i.e., concatenated or framed protocol messages, which is the natural usage for a `read`/`write` type pair in a threshold-signing stack. The trigger requires only that data follow the record in the stream; no special privileges or cryptographic conditions are needed.

### Recommendation
Do not wrap a caller-owned `Read` in `BufReader`. Either decode `TxOut`/`OutPoint` directly from `r`, or read the needed bytes explicitly and consensus-decode from a bounded slice:

```rust
let offset = Secp256k1::read_F(r)?;
// Decode directly without buffering; consensus_decode only reads what it needs
// from a plain reader.
let output = TxOut::consensus_decode(r).map_err(|_| io::Error::other("invalid TxOut"))?;
let outpoint = OutPoint::consensus_decode(r).map_err(|_| io::Error::other("invalid OutPoint"))?;
```

(If `consensus_decode`'s small `read` calls are a performance concern, first length-prefix the record at the framing layer and decode from an owned `&[u8]`.) Additionally, add a test that serializes `received.serialize() ++ trailing_bytes` and asserts `trailing_bytes` remain readable afterward.

### Proof of Concept
```rust
use std::io::Read;
use serai_bitcoin::wallet::ReceivedOutput;

let received: ReceivedOutput = /* any output from Scanner::scan_transaction */;
let mut stream = received.serialize();
stream.extend_from_slice(b"TRAILING-PROTOCOL-DATA");

let mut cursor: &[u8] = &stream;
let parsed = ReceivedOutput::read(&mut cursor).unwrap();
assert_eq!(parsed, received);

// The bytes after the ReceivedOutput should still be available, but any bytes
// BufReader prefetched beyond the OutPoint were consumed and discarded.
let mut rest = Vec::new();
cursor.read_to_end(&mut rest).unwrap();
assert_eq!(rest, b"TRAILING-PROTOCOL-DATA"); // FAILS: `rest` is missing the prefetched prefix
```
