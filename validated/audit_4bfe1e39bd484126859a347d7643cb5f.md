Based on the evidence gathered, I found a concrete local analog: `EvmHost.sol`'s `withdraw()` function, which is the direct on-chain payout path for relayer fee withdrawals initiated via `pallet-ismp-relayer`, is only protected by the `restrict(_hostParams.hostManager)` modifier and does **not** carry the `notFrozen` modifier that guards the request/response dispatch paths.

### Title
`EvmHost.withdraw()` executes relayer/host fee payouts without checking `FrozenStatus`, unlike outgoing dispatch paths - (File: evm/src/core/EvmHost.sol)

### Summary
### Finding Description
`EvmHost.sol` defines a `notFrozen` modifier that gates message dispatch when the host is frozen: [1](#0-0) 

The host also exposes `withdraw()`, called by the `HostManager` (reachable cross-chain via the relayer fee-withdrawal flow documented in `pallet-ismp-relayer`), which transfers native tokens or ERC20 fee-token balance to a beneficiary: [2](#0-1) 

This function is guarded only by `restrict(_hostParams.hostManager)`: [3](#0-2) 

It has no `notFrozen` check, meaning that even when the `EvmHost` is frozen (`FrozenStatus.Outgoing`, `Incoming`, or `All` — set precisely to stop the protocol from continuing normal operation, e.g. during an active security incident or dispute), the `withdraw` code path used for relayer fee disbursement and host-revenue withdrawal is not disabled. Relayers can continue to `accumulate_fees` and `withdraw_fees` on the substrate side and, since delivery of the resulting ISMP POST request to a frozen `EvmHost` still resolves into a call to `withdraw()`, funds keep moving out during the very state that freezing is meant to halt.

This is structurally identical to the referenced bug class: a state-mutating, fund-moving operation (`startRewardsCycle` for GoGoPool, `withdraw` for Hyperbridge) omits the pause/freeze guard that sibling functions (`dispatch`, other `notFrozen`-gated calls) already apply, letting privileged economic flows continue during an emergency stop.

### Impact Explanation
If the host is frozen in response to a compromised consensus client, a malicious state commitment, or another active incident, in-flight or newly accumulated relayer fee withdrawals and host-revenue withdrawals still execute and drain vault balances via `withdraw()`, contradicting the purpose of `FrozenStatus`. This can result in funds leaving the protocol precisely when governance/guardians intended a full stop, and is not limited to the withdrawing relayer's rightful balance timing — it silently bypasses the incident-response control.

### Likelihood Explanation
Likelihood is moderate: it requires the host to be frozen (an admin/governance action) while a withdrawal request is in flight or gets dispatched from Hyperbridge afterward — an ordinary, expected sequence of events during an incident, not an attacker-crafted edge case. No malicious peer, relayer, or governance actor is required; this is a straightforward gap in the existing guard set on a public/authorized entrypoint.

### Recommendation
Add the `notFrozen` modifier (or an explicit check against `_frozen == FrozenStatus.All`) to `EvmHost.withdraw()` so that fee/host-revenue withdrawals are halted whenever the host is frozen, consistent with how dispatch functions are already protected.

### Proof of Concept
1. Admin sets `_frozen = FrozenStatus.All` on `EvmHost` (e.g., in response to a detected consensus/state anomaly) — [4](#0-3) .
2. A relayer with a previously accumulated fee balance on Hyperbridge calls `withdraw_fees`, which builds and dispatches an ISMP POST to the frozen chain's `hostManager` — [5](#0-4) .
3. The request is delivered to the frozen `EvmHost` and resolves into a call to `EvmHost.withdraw()`, which only checks `restrict(_hostParams.hostManager)`, not `notFrozen` — [6](#0-5) .
4. Funds transfer out of the vault despite the host being frozen, exactly mirroring the `RewardsPool.startRewardsCycle` bug where a fund-distributing function ignored the pause state that all its sibling functions respected.

     * @param params, the parameters for withdrawal
     */
    function withdraw(WithdrawParams memory params) external restrict(_hostParams.hostManager) {
        if (params.token == address(0)) {
            // this is safe because re-entrancy is mitigated before dispatching requests
            (bool sent,) = params.beneficiary.call{value: params.amount}("");
            if (!sent) revert WithdrawalFailed();
        } else {
            IERC20(params.token).safeTransfer(params.beneficiary, params.amount);
        }
        emit HostWithdrawal({beneficiary: params.beneficiary, amount: params.amount, token: params.token});
    }
