## Title
Data Layer mirror URLs are fetched via unrestricted `http_download()`, enabling SSRF against subscriber nodes - (File: `chia/data_layer/download_data.py`)

### Summary
Chia's Data Layer lets any wallet holding a DataLayer singleton call `add_mirror()`/`dl_new_mirror` to publish arbitrary mirror URLs on-chain for their store, and lets any other wallet user `subscribe()` to that store. Subscribing nodes periodically pull mirror URLs from the wallet and fetch delta/full-tree files from them via `http_download()`, which performs an unrestricted `aiohttp` GET to the attacker-chosen URL, with no scheme/host allow-listing. This is the same bug class as the reported gradio issue: a user-supplied URL is dereferenced by server-side code with no restriction on the destination, enabling SSRF.

### Finding Description
`DataLayer.subscribe()` accepts a caller-supplied list of `urls` and stores them essentially unvalidated (only `rstrip("/")` is applied) as `ServerInfo` for a store id: [1](#0-0) 

Separately, `add_mirror()` lets any store owner publish mirror `urls` on-chain via wallet RPC `dl_new_mirror`, with only an empty-list check: [2](#0-1) 

Other nodes that subscribe to that store synchronize these URLs into their local subscription state without any validation: [3](#0-2) 

During the periodic sync loop, `fetch_and_validate()` iterates over these server URLs and calls `insert_from_delta_file()` → `download_file()` → `http_download()`, which performs a plain `aiohttp` GET against `server_info.url + "/" + filename` with no scheme or destination restriction (no blocking of `localhost`, private/link-local ranges such as `169.254.169.254`, or non-HTTP schemes): [4](#0-3) 

The project's own internal notes acknowledge that "Plugin and mirror URLs are external trust inputs," but the mitigation described there (verifying *downloaded data* against wallet-advertised roots) does nothing to prevent the *request itself* from being sent to an attacker-chosen internal target: [5](#0-4) 

This mirrors the gradio `save_url_to_cache` SSRF: a URL under attacker control (mirror URL published on-chain, or directly via the local `subscribe`/`add_mirror` RPCs) is dereferenced server-side without restricting the target host/scheme.

### Impact Explanation
Any wallet user can create a DataLayer store and publish (via a small on-chain fee) a mirror URL pointing at an internal-only resource (e.g. a cloud metadata endpoint, an internal admin panel, or another local service bound to `127.0.0.1`/private network). Any other DataLayer node that subscribes to that store — a completely normal, low-trust action for consuming public DataLayer data — will have its `fetch_and_validate()` background loop automatically issue outbound GET requests to that attacker-chosen destination on a recurring basis, with the response body written to disk as a "delta file" attempt. This can be used to probe/scan internal network services from the victim's environment, hit cloud metadata services, or interact with internal HTTP endpoints that perform state changes on GET. This fits the "Data Layer roots and proofs" / "Data Layer client" reachable surface explicitly in scope.

### Likelihood Explanation
Likelihood is high: creating a store and adding a mirror requires only a wallet transaction (a normal user action, no special privilege), and getting a victim to subscribe is a standard DataLayer usage pattern (subscribing to publicly advertised stores is the intended workflow). No malicious peer/node behavior or protocol-level attack is required — it is a pure application-logic SSRF triggered by ordinary wallet/DataLayer RPC calls.

### Recommendation
Validate and restrict mirror/subscription URLs before they are persisted and before `http_download()`/`download_file()` dereference them: enforce an `http(s)` scheme allow-list, resolve and reject destinations in loopback, link-local, and private IP ranges (and re-validate after any redirect), and consider making this restriction configurable but secure-by-default, mirroring the fix pattern used for the gradio SSRF (URL/target validation prior to fetch in `save_url_to_cache`-equivalent code, here `http_download()` in `chia/data_layer/download_data.py`).

### Proof of Concept
1. Attacker creates a DataLayer store and calls the `add_mirror` RPC (`chia/data_layer/data_layer_rpc_api.py` `add_mirror`) with `urls=["http://169.254.169.254"]` (or `http://127.0.0.1:<internal-port>`).
2. Victim node discovers/subscribes to the attacker's store via `subscribe()` (`chia/data_layer/data_layer.py:895`).
3. Victim's background `periodically_manage_data()` → `update_subscription()` → `update_subscriptions_from_wallet()` pulls the attacker's mirror URL into `ServerInfo` (`chia/data_layer/data_layer.py:979-985`).
4. `fetch_and_validate()` → `insert_from_delta_file()` → `download_file()` → `http_download()` issues a GET to the attacker-controlled/internal URL (`chia/data_layer/download_data.py:298-319`), demonstrating SSRF from the victim's node.

```python
        parsed_urls = [url.rstrip("/") for url in urls]
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
```
