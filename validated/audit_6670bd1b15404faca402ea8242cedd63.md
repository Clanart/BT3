### Title
Aggregator accepts unauthenticated `Setup` requests when `client_verification=false`, letting any caller trigger N-of-N round configuration - (File: core/src/servers.rs)

### Summary
`create_grpc_server` in `core/src/servers.rs` selects `Interceptors::Noop` whenever `config.client_verification == false`, and `Noop::call` in `core/src/rpc/interceptors.rs` returns `Ok(req)` unconditionally with no certificate check. `create_aggregator_grpc_server` only logs a `tracing::warn!` when verification is enabled and does nothing to force verification when it is disabled, so the aggregator's `Setup` RPC is fully reachable by any TCP client that can complete the server-side TLS handshake.

### Finding Description
The binding this should enforce is: `caller_identity == aggregator_cert || caller_identity == our_cert` (as checked by `only_aggregator_and_self`, `core/src/rpc/interceptors.rs:36-77`) before any state-changing aggregator RPC executes. When `config.client_verification` is `false`, `create_grpc_server` (`core/src/servers.rs:106-138`) builds a TLS config with no `client_ca_root` and wires `InterceptedService::new(service, Noop)` instead of `OnlyAggregatorAndSelf`. `Noop::call` (`core/src/rpc/interceptors.rs:30`) simply returns `Ok(req)`, so the equality is never evaluated — any TLS client (with no client certificate, since none is required) reaches the handler. `create_aggregator_grpc_server` (`core/src/servers.rs:293-317`) does not override or force `client_verification = true`; it just emits a warning in the *enabled* branch and is silent in the disabled branch, meaning the insecure default flows straight into `create_grpc_server`.

Given this, an attacker who can open a TCP/TLS connection to the aggregator's advertised gRPC port (server TLS identity is still required, but client certs are not checked) can invoke `ClementineAggregator::setup` directly, since the `Setup` RPC has no additional authorization check beyond the interceptor layer.

### Impact Explanation
This matches the "unauthenticated state-changing or broadcasting call" category. `setup` mutates verifier/operator round-configuration state (`check_compatibility_with_actors`, `fetch_operator_keys`, `fetch_verifier_keys`, broadcast of operator params to all verifiers) that gates subsequent N-of-N signing sessions. An unprivileged party could repeatedly invoke `Setup`, forcing internal re-coordination among verifiers/operators without holding any key share or certificate. This is a configuration/coordination-state issue rather than a direct fund-movement primitive by itself, but it is an unauthenticated state-changing call reachable purely over gRPC.

### Likelihood Explanation
The precondition is explicit and deployment-controlled: `client_verification=false` must be set in the aggregator's `BridgeConfig`. Per the question framing this is described as the "documented default posture," but this could not be independently confirmed from the accessible `core/src/config/mod.rs`/`env.rs` default values or from deployment configs within the tool budget available — those files matched `client_verification` but their exact default value was not read before the iteration budget was exhausted. If `client_verification=false` is indeed the shipped default (or a supported/likely production configuration), the attack requires only network reachability to the aggregator's public port and no BTC cost, making it trivially repeatable.

### Recommendation
- Make `create_aggregator_grpc_server` refuse to start (or hard-fail) when `config.client_verification == false`, rather than only warning; the aggregator is a privileged coordination endpoint and should never run with `Noop` in production.
- Alternatively, decouple TLS client-cert verification from the interceptor selection: always require `OnlyAggregatorAndSelf`-style authorization for state-changing RPCs like `Setup`, independent of `client_verification`, or add an explicit authorization check inside `ClementineAggregator::setup` itself.
- Ensure `client_verification` cannot default to `false` in shipped configs (`core/src/config/env.rs`, `core/src/config/mod.rs`) for aggregator deployments — this needs confirmation of the actual default before treating it as remediation-complete.

pub async fn create_aggregator_grpc_server(
    config: BridgeConfig,
) -> Result<(std::net::SocketAddr, oneshot::Sender<()>), BridgeError> {
    let addr: std::net::SocketAddr = format!("{}:{}", config.host, config.port)
        .parse()
        .wrap_err("Failed to parse address")?;
    let aggregator_server = AggregatorServer::new(config.clone()).await?;
    aggregator_server.start_background_tasks().await?;

    let svc = ClementineAggregatorServer::new(aggregator_server)
        .max_encoding_message_size(config.grpc.max_message_size)
        .max_decoding_message_size(config.grpc.max_message_size);

    if config.client_verification {
        tracing::warn!("Client verification is enabled on aggregator gRPC server",);
    }

    let (server_addr, shutdown_tx) =
        create_grpc_server(addr.into(), svc, "Aggregator", &config).await?;

fn only_aggregator_and_self(
    req: Request<()>,
    our_cert: &CertificateDer<'static>,
    aggregator_cert: &CertificateDer<'static>,
) -> Result<Request<()>, Status> {
    let Some(peer_certs) = req.peer_certs() else {
        if cfg!(test) {
            // Test mode, we don't need to verify peer certificates
            return Ok(req);
        } else {
            // If we're not in test mode, we need to check peer certificates
            return Err(Status::unauthenticated(
                "Failed to verify peer certificate, is TLS enabled?",
            ));
        }
    };

    // IMPORTANT: Only check the leaf (end-entity) certificate, which is always the first
    // certificate in the chain. The leaf is the only certificate whose private key the peer
    // proved possession of during the TLS handshake. Checking anywhere else in the chain
    // would allow identity spoofing: an attacker could include a pinned cert as an
    // intermediate in their chain without possessing its private key.
    let Some(leaf_cert) = peer_certs.first() else {
        return Err(Status::unauthenticated("Peer certificate chain is empty"));
    };

    if is_internal(&req) {
        if leaf_cert == our_cert {
            Ok(req)
        } else {
            Err(Status::unauthenticated(
                "Unauthorized call to internal method (not self)",
            ))
        }
    } else if leaf_cert == aggregator_cert || leaf_cert == our_cert {
        Ok(req)
    } else {
        Err(Status::unauthenticated(
            "Unauthorized call to method (not aggregator or self)",
        ))
    }
}
