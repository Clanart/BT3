### Title
Silent data-integrity failure on invalid embedded bytes in `LazyFieldLite` merge/parse paths - (File: `java/core/src/main/java/com/google/protobuf/LazyFieldLite.java`)

### Summary
The external report flags `transfer()`/`transferFrom()` calls whose boolean return value is discarded, so a failed token transfer is silently treated as success, corrupting the caller's accounting. The Protobuf analog is `LazyFieldLite`'s lazy-parse/merge machinery, which catches `InvalidProtocolBufferException` for corrupted embedded-message bytes and silently discards the error — returning the *old* (or default) value with no signal to the caller — so a parse "failure" is silently treated as a no-op success, corrupting message state without any indication to the consuming application.

### Finding Description
`LazyFieldLite` defers parsing of an embedded/extension message's bytes until first access. Three code paths swallow `InvalidProtocolBufferException` and continue as if nothing happened:

- `ensureInitialized()` catches the exception, sets `corrupted = true`, and substitutes the default instance for `value` — with the comment "Nothing is logged and no exceptions are thrown. Clients will be unaware that this proto was invalid." [1](#0-0) 
- `mergeFrom(CodedInputStream, ExtensionRegistryLite)` catches the exception during a merge and simply keeps the prior `value`, again with "Nothing is logged and no exceptions are thrown." [2](#0-1) 
- `mergeValueAndBytes(...)`, used by `merge(LazyFieldLite)`, catches the exception and returns the original `value` unchanged. [3](#0-2) 

The attacker-controlled value is the length-delimited byte payload for a `LazyFieldLite`-backed message/extension field (bounded, ordinary Protobuf binary input via a supported parse/merge API). The failed invariant is that a failed sub-message parse must be observable to the caller (either via exception or an explicit corrupted flag check); instead, the caller of `mergeFrom`/`merge`/`getValue()` on the lite API gets a value that silently diverges from what the wire bytes actually encoded, with no exception and no return-value signal — the missing check is exactly the "check the return/outcome of the operation" pattern the external report calls out for `transfer()`.

By contrast, the full-runtime counterpart `InternalLazyField` treats corruption as an explicit, propagated failure: `ensureInitialized()` re-throws on corruption, and callers either surface `InvalidProtobufRuntimeException` or intentionally opt into the documented "old behavior" of returning the default instance — a conscious, visible choice, not a silent swallow. [4](#0-3) [5](#0-4)  `LazyFieldLite` has no such propagation path for its `mergeFrom`/`merge` callers; only `isCorrupted()` exists as a package-private flag that ordinary API consumers never check. [6](#0-5) 

### Impact Explanation
This is a data-integrity issue analogous to the "silent transfer failure" pattern: an application merging a lazily-parsed protobuf field (e.g., accumulating extension data across multiple wire chunks, or merging two builders) can silently lose or fail to apply an update when the incoming bytes for that specific sub-message are malformed, while the rest of the outer message parses successfully and no error is raised anywhere in the call chain. Downstream logic that assumes a successful `mergeFrom`/`merge()` call means the field now reflects the input can operate on stale/default data, mirroring the token-accounting corruption described in the report, but for message-state accounting instead of ERC20 balances. This does not crash the process and is bounded to a single field's semantics, which keeps it below Critical, but it is a genuine, exploitable integrity gap with a normal client-supplied payload.

### Likelihood Explanation
High likelihood of reachability: any application using the Protobuf Lite runtime with extensions/lazily-parsed sub-messages (a common configuration for size-constrained mobile/embedded targets) that calls `mergeFrom` (stream) or `merge` (other `LazyFieldLite`) on a field whose serialized bytes are attacker-influenced will hit this path whenever those bytes are malformed for that message type — no special conditions, privileges, or races are required beyond supplying invalid embedded bytes in an otherwise well-formed outer message.

### Recommendation
Do not silently discard `InvalidProtocolBufferException` in `LazyFieldLite.ensureInitialized()`, `mergeFrom(CodedInputStream, ExtensionRegistryLite)`, and `mergeValueAndBytes(...)`. At minimum, propagate the failure to the caller (throw, or return a status the caller must check) rather than only setting the internal `corrupted` flag that public/lite API consumers have no way to inspect, bringing the lite path's behavior in line with `InternalLazyField`'s explicit-failure model.

### Proof of Concept
1. Construct a message `Outer` containing a lazily-parsed field/extension of type `Inner` (`LazyFieldLite`-backed).
2. Populate `Outer` with a first, valid, non-default `Inner` sub-message so `this.value != null` (forces the `merge`/`mergeValueAndBytes` code path rather than the "adopt other" fast path).
3. Serialize a second byte payload for the same field that is *not* a valid `Inner` encoding (e.g., a malformed length-delimited byte sequence), and feed it into `LazyFieldLite.mergeFrom(CodedInputStream, ExtensionRegistryLite)` or `merge(LazyFieldLite other)` for the field already holding the valid `Inner` value.
4. Observe: no exception is thrown from `mergeFrom`/`merge`; `getValue()` afterward returns the original (unmerged) `Inner` value unchanged [2](#0-1) [3](#0-2) , i.e., the caller cannot distinguish "successful no-op merge" from "corrupted input silently dropped" — confirming the missing-check/silent-failure analog to the external report's unchecked `transfer()` return value.

  private void ensureInitialized() throws InvalidProtocolBufferException {
    if (value != null) {
      return;
    }

    synchronized (this) {
      if (corrupted) {
        throw new InvalidProtocolBufferException("Repeat access to corrupted lazy field");
      }
      try {
        // `bytes` is guaranteed to be non-null since `value` was null.
        CodedInputStream input = bytes.newCodedInput();
        input.enableAliasing(/* enabled= */ true);
        // When lazyExtensionEnabled() returns true, it means all extensions including MessageSet's
        // will be fully parsed. When it returns false, it basically implies this can only be a
        // MessageSet extension, and we should fall back to the old behavior of silently returning
        // the default instance on corrupted extensions i.e. a full parse.
        value =
            extensionRegistry.lazyExtensionEnabled()
                ? defaultInstance.getParserForType().parsePartialFrom(input, extensionRegistry)
                : defaultInstance.getParserForType().parseFrom(input, extensionRegistry);
        input.checkLastTagWas(0);
      } catch (InvalidProtocolBufferException e) {
        corrupted = true;
        throw e;
      }
    }
  }
