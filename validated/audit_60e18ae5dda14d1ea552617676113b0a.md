### Title
Unauthenticated `InternalSendTx` broadcast on the aggregator's public gRPC port - (`core/src/rpc/aggregator.rs`, `core/src/rpc/interceptors.rs`)

### Summary
`ClementineAggregator::internal_send_tx` forwards an attacker-supplied raw Bitcoin transaction straight to `tx_sender.insert_try_to_send` with no validation of its contents, relying solely on the `is_internal`/`OnlyAggregatorAndSelf` certificate check to restrict it to the aggregator itself. When the server runs with `Interceptors::Noop` (`client_verification == false`), that check never executes, so any network caller reaching the aggregator's gRPC port can invoke `InternalSendTx` and have it enqueued for broadcast/fee-management.

### Finding Description
The intended binding is: `caller of an Internal-prefixed RPC == our_cert (the server's own client certificate)`, enforced in `only_aggregator_and_self` via `is_internal(req)` and `leaf_cert == our_cert` [1](#0-0) . That function is only reached through `Interceptors::OnlyAggregatorAndSelf`; under `Interceptors::Noop` the interceptor is a pass-through and performs no certificate check at all [2](#0-1) .

`create_grpc_server` selects `Noop` whenever `config.client_verification` is `false`, and this same function is used to build the aggregator's server [3](#0-2) [4](#0-3) . `docs/usage.md` documents this as intentional for the aggregator: "The aggregator does not enforce client certificates but does use TLS for encryption" [5](#0-4) .

`internal_send_tx` itself performs zero authorization or content validation beyond deserializing the transaction and forwarding it: it deserializes `raw_tx` into a `bitcoin::Transaction` and calls `tx_sender.insert_try_to_send` with the attacker-chosen `fee_type` [6](#0-5) . `insert_try_to_send` only checks for a duplicate txid before persisting the transaction into the send queue with the specified `FeePayingType` [7](#0-6) ; there is no check that the transaction relates to any legitimate bridge operation.

Given the rules' stated attacker capability of sending requests to "the aggregator's public gRPC port," and the fact that the aggregator's documented/intended deployment does not enforce client certificates, an unprivileged attacker can call `InternalSendTx` directly with a syntactically valid `SendTxRequest{raw_tx, fee_type}` and have it accepted into the aggregator's `tx_sender` queue with no certificate, no key, and no prior interaction with the bridge.

### Impact Explanation
This is an unauthenticated, state-changing/broadcasting call reachable on the aggregator's public interface, matching the High-severity category "an unauthenticated state-changing or broadcasting call." It does not by itself let the attacker spend bridge UTXOs — the attacker cannot forge valid signatures for bridge-controlled inputs, so `SECP.verify_schnorr`/consensus validation on the Bitcoin network still blocks any transaction spending real bridge funds from actually confirming. However, the aggregator's own fee-paying infrastructure (CPFP/RBF via `tx_sender`) can be made to track and fee-bump an attacker-chosen transaction using the aggregator's own signing/fee-paying wallet, entirely outside of any legitimate protocol transaction type, at the attacker's unilateral direction and with no authentication. This is repeatable per request with no per-caller limit tied to the vulnerability itself (rate limiting/resource exhaustion aspects are explicitly out of scope per the rules).

### Likelihood Explanation
Preconditions: the aggregator is deployed with `client_verification = false` (i.e., `Interceptors::Noop`), which is the behavior documented as intended for the aggregator in `docs/usage.md`. No TLS client certificate, key, or bridge participation is required — only network reachability to the aggregator's gRPC port, which the threat model explicitly grants. Attacker cost is limited to constructing a syntactically valid `SendTxRequest`; feasibility is high and trivially repeatable.

### Recommendation
Do not rely solely on `client_verification` to gate `InternalSendTx` and other `Internal`-prefixed aggregator RPCs. Enforce authentication/authorization for `Internal`-prefixed methods on the aggregator independent of the `client_verification` toggle (e.g., always require `OnlyAggregatorAndSelf`-style self-cert checking for `Internal*` RPCs, or bind these RPCs only to a loopback/Unix-socket listener not exposed on the public gRPC port), and additionally validate that `internal_send_tx`'s `raw_tx` corresponds to a transaction the aggregator itself previously constructed/tracks before enqueuing it.

### Proof of Concept
```
cargo test -p clementine-core --features automation -- internal_send_tx_unauthenticated
```
Test plan:
1. Start an aggregator gRPC server via `create_aggregator_grpc_server`/`create_aggregator_unix_server` with `config.client_verification = false`.
2. Connect a bare client with no client certificate configured (or using `Interceptors::Noop` path directly).
3. Send `InternalSendTx` with an attacker-crafted, syntactically valid `bitcoin::Transaction` (e.g., spending an arbitrary/attacker-owned outpoint) wrapped in `SendTxRequest{raw_tx, fee_type: FeeType::Cpfp}`.
4. Assert the RPC returns `Ok(Empty {})` rather than `Status::unauthenticated`, and assert the transaction row exists in the tx_sender DB queue (`check_if_tx_exists_on_txsender`/`get_try_to_send_tx`), demonstrating it reached `tx_sender().insert_try_to_send` with no certificate presented — i.e., `leaf_cert == our_cert` was never evaluated.

pub async fn create_aggregator_grpc_server(
    config: BridgeConfig,
) -> Result<(std::net::SocketAddr, oneshot::Sender<()>), BridgeError> {
    let addr: std::net::SocketAddr = format!("{}:{}", config.host, config.port)
        .parse()
        .wrap_err("Failed to parse address")?;
    let aggregator_server = AggregatorServer::new(config.clone()).await?;
    aggregator_server.start_background_tasks().await?;

    let svc = ClementineAggregatorServer::new(aggregator_server)
        .max_encoding_message_size(config.grpc.max_message_size)
        .max_decoding_message_size(config.grpc.max_message_size);

    if config.client_verification {
        tracing::warn!("Client verification is enabled on aggregator gRPC server",);
    }

    let (server_addr, shutdown_tx) =
        create_grpc_server(addr.into(), svc, "Aggregator", &config).await?;

    match server_addr {
        ServerAddr::Tcp(socket_addr) => Ok((socket_addr, shutdown_tx)),
        _ => Err(BridgeError::ConfigError("Expected TCP address".into())),
    }
}

                .raw_tx

                .try_into()?;
            tracing::warn!(
                "Internal send tx rpc called with feetype: {:?}, tx hex: {}",
                fee_type,
                bitcoin::consensus::encode::serialize_hex(&signed_tx)
            );

            let mut dbtx = self.db.begin_transaction().await?;
            self.tx_sender
                .insert_try_to_send(
                    &mut dbtx,
                    None,
                    &signed_tx,
                    fee_type.try_into()?,
                    None,
                    &[],
                    &[],
                    &[],
                    &[],
                )
                .await
                .map_to_status()?;
            dbtx.commit()
                .await
                .map_err(|e| Status::internal(format!("Failed to commit db transaction: {e}")))?;
            Ok(Response::new(Empty {}))
        }
    }

    pub async fn insert_try_to_send(
        &self,
        dbtx: &mut crate::TxSenderTransaction,
        tx_metadata: Option<TxMetadata>,
        signed_tx: &Transaction,
        fee_paying_type: FeePayingType,
        rbf_signing_info: Option<RbfSigningInfo>,
        cancel_outpoints: &[OutPoint],
        cancel_txids: &[Txid],
        activate_txids: &[ActivatedWithTxid],
        activate_outpoints: &[ActivatedWithOutpoint],
    ) -> Result<u32, BridgeError> {
        let txid = signed_tx.compute_txid();

        // do not add duplicate transactions to the txsender
        let tx_exists = self
            .db
            .check_if_tx_exists_on_txsender(Some(dbtx), txid)
            .await?;
        if let Some(try_to_send_id) = tx_exists {
            return Ok(try_to_send_id);
        }

        tracing::info!(
            "Added tx {} with txid {} to the queue",
            tx_metadata
                .as_ref()
                .map(|data| format!("{:?}", data.tx_type))
                .unwrap_or("N/A".to_string()),
            txid
        );

        let try_to_send_id = self
            .db
            .save_tx(
                dbtx,
                tx_metadata,
                signed_tx,
                fee_paying_type,
                txid,
                rbf_signing_info,
            )
            .await?;
