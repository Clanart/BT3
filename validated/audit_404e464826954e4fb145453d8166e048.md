### Title
SignableTransaction trusts attacker-supplied `ReceivedOutput` prevout amounts/outpoints — FROST signs transactions burning funds to fees - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
The bug class in the external report is *untrusted, externally-supplied values copied into privileged network/signing state without validation*. In bitcoin-serai, `ReceivedOutput` can be deserialized from arbitrary bytes via `ReceivedOutput::read` (`networks/bitcoin/src/wallet/mod.rs:122-134`) and fed directly into `SignableTransaction::new`. Only the `script_pubkey` is validated (indirectly, in `SignableTransaction::multisig`); the `value` and `outpoint` fields are trusted verbatim — they drive fee/change arithmetic and are committed into the Taproot sighash via `Prevouts::All`. A malicious input descriptor therefore causes the threshold group to sign a transaction that either spends a nonexistent outpoint (invalid TX, DoS of a signing round) or silently burns real funds as miner fees.

### Finding Description
`ReceivedOutput::read` parses `offset`, `output` (a full `TxOut` including `value`), and `outpoint` purely from the byte stream, with no check that `outpoint` refers to a real UTXO carrying that `output` [1](#0-0) .

`SignableTransaction::new` consumes `inputs: Vec<ReceivedOutput>` and uses `input.output.value` to compute `input_sat`, the fee check, and the change amount, and stores `input.output` into `prevouts` [2](#0-1) .

`SignableTransaction::multisig` verifies only that `p2tr_script_buf(keys.offset(offset).group_key()) == prevouts[i].script_pubkey` — the key/script binding is checked, but the *amount* and *outpoint* are never compared against the chain state [3](#0-2) .

`TransactionSignMachine::sign` then commits to these unvalidated prevouts with `Prevouts::All(&self.tx.prevouts)` under `TapSighashType::Default`, so every participant produces a valid BIP-340 signature over the attacker-chosen amounts [4](#0-3) .

Two exploitable directions:

1. **Understated `value`**: attacker declares `output.value` lower than the real UTXO at `outpoint` (or a real script-matching UTXO of theirs). The signed transaction is consensus-valid, but the difference between the actual input value and `input_sat` becomes implicit miner fee — permanent, silent fund loss distributed to miners.
2. **Overstated `value` / fake `outpoint`**: the signed transaction is invalid and unbroadcastable — a full FROST signing ceremony (preprocess + sign + complete over all inputs) is wasted, and if the invalid TX is submitted it permanently marks the ceremony's outputs as spent in bookkeeping.

### Impact Explanation
Confidentiality: none. Integrity/Availability: the threshold group produces a genuine, attacker-influenced signature over a transaction committing to false prevout amounts. With an understated value this is a direct, unrecoverable loss of funds (excess paid as fee) with no error surfaced — the signature verifies fine and the TX is valid. With an inflated value or fake outpoint it is a reliable signing-round/availability DoS on the multisig wallet. This matches the report's pattern: an unprivileged party's unvalidated input is programmed into the privileged data plane (here, the signed sighash), like an externalIP matching a ClusterIP replacing legitimate state.

### Likelihood Explanation
Requires an attacker able to supply the `Vec<ReceivedOutput>` (or serialized bytes reaching `ReceivedOutput::read`) consumed by the wallet's transaction-building path — e.g., a coordinator, an API endpoint, or a peer that provides input descriptors rather than the local `Scanner`. Any deployment where inputs to `SignableTransaction::new` aren't exclusively self-scanned is exposed. No cryptographic break, no collusion, no validator misbehavior needed — just untrusted bytes into a documented parse function. Medium severity.

### Recommendation
- In `SignableTransaction::new`/`multisig`, verify each `ReceivedOutput`'s `outpoint` resolves on-chain (or accept a verified UTXO set) and that `output.value`/`script_pubkey` equal the confirmed UTXO — not just the script/key binding.
- Mark `ReceivedOutput::read` as trusted-input-only, or add an authenticated/verified variant that binds `outpoint → TxOut` before wallet use.
- Treat the `Prevouts::All` commitment as authoritative: since signatures commit to declared amounts, false amounts must be rejected before `preprocess`.

### Proof of Concept
```rust
// Attacker knows a real received output `real` for key+offset o
// (e.g., a deposit they made). They craft:
let mut evil = real.clone();
// Decrease declared value: real UTXO is 100_000 sat, declare 60_000
evil.output.value = Amount::from_sat(60_000);
// Serialize/deserialize boundary where untrusted bytes enter:
let bytes = evil.serialize();
let input = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();

// Wallet builds a tx paying 50_000 sat with ~1_000 sat declared fee
let tx = SignableTransaction::new(vec![input], &payments, Some(change), None, fee).unwrap();
// multisig() passes: script_pubkey still matches key + offset
let machine = tx.clone().multisig(&keys).unwrap();
// Group signs with Prevouts::All committing to value = 60_000
let signed = sign(&keys, &tx);
// On-chain: input actually provides 100_000 sat; outputs total ~59_000.
// ~41_000 sat are silently burned as miner fee. TX is fully valid.
```
Variant: set `outpoint` to a nonexistent TXID — `complete` still returns a signed transaction that can never be broadcast, consuming a full threshold ceremony.

    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;

      let mut buf_r = BufReader::with_capacity(0, r);

      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }
