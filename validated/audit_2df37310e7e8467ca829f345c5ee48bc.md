### Title
Loss of funds sent directly to the un-initialized `CnStakingV4` implementation (beacon logic) contract - (File: `blockchain/system/permissionless.go`)

### Summary
The permissionless staking allocation path deploys a standalone `CnStakingV4` implementation contract that is only ever meant to be used as delegatecall logic behind `UpgradeableBeacon`/`BeaconProxy` instances. That implementation contract itself is a live, independently addressable contract with a public `receive() external payable` function, and its constructor permanently disables `initialize()` via OpenZeppelin's `_disableInitializers()` pattern. Any KAIA sent directly to this raw implementation address is accepted by `receive()` but can never be recovered, because the contract's owner/admin state is never set and `initialize()`/`initializeWithPD()` are blocked forever.

### Finding Description
`deployBeaconInfra` deploys the `CnStakingV4` logic contract directly via `evmCreate` and only afterwards wraps it in an `UpgradeableBeacon`, which `CnStakingV4Factory` uses to create per-validator `BeaconProxy` clones: [1](#0-0) 

The `CnStakingV4` ABI shows a payable `receive` entry, meaning the implementation contract (like any deployed clone) accepts bare ETH transfers with no restriction: [2](#0-1) 

The constructor bytecode of `CnStakingV4` calls OpenZeppelin's `_disableInitializers()` guard (checking/setting the `Initializable` storage slot and reverting with `InvalidInitialization()` if already initializing), which permanently prevents `initialize(address _owner)` / `initializeWithPD(...)` from ever succeeding on this specific deployed instance: [3](#0-2) 

Because `owner` is never set on this instance, and initializer functions are permanently blocked, none of the owner-gated withdrawal/admin functions can ever be exercised on it. This is the exact bug class from the source report: a shared "base"/"logic" contract instance that accepts ETH via an unguarded payable entry point but has no path to recovery because it is intentionally never initialized.

### Impact Explanation
Any KAIA (native token) sent directly to the `CnStakingV4` implementation address — which is publicly discoverable via `CnStakingV4Factory.cnStakingBeacon()` → `UpgradeableBeacon.implementation()` — is irrecoverably locked. This is a genuine, unrecoverable loss of funds reachable by any unprivileged sender who mistakenly or accidentally interacts with the logic contract instead of a validator's `BeaconProxy`, matching the Medium severity classification of the original report (accidental-but-realistic loss-of-funds path with no owner/withdrawal mechanism).

### Likelihood Explanation
The implementation address is a normal, permanently-deployed contract on-chain (part of genesis/permissionless allocation) and is queryable through public factory/beacon getters, so any RPC caller or wallet could target it, e.g. by copy-pasting the wrong "staking contract" address. There is no `require(address(this) != implementation)` guard or similar protection analogous to what the original SwapperImpl report recommended.

### Recommendation
Add a check in `receive()` (and any other externally payable entry point) of `CnStakingV4` to revert when called on the un-initialized/base implementation instance — e.g., guard on `owner() == address(0)` or track the canonical implementation address (as set by the beacon) and revert `receive()`/staking entry points if `address(this) == <recorded implementation address>`, mirroring the SwapperImpl fix recommendation of rejecting calls on the un-clone-initialized base contract.

### Proof of Concept
1. Read `CnStakingV4Factory.cnStakingBeacon()` to get the beacon address, then read `UpgradeableBeacon.implementation()` to obtain the `CnStakingV4` logic contract's address (as deployed in `deployBeaconInfra`, see `blockchain/system/permissionless.go:191-210`).
2. Send a plain KAIA transfer transaction to that implementation address; `receive() external payable` (per `CnStakingV4MetaData.ABI`) accepts it.
3. Attempt `initialize(owner)` / `initializeWithPD(...)` on the same address — both revert because the constructor already called `_disableInitializers()` (visible in the constructor bytecode of `CnStakingV4Bin`).
4. With `owner == address(0)` and initializers permanently disabled, no `onlyOwner` withdrawal path can ever be invoked on this instance — the sent KAIA is permanently stuck.
