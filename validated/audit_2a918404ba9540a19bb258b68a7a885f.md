### Title
Untrusted `ReceivedOutput` values can overflow input totals and crash transaction creation - ([File: networks/bitcoin/src/wallet/send.rs](networks/bitcoin/src/wallet/send.rs))

### Summary
`ReceivedOutput::read` accepts a consensus-decoded `TxOut` without constraining its `value` field. `SignableTransaction::new` then sums all attacker-controlled output values with `sum::<u64>()` and uses unchecked addition for payment and fee totals. Multiple outputs with large `u64` values overflow the input total, producing a deterministic panic when overflow checks are enabled, or a wrapped balance when they are disabled.

### Finding Description
`ReceivedOutput::read` deserializes an arbitrary scalar, `TxOut`, and `OutPoint` directly from bytes [1](#0-0) . `SignableTransaction::new` accepts the resulting outputs and calculates `input_sat` using an unchecked `u64` sum [2](#0-1) . It subsequently uses unchecked arithmetic in `payment_sat + needed_fee` and `input_sat.checked_sub(payment_sat + fee_with_change)` [3](#0-2) .

Two decoded outputs whose values are each `u64::MAX` overflow `sum::<u64>()`. In a debug build, or a release build with `overflow-checks = true`, this reliably aborts the caller. Without overflow checks, the sum wraps, causing later payment, change, and fee calculations to operate on a false balance.

### Impact Explanation
This is an externally reachable availability failure: untrusted bytes passed to `ReceivedOutput::read` can cause a repeatable panic during transaction construction. If overflow checks are disabled, the same input causes an incorrect wrapped balance and fee calculation rather than a crash.

### Likelihood Explanation
The attacker only needs to supply two syntactically valid serialized `ReceivedOutput` values containing extreme `TxOut` amounts. No malformed point encoding, private state, validator privilege, or protocol collusion is required.

### Recommendation
Reject outputs whose `Amount` exceeds Bitcoin's maximum money range or use checked arithmetic for `input_sat`, `payment_sat`, `needed_fee`, and all output-value totals. Return `TransactionError::NotEnoughFunds` or a dedicated overflow error instead of panicking or wrapping.

### Proof of Concept
Each serialized `ReceivedOutput` is:

```text
32-byte canonical zero secp256k1 scalar
8-byte little-endian TxOut value = ff ff ff ff ff ff ff ff
1-byte empty script length      = 00
32-byte txid                    = 00 ... 00
4-byte little-endian vout       = 00 00 00 00
```

```rust
use bitcoin::ScriptBuf;
use serai_bitcoin::wallet::{ReceivedOutput, SignableTransaction};

fn read_output(bytes: &[u8]) -> ReceivedOutput {
  ReceivedOutput::read(&mut &bytes[..]).unwrap()
}

let mut output = Vec::new();
output.extend([0; 32]);                    // offset = zero scalar
output.extend(u64::MAX.to_le_bytes());      // TxOut.value
output.push(0);                            // empty script_pubkey
output.extend([0; 32]);                    // txid
output.extend(0u32.to_le_bytes());         // vout

let inputs = vec![read_output(&output), read_output(&output)];
let payments = vec![(ScriptBuf::new(), 546)];

// Panics on integer overflow when overflow checks are enabled.
let _ = SignableTransaction::new(inputs, &payments, None, None, 1);
```
