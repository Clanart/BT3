### Title
Auction bid pool state corruption allows griefing/DoS of MEV auction slots via post-insertion gas-limit failure - ([File: kaiax/auction/impl/bid_pool.go])

### Summary
`BidPool.AddBid` inserts a bid into the shared pool state (`bidMap`, `bidTargetMap`, `bidWinnerMap`) via `insertBid` **before** validating that the bid's derived gas limit can be computed via `getBidTxGasLimit`. If that later step fails, `AddBid` returns an error to the caller, but the bid remains committed in the pool's maps because there is no rollback path.

### Finding Description
`AddBid` performs the sequence: `validateBid` → `insertBid` → `getBidTxGasLimit` → `SetGasLimit` → dispatch on `newBidCh`. [1](#0-0) 

`insertBid` unconditionally writes the bid into `bp.bidMap[hash]`, claims the `(blockNumber, targetTxHash)` slot in `bp.bidTargetMap`, and claims the `(blockNumber, sender)` slot in `bp.bidWinnerMap` under `bidMu.Lock()`: [2](#0-1) 

Only afterward does `AddBid` call `getBidTxGasLimit`, which can fail (e.g. `system.EncodeAuctionCallData` error, `types.IntrinsicGas` error) and return an error: [3](#0-2) 

When this happens, `AddBid` returns the error to the caller without ever removing the just-inserted bid from `bidMap`/`bidTargetMap`/`bidWinnerMap`, and without sending it on `newBidCh` (so it is never surfaced to the auction consumer/dispatch feed). The bid permanently (until block expiry via `removeOldBids`) occupies:
- the winner slot `bidWinnerMap[blockNumber][sender]`, which blocks the same sender from submitting any other (non-identical) bid for that block via `senderHasDifferentWinner`, [4](#0-3) 
- the target slot `bidTargetMap[blockNumber][targetTxHash]`, which only accepts a strictly higher bid (`existingBid.Bid.Cmp(bid.Bid) >= 0` → reject), [5](#0-4) 

This is directly analogous to the CVE-2020-25636 bug class: a shared namespace (here, per-block per-sender / per-block per-target "slots" in the bid pool) is written to without atomicity/rollback guarantees across the full validation pipeline, allowing one party's (unprivileged bidder's) request to permanently occupy a slot that legitimately belongs to future, valid requests — causing collisions and denial of service in that namespace, exactly as the original CVE describes for file-transfer namespace collisions.

### Impact Explanation
An unprivileged auction bidder (searcher) can craft a validly-signed bid (passing `validateBid`, which does not exercise `EncodeAuctionCallData`/`IntrinsicGas`) that is engineered to fail at `getBidTxGasLimit` (e.g., unsupported/edge-case entry point version or data causing an intrinsic-gas computation error) while setting `Bid` to the maximum possible value and targeting a specific `TargetTxHash`. Because `insertBid` commits the slot claim before the failure is detected, and there is no compensating removal, the attacker permanently occupies the highest-bid slot for that target transaction (and the winner slot for their own address) for the block window (`allowFutureBlock`), with no way for a real bid to replace it (since no bid can exceed the maximal value) and no way for the poisoned bid to be dispatched (since `AddBid` errored out before reaching `newBidCh`). This denies the entire MEV/gasless-auction settlement mechanism for that target transaction — a legitimate reachable "auction settlement theft/denial" as scoped (auction bidder role, gasless/auction module), causing loss of expected auction proceeds/settlement for validators/auctioneer and griefing competing searchers.

### Likelihood Explanation
High/Medium likelihood: any bidder able to call the public `SubmitBid`/`HandleBid` path can reach `AddBid` directly with attacker-controlled `Data`, `CallGasLimit`, `Bid`, and `TargetTxHash` fields; no special privilege beyond a valid EIP-712 signature pair (searcher+auctioneer sig requirement) is needed, and crafting a bid that fails gas-limit computation while still passing `validateBid`'s earlier checks is plausible given the independent code paths.

### Recommendation
Perform all bid validation, including `getBidTxGasLimit` computation, **before** calling `insertBid`, or make `insertBid` transactional: if any post-insertion step fails, explicitly roll back the `bidMap`/`bidTargetMap`/`bidWinnerMap` entries added for that bid under `bidMu.Lock()` before returning the error from `AddBid`.

### Proof of Concept
1. Attacker crafts a `Bid` with `Bid` field = maximum allowed value, `TargetTxHash` = victim's pending transaction hash, `BlockNumber` = `curNum+1`, valid `SearcherSig`/`AuctioneerSig`, and `Data`/`CallGasLimit` engineered such that `system.EncodeAuctionCallData` or `types.IntrinsicGas` in `getBidTxGasLimit` [6](#0-5)  returns an error (e.g. malformed auction-entry-point-version-specific payload).
2. Attacker submits the bid via the bid submission entrypoint, reaching `AddBid`.
3. `validateBid` passes (checks 1–6 do not exercise the gas-limit computation path) [7](#0-6) .
4. `insertBid` commits the bid into `bidMap`, `bidTargetMap[blockNumber][targetTxHash]`, and `bidWinnerMap[blockNumber][sender]` [8](#0-7) .
5. `getBidTxGasLimit` fails; `AddBid` returns an error to the caller, but the bid remains in all three maps [9](#0-8) .
6. Any subsequent legitimate bid for the same `targetTxHash` with a lower or equal `Bid` value is rejected with `ErrLowBid` [10](#0-9) , and since the attacker's `Bid` is maximal, no legitimate bid can replace it — the auction for that target transaction is permanently denied for the block window, with no bid ever dispatched via `newBidCh`.

// AddBid adds a bid to the bid pool.
// Required mutex is locked in each function.
func (bp *BidPool) AddBid(bid *auction.Bid) (common.Hash, error) {
	if atomic.LoadUint32(&bp.running) == 0 {
		return common.Hash{}, auction.ErrAuctionPaused
	}

	if err := bp.validateBid(bid); err != nil {
		return common.Hash{}, err
	}

	if err := bp.insertBid(bid); err != nil {
		return common.Hash{}, err
	}

	gasLimit, err := bp.getBidTxGasLimit(bid)
	if err != nil {
		return common.Hash{}, err
	}
	bid.SetGasLimit(gasLimit)

	bp.newBidCh <- bid

	return bid.Hash(), nil
}

func (bp *BidPool) insertBid(bid *auction.Bid) error {
	bp.bidMu.Lock()
	defer bp.bidMu.Unlock()

	var (
		blockNumber  = bid.BlockNumber
		targetTxHash = bid.TargetTxHash
		sender       = bid.Sender
	)

	// Re-check bidWinnerMap here — two concurrent bids can pass validateBid together.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		return auction.ErrBidAlreadyExists
	}
	if bp.senderHasDifferentWinner(bid) {
		return auction.ErrBidSenderExists
	}

	// If same block number, same target tx hash exists, replace it if it's better
	if existingBid, ok := bp.bidTargetMap[blockNumber][targetTxHash]; ok {
		// FCFS if the bid is the same.
		if existingBid.Bid.Cmp(bid.Bid) >= 0 {
			return auction.ErrLowBid
		}

		logger.Trace("Replace bid", "old", existingBid.Hash(), "new", bid.Hash())
		delete(bp.bidMap, existingBid.Hash())
		delete(bp.bidWinnerMap[blockNumber], existingBid.Sender)
	} else {
		if int64(len(bp.bidMap)) >= bp.maxBidPoolSize {
			logger.Info("Bid pool is full", "maxBidPoolSize", bp.maxBidPoolSize, "bid", bid.Hash())
			return auction.ErrBidPoolFull
		}
	}

	hash := bid.Hash()

	bp.initializeBidMap(blockNumber)

	bp.bidMap[hash] = bid
	bp.bidTargetMap[blockNumber][targetTxHash] = bid
	bp.bidWinnerMap[blockNumber][sender] = hash

	numBidsGauge.Update(int64(len(bp.bidMap)))

	logger.Trace("Add bid", "bid", hash)

	return nil
}

// senderHasDifferentWinner reports whether a different bid from the same sender
// already exists in the winner list for this block. Caller must hold bidMu.
func (bp *BidPool) senderHasDifferentWinner(bid *auction.Bid) bool {
	hash, ok := bp.bidWinnerMap[bid.BlockNumber][bid.Sender]
	if !ok {
		return false
	}
	return !bid.Equals(bp.bidMap[hash])
}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}

func (bp *BidPool) getBidTxGasLimit(bid *auction.Bid) (uint64, error) {
	bp.auctionInfoMu.RLock()
	buffer := bp.bidTxGasBuffer
	bp.auctionInfoMu.RUnlock()

	data, err := system.EncodeAuctionCallData(bid, bp.auctionEntryPointVersion)
	if err != nil {
		return 0, err
	}

	rules := bp.ChainConfig.Rules(big.NewInt(int64(bid.BlockNumber)))
	intrinsicGas, err := types.IntrinsicGas(data, nil, nil, false, rules)
	if err != nil {
		return 0, err
	}
	floorDataGas := uint64(0)
	if rules.IsPrague {
		floorDataGas, err = blockchain.FloorDataGas(types.TxTypeEthereumDynamicFee, data, 0)
		if err != nil {
			return 0, err
		}
	}

	return max(intrinsicGas+bid.CallGasLimit+buffer, floorDataGas), nil
}
