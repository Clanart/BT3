### Title
Users cannot `unvote` from a deactivated pool, permanently locking their vlMGP - (File: wombat/WombatBribeManager.sol)

### Summary
`WombatBribeManager.unvote()` is documented as the mechanism that lets a user pull their vote weight out of a pool that has been deactivated ("Unvote from an inactive pool. This makes it so that deleting a pool ... doesn't block users from withdrawing"), but the actual guard condition does the opposite: it reverts unless the pool is still active.

### Finding Description
`unvote()` contains:
```solidity
function unvote(address _lp) public {
    Pool storage pool = poolInfos[_lp];
    uint256 currentVote = userVotedForPoolInVlmgp[msg.sender][pool.poolAddress];
    if(!pool.isActive)
        revert PoolNotActive();
    ...
``` [1](#0-0) 

The check `if(!pool.isActive) revert PoolNotActive();` reverts precisely when the pool is inactive — the opposite of what the function's own docstring promises. `vote()` has the same "must be active" guard, which is correct for casting new votes: [2](#0-1) 

Once a pool is deactivated by governance, a user who previously voted for it (`userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] > 0`, counted in `userTotalVotedInVlmgp[msg.sender]`) has no path to zero out that vote allocation: `vote()` on that same pool also reverts with `PoolNotActive()`, and `unvote()` reverts too. This mirrors the report's root cause — the check that is supposed to reflect current, live authorization/eligibility state instead blocks the very state transition (revocation of the stale allocation) that should be always be permitted, exactly as the Zeta Chain bug prevented cleanup of a stale node-account entry.

The locked `userTotalVotedInVlmgp[msg.sender]` value then becomes unreachable, since `VLMGP.startUnlock()` explicitly enforces:
```solidity
if (address(wombatBribeManager) != address(0) &&
    totalLockAfterStartUnlock < IWombatBribeManager(wombatBribeManager).userTotalVotedInVlmgp(msg.sender))
    revert NotEnoughLockedMPG();
``` [3](#0-2) 

Because `userTotalVotedInVlmgp[msg.sender]` can never be reduced for votes cast on a now-inactive pool, the user can never unlock the corresponding amount of vlMGP-locked MGP.

### Impact Explanation
Any ordinary vlMGP holder who voted for a pool that is later deactivated has that portion of their vlMGP position permanently frozen: they cannot `unvote()` (reverts), cannot re-`vote()` on that pool to zero it out (reverts), and consequently cannot pass the `startUnlock()` check in `VLMGP.sol` to withdraw the corresponding MGP. This is a permanent freeze of user funds triggered purely by normal, unprivileged voting activity combined with a foreseeable admin action (pool deactivation), satisfying the "permanent freezing of funds" impact bar.

### Likelihood Explanation
Likelihood is high: pool deactivation is an expected, routine lifecycle event (rewarder changes, pool delisting), and any user who has voted for that pool via the standard `vote()` flow is affected with no possible self-remediation.

### Recommendation
Invert the guard in `unvote()` so it operates independent of `pool.isActive` (or explicitly allows unvoting only when inactive/always), matching the documented intent: remove the `if(!pool.isActive) revert PoolNotActive();` check from `unvote()`, or replace it with logic that always permits reducing votes on any pool (active or not) while only blocking new vote increases on inactive pools in `vote()`.

### Proof of Concept
1. User calls `vote(["poolA"], [1000])`, setting `userVotedForPoolInVlmgp[user][poolA] = 1000` and `userTotalVotedInVlmgp[user] += 1000`. [4](#0-3) 
2. Owner/governance later deactivates `poolA` (sets `poolInfos[poolA].isActive = false` via the pool management flow).
3. User calls `unvote(poolA)` to reclaim voting capacity — reverts with `PoolNotActive()` because of the inverted check. [5](#0-4) 
4. User calls `vote(["poolA"], [-1000])` to try to zero it out instead — also reverts with `PoolNotActive()` in the loop. [2](#0-1) 
5. User attempts `VLMGP.startUnlock(fullLockedAmount)` — reverts with `NotEnoughLockedMPG()` because `userTotalVotedInVlmgp(user)` (still 1000) exceeds `totalLockAfterStartUnlock`. [3](#0-2) 
6. The 1000-unit vlMGP position tied to the deactivated pool's vote is now permanently unlockable.

    /// @notice Unvote from an inactive pool. This makes it so that deleting a pool, or changing a rewarder doesn't block users from withdrawing
    function unvote(address _lp) public {
        Pool storage pool = poolInfos[_lp];
        uint256 currentVote = userVotedForPoolInVlmgp[msg.sender][pool.poolAddress];
        if(!pool.isActive)
            revert PoolNotActive();
        
        pool.totalVoteInVlmgp -= uint256(currentVote);
        userTotalVotedInVlmgp[msg.sender] -= uint256(currentVote);
        userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] = 0;
        if (msg.sender != delegatedPool) {
            totalVlMgpInVote -= currentVote;
        }
        
        IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(currentVote), true);
    }
