### Title
Instant, non-time-weighted reward distribution in `BaseRewardPool` allows flash-deposit-harvest-claim-withdraw reward theft via `WombatPoolHelper.harvest()` - (File: wombat/WombatPoolHelper.sol, rewards/BaseRewardPool.sol, wombat/WombatStaking.sol)

### Summary
`WombatPoolHelper.harvest()` is a permissionless external function that forwards to `WombatStaking.harvest(lpToken)`, which pulls all WOM/bonus rewards accrued by the pool since the last harvest and immediately queues them into `BaseRewardPool` via `queueNewRewards`. `BaseRewardPool._provisionReward` distributes the entire harvested amount instantly and proportionally to whatever `totalStaked()` is at that exact moment, with no time-weighting, vesting schedule, or minimum staking duration. An attacker can inflate `totalStaked()` immediately before calling `harvest()`, capture a large share of rewards that accrued while they held no position, then withdraw right after.

### Finding Description
`WombatStaking.harvest()` is guarded only by `whenNotPaused` and `_onlyActivePool`, not by any staker-identity or manager check, so any address (including via `WombatPoolHelper.harvest()`) can trigger it: [1](#0-0) 

`_toMasterWomAndSendReward` measures the WOM balance delta from calling `IMasterWombat.withdraw(pid, 0)` (which harvests all pending WOM accrued by the pool since the last touch) and forwards it to `_sendRewards`, which calls `IBaseRewardPool.queueNewRewards`: [2](#0-1) [3](#0-2) 

`BaseRewardPoolV2._provisionReward` (and the equivalent in `BaseRewardPool`) distributes the entire incoming reward amount by immediately bumping `rewardPerTokenStored` in proportion to current `totalStaked()`, with no per-second linear release: [4](#0-3) 

Because reward accounting is a pure `rewardPerToken` snapshot model (`earned = balance * (rewardPerToken - userRewardPerTokenPaid)`), any staking balance present at the instant `queueNewRewards` executes captures its full pro-rata share of the newly queued rewards — regardless of how long that balance has actually been staked: [5](#0-4) 

`WombatPoolHelper.depositLP` / `deposit` place staking tokens with no lockup, and `withdraw` allows immediate exit, with no cooldown or minimum holding period between deposit and withdrawal: [6](#0-5) 

Exploit flow:
1. Attacker flash-borrows funds, swaps into `lpToken` (or `depositToken`), and calls `WombatPoolHelper.depositLP`/`deposit`, dramatically increasing `totalStaked()` in `BaseRewardPool` right before harvest.
2. Attacker calls `WombatPoolHelper.harvest()` → `WombatStaking.harvest(lpToken)`, which realizes WOM/bonus rewards accrued by *previous* stakers over the harvest interval and calls `queueNewRewards`, instantly inflating `rewardPerTokenStored` based on the now-inflated `totalStaked()` that includes the attacker's flash stake.
3. Attacker claims rewards (via MasterMagpie, which calls `BaseRewardPool.getReward`), receiving a share of rewards proportional to their large momentary stake despite having held it for zero economically meaningful time.
4. Attacker withdraws their LP/stake and repays the flash loan in the same transaction or immediately after.

This is not stopped by any existing check: `getReward` is `onlyMasterMagpie` but that only restricts the caller identity to MasterMagpie's own claim flow, which the attacker (a legitimate depositor of record at claim time) can trigger for themselves; there is no `nonReentrant` guard relevant here (no reentrancy is needed—this is a single-block/ single-tx sequential call, not a reentrant call); and there is no minimum staking duration, harvest cooldown, or linear reward-release mechanism to prevent capturing rewards accrued before the attacker's deposit.

### Impact Explanation
This constitutes theft of unclaimed yield belonging to legitimate long-term LPs: the attacker extracts a share of WOM/bonus rewards that accrued while their capital was not at risk in the pool, diluting genuine stakers' rewards. This matches the Immunefi impact class "theft of unclaimed yield" / direct fund theft from other users, since the pro-rata reward pie is fixed at harvest time and any inflation of `totalStaked()` at that instant directly reduces the `rewardPerToken` share ultimately payable to genuine long-term stakers for that same harvested batch.

### Likelihood Explanation
Feasibility depends on: (a) the size of the pool's `totalStaked()` relative to the amount of capital an attacker can borrow/flash-swap into the underlying LP token — the smaller/relatively illiquid the pool, the larger the attacker's achievable share and thus profit; (b) the value of rewards accrued since the last harvest — pools that are harvested infrequently (larger accrued WOM/bonus balances) are more profitable to attack; (c) the cost of entering/exiting the Wombat AMM LP position (coverage-ratio-based swap fees/slippage) and any Wombat protocol-level withdrawal fees, which act as the main friction cost against the attack, but do not eliminate it as a design flaw. The attack requires no special privileges — only capital (which can be flash-borrowed) and the ability to call three permissionless functions (`depositLP`/`deposit`, `harvest`, `withdraw`, plus MasterMagpie's own claim) — and is repeatable every time a pool has meaningful queued/accrued rewards.

### Recommendation
Replace the instant lump-sum distribution model in `BaseRewardPool`/`BaseRewardPoolV2._provisionReward` with a time-weighted (streaming) reward release similar to Synthetix's `rewardRate`/`periodFinish` model, so that a staker's share of a reward batch is proportional to the time-integral of their stake rather than their stake at a single instant. Alternatively/additionally, enforce a minimum staking duration before a deposit is eligible to earn from a reward batch queued via `harvest()`, or restrict/rate-limit permissionless `harvest()` calls combined with per-block deposit/withdraw snapshots to prevent same-block or same-transaction stake inflation immediately before a harvest.

### Proof of Concept
Foundry fork test plan:
1. Fork BSC at a block where the target Wombat pool (via `WombatPoolHelper`) has significant unharvested WOM/bonus rewards pending in `MasterWombat`.
2. Record `totalStaked()` in the pool's `BaseRewardPool`/`rewarder` and the pending WOM (`WombatPoolHelper.pendingWom()`).
3. Attacker contract: flash-borrow stablecoin/LP token from a lending pool or DEX, swap into the pool's `lpToken`, call `WombatPoolHelper.depositLP(_lpAmount)` with an amount large relative to existing `totalStaked()`.
4. In the same transaction, call `WombatPoolHelper.harvest()`.
5. Call `MasterMagpie`'s claim path for the attacker's staking token to trigger `BaseRewardPool.getReward`, recording WOM/bonus token balances received.
6. Call `WombatPoolHelper.withdraw(_liquidity, _minAmount)` to exit the position, swap the LP token back, and repay the flash loan.
7. Assert: attacker's net WOM/bonus reward token balance > 0 while net LP/stable exposure (post flash-loan repayment and any swap fees) is near zero or a small, bounded cost — demonstrating a positive-EV reward-capture attack disproportionate to the attacker's time-weighted exposure, and compare against a baseline scenario where a genuine long-term staker's `earned()` share for the same harvested batch is reduced accordingly.

        Pool storage poolInfo = pools[_lpToken];

        address[] memory bonusTokens = assetToBonusRewards[_lpToken];
        uint256 bonusTokensLength = bonusTokens.length;

        uint256 womBeforeBalance = IERC20(wom).balanceOf(address(this));

        if(_isStake)
            _stakeToWombatMaster(_lpToken, lpAmount); // triggers harvest from wombat exchange

        _sendRewards(_lpToken, wom, poolInfo.rewarder, womRewards);

            }

                    uint256 feeAmount = (originalRewardAmount * feeInfo.value) / DENOMINATOR;
                    _amount -= feeAmount;
                    uint256 feeTosend = feeAmount;

                            IERC20(wom).safeApprove(smartWomConverter, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IConverter(smartWomConverter).smartConvert(feeAmount, 0);

        IERC20(_rewardToken).safeApprove(_rewarder, _amount);
        IBaseRewardPool(_rewarder).queueNewRewards(_amount, _rewardToken);

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;

        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingTokenDecimals) /
                totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
    }
