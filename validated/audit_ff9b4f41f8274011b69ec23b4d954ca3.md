## Title
Malicious Git server can spoof `WWW-Authenticate` realm to trigger a GitHub Enterprise sign-in flow pointed at an attacker-controlled endpoint, leaking credentials/tokens - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The credential-helper trampoline classifies an unknown Git remote as a trusted "GitHub Enterprise" host based solely on the `WWW-Authenticate` header the remote server returns during HTTP auth negotiation. This classification is fully attacker-controlled (any Git server/proxy can emit that header) and, once accepted, causes GitHub Desktop to launch its real sign-in UI (`SignInStep`, `beginEnterpriseSignIn`) against the attacker's URL, without any independent verification that the host is actually GitHub Enterprise.

### Finding Description
When Git needs credentials for an HTTPS remote, it invokes Desktop's credential helper trampoline, which ends up in `getEndpointKind` in `app/src/lib/trampoline/trampoline-credential-helper.ts`: [1](#0-0) 

The function iterates over `wwwauth[...]` entries in the credential map — values that originate directly from the remote git server's `WWW-Authenticate` response header — and if the value contains `realm="GitHub"`, it unconditionally decides `endpointKind = 'enterprise'`. This value is attacker controlled: any HTTP(S) git remote or man-in-the-middle proxy that the victim clones/fetches from can return that header.

Back in `getCredential`, once the endpoint is classified as non-generic ('enterprise') and no existing account matches that endpoint (which is guaranteed for a brand-new attacker host), Desktop prompts the user to sign in: [2](#0-1) 

`ui.promptForGitHubSignIn(endpoint)` in `trampoline-ui-helper.ts` then drives the *real* GitHub sign-in flow, but scoped to the attacker's `endpoint`/`origin`: [3](#0-2) 

Because `hostname !== 'github.com'`, this calls `dispatcher.beginEnterpriseSignIn(cb)` and `dispatcher.setSignInEndpoint(origin)` with `origin` being the attacker's server, and shows the standard "Sign in" popup (`PopupType.SignIn`, `isCredentialHelperSignIn: true`, `credentialHelperUrl: endpoint`). The user sees Desktop's normal, trusted-looking sign-in dialog, but any OAuth authorization or basic-auth entered here is directed at the attacker-controlled endpoint via `getEnterpriseAPIURL`/`requestOAuthToken` in the sign-in store, which builds API/OAuth URLs from that same untrusted origin.

Existing guards do not stop this path: the only check performed is a substring match on `wwwauth[...]` containing `realm="GitHub"` — there is no TLS pinning, no verification against the real `api.github.com`/GHES `/meta` endpoint, and no confirmation dialog telling the user "this is not a verified GitHub Enterprise server."

### Impact Explanation
An attacker who controls a git remote (or a MITM/proxy in front of one) that the victim clones or fetches from can spoof the `WWW-Authenticate: realm="GitHub"` header on an HTTP 401 response. Desktop will then present its native GitHub Enterprise sign-in UI scoped to the attacker's host. A victim who is used to Desktop prompting for GitHub credentials may complete the OAuth flow or enter a personal access token, believing they're authenticating to a legitimate GitHub instance, while the resulting token/credentials are sent to and bound against the attacker-controlled endpoint. This can lead to credential/token exfiltration and unauthorized account binding within Desktop.

### Likelihood Explanation
The trigger requires nothing beyond the victim adding/cloning/fetching from an attacker-supplied HTTPS remote URL — a very normal, expected Desktop workflow (e.g. "Clone repository" from a URL, or fetching an existing remote that has been tampered with via DNS/MITM). No local access, admin rights, or social engineering beyond "use this git URL" is required, matching the valid-impact criteria (attacker controls a git remote/proxy response).

### Recommendation
Do not classify an endpoint as `'enterprise'` based purely on a client-supplied `WWW-Authenticate` header value. At minimum, corroborate the claim by making an independent request to the candidate endpoint's well-known GitHub API discovery route (similar to the existing `isGitHubHost` check used later in the same function) before elevating trust, and surface a clear warning in the sign-in UI stating that the identity of the host has not been verified when the classification is based on this heuristic.

### Proof of Concept
1. Stand up a malicious HTTPS git server (e.g. a small Node/Go HTTP server implementing the minimal git-http-backend "smart HTTP" 401 challenge).
2. Configure it to respond to unauthenticated requests with `WWW-Authenticate: Basic realm="GitHub"`.
3. In GitHub Desktop, clone/add `https://malicious-server.example/attacker/repo.git`.
4. Observe that `getEndpointKind` in `app/src/lib/trampoline/trampoline-credential-helper.ts` returns `'enterprise'` for this URL, and `getCredential` invokes `ui.promptForGitHubSignIn('https://malicious-server.example')`.
5. The GitHub Enterprise sign-in dialog appears scoped to `malicious-server.example`; any credentials/OAuth code the user provides are sent to that attacker-controlled host.

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
