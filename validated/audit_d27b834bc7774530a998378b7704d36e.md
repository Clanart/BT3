### Title
`_has_redos_structure` heuristic misses curly-brace (`{n,m}`) nested-quantifier ReDoS shapes, allowing a committed `security-patterns.yaml` regex to hang every PostToolUse hook invocation - (File: `plugins/security-guidance/hooks/extensibility.py`)

### Finding Description
`_validate_pattern` gates every user-supplied `regex` field through `_has_redos_structure` before it is added to `_user_patterns` and later matched with `re.search` on file content during PostToolUse hooks: [1](#0-0) 

`_has_redos_structure` only recognizes two literal shapes: `_REDOS_SHAPES` (nested `+`/`*` quantifiers with a `+`/`*`/`?` immediately following the closing paren) and `_ALT_UNDER_REP` (alternation under `+`/`*` repetition with overlapping prefixes): [2](#0-1) 

Both heuristics only match literal `+`, `*`, or `?` characters, never `{n,m}` bounded-repetition syntax. A regex such as `^(a{2,50}){2,50}b$` is structurally identical to the classic catastrophic-backtracking pattern `(a+)+b` (nested repetition over the same character), but:
- The inner group `a{2,50}` contains no literal `+`/`*` character, so `_REDOS_SHAPES[0]` (`\([^()]*[+*][^()]*\)[+*?]`) does not match its content.
- The suffix after the closing paren is `{2,50}`, not `+`/`*`/`?`, so the second half of the same regex also fails to match.
- `_ALT_UNDER_REP` is irrelevant since there is no `|`.

Thus `_has_redos_structure` returns `False`, `re.compile` succeeds, and the rule is accepted into `_user_patterns` via `_load_user_patterns` → `load_for_session`. The rule is then evaluated against the content of every subsequent PostToolUse Edit/Write with `re.search`, and on any input that almost-but-not-quite matches (e.g. `"a" * 40 + "X"`), Python's backtracking engine explores exponentially many ways to partition the `a`s between the nested repetitions before failing.

### Impact Explanation
Because `_user_patterns` is loaded once per session (`load_for_session`) and reused for pattern checks on every file edit thereafter, a single malicious `security-patterns.yaml` committed to `.claude/` causes the hook to hang (effectively forever, from the user's perspective) the first time a file's content is long enough to trigger the exponential blowup. This denies pattern-based security warnings for the rest of the session and stalls the Edit/Write tool call itself, since the hook is synchronous. This matches a resource/DoS-class impact against Claude Code's hook enforcement.

### Likelihood Explanation
Preconditions are modest and match the threat model: PyYAML installed (or use `.json` instead, avoiding the PyYAML dependency entirely) and the assistant opens/edits a repo containing the crafted `.claude/security-patterns.yaml`/`.json`. No privilege beyond committing a file to the repository is required, and the bypass is a single, easily fuzzable regex shape (swap `+`/`*` for `{n,m}` in nested-quantifier or alternation-under-repetition constructs). This is fully attacker-controlled and repeatable on demand.

### Recommendation
Extend `_has_redos_structure`'s pattern set to also detect bounded quantifiers (`{n,m}`, `{n,}`) in both the inner-group and outer-suffix positions (not just literal `+`/`*`/`?`), e.g. by normalizing `{2,}`/`{2,50}` to an equivalent "unbounded repetition" token before running the existing `_REDOS_SHAPES`/`_ALT_UNDER_REP` checks. More robustly, stop relying on a static heuristic entirely: enforce a wall-clock timeout around every `re.search` call against user-supplied patterns (e.g. via a per-call `signal.alarm`/subprocess/`regex` module with `timeout=`, or precompute with a bounded-time regex library), and drop/disable any rule whose match call exceeds the budget, logging a debug entry instead of blocking the hook indefinitely.

### Proof of Concept
Fuzz/unit test plan:
1. Add a regression test in the plugin's test suite that calls `_has_redos_structure` with `r"(a{2,50}){2,50}b"` and asserts it currently returns `False` (demonstrating the heuristic gap).
2. Feed this same regex through `_validate_pattern({"rule_name": "x", "reminder": "y", "regex": r"^(a{2,50}){2,50}b$"}, source="Project")` and assert the rule is accepted (not `None`).
3. Wall-clock-timeout invariant test: run `re.search(r"^(a{2,50}){2,50}b$", "a" * 45 + "!")` under a hard 2-second timeout (e.g. `signal.alarm` or `multiprocessing` with a timeout) and assert the call exceeds the timeout, proving the exponential backtracking is real and unmitigated at the `check_patterns()`/`re.search` call site.
4. Optionally, a property-based fuzz harness generating regex strings with nested `{n,m}` repetition (varying bounds/characters) that (a) pass `_has_redos_structure` (return `False`) and (b) exhibit super-linear `re.search` runtime growth on crafted non-matching inputs of increasing length, asserting the timeout invariant is violated for at least one generated case.

```python
# Catastrophic backtracking: nested quantifiers, overlapping alternations
# under repetition, and wildcard groups under repetition. Static check, not a
# proof — catches the common shapes that hang the hook on every edit.
_REDOS_SHAPES = [
    re.compile(r"\([^()]*[+*][^()]*\)[+*?]"),  # nested quantifier: (a+)*  (a*b)*
    re.compile(r"\(\.\*[^()]*\)[+*]"),         # wildcard group: (.*)*
]
_ALT_UNDER_REP = re.compile(r"\(([^()]*)\|([^()|]*)(?:\|[^()]*)*\)[+*]")


def _has_redos_structure(regex: str) -> bool:
    """Heuristic catastrophic-backtracking check. Not a proof. Catches:
      - nested quantifiers ((a+)*, (a*b)+)
      - wildcard groups under repetition ((.*)*)
      - alternation under repetition where one branch is a prefix of another
        ((a|aa)*, (ab|a)*) — these overlap and explode on non-matching input.
    Does NOT flag non-overlapping alternation ((a|b)*) which is safe."""
    if any(p.search(regex) for p in _REDOS_SHAPES):
        return True
    for m in _ALT_UNDER_REP.finditer(regex):
        branches = [b for b in m.group(0).strip("()*+").split("|") if b]
        for i, a in enumerate(branches):
            for b in branches[i + 1:]:
                # If one branch is a literal prefix of another, the alternation
                # overlaps and the engine backtracks combinatorially.
                if a.startswith(b) or b.startswith(a):
                    return True
    return False
```
