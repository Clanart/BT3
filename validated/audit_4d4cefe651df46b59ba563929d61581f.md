### Title
Empty `SchnorrAggregate` verifies as a valid signature for any verifier supplied with an empty key set — (File: crypto/schnorr/src/aggregate.rs)

### Summary
The Serai analog of "an empty SAT scenario is dropped as a no-op instead of treated as `false`" is `SchnorrAggregate::verify` in `crypto/schnorr/src/aggregate.rs`. When the aggregate contains zero signatures (`Rs` empty) and the verifier's `keys_and_challenges` list is empty, the length check passes trivially and the verification equation degenerates to `(-s) * G == identity`, which any caller can satisfy by submitting `s = 0`. An attacker-controlled byte stream fed to `SchnorrAggregate::read` produces exactly such an object. The encoder side guards against this (`SchnorrAggregator::complete` returns `None` for empty aggregation), but the decoder side (`read`) does not — the same asymmetry as the upstream bug where the compiler guarded the normal path but dropped the impossible/empty case.

### Finding Description
`verify` checks `self.Rs.len() != keys_and_challenges.len()` and returns `false` on mismatch (crypto/schnorr/src/aggregate.rs:128-130). For the empty/empty case it proceeds: the `for` loop over `keys_and_challenges` pushes no pairs, so `pairs` contains only `(-self.s, C::generator())` (lines 138-145). `multiexp_vartime(&pairs).is_identity()` then returns true iff `self.s == 0`.

`SchnorrAggregate::read` (lines 77-88) reads a length-prefixed `Rs` vector; a length of `0` followed by a canonical encoding of `0` for `s` is accepted without any semantic validation. `write`/`serialize` round-trip this object freely.

Meanwhile `SchnorrAggregator::complete` explicitly refuses to produce an empty aggregate (`if self.sigs.is_empty() { return None; }`, lines 175-178), showing the codebase knows the empty case is meaningless — yet `read` constructs the same meaningless object directly from untrusted bytes, exactly mirroring the advisory's pattern where the impossible/empty clause collapsed into a permissive result rather than `false`.

### Impact Explanation
If a verifier ever invokes `SchnorrAggregate::verify(dst, &[])` — e.g., a batch of zero transactions, an empty validator set for a round, or a filtered list that happened to be empty — the attacker-submitted aggregate `{"Rs": [], "s": 0}` verifies as a valid aggregate signature over that DST. This is signature forgery in the degenerate case: bytes the verifier did not sign are accepted as a valid signature. It is reachable purely through attacker-supplied bytes (`SchnorrAggregate::read`) and requires no key material, matching the "untrusted bytes fed to read/verify" reachability rule.

### Likelihood Explanation
The vulnerability requires the verifier to pass an empty `keys_and_challenges` slice. That occurs whenever the application-level notion of "things to verify" is empty — an edge case the upstream advisory demonstrates is realistic (policies/filters routinely reduce to empty sets at runtime). No other cryptographic preconditions are needed: the caller controls the serialized aggregate entirely. Because `verify` is `#[must_use]` and returns `bool` with no distinction between "vacuous" and "verified", the empty case silently returns `true` — the permissive-collapse shape of the bug class.

### Recommendation
In `SchnorrAggregate::verify`, return `false` when `self.Rs.is_empty()` (or when `keys_and_challenges.is_empty()`), treating the empty scenario as `false` rather than a vacuous multiexp. Additionally, `SchnorrAggregate::read` should reject a zero-length `Rs` to mirror the `complete()` guarantee that an aggregate always contains at least one signature.

### Proof of Concept
```rust
use std::io::Cursor;
use ciphersuite::Ciphersuite;
use schnorr::aggregate::SchnorrAggregate;

// For any ciphersuite C and any dst:
let mut bytes = vec![];
bytes.extend(0u32.to_le_bytes());           // Rs length = 0
bytes.extend(C::F::ZERO.to_repr());         // s = 0

let agg = SchnorrAggregate::<C>::read(&mut Cursor::new(bytes)).unwrap();

// Verifier with an empty statement set:
assert!(agg.verify(b"any_dst", &[]));       // returns true — forged aggregate accepted
```
