### Title
Missing `output_script_pubkey` Validation in `Operator::withdraw` Allows Permanent BTC Burn While Operator Claims Full Vault Reimbursement — (`File: core/src/operator.rs`)

---

### Summary

The standard (BitVM) payout path in `Operator::withdraw` accepts any `output_script_pubkey` without script-type validation, while the optimistic payout path enforces a strict allowlist (p2tr, p2pkh, p2sh, p2wpkh, p2wsh) in both the aggregator and every verifier. A user who signs a `SinglePlusAnyoneCanPay` payout over an unspendable output (e.g. `OP_RETURN`) can cause the operator to broadcast a payout that permanently burns the BTC, yet the bridge circuit accepts the payout as valid and the operator is fully reimbursed from the vault. The user's L2 BTC is consumed on Citrea, the vault loses the bridge amount, and the burned BTC is irrecoverable.

---

### Finding Description

**Optimistic payout path — guard present in two places:**

`core/src/rpc/aggregator.rs` lines 1044–1054:
```rust
if !(output_script_pubkey.is_p2tr()
    || output_script_pubkey.is_p2pkh()
    || output_script_pubkey.is_p2sh()
    || output_script_pubkey.is_p2wpkh()
    || output_script_pubkey.is_p2wsh())
{
    return Err(Status::invalid_argument(...));
}
``` [1](#0-0) 

`core/src/verifier.rs` lines 1588–1598 (identical guard in `sign_optimistic_payout`): [2](#0-1) 

**Standard payout path — guard absent:**

`core/src/operator.rs` `Operator::withdraw` (lines 560–637) builds the `output_txout` directly from the caller-supplied `out_script_pubkey` with no script-type check:

```rust
let output_txout = TxOut {
    value: out_amount,
    script_pubkey: out_script_pubkey,   // ← no validation
};
``` [3](#0-2) 

The function then verifies only that the user's Schnorr signature is valid for the given `(input_outpoint, output_txout)` pair — it does not inspect what `output_txout.script_pubkey` actually is: [4](#0-3) 

The resulting payout transaction is built by `create_payout_txhandler`, which also performs no script-type check on `output_txout`: [5](#0-4) 

**Bridge circuit does not validate the payout output script:**

`circuits-lib/src/bridge_circuit/mod.rs` `bridge_circuit()` verifies:
1. SPV inclusion of the payout tx
2. That the payout tx spends the correct withdrawal UTXO
3. That the payout tx carries an `OP_RETURN` with the operator's xonly pubkey

It does **not** check that the user-facing output (index 0) is a spendable script type: [6](#0-5) 

Because the circuit is satisfied, the operator can proceed through the full kickoff → reimburse flow and recover the bridge amount from the vault.

**The `aggregator_verification_address` guard does not close the gap:**

The aggregator's `withdraw` RPC (which generates the optional verification signature) also performs no script-type check on `output_script_pubkey` before forwarding to operators: [7](#0-6) 

---

### Impact Explanation

| Party | Outcome |
|---|---|
| User | L2 BTC consumed on Citrea; receives zero BTC on L1 |
| Operator | Fronts BTC to an `OP_RETURN` output (burned), then claims full `bridge_amount` reimbursement from the vault |
| Bridge vault | Loses `bridge_amount` of BTC with no corresponding user payout |
| Burned BTC | Permanently irrecoverable |

The vault is drained by `bridge_amount` per exploited withdrawal. Because the bridge circuit accepts the payout as valid, no challenge can reverse the reimbursement.

---

### Likelihood Explanation

The user must supply a `SinglePlusAnyoneCanPay` signature that commits to the `OP_RETURN` output. This requires user cooperation (or the operator acting as their own user by registering a withdrawal with their own L2 BTC). The `internal_withdraw` RPC — explicitly described as "intended for operator's own use" — provides a direct path for an operator to self-execute this without any external party: [8](#0-7) 

An operator who also holds L2 BTC can: register a withdrawal on Citrea, sign a payout to `OP_RETURN`, call `InternalWithdraw`, burn the fronted BTC, and collect the vault reimbursement — netting the difference between the reimbursement and the burned amount (bounded by the profitability check, but still a vault drain).

---

### Recommendation

Add the same script-type allowlist guard to `Operator::withdraw` immediately after the profitability check, mirroring the existing guard in `sign_optimistic_payout` and `optimistic_payout`:

```rust
if !(output_txout.script_pubkey.is_p2tr()
    || output_txout.script_pubkey.is_p2pkh()
    || output_txout.script_pubkey.is_p2sh()
    || output_txout.script_pubkey.is_p2wpkh()
    || output_txout.script_pubkey.is_p2wsh())
{
    return Err(eyre::eyre!(
        "Output script pubkey is not a standard spendable script: {}",
        output_txout.script_pubkey
    ).into());
}
```

Apply the same guard in the aggregator's `withdraw` RPC for defence-in-depth.

---

### Proof of Concept

1. Operator (acting as user) holds L2 BTC on Citrea and a dust UTXO on L1.
2. Operator registers a withdrawal on Citrea, consuming their L2 BTC and recording the dust UTXO as the withdrawal UTXO.
3. Operator constructs a payout `TxOut` with `script_pubkey = OP_RETURN <data>` and `value = bridge_amount - fee`.
4. Operator signs this output with `TapSighashType::SinglePlusAnyoneCanPay` over the dust UTXO input.
5. Operator calls `InternalWithdraw` (no aggregator verification signature required when `aggregator_verification_address` is unset) with the OP_RETURN output and the self-signed signature.
6. `Operator::withdraw` verifies the Schnorr signature (valid — the signature commits to the OP_RETURN output), passes the profitability check, and calls `fund_raw_transaction` + `sign_raw_transaction_with_wallet`.
7. Bitcoin Core broadcasts the payout tx; the OP_RETURN output burns the fronted BTC.
8. The bridge circuit's SPV check passes (payout tx is in a block, spends the correct UTXO, has an OP_RETURN with the operator xonly pubkey).
9. Operator sends kickoff, no valid challenge can be raised (the circuit proof is correct), and the operator collects the full `bridge_amount` reimbursement from the vault.
10. Net result: vault loses `bridge_amount`, BTC is permanently burned, operator recovers the reimbursement.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
