### Title
Unbounded Signature Replay in App Proxy Request Verification - (File: `lib/shopify_app/controller_concerns/app_proxy_verification.rb`)

### Summary
`ShopifyApp::AppProxyVerification#query_string_valid?` verifies only that the HMAC over the query parameters matches the `signature` parameter, with no check on the `timestamp` value's freshness and no nonce/one-time-use tracking. This mirrors the report's "Signature Replay" bug class: any valid signed request can be captured and replayed an unlimited number of times, since nothing marks the signature as consumed or expired.

### Finding Description
`verify_proxy_request` calls `query_string_valid?(request.query_string)`, which recomputes the HMAC over all query params (excluding `signature`) and does a `secure_compare` against the supplied `signature`: [1](#0-0) 

The `timestamp` field is present in the signed data, but the code never validates that it is recent — it's simply treated as another signed field to include in the HMAC, exactly like `shop` or `path_prefix`. There is no expiry window check (e.g. rejecting requests where `Time.now.to_i - timestamp.to_i > threshold`) and no tracking of previously-seen signatures/nonces. Any request whose query string (including its original `signature`) is intercepted or observed remains permanently valid and can be POSTed/GETted again verbatim to `verify_proxy_request`-protected endpoints, since `hmac_valid?`/`query_string_valid?` will always recompute the same digest for the same query string.

Because App Proxy requests are ordinary front-end GET requests forwarded by Shopify to the app with the query string (including `shop`, `path_prefix`, `timestamp`, and `signature`) fully visible in the browser's address bar / network tab to the visitor making the request, any unauthenticated visitor of the storefront can capture one legitimate request URL and replay it indefinitely — there is no server-side mechanism in this gem to invalidate it.

### Impact Explanation
Any app-proxy-protected controller action (as documented and generated via `rails g shopify_app:app_proxy_controller`, see `docs/shopify_app/engine.md` and `lib/generators/shopify_app/app_proxy_controller/templates/app_proxy_controller.rb`) that performs a state change, external API call, or resource-consuming action driven by request parameters is vulnerable to unlimited replay by anyone who has ever seen a single valid request URL. This is the same root cause as the referenced report: a valid signed action, once observed, can be re-executed without limit or authorization, because the digest carries no nonce and there is no consumption/expiry tracking.

### Likelihood Explanation
High reachability: an anonymous storefront visitor triggers this signed request organically by visiting a page that hits an `/apps/...` app-proxy path; the resulting URL (with a valid `signature`) is visible client-side. No credentials, secrets, or privileged access are required to capture and replay it — only observation of one legitimate network request.

### Recommendation
Enforce a strict freshness window on `timestamp` (e.g., reject if `Time.now.to_i - timestamp.to_i` exceeds a small threshold such as 60–300 seconds) inside `query_string_valid?`/`verify_proxy_request`, in addition to the HMAC check. For endpoints that perform sensitive or state-changing actions, additionally track consumed signatures (or an app-supplied nonce/idempotency key) so a given signed request cannot be accepted more than once.

### Proof of Concept
1. Visitor V loads a storefront page that calls the app's App Proxy endpoint, e.g. `GET https://shop.example.com/apps/my-app?shop=some-shop.myshopify.com&path_prefix=%2Fapps%2Fmy-app&timestamp=1700000000&signature=<valid_hmac>`.
2. V copies this exact URL from the browser's network tab.
3. `ShopifyApp::AppProxyVerification#verify_proxy_request` accepts it because `query_string_valid?` only checks HMAC correctness, not freshness or one-time use: [2](#0-1) 
4. V replays the identical URL any number of times, at any point in the future — each request is verified as valid and processed by the underlying controller action, demonstrating unauthenticated, unlimited signature replay.

```ruby
    def verify_proxy_request
      head(:forbidden) unless query_string_valid?(request.query_string)
    end

    private

    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end

    def calculated_signature(query_hash_without_signature)
      sorted_params = query_hash_without_signature.collect { |k, v| "#{k}=#{Array(v).join(",")}" }.sort.join

      OpenSSL::HMAC.hexdigest(
        OpenSSL::Digest.new("sha256"),
        ShopifyApp.configuration.secret,
        sorted_params,
      )
    end
```
