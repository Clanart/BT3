## Title
Attacker-Controlled PR Head Clone URL Is Passed Unvalidated to `git remote add`, Enabling Remote/Origin Confusion for Silent Push/Fetch Redirection - (`File: app/src/lib/stores/app-store.ts`)

### Summary
`_findPullRequestBranch` in `app-store.ts` takes `headCloneUrl` straight from a GitHub API pull-request object (or from the `x-github-client://openRepo` deep link flow) and, if no existing remote matches it, calls `addRemote(repository, forkRemoteName, headCloneUrl)`, which shells out to `git remote add name url` with no scheme/host validation. [1](#0-0) [2](#0-1) 

### Finding Description
The broken invariant, mirroring the audited contract's failure to validate a value it trusts as safe (price parity between pools), is here: Desktop trusts `headCloneUrl`/`clone_url` from a pull-request object as a legitimate git remote URL without any allow-list on scheme or host. `urlMatchesRemote`/`parseRemote` are used only to detect an *existing* matching remote; if none matches, the raw string is passed directly into `git remote add` [3](#0-2) . This flow is reachable either from the "Open in Desktop" deep link (`x-github-client://openRepo/...?pr=NNN`, parsed with no host restriction in `parseAppURL`, which only validates the numeric `pr` and `branch` shape, not the repo `url` itself) [4](#0-3) , or from an in-app "Checkout this PR" action that reads `pullRequest.head.repo.clone_url` from the GitHub API response [5](#0-4) .

Unlike `updateRemoteUrl`, which explicitly checks protocol match and refuses to alter an existing remote if the protocol/owner/name don't line up [6](#0-5) , `_findPullRequestBranch` has no such guard when *creating* a brand-new remote — it accepts whatever string is supplied as `headCloneUrl` (e.g., an `ext::`, `file://`, or arbitrary transport-helper URL supported by git) and feeds it to `git remote add`.

### Impact Explanation
If an attacker can influence the `head.repo.clone_url` value returned for a PR object that Desktop consumes (e.g., by controlling the deep-link `url` value which is never validated to be `github.com`/GHE, or a compromised/MITM'd GHES/API endpoint response), the value ends up as the URL of a newly created git remote inside the user's real repository, silently, without any confirmation dialog (contrast with `UpstreamAlreadyExists`, which does prompt before rewriting the `upstream` remote — no equivalent prompt exists for fork remotes added by `_findPullRequestBranch`) [7](#0-6) . Git itself then immediately performs a `fetch` against that URL via `this._fetchRemote(repository, remote, ...)` [8](#0-7) , and if the URL uses a git transport helper syntax (e.g. `ext::`), this results in arbitrary local process execution outside the sandbox — i.e., code execution triggered purely by an attacker-controlled repository/API object, matching the requested impact class.

### Likelihood Explanation
Moderate. The attacker-controlled surface (PR head repo/clone URL, deep link `url` parameter) is unauthenticated from Desktop's point of view: any PR, including PRs from any external contributor visible to the victim, or a crafted `x-github-client://openRepo/<attacker-url>?pr=1` link the victim clicks, reaches this code path. No local access, admin rights, or pre-existing malware is required — only that the victim opens/checks-out a PR or clicks an "Open in Desktop" link, which is the intended primary use case for this exact feature. The main uncertainty (not confirmed in the indexed code) is whether upstream git or Desktop's `envForRemoteOperation`/git config globally disables `ext::`/protocol-less transports (e.g., via `protocol.ext.allow`); this could not be verified from the available files, so the concrete code-execution outcome is not fully confirmed, but the invariant violation — accepting an arbitrary clone URL from a remote-controlled object and auto-adding/auto-fetching it as a trusted remote with no user confirmation — is confirmed in code.

### Recommendation
Before calling `addRemote` in `_findPullRequestBranch`, validate `headCloneUrl` against the same `parseRemote`/protocol allow-list (`https`/`ssh`) used in `remote-parsing.ts`, reject anything that doesn't parse to a recognized GitHub host/owner/name shape, and require explicit user confirmation (similar to `UpstreamAlreadyExists`) before adding and fetching a brand-new remote sourced from PR/API/deep-link data.

### Proof of Concept
1. Craft `x-github-client://openRepo/<attacker-supplied-url>?pr=1&branch=pr%2F1` and get the victim to click it (satisfies `parseAppURL`'s regex checks, which only validate `pr` is numeric and `branch` matches `pr/\d+`) [9](#0-8) .
2. `openPullRequestFromUrl` calls `fetchPullRequest(url, pr)` against whatever host is embedded in `url`, then reads `pullRequest.head.repo.clone_url` from that response.
3. `_checkoutPullRequest` → `_findPullRequestBranch` finds no existing remote matching this URL and calls `addRemote(repository, forkRemoteName, headCloneUrl)` unchecked [10](#0-9) .
4. Desktop immediately fetches from the newly-added remote [8](#0-7) , executing whatever `git fetch` does against the attacker-controlled URL/transport with no host allow-list and no user confirmation prompt.

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}

export function parseAppURL(url: string): URLActionType {
  const parsedURL = URL.parse(url, true)
  const hostname = parsedURL.hostname
  const unknown: IUnknownAction = { name: 'unknown', url }
  if (!hostname) {
    return unknown
  }

  const query = parsedURL.query

  const actionName = hostname.toLowerCase()
  if (actionName === 'oauth') {
    const code = getQueryStringValue(query, 'code')
    const state = getQueryStringValue(query, 'state')
    if (code != null && state != null) {
      return { name: 'oauth', code, state }
    } else {
      return unknown
    }
  }

  // we require something resembling a URL first
  // - bail out if it's not defined
  // - bail out if you only have `/`
  const pathName = parsedURL.pathname
  if (!pathName || pathName.length <= 1) {
    return unknown
  }

  // Trim the trailing / from the URL
  const parsedPath = pathName.substring(1)

  if (actionName === 'openrepo') {
    const pr = getQueryStringValue(query, 'pr')
    const branch = getQueryStringValue(query, 'branch')
    const filepath = getQueryStringValue(query, 'filepath')

    if (pr != null) {
      if (!/^\d+$/.test(pr)) {
        return unknown
      }

      // we also expect the branch for a forked PR to be a given ref format
      if (branch != null && !/^pr\/\d+$/.test(branch)) {
        return unknown
      }
    }

    if (branch != null && testForInvalidChars(branch)) {
      return unknown
    }

    return {
      name: 'open-repository-from-url',
      url: parsedPath,
      branch,
      pr,
      filepath,
    }
  }

  return unknown

  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously

    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)
