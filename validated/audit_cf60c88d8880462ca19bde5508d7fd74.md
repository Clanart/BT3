## Analog Found

### Title
Gasless swap admission relies on an instantaneous, single-block AMM spot price that can be manipulated to defeat the repay-solvency check, risking proposer fund loss - (File: `kaiax/gasless/impl/tx_pool.go`)

### Summary
The reported bug class is that a TWAP with an effectively 1-second update window offers no meaningful manipulation resistance because the price can be moved and read back within the same short window. The closest reachable analog on Kaia is the `GaslessModule.checkBalanceForSwap` sanity check in the gasless-transaction (KIP-247) pipeline, which reads a **live, un-averaged AMM spot price** (`GaslessSwapRouter.GetAmountIn`, itself Uniswap-V2-style `reserveIn`/`reserveOut` math) at the instant a `GaslessSwapTx` is validated for tx-pool admission. This is not merely a "1-second TWAP" — it has **zero time-weighting at all**, making it strictly more manipulable than the original report's target.

### Finding Description
`checkBalanceForSwap` enforces two solvency conditions before admitting a gasless swap transaction to the pool: [1](#0-0) 

Both `minAmountOut >= amountRepay` and `amountIn >= getAmountIn(minAmountOut)` are checked against the **current** on-chain reserves of the underlying AMM pair via `GaslessSwapRouter.GetAmountIn`, which itself just forwards to the pool's constant-product formula: [2](#0-1) 

Meanwhile, `amountRepay` — the amount the user is expected to return to the proposer — is **not** priced from the AMM at all; it is a deterministic function of gas fees only: [3](#0-2) 

Crucially, before the swap is even attempted, the block proposer unconditionally transfers native KAIA to the sender via a plain value-transfer `LendTx` generated by `GetLendTxGenerator`/`lendAmount`, with no conditional linkage to whether the subsequent swap will actually succeed: [4](#0-3) [5](#0-4) 

Because `GetAmountIn` is read from live reserves with no time-window protection, an attacker (the swap sender or a colluding party) can move the pool price immediately before/around the mempool-admission check to make an under-collateralized `amountIn`/`minAmountOut` pair pass `checkBalanceForSwap`, then let the pool revert to its natural price before the transaction is actually executed in a block. At execution time, the real Uniswap-style swap inside `swapForGas` enforces `minAmountOut` as slippage protection and will revert if the true output is insufficient — but the `LendTx` that already handed the user real KAIA is a separate, unconditional transaction.

### Impact Explanation
If the `LendTx` is not strictly atomic with the paired `GaslessApproveTx`/`GaslessSwapTx` (i.e., the block-building/bundle logic does not guarantee all-or-nothing inclusion when the swap reverts), the proposer/block-builder loses the lent KAIA with no repayment, because the repay logic executes only inside `swapForGas`, which can revert due to AMM manipulation while the value transfer already happened. This is a direct value-movement / gasless-settlement-theft risk, matching the categories explicitly in scope (gasless settlement theft, fee-delegation abuse). This mirrors the report's root cause exactly: a security-critical financial check keyed off a spot/short-window on-chain price that an adversary can move within a single block.

### Likelihood Explanation
Medium. The `ShouldCheckSwapAmount` / `ShouldCheckToken` checks are configurable (`GaslessConfig`), and even when enabled they rely on the manipulable, un-averaged price read described above. Executing the manipulation requires the attacker to control (or front-run) pool reserves and time transactions around the tx-pool admission/block-inclusion window, which is achievable by any unprivileged transaction sender with sufficient capital to move the relevant AMM pair, without needing validator/proposer privileges.

### Recommendation
- Do not rely on a single-block/instant AMM spot price (`getAmountIn`) to gate a solvency check that determines whether the proposer is safe to lend value; use a time-weighted or multi-block-observed price, or re-validate against the same reserves used at execution time.
- Ensure the `LendTx`, `GaslessApproveTx`, and `GaslessSwapTx` bundle is atomic at block-building time (i.e., the bundle is only included if every transaction, including the swap's actual repay leg, succeeds), so a reverted swap cannot leave an unconditional value transfer stranded.

### Proof of Concept
Conceptual PoC (bundle-atomicity assumption not independently confirmed in the reviewed builder code — see caveat below):
1. Attacker (or colluding party) prepares a large swap to temporarily depress/inflate the reserves of the pool backing an `allowedToken`.
2. Attacker submits `GaslessSwapTx` with `amountIn` set to just barely satisfy `amountIn >= GetAmountIn(minAmountOut)` computed against the manipulated reserves, per [6](#0-5) .
3. The manipulation swap is then reversed/settled, restoring true reserves before the gasless bundle is executed by the block builder.
4. The block builder issues the `LendTx` (unconditional native transfer of `lendAmount`) per [7](#0-6) , then attempts `GaslessApproveTx`/`GaslessSwapTx`.
5. `swapForGas`'s internal Uniswap-style `minAmountOut` slippage check fails against the true (restored) reserves, and the swap reverts — while the KAIA lent in step 4 has already left the proposer's control.

**Caveat / unverified assumption:** This PoC's fund-loss conclusion depends on the block-builder/bundle logic (`work/builder`) not enforcing strict atomic inclusion (i.e., dropping the whole `[LendTxGenerator, ApproveTx, SwapTx]` bundle if the swap simulation reverts). I was not able to fully trace the bundle-simulation/inclusion logic in `work/builder` within the available index to confirm whether such atomicity is guaranteed; if it is strictly enforced, the manipulation would only cause the bundle to be dropped (denial-of-service on that specific gasless tx) rather than direct fund loss. This should be verified against the full `work/builder` source, which may require a full Devin session for complete file access given index size limits.

// MakeLendTx creates a transaction with following properties:
// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)
// L2. LendTx.from = proposer
// L3. LendTx.to = SwapTx.from
// L4. LendTx.value = LendAmount(approveTxOrNil, swapTx)
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}
