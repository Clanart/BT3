Based on my investigation, I found a strong analog to the price-oracle outlier bug class within the Kaia gasless module. The `GaslessSwapRouter` contract's `GetAmountIn` call is used as the sole, single-source price for the gasless swap admission check — the exact same "trust a single price source with no bounds/deviation check" pattern flagged in the external report.

### Title
Gasless-swap admission check relies on a single, unfiltered instantaneous DEX spot price (`GetAmountIn`), enabling TOCTOU price manipulation - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
`GaslessModule.checkBalanceForSwap` validates a user's `SwapTx` by querying the live, unfiltered spot price from the on-chain `GaslessSwapRouter`/underlying AMM pool (`routerContract.GetAmountIn(nil, token, minAmountOut)`) and comparing it to the transaction's declared `amountIn`. There is no secondary price source, no deviation/outlier bound, and no historical/TWAP consistency check — exactly the missing-outlier-filtering pattern described in the external report, just applied to the on-chain AMM spot price instead of a Chainlink feed.

### Finding Description
`checkBalanceForSwap` in [1](#0-0)  computes `requiredAmountIn` purely from the current AMM reserves exposed by `GaslessSwapRouter.GetAmountIn`, and rejects the tx only if `amountIn < requiredAmountIn`. This price is read fresh at admission time (both mempool insertion and re-validation before block building), with no comparison against a second oracle, no bound on divergence from a recent average, and no protection against the price having been moved by a transaction earlier in the same block.

Because `checkBalanceForSwap` is invoked as a promotion/admission gate (via `GetCheckBalance`, wired into pending-pool promotion in [2](#0-1) ) rather than atomically with the on-chain `swapForGas` execution, there is a time-of-check/time-of-use gap: any actor able to influence transaction ordering ahead of a pending `SwapTx` within the pool's admission window (e.g., a searcher/user submitting large swaps against the same pool, or the block-producing validator reordering) can shift the AMM reserves so that the price observed at check-time differs from the price that will exist at execution-time. The check has no tolerance band or secondary reference to catch this divergence — it simply reflects whatever the pool state says "right now," the same failure mode the report calls out for `PriceOracle::getLatestPrice` accepting whatever a single feed returns.

The `GaslessConfig.BalanceCheckLevel` flag ( [3](#0-2) ) even allows operators to run with `BalanceCheckLevelTokenBalanceAndAllowance`, which skips the swap-amount check (`ShouldCheckSwapAmount`) entirely, meaning some nodes may admit gasless swap txs into blocks with no price sanity check at all — an even more direct analog to "prices are utilised regardless of their actual value."

### Impact Explanation
A gasless (fee-delegated) `SwapTx` is trusted by the network to have a valid, non-abusive exchange rate between the sponsored gas repayment (`amountRepay`) and the token amount swapped, based solely on the AMM's live spot price. If the underlying pool's reserves are manipulated between the time a node validates/admits the tx and the time it is executed in `swapForGas` on-chain, the effective repayment/output ratio realized on-chain can diverge from what the admission check verified, allowing value extraction from the gasless flow (e.g., sandwiching the sponsored swap) without the tx pool's soft check ever detecting it, since the check itself has no outlier/deviation protection and simply mirrors instantaneous pool state.

### Likelihood Explanation
Reachable by any unprivileged transaction sender able to submit ordinary swap transactions against the same DEX pool used by `GaslessSwapRouter`, or by the block-producing validator who controls final ordering — no privileged access, p2p manipulation, or consensus-message forgery is required. The `checkBalanceForSwap` code path is exercised on every gasless swap admission, so the exposure is continuous rather than conditional on rare configuration.

### Recommendation
Do not rely on a single, instantaneous AMM read for either admission or execution-time validation of `amountIn`/`amountRepay`. Consider requiring the check to use a TWAP or multi-block average price, bound the allowed deviation between the price used at admission and at execution, or re-validate `checkBalanceForSwap` immediately before inclusion in the same block context that will execute the swap so no reordering window exists between check and use.

### Proof of Concept
1. Observe a pending `SwapTx` targeting `GaslessSwapRouter` for `token` with `minAmountOut`/`amountIn` computed against current pool reserves.
2. Submit (or, as validator, order) a large swap against the same underlying pool before the target `SwapTx`, shifting reserves so the instantaneous price read by `GetAmountIn` no longer reflects the rate the sender computed off-chain.
3. Because `checkBalanceForSwap` ( [1](#0-0) ) only re-reads the live `GetAmountIn` value with no deviation bound, the tx pool re-validates/promotes the tx using the post-manipulation price, and the resulting on-chain `swapForGas` settlement can be skewed in the attacker's favor relative to the fair/expected rate, with no oracle-outlier protection catching the discrepancy.

func (g *GaslessModule) GetCheckBalance() func(tx *types.Transaction) error {
	return func(tx *types.Transaction) error {
		if approveArgs, ok := decodeApproveTx(tx, g.signer); ok {
			return g.checkBalanceForApprove(approveArgs)
		}
		if swapArgs, ok := decodeSwapTx(tx, g.signer); ok {
			return g.checkBalanceForSwap(swapArgs, tx.Nonce())
		}
		return errors.New("not a gasless transaction") // should not happen because IsModuleTx is called before GetCheckBalance
	}
}

type GaslessConfig struct {
	// all tokens are allowed if AllowedTokens is nil while all are disallowed if empty slice
	AllowedTokens         []common.Address `toml:",omitempty"`

	MaxBundleTxsInPending uint
	MaxBundleTxsInQueue   uint

func DefaultGaslessConfig() *GaslessConfig {
	return &GaslessConfig{
		AllowedTokens:         nil,
		Disable:               false,
		MaxBundleTxsInPending: 100,
		MaxBundleTxsInQueue:   200,
		BalanceCheckLevel:     BalanceCheckLevelAll,
	}
}

func (cfg *GaslessConfig) ShouldCheckToken() bool {
	return cfg.BalanceCheckLevel >= BalanceCheckLevelTokenBalanceAndAllowance
}

func (cfg *GaslessConfig) ShouldCheckSwapAmount() bool {
	return cfg.BalanceCheckLevel >= BalanceCheckLevelSwapAmount
