## Finding: `getAbsoluteUrl` mishandles multiple leading slashes, allowing host takeover via crafted `path`

### Summary
`getAbsoluteUrl(endpoint, path)` in `app/src/lib/http.ts` strips **at most one** leading `/` from `path` before resolving it against the configured `endpoint` with the WHATWG `URL` constructor. If `path` begins with two or more slashes (e.g. `//evil.com/x` or `///evil.com/x`), stripping a single leading slash still leaves a protocol-relative reference (`//evil.com/x`), which the `URL` resolver interprets as an authority override — replacing the host of `endpoint` while keeping its scheme. The resulting URL points at `evil.com` instead of the trusted GHE/dotcom host. [1](#0-0) 

### Finding Description
```
let relativePath = path[0] === '/' ? path.substring(1) : path
if (relativePath.startsWith('api/v3/')) {
  relativePath = relativePath.substring(7)
}
...
return new URL(relativePath, base).toString()
```
This code only removes a single leading `/`. For `path = '///evil.com/foo'`:
1. `path[0] === '/'` → `relativePath = '//evil.com/foo'`.
2. `relativePath` does not start with `api/v3/`, so it is left unchanged.
3. `new URL('//evil.com/foo', 'https://ghe.enterprise.local/api/v3/')` resolves per the URL spec's "special scheme, relative-with-leading-slashes" rule to `https://evil.com/foo` — the host component of `base` is discarded and replaced by `evil.com`.

The function comment states the intent is to prevent duplicating `/api/v3/` when the API returns pagination `Link` headers that include that fragment, and the existing unit tests confirm that values such as `/api/v3/user/repos?page=2` — i.e. server-supplied, endpoint-relative pagination/next-page paths — are passed straight through to `getAbsoluteUrl` as the `path` argument. [2](#0-1)  That confirms `path` legitimately originates from server (GHE) response data rather than solely from hardcoded literals in the app, so a malicious/compromised GitHub Enterprise Server (or an on-path attacker able to influence its responses) that returns a `Link`/pagination path such as `///evil.com/...` would cause `getAbsoluteUrl` to compute a URL on `evil.com`.

`request()` then fetches that URL with the user's bearer token attached: [3](#0-2) 

### Impact Explanation
If a crafted pagination path reaches `request()`, the `Authorization: Bearer <token>` header for the account (a dotcom or GHE personal access/OAuth token) would be sent to the attacker-controlled origin, resulting in credential/token exfiltration — matching the "unauthorized OAuth or account binding / credential exfiltration" impact class in scope.

### Likelihood Explanation
Exploitability depends entirely on whether the specific call sites in `app/src/lib/api.ts` that consume pagination `Link` headers pass the raw header value (or a value derived from it without further sanitization) into `request()`/`getAbsoluteUrl` as `path`. I was not able to fully trace that specific pagination/`Link`-header parsing code path in `app/src/lib/api.ts` within the available search budget — the file has many matches for pagination-related logic, and I could not confirm the exact transformation applied to the header value before it's handed to `getAbsoluteUrl`. The unit test `'handles next page resource which already contains prefix'` demonstrates the intended shape of such input (`/api/v3/user/repos?page=2`), but not whether malformed/adversarial variants (multiple leading slashes) are rejected upstream. This should be verified with full file access.

### Recommendation
Normalize `relativePath` to strip **all** leading slashes (or otherwise reject/normalize any leading `//`) before constructing the `URL`, e.g. `path.replace(/^\/+/, '')`, and additionally validate that the resolved URL's origin matches `new URL(base).origin` before returning it from `getAbsoluteUrl`, throwing/logging if not.

### Proof of Concept
```ts
import { getAbsoluteUrl } from '../../src/lib/http'

const enterpriseEndpoint = 'https://my-cool-company.com/api/v3'

// Adversarial pagination/Link-derived path with 3 leading slashes
const result = getAbsoluteUrl(enterpriseEndpoint, '///evil.com/steal')

// Expected (if invariant held): origin === 'https://my-cool-company.com'
// Actual:
console.log(result) // -> 'https://evil.com/steal'
console.log(new URL(result).origin) // -> 'https://evil.com'
```
This test asserts the resolved origin should equal `my-cool-company.com` but instead resolves to `evil.com`, confirming the base-URL invariant is broken by `getAbsoluteUrl` for this input shape. Full confirmation that this specific `path` string is reachable from a real GHE `Link` header response requires further tracing of the pagination code in `app/src/lib/api.ts`.

```typescript
export function getAbsoluteUrl(endpoint: string, path: string): string {
  let relativePath = path[0] === '/' ? path.substring(1) : path
  if (relativePath.startsWith('api/v3/')) {
    relativePath = relativePath.substring(7)
  }

  // Our API endpoints are a bit sloppy in that they don't typically
  // include the trailing slash (i.e. we use https://api.github.com for
  // dotcom and https://ghe.enterprise.local/api/v3 for Enterprise when
  // both of those should really include the trailing slash since that's
  // the qualified base). We'll work around our past since here by ensuring
  // that the endpoint ends with a trailing slash.
  const base = endpoint.endsWith('/') ? endpoint : `${endpoint}/`

  return new URL(relativePath, base).toString()
}
```
