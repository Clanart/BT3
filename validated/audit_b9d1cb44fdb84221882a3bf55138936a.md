## Title
CLI `aptos move verify-package` never compares deployed bytecode to source, allowing malicious modules to be certified as "verified" - (File: `aptos-move/cli/src/stored_package.rs`)

### Summary
The `VerifyPackage` CLI command is meant to let users confirm that the bytecode actually stored on-chain at a given address matches a given (trusted) source tree. In reality, `CachedPackageMetadata::verify()` only compares `PackageMetadata` fields — name, deps, `ModuleMetadata` (which just carries the gzipped *source text*, not bytecode), manifest, upgrade policy, extension, and `source_digest` (a hash of the *source files*, not of the compiled module bytes). It never fetches or hashes the on-chain compiled bytecode and never compares it to the bytecode produced by the local build, even though the surrounding `CachedPackageRegistry` type explicitly supports downloading module bytecode (`with_bytecode`, `get_bytecode`).

### Finding Description
`code::PackageMetadata` on-chain has no field that commits to the actual compiled module bytes — `ModuleMetadata.source` is just gzipped source text, and `source_digest` is documented as a hash over the *source files*: [1](#0-0) . The chain's `code::publish_package` and native `request_publish[_with_allowed_deps]` never validate that `ModuleMetadata.source`/`source_digest` actually correspond to the bytecode bundle being published — the module bytes and the metadata are two independently supplied, unrelated payloads: `code::publish_package_txn` just deserializes a raw `PackageMetadata` and a raw `code: vector<vector<u8>>` and forwards both to `request_publish` without any cross-check [2](#0-1) [3](#0-2) . The native handler simply stores the bundle bytes and the (separately supplied) expected module name set, again with no linkage to the metadata's source text: [4](#0-3) .

Given that, the *only* mechanism a user has to confirm that deployed code matches an expected source tree is the CLI `verify-package` command. But its implementation:

1. Builds the package locally and gets local metadata via `pack.extract_metadata()`.
2. Fetches the on-chain package **without bytecode** (`with_bytecode = false`): [5](#0-4) .
3. Calls `package.verify(&compiled_metadata)`, which only performs equality checks over `name`, `deps`, `modules` (source text/source map/extension), `manifest`, `upgrade_policy`, `extension`, and `source_digest` — never the actual `.mv` bytecode: [6](#0-5) .

`CachedPackageRegistry` explicitly has the capability to download real bytecode per module (`get_account_module(...).bytecode`) and expose it via `get_bytecode`, but this capability is unused by `verify()`: [7](#0-6) .

Because the on-chain `ModuleMetadata.source` field is attacker-controlled and *not* enforced to correspond to the published bytecode by any on-chain check, a malicious publisher can:
- Publish a package whose bytecode contains malicious/backdoored logic.
- Set `ModuleMetadata.source` (and `source_digest`) to the gzipped text of a legitimate, benign, publicly-known source tree.

Any third party who runs `aptos move verify-package` against the legitimate source tree will find every field in `verify()` matching and receive `"Successfully verified source of package"`, even though the bytecode actually executing on-chain is completely different from that source.

### Impact Explanation
This breaks the code-safety invariant that "verified bytes, package metadata... and committed module bytes" must agree, per the publish impact gate. Users, auditors, wallets, or automated tooling that rely on `verify-package` (the officially documented mechanism for confirming deployed code matches source, referenced in the "Security considerations for dependencies" guidance for depending on `compatible` packages) can be misled into trusting/depending on/interacting with malicious bytecode that they believe has been verified against known-safe source. This can enable social-engineering-free supply-chain style attacks: a malicious framework/package can pose as an audited, source-verified dependency while running arbitrary different logic, directly undermining the guarantee the report's bug class targets — that on-chain identity/verification data must not be spoofable to make different actual content appear identical to trusted content.

### Likelihood Explanation
The attack requires no special privilege: any account able to publish/upgrade a package (permissionless on Aptos, including via `code::publish_package_txn`, resource accounts, or `object_code_deployment::publish`/`upgrade`) can freely choose `ModuleMetadata.source` independent of the actual bytecode, since nothing on-chain checks this correspondence. It requires only that a downstream user/tool trust the CLI `verify-package` output, which is a normal, expected usage pattern documented as the way to validate on-chain code.

### Recommendation
`CachedPackageMetadata::verify()` should download the actual on-chain module bytecode (already supported by `CachedPackageRegistry::create(..., with_bytecode = true)` / `get_bytecode`) and compare it (e.g., via hash) against the bytecode produced by locally building the same source, rather than relying solely on self-declared `ModuleMetadata`/`source_digest` fields. Alternatively/additionally, the on-chain `code::publish_package` flow could enforce a binding commitment between `source_digest`/module source and the actually published bytecode bundle so that source metadata cannot diverge from what is executed.

### Proof of Concept
1. Attacker authors malicious Move bytecode `M_evil` and a legitimate-looking, benign source tree `S_good` that a victim would trust (e.g., copy of a known audited package's source).
2. Attacker compiles `S_good` locally only to obtain `ModuleMetadata.source`/`source_map`/`source_digest`/`manifest` fields, but substitutes `M_evil` as the actual `code: vector<vector<u8>>` bundle passed to `code::publish_package_txn` (or `object_code_deployment::publish`).
3. Attacker publishes the package: on-chain `PackageRegistry` now stores `PackageMetadata` whose `modules[i].source` == gzip(`S_good`) but whose actual module bytecode is `M_evil`; nothing in `code.move`/`code.rs` cross-checks this.
4. A victim clones `S_good`, runs `aptos move verify-package --account <attacker_addr>`.
5. `VerifyPackage::execute` builds `S_good` locally, fetches on-chain metadata with `with_bytecode = false` (`aptos-move/cli/src/commands.rs:2121`), and calls `verify()`, which only compares metadata fields — all of which match, since the attacker copied `S_good`'s source into the metadata.
6. The CLI reports `"Successfully verified source of package"`, even though the deployed, executing bytecode is `M_evil`, not the bytecode of `S_good`.

fn native_request_publish(
    context: &mut SafeNativeContext,
    _ty_args: &[Type],
    mut args: VecDeque<Value>,
) -> SafeNativeResult<SmallVec<[Value; 1]>> {
    debug_assert!(matches!(args.len(), 4 | 5));
    let with_allowed_deps = args.len() == 5;

    context.charge(CODE_REQUEST_PUBLISH_BASE)?;

    let policy = safely_pop_arg!(args, u8);
    let mut code = vec![];
    for module in safely_pop_arg!(args, Vec<Value>) {
        let module_code = module.value_as::<Vec<u8>>()?;

        context.charge(CODE_REQUEST_PUBLISH_PER_BYTE * NumBytes::new(module_code.len() as u64))?;
        code.push(module_code);
    }

    let allowed_deps = if with_allowed_deps {
        let mut allowed_deps: BTreeMap<AccountAddress, BTreeSet<String>> = BTreeMap::new();

        for dep in safely_pop_arg!(args, Vec<Value>) {
            let (account, module_name) = unpack_allowed_dep(dep)?;

            let entry = allowed_deps.entry(account);

            if let Entry::Vacant(_) = &entry {
                // TODO: Is the 32 here supposed to indicate the length of an account address in bytes?
                context.charge(CODE_REQUEST_PUBLISH_PER_BYTE * NumBytes::new(32))?;
            }

            context
                .charge(CODE_REQUEST_PUBLISH_PER_BYTE * NumBytes::new(module_name.len() as u64))?;
            entry.or_default().insert(module_name);
        }

        Some(allowed_deps)
    } else {
        None
    };

    let mut expected_modules = BTreeSet::new();
    for name in safely_pop_arg!(args, Vec<Value>) {
        let str = get_move_string(name)?;

        // TODO(Gas): fine tune the gas formula
        context.charge(CODE_REQUEST_PUBLISH_PER_BYTE * NumBytes::new(str.len() as u64))?;
        expected_modules.insert(str);
    }

    let destination = safely_pop_arg!(args, AccountAddress);

    // Add own modules to allowed deps
    let allowed_deps = allowed_deps.map(|mut allowed| {
        allowed
            .entry(destination)
            .or_default()
            .extend(expected_modules.clone());
        allowed
    });

    let code_context = context.extensions_mut().get_mut::<NativeCodeContext>();
    if code_context.requested_module_bundle.is_some() || !code_context.enabled {
        // Can't request second time or if publish requests are not allowed.
        return Err(SafeNativeError::abort(EALREADY_REQUESTED));
    }
    code_context.requested_module_bundle = Some(PublishRequest {
        destination,
        bundle: ModuleBundle::new(code),
        expected_modules,
        allowed_deps,
        check_compat: policy != ARBITRARY_POLICY,
    });

    Ok(smallvec![])
}

impl CachedPackageRegistry {
    /// Creates a new registry.
    pub async fn create(
        client: Client,
        addr: AccountAddress,
        with_bytecode: bool,
    ) -> anyhow::Result<Self> {
        // Need to use a different type to deserialize JSON
        let inner = client
            .get_account_resource_bcs::<PackageRegistry>(addr, "0x1::code::PackageRegistry")
            .await?
            .into_inner();
        let mut bytecode = BTreeMap::new();
        if with_bytecode {
            for pack in &inner.packages {
                for module in &pack.modules {
                    let bytes = client
                        .get_account_module(addr, &module.name)
                        .await?
                        .into_inner()
                        .bytecode
                        .0;
                    bytecode.insert(module.name.clone(), bytes);
                }
            }
        }
        Ok(Self { inner, bytecode })
    }

    /// Returns the list of packages in this registry by name.
    pub fn package_names(&self) -> Vec<&str> {
        self.inner
            .packages
            .iter()
            .map(|p| p.name.as_str())
            .collect()
    }

    /// Finds the metadata for the given module in the registry by its unique name.
    pub async fn get_module(
        &self,
        name: impl AsRef<str>,
    ) -> anyhow::Result<CachedModuleMetadata<'_>> {
        let name = name.as_ref();
        for package in &self.inner.packages {
            for module in &package.modules {
                if module.name == name {
                    return Ok(CachedModuleMetadata { metadata: module });
                }
            }
        }
        bail!("module `{}` not found", name)
    }

    /// Finds the metadata for the given package in the registry by its unique name.
    pub async fn get_package(
        &self,
        name: impl AsRef<str>,
    ) -> anyhow::Result<CachedPackageMetadata<'_>> {
        let name = name.as_ref();
        for package in &self.inner.packages {
            if package.name == name {
                return Ok(CachedPackageMetadata { metadata: package });
            }
        }
        bail!("package `{}` not found", name)
    }

    /// Gets the bytecode associated with the module.
    pub async fn get_bytecode(
        &self,
        module_name: impl AsRef<str>,
    ) -> anyhow::Result<Option<&[u8]>> {
        Ok(self
            .bytecode
            .get(module_name.as_ref())
            .map(|v| v.as_slice()))
    }

    pub fn verify(&self, package_metadata: &PackageMetadata) -> anyhow::Result<()> {
        let self_metadata = self.metadata;

        if self_metadata.name != package_metadata.name {
            bail!(
                "Package name doesn't match {} : {}",
                package_metadata.name,
                self_metadata.name
            )
        } else if self_metadata.deps != package_metadata.deps {
            bail!(
                "Dependencies don't match {:?} : {:?}",
                package_metadata.deps,
                self_metadata.deps
            )
        } else if self_metadata.modules != package_metadata.modules {
            bail!(
                "Modules don't match {:?} : {:?}",
                package_metadata.modules,
                self_metadata.modules
            )
        } else if self_metadata.manifest != package_metadata.manifest {
            bail!(
                "Manifest doesn't match {:?} : {:?}",
                package_metadata.manifest,
                self_metadata.manifest
            )
        } else if self_metadata.upgrade_policy != package_metadata.upgrade_policy {
            bail!(
                "Upgrade policy doesn't match {:?} : {:?}",
                package_metadata.upgrade_policy,
                self_metadata.upgrade_policy
            )
        } else if self_metadata.extension != package_metadata.extension {
            bail!(
                "Extensions doesn't match {:?} : {:?}",
                package_metadata.extension,
                self_metadata.extension
            )
        } else if self_metadata.source_digest != package_metadata.source_digest {
            bail!(
                "Source digests doesn't match {:?} : {:?}",
                package_metadata.source_digest,
                self_metadata.source_digest
            )
        }

        Ok(())
    }
