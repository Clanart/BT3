### Title
Unauthenticated `InternalSendTx` on the aggregator gRPC server due to `Noop` interceptor when `client_verification=false` - ([File: core/src/servers.rs])

### Summary
`create_grpc_server` in `core/src/servers.rs` wraps every service in `InterceptedService::new(service, Noop)` whenever `config.client_verification` is `false`, and `Interceptors::Noop::call` unconditionally returns `Ok(req)` with no authentication check at all. Because `create_aggregator_grpc_server` only emits a `tracing::warn!` when `client_verification` is `true` (i.e. it treats `false` as the normal/expected posture for the aggregator), the `is_internal`/`OnlyAggregatorAndSelf` check that is supposed to gate `Internal*`-prefixed RPCs such as `InternalSendTx` is never invoked, letting any TCP peer with no TLS client certificate call it.

### Finding Description
The intended binding is: `caller reaching InternalSendTx == holder of the aggregator's own TLS client certificate` (enforced by `only_aggregator_and_self`'s `is_internal` branch in `core/src/rpc/interceptors.rs:62-69`, which requires `leaf_cert == our_cert`).

In `core/src/servers.rs:106-138`, the interceptor actually installed is chosen purely from `config.client_verification`: [1](#0-0) 

When `client_verification` is `false` (which `create_aggregator_grpc_server` treats as the normal case — it only logs a warning if the flag is `true`, implying `true` is the exceptional/misconfigured state for the aggregator): [2](#0-1) 

`Noop` is selected, and `Interceptors::Noop::call` performs no check whatsoever: [3](#0-2) 

This means the `is_internal` self-certificate check (`core/src/rpc/interceptors.rs:12-20, 62-69`) — the only code path in the whole binary that restricts `Internal*` RPCs to the aggregator's own certificate — is never exercised when `client_verification=false`. Any TCP client that completes a plain TLS handshake with the aggregator's server identity (no client cert required, since `ServerTlsConfig::new().identity(server_identity)` without `.client_ca_root(...)` is used in that branch) can call `ClementineAggregator/InternalSendTx` directly.

### Impact Explanation
The equality "caller of `InternalSendTx` == aggregator itself" collapses to "caller == anyone" under the default/recommended aggregator configuration. This is an unauthenticated state-changing/broadcasting gRPC call, matching the "High" category explicitly defined in this audit's rules (unauthenticated state-changing or broadcasting call). It lets an outside party queue an attacker-chosen transaction into the aggregator's `tx_sender` for broadcast/fee-bumping without holding any key or certificate, mutating internal protocol/broadcast queue state that is meant to be exclusively aggregator-controlled. This is repeatable per call and not bound to any specific deposit/withdrawal — it is a blanket authentication gap on the whole `Internal*` RPC surface of the aggregator, not just `InternalSendTx`.

### Likelihood Explanation
Preconditions: the aggregator is deployed with `client_verification=false`, which per the code's own logic (`tracing::warn!` fires only for `true`) is the documented/expected posture for the aggregator role, and the `automation` feature is enabled (gating `tx_sender`-related code). No key, certificate, collateral, or special role is required — only network reachability to the aggregator's public gRPC/TLS port, which is explicitly within the attacker's granted capabilities. Attacker cost is a single TLS connection and a crafted `SendTxRequest`; no BTC or fees are required to reach the vulnerable call itself. Feasibility is high and the action is trivially repeatable.

### Recommendation
Do not rely solely on `client_verification` to gate `Internal*` RPCs. Enforce the `is_internal` self-certificate check (or an equivalent authenticated-loopback mechanism, e.g. binding internal methods to a Unix socket / mTLS-required listener) unconditionally, regardless of the `client_verification` setting, or refuse to start the aggregator's TCP listener with `Noop` if any `Internal*` method is exposed on it.

#[tokio::test]
async fn internal_send_tx_reachable_without_client_cert() {
    let mut config = create_test_config().await;
    config.client_verification = false; // documented aggregator default

    let (addr, _shutdown) = create_aggregator_grpc_server(config.clone()).await.unwrap();

    // Bare TLS channel: server cert trusted, NO client Identity supplied.
    let tls = ClientTlsConfig::new().ca_certificate(server_ca_cert());
    let channel = Channel::from_shared(format!("https://{addr}"))
        .unwrap()
        .tls_config(tls)
        .unwrap()
        .connect()
        .await
        .unwrap();

    let mut client = ClementineAggregatorClient::new(channel);

    let resp = client
        .internal_send_tx(SendTxRequest {
            raw_tx: attacker_crafted_tx_bytes(),
            fee_type: FeeType::Cpfp as i32,
        })
        .await;

    // Binding under test: caller == aggregator's own cert holder.
    // Broken binding observed: Ok(_) returned instead of Status::unauthenticated.
    assert!(resp.is_ok(), "expected unauthenticated call to be rejected, but it succeeded");
}
