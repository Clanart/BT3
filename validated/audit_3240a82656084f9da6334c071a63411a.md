### Title
Historical rewards accrued while fully locked are retroactively forfeited based on the account's *current* lock/cooldown state - ([File: rewards/vlMGPBaseRewarder.sol])

### Summary
`vlMGPBaseRewarder` (and the identical pattern in `mWOMSVBaseRewarder`) accumulates a user's pending reward bucket (`userRewards[token][account]`) additively across time using the full, unweighted `balanceOf()` of the account, but only applies the "forfeit" haircut for time spent unlocking/in‑cooldown at the moment of claim (`getReward`/`getRewards`/`queueMGP`), using the account's *current* `getRewardablePercentWAD()`. Because the forfeit percentage is applied to the entire cumulative bucket rather than snapshotted per accrual period, rewards that were fully earned while 100% locked get partially forfeited later, purely because the user subsequently calls the ordinary, unprivileged `startUnlock()` function on `VLMGP`/`mWomSV` before claiming. This is the same root-cause class as the reported `fatBERA` bug: reward state tied to an account "status" is not captured/settled before that status changes, so previously-earned rewards are lost.

### Finding Description
`_updateFor` and the `updateRewards` modifier in `vlMGPBaseRewarder.sol` compute the pending reward as a running, cumulative value: [1](#0-0) 

`_earned` folds the newly accrued delta into whatever `userRewards[token][account]` already holds, with no distinction between reward accrued while fully locked vs. accrued while unlocking: [2](#0-1) 

The forfeiture penalty is computed only when the user actually claims, via `_calExpireForfeit`, and it is applied to the *entire* accumulated `userRewards[token][account]` bucket, using the account's rewardable percentage **at the time of the claim call**, not at the time each portion of the reward accrued: [3](#0-2) 

`getRewardablePercentWAD` on `VLMGP` computes the percentage from the account's *current* split between fully-locked MGP and MGP currently in a cooldown/unlock slot: [4](#0-3) 

Crucially, `startUnlock()` is a completely permissionless, ordinary-user function that moves part of a user's locked MGP into a cooldown slot without touching the user's staked balance recorded in `MasterMagpie` (so `balanceOf()`/reward accrual in the rewarder is unaffected), yet it does change `getRewardablePercentWAD()` going forward: [5](#0-4) 

Sequence that reproduces the loss:
1. User locks MGP into `VLMGP`; `rewardablePercentWAD = 100%`.
2. Rewards are queued via `queueNewRewards`, accruing entirely to the user's `userRewards` bucket while still 100% locked (no forfeiture applies yet, since forfeiture is only computed at claim time).
3. Time passes; a large amount of reward accrues in `userRewards[token][user]`.
4. The user later calls `startUnlock()` for even a small portion of their lock (a completely normal, unprivileged action). `getRewardablePercentWAD` now returns a reduced percentage.
5. The user (or `MasterMagpie.multiclaimFor`, which is invoked inside `startUnlock`/`unlock` themselves) triggers `getReward`/`getRewards`/`queueMGP`. `_calExpireForfeit` is applied to the *entire* cumulative `userRewards` bucket — including the portion that was 100% earned prior to any unlocking — using the newly reduced percentage.
6. A portion of rewards that were fully earned while 100% locked is forfeited and redistributed to other stakers via `_queueNewRewardsWithoutTransfer`, permanently taking value away from the original earner.

### Impact Explanation
This causes a direct, permanent loss of already-earned yield for any vlMGP/mWomSV holder who performs the ordinary action of starting an unlock before claiming rewards — the forfeiture is retroactively (and incorrectly) applied to reward-per-token accrued during a period when the account was fully locked and should not be subject to any forfeiture at all. The forfeited amount is not lost to the system (it is redistributed via `_queueNewRewardsWithoutTransfer`), i.e., it is a transfer of the honest user's already-vested yield to other participants without their consent — theft/permanent loss of unclaimed yield for the affected user.

### Likelihood Explanation
High likelihood: `startUnlock()` is a core, frequently used, permissionless user flow (partial unlocking of vote-locked MGP/mWom is a standard use case, not an edge case), and both `startUnlock()` and `unlock()` themselves trigger `multiclaimFor`, meaning almost every ordinary partial-unlock operation will pass through the vulnerable forfeit computation over the account's full historical reward bucket.

### Recommendation
Snapshot (settle) the user's rewardable/forfeitable amount at each accrual boundary rather than applying the account's current `rewardablePercentWAD` retroactively to the whole cumulative bucket. For example, apply `_calExpireForfeit` incrementally to only the newly accrued delta inside `_updateFor`/`updateRewards` (immediately queuing any forfeited delta), so that `userRewards` only ever contains amounts that are already guaranteed rewardable, mirroring the general principle of updating/settling reward state before an account's forfeitable status can change (analogous to calling `_updateRewards` before toggling `isWhitelistedVault` in the `fatBERA` fix).

### Proof of Concept
1. `alice` locks `100e18` MGP into `VLMGP` → `getRewardablePercentWAD(alice) == 1e18` (100%).
2. Admin/manager queues `20e18` of reward token to `vlMGPBaseRewarder` via `queueNewRewards`; after enough time, `earned(alice, token) == 20e18` fully accrued while 100% locked.
3. `alice` calls `startUnlock(50e18)` — a normal unlock of half her position. `getRewardablePercentWAD(alice)` now drops (e.g., to ~50%, growing toward 100% again only after the cooldown period elapses).
4. `alice` claims via `MasterMagpie` → `vlMGPBaseRewarder.getReward` → `_sendReward` computes `_calExpireForfeit(alice, 20e18)` using the now-reduced percentage, forfeiting roughly half of the `20e18` reward that was earned entirely while `alice` was 100% locked, and sending it to `_queueNewRewardsWithoutTransfer` for other stakers.
5. `alice` receives less than the `20e18` she was entitled to when the reward accrued, despite never having been in cooldown during the accrual window.

    function _sendReward(address _rewardToken, address _account, address _receiver) internal {
        uint256 forfeitAmount = _calExpireForfeit(_account, userRewards[_rewardToken][_account]);
        uint256 toSend = userRewards[_rewardToken][_account] - forfeitAmount;


        userRewards[_rewardToken][_account] = 0;
            
        if (toSend > 0) {
            IERC20(_rewardToken).safeTransfer(_receiver, toSend);
            emit RewardPaid(_account, _receiver, toSend, _rewardToken);
        }

        if(forfeitAmount > 0)
            _queueNewRewardsWithoutTransfer(forfeitAmount, _rewardToken);
    }

    function _earned(address _account, address _rewardToken, uint256 _userVlmgpShare) internal view returns (uint256) {
        return ((_userVlmgpShare *
                (rewardPerToken(_rewardToken) -
                    userRewardPerTokenPaid[_rewardToken][_account])) /
                10**vlMGPDecimal) + userRewards[_rewardToken][_account];
    }

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalVlmgp = fullyInLock + inCoolDown;
        if (userTotalVlmgp == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalVlmgp;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalVlmgp / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalVlmgp;
                }

            }
        }

        return percent;
    }
