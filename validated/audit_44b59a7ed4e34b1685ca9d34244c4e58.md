Based on the investigation, I found a strong and directly relevant analog. The Python C++ extension explicitly documents and regression-tests a use-after-free class that mirrors the CVE's failed-invariant pattern (operating on an object without validating/tracking its existence before disposal).

## Title
Oneof-switch Use-After-Free on Python C++ Message MergeFrom/MergeFromString — ([File: python/google/protobuf/pyext/message.cc])

### Summary
The Python C++ (`pyext`) implementation of `Message.MergeFrom`/`MergeFromString` wraps C++ sub-messages in long-lived Python wrapper objects (`CMessage`) cached in `composite_fields`. When a bounded, attacker-controlled Protobuf payload switches an active oneof member during a merge, the underlying C++ `Message*` backing an existing Python wrapper can be deleted by `Reflection::ClearOneof`/`TcParser::ChangeOneof` without the wrapper being notified — unless the code explicitly detects and "releases" the field first. This is exactly the invariant violated in CVE-2022-24050 (operate on an object without validating its continued existence/ownership before performing the operation), applied to the parser/merge surface instead of SQL execution.

### Finding Description
`Reflection::ClearOneof` deletes the previous oneof payload once a new field number is written into the oneof case (`generated_message_reflection.cc:3403-3447`), and the table-driven parser's `TcParser::ChangeOneof` performs the same disposal inline during binary parsing (`generated_message_tctable_lite.cc:1989-2053`): [1](#0-0) [2](#0-1) 

Both paths free the pointer previously stored for the *old* active oneof member as soon as the new one wins the parse — the "invariant" being violated in the CVE analog is "do not perform an operation (delete) on an object without first confirming no other live reference still depends on that exact pointer."

In the Python `pyext` binding, a Python `CMessage` wrapper for a oneof sub-message caches the underlying C++ `Message*` directly (`message.h:107-149`). If a user holds a Python reference to `msg.oneof_nested_message` and then calls `msg.MergeFromString(data)` where `data` switches the oneof to a different field, the naive implementation would parse directly into the C++ message, triggering `ChangeOneof`/`ClearOneof` to `delete` the previously active submessage while the Python wrapper still points at it — a use-after-free reachable by an ordinary attacker sending bounded binary protobuf through the public `MergeFromString` API.

This exact bug class was identified and mitigated with `MaybeReleaseOneofBeforeMerge`, which walks `composite_fields` before the merge and calls `InternalReleaseFieldByDescriptor` to detach (rather than delete) any live wrapper whose oneof will be switched by the incoming data: [3](#0-2) 

The `MergeFromStringImpl` entry point documents the exact race being closed — parsing into a throwaway temporary first specifically "to release the wrappers for switching oneof fields in the target message before they are deleted by C++ during the merge, preventing use-after-free bugs": [4](#0-3) 

The regression test `testOneofSwitchMergeUAF` is an explicit reproduction of this exact scenario (hold a wrapper reference across a `MergeFromString` that switches the oneof and would otherwise dangle): [5](#0-4) 

### Impact Explanation
Where this protection (`MaybeReleaseOneofBeforeMerge` / temp-message + `FixupMessageAfterMerge`) is missing or bypassed for a given call path, an attacker who controls only a bounded serialized Protobuf payload delivered to `MergeFrom`/`MergeFromString` can cause a stale Python wrapper to reference freed C++ heap memory. Subsequent attribute access on that wrapper (`sub_ref.bb` in the regression test) reads/writes through a dangling pointer, which is a genuine memory-corruption primitive (type confusion / info-disclosure / potential further corruption depending on heap reuse), consistent in class with the CVE's "operate on a possibly-nonexistent/freed object" root cause. The confirmed fix indicates the vulnerable window was previously reachable purely through the public parsing API with no attacker privilege beyond sending bytes to be merged.

### Likelihood Explanation
High for the historical vulnerable window: the trigger requires only (1) obtaining a Python wrapper reference to a oneof sub-message field, and (2) calling `MergeFrom`/`MergeFromString` with a bounded payload that sets a different member of the same oneof — both are ordinary, documented, unprivileged API usage with attacker-controlled bytes. The current tree contains the fix (`MaybeReleaseOneofBeforeMerge`, temp-message parsing, `FixupMessageAfterMerge`, and the `testOneofSwitchMergeUAF` regression test), so likelihood in the current mainline is low; the residual risk is any code path that mutates a message's oneof directly (bypassing `MergeFromStringImpl`'s guard) while Python wrappers are cached, or an equivalent binding (Ruby/Java) lacking an analogous guard for their own cached wrapper objects — none of which were confirmed vulnerable in this pass, only the Python path was confirmed to have required an explicit, documented fix for this exact class.

### Recommendation
- Audit all mutation entry points that can change a oneof's active field (`MergeFrom`, `CopyFrom`, `SetField` via reflection, text-format/JSON merge) in every language binding that caches native sub-message pointers in wrapper objects, and ensure each path runs the equivalent of `MaybeReleaseOneofBeforeMerge` (detach-before-delete) rather than allowing `ClearOneof`/`ChangeOneof` to delete a pointer that might still be externally referenced.
- Keep/extend the `testOneofSwitchMergeUAF`-style regression coverage for every binding (Ruby, Java/JRuby, PHP) that maintains a wrapper-object cache over native message pointers, since the underlying C++ `ClearOneof`/`ChangeOneof` disposal logic is shared and any binding without an equivalent "release before merge" guard is structurally exposed to the same primitive.
- Consider hardening `ClearOneof`/`ChangeOneof` themselves (e.g., via debug-mode poisoning, already partially done in `Reflection::MaybePoisonAfterClear`) to fail fast under ASan/hardening builds rather than relying solely on each binding independently reimplementing the release-before-merge protocol.

### Proof of Concept

  if (oneof_descriptor->is_synthetic()) {
    ClearField(message, oneof_descriptor->field(0));
    return;
  }

  // it. It will be much faster if an application switches a lot from
  // a few oneof fields.  Time/space tradeoff
  uint32_t oneof_case = GetOneofCase(*message, oneof_descriptor);
  if (oneof_case > 0) {
    const FieldDescriptor* field = descriptor_->FindFieldByNumber(oneof_case);
    if (message->GetArena() == nullptr) {

        case FieldDescriptor::CPPTYPE_STRING: {

              break;

          break;

void TcParser::ChangeOneof(const TcParseTableBase* table,
                           const ClassData* class_data,
                           const TcParseTableBase::FieldEntry& entry,
                           uint32_t field_num, ParseContext* ctx,
                           MessageLite* msg) {
  // The _oneof_case_ value offset is stored in the has-bit index.
  uint32_t* oneof_case = &TcParser::RefAt<uint32_t>(msg, entry.has_idx);
  uint32_t current_case = *oneof_case;
  *oneof_case = field_num;

  // If the member is already active, then it should be merged. We're done.
  if (current_case == field_num) return;

  if (current_case == 0) {
    // If the member is empty, we don't have anything to clear.
    // We must create a new member object.
    InitOneof(table, class_data, entry, msg);
    return;
  }

  // Look up the value that is already stored, and dispose of it if necessary.
  const FieldEntry* current_entry = FindFieldEntry(table, current_case);
  uint16_t current_kind = current_entry->type_card & field_layout::kFkMask;
  uint16_t current_rep = current_entry->type_card & field_layout::kRepMask;
  if (current_kind == field_layout::kFkString) {
    switch (current_rep) {
      case field_layout::kRepAString: {
        auto& field = RefAt<ArenaStringPtr>(msg, current_entry->offset);
        field.Destroy();
        break;
      }
      case field_layout::kRepMString: {
        if (msg->GetArena() == nullptr) {
          RefAt<MicroString>(msg, current_entry->offset).Destroy();
        }
        break;
      }
      case field_layout::kRepCord: {
        if (msg->GetArena() == nullptr) {
          delete RefAt<absl::Cord*>(msg, current_entry->offset);
        }
        break;
      }
      case field_layout::kRepSString:
      case field_layout::kRepIString:
      default:
        internal::Unreachable();
        return;
    }
  } else if (current_kind == field_layout::kFkMessage) {
    switch (current_rep) {
      case field_layout::kRepMessage:
      case field_layout::kRepGroup: {
        auto& field = RefAt<MessageLite*>(msg, current_entry->offset);
        if (!msg->GetArena()) {
          delete field;
        }
        break;
      }
      default:
        internal::Unreachable();
        return;
    }
  }
  InitOneof(table, class_data, entry, msg);

int MaybeReleaseOneofBeforeMerge(CMessage* self, const Message& other) {
  CMessage::CompositeFieldsMap* composite_fields =
      self->composite_fields.TryGet();
  if (!composite_fields) {
    return 0;
  }

  Message* message = AssureWritable(self);
  if (message == nullptr) return -1;
  const Reflection* reflection = message->GetReflection();
  PyMessageFactory* factory = GetFactoryForMessage(self);
  std::vector<const FieldDescriptor*> fields_to_release;
  std::vector<std::pair<const FieldDescriptor*, ScopedPyObjectPtr>>
      nested_message_fields;
  composite_fields->ForEach([&](const void* key, PyObject* value) {
    const FieldDescriptor* descriptor =
        reinterpret_cast<const FieldDescriptor*>(key);
    if (descriptor->cpp_type() == FieldDescriptor::CPPTYPE_MESSAGE &&
        // For normal repeated message, MergeFrom will append the messages.
        // For message map with same keys, it is overwrite
        !descriptor->is_repeated() &&
        reflection->HasField(*message, descriptor)) {
      if (reflection->HasField(other, descriptor)) {
        Py_INCREF(value);
        nested_message_fields.emplace_back(descriptor, value);
      } else {
        // Release oneof message if the other message has set a different oneof
        const OneofDescriptor* oneof = descriptor->containing_oneof();
        if (oneof && reflection->HasOneof(other, oneof)) {
          fields_to_release.push_back(descriptor);
        }
      }
    }
  });

  for (const auto& [field, value] : nested_message_fields) {
    if (MaybeReleaseOneofBeforeMerge(
            reinterpret_cast<CMessage*>(value.get()),
            reflection->GetMessage(other, field, factory->message_factory)) <
        0) {
      return -1;
    }
  }

  for (const FieldDescriptor* field : fields_to_release) {
    if (InternalReleaseFieldByDescriptor(self, field) < 0) {
      return -1;
    }
  }
  return 0;
}

static PyObject* MergeFromStringImpl(CMessage* self, PyObject* arg,
                                     bool is_cleared) {
  Py_buffer data;
  if (PyObject_GetBuffer(arg, &data, PyBUF_SIMPLE) < 0) {
    return nullptr;
  }
  auto cleanup_data = absl::MakeCleanup([&data] { PyBuffer_Release(&data); });

  Message* message = AssureWritable(self);
  if (message == nullptr) {
    return nullptr;
  }

  // We parse into a temporary message first to detect oneof switches before
  // modifying the target message. This allows us to release the wrappers
  // for switching oneof fields in the target message before they are deleted
  // by C++ during the merge, preventing use-after-free bugs.
  // We use heap allocation (nullptr arena) for the temporary message so that
  // it is collected immediately after the merge, avoiding wasting arena memory.
  std::unique_ptr<Message> temp_message;
  Message* merge_dst;

  if (is_cleared) {
    // Check that it is really empty.
    ABSL_DCHECK_EQ(message->ByteSizeLong(), 0);
    merge_dst = message;
  } else {
    temp_message.reset(message->New(nullptr));
    merge_dst = temp_message.get();
  }

  PyMessageFactory* factory = GetFactoryForMessage(self);
  int depth = allow_oversize_protos
                  ? INT_MAX
                  : io::CodedInputStream::GetDefaultRecursionLimit();
  const char* ptr;
  internal::ParseContext ctx(
      depth, false, &ptr,
      absl::string_view(static_cast<const char*>(data.buf), data.len));

  ctx.data().pool = factory->pool->pool->get();
  ctx.data().factory = factory->message_factory;

  ptr = merge_dst->_InternalParse(ptr, &ctx);

  if (is_cleared) {
    // If we merged into the final destination, fix up now before we might have
    // an early exit.
    FixupMessageAfterMerge(self);
  }
