### Title
Unbounded `io.ReadAll(r.Body)` in NewRelic/Datadog HTTP-RPC tracing wrappers allows memory-exhaustion DoS - (File: networks/rpc/http_newrelic.go)

### Summary
When APM tracing (`NEWRELIC_APP_NAME`/`NEWRELIC_LICENSE` or `DD_TRACE_ENABLED`) is configured on a Kaia node's public JSON-RPC HTTP endpoint, every incoming request body is fully buffered into memory via `io.ReadAll` before any request-size validation occurs, allowing an unauthenticated RPC caller to exhaust node memory with a single oversized HTTP request — the same bug class as CVE-2022-31073 (KubeEdge ServiceBus DoS from an unbounded HTTP body read).

### Finding Description
The normal JSON-RPC HTTP path enforces a body-size cap: `newHTTPServerConn` wraps the request body in `io.LimitReader(r.Body, int64(common.MaxRequestContentLength))` [1](#0-0) , and `validateRequest` rejects any request whose `Content-Length` exceeds `common.MaxRequestContentLength` (512 KiB) [2](#0-1)  before the body is read.

However, `NewHTTPServer` wraps the handler chain with the NewRelic and/or Datadog tracing handlers *outside* the handler that performs this validation: [3](#0-2) 

Both tracing wrappers call `getRPCRequests(r)` to extract the RPC method name for span naming, and that helper reads the entire body with no size limit whatsoever: [4](#0-3) 

`newNewRelicHTTPHandler` and `newDatadogHTTPHandler` invoke `getRPCRequests(r)` unconditionally on every request, prior to calling the inner `handler.ServeHTTP` that would otherwise perform the `Content-Length` check: [5](#0-4)  and [6](#0-5) .

Because `io.ReadAll` has no bound, an attacker can send an HTTP POST with an arbitrarily large (or `Transfer-Encoding: chunked`, unbounded) body to the public RPC port, forcing the node to allocate memory proportional to the attacker-controlled body size before the existing 512 KiB `MaxRequestContentLength` guard in `validateRequest` ever gets a chance to run.

### Impact Explanation
An unprivileged, unauthenticated network caller with access to the node's public JSON-RPC HTTP endpoint can send one or a handful of large-bodied HTTP requests to force excessive heap allocation, exhausting node memory. This can crash or degrade the kaia node process, denying RPC service and potentially destabilizing the host, mirroring the "Availability: High" impact rated in the referenced advisory. This is gated on the node operator having enabled APM tracing (NewRelic or Datadog env vars), a config-dependent condition analogous to the `serviceBus.enable: true` gate in the original KubeEdge advisory.

### Likelihood Explanation
Likelihood is limited to deployments that have enabled NewRelic or Datadog tracing via environment variables — a common operational practice for production RPC nodes/infrastructure providers (e.g., KAS-style deployments, given the `parseKASHeader`/KAS-specific code present in the same file) [7](#0-6) . Where enabled, exploitation requires only a single crafted HTTP request with no authentication, making it trivial to trigger.

### Recommendation
Bound the body read in `getRPCRequests` the same way the primary RPC path does, e.g. wrap `r.Body` with `io.LimitReader(r.Body, int64(common.MaxRequestContentLength))` (or `http.MaxBytesReader`) before calling `io.ReadAll`, and/or perform the existing `validateRequest`/`Content-Length` check before invoking the NewRelic/Datadog wrappers so oversized requests are rejected prior to any buffering.

### Proof of Concept
1. Run a Kaia node with HTTP RPC enabled and `NEWRELIC_APP_NAME`/`NEWRELIC_LICENSE` (or `DD_TRACE_ENABLED=true`) set.
2. Send `POST /` to the RPC endpoint with `Content-Type: application/json` and a body far exceeding 512 KiB (e.g. several hundred MB, or via chunked transfer-encoding with no `Content-Length`).
3. `newNewRelicHTTPHandler`/`newDatadogHTTPHandler` calls `getRPCRequests(r)` → `io.ReadAll(r.Body)`, buffering the entire payload in memory regardless of size, before `validateRequest`'s `MaxRequestContentLength` check in the wrapped handler ever executes.
4. Repeating this with multiple large/concurrent requests exhausts node memory, causing denial of service.

func validateRequest(r *http.Request) (int, error) {
	if r.Method == http.MethodPut || r.Method == http.MethodDelete {
		return http.StatusMethodNotAllowed, errors.New("method not allowed")
	}
	if r.ContentLength > int64(common.MaxRequestContentLength) {
		err := fmt.Errorf("content length too large (%d>%d)", r.ContentLength, int64(common.MaxRequestContentLength))
		return http.StatusRequestEntityTooLarge, err
	}

// getRPCRequests copies a http request body data and parses RPC requests from the data.
// It returns a slice of RPC request, an indication if these requests are in batch, and an error.
// Ethereum returns []*jsonrpcMessage, which replaces []rpcRequest
func getRPCRequests(r *http.Request) ([]*jsonrpcMessage, bool, error) {
	reqBody, err := io.ReadAll(r.Body)
	if err != nil {
		logger.Error("cannot read a request body", "err", err)
		return nil, false, err
	}

	r.Body = io.NopCloser(bytes.NewReader(reqBody))
	conn := &httpServerConn{Reader: io.NopCloser(bytes.NewReader(reqBody)), Writer: bytes.NewBufferString(""), r: r}

	codec := NewCodec(conn)

	defer codec.close()

	return codec.readBatch()
}
