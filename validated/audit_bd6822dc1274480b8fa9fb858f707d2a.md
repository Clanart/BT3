### Title
Blame proof returned before PoP verification leaks ECDH key, letting any DKG participant recover all secret shares / the group key - (File: crypto/dkg/pedpop/src/lib.rs)

### Summary
`KeyMachine::calculate_share` decrypts every received `EncryptedMessage` and unconditionally builds an `EncryptionKeyProof` (which publicly reveals the ECDH shared point `enc_key * msg.key`) before the batch verifier has actually verified the message's Schnorr proof-of-possession. On the early `from_repr` failure path it returns `InvalidShare { blame: Some(proof) }` without ever checking the PoP. A malicious participant can replay an honest sender's per-message key with garbage ciphertext, causing victims to publish blame proofs that reveal the decryption key for the honest sender's real message — exactly the attack the PoP was added to prevent.

### Finding Description
In `Encryption::decrypt` (`crypto/dkg/pedpop/src/encryption.rs`), the PoP is only *queued* into the `BatchVerifier` (`msg.pop.batch_verify`, line 479), yet the ECDH value `key = ecdh(&self.enc_key, msg.key)` is computed and an `EncryptionKeyProof { key, dleq }` is immediately returned (lines 487–499). `EncryptionKeyProof::write` serializes `key` in the clear (lines 271–274).

In `KeyMachine::calculate_share` (`crypto/dkg/pedpop/src/lib.rs`, lines 476–499), when the decrypted bytes fail `C::F::from_repr`, the function returns `PedPoPError::InvalidShare { participant: l, blame: Some(blame) }` immediately (lines 479–482) — `batch.verify_with_vartime_blame()` at line 493 is never reached, so the PoP for that message is never verified. The documented defense at `encryption.rs:84–90` — Eve replaying Alice's key `X` so Bob's blame reveals `bX` (Alice's message key) — is therefore bypassed whenever the forged message decrypts to non-canonical scalar bytes, which the attacker fully controls (they pick the ciphertext; probability ~≥1/2 per attempt for Ristretto/ed25519 reprs, and retriable across attempts).

The processor broadcasts this blame (`processor/src/key_gen.rs:424`, `blame.serialize()`), so the ECDH point is public.

### Impact Explanation
An attacker Eve observes Alice's `EncryptedMessage` to Bob (key `K_A`, ciphertext `C_A` encrypting Alice's share `s_AB`). Eve sends Bob a forged message `{key: K_A, pop: <invalid>, msg: <garbage>}`. Bob's `from_repr` fails and he publishes `EncryptionKeyProof` revealing `K_shared = b·K_A` where `b` is Bob's encryption private key — the exact keystream seed for `cipher(context, K_shared)` protecting `C_A`. Eve decrypts `C_A` and recovers `s_AB`. Repeating for every (sender, recipient) pair recovers every participant's polynomial and hence the full group secret key — complete threshold-key compromise by a single unprivileged participant using only public inputs to `EncryptedMessage::read`/`calculate_share`.

### Likelihood Explanation
Any DKG participant (or anyone who can deliver bytes to `calculate_share`) can mount this; no collusion needed. The forged message needs no valid PoP, and the garbage ciphertext need only decode to a non-canonical scalar. The attack is deterministic in structure and repeatable across all victims in the same session.

### Recommendation
Verify the PoP *before* constructing/returning the `EncryptionKeyProof`: in `calculate_share`, don't emit `blame` until `batch.verify_with_vartime_blame()` confirms the `BatchId::Decryption(l)` statement; on `from_repr` failure, only attach the blame proof after the queued PoP verifies (e.g., run a targeted verification of that message's PoP before returning `Some(blame)`, else return `blame: None` and blame the sender for an invalid PoP). Alternatively, make `decrypt` synchronous-verify the Schnorr PoP before computing the ECDH/proof.

### Proof of Concept
1. Run PedPoP with n ≥ 2; Eve is participant E, victim Bob is participant B, honest sender Alice is A.
2. Alice's `generate_secret_shares` emits `EncMsg_AB = {key: K_A = k_A·G, pop, msg: C_A}` where `C_A = keystream(ecdh(k_A, B_pub)) ⊕ s_AB`.
3. Eve sends Bob `EncMsg_fake = {key: K_A, pop: invalid_sig, msg: random_bytes}`.
4. Bob's `calculate_share`: `decrypt` queues the (failing) PoP, computes `key = b·K_A`, returns `proof = {key: b·K_A, dleq}`; `from_repr(random_bytes)` fails → returns `InvalidShare { blame: Some(proof) }` before `batch.verify...` runs.
5. Processor broadcasts `proof.serialize()`, exposing `b·K_A`.
6. Eve computes `cipher(context, b·K_A)` and XORs `C_A`, recovering Alice's share `s_AB`. Repeat for all senders/recipients to recover the group secret key.
