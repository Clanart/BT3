### Title
Gasless transaction pool admission checks invoke attacker-controlled ERC20/router contracts with a fixed 300,000,000-gas budget unrelated to the transaction's own gas limit, enabling free computational DoS amplified by recursive contract calls - (File: `kaiax/gasless/impl/tx_pool.go`)

### Summary
`kaiax/gasless` implements KIP-247 gasless transactions. When a `GaslessApproveTx` or `GaslessSwapTx` is submitted to the mempool, the module's `GetCheckBalance()` hook is invoked and internally calls `checkBalanceForApprove`/`checkBalanceForSwap`, which perform read-only `eth_call`-style invocations (`BalanceOf`, `Allowance`, `GetAmountIn`) against a **sender-supplied token address** and the registered `GaslessSwapRouter`. [1](#0-0) [2](#0-1) 

These calls are executed through `BlockchainContractBackend.callContract`, which assigns a hardcoded `call.Gas = 3e8` (300,000,000 gas) whenever the caller does not specify a gas value — completely disconnected from the actual gas limit the sender declared on the pending transaction (300,000 in the project's own test fixtures). [3](#0-2) [4](#0-3) 

### Finding Description
The root cause mirrors the tokenfactory advisory's bug class: a "hook" invoked as part of normal transaction admission grants far more computational budget to externally-controlled contract code than what the originating transaction is metered/paid for, and that budget is not tied to (nor deducted from) the sender's actual gas allowance.

In Kaia's implementation:
1. `IsModuleTx`/`GetCheckBalance` in `kaiax/gasless/impl/tx_pool.go` are registered as a `TxPoolModule` hook and run on transaction pool admission for any gasless-tagged transaction (identified purely by matching a KIP-247 selector on the `To`/router address — no privilege required). [5](#0-4) 
2. `checkBalanceForSwap` decodes `swapArgs.Token` directly from the attacker-supplied transaction payload and calls `BalanceOf`/`Allowance` on that address, and `GetAmountIn` on the router, all via `BlockchainContractBackend`. [6](#0-5) 
3. The backend used for these calls defaults unset `call.Gas` to `3e8` gas — roughly 1000x larger than a typical 300,000-gas gasless swap transaction's own `GasLimit`. [7](#0-6) 
4. Since `swapArgs.Token` is fully attacker-controlled, a malicious contract deployed at that address can implement a `balanceOf`/`allowance` function containing deeply recursive or otherwise expensive EVM logic, consuming close to the entire 300,000,000-gas budget on every single mempool admission check — while the sender pays zero gas for this computation (the call uses `gasPrice = 0` and is not part of any executed/charged transaction).
5. Because tx pool admission checks are re-run whenever the transaction is (re-)evaluated for promotion/pending status by any node receiving the broadcasted transaction, an attacker can repeatedly trigger this expensive, unpaid computation across the network by submitting or resubmitting a single crafted gasless transaction referencing the malicious token.

This is structurally identical to the tokenfactory finding: an unprivileged, single-transaction-reachable "hook" call path executes external, attacker-controlled contract code under a gas/computation budget that is neither derived from nor limited by the actual transaction's declared gas, and that budget can be amplified through recursive calls inside the attacker's contract.

### Impact Explanation
Any account (no special permissions required) can submit a `GaslessSwapTx` (and/or `GaslessApproveTx`) referencing a malicious "token" contract. Every node that receives and evaluates this transaction for mempool admission will execute up to 300,000,000 gas worth of attacker-chosen EVM computation for free, repeatedly, as the transaction propagates and is re-validated. This is a network-wide computational resource-exhaustion vector reachable purely through public RPC transaction submission — matching CWE-400/CWE-770 (uncontrolled resource consumption), analogous in severity class to the tokenfactory hook issue, since it allows an unprivileged actor to impose unbounded, unpaid computation on validating nodes.

### Likelihood Explanation
High likelihood: gasless transactions are processed by any full/endpoint node running the `kaiax/gasless` module whenever `GaslessConfig.ShouldCheckToken()`/`ShouldCheckSwapAmount()` are enabled (the module's default operating mode per KIP-247). No special timing, staking, or governance conditions are needed — a single crafted transaction with a malicious token address suffices, and it can be resubmitted or rebroadcast cheaply.

### Recommendation
Bound the gas used for these tx-pool admission `CallContract` invocations (in `checkBalanceForApprove`/`checkBalanceForSwap` and the underlying `BlockchainContractBackend.callContract`) to a small, fixed, and non-amplifiable value appropriate for simple `balanceOf`/`allowance`/`getAmountIn` view calls (e.g., tens of thousands of gas), rather than defaulting to `3e8`. Additionally, consider caching/deduplicating these checks per token address per block and enforcing a strict per-check wall-clock or opcode-computation-cost cap (mirroring the existing `ComputationCostLimit` EVM safeguard) so that a malicious contract cannot consume disproportionate node resources during mempool admission.

### Proof of Concept
1. Deploy a malicious ERC20-like contract at address `M` whose `balanceOf(address)` and `allowance(address,address)` functions execute deep recursive/self-referential external calls designed to consume close to 300,000,000 gas before returning.
2. Craft and sign a `GaslessSwapTx` (KIP-247 `SwapForGas`) with `token = M`, a plausible `minAmountOut`/`amountRepay`, and normal `GasLimit` (e.g., 300,000).
3. Broadcast the transaction to the network. Each node evaluating tx-pool admission for this transaction invokes `checkBalanceForSwap`, which calls `M.balanceOf(sender)`/`M.allowance(sender, router)` through `BlockchainContractBackend.callContract` with `call.Gas = 3e8`, executing the attacker's expensive recursive logic in full, at zero cost to the attacker.
4. Repeat by resubmitting/rebroadcasting the same or similar transactions (with incrementing nonce) to sustain repeated unpaid computational load across the network's mempools. [2](#0-1) [8](#0-7)

func (g *GaslessModule) GetCheckBalance() func(tx *types.Transaction) error {
	return func(tx *types.Transaction) error {
		if approveArgs, ok := decodeApproveTx(tx, g.signer); ok {
			return g.checkBalanceForApprove(approveArgs)
		}
		if swapArgs, ok := decodeSwapTx(tx, g.signer); ok {
			return g.checkBalanceForSwap(swapArgs, tx.Nonce())
		}
		return errors.New("not a gasless transaction") // should not happen because IsModuleTx is called before GetCheckBalance
	}
}

	swapRouter := g.swapRouter

	// tx.minAmountOut >= tx.amountRepay

		}

		// tx.amountIn >= gsr.getAmountIn(minAmountOut)

		if err != nil {
			return err
		}

//
// Returns call result in []byte.
// Returns error when:
// - cannot find the corresponding block or stateDB
// - VM revert error
// - VM other errors (e.g. NotProgramAccount, OutOfGas)
// - Error outside VM
func (b *BlockchainContractBackend) CallContract(ctx context.Context, call kaia.CallMsg, blockNumber *big.Int) ([]byte, error) {
	block, state, err := b.getBlockAndState(blockNumber)
	if err != nil {
		return nil, err
	}

	res, err := b.callContract(call, block, state)
	if err != nil {
		return nil, err
	}
	if len(res.Revert()) > 0 {
		return nil, blockchain.NewRevertError(res)
	}
	return res.Return(), res.Unwrap()
}

func (b *BlockchainContractBackend) callContract(call kaia.CallMsg, block *types.Block, state *state.StateDB) (*blockchain.ExecutionResult, error) {
	gasPrice := common.Big0
	if call.GasPrice != nil && (call.GasFeeCap != nil || call.GasTipCap != nil) {
		return nil, errors.New("both gasPrice and (maxFeePerGas or maxPriorityFeePerGas) specified")
	}
	if !b.bc.Config().IsKaiaForkEnabled(block.Number()) { // before KIP-162
		if call.GasPrice != nil {
			gasPrice = call.GasPrice
		}
	} else { // after KIP-162
		if call.GasPrice != nil {
			gasPrice = call.GasPrice
		} else {
			if call.GasFeeCap == nil {
				call.GasFeeCap = big.NewInt(0)
			}
			if call.GasTipCap == nil {
				call.GasTipCap = big.NewInt(0)
			}
			gasPrice = math.BigMin(new(big.Int).Add(call.GasTipCap, block.Header().BaseFee), call.GasFeeCap)
		}
	}

	if call.Gas == 0 {
		call.Gas = uint64(3e8) // enough gas for ordinary contract calls
	}
