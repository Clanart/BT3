### Title
Oracle slash fraction applies retroactively to accumulated vote penalty counters - (File: x/oracle/keeper/slash.go)

### Summary
The oracle module accumulates `VotePenaltyCounter` records over a `SlashWindow` and then, at the end of the window, reads `SlashFraction` and `MinValidPerWindow` from the current parameter store to decide how much stake to burn. These percentages are not cached when the window starts, so a governance parameter update during the window retroactively changes the penalty for votes already cast.

### Finding Description
In `x/oracle/keeper/slash.go`, `SlashAndResetCounters` fetches `minValidPerWindow` and `slashFraction` from the param space at slash time [1](#0-0) . It then iterates over `VotePenaltyCounter` entries accumulated during the slash window and, for each validator whose `validVoteRate` is below the current `minValidPerWindow`, calls `StakingKeeper.Slash` with the current `slashFraction` [2](#0-1) . The counter only stores success/miss/abstain counts; it does not record the `SlashFraction` or `MinValidPerWindow` in effect when the window began. Therefore, if either parameter is changed via governance before `EndBlocker` invokes `SlashAndResetCounters`, the new values are applied to the entire window's accumulated record.

### Impact Explanation
A validator's staked `usei` can be burned at a higher rate than was in effect when the validator cast its votes. If `SlashFraction` is raised toward 100% during a slash window, validators whose `validVoteRate` falls below `MinValidPerWindow` lose proportionally more stake than they would have under the original parameters. This is concrete fund loss for validators and their delegators.

### Likelihood Explanation
The path is triggered automatically at the end of each oracle `SlashWindow` in `EndBlocker` [3](#0-2) . The parameter change requires a governance proposal, but once active, the next `EndBlocker` applies it retroactively to all counters accumulated during the current window. Any validator participating in oracle voting is exposed.

### Recommendation
Cache the effective `SlashFraction` and `MinValidPerWindow` in a per-slash-window state record (or in each `VotePenaltyCounter`) when the window begins, and use those cached values in `SlashAndResetCounters` instead of reading current params.

### Proof of Concept
1. At block H, oracle `SlashWindow` starts with `SlashFraction = 1%` and `MinValidPerWindow = 50%` [4](#0-3) .
2. Validator V submits votes during the window and accumulates `SuccessCount=0, MissCount=1` (`validVoteRate = 0%`).
3. Before the window ends, governance passes a proposal setting `SlashFraction = 100%`.
4. `EndBlocker` calls `SlashAndResetCounters`, which reads the new `SlashFraction` [5](#0-4)  and slashes V's full bonded stake instead of 1%.

func EndBlocker(ctx sdk.Context, k keeper.Keeper) {
	start := time.Now()
	defer func() {
		oracleMetrics.endBlockerDuration.Record(ctx.Context(), time.Since(start).Seconds())
	}()

	params := k.GetParams(ctx)
	// Do slash who did miss voting over threshold and
	// reset miss counters of all validators at the last block of slash window
	if utils.IsPeriodLastBlock(ctx, params.SlashWindow) {
		k.SlashAndResetCounters(ctx)
		// Compare vote targets and actives and remove excess feeds
		k.RemoveExcessFeeds(ctx)
	}
