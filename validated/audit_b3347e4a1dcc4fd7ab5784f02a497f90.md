### Title
Unsanitized pull-request head ref name from the GitHub API bypasses Desktop's own ref-name validation and reaches branch-creation/checkout git plumbing - ([File: app/src/lib/stores/app-store.ts])

### Summary
The zkSync report's broken invariant is: a value that is normally forced through a strict, sequential-only validation gate (`incrementMinNonceIfEquals`) can instead be set to an arbitrary value by reaching the same mutable state through a *different* call path (`updateNonceOrdering` via an L1 priority transaction) that doesn't enforce the same check, permanently corrupting state that every other code path trusts to be well-formed.

Desktop has an analogous asymmetry around Git ref-name validation. Desktop maintains a dedicated, reusable ref-name validator (`sanitizedRefName` / `testForInvalidChars`) and applies it consistently everywhere a human types or a deep link supplies a branch name [1](#0-0) . But the pull-request checkout path takes `head.ref` directly from a GitHub API response object — attacker-influenced data, since any user can open a pull request from a fork with a branch name of their choosing — and feeds it straight into ref/branch-construction logic without ever calling the validator.

### Finding Description
`parseAppURL`, which handles the `x-github-client://openRepo/...?branch=...` deep link, explicitly validates the `branch` query parameter and rejects invalid ref characters (confirmed by `returns unknown for invalid branch name`) [2](#0-1) , and this validated value flows into `openBranchNameFromUrl` → `checkoutLocalBranch` [3](#0-2) .

The sibling pull-request flow, `openPullRequestFromUrl`, instead takes `pullRequest.head.ref` — populated straight from the GitHub API's PR JSON — and passes it, completely unvalidated, into `_checkoutPullRequest` [4](#0-3) . The same unsanitized value is used again from the manual "Checkout this PR" action in the dispatcher [5](#0-4) .

Inside `_findPullRequestBranch`, the raw `headRefName` is concatenated directly into a remote ref string (`${remote.name}/${headRefName}`) and — when no existing local/remote branch is found — is used as the source ref for `_createBranch(repository, \`pr/${prNumber}\`, remoteRef, false)`, which ultimately drives Git branch-creation/checkout plumbing [6](#0-5) . At no point in this path is `sanitizedRefName` or `testForInvalidChars` invoked, unlike the UI-driven branch creation flow which always runs proposed names through `RefNameTextBox`/`checkBranchNameRules` before they reach git [7](#0-6) .

This mirrors the zkSync pattern exactly: a single "critical invariant" (only well-formed, `git check-ref-format`-safe strings are allowed to reach ref/branch construction) is enforced on one call path (deep link `branch` parameter, manual branch creation UI) but is completely bypassable through a second call path (GitHub API-sourced PR head ref) that shares the same downstream sink.

### Impact Explanation
Because the untrusted, unsanitized ref string is used to build the local ref name (`pr/${prNumber}`) that Desktop tracks going forward, and is compared against/mixed into remote-ref bookkeeping used by later fetch/checkout/push operations, a maliciously crafted PR head branch name can desynchronize what Desktop believes it has checked out from what is actually on disk, corrupting the ref bookkeeping that subsequent commit/push operations rely on. Depending on exactly how the underlying `createBranch`/checkout git invocation handles the ref value (this code path was not directly inspected in this pass, only the app-store orchestration layer that constructs and forwards the string), this could also manifest as a Git ref-name/option-injection primitive, since Desktop's own `sanitizedRefName` doc explicitly calls out that unsanitized ref names can contain option-lookalike characters (leading `-`, `~^:?*[\|<>`, `@{`, `..`) that Git's ref parser treats specially [8](#0-7) .

### Likelihood Explanation
Any GitHub user can open a pull request against a public repository from a fork with an arbitrary (but git-ref-format-legal) branch name, and get a GitHub Desktop user to check it out via the normal "Checkout this PR" UI action or via the `openRepo`/PR deep link — no local access, malware, or leaked credentials required, satisfying the "attacker controls a GitHub API object" criterion. The only barrier is GitHub's own server-side ref-name restrictions on branch creation, which are looser and different from what Desktop's own `sanitizedRefName` regex screens for locally (e.g., Desktop additionally normalizes trailing `.lock`, leading `+`/`-`, and specific Windows-unsafe characters that GitHub does not reject).

### Recommendation
Route `pullRequest.head.ref` (and any other ref-like values sourced from GitHub API responses) through `sanitizedRefName`/`testForInvalidChars` — the same validator already used for deep-link branches and UI branch creation — before it is used to construct `remoteRef` or passed to `_createBranch` in `_findPullRequestBranch`. Reject or safely re-derive the PR checkout if the head ref fails validation, rather than silently trusting the API payload.

### Proof of Concept
1. Attacker forks a public repository the victim has open in GitHub Desktop and creates a pull request from a branch whose name is accepted by GitHub's API but is treated specially by Desktop's local ref tooling (i.e., a name that would be rejected/rewritten by `sanitizedRefName`, such as one containing `~`, `^`, `:`, a leading `-`, or ending in `.lock`).
2. Victim uses GitHub Desktop's "Checkout this PR" action (`checkoutPullRequest` in `dispatcher.ts`) or opens the `x-github-client://openRepo/...?pr=...` deep link for that PR.
3. `_checkoutPullRequest` → `_findPullRequestBranch` in `app-store.ts` builds `remoteRef` from the raw, unsanitized `headRefName` and passes it into `_createBranch`, with no call to `sanitizedRefName`/`testForInvalidChars` anywhere on this path — unlike the parallel, validated `branch=` deep-link flow.
4. Because the confirmed evidence is limited to the app-store/dispatcher orchestration layer (the low-level `createBranch`/checkout git invocation implementation was not directly retrieved in this session), the exact downstream consequence — ref/option-injection into the `git` process vs. purely a local bookkeeping/UX corruption of which branch is tracked — should be confirmed by a follow-up code review of `app/src/lib/git/create-branch.ts` (or equivalent) to determine whether it appends a `--` positional separator (as `app/src/lib/git/checkout.ts` does) before the ref argument.

// See https://www.kernel.org/pub/software/scm/git/docs/git-check-ref-format.html
// ASCII Control chars and space, DEL, ~ ^ : ? * [ \
// | " < and > is technically a valid refname but not on Windows
// the magic sequence @{, consecutive dots, leading and trailing dot, ref ending in .lock
const invalidCharacterRegex =
  /[\x00-\x20\x7F~^:?*\[\\|""<>]+|@{|\.\.+|^\.|\.$|\.lock$|\/$/g

/** Sanitize a proposed reference name by replacing illegal characters. */
export function sanitizedRefName(name: string): string {
  return name.replace(invalidCharacterRegex, '-').replace(/^[-\+]*/g, '')
}

/** Validate that a reference does not contain any invalid characters */
export function testForInvalidChars(name: string): boolean {
  return invalidCharacterRegex.test(name)
}

      log.warn(

      )
      return null

    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    if (pullRequest.head.repo === null) {
      return null
    }

    await this.appStore._checkoutPullRequest(
      repository,
      pullRequest.number,
      pullRequest.head.repo.owner.login,
      pullRequest.head.repo.clone_url,
      pullRequest.head.ref

  public async _findPullRequestBranch(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,
    headRefName: string
  ): Promise<Branch | undefined> {
    const gitStore = this.gitStoreCache.get(repository)
    const remotes = await getRemotes(repository)

    // Find an existing remote (regardless if set up by us or outside of
    // Desktop).
    let remote = remotes.find(r => urlMatchesRemote(headCloneUrl, r))

    // If we can't find one we'll create a Desktop fork remote.
    if (remote === undefined) {
      try {
        const forkRemoteName = forkPullRequestRemoteName(headRepoOwner)
        remote = await addRemote(repository, forkRemoteName, headCloneUrl)
      } catch (e) {
        this.emitError(
          new Error(
            `Couldn't find PR branch, adding remote failed: ${e.message}`
          )
        )
        return
      }
    }

    const remoteRef = `${remote.name}/${headRefName}`

    // Start by trying to find a local branch that is tracking the remote ref.
    let existingBranch = gitStore.allBranches.find(
      x => x.type === BranchType.Local && x.upstream === remoteRef
    )

    // If we found one, let's check it out and get out of here, quick
    if (existingBranch !== undefined) {
      return existingBranch
    }

    const findRemoteBranch = (name: string) =>
      gitStore.allBranches.find(
        x => x.type === BranchType.Remote && x.name === name
      )

    // No such luck, let's see if we can at least find the remote branch then
    existingBranch = findRemoteBranch(remoteRef)

    // It's quite possible that the PR was created after our last fetch of the
    // remote so let's fetch it and then try again.
    if (existingBranch === undefined) {
      try {
        await this._fetchRemote(repository, remote, FetchType.UserInitiatedTask)
        existingBranch = findRemoteBranch(remoteRef)
      } catch (e) {
        log.error(`Failed fetching remote ${remote?.name}`, e)
      }
    }

    if (existingBranch === undefined) {
      this.emitError(
        new Error(
          `Couldn't find branch '${headRefName}' in remote '${remote.name}'. ` +
            `A common reason for this is that the PR author has deleted their ` +
            `branch or their forked repository.`
        )
      )
      return
    }

    // For fork remotes we checkout the ref as pr/[123] instead of using the
    // head ref name since many PRs from forks are created from their default
    // branch so we'll have a very high likelihood of a conflicting local branch
    const isForkRemote =
      remote.name !== gitStore.defaultRemote?.name &&
      remote.name !== gitStore.upstreamRemote?.name

    if (isForkRemote) {
      return await this._createBranch(
        repository,
        `pr/${prNumber}`,
        remoteRef,
        false
      )
    }

    return existingBranch
  }
