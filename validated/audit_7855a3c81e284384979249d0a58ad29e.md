## Analysis

I confirmed `create_new_mirror()` (`chia/data_layer/data_layer_wallet.py:687-703`) creates a mirror coin by curried `P2_PARENT.curry(Program.to(1))` puzzle whose memo simply encodes `[launcher_id, *urls]` — the launcher_id is caller-supplied data embedded in a `CREATE_COIN` condition, not a puzzle-enforced ownership/authorization check tying the spend to actually owning that singleton. [1](#0-0) [2](#0-1) 
Any wallet holder can call `create_new_mirror`/`dl_new_mirror` with an arbitrary `launcher_id` belonging to someone else's store and arbitrary `urls`, paying only a standard fee — no proof of store ownership is required by the mirror puzzle or the wallet RPC handler. [3](#0-2) 
Any full node/wallet that observes this coin and already tracks that launcher id ingests the mirror unconditionally: [4](#0-3) 
Those URLs then flow, unauthenticated and unvalidated, into `DataLayer.update_subscriptions_from_wallet()` and are handed to `data_store.subscribe`/`get_available_servers_for_store`: [5](#0-4) 
`fetch_and_validate()` then iterates these attacker-chosen URLs and issues outbound requests via `http_download()`, which performs a plain `aiohttp` GET to `server_info.url + "/" + filename` with no scheme/host allow-listing, no private-network/metadata-IP blocking, and no verification that the URL's owner is the actual store publisher: [6](#0-5) [7](#0-6) 
This mirrors the sliver bug class closely: an untrusted party (there, the implant; here, any wallet holder able to publish a mirror coin for someone else's launcher_id) can cause the victim's service (teamserver / DataLayer node) to make an unauthenticated outbound network connection to an attacker-chosen destination, without any verification that the intended operator authorized it.

I was **not** able to fully verify from the index alone whether there is any additional client-side allow-list, TLS pinning, or scheme restriction elsewhere in the DataLayer plugin/downloader path that might mitigate this (e.g., in `chia/data_layer/data_layer_util.py` or plugin manager code was not indexed for this check), so this should be validated with the full source before treating it as fully confirmed. The impact is bounded to SSRF-class information leakage/probing (internal service/port scanning, cloud metadata endpoint access) triggered by the DataLayer node's own outbound HTTP client — not consensus-breaking, coin-theft, or asset-forgery impact.

### Title
Unauthenticated on-chain Data Layer mirror coins let any wallet cause victim nodes to send SSRF-style outbound HTTP requests - (chia/data_layer/data_layer.py, chia/data_layer/download_data.py)

### Summary
Any wallet can create a "mirror" coin for **any** DataLayer store's `launcher_id` — not only stores it owns — embedding arbitrary attacker-chosen URLs in the coin's memo. Nodes that subscribe/track that store will unconditionally ingest these URLs and later have `DataLayer.fetch_and_validate()`/`http_download()` issue outbound HTTP GET requests to them with no host/scheme validation.

### Finding Description
`create_mirror_puzzle()` is a generic `P2_PARENT.curry(Program.to(1))` puzzle; the mirror's association to a store is purely a memo value (`launcher_id`, `urls`) attached to a `CREATE_COIN` condition, with no on-chain enforcement that the spender owns or controls that `launcher_id`'s singleton (`chia/wallet/db_wallet/db_wallet_puzzles.py:90-110`). The wallet RPC path `dl_new_mirror` → `create_new_mirror` performs no ownership check before broadcasting the mirror-creation spend bundle (`chia/wallet/wallet_rpc_api.py:3255-3274`, `chia/data_layer/data_layer_wallet.py:687-703`).

When any node tracking that `launcher_id` observes the mirror coin via `coin_added`, it stores the attacker-supplied URLs unconditionally as long as the launcher is tracked (`chia/data_layer/data_layer_wallet.py:775-800`). `DataLayer.update_subscriptions_from_wallet()` copies these URLs directly into the local subscription table used for server selection (`chia/data_layer/data_layer.py:979-985`), and the periodic sync loop's `fetch_and_validate()` picks a URL and calls `insert_from_delta_file()` → `download_file()` → `http_download()`, which performs a raw `aiohttp` GET against `server_info.url + "/" + filename` (`chia/data_layer/data_layer.py:642-694`, `chia/data_layer/download_data.py:298-324`). There is no allow-list, no restriction against internal/loopback/link-local (e.g., cloud metadata `169.254.169.254`) addresses, and no verification that the URL actually belongs to a legitimate mirror of that store before the connection is attempted.

### Impact Explanation
This lets any unprivileged chain participant force any DataLayer-enabled node that subscribes to a targeted store to make outbound HTTP requests to attacker-chosen hosts/ports — classic SSRF: internal network/service probing, hitting cloud metadata endpoints, or leaking the victim node's origin IP behind NAT/proxies. It does not achieve coin theft, supply inflation, or consensus divergence; response bodies are only trusted after being cryptographically verified against the on-chain root (`insert_into_data_store_from_file`), so full data exfiltration back through this channel is limited, but the SSRF request itself (and any side effects on the target of the request) is unauthenticated and attacker-controlled.

### Likelihood Explanation
Likelihood is fairly high for any node operator running a DataLayer service and subscribing to third-party stores: mirror creation only costs a fee and a small amount, requires no special privilege, and the resulting URLs are consumed automatically by the periodic sync loop without operator review.

### Recommendation
- Before accepting mirror URLs, verify the mirror-creating coin's spender is the actual current DataLayer singleton owner for that `launcher_id` (e.g., require the mirror spend to be conditioned on/co-signed with the singleton, or otherwise cryptographically bind mirror creation to store ownership).
- Apply an SSRF-safe HTTP client policy in `http_download()`/`download_file()`: resolve and reject requests to loopback, link-local, private, and cloud-metadata address ranges, and enforce scheme allow-listing (https/http only, no redirects to disallowed hosts).
- Consider requiring explicit operator opt-in/allow-listing of mirror URLs rather than fully automatic consumption from `update_subscriptions_from_wallet()`.

### Proof of Concept
1. Attacker (any wallet) calls `dl_new_mirror` with `launcher_id` set to a victim's existing DataLayer store id and `urls=["http://169.254.169.254/latest/meta-data/"]`, paying only the required fee/amount.
2. Once confirmed on-chain, any node that already tracks/subscribes to that `launcher_id` ingests the mirror via `coin_added()` (`chia/data_layer/data_layer_wallet.py:775-800`) and stores the URL via `update_subscriptions_from_wallet()` (`chia/data_layer/data_layer.py:979-985`).
3. On the next `periodically_manage_data()` cycle, `fetch_and_validate()` selects this URL and `http_download()` issues an unauthenticated GET request from the victim node to the attacker-chosen address (`chia/data_layer/data_layer.py:642-694`, `chia/data_layer/download_data.py:298-324`).

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
