Chia's coin model does not have an ERC20-style `transferFrom` semantics where a third-party token contract can silently skim value during a transfer. In Chia, value movement is defined declaratively via `CREATE_COIN` conditions inside a CLVM puzzle solution, and consensus itself enforces that the sum of output coin amounts on a spend matches the committed values [1](#0-0) . There is no code path where a wallet or manager contract "pulls" a token from a user and then acts on an assumed vs. actual received balance — the puzzle hash and coin amount are fixed to the coin ID itself, so a coin either exists with exactly the specified amount or the spend is invalid at the block-validation layer. CAT coins (`CAT_MOD`) enforce token conservation through TAIL and inner-puzzle delta checks rather than an external contract-controlled transfer step, so there's no equivalent "fee-on-transfer" hazard for CAT-as-collateral analogs (e.g., in DID/NFT ownership or CR-CAT flows) reachable by an unprivileged spend-bundle submitter or wallet user [2](#0-1) .
