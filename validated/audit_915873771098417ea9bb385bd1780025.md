### Title
SSRF via on-chain DataLayer mirror URLs fetched automatically by any tracking node - (File: chia/data_layer/data_layer_wallet.py, chia/data_layer/data_layer.py, chia/data_layer/download_data.py)

### Summary
Any unprivileged spend-bundle submitter can create a coin with the DataLayer "mirror" puzzle hash and an arbitrary URL memo. Every node that tracks the referenced DataLayer singleton (store_id/launcher_id) will automatically persist that URL as a mirror server and later have its `DataLayer` service make outbound HTTP(S) requests to it while trying to sync data, with no restriction against internal/private network destinations. This is the same bug class as GHSA-q347-cg56-pcq4 (Gogs SSRF via repository migration): user-supplied remote endpoints are blindly dereferenced by server-side infrastructure, enabling internal network probing/SSRF.

### Finding Description
The DataLayer mirror puzzle is a trivial pass-through puzzle (`P2_PARENT.curry(Program.to(1))`), so creating a coin at that puzzle hash requires no special authorization beyond a normal `CREATE_COIN` condition in any spend bundle: [1](#0-0) 

When such a coin confirms, `DataLayerWallet.coin_added()` decodes the memo as `(launcher_id, urls)` via `get_mirror_info()` and — if that `launcher_id` is tracked by the local wallet (e.g. because the node is subscribed to that DataLayer store) — stores the attacker-supplied URLs as a trusted mirror server record with no URL validation: [2](#0-1) 

The DataLayer service periodically converts these wallet-tracked mirrors directly into subscription server URLs: [3](#0-2) 

Those server URLs are later dereferenced by `fetch_and_validate()` → `insert_from_delta_file()` → `download_file()` → `http_download()`, which performs an `aiohttp` GET request straight to `server_info.url` with no scheme/host allow-list or private-network CIDR exclusion: [4](#0-3) [5](#0-4) 

The module's own documentation acknowledges mirror/plugin URLs are external, untrusted inputs, but only speaks to validating downloaded *content* against the wallet-advertised root — not to restricting *where* requests are sent: [6](#0-5) 

### Impact Explanation
An attacker with no special privileges (just the ability to broadcast a low-value spend bundle) can cause every full node/DataLayer client that tracks a given store to issue attacker-chosen outbound HTTP requests, including to internal-only addresses (cloud metadata endpoints, localhost services, internal RPC ports, etc.). This enables internal network reconnaissance/SSRF against any node operator running the DataLayer service and subscribing to (or owning) the targeted store — matching the CWE-918 classification and severity band of the referenced advisory (Medium, network-reachable, low privilege, no user interaction beyond normal chain processing).

### Likelihood Explanation
Likelihood is high for operators who run the DataLayer service and subscribe to third-party stores (a normal, documented usage pattern): the malicious mirror coin only needs to be broadcast and confirmed once, after which every tracking node's periodic sync loop (`periodically_manage_data()` → `update_subscription()` → `fetch_and_validate()`) will automatically issue the SSRF request without any operator action.

### Recommendation
Validate mirror/subscription URLs before storing and before dereferencing them in `download_file()`/`http_download()`: reject non-HTTP(S) schemes, resolve hostnames and reject private/loopback/link-local/metadata CIDR ranges (RFC1918, 127.0.0.0/8, 169.254.0.0/16, etc.), and re-validate on each fetch (not just at insert time) since DNS can change between validation and request. This mirrors the fix applied upstream in Gogs 0.12.5 (prohibiting internal CIDRs as migration targets).

### Proof of Concept
1. Attacker crafts and broadcasts a spend bundle that creates a coin with `puzzle_hash == create_mirror_puzzle().get_tree_hash()`, memo `[victim_launcher_id, b"http://169.254.169.254/latest/meta-data/"]` (see puzzle at `chia/wallet/db_wallet/db_wallet_puzzles.py:90-109`, mirrored by the legitimate flow in `chia/data_layer/data_layer_wallet.py:687-703`).
2. Once confirmed, any node tracking `victim_launcher_id` records this via `DataLayerWallet.coin_added()` (`chia/data_layer/data_layer_wallet.py:775-799`) into `dl_wallet_store.add_mirror()`.
3. `DataLayer.update_subscriptions_from_wallet()` (`chia/data_layer/data_layer.py:979-985`) turns the malicious URL into an active subscription server.
4. On the next sync cycle, `fetch_and_validate()`/`download_file()`/`http_download()` (`chia/data_layer/data_layer.py:642-666`, `chia/data_layer/download_data.py:298-324`) issues an outbound GET to the attacker-chosen internal URL from the victim node's process.

```python
                    Mirror(
                        coin.name(),
                        launcher_id,
                        uint64(coin.amount),
                        Mirror.decode_urls(urls),
                        ours,
                        height,
                    )
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
