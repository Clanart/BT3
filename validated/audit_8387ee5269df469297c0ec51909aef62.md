### Title
`ReceivedOutput::read` accepts an attacker-controlled `offset` field that is never re-bound to the output's `script_pubkey`, bypassing the ownership/derivation check the `Scanner` enforces - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The BlogoText bug is an access-control bypass where a single attacker-controlled field (the e-mail field) escapes the validation applied to every other field, letting the requester bypass intended restrictions. The Serai analog is the `offset` field of `ReceivedOutput`. When a `ReceivedOutput` is produced by `Scanner::scan_transaction`, the offset is looked up in `self.scripts`, a `HashMap<ScriptBuf, Scalar>` that cryptographically binds each offset to the exact P2TR script it derives (`key + offset*G`) [1](#0-0) . But `ReceivedOutput::read` deserializes `offset`, `output`, and `outpoint` directly from untrusted bytes with no re-check that `p2tr_script_buf(scanner_key + offset*G) == output.script_pubkey` [2](#0-1) . The field that encodes *which key owns the funds* is taken on faith, exactly like the unchecked e-mail field.

### Finding Description
- `Scanner::register_offset` documents that offsets must be "securely generated" because an arbitrary offset "may introduce a script path into the output, allowing the output to be spent by satisfaction of an arbitrary script (not by the signature of the key)" [3](#0-2) . `register_offset` enforces this by only registering scripts it computed itself [4](#0-3) .
- `ReceivedOutput::read` performs none of that binding: it reads a `Secp256k1` scalar, a `TxOut`, and an `OutPoint` and returns them as a spendable output [2](#0-1) .
- Downstream, `Output::key` reconstructs the owning key as `scriptPubKey_key - offset*G` [5](#0-4) , so a forged offset re-attributes the output to an arbitrary base key. And `SignableTransaction`/FROST signing consumes `offset` to tweak `ThresholdKeys` (via `tweak_keys`/`keys.offset` [6](#0-5) ), so a mismatched offset causes the multisig to sign with the wrong key.

### Impact Explanation
Two concrete impacts are reachable by an unprivileged party feeding crafted bytes to `ReceivedOutput::read`:
1. **Funds reported received that are not spendable**: an output whose `script_pubkey` pays to an arbitrary Taproot key (or a script-path-spendable key) can be paired with an offset claiming it belongs to the Serai multisig key. The scheduler/wallet will treat it as spendable, yet the FROST signature produced for `key + offset*G` cannot satisfy the actual script — the claimed deposit is unspendable, or worse, is spendable by a third party via the script path.
2. **Misattribution of ownership**: `Output::key()` derives `scriptKey - offset*G`, so a forged offset makes any P2TR output appear owned by a chosen multisig key, bypassing the key→script binding that is the scanner's access control.

### Likelihood Explanation
`ReceivedOutput::read` is part of the documented untrusted-byte surface and is consumed via `Output::read` in the processor [7](#0-6) . Exploitation requires only control of serialized bytes (e.g., outputs relayed through peer/RPC-fed paths or stored data), no threshold collusion and no leaked keys. The requirement that the output be P2TR is the only sanity check downstream [8](#0-7) , which any attacker-crafted `TxOut` trivially satisfies.

### Recommendation
Either make `ReceivedOutput` unforgable-by-construction (deserialize only inside a `Scanner` context that re-derives and verifies `self.scripts[script_pubkey] == offset`), or add a `verify(key)` method that recomputes `p2tr_script_buf(key + offset*G)` and compares it to `output.script_pubkey`, invoked by `read` callers before the output is used for signing or credited. Document that a raw `ReceivedOutput::read` result is unauthenticated.

### Proof of Concept
```rust
// Attacker-controlled bytes: arbitrary scalar `offset`, a TxOut paying to an
// attacker-chosen P2TR key, and any outpoint.
let forged = ReceivedOutput {
    offset: arbitrary_scalar,        // NOT in scanner.scripts for this script
    output: TxOut { value: ..., script_pubkey: attacker_p2tr_script },
    outpoint: some_outpoint,
}.serialize();

// Vulnerable path: read() accepts the binding without re-derivation.
let ro = ReceivedOutput::read(&mut forged.as_slice()).unwrap();
// ro.offset() is now trusted downstream: Output::key() returns
//   scriptKey - offset*G  -> an arbitrary "owning" key, and
// SignableTransaction tweaks ThresholdKeys by a wrong offset,
// producing signatures that cannot spend the output.
```
Contrast with the legitimate path: `scan_transaction` only yields outputs whose `script_pubkey` was looked up in `self.scripts`, guaranteeing `p2tr_script_buf(self.key + offset*G) == output.script_pubkey` [9](#0-8) .

Caveat: I could not trace a specific production call site where fully attacker-controlled bytes reach `ReceivedOutput::read` end-to-end within my search budget; the finding stands on `read` being an exposed deserialization entry point (per the in-scope list) that silently accepts a field the honest construction path cryptographically binds.

  // Adds the unspendable script path per
  // https://github.com/bitcoin/bips/blob/master/bip-0341.mediawiki#cite_note-23
  let keys = {
    use k256::elliptic_curve::{
      bigint::{Encoding, U256},
      ops::Reduce,
      group::GroupEncoding,
    };
    let tweak_hash = TapTweakHash::hash(&keys.group_key().to_bytes().as_slice()[1 ..]);
    /*
      https://github.com/bitcoin/bips/blob/master/bip-0340.mediawiki#cite_ref-13-0 states how the
      bias is negligible. This reduction shouldn't ever occur, yet if it did, the script path
      would be unusable due to a check the script path hash is less than the order. That doesn't
      impact us as we don't want the script path to be usable.
    */
    keys.offset(<Secp256k1 as Ciphersuite>::F::reduce(U256::from_be_bytes(
      *tweak_hash.to_raw_hash().as_ref(),
    )))

  keys
    .scale(<_ as subtle::ConditionallySelectable>::conditional_select(
      &Scalar::ONE,
      &-Scalar::ONE,
      needs_negation,
    ))
    .expect("scaling keys by 1 or -1 yet interpreted as 0?")
}

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
