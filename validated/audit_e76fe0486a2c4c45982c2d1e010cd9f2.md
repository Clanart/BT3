### Title
Reward tokens permanently lost when `WomUp` has zero stakers during an active reward period - ([File: wombat/WomUp.sol])

### Summary
`WomUp.sol` implements a Synthetix-style, time-based reward-streaming mechanism (`rewardRate`, `periodFinish`, `rewardPerTokenStored`) identical in structure to the MultiRewards pattern described in the report. When `_totalSupply` is zero, `rewardPerToken()` skips accrual and simply advances `lastUpdateTime`, causing any reward that "streamed" during the zero-staker window to be permanently and unrecoverably lost.

### Finding Description
`rewardPerToken()` short-circuits to `rewardPerTokenStored` whenever `totalSupply() == 0`: [1](#0-0) 

The `updateReward` modifier unconditionally advances `lastUpdateTime` to `lastTimeRewardApplicable()` regardless of whether `totalSupply()` was zero during the elapsed interval: [2](#0-1) 

`stake()` invokes this modifier *before* `_totalSupply` is incremented, so if a user is the first staker after a period of inactivity, all the reward emission that "occurred" between `lastUpdateTime` and the current call is discarded — `rewardPerTokenStored` is never updated for that interval, and `lastUpdateTime` jumps forward, meaning no future accounting can recapture it: [3](#0-2) 

Unlike `BaseRewardPool._provisionReward`, which explicitly queues rewards (`rewardInfo.queuedRewards`) when `totalStaked() == 0` and re-applies them once someone stakes again, `WomUp` has no equivalent queuing/rollover mechanism: [4](#0-3) 

Additionally, `rescueReward()` is only callable while `rewardRate == 0`, so once `initializeRewards()` has been called, the owner cannot reclaim any of the lost reward tokens for the remainder of that stream: [5](#0-4) [6](#0-5) 

### Impact Explanation
Reward tokens (MGP) that were emitted during any window in which `_totalSupply == 0` — whether at the very start of the `duration` before the first staker arrives, or after every staker has fully withdrawn mid-stream — become permanently unclaimable by any user and unrecoverable by governance, since `rescueReward()` is blocked once `rewardRate > 0`. This is a permanent freezing/loss of protocol yield tokens.

### Likelihood Explanation
This requires no attacker and no privileged misbehavior: it occurs naturally any time `initializeRewards()` is called before the first staker deposits, or any time all stakers withdraw before the 7-day `duration` elapses (a normal, unprivileged user action via `withdraw()`). Given `duration` is fixed at 7 days, even a short delay in the first stake, or a brief period where all users exit, results in real, permanent loss.

### Recommendation
Adopt the same `queuedRewards` fallback pattern used in `BaseRewardPool._provisionReward` / `DelegateVoteRewardPool._queueNewRewardsWithoutTransfer`: when `totalSupply() == 0` at reward-provisioning or reward-update time, hold the corresponding reward in a queued balance instead of letting it lapse via `lastUpdateTime`, and apply it once a staker exists (or allow governance to reclaim genuinely orphaned rewards via a dedicated sweep function that isn't blocked by `rewardRate > 0`).

### Proof of Concept
1. Owner deploys `WomUp`, transfers MGP into it, and calls `initializeRewards()` while `_totalSupply == 0`. This sets `rewardRate = balance/7 days`, `lastUpdateTime = now`, `periodFinish = now + 7 days`.
2. No user stakes for 3 days.
3. On day 3, `user1` calls `stake()`. The `updateReward` modifier runs first: since `totalSupply() == 0`, `rewardPerToken()` returns the unchanged `rewardPerTokenStored`, and `lastUpdateTime` is advanced to day 3 — the 3 days' worth of `rewardRate` emission is discarded.
4. `_totalSupply` is then increased by the stake amount.
5. From day 3 to day 7, rewards accrue and are correctly earned by `user1`, but the reward corresponding to days 0–3 is permanently lost — it was never added to `rewardPerTokenStored`, and `rescueReward()` reverts with `AlreadyStarted` because `rewardRate > 0`, so the owner cannot recover it either.

        if (totalSupply() == 0) {
            return rewardPerTokenStored;
        }

    function initializeRewards() external onlyOwner returns (bool) {
        if(rewardRate > 0) revert MustZero();

        uint256 rewardsAvailable = IERC20(mgp).balanceOf(address(this));
        if(rewardsAvailable == 0) revert MustNotZero();

        rewardRate = rewardsAvailable / (duration);

        lastUpdateTime = block.timestamp;
        periodFinish = block.timestamp + (duration);

        emit RewardAdded(rewardsAvailable);

        return true;
    }
