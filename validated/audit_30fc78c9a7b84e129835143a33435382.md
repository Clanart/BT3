### Title
Attacker-controlled `WWW-Authenticate` header from a git remote spoofs GitHub Enterprise sign-in prompt, phishing the user's real GitHub credentials - (File: app/src/lib/trampoline/trampoline-credential-helper.ts)

### Summary
The Substrate report is about a peer secret being trusted from an unauthenticated/uncontrolled local source (off-chain storage) and used without integrity checks. The closest reachable Desktop analog is not "secrets on disk in plaintext" (Desktop already stores account tokens via the OS keychain through `TokenStore`/`keytar` [1](#0-0) , and that class of bug requires local file-system access, which is out of scope per this task's Valid Impact rules). Instead, the same "attacker-controlled input is trusted to determine how a secret should be handled" pattern shows up in the git credential-helper trampoline: it derives trust ("is this a GitHub host?") directly from an HTTP response header (`WWW-Authenticate`) sent by the remote git server itself, and uses that classification to launch Desktop's native GitHub Enterprise sign-in flow.

### Finding Description
When Git needs credentials for a remote, it forwards any `WWW-Authenticate` header from the server's HTTP response to Desktop's credential helper as `wwwauth[]` fields. `getEndpointKind` in `app/src/lib/trampoline/trampoline-credential-helper.ts` uses the *content* of that attacker/server-supplied header as a trust signal: [2](#0-1) 

If the header contains `realm="GitHub"`, the endpoint is classified as `'enterprise'` — with no verification that the host is actually GitHub Enterprise (no certificate check, no `/meta` probe like the fallback `isGitHubHost` path below it, no allow-list). This classification then flows into `getCredential`: [3](#0-2) 

Because the endpoint is not `'generic'` and no existing account matches it, Desktop calls `ui.promptForGitHubSignIn(endpoint)`, which — since the hostname isn't `github.com` — starts the real "Sign in to GitHub Enterprise" flow pointed at the attacker's own origin: [4](#0-3) 

This reuses the legitimate `SignInStore` enterprise flow (`beginEnterpriseSignIn` / `setSignInEndpoint`) which will hit whatever URL the attacker's git server presented, and if the user completes authentication, any credentials/OAuth code exchange happen against the attacker-controlled endpoint.

### Impact Explanation
An attacker who controls a git remote/proxy that the user adds or fetches from (e.g., a malicious `http(s)://` remote or a machine-in-the-middle proxy intercepting a `git fetch`/`clone`) can respond with a `401` and a crafted `WWW-Authenticate: Basic realm="GitHub"` header. Desktop's credential trampoline will then pop up its native, trusted-looking "Sign in to GitHub Enterprise" dialog, pre-seeded with the attacker's own host as the enterprise endpoint. A user who is used to seeing this legitimate Desktop dialog when Desktop asks them to authenticate to an unfamiliar host may proceed to enter GitHub credentials or complete an OAuth-style login against the attacker's server, resulting in credential/token theft. This matches the requested impact class: "unauthorized OAuth or account binding" / "credential/token exfiltration" triggered purely by a git remote/proxy response, no local access required.

### Likelihood Explanation
Likelihood is moderate. The exploit primitive (spoofing a `WWW-Authenticate` header) is trivial for any attacker who controls the remote server or can intercept the HTTP response for a git operation over plain HTTP or a compromised/mismatched HTTPS endpoint (e.g. self-signed cert accepted, or corporate MITM proxy scenario, or simply a `.git` server the user was told to add). The main mitigating factor is that the user must still complete the sign-in dialog (enter credentials or approve OAuth) — this is a phishing-style requirement, not silent, and the `credentialHelperUrl`/origin is shown in the sign-in UI (`isCredentialHelperSignIn: true, credentialHelperUrl: endpoint`), which a careful user could notice as suspicious. No code was found in `getEndpointKind` that cross-checks the `wwwauth[]` claim against `isGitHubHost` or does any TLS/host validation before granting `'enterprise'` trust, so the guard that exists lower in the same function (`isGitHubHost(endpoint)`, an actual network probe) is bypassed entirely by the header-based happy path above it.

### Recommendation
- Do not trust the `realm="GitHub"` string in `WWW-Authenticate` as sufficient evidence of a GitHub Enterprise host. At minimum, corroborate it with the same `isGitHubHost(endpoint)` probe (or GHES `/meta`/version-header check) already used as the fallback later in `getEndpointKind`.
- When `promptForGitHubSignIn` is invoked for a non-`github.com`, non-previously-known endpoint, surface a stronger warning in the sign-in dialog indicating this host was not previously trusted and was inferred from the remote's own response, rather than presenting the standard GHE sign-in UI indistinguishably from a legitimate one.
- Consider gating the credential-helper's enterprise auto-prompt behind an explicit user confirmation ("This repository is asking you to sign in to a new host: `<origin>` — is this correct?") before opening the sign-in flow.

### Proof of Concept
1. Attacker sets up an HTTP(S) git server (or a MITM proxy) at `https://evil.example.com/repo.git`.
2. User adds this as a remote in Desktop (e.g., cloning a link they were given, or Desktop fetching from a remote already present in a cloned repository) and performs a fetch/pull.
3. When Git requests credentials, the attacker's server responds `401 Unauthorized` with header `WWW-Authenticate: Basic realm="GitHub"`.
4. Git forwards this as a `wwwauth[]=Basic realm="GitHub"` field to Desktop's credential helper.
5. `getEndpointKind` (`app/src/lib/trampoline/trampoline-credential-helper.ts:157-165`) matches `realm="GitHub"` and returns `'enterprise'`.
6. `getCredential` finds no existing account for `evil.example.com` and calls `ui.promptForGitHubSignIn('https://evil.example.com')`.
7. `promptForGitHubSignIn` (`trampoline-ui-helper.ts:80-104`) starts the "Sign in to GitHub Enterprise" flow targeting `https://evil.example.com` and shows the sign-in popup.
8. If the user proceeds with sign-in, their credentials/OAuth flow are directed at the attacker-controlled `evil.example.com`.

Note: I was unable to fully verify from the indexed code how `SignInStep.Authentication`'s `isCredentialHelperSignIn`/`credentialHelperUrl` are rendered in the actual `SignIn` popup UI component (exact wording/URL visibility shown to the user), since that renderer component wasn't returned by search — a Devin session with full repo access would be needed to confirm exactly how prominently the target host is surfaced to the user in this dialog.

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
