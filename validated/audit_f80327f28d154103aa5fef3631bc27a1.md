### Title
Unbounded in-memory body read in New Relic RPC instrumentation bypasses `MaxRequestContentLength`, enabling public-RPC memory-exhaustion DoS - (File: networks/rpc/http_newrelic.go)

### Summary
When New Relic instrumentation is enabled (`NEWRELIC_APP_NAME`/`NEWRELIC_LICENSE` env vars set — a common production observability configuration, not a privileged/operator-secret setting from the perspective of a public RPC caller), every HTTP JSON-RPC request passes through `newNewRelicHTTPHandler`, which calls `getRPCRequests(r)` to pre-parse the request for logging. This function reads the full request body via `io.ReadAll(r.Body)` with no size limit, before the request is handed to the downstream handler that actually applies `common.MaxRequestContentLength` via `io.LimitReader`/`MaxRequestBodySize`.

### Finding Description
`getRPCRequests` at `networks/rpc/http_newrelic.go:141-159` does:
```go
reqBody, err := io.ReadAll(r.Body)
```
This is functionally analogous to the wisp bug: the "quota" (here, `common.MaxRequestContentLength`, default 512KB set in `common/variables.go:21`) is only enforced on the path that ultimately constructs the JSON-RPC codec (`newHTTPServerConn` in `networks/rpc/http.go:249-253`, or the `fasthttp.Server.MaxRequestBodySize` field in `networks/rpc/http.go:301-345`). The New Relic wrapper's pre-read of the body happens *before* that enforcement point is reached, and imposes no cap of its own — every byte the client sends is buffered into a Go `[]byte` slice regardless of the configured limit. Just as the wisp parser only decremented its quota on the "boundary found" branch and let intermediate chunks through “free,” this code path lets an entire oversized HTTP body through free of the size check that is supposed to gate all requests.

### Impact Explanation
An unauthenticated caller to any public HTTP JSON-RPC endpoint (`eth_*`, `kaia_*`, etc.) on a node that has New Relic monitoring enabled can send an arbitrarily large POST body. `io.ReadAll` will allocate memory proportional to the full body size before any RPC-layer size validation occurs, and this happens on every single request — allowing repeated/concurrent requests to exhaust server memory and crash or degrade the node (denial of service), consistent with CWE-770 / Allocation of Resources Without Limits.

### Likelihood Explanation
Likelihood is Medium: exploitation requires the node operator to have New Relic instrumentation enabled (an optional but common production deployment choice, controlled by environment variables, not requiring any privileged access from the attacker's side). Once enabled, the vulnerability is trivially reachable by any anonymous RPC client with a single crafted large HTTP request, with no authentication or special conditions needed.

### Recommendation
Wrap `r.Body` in `io.LimitReader(r.Body, int64(common.MaxRequestContentLength))` (or an equivalent bound) inside `getRPCRequests` before calling `io.ReadAll`, mirroring the limit already applied in `newHTTPServerConn` and the fasthttp `MaxRequestBodySize` setting, and reject/short-circuit logging for oversized bodies rather than buffering them in full.

### Proof of Concept
1. Start a `kaia` node with HTTP RPC enabled and New Relic instrumentation active (`NEWRELIC_APP_NAME`/`NEWRELIC_LICENSE` set).
2. Send a JSON-RPC POST request whose body is many times larger than `common.MaxRequestContentLength` (default 512KB), e.g. tens or hundreds of MB of padding in a JSON string field.
3. Observe that `newNewRelicHTTPHandler` → `getRPCRequests` reads the entire body into memory via `io.ReadAll` before any size limit is applied, unlike the codec path which would have rejected/truncated it via `common.MaxRequestContentLength`.
4. Repeat concurrently from multiple connections to exhaust server memory, causing degraded service or OOM termination — a resource-exhaustion DoS reachable by any public, unauthenticated RPC caller.

// newNewRelicHTTPHandler enables NewRelic web transaction monitor.
// It also prints error logs when RPC returns contains error messages.
func newNewRelicHTTPHandler(nrApp *newrelic.Application, handler http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if err := recover(); err != nil {
				logger.ErrorWithStack("NewRelic http handler panic", "err", err)
			}
		}()

		reqMethod := ""

		// parse RPC requests
		reqs, isBatch, err := getRPCRequests(r)
		if err != nil || len(reqs) < 1 {
			// The error will be handled in `handler.ServeHTTP()` and printed with `printRPCErrorLog()`
			logger.Debug("failed to parse RPC request", "err", err, "len(reqs)", len(reqs))
		} else {
			reqMethod = reqs[0].Method
			if isBatch {
				reqMethod += "_batch"
			}
		}

		// new relic transaction name contains the first API method of the request
		txn := nrApp.StartTransaction(r.Method + " " + r.URL.String() + " " + reqMethod)
		defer txn.End()

		w = txn.SetWebResponse(w)
		txn.SetWebRequestHTTP(r)
		r = newrelic.RequestWithTransactionContext(r, txn)

		// duplicate writer
		dupW := &dupWriter{
			ResponseWriter: w,
			body:           bytes.NewBufferString(""),
		}

		// serve HTTP
		handler.ServeHTTP(dupW, r)

// getRPCRequests copies a http request body data and parses RPC requests from the data.
// It returns a slice of RPC request, an indication if these requests are in batch, and an error.
// Ethereum returns []*jsonrpcMessage, which replaces []rpcRequest
func getRPCRequests(r *http.Request) ([]*jsonrpcMessage, bool, error) {
	reqBody, err := io.ReadAll(r.Body)
	if err != nil {
		logger.Error("cannot read a request body", "err", err)
		return nil, false, err
	}

	r.Body = io.NopCloser(bytes.NewReader(reqBody))
	conn := &httpServerConn{Reader: io.NopCloser(bytes.NewReader(reqBody)), Writer: bytes.NewBufferString(""), r: r}

	codec := NewCodec(conn)

	defer codec.close()

	return codec.readBatch()
}
