### Title
`_diff_pathspec` misclassifies in-repo filenames beginning with `..` as escaping the repo, causing silent security-review bypass - (File: `plugins/security-guidance/hooks/gitutil.py`)

### Summary
`_diff_pathspec` filters touched paths to a repo-scoped pathspec by checking `r.startswith("..")` on the `os.path.relpath` result, but this is a naive string-prefix check rather than a proper path-component check. Any legitimately in-repo file or directory whose name begins with the two characters `..` (e.g. `..cfg/secrets.py`, `...utils.py`) produces a relpath that also starts with `..` and is wrongly dropped as "outside the repo," even though it never leaves `cwd`.

### Finding Description
`_diff_pathspec` is meant to convert absolute touched-file paths into a `git diff` pathspec restricted to the current repo, dropping anything genuinely outside it: [1](#0-0) 

The containment check is:
```python
r = os.path.relpath(os.path.realpath(p), cwd_abs)
...
if r.startswith(".."):
    continue
```
`os.path.relpath` produces `".." + sep + ...` (or exactly `".."`) only when `p` is a genuine ancestor/sibling outside `cwd`. However, a file that is inside `cwd` but whose top-level name literally begins with two dots — e.g. `..hidden.py`, `..config/handler.py`, `...notes.md` — also yields a relpath string starting with the substring `".."` (`"..hidden.py".startswith("..")` is `True`) despite being fully inside the repo. The check conflates "starts with the parent-dir token" with "starts with the two-character substring `..`," so such filenames are incorrectly treated as escaping the repo and are silently excluded from `rel`.

This path is reachable from the normal touched-file flow: `compute_v2_review_set` in `plugins/security-guidance/hooks/diffstate.py` builds `review_paths` from `git status`-derived repo-relative filenames joined onto the repo root, and `get_git_diff` passes those through `_diff_pathspec`: [2](#0-1) 

If the affected file is the only touched path, `pathspec` becomes `[]`, and the explicit fallback at line 407-412 treats a non-empty `paths` with an empty pathspec as "no paths are inside this repo," returning `""` for the diff — which the caller then treats as nothing to review (comment: "flows to skip(6)"), silently skipping the security review of that file entirely. If it's one of several touched files, that file is simply dropped from the diff scope while others are still reviewed, i.e., a partial review bypass. Neither `get_git_diff` nor the pathspec construction has any check that would catch this class of misclassification — the whole containment guarantee relies solely on the flawed `startswith("..")` test.

### Impact Explanation
This is a logic-level bypass of the security-guidance review guard: repository content controlled by any contributor (a file/directory name is not a privileged trust boundary) can cause code changes in that path to be excluded from Claude Code's own security review diff, up to and including causing the review to be skipped outright when it's the only touched path in the turn. This matches "Logic-level service disruption caused by bypassing a required guard" — the git path-scoping invariant ("must never escape the intended repo target," which implicitly requires accurately classifying in-repo vs. out-of-repo) is broken, letting attacker-influenced file naming steer which edits get reviewed.

### Likelihood Explanation
Trivial precondition and fully repeatable: any repo can contain (or Claude can be made to create, via ordinary file edits) a file/directory whose name starts with `..` — this is valid on POSIX filesystems and in git. No symlink tricks, unicode, or special worktree layout are even required, though those could be combined for further obfuscation. Every time such a path is the (or one of the) touched paths in a turn, the misclassification triggers deterministically.

### Recommendation
Fix the containment check in `_diff_pathspec` to test path components, not a raw string prefix, e.g.:
```python
if r == os.pardir or r.startswith(os.pardir + os.sep):
    continue
```
This correctly rejects true parent-directory escapes (`".."`, `"../x"`) while keeping in-repo files/directories whose names merely begin with dots (`"..cfg/secrets.py"`) in scope. Add a regression test asserting a file literally named with a leading `..` inside the repo is retained in the pathspec.

### Proof of Concept
Unit test against `_diff_pathspec` in `plugins/security-guidance/hooks/gitutil.py`:
```python
import os, tempfile
from gitutil import _diff_pathspec

def test_diff_pathspec_keeps_dotdot_prefixed_filename(tmp_path):
    repo = tmp_path / "repo"
    (repo / "..cfg").mkdir(parents=True)
    target = repo / "..cfg" / "secrets.py"
    target.write_text("x = 1\n")

    pathspec = _diff_pathspec(str(repo), [str(target)])

    # Expected: file is inside the repo, so it must remain in scope.
    assert pathspec == ["--", os.path.join("..cfg", "secrets.py")]
    # Actual (bug): pathspec == [] because relpath("..cfg/secrets.py")
    # starts with ".." and is dropped, even though the file never left `repo`.
```
Expected assertion failure demonstrates the bug: `pathspec` comes back `[]` instead of including the in-repo file, and via `get_git_diff` this collapses to an empty diff (`""`), silencing the security review for that file.

```python
def _diff_pathspec(cwd, paths):
    """Convert absolute touched-paths to repo-relative pathspec args for
    git diff. Paths outside cwd (e.g. ~/.claude/…) are dropped. Returns the
    list to splice after `--`, or [] for an unrestricted diff. realpath both
    sides so the macOS /var ↔ /private/var symlink doesn't make in-repo
    paths look external."""
    if not paths:
        return []
    cwd_abs = os.path.realpath(cwd)
    rel = []
    for p in paths:
        try:
            r = os.path.relpath(os.path.realpath(p), cwd_abs)
        except ValueError:
            continue
        if r.startswith(".."):
            continue
        rel.append(r)
    return ["--"] + rel if rel else []
```
