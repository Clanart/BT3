## Finding

### Title
Deep-link "Open in Desktop" flow auto-checks-out an attacker-controlled PR fork branch without confirmation - ([File: app/src/ui/dispatcher/dispatcher.ts])

### Summary
The external report's core defect is that a once-approved value (a signed listing) keeps being trusted after the underlying state changes, with no way to revoke it and no confirmation step before it is consumed. The closest analog in GitHub Desktop is the `x-github-client://openrepo/...?pr=<n>` deep-link handler: once a repository is known to Desktop, any externally supplied link can silently make Desktop fetch a pull request and check out the **PR author's own fork branch** — data that is fully attacker controlled — into the user's working copy, with no re-confirmation dialog gating the action.

### Finding Description
`parseAppURL` accepts a `pr` query parameter from any external URL and only validates that it is numeric [1](#0-0) . `dispatchURLAction` routes `open-repository-from-url` actions straight to `openRepositoryFromUrl` [2](#0-1) , which — when a `pr` is present — calls `openPullRequestFromUrl` [3](#0-2) .

`openPullRequestFromUrl` fetches the PR object from the API by number, locates (or clones) the base repository, and then unconditionally calls `_checkoutPullRequest` using `pullRequest.head.repo.clone_url` and `pullRequest.head.ref` taken directly from the API response: [4](#0-3) . The `head.repo` of a pull request is the PR author's fork — an object fully controlled by whoever opened the PR, i.e., an unprivileged GitHub user with no write access to the base repository. Because the entry point is a deep link with only numeric validation on `pr`, an attacker can:
1. Open a pull request (from their own fork) against any public repository that the victim has open in Desktop.
2. Send the victim a link such as `x-github-client://openrepo/https://github.com/<base-owner>/<base-repo>?pr=<attacker-pr-number>`.
3. When clicked, Desktop resolves the existing local repository via `doesRepositoryMatchUrl` (matching only on the repo's `htmlURL`, not on any per-invocation secret/nonce) [5](#0-4) , fetches the attacker's PR, and adds/checks out the attacker fork's branch into the victim's working directory without a discrete "are you sure you want to bring in code from `<attacker-fork-url>`?" confirmation gate at this call site.

This mirrors the report's broken invariant: there is no per-action "nonce"/fresh confirmation tying the trust decision (the user previously added/cloned the base repository) to the specific action being performed now (pulling in an arbitrary, attacker-named fork+ref). Once the base repository is "trusted" (already added to Desktop), that trust is silently reused indefinitely for any later PR number an attacker chooses, exactly as the original report's signature remained valid indefinitely absent a nonce/revocation mechanism.

### Impact Explanation
If exploited, an attacker with no write access to the target repository can cause a victim's Desktop working directory to be silently switched to, or to include, the attacker's fork content and branch. Depending on what the user does next (commits, merges, or simply runs local tooling/build scripts against the now-attacker-influenced working tree), this can lead to silent corruption of what the user later commits/pushes, and — if the checked-out content is then built or has hooks/tooling run against it — potential local code execution. This lines up with the "silent corruption of what the user commits or pushes" impact category explicitly called out as valid.

### Likelihood Explanation
Likelihood is medium: it requires (a) the victim to have the base repository already present in Desktop, and (b) the victim to click a crafted deep link (a normal, low-friction social step already used for legitimate "Open in Desktop" buttons across GitHub's UI, so it doesn't require unnatural steps). The attacker-controlled input (a PR they opened themselves) requires no elevated privileges on the base repository.

### Recommendation
Before invoking `_checkoutPullRequest` from a deep-link-triggered flow, present an explicit confirmation dialog identifying the fork URL/owner and branch that is about to be fetched and checked out, and require the user to affirmatively approve it — effectively re-validating the "signature" (i.e., binding the trust decision to this specific fork+ref) instead of silently reusing the trust already placed in the base repository. Additionally, consider constraining automatic checkout to PRs whose head repository matches an account the user has previously interacted with, or to same-repository branches, unless the user opts in.

### Proof of Concept
Not independently executed; based on static code tracing of `parseAppURL` → `dispatchURLAction` → `openRepositoryFromUrl` → `openPullRequestFromUrl` → `_checkoutPullRequest`. I was not able to locate/verify the exact implementation of `_checkoutPullRequest` (whether it shows any confirmation UI) within the indexed portion of the codebase, so this aspect is unverified — a Devin session with full repository access should inspect `_checkoutPullRequest` in `app/src/lib/stores/app-store.ts` and the checkout-pull-request UI flow to confirm whether any confirmation gate currently exists at that specific call path before treating this as fully proven.     repo: Repository | CloningRepository,
    url: string
  ): repo is RepositoryWithGitHubRepository {

      const originRepoUrl = repo.gitHubRepository.htmlURL
      const upstreamRepoUrl = repo.gitHubRepository.parent?.htmlURL ?? null

      if (originRepoUrl !== null && urlsMatch(originRepoUrl, url)) {
        return true
      }

      if (upstreamRepoUrl !== null && urlsMatch(upstreamRepoUrl, url)) {
        return true
      }
    }

    return false
  }

  private async openRepositoryFromUrl(action: IOpenRepositoryFromURLAction) {
    const { url, pr, branch, filepath } = action

    let repository: Repository | null

    if (pr !== null) {
      repository = await this.openPullRequestFromUrl(url, pr)
    } else if (branch !== null) {
      repository = await this.openBranchNameFromUrl(url, branch)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      return
    }

    if (filepath !== null) {
      if (isAbsolute(filepath)) {
        log.error(`Refusing to open absolute path: ${filepath}`)
        return
      }

      const resolved = await resolveWithin(repository.path, filepath)

      if (resolved !== null) {
        shell.showItemInFolder(resolved)
      } else {
        log.error(
          `Prevented attempt to open path outside of the repository root: ${filepath}`
        )
      }
    }
  }

  private async openBranchNameFromUrl(
    url: string,
    branchName: string
  ): Promise<Repository | null> {
    const repository = await this.openOrCloneRepository(url)

    if (repository === null) {
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    // if the repo has a remote, fetch before switching branches to ensure
    // the checkout will be successful. This operation could be a no-op.
    await this.appStore._fetch(repository, FetchType.UserInitiatedTask)

    await this.checkoutLocalBranch(repository, branchName)

    return repository
  }

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }
    if (!isRepositoryWithGitHubRepository(repository)) {
      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    if (pullRequest.head.repo === null) {
      return null
    }

    await this.appStore._checkoutPullRequest(
      repository,
      pullRequest.number,
      pullRequest.head.repo.owner.login,
      pullRequest.head.repo.clone_url,
      pullRequest.head.ref
    )

    return repository
  }
