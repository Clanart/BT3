### Title
`ReceivedOutput::read` accepts fabricated outputs with no binding between claimed `TxOut`/value and the spend key offset — untrusted bytes can report unspendable funds as received - (File: `networks/bitcoin/src/wallet/mod.rs`)

### Summary
`ReceivedOutput::read` in `networks/bitcoin/src/wallet/mod.rs` deserializes an `offset` scalar, an arbitrary `TxOut`, and an arbitrary `OutPoint` directly from attacker-controlled bytes, performing zero validation: no check that `output.script_pubkey` is a P2TR script committing to `key + offset·G`, no check that `value` is within `MAX_MONEY` or above dust, and no binding between the claimed `TxOut` and the claimed `OutPoint`. This is the analog of the CurveSpell `minOuts = [0,0]` bug: a value that should be bounded/validated is accepted unconditionally, so an attacker-influenced input causes the system to act on an incorrect economic claim. ### Finding Description
`ReceivedOutput` is the structure through which a "received" Bitcoin output flows into the spend/signing path. Its fields are:

- `offset` — scalar offset added to the multisig key to derive the spend key (`networks/bitcoin/src/wallet/mod.rs:90-97`)
- `output` — the `TxOut` whose `value` and `script_pubkey` are later committed into the Taproot sighash via `Prevouts::All` and used for fee/change/dust accounting in `SignableTransaction` (`networks/bitcoin/src/wallet/send.rs`)
- `outpoint` — the claimed txid/vout

`read` performs only `Secp256k1::read_F`, `TxOut::consensus_decode`, and `OutPoint::consensus_decode`. `consensus_decode` accepts any `u64` amount (no `MAX_MONEY` check) and any `script_pubkey`. Compare with the honest construction path: `Scanner::scan_transaction` only produces a `ReceivedOutput` after matching `output.script_pubkey` against the `scripts` map of registered, key-bound scripts (`networks/bitcoin/src/wallet/mod.rs:199-213`), and `register_offset` guarantees the script equals `p2tr(key + offset·G)` (`networks/bitcoin/src/wallet/mod.rs:180-196`). None of these invariants are re-established on deserialization.

When the output is spent, the Taproot sighash (`Prevouts::All`) commits to the deserialized `TxOut` — including its fabricated `value` — and the signature is produced for the tweaked key `key + offset`. Two distinct failure modes result:

1. **Unspendable funds reported as received**: an attacker supplies `offset`/`script_pubkey` pairs that do not correspond to any registered offset (e.g., `offset = 0` with a P2TR script for the attacker's own key, or an `outpoint` of a real output whose actual `TxOut` differs from the claimed one). The output is reported as a received balance, but the derived spend key cannot produce a valid signature for the real on-chain output, or the committed `Prevouts` amount mismatches consensus, so the signed transaction is invalid — the funds can never actually be moved.
2. **Fabricated amounts**: `value` can be set arbitrarily (up to `u64::MAX`), inflating the reported balance and corrupting fee/change/dust arithmetic downstream (`SignableTransaction::new` computes payments and change against this claimed value).

The processor-side wrapper `Output::read` in `processor/src/networks/bitcoin.rs:145-166` feeds bytes straight into `ReceivedOutput::read`, and `Output::key()` (`processor/src/networks/bitcoin.rs:112-122`) trusts `self.output.offset()` to reconstruct the owning key, so the fabricated offset is consumed as authoritative.

### Impact Explanation
Any consumer that accepts externally supplied serialized `ReceivedOutput`s (relay of scanned-output data between components, restore of outputs from an untrusted source, or any untrusted `read` path) will accept outputs that are not spendable by the threshold key or that claim arbitrary values. Consequences: balances credited for UTXOs that either don't exist, belong to a different key, or carry amounts that make the resulting `Prevouts::All` sighash fail consensus validation — permanently freezing the spend pipeline for that output and corrupting fee/change accounting for the transaction built from it. This satisfies the accepted-impact criterion "funds reported received that are not spendable".

### Likelihood Explanation
Reachable by any unprivileged party able to supply bytes to `ReceivedOutput::read` / `Output::read`. No key material, validator status, or collusion is required — only control of serialized bytes. The honest path (`Scanner`) enforces the script↔offset binding precisely because it is security-critical; the deserialization path silently drops all of it. Exploitation requires only that some component deserialize attacker-influenced `ReceivedOutput`s rather than regenerating them via `Scanner::scan_transaction`.

### Recommendation
In `ReceivedOutput::read`, re-establish the invariants enforced by `Scanner`:

- Reject non-P2TR `script_pubkey`s.
- Reject `output.value` of `0`, below the dust threshold (`Bitcoin::DUST = 10_000`, `processor/src/networks/bitcoin.rs:638`), or above `Amount::MAX_MONEY`.
- Where the owning `key` is available (e.g., by moving validation into a method taking the group key, or validating in `Output::read`/`Output::key()`), verify `p2tr_script_buf(key + GENERATOR * offset) == Some(output.script_pubkey)` — the same check `register_offset` performs — so a claimed output provably belongs to the claimed spend key.
- Document that `ReceivedOutput`s must only originate from `Scanner::scan_transaction`/`scan_block` against confirmed chain data.

### Proof of Concept
```rust
// Attacker-controlled bytes fed to ReceivedOutput::read
use bitcoin::{TxOut, OutPoint, Amount, ScriptBuf, consensus::Encodable};
use k256::Scalar;
use frost::curve::Secp256k1;
use serai_bitcoin::wallet::ReceivedOutput;

// Build a TxOut paying an arbitrary P2TR script the multisig does NOT control
// (e.g., p2tr of attacker_pubkey), with an inflated or dust value,
// and an outpoint of a real (or fake) transaction.
let mut buf = vec![];
// offset = 0
buf.extend(Scalar::ZERO.to_bytes());
// TxOut { value: u64::MAX-ish or dust, script_pubkey: attacker's p2tr }
let fake = TxOut { value: Amount::from_sat(21_000_000_0000_0000 - 1),
                   script_pubkey: attacker_p2tr_script };
fake.consensus_encode(&mut buf).unwrap();
// any outpoint
fake_outpoint.consensus_encode(&mut buf).unwrap();

let out = ReceivedOutput::read(&mut buf.as_slice()).unwrap(); // succeeds: no validation
// out.value() reports the fabricated amount; out.offset() = 0
// SignableTransaction built on `out` commits the fake value via Prevouts::All
// and derives the spend key as key + 0*G -> cannot sign for attacker's script,
// or produces a consensus-invalid sighash -> output reported received is unspendable.
```

```rust
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }
```
