### Title
Fee evasion via malformed/wrong-variant `signer` bytes silently bypasses originator debit in `WeightFeeHandler::on_executed` - (File: `modules/pallets/ismp/src/fee_handler.rs`)

### Summary
`WeightFeeHandler::on_executed` computes a non-zero `fee` from message weight and then tries to resolve the paying `originator` by decoding `msg.signer` into a `Signature` and calling `verify_and_get_sr25519_pubkey`. If decoding fails or the signature is any non-`Sr25519` variant (e.g. `Signature::Evm`), `originator` resolves to `None`, and the code silently skips the debit instead of rejecting the message or erroring out.

### Finding Description
In `on_executed` [1](#0-0) , for each `Message::Request`/`Message::Response` with non-zero `fee`, the originator is computed as:
```
Signature::decode(&mut &msg.signer[..]).ok()
    .and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
```
`Signature::verify_and_get_sr25519_pubkey` unconditionally returns `Err` for any non-`Sr25519` variant [2](#0-1) , and `Signature::decode` will fail on garbage bytes. In either case `originator` is `None`, and the `if let Some(originator_bytes) = originator { ... }` block is simply skipped with no transfer and no error [3](#0-2) . The message itself is still processed and included in the successfully executed batch, i.e. `Pallet::<T>::execute` already ran `handle_incoming_message` and applied the request/response effects before `on_executed` is invoked [4](#0-3) , so there is no re-validation gate blocking messages whose `signer` field is bogus.

The same fallback pattern (documented as intentional) exists in `pallet-messaging-incentives`'s `relayer_for`, whose doc comment explicitly states it returns `None` "if the message has no signer ... or the signature is bad" [5](#0-4) . This confirms the `signer` field is treated project-wide as an optional/best-effort attribution field rather than a mandatory, proof-bound authorization field, and both consumers (`fee_handler.rs`, `messaging-incentives`) choose to silently no-op rather than reject the message when it can't be attributed.

### Impact Explanation
An unprivileged submitter of ISMP requests/responses can supply a `signer` value that fails to decode as `Signature` or decodes to `Signature::Evm`/`Signature::Ed25519`, causing `on_executed` to skip the fee debit for that message while the message's underlying application effects are still fully executed. This evades the protocol's weight-based fee (meant to fund the treasury and deter spam per the module's own design documentation), but it does not let the attacker move, mint, or redirect any other party's bridged assets, escrow, or rewards — the only broken invariant is that the treasury does not receive the fee it was owed for that message. This is a fee-accounting/revenue-loss issue for the protocol treasury, not an unauthorized withdrawal or misdirection of user funds.

### Likelihood Explanation
Trivially reproducible by any unprivileged relayer/caller who controls the `signer` bytes of a submitted `Message::Request`/`Message::Response` — no special privilege, race condition, or infrastructure compromise is required.

### Recommendation
Treat `signer`-attribution failure as a hard error rather than a silent skip when `fee` is non-zero: reject the message (or reject the whole `execute` batch) if `Signature::decode`/`verify_and_get_sr25519_pubkey` fails, or otherwise fall back to a deterministic account (e.g. the submitting extrinsic's `origin`) so the fee is always collected from a well-defined payer.

### Proof of Concept
1. Construct a `MessageWithWeight` whose `message` is `Message::Request(msg)` with `msg.signer` set to the SCALE encoding of `Signature::Evm { address: vec![...], signature: vec![0u8;65] }` (or arbitrary garbage bytes that fail `Decode`).
2. Ensure `W::weight_to_fee(&message.weight)` is non-zero (any realistic processed request weight).
3. Call `WeightFeeHandler::on_executed(vec![message], events)`.
4. Observe: `Signature::decode` either fails, or succeeds but `verify_and_get_sr25519_pubkey` returns `Err` (since the variant isn't `Sr25519`) [2](#0-1) ; `originator` is `None`, the transfer block is skipped [3](#0-2) , and the treasury account balance is unchanged despite `fee` being non-zero and the message having been fully processed.

	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

		let message_results = messages
			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		let messages_with_weights = message_results
			.iter()
			.zip(messages)
			.map(|(result, message)| MessageWithWeight { message, weight: result.weight() })
			.collect::<Vec<_>>();

		let events = message_results
			.into_iter()
			// check that requests will be successfully dispatched
			// so we can not be spammed with failing txs
			.map(|result| match result {
				MessageResult::Request { events, .. } |
				MessageResult::Response { events, .. } |
				MessageResult::Timeout { events, .. } => events,
				MessageResult::ConsensusMessage(events) => events.into_iter().map(Ok).collect(),
				MessageResult::FrozenClient(_) => vec![],
			})
			.flatten()
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		T::FeeHandler::on_executed(messages_with_weights, events.clone())
			.map_err(|_| Error::<T>::ErrorChargingFee)?;

	fn relayer_for(message: &Message) -> Option<T::AccountId> {
		let (signer, signed) = match message {
			Message::Request(msg) =>
				(&msg.signer, sp_io::hashing::keccak_256(&msg.requests.encode())),
			Message::Response(msg) =>
				(&msg.signer, sp_io::hashing::keccak_256(&msg.requests.encode())),
			_ => return None,
		};
		Signature::decode(&mut &signer[..])
			.ok()?
			.verify_and_get_sr25519_pubkey(&signed, None)
			.ok()
			.map(T::AccountId::from)
	}
