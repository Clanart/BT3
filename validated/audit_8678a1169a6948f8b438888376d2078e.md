### Title
Coinbase outputs are reported as spendable `ReceivedOutput`s before maturity - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_block` scans every transaction in a block, including the coinbase transaction, and returns matching outputs as `ReceivedOutput`s even though `ReceivedOutput` is documented as “A spendable output.” [1](#0-0) [2](#0-1) 

This mirrors the report’s event-semantics bug: an object/event whose name and type imply completed, usable funds is emitted for an output that is not yet spendable under Bitcoin consensus rules. The warning is only present in `scan_block`’s documentation; the returned `ReceivedOutput` carries no maturity state, and `SignableTransaction::new` accepts it without checking whether its outpoint belongs to an immature coinbase. [3](#0-2) 

### Finding Description
`Scanner::scan_transaction` matches only `output.script_pubkey` and constructs a `ReceivedOutput` containing the script’s registered offset, the output, and its outpoint. [4](#0-3) 

`Scanner::scan_block` blindly applies that function to `block.txdata`, including `block.txdata[0]`, the coinbase. [5](#0-4) 

`ReceivedOutput` exposes only `offset`, `output`, `outpoint`, and `value`, so downstream code cannot distinguish a mature normal output from an immature coinbase output unless it retained and independently inspected the containing transaction. [6](#0-5) 

`SignableTransaction::new` then treats all supplied `ReceivedOutput`s as spendable inputs: it sums their values, copies their outpoints into `TxIn`s, and stores their previous outputs for Taproot sighash signing. [7](#0-6) [8](#0-7) 

### Impact Explanation
A wallet or processor can account for an immature coinbase payout as available balance and ask the threshold group to sign a transaction spending it. `TransactionSignMachine::sign` generates valid BIP-340 signature shares over the transaction’s Taproot sighashes, and `TransactionSignatureMachine::complete` inserts the completed signatures into the witnesses. [9](#0-8) [10](#0-9) 

The resulting transaction is nevertheless consensus-invalid until the coinbase reaches maturity. This causes funds to be reported as received/spendable when they are not currently spendable, and can cause a threshold signing round to be consumed for a transaction that nodes will reject.

### Likelihood Explanation
Exploitation requires a block containing a coinbase output paid to a scanner-registered script. That is not available to an arbitrary transaction sender, but it is reachable by any miner or mining pool capable of directing a coinbase payout to the target’s Taproot script. Once such a block is scanned with `scan_block`, no malformed encoding, invalid key, private state, or privileged API is required for the immature output to be returned.

### Recommendation
Encode maturity in the returned type or prevent immature outputs from being returned as ordinary spendable outputs:

- Have `scan_block` skip `block.txdata[0]` by default, matching the documented alternative.
- Or return a distinct type/state such as `ImmatureCoinbase { maturity_height, output }`.
- Add the scanned block height or transaction position to `ReceivedOutput` so callers can enforce coinbase maturity.
- In `SignableTransaction::new`, reject inputs known to be immature rather than relying on every caller to filter them.
- If compatibility requires retaining current behavior, rename or split the result so `ReceivedOutput` cannot silently represent a not-yet-spendable output.

### Proof of Concept
```rust
use bitcoin::{Block, Transaction};
use serai_bitcoin::wallet::Scanner;

fn immature_coinbase_is_reported(
  scanner: &Scanner,
  block: &Block,
) {
  // Construct or obtain a valid block whose txdata[0] is a coinbase paying
  // one of the scanner's registered Taproot scripts.
  assert!(block.txdata[0].is_coinbase());

  let outputs = scanner.scan_block(block);

  // The immature coinbase output is returned as a ReceivedOutput, despite
  // ReceivedOutput being documented as "A spendable output".
  assert!(
    outputs.iter().any(|output|
      output.outpoint().txid == block.txdata[0].compute_txid()
    )
  );
}
```

The returned value can then be passed to `SignableTransaction::new`, which converts it into a `TxIn` without a maturity check and makes it part of the threshold-signed transaction. [7](#0-6)

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
