### Title
Unchecked nil `*ethtypes.Transaction` from `MsgEVMTransaction.AsTransaction()` causes RPC-node panic in `GetEvmTxIndex` - (File: evmrpc/tx.go)

### Summary
`MsgEVMTransaction.AsTransaction()` returns `(nil, nil)` whenever `UnpackTxData` fails to decode the packed `ethtx.TxData`, mirroring the `qlcnic_83xx_alloc_mbx_args()` pattern in the reference CVE where an allocator/decoder is allowed to fail and the caller dereferences the result unconditionally. Most call sites in `evmrpc` guard this (`getEthTxForTxBz` excludes `AssociateTx` and checks the returned pointer; `Backend.BlockByNumber` explicitly checks `if ethtx == nil { continue }`), but `GetEvmTxIndex` in `evmrpc/tx.go` does not.

### Finding Description
`AsTransaction()` is defined to fail closed: [1](#0-0) 

`GetEvmTxIndex` calls it and immediately dereferences the result without a nil check: [2](#0-1) 

Other call sites in the same package treat the nil return as expected and defend against it, confirming that a nil result is a known, reachable outcome rather than a purely theoretical one: [3](#0-2) [4](#0-3) 

`GetEvmTxIndex` is reached from the public JSON-RPC surface via `GetTransactionByHash`, which iterates block messages, and on a `*types.MsgEVMTransaction` calls `AsTransaction()`/`.Hash()` without excluding `AssociateTx` or checking for a nil transaction: [5](#0-4) 

### Impact Explanation
If `etx` is nil when `etx.Hash()` executes, this is a nil-pointer dereference panic inside the `eth_getTransactionByHash` handler goroutine. Depending on whether panic recovery wraps this specific call path, this can crash the RPC node's request-handling goroutine or the whole process, denying `eth_getTransactionByHash` (and its callers, e.g. wallets/dApps polling for transaction status) to all public RPC clients on that node — a crash of a default-configuration RPC node, which is in the accepted impact list.

### Likelihood Explanation
I was not able to conclusively verify, within the available tool budget, that `filterTransactions` (in `evmrpc/utils.go`) allows an `AssociateTx`-carrying `MsgEVMTransaction` (or another message whose `Data` fails to unpack) to reach `GetEvmTxIndex`'s `msgs` slice. If `filterTransactions` already filters out `IsAssociateTx()` messages (mirroring `getEthTxForTxBz`'s explicit exclusion), the nil-dereference path may not be reachable in the current build, which would make this a defensive-coding gap rather than an exploitable Medium-severity bug. This uncertainty should be resolved before treating the finding as confirmed.

### Recommendation
In `GetEvmTxIndex`, check `etx == nil` immediately after `AsTransaction()` (mirroring `Backend.BlockByNumber`'s guard) and either `continue`/skip the message or compute the synthetic hash the same way it is done for `wasmtypes.MsgExecuteContract`, before using `etx.Hash()`. Additionally, verify `filterTransactions` (`evmrpc/utils.go`) excludes `IsAssociateTx()` messages from the slice passed into `GetEvmTxIndex`, and add a regression test that submits an `AssociateTx` (or any message with malformed `Data`) inside a block and calls `eth_getTransactionByHash`/`eth_getTransactionByBlockHashAndIndex` to confirm no panic occurs.

### Proof of Concept
Not fully constructible from static review alone: it depends on confirming (1) whether `filterTransactions` in `evmrpc/utils.go` passes `AssociateTx`-carrying (or otherwise-undecodable) `MsgEVMTransaction` entries through to `GetEvmTxIndex`, and (2) whether a panic in this call path (invoked from `eth_getTransactionByHash`) is caught by an outer recover wrapper that only logs/returns an error versus crashing the node. These two points were not confirmed within the available search budget and should be validated directly against `evmrpc/utils.go`'s `filterTransactions` implementation and the RPC server's panic-recovery middleware before treating this as a fully proven Medium-severity finding.

	}

func GetEvmTxIndex(ctx sdk.Context, block *coretypes.ResultBlock, msgs []indexedMsg, txIndex uint32, k *keeper.Keeper, cacheCreationMutex *sync.Mutex, globalBlockCache BlockCache) (index int, found bool, etx *ethtypes.Transaction, logIndexOffset int) {
	var evmTxIndex, logIndex int
	for _, msg := range msgs {
		var txHash common.Hash
		switch m := msg.msg.(type) {
		case *types.MsgEVMTransaction:
			etx, _ = m.AsTransaction()
			txHash = etx.Hash()
		case *wasmtypes.MsgExecuteContract:
			etx = nil
			txHash = common.Hash(sha256.Sum256(block.Block.Txs[msg.index]))
		}
		receipt, ok := getOrSetCachedReceipt(cacheCreationMutex, globalBlockCache, ctx, k, block, txHash)
		if !ok {
			continue
		}
		if msg.index == int(txIndex) {
			return evmTxIndex, true, etx, logIndex
		}

		evmTxIndex++
		logIndex += len(receipt.Logs)
	}
	return -1, false, nil, -1
}
