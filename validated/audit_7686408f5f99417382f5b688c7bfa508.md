### Title
Payout `SinglePlusAnyoneCanPay` signature leaves anchor/OP_RETURN outputs and all non-index-0 inputs unsigned, letting anyone frame an arbitrary operator for a self-funded withdrawal - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
`create_payout_txhandler` (`core/src/builder/transaction/operator_reimburse.rs:407-436`) signs the withdrawal input with `SpendPath::KeySpend` under a user-supplied `taproot::Signature` whose `sighash_type` is enforced to be `TapSighashType::SinglePlusAnyoneCanPay` (`core/src/rpc/parser/operator.rs:174-187`, `core/src/operator.rs:630-637`). Because `SIGHASH_SINGLE|ANYONECANPAY` only commits the spent input's own outpoint/amount/script and the single output at the same index (output 0, the user's payout output), the anchor output (index 1) and the OP_RETURN output (index 2, which carries `operator_xonly_pk`) are completely unconstrained, as is the presence of any other inputs. Any party who possesses (or produces, since they are the withdrawer) a valid `SinglePlusAnyoneCanPay` signature over the withdrawal UTXO can build and broadcast their own transaction spending that same UTXO, self-funding output 0 with additional inputs of their own choosing, while attaching an arbitrary OP_RETURN naming any registered operator - all while the same signature still verifies.

### Finding Description
The claimed binding — "the txid/output set committed by `SinglePlusAnyoneCanPay` over input 0 == the txid/output set the operator's `payout_txhandler` actually broadcasts" — does **not** hold. `SIGHASH_SINGLE` only commits to the output with the *same index* as the signed input (index 0 here); `ANYONECANPAY` further removes commitment to any other inputs. `create_payout_txhandler` builds outputs `[user_payout, anchor, op_return]` at indices `[0,1,2]` [1](#0-0) , so only output 0 (script_pubkey + amount, matching `output_txout`) and the spent input's outpoint/value are covered by the Schnorr signature; the anchor (index 1) and OP_RETURN with `operator_xonly_pk` (index 2) are free for anyone to change, and additional funding inputs are free to add, because ANYONECANPAY drops the requirement that all inputs be present/committed.

`Operator::withdraw` recomputes the sighash from the transaction it just built and verifies the signature with `SECP.verify_schnorr` [2](#0-1) , then funds and broadcasts it via `fund_raw_transaction`/`sign_raw_transaction_with_wallet`/`send_raw_transaction` [3](#0-2) . Nothing prevents a third party from independently constructing a *different*, equally valid transaction over the same input (with different added inputs and a different anchor/OP_RETURN), using the identical signature, and broadcasting it first.

Downstream, the protocol attributes "who fronted this payout" purely by scanning the confirmed payout transaction's OP_RETURN for an x-only pubkey — there is no on-chain or off-chain check that the operator named in that OP_RETURN actually supplied any of the transaction's funding inputs:
- `update_finalized_payouts` extracts `operator_xonly_pk` solely from `get_first_op_return_output`/`parse_op_return_data` of whichever payout tx is found on-chain for the withdrawal, and stores it as `payout_payer_operator_xonly_pk` [4](#0-3) .
- `PayoutCheckerTask` picks up "unhandled payouts" purely by querying `get_first_unhandled_payout_by_operator_xonly_pk(self.operator.signer.xonly_public_key)` [5](#0-4)  — i.e., it trusts the DB-recorded OP_RETURN attribution, not any local record that this operator itself broadcast the payout.
- `Verifier::is_kickoff_malicious` only checks that the OP_RETURN-derived `operator_xonly_pk` equals `kickoff_data.operator_xonly_pk` and that the committed blockhash matches; it never checks that the named operator's own wallet funded the transaction [6](#0-5) .

Consequently, an attacker (the withdrawer, who legitimately produces the `SinglePlusAnyoneCanPay` signature over their own withdrawal UTXO) can, instead of letting the targeted operator complete `Operator::withdraw`, build their own transaction spending the same withdrawal UTXO, add their own funding input(s) to cover `output_txout`, and add an OP_RETURN naming an arbitrary registered operator, then broadcast it first. Once mined, the honest operator's automation (`PayoutCheckerTask` → `handle_finalized_payout`) will treat this as "my payout," build a kickoff, and eventually be reimbursed from that deposit's move-to-vault output — despite never having spent a satoshi to fund the withdrawal (the attacker self-funded it).

### Impact Explanation
This lets bridge value leave a move-to-vault UTXO without a matching fronted withdrawal from the credited operator: the operator that is auto-credited via OP_RETURN receives the full deposit reimbursement even though the payout output was funded entirely by the attacker's own UTXOs, not the operator's. This matches the Critical category "an operator reimbursed for a payout it never funded" / "BTC leaving a move-to-vault UTXO without a matching fronted withdrawal." The attack is repeatable per withdrawal (any withdrawal signature the attacker controls, i.e., every withdrawal they themselves initiate, since they legitimately produce the SinglePlusAnyoneCanPay signature) and applies across any deposit/operator pairing, since the OP_RETURN's operator field is entirely attacker-chosen at broadcast time and is the only signal the protocol uses for payer attribution.

### Likelihood Explanation
The attacker needs: (1) to be the withdrawer producing a valid `SinglePlusAnyoneCanPay` signature over their own withdrawal UTXO (trivial, they control the L2 withdrawal and can sign it themselves before ever contacting an operator/aggregator), (2) sufficient BTC to self-fund `output_txout`'s value as an additional input (capital cost equal to the withdrawal amount, but this capital returns to the same address they specified as `output_txout`, so net cost is only mining fees), and (3) to win the confirmation race against the targeted operator's `fund_raw_transaction`-funded broadcast (feasible by broadcasting first / with a higher fee rate, since Bitcoin transaction relay/broadcast is fully public and unauthenticated). No verifier, operator, or aggregator privilege is required.

### Recommendation
Bind the anchor and OP_RETURN outputs (and, ideally, all inputs) into the user's commitment, e.g. by requiring `TapSighashType::All` (or `AllPlusAnyoneCanPay` if additional operator-funded inputs must remain flexible but the operator/anchor/OP_RETURN outputs must be fixed) instead of `SinglePlusAnyoneCanPay`, or by having the user co-sign a template that fixes all outputs. Alternatively, require the operator's reimbursement-claim flow to independently verify — using its own wallet's transaction history / signed PSBT record — that it, not a third party, actually broadcast the specific confirmed payout transaction being credited, rather than trusting OP_RETURN content scraped from the chain alone.

            .db
            .get_payout_info_from_move_txid(Some(dbtx), move_txid)
            .await?;
        let Some((operator_xonly_pk_opt, payout_blockhash, _, _)) = payout_info else {
            tracing::warn!(
                "No payout info found in db for move txid {move_txid}, assuming malicious"
            );
            return Ok(true);
        };

        let Some(operator_xonly_pk) = operator_xonly_pk_opt else {
            tracing::warn!("No operator xonly pk found in payout tx OP_RETURN, assuming malicious");
            return Ok(true);
        };

        if operator_xonly_pk != kickoff_data.operator_xonly_pk {
            tracing::warn!("Operator xonly pk for the payout does not match with the kickoff_data");
            return Ok(true);

            kickoff_data.round_idx,
            kickoff_data.kickoff_idx,
            self.config.protocol_paramset(),

        let commits = extract_winternitz_commits(
            kickoff_witness,
            &[wt_derive_path],
            self.config.protocol_paramset(),
        )?;
        let blockhash_data = commits.first();
        // only last 20 bytes of the blockhash is committed
        let truncated_blockhash = &payout_blockhash[12..];
        if let Some(committed_blockhash) = blockhash_data {
            if committed_blockhash != truncated_blockhash {
                tracing::warn!("Payout blockhash does not match committed hash: committed: {:?}, truncated payout blockhash: {:?}",
                        blockhash_data, truncated_blockhash);
                return Ok(true);
            }
        } else {
            return Err(eyre::eyre!("Couldn't retrieve committed data from witness").into());
        }
        Ok(false)
    }
