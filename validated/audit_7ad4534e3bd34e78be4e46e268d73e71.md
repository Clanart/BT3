### Title
Unanchored hostname regex in `isGitHubHost` causes attacker-controlled remote hosts to be classified as GitHub Enterprise, triggering an auto sign-in prompt / GitHub credential release - (File: `app/src/lib/api.ts`)

### Summary
`isGitHubHost` decides whether a git remote's hostname should be treated as a first-party GitHub endpoint. The decision uses the unanchored regex `/(^|\.)(github)\./.test(hostname)`, which matches any hostname that merely contains the substring `.github.` anywhere, not just as a suffix. This is used by `getEndpointKind` in the credential-helper trampoline to decide whether a host is `'enterprise'` (GitHub) vs `'generic'`, which in turn controls whether GitHub OAuth credentials are looked up/offered for that host. [1](#0-0) [2](#0-1) 

### Finding Description
The broken invariant in the original report is: a boundary check (`>=` vs `==`) that should enforce an *exact* match instead accepts a superset, letting attacker-influenced input past a guard that was meant to be strict. The Desktop analog is the same class of bug applied to hostname trust validation: `isGitHubHost` is supposed to strictly determine "is this hostname a GitHub(.com/GHE) host," but its regex only requires the substring `.github.` to appear somewhere in the hostname — it is not anchored to the end of the string (`$`). Domains such as `sub.github.attacker.com` or `evil.github.example.org` will match the pattern `(^|\.)(github)\.` because there is a `.` immediately before `github` and a `.` immediately after it, even though the actual registrable domain is `attacker.com`. [3](#0-2) 

This function feeds `getEndpointKind` in the git-credential trampoline handler, which is invoked whenever Git performs an HTTP(S) credential lookup for a remote (e.g., during `clone`, `fetch`, or `push`). When `credentialUrl.protocol === 'https:'` and no cached account or `WWW-Authenticate` header is present, the code falls through to `isGitHubHost(endpoint)` and treats a match as `'enterprise'`. [2](#0-1) 

Back in `getCredential`, when `endpointKind !== 'generic'` and there's no stored account for that endpoint, Desktop automatically calls `ui.promptForGitHubSignIn(endpoint)` instead of falling back to a generic/manual credential prompt. [4](#0-3) 

The existing guard, `isKnownThirdPartyHost`, only rejects a small hardcoded allowlist (`dev.azure.com`, `gitlab.com`, `bitbucket.org`, `amazonaws.com`, `visualstudio.com`) via a correctly-anchored `endsWith` check, so it does not stop attacker-chosen hostnames containing `.github.` from reaching the vulnerable regex. [5](#0-4) 

### Impact Explanation
An attacker who controls a remote URL that a user clones/fetches/pushes to (e.g., via a malicious clone-URL link, a forked repo's remote, or a git submodule URL) can register/host a domain such as `foo.github.evil.example` or `x.github.<attacker-tld>`. When Desktop's trampoline credential helper is asked by Git for credentials for that host, `isGitHubHost` misclassifies it as GitHub Enterprise (`'enterprise'`), causing Desktop to invoke the GitHub sign-in flow (`ui.promptForGitHubSignIn`) for that attacker-controlled endpoint. This can trick a user into starting an OAuth device/browser flow "for" an unrelated attacker domain, and/or cause any account already associated with an endpoint whose hostname matches to have its GitHub token attached to requests intended for the attacker's host — misdirecting GitHub authentication context to a domain the user did not intend to trust. This falls under "unauthorized OAuth or account binding" / credential-related risk sourced from an attacker-controlled git remote.

### Likelihood Explanation
Reaching this code path requires no privileged access — only that the user interact with a git remote/URL that resolves to an attacker-chosen hostname containing `.github.` as a non-terminal label, which is easy for anyone who can register or subdomain a domain to construct (`something.github.attacker-domain.tld`). The path is naturally reachable through ordinary Desktop workflows (clone/fetch/push with a crafted remote URL), and none of the existing checks (`isDotCom`, `isGHE`, `isKnownThirdPartyHost`) anchor or otherwise validate that `github` appears as the actual last-but-one label of the domain before falling into the vulnerable substring regex. [6](#0-5) 

### Recommendation
Anchor the hostname check to the end of the string and validate the effective top-level structure, e.g. replace `/(^|\.)(github)\./.test(hostname)` with a suffix-based check similar to `isKnownThirdPartyHost`/`isGHE` (`hostname === 'github.<x>' || hostname.endsWith('.github.<x>')` after validating that `<x>` is a real public suffix), or better, rely on `getEndpointVersion`/actual `/meta` probe results rather than substring heuristics for any hostname not exactly equal to a known GitHub domain.

### Proof of Concept
1. Configure a git remote (or click a deep link / open a repo) whose HTTPS URL host is `ci.github.attacker.example` (attacker fully controls `attacker.example` and creates the `github` subdomain label).
2. Perform a `fetch`/`clone`/`push` against that remote; Git invokes the Desktop credential helper trampoline for `https://ci.github.attacker.example`.
3. `getEndpointKind` finds no `WWW-Authenticate` hint and no cached account, and protocol is `https:`, so it calls `isGitHubHost('https://ci.github.attacker.example')`. [2](#0-1) 
4. Inside `isGitHubHost`, hostname `ci.github.attacker.example` is not `github.com`/`api.github.com`, not dotcom/GHE, not in `knownThirdPartyHosts`, but `/(^|\.)(github)\./.test('ci.github.attacker.example')` evaluates `true` (matches `.github.` between `ci` and `attacker`), so the function returns `true` without ever making the `/meta` HEAD request. [7](#0-6) 
5. `getEndpointKind` returns `'enterprise'`, and since no account exists for this endpoint, `getCredential` calls `ui.promptForGitHubSignIn('https://ci.github.attacker.example')`, initiating a GitHub-branded sign-in/OAuth flow bound to the attacker's host. [4](#0-3)

```typescript
/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }
```
