## Analysis

The PowerPerp bug's core invariant is: **one mint channel, two independent burn channels that aren't mutually exclusive**, letting the two channels double-drain a shared pool. The local Hyperbridge analog is the relayer-fee escrow: **one escrow (dispatch), two independent withdrawal channels** — `pallet-relayer::accumulate_fees` (pays the delivering relayer) and `pallet-ismp`'s timeout handler `on_request_timeout` (refunds the payer) — that are not mutually exclusive, both drawing from the same shared `RELAYER_FEE_ACCOUNT`.

### Title
Timeout refund path pays out relayer fees already claimed via `accumulate_fees`, double-draining `RELAYER_FEE_ACCOUNT` - (File: `modules/pallets/ismp/src/host.rs`)

### Summary
When a POST request is dispatched with a fee, `pallet-ismp` escrows the fee into the shared `RELAYER_FEE_ACCOUNT` and stores `RequestMetadata { fee, claimed: false }` [1](#0-0) . There are two independent, permissionless ways to drain that escrow: (1) `pallet-relayer::accumulate_fees`, which proves delivery on the destination and pays the relayer, marking `claimed = true` [2](#0-1) ; and (2) the timeout message handler, which proves non-membership of the request on the destination at a caller-chosen still-retained height and refunds the fee to the payer via `IsmpHost::on_request_timeout` [3](#0-2) . Neither the timeout handler nor `on_request_timeout` checks the `claimed` flag before paying out.

### Finding Description
`accumulate_fees` explicitly guards against re-claiming an already-claimed commitment on its own path: `Some(leaf_meta) => !leaf_meta.claimed` [4](#0-3) , but it does **not** delete the `RequestCommitments` entry — it only flips `claimed` to `true` and leaves the entry (with its `fee` metadata) in storage.

The core ISMP timeout handler, `handle<H>()` in `modules/ismp/core/src/handlers/timeout.rs`, only checks that a commitment entry still *exists* — `host.request_commitment(commitment).is_err()` — never whether `claimed` is already `true`: [5](#0-4) 

It then deletes the commitment and unconditionally calls `host.on_request_timeout(&request, meta)` on success of the module callback [6](#0-5) . `on_request_timeout` decodes the `RequestMetadata` (which includes `claimed`) but never inspects that field — it refunds `leaf_meta.fee.fee` from `RELAYER_FEE_ACCOUNT` back to the payer purely based on `fee.fee > 0`: [3](#0-2) 

Crucially, the timeout's non-membership proof is verified against a **caller-supplied height**, not necessarily the latest known height for the destination: `let state = host.state_machine_commitment(timeout_proof.height)?;` and the "timed out" check only compares `post.timeout()` against that specific height's `state.timestamp()` [7](#0-6) . Because Hyperbridge retains a bounded window of past state commitments (`BoundedStateCommitments`, capped by `MAX_STATE_MACHINE_COMMITMENTS`) [8](#0-7) , an attacker can submit a timeout proof anchored to an **older, still-retained** destination height at which the request had not yet been delivered (non-membership holds) but whose timestamp already exceeds the request's `timeout_timestamp` — even though delivery and fee accumulation already happened at a *later* height.

Both `accumulate_fees` and the timeout submission are permissionless, unsigned extrinsics reachable by any unprivileged actor (the request's own `payer`), requiring no malicious relayer, prover, or admin.

### Impact Explanation
This directly matches the required impact class: unauthorized/duplicate settlement causing loss of funds. The same escrowed fee is paid out twice from `RELAYER_FEE_ACCOUNT` — once to the delivering relayer via `accumulate_fees`, and again to the original payer via the timeout refund — draining a shared pool (`PalletId(*b"ISMPFEES")`) that backs every other pending request's fee. This can starve or fail legitimate future relayer-fee refunds/claims for unrelated requests, and gives the payer a free refund for a message that was in fact delivered and paid for, at the network's expense.

### Likelihood Explanation
No privileged role, relayer collusion, or governance action is required — only a request whose `timeout` is short relative to real-world delivery latency (a value the payer/app controls when dispatching), plus submission of two independently-available, permissionless extrinsics (`accumulate_fees` and a timeout message) using proofs against two different retained heights. Both proof types are standard, expected inputs to these pallets, so this is reachable by any user in normal operating conditions, not just adversarial edge cases.

### Recommendation
- In `on_request_timeout` (`modules/pallets/ismp/src/host.rs`), check `leaf_meta.claimed` and skip/reject the refund if the fee has already been claimed by a relayer.
- In the ISMP timeout handler (`modules/ismp/core/src/handlers/timeout.rs`), require that the destination height used for non-membership verification be at least the latest known commitment height for that state machine (or otherwise reconcile with any later commitment that may already contain a receipt), rather than accepting an arbitrary caller-chosen retained height.
- Alternatively, have `accumulate_fees` delete the `RequestCommitments` entry entirely upon successful accumulation (instead of leaving it with `claimed = true`), so a subsequent timeout for the same commitment fails the `request_commitment` existence check outright.

### Proof of Concept
1. App dispatches a POST request with `fee = F`, `timeout = t` (small), `payer = P`. `RequestMetadata { fee: F, claimed: false }` is stored; `F` moves from `P` into `RELAYER_FEE_ACCOUNT` [9](#0-8) .
2. A relayer delivers the request to the destination at height `H2`, creating a receipt.
3. Anyone submits `accumulate_fees` with a `source_proof`/`dest_proof` pair proving the fee and the `H2` receipt; `Fees[relayer] += F` and `RequestCommitments[commitment].claimed = true` [10](#0-9) .
4. `P` (or anyone) submits a `TimeoutMessage::Post` anchored at an earlier retained destination height `H1 < H2` (still within `BoundedStateCommitments`) where the receipt did not yet exist and `H1`'s timestamp already exceeds `t`. `host.request_commitment(commitment)` still succeeds (entry not deleted by step 3), non-membership at `H1` verifies, and `on_request_timeout` unconditionally refunds `F` back to `P` from `RELAYER_FEE_ACCOUNT` [3](#0-2) .
5. Net effect: `2F` leaves `RELAYER_FEE_ACCOUNT` for a single `F` escrow — the relayer was paid and the payer was refunded the same fee, draining the shared pool.

	fn on_request_timeout(&self, _req: &Request, meta: Vec<u8>) -> Result<(), Error> {
		let leaf_meta = RequestMetadata::<T>::decode(&mut &*meta)
			.map_err(|_| Error::Custom("Failed to decode leaf metadata".to_string()))?;
		if leaf_meta.fee.fee > Zero::zero() {
			T::Currency::transfer(
				&RELAYER_FEE_ACCOUNT.into_account_truncating(),
				&leaf_meta.fee.payer,
				leaf_meta.fee.fee,
				Preservation::Expendable,
			)
			.map_err(|err| Error::Custom(format!("Failed to refund relayer fee: {err:?}")))?;
		}
		Ok(())
	}
