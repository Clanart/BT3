## Analysis

The Notional bug is a missing state-check: a security‑relevant action (`deleverageAccount`) is allowed to run without verifying the value of an invariant (`ENABLED`) that every other privileged action in the same module already checks. The Desktop analog I found follows the exact same shape: a function that *silently mutates a security‑relevant value* (the local git remote URL that determines where the user pushes/fetches) skips the one check that would prevent it from trusting attacker‑supplied data — it never verifies that the new value actually belongs to the expected host/account endpoint.

### Title
Automatic remote-URL rewrite from a GitHub API response never validates the new URL's host against the account endpoint - (File: app/src/lib/stores/updates/update-remote-url.ts)

### Summary
When Desktop refreshes a repository's GitHub metadata, `repositoryWithRefreshedGitHubRepository` fetches the repository object from the API and calls `updateRemoteUrl`, which will silently rewrite the local `origin` remote URL to whatever `clone_url` the API returned [1](#0-0) . The gating logic only checks that the URL *protocol* is unchanged and that the *previous* remote hadn't been manually altered — it never checks that the new `clone_url`'s hostname belongs to the account's actual endpoint [2](#0-1) .

### Finding Description
`urlMatchesRemote`, used both to detect "did the user change the remote" and "does the new URL already match", only compares `hostname`/`owner`/`name` between two URLs — it has no notion of "is this hostname the account's real GitHub/GHE endpoint" [3](#0-2) .

`updateRemoteUrl`'s three guards are:
1. `protocolsMatch` – only compares `https:` vs `ssh:`/`git@`, not the host.
2. `remoteUrlUnchanged` – compares the *previously stored* `gitHubRepository.cloneURL` to the current remote, to detect user tampering.
3. `!urlsMatch` – the new URL differs from the current remote.

If all three hold, Desktop calls `gitStore.setRemoteURL(...)` and rewrites `origin` to `apiRepo.clone_url` with **no confirmation dialog and no host allow-list check** [4](#0-3) .

`apiRepo` comes straight from `api.fetchRepository(owner, name)` against the account's configured endpoint [5](#0-4) . For GitHub Enterprise accounts this is exactly the "GitHub API object" class of attacker-controlled input called out as in-scope: a malicious or compromised GHE server (or a MITM/rogue proxy sitting in front of it) can return an arbitrary `clone_url` value for a repository the victim already has cloned — including one pointing at a completely different host, e.g. `https://attacker.example/org/repo`. Because none of the three guards inspect the resulting hostname against the account's real endpoint, the check that should stop this ("is the new remote actually on my configured GitHub host?") simply doesn't exist — mirroring the missing `ENABLED`/pause check in the original report: the surrounding logic assumes a state invariant (here: "the API only ever returns URLs for the account's own host") that is never actually enforced in code.

### Impact Explanation
This lets a malicious/compromised GitHub Enterprise endpoint silently repoint a victim's `origin` remote to an attacker-controlled git server the next time Desktop refreshes repository metadata (which happens automatically on repository selection/background refresh, requiring no unusual user action). Once the remote is repointed:
- Subsequent pushes go to the attacker's server instead of the real one (silent corruption of what the user pushes / data exfiltration of source code).
- Subsequent fetches/pulls bring in attacker-controlled history/content, which the user will treat as legitimate.
- Because the credential trampoline's host classification (`getEndpointKind`) falls back to heuristics like `WWW-Authenticate` realm strings and a `isGitHubHost` probe rather than a strict endpoint allow-list [6](#0-5) , there is a realistic risk that stored credentials could be offered to the newly-substituted host under some circumstances.

### Likelihood Explanation
Requires the attacker to control the response of the GitHub/GHE API for a repository the victim already has locally (compromised/malicious enterprise server, or an intermediary able to tamper with that specific API response) — no local access, no social engineering step, and no unusual user interaction is needed; the refresh path runs automatically as part of normal repository selection/background sync [7](#0-6) .

### Recommendation
In `updateRemoteUrl`, add an explicit check that the hostname of `apiRepo.clone_url` matches the hostname of `gitHubRepository.endpoint` (or the account's `getHTMLURL(endpoint)` hostname) before calling `setRemoteURL`, and reject/prompt the user rather than silently rewriting the remote when the hosts differ.

### Proof of Concept
1. Add a GitHub Enterprise account in Desktop pointing at `ghe.example.com`, and clone a repo `org/repo` from it (`origin` = `https://ghe.example.com/org/repo`).
2. Compromise/control the GHE instance's (or a MITM in front of it) response to `GET /api/v3/repos/org/repo` so that `clone_url` is `https://attacker.example/org/repo` instead of the real host.
3. Trigger a repository refresh (select the repo, or wait for the background repository indicator/PR updater) — `repositoryWithRefreshedGitHubRepository` → `updateRemoteUrl` runs [8](#0-7) .
4. Because protocol matches (`https:`) and the stored `gitHubRepository.cloneURL` still matches the unmodified current remote, `remoteUrlUnchanged` is true and `urlsMatch` is false, so Desktop silently calls `gitStore.setRemoteURL('origin', 'https://attacker.example/org/repo')` [4](#0-3) .
5. The next `git push`/`git fetch` in Desktop now targets `attacker.example` with no warning shown to the user.

  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe

  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
