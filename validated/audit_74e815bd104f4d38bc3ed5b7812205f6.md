### Title
Missing degree-bound check in `RecoverPolynomialCoefficients` allows inconsistent cell sets to be silently "recovered" - (File: `internal/erasure_code/erasure_code.go`, reached via `api_eip7594.go`)

### Summary
`Context.RecoverCells`/`RecoverCellsAndComputeKZGProofs` call `recoverPolynomialCoeffs`, which delegates to `DataRecovery.RecoverPolynomialCoefficients`. That function computes the full extended-domain coefficient vector (`cosetQuotientEval`, length `numScalarsInCodeword` = 8192) and truncates it to the first `numScalarsInDataWord` (=`ScalarsPerBlob`=4096) coefficients without ever checking that the discarded upper half is all-zero. This omits the exact invariant check present in the reference `c-kzg-4844` implementation, which rejects reconstruction when the recovered polynomial's true degree is not `< ScalarsPerBlob`.

### Finding Description
The broken equality: for a correctly-recovered codeword, `cosetQuotientEval[ScalarsPerBlob:scalarsPerExtBlob]` must all be the zero element (i.e. the recovered polynomial's degree is `< ScalarsPerBlob`). The code never checks this before truncating and returning: [1](#0-0) 

The call path is `Context.RecoverCells...` → `recoverPolynomialCoeffs` (api_eip7594.go), which deserializes attacker-supplied `Cell` bytes into `extendedBlob` at the attacker-chosen `cellIDs` positions and hands the whole vector (with the complementary bit-reversed indices marked "missing") straight to `RecoverPolynomialCoefficients`: [2](#0-1) 

Existing guards (`isAscending`, `cellID >= CellsPerExtBlob`, `NumBlocksNeededToReconstruct`, `deserializeCell`'s canonical-scalar check) only validate structural well-formedness of the input (count, ordering, range, canonical field elements). None of them constrain the *values* of the supplied cells to lie on a valid degree-`<ScalarsPerBlob` codeword. An attacker can therefore submit a self-consistent-looking (correct length/order/range) but algebraically inconsistent set of cells that does not correspond to any degree-`<4096` polynomial. The erasure-decoding algebra (`E(x)=D(x)*Z(x)`, `Q=E/Z`) only reproduces the *original* codeword exactly at non-erased points when the input actually lies on such a low-degree codeword; for an inconsistent input, `Q` will have non-zero high-order coefficients, which are silently discarded by the slice `cosetQuotientEval[:dr.numScalarsInDataWord]` instead of triggering an error.

### Impact Explanation
Because the degree-bound check is absent, `RecoverCellsAndComputeKZGProofs`/consumers of `recoverPolynomialCoeffs` will accept and successfully process (compute cells + proofs, no error) inputs that `c-kzg-4844`'s reference recovery would reject with `C_KZG_BADARGS` (which explicitly checks that coefficients at indices `[FIELD_ELEMENTS_PER_BLOB, FIELD_ELEMENTS_PER_EXT_BLOB)` are zero). This is a client-split condition: for the same attacker-supplied `cellIDs`/`cells`, go-eth-kzg returns success plus some (wrong) recovered cells/proofs, while c-kzg-4844 returns an error. This matches the "High" impact category (library and c-kzg disagreeing on accept/reject or emitted recovered data for the same input).

### Likelihood Explanation
The attacker needs no privileges: `RecoverCellsAndComputeKZGProofs`/`RecoverCells` is a normal public API reachable with attacker-controlled `cellIDs` and `cells` byte arrays that already pass all existing structural checks (ascending order, in-range IDs, canonical scalars, enough cells for the reconstruction threshold). Constructing an inconsistent-but-canonical cell set is a matter of picking arbitrary field elements for the provided cells (no proof-of-knowledge or SRS access needed), making this practically feasible and repeatable per call.

### Recommendation
After computing `cosetQuotientEval` in `RecoverPolynomialCoefficients`, verify that all coefficients from index `numScalarsInDataWord` to `numScalarsInCodeword-1` are the zero field element; if any are non-zero, return an error (mirroring the `C_KZG_BADARGS` check in `c-kzg-4844`) instead of silently truncating.

### Proof of Concept
```go
func TestRecoverPolynomialCoeffsDegreeCheck(t *testing.T) {
    ctx := NewContext4096Secure()
    // Build a valid blob, compute cells normally.
    var blob Blob
    // fill blob with canonical scalars...
    cells, _, err := ctx.ComputeCellsAndKZGProofs(&blob, 0)
    require.NoError(t, err)

    // Take a subset of cellIDs sufficient for reconstruction, but tamper
    // with one supplied cell's scalar values so the set is no longer a
    // valid degree-<4096 codeword (still canonical field elements, still
    // ascending IDs, still in range).
    cellIDs := []uint64{...}      // enough IDs to pass NumBlocksNeededToReconstruct
    tamperedCells := []*Cell{...} // corresponding cells, one deliberately altered

    polyCoeff, err := ctx.recoverPolynomialCoeffs(cellIDs, tamperedCells)
    // EXPECTED (per invariant): err != nil, because recovered polynomial's
    // degree is not < ScalarsPerBlob.
    // ACTUAL (bug): err == nil, and recovered evaluations at cellIDs do not
    // equal tamperedCells, demonstrating the missing degree/consistency check.
    require.Error(t, err)
    _ = polyCoeff
}
```
