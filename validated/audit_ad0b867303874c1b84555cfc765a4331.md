Found the local analog. This is the direct structural counterpart of the Nomad `Queue.contains()` DoS: an unprivileged, permissionless actor can force eviction of another party's already-paid-for entries in a bounded FIFO queue, causing fund loss to the victim.

### Title
Bandwidth subscription FIFO eviction lets anyone with cheap, permissionless purchase-message traffic burn a victim app's prepaid bandwidth - ([File: modules/pallets/bandwidth/src/lib.rs])

### Summary
`pallet-bandwidth` stores each `(app_chain, app)` allowance as a `BoundedVec<Subscription, 1024>` FIFO queue [1](#0-0) . Every accepted `BandwidthPurchaseMsg` — regardless of which chain paid, or which manager relayed it, as long as `request.from` matches the registered `BandwidthManager` for `request.source` — calls `push_subscription`, which unconditionally evicts the oldest live entry once the list hits the 1024 cap [2](#0-1) . This is exactly the Nomad `Queue`/`improperUpdate` pattern: a shared, bounded, permissionlessly-appendable queue where insertion by any party can silently discard another party's already-committed entry.

### Finding Description
The eviction key is `(app_chain, app)`, taken from the purchase message's `chain`/`app` fields, not from `request.source` (the paying chain) [3](#0-2) . The docs confirm this by design: "any deployment can sponsor any app on any chain" [4](#0-3) . So any account holding a small amount of the fee token on any registered source chain can call `BandwidthManager.purchase()` repeatedly with `tier=TierOne`/`months=1` (the cheapest SKU) targeting the exact same `(app_chain, app)` pair a victim already funded, and each purchase appends a new `Subscription` row to that same bounded queue.

Once the queue for that `(app_chain, app)` reaches 1024 entries, every subsequent purchase evicts index 0 — the oldest subscription — via `list.remove(0)` inside `Allowance::<T>::mutate` [5](#0-4) . There is no minimum purchase size, no per-purchaser quota, no reservation of "your own" purchase's queue slot, and no check that the entry being evicted belongs to (or was paid by) the same source. Only a passive `SubscriptionEvicted` event records the loss after the fact [6](#0-5) . This mirrors the report's core broken invariant precisely: "anyone can dispatch a message and insert a new [entry] into the queue," degrading availability/funds for the honest party, with the fix acknowledged as "costly to perform" but still open.

### Impact Explanation
An attacker who repeatedly buys 1024+ cheap `TierOne` subscriptions against a specific `(app_chain, app)` can push out a victim's legitimate, still-unused, already-paid-for `Subscription` before its `remaining_bytes` are ever consumed by the gate. The evicted subscription's `remaining_bytes` (`lost_bytes` in the event) is bridged fee-token value the victim paid for at `BandwidthManager.purchase()` and can never recover — this is direct loss of prepaid funds/allowance for the rightful beneficiary, and it also causes `BandwidthGate::try_consume` to reject or short-charge the victim's genuine ISMP traffic (`GateError::NoAllowance` / `Insufficient`) even though they paid for capacity, matching the "bridged assets ... must move exactly once and only to the rightful beneficiary" pivot.

### Likelihood Explanation
The attack requires only funds for 1024 minimum-tier purchases (`TierOne`, 1 month) plus their relayer/gas cost — no privileged role, no malicious relayer/prover, and no race condition against the victim's transaction is needed since eviction always targets the oldest entry once the cap is hit. Cost scales with tier price × 1024, which the docs list starting at $0.0005/byte for the smallest tier, i.e., the attack is bounded and computable, similar in spirit to the "costly but existing" Nomad DoS acknowledged as open.

### Recommendation
Do not use a single shared FIFO capped at a fixed size across all purchasers of an `(app_chain, app)` pair. Options: (1) key subscriptions per payer (or per purchase transaction) so eviction only ever discards the same purchaser's oldest entry; (2) raise the cap dynamically or reject new purchases instead of silently evicting when the list is full; (3) require a minimum bytes/duration per purchase proportional to cost so filling 1024 slots is materially more expensive than the value it destroys; (4) track and refund/compensate `lost_bytes` to the evicted subscription's original payer instead of just emitting an event.

### Proof of Concept
1. Victim calls `BandwidthManager.purchase(app, TierFour, months=1, chain)` on their source chain, crediting a `Subscription` into `Allowance[app_chain][app]` at, say, index 500.
2. Attacker (any unrelated account, on any chain with a registered `BandwidthManager`) repeatedly calls `purchase(app, TierOne, 1, chain)` targeting the same `(app_chain, app)`, each purchase relayed to Hyperbridge and processed by `on_accept` → `push_subscription` [7](#0-6) .
3. Once `Allowance[app_chain][app].len() == 1024`, each further attacker purchase removes index 0 in `push_subscription` [5](#0-4) ; repeated enough times the victim's subscription reaches index 0 and is evicted, emitting `SubscriptionEvicted { lost_bytes: <victim's remaining_bytes> }`.
4. The victim's app now finds its ISMP messages rejected by `BandwidthGate::try_consume` with `NoAllowance`/`Insufficient` despite having paid, and the bytes they purchased are unrecoverable.

		/// Append a fresh subscription with a fixed expiry. If the list
		/// is already at `MaxSubscriptions`, evict the oldest entry and
		/// emit [`Event::SubscriptionEvicted`] so the lost bytes are
		/// auditable. Returns the new subscription's `expires_at`.
		fn push_subscription(
			app_chain: &StateMachine,
			app: &AppKey,
			tier: TierIndex,
			bytes: BandwidthBytes,
			duration_secs: u64,
		) -> u64 {
			let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();
			let expires_at = now.saturating_add(duration_secs);
			let new_sub =
				Subscription { tier, remaining_bytes: bytes, expires_at, purchased_at: now };

			let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
				let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
					Some(list.remove(0))
				} else {
					None
				};
				// Capacity is now guaranteed; try_push can't fail.
				let _ = list.try_push(new_sub);
				evicted
			});

			if let Some(old) = evicted {
				Self::deposit_event(Event::SubscriptionEvicted {
					app_chain: *app_chain,
					app: app.clone(),
					tier: old.tier,
					lost_bytes: old.remaining_bytes,
				});
			}

			expires_at
		}

	impl<T: Config> IsmpModule for Pallet<T> {
		fn on_accept(&self, request: PostRequest) -> Result<Weight, anyhow::Error> {
			let manager = BandwidthManager::<T>::get(&request.source).ok_or_else(|| {
				anyhow::anyhow!(format!("no bandwidth manager registered for {:?}", request.source))
			})?;

			if request.from != manager.0.to_vec() {
				return Err(anyhow::anyhow!(format!(
					"purchase from unauthorised sender on {:?}: expected {:x?}, got {:x?}",
					request.source, manager.0, request.from
				)));
			}

			let msg = PurchaseMessage::try_from(request.body.as_slice())?;
			let tier = TierIndex::try_from(msg.tier)
				.map_err(|_| anyhow::anyhow!(format!("unknown tier discriminant {}", msg.tier)))?;
			let cfg = Tiers::<T>::get(tier)
				.ok_or_else(|| anyhow::anyhow!(format!("tier {:?} is not configured", tier)))?;

			let bytes = cfg.bytes.saturating_mul(msg.months as u128);
			let duration = cfg.duration_secs.saturating_mul(msg.months as u64);

			let key = AppKey::truncate_from(msg.app);
			let expires_at = Self::push_subscription(&msg.chain, &key, tier, bytes, duration);

			Self::deposit_event(Event::BandwidthCredited {
				app_chain: msg.chain,
				app: key,
				paid_from: request.source,
				tier,
				bytes,
				expires_at,
			});

			Ok(Weight::zero())
		}
