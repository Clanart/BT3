### Title
Spoofed `ReceivedOutput` metadata — claimed `output`/`value` is not bound to the `outpoint` actually spent — (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
Analogous to CVE-2018-5170 (an attachment's displayed name could be spoofed to differ from the actual file opened), `ReceivedOutput::read` deserializes three independent fields — `offset`, `output` (`TxOut`), and `outpoint` — with no check that they are consistent with each other. The value and script_pubkey a caller sees via `value()`/`output()` are arbitrary bytes, while `SignableTransaction` spends `outpoint`. The only consistency check downstream, in `SignableTransaction::multisig`, verifies the claimed `script_pubkey` matches `p2tr_script_buf(offset.group_key())` — it never checks that the claimed `output` corresponds to the real UTXO at `outpoint`, nor that the `offset` belongs to that `outpoint`.

### Finding Description
`ReceivedOutput` is deserialized as three unrelated fields at `networks/bitcoin/src/wallet/mod.rs` (`read`, lines 122–134):

```rust
let offset = Secp256k1::read_F(r)?;
output = TxOut::consensus_decode(&mut buf_r)...;
outpoint = OutPoint::consensus_decode(&mut buf_r)...;
```

No validation ties `output` to `outpoint` (a `TxOut` carries no identity of its own on-chain; validity depends entirely on the UTXO set) or `offset` to `output.script_pubkey`.

When these untrusted `ReceivedOutput`s are passed into `SignableTransaction::new` (`networks/bitcoin/src/wallet/send.rs`, lines 150–256), the two fields are used for disjoint purposes:

- Accounting uses the *claimed* `output`: `input_sat` (line 175), `NotEnoughFunds` check (line 215), change computation (line 228), and `fee()` (lines 138–141) all trust `input.output.value`.
- Spending uses the *claimed* `outpoint`: `tx_ins` are built from `input.outpoint` (line 180), and the signature commits `Prevouts::All(&self.tx.prevouts)` built from the claimed `output`s (line 375).

`SignableTransaction::multisig` (lines 273–285) checks only:

```rust
if p2tr_script_buf(offset.group_key())? != self.prevouts[i].script_pubkey { None?; }
```

i.e., the *declared* script matches the derived key — trivially satisfiable by an attacker who computes `p2tr_script_buf(key + G*offset)` themselves. Nothing verifies `prevouts[i]` equals the actual output at `tx.input[i].previous_output`.

### Impact Explanation
An unprivileged party feeding attacker-crafted bytes to `ReceivedOutput::read` (e.g., a relayed/peer-supplied serialized output, or an output list merged from an untrusted source before `SignableTransaction::new`) can make the wallet display/account for one output while actually spending another:

- **Inflated claim** (claimed value > real UTXO value): the transaction passes `NotEnoughFunds`, gets a threshold signature committing to fake prevouts via `Prevouts::All`, and is then consensus-invalid — burning a full FROST signing session and stalling withdrawals.
- **Deflated claim** (claimed value < real UTXO value): the transaction is *valid*, but the difference between the real UTXO value and the claimed value becomes silent excess miner fee — real, irreversible loss of multisig funds produced by a legitimately-signed transaction.
- Because `offsets` and `prevouts` are zipped by index (lines 176, 275–281) rather than by outpoint, an attacker can also permute which offset/key authorizes which input relative to the declared `TxOut`, provided each declared `script_pubkey` matches its offset's derived key.

### Likelihood Explanation
`ReceivedOutput::read`/`serialize` exist precisely to transport outputs across trust boundaries (`write`/`read` round-trip in `mod.rs` lines 120–148), and the constructor-free struct invites instantiation/merging from external sources. Any deployment path where serialized `ReceivedOutput`s are accepted from a peer, indexer, or RPC-derived data (rather than exclusively produced by the local `Scanner`) is exposed. The attacker only needs to control the serialized bytes — no keys, no threshold participation, no validator compromise. Severity is Medium: direct monetary loss is bounded by the excess-fee scenario (deflated claims), while the inflated-claim scenario is a signing-availability attack.

### Recommendation
Bind the fields together at construction/deserialization time, or treat `ReceivedOutput` as untrusted input:

1. In `ReceivedOutput::read` (or a new `verify`/`checked` constructor), require the caller to resolve `outpoint` against the chain and confirm the on-chain `TxOut` equals `output` — or store only `outpoint` + `offset` and fetch the `TxOut` at spend time.
2. In `SignableTransaction::new`, reject `inputs` not produced by `Scanner::scan_transaction`/`scan_block` (which derive `outpoint` and `output` from the same on-chain object, `mod.rs` lines 199–214), or re-resolve every `input.outpoint` and compare to `input.output` before computing `input_sat`/prevouts.
3. In `SignableTransaction::multisig`, additionally verify `offset` derives a key consistent with the *resolved* prevout, not just the attacker-supplied `script_pubkey` field.

### Proof of Concept
```rust
use bitcoin_serai::{
  bitcoin::{OutPoint, TxOut, Amount, Txid, hashes::Hash},
  wallet::{ReceivedOutput, SignableTransaction, p2tr_script_buf},
};
use k256::{Scalar, ProjectivePoint, elliptic_curve::group::Group};
use frost::curve::Secp256k1;
use std::io::Write;

// Attacker knows the multisig's p2tr script (public on chain).
let group_key = /* even-Y group key */;
let offset = Scalar::ZERO;
let script = p2tr_script_buf(group_key).unwrap();

// Real UTXO at `victim_outpoint` is worth 1_000_000 sats.
let victim_outpoint = OutPoint::new(Txid::from_byte_array([0x11; 32]), 0);

// Craft a serialized ReceivedOutput CLAIMING the outpoint holds only 100_000 sats.
let mut bytes = Vec::new();
bytes.write_all(&offset.to_bytes()).unwrap();
let fake_txout = TxOut { value: Amount::from_sat(100_000), script_pubkey: script };
bytes.write_all(&bitcoin::consensus::serialize(&fake_txout)).unwrap();
bytes.write_all(&bitcoin::consensus::serialize(&victim_outpoint)).unwrap();

let spoofed = ReceivedOutput::read::<&[u8]>(&mut bytes.as_ref()).unwrap();
assert_eq!(spoofed.value(), 100_000);              // "displayed" value (the filename)
assert_eq!(spoofed.outpoint(), &victim_outpoint);  // actually spends the 1M-sat UTXO (the file)

// SignableTransaction::new trusts `spoofed.value()` for input_sat/change and
// builds the input + Prevouts::All commitment from the mismatched fields.
// The multisig() check passes because script_pubkey matches key + G*offset.
// Result: a validly-signed tx that silently pays ~900_000 sats (minus outputs)
// as miner fee — funds reported/accounted as one output while spending another.
