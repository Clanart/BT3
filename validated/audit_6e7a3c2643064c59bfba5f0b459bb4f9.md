### Title
Unbounded buffer offset read in `is_atom_canonical` can raise an unhandled `IndexError` during mempool spend-bundle validation, causing a transaction-processing DoS - (File: `chia/full_node/mempool_manager.py`)

### Summary
`chia/full_node/mempool_manager.py` implements a hand-rolled CLVM atom-length-prefix parser, `is_atom_canonical()`, used by `is_clvm_canonical()`, which is called directly on attacker-supplied `puzzle_reveal`/`solution` bytes from every coin spend in `MempoolManager.validate_spend_bundle()`. The parser advances a byte offset based on a length-prefix tag read from the buffer but never checks that the offset stays within buffer bounds before indexing into it, the same bug class as jsonparser's `Delete()` failing to validate offsets before slicing, leading to an out-of-bounds access and an unhandled runtime error.

### Finding Description
`is_atom_canonical()` decodes CLVM's variable-length atom size prefix (1–6 bytes depending on the tag bits of the first byte) and then loops `prefix_len` times reading `clvm_buffer[offset]` while incrementing `offset`: [1](#0-0) 

None of the branches, nor the loop that consumes `prefix_len` additional bytes, verify `offset < len(clvm_buffer)` before indexing. `is_clvm_canonical()` drives this walker over the whole buffer purely by token counting, again indexing `clvm_buffer[offset]` without a bounds check at loop top: [2](#0-1) 

This is invoked directly on raw bytes of every coin spend's `puzzle_reveal` and `solution` inside the mempool admission path, before any other structural validation of those specific fields occurs in this code path: [3](#0-2) 

`coin_spend.puzzle_reveal`/`coin_spend.solution` are typed as `SerializedProgram`, which is simply an alias for `chia_rs.Program` and is documented in this repo's own architecture notes as using "Lazy deserialization": [4](#0-3) [5](#0-4) 

Because deserialization is lazy, `bytes(coin_spend.puzzle_reveal)` can hand back attacker-controlled bytes that have not yet been fully walked/validated as a well-formed CLVM s-expression by this point — `is_clvm_canonical` may be the first code to actually walk the atom-length structure. If a submitter crafts a truncated or malformed length-prefix (e.g., a byte indicating a 5-byte trailing length field but supplying fewer trailing bytes before the buffer ends), `is_atom_canonical`/`is_clvm_canonical` will index past the end of `clvm_buffer`, raising an uncaught `IndexError` inside `validate_spend_bundle()`.

### Impact Explanation
`validate_spend_bundle()` sits directly in the mempool admission pipeline invoked for every submitted `SpendBundle` (from a wallet peer, RPC caller, or gossiped transaction). An uncaught `IndexError` propagating out of this function during spend-bundle admission is a spend-triggered transaction-processing halt: a single malicious or malformed spend bundle can crash/abort the validation call for that mempool-processing invocation, degrading or halting mempool admission (denial of service) rather than being cleanly rejected with `Err.INVALID_COIN_SOLUTION` as the surrounding code clearly intends. This matches the reported bug class (CWE-125/129: insufficient offset validation before buffer indexing, leading to out-of-bounds access and a runtime panic/DoS), applied here to reachable, unprivileged spend-bundle submission rather than to jsonparser's `Delete()`.

### Likelihood Explanation
The `is_clvm_canonical`/`is_atom_canonical` call sites are reached unconditionally for every coin spend of every submitted spend bundle, with no apparent length/bounds validation performed on the raw bytes beforehand in this code path. This makes the trigger straightforward to reach for a single unprivileged spend-bundle submitter, requiring only a puzzle_reveal or solution blob with a crafted atom-length prefix and insufficient following bytes. I was not able to fully confirm, within the scope of this investigation, whether an outer call site (e.g., `add_spend_bundle()` or the RPC/protocol handler that ultimately calls `validate_spend_bundle()`) wraps the entire admission pipeline in a broad `try/except Exception` that would convert this crash into a graceful `FAILED` status rather than a hard failure/crash of the processing task — this uncertainty affects whether the impact is a per-request failure or a broader mempool-manager disruption, and should be verified directly in the surrounding `add_spend_bundle()`/task-scheduling code before treating this as fully confirmed.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` (and the driving loop in `is_clvm_canonical()`) before every `clvm_buffer[offset]` access, returning a definitive "non-canonical"/invalid result (or raising a handled `ValueError`) instead of allowing an `IndexError` to escape. Additionally, wrap the canonical-serialization check call sites in `validate_spend_bundle()` in a narrow `try/except` that maps any parsing failure to `Err.INVALID_COIN_SOLUTION`, ensuring malformed attacker bytes can never produce an unhandled exception in the mempool admission path.

### Proof of Concept
1. Construct a `CoinSpend` whose `solution` (or `puzzle_reveal`) raw bytes begin with a length-prefix byte matching the 6-byte-prefix tag pattern (`(b & 0b11111110) == 0b11111100`, i.e., `prefix_len = 5`), but which is truncated so fewer than 5 additional bytes follow before the buffer ends (e.g., total buffer length only 2–3 bytes after the tag byte).
2. Wrap this `CoinSpend` in a `SpendBundle` and submit it to a full node's mempool (e.g., via `push_tx`/`add_transaction`), reaching `MempoolManager.validate_spend_bundle()`.
3. `is_clvm_canonical(bytes(coin_spend.solution))` → `is_atom_canonical(clvm_buffer, offset)` attempts to read `clvm_buffer[offset]` past the end of the truncated buffer, raising `IndexError` instead of returning a controlled `Err.INVALID_COIN_SOLUTION` result.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
