### Title
Forged `ReceivedOutput` via unchecked offset/script/outpoint binding in `ReceivedOutput::read` reports unspendable phantom funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The TrufMigrator bug class is a claim accounting flaw: the contract accepts a caller-supplied `amount` and only compares it against `migratedAmount[msg.sender]`, so a user can make claims decoupled from the amount they are actually entitled to — accumulated claims can exceed the real allocation. The analog in Serai's Bitcoin wallet is `ReceivedOutput::read`, which deserializes a triple `(offset, output, outpoint)` and never checks that the three fields are mutually consistent. A `ReceivedOutput` is Serai's authoritative "funds received" record: `offset` is the scalar which, added to `key * G`, yields the key able to spend `output`, and `outpoint` names the UTXO. Because `read` validates none of these relationships, untrusted bytes can fabricate claims of received funds which are not spendable — the same shape as a migrate-claim accepted for an amount the caller was never allocated.

### Finding Description
`ReceivedOutput` is defined at `networks/bitcoin/src/wallet/mod.rs:90-97` with three independent fields: [1](#0-0) 

`read` parses them independently and returns the object with no cross-field check: [2](#0-1) 

Legitimately, `ReceivedOutput`s are only minted by `Scanner::scan_transaction`, which sets `offset` from the `scripts` map keyed by the real `script_pubkey` and sets `outpoint` from the actual txid/vout, so the invariant `p2tr_script_buf(key + G*offset) == output.script_pubkey` and "outpoint exists on-chain paying `output`" holds by construction: [3](#0-2) 

`read` bypasses that construction entirely. An attacker supplying bytes can claim:

1. An arbitrary `offset` paired with a real output paying the scanner's plain key — the spending key derived is `key + offset*G`, which does not match the output's taproot key, so the output can never be signed for (FROST's additive offset is applied to `included[0]`'s share in `sign`, producing a signature for the wrong key; see `crypto/frost/src/sign.rs:283-312` where the view/offset is committed).
2. A fabricated `outpoint` and/or inflated `TxOut.value` — a phantom UTXO reported as received balance. `value()` returns whatever the attacker encoded (`mod.rs:116-118`), and downstream planning treats `ReceivedOutput`s as spendable inputs (`processor/src/multisigs/mod.rs` builds `Plan`s from scanned outputs).
3. Mismatched `output`/`outpoint` pairs — a real outpoint claimed with a different amount or script.

Like the migrator's `amount <= _migratedAmount` check, which validates the claim against the wrong accumulator instead of the claimant's entitlement, `read` performs only syntactic parsing (scalar canonicality via `read_F`, consensus-decodability) and never validates the claim (offset/output/outpoint) against the chain state or the scanner key that makes it spendable.

### Impact Explanation
- Funds reported received that are not spendable: a `ReceivedOutput` whose `offset` does not satisfy `p2tr_script_buf(key + G*offset) == output.script_pubkey` will be included as an input to `SignableTransaction`, but the produced Schnorr signature verifies under `key + offset*G`, not under the output's actual taproot key — the spend transaction is invalid and the input value is stranded/accounted incorrectly.
- Phantom balance: a forged `outpoint`/`value` reports received funds that do not exist on-chain, corrupting accounting and any fee/change/dust math computed over `input_value` (`networks/bitcoin/tests/wallet.rs:270-279` shows this math depends entirely on `output.value()`).
- The dust-attack flavor of the original report maps to many small forged claims accumulating into a materially wrong balance/plan rather than a single large forgery.

### Likelihood Explanation
Reachability requires untrusted bytes reaching `ReceivedOutput::read` — e.g., a `ReceivedOutput` blob relayed from an untrusted coordinator peer, restored from externally writable storage, or supplied by any integration path that serializes outputs (`write`/`serialize` at `mod.rs:136-148` define the exact byte format, so forgery is trivial). Within the pure scanner path outputs are always self-consistent, so exploitation depends on an integration feeding adversarial bytes to `read`; the rules accept this surface. Medium severity: integrity/accounting corruption and stranded funds, not direct key recovery.

### Recommendation
Make `read` enforce the construction invariant, or add a verification method and require callers to invoke it:

- Take the scanner's base `key` (or make `read` a method on `Scanner`) and reject outputs where `p2tr_script_buf(self.key + (GENERATOR * offset)) != output.script_pubkey` or where `offset` is not the registered scalar for that script (`self.scripts.get(&output.script_pubkey) != Some(offset)`).
- Verify `outpoint` against the chain (or at minimum, against the set of outpoints produced by `scan_transaction`/`scan_block`) before treating the `ReceivedOutput` as spendable.
- Alternatively, store/transport the output ID plus a commitment to the script instead of trusting a self-describing `(offset, output, outpoint)` triple.

### Proof of Concept
Conceptual (no Rust harness executed — the index provides source only):

```rust
// networks/bitcoin/src/wallet/mod.rs behavior
let key = even_taproot_key();                       // scanner key, even Y
let real = scanner.scan_transaction(&tx).pop().unwrap(); // offset = Scalar::ZERO

// Attacker crafts bytes: same TxOut and OutPoint, but offset = 1
let mut forged = Vec::new();
forged.extend(Scalar::ONE.to_bytes());
forged.extend(serialize(real.output()));
forged.extend(serialize(real.outpoint()));

let claimed = ReceivedOutput::read(&mut forged.as_slice()).unwrap();
// read() succeeds: scalar is canonical, TxOut/OutPoint decode fine.
assert_eq!(claimed.offset(), Scalar::ONE);
// But p2tr_script_buf(key + G*1) != real.output().script_pubkey,
// so any SignableTransaction consuming `claimed` produces a signature
// for key + G that does not satisfy the real output's key path —
// the input is reported received yet is unspendable.

// Phantom balance variant:
let mut phantom = Vec::new();
phantom.extend(Scalar::ZERO.to_bytes());
phantom.extend(serialize(&TxOut {
    script_pubkey: p2tr_script_buf(key).unwrap(),
    value: Amount::from_sat(u64::MAX >> 10), // arbitrary claimed value
}));
phantom.extend(serialize(&OutPoint::null())); // nonexistent outpoint
let phantom = ReceivedOutput::read(&mut phantom.as_slice()).unwrap();
assert!(phantom.value() > 0); // accepted as received balance
```

Root cause: `ReceivedOutput::read` (`networks/bitcoin/src/wallet/mod.rs:120-134`) treats three independently meaningful fields as self-certifying, exactly as `migrate` treated a caller-supplied `amount` as self-certifying against a weak equality check — claims are deserialized, not validated against the entitlement (chain output + registered offset) that would make them spendable.

Caveat: the severity of the forged-offset path depends on how callers treat deserialized `ReceivedOutput`s; if every consumer re-derives them exclusively via `Scanner::scan_transaction`/`scan_block`, `read` is only used on trusted bytes and the finding degrades to a hardening issue.

  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
