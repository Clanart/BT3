## Title
Sensitive-path clone guard compares a lexical `Path.resolve()` string instead of the real filesystem target, letting a crafted clone name write outside the intended directory - ([File: app/src/lib/git/clone.ts])

### Summary
`isClonePathSensitive()` in `app/src/lib/git/clone.ts` is a denylist check meant to guarantee that `git clone` can never write into sensitive locations such as `~/.ssh`, `~/.gnupg`, `~/.config`, `~/.gitconfig`, or (on Windows) `%APPDATA%`. Like `Address.isContract()` in the Solidity report, it is a heuristic proxy for a real-world property ("this destination is safe") rather than an authoritative check, and it can be satisfied even when the underlying assumption is false.

### Finding Description
`isClonePathSensitive()` only performs a **lexical, string-level** normalization of the destination path: [1](#0-0) 

`Path.resolve()` never touches the filesystem — it does not resolve symlinks, junctions, 8.3 short names, or OS-specific path canonicalization (e.g. Windows silently stripping trailing dots/spaces from path segments, or treating short names like `GNUPG~1` as equivalent to `gnupg`). The function assumes that a purely syntactic comparison against a hard-coded list of sensitive locations is equivalent to asking the OS "will this write actually land inside one of these directories?" — the same category of mistake as trusting `Address.isContract()` to prove an address can never later behave like a contract.

The destination path fed into `clone()` is influenced by attacker-controlled data: `sanitizeCloneName()` derives a single path component from a URL-supplied repository name (from a crafted clone URL or an `x-github-client://openRepo/...` deep link a user clicks), which is then joined with the user's base clone directory: [2](#0-1) [3](#0-2) 

Because the guard only rejects an *exact* (case-insensitive) lexical match or prefix match against the sensitive list, any technique that makes the final on-disk write target one of these directories while the resolved string differs bypasses the check entirely — for example:
- A pre-existing symlink/junction at the destination component whose target is `~/.gnupg` or `~/.ssh` — `Path.resolve()` returns the symlink's own path, not its target, so the comparison never matches, yet `git clone` (via the OS) follows the link and writes through it.
- Windows path-normalization quirks (trailing `.`/space stripping, 8.3 short names, alternate casing of UNC/`\\?\` prefixes) that make two syntactically different strings resolve to the same real directory.

`clone()` performs the check once, then unconditionally hands the same string to `git`, which does the actual directory creation/writes — a classic check/use mismatch: [4](#0-3) 

### Impact Explanation
If bypassed, `git clone` writes an attacker-controlled tree directly into a security-sensitive directory (`~/.ssh`, `~/.gnupg`, `~/.config/git`, `~/.gitconfig`, `%APPDATA%`). This can overwrite `~/.ssh/authorized_keys` or `~/.ssh/config` (e.g. injecting a `ProxyCommand`/`ProxyJump` for command execution on next SSH use), corrupt the user's GPG keyring/trustdb, or overwrite global Git configuration (`~/.gitconfig`, `include.path` directives) to silently alter how future commits are signed/authored or redirect credential helpers — matching the "file write outside the repo" / "silent corruption of what the user commits or pushes" / "credential exfiltration" categories in the valid-impact list.

### Likelihood Explanation
Exploitation requires the destination path string to differ from its real filesystem target while still resolving to a sensitive directory at the OS level — most reliably via a pre-planted symlink/junction at the clone destination, or Windows path-canonicalization edge cases. This is a narrower, secondary condition on top of the primary attacker-controlled input (a crafted clone URL/deep link, which fits the allowed threat model), so likelihood is lower than a fully self-contained remote exploit, but the guard is explicitly a "backstop against path traversal" and provides no defense once its string-equality assumption is violated — the exact "checked with an unreliable proxy" pattern from the source report.

### Recommendation
Do not rely on lexical string comparison of an unresolved path. After resolving the destination, use the filesystem's real path (`fs.realpath`/`fs.realpathSync`, resolving through any existing symlinks/junctions) before comparing against the sensitive-location list, and re-validate the real path again immediately before invoking `git clone` (or have `clone()` create the destination itself with `O_NOFOLLOW`-style semantics rather than trusting a pre-existing directory/symlink). Consider rejecting destinations that already exist as symlinks/junctions outright.

### Proof of Concept
1. On a Windows or POSIX machine, use the default "Clone in Desktop" base directory (e.g. `~/Documents/GitHub`) that already contains a symlink/junction named `payload` pointing at `~/.ssh` (this is a one-time local setup step preceding the remote-triggered part; on POSIX, per the existing test suite in `app/test/unit/path-test.ts`, `resolveWithin`-style checks demonstrate that plain path-string logic can't see through symlinks).
2. Craft a clone URL/deep link whose derived name (via `sanitizeCloneName`) resolves to `payload`, e.g. `x-github-client://openRepo/https://attacker.example/owner/payload.git`, and get the victim to click it.
3. `isClonePathSensitive(join(baseDir, 'payload'))` computes `Path.resolve(...)` which returns the literal `.../Documents/GitHub/payload` string — this does not match any entry in `sensitiveLocations` (which contains the real `~/.ssh` path), so the check passes.
4. `git clone ... payload` is executed; the OS follows the symlink, and the attacker's repository content is written directly into `~/.ssh`, overwriting `authorized_keys`/`config`. [5](#0-4) [2](#0-1)

function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}

/**
 * Clones a repository from a given url into to the specified path.
 *
 * @param url     - The remote repository URL to clone from
 *
 * @param path    - The destination path for the cloned repository. If the
 *                  path does not exist it will be created. Cloning into an
 *                  existing directory is only allowed if the directory is
 *                  empty.
 *
 * @param options  - Options specific to the clone operation, see the
 *                   documentation for CloneOptions for more details.
 *
 * @param progressCallback - An optional function which will be invoked
 *                           with information about the current progress
 *                           of the clone operation. When provided this enables
 *                           the '--progress' command line flag for
 *                           'git clone'.
 */
export async function clone(
  url: string,
  path: string,
  options: CloneOptions,
  progressCallback?: (progress: ICloneProgress) => void
): Promise<void> {
  if (isClonePathSensitive(path)) {
    throw new Error(
      `The clone destination "${path}" targets a sensitive system location. ` +
        'Cloning into this directory is not allowed.'
    )
  }

  const env = {
    ...(await envForRemoteOperation(url)),
    GIT_CLONE_PROTECTION_ACTIVE: 'false',
  }

  const defaultBranch = options.defaultBranch ?? (await getDefaultBranch())

  const args = [
    '-c',
    `init.defaultBranch=${defaultBranch}`,
    'clone',
    '--recursive',
  ]

  let opts: IGitStringExecutionOptions = { env }

  if (progressCallback) {
    args.push('--progress')

    const title = `Cloning into ${path}`
    const kind = 'clone'

    opts = await executionOptionsWithProgress(
      { ...opts, trackLFSProgress: true },
      new CloneProgressParser(),
      progress => {
        const description =
          progress.kind === 'progress' ? progress.details.text : progress.text
        const value = progress.percent

        progressCallback({ kind, title, description, value })
      }
    )

    // Initial progress
    progressCallback({ kind, title, value: 0 })
  }

  if (options.branch) {
    args.push('-b', options.branch)
  }

  args.push('--', url, path)

  await git(args, __dirname, 'clone', opts)

export function sanitizeCloneName(name: string): string | null {
  const components = name.split(/[/\\:]/)

  let lastComponent = ''
  for (let i = components.length - 1; i >= 0; i--) {
    if (components[i].length > 0) {
      lastComponent = components[i]
      break
    }
  }

  if (lastComponent.length === 0) {
    return null
  }

  if (lastComponent.endsWith('.git')) {
    lastComponent = lastComponent.slice(0, -4)
  }

  if (
    lastComponent === '..' ||
    lastComponent === '.' ||
    lastComponent.length === 0
  ) {
    return null
  }

  return lastComponent
}
