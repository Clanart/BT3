### Title
Permissionless `harvest()` allows flash-deposit sandwiching of reward distribution, diluting rewards for genuine stakers - (File: wombat/WombatStaking.sol, rewards/BaseRewardPool.sol)

### Summary
`WombatStaking.harvest()` is callable by anyone with no caller restriction beyond the pool being active, and it immediately pushes newly harvested WOM (and bonus token) rewards into `BaseRewardPool.queueNewRewards`, which instantly recomputes `rewardPerTokenStored` using the *current* `totalStaked()` snapshot. Because `MasterMagpie.deposit`/`withdraw` have no lock-up or cooldown, any unprivileged wallet can inflate its share of `totalStaked` immediately before triggering (or being present for) a harvest, capture a disproportionate slice of the freshly queued rewards, and withdraw right after — an economically equivalent "sandwich" to the DODO GSP `adjustPrice` bug, except the trigger here (`harvest`) is itself unprivileged.

### Finding Description
`harvest()` is declared `external` and gated only by `whenNotPaused` and `_onlyActivePool(_lpToken)`, neither of which restricts the caller identity: [1](#0-0) 

It calls `_toMasterWomAndSendReward`, which withdraws/harvests from `MasterWombat` and immediately forwards the harvested WOM/bonus balances to the pool's rewarder via `_sendRewards` → `queueNewRewards`: [2](#0-1) [3](#0-2) 

`BaseRewardPool.queueNewRewards`/`_provisionReward` distributes the entire incoming reward amount over the *current* `totalStaked()` in a single atomic step, immediately raising `rewardPerTokenStored`: [4](#0-3) 

`MasterMagpie.deposit`/`withdraw` (and their `depositFor`/`withdrawFor` counterparts used by the pool helpers) have no minimum holding period, cooldown, or exit fee — a user can deposit and withdraw in the same transaction/block: [5](#0-4) [6](#0-5) 

Because the reward split is proportional to `totalStaked` at the exact moment `queueNewRewards` executes, and both the stake-inflation action and the `harvest()` trigger are permissionless and combinable in one transaction, an attacker can:
1. Flash/temporarily deposit a large amount of the pool's receipt token into `MasterMagpie` right before calling `WombatStaking.harvest(lpToken)`.
2. `harvest()` pulls pending WOM from `MasterWombat` and immediately queues it into `BaseRewardPool`, computing `rewardPerTokenStored` using the now-inflated `totalStaked` that includes the attacker's flash stake.
3. The attacker's flash stake earns a share of `rewardPerTokenStored` disproportionate to the time it was actually staked, at the expense of genuine long-term stakers, then withdraws immediately.

This mirrors the report's root cause exactly: a state change that instantly re-prices a per-share value (there: AMM price via `I`; here: `rewardPerTokenStored`) is exploitable by an unprivileged wallet wrapping the triggering action with deposit/withdraw, extracting value that should have accrued to honest, longer-term liquidity/stake providers.

### Impact Explanation
This results in a direct, permanent transfer of yield from genuine stakers to the attacker — a theft of unclaimed yield category. Each harvest cycle that the attacker sandwiches permanently reduces the rewards available to legitimate stakers who were staked the entire accrual period, since `rewardPerTokenStored` only increases and the attacker's transient stake competes for a slice of it without contributing meaningfully to the LP/staking duration that earned it. Given `harvest()` can be called by anyone at any time and reward distributions to Wombat pools accrue continuously, this is repeatable and scales with the size of the flash deposit relative to existing `totalStaked`.

### Likelihood Explanation
High. No privileged role, oracle, or governance action is required — only an unprivileged wallet capable of performing deposit → harvest → withdraw within one transaction (or across consecutive blocks with MEV bundling), using its own or borrowed (flash-loanable, if the receipt/LP token or its underlying is flash-loan-able) capital.

### Recommendation
- Snapshot eligible stakers' shares at the time rewards are earned (e.g., time-weighted or per-block accrual) rather than instantaneously socializing a lump-sum reward over the current `totalStaked`.
- Add a minimum staking duration / cooldown between deposit and withdrawal in `MasterMagpie`, or an entry/exit fee that neutralizes flash-deposit profitability.
- Alternatively, restrict `harvest()` or its downstream reward queuing to occur only via time-locked, rate-limited schedules so a single large harvest cannot be paired atomically with a stake-size manipulation.

### Proof of Concept
```
1. Attacker observes there is pending WOM reward accrued in MasterWombat for lpToken X.
2. Attacker calls MasterMagpie.deposit(receiptTokenX, largeAmount) (or depositFor via pool helper),
   drastically increasing totalStaked() for pool X.
3. Attacker (or anyone) calls WombatStaking.harvest(lpTokenX), which:
     - withdraws/harvests WOM from MasterWombat
     - calls BaseRewardPool.queueNewRewards(womRewards, wom)
     - rewardPerTokenStored jumps using the now-inflated totalStaked()
4. Attacker immediately calls MasterMagpie.withdraw(receiptTokenX, largeAmount),
   claiming their proportional share of the just-queued reward via getReward/harvest path.
5. Net effect: attacker earns reward for holding stake for ~0 duration, diluting the
   rewardPerToken accrual that legitimate long-term stakers would have otherwise received in full.
```

    function _sendRewards(
        address _lpToken,
        address _rewardToken,
        address _rewarder,
        uint256 _amount
    ) internal {
        if (_amount == 0) return;
        uint256 originalRewardAmount = _amount;

        if (!isPoolFeeFree[_lpToken]) {
            for (uint256 i = 0; i < feeInfos.length; i++) {
                Fees storage feeInfo = feeInfos[i];

                if (feeInfo.isActive) {
                    address rewardToken = _rewardToken;
                    uint256 feeAmount = (originalRewardAmount * feeInfo.value) / DENOMINATOR;
                    _amount -= feeAmount;
                    uint256 feeTosend = feeAmount;

                    if (feeInfo.isMWOM && rewardToken == wom) {
                        if (smartWomConverter != address(0)) {
                            IERC20(wom).safeApprove(smartWomConverter, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IConverter(smartWomConverter).smartConvert(feeAmount, 0);
                            rewardToken = mWom;
                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
                        } else {
                            IERC20(wom).safeApprove(mWom, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IMWom(mWom).deposit(feeAmount);
                            rewardToken = mWom;
                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
                        }
                    }

                    if (!feeInfo.isAddress) {
                        IERC20(rewardToken).safeApprove(feeInfo.to, 0);
                        IERC20(rewardToken).safeApprove(feeInfo.to, feeTosend);
                        IBaseRewardPool(feeInfo.to).queueNewRewards(feeTosend, rewardToken);
                    } else {
                        IERC20(rewardToken).safeTransfer(feeInfo.to, feeTosend);
                        emit RewardPaidTo(feeInfo.to, rewardToken, feeTosend);
                    }
                }
            }
        }

        IERC20(_rewardToken).safeApprove(_rewarder, 0);
        IERC20(_rewardToken).safeApprove(_rewarder, _amount);
        IBaseRewardPool(_rewarder).queueNewRewards(_amount, _rewardToken);
    }

    /// @notice Sends new rewards to be distributed to the users staking. Only callable by manager
    /// @param _amountReward Amount of reward token to be distributed
    /// @param _rewardToken Address reward token
    function queueNewRewards(uint256 _amountReward, address _rewardToken)
        override
        external
        onlyManager
        returns (bool)
    {
        if (!isRewardToken[_rewardToken]) {
            rewardTokens.push(_rewardToken);
            isRewardToken[_rewardToken] = true;
        }

        _provisionReward(_amountReward, _rewardToken);
        return true;
    }

        if (!isRewardToken[_rewardToken])
            revert MustBeRewardToken();

        _provisionReward(_amountReward, _rewardToken);
    }

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (this.totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingDecimals()) /
                this.totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
