### Title
Permissionless `WombatStaking.harvest()` Allows Flash-Deposit Reward Skimming From Long-Term Stakers - (File: `wombat/WombatStaking.sol`, `rewards/BaseRewardPool.sol`, `rewards/MasterMagpie.sol`)

### Summary
`WombatStaking.harvest()` is a permissionless, unrestricted external function that pulls accumulated WOM rewards from Wombat's MasterWombat and immediately books them into the pool's `BaseRewardPool` via `queueNewRewards`/`_provisionReward`. Because the reward-per-share update uses the *current* `totalStaked()` at the moment of the call, and because `MasterMagpie` deposits/withdrawals have no lock-up period or entry/exit fee, an attacker can deposit a large stake, immediately trigger `harvest()` to book rewards that accrued to long-term stakers, and immediately withdraw — capturing a share of the harvested rewards proportional to their capital rather than their staking duration.

### Finding Description
`WombatStaking.harvest()` is callable by anyone and is gated only by `_onlyActivePool(_lpToken)`, which validates pool state, not caller identity: [1](#0-0) 

It calls `_toMasterWomAndSendReward`, which pulls WOM from MasterWombat and forwards it to the pool's rewarder via `_sendRewards`, ultimately invoking the rewarder's `queueNewRewards`: [2](#0-1) 

`BaseRewardPool._provisionReward` updates `rewardPerTokenStored` using the reward amount divided by the *current* `totalStaked()`, with no snapshotting or time-weighting of who contributed to a given period of reward accrual: [3](#0-2) 

Meanwhile, `MasterMagpie._deposit`/`_withdraw` set a user's `rewardDebt` immediately at deposit/withdraw time with no lock-up period and no entry/exit fee, allowing deposit → harvest → withdraw to be executed in a single transaction: [4](#0-3) 

Sequence of the attack:
1. Attacker deposits a large LP amount via a `WombatPoolHelper`, which calls `WombatStaking.deposit` (this call itself harvests only the rewards accrued *before* the attacker's stake is added to `totalStaked`, since the receipt token is staked into `MasterMagpie` afterward) then stakes the receipt token into `MasterMagpie`, setting the attacker's `userRewardPerTokenPaid` to the pre-harvest index.
2. Attacker calls `WombatStaking.harvest(lpToken)` directly, which pulls all WOM rewards accumulated by MasterWombat since the last harvest (accrued by long-term stakers over time) and books them into the `BaseRewardPool` using `totalStaked()` that now includes the attacker's freshly-deposited large stake.
3. Because `earned()` computes `user.amount * (rewardPerToken() - userRewardPerTokenPaid)`, and the attacker's `user.amount` is now large while `userRewardPerTokenPaid` reflects the pre-harvest baseline, the attacker captures a share of the newly-booked reward proportional to their capital, not their staking duration.
4. Attacker withdraws immediately (no lock-up, no fee) and exits with a disproportionate share of rewards that rightfully belonged to long-term stakers.

This mirrors the root causes identified in M-7: a permissionless reward-triggering function, no deposit/withdrawal fee, no minimum holding period preventing same-block enter/exit, and no mechanism to weight reward distribution by deposit duration.

### Impact Explanation
Long-term stakers in a Wombat pool have their fair share of harvested WOM rewards diluted/stolen by an attacker who deposits capital immediately before calling `harvest()` and withdraws immediately after. This constitutes theft of unclaimed yield belonging to existing stakers, repeatable on any pool where `harvest()` can be profitably front-run relative to the pending reward size.

### Likelihood Explanation
Likelihood is moderate-to-high: any address can call `harvest()` at will (no access control), `MasterMagpie` deposit/withdraw have no time lock or fee, and the profitability only requires the attacker's capital to be large relative to the pool's total stake at the moment relative to the size of accrued, un-harvested WOM rewards — information that is fully observable on-chain (MasterWombat's `pendingTokens`/reward rate).

### Recommendation
- Restrict/rate-limit `WombatStaking.harvest()` so it cannot be triggered by arbitrary externally-owned accounts, or route it through a keeper with private-mempool submission.
- Introduce a minimum holding/lock period between `MasterMagpie` deposit and withdrawal for a given staking token (e.g., N blocks) to prevent flash deposit/withdraw around reward-harvest events.
- Consider time-weighting reward distribution (e.g., snapshot `totalStaked` prior to the triggering deposit, or checkpoint rewards prior to processing new deposits in the same block) so freshly deposited capital cannot claim rewards accrued before the deposit.

### Proof of Concept
1. Long-term stakers hold LP receipt tokens staked in `MasterMagpie` against a Wombat pool; WOM rewards accrue in `MasterWombat` over time, unharvested.
2. Attacker deposits a large LP amount via the pool's `WombatPoolHelper`/`WombatStaking.deposit`, staking the resulting receipt tokens into `MasterMagpie` (`rewards/MasterMagpie.sol` `_deposit`, lines 482-505) — their `rewardDebt` snapshot excludes the impending harvest.
3. In the same transaction, attacker calls `WombatStaking.harvest(lpToken)` (`wombat/WombatStaking.sol`, lines 331-335), pulling accumulated WOM and booking it via `BaseRewardPool._provisionReward` (`rewards/BaseRewardPool.sol`, lines 297-320) using the now-inflated `totalStaked()`.
4. Attacker calls `withdraw` through the pool helper, which triggers `MasterMagpie._withdraw`/`_harvestAndUnstake` (lines 508-534) with no lock or fee, claiming their disproportionate share of the reward and exiting immediately.

        Pool storage poolInfo = pools[_lpToken];

        address[] memory bonusTokens = assetToBonusRewards[_lpToken];
        uint256 bonusTokensLength = bonusTokens.length;

        uint256 womBeforeBalance = IERC20(wom).balanceOf(address(this));

        if(_isStake)
            _stakeToWombatMaster(_lpToken, lpAmount); // triggers harvest from wombat exchange

        _sendRewards(_lpToken, wom, poolInfo.rewarder, womRewards);

            }

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (this.totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingDecimals()) /
                this.totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
    }

    function _withdraw(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        _harvestAndUnstake(_stakingToken, _account, _amount, _isVlMgp);

        if (!_isVlMgp)

    function _harvestAndUnstake(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        updatePool(_stakingToken);

        UserInfo storage user = userInfo[_stakingToken][_account];

        if (!_isVlMgp && user.available < _amount)
            revert WithdrawAmountExceedsStaked();
        else if(user.amount < _amount && _isVlMgp)
            revert UnlockAmountExceedsLocked();
        
        _harvestMGP(_stakingToken, _account);
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount - _amount;
        
        if(!_isVlMgp)
            user.available = user.available - _amount;
        user.rewardDebt = (user.amount * tokenToPoolInfo[_stakingToken].accMGPPerShare) / 1e12;
    }
