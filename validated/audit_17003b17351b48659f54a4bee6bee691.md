### Title
Forged DKG blame evidence: PedPoP `EncryptedMessage` PoP binds only a self-asserted sender index, letting an accuser frame any honest participant - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
The bug class from CVE-2023-41894 is *origin confusion*: an action restricted to a "trusted/local" principal is authorized based on attacker-controllable origin metadata (SniTun rewriting the source to `127.0.0.1`). The Serai analog lives in PedPoP's blame path. `BlameMachine::blame_internal` (`crypto/dkg/pedpop/src/lib.rs`) evaluates a fault claim `(sender, recipient, EncryptedMessage, proof)` supplied entirely by the accuser. The only cryptographic binding of the message to `sender` is the `from` field mixed into `pop_challenge` — and that field is chosen by whoever *created* the message, not proven. An accuser can therefore fabricate an `EncryptedMessage` whose PoP verifies under any claimed `sender`, decrypt it with a valid `EncryptionKeyProof`, and get an innocent participant blamed for sending an invalid secret share.

### Finding Description
`pop_challenge` computes the Schnorr challenge over `(context, nonce, key, sender, msg)` where `sender` is just a `Participant` integer (crypto/dkg/pedpop/src/encryption.rs:302-324). `encrypt` sets `from = self.i` honestly (encryption.rs:135-168), but nothing prevents an attacker from constructing the identical challenge with `from = victim` — all transcript inputs are public. The per-message key `k` is ephemeral and attacker-chosen, so `SchnorrSignature::sign(&k, nonce, pop_challenge(..., victim, ...))` verifies under `msg.key = G*k` for the claimed victim.

`Decryption::decrypt_with_proof` (encryption.rs:366-397) then:
1. Verifies `msg.pop` against `pop_challenge(context, msg.pop.R, msg.key, from, msg.msg)` — passes, because the attacker embedded `from = victim` when crafting it.
2. Verifies `proof.dleq` showing `proof.key = enc_keys[decryptor]^k` — the accuser sets `decryptor = themselves` (they know `k`, so they compute `enc_keys[accuser]^k` and a valid DLEq). The ECDH input requires no knowledge of the victim's secrets.
3. Decrypts the message and `blame_internal` (lib.rs:575-613) checks `share_verification_statements(recipient, commitments[victim], share)`. The attacker put a garbage share inside, so this fails and `blame_internal` returns `sender` = the victim.

The honest victim's real share message (which was valid) is irrelevant — the fabricated blame proof is what gets judged.

### Impact Explanation
Any participant (or any party able to submit a blame claim containing `EncryptedMessage`/`EncryptionKeyProof` bytes) can produce a fully "valid" blame proof convicting an arbitrary honest participant of sending an invalid DKG share. Downstream this causes the honest party to be marked faulty and removed (and, in Serai's coordinator flow, subject to `RemoveParticipant`/slashing), while the malicious accuser is cleared. This is a forged proof of misbehavior — an integrity failure of the DKG's accountability mechanism — reachable purely from public inputs (the accuser-controlled message bytes and claimed participant indexes). Severity: Medium.

### Likelihood Explanation
The attack requires the attacker to be able to trigger blame evaluation, which happens whenever shares are disputed during DKG — a routine protocol path. Crafting the message needs only public data (the context, the accuser's own registered encryption key `enc_keys[accuser]`, the victim's public commitments) plus locally generated scalars. No secret knowledge, collusion, or timing condition is required. The only mitigating factor is that an embedding protocol could, in principle, check that the submitted `msg` hash-matches a previously observed authenticated message — the library itself does not provide or enforce this, and its own test helper `invalidate_msg` demonstrates exactly this attacker capability (arbitrary `from`, valid PoP, gibberish plaintext).

### Recommendation
Bind blame evidence to the sender's registered identity, not to a self-declared index. Concretely:
- Include the sender's round-1 `enc_key` (the `EncryptionKeyMessage.enc_key` registered under `sender` in `Decryption::register`) or the sender's commitments/first PoK key inside `pop_challenge`, and require the PoP to verify under a key the victim actually published in round 1, OR
- Require the round-2 message PoP to be a signature under the sender's long-term/registered key (e.g., the key that proved knowledge of `commitments[0]`), so only the genuine sender can produce a PoP carrying `from = sender`.

Until then, `blame_internal`/`decrypt_with_proof` verdicts of `InvalidSignature`/invalid share are unattributable and must not be used to fault the claimed `sender`.

### Proof of Concept
Conceptual (all APIs are public or `pub(crate)` within the crate):

```rust
// Attacker: participant `a`, accuses honest `h` of sending an invalid share to `a`.
// `context`, h's commitments, and a's own enc_pub_key are all public/known.

// 1. Choose a garbage share and per-message key k
let k = Zeroizing::new(C::random_nonzero_F(rng));
let bad_share = SecretShare::<C::F>(C::F::ONE.to_repr()); // invalid for h's polynomial

// 2. Encrypt it "to a" using a's public enc key (public ECDH: enc_keys[a]^k)
let mut msg_bytes = Zeroizing::new(bad_share.clone());
cipher::<C>(context, &ecdh::<C>(&k, a_enc_pub_key)).apply_keystream(msg_bytes.as_mut().as_mut());

// 3. Sign the PoP with `from = h` — from is just bytes in the challenge
let nonce = Zeroizing::new(C::random_nonzero_F(rng));
let pop = SchnorrSignature::sign(&k, nonce,
    pop_challenge::<C>(context, G * nonce, G * k, /* from */ h, msg_bytes.as_ref()));
let forged = EncryptedMessage { key: G * k, pop, msg: msg_bytes };

// 4. Produce the EncryptionKeyProof with k (attacker knows k)
let proof = EncryptionKeyProof { key: ecdh(&k_for_a_key_dir, a_enc_pub_key),
    dleq: DLEqProof::prove(rng, &mut encryption_key_transcript(context),
                           &[G, forged.key], &k) };

// 5. blame_internal(sender=h, recipient=a, forged, Some(proof)):
//    - pop.verify passes (challenge used from=h, as forged)
//    - dleq.verify passes (proves decryptability by a's key)
//    - share_verification_statements(a, commitments[h], F::ONE) fails
//    => returns h. Honest participant h is blamed for a message they never sent.
```

The primitive gap is encryption.rs:302-317: `sender.to_bytes()` is the only thing tying the PoP to an identity, and the signer picks it freely.
