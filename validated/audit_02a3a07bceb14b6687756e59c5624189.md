Note on scope: this analog is unrelated to the smart-contract `MIN_AMOUNT` report itself — the report is only used as a "bug-class seed" (a validation/parsing gap that silently corrupts an outcome the user expects to be complete/correct). The closest Desktop analog is in the AI-assisted merge-conflict resolution pipeline, where a naive, unauthenticated text-pattern scan for git conflict markers can misidentify attacker-supplied content as a real conflict and let the model's output silently overwrite it.

### Title
Copilot conflict-marker parser treats any `<<<<<<<`/`=======`/`>>>>>>>`-shaped text as a real git conflict, letting a malicious branch/file trigger silent content substitution during AI conflict resolution - (File: `app/src/lib/copilot-conflict-context.ts`, `app/src/lib/copilot-conflict-resolution.ts`)

### Summary
`extractConflictHunks` and `reassembleResolvedFile` both identify conflict boundaries purely by regex matching lines that look like `<<<<<<< `, `=======`, `>>>>>>> ` (and `|||||||` for diff3), with no verification that these lines were actually emitted by git for a real merge conflict at that location. [1](#0-0) [2](#0-1) 
Because the two functions apply the exact same line-scanning algorithm to the same on-disk content, hunk counts stay internally consistent, so `validateResolutionPaths`'s count check does not catch the discrepancy. [3](#0-2) 
Any file that legitimately contains text shaped like a marker triple (documentation, sample fixtures, README snippets showing conflict markers, generated diffs embedded as text, etc.) that an attacker controls on a branch/PR being merged will be parsed as a genuine conflict hunk, sent to the model, and — critically — the model's fabricated "resolution" for that phantom hunk is spliced directly into the file on disk in place of the attacker's/legitimate original text.

### Finding Description
`extractConflictHunks` walks the file content line by line and opens a hunk the moment it sees a line matching `^<{7}(?:\s|$)`, closes it at the next `^>{7}(?:\s|$)`, with an optional `=======`/`|||||||` in between — with no cross-check against git's actual conflict state (e.g., `git diff --check`, `.git/MERGE_MSG`, or the file's real `<<<<<<< HEAD` / `>>>>>>> branch` labels). [4](#0-3) 
This function is only invoked for files git already flagged as conflicted, but it scans the *entire* file content, not just the actual conflicted regions, so any additional marker-shaped text elsewhere in the same file is captured as an extra "hunk" and forwarded to the model as if it were a real conflict. [5](#0-4) 

`reassembleResolvedFile` performs the mirror operation when writing the model's output back to disk: it re-scans the same raw content with the identical marker regexes and replaces each detected marker block with the corresponding model-provided `resolvedContent`, matched purely by *ordinal position*, not by verified association with an actual git conflict. [6](#0-5) 
Because both stages use the same naive matching, the hunk counts line up and `validateResolutionPaths` sees no mismatch — the guard only checks *count*, not *authenticity*, of each hunk. [7](#0-6) 

Attack path: an attacker who controls a branch, fork, or PR that the victim merges/rebases/cherry-picks (the valid-impact "attacker controls a cloned/fetched repository" primitive) crafts a file containing a marker-shaped text block (e.g. `<<<<<<< example\n=======\n>>>>>>> example` inside a comment, string literal, markdown snippet, or fixture) placed anywhere in a file that *also* has a real, unrelated git conflict elsewhere. When the victim invokes AI conflict resolution:
1. `extractConflictHunks` extracts the attacker's fake block as an additional "Conflict N of M" and includes it in the prompt sent to the model. [8](#0-7) 
2. The model, per the system prompt, is instructed to resolve every listed conflict and its response is spliced back in automatically — the model has no way to know the "conflict" is fabricated text rather than a real merge conflict. [9](#0-8) 
3. `reassembleResolvedFile` replaces the attacker's literal text block with the model's (unrelated, hallucinated) output, and this becomes the file content that gets written and ultimately staged/committed by the user without any real conflict having existed there. [10](#0-9) 

### Impact Explanation
This results in silent corruption of what the user commits: content that was never actually in conflict (attacker-controlled bytes, which could be a legitimate-looking config value, security-relevant literal, or license/notice text) is silently replaced by AI-generated text chosen without any real ground truth, and the surrounding diff review UX treats this as a normal AI-assisted conflict resolution rather than an anomaly. Depending on what the attacker seeds near the fake marker (e.g., a fake conflict wrapping an important constant, credential placeholder, or dependency pin) the model's fabricated replacement can differ arbitrarily from both the "ours" and "theirs" content, and the user is likely to accept it since the dialog's premise is "AI resolved N conflicts" rather than "verify this specific hunk existed."

### Likelihood Explanation
Requires no special access beyond contributing a branch/PR/fork that the victim later merges/rebases/cherry-picks with AI conflict resolution enabled, and a real (unrelated) conflict must exist somewhere in the target file to put it through this pipeline at all — a realistic condition in any actively-developed shared file. The marker regexes (`^<{7}(?:\s|$)`, `^={7}$`, `^>{7}(?:\s|$)`) are permissive enough to be triggered by benign-looking content (git tutorials, test fixtures for merge-conflict tooling, ASCII banners) that an attacker can plant deliberately.

### Recommendation
Anchor hunk extraction/reassembly to the file's verified real conflict regions rather than raw regex scanning of arbitrary file content — e.g., derive hunk boundaries from `git diff --check`/`git merge-file` output, or validate that each detected marker triple corresponds to an actual unmerged path region reported by git status/index, and reject or flag any marker-shaped block that doesn't match. At minimum, add a sanity check that the hunk count derived from `extractConflictHunks` matches an independent conflict count for the same file (e.g., from `getFilesWithConflictMarkers` in `app/src/lib/git/diff-check.ts`, which already parses `git diff --check` output) before sending anything to the model. [11](#0-10) 

### Proof of Concept
1. On a malicious branch, create/modify a file so it contains, outside any real conflicted region: a comment block with literal lines `<<<<<<< example`, `=======`, `>>>>>>> example`, e.g. inside a code comment documenting how git conflicts look.
2. Ensure the same file also has a genuine conflicting change elsewhere relative to the victim's branch (so the file is flagged as conflicted by git).
3. Get the victim to merge/rebase/cherry-pick this branch in GitHub Desktop and invoke AI conflict resolution.
4. Observe that `extractConflictHunks` reports one extra hunk for the fake marker block (verify via the prompt/log or by counting `### Conflict N of M` sections), and after resolution, `reassembleResolvedFile` has replaced the attacker's literal comment text with the model's generated content — a change with no corresponding real git conflict, applied and offered for staging/commit without indication that it originated from non-conflicting content.

export function extractConflictHunks(
  fileContent: string,
  contextLines: number = 3
): ReadonlyArray<IConflictHunk> {
  const lines = fileContent.split(/\r?\n/)
  const hunks: Array<IConflictHunk> = []

  let i = 0
  while (i < lines.length) {
    if (!oursMarker.test(lines[i])) {
      i++
      continue
    }

    const oursStart = i + 1
    const oursLines: Array<string> = []
    const baseLines: Array<string> = []
    let hasBase = false
    const theirsLines: Array<string> = []
    let hunkEnd = -1

    i = oursStart
    // Collect ours content
    while (i < lines.length) {
      if (baseMarker.test(lines[i])) {
        hasBase = true
        i++
        break
      }
      if (separatorMarker.test(lines[i])) {
        i++
        break
      }
      oursLines.push(lines[i])
      i++
    }

    // If diff3, collect base content until separator
    if (hasBase) {
      while (i < lines.length) {
        if (separatorMarker.test(lines[i])) {
          i++
          break
        }
        baseLines.push(lines[i])
        i++
      }
    }

    // Collect theirs content until closing marker
    while (i < lines.length) {
      if (theirsMarker.test(lines[i])) {
        hunkEnd = i
        i++
        break
      }
      theirsLines.push(lines[i])
      i++
    }

    // If we never found the closing marker, skip this malformed hunk
    if (hunkEnd === -1) {
      continue
    }

export function validateResolutionPaths(
  resolutions: ReadonlyArray<IRawFileResolution>,
  expectedFiles: ReadonlyArray<IFileConflictContext>
): void {
  const expectedPaths = new Set(expectedFiles.map(f => f.path))
  const expectedHunkCounts = new Map(
    expectedFiles.map(f => [f.path, f.hunks.length])
  )
  const returnedPaths = new Set(resolutions.map(r => r.path))

  for (const path of returnedPaths) {
    if (!expectedPaths.has(path)) {
      throw new CopilotValidationError(
        `Copilot returned resolution for unexpected file: ${path}`
      )
    }
  }

  if (returnedPaths.size !== resolutions.length) {
    throw new CopilotValidationError(
      'Copilot returned duplicate file paths in resolutions'
    )
  }

  const missingPaths: Array<string> = []
  for (const path of expectedPaths) {
    if (!returnedPaths.has(path)) {
      missingPaths.push(path)
    }
  }
  if (missingPaths.length > 0) {
    throw new CopilotValidationError(
      `Copilot did not return resolutions for: ${missingPaths.join(', ')}`
    )
  }

  for (const resolution of resolutions) {
    // Delete-vs-modify resolutions use action instead of hunks — skip count check
    if (resolution.action !== undefined) {
      continue
    }
    const expectedCount = expectedHunkCounts.get(resolution.path) ?? 0
    if (resolution.hunks.length !== expectedCount) {
      throw new CopilotValidationError(
        `Copilot returned ${resolution.hunks.length} hunk(s) for "${resolution.path}" but expected ${expectedCount}`
      )
    }
  }

export function reassembleResolvedFile(
  rawContent: string,
  hunkResolutions: ReadonlyArray<IHunkResolution>
): string {
  const eol = rawContent.includes('\r\n') ? '\r\n' : '\n'
  const lines = rawContent.split(/\r?\n/)
  const resultLines: Array<string> = []
  let hunkIndex = 0
  let i = 0

  while (i < lines.length) {
    if (reassemblyOursMarker.test(lines[i])) {
      // Look ahead to verify this is a well-formed conflict block:
      // must have a ======= separator and a >>>>>>> closing marker.
      let hasSeparator = false
      let closingIndex = -1
      for (let j = i + 1; j < lines.length; j++) {
        if (reassemblySeparatorMarker.test(lines[j])) {
          hasSeparator = true
        } else if (reassemblyTheirsMarker.test(lines[j])) {
          closingIndex = j
          break
        }
      }

      if (!hasSeparator || closingIndex === -1) {
        // Malformed marker — copy through as regular content
        resultLines.push(lines[i])
        i++
        continue
      }

      // Skip through the entire conflict marker block
      i = closingIndex + 1

      // Splice in the resolved content for this hunk
      if (hunkIndex < hunkResolutions.length) {
        const resolved = hunkResolutions[hunkIndex].resolvedContent
        if (resolved.length > 0) {
          resultLines.push(...resolved.split(/\r?\n/))
        }
      }
      hunkIndex++
    } else {
      resultLines.push(lines[i])
      i++
    }
  }

  return resultLines.join(eol)
}

export async function getFilesWithConflictMarkers(
  repositoryPath: string
): Promise<Map<string, number>> {
  const { stdout } = await git(
    ['diff', '--check'],
    repositoryPath,
    'getFilesWithConflictMarkers',
    { successExitCodes: new Set([0, 2]) }
  )

  const files = new Map<string, number>()
  const matches = stdout.matchAll(/^(.+):\d+: leftover conflict marker/gm)

  for (const [, path] of matches) {
    files.set(path, (files.get(path) ?? 0) + 1)
  }

  return files
}
