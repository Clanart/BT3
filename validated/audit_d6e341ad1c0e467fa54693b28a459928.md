### Title
`compute_v2_review_set` drops dangerous changes when HEAD moves non-linearly (checkout/reset to an unrelated ref), letting Stop-hook review silently skip committed malicious content - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`compute_v2_review_set` only folds committed changes into the reviewable `dirty_now` set when `head_at_capture` is an ancestor of the new `HEAD` [1](#0-0) . If the working tree moves to an unrelated commit (e.g. via `git checkout <ref>` or `git reset --hard <ref>`) whose tree already contains the dangerous content, the working tree becomes clean relative to the new `HEAD`, `dirty_now` ends up empty, and the intersection with `changed_since` yields an empty review set — hiding the change entirely even though it materially differs from the session's `baseline_sha`.

### Finding Description
`compute_v2_review_set` derives the Stop-hook review window as `review_set = dirty_now ∩ changed_since` [2](#0-1) .

- `dirty_now` is `tracked_dirty | new_untracked` from `git status --porcelain`, plus (only when `head_at_capture` is an ancestor of `current_head`) the name-only diff of `head_at_capture..HEAD` [3](#0-2) .
- `changed_since` is the diff of the current working tree against `baseline_sha` (the session-start stash SHA) [4](#0-3) .

The ancestor guard exists to keep `dirty_now`'s committed-diff term "immune to checkout/pull ballooning" per the docstring [5](#0-4) , but it has an unhandled side effect: if a turn performs `git checkout <ref>` or `git reset --hard <ref>` to a commit that is **not** a descendant of `head_at_capture` (`_is_ancestor` returns `False` via `git merge-base --is-ancestor` [6](#0-5) ), then:
1. `dirty_now`'s committed-diff term is never added (the `if` branch is skipped) [7](#0-6) .
2. The checkout/reset makes the worktree exactly match the new `HEAD`, so `git status --porcelain` reports it as clean, i.e. `tracked_dirty = ∅`.
3. `dirty_now` collapses to `∅` (assuming no untracked files), while `changed_since` (computed against `baseline_sha`, unaffected by the ref move) still correctly shows the dangerous file as different from the session baseline.
4. `review_set = ∅ ∩ changed_since = ∅` — the dangerous, already-committed file is completely excluded from the Stop-hook's reviewed set and from `get_git_diff`'s pathspec, so it is never surfaced to the security reviewer.

This is a real, git-native operation ("standard command inputs / normal git operations in a cloned repo" per the question) — no privilege escalation, mock mutation, or admin access is required. An attacker who can influence what git ref gets checked out during a Claude turn (e.g. repository instructions, a tag/branch name in a script, a `git pull`/`git checkout` invoked as part of normal automation) that lands on a commit already containing the dangerous payload defeats the review entirely.

### Impact Explanation
This breaks the stated invariant ("an attacker must not hide a dangerous change by shifting it outside the computed review window"). Since the Stop-hook's `review_set` gates which files get diffed and sent to the security reviewer/approval flow, a dangerous change that reaches this state is executed/persisted without any Claude Code security review, i.e. unauthorized local command/content execution that bypasses the approval/deny pipeline the security-guidance plugin is meant to enforce.

### Likelihood Explanation
Feasible with only standard git operations available to any user/automation running inside the target repo clone: create or point to a commit/ref containing the dangerous content, then have the turn execute `git checkout <ref>` or `git reset --hard <ref>` where `<ref>` is not a descendant of the turn's `head_at_capture`. This is a common pattern (switching branches, checking out a tag/PR ref, resetting to `origin/main` after a rebase) and requires no elevated privileges — repeatable every time HEAD moves non-linearly relative to the session baseline while leaving the working tree clean.

### Recommendation
Do not gate the committed-diff term purely on ancestry combined with a clean-worktree check. Instead, when `head_at_capture != current_head`, always compute the diff of the current worktree against `baseline_sha` (already done as `changed_since`) independent of `dirty_now`'s clean/dirty status, or explicitly detect non-ancestor `HEAD` moves and union in `git diff --name-only baseline_sha HEAD` (tree vs tree) regardless of working-tree cleanliness, rather than relying on `tracked_dirty` being non-empty. Effectively, `review_set` should never require `dirty_now` to be non-empty for files whose committed tree content diverges from `baseline_sha` — the intersection logic should be replaced with a union-of-evidence approach that can't be nulled out by a clean checkout.

### Proof of Concept
Integration test outline (pytest style) using a real git repo fixture:
1. Init repo, commit `safe.py` on commit `A`. Set `head_at_capture = A`; `baseline_sha = A` (clean tree at session start).
2. In a detached/unrelated branch, create commit `B` (not descendant of `A`) that adds `dangerous.py` with attacker payload.
3. Simulate the turn's git action: `git checkout B` (or `git reset --hard B`), leaving the worktree clean relative to `B`.
4. Call `compute_v2_review_set(cwd, baseline_sha=A, head_at_capture=A)`.
5. Assert `_is_ancestor(repo, A, B) is False`.
6. Assert `review_paths` (the first return value) **should** contain `dangerous.py`, and demonstrate that the current implementation returns `[]` (empty review set) — proving the dangerous file is skipped/hidden.
7. Contrast with the same scenario where `B` is a genuine descendant of `A` (normal linear commit) — confirm `review_set` correctly includes `dangerous.py`, isolating the bug to the non-ancestor HEAD-move case.

    diff_base = "HEAD"
    current_head = _git_rev_parse_head(repo)
    if (head_at_capture and current_head and head_at_capture != current_head
            and _is_ancestor(repo, head_at_capture, current_head)):

        diff_base = head_at_capture

    # changed_since: tracked files vs the stash baseline (no temp index — the
    # stash never contained untracked files anyway), then union with
    # currently-untracked. The previous `include_untracked=True` arm cost a
    # full `git add -N .` (slow in large repos) per call to surface
    # untracked files in the diff output — but `git diff <stash>` already
    # lists them as "only in worktree" without that, and we have the explicit
    # set from status regardless.
    if baseline_sha:
        changed_since = _git_name_only(repo, baseline_sha)
        if changed_since is not None:
            changed_since |= new_untracked
    else:
        changed_since = None
    # changed_since is None on missing baseline OR on git error (e.g. the
    # dangling stash SHA was pruned). Either way, don't intersect with ∅ —
    # that would silently zero the review set. Fall back to dirty_now.
    review_set = (dirty_now & changed_since) if changed_since is not None else dirty_now

def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
