### Title
Out-of-bounds indexing panic on malformed preprocess/share vectors in Bitcoin TransactionSignMachine - ([File: networks/bitcoin/src/wallet/send.rs])

### Summary
Analogous to CVE-2023-3164 (heap-buffer-overflow → DoS via crafted input), `TransactionSignMachine::sign` and `TransactionSignatureMachine::complete` index into attacker-supplied `Vec`s deserialized from untrusted bytes, with no length validation against the number of transaction inputs. A peer can send a truncated/empty per-input preprocess or share vector and deterministically panic the signer.

### Finding Description
`TransactionSignMachine::read_preprocess` parses `Vec<Preprocess<Secp256k1, ()>>` per participant by reading exactly `self.sigs.len()` inner preprocesses only when the peer's bytes are well-formed — but nothing enforces that the *outer* structure each participant supplies contains `sigs.len()` entries. In `sign`, the code indexes `commitments[c]` for each input `c` in `0 .. self.sigs.len()`; if a participant's preprocess `Vec` has fewer elements, `commitments[c]` panics with an out-of-bounds index [1](#0-0) . Symmetrically, `complete` calls `shares.remove(0)` per input; an empty share `Vec` (readable via `TransactionSignatureMachine::read_share` on a truncated stream yields `io::Error` — but a `Vec` shorter than `sigs.len()` is accepted at the type level since it's just `Vec<SignatureShare>`) panics on `remove(0)` [2](#0-1) . The inner `SignatureShare`/`Preprocess` reads themselves are fixed-size and safe [3](#0-2) , but the outer `Vec` length is attacker-controlled.

The reachability path: an unprivileged cosigner sends preprocess/share bytes → local node calls `read_preprocess`/`read_share` (which return `Ok` for any shorter `Vec` the framing produces) → `sign`/`complete` indexes past the end → panic. This is the same "crafted input causes out-of-bounds memory access / crash" class as the tiffcrop bug: a length field trusted without a bounds check.

Additionally, `SchnorrkelHram::hram` slices `m[0 .. 4]` and `m[4 .. (4 + ctx_len)]` on the message being hashed; a message shorter than 4 bytes or with a forged length prefix panics [4](#0-3)  — but `msg` there is locally generated, so the send.rs path is the cleaner analog.

### Impact Explanation
Denial of service: any participant in a Bitcoin multisig signing session can crash every other signer's `sign`/`complete` call by submitting a syntactically parseable but under-length preprocess/share vector. Repeated attempts abort signing rounds, halting fund movement — matching the CVE's availability-only impact profile.

### Likelihood Explanation
Reachable by any unprivileged party able to submit preprocess/share messages to a signer (exactly the threat model FROST preprocesses are designed for over authenticated channels). Requires only sending a truncated encoding; no cryptographic work needed. Medium rather than High because it yields a crash/abort rather than an invalid signature or key leakage.

### Recommendation
In `TransactionSignMachine::sign`, validate `commitments.len() == self.sigs.len()` for each participant's preprocess vector before indexing; in `TransactionSignatureMachine::complete`, check `shares.len() == self.tx.input.len()` before `remove(0)` (or drain the Vec once). Return `FrostError::InvalidParticipant`/a dedicated error instead of panicking.

### Proof of Concept
```rust
// In a signing session with a 2-input SignableTransaction:
// 1. Attacker produces their own valid (SignMachine, Vec<Preprocess>) via
//    TransactionMachine::preprocess, then truncates the outer Vec to 1 element
//    (or re-encodes with fewer inner preprocesses).
// 2. Victim calls sign_machine.read_preprocess(&mut bytes) -> Ok(preprocess)
//    since read_preprocess only reads what each sig machine needs from *its own*
//    stream; a per-participant Vec with 1 element is accepted into the
//    HashMap<Participant, Vec<Preprocess>>.
// 3. Victim calls sign_machine.sign(commitments, b""):
//    at send.rs:368, `commitments[c]` with c == 1 indexes a Vec of len 1
//    -> thread panics (index out of bounds), aborting the signing attempt.
// Equivalent: a Vec<SignatureShare> of length 0 passed to complete() panics on
// shares.remove(0) at send.rs:419.
```
