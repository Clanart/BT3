### Title
Missing zero-value validation for `kip71.gastarget` governance parameter allows chain-halting division-by-zero panic - (File: `params/kip71_config.go`)

### Summary
The `kip71.gastarget` governance parameter is used as a divisor when computing the next block's base fee under KIP-71/Magma, but unlike its sibling parameter `kip71.basefeedenominator`, it has no `FormatChecker` that rejects a zero value. A governance vote (or GovParam contract update) setting `GasTarget = 0` will cause every node's base-fee calculation to panic on division by zero, halting block production/validation network-wide.

### Finding Description
`Kip71GasTarget` is registered with `FormatChecker: noopFormatChecker`, which accepts any `uint64` value including `0`: [1](#0-0) 

By contrast, `Kip71BaseFeeDenominator` explicitly guards against a zero value: [2](#0-1) 

The `GasTarget` value flows unchecked into `ParamSet.ToKip71Config()` and then into `NextMagmaBlockBaseFee`, where it is used both as a divisor and as a comparison target: [3](#0-2) 

```go
gasTarget := kc.GasTarget
...
gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
y := x.Div(x, new(big.Int).SetUint64(gasTarget))
``` [4](#0-3) 

If `gasTarget == 0`, `new(big.Int).SetUint64(0)` is passed to `big.Int.Div`, which panics on division by zero in Go's `math/big` package. This function is invoked from `VerifyMagmaHeader`, which every node calls while validating each new block header's base fee: [5](#0-4) 

The parameter passes through the same unguarded path in both header governance (`checkConsistency` explicitly allows `Kip71GasTarget` with no bound check) and contract governance (`GovParam.setParam`, KIP-81), since `ParamSet.Set`/`contractGovModule.GetParamSet` apply no additional bound: [6](#0-5) [7](#0-6) 

This is the direct analog of the reported bug class: an under-constrained, governance-settable numeric parameter (like `daPriceCurveLength`/`daDropInterval`) that is used as a divisor/denominator in a price/fee curve calculation without being bounded away from zero, leading to a revert (here, a Go panic) in the core pricing routine.

### Impact Explanation
Once `GasTarget = 0` becomes effective at a block boundary, every full node, CN, PN, and EN attempting to compute or verify the Magma base fee for that block will panic in `NextMagmaBlockBaseFee`/`VerifyMagmaHeader`. Because base fee is computed for every block post-Magma HF, this results in a chain-wide halt (all honest nodes crash or reject blocks), a critical denial-of-service on block production and consensus — exactly the kind of concrete, network-affecting impact the review criteria require (state divergence / inability to process valid blocks).

### Likelihood Explanation
The value is only reachable through governance (header governance vote by a CN/validator, or `GovParam.setParam`/`setParamIn` by a GC member via KIP-81 contract governance), so it requires a governance-privileged actor. However, no format/consistency check currently rejects `0`, and the closely related `BaseFeeDenominator` parameter already demonstrates the team's awareness that divisor-parameters need a `!= 0` guard, making this a straightforward oversight rather than a hypothetical edge case. A single accidental or malicious vote (e.g., a copy-paste of the wrong default value, or a compromised/malicious GC member) is sufficient to trigger the panic at the next base-fee computation.

### Recommendation
Add an explicit `FormatChecker` for `Kip71GasTarget` that rejects zero (and any other config-breaking edge values), mirroring the existing check for `Kip71BaseFeeDenominator`:
```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0
    },
    ...
},
```
Additionally, consider adding a defensive fallback in `NextMagmaBlockBaseFee` (similar to the existing `BaseFeeDenominator == 0` fallback) so that a zero `GasTarget` sourced from stale/invalid contract-governance data cannot crash node execution even if the format checker is bypassed.

### Proof of Concept
1. A CN/validator submits (or a compromised GC member via `GovParam.setParam`) a header-governance vote `kip71.gastarget = 0`.
2. `NewVoteData`/`checkConsistency` accept the vote because `Kip71GasTarget`'s `FormatChecker` is `noopFormatChecker` and `checkConsistency` performs no additional validation for this key (`kaiax/gov/headergov/impl/header.go` lines 214-220).
3. Once the vote is finalized and the parameter becomes effective, `ParamSet.ToKip71Config()` propagates `GasTarget: 0` into `KIP71Config`.
4. At the next block, every node calls `VerifyMagmaHeader` → `NextMagmaBlockBaseFee`, which executes `x.Div(x, new(big.Int).SetUint64(0))` (either in the `parentGasUsed > gasTarget` or `parentGasUsed < gasTarget` branch, since `parentGasUsed == 0` is the only case avoiding division), causing a runtime panic and crashing all consensus-participating nodes simultaneously.

func (kc *KIP71Config) VerifyMagmaHeader(headerBaseFee *big.Int, parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) error {
	if headerBaseFee == nil {
		return fmt.Errorf("header is missing baseFee")
	}
	// Verify the baseFee is correct based on the parent header.
	expectedBaseFee := kc.NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)
	if headerBaseFee.Cmp(expectedBaseFee) != 0 {
		return fmt.Errorf("invalid baseFee: have %s, want %s, parentBaseFee %s, parentGasUsed %d",
			headerBaseFee, expectedBaseFee, parentHeaderBaseFee, parentHeaderGasUsed)
	}
	return nil
}

func (c *contractGovModule) GetParamSet(blockNum uint64) gov.ParamSet {
	m, err := c.contractGetAllParamsAt(blockNum)
	if err != nil {
		return *gov.GetDefaultGovernanceParamSet()
	}

	ret := *gov.GetDefaultGovernanceParamSet()
	for k, v := range m {
		err = ret.Set(k, v)
		if err != nil {
			return *gov.GetDefaultGovernanceParamSet()
		}
	}

	return ret
}
