### Title
Actual fee silently exceeds the quoted `needed_fee` when the change output is dropped as dust - ([File: networks/bitcoin/src/wallet/send.rs](networks/bitcoin/src/wallet/send.rs))

### Summary
`SignableTransaction::new` quotes a fee (`needed_fee = fee_per_vbyte * vbytes`) and records it in the returned struct, but the *actual* fee is defined as `sum(inputs) - sum(outputs)` (`fee()`). When a `change` script is supplied yet the leftover would fall below `DUST`, no change output is created and the entire leftover — beyond the quoted `needed_fee` — is silently burned as fee. The caller's agreed-upon fee rate is therefore not what is actually paid: the charged fee can exceed `needed_fee` by up to `DUST + fee_for_change_output`, with no error, warning, or bound enforced against the quote.

### Finding Description
In `SignableTransaction::new`, the fee is first quoted from the no-change vbytes estimate (`needed_fee = fee_per_vbyte * vbytes`, send.rs:204-206). Then, if `change` is `Some`, the code recomputes `fee_with_change` and only appends the change output when `input_sat - payment_sat - fee_with_change >= DUST` (send.rs:223-235). If the leftover is below `DUST`, the change output is dropped, but `needed_fee` retains the lower no-change quote while the true fee becomes `input_sat - payment_sat` — the quoted fee plus the entire sub-dust leftover, plus the difference between `fee_with_change` and the non-change `needed_fee`.

This mirrors the external report's class: a fee/price the user implicitly agreed to at "listing" time (the `fee_per_vbyte`-derived `needed_fee` committed in the struct) diverges from the amount actually charged at execution, with the protocol retaining the difference. The struct even exposes both `needed_fee()` ("the fee necessary ... specified at construction") and `fee()` ("the fee this transaction will use"), documenting that they may diverge — but nothing bounds the divergence or lets the caller reject it before signing. `TransactionSignMachine::sign` then produces shares committing to this overcharging transaction.

### Impact Explanation
Funds are spent at a higher fee than the rate the caller specified and than `needed_fee()` reports. For a threshold wallet, every signer who checks `needed_fee()` as the agreed fee will sign a transaction whose real fee is strictly higher — an unintended payment of up to ~`DUST` + the change-output's marginal fee per transaction, burned to miners. For Serai's UTXO flows this misattributes value and breaks fee accounting (`needed_fee` is used by callers as the amortized fee basis).

### Likelihood Explanation
Reachable by anyone supplying `inputs`, `payments`, `change`, and `fee_per_vbyte` to `SignableTransaction::new`: choose `input_sat - payment_sat - fee_with_change` in `[0, DUST)`. No privileged position required; the caller (or the party assembling the plan) controls all inputs. It triggers deterministically whenever the leftover lands in the dust band.

### Recommendation
When the change output is dropped, either (a) return an error if the resulting true fee would exceed the quoted `needed_fee`, or (b) recompute and store `needed_fee = fee()` so callers can detect and reject the divergence before signing. At minimum, `multisig`/signing should assert `self.fee() <= self.needed_fee` or the excess should be bounded by an explicit tolerance rather than silently absorbed.

### Proof of Concept
```rust
// networks/bitcoin/src/wallet/send.rs
// inputs = 10_000 sats, payment = 9_000 sats, change = Some(script), FEE = 20 sat/vb
// Suppose fee_with_change pushes (10_000 - 9_000 - fee_with_change) < DUST (546):
//   -> change branch at send.rs:223-235 is skipped, needed_fee stays fee_per_vbyte * vbytes
let st = SignableTransaction::new(inputs, &payments, Some(change), None, FEE).unwrap();
assert!(st.fee() > st.needed_fee()); // charged fee exceeds the quoted fee
// The excess (up to ~DUST + change-output fee) is paid to miners with no error.
```
