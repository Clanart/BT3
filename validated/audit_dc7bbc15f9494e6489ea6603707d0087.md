### Title
Malformed Ed448 commitments bypass PedPoP proofs of knowledge via accepted torsion points - (File: crypto/ed448/src/point.rs)

### Summary
Ed448 point decoding accepts non-prime-subgroup points because `Point::is_torsion_free` computes `(-P) + P`, which is always the identity and therefore accepts every decoded point. [1](#0-0) 

An attacker can place a low-order torsion component inside a PedPoP commitment and forge the Schnorr proof of knowledge for that commitment without knowing a discrete logarithm for the malformed point. [2](#0-1) [3](#0-2) 

### Finding Description
`Point::is_torsion_free` is intended to reject Ed448 points outside the prime-order subgroup, but it evaluates `(*self * (Scalar::ZERO - Scalar::ONE)) + self`, equivalent to `(-P) + P`, so every point returns identity. [4](#0-3) 

`GroupEncoding::from_bytes` relies on that check when accepting a decompressed point, so compressed encodings carrying a cofactor component are accepted by `C::read_G`. [5](#0-4) [6](#0-5) 

PedPoP deserializes attacker-controlled commitments through `Commitments::read`, then verifies the Schnorr proof against `msg.commitments[0]` using `batch_verify`. [2](#0-1) [7](#0-6) 

Schnorr verification accepts when `R + cA - sG = 0`, but it does not separately require `A` to be a prime-order point. [8](#0-7) 

Let `G` be the prime-order generator, `T` an order-4 Ed448 torsion point, and `A = xG + T` for attacker-known `x`; there is no scalar `a` satisfying `A = aG` because scalar multiplication by `G` remains in the prime-order subgroup. [9](#0-8) [10](#0-9) 

For a protocol challenge `c`, choose `R = (-c mod 4)T` and `s = cx`; the verification equation becomes `R + cA - sG = (-c mod 4)T + c(xG + T) - cxG = 0`. [8](#0-7) 

Because `c` commits to `R`, the attacker selects one of the four possible `kT` values, computes the resulting `c`, and retries with changed commitment bytes or `x` until `k = -c mod 4`; PedPoP allows this by varying the remaining commitment coefficients included in `cached_msg`. [11](#0-10) [2](#0-1) 

### Impact Explanation
This produces a valid Schnorr proof of possession for a commitment that is not a scalar multiple of the generator, defeating the proof-of-knowledge property used to bind PedPoP participants to committed secret coefficients. [11](#0-10) [3](#0-2) 

The forged proof is accepted through the normal untrusted-byte path: malformed commitment bytes enter `Commitments::read`, `read_G` accepts the torsion-bearing point, and `verify_r1` queues the forged signature for batch verification. [2](#0-1) [12](#0-11) 

This is a forged cryptographic proof rather than a merely malformed encoding because the accepted public key cannot be represented as `aG` for any scalar `a`. [9](#0-8) [10](#0-9) 

### Likelihood Explanation
An unprivileged DKG participant controls the commitment bytes sent to `Commitments::read`, including each encoded group element and the Schnorr proof. [13](#0-12) 

Ed448 has a small cofactor, so the forged-proof condition has only four possible torsion residues; the attacker can vary the commitment bytes or known prime component until the required challenge residue is obtained. [1](#0-0) [11](#0-10) 

The attack does not require malformed encodings to bypass canonicality: the decoded torsion-bearing point serializes back to the same accepted encoding. [6](#0-5) [14](#0-13) 

### Recommendation
Replace `is_torsion_free` with an actual prime-order-subgroup membership test; the current `(-P) + P` expression is tautological and cannot reject any point. [4](#0-3) 

After correcting subgroup validation, keep canonical-encoding validation in `C::read_G` and consider rejecting identity in protocol-specific commitment readers where the protocol requires a nontrivial committed coefficient. [6](#0-5) [15](#0-14) 

### Proof of Concept
1. Select an order-4 Ed448 torsion point `T` and a known scalar `x`.
2. Construct `A = xG + T`, where `G` is the Ed448 generator; encode `A` as the first PedPoP commitment point.
3. Submit the commitment bytes through `Commitments::read`; `C::read_G` accepts `A` because `from_bytes` calls the tautological `is_torsion_free`. [1](#0-0) [2](#0-1) 
4. For each `k in {0,1,2,3}`, set `R = kT` and calculate the PedPoP challenge `c` over the context, participant, `R`, and commitment bytes. [11](#0-10) 
5. When `k = -c mod 4`, submit `(R, s)` with `s = cx`; verification computes `R + cA - sG = (k + c)T = 0`. [8](#0-7) 
6. If the challenge residue does not match, change `x` or another commitment coefficient and repeat; the malformed `A` remains non-prime-order but continues to deserialize successfully. [15](#0-14) [5](#0-4)

impl GroupEncoding for Point {
  type Repr = <FieldElement as PrimeField>::Repr;

  fn from_bytes(bytes: &Self::Repr) -> CtOption<Self> {
    // Extract and clear the sign bit
    let sign = Choice::from(bytes[56] >> 7);
    let mut bytes = *bytes;
    let mut_ref: &mut [u8] = bytes.as_mut();
    mut_ref[56] &= !(1 << 7);

    // Parse y, recover x
    FieldElement::from_repr(bytes).and_then(|y| {
      recover_x(y).and_then(|mut x| {
        x.conditional_negate(x.is_odd().ct_eq(&!sign));
        let not_negative_zero = !(x.is_zero() & sign);
        let point = Point { x, y, z: FieldElement::ONE };
        CtOption::new(point, not_negative_zero & point.is_torsion_free())
      })
    })
  }

  fn from_bytes_unchecked(bytes: &Self::Repr) -> CtOption<Self> {
    Point::from_bytes(bytes)
  }

  fn to_bytes(&self) -> Self::Repr {
    let z = self.z.invert().unwrap();
    let x = self.x * z;
    let y = self.y * z;

    let mut bytes = y.to_repr();
    let mut_ref: &mut [u8] = bytes.as_mut();
    mut_ref[56] |= x.is_odd().unwrap_u8() << 7;
    bytes
