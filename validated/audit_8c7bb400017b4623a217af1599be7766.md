### Title
`ReceivedOutput::read` accepts attacker-controlled offset/script/outpoint with no consistency or ownership validation, letting untrusted bytes fabricate "received" outputs the multisig will try to sign for - ([File: networks/bitcoin/src/wallet/mod.rs])

### Summary
Analogous to the Onyx NFTLiquidation flaw (unvalidated user input inflating a credited amount), `ReceivedOutput::read` deserializes the three fields that fully determine an output's claimed value (`output.value`), its spending key (`offset`, via `key + G*offset`), and its claimed on-chain existence (`outpoint`) from raw bytes with zero validation. Nothing ties the offset to the script, the script to P2TR, or the outpoint to a real UTXO.

### Finding Description
`ReceivedOutput` is the unit by which bitcoin-serai reports "funds received by the multisig." Its reader accepts any scalar offset, any `TxOut` (any `script_pubkey`, any `value`), and any `OutPoint` (networks/bitcoin/src/wallet/mod.rs:122-134). The legitimately constructed path (`Scanner::scan_transaction`, mod.rs:199-214) guarantees the invariant `script_pubkey == p2tr(key + G*offset)`; the deserialized path does not.

The only downstream check is in `SignableTransaction::multisig`, which verifies `p2tr_script_buf(offset.group_key()) == prevout.script_pubkey` (networks/bitcoin/src/wallet/send.rs:276-279). This check is satisfiable by a *forged* object: an attacker who can feed bytes to `ReceivedOutput::read` picks any offset `o`, computes `K' = group_key + G*o` (incrementing `o` until `K'` is even, exactly as `register_offset` does at mod.rs:184-194), and writes the matching P2TR script. The forged output then:

1. Reports `value()`/`balance()` of an arbitrary amount — the processor's `Output::balance()` returns `self.output.value()` verbatim (processor/src/networks/bitcoin.rs:128-130), so an outpoint that doesn't exist (or exists with a different value/script owner) is reported as received funds. Note the sighash commits to the *claimed* prevout value via `Prevouts::All` (send.rs:375), not to any verified on-chain value, so the claimed value is what the protocol accounts for, not what exists.
2. Causes the threshold group to produce a valid BIP-340 signature under `key + o` for a transaction spending a non-existent or non-owned outpoint — a signature over an attacker-influenced input set the honest scan path would never have produced.
3. Can set `offset = 0` with a script for `group_key` itself and an outpoint belonging to a third party's identically-keyed output, misattributing ownership (the scanner's script-only matching, mod.rs:205, provides no defense once bytes are injected).

### Impact Explanation
Funds reported received that are not actually spendable by the group: fabricated `value` inflates credited balances (mirroring the Onyx reward inflation), and the multisig is driven to sign transactions whose inputs don't exist or aren't owned — producing invalid transactions, or signatures committing to attacker-chosen prevout sets. Severity Medium-to-High depending on how much the integrating processor trusts `ReceivedOutput::read` bytes from peers/messages.

### Likelihood Explanation
Exploitable wherever serialized `ReceivedOutput`s cross a trust boundary (coordinator/peer messages, restart deserialization fed by an untrusted store). The requirements listed in scope explicitly name `ReceivedOutput::read` as an untrusted-byte sink. No collusion or key material is needed — only the ability to supply bytes.

### Recommendation
Bind the invariant at construction: store the group key (or key fingerprint) in `ReceivedOutput` and have `read` take the expected key, rejecting inputs where `p2tr_script_buf(key + G*offset) != output.script_pubkey` or where the script isn't P2TR. Treat `outpoint`/`value` as claims requiring on-chain confirmation before being credited or signed over.

### Proof of Concept
```
let o = loop {
  let o = Scalar::random(rng);
  if p2tr_script_buf(group_key + (ProjectivePoint::GENERATOR * o)).is_some() { break o }
};
let forged = ReceivedOutput {
  offset: o,
  output: TxOut { value: Amount::from_sat(1_000_000),
                  script_pubkey: p2tr_script_buf(group_key + G*o).unwrap() },
  outpoint: OutPoint::new(attacker_chosen_txid, 0),
};
let bytes = forged.serialize();
let ro = ReceivedOutput::read(&mut bytes.as_slice()).unwrap(); // accepted
// SignableTransaction::new(vec![ro], &payments, ...).multisig(&keys) returns Some(..)
// -> group signs a spend of a possibly non-existent outpoint credited at 1M sats
```
