### Title
Consumed FROST cached preprocesses are never revoked — identical nonces are re-derived for every signing attempt under the same context, enabling secret share recovery - (File: coordinator/src/tributary/signing_protocol.rs)

### Summary
CVE-2022-30256 describes a "ghost" condition: a revoked/expired resource remains resolvable because the resolver caches it and never enforces revocation. The Serai analog lives in `SigningProtocol::preprocess_internal`: a `CachedPreprocess` seed is persisted under `CachedPreprocesses: (context) -> [u8; 32]` and is loaded on *every* call to `preprocess_internal` / `share_internal` for that context, but is **never deleted or rotated after use**. FROST preprocesses MUST be single-use; here a consumed preprocess remains "resolvable" (re-derivable) indefinitely, exactly like a revoked domain staying resolvable from cache.

### Finding Description
In `preprocess_internal`, the flow is:

1. If `CachedPreprocesses::get(txn, &context)` is empty, a fresh `AlgorithmMachine::new(...).preprocess(&mut OsRng)` is run, its seed is XOR-encrypted and stored under `context`. [1](#0-0) 
2. The stored seed is then read back, decrypted, and passed to `AlgorithmSignMachine::from_cache`. [2](#0-1) 
3. `share_internal` calls `self.preprocess_internal(participants).0` again for the share phase, re-deriving the machine from the same stored seed. [3](#0-2) 

There is no `txn.del` / removal of the `CachedPreprocesses` entry after `from_cache` — the seed persists and deterministically regenerates the same nonces via `ChaCha20Rng::from_seed(*seed.0)` in `seeded_preprocess`. [4](#0-3) 

The library contract is explicit that reuse is fatal: "A preprocess MUST only be used once. Reuse will enable third-party recovery of your private key share" and "After this, the preprocess must be deleted so it's never reused." [5](#0-4) [6](#0-5)  The spec repeats this: "Reusing preprocesses would enable a third-party to recover your private key share." [7](#0-6) 

Because `sign()` commits to `msg` only at share time (`machine.sign(preprocesses, msg)`), two signing rounds that reuse the same `context` but bind different `msg` values produce two shares over identical nonce scalars `(d, e)` — classic Schnorr/FROST nonce reuse, from which `d + ρe` and hence the secret share are recovered algebraically.

### Impact Explanation
Reuse of FROST nonces across two distinct messages yields two linear equations in the same nonce scalars, allowing an unprivileged participant (or anyone observing two shares/preprocesses on the authenticated channel) to solve for the victim's nonce pair and, since shares are `s = d + e·ρ·λ ... + c·x_i`-structured, recover the victim's private key share — compromising the MuSig/FROST cosigning key used for `Sign`/`CosignPreprocess`/`SlashReport`/`BatchPreprocess` tributary transactions. This satisfies the "key share recovery" acceptance criterion.

### Likelihood Explanation
The seed is deterministic and keyed solely by `context`. Any path that invokes `share_internal` (or `preprocess_internal`) twice under the same `context` — e.g., a retried signing attempt that does not bump the attempt/context encoding, a crash-and-resume between the preprocess publish and `sign()` completion, or two distinct messages routed through one context label — reuses nonces. The persistence layer actively guarantees the "revoked" preprocess remains resolvable after reboot, mirroring the CVE's long-lived cache behavior. Note: whether a repeated `context` with differing `msg` is reachable depends on how callers encode `C` (attempt counters etc.) — I could not fully verify every call site, so likelihood is Moderate rather than certain.

### Recommendation
Delete the `CachedPreprocesses` entry in the same DB transaction that consumes it (i.e., inside `share_internal` before/after `from_cache`), so a consumed preprocess is cryptographically revoked rather than re-derivable. Alternatively, derive the seed as `H(stored_seed || attempt/msg-binding)` or persist a monotonic counter mixed into the seed, and assert uniqueness of `(context, msg)` pairs before signing.

### Proof of Concept
1. Validator processes a `SignData`/share request under context `ctx`, calling `share_internal(participants, preprocesses, msg1)` — internally `preprocess_internal` loads stored seed `s`, produces nonces `(d, e)`, emits share `share1` for `msg1`. [8](#0-7) 
2. A second share request under the same `ctx` with `msg2 ≠ msg1` (e.g., repeated attempt where `context.encode()` is unchanged) reloads the same undeleted `s`, regenerating identical `(d, e)` and emitting `share2`. [9](#0-8) 
3. With `share_i = d + e·ρ_i·λ + c_i·x_i` style FROST share equations and `ρ` bound to the (identical) published commitments, the attacker solves the two-equation system for `d + ρe` and then the secret share `x_i`, recovering the validator's FROST share and enabling forgery against the tributary cosigning key. [10](#0-9)

```rust
  fn preprocess_internal(
    &mut self,
    participants: &[<Ristretto as Ciphersuite>::G],
  ) -> (AlgorithmSignMachine<Ristretto, Schnorrkel>, [u8; 64]) {
    // Encrypt the cached preprocess as recovery of it will enable recovering the private key
    // While the DB isn't expected to be arbitrarily readable, it isn't a proper secret store and
    // shouldn't be trusted as one
    let mut encryption_key = {
      let mut encryption_key_preimage =
        Zeroizing::new(b"Cached Preprocess Encryption Key".to_vec());
      encryption_key_preimage.extend(self.context.encode());
      let repr = Zeroizing::new(self.key.to_repr());
      encryption_key_preimage.extend(repr.deref());
      Blake2s256::digest(&encryption_key_preimage)
    };
    let encryption_key_slice: &mut [u8] = encryption_key.as_mut();

    let algorithm = Schnorrkel::new(b"substrate");
    let keys: ThresholdKeys<Ristretto> =
      musig(musig_context(self.spec.set().into()), self.key.clone(), participants)
        .expect("signing for a set we aren't in/validator present multiple times")
        .into();

    if CachedPreprocesses::get(self.txn, &self.context).is_none() {
      let (machine, _) =
        AlgorithmMachine::new(algorithm.clone(), keys.clone()).preprocess(&mut OsRng);

      let mut cache = machine.cache();
      assert_eq!(cache.0.len(), 32);
      #[allow(clippy::needless_range_loop)]
      for b in 0 .. 32 {
        cache.0[b] ^= encryption_key_slice[b];
      }

      CachedPreprocesses::set(self.txn, &self.context, &cache.0);
    }

    let cached = CachedPreprocesses::get(self.txn, &self.context).unwrap();
    let mut cached: Zeroizing<[u8; 32]> = Zeroizing::new(cached);
    #[allow(clippy::needless_range_loop)]
    for b in 0 .. 32 {
      cached[b] ^= encryption_key_slice[b];
    }
    encryption_key_slice.zeroize();
    let (machine, preprocess) =
      AlgorithmSignMachine::from_cache(algorithm, keys, CachedPreprocess(cached));

    (machine, preprocess.serialize().try_into().unwrap())
  }

  fn share_internal(
    &mut self,
    participants: &[<Ristretto as Ciphersuite>::G],
    mut serialized_preprocesses: HashMap<Participant, Vec<u8>>,
    msg: &[u8],
  ) -> Result<(AlgorithmSignatureMachine<Ristretto, Schnorrkel>, [u8; 32]), Participant> {
    let machine = self.preprocess_internal(participants).0;

    let mut participants = serialized_preprocesses.keys().copied().collect::<Vec<_>>();
    participants.sort();
    let mut preprocesses = HashMap::new();
    for participant in participants {
      preprocesses.insert(
        participant,
        machine
          .read_preprocess(&mut serialized_preprocesses.remove(&participant).unwrap().as_slice())
          .map_err(|_| participant)?,
      );
    }

    let (machine, share) = machine.sign(preprocesses, msg).map_err(|e| match e {
      FrostError::InternalError(e) => unreachable!("FrostError::InternalError {e}"),

      FrostError::InvalidSigningSet(_) |
      FrostError::InvalidParticipantQuantity(_, _) |
      FrostError::DuplicatedParticipant(_) |
      FrostError::MissingParticipant(_) => unreachable!("{e:?}"),
      FrostError::InvalidPreprocess(p) | FrostError::InvalidShare(p) => p,
    })?;

    Ok((machine, share.serialize().try_into().unwrap()))
```

```markdown
# Caching

modular-frost supports caching a preprocess. This is done by having all
preprocesses use a seeded RNG. Accordingly, the entire preprocess can be derived
from the RNG seed, making the cache just the seed.

Reusing preprocesses would enable a third-party to recover your private key
share. Accordingly, you MUST not reuse preprocesses. Third-party knowledge of
your preprocess would also enable their recovery of your private key share.
Accordingly, you MUST treat cached preprocesses with the same security as your
private key share.

Since a reused seed will lead to a reused preprocess, seeded RNGs are generally
frowned upon when doing multisignature operations. This isn't an issue as each
new preprocess obtains a fresh seed from the specified RNG. Assuming the
provided RNG isn't generating the same seed multiple times, the only way for
this seeded RNG to fail is if a preprocess is loaded multiple times, which was
already a failure point.
```
