### Title
`saveGitIgnore` follows an attacker-controlled `.gitignore` symlink and overwrites arbitrary out-of-tree files - (File: `app/src/lib/git/gitignore.ts`)

### Summary
`saveGitIgnore` computes `ignorePath = Path.join(repository.path, '.gitignore')` and then calls Node's `writeFile(ignorePath, fileContents)` without ever checking whether `.gitignore` is a symlink. [1](#0-0)  `fs.promises.writeFile` opens the target path with the default flag `'w'`, which does **not** set `O_NOFOLLOW`, so if `.gitignore` in the working tree is a symbolic link, Node will open and truncate the symlink's *target* file rather than the symlink itself.

### Finding Description
Git checkout does not validate that a tracked symlink's target stays inside the working tree — a malicious repository can commit a symlink literally named `.gitignore` whose stored target is an arbitrary absolute or relative path (e.g. `/home/user/.bashrc`, `~/.ssh/authorized_keys`, or a git hook file). When the victim clones/fetches and checks out this repository in GitHub Desktop, the symlink is materialized on disk exactly as specified by the attacker.

From there, several UI-reachable code paths end up calling `saveGitIgnore`:
- The "Ignore file" context-menu action on a change list entry, which flows through `appendIgnoreFile` → `appendIgnoreRule` → `saveGitIgnore`. [2](#0-1) [3](#0-2) 
- The Repository Settings "Ignored Files" text editor, which calls `saveGitIgnore` directly when the user hits Save.

None of these paths perform an `lstat`/`isSymbolicLink` check on `ignorePath` before writing, and there is no `O_NOFOLLOW`/`fs.constants` flag used to prevent following a symlink. As a result, `writeFile(ignorePath, fileContents)` transparently follows the symlink and overwrites whatever file it points to, with content fully or partially controlled by the user's typed/appended ignore text (and, in the "append" flow, that content is influenced by the escaped file path the user chose to ignore — still attacker-influenced format via `formatGitIgnoreContents`).

### Impact Explanation
This allows a malicious repository to achieve a write primitive on files outside the repository's working directory, purely by getting the victim to perform a normal, expected UI action ("Ignore file" or editing/saving the ignore list in Repository Settings) — actions that are advertised as operating only on the repository's own `.gitignore`. Depending on the symlink target chosen by the attacker (shell rc files, SSH `authorized_keys`, git hooks, cron files, etc.), this can lead to persistence or code execution on the victim's machine, satisfying the "file write outside the repo" / potential code-execution impact criteria.

### Likelihood Explanation
Likelihood is moderate-to-high in scope terms: the only user interaction required is cloning an attacker-supplied repository and clicking "Ignore file" on any change (a very common, expected workflow) or opening/saving the Ignored Files editor in Repository Settings. No admin rights, malware, or unusual steps are needed — the trigger is a standard Desktop feature acting on attacker-controlled repository content (a tracked symlink named `.gitignore`).

### Recommendation
Before writing, `lstat` the computed `ignorePath` and refuse to write (or unlink-then-recreate as a regular file) if it is a symlink, e.g.:
```ts
const stat = await FS.promises.lstat(ignorePath).catch(() => null)
if (stat?.isSymbolicLink()) {
  throw new Error('Refusing to write through a symlinked .gitignore')
}
```
Alternatively, open the file with `O_NOFOLLOW` (or use `fs.open` + `fs.constants.O_WRONLY | O_CREAT | O_TRUNC | O_NOFOLLOW`) so the OS itself rejects following the symlink, and apply the same check to `readGitIgnoreAtRoot`.

### Proof of Concept
1. Create a repository containing a symlink `.gitignore -> /tmp/target` (e.g. `ln -s /tmp/target .gitignore && git add .gitignore && git commit`), and populate `/tmp/target` with sentinel content.
2. Push/host the repo and have the victim clone it with GitHub Desktop.
3. In Desktop, modify any tracked/untracked file and use the "Ignore file" context menu action, or open Repository Settings → Ignored Files and click Save.
4. Observe that `/tmp/target` (outside the repository) has been overwritten with the ignore-file contents instead of `.gitignore` inside the repo, confirming `saveGitIgnore`/`writeFile` followed the symlink.

export async function saveGitIgnore(
  repository: Repository,
  text: string
): Promise<void> {
  const ignorePath = Path.join(repository.path, '.gitignore')

  if (text === '') {
    return new Promise<void>((resolve, reject) => {
      FS.unlink(ignorePath, err => {
        if (err) {
          reject(err)
        } else {
          resolve()
        }
      })
    })
  }

  const fileContents = await formatGitIgnoreContents(text, repository)
  await writeFile(ignorePath, fileContents)
```

export async function appendIgnoreRule(
  repository: Repository,
  patterns: string | string[]
): Promise<void> {
  const text = (await readGitIgnoreAtRoot(repository)) || ''

  const currentContents = await formatGitIgnoreContents(text, repository)

  const newPatternText =
    patterns instanceof Array ? patterns.join('\n') : patterns
  const newText = await formatGitIgnoreContents(
    `${currentContents}${newPatternText}`,
    repository
  )

  await saveGitIgnore(repository, newText)
}
```

export async function appendIgnoreFile(
  repository: Repository,
  filePath: string | string[]
): Promise<void> {
  if (filePath instanceof Array) {
    const escapedFilePaths = filePath.map(path =>
      escapeGitSpecialCharacters(path)
    )

    return appendIgnoreRule(repository, escapedFilePaths)
  }

  const escapedFilePath = escapeGitSpecialCharacters(filePath)
  return appendIgnoreRule(repository, escapedFilePath)
}
