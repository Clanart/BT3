### Title
Out-of-bounds read / unhandled `IndexError` in `is_atom_canonical()` allows a submitted spend bundle to crash mempool validation - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_atom_canonical()` parses CLVM atom length-prefix bytes from an attacker-supplied buffer without validating that the buffer is long enough to contain the full multi-byte length prefix or the atom payload implied by `atom_len`. It is invoked, unguarded by any try/except, from `is_clvm_canonical()`, which is called directly on the raw `puzzle_reveal`/`solution` bytes of every coin spend during mempool admission in `MempoolManager.validate_spend_bundle()`.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` [1](#0-0)  reads `b = clvm_buffer[offset]` to determine a length-prefix class (1–6 bytes), then loops `prefix_len` times incrementing `offset` and indexing `clvm_buffer[offset]` again to accumulate `atom_len`, with **no check that `offset` stays within `len(clvm_buffer)`**. It also returns `1 + prefix_len + atom_len` as the atom's total length without verifying that this length actually fits inside the remaining buffer.

The caller, `is_clvm_canonical()` [2](#0-1) , walks the buffer token-by-token, calling `is_atom_canonical()` whenever it hits an atom-length byte (`b > 0x80`), and then advances `offset += atom_len`. If `atom_len` overshoots the real buffer (e.g., a length-prefix byte at the very end of the buffer claims a multi-byte prefix that isn't actually present, or the atom length claims content beyond the buffer's actual size), the subsequent iteration's `clvm_buffer[offset]` access raises an uncaught `IndexError`.

This is directly analogous to the reported virglrenderer bug class: an insufficiently bounds-checked length/offset value taken from untrusted input drives a buffer access past its allocated bounds. In Python this manifests as an unhandled exception rather than raw memory corruption, but the trigger mechanism (attacker-controlled length field consumed without a bounds check before indexing) is the same root cause.

`is_clvm_canonical()` is called unconditionally, with no exception handling, from `MempoolManager.validate_spend_bundle()`: [3](#0-2) 
This is on the hot path for every coin spend of every spend bundle submitted to the mempool by any peer/wallet client — no privileged position required.

### Impact Explanation
A single malformed but otherwise well-formed-looking `CoinSpend` (crafted `puzzle_reveal` or `solution` bytes ending with a truncated/dangling atom length-prefix) can raise an unhandled `IndexError` inside `validate_spend_bundle()`. Since this runs as part of mempool admission for every incoming spend bundle, it can disrupt the transaction-processing pipeline for that call — a spend-triggered processing halt, which is one of the explicitly accepted impact categories (denial of service / mempool validation crash) for this analog class. The severity is bounded by whatever surrounds the call (task-level exception isolation), but the vulnerable code path itself performs no bounds validation and is directly reachable by unprivileged submitters.

### Likelihood Explanation
High reachability: any wallet/user/peer that can submit a `SpendBundle` to a full node's mempool controls `puzzle_reveal` and `solution` byte content precisely enough to construct a buffer whose trailing bytes look like the start of a multi-byte atom length prefix but do not contain the full prefix/payload, per the tested encodings already exercised in `chia/_tests/core/mempool/test_mempool_manager.py:181-195` (`test_atom_canonical`). Constructing such an input requires no signature verification bypass — canonical-serialization checking happens on the raw CLVM bytes before the coin's puzzle is actually executed. However, whether this raises in practice depends on exact truncation placement (it is easy to construct: e.g., a buffer ending exactly on the length-prefix indicator byte with no trailing bytes).

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before indexing `clvm_buffer[offset]` in the prefix loop (verify `offset < len(clvm_buffer)` for each prefix byte read), and in `is_clvm_canonical()` verify that `atom_len` (the declared atom size) does not run past `len(clvm_buffer)` before advancing `offset`, returning `False` (non-canonical) rather than throwing. Additionally, wrap the `is_clvm_canonical()` calls in `validate_spend_bundle()` with an exception guard that treats malformed CLVM as `Err.INVALID_COIN_SOLUTION` instead of letting an `IndexError` propagate.

### Proof of Concept
Construct a `CoinSpend` whose `solution` (or `puzzle_reveal`) is a truncated multi-byte atom prefix, e.g. bytes `b"\xff\xc0"` (a pair marker followed by a lone `0xC0` byte indicating a "5+8 bits length prefix" atom that requires one more length byte which is absent). Submitting a `SpendBundle` containing this `CoinSpend` to `MempoolManager.validate_spend_bundle()` reaches `is_clvm_canonical(bytes(coin_spend.solution))` → `is_atom_canonical(buf, offset=1)`, which executes `offset += 1; atom_len |= clvm_buffer[offset]` with `offset == len(buf)`, raising `IndexError: index out of range` before any handling code can catch it — matching the existing test harness pattern in `test_atom_canonical` [4](#0-3)  and the call site in `validate_spend_bundle` [3](#0-2) .

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

```python
def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
