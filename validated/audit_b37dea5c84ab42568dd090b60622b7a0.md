### Title
Untrusted `ReceivedOutput` bytes are accepted as spendable funds without verifying the output exists or belongs to the key - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The audit hint concerns treating a failed value transfer as successful because its return value was never checked. The Serai analog is `ReceivedOutput::read`, which deserializes an attacker-controlled `(offset, TxOut, OutPoint)` triple and treats it as a received, spendable output with no validation that the `script_pubkey` corresponds to `key + offset*G`, that the outpoint exists on-chain, or that it is unspent. Downstream, `SignableTransaction::new` happily consumes the fabricated output, inflates `input_sat`, builds a transaction spending a non-existent or foreign UTXO, and the resulting signature is useless — funds are "reported received" that are not actually spendable.

### Finding Description
`ReceivedOutput::read` in `networks/bitcoin/src/wallet/mod.rs:122-134` reads a scalar offset, a `TxOut`, and an `OutPoint` from an untrusted reader and returns the struct unconditionally. There is no check that:

- `p2tr_script_buf(scanner_key + GENERATOR * offset) == output.script_pubkey`, or
- the `outpoint` refers to a real, unspent UTXO carrying that `TxOut`.

`SignableTransaction::new` (`networks/bitcoin/src/wallet/send.rs:150-256`) then sums `input.output.value` into `input_sat` (line 175) and builds `TxIn`s from the supplied outpoints (lines 177-185). The only consistency check is deferred to `multisig` (lines 273-285), which verifies `offset` against `prevouts[i].script_pubkey` — but a fabricated `ReceivedOutput` can simply copy the wallet's real `script_pubkey` while pointing `outpoint` at a non-existent or already-spent UTXO. That passes the `multisig` check, the threshold signature is produced over `Prevouts::All` (line 375) committing to the phantom prevout, and the broadcast transaction is invalid. The fee check at line 215 (`input_sat >= payment_sat + needed_fee`) is also satisfied using phantom value, so the protocol believes it has funds it does not.

### Impact Explanation
Any unprivileged party able to feed bytes into `ReceivedOutput::read` (an explicitly in-scope deserialization API) can cause Serai's Bitcoin wallet layer to record phantom deposits. The network then signs a transaction spending a non-existent outpoint, which Bitcoin will reject — the protocol has committed nonce/signature shares and believes funds were received that are not spendable. With enough phantom inputs, real change/payment outputs get sized and signed against fabricated input value, producing systematically invalid transactions and stalling legitimate payouts.

### Likelihood Explanation
Reachable whenever `ReceivedOutput` is transported via untrusted serialization (the whole reason `read`/`write` exist). The attacker needs no keys and no threshold collusion; they only supply crafted bytes. The `multisig` script check mitigates only the case where the script doesn't match — a copied script with a fake outpoint bypasses it entirely.

### Recommendation
Bind the `ReceivedOutput` to the scanning key at construction/read time: store or pass the expected `ProjectivePoint` and assert `p2tr_script_buf(key + GENERATOR * offset) == output.script_pubkey`. Separately, confirm via RPC (`gettxout`) that `outpoint` resolves to an unspent output equal to `output` before admitting it into `SignableTransaction::new`, rather than trusting the serialized claim.

### Proof of Concept
1. Attacker obtains the wallet's `script_pubkey` (public on-chain) and any registered `offset`.
2. Craft bytes: `offset || TxOut{value: 10 BTC, script_pubkey: <wallet script>} || OutPoint{txid: 0x00.., vout: 0}` and feed to `ReceivedOutput::read`.
3. The fabricated output passes `SignableTransaction::new` (input_sat inflated by 10 BTC), passes `multisig`'s script check, and `TransactionSignMachine::sign` produces a valid Schnorr signature over `Prevouts::All` including the phantom prevout.
4. The completed transaction is broadcast and rejected by Bitcoin (`bad-txns-inputs-missingorspent`); Serai has signed for funds it never received.
