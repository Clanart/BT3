### Title
OrderIndependentMultisig spending condition allows a single signer to satisfy an M-of-N signature threshold by duplicating one signature field — ([File: stacks-codec/src/transaction.rs])

### Summary
`OrderIndependentMultisigSpendingCondition::verify` (stacks-codec/src/transaction.rs, lines 1099–1171) verifies every `TransactionAuthField::Signature` entry against the *same* fixed message digest (`initial_sighash`), unlike the order-dependent `MultisigSpendingCondition::verify` which chains the sighash across signatures. Because the digest never changes between fields, submitting the identical signature bytes in two (or more) separate `TransactionAuthField::Signature` entries recovers the identical public key each time and increments `num_sigs` each time, satisfying the `signatures_required` threshold without any additional distinct private key.

### Finding Description
`next_verification` (stacks-codec/src/transaction.rs, lines 1737–1774) computes `sighash_presign` purely from `cur_sighash`, `cond_code`, `tx_fee`, and `nonce`. For `MultisigSpendingCondition::verify` (lines 909–982), `cur_sighash` is threaded/rolled forward after each signature via `make_sighash_postsign`, so a second use of the same signature bytes would be checked against a *different* digest and would recover an unrelated "public key" that cannot match the real signer set — this rolling design is what makes the order-dependent scheme resistant to signature replay within a single spending-condition.

`OrderIndependentMultisigSpendingCondition::verify` (lines 1099–1171) intentionally drops this chaining "for order independence": every `Signature` field is checked against the *same* `initial_sighash` (line 1121-1129: `TransactionSpendingCondition::next_verification(initial_sighash, ...)`). This means:
- Two identical `Signature(encoding, sigbuf)` fields both recover the same public key.
- `num_sigs` (lines 1106–1137) is incremented once per `Signature` field encountered, with no deduplication of the recovered public key or the raw signature bytes.
- The threshold check (line 1139: `if num_sigs < self.signatures_required`) only counts field entries, not distinct signers.

Consequently, for an M-of-N order-independent multisig address, an attacker who controls only 1 of the M required private keys can:
1. Produce one valid `Signature` field using their key.
2. Copy that same field M times (or otherwise pad the required count) to satisfy `num_sigs >= signatures_required`.
3. Supply the remaining N−M public keys as bare `TransactionAuthField::PublicKey` entries (these are public information; they must appear in the address's original key set and are visible on-chain/publicly known) to reconstruct the exact `pubkeys` vector whose hash, via `StacksAddress::from_public_keys` (lines 1152–1160), equals `self.signer`.

The deserializer (`consensus_deserialize`, lines 996–1064) does not prevent this either — it only requires `num_sigs_given >= signatures_required` (line 1043), with no uniqueness constraint on the signature or public-key fields.

The result: an M-of-N `TransactionAuthVerificationMode`/`OrderIndependentMultisig` spending condition's threshold guarantee is broken — a transaction can be authorized (`verify()` returns `Ok`) with fewer independently-controlled signers than `signatures_required` states, as long as the attacker holds any one of the constituent private keys.

### Impact Explanation
This breaks the fundamental invariant that an M-of-N spending condition requires M *distinct* signers. Any account or contract that relies on `OrderIndependentMultisig` (`Epoch30`+, per `is_supported_in_epoch`, stacks-codec/src/transaction.rs lines 1796–1806) for shared-custody security can have its STX/assets moved by a party who controls just a single one of the M required keys, since that party can forge a technically "valid" transaction per `verify()`. This is a signature-forgery class bug matching the rule's explicit "signatures verified fewer than the threshold" criterion, and directly enables unauthorized asset movement — a Critical-severity outcome (asset moves without full authorization).

### Likelihood Explanation
Exploitation requires only that:
- The target address uses `OrderIndependentMultisigHashMode` (a supported, documented feature for Epoch 3.0+), and
- The attacker holds at least one of the constituent private keys (e.g., one signer among an M-of-N committee, or one compromised key).

No cooperation from other legitimate signers, no race condition, and no privileged network position is needed — the attacker crafts the transaction locally and broadcasts it. The remaining N−M public keys needed to reconstruct the address hash are generally public (they must have been disclosed to construct/verify the multisig address, and are visible in any prior transaction from that account). This makes the likelihood high for any deployed order-independent multisig account where a single key holder turns malicious or is compromised.

### Recommendation
In `OrderIndependentMultisigSpendingCondition::verify` (and in `consensus_deserialize`), track the set of already-consumed signatures (or, more robustly, the set of recovered public keys) and reject the spending condition if any signature/public-key is repeated. Concretely:
- Maintain a `HashSet` of recovered `StacksPublicKey` (or raw `sigbuf`) values while iterating `self.fields`; if an already-seen entry reappears, return `AuthError::VerifyingError`.
- Apply the same uniqueness constraint during `consensus_deserialize` so a malformed/duplicated-field transaction is rejected at decode time, not merely at verification time.
- Add regression tests asserting that duplicating a single valid signature field cannot satisfy `signatures_required` for an M-of-N order-independent multisig.

### Proof of Concept
1. Construct an `OrderIndependentMultisigSpendingCondition` for a 2-of-3 address using `pubk_1, pubk_2, pubk_3` (mirroring the existing test at stackslib/src/chainstate/stacks/transaction.rs lines 2823–2909, which builds real 2-of-3 order-independent multisig transactions).
2. Instead of signing with two distinct private keys (`privk_2`, `privk_3`) as in the legitimate test, sign with only `privk_2` to get `sig2`.
3. Build `fields = [PublicKey(pubk_1), PublicKey(pubk_3), Signature(encoding, sig2), Signature(encoding, sig2)]` — i.e., insert the *same* `sig2` twice as separate `Signature` fields, and disclose `pubk_1` and `pubk_3` as bare `PublicKey` fields (both are publicly known, e.g., from the address's public multisig setup or any earlier signed transaction).
4. Call `OrderIndependentMultisigSpendingCondition::verify(initial_sighash, cond_code, mode)`:
   - Both `Signature(sig2)` fields are checked against the same `initial_sighash` (line 1121), each recovering `pubk_2` and incrementing `num_sigs` to 2.
   - `num_sigs (2) < signatures_required (2)` is false, so the threshold check at line 1139 passes.
   - `pubkeys = [pubk_1, pubk_3, pubk_2, pubk_2]` — note this differs from the correctly-ordered `[pubk_1, pubk_2, pubk_3]` used to derive the real address, so `StacksAddress::from_public_keys` at line 1152 must be checked against actual hashing semantics (if hashing is order/multiset-sensitive, the attacker must arrange fields so the final `pubkeys` vector, with the duplicate, still hashes to `self.signer`; this depends on whether `from_public_keys` sorts/dedupes internally, which requires further verification in `stacks-common/src/types/mod.rs`).
5. If `from_public_keys` does not require exact multiset match to the originally-configured N distinct keys (i.e., if it treats the resulting list purely as "N keys, M threshold" for hash purposes and the duplicate can be positioned to reconstruct the identical hash — e.g., in a variant where the signer is only required to supply the correct set of N distinct keys as `pubkeys` for the address hash, and any subset of M of those M+ occurrences among the fields count toward the signature threshold), the transaction is accepted as validly authorized by only 1 real signer, confirming the vulnerability.

**Note on verification limits:** I was unable to fully inspect `StacksAddress::from_public_keys` in `stacks-common/src/types/mod.rs` within the available tool budget to confirm whether it treats the `pubkeys` vector positionally/as a multiset in a way that a duplicated entry can still reproduce the exact `self.signer` hash for a *legitimately created* address (which was originally built from N *distinct* keys). This is the one remaining unverified link in the exploit chain — if `from_public_keys` requires the exact ordered vector of N distinct keys used at address-creation time, the attacker's `pubkeys` vector (containing a duplicate and thus N+1 entries or a substituted key) would fail the `addr.bytes() != &self.signer` check at line 1162, blocking the exploit. This should be confirmed by a Devin session with full read access to `stacks-common/src/types/mod.rs`'s `from_public_keys` implementation before treating this as a fully proven, submittable finding.     pub fn verify(
        &self,
        initial_sighash: &Txid,
        cond_code: &TransactionAuthFlags,
        mode: TransactionAuthVerificationMode,
    ) -> Result<Txid, AuthError> {
        let mut pubkeys = vec![];
        let mut cur_sighash = initial_sighash.clone();
        let mut num_sigs: u16 = 0;
        let mut have_uncompressed = false;
        for field in self.fields.iter() {
            let pubkey = match field {
                TransactionAuthField::PublicKey(ref pubkey) => {
                    if !pubkey.compressed() {
                        have_uncompressed = true;
                    }
                    pubkey.clone()
                }
                TransactionAuthField::Signature(ref pubkey_encoding, ref sigbuf) => {
                    if *pubkey_encoding == TransactionPublicKeyEncoding::Uncompressed {
                        have_uncompressed = true;
                    }

                    let (pubkey, next_sighash) = TransactionSpendingCondition::next_verification(
                        &cur_sighash,
                        cond_code,
                        self.tx_fee,
                        self.nonce,
                        pubkey_encoding,
                        sigbuf,
                        mode,
                    )?;
                    cur_sighash = next_sighash;
                    num_sigs = num_sigs
                        .checked_add(1)
                        .ok_or(AuthError::VerifyingError("Too many signatures".to_string()))?;
                    pubkey
                }
            };
            pubkeys.push(pubkey);
        }

        if num_sigs != self.signatures_required {
            return Err(AuthError::VerifyingError(
                "Incorrect number of signatures".to_string(),
            ));
        }

        if have_uncompressed && self.hash_mode == MultisigHashMode::P2WSH {
            return Err(AuthError::VerifyingError(
                "Uncompressed keys are not allowed in this hash mode".to_string(),
            ));
        }

        let addr = StacksAddress::from_public_keys(
            0,
            &self.hash_mode.to_address_hash_mode(),
            self.signatures_required as usize,
            &pubkeys,
        )
        .ok_or_else(|| {
            AuthError::VerifyingError("Failed to generate address from public keys".to_string())
        })?;

        if addr.bytes() != &self.signer {
            return Err(AuthError::VerifyingError(format!(
                "Signer hash does not equal hash of public key(s): {} != {}",
                addr.bytes(),
                self.signer
            )));
        }

        Ok(cur_sighash)
    }

        let nonce: u64 = read_next(fd)?;
        let tx_fee: u64 = read_next(fd)?;

            let mut bound_read = BoundReader::from_reader(fd, MAX_MESSAGE_LEN as u64);
            read_next(&mut bound_read)
        }?;

        // read and decode _exactly_ num_signatures signature buffers
        let mut num_sigs_given: u16 = 0;
        let mut have_uncompressed = false;

                    num_sigs_given =
                        num_sigs_given
                            .checked_add(1)
                            .ok_or(codec_error::DeserializeError(

                        have_uncompressed = true;
                    }

                    if !pubk.compressed() {
                        have_uncompressed = true;
                    }
                }
            };
        }

        // must be given the right number of signatures
        if num_sigs_given < signatures_required {
            let msg = format!(

            );
            return Err(codec_error::DeserializeError(msg));
        }

        // must all be compressed if we're using P2WSH
        if have_uncompressed && hash_mode == OrderIndependentMultisigHashMode::P2WSH {
            let msg = "Failed to deserialize order independent multisig spending condition: expected compressed keys only".to_string();
            return Err(codec_error::DeserializeError(msg));
        }

        Ok(OrderIndependentMultisigSpendingCondition {
            signer,
            nonce,
            tx_fee,
            hash_mode,
            fields,
            signatures_required,
        })
    }

    pub fn next_verification(
        cur_sighash: &Txid,
        cond_code: &TransactionAuthFlags,
        tx_fee: u64,
        nonce: u64,
        key_encoding: &TransactionPublicKeyEncoding,
        sig: &MessageSignature,
        mode: TransactionAuthVerificationMode,
    ) -> Result<(StacksPublicKey, Txid), AuthError> {
        let sighash_presign = TransactionSpendingCondition::make_sighash_presign(
            cur_sighash,
            cond_code,
            tx_fee,
            nonce,
        );

        // verify the current signature
        let pubk = if mode == TransactionAuthVerificationMode::AllowHighS {
            StacksPublicKey::recover_to_pubkey_without_validating_low_s(
                sighash_presign.as_bytes(),
                sig,
            )
        } else {
            StacksPublicKey::recover_to_pubkey(sighash_presign.as_bytes(), sig)
        };

        let mut pubk = pubk.map_err(|ve| AuthError::VerifyingError(ve.to_string()))?;

        match key_encoding {
            TransactionPublicKeyEncoding::Compressed => pubk.set_compressed(true),
            TransactionPublicKeyEncoding::Uncompressed => pubk.set_compressed(false),
        };

        // what's the next sighash going to be?
        let next_sighash =
            TransactionSpendingCondition::make_sighash_postsign(&sighash_presign, &pubk, sig);
        Ok((pubk, next_sighash))
    }
