### Title
Auctioneer signature omits `maxGasPrice` from the signed payload, allowing bid tampering without invalidating signatures - ([File: kaiax/auction/bid.go])

### Summary
The `AffiliateValidator.addKey` bug pattern is a signature that is not cryptographically bound to a value that determines the authorization's effect (there `msg.sender`), letting an attacker capture a valid signature and rebind it to different, unintended data. The Kaia auction module's `Bid.ValidateAuctioneerSig` (`kaiax/auction/bid.go`) exhibits the analogous flaw: the auctioneer's approval signs only `keccak256("\x19Ethereum Signed Message:\n" + len(SearcherSig) + SearcherSig)` — i.e. it authenticates the *searcher's signature bytes*, not the bid's `MaxGasPrice` field directly, and the V2 EIP-712 struct that the searcher signs (`auctionType` in `kaiax/auction/eip712.go`) also excludes `maxGasPrice` from the hashed struct fields (only `auctionTypeV3`/`bidV3.EncodeData` includes it).

### Finding Description
`Bid.ValidateSearcherSig` verifies `SearcherSig` against an EIP-712 digest computed by `GetHashTypedData`, which for `AuctionVersionV2` ("0.0.1") calls `EncodeData()` on the base `Bid` type: [1](#0-0) 
This struct explicitly does **not** include `MaxGasPrice`, unlike the V3 variant `bidV3.EncodeData`: [2](#0-1) 

`Bid.ValidateAuctioneerSig` then only re-hashes the raw `SearcherSig` bytes as an Ethereum-signed message, without incorporating any other bid field independently: [3](#0-2) [4](#0-3) 

Because `MaxGasPrice` is carried in `BidData` (and propagated end-to-end through `SubmitBid`/RLP/gossip) but is not part of either the searcher's or the auctioneer's signed digest for the V2 struct hash, a value that is not protected by any signature can be freely modified by anyone who relays or resubmits the bid (e.g., via the `auction_submitBid` RPC in `kaiax/auction/impl/api.go`) without invalidating `ValidateSearcherSig` or `ValidateAuctioneerSig`, both of which are the only two signature checks performed in `BidPool.validateBidSigs`: [5](#0-4) 

This mirrors the root cause of H03: a signed authorization (the auctioneer's/searcher's signature) does not cover a field that materially affects how the authorization is later used, allowing an unauthorized third party to alter that field and have it accepted as if it had been approved by the signers.

### Impact Explanation
`MaxGasPrice` in the auction context represents a price ceiling term negotiated/approved by the `Auctioneer` for a searcher's bid under KIP-249. If this field can be silently modified post-signature by any relaying party (or an attacker observing a bid in the bid-pool/gossip network and resubmitting a modified copy through the `auction_submitBid` RPC) without breaking either signature check, it undermines the integrity of the auction price commitment that the auctioneer believed it was attesting to. Depending on how `MaxGasPrice` is later consumed by the block-builder/tx-generation logic (not fully verifiable from the indexed code available, since `blockchain/system/auction.go`'s usage of `MaxGasPrice` could not be fully traced in this pass), this could enable fee/settlement manipulation in the auction flow — a concrete instance of "acceptance of an invalid/unauthorized bid" reachable purely from a public RPC bid submission.

### Likelihood Explanation
Medium. Exploitation requires only capturing or constructing a `BidInput` with valid `SearcherSig`/`AuctioneerSig` (which are visible once the bid is gossiped or once a searcher/auctioneer publishes them) and resubmitting it with an altered `MaxGasPrice` via the `auction_submitBid` RPC — no special privileges beyond bid-pool RPC access are needed, and both signature checks in `validateBidSigs` still pass since they never examine `MaxGasPrice` for the V2 path.

### Recommendation
Include all `BidData` fields that affect bid semantics — specifically `MaxGasPrice` — in the EIP-712 struct hash used for `AuctionVersionV2` (or reject `AuctionVersionV2` bids where `MaxGasPrice != nil`), and/or have `GetEthSignedMessageHash` (the auctioneer digest) hash the full `BidData` content rather than only the `SearcherSig` bytes, so that no field can be altered post-signature without invalidating both signatures.

### Proof of Concept
1. A searcher signs a V2 bid (`AuctionVersionV2`) via `ValidateSearcherSig`'s EIP-712 digest, which excludes `MaxGasPrice` (`kaiax/auction/eip712.go` `EncodeData`, lines 75-86).
2. The `Auctioneer` approves by signing only `GetEthSignedMessageHash()` = hash of `SearcherSig` bytes (`kaiax/auction/bid.go` lines 52-55), also independent of `MaxGasPrice`.
3. An attacker observing this bid (e.g. from P2P gossip or a prior RPC response) constructs a new `BidInput` with the same `TargetTxHash`, `Sender`, `SearcherSig`, `AuctioneerSig`, but a different `MaxGasPrice`, and calls `auction_submitBid` (`kaiax/auction/impl/api.go` `SubmitBid`).
4. `BidPool.validateBid` → `validateBidSigs` (`kaiax/auction/impl/bid_pool.go` lines 397-419) calls `ValidateSearcherSig` and `ValidateAuctioneerSig`; both succeed because neither depends on `MaxGasPrice`.
5. The tampered bid, with an unauthorized `MaxGasPrice`, is accepted into the bid pool as if approved by both the searcher and auctioneer.

func (b *Bid) ValidateAuctioneerSig(auctioneer common.Address) error {
	digest := b.GetEthSignedMessageHash()

	recoveredAuctioneer, err := getSigner(b.AuctioneerSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover auctioneer sig: %v", err)
	}

	if recoveredAuctioneer != auctioneer {
		return fmt.Errorf("invalid auctioneer sig: expected %v, calculated %v", auctioneer.String(), recoveredAuctioneer.String())
	}

	return nil
}

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}
