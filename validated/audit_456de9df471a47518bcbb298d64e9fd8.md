### Title
Unprivileged bypass of `harvestAll()`/`_manageRewards()` via direct `claimAllBribes(delegatedPool)` call permanently freezes bribe tokens in `DelegateVoteRewardPool` - (File: wombat/WombatBribeManager.sol, rewards/DelegateVoteRewardPool.sol)

### Summary
`WombatBribeManager.claimAllBribes(address _for)` is a `public` function with no access control restricting who can call it or what `_for` value can be used. An unprivileged attacker can call `claimAllBribes(delegatedPool)` directly, causing every pool that the `DelegateVoteRewardPool` (a.k.a. `delegatedPool`) has voted in to send its earned bribe tokens straight to the `delegatedPool` contract's balance, completely bypassing `DelegateVoteRewardPool.harvestAll()` → `_manageRewards()` → `_queueNewRewardsWithoutTransfer()`, so the tokens are never reflected in `rewardPerTokenStored`.

### Finding Description
`claimAllBribes` loops over `pools` and, for any pool `lp` where `userVotedForPoolInVlmgp[_for][lp] > 0`, calls `IBribeRewardPool(pool.rewarder).getReward(_for, _for)` directly: [1](#0-0) 

`userVotedForPoolInVlmgp[delegatedPool][lp]` is populated whenever `DelegateVoteRewardPool._updateVote()` calls `IWombatBribeManager(operator).vote(votePools, deltas)`, in which `msg.sender` is the `DelegateVoteRewardPool` contract, so `userVotedForPoolInVlmgp[msg.sender][pool.poolAddress]` (i.e. `[delegatedPool][lp]`) is incremented: [2](#0-1) [3](#0-2) 

The downstream `getReward(address _account, address _receiver)` in `BaseRewardPoolV2` is guarded only by `onlyMasterMagpie`, which checks `msg.sender == operator`. Since the call is made *from* `WombatBribeManager` (the operator/master magpie for the pool rewarders), this check passes regardless of who originally called `claimAllBribes`: [4](#0-3) [5](#0-4) 

Because `_receiver = _for = delegatedPool`, the bribe tokens are transferred directly into the `DelegateVoteRewardPool` contract's balance. The intended path (`DelegateVoteRewardPool.harvestAll()`) instead calls `claimAllBribes(address(this))` and then feeds the returned tokens into `_manageRewards`, which deducts protocol fees and calls `_queueNewRewardsWithoutTransfer` to update `rewards[token].rewardPerTokenStored`: [6](#0-5) [7](#0-6) 

When the attacker calls `claimAllBribes(delegatedPool)` directly (not through `harvestAll`), the tokens are transferred to `delegatedPool` but `_manageRewards`/`_queueNewRewardsWithoutTransfer` are never invoked, so `rewardInfo.rewardPerTokenStored` is never increased. Because `earned()` inside each pool rewarder resets `userRewards[token][delegatedPool] = 0` after transfer, a later legitimate `harvestAll()` call will compute `earnedRewards = 0` for those same pools (nothing left to claim), so the tokens already sitting in `DelegateVoteRewardPool`'s balance can never be queued or claimed by any staker.

No modifier (`onlyOperator`, `nonReentrant`, access control) prevents an arbitrary EOA from calling `claimAllBribes` with an arbitrary `_for` argument, including the `delegatedPool` address.

### Impact Explanation
This results in permanent freezing of unclaimed yield: bribe reward tokens accumulate as raw ERC20 balance inside `DelegateVoteRewardPool` but are never reflected in `rewardPerTokenStored`, so no staker in `DelegateVoteRewardPool` can ever claim them. This breaks the backing/conservation invariant (token balance exceeds total claimable amount) and matches the Immunefi impact class "permanent freezing of unclaimed yield."

### Likelihood Explanation
- Preconditions: `delegatedPool` must be configured in `WombatBribeManager` and have nonzero `userVotedForPoolInVlmgp[delegatedPool][lp]` for at least one pool — a normal, expected operational state once any user has deposited into `DelegateVoteRewardPool` and votes have been cast.
- No special privileges, capital, or complex setup are required; any EOA can call `claimAllBribes(delegatedPool)` at any time bribes have accrued.
- Fully repeatable each time new bribes accrue for the delegated pool's voted LPs, front-running/preceding legitimate `harvestAll()` calls.

### Recommendation
Restrict `claimAllBribes` to disallow arbitrary `_for` harvesting on behalf of `delegatedPool` by unprivileged callers — e.g., require `msg.sender == _for` or `msg.sender == delegatedPool` when `_for == delegatedPool`, or make the delegate-pool branch only callable internally through `harvestAll()` (e.g., add an `onlyDelegatedPool` check when `_for == delegatedPool`). Ensure any direct pull of rewards belonging to `delegatedPool` always routes through `_manageRewards`/`_queueNewRewardsWithoutTransfer` before tokens can be considered received.

### Proof of Concept
Foundry test outline:
1. Deploy `WombatBribeManager`, `DelegateVoteRewardPool`, and pool `BribeRewardPool`s; set `delegatedPool` and add pools via `addPool`.
2. Have a user stake into `DelegateVoteRewardPool` so `_updateVote()` casts votes, setting `userVotedForPoolInVlmgp[delegatedPool][lp] > 0` for at least one pool.
3. Simulate bribe accrual on that pool's `rewarder` (e.g., via `queueNewRewards`/`donateRewards`) so `earned(delegatedPool, token) > 0`.
4. As an arbitrary EOA (not `delegatedPool`, not owner), call `wombatBribeManager.claimAllBribes(delegatedPool)` directly.
5. Assert: `IERC20(rewardToken).balanceOf(delegatedPool)` increased by the bribe amount, while `DelegateVoteRewardPool.rewards(rewardToken).rewardPerTokenStored` remains unchanged (0 or unmodified) — proving tokens are stuck and unaccounted.
6. Call `DelegateVoteRewardPool.harvestAll()` afterward and assert it queues 0 new rewards for that token (since `earned` was already reset to 0), confirming the tokens are permanently unclaimable by any staker.

    function _manageRewards(
        address[] memory rewardTokensList,
        uint256[] memory earnedRewards
    ) internal {
        uint256 length = rewardTokensList.length;
        for (uint256 index = 0; index < length; ++index) {
            uint256 fees = (protocolFee * earnedRewards[index]) / DENOMINATOR;
            if (fees > 0 && feeCollector != address(0)) {
                earnedRewards[index] = earnedRewards[index] - fees;
                IERC20(rewardTokensList[index]).safeTransfer(
                    feeCollector,
                    fees
                );
            }
            if (earnedRewards[index] > 0) {
                _queueNewRewardsWithoutTransfer(
                    earnedRewards[index],
                    rewardTokensList[index]
                );
            }
        }
    }

    /// @notice Sends new rewards to be distributed to the users staking.
    /// @param _amountReward Amount of reward token to be distributed
    /// @param _rewardToken Address reward token
    function _queueNewRewardsWithoutTransfer(
        uint256 _amountReward,
        address _rewardToken
    ) internal {
        if (!isRewardToken[_rewardToken]) {
            rewardTokens.push(_rewardToken);
            isRewardToken[_rewardToken] = true;
        }
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (totalSupply == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10 ** this.stakingDecimals()) /
                totalSupply;
        }
        emit RewardAdded(_amountReward, _rewardToken);
    }
