### Title
Missing LowerBoundBaseFee/UpperBoundBaseFee consistency check in contract-based governance parameter application - (File: kaiax/gov/contractgov/impl/getter.go, kaiax/gov/paramset.go)

### Summary
`kaiax/gov/headergov` enforces a cross-parameter consistency check ensuring `Kip71LowerBoundBaseFee` cannot exceed `Kip71UpperBoundBaseFee` (and vice versa) when governance parameters are changed via block-header votes. However, this exact check is absent from the contract-based governance path (`ContractGovModule`), which reads and applies the `KIP71` parameters directly from the `GovParam` contract without any cross-validation between the lower and upper bound.

### Finding Description
In the header-vote governance path, `checkConsistency` explicitly validates that a new `Kip71LowerBoundBaseFee` vote is not greater than the current `UpperBoundBaseFee`, and that a new `Kip71UpperBoundBaseFee` vote is not lower than the current `LowerBoundBaseFee`: [1](#0-0) 

This is the direct analog of the reported `FlatcoinVault.setExecutabilityAge` issue — a min/max pair of governance-controlled bounds that must maintain `min <= max` or the derived mechanism breaks.

By contrast, `Kip71LowerBoundBaseFee` and `Kip71UpperBoundBaseFee` are declared in the shared `Params` table with only a `noopFormatChecker` (no bound relationship enforced), and are applied via `ParamSet.Set`, which performs a bare type assertion with no cross-field validation: [2](#0-1) [3](#0-2) 

`ContractGovModule.GetParamSet` merges these raw contract-sourced values into the parameter set with the same unchecked `Set` call, and explicitly documents that "invalid parameters in the contract... are ignored" only for type/format errors, not value-relationship errors: [4](#0-3) 

Since `GovModule.GetParamSet` layers `ContractGovModule`'s partial param set on top of the header-vote-derived set post-Kore, a `LowerBoundBaseFee > UpperBoundBaseFee` combination set via the `GovParam` contract (the primary governance mechanism after the Kore hardfork) is accepted with no equivalent guard: [5](#0-4) 

The resulting inconsistent `KIP71Config` is then used directly to compute every block's base fee: [6](#0-5) 

### Impact Explanation
`NextMagmaBlockBaseFee` clamps `parentBaseFee` between `lowerBoundBaseFee` and `upperBoundBaseFee` and computes deltas relative to `gasTarget`. If `lowerBoundBaseFee > upperBoundBaseFee`, the clamp/delta logic produces an ill-defined result (e.g., the "shortcut" comparisons against `upperBoundBaseFee`/`lowerBoundBaseFee` can conflict, and `makeEvenByCeil`/`makeEvenByFloor` on out-of-order bounds can yield a base fee that violates one of the intended bounds). Because this computation determines the base fee that **every transaction sender network-wide** must pay to be included, a misconfigured bound pair can force gas price to an unintended extreme (e.g., permanently pinned to an unreasonably high value), effectively causing a network-wide denial of service on transaction inclusion — directly matching the "DoS due to lack of a valid operating range" impact class in the reference report.

### Likelihood Explanation
Exploitation requires control over the `GovParam` contract (the parameter-setting authority, e.g., contract owner/governance council), which is a privileged actor — the same privilege level required for the original `FlatcoinVault.setExecutabilityAge` (an owner/admin-only setter). Given that governance-parameter configuration is an explicitly in-scope analog category, and that the header-vote path already had to add this exact guard (indicating it is a recognized real risk in this codebase), a misconfiguration or malicious governance action through the contract path is a realistic and low-effort trigger — it's a single contract call setting one of the two KIP-71 bound parameters without needing to compromise consensus, cryptography, or the P2P layer.

### Recommendation
Add the same cross-field consistency validation used in `headergov`'s `checkConsistency` to the contract-based path — either inside `ContractGovModule.GetParamSet`/`GetPartialParamSet` before merging, or centrally in `ParamSet.Set`/`SetFromMap`, so that any attempt to apply `Kip71LowerBoundBaseFee > Kip71UpperBoundBaseFee` (from either governance source) is rejected/ignored and falls back to the previous valid values, exactly as done for header votes: [1](#0-0) 

### Proof of Concept
1. Governance council (owner of the `GovParam` contract, or via a passed governance proposal) calls `GovParam.setParam("kip71.lowerboundbasefee", true, <value greater than current upperboundbasefee>, activationBlock)`.
2. At `activationBlock`, `ContractGovModule.GetParamSet` reads this raw value and calls `ParamSet.Set(Kip71LowerBoundBaseFee, value)`, which only checks the Go type (`uint64`), not the relationship to `UpperBoundBaseFee`.
3. `GovModule.GetParamSet` merges this into the effective `ParamSet` with no rejection, unlike the analogous header-vote path (`checkConsistency`) which would reject such a vote.
4. From the activation block onward, `KIP71Config.NextMagmaBlockBaseFee` (`params/kip71_config.go`) computes base fees using inconsistent `lowerBoundBaseFee > upperBoundBaseFee`, producing base fee values that do not conform to the intended fee bounds and can degrade or effectively halt normal transaction submission for all users network-wide.

// GetParamSet returns default parameter set in case of the following errors:
// (1) contractgov is disabled (i.e., pre-Kore or GovParam address is zero)
// (2) GovParam address is not set
// (3) Contract call to GovParam failed
// Invalid parameters in the contract (i.e., invalid parameter name or non-canonical value) are ignored.
func (c *contractGovModule) GetParamSet(blockNum uint64) gov.ParamSet {
	m, err := c.contractGetAllParamsAt(blockNum)
	if err != nil {
		return *gov.GetDefaultGovernanceParamSet()
	}

	ret := *gov.GetDefaultGovernanceParamSet()
	for k, v := range m {
		err = ret.Set(k, v)
		if err != nil {
			return *gov.GetDefaultGovernanceParamSet()
		}
	}

	return ret
}

func (kc *KIP71Config) NextMagmaBlockBaseFee(parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) *big.Int {
	// governance parameters
	lowerBoundBaseFee := new(big.Int).SetUint64(kc.LowerBoundBaseFee)
	upperBoundBaseFee := new(big.Int).SetUint64(kc.UpperBoundBaseFee)
	makeEvenByCeil(lowerBoundBaseFee)
	makeEvenByFloor(upperBoundBaseFee)

	// If the parent is the magma disabled block or genesis, then return the lowerBoundBaseFee (default 25ston)
	if parentHeaderNumber.Cmp(new(big.Int).SetUint64(0)) == 0 || parentHeaderBaseFee == nil {
		return makeEvenByFloor(lowerBoundBaseFee)
	}
