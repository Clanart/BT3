### Title
Gasless bundle re-execution skips deadline revalidation, allowing bundling of expired swaps that front KAIA with no repayment guarantee - (File: `kaiax/gasless/impl/tx_pool.go`, `kaiax/gasless/impl/getter.go`)

### Summary
In the gasless module, `checkBalanceForSwap` validates `swapArgs.Deadline >= currentBlockTime` [1](#0-0)  but this check only runs once, at tx-pool admission time via `GetCheckBalance()` [2](#0-1) . The subsequent gate that actually decides whether a `LendTx` (which unconditionally sends native KAIA to the sender) is generated and bundled — `VerifyExecutable`/`IsExecutable`, invoked from `isSwapTxReady`/`isApproveTxReady` at promotion time and from `ExtractTxBundles` at block-building time — never re-checks the deadline [3](#0-2) , [4](#0-3) .

### Finding Description
The gasless flow works by pairing an `ApproveTx`/`SwapTx` with a synthetic `LendTx` that fronts KAIA to the sender so they can pay gas, expecting the bundled `SwapTx` to swap ERC20 tokens for KAIA and repay the lender (`AmountRepay`) in the same block [4](#0-3) . The `SwapArgs.Deadline` field is meant to bound how stale a swap execution can be before the on-chain router should reject it [5](#0-4) .

The deadline is only validated in `checkBalanceForSwap`, which is wired as `GetCheckBalance()` and used by the tx pool at the time the transaction is first admitted/validated [2](#0-1) , [1](#0-0) . However, `VerifyExecutable` — the function that decides `IsExecutable` used both for tx-pool promotion (`isApproveTxReady`, `isSwapTxReady`) and for actual block-building bundling (`ExtractTxBundles`) — checks Ax/Sx/AP1/SP1-SP4 conditions (sender match, token match, allowance, nonce sequencing, repay amount correctness) but has no deadline check whatsoever [3](#0-2) . A transaction can sit in the pool (subject to `PendingTimeout`/`QueueTimeout`/`KnownTxTimeout` of up to 30 seconds [6](#0-5) ) or be delayed across block-building attempts, and by the time `ExtractTxBundles` generates the `LendTx` for it [4](#0-3) , the block time may have advanced past `Deadline` — yet the bundling logic proceeds anyway since deadline is never re-checked at that stage.

This mirrors the audited Carapace bug class: a time-bound condition is validated once against a "current" reference timestamp, but the actual settlement/accrual action executes later using stale validation, without re-verifying that the condition still holds at execution time.

### Impact Explanation
If a swap's deadline has expired by the time the bundle (`LendTx + ApproveTx + SwapTx`) is actually included in a block, the on-chain `GaslessSwapRouter.swapForGas` call is expected to revert due to its own deadline check inside the contract. Since `LendTx`, `ApproveTx`, and `SwapTx` are packaged into a single atomic bundle via `builder.NewBundle`, if the swap reverts, the entire bundle may fail atomically depending on the bundle execution semantics — meaning value movement risk depends on whether bundle atomicity is enforced by the `builder` package. If it is not strictly atomic (e.g., partial application, or if the `LendTx` from the block proposer's own key is applied regardless of subsequent tx failure within the same bundle build attempt), the block proposer's fronted KAIA is not repaid, resulting in a direct value loss to the proposer/lender for every expired swap that still gets bundled. Even if atomicity fully protects the proposer from value loss, the missed deadline re-check remains a correctness gap that lets expired user intents be needlessly re-processed by the block-building pipeline, wasting proposer compute/bundling resources on doomed-to-revert transactions and delaying valid transaction inclusion — a lesser but still real relevant impact under "gasless settlement" scope.

### Likelihood Explanation
This requires only ordinary tx-pool timing/latency: submit a gasless swap transaction with a `Deadline` close to the current time, and let normal network/block-production delay (or `KnownTxTimeout`'s 30-second window) elapse before the transaction is picked up for bundling. No malicious peer, node, or validator collusion is needed — any regular gasless swap user or a submitter deliberately setting `Deadline` to a value just past the pool-admission check timestamp can trigger the condition. This is a straightforward "normal transaction submission" reachable path.

### Recommendation
Re-validate `swapArgs.Deadline` against the current (about-to-be-produced) block's timestamp inside `VerifyExecutable` in `kaiax/gasless/impl/getter.go`, in addition to the pool-admission check in `checkBalanceForSwap`. This ensures `ExtractTxBundles` and the `isReady`/promotion path in `tx_pool.go` never bundle or promote a swap whose deadline has already passed relative to the block currently being assembled, closing the gap between admission-time validation and execution-time bundling.

### Proof of Concept
1. A user submits an `ApproveTx` + `SwapTx` pair through `GaslessAPI.IsGaslessTx`/normal tx submission, with `SwapArgs.Deadline` set to a timestamp only slightly in the future (e.g., current block time + a few seconds) — this passes the initial `checkBalanceForSwap` deadline check at admission [1](#0-0) .
2. Due to normal network/block timing, several seconds elapse (well within the module's own `PendingTimeout`/`KnownTxTimeout` windows of up to 30s) [6](#0-5)  before the block containing this tx is actually assembled.
3. When `ExtractTxBundles` runs during block building, it calls `GetLendTxGenerator`/`IsExecutable` via `VerifyExecutable`, which validates all Ax/Sx/AP/SP conditions but never re-checks `Deadline` against the new block's timestamp [3](#0-2) , so the bundle (including the `LendTx` fronting native KAIA) is still generated and included [4](#0-3) .
4. On execution, the router's on-chain deadline check causes `SwapForGas` to revert, so the token-for-KAIA repayment to the lender never occurs, while the `LendTx`'s fronted value transfer is a separate transaction whose independent success/failure depends on bundle atomicity guarantees not verified in this analysis.

func (g *GaslessModule) GetCheckBalance() func(tx *types.Transaction) error {
	return func(tx *types.Transaction) error {
		if approveArgs, ok := decodeApproveTx(tx, g.signer); ok {
			return g.checkBalanceForApprove(approveArgs)
		}
		if swapArgs, ok := decodeSwapTx(tx, g.signer); ok {
			return g.checkBalanceForSwap(swapArgs, tx.Nonce())
		}
		return errors.New("not a gasless transaction") // should not happen because IsModuleTx is called before GetCheckBalance
	}
}

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
