### Title
`isGitHubHost()` classifies attacker-controlled domains as GitHub hosts via substring match instead of exact/suffix validation - ([File: app/src/lib/api.ts])

### Summary
The LSP20 report's broken invariant is "accept anything that *starts with* the required exact value instead of requiring an exact match." The same pattern exists in GitHub Desktop's `isGitHubHost()` helper, which is supposed to authoritatively decide whether a git remote's host is a genuine GitHub/GHE instance before the credential helper treats it as one. Instead of validating that the hostname *is* (or is a proper subdomain of) `github.com`/`*.ghe.com`, it falls back to a loose regex test (`/(^|\.)(github)\./`) that matches any hostname merely containing the literal substring `github.` — a string any attacker can trivially include in a domain they own.

### Finding Description
`isGitHubHost()` first checks the real, hardened predicates `isDotCom()`/`isGHE()` [1](#0-0) , which do exact hostname equality (`github.com`/`api.github.com`) or exact `.ghe.com` suffix checks [2](#0-1) . If those fail and the host isn't a known third party, it falls through to:

```
// github.example.com,
if (/(^|\.)(github)\./.test(hostname)) {
  return true
}
``` [3](#0-2) 

This regex is anchored only on the literal token `github.` appearing at the start of the hostname or immediately after a dot — it says nothing about the *suffix* of the domain (the actual owner). Any attacker who registers or controls a domain can create a subdomain like `github.attacker-domain.com` or `sub.github.attacker-domain.com` and this check returns `true`, exactly mirroring the LSP20 bug of accepting any value that starts with the expected magic bytes instead of requiring the full, exact expected value.

`isGitHubHost()` is consumed by the git credential helper's `getEndpointKind()` to decide whether an unauthenticated host should be treated as `'enterprise'` (prompt user to sign in to GitHub Enterprise) versus `'generic'` (treated as an ordinary/non-GitHub credential target) [4](#0-3) . When git needs credentials for a remote URL — driven entirely by the (attacker-controlled) remote/clone URL — and no account already exists for that endpoint, `getCredential()` calls `ui.promptForGitHubSignIn(endpoint)` for any endpoint classified as non-generic [5](#0-4) . The misclassification therefore causes the user to be shown a "Sign in to GitHub Enterprise" flow pointed at the attacker's server rather than being handled as a generic/unknown git host.

### Impact Explanation
An attacker who controls (or can register) any domain can craft a git remote/clone URL such as `https://github.attacker-domain.com/foo/bar.git`. If a victim clones or fetches from that URL in Desktop, the credential helper misclassifies the host as GitHub Enterprise due solely to the substring match, and the user is directed into Desktop's GitHub Enterprise sign-in / OAuth flow against attacker infrastructure. This is a phishing-primitive with a legitimate UI (the app itself initiates the prompt, not a spoofed page), potentially leading to credential/token exfiltration or an unwanted OAuth binding to an attacker-controlled "enterprise" endpoint — matching the report's category of unauthorized OAuth/account binding driven by attacker-controlled remote content.

### Likelihood Explanation
The only precondition is that the victim adds or clones from an attacker-supplied remote URL containing the substring `github.` — a routine, no-privilege attacker action requiring nothing more than domain registration, no local access, no prior compromise. The existing guards (`isDotCom`, `isGHE`, `isKnownThirdPartyHost`) do not stop this path because they run first and simply fail to match, falling through to the vulnerable substring check.

### Recommendation
Replace the substring-based heuristic with a strict, exact-domain check equivalent to `isGHE`/`isDotCom`: require the hostname to equal `github.com`/`api.github.com` or end with a validated enterprise suffix, and remove/tighten the generic `github.` substring heuristic so it cannot match attacker-chosen subdomains of arbitrary domains.

### Proof of Concept
1. Attacker registers `attacker-domain.com` and creates DNS/host `github.attacker-domain.com` (or `foo.github.attacker-domain.com`) serving an HTTPS git repo.
2. Victim clones `https://github.attacker-domain.com/foo/bar.git` in GitHub Desktop.
3. Git requests credentials via Desktop's trampoline credential helper; `getEndpointKind()` calls `isGitHubHost('https://github.attacker-domain.com')`.
4. `isDotCom`/`isGHE`/`isKnownThirdPartyHost` all return false; the regex `/(^|\.)(github)\./.test('github.attacker-domain.com')` returns `true`, so `isGitHubHost` returns `true` and `getEndpointKind` returns `'enterprise'` [3](#0-2) .
5. `getCredential()` finds no existing account for the derived enterprise API endpoint and calls `ui.promptForGitHubSignIn(endpoint)`, presenting the victim with an in-app "Sign in to GitHub Enterprise" flow targeting the attacker's host [5](#0-4) .

Note: I could not fully trace the exact downstream token-handling code inside `promptForGitHubSignIn`/`trampoline-ui-helper.ts` before running out of investigation budget, so the precise mechanism by which credentials would reach the attacker (OAuth redirect vs. basic-auth submission) is not fully confirmed from local code alone — this would need a Devin session with full file access to verify end-to-end.

export const isDotCom = (ep: string) => {
  if (ep === getDotComAPIEndpoint()) {
    return true
  }

  const { hostname } = new URL(ep)
  return hostname === 'api.github.com' || hostname === 'github.com'
}

export const isGist = (ep: string) => {
  const { hostname } = new URL(ep)
  return hostname === 'gist.github.com' || hostname === 'gist.ghe.io'
}

/** Whether or not the given endpoint URI is under the ghe.com domain */
export const isGHE = (ep: string) => new URL(ep).hostname.endsWith('.ghe.com')

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
