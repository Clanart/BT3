### Title
Server-Side Request Forgery via unauthenticated DataLayer mirror coins - (File: `chia/data_layer/data_layer_wallet.py`)

### Summary
Any unprivileged wallet user (a "single spend bundle submitter") can create a DataLayer "mirror" coin for **any** store id with an arbitrary attacker-controlled URL in the coin memo, with no signature, ownership, or scheme/host validation tying the URL to the actual store owner. When any other node subscribes to that store id, `DataLayer.fetch_and_validate()`/`insert_from_delta_file()`/`download_file()` will make outbound HTTP(S) or plugin-POST requests to that attacker-chosen URL, exactly the SSRF bug class described in the CAI Content Credentials advisory (CVE-2026-47922), where a maliciously crafted resource reference causes an unwanted outbound request.

### Finding Description
The DataLayer "mirror" mechanism uses a fully public, unauthenticated puzzle: `create_mirror_puzzle()` in `chia/wallet/db_wallet/db_wallet_puzzles.py:90-94` is simply `P2_PARENT.curry(Program.to(1))` — a puzzle with no owner-specific key or restriction. Any spend bundle can create a `CREATE_COIN` output to `MIRROR_PUZZLE_HASH` and attach arbitrary memos: `memos[0]` = any `launcher_id` (store id) and `memos[1:]` = arbitrary URL strings, per `get_mirror_info()` in `chia/wallet/db_wallet/db_wallet_puzzles.py:97-110`.

There is no check anywhere in the mirror-parsing/wallet code that the coin creator is the actual DataLayer singleton owner for that `launcher_id` — the mirror's validity is purely "did a coin get created with this puzzle hash and these memos," which any wallet user can trigger with a normal transaction.

On the consuming side, `DataLayer.get_mirrors()`/`update_subscriptions_from_wallet()` (`chia/data_layer/data_layer.py:975-985`) blindly takes these attacker-supplied URLs and stores them as subscription server URLs. `fetch_and_validate()` (`chia/data_layer/data_layer.py:642-706`) later iterates these URLs and calls `insert_from_delta_file()` → `download_file()` → `http_download()` (`chia/data_layer/download_data.py:110-169`, `298-346`), which does:
```python
async with session.get(server_info.url + "/" + filename, headers=headers, timeout=timeout, proxy=proxy_url)
```
with no scheme allowlist, no blocking of private/loopback/link-local addresses (e.g., `http://169.254.169.254/...` cloud metadata, `http://127.0.0.1:<internal-port>/...`), and no restriction preventing `file://`-like or internal-network targets other than what `aiohttp` itself would reject. The same applies to the downloader-plugin path, which POSTs to `downloader.url + "/handle_download"` (`chia/data_layer/data_layer.py:731-747`) using a plugin-configured host, and to the S3 plugin's `handle_download`/`download` endpoints (`chia/data_layer/s3_plugin_service.py:241-303`) which trust `data["url"]` as long as it matches a configured store's known URL list — but the store's known URL list itself is fed from these same unauthenticated on-chain mirror coins.

This matches the CWE-918 pattern in the advisory: a resource reference (URL) that is meant to identify content is instead used to make a server-side outbound request, and the reference is attacker-influenceable rather than trust-anchored, causing privilege/network-boundary crossing (local subscriber's server making requests into networks the operator/DataLayer node can reach, e.g., cloud metadata endpoints, internal admin services).

### Impact Explanation
Any node running the `DataLayer` service and subscribing to a store (which is a completely normal, low-privilege DataLayer client operation, `chia/data_layer/data_layer.py:979-985`) can be coerced into issuing outbound HTTP requests to attacker-chosen internal or external hosts by any third party who spends a small amount of XCH to create a mirror coin naming that store id. This is a classic internal-network reconnaissance / cloud-metadata-exfiltration primitive (SSRF), and it can also be used as a denial-of-service/resource-exhaustion vector against the victim node by pointing many mirrors at slow or malicious endpoints. It does not directly forge assets or move coins, but it satisfies the "unauthorized read/side effect via server-triggered outbound request" bug class from the advisory, reachable purely from an unprivileged wallet action (spend bundle) rather than a malicious peer/node.

### Likelihood Explanation
Likelihood is high for triggering (any wallet holder can create such a coin trivially, no special privilege, no coordination with the actual singleton owner) but requires the victim to actually run a `DataLayer` service and be subscribed to (or auto-subscribed/pseudo-subscribed to) the targeted store id for the SSRF request to fire, similar to the "user interaction" requirement noted in the source advisory (a victim must sync/subscribe to the store). Given DataLayer subscription and mirror-following is a designed, automatic background behavior (`periodically_manage_data()`), exploitation only requires the attacker to know or guess/target a store id that some victim already subscribes to.

### Recommendation
Validate mirror URLs before use: enforce an allow-list of schemes (http/https only), reject loopback/link-local/private-IP targets by default (with an explicit opt-in for local testing), and require some authenticated linkage between a mirror coin and the store's legitimate owner/administrator (e.g., signature check, or restrict which mirrors are trusted to those explicitly configured/approved by the local operator rather than any coin found on-chain). At minimum, apply the same SSRF-hardening validation to `http_download()`, `get_downloader()`, and the S3 plugin's `handle_download`/`download` handlers.

### Proof of Concept
1. Attacker crafts and submits a standard spend bundle that creates a coin with puzzle hash `MIRROR_PUZZLE_HASH` (`chia/wallet/db_wallet/db_wallet_puzzles.py:94`) and memos `[victim_store_launcher_id, b"http://169.254.169.254/latest/meta-data/"]`.
2. This spend is accepted by mempool/consensus like any normal coin creation — no signature tying it to the DataLayer singleton owner is required (`get_mirror_info`, `chia/wallet/db_wallet/db_wallet_puzzles.py:97-110`).
3. A victim node subscribed to `victim_store_launcher_id` calls `update_subscriptions_from_wallet()` (`chia/data_layer/data_layer.py:979-985`), which pulls this malicious URL in via `dl_get_mirrors` and stores it as a subscription server.
4. On the next sync cycle, `fetch_and_validate()` (`chia/data_layer/data_layer.py:642-706`) picks this server and calls `insert_from_delta_file()` → `download_file()` → `http_download()` (`chia/data_layer/download_data.py:298-318`), causing the victim node to issue `GET http://169.254.169.254/latest/meta-data/<generated-filename>` — an SSRF request to an attacker-chosen host, entirely driven by attacker-controlled on-chain memo data. def create_mirror_puzzle() -> Program:
    return P2_PARENT.curry(Program.to(1))


MIRROR_PUZZLE_HASH = create_mirror_puzzle().get_tree_hash()


def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")

    async def get_downloader(self, store_id: bytes32, url: str) -> PluginRemote | None:
        request_json = {"store_id": store_id.hex(), "url": url}
        for d in self.downloaders:
            async with aiohttp.ClientSession() as session:
                try:
                    async with session.post(
                        d.url + "/handle_download",
                        json=request_json,
                        headers=d.headers,
                        timeout=self.client_timeout,
                    ) as response:
                        res_json = await response.json()
                        if res_json["handle_download"]:
                            return d
                except Exception as e:
                    self.log.error(f"get_downloader could not get response: {type(e).__name__}: {e}")

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")

    async def download(self, request: web.Request) -> web.Response:
        try:
            data = await request.json()
            url = data["url"]
            filename = data["filename"]
            group_files_by_store = data.get("group_files_by_store", False)
            max_delta_file_size = data.get("max_delta_file_size")
            if not isinstance(max_delta_file_size, int) or max_delta_file_size <= 0:
                max_delta_file_size = 250

            # filename must follow the DataLayer naming convention
            if not is_filename_valid(filename, group_files_by_store):
                return web.json_response({"downloaded": False})

            # Pull the store_id from the filename to make sure we only download for configured stores
            filename_store_id = bytes32.fromhex(filename[:64])
            parse_result = urlparse(url)
            should_download = False
            for store in self.stores:
                if store.id == filename_store_id and parse_result.scheme == "s3" and url in store.urls:
                    should_download = True
                    break

            if not should_download:
                return web.json_response({"downloaded": False})

            bucket_str = parse_result.netloc
            my_bucket = self.boto_resource.Bucket(bucket_str)
            trimmed_filename = filename[65:] if group_files_by_store else filename
