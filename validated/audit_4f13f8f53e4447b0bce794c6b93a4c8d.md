Confirmed: `Pallet::<T>::execute` at [1](#0-0)  accepts an arbitrary caller-supplied `Vec<Message>` in a single permissionless call, executes every message with `handle_incoming_message`, flattens all resulting `IsmpEvent`s from the whole batch, and hands the **entire batch of messages + entire flattened event list** to `T::FeeHandler::on_executed`. The consensus-incentives handler then derives the reward recipient **only from `messages[0]`** and pays it for every `StateMachineUpdated` event in the whole batch.

### Title
Consensus-incentive rewards for an entire message batch are paid to the signer of the first message only, letting anyone steal other relayers' rewards - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet_consensus_incentives::on_executed` extracts the relayer identity from `messages.get(0)` and then uses that single identity to reward **every** `StateMachineUpdated` event produced by the whole batch, regardless of which message in the batch actually produced which event.

### Finding Description
`Pallet::<T>::execute` builds `messages_with_weights` and `events` from an arbitrary, permissionlessly-submitted `Vec<Message>` and passes both to `FeeHandler::on_executed` as one call [2](#0-1) .

Inside `pallet_consensus_incentives`, `on_executed` computes `maybe_relayer_account` solely from `messages.get(0)` by recovering the sr25519 pubkey from that first message's `signer`/`consensus_proof` [3](#0-2) . It then iterates over **all** `StateMachineUpdated` events in the batch (collapsed per `state_machine_id` to the highest height) and calls `process_message` for each one using that single `relayer_account` [4](#0-3) , transferring treasury funds and minting reputation to it [5](#0-4) .

The invariant that breaks here is directly analogous to the ChainlinkARBOracle bug: the code assumes a rigid 1:1/sequential relationship ("the reward-worthy event corresponds to the first item") instead of actually tracing which message produced which event. Just as `_getPrevChainlinkResponse` blindly assumes `roundId - 1` is the correct predecessor without verifying the relationship, `on_executed` blindly assumes "first message in the batch = signer for all consensus-driven state advances in the batch" without verifying that the events it is paying for actually originated from that message. A permissionless caller assembling the batch (this call has no origin/authorization restriction other than being a valid ISMP message set) can place their own cheap/self-produced `ConsensusMessage` as `messages[0]`, then append other genuine consensus messages (for other state machines, potentially signed/submitted originally by other relayers) later in the same batch; every `StateMachineUpdated` event across the whole batch — including those produced by the other relayers' messages — is paid to the attacker's key.

### Impact Explanation
This is a direct "wrong beneficiary" fund-diversion bug in the reward/incentive path: treasury funds intended for the relayers who actually delivered specific consensus updates for specific state machines can be redirected entirely to whoever controls the first message in a batch. This matches the required impact class of stealing/loss of funds and unauthorized transaction manipulation, since it lets an unprivileged actor claim rewards for work they did not do, at the expense of the treasury and honest relayers.

### Likelihood Explanation
The only requirement is the ability to submit a batch of ISMP messages via the public `execute` entrypoint, which is explicitly designed to accept a permissionless `Vec<Message>` (no per-message check ties the reward recipient to the specific message that generated a given event). No malicious relayer, prover, admin, or leaked key is needed — the attacker only needs to be an unprivileged sender of the extrinsic and be able to craft (or observe and re-batch) any valid `ConsensusMessage` as the first element while including other pending/valid consensus proofs afterward. This makes the likelihood high in any deployment using `pallet_consensus_incentives`.

### Recommendation
Rework `on_executed` to associate each `StateMachineUpdated` event with the specific `ConsensusMessage` (and its recovered signer) that produced it, rather than using `messages.get(0)` for the whole batch. Concretely, iterate the batch pairing each `Message::Consensus` with the exact subset of `IsmpEvent::StateMachineUpdated` events it generated (e.g., by having `handle_incoming_message`/`MessageResult::ConsensusMessage` return events scoped per source message) and reward that message's own recovered relayer only for that message's events.

### Proof of Concept
1. Attacker crafts/obtains a valid `Message::Consensus` (`msg_A`) that they can sign — this can be minimal, e.g., a no-op or low-cost consensus update they generate themselves, and place it as element `[0]` of the batch.
2. Attacker observes or otherwise assembles additional independently-valid `Message::Consensus` items (`msg_B`, `msg_C`, ...) targeting other state machines — for example, previously broadcast valid consensus proofs, which are public data on the network — and appends them after `msg_A` in the same `Vec<Message>` sent to `Pallet::<T>::execute`.
3. `execute` runs `handle_incoming_message` on each message successfully, producing `StateMachineUpdated` events for every state machine advanced by `msg_A`, `msg_B`, `msg_C`, etc., then flattens them all into one `events` vector [6](#0-5) .
4. `pallet_consensus_incentives::on_executed` recovers only `msg_A`'s signer as `relayer_account` [7](#0-6)  and pays that account the reward for every distinct `state_machine_id` present in the combined event set [8](#0-7) , including rewards that should have gone to whoever actually produced `msg_B`/`msg_C`.
5. Result: the attacker's account receives treasury funds and reputation-asset mints for state-machine advances they did not perform, at the expense of the treasury and the legitimate relayers.

Note: I was not able to fully trace how `execute`/`handle_unsigned` is exposed as an extrinsic (its exact call-site, weight/fee gating, and whether any additional origin checks exist) beyond what is shown in `modules/pallets/ismp/src/impls.rs`; a Devin session with full repo access should confirm the exact dispatchable wrapper and its `ensure_none`/`ensure_signed` origin to fully validate that this path is reachable by an arbitrary unprivileged account before remediation.

	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

		let message_results = messages
			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		let messages_with_weights = message_results
			.iter()
			.zip(messages)
			.map(|(result, message)| MessageWithWeight { message, weight: result.weight() })
			.collect::<Vec<_>>();

		let events = message_results
			.into_iter()
			// check that requests will be successfully dispatched
			// so we can not be spammed with failing txs
			.map(|result| match result {
				MessageResult::Request { events, .. } |
				MessageResult::Response { events, .. } |
				MessageResult::Timeout { events, .. } => events,
				MessageResult::ConsensusMessage(events) => events.into_iter().map(Ok).collect(),
				MessageResult::FrozenClient(_) => vec![],
			})
			.flatten()
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		T::FeeHandler::on_executed(messages_with_weights, events.clone())
			.map_err(|_| Error::<T>::ErrorChargingFee)?;

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});
