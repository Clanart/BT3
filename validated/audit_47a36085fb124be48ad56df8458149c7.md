### Title
Symlinked `.gitignore` allows arbitrary file write via `saveGitIgnore` - (File: `app/src/lib/git/gitignore.ts`)

### Summary
`saveGitIgnore` builds the target path with a plain `Path.join(repository.path, '.gitignore')` and passes it directly to `writeFile`, with no check for whether `.gitignore` (or any parent segment) is a symlink pointing outside the repository.

### Finding Description
`saveGitIgnore` computes `ignorePath` via `Path.join(repository.path, '.gitignore')` and then calls `FS.unlink(ignorePath, ...)` (when clearing) or `writeFile(ignorePath, fileContents)` (when saving) without ever resolving/validating the real path. [2](#0-1) 
Node's `fs.writeFile`/`fs.unlink` follow symlinks by default (no `O_NOFOLLOW`), so if the working tree at `.gitignore` is actually a symbolic link — which git can create during checkout of a maliciously crafted repository when the tracked blob is a symlink mode entry (`120000`) — the write (or delete) operation will follow the link and act on whatever target it points to, including a path outside the repository.

The codebase already has infrastructure to prevent exactly this class of bug: `resolveWithin` in `app/src/lib/path.ts` resolves a path via `realpath` and verifies the real, symlink-resolved path stays under the intended root, returning `null` otherwise. [3](#0-2) 
This helper is used elsewhere in the codebase (e.g. `app/src/lib/stores/app-store.ts`, `app/src/ui/dispatcher/dispatcher.ts`) precisely to guard against symlink-based path traversal, but `gitignore.ts`'s `readGitIgnoreAtRoot`, `saveGitIgnore`, `appendIgnoreRule`, and `appendIgnoreFile` do not use it at all.

### Impact Explanation
If exploitable, an attacker who controls a cloned repository could commit a symlink named `.gitignore` (or a directory component leading to it) pointing to a sensitive out-of-repo file (e.g. a config file, an SSH key, a startup script). If the victim opens the "Ignore Files" tab in Repository Settings and clicks Save (or triggers the flow that calls `appendIgnoreFile`/`appendIgnoreRule`, such as the "Ignore file" context-menu action referenced in `app/src/ui/changes/sidebar.tsx`), `writeFile`/`unlink` would follow the symlink and modify/delete the external target instead of the repo's `.gitignore`. This matches the "file write outside the repo" impact category.

### Likelihood Explanation
Exploitability depends on platform behavior that I was not able to fully verify within the available tooling/index:
- On macOS/Linux, git checks out tracked symlink entries as real filesystem symlinks by default (`core.symlinks=true`), so a malicious repo can plant a symlinked `.gitignore` that survives clone/checkout.
- On Windows, without Developer Mode/admin privileges, git typically materializes symlink entries as regular text files containing the link target rather than actual symlinks, which would likely neutralize this specific vector — but I could not confirm the exact `core.symlinks` handling/config used by this app's clone path (`app/src/lib/git/clone.ts`) in this codebase.
- Triggering the write requires the user to open the Git Ignore settings and click Save (or use "Ignore file" from the changes list), which is a normal, low-friction interaction rather than an "unnatural" step, and does not require existing checks to be bypassed since no path-containment check currently exists here (unlike `clone.ts`'s `isClonePathSensitive` or `path.ts`'s `resolveWithin`, which are absent from `gitignore.ts`).

I was unable to fully verify within the current session whether any other layer (e.g., git checkout protections, symlink policy enforced elsewhere in the app, or OS-level sandboxing) mitigates this before `saveGitIgnore` is ever reached; a Devin session with full repo/checkout access would be needed to confirm end-to-end reproducibility (clone a crafted repo with a symlinked `.gitignore`, then trigger Save).

### Recommendation
Use the existing `resolveWithin` helper (`app/src/lib/path.ts`) to resolve `.gitignore` relative to `repository.path` before any read/write/unlink in `app/src/lib/git/gitignore.ts`, and abort (or fall back to a safe default) if the resolved real path is not contained within the repository root, mirroring the pattern already used in `app/src/lib/stores/app-store.ts` and `app/src/lib/git/clone.ts`'s `isClonePathSensitive` check. ### Proof of Concept
1. On macOS/Linux, create a malicious repository where `.gitignore` is committed as a symlink (mode `120000`) pointing to an out-of-repo file, e.g. `~/.ssh/known_hosts` or another sensitive path.
2. Have the victim clone this repository with GitHub Desktop.
3. Victim opens Repository → Repository Settings → Git Ignore, edits the text, and clicks Save (which invokes `saveGitIgnore`, `app/src/lib/git/gitignore.ts:40`), or right-clicks a file in the Changes list and selects "Ignore file" (invoking `appendIgnoreFile`/`appendIgnoreRule` in the same file, referenced from `app/src/ui/changes/sidebar.tsx`).
4. `writeFile(ignorePath, fileContents)` follows the symlink and overwrites the external target file's contents (or `unlink` deletes it, if the text field is cleared), confirming write/delete outside the intended repository directory.

```typescript
async function _resolveWithin(
  rootPath: string,
  pathSegments: string[],
  options: {
    join: (...pathSegments: string[]) => string
    normalize: (p: string) => string
    resolve: (...pathSegments: string[]) => string
  } = Path
) {
  // An empty root path would let all relative
  // paths through.
  if (rootPath.length === 0) {
    return null
  }

  const { join, normalize, resolve } = options

  const normalizedRoot = normalize(rootPath)
  const normalizedRelative = normalize(join(...pathSegments))

  // Null bytes has no place in paths.
  if (
    normalizedRoot.indexOf('\0') !== -1 ||
    normalizedRelative.indexOf('\0') !== -1
  ) {
    return null
  }

  // Resolve to an absolute path. Note that this will not contain
  // any directory traversal segments.
  const resolved = resolve(normalizedRoot, normalizedRelative)

  const realRoot = await realpath(normalizedRoot)
  const realResolved = await realpath(resolved)

  return realResolved.startsWith(realRoot) ? resolved : null
```

```typescript
export async function saveGitIgnore(
  repository: Repository,
  text: string
): Promise<void> {
  const ignorePath = Path.join(repository.path, '.gitignore')

  if (text === '') {
    return new Promise<void>((resolve, reject) => {
      FS.unlink(ignorePath, err => {
        if (err) {
          reject(err)
        } else {
          resolve()
        }
      })
    })
  }

  const fileContents = await formatGitIgnoreContents(text, repository)
  await writeFile(ignorePath, fileContents)
}
```

```typescript
function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}
```
