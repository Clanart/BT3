### Title
Unbounded per-request outbound dial to `UpstreamArchiveEN` in `requestUpstream` enables file-descriptor exhaustion via public RPC calls - (File: networks/rpc/handler.go)

### Summary
Every public RPC call whose execution fails with a `MissingNodeError` (e.g., querying old/pruned state) causes the node to open a brand-new outbound TCP connection to the configured `UpstreamArchiveEN` endpoint, with no reuse, no connection pool, and no global concurrency cap. This mirrors the PowerDNS `forward-dnsupdate` bug class: an untrusted party can cheaply trigger the target to establish outbound connections to a remote peer, and because each triggering request opens a fresh socket (closed only after the request's own timeout), a burst of concurrent unprivileged RPC calls can pile up enough open descriptors to exhaust the process's file-descriptor table.

### Finding Description
`runMethod` in `networks/rpc/handler.go` calls `requestUpstream` whenever a callback returns an error wrapping `statedb.MissingNodeError`: [1](#0-0) [2](#0-1) 

`requestUpstream` unconditionally dials the configured upstream endpoint for every such failing call: [3](#0-2) 

`DialContext` for an `http`/`https` upstream URL calls `DialHTTP`, which creates a brand-new `*http.Client` (and therefore a brand-new underlying `http.Transport`/connection, since no client instance is cached or reused across calls): [4](#0-3) [5](#0-4) 

There is no limiter tied specifically to how many concurrent `requestUpstream` dials may be in flight; the only throttle present in the RPC layer is the generic `ConcurrencyLimit` / `pendingRequestLimit` for RPC method calls in general (3000 and 200000 respectively), which is far larger than what is needed to open enough sockets to threaten typical OS file-descriptor limits, especially when combined with other already-open sockets (peer connections, DB file handles, etc.): [6](#0-5) 

`MissingNodeError` is a normal, externally-triggerable condition — any RPC caller can request state for a block number whose trie nodes have been pruned/garbage-collected (common on non-archive nodes), which is exactly the trigger condition documented in `shouldRequestUpstream`: [2](#0-1) 

Because a new connection is opened per triggering call and only closed via `defer c.Close()` after the (per-call) `DefaultHTTPTimeouts.ExecutionTimeout` elapses, a caller who issues many concurrent RPC requests that are guaranteed to hit missing/pruned trie nodes (e.g. `eth_getBalance`/`eth_call` at very old block numbers) can force the node to open many simultaneous outbound sockets toward `UpstreamArchiveEN`. If that endpoint is slow, unresponsive, or a malicious/compromised peer holding connections open without closing them, sockets accumulate until the timeout fires — directly analogous to the PowerDNS scenario where a rogue primary holds open connections from forwarded updates, exhausting the sender's file descriptors.

### Impact Explanation
File-descriptor exhaustion on a Kaia node degrades or halts its ability to accept new inbound RPC connections, new P2P peer connections, and to open LevelDB file handles for state/trie access — a denial-of-service condition (`A:H` per the referenced CVSS vector) reachable purely by public, unprivileged RPC callers, without requiring any transaction to be mined. Because the same node config flag that enables this behavior is also intended to keep endpoint nodes with pruned state serving requests, and archived-state queries at old block numbers are ordinary and expected from public users, the reachable surface is broad on any EN operator who sets `UpstreamArchiveEN`.

### Likelihood Explanation
The likelihood depends on `UpstreamArchiveEN` being configured (this is opt-in per `node/config.go`/`cmd/utils/config.go`), so the exposure is limited to deployments that enable upstream forwarding for pruned-state fallback. Where enabled, the trigger condition (`MissingNodeError`) is trivially reachable by any public RPC caller with no authentication, and the lack of connection reuse/global concurrency cap for this specific code path makes exhausting descriptors comparatively easy under moderate concurrent request volume — the medium severity is consistent with the CVSS 5.9 (`AC:H`) rating of the analog, since some precondition (feature enabled, plus sufficient concurrent request volume/timeout window) is required.

### Recommendation
- Reuse a single, long-lived HTTP/WS client (with a bounded `http.Transport` connection pool and `MaxIdleConnsPerHost`) for `UpstreamArchiveEN` instead of dialing a new connection on every `requestUpstream` invocation.
- Add an explicit, small concurrency limiter (e.g., a semaphore) specifically bounding in-flight `requestUpstream` dials, independent of the general RPC `ConcurrencyLimit`.
- Enforce a strict, short dial/connect timeout distinct from `ExecutionTimeout` so that a slow/unresponsive upstream cannot hold a socket open for the full execution timeout.
- Consider rate-limiting per-IP how often a caller can trigger `MissingNodeError` fallbacks to prevent request bursts from translating directly into new upstream connections.

### Proof of Concept
1. Configure an EN with `--rpc.upstreamarchiveen=<attacker-controlled-or-slow-endpoint>` (a supported opt-in flag).
2. As an unauthenticated public RPC caller, issue a large burst of concurrent `eth_getBalance`/`eth_call` requests specifying a very old `blockNumber` guaranteed to be pruned on the target EN, so each call fails with `MissingNodeError` and enters `requestUpstream`.
3. Have the attacker-controlled/slow "upstream" endpoint accept TCP connections but delay responding (or never respond) up to `ExecutionTimeout`.
4. Observe that each failing RPC request opens a new outbound TCP connection to the upstream endpoint (visible via `netstat`/`lsof` on the EN process) that remains open for the duration of the timeout; sufficient concurrent request volume drives the EN's open file descriptor count toward the OS limit, causing new inbound RPC/P2P connections and DB file opens to fail (`EMFILE`).

Note: I was unable to fully trace `node/config.go`/`cmd/utils/config.go` wiring for how `UpstreamArchiveEN` is enabled/validated at startup (only grep hits were reviewed, not full file contents), so the exact conditions/flags gating this feature in production deployments should be verified in a full session before treating this as a confirmed production-exposed finding.

```go
// shouldRequestUpstream is a function that determines whether must be requested upstream.
func shouldRequestUpstream(err error) bool {
	// Checks if the error contains MissingNodeError in the wrapped error chain.
	// MissingNodeError is a strong evidence that the node has no state and worth dialing the upstream.
	var missingNodeError *statedb.MissingNodeError
	return errors.As(err, &missingNodeError)
}
```

```go
// requestUpstream is the function to request upstream archive en
func requestUpstream(ctx context.Context, msg *jsonrpcMessage, args []reflect.Value) *jsonrpcMessage {
	ctx, cancel := context.WithTimeout(ctx, DefaultHTTPTimeouts.ExecutionTimeout)
	defer cancel()

	var result interface{}
	c, err := DialContext(ctx, UpstreamArchiveEN)
	if err == nil {
		defer c.Close()

		var params []interface{}
		for _, a := range args {
			params = append(params, a.Interface())
		}
		if err = c.CallContext(ctx, &result, msg.Method, params...); err == nil {
			rpcSuccessResponsesCounter.Inc(1)
			return msg.response(result)
		}
	}

	rpcErrorResponsesCounter.Inc(1)
	return msg.errorResponse(fmt.Errorf("from upstream rpc endpoint: %w", err))
}
```

```go
// DialContext creates a new RPC client, just like Dial.
//
// The context is used to cancel or time out the initial connection establishment. It does
// not affect subsequent interactions with the client.
func DialContext(ctx context.Context, rawurl string) (*Client, error) {
	u, err := url.Parse(rawurl)
	if err != nil {
		return nil, err
	}
	switch u.Scheme {
	case "http", "https":
		return DialHTTP(rawurl)
	case "ws", "wss":
		return DialWebsocket(ctx, rawurl, "")
	case "stdio":
		return DialStdIO(ctx)
	case "":
		return DialIPC(ctx, rawurl)
	default:
		return nil, fmt.Errorf("no known transport for URL scheme %q", u.Scheme)
	}
}
```
