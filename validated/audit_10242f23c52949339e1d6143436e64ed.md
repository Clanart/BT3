### Title
Unix Socket Transport Bypasses `OnlyAggregatorAndSelf` mTLS Interceptor, Allowing Unauthorized Calls to Internal gRPC Methods — (`core/src/servers.rs`)

### Summary

`create_grpc_server` applies the `OnlyAggregatorAndSelf` certificate-pinning interceptor only on the TCP code path. When the server is started with a `ServerAddr::Unix` socket, the service is registered with `.add_service(service)` directly — no interceptor is attached. Any local process that can reach the Unix socket file can call every gRPC method, including `Internal*` methods that are supposed to be callable only by the entity itself.

### Finding Description

`create_grpc_server` in `core/src/servers.rs` has two transport branches:

**TCP branch** (lines 106–139) — wraps the service in `InterceptedService::new(service, OnlyAggregatorAndSelf { … })` when `client_verification` is enabled: [1](#0-0) 

**Unix socket branch** (lines 178–189) — calls `.add_service(service)` with no interceptor at all: [2](#0-1) 

The interceptor `only_aggregator_and_self` in `core/src/rpc/interceptors.rs` enforces two rules:

1. Non-internal methods: caller's leaf certificate must equal the aggregator cert or the entity's own cert.
2. Internal methods (method name starts with `"Internal"`): caller's leaf certificate must equal the entity's own cert only. [3](#0-2) 

`is_internal` classifies a request by reading the `grpc-method` metadata header injected by `AddMethodMiddlewareLayer`: [4](#0-3) 

Because the Unix socket branch never wraps the service in `InterceptedService`, the interceptor is never invoked. The `client_verification` config flag is irrelevant for Unix sockets — the check is structurally absent.

Internal methods exposed on the operator include `internal_end_round`: [5](#0-4) 

The auth test explicitly confirms that `internal_end_round` must reject non-self callers on TCP, but this test only exercises the TCP path: [6](#0-5) 

### Impact Explanation

Any process on the same host that can open a connection to the Unix socket file can call `internal_end_round` (and any other `Internal*` method) on the operator or verifier without possessing the entity's private key or certificate. Forcing `internal_end_round` prematurely disrupts the operator's round lifecycle — the round-UTXO chain that backs operator collateral and reimbursement flows. Depending on timing, this can cause the operator to lose its collateral bond or leave withdrawal reimbursements in an unrecoverable state, constituting a material fund impact.

### Likelihood Explanation

The Unix socket path is actively used in tests and is a documented deployment option. Any co-located process (another container sharing a volume, a compromised sidecar, or a misconfigured service) with filesystem access to the socket path can exploit this without any cryptographic material.

### Recommendation

Apply the same `InterceptedService` wrapping in the Unix socket branch as in the TCP branch:

```rust
// Unix socket branch — mirror the TCP branch
let service = InterceptedService::new(
    service,
    if config.client_verification {
        OnlyAggregatorAndSelf {
            aggregator_cert,
            our_cert: client_cert,
        }
    } else {
        Noop
    },
);
let server_builder = tonic::transport::Server::builder()
    // ... layers ...
    .add_service(service);
```

Note that mTLS peer certificates are not available on Unix domain sockets (there is no TLS handshake), so `req.peer_certs()` will always return `None` on that path. The interceptor's existing `cfg!(test)` bypass for missing peer certs would therefore pass all requests in production as well. The correct fix is either (a) to disallow `Internal*` methods entirely over Unix sockets, or (b) to use OS-level socket permissions (e.g., `chmod 0600` + `chown`) to restrict access to the socket file to the owning process only, and document this as a hard deployment requirement.

### Proof of Concept

1. Start an operator node configured with a Unix socket address (e.g., `unix:///tmp/operator.sock`).
2. From any process on the same host with read/write access to `/tmp/operator.sock`, connect without a client certificate:
   ```
   grpcurl -plaintext -unix /tmp/operator.sock \
     clementine.ClementineOperator/InternalEndRound
   ```
3. The call succeeds — no certificate is checked, no `Unauthenticated` error is returned — because the `OnlyAggregatorAndSelf` interceptor was never registered for the Unix socket server. [7](#0-6)
