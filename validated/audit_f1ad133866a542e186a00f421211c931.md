### Title
Loose "contains github." regex in `isGitHubHost` misclassifies attacker-controlled remotes as trusted GitHub hosts - (File: `app/src/lib/api.ts`)

### Summary
The WATCHPUG finding flags that a security-relevant value (`ETH`) was implemented as a *configurable/derived* value when it must be an exact, fixed constant, because any deviation breaks the invariant the rest of the contract relies on. The same bug class exists in GitHub Desktop's host-trust classification: instead of comparing a remote's hostname against an exact allowlist (`github.com`, `api.github.com`, or a `.ghe.com`/known-enterprise suffix), `isGitHubHost` falls back to a loose substring/regex test that can be satisfied by an attacker-chosen hostname.

### Finding Description
`isGitHubHost` in `app/src/lib/api.ts` is used to decide, on a best-effort basis, whether a URL "belongs to a GitHub host" [1](#0-0) . After the strict checks (`isDotCom`/`isGHE`, and the `isKnownThirdPartyHost` deny-list) fail to classify the host, the function falls through to a loose heuristic:

```
// github.example.com,
if (/(^|\.)(github)\./.test(hostname)) {
  return true
}
``` [2](#0-1) 

This regex only requires the label `github` to appear immediately before a dot anywhere in the hostname preceded by either the start of the string or another dot. It is meant to catch legitimate self-hosted names like `github.example.com`, but it equally matches attacker-registered domains such as `github.attacker.com`, `my-github.attacker.io` is rejected (needs exact label) but `x.github.attacker.com` or `github.attacker.com` is accepted — i.e., any domain the attacker controls that simply contains a `github.` label. There is no requirement that the host actually be a GitHub Enterprise Server (no `/meta` verification, no certificate check) before this branch returns `true`.

`isGitHubHost` is imported together with `getAPIEndpoint` into the trampoline credential helper: `import { getAPIEndpoint, isGitHubHost } from '../api'` [3](#0-2) . In `getCredential`, once the local account lookup fails, the code branches on an "endpoint kind" derived from this classification, and if the endpoint is judged GitHub-like it prompts the user to sign in to GitHub for that endpoint rather than treating it as generic:
```
const endpointKind = await getEndpointKind(cred, store)
...
if (endpointKind !== 'generic' && !accounts.some(a => a.endpoint === apiEndpoint)) {
  ...
  const account = await ui.promptForGitHubSignIn(endpoint)
``` [4](#0-3) 

Because the classification that feeds this decision uses the loose regex instead of an exact/allowlisted comparison, a git remote or fetch URL under attacker control (e.g. `https://github.attacker.com/x/y.git`, easily reachable via a cloned repo's remote, a "clone" deep link, or a hostile git server the user is redirected to) is treated as a genuine GitHub endpoint. I was not able to retrieve the full body of `getEndpointKind` in this session, so the exact downstream branching (whether it always prompts a GitHub sign-in dialog, or also affects OAuth/API-endpoint selection) is not fully confirmed here and should be verified directly in the code before filing a fix.

### Impact Explanation
If the loose classification causes GitHub Desktop to present a "Sign in to GitHub" prompt (or otherwise route credential handling) for an attacker-controlled host that merely contains the string `github.` in its hostname, a user who is unaware of the distinction between GitHub.com/legitimate GHE and an attacker's server could be led to authenticate — via OAuth or PAT entry — against the wrong endpoint. Depending on exactly how `getEndpointKind`/`promptForGitHubSignIn` route the resulting token, this could send credentials/tokens to, or associate an account object with, an attacker-controlled host, matching the "unauthorized OAuth or account binding" / "credential exfiltration" impact classes for this class of bugs. This requires no local access, malware, or leaked credentials — only a repository/remote/link the user is induced to clone or fetch, matching the valid-impact bar.

### Likelihood Explanation
The attacker primitive is trivial and cheap: registering any domain containing the label `github.` (`github.<attacker-domain>` or `<sub>.github.<attacker-domain>`) is enough to satisfy the regex, and the user only needs to interact with a remote pointing at that host (clone, fetch, or an "Open in Desktop"-style flow). No certificate, DNS spoofing, or GitHub-Enterprise `/meta` response forgery is needed because that stronger check only runs if the earlier heuristics don't already resolve `true`. Because the regex classification happens before the network-based `/meta` verification in `isGitHubHost`, it can short-circuit the more robust check entirely.

### Recommendation
Replace the loose `/(^|\.)(github)\./` heuristic with a stricter, allowlist-based check analogous to `isGHE`/`isDotCom`, requiring an exact suffix match (e.g., `.ghe.com`) or a positively-verified `/meta` response with a valid TLS certificate before ever classifying a host as GitHub-like, rather than relying on substring/regex pattern matches that can be satisfied by attacker-registered domains. This mirrors the original report's recommendation to replace a "configurable/derivable" value with a fixed, verifiable constant/allowlist.

### Proof of Concept
1. Attacker registers `github.attacker.com` (or any hostname where a `github.` label appears after the start or a dot) and stands up a git server / hosts a repo there.
2. Attacker sends the victim a clone URL or repository remote pointing at `https://github.attacker.com/foo/bar.git`.
3. Victim clones or fetches through GitHub Desktop; the credential-manager flow calls into `getCredential`, which (via `getEndpointKind`) uses `isGitHubHost` to classify `github.attacker.com` [2](#0-1) .
4. Because `isKnownThirdPartyHost` doesn't cover `attacker.com`, and no `.ghe.com`/`api.github.com` match exists, execution reaches the regex branch and returns `true`, causing Desktop to treat this untrusted host as a GitHub endpoint and drive the credential/sign-in prompt flow in `getCredential` [4](#0-3)  as though it were a legitimate GitHub or GHE instance.

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }
```
