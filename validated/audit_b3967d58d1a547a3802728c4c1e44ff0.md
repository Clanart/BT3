### Title
Fee double-payment on GetResponse delivery: `_requestCommitments` is never cleared in `dispatchIncoming(GetResponse)`, letting the same GetRequest fee be paid to the relayer and later refunded again via a stale timeout proof - ([File: evm/src/core/EvmHost.sol])

### Summary
`EvmHost.dispatch(DispatchGet)` escrows the caller's fee in `_requestCommitments[commitment] = FeeMetadata({sender, fee})` [1](#0-0) . When the corresponding `GetResponse` is later delivered, `dispatchIncoming(GetResponse, relayer)` pays the escrowed fee straight to the relayer but never deletes the `_requestCommitments` entry that funded it [2](#0-1) . That same entry is later consulted by `handleGetRequestTimeouts`/`dispatchTimeOut(GetRequestTimeout,...)` as the "known request" check and as the source of the refund amount, and `dispatchTimeOut` pays `meta.fee` to `meta.sender` [3](#0-2) . Since no other on-chain state on the EVM host is cleared once the response has been delivered, a non-membership proof anchored at an older, already-committed state height (one whose timestamp is past `timeout` but predates the actual response) still satisfies the handler's checks, allowing the escrowed fee to be paid out a second time.

### Finding Description
On the EVM side, `handleGetResponses` verifies a GetResponse's inclusion via an MMR proof against `host.stateMachineCommitment(message.proof.height)` and then calls `host.dispatchIncoming(response, relayer)` [4](#0-3) . `dispatchIncoming` sets a `_responseReceipts` entry (replay protection for redelivery of the same response) and, on success, transfers `_requestCommitments[commitment].fee` to the relayer — but it does **not** delete `_requestCommitments[commitment]` [2](#0-1) .

Compare this to the two `dispatchTimeOut` variants, which both explicitly `delete _requestCommitments[commitment]` as "replay protection" before invoking the app callback, and restore it only if the callback fails [5](#0-4) . The response path is missing this cleanup entirely, so the `FeeMetadata{sender, fee}` for a `GetRequest` remains live in storage forever after a successful response delivery.

`handleGetRequestTimeouts` treats a non-zero `meta.sender` as proof the request is "known", checks `request.timeout() > state.timestamp` against the *proof height's* recorded timestamp (not necessarily the latest height), and verifies a non-membership proof of `ResponseReceipts[commitment]` at that same historical height [6](#0-5) . Because EVM state-machine commitments for past heights are not pruned once stored, any height whose recorded timestamp is past the request's `timeoutTimestamp` — including one committed *before* the response was actually produced on the remote chain — remains a valid anchor for this non-membership proof. Nothing re-checks the *current/latest* state to confirm a response was never produced.

This lets anyone (an unprivileged caller who submits `handleGetRequestTimeouts`, requiring no privileged role — `notFrozen` is the only host-level modifier) submit a timeout for a `GetRequest` whose response was already delivered and whose relayer fee was already paid out, using a proof anchored at a stale height, and collect a second payout of the same `fee` to `meta.sender` via `dispatchTimeOut`.

### Impact Explanation
This is a direct loss-of-funds / double-settlement bug in the fee-token treasury held by `EvmHost`: the same escrowed `GetRequest` fee can be paid out twice — once to the relayer that delivered the response, and again as a "timeout refund" to `meta.sender` — draining the host's fee-token balance beyond what was actually collected. This falls squarely under the required impact class "bridged assets, order escrow, refunds ... relayer rewards ... must move exactly once and only to the rightful beneficiary and amount" and "duplicate settlement or claim."

### Likelihood Explanation
No malicious relayer, prover, or admin is required. Any address can call `handleGetRequestTimeouts` with a legitimately-generated non-membership proof anchored at an older, still-stored state commitment height that satisfies `request.timeout() > state.timestamp` is false (i.e., `state.timestamp >= timeoutTimestamp`) yet predates the real response. Because Hyperbridge continuously advances state and old commitments are not deleted after new ones land (`delete_state_commitment` is only used for invalidation of bad states, not routine pruning), such a stale-but-valid height is very likely to exist for any `GetRequest` whose timeout window is short relative to the interval between consensus/state updates.

### Recommendation
Delete (or otherwise invalidate) `_requestCommitments[commitment]` in `dispatchIncoming(GetResponse, ...)` immediately after a successful response delivery (mirroring the replay-protection pattern already used in both `dispatchTimeOut` overloads), so that a subsequent `handleGetRequestTimeouts` call for the same commitment fails the "known request" (`meta.sender == address(0)`) check. Additionally, consider requiring timeout proofs to be anchored at the *latest* known state commitment height for the destination rather than any historically stored height, to remove the stale-proof attack surface generally.

### Proof of Concept
1. Attacker/user calls `EvmHost.dispatch(DispatchGet{...fee: F, timeout: T,...})`. This sets `_requestCommitments[commitment] = {sender: payer, fee: F}` [1](#0-0) .
2. The request is fulfilled normally: a relayer submits `handleGetResponses`, which calls `dispatchIncoming(GetResponse, relayer)`. This pays `fee = F` to `relayer` via `IERC20(feeToken()).safeTransfer(relayer, fee)`, but `_requestCommitments[commitment]` is left untouched [7](#0-6) .
3. Time passes; the host has multiple stored `StateCommitment`s for the destination state machine, including one `height_old` whose recorded `timestamp` is already `>= timeoutTimestamp` but was committed to the EVM host *before* the response's `ResponseReceipts` entry existed on the destination chain.
4. Attacker builds a `PolkadotTrie` non-membership proof of `ResponseReceipts[commitment]` at `height_old` (valid, because at that historical point in time the response indeed had not yet been produced) and calls `handleGetRequestTimeouts` with this proof.
5. Checks pass: `meta.sender != address(0)` (never cleared in step 2), `request.timeout() > state.timestamp` is false so no revert, and the non-membership proof verifies against `height_old`'s stored `stateRoot`.
6. `dispatchTimeOut(GetRequestTimeout, meta, commitment)` executes, deletes `_requestCommitments[commitment]` (too late), invokes `onGetTimeout`, and on success transfers `meta.fee = F` to `meta.sender` [3](#0-2) .
7. Net result: fee `F` has now been paid out twice from the host's fee-token balance for a single `GetRequest` — once to the relayer, once as a "refund."

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function handleGetResponses(IHost host, GetResponseMessage calldata message) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(message.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 responsesLength = message.responses.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](responsesLength);

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // don't check for timeouts because it's checked on Hyperbridge

            // known request? also serves as source check
            FeeMetadata memory meta = host.requestCommitments(leaf.response.request.hash());
            if (meta.sender == address(0)) revert UnknownMessage();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.response.hash());
        }

        bytes32 root = host.stateMachineCommitment(message.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, message.proof.multiproof, leaves, message.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // duplicate response?
            if (host.responseReceipts(leaf.response.request.hash()).relayer != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.response, _msgSender());
        }
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
