## Analysis

The Sherlock report's core failure pattern is: **two different code paths compute the same derived accounting quantity using different logic/state, and a downstream consumer trusts one value while the actual result comes from the other path — breaking the invariant that "total accounted == total claimable."**

The closest reachable Protobuf analog is in `LazyFieldLite`, used for lazily-parsed message and extension fields — reached via the ordinary public parsing API (`parseFrom`) when `ExtensionRegistryLite.lazyExtensionEnabled()` is `false` (the default/old behavior for lazy extensions).

### The failed invariant
`LazyFieldLite.getSerializedSize()` / `computeSizeNoTag()` (used by the *containing* message to compute its `ByteSizeLong()`/pre-size a buffer) and `writeTo()` (used to actually emit bytes) are supposed to always agree on which underlying byte source (`delayedBytes`, `memoizedBytes`, or `value`) represents the field's contents, in the same priority order. [1](#0-0) [2](#0-1) 

### The attacker-controlled value and missing check
`ensureInitialized()` is invoked lazily when any getter is first called. If the attacker-supplied `delayedBytes` fail to parse (corrupted/malformed submessage bytes — fully attacker-controlled, bounded, reachable via a normal `parseFrom` call), the catch block sets `memoizedBytes = ByteString.EMPTY` and `value = defaultInstance`, but **does not clear `delayedBytes`**: [3](#0-2) 

Because `getSerializedSize()` checks `delayedBytes != null` *first* (returning the stale, larger `delayedBytes.size()`), while `writeTo()` checks `memoizedBytes != null` *first* (now non-null, so it writes the empty bytes instead), the two methods diverge as soon as corruption is detected once `ensureInitialized()` has run — the size-computation path and the byte-emission path silently pick different underlying sources, exactly mirroring the Solidity bug's "different ordering of calculations . . . causes the totalShares tracked to be less than the claimable amount."

### Why this matters
A containing message computes its `ByteSizeLong()` (and any length-prefix / buffer sizing) using the inflated `getSerializedSize()` value while the bytes actually written via `writeTo()` are far fewer. This breaks the byte-accounting invariant between size-computation and serialization for that field, the same class of bug documented as a historical, now-fixed issue for map fields elsewhere in the codebase (`map_test.inc`'s regression test explicitly describes: "Protobuf used to have a bug for serialize when map is marked CLEAN. It used repeated field to calculate ByteSizeLong but use map to serialize the real data, thus the ByteSizeLong may [be] bigger than real serialized size... crash... or 'unexpected end group' warning... at parse back"): [4](#0-3) 

That map-field case is fixed and covered by regression tests, but the `LazyFieldLite` corruption path is not covered by an equivalent consistency check.

### Title
Stale `delayedBytes` after lazy-field parse failure causes `getSerializedSize()`/`writeTo()` divergence — (File: `java/core/src/main/java/com/google/protobuf/LazyFieldLite.java`)

### Summary
When a lazily-parsed message/extension field's `delayedBytes` fail to parse in `ensureInitialized()`, the catch block resets `value`/`memoizedBytes` to the empty default but forgets to null out `delayedBytes`. Because `getSerializedSize()` and `writeTo()` check the three backing fields (`delayedBytes`, `memoizedBytes`, `value`) in the same priority order but the state left behind by the corruption path breaks that ordering consistency, callers relying on `getSerializedSize()` before serialization can obtain a size that no longer matches what `writeTo()` actually emits for that field.

### Finding Description
`LazyFieldLite` stores a field's data across three mutually-exclusive representations, and its class comment states callers "must first check if the memoizedBytes or delayedBytes ByteString is non-null and use it directly." `getSerializedSize()` prioritizes `delayedBytes`, then `memoizedBytes`, then `value`. `writeTo()` prioritizes `memoizedBytes`, then `delayedBytes`, then `value` — a different order. Under normal (non-corrupted) operation this doesn't matter because the two are always kept in sync (e.g., `ensureInitialized()` sets `memoizedBytes = delayedBytes` on success). But on the corruption branch, `delayedBytes` is left set to the attacker's original (larger) bytes while `memoizedBytes` becomes `ByteString.EMPTY`. `getSerializedSize()` still sees `delayedBytes != null` and returns its size; `writeTo()` now sees `memoizedBytes != null` first and emits the empty representation instead.

### Impact Explanation
The outer message's precomputed `ByteSizeLong()`/length-prefix for that field can be larger than what is actually serialized once corruption has been triggered and any getter has been called. This is analogous in kind (not necessarily magnitude) to the Sherlock finding: an accounting quantity computed one way for planning/allocation purposes diverges from the quantity produced by the actual "spend"/emit path, breaking the equality invariant relied on by size-prefixed wire encoding and downstream consumers that trust the precomputed size.

### Likelihood Explanation
Reachable by any ordinary client sending a bounded, malformed embedded message/extension through the standard `parseFrom` API when lazy extension verification is not eagerly enabled (the legacy/default silent-corruption behavior documented in the class). No privileged access or hostile schema is required — only an attacker-controlled invalid submessage payload.

### Recommendation
In `ensureInitialized()`'s catch block, clear `delayedBytes` (set it to `null`) whenever falling back to the default/empty value, so that `getSerializedSize()`, `toByteString()`, and `writeTo()` are guaranteed to agree on the same backing representation after a parse failure.

### Proof of Concept
1. Construct a `LazyFieldLite` (or equivalent lazy extension field) with `delayedBytes` set to a syntactically-invalid but non-empty byte sequence for the target message type, via a standard `parseFrom` call on a message containing that field/extension.
2. Trigger `ensureInitialized()` (e.g., by calling any getter) — this sets `memoizedBytes = ByteString.EMPTY`, `value = defaultInstance`, `corrupted = true`, but leaves `delayedBytes` non-null.
3. Call `getSerializedSize()` — observe it returns `delayedBytes.size()` (non-zero, equal to the original malformed payload length).
4. Call `writeTo(writer, fieldNumber)` — observe it takes the `memoizedBytes != null` branch and writes the empty representation instead, producing far fewer bytes than `getSerializedSize()` reported. [1](#0-0) [5](#0-4)

  /** Writes this lazy field into a {@link CodedOutputStreamWriter}. */
  void writeTo(CodedOutputStreamWriter writer, int fieldNumber) throws IOException {
    if (memoizedBytes != null) {
      writer.writeBytes(fieldNumber, memoizedBytes);
    } else if (delayedBytes != null) {
      writer.writeBytes(fieldNumber, delayedBytes);
    } else if (value != null) {
      writer.writeMessage(fieldNumber, value);
    } else {
      writer.writeBytes(fieldNumber, ByteString.EMPTY);
    }
  }

  /** Might lazily parse the bytes that were previously passed in. Is thread-safe. */
  protected void ensureInitialized(MessageLite defaultInstance) {
    if (value != null) {
      return;
    }
    synchronized (this) {
      if (value != null) {
        return;
      }
      try {
        if (delayedBytes != null) {
          // The extensionRegistry shouldn't be null here since we have delayedBytes.
          MessageLite parsedValue =
              defaultInstance.getParserForType().parseFrom(delayedBytes, extensionRegistry);
          this.value = parsedValue;
          this.memoizedBytes = delayedBytes;
        } else {
          this.value = defaultInstance;
          this.memoizedBytes = ByteString.EMPTY;
        }
      } catch (InvalidProtocolBufferException e) {
        // Nothing is logged and no exceptions are thrown. Clients will be unaware that this proto
        // was invalid.
        this.corrupted = true;
        this.value = defaultInstance;
        this.memoizedBytes = ByteString.EMPTY;
      }
    }
  }
