### Title
Auction module never enforces the searcher-set `MaxGasPrice` slippage cap on bid inclusion - (File: kaiax/auction/impl/bid_pool.go)

### Summary
KIP-249 auction v3.0 introduced a `MaxGasPrice` field on the searcher's bid, intended to let the searcher cap the gas price it is willing to pay when its bid transaction is executed by the block proposer. However, the CN-side bid pool admission logic (`validateBid`) never reads or checks `bid.MaxGasPrice` against the current or upcoming block's base fee/gas price before accepting and queuing the bid for execution.

### Finding Description
`BidData.MaxGasPrice` is defined and propagated through the EIP-712 signing path and RPC input (`kaiax/auction/bid.go`, `kaiax/auction/eip712.go`, `kaiax/auction/impl/api.go`) as an explicit price-protection field for v3.0 bids. [2](#0-1) [3](#0-2) 

The bid pool's admission checks in `validateBid`, however, only validate: sender-winner conflicts, block-number range, `Bid > 0`, data size, call-gas-limit, and signatures — no comparison of `MaxGasPrice` to the current/expected base fee (KIP-71) is performed. [1](#0-0) 

Similarly, `AddBid`/`insertBid` accept and store the bid, compute `getBidTxGasLimit`, and forward it to `newBidCh` without any gas-price check tied to `MaxGasPrice`. [4](#0-3) 

This mirrors the reported bug class: a value-bearing parameter (`MaxGasPrice`, analogous to a "minimum acceptable value"/slippage bound in the liquidation report) is defined by the field's protocol design but is not actually enforced by the code path that decides whether to admit/execute the transaction, so the guarantee it is supposed to provide is never checked at the point that matters.

### Impact Explanation
Because `MaxGasPrice` is never checked at bid-pool admission time, a bid can be accepted and later included/executed by a block proposer even when the effective gas price at execution time (base fee for that block) exceeds the searcher's declared maximum. The searcher's fee-delegation/gas payment for the auction transaction is thus not actually bounded by the value they explicitly signed and submitted, defeating the purpose of the field and potentially causing the searcher to overpay gas fees beyond their intended cap — an unauthorized value movement from the searcher's perspective, without any recourse since the check never exists on the node side.

### Likelihood Explanation
Medium likelihood: this occurs any time base fee moves upward between when a searcher/auctioneer submits a v3.0 bid and when the target block is actually proposed (which KIP-71's dynamic base-fee mechanism makes routine), and requires no malicious behavior by any party — simply the absence of a check causes the field to be silently ignored under normal network conditions.

### Recommendation
In `BidPool.validateBid` (and/or at bid-tx generation/inclusion time), when `bid.MaxGasPrice` is set (v3.0 bids), compare it against the expected gas price/base fee for the target block (or the current tx-pool gas price) and reject the bid with an error (e.g., `ErrExceedMaxGasPrice`) if the price would exceed the searcher's declared cap, consistent with how `LowerBoundGasPrice`/`UpperBoundGasPrice` and KIP-71 base-fee bounds are already read elsewhere in the codebase (`node/cn/api_backend.go`).

### Proof of Concept
1. A searcher submits a v3.0 bid via `auction_submitBid` with `MaxGasPrice = X` for `BlockNumber = N`. [5](#0-4) 
2. Between submission and block `N` being proposed, KIP-71's `NextMagmaBlockBaseFee` raises the base fee above `X` due to high demand. [6](#0-5) 
3. `BidPool.validateBid` performs none of its checks against `MaxGasPrice`, so the bid remains valid/queued in `bidTargetMap`/`bidWinnerMap`. [1](#0-0) 
4. The bid's transaction is generated and included in block N (via `EncodeAuctionCallData`, which faithfully encodes the stale `MaxGasPrice` into calldata but this value is only consumed by the auction entry-point contract's on-chain logic, not by the CN's own admission/inclusion logic), and the searcher effectively pays gas at a price above what they capped for, with no node-side rejection. [7](#0-6) 

**Uncertainty note:** I could not verify whether the actual on-chain `AuctionEntryPoint` v3.0 contract (source not present in this index — only the mock `AuctionEntryPointMock.sol`, which implements a stripped-down v2.1-only flow with commented-out logic) independently enforces `MaxGasPrice` at execution time; if it does, the impact would be limited to wasted gas/reverted execution rather than fund loss, which would reduce severity. Given the index does not contain the full v3.0 entry-point contract source, this could not be fully confirmed and a Devin session with full repository access would be needed to check the actual on-chain contract logic.

func (bp *BidPool) AddBid(bid *auction.Bid) (common.Hash, error) {
	if atomic.LoadUint32(&bp.running) == 0 {
		return common.Hash{}, auction.ErrAuctionPaused
	}

	if err := bp.validateBid(bid); err != nil {
		return common.Hash{}, err
	}

	if err := bp.insertBid(bid); err != nil {
		return common.Hash{}, err
	}

	gasLimit, err := bp.getBidTxGasLimit(bid)
	if err != nil {
		return common.Hash{}, err
	}
	bid.SetGasLimit(gasLimit)

	bp.newBidCh <- bid

	return bid.Hash(), nil
}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil

func (b bidV3) EncodeData() []byte {
	maxGasPrice := b.MaxGasPrice
	if maxGasPrice == nil {
		maxGasPrice = new(big.Int)
	}
	encoded := make([]byte, 0, 10*32)
	encoded = append(encoded, b.TargetTxHash.Bytes()...)
	encoded = append(encoded, common.LeftPadBytes(common.Int64ToByteBigEndian(b.BlockNumber), 32)...)
	encoded = append(encoded, common.LeftPadBytes(b.Sender.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(b.To.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(common.Int64ToByteBigEndian(b.Nonce), 32)...)
	encoded = append(encoded, common.LeftPadBytes(b.BidData.Bid.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(maxGasPrice.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(common.Int64ToByteBigEndian(b.CallGasLimit), 32)...)
	encoded = append(encoded, crypto.Keccak256Hash(b.Data).Bytes()...)
	return encoded
}

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)
