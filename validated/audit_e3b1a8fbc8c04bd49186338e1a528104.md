### Title
Anyone can front-run WombatStaking's harvest by calling `MasterWombat.depositFor()` directly, permanently freezing WOM/bonus rewards owed to LP stakers - (File: wombat/WombatStaking.sol)

### Summary
`WombatStaking` harvests pending WOM (and bonus token) rewards from the external `MasterWombat` contract by measuring its own token balance before and after triggering a zero-amount `deposit`/`withdraw` call on `MasterWombat`, then forwards the delta to the pool's rewarder via `_sendRewards`/`queueNewRewards` [1](#0-0) . Because `MasterWombat` is a public, permissionless external contract that exposes `depositFor(pid, amount, account)` [2](#0-1) , any unprivileged wallet can call it directly with `account = address(WombatStaking)` and `amount = 0`, forcing `MasterWombat` to pay out `WombatStaking`'s pending WOM rewards straight into `WombatStaking`'s token balance — completely bypassing the `_toMasterWomAndSendReward` accounting wrapper that is supposed to route that harvest through `_sendRewards`/`queueNewRewards`.

### Finding Description
`WombatStaking.harvest()` and the deposit/withdraw flows all route through `_toMasterWomAndSendReward`, which snapshots `womBeforeBalance` and per-token bonus balances, then calls into `MasterWombat` (`_stakeToWombatMaster` → `deposit(pid, amount)`, or `withdraw(pid, amount)`), and finally computes `womRewards`/`bonusBalanceDiff` as the balance delta to forward through `_sendRewards` into the pool's `IBaseRewardPool` via `queueNewRewards` [3](#0-2) [1](#0-0) .

This accounting entirely relies on the harvest being triggered *inside* `_toMasterWomAndSendReward`'s balance-diff window. `MasterWombat`, however, exposes `depositFor(pid, amount, account)`, which lets an arbitrary caller deposit (even `amount = 0`) on behalf of any `account` [2](#0-1) ; as with typical MasterChef-style staking, this pays out the pending reward accrued for `account`'s position directly to `account` — not to `msg.sender` — which the repo's own mock confirms (`safeWOMTransfer(payable(_account), pool.rewardAmount)`) [4](#0-3) . Anyone can therefore call `MasterWombat.depositFor(pid, 0, address(WombatStaking))` directly, which harvests `WombatStaking`'s pending WOM position and deposits it as a plain token balance increase in `WombatStaking`, entirely outside of any `_toMasterWomAndSendReward` invocation.

The next time the legitimate `harvest()` path runs for that same `_lpToken`, `womBeforeBalance` is snapshotted *after* the stray reward has already landed in the contract, so the subsequent balance diff (`womRewards`) only reflects the newly-accrued pending amount since the external call — the previously stray-harvested amount is silently excluded from `_sendRewards`/`queueNewRewards` and is never credited to the pool's rewarder. That WOM (or bonus token) permanently sits in `WombatStaking`'s balance, un-attributed to any pool's `IBaseRewardPool`, with no function to sweep and re-queue it.

### Impact Explanation
LP stakers permanently lose a portion of the yield they are owed: the WOM/bonus rewards accrued in `MasterWombat` for a given pool position are physically transferred into `WombatStaking`, but never routed through `_sendRewards`'s fee logic and `queueNewRewards` call to the pool's `BaseRewardPool`, so they never become claimable by depositors. This matches "theft or permanent freezing of unclaimed yield."

### Likelihood Explanation
Any unprivileged wallet can trigger this at will and at zero cost (a zero-amount `depositFor` call, no capital required) against any of `WombatStaking`'s active pools, since `masterWombat`, `pools[_lpToken].pid`, and `WombatStaking`'s address are all public/readable state [5](#0-4) .

### Recommendation
Do not rely on balance-diff bracketing around calls into `MasterWombat` to determine harvested rewards. Instead, track claimed vs. previously-known reward amounts using persistent accounting (e.g., record last-known/queued reward balances) and reconcile any un-attributed balance increase (e.g., in a dedicated sweep function callable by anyone) into `_sendRewards` for the correct pool, similar to the Casimir fix of moving accounting into the token-receiving path and filtering strictly by the source of funds.

### Proof of Concept
1. `WombatStaking` deposits LP tokens for `lpTokenA` into `MasterWombat` under `pid = poolInfo.pid`, accruing pending WOM rewards over time.
2. An arbitrary wallet calls `MasterWombat.depositFor(pid, 0, address(WombatStaking))` directly (no allowance/approval or capital required, `amount = 0`).
3. `MasterWombat` pays out the currently pending WOM reward for that position directly to `address(WombatStaking)`, increasing its WOM balance, without any call into `WombatStaking.harvest()` or `_toMasterWomAndSendReward`.
4. Later, `WombatStaking.harvest(lpTokenA)` is called normally; `_toMasterWomAndSendReward` snapshots `womBeforeBalance` (which now already includes the stray reward from step 3), triggers `deposit(pid, 0)` (harvesting only the newly accrued pending amount since step 2), and computes `womRewards` as only that new delta.
5. The WOM amount paid out in step 3 is never passed to `_sendRewards`/`queueNewRewards`, remaining stuck in `WombatStaking`'s balance indefinitely, permanently withheld from the pool's `BaseRewardPool` and its stakers.

    function _toMasterWomAndSendReward(address _lpToken, uint256 lpAmount, bool _isStake) internal {
        Pool storage poolInfo = pools[_lpToken];

        address[] memory bonusTokens = assetToBonusRewards[_lpToken];
        uint256 bonusTokensLength = bonusTokens.length;

        uint256 womBeforeBalance = IERC20(wom).balanceOf(address(this));
        uint256[] memory beforeBalances = _rewardBeforeBalances(_lpToken);

        if(_isStake)
            _stakeToWombatMaster(_lpToken, lpAmount); // triggers harvest from wombat exchange
        else
            IMasterWombat(masterWombat).withdraw(poolInfo.pid, lpAmount); // triggers harvest from wombat exchange
        uint256 womRewards = IERC20(wom).balanceOf(address(this)) - womBeforeBalance;
        _sendRewards(_lpToken, wom, poolInfo.rewarder, womRewards);

        for (uint256 i; i < bonusTokensLength; i++) {
            uint256 bonusBalanceDiff = IERC20(bonusTokens[i]).balanceOf(address(this)) - beforeBalances[i];
            if (bonusBalanceDiff > 0) {
                _sendRewards(_lpToken, bonusTokens[i], poolInfo.rewarder, bonusBalanceDiff);
            }
        }

        emit WomHarvested(womRewards);

    }
