## Title
Spoofed `WWW-Authenticate` realm from a malicious git remote/proxy can trick GitHub Desktop into initiating a GitHub Enterprise sign-in flow bound to an attacker-controlled host - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
`getEndpointKind()` in the trampoline credential helper classifies the host Git is talking to as `'github.com'`, `'ghe.com'`, `'enterprise'`, or `'generic'` in order to decide how to source credentials for that request. One of its heuristics trusts the `WWW-Authenticate` HTTP header Git captures from the remote's `401` response: if the header's `realm` contains the literal string `GitHub`, the endpoint is classified as `'enterprise'`. This value is fully attacker-controlled — it comes straight from the HTTP response of whatever server the user's remote URL points to (or any MITM/malicious proxy sitting on that connection) — yet it is used to trigger security-relevant UI (the "sign in to GitHub Enterprise" flow) for hosts that Desktop has no other reason to trust.

The `wwwauth[]` credential fields are populated by Git itself from the server's HTTP response headers and passed through the git-credential protocol to Desktop's trampoline unmodified — Desktop performs no validation that the responding host is actually a genuine GitHub/GHE server (e.g. no TLS certificate check tied to a known GitHub CA, no call to `isGitHubHost()`/an actual API probe) before trusting the header. Any git server — including one the user cloned/added as a remote, or a MITM proxy sitting on an insecure/misconfigured connection — can simply respond to Git's authentication probe with a header such as:

```
WWW-Authenticate: Basic realm="GitHub"
```

The "existing guard" that might be expected here — validating the endpoint is a genuine GitHub Enterprise instance (e.g. via `isGitHubHost()`, which does perform an actual network probe) — is explicitly bypassed by design: the code comment states the `WWW-Authenticate` check exists specifically "without having to resort to making a request ourselves." The real validation path (`isGitHubHost(endpoint)`, used later in the same function as a fallback) is only reached if the header-based happy-path check does *not* match, meaning the unverified fast-path takes precedence.

### Impact Explanation
This matches the "unauthorized OAuth or account binding" and "attacker controls a git remote/proxy response" impact categories: a remote the user does not control (or a network attacker on an insecure connection) can force GitHub Desktop to present a "Sign in to GitHub Enterprise" dialog bound to the attacker's host origin, purely by spoofing a response header — no valid credentials, GitHub branding on the server, or prior trust relationship required. Depending on the enterprise sign-in flow this can:
- Trick users into believing an untrusted host is a legitimate GitHub Enterprise Server, priming a phishing flow (`credentialHelperUrl` shown to the user is the attacker's endpoint).
- Cause the OAuth/device sign-in flow to be initiated against the attacker-controlled origin, associating any resulting session/account state with that origin in Desktop's `AccountsStore`.
- In non-interactive/background contexts this branch is short-circuited (`getIsBackgroundTaskEnvironment`), but any interactive `fetch`/`clone`/`push` against a malicious or compromised remote can trigger it.

The severity is bounded by the fact that the follow-on sign-in flow for enterprise still typically opens a browser-based OAuth/device flow rather than directly accepting a typed password sent to the attacker's server, so credential exfiltration is not immediate — but the trust decision itself (classifying an arbitrary server as "GitHub Enterprise" from an unauthenticated header) is the broken invariant, analogous to the smart-contract bug's core problem: a control-flow decision that should require a hard, verifiable guarantee (real success/real GitHub identity) is instead made from an unverified/attacker-influenced signal (63/64 gas heuristic / spoofable HTTP header).

### Likelihood Explanation
Likelihood is moderate-to-low in practice: it requires the user to perform a git network operation (clone/fetch/push/pull) against a repository or proxy the attacker controls, and requires no existing signed-in account for that specific origin. This is a very natural scenario for anyone adding an untrusted remote, working through a corporate/malicious proxy, or being MITM'd on a misconfigured connection — no unusual user interaction is needed beyond a normal git operation, which is within scope (git remote/proxy response is attacker-controlled input per the task's valid-impact definition).

### Recommendation
Do not treat the `WWW-Authenticate` realm string as authoritative for classifying a host as GitHub/Enterprise. At minimum:
- Require the header match to be corroborated by an actual host check (`isGitHubHost()`) before trusting it, rather than using it purely as a "no request needed" shortcut.
- Restrict the header-derived classification to hosts already known/allow-listed by the user (e.g., matching a previously configured GHE endpoint), rather than allowing it to escalate an arbitrary new host directly into the "prompt for GitHub sign-in" branch.
- Make it clear in the sign-in dialog when the endpoint has not been independently verified as a genuine GitHub host, so users aren't misled by attacker-chosen labeling.

### Proof of Concept
1. Attacker stands up an HTTP git server (or MITM proxy) at `https://evil.example.com/attacker/repo.git`.
2. The server is configured so that any authentication challenge for a Git HTTP request returns:
   ```
   HTTP/1.1 401 Unauthorized
   WWW-Authenticate: Basic realm="GitHub"
   ```
3. Victim, who has no GitHub Desktop account signed in for `evil.example.com`, adds this remote/clones/fetches it via GitHub Desktop.
4. Git forwards the captured `wwwauth[]` header to Desktop's credential-helper trampoline via `command.stdin`.
5. `getEndpointKind()` matches `realm="GitHub"` and returns `'enterprise'`; since no account exists for `evil.example.com`, `getCredential()` calls `ui.promptForGitHubSignIn('https://evil.example.com')`.
6. Desktop shows a "Sign in" dialog stating "Git requesting credentials to access `https://evil.example.com`" and begins an enterprise OAuth sign-in flow bound to that attacker-controlled origin — confirming the unauthenticated header alone is sufficient to trigger this security-sensitive flow.

Note: I was not able to trace the full downstream OAuth/device-flow implementation (`beginEnterpriseSignIn` in `dispatcher.ts` / `sign-in-store.ts`) in this pass to determine exactly what network requests are made against the attacker's origin during the flow (e.g., whether a client secret or authorization code could be sent to it); this would need to be verified with a full read of `app/src/lib/stores/sign-in-store.ts` and `app/src/ui/dispatcher/dispatcher.ts` in a follow-up session before assessing the maximum severity of credential/token exposure.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
