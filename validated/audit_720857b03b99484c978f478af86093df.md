### Title
ReceivedOutput::read accepts an arbitrary offset/output pair, reporting unspendable outputs as received - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput::read` deserializes an offset scalar, a `TxOut`, and an `OutPoint` from untrusted bytes with no consistency check between them. In legitimate construction (`Scanner::scan_transaction`), the offset is only attached to an output whose `script_pubkey` equals the P2TR script for `key + offset·G`, i.e., the key the threshold group can actually spend with. The deserialization path skips this binding entirely, analogous to CVE-2017-13670's upload of arbitrary content: arbitrary attacker-controlled bytes are accepted into a structure that is later treated as authoritative.

### Finding Description
`Scanner::scan_transaction` guarantees the invariant that `output.script_pubkey == p2tr(key + offset·G)` by looking the offset up in `self.scripts` keyed on the script [1](#0-0) . `ReceivedOutput::read` instead reads `offset`, `output`, and `outpoint` independently and constructs the object unconditionally [2](#0-1) . There is no field tying the offset to the output, and no post-read verification exists on the type [3](#0-2) . Any `ReceivedOutput` obtained via `read` with a mismatched offset yields a key `key + offset·G` that does not correspond to the output's `script_pubkey`, so the FROST signature produced for it will not satisfy the P2TR output.

### Impact Explanation
An untrusted byte stream fed to `ReceivedOutput::read` produces an output the wallet reports as received (with `value()` returning the decoded amount) that is cryptographically unspendable: the declared offset cannot re-key the group key to the output's script. This is the "funds reported received that are not spendable" acceptance criterion — an attacker who can supply or tamper with serialized `ReceivedOutput` data causes accounting/funding errors equivalent to crediting deposits that can never be moved.

### Likelihood Explanation
Exploitation requires attacker control over bytes reaching `ReceivedOutput::read` (listed in scope for untrusted input). Where this data passes over an untrusted channel, the attack is a pure byte-level forgery — no cryptographic break needed, since the check that would reject it is simply absent. Likelihood is therefore bounded by whether the integrator deserializes attacker-controlled `ReceivedOutput`s; the bug itself is deterministic.

### Recommendation
After decoding in `ReceivedOutput::read`, recompute `p2tr_script_buf(key + GENERATOR * offset)` for the expected base key and reject the input if it does not equal `output.script_pubkey` — or store/verify the script→offset association via a `Scanner` rather than trusting the serialized offset. Alternatively, serialize only the `OutPoint` and re-derive the offset/output pair from chain data through `Scanner::scan_transaction`.

### Proof of Concept
```
// Given base group key K and a legitimately registered offset o:
//   script = p2tr(K + o·G)
// Attacker crafts bytes:
//   offset' = arbitrary scalar (e.g., o + 1)
//   output' = TxOut { value: 1_000_000, script_pubkey: script }
//   outpoint' = any OutPoint
// ReceivedOutput::read(buf) returns Ok(ReceivedOutput { offset', output', outpoint' })
// value() == 1_000_000 (reported received)
// Spending re-keys to K + (o+1)·G whose P2TR script != output'.script_pubkey
// → signature cannot satisfy the output; funds unspendable.
```
The mismatch passes silently because `read` performs no re-derivation of the script from `offset` [2](#0-1) .

  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
