Confirmed critical finding: `create_reimburse_txhandler` in `core/src/builder/transaction/operator_reimburse.rs:341-385` spends the actual deposit's `MoveToVaultTx` output (`UtxoVout::DepositInMove`) — i.e., the depositor's escrowed BTC — directly to the operator named in the OP_RETURN. This is real bridge value, not merely the operator's own recycled collateral.

### Title
Operator reimbursed from move-to-vault escrow for a payout it never funded via forged OP_RETURN attribution - (File: core/src/verifier.rs::update_finalized_payouts, core/src/database/verifier.rs::get_first_unhandled_payout_by_operator_xonly_pk, core/src/task/payout_checker.rs::PayoutCheckerTask::run_once)

### Summary
The withdrawal user's authorization signature uses `TapSighashType::SinglePlusAnyoneCanPay` (enforced in `core/src/rpc/parser/operator.rs::parse_withdrawal_sig_params`), which only commits to input 0's prevout and output 0 (the user's payout amount). It does not cover additional funding inputs or the OP_RETURN output added in `create_payout_txhandler` (`core/src/builder/transaction/operator_reimburse.rs:407-436`). Because the OP_RETURN is unsigned, any unprivileged party possessing the user's withdrawal signature (i.e., the withdrawer itself) can front the payout with their own BTC while writing an arbitrary honest operator's xonly pubkey into the OP_RETURN, causing `verifier.rs::update_finalized_payouts` to record that operator as `payout_payer_operator_xonly_pk` with no verification that the named operator actually supplied any funds.

### Finding Description
The broken binding is: `payout_payer_operator_xonly_pk (DB) == the operator that actually funded the withdrawal payout`. The code never enforces this equality; it only trusts the OP_RETURN bytes.

Path:
1. Attacker (the withdrawer, an unprivileged Citrea Bridge `withdraw` caller) obtains their own withdrawal UTXO and signs it with `SinglePlusAnyoneCanPay` as required (`core/src/rpc/parser/operator.rs:174-187`). This sighash type commits only to input 0 and output 0 [1](#0-0) .
2. Instead of letting an operator front the withdrawal, the attacker constructs their own payout transaction using `create_payout_txhandler`'s structure: input 0 = withdrawal UTXO + valid user sig, additional attacker-funded input(s) to cover the payout amount, output 0 = the same payout to themselves, and an OP_RETURN naming an arbitrary honest operator's xonly pubkey instead of their own [2](#0-1) . Since the OP_RETURN and extra inputs fall outside the SIGHASH_SINGLE|ANYONECANPAY commitment, the original user signature remains valid.
3. Attacker broadcasts this transaction, racing/replacing the legitimate operator's payout tx for the same withdrawal UTXO.
4. `Verifier::update_finalized_payouts` parses the first OP_RETURN output and blindly writes it as `payout_payer_operator_xonly_pk` via `update_payout_txs_and_payer_operator_xonly_pk`, with no check binding the named key to who actually funded the tx [3](#0-2) .
5. `get_first_unhandled_payout_by_operator_xonly_pk` returns this withdrawal row keyed exactly on that forged pubkey [4](#0-3) .
6. The framed (honest) operator's own `PayoutCheckerTask::run_once`, querying with its own `signer.xonly_public_key`, picks up this row, calls `handle_finalized_payout`, and later `mark_payout_handled` [5](#0-4) .
7. `handle_finalized_payout` allocates a real kickoff connector and proceeds through the Kickoff → Reimburse chain automatically (automation feature) [6](#0-5) .
8. `Verifier::is_kickoff_malicious` only checks *internal consistency* — that the OP_RETURN operator equals `kickoff_data.operator_xonly_pk` — which trivially matches since both are the framed operator's own key; it does not verify that operator actually supplied the payout funds [7](#0-6) .
9. `create_reimburse_txhandler` ultimately spends `MoveToVaultTx`'s `DepositInMove` output — the depositor's actual escrowed BTC — to the operator's reimbursement address [8](#0-7) .

No existing guard (SECP.verify_schnorr on the user's SIGHASH_SINGLE|ANYONECANPAY signature, `is_kickoff_malicious`, `verify_storage_proofs`, `SPV::verify`, or the bridge circuit) checks that the additional funding input(s) of the payout tx belong to the operator named in the OP_RETURN. The bridge circuit (`circuits-lib/src/bridge_circuit/mod.rs:206-229`) also only re-extracts and trusts the same unsigned OP_RETURN bytes for `deposit_constant`, so the on-chain disprove machinery cannot detect this misattribution either — it was never designed to authenticate "who funded the payout," only that the OP_RETURN/kickoff/committed blockhash are self-consistent.

### Impact Explanation
Critical: an honest operator, running standard automation, is credited (via a real `Reimburse` transaction spending `MoveToVaultTx`'s deposit output) for a withdrawal payout it never made. This spends real escrowed bridge/deposit BTC to that operator with no corresponding legitimate fronting by them — money leaves the deposit's vault UTXO without a "true" fronting operator ever being paid back for their own funds, since the framed operator's collateral/kickoff cycle produces a reimbursement they didn't earn. This exactly matches the stated Critical category "an operator reimbursed for a payout it never funded." It is repeatable per withdrawal and can target any operator whose xonly pubkey is known (public information), and is not limited to a single deposit.

### Likelihood Explanation
The attacker needs no privileged role: only the ability to (a) create the withdrawal request/signature as a normal user (already required and permitted per threat model), (b) possess enough BTC to fund the payout output themselves (identical cost to what an honest operator would spend), and (c) win the race to get their forged-OP_RETURN transaction confirmed first (or before an honest operator's version, e.g., via fee bumping/RBF since the operator's payout tx uses RBF via `fund_raw_transaction`). Feasibility is high: the sighash type is fixed by protocol design (`SinglePlusAnyoneCanPay`) specifically to allow flexible funding, but this flexibility also frees the OP_RETURN from cryptographic protection. This requires the "automation" feature to be enabled for the fully automatic pathway to Reimburse, which is the default described flow in this repo.

### Recommendation
Bind the OP_RETURN operator attribution cryptographically to the actual funder: e.g., require the additional funding input(s) of the payout transaction to be provably controlled by/co-signed with the operator's own key (or require the operator's own signature over the full transaction including the OP_RETURN, instead of relying on a raw, unauthenticated `parse_op_return_data` result), and validate this both in `update_finalized_payouts` before writing `payout_payer_operator_xonly_pk`, and in the bridge circuit / `is_kickoff_malicious` before allowing kickoff/reimbursement to proceed.

### Proof of Concept

2. Construct and broadcast a payout transaction like `create_payout_txhandler` but with an attacker-funded extra input covering the payout amount, and an OP_RETURN containing `operator1_xonly_pk` — a different operator than the one actually supplying the funding input.
3. Run block sync so `update_finalized_payouts` records `payout_payer_operator_xonly_pk = operator1_xonly_pk` for that withdrawal idx (assert via `db.get_payout_info_from_move_txid`).

5. pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }

    async fn run_once(&mut self) -> Result<Self::Output, BridgeError> {
        let mut dbtx = self.db.begin_transaction().await?;
        let unhandled_payout = self
            .db
            .get_first_unhandled_payout_by_operator_xonly_pk(
                Some(&mut dbtx),
                self.operator.signer.xonly_public_key,
            )
            .await?;

        if unhandled_payout.is_none() {
            return Ok(false);
        }

        let (citrea_idx, move_to_vault_txid, payout_tx_blockhash) =
            unhandled_payout.expect("Must be Some");

        tracing::info!(
            "Unhandled payout found for withdrawal {}, move_txid: {}",
            citrea_idx,
            move_to_vault_txid
        );

        let deposit_data = self
            .db
            .get_deposit_data_with_move_tx(Some(&mut dbtx), move_to_vault_txid)
            .await?;
        if deposit_data.is_none() {
            return Err(eyre::eyre!("Fronted withdrawal for move tx {move_to_vault_txid} found, but the signatures for the deposit are not found in the db.").into());
        }

        let deposit_data = deposit_data.expect("Must be Some");

        let kickoff_txid = self
            .operator
            .handle_finalized_payout(
                &mut dbtx,
                deposit_data.get_deposit_outpoint(),
                payout_tx_blockhash,
            )
            .await?;

        // fetch and save the LCP for if we get challenged and need to provide proof of payout later
        let (_, payout_block_height) = self
            .operator
            .db
            .get_block_info_from_hash(Some(&mut dbtx), payout_tx_blockhash)
            .await?
            .ok_or_eyre("Couldn't find payout blockhash in bitcoin sync")?;

        let _ = self
            .operator
            .citrea_client
            .fetch_validate_and_store_lcp(
                payout_block_height as u64,
                citrea_idx,
                &self.operator.db,
                Some(&mut dbtx),
                self.operator.config.protocol_paramset(),
            )
            .await?;

        #[cfg(feature = "automation")]
        self.operator.end_round(&mut dbtx).await?;

        self.db
            .mark_payout_handled(Some(&mut dbtx), citrea_idx, kickoff_txid)
            .await?;

        dbtx.commit().await?;

        Ok(true)
    }
