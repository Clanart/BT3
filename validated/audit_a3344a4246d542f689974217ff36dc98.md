### Title
Broken forfeiture logic in `mWOMSVBaseRewarder._calExpireForfeit` lets any staker (including cooldown/unlocking stakers) claim 100% of rewards with zero forfeiture, enabling front-running of newly queued rewards - ([File: rewards/mWOMSVBaseRewarder.sol])

### Summary
`mWOMSVBaseRewarder._calExpireForfeit` never queries `mWOMSV`'s actual rewardable percentage — it hardcodes `rewardableAmount = _amount`, so `forfeitAmount` is always `0`. This is inconsistent with the sibling contract `vlMGPBaseRewarder`, whose `_calExpireForfeit` correctly calls `vlMGP.getRewardablePercentWAD(_account)` to scale down rewards for users in/through cooldown. As a result, an attacker who deposits mWOMSV and immediately starts unlocking the full balance still receives 100% of `earned()` via `getReward`/`getRewards`, with none of the intended forfeiture redistributed to long-term lockers.

### Finding Description
`earned()`/`_earned()` computes reward entitlement purely from `balanceOf(_account)` (the staked amount in `MasterMagpie`), independent of cooldown state: [1](#0-0) 

The mechanism intended to claw back rewards from users mid-unlock is `_calExpireForfeit`, invoked from `_sendReward` on every `getReward`/`getRewards` call: [2](#0-1) 

However, `_calExpireForfeit` in `mWOMSVBaseRewarder.sol` is broken — it sets `rewardableAmount = _amount` unconditionally and never calls `mWOMSV.getRewardablePercentWAD(_account)`, so `forfeitAmount` is always `_amount - _amount = 0`: [3](#0-2) 

Compare this to the sibling `vlMGPBaseRewarder._calExpireForfeit`, which correctly scales by the locker's rewardable percentage: [4](#0-3) 

`mWomSV.getRewardablePercentWAD` exists and is designed exactly for this purpose — it computes a percentage that discounts amounts currently in cooldown (or fully unlocked-but-unclaimed) relative to full lock: [5](#0-4) 

But `mWOMSVBaseRewarder` never calls it. Because of this, the attacker path described works exactly as stated: deposit mWOMSV → `mWomSV.unlock`/`startUnlock` the full balance (entering or completing cooldown) → `queueNewRewards` increases `rewardPerTokenStored` → attacker calls `MasterMagpie.claim` → `getReward` → `_sendReward` → `_calExpireForfeit` returns `0` forfeiture regardless of cooldown state → attacker receives the full `earned()` amount. No modifier (`onlyMasterMagpie`, `updateReward`) blocks this, since these only gate access/state-sync, not the forfeiture calculation itself.

### Impact Explanation
This breaks the reward-forfeiture invariant for the mWOMSV reward pool: users in or past cooldown are supposed to forfeit a portion of pending rewards (redistributed via `_queueNewRewardsWithoutTransfer` to remaining long-term stakers), but currently 0% is ever forfeited. This is a theft/misallocation of unclaimed yield — rewards that should be redistributed back into the pool for long-term lockers are instead fully captured by short-term/cooldown depositors, matching the Immunefi impact class "theft of unclaimed yield" from other stakers.

### Likelihood Explanation
Trivial and fully repeatable: any unprivileged EOA can deposit any amount of mWOMSV-eligible LP tokens, start/complete an unlock, and call claim through `MasterMagpie` at any time — no special capital, timing precision, or privileged role is required (though timing right after `queueNewRewards`/`ManualCompound` maximizes benefit). This applies to every claim on this rewarder, not merely one contrived scenario, since the forfeiture path is unconditionally dead code.

### Recommendation
Fix `_calExpireForfeit` in `rewards/mWOMSVBaseRewarder.sol` to mirror `vlMGPBaseRewarder`'s implementation, scaling `rewardableAmount` by `mWOMSV.getRewardablePercentWAD(_account)`:
```solidity
function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
    uint256 rewardablePercentWAD = mWOMSV.getRewardablePercentWAD(_account);
    uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
    if (rewardableAmount > _amount)
        revert InvalidRewardableAmount();

    uint256 forfeitAmount = _amount - rewardableAmount;

    if (forfeitAmount < (_amount / 1000)) {
        forfeitAmount = 0;
        rewardableAmount = _amount;
    }

    return forfeitAmount;
}
```
Ensure `ILocker` (or the concrete `mWOMSV` type used) exposes `getRewardablePercentWAD` so this compiles/links correctly.

### Proof of Concept
Foundry test plan:
1. Deploy `mWOMSVBaseRewarder`, `mWomSV`, `MasterMagpie`, and a reward token; register the rewarder for the mWOMSV pool.
2. Two actors: `honestLocker` deposits and stays fully locked; `attacker` deposits a small amount of the LP-derived mWOMSV.
3. `attacker` calls `mWomSV.startUnlock(fullAmount)` (or `unlock` after cooldown elapses, depending on which slot state is being tested) in the same block/period as step 4.
4. Reward manager calls `queueNewRewards(amount, rewardToken)` on the rewarder (simulating `ManualCompound`/`WombatBribeManager`).
5. Assert `rewarder.calExpireForfeit(attacker, rewardToken) == 0` even though `mWomSV.getRewardablePercentWAD(attacker) < 1e18` (i.e., attacker is not fully rewardable per the locker's own accounting).
6. `attacker` calls `MasterMagpie.claim` (routes to `getReward`); assert attacker receives `earned(attacker, rewardToken)` in full — i.e., `toSend == userRewards` with no reduction — proving forfeiture was bypassed.
7. Quantify the diverted amount: compare against the expected forfeited amount computed as `earned * (1e18 - getRewardablePercentWAD(attacker)) / 1e18`, which under a correct implementation would have been re-queued via `_queueNewRewardsWithoutTransfer` and redistributed to `honestLocker`.

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalmWomSV = fullyInLock + inCoolDown;
        if (userTotalmWomSV == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalmWomSV;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalmWomSV / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalmWomSV;
                }

            }
        }

        return percent;
    }
