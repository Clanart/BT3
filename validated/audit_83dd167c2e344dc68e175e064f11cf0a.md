### Title
Ed448 decoding accepts identity and torsion points as prime-group elements - (File: crypto/ed448/src/point.rs)

### Summary
Ed448’s subgroup check is tautological and therefore accepts identity and low-order/torsion components while still satisfying the `PrimeGroup` contract expected by `Ciphersuite::read_G` and generic proof/signature verification.

### Finding Description
`Point::is_torsion_free` computes `(-P) + P`, which is identity for every point, so `GroupEncoding::from_bytes` accepts any otherwise-decodable Ed448 point regardless of subgroup membership [1](#0-0) . `Ciphersuite::read_G` relies on `from_bytes` plus canonical re-encoding and does not separately reject the identity [2](#0-1) . Consequently, untrusted Ed448 encodings can represent values outside the intended prime-order group while being treated as valid `PrimeGroup` elements. Generic Schnorr verification then evaluates `R + cA - sG == 0`; for an accepted identity public key `A`, the challenge term disappears and any `R = sG` verifies for every message/challenge [3](#0-2) .

### Impact Explanation
An unprivileged party can supply an Ed448 identity key encoding and a correspondingly constructed signature or proof and have it accepted as if it belonged to the prime-order group. This enables signature/proof forgery in any reachable flow that accepts attacker-selected Ed448 public keys or statement points through `Ed448::read_G`, `SchnorrSignature::read`, `DLEqProof::read`, or a `verify` API.

### Likelihood Explanation
The malformed input is a single canonical Ed448 encoding and requires no private key, network privilege, malformed length, or collision. Exploitation requires the calling protocol to accept an attacker-controlled Ed448 key or proof statement; paths enforcing the stricter `Curve::read_G` reject the identity, but generic `Ciphersuite::read_G` consumers do not [4](#0-3) .

### Recommendation
Implement a real cofactor/subgroup check for Ed448, such as rejecting identity and requiring multiplication by the cofactor-cleared order to yield identity, or equivalently checking the point lies in the prime-order subgroup. Ensure `from_bytes` rejects identity and all torsion components before `Ciphersuite::read_G` performs its canonicality comparison.

### Proof of Concept
For an Ed448 verifier accepting an attacker-supplied public key:

1. Encode the affine Ed448 identity as `y = 1`, sign bit `0`: the 57-byte encoding `[0x01, 0x00, ..., 0x00]`.
2. `Ed448::read_G` accepts it because `Point::from_bytes` invokes the always-true `is_torsion_free`.
3. Choose any scalar `s` and construct `R = s * Ed448::generator()`.
4. Submit `SchnorrSignature { R, s }` for verification under the decoded identity key.
5. Verification computes `R + c*identity - s*G`, which is identity for every challenge `c`, so the forged signature succeeds.
