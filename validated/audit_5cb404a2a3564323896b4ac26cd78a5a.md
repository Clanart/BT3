## Title
Path Traversal via Symlinked Working-Directory Entries in Diff Syntax Highlighting - (File: app/src/ui/diff/syntax-highlighting/index.ts)

### Summary
`getNewFileContent` builds the on-disk path for a working-directory file change with a raw `Path.join(repository.path, file.path)` and hands it straight to `readPartialFile`, which uses `fs.createReadStream` and therefore follows symlinks. Unlike other file-reading code paths in this codebase, this call never validates that the resolved real path stays inside the repository, so a tracked directory that is a symlink pointing outside the repo can be used to make the renderer read and display arbitrary out-of-tree file contents.

### Finding Description
`getNewFileContent` reads working directory file contents for syntax highlighting like this: [1](#0-0) 

`file.path` is the repository-root-relative path taken verbatim from `git status --porcelain=2 -z` output, parsed in `parseChangedEntry`/`parseUntrackedEntry` and stored on `WorkingDirectoryFileChange` without any filesystem-level validation: [2](#0-1) [3](#0-2) 

`readPartialFile` simply opens a read stream at the given path with no symlink checks: [4](#0-3) 

The codebase already has a purpose-built defense for exactly this class of bug — `resolveWithin`/`_resolveWithin` in `app/src/lib/path.ts`, which `realpath`s both the root and the resolved path and rejects anything that escapes the root after symlink resolution (with dedicated tests for the “symlink used to traverse outside of the root” case): [5](#0-4) [6](#0-5) 

This helper is used elsewhere (e.g. `app/src/lib/copilot-conflict-context.ts`'s `buildConflictContext`, which explicitly guards "path traversal and symlink escapes" before reading conflicted files): [7](#0-6) 

but `getNewFileContent` in the syntax-highlighting module does not call `resolveWithin` (or any equivalent check) before joining `repository.path` with `file.path` and reading the target. If a repository contains a tracked directory entry that is a symlink pointing outside the working tree, `git status` will report a path like `symlinked-dir/secret.txt` that is syntactically "inside" `repository.path` per `Path.join`, but resolves on disk (following the symlink) to a location outside the repo. `readPartialFile` will happily stream that out-of-tree file's contents into the renderer for syntax highlighting/diff display.

### Impact Explanation
This allows a malicious repository (something the attacker fully controls, per scope — a "cloned/fetched repository") to make GitHub Desktop read and render file contents from outside the working directory whenever the victim views the seamless diff for a file under the symlinked path (e.g. after modifying/creating such a file so it shows up as a working directory change). This is an out-of-repo file read that gets displayed in the renderer, matching the "file... read outside the repo" impact category in scope.

### Likelihood Explanation
The victim needs to have a symlinked directory checked out as part of a cloned repository and to trigger a diff view of a corresponding working-directory file change — this is a fairly natural workflow (viewing changes/diffs is core Desktop functionality) and doesn't require unusual user steps beyond opening the repository and looking at the Changes/diff view, which the diff-switcher renders via `getFileContents`.

### Recommendation
In `getNewFileContent` (app/src/ui/diff/syntax-highlighting/index.ts), replace the raw `Path.join(repository.path, file.path)` with a call to the existing `resolveWithin(repository.path, file.path)` helper (as already done in `copilot-conflict-context.ts`), and treat a `null` result (path escapes the repo root, including via symlink) as "no content" instead of attempting to read it.

### Proof of Concept
1. Clone/create a repository containing a symlinked directory whose target resolves outside the repository root (e.g. `ln -s /path/outside repo/linked-dir`), commit the symlink.
2. Create/place a file at `repo/linked-dir/secret.txt` on disk (physically written to the outside target) so `git status` reports it as a new/modified working directory file `linked-dir/secret.txt`.
3. Open the repository in GitHub Desktop, select that file in Changes to trigger the seamless diff switcher / `getFileContents` → `getNewFileContent`.
4. Observe that `readPartialFile(Path.join(repository.path, 'linked-dir/secret.txt'), ...)` follows the symlink and the outside file's contents are rendered in the diff view.

export async function readPartialFile(
  path: string,
  start: number,
  end: number
): Promise<Buffer> {
  return await new Promise<Buffer>((resolve, reject) => {
    const chunks = new Array<Buffer>()
    let total = 0

    createReadStream(path, { start, end })
      .on('data', (chunk: Buffer) => {
        chunks.push(chunk)
        total += chunk.length
      })
      .on('error', reject)
      .on('end', () => resolve(Buffer.concat(chunks, total)))
  })
}
```

async function _resolveWithin(
  rootPath: string,
  pathSegments: string[],
  options: {
    join: (...pathSegments: string[]) => string
    normalize: (p: string) => string
    resolve: (...pathSegments: string[]) => string
  } = Path
) {
  // An empty root path would let all relative
  // paths through.
  if (rootPath.length === 0) {
    return null
  }

  const { join, normalize, resolve } = options

  const normalizedRoot = normalize(rootPath)
  const normalizedRelative = normalize(join(...pathSegments))

  // Null bytes has no place in paths.
  if (
    normalizedRoot.indexOf('\0') !== -1 ||
    normalizedRelative.indexOf('\0') !== -1
  ) {
    return null
  }

  // Resolve to an absolute path. Note that this will not contain
  // any directory traversal segments.
  const resolved = resolve(normalizedRoot, normalizedRelative)

  const realRoot = await realpath(normalizedRoot)
  const realResolved = await realpath(resolved)

  return realResolved.startsWith(realRoot) ? resolved : null
}
```
