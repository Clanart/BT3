### Title
Unbounded recursion in `PuzzleWithRestrictions.from_memo()` allows a crafted memo to cause Python stack exhaustion / DoS - (File: chia/wallet/puzzles/custody/custody_architecture.py)

### Summary
`PuzzleWithRestrictions.from_memo()` recursively parses attacker-controlled memo data attached to on-chain `CREATE_COIN` outputs (CHIP-0043 custody puzzles / plotnft memoization). When the memo describes an `MofN` node, `from_memo()` recursively calls itself once per member, with no depth limit, directly mirroring the CVE-2021-3530 bug class (unbounded recursion on crafted symbol/tree data causing stack exhaustion).

### Finding Description
`from_memo()` is a classmethod that reconstructs a `PuzzleWithRestrictions` tree from a `Program` memo blob that comes from chain data (a coin's `memo_blob`), not from a trusted or size-checked source: [1](#0-0) 

Specifically, when `further_branching` is true (i.e., the memo declares an `MofN` puzzle), the code does:
```
puzzle: MIPSComponent = MofN(
    m=m_of_n_hint.m, members=[PuzzleWithRestrictions.from_memo(memo) for memo in m_of_n_hint.member_memos]
)
```
Each member's memo can itself declare another `MofN` with further members, so an attacker can nest `MofN` structures arbitrarily deep. Since this is plain Python recursion (no iterative stack, no depth cap, no bound on `MofNHint.member_memos` length), a sufficiently deep nesting will raise `RecursionError` (uncontrolled Python stack growth) when any node (wallet, pool operator's PlotNFT bookkeeping, or client library) attempts to parse the memo.

This is a real regression risk relative to the rest of the codebase, which explicitly guards against this exact bug class elsewhere: `sha256_treehash()` is intentionally iterative "so we don't have to worry about blowing out the python stack" ( [2](#0-1) ), and the Data Layer's tree-insertion path raises a dedicated `chia_rs.datalayer.RecursionDepthExceededError` for deep line graphs ( [3](#0-2) ). `PuzzleWithRestrictions.from_memo()` has no equivalent protection.

`from_memo()` is reachable from consensus-adjacent, unprivileged-input code paths, most notably `PlotNFT.get_next_from_coin_spend()`, which parses `singleton_create_coin.memo_blob` directly from a coin spend on chain: [4](#0-3) 

Any wallet, farmer, or pool client that resyncs plotnft state, or any custody-wallet client that syncs an unknown inner puzzle from chain (per the documented purpose of `from_memo()`: "This is necessary functionality to sync an unknown inner puzzle from on chain," [5](#0-4) ), will call this recursive parser on attacker-influenced memo bytes taken straight from a spend that was accepted on chain.

### Impact Explanation
A crafted, deeply-nested `MofN` memo (attached to a `CREATE_COIN` condition in a spend, e.g. inside a custody/plotnft-style puzzle) causes any client parsing that memo via `from_memo()` — wallets syncing custody puzzles or pool-client software walking plotnft history — to hit Python's recursion limit and crash with `RecursionError`. This is a spend-triggered, client-side transaction-processing halt: a single confirmed (or even just broadcast/simulated) spend bundle containing such a memo can repeatedly crash any wallet/pool client attempting to resolve/sync that coin's puzzle, which matches the "spend-triggered transaction-processing halt" impact category. It does not directly enable fund theft or consensus divergence, but it is a reliable, low-cost, spend-based denial of service against wallet/pool-client processes that rely on this parsing path.

### Likelihood Explanation
Likelihood is high once a coin using this memoization scheme is created: constructing a deeply nested `MofN` memo requires no special privileges — only crafting a `CREATE_COIN` condition with an oversized/nested memo blob, well within reach of any spend-bundle submitter. The recursion depth needed to exhaust the default CPython stack (~1000 frames, several frames per recursive call here) is easily reachable with a memo of modest size (each level only needs a small nested list), so the cost to the attacker is low relative to the guaranteed crash on the victim's parsing client.

### Recommendation
Convert `PuzzleWithRestrictions.from_memo()` (and the corresponding `MofN` reconstruction) to an iterative, explicit-stack algorithm, mirroring the approach already used in `sha256_treehash()` and the Data Layer's iterative tree walker. At minimum, impose and enforce a maximum nesting depth (returning a clear `ValueError` rather than crashing) before recursing into `MofNHint.member_memos`, and reuse the same bound in any other memo-driven recursive reconstruction (e.g., `unknown_puzzles`, `fill_in_unknown_puzzles`, which are also recursive over `MofN.members`).

### Proof of Concept
Conceptually (following the exact structure used in `test_pwr_errors`, [6](#0-5) ):
```python
from chia.wallet.puzzles.custody.custody_architecture import PuzzleWithRestrictions
from chia.types.blockchain_format.program import Program

def nested_mofn_memo(depth: int) -> Program:
    # base case: a simple UnknownMember leaf memo
    leaf = Program.to((PuzzleWithRestrictions.spec_namespace, [0, [], None, [bytes([0]*32), None]]))
    memo = leaf
    for _ in range(depth):
        # wrap memo as the sole member of a 1-of-1 MofN
        memo = Program.to((PuzzleWithRestrictions.spec_namespace, [0, [], 1, [1, [memo]]]))
    return memo

# depth chosen large enough (e.g. tens of thousands) to exceed Python's recursion limit
malicious_memo = nested_mofn_memo(depth=50_000)
PuzzleWithRestrictions.from_memo(malicious_memo)  # raises RecursionError, crashing the parsing client
```
An attacker embeds `malicious_memo` as the `memo_blob` of a `CREATE_COIN` condition in a spend bundle; any wallet or plotnft-syncing client that later calls `from_memo()` (directly, or via `PlotNFT.get_next_from_coin_spend`) on that memo crashes.

    @classmethod
    def from_memo(cls, memo: Program) -> PuzzleWithRestrictions:
        if memo.atom is not None or memo.first() != Program.to(cls.spec_namespace):
            raise ValueError("Attempting to parse a memo that does not belong to this spec")
        nonce = memo.at("rf")
        restriction_hints_prog = memo.at("rrf")
        further_branching_prog = memo.at("rrrf")
        puzzle_hint_prog = memo.at("rrrrf")
        additional_memos = memo.at("rrrrrf") if memo.at("rrrrr").atom is None else None
        restriction_hints = [RestrictionHint.from_program(hint) for hint in restriction_hints_prog.as_iter()]
        further_branching = further_branching_prog != Program.to(None)
        if further_branching:
            m_of_n_hint = MofNHint.from_program(puzzle_hint_prog)
            puzzle: MIPSComponent = MofN(

            )
