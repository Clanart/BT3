### Title
Unbounded recursive puzzle-layer matching in wallet outer-puzzle drivers allows attacker-controlled deep nesting to exhaust memory/stack (analogous to CVE-2025-49763) - ([File: chia/wallet/outer_puzzles.py])

### Summary
Apache Traffic Server's ESI plugin had no limit on inclusion depth, letting an attacker force unbounded recursive expansion and exhaust memory. The Chia wallet's outer-puzzle driver dispatch (`match_puzzle` in `chia/wallet/outer_puzzles.py`) has the same structural weakness: each driver's `match()` recurses into `self._match()` (bound back to `match_puzzle`) for the puzzle's inner layer, with no maximum recursion/inclusion-depth check, and the "depth" is entirely attacker-controlled by how many recognized outer-puzzle layers (CAT, singleton, ownership, metadata, CR) are curried into a puzzle reveal.

### Finding Description
`match_puzzle()` [1](#0-0)  iterates known drivers and calls `driver.match(puzzle)`. Each driver implementation (e.g. `CATOuterPuzzle.match`, `OwnershipOuterPuzzle.match`, `MetadataOuterPuzzle.match`, `SingletonOuterPuzzle.match`, `CROuterPuzzle.match`) recognizes its own curried layer and then calls `self._match(UnknownPuzzle(known_program=inner_puzzle))` to recurse into the next inner layer, e.g. in `CATOuterPuzzle.match`: [2](#0-1)  and similarly in `OwnershipOuterPuzzle.match`, `MetadataOuterPuzzle.match`, `SingletonOuterPuzzle.match`, and `CROuterPuzzle.match`, all sharing the identical unbounded recursive pattern. `_match` is wired directly to the top-level `match_puzzle` function via `function_args` [3](#0-2) , so recognizing one outer layer immediately triggers another full `match_puzzle` pass on the inner puzzle — a mutual recursion loop bounded only by how many recognizable layers the attacker curries into the puzzle.

There is no `max_inclusion_depth`-style guard anywhere in this dispatch chain, unlike the CVE's fix which added `--max-inclusion-depth`. A puzzle reveal (or a coin's puzzle observed on-chain / included in an offer) can nest CAT-of-CAT-of-CAT (as shown to be constructible in the existing test `test_cat_outer_puzzle`, which builds `double_cat_puzzle = construct_cat_puzzle(CAT_MOD, tail, cat_puzzle)` [4](#0-3) ) arbitrarily deep, and each additional layer costs the attacker only a constant amount of CLVM curry bytes while forcing the victim wallet to perform one more `uncurry()` + recursive `match()` call. The equivalent `construct()`, `get_inner_puzzle()`, and `get_inner_solution()` methods on every outer-puzzle driver follow the identical unbounded recursive-call pattern (see `CATOuterPuzzle.get_inner_puzzle`/`get_inner_solution`, `MetadataOuterPuzzle`, `OwnershipOuterPuzzle`, `SingletonOuterPuzzle`, `CROuterPuzzle` — all cited above), so any wallet code path that reconstructs, matches, or extracts inner puzzles/solutions from an attacker-influenced puzzle reveal is affected, not just `match_puzzle`.

`match_puzzle` is called from offer processing (`chia/wallet/trading/offer.py`), NFT wallet coin processing (`chia/wallet/nft_wallet/nft_wallet.py`), which are code paths a wallet exercises when parsing offers received from an untrusted counterparty or coins observed during wallet sync.

### Impact Explanation
Python has a default recursion limit (~1000), and Rust-backed `uncurry()`/CLVM tree-hash operations performed per recursion layer add real memory and CPU cost per additional nesting level. An attacker who crafts a coin puzzle or offer with hundreds/thousands of nested recognized outer-puzzle layers can force the wallet client to recurse until it hits Python's recursion limit (raising an unhandled `RecursionError`) or, on configurations with a raised recursion limit, to consume excessive stack/heap memory per additional layer, crashing or hanging the wallet's coin-processing/offer-processing thread. This is a spend/offer-triggered denial-of-service against a wallet process — consistent with the "spend-triggered transaction-processing halt" impact class validated by the rules. It affects the local wallet user or offer counterparty processing untrusted data, not consensus-critical full-node paths, keeping severity at denial-of-service rather than fund-loss.

### Likelihood Explanation
Constructing arbitrarily nested CAT/ownership/metadata/singleton/CR puzzle layers is straightforward using existing puzzle-construction helpers (as demonstrated by the codebase's own `construct_cat_puzzle` nesting in tests), requires no special privileges, and can be delivered via a normal offer file or as a coin's puzzle reveal that the victim wallet later processes. No CLVM execution cost applies to `match_puzzle`/`uncurry` calls themselves (they run in Python/Rust helper code outside the metered CLVM cost model), so the existing mempool/CLVM cost limits do not mitigate this path.

### Recommendation
Add an explicit maximum recursion/inclusion depth (analogous to the ESI fix's `--max-inclusion-depth`) to `match_puzzle`, `construct_puzzle`, `get_inner_puzzle`, and `get_inner_solution` dispatch in `chia/wallet/outer_puzzles.py`, and thread a depth counter through each outer-puzzle driver's `match`/`construct`/`get_inner_puzzle`/`get_inner_solution` implementations (`CATOuterPuzzle`, `SingletonOuterPuzzle`, `MetadataOuterPuzzle`, `OwnershipOuterPuzzle`, `CROuterPuzzle`), rejecting/aborting processing once a sane layer-count bound is exceeded rather than recursing unconditionally.

### Proof of Concept
Conceptual PoC (not executed): use `construct_cat_puzzle` (or the equivalent ownership/metadata/singleton curry helpers) to build a puzzle with N (e.g. 5,000+) nested outer layers, following the same pattern the existing test uses for a single extra layer:
```python
puzzle = ACS
for _ in range(N):
    puzzle = construct_cat_puzzle(CAT_MOD, tail, puzzle)  # each iteration adds one recursible layer
match_puzzle(UnknownPuzzle(known_program=puzzle))  # triggers N-deep mutual recursion in match_puzzle/CATOuterPuzzle.match
```
Submitting a coin with this puzzle reveal in an offer, or as an observed coin puzzle during wallet sync, forces the recipient wallet to recurse N times when it later calls `match_puzzle`, `construct_puzzle`, or `get_inner_puzzle`/`get_inner_solution` on the reveal, exhausting the Python call stack (`RecursionError`) or, with a raised limit, driving up memory/CPU until the wallet becomes unresponsive.
