### Title
Unbounded length-prefix read in CLVM canonical-encoding check can raise an uncaught `IndexError` from an attacker-controlled spend bundle - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_atom_canonical()` / `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` walk a CLVM-serialized buffer using multi-byte atom-length prefixes taken directly from untrusted bytes, indexing further into the buffer without first checking that the declared prefix/atom length actually fits inside the remaining buffer. This mirrors the libmodbus root cause in CVE-2019-14463: a count/length field taken from untrusted input is used to keep reading without validating it against the actual remaining buffer size.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads the encoding byte and, depending on its high bits, decides how many additional prefix bytes (`prefix_len`, up to 5) to consume to build `atom_len`: [1](#0-0) 

The loop `for i in range(prefix_len): ... offset += 1; atom_len |= clvm_buffer[offset]` never checks that `offset` stays within `len(clvm_buffer)` before indexing. `is_clvm_canonical()` then loops over the buffer, calling `is_atom_canonical()` and advancing `offset` by `atom_len` (also derived from the untrusted prefix) without validating it against the buffer's remaining length before the next iteration reads `clvm_buffer[offset]`: [2](#0-1) 

Unlike C, Python bytes indexing is bounds-checked, so an out-of-range `offset` raises `IndexError` rather than reading adjacent memory — the memory-safety class of the original CVE does not directly reproduce. However, the underlying defect is the same: a length/count value taken from attacker-supplied bytes is trusted to walk further into a buffer without first confirming the buffer actually contains that many remaining bytes, which is exactly the bug class the report flags (`MODBUS_FC_WRITE_MULTIPLE_REGISTERS` trusting a register/byte count without validating it against the actual payload length).

### Impact Explanation
If a maliciously crafted CLVM buffer (e.g., a puzzle reveal or solution byte string inside a submitted `SpendBundle`) reaches `is_clvm_canonical()`/`is_atom_canonical()` with a truncated multi-byte length prefix or an atom length that overruns the remaining buffer, the unguarded indexing raises an `IndexError`. If this exception is not caught by the caller, it can propagate up through mempool-admission code paths for a user-submitted spend bundle, which is on the reachable attack surface named in scope ("mempool admission and CLVM cost", "condition ... handling"). An uncaught exception during spend-bundle processing is a spend-triggered transaction-processing halt for that code path.

### Likelihood Explanation
Likelihood is moderate: constructing a byte sequence with a malformed multi-byte CLVM atom-length prefix is trivial for any spend bundle submitter, and no external privilege is required. The exact call sites that invoke `is_clvm_canonical()`/`is_atom_canonical()` within `MempoolManager`'s bundle-admission flow, and whether those call sites wrap the call in exception handling, could not be fully confirmed within the available tool budget — this is the key remaining uncertainty affecting whether the `IndexError` is actually unhandled in production.

### Recommendation
Add explicit bounds checks before every indexing operation in `is_atom_canonical()` and `is_clvm_canonical()`: verify `offset < len(clvm_buffer)` before each `clvm_buffer[offset]` access and verify `offset + atom_len <= len(clvm_buffer)` before advancing past an atom, returning a definite "not canonical"/invalid result instead of relying on an `IndexError` to signal malformed input. Additionally, confirm (and if missing, add) exception handling at every call site that invokes these functions with untrusted, attacker-supplied bytes so a malformed buffer cannot propagate an unhandled exception through mempool processing.

### Proof of Concept
A `clvm_buffer` whose final byte encodes a large multi-byte atom-length prefix (e.g., `bytes([0xF8])`, indicating a 5-byte length prefix and requiring 5 more bytes) but is truncated to just that one byte will cause `is_atom_canonical()` to attempt `clvm_buffer[offset]` past the end of the buffer: [3](#0-2) 
This raises `IndexError` inside `is_atom_canonical()`/`is_clvm_canonical()`; whether this exception is caught depends on the (unverified) caller code path in `MempoolManager`.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
