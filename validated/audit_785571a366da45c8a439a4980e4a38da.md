### Title
Deserialized Bitcoin outputs are trusted without validating their claimed value or outpoint - (File: `networks/bitcoin/src/wallet/mod.rs`)

### Summary
`ReceivedOutput::read` accepts an untrusted scalar offset, `TxOut`, and `OutPoint` without verifying that the referenced on-chain output exists, has the claimed value, is spendable, or is even related to the supplied key/offset. `SignableTransaction::new` then uses the deserialized `TxOut` value as the input amount and later commits those same attacker-controlled `prevouts` into the Taproot sighash. This allows a forged serialized output to report funds that cannot actually be spent, or to turn a real received output into an invalid transaction by inflating its amount.

### Finding Description
The report’s bug class is consuming an external value without validating freshness, correctness, or reasonable bounds. In Serai, the analogous path is `ReceivedOutput::read`, which deserializes `offset`, `output`, and `outpoint` directly from caller-controlled bytes and returns them as a claimed spendable output. [1](#0-0) 

`SignableTransaction::new` trusts `input.output.value` when calculating available funds and copies `input.outpoint` into the transaction inputs. [2](#0-1)  It also stores the claimed `TxOut`s in `prevouts`. [3](#0-2) 

The only later consistency check is that `keys + offset` produces the claimed prevout’s `script_pubkey`; it does not check that `outpoint` exists or that its on-chain amount matches the serialized `TxOut`. [4](#0-3)  Signing commits to all supplied prevouts with `Prevouts::All`, so a modified amount changes the sighash but cannot make the resulting transaction valid. [5](#0-4) 

### Impact Explanation
An unprivileged party who can supply serialized `ReceivedOutput`/Bitcoin `Output` bytes can claim a nonexistent or incorrectly valued UTXO. If the claimed script corresponds to the derived key, downstream code treats it as spendable funding. If the script belongs to a real Serai output but the amount is inflated, accounting reports more funds than are spendable and any signed transaction is invalid because its Taproot prevout commitment does not match the actual UTXO. If the outpoint is fabricated, the claimed funds are simply unspendable.

### Likelihood Explanation
This requires a caller to accept serialized wallet outputs from an untrusted source or to deserialize corrupted/malicious output records. `ReceivedOutput::read` exposes no chain-verification step, and `SignableTransaction::new` does not independently recover the referenced prevout. The exploit does not require validator collusion, leaked keys, or malformed curve encodings.

### Recommendation
Treat `ReceivedOutput::read` as a serialization-only primitive and require a separate validation step before spending or crediting it. Validation should resolve the claimed `outpoint` against a trusted Bitcoin node or proof, compare the returned `TxOut` value and `script_pubkey`, reject coinbase/immature outputs where immediate spending is required, and only then construct `SignableTransaction`. Alternatively, make the deserialized representation explicitly unverified and require a verified wrapper for scheduling/signing.

### Proof of Concept
Take a real scanned output serialized by `Scanner::scan_transaction`, decode it, modify `output.value` to a larger amount, re-serialize it, and pass it through `ReceivedOutput::read`. The read succeeds because no relation between `outpoint`, `output`, and chain state is checked. `SignableTransaction::new` then uses the inflated value for fee/funding arithmetic, and `multisig` still succeeds because the unchanged script still matches `key + offset`. The resulting transaction is signed over `Prevouts::All` containing the false amount, so Bitcoin consensus rejects it even though the wallet reported the funds as available.

  /// Read a ReceivedOutput from a generic satisfying Read.
  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }
