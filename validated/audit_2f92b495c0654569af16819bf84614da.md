### Title
`EvmHost.dispatchIncoming(GetResponse)` never clears `_requestCommitments`, allowing a timed-out GET request to be double-settled via `onGetTimeout` after `onGetResponse` already succeeded - (File: `evm/src/core/EvmHost.sol`)

### Summary
This is the local analog of the Optimism `revert`-vs-`return` bug: the external report's core broken invariant is *"a request can be marked as finalized/settled through one path while a parallel path (timeout) still believes it is pending, allowing the pending path to be executed anyway and cause loss/duplication of funds."* In Hyperbridge's `EvmHost.sol`, the GET-request lifecycle has exactly this asymmetry: the success path (`dispatchIncoming(GetResponse)`) never deletes the `_requestCommitments[commitment]` entry that the timeout path (`dispatchTimeOut(GetRequestTimeout)`) uses as its sole "is this request still live" check.

### Finding Description
Compare the two terminal paths for a GET request in `evm/src/core/EvmHost.sol`:

- Success path, `dispatchIncoming(GetResponse ...)`: [1](#0-0) 
This function sets `_responseReceipts[commitment]`, calls `onGetResponse` on the origin module, and on success pays the relayer fee by reading `_requestCommitments[commitment].fee` — but it **never deletes `_requestCommitments[commitment]`**.

- Timeout path, `dispatchTimeOut(GetRequestTimeout ...)`: [2](#0-1) 
This function's *only* gating check for whether the request is still eligible to be timed out is performed one level up in `HandlerV2.handleGetRequestTimeouts`: [3](#0-2) 
That function checks `meta.sender == address(0)` from `host.requestCommitments(commitment)` (line 309-310) as its "is this a known, still-pending request" gate, and separately proves *non-membership* of a response receipt in a **historical** state root at an arbitrary `message.height` chosen by the caller (lines 298-317). Because `stateMachineCommitment` is stored per-height and old heights remain queryable, a caller can supply a height captured **before** the GET response was actually delivered/recorded, together with a valid non-membership proof for that earlier snapshot, while still satisfying `request.timeout() > state.timestamp` is false (i.e., timestamp at that height is already past the request's timeout — plausible for a legitimately late response).

Since `dispatchIncoming(GetResponse)` never clears `_requestCommitments[commitment]`, `meta.sender` remains non-zero forever after a successful response, so `handleGetRequestTimeouts`'s "known request" gate keeps passing indefinitely, and the historical non-membership proof lets the request be timed out **even though it was already successfully responded to**. `dispatchTimeOut` then invokes `IApp.onGetTimeout` on the requesting module a second time for a request whose `onGetResponse` already executed and mutated state/paid out based on real data.

This is a genuine one-time-receipt/commitment-uniqueness violation of the kind the pivots call out explicitly: *"Request, response, and timeout paths must bind ... commitment uniqueness and one-time receipt handling."* The by-design safe-call pattern used elsewhere in this same file (`dispatchIncoming(PostRequest)` deletes `_requestReceipts` on failure only, and `dispatchTimeOut(PostRequestTimeout)`/`dispatchTimeOut(GetRequestTimeout)` delete `_requestCommitments` up front) shows the intended pattern is "delete the commitment once its terminal outcome is settled" — but that deletion is missing specifically for the `GetResponse` success path.

### Impact Explanation
Any application built on `IApp.onGetTimeout` that assumes it is mutually exclusive with a prior successful `onGetResponse` (e.g., an app that escrows funds when dispatching a GET and releases/refunds them on `onGetTimeout` if no response arrived) can be driven into paying out twice for the same request: once via the legitimate `onGetResponse` result, and again via a spuriously-accepted `onGetTimeout` call reusing the stale commitment. This matches the "double-claim / double-settlement" and "logic attack via request/timeout path" categories in the required impact list.

### Likelihood Explanation
The path is reachable by any unprivileged, permissionless caller of `IHandlerV2.handleGetRequestTimeouts` — no relayer, prover, or admin compromise is required. It only requires: (1) a GET response that is delivered later than the request's nominal timeout (a normal, non-malicious occurrence under network delay), and (2) a valid non-membership proof against a historical (pre-response) state commitment height that the host still stores, both of which are attacker-obtainable from public chain data. The main uncertainty is how strict `stateMachineCommitment`'s public queryability/pruning is for old heights and how the counterparty chain's response-receipt trie key is populated relative to the `EvmHost`'s own `_responseReceipts`; I could not fully trace that cross-chain proof binding in the time available, so confirmation requires exercising the exact commitment key/height semantics against a live consensus client in a PoC.

### Recommendation
In `dispatchIncoming(GetResponse ...)`, delete `_requestCommitments[commitment]` once the response has been successfully delivered (mirroring how `dispatchTimeOut` deletes it up front and restores it only on callback failure), so that a request can never again pass the `meta.sender == address(0)` gate in `handleGetRequestTimeouts` after it has been terminally resolved by a response.

### Proof of Concept
1. App `X` dispatches a `GetRequest` via `EvmHost.dispatch(DispatchGet)` with `timeout = T`; `_requestCommitments[commitment]` is populated with `{sender: payer, fee: F}`.
2. Due to network delay, the relayer delivers the response after `T` has elapsed. `HandlerV2` (no relevant timeout check exists for GET responses per code comment "don't check for timeouts because it's checked on Hyperbridge") calls `host.dispatchIncoming(GetResponse, relayer)`; `onGetResponse` succeeds, fee `F` is paid to `relayer`, and `_requestCommitments[commitment]` remains populated.
3. An attacker (or the same relayer) later calls `HandlerV2.handleGetRequestTimeouts` for the same request, supplying `message.height` pointing at a state commitment recorded **before** step 2 occurred (still legally stored/queryable), with a valid non-membership proof of the response receipt at that height, and satisfying `request.timeout() > state.timestamp` == false.
4. `handleGetRequestTimeouts`'s `meta.sender == address(0)` check passes (commitment still present), the stale non-membership proof verifies, and `host.dispatchTimeOut(GetRequestTimeout, ...)` is called, invoking `onGetTimeout` on module `X` a second time for an already-resolved request — triggering any refund/rollback logic `X` performs on timeout in addition to the effects already applied by `onGetResponse`.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
