Audit Report

## Title
Staked connection eviction is committed before verifying the new connection can actually be added, allowing a staked peer to permanently drain the QUIC/TPU staked-connection table - ([File: streamer/src/nonblocking/swqos.rs])

## Summary
`SwQos::try_add_connection` and `SimpleQos::try_add_connection` call `ConnectionTable::prune_random` to unconditionally evict a lower-stake connection whenever the staked connection table is at/over capacity, before checking whether the connecting peer's own per-peer connection cap (`max_connections_per_peer` / `max_connections_per_staked_peer`) will allow the insertion to succeed. Because the eviction is committed to `self.table` immediately inside `prune_random` and is never rolled back if the subsequent `try_add_connection` call rejects the new connection due to the caller's own per-peer cap, an attacker can repeatedly evict other staked peers' connections while never occupying the freed slot.

## Finding Description
`ConnectionTable::prune_random` in [1](#0-0)  samples random entries and, if the minimum-stake sampled entry is below `threshold_stake`, calls `self.table.swap_remove_index(index)` — removing that entry from the table immediately and unconditionally, decrementing `self.total_size`.

`ConnectionTable::try_add_connection` in [2](#0-1)  separately enforces a per-key cap: it computes `has_connection_capacity` from `connection_entry.len() + 1 <= max_connections_per_peer` and rejects (closing with `CONNECTION_CLOSE_CODE_TOO_MANY`) if the cap is already reached for that specific `ConnectionTableKey`.

Both `SwQos::try_add_connection` ( [3](#0-2) ) and `SimpleQos::try_add_connection` ( [4](#0-3) ) follow the same sequence: first check `total_size >= max_staked_connections` and call `prune_random` if so (unconditional eviction), then separately check `total_size < max_staked_connections` and attempt `cache_new_connection` → `ConnectionTable::try_add_connection`. `cache_new_connection` in both `swqos.rs` ( [5](#0-4) ) and `simple_qos.rs` ( [6](#0-5) ) passes the connecting peer's own per-peer cap into `try_add_connection`, which is checked against the *connecting key's* existing entry count — independent of and unrelated to which entry `prune_random` evicted (a different, lower-stake key sampled at random).

This confirms there is no capacity pre-check on the connecting key before `prune_random` runs, and no rollback mechanism if the subsequent per-peer-cap check fails, exactly as the claim describes.

## Impact Explanation
A staked peer that has already filled its own per-peer slot (`max_connections_per_staked_peer` in `swqos.rs`, or `max_connections_per_peer` in `simple_qos.rs`) can issue additional connection attempts. Each attempt:
1. Passes `total_size >= max_staked_connections` (true whenever the table is at capacity from legitimate traffic).
2. Triggers `prune_random`, which evicts some other lower-stake staked peer's connection entry from `self.table`, as long as the sampled minimum stake is below the attacker's own stake.
3. Fails at `ConnectionTable::try_add_connection`'s `has_connection_capacity` check because the attacker's own key is already at its per-peer cap, so no compensating insertion occurs.

The net effect is a legitimate lower-stake staked validator's connection is evicted from the table (a genuine resource-bound corruption: the staked connection table's occupancy/`self.total_size` and specific victim connection entries), with no replacement, degrading TPU QUIC connectivity for other staked validators. This matches the "non-RPC remote exhaustion/degradation" impact category, since the attacker is an ordinary staked node (not privileged) exploiting an unprivileged QUIC/TPU connection-admission path.

## Likelihood Explanation
The attacker needs only: (a) a staked keypair capable of opening QUIC connections to the TPU/TPU-forward port — an ordinary, unprivileged capability, and (b) enough stake to exceed the minimum of a 2-entry random sample (`PRUNE_RANDOM_SAMPLE_SIZE = 2` in both `swqos.rs` and `simple_qos.rs`). No leaked keys, elevated privileges, or validator cooperation are required. Filling one's own per-peer slot and then repeatedly opening/dropping connections is entirely within a normal client's control, making the attack cheap and repeatable.

## Recommendation
Before invoking `prune_random`, check whether the connecting `ConnectionTableKey` has spare capacity under its applicable `max_connections_per_peer`/`max_connections_per_staked_peer` limit (mirroring the `has_connection_capacity` logic in `ConnectionTable::try_add_connection`), and only prune if that pre-check passes. Alternatively, merge pruning and insertion into a single guarded/atomic operation within `ConnectionTable`, so that if the insertion ultimately fails due to the per-peer cap, the pruned entry is restored (or the prune is deferred until insertion is guaranteed to succeed).

## Proof of Concept
1. Attacker controls a staked keypair `K` with stake `s`.
2. Attacker opens `max_connections_per_staked_peer` (or `max_connections_per_peer` for `SimpleQos`) QUIC connections from `K`, filling `K`'s per-peer slot in `staked_connection_table`.
3. Attacker opens one more QUIC connection from `K` while `staked_connection_table.total_size >= max_staked_connections` (true under ordinary cluster load). This triggers `connection_table_l.prune_random(2, s)` ( [7](#0-6) ), evicting some other staked peer's connection with stake below `s`.
4. `cache_new_connection` → `ConnectionTable::try_add_connection` rejects the new connection for `K` because `has_connection_capacity` is false ( [8](#0-7) ); the connection closes with `CONNECTION_CLOSE_CODE_TOO_MANY`.
5. Repeating step 3 indefinitely removes one legitimate lower-stake staked connection from `staked_connection_table` per cycle with no compensating addition, progressively reducing the table's effective staked population and degrading TPU availability for lower-stake validators. This can be verified with a Rust unit test extending the existing `test_cache_new_connection_max_connections_reached` pattern ( [9](#0-8) ): populate `staked_connection_table` to `max_staked_connections` with distinct low/high-stake keys, saturate the attacker key's per-peer slot, then repeatedly invoke `try_add_connection` for the attacker and assert that `total_size` decreases over successive calls while the attacker's own connection count never increases.

    pub(crate) fn prune_random(&mut self, sample_size: usize, threshold_stake: u64) -> usize {
        let num_pruned = std::iter::once(self.table.len())
            .filter(|&size| size > 0)
            .flat_map(|size| {
                let mut rng = rng();
                repeat_with(move || rng.random_range(0..size))
            })
            .map(|index| {
                let connection = self.table[index].first();
                let stake = connection.map(|connection: &ConnectionEntry<S>| connection.stake());
                (index, stake)
            })
            .take(sample_size)
            .min_by_key(|&(_, stake)| stake)
            .filter(|&(_, stake)| stake < Some(threshold_stake))
            .and_then(|(index, _)| self.table.swap_remove_index(index))
            .map(|(_, connections)| connections.len())
            .unwrap_or_default();
        self.total_size = self.total_size.saturating_sub(num_pruned);
        num_pruned
    }

            .checked_add(1)

                cancel.clone(),
                peer_type,
                last_update.clone(),
                port,
                client_connection_tracker,
                connection,
                stream_counter.clone(),
            ));
            self.total_size += 1;
            Some((last_update, cancel, stream_counter))
        } else {
            if let Some(connection) = connection {
                connection.close(
                    CONNECTION_CLOSE_CODE_TOO_MANY.into(),
                    CONNECTION_CLOSE_REASON_TOO_MANY,
                );
            }
            None
        }

    async fn test_cache_new_connection_max_connections_reached() {

        let cancel = CancellationToken::new();
        let stats = Arc::new(StreamerStats::default());

        let simple_qos = SimpleQos::new(

                max_connections_per_peer: 1,

            stats.clone(),

            cancel.clone(),

        let mut connection_table =
            ConnectionTable::new(ConnectionTableType::Staked, cancel.clone());

        // Create first server-side connection and add it to reach the limit
        let (connection1, _client_endpoint1, _server_endpoint1) =
            create_server_side_connection().await;
        let remote_addr = connection1.remote_address();
        let key = ConnectionTableKey::new(remote_addr.ip(), None);

        let client_tracker1 = ClientConnectionTracker {
            stats: stats.clone(),
        };

        // Add first connection to reach the limit
        let _ = connection_table.try_add_connection(
            key,
            remote_addr.port(),
            client_tracker1,
            Some(connection1),
            ConnectionPeerType::Staked(1000),
            Arc::new(AtomicU64::new(0)),
            1, // max_connections_per_peer
            || Arc::new(TokenBucket::new(1, 1, 1.0)),

        let connection_table_guard = tokio::sync::Mutex::new(connection_table);
        let connection_table_l = connection_table_guard.lock().await;

        // Try to add second connection (should fail)
        let (connection2, _client_endpoint2, _server_endpoint2) =
            create_server_side_connection().await;
        let client_tracker2 = ClientConnectionTracker {
            stats: stats.clone(),
        };

        let conn_context = SimpleQosConnectionContext {
            peer_type: ConnectionPeerType::Staked(1000),
            remote_pubkey: None,
            remote_address: remote_addr,
            last_update: Arc::new(AtomicU64::new(0)),
            stream_counter: None,
        };

        // Test
        let result = simple_qos.cache_new_connection(
            client_tracker2,
            &connection2, // Use server-side connection
            connection_table_l,
            &conn_context,
        );

        // Verify failure due to connection limit
        assert!(result.is_err());

        // Verify stats were updated
