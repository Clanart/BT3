## Finding



### Title
Attacker-Controlled `WWW-Authenticate` Header Triggers Unverified GitHub Enterprise Sign-In Binding - (File: app/src/lib/trampoline/trampoline-credential-helper.ts)

### Summary
`getEndpointKind()` classifies a git remote as an `'enterprise'` (GitHub Enterprise Server) host purely by inspecting the `wwwauth[]` credential fields — content that originates from the `WWW-Authenticate` HTTP response header sent by the remote git server itself — before performing (or in lieu of) the authoritative network probe `isGitHubHost()`. A malicious or compromised git remote/proxy can set `WWW-Authenticate: realm="GitHub"` on an authentication challenge for an arbitrary HTTPS URL and cause Desktop to treat that untrusted host as an "enterprise" GitHub endpoint, triggering the Enterprise sign-in popup and binding the resulting `Account` to the attacker-controlled endpoint.

### Finding Description
When a git command (clone/fetch/push) needs credentials, Desktop's credential-helper trampoline is invoked with the credential fields Git collected, including any `wwwauth[]` entries copied from the server's `WWW-Authenticate` response header: [1](#0-0) 

This heuristic is explicitly a "happy path" used to avoid an actual network verification call, and it runs before `findGitHubTrampolineAccount` (existing-account match) and before the real check `isGitHubHost(endpoint)`: [2](#0-1) 

If the endpoint is classified as `'enterprise'` and there's no already-stored `Account` for that exact origin, `getCredential` calls `ui.promptForGitHubSignIn(endpoint)`: [3](#0-2) 

`promptForGitHubSignIn` then begins an **Enterprise sign-in flow scoped to the attacker-controlled origin** — since the hostname is not literally `github.com`, it calls `beginEnterpriseSignIn` and sets the sign-in endpoint to the attacker's `origin`: [4](#0-3) 

The corrupted value here is the derived `endpointKind`/sign-in `origin`: it is computed from attacker-supplied header content rather than a verified GitHub Enterprise signal. The existing guard (`isGitHubHost`, a real HTTP request to confirm the server is actually a GitHub instance) is bypassed entirely by the `wwwauth[]` fast path, so there is no re-validation before the OAuth/PAT sign-in UI is shown and before any resulting `Account` is persisted and bound to that origin via `AccountsStore`.

### Impact Explanation
A malicious git server (a repository remote the user clones/fetches/pushes to, or a MITM-capable proxy on that connection) can spoof the GitHub Enterprise authentication challenge to make Desktop display its native "Sign in to GitHub Enterprise" dialog for a host the user does not control and never intended to authenticate against. A user who trusts the Desktop-native prompt (since it appears identical to legitimate Enterprise sign-in) may complete OAuth or paste a Personal Access Token, resulting in:
- An `Account` bound (via `findGitHubTrampolineAccount`'s origin match) to the attacker-controlled endpoint, so the token is subsequently sent automatically as Basic Auth on future git operations to that same origin.
- Unauthorized account binding — the account/token addition happens without any real verification that the target is actually a GitHub product, purely on the strength of a spoofable HTTP response header.

This matches the "unauthorized OAuth or account binding" and "credential/token exfiltration" impact classes: the attacker controls the git remote/proxy response that drives the decision.

### Likelihood Explanation
Likelihood is moderate: it requires the user to clone/fetch/push against a repository controlled (or MITM'd) by the attacker and to complete the resulting sign-in prompt. No local access, admin rights, or pre-existing malware is required — only an ordinary git operation against an attacker-supplied remote, which is squarely within GitHub Desktop's threat model (untrusted cloned/fetched repositories and remote/proxy responses).

### Recommendation
Do not let the `wwwauth[]` heuristic alone select the `'enterprise'` classification for security-sensitive decisions (sign-in popup, account binding). At minimum:
- Require the real `isGitHubHost(endpoint)` network verification to succeed before invoking `promptForGitHubSignIn` / `beginEnterpriseSignIn`, even when a `wwwauth[]` GitHub realm hint is present.
- Alternatively, treat the `wwwauth[]`-derived classification as advisory only for prompting UX copy, but gate any `Account`-creation/binding action strictly on the verified `isGitHubHost` result.

### Proof of Concept
1. Attacker hosts a git-over-HTTPS server (or MITM proxy) for a repository URL, e.g. `https://evil.example.com/repo.git`.
2. When Git requests credentials, the attacker's server responds to the unauthenticated request with an HTTP 401 and header `WWW-Authenticate: Basic realm="GitHub"`.
3. Git captures this and forwards it to Desktop's credential helper as `wwwauth[0]=Basic realm="GitHub"` on the `get` command.
4. In `getEndpointKind`, the loop at `app/src/lib/trampoline/trampoline-credential-helper.ts:157-165` matches `realm="GitHub"` and immediately returns `'enterprise'`, without calling `isGitHubHost`.
5. Since no `Account` in `AccountsStore` matches `https://evil.example.com`, `getCredential` calls `ui.promptForGitHubSignIn('https://evil.example.com/repo.git')`.
6. `promptForGitHubSignIn` (hostname ≠ `github.com`) calls `dispatcher.beginEnterpriseSignIn(cb)` and `dispatcher.setSignInEndpoint('https://evil.example.com')`, displaying Desktop's native Enterprise sign-in dialog for the attacker's domain.
7. If the user completes sign-in (OAuth or PAT) believing it's a legitimate corporate GHES prompt, an `Account` bound to `evil.example.com` is created and persisted, and its token will be sent as Basic Auth to that origin on subsequent git operations matched via `findGitHubTrampolineAccount`.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
