Based on the code I was able to examine, the strongest local analog to the Flayer "self-triggered cheap loophole" pattern is in Hyperbridge's `IntentGatewayV2` cross-chain order cancellation logic, specifically the `_cancelFromSource` / `onGetResponse` path in `evm/src/apps/intentsv2/ExtrinsicIntents.sol`.

### Title
Stale-height GET proof lets `cancelOrder` accept outdated destination state, enabling double-settlement of escrow - (File: evm/src/apps/intentsv2/ExtrinsicIntents.sol)

### Summary
`_cancelFromSource` only requires the caller-supplied proof `options.height` to be **strictly greater than `order.deadline`** — it does not require the height to be the *latest* finalized destination height. Combined with the fact that the top-level `cancelOrder` guard (`if (_filled[commitment] != address(0)) revert Filled();`) is checked only against **local** per-chain storage, an order's own user can race the authoritative destination-side settlement (a solver's fill, or a destination-side cancel) against a source-side "proof of non-fill" that is deliberately captured at an earlier, now-stale height.

### Finding Description
The two cancellation routes are asymmetric in trust model:

- `_cancelFromDest` (`ExtrinsicIntents.sol:240-267`) is the *authoritative* path: it immediately writes `_filled[commitment] = order.user` on the destination chain and dispatches a `RefundEscrow` POST back to source.
- `_cancelFromSource` (`ExtrinsicIntents.sol:188-223`) is a *derived* path: it does not touch any local state, it only requires `options.height <= order.deadline` to revert, then dispatches a `DispatchGet` reading the destination's `_filled` slot **at that specific historical height**.
- `onGetResponse` (`ExtrinsicIntents.sol:319-324`) unconditionally calls `_withdraw(body, true, true)` if the returned storage value at `options.height` is empty — it performs no check against the *current* state of the order, nor any requirement that `options.height` be the most recent available consensus height.

Because `options.height` merely needs to be greater than `order.deadline` (any post-deadline block works, not necessarily the newest one Hyperbridge has finalized), a user can:
1. Capture a valid state proof for a height right after `order.deadline`, at a moment when the destination `_filled[commitment]` slot is still empty.
2. Independently let (or have a colluding/rushed solver) fill the order, or self-trigger `_cancelFromDest` after the deadline, on the destination chain — both dispatch a POST (`RedeemEscrow` or `RefundEscrow`) back to source that ultimately calls `_withdraw`.
3. Submit the stale proof from step 1 via `_cancelFromSource`/`onGetResponse`, which calls `_withdraw` a second time for the same commitment, since the top-level `_filled[commitment] != address(0)` guard in `cancelOrder` (`IntentGatewayV2.sol:470-490`, mirrored in `evm/tron/contracts/apps/IntentGatewayV2.sol:511`) is bypassed entirely — `onGetResponse` and `onAccept` invoke `_withdraw` directly, not through `cancelOrder`, so that guard never runs on the settlement path.

This is a "false state acceptance" bug: the contract treats an old, superseded proof of destination state as if it authoritatively reflects the order's *current* status, which is exactly the invariant the Hyperbridge pivots call out ("state proofs... must never let false remote state become trusted").

### Impact Explanation
If `_withdraw`'s internal accounting is not itself idempotent per-token (i.e., if it releases based on `order.inputs` amounts rather than re-checking a live, monotonically-updated `_orders[commitment][token]` balance that was already zeroed by the first settlement), this produces a duplicate release of the same escrowed input tokens — a direct loss of protocol/user funds and a double-settlement of a single order, matching the bounty's explicit "double-claim/double-settlement" and "loss of funds" categories.

### Likelihood Explanation
Reachable by any unprivileged order owner (`order.user`), using only the public `cancelOrder` entrypoint and normal ISMP GET request/response flow — no relayer collusion, no admin, no leaked keys. The only requirement is timing a proof capture to just after `order.deadline` and before a destination-side settlement lands, which the order owner fully controls by choosing to hold off on being present for the destination-side event.

### Recommendation
- Require `_cancelFromSource`'s proof height to reflect the *latest* known destination height (or bound it against `LatestStateMachineHeight` at claim time), not merely `> order.deadline`.
- Have `onGetResponse` re-check `_filled[commitment]` locally before calling `_withdraw`, and have `_withdraw` be strictly idempotent (zero the escrow ledger entry before transfer, and no-op or revert if already zero) so a second settlement attempt for the same commitment cannot move funds twice.
- Route `onGetResponse`/`onAccept`'s Redeem/RefundEscrow handling through the same `_filled` guard enforced in `cancelOrder`, rather than bypassing it.

### Proof of Concept
1. `user` places a cross-chain order via `IntentGatewayV2.placeOrder` with `deadline = D`.
2. At block `D+1` on the destination chain, before any fill, `user` (or their infra) fetches/records a Hyperbridge GET-proof of the empty `_filled[commitment]` storage slot at height `D+1`.
3. A solver later fills the order at height `D+5` on the destination (`_fillCrossChain`), which sets `_filled[commitment] = solver` and dispatches `RedeemEscrow` back to source — eventually calling `_withdraw` on source, releasing escrow to the solver.
4. Independently (or racing the delivery of step 3's message), `user` calls `cancelOrder` on the source chain with `options.height = D+1` (`_cancelFromSource`), which dispatches the GET request; Hyperbridge returns the recorded empty-slot proof from height `D+1` (still valid/verifiable since it's a real, finalized historical state); `onGetResponse` sees an empty value and calls `_withdraw(body, true, true)` a second time for the same `commitment`.
5. If step 4's `_withdraw` does not detect that the order's escrow was already released in step 3, `user` receives a duplicate refund of the same input tokens that were already paid out to the solver — a double-settlement / fund loss.

Note: I was not able to fully inspect the body of `_withdraw` (its exact ledger-zeroing/idempotency logic) within the available index, so whether this specific race achieves a literal double-transfer or is caught by `_withdraw`'s internal bookkeeping is not fully confirmed from the snippets retrieved. The structural issue — that `_cancelFromSource` accepts an arbitrary non-latest post-deadline proof height as authoritative "current" state, and that this settlement path bypasses `cancelOrder`'s `_filled` guard — is confirmed directly from `ExtrinsicIntents.sol` and `IntentGatewayV2.sol`. A Devin session with full repo access should inspect `IntentsBase.sol::_withdraw` (and its Tron/EVM mirrors) to confirm whether the ledger check is per-token-amount idempotent or whether it trusts the message body's `tokens` list unconditionally, which would confirm exploitability end-to-end.     function _cancelFromSource(Order calldata order, CancelOptions calldata options, bytes32 commitment) internal {
        if (order.user != bytes32(uint256(uint160(msg.sender)))) revert Unauthorized();

        if (options.height <= order.deadline) revert NotExpired();

        uint256 inputsLen = order.inputs.length;
        for (uint256 i; i < inputsLen;) {
            if (_orders[commitment][address(uint160(uint256(order.inputs[i].token)))] == 0) revert UnknownOrder();

            unchecked {
                ++i;
            }
        }

        bytes memory context =
            abi.encode(WithdrawalRequest({commitment: commitment, tokens: order.inputs, beneficiary: order.user}));

        bytes[] memory keys = new bytes[](1);
        keys[0] = bytes.concat(abi.encodePacked(_instance(order.destination)), _calculateCommitmentSlotHash(commitment));
        DispatchGet memory request = DispatchGet({
            dest: order.destination,
            keys: keys,
            timeout: 0,
            height: options.height,
            fee: options.relayerFee,
            context: context,
            payer: msg.sender
        });

        address hostAddr = host();
        if (msg.value > 0) {
            IDispatcher(hostAddr).dispatch{value: msg.value}(request);
        } else {
            dispatchWithFeeToken(request);
        }
    }

    function _cancelFromDest(Order calldata order, CancelOptions calldata options, bytes32 commitment) internal {
        if (order.deadline >= _blockNumber()) {
            if (order.user != bytes32(uint256(uint160(msg.sender)))) revert Unauthorized();
        }

        _filled[commitment] = address(uint160(uint256(order.user)));

        bytes memory body = bytes.concat(
            bytes1(uint8(RequestKind.RefundEscrow)),
            abi.encode(WithdrawalRequest({commitment: commitment, tokens: order.inputs, beneficiary: order.user}))
        );

        DispatchPost memory request = DispatchPost({
            dest: order.source,
            to: abi.encodePacked(_instance(order.source)),
            body: body,
            timeout: 0,
            fee: options.relayerFee,
            payer: msg.sender
        });

        address hostAddr = host();
        if (msg.value > 0) {
            IDispatcher(hostAddr).dispatch{value: msg.value}(request);
        } else {
            dispatchWithFeeToken(request);
        }
    }

    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost {
        RequestKind kind = RequestKind(uint8(incoming.request.body[0]));
        if (kind == RequestKind.RedeemEscrow || kind == RequestKind.RefundEscrow) {
            _authenticate(incoming.request);
            WithdrawalRequest memory body = abi.decode(incoming.request.body[1:], (WithdrawalRequest));
            return _withdraw(body, kind == RequestKind.RefundEscrow, true);
        }

        // only hyperbridge is permitted to perform these actions
        if (keccak256(incoming.request.source) != keccak256(IDispatcher(host()).hyperbridge())) revert Unauthorized();
        if (kind == RequestKind.NewDeployment) {
            _addDeployment(abi.decode(incoming.request.body[1:], (Deployment)));
        } else if (kind == RequestKind.UpdateParams) {
            _updateParams(abi.decode(incoming.request.body[1:], (ParamsUpdate)));
        } else if (kind == RequestKind.SweepDust) {
            _sweepDust(abi.decode(incoming.request.body[1:], (SweepDust)));
        } else if (kind == RequestKind.UpgradeContract) {
            (address newImpl, bytes memory initData) = abi.decode(incoming.request.body[1:], (address, bytes));
            ERC1967Utils.upgradeToAndCall(newImpl, initData);
        }

    /**
     * @dev Handles the response to a Hyperbridge GET request dispatched during
     * `_cancelFromSource`. Verifies that the `_filled` storage slot on the destination
     * chain is empty (meaning the order was never filled), then refunds the escrowed
     * tokens to the original user. Reverts with `Filled` if the slot is non-empty.
     *
     * @param incoming The incoming GET response from Hyperbridge containing the storage proof.
     */
    function onGetResponse(IncomingGetResponse calldata incoming) external override onlyHost {
        if (incoming.response.values[0].value.length != 0) revert Filled();

        WithdrawalRequest memory body = abi.decode(incoming.response.request.context, (WithdrawalRequest));
        _withdraw(body, true, true);
    }

    function cancelOrder(Order calldata order, CancelOptions calldata options) public payable nonReentrant {
        bytes32 commitment = keccak256(abi.encode(order));

        if (_filled[commitment] != address(0)) revert Filled();

        address hostAddr = host();
        bytes32 currentChain = keccak256(IDispatcher(hostAddr).host());
        bytes32 orderSource = keccak256(order.source);
        bytes32 orderDest = keccak256(order.destination);
        bool isSameChain = orderSource == orderDest;

        if (isSameChain) {
            _cancelSameChain(order, commitment);
        } else if (currentChain == orderSource) {
            _cancelFromSource(order, options, commitment);
        } else if (currentChain == orderDest) {
            _cancelFromDest(order, options, commitment);
        } else {
            revert WrongChain();
        }
    }
}
