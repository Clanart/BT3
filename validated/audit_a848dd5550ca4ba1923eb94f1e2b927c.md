### Title
Unvalidated `url` parameter from `x-github-client://openRepo` deep link flows unsanitized into clone operation - (File: app/src/lib/parse-app-url.ts)

### Summary
`parseAppURL` validates the `branch` and `pr` query parameters of an `openrepo` deep link with strict regexes, but performs no validation whatsoever on the `url` path segment (the actual remote to be cloned) before returning it as `IOpenRepositoryFromURLAction.url`. This mirrors the report's bug class: missing input validation on an externally-supplied "address"/identifier before it is trusted and threaded through privileged operations.

### Finding Description
In `parseAppURL`, for the `openrepo` action, `branch` is checked against `/^pr\/\d+$/` and passed through `testForInvalidChars`, and `pr` is checked against `/^\d+$/`, but `url` (`parsedPath`, taken directly from the untrusted deep-link path) is returned completely unchecked: [1](#0-0) 

This `url` is attacker-controlled: it originates from `open-url`/`--protocol-launcher` handling in the main process, which forwards any string following the app's custom protocol scheme straight to `parseAppURL`/`handleAppURL`: [2](#0-1) 

The resulting `url` is passed as `initialURL` into `CloneRepository`, which stores it verbatim in tab state and forwards it to git operations: [3](#0-2) [4](#0-3) 

The only sanitization applied anywhere in this path, `sanitizeCloneName`, is scoped to computing a safe *local directory name* for the clone destination — it strips path-traversal components from the derived repo name, but it does not sanitize or reject the actual remote `url` string that gets handed to `dispatcher.clone(url, path, ...)`: [5](#0-4) [6](#0-5) 

Because `url` is not required to match `parseRemote`'s protocol regexes (that parsing only affects `lastParsedIdentifier`/directory naming, and clone still proceeds with the raw `url` on failure to parse via `resolveCloneInfo`'s fallback `return { url }`), a value that doesn't look like a normal `https://`/`git@` URL — e.g. one beginning with a dash — is passed unmodified into the clone command: [7](#0-6) 

I was not able to retrieve `app/src/lib/git/clone.ts` in this session to confirm whether the underlying `git clone` argument array inserts a `--` separator before the URL argument (the standard mitigation for CLI argument/flag injection). If that separator is absent, a maliciously crafted deep link (e.g. `x-github-client://openRepo/--upload-pack=...`) could cause `git` to interpret the "URL" as an option rather than a repository location, since none of `parseAppURL`, `updateUrl`, or `resolveCloneInfo` reject option-like or otherwise malformed values before they reach the clone call.

### Impact Explanation
If the downstream git invocation lacks a `--` guard, an attacker can craft a link that, when clicked, causes GitHub Desktop to invoke `git clone` with attacker-controlled option flags (e.g. `--upload-pack`) instead of a URL, potentially achieving local command/process execution as the user who clicked the link — a "code execution via crafted link" primitive explicitly in scope for this task's Valid Impact criteria.

### Likelihood Explanation
The only requirement is that a user click a `x-github-client://openRepo/...` (or platform-equivalent) link; no local access, credentials, or malware is needed, and the `url` field is never checked against the `branch`/`pr` style allow-list validation applied elsewhere in the same function, making this a plausible oversight rather than an intentionally accepted design tradeoff.

### Recommendation
Validate `url` in `parseAppURL` the same way `branch` and `pr` are validated: require it to successfully parse via `parseRemote`/`parseRepositoryIdentifier` (or otherwise match an allow-list of URL forms), and reject/return `unknown` for any value that does not start with a recognized scheme (`https://`, `git@`, `ssh://`, `git://`) or that begins with a dash. Additionally, confirm and, if missing, add a `--` argument separator immediately before the URL argument in the underlying git clone subprocess call so a hostile string can never be interpreted as a flag.

### Proof of Concept
1. Publish/send a link such as `x-github-client://openRepo/--upload-pack=touch%20/tmp/pwned;`
2. User clicks the link; the OS routes it to GitHub Desktop's registered protocol handler, which calls `handleAppURL` → `parseAppURL`.
3. `parseAppURL` returns `{ name: 'open-repository-from-url', url: '--upload-pack=touch /tmp/pwned;', ... }` with no rejection, since only `branch`/`pr` are validated.
4. This flows into `CloneRepository`'s `initialURL` → `updateUrl` → `resolveCloneInfo` → `dispatcher.clone(url, path, ...)` unchanged.
5. If the underlying `git clone` argument array does not insert a `--` separator before the URL, git treats the string as an option, potentially executing attacker-supplied commands via `--upload-pack`. (This final step depends on the un-inspected `clone.ts` implementation and should be verified directly.)

  const args = parseCommandLineArgs(argv, {

  // Desktop registers it's protocol handler callback on Windows as
  // `[executable path] --protocol-launcher "%1"`. Note that extra command
  // line arguments might be added by Chromium
  // (https://electronjs.org/docs/api/app#event-second-instance).

  if (__WIN32__ && args['protocol-launcher'] === true) {
    // On Windows we'll end up getting called with something like
    // `--protocol-launcher --allow-file-access-from-files x-github-client://..`
    // which minimist naturally interprets as
    // `--allow-file-access-from-files=x:/github-client`. This is due to
    // Chromium's hot take on parsing command line arguments, see:
    // https://github.com/electron/electron/issues/20322#issuecomment-534137321
    // So while we could add '--allow-file...' as a boolean we can't know for
    // sure that Chromium won't add more switches later on which is why we have
    // to resort to looking through all arguments looking for something that
    // appears to be an app url.
    const prefixes = Array.from(possibleProtocols, p => `${p}://`)
    const matchingUrl = argv.find(arg => {
      if (prefixes.some(p => arg.startsWith(p))) {
        try {
          new URL(arg)
          return true
        } catch (e) {
          log.error(`Unable to parse argument as URL: ${arg}`)
        }
      }
      return false
    })

    if (matchingUrl) {
      handleAppURL(matchingUrl)
    } else {
      log.error(`Encountered --protocol-launcher without app url`)
    }
    // If --protocol-launcher is present we always want to bail and not
    // risk a smuggled cli switch
    return
  }

export function sanitizeCloneName(name: string): string | null {
  const components = name.split(/[/\\:]/)

  let lastComponent = ''
  for (let i = components.length - 1; i >= 0; i--) {
    if (components[i].length > 0) {
      lastComponent = components[i]
      break
    }
  }

  if (lastComponent.length === 0) {
    return null
  }

  if (lastComponent.endsWith('.git')) {
    lastComponent = lastComponent.slice(0, -4)
  }

  if (
    lastComponent === '..' ||
    lastComponent === '.' ||
    lastComponent.length === 0
  ) {
    return null
  }

  return lastComponent
}
