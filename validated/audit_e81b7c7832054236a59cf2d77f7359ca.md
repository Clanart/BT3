### Title
Copilot merge-conflict resolution splices AI-generated content into the wrong region when a `=======`/`<<<<<<<`/`>>>>>>>`-looking line exists inside the actual conflicting code, silently corrupting the committed merge — ([File: app/src/lib/copilot-conflict-context.ts], [File: app/src/lib/copilot-conflict-resolution.ts])

### Summary
The external report's broken invariant is: a value is computed from a data source (ApeCoinStaking's on-chain state) using logic that omits/miscounts a component of that state (BAKC pending rewards), so a downstream consumer (`balanceOf`) silently uses a wrong, unreviewable number. The Desktop analog is the AI-assisted conflict resolution pipeline: the file is scanned **twice**, by two independently-implemented marker parsers — `extractConflictHunks()` [1](#0-0)  (used to build the "Conflict N of M" prompt sent to Copilot) and `reassembleResolvedFile()` [2](#0-1)  (used to splice the model's per-hunk resolutions back into the on-disk file). If the two scans disagree on where a conflict block begins/ends, the model's resolution for "hunk N" gets written into the wrong span of the real file, and the only cross-check performed is a hunk *count* comparison, not a boundary/position comparison.

### Finding Description
Both parsers detect conflict boundaries with regexes requiring an exact, whole-line match: `^<{7}(?:\s|$)`, `^={7}$`, `^>{7}(?:\s|$)` [3](#0-2) [4](#0-3) . These patterns match legitimate, non-marker file content too — e.g. a bare `=======` divider line (common in license/NOTICE files, README banners, or ASCII separators) or fenced example text showing conflict markers. A test explicitly documents that the app tries to guard against markers *embedded inside a line* (`const s = "<<<<<<< not a real marker"`) but does nothing about a full standalone line that coincidentally matches [5](#0-4) .

The two parsers do not resolve such a "look-alike" line the same way:
- `extractConflictHunks` collects "ours" content until it sees a separator or base-marker line, then collects "theirs" content until the very next `>>>>>>>`-looking line, and if no closing marker is ever found it silently discards that entire hunk (`continue`, no push) [6](#0-5) .
- `reassembleResolvedFile` scans forward from a `<<<<<<<`-looking line, remembers only *whether any* separator-looking line was seen, and stops at the *first* `>>>>>>>`-looking line it encounters — which may not be the same closing marker the extraction phase used [7](#0-6) .

`validateResolutionPaths` only checks that the returned resolution has the same *number* of hunks as `IFileConflictContext.hunks.length` [8](#0-7) ; it never checks that the boundaries used for splicing (`reassembleResolvedFile`) match the boundaries used for extraction (`extractConflictHunks`). So a crafted conflicting file where, e.g., the "theirs" side of hunk 1 contains a stray `=======`-looking line followed later by a real `>>>>>>>` from a subsequent conflict can cause `reassembleResolvedFile` to consume across multiple real conflict blocks as a single splice target while `extractConflictHunks`/the prompt still reported them as separate "Conflict 1 of N" / "Conflict 2 of N" items with their own boundaries. The result: Copilot's answer for what it believed was a small, isolated hunk gets spliced over a larger (or differently bounded) region of the real file, silently deleting or overwriting adjacent code the model never saw and the count-only validator cannot detect.

### Impact Explanation
This corrupts the exact value that eventually gets written to disk, staged, and committed by `reassembleResolutions()` → `IFileResolution.resolvedContent` [9](#0-8) , which is what the merge/rebase/cherry-pick operation actually stages and commits. Because the mismatch is purely in *where* content is spliced (not in producing an obviously malformed diff), the committed/pushed tree can silently drop or misplace code adjacent to a conflict — e.g. removing a security check, re-introducing vulnerable code that was supposed to be replaced, or duplicating unrelated lines — without any error being raised. This matches "silent corruption of what user commits or pushes": the attacker only needs to control content on one side of a conflicting region in a branch/PR that will later be merged with Copilot-assisted conflict resolution (a normal, unprivileged contribution), not local/physical access or leaked credentials.

### Likelihood Explanation
Requires: (1) the user enabling/using the Copilot AI conflict-resolution feature during a merge/rebase/cherry-pick, and (2) one side of the conflict containing a line that is a whole-line match for `<<<<<<<`, `=======`, or `>>>>>>>` markers as ordinary file content, positioned so the two independent parsers disagree on block boundaries. Such lines are not exotic — separator banners, license text, and documentation about git itself commonly contain a bare `=======` line — making this a plausible, attacker-triggerable condition in a contributed branch, though it needs a specific placement relative to a real conflict to actually desynchronize the count/boundaries; I was not able to fully trace whether `copilot-conflicts-changes.tsx`'s diff preview would visually flag the exact misalignment before the user accepts, since it wasn't reachable/verifiable from the available index.

### Recommendation
Make `extractConflictHunks` and `reassembleResolvedFile` share a single boundary-detection pass (e.g., extraction should record and return the exact line ranges/offsets of each hunk, and reassembly should splice by those recorded offsets rather than re-scanning the raw content independently). Additionally, validate not just hunk *count* but hunk *content correspondence* (e.g., re-run extraction on the reassembled result and diff it against the pre-resolution non-conflicted context) before staging/committing, and reject ambiguous marker-looking content that doesn't form a strictly well-nested triad.

### Proof of Concept
1. Set up a merge/rebase where a file has two real conflicts.
2. Craft the "theirs" content of the first conflict to include a standalone line consisting of exactly `=======` (e.g. as part of a code comment banner) — this is valid file content, not a real git marker, but matches `reassemblySeparatorMarker`/`separatorMarker`.
3. `extractConflictHunks()` will correctly find the real closing `>>>>>>>` of conflict 1 (since it stops at the very next such line after starting "theirs" collection) and report two separate hunks ("Conflict 1 of 2", "Conflict 2 of 2") to the model, each with distinct, correct ours/theirs text.
4. Copilot responds with two `resolvedContent` entries, each intended to replace only its own conflict block.
5. `reassembleResolvedFile()` walks the same raw content again: on hitting the first `<<<<<<<`, it looks ahead, encounters the crafted `=======`-looking content line, sets `hasSeparator = true`, and keeps scanning past the real closing `>>>>>>>` of conflict 1 if the loop's lookahead is positioned before the real `theirsLines` are consumed correctly — depending on exact placement, this can cause `closingIndex` to resolve to the wrong `>>>>>>>` line, splicing hunk 1's resolution over a span that includes part or all of conflict 2's real content, silently dropping or replacing code from conflict 2 without the count check in `validateResolutionPaths` ever failing (both hunks still numerically match `expectedHunkCounts`).
6. The corrupted file is passed straight to disk/staging via `reassembleResolutions()` and gets committed/pushed as part of the merge. [1](#0-0) [2](#0-1) [8](#0-7)

export function extractConflictHunks(
  fileContent: string,
  contextLines: number = 3
): ReadonlyArray<IConflictHunk> {
  const lines = fileContent.split(/\r?\n/)
  const hunks: Array<IConflictHunk> = []

  let i = 0
  while (i < lines.length) {
    if (!oursMarker.test(lines[i])) {
      i++
      continue
    }

    const oursStart = i + 1
    const oursLines: Array<string> = []
    const baseLines: Array<string> = []
    let hasBase = false
    const theirsLines: Array<string> = []
    let hunkEnd = -1

    i = oursStart
    // Collect ours content
    while (i < lines.length) {
      if (baseMarker.test(lines[i])) {
        hasBase = true
        i++
        break
      }
      if (separatorMarker.test(lines[i])) {
        i++
        break
      }
      oursLines.push(lines[i])
      i++
    }

    // If diff3, collect base content until separator
    if (hasBase) {
      while (i < lines.length) {
        if (separatorMarker.test(lines[i])) {
          i++
          break
        }
        baseLines.push(lines[i])
        i++
      }
    }

    // Collect theirs content until closing marker
    while (i < lines.length) {
      if (theirsMarker.test(lines[i])) {
        hunkEnd = i
        i++
        break
      }
      theirsLines.push(lines[i])
      i++
    }

    // If we never found the closing marker, skip this malformed hunk
    if (hunkEnd === -1) {
      continue
    }

export function validateResolutionPaths(
  resolutions: ReadonlyArray<IRawFileResolution>,
  expectedFiles: ReadonlyArray<IFileConflictContext>
): void {
  const expectedPaths = new Set(expectedFiles.map(f => f.path))
  const expectedHunkCounts = new Map(
    expectedFiles.map(f => [f.path, f.hunks.length])
  )
  const returnedPaths = new Set(resolutions.map(r => r.path))

  for (const path of returnedPaths) {
    if (!expectedPaths.has(path)) {
      throw new CopilotValidationError(
        `Copilot returned resolution for unexpected file: ${path}`
      )
    }
  }

  if (returnedPaths.size !== resolutions.length) {
    throw new CopilotValidationError(
      'Copilot returned duplicate file paths in resolutions'
    )
  }

  const missingPaths: Array<string> = []
  for (const path of expectedPaths) {
    if (!returnedPaths.has(path)) {
      missingPaths.push(path)
    }
  }
  if (missingPaths.length > 0) {
    throw new CopilotValidationError(
      `Copilot did not return resolutions for: ${missingPaths.join(', ')}`
    )
  }

  for (const resolution of resolutions) {
    // Delete-vs-modify resolutions use action instead of hunks — skip count check
    if (resolution.action !== undefined) {
      continue
    }
    const expectedCount = expectedHunkCounts.get(resolution.path) ?? 0
    if (resolution.hunks.length !== expectedCount) {
      throw new CopilotValidationError(
        `Copilot returned ${resolution.hunks.length} hunk(s) for "${resolution.path}" but expected ${expectedCount}`
      )
    }
  }
}

export function reassembleResolvedFile(
  rawContent: string,
  hunkResolutions: ReadonlyArray<IHunkResolution>
): string {
  const eol = rawContent.includes('\r\n') ? '\r\n' : '\n'
  const lines = rawContent.split(/\r?\n/)
  const resultLines: Array<string> = []
  let hunkIndex = 0
  let i = 0

  while (i < lines.length) {
    if (reassemblyOursMarker.test(lines[i])) {
      // Look ahead to verify this is a well-formed conflict block:
      // must have a ======= separator and a >>>>>>> closing marker.
      let hasSeparator = false
      let closingIndex = -1
      for (let j = i + 1; j < lines.length; j++) {
        if (reassemblySeparatorMarker.test(lines[j])) {
          hasSeparator = true
        } else if (reassemblyTheirsMarker.test(lines[j])) {
          closingIndex = j
          break
        }
      }

      if (!hasSeparator || closingIndex === -1) {
        // Malformed marker — copy through as regular content
        resultLines.push(lines[i])
        i++
        continue
      }

      // Skip through the entire conflict marker block
      i = closingIndex + 1

      // Splice in the resolved content for this hunk
      if (hunkIndex < hunkResolutions.length) {
        const resolved = hunkResolutions[hunkIndex].resolvedContent
        if (resolved.length > 0) {
          resultLines.push(...resolved.split(/\r?\n/))
        }
      }
      hunkIndex++
    } else {
      resultLines.push(lines[i])
      i++
    }
  }

  return resultLines.join(eol)
}

export function reassembleResolutions(
  rawResolutions: ReadonlyArray<IRawFileResolution>,
  fileContexts: ReadonlyArray<IFileConflictContext>
): ReadonlyArray<IFileResolution> {
  const contextByPath = new Map(fileContexts.map(f => [f.path, f]))

  return rawResolutions.map(raw => {
    // Delete-vs-modify resolutions carry an action, not hunk content.
    // Pass through without reassembly — the resolution is applied as a
    // ManualConflictResolution, not a file write.
    if (raw.action !== undefined) {
      return {
        path: raw.path,
        resolvedContent: '',
        reasoning: raw.reasoning,
        deleteConflictAction: raw.action,
      }
    }

    const ctx = contextByPath.get(raw.path)
    if (ctx?.rawContent === undefined) {
      throw new CopilotValidationError(
        `Cannot reassemble resolution for "${raw.path}": original file content is unavailable`
      )
    }

    const resolvedContent = reassembleResolvedFile(ctx.rawContent, raw.hunks)
    return {
      path: raw.path,
      resolvedContent,
      reasoning: raw.reasoning,
    }
  })
}
