### Title
Governance-controlled pointer-registration disablement is not enforced on the reverse (EVM→CW) pointer precompile, allowing bypass of `RegisterPointerDisabled` - ([File: precompiles/pointer/pointer.go])

### Summary
The `RegisterPointerDisabled` param is meant to globally disable creation of new pointer contracts on Sei. It is enforced only in the Cosmos `MsgRegisterPointer` handler (CW→ERC direction) but is never checked in the EVM `pointer` precompile's `AddNativePointer`/`AddCW20Pointer`/`AddCW721Pointer`/`AddCW1155Pointer` methods (EVM→CW direction), allowing an unprivileged EVM caller to create pointer contracts even when the chain has disabled that capability — mirroring the Mattermost bug class where a permission control checked in one conversion direction was not enforced for the reverse direction.

### Finding Description
`x/evm/keeper/msg_server.go`'s `RegisterPointer` handler explicitly gates pointer creation behind the governance/param flag: [1](#0-0) 

This flag was deliberately turned on chain-wide via a migration, indicating operators intended to fully halt new pointer creation: [2](#0-1) 

However, the `pointer` precompile at address `0x000000000000000000000000000000000000100b`, which lets any EVM caller register the *reverse*-direction pointers (native token → ERC20, CW20 → ERC20, CW721 → ERC721, CW1155 → ERC1155), never reads or checks `RegisterPointerDisabled`: [3](#0-2) [4](#0-3) [5](#0-4) 

A search of the entire `precompiles/` tree confirms no reference to `RegisterPointerDisabled`/`GetRegisterPointerDisabled` exists outside the `x/evm` keeper/msg_server path, so the precompile path is completely unguarded by the param. Any EVM transaction sender can call `addNativePointer`, `addCW20Pointer`, `addCW721Pointer`, or `addCW1155Pointer` and successfully create a new pointer contract via `UpsertERCNativePointer`/`UpsertERCCW20Pointer`/`UpsertERCCW721Pointer`/`UpsertERCCW1155Pointer` on the keeper, regardless of the `RegisterPointerDisabled` setting.

### Impact Explanation
Once `RegisterPointerDisabled=true` is set (as it is by default post-migration), operators/governance expect that no new CW↔EVM pointer contracts can be minted through any path — this restriction was presumably put in place to prevent a class of issue with pointer creation (e.g., pointer-to-pointer abuse, mismatched pointer versions, or exploitation of the pointer-creation flow for unauthorized token bridging). Because the EVM-side precompile ignores the flag, an attacker can still mint new pointer contracts for arbitrary native denoms or CW20/CW721/CW1155 contracts. This can be used to establish unauthorized ERC representations of tokenfactory/native denoms or CW20/721/1155 assets that bypass the intended freeze, potentially enabling unauthorized token transfer/mint pathways through freshly created pointer contracts, or reintroducing state inconsistency the disablement was meant to prevent (e.g., duplicate/rogue pointer creation that the CW→ERC path is blocked from creating but the EVM→CW path is not).

### Likelihood Explanation
The precompile is a public, permissionless EVM entry point reachable by any transaction sender with no special privileges — just a normal EVM call to `0x...100b`. No governance, admin, or special permission check exists at all in this code path, so exploitation only requires knowledge that `RegisterPointerDisabled` is set and calling the alternate precompile method instead of the Cosmos message. This is trivially reachable and requires no race condition or validator collusion.

### Recommendation
Add a `RegisterPointerDisabled` (or an equivalent dedicated param/check) gate at the top of `pointer.Execute` in `precompiles/pointer/pointer.go`, mirroring the check in `x/evm/keeper/msg_server.go`'s `RegisterPointer`, so that `AddNative`, `AddCW20`, `AddCW721`, and `AddCW1155` all fail with the same "registering ... pointers has been disabled" error whenever the param is set, ensuring consistent enforcement across both pointer-creation directions.

### Proof of Concept
1. Governance/operator sets `RegisterPointerDisabled = true` (already the default post-migration per `x/evm/migrations/disable_register_pointer.go`).
2. Attempt `seid tx evm register-pointer ...` (CW→ERC) — confirmed to fail with `"registering CW->ERC pointers has been disabled"` per `x/evm/keeper/msg_server.go` lines 249-251.
3. From any EVM account, call the `pointer` precompile at `0x000000000000000000000000000000000000100b` with `addCW20Pointer(cwAddress)` (or `addNativePointer`/`addCW721Pointer`/`addCW1155Pointer`).
4. The call succeeds and a new ERC20/native/721/1155 pointer contract is created via `p.evmKeeper.UpsertERCCW20Pointer` (`precompiles/pointer/pointer.go` lines 134-164), despite `RegisterPointerDisabled=true`, demonstrating the bypass of the intended chain-wide restriction.

func (p PrecompileExecutor) AddNative(ctx sdk.Context, method *ethabi.Method, caller common.Address, args []interface{}, value *big.Int, evm *vm.EVM, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	token := args[0].(string)
	metadata, metadataExists := p.bankKeeper.GetDenomMetaData(ctx, token)
	if !metadataExists {
		return nil, 0, fmt.Errorf("denom %s does not have metadata stored and thus can only have its pointer set through gov proposal", token)
	}
	name := metadata.Name
	symbol := metadata.Symbol
	var decimals uint8
	for _, denomUnit := range metadata.DenomUnits {
		if denomUnit.Exponent > uint32(decimals) && denomUnit.Exponent <= math.MaxUint8 {
			decimals = uint8(denomUnit.Exponent)
			name = denomUnit.Denom
			symbol = denomUnit.Denom
			if len(denomUnit.Aliases) > 0 {
				name = denomUnit.Aliases[0]
			}
		}
	}
	contractAddr, err := p.evmKeeper.UpsertERCNativePointer(ctx, evm, token, utils.ERCMetadata{Name: name, Symbol: symbol, Decimals: decimals})
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(contractAddr)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}

func (p PrecompileExecutor) AddCW20(ctx sdk.Context, method *ethabi.Method, caller common.Address, args []interface{}, value *big.Int, evm *vm.EVM, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	cwAddr := args[0].(string)
	cwAddress, err := sdk.AccAddressFromBech32(cwAddr)
	if err != nil {
		return nil, 0, err
	}
	res, err := p.wasmdKeeper.QuerySmartSafe(ctx, cwAddress, []byte("{\"token_info\":{}}"))
	if err != nil {
		return nil, 0, err
	}
	formattedRes := map[string]interface{}{}
	if err := json.Unmarshal(res, &formattedRes); err != nil {
		return nil, 0, err
	}
	name := formattedRes["name"].(string)
	symbol := formattedRes["symbol"].(string)
	contractAddr, err := p.evmKeeper.UpsertERCCW20Pointer(ctx, evm, cwAddr, utils.ERCMetadata{Name: name, Symbol: symbol})
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(contractAddr)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}
