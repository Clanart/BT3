### Title
Unescaped `Any.type_url` field is embedded directly into TextFormat bracket syntax during printing, enabling text-format structure injection - (File: `src/google/protobuf/text_format.cc`)

### Summary
`TextFormat::Printer::PrintAny` writes the `google.protobuf.Any.type_url` string value verbatim between `[` and `]` delimiters without any escaping, unlike every other string field in TextFormat/ProtoJSON output which is properly escaped (quotes, backslashes, control characters). Because `type_url` is an ordinary attacker-controlled `string` field with no character restrictions enforced at binary/ProtoJSON parse time, a crafted `Any` message can inject TextFormat delimiter characters (`]`, `{`, `}`, newlines, `#`) into the printed output, corrupting the structure of the generated text and, if that text is later re-consumed by a TextFormat parser or log processor, causing content to be reinterpreted differently than intended by the producing application — the same "attacker string breaks out of its delimited field into an adjacent structural context" failure pattern as the Gin `Content-Disposition` filename issue.

### Finding Description
The failed invariant in the Gin CVE is: an attacker-controlled string embedded into a delimiter-based serialization format (the `Content-Disposition` header's `filename="..."` parameter) is not sanitized for the format's reserved characters (`"`, `;`), letting the attacker terminate the intended field early and inject additional directives.

The Protobuf analog: `google.protobuf.Any.type_url` is an ordinary `string` field with **no restrictions on its byte content beyond UTF‑8 validity** — arbitrary structurally-valid UTF‑8, including `]`, `{`, `}`, `\n`, `#`, and quote characters, is accepted when parsing binary protobuf or ProtoJSON into an `Any` message through the standard public parse API (`ParseFromString`/`ParseFromCord`, `JsonStringToMessage`, etc.). This matches the "attacker is an ordinary client sending bounded binary Protobuf or ProtoJSON" threat model: the consuming application later calls `TextFormat::PrintToString`/`Print` (a supported public API, e.g. for logging or debugging) on a message tree containing this attacker-supplied `Any`.

When `TextFormat::Printer::PrintAny` renders the `Any`, it does:
```
generator->PrintLiteral("[");
generator->PrintString(type_url);   // no CEscape / quoting applied
generator->PrintLiteral("]");
``` [2](#0-1) 

This is a direct contrast with every other string-valued field in the same file, which is escaped through `CEscape`/`HardenedPrintString`/`ContainsCharactersToCEscape` before being wrapped in quotes [3](#0-2) [4](#0-3) . The `[...]` construct used for `Any` is a **structural delimiter**, analogous to the `filename="..."` parameter delimiter in `Content-Disposition`, yet unlike the quoted-string case it receives no escaping at all.

The only check performed before entering this print path is `internal::ParseAnyTypeUrl`, which merely requires the presence of a `/` character to split prefix from type name — it performs **no validation of allowed characters** [1](#0-0) . This is different from the *parsing* side (`TextFormat::Parser::ConsumeAnyTypeUrlOrFullTypeName`), which does enforce a restrictive URL-character grammar and validates the type name as dot-separated identifiers when consuming `[type_url]` syntax from text input [5](#0-4) . In other words: TextFormat *parsing* of `Any` enforces character restrictions, but TextFormat *printing* of `Any` (populated from binary/JSON input, which has no such restriction) does not enforce or re-validate those restrictions before emitting the bracketed literal.

### Impact Explanation
If application code parses attacker-controlled binary Protobuf or ProtoJSON containing a `google.protobuf.Any` with a malicious `type_url` (e.g. containing `]`, newlines, or `{`/`}`), and later serializes the resulting message via `TextFormat::PrintToString`/`Print` for logging, debugging, audit trails, or any downstream system that treats TextFormat output as structured/re-parsable, the printed text no longer faithfully represents the original message. An attacker can inject bracket/brace/newline sequences that alter the apparent structure of the surrounding text (e.g., prematurely closing the `[...]` construct and injecting fabricated adjacent field-looking text, or breaking a single-line log record into multiple lines). This is a data-integrity/output-injection issue, not memory corruption — impact is bounded to confusion/misinterpretation of the generated text by whatever downstream tool consumes it (logs, config re-import, other TextFormat parsers), matching the "integrity: low" impact rating of the original CVSS vector (C:N/I:L/A:N).

### Likelihood Explanation
Likelihood is Medium-to-Low in practice: it requires (1) an application accepting untrusted binary/ProtoJSON input containing an `Any` field, (2) later feeding the resulting message through `TextFormat` printing, and (3) a downstream consumer of that text that treats it as structured or re-parses it. This is a plausible but not universal pattern (debug logging of arbitrary protobuf messages, config diffing/snapshotting tools, `DebugString()` used in structured logs). Requires user-triggered action per the CVSS `UI:R`-style reasoning transferred from the original advisory: the victim application must choose to print the attacker-influenced message via TextFormat rather than binary/JSON.

### Recommendation
Escape the `type_url` value in `TextFormat::Printer::PrintAny` the same way every other string field is escaped (`CEscape`/`ContainsCharactersToCEscape` or equivalent hardened escaping), and/or re-validate that `type_url` conforms to the restricted URL-character/identifier grammar already enforced on the parsing side (`ConsumeAnyTypeUrlOrFullTypeName`) before printing it unescaped inside `[...]`. If validation fails, fall back to printing `type_url`/`value` as ordinary escaped/quoted string fields instead of the special bracketed `Any` syntax.

bool ParseAnyTypeUrl(absl::string_view type_url,
                     std::string* PROTOBUF_NULLABLE url_prefix,
                     std::string* PROTOBUF_NONNULL full_type_name) {
  size_t pos = type_url.find_last_of('/');
  if (pos == std::string::npos || pos + 1 == type_url.size()) {
    return false;
  }
  if (url_prefix) {
    *url_prefix = std::string(type_url.substr(0, pos + 1));
  }
  *full_type_name = std::string(type_url.substr(pos + 1));
  return true;
}

void TextFormat::Printer::HardenedPrintString(
    absl::string_view src, TextFormat::BaseTextGenerator* generator) {
  // Print as UTF-8, while guarding against any invalid UTF-8 in the string
  // field.
  //
  // If in the future we have a guaranteed invariant that invalid UTF-8 will
  // never be present, we could avoid the UTF-8 check here.

  generator->PrintLiteral("\"");
  while (!src.empty()) {
    size_t n = SkipPassthroughBytes(src);
    if (n != 0) {
      generator->PrintString(src.substr(0, n));
      src.remove_prefix(n);
      if (src.empty()) break;
    }

    // If repeated calls to CEscape() and PrintString() are expensive, we could
    // consider batching them, at the cost of some complexity.
    generator->PrintString(absl::CEscape(src.substr(0, 1)));
    src.remove_prefix(1);
  }
  generator->PrintLiteral("\"");
}

bool ContainsCharactersToCEscape(absl::string_view val) {
  bool needs_escape = false;
  for (unsigned char c : val) {
    needs_escape |=
        ((c < 32) | (c > 126) | (c == '"') | (c == '\'') | (c == '\\'));
  }
  return needs_escape;
}

}  // namespace

void TextFormat::FastFieldValuePrinter::PrintString(
    const std::string& val, BaseTextGenerator* generator) const {
  generator->PrintLiteral("\"");
  if (!val.empty()) {
    if (ABSL_PREDICT_FALSE(ContainsCharactersToCEscape(val))) {
      generator->PrintString(absl::CEscape(val));
    } else {
      generator->PrintString(val);
    }
  }
  generator->PrintLiteral("\"");
}
