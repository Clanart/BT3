## Title
Compute-budget instruction validity is checked only during banking-stage buffering, not during sigverify/sanitization — allowing costly signature verification of transactions guaranteed to be rejected - (File: `compute-budget-instruction/src/instructions_processor.rs`, `runtime/src/bank/check_transactions.rs`)

### Summary
The external report's broken invariant is: a value/message is accepted at an early, cheap-to-process stage (Layer 1) without validating constraints that a later, more authoritative stage (Layer 2) will use to reject it — so resources are wasted on data that is provably going to be rejected, and there is "no mechanism" at the earlier stage to reject it up front. The Agave analog is compute-budget instruction validation: the code that decodes and sanitizes `ComputeBudgetInstruction`s explicitly documents that this validation *could* be folded into transaction sanitizing to "fail early," but in the current pipeline it is *not* done at sanitization/sigverify time — it is only performed later, in `receive_and_buffer_packets` / `check_age_and_compute_budget_limits`, after the expensive ed25519 signature verification and account-lock/dedup work has already been spent.

### Finding Description
`process_compute_budget_instructions` in `compute-budget-instruction/src/instructions_processor.rs` carries an explicit comment acknowledging the gap: [1](#0-0) 

This function (via `ComputeBudgetInstructionDetails::try_from` and `sanitize_and_convert_to_compute_budget_limits`) is the only place that rejects malformed compute-budget instructions, such as duplicate `SetComputeUnitLimit`/`SetComputeUnitPrice` instructions, invalid heap sizes not aligned to 1024 bytes, or a zero `loaded_accounts_data_size_limit`: [2](#0-1) [3](#0-2) 

However, transaction sanitization at the TPU ingestion / sigverify boundary — `Bank::verify_transaction_with_serialized_message` — only performs size checks, an instruction-count check (SIMD-0160), and full ed25519 signature verification (`tx.verify_and_hash_message()`); it never calls `process_compute_budget_instructions`: [4](#0-3) 

The ed25519 verification itself happens even earlier, in the per-packet `sigverify` worker pool, which only checks signature validity and simple-vote classification — again with no compute-budget-instruction validation: [5](#0-4) [6](#0-5) 

The compute-budget instructions are only decoded and validated much later, in banking-stage buffering (`num_dropped_on_compute_budget` counter exists specifically for this) and in `Bank::check_age_and_compute_budget_limits`, which is invoked only *after* lock validation for a batch of already sig-verified transactions: [7](#0-6) [8](#0-7) 

This mirrors the report's pattern precisely: a value (`compute_unit_limit`/`heap_size`/`loaded_accounts_data_size_limit`, encoded as sub-fields of the compute-budget program's instruction data, analogous to the bridge's "networkId encoded in the amount") is only range/duplicate-checked at a downstream stage (banking-stage buffering / bank-level check), while the upstream stage (packet reception + full ed25519 sigverify + dedup) accepts and fully processes the transaction with no early-rejection mechanism for this specific defect class, exactly as the report describes "no mechanism rejects incorrect trades" before the costlier stage is reached.

### Impact Explanation
An unprivileged, unstaked sender can construct transactions with valid signatures but syntactically invalid compute-budget instructions (e.g., two `SetComputeUnitLimit` instructions, or a `RequestHeapFrame` value not a multiple of 1024) that are guaranteed to be rejected. Each such transaction still forces a full, CPU-bound ed25519 signature verification pass and packet-level deduplication/prioritization work in the sigverify stage before ever reaching the point where the compute-budget instructions are decoded and rejected in banking-stage buffering. This is a non-RPC, low-privilege remote resource-exhaustion vector against the TPU/sigverify pipeline: signature verification is one of the most CPU-expensive per-packet operations a validator performs, and there is no requirement of malicious peer/validator collusion — a single ordinary client can generate large volumes of well-formed-but-doomed transactions cheaply (no fee needs to be paid since they never reach execution) to consume disproportionate sigverify CPU relative to legitimately processable transactions.

### Likelihood Explanation
Likelihood is moderate: the attack requires no special access, no leaked keys, and no cooperation from other nodes — any client with network access to a validator's TPU port can send such packets. The main mitigating factors are existing sigverify-stage deduplication and rate limiting (dedupers, priority floors), which reduce but do not eliminate the CPU cost of verifying signatures on each unique doomed transaction, since dedup operates on already-received packets and does not know in advance that the payload's compute-budget instructions are invalid.

### Recommendation
Move `process_compute_budget_instructions` (or an equivalent lightweight duplicate/range check) into the transaction sanitization path used before or alongside signature verification — e.g., inside `Bank::verify_transaction_with_serialized_message` in `runtime/src/bank.rs`, or as a pre-sigverify parsing step in `perf/src/sigverify.rs` / `core/src/sigverify_stage.rs` — so that packets with structurally invalid compute-budget instructions are discarded before the expensive ed25519 verification and downstream buffering/locking work is performed, consistent with the comment already present in `compute-budget-instruction/src/instructions_processor.rs` acknowledging that this check "may as well fail it early."

### Proof of Concept
Not independently executed; based on static code review only. A conceptual PoC:
1. Build a `VersionedTransaction` containing two `ComputeBudgetInstruction::SetComputeUnitLimit` instructions (duplicate), sign it validly with a funded or even unfunded keypair.
2. Submit repeated variants of this transaction (varying nonce/blockhash to bypass sigverify-stage dedup) via TPU.

        &self,
        feature_set: &FeatureSet,
    ) -> Result<ComputeBudgetLimits> {
        // Sanitize requested heap size
        let updated_heap_bytes =
            if let Some((index, requested_heap_size)) = self.requested_heap_size {
                if Self::sanitize_requested_heap_size(requested_heap_size) {
                    requested_heap_size
                } else {
                    return Err(TransactionError::InstructionError(
                        index,
                        InstructionError::InvalidInstructionData,
                    ));
                }
            } else {
                MIN_HEAP_FRAME_BYTES
            }

        // Calculate compute unit limit

            .requested_compute_unit_limit
            .map_or_else(
                || self.calculate_default_compute_unit_limit(feature_set),
                |(_index, requested_compute_unit_limit)| requested_compute_unit_limit,
            )
            .min(MAX_COMPUTE_UNIT_LIMIT);

            .requested_compute_unit_price
            .map_or(0, |(_index, requested_compute_unit_price)| {
                requested_compute_unit_price
            });

            if let Some((_index, requested_loaded_accounts_data_size_limit)) =

                NonZeroU32::new(requested_loaded_accounts_data_size_limit)

                MAX_LOADED_ACCOUNTS_DATA_SIZE_BYTES
            }

    fn process_instruction(&mut self, index: u8, instruction: &SVMInstruction) -> Result<()> {
        let invalid_instruction_data_error =
            TransactionError::InstructionError(index, InstructionError::InvalidInstructionData);
        let duplicate_instruction_error = TransactionError::DuplicateInstruction(index);

        match try_from_slice_unchecked(instruction.data) {
            Ok(ComputeBudgetInstruction::RequestHeapFrame(bytes)) => {
                if self.requested_heap_size.is_some() {
                    return Err(duplicate_instruction_error);
                }
                self.requested_heap_size = Some((index, bytes));
            }
            Ok(ComputeBudgetInstruction::SetComputeUnitLimit(compute_unit_limit)) => {
                if self.requested_compute_unit_limit.is_some() {
                    return Err(duplicate_instruction_error);
                }
                self.requested_compute_unit_limit = Some((index, compute_unit_limit));
            }
            Ok(ComputeBudgetInstruction::SetComputeUnitPrice(micro_lamports)) => {
                if self.requested_compute_unit_price.is_some() {
                    return Err(duplicate_instruction_error);
                }
                self.requested_compute_unit_price = Some((index, micro_lamports));
            }
            Ok(ComputeBudgetInstruction::SetLoadedAccountsDataSizeLimit(bytes)) => {
                if self.requested_loaded_accounts_data_size_limit.is_some() {
                    return Err(duplicate_instruction_error);
                }
                self.requested_loaded_accounts_data_size_limit = Some((index, bytes));
            }
            _ => return Err(invalid_instruction_data_error),
        }

        Ok(())
    }

    pub fn verify_transaction_with_serialized_message(
        &self,
        tx: VersionedTransaction,
        serialized_message: &[u8],
        verification_mode: TransactionVerificationMode,
    ) -> Result<RuntimeTransaction<SanitizedTransaction>> {
        // Discard v1 transactions until feature gate is activated.
        let enable_tx_v1 = self.feature_set.snapshot().enable_tx_v1;
        if !enable_tx_v1 && tx.version() == TransactionVersion::Number(1) {
            return Err(TransactionError::UnsupportedVersion);
        }
        let max_transaction_size = match tx.version() {
            TransactionVersion::Number(1) if enable_tx_v1 => {
                solana_message::v1::MAX_TRANSACTION_SIZE
            }
            _ => PACKET_DATA_SIZE,
        } as u64;

        // WARNING: Any pending features added here most likely must also be checked in
        //          `Bank::resanitize_transaction_minimally`.
        let sanitized_tx = {
            let size =
                wincode::serialized_size(&tx).map_err(|_| TransactionError::SanitizeFailure)?;
            if size > max_transaction_size {
                return Err(TransactionError::SanitizeFailure);
            }

            // SIMD-0160, check instruction limit before signature verification
            if tx.message.instructions().len()
                > solana_transaction_context::MAX_INSTRUCTION_TRACE_LENGTH
            {
                return Err(solana_transaction_error::TransactionError::SanitizeFailure);
            }

            let message_hash = if verification_mode == TransactionVerificationMode::FullVerification
            {
                tx.verify_and_hash_message()?
            } else {
                VersionedMessage::hash_raw_message(serialized_message)
            };

            RuntimeTransaction::try_create(
                tx,
                MessageHash::Precomputed(message_hash),
                None,
                self,
                self.get_reserved_account_keys(),
            )
        }?;

        Ok(sanitized_tx)
    }

/// Returns true if the signature on the packet verifies.
/// Caller must do packet.set_discard(true) if this returns false.
#[must_use]
fn verify_packet(packet: &mut PacketRefMut, reject_non_vote: bool, enable_tx_v1: bool) -> bool {
    // If this packet was already marked as discard, drop it
    if packet.meta().discard() {
        return false;
    }

    let Some(data) = packet.data(..) else {
        return false;
    };

    let (is_simple_vote_tx, verified) = {
        let Ok(view) = SanitizedTransactionView::try_new_sanitized(data, &sanitize_config()) else {
            return false;
        };

        if !enable_tx_v1 && matches!(view.version(), TransactionVersion::V1) {
            return false;
        }

        let is_simple_vote_tx = is_simple_vote_transaction_view(&view);
        if reject_non_vote && !is_simple_vote_tx {
            (is_simple_vote_tx, false)
        } else {
            let signatures = view.signatures();
            if signatures.is_empty() {
                (is_simple_vote_tx, false)
            } else {
                let message = view.message_data();
                let static_account_keys = view.static_account_keys();
                let verified = signatures
                    .iter()
                    .zip(static_account_keys.iter())
                    .all(|(signature, pubkey)| signature.verify(pubkey.as_ref(), message));
                (is_simple_vote_tx, verified)
            }
        }
    };

    if is_simple_vote_tx {
        packet.meta_mut().flags |= PacketFlags::SIMPLE_VOTE_TX;
    }

    verified
}

    fn check_age_and_compute_budget_limits<Tx: TransactionWithMeta>(
        &self,
        sanitized_txs: &[impl core::borrow::Borrow<Tx>],
        lock_results: impl IntoIterator<Item = TransactionResult<()>>,
        max_age: usize,
        strict_nonce_size_check: bool,
        error_counters: &mut TransactionErrorMetrics,
    ) -> Vec<TransactionCheckResult> {
        let hash_queue = self.blockhash_queue.read().unwrap();
        let next_durable_nonce = hash_queue.next_durable_nonce();

        let feature_set: &FeatureSet = &self.feature_set;
        let feature_snapshot = feature_set.snapshot();
        let fee_features = self.fee_features();

        let raise_cpi_limit = feature_snapshot.raise_cpi_nesting_limit_to_8;

        sanitized_txs
            .iter()
            .zip(lock_results)
            .map(|(tx, lock_res)| match lock_res {
                Ok(()) => {
                    let compute_budget_and_limits = tx
                        .borrow()
                        .transaction_configuration(feature_set)
                        .map(|config| {
                            let fee_details = calculate_fee_details(
                                tx.borrow(),
                                self.fee_structure.lamports_per_signature,
                                config.priority_fee_lamports,
                                fee_features,
                            );
                            if let Some(compute_budget) = self.compute_budget {
                                // This block of code is only necessary to retain legacy behavior of the code.
                                // It should be removed along with the change to favor transaction's compute budget limits
                                // over configured compute budget in Bank.
                                compute_budget.get_compute_budget_and_limits(
                                    config.loaded_accounts_data_size_limit,
                                    fee_details,
                                )
                            } else {
                                SVMTransactionExecutionAndFeeBudgetLimits {
                                    budget: SVMTransactionExecutionBudget {
                                        compute_unit_limit: u64::from(config.compute_unit_limit),
                                        heap_size: config.updated_heap_bytes,
                                        ..SVMTransactionExecutionBudget::new_with_defaults(
                                            raise_cpi_limit,
                                        )
                                    },
                                    loaded_accounts_data_size_limit: config
                                        .loaded_accounts_data_size_limit,
                                    fee_details,
                                }
                            }
                        })
                        .inspect_err(|_err| {
                            error_counters.invalid_compute_budget += 1;
                        })?;
