### Title
`CallDispatcher.dispatch()` has no caller authentication, letting anyone drain token/native residue left by predispatch/output-calldata execution across `IntentGatewayV2`, `HyperFungibleToken`, and `WrappedHyperFungibleToken` - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
This is the direct local analog of the `onTokenTransfer` finding: an execution entrypoint that moves value/executes arbitrary calls has zero validation of `msg.sender`, unlike the sibling ISMP callbacks in the same codebase which are correctly gated with `onlyHost`.

### Finding Description
`CallDispatcher.dispatch()` is a shared, singleton, fully public function with no access control whatsoever: [1](#0-0) 

Compare this with every other value-moving/execution entrypoint in the codebase, which is explicitly restricted via `onlyHost`: [2](#0-1) 

`CallDispatcher` is deployed once and shared across multiple, otherwise-unrelated apps: `HyperFungibleToken.onAccept`, `WrappedHyperFungibleToken.onAccept`, and `IntentsBase._execute` (used by `IntentGatewayV2`) all call `ICallDispatcher(dispatcher).dispatch(...)` to run solver/relayer-supplied calldata in the dispatcher's own execution context: [3](#0-2) [4](#0-3) 

In `IntentsBase._execute`, the flow is:
1. `dispatcher.dispatch(order.output.call)` runs solver-controlled calls (e.g., DEX swaps) in the `CallDispatcher`'s own address/context, which can leave ERC20/native balances sitting temporarily at the `CallDispatcher` address.
2. The code then sweeps back only the balances for tokens explicitly listed in `order.output.assets` (`outputsLen`), via a second `dispatcher.dispatch(finalCalls)` call.

Any token or native value that lands at the `CallDispatcher` address but is **not** one of the declared output assets (e.g., reward tokens, DEX cashback, dust, or a partially-executed sweep that reverted/only covered listed assets) is never recovered by step 2 and persists at the `CallDispatcher` address across transactions. Because `dispatch()` has no caller check (`msg.sender` is never validated, unlike `onAccept`/`onPostRequestTimeout` which enforce `onlyHost`), **any unrelated third party** can call `CallDispatcher.dispatch()` directly at any later block with a `Call[]` such as `{to: token, value: 0, data: transfer(attacker, balance)}` or `{to: attacker, value: address(this).balance, data: ""}` to pull out any residual balance sitting on the shared dispatcher — regardless of which app (IntentGatewayV2, HyperFungibleToken, WrappedHyperFungibleToken) originally caused it to be there.

### Impact Explanation
Any ERC20 or native token residue left at the `CallDispatcher` singleton — from a solver's swap output, a rounding/slippage remainder, or a partially-covered sweep in `IntentsBase._execute` — is permanently exposed to theft by any unprivileged address, since `dispatch()` performs no `onlyOwner`/`onlyApp`/allow-listed-caller check at all. This is a direct loss-of-funds primitive tied to the shared, permissionless custody contract used by the intent-settlement (`IntentGatewayV2`) and HFT bridging apps, matching the "stealing or loss of funds" / "unauthorized transaction or execution" impact classes in the bounty scope.

### Likelihood Explanation
Likelihood is dependent on residual balances actually accumulating at `CallDispatcher` (e.g., swap dust, reward tokens not declared as `order.output.assets`, or partial-fill scenarios where `outputsLen` sweep misses non-listed tokens). Given `_execute` explicitly implements a "sweep residual balances" step and documents this as an expected, recurring event (`DustCollected`), some residual balance is expected to occur in normal operation, and the entrypoint to steal it requires nothing more than a plain transaction call — no relayer, prover, or admin compromise needed.

### Recommendation
Add caller authentication to `CallDispatcher.dispatch()`, e.g., restrict callers to a registered allow-list of app contracts (`HyperFungibleToken`, `WrappedHyperFungibleToken`, `IntentGatewayV2` instances) set at deployment/configuration time, mirroring the `onlyHost` pattern already used for `onAccept`/`onPostRequestTimeout`. Alternatively, make `CallDispatcher` per-app (non-shared) so no cross-app residual balance can ever accumulate, or ensure `_execute`'s sweep step unconditionally sweeps the dispatcher's *entire* balance of every token touched by `order.output.call` (not only the declared `order.output.assets`) before returning.

### Proof of Concept
1. A solver fills an order via `IntentGatewayV2`/`IntentsBase._execute` with `order.output.call` routing through a DEX that, in addition to the declared output token, also pays out a secondary reward/bonus token (or leaves rounding dust in a token not listed in `order.output.assets`).
2. `_execute` only builds sweep calls for tokens in `order.output.assets` (`outputsLen`), so the secondary/reward token balance remains held at `CallDispatcher`'s address after the transaction completes: [5](#0-4) 
3. Any external, unprivileged address later calls `CallDispatcher.dispatch(abi.encode([Call({to: rewardToken, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, balance)})]))` directly — this succeeds because `dispatch()` performs no caller validation: [6](#0-5) 
4. The attacker receives the residual tokens that rightfully belonged to the protocol/user, with no relayer, prover, or governance compromise required.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {
            Call[] memory finalCalls = new Call[](sweepCount);
            for (uint256 i; i < sweepCount;) {
                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
    }
