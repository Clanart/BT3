### Title
Aggregate Schnorr signature verification permits universal forgery through an algebraically selected nonce - ([File: crypto/schnorr/src/aggregate.rs](crypto/schnorr/src/aggregate.rs))

### Summary
`SchnorrAggregate::verify` accepts a linear equation over attacker-controlled nonce commitments without binding those commitments, public keys, or the resulting aggregate relation into the aggregation weights. An attacker can therefore choose a nonce commitment that algebraically cancels the public-key terms and submit `s = 0`, causing verification to succeed without knowledge of any private key. [1](#0-0) 

### Finding Description
`SchnorrAggregate::read` accepts an arbitrary number of encoded `Rs` points followed by a scalar `s` from untrusted input. [2](#0-1) 

During verification, the transcript is initialized with the caller-provided domain separator, but only the caller-supplied challenges are appended to it. [3](#0-2) 

The verifier then derives each deterministic weight and evaluates:

```text
sum_i(weight_i * R_i + weight_i * challenge_i * public_key_i) - s * G == 0
```

This is implemented by pushing `(z, Rs[i])` and `(z * challenge, key)` into the multi-exponentiation, followed by `(-s, generator)`. [4](#0-3) 

Because `R_i` is attacker-controlled and is not bound by the weight transcript, the attacker can solve this equation after learning the challenges and their resulting weights. For a single signature, choosing `R = -challenge * public_key` and `s = 0` makes the complete expression zero for every nonzero aggregation weight. [5](#0-4) [6](#0-5) 

### Impact Explanation
An unprivileged attacker can produce a `SchnorrAggregate` encoding that verifies as an aggregate signature for public keys and challenges without knowing the associated private keys. This is a direct signature forgery: the accepted verification equation does not establish possession of a discrete logarithm. [2](#0-1) [4](#0-3) 

For multiple entries, the attacker can select arbitrary nonce points for all but one entry and solve the final nonce point so the entire weighted relation equals identity. This turns the aggregate verifier into an algebraic consistency check rather than proof of signatures. [1](#0-0) 

### Likelihood Explanation
The attack requires only public inputs: a public key, the challenge associated with the purported signature, and canonical group/scalar encodings. No secret, malformed point, non-canonical scalar, exceptional probability, or control over the verifier's RNG is required because the weights are deterministically derived from public data. [5](#0-4) [6](#0-5) 

Any caller that exposes `SchnorrAggregate::read` followed by `verify` to untrusted bytes is reachable by this issue. [2](#0-1) 

### Recommendation
Derive each aggregation weight from a transcript that binds the complete verification statement, including the domain separator, index/count, public key, nonce commitment `R_i`, and challenge for every aggregate member. Alternatively, generate nonzero weights with verifier-controlled randomness after all `Rs`, keys, and challenges have been fixed. The aggregate equation should remain:

```text
sum_i(w_i * (R_i + c_i * A_i)) == s * G
```

but `w_i` must not be predictable before the attacker commits to every `R_i`. [5](#0-4) [6](#0-5) 

### Proof of Concept
For one target public key `A` and expected nonzero challenge `c`, encode:

```text
R = -(c * A)
s = 0
```

as a one-element `SchnorrAggregate`. Verification computes:

```text
w * R + w * c * A - 0 * G
= w * (-c * A) + w * c * A
= 0
```

Thus `multiexp_vartime` returns identity and `verify` returns `true`, despite the attacker not knowing the private key for `A`. [2](#0-1) [4](#0-3) 

For `n` entries, select arbitrary `R_1..R_{n-1}`, set `s = 0`, and compute:

```text
R_n = -w_n^-1 * (sum_{i=1}^{n-1} w_i * (R_i + c_i * A_i) + w_n * c_n * A_n)
```

The serialized result satisfies the verifier's equation for all targeted public keys. [4](#0-3)
