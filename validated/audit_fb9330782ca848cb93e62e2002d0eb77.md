### Title
Encrypted DKG share messages are not bound to their intended recipient, allowing a malicious participant to frame an honest sender in blame arbitration - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
The Symfony advisory class — a credential valid under one firewall being accepted by all others — maps onto PedPoP's `EncryptedMessage` proof-of-possession: `pop_challenge` binds the context, nonce, ephemeral key, sender, and ciphertext, but never the *recipient*. A ciphertext produced by Alice for Bob therefore carries a PoP that verifies equally well when presented as Alice's share "for" any other participant. During blame arbitration (`BlameMachine::blame` / `AdditionalBlameMachine::blame`), this lets a malicious recipient substitute another party's copy of a sender's message and cause the honest sender to be declared faulty.

### Finding Description
`pop_challenge` transcripts `context`, `nonce`, `key`, `sender`, and `msg` — but no recipient field [1](#0-0) . `encrypt` signs this challenge over the recipient-specific ECDH ciphertext, so the PoP is identical regardless of who the message was intended for [2](#0-1) . In `decrypt_with_proof`, the accuser supplies `(sender, recipient, msg, proof)`; the DLEq proof is checked against `self.enc_keys[&decryptor]`, i.e., whichever recipient the accuser names [3](#0-2) . A malicious participant Eve who observes (or whose authenticated channel delivers) Alice's `EncryptedMessage` addressed to Bob can call blame arbitration with `sender = Alice`, `recipient = Eve`, that ciphertext, and a DLEq proof under Eve's own registered encryption key — which Eve can always produce since she knows her private key [4](#0-3) . The PoP verifies (it never encoded "Bob"), the DLEq verifies, decryption yields garbage, `from_repr` fails, and `blame_internal` returns `sender` — Alice, who behaved correctly, is blamed [5](#0-4) .

### Impact Explanation
Blame miscarriage: an honest DKG participant is marked faulty and the protocol aborts, while the actually-malicious accuser escapes attribution. In validator-set key generation this allows targeted exclusion of honest participants and repeated DKG aborts (liveness denial). The analogous "wrong-firewall acceptance" is exact: the PoP authenticates the message for *a* recipient, and arbitration accepts it for *any* recipient.

### Likelihood Explanation
Any DKG participant can attempt this; it requires only their own encryption key and a copy of a victim's round-2 message (which blame evaluation already assumes is available to arbitrators via `AdditionalBlameMachine` [6](#0-5) ). No collusion or key compromise needed. Impact is integrity/liveness of the DKG rather than key recovery, so Medium.

### Recommendation
Append the recipient `Participant` (or `enc_keys[recipient]`) to `pop_challenge` in `crypto/dkg/pedpop/src/encryption.rs`, and have `decrypt`/`decrypt_with_proof` include the claimed recipient when recomputing the challenge, so a ciphertext's PoP only verifies for its intended recipient.

### Proof of Concept
1. Alice runs `generate_secret_shares`, producing `EncryptedMessage`s `m_B` (for Bob) and `m_E` (for Eve), each PoP-signed with `from = Alice` and no recipient binding [7](#0-6) .
2. Eve obtains `m_B` (e.g., as a blame arbitrator or via the broadcast channel) and invokes `AdditionalBlameMachine::blame(sender = Alice, recipient = Eve, msg = m_B, proof = Some(p))`, where `p.key = m_B.key * enc_key_eve` and `p.dleq` proves `log_G(enc_pub_eve) == log_{m_B.key}(p.key)` — trivially constructible by Eve.
3. `m_B.pop` verifies under `pop_challenge(context, R, key, Alice, ciphertext)`; the DLEq verifies against `enc_keys[Eve]`; decryption produces non-canonical bytes; `blame_internal` returns `Alice` — an honest sender is convicted.

fn pop_challenge<C: Ciphersuite>(
  context: [u8; 32],
  nonce: C::G,
  key: C::G,
  sender: Participant,
  msg: &[u8],
) -> C::F {
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption Key Proof of Possession v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"proof_of_possession");

  transcript.append_message(b"nonce", nonce.to_bytes());
  transcript.append_message(b"key", key.to_bytes());
  // This is sufficient to prevent the attack this is meant to stop
  transcript.append_message(b"sender", sender.to_bytes());
  // This, as written above, doesn't hurt
  transcript.append_message(b"message", msg);
  // While this is a PoK and a PoP, it's called a PoP here since the important part is its owner
  // Elsewhere, where we use the term PoK, the important part is that it isn't some inverse, with
  // an unknown to anyone discrete log, breaking the system
  C::hash_to_F(b"DKG-encryption-proof_of_possession", &transcript.challenge(b"schnorr"))
}

  pub(crate) fn decrypt_with_proof<E: Encryptable>(
    &self,
    from: Participant,
    decryptor: Participant,
    mut msg: EncryptedMessage<C, E>,
    // There's no encryption key proof if the accusation is of an invalid signature
    proof: Option<EncryptionKeyProof<C>>,
  ) -> Result<Zeroizing<E>, DecryptionError> {
    if !msg.pop.verify(
      msg.key,
      pop_challenge::<C>(self.context, msg.pop.R, msg.key, from, msg.msg.deref().as_ref()),
    ) {
      Err(DecryptionError::InvalidSignature)?;
    }

    if let Some(proof) = proof {
      // Verify this is the decryption key for this message
      proof
        .dleq
        .verify(
          &mut encryption_key_transcript(self.context),
          &[C::generator(), msg.key],
          &[self.enc_keys[&decryptor], *proof.key],
        )
        .map_err(|_| DecryptionError::InvalidProof)?;

      cipher::<C>(self.context, &proof.key).apply_keystream(msg.msg.as_mut().as_mut());
      Ok(msg.msg)
    } else {
      Err(DecryptionError::InvalidProof)
    }
