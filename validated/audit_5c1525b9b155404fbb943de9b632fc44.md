### Title
Deterministic FROST preprocess is never consumed — repeated `share` calls reuse nonces, enabling private key share recovery - (File: coordinator/src/tributary/signing_protocol.rs)

### Summary
The RT-locking CVE releases RCU protection *before* the critical section ends; the analogous bug here is that `SigningProtocol::preprocess_internal` derives FROST nonces deterministically from a cached seed (`CachedPreprocess`) keyed only by `context`, and nothing marks that seed as consumed after `share_internal` produces a signature share. Any second call into `share_internal`/`share`/`complete` with the same context regenerates the identical nonce scalars `d, e` while the bound message or peer preprocess set may differ — classic FROST nonce reuse that reveals the MuSig private key share.

### Finding Description
`preprocess_internal` builds `CachedPreprocess(encrypted_seed)` stored under `CachedPreprocesses: (context) -> [u8; 32]` at `coordinator/src/tributary/signing_protocol.rs:123-145`. `seeded_preprocess` (`crypto/frost/src/sign.rs:121-144`) seeds `ChaCha20Rng` directly from `*seed.0`, so the nonces and commitments are a pure function of the seed. `share_internal` (`signing_protocol.rs:150-181`) calls `self.preprocess_internal(participants).0` — reconstructing the same `AlgorithmSignMachine` with the same nonces every time it runs for a given context.

In `DkgConfirmer` the context is `(b"DkgConfirmer", self.attempt)` (`signing_protocol.rs:274-277`). `share()` and `complete()` both go through `share_internal`; `complete` calls `share_internal(...)` a second time to rebuild the machine (`signing_protocol.rs:321-324`). Nothing deletes `CachedPreprocesses` or otherwise prevents a third, fourth, … invocation with different `preprocesses`/`key_pair` inputs but the same attempt. The `msg` passed to `machine.sign` incorporates an attacker-influenced `key_pair` (`signing_protocol.rs:296-301`), so two `share` calls for the same attempt over different `key_pair`s produce two shares `s1 = k + c1·λ·x`, `s2 = k + c2·λ·x` with identical nonce contribution `k` — solving `x = (s1 − s2) / ((c1 − c2)·λ)`.

### Impact Explanation
Recovery of the validator's MuSig/FROST private key share. Since `musig(...)` wraps the participant's key into `ThresholdKeys` (`signing_protocol.rs:118-121`), a recovered share compromises the validator's substrate signing key for the DKG confirmation/set-keys path — exactly the "key share recovery" outcome listed as a valid impact.

### Likelihood Explanation
Reachable by any party able to feed a `key_pair` / preprocess set into the confirmation flow (tributary transactions are consensus-delivered inputs, and `share`/`complete` are re-entrant DB-backed functions with no consumed-flag). Requires two `share` derivations under the same `attempt` context with differing `msg`; the code explicitly tolerates repeated invocations ("this is an error if we didn't reboot" pattern elsewhere implies reboot/retry re-entrancy is expected). No malicious-validator assumption needed — the triggering bytes (preprocess map, `KeyPair`) are externally supplied.

### Recommendation
Delete or invalidate `CachedPreprocesses` for the context at the moment `share_internal` consumes it (a DB tombstone), so any re-derivation fails loudly instead of silently reusing nonces. Alternatively, mix a per-consumption value (e.g., hash of `msg`/preprocess set) into the nonce derivation seed, or refactor so the consumed machine state is stored and reused rather than regenerated from the seed.

### Proof of Concept
For context `c = (b"DkgConfirmer", attempt)`:

1. Call `share(preprocesses_A, key_pair_1)` → emits share `s1`. Internally: `preprocess_internal` loads cached seed, `seeded_preprocess` regenerates `d, e`; `sign` computes `s1 = d + e·ρ1 + c1·λ·x`.
2. Call `share(preprocesses_A, key_pair_2)` (different `key_pair` → different `msg` → different challenge `c2`, same `d, e`, same `ρ`).
3. `s1 − s2 = (c1 − c2)·λ·x` → `x = (s1 − s2)·((c1 − c2)·λ)⁻¹`, recovering the secret share modulo the group order.

Code path: `signing_protocol.rs:274-301` (context fixed by attempt; `msg` varies with `key_pair`), `signing_protocol.rs:137-147` (deterministic nonce regeneration from unchanged cached seed), `crypto/frost/src/sign.rs:127-141` (`ChaCha20Rng::from_seed(*seed.0)` → identical `nonces`).
