### Title
Address-association precompile accepts a signature over any attacker-chosen message, allowing consent-less forced association - ([File: precompiles/addr/addr.go])

### Summary
The `associate` method of the `addr` precompile (`0x1004`) recovers a user's public key from a raw ECDSA `v/r/s` signature and an arbitrary `customMessage` supplied by the *caller*, without ever checking that `customMessage` is the canonical "Please sign this message to link your EVM and Sei addresses…" consent text. Because Keccak256(customMessage) is not pinned to any fixed, association-specific value, **any** ECDSA signature the victim has ever produced for an unrelated purpose (a `personal_sign` login challenge, an EIP-712 permit, a signed transaction, etc.) can be replayed by an attacker as the `v,r,s` input together with that other message as `customMessage` to force-associate the victim's EVM address with their pubkey-derived Sei address — an action the victim never consented to performing via this precompile.

### Finding Description
`PrecompileExecutor.associate` takes `v`, `r`, `s`, and `customMessage` directly from caller-controlled `args` with no restriction on `customMessage`'s content: [1](#0-0) 

It computes `customMessageHash := crypto.Keccak256Hash([]byte(customMessage))` and feeds it straight into `helpers.GetAddresses(vBig, rBig, sBig, customMessageHash)` to recover the EVM address, Sei address, and public key — this is exactly the same operation used by the legitimate "sign this to link your addresses" flow in the integration tests and Hardhat tests, but nothing in the precompile enforces that the signed content is that specific consent message: [2](#0-1) 

This is structurally analogous to CVE-2024-45159: a cryptographic proof (an mTLS client certificate / here, an ECDSA signature) that is valid and was produced for one purpose is silently accepted as authorization for a distinct, more consequential purpose (TLS client authentication / here, permanent on-chain address linking) because the code omits the check that would confirm the credential's scope matches its intended use.

The consequence of a forced association is not benign bookkeeping — the codebase's own comments confirm that force-associating an address migrates on-chain balances and can orphan staking/distribution state: [3](#0-2) [4](#0-3) 

and `AssociateAddresses`/`MigrateBalance` unconditionally sweeps all spendable coins and wei balance from the direct-cast address to the newly-associated Sei address as soon as association happens: [5](#0-4) 

The EIP-7702 SetCode authorization path was specifically hardened (`AuthorityToPreAssociate`) to prevent exactly this class of "replay a publicly visible signature to force-associate a victim," because doing so can move funds under the direct-cast address and, if that address happened to be a validator operator address, previously could destabilize distribution/staking hooks. The generic `addr.associate()` entry point has none of the equivalent protections (no chain-id/nonce/context binding, no fixed canonical message check) — it accepts literally any prior signature the victim ever produced online.

### Impact Explanation
An attacker who observes or is given any signature from a victim (e.g., from a wallet-connect login flow, a DEX permit signature, an off-chain message, or a copy of a raw transaction signature reused as v/r/s) can submit an `associate` transaction that force-migrates the victim's `usei`/wei balance sitting at their direct-cast address to the victim's true pubkey-derived address, without the victim's knowledge or consent, at a time of the attacker's choosing. This can also affect the reachability of the victim's cast address for future deposits and, per the codebase's own hardening rationale for the SetCode path, risks orphaning staking/distribution state tied to the cast identity. This satisfies "unauthorized transfer/permanent freezing" impact criteria via a fund-affecting state change performed without the address owner's intended consent.

### Likelihood Explanation
Reachable by any unprivileged EVM caller with zero special privileges: `associate` is a plain EVM precompile call at `0x1004`, callable by any contract or EOA, and the only prerequisite is possessing a `v,r,s` triple that recovers to the victim's pubkey for *some* message — such signatures are routinely produced and often publicly observable (e.g., emitted in dApp logs, gasless-relay payloads, or simply captured off-chain) since ECDSA signatures do not keep the signer's public key secret.

### Recommendation
Bind the `associate` and `associatePubKey` message hash to a fixed, precompile-specific, chain-bound domain (e.g., include chain ID, contract address, and a fixed literal prefix) and reject any `customMessage` that does not exactly match this canonical template, mirroring the checks (`ChainID`, `Authority()` cross-check, nonce/account-state checks) that were already added for `AuthorityToPreAssociate` in the EIP-7702 path.

### Proof of Concept
1. Victim signs an unrelated off-chain message `M` (e.g., a login challenge for some dApp) with their EVM key, producing `(v, r, s)`.
2. Attacker observes this signature (many dApps log or transmit it) and submits `addr.associate(v-27, r, s, M)` on Sei.
3. `helpers.GetAddresses` recovers the victim's pubkey/EVM/Sei address from `(v,r,s, keccak256(M))` exactly as it would for the legitimate consent message, since `M` is never checked against the canonical text: [6](#0-5) 
4. `associateAddresses` → `AssociateAddresses` runs, sweeping the victim's direct-cast balance to their derived Sei address without their consent: [5](#0-4)

func (p PrecompileExecutor) associate(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}

	// v, r and s are components of a signature over the customMessage sent.
	// We use the signature to construct the user's pubkey to obtain their addresses.
	v := args[0].(string)
	r := args[1].(string)
	s := args[2].(string)
	customMessage := args[3].(string)

	rBytes, err := decodeHexString(r)
	if err != nil {
		return nil, 0, err
	}
	sBytes, err := decodeHexString(s)
	if err != nil {
		return nil, 0, err
	}
	vBytes, err := decodeHexString(v)
	if err != nil {
		return nil, 0, err
	}

	vBig := new(big.Int).SetBytes(vBytes)
	rBig := new(big.Int).SetBytes(rBytes)
	sBig := new(big.Int).SetBytes(sBytes)

	// Derive addresses
	vBig = new(big.Int).Add(vBig, utils.Big27)

	customMessageHash := crypto.Keccak256Hash([]byte(customMessage))
	evmAddr, seiAddr, pubkey, err := helpers.GetAddresses(vBig, rBig, sBig, customMessageHash)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}
