### Title
`SignableTransaction` trusts the stated `TxOut` value in a deserialized `ReceivedOutput`, committing signatures to amounts never verified against the chain - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
The external report's bug class is "credit the stated amount rather than the amount actually received." In bitcoin-serai, `ReceivedOutput` couples an `outpoint` with a `TxOut` whose `value`/`script_pubkey` are whatever was serialized. `ReceivedOutput::read` accepts these fields verbatim from untrusted bytes, and `SignableTransaction::new` / `TransactionSignMachine::sign` then trust the stated `prevouts` for input-sum, fee, change, and — critically — the BIP-341 `Prevouts::All` sighash. `multisig()` verifies only that the prevout's `script_pubkey` matches the derived offset key; the `value` and even the `outpoint`→UTXO binding are never checked against chain data. A forged `ReceivedOutput` therefore makes the threshold group produce signatures committing to amounts that do not exist on-chain.

### Finding Description
`ReceivedOutput::read` decodes `offset`, `output: TxOut`, and `outpoint` straight from the reader with no validation that the `TxOut` matches the real UTXO at `outpoint` (`mod.rs:122-134`). `SignableTransaction::new` then computes `input_sat` purely from `input.output.value` (`send.rs:175`), uses it for the `NotEnoughFunds` check (`send.rs:215`), change computation (`send.rs:228-230`), and stores the claimed TxOuts as `prevouts` (`send.rs:253`). During signing, `taproot_key_spend_signature_hash(i, &Prevouts::All(&self.tx.prevouts), ...)` commits every prevout's stated `value` and `script_pubkey` into the signed message (`send.rs:373-390`). The only integrity check is in `multisig()`: `p2tr_script_buf(offset.group_key())? != self.prevouts[i].script_pubkey` (`send.rs:277`) — the amount is never constrained.

### Impact Explanation
An unprivileged party who can feed bytes to `ReceivedOutput::read` (explicitly an untrusted-input sink for this crate) can inflate `TxOut.value`. The multisig then signs a BIP-341 sighash committing to that inflated amount. Because the commitment is wrong relative to the real UTXO, the completed signature is invalid and the transaction can never be broadcast — yet each participant has produced a valid-looking share for a message misrepresenting the actual funds. Deflated or mismatched stated values similarly cause `fee()` (`send.rs:138-141`) and change math to report balances that diverge from reality: funds "received" per the stated ledger are not spendable at those amounts, and `NotEnoughFunds` can be bypassed to construct transactions whose stated inputs exceed real inputs.

### Likelihood Explanation
Reachable wherever serialized `ReceivedOutput`s cross a trust boundary (network messages, DB rows writable by a peer, or coordinator-supplied inputs). It requires no key material and no malicious validator — only control of the untrusted bytes. The impact is bounded to signing unintended/invalid messages and misreported balances rather than direct theft, matching Medium severity.

### Recommendation
Treat `ReceivedOutput` as a claim, not a fact: at minimum, re-fetch or verify the prevout `TxOut` (value + script_pubkey) for each `outpoint` before `SignableTransaction::new` or inside `multisig()`, analogous to "measure balance before/after" — i.e., bind the stated value to the chain-verified value. If the library is intended to be offline, document that `ReceivedOutput`s MUST originate from `Scanner::scan_transaction`/`scan_block` output (which copies real `TxOut`s) and reject externally supplied ones.

### Proof of Concept
```rust
// Attacker crafts bytes claiming an inflated value for a real outpoint
let mut forged = Vec::new();
forged.extend(real_received_output.offset().to_bytes());
let mut fake_txout = real_received_output.output().clone();
fake_txout.value = Amount::from_sat(real_received_output.value() * 100);
forged.extend(serialize(&fake_txout));
forged.extend(serialize(real_received_output.outpoint()));

let output = ReceivedOutput::read(&mut forged.as_slice()).unwrap();
// input_sat is now 100x the real value; NotEnoughFunds check is bypassed
let tx = SignableTransaction::new(vec![output], &payments, Some(change), None, FEE).unwrap();
// multisig() passes: it checks script_pubkey only, not the value
let machine = tx.clone().multisig(&keys).unwrap();
// Each participant signs a sighash committing to Prevouts::All with the forged
// amount — shares are produced for a message that does not match the real UTXO,
// and the final transaction's witnesses are invalid on-chain.
```
