## Title
Automatic Remote URL Rewrite Trusts Unvalidated GitHub API `clone_url`, Allowing Silent Redirection of Push/Fetch Targets - (File: app/src/lib/stores/updates/update-remote-url.ts)

## Summary
The reported bug's broken invariant is "a value that other trusted logic relies on for a security-sensitive action (fund transfer) can be silently overwritten by an untrusted party, with no confirmation and no validation of the new value." The Desktop analog is `updateRemoteUrl`, which silently overwrites a repository's `origin` remote URL — the destination for every future `git push`/`git fetch` — based on the `clone_url` field of a GitHub API repository object, with no user confirmation and no validation that the new host is the same host/owner as before.

## Finding Description
`updateRemoteUrl` [1](#0-0)  takes the `clone_url` returned by the GitHub API for the tracked `GitHubRepository` and, if a few heuristics pass, calls `gitStore.setRemoteURL` to rewrite the local `origin` remote: [2](#0-1) 

The only checks performed are:
- `protocolsMatch`: only compares the URL *scheme* (`https:` vs `https:`), never the hostname.
- `remoteUrlUnchanged`: only verifies that the user hasn't manually diverged the remote from the previously cached `clone_url`.

There is no check that the new `clone_url` points to the same host/owner/repo family as the old one, and no user-facing confirmation dialog before the remote is rewritten.

This function is invoked automatically from `repositoryWithRefreshedGitHubRepository`, which is called on essentially every fetch/pull/push cycle via `withRefreshedGitHubRepository`: [3](#0-2) [4](#0-3) 

The `apiRepo` object comes directly from `api.fetchRepository(owner, name)`, i.e., from whatever the configured GitHub.com/GHE endpoint returns for that repository — this is the "GitHub API object" the attacker can influence (a malicious/compromised GitHub Enterprise instance, a repo transfer/rename response, or a MITM'd/spoofed API response against a GHE endpoint without proper certificate validation).

## Impact Explanation
If the API-returned `clone_url` is attacker-controlled (same scheme, different host), Desktop will silently execute `git remote set-url origin <attacker-url>` with no prompt [5](#0-4) [6](#0-5) . Because the check is purely scheme-based rather than host/owner-based, an attacker who can make one crafted API response reach the user (compromised GHE admin/server, or MITM against a GHE endpoint with weak TLS trust) can redirect the user's `origin` to attacker infrastructure. Subsequent operations are corrupted silently:
- `git push` sends the user's code/credentials-bearing HTTPS URL traffic to the attacker's server.
- `git fetch`/`pull` pulls attacker-controlled refs into the user's local history without warning.

This matches "silent corruption of what the user commits or pushes" from an attacker-controlled GitHub API object.

## Likelihood Explanation
Likelihood is limited primarily to environments where the API endpoint or its response can be influenced — most plausible against self-hosted/GitHub Enterprise endpoints (compromised or MITM'd) or a scenario where the repository's owner/admin (who is inherently untrusted from the current user's perspective) changes what `clone_url` the API reports for a repository the user already has cloned. It does not require any user click beyond a normal fetch/pull/push, which happens continuously and automatically in Desktop.

## Recommendation
- Require that the new `clone_url` share the same hostname/owner as the previously known one (or otherwise cryptographically/administratively verify the API endpoint), not just the same protocol scheme.
- Prompt the user for explicit confirmation before silently rewriting `origin`'s URL, especially when the host changes.
- Log/telemetry an event whenever an automatic remote URL rewrite occurs so users/admins can detect unexpected redirections.

## Proof of Concept
1. User has a repository cloned from `https://ghe.example.com/org/repo` associated with a tracked `GitHubRepository` record in Desktop.
2. Attacker compromises/controls the GHE server (or the account owning the repository) and causes `GET repos/org/repo` to return `clone_url: "https://attacker-controlled.example/org/repo.git"` (same `https:` scheme).
3. User performs any fetch/pull/push in Desktop, which triggers `withRefreshedGitHubRepository` → `repositoryWithRefreshedGitHubRepository` → `updateRemoteUrl` [7](#0-6) .
4. Since `protocolsMatch` is true and `remoteUrlUnchanged` is true (user hasn't manually diverged origin), Desktop silently runs `git remote set-url origin https://attacker-controlled.example/org/repo.git` with no prompt.
5. The next `git push` from Desktop sends the user's commits to the attacker's server instead of the legitimate one.

Note: I was unable to verify from the indexed code whether any additional TLS-pinning or endpoint-trust checks exist elsewhere in the API client that would prevent a spoofed/compromised GHE response from reaching `fetchRepository` — this would need to be confirmed in a full checkout, since the index may not include every file (e.g., certificate-pinning logic under `app/src/lib/http` or similar, if present, was not located by search).

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
