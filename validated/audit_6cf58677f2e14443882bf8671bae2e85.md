### Title
Malicious Git server can spoof `WWW-Authenticate: realm="GitHub"` to trigger a GitHub/Enterprise sign-in prompt and bind an OAuth account to an attacker-chosen endpoint - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The credential-helper trampoline determines whether a Git remote is a "GitHub-like" host (`github.com`, GHE, or generic) via `getEndpointKind()`. As a "happy path" optimization, it trusts the `WWW-Authenticate` header captured by Git from the remote server's actual HTTP response, short-circuiting the legitimate network-based `isGitHubHost()` check. Because this header is fully attacker-controlled server output, any HTTP(S) Git remote can impersonate a GitHub Enterprise host, causing GitHub Desktop to display a native GitHub sign-in prompt and bind the resulting OAuth account to the attacker's endpoint.

### Finding Description
`getEndpointKind()` classifies each credential-helper request as `'generic'`, `'github.com'`, `'ghe.com'`, or `'enterprise'`. Before it does any real verification, it inspects the credential entries forwarded from Git for a `wwwauth[...]` field and, if the value contains `realm="GitHub"`, unconditionally returns `'enterprise'`: [1](#0-0) 

The comment itself acknowledges the header is attacker/server-supplied: "When Git attempts to authenticate with a host it captures any WWW-Authenticate headers and forwards them to the credential helper. We use them as a happy-path to determine if the host is a GitHub host **without having to resort to making a request ourselves**." Only when no matching header is present does the code fall back to the legitimate check, `isGitHubHost(endpoint)`, which presumably makes a real verification request: [2](#0-1) 

This header originates from an HTTP 401 response sent by the actual Git remote (`WWW-Authenticate: Basic realm="GitHub"`), which is exactly the "attacker controls... a git remote/proxy response" primitive. Any malicious or compromised HTTPS Git server the user clones/fetches from can send this header for a plain, non-GitHub URL.

Once `getEndpointKind` is fooled into returning `'enterprise'` for an arbitrary host, `getCredential()` treats it as a first-party GitHub host: [3](#0-2) 

If no existing account matches that endpoint, it calls `ui.promptForGitHubSignIn(endpoint)`, using the attacker-controlled origin directly: [4](#0-3) 

This begins an Enterprise sign-in flow (`dispatcher.beginEnterpriseSignIn` + `dispatcher.setSignInEndpoint(origin)`), which is subsequently completed via `SignInStore.authenticateWithBrowser()`, opening an OAuth authorization URL built from that attacker-supplied endpoint: [5](#0-4) 

If the user completes the flow (believing they are simply signing into "GitHub Enterprise" as prompted by their own trusted app), the resulting `Account` is persisted with `endpoint` equal to the attacker-chosen origin via `AccountsStore.addAccount`: [6](#0-5) 

From that point forward, `findGitHubTrampolineAccount` will match that endpoint's origin for any future Git operation against the same host and automatically inject the user's GitHub/GHE credentials/token into requests to it: [7](#0-6) 

The broken invariant is analogous to the TCR-15 pattern: one enforcement path (the real `isGitHubHost` network check, or the "generic" credential path with its own manual auth prompt) is bypassed by a second path (the header-based heuristic) that skips the verification a security-relevant decision depends on — exactly like `transfer()` enforcing a withdraw while `transferFrom()` does not.

### Impact Explanation
An attacker who controls (or has compromised, or is in a position to serve via a malicious proxy) an HTTPS Git remote endpoint can:
1. Trick GitHub Desktop into presenting a legitimate-looking native "Sign in to GitHub Enterprise" dialog for a host that is not GitHub at all.
2. Cause a user's OAuth account to become bound (`AccountsStore.addAccount`) to that attacker-controlled endpoint.
3. Have Desktop automatically inject that account's credentials into any future request to the attacker's origin (via `findGitHubTrampolineAccount`), since the account's endpoint now matches.

This is an unauthorized OAuth/account-binding condition triggered purely by a crafted server response to a cloned/fetched remote, without any local access, admin rights, or prior compromise of the host.

### Likelihood Explanation
Exploitation only requires the victim to add and fetch/clone from an attacker-controlled or malicious/compromised HTTP(S) remote (a common workflow for any Desktop user adding a new remote or forking a repo), and for the server to include a single 401 response header. It does not require special user error beyond normal sign-in dialog interaction, which the app itself initiates and visually presents as trustworthy. This is a fairly low-friction, server-side-only requirement.

### Recommendation
Do not treat the `WWW-Authenticate` header value as authoritative for determining `'enterprise'`/`'github.com'` classification. It should, at most, be used as a hint to prioritize which verification method to attempt, but the actual classification must always be confirmed via the legitimate `isGitHubHost()` (or equivalent authenticated) check before routing a host into GitHub/GHE-specific credential handling and, particularly, before initiating any OAuth sign-in flow or persisting an `Account` bound to that endpoint.

### Proof of Concept
1. Attacker stands up an HTTPS Git server at `https://evil.example.com/repo.git` that, on an unauthenticated request, returns `401` with header `WWW-Authenticate: Basic realm="GitHub"`.
2. Victim adds this remote in GitHub Desktop and performs a fetch/clone.
3. Git invokes the Desktop credential helper (`get`); `getEndpointKind()` sees the spoofed header and returns `'enterprise'` without ever calling `isGitHubHost()`.
4. Since no `Account` exists for `evil.example.com`, `getCredential()` calls `ui.promptForGitHubSignIn('https://evil.example.com')`, which starts the GHE sign-in flow, opening an OAuth authorization page rooted at the attacker's origin.
5. If the victim proceeds through the (visually legitimate, Desktop-native) sign-in prompt, an `Account` is stored with `endpoint: 'https://evil.example.com'`, and future requests to that host will automatically receive the account's token via `findGitHubTrampolineAccount`.

Note: I was unable to fully inspect `isGitHubHost()` in `app/src/lib/api.ts` (index limits prevented reading its full body), so I could not confirm exactly what real verification it performs or how robust it is; however, this does not affect the core finding, since the vulnerability is that the header-based branch bypasses that check entirely for attacker-chosen inputs, regardless of the its implementation strength. For full verification of `isGitHubHost()`'s internals, a Devin session with full file access would be needed.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }

export async function findGitHubTrampolineAccount(
  accountsStore: AccountsStore,
  remoteUrl: string
): Promise<Account | undefined> {
  const accounts = await accountsStore.getAll()
  const parsedUrl = new URL(remoteUrl)
  return accounts.find(
    a => new URL(getHTMLURL(a.endpoint)).origin === parsedUrl.origin
