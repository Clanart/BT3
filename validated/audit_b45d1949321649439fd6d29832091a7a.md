### Title
Unchecked nil-pointer dereference in legacy precompile error handling - ([File: precompiles/common/legacy/v600/precompiles.go])

### Summary
Multiple legacy (block-height-gated) precompile implementations dereference the result of `state.GetDBImpl(evm.StateDB)` without a nil check when reporting a precompile execution error, mirroring the TensorFlow `ctx->session_state()` bug class: a pointer-returning accessor that can legitimately return nil is called through directly instead of being checked first.

### Finding Description
The current, actively-maintained precompile dispatcher guards this call: [1](#0-0) 

```go
func HandlePrecompileError(err error, evm *vm.EVM, operation string) {
	if err != nil {
		if sdb := state.GetDBImpl(evm.StateDB); sdb != nil {
			sdb.SetPrecompileError(err)
		}
		...
```

but every legacy/historical precompile version still in the compiled binary (used for block-height-gated tracer/replay dispatch per `x/evm/AGENTS.md`'s "Precompiles are versioned by block height, allowing tracer functionality at historical heights") calls the unguarded form directly: [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4) 

`GetDBImpl` explicitly documents/returns nil when the `vm.StateDB` implementation is not a `*DBImpl` or a `*state.HookedStateDB` wrapping one: [6](#0-5) 

This is the exact bug class from the report: a helper that can return an invalid/nullable pointer is dereferenced by calling a member function (`.SetPrecompileError(err)`) on it without a nil guard, exactly as `ctx->session_state()` was dereferenced unchecked in the TensorFlow CVE.

### Impact Explanation
If any code path that invokes one of these legacy/versioned precompiles supplies a `vm.StateDB` implementation other than `*DBImpl`/`*HookedStateDB` (e.g., a tracer, simulation, or block-replay `StateDB` wrapper used for historical-height execution), the deferred error handler will nil-dereference and panic. Depending on whether the calling path recovers panics, this can surface as an uncaught panic that crashes the node process serving that request (a public RPC/tracing node), rather than being cleanly converted into a revert — a crash of a default-configuration RPC node is explicitly in the accepted impact list.

### Likelihood Explanation
I could **not conclusively verify** (within the available tool budget) that a production, unprivileged-reachable call path actually supplies a non-`DBImpl` `StateDB` into these specific legacy precompile versions, nor whether the outer tracing/replay call stack (`evmrpc/tracers.go`, `evmrpc/block_trace_profiled.go`) recovers panics before they reach the process level. The `eth_call`/`eth_estimateGas` path (`evmrpc/simulate.go`) does have a `recover()` guard converting panics into JSON-RPC errors, which would likely mask this specific issue for that entry point, but I was unable to confirm the same protection exists for `debug_traceTransaction`/`debug_traceBlock*` handlers that specifically exercise historical, block-height-versioned precompile code. This uncertainty materially affects severity: if those trace/replay entry points lack panic recovery, this is a real unauthenticated node-crash vector reachable by any public-RPC client; if they always recover, the practical impact is degraded to an RPC error rather than a crash.

### Recommendation
- Apply the same `if sdb := state.GetDBImpl(evm.StateDB); sdb != nil { sdb.SetPrecompileError(err) }` guard uniformly across all `precompiles/**/legacy/**/*.go` `Run`/`HandlePrecompileError` implementations that still use the unguarded form (v552 through v610 across `common`, `addr`, `bank`, `distribution`, `gov`, `json`, `oracle`, `pointer`, `pointerview`, `staking`, `wasmd`).
- Confirm (with full repository access, which was not fully explorable here) whether `debug_traceTransaction`, `debug_traceBlockByNumber`, and block-replay code paths that invoke these legacy precompiles wrap execution in a `recover()` at the RPC-handler boundary; add one if missing.

### Proof of Concept
Not constructed — reproducing this requires confirming, with full access to `evmrpc/tracers.go` and the block-replay `StateDB` construction, a concrete request (e.g. `debug_traceBlockByNumber` at a height governed by one of the affected legacy precompile versions) that supplies a `vm.StateDB` not satisfying `*DBImpl`/`*HookedStateDB` to the precompile's `Run`. I was unable to trace that construction fully within the available iterations and do not want to assert a PoC I cannot support with code evidence.

func GetDBImpl(vmsdb vm.StateDB) *DBImpl {
	if sdb, ok := vmsdb.(*DBImpl); ok {
		return sdb
	}

		return GetDBImpl(hdb.StateDB)
