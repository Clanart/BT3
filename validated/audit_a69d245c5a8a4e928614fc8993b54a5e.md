### Title
Weak host validation in `githubAssetVideoRegex` allows lookalike-hostname bypass of the video-tag filter - (File: `app/src/lib/markdown-filters/video-url-regex.ts`)

### Summary
`githubAssetVideoRegex` only checks that a `src`/`href` string *starts with* the literal string `https://user-images.githubusercontent.com` followed by `.+` and a video-file extension. It does not verify that the character following the trusted hostname is a path delimiter (`/`) or otherwise anchor the hostname boundary, so any origin that has `user-images.githubusercontent.com` as a *prefix* of its hostname is accepted as if it were the trusted GitHub asset CDN.

### Finding Description
The regex is built as: [1](#0-0) 

`escapeRegExp(user_images_cdn_url)` correctly escapes the dots in `https://user-images.githubusercontent.com`, but the regex is `^<escaped-literal>.+<extension>$` — there is no delimiter requirement (e.g. `[/:]`) between the literal domain and the following `.+`. Because `.+` matches *any* character including additional dots, a string like:

```
https://user-images.githubusercontent.com.attacker.io/evil.mp4
```

satisfies `^https://user-images\.githubusercontent\.com` (literal prefix match) followed by `.+` matching `.attacker.io/evil` and then the extension `mp4` at the end — the full regex test returns `true`.

This value is used both in `VideoTagFilter.createFilterTreeWalker`/`filter` to decide whether a `<video src>` tag is kept: [2](#0-1) [3](#0-2) 

and in `VideoLinkFilter.getGithubVideoLink` to decide whether an auto-linked URL should be converted into a `<video>` element: [4](#0-3) 

Both filters run inside `SandboxedMarkdown.applyFilters`, after DOMPurify sanitization but before the video element is left in the rendered document that's displayed in the app's markdown iframe: [5](#0-4) 

### Impact Explanation
The iframe is sandboxed with `sandbox="allow-same-origin"` only (no `allow-scripts`), so this cannot lead to script execution: [6](#0-5) 

The practical impact is limited to the `<video>` element's `src` (and any `poster`, if it were checked — it currently isn't) loading media from an attacker-controlled origin instead of GitHub's CDN. This means:
- The video request leaks the requesting user's IP address and, since `allow-same-origin` is set, cookies/referrer behavior tied to the iframe's effective origin could be sent to the attacker's server (subject to Electron/Chromium's handling of `data:` URI-derived iframe origins, which is opaque/`null` — same-origin doesn't grant it the app's own cookies, but does allow same-origin scripting/storage isolation for the iframe's own null origin).
- No arbitrary URL scheme bypass beyond `.mp4`/etc. extension requirement, and no direct RCE, credential exfiltration, or IPC escape.

This is a real regex logic bug (host-prefix match instead of proper hostname/origin comparison), but the resulting impact is confined to loading attacker media inside a `allow-scripts`-free sandbox, which is a low-severity content-spoofing / minor SSRF-style leak rather than code execution, file access, or credential theft.

### Likelihood Explanation
Trivial to exploit — any repository README, issue, PR, or commit-message markdown rendered through `SandboxedMarkdown` can include a `<video src="https://user-images.githubusercontent.com.attacker.io/x.mp4">` tag or an auto-linked URL with the same lookalike host, requiring no special privileges beyond making the attacker-controlled markdown reachable to a victim (e.g., a public repo, PR, or issue the victim opens in Desktop).

### Recommendation
Replace the prefix-based regex with proper URL parsing/host comparison, e.g. parse the candidate URL with the `URL` constructor and check `url.protocol === 'https:' && url.hostname === 'user-images.githubusercontent.com'`, or at minimum require a hostname boundary in the regex, such as `^https://user-images\.githubusercontent\.com(/|$)` before allowing any further path/extension matching, to prevent hostname-suffix spoofing like `user-images.githubusercontent.com.attacker.io`.

### Proof of Concept
1. Craft a markdown comment/README containing:
```html
<video src="https://user-images.githubusercontent.com.attacker.io/evil.mp4"></video>
```
2. Render it via `SandboxedMarkdown` (e.g., in a PR description, issue, or commit message viewed in GitHub Desktop).
3. Observe that `githubAssetVideoRegex.test('https://user-images.githubusercontent.com.attacker.io/evil.mp4')` returns `true`, so `VideoTagFilter` does **not** strip the tag, and the iframe issues a request for the video to `attacker.io` instead of GitHub's CDN.
4. Equivalent PoC via `VideoLinkFilter` using an auto-linked markdown URL: `https://user-images.githubusercontent.com.attacker.io/evil.mp4` pasted as plain text, which markdown auto-links and the filter converts into a `<video>` tag pointing at the attacker host.

    if (!isElement(node, 'video') || githubAssetVideoRegex.test(node.src)) {
      // If it is video element with a valid source, we return null to leave it alone.
      // This is different than dotcom which regenerates a video tag because it
      // verifies through a db call that the assets exists
      return null
    }

    // Return empty array so that video tag is removed
    return []
  }

  private async applyFilters(doc: Document) {
    const { emoji, repository, markdownContext } = this.props
    const filters = buildCustomMarkDownNodeFilterPipe({
      emoji,
      repository,
      markdownContext,
    })

    for (const nodeFilter of filters) {
      let docMutated = false
      const walker = nodeFilter.createFilterTreeWalker(doc)

      let node = walker.nextNode()
      while (node !== null) {
        const replacementNodes = await nodeFilter.filter(node)

        if (this.currentDocument !== doc) {
          // Abort, the document has changed
          return
        }

        const currentNode = node
        node = walker.nextNode()

        if (replacementNodes === null) {
          continue
        }

        docMutated = true

        for (const replacementNode of replacementNodes) {
          currentNode.parentNode?.insertBefore(replacementNode, currentNode)
        }
        currentNode.parentNode?.removeChild(currentNode)
      }

      if (docMutated) {
        this.refreshHeight()
      }
    }
  }
