### Title
Flash-loan spot-price manipulation of the WOM–mWOM pool lets an attacker mint mWOM at a manipulated rate via `SmartWomConvert.convert`/`convertFor` - (File: `wombat/SmartWomConvert.sol`)

### Summary
`SmartWomConvert` allows any unprivileged wallet to convert WOM into mWOM through a caller-chosen split between (a) a direct 1:1 mint via `mWOM.deposit()` and (b) an AMM swap through the Wombat `womMWomPool` (`IWombatRouter.swapExactTokensForTokens`). Because the swap-based portion relies on the pool's instantaneous spot price with no TWAP or external price check, an attacker can atomically manipulate the pool, execute the conversion at the manipulated rate, and reverse the manipulation within a single transaction — the exact bug class described in the referenced report (spot-price/flash-loan manipulation of a pool used to price a deposit/mint).

### Finding Description
`convert`/`convertFor` are public, unprivileged entry points into `_convertFor`: [1](#0-0) 

The caller fully controls `_convertRatio` (the split between direct mint vs. swap) and `_minRec` (their own slippage floor), and `_convertFor` executes the swap leg using the router's real-time spot pricing from `womMWomPool`: [2](#0-1) 

The swap output is determined purely by the pool's current `cash`/`liability` state at call time (see `currentRatio()` and `maxSwapAmount()`, which also read live pool state via `IAsset(womAsset).cash()`/`liability()`): [3](#0-2) 

An attacker can, within one transaction:
1. Flash-loan WOM (or mWOM).
2. Swap mWOM into `womMWomPool` (increasing mWOM cash / decreasing WOM cash), which makes mWOM cheap relative to WOM in that pool.
3. Call `convert(_amountIn, _convertRatio=0, _minRec, _mode)` so the entire `_amountIn` routes through the swap leg (`buybackAmount == _amount`), receiving an inflated amount of mWOM because the pool momentarily favors WOM→mWOM conversion.
4. Reverse step 2 (swap WOM back for mWOM, or vice versa) to restore the pool to its prior state.
5. Repay the flash loan, keeping the excess mWOM minted at better-than-fair value.

Since mWOM is a non-redeemable, permanently-locked liquid wrapper (backed 1:1 by locked WOM/veWOM under normal `deposit()` mint), obtaining mWOM at a rate more favorable than 1:1 dilutes the backing ratio for all existing mWOM holders — this is the underlying insolvency/dilution mechanism flagged in the report (extra "shares" minted from a manipulated spot price, later cashed out as if legitimately earned).

### Impact Explanation
Any unprivileged wallet with flash-loan access can extract mWOM in excess of the WOM value actually contributed, directly diluting/harming existing mWOM and downstream vlMGP/mWomSV holders whose positions are valued against the mWOM supply and its WOM backing. This is a direct value-extraction (theft-of-funds-class) vulnerability reachable without any privileged role, matching the "protocol insolvency / theft of user funds" impact bar.

### Likelihood Explanation
The attack requires only: (1) flash-loan liquidity for WOM/mWOM, (2) sufficient depth/shallowness imbalance in `womMWomPool` to move the spot price profitably net of swap fees, and (3) a single atomic transaction calling public, unprivileged functions (`convert`/`convertFor`). No governance or admin cooperation is needed, making this practically exploitable whenever the pool's liquidity is thin relative to available flash-loan capital.

### Recommendation
- Do not let a caller unilaterally set `_convertRatio` for the swap-based buyback path; restrict `convert`/`convertFor` (or at least the swap leg) to be driven by protocol-computed ratios only (as in `smartConvert`), or remove public access to the raw swap leg entirely.
- Use a manipulation-resistant price reference (e.g., time-weighted average of `currentRatio()`, or a minimum-bound check against the last several blocks) rather than the pool's instantaneous spot state for `currentRatio()`/`maxSwapAmount()`.
- Add same-block/flash-loan protections (e.g., disallow swap-and-convert within the same block as a large pool-state change, or cap `_amountIn` relative to pool depth) to bound the attacker's manipulation budget.

### Proof of Concept
1. Attacker flash-loans WOM.
2. Attacker calls the Wombat router to swap mWOM→WOM (or WOM→mWOM) against `womMWomPool` in a size sufficient to skew `cash`/`liability`, per `IAsset(womAsset).cash()/liability()` referenced in `maxSwapAmount()`/`currentRatio()` (`wombat/SmartWomConvert.sol:98-117`).
3. Attacker calls `SmartWomConvert.convert(_amountIn, _convertRatio=0, _minRec=0, _mode)` so the entire amount routes through `swapExactTokensForTokens` in `_convertFor` (`wombat/SmartWomConvert.sol:186-197`), receiving mWOM at the manipulated, favorable rate.
4. Attacker reverses the initial pool swap to restore state and repays the flash loan, net keeping mWOM minted above fair 1:1 backing.
