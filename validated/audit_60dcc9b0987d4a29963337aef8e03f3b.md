### Title
Attacker-crafted `Co-Authored-By` trailers from foreign commits are silently folded into the user's squashed commit metadata - ([File: app/src/ui/history/compare.tsx])

### Summary
Desktop's squash feature reads `Co-Authored-By` trailers directly out of the raw body text of every commit involved in a squash (including commits the user did **not** author, e.g. commits that arrived via clone/fetch/merge from a fork) and uses them to pre-populate the co-author list and merged description of the newly created commit, with no check on whether those trailers originated from a trusted source.

### Finding Description
Git commit trailers are just text embedded in a commit body — anyone who can get a commit into the user's local history (by being merged, cherry-picked, or simply present on a branch/fork the user fetched) fully controls that text. `extractCoAuthors` in `app/src/models/commit.ts` (lines 39-52) parses `Co-Authored-By` trailers straight out of `trailers` on the `Commit` model with no origin/trust check: [1](#0-0) 

When the user squashes commits, `onSquash` in `app/src/ui/history/compare.tsx` collects co-authors from *all* commits being squashed (`toSquashSansSquashOnto` + `squashOnto`) via `getUniqueCoauthorsAsAuthors(allCommitsInSquash)`, and merges their bodies (minus trailers) into a new description via `getSquashedCommitDescription`, then pre-fills the commit dialog with `coAuthors` and `showCoAuthoredBy: coAuthors.length > 0`: [2](#0-1) 

`getSquashedCommitDescription` simply concatenates the (co-author-stripped) bodies of every squashed commit, oldest to newest, into the new commit body: [3](#0-2) 

Neither of these code paths distinguishes "trailers I typed" from "trailers that came from a commit somebody else authored and that ended up in my history." The broken invariant mirrors the AA-wallet report's root cause: an identifier (there, a wallet address; here, a `name <email>` co-author identity) that is only meaningful/valid in one context (the foreign commit's author) is silently reused as if it were an identity the current user (the committer performing the squash) explicitly vouched for, and the app has no way to tell the two apart once the trailer text is parsed.

### Impact Explanation
This is a silent corruption of what the user commits/pushes:
- An attacker who gets even one crafted commit into a fork/branch that the victim later fetches, cherry-picks, or merges (a normal, low-friction interaction) can inject a `Co-Authored-By: <arbitrary name> <arbitrary email>` trailer that will automatically resurface as a co-author chip and be baked into the victim's own squashed commit the next time they squash across that commit.
- Because the co-author list is presented as UI chips (not raw diffed text), a user reviewing the summary/description text box may not notice an unfamiliar co-author was silently added to the commit metadata.
- If pushed to GitHub, `Co-Authored-By` trailers cause GitHub to attribute contribution/credit (and can trigger notifications) to the named account — allowing an attacker to force spurious "contributor" attribution onto arbitrary email addresses/accounts, or to forge apparent endorsement/review of a commit's content without that party's consent.
- The concatenated body text from foreign commits (`getSquashedCommitDescription`) is also merged wholesale into the description of the user's new commit, meaning any other trailers or content (e.g. forged `Signed-off-by:` DCO lines) embedded by an attacker also propagate into the victim's own signed history.

### Likelihood Explanation
Requires no special privileges — only that the victim performs an ordinary workflow (fetch a branch/fork, cherry-pick or merge a commit, then use Desktop's "Squash" feature across commits that include the foreign one). No local/physical access, no admin rights, and no prior compromise of the host are needed; the only "unnatural" step is a squash that spans a foreign commit, which is a common occurrence when integrating PR feedback or rebasing forked contributions.

### Recommendation
- Do not treat `Co-Authored-By` (or other) trailers extracted from commits the user did not author as trusted input for auto-populating co-author chips; at minimum, visually distinguish "co-authors inherited from squashed commits" from user-entered ones, and require explicit confirmation before including them.
- Validate/normalize co-author email/name pairs against known, previously-interacted-with identities (e.g., GitHub API identities from actual repository collaborators) before silently attaching them to a new commit.
- When concatenating commit bodies for `getSquashedCommitDescription`, strip or flag any trailer-like lines (not just `Co-Authored-By`) originating from squashed-in commits so they cannot be laundered into the new commit's trailers without the user's awareness.

### Proof of Concept
1. Attacker creates a public fork/branch containing a commit whose message includes:
   ```
   Fix minor bug

   Co-Authored-By: Trusted Maintainer <maintainer@example.com>
   ```
2. Victim fetches/merges or cherry-picks that commit into their local branch in GitHub Desktop (a routine action, e.g. incorporating a PR suggestion).
3. Victim selects that commit together with one or more of their own commits and chooses "Squash" in Desktop's history view (`app/src/ui/history/compare.tsx`, `onSquash`).
4. `getUniqueCoauthorsAsAuthors(allCommitsInSquash)` extracts the attacker's `Co-Authored-By` trailer from the foreign commit's `coAuthors` (populated via `extractCoAuthors` in `app/src/models/commit.ts`) and the commit-message dialog opens pre-populated with `Trusted Maintainer <maintainer@example.com>` as a co-author chip.
5. Victim, focused on editing the summary/description text, submits the squash. The resulting commit is created with `Co-Authored-By: Trusted Maintainer <maintainer@example.com>` even though that person had no involvement, and the merged description contains attacker-supplied body text — all without any warning that this data originated from an untrusted, externally-authored commit.

function extractCoAuthors(trailers: ReadonlyArray<ITrailer>) {
  const coAuthors = []

  for (const trailer of trailers) {
    if (isCoAuthoredByTrailer(trailer)) {
      const author = GitAuthor.parse(trailer.value)
      if (author) {
        coAuthors.push(author)
      }
    }
  }

  return coAuthors
}

import { Commit } from '../../models/commit'

export function getSquashedCommitDescription(
  commits: ReadonlyArray<Commit>,
  squashOnto: Commit
): string {
  const commitMessages = commits.map(
    c => `${c.summary.trim()}\n\n${c.bodyNoCoAuthors.trim()}`
  )

  const descriptions = [
    squashOnto.bodyNoCoAuthors.trim(),
    ...commitMessages,
  ].filter(d => d.trim() !== '')

  return descriptions.join('\n\n')
}
