## Analysis Result [1](#0-0) 

An analog to CVE-2023-29291 (SSRF via attacker-controlled URL configuration) exists in Chia's DataLayer mirror mechanism.

### Title
Unauthenticated on-chain SSRF via arbitrary mirror URLs fetched by any DataLayer node - ([File: chia/data_layer/download_data.py])

### Summary
Any wallet user can create an on-chain "mirror" coin for **any** DataLayer `launcher_id` (not just their own store) by calling `dl_new_mirror`, embedding arbitrary attacker-controlled URLs in the coin memo. Any other party's `DataLayer` service that tracks/subscribes to that same `launcher_id` will automatically pull these URLs from the chain and use them as HTTP(S) endpoints to fetch delta files, with no host/scheme validation — allowing an unprivileged chain participant to force victim nodes to issue arbitrary outbound HTTP requests (classic SSRF).

### Finding Description
`DataLayerWallet.create_new_mirror()` builds a standard coin spend with a memo containing `[launcher_id, *urls]` and does not verify that the caller owns or controls `launcher_id`: [1](#0-0) 

The RPC path (`dl_new_mirror` → `WalletRpcApi.dl_new_mirror`) exposes this without additional authorization checks beyond normal spend-bundle submission: [2](#0-1) 

Once the mirror coin is confirmed on-chain, **any** wallet tracking that launcher (e.g. via `dl_track_new`) picks it up in `coin_added()`, decodes the attacker-supplied URLs from the coin's parent spend, and stores them as a `Mirror` record, with no URL validation: [3](#0-2) 

The `DataLayer` service's periodic sync loop (`update_subscription()`) then calls `update_subscriptions_from_wallet()`, which pulls these mirror URLs from the wallet and inserts them into the local `subscriptions` table for the store: [4](#0-3) [5](#0-4) 

`fetch_and_validate()` then randomly selects one of these server URLs and attempts to download delta files from it: [6](#0-5) 

The actual HTTP fetch in `http_download()` concatenates the attacker-controlled `server_info.url` directly into an `aiohttp` GET request with **no validation of scheme, host, or destination** (no check against private/link-local/loopback ranges, no allowlist): [7](#0-6) 

### Impact Explanation
Because `create_new_mirror` never checks that the submitter owns `launcher_id`, any user who can submit a spend bundle can inject arbitrary URLs (e.g. `http://169.254.169.254/latest/meta-data/`, `http://internal-service:port/admin`, or a large-response host to cause disk exhaustion) into the mirror table for **any** store, including popular/widely-subscribed stores. Every DataLayer node that tracks or subscribes to that store — a normal, unprivileged operation for any Data Layer client — will automatically make outbound HTTP GET requests to the attacker-chosen destination during its periodic sync loop, with the response content parsed and written to disk (`insert_into_data_store_from_file`). This can be used to probe/attack internal network services reachable from DataLayer nodes, hit cloud metadata endpoints, or perform request smuggling/denial-of-service against arbitrary hosts, all triggered purely by an on-chain coin creation that costs only a mojo fee.

### Likelihood Explanation
Likelihood is high for any environment where third parties run DataLayer nodes and track/subscribe to stores they don't fully trust: creating a mirror coin requires no special privilege beyond a standard signed spend bundle, and subscription/mirror URL ingestion happens automatically in the background sync loop (`periodically_manage_data()` → `update_subscription()`) without any user interaction or approval step.

### Recommendation
- In `DataLayerWallet.create_new_mirror()` / `dl_new_mirror` RPC, restrict which URLs/hosts may be published, or at minimum validate them (reject private/loopback/link-local ranges, non-HTTP(S) schemes) before accepting.
- In `download_data.http_download()` and `DataLayer.get_downloader()`, validate `server_info.url` / mirror URLs against an allowlist of schemes (`http`/`https`) and reject requests to private, loopback, link-local, or metadata-service IP ranges before issuing the `aiohttp` request.
- Consider requiring explicit user confirmation (opt-in per mirror URL) before a DataLayer node will actually dial a URL sourced from chain data it does not control.

### Proof of Concept
1. Attacker calls `dl_new_mirror` (via wallet RPC or `chia data add_mirror`) targeting a `launcher_id` of a store that victim nodes subscribe to, with `urls=["http://169.254.169.254/latest/meta-data/iam/security-credentials/"]` (or an internal service URL) and pushes the transaction. [8](#0-7) 
2. Once confirmed, any victim DataLayer node tracking that `launcher_id` ingests the mirror via `coin_added()` and stores it via `update_subscriptions_from_wallet()`. [4](#0-3) 
3. On the next sync cycle, `fetch_and_validate()` selects the malicious URL and `http_download()` issues an unauthenticated `GET` request to it from the victim's network, with no destination validation. [7](#0-6)

```python
    async def update_subscriptions_from_wallet(self, store_id: bytes32, new_urls: list[str]) -> None:
        async with self.db_wrapper.writer() as writer:
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 1 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            old_urls = [row["url"] async for row in cursor]
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 0 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            from_subscriptions_urls = {row["url"] async for row in cursor}
            additions = {url for url in new_urls if url not in old_urls}
            removals = [url for url in old_urls if url not in new_urls]
            for url in removals:
                await writer.execute(
                    "DELETE FROM subscriptions WHERE url == :url AND tree_id == :tree_id",
                    {
                        "url": url,
                        "tree_id": store_id,
                    },
                )
            for url in additions:
                if url not in from_subscriptions_urls:
                    await writer.execute(
                        "INSERT INTO subscriptions(tree_id, url, ignore_till, num_consecutive_failures, from_wallet) "
                        "VALUES (:tree_id, :url, 0, 0, 1)",
                        {
                            "tree_id": store_id,
                            "url": url,
                        },
                    )
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
