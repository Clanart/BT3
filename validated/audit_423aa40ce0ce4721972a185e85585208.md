### Title
Blind SSRF via attacker-controlled git remote/submodule URL in `isGitHubHost()` credential-classification probe — (File: `app/src/lib/api.ts`)

### Summary
The HackerOne report describes a CI-runner SSRF where an initial security check against cloud metadata endpoints is bypassed on a second pass because the underlying network state was cached rather than re-validated. The closest local analog in GitHub Desktop is `isGitHubHost()` in [1](#0-0) , which issues a real outbound `fetch()` from Desktop's privileged main process to whatever host is embedded in a git credential URL, and whose "is this really GitHub" verdict is then cached to `localStorage` in [2](#0-1)  — a decision that, once made, is trusted on future invocations without re-probing, mirroring the "defended on first run, not on re-run" pattern.

### Finding Description
Every time Git needs credentials for an HTTPS remote, GitHub Desktop's credential trampoline handler is invoked (`createCredentialHelperTrampolineHandler` in [3](#0-2) ). This calls `getEndpointKind()` [4](#0-3) , which — when the WWW-Authenticate realm header doesn't already disambiguate the host and no existing account matches — falls through to:

```
return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
```

`isGitHubHost()` builds `endpoint` directly from the URL Git is authenticating against (`getCredentialUrl(cred)`), with no restriction on host/IP, and performs an outbound HEAD request to `${endpoint}/meta?ghd=...` [5](#0-4) . Because Git resolves credential-helper lookups for **every** host it talks to during clone/fetch — including submodule remotes and LFS endpoints defined in `.git/config`/`.gitmodules`, which are attacker-controlled content inside a cloned/fetched repository — an attacker who controls a repository (e.g., a malicious submodule URL such as `https://169.254.169.254/`) can cause Desktop's main process to issue a network request to an internal/cloud-metadata address chosen entirely by the attacker.

The verdict from this probe is not purely ephemeral: a successful response updates a persistent classification cache keyed only by endpoint string in `endpoint-capabilities.ts` (`updateEndpointVersion` writes to `localStorage`, `getEndpointVersion` reads it back on subsequent calls without re-validating) [2](#0-1) . This means once an attacker-controlled internal endpoint has been probed and classified, later app runs can reuse the cached classification rather than re-issuing (or re-checking) the request, which is structurally the same "guard applies once, then is trusted forever" flaw as the CI/metadata report.

### Impact Explanation
The request is made by the Desktop main process (not the sandboxed renderer), from a real HTTP client with `redirect: 'error'` and 2-second timeout, but with no allowlist/denylist for private, loopback, or link-local addresses (e.g. `169.254.169.254`). This is a blind SSRF primitive: an attacker who controls a cloned/fetched repository's remotes or submodule URLs can force Desktop to make outbound requests to internal-only hosts (cloud metadata services, internal admin endpoints, etc.), which is exactly the bug class in the source report. Unlike the original report, `isGitHubHost()` does not return response bodies to the user, so this does not directly exfiltrate metadata contents — it only confirms reachability and can trigger internal side effects on any endpoint that reacts to a bare `HEAD`/GET.

### Likelihood Explanation
The credential trampoline runs on every Git network operation without user awareness, and submodule/LFS URLs are ordinary repository content that an attacker fully controls when the victim clones or fetches from a malicious/compromised repository — no local access, admin rights, or social engineering beyond "clone this repo" is required. This keeps likelihood moderate, but the confirmed impact is limited to blind SSRF (host/port reachability probing) rather than a data-exfiltration primitive, since I could not find any code path where `isGitHubHost()`'s response body/content is surfaced to the attacker or where a session token is silently sent to the untrusted host without a user-facing sign-in prompt (`ui.promptForGitHubSignIn`, [6](#0-5) ).

### Recommendation
- Restrict `isGitHubHost()`/`getAbsoluteUrl`-style outbound probing to exclude loopback, link-local (169.254.0.0/16), and RFC1918 private address ranges unless the user has explicitly configured that host as an Enterprise endpoint.
- Do not persist a "GitHub host" classification (`updateEndpointVersion`/`localStorage` cache in `endpoint-capabilities.ts`) for hosts that haven't been explicitly added as an account endpoint by the user, to avoid trust decisions surviving across app restarts without re-validation.
- Consider gating the credential-helper's automatic SSRF-prone probe (`isGitHubHost`) behind the same submodule/URL trust prompts already used elsewhere in Desktop for untrusted repository content.

### Proof of Concept
1. Create/host a malicious repository containing a `.gitmodules` entry (or a remote in `.git/config`) with `url = https://169.254.169.254/`.
2. Have the victim clone or fetch this repository (or add it as a remote) in GitHub Desktop.
3. During the fetch/clone, Git invokes the credential helper for the submodule URL's host; `getEndpointKind()` → `isGitHubHost('https://169.254.169.254')` causes Desktop's main process to send an HTTP HEAD request to the internal metadata address [7](#0-6) , confirming the SSRF primitive without any explicit user consent for that specific network call.

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}

export function getEndpointVersion(endpoint: string) {
  const key = endpointVersionKey(endpoint)
  const cached = versionCache.get(key)

  if (cached !== undefined) {
    return cached
  }

  const raw = localStorage.getItem(key)
  const parsed = raw === null ? null : semver.parse(raw)

  if (parsed !== null) {
    versionCache.set(key, parsed)
  }

  return parsed
}

/**
 * Update the known version number for a given endpoint
 */
export function updateEndpointVersion(endpoint: string, version: string) {
  const key = endpointVersionKey(endpoint)

  if (rawVersionCache.get(key) !== version) {
    const parsed = semver.parse(version)
    localStorage.setItem(key, version)
    rawVersionCache.set(key, version)
    versionCache.set(key, parsed)
  }
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

export const createCredentialHelperTrampolineHandler: (
  store: AccountsStore
) => TrampolineCommandHandler = (store: Store) => async command => {
  const firstParameter = command.parameters.at(0)
  if (!firstParameter) {
    return undefined
  }

  const { trampolineToken: token } = command
  const input = parseCredential(command.stdin)

  if (__DEV__) {
    debug(
      `${firstParameter}\n${command.stdin
        .replaceAll(/^password=.*$/gm, 'password=***')
        .replaceAll(/^(.*)$/gm, '  $1')
        .trimEnd()}`
    )
  }

  try {
    if (firstParameter === 'get') {
      const cred = await getCredential(input, store, token)
      if (!cred) {
        const endpoint = `${getCredentialUrl(input)}`
        info(`could not find credential for ${endpoint}`)
        setHasRejectedCredentialsForEndpoint(token, endpoint)
      }
      return cred ? formatCredential(cred) : undefined
    } else if (firstParameter === 'store') {
      await storeCredential(input, store, token)
    } else if (firstParameter === 'erase') {
      await eraseCredential(input, store, token)
    }
    return undefined
  } catch (e) {
    error(`${firstParameter} failed`, e)
    return undefined
  }
}
