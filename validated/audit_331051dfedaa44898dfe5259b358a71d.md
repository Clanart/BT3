### Title
Honest operator's collateral burned when payout OP_RETURN is malleated into an unparsable push, causing `is_kickoff_malicious` to default to "malicious" - (File: core/src/verifier.rs)

### Summary
`Verifier::is_kickoff_malicious` treats any withdrawal whose confirmed payout tx OP_RETURN fails to decode into a valid `XOnlyPublicKey` as automatically malicious, with no fallback check of whether the payout's actual input/output still matches the registered withdrawal. If the payout transaction's non-OP_RETURN signature coverage allows a third party to mutate the OP_RETURN output while keeping input0/output0 unchanged (e.g., via a malleable sighash on the withdrawal UTXO's signature) and get that mutated version confirmed instead, any operator who legitimately fronted the withdrawal becomes permanently unable to prove it and is judged malicious, resulting in a challenge being queued against it.

### Finding Description
The claimed binding is: `payout_tx.input[0] == registered_withdrawal_utxo AND payout_tx.output[0] == withdrawal_recipient_output` should imply the operator that broadcast this payout is judged non-malicious for that withdrawal (assuming the committed blockhash also matches). Instead, the actual code checks only whether `payout_payer_operator_xonly_pk` decoded successfully: [1](#0-0) 

`operator_xonly_pk_opt` is populated from parsing the OP_RETURN of the confirmed payout tx via `parse_op_return_data` and `XOnlyPublicKey::from_slice`: [2](#0-1) 

and stored per-withdrawal via `update_payout_txs_and_payer_operator_xonly_pk`, which explicitly supports a `None` value in the schema (as the test comment notes, "optimistic payout or incorrect payout"): [3](#0-2) [4](#0-3) 

`get_payout_info_from_move_txid` is keyed only by `move_to_vault_txid`, so exactly one payout tx (the one that ends up confirmed at the withdrawal's UTXO input/output position tracked by `bitcoin_syncer_spent_utxos`) determines the outcome for that withdrawal index, with no re-derivation or fallback comparison against the actually fronted input/output once the pubkey field is `NULL`: [5](#0-4) 

If the withdrawal UTXO's spending signature (the `in_signature`/sighash flag chosen by the withdrawing party at `withdraw()` time) does not cover the OP_RETURN output, an attacker can broadcast a replacement transaction preserving input0 and the recipient output0 (so it still validly spends the same UTXO with the same signature) but with a corrupted, non-32-byte OP_RETURN push (e.g. `OP_RETURN OP_PUSHBYTES_1 0x00`). Once this replacement confirms instead of the honest operator's original broadcast, `parse_op_return_data` still returns `Some(bytes)`, but `XOnlyPublicKey::from_slice` fails on the wrong-length data, so `operator_xonly_pk` is stored as `NULL`. When honest operator O later performs its kickoff for this withdrawal, `is_kickoff_malicious` hits the `None` branch at line 1882-1885 and returns `true` unconditionally, before ever checking whether O's `kickoff_data.operator_xonly_pk` matches, or whether the committed blockhash matches. `handle_kickoff` then queues a `Challenge` transaction against O: [6](#0-5) 

No other guard in the reachable path revalidates the input/output correspondence once the pubkey field is null; the `None` case is treated purely as "cannot attribute payout to any operator, so any claim is malicious," which is fatal to the honest operator that in fact fronted the exact withdrawal.

### Impact Explanation
Operator O, having correctly and fully fronted a withdrawal (same input0 spending the registered withdrawal UTXO, same output0 paying the recipient), is deterministically judged "malicious" once the confirmed payout tx's OP_RETURN cannot decode to a 32-byte x-only pubkey. This triggers automatic queuing of a `Challenge` transaction in `handle_kickoff`, leading to Disprove/collateral loss for an operator that made zero protocol deviation. This is repeatable per-withdrawal and does not depend on which operator is targeted; any operator whose payout's OP_RETURN gets malleated into an invalid pubkey length is affected the same way. This matches the Critical impact category "an honest operator's collateral burned."

### Likelihood Explanation
This requires: (1) the withdrawal UTXO's spending authorization (signature/sighash flag chosen at Citrea `withdraw()` time, which the rules state is attacker-controllable) to not cover the OP_RETURN output of the payout transaction, and (2) the attacker's malleated replacement to be the one that gets mined instead of, or in place of, the operator's original broadcast (e.g. via RBF or by winning the race to inclusion). Both are within the stated attacker capabilities (calling `withdraw()`, choosing signature/sighash bytes, broadcasting Bitcoin transactions and paying fees) and require no operator/verifier key compromise. Cost is limited to fees to get the malleated tx mined ahead of/in place of the honest broadcast.

### Recommendation
Do not treat a null/unparsable `operator_xonly_pk` in the confirmed payout OP_RETURN as automatically malicious for the querying operator. Instead, when the pubkey field is null (or fails to parse), independently verify whether the confirmed payout transaction's input(s)/output(s) still match what the querying operator's kickoff claims to have fronted (i.e., re-derive attribution from the transaction body itself, not solely from the OP_RETURN commitment), or require the payout signature scheme to cover the OP_RETURN output (e.g., mandate `SIGHASH_ALL` for the withdrawal UTXO's spending signature) so that no output, including OP_RETURN, can be mutated post-broadcast without invalidating the signature.

    /// Checks if the kickoff is malicious and sends the appropriate txs if it is.
    /// Returns true if the kickoff is malicious.
    /// Sends a challenge tx if the kickoff is first malicious one in the current round, and the network is not mainnet or testnet4.
    pub async fn handle_kickoff<'a>(
        &'a self,
        dbtx: DatabaseTransaction<'a>,
        kickoff_witness: Witness,
        mut deposit_data: DepositData,
        kickoff_data: KickoffData,
        challenged_before: bool,
    ) -> Result<bool, BridgeError> {
        let is_malicious = self
            .is_kickoff_malicious(kickoff_witness, &mut deposit_data, kickoff_data, dbtx)
            .await?;

        let deposit_outpoint = deposit_data.get_deposit_outpoint();

        let (_signed_txs, tx_metadata, challenge_tx) = self
            .get_signed_txs_for_kickoff(dbtx, kickoff_data, deposit_data)
            .await?;

        if is_malicious {
            tracing::warn!(
                "Malicious {} detected. {} Challenge tx: {} for deposit {}",
                kickoff_data,
                match challenged_before {
                    false => "This is the first malicious kickoff in the current round.",
                    true => "This is not the first malicious kickoff in the current round.",
                },
                bitcoin::consensus::encode::serialize_hex(&challenge_tx),
                deposit_outpoint
            );
            // do not automatically send challenge txs on mainnet or testnet4
            if !challenged_before
                && !matches!(
                    self.config.protocol_paramset().network,
                    bitcoin::Network::Bitcoin | bitcoin::Network::Testnet4
                )
            {
                #[cfg(feature = "automation")]
                self.tx_sender
                    .add_tx_to_queue(
                        dbtx,
                        TransactionType::Challenge,
                        &challenge_tx,
                        &[],
                        Some(tx_metadata),
                        self.config.protocol_paramset(),
                        None,
                    )
                    .await?;
            }

/// Parses the OP_RETURN data from a Bitcoin script. It retrieves the first data push after an OP_RETURN.
pub fn parse_op_return_data(script: &Script) -> Option<&[u8]> {
    let mut instructions = script.instructions();
    if let Some(Ok(Instruction::Op(opcodes::all::OP_RETURN))) = instructions.next() {
        if let Some(Ok(Instruction::PushBytes(data))) = instructions.next() {
            return Some(data.as_bytes());
        }
    }
    None
}

    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

    pub async fn get_payout_info_from_move_txid(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        move_to_vault_txid: Txid,
    ) -> Result<Option<(Option<XOnlyPublicKey>, BlockHash, Txid, i32)>, BridgeError> {
        let query = sqlx::query_as::<_, (Option<XOnlyPublicKeyDB>, BlockHashDB, TxidDB, i32)>(
            "SELECT w.payout_payer_operator_xonly_pk, w.payout_tx_blockhash, w.payout_txid, w.idx
             FROM withdrawals w
             WHERE w.move_to_vault_txid = $1
               AND w.payout_txid IS NOT NULL
               AND w.payout_tx_blockhash IS NOT NULL",
        )
        .bind(TxidDB(move_to_vault_txid));

        let result: Option<(Option<XOnlyPublicKeyDB>, BlockHashDB, TxidDB, i32)> =
            execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        result
            .map(|(operator_xonly_pk, block_hash, txid, deposit_idx)| {
                Ok((
                    operator_xonly_pk.map(|pk| pk.0),
                    block_hash.0,
                    txid.0,
                    deposit_idx,
                ))
            })
            .transpose()
    }
