### Title
Forged `ReceivedOutput` can poison a Bitcoin spend with an unspendable input - (File: `networks/bitcoin/src/wallet/mod.rs`)

### Summary
`ReceivedOutput::read` accepts an attacker-supplied scalar offset, `TxOut`, and `OutPoint` without proving that the outpoint exists or that the claimed prevout came from Bitcoin consensus state. If the forged `TxOut` uses the scanner’s expected Taproot script and a matching offset, `SignableTransaction::multisig` accepts it and the wallet signs a transaction spending the nonexistent or misrepresented UTXO. This is analogous to accepting an unapproved asset into a shared payout: one poisoned input invalidates the entire transaction and can cause funds to be reported as spendable when they are not.

### Finding Description
`ReceivedOutput::read` deserializes an arbitrary offset, output value/script, and outpoint. It performs no authentication, ownership check, or chain-state verification. [1](#0-0) 

`SignableTransaction::new` trusts each supplied `ReceivedOutput`, adds its claimed value to the available input total, and uses its claimed `OutPoint` directly as a transaction input. [2](#0-1) 

`SignableTransaction::multisig` checks only that the output script equals the script derived by applying the supplied offset to the threshold key. An attacker can satisfy this by choosing `offset = 0` and setting the claimed `TxOut.script_pubkey` to `p2tr_script_buf(group_key)`, regardless of whether the referenced `OutPoint` actually exists or contains that script. [3](#0-2) 

The transaction machine then signs all inputs with `Prevouts::All`, including the forged prevout, and `complete` inserts signatures for every input before returning the transaction. [4](#0-3) [5](#0-4) 

### Impact Explanation
A forged `ReceivedOutput` can be reported as received wallet funds even though the referenced UTXO does not exist or does not contain the claimed script/value. If bundled with genuine inputs, the fake input causes the fully signed transaction to be rejected by Bitcoin consensus or mempool validation, preventing all of the transaction’s payments and change from confirming.

This satisfies the same failure shape as the source finding: an attacker-controlled item enters an aggregate list and causes the final spend/claim operation to fail.

### Likelihood Explanation
The attack requires an application path that feeds attacker-controlled bytes to `ReceivedOutput::read`. Under that stated trust boundary, exploitation requires no private keys, validator privileges, malformed encodings, or race conditions. The attacker only needs to know or observe the wallet’s public Taproot script and encode a structurally valid `ReceivedOutput` referencing a nonexistent or misrepresented outpoint.

### Recommendation
Do not treat `ReceivedOutput::read` as authenticating an unspent chain output. Separate trusted local-storage deserialization from untrusted input parsing, and reconstruct untrusted deposits only through `Scanner::scan_transaction`/`scan_block` plus confirmation that the transaction exists in an accepted block. If an untrusted representation must be accepted, bind it to a full Bitcoin transaction and block/merkle proof and verify the exact `TxOut`, `OutPoint`, and offset relationship before passing it to `SignableTransaction::new`.

### Proof of Concept
```rust
use bitcoin::{
  OutPoint, TxOut, Txid,
  hashes::Hash,
};
use k256::Scalar;

use serai_bitcoin::wallet::{p2tr_script_buf, ReceivedOutput};

// group_key is the wallet's even-Y threshold key.
let script = p2tr_script_buf(group_key).unwrap();

let mut encoded = Vec::new();

// offset = 0, encoded canonically.
encoded.extend_from_slice(&Scalar::ZERO.to_bytes());

// A claimed output controlled by the group key. The referenced chain output
// does not need to exist.
let claimed_txout = TxOut {
  value: bitcoin::Amount::from_sat(100_000),
  script_pubkey: script,
};
encoded.extend_from_slice(&bitcoin::consensus::serialize(&claimed_txout));

// A syntactically valid but nonexistent or misrepresented outpoint.
let fake_outpoint = OutPoint {
  txid: Txid::all_zeros(),
  vout: 0,
};
encoded.extend_from_slice(&bitcoin::consensus::serialize(&fake_outpoint));

let forged = ReceivedOutput::read(&mut encoded.as_slice()).unwrap();

// This counts the forged value as spendable and creates an input for the fake
// outpoint.
let tx = SignableTransaction::new(
  vec![forged, genuine_output],
  payments,
  change,
  None,
  fee_rate,
).unwrap();

// multisig succeeds because the forged TxOut script matches offset 0 of the
// group key. Signing produces a transaction which Bitcoin rejects because the
// fake previous output cannot be spent.
let machine = tx.multisig(&threshold_keys).unwrap();
```
