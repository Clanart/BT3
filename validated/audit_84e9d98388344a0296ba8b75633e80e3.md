### Title
Forged `ReceivedOutput` deserialization reports unspendable Bitcoin funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput::read` accepts a fully attacker-controlled scalar offset, `TxOut`, and `OutPoint` without proving that the output exists on Bitcoin or was produced by `Scanner`. Because `SignableTransaction` trusts the embedded value and `multisig` only checks that the declared script matches the threshold key plus offset, serialized public input can create a fake high-value deposit that later produces an invalid, unspendable transaction.

### Finding Description
`ReceivedOutput` consists of:

- an offset scalar;
- the claimed `TxOut`;
- the claimed `OutPoint`.

`ReceivedOutput::read` in `networks/bitcoin/src/wallet/mod.rs:120-133` only deserializes those fields. It does not verify:

- that `outpoint` exists;
- that the referenced transaction output equals `output`;
- that the output is mature;
- that the script was discovered by a `Scanner`;
- that the offset is a registered offset for the scanner.

The legitimate provenance check exists only in `Scanner::scan_transaction`, where a transaction output is accepted after `scripts.get(&output.script_pubkey)` succeeds and the real transaction ID/vout are recorded (`networks/bitcoin/src/wallet/mod.rs:198-214`). That provenance is not preserved or revalidated during deserialization.

`SignableTransaction::new` then trusts `input.output.value` as available input value (`networks/bitcoin/src/wallet/send.rs:175-221`), and `multisig` only verifies that `p2tr_script_buf(keys.offset(offset).group_key())` equals the declared `script_pubkey` (`networks/bitcoin/src/wallet/send.rs:273-284`). An attacker can satisfy that by using the known group key, offset `0`, and the corresponding Taproot script while claiming a nonexistent outpoint and arbitrary value.

### Impact Explanation
A caller that accepts untrusted serialized outputs can report funds as received even though no corresponding Bitcoin UTXO exists. The forged object can be used to construct a `SignableTransaction` and pass the local key/script check, but Bitcoin will reject the eventual spend because the prevout is absent or the committed `TxOut` does not match the real UTXO.

This is a medium-severity integrity issue: it does not recover the threshold private key, but it can corrupt balance accounting, schedule transactions that can never confirm, and cause unavailable funds or stuck withdrawals.

### Likelihood Explanation
Exploitation requires the application to feed attacker-controlled bytes to `ReceivedOutput::read` or to serialize a `ReceivedOutput` supplied by an untrusted peer. The attack needs no private keys, threshold participation, validator compromise, or invalid curve encodings:

- the attacker can choose offset `0`;
- the group Taproot script is public;
- any arbitrary `OutPoint` and amount can be encoded.

The impact is limited to paths treating the deserialized structure as authoritative rather than requiring fresh scanner/RPC confirmation.

### Recommendation
Do not treat `ReceivedOutput::read` as proof of ownership or existence. Either:

1. restrict deserialization to authenticated local state produced by `Scanner`;
2. revalidate the outpoint against the Bitcoin UTXO set and compare the actual `TxOut`; or
3. store enough context to prove the output was obtained through `Scanner::scan_transaction`/`scan_block`, and recompute that the offset belongs to a registered script.

`SignableTransaction::new` should also receive only scanner-validated outputs, and `multisig` should verify the actual prevout contents rather than only the script.

### Proof of Concept
```rust
use bitcoin::{Amount, OutPoint, TxOut};
use k256::{ProjectivePoint, Scalar};
use bitcoin_serai::wallet::{p2tr_script_buf, ReceivedOutput, SignableTransaction};

// Public, even-y threshold group key.
let group_key: ProjectivePoint = /* threshold group key */;

// Forge an output claiming a large balance at an outpoint that does not exist.
let forged = {
    let output = TxOut {
        value: Amount::from_sat(100_000_000),
        script_pubkey: p2tr_script_buf(group_key).unwrap(),
    };

    // Offset zero satisfies multisig's key/script check.
    let mut bytes = Scalar::ZERO.to_bytes().to_vec();
    bytes.extend(bitcoin::consensus::serialize(&output));
    bytes.extend(bitcoin::consensus::serialize(&OutPoint::default()));

    ReceivedOutput::read(&mut bytes.as_slice()).unwrap()
};

assert_eq!(forged.value(), 100_000_000);

// The wallet treats the fake value as spendable input when constructing a plan.
let tx = SignableTransaction::new(
    vec![forged],
    &[(p2tr_script_buf(group_key).unwrap(), 50_000_000)],
    None,
    None,
    10,
).unwrap();

// The signature ritual can proceed, but the resulting Bitcoin transaction is invalid
// because OutPoint::default() does not reference a real UTXO carrying this TxOut.
```
