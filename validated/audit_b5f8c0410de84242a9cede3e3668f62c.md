### Title
Unbounded index read on attacker-controlled CLVM length prefix in `is_atom_canonical()` - (File: chia/full_node/mempool_manager.py)

### Summary
`is_atom_canonical()` decodes a CLVM atom's length-prefix byte(s) taken directly from a submitted `SpendBundle`'s `puzzle_reveal` / `solution` and then indexes further into the buffer using `prefix_len` derived from that untrusted byte, without first checking that the buffer actually contains that many remaining bytes. This is the same bug class as CVE-2019-6444: an attacker-controlled length value is used to walk/dereference a buffer before its bounds are validated.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` inspects `clvm_buffer[offset]` and, depending on the high bits, sets `prefix_len` (0–5) purely from attacker data, then loops `for i in range(prefix_len): offset += 1; atom_len |= clvm_buffer[offset]` with no check that `offset` stays within `len(clvm_buffer)`. [1](#0-0) 

This function is called from `is_clvm_canonical()`, which itself is invoked directly on attacker-supplied bytes during mempool admission in `validate_spend_bundle()`: [2](#0-1) 

`is_clvm_canonical()` walks the buffer atom-by-atom, calling `is_atom_canonical()` whenever it encounters a byte `> 0x80`, again with no upfront bound check before dereferencing subsequent bytes: [3](#0-2) 

If a submitter crafts a `puzzle_reveal` or `solution` blob whose last byte is a length-prefix marker (e.g. `0xFC`) but which is truncated so that fewer trailing bytes exist than `prefix_len` requires, `clvm_buffer[offset]` in the loop will index past the end of the `bytes` object.

### Impact Explanation
In Python, this out-of-bounds `bytes` index raises an `IndexError` rather than reading adjacent process memory (Python bytes objects are bounds-checked), so this cannot leak memory the way the original NTPsec stack over-read could. However, this exception is not the intentionally-handled `ValueError` that `pre_validate_spendbundle()` / `validate_spend_bundle()` expects and converts to a `ValidationError`/`Err.INVALID_COIN_SOLUTION`; an uncaught `IndexError` propagating out of `validate_spend_bundle()` during mempool admission would surface as an unexpected exception in the full-node's transaction-processing path rather than a clean rejection, which is a potential spend-triggered halt/DoS of transaction processing for a single submitter-controlled input, matching the "spend-triggered transaction-processing halt" impact category in scope.

### Likelihood Explanation
Any unprivileged party who can submit a spend bundle (a wallet user, an RPC caller, or a mempool peer submitting `RespondTransaction`) fully controls the `puzzle_reveal` and `solution` bytes evaluated by `is_clvm_canonical()`/`is_atom_canonical()` for DEDUP-eligibility canonicalization checks in `validate_spend_bundle()`. Constructing such a truncated buffer (byte `0xFC` as the very last byte of the puzzle reveal or solution, with no trailing bytes) is trivial and requires no signature or fee to reach this code path during mempool admission.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before dereferencing `clvm_buffer[offset]` in the `for i in range(prefix_len)` loop (raise a `ValueError`/return non-canonical if `offset >= len(clvm_buffer)`), and ensure `is_clvm_canonical()` similarly validates that `offset` remains within bounds before every `clvm_buffer[offset]` access, so malformed/truncated buffers fail with the expected `ValueError` that `validate_spend_bundle()` already handles, instead of an uncaught `IndexError`.

### Proof of Concept
Construct a `CoinSpend` whose `solution` (or `puzzle_reveal`) serialized bytes end with the single byte `0xFC` (matching the `0b11111100` prefix pattern, which requires 5 additional length bytes) and provide zero trailing bytes, e.g. `solution_hex = "80fc"` (a NIL atom followed by the truncated length marker). Submitting this via `SpendBundle`/`push_tx` causes `validate_spend_bundle()` to call `is_clvm_canonical(bytes(coin_spend.solution))` → `is_atom_canonical(clvm_buffer, offset)`, which attempts `clvm_buffer[offset]` past the buffer end and raises `IndexError` instead of the expected `ValueError`, deviating from the intended `Err.INVALID_COIN_SOLUTION` handling path. def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
