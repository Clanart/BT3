## Title
Silent, unconfirmed rewrite of a repository's git remote URL from GitHub API data with no hostname validation - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

## Summary
The Curve `Swap.vy` finding is about a governance/ownership value that, once set, can never be safely rotated or re-validated, leaving no vetted path to update a trust-critical value. The closest real analog in GitHub Desktop is the inverse but related failure mode: a trust-critical value — the local repository's `origin` remote URL — is automatically rewritten by the app based on a value it receives from the GitHub API (`clone_url`), with a validation check that is too weak to guarantee the new value is safe, and with no user confirmation step.

## Finding Description
`updateRemoteUrl` in `app/src/lib/stores/updates/update-remote-url.ts` compares the local `git remote` URL against `apiRepo.clone_url` (data fetched from the GitHub API for the tracked `GitHubRepository`) and, if the remote hasn't been "manually changed" and the URL protocol still matches, silently calls `gitStore.setRemoteURL` to overwrite the user's configured remote: [1](#0-0) 

The only safety checks performed are:
1. `protocolsMatch` — comparing `URL.parse(remoteUrl).protocol` to `URL.parse(updatedRemoteUrl).protocol` [2](#0-1) 
2. `remoteUrlUnchanged` — checking the current remote still matches the *previously cached* `gitHubRepository.cloneURL` via `urlMatchesRemote` [3](#0-2) 

Neither check validates that the **hostname** of the new `clone_url` matches the expected GitHub/GHE endpoint hostname the repository was originally associated with. `urlMatchesRemote` is only used to detect whether the user manually edited the remote — it is never used to constrain what host the *new* URL can point to. As long as the scheme (`https:`/`https:`, or `ssh:`/`ssh:`) is unchanged, any hostname, port, or path returned by the API in `clone_url` will be written directly into the repository's git config via `git remote set-url`.

`clone_url` originates from a `IAPIRepository` object returned by the GitHub API/GHE server for the tracked repository (renames, transfers, or a compromised/malicious API response could change this value between refreshes), which is the class of attacker-controlled input in scope ("a GitHub API object").

## Impact Explanation
If the value returned for a repository's `clone_url` is attacker-influenced or spoofed (e.g., via a compromised/malicious GitHub Enterprise server, a man-in-the-middle on an Enterprise instance, or an attacker who gains transient control of a repository's metadata), Desktop will silently repoint the user's `origin` remote to a different host with the same protocol, without any dialog or confirmation. Subsequent `git push`/`git fetch`/`git pull` operations performed by the user — including credential negotiation for that remote — will be silently redirected to the attacker-controlled host. This falls squarely into "silent corruption of what the user commits or pushes" and "git remote/proxy response" attacker-controlled categories from the impact criteria, since the write path is an automatic, non-interactive `git remote set-url`.

## Likelihood Explanation
The check requires no local access, malware, or social engineering — it triggers automatically as part of normal repository refresh/update flow whenever `updateRemoteUrl` is invoked with the current `GitHubRepository`/API data. The weak guard (protocol-only comparison, not host comparison) means the existing invariant checks (`protocolsMatch`, `remoteUrlUnchanged`) do not stop a same-protocol, different-host URL from being accepted. I could not fully trace, within the remaining iterations, every call site in `app-store.ts` that invokes `updateRemoteUrl` (3 references found but not fully read) or precisely how/when the API response backing `apiRepo` is refreshed and whether server-side authorization API further constrains hosts; this uncertainty affects how directly a remote attacker (vs. a compromised/malicious GHE server operator) could trigger it in practice.

## Recommendation
In `updateRemoteUrl`, before calling `gitStore.setRemoteURL`, additionally validate that the hostname (and ideally owner/name) of `apiRepo.clone_url` matches the hostname of the `GitHubRepository`'s configured `endpoint`/API host, not just that the protocol is unchanged. Consider also surfacing a confirmation UI when the remote URL is programmatically changed by Desktop, rather than applying it silently.

## Proof of Concept
1. Track a repository whose `GitHubRepository.cloneURL` and current `origin` remote both point to `https://github.com/org/repo.git`.
2. Arrange for the next API refresh's `IAPIRepository.clone_url` to be `https://attacker-controlled-host/org/repo.git` (same `https:` scheme) — e.g., via a malicious/compromised GitHub Enterprise server, or any code path where this API object can be influenced.
3. `updateRemoteUrl` runs: `protocolsMatch` is `true` (both `https:`), `remoteUrlUnchanged` is `true` (user hasn't manually edited the remote), `urlsMatch` is `false` (different host) — all conditions in the `if` at [4](#0-3)  are satisfied.
4. `gitStore.setRemoteURL` is called, silently rewriting `origin` to the attacker host via `git remote set-url` [5](#0-4) , with no user prompt.

```typescript
  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
```

```typescript
  /** Changes the URL for the remote that matches the given name  */
  public async setRemoteURL(name: string, url: string): Promise<boolean> {
    const wasSuccessful =
      (await this.performFailableOperation(() =>
        setRemoteURL(this.repository, name, url)
      )) === true
    await this.loadRemotes()

    this.emitUpdate()
    return wasSuccessful
  }
```
