### Title
Unrecovered panic (Go type-assertion `CHECK`-fail analog) in the `pointer` precompile's CW20/CW721/CW1155 pointer-creation path via attacker-controlled query response shape - (File: precompiles/pointer/pointer.go)

### Summary
The `pointer` precompile's `AddCW20`, `AddCW721`, and `AddCW1155` executors query an arbitrary CosmWasm contract address supplied by the EVM caller, JSON-decode the response into `map[string]interface{}`, and then perform unchecked type assertions `formattedRes["name"].(string)` / `formattedRes["symbol"].(string)`. If the queried contract's `token_info`/`contract_info` response omits `name`/`symbol` or returns them as a non-string JSON value (number, bool, object, array, null), the assertion panics with `interface conversion: interface {} is nil, not string` (or similar). `RunAndCalculateGas` in `precompiles/common/precompiles.go`, which invokes `Execute`, has no `recover()` guarding this call, so the panic is unrecovered and propagates out of EVM execution.

### Finding Description
`addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` let any EVM caller register a pointer contract for an arbitrary CW20/CW721/CW1155 address they control. The precompile does a `wasmdKeeper.QuerySmartSafe` against that attacker-controlled contract and blindly decodes the JSON reply: [5](#0-4) [6](#0-5) [7](#0-6) 

Since the caller fully controls the target CW contract's code (they deploy/instantiate it themselves before calling the precompile), they can make its `token_info`/`contract_info` query handler return `{"name": 123, "symbol": {}}` or omit the fields entirely. `formattedRes["name"]` then holds a `float64`/`map[string]interface{}`/`nil`, and `.(string)` panics rather than returning `ok=false` (the two-value form is not used anywhere in this code).

The call chain is `Execute` → `AddCW20`/`AddCW721`/`AddCW1155` → panic, invoked from `RunAndCalculateGas`: [8](#0-7) 
which contains only a `defer` that calls `HandlePrecompileError` and rewrites a *returned error* into `vm.ErrExecutionReverted` — it does not `recover()` a panic. Consequently the panic keeps unwinding through the go-ethereum EVM interpreter and the Sei `ApplyMessage`/`DeliverTx` stack.

This mirrors the TensorFlow report's bug class exactly: an operation trusts the shape of externally-supplied data (there: `element_shape`; here: a JSON query response) and hits a hard-fail (`CHECK`/type-assertion panic) instead of a graceful error when the shape is violated — reachable purely from a normal, unprivileged transaction.

### Impact Explanation
An unrecovered panic during EVM message processing, if not caught by an outer recovery layer in `baseapp`/ante, causes the node to crash or the block processing goroutine to fail, which can produce a validator halt or non-deterministic outcomes across nodes if the ABCI panic-recovery middleware handles it differently pre/post-fix (some nodes might recover the panic into an error, others might crash if any panic bypasses the outer `recover`). At minimum this is a targeted denial-of-service: any address can permanently break the `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` call for their own crafted contract, and if the panic is not caught by `baseapp`'s tx-level recovery, it can halt block production entirely, since this precompile call is executed deterministically by every validator applying the same block — a panic that isn't uniformly recovered is a chain-halt/block-delay risk, satisfying the "validator halt / block delay beyond 2.5 seconds" bar.

### Likelihood Explanation
High feasibility: the attacker only needs to (1) instantiate a CW20/CW721/CW1155-like contract they fully control whose `token_info`/`contract_info` query handler returns a malformed `name` or `symbol` field, and (2) call `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` on the pointer precompile (`0x000000000000000000000000000000000000100b`) pointing at that contract. No special privileges, governance, or validator collusion are required — this is reachable from a single ordinary EVM transaction from any account.

### Recommendation
Replace every unchecked type assertion (`formattedRes["name"].(string)`, `formattedRes["symbol"].(string)`) with the two-value form (`name, ok := formattedRes["name"].(string)`) and return a normal `error` (causing `vm.ErrExecutionReverted`) when the assertion fails, in all three functions (`AddCW20`, `AddCW721`, `AddCW1155`) and their legacy versions under `precompiles/pointer/legacy/**/pointer.go`. As defense in depth, wrap `DynamicGasPrecompileExecutor.Execute` invocation inside `RunAndCalculateGas` (and the static `PrecompileExecutor.Execute` inside `Run`) with a `recover()` that converts any panic into a returned error, exactly as `chargeDecodeGas` already does for gas-meter panics, so that no single malicious/malformed external response (CW query result, or future similarly-shaped external data) can escape as an unrecovered panic out of EVM execution.

### Proof of Concept
1. Deploy/instantiate a CosmWasm contract `M` (fully attacker-controlled) whose query handler responds to `{"token_info":{}}` (or `{"contract_info":{}}`) with valid JSON that omits `name`/`symbol` or returns a non-string value for them, e.g. `{"decimals":6}` or `{"name":42,"symbol":42}`.
2. From any EVM account, call the `pointer` precompile at `0x000000000000000000000000000000000000100b`, method `addCW20Pointer(string cwAddr)` (or `addCW721Pointer`/`addCW1155Pointer`), with `cwAddr` set to `M`'s bech32 address.
3. Execution reaches `formattedRes["name"].(string)` in `precompiles/pointer/pointer.go` line 154 (or 186/218), which panics on the type assertion because the interface value is not a `string`.
4. Because `RunAndCalculateGas` in `precompiles/common/precompiles.go` does not `recover()` around `d.executor.Execute`, the panic propagates out of the precompile call into the EVM execution path, where its handling depends entirely on whatever outer recovery layer (if any) processes the current block/tx — a gap in that layer results in a node crash or chain halt rather than a normal reverted transaction.

```go
func (d DynamicGasPrecompile) RunAndCalculateGas(evm *vm.EVM, caller common.Address, callingContract common.Address, input []byte, suppliedGas uint64, value *big.Int, hooks *tracing.Hooks, readOnly bool, isFromDelegateCall bool) (ret []byte, remainingGas uint64, err error) {
	operation := fmt.Sprintf("%s_unknown", d.name)
	defer func() {
		HandlePrecompileError(err, evm, operation)
		if err != nil {
			fmt.Printf("precompile %s encountered error: %v\n", d.name, err)
			err = vm.ErrExecutionReverted
		}
	}()
	ctxer := state.GetDBImpl(evm.StateDB)
	if ctxer == nil {
		return nil, 0, errors.New("cannot get context from EVM")
	}
	// Resolve the target method from the 4-byte selector only. The argument
	// payload is intentionally NOT decoded yet: ABI decoding of attacker-
	// controlled calldata can cost far more than len(input) (a single string can
	// be referenced by many array/tuple slots), so it must be paid for out of the
	// gas the caller supplied. The static-precompile path charges RequiredGas in
	// vm.RunPrecompiledContract before running; that step is skipped for
	// dynamic-gas precompiles, so we apply the equivalent charge here.
	methodID, err := ExtractMethodID(input)
	if err != nil {
		return nil, 0, err
	}
	method, err := d.MethodById(methodID)
	if err != nil {
		return nil, 0, err
	}
	operation = method.Name

	ctx := ctxer.Ctx()
	// Install the gas meter derived from the supplied EVM gas, then charge for
	// decoding the calldata BEFORE decoding it. A call that cannot afford the
	// decode is rejected here, before the parse/allocation work is performed.
	// chargeDecodeGas scopes the out-of-gas recovery to just these charges, so an
	// executor that later exhausts its gas keeps its normal (propagating)
	// out-of-gas semantics.
	gasLimit := d.executor.EVMKeeper().GetCosmosGasLimitFromEVMGas(ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx)), suppliedGas)
	ctx = ctx.WithGasMeter(sdk.NewGasMeterWithMultiplier(ctx, gasLimit))
	if err = d.chargeDecodeGas(ctx, method, input); err != nil {
		return nil, 0, err
	}

	args, err := method.Inputs.Unpack(input[4:])
	if err != nil {
		return nil, 0, err
	}
	em := ctx.EventManager()
	ctx = ctx.WithEventManager(sdk.NewEventManager())
	ctx = ctx.WithEVMPrecompileCalledFromDelegateCall(isFromDelegateCall)
	ret, remainingGas, err = d.executor.Execute(ctx, method, caller, callingContract, args, value, readOnly, evm, suppliedGas, hooks)
	if err != nil {
		return ret, remainingGas, err
	}
	events := ctx.EventManager().Events()
	if len(events) > 0 {
		em.EmitEvents(ctx.EventManager().Events())
	}
	return ret, remainingGas, err
```
