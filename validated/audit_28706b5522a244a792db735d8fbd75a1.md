### Title
Malformed GeneratorProof map causes participant crash via unchecked `unwrap` - (File: crypto/dkg/promote/src/lib.rs)

### Summary
`GeneratorPromotion::complete` trusts that an attacker-controlled `HashMap<Participant, GeneratorProof<C1>>` containing `n - 1` entries contains every participant other than the local participant. It only bounds-checks participant IDs and then unconditionally unwraps each expected entry, allowing an omitted participant to trigger a panic. [1](#0-0) 

### Finding Description
`GeneratorPromotion::complete` requires `proofs.len() == n - 1`, but this count does not establish that the map contains all participants except `params.i()`. A map can include a proof for the local participant while omitting another valid participant. Because `Participant` keys are nonzero and each supplied key only has to satisfy `i <= n`, such a map passes both checks. During reconstruction, `proofs.get(&i).unwrap()` panics when the omitted participant is reached. [2](#0-1) 

The analogous flaw to CVE-2018-10323 is missing structural validation before dereferencing state derived from attacker-controlled input: here, a malformed participant/proof set causes an unwrap panic rather than a NULL-pointer dereference. [3](#0-2) 

### Impact Explanation
An unprivileged participant that supplies promotion proofs can cause the local generator-promotion operation to panic. In deployments where promotion is performed during key migration or protocol setup, this crashes the processing task or process and prevents completion of the protocol. [1](#0-0) 

### Likelihood Explanation
The attacker only has to cause the input map to contain `n - 1` in-range participant entries while omitting at least one required participant and optionally including the local participant instead. No invalid proof needs to verify because the panic occurs before the missing proof can be checked. [4](#0-3) 

### Recommendation
Before iterating over `1 ..= params.n()`, reject any proof keyed by `params.i()` and explicitly verify that every other participant is present. Replace `proofs.get(&i).unwrap()` with `proofs.get(&i).ok_or(PromotionError::MissingParticipant(i))` or an equivalent checked error. [5](#0-4) 

### Proof of Concept
For `params.n() == 3` and local `params.i() == 1`, submit a map with entries for participants `1` and `2`, while omitting participant `3`. The length check accepts the two entries and the range check accepts both keys, but the loop skips `1`, processes `2`, and panics at `proofs.get(&3).unwrap()`. [4](#0-3) 

```rust
// Conceptual PoC for params.i() = Participant(1), params.n() = 3.
let mut proofs = HashMap::new();
proofs.insert(Participant::new(1).unwrap(), own_or_dummy_proof);
proofs.insert(Participant::new(2).unwrap(), proof_from_2);
// Participant 3 is omitted even though proofs.len() == n - 1.
promotion.complete(&proofs); // panics at proofs.get(&Participant(3)).unwrap()
```

  pub fn complete(
    self,
    proofs: &HashMap<Participant, GeneratorProof<C1>>,
  ) -> Result<ThresholdKeys<C2>, PromotionError> {
    let params = self.base.params();
    if proofs.len() != (usize::from(params.n()) - 1) {
      Err(PromotionError::IncorrectAmountOfParticipants {
        t: params.n(),
        n: params.n(),
        amount: proofs.len() + 1,
      })?;
    }
    for i in proofs.keys().copied() {
      if u16::from(i) > params.n() {
        Err(PromotionError::InvalidParticipant { n: params.n(), participant: i })?;
      }
    }

    let mut verification_shares = HashMap::new();
    verification_shares.insert(params.i(), self.proof.share);
    for i in 1 ..= params.n() {
      let i = Participant::new(i).unwrap();
      if i == params.i() {
        continue;
      }

      let proof = proofs.get(&i).unwrap();
      proof
        .proof
        .verify(
          &mut transcript(&self.base.original_group_key(), i),
          &[C1::generator(), C2::generator()],
          &[self.base.original_verification_share(i), proof.share],
        )
        .map_err(|_| PromotionError::InvalidProof(i))?;
      verification_shares.insert(i, proof.share);
