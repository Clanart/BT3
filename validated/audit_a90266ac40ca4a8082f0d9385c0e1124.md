### Title
EVM Access Control Bypass via Signer-Privilege Escalation in Nested Calls - ([File: x/vm/types/permissions.go])

### Summary
The Cosmos EVM implements a permission policy to restrict contract creation and calls. However, the authorization logic in `RestrictedPermissionPolicy` prioritizes the transaction `signer`'s permissions over the immediate `caller`'s permissions. This allows a malicious or compromised contract, when called by a privileged EOA, to perform restricted operations (like deploying contracts or calling sensitive precompiles) that it should not be authorized to perform, leading to unauthorized state mutation.

### Finding Description
The vulnerability exists in the `permissionlessCheckFn` and `permissionedCheckFn` functions within `x/vm/types/permissions.go`. These functions are used to determine if an EVM operation (`CALL` or `CREATE`) is allowed based on the `AccessControl` parameters.

In `permissionedCheckFn`: [1](#0-0) 
The logic returns `true` if `isSignerAllowed` is true OR if the `caller` is in the address list. If a privileged EOA (the `signer`) calls a malicious contract, `isSignerAllowed` will be `true`. The malicious contract (the `caller`) can then execute `CREATE` or `CALL` opcodes that are restricted to the `AccessControlList`, effectively inheriting the EOA's privileges without explicit authorization for the contract itself.

Similarly, in `permissionlessCheckFn`: [2](#0-1) 
The operation is allowed if the `signer` is NOT blocked AND the `caller` is NOT blocked. This means a blocked contract can still perform restricted actions if it is invoked via a `DELEGATECALL` or similar context where the `signer` is used for the check but the `caller` logic is bypassed by the "OR" or "AND" combination of privileges.

### Impact Explanation
This is a **Critical** vulnerability because it allows **unauthorized state mutation** and **privilege escalation**. An unprivileged contract can "trick" a privileged user into interacting with it, and then use that user's authority to:
1. Deploy unauthorized contracts (bypassing `AccessTypePermissioned` for `CREATE`).
2. Call restricted precompiles (e.g., `Bank`, `Staking`, `Gov`) to move funds, change validator sets, or alter governance, provided the EOA has those rights.
This violates the core security invariant that contract execution should be sandboxed and only exercise permissions explicitly granted to the contract's own identity in the current call frame.

### Likelihood Explanation
The likelihood is medium. It requires a chain configuration where `AccessControl` is set to `RESTRICTED` or `PERMISSIONED` (which is a primary feature of this repo for "Permissioned EVM" use cases). An attacker would need to social-engineer a privileged user into calling their contract or find a way to trigger a call from a privileged context.

### Recommendation
Modify `permissionedCheckFn` and `permissionlessCheckFn` to enforce that **both** the `signer` and the `caller` must satisfy the permission requirements. The check should be an "AND" for allowed lists and an "OR" for blocked lists (i.e., if either is blocked, the action is denied).

### Proof of Concept
1. The chain is configured with `AccessControl.Create.AccessType = ACCESS_TYPE_PERMISSIONED`.
2. Only `Admin_EOA` is in the `AccessControlList` for `Create`.
3. `Attacker_Contract` is deployed (it does not have `Create` permissions).
4. `Admin_EOA` sends a transaction calling `Attacker_Contract.exploit()`.
5. Inside `exploit()`, the contract executes the `CREATE` opcode.
6. The `CreateHook` is triggered:
   - `signer` is `Admin_EOA` (isSignerAllowed = true).
   - `caller` is `Attacker_Contract`.
7. `permissionedCheckFn` returns `true` because `isSignerAllowed` is `true`.
8. `Attacker_Contract` successfully deploys a new contract despite not being in the `AccessControlList`.

func permissionlessCheckFn(addresses []string, signer common.Address) callerFn {
	strSigner := signer.String()
	isSignerBlocked := !slices.Contains(addresses, strSigner)
	return func(caller common.Address) bool {
		strCaller := caller.String()
		return isSignerBlocked && !slices.Contains(addresses, strCaller)
	}

func permissionedCheckFn(addresses []string, signer common.Address) callerFn {
	strSigner := signer.String()
	isSignerAllowed := slices.Contains(addresses, strSigner)
	return func(caller common.Address) bool {
		strCaller := caller.String()
		return isSignerAllowed || slices.Contains(addresses, strCaller)
	}
