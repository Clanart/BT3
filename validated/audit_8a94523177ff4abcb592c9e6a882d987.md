### Title
SSRF-class flaw: attacker-controlled DataLayer mirror URLs are dereferenced by victim DataLayer nodes without any host/scheme restriction - ([File: chia/data_layer/download_data.py])

### Summary
Any wallet participant can create a DataLayer "mirror" coin whose memo payload embeds an arbitrary URL string for a given `launcher_id`/store. Any peer that tracks/subscribes to that store persists this attacker-chosen URL as a `ServerInfo.url`, and the DataLayer sync loop later issues an outbound HTTP GET directly to `server_info.url + "/" + filename` with no validation of scheme, host, or destination address — the same bug class as CVE-2022-41497 (SSRF via an unsanitized URL parameter used to construct an outbound request).

### Finding Description
`create_mirror_puzzle()` / `get_mirror_info()` in `chia/wallet/db_wallet/db_wallet_puzzles.py` extract a `launcher_id` and a list of raw URL bytes straight from the `CREATE_COIN` memo of a spend that creates a mirror-puzzle coin, with zero validation of the URL contents: [1](#0-0) 

This is consumed in `DataLayerWallet.coin_added()`, which — as soon as the corresponding `launcher_id` is a tracked store — stores the attacker-supplied URLs verbatim via `dl_store.add_mirror()`: [2](#0-1) 

Later, `DataLayer.fetch_and_validate()` pulls candidate server URLs for a store via `data_store.get_available_servers_for_store()`, shuffles them, and for each iterates calling `insert_from_delta_file()` with that `server_info` (unvalidated URL): [3](#0-2) 

`insert_from_delta_file()` calls `download_file()`, which (absent a configured plugin downloader) calls `http_download()`: [4](#0-3) 

`http_download()` performs an unrestricted `aiohttp` GET straight to the attacker-controlled URL concatenated with a filename, with no allowlist, no scheme check, and no blocking of loopback/link-local/internal network ranges: [5](#0-4) 

The internal module documentation explicitly flags this as a known trust boundary ("Mirror URLs, plugins, or static file names" are not trusted data sources, yet must still be dereferenced by the sync loop), confirming this is the intended (and unresolved) attack surface rather than a hypothetical: [6](#0-5) [7](#0-6) 

### Impact Explanation
Any user who can submit a spend that creates a DataLayer mirror coin (a normal, unprivileged wallet action available to anyone with a small amount of XCH, requiring no special role) can plant an arbitrary URL — e.g. `http://169.254.169.254/latest/meta-data/`, `http://127.0.0.1:<internal-port>/`, or an internal-network address — that a victim's DataLayer service will later fetch when it syncs/subscribes to the associated store. Because the request is a real outbound `GET` (not sandboxed), this allows internal network reconnaissance/probing, interaction with cloud metadata services, or use of the DataLayer node as a proxy against arbitrary hosts/ports reachable from the node's network position. The response is only rejected downstream if it fails Merkle-root validation, but the SSRF request itself (and any side effects on the target from being hit, e.g. non-idempotent internal endpoints) already occurs before that check.

### Likelihood Explanation
Likelihood is high for any environment where DataLayer subscriptions are used: creating a mirror coin is a normal, permissionless wallet operation, and `coin_added()` unconditionally records any URL embedded in the memo for tracked launchers — there is no on-chain or off-chain filtering of the URL value before it becomes a `ServerInfo` used by the fetch loop.

### Recommendation
Validate and restrict mirror/server URLs before they are persisted (`add_mirror`) and before they are dereferenced in `http_download`/`get_downloader`/`get_uploaders`: enforce an `https://` (or otherwise allow-listed) scheme, resolve and reject requests to loopback, link-local, multicast, and RFC1918 private ranges (unless explicitly operator-allowed), and consider making outbound mirror fetches opt-in / requiring explicit user confirmation per store, similar to the existing enforced-HTTPS check used for pool URLs in `chia/cmds/plotnft_funcs.py`.

### Proof of Concept
1. Attacker creates a DataLayer mirror coin for a `launcher_id` corresponding to a store the victim tracks, spending the mirror puzzle with a `CREATE_COIN` condition whose memos encode `launcher_id` followed by `b"http://169.254.169.254"` (per `get_mirror_info()` decoding in `chia/wallet/db_wallet/db_wallet_puzzles.py:97-110`).
2. Victim's `DataLayerWallet.coin_added()` observes the mirror coin, sees the launcher is tracked, and calls `dl_store.add_mirror()` with the attacker URL (`chia/data_layer/data_layer_wallet.py:775-800`).
3. On the next sync cycle, `DataLayer.fetch_and_validate()` selects this server info and calls `insert_from_delta_file()` → `download_file()` → `http_download()`, causing the victim node to issue `GET http://169.254.169.254/<filename>` (`chia/data_layer/download_data.py:298-319`).
4. The victim's file-download attempt fails Merkle-root validation and is discarded, but the outbound SSRF request has already been made against the attacker-chosen internal target.

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
```
