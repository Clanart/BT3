### Title
`TextFormat::Printer::PrintAny` emits the attacker-controlled `Any.type_url` unescaped, bypassing TextFormat's string-escaping invariant - (File: `src/google/protobuf/text_format.cc`)

### Summary
Every ordinary `string`/`bytes` field printed by `TextFormat` is escaped through `FastFieldValuePrinter::PrintString`, which calls `absl::CEscape` whenever the value contains control characters, quotes, backslashes, or non-printable bytes. [3](#0-2)  `TextFormat::Printer::PrintAny`, however, is a special-cased code path for `google.protobuf.Any` messages: it pulls `type_url` directly out of the message via `reflection->GetString(message, type_url_field)` and writes it out using `generator->PrintString(type_url)`, which is `BaseTextGenerator::PrintString` — a literal byte pass-through with zero escaping. [4](#0-3) [1](#0-0)  The same unescaped pattern exists in the Java implementation's `printAny`, which does `generator.print(typeUrl)` directly. [5](#0-4) 

### Finding Description
`Any.type_url` is a plain proto3 `string` field with no format restriction enforced at the wire/parse layer beyond being valid UTF-8; the `.proto` comment only documents an expected `scheme://host/full.type.Name` convention but this is not validated by the parser. [6](#0-5)  A client can therefore construct a bounded, valid binary-encoded `Any` message whose `type_url` string contains arbitrary bytes, including ASCII control characters such as `\r`, `\x1b` (ESC, used to start ANSI/VT100 escape sequences), backspace, or bell.

When such a message is later rendered by any consumer that calls `Message::DebugString()`, `ShortDebugString()`, `Utf8DebugString()`, or `TextFormat::PrintToString()`/`Print()` with `expand_any_` enabled (the default), `PrintAny` is invoked. It writes `[` + raw `type_url` + `]` via `generator->PrintString(type_url)`, which performs no escaping at all — unlike every other string field, which goes through `FastFieldValuePrinter::PrintString`'s `CEscape` path, or `HardenedPrintString`'s UTF-8-aware escaping used by the UTF-8-escaping printer variant. [7](#0-6) [8](#0-7)  The missing invariant is exactly the one Helm's advisory identifies: any string value that can end up in a "for human eyes" text stream must be sanitized before being written, and this code path skips that step for `type_url`.

This is a genuine gap in TextFormat's own hardening effort — `text_format.cc` explicitly built `HardenedPrintString`/`DefinitelyNeedsEscape`/`SkipPassthroughBytes` machinery specifically to guard against exactly this class of issue for ordinary string fields, but `PrintAny` was not routed through it.

### Impact Explanation
Any application that logs, prints to a terminal, or displays `Message::DebugString()` output for messages containing (possibly nested/repeated) `google.protobuf.Any` fields is exposed to terminal escape-sequence and log-injection attacks from an ordinary, schema-valid message an untrusted client can construct and send through any binary/ProtoJSON parse API. Concretely this enables: obscuring/forging log lines, clearing/manipulating a terminal (as called out explicitly in the Helm advisory), or injecting spoofed OSC/CSI sequences into terminals that interpret them (some terminal emulators execute higher-order escape sequences, e.g. changing window titles or, in vulnerable terminal/log-viewer combinations, worse). This matches CWE-74/"Improper Neutralization of Special Elements in Output" and mirrors the Helm CVE-2021-21303 impact class, though scoped to consuming applications that display TextFormat DebugString output rather than to Protobuf itself providing an RPC surface.

### Likelihood Explanation
The trigger requires only a legally-encoded binary protobuf message with a crafted `type_url` string on an `Any` submessage — no malformed wire data, no huge payloads, no privileged access, and no schema/plugin trust violation. Any public API accepting untrusted `Any`-containing messages and later debug-printing them for logging/diagnostics reaches this path by default, since `expand_any_`/Any-expansion is the default behavior of `DebugString()`/`ShortDebugString()`. This makes the likelihood moderate-to-high wherever DebugString-style output of attacker-influenced messages reaches a terminal or a naive log viewer that interprets control sequences.

### Recommendation
Route `type_url` through the same escaping path used for ordinary string fields (`FastFieldValuePrinter::PrintString`'s `CEscape` logic or `HardenedPrintString`) inside `TextFormat::Printer::PrintAny` (and the equivalent Java/Python/C# `printAny`/`_TryPrintAsAnyMessage` implementations), rather than calling `generator->PrintString(type_url)` / `generator.print(typeUrl)` directly on the raw value.

### Proof of Concept
1. Construct (in trusted generated code, e.g. C++) an `Any` message with `type_url = "type.googleapis.com/foo.Bar\x1b[2Jmalicious"` and `value` set to any valid serialized bytes for a registered/known type (e.g. an empty message), so it parses successfully.
2. Serialize this `Any` to bytes (bounded, valid binary protobuf) and have it received via a normal `ParseFromString`/`ParseFromArray` call, embedded as a field of some outer message.
3. Call `outer_message.DebugString()` (or `ShortDebugString()`), which internally invokes `TextFormat::Printer::PrintAny`.
4. Observe that the resulting string contains the raw, unescaped `\x1b[2J` (or `\r`, `\n`, etc.) sequence embedded in the `[type_url]` bracket, in contrast to how the same bytes would be rendered (escaped as `\033[2J`) if placed in an ordinary `string` field of the same message. Displaying this string on a terminal (e.g. via `printf`, `std::cout`, or a naive log viewer) executes/interprets the injected escape sequence.

void TextFormat::Printer::HardenedPrintString(
    absl::string_view src, TextFormat::BaseTextGenerator* generator) {
  // Print as UTF-8, while guarding against any invalid UTF-8 in the string
  // field.
  //
  // If in the future we have a guaranteed invariant that invalid UTF-8 will
  // never be present, we could avoid the UTF-8 check here.

  generator->PrintLiteral("\"");
  while (!src.empty()) {
    size_t n = SkipPassthroughBytes(src);
    if (n != 0) {
      generator->PrintString(src.substr(0, n));
      src.remove_prefix(n);
      if (src.empty()) break;
    }

    // If repeated calls to CEscape() and PrintString() are expensive, we could
    // consider batching them, at the cost of some complexity.
    generator->PrintString(absl::CEscape(src.substr(0, 1)));
    src.remove_prefix(1);
  }
  generator->PrintLiteral("\"");
}

namespace {

bool ContainsCharactersToCEscape(absl::string_view val) {
  bool needs_escape = false;
  for (unsigned char c : val) {
    needs_escape |=
        ((c < 32) | (c > 126) | (c == '"') | (c == '\'') | (c == '\\'));
  }
  return needs_escape;
}
