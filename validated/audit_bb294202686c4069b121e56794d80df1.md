Based on the investigation, I did not find a code-execution-outside-repo, credential-exfiltration, or IPC/sandbox-escape analog tied to a "missing deadline/stale execution" pattern. However, I found the closest structural analog: an attacker-controlled deep link that causes Desktop to silently mutate the state of an *already cloned* repository (fetch + branch checkout) with no user confirmation and no check that the resulting action still matches the user's current intent/context — the same "unconfirmed action executed on stale/attacker-influenced conditions" root cause as the reported "missing deadline" bug.

### Title
Deep link `openRepo` action silently fetches and checks out an attacker-chosen branch in an existing local repository without user confirmation - ([File: app/src/ui/dispatcher/dispatcher.ts])

### Summary
GitHub Desktop registers custom protocol handlers (`x-github-client`, `github-mac`, `github-windows`) that any web page or link can invoke. When the URL action is `openRepo` with a `branch` parameter and the `url` matches a repository the user already has cloned, `openBranchNameFromUrl` fetches from the remote and checks out the attacker-specified branch automatically, with no dialog asking the user to confirm the checkout.

### Finding Description
`parseAppURL` accepts an `openrepo://` URL with a `branch` query parameter, only validating that it doesn't contain characters rejected by `testForInvalidChars` [1](#0-0) . This action flows to `dispatchURLAction` → `openRepositoryFromUrl` → `openBranchNameFromUrl` [2](#0-1) .

Inside `openBranchNameFromUrl`, `openOrCloneRepository(url)` is called first. If the URL matches the origin or upstream `htmlURL` of a repository the user already has open in Desktop (via `doesRepositoryMatchUrl`/`urlsMatch`), the *existing* local repository is returned instead of prompting a clone [3](#0-2)  and [4](#0-3) . Desktop then unconditionally refreshes, fetches, and checks out the attacker-supplied `branchName` on that repository: [5](#0-4) 

No popup, prompt, or "are you sure" confirmation is shown to the user before the fetch+checkout is performed — unlike the "Clone Repository" popup path used for repos that aren't already present [6](#0-5) . Because this is reachable purely by getting the user to click a link (browser, chat client, email, README), the attacker fully controls the `branch` parameter and, by controlling content on the matching remote (e.g., a public/shared repo, a fork with a same-named `origin`, or any repo where the attacker can push a branch), can force Desktop to silently switch the user's working directory to attacker-controlled branch content. This mirrors the reported bug class: a triggerable action carries no "is this still what the user wants / is this still safe" check, so it executes later, silently, against conditions the attacker can shape in the interim — the local equivalent of a stale flash-swap executing after the pool price has moved.

### Impact Explanation
A forced, unconfirmed checkout to an attacker-chosen branch can overwrite files in the user's working directory with attacker content and lay the groundwork for further compromise (e.g., a subsequent build/run of the checked-out code, or repo-level git hooks/config files being switched in). It can also silently discard/hide the user's current work context (changing HEAD without an explicit user click on "checkout"), which fits the "silent corruption of what the user commits or pushes" impact category.

### Likelihood Explanation
Requires no local access, malware, or credentials — only that the victim clicks a crafted `x-github-client://openRepo/...?branch=...` link while already having the target repository cloned in Desktop, which is a realistic and common Desktop workflow (the protocol is designed for exactly this "Open in Desktop" use case).

### Recommendation
Require explicit user confirmation (a dialog naming the target repository and branch) before performing a fetch + checkout triggered by a protocol/deep-link action, especially when the target is an already-open repository rather than a fresh clone. Additionally, verify no uncommitted changes would be silently discarded before checkout.

### Proof of Concept
1. Victim has cloned `https://github.com/acme/webapp` in Desktop.
2. Attacker hosts a link: `x-github-client://openRepo/https://github.com/acme/webapp?branch=malicious-branch` (or embeds it in a webpage/email).
3. Attacker has pushed (or controls) a branch `malicious-branch` on that same remote (e.g., via a permitted fork/PR branch or a repo where attacker has push access).
4. Victim clicks the link; Desktop matches the existing local repo via `doesRepositoryMatchUrl`, fetches, and calls `checkoutLocalBranch` automatically — no confirmation dialog appears, and the user's working directory is now on the attacker's branch.

Note: I was unable to inspect the exact implementation of `checkoutLocalBranch` in `dispatcher.ts` due to running out of tool calls, so I cannot confirm additional safeguards (e.g., dirty-worktree checks) that might partially mitigate this within that specific function; this should be verified in a follow-up review.

  private doesRepositoryMatchUrl(
    repo: Repository | CloningRepository,
    url: string
  ): repo is RepositoryWithGitHubRepository {
    if (repo instanceof Repository && isRepositoryWithGitHubRepository(repo)) {
      const originRepoUrl = repo.gitHubRepository.htmlURL
      const upstreamRepoUrl = repo.gitHubRepository.parent?.htmlURL ?? null

      if (originRepoUrl !== null && urlsMatch(originRepoUrl, url)) {
        return true
      }

      if (upstreamRepoUrl !== null && urlsMatch(upstreamRepoUrl, url)) {
        return true
      }
    }

    return false
  }

  private async openRepositoryFromUrl(action: IOpenRepositoryFromURLAction) {
    const { url, pr, branch, filepath } = action

    let repository: Repository | null

    if (pr !== null) {
      repository = await this.openPullRequestFromUrl(url, pr)
    } else if (branch !== null) {
      repository = await this.openBranchNameFromUrl(url, branch)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      return
    }

    if (filepath !== null) {
      if (isAbsolute(filepath)) {
        log.error(`Refusing to open absolute path: ${filepath}`)
        return
      }

      const resolved = await resolveWithin(repository.path, filepath)

      if (resolved !== null) {
        shell.showItemInFolder(resolved)
      } else {
        log.error(
          `Prevented attempt to open path outside of the repository root: ${filepath}`
        )
      }
    }
  }

  private async openBranchNameFromUrl(
    url: string,
    branchName: string
  ): Promise<Repository | null> {
    const repository = await this.openOrCloneRepository(url)

    if (repository === null) {
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    // if the repo has a remote, fetch before switching branches to ensure
    // the checkout will be successful. This operation could be a no-op.
    await this.appStore._fetch(repository, FetchType.UserInitiatedTask)

    await this.checkoutLocalBranch(repository, branchName)

    return repository
  }

    const repositories = state.repositories
