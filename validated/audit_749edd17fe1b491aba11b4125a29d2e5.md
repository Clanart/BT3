### Title
Unauthenticated `ReceivedOutput` deserialization accepts arbitrary UTXO ownership claims - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput::read` accepts an attacker-controlled scalar offset, `TxOut`, and `OutPoint` without proving that the encoded output was produced by `Scanner` or exists on Bitcoin. [1](#0-0)  Legitimate outputs are derived only when `scan_transaction` finds a previously registered `script_pubkey` and stores its associated offset. [2](#0-1) 

### Finding Description
The parsed `offset` is treated as the authority linking `output.script_pubkey` to a threshold-key derivation, but deserialization performs no equivalent lookup in `Scanner::scripts` and does not validate the claimed outpoint against the chain. [3](#0-2)  `SignableTransaction::new` then trusts the supplied output amount as input value and the supplied outpoint as the transaction input. [4](#0-3) 

The later `multisig` check verifies only that `group_key + offset*G` produces the embedded `script_pubkey`; it does not verify that the `OutPoint` exists or that its on-chain `TxOut` equals the deserialized `TxOut`. [5](#0-4) 

### Impact Explanation
An attacker can fabricate bytes naming a nonexistent or mismatched UTXO while selecting a script consistent with the claimed offset. The result is a `ReceivedOutput` reported as spendable and accepted into transaction construction even though no corresponding spendable Bitcoin output exists, satisfying the false-received-funds condition. [6](#0-5) [7](#0-6) 

### Likelihood Explanation
The required input is only untrusted serialized wallet data; no validator key, threshold share, RPC access, or malformed cryptographic object is required. The attacker must induce the wallet to consume forged `ReceivedOutput` bytes rather than bytes produced by an authenticated `Scanner::scan_transaction` result. [1](#0-0) 

### Recommendation
Do not expose `ReceivedOutput::read` as an unauthenticated ownership constructor. Either require the expected base key/scanner registry during deserialization and verify `output.script_pubkey == p2tr_script_buf(base_key + offset*G)` for a registered offset, or serialize outputs with authenticated metadata and verify the claimed `OutPoint` and `TxOut` against a trusted UTXO view before use. [8](#0-7) 

### Proof of Concept
1. Let `K` be the victim wallet's even Taproot group key and construct `victim_script = p2tr_script_buf(K)`.
2. Serialize:
   - a 32-byte zero scalar for `offset`;
   - a consensus-encoded `TxOut { value: attacker_chosen_amount, script_pubkey: victim_script }`;
   - a consensus-encoded `OutPoint` with a fabricated transaction ID and `vout`.
3. Pass those bytes to `ReceivedOutput::read`; the function returns `Ok` without checking the outpoint. [3](#0-2) 
4. Pass the resulting object to `SignableTransaction::new`; its amount and outpoint are incorporated into the proposed spend. [4](#0-3) 
5. `multisig` accepts the forged object because `K + 0*G` matches `victim_script`, despite the referenced UTXO being nonexistent or inconsistent with the encoded amount. [5](#0-4)

/// A transaction scanner capable of being used with HDKD schemes.
#[derive(Clone, Debug)]
pub struct Scanner {
  key: ProjectivePoint,
  scripts: HashMap<ScriptBuf, Scalar>,
}

impl Scanner {
  /// Construct a Scanner for a key.
  ///
  /// Returns None if this key can't be scanned for.
  pub fn new(key: ProjectivePoint) -> Option<Scanner> {
    let mut scripts = HashMap::new();
    scripts.insert(p2tr_script_buf(key)?, Scalar::ZERO);
    Some(Scanner { key, scripts })
  }

  /// Register an offset to scan for.
  ///
  /// Due to Bitcoin's requirement that points are even, not every offset may be used.
  /// If an offset isn't usable, it will be incremented until it is. If this offset is already
  /// present, None is returned. Else, Some(offset) will be, with the used offset.
  ///
  /// This means offsets are surjective, not bijective, and the order offsets are registered in
  /// may determine the validity of future offsets.
  ///
  /// The offsets registered must be securely generated. Arbitrary offsets may introduce a script
  /// path into the output, allowing the output to be spent by satisfaction of an arbitrary script
  /// (not by the signature of the key).
  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {

    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
