### Title
Unauthenticated on-chain SSRF via DataLayer mirror URLs - (File: chia/data_layer/data_layer_wallet.py)

### Summary
DataLayer mirror coins let any XCH holder publish an arbitrary attacker-chosen URL on-chain that is memo-bound to a store's launcher id. Any node that syncs/subscribes to that DataLayer store will automatically parse the URL from the mirror coin and later have its DataLayer service issue outbound `aiohttp` HTTP requests to it, with no validation of scheme, host, or destination (no blocking of loopback/link-local/private ranges). This mirrors the CVE-2019-6793 bug class: an unauthenticated/unprivileged actor supplies a URL that causes a victim's server component to make a blind outbound request.

### Finding Description
The mirror puzzle is a well-known, uncurried puzzle hash (`create_mirror_puzzle()` = `P2_PARENT.curry(1)`), and creating a mirror coin only requires a `CREATE_COIN` condition to that puzzle hash with `memos = [launcher_id, *urls]`: [1](#0-0) 

Any wallet user (or in principle any spend-bundle submitter who controls a coin) can build this exact condition without going through `dl_new_mirror` RPC validation, since the puzzle/memo format is public and requires no signature check tied to store ownership, only ownership of the coin being spent.

When any other node is tracking that launcher id, `DataLayerWallet.coin_added` decodes the mirror coin's parent spend and extracts `launcher_id, urls` directly from the attacker-controlled memos, then persists them as a `Mirror` record with no URL sanitization: [2](#0-1) [3](#0-2) 

The DataLayer service then pulls these mirror URLs via wallet RPC and merges them into the store's subscription server list without any allow-list/deny-list or private-network filtering: [4](#0-3) 

Those URLs are subsequently used to issue outbound HTTP requests during normal background sync (`fetch_and_validate`, `get_downloader`, `upload_files`) using `aiohttp.ClientSession`, with the destination host taken verbatim from the attacker-supplied memo: [5](#0-4) [6](#0-5) [7](#0-6) 

No component along this path (memo decoding, `Mirror` storage, subscription URL merge, or `aiohttp` request construction) restricts the URL to public/expected mirror hosts, rejects `localhost`/private IPs, or restricts scheme.

### Impact Explanation
Any party who can push a mirror coin on-chain for a DataLayer store id (which only requires spending an owned coin — no relationship to the store owner is required) can cause every peer's DataLayer node that subscribes/tracks that store to make blind outbound HTTP requests to attacker-chosen destinations. This is a classic blind SSRF: it can be used to probe/attack internal services reachable from the victim node (local RPC ports, cloud metadata endpoints, internal HTTP services), or as an amplification/DoS vector by pointing many mirrors at a victim IP. Because response bodies are only loosely validated (`res_json["handle_download"]`/`res_json["downloaded"]`) and are otherwise best-effort/logged, the requests are "fire-and-forget," matching a blind SSRF profile. This does not directly allow coin theft or consensus divergence, capping severity at Medium/High rather than Critical.

### Likelihood Explanation
Likelihood is high for any user running the DataLayer service who subscribes to third-party stores or lets `add_mirror`/discovery pick up mirrors automatically — this is a normal, expected DataLayer workflow (subscribing to a store and letting `periodically_manage_data()` sync mirrors). No special privilege beyond owning a coin and constructing a `CREATE_COIN` condition to the mirror puzzle with attacker URLs is required to plant the malicious mirror.

### Recommendation
- Validate mirror/downloader/uploader URLs before use: enforce `http`/`https` scheme, resolve and reject requests to loopback, link-local, and RFC1918 private ranges (and cloud metadata IPs) unless explicitly allow-listed by the operator.
- Consider requiring operator opt-in / an allow-list for which mirror hosts a DataLayer node will actually contact, rather than trusting all urls decoded from arbitrary on-chain memos.
- Apply the same validation to `PluginRemote` uploader/downloader URLs configured via mirrors, and to `get_downloader`/`upload_files`/`fetch_and_validate` request targets.

### Proof of Concept
1. Attacker crafts a spend of any XCH coin they own with a `CREATE_COIN` condition to `create_mirror_puzzle().get_tree_hash()` amount arbitrary, memo `[victim_store_launcher_id, b"http://169.254.169.254/latest/meta-data/"]` (or `http://127.0.0.1:<internal-port>/...`), per `create_new_mirror` construction: [1](#0-0) .
2. Attacker submits this spend bundle to the mempool; it needs no relationship to the store owner and is accepted as a normal coin spend.
3. Any node that already tracks/subscribes to `victim_store_launcher_id` observes the mirror coin, decodes the URL via `get_mirror_info` and stores it as a `Mirror`: [2](#0-1) .
4. On its next `periodically_manage_data()` cycle, that node's DataLayer service calls `update_subscriptions_from_wallet` → `fetch_and_validate`, issuing an outbound `aiohttp` request to the attacker-chosen URL: [8](#0-7) [9](#0-8) .

def create_mirror_puzzle() -> Program:
    return P2_PARENT.curry(Program.to(1))


MIRROR_PUZZLE_HASH = create_mirror_puzzle().get_tree_hash()


def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")

    async def get_downloader(self, store_id: bytes32, url: str) -> PluginRemote | None:
        request_json = {"store_id": store_id.hex(), "url": url}
        for d in self.downloaders:
            async with aiohttp.ClientSession() as session:
                try:
                    async with session.post(
                        d.url + "/handle_download",
                        json=request_json,
                        headers=d.headers,
                        timeout=self.client_timeout,
                    ) as response:
                        res_json = await response.json()
                        if res_json["handle_download"]:
                            return d
                except Exception as e:
                    self.log.error(f"get_downloader could not get response: {type(e).__name__}: {e}")
        return None

        uploaders = []
