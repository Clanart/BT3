## Title
Symlink-following write in `saveGitIgnore` allows out-of-repo file overwrite via a malicious cloned repository - (File: `app/src/lib/git/gitignore.ts`)

### Summary
`saveGitIgnore` resolves the on-disk `.gitignore` path with `Path.join(repository.path, '.gitignore')` and passes it straight to Node's `fs/promises` `writeFile`/`FS.unlink`, without checking whether that path is (or resolves through) a symlink. [1](#0-0) 
`FS.writeFile`/`unlink` in Node follow symlinks by default (no `O_NOFOLLOW`), so if `.gitignore` in the working tree is a symlink to a path outside the repository, the write/delete is redirected to that external target.

### Finding Description
A repository committed with `.gitignore` as a symlink (git blob mode `120000`) pointing to a file outside the working directory (e.g. `../../.bashrc`, `~/.ssh/authorized_keys`, another repo's `.git/hooks/pre-commit`) will, on clone (macOS/Linux with `core.symlinks=true`, the default), materialize an actual filesystem symlink at `<repo>/.gitignore`.
When the user opens **Repository Settings → Ignored Files** (backed by `GitIgnore` in `app/src/ui/repository-settings/git-ignore.tsx`) and clicks Save, `saveGitIgnore` is invoked with `repository.path` unmodified. [2](#0-1) 
Because `Path.join` does not canonicalize/verify the resulting path against symlink traversal, and `writeFile`/`FS.unlink` transparently dereference the final path component, the write (or, if the user clears the ignore rules, the `FS.unlink` delete) lands on the attacker-chosen target rather than a file scoped to the repository. [3](#0-2) 
No symlink canonicalization/verification exists anywhere in this module or its callers (`appendIgnoreRule`, `appendIgnoreFile`) — a repo-wide search for `symlink` handling turned up none relevant to this code path.

### Impact Explanation
This gives an attacker who controls repository content (a cloned/fetched repo) the ability to overwrite or delete an arbitrary file writable by the current user outside the repository, once the victim performs an ordinary, expected action (editing/saving `.gitignore` via Repository Settings, or the “ignore this file” convenience actions that call `appendIgnoreFile`/`appendIgnoreRule`, which internally call `saveGitIgnore`). Depending on the target chosen by the attacker (shell rc files, SSH config, other project files, `.git/hooks`), this can escalate to code execution or persistent compromise, matching the "file write outside the repo" valid-impact category.

### Likelihood Explanation
Requires the victim to interact with the gitignore editor/append feature after cloning a malicious repository containing a symlinked `.gitignore` — this is a normal, expected user action, not an unnatural step. The primary constraint is platform: on Windows, Git typically requires Developer Mode/admin privilege to create real symlinks and otherwise checks out a plain-text placeholder file, reducing exploitability there; on macOS/Linux with default `core.symlinks=true`, the symlink is created as-is, making the attack directly viable.

### Recommendation
Before writing to (or unlinking) `.gitignore`, resolve the path with `fs.lstat`/`fs.realpath` and verify it is not a symlink (or that its real path still resolves inside `repository.path`); reject/refuse the operation (or write via an `O_NOFOLLOW`-based file descriptor) if a symlink pointing outside the repository is detected.

### Proof of Concept
1. Create a repository containing `.gitignore` as a symlink: `ln -s /tmp/outside-target .gitignore && git add .gitignore && git commit -m "evil gitignore"`.
2. Clone this repository on macOS/Linux with GitHub Desktop.
3. Open the repository in Desktop, go to Repository Settings → Ignored Files, add/modify an ignore rule, click Save (triggers `saveGitIgnore`).
4. Inspect `/tmp/outside-target` — its contents have been overwritten with the new gitignore text, confirming the write escaped the repository directory.

```typescript
export async function saveGitIgnore(
  repository: Repository,
  text: string
): Promise<void> {
  const ignorePath = Path.join(repository.path, '.gitignore')

  if (text === '') {
    return new Promise<void>((resolve, reject) => {
      FS.unlink(ignorePath, err => {
        if (err) {
          reject(err)
        } else {
          resolve()
        }
      })
    })
  }

  const fileContents = await formatGitIgnoreContents(text, repository)
  await writeFile(ignorePath, fileContents)
```
