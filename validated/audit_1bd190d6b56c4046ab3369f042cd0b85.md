### Title
Native ERC20 pointer decimals can be silently changed post-deployment via public `addNativePointer`, breaking ERC20 immutability assumed by integrators - (File: `x/evm/keeper/pointer_upgrade.go`, `precompiles/pointer/pointer.go`)

### Summary
The Sei EVM pointer precompile's `addNativePointer` method is callable by any unprivileged EVM caller and always "upserts" the ERC20 native pointer contract for a given bank/tokenfactory denom, redeploying its bytecode with whatever `decimals`/`name`/`symbol` the denom's current bank `DenomMetadata` reports. Because `decimals` is normally treated by ERC20 consumers as an immutable, deploy-time constant, this allows the pointer's decimals to be changed after other on-chain contracts have already read and cached that value, producing an accounting/precision mismatch analogous to the `CollectionShutdown` denomination-manipulation bug (H-25), where re-fetching a mutable "denomination" value after state had already been established let an attacker corrupt downstream accounting.

### Finding Description
`AddNative` in the pointer precompile takes only the denom string as an argument, has no access control beyond "not a staticcall/delegatecall", pulls the token's *current* bank denom metadata, and always calls `UpsertERCNativePointer`: [1](#0-0) 

`UpsertERCPointer` looks up whether a pointer already exists for the pointee; if it does, it does **not** reject the call — it redeploys the runtime bytecode (`evm.GetDeploymentCode`) at the *same* contract address and overwrites the on-chain code via `k.SetCode`/`sdb.RefreshCodeCache`: [2](#0-1) 

The unit test `TestUpsertERCNativePointer` explicitly demonstrates that calling `UpsertERCNativePointer` twice for the same token with different `Decimals` (6, then 12) redeploys the same address and the `decimals()` view now returns the new value: [3](#0-2) 

Decimals are sourced from `bankKeeper.GetDenomMetaData(ctx, token)`, whose largest-exponent `DenomUnit` is used: [4](#0-3) 

For tokenfactory denoms, this metadata is mutable by the denom's admin at any time via `MsgSetDenomMetadata`, gated only by an admin check, not by any restriction tied to whether a pointer has already been created or is in active use: [5](#0-4) 

This is structurally the same root cause as H-25: a value that downstream logic treats as fixed at "registration time" (there: `denomination` used in `CollectionShutdown::cancel`; here: `decimals` baked into an ERC20 pointer) is instead re-derived from a live, attacker/admin-mutable source and can be changed after other participants (integrators, AMMs, lending markets, off-chain indexers) have already relied on the original value, and the "re-registration" action (`vote()` in H-25, `addNativePointer` here) is open to any caller with no guard against acting on an already-established pointer.

### Impact Explanation
Any EVM contract or off-chain system that integrates a tokenfactory-denom's ERC20 pointer (e.g., a DEX pool, lending market, or price-normalization logic) typically reads `decimals()` once and assumes it is immutable per the ERC20 standard. If the tokenfactory admin changes the denom's metadata (e.g., from `exponent: 6` to `exponent: 0` or `18`) and any account then calls `addNativePointer(denom)` again, the pointer's `decimals()` silently changes at the same address. Contracts that cached the old decimals value (or compute conversions assuming decimals never change) will misprice trades, misvalue collateral, or miscalculate transfer amounts by orders of magnitude, enabling drain of pooled funds or improper liquidations — a direct fund-loss vector reachable purely from a tokenfactory denom admin plus any public caller of the pointer precompile.

### Likelihood Explanation
The tokenfactory denom admin is an explicitly in-scope, unprivileged-relative-to-the-chain actor (any account can create a tokenfactory denom and become its admin). Calling `addNativePointer` requires no special privilege — it is a public EVM precompile call reachable from any transaction. No governance or validator collusion is needed; the whole chain (change metadata → call `addNativePointer`) can be executed by a single actor across two ordinary transactions.

### Recommendation
- Reject re-registration (`UpsertERCNativePointer`/`UpsertERCPointer`) once a pointer has already been created for a token whenever the immutable ERC20 fields (`decimals` in particular, and ideally `name`/`symbol`) differ from the originally deployed values, or explicitly document/version the pointer so dependents can detect a decimals change (e.g., bump `PointerVersion` and require callers to re-resolve, rather than silently rewriting bytecode at the same address).
- Alternatively, snapshot `decimals` at first pointer creation and make subsequent `addNativePointer` calls fail (or be a governance-only action) if the underlying denom metadata's decimals would change, mirroring the fix recommended in the reference report of using the value captured at the moment authority/quorum was established rather than a live, mutable lookup.

### Proof of Concept
1. Create a tokenfactory denom `factory/<admin>/foo` and set its metadata via `MsgSetDenomMetadata` with a `DenomUnit` of `exponent: 6` [6](#0-5) .
2. Any account calls the pointer precompile `addNativePointer("factory/<admin>/foo")`; the ERC20 pointer is deployed at address `X` with `decimals() == 6` [1](#0-0) .
3. A DeFi contract integrates pointer `X`, reading/caching `decimals() == 6` for pricing/conversion math.
4. The tokenfactory admin calls `MsgSetDenomMetadata` again, changing the `DenomUnit` exponent to `0` (or `18`).
5. Any account calls `addNativePointer("factory/<admin>/foo")` again; `UpsertERCPointer` sees the pointer `exists` and redeploys bytecode at the same address `X`, now returning `decimals() == 0` (as proven directly by `TestUpsertERCNativePointer` for the analogous 6→12 case) [3](#0-2) .
6. The integrating contract, still using its cached decimals assumption (or reading fresh but expecting no change since ERC20 decimals are supposed to be immutable), miscalculates amounts by the resulting order-of-magnitude difference, enabling value extraction or destruction of user funds.

func (k *Keeper) UpsertERCPointer(
	ctx sdk.Context, evm *vm.EVM, typ string, args []interface{}, getter PointerGetter, setter PointerSetter,
) (contractAddr common.Address, err error) {
	pointee := args[0].(string)
	evmModuleAddress := k.GetEVMAddressOrDefault(ctx, k.AccountKeeper().GetModuleAddress(types.ModuleName))

	var bin []byte
	bin, err = artifacts.GetParsedABI(typ).Pack("", args...)
	if err != nil {
		panic(err)
	}
	bin = append(artifacts.GetBin(typ), bin...)
	// GetDeploymentCode / Create take EVM snapshots that Freeze() Multistore layers.
	// Exists-lookup and commits must use the live unfrozen top (sdb.Ctx): cachekv
	// forbids writing a frozen layer, and same-tx readers that skip frozen-empty
	// parents would miss those writes. The precompile Prepare `ctx` is that top at
	// Prepare time, but is frozen once this Upsert snapshots. Always attach the
	// caller's gas meter (finite precompile meter in deliver) — sdb.Ctx() alone
	// carries the infinite EVM meter.
	sdb := state.GetDBImpl(evm.StateDB)
	liveCtx := func() sdk.Context {
		if sdb == nil {
			return ctx
		}
		return sdb.Ctx().WithGasMeter(ctx.GasMeter())
	}
	existingAddr, _, exists := getter(liveCtx(), pointee)
	suppliedGas := k.getEvmGasLimitFromCtx(ctx)
	var remainingGas uint64
	if exists {
		var ret []byte
		contractAddr = existingAddr
		ret, remainingGas, err = evm.GetDeploymentCode(evmModuleAddress, bin, suppliedGas, utils.Big0, existingAddr)
		if err != nil {
			return
		}
		// Only write on success: a failed GetDeploymentCode can leave ret as nil or
		// revert data, which must not clobber live pointer bytecode (even transiently).
		writeCtx := liveCtx()
		k.SetCode(writeCtx, contractAddr, ret)
		if sdb != nil {
			sdb.RefreshCodeCache(contractAddr, ret)
		}
	} else {
		_, contractAddr, remainingGas, err = evm.Create(evmModuleAddress, bin, suppliedGas, uint256.NewInt(0))
	}
	if err != nil {
		return
	}
	ctx.GasMeter().ConsumeGas(k.GetCosmosGasLimitFromEVMGas(ctx, suppliedGas-remainingGas), "ERC pointer deployment")
	if err = setter(liveCtx(), pointee, contractAddr); err != nil {
		return

func TestUpsertERCNativePointer(t *testing.T) {
	k := &testkeeper.EVMTestApp.EvmKeeper
	ctx := testkeeper.EVMTestApp.GetContextForDeliverTx([]byte{}).WithBlockTime(time.Now())
	ctx = ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx))
	var addr common.Address
	err := k.RunWithOneOffEVMInstance(ctx, func(e *vm.EVM) error {
		a, err := k.UpsertERCNativePointer(ctx, e, "test", utils.ERCMetadata{
			Name:     "test",
			Symbol:   "test",
			Decimals: 6,
		})
		addr = a
		return err
	}, func(s1, s2 string) {})
	require.Nil(t, err)
	var newAddr common.Address
	err = k.RunWithOneOffEVMInstance(ctx, func(e *vm.EVM) error {
		a, err := k.UpsertERCNativePointer(ctx, e, "test", utils.ERCMetadata{
			Name:     "test2",
			Symbol:   "test2",
			Decimals: 12,
		})
		newAddr = a
		return err
	}, func(s1, s2 string) {})
	require.Nil(t, err)
	require.Equal(t, addr, newAddr)
	res, err := k.QueryERCSingleOutput(ctx, "native", addr, "name")
	require.Nil(t, err)
	require.Equal(t, "test2", res.(string))
	res, err = k.QueryERCSingleOutput(ctx, "native", addr, "symbol")
	require.Nil(t, err)
	require.Equal(t, "test2", res.(string))
	res, err = k.QueryERCSingleOutput(ctx, "native", addr, "decimals")
	require.Nil(t, err)
	require.Equal(t, uint8(12), res.(uint8))
	_, err = k.QueryERCSingleOutput(ctx, "native", addr, "nonexist")
	require.NotNil(t, err)
}

func (server msgServer) SetDenomMetadata(goCtx context.Context, msg *types.MsgSetDenomMetadata) (*types.MsgSetDenomMetadataResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	// Defense in depth validation of metadata
	err := msg.Metadata.Validate()
	if err != nil {
		return nil, err
	}

	authorityMetadata, err := server.GetAuthorityMetadata(ctx, msg.Metadata.Base)
	if err != nil {
		return nil, err
	}

	if msg.Sender != authorityMetadata.GetAdmin() {
		return nil, types.ErrUnauthorized
	}

	server.bankKeeper.SetDenomMetaData(ctx, msg.Metadata)

	ctx.EventManager().EmitEvents(sdk.Events{
		sdk.NewEvent(
			types.TypeMsgSetDenomMetadata,
			sdk.NewAttribute(types.AttributeDenom, msg.Metadata.Base),
			sdk.NewAttribute(types.AttributeDenomMetadata, msg.Metadata.String()),
		),
	})

	return &types.MsgSetDenomMetadataResponse{}, nil
}
