Confirmed: `AddCW20` in `precompiles/pointer/pointer.go` does not check the CW20 contract's admin/mutability status before creating a pointer — it only queries `token_info` once at pointer-creation time to seed `name`/`symbol`, with no restriction requiring the target contract to have no admin (i.e., be non-migratable).

### Title
CW20-to-ERC20 pointer permanently trusts a mutable, admin-migratable CosmWasm contract, letting an unprivileged actor create pointers that can be silently rug-pulled by contract-code migration - (File: `precompiles/pointer/pointer.go`, `contracts/src/CW20ERC20Pointer.sol`)

### Summary
`addCW20Pointer` lets any caller register an ERC20 pointer for **any** CW20 address without verifying that the CW20 contract's admin has been cleared (i.e., that the contract is immutable). All state-changing ERC20 semantics of the resulting pointer (`decimals`, `balanceOf`, `totalSupply`, `allowance`, and the effects of `transfer`/`transferFrom`) are computed by live `wasmd` queries/executes against the pointee contract on every call, rather than being fixed at pointer-creation time. Because CosmWasm contracts with a non-empty admin can be migrated (`MsgMigrateContract`) to arbitrary new code at any time by that admin, the pointer's ERC20 behavior can change after the fact — exactly the "proxy + implementation" upgrade risk described for tokens like TUSD.

### Finding Description
`AddCW20` in `precompiles/pointer/pointer.go` (and all legacy versions) performs only a `QuerySmartSafe(... "token_info" ...)` to fetch `name`/`symbol` and then calls `UpsertERCCW20Pointer` / `evm.Create` to deploy a `CW20ERC20Pointer` (`contracts/src/CW20ERC20Pointer.sol`). [1](#0-0) 

There is no check on `wasmdKeeper.GetContractInfo(cwAddress).Admin` to require the CW20 contract be non-migratable (admin cleared). CosmWasm's `migrate` entrypoint lets whoever holds the `admin` role on a contract swap its code (and thus its logic) for any other stored code ID, as shown in the `migrate` handler: [2](#0-1) 

`CW20ERC20Pointer.decimals()`, `balanceOf()`, `totalSupply()`, and `allowance()` all issue a live `WasmdPrecompile.query` against the pointee CW20 contract every time they're called, and `transfer`/`transferFrom`/`approve` all issue live `execute` calls into it: [3](#0-2) [4](#0-3) 

Only `name` and `symbol` are frozen at pointer-creation time (constructor args); every other observable ERC20 property is dynamically re-derived from whatever code currently backs the CW20 address. If that address's admin migrates the contract to new code — e.g., one that reports different `decimals`, applies a transfer fee, rebases balances, freezes transfers for a blocklist, or simply misreports `token_info`/`balance` — every downstream EVM integrator (lending markets, DEX pools, custody contracts) that treats the pointer as a standard immutable ERC20 will silently inherit that new, unreviewed behavior.

### Impact Explanation
Any EVM protocol built on top of a CW20 pointer (lending/borrowing markets, AMMs, vaults) typically caches `decimals()` and assumes ERC20 balance/transfer semantics are stable at integration time, consistent with widespread DeFi conventions (this is precisely the class of bug the cited external report describes for upgradeable ERC20s like TUSD). Because the pointer never freezes or snapshots this behavior and there is no admin/immutability check at `AddCW20` pointer-creation time, a CW20 admin (which could itself be a compromised or malicious key, or a DAO-controlled migration) can:
- change `decimals` after integrators have already priced/collateralized the pointer token, corrupting valuation math and collateral ratios,
- alter transfer/balance semantics (fees, rebasing, blocklisting) to break invariants relied upon by lending/AMM logic, potentially leading to bad debt, stuck funds, or unliquidatable positions,
- do all of this without any on-chain signal to the EVM side that would let the pointer or its integrators detect/freeze the change.

This matches the "Medium/High" impact bar for fund loss or permanent freezing via a pointer that unauthorized parties (the CW20 admin) can weaponize to break EVM-side integrations relying on the pointer.

### Likelihood Explanation
Likelihood is moderate: it requires (a) a CW20 token whose admin has not been cleared (common for many non-finalized/non-immutable CW20 deployments) to have an ERC20 pointer created for it (anyone can call `addCW20Pointer` for any CW20 address, unprivileged), and (b) that admin later migrating the contract. Because pointer creation itself is fully permissionless and performs no admin/immutability validation, an attacker can also deliberately deploy a CW20 token with themselves as admin, get integrators to adopt the resulting pointer as if it were a normal ERC20, and then migrate the code to introduce malicious behavior post-integration — a classic "bait-and-switch" upgradeable-token attack.

### Recommendation
- In `AddCW20` (`precompiles/pointer/pointer.go`), query the CW20 contract's `ContractInfo.Admin` via the wasm keeper and reject pointer creation (or mark the pointer specially) unless the admin is empty (contract is immutable/non-migratable).
- Alternatively, track the CW20 contract's code ID/code hash at pointer-creation time and have `CW20ERC20Pointer` (or the keeper) detect a code-ID change (e.g., by checking `ContractInfo.CodeID` on each call, or by reacting to `MsgMigrateContract` via a hook) and revert/freeze all pointer operations once a migration is detected, mirroring the TUSD-adapter pattern cited in the report.
- Document/enforce this requirement for any future `addNativePointer`-style logic that similarly trusts external, potentially mutable, state.

### Proof of Concept
1. Attacker instantiates a CW20 contract with themselves set as `admin` (not cleared), with legitimate-looking `token_info` (name/symbol/decimals=18).
2. Attacker calls the `pointer` precompile's `addCW20Pointer(cwAddr)` (`AddCW20` in `precompiles/pointer/pointer.go`), which deploys a `CW20ERC20Pointer` contract with no admin/immutability check.
3. A third-party DeFi protocol on the EVM side integrates the pointer as collateral, calling `decimals()` once at listing time and caching it, and treating `balanceOf`/`transfer` as standard non-rebasing ERC20 semantics, consistent with `contracts/src/CW20ERC20Pointer.sol` exposing those exact functions.
4. Attacker submits `MsgMigrateContract` (permitted because they are still the CW20's admin) to swap the CW20's code for one that reports a different `decimals` in `token_info`, or introduces transfer fees/rebasing/blocklisting in `balance`/`transfer` handlers.
5. Because `CW20ERC20Pointer.decimals()/balanceOf()/transfer()` all live-query the now-migrated contract, the integrating protocol's cached assumptions (decimals, non-rebasing balances) become wrong, corrupting valuation/collateral accounting and potentially leading to bad debt or frozen positions — with no mechanism on the pointer or precompile side to have prevented or detected the migration.

func (p PrecompileExecutor) AddCW20(ctx sdk.Context, method *ethabi.Method, caller common.Address, args []interface{}, value *big.Int, evm *vm.EVM, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	cwAddr := args[0].(string)
	cwAddress, err := sdk.AccAddressFromBech32(cwAddr)
	if err != nil {
		return nil, 0, err
	}
	res, err := p.wasmdKeeper.QuerySmartSafe(ctx, cwAddress, []byte("{\"token_info\":{}}"))
	if err != nil {
		return nil, 0, err
	}
	formattedRes := map[string]interface{}{}
	if err := json.Unmarshal(res, &formattedRes); err != nil {
		return nil, 0, err
	}
	name := formattedRes["name"].(string)
	symbol := formattedRes["symbol"].(string)
	contractAddr, err := p.evmKeeper.UpsertERCCW20Pointer(ctx, evm, cwAddr, utils.ERCMetadata{Name: name, Symbol: symbol})
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(contractAddr)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}

func (k Keeper) migrate(ctx sdk.Context, contractAddress sdk.AccAddress, caller sdk.AccAddress, newCodeID uint64, msg []byte, authZ AuthorizationPolicy) ([]byte, error) {
	start := time.Now()
	defer func() { recordContractMigrateDuration(ctx.Context(), start) }()
	migrateSetupCosts := k.gasRegister.InstantiateContractCosts(k.IsPinnedCode(ctx, newCodeID), len(msg))
	ctx.GasMeter().ConsumeGas(migrateSetupCosts, "Loading CosmWasm module: migrate")

	contractInfo := k.GetContractInfo(ctx, contractAddress)
	if contractInfo == nil {
		return nil, sdkerrors.Wrap(sdkerrors.ErrInvalidRequest, "unknown contract")
	}
	if !authZ.CanModifyContract(contractInfo.AdminAddr(), caller) {
		return nil, sdkerrors.Wrap(sdkerrors.ErrUnauthorized, "can not migrate")
	}

	newCodeInfo := k.GetCodeInfo(ctx, newCodeID)
	if newCodeInfo == nil {
		return nil, sdkerrors.Wrap(sdkerrors.ErrInvalidRequest, "unknown code")
	}

	// check for IBC flag
	switch report, err := k.getWasmer(ctx).AnalyzeCode(newCodeInfo.CodeHash); {
	case err != nil:
		return nil, sdkerrors.Wrap(types.ErrMigrationFailed, err.Error())
	case !report.HasIBCEntryPoints && contractInfo.IBCPortID != "":
		// prevent update to non ibc contract
		return nil, sdkerrors.Wrap(types.ErrMigrationFailed, "requires ibc callbacks")
	case report.HasIBCEntryPoints && contractInfo.IBCPortID == "":
		contractInfo.IBCPortID = PortIDForContract(contractAddress)
	}

    function transfer(address to, uint256 amount) public override returns (bool) {
        require(to != address(0), "ERC20: transfer to the zero address");
        string memory recipient = _formatPayload("recipient", _doubleQuotes(AddrPrecompile.getSeiAddr(to)));

        string memory req = _curlyBrace(_formatPayload("transfer", _curlyBrace(_join(recipient, amt, ","))));

        return true;
    }

    function transferFrom(address from, address to, uint256 amount) public override returns (bool) {
        require(to != address(0), "ERC20: transfer to the zero address");
        string memory sender = _formatPayload("owner", _doubleQuotes(AddrPrecompile.getSeiAddr(from)));
        string memory recipient = _formatPayload("recipient", _doubleQuotes(AddrPrecompile.getSeiAddr(to)));
        string memory amt = _formatPayload("amount", _doubleQuotes(Strings.toString(amount)));
        string memory req = _curlyBrace(_formatPayload("transfer_from", _curlyBrace(_join(_join(sender, recipient, ","), amt, ","))));
        _execute(bytes(req));
        return true;
    }

    function _execute(bytes memory req) internal returns (bytes memory) {
        (bool success, bytes memory ret) = WASMD_PRECOMPILE_ADDRESS.delegatecall(
            abi.encodeWithSignature(
                "execute(string,bytes,bytes)",
                Cw20Address,
                bytes(req),
                bytes("[]")
            )
        );
        require(success, "CosmWasm execute failed");
        return ret;
    }
