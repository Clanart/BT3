## Title
`WomUp.stake`, `WomUp.withdraw`, `WomUp.migrate`, and `WomUp.getReward` do not use `whenNotPaused` modifier - (File: `wombat/WomUp.sol`)

### Summary
`WomUp` inherits `PausableUpgradeable` and exposes `pause()`/`unpause()` admin functions, but none of its user-facing state-changing functions — `stake`, `withdraw`, `migrate`, and `getReward` — enforce the `whenNotPaused` modifier, mirroring exactly the reported bug class where a contract imports pause functionality but fails to gate its core deposit/withdraw/claim flows with it.

### Finding Description
`WomUp` is set up with `PausableUpgradeable` and admin-only `pause`/`unpause` functions intended to halt user interactions in an emergency: [1](#0-0) 

However, the core unprivileged-wallet entrypoints only use the `updateReward` modifier and never check the pause state: [2](#0-1) [3](#0-2) [4](#0-3) 

`stake` pulls WOM from the caller and forwards it into `mWom.deposit`, `withdraw` releases `mWom` back to the caller, `migrate` moves a user's staked balance to another helper via `ISimpleHelper.depositFor`, and `getReward` locks accrued MGP rewards into `vlMGP` for the caller — all reachable directly by any wallet with no pause gate, unlike the sibling contract `wombat/mWOM.sol`, whose analogous `convert`/`deposit`/`_convert` functions are explicitly protected with `whenNotPaused`: [5](#0-4) [6](#0-5) 

This is the same bug class as the referenced report: the contract has pause machinery wired up but the functions that move user funds don't respect it.

### Impact Explanation
If an incident affecting the WOM/mWOM/vlMGP path occurs (e.g. a compromised or misbehaving `mWom`, `vlMGP`, or downstream `WombatStaking`/`veWom` integration), the protocol admin can call `pause()` on `WomUp`, but `stake`, `withdraw`, `migrate`, and `getReward` remain fully callable because they don't check `whenNotPaused`. This prevents the admin from halting fund movement through `WomUp` during an emergency, which can lead to loss of user or protocol funds that a working pause would have prevented — consistent with the confirmed Medium severity of the analogous `KangarooVault` finding.

### Likelihood Explanation
Likelihood is tied to emergency scenarios (exploit in a connected contract) where pausing is needed; under normal operation there is no direct exploit, but the missing guard removes an emergency safety control from a fund-moving contract, which is precisely the scenario the pause mechanism was built to address.

### Recommendation
Add the `whenNotPaused` modifier to `WomUp.stake`, `WomUp.withdraw`, `WomUp.migrate`, and `WomUp.getReward` (and any other user-facing fund-moving functions), consistent with how `mWOM.sol` and `WombatStaking.sol` gate their deposit/withdraw/convert functions.

### Proof of Concept
1. An emergency occurs affecting `mWom`, `vlMGP`, or the wider Wombat integration such that continued staking/withdrawing/claiming through `WomUp` would cause loss of funds.
2. The protocol team calls `WomUp.pause()`.
3. Because `stake`, `withdraw`, `migrate`, and `getReward` lack `whenNotPaused`, users can still call them and move funds through the compromised path.
4. Funds are lost that the pause mechanism was designed to protect.
