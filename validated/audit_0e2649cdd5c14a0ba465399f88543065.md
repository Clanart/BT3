### Title
Unvalidated DataLayer mirror URLs enable SSRF via attacker-controlled `Mirror` coin memos - (File: `chia/data_layer/download_data.py`)

### Summary
Any user can submit a spend bundle that creates a coin paid to the fixed, unowned `MIRROR_PUZZLE_HASH` with memos containing an arbitrary `launcher_id` and arbitrary URL strings. Once a DataLayer node is tracking that `launcher_id` (which happens automatically for owned or subscribed stores), the wallet records these attacker-supplied strings as mirror "URLs" with no validation, and the DataLayer service later performs an outbound HTTP GET to that exact string. This mirrors the CVE-2019-9827 bug class: an unauthenticated party controls a "target" value that the server later uses to issue an outbound HTTP request, i.e. SSRF.

### Finding Description
`create_mirror_puzzle()` returns a fixed, publicly known puzzle (`P2_PARENT.curry(Program.to(1))`), not bound to any specific singleton owner's key [1](#0-0) . Anyone can spend one of their own coins to create a coin paying this puzzle hash with `memos=[launcher_id, url1, url2, ...]`, as the wallet-side helper itself demonstrates [2](#0-1) . `launcher_id` can be *any* DataLayer singleton launcher id (not necessarily one the spender owns or controls), and the URL strings are fully attacker-chosen memo bytes.

When any node observes this coin, `DataLayerWallet.coin_added()` matches the puzzle hash, decodes `launcher_id, urls` from the parent spend, and — with no scheme/host validation — persists the URLs as a `Mirror` record as long as the node is tracking that `launcher_id`: `is_launcher_tracked(launcher_id)` is the only gate [3](#0-2) . Tracking happens automatically for any store a wallet owns or has subscribed to via `dl_track_new`.

The DataLayer service then periodically pulls these mirrors and stages the raw URLs into its local subscription table with only trailing-slash stripping, no scheme/host allow-listing: `update_subscriptions_from_wallet()` [4](#0-3) . During the periodic sync loop (`periodically_manage_data()` / `update_subscription()` / `fetch_and_validate()`), these URLs are selected as candidate servers and passed into `insert_from_delta_file()` → `download_file()` → `http_download()`, which issues an aiohttp GET directly against the attacker-controlled string: `session.get(server_info.url + "/" + filename, ...)` [5](#0-4) .

No part of this pipeline (RPC `subscribe`/`add_mirror` handlers, `update_subscriptions_from_wallet`, or `http_download`) validates that the URL scheme is `http(s)` pointed at an expected external mirror, nor restricts it from resolving to loopback, link-local, or cloud metadata addresses. This is analogous to the Hawtio `/proxy/` SSRF: an externally influenced "target" string is fed straight into an outbound request performed by the server process.

### Impact Explanation
A DataLayer node that owns or subscribes to any store can be induced (by anyone submitting a cheap spend bundle referencing that store's `launcher_id`) to issue outbound HTTP requests to attacker-chosen destinations, including internal-only services, cloud instance metadata endpoints (e.g. `169.254.169.254`), or other hosts on the operator's private network. This can lead to credential/metadata disclosure, internal network reconnaissance/pivoting, or interaction with internal services that trust requests originating from the DataLayer host. This is reachable purely through a wallet-observable coin spend — no direct RPC access to the victim is required, satisfying "Data Layer roots and proofs" / "Data Layer client" reachability.

### Likelihood Explanation
Creating the mirror coin costs only a small standard coin spend to a well-known, public puzzle hash; no signature from the store owner or any privileged key is required. The victim only needs to be tracking the referenced `launcher_id`, which is the normal state for any DataLayer user who owns a store or has subscribed to one (a common, expected DataLayer usage pattern). The periodic sync loop runs unattended (`manage_data_interval`, default 60s), so the malicious mirror will be picked up and acted upon automatically without further user interaction.

### Recommendation
- Validate mirror/subscription URLs at ingestion (`coin_added()` in `chia/data_layer/data_layer_wallet.py` and `update_subscriptions_from_wallet()`/`subscribe()` in `chia/data_layer/data_layer.py`): enforce an allowed URL scheme (`http`/`https`), reject loopback/link-local/private IP ranges and non-standard ports unless explicitly opted in, and consider requiring operator confirmation before a discovered mirror is added to the fetch rotation.
- In `http_download()` (`chia/data_layer/download_data.py`), resolve and re-validate the destination host before connecting, and/or route mirror downloads through an egress policy that blocks internal/metadata address ranges.

### Proof of Concept
1. Attacker creates a standard coin spend with a `CREATE_COIN` condition to `create_mirror_puzzle().get_tree_hash()` (`MIRROR_PUZZLE_HASH`), with `memos = [victim_store_launcher_id, b"http://169.254.169.254/latest/meta-data/"]`, and submits it as a normal spend bundle (as done by `DataLayerWallet.create_new_mirror()`).
2. Once confirmed, any node tracking `victim_store_launcher_id` (owner or subscriber) picks it up in `coin_added()` and stores the mirror with the attacker's URL, since `get_mirror_info()`/`Mirror.decode_urls()` perform no validation.
3. On the next `periodically_manage_data()` cycle, `update_subscriptions_from_wallet()` copies the URL into the subscriptions table, and `fetch_and_validate()`/`http_download()` issues `GET http://169.254.169.254/latest/meta-data/<delta-filename>` from the victim's DataLayer node.

    async def coin_added(
        self, coin: Coin, height: uint32, peer: WSChiaConnection, coin_data: object | None, sync_scope: WalletSyncScope
    ) -> None:
        if coin.puzzle_hash == create_mirror_puzzle().get_tree_hash():
            parent_state: CoinState = (
                await self.wallet_state_manager.wallet_node.get_coin_state([coin.parent_coin_info], peer=peer)
            )[0]
            parent_spend = await fetch_coin_spend(height, parent_state.coin, peer)
            assert parent_spend is not None
            launcher_id, urls = get_mirror_info(parent_spend.puzzle_reveal, parent_spend.solution)
            # Don't track mirrors with empty url list.
            if not urls:
                return
            if await self.wallet_state_manager.dl_store.is_launcher_tracked(launcher_id):
                ours: bool = await self.wallet_state_manager.get_wallet_for_coin(coin.parent_coin_info) is not None
                await self.wallet_state_manager.dl_store.add_mirror(
                    Mirror(
                        coin.name(),
                        launcher_id,
                        uint64(coin.amount),
                        Mirror.decode_urls(urls),
                        ours,
                        height,
                    )
                )
                await self.wallet_state_manager.add_interested_coin_ids([coin.name()])

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
