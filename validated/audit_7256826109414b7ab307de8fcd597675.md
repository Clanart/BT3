### Title
Unbounded index read in `is_atom_canonical` allows a crafted spend bundle to raise an uncaught `IndexError` during mempool admission - ([File: chia/full_node/mempool_manager.py])

### Summary
`is_atom_canonical()` parses a CLVM atom length-prefix directly out of an attacker-supplied `puzzle_reveal`/`solution` byte buffer without ever checking that `offset` stays within `len(clvm_buffer)`. A crafted buffer whose final byte declares a multi-byte length prefix (e.g. the `0xFC` 5-extra-byte prefix) but is truncated right after that byte causes the function to index past the end of the `bytes` object, raising an unhandled `IndexError`. This is the same class of bug as CVE-2024-29163 (an out-of-bounds read while parsing a bit/length field from external, mostly-untrusted binary input), just manifesting in Python as an unchecked index instead of a C heap read.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads the first descriptor byte and, based on its top bits, determines `prefix_len` (0–5 extra bytes) that must be consumed to build `atom_len`: [1](#0-0) 

The loop `for i in range(prefix_len): ... offset += 1; atom_len |= clvm_buffer[offset]` never verifies that `offset < len(clvm_buffer)` before indexing. Because `clvm_buffer` is a plain `bytes` object, indexing past the end raises `IndexError` (unlike slicing, which would silently return an empty result). The caller, `is_clvm_canonical()`, similarly indexes `clvm_buffer[offset]` in its main loop without length checks, and is invoked directly on attacker-controlled data: [2](#0-1) 

This is reached from `MempoolManager.validate_spend_bundle()`, on every coin spend in a submitted `SpendBundle`, before any other structural checks reject a malformed atom-length prefix: [3](#0-2) 

`validate_spend_bundle()` is called from `add_spend_bundle()`, which is called from `FullNode.add_transaction()` for every spend bundle a peer or wallet RPC submits to the mempool: [4](#0-3) [5](#0-4) 

No `try/except` wraps this specific call site around `is_clvm_canonical()`, so an `IndexError` raised here propagates up through `validate_spend_bundle` → `add_spend_bundle` → `add_transaction`, outside the exception classes (`Err`, `ValidationError`) that the mempool admission pipeline is designed to convert into a rejected/`FAILED` status.

By contrast, the equivalent binary parsers elsewhere in the codebase (`chia/full_node/full_block_utils.py`) explicitly bounds-check lengths against the remaining buffer and raise a descriptive, caught `ValueError` (e.g. `skip_bytes`, `generator_from_block`), showing this is a known hazard class that was hardened in one location but not in `is_atom_canonical`/`is_clvm_canonical`: [6](#0-5) 

### Impact Explanation
An unprivileged spend-bundle submitter (wallet RPC caller, or peer submitting `tx` messages) can craft a `puzzle_reveal` or `solution` blob whose trailing bytes form a valid multi-byte length prefix marker with no continuation bytes present. This reaches `is_clvm_canonical()`/`is_atom_canonical()` during `validate_spend_bundle()`, causing an unhandled `IndexError`. Whether this crashes the `asyncio` task handling that RPC/peer message, or propagates further and disrupts the full node's transaction-processing loop, depends on exception handling further up the call stack in `full_node.py` around `add_transaction`, which was not fully confirmed in this investigation. At minimum this is a spend-triggered exception in the mempool admission hot path that bypasses the intended graceful-rejection (`Err.INVALID_COIN_SOLUTION`) flow, which matches a "spend-triggered transaction-processing halt" pattern; the CVSS-analog severity is High if it propagates to crash/hang request handling for the full node's transaction ingestion path, but I could not fully verify the topmost exception boundary in the time available, so this should be validated against the actual behavior of `FullNode.add_transaction()`'s callers (e.g. RPC handler / peer protocol handler try/except wrapping) before treating this as confirmed process-crashing DoS versus a contained, per-request failure.

### Likelihood Explanation
High reachability: the vulnerable code executes on every `SpendBundle` submitted to the mempool, using only the raw bytes of `puzzle_reveal`/`solution`, which are fully attacker-controlled and require no special privileges, valid signature, or successful CLVM execution to reach this check (`is_clvm_canonical` is called before fast-forward/dedup logic and before full puzzle_reveal/solution CLVM execution results are used). Constructing a triggering byte sequence is trivial and deterministic (just append a lone multi-byte length-prefix marker byte at the very end of the buffer).

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before each indexed read (verify `offset < len(clvm_buffer)` prior to reading `clvm_buffer[offset]`, both for the initial byte and inside the prefix-consuming loop), and do the same in `is_clvm_canonical()`'s main loop. On an out-of-bounds condition, treat the buffer as non-canonical (return `False`) or raise a caught `ValidationError`/`Err.INVALID_COIN_SOLUTION` rather than letting a raw `IndexError` escape, mirroring the defensive bounds-checked style already used in `chia/full_node/full_block_utils.py`.

### Proof of Concept
Construct a `puzzle_reveal` (or `solution`) buffer consisting of a single truncated atom header, e.g. the byte `0xFC` (declares a 5-extra-byte length prefix) with zero following bytes: `bytes([0xFC])`. Passing this buffer through `is_clvm_canonical(bytes([0xFC]))` invokes `is_atom_canonical(buf, 0)`, which sets `prefix_len = 5` and then, on the first loop iteration, executes `offset += 1; atom_len |= clvm_buffer[offset]` with `offset == 1` against a 1-byte buffer, raising `IndexError: index out of range`. Embedding such a `puzzle_reveal`/`solution` in a `CoinSpend` inside a `SpendBundle` and submitting it via wallet RPC or the peer transaction protocol drives execution into `MempoolManager.validate_spend_bundle()` at the `is_clvm_canonical(bytes(coin_spend.puzzle_reveal))` call site, reproducing the unhandled exception during mempool admission. def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
