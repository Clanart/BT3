### Title
`forceUnLock()` distorts `getRewardablePercentWAD()` denominator, letting an attacker reduce their own reward forfeiture via a same-block `forceUnLock → getReward` sequence - (File: `VLMGP.sol` / `rewards/vlMGPBaseRewarder.sol`)

### Summary
`VLMGP.forceUnLock()` zeroes a slot's `amountInCoolDown` and simultaneously withdraws that same amount from the user's `masterMagpie` staking balance via `_unlock()`, but `getUserTotalLocked()` (`fullyInLock`) is derived by subtracting the (now smaller) cool-down total from the (now smaller) master-magpie balance, so `fullyInLock` stays numerically unchanged while `userTotalVlmgp = fullyInLock + inCoolDown` shrinks by the forced amount. Because `getRewardablePercentWAD()` divides by `userTotalVlmgp` for the fully-locked component and for every other unlocking slot, this shrinkage inflates the computed forfeit-avoidance percentage for the user's remaining balance/slots immediately after the call, allowing an attacker to call `forceUnLock()` then `getReward()` in the same block to reduce `_calExpireForfeit`'s `forfeitAmount` below what the correct time-weighted state would produce.

### Finding Description
`getRewardablePercentWAD` ( [1](#0-0) ) computes:
- `fullyInLock = getUserTotalLocked(_user)` = `amountInMasterMagpie - inCoolDown` ( [2](#0-1) )
- `inCoolDown = getUserAmountInCoolDown(_user)` = sum of all slots' `amountInCoolDown` ( [3](#0-2) )
- `userTotalVlmgp = fullyInLock + inCoolDown` (i.e. total master-magpie balance)
- `percent = fullyInLock * 1e18 / userTotalVlmgp`, plus a time-weighted contribution per unlocking slot, all divided by the same `userTotalVlmgp`.

`forceUnLock()` does the following, in order ( [4](#0-3) ):
1. `_unlock(slot.amountInCoolDown)` → calls `masterMagpie.withdrawVlMGPFor(A, msg.sender)`, which reduces the user's `amountInMasterMagpie` by `A` ( [5](#0-4) ).
2. Computes penalty/`amountToUser` from `slot.amountInCoolDown` (still `A` at this point).
3. Sets `slot.amountInCoolDown = 0` and `slot.endTime = block.timestamp`.

After this sequence: `amountInMasterMagpie' = amountInMasterMagpie - A`, `inCoolDown' = inCoolDown - A`, so `fullyInLock' = amountInMasterMagpie' - inCoolDown' = fullyInLock` (unchanged), while `userTotalVlmgp' = userTotalVlmgp - A` (strictly smaller). Consequently `percent' = fullyInLock / (userTotalVlmgp - A) > fullyInLock / userTotalVlmgp = percent` before the call, and every remaining unlocking-slot term in the loop is also divided by the now-smaller `userTotalVlmgp'`, inflating their contributions too.

This inflated `percent` feeds directly into `_calExpireForfeit()` in `rewards/vlMGPBaseRewarder.sol` ( [6](#0-5) ), which is invoked from `_sendReward()` during `getReward()` ( [7](#0-6) ), reducing `forfeitAmount` and increasing `toSend` for the attacker, while less MGP/bonus reward is queued back into the shared pool via `_queueNewRewardsWithoutTransfer` ( [8](#0-7) ) that would otherwise be redistributed pro-rata to all other stakers.

No existing check prevents this: `forceUnLock` only has `whenNotPaused nonReentrant` and `_checkInCoolDown` guards ( [9](#0-8) ), none of which validate or freeze `getRewardablePercentWAD` against manipulation from a self-inflicted slot removal in the same block. `getReward()` is `onlyMasterMagpie` ( [10](#0-9) ), but an unprivileged staker can trivially reach it by calling `masterMagpie`'s public claim entrypoint for their own account.

### Impact Explanation
This lets an attacker unilaterally shrink their own forfeiture on accrued bonus/MGP rewards below the value the reward-accounting design intends, at the direct expense of other stakers who share the `_queueNewRewardsWithoutTransfer`-redistributed forfeit pool. This matches the "theft of unclaimed yield" impact class — value that should flow to the collective reward pool for other vlMGP holders is instead retained by the attacker. The magnitude scales with the size of the attacker's fully-locked/other-cooling balance relative to the forced slot amount `A`; a user can maximize `percent'` by choosing a small `A` slot to sacrifice (paying a comparatively small forced-unlock penalty on `A`) to boost the forfeit-avoidance ratio applied over their much larger remaining/other balances.

### Likelihood Explanation
No privileged role is required — any staker with an active cool-down slot can trigger this by simply calling `forceUnLock()` and then triggering `getReward()` (via `masterMagpie`'s multiclaim path) in the same block/transaction. The only cost is the forced-unlock penalty on the sacrificed slot's own amount, which can be minimized by using the smallest possible cool-down slot while holding a much larger fully-locked/other-cooling balance, making this cheaply repeatable by any user who plans their lock/unlock slots accordingly.

### Recommendation
Decouple the `fullyInLock`/`userTotalVlmgp` denominator calculation from same-block mutation by `forceUnLock`: e.g., snapshot/checkpoint the rewardable percent computation to a state prior to any cool-down slot changes in the same block, or recompute `userTotalVlmgp` and per-slot forfeiture accounting incrementally at the time reward accrues (per rewardPerToken update) rather than as a live division at claim-time. At minimum, force an `_updateFor`/reward-settlement of the account's other reward tokens using the pre-forceUnLock rewardable percent before mutating `slot.amountInCoolDown`/`endTime`, so that `forceUnLock` cannot retroactively change the effective percent applied to reward that already accrued before the call.

### Proof of Concept
Foundry test plan:
1. Deploy `VLMGP`, `MasterMagpie`, and `vlMGPBaseRewarder`; fund reward pool with a bonus token via `queueNewRewards`.
2. Attacker locks a large amount (e.g. 1000 MGP) via `lock()`, then starts two cool-down slots: slot A (small, e.g. 10 MGP) and slot B (large, e.g. 500 MGP, past `endTime` so it is "fully unlocked but unclaimed").
3. Let reward accrue via `queueNewRewards` on the rewarder so `userRewards`/`rewardPerToken` build up for the attacker.
4. Path 1 (baseline): call `masterMagpie` claim (`getReward`) directly without touching slot A; record `forfeitAmount` (via `RewardPaid`/`ForfeitRewardAdded` events or `calExpireForfeit` view before call).
5. Path 2 (exploit): in a fresh snapshot, call `VLMGP.forceUnLock(slotA_index)` then immediately call the same claim path in the same block; record `forfeitAmount`.
6. Assert `forfeitAmount_exploit < forfeitAmount_baseline` for equal accrued reward amounts, and assert `getRewardablePercentWAD(attacker)` computed immediately after `forceUnLock` exceeds the value computed immediately before it (Conservation violation), confirming the denominator manipulation and the resulting reduction in forfeited yield returned to the shared pool.

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalVlmgp = fullyInLock + inCoolDown;
        if (userTotalVlmgp == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalVlmgp;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalVlmgp / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalVlmgp;
                }

            }
        }

        return percent;
    }

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }
