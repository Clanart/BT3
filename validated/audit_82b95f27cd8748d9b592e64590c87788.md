In `kaiax/auction/bid.go`, `getSigner()` dereferences a user-controlled signature byte slice (`sig`) without any length check before indexing/slicing it, directly analogous to the SocketCAN `zcan_sendto_ctx()` bug where an unvalidated length is trusted before dereferencing frame fields.

### Title
Out-of-bounds slice access on unvalidated auction bid/auctioneer signature length in `getSigner()` - (File: kaiax/auction/bid.go)

### Summary
`getSigner()` in `kaiax/auction/bid.go` indexes and slices a signature byte slice (`sig[crypto.RecoveryIDOffset]`, `sig[0:32]`, `sig[32:64]`) that originates from externally supplied `Bid.SearcherSig` / `Bid.AuctioneerSig` fields, with no length validation performed before the access [1](#0-0) . This mirrors the SocketCAN pattern where the length of a caller-supplied buffer is never validated before the code dereferences fixed offsets within it, resulting in an out-of-bounds read/panic.

### Finding Description
`getSigner(sig, digest []byte)` is called from `ValidateSearcherSig` and `ValidateAuctioneerSig` to recover the address that produced a signature attached to an auction `Bid` object [2](#0-1) . The function immediately clones the signature and accesses fixed offsets:
```go
copiedSig := slices.Clone(sig)
if copiedSig[crypto.RecoveryIDOffset] == 27 || copiedSig[crypto.RecoveryIDOffset] == 28 {
    copiedSig[crypto.RecoveryIDOffset] -= 27
}
v := copiedSig[crypto.RecoveryIDOffset]
r := new(big.Int).SetBytes(copiedSig[0:32])
s := new(big.Int).SetBytes(copiedSig[32:64])
``` [3](#0-2) 
There is no check that `len(sig) >= 65` (or even that `sig` is non-nil) before indexing `sig[crypto.RecoveryIDOffset]` (offset 64) or slicing `sig[32:64]`. If an unprivileged auction bidder submits a `Bid` with a `SearcherSig` or `AuctioneerSig` shorter than 65 bytes (or empty/nil), Go's runtime will panic with an out-of-bounds slice/index error before `crypto.ValidateSignatureValues` or `crypto.SigToPub` (which do perform proper length checks) is ever reached [4](#0-3) .

This is directly analogous to the reported CVE-2026-5071 bug class: a length-unchecked, externally supplied buffer is dereferenced at fixed offsets before any length validation happens, causing a crash (denial of service) reachable by an unprivileged, untrusted input source — here an auction bidder submitting a malformed bid rather than a local process performing a `sendto` syscall.

### Impact Explanation
An auction bidder (or any entity able to submit a `Bid` to the gasless/auction subsystem) can craft a `Bid` with a truncated `SearcherSig` or `AuctioneerSig` field. When `ValidateSearcherSig`/`ValidateAuctioneerSig` is invoked during bid processing, the unchecked slice access panics, crashing the goroutine/process handling bid validation. If this validation path executes without a recovering deferred handler, it can crash the node process, denying service to the auction/gasless mechanism (impact: availability, matching CVSS AV:L/AC:L/PR:L/UI:N with C:L/I:N/A:H style DoS).

### Likelihood Explanation
Likelihood is high for any node that exposes bid submission (e.g., an auction/gasless RPC endpoint or P2P propagation path) to external, low-privilege participants, since crafting an arbitrarily short byte slice for `SearcherSig`/`AuctioneerSig` requires no special access — only the ability to submit a bid.

### Recommendation
Add an explicit length check (`len(sig) != crypto.SignatureLength`, i.e., 65 bytes) at the very start of `getSigner()`, returning `ErrInvalidSignature` (or similar) before indexing or slicing the signature buffer, mirroring the length checks already present in `crypto.Ecrecover`/`crypto.sigToPub` [4](#0-3)  and `crypto/signature_nocgo.go`.

### Proof of Concept
1. Construct a `Bid` object where `SearcherSig` (or `AuctioneerSig`) is set to a byte slice shorter than 65 bytes (e.g., `[]byte{0x01}` or `nil`).
2. Submit the bid so that `ValidateSearcherSig`/`ValidateAuctioneerSig` is invoked on it [2](#0-1) .
3. `getSigner()` executes `copiedSig[crypto.RecoveryIDOffset]` with `crypto.RecoveryIDOffset == 64`, which panics with "index out of range" for any slice shorter than 65 bytes, crashing the goroutine processing the bid [3](#0-2) .

func getSigner(sig, digest []byte) (common.Address, error) {
	// Manually convert V from 27/28 to 0/1
	copiedSig := slices.Clone(sig)
	if copiedSig[crypto.RecoveryIDOffset] == 27 || copiedSig[crypto.RecoveryIDOffset] == 28 {
		copiedSig[crypto.RecoveryIDOffset] -= 27
	}

	v := copiedSig[crypto.RecoveryIDOffset]
	r := new(big.Int).SetBytes(copiedSig[0:32])
	s := new(big.Int).SetBytes(copiedSig[32:64])
	if !crypto.ValidateSignatureValues(v, r, s, true) {
		return common.Address{}, ErrInvalidSignature
	}
```

// Ecrecover returns the uncompressed public key that created the given signature.
func Ecrecover(hash, sig []byte) ([]byte, error) {
	if len(sig) != SignatureLength {
		return nil, errors.New("invalid signature")
	}
	if len(hash) != DigestLength {
		return nil, fmt.Errorf("hash is required to be exactly %d bytes (%d)", DigestLength, len(hash))
	}
	// Enforce canonical Ethereum recovery id v ∈ {0, 1}.
	if sig[RecoveryIDOffset] >= 2 {
		return nil, errors.New("invalid signature recovery id")
	}
	return secp256k1.RecoverPubkey(hash, sig)
}
