### Title
Deterministic `CachedPreprocess` reuse re-derives identical FROST nonces, enabling secret share recovery - (File: crypto/frost/src/sign.rs)

### Summary
Analogous to the Nextcloud "pending token replay" bug — where a temporary credential issued mid-protocol could be replayed to gain the privileges of the fully authenticated session — Serai's FROST implementation allows a *preprocess* (the intermediate signing credential) to be deterministically regenerated and replayed across distinct signing sessions. `AlgorithmSignMachine::from_cache` seeds a `ChaCha20Rng` directly from the caller-supplied `CachedPreprocess`, so every machine built from the same seed produces bit-identical nonces and commitments. There is no consumption marker, counter, or message binding at cache-derivation time, so a "replayed" intermediate state yields a real signature share for an unintended session, and reusing it twice leaks the signer's secret share.

### Finding Description
`seeded_preprocess` at `crypto/frost/src/sign.rs:127` instantiates `ChaCha20Rng::from_seed(*seed.0)` and derives the binomial nonces via `Commitments::new`, which calls `C::random_nonce(secret_share, rng)` twice (`crypto/frost/src/nonce.rs:58-61`). `from_cache` (lines 268-274) is a public, deterministic function of `(algorithm, keys, seed)` only — no session index, message, or participant set enters nonce derivation. Consequently, calling `from_cache` twice with the same `CachedPreprocess` produces `AlgorithmSignMachine`s holding identical `Nonce` pairs and identical `Preprocess` commitments.

This is exactly the reachable pattern in `coordinator/src/tributary/signing_protocol.rs:123-145`: the seed is stored once under a context key in `CachedPreprocesses`, XOR-decrypted, and passed to `AlgorithmSignMachine::from_cache` on *every* `share_internal` invocation. Any retry/second attempt within the same context — driven by externally supplied `serialized_preprocesses` and `msg` — re-derives the same nonces.

In `sign` (`crypto/frost/src/sign.rs:390-398`), the actual nonce is `d + rho * e` where `rho` is a per-session binding factor computed over the co-signers' commitments and message (lines 361-371), and the share is `z = (d + rho*e) + c*lam*x`. Two shares under the same `(d, e)` but different `(rho, c)` give the attacker two linear equations recovering `d` and `e`, then `x = (z - d - rho*e) / (c*lam)`.

### Impact Explanation
Any party who can trigger a second `sign` on a machine built from the same cached seed — e.g., by feeding different preprocess sets or messages to a coordinator that caches preprocess seeds — obtains two shares that linearly reveal the victim's FROST secret share. Recovery of `t` shares (or one share combined with knowledge of other shares) yields the group private key, enabling arbitrary signature forgery for the threshold key. This converts an intermediate-protocol artifact into full credential compromise, matching the severity profile of the reference bypass (Medium/High: secret material leakage reachable with public inputs).

### Likelihood Explanation
The vulnerability requires only that a `CachedPreprocess` seed be reused for two `from_cache`/`sign` sequences, which the coordinator's design (cache-by-context, `get` before `set`, reuse on every `share_internal`) makes the default behavior whenever signing is retried or run for a second message under the same context. The attacker needs only the ability to submit preprocess bytes and a message — normal protocol participation — plus differing binding factors, which occur naturally whenever the co-signer set, their commitments, or the message changes. No collusion, timing, or secret knowledge is needed.

### Recommendation
- Bind nonce derivation to session context: mix `msg`, the sorted `included` set, or a monotonically increasing session counter into the seed before constructing `ChaCha20Rng` in `seeded_preprocess` (`crypto/frost/src/sign.rs:121-144`).
- Treat `from_cache` as one-shot: make the coordinator generate and persist a fresh seed after each `sign` (rotate `CachedPreprocesses` per attempt, not per context), and document/enforce that a given `CachedPreprocess` must be used at most once.
- Optionally reject reuse inside the library by refusing `sign` on a `from_cache`-built machine or deriving nonces as `hash(seed || session_params)` so identical shares can never be emitted for differing sessions.

### Proof of Concept
```rust
// crypto/frost — conceptual PoC
let seed = CachedPreprocess(Zeroizing::new([0x42; 32]));

// Session 1: attacker feeds preprocesses set P1 and message m1
let (m1, _pp) = AlgorithmSignMachine::from_cache(algo.clone(), keys.clone(), seed);
let (_sm1, share1) = m1.sign(preprocesses_p1, b"message-1").unwrap();

// Session 2: same seed -> identical nonces (d, e); different rho/c
let (m2, _pp) = AlgorithmSignMachine::from_cache(algo, keys, seed); // deterministic
let (_sm2, share2) = m2.sign(preprocesses_p2, b"message-2").unwrap();

// Attacker knows rho_1, rho_2, c_1, c_2, lam_i (all public):
//   z1 = d + rho1*e + c1*lam*x
//   z2 = d + rho2*e + c2*lam*x
// Solve the 2x2 system for (d, e) if lam equal, or use a third share;
// then x = (z1 - d - rho1*e) / (c1*lam)  -> secret share recovered.
```
`seeded_preprocess` (`crypto/frost/src/sign.rs:127-133`) makes nonce generation a pure function of the seed; `C::random_nonce` (`crypto/frost/src/curve/mod.rs:94-121`) contributes no freshness beyond that RNG, so the replayed intermediate state deterministically produces the same nonce pair — the direct analog of a replayed pending-session token.
