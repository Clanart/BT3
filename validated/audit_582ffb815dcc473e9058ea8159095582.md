### Title
Distribution precompile `rewards()` accepts msg.value with no refund or accounting, permanently stranding sent SEI - (File: precompiles/distribution/distribution.go)

### Summary
The distribution precompile at `0x0000000000000000000000000000000000001007` dispatches every transaction-type method through either `p.validateInput()` (which calls `pcommon.ValidateNonPayable`) or an explicit `pcommon.ValidateNonPayable(value)` check before executing, rejecting any call that carries `msg.value`. The `RewardsMethod` case is the one exception: it is dispatched straight to `p.rewards(ctx, method, args)` without any non-payable validation, and the `rewards()` implementation itself never inspects or refunds `value`. [1](#0-0) [2](#0-1) 

### Finding Description
Every other state-changing/query dispatch path in `PrecompileExecutor.Execute` enforces non-payability:
- `WithdrawValidatorCommissionMethod` explicitly calls `pcommon.ValidateNonPayable(value)`. [3](#0-2) 
- `withdrawDelegationRewards`/`withdrawMultipleDelegationRewards`/`setWithdrawAddress` all route through `p.validateInput(value, args, n)`, which calls `pcommon.ValidateNonPayable(value)` first. [4](#0-3) 

The `rewards` case, however, is dispatched with no such guard:
```go
case RewardsMethod:
    return p.rewards(ctx, method, args)
``` [1](#0-0) 

And `p.rewards` itself only validates argument count/address association — it never touches `value`, never refunds it, and never records it anywhere: [5](#0-4) 

This gap is explicitly acknowledged in the integration test suite's own documentation comment:
> "Guard quirk worth knowing: rewards() is the one phase-2 view WITHOUT a non-payable check (a value-bearing call would succeed and strand the funds), so this spec deliberately has no 'view rejects value' test." [6](#0-5) 

This is the same bug class as the external report: a callable entry point that accepts value with no bookkeeping and no path to reclaim the funds, sent by any unprivileged EVM caller (any address that calls `rewards(address)` on the precompile with non-zero `value`, whether accidentally via a mis-set `msg.value` in a wallet/dApp, or via another contract that forwards value).

### Impact Explanation
Because `rewards` is a query-style method with no payment-handling logic (unlike `withdrawDelegationRewards`/authorized variants, which use `HandlePaymentUsei` semantics in other guarded paths, or explicit rejection elsewhere), any SEI sent along with a `rewards(address)` call is transferred into the precompile's associated balance/module context during EVM value transfer for the call, but is never refunded, credited, or made recoverable through any code path in the distribution module or precompile. This constitutes a concrete, permanent loss of user funds for anyone (or any integrating contract) that mistakenly attaches value to this specific call — a real fund-freezing bug reachable directly from an ordinary EVM transaction.

### Likelihood Explanation
Likelihood is moderate: unlike `withdrawValidatorCommission`, `withdrawDelegationRewards`, etc., which are the "primary" payable-looking flows most integrators would be careful with, `rewards` is a getter/view-style function that developers/wallets are less likely to expect a value check on, and no compile-time Solidity interface enforcement stops a caller from attaching value (the `IDistr.rewards` interface signature does not mark itself `view`/`nonpayable` at the ABI level in a way that off-chain tooling reliably rejects value automatically for arbitrary raw calls or misconfigured integrations). Any transaction that calls this function with `value > 0` triggers the bug deterministically, with no special privileges required.

### Recommendation
Add a `pcommon.ValidateNonPayable(value)` check to the `RewardsMethod` case in `PrecompileExecutor.Execute` (and any other query-style dispatch branch confirmed to be missing it), consistent with how `WithdrawValidatorCommissionMethod` and `p.validateInput` enforce it elsewhere: [1](#0-0)

func (p PrecompileExecutor) validateInput(value *big.Int, args []interface{}, expectedArgsLength int) error {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return err
	}

	if err := pcommon.ValidateArgsLength(args, expectedArgsLength); err != nil {
		return err
	}

	return nil
}

func (p PrecompileExecutor) rewards(ctx sdk.Context, method *abi.Method, args []interface{}) (ret []byte, remainingGas uint64, rerr error) {
	defer func() {
		if err := recover(); err != nil {
			ret = nil
			remainingGas = 0
			rerr = fmt.Errorf("%s", err)
			return
		}
	}()

	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		rerr = err
		return
	}

	seiDelegatorAddress, err := p.accAddressFromArg(ctx, args[0])
	if err != nil {
		rerr = err
		return
	}

	req := &distrtypes.QueryDelegationTotalRewardsRequest{
		DelegatorAddress: seiDelegatorAddress.String(),
	}

	wrappedC := sdk.WrapSDKContext(ctx)
	response, err := p.distrKeeper.DelegationTotalRewards(wrappedC, req)
	if err != nil {
		rerr = err
		return
	}

	rewardsOutput := getResponseOutput(response)
	ret, rerr = method.Outputs.Pack(rewardsOutput)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}
```
