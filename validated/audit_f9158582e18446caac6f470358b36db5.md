### Title
Aggregator's move-to-vault/withdrawal broadcast RPCs lack any caller authentication - ([File: core/src/servers.rs])

### Summary
The `ClementineAggregator` gRPC service is intentionally started without any client-certificate authentication. Both `internal_send_tx` and `send_move_to_vault_tx` (as well as `withdraw`, `optimistic_payout`, `new_deposit`, `internal_get_emergency_stop_tx`) are exposed as ordinary, non-"Internal"-prefixed unary RPCs that broadcast/queue Bitcoin transactions, yet the aggregator never enforces mTLS peer-certificate checks, unlike the verifier/operator servers which use the `OnlyAggregatorAndSelf` interceptor.

### Finding Description
`create_grpc_server` builds the mTLS interceptor only `if config.client_verification` [1](#0-0) , and `create_aggregator_grpc_server` merely logs a warning if `client_verification` happens to be turned on for the aggregator, without ever requiring it [2](#0-1) . The project's own documentation confirms this is deliberate design, not a misconfiguration: "The aggregator does not enforce client certificates but does use TLS for encryption" [3](#0-2) .

Because of this, any network peer that can reach the aggregator's TCP port can call `InternalSendTx`, which takes an arbitrary raw signed transaction and queues it for broadcast via `tx_sender.insert_try_to_send` [4](#0-3) , and `SendMoveToVaultTx`, which accepts an arbitrary deposit outpoint plus a raw move-to-vault transaction and queues it for on-chain broadcast after only checking the transaction's structural shape (script pubkeys/amounts) [5](#0-4) . The verifier and operator server counterparts of sensitive methods are protected by an interceptor that restricts non-"Internal" calls to the aggregator's certificate and "Internal" calls to the entity's own certificate [6](#0-5) , but the aggregator itself has no equivalent restriction on its own inbound calls, meaning the "party the method is meant for" (the trusted clementine-backend service) is not actually enforced at the protocol layer.

### Impact Explanation
This maps to the report's access-control class: state-changing/broadcasting functions with no caller restriction. Here, `InternalSendTx` and `SendMoveToVaultTx` are broadcast-triggering calls reachable by an unauthenticated caller. However, the actual value-moving primitives are still bounded by cryptographic construction: `SendMoveToVaultTx` only queues transactions whose outputs match the exact N-of-N/security-council script and bridge amount (i.e., it cannot invent a move-to-vault transaction without a validly pre-signed one from the N-of-N), and `InternalSendTx` only broadcasts a transaction the caller already fully constructed and (if consensus-valid) needs no signature the caller doesn't already possess. Thus the exposure is best characterized as an unauthenticated **broadcasting** capability (potentially enabling premature disclosure/broadcast of already-signed protocol transactions, e.g. forcing early confirmation of a presigned move-to-vault or emergency tx) rather than a path to mint or steal bridge funds outright.

### Likelihood Explanation
Reaching this surface requires network access to the aggregator's gRPC/TCP endpoint. If the aggregator is deployed as documented (network-isolated, only reachable by the "clementine-backend" service), exploitation likelihood is low; but the code itself provides no defense-in-depth if that network boundary is ever weaker than assumed, since the documented design (not a deployment error) is to skip certificate checks entirely for the aggregator.

### Recommendation
Add an authentication layer for the aggregator's state-changing/broadcasting RPCs equivalent to the `Interceptors::OnlyAggregatorAndSelf` mechanism already used for verifier/operator servers, even if `client_verification` cannot always be true for external backend clients. At minimum, restrict `InternalSendTx`, `SendMoveToVaultTx`, `Withdraw`, `OptimisticPayout`, `InternalGetEmergencyStopTx` to a known caller (e.g., a dedicated backend client certificate), and document/enforce that these must never be exposed on a network reachable by untrusted parties.

### Proof of Concept
1. Deploy the aggregator per documented defaults (no client cert enforcement) — [2](#0-1) .
2. From any machine with network access to the aggregator's port, open a plain TLS (non-mTLS) gRPC connection.
3. Call `ClementineAggregator/InternalSendTx` with any raw transaction hex, or `ClementineAggregator/SendMoveToVaultTx` with a deposit outpoint and a structurally valid move-to-vault transaction obtained from any observed deposit flow — [7](#0-6) [8](#0-7) .
4. Observe the transaction is accepted and queued for broadcast without any verification of caller identity, confirming the absence of access control on this state-changing/broadcasting call.

pub async fn create_aggregator_grpc_server(
    config: BridgeConfig,
) -> Result<(std::net::SocketAddr, oneshot::Sender<()>), BridgeError> {
    let addr: std::net::SocketAddr = format!("{}:{}", config.host, config.port)
        .parse()
        .wrap_err("Failed to parse address")?;
    let aggregator_server = AggregatorServer::new(config.clone()).await?;
    aggregator_server.start_background_tasks().await?;

    let svc = ClementineAggregatorServer::new(aggregator_server)
        .max_encoding_message_size(config.grpc.max_message_size)
        .max_decoding_message_size(config.grpc.max_message_size);

    if config.client_verification {
        tracing::warn!("Client verification is enabled on aggregator gRPC server",);
    }

    let (server_addr, shutdown_tx) =
        create_grpc_server(addr.into(), svc, "Aggregator", &config).await?;

    match server_addr {
        ServerAddr::Tcp(socket_addr) => Ok((socket_addr, shutdown_tx)),
        _ => Err(BridgeError::ConfigError("Expected TCP address".into())),
    }
}

fn is_internal(req: &Request<()>) -> bool {
    // This normally doesn't exist but we add it in the AddMethodMiddleware
    let Some(path) = req.metadata().get("grpc-method") else {
        // No grpc method? this should not happen
        tracing::error!("Missing grpc-method header in request");
        return false;
    };
    path.as_bytes().starts_with(b"Internal")
}

impl Interceptor for Interceptors {
    #[allow(clippy::result_large_err)]
    fn call(&mut self, req: Request<()>) -> Result<Request<()>, Status> {
        match self {
            Interceptors::OnlyAggregatorAndSelf {
                our_cert,
                aggregator_cert,
            } => only_aggregator_and_self(req, our_cert, aggregator_cert),
            Interceptors::Noop => Ok(req),
        }
    }
}

#[allow(clippy::result_large_err)]
fn only_aggregator_and_self(
    req: Request<()>,
    our_cert: &CertificateDer<'static>,
    aggregator_cert: &CertificateDer<'static>,
) -> Result<Request<()>, Status> {
    let Some(peer_certs) = req.peer_certs() else {
        if cfg!(test) {
            // Test mode, we don't need to verify peer certificates
            return Ok(req);
        } else {
            // If we're not in test mode, we need to check peer certificates
            return Err(Status::unauthenticated(
                "Failed to verify peer certificate, is TLS enabled?",
            ));
        }
    };

    // IMPORTANT: Only check the leaf (end-entity) certificate, which is always the first
    // certificate in the chain. The leaf is the only certificate whose private key the peer
    // proved possession of during the TLS handshake. Checking anywhere else in the chain
    // would allow identity spoofing: an attacker could include a pinned cert as an
    // intermediate in their chain without possessing its private key.
    let Some(leaf_cert) = peer_certs.first() else {
        return Err(Status::unauthenticated("Peer certificate chain is empty"));
    };

    if is_internal(&req) {
        if leaf_cert == our_cert {
            Ok(req)
        } else {
            Err(Status::unauthenticated(
                "Unauthorized call to internal method (not self)",
            ))
        }
    } else if leaf_cert == aggregator_cert || leaf_cert == our_cert {
        Ok(req)
    } else {
        Err(Status::unauthenticated(
            "Unauthorized call to method (not aggregator or self)",
        ))
    }
