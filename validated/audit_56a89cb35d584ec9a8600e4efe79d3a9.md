### Title
Blind SSRF via unrestricted DataLayer mirror/subscription URLs - (File: `chia/data_layer/download_data.py`, `chia/data_layer/data_layer.py`)

### Summary
Any wallet user can publish a DataLayer mirror URL on-chain via `add_mirror`, and any other DataLayer node that subscribes to that store id will later fetch data from that URL using unauthenticated, unrestricted HTTP GET requests. Because there is no restriction on the URL's target address space, an attacker-supplied mirror URL can point at internal/loopback addresses on the fetching node's network, producing a blind SSRF that can be used to port-scan the victim's local network.

### Finding Description
`add_mirror` lets any wallet holder that owns/controls a DataLayer singleton publish arbitrary mirror `urls` on-chain via wallet RPC `dl_new_mirror` [1](#0-0) . These URLs propagate to any node that later subscribes to that store: `update_subscriptions_from_wallet()` reads mirrors via `dl_get_mirrors` and stores the raw URLs into the local subscription table with no scheme/host validation beyond a trailing-slash strip [2](#0-1) .

During the periodic sync loop, `fetch_and_validate()` pulls `get_available_servers_for_store()` and, for each mirror `server_info.url`, calls `insert_from_delta_file()` → `download_file()` → `http_download()`, which performs an `aiohttp` `session.get(server_info.url + "/" + filename, ...)` with no restriction on target IP/host [3](#0-2) . The caller in `fetch_and_validate()` even distinguishes connection failures from other exceptions/log messages [4](#0-3) , giving an external, attacker-controlled response differential (reachable/open port vs. connection refused/closed) exactly like the reported Open WebUI SSRF pattern. The same unrestricted-URL fetch pattern also exists in `get_downloader()`/`get_uploaders()`, which POST to attacker-influenced plugin URLs and DataLayer server URLs without validating that they are not local/internal addresses [5](#0-4) [6](#0-5) .

No code path found during this investigation performs address-space/scheme restriction (no loopback/private-range blocking) on these mirror or plugin URLs before the outbound HTTP request is made.

### Impact Explanation
Because DataLayer subscriptions and mirror sync are automatic background operations (`periodically_manage_data()`), a party can cause other DataLayer nodes that subscribe to their store id to issue outbound HTTP requests to attacker-chosen hosts/ports, including internal-network or loopback addresses of the victim's own machine or LAN. The response differential (`aiohttp.client_exceptions.ClientConnectorError` vs. other outcomes) lets the attacker infer which internal ports are open, enabling port scanning of the victim node operator's local network — matching CWE-918 impact described in the reference advisory. This is a confidentiality/network-reconnaissance impact rather than direct fund loss, consistent with a Medium-severity analog.

### Likelihood Explanation
Likelihood is moderate: exploitation requires a victim operator to explicitly subscribe to (or already own/watch) the attacker's DataLayer store id, which is a normal, expected DataLayer workflow (subscribing to a store to replicate its data). Once subscribed, the periodic sync loop will automatically attempt HTTP GETs against every mirror URL associated with that store without further user interaction, so no additional user action beyond the initial subscribe is required to trigger repeated SSRF probes.

### Recommendation
Validate mirror, downloader, and DataLayer server URLs before performing outbound HTTP(S) requests in `http_download()` (`chia/data_layer/download_data.py`), `get_downloader()`/`get_uploaders()` (`chia/data_layer/data_layer.py`), and anywhere `update_subscriptions_from_wallet()`-sourced URLs are dereferenced. Resolve the hostname and reject requests to loopback, link-local, private (RFC1918), and other non-routable/internal address ranges unless explicitly allow-listed by the node operator, and consider disabling automatic redirects to re-validate on redirect targets as well.

### Proof of Concept
1. Operator A creates a DataLayer store and calls `dl new_mirror --id <store_id> --url http://127.0.0.1:22 --amount <mojos>` (routes through `add_mirror`/`dl_new_mirror`) to publish an internal-looking URL on-chain [7](#0-6) .
2. Operator B's DataLayer node subscribes to store `<store_id>` (`data_rpc_api.subscribe`), causing `update_subscriptions_from_wallet()` to store the mirror URL [2](#0-1) .
3. On the next sync cycle, `fetch_and_validate()` iterates `servers_info` and calls `http_download()`, issuing a GET to `http://127.0.0.1:22/<filename>` from Operator B's node [8](#0-7) .
4. Operator A observes differing behavior/log timing depending on whether Operator B's port 22 (or any other probed port) is open, by publishing multiple mirror URLs against different ports/hosts and inferring success/failure of connection attempts from repeated subscribe/sync cycles, effectively port-scanning Operator B's internal network blind.

    async def get_downloader(self, store_id: bytes32, url: str) -> PluginRemote | None:
        request_json = {"store_id": store_id.hex(), "url": url}
        for d in self.downloaders:
            async with aiohttp.ClientSession() as session:
                try:
                    async with session.post(
                        d.url + "/handle_download",
                        json=request_json,
                        headers=d.headers,
                        timeout=self.client_timeout,
                    ) as response:
                        res_json = await response.json()
                        if res_json["handle_download"]:
                            return d
                except Exception as e:
                    self.log.error(f"get_downloader could not get response: {type(e).__name__}: {e}")
        return None

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
