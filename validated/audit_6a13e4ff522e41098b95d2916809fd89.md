### Title
`ReceivedOutput::read` accepts a crafted offset/TxOut pairing with no consistency check, so attacker-supplied bytes are treated as owned spendable funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
CVE-2023-50692 is a "crafted attacker-controlled input trusted as a valid object" bug class: a malicious file/parameter is supplied and the application acts on it without validating that it is legitimate. The Serai analog is `ReceivedOutput::read`, which deserializes a purportedly owned, spendable UTXO (`offset`, `TxOut`, `OutPoint`) purely from untrusted bytes and never verifies that `output.script_pubkey` is actually the P2TR script of `key + offset * G` — the invariant that `Scanner::scan_transaction` establishes when it creates `ReceivedOutput`s itself.

### Finding Description
`ReceivedOutput` couples three pieces of data:

- `offset`: the scalar offset which yields the spendable key (`key + offset * G`) [1](#0-0) 
- `output`: the `TxOut` claimed to pay that script
- `outpoint`: the claimed location of that output

When produced by `Scanner::scan_transaction`, these are consistent by construction: the scanner only emits a `ReceivedOutput` after looking up `output.script_pubkey` in the registered script map, so the stored `offset` provably corresponds to the key that `script_pubkey` pays to [2](#0-1) .

`ReceivedOutput::read` performs no such check. It reads an arbitrary scalar via `Secp256k1::read_F`, then consensus-decodes an arbitrary `TxOut` (any `script_pubkey`, any `value`) and an arbitrary `OutPoint`, and returns the object as if it were a verified owned output [3](#0-2) . Any consumer that receives `ReceivedOutput`s over an untrusted channel (the type is `Serialize`/`Read`-round-trippable and is explicitly listed in scope as an untrusted-bytes sink) will treat the forged tuple as spendable balance and feed it into `SignableTransaction::new`, which signs assuming the inputs are real and owned.

### Impact Explanation
Two reachable harms for an unprivileged party supplying crafted `ReceivedOutput` bytes:

1. **Funds reported received that are not spendable.** The attacker sets `offset` to any registered offset but `output.script_pubkey`/`value` to anything (e.g., a huge value at a script the wallet doesn't control, or a real-looking script at a nonexistent `outpoint`). Balance/accounting code accepts this as wallet-owned funds. When spending is attempted, the derived key cannot satisfy the actual on-chain script (or the outpoint doesn't exist), so the "received" funds are phantom.
2. **Corrupted signing / denial of spend.** `SignableTransaction` commits to the prevouts (script + value) of all supplied inputs in the Taproot sighash. A forged `TxOut` value for a *real* owned outpoint produces signatures over a false amount commitment, yielding an invalid transaction and stalling the multisig flow that consumed the forged input.

### Likelihood Explanation
Reachability requires only that attacker-influenced bytes reach `ReceivedOutput::read` — the parsing itself is trivially satisfied (any scalar encoding + consensus-valid `TxOut`/`OutPoint`). No cryptographic break, no malformed encoding tricks; `read_F`/`consensus_decode` happily accept the crafted fields. Severity is bounded by how an integrator sources `ReceivedOutput`s (if they only ever come from a local `Scanner`, the attack surface is the persistence/sync path), so Medium is the appropriate ceiling.

### Recommendation
Either re-derive the expected `script_pubkey` in `read`/`SignableTransaction::new` and reject mismatches, or split the type: keep `ReceivedOutput` constructible only by `Scanner`, and have `read` take the wallet's `Scanner` (or base key) so it can verify `output.script_pubkey == p2tr_script_buf(key + G * offset)` before returning.

### Proof of Concept
```rust
// Networks/bitcoin context: attacker supplies serialized bytes consumed by ReceivedOutput::read
let offset = Scalar::ZERO;                        // claims the base-key spend path
let forged = TxOut {
    value: Amount::from_sat(21_000_000_0000_0000), // arbitrary claimed value
    script_pubkey: victim_or_garbage_script,       // not p2tr_script_buf(key + G*offset)
};
let forged_outpoint = OutPoint::new(Txid::all_zeros(), 0); // nonexistent on-chain

// serialize(offset || forged || forged_outpoint) -> feed to:
let ro = ReceivedOutput::read(&mut bytes).unwrap(); // accepted, no consistency check
// `ro` is now indistinguishable from a scanner-produced output:
// balance accounting reports it as owned; SignableTransaction::new(vec![ro], ...)
// will build and sign a transaction over a phantom/misdeclared input.
```

```rust
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }
```

```rust
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
```
