### Title
Scanner reports unspendable dust outputs as received funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_transaction` classifies any output whose `script_pubkey` matches a registered script as a spendable `ReceivedOutput`, without checking that the output's value meets the dust threshold or is economically spendable. An unprivileged party can send a transaction on-chain paying dust (e.g. 1 satoshi) to a Serai Taproot key, and the scanner will report it as a received, spendable output.

### Finding Description
In `scan_transaction`, the only predicate applied to each `TxOut` is `self.scripts.get(&output.script_pubkey)` — a lookup of the script in the registered key/offset map. There is no check on `output.value`, no dust-limit check, and no check that the output could ever fund the witness/redeem cost of spending it.

```rust
if let Some(offset) = self.scripts.get(&output.script_pubkey) {
  res.push(ReceivedOutput { offset: *offset, output: output.clone(), ... });
}
``` [1](#0-0) 

This mirrors the injection class of the reference bug: attacker-controlled input (an arbitrary Bitcoin output) is accepted verbatim into a security-relevant structure (the set of spendable outputs) with no validation of a field that determines its meaning (the value). The downstream consumer acknowledges the gap — the processor had to add its own `output.balance().amount.0 >= N::DUST` filter in `get_outputs`/scanner plumbing, showing the library contract is ambiguous — but `scan_transaction`/`scan_block` themselves return dust unconditionally to any direct caller. [2](#0-1) 

Relatedly, `scan_block` scans `block.txdata` including the coinbase, whose outputs are immature for 100 blocks; the doc comment defers this to "a post-processing pass", i.e. again the API hands callers outputs that are not spendable. [3](#0-2) 

### Impact Explanation
Any output reported by `Scanner` is treated as owned, spendable funds. A dust output (below the ~294–330 sat P2TR dust limit, or simply below the fee needed to spend it) can never be profitably — or even validly — spent: it will fail relay/mining policy as part of a transaction, and consuming it in `SignableTransaction` costs more in added input/witness weight than its value contributes. The result is "funds reported received that are not spendable" — exactly the accepted impact class. Attackers can repeatedly inject such outputs at near-zero cost, inflating reported balances and polluting the output set a multisig coordinator draws inputs from.

### Likelihood Explanation
Exploitation requires only that an attacker broadcast a valid Bitcoin transaction with a dust output to a registered script — a public, unauthenticated action on-chain. No key material, no collusion, no protocol access is needed. Cost per injected output is a few hundred satoshis plus marginal fee.

### Recommendation
In `Scanner::scan_transaction` (and hence `scan_block`), reject outputs below the P2TR dust threshold (`Amount::MIN_RELAY_FEE`-style bound or the script's `dust_value()`), and document/enforce that callers must not treat returned outputs as spendable until a minimum-value and maturity check is applied. Alternatively return a tri-state (spendable / dust / immature-coinbase) so the contract is explicit rather than relying on each downstream consumer to reimplement filtering.

### Proof of Concept
1. Create `Scanner::new(key)` for an even Taproot group key (or register an offset).
2. Build a Bitcoin transaction containing a `TxOut { value: 1 sat, script_pubkey: p2tr_script_buf(key) }` and have it mined (regtest suffices).
3. Call `scanner.scan_transaction(&tx)` — it returns a `ReceivedOutput` with `value() == 1` and a valid `offset`.
4. Attempting to spend it via `SignableTransaction`/`multisig` either fails fee policy or burns more fee than the output is worth; the library nevertheless reported it as owned, spendable funds.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  /// Scan a block.
  ///
  /// This will also scan the coinbase transaction which is bound by maturity. If received outputs
  /// must be immediately spendable, a post-processing pass is needed to remove those outputs.
  /// Alternatively, scan_transaction can be called on `block.txdata[1 ..]`.
  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }
