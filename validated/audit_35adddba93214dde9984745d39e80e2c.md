### Title
Scanner Reports Immature/Unspendable Deposits as Spendable `ReceivedOutput`s With No Rejection Mechanism - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
The analog of "L1 accepts trades that L2 will reject" in Serai is `Scanner::scan_block` / `Scanner::scan_transaction` in `bitcoin_serai::wallet`. The scanner turns any transaction output whose `script_pubkey` matches a registered script into a `ReceivedOutput` — a type explicitly documented as "A spendable output" — without checking whether the output is actually spendable. Two reachable cases exist: (1) `scan_block` iterates `block.txdata` including `txdata[0]`, the coinbase transaction, whose outputs are consensus-immature and cannot be spent for 100 blocks; (2) `scan_transaction` performs no value/dust validation at all, so zero-value or sub-dust deposits are reported as received. An unprivileged party (any miner crafting a coinbase paying the multisig script, or any user broadcasting a dust/valueless deposit) can cause the wallet to report funds as received that are not spendable. [1](#0-0) [2](#0-1) 

### Finding Description
`Scanner::scan_transaction` matches solely on `self.scripts.get(&output.script_pubkey)` and immediately constructs a `ReceivedOutput` containing the offset, the `TxOut`, and the `OutPoint`. There is no check on `output.value` (the only dust filter, `output.balance().amount.0 >= N::DUST`, lives in the out-of-wallet processor loop) and no check on the transaction's position or type. `scan_block` then iterates `for tx in &block.txdata`, explicitly including `block.txdata[0]` — the coinbase — and its own doc comment concedes the resulting outputs are "bound by maturity" and pushes the burden onto callers to post-filter or remember to call `scan_transaction` on `block.txdata[1 ..]` instead. The processor's `Bitcoin::get_outputs` does skip `block.txdata[1 ..]` onward, confirming the library-level API is the only place this can be enforced and it does not enforce it. [3](#0-2) [4](#0-3) 

### Impact Explanation
A `ReceivedOutput` is the wallet crate's "spendable output" currency type: it is consumed directly by `SignableTransaction::new`, which copies `input.output` into `prevouts` and commits to `input.output.value` in the BIP-341 sighash via `Prevouts::All`. If an immature coinbase output is fed in, the threshold multisig signs a transaction that no Bitcoin node will relay or confirm — the network burns a signing session on an unspendable input. More importantly for the reporting path, the scanner API reports these deposits as confirmed received funds with no validity signal, exactly mirroring the reported bug: deposits that downstream consensus deems invalid are accepted at the entry point with no rejection mechanism. Any miner (a fully unprivileged party) can create coinbase outputs to the publicly known multisig address, and any user can create sub-dust/zero-value outputs to it. [5](#0-4) [6](#0-5) 

### Likelihood Explanation
Triggering requires no privilege: mining a block paying the multisig script (permissionless) or sending a dust/valueless output to a publicly derivable address. Exploitation requires a caller of `scan_block`/`scan_transaction` to consume results without the manual post-processing described only in a doc comment — which is a documented caveat, but the API itself neither enforces nor encodes the invariant (`ReceivedOutput` has no maturity flag), and the processor had to special-case `txdata[1 ..]` to compensate. Impact is bounded: coinbase outputs become spendable after 100 confirmations rather than being permanently lost, and invalid-input spends fail at relay rather than stealing funds.

### Recommendation
Enforce spendability inside `Scanner` rather than relying on doc-comment discipline: have `scan_block` skip `block.txdata[0]` (or tag `ReceivedOutput` with a maturity flag), and reject outputs below the dust threshold in `scan_transaction` so that a returned `ReceivedOutput` is always a spendable `ReceivedOutput`. This mirrors the report's recommendation to push validity rejection as close to the intake layer as the domain allows.

### Proof of Concept
1. A miner (or regtest `generatetoaddress` to `p2tr_script_buf(key)`) creates a coinbase transaction whose output pays the multisig's P2TR script.
2. Call `Scanner::new(key).unwrap().scan_block(&block)` — it returns a `ReceivedOutput` for `txdata[0]` (this is literally exercised in `send_and_get_output`, which then has to mine 100 blocks before the output is usable).
3. Feed that `ReceivedOutput` into `SignableTransaction::new` and produce a signed transaction; `send_raw_transaction` rejects it because the coinbase input is immature — the scanner reported funds that were not spendable.
4. Equivalently, broadcast any transaction paying `p2tr_script_buf(key)` with `value < DUST`; `scan_transaction` returns it as a `ReceivedOutput` despite it being uneconomical/rejected by the processor's dust rule. [7](#0-6)

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  /// Scan a block.
  ///
  /// This will also scan the coinbase transaction which is bound by maturity. If received outputs
  /// must be immediately spendable, a post-processing pass is needed to remove those outputs.
  /// Alternatively, scan_transaction can be called on `block.txdata[1 ..]`.
  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }

async fn send_and_get_output(rpc: &Rpc, scanner: &Scanner, key: ProjectivePoint) -> ReceivedOutput {
  let block_number = rpc.get_latest_block_number().await.unwrap() + 1;

  rpc
    .rpc_call::<Vec<String>>(
      "generatetoaddress",
      serde_json::json!([
        1,
        Address::from_script(&p2tr_script_buf(key).unwrap(), Network::Regtest).unwrap()
      ]),
    )
    .await
    .unwrap();

  // Mine until maturity
  rpc
    .rpc_call::<Vec<String>>(
      "generatetoaddress",
      serde_json::json!([100, Address::p2sh(Script::new(), Network::Regtest).unwrap()]),
    )
    .await
    .unwrap();

  let block = rpc.get_block(&rpc.get_block_hash(block_number).await.unwrap()).await.unwrap();

  let mut outputs = scanner.scan_block(&block);
  assert_eq!(outputs, scanner.scan_transaction(&block.txdata[0]));

  assert_eq!(outputs.len(), 1);
  assert_eq!(outputs[0].outpoint(), &OutPoint::new(block.txdata[0].compute_txid(), 0));
  assert_eq!(outputs[0].value(), block.txdata[0].output[0].value.to_sat());

  assert_eq!(
    ReceivedOutput::read::<&[u8]>(&mut outputs[0].serialize().as_ref()).unwrap(),
    outputs[0]
  );

  outputs.swap_remove(0)
}
