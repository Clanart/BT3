### Title
Missing Slippage Protection in `SmartWomConvert._convertFor` Enables Sandwich Attacks on `ArbWomUp3.incentiveDeposit` - ([File: wombat/SmartWomConvert.sol])

### Summary
`SmartWomConvert._convertFor()` performs an on-chain WOM→mWom swap via `IWombatRouter.swapExactTokensForTokens()` with a hardcoded `amountOutMin` of `0`, and only validates the *aggregate* result against a caller-supplied `_minRec` after the fact. When this function is reached through `ArbWomUp3._deposit()` (mode 2 path), the caller hardcodes `_minRec = 0` as well, so there is no slippage protection whatsoever for that call path, leaving ordinary users' airdrop deposits fully exposed to price manipulation/sandwich attacks by any unprivileged wallet.

### Finding Description
`SmartWomConvert._convertFor()` swaps the "buyback" portion of a user's WOM through the `womMWomPool` with the router call: [1](#0-0) 

The `amountOutMin` argument to `swapExactTokensForTokens` is hardcoded to `0`, so the swap itself has zero on-chain slippage protection, relying entirely on the post-hoc check: [2](#0-1) 

This aggregate check is only meaningful if the caller supplies a real `_minRec`. However, `ArbWomUp3._deposit()` (mode 2, the "lock" path of the airdrop program) invokes the converter with `_minRec` hardcoded to `0`: [3](#0-2) 

Since `incentiveDeposit()` is a permissionless, user-initiated function that funnels into this code path with zero user-supplied slippage input, and the pool price is derived from `IWombatRouter.getAmountOut`/`swapExactTokensForTokens` against the live WOM/mWom Wombat pool, any external actor can manipulate the pool price immediately before a victim's `incentiveDeposit` transaction (e.g., via a large swap or flash loan into `womMWomPool`), causing the victim's swap to execute at a degraded rate, and then reverse the manipulation afterward to extract the difference — a classic sandwich attack. No admin, oracle, or governance interaction is required; only an ordinary wallet transacting around the victim's transaction in the same block(s).

### Impact Explanation
The victim ends up locking a smaller amount of `mWom` into `mWomSV` than the fair-market conversion would have produced, and the difference is captured by the attacker via arbitrage on the manipulated pool. This is a direct theft of user funds reachable by any unprivileged wallet, matching the reported bug class (missing slippage/oracle protection allowing execution with high, attacker-induced slippage).

### Likelihood Explanation
Likelihood is high for any user calling `ArbWomUp3.incentiveDeposit(..., _mode == 2)`: the attack requires no special permissions, only capital to move the `womMWomPool` price and standard MEV/sandwich tooling, both readily available on public mempools.

### Recommendation
- Do not hardcode `_minRec = 0` in `ArbWomUp3._deposit()`; require the user to supply a real minimum-received amount (or compute one on-chain from `estimateTotalConversion` with a tolerance).
- In `SmartWomConvert._convertFor()`, pass a non-zero, properly derived `amountOutMin` directly into `swapExactTokensForTokens` rather than `0`, so the DEX call itself reverts on adverse price movement rather than relying solely on the aggregate post-check.

### Proof of Concept
1. Attacker observes a pending `ArbWomUp3.incentiveDeposit(amount, convertRatio, bullMode=false, mode=2)` transaction from a victim in the mempool.
2. Attacker front-runs it with a large WOM→mWom (or mWom→WOM) swap against `womMWomPool` to skew the pool price unfavorably for the upcoming buyback swap.
3. Victim's transaction executes `ArbWomUp3._deposit` → `SmartWomConvert.convert(toSwap, _convertRatio, 0, 0)` → `_convertFor`, which swaps `buybackAmount` WOM for mWom via `IWombatRouter.swapExactTokensForTokens(..., 0, ...)`; because `amountOutMin` is `0` and `_minRec` is `0`, the swap executes at the manipulated (bad) rate and cannot revert.
4. Attacker back-runs with the reverse swap to restore the pool price and realize the profit, which comes from the value the victim should have received in locked `mWom` at `mWomSV`.
