The reported bug class concerns price-oracle sandwiching in AMM-style mint/burn functions (CAP protocol, Chainlink-fed stablecoin exchange rates). Clementine's bridge does not use any price oracle or variable exchange rate for its deposit/withdrawal flow — the `move_to_vault` transaction always moves a fixed `paramset.bridge_amount` [1](#0-0) , and withdrawal payouts are constrained to be at most `bridge_amount - NON_EPHEMERAL_ANCHOR_AMOUNT` [2](#0-1) , with all custody bindings between deposit, move-to-vault txid, and withdrawal UTXO enforced via fixed database lookups rather than any price computation [3](#0-2) . There is no Chainlink or any external price feed integration in the deposit/withdraw/reimbursement code paths searched. Since there is no price-dependent conversion rate anywhere in the custody-binding logic, the "oracle update front-running" bug class has no reachable analog in this repository.
