### Title
Missing Lower-Bound Validation on `output_amount` in Optimistic Payout Allows Bridged BTC to Be Burned as Miner Fees - (File: core/src/verifier.rs)

---

### Summary

`Verifier::sign_optimistic_payout` enforces only an **upper bound** on the caller-supplied `output_amount`. There is no lower-bound check. Because the optimistic payout transaction always spends the full `bridge_amount` UTXO from the move-to-vault vault, any `output_amount` below the canonical value silently converts the difference into miner fees, permanently destroying bridged BTC.

---

### Finding Description

In `core/src/verifier.rs`, `sign_optimistic_payout` validates `output_amount` with a single one-sided inequality:

```rust
// amount in move_tx is exactly the bridge amount
if output_amount
    > self.config.protocol_paramset().bridge_amount - NON_EPHEMERAL_ANCHOR_AMOUNT
{
    return Err(...);
}
``` [1](#0-0) 

The comment itself states the intent: *"amount in move_tx is exactly the bridge amount."* The canonical expected payout is `bridge_amount - NON_EPHEMERAL_ANCHOR_AMOUNT` (confirmed by every test helper that constructs the optimistic payout). [2](#0-1) 

The check only rejects values **above** the ceiling. Any value from `0` to `bridge_amount - NON_EPHEMERAL_ANCHOR_AMOUNT` passes.

The resulting transaction structure, built by `create_optimistic_payout_txhandler`, is:

| | Amount |
|---|---|
| **Input 0** | withdrawal dust UTXO (~550 sat) |
| **Input 1** | `DepositInMove` UTXO = `bridge_amount` (e.g. 1 BTC = 100 000 000 sat) |
| **Output 0** | user payout = `output_amount` (attacker-controlled) |
| **Output 1** | non-ephemeral anchor = 240 sat |
| **Implicit fee** | `bridge_amount + ~550 - output_amount - 240` sat | [3](#0-2) 

If `output_amount = 1 sat`, the implicit fee is `≈ bridge_amount` — the entire vault UTXO goes to miners.

The aggregator's `optimistic_payout` handler performs **no amount validation at all** before forwarding to verifiers: [4](#0-3) 

The `aggregator_verification_address` guard is **optional** (config field, not required). When unset, any caller can invoke `optimistic_payout` on the aggregator RPC endpoint. [5](#0-4) 

---

### Impact Explanation

**High — permanent loss of bridged BTC.**

The optimistic payout transaction spends the full `bridge_amount` UTXO from the move-to-vault transaction. If `output_amount` is set to a value far below `bridge_amount - NON_EPHEMERAL_ANCHOR_AMOUNT`, the difference is paid as a Bitcoin miner fee and is irrecoverable. With `bridge_amount = 1 BTC` (the regtest/mainnet paramset value) and `output_amount = 1 sat`, approximately 1 BTC is destroyed per withdrawal. [6](#0-5) 

---

### Likelihood Explanation

**Low — requires the user to sign a low `output_amount`.**

The user's `input_signature` uses `TapSighashType::SinglePlusAnyoneCanPay`, which commits to the specific `output_amount` in output index 0. An external attacker cannot forge a different amount without invalidating the user's signature. The realistic trigger is a bug in client software that constructs the withdrawal signature with an incorrect (too-low) amount — exactly the class of mistake described in the seed report. When `aggregator_verification_address` is not configured, the attack surface is wider (any caller can submit), but the user's signature still binds the amount. [7](#0-6) 

---

### Recommendation

Replace the one-sided inequality with an exact equality check, matching the comment's stated invariant:

```diff
-        // amount in move_tx is exactly the bridge amount
-        if output_amount
-            > self.config.protocol_paramset().bridge_amount - NON_EPHEMERAL_ANCHOR_AMOUNT
-        {
-            return Err(eyre::eyre!(
-                "Output amount is greater than the bridge amount: {} > {}",
-                output_amount,
-                self.config.protocol_paramset().bridge_amount - NON_EPHEMERAL_ANCHOR_AMOUNT
-            )
-            .into());
-        }
+        // amount in move_tx is exactly the bridge amount; payout must equal bridge_amount - anchor
+        let expected_output = self.config.protocol_paramset().bridge_amount
+            - NON_EPHEMERAL_ANCHOR_AMOUNT;
+        if output_amount != expected_output {
+            return Err(eyre::eyre!(
+                "Output amount must equal bridge_amount - anchor ({}), got {}",
+                expected_output,
+                output_amount
+            )
+            .into());
+        }
```

Apply the same exact-equality guard in `AggregatorServer::optimistic_payout` (`core/src/rpc/aggregator.rs`) before the verifier signing round begins, so the check is enforced at the trust boundary closest to the caller. [1](#0-0) 

---

### Proof of Concept

1. User registers a valid withdrawal UTXO in the Citrea bridge contract (sends `bridge_amount` ETH).
2. User (or a buggy client) constructs a `SinglePlusAnyoneCanPay` Schnorr signature over a payout transaction whose output 0 has `value = 1 sat`.
3. Caller submits `OptimisticWithdrawParams { output_amount: 1, ... }` to the aggregator's `optimistic_payout` gRPC endpoint.
4. Aggregator performs no amount validation; forwards to all verifiers.
5. Each verifier executes `sign_optimistic_payout`. The check `1 > bridge_amount - 240` is `false`, so no error is returned. Each verifier signs.
6. Aggregator aggregates the MuSig2 partial signatures and broadcasts the optimistic payout transaction.
7. The transaction spends the `bridge_amount` vault UTXO and pays out 1 sat to the user. The remaining `bridge_amount - 241` sat is consumed as miner fee.
8. The bridged BTC is permanently destroyed. [8](#0-7) [9](#0-8)

```rust
pub fn create_optimistic_payout_txhandler(
    deposit_data: &mut DepositData,
    input_utxo: UTXO,
    output_txout: TxOut,
    user_sig: taproot::Signature,
    paramset: &'static ProtocolParamset,
) -> Result<TxHandler, BridgeError> {
    let move_txhandler: TxHandler = create_move_to_vault_txhandler(deposit_data, paramset)?;
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::NotStored,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::non_ephemeral_anchor_output(),
        ))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    Ok(txhandler)
}
