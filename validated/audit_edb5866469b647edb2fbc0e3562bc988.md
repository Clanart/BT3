### Title
Packed fixed-width field decode skips submessage-limit check before copying attacker-controlled length of bytes into message memory - (File: `upb/wire/decode.c`)

### Summary
`_upb_Decoder_DecodeFixedPacked()` copies a wire-attacker-controlled byte length (`val->size`, decoded straight off the wire as a packed-field length prefix) into the target array via `upb_EpsCopyInputStream_ReadStringEphemeral()` **without first pushing a submessage limit**, unlike its sibling packed-decode routines. `ReadStringEphemeral()` is documented to skip the very limit/end-of-stream check that would normally reject an oversized length, and to instead defer detection to a later `IsDone()` call — after the (potentially out-of-bounds) bytes have already been `memcpy`'d into the message. [1](#0-0) [2](#0-1) 

### Finding Description
`_upb_Decoder_DecodeFixedPacked` handles packed `float`/`double`/`fixed32`/`fixed64`/`sfixed32`/`sfixed64` repeated fields. `val->size` is the packed-field byte length taken directly from the wire (an ordinary varint an attacker fully controls), decoded in `_upb_Decoder_DecodeWireValue` for `kUpb_WireType_Delimited`. [3](#0-2) 

It is passed straight into `upb_EpsCopyInputStream_ReadStringEphemeral(&d->input, ptr, val->size, &sv)`: [4](#0-3) 

Compare this to the *varint*-packed and *enum*-packed variants, which call `upb_EpsCopyInputStream_PushLimit(&d->input, ptr, val->size)` first and then loop element-by-element while checking `upb_EpsCopyInputStream_IsDone()`: [5](#0-4) [6](#0-5) 

`ReadStringEphemeral()`'s own header comment states the invariant that is being violated by the fixed-packed path:

> "For efficiency, this function does not check that `size` is within the current limit or even the end of the stream. The bytes are guaranteed to be safe to read ephemerally, but they may contain garbage data that does not correspond to anything in the input. This error will be detected later, when calling `upb_EpsCopyInputStream_IsDone()`... but it may result in nonsense bytes ending up in the output." [7](#0-6) 

The check that *is* performed inside `ReadStringEphemeral()` only bounds `size` against the current physical chunk (`e->end + kSlopBytes`, i.e. the live buffer plus the 16-byte “slop”/patch region), not against the field's own delimited-length or any enclosing submessage limit: [2](#0-1) 

Because `_upb_Decoder_DecodeFixedPacked` never calls `PushLimit` for this field, an attacker can supply a packed-fixed length (`val->size`) that overruns the field's actual encoded content — and even overruns the enclosing message/submessage boundary — as long as it stays within the physical input buffer plus its trailing 16-byte slop region (which, per the class comment, is deliberately allowed to contain "unspecified" bytes past the true end of the stream, sourced from the `patch[]` staging buffer inside `struct upb_EpsCopyInputStream`). The immediately following code unconditionally `memcpy`s exactly `sv.size` (`== val->size`) bytes into the newly-allocated array storage: [8](#0-7) 

only *after* this copy does control return to the caller, which continues decoding at the advanced pointer; any resulting inconsistency is only caught the next time `IsDone()`/limit bookkeping runs on the *outer* message, i.e. strictly after the leaked/garbage bytes are already committed into message memory.

### Impact Explanation
This is the direct structural analog of CVE-2015-3237: a length value taken from untrusted wire data is used to decide how many bytes get copied into data that is subsequently exposed to the application (and, if the message is echoed/re-serialized/reflected by the consuming application — a very common pattern for RPC middleboxes, proxies, and logging), those bytes can include content the sender never supplied — either stale bytes from the library's own internal patch/slop buffer, or (when the overrun stays inside the live input buffer but crosses a submessage/field boundary) bytes belonging to unrelated sibling fields that were never intended to be exposed as this field's value. This is a wire-parsing information-disclosure/data-integrity primitive reachable from any public `upb_Decode()` call (and transitively from every language binding built on upb, e.g. Python/PHP/Ruby), not a hostile-schema or privileged-access scenario.

### Likelihood Explanation
Reachable with a single, bounded, well-formed-looking Protobuf message containing one packed fixed-width repeated field (e.g., `repeated fixed32`/`double`) whose length-delimited size prefix is deliberately inflated beyond the field's true content but still small enough to land within the 16-byte slop/patch region or within the remainder of the physical input buffer. No malicious schema, no privileged access, and no huge/unbounded payload is required — only a small, crafted length prefix. Any trusted schema with a packed fixed-numeric field is affected.

### Recommendation
Make `_upb_Decoder_DecodeFixedPacked` push a submessage limit via `upb_EpsCopyInputStream_PushLimit(&d->input, ptr, val->size)` before validating/copying the packed payload (mirroring `_upb_Decoder_DecodeVarintPacked`/`_upb_Decoder_DecodeEnumPacked`), or otherwise explicitly validate `val->size` against `upb_EpsCopyInputStream_CheckSize()`/the enclosing limit before calling `ReadStringEphemeral`, ensuring the copy cannot execute until the length has been proven to lie entirely within the legitimately-encoded field bounds.

const char* _upb_Decoder_DecodeFixedPacked(upb_Decoder* d, const char* ptr,
                                           upb_Array* arr, wireval* val,
                                           const upb_MiniTableField* field,
                                           int lg2) {
  upb_StringView sv;
  ptr = upb_EpsCopyInputStream_ReadStringEphemeral(&d->input, ptr, val->size,
                                                   &sv);
  if (!ptr) upb_ErrorHandler_ThrowError(d->err, kUpb_DecodeStatus_Malformed);
  int mask = (1 << lg2) - 1;
  if (UPB_UNLIKELY((val->size & mask) != 0 || ptr == NULL)) {
    upb_ErrorHandler_ThrowError(d->err, kUpb_DecodeStatus_Malformed);
  }
  size_t count = val->size >> lg2;
  if (count == 0) return ptr;
  _upb_Decoder_Reserve(d, arr, count);
  void* mem = UPB_PTR_AT(upb_Array_MutableDataPtr(arr),
                         arr->UPB_PRIVATE(size) << lg2, void);
  arr->UPB_PRIVATE(size) += count;
  if (upb_IsLittleEndian()) {
    memcpy(mem, sv.data, sv.size);
  } else {
    const char* src = sv.data;
    const char* src_end = src + sv.size;
    char* dst = mem;
    if (lg2 == 2) {
      for (; src < src_end; src += 4, dst += 4) {
        uint32_t x;
        memcpy(&x, src, 4);
        x = upb_BigEndian32(x);
        memcpy(dst, &x, 4);
      }
    } else {
      UPB_ASSERT(lg2 == 3);
      for (; src < src_end; src += 8, dst += 8) {
        uint64_t x;
        memcpy(&x, src, 8);
        x = upb_BigEndian64(x);
        memcpy(dst, &x, 8);
      }
    }
  }

  return ptr;

UPB_INLINE const char* upb_EpsCopyInputStream_ReadStringEphemeral(
    struct upb_EpsCopyInputStream* e, const char* ptr, size_t size,
    upb_StringView* sv) {
  UPB_ASSERT(size <= PTRDIFF_MAX);
  // Size must be within the current buffer (including slop bytes).
  const char* limit = e->end + kUpb_EpsCopyInputStream_SlopBytes;
  if ((ptrdiff_t)size > limit - ptr) {
    // For the moment, we consider this an error.  In a multi-buffer world,
    // it could be that the requested string extends into the next buffer, which
    // is not an error and should be recoverable.
    return UPB_PRIVATE(upb_EpsCopyInputStream_ReturnError)(e);
  }
  *sv = upb_StringView_FromDataAndSize(ptr, size);
  return ptr + size;
}
