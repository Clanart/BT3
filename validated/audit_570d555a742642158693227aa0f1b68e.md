### Title

Deserialized empty Schnorr aggregate verifies as a valid signature - (File: crypto/schnorr/src/aggregate.rs)

### Summary

`SchnorrAggregate::read` accepts an aggregate containing zero nonce commitments, while `SchnorrAggregate::verify` accepts an empty `keys_and_challenges` list and then checks only that `-sG == 0`. [1](#0-0) [2](#0-1)  Consequently, untrusted bytes encoding `Rs.len() == 0` and `s == 0` produce an aggregate accepted as valid despite no public key, nonce, challenge, or message being verified. [3](#0-2) 

### Finding Description

The deserialization path reads a caller-controlled `u32` count, allows that count to be zero, and then reads `s` without enforcing that at least one signature was supplied. [1](#0-0)  During verification, an empty aggregate is considered length-compatible with an empty claim list, the loop queues no `R` or public-key statements, and the only remaining equation is `-sG == 0`. [2](#0-1) 

This behavior is inconsistent with `SchnorrAggregator::complete`, which explicitly refuses to produce an aggregate when no signatures were supplied, indicating that the empty aggregate is not an intended valid signature value. [4](#0-3) 

### Impact Explanation

An unprivileged party who can submit serialized aggregate-signature bytes can forge an accepted signature for an empty verification statement. [1](#0-0) [3](#0-2)  If malformed request handling maps missing or unvalidated claims to `keys_and_challenges == []`, the verifier will accept the forged aggregate without any signer participating. [2](#0-1) 

### Likelihood Explanation

The required attacker-controlled bytes are minimal and deterministic: a zero count followed by the canonical encoding of scalar zero. [1](#0-0)  Exploitation requires the verifier to invoke this API with an empty claim list, so deployments that always supply a fixed nonempty statement are not affected. [5](#0-4) 

### Recommendation

Reject empty aggregates in `SchnorrAggregate::read` and defensively reject `keys_and_challenges.is_empty()` or `self.Rs.is_empty()` in `verify`. [1](#0-0) [6](#0-5)  Add a regression test asserting that the serialized empty aggregate below fails verification. [7](#0-6) 

### Proof of Concept

```rust
use ciphersuite::{Ciphersuite, group::ff::PrimeField};
use dalek_ff_group::Ristretto;
use schnorr::aggregate::SchnorrAggregate;

// Encode an aggregate with zero R values and s = 0.
let mut encoded = 0u32.to_le_bytes().to_vec();
encoded.extend(<Ristretto as Ciphersuite>::F::ZERO.to_repr().as_ref());

let aggregate =
  SchnorrAggregate::<Ristretto>::read(&mut encoded.as_slice()).unwrap();

// Accepted because there are no per-signature statements and -0 * G is identity.
assert!(aggregate.verify(b"example verifier domain", &[]));
```
