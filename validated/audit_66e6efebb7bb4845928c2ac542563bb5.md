`SchnorrAggregate::verify` accepts an empty aggregate signature (empty `Rs`, `s = 0`), which `SchnorrAggregator::complete` can never produce — ([File: crypto/schnorr/src/aggregate.rs](crypto/schnorr/src/aggregate.rs))

### Summary
Analogous to CL-2020-18 (`FastAggregateVerify` edge-case inconsistencies across BLS libraries for empty pubkey sets / infinity signatures), Serai's half-aggregation verifier in `crypto/schnorr` accepts an aggregate signature over an empty signer set. `SchnorrAggregator::complete` explicitly refuses to emit an aggregate when zero signatures were aggregated (returns `None`), yet `SchnorrAggregate::verify` treats the empty case as valid: with `Rs.len() == 0 == keys_and_challenges.len()`, the only remaining term is `(-s, G)`, so `s = 0` makes the multiexp evaluate to the identity and `verify` returns `true`. [1](#0-0) [2](#0-1) 

### Finding Description
`SchnorrAggregate::verify` performs only a length-equality check (`self.Rs.len() != keys_and_challenges.len()`), then builds the pairing-style sum `Σ z_i·R_i + Σ z_i·c_i·K_i − s·G` and checks it equals the identity. For an empty input, the sum reduces to `−s·G`, which is the identity whenever `s == 0`. [3](#0-2) 

`SchnorrAggregate::read` happily deserializes this object: a `u32` length of `0`, zero points, then a single scalar `0` — a 36-byte payload fully controlled by an unprivileged party. [4](#0-3) 

The same function additionally performs no identity/torsion rejection on the `Rs` it deserializes or the keys in `keys_and_challenges`: any entry where both `R_i` and `K_i` are the identity contributes `z·𝒪 + z·c·𝒪 = 𝒪` regardless of the weight `z`, so such "phantom signers" can be appended to (or wholly constitute) an aggregate that still verifies. `C::read_G` only enforces canonical encoding, and the identity has a canonical encoding on the dalek-ff-group curves (e.g., 32 zero bytes for Ristretto/Ed25519). This mirrors the disclosure's root cause — libraries disagreeing on whether identity/empty inputs are admissible in aggregate verification. [5](#0-4) 

### Impact Explanation
The verifier formula is incorrect at the boundary: `SchnorrAggregate::verify` returns `true` for a signature that no `SchnorrAggregator` could ever emit (`complete` returns `None` for an empty input) and that binds to no public key. Any caller that interprets `verify(...) == true` as "the listed signers produced valid signatures" — e.g., `verify_aggregate` in `coordinator/tributary/src/tendermint/mod.rs`, which checks only `signers.len() == aggregate.Rs().len()` before calling `aggregate.verify` — accepts a forged aggregate attesting an empty or padded signer set. Phantom identity-key entries likewise let a caller's signer list claim signatures that were never produced. [6](#0-5) 

### Likelihood Explanation
The forged object is 36 attacker-controlled bytes (`0x00000000 || s=0`) fed through `SchnorrAggregate::read` into `verify`; no secret material, collusion, or protocol position is required. Whether it yields consensus-level impact depends on the caller checking signer weight separately, but as a library-level verifier inconsistency (producer rejects, verifier accepts; and identity points pass unfiltered) it is directly reachable and deterministic. Medium severity.

### Recommendation
- In `SchnorrAggregate::verify`, return `false` when `keys_and_challenges` is empty.
- Reject identity points for `Rs` and for the public keys in `keys_and_challenges` (and/or torsioned components on Ed25519), matching the strictness documented for `SchnorrSignature` in `crypto/schnorr/src/lib.rs` lines 36-41.
- Alternatively/additionally, have `read` reject `len == 0`, keeping deserialization consistent with `SchnorrAggregator::complete`'s `None` for empty input.

  pub fn verify(&self, dst: &'static [u8], keys_and_challenges: &[(C::G, C::F)]) -> bool {
    if self.Rs.len() != keys_and_challenges.len() {
      return false;
    }

    let mut digest = DigestTranscript::<C::H>::new(dst);
    digest.domain_separate(b"signatures");
    for (_, challenge) in keys_and_challenges {
      digest.append_message(b"challenge", challenge.to_repr());
    }

    let mut pairs = Vec::with_capacity((2 * keys_and_challenges.len()) + 1);
    for (i, (key, challenge)) in keys_and_challenges.iter().enumerate() {
      let z = weight(&mut digest);
      pairs.push((z, self.Rs[i]));
      pairs.push((z * challenge, *key));
    }
    pairs.push((-self.s, C::generator()));
    multiexp_vartime(&pairs).is_identity().into()
  }

  pub fn complete(mut self) -> Option<SchnorrAggregate<C>> {
    if self.sigs.is_empty() {
      return None;
    }

    let mut aggregate = SchnorrAggregate { Rs: Vec::with_capacity(self.sigs.len()), s: C::F::ZERO };
    for i in 0 .. self.sigs.len() {
      aggregate.Rs.push(self.sigs[i].R);
      aggregate.s += self.sigs[i].s * weight::<_, C::F>(&mut self.digest);
    }
    Some(aggregate)
  }
