### Title
Unauthenticated access to `ClementineAggregator::internal_get_emergency_stop_tx` when `client_verification=false` bypasses the internal-method gate - (File: core/src/rpc/interceptors.rs)

### Summary
The `Internal*`-prefixed gRPC method authorization gate (`is_internal` check requiring the caller's leaf certificate to equal the aggregator's own cert) is implemented exclusively inside `only_aggregator_and_self`. When `client_verification` is `false`, the server installs `Interceptors::Noop` instead, which performs no check whatsoever, so any caller reaching the aggregator's public gRPC port can invoke `internal_get_emergency_stop_tx` with attacker-chosen txids and receive encrypted emergency-stop transaction data.

### Finding Description
The claimed binding is: caller reaching an `Internal*`-prefixed method == the aggregator itself, enforced via `is_internal(&req)` combined with `leaf_cert == our_cert` inside `only_aggregator_and_self` [1](#0-0) [2](#0-1) .

This equality check exists only within the `OnlyAggregatorAndSelf` interceptor variant; the other variant, `Interceptors::Noop`, is a pure pass-through that returns `Ok(req)` unconditionally, performing no identity or "internal-ness" check at all [3](#0-2) .

Which interceptor gets installed is decided at server construction time based on `config.client_verification`: when `client_verification` is `false`, TLS is configured without a client CA root and `Noop` is used instead of `OnlyAggregatorAndSelf` [4](#0-3) . Since `create_aggregator_grpc_server` merely warns (does not refuse) when client verification is disabled, an operator/deployment can run the aggregator's public gRPC port with `client_verification=false`, and every method — including all `Internal*`-prefixed ones — becomes reachable by any unauthenticated caller [5](#0-4) .

Under this configuration, an attacker sends a plain `GetEmergencyStopTxRequest { txids: [...] }` to the aggregator's port and the `Noop` interceptor forwards the request straight to `ClementineAggregator::internal_get_emergency_stop_tx` without any equality check between the caller and the aggregator's own certificate, returning the encrypted emergency-stop transactions for the requested txids.

### Impact Explanation
This is a premature disclosure of a protocol commitment: encrypted emergency-stop transactions are meant to be revealed only through the intended internal/self-call flow, not to arbitrary public callers. Leaking them ahead of schedule lets an attacker learn about and potentially race emergency-stop broadcast timing against the honest recovery flow, which is relevant to move-to-vault UTXO availability. This matches the High-severity category "premature disclosure of a protocol commitment." The exposure is repeatable for any txid the attacker chooses to query and applies across all deposits/move-txids known or guessed by the attacker, for the lifetime of the misconfigured deployment.

### Likelihood Explanation
The vulnerability is entirely conditioned on the deployment configuration `client_verification=false`. If `true` (which appears to be the intended production security posture, given the "warn" log when disabled indicates it's expected to normally be enabled), `OnlyAggregatorAndSelf` is installed and the `is_internal`/self-cert equality check fully closes this gap. So this issue is real but strictly configuration-gated: it is not exploitable against a correctly configured, TLS-mutual-auth-enabled aggregator. No BTC cost is required to exploit it — only network access to the aggregator's gRPC port and knowledge/guessing of target txids.

### Recommendation
Do not rely solely on `client_verification` to gate `Internal*` methods. Either (a) always enforce the `Internal*`-prefix caller-identity check regardless of the configured interceptor (e.g., make `is_internal` checking mandatory in a base layer applied before/independent of `Noop`), or (b) refuse to start the aggregator server with `Internal*` RPCs exposed when `client_verification=false`, or (c) require a separate, always-on authentication mechanism (e.g., a loopback-only bind or a shared secret) for `Internal*`-prefixed RPCs independent of the general client-verification TLS setting.
