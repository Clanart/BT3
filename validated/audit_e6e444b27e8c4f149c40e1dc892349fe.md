### Title
Governance vote can set `kip71.gastarget` to `0`, causing a division-by-zero panic in `NextMagmaBlockBaseFee` during block validation and mining - ([File: params/kip71_config.go])

### Summary
`kaiax/gov` allows the governing node (or authorized voters) to set governance parameters via `governance_vote`. Unlike `Kip71BaseFeeDenominator`, which explicitly rejects `0`, the `Kip71GasTarget` and `Kip71MaxBlockGasUsedForBaseFee` parameters use `noopFormatChecker`, which accepts *any* `uint64` value including `0`, with no additional consistency check performed in `checkConsistency`.

### Finding Description
The parameter definitions in `Params` show that `Kip71BaseFeeDenominator` enforces `v != 0`, but `Kip71GasTarget` and `Kip71MaxBlockGasUsedForBaseFee` use `noopFormatChecker`, which always returns `true`: [1](#0-0) 

The `checkConsistency` function in the header governance module explicitly whitelists `gov.Kip71GasTarget` and `gov.Kip71MaxBlockGasUsedForBaseFee` among parameters that receive "no more checks" beyond `NewVoteData()`'s format check: [2](#0-1) 

The `Vote` RPC handler only checks the caller's permission (governing node in single mode) and calls `checkConsistency`, meaning a `governance.vote` call with `kip71.gastarget=0` is accepted and queued to be embedded into the block header: [3](#0-2) 

Once accepted, `GasTarget` (and equally `MaxBlockGasUsedForBaseFee`, which also lacks a `!= 0` check) is used unconditionally as a divisor in `NextMagmaBlockBaseFee`, which is invoked on every node when validating/computing the next block's base fee: [4](#0-3) 

When `parentGasUsed != gasTarget` (which will happen for essentially every real block if `gasTarget == 0`), the code executes `x.Div(x, new(big.Int).SetUint64(gasTarget))` with a zero divisor. `big.Int.Div` panics on division by zero in Go's standard library, and this occurs deterministically for every node that processes the new header (both proposer while building the block and every honest node validating it via `VerifyMagmaHeader`).

### Impact Explanation
This causes a deterministic panic/crash on every node processing the affected block — a chain-wide halt at the moment the malicious `gastarget=0` value takes effect. Because the same code path (`NextMagmaBlockBaseFee`) is invoked identically by the block validator (`blockchain/block_validator.go`) and block-building code (`work/worker.go`, `blockchain/chain_makers.go`), all nodes hit the same panic at the same block, resulting in a full liveness failure of the network rather than a divergence between nodes. This is reachable purely through the governance parameter voting mechanism (an explicitly in-scope category) and requires no p2p/consensus-message manipulation, malicious peer, or leaked key — only a single `governance_vote` RPC call by an authorized voter (the governing node in single mode).

### Likelihood Explanation
Likelihood depends on the governance mode: in `single` mode only the designated `GoverningNode` can cast this vote, so it requires that account to be malicious or compromised — moderate likelihood, comparable to the original Mover finding where "admin" controls unchecked fee parameters. In `ballot`/`none` governance modes the vote permission check in `api.go` (`gMode == "single" && voter != gp.GoverningNode`) is bypassed for other modes, which would need further review to confirm whether broader voter sets are permitted; this could raise the likelihood on networks not using single mode.

### Recommendation
Add explicit non-zero (and reasonable upper-bound) `FormatChecker`s for `Kip71GasTarget` and `Kip71MaxBlockGasUsedForBaseFee` in `kaiax/gov/param.go`, mirroring the existing `v != 0` check already present for `Kip71BaseFeeDenominator`. Additionally, add a defensive guard in `NextMagmaBlockBaseFee` (`params/kip71_config.go`) to reject or clamp a zero `GasTarget`/`MaxBlockGasUsedForBaseFee` before performing the division, consistent with the existing zero-guard already present for `BaseFeeDenominator` at line 71-73 of that file.

### Proof of Concept
1. As the governing node (single governance mode), call the JSON-RPC:
   `governance_vote("kip71.gastarget", 0)`
2. The vote passes `NewVoteData` (uses `noopFormatChecker`) and `checkConsistency` (no dedicated check for this parameter), and is queued via `PushMyVotes`.
3. When the vote is embedded in the header at the next epoch block, `GetParamSet` returns `GasTarget = 0` for subsequent blocks.
4. On the next block after that epoch, any node (proposer building or validator verifying) calls `KIP71Config.NextMagmaBlockBaseFee` with the actual `parentGasUsed` (almost certainly not exactly `0`), entering the `parentGasUsed > gasTarget` branch and executing `x.Div(x, big.NewInt(0))`, which panics.
5. Every node that reaches this code panics simultaneously, halting the chain.

Note: I was not able to fully verify the exact permission model for `ballot`/`none` governance modes (whether an unauthorized/arbitrary sender's vote could also reach this same code path) within the available tool budget; this would need further confirmation, but the single-mode governing-node path is confirmed reachable and exploitable as described.

func (api *headerGovAPI) Vote(name string, value any) (string, error) {
	var (
		voter     = api.h.nodeAddress
		nextBlock = api.h.Chain.CurrentBlock().NumberU64() + 1
		gp        = api.h.GetParamSet(nextBlock)
		gMode     = gp.GovernanceMode
	)

	if gMode == "single" && voter != gp.GoverningNode {
		return "", ErrVotePermissionDenied
	}

	vote := headergov.NewVoteData(voter, name, value)
	if vote == nil {
		return "", ErrInvalidKeyValue
	}

	if gov.DeprecatedAt(vote.Name(), api.h.ChainConfig.Rules(new(big.Int).SetUint64(nextBlock))) {
		return "", ErrDeprecatedVote
	}

	err := api.h.checkConsistency(nextBlock, vote)
	if err != nil {
		return "", err
	}

	// TODO-kaiax: add removevalidator vote check

	api.h.PushMyVotes(vote)
	return "(kaiax) Your vote is prepared. It will be put into the block header or applied when your node generates a block as a proposer. Note that your vote may be duplicate.", nil
}

func (kc *KIP71Config) NextMagmaBlockBaseFee(parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) *big.Int {
	// governance parameters
	lowerBoundBaseFee := new(big.Int).SetUint64(kc.LowerBoundBaseFee)
	upperBoundBaseFee := new(big.Int).SetUint64(kc.UpperBoundBaseFee)
	makeEvenByCeil(lowerBoundBaseFee)
	makeEvenByFloor(upperBoundBaseFee)

	// If the parent is the magma disabled block or genesis, then return the lowerBoundBaseFee (default 25ston)
	if parentHeaderNumber.Cmp(new(big.Int).SetUint64(0)) == 0 || parentHeaderBaseFee == nil {
		return makeEvenByFloor(lowerBoundBaseFee)
	}

	var baseFeeDenominator *big.Int
	if kc.BaseFeeDenominator == 0 {
		// To avoid panic, set the fluctuation range small
		baseFeeDenominator = new(big.Int).SetUint64(64)
	} else {
		baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
	}
	gasTarget := kc.GasTarget
	upperGasLimit := kc.MaxBlockGasUsedForBaseFee

	// check the case of upper/lowerBoundBaseFee is updated by governance mechanism
	parentBaseFee := parentHeaderBaseFee
	if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
		parentBaseFee = upperBoundBaseFee
	} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
		parentBaseFee = lowerBoundBaseFee
	}

	// upper gas limit cut off the impulse of used gas to upper bound
	parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
	if parentGasUsed == gasTarget {
		return makeEvenByFloor(parentBaseFee)
	} else if parentGasUsed > gasTarget {
		// shortcut. If parentBaseFee is already reached upperbound, do not calculate.
		if parentBaseFee.Cmp(upperBoundBaseFee) == 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		// If the parent block used more gas than its target,
		// the baseFee of the next block should increase.
		// baseFeeDelta = max(1, parentBaseFee * (parentGasUsed - gasTarget) / gasTarget / baseFeeDenominator)
		gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := math.BigMax(x.Div(y, baseFeeDenominator), common.Big1)

		nextBaseFee := x.Add(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(upperBoundBaseFee) > 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	} else {
		// shortcut. If parentBaseFee is already reached lower bound, do not calculate.
		if parentBaseFee.Cmp(lowerBoundBaseFee) == 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		// Otherwise if the parent block used less gas than its target,
		// the baseFee of the next block should decrease.
		// baseFeeDelta = parentBaseFee * (gasTarget - parentGasUsed) / gasTarget / baseFeeDenominator
		gasUsedDelta := new(big.Int).SetUint64(gasTarget - parentGasUsed)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := x.Div(y, baseFeeDenominator)

		nextBaseFee := x.Sub(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(lowerBoundBaseFee) < 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
