## Finding [1](#0-0) 

### Title
Silent, unconfirmed rewrite of a repository's git remote URL from stale GitHub API `owner/name` lookup enables repo-jacking / silent push-redirection - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
When Desktop refreshes a repository's associated GitHub metadata, it re-resolves the repository purely by the `owner/name` pair parsed from the existing git remote URL, fetches fresh data from the GitHub API for that `owner/name`, and — if a few loose heuristic conditions hold — silently runs `git remote set-url` to point the local `origin` remote at whatever `clone_url` the API returned, with no user confirmation. Because the lookup key is `owner/name` and not GitHub's stable repository ID, an attacker who acquires an abandoned `owner/name` (via GitHub's classic "repository/organization takeover" pattern: original owner renames/deletes/transfers the repo and the name becomes claimable) can cause any Desktop client that still tracks that name to have its remote silently repointed to the attacker's repository on the next background refresh.

### Finding Description
The refresh flow resolves and refreshes GitHub metadata like this: [2](#0-1) 

`matchGitHubRepository` derives `owner`/`name` solely from parsing the current remote URL string — there is no repository ID pinning: [3](#0-2) 

That `owner`/`name` pair is then used to hit the live GitHub API (`api.fetchRepository(owner, name)`), and whatever repository currently exists at that `owner/name` slug is treated as authoritative and fed into `updateRemoteUrl`: [4](#0-3) 

The only gates before `gitStore.setRemoteURL` is called are:
1. `protocolsMatch` — both old and new URL use the same scheme (ssh vs https). Trivial for an attacker to match.
2. `remoteUrlUnchanged` — the *current* local remote still matches the *previously cached* `gitHubRepository.cloneURL`. This only proves the user hasn't manually customized the remote; it does nothing to verify that the *new* API response actually refers to the same underlying repository.
3. `!urlsMatch` — the API's `clone_url` differs from the current remote, i.e., something changed.

None of these checks verify repository identity (e.g., GitHub's numeric repo `id`, or that the returned repo's default branch/history is continuous with what's cached). Once these three conditions are true, `gitStore.setRemoteURL` executes `git remote set-url` unconditionally and silently: [5](#0-4) [6](#0-5) 

This exact rewrite path was intentionally added to handle legitimate repo renames (see changelog entry "`[Fixed] Update the remote url when a repository's name changes on GitHub - #8590`") [7](#0-6) , but the implementation trusts the API response for the stale `owner/name` unconditionally, which is exactly the scenario abused in GitHub "repo-jacking": if the legitimate owner renames their account/org or deletes/transfers the repo, the old `owner/name` becomes claimable by any third party. Once claimed, `repos/{owner}/{name}` on the GitHub API returns the attacker's repository, and Desktop will silently reprogram the user's `origin` remote to the attacker's `clone_url` on the next background refresh (`_refreshRepository` → `repositoryWithRefreshedGitHubRepository`), with no dialog, confirmation, or diff shown to the user.

### Impact Explanation
After the silent rewrite, all subsequent `git push`/`git fetch`/`git pull` operations for that repository target the attacker-controlled remote instead of the user's real repository:
- Pushes (including private code, credentials embedded in commit history, etc.) go to the attacker's repository — a confidentiality and integrity breach of "what the user pushes."
- Fetches/pulls bring in attacker-controlled history/refs, which Desktop will then present to the user as trusted content from "their" repository, potentially seeding malicious commits, submodules, or hooks into subsequent work.
- No corruption warning is shown; the change is transparent to the user because Desktop still displays the same local repository name/path.

This satisfies the report's valid-impact bar: attacker controls a GitHub API object (the reclaimed repository at the stale `owner/name`) and the result is silent corruption of what the user pushes/fetches, without requiring local access, admin rights, or social engineering beyond passively waiting for the name to be reused.

### Likelihood Explanation
Requires only that: (1) the original repository's `owner/name` becomes available (owner renames account/org, or repo is renamed/deleted/transferred — a routine occurrence), and (2) an attacker registers that `owner/name` on GitHub with a matching-protocol clone URL. Desktop performs this refresh automatically and periodically as part of normal repository refresh (`_refreshRepository` → `repositoryWithRefreshedGitHubRepository`), so no unusual user action is needed beyond keeping the app open with the affected repository present — a background/passive trigger.

### Recommendation
Do not treat `owner/name` API responses as authoritative for a URL rewrite. Before calling `setRemoteURL`, verify repository identity continuity, e.g.:
- Compare the API repository's stable numeric `id` (or `node_id`) against the previously cached `gitHubRepository`'s ID, and only proceed if they match (a true rename preserves the ID; a repo-jacked slug returns a different ID).
- If the ID differs (or is unavailable), do not silently rewrite the remote — instead surface a prompt/banner asking the user to confirm before changing `origin`.

### Proof of Concept
1. Victim clones `https://github.com/alice/project` in Desktop; `gitHubRepository.cloneURL` is cached as this URL.
2. Alice renames her GitHub account (or deletes/transfers `project`), freeing the `alice/project` slug.
3. Attacker registers account `alice` (or creates a repo named `project` under a reclaimed identical path resolution) with `clone_url` pointing to an attacker-controlled repo, using the same protocol (https).
4. On the victim's next automatic repository refresh, `_refreshRepository` → `repositoryWithRefreshedGitHubRepository` calls `matchGitHubRepository` (owner=`alice`, name=`project`) and `api.fetchRepository('alice','project')`, which now returns the attacker's repo data [8](#0-7) .
5. `updateRemoteUrl` sees `protocolsMatch = true`, `remoteUrlUnchanged = true` (victim hasn't touched the remote), `urlsMatch = false` (new clone_url differs) and calls `gitStore.setRemoteURL('origin', <attacker clone_url>)` [9](#0-8) , silently rewriting `origin` via `git remote set-url`.
6. The victim's next `git push`/`fetch` in Desktop silently targets the attacker's repository.

import { IAPIRepository } from '../../api'
import { GitStore } from '../git-store'
import { urlMatchesRemote } from '../../repository-matching'
import * as URL from 'url'
import { GitHubRepository } from '../../../models/github-repository'

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

  private async repositoryWithRefreshedGitHubRepository(
    repository: Repository
  ): Promise<Repository> {
    const repoStore = this.repositoriesStore
    const match = await this.matchGitHubRepository(repository)

    // TODO: We currently never clear GitHub repository associations (see
    // https://github.com/desktop/desktop/issues/1144). So we can bail early at
    // this point.
    if (!match) {
      return repository
    }

    const { account, owner, name } = match
    const { endpoint } = account
    const api = API.fromAccount(account)
    const apiRepo = await api.fetchRepository(owner, name)

    if (apiRepo === null) {
      // If the request fails, we want to preserve the existing GitHub
      // repository info. But if we didn't have a GitHub repository already or
      // the endpoint changed, the skeleton repository is better than nothing.
      if (endpoint !== repository.gitHubRepository?.endpoint) {
        const ghRepo = await repoStore.upsertGitHubRepositoryFromMatch(match)
        return repoStore.setGitHubRepository(repository, ghRepo)
      }

      return repository
    }

    if (repository.gitHubRepository) {
      const gitStore = this.gitStoreCache.get(repository)
      await updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)
    }

    const ghRepo = await repoStore.upsertGitHubRepository(endpoint, apiRepo)
    const freshRepo = await repoStore.setGitHubRepository(repository, ghRepo)

    await this.refreshBranchProtectionState(freshRepo)
    return freshRepo
  }

export function matchGitHubRepository(
  accounts: ReadonlyArray<Account>,
  remote: string
): IMatchedGitHubRepository | null {
  for (const account of accounts) {
    const htmlURL = getHTMLURL(account.endpoint)
    const { hostname } = URL.parse(htmlURL)
    const parsedRemote = parseRemote(remote)

    if (parsedRemote !== null && hostname !== null) {
      if (parsedRemote.hostname.toLowerCase() === hostname.toLowerCase()) {
        return { name: parsedRemote.name, owner: parsedRemote.owner, account }
      }
    }
  }

  return null
}
