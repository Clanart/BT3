### Title
Unprivileged depositor can create outputs of privileged internal kinds (Branch/Change/Forwarded) by paying to deterministically-derived internal offset addresses - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary

The bug class in CVE-2022-21701 is privilege escalation: an actor holding permission to create only one resource type (Kubernetes Gateway API `gateways`) uses it to create other resource types they should not be able to create (`Pod`s). The Serai analog lives in `bitcoin-serai`'s `Scanner`: the scanner recognizes received outputs purely by `script_pubkey`, and the processor derives all of its internal output kinds (`Branch`, `Change`, `Forwarded`) from fixed, publicly computable scalar offsets over the group key. Any unprivileged Bitcoin user — who should only be able to create `External` deposits — can send funds to an internal offset address and thereby cause the processor to register an output classified as an internal kind.

### Finding Description

`Scanner` is a `script_pubkey → offset` map with no authentication of who created the output. `Scanner::new` registers the base (External) script, and `register_offset` registers `p2tr_script_buf(key + G*offset)` for each offset [1](#0-0) . `scan_transaction` then reports any output whose `script_pubkey` matches, returning the associated offset [2](#0-1) .

The processor constructs the scanner with four fixed offsets: `External = Scalar::ZERO`, and `Branch`/`Change`/`Forwarded` = `Secp256k1::hash_to_F(b"Serai Bitcoin Output Offset", b"branch"|"change"|"forward")` — public constants [3](#0-2) . The internal deposit addresses are therefore publicly derivable by anyone who knows the multisig group key (which is on-chain in every P2TR output it receives).

`Bitcoin::get_outputs` then assigns `output.kind` purely from `kinds[offset_repr]` — the scanned offset — and only attaches the extracted Serai `data` (the InInstruction carrying the depositor's intended action) when `kind == OutputType::External` [4](#0-3) . A malicious sender who pays to a `Branch`/`Change`/`Forwarded` offset script produces a `ReceivedOutput`/`Output` of an internal kind: a resource type an external party was never meant to create. Note `Output::key()` reconstructs the key by subtracting `offset*G`, so the forged-kind output still passes the `assert_eq!(output.key(), key)` consistency check in the scanner loop [5](#0-4) [6](#0-5) .

### Impact Explanation

External parties escalate "send a deposit" into "create a `Branch`/`Change`/`Forwarded`-classified output". Because `data` is only attached to `External` outputs, such an output is processed as protocol-internal funds rather than a user deposit carrying an InInstruction [7](#0-6) . Depending on downstream handling of internal kinds, this corrupts balance accounting and the intent associated with funds: an attacker-credited output can be treated as protocol change/branch liquidity while the attacker's declared deposit never materializes as instructed, enabling griefing of the accounting layer and mis-attribution of funds flows at minimum.

### Likelihood Explanation

The internal addresses are computable offline: `key + G*hash_to_F(KEY_DST, b"change")` etc., then `p2tr_script_buf`. Any Bitcoin user can send to them in a normal transaction; the scanner will match it with probability 1 on the parity condition (register_offset already incremented to an even point). No privileged access, collusion, or validator misbehavior is needed — only the ability to send Bitcoin transactions, which is the reachability criterion.

### Recommendation

Authenticate output kinds rather than deriving them purely from script equality. Options: require `data`/InInstruction presence for classification, or bind the offset class into a spend-time proof (e.g., only treat an output as `Change`/`Branch`/`Forwarded` if it was created by a transaction the multisig itself signed). At minimum, treat unexpected payments to internal offset scripts as `External`-with-no-data anomalies and flag them rather than silently classifying by offset.

### Proof of Concept

// Attacker knows the multisig's tweaked group key `key` (public, on-chain).
// Compute the internal Change offset exactly as the processor does:
const KEY_DST: &[u8] = b"Serai Bitcoin Output Offset";
let change_offset = Secp256k1::hash_to_F(KEY_DST, b"change");
// Walk to the even-parity point exactly as register_offset does:
let mut offset = change_offset;
while p2tr_script_buf(key + (ProjectivePoint::GENERATOR * offset)).is_none() {
    offset += Scalar::ONE;
}
let internal_addr = p2tr_script_buf(key + (ProjectivePoint::GENERATOR * offset)).unwrap();

// Attacker broadcasts a normal Bitcoin tx paying `internal_addr`.
// In Bitcoin::get_outputs, scanner.scan_transaction matches the script_pubkey,
// offset resolves to the Change offset, and:
//   kind = kinds[offset_repr]  // == OutputType::Change
// while `data` stays empty since kind != External.
// Result: an externally-initiated payment is registered as an internal
// protocol output kind the attacker had no permission to create.

pub struct Scanner {
  key: ProjectivePoint,
  scripts: HashMap<ScriptBuf, Scalar>,
}

impl Scanner {
  /// Construct a Scanner for a key.
  ///
  /// Returns None if this key can't be scanned for.
  pub fn new(key: ProjectivePoint) -> Option<Scanner> {
    let mut scripts = HashMap::new();
    scripts.insert(p2tr_script_buf(key)?, Scalar::ZERO);
    Some(Scanner { key, scripts })
  }

  /// Register an offset to scan for.
  ///
  /// Due to Bitcoin's requirement that points are even, not every offset may be used.
  /// If an offset isn't usable, it will be incremented until it is. If this offset is already
  /// present, None is returned. Else, Some(offset) will be, with the used offset.
  ///
  /// This means offsets are surjective, not bijective, and the order offsets are registered in
  /// may determine the validity of future offsets.
  ///
  /// The offsets registered must be securely generated. Arbitrary offsets may introduce a script
  /// path into the output, allowing the output to be spent by satisfaction of an arbitrary script
  /// (not by the signature of the key).
  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

fn scanner(
  key: ProjectivePoint,
) -> (Scanner, HashMap<OutputType, Scalar>, HashMap<Vec<u8>, OutputType>) {
  let mut scanner = Scanner::new(key).unwrap();
  let mut offsets = HashMap::from([(OutputType::External, Scalar::ZERO)]);

  let zero = Scalar::ZERO.to_repr();
  let zero_ref: &[u8] = zero.as_ref();
  let mut kinds = HashMap::from([(zero_ref.to_vec(), OutputType::External)]);

  let mut register = |kind, offset| {
    let offset = scanner.register_offset(offset).expect("offset collision");
    offsets.insert(kind, offset);

    let offset = offset.to_repr();
    let offset_ref: &[u8] = offset.as_ref();
    kinds.insert(offset_ref.to_vec(), kind);
  };

    OutputType::Branch,
    *BRANCH_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"branch")),

    OutputType::Change,
