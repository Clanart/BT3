### Title
Unchecked `*big.Int.Uint64()` downcast of on-chain staking amounts causes silent truncation and miscalculated staking rewards - (File: kaiax/staking/impl/getter.go)

### Summary
`kaiax/staking/impl/getter.go` reads validator staking balances from the `AddressBook`/`MultiCall` system contracts as `*big.Int` (wei-denominated), divides by `params.KAIA` to convert to whole-KAIA units, and then calls Go's `big.Int.Uint64()` to store the result in the `StakingInfo.StakingAmounts []uint64` field and `CLStakingInfo.CLStakingAmount uint64`. `big.Int.Uint64()` is explicitly documented as producing an *undefined* (silently truncated) result when the value does not fit in 64 bits — there is no overflow check analogous to `SafeCast`/explicit bound checks. This mirrors the reported `Distributor` bug class: a `uint256`-range value is downcast to a smaller fixed-width type without validating that it fits, and the truncated value is later used as the authoritative amount for value distribution (staking rewards), silently distorting recipients' entitlements.

### Finding Description
In `parsePermissionlessCallResult` and `parseCallResult`:
```go
stakingAmounts = append(stakingAmounts, new(big.Int).Div(amounts[i], big.NewInt(params.KAIA)).Uint64())
...
CLStakingAmount: big.NewInt(0).Div(clRes.StakingAmounts[i], big.NewInt(params.KAIA)).Uint64(),
``` [1](#0-0) [2](#0-1) 

These amounts come directly from `MultiCallStakingInfo`/`MultiCallStakingInfoPermissionless`/`MultiCallDPStakingInfo`, which read on-chain balances of `CNStaking` (and consensus-liquidity) contracts — balances that grow purely from KAIA deposited/staked by third parties (stakers) into those contracts, i.e. reachable without any special privilege, only ordinary value-transfer transactions into a staking contract. No bound check is performed before the `Uint64()` conversion; if the accumulated staking balance in KAIA units exceeds `math.MaxUint64`, the conversion truncates silently (Go's documented "undefined" behavior for values outside range), producing an arbitrary/wrapped `StakingAmount`.

This truncated `StakingAmount` is subsequently used, without re-validation, as the basis for reward proportionality in `assignStakingRewards`/`assignStakingRewardsFlex` and in `consolidatedNode.Split`: [3](#0-2) [4](#0-3) 

If the truncated value undercounts (or overcounts, depending on modulus) a validator's real stake, the KIP-82/Flex staking reward split among validators (`Recipients` of `RewardSpec`) is computed against the wrong proportions, redirecting minted-reward value away from the entitled staker to other stakers/proposer.

### Impact Explanation
A miscalculated `StakingAmount` directly changes `assignStakingRewards`'s per-validator `excess` computation and thus the `reward (kei) = excess * budget / totalExcess` split described in `kaiax/reward/README.md`, silently redirecting minted block-reward KAIA away from the affected staker to other validators/proposer every block until the staking balance changes. This is a concrete reward-redirection / unauthorized value movement across the honest reward-distribution path, matching the category of "reward redirection" called out as acceptable impact.

### Likelihood Explanation
Exploitability requires a single staking (or consensus-liquidity) contract's staked KAIA balance, expressed in whole-KAIA units, to exceed `math.MaxUint64` (~1.8×10^19 KAIA). Given Kaia's actual circulating/minted supply is many orders of magnitude smaller than this bound, triggering the overflow via legitimate staking deposits is not practically feasible today, and would require either extreme long-term inflation growth or a bug elsewhere inflating a single contract's balance. This significantly limits real-world likelihood compared with the original `Distributor` `uint120` report (which used a much smaller threshold and attacker-supplied merkle amounts).

### Recommendation
Replace the raw `.Uint64()` conversions in `parseCallResult`/`parsePermissionlessCallResult` with a safe/bounds-checked conversion (e.g., verify `big.Int.IsUint64()` before calling `.Uint64()`, or use a `SafeCast`-equivalent helper) and return `staking.ErrAddressBookResult` (or similar) if a staking amount does not fit in `uint64`, instead of silently truncating it.

### Proof of Concept
1. A staking contract accrues (through repeated legitimate stake transactions from unprivileged senders) a balance whose KAIA-unit value exceeds `math.MaxUint64`.
2. `getFromState` → `parseCallResult`/`parsePermissionlessCallResult` computes `new(big.Int).Div(amount, big.NewInt(params.KAIA)).Uint64()`, which silently wraps/truncates per Go's `big.Int.Uint64()` documented undefined behavior for out-of-range values.
3. The truncated `StakingAmount` is stored in `StakingInfo` and consumed unmodified by `assignStakingRewards`/`assignStakingRewardsFlex` in `kaiax/reward/impl/getter.go`, permanently skewing the staker's share of the block reward relative to its true stake.

// assignStakingRewards assigns staking rewards to stakers according to their staking amounts.
// Returns the allocation and the remainder.
func assignStakingRewards(config *reward.RewardConfig, stakersReward *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		cns               = si.ConsolidatedNodes()
		minStake          = config.MinimumStake.Uint64()
		totalExcessInt    = uint64(0) // sum of excess stakes (the amount over minStake) over all stakers
		cnTotalStakingMap = make(map[common.Address]uint64)
		isPrague          = config.Rules.IsPrague
	)
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it.
		if cn.StakingAmount >= minStake {
			// Calculate total staking amount once
			cnTotalStakingAmount := cn.StakingAmount
			if isPrague && cn.CLStakingInfo != nil {
				cnTotalStakingAmount += cn.CLStakingInfo.CLStakingAmount
			}
			totalExcessInt += cnTotalStakingAmount - minStake
			cnTotalStakingMap[cn.RewardAddr] = cnTotalStakingAmount
		}
	}

	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(stakersReward)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		cnTotalStakingAmount := cnTotalStakingMap[cn.RewardAddr]
		if cnTotalStakingAmount > minStake {
			// The KAIA unit will cancel out:
			// reward (kei) = excess (KAIA) * stakersReward (kei) / totalExcess (KAIA)
			excess := new(big.Int).SetUint64(cnTotalStakingAmount - minStake)
			if reward := new(big.Int).Div(new(big.Int).Mul(excess, stakersReward), totalExcess); reward.Sign() > 0 {
				if isPrague && cn.CLStakingInfo != nil {
					// The remaining amount will be added to the cnAmount.
					cnAmount, clAmount := cn.Split(reward)
					alloc[cn.RewardAddr] = cnAmount
					alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
				} else {
					alloc[cn.RewardAddr] = reward
				}
				remaining.Sub(remaining, reward)
			}
		}
	}
	return alloc, remaining

func (c consolidatedNode) Split(amount *big.Int) (*big.Int, *big.Int) {
	if c.CLStakingInfo == nil {
		return amount, big.NewInt(0)
	}

	var (
		cnAmountBig = big.NewInt(int64(c.StakingAmount))
		clAmountBig = big.NewInt(int64(c.CLStakingInfo.CLStakingAmount))
		totalAmount = new(big.Int).Add(cnAmountBig, clAmountBig)
	)

	clAmount := new(big.Int).Mul(clAmountBig, amount)
	clAmount = clAmount.Div(clAmount, totalAmount)

	// The remaining amount is for the CN.
	cnAmount := big.NewInt(0).Sub(amount, clAmount)

	return cnAmount, clAmount
}
