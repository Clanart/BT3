### Title
Deployment script hardcodes `challengePeriod: 0` for both mainnet and testnet hosts, disabling the state-commitment dispute window on mainnet - (File: evm/script/DeployIsmp.s.sol)

### Summary
The canonical host-deployment script `DeployScript.deploy()` branches on `isMainnet` to select mainnet-appropriate values for the fee token, Uniswap router, and consensus routing, but it builds a single `HostParams` struct with `challengePeriod: 0` used identically for both the mainnet `EvmHost` and testnet `TestnetHost` deployment paths. This mirrors the reported bug class exactly: a value that is only safe/intended for testnet ("no need to wait, iterate fast") is not gated behind the same `isMainnet` branch that already exists in the file for every other environment-sensitive parameter, so it silently ships into the mainnet host configuration.

### Finding Description
`DeployScript.deploy()` explicitly forks behavior on `isMainnet` for `feeToken`, `uniswapV2`, `decimals`, and `hyperbridge` state-machine id, and even instantiates a different host contract (`EvmHost` vs `TestnetHost`). [1](#0-0) 

However, the `HostParams` struct that both branches feed into `host.initialize(params)` sets `challengePeriod: 0` unconditionally, outside of the `isMainnet`/testnet split: [2](#0-1) 

`challengePeriod` is a core protocol invariant consumed by `HandlerV2`, which reverts with `ChallengePeriodNotElapsed` when a caller attempts to process a request/response/timeout proof before the configured challenge window has elapsed since the underlying state commitment was recorded: [3](#0-2) 

This dispute window exists to let relayers/watchers detect and freeze the host in response to fraudulent or long-range-forked consensus updates before any request proved against that state commitment is honored. With `challengePeriod = 0`, that protection is void: any state commitment stored via `storeConsensusState`/`setConsensusState` becomes immediately usable to satisfy proof verification in `HandlerV2`, with zero time for the network to observe and react to an invalid consensus update.

Because `EvmHost` (the strict mainnet host) only allows `challengePeriod` (and the rest of `HostParams`) to be changed later via `updateHostParams`, which is restricted to `_hostParams.hostManager` (cross-chain governance) — not the local admin — a mainnet deployment that goes out with `challengePeriod: 0` cannot be trivially patched by the deploying team; it requires a cross-chain governance action to fix, unlike `TestnetHost`, which additionally allows the local `admin` to call `updateHostParams`: [4](#0-3) 

### Impact Explanation
This produces false state acceptance in the ISMP proof pipeline: PostRequest/PostResponse/GetResponse/timeout proofs are accepted and dispatched to destination applications immediately upon any new state/consensus commitment, without the intended latency buffer meant to allow the network to freeze the host in the face of an invalid or maliciously produced consensus proof. On EVM chains where this script is used verbatim for mainnet deployment, an attacker who can get a bad state commitment finalized (e.g., through a short-range consensus fault, or during any transient period where consensus clients disagree) gains an immediate window to have forged cross-chain messages accepted and executed by `dispatchIncoming`, rather than the intended challenge delay giving operators time to call `freeze`. This falls squarely under "false proof/state acceptance" and "unauthorized transaction or execution."

### Likelihood Explanation
The value is not conditioned on `isMainnet` at all — it applies to every environment the script targets, including live mainnet deployments run via `deploy.sh` (which drives this same script for both testnet and mainnet chain lists). There is no code path in `DeployIsmp.s.sol` that overrides `challengePeriod` for `isMainnet == true`, and no post-deploy step in the script sets it to a nonzero value before `host.initialize(params)` is called. Any environment/config-driven run of this exact script for mainnet reproduces the issue deterministically; it does not depend on relayer, prover, or admin misbehavior — only on this script being used to configure a mainnet host, which is its stated purpose (the `isMainnet` flag exists specifically to differentiate mainnet configuration).

### Recommendation
Move `challengePeriod` into the `isMainnet`/testnet branch alongside `feeToken`/`uniswapV2`/`hyperbridge`, sourcing it from a per-chain config value (e.g., `config.get("CHALLENGE_PERIOD").toUint256()`) for mainnet deployments, and keep `0` (or a short dev value) only for the testnet branch. Add a script-level assertion that reverts if `isMainnet == true && challengePeriod == 0` to prevent this from silently shipping again.

### Proof of Concept
1. Run `DeployScript.deploy()` (via `deploy.sh`) with `is_mainnet = true` set in the environment/config, targeting a live EVM mainnet chain, without separately overriding `challengePeriod`.
2. Inspect the resulting `EvmHost` storage: `_hostParams.challengePeriod == 0`. [5](#0-4) 
3. As soon as any state commitment is stored via `setConsensusState`/`storeConsensusState`, submit a `PostRequestMessage`/`GetResponseMessage` proven against that commitment to `HandlerV2`.
4. Because `block.timestamp - _stateCommitmentsUpdateTime[...] >= challengePeriod(=0)` is trivially true, the `ChallengePeriodNotElapsed` check in `HandlerV2` never blocks processing, and the message is dispatched immediately via `EvmHost.dispatchIncoming` with no opportunity for operators to freeze the host in response to a bad commitment. [6](#0-5)

    /**
     * @dev Updates the HostParams. Callable by either `hostManager`
     * (cross-chain governance) or the configured `admin`. When invoked by
     * the admin, resets `_latestStateMachineHeight` for each state machine
     * in `params.stateMachines` before applying the new params, mirroring
     * the prior testnet behavior that lived inside `EvmHost`.
     */
    function updateHostParams(HostParams memory params) external override {
        address caller = _msgSender();
        if (caller != _hostParams.hostManager && caller != _hostParams.admin) {
            revert UnauthorizedAction();
        }

        if (caller == _hostParams.admin) {
            uint256 whitelistLength = params.stateMachines.length;
            for (uint256 i = 0; i < whitelistLength; ++i) {
                delete _latestStateMachineHeight[params.stateMachines[i]];
            }
        }

        updateHostParamsInternal(params);
    }

     * @dev Dispatch an incoming POST request to destination module

    function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
        address destination = _bytesToAddress(request.to);
        uint256 size;
        assembly {
            size := extcodesize(destination)
        }
        if (size == 0) {
            // instead of reverting the entire batch, early return here.
            return;
        }

        // replay protection
        bytes32 commitment = request.hash();
        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)
            .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));
