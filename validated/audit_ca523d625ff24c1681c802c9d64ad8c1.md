Based on my research, the credential-helper trampoline in GitHub Desktop is the closest structural analog to the ShapeShift/MetaMask issue: instead of mediating secret disclosure through an explicit, per-action user confirmation, Desktop's git credential helper silently hands out a previously-stored token to *any* git operation whose target host matches a stored account/generic-credential host — including operations triggered indirectly by content an attacker controls (a remote or submodule URL inside a cloned/fetched repository).

### Title
Generic/GitHub credential trampoline discloses stored tokens to any git operation matching a trusted host, without per-repository confirmation - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
Git credential requests are routed through `createCredentialHelperTrampolineHandler`, which resolves the destination purely from data the git subprocess supplies (`url`/`protocol`/`host`/`path`) via `getCredentialUrl` [1](#0-0) , and then looks up a matching account/credential by host only, via `findGitHubTrampolineAccount` (matches on URL `origin`) [2](#0-1)  and `findGenericTrampolineAccount` (matches on host + stored username) [3](#0-2) . If a match is found, the stored token/password is returned automatically with no additional confirmation dialog, mirroring the report's core complaint that a component is granted broad, low-level secret access instead of being routed through a mediated, per-use confirmation surface. The user is only prompted (`ui.promptForGenericGitAuthentication` / `ui.promptForGitHubSignIn`) when no cached credential exists yet [4](#0-3) .

### Finding Description
`withTrampolineEnv` configures every git subprocess Desktop spawns to use `credential.helper=desktop`, forwarding credential fill/store/erase requests to `createCredentialHelperTrampolineHandler` over the trampoline TCP channel [5](#0-4) . Because this configuration is applied globally to git invocations (not scoped to "the repository the user is currently authenticating against"), any git subcommand that internally triggers a fetch of a *different* URL on a host for which the user has previously stored credentials — for example, a `git submodule update` triggered by a malicious `.gitmodules` in a cloned/fetched repository, or Git LFS filters invoked during checkout — will transparently receive the disclosure of the stored secret for that host, computed solely from `getCredentialUrl(cred)` [1](#0-0) . The matching logic in `getGitHubCredential`/`getGenericCredential` does not verify that the destination corresponds to a URL the user explicitly navigated to in Desktop's UI (e.g., the repository's configured `origin`); it only checks host-level equality [6](#0-5) .

### Impact Explanation
If exploited, an attacker-authored repository (cloned or fetched by the victim, e.g. via a "Clone in Desktop"/`x-github-client://openRepo` deep link handled by `openOrCloneRepository`/`handleAppURL` [7](#0-6) ) can define a submodule or LFS remote pointing at a host the victim already trusts (their own GitHub Enterprise/self-hosted Git server) but at an attacker-controlled path/namespace on that host. Desktop's credential helper will disclose the victim's stored PAT/basic-auth credential to that attacker-influenced destination without any additional prompt, since the check is host-scoped rather than repository/URL-scoped.

### Likelihood Explanation
Exploitation requires the victim to already have a stored credential for a host the attacker can also reach with a namespace/path they control (e.g., a shared self-hosted instance, or a GitHub Enterprise org where the attacker can create a repo). This is a real but narrower precondition than a fully host-agnostic leak, so likelihood is low-to-moderate; it does not require local access, malware, or leaked secrets — only that the victim opens/fetches a crafted repository or deep link.

### Recommendation
Scope credential disclosure to the URL/remote the user explicitly initiated the operation for (e.g., pass and verify the originating remote URL through the trampoline token context) rather than resolving matches solely by host, and require explicit user confirmation before silently reusing a stored credential for a *new* destination path discovered indirectly (submodules, LFS remotes, redirects) during an operation, mirroring the report's recommendation to fall back on mediated, user-confirmed flows instead of direct secret handoff.

### Proof of Concept
1. Victim signs in to a self-hosted GitHub Enterprise/GitLab instance in Desktop (or previously stores a generic credential for `git.company.com` via the "Save and Retry" prompt flow, per `docs/integrations/gitlab.md`) [8](#0-7) .
2. Attacker creates a public repo on the same host under an attacker-controlled namespace (`https://git.company.com/attacker/evil.git`) and crafts a victim-facing repository whose `.gitmodules` references that URL, distributing it via a normal clone or an `x-github-client://openRepo/...` deep link.
3. Victim opens/fetches the repository in Desktop; during submodule initialization, git requests credentials for `git.company.com`.
4. `createCredentialHelperTrampolineHandler` → `getCredential` → `getGenericCredential`/`findGenericTrampolineAccount` matches purely on host and returns the victim's stored token, which git then sends (as HTTP Basic Auth) to the attacker's repository path, without any Desktop-side confirmation dialog [9](#0-8) .

export const getCredentialUrl = (cred: Map<string, string>) => {
  const u = cred.get('url')
  if (u) {
    return new URL(u)
  }

  const protocol = cred.get('protocol') ?? ''
  const username = cred.get('username')
  const user = username ? `${encodeURIComponent(username)}@` : ''
  const host = cred.get('host') ?? ''
  const path = cred.get('path') ?? ''

  return new URL(`${protocol}://${user}${host}/${path}`)
}

export async function findGenericTrampolineAccount(
  trampolineToken: string,
  remoteUrl: string
) {
  const parsedUrl = new URL(remoteUrl)
  const endpoint = urlWithoutCredentials(remoteUrl)

  const login =
    parsedUrl.username === ''
      ? getGenericUsername(endpoint)
      : parsedUrl.username

  if (!login) {
    return undefined
  }

  const token = await memoizedGetGenericPassword(
    trampolineToken,
    endpoint,
    login
  )

  if (!token) {
    // We have a username but no password, that warrants a warning
    log.warn(`credential: generic password for ${remoteUrl} missing`)
    return undefined
  }

  return { login, endpoint, token }
}

async function promptForCredential(cred: Credential, endpoint: string) {
  const parsedUrl = new URL(endpoint)
  const username = parsedUrl.username === '' ? undefined : parsedUrl.username
  const account = await ui.promptForGenericGitAuthentication(endpoint, username)
  info(`prompt for ${endpoint}: ${account ? 'completed' : 'cancelled'}`)
  return credWithAccount(cred, account)
}

async function getGenericCredential(cred: Credential, token: string) {
  const endpoint = `${getCredentialUrl(cred)}`
  const account = await findGenericTrampolineAccount(token, endpoint)

  if (account) {
    info(`found generic credential for ${endpoint}`)
    return credWithAccount(cred, account)
  }

  if (getIsBackgroundTaskEnvironment(token)) {
    debug('background task environment, skipping prompt')
    return undefined
  } else {
    return promptForCredential(cred, endpoint)
  }
}

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}
