### Title
Unsigned OP_RETURN in `payout_tx` lets anyone who fronts a withdrawal falsely attribute the payout credit to an uninvolved operator, permanently denying reimbursement to the real payer — ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
`create_payout_txhandler` only signs input 0 and output 0 of the payout transaction (`TapSighashType::SinglePlusAnyoneCanPay`), leaving the OP_RETURN output (which encodes the operator's `xonly_pk` used to credit reimbursement) completely unsigned and freely rewritable by anyone. `update_finalized_payouts` and `is_kickoff_malicious` trust this unsigned OP_RETURN as ground truth for "who paid," with no check that the named operator's key corresponds to the party who actually supplied the funding inputs for `output_txout`.

### Finding Description
The broken binding is:
`operator_credited_in_payout_op_return` (the xonly_pk parsed out of the payout tx's OP_RETURN by `update_finalized_payouts`, [1](#0-0) ) `==` `operator_that_actually_funded_output_txout` (whoever supplied the funding UTXOs that pay for the withdrawal output).

`create_payout_txhandler` builds the payout transaction with input 0 (user's withdrawal UTXO), output 0 (user payout), output 1 (anchor), and output 2 (OP_RETURN carrying `operator_xonly_pk`), then sets the witness on input 0 only with the user's `SinglePlusAnyoneCanPay` signature: [2](#0-1) . Because the sighash uses `Prevouts::One` for `*PlusAnyoneCanPay` types, the signature commits only to input 0's outpoint/script and to output 0 — never to the OP_RETURN: [3](#0-2) .

An operator's `withdraw()` flow then funds this transaction via `fund_raw_transaction` with `add_inputs: true`, adding the operator's own UTXOs (which pay for the real withdrawal value) and signing those new inputs: [4](#0-3) . Nothing requires that whoever supplies these funding inputs be the same identity written into the OP_RETURN.

Any unprivileged actor holding the user's `SinglePlusAnyoneCanPay` signature and the withdrawal outpoint (trivially true if the attacker is the withdrawing user themselves, or by observing the operator's tx in the mempool) can build a competing transaction spending the same withdrawal outpoint, reusing input 0's witness unmodified, keeping output 0 identical (required for signature validity), but supplying their *own* funding inputs and writing an arbitrary/different `xonly_pk` into the OP_RETURN. If this transaction is mined first (double-spending/evicting the honest operator's version), Bitcoin's `bitcoin_syncer_spent_utxos` records the attacker's txid as the one that spent the withdrawal UTXO: [5](#0-4) .

`update_finalized_payouts` then reads whichever txid actually spent the withdrawal UTXO and blindly parses its OP_RETURN as the "payer": [6](#0-5) . Later, `is_kickoff_malicious` only checks that this stored `operator_xonly_pk` equals `kickoff_data.operator_xonly_pk` of whichever operator broadcasts a kickoff — it never verifies that operator actually funded anything: [7](#0-6) . Meanwhile `validate_payer_is_operator` will permanently reject the honest operator's reimbursement attempt because the DB's `payer_xonly_pk` no longer matches them: [8](#0-7) . The named (uninvolved) operator's automated `PayoutCheckerTask` will pick up this "unhandled payout" credited to its own key and proceed to claim reimbursement without ever having funded the payout: [9](#0-8) .

No existing guard (`SECP.verify_schnorr`, `is_kickoff_malicious`, `verify_storage_proofs`, DB uniqueness) checks that the OP_RETURN-named operator's registered wallet/collateral actually supplied the extra funding inputs of the mined payout transaction — the OP_RETURN is unauthenticated plaintext.

### Impact Explanation
- An honest operator that fully funded a withdrawal via its own capital can be permanently prevented from ever being reimbursed (`validate_payer_is_operator` fails forever for that deposit) — Critical: "an honest operator permanently unable to be reimbursed."
- A different, uninvolved operator, whose only "contribution" is having a public xonly_pk, is automatically credited and will be reimbursed by its own automation for a payout it never funded — Critical: "an operator reimbursed for a payout it never funded."
- Repeatable per withdrawal/deposit against any operator, since it only requires knowledge of a public operator xonly_pk (`fetch_operator_keys`) and the ability to win a one-time transaction race for the withdrawal UTXO.

### Likelihood Explanation
The attacker needs to construct and get mined a transaction that spends the same withdrawal outpoint before/instead of the honest operator's broadcast payout tx, while fully funding the real withdrawal output value themselves (a real capital cost equal to the withdrawal amount, not merely fees) plus a competitive fee to win the mempool/mining race. This is feasible for anyone with capital and Bitcoin fee-market knowledge, requires no privileged role, and needs no cooperation from operators, verifiers, or Citrea. Every affected deposit only needs to be attacked once to permanently break the binding.

### Recommendation
Bind the operator's identity commitment cryptographically to the funding of the payout tx: require the OP_RETURN (or an equivalent commitment) to be covered by a signature from the credited operator's own key (e.g., sign the OP_RETURN output within the operator's added funding-input signatures using `SIGHASH_ALL`, and verify in `update_finalized_payouts`/`is_kickoff_malicious` that at least one of the transaction's other inputs is provably spent from the named operator's registered collateral/wallet key) rather than trusting plaintext OP_RETURN bytes as sufficient proof of payer identity.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

                Ok((
                    u32::try_from(idx).wrap_err("Failed to convert withdrawal index to u32")?,
