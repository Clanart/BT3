### Title
Unrestricted `CallDispatcher.dispatch()` allows anyone to drain residual token/ETH balances left in the shared dispatcher - ([File: evm/src/utils/CallDispatcher.sol])

### Summary
`CallDispatcher.dispatch()` performs arbitrary low-level calls (`to.call{value: call.value}(call.data)`) using calldata that the caller supplies directly, with **no access control on who may call `dispatch()`**. The `CallDispatcher` is a shared, stateless singleton used by `IntentGatewayV2.placeOrder`/`fillOrder` (via `IntentsBase._execute`, `_params.dispatcher`) to temporarily hold escrowed tokens and execute user-supplied `predispatch.call` / `output.call` bytes. Because the dispatcher's balance is not guaranteed to be fully zeroed after every legitimate flow (e.g., tokens produced by `predispatch.call` that are not part of `order.inputs` are never swept back), any unprivileged address can call `CallDispatcher.dispatch()` directly and steal whatever balance is sitting there. This is the same broken invariant as the Chainlink report: an external, unrestricted low-level call whose target/selector/params are fully attacker-controlled, executed against funds that are not the caller's own.

### Finding Description
`CallDispatcher.dispatch(bytes memory encoded)` is declared `external` with no modifier and no `msg.sender` check: [1](#0-0) 

It decodes an arbitrary `Call[]` (target `to`, `value`, `data`) and performs a low-level call for each entry using the CallDispatcher's own balance — exactly the `callback.addr.call(callback.functionId, ...)` pattern flagged in the external report, except here the "Oracle" (fund holder) is the `CallDispatcher` and any address can supply the `Call[]`.

The dispatcher is intended to be used only internally by `IntentGatewayV2`/`IntentsBase`. During `placeOrder`, when an order carries `predispatch.call` (e.g., to unwrap LP tokens before escrow), tokens are sent to the dispatcher and `predispatch.call` is executed there: [2](#0-1) 

After the predispatch call, the gateway only sweeps back the tokens explicitly listed in `order.inputs` (a full-balance sweep per listed token): [3](#0-2) 

Any token or native ETH produced as a **byproduct** of `predispatch.call` that is *not* one of the enumerated `order.inputs` tokens is never swept and is left sitting on the `CallDispatcher` contract indefinitely — this is exactly the kind of "protocol dust" the code elsewhere assumes only the gateway itself will later collect via `_execute`'s sweep logic: [4](#0-3) 

Because `CallDispatcher.dispatch()` has no caller restriction, that residual balance (and any other ETH/tokens ever sent to the dispatcher, since it has a public `receive()`) is directly withdrawable by anyone who calls `dispatch()` with a `Call[]` pointing the token `transfer`/native send at their own address. There is no requirement that the caller be `IntentGatewayV2`, no requirement that the caller be the order's creator/solver, and no requirement that the call correspond to any real order.

### Impact Explanation
This is unauthorized execution leading directly to fund loss: an unprivileged attacker can call `CallDispatcher.dispatch()` to sweep any balance the dispatcher happens to hold — including protocol-owned dust generated by legitimate `predispatch.call` unwrap flows, or ETH/tokens sent to the dispatcher by mistake or by any other integration that shares the same dispatcher instance (`IntentGatewayV2`, the Tron `IntentGatewayV2`, `HyperFungibleToken`/`HyperFungibleTokenUpgradeable` all route `dispatch()` calls to the configured `_dispatcher` address). No consensus proof, relayer, or privileged role is required — this is a pure unauthenticated external call.

### Likelihood Explanation
Exploitability requires only that the dispatcher hold a non-zero balance at some point, which is a realistic, code-supported scenario: any `predispatch.call` that produces a token not listed in `order.inputs` leaves residual balance there permanently (there is no code path that ever sweeps non-`order.inputs` tokens from the dispatcher after `placeOrder`). An attacker only needs to watch for such dust and call `dispatch()` — a single unauthenticated transaction, no timing race, no relayer/prover assumptions needed.

### Recommendation
Restrict `CallDispatcher.dispatch()` to a whitelisted set of authorized callers (e.g., an `onlyAuthorized` modifier checking `msg.sender` against a registry of gateway/app contracts set at construction or via governance), mirroring the Chainlink fix's principle of not allowing arbitrary external actors to trigger a privileged low-level call. Additionally, ensure `IntentGatewayV2.placeOrder`'s predispatch flow sweeps *all* balances left on the dispatcher (not just the tokens enumerated in `order.inputs`) back to the gateway before returning, so no exploitable dust can persist between transactions.

### Proof of Concept
1. A user calls `IntentGatewayV2.placeOrder` with a `predispatch.call` that unwraps an LP/vault token into two underlying tokens, `A` and `B`, but only lists `A` in `order.inputs` (this is a legitimate, permitted order shape since nothing enforces that `predispatch` outputs match `order.inputs` exactly).
2. `placeOrder` sweeps only token `A` back to the gateway via `ICallDispatcher(dispatcher).dispatch(abi.encode(transferCalls))`; token `B`'s full balance remains on the `CallDispatcher` contract.
3. Any external attacker (not the order creator, not `IntentGatewayV2`) calls `CallDispatcher.dispatch(encoded)` directly, where `encoded` decodes to `Call[]{ to: tokenB, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, tokenB.balanceOf(dispatcher)) }`.
4. `CallDispatcher.dispatch` executes the low-level call unconditionally (no access check), transferring all of token `B`'s balance to the attacker — funds that belonged to the protocol/order-creator are stolen with no privileged role or proof required.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
