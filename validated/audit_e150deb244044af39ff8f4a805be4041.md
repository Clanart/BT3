### Title
Immature coinbase outputs are reported as spendable wallet funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_block` scans every transaction in `block.txdata`, including `txdata[0]` coinbase transactions, and credits any output whose `script_pubkey` matches a registered script without enforcing Bitcoin’s 100-block coinbase maturity rule. [1](#0-0)  The returned `ReceivedOutput` contains only an offset, output, and outpoint, with no field indicating that the input is immature. [2](#0-1)  `SignableTransaction::new` subsequently converts the reported outpoint directly into a transaction input and treats its claimed value as available funds. [3](#0-2) 

### Finding Description
The access-control analog is a missing spend-authority check: an output being addressed to Serai does not imply that it is currently authorized for spending. [4](#0-3)  `scan_transaction` matches only `output.script_pubkey`, computes the outpoint, and returns a `ReceivedOutput`; `scan_block` applies that logic to the coinbase transaction as well. [5](#0-4)  The transaction builder then validates only that the offset-derived P2TR script equals the previous output’s script before constructing the FROST signing machine. [6](#0-5)  No in-scope code checks `Transaction::is_coinbase()`, transaction position, confirmation depth, or the 100-block maturity window. [1](#0-0) 

### Impact Explanation
An unprivileged Bitcoin miner can place an output paying a monitored Serai script in their coinbase transaction, causing the scanner to report funds that consensus does not yet allow to be spent. [5](#0-4)  Downstream code may count that value as available and produce a fully signed transaction spending an immature outpoint, which Bitcoin nodes will reject. [3](#0-2)  This creates incorrect received-funds reporting and can trigger unnecessary threshold-signing rounds for transactions that cannot confirm. [7](#0-6) 

### Likelihood Explanation
The trigger is a public Bitcoin transaction and requires no validator, coordinator, RPC, or account privileges, although the attacker must successfully produce a block containing the crafted coinbase. [8](#0-7)  Once such a block is scanned, the behavior is deterministic because `scan_block` unconditionally iterates over every transaction and emits the matching coinbase output. [9](#0-8) 

### Recommendation
Exclude `block.txdata[0]` from `scan_block`, or track coinbase outputs separately until they have at least 100 confirmations. [1](#0-0)  If scanning coinbase outputs is required for observability, extend `ReceivedOutput` with maturity metadata and reject immature values in `SignableTransaction::new` rather than silently accepting them as spendable inputs. [10](#0-9)

```rust
// Conceptual regression test for networks/bitcoin/src/wallet/mod.rs.

let scanner = Scanner::new(group_key).unwrap();
let script = p2tr_script_buf(group_key).unwrap();

// A miner-controlled coinbase transaction paying the monitored script.
let coinbase = Transaction {
  input: vec![coinbase_input],
  output: vec![TxOut {
    value: Amount::from_sat(100_000),
    script_pubkey: script,
  }],
  ..Default::default()
};

let block = Block {
  header,
  txdata: vec![coinbase],
};

// Currently returns one ReceivedOutput even though Bitcoin consensus
// prevents spending this coinbase output for 100 blocks.
let received = scanner.scan_block(&block);
assert_eq!(received.len(), 1);

// SignableTransaction then treats the immature value as an input and
// TransactionMachine can produce a signed transaction that nodes reject.
let signable = SignableTransaction::new(
  received,
  &[(payment_script, 50_000)],
  None,
  None,
  1,
).unwrap();
let machine = signable.multisig(&tweaked_keys).unwrap();
```

The decisive behavior is that `scan_block` does not distinguish the coinbase before calling `scan_transaction`. [9](#0-8)

```rust
  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  /// Scan a block.
  ///
  /// This will also scan the coinbase transaction which is bound by maturity. If received outputs
  /// must be immediately spendable, a post-processing pass is needed to remove those outputs.
  /// Alternatively, scan_transaction can be called on `block.txdata[1 ..]`.
  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }
```
