### Title
Spoofable `WWW-Authenticate: realm="GitHub"` header lets any HTTP remote force GitHub Desktop into the GitHub/Enterprise sign-in flow - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
`getEndpointKind` in the trampoline credential helper classifies a remote host as a GitHub-affiliated endpoint ("enterprise") based solely on the content of a `WWW-Authenticate` header that Git forwards from the remote server's HTTP response, with no cryptographic or independent verification of that claim. Because this header is fully attacker-controlled data returned by whatever server the user's `git` invocation talks to, any self-hosted, malicious, or MITM-proxied HTTP git remote can trip this classification and force Desktop's credential-helper trampoline down the "sign in to GitHub/Enterprise" code path instead of the generic-credential path, even though the host has nothing to do with GitHub.

### Finding Description
When Git needs credentials for an HTTP(S) remote, it invokes Desktop's credential-helper trampoline (`vendor/desktop-trampoline`), which forwards the request to `createCredentialHelperTrampolineHandler` → `getCredential` → `getEndpointKind`: [1](#0-0) 

The relevant branch:
```
for (const [k, v] of cred.entries()) {
  if (k.startsWith('wwwauth[')) {
    if (v.includes('realm="GitHub"')) {
      return 'enterprise'
    } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
      return 'generic'
    }
  }
}
```
The `wwwauth[]` credential fields are populated straight from the server's HTTP `WWW-Authenticate` response header, which Git's credential protocol passes through verbatim to any registered credential helper. There is no TLS certificate pinning, no comparison against a known GitHub/GHE endpoint list, and no server-identity check — the string `realm="GitHub"` alone is sufficient.

Once classified as non-`generic`, `getCredential` takes the branch that looks for an existing stored account matching the URL's API origin, and if none exists it invokes the interactive sign-in UI instead of the generic external/internal credential-store flow: [2](#0-1) 

`ui.promptForGitHubSignIn(endpoint)` is where this misclassification becomes user-facing: for a non-`github.com` hostname it calls `dispatcher.beginEnterpriseSignIn(cb)` and `setSignInEndpoint(origin)` with `origin` derived directly from the attacker-controlled host, launching Desktop's built-in GitHub Enterprise sign-in dialog (OAuth/PAT flow) against that host: [3](#0-2) 

The `endpoint` string used throughout is built by `getCredentialUrl`, which is populated from Git's credential-protocol fields (`host`, `protocol`, `path`) as reported by the trampoline for the connection actually in progress: [4](#0-3) 

The broken invariant mirrors the referenced bug class: a downstream security-relevant decision (whether to treat a host as an authoritative, trusted GitHub/Enterprise identity worth an interactive sign-in flow) is driven by an untrusted, attacker-suppliable input (`realm="GitHub"`) with no independent validation, and the existing "safety net" — matching against `accounts.some(a => a.endpoint === apiEndpoint)` — only protects users who already have a real account for that exact host; it does nothing to stop the initial misclassification or the resulting UI/OAuth flow being kicked off against an arbitrary host.

### Impact Explanation
This is a trust-boundary defect at the point where Desktop decides how to authenticate to a remote:
- A user who manually adds/clones from an untrusted HTTP(S) git remote (or is subjected to a MITM proxy on an otherwise legitimate but non-GitHub HTTP remote) can be steered into GitHub Desktop's "Enterprise sign-in" dialog for a host of the attacker's choosing, which then performs an OAuth/device or PAT-entry flow scoped to that attacker endpoint and, on success, is persisted locally as a legitimate Desktop "account" bound to that endpoint (`findGitHubTrampolineAccount`/`AccountsStore`). This is an unauthorized OAuth/account-binding condition: Desktop is tricked, purely by remote-controlled header content, into treating an arbitrary server as a first-class "GitHub-like" identity provider worthy of its native sign-in chrome, which the user may reasonably trust as verified GitHub UI.
- Because subsequent credential lookups (`findGitHubTrampolineAccount`) match by URL origin, any future request to that same attacker host will auto-fill whatever token the user entrusted to that flow, without further prompting — silently perpetuating the mis-trust for as long as the fake account exists.

The impact is bounded by the fact that no GitHub.com/actual-enterprise credentials are exfiltrated by this path alone (the classification only changes *which* prompt is shown, not which secret is disclosed), so this sits below full "credential exfiltration" severity but squarely inside "unauthorized OAuth or account binding" driven by attacker-controlled remote/proxy response data.

### Likelihood Explanation
Reachability is high: any HTTP(S) git remote a user adds (self-hosted Gitea/Forgejo/Gogs instance, a compromised or malicious server, or a MITM proxy on a network path to a legitimate host) can return a crafted `WWW-Authenticate` header on the very first 401 response to a `fetch`/`clone`/`push`, and Git will forward that header to Desktop's credential helper automatically — no special user action beyond a normal Git operation against that remote is required to trigger the classification. Completing the resulting sign-in flow does require some user interaction (entering credentials/approving OAuth in the dialog Desktop shows), which somewhat limits automatic exploitation but does not require any unusual or "unnatural" steps beyond what a user would already do when adding a new enterprise-style remote.

### Recommendation
Do not use raw `WWW-Authenticate` header content as a trust signal for GitHub/Enterprise classification. Verify GitHub/Enterprise identity via an authenticated, out-of-band check (e.g., the existing `isGitHubHost`/version-header probing already used later in the same function) before treating an endpoint as anything other than `generic`, or require the `wwwauth[]` heuristic to only be a *hint* that additionally gates on a positive `isGitHubHost` check rather than short-circuiting to `'enterprise'` outright.

### Proof of Concept
1. Stand up an HTTP git server (e.g. a minimal server wrapping `git-http-backend`) that, on any unauthenticated request, responds with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
2. In GitHub Desktop, add/clone this server as a plain HTTP remote (not a known GitHub/GHE endpoint) and trigger a fetch/pull.
3. Git invokes the Desktop credential-helper trampoline with `wwwauth[0]=Basic realm="GitHub"` in the credential fields; `getEndpointKind` returns `'enterprise'` purely from this string.
4. Since no existing account matches this host's API endpoint, `getCredential` calls `ui.promptForGitHubSignIn(endpoint)`, which opens Desktop's built-in "Enterprise sign-in" dialog scoped to the attacker's host — confirming the misclassification and the unintended trust escalation, entirely driven by the remote server's response content. /** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }

export const getCredentialUrl = (cred: Map<string, string>) => {
  const u = cred.get('url')
  if (u) {
    return new URL(u)
  }

  const protocol = cred.get('protocol') ?? ''
  const username = cred.get('username')
  const user = username ? `${encodeURIComponent(username)}@` : ''
  const host = cred.get('host') ?? ''
  const path = cred.get('path') ?? ''

  return new URL(`${protocol}://${user}${host}/${path}`)
}
