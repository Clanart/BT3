## Title
Vesting/locked balances become permanently frozen at the EVM direct-cast address during Sei↔EVM address association - (File: `utils/helpers/associate.go`)

### Summary
`AssociationHelper.MigrateBalance`, which runs automatically the first time a Sei signer or EVM sender is associated with its true (pubkey-derived) address, only sweeps the **spendable** balance and wei balance of the direct-cast address (`sdk.AccAddress(evmAddr[:])`) into the real Sei address. Any coins that are still **locked** (e.g. an unexpired vesting schedule) are left behind at the cast address, and the migration/association routine is never re-invoked for that signer afterwards. Because the cast address's 20 bytes are derived from Keccak256 of an Ethereum pubkey rather than the SDK's SHA-256-based pubkey-hash scheme, no Cosmos private key can ever produce a valid signature for that address once it is no longer the "identity" backing further activity, so any vesting funds that later mature there become permanently unspendable.

### Finding Description
`MigrateBalance` is the function that performs the one-time transfer of funds out of the EVM-address-cast Sei account when an address association happens: [1](#0-0) 

It moves `SpendableCoins` and any wei balance, but explicitly does not touch `LockedCoins`; it only checks `LockedCoins(ctx, castAddr).IsZero()` to decide whether the leftover cast account can be deleted. If the cast address is a vesting account with a non-zero locked amount, the account (and its still-locked coins) are simply left in place at the cast address, untouched:

```go
if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
    p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
}
```

This is exercised and confirmed by the repo's own test, which sets up a `DelayedVestingAccount` at the cast address with 1 usei locked, calls `MigrateBalance`, and asserts the locked usei remains stuck at the cast address rather than being moved to the associated Sei address: [2](#0-1) 

`MigrateBalance`/`AssociateAddresses` is invoked from every reachable association entry point that a normal user (or their signed transaction) triggers exactly once per signer — the Cosmos-tx ante path, the EVM-tx ante path, and the `associate`/`associatePublicKey` precompile: [3](#0-2) [4](#0-3) [5](#0-4) 

In every one of these call sites, the migration only runs the first time a signer's `GetEVMAddress`/`GetEVMAddress` mapping is unset (`associated == false`); once `SetAddressMapping` is recorded, subsequent transactions from the same signer skip the whole association/migration block. There is no periodic or later re-sweep of the cast address's balance as its vesting schedule matures.

Additionally, `AssociateAddresses` deliberately declines to "reuse" the cast account (i.e., re-key it to the new pubkey, preserving account number/sequence) when it still has locked coins — this is a tested, intentional behavior: [6](#0-5) [7](#0-6) 

Because a valid Cosmos secp256k1 signature for `sdk.AccAddress(evmAddr[:])` would require a keypair whose SDK address hash (SHA-256-based) collides with an EVM address (Keccak256-based) chosen independently, no one can ever sign a transaction from that account after the association event moves the "identity" to the true Sei address. `CanAddressReceive` documents/enforces that once an EVM address is truly associated with a different Sei address, the direct-cast address is no longer treated as the effective owner: [8](#0-7) 

### Impact Explanation
Any user who holds a vesting grant at the direct-cast Sei address of their own EVM address (a routine situation, since Sei treats the cast address as the default usable identity for an EVM-only user before explicit association) and later triggers association by submitting any ordinary signed transaction (Cosmos tx or EVM tx) while their vesting is still partially locked will have that remaining locked balance stranded at an address that becomes cryptographically uncontrollable going forward. As the vesting schedule naturally unlocks over time, those coins become "spendable" in the ledger's accounting sense but are permanently unclaimable, because there is no reachable code path that re-runs `MigrateBalance` for a signer that is already associated. This is a permanent freezing of user funds, triggered entirely by ordinary self-initiated activity (no attacker or governance action required).

### Likelihood Explanation
This requires only that (a) a user has locked/vesting coins under the pre-association cast address of their own EVM identity, and (b) they perform any signed transaction (Cosmos or EVM) before that vesting fully matures — both of which are standard, expected usage patterns for genesis-vesting or team/investor accounts that also want to use EVM. No special privileges, governance action, or malicious actor is needed; it is fully self-triggered by an unprivileged transaction sender.

### Recommendation
`MigrateBalance` should also account for locked/vesting balances at the cast address — either by transferring the underlying vesting schedule (not just spendable coins) to the new Sei address, or by retaining a persistent mapping/sweep mechanism that re-attempts the balance migration for the cast address whenever it still holds locked coins (e.g., during vesting-completion processing, or by re-checking on each association call whether the previously-skipped cast address's locked balance has since become spendable).

### Proof of Concept
1. Grant a Sei `DelayedVestingAccount`/`ContinuousVestingAccount` to address `A`, where `A` happens to equal `sdk.AccAddress(evmAddr[:])` for some EVM address `evmAddr` (the default cast identity a user controls with their Ethereum key before formal association).
2. Before the vesting end time, the user submits any ordinary signed EVM transaction from `evmAddr` (or a Cosmos tx signed as `A`). This runs `EVMAddressDecorator.AnteHandle` / `UpdateSigners`, which calls `SetAddressMapping` then `MigrateBalance(ctx, evmAddr, realSeiAddr, false)` as shown in `x/evm/ante/preprocess.go` lines 304-347.
3. `MigrateBalance` transfers only `SpendableCoins(A)` to `realSeiAddr`; because `LockedCoins(A)` is non-zero, the vesting account is left in place at `A` (per `utils/helpers/associate.go` lines 57-83, matching the assertions in `TestMigrateBalance`).
4. Once the vesting period elapses, the locked coins become nominally spendable at `A`, but no further transaction can ever be signed for `A` (it is not derivable from any real private key under the SDK's address-hash scheme), and no code path re-invokes migration for an already-associated signer.
5. Result: the previously-locked vesting funds are permanently unclaimable by anyone.

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}

func UpdateSigners(ctx sdk.Context, tx sdk.Tx, accountKeeper authkeeper.AccountKeeper, evmKeeper *evmkeeper.Keeper) (sdk.Events, error) {
	signers := tx.(authsigning.SigVerifiableTx).GetSigners()
	var events sdk.Events
	for _, signer := range signers {
		acc := accountKeeper.GetAccount(ctx, signer)
		if err := acc.SetSequence(acc.GetSequence() + 1); err != nil {
			panic(err)
		}

		accountKeeper.SetAccount(ctx, acc)
		if evmAddr, associated := evmKeeper.GetEVMAddress(ctx, signer); associated {
			events = append(events, sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeyEvmAddress, evmAddr.Hex()),
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		if acc.GetPubKey() == nil {
			logger.Error("missing pubkey for signer", "signer", signer)
			events = append(events, sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		pk, err := btcec.ParsePubKey(acc.GetPubKey().Bytes())
		if err != nil {
			logger.Debug("failed to parse pubkey, likely due to the fact that it isn't on secp256k1 curve", "pub-key", acc.GetPubKey(), "err", err)
			events = append(events, sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		evmAddr, err := helpers.PubkeyToEVMAddress(pk.SerializeUncompressed())
		if err != nil {
			logger.Error("failed to get EVM address from pubkey", "err", err)
			events = append(events, sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		events = append(events, sdk.NewEvent(evmtypes.EventTypeSigner,
			sdk.NewAttribute(evmtypes.AttributeKeyEvmAddress, evmAddr.Hex()),
			sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
		evmKeeper.SetAddressMapping(ctx, signer, evmAddr)
		associationHelper := helpers.NewAssociationHelper(evmKeeper, evmKeeper.BankKeeper(), accountKeeper)
		if err := associationHelper.MigrateBalance(ctx, evmAddr, signer, false); err != nil {
			logger.Error("failed to migrate EVM address balance", "address", evmAddr, "err", err)
			return nil, err
		}

	sigTx, ok := tx.(authsigning.SigVerifiableTx)
	if !ok {
		return ctx, sdkerrors.Wrap(sdkerrors.ErrTxDecode, "invalid tx type")
	}
	signers := sigTx.GetSigners()
	for _, signer := range signers {
		if evmAddr, associated := p.evmKeeper.GetEVMAddress(ctx, signer); associated {
			ctx.EventManager().EmitEvent(sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeyEvmAddress, evmAddr.Hex()),
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		acc := p.accountKeeper.GetAccount(ctx, signer)
		if acc.GetPubKey() == nil {
			logger.Error("missing pubkey for signer", "signer", signer)
			ctx.EventManager().EmitEvent(sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		pk, err := btcec.ParsePubKey(acc.GetPubKey().Bytes())
		if err != nil {
			logger.Debug("failed to parse pubkey for account, likely due to the fact that it isn't on secp256k1 curve", "account", acc.GetPubKey(), "err", err)

func (p PrecompileExecutor) associateAddresses(ctx sdk.Context, method *abi.Method, evmAddr common.Address, seiAddr sdk.AccAddress, pubkey cryptotypes.PubKey) (ret []byte, remainingGas uint64, err error) {
	// Check that address is not already associated
	_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if found {
		return nil, 0, fmt.Errorf("address %s is already associated with evm address %s", seiAddr, evmAddr)
	}

	// Associate Addresses:
	associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.bankKeeper, p.accountKeeper)
	err = associationHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false)
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(seiAddr.String(), evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

// A sdk.AccAddress may not receive funds from bank if it's the result of direct-casting
// from an EVM address AND the originating EVM address has already been associated with
// a true (i.e. derived from the same pubkey) sdk.AccAddress.
func (k *Keeper) CanAddressReceive(ctx sdk.Context, addr sdk.AccAddress) bool {
	directCast := common.BytesToAddress(addr) // casting goes both directions since both address formats have 20 bytes
	associatedAddr, isAssociated := k.GetSeiAddress(ctx, directCast)
	// if the associated address is the cast address itself, allow the address to receive (e.g. EVM contract addresses)
	return associatedAddr.Equals(addr) || !isAssociated // this means it's either a cast address that's not associated yet, or not a cast address at all.
}
