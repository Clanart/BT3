### Title
Unconstrained JOIN on `withdrawal_utxo_txid`/`withdrawal_utxo_vout` lets one Bitcoin payout satisfy two withdrawal indices, causing an operator to be reimbursed for a withdrawal it never funded - ([File: core/src/database/verifier.rs])

### Summary
`Database::get_payout_txs_for_withdrawal_utxos` joins `withdrawals` to `bitcoin_syncer_spent_utxos` purely on `(txid, vout)`, with no uniqueness constraint anywhere in the schema preventing two different `idx` rows from carrying the same `withdrawal_utxo_txid`/`withdrawal_utxo_vout`. If two withdrawal indices `i` and `j` are ever registered with the identical outpoint, spending that outpoint once causes `Verifier::update_finalized_payouts` to mark **both** indices as paid by the same `payout_txid`, and the operator's own `PayoutCheckerTask` will then autonomously kick off reimbursement for the index it never actually funded.

### Finding Description
The binding that must hold is: **number of distinct fronted BTC payouts for withdrawal index `j` == number of times index `j` is credited with a `payout_txid` in the `withdrawals` table**. The code breaks this equality because the join key is the bare outpoint, not a 1:1 relation: [1](#0-0) 

There is no `UNIQUE` constraint on `(withdrawal_utxo_txid, withdrawal_utxo_vout)` in the `withdrawals` table: [2](#0-1) 

`update_withdrawal_utxo_from_citrea_withdrawal` blindly writes whatever outpoint Citrea reports for a given `idx`, with no cross-index duplicate check: [3](#0-2) 

If indices `i` and `j` ever end up with identical `withdrawal_utxo_txid`/`vout` (Citrea's `withdraw()` records whatever outpoint bytes the caller supplies, per `core/src/citrea.rs:458-496`, and this repo performs no cross-index duplicate detection when ingesting via `update_citrea_deposit_and_withdrawals`, `core/src/verifier.rs:2204-2262`), spending that single outpoint once produces two rows from the JOIN. `update_finalized_payouts` then writes `payout_txid`/`payout_tx_blockhash`/`payout_payer_operator_xonly_pk` for both `i` and `j`: [4](#0-3) 

The consequence surfaces automatically in the operator's own reimbursement pipeline. `get_first_unhandled_payout_by_operator_xonly_pk` selects any row where `payout_txid IS NOT NULL`, `is_payout_handled = FALSE`, and `payout_payer_operator_xonly_pk` equals the operator's own key — with no check that the payout transaction actually, distinctly, satisfies that specific index: [5](#0-4) 

`PayoutCheckerTask::run_once` then fetches deposit `j`'s own (separately-funded) `deposit_data` and calls `handle_finalized_payout` for deposit `j`'s outpoint using the borrowed blockhash/txid from `i`'s spend, unconditionally proceeding to kickoff and eventual reimbursement: [6](#0-5) 

No guard in this path (`is_deposit_valid`, `SPV::verify`, `verify_storage_proofs`, or a DB uniqueness constraint) checks that the same on-chain spend cannot satisfy two independent withdrawal indices; the JOIN's key space (outpoint only) is strictly narrower than the attribution space (per-`idx` claim), so the conflation is real.

### Impact Explanation
An honest operator's own automation is misled into reimbursing itself (via the kickoff/reimburse presigned transaction graph and the operator's collateral-backed vault UTXO for deposit `j`) for a withdrawal it never fronted BTC for — this is exactly the Critical category "an operator reimbursed for a payout it never funded." The blast radius scales with however many duplicate-outpoint withdrawal registrations can be produced across deposits; each successful conflation drains one additional vault UTXO's worth of reimbursement collateral per colliding index, without a corresponding BTC payout ever reaching that withdrawal's beneficiary.

### Likelihood Explanation
This requires that two Citrea `withdraw()`/`safeWithdraw()` calls register the identical Bitcoin outpoint at two different withdrawal indices — a precondition that depends on the Citrea Bridge contract's on-chain validation (not visible in this repository) not rejecting a re-used outpoint. Assuming that registration succeeds (nothing in this repo's ingestion path, `update_citrea_deposit_and_withdrawals`, checks for or rejects duplicate outpoints across indices), the rest of the chain — the JOIN conflation, the dual `payout_txid` write, and the automatic `PayoutCheckerTask` pickup — is fully deterministic and requires no further attacker action once the duplicate registration exists and the shared outpoint is spent on Bitcoin.

### Recommendation
Make `get_payout_txs_for_withdrawal_utxos` attribution 1:1: add a `UNIQUE (withdrawal_utxo_txid, withdrawal_utxo_vout)` constraint (or reject/flag duplicate registrations in `update_withdrawal_utxo_from_citrea_withdrawal`) so a given outpoint can only ever back one withdrawal index; additionally, before marking `payout_txid` for an index in `update_finalized_payouts`, verify that the spending transaction's specific input/output actually corresponds to that index's registered outpoint and hasn't already been attributed to another index.

```rust
// cargo test in core/src/database/verifier.rs (extending existing test module)
#[tokio::test]
async fn duplicate_withdrawal_utxo_conflates_two_indices() {
    let config = create_test_config_with_thread_name().await;
    let db = Database::new(&config).await.unwrap();
    let mut dbtx = db.begin_transaction().await.unwrap();

    let spending_txid = Txid::from_byte_array([0x99; 32]);
    let shared_utxo = bitcoin::OutPoint {
        txid: bitcoin::Txid::from_byte_array([0x11; 32]),
        vout: 0,
    };
    let idx_i = 10u32;
    let idx_j = 20u32;

    let block_id = db.insert_block_info(Some(&mut dbtx), &BlockHash::all_zeros(), &BlockHash::all_zeros(), 0).await.unwrap();
    db.insert_txid_to_block(&mut dbtx, block_id, &spending_txid).await.unwrap();
    // ONE bitcoin spend of the shared outpoint
    db.insert_spent_utxo(&mut dbtx, block_id, &spending_txid, &shared_utxo.txid, shared_utxo.vout.into()).await.unwrap();

    // Register the SAME outpoint at two different withdrawal indices (simulating duplicate Citrea registration)
    db.upsert_move_to_vault_txid_from_citrea_deposit(Some(&mut dbtx), idx_i, &Txid::from_byte_array([0xAA; 32])).await.unwrap();
    db.update_withdrawal_utxo_from_citrea_withdrawal(Some(&mut dbtx), idx_i, shared_utxo, block_id).await.unwrap();

    db.upsert_move_to_vault_txid_from_citrea_deposit(Some(&mut dbtx), idx_j, &Txid::from_byte_array([0xBB; 32])).await.unwrap();
    db.update_withdrawal_utxo_from_citrea_withdrawal(Some(&mut dbtx), idx_j, shared_utxo, block_id).await.unwrap();

    // Assert violation: 1 spend attributed to 2 indices
    let txs = db.get_payout_txs_for_withdrawal_utxos(Some(&mut dbtx), block_id).await.unwrap();
    assert_eq!(txs.len(), 2, "ATTRIBUTION violated: one spend credited to two withdrawal indices");
    assert!(txs.iter().any(|(idx, _)| *idx == idx_i));
    assert!(txs.iter().any(|(idx, _)| *idx == idx_j));
}
```

```rust
    pub async fn get_payout_txs_for_withdrawal_utxos(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        block_id: u32,
    ) -> Result<Vec<(u32, Txid)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, TxidDB)>(
            "SELECT w.idx, bsu.spending_txid
             FROM withdrawals w
             JOIN bitcoin_syncer_spent_utxos bsu
                ON bsu.txid = w.withdrawal_utxo_txid
                AND bsu.vout = w.withdrawal_utxo_vout
             WHERE bsu.block_id = $1",
        )
        .bind(i32::try_from(block_id).wrap_err("Failed to convert block id to i32")?);

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_all)?;

        results
            .into_iter()
            .map(|(idx, txid)| {
                Ok((
                    u32::try_from(idx).wrap_err("Failed to convert withdrawal index to u32")?,
                    txid.0,
                ))
            })
            .collect()
    }
```

```rust
    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
            ));
        }

        self.db
            .update_payout_txs_and_payer_operator_xonly_pk(
                Some(dbtx),
                payout_txs_and_payer_operator_idx,
            )
            .await?;

        Ok(())
    }
```

```rust
    async fn run_once(&mut self) -> Result<Self::Output, BridgeError> {
        let mut dbtx = self.db.begin_transaction().await?;
        let unhandled_payout = self
            .db
            .get_first_unhandled_payout_by_operator_xonly_pk(
                Some(&mut dbtx),
                self.operator.signer.xonly_public_key,
            )
            .await?;

        if unhandled_payout.is_none() {
            return Ok(false);
        }

        let (citrea_idx, move_to_vault_txid, payout_tx_blockhash) =
            unhandled_payout.expect("Must be Some");

        tracing::info!(
            "Unhandled payout found for withdrawal {}, move_txid: {}",
            citrea_idx,
            move_to_vault_txid
        );

        let deposit_data = self
            .db
            .get_deposit_data_with_move_tx(Some(&mut dbtx), move_to_vault_txid)
            .await?;
        if deposit_data.is_none() {
            return Err(eyre::eyre!("Fronted withdrawal for move tx {move_to_vault_txid} found, but the signatures for the deposit are not found in the db.").into());
        }

        let deposit_data = deposit_data.expect("Must be Some");

        let kickoff_txid = self
            .operator
            .handle_finalized_payout(
                &mut dbtx,
                deposit_data.get_deposit_outpoint(),
                payout_tx_blockhash,
            )
            .await?;

        // fetch and save the LCP for if we get challenged and need to provide proof of payout later
        let (_, payout_block_height) = self
            .operator
            .db
            .get_block_info_from_hash(Some(&mut dbtx), payout_tx_blockhash)
            .await?
            .ok_or_eyre("Couldn't find payout blockhash in bitcoin sync")?;

        let _ = self
            .operator
            .citrea_client
            .fetch_validate_and_store_lcp(
                payout_block_height as u64,
                citrea_idx,
                &self.operator.db,
                Some(&mut dbtx),
                self.operator.config.protocol_paramset(),
            )
            .await?;

        #[cfg(feature = "automation")]
        self.operator.end_round(&mut dbtx).await?;

        self.db
            .mark_payout_handled(Some(&mut dbtx), citrea_idx, kickoff_txid)
            .await?;

        dbtx.commit().await?;

        Ok(true)
    }
```
