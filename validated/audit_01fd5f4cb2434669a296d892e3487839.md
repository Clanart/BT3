### Title
Unrate-limited `auction_submitBid` RPC bypasses the peer bid rate limiter, enabling signature-verification CPU exhaustion DoS - ([File: kaiax/auction/impl/api.go])

### Summary
The bid pool's only DoS defense against flooding is a per-peer token-bucket limiter (`bidsPerSecondPerPeer = 300`) applied exclusively to bids received over p2p via `HandleBid`. The public JSON-RPC method `auction_submitBid` calls `bidPool.AddBid` directly, completely bypassing this rate limiter, allowing an unauthenticated RPC caller to submit unlimited bids per second, each of which performs expensive EIP-712/ECDSA signature recovery under a pool-wide mutex.

### Finding Description
`BidPool.HandleBid` (the p2p ingestion path) enforces `checkRateLimit(peerID)` before queuing a bid for processing: [1](#0-0) 

The rate limiter is a `golang.org/x/time/rate.Limiter` capped at `bidsPerSecondPerPeer = 300` bids/sec per peer, defined alongside the pool: [2](#0-1) 

However, the public RPC handler `AuctionAPI.SubmitBid` does not go through `HandleBid`/`checkRateLimit` at all — it calls `bidPool.AddBid` directly: [3](#0-2) 

`AddBid` → `validateBid` → `validateBidSigs` performs `ValidateSearcherSig` and `ValidateAuctioneerSig` (EIP-712 hashing + ECDSA public-key recovery) for every call, and `insertBid` takes `bp.bidMu.Lock()`: [4](#0-3) [5](#0-4) 

Because the RPC path has no per-caller or global throttle (only a metrics counter `numBidRequestCounter.Inc(1)` is incremented, with no gating), a single unauthenticated caller can issue an unbounded number of `auction_submitBid` calls per second. Each call reaches deep into signature verification and lock contention before being rejected, whereas the analogous p2p path is capped to 300/sec/peer specifically to prevent this. This mirrors the OnionShare report's root cause: an insufficiently-scoped rate limit (there, per-second directory creation; here, per-peer-only limiting) that a caller reaching the system through an unthrottled channel (there, raw HTTP upload; here, the JSON-RPC endpoint) can exploit to overwhelm the resource intended to be protected.

### Impact Explanation
An attacker with access to the node's public RPC (as is standard for auction searchers who must call `auction_submitBid`) can flood the endpoint with high-volume, cheaply-constructed bid submissions (even with invalid signatures, since block-number/bid-value/data-size checks happen before signature verification, but the signature checks are still reached for near-valid ones targeting different addresses/blocks to avoid early "duplicate/loser" short-circuits). This drives sustained CPU consumption (ECDSA recovery) and contention on `bidMu`, degrading or blocking legitimate bid submissions and the block-builder's ability to read the bid pool (`ExtractTxBundles`/`FilterTxs`), which can delay or disrupt auction-based block building — a resource-exhaustion DoS against a node-level module, satisfying High severity in line with the CVE analog (CVSS AV:N/AC:L/PR:N/UI:N/S:U/A:H).

### Likelihood Explanation
High. `auction_submitBid` is a documented, intentionally public RPC method (per the module's README) that requires no special privilege or prior state — it is directly reachable by any RPC client. No additional rate limiting exists at the HTTP/RPC transport layer for this method based on the code reviewed, and the peer-based limiter in `bid_pool.go` structurally cannot apply to RPC-originated calls since they carry no `peerID`.

### Recommendation
Apply an equivalent (or RPC-caller-keyed, e.g., by remote address or a per-connection identifier) rate limit to the `auction_submitBid` RPC path before invoking `AddBid`, mirroring the `checkRateLimit` mechanism already used for p2p bids. Alternatively, move signature verification earlier or cache verification results to reduce per-call cost, and consider a global (not just per-source) cap on `AddBid` invocation rate from the API layer.

### Proof of Concept
1. Start a Kaia CN with the auction module enabled and RPC exposed.
2. From an unauthenticated client, script rapid repeated calls to `auction_submitBid` (as documented) with distinct `targetTxHash`/`sender` values to avoid early duplicate-rejection, at a rate far exceeding 300/sec (the p2p-imposed cap), e.g. thousands of requests per second using concurrent HTTP connections.
3. Observe that, unlike bids sent over the p2p `HandleBid` path (capped and tested in `TestHandler_RateLimit`, `kaiax/auction/impl/handler_test.go:133-239`), no throttling occurs on the RPC path in `AuctionAPI.SubmitBid` (`kaiax/auction/impl/api.go:118-142`), and CPU usage / lock contention on `bidMu` rises with submission volume, degrading legitimate bid processing. func (bp *BidPool) insertBid(bid *auction.Bid) error {
	bp.bidMu.Lock()
	defer bp.bidMu.Unlock()

	var (
		blockNumber  = bid.BlockNumber
		targetTxHash = bid.TargetTxHash
		sender       = bid.Sender
	)

	// Re-check bidWinnerMap here — two concurrent bids can pass validateBid together.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		return auction.ErrBidAlreadyExists
	}
	if bp.senderHasDifferentWinner(bid) {
		return auction.ErrBidSenderExists
	}

	// If same block number, same target tx hash exists, replace it if it's better
	if existingBid, ok := bp.bidTargetMap[blockNumber][targetTxHash]; ok {
		// FCFS if the bid is the same.
		if existingBid.Bid.Cmp(bid.Bid) >= 0 {
			return auction.ErrLowBid
		}

		logger.Trace("Replace bid", "old", existingBid.Hash(), "new", bid.Hash())
		delete(bp.bidMap, existingBid.Hash())
		delete(bp.bidWinnerMap[blockNumber], existingBid.Sender)
	} else {
		if int64(len(bp.bidMap)) >= bp.maxBidPoolSize {
			logger.Info("Bid pool is full", "maxBidPoolSize", bp.maxBidPoolSize, "bid", bid.Hash())
			return auction.ErrBidPoolFull

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}

func (bp *BidPool) HandleBid(peerID string, bid *auction.Bid) {
	if atomic.LoadUint32(&bp.running) == 0 || bid == nil {
		return
	}

	// Check rate limit for this peer
	if !bp.checkRateLimit(peerID) {
		logger.Trace("Rate limit exceeded for peer", "peerID", peerID)
		return
	}

	select {
	case bp.bidMsgCh <- bid:
	default:
		logger.Trace("Bid queue is full, dropping bid", "peerID", peerID)
	}
}

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)
}
