### Title
Silently Ignored Parse Failure in `Any`-to-JSON Unparsing Causes Corrupted/Partial Data to Be Emitted as Well-Formed JSON - ([File: src/google/protobuf/json/internal/unparser_traits.h])

### Summary
The error-propagation invariant in the audited Solidity report — "a function returns an error code / success flag; callers must check it and bubble it up, otherwise incorrect state is silently treated as success" — has a direct analog in the protobuf JSON writer's handling of `google.protobuf.Any` payloads. In `Proto2Descriptor::WithDecodedMessage`, the return value of `ParsePartialFromString` (a `bool` success/failure signal, protobuf's equivalent of the audited contract's `Error` enum) is explicitly discarded with `(void)`, and the code proceeds as if decoding always succeeded. [1](#0-0) 

### Finding Description
When printing an `Any` field via the reflection-based JSON writer (`MessageToJsonString` path, using `UnparseProto2Descriptor`/`Proto2Descriptor` traits), `WriteAny` extracts the raw bytes from the `Any.value` field (attacker-controlled bytes embedded inside an otherwise valid, trusted top-level message) and calls `Traits::WithDecodedMessage(any_desc, any_bytes, ...)`: [2](#0-1) 

`WithDecodedMessage` builds a `DynamicMessage` of the type named by `Any.type_url` and attempts to parse `any_bytes` into it, but ignores the boolean success result of the parse:

```cpp
static absl::Status WithDecodedMessage(const Desc& desc,
                                       absl::string_view data, F body) {
  DynamicMessageFactory factory;
  std::unique_ptr<Message> unerased(factory.GetPrototype(&desc)->New());
  // TODO: Remove this suppression.
  (void)unerased->ParsePartialFromString(data);

  const Msg& ref = *unerased;
  return body(ref);
}
``` [1](#0-0) 

The invariant that is violated is exactly the one described in the report: a function (`ParsePartialFromString`) returns a status ("NO_ERROR"/"ERROR") that the caller is required to check and propagate, but instead the caller assumes success unconditionally and passes the (possibly partially-populated, truncated, or entirely unparsed) message object on to `body(ref)`, which serializes whatever fields happen to be set into the final JSON output via `WriteMessage<Traits>`/`WriteFields<Traits>` in `WriteAny`.

`ParsePartialFromString` (unlike `ParseFromString`) deliberately allows missing required fields and does not treat a truncated/malformed wire stream identically to `ParseFromString` — it can return `false` while having already merged a subset of fields from the corrupted input before hitting the error, leaving the `DynamicMessage` in an inconsistent partially-parsed state that is nonetheless silently treated as a fully valid message.

### Impact Explanation
An attacker who controls the bytes of an embedded `Any.value` (a common trust boundary: `Any` payloads frequently originate from a different, less-trusted producer than the enclosing message, e.g. an API gateway relaying a client-supplied `Any`) can supply a truncated or malformed sub-message. Instead of the whole conversion failing with `absl::InvalidArgumentError` (which is how every other decode failure in the same file is handled via `RETURN_IF_ERROR`), the writer will happily emit whatever subset of fields were parsed before failure occurred, presenting corrupted/incomplete data to downstream JSON consumers as if it were a valid, complete representation of the `Any` payload. This is an integrity failure of the JSON serialization contract: the caller of `MessageToJsonString`/`BinaryToJsonStream` has no way to detect that the embedded message was actually malformed, since the top-level `absl::Status` returned by the API will report `OK`.

This is a Medium-severity finding, consistent with the original report's severity: it does not cause memory corruption or an obvious crash (bounded by `DynamicMessageFactory`/arena-backed proto parsing safety), but it silently defeats the fail-fast/fail-loud design used everywhere else in this same file (every other `Traits::Get*`/`WithFieldType`/`WithDynamicType` call site uses `RETURN_IF_ERROR` to bubble up failures), producing an inconsistent, misleading, and silently-corrupted JSON output for a subset of inputs.

### Likelihood Explanation
This code path is reachable through any normal, supported public API call that serializes a message containing an `Any` field to JSON using the reflective JSON writer (`google::protobuf::json::MessageToJsonString`, and transitively `BinaryToJsonStream`/`util::JsonStringToMessage`'s Reflective codec path used in tests, and any application-level call to reflectively convert a message containing `Any` fields to JSON). The `Any.value` bytes are ordinary bounded binary protobuf bytes supplied by any producer of the enclosing message — no privileged access, malicious plugin, or forged MiniTable is required. The bug is explicitly flagged by the developers themselves via the `// TODO: Remove this suppression.` comment, confirming it is a known, intentional-but-unaddressed deviation from the fail-loudly pattern used elsewhere in the same translation unit.

### Recommendation
Check the return value of `ParsePartialFromString` in `Proto2Descriptor::WithDecodedMessage` and propagate a proper `absl::Status` (e.g. `absl::InvalidArgumentError("broken Any: could not parse embedded message")`) on failure, consistent with the `RETURN_IF_ERROR` convention used by every other status-returning helper in `unparser.cc`/`unparser_traits.h`. This aligns the `Any` decode path with the "fail early and loudly" principle the rest of the JSON serialization code already follows, removing the single silent-success assumption in this file.

### Proof of Concept
1. Construct a trusted top-level message `M` with a field `google.protobuf.Any any_field`.
2. Set `any_field.type_url = "type.googleapis.com/some.KnownMessageWithRequiredOrMultiByteFields"`.
3. Set `any_field.value` to a byte string that is a truncated/malformed encoding of that message type — e.g., a valid tag/varint-length prefix for a `string`/`bytes` field followed by fewer bytes than the declared length (a classic wire-format truncation), so that `ParsePartialFromString` merges some fields successfully and then returns `false` upon hitting EOF mid-field.
4. Call `MessageToJsonString(M, &json_output)` (reflective codec).
5. Observe: `MessageToJsonString` returns `absl::OkStatus()` and `json_output` contains a `"@type"` entry plus a `"value"` object populated with whatever fields were parsed before truncation was hit in step 3 — with no indication that the embedded `Any` payload was actually corrupt/incomplete, unlike the sibling error path at `unparser.cc:781` (`"broken Any: missing type URL"`) which does correctly reject malformed `Any` inputs missing a `type_url`.
