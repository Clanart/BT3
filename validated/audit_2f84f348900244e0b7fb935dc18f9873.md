## Title
Unbounded full mempool scan triggered by wallet puzzle-hash subscription causes CPU-consumption Denial of Service - (File: `chia/full_node/full_node_api.py`)

### Summary
`CVE-2014-3708` describes a Nova bug where an authenticated user could submit a cheap filter parameter (an IP filter on "list active servers") that forced the server to perform an unbounded, CPU-expensive scan over all active records, causing a CPU-exhaustion DoS. Chia's full-node wallet-sync protocol has an analogous pattern: an unprivileged wallet peer can send a small `RequestPuzzleState` message with `subscribe_when_finished=True`, which causes the full node to synchronously scan **every item currently in the mempool** with no iteration cap, unlike the sibling function `get_items_not_in_filter` which was explicitly hardened with a `max_checked` bound for the same class of risk.

### Finding Description
When a wallet peer calls `request_puzzle_state` with `subscribe_when_finished=True`, once the puzzle-hash sync completes, the full node calls `mempool_updates_for_puzzle_hashes`: [1](#0-0) 

which invokes: [2](#0-1) 

`items_with_puzzle_hashes` and `items_with_coin_ids` iterate over *every single item currently held in the mempool* (`self._items.items()`), and for each item loop over all of its spends and all `create_coin` outputs, checking membership against the caller-supplied puzzle-hash set: [3](#0-2) 

There is no cap on the number of mempool items scanned. This contrasts with the sibling mempool-scanning function `get_items_not_in_filter`, which was explicitly given a `max_checked` bound (default 5000) to stop it from always traversing the full mempool: [4](#0-3) 

The `request_puzzle_state` handler accepts up to `CoinStore.MAX_PUZZLE_HASH_BATCH_SIZE` (`SQLITE_MAX_VARIABLE_NUMBER - 10`, i.e. hundreds of hashes) puzzle hashes per call: [5](#0-4) 

Because the message payload is small (a list of hashes) but the resulting work is `O(mempool_size × conditions_per_item × puzzle_hashes)`, and the mempool can legitimately hold many thousands of items each with many conditions (up to consensus condition limits), a wallet peer can cheaply and repeatedly trigger an expensive, synchronous, single-threaded scan of the entire mempool — exactly the "cheap filter request → expensive unbounded server-side iteration" pattern described in CVE-2014-3708.

### Impact Explanation
Since this scan runs synchronously in the full node's single-threaded async event loop, a sufficiently large mempool combined with repeated `RequestPuzzleState(subscribe_when_finished=True)` calls (or equivalent) from one or more wallet peers can stall block/transaction processing for the duration of each scan, degrading availability of mempool admission and block validation for all other peers — a CPU-consumption denial of service reachable by any unprivileged wallet client connected to the full node.

### Likelihood Explanation
The request path is a standard, unauthenticated wallet-sync protocol message (`RequestPuzzleState`) that any connected wallet peer can send; no special privileges are required. The cost is asymmetric (a small request causes a large, unbounded server-side computation), and the trigger can be repeated. The existing hardening of the structurally identical `get_items_not_in_filter` (with `max_checked`) indicates the project is aware of and has previously mitigated this exact scan pattern elsewhere, but `items_with_puzzle_hashes`/`items_with_coin_ids` were left unbounded.

### Recommendation
Add an iteration/time cap (analogous to `max_checked` in `get_items_not_in_filter`) to `Mempool.items_with_puzzle_hashes` and `Mempool.items_with_coin_ids`, or rate-limit/throttle `mempool_updates_for_puzzle_hashes` calls per peer, so that a single wallet-protocol request cannot force an unbounded full scan of the mempool.

### Proof of Concept
1. Grow the full node's mempool to near its cost cap with many independent spend bundles (each with many `CREATE_COIN` outputs, which is legitimate mempool-admission traffic).
2. As an unprivileged wallet peer, send `wallet_protocol.RequestPuzzleState` with a puzzle-hash list near `CoinStore.MAX_PUZZLE_HASH_BATCH_SIZE` and `subscribe_when_finished=True`.
3. Observe that on completion the node executes `mempool_updates_for_puzzle_hashes`, which calls `items_with_puzzle_hashes`/`items_with_coin_ids`, each iterating the entire in-memory mempool `_items` dict and all conditions therein with no cap — repeat the request rapidly to keep the event loop busy and degrade node responsiveness for all peers.

    def items_with_coin_ids(self, coin_ids: set[bytes32]) -> list[bytes32]:
        """
        Returns a list of transaction ids that spend or create any coins with the provided coin ids.
        This iterates over the internal items instead of using a query.
        """

        transaction_ids: list[bytes32] = []

        for transaction_id, item in self._items.items():
            conds = item.conds
            assert conds is not None

            for spend in conds.spends:
                if spend.coin_id in coin_ids:
                    transaction_ids.append(transaction_id)
                    break

                for puzzle_hash, amount, _memo in spend.create_coin:
                    if Coin(spend.coin_id, puzzle_hash, uint64(amount)).name() in coin_ids:
                        transaction_ids.append(transaction_id)
                        break
                else:
                    continue

                break

        return transaction_ids

    def items_with_puzzle_hashes(self, puzzle_hashes: set[bytes32], include_hints: bool) -> list[bytes32]:
        """
        Returns a list of transaction ids that spend or create any coins
        with the provided puzzle hashes (or hints, if enabled).
        This iterates over the internal items instead of using a query.
        """

        transaction_ids: list[bytes32] = []

        for transaction_id, item in self._items.items():
            conds = item.conds
            assert conds is not None

            for spend in conds.spends:
                if spend.puzzle_hash in puzzle_hashes:
                    transaction_ids.append(transaction_id)
                    break

                for puzzle_hash, _amount, memo in spend.create_coin:
                    if puzzle_hash in puzzle_hashes or (include_hints and memo is not None and memo in puzzle_hashes):
                        transaction_ids.append(transaction_id)
                        break
                else:
                    continue

                break

        return transaction_ids

    def get_items_not_in_filter(
        self, mempool_filter: PyBIP158, limit: int = 100, max_checked: int = 5000
    ) -> list[MempoolItem]:
        items: list[MempoolItem] = []

        checked = 0
        for item in self.mempool.items_by_feerate():
