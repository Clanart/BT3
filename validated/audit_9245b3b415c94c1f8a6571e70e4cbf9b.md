### Title
Unauthenticated operator-attribution field in payout transaction allows reimbursement credit to be misattributed - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
The Clementine payout flow signs the user's withdrawal authorization using `TapSighashType::SinglePlusAnyoneCanPay` [1](#0-0) , which under BIP341 only commits to input index 0 and the matching output index 0. The `OP_RETURN` output that records which operator's x-only public key fronted the payout — the sole piece of data used later to attribute reimbursement credit — is **not covered** by the user's signature [2](#0-1) . Anyone who can reconstruct a conflicting transaction spending the same withdrawal UTXO (using the same public `input_signature`/`WithdrawParams`, which are shared to all operators and observable on Citrea) can substitute an arbitrary x-only public key into that `OP_RETURN` field while still paying the user's committed output, hijacking or forging which operator gets reimbursement credit for the deposit.

### Finding Description
`create_payout_txhandler` builds the payout transaction with:
1. A single signed input/output pair (the user's withdrawal UTXO and the user's payout output), spent via `SpendPath::KeySpend` with the user's `taproot::Signature` [2](#0-1) .
2. An unsigned anchor output for CPFP.
3. An unsigned `OP_RETURN` output containing `operator_xonly_pk.serialize()` — i.e., whichever operator claims to have fronted the payout [3](#0-2) .

`parse_withdrawal_sig_params` explicitly enforces that the user signature's sighash type is `SinglePlusAnyoneCanPay` [4](#0-3) . Per BIP341, `SIGHASH_SINGLE | SIGHASH_ANYONECANPAY` commits only to the signer's own input and the output at the same index; it explicitly does not commit to any other outputs (here, the anchor and `OP_RETURN`), and `ANYONECANPAY` permits arbitrary substitution/addition of other inputs. Consequently, whoever provides the on-chain payout tx is free to set the `OP_RETURN` operator-attribution field to any x-only public key while leaving the user's paid output intact and valid under the signature.

Later, when the verifier/operator side determines who is owed reimbursement, it derives the payer purely from this unauthenticated `OP_RETURN` field:
- `update_finalized_payouts` parses the first `OP_RETURN` output of the mined payout tx and stores it as `payout_payer_operator_xonly_pk` [5](#0-4) .
- `PayoutCheckerTask::run_once` looks up "unhandled payouts" filtered by `operator_xonly_pk` matching the operator's own key and proceeds to call `handle_finalized_payout`, kicking off the reimbursement (kickoff/round/assert) flow for that operator [6](#0-5) [7](#0-6) .
- `validate_payer_is_operator`/`is_kickoff_malicious` only check that the kickoff sender's x-only public key matches the payer recorded from the `OP_RETURN`, not that the credited operator actually supplied the funding input for the payout [8](#0-7) [9](#0-8) .

Because none of these checks verify that the operator named in `OP_RETURN` is the one whose Bitcoin funds actually paid the user (the funding inputs added via CPFP/RBF are not signed by anyone tying them to the claimed `operator_xonly_pk`), the binding "operator credited == party that paid" is not enforced by any signature or on-chain constraint — only by social convention that each operator only builds payout transactions crediting itself.

### Impact Explanation
This breaks the custody/attribution invariant "the operator credited versus the party that paid." An attacker (which, per the code, need not be a registered protocol role — it only requires observing a broadcast/pending `WithdrawParams` and having enough BTC to fund a competing version of the payout tx) can construct a payout transaction that pays the exact same user output required by the signature, but writes an arbitrary operator's x-only public key into the `OP_RETURN`. If this transaction confirms, that named operator is credited in the `withdrawals` table as the payer and subsequently proceeds through the kickoff/reimburse flow to claim the deposited BTC back from `move_to_vault`, even though it never fronted anything. Meanwhile, whichever party actually funded the user's payout receives no attribution and no reimbursement path, permanently losing the BTC they fronted. This matches the Critical-severity class "an operator reimbursed for a payout it never funded" / "an honest operator permanently unable to be reimbursed."

### Likelihood Explanation
The `WithdrawParams` (including the user's `input_signature`) are transmitted to operators over gRPC to compete for fronting the withdrawal, and the underlying withdrawal request itself originates from a public, observable Citrea bridge transaction. Constructing a substitute payout transaction requires only: (1) access to the (widely distributed) `WithdrawParams`, (2) enough BTC to fund the output, and (3) the ability to broadcast/replace the transaction before the legitimate payer's version confirms (e.g. via fee bumping/RBF race). No verifier, aggregator, or security-council privilege is needed to construct the conflicting transaction. However, actually benefiting from the resulting misattribution as a reimbursed party still requires being one of the deposit's registered operators (to run the kickoff/reimburse machinery) — this constrains who profits, though the loss to the honest funding party occurs regardless of whether the attacker itself is a registered operator.

### Recommendation
Bind the operator-attribution data to the same signature that authorizes spending the user's withdrawal UTXO, or otherwise anchor payer attribution to something cryptographically tied to the actual funding inputs — e.g.:
- Change the payout transaction structure/signature scheme so the user's signature (or a second signature layer) also commits to the `OP_RETURN` output (e.g., via `SIGHASH_ALL` for a dedicated commitment output, or a covenant/PoP that ties `OP_RETURN` to the specific funding input(s)).
- Alternatively, verify at the protocol level that the operator credited in `OP_RETURN` is provably the source of the additional funding inputs (e.g., require those inputs to be signed by / spendable only by the claimed operator's key, and validate this on-chain or during `update_finalized_payouts`).

### Proof of Concept
1. User creates a withdrawal on Citrea and produces a `SinglePlusAnyoneCanPay` signature over `(input_outpoint, output_script_pubkey, output_amount)`, published as part of `WithdrawParams` [10](#0-9) .
2. Honest operator O1 observes this and calls `withdraw`, building a payout tx via `create_payout_txhandler` with `operator_xonly_pk = O1`, funding it with its own additional input(s), and broadcasts it [11](#0-10) [2](#0-1) .
3. Attacker (or a competing operator O2), having the same public `WithdrawParams`/signature, independently builds a conflicting transaction reusing the same signed input/output (still valid under `SinglePlusAnyoneCanPay`) but supplies its own funding input(s) and sets `OP_RETURN = O2`'s x-only public key, then gets this version confirmed first (e.g., with a higher fee).
4. `update_finalized_payouts` parses the confirmed tx's `OP_RETURN` and records `payout_payer_operator_xonly_pk = O2` [5](#0-4) .
5. `PayoutCheckerTask` for O2 picks up this "unhandled payout" and proceeds to call `handle_finalized_payout`, allowing O2 to claim reimbursement for a payout it did not (or did not solely) fund, while O1's actually-fronted funds are unattributed and unreimbursable [6](#0-5) .

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }

    pub async fn withdraw(

        in_signature: taproot::Signature,
        in_outpoint: OutPoint,

            "Withdrawing with index: {}, in_signature: {:?}, in_outpoint: {:?}, out_script_pubkey: {}, out_amount: {}",
            withdrawal_index,
            in_signature,
            in_outpoint,
            out_script_pubkey,
            out_amount
        );

        // Prepare input and output of the payout transaction.
        let input_prevout = self.rpc.get_txout_from_outpoint(&in_outpoint).await?;
        let input_utxo = UTXO {
            outpoint: in_outpoint,
            txout: input_prevout,
        };
        let output_txout = TxOut {
            value: out_amount,
            script_pubkey: out_script_pubkey,
        };

        let withdrawal_utxo = self
            .db
            .get_withdrawal_utxo_from_citrea_withdrawal(None, withdrawal_index)
            .await?;

        if withdrawal_utxo != input_utxo.outpoint {
            return Err(eyre::eyre!("Input UTXO does not match withdrawal UTXO from Citrea: Input Outpoint: {0}, Withdrawal Outpoint (from Citrea): {1}", input_utxo.outpoint, withdrawal_utxo).into());

        let operator_withdrawal_fee_sats =
            self.config
                .operator_withdrawal_fee_sats
                .ok_or(BridgeError::ConfigError(
                    "Operator withdrawal fee sats is not specified in configuration file"
                        .to_string(),
                ))?;
        if !Self::is_profitable(
            input_utxo.txout.value,
            output_txout.value,
            self.config.protocol_paramset().bridge_amount,
            operator_withdrawal_fee_sats,
        ) {
            return Err(eyre::eyre!("Not enough fee for operator").into());
        }

        let user_xonly_pk = &input_utxo
            .txout
            .script_pubkey
            .try_get_taproot_pk()
            .wrap_err("Input utxo script pubkey is not a valid taproot script")?;

        let payout_txhandler = builder::transaction::create_payout_txhandler(
            input_utxo,
            output_txout,
            self.signer.xonly_public_key,
            in_signature,
            self.config.protocol_paramset().network,
        )?;
