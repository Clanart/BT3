### Title
`CW721ERC721Pointer.transferFrom` allows any caller to steal any NFT without owner/approval check - ([File: contracts/src/CW721ERC721Pointer.sol])

### Summary
`CW721ERC721Pointer.transferFrom` overrides OpenZeppelin's `ERC721.transferFrom` but only verifies that the `from` argument is the current owner of the token; it never checks that `msg.sender` is the owner, an approved address, or an approved operator for that token. This is the same bug class as the referenced external report ("missing owner/approval authorization check on a state-changing token action"), except here it applies to `transferFrom` on a Sei EVM<->CW721 pointer contract, which any EVM account can call for tokens they don't own.

### Finding Description
`CW721ERC721Pointer` is the ERC721-compatible pointer contract exposed to EVM users for a wrapped CW721 collection. [1](#0-0) 

Its `transferFrom` implementation is: [2](#0-1) 

The only guard is `require(from == ownerOf(tokenId), "\`from\` must be the owner")`, which merely confirms the `from` address supplied by the caller actually owns the token — it does **not** verify that `msg.sender` is that owner, is `getApproved(tokenId)`, or `isApprovedForAll(from, msg.sender)`. Compare this to the equivalent pointer for ERC1155 tokens, `CW1155ERC1155Pointer.burn`/`burnBatch`, which correctly enforces `msg.sender == account || isApprovedForAll(account, msg.sender)` before executing the CosmWasm burn message. [3](#0-2) 

The bare-metal reference `ERC721.sol` in the repo also demonstrates the standard `_isApprovedOrOwner` check pattern that is expected but absent from the pointer's `transferFrom`. [4](#0-3) 

Because `_execute` in the pointer simply forwards the `transfer_nft` CosmWasm message using the token's real Sei owner address (not `msg.sender`), an attacker can call `transferFrom(victimOwner, attacker, tokenId)` directly and the underlying CW721 contract will execute the transfer, since the message is built and signed by the pointer contract acting on behalf of the wasm module, not the EVM caller. [5](#0-4) 

### Impact Explanation
Any unprivileged EVM account can call `transferFrom` on any `CW721ERC721Pointer` and move any NFT it does not own and has no approval for, to any address of its choosing. This is a direct unauthorized-transfer / fund-theft vulnerability reachable by any EVM transaction sender against every CW721 pointer contract deployed on Sei, matching the "unauthorized transfer via precompile or pointer" impact category.

### Likelihood Explanation
The bug is trivially and deterministically reachable: it requires only a single `transferFrom(from, to, tokenId)` EVM call with `from` set to the real owner's address and `to` set to the attacker's address, no special privileges, timing, or race condition needed. Because pointer contracts are permissionlessly deployed/used to wrap CW721 tokens for EVM interoperability, the exposure applies to every pointer of this kind.

### Recommendation
Add proper authorization checks to `transferFrom` (and any code paths relying on it, such as inherited `safeTransferFrom`), mirroring OpenZeppelin's `_isApprovedOrOwner(msg.sender, tokenId)` pattern:
```solidity
require(
    _msgSender() == from ||
    getApproved(tokenId) == _msgSender() ||
    isApprovedForAll(from, _msgSender()),
    "caller is not owner or approved"
);
```
This should be enforced before dispatching the `transfer_nft` CosmWasm execute message.

### Proof of Concept
1. Owner A holds `tokenId = 1` in a CW721 collection wrapped by `CW721ERC721Pointer` at address `P`.
2. Attacker B (unrelated EVM account, no approval) calls `P.transferFrom(A, B, 1)`.
3. `transferFrom` checks `require(from == ownerOf(tokenId))` — passes since `from == A` and `A` is indeed the owner.
4. No check is made that `msg.sender (B)` is `A`, approved, or an operator.
5. The pointer executes the wasm `transfer_nft` message moving token `1` from `A` to `B`, completing the unauthorized theft. [2](#0-1)

```text
    function transferFrom(address from, address to, uint256 tokenId) public override {
        if (to == address(0)) {
            revert ERC721InvalidReceiver(address(0));
        }
        require(from == ownerOf(tokenId), "`from` must be the owner");
        string memory recipient = _formatPayload("recipient", _doubleQuotes(AddrPrecompile.getSeiAddr(to)));
        string memory tId = _formatPayload("token_id", _doubleQuotes(Strings.toString(tokenId)));
        string memory req = _curlyBrace(_formatPayload("transfer_nft", _curlyBrace(_join(recipient, tId, ","))));
        _execute(bytes(req));
    }
```
