### Title
Relayer reward theft via multi-message batches in `pallet-consensus-incentives::on_executed` - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`FeeHandler::on_executed` is invoked once per batch of ISMP messages submitted in a single extrinsic. `pallet-consensus-incentives` derives the reward recipient solely from `messages[0]`'s signature, but distributes rewards for *every* `StateMachineUpdated` event produced by the entire batch — including consensus updates that were actually delivered by other relayers' consensus messages later in the same batch.

### Finding Description
`Pallet::<T>::execute` (pallet-ismp) takes an unauthenticated `Vec<Message>` from any caller, processes them all via `handle_incoming_message`, collects all resulting events, and passes the *entire* batch of messages and events to `T::FeeHandler::on_executed` in a single call. [4](#0-3) 

In `pallet-consensus-incentives`'s `on_executed`:
```rust
let maybe_relayer_account = messages.get(0).and_then(|first_message| {
    if let Message::Consensus(consensus_msg) = &first_message.message {
        ...verify signature of consensus_msg.signer...
    } else { None }
});

if let Some(relayer_account) = maybe_relayer_account {
    // collapse ALL StateMachineUpdated events in the whole batch
    let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
    for event in events { ... }
    for (state_machine_id, latest_height) in highest_per_state_machine {
        let _ = Self::process_message(state_machine_height, state_machine_id, relayer_account.clone().into());
    }
}
``` [5](#0-4) 

Because `Pallet::execute` accepts any caller-supplied `Vec<Message>`, and consensus messages are signed data that anyone who observes them (e.g. from the p2p network, mempool, or a public block explorer) can re-broadcast verbatim, an attacker can take their own valid consensus message for state machine A (a chain they legitimately relayed) and bundle it as the *first* element of a batch alongside one or more other relayers' already-published, valid consensus messages for state machines B, C, etc. The signature check on `messages[0]` still passes (it's the attacker's own real signature), but `process_message` then pays out the reward for *every* state machine advance in the batch — including B and C, which were delivered by other relayers' proofs — entirely to the attacker's account. `LastRewardedHeight` is a per-`state_machine_id` watermark, so it does not gate on which relayer is credited, only that a height isn't rewarded twice. [6](#0-5) 

The comment at lines 124-132 shows the developers were aware of and fixed the "same state machine rewarded multiple times in one batch" issue by collapsing to the highest height per `state_machine_id`, but this fix does not address that all rewards in the batch still flow to a single signer derived from `messages[0]`, regardless of which message actually produced which `StateMachineUpdated` event. [7](#0-6) 

### Impact Explanation
This is a direct fund-theft / wrong-beneficiary vulnerability: an unprivileged actor can misappropriate relayer rewards owed to other relayers by re-submitting their publicly-visible consensus proofs bundled after their own message in a single batch extrinsic. `T::Currency::transfer` moves treasury funds to the attacker's account for state-machine advances they did not deliver, and `T::ReputationAsset::mint_into` also inflates their reputation score dishonestly. [8](#0-7) 

### Likelihood Explanation
Any account can call the extrinsic that invokes `Pallet::execute` with an arbitrary `Vec<Message>` — no relayer identity check gates batch composition, and consensus messages are inherently public once broadcast (they must be, to be gossiped/verified). No malicious relayer, prover, or governance actor is needed — a single unprivileged batching attacker suffices, satisfying the "unprivileged attacker" requirement.

### Recommendation
Attribute each `StateMachineUpdated` event's reward to the signer of the specific `Message::Consensus` that produced it, rather than to `messages[0]`. This requires correlating each consensus message in the batch with the state machine(s) it actually updates (e.g., by re-deriving/matching events to their originating message index) instead of collapsing to a single batch-wide signer.

### Proof of Concept
1. Relayer R1 obtains/observes a valid, publicly broadcastable `Message::Consensus` proof `M_B` for state machine B (e.g. from mempool/gossip, submitted by relayer R2 but not yet included).
2. R1 crafts a batch `[M_A, M_B]` where `M_A` is R1's own valid consensus message for state machine A, placed first.
3. R1 calls the extrinsic wrapping `Pallet::<T>::execute(vec![M_A, M_B])`.
4. `handle_incoming_message` processes both, producing `StateMachineUpdated` events for both A and B. [9](#0-8) 
5. `on_executed` extracts `relayer_account = R1` from `messages[0]` (`M_A`'s signer), then iterates `highest_per_state_machine` containing both A and B, calling `process_message` for each with `relayer_account = R1`. [10](#0-9) 
6. R1 receives the reward for state machine B's advance in full, even though R2 produced/should have submitted `M_B` first. R2's later attempt to claim the same height range fails or pays nothing since `LastRewardedHeight` for B has already advanced past that height.

	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

		let message_results = messages
			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		let messages_with_weights = message_results
			.iter()
			.zip(messages)
			.map(|(result, message)| MessageWithWeight { message, weight: result.weight() })
			.collect::<Vec<_>>();

		let events = message_results
			.into_iter()
			// check that requests will be successfully dispatched
			// so we can not be spammed with failing txs
			.map(|result| match result {
				MessageResult::Request { events, .. } |
				MessageResult::Response { events, .. } |
				MessageResult::Timeout { events, .. } => events,
				MessageResult::ConsensusMessage(events) => events.into_iter().map(Ok).collect(),
				MessageResult::FrozenClient(_) => vec![],
			})
			.flatten()

				Error::<T>::InvalidMessage
			})?;

		T::FeeHandler::on_executed(messages_with_weights, events.clone())

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}
