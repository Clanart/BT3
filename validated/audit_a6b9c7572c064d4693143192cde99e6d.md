### Title
Wallet `execute_signing_instructions` RPC is an unauthenticated blind-signing oracle that unconditionally delegates the wallet's private key to sign attacker-chosen messages - ([File: chia/wallet/wallet_signer.py])

### Summary
The CVE-2011-2192 bug class is "credential material is handed to a caller/party without checking that the specific operation was authorized." The analogous flaw in this repo is `WalletSigner.execute_signing_instructions()`, reachable through the wallet RPC endpoint `execute_signing_instructions`, which signs any attacker-supplied `(fingerprint, message)` pair with the wallet's real private key material without verifying that the message was actually produced by `gather_signing_info()` for a legitimate, wallet-generated coin spend.

### Finding Description
`WalletSigner.execute_signing_instructions()` takes a `SigningInstructions` object composed of `KeyHints` (path/sum hints) and `SigningTarget`s, each of which is just a `(fingerprint, message, hook)` tuple supplied directly by the RPC caller: [1](#0-0) 
For every `PathHint`, the code unconditionally derives child keys from `root_private_key` using arbitrary attacker-chosen derivation paths (`_derive_path` / `_derive_path_unhardened`), and for every `SigningTarget` it signs the attacker-supplied `message` with whatever key was derived/looked up — there is no cross-check against `gather_signing_info()`'s own output, no verification that `message` corresponds to an `AGG_SIG_ME`/`AGG_SIG_UNSAFE` condition of a coin spend the wallet actually created, and no binding of the message to any coin, offer, or transaction the user approved: [2](#0-1) 

This function is exposed directly by the wallet RPC: [3](#0-2) 

Contrast this with the legitimate flow, `gather_signing_info()`, which derives `SigningTarget.message` strictly from `pkm_pairs_for_conditions_dict()` over an actual `CoinSpend`'s puzzle/solution — i.e., the message is cryptographically tied to a real, user-intended spend: [4](#0-3) 

`execute_signing_instructions` skips this binding entirely: it will happily sign whatever `message` is handed to it as long as a key can be resolved for the given fingerprint (directly, via path hint, or via sum hint), as demonstrated by the test harness signing arbitrary hashes like `std_hash(b"path hint only")` with no coin context at all: [5](#0-4) 

Because BLS signatures over `AGG_SIG_UNSAFE` conditions are not domain-separated by coin id (unlike `AGG_SIG_ME`, which chia partially binds through `agg_sig_me_additional_data` + coin name during `gather_signing_info`, but that binding is not re-verified by `execute_signing_instructions`), an attacker who can reach this RPC endpoint effectively obtains a raw BLS signing oracle keyed off the wallet's master key. The oracle also permits deriving and signing under arbitrary unhardened BIP32 paths beneath the wallet's root key, which is broader delegation authority than any single transaction should require.

### Impact Explanation
Any local caller with wallet RPC access (a design surface explicitly intended for local, semi-trusted use including hardware/external "blind signer" protocols per CHIP-0029) can obtain a valid BLS signature from the wallet's real private key over an arbitrary message of their choosing, for any key reachable via the wallet's derivation tree. Because signature validity for `AGG_SIG_UNSAFE` conditions depends only on the raw message match (no coin binding), such a signature can potentially be replayed into an unrelated coin spend/puzzle requiring the same pubkey and message, producing unauthorized coin movement without the wallet ever having generated or approved that transaction. This is a credential-delegation failure of the same class as CVE-2011-2192: the signing authority (equivalent to GSSAPI credentials) is handed out for any request without confirming the request corresponds to an authorized operation.

### Likelihood Explanation
Requires the ability to call the wallet RPC's `execute_signing_instructions` endpoint (local RPC/CLI/GUI plugin access), which is the same trust boundary the CHIP-0029 "signer protocol" and `chia rpc wallet execute_signing_instructions` CLI command already expose by design. No consensus-node compromise or peer access is needed — only ordinary local wallet-RPC reachability, matching the "local RPC caller" scope for this review.

### Recommendation
`execute_signing_instructions` should not accept freeform `SigningTarget.message` values from the RPC boundary without validating that each target was actually produced by `gather_signing_info()` for a spend the wallet itself constructed (e.g., by requiring the caller to also supply the originating `Spend`/`CoinSpend` set and recomputing/matching the expected `pkm_pairs_for_conditions_dict()` output before signing), or by scoping this blind-signing capability to a clearly separate, opt-in "external signer" mode with its own explicit user consent/confirmation step, rather than being reachable through the same key material used for normal wallet operation.

### Proof of Concept
Using the wallet RPC client against a running wallet:
```python
# Attacker with local wallet-RPC access derives an arbitrary key under the wallet root
# via an unhardened path hint and obtains a signature over a message of their choosing,
# with no coin spend ever generated or approved by the wallet:

    ExecuteSigningInstructions(
        signing_instructions=SigningInstructions(
            KeyHints([], [PathHint(root_fingerprint, [12381, 8444, 3, 7])]),
            [SigningTarget(target_pubkey_fingerprint, attacker_chosen_message, hook)],
        )
    )
)
# resp.signing_responses[0].signature is a valid BLS signature by a wallet-derived key
# over attacker_chosen_message, unconstrained to any real transaction.
```

        pks: list[bytes] = []
        signing_targets: list[SigningTarget] = []
        for spend in spends:
            coin_spend = spend.as_coin_spend()
            # Get AGG_SIG conditions

                coin_spend.puzzle_reveal,
                coin_spend.solution,
                self.max_block_cost_clvm,
            )

            for pk, msg in pkm_pairs_for_conditions_dict(
                conditions_dict, coin_spend.coin, self.agg_sig_me_additional_data
            ):

                pks.append(pk_bytes)
                fingerprint: bytes = pk.get_fingerprint().to_bytes(4, "big")
                signing_targets.append(SigningTarget(fingerprint, msg, std_hash(pk_bytes + msg)))

        return SigningInstructions(
            await self.key_hints_for_pubkeys(pks),
            signing_targets,

    async def execute_signing_instructions(
        self, signing_instructions: SigningInstructions, partial_allowed: bool = False
    ) -> list[SigningResponse]:
        pk_lookup: dict[int, G1Element] = (
            {self.root_pubkey.get_fingerprint(): self.root_pubkey} if self.root_private_key is not None else {}
        )
        sk_lookup: dict[int, PrivateKey] = (
            {self.root_pubkey.get_fingerprint(): self.root_private_key} if self.root_private_key is not None else {}
        )
        aggregate_responses_at_end: bool = True
        responses: list[SigningResponse] = []

        # TODO: expand path hints and sum hints recursively (a sum hint can give a new key to path hint)
        # Next, expand our pubkey set with path hints
        if self.root_private_key is not None:
            for path_hint in signing_instructions.key_hints.path_hints:
                if int.from_bytes(path_hint.root_fingerprint, "big") != self.root_pubkey.get_fingerprint():
                    if not partial_allowed:
                        raise ValueError(f"No root pubkey for fingerprint {self.root_pubkey.get_fingerprint()}")
                    else:
                        continue
                else:
                    path = [int(step) for step in path_hint.path]
                    derive_child_sk = _derive_path(self.root_private_key, path)
                    derive_child_sk_unhardened = _derive_path_unhardened(self.root_private_key, path)
                    derive_child_pk = derive_child_sk.get_g1()
                    derive_child_pk_unhardened = derive_child_sk_unhardened.get_g1()
                    pk_lookup[derive_child_pk.get_fingerprint()] = derive_child_pk
                    pk_lookup[derive_child_pk_unhardened.get_fingerprint()] = derive_child_pk_unhardened
                    sk_lookup[derive_child_pk.get_fingerprint()] = derive_child_sk
                    sk_lookup[derive_child_pk_unhardened.get_fingerprint()] = derive_child_sk_unhardened
