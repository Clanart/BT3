### Title
Cached FROST preprocess reused across signing attempts with different signer sets/messages enables secret share recovery via nonce reuse — (File: coordinator/src/tributary/signing_protocol.rs)

### Summary
`SigningProtocol::preprocess_internal` caches a single deterministic preprocess seed keyed only by `context` (`(b"DkgConfirmer", attempt)`). Every subsequent call to `share_internal`/`complete_internal` for that context rebuilds `AlgorithmSignMachine` from the *same* seed via `from_cache` → `seeded_preprocess`, which feeds the seed into `ChaCha20Rng` and regenerates the identical nonces `(d, e)`. If `share`/`complete` is invoked more than once within one attempt with a different preprocess set or a different `key_pair` message — e.g., after blaming an `InvalidParticipant` and retrying, or signing a second `set_keys_message` — the same nonces are committed under different binding factors `rho` and/or different challenges `c`. The broadcast signature shares then form linear equations that recover the validator's secret share (its actual MuSig/validator private key).

### Finding Description
In `SigningProtocol::preprocess_internal` (coordinator/src/tributary/signing_protocol.rs:100-148), the preprocess seed is fetched-or-created under `CachedPreprocesses` keyed by `self.context`, decrypted with a key derived from `context || key`, and passed to `AlgorithmSignMachine::from_cache`. `seeded_preprocess` (crypto/frost/src/sign.rs:121-144) deterministically derives `nonces` and `commitments` from `ChaCha20Rng::from_seed(*seed.0)`, so two invocations with the same context produce identical nonces and identical published commitments.

`DkgConfirmer` sets `context = (b"DkgConfirmer", self.attempt)` (line 275). Its `share` (line 304) and `complete` (line 312) both funnel into `share_internal`, and `complete` *re-runs* `share_internal` (line 321-324). The signed message is `set_keys_message(set, removed, key_pair)` where `key_pair` is supplied per-call (line 296-300), and the preprocess map is supplied per-call and remapped by `threshold_i_map_to_keys_and_musig_i_map` (line 294-295), which can produce different MuSig signer sets if the preprocess sets differ.

Concretely, a first `share(...)` call may fail with `InvalidParticipant(p)` (an unprivileged peer feeds a malformed preprocess — reachable via `read_preprocess` on untrusted bytes, per scope). On retry with the blamed participant excluded, `included` changes, so FROST's per-participant binding factor `rho` (computed over `hash_msg` and the preprocess commitments) changes while `d`, `e` stay identical. The two shares `s = d + e·rho + λ·x·c` and `s' = d + e·rho' + λ'·x·c'` over different messages give two equations; anyone observing both public shares recovers `x` — the validator's private key. This is exactly the nonce-reuse/preprocess-reuse failure the spec warns about (spec/cryptography/FROST.md:51-55), but triggered here by design because the cache is consumed on every signing call within the same context rather than being deleted after first use.

### Impact Explanation
Recovery of a validator's `Ristretto` secret key (the same `self.key` used as the MuSig private key for the set). An attacker who triggers or merely observes two shares produced under one attempt — differing in signer set or `key_pair` — can reconstruct the key and thereafter forge the validator's participation in the tributary signing protocol (equivocation, signing unintended `set_keys_message`s). Both shares are broadcast publicly, so passive observation suffices once the reuse is triggered.

### Likelihood Explanation
Triggering requires two `share`/`complete` executions within a single DKG attempt, which occurs on the blame-and-retry path (`FrostError::InvalidPreprocess(l) | InvalidShare(l) => Participant` at line 177/200) or if `complete` is invoked after `share` with a different preprocess map. An unprivileged participant controls the bytes passed to `read_preprocess` (line 165), so it can force an `InvalidParticipant` outcome for a chosen signer set, inducing a retry under the same `attempt` context. Whether the coordinator's outer flow actually retries within the same attempt (rather than incrementing `attempt`) could not be fully confirmed within the iteration limit — the call sites in `coordinator/src/tributary/handle.rs` were not fully traced. If each retry increments `attempt`, the issue reduces to `complete` re-signing (same message → same share → harmless duplicate), and the vulnerability does not manifest.

### Recommendation
Consume the cached preprocess on first use: delete `CachedPreprocesses::get(context)` (or mark it spent) inside `preprocess_internal`/`share_internal` after calling `from_cache`, and generate a fresh seed for every new `sign` invocation — including retries with reduced signer sets and the re-derivation inside `complete`. If `complete` must reuse the share produced by `share`, cache the produced `AlgorithmSignatureMachine`/share rather than re-running `share_internal` on the same seed. Alternatively, key the cache by `(context, included_set, msg_hash)` and refuse to sign if the seed would be reused with different `rho`/`c`.

### Proof of Concept
1. In DKG attempt `a`, the coordinator calls `DkgConfirmer::share(preprocesses_A, key_pair)` where `preprocesses_A` contains a malformed preprocess for participant `p`. `read_preprocess` fails → `InvalidParticipant(p)`; `p` is blamed.
2. The coordinator retries within attempt `a` with `preprocesses_B = preprocesses_A \ {p}` (or `complete` is invoked with a different map/`key_pair`). `preprocess_internal` returns the same decrypted seed; `seeded_preprocess` regenerates identical nonces `d, e` and identical published commitments.
3. `sign` computes new binding factors `rho'` over the changed `included`/commitment set and a new challenge `c'` over the changed message. The validator broadcasts share `s' = d + e·rho' + λ'·x·c'` alongside the earlier `s = d + e·rho + λ·x·c`.
4. Any observer of the tributary solves the two linear equations for the validator's MuSig secret `x` (and nonces `d, e`), recovering the validator's private key — a private-key-share disclosure caused purely by untrusted preprocess bytes and publicly broadcast shares.
