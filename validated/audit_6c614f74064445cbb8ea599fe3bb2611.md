### Title
Automatic silent rewrite of the local git remote URL from an untrusted GitHub API `clone_url` value - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
When Desktop refreshes a repository's GitHub association (done automatically before every pull/push/fetch), it fetches the repository object from the GitHub API and, if the returned `clone_url` differs from the locally configured `origin` URL, silently rewrites the git remote to the new URL via `git remote set-url` — with no user confirmation and no verification that the API response actually refers to the same underlying repository the user originally added.

### Finding Description
`_pull`/`_fetch`/`_push` flows call `withRefreshedGitHubRepository`, which invokes `repositoryWithRefreshedGitHubRepository`: [1](#0-0) 

This function re-derives `owner`/`name` purely from parsing the *current* git remote URL string (`matchGitHubRepository`), then calls `api.fetchRepository(owner, name)` to get a fresh `IAPIFullRepository`, and passes the result straight into `updateRemoteUrl`: [2](#0-1) 

The only checks performed are:
- protocol equality between old and new URL,
- that the previously *cached* clone URL still matches the current remote (i.e. the user hasn't manually edited it),
- that the new URL differs from the current one.

None of these checks validate that the new `clone_url` refers to the *same* repository (e.g. by GitHub's immutable numeric repository id). The local database itself keys `GitHubRepository`/`Owner` records by `[ownerID+name]` / `login` strings rather than the API's immutable `id`: [3](#0-2) 

If `protocolsMatch && remoteUrlUnchanged && !urlsMatch`, Desktop calls `gitStore.setRemoteURL`, which directly executes `git remote set-url` without any diff/confirmation dialog to the user: [4](#0-3) [5](#0-4) 

This is analogous to the PoolTogether bug's broken invariant: a piece of persistent state (the local `origin` remote / cached `cloneURL`) is mutated based on an externally-supplied object (the GitHub API repository response) whose trustworthiness/identity was never re-validated against the invariant it's supposed to preserve (that it's still the *same* repository), and the mutation happens transparently as a side effect of a routine, unprivileged operation (pull/fetch/push) rather than an explicit, confirmed user action.

### Impact Explanation
If the value returned by `fetchRepository` for the resolved `owner/name` legitimately (or through GHE server compromise/MITM, or through GitHub repository-rename/ownership-transfer edge cases) points to a different underlying repository than the one the user originally cloned, Desktop will automatically retarget the user's `origin` remote to that new location with no visual diff or confirmation. Because this happens transparently as part of a routine pull/fetch/push, the user's subsequent `git push` can silently upload their commits (potentially private source code) to a repository the user never intended to push to, and a subsequent `git pull`/`fetch` can silently bring in commits from an unintended repository, which the user may then merge and build/run. This matches the accepted impact classes of "silent corruption of what the user commits or pushes" and potential downstream code execution from pulled content.

### Likelihood Explanation
The refresh path (`repositoryWithRefreshedGitHubRepository` → `updateRemoteUrl`) fires automatically on ordinary `_pull`/`_fetch`/`_push` operations with no special user action required beyond routine repository usage, and the trust decision hinges entirely on the API response for a given `owner/name`, which the app resolves fresh on every refresh cycle from the string-based git remote URL rather than a stable repository identity. The only mitigating checks (protocol match, unchanged-cache check) are heuristic string comparisons, not identity verification.

### Recommendation
Before automatically rewriting the remote URL, verify that the new API repository object refers to the same repository as before (e.g. compare a stored immutable repository `id`, not just owner/name strings), and/or require explicit user confirmation (similar to the manual "Repository Settings" remote URL change flow) before calling `setRemoteURL` as a side effect of a background refresh.

### Proof of Concept
1. Clone a GitHub repository, `origin` = `https://github.com/owner/repo`. Desktop caches `gitHubRepository.cloneURL = https://github.com/owner/repo`.
2. On a subsequent `_pull`/`_fetch`/`_push`, `repositoryWithRefreshedGitHubRepository` resolves `owner/repo` from the current remote and calls `api.fetchRepository('owner', 'repo')`.
3. If the API (a malicious/compromised GHE endpoint, or a repository-identity edge case) returns an `IAPIFullRepository` whose `clone_url` is `https://github.com/owner/repo2` (attacker-controlled destination, same protocol/host):
   - `protocolsMatch` = true
   - `remoteUrlUnchanged` = true (cached cloneURL still matches current remote)
   - `urlsMatch` = false (different repo path)
4. `updateRemoteUrl` calls `gitStore.setRemoteURL('origin', 'https://github.com/owner/repo2')`, silently rewriting `origin` — confirmed by the existing unit test demonstrating the update fires under exactly these conditions: [6](#0-5) 
5. The next `git push` from the user now targets `repo2` instead of the originally intended repository, with no prompt shown to the user.

  private async repositoryWithRefreshedGitHubRepository(
    repository: Repository
  ): Promise<Repository> {
    const repoStore = this.repositoriesStore
    const match = await this.matchGitHubRepository(repository)

    // TODO: We currently never clear GitHub repository associations (see
    // https://github.com/desktop/desktop/issues/1144). So we can bail early at
    // this point.
    if (!match) {
      return repository
    }

    const { account, owner, name } = match
    const { endpoint } = account
    const api = API.fromAccount(account)
    const apiRepo = await api.fetchRepository(owner, name)

    if (apiRepo === null) {
      // If the request fails, we want to preserve the existing GitHub
      // repository info. But if we didn't have a GitHub repository already or
      // the endpoint changed, the skeleton repository is better than nothing.
      if (endpoint !== repository.gitHubRepository?.endpoint) {
        const ghRepo = await repoStore.upsertGitHubRepositoryFromMatch(match)
        return repoStore.setGitHubRepository(repository, ghRepo)
      }

      return repository
    }

    if (repository.gitHubRepository) {
      const gitStore = this.gitStoreCache.get(repository)
      await updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)
    }

import { IAPIRepository } from '../../api'
import { GitStore } from '../git-store'
import { urlMatchesRemote } from '../../repository-matching'
import * as URL from 'url'
import { GitHubRepository } from '../../../models/github-repository'

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

export async function setRemoteURL(
  repository: Repository,
  name: string,
  url: string
): Promise<true> {
  await git(['remote', 'set-url', name, url], repository.path, 'setRemoteURL')
  return true
}
