### Title
Auction bid `maxGasPrice` field is unauthenticated under the V2 EIP-712 typehash, allowing bid-parameter tampering while preserving a valid searcher signature - ([File: kaiax/auction/eip712.go])

### Summary
The `auction_submitBid` RPC (reachable by any auction bidder/searcher submitting a bid over RPC, per `kaiax/auction/impl/api.go`) accepts a `BidInput` struct that includes an optional `MaxGasPrice` field alongside all other bid parameters. This field is copied verbatim into the `auction.Bid`/`BidData` that is inserted into the bid pool [1](#0-0) , but the EIP-712 struct hash used to verify the searcher's signature under `AuctionVersionV2` ("0.0.1") does not include `maxGasPrice` at all [2](#0-1) [3](#0-2) . Only the newer `AuctionVersionV3` ("0.0.2") typehash/encoder binds `maxGasPrice` into the signed digest [4](#0-3) .

### Finding Description
This is the same bug class as the Flowise mass-assignment issue: a create/submit endpoint (`auction_submitBid`) accepts a full attacker-controlled struct (`BidInput`), but the authorization mechanism protecting that struct (the searcher's EIP-712 signature) does not cover every field that gets persisted and later acted upon.

`BidPool.validateBidSigs` verifies the searcher signature by recomputing `bid.GetHashTypedData(chainId, verifyingContract, version)` where `version` is `bp.auctionEntryPointVersion`, read from the on-chain `AuctionEntryPoint.AUCTION_VERSION()` [5](#0-4) . `GetHashTypedData` branches on this `version`: only `AuctionVersionV3` uses the `bidV3` encoder that includes `maxGasPrice` in the struct hash; `AuctionVersionV2` (and any unknown/default version) uses the plain `Bid` encoder, whose `EncodeData` never serializes `MaxGasPrice` [6](#0-5) [7](#0-6) .

Consequently, for any deployment/period where the on-chain `AuctionEntryPoint` reports version `0.0.1` (V2), a valid `SearcherSig` produced for one `MaxGasPrice` value (including "unset"/nil) remains valid for the exact same bid with an arbitrary, attacker-substituted `MaxGasPrice`, because that field is entirely outside the signed digest. `Bid.Hash()` (used for pool de-duplication/keying) is computed over the full `BidData` via RLP, not the EIP-712 digest, so a modified `MaxGasPrice` produces a different pool entry hash but an identical, still-valid `SearcherSig`/`AuctioneerSig` pair [8](#0-7) . `BidPool.AddBid` → `validateBid` → `validateBidSigs` will accept this tampered bid because signature verification passes [9](#0-8) .

### Impact Explanation
`MaxGasPrice` is intended to represent the searcher's self-declared cap on gas price for their bid transaction — a value they explicitly agreed to via signature. Because it is unauthenticated under the V2 typehash, any RPC caller who observes a valid signed bid (e.g., from a prior submission, mempool gossip, or replay) can resubmit it with a different `MaxGasPrice` while the searcher's original signature is still accepted as valid. This allows fee-abuse: forcing the bid to be processed with a different maximum gas price than the searcher actually authorized, undermining the fee/price guarantee the searcher's signature was supposed to provide, without invalidating cryptographic authorization — a direct parallel to the Flowise mass-assignment issue where extra unauthorized fields ride along with an otherwise-legitimate update.

### Likelihood Explanation
Exploitation requires only observing one valid signed `BidInput` (trivially obtainable since a searcher must submit it via the public `auction_submitBid` RPC or it propagates via the bid gossip handler) and resubmitting it with a modified `maxGasPrice` while the auction entry point is on `AuctionVersionV2`. No special privileges, node access, or cryptographic breaks are needed — only a single crafted RPC call, matching the "unprivileged... auction bidder" reachability criterion.

### Recommendation
Bind `maxGasPrice` into the signed digest unconditionally (not only for V3), or reject/ignore `MaxGasPrice` entirely when the negotiated auction version is V2, so that no field influencing bid execution can be modified independent of the searcher's signature. Alternatively, treat `MaxGasPrice` as a first-class required field validated by hash equality against the pool's canonical `Bid.Hash()` prior to signature checks, ensuring tampering with any field invalidates the entry regardless of protocol version.

### Proof of Concept
1. A searcher signs a `BidInput` with `MaxGasPrice` unset (nil) or set to value `X`, targeting an `AuctionEntryPoint` whose `AUCTION_VERSION()` returns `"0.0.1"`.
2. An attacker observes this bid (via RPC response, bid pool gossip handler `HandleBid`, or resubmission) and constructs a new `BidInput` identical in every field except `MaxGasPrice`, set to value `Y ≠ X`.
3. The attacker calls `auction_submitBid` with the tampered input, reusing the original `SearcherSig`/`AuctioneerSig`.
4. `BidPool.validateBidSigs` recomputes the V2 EIP-712 digest via `Bid.EncodeData`, which never serializes `MaxGasPrice`; the digest matches, `ValidateSearcherSig` succeeds, and `AddBid` accepts the tampered bid [10](#0-9) .

// GetHashTypedData returns the EIP-712 digest for the bid.
// version must match the on-chain AUCTION_VERSION of the entry-point contract
// the bid targets; "0.0.2" selects the v3.0 struct typehash (with maxGasPrice),
// any other value falls back to the v2.1 typehash.
func (b *Bid) GetHashTypedData(chainId *big.Int, verifyingContract common.Address, version string) []byte {
	if chainId == nil {
		return nil
	}

	domain := EIP712Domain{
		EIP712DomainTypeHash: eip712TypeHash,
		NameHash:             auctionNameHash,
		VersionHash:          crypto.Keccak256Hash([]byte(version)),
		ChainId:              chainId,
		VerifyingContract:    verifyingContract,
	}

	domainSeparator := EncodeEIP712(domain)

	var structHash []byte
	if version == AuctionVersionV3 {
		structHash = EncodeEIP712(bidV3{b})
	} else if version == AuctionVersionV2 {
		structHash = EncodeEIP712(b)
	} else {
		// Unknown version: default to v2.1 typehash.
		structHash = EncodeEIP712(b)
	}

	return crypto.Keccak256([]byte{0x19, 0x01}, domainSeparator, structHash)

func (bp *BidPool) AddBid(bid *auction.Bid) (common.Hash, error) {
	if atomic.LoadUint32(&bp.running) == 0 {
		return common.Hash{}, auction.ErrAuctionPaused
	}

	if err := bp.validateBid(bid); err != nil {
		return common.Hash{}, err
	}

	if err := bp.insertBid(bid); err != nil {
		return common.Hash{}, err
	}

	gasLimit, err := bp.getBidTxGasLimit(bid)
	if err != nil {
		return common.Hash{}, err
	}
	bid.SetGasLimit(gasLimit)

	bp.newBidCh <- bid

	return bid.Hash(), nil
}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}
