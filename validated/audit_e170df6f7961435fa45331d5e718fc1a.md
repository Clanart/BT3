## Analog identified [1](#0-0) 

### Title
Path-containment bypass in `resolveWithin` via missing path-separator boundary check (sibling-directory prefix collision) - (File: app/src/lib/path.ts)

### Summary
The external report's broken invariant is: a security gate that is supposed to be the sole arbiter of "is this action within the allowed boundary" contains a subtle logic flaw that lets an attacker-controlled value slip past the boundary while looking legitimate to the code reading it. In the Solidity report this was selector/sender-based routing; the closest real analog found in this codebase is GitHub Desktop's directory-containment guard `resolveWithin`, which is trusted throughout the app to guarantee "this resolved path is inside the repository," but its final comparison is a naive string-prefix check without verifying a path-separator boundary.

### Finding Description
`_resolveWithin` in [2](#0-1)  resolves a candidate path and then decides containment purely with:
```
return realResolved.startsWith(realRoot) ? resolved : null
```
This is a classic prefix-check flaw: `startsWith` does not require the next character after the matched prefix to be a path separator. If `realRoot` is `/Users/victim/Documents/GitHub/myrepo` and a sibling directory `/Users/victim/Documents/GitHub/myrepo-secrets` exists, then `realResolved = "/Users/victim/Documents/GitHub/myrepo-secrets/data.txt"` satisfies `startsWith(realRoot)` even though it is a completely different directory tree, not a subdirectory of `myrepo`.

The resolved candidate is built from attacker-influenced input via `resolve(normalizedRoot, normalizedRelative)`, where `normalizedRelative` can contain `..` segments supplied by the attacker (the function explicitly documents that it accepts such input and is meant to reject anything that escapes the root — see the doc comment at lines 13-24). A relative segment like `../myrepo-secrets/data.txt` produces exactly this sibling-collision path, and no symlink is even required to trigger it — pure `..` traversal into a same-parent sibling whose name happens to begin with the root's basename is sufficient.

This guard is the single point of trust used in at least two attacker-reachable call sites:
- `openRepositoryFromUrl` in [3](#0-2)  — the `filepath` field comes directly from a parsed deep link (`x-github-client://openrepo/...?filepath=...`), i.e. attacker-controlled content a user is lured into clicking, per `parseAppURL` in [4](#0-3) .
- Copilot conflict resolution writes in [5](#0-4)  and [6](#0-5) , where `resolveWithin(repository.path, resolution.path)` gates a subsequent `writeFile(absolutePath, ...)`. `resolution.path` originates from AI-suggested conflict resolutions derived from file paths reported by `git status`/diff for a cloned repository — paths that an attacker who controls the repository content (a malicious commit/tree entry) can influence.

### Impact Explanation
If a directory named `<repoBasename><suffix>` exists as a sibling of the checked-out repository (a common occurrence — e.g. `project` and `project-backup`, `project` and `project.wiki`, or two repos cloned into the same parent with similar names), an attacker can craft a `filepath`/conflict `resolution.path` value such as `../<repoBasename><suffix>/<target>` that:
- Passes `resolveWithin`'s containment check because of the missing separator boundary.
- Results in `shell.showItemInFolder` revealing, or — in the Copilot write path — `writeFile` overwriting, a file **outside** the intended repository root, silently corrupting content the user did not intend to touch.

This matches the "silent corruption of what the user commits" and "file write/read outside the repo" impact classes explicitly called out as valid.

### Likelihood Explanation
Exploitation requires: (1) the victim clicking an attacker-supplied deep link (`x-github-client://openrepo/...`) or opening a malicious/collaborative repository whose conflicting files drive Copilot's resolution paths, and (2) an on-disk sibling directory whose name is a superstring of the repo's basename. Sibling directories with overlapping name prefixes are a realistic, unprompted, naturally occurring layout (backup folders, forks cloned side-by-side, `.wiki` companion repos), so this does not require any local/physical access, admin rights, or pre-existing malware — only normal Desktop usage plus one link click or one untrusted clone, which is within the valid unprivileged-attacker model.

### Recommendation
Fix the boundary check to require a path separator (or exact equality) after the matched prefix:
```ts
return realResolved === realRoot || realResolved.startsWith(realRoot + Path.sep)
  ? resolved
  : null
```
Apply the same fix to `resolveWithinPosix`/`resolveWithinWin32` (they share `_resolveWithin`), and add regression tests covering the sibling-directory-with-shared-prefix case for both the non-symlink and symlink scenarios (extending the existing suite in [7](#0-6) , which currently only tests exact-parent-traversal and symlink escape, not the prefix-collision case).

### Proof of Concept
1. Layout on disk:
   - `/Users/victim/Documents/GitHub/myrepo` (a Desktop-tracked repository)
   - `/Users/victim/Documents/GitHub/myrepo-evil/secret.txt` (attacker-influenced or pre-existing sibling directory)
2. Attacker sends the victim a link:
   `x-github-client://openrepo/https://github.com/owner/myrepo?filepath=..%2Fmyrepo-evil%2Fsecret.txt`
3. `parseAppURL` extracts `filepath = "../myrepo-evil/secret.txt"` (no invalid-char rejection applies to `filepath`, only to `branch`) — see [8](#0-7) .
4. `dispatcher.openRepositoryFromUrl` calls `isAbsolute(filepath)` (false, since it's relative) then `resolveWithin(repository.path, filepath)` — see [3](#0-2) .
5. Inside `_resolveWithin`, `resolved = "/Users/victim/Documents/GitHub/myrepo-evil/secret.txt"`; `realRoot = "/Users/victim/Documents/GitHub/myrepo"`; `realResolved.startsWith(realRoot)` evaluates `true` due to the shared string prefix, even though `myrepo-evil` is not inside `myrepo`.
6. `shell.showItemInFolder(resolved)` reveals the outside-repo file to the user as if it belonged to `myrepo`; in the Copilot write path the equivalent flaw lets `writeFile` overwrite `secret.txt` outside the repository.

async function _resolveWithin(
  rootPath: string,
  pathSegments: string[],
  options: {
    join: (...pathSegments: string[]) => string
    normalize: (p: string) => string
    resolve: (...pathSegments: string[]) => string
  } = Path
) {
  // An empty root path would let all relative
  // paths through.
  if (rootPath.length === 0) {
    return null
  }

  const { join, normalize, resolve } = options

  const normalizedRoot = normalize(rootPath)
  const normalizedRelative = normalize(join(...pathSegments))

  // Null bytes has no place in paths.
  if (
    normalizedRoot.indexOf('\0') !== -1 ||
    normalizedRelative.indexOf('\0') !== -1
  ) {
    return null
  }

  // Resolve to an absolute path. Note that this will not contain
  // any directory traversal segments.
  const resolved = resolve(normalizedRoot, normalizedRelative)

  const realRoot = await realpath(normalizedRoot)
  const realResolved = await realpath(resolved)

  return realResolved.startsWith(realRoot) ? resolved : null
}

export function parseAppURL(url: string): URLActionType {
  const parsedURL = URL.parse(url, true)
  const hostname = parsedURL.hostname
  const unknown: IUnknownAction = { name: 'unknown', url }
  if (!hostname) {
    return unknown
  }

  const query = parsedURL.query

  const actionName = hostname.toLowerCase()
  if (actionName === 'oauth') {
    const code = getQueryStringValue(query, 'code')
    const state = getQueryStringValue(query, 'state')
    if (code != null && state != null) {
      return { name: 'oauth', code, state }
    } else {
      return unknown
    }
  }

  // we require something resembling a URL first
  // - bail out if it's not defined
  // - bail out if you only have `/`
  const pathName = parsedURL.pathname
  if (!pathName || pathName.length <= 1) {
    return unknown
  }

  // Trim the trailing / from the URL
  const parsedPath = pathName.substring(1)

  if (actionName === 'openrepo') {
    const pr = getQueryStringValue(query, 'pr')
    const branch = getQueryStringValue(query, 'branch')
    const filepath = getQueryStringValue(query, 'filepath')

    if (pr != null) {
      if (!/^\d+$/.test(pr)) {
        return unknown
      }

      // we also expect the branch for a forked PR to be a given ref format
      if (branch != null && !/^pr\/\d+$/.test(branch)) {
        return unknown
      }
    }

    if (branch != null && testForInvalidChars(branch)) {
      return unknown
    }

    return {
      name: 'open-repository-from-url',
      url: parsedPath,
      branch,
      pr,
      filepath,
    }
  }

  describe('resolveWithin', () => {
    const root = process.cwd()

    it('fails for paths outside of the root', async () => {
      assert((await resolveWithin(root, join('..'))) === null)
      assert((await resolveWithin(root, join('..', '..'))) === null)
    })

    it('succeeds for paths that traverse out, and then back into, the root', async () => {
      assert.equal(await resolveWithin(root, join('..', basename(root))), root)
    })

    it('fails for paths containing null bytes', async () => {
      assert((await resolveWithin(root, 'foo\0bar')) === null)
    })

    it('succeeds for absolute relative paths as long as they stay within the root', async () => {
      const parent = resolve(root, '..')
      assert.equal(await resolveWithin(parent, root), root)
    })

    if (!__WIN32__) {
      it('fails for paths that use a symlink to traverse outside of the root', async () => {
        const tempDir = await mkdtemp(join(tmpdir(), 'path-test'))
        const symlinkName = 'dangerzone'
        const symlinkPath = join(tempDir, symlinkName)
