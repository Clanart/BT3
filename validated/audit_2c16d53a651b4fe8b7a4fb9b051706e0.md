## Analog Found

### Title
Auction bid's `MaxGasPrice` slippage-protection field is never validated or enforced when admitting or building bid transactions - (File: `kaiax/auction/impl/bid_pool.go`, `kaiax/auction/impl/getter.go`)

### Summary
The KIP-249 v3.0 auction bid schema introduces `BidData.MaxGasPrice` as the searcher's declared upper bound on the gas price they are willing to pay for their bid execution — functionally the auction analog of a `minAmountOut`/slippage-protection parameter. However, neither the bid-pool admission logic nor the bid-transaction builder ever reads or checks this field, so the protection it is meant to provide is entirely unenforced.

### Finding Description
`BidData` explicitly carries a `MaxGasPrice` field intended to cap what a searcher will pay: [1](#0-0) . The v3.0 EIP-712 typehash and calldata encoding include this field, confirming it is a first-class, security-relevant parameter that searchers sign over: [2](#0-1)  and [3](#0-2) .

Despite this, `BidPool.validateBid`, which is the sole gate for admitting a bid into the pool, only checks sender/winner conflicts, block-number range, `bid.Bid > 0`, data size, call-gas-limit, and signatures — `MaxGasPrice` is never referenced: [4](#0-3) . The module's own documented "Bid pool validation rules" list (six rules) confirms `MaxGasPrice` was never intended to be checked here: [5](#0-4) .

Worse, when the CN actually builds the transaction that will consume the bid, `GetBidTxGenerator` derives `GasFeeCap`/`GasTipCap` from the *target transaction* the bid is attached to, not from `bid.MaxGasPrice`: [6](#0-5) . `MaxGasPrice` is used only for EIP-712 signature verification purposes and is otherwise dead data as far as gas-price bounding goes.

### Impact Explanation
Because `MaxGasPrice` is signed by the searcher as their contractual maximum acceptable gas cost but is never checked against the actual gas price used for the generated bid transaction, a searcher can be forced to pay for their winning bid at any prevailing network gas price — potentially far above what they explicitly declared and cryptographically committed to. This is a direct, unauthorized-value-extraction analog to the reported "rebalance() lacks slippage protection" issue: a protection field exists in the schema/signature but is not enforced at the point value is actually moved (fee payment), letting the searcher's cost run away between bid signing and block inclusion.

### Likelihood Explanation
Any account acting as an "Auctioneer"-forwarded bid or (in the mock/no-arbitration path) an auction bidder submitting through `auction_submitBid` can trigger this: the bid pool and generator process every admitted bid identically, with no code path checking `MaxGasPrice`. Since gas price/base fee can move between when a searcher signs a bid and when the CN builds/executes the corresponding transaction (across `allowFutureBlock` blocks), this is a naturally reachable condition, not a contrived edge case.

### Recommendation
Enforce `bid.MaxGasPrice` in two places: (1) reject/limit bids in `BidPool.validateBid` when `MaxGasPrice` is set to an unreasonably low or zero value inconsistent with the current pool base fee (as appropriate to policy), and (2) in `GetBidTxGenerator`, cap the generated transaction's `GasFeeCap`/`GasTipCap` to `bid.MaxGasPrice` (or fail bid tx generation) instead of unconditionally copying the target transaction's fee caps, so a searcher never pays more than the value they signed.

### Proof of Concept
1. Searcher submits a v3.0 bid via `auction_submitBid` with `MaxGasPrice = X`, signing the EIP-712 digest that includes `MaxGasPrice` per [7](#0-6) .
2. `BidPool.AddBid` → `validateBid` admits the bid without ever inspecting `MaxGasPrice`: [8](#0-7) .
3. When the target transaction is seen, `ExtractTxBundles` calls `GetBidTxGenerator(tx, bid)`, which sets the bid transaction's `GasFeeCap`/`GasTipCap` from `tx.GasFeeCap()`/`tx.GasTipCap()` (the target tx's fee), completely ignoring `bid.MaxGasPrice`: [9](#0-8) .
4. If the target transaction's (or network's) gas price at inclusion time exceeds `X`, the searcher's bid transaction executes and pays gas fees above the maximum they explicitly signed for, with no on-chain or off-chain check preventing it.

	maxGasPrice := b.MaxGasPrice
	if maxGasPrice == nil {
		maxGasPrice = new(big.Int)
	}
	encoded := make([]byte, 0, 10*32)
	encoded = append(encoded, b.TargetTxHash.Bytes()...)
	encoded = append(encoded, common.LeftPadBytes(common.Int64ToByteBigEndian(b.BlockNumber), 32)...)
	encoded = append(encoded, common.LeftPadBytes(b.Sender.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(b.To.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(common.Int64ToByteBigEndian(b.Nonce), 32)...)
	encoded = append(encoded, common.LeftPadBytes(b.BidData.Bid.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(maxGasPrice.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(common.Int64ToByteBigEndian(b.CallGasLimit), 32)...)
	encoded = append(encoded, crypto.Keccak256Hash(b.Data).Bytes()...)
	return encoded
}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}

## Bid pool validation rules

A bid pool is responsible for managing the valid bids from the `Auctioneer`. The bid must satisfy the following rules:

1. The `bid.Sender` must not be in the winner list of the same block number if the new bid doesn't have the same target block and hash as the previous bid.
2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
3. The `bid.Bid` must be greater than 0.
4. The `bid.Data` size must be less than or equal to `BidTxMaxDataSize`.
5. The `bid.CallGasLimit` must be less or equal to `BidTxMaxCallGasLimit`.
6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.

Please note that `Auctioneer` also validates the searcher's bid according to the KIP-249.

func (a *AuctionModule) GetBidTxGenerator(tx *types.Transaction, bid *auction.Bid) *builder.TxOrGen {
	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId           = a.InitOpts.ChainConfig.ChainID
			signer            = types.LatestSignerForChainID(chainId)
			auctionEntryPoint = a.bidPool.GetAuctionEntryPoint()
			key               = a.InitOpts.NodeKey
		)

		data, err := system.EncodeAuctionCallData(bid, a.bidPool.GetAuctionEntryPointVersion())
		if err != nil {
			return nil, err
		}

		if bid.GetGasLimit() == 0 {
			gasLimit, err := a.bidPool.getBidTxGasLimit(bid)
			if err != nil {
				return nil, err
			}
			bid.SetGasLimit(gasLimit)
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &auctionEntryPoint,
			types.TxValueKeyAmount:     common.Big0,
			types.TxValueKeyData:       data,
			types.TxValueKeyGasLimit:   bid.GetGasLimit(),
			types.TxValueKeyGasFeeCap:  tx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  tx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)

		return tx, err
	}
