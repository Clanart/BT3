### Title
Variable-time modular reduction in Ed448 scalar construction leaks nonce/key material via timing - (File: crypto/ed448/src/backend.rs)

### Summary
The Ed448 ciphersuite implements its scalar field on top of `crypto_bigint`'s `Residue`/`U896` types and performs wide-value reduction with `Uint::rem`, which is a variable-time division algorithm whose runtime depends on the value being reduced. This reduction is executed on secret-derived data every time `Curve::random_nonce` hashes `seed || secret_share` through `hash_to_F` (`crypto/frost/src/curve/mod.rs:94-121`) and whenever `Field::random`/`from_repr`-style reductions touch secret scalars in `crypto/ed448/src/backend.rs:106-108,193-197`. An attacker who can time signing operations (or DKG scalar operations) on a host they co-reside with obtains biased timing correlated with the nonce/reduction result, enabling partial-nonce recovery and, across signatures, secret share recovery — the same "improper isolation / information disclosure" class as CVE-2020-8698 mapped onto Serai's own arithmetic.

### Finding Description
`reduce` performs a general variable-time division:

```rust
// crypto/ed448/src/backend.rs:106-108
fn reduce(x: U896) -> U448 {
  U448::from_le_slice(&x.rem(&NonZero::new($WIDE_MODULUS).unwrap()).to_le_bytes()[.. 56])
}
```

`crypto_bigint::Uint::rem` uses schoolbook long division with data-dependent early exits; its timing is a function of the dividend/quotient. The same pattern exists in the Ed25519 base field implementation (`crypto/dalek-ff-group/src/field.rs:58-62`), but there it is only applied to base-field elements (public/random), whereas for Ed448 the scalar type built by the same `field!` macro machinery is reduced this way for every scalar.

The secret-reaching path is:

- `SignMachine::sign` → `NonceCommitments::new` → `Curve::random_nonce` (`crypto/frost/src/curve/mod.rs:110-117`), which computes `hash_to_F(b"nonce", seed || repr(secret_share))`. For the Ed448 ciphersuite, `hash_to_F`/`Scalar` construction routes through the `reduce`/`Residue` machinery, so the timing of nonce derivation is a function of a value that is H(seed || secret_share).
- `Field::random` (`backend.rs:193-197`) similarly reduces freshly drawn 112 bytes with the same variable-time `rem`, affecting `C::random_nonzero_F` used for PedPoP coefficients (`crypto/dkg/pedpop/src/lib.rs:167`) and signing nonces (`pedpop/src/lib.rs:174`).
- `FieldElement::invert`/`sqrt` use `self.pow(NEG_2)` / `pow(MOD_1_4)` on a `Residue`; `Residue` internals are constant-time for multiplication, but the code also relies on `FieldElement`'s derived `PartialEq` (`backend.rs` `#[derive(PartialEq)]` on the wrapper over `Residue`) in equality paths such as `FieldElement::sqrt`'s `ct_eq` wrapper — those are CT — however the reduction itself is the exposed non-CT primitive.

The attacker-reachable trigger is public input: any signing request the attacker can cause (`AlgorithmMachine::sign`/`SignatureMachine` flow over attacker-supplied `msg` and preprocesses) forces a fresh `random_nonce` computation on the victim's secret share. No privileged access to Serai internals is needed — just the ability to feed messages for signing and measure the operation, analogous to the local-access information disclosure of the CVE.

### Impact Explanation
Timing leakage of `H(seed || secret_share)` and of the reduced nonce scalar leaks bits of each signing nonce. In FROST/Schnorr, each share is `z_i = d_i + (b·e_i) + λ_i·s_i·c`; recovery of even partial nonce bits across many signatures (lattice/HNP attack) recovers the signer's secret share `λ_i·s_i`, equivalent to recovering the threshold key share — full key-share disclosure, the concrete "secret leakage" outcome required for acceptance.

### Likelihood Explanation
Medium. Exploitation requires precise timing measurement (local co-residency or high-resolution remote timing), and the magnitude of the leak per operation is small (division early-exit behavior). But the operation is invoked on every signature and every DKG round with zero attacker privileges beyond submitting messages to be signed, and the underlying `rem`/`pow` timing variance is structural, not speculative — `crypto_bigint` documents its division as variable-time. For Ed25519 the analogous `reduce` only touches base-field data, so this primarily affects deployments using the Ed448 ciphersuite for FROST/PedPoP.

### Recommendation
- Replace `x.rem(&NonZero::new(WIDE_MODULUS))` in both `reduce` functions with a constant-time reduction (e.g., `crypto_bigint::modular::constant_mod` wide reduction, Barrett reduction, or a CT `Residue` constructor that accepts the wide form).
- Avoid `Uint::pow`-based inversion on secrets where the exponent path isn't constant-time; prefer the provided constant-time `invert`/`sqrt` machinery of the residue type.
- Add CI timing checks or dudect-style analysis for `random_nonce`, `hash_to_F`, `Field::random`, and `from_repr` on both dalek-ff-group and ed448 to catch regressions.

### Proof of Concept

// Conceptual: measure timing of random_nonce under fixed secret, varying seeds.
// Variable-time `rem` correlates elapsed cycles with the hash-derived dividend.
use frost::curve::Curve;
use zeroize::Zeroizing;
use rand_core::OsRng;

let secret = Zeroizing::new(<Ed448 as Ciphersuite>::random_nonzero_F(&mut OsRng));

let _nonce = <Ed448 as Curve>::random_nonce(&secret, &mut OsRng);

// Collect (elapsed) across many sign() calls; statistical dependence on
