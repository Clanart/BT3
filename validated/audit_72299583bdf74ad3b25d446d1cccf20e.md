### Title
Loose substring-based hostname classification lets an attacker-controlled git host be misidentified as a trusted GitHub Enterprise endpoint - (File: app/src/lib/api.ts)

### Summary
GitHub Desktop decides whether a remote host should be treated as a genuine GitHub/GitHub Enterprise endpoint using a permissive regular expression on the hostname rather than validating it as a proper domain label/suffix. This "is this a GitHub host" decision is consumed by the git credential trampoline to decide how to handle authentication for a remote, which is conceptually the same class of bug as the LSP0 report: a value (here, a hostname) is reduced/matched in a way that does not match the intended, stricter identity check, so an attacker-supplied identifier collides with a trusted one.

### Finding Description
`isGitHubHost()` uses the regex `/(^|\.)(github)\./.test(hostname)` to heuristically decide whether an arbitrary hostname belongs to GitHub: [1](#0-0) 

This regex only requires the literal label `github` to appear anywhere in the hostname, bounded by dots (or start-of-string) on both sides — it does not require `github` to be the registrable domain or even a suffix label. A hostname such as `ci.github.attacker.io` or `github.attacker.io` satisfies `(^|\.)(github)\.` even though the actual registrable domain is `attacker.io`.

This function is invoked from the git credential trampoline to classify the kind of endpoint a remote/proxy is talking to: [2](#0-1) 

`getEndpointKind()` falls through to `isGitHubHost(endpoint)` only after checking `isDotCom`/`isGHE`, known accounts, and `WWW-Authenticate` headers — all of which are legitimate signals — but the final fallback trusts the loose regex match (and, prior to that, the network-probe branch inside `isGitHubHost` also trusts the same regex to short-circuit before making any request): [3](#0-2) 

Once `getEndpointKind()` returns `'enterprise'` for a host that satisfies the regex, `getCredential()` treats the endpoint as GitHub-only: if there's no existing account for that endpoint it will invoke `ui.promptForGitHubSignIn(endpoint)`, and if the endpoint is treated as GitHub it explicitly skips the generic/external credential helper path entirely: [4](#0-3) [5](#0-4) 

The broken invariant is exactly analogous to the LSP0 report: the "canonical identity" of an entity (there, a `typeId`; here, a hostname) is derived via an imprecise transformation (bytes32→bytes20 truncation there; substring/regex matching here) instead of an exact, spec-consistent identity check, so a value crafted by an untrusted party (attacker-controlled remote host) can collide with the trusted identity space (GitHub/GHE).

### Impact Explanation
An attacker who controls a git remote or an HTTP(S) proxy/host that a user is convinced to add (e.g. via a "clone this repo" link, a forked remote, or a corporate-style URL like `something.github.someattacker.com`) can get GitHub Desktop to treat that non-GitHub host as an "enterprise" GitHub endpoint. This:
- Triggers the "prompt for GitHub sign-in" / OAuth flow for a host the user has no reason to trust, which can be used to socially engineer the user into binding a spoofed "Enterprise" account entry pointed at the attacker's endpoint (account-binding confusion).
- Bypasses the generic/external git credential helper path for that host, since `getEndpointKind()` returning non-`'generic'` causes `storeCredential`/`eraseCredential`/`getCredential` to skip the external/generic credential helper logic entirely, changing how credentials for that remote are (not) stored, independent of the user's actual credential-manager configuration.

This does not require local/physical access, admin rights, or pre-existing malware — only that the user interacts with a crafted remote/host string, matching the "unauthorized OAuth or account binding" and "git remote/proxy response" categories in scope.

### Likelihood Explanation
The regex is reachable purely by choosing a remote hostname the attacker controls (e.g. registering `github.example.org` or any domain with a `github.` label bounded by dots) — no privileged network position or MITM is required for the classification bug itself, only for exploiting the credential-related side effects the classification triggers. The existing guards (`isDotCom`, `isGHE`, known-account lookup, `WWW-Authenticate` header check, `isKnownThirdPartyHost`) run first and do not stop this path because they are all checked-and-passed before falling through to the vulnerable regex, and none of them anchor the `github` label to the actual registrable domain.

### Recommendation
Replace the substring/regex heuristic in `isGitHubHost()` (`app/src/lib/api.ts`) with a strict public-suffix/registrable-domain check (e.g., verifying that the hostname equals `github.<tld>` or ends with `.github.<tld>` at the domain-label boundary using a proper URL/PSL-based comparison), and ensure `getEndpointKind()` in `trampoline-credential-helper.ts` never grants "enterprise" classification based on an unauthenticated heuristic alone without also completing the network verification (`x-github-request-id` check) that already exists later in the function.

### Proof of Concept
1. Configure a git remote (or receive one via a crafted clone/open-in-desktop URL) pointing to `https://ci.github.attacker.io/owner/repo.git`.
2. When GitHub Desktop's credential trampoline calls `getCredential()` for this remote, `getEndpointKind()` falls through the `isDotCom`/`isGHE`/account/header checks and reaches `isGitHubHost('https://ci.github.attacker.io')`.
3. `isGitHubHost` evaluates `/(^|\.)(github)\./.test('ci.github.attacker.io')`, which is `true` because `.github.` appears preceded by a dot, so the function returns `true` without ever making the network probe. [6](#0-5) 
4. `getEndpointKind()` therefore returns `'enterprise'`, and `getCredential()` prompts the user via `ui.promptForGitHubSignIn(endpoint)` for `ci.github.attacker.io`, and both `storeCredential`/`eraseCredential` skip the generic/external helper path for this attacker-controlled host. [7](#0-6)

export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)

  }

/** Implementation of the 'store' git credential helper command */
async function storeCredential(cred: Credential, store: Store, token: string) {
  if ((await getEndpointKind(cred, store)) !== 'generic') {
    return
  }

  return useExternalCredentialHelper()
    ? storeExternalCredential(cred, token)
    : setGenericCredential(
        urlWithoutCredentials(getCredentialUrl(cred)),
        forceUnwrap(`credential missing username`, cred.get('username')),
        forceUnwrap(`credential missing password`, cred.get('password'))
      )
}
