### Title
Payout tx `OP_RETURN` operator attribution is unsigned, enabling reimbursement credit to be hijacked - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
The `payout_tx` that fronts a Citrea withdrawal commits the "who fronted this payout" attribution in an `OP_RETURN` output containing the operator's x-only public key. This output is not covered by the withdrawing user's signature, whose sighash type is documented as `SinglePlusAnyoneCanPay`. `SIGHASH_SINGLE|ANYONECANPAY` only commits to the single signed input and the output at the same index (the user payout output, index 0). The anchor output (index 1) and, critically, the `OP_RETURN` output (index 2) carrying the operator attribution are left completely unsigned. Since the aggregator broadcasts the same withdrawal signature to potentially several operators at once, any of those operators (or anyone who observes the transaction in the mempool) can rebuild the transaction with an arbitrary `operator_xonly_pk` in the `OP_RETURN` while keeping the signed input/output intact, and race to get their version confirmed. Whoever wins the race is the one credited by the protocol as "the operator that fronted the payout" and becomes entitled to reimbursement — independent of whether they were the operator who actually should have been credited.

### Finding Description
`create_payout_txhandler` builds the payout transaction with three outputs: the user payout output (index 0, signed), the anchor (index 1), and an `OP_RETURN` output holding `operator_xonly_pk` (index 2): [1](#0-0) 

The only signature applied is `set_p2tr_key_spend_witness(&user_sig, 0)`, i.e. a single key-spend signature over input 0 given off-chain by the withdrawing user to operators, described explicitly in the doc comments as using sighash `SinglePlusAnyoneCanPay`, verified via `parse_withdrawal_sig_params`: [2](#0-1) 

`SIGHASH_SINGLE | SIGHASH_ANYONECANPAY` commits only to the single input being spent and to the output at the same index as that input (output 0). It does **not** commit to any other output, meaning outputs 1 (anchor) and 2 (`OP_RETURN`, the operator attribution) can be freely rewritten by anyone holding the signature and the base transaction template without invalidating the witness.

The aggregator's `Withdraw` RPC forwards this same signed withdrawal request to a set of operators concurrently (all operators, or a caller-specified list): [3](#0-2) 

Each operator independently builds and broadcasts its own version of the payout tx via `withdraw()`, embedding its own `operator_xonly_pk` in the unsigned `OP_RETURN`: [4](#0-3) 

On the verifier side, the attribution of "who fronted this payout" — used to decide who is authorized to claim reimbursement — is derived purely by parsing the `OP_RETURN` of whichever payout transaction actually gets confirmed on-chain, with no cryptographic binding tying that pubkey to the signed part of the transaction: [5](#0-4) 

This attribution then drives `validate_payer_is_operator`, which gates the entire reimbursement transaction chain (kickoff/challenge-timeout/ready-to-reimburse/reimburse): [6](#0-5) 

and `is_kickoff_malicious`, which trusts the same DB-recorded `operator_xonly_pk` from the `OP_RETURN` to decide whether a kickoff is legitimate: [7](#0-6) 

Because none of these checks require the `OP_RETURN` pubkey to be cryptographically bound to the payer of the transaction, the equality the protocol implicitly assumes — "operator attributed in `OP_RETURN`" == "operator whose broadcast/funds actually confirmed the payout" — does not hold. Any actor capable of observing the signed withdrawal parameters (all operators that received the parallel `Withdraw` call, or anyone monitoring the mempool once one operator broadcasts) can substitute their own `operator_xonly_pk` into output 2 and try to win the race to get it mined, since the txid and witness validity are unaffected by that change.

### Impact Explanation
If a party other than the intended/honest fronting operator manages to get their `OP_RETURN`-rewritten version of the payout confirmed first, they will be recorded by all verifiers as the payer via `update_finalized_payouts`, and will subsequently be able to drive the kickoff/reimburse flow to claim the operator's collateral-backed reimbursement — while the operator that actually intended to front the withdrawal (or that legitimately should be credited) is permanently excluded, since `validate_payer_is_operator` will reject any deposit id whose recorded `payer_xonly_pk` doesn't match their own key. This matches the "operator reimbursed for a payout it never funded" / "honest operator permanently unable to be reimbursed" Critical-impact criteria.

### Likelihood Explanation
The precondition — multiple operators receiving the same signed withdrawal parameters simultaneously — is a normal part of the documented flow (`Withdraw` RPC fans out to all or a subset of operators), so no privileged access or compromise is required; only ordinary participation as an operator (an untrusted, permissionless role in this protocol) or passive mempool observation is needed to attempt the substitution and race.

### Recommendation
Bind the `OP_RETURN` operator attribution to the signed part of the payout transaction (e.g., commit to it via a sighash flag that covers all outputs such as `SIGHASH_ALL`, or otherwise structurally tie the attribution output to the input being spent) so that the credited operator cannot be altered independently of the signature that authorizes the spend.

### Proof of Concept
1. Aggregator receives a withdrawal request and calls `Withdraw` on operators A and B simultaneously (`core/src/rpc/aggregator.rs:1870-1885`).
2. Operator A calls `create_payout_txhandler` with `operator_xonly_pk = A`, builds tx `T_A` = {input: withdrawal UTXO, sig: user_sig; outputs: [payout, anchor, OP_RETURN(A)]}, and broadcasts it (`core/src/builder/transaction/operator_reimburse.rs:407-436`).
3. Operator B observes `T_A` in the mempool (or independently constructs its own version using the same off-chain-provided `user_sig` and `input_utxo`), and constructs `T_B` = {same input, same `user_sig` witness (still valid, since `SIGHASH_SINGLE|ANYONECANPAY` does not cover output 2); outputs: [same payout output, anchor, OP_RETURN(B)]}.
4. Operator B broadcasts `T_B` with a competitive fee and it confirms instead of `T_A`.
5. `update_finalized_payouts` on all verifiers parses the on-chain tx's `OP_RETURN` and records operator `B` as the payer (`core/src/verifier.rs:2311-2343`).
6. Operator B now passes `validate_payer_is_operator` and can proceed through kickoff/challenge-timeout/reimburse to claim reimbursement, while operator A — despite believing it fronted the payout — is permanently rejected by the same check.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// For a deposit_id checks that the payer for that deposit is the operator, and the payout blockhash and kickoff txid are set.
    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

        tracing::info!(
            "Payer xonly pk, payout blockhash and kickoff txid found and valid for own operator for the requested deposit id: {}, payer xonly pk: {:?}, payout blockhash: {:?}, kickoff txid: {:?}",
            deposit_id,
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid
        );

        Ok((payout_blockhash, kickoff_txid))
    }

    ) -> Result<bool, BridgeError> {

                .get_cached_tx()

            .db
            .get_payout_info_from_move_txid(Some(dbtx), move_txid)
            .await?;
        let Some((operator_xonly_pk_opt, payout_blockhash, _, _)) = payout_info else {

                "No payout info found in db for move txid {move_txid}, assuming malicious"

            return Ok(true);
        };

        let Some(operator_xonly_pk) = operator_xonly_pk_opt else {
            tracing::warn!("No operator xonly pk found in payout tx OP_RETURN, assuming malicious");
            return Ok(true);
        };

        if operator_xonly_pk != kickoff_data.operator_xonly_pk {
            tracing::warn!("Operator xonly pk for the payout does not match with the kickoff_data");
            return Ok(true);

            kickoff_data.kickoff_idx,
            self.config.protocol_paramset(),

            kickoff_witness,
            &[wt_derive_path],
            self.config.protocol_paramset(),
        )?;
        let blockhash_data = commits.first();
        // only last 20 bytes of the blockhash is committed
        let truncated_blockhash = &payout_blockhash[12..];
        if let Some(committed_blockhash) = blockhash_data {
            if committed_blockhash != truncated_blockhash {
                tracing::warn!("Payout blockhash does not match committed hash: committed: {:?}, truncated payout blockhash: {:?}",
                        blockhash_data, truncated_blockhash);
                return Ok(true);
            }
        } else {
            return Err(eyre::eyre!("Couldn't retrieve committed data from witness").into());
        }
        Ok(false)
    }
