### Title
`compute_v2_review_set` intersection logic drops dangerous committed content on sideways HEAD moves (checkout/reset to a non-descendant commit) - ([File: plugins/security-guidance/hooks/diffstate.py])

### Finding Description
`capture_git_baseline` (`plugins/security-guidance/hooks/diffstate.py:163-204`) is invoked at `UserPromptSubmit` from `handle_user_prompt_submit` in `security_reminder_hook.py:446-515`, storing `baseline_sha` (a `git stash create` snapshot of HEAD+dirty state) and `head_at_capture` (`_git_rev_parse_head`) into session state.

At `Stop`, `compute_v2_review_set` (`plugins/security-guidance/hooks/diffstate.py:353-438`) derives the review set as:

```
review_set = dirty_now & changed_since   (when changed_since is not None)
```

where:
- `dirty_now` = `tracked_dirty | new_untracked` from `git status --porcelain` against the *current* HEAD, plus (only if `head_at_capture` is an ancestor of the current HEAD — i.e., HEAD moved forward linearly via commit) the name-only diff of `head_at_capture..HEAD` [1](#0-0) .
- `changed_since` = name-only diff of the working tree against the pre-turn stash `baseline_sha` [2](#0-1) .

`_is_ancestor` uses `git merge-base --is-ancestor` and explicitly only returns true for a linear "forward" move via commit/merge, not a sideways move via checkout [3](#0-2) .

If, within a single Claude turn, the working tree is switched to a different commit/branch that is **not a descendant** of `head_at_capture` but already contains the dangerous code (e.g. `git checkout <other-branch>`, `git reset --hard <unrelated-sha>`, or a rebase/cherry-pick sequence that rewrites ancestry), then:
- `tracked_dirty` is empty (the working tree is clean relative to the *new* HEAD),
- the ancestor-linear bonus term is skipped (`_is_ancestor` returns False),
- so `dirty_now` is `{}` (assuming no untracked files),
- while `changed_since` (diff of working tree against the original `baseline_sha`) is non-empty and *does* contain the dangerous file.

Because `review_set = dirty_now & changed_since`, the intersection with an empty `dirty_now` yields `{}` — the dangerous file is silently dropped from review even though it is present in the final working tree and differs from the session's baseline. This is exactly the scenario the question describes: git operations (checkout/reset to a sideways commit) shift what counts as "current" without qualifying as a reviewable diff, breaking the invariant that "the review set must stay bound to the right repo, baseline, and touched paths."

### Impact Explanation
A dangerous change (e.g., a backdoor already committed on another branch, or reintroduced via `git reset --hard` to an unrelated commit) can end up in the working tree at Stop time and be completely excluded from the LLM security review, because `dirty_now` (git-status-relative-to-current-HEAD) is empty while `changed_since` (diff-relative-to-session-baseline) is non-empty, and the code intersects rather than unions these sets. This matches "wrong-target mutation" impact: the review set is bound to the wrong reference frame (current HEAD) instead of the session's actual baseline, letting a real code change silently bypass the Stop-hook's security review layer, even though the commit-review PostToolUse hook (a separate, `git commit`-triggered layer) may still catch pure `git commit` invocations — it does not fire on `checkout`/`reset` sequences that merely move HEAD to already-existing content.

### Likelihood Explanation
Requires only ordinary git commands (`checkout`, `reset --hard`, or history-rewriting operations) executed during a Claude Code turn — no privilege escalation, no leaked credentials, and no additional access beyond what Claude Code/the session already has via the Bash tool. The most realistic trigger is prompt-injected repository content (e.g., a malicious README/issue instructing the agent to "sync with branch X" or "reset to a known-good commit") causing Claude to run such a sideways git operation, after which the intersection logic silently empties the review set. This is a plausible, low-effort sequence, not a contrived edge case, and is reproducible deterministically.

### Recommendation
Do not intersect `dirty_now` and `changed_since` when they can diverge for reasons other than "already reviewed." Specifically:
1. Detect non-ancestor HEAD changes (sideways checkout/reset) explicitly and treat them as a full re-baseline event requiring review of the entire diff against `baseline_sha`, not an intersection with `dirty_now`.
2. At minimum, union `changed_since` into the review set whenever HEAD is not a linear descendant of `head_at_capture`, rather than silently defaulting to the empty `dirty_now` term.
3. Add an explicit test asserting that `compute_v2_review_set` returns a non-empty review set for a file that differs from `baseline_sha` after a sideways `git checkout`/`git reset --hard` to a commit not reachable as a descendant of `head_at_capture`.

### Proof of Concept
Unit/integration test plan (extends existing `compute_v2_review_set` test style):
1. Init a temp git repo, commit `safe.py` → `head_at_capture` = C0. Capture `baseline_sha` via `capture_git_baseline` (clean tree → returns C0).
2. Create a second branch `evil` from an unrelated root commit containing `danger.py` with the "dangerous" marker content, and commit it there (SHA `E`, not a descendant of C0).
3. In the working tree, run `git checkout evil` (or `git reset --hard E` after fetching it), simulating the attacker-controlled/injected git sequence.
4. Call `compute_v2_review_set(cwd, baseline_sha=C0, head_at_capture=C0)`.
5. Assert `_is_ancestor(repo, C0, E)` is False, `tracked_dirty` is empty, but the current expected/desired behavior (which currently fails) is that `danger.py` (present in the working tree and differing from `baseline_sha`) still appears in the returned `review_paths`.
6. Current implementation: assert reproduces the bug — `review_paths == []` even though `_git_name_only(repo, baseline_sha)` contains `danger.py`, demonstrating the review set silently drops a dangerous, present-in-tree file.

```python
def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
```
