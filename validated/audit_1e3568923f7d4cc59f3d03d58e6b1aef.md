### Title
Payout OP_RETURN Not Covered by `SinglePlusAnyoneCanPay` Signature Allows Mempool Attacker to Corrupt Operator Attribution and Block Reimbursement — (`core/src/verifier.rs`, `core/src/builder/transaction/operator_reimburse.rs`)

---

### Summary

The user's withdrawal signature is enforced to be `TapSighashType::SinglePlusAnyoneCanPay`, which commits only to input 0 (the withdrawal UTXO) and output 0 (the user payout output). The OP_RETURN output at output index 2 — which carries the operator's xonly public key — is **not covered** by this signature. An unprivileged attacker who observes the funded payout transaction in the mempool can extract the user's reusable `SinglePlusAnyoneCanPay` signature, construct a replacement V3 transaction with an arbitrary xonly pk in the OP_RETURN, and broadcast it with a higher fee. If the replacement confirms, `update_finalized_payouts` blindly stores the forged xonly pk, permanently breaking the operator's ability to claim reimbursement.

---

### Finding Description

**Step 1 — Signature enforcement confirms the attack surface.**

`parse_withdrawal_sig_params` enforces `SinglePlusAnyoneCanPay`: [1](#0-0) 

`SinglePlusAnyoneCanPay` commits to exactly one input (the signed input) and the output at the same index. For the payout transaction, that means input 0 and output 0 only.

**Step 2 — The payout transaction layout places the OP_RETURN outside the signed scope.**

`create_payout_txhandler` builds:
- Output 0: user payout (covered by signature)
- Output 1: anchor (not covered)
- Output 2: OP_RETURN with `operator_xonly_pk.serialize()` (not covered) [2](#0-1) 

After `fund_raw_transaction` adds wallet inputs and a change output, the OP_RETURN shifts further but remains uncovered. The `copy_witnesses` helper in the tx-sender explicitly identifies and reuses `SinglePlusAnyoneCanPay` signatures (65-byte witness, last byte `0x83`) across replacement transactions: [3](#0-2) 

**Step 3 — The payout transaction is V3 and replaceable.**

`NON_STANDARD_V3` is `Version(3)`: [4](#0-3) 

V3 (TRUC) transactions are always replaceable. The operator also explicitly sends the payout via `fund_raw_transaction` with `replaceable: None` (wallet default = RBF enabled).

**Step 4 — `update_finalized_payouts` blindly trusts the OP_RETURN.**

The verifier reads whatever xonly pk is in the OP_RETURN of the confirmed spending transaction and writes it to the DB with no validation against any known operator set: [5](#0-4) [6](#0-5) 

**Step 5 — `PayoutCheckerTask` uses the stored xonly pk to route reimbursement.**

The task queries for unhandled payouts where `payout_payer_operator_xonly_pk = self.operator.signer.xonly_public_key`: [7](#0-6) 

If the DB contains a forged xonly pk, the actual operator's `PayoutCheckerTask` finds nothing and never triggers a kickoff.

**Step 6 — `is_kickoff_malicious` uses the same corrupted DB field.**

If the actual operator manually sends a kickoff, the verifier compares the stored `operator_xonly_pk` (forged) against `kickoff_data.operator_xonly_pk` (real operator). They differ, so the kickoff is flagged malicious and challenged: [8](#0-7) 

The operator is in a lose-lose position: skip the kickoff and lose the fronted BTC, or send the kickoff and lose collateral to a challenge.

**Step 7 — `validate_payer_is_operator` also blocks manual recovery.**

`get_reimbursement_txs` calls `validate_payer_is_operator`, which checks `payer_xonly_pk != self.signer.xonly_public_key`. With the forged pk in the DB, this check fails for the real operator, blocking all automated and manual recovery paths: [9](#0-8) 

---

### Impact Explanation

An unprivileged attacker who monitors the Bitcoin mempool can permanently block an operator from recovering the BTC they fronted for a user withdrawal. The operator loses the full bridge amount they paid out. If the attacker places a specific operator's xonly pk in the forged OP_RETURN (all operator xonly pks are public), that operator's `PayoutCheckerTask` will attempt to handle the payout, potentially triggering a kickoff and reimbursement for an operator who did not front the withdrawal — a direct theft of the deposit UTXO.

---

### Likelihood Explanation

The attack requires only: (1) a Bitcoin node with mempool access, (2) a small amount of BTC to pay replacement fees, and (3) the ability to broadcast a V3 transaction. No privileged access, key material, or protocol participation is needed. The `SinglePlusAnyoneCanPay` signature is visible in the mempool witness and is explicitly designed to be reusable across transactions with different outputs.

---

### Recommendation

1. **Bind the OP_RETURN to the operator's signature.** Have the operator sign a commitment over `(withdrawal_utxo_outpoint || operator_xonly_pk)` and include that signature in the OP_RETURN, or use a sighash type that covers all outputs (`TapSighashType::All`) for the operator's own fee inputs.
2. **Validate the OP_RETURN against known operators.** In `update_finalized_payouts`, reject any `operator_xonly_pk` that does not appear in the set of registered operators for the deposit.
3. **Cross-check with the kickoff.** Derive the authoritative operator identity from the kickoff transaction's Winternitz commitment (which is operator-signed) rather than from the unauthenticated OP_RETURN.

let forged_op_return = op_return_txout(PushBytesBuf::from(operator_b_xonly_pk.serialize()));

    output: vec![user_payout_txout, attacker_change, forged_op_return],
    ..Default::default()

// 4. After confirmation, insert into BlockCache and call update_finalized_payouts
let block = Block { txdata: vec![replacement.clone()], .. };

verifier.update_finalized_payouts(&mut dbtx, block_id, &block_cache).await.unwrap();

// 5. Assert the DB now stores operator_b's xonly pk, not operator_a's
let stored_pk = db.get_payout_info_from_move_txid(None, move_txid).await.unwrap().unwrap().0;

    /// Given a PSBT with inputs, fill in the existing witnesses from the original tx
    /// This allows us to create a finalized PSBT if
    /// the original tx had SinglePlusAnyoneCanPay signatures.  If the original
    /// tx did not have S+AP, these signatures will be added. The expected behavior is for them to be replaced using RbfSigningInfo.
    ///
    /// # Returns
    /// The PSBT as a base64-encoded string.
    pub async fn copy_witnesses(&self, psbt: String, initial_tx: &Transaction) -> Result<String> {
        let mut decoded_psbt = Psbt::from_str(&psbt).map_err(|e| eyre!(e))?;

        for (idx, input) in initial_tx.input.iter().enumerate() {
            if let Some(sig) = input.witness.nth(0) {
                if sig.len() == 65 && sig[64] == 0x83 {
                    // This is a S+AP signature, copy it over
                    decoded_psbt.inputs[idx].final_script_witness = Some(input.witness.clone());
                }
            }
        }

        Ok(decoded_psbt.to_string())
    }
