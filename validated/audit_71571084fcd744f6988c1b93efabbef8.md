### Title
Unsynchronized read of `BidPool.auctionEntryPointVersion` races with concurrent `updateAuctionInfo` writes, causing EIP-712 typehash mismatch and bid corruption - (File: kaiax/auction/impl/bid_pool.go)

### Summary
`BidPool` protects `auctioneer`, `auctionEntryPoint`, `auctionEntryPointVersion`, and `bidTxGasBuffer` with `auctionInfoMu` [1](#0-0) , and all other accessors (`GetAuctionEntryPoint`, `GetAuctionEntryPointVersion`, `validateBidSigs`) correctly take the lock before reading these fields [2](#0-1) [3](#0-2) . However, `getBidTxGasLimit`, which is invoked synchronously on every `AddBid` call, reads `bp.auctionEntryPointVersion` directly on line 490 outside the `auctionInfoMu` critical section — only `bidTxGasBuffer` is read under lock [4](#0-3) .

### Finding Description
`AddBid` is reachable by any unprivileged transaction/bid sender through the auction bid submission path, and internally calls `validateBid` → `insertBid` → `getBidTxGasLimit` [5](#0-4) . At the same time, `PostInsertBlock`, invoked from the block-processing pipeline on every new block, calls `updateAuctionInfo`, which writes `auctioneer`, `auctionEntryPoint`, `auctionEntryPointVersion`, and `bidTxGasBuffer` under `auctionInfoMu.Lock()` whenever the on-chain auctioneer/version changes [6](#0-5) [7](#0-6) .

Because `getBidTxGasLimit` reads `bp.auctionEntryPointVersion` without holding `auctionInfoMu` while `updateAuctionInfo` can concurrently mutate that same field from a different goroutine (block-import goroutine vs. bid-processing goroutine `handleBidMsg`/API caller), this is a textbook unsynchronized concurrent read/write on shared mutable state — the same bug class as the gfwx advisory (missing synchronization bound allowing a value to be observed/mutated across concurrent execution contexts, CWE-662). In Go this manifests as: (a) a data-race-detected read of a string header that can be torn (mismatched pointer/length) under the Go memory model, and (b) more practically, `EncodeAuctionCallData(bid, bp.auctionEntryPointVersion)` on line 490 potentially uses a stale or a different version string than the one under which `bid.ValidateSearcherSig`/`ValidateAuctioneerSig` were verified moments earlier in `validateBidSigs` (which does hold the lock) [8](#0-7) . If the on-chain `AUCTION_VERSION` changes between the signature-verification step and the gas-limit/calldata-encoding step for the same in-flight bid, the resulting call data encoded with the wrong ABI/typehash can diverge from what was signature-validated, producing either acceptance of a bid whose calldata does not match what was cryptographically authorized, or a gas-limit computed against a version that no longer matches the entry point actually invoked at inclusion time.

### Impact Explanation
This directly touches the auction/gasless settlement path reachable from a single submitted bid. A mismatch between the version used for signature verification and the version used to build/estimate the bid transaction's call data can lead to acceptance of bids whose encoded calldata is inconsistent with the entry point's expected ABI at execution time (state divergence / incorrect gas accounting for auction settlement), which the scope explicitly calls out as in-scope impact (gasless/auction settlement issues). Severity is bounded by the fact that `auctionEntryPointVersion` changes only when governance/system-contract config changes (relatively rare), and the race window is narrow (single field read between two nearby lock-protected sections).

### Likelihood Explanation
Requires the on-chain `AUCTION_VERSION`/auctioneer/entry-point to actually change (via `updateAuctionInfo`) in the same short window that a bid is being processed by `AddBid`/`getBidTxGasLimit` — i.e., a version rotation occurring concurrently with in-flight bid processing on `handleBidMsg` or the API bid-submission goroutine. This is a genuine, always-possible race under Go's concurrency model whenever version rotation happens, but the trigger (mid-processing config change) is infrequent, so likelihood is moderate rather than high.

### Recommendation
In `getBidTxGasLimit`, read `bp.auctionEntryPointVersion` under `auctionInfoMu.RLock()` together with `bidTxGasBuffer` (a single lock acquisition capturing a consistent snapshot of all auction-info fields), instead of reading `buffer` under lock and `auctionEntryPointVersion` unprotected. More broadly, snapshot all auction-info fields (`auctioneer`, `auctionEntryPoint`, `auctionEntryPointVersion`, `bidTxGasBuffer`) once per `AddBid` invocation under a single `auctionInfoMu.RLock()`, and pass that snapshot through `validateBidSigs` and `getBidTxGasLimit` so the same version is used consistently for signature verification and calldata/gas computation.

### Proof of Concept
1. Node processes a bid submitted via `AddBid`, currently mid-way past `validateBidSigs` (which read `auctionEntryPointVersion = "v1"` under lock) and about to call `getBidTxGasLimit`.
2. Concurrently, a new block is imported and `PostInsertBlock` → `updateAuctionInfo` detects the auction entry point's `AUCTION_VERSION` changed to `"v2"` and calls `bp.updateAuctionInfo(..., "v2", ...)`, updating `bp.auctionEntryPointVersion` under `auctionInfoMu.Lock()` [9](#0-8) .
3. `getBidTxGasLimit` then reads `bp.auctionEntryPointVersion` unprotected on line 490, observing `"v2"`, and calls `system.EncodeAuctionCallData(bid, "v2")` — even though the bid's signature was validated against `"v1"`'s typehash/ABI in step 1.
4. The resulting bid transaction's calldata/gas limit is now built against a different ABI version than the one whose EIP-712 typehash was cryptographically verified, producing an inconsistency between the authorized bid and the encoded transaction that gets queued for settlement [4](#0-3) .

func (bp *BidPool) updateAuctionInfo(auctioneer common.Address, auctionEntryPoint common.Address, auctionEntryPointVersion string, bidTxGasBuffer uint64) {
	bp.auctionInfoMu.Lock()
	defer bp.auctionInfoMu.Unlock()

	if bp.auctioneer == auctioneer && bp.auctionEntryPoint == auctionEntryPoint && bp.auctionEntryPointVersion == auctionEntryPointVersion && bp.bidTxGasBuffer == bidTxGasBuffer {
		return
	}

	// Clear the existing auction pool since the auctioneer or auction entry point address is changed.
	bp.clearBidPool()

	bp.auctioneer = auctioneer
	bp.auctionEntryPoint = auctionEntryPoint
	bp.auctionEntryPointVersion = auctionEntryPointVersion
	bp.bidTxGasBuffer = bidTxGasBuffer

	logger.Info("Update auction info", "auctioneer", auctioneer, "auctionEntryPoint", auctionEntryPoint, "auctionEntryPointVersion", auctionEntryPointVersion, "bidTxGasBuffer", bidTxGasBuffer)
}

func (bp *BidPool) AddBid(bid *auction.Bid) (common.Hash, error) {
	if atomic.LoadUint32(&bp.running) == 0 {
		return common.Hash{}, auction.ErrAuctionPaused
	}

	if err := bp.validateBid(bid); err != nil {
		return common.Hash{}, err
	}

	if err := bp.insertBid(bid); err != nil {
		return common.Hash{}, err
	}

	gasLimit, err := bp.getBidTxGasLimit(bid)
	if err != nil {
		return common.Hash{}, err
	}
	bid.SetGasLimit(gasLimit)

	bp.newBidCh <- bid

	return bid.Hash(), nil
}

func (a *AuctionModule) PostInsertBlock(block *types.Block) error {
	if a.Downloader.Synchronising() || !a.ChainConfig.IsRandaoForkEnabled(block.Number()) {
		atomic.CompareAndSwapUint32(&a.bidPool.running, 1, 0)
		return nil
	}

	if !a.updateAuctionInfo(block.Number()) {
		logger.Debug("stop auction since auctioneer or auction entry point is not set")
		atomic.CompareAndSwapUint32(&a.bidPool.running, 1, 0)
		return nil
	}

	atomic.CompareAndSwapUint32(&a.bidPool.running, 0, 1)

	txHashMap := make(map[common.Hash]struct{})
	for _, tx := range block.Transactions() {
		txHashMap[tx.Hash()] = struct{}{}
	}
	a.bidPool.removeOldBids(block.Number().Uint64(), txHashMap)

	return nil
}

// updateAuctionInfo updates the auctioneer address and auction entry point address for the given block number.
// It expects the `num` is after Randao fork.
// It returns true if the non-zero auctioneer address and auction entry point address are set, otherwise false.
func (a *AuctionModule) updateAuctionInfo(num *big.Int) bool {
	auctioneer := common.Address{}
	auctionEntryPointAddr := common.Address{}
	auctionEntryPointVersion := ""
	bidTxGasBuffer := uint64(0)

	defer func() {
		a.bidPool.updateAuctionInfo(auctioneer, auctionEntryPointAddr, auctionEntryPointVersion, bidTxGasBuffer)
	}()

	header := a.Chain.GetHeaderByNumber(num.Uint64())
	if header == nil {
		return false
	}
	_, err := a.Chain.StateAt(header.Root)
	if err != nil {
		return false
	}

	backend := backends.NewBlockchainContractBackend(a.Chain, nil, nil)

	// 1. Read auction entry point address
	auctionEntryPointAddr, err = system.ReadActiveAddressFromRegistry(backend, system.AuctionEntryPointName, num)
	if err != nil {
		return false
	}

	if auctionEntryPointAddr == (common.Address{}) {
		return false
	}

	// 2. Read auctioneer address
	auctioneer, err = system.ReadAuctioneer(backend, auctionEntryPointAddr, num)
	if err != nil {
		return false
	}

	if auctioneer == (common.Address{}) {
		return false
	}

	// 3. Read gas buffer estimate
	bidTxGasBuffer, err = system.ReadGasBufferEstimate(backend, auctionEntryPointAddr, num)
	if err != nil {
		return false
	}

	// 4. Read AUCTION_VERSION to pick the right EIP-712 typehash and ABI for bids targeting this entry point.
	auctionEntryPointVersion, err = system.ReadAuctionVersion(backend, auctionEntryPointAddr, num)
	if err != nil {
		return false
	}

	return true
