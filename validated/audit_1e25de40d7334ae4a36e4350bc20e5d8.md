### Title
Forged `RedeemEscrow`/`RefundEscrow` requests can drain any pending order's escrow via the `instance()` default-trust fallback - (File: `evm/tron/contracts/apps/IntentGatewayV2.sol`, mirrored in `evm/src/apps/IntentGatewayV2.sol` / `IntentsBase.sol`)

### Summary
`IntentGatewayV2.instance()` silently falls back to `address(this)` whenever a state machine has not yet been explicitly registered through the governance-driven `NewDeployment` flow. `authenticate()` uses this same fallback to decide whether an incoming cross-chain request is coming from a "known" gateway instance. Because Hyperbridge intent-gateway contracts are meant to be deployed deterministically at the same address on every chain, this fallback effectively means "trust `address(this)` on any yet-unregistered chain." An attacker who deploys a look-alike contract at that identical address on *any other* Hyperbridge-connected state machine (a permissionless, unprivileged action - no relayer/prover/admin compromise needed) can dispatch a real, correctly-proven `PostRequest` whose `from` field equals `address(this)`. `authenticate()` will accept it, letting the attacker invoke `withdraw()` with an arbitrary `beneficiary` for any commitment that still has non-zero escrow - i.e., steal a legitimate user's escrowed order funds before the real solver/fill flow completes.

### Finding Description
`instance()` returns the registered gateway for a state machine, or `address(this)` if nothing is registered yet: [1](#0-0) 

`authenticate()` is the sole gate protecting `RedeemEscrow`/`RefundEscrow` execution and simply compares the request's declared `from` module address against `instance(request.source)`: [2](#0-1) 

`onAccept()` routes `RedeemEscrow`/`RefundEscrow` kinds straight through `authenticate()` into `withdraw()`, with the beneficiary and token amounts fully attacker-controlled inside the decoded `WithdrawalRequest` body: [3](#0-2) 

`withdraw()` only checks that the referenced commitment has non-zero escrow for the given tokens - it does not verify that the request actually originated from a legitimate solver fill or a legitimate order cancellation flow, only that `authenticate()` passed: [4](#0-3) 

Real registrations of `_instances[keccak256(stateMachineId)]` only happen when Hyperbridge itself dispatches a `NewDeployment` request (gated to `IDispatcher(host()).hyperbridge()` as the source): [5](#0-4) 

The attack path:
1. Order commitments are public (emitted in `OrderPlaced`, and `_orders[commitment][token]` is publicly readable), so any pending order's commitment and escrowed token amounts can be read off-chain. [6](#0-5) 
2. An attacker deploys a minimal contract at the same address as the legitimate `IntentGatewayV2` (achievable via the same deterministic deployment factory/salt Hyperbridge uses for its cross-chain gateway deployments) on some other Hyperbridge-connected state machine that has never gone through `NewDeployment` registration for the target chain.
3. From that attacker-controlled chain, the attacker dispatches a genuine ISMP `PostRequest` (correctly proven by consensus + state proof - no relayer/prover collusion required) with `from = address(this)` (the shared deterministic address) and a body encoding `RequestKind.RedeemEscrow` with `WithdrawalRequest{ commitment: <victim's known commitment>, tokens: <victim's escrowed tokens>, beneficiary: attacker }`.
4. On the target chain, `authenticate()` calls `instance(request.source)`, which — since that source chain was never registered — returns `address(this)`, matching `request.from`. The check passes.
5. `withdraw()` transfers the victim's escrowed input tokens to the attacker's `beneficiary` and marks `_filled[commitment] = attacker`, permanently blocking the legitimate solver from ever completing the fill/redeem for that order.

This is structurally the same bug class as the external report: a mapping (`_instances`) meant to authorize/scope operations per key (per-`optionIndex` token vs. per-`stateMachineId` gateway) has an implicit "default/unset" value that silently resolves to a value that should only be trusted when *explicitly* set, letting an unrelated actor's action collide with and override the intended authorization, causing the rightful party (order placer/solver) to lose funds.

### Impact Explanation
This directly matches the bounty's "stealing or loss of funds" and "unauthorized transaction or execution" categories: an unprivileged, permissionless attacker can drain escrowed order funds to an arbitrary beneficiary without needing a malicious relayer, prover, or admin — they only need to deploy a contract on any Hyperbridge-connected chain that hasn't yet been registered as a known `IntentGatewayV2` instance and dispatch a normal, correctly-verified cross-chain message. Given Hyperbridge continually onboards new state machines, there is very likely a window (or a permanently-unregistered but still ISMP-routable chain) where this default-trust gap is exploitable against live escrowed orders on already-deployed, registered chains.

### Likelihood Explanation
Likelihood is high for any newly-onboarded or intentionally-unregistered chain: the attacker needs no special privileges, only the ability to deploy a contract (permissionless) at the shared deterministic gateway address on some chain Hyperbridge already relays consensus/state proofs for, and to call a dispatch function from it. No governance, relayer, or prover compromise is required, and the proof presented to the destination `HandlerV2`/`EvmHost` is entirely legitimate for the attacker's own (real) chain.

### Recommendation
Change `instance()`/`authenticate()` semantics so that an unregistered state machine is treated as **untrusted by default**, not as `address(this)`. Require an explicit, non-zero `_instances[keccak256(stateMachineId)]` entry before accepting any `RedeemEscrow`/`RefundEscrow`/other privileged incoming request from that source chain, and revert (e.g. with `UnknownInstance`) when no entry exists — mirroring the guard already documented for the `instance(bytes)` external view (`Reverts with UnknownInstance if no remote deployment is registered`) but not actually enforced in the internal `authenticate()` path.

### Proof of Concept
1. Victim calls `placeOrder(...)` on Chain A (registered `IntentGatewayV2`), escrowing tokens under `commitment = keccak256(abi.encode(order))`; this commitment/amount is publicly visible via `OrderPlaced` and `_orders(commitment, token)`. [6](#0-5) 
2. Attacker identifies Chain X, a state machine Hyperbridge has consensus/state verification for but for which Chain A's `_instances[keccak256(stateMachineId_X)]` has never been set via `NewDeployment`.
3. Attacker deploys, on Chain X, a contract at the exact same address as Chain A's `IntentGatewayV2` (using the same CREATE2 factory/salt convention Polytope Labs uses for cross-chain gateway parity), and from it dispatches a `PostRequest` to Chain A with `body = RequestKind.RedeemEscrow || abi.encode(WithdrawalRequest{commitment, tokens: victim's inputs, beneficiary: attacker})`.
4. Relayer submits the (real, valid) consensus + state proof to Chain A's host; `onAccept()` is invoked, `authenticate()` compares `request.from` (attacker's contract address on Chain X) against `instance(request.source)` which resolves to `address(this)` because Chain X is unregistered — match succeeds. [3](#0-2) 
5. `withdraw()` executes, transferring the victim's escrowed tokens to the attacker's beneficiary and setting `_filled[commitment] = attacker`, permanently preventing the legitimate solver from redeeming. [4](#0-3)

    function instance(bytes calldata stateMachineId) public view returns (address) {
        address gateway = _instances[keccak256(stateMachineId)];
        return gateway == address(0) ? address(this) : gateway;
    }

    /**
     * @dev Checks that the request originates from a known instance of the IntentGateway.
     */
    function authenticate(PostRequest calldata request) internal view {
        if (request.from.length != 20) revert InvalidInput();
        address module = address(bytes20(request.from));
        // IntentGateway only accepts incoming assets from itself or known instances
        if (instance(request.source) != module) revert Unauthorized();
    }
