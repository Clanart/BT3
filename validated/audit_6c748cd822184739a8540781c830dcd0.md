Based on my investigation, I found a solid structural analog in `pallet-consensus-incentives`. Note: I was not able to fully trace the exact call site that constructs the `messages`/`events` batch passed into `on_executed` (ran out of tool iterations before reading `modules/pallets/ismp/src/fee_handler.rs` and `lib.rs` in full), so the precise batching semantics (whether a single extrinsic can bundle `ConsensusMessage`s signed by different relayers together with resulting `StateMachineUpdated` events from other message types) should be verified by whoever picks this up. The defect I can prove from the code I did read is the mismatch between "who is identified as the relayer" (first message only) and "what is paid out" (all events in the batch).

### Title
Consensus-incentive reward misattribution: entire batch's `StateMachineUpdated` rewards paid to the relayer of only the first message - (File: modules/pallets/consensus-incentives/src/impls.rs)

### Summary
`pallet-consensus-incentives::on_executed` identifies the reward recipient by recovering a signature from **only the first message** in the batch (`messages.get(0)`), but then pays out rewards for **every** `StateMachineUpdated` event contained in the **entire batch's `events` list**, regardless of which message actually produced each event or who actually signed/delivered it.

### Finding Description
`process_message`/`on_executed` in [1](#0-0)  extracts a single `relayer_account` by decoding the signature embedded in `messages[0]` only: [2](#0-1) 

It then collapses **all** `StateMachineUpdated` events in the batch's `events` vector (across potentially many different state machines, produced by potentially many different messages) into a per-state-machine highest-height map, and pays a reward for each entry to that single `relayer_account`: [3](#0-2) 

The reward calculation itself reads a **shared, chain-level** quantity — `latest_commitment_height`/`previous_commitment_height`/`LastRewardedHeight` for the *state machine*, not anything scoped to the specific relayer or specific message that produced the update: [4](#0-3) 

This is structurally the same defect class as TRST-H-7: instead of reading the value scoped to the specific actor/position responsible for the state change (the position-specific `liquidity`/`tokensOwed` in the Uniswap report, here the specific message/relayer that produced a given `StateMachineUpdated` event), the code reads/aggregates a value spanning **all** contributors in scope (the whole state-machine's height progress across the whole batch) and credits it to a single, arbitrarily-chosen party (whoever happens to be `messages[0]`).

The existing in-code comment confirms multiple `StateMachineUpdated` events for multiple state machines can appear in a single `on_executed` call and that the pallet already had to patch a related double-payment bug for repeated updates to the *same* chain — showing the surrounding batching model is exactly the shape needed for this misattribution to occur.

### Impact Explanation
If a batch/call to `on_executed` can contain messages/events attributable to more than one relayer (e.g., several consensus proofs for different state machines processed in the same runtime call, or events generated as a side effect of processing subsequent messages in the batch), every reward in that call is paid to whoever's message sits at index 0, rather than the relayer who actually delivered each particular consensus update. This causes:
- Loss of rewards to the relayer(s) who genuinely delivered updates for state machines other than the one tied to `messages[0]`.
- Unearned reward (and matching `ReputationAsset` mint) to the party occupying slot 0, i.e., wrong-beneficiary fund transfer from `TreasuryAccount`.

This matches the required impact class: incorrect/unauthorized transfer of treasury funds to the wrong beneficiary due to a logic flaw in reward attribution.

### Likelihood Explanation
The pallet processes external, permissionless, unsigned ISMP message batches (as documented elsewhere in the repo, e.g. relayer withdrawal/consensus submission extrinsics are unsigned). Any relayer able to influence message ordering within a batch, or any batch that legitimately mixes messages from multiple sources, triggers the misattribution automatically — no privileged actor, malicious peer, or admin action is required, only normal submission of a multi-message batch.

### Recommendation
Bind reward payout strictly to the message/event that produced it: track the signer/relayer per individual `ConsensusMessage` and only pay the reward for `StateMachineUpdated` events that are directly attributable to that specific message's proof (e.g., pair each `Message::Consensus` with the `StateMachineUpdated` events it generates instead of pooling `events` for the whole batch under a single `messages[0]`-derived signer).

### Proof of Concept
Conceptual (exact batch-construction entry point not fully verified due to time constraints — needs confirmation against `modules/pallets/ismp/src/fee_handler.rs`/`lib.rs`):
1. Attacker submits (or is naturally included in) a batch where `messages[0]` is their own signed `Message::Consensus`.
2. The batch/processing pipeline also yields `StateMachineUpdated` events for other state machines that were actually advanced by other relayers' proofs earlier in the same call.
3. `on_executed` recovers only the attacker's pubkey from `messages[0]`, then iterates the full `events` list and pays the attacker the reward for every state machine's height advance in the batch, not just their own.
4. The legitimate relayers who advanced the other chains receive nothing for that batch; the attacker collects `TreasuryAccount` funds and `ReputationAsset` mints they did not earn. [5](#0-4)

	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}

		// Return with actual weight information
		// We use Pays::No to indicate that someone (the message sender) doesn't pay for this
		// operation, though we're using this mechanism to reward relayers rather than charge fees
		Ok(PostDispatchInfo { actual_weight: None, pays_fee: Pays::No })
	}
