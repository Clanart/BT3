### Title
DataLayer mirror URLs are fetched by `http_download()` without any destination validation, allowing SSRF against subscribing nodes - (File: `chia/data_layer/download_data.py`)

### Summary
Chia's DataLayer subscribes to arbitrary HTTP "mirror" URLs registered on-chain by any DataLayer store owner via `add_mirror()`. Any node that subscribes to that store id will have its DataLayer service periodically issue outbound HTTP GET requests to those attacker-chosen URLs with no scheme/host allow-listing, mirroring the CRMEB `get_image_base64` SSRF pattern of taking an attacker-controlled URL and fetching it server-side.

### Finding Description
`DataLayer.add_mirror()` lets any wallet owning a DataLayer singleton register a list of arbitrary `urls` on-chain, with the only client-side check being that the list is non-empty: [1](#0-0) 

These mirror URLs are pulled from the wallet and written directly into the local `subscriptions` table as fetch targets, with no validation of scheme or host: [2](#0-1) [3](#0-2) 

Any node that subscribes to that store id (e.g. via `dl_track_new`/subscription RPC or by owning the store) periodically runs `fetch_and_validate()`, which selects one of these registered server URLs and issues an outbound request through `insert_from_delta_file()` → `download_file()` → `http_download()`: [4](#0-3) [5](#0-4) 

`http_download()` performs a raw `aiohttp` GET against `server_info.url + "/" + filename` with no restriction on the URL's host/IP (no blocking of loopback, link-local/metadata addresses, or private ranges): [6](#0-5) 

Because the URL is entirely attacker-supplied (via an on-chain mirror coin anyone can create for a store they control) and the fetch happens server-side from the victim's DataLayer process, this is a textbook SSRF: a remote value controls the destination of a server-initiated network request, exactly analogous to CRMEB's `get_image_base64` taking a URL parameter and fetching it without validation.

### Impact Explanation
An attacker who creates or controls a DataLayer store (trivial and unprivileged - just requires normal wallet operations) can register mirror URLs pointing at internal-only services reachable from the victim's DataLayer host: localhost RPC ports, cloud metadata endpoints (e.g., `169.254.169.254`), or other internal network hosts. Any victim node that subscribes to that store (a normal DataLayer workflow for replicating/verifying third-party data) will have its DataLayer service issue outbound requests to that target on a recurring schedule (`periodically_manage_data()` / `fetch_and_validate()`), effectively turning the victim node into a network proxy for internal reconnaissance or crafted requests to sensitive local services. This does not directly move coins or forge assets, but it is a genuine server-side request forgery reachable by an unprivileged Data Layer store owner/mirror publisher against any subscribing node.

### Likelihood Explanation
Likelihood is moderate: exploitation requires that a victim voluntarily subscribes to (or auto-subscribes/mirrors) a store controlled by the attacker, which is a normal part of DataLayer's mirror-discovery design (arbitrary mirror URLs are explicitly treated as "external trust inputs" per the module's own documentation, but only the downloaded *content* is described as being validated - the destination URL itself is never validated). No authentication or privileged access is required to publish a malicious mirror; only the ability to create a DataLayer singleton and pay the mirror coin fee.

### Recommendation
Validate and restrict mirror/server URLs before they are stored as fetch targets and again immediately before `http_download()`/`get_downloader()` dial them: enforce an allow-listed scheme (e.g., `https` only), resolve and reject requests to loopback, link-local, and private/internal IP ranges (SSRF-safe URL/IP validation), and make this policy configurable per deployment (e.g., disallow private ranges by default, with an explicit opt-in for local test networks). Apply the same validation to plugin/downloader/uploader URLs (`get_downloader()`, `get_uploaders()`, `get_plugin_info()`) which have the same unrestricted-fetch pattern.

### Proof of Concept
1. Attacker creates a DataLayer store and calls `add_mirror(store_id, urls=["http://169.254.169.254/latest/meta-data/"], amount, fee)`, which is accepted with no URL validation (`chia/data_layer/data_layer.py:965-970`).
2. Victim node subscribes to the attacker's store id (normal DataLayer usage) and periodically runs `update_subscription()` → `fetch_and_validate()`.
3. `fetch_and_validate()` selects the malicious server URL and calls `insert_from_delta_file()` → `download_file()` → `http_download()` (`chia/data_layer/data_layer.py:642-694`, `chia/data_layer/download_data.py:110-145,298-319`).
4. The victim's DataLayer process issues an outbound GET to `http://169.254.169.254/latest/meta-data/<delta-filename>` (or any other internal host/port supplied by the attacker) - a request the attacker could not otherwise trigger, confirming SSRF via unvalidated mirror URLs.

```python
                {
                    "tree_id": store_id,
                },
            )
            from_subscriptions_urls = {row["url"] async for row in cursor}
            additions = {url for url in new_urls if url not in old_urls}
            removals = [url for url in old_urls if url not in new_urls]

                    "DELETE FROM subscriptions WHERE url == :url AND tree_id == :tree_id",
                    {
                        "url": url,
                        "tree_id": store_id,

                if url not in from_subscriptions_urls:
                    await writer.execute(
```

```python
async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
```
