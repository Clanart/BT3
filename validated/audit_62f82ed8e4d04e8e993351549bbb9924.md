### Title
Gasless swap price validation relies on manipulable spot AMM price (no TWAP/oracle) - ([File: kaiax/gasless/impl/tx_pool.go])

### Summary
The `kaiax/gasless` module (KIP-247) validates and executes gasless swap transactions by reading the *instantaneous* reserve-based exchange rate from a Uniswap V2-style DEX (`GaslessSwapRouter.GetAmountIn`), the same primitive flagged as manipulable in the external report (`uniswapV2Router.getAmountsIn()`). No TWAP or external oracle is used, so the price used both for tx-pool admission (`checkBalanceForSwap`) and for on-chain settlement (`SwapForGas`) can be moved within the same block/bundle that the gasless sender fully controls.

### Finding Description
`GaslessModule.checkBalanceForSwap` enforces `tx.amountIn >= gsr.getAmountIn(minAmountOut)` by calling the on-chain view function `GaslessSwapRouter.GetAmountIn(token, minAmountOut)`: [1](#0-0) 

`GaslessSwapRouter.GetAmountIn` is a thin wrapper that queries the underlying DEX (`GetDEXInfo` returns `factory`/`router`) and computes the amount using the pair's current reserves, exactly like `UniswapV2Router.getAmountsIn`/`getAmountOut`: [2](#0-1) [3](#0-2) 

The block-building rules for gasless transactions bundle `[LendTxGenerator, GaslessApproveTx, GaslessSwapTx]` (or `[LendTxGenerator, GaslessSwapTx]`) atomically into a single bundle that executes together in one block, entirely controlled by the sender: [4](#0-3) 

Because the sender fully controls the ordering/composition of transactions that land in the same block as their `GaslessSwapTx` (subject only to the bundling constraints of the gasless module), they can execute an auxiliary swap on the same DEX pair to skew the pool reserves immediately before their `SwapForGas` call, moving the spot price that both the admission check (`GetAmountIn`) and the settlement call use. The test harness confirms the pool price (`GetAmountsOut`) is queried directly against live reserves with no TWAP/staleness protection when computing the expected swap outcome: [5](#0-4) 

This mirrors the reported bug class exactly: a `getAmountsIn`/`getAmountOut`-based check against a manipulable AMM spot price, with the manipulator controlling transaction ordering in the same block (here, via gasless bundling rather than a generic flashloan), rather than relying on TWAP or a Chainlink-style oracle.

### Impact Explanation
An attacker submitting a gasless transaction can transiently distort the DEX pool used by `GaslessSwapRouter` to make `GetAmountIn`/`GetAmountsOut` report a favorable exchange rate at the moment the gasless swap is validated and settled, then reverse the distortion within the same block. This lets the sender satisfy the protocol's `AmountIn`/`minAmountOut`/`amountRepay` invariants using a much smaller real economic value of `token` than the fair market rate would require, effectively getting their gas subsidized (paid by the block proposer via `LendTxGenerator`) more cheaply than intended, while extracting value from the underlying DEX liquidity pool. This is a fee-delegation / gasless-settlement value-transfer bug directly tied to price-oracle manipulation, matching the "Medium/High" severity bar for gasless settlement abuse.

### Likelihood Explanation
Likelihood is High for any low-liquidity `paymentToken`/DEX pair allowed by the gasless configuration, since the attacker (the gasless tx sender) already has guaranteed atomic block placement of their bundle and does not need external actors or validators to cooperate — only a sufficiently large trade (their own funds or borrowed) against the specific pair used by `GaslessSwapRouter`.

### Recommendation
Do not rely on instantaneous AMM reserve queries (`getAmountIn`/`getAmountOut`/`getAmountsOut`) from `GaslessSwapRouter` for either the tx-pool admission check (`checkBalanceForSwap`) or final settlement (`swapForGas`). Use a TWAP window across multiple blocks or a decentralized/centralized price oracle (e.g., Chainlink) to derive `minAmountOut`/`amountRepay` bounds, and/or restrict allowed `paymentToken`/DEX pairs to those with oracle-backed pricing and sufficient liquidity depth so that a single-block manipulation cannot materially move the settlement price.

### Proof of Concept
1. Governance/registry configures `GaslessSwapRouter` to use a low-liquidity Uniswap V2 pair (`token`/`WKAIA`) as in `deployGaslessSwapRouter`/`setupLiquidity` (see `tests/gasless_test.go`).
2. Attacker crafts a bundle: `[large sell of token into the pair to skew reserves] -> [GaslessApproveTx] -> [GaslessSwapTx with amountIn set just above the manipulated GetAmountIn(minAmountOut)] -> [reverse trade to restore reserves]`.
3. `checkBalanceForSwap` (`kaiax/gasless/impl/tx_pool.go:128-141`) reads the manipulated `GetAmountIn` and accepts an `amountIn` far lower than the pre-manipulation fair price would require.
4. `SwapForGas` executes against the same manipulated reserves, satisfying `minAmountOut >= amountRepay`, repaying the proposer's lent gas while the attacker's true cost (in `token`) is minimized and the manipulated liquidity pool absorbs the loss. [6](#0-5) [5](#0-4)

	token := swapArgs.Token

// Solidity: function getDEXInfo(address token) view returns(address factory, address router)
func (_GaslessSwapRouter *GaslessSwapRouterCaller) GetDEXInfo(opts *bind.CallOpts, token common.Address) (struct {
	Factory common.Address
	Router  common.Address
}, error) {
	var out []interface{}
	err := _GaslessSwapRouter.contract.Call(opts, &out, "getDEXInfo", token)

	outstruct := new(struct {
		Factory common.Address
		Router  common.Address
	})
	if err != nil {
		return *outstruct, err
	}

	outstruct.Factory = *abi.ConvertType(out[0], new(common.Address)).(*common.Address)
	outstruct.Router = *abi.ConvertType(out[1], new(common.Address)).(*common.Address)

	return *outstruct, err

}

### Block building rules

Upon detection of GaslessTxs, the following logics are executed:

- Per sender, if exists, GaslessApproveTx is relocated before GaslessSwapTx.
- LendTxGenerator is prepended before GaslessApproveTx.
- A new bundle is generated which contain either `[LendTxGenerator, GaslessApproveTx, GaslessSwapTx]` or `[LendTxGenerator, GaslessSwapTx]`
- If the bundle has conflict with any previous bundles, it is excluded from the returned bundle list.
