### Title
Duplicate Schnorr signatures can be counted multiple times in an aggregate - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregator::aggregate` accepts and counts the same `(challenge, SchnorrSignature)` repeatedly because it has no uniqueness or already-aggregated check. [1](#0-0)  An attacker with one valid signature can create an aggregate containing multiple copies of its nonce and a scalar formed from independently weighted copies. [2](#0-1)  `SchnorrAggregate::verify` accepts the result whenever the caller supplies the same key/challenge pair the same number of times. [3](#0-2) 

### Finding Description
The aggregator unconditionally appends each supplied challenge and pushes each supplied signature into `sigs`, without tracking whether either value was already submitted. [1](#0-0)  During completion, every copy receives a different aggregation weight, so duplicating a signature changes `s` to `s * (w1 + w2 + ...)` rather than merely repeating identical terms. [2](#0-1) 

Verification mirrors this behavior by deriving one weight per supplied `(key, challenge)` entry and requiring only that `Rs.len()` equals the number of entries. [4](#0-3)  It does not reject duplicate public keys, challenges, key/challenge pairs, or nonce commitments before checking the aggregate equation. [5](#0-4)  `SchnorrAggregate::read` also accepts an attacker-supplied list of nonce points and scalar without uniqueness validation. [6](#0-5) 

### Impact Explanation
A consumer that treats each aggregate entry as a distinct signature, authorization, or vote can be presented with a cryptographically valid aggregate produced from only one actual signature. [7](#0-6)  The duplicate is not detected by the aggregate itself because `Rs` contains multiple entries and the weighted scalar satisfies the verification equation. [5](#0-4)  This is severity Medium because exploitation requires an integration to accept repeated signer/challenge contexts as independent signatures, but the primitive does not prevent or disclose that duplicate counting. [8](#0-7) 

### Likelihood Explanation
Any party possessing one valid signature can submit it to `aggregate` multiple times or construct equivalent serialized aggregate bytes. [8](#0-7)  The attack is deterministic because the verifier recomputes the same per-entry weights from the repeated challenges. [9](#0-8)  Integrations that already require globally unique public keys or unique challenge contexts are not affected. [3](#0-2) 

### Recommendation
Change `SchnorrAggregator::aggregate` to return an error when the same challenge, serialized signature, or signer identity has already been supplied. [1](#0-0)  If signatures must represent distinct signers, include the signer public key in the aggregation API and reject duplicate keys before producing `s`. [8](#0-7)  `SchnorrAggregate::verify` should also reject duplicate `(key, challenge)` entries, and duplicate keys when the intended semantics are one signature per signer. [3](#0-2) 

### Proof of Concept
```rust
const DST: &[u8] = b"duplicate-aggregate";

let private_key = Zeroizing::new(C::random_nonzero_F(&mut OsRng));
let public_key = C::generator() * private_key.deref();
let challenge = C::random_nonzero_F(&mut OsRng);
let signature = SchnorrSignature::<C>::sign(
  &private_key,
  Zeroizing::new(C::random_nonzero_F(&mut OsRng)),
  challenge,
);

let mut aggregator = SchnorrAggregator::<C>::new(DST);
aggregator.aggregate(challenge, signature);
aggregator.aggregate(challenge, signature); // Accepted a second time.

let aggregate = aggregator.complete().unwrap();
assert_eq!(aggregate.Rs(), &[signature.R, signature.R]);

// Passes even though only one signature was ever produced.
assert!(aggregate.verify(
  DST,
  &[(public_key, challenge), (public_key, challenge)],
));
```

The duplicated calls are accepted because `aggregate` only appends the challenge and pushes the signature. [1](#0-0)  `complete` assigns each duplicate a separate weight and adds both weighted `s` values. [2](#0-1)  The verifier performs the corresponding weighted statements for both supplied key/challenge pairs and therefore accepts the forged two-entry aggregate. [10](#0-9)

  /// Aggregate a signature.
  pub fn aggregate(&mut self, challenge: C::F, sig: SchnorrSignature<C>) {
    self.digest.append_message(b"challenge", challenge.to_repr());
    self.sigs.push(sig);
