### Title
Ed448 torsion check is vacuous, allowing forged Schnorr proofs for attacker-controlled low-order public keys - (File: crypto/ed448/src/point.rs)

### Summary
`Point::is_torsion_free` computes `(-P) + P`, which is always the identity, so it accepts every decoded curve point rather than proving prime-order membership. [1](#0-0)  Because `GroupEncoding::from_bytes` trusts this check, `Ciphersuite::read_G` accepts canonical encodings of Ed448 torsion components. [2](#0-1)  An unprivileged participant can therefore submit a low-order commitment/public key and a forged Schnorr `(R, s)` proof that satisfies `R + cA - sG = identity` without knowing a discrete logarithm for `A`. [3](#0-2) 

### Finding Description
The report’s bug class is a validation predicate that does not constrain the decoded value actually used later. Serai’s analogous shape is the Ed448 point decoder: after percent-decoding-style canonicalization is replaced here by point decompression, the supposedly authoritative subgroup predicate always returns true. Specifically, `Scalar::ZERO - Scalar::ONE` is `-1`, so `(*self * -1) + self` is definitionally identity for every `self`, including points outside the prime-order subgroup. [1](#0-0) 

This is reachable through public bytes passed to `Ed448::read_G`, `SchnorrSignature::<Ed448>::read`, PedPoP `Commitments::read`, `EncryptedMessage::read`, or `ThresholdKeys::read`. The generic `read_G` adds a canonical round-trip check, but it does not re-check subgroup membership; it trusts `from_bytes`. [2](#0-1) 

The PedPoP proof-of-knowledge path is directly exposed: commitments are decoded from attacker-controlled bytes, and `msg.commitments[0]` becomes the Schnorr public key for the queued proof verification. [4](#0-3) [5](#0-4) 

### Impact Explanation
An attacker can create a valid-looking Schnorr proof for a malformed Ed448 public key whose discrete logarithm relative to the generator is not known. For a 2-torsion public key `A = T`, choose `s = 0` and choose `R` as either identity or `T` according to whether the canonical challenge scalar is even or odd. Then `R + cA - sG = identity`, so `SchnorrSignature::verify` accepts the forgery. [3](#0-2) 

This defeats the knowledge-soundness assumption relied on by PedPoP’s commitment PoK and by standalone Schnorr verification. The malformed point is attacker-controlled public input and does not require a malicious validator model, leaked key, unsafe code, or an invalid integrator-supplied curve.

### Likelihood Explanation
Likelihood is moderate because the attacker must be able to select or influence the public key/commitment being verified. That is the intended input model for PedPoP commitment messages and other proof-verification APIs. The cryptographic trigger itself is deterministic for a 2-torsion key: one of the two candidate nonces satisfies the parity relation required by the challenge.

Full protocol impact beyond accepting a forged PoK depends on whether the attacker can additionally provide shares satisfying the commitment relation. Nevertheless, acceptance of a forged Schnorr proof is itself a concrete verifier failure and violates the security invariant that the PoK proves knowledge of the committed coefficient.

### Recommendation
Fix `Point::is_torsion_free` to multiply by the actual prime subgroup order, or another mathematically valid cofactor test. For Ed448, checking `l * P == identity` is appropriate for proving membership in the prime-order subgroup. Do not use `-P + P`, which is tautological.

Additionally, reject the identity where protocol semantics require non-identity keys/nonces, and add regression vectors for Ed448 low-order encodings, including the canonical order-2 point `(x, y) = (0, -1)`.

t2_encoding[0] = 0xfe;
t2_encoding[28] = 0xfe;
t2_encoding[56] = 0x00;

let a = Ed448::read_G(&mut t2_encoding.as_slice()).unwrap();
let identity = Ed448::read_G(
    &mut Ed448::G::identity().to_bytes().as_ref()
).unwrap();

let msg = b"attacker-selected message";

// s = 0. Verification succeeds iff R + cA = identity.
// For order-2 A, this means R = cA.
let mut s_encoding = [0u8; 32];
let s = Ed448::read_F(&mut s_encoding.as_slice()).unwrap();

let c_if_identity = IetfEd448Hram::hram(&identity, &a, msg);
let forged_r = if c_if_identity.to_repr().as_ref()[0] & 1 == 0 {
    identity
} else {
    a
};

let forged = SchnorrSignature::<Ed448> { R: forged_r, s };
let c = IetfEd448Hram::hram(&forged_r, &a, msg);
assert!(forged.verify(a, c));

The critical enabling defect is that `Point::from_bytes` intended to require `point.is_torsion_free()`, but the implementation always evaluates to true.
