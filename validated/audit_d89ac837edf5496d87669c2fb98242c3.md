### Title
Symlink/path-traversal escape in `getWorkingDirectoryImage` allows reading files outside the repository - (File: `app/src/lib/git/diff.ts`)

### Summary
The bug report's core pattern is an **incomplete accounting/validation**: `withdrawAll` computed a value from only one source (`balanceOfPool`) while ignoring another source that legitimately contributes to the total (`IERC20(_token).balanceOf(address(this))`), so tokens the code "forgot" to count were left unprotected. The Desktop analog is the same class of bug applied to path validation: a file-path is joined onto the repository root and used to read a file, but the join is done "raw" (`Path.join(repository.path, file.path)`) instead of going through the codebase's own path-containment check, `resolveWithin`, which is specifically designed to catch symlink escapes and traversal segments and is used elsewhere in the code for exactly this purpose.

### Finding Description
`getWorkingDirectoryImage` in `app/src/lib/git/diff.ts` reads image content for the working-directory version of a changed file like this: [1](#0-0) 

It builds the on-disk path with a plain `Path.join(repository.path, file.path)` and calls `readFile` directly on it. `file.path` originates from the file-change/status list produced from the working directory of a **cloned/fetched repository** — content that is fully attacker controlled if the user opens or fetches a hostile repo.

Elsewhere in this same codebase, the authors added an explicit guard, `resolveWithin`/`resolveWithinPosix`/`resolveWithinWin32` in `app/src/lib/path.ts`, precisely to prevent this class of bug: it normalizes the path, resolves it to an absolute path, and then calls `realpath()` on both the root and the resolved path so that **symlink escapes** (not just `..` traversal) are caught, returning `null` if the real path is not underneath the real root: [2](#0-1) 

This guard is already applied to other places that read files named by attacker-influenced repository content, e.g. `copilot-conflict-context.ts` explicitly documents "Guard against path traversal and symlink escapes (cross-platform)": [3](#0-2) 

and `dispatcher.ts`'s `openRepositoryFromUrl` also resolves user/attacker-supplied file paths through `resolveWithin` before doing anything with them: [4](#0-3) 

`getWorkingDirectoryImage`, however, skips this check entirely. Because git tracks symlinks as ordinary blobs, a hostile repository can commit a symlink such as `evil -> /` (or to any sensitive directory/file), and when the repository is cloned/checked out the symlink is materialized on disk. Any file appearing to live under `evil/...` in the working tree (e.g. an untracked/modified entry reported by `git status` through that symlinked directory) will have a `file.path` like `evil/secrets.png`. When the app then tries to render an "image diff" for that change, `Path.join(repository.path, file.path)` resolves through the symlink and escapes the repository root; `readFile` returns the *real* target file's bytes, which are base64-encoded and handed back as `Image` data to be rendered/exposed in the UI.

### Impact Explanation
This lets an attacker who controls a cloned/fetched repository (or a crafted "Open repository from URL"/PR checkout flow that ends up diffing such content) cause GitHub Desktop to read and disclose the contents of arbitrary files outside the repository that are accessible to the user's OS account (e.g., SSH keys, `.netrc`, other repos, credential files), by naming them so the working-directory diff/image-preview code path is triggered on a symlink-crafted path. This matches the requested impact class: "file... read outside the repo" caused by content the attacker fully controls (a cloned/fetched repository), reachable without any local/physical access, admin rights, or pre-existing host compromise.

### Likelihood Explanation
The prerequisite is simply that the victim clones/opens a malicious repository and that a file recognized as an "image" change appears under a symlinked path in the working directory (attacker fully controls repo content, including symlinks and file naming/extension to trigger the image-diff code path). No unusual user gesture beyond normal repository browsing (viewing the Changes/diff pane) is required, which is a standard part of the GitHub Desktop workflow. The fix pattern (`resolveWithin`) already exists and is applied to sibling code paths in the same file/area of the codebase, indicating the maintainers consider this exact class of bug in-scope and exploitable, but this particular function was missed — analogous to `withdrawAll` in the original report using an incomplete accounting formula while a sibling/complete formula existed and should have been reused.

### Recommendation
In `getWorkingDirectoryImage` (and any other function in `app/src/lib/git/diff.ts` that joins `repository.path` with a `file.path` derived from working-directory status, e.g. blob/diff readers), replace the raw `Path.join` + `readFile` with the existing `resolveWithin` helper from `app/src/lib/path.ts`, mirroring the pattern already used in `copilot-conflict-context.ts`:
```ts
const absolutePath = await resolveWithin(repository.path, file.path)
if (absolutePath === null) {
  throw new Error('File path is outside the repository')
}
const contents = await readFile(absolutePath)
```
Audit all other direct `Path.join(repository.path, ...)` + filesystem-access call sites (diff rendering, "open file", binary detection) for the same missing guard.

### Proof of Concept
1. Attacker creates a repository containing a symlink `evil` pointing to a sensitive directory reachable from the victim's filesystem (e.g., `evil -> ../../../../` or an absolute path such as `/Users/victim` on macOS/Linux, or a UNC/drive-relative equivalent trick on Windows) and commits it.
2. Victim clones this repository into GitHub Desktop.
3. Attacker's repo also ships (or the victim locally creates, e.g. via a script triggered by another means, or simply because the symlinked path already contains files) a working-directory-visible change under `evil/<targetFileName>.png` (any file, renamed with an image extension so `getMediaType` treats it as an image).
4. Victim opens the Changes view in Desktop and clicks the modified/untracked file to preview it; Desktop calls `getWorkingDirectoryImage(repository, file)` with `file.path === 'evil/<targetFileName>.png'`.
5. `Path.join(repository.path, 'evil/<targetFileName>.png')` resolves through the `evil` symlink to a path outside the repository; `readFile` succeeds and returns the target file's bytes, which get base64-encoded and rendered/exposed via the diff UI — demonstrating file read outside the intended repository boundary, unguarded by `resolveWithin` (unlike the `copilot-conflict-context.ts` sibling code path).

Note: I was not able to execute this PoC or trace the exact `git status` parsing code that produces `file.path` for symlinked subpaths in this session (index-size limits on the available tooling), so the exact reachability of a symlinked working-directory path through the status/diff pipeline into `getWorkingDirectoryImage` should be confirmed by a Devin session with full repository/checkout access before treating this as fully verified.

```typescript
  repository: Repository,

): Promise<Image> {

    contents.toString('base64'),
    getMediaType(Path.extname(file.path)),

}
```

```typescript
async function _resolveWithin(
  rootPath: string,
  pathSegments: string[],
  options: {
    join: (...pathSegments: string[]) => string
    normalize: (p: string) => string
    resolve: (...pathSegments: string[]) => string
  } = Path
) {
  // An empty root path would let all relative
  // paths through.
  if (rootPath.length === 0) {
    return null
  }

  const { join, normalize, resolve } = options

  const normalizedRoot = normalize(rootPath)
  const normalizedRelative = normalize(join(...pathSegments))

  // Null bytes has no place in paths.
  if (
    normalizedRoot.indexOf('\0') !== -1 ||
    normalizedRelative.indexOf('\0') !== -1
  ) {
    return null
  }

  // Resolve to an absolute path. Note that this will not contain
  // any directory traversal segments.
  const resolved = resolve(normalizedRoot, normalizedRelative)

  const realRoot = await realpath(normalizedRoot)
  const realResolved = await realpath(resolved)

  return realResolved.startsWith(realRoot) ? resolved : null
```
