## Title
Malicious git remote can spoof a `WWW-Authenticate: realm="GitHub"` header to hijack the credential-helper flow, tricking Desktop into binding a real GitHub account/token to an attacker-controlled host - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
GitHub Desktop's git credential helper trusts a server-supplied `WWW-Authenticate` header value to decide whether an arbitrary remote host is a "GitHub Enterprise" host, without any origin/identity verification. An attacker who controls the HTTP response for a git remote (or a MITM/corporate-style proxy) can set `realm="GitHub"` on a 401 response for any hostname whatsoever, causing Desktop to (1) skip its network-based `isGitHubHost` verification and (2) trigger a "Sign in to GitHub" popup bound to the attacker's endpoint. If the user completes sign-in, the resulting real account/token is registered against the attacker's endpoint and will subsequently be sent as a Basic-auth credential to that attacker-controlled host on future git operations.

### Finding Description
The trampoline credential helper's `getEndpointKind` function determines how to treat a credential request for an unknown host: [1](#0-0) 

```
  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }
```

This is a "happy-path" shortcut that entirely bypasses the actual verification function `isGitHubHost` (which performs an out-of-band HEAD request to `<endpoint>/meta` and checks for the `x-github-request-id` response header before trusting a host) — that check is only reached as a fallback *when no `wwwauth` header is present*: [2](#0-1) 

Because `wwwauth[]` values are populated directly from the server's `WWW-Authenticate` response header (an attacker-controlled value for any remote the user clones or fetches from, or any MITM/corporate proxy sitting in front of it), any host can force `getEndpointKind` to return `'enterprise'` simply by responding with `WWW-Authenticate: Basic realm="GitHub"` on a 401.

Once `getEndpointKind` returns non-`'generic'`, `getCredential` checks whether an existing account matches the endpoint; since this is a brand-new attacker host, none exists, so it invokes the sign-in prompt directly with the attacker-controlled endpoint URL: [3](#0-2) 

`ui.promptForGitHubSignIn` then routes to the Enterprise sign-in flow and sets the sign-in endpoint to the attacker's origin: [4](#0-3) 

If the user (believing they're authenticating a legitimate corporate GHE instance, since it's presented via the normal "Sign in to GitHub" UI) completes authentication, the resulting `Account` — carrying a genuine GitHub token — is persisted keyed by that attacker endpoint. Subsequent credential lookups for that same origin match it via `findGitHubTrampolineAccount`, which only compares URL `origin`: [5](#0-4) 

and `credWithAccount` will happily hand the real login/token to git as the password to be sent (as HTTP Basic auth) to the attacker's server on every future request to that host: [6](#0-5) 

### Impact Explanation
This lets an attacker who controls a git remote/proxy response (no local access, no leaked credentials, no malware needed) impersonate "GitHub Enterprise" to Desktop's credential helper for an arbitrary hostname, bypassing the legitimate network-based `isGitHubHost` verification entirely. This can be used to phish the user into an OAuth/PAT sign-in flow that is silently bound to the attacker's endpoint, and — because the credential lookup matches purely by URL origin — any credential (token) associated with that endpoint is subsequently transmitted to the attacker's server as a Basic-auth password on further git requests. This maps to "unauthorized OAuth or account binding" and "credential/token exfiltration" in the accepted impact categories.

### Likelihood Explanation
The trigger requires only that the user perform a normal, expected action — cloning or fetching from a repository whose remote (or its network path) is under attacker control, or one they've routed through a corporate/MITM-style proxy — and the server return a single crafted `WWW-Authenticate` header on a 401 response. No unusual interaction is needed beyond the existing "enter credentials" flow that already occurs for any private git remote requiring auth.

### Recommendation
Do not use the `wwwauth[]` realm string alone as a trust signal for classifying an arbitrary host as GitHub/Enterprise. At minimum, treat the header as a hint that should still require the `isGitHubHost` network-based confirmation (checking the actual `x-github-request-id` response header) before routing to the GitHub-Enterprise sign-in flow, and clearly surface the actual endpoint hostname to the user in the sign-in prompt so a mismatch with the URL they intended to reach is visible.

### Proof of Concept
1. Host an HTTP server at `https://evil.example.com` that responds to any git-over-HTTP auth-info/credential request with `401 Unauthorized` and header `WWW-Authenticate: Basic realm="GitHub"`.
2. In GitHub Desktop, add/clone/fetch a repository whose remote is `https://evil.example.com/foo/bar.git` (or force any legitimate remote's traffic through a proxy that injects this header).
3. Git captures the header and forwards it to Desktop's trampoline credential helper as a `wwwauth[]` credential field.
4. `getEndpointKind` (`app/src/lib/trampoline/trampoline-credential-helper.ts`, lines 153-165) returns `'enterprise'` without ever calling `isGitHubHost`.
5. Since no account matches `evil.example.com`, Desktop shows a "Sign in to GitHub" popup bound to `https://evil.example.com`.
6. If the user signs in (e.g., with a PAT or via OAuth to a *different*, correct GHE instance they own, mistakenly typed/confused because the dialog looks identical to a legitimate GHE sign-in), that account/token is now stored keyed to `evil.example.com`'s origin and will be sent as Basic-auth credentials to `evil.example.com` on subsequent git operations.

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}

        credentialHelperUrl: endpoint,
      })

export async function findGitHubTrampolineAccount(
  accountsStore: AccountsStore,
  remoteUrl: string
): Promise<Account | undefined> {
  const accounts = await accountsStore.getAll()
  const parsedUrl = new URL(remoteUrl)
  return accounts.find(
    a => new URL(getHTMLURL(a.endpoint)).origin === parsedUrl.origin
  )
}
