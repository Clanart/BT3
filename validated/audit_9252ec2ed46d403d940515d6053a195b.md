### Title
Unauthenticated `ReceivedOutput::read` credits arbitrary funds that can never be spent - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The FOSSBilling advisory is a forged-callback bug: an unauthenticated endpoint mutates accounting state ("invoice paid") without verifying that the claimed payment exists. The Serai analog is `ReceivedOutput::read` in `networks/bitcoin/src/wallet/mod.rs`: it accepts attacker-controlled bytes and mints a `ReceivedOutput` — the object every downstream consumer treats as "funds received" — with no check that the claimed `outpoint`, `value`, or `script_pubkey` corresponds to any real on-chain output or to the scanner's key. A single crafted byte stream "credits" an arbitrary balance that is unspendable.

### Finding Description
`ReceivedOutput` is the record the `Scanner` produces when it finds a payment, and its `read`/`write` pair is the serialization boundary for that record. `read` deserializes three fields directly from untrusted input:

```rust
// networks/bitcoin/src/wallet/mod.rs:122-134
pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
  let offset = Secp256k1::read_F(r)?;
  output  = TxOut::consensus_decode(...)?;    // arbitrary script_pubkey + value
  outpoint = OutPoint::consensus_decode(...)?; // arbitrary txid/vout
  Ok(ReceivedOutput { offset, output, outpoint })
}
```

There is no binding between `offset` and `output.script_pubkey`. The genuine path (`Scanner::scan_transaction`, mod.rs:199-213) only ever constructs a `ReceivedOutput` whose `script_pubkey` equals `p2tr_script_buf(key + G*offset)` and whose `outpoint` is a real position in a real transaction. `read` enforces neither invariant, so forged bytes produce a struct indistinguishable from a scanner-produced one.

The forged object is then consumed as real money:

- `SignableTransaction::new` sums `input.output.value` into `input_sat` and treats it as spendable balance for fee/change/payment math (`send.rs:175`, `send.rs:187-235`). `ReceivedOutput::value()` (mod.rs:116-118) reports the attacker's chosen amount to any accounting/crediting logic.
- The only consistency check lives in `SignableTransaction::multisig` (`send.rs:273-285`), which compares `p2tr_script_buf(offset.group_key())` against `prevouts[i].script_pubkey` — i.e., it can only prove the output is *not* spendable, long after the funds have been recorded, and it does so by returning `None` (failure), not by rejecting the credit.
- `TransactionSignMachine::sign` commits to `Prevouts::All(&self.tx.prevouts)` (`send.rs:373-390`), so even if the `script_pubkey` is forged to match, the signature commits to a fictitious prevout value/outpoint and the resulting transaction is consensus-invalid — the "received" funds can never move.

### Impact Explanation
An unprivileged party supplies bytes to `ReceivedOutput::read` (explicitly an untrusted-input sink). They receive back a `ReceivedOutput` asserting `value()` of any amount at any `outpoint`. Any crediting, deposit-confirmation, balance, or re-serialized-store path that trusts this object marks funds as received without a corresponding on-chain payment — the exact "mark invoice paid without paying" effect of CVE-2026-42341. The forged credit is then unspendable: `multisig` refuses to build a signing machine, or the signed transaction is rejected by the network because its sighash commits to nonexistent prevouts. This is integrity loss of funds-accounting (funds reported received that are not spendable), matching Medium severity.

### Likelihood Explanation
Reachable by any party who can get bytes to the `read` boundary — no keys, no mining, no threshold collusion required, and `read_F`/`consensus_decode` accept the crafted field values trivially. The impact is capped at accounting-integrity (the forger cannot *steal*, only cause phantom credit and a later failed/DoS'd spend), consistent with Medium rather than High.

### Recommendation
Bind the deserialized record to the scanning key and to the chain:

- In `ReceivedOutput::read` (or a new `read_for_key(key, r)` / `verify(&self, key)`), recompute `p2tr_script_buf(key + (GENERATOR * offset))` and reject if it doesn't equal `output.script_pubkey`, mirroring the check in `Scanner::scan_transaction`/`SignableTransaction::multisig`.
- Require integrators to confirm `outpoint` against the blockchain (or persist only scanner-derived bytes and authenticate the store) before crediting `value()`.
- Document that `read` is only safe for trusted storage until such validation exists.

### Proof of Concept
```rust
use bitcoin::{
  OutPoint, TxOut, Amount, ScriptBuf, Txid,
  hashes::Hash,
};
use bitcoin_serai::wallet::ReceivedOutput;
use k256::Scalar;
use std::io::Write;

// Attacker-controlled bytes: any offset, any value, any outpoint
let mut forged = Vec::new();
forged.write_all(&Scalar::ZERO.to_bytes()).unwrap(); // offset = 0 (external)

// Claim a TxOut paying 10 BTC to ANY script — never validated against the key
let fake_txout = TxOut {
  value: Amount::from_sat(1_000_000_000),
  script_pubkey: ScriptBuf::new(), // not p2tr(key + G*offset)
};
forged.extend(bitcoin::consensus::encode::serialize(&fake_txout));

// Claim an outpoint that does not exist on chain
let fake_outpoint = OutPoint { txid: Txid::all_zeros(), vout: 0 };
forged.extend(bitcoin::consensus::encode::serialize(&fake_outpoint));

// The unauthenticated "callback": forged bytes are accepted as a real payment
let output =
  ReceivedOutput::read::<&[u8]>(&mut forged.as_ref()).unwrap();
assert_eq!(output.value(), 1_000_000_000); // "credited" 10 BTC that never existed

// Any downstream SignableTransaction::new counts this toward input_sat
// (send.rs:175); multisig() can only fail (send.rs:277) — the credit
// is recorded before spendability is ever checked, and the signed TX
// commits to Prevouts::All of nonexistent prevouts (send.rs:375).
```
