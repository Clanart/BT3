### Title
Unbounded buffer offset advance in `is_atom_canonical`/`is_clvm_canonical` causes unhandled out-of-bounds index on attacker-controlled spend data - (File: chia/full_node/mempool_manager.py)

### Summary
`chia/full_node/mempool_manager.py`'s `is_clvm_canonical()` and its helper `is_atom_canonical()` walk a CLVM-serialized buffer by reading a length prefix and advancing an `offset` variable by the computed atom length, exactly like the Vim `typebuf` bug: the length used to advance the position is taken from attacker-controlled data and the code never verifies that the advanced `offset` still lies inside the buffer before the next byte is dereferenced.

### Finding Description
`is_atom_canonical()` decodes a variable-length atom-length prefix (0–5 extra bytes) directly from `clvm_buffer[offset]` without any prior check that `offset + prefix_len` is within `len(clvm_buffer)`: [1](#0-0) 

`is_clvm_canonical()` then uses the returned `atom_len` (which is fully attacker-controlled via the length-prefix bytes) to blindly advance `offset` and immediately re-index `clvm_buffer[offset]` on the next loop iteration, with no bounds check comparable to the ones added elsewhere in the codebase (`skip_bytes`/`skip_list` in `chia/full_node/full_block_utils.py`, which explicitly raise `ValueError` when a declared length exceeds the remaining buffer): [2](#0-1) 

Compare to the pattern that is correctly hardened elsewhere in this codebase: [3](#0-2) 

This function is invoked on every coin spend of every submitted `SpendBundle`, on both the `puzzle_reveal` and `solution` bytes, before any other content validation, directly from `MempoolManager.validate_spend_bundle()`: [4](#0-3) 

A malicious spend bundle can supply a puzzle_reveal/solution whose atom length prefix encodes a length that, when added to `offset`, walks past the end of the byte buffer. Because Python `bytes`/`bytearray` indexing is bounds-checked, this does not yield a C-style heap-buffer-overflow, but it does raise an unhandled `IndexError` deep inside `is_clvm_canonical()`, which is called with no surrounding `try`/`except` in `validate_spend_bundle()`.

### Impact Explanation
Any unprivileged peer or wallet client can submit a spend bundle whose puzzle reveal or solution is a syntactically valid-looking but truncated/malformed CLVM buffer that triggers this unbounded `offset` walk. This causes an uncaught `IndexError` inside core mempool-admission logic (`validate_spend_bundle` → `is_clvm_canonical`) that runs on the transaction-processing path used to admit every incoming spend bundle. Unlike Vim's native heap corruption/crash, the Python-level effect is a raised exception rather than memory corruption, but the finding matches the Vim CVE's underlying bug class one-for-one: a buffer cursor that is advanced by a value taken from untrusted input without validating remaining space before the next dereference. Depending on whether an enclosing caller catches generic exceptions, this can manifest as a mempool-admission failure for that bundle (low impact) or an unhandled exception propagating out of the transaction-processing task.

### Likelihood Explanation
High reachability: `is_clvm_canonical()` runs unconditionally on every coin spend's puzzle_reveal and solution for every spend bundle submitted to the mempool, so the trigger requires nothing beyond crafting one CLVM buffer with a malformed/truncated atom-length prefix and submitting it as a normal spend bundle.

### Recommendation
Add explicit remaining-length checks in `is_atom_canonical()` before each byte read (mirroring `skip_bytes`/`skip_list` in `full_block_utils.py`), and in `is_clvm_canonical()` validate that `offset + atom_len <= len(clvm_buffer)` before continuing the loop, raising a controlled error (e.g., returning non-canonical / raising `ValidationError`) instead of allowing an unchecked index to be computed and dereferenced.

### Proof of Concept
Construct a `puzzle_reveal` or `solution` byte string ending in an atom-length prefix byte (e.g. `0xFC`) that declares 5 additional length bytes but is truncated immediately after, e.g. `bytes([0xFC])` alone, or a buffer where the final atom's decoded `atom_len` causes `offset` to exceed `len(clvm_buffer)` by a few bytes; submit it via a `CoinSpend`/`SpendBundle` so that `MempoolManager.validate_spend_bundle()` calls `is_clvm_canonical(bytes(coin_spend.solution))`, triggering an out-of-bounds index inside `is_atom_canonical`/`is_clvm_canonical`. def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value


def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)

def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
