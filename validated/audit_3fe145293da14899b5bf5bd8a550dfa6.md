### Title
Unbounded recursive parsing of custody memo hints causes wallet stack exhaustion - (File: chia/wallet/puzzles/custody/custody_architecture.py)

### Summary
`PuzzleWithRestrictions.from_memo()` recursively reconstructs an `MofN` member tree by calling itself once per nested member memo, with no limit on nesting depth. Since memos are attacker-influenced data delivered via coin hints/offers/spend bundles that a wallet parses when syncing or accepting an offer, a maliciously deep `MofN` memo tree can drive unbounded Python-level recursion in a wallet process, mirroring the CVE-2015-7978 pattern of unbounded recursive traversal of external, structured input leading to stack exhaustion.

### Finding Description
`PuzzleWithRestrictions.from_memo()` [1](#0-0)  parses a `Program` memo tree. When `further_branching` is true, it builds an `MofN` node whose `members` list is populated by calling `PuzzleWithRestrictions.from_memo(memo)` for each nested member memo: [2](#0-1) 

This is genuine Python-level recursion (not CLVM/Rust cost-metered execution): each nested `MofN` member memo causes another `from_memo()` call, one Python stack frame deeper, with no check against a maximum nesting depth. `member_memos` is itself derived from `MofNHint.from_program()` [3](#0-2) , which simply iterates whatever the attacker encodes in the memo program — there is no cap on the number of members or on nesting depth anywhere in this parsing path.

The memo tree is documented as an on-chain/exported synchronization contract: `from_memo()` must reconstruct unknown members/restrictions, including recursive `MofN`, from data seen on-chain or in wallet-to-wallet exchanges. This class of construct (`PuzzleWithRestrictions`) is used for coin hints and offer memos, which are attacker/counterparty controlled and are parsed by another party's wallet without pre-validation of structural depth — directly analogous to `ntpdc`'s `relist` triggering unbounded recursive restriction-list traversal.

### Impact Explanation
An attacker who controls a coin's hint memo (e.g. a crafted custody coin sent to a victim, or a memo embedded in an offer/spend a wallet is asked to parse) can construct a deeply nested `MofN` memo tree. When the victim wallet calls `PuzzleWithRestrictions.from_memo()` to reconstruct/sync the puzzle (standard wallet behavior for recognizing custody coins), it recurses once per nesting level. With sufficiently deep nesting, this exhausts the Python call stack, raising `RecursionError` (or crashing the interpreter/thread) and halting wallet transaction/coin-state processing for that wallet — a spend-triggered denial-of-service against a wallet process, matching the "spend-triggered transaction-processing halt" impact category.

### Likelihood Explanation
This is reachable purely through data delivered in a memo (visible to wallet clients that scan hints/memos for custody coins) or an offer file, both of which are attacker-controlled and are commonly parsed automatically by wallet software without a depth cap. No special privileges are required — any coin sender or offer counterparty can construct the memo. The construct is a small Program tree, cheap to build, so triggering deep recursion is low-cost for the attacker.

### Recommendation
Add an explicit maximum nesting-depth check (or iterative/worklist-based rewrite, as already done elsewhere in the codebase for `sha256_treehash()` and Data Layer tree loading which raises `chia_rs.datalayer.RecursionDepthExceededError`) to `PuzzleWithRestrictions.from_memo()` and `MofN` reconstruction, rejecting memos that exceed a safe depth (e.g. mirroring Python's practical recursion limits with margin) before recursing further.

### Proof of Concept
1. Construct a `Program` memo using `PuzzleWithRestrictions.memo()`-compatible encoding where the `MofN` `further_branching` flag is set and `member_memos` recursively contains another maximally nested `MofN` memo, repeated N times (e.g. N = 5,000–100,000, well beyond Python's default recursion limit).
2. Deliver this memo to a victim wallet as a coin hint (or within an offer/spend that references the coin), causing the wallet's normal coin-hint scanning / custody-sync logic to call `PuzzleWithRestrictions.from_memo(memo)`.
3. Observe that the recursive call chain in `from_memo()` → `MofN(...)` → `from_memo()` (repeated) exhausts the Python call stack, raising `RecursionError` and halting the wallet's processing of that spend/coin without any prior bound check.

**Uncertainty note:** I was not able to trace the exact call site(s) that invoke `PuzzleWithRestrictions.from_memo()` on unvalidated network/offer-derived data (e.g. hint-scanning code in the wallet sync path) due to search/index limits, so the precise reachability trigger (automatic hint scan vs. explicit user action) could not be fully confirmed from the available index; a full-repo Devin session would be needed to confirm the exact invocation path.

    @classmethod
    def from_memo(cls, memo: Program) -> PuzzleWithRestrictions:
        if memo.atom is not None or memo.first() != Program.to(cls.spec_namespace):
            raise ValueError("Attempting to parse a memo that does not belong to this spec")
        nonce = memo.at("rf")
        restriction_hints_prog = memo.at("rrf")
        further_branching_prog = memo.at("rrrf")
        puzzle_hint_prog = memo.at("rrrrf")
        additional_memos = memo.at("rrrrrf") if memo.at("rrrrr").atom is None else None
        restriction_hints = [RestrictionHint.from_program(hint) for hint in restriction_hints_prog.as_iter()]
        further_branching = further_branching_prog != Program.to(None)
        if further_branching:
            m_of_n_hint = MofNHint.from_program(puzzle_hint_prog)
            puzzle: MIPSComponent = MofN(
                m=m_of_n_hint.m, members=[PuzzleWithRestrictions.from_memo(memo) for memo in m_of_n_hint.member_memos]
            )
        else:
            puzzle_hint = MemberHint.from_program(puzzle_hint_prog)
            puzzle = UnknownMember(puzzle_hint)

        return PuzzleWithRestrictions(
            nonce=nonce.as_int(),
            restrictions=[UnknownRestriction(hint) for hint in restriction_hints],
            puzzle=puzzle,
            additional_memos=additional_memos,
        )
