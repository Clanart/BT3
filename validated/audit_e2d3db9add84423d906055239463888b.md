### Title
Cached FROST preprocess deterministically regenerates identical nonces across distinct signing sessions, enabling ROS-style secret-share recovery - (File: crypto/frost/src/sign.rs)

### Summary
`AlgorithmSignMachine::from_cache` rebuilds a sign machine from a `CachedPreprocess` and regenerates the nonce pair `(d, e)` deterministically from the cached seed. Nothing in `crypto/frost` binds the derived nonces to the message or signing set, and the production caller (`share_internal` in `coordinator/src/tributary/signing_protocol.rs`) loads the same cached seed for every signing attempt under the same context and never deletes or rotates it. An unprivileged participant who gets the validator to sign under two or more distinct preprocess sets or messages within the same context receives shares that reuse the same `(d, e)`, yielding linear equations that recover the validator's secret share — the analog of an unauthenticated entry point performing a privileged operation without the required validation.

### Finding Description
`from_cache` calls `AlgorithmMachine::new(algorithm, keys).seeded_preprocess(cache)`, deterministically regenerating `self.nonces` from the 32-byte seed [1](#0-0) . In `sign()`, the actual nonce is computed as `base + actual * our_binding_factors[n]`, where `base`/`actual` are the cached `(d, e)` and only `rho` (the binding factor) varies with the preprocess set and message [2](#0-1) . The emitted share is `s = c·share_i + d + e·rho` via `sign_share`/`SchnorrSignature::sign` [3](#0-2) .

The caller caches one seed per context and reuses it on every `share_internal` call: `CachedPreprocesses::get` loads the same bytes and `from_cache` is invoked fresh each time, with no consumption/invalidation of the cache [4](#0-3) . `share_internal` then signs whatever `msg` and attacker-influenced `serialized_preprocesses` are supplied [5](#0-4) .

`sign()` validates the participant set (count, bounds, duplicates) but performs no check that the underlying nonce material is fresh for this `(msg, included)` combination [6](#0-5) .

### Impact Explanation
Each observed share is a linear equation `s_j = c_j·x + d + e·rho_j` in the three unknowns `{x (secret share), d, e}`, since `c_j` and `rho_j` are publicly computable from the transcript (`rho` derives from `group_key`, `hash_msg(msg)`, and the `preprocesses` challenge) [7](#0-6) . Three distinct signing sessions under one cached seed give a solvable linear system revealing the signer's FROST secret share `x`. Combined with other compromised shares (or iterated against enough honest validators), this recovers the threshold private key, converting nonce reuse into full key compromise — the direct analog of the CVE's "no authorization check → privileged action by unauthenticated party", where the missing check is one-time-use enforcement/binding of nonce material to the session.

### Likelihood Explanation
Reachability only requires an unprivileged signer to cause `share_internal` to run multiple times for the same context with different preprocess sets or messages — e.g., by participating in multiple attempts or by varying the accumulated preprocess set. `from_cache`'s documentation states reuse "will presumably cause the signer to leak their secret share," confirming the deterministic-nonce behavior [8](#0-7) . The residual uncertainty is whether the coordinator's `context` encodes attempt/message identity; if it does not, reuse across distinct messages is guaranteed. Note the documented-MUST caveat partially mitigates this as an integration-level hazard, yet Serai's own production caller performs the reuse unconditionally per context, so the exposure exists in shipped code.

### Recommendation
Bind the derived nonces to the signing session: incorporate `msg` and the sorted `included` set into the nonce derivation inside `seeded_preprocess`/`sign` (e.g., hash `seed || msg || included || secret` via `Curve::random_nonce`), so reusing a `CachedPreprocess` for a different session yields different `(d, e)`. Alternatively, atomically consume `CachedPreprocesses` entries in `preprocess_internal` (delete on read) so `from_cache` can never execute twice with the same seed under one context.

### Proof of Concept
```rust
// crypto/frost — conceptual PoC
// Let cache be a CachedPreprocess previously stored for context C.
// Session 1: attacker contributes preprocess set P1, message m1
let (m1, _) = AlgorithmSignMachine::from_cache(alg.clone(), keys.clone(), cache.clone());
let (_, s1) = m1.sign(preprocesses_P1, b"msg1").unwrap(); // s1 = c1*x + d + e*rho1

// Session 2: same cache, different preprocess set / message
let (m2, _) = AlgorithmSignMachine::from_cache(alg, keys, cache); // identical (d, e)
let (_, s2) = m2.sign(preprocesses_P2, b"msg2").unwrap(); // s2 = c2*x + d + e*rho2

// Session 3 yields s3 = c3*x + d + e*rho3
// rho_j = hash_binding_factor(rho_transcript_j || participant), c_j = hram(R_j, group_key, msg_j)
// Solve the 3x3 linear system {x, d, e} over C::F:
//   [c1  1  rho1] [x]   [s1]
//   [c2  1  rho2] [d] = [s2]
//   [c3  1  rho3] [e]   [s3]
// x is the signer's interpolated secret share for the included set.
```

  fn share_internal(
    &mut self,
    participants: &[<Ristretto as Ciphersuite>::G],
    mut serialized_preprocesses: HashMap<Participant, Vec<u8>>,
    msg: &[u8],
  ) -> Result<(AlgorithmSignatureMachine<Ristretto, Schnorrkel>, [u8; 32]), Participant> {
    let machine = self.preprocess_internal(participants).0;

    let mut participants = serialized_preprocesses.keys().copied().collect::<Vec<_>>();
    participants.sort();
    let mut preprocesses = HashMap::new();
    for participant in participants {
      preprocesses.insert(
        participant,
        machine
          .read_preprocess(&mut serialized_preprocesses.remove(&participant).unwrap().as_slice())
          .map_err(|_| participant)?,
      );
    }

    let (machine, share) = machine.sign(preprocesses, msg).map_err(|e| match e {
      FrostError::InternalError(e) => unreachable!("FrostError::InternalError {e}"),
      FrostError::InvalidParticipant(_, _) |
      FrostError::InvalidSigningSet(_) |
      FrostError::InvalidParticipantQuantity(_, _) |
      FrostError::DuplicatedParticipant(_) |
      FrostError::MissingParticipant(_) => unreachable!("{e:?}"),
      FrostError::InvalidPreprocess(p) | FrostError::InvalidShare(p) => p,
    })?;

    Ok((machine, share.serialize().try_into().unwrap()))
