### Title
Missing input-length bound in legacy JSON precompile `ExtractAsUint256` allows unbounded `big.Int` string parsing - ([File: precompiles/json/legacy/v640/json.go])

### Summary
Every legacy version of the JSON precompile's `ExtractAsUint256` (versions `v5.6.2` through `v6.4.0`) extracts an arbitrary-length numeric string from attacker-supplied JSON and feeds it directly into `new(big.Int).SetString(strValue, 10)` with no upper bound on string length. Only the current/latest implementation and the very latest legacy versions (`v66`/`v67`) add a `len(strValue) > 100` guard. This is the same bug class as CVE-2019-6975 (Django `numberformat.format()`): an attacker-controlled numeric string of unbounded length is passed into a big-number routine whose cost grows superlinearly with input length, allowing memory/CPU blow-up from a small request.

### Finding Description
The JSON precompile at address `0x0000000000000000000000000000000000001003` exposes `extractAsUint256(bytes json, string key)`. In the current code, `ExtractAsUint256` bounds the extracted value string to 100 characters before calling `big.Int.SetString`: [1](#0-0) 

However, all legacy precompile implementations reachable via historical block-height routing (`v5.6.2`, `v6.0.3`, `v6.0.5`, `v6.0.6`, `v6.1.0`, `v6.1.4`, `v6.2.0`, `v6.3.0`, `v6.4.0`) never had this check added — they parse the trimmed JSON value string directly with `big.Int.SetString`, with no length restriction: [2](#0-1) 

The only gas charged for this call is `GasCostPerByte * len(input)` on the raw JSON payload bytes: [3](#0-2) 

which is linear in the input size and does not account for the actual cost of `big.Int.SetString`/decimal-to-binary conversion, which is superlinear (roughly O(n²)) in the number of digits for large decimal strings — mirroring the exact algorithmic weakness described in the Django advisory.

These legacy precompile versions are selected via the keeper's per-address, per-block-height version routing, used whenever the EVM is executing in a tracing context (e.g., debugging/replaying historical transactions): [4](#0-3) [5](#0-4) 

Any transaction or `eth_call`/`debug_traceCall`-style RPC request executed against a block height mapped to one of the affected upgrade versions will invoke the unguarded legacy `ExtractAsUint256`.

### Impact Explanation
An unprivileged caller (any contract, or a public JSON-RPC client using debug/trace/historical-call methods) can submit a call to the JSON precompile with a crafted JSON payload whose target key's value is a decimal string containing an extremely large number of digits (limited only by the EVM calldata size limit / block gas limit, since gas cost is only linear per byte at `GasCostPerByte=100`). Parsing such a string with `big.Int.SetString` allocates and manipulates internal `big.Word` buffers whose cost grows faster than the gas charged, letting an attacker spend disproportionately little gas to consume large amounts of CPU/memory on the executing node. Repeated or concurrent invocation of this pattern against RPC nodes evaluating historical/tracing calls can exhaust node memory or stall block/query processing, a form of Uncontrolled Memory Consumption (CWE-770) matching the High-severity classification of the referenced Django CVE.

### Likelihood Explanation
Likelihood is constrained by the fact that the vulnerable code paths are only invoked when the EVM executes with `ctx.IsTracing() == true` (i.e., during `debug_trace*`/historical replay-style RPC calls) — normal, in-block transaction execution always uses the latest (patched) precompile version. This narrows practical exploitation to public RPC nodes that expose debug/trace endpoints and allow calls at or near the affected historical upgrade heights. Where such endpoints are exposed without additional resource limits, the attack requires only a single crafted RPC request, making it easy to trigger for a node operator that has not disabled debug/trace APIs.

### Recommendation
Backport the `len(strValue) > 100` (or an equivalent, conservative) length check to all legacy `ExtractAsUint256` implementations that lack it (`v562`, `v603`, `v605`, `v606`, `v610`, `v614`, `v620`, `v630`, `v640`), or alternatively have the tracing/historical-call code path always invoke the latest-patched precompile logic for the JSON precompile regardless of the on-chain upgrade-height mapping, since these are computational routines with no persisted state and no consensus reason to preserve old vulnerable string-parsing behavior. Additionally, consider charging gas proportional to the digit count actually passed to `big.Int.SetString` rather than only to the raw JSON payload length, to remove the gas/cost mismatch at its root.

### Proof of Concept
1. Identify or wait for a debug/trace-enabled public RPC node whose block height (or explicit tracing/eth_call target block) maps to an upgrade version between `v5.6.2` and `v6.4.0` (per `GetCustomPrecompilesVersions`).
2. Construct calldata to `0x0000000000000000000000000000000000001003` (`extractAsUint256(bytes,string)`) where the JSON payload is `{"k":"<N digit decimal string>"}` (N in the hundreds of thousands to millions, subject to calldata/gas ceiling), and `key = "k"`.
3. Submit via `debug_traceCall` (or replay a stored transaction with `debug_traceTransaction`) at a block height mapped to one of the vulnerable versions.
4. Observe that the legacy `ExtractAsUint256` in `precompiles/json/legacy/vXXX/json.go` calls `new(big.Int).SetString(strValue, 10)` on the full N-digit string without any length guard, consuming CPU/memory disproportionate to the `GasCostPerByte`-based gas charge, while the equivalent call against the latest precompile (`precompiles/json/json.go`) is rejected immediately by the `len(strValue) > 100` check.

func (k *Keeper) GetCustomPrecompilesVersions(ctx sdk.Context) map[common.Address]string {
	height := ctx.BlockHeight()
	cp := make(map[common.Address]string, len(k.customPrecompiles))
	for addr, versioned := range k.customPrecompiles {
		mostRecentUpgradeHeight := int64(0)
		noForkHistory := true
		for upgrade := range versioned {
			upgradeHeight := k.upgradeKeeper.GetDoneHeight(ctx, upgrade)
			if upgradeHeight != 0 {
				noForkHistory = false
			}
			if height < upgradeHeight {
				// requested height hasn't seen this upgrade version yet.
				continue
			}
			if upgradeHeight > mostRecentUpgradeHeight {
				mostRecentUpgradeHeight = upgradeHeight
				cp[addr] = upgrade
			}
		}
		if noForkHistory {
			cp[addr] = k.latestUpgrade
		}
	}
	return cp
}

func (k *Keeper) CustomPrecompiles(ctx sdk.Context) map[common.Address]vm.PrecompiledContract {

	versions := k.GetCustomPrecompilesVersions(ctx)

		cp[addr] = versioned[versions[addr]]

	return cp
