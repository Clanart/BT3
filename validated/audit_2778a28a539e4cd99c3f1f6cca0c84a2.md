### Title
mWOMSVBaseRewarder never forfeits early-unlock rewards, permanently diverting yield owed to loyal mWomSV stakers - (File: `rewards/mWOMSVBaseRewarder.sol`)

### Summary
`mWOMSVBaseRewarder._calExpireForfeit` is supposed to compute the portion of a user's accrued rewards that must be forfeited (and redistributed to remaining stakers) when the user has started/kept mWomSV in "cool down" (early unlock), mirroring the analogous logic in `vlMGPBaseRewarder`. In `mWOMSVBaseRewarder` this logic is broken: it never actually consults the loyalty percentage from the locker, so the forfeit amount is always zero regardless of a user's unlock state.

### Finding Description
`vlMGPBaseRewarder._calExpireForfeit` correctly queries the locker for the user's rewardable percentage and computes a forfeit based on it: [1](#0-0) 

The corresponding function in `mWOMSVBaseRewarder`, which is meant to do the same thing for mWomSV stakers, instead sets `rewardableAmount = _amount` unconditionally, so `forfeitAmount = _amount - rewardableAmount` is always `0`: [2](#0-1) 

It never calls `mWOMSV.getRewardablePercentWAD(_account)`, even though `mWomSV.sol` implements exactly this getter to compute the loyalty-weighted percent based on locked vs. cooling-down amounts: [3](#0-2) 

This getter is used elsewhere (e.g., `VLMGP.getRewardablePercentWAD`) to reduce rewards for users who are unlocking early, with the forfeited share re-queued as rewards for the remaining stakers: [4](#0-3) 

Because `mWOMSVBaseRewarder._sendReward` and `_earned` rely on the broken `_calExpireForfeit`, every mWomSV holder receives 100% of their accrued rewards on `getReward`/`getRewards`, even while they hold tokens in cooldown/early-unlock slots that should be penalized: [5](#0-4) 

### Impact Explanation
The forfeit mechanism exists to redistribute a share of rewards from users who exit early (via `startUnlock`/`unlock` cool-down slots in `mWomSV.sol`) to users who remain committed to the lock. Because the forfeit calculation is always zero, this redistribution never happens: early-unlocking users permanently capture yield that should have been forfeited to loyal, long-term stakers. This is a direct, permanent loss (theft) of unclaimed yield for the honest, long-term mWomSV holders, and it is triggerable by any ordinary wallet calling `startUnlock`/`unlock`/`getReward` — no privileged role is required.

### Likelihood Explanation
High likelihood: this triggers automatically on every reward claim through the normal user flow (`getReward`/`getRewards` on `mWOMSVBaseRewarder`, called via `MasterMagpie`), with no special preconditions other than having previously entered a cool-down slot in `mWomSV.sol`. There is no attacker cost or complexity — it's simply the default, unconditional behavior of the buggy function.

### Recommendation
Fix `mWOMSVBaseRewarder._calExpireForfeit` to mirror `vlMGPBaseRewarder._calExpireForfeit`, i.e., compute `rewardableAmount` using `mWOMSV.getRewardablePercentWAD(_account)`:
```solidity
function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
    uint256 rewardablePercentWAD = mWOMSV.getRewardablePercentWAD(_account);
    uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
    if (rewardableAmount > _amount)
        revert InvalidRewardableAmount();

    uint256 forfeitAmount = _amount - rewardableAmount;
    if (forfeitAmount < (_amount / 1000)) {
        forfeitAmount = 0;
        rewardableAmount = _amount;
    }
    return forfeitAmount;
}
```

### Proof of Concept
1. User locks mWOM into `mWomSV` and accrues rewards over time via `mWOMSVBaseRewarder`.
2. User calls `mWomSV.startUnlock(amount)` to move part of their balance into a cool-down slot — per `getRewardablePercentWAD`, this should reduce their rewardable share going forward. [6](#0-5) 
3. User calls `getReward`/`getRewards` on `mWOMSVBaseRewarder` (via `MasterMagpie`). `_sendReward` calls `_calExpireForfeit`, which — due to the bug — always returns `forfeitAmount = 0`. [5](#0-4) 
4. The user receives 100% of `userRewards[...]` instead of the reduced amount, and no forfeited amount is ever re-queued to `rewardInfo.rewardPerTokenStored` for remaining stakers, permanently depriving loyal stakers of the yield they were entitled to.

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalmWomSV = fullyInLock + inCoolDown;
        if (userTotalmWomSV == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalmWomSV;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalmWomSV / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalmWomSV;
                }

            }
        }

        return percent;
    }
