### Title
Missing caller-authorization check in `CW721ERC721Pointer.transferFrom()` allows unauthorized NFT transfer - ([File: contracts/src/CW721ERC721Pointer.sol])

### Summary
`CW721ERC721Pointer.transferFrom()` overrides OpenZeppelin's ERC721 `transferFrom` but only validates that `from` is the current owner of the token; it never checks whether `msg.sender` is the owner, an approved spender, or an approved operator. This omits the core access-control check that standard ERC721 (`_isAuthorized`/`_checkAuthorized`) enforces, allowing any address to move any CW721 NFT (via its ERC721 pointer) out of its owner's account.

### Finding Description
`CW721ERC721Pointer` wraps a CosmWasm CW721 NFT so it can be used as an EVM ERC721. Its `transferFrom` implementation is: [1](#0-0) 

```solidity
function transferFrom(address from, address to, uint256 tokenId) public override {
    if (to == address(0)) {
        revert ERC721InvalidReceiver(address(0));
    }
    require(from == ownerOf(tokenId), "`from` must be the owner");
    string memory recipient = _formatPayload("recipient", _doubleQuotes(AddrPrecompile.getSeiAddr(to)));
    string memory tId = _formatPayload("token_id", _doubleQuotes(Strings.toString(tokenId)));
    string memory req = _curlyBrace(_formatPayload("transfer_nft", _curlyBrace(_join(recipient, tId, ","))));
    _execute(bytes(req));
}
```

Note there is no `require(msg.sender == from || isApprovedForAll(from, msg.sender) || getApproved(tokenId) == msg.sender, ...)` check anywhere in this function. The contract *does* implement `getApproved` and `isApprovedForAll` (queried from the underlying CW721 contract) [2](#0-1)  — but `transferFrom` never consults them.

The underlying `_execute` call delegatecalls into the wasmd precompile with a `transfer_nft` CosmWasm message: [3](#0-2) . The wasmd precompile's `execute` entrypoint runs the message with the *contract's* (i.e., the pointer's) authority as the sender against the CW721 contract, since the pointer is what's calling `transfer_nft`. Because the CW721 contract sees the pointer contract itself as the sender of `transfer_nft`, the CW721-level authorization is effectively bypassed by the pointer, and the pointer's own EVM-level `require(from == ownerOf(tokenId))` check is the only remaining gate — which checks the wrong party (the token's owner) instead of the caller's authorization.

This directly contrasts with the sibling `CW1155ERC1155Pointer.safeTransferFrom`, which correctly enforces `require(msg.sender == from || isApprovedForAll(from, msg.sender), ...)` [4](#0-3) , showing that this authorization check is the intended pattern that was omitted for `CW721ERC721Pointer.transferFrom`.

### Impact Explanation
Any EVM account (an unprivileged transaction sender) can call `transferFrom(ownerAddr, attackerAddr, tokenId)` on any deployed `CW721ERC721Pointer` for any `tokenId` currently owned by `ownerAddr`, without ever having been granted approval by the owner. This results in unauthorized transfer of an NFT asset represented through the pointer — permanent, unauthorized loss of the asset for the legitimate owner, matching the "unauthorized transfer via precompile or pointer" impact class.

### Likelihood Explanation
Highly reachable: any address holding gas can call `transferFrom` on a public `CW721ERC721Pointer` contract address with attacker-chosen `to`. The only precondition is knowing the `tokenId` and current owner, both of which are readable via `ownerOf`. No special privileges, front-running, or race conditions are required — a single transaction fully exploits it.

### Recommendation
Add the missing authorization check before executing the transfer, mirroring the ERC1155 pointer and standard ERC721 semantics:
```solidity
require(
    msg.sender == from || getApproved(tokenId) == msg.sender || isApprovedForAll(from, msg.sender),
    "ERC721: caller is not token owner or approved"
);
```
This should be added immediately after the `from == ownerOf(tokenId)` check in `transferFrom`, and the same pattern should be audited for any other transfer-capable function in the pointer contracts to ensure caller authorization is always checked against `msg.sender`, not just the `from` argument.

### Proof of Concept
1. Owner `A` owns CW721 NFT `tokenId=1`, represented by pointer `P` (`CW721ERC721Pointer`).
2. Attacker `B` (no approval from `A`) calls `P.transferFrom(A, B, 1)` directly.
3. The function checks only `from == ownerOf(tokenId)` — true, since `A` is indeed the owner — and never checks that `msg.sender` (`B`) is `A`, approved, or an operator.
4. The `transfer_nft` CosmWasm message executes, and the NFT is now owned by `B`, despite `B` never having been granted approval by `A`. [1](#0-0)

    function getApproved(uint256 tokenId) public view override returns (address) {
        string memory tId = _formatPayload("token_id", _doubleQuotes(Strings.toString(tokenId)));

        return address(0);

    function isApprovedForAll(address owner_, address operator) public view override returns (bool) {
        string memory o = _formatPayload("owner", _doubleQuotes(AddrPrecompile.getSeiAddr(owner_)));
        string memory req = _curlyBrace(_formatPayload("all_operators", _curlyBrace(o)));
        bytes memory response = WasmdPrecompile.query(Cw721Address, bytes(req));
        bytes[] memory approvals = JsonPrecompile.extractAsBytesList(response, "operators");
        for (uint i=0; i<approvals.length; i++) {
            bytes memory op = JsonPrecompile.extractAsBytes(approvals[i], "spender");
            if (AddrPrecompile.getEvmAddr(string(op)) == operator) {
                return true;
            }
        }
        return false;
    }
