## Analysis

Mapping the report's broken invariant onto GitHub Desktop: the swap-pool bug ties a security restriction (deposit cool-off) to a *fungible identity* (an address) rather than to the underlying resource state, so transferring the resource to a fresh identity resets the restriction. The structural analog in GitHub Desktop is the "unsafe repository" (Git's dubious-ownership) trust decision, which is likewise bound to a mutable identity — a filesystem **path** — rather than to the actual owner/content of the resource that triggered the warning, and once approved that trust is permanent and global.

### Title
Permanent, path-only `safe.directory` trust exception allows a different/attacker-controlled repository placed at a previously-trusted path to silently bypass the dubious-ownership warning - (File: `app/src/lib/git/config.ts`)

### Summary
When Desktop detects an "unsafe" (dubious ownership) repository, the user can click "Trust Repository", which calls `addSafeDirectory(path)` [1](#0-0) . This permanently appends the literal path string to the global `safe.directory` git config via `addGlobalConfigValueIfMissing('safe.directory', path)` [2](#0-1) . The trust is keyed purely on the path string, with no binding to the directory's owner, inode, or content at the time of approval, and it is never revoked or re-checked.

### Finding Description
`getRepositoryType` treats a repository as `unsafe` only by parsing git's `dubious ownership` error, and as soon as the exact same path is present in `safe.directory`, Git (and thus Desktop) will always treat any content later placed at that path as trusted, skipping the ownership check entirely [3](#0-2) . `MissingRepository.cloneAgain` clones using `gitHubRepository.cloneURL`, an attribute originating from the GitHub API response for the repository object, into `this.props.repository.path` — the exact path previously recorded for the repository [4](#0-3) . If that path was ever approved once (e.g., the repository lived on a network share, external volume, or corporate-managed home directory where ownership metadata legitimately differed at some point), the trust exception persists indefinitely in the user's global gitconfig. Because trust is keyed only on the path and never re-validated against current ownership or content, any new/different content that later ends up at that exact path (via `cloneAgain`'s use of an API-supplied `cloneURL`, via `AddExistingRepository`/`_relocateRepository` re-pointing to it, or simply re-cloning into a recycled path) inherits the pre-existing trust and is exempted from the "may automatically execute files in the repository" warning shown in `add-existing-repository.tsx` and `missing-repository.tsx` [5](#0-4) .

This mirrors the report's flaw precisely: the safeguard is meant to gate a specific, currently-owned resource, but it is implemented as a durable allowlist entry against a mutable identifier (path ≈ address), so swapping out the underlying resource silently carries over the approval — the identical class of "bypass via transferring/re-populating the tracked identity" described in the LP-token cool-off report.

### Impact Explanation
Once bypassed, Git will run without ownership protections against the newly-placed repository content at the trusted path, which can lead to execution of repository-controlled configuration/hooks (e.g., `core.fsmonitor`, `core.hooksPath`, filter/clean/smudge drivers) that the dubious-ownership check exists specifically to block. This constitutes code execution driven by attacker-controlled repository content that the user never explicitly re-approved, an impact category the task classifies as valid (code execution from an attacker-controlled cloned/fetched repository or GitHub API object).

### Likelihood Explanation
Likelihood is moderated by the precondition that the exact path must have been trusted at some earlier point (common on shared machines, mounted/network drives, restored disk images, or reused temp/workspace directories) and that a subsequent clone/redirect targets that same path — both of which occur naturally through normal Desktop flows (`cloneAgain`, `_relocateRepository`, re-adding an existing directory) without requiring any unusual user action beyond the single, expected "Trust Repository" click the UI already prompts for.

### Recommendation
Bind the `safe.directory` trust decision to something that identifies the specific resource instance rather than only the path — e.g., re-validate current filesystem ownership at every git invocation (which Git already does) is not sufficient because Desktop's own flows never re-surface the warning once the path is globally allowlisted; instead, avoid indefinite/global `safe.directory` entries for paths outside of stable, user-owned locations, prompt again when previously-`missing`/re-created content is detected at a trusted path, and/or scope trust exceptions narrowly (e.g., `--local` per-clone rather than `--global`) so that reusing a path for new content does not silently inherit prior trust.

### Proof of Concept
1. On a machine where a repository directory legitimately triggers Git's dubious-ownership detection (e.g., a mounted volume or shared workspace path), add the repository in Desktop and click "Trust Repository", invoking `addSafeDirectory(path)` [1](#0-0)  which globally allowlists that exact path in `safe.directory` [6](#0-5) .
2. Remove/replace the directory contents at that same path with a different, attacker-controlled repository (e.g., via `cloneAgain` using an API-supplied `cloneURL` pointing elsewhere, or by re-adding an existing directory at the same location) [4](#0-3) .
3. Reopen the repository in Desktop: `getRepositoryType` no longer reports `unsafe` for this path because `safe.directory` already contains it [3](#0-2) , so the ownership/ "may automatically execute files" warning is never shown for the new, attacker-controlled content, and any hook/config-driven behavior it defines executes as if fully trusted.

      return
    }

    if (!cloneURL) {
      return
    }

        this.props.repository.path
      )
    } catch (error) {

/**
 * Adds a path to the `safe.directories` configuration variable if it's not
 * already present. Adding a path to `safe.directory` will cause Git to ignore
 * if the path is owner by a different user than the current.
 */
export async function addSafeDirectory(path: string) {
  // UNC-paths on Windows need to be prefixed with `%(prefix)/`, see
  // https://github.com/git-for-windows/git/commit/e394a16023cbb62784e380f70ad8a833fb960d68
  if (__WIN32__ && path[0] === '/') {
    path = `%(prefix)/${path}`
  }

  await addGlobalConfigValueIfMissing('safe.directory', path)
}

export async function getRepositoryType(path: string): Promise<RepositoryType> {
  if (!(await directoryExists(path))) {
    return { kind: 'missing' }
  }

  try {
    const result = await git(
      ['rev-parse', '--is-bare-repository', '--show-cdup', '--git-dir'],
      path,
      'getRepositoryType',
      { successExitCodes: new Set([0, 128]) }
    )

    if (result.exitCode === 0) {
      // Bare repositories will not include gitdir so we handle that separately
      if (result.stdout.startsWith('true\n')) {
        return { kind: 'bare' }
      }

      // --is-bare-repository and --show-cdup each produce a single line but
      // --git-dir could theoretically contain newlines so we parse the known
      // fields first and treat the remainder as the git dir. We use [\s\S]*
      // instead of .* for the git dir capture group because .* doesn't match
      // newlines whereas [\s\S]* matches any character including newlines.
      const match = result.stdout.match(/^(true|false)\n(.*)\n([\s\S]*)\n$/)

      if (match) {
        const [, isBare, cdup, gitDir] = match

        return isBare === 'true'
          ? { kind: 'bare' }
          : {
              kind: 'regular',
              topLevelWorkingDirectory: resolve(path, cdup),
              gitDir: resolve(path, gitDir),
            }
      }
    }

    const unsafeMatch =
      /fatal: detected dubious ownership in repository at '(.+)'/.exec(
        result.stderr
      )
    if (unsafeMatch) {
      return { kind: 'unsafe', path: unsafeMatch[1] }
    }

    return { kind: 'missing' }
