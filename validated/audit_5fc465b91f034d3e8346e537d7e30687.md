## Title
Missing ownership/permission check on Data Layer mirror coin creation allows any spend-bundle submitter to force victim Data Layer nodes to connect to attacker-controlled URLs - (File: chia/wallet/db_wallet/db_wallet_puzzles.py)

### Summary
The Jenkins ThreadFix advisory (GHSA-77vq-4j66-46m5 / CVE-2022-34210) describes a missing permission check that lets a low-privilege caller make the server connect to an attacker-specified URL. The Chia Data Layer "mirror" mechanism has an analogous missing-authorization defect: the on-chain puzzle used to register a mirror URL for a store (`create_mirror_puzzle()`) does not verify that the spender is the owner of the referenced `launcher_id`/store. Any unprivileged party who can get a spend bundle into the mempool can create a mirror record for **any** store id, embedding arbitrary attacker-controlled URLs, and every peer that subscribes to that store will automatically make outbound HTTP requests to those URLs.

### Finding Description
`create_mirror_puzzle()` curries `P2_PARENT` with `Program.to(1)`: [1](#0-0) 

This is an "anyone-can-spend"-style puzzle: the mirror coin's identity/URL binding is derived purely from the `CREATE_COIN` condition's memo field (`launcher_id`, `urls`), not from any signature or relationship to the singleton owner: [2](#0-1) 

The wallet-side `create_new_mirror()` simply creates a standard coin to `create_mirror_puzzle().get_tree_hash()` with the target `launcher_id` and URLs stuffed into memos — there is no on-chain assertion that the spender actually owns or controls the `launcher_id` singleton being mirrored: [3](#0-2) 

When any node observes a coin sent to the mirror puzzle hash, it unconditionally decodes the `launcher_id` and `urls` from the parent spend and, if that `launcher_id` is tracked locally, records it as a mirror for that store — again with no ownership check tying the coin creator to the actual store owner: [4](#0-3) 

Once recorded, the `update_subscriptions_from_wallet()` / `fetch_and_validate()` sync loop pulls these attacker-supplied URLs and issues outbound HTTP requests (including plugin downloader/uploader POST calls) to them without further gating: [5](#0-4) [6](#0-5) [7](#0-6) 

The `.cursor/context/data-layer.md` notes explicitly flag mirror/plugin URLs as "external trust inputs," confirming this is a recognized trust boundary, but the boundary is only enforced at the file-content-validation layer, not at the mirror-registration/ownership layer: [8](#0-7) 

### Impact Explanation
Any actor able to submit a spend bundle to the mempool (no special permission or wallet ownership of the target store required) can create a "mirror" coin naming an arbitrary victim `launcher_id` and arbitrary attacker-controlled URLs. Every Data Layer node subscribed to that store will then automatically issue outbound HTTP requests (GET for delta/full-tree files, and POST for uploader/downloader plugin calls) to attacker infrastructure. This is a server-side request forgery primitive directly analogous to the Jenkins CVE's "missing permission check allows connection to attacker-specified URL": in both cases, an entity lacking the intended authority (Overall/Read-only Jenkins user vs. an arbitrary chain participant with no relationship to the store) triggers an outbound network connection controlled by attacker input. It can be used for internal network probing/SSRF against Data Layer operators, resource exhaustion via repeated failed connection attempts, or exfiltration of node metadata (store id, url path) to attacker-controlled endpoints, though it does not directly cause coin-set divergence, forged asset identity, or fund loss.

### Likelihood Explanation
Likelihood is moderate-to-high: creating the mirror coin only requires a standard coin spend to a well-known, publicly-computable puzzle hash with a small amount and fee — no relationship to the target `launcher_id`'s owner key is needed. The only friction is that the victim node must currently be tracking/subscribed to the targeted `store_id`, which is common for popular public Data Layer stores.

### Recommendation
Add an authorization/ownership check before honoring a mirror record: either require the mirror-creation puzzle to prove control of the singleton's current owner key (e.g., via a puzzle-announcement or signature tied to the singleton's inner puzzle), or have `DataLayerWallet.coin_added()` / `get_mirrors_for_launcher()` verify that the mirror coin's parent spend was authorized by the store's actual singleton owner before persisting/using the URL, and rate-limit or sandbox outbound fetches triggered by unauthenticated mirror data.

### Proof of Concept
1. Attacker identifies a public `launcher_id` (store id) that victim Data Layer nodes subscribe to.
2. Attacker constructs and broadcasts a standard coin spend that creates a coin with puzzle hash `create_mirror_puzzle().get_tree_hash()` and a `CREATE_COIN` condition whose memo is `[launcher_id, b"http://attacker.example/exfil"]`, per the format expected by `get_mirror_info()`: [2](#0-1) 
3. Once confirmed, any victim node tracking `launcher_id` records this as a legitimate mirror via `coin_added()`: [4](#0-3) 
4. On the next sync cycle, the victim's `update_subscriptions_from_wallet()`/`fetch_and_validate()` loop issues outbound HTTP requests to `http://attacker.example/exfil`: [5](#0-4)

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
    async def coin_added(
        self, coin: Coin, height: uint32, peer: WSChiaConnection, coin_data: object | None, sync_scope: WalletSyncScope
    ) -> None:
        if coin.puzzle_hash == create_mirror_puzzle().get_tree_hash():
            parent_state: CoinState = (
                await self.wallet_state_manager.wallet_node.get_coin_state([coin.parent_coin_info], peer=peer)
            )[0]
            parent_spend = await fetch_coin_spend(height, parent_state.coin, peer)
            assert parent_spend is not None
            launcher_id, urls = get_mirror_info(parent_spend.puzzle_reveal, parent_spend.solution)
            # Don't track mirrors with empty url list.
            if not urls:
                return
            if await self.wallet_state_manager.dl_store.is_launcher_tracked(launcher_id):
                ours: bool = await self.wallet_state_manager.get_wallet_for_coin(coin.parent_coin_info) is not None
                await self.wallet_state_manager.dl_store.add_mirror(
                    Mirror(
                        coin.name(),
                        launcher_id,
                        uint64(coin.amount),
                        Mirror.decode_urls(urls),
                        ours,
                        height,
                    )
                )
                await self.wallet_state_manager.add_interested_coin_ids([coin.name()])
```

```python
    async def get_downloader(self, store_id: bytes32, url: str) -> PluginRemote | None:
        request_json = {"store_id": store_id.hex(), "url": url}
        for d in self.downloaders:
            async with aiohttp.ClientSession() as session:
                try:
                    async with session.post(
                        d.url + "/handle_download",
                        json=request_json,
                        headers=d.headers,
                        timeout=self.client_timeout,
                    ) as response:
                        res_json = await response.json()
                        if res_json["handle_download"]:
                            return d
                except Exception as e:
```
