### Title
Unbounded gas-cost loop in `CW721ERC721Pointer.balanceOf()` enables DoS via NFT-count griefing - (File: `contracts/src/CW721ERC721Pointer.sol`)

### Summary
The Sei EVM↔CosmWasm CW721 pointer contract implements `balanceOf()` by paging through the underlying CW721 contract's `tokens` query in batches of 1000 and looping until a terminator response is returned, with no upper bound on the number of pages traversed. Because the number of tokens a Sei address can hold in the wrapped CW721 collection is fully attacker-controlled (via minting or simply receiving transfers), any caller can inflate the iteration count arbitrarily, turning a single `balanceOf()` call — a function other contracts and the EVM commonly rely on — into an unbounded-gas operation. This mirrors the `_calculateClaimableAmount()` DoS pattern in the source report: an attacker-growable list that is fully iterated in a single call with no cap.

### Finding Description
`balanceOf()` performs an on-chain `while` loop, driven entirely by CosmWasm precompile query responses, that never terminates based on gas or iteration count — only on exhausting the token list: [1](#0-0) 

Each iteration issues a `WasmdPrecompile.query` call (a CosmWasm query invoked from the EVM via the wasmd precompile) and a `JsonPrecompile.extractAsBytesList` call to parse up to 1000 token IDs, then continues with a new `start_after` cursor. The loop only stops when the CW721 contract eventually returns an empty `tokens` list. There is no limit on the number of pages that will be traversed.

The number of tokens owned by any given Sei address in the underlying CW721 collection is not bounded by this contract — it is set by whatever minting/transfer logic the wrapped CW721 contract allows, which for public collections is attacker-reachable (mint many tokens to a single address, or transfer many low-value tokens into a victim's address to "grief" their balance). Once an address holds enough tokens (e.g., tens or hundreds of thousands), a single call to `balanceOf()` on the ERC721 pointer requires a correspondingly large number of expensive precompile query round-trips, each of which performs work in the Cosmos/CosmWasm layer (JSON marshal/unmarshal, store iteration) in addition to consuming EVM gas for the ABI/JSON glue.

### Impact Explanation
`balanceOf()` is one of the most heavily relied-upon and frequently invoked ERC721 methods — used by wallets, marketplaces, and other smart contracts. If it becomes gas-prohibitive or reverts with out-of-gas for a specific address (whether the attacker's own address, used to disrupt a protocol they interact with, or a victim's address they grief by sending many worthless NFTs to it), any downstream contract logic gated on `balanceOf()` for that address is effectively frozen. This satisfies the "crash/DoS of a critical operation reachable by any user" impact bar: functionality that depends on this pointer contract's `balanceOf()` can be permanently denied for the targeted address without any privileged action, matching the class of bug described in the source report (unbounded, attacker-growable collection iterated to completion in one call).

### Likelihood Explanation
Likelihood is high: minting or acquiring/transferring a large quantity of CW721 tokens to a target address requires no special privileges beyond normal CW721 mint/transfer permissions of the wrapped collection, and many CW721 collections allow public minting or at least permit anyone to transfer arbitrarily many tokens into another address. No governance, validator, or operator action is needed — a single unprivileged actor with a wasm contract entrypoint (mint) or ordinary CW721 transfer messages can set this up over time or in a batch of transactions, after which any subsequent `balanceOf()` call for the address becomes prohibitively expensive.

### Recommendation
Bound `balanceOf()`'s work: either cap the total number of pages/tokens scanned and revert (or return a best-effort/capped value) beyond a fixed limit, or avoid recomputing balance via full enumeration entirely — e.g., maintain a counter incremented/decremented on transfer/mint/burn events surfaced through the pointer's own state rather than re-deriving it by paginated CW721 queries on every call.

### Proof of Concept
1. Deploy (or use an existing) CW721 collection that permits public/attacker minting, then create/obtain its ERC721 pointer via the sei-chain pointer registry (`SetCW721ERC721Pointer` / `UpsertERCCW721Pointer` flow).
2. As the attacker, mint (or otherwise cause to be transferred) a very large number of tokens (e.g., 100,000+) to a chosen address `V` in the underlying CW721 contract — this requires only ordinary CW721 `Mint`/`TransferNft` messages, no special privilege.
3. Call `CW721ERC721Pointer.balanceOf(V)`. The Solidity code at [2](#0-1)  will loop once per 1000 tokens owned, issuing a wasmd precompile query and JSON extraction each iteration; with 100,000 tokens this is 100+ round trips within a single EVM call, consuming gas proportional to the attacker-chosen token count, with no cap — causing the call to run out of gas or take excessive processing time for any contract or off-chain client depending on it.

    function balanceOf(address owner_) public view override returns (uint256) {
        if (owner_ == address(0)) {
            revert ERC721InvalidOwner(address(0));
        }
        uint256 numTokens = 0;
        string memory startAfter;
        string memory qb = string.concat(
            string.concat("\"limit\":1000,\"owner\":\"", AddrPrecompile.getSeiAddr(owner_)),
            "\""
        );
        bytes32 terminator = keccak256("{\"tokens\":[]}");

        bytes[] memory tokens;
        uint256 tokensLength;
        string memory req = string.concat(string.concat("{\"tokens\":{", qb), "}}");
        bytes memory response = WasmdPrecompile.query(Cw721Address, bytes(req));
        while (keccak256(response) != terminator) {
            tokens = JsonPrecompile.extractAsBytesList(response, "tokens");
            tokensLength = tokens.length;
            numTokens += tokensLength;
            startAfter = string.concat(",\"start_after\":", string(tokens[tokensLength-1]));
            req = string.concat(
                string.concat("{\"tokens\":{", string.concat(qb, startAfter)),
                "}}"
            );
            response = WasmdPrecompile.query(Cw721Address, bytes(req));
        }
        return numTokens;
    }
