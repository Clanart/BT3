### Title
`associatePubKey` permissionlessly binds Sei⇄EVM identity from a bare public key with no private-key challenge - ([File: precompiles/addr/addr.go])

### Summary
The `addr` precompile exposes two ways to link an EVM address to a Sei address: `associate`, which requires a v/r/s ECDSA signature over a caller-chosen message (proving possession of the private key), and `associatePubKey`, which accepts only a raw secp256k1 public key and performs **no signature/challenge check** before calling `associateAddresses`. This mirrors CVE‑2023‑42818: an authentication/identity-binding path that trusts a presented public key without proving the caller controls the corresponding private key.

### Finding Description
`associatePublicKey` in [1](#0-0)  takes a single hex-encoded compressed public key argument, parses it with `btcec.ParsePubKey`, derives `evmAddr`/`seiAddr` from it via `helpers.GetAddressesFromPubkeyBytes`, and immediately calls `p.associateAddresses(...)` — with **no signature, no message challenge, and no proof that the transaction sender actually owns the private key** for that public key. Contrast this with `associate` at [2](#0-1) , which requires the caller to supply v/r/s over a message and recovers the pubkey from that signature — i.e., a real challenge-response proof of key possession.

`associateAddresses` then unconditionally performs privileged state mutations for the derived `seiAddr`/`evmAddr` pair via `AssociateAddresses` in [3](#0-2) :
- Sets the account's on-chain pubkey if unset (`acc.SetPubKey(pubkey)`), and may adopt/reuse the "cast" account's account number/sequence (lines 36-41).
- Calls `p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)`.
- Calls `MigrateBalance`, which moves all spendable coins and wei balance from the direct-cast shadow address `sdk.AccAddress(evmAddr[:])` into the real `seiAddr`, and removes the cast account ( [4](#0-3) ).

Since a Cosmos SDK account's public key becomes public as soon as it signs any transaction (it is embedded in the tx and stored on-chain), **any unprivileged third party can harvest a victim's already-revealed public key and call `associatePubKey` on the victim's behalf**, forcing the association and balance migration to occur before the victim ever submits an EVM transaction. The maintainers' own comment in the ante handler acknowledges the danger of unauthenticated pubkey-based association: `x/evm/ante/preprocess.go` lines 103-110 explicitly pre-associates EIP‑7702 authorization authorities to prevent "a later `associatePubKey` call [remapping]" a direct-cast identity and "orphaning any staking/distribution state created under the direct-cast identity (which can then halt the chain via the distribution validator-removal hook)." [5](#0-4)  That fix only covers the narrow EIP‑7702 authority case reachable inside `AnteHandle`; the general-purpose `associatePubKey` precompile entry point itself still allows anyone to force an association/migration for an arbitrary victim's public key with zero proof of key possession, at any time, for any account that has accrued state (staking, distribution, or a "cast" account with balance) under its direct-cast identity.

### Impact Explanation
Because both `evmAddr` and `seiAddr` are deterministically re-derived from the *same* submitted public key, an attacker cannot redirect a victim's funds to an address they control — this rules out direct theft via this specific call. However, this is still a real integrity violation of an authentication-style primitive: an unprivileged caller can force a security-relevant state transition (identity binding + balance migration + account-number/sequence adoption + pubkey-on-chain commitment) for a victim account **without the victim's consent or participation**, purely from a public key the victim never intended to have used for EVM linkage. The project's own in-code warning confirms that premature/uncontrolled association triggered this way can orphan staking/distribution state tied to a direct-cast identity and can "halt the chain via the distribution validator-removal hook" — i.e., a validator halt / chain-halt class impact, which is explicitly in-scope per the finding's severity ceiling.

### Likelihood Explanation
Likelihood is moderate: exploitation requires only knowledge of a target's already-revealed Cosmos secp256k1 public key (trivially obtainable from any prior signed transaction by that account, which is on-chain and public) and a single unprivileged call to the `associatePubKey` precompile function (selector `AssociatePubKey`) via any EVM transaction — no special permissions, staking, or contract deployment needed.

### Recommendation
Require the same challenge-response proof used by `associate` (a signature over a fresh/replay-protected message) before accepting a bare public key in `associatePubKey`, or otherwise gate/rate-limit forced pre-association of accounts holding staking/distribution state so that a third party cannot unilaterally trigger the account/state transitions described above without the key holder's participation.

### Proof of Concept
1. Observe any Sei account's Cosmos public key from a previously broadcast/signed transaction (public key is included in on-chain tx data per Cosmos SDK signing).
2. As an unrelated unprivileged caller, submit an EVM transaction invoking `addr.associatePubKey(<victim_compressed_pubkey_hex>)` on precompile `0x1004`.
3. Observe from `precompiles/addr/addr.go` `associatePublicKey`/`associateAddresses` that no signature check occurs — the call succeeds, forcing `SetAddressMapping`, on-chain pubkey commitment, and `MigrateBalance` for the victim's derived `seiAddr`/`evmAddr` pair, all without the victim submitting or authorizing any transaction themselves.

func (p PrecompileExecutor) associate(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}

	// v, r and s are components of a signature over the customMessage sent.
	// We use the signature to construct the user's pubkey to obtain their addresses.
	v := args[0].(string)
	r := args[1].(string)
	s := args[2].(string)
	customMessage := args[3].(string)

	rBytes, err := decodeHexString(r)
	if err != nil {
		return nil, 0, err
	}
	sBytes, err := decodeHexString(s)
	if err != nil {
		return nil, 0, err
	}
	vBytes, err := decodeHexString(v)
	if err != nil {
		return nil, 0, err
	}

	vBig := new(big.Int).SetBytes(vBytes)
	rBig := new(big.Int).SetBytes(rBytes)
	sBig := new(big.Int).SetBytes(sBytes)

	// Derive addresses
	vBig = new(big.Int).Add(vBig, utils.Big27)

	customMessageHash := crypto.Keccak256Hash([]byte(customMessage))
	evmAddr, seiAddr, pubkey, err := helpers.GetAddresses(vBig, rBig, sBig, customMessageHash)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p PrecompileExecutor) associatePublicKey(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}

	// Takes a single argument, a compressed pubkey in hex format, excluding the '0x'
	pubKeyHex := args[0].(string)

	pubKeyBytes, err := hex.DecodeString(pubKeyHex)
	if err != nil {
		return nil, 0, err
	}

	// Parse the compressed public key
	pubKey, err := btcec.ParsePubKey(pubKeyBytes)
	if err != nil {
		return nil, 0, err
	}

	// Convert to uncompressed public key
	uncompressedPubKey := pubKey.SerializeUncompressed()

	evmAddr, seiAddr, pubkey, err := helpers.GetAddressesFromPubkeyBytes(uncompressedPubKey)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}
