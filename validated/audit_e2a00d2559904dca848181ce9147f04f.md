### Title
PlotNFT `melt` allows destroying the pooling singleton while unclaimed pool rewards remain, permanently stranding those funds - (File: chia/pools/plotnft_drivers.py)

### Summary
This is a structural analog of the OpenQ finding: a privileged/local "close" action (there: `closeOngoing()`, here: `melt_plotnft`/`PlotNFT.melt()`) transitions a stateful contract/singleton to a terminal state without checking whether outstanding value tied to that state still exists and is claimable only through it.

### Finding Description
`PlotNFT.melt()` in `chia/pools/plotnft_drivers.py` only guards against melting while actively pooling: [1](#0-0) 

It performs no check for unclaimed pool reward coins sent to the plot NFT's `p2_singleton_puzzle_hash`. `melt_plotnft()` in `chia/wallet/plotnft_wallet/plotnft_wallet.py` calls `plotnft.melt(...)` directly and immediately spends the singleton coin with the `-113` melt condition: [2](#0-1) 

Pool reward coins (self-pooling farming rewards paid to the p2-singleton puzzle hash) can only be claimed through `claim_rewards()`, which requires spending the still-live plotnft singleton to authorize the reward-coin spends via `PoolReward.solve()` / `singleton_action_spend`: [3](#0-2) [4](#0-3) 

Once the singleton is melted, the singleton coin (and its inner puzzle hash used as the authorization anchor for `PoolReward`) no longer exists, so any not-yet-claimed reward coin sitting at the p2-singleton puzzle hash can never be spent again — there is no other path to claim it, since the reward puzzle's `SingletonMember` restriction is bound to the specific singleton identity.

### Impact Explanation
This matches the report's root cause exactly: a "close"/terminal state transition is permitted while claimable balance still exists in the position, permanently stranding funds. Any self-pooling farmer with unclaimed farming rewards who melts (or is prompted by CLI tooling to melt) their plot NFT before calling `claim_rewards()` will permanently lose those reward coins, since the only spend path for `PoolReward` coins requires proof of authorization from the (now-destroyed) singleton.

### Likelihood Explanation
Melting is a legitimate wallet-level user operation (`plotnft melt` CLI / `plotnft_melt` RPC), reachable by any wallet owner without needing malicious peers, and there is no automated ordering enforced between reward-claim and melt (they are entirely independent RPC calls). A user simply forgetting to run `claim_rewards()` before `melt_plotnft()` — e.g., because they just switched to self-pooling and immediately decided to melt, or farming rewards land between checking and melting — triggers permanent fund loss. This is a plausible, easily-triggered operator mistake rather than a contrived edge case.

### Recommendation
Before allowing `PlotNFT.melt()` / `melt_plotnft()` to proceed, check for any unclaimed pool reward coins associated with the plot NFT's `p2_singleton_puzzle_hash` (e.g., via `plotnft2_store.get_pool_rewards(plotnft_id=...)`) and reject the melt (or require the caller to pass an explicit override) if any unclaimed rewards remain, mirroring the recommended fix of requiring a zero remaining balance before allowing a terminal "close" transition.

### Proof of Concept
1. Create a v2 PlotNFT and set it to self-pooling.
2. Farm blocks so that pool reward coins accumulate at `p2_singleton_puzzle_hash` (tracked via `plotnft2_store.add_pool_reward`), as exercised in [5](#0-4) .
3. Instead of calling `claim_rewards()`, call `melt_plotnft()` (or the CLI `plotnft melt` command / `plotnft_melt` RPC, see [6](#0-5) ) to spend the singleton with the melt condition.
4. The singleton coin is destroyed and the wallet's PlotNFT2Wallet is deleted (`delete_self`), while the reward coin(s) at `p2_singleton_puzzle_hash` remain unspent on-chain with no remaining authorization path, permanently stranding the funds.

Note: I was not able to fully trace every CLVM-level detail of the `SingletonMember` restriction proof requirement (e.g., exact puzzle reveal validation inside the compiled CLVM module) within the available index; this assessment is based on the Python driver code and wallet logic shown above, which strongly indicates the reward-claim path is singleton-dependent.

    async def claim_rewards(
        self,
        *,
        action_scope: WalletActionScope,
        fee: uint64 = uint64(0),
        extra_conditions: tuple[Condition, ...] = tuple(),
    ) -> None:
        rewards_to_claim = await self.wallet_state_manager.plotnft2_store.get_pool_rewards(plotnft_id=self.plotnft_id)
        if len(rewards_to_claim) == 0:
            raise ValueError("No rewards to claim")
        total_reward_amount = uint64(sum(reward.coin.amount for reward in rewards_to_claim))
        if fee > total_reward_amount:
            raise ValueError("Fee is greater than the total amount of rewards")

        plotnft = await self.get_current_plotnft()
        coin_spends = plotnft.claim_pool_rewards(
            rewards_to_claim=rewards_to_claim,
            reward_delegated_puzzles_and_solutions=[
                DelegatedPuzzleAndSolution(
                    puzzle=self.xch_wallet.make_solution(
                        primaries=[
                            CreateCoin(
                                puzzle_hash=self.rewards_claim_puzhash,
                                amount=uint64(total_reward_amount - fee),
                            ),
                        ],
                        fee=fee,
                        conditions=(*extra_conditions, CreateCoinAnnouncement(b""))
                        if len(rewards_to_claim) > 1
                        else extra_conditions,
                    ).at("rf"),  # strips away to just the delegated puzzle (bit of a hack)
                    solution=Program.to(None),
                )
                if i == 0
                else DelegatedPuzzleAndSolution(
                    puzzle=Program.to(
                        (
                            1,
                            [
                                AssertCoinAnnouncement(
                                    asserted_id=rewards_to_claim[0].coin.name(), asserted_msg=b""
                                ).to_program()
                            ],
                        )
                    ),
                    solution=Program.to(None),
                )
                for i, reward in enumerate(rewards_to_claim)

    async def melt_plotnft(
        self,
        *,
        action_scope: WalletActionScope,
        fee: uint64 = uint64(0),
        extra_conditions: tuple[Condition, ...] = tuple(),
    ) -> None:
        plotnft = await self.get_current_plotnft()
        fee_hook = CreateCoinAnnouncement(msg=b"", coin_id=plotnft.coin.name())
        coin_spends = plotnft.melt(extra_conditions=(fee_hook, *extra_conditions))
        if fee > 0:
            await self.xch_wallet.create_tandem_xch_tx(
                fee=fee,
                action_scope=action_scope,
                extra_conditions=(fee_hook.corresponding_assertion(),),
            )

        spend_bundle = WalletSpendBundle(coin_spends, G2Element())
        async with action_scope.use() as interface:
            interface.side_effects.transactions.append(
                self.wallet_state_manager.new_outgoing_transaction(
                    wallet_id=self.id(),
                    puzzle_hash=bytes32.zeros,
                    amount=uint64(1),
                    fee=fee,
                    spend_bundle=spend_bundle,
                    additions=[],
                    removals=[plotnft.coin],
                    name=spend_bundle.name(),
                    extra_conditions=extra_conditions,
                )
            )
