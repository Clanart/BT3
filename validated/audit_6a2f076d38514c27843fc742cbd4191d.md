### Title
Unauthenticated `InternalSendTx` broadcast on the aggregator's public gRPC port when `client_verification=false` - ([File: core/src/rpc/interceptors.rs])

### Summary
The `Internal*`-prefixed RPC naming convention is meant to restrict calls to the entity's own client certificate (`our_cert`), enforced only inside `only_aggregator_and_self` via the `is_internal` check. When an entity (including the aggregator) is started with `client_verification=false`, `create_grpc_server` installs `Interceptors::Noop` instead, which performs zero caller-identity checks — including no TLS peer-certificate requirement at all — letting any unauthenticated caller invoke `ClementineAggregator::internal_send_tx`.

### Finding Description
Binding: `caller reaching InternalSendTx == our_cert (aggregator's own client certificate)`, as enforced by `is_internal`/`only_aggregator_and_self` in [1](#0-0)  and [2](#0-1) .

This binding is only checked when `Interceptors::OnlyAggregatorAndSelf` is the active interceptor. `create_grpc_server`, used identically for verifier, operator, *and* aggregator servers, selects the interceptor purely from `config.client_verification`: [3](#0-2) 

`create_aggregator_grpc_server` routes through this same generic `create_grpc_server`, and explicitly warns that when `client_verification` is left `false` (the documented supported mode for the aggregator), no interceptor enforcement exists: [4](#0-3) 

The docs confirm this is the intended aggregator deployment posture: "The aggregator does not enforce client certificates but does use TLS for encryption," i.e. `Noop` is expected to be used for the aggregator. In that mode, `is_internal` is never consulted because `Noop::call` simply returns `Ok(req)` unconditionally: [5](#0-4) .

`internal_send_tx` itself performs no additional authorization check — it deserializes the attacker-supplied raw transaction and unconditionally enqueues it into the tx-sender's broadcast/fee-bump queue: [6](#0-5) . `TxSenderClient::insert_try_to_send` performs no validation that the transaction is part of the bridge's presigned transaction graph — it only deduplicates by txid and persists it for the background sender loop to broadcast/fee-bump: [7](#0-6) .

Exploit: an attacker with only network access to the aggregator's gRPC port, no TLS client certificate, constructs any `SendTxRequest{raw_tx, fee_type}` (e.g. a syntactically valid but arbitrary transaction, or a fee_type of `Cpfp`/`Rbf` causing the aggregator to spend its own UTXOs for fee-bumping) and calls `InternalSendTx` directly. There is no check that the caller is the aggregator itself.

### Impact Explanation
This matches the defined High-severity category "an unauthenticated state-changing or broadcasting call": any unprivileged network caller can force the aggregator's tx-sender to accept and attempt to broadcast/fee-bump an arbitrary transaction, without needing a client certificate, a verifier/operator identity, or protocol participation. Repeatable per call, not scoped to a specific deposit or operator, and works against every aggregator instance deployed with `client_verification=false` — a state the codebase itself documents and supports.

### Likelihood Explanation
Requires the aggregator to be run with `client_verification=false` (non-default; default `BridgeConfig` sets `client_verification: true`, but this mode is explicitly documented and supported for the aggregator specifically). Given that precondition, exploitation costs nothing beyond a gRPC call with a syntactically valid transaction — no BTC, no fees, no privileged role — and is fully repeatable.

### Recommendation
Do not rely solely on `client_verification` to gate `Internal*` methods. Enforce `is_internal` semantics unconditionally for `Internal*`-prefixed RPCs regardless of the `Noop`/`OnlyAggregatorAndSelf` selection (e.g., always require the caller's leaf certificate to equal `our_cert` for any method matching the `Internal` prefix, independent of `client_verification`), or reject `Internal*` calls entirely when TLS peer certificates are unavailable.

pub async fn create_aggregator_grpc_server(
    config: BridgeConfig,
) -> Result<(std::net::SocketAddr, oneshot::Sender<()>), BridgeError> {
    let addr: std::net::SocketAddr = format!("{}:{}", config.host, config.port)
        .parse()
        .wrap_err("Failed to parse address")?;
    let aggregator_server = AggregatorServer::new(config.clone()).await?;
    aggregator_server.start_background_tasks().await?;

    let svc = ClementineAggregatorServer::new(aggregator_server)
        .max_encoding_message_size(config.grpc.max_message_size)
        .max_decoding_message_size(config.grpc.max_message_size);

    if config.client_verification {
        tracing::warn!("Client verification is enabled on aggregator gRPC server",);
    }

    let (server_addr, shutdown_tx) =
        create_grpc_server(addr.into(), svc, "Aggregator", &config).await?;

    match server_addr {
        ServerAddr::Tcp(socket_addr) => Ok((socket_addr, shutdown_tx)),
        _ => Err(BridgeError::ConfigError("Expected TCP address".into())),
    }
}

    pub async fn insert_try_to_send(
        &self,
        dbtx: &mut crate::TxSenderTransaction,
        tx_metadata: Option<TxMetadata>,
        signed_tx: &Transaction,
        fee_paying_type: FeePayingType,
        rbf_signing_info: Option<RbfSigningInfo>,
        cancel_outpoints: &[OutPoint],
        cancel_txids: &[Txid],
        activate_txids: &[ActivatedWithTxid],
        activate_outpoints: &[ActivatedWithOutpoint],
    ) -> Result<u32, BridgeError> {
        let txid = signed_tx.compute_txid();

        // do not add duplicate transactions to the txsender
        let tx_exists = self
            .db
            .check_if_tx_exists_on_txsender(Some(dbtx), txid)
            .await?;
        if let Some(try_to_send_id) = tx_exists {
            return Ok(try_to_send_id);
        }

        tracing::info!(
            "Added tx {} with txid {} to the queue",
            tx_metadata
                .as_ref()
                .map(|data| format!("{:?}", data.tx_type))
                .unwrap_or("N/A".to_string()),
            txid
        );

        let try_to_send_id = self
            .db
            .save_tx(
                dbtx,
                tx_metadata,
                signed_tx,
                fee_paying_type,
                txid,
                rbf_signing_info,
            )
            .await?;
