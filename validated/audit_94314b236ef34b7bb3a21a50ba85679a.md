### Title
PedPoP accepts an identity long-term encryption key, enabling public decryption of that participant's secret shares and forged blame proofs against honest senders - ([File: crypto/dkg/pedpop/src/encryption.rs])

### Summary
Analogous to CVE-2026-73881 (a low-privileged remote party gaining unauthorized read and unauthorized modification of data due to a missing validation check), `Decryption::register` / `EncryptionKeyMessage::read` in `dkg-pedpop` never reject the identity group element as a participant's long-term encryption key (`enc_key`). `Ciphersuite::read_G` enforces only canonical encoding, not non-identity. An unprivileged DKG participant who registers `enc_key = identity` causes every ECDH shared key for messages addressed to them to be the identity point, making the ChaCha20 keystream publicly computable (unauthorized read of all shares sent to them) and making `EncryptionKeyProof`s trivially forgeable by anyone (a DLEq for scalar `0`), enabling false blame against honest senders (unauthorized integrity impact).

### Finding Description
`Encryption::register` inserts `msg.enc_key` into `enc_keys` with only a duplicate-registration assertion, no validity check:

```rust
// crypto/dkg/pedpop/src/encryption.rs
self.enc_keys.insert(participant, msg.enc_key);
```

The field is decoded via `C::read_G`, i.e., `Ciphersuite::read_G` in `crypto/ciphersuite/src/lib.rs`, which rejects non-canonical/invalid encodings but accepts the identity point (the stricter `Curve::read_G` in `crypto/frost/src/curve/mod.rs` that rejects identity is not used by pedpop):

```rust
let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))...;
if point.to_bytes().as_ref() != encoding.as_ref() { Err(...) }
Ok(point)   // identity passes
```

Consequences, both reachable by an unprivileged participant via their commitment/`EncryptionKeyMessage` bytes:

1. **Confidentiality loss.** `encrypt` computes `ecdh(&key, to)` where `to = enc_keys[participant]`; if `to` is identity, the shared point is identity, so `cipher(context, identity)` — a function of only public values — produces the keystream. Every `EncryptedMessage` addressed to that participant is publicly decryptable, exposing the secret shares `f_i(l)` that all other participants send to them.

2. **Forged blame / false slashing.** In `decrypt_with_proof`, the `EncryptionKeyProof` DLEq binds `[G, msg.key]` to `[enc_keys[decryptor], proof.key]`. With `enc_keys[decryptor] = identity`, choosing `proof.key = identity` corresponds to scalar `0` under both generators; `DLEqProof::prove`/`verify` in `crypto/dleq/src/lib.rs` imposes no non-identity checks, so anyone can produce a verifying proof. An accuser (or the malicious participant themselves) can attach this valid proof to any authenticated message sent to that participant; it decrypts to garbage, `blame_internal` then returns `sender`, and the honest sender is faulted (fatal slash in the coordinator flow at `processor/src/key_gen.rs` `VerifyBlame`).

### Impact Explanation
- Unauthorized read: all shares addressed to the malicious participant decrypt publicly, exposing that participant's combined secret share to every observer, weakening the threshold key's security margin.
- Unauthorized modification (integrity): the blame attribution mechanism can be forced to blame an honest `sender` via a forged `EncryptionKeyProof`, aborting the DKG and slashing an honest participant — an incorrect verification outcome reachable entirely from public inputs (`EncryptedMessage` bytes + a forged proof parsed by `EncryptionKeyProof::read`).

### Likelihood Explanation
Any PedPoP participant (or any party able to supply an `EncryptionKeyMessage` attributed to a participant slot in contexts where commitment messages are aggregated) can set `enc_key` to identity; no proof of possession is required for the long-term encryption key — only per-message keys carry a PoP (`pop` on `EncryptedMessage`). The attack requires only publishing crafted bytes during the commitment round; subsequent blame evaluation is deterministic and succeeds for any observer.

### Recommendation
Reject the identity element (and ideally non-torsion-free elements where applicable) for `enc_key` in `EncryptionKeyMessage::read` or `Decryption::register`; equivalently use the identity-rejecting `Curve::read_G` semantics, or add `if enc_key.is_identity() { Err }`. Also consider rejecting identity `msg.key` in `EncryptedMessage::read` for defense in depth.

### Proof of Concept
```rust
// PedPoP on Ristretto, threshold params (t=2, n=3); malicious participant 3.
// 1) Participant 3 broadcasts EncryptionKeyMessage { enc_key: identity, msg: Commitments{...} }.
//    EncryptionKeyMessage::read uses C::read_G (identity accepted); Decryption::register
//    stores identity under participant 3.

// 2) For every share message m_i3 = EncryptedMessage { key: K_i, pop, msg: ct_i } sent to 3,
//    the ECDH shared key is enc_key_3 * k_i = identity for all i, so:
let shared = <Ristretto as Ciphersuite>::G::identity();
let mut cipher = cipher::<Ristretto>(CONTEXT, &Zeroizing::new(shared));
let mut ct = share_msg_bytes.clone();
cipher.apply_keystream(&mut ct); // recovers f_i(3) plaintext for all senders i

// 3) Forged blame against an honest sender 1 who sent a *valid* share to 3:
//    Accuser supplies EncryptionKeyProof { key: identity, dleq } where dleq proves
//    scalar 0 for generators [G, msg.key] -> points [enc_key_3 = identity, proof.key = identity].
//    DLEqProof::prove(rng, &mut encryption_key_transcript(ctx), &[G, msg.key], &Zeroizing::new(F::ZERO))
//    verifies since 0*G = identity = enc_key_3 and 0*msg.key = identity = proof.key.
//    decrypt_with_proof then applies keystream(identity) to 1's ciphertext -> non-canonical or
//    invalid share bytes -> blame_internal returns `sender` -> honest participant 1 is blamed/slashed.
```

Note: I could not fully verify the exact decoding path of `EncryptionKeyMessage` (its `read` implementation was not directly retrieved), but `Decryption::register` inserts `msg.enc_key` unconditionally and the only point decoding available via `Ciphersuite::read_G` explicitly permits identity; if the message layer already applies the identity-rejecting `Curve::read_G`, the finding is mitigated and should be downgraded accordingly.
