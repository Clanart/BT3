### Title
Permissionless bandwidth purchases let a griefer evict a victim's prepaid, unexpired bandwidth subscription via FIFO cap overflow - (File: `modules/pallets/bandwidth/src/lib.rs`)

### Summary
`pallet-bandwidth` stores prepaid `(chain, app)` bandwidth as a FIFO `BoundedVec<Subscription, MaxSubscriptions>` capped at 1024 entries [1](#0-0) . Any purchase past the cap evicts index `0` — the oldest entry — regardless of how many `remaining_bytes` it still holds [2](#0-1) . The `purchase()` entrypoint on `BandwidthManager.sol` is fully public and lets any caller pick an arbitrary `app`, `chain`, `tier`, and `months`, paying only the tier price [3](#0-2) . An attacker can therefore target any specific `(app_chain, app)` bucket and flood it with 1024 minimal-cost, minimal-duration purchases to force-evict a victim's legitimate, already-paid, unconsumed subscription — the same "fill the bounded array with worthless entries to push out the victim's real entry" primitive as the Golom `VoteEscrowDelegation` griefing report, just applied to the bandwidth ledger instead of a delegated-voting-power array.

### Finding Description
- `push_subscription` appends every new purchase to the tail of the `Allowance[app_chain][app]` list; once the list reaches `MAX_SUBSCRIPTIONS` (1024), it unconditionally removes index `0` — the oldest subscription — before pushing the new one [4](#0-3) .
- Eviction has no concept of "protect entries with large `remaining_bytes`" or "protect entries close to full value" — age alone (FIFO position) decides who gets evicted, so a victim's large, mostly-unconsumed subscription sitting at the front of the queue is exactly what gets destroyed first once the queue overflows.
- `on_accept` is the only gate on a purchase, and it only checks that `request.from` matches the registered `BandwidthManager` contract for the source chain — it does not restrict who calls `purchase()` on that manager, nor what `app`/`chain`/`tier`/`months` values are chosen [5](#0-4) .
- On the EVM side, `purchase(bytes app, uint256 tier, uint256 months, bytes chain)` is `external` with no access control, and `app`/`chain` are attacker-supplied raw bytes — an attacker can target *any* victim's exact `(app, chain)` key by copying the victim's own values [6](#0-5) .
- Each purchase only needs `months >= 1` and the configured tier price; buying the cheapest tier at `months = 1`, 1024 times, is the minimum cost required to flush a full cycle of the victim's queue and evict its front element.

### Impact Explanation
This is a direct "loss of funds"-class bug against the bandwidth-balance invariant explicitly called out in the pivots ("bandwidth balances must move exactly once and only to the rightful beneficiary and amount"). A griefer can permanently destroy a victim's already-paid, non-expired prepaid bandwidth (`lost_bytes` in `Event::SubscriptionEvicted` [7](#0-6) ) with no refund path, and no way for the victim to detect or preempt it beyond monitoring events. Since the gate (`try_consume`) drains strictly from the front in FIFO order and denies service once the sum of live `remaining_bytes` is insufficient [8](#0-7) , evicting a victim's large subscription can also push the app straight into `GateError::NoAllowance`/`Insufficient`, denying the app's ISMP dispatch capability entirely until it repurchases — a targeted denial-of-service on top of the fund loss.

### Likelihood Explanation
No privileged role, relayer, prover, or admin is required — `purchase()` is a public, unauthenticated entrypoint that anyone holding the fee token can call, and `app`/`chain` are fully attacker-chosen to match any victim's bucket. The only cost is `tierPrice[cheapest_tier] * 1 * 1024` in fee-token payments, which is bounded and attacker-controlled (the docs themselves acknowledge the eviction path exists but only reason about "pathological repeat-buy behavior" under benign usage, not an adversarial actor deliberately targeting another app's bucket) [9](#0-8) . This makes the attack economically bounded and independent of the victim's purchase size — a victim who buys a large, long-duration allocation is exactly as evictable as one buying small allocations, since eviction ignores `remaining_bytes` and `expires_at` entirely.

### Recommendation
- Do not evict strictly by FIFO position. Either evict only expired/near-zero-`remaining_bytes` entries first, or reject the push (return an error to the purchaser) instead of evicting a live subscription when the list is full.
- Consider rate-limiting or per-caller cooldowns on `purchase()` for a given `(chain, app)` key, or size subscriptions by value so a griefer cannot cheaply generate 1024 queue entries.
- Alternatively, aggregate/merge same-tier repurchases into a single running counter rather than always appending a new bounded-list row, removing the fixed-size array as an evictable griefing surface altogether.

### Proof of Concept
1. Governance configures at least one tier with a low price on `BandwidthManager.sol` (`set_tier` + `dispatch_set_tiers`), and Victim buys a large multi-month subscription for `app = VICTIM_APP` on `chain = "EVM-8453"` via `manager.purchase(VICTIM_APP, tier, many_months, "EVM-8453")`, landing at the front of `Allowance["EVM-8453"][VICTIM_APP]`.
2. Attacker repeatedly calls `manager.purchase(VICTIM_APP, cheapest_tier, 1, "EVM-8453")` 1024 times (any EOA, no allowlisting required — see `purchase()` [10](#0-9) ), each relayed to `pallet-bandwidth::on_accept`, appending to the same `(chain, app)` bucket.
3. On the 1024th attacker purchase, `push_subscription` detects `list.len() == MAX_SUBSCRIPTIONS` and calls `list.remove(0)` [2](#0-1) , evicting Victim's large subscription and emitting `SubscriptionEvicted { lost_bytes: <victim's remaining bytes> }`.
4. Victim's prepaid bandwidth is permanently gone; subsequent `BandwidthGate::try_consume` calls for the app either fail with `Insufficient`/`NoAllowance` or drain from the attacker's near-worthless, near-expired entries instead of the victim's paid allocation.

		/// Append a fresh subscription with a fixed expiry. If the list
		/// is already at `MaxSubscriptions`, evict the oldest entry and
		/// emit [`Event::SubscriptionEvicted`] so the lost bytes are
		/// auditable. Returns the new subscription's `expires_at`.
		fn push_subscription(
			app_chain: &StateMachine,
			app: &AppKey,
			tier: TierIndex,
			bytes: BandwidthBytes,
			duration_secs: u64,
		) -> u64 {
			let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();
			let expires_at = now.saturating_add(duration_secs);
			let new_sub =
				Subscription { tier, remaining_bytes: bytes, expires_at, purchased_at: now };

			let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
				let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
					Some(list.remove(0))
				} else {
					None
				};
				// Capacity is now guaranteed; try_push can't fail.
				let _ = list.try_push(new_sub);
				evicted
			});

    /// @notice Pay for `months` of `tier` bandwidth on `chain` for `app`.
    /// @dev Pulls the scaled tier price from `msg.sender` in the host's
    /// fee token, then dispatches a `BandwidthPurchaseMsg` to
    /// `pallet-bandwidth` on hyperbridge. The pallet credits an
    /// `(chain, app)` bucket bounded by tier `bytes` × `months`.
    /// @param app Recipient app address (usually 20-byte EVM, packed as bytes).
    /// @param tier Tier discriminant; must be configured via `SetTiers`.
    /// @param months Number of tier-windows to credit; must be > 0.
    /// @param chain UTF-8 chain id (e.g. `"EVM-8453"`) of the credit chain.
    /// @return commitment Hyperbridge dispatch commitment for tracking.
    function purchase(bytes calldata app, uint256 tier, uint256 months, bytes calldata chain)
        external
        returns (bytes32 commitment)
    {
        if (app.length == 0 || chain.length == 0 || months == 0) revert InvalidPurchase();
        uint256 price18d = tierPrice[tier];
        if (price18d == 0) revert UnknownTier();

        uint256 total18d = price18d * months;
        address feeToken = IDispatcher(_host).feeToken();
        uint8 dec = IERC20Metadata(feeToken).decimals();
        uint256 scale = 10 ** (18 - dec);
        if (total18d % scale != 0) revert PriceNotRepresentable();
        uint256 amount = total18d / scale;

        IERC20(feeToken).safeTransferFrom(msg.sender, address(this), amount);

        BandwidthPurchaseMsg memory body = BandwidthPurchaseMsg({
            app: app,
            tier: tier,
            months: months,
            chain: chain
        });

        commitment = IDispatcher(_host).dispatch(
            DispatchPost({
                dest: IDispatcher(_host).hyperbridge(),
                to: PALLET_BANDWIDTH_MODULE_ID,
                body: abi.encode(body),
                timeout: 0,
                fee: 0,
                payer: address(this)
            })
        );
