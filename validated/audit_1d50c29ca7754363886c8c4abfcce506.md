## Finding: `aptos move verify-package` never compares on-chain bytecode, only metadata fields [1](#0-0) 

### Title
`verify-package` claims bytecode verification but only compares package metadata, allowing malicious on-chain bytecode to pass as "verified" - (File: aptos-move/cli/src/stored_package.rs)

### Summary
The Aptos CLI's `aptos move verify-package` command is documented as downloading the on-chain package and verifying that its "bytecode matches a local compilation of the Move code" [2](#0-1)  and the corresponding docs echo this: "Build the package locally and verify that the on-chain copy matches" [3](#0-2) . However, the actual verification routine `CachedPackageMetadata::verify` never touches module bytecode at all — it only compares `PackageMetadata` fields (`name`, `deps`, `modules` [name/gzipped source/source map], `manifest`, `upgrade_policy`, `extension`, `source_digest`) between the locally-built metadata and the on-chain metadata [4](#0-3) .

### Finding Description
`code::publish_package` on-chain only checks that the module *names* in the submitted bytecode bundle match the `expected_modules` derived from `PackageMetadata.modules[].name`; it does not check that the (optional, purely informational) gzipped `source`/`source_map` fields in `ModuleMetadata`, or the `source_digest`, actually correspond to the bytecode bytes being published [5](#0-4) . There is no on-chain enforcement linking `metadata.modules[].source` to the real bytecode — those fields exist purely for off-chain human/tooling consumption (e.g. `save_package_to_disk`) [6](#0-5) .

Because of this, a publisher can submit `publish_package_txn`/`object_code_deployment::publish`/`upgrade` with:
- `code` = malicious/backdoored compiled module bytes, and
- `metadata` whose `modules[].source`, `manifest`, and `source_digest` describe innocent/benign source that a third party would expect.

This transaction succeeds on-chain because the VM's compatibility/dependency checks never cross-check source-derived digests against the actual bytecode bytes (only names, and struct/API-level bytecode compatibility for upgrades — not identity with claimed source).

Later, when a reviewer runs `aptos move verify-package --account <addr>` to confirm the deployed code matches the expected source, `CachedPackageRegistry::create` fetches the on-chain `PackageRegistry` (metadata only) and `CachedPackageMetadata::verify` is invoked, comparing only the metadata fields listed above [4](#0-3) . Since the attacker crafted `modules[].source`/`source_digest`/`manifest` to match a legitimate local build of the "expected" (benign) source, all these equality checks pass — the tool reports "Successfully verified source of package" [7](#0-6)  — even though the actually-loaded, executing on-chain bytecode is different (malicious) from what a local compile of that source would produce. The `CachedPackageRegistry` structure even carries a `bytecode: BTreeMap<String, Vec<u8>>` field that could hold the fetched on-chain module bytes, but `verify()` never uses it.

### Impact Explanation
This breaks the specific code-safety guarantee the tool advertises: verified/attested bytes vs. committed module bytes should agree. Consumers of this tool include:
- Developers/auditors verifying a deployed dependency before depending on it (per the framework's own guidance to "know and understand the entity publishing the package" via verification for `compatible` deps) [8](#0-7) .
- Governance reviewers relying on package-metadata inspection tooling before voting on framework or module-publishing proposals.

A malicious or compromised publisher can pass `verify-package` while running code that differs materially from the claimed/reviewed source, enabling a supply-chain-style deception: reviewers believe (and the CLI affirmatively states) that the deployed bytecode matches trusted source, when it does not. This is a false sense of security around code provenance/verification for any downstream Move package or object-code deployment, directly matching "Mismatch between verified bytes, package metadata, dependency declarations, and committed module bytes."

### Likelihood Explanation
High likelihood of exploitation feasibility: the attacker fully controls both `metadata_serialized` and `code` in `publish_package_txn` / object-code deployment entry points, and there is no on-chain requirement that they be consistent beyond module *names*. No special privilege is needed — any account (or code object owner) permissionlessly publishing/upgrading packages can do this. The only barrier is that a victim must actually run `verify-package` and trust its "Success" output, which is exactly the scenario the tool exists to support (and its documented purpose implies exactly this trust model).

### Recommendation
- **Short term**: Update `VerifyPackage`/`CachedPackageMetadata::verify` to actually fetch on-chain module bytecode (already partially supported via `CachedPackageRegistry.bytecode`) and compare it byte-for-byte (or by hash) against bytecode compiled locally from the same source, rather than only comparing metadata fields.
- **Long term**: Consider having the framework enforce (or at minimum make it possible to enforce) a binding between `source_digest`/module source metadata and the submitted bytecode at publish time, or clearly document that `verify-package` currently only checks metadata self-consistency, not bytecode identity, to avoid over-trusting its output.

### Proof of Concept
1. Compile a legitimate/benign Move package `P` and extract its `PackageMetadata` (`meta_benign`) via `BuiltPackage::extract_metadata()`.
2. Separately compile a backdoored variant of `P` (different logic, same module names) to get bytecode `code_malicious`.
3. Submit `code::publish_package_txn(owner, bcs(meta_benign), code_malicious)` (or the object-code-deployment equivalent). This succeeds on-chain because only module names in `code_malicious` are checked against `meta_benign.modules[].name`; nothing checks that `code_malicious` was actually compiled from the source embedded in `meta_benign`.
4. A reviewer runs `aptos move verify-package --account <addr>`, which rebuilds the *benign* source locally, fetches on-chain `meta_benign`, and calls `verify()` — all fields match, and the CLI reports success, while the actually running code is `code_malicious`.

/// Downloads the package from onchain and verifies the bytecode matches a local compilation of the Move code
#[derive(Parser)]
pub struct VerifyPackage {
    /// Address of the account containing the package
    #[clap(long, value_parser = aptos_cli_common::load_account_arg)]
    pub(crate) account: AccountAddress,

    /// Artifacts to be generated when building this package.
    #[clap(long, default_value_t = IncludedArtifacts::Sparse)]
    pub(crate) included_artifacts: IncludedArtifacts,

    #[clap(flatten)]
    pub(crate) move_options: MovePackageOptions,
    #[clap(flatten)]
    pub(crate) rest_options: RestOptions,
    #[clap(flatten)]
    pub(crate) profile_options: ProfileOptions,

    #[clap(skip)]
    pub env: Arc<MoveEnv>,
}

#[async_trait]
impl CliCommand<&'static str> for VerifyPackage {
    fn command_name(&self) -> &'static str {
        "VerifyPackage"
    }

    async fn execute(self) -> CliTypedResult<&'static str> {
        // First build the package locally to get the package metadata
        let build_options = BuildOptions {
            install_dir: self.move_options.output_dir.clone(),
            bytecode_version: fix_bytecode_version(
                self.move_options.bytecode_version,
                self.move_options.language_version,
            ),
            ..self.included_artifacts.build_options(&self.move_options)?
        };
        let w = self.env.writer();
        let pack = BuiltPackage::build_to(&w, self.move_options.get_package_path()?, build_options)
            .map_err(|e| CliError::MoveCompilationError(format!("{:#}", e)))?;
        let compiled_metadata = pack.extract_metadata()?;

        // Now pull the compiled package
        let client = self.rest_options.client(&self.profile_options)?;
        let registry = CachedPackageRegistry::create(client, self.account, false).await?;
        let package = registry
            .get_package(pack.name())
            .await
            .map_err(|s| CliError::CommandArgumentError(s.to_string()))?;

        // We can't check the arbitrary, because it could change on us
        if package.upgrade_policy() == UpgradePolicy::arbitrary() {
            return Err(CliError::CommandArgumentError(
                "A package with upgrade policy `arbitrary` cannot be downloaded \
                since it is not safe to depend on such packages."
                    .to_owned(),
            ));
        }

        // Verify that the source digest matches
        package.verify(&compiled_metadata)?;

        Ok("Successfully verified source of package")
    }

    pub fn verify(&self, package_metadata: &PackageMetadata) -> anyhow::Result<()> {
        let self_metadata = self.metadata;

        if self_metadata.name != package_metadata.name {
            bail!(
                "Package name doesn't match {} : {}",
                package_metadata.name,
                self_metadata.name
            )
        } else if self_metadata.deps != package_metadata.deps {
            bail!(
                "Dependencies don't match {:?} : {:?}",
                package_metadata.deps,
                self_metadata.deps
            )
        } else if self_metadata.modules != package_metadata.modules {
            bail!(
                "Modules don't match {:?} : {:?}",
                package_metadata.modules,
                self_metadata.modules
            )
        } else if self_metadata.manifest != package_metadata.manifest {
            bail!(
                "Manifest doesn't match {:?} : {:?}",
                package_metadata.manifest,
                self_metadata.manifest
            )
        } else if self_metadata.upgrade_policy != package_metadata.upgrade_policy {
            bail!(
                "Upgrade policy doesn't match {:?} : {:?}",
                package_metadata.upgrade_policy,
                self_metadata.upgrade_policy
            )
        } else if self_metadata.extension != package_metadata.extension {
            bail!(
                "Extensions doesn't match {:?} : {:?}",
                package_metadata.extension,
                self_metadata.extension
            )
        } else if self_metadata.source_digest != package_metadata.source_digest {
            bail!(
                "Source digests doesn't match {:?} : {:?}",
                package_metadata.source_digest,
                self_metadata.source_digest
            )
        }

        Ok(())
    }

    public fun publish_package(owner: &signer, pack: PackageMetadata, code: vector<vector<u8>>) acquires PackageRegistry {
        // Disallow incompatible upgrade mode. Governance can decide later if this should be reconsidered.
        assert!(
            pack.upgrade_policy.policy > upgrade_policy_arbitrary().policy,
            error::invalid_argument(EINCOMPATIBLE_POLICY_DISABLED),
        );

        let addr = signer::address_of(owner);
        if (!exists<PackageRegistry>(addr)) {
            move_to(owner, PackageRegistry { packages: vector::empty() })
        };

        // Checks for valid dependencies to other packages
        let allowed_deps = check_dependencies(addr, &pack);

        // Check package against conflicts
        // To avoid prover compiler error on spec
        // the package need to be an immutable variable
        let module_names = get_module_names(&pack);

        // Record, per module in this package, the object's transitive root owner at (re)publish, so
        // lazy self-init can detect a later transfer of the object or an ancestor since that module
        // was published (see `init::internal_maybe_initialize`). Objects only; feature-gated.
        if (features::is_lazy_module_initialization_enabled() && object::is_object(addr)) {
            let owner = object::address_to_object<object::ObjectCore>(addr).root_owner();
            module_names.for_each_ref(|name| {
                init::record_deploy_owner(addr, *name.bytes(), owner);
            });
        };
        let package_immutable = &borrow_global<PackageRegistry>(addr).packages;
        let len = package_immutable.length();
        let index = len;
        let upgrade_number = 0;
        package_immutable.enumerate_ref(|i, old| {
            let old: &PackageMetadata = old;
            if (old.name == pack.name) {
                upgrade_number = old.upgrade_number + 1;
                check_upgradability(old, &pack, &module_names);
                index = i;
            } else {
                check_coexistence(old, &module_names)
            };
        });

        // Assign the upgrade counter.
        pack.upgrade_number = upgrade_number;

        let packages = &mut borrow_global_mut<PackageRegistry>(addr).packages;
        // Update registry
        let policy = pack.upgrade_policy;
        if (index < len) {
            pack.modules.for_each_ref(|m| {
                let m: &ModuleMetadata = m;
                init::reset_initialized(addr, *m.name.bytes());
            });
            *packages.borrow_mut(index) = pack
        } else {
            packages.push_back(pack)
        };

        event::emit(PublishPackage {
            code_address: addr,
            is_upgrade: upgrade_number > 0
        });

        // Request publish
        if (features::code_dependency_check_enabled())
            request_publish_with_allowed_deps(addr, module_names, allowed_deps, code, policy.policy)
        else
        // The new `request_publish_with_allowed_deps` has not yet rolled out, so call downwards
        // compatible code.
            request_publish(addr, module_names, code, policy.policy)
    }
