### Title
Forfeit mechanism is dead code in `_calExpireForfeit` - unconditional 100% payout of unlocked rewards regardless of cooldown/lock state ([File: rewards/mWOMSVBaseRewarder.sol])

### Summary
`mWOMSVBaseRewarder._calExpireForfeit()` never queries `mWOMSV.getRewardablePercentWAD(_account)` at all, unlike its sibling `vlMGPBaseRewarder._calExpireForfeit()` which does. Consequently `getReward`/`getRewards` always pay out 100% of accrued rewards to any account, whether the account is fully locked, mid-cooldown, or has never served any lock commitment, making the forfeit-during-cooldown protection completely inert — not merely bypassable via the specific block-timing trick described in the question, but unconditionally absent.

### Finding Description
Compare the two sibling implementations:

- `vlMGPBaseRewarder._calExpireForfeit` computes `rewardableAmount = _amount * vlMGP.getRewardablePercentWAD(_account) / 1e18` [1](#0-0) .
- `mWOMSVBaseRewarder._calExpireForfeit` sets `rewardableAmount = _amount` directly and never references `mWOMSV.getRewardablePercentWAD(_account)` anywhere in the function body [2](#0-1) .

As a result, `forfeitAmount = _amount - rewardableAmount` is always `0` in `mWOMSVBaseRewarder`, for every account, in every state (fully locked, fully unstarted cooldown, mid-cooldown, or fully matured cooldown). This is invoked from `_sendReward`, which is called by `getReward`/`getRewards` (both reachable by any account through `MasterMagpie`'s `onlyMasterMagpie` gate, e.g. via `multiclaim`) [3](#0-2) .

The question's premised mechanism — that `getRewardablePercentWAD` is consulted but stays pinned at `1e18` throughout the cooldown window, so a precisely-timed lock/unlock around a large settlement lets an attacker dodge forfeiture — does not match the code. `getRewardablePercentWAD` in `wombat/mWomSV.sol` is a real, correctly time-decaying percentage calculation (locked stake weighted at 100%, cooling-down stake decays over `coolDownInSecs`) [4](#0-3) , but `mWOMSVBaseRewarder` simply never calls it. There is no dependency on settlement timing, block placement, or cooldown-window entry/exit at all — the forfeit is zero unconditionally, for every user, at every point in time. Since no forfeit logic exists to bypass, the specific "lock one block before / unlock one block after a settlement" timing attack described is unnecessary and not the actual root cause; the real defect is broader and simpler: **forfeiture never functions in this contract**.

### Impact Explanation
Any staker of `mWomSV` (mWOMSV) receives full, un-forfeited rewards through `getReward`/`getRewards` regardless of their actual lock commitment, permanently defeating the intended penalty for early/committed exits. This matches "High – Theft of unclaimed yield" because rewards meant to be redistributed to long-term lockers (via `_queueNewRewardsWithoutTransfer` forfeit re-injection) are instead fully captured by any account, diluting/loss to committed long-term stakers who should have received the forfeited share.

### Likelihood Explanation
No special timing, capital, or privileged role is required — this triggers on every single call to `getReward`/`getRewards` for every account, since the code path computing forfeit unconditionally yields zero. It is trivially and repeatably exploitable by any regular staker with zero precondition beyond holding staked `mWomSV` and calling the standard claim path (e.g., via `MasterMagpie.multiclaim`).

### Recommendation
Fix `mWOMSVBaseRewarder._calExpireForfeit` to mirror `vlMGPBaseRewarder._calExpireForfeit`: compute `rewardableAmount = _amount * mWOMSV.getRewardablePercentWAD(_account) / 1e18` instead of hardcoding `rewardableAmount = _amount`, so forfeiture actually reflects the account's real lock/cooldown state.

### Proof of Concept
Hardhat/Foundry test plan:
1. Deploy `mWomSV`, `MasterMagpie`, and `mWOMSVBaseRewarder`; fund the rewarder with reward tokens via `queueNewRewards`.
2. Have an account lock `mWOM`, then immediately call `startUnlock` for the full amount (entering cooldown, `getRewardablePercentWAD` would be less than 100% partway through cooldown for a correct implementation, since cooling-down principal should decay over `coolDownInSecs`).
3. Advance time partway into the cooldown window (e.g., 50%), accrue rewards via `queueNewRewards`.
4. Call `getReward(account, receiver)` through `MasterMagpie`.
5. Assert: `calExpireForfeit(account, rewardToken)` returns `0` and the full `earned()` amount is transferred to `receiver`, even though the account is mid-cooldown and has not fully served its lock — demonstrating forfeiture never applies, independent of any block-timing manipulation around settlements.

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalmWomSV = fullyInLock + inCoolDown;
        if (userTotalmWomSV == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalmWomSV;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalmWomSV / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalmWomSV;
                }

            }
        }

        return percent;
    }
