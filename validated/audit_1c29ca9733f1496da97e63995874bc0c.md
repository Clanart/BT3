Found it: `isSafeFileExtension` in `app/src/ui/lib/context-menu.ts` is a hard-coded, incomplete blocklist that gates the "Open with Default Program" action across the Changes list, commit history, and PR file views — an attacker-controlled repository can trivially bypass it.

### Title
Incomplete extension blocklist in `isSafeFileExtension` allows "Open with Default Program" to launch attacker-supplied executables from a cloned/checked-out repository - (File: `app/src/ui/lib/context-menu.ts`)

### Summary
The "Open with Default Program" context-menu action, available on changed files, committed files, and pull-request diff files, is only guarded by `isSafeFileExtension`, which checks a file's extension against a tiny hard-coded array `RestrictedFileExtensions = ['.cmd', '.exe', '.bat', '.sh']` on Windows only, and returns `true` unconditionally on macOS/Linux [1](#0-0) . This is the sole safety gate before invoking the OS "open" action (`shell.openPath`/`openFile`) on a path derived directly from files in the working directory of a repository the user cloned or checked out.

### Finding Description
Multiple UI surfaces enable the "Open with Default Program" menu item whenever `isSafeFileExtension(extension)` returns `true`:
- Changes list: `enabled: enabled && isSafeExtension` [2](#0-1) 
- History/commit file view: `enabled: isSafeExtension && fileExistsOnDisk` [3](#0-2) 
- Pull request file view: `enabled: isSafeExtension && fileExistsOnDisk` [4](#0-3) 

`isSafeFileExtension` only restricts `.cmd`, `.exe`, `.bat`, `.sh` and only on Windows; on macOS/Linux it always returns `true` [5](#0-4) . It does not account for:
- Other Windows-launchable/dangerous extensions the shell will execute (`.com`, `.scr`, `.pif`, `.msi`, `.js`, `.jse`, `.vbs`, `.wsf`, `.hta`, `.ps1`, `.lnk`, `.jar`, etc.).
- macOS `.app` bundles and executable scripts with the executable bit set, or double-extension tricks (e.g. `invoice.pdf.app`), which macOS's Launch Services / Finder will happily execute despite `isSafeFileExtension` returning `true` unconditionally for `__DARWIN__`.
- Symlinks inside the working tree that point to an executable outside the repo (git can create symlinks; `Path.join(repository.path, file.path)` followed by `shell.openPath`/`open` will resolve and execute through the symlink).

Since the file whose extension is checked, and whose full path is later passed to the OS "open" call, comes directly from an attacker-controlled repository (a clone, a checked-out branch, or a viewed PR diff), an attacker who gets a victim to clone/checkout their repo and use the completely normal "Open with Default Program" action on a file can get an executable launched. This mirrors the report's core flaw: a supposedly protective guard is *incomplete/bypassable* and is evaluated purely on attacker-controlled input (file extension/name in a repo the attacker fully controls), silently defeating the safety check the same way the missing `require(amount > 0)` check silently defeated the withdrawal-timer invariant in the Mochi report.

### Impact Explanation
If a victim clones or checks out an attacker-authored repository (or reviews a malicious PR's file list) and uses the built-in "Open with Default Program" feature — an entirely ordinary Desktop workflow — on a file crafted to slip past the blocklist (e.g. `.scr`, `.js`, `.app`, `.lnk`, or a symlink to an external executable), arbitrary code execution can result on the victim's machine. This falls squarely within scope: attacker controls a cloned/checked-out repository, and the result is code execution outside the sandboxed diff-viewing context.

### Likelihood Explanation
Likelihood is moderate: it requires the victim to explicitly invoke "Open with Default Program" on a specific file rather than just viewing a diff, but this is a documented, discoverable, single-click context-menu action exposed for every changed/committed/PR file, and the blocklist approach (rather than an allowlist) is inherently incomplete — new dangerous extensions or platform-specific execution vectors (macOS `.app`/executable bit, symlinks) are trivially missed. No admin rights, local access, or leaked credentials are required; the only "step" is normal use of a documented feature on attacker-supplied content.

### Recommendation
- Replace the extension blocklist with a strict allowlist of known-safe, non-executable document/media extensions, or otherwise refuse to enable "Open with Default Program" unless the file's extension is verified via content-type/`mdls` (similar to `isApplicationBundle`) to be non-executable on all platforms, not just Windows.
- Explicitly check for and refuse macOS application bundles/executable-bit files and symlinks that resolve outside expected content types before enabling the action.
- Apply the same enhanced check consistently everywhere `isSafeFileExtension` currently gates `shell.openPath`/`openFile` (Changes list, history/commit view, PR file view).

### Proof of Concept
1. Attacker creates/pushes a repository containing a file such as `resume.scr` (Windows) or `resume.pdf.app` / an executable shell script with the executable bit set (macOS), or a symlink `notes.txt -> /Applications/Terminal.app/Contents/MacOS/Terminal`.
2. Victim clones the repository in GitHub Desktop, or opens a pull request containing this file for review.
3. Victim right-clicks the file in the Changes list, History view, or PR "Files changed" view and selects "Open with Default Program" — enabled because `isSafeFileExtension(extension)` returns `true` for `.scr` (non-Windows) or unconditionally on macOS/Linux, per [5](#0-4) .
4. The OS launches the attacker's payload with the victim's privileges.
