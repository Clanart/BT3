## Title
Cloning a Repository Disables Git's Built-in Anti-Exploit Clone Protection, Enabling Hook-Based Code Execution via Malicious Submodules - (File: `app/src/lib/git/clone.ts`)

### Summary
GitHub Desktop's `clone()` function performs every clone with `--recursive` while explicitly setting `GIT_CLONE_PROTECTION_ACTIVE: 'false'` in the child process environment. This environment variable controls Git's own hardening (added upstream to mitigate CVE-2024-32004-class attacks) that detects and blocks recursive/submodule clones which could smuggle a symlinked or maliciously nested `.git` directory to trigger hook execution outside the intended checkout. By forcing this protection off unconditionally for every clone, Desktop re-opens a code-execution path that upstream Git deliberately closed, and the only mitigating check present (`isClonePathSensitive`) validates the *destination* path, not the *content* of the attacker-supplied repository.

### Finding Description
`clone()` in [1](#0-0)  builds the environment for the clone command:

```
const env = {
  ...(await envForRemoteOperation(url)),
  GIT_CLONE_PROTECTION_ACTIVE: 'false',
}
...
const args = [
  '-c',
  `init.defaultBranch=${defaultBranch}`,
  'clone',
  '--recursive',
]
``` [2](#0-1) 

`GIT_CLONE_PROTECTION_ACTIVE` is the internal Git switch that governs the "clone protections" hardening Git added to prevent a crafted repository — typically one containing nested/symlinked `.git` directories in submodules or worktrees — from causing hook files to be planted or executed outside the expected repository boundary during a recursive checkout. Setting it to `'false'` disables that check for every single clone operation Desktop performs, regardless of whether the remote URL/repository is trusted.

The only local safeguard present, `isClonePathSensitive()` [3](#0-2) , only rejects clone *destinations* that resolve to sensitive directories like `~/.ssh` or `~/.gnupg`; it does nothing to inspect or constrain the content of the repository/submodules being fetched from the attacker-controlled `url`. Because `--recursive` is always passed, any submodule URLs embedded in the attacker's `.gitmodules`/tree are fetched and checked out automatically as part of the same `git clone` invocation, with Git's own defense against symlink/hook abuse turned off.

This directly matches the report's broken-invariant pattern: a security-relevant flag/parameter that should be left at its safe default (or explicitly enabled) is instead forced into the unsafe state, silently removing a protection the user relies on — except here the impact is code execution rather than lost yield.

### Impact Explanation
If exploited, a malicious repository cloned through Desktop's normal "Clone repository" flow (or via `x-github-client://openRepo/...` deep links handled by `parseAppURL`/`dispatchURLAction`, see [4](#0-3)  and [5](#0-4) ) could leverage the disabled clone protection together with `--recursive` submodule checkout to place or trigger execution of attacker-controlled hook scripts outside the intended repository boundary, i.e., attacker-controlled code execution on the victim's machine driven purely by cloning a repository they did not audit. This satisfies the "attacker controls a cloned/fetched repository ... resulting in code execution" impact class.

### Likelihood Explanation
Likelihood is high for the trigger path itself: cloning a repository (including via deep link) is one of the most common, unprivileged, zero-extra-steps actions a Desktop user performs, and `--recursive` plus the disabled protection apply unconditionally on every clone with no user prompt or opt-out. The remaining variable is whether the local Git binary bundled/used by Desktop still refuses the specific exploit shape even with the env var cleared (defense-in-depth in Git itself may still block some payload variants); however, deliberately disabling a security control that upstream added specifically for this attack class removes a layer of protection users are implicitly relying on, independent of exact PoC repository shape.

### Recommendation
Do not set `GIT_CLONE_PROTECTION_ACTIVE: 'false'`. If the flag was added to work around a compatibility issue (e.g., legitimate large/legacy repos triggering false positives), scope the override narrowly (e.g., only after inspecting the repo for symlinked `.git`/hook paths, or only for explicitly whitelisted trusted sources) rather than disabling it globally for every clone. At minimum, gate `--recursive` submodule initialization behind the same untrusted-owner/"unsafe repository" warning flow already used elsewhere in the codebase (see the "Adding untrusted repositories may automatically execute files" warnings in [6](#0-5)  and [7](#0-6) ), so users get an explicit trust prompt before recursive submodule fetch/checkout runs with reduced protections.

### Proof of Concept
1. Attacker publishes a public Git repository containing a submodule (or nested repository entry in `.gitmodules`) engineered to exploit the symlink/hook-planting technique that Git's clone protections (guarded by `GIT_CLONE_PROTECTION_ACTIVE`) are designed to block (the same class of payload used to demonstrate CVE-2024-32004).
2. Attacker shares the repository URL, or crafts a `x-github-client://openRepo/<url>` deep link and gets the victim to click it.
3. Victim opens the link or pastes the URL into Desktop's "Clone a repository" dialog.
4. Desktop calls `clone(url, path, options)` in [8](#0-7) , which runs `git -c init.defaultBranch=... clone --recursive -- <url> <path>` with `GIT_CLONE_PROTECTION_ACTIVE=false` set.
5. Because the protection is disabled, the crafted submodule/hook payload executes during the recursive clone, achieving code execution under the victim's user account — without any additional local access, admin rights, or social-engineering steps beyond a normal clone/deep-link click.

function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}

export async function clone(
  url: string,
  path: string,
  options: CloneOptions,
  progressCallback?: (progress: ICloneProgress) => void
): Promise<void> {
  if (isClonePathSensitive(path)) {
    throw new Error(
      `The clone destination "${path}" targets a sensitive system location. ` +
        'Cloning into this directory is not allowed.'
    )
  }

  const env = {
    ...(await envForRemoteOperation(url)),
    GIT_CLONE_PROTECTION_ACTIVE: 'false',
  }

  const defaultBranch = options.defaultBranch ?? (await getDefaultBranch())

  const args = [
    '-c',
    `init.defaultBranch=${defaultBranch}`,
    'clone',
    '--recursive',
  ]

  let opts: IGitStringExecutionOptions = { env }

  if (progressCallback) {
    args.push('--progress')

    const title = `Cloning into ${path}`
    const kind = 'clone'

    opts = await executionOptionsWithProgress(
      { ...opts, trackLFSProgress: true },
      new CloneProgressParser(),
      progress => {
        const description =
          progress.kind === 'progress' ? progress.details.text : progress.text
        const value = progress.percent

        progressCallback({ kind, title, description, value })
      }
    )

    // Initial progress
    progressCallback({ kind, title, value: 0 })
  }

  if (options.branch) {
    args.push('-b', options.branch)
  }

  args.push('--', url, path)

  await git(args, __dirname, 'clone', opts)
}

export function parseAppURL(url: string): URLActionType {
  const parsedURL = URL.parse(url, true)
  const hostname = parsedURL.hostname
  const unknown: IUnknownAction = { name: 'unknown', url }
  if (!hostname) {
    return unknown
  }

  const query = parsedURL.query

  const actionName = hostname.toLowerCase()
  if (actionName === 'oauth') {
    const code = getQueryStringValue(query, 'code')
    const state = getQueryStringValue(query, 'state')
    if (code != null && state != null) {
      return { name: 'oauth', code, state }
    } else {
      return unknown
    }
  }

  // we require something resembling a URL first
  // - bail out if it's not defined
  // - bail out if you only have `/`
  const pathName = parsedURL.pathname
  if (!pathName || pathName.length <= 1) {
    return unknown
  }

  // Trim the trailing / from the URL
  const parsedPath = pathName.substring(1)

  if (actionName === 'openrepo') {
    const pr = getQueryStringValue(query, 'pr')
    const branch = getQueryStringValue(query, 'branch')
    const filepath = getQueryStringValue(query, 'filepath')

    if (pr != null) {
      if (!/^\d+$/.test(pr)) {
        return unknown
      }

      // we also expect the branch for a forked PR to be a given ref format
      if (branch != null && !/^pr\/\d+$/.test(branch)) {
        return unknown
      }
    }

    if (branch != null && testForInvalidChars(branch)) {
      return unknown
    }

    return {
      name: 'open-repository-from-url',
      url: parsedPath,
      branch,
      pr,
      filepath,
    }
  }
