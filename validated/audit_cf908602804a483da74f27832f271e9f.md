**Reasoning:**

The premise misunderstands how `memoize-one` works. `memoizedGetShellEnv` is a `memoizeOne`-wrapped function, which only remembers the *most recent* call and its arguments; it recomputes whenever any argument differs from the last call (using shallow/`Object.is` comparison per argument) [1](#0-0) . The arguments passed are `(shellKind, cwd, cacheKey)` — `cwd` is always included, so even when `getCacheHooksEnv()` is `true` and the literal string `'global'` is used as the cache key, a call for repo A's `cwd` and a subsequent call for repo B's different `cwd` will **not** match the memoized last-call arguments, forcing a fresh invocation of `getShellEnv(cwd, shellKind)` for repo B [2](#0-1) . The `'global'` cache key only allows reuse across multiple hook invocations *within the same repository/cwd and same operation sequence*, not across "unrelated" repositories with different paths — the comment in the code confirms this intent ("we can optionally cache it over multiple operations in the same repository") [3](#0-2) .

Additionally, the premise that a "repo-supplied hook" can mutate the captured `SHELL_ENV` doesn't correspond to the actual code path: `getShellEnv` spawns the configured shell (`git-bash`/`pwsh`/`cmd`) to run `printenvz` in the given `cwd` and captures the resulting environment (populated by the user's own shell profile/rc scripts) [4](#0-3)  — this happens *before* any repo-defined Git hook is executed by `hooks-proxy.ts`, so a hook cannot influence this shell-env capture to poison a shared cache entry that would later apply to a different repository.

Because `cwd` is always part of the memoization key, the "leak repo A's env into repo B's execution" scenario described cannot occur through this code as written.

export const getShellEnv = async (
  cwd?: string,
  shellKind?: SupportedHooksEnvShell,
  printenvzPath?: string
): Promise<ShellEnvResult> => {
  const ext = __WIN32__ ? '.exe' : ''
  printenvzPath ??= join(__dirname, `printenvz${ext}`)

  const shellInfo = await getShell(shellKind)

  if (!shellInfo) {
    return { kind: 'failure', shellKind }
  }

  const { shell, args, quoteCommand, windowsVerbatimArguments, argv0 } =
    shellInfo

  return await new Promise((resolve, reject) => {
    const child = spawn(shell, [...args, quoteCommand(printenvzPath)], {
      env: {},
      windowsVerbatimArguments,
      argv0,
      stdio: 'pipe',
      cwd,
    })
