### Title
Unauthenticated `ReceivedOutput` imports let attackers report nonexistent Bitcoin funds - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
`ReceivedOutput::read` deserializes an output offset, full prevout data, and outpoint without authenticating that the object came from `Scanner` or corresponds to a confirmed chain output. Because the record contains no wallet/group-key binding, callers cannot distinguish scanner-produced outputs from attacker-supplied assertions during deserialization. [1](#0-0) [2](#0-1) 

### Finding Description
`Scanner::scan_transaction` normally creates a `ReceivedOutput` only after matching `output.script_pubkey` against a registered derived script. [3](#0-2)  `ReceivedOutput::read` bypasses that provenance check and accepts all three security-relevant fields from untrusted bytes: the scalar `offset`, claimed `TxOut`, and claimed `OutPoint`. [2](#0-1) 

`SignableTransaction::new` then trusts the imported claimed value as spendable input balance and uses the claimed outpoint as the transaction input. [4](#0-3)  The later `multisig` check verifies only that the embedded `prevout.script_pubkey` matches `keys + offset`; it does not prove that the claimed outpoint exists on-chain or that its actual prevout has that script. [5](#0-4) 

An attacker who knows the wallet’s public group key can choose an offset which produces an even Taproot key, embed that script in a fabricated `TxOut`, pair it with a nonexistent or unrelated `OutPoint`, and have it accepted as a wallet input. [6](#0-5) [5](#0-4) 

### Impact Explanation
A forged imported output is reported as received wallet balance even though the claimed UTXO does not exist or is not actually controlled by that output’s real on-chain script. [2](#0-1) [4](#0-3)  The transaction builder can then construct and threshold-sign a transaction spending that fabricated input, producing an invalid transaction and incorrect accounting rather than spendable funds. [7](#0-6) [8](#0-7) 

### Likelihood Explanation
This requires an attacker to supply serialized `ReceivedOutput` bytes to an import path, which is the untrusted deserialization surface explicitly exposed by `ReceivedOutput::read`. [9](#0-8)  No private key material is needed: the attacker only needs the public group key to derive a matching script and can select an offset until `p2tr_script_buf` returns an even Taproot script. [10](#0-9) [6](#0-5) 

### Recommendation
Bind `ReceivedOutput` serialization to the wallet identity and scanner provenance. Store or derive the expected `script_pubkey` from the wallet key plus `offset`, verify it against the embedded `TxOut`, and authenticate/import only scanner-issued records, for example with a wallet-scoped MAC over `offset || TxOut || OutPoint`. Before treating an imported output as balance, additionally require confirmation that `outpoint` resolves on-chain to the claimed `TxOut`.

### Proof of Concept
Conceptually construct the serialized input as:

```rust
// Public wallet key known to the attacker.
let base = wallet_group_key;

// Pick the smallest offset yielding an even P2TR key.
let mut offset = Scalar::ZERO;
let script = loop {
  if let Some(script) = p2tr_script_buf(base + (ProjectivePoint::GENERATOR * offset)) {
    break script;
  }
  offset += Scalar::ONE;
};

// Fabricate a received output for a nonexistent outpoint.
let fake_txout = TxOut {
  value: Amount::from_sat(100_000),
  script_pubkey: script,
};
let fake_outpoint = OutPoint::new(Txid::all_zeros(), 0);

// Bytes accepted by ReceivedOutput::read:
// offset.to_bytes() || consensus(fake_txout) || consensus(fake_outpoint)
let imported = ReceivedOutput::read(&mut forged_bytes).unwrap();
```

`SignableTransaction::new(vec![imported], ...)` counts the forged 100,000 sats as inputs. [4](#0-3)  Calling `.multisig(&keys)` succeeds because the attacker selected the embedded script to equal `p2tr_script_buf(keys.offset(offset).group_key())`. [5](#0-4)  The resulting transaction is signed for `Prevouts::All(&self.tx.prevouts)`, but the claimed prevout is fabricated, so the reported funds are not actually spendable on-chain. [8](#0-7)
