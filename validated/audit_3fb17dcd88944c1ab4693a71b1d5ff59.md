### Title
Attacker-controlled remote hostname bypasses GitHub-host verification, triggering Enterprise OAuth sign-in against an untrusted domain - (File: `app/src/lib/api.ts`)

### Summary
`isGitHubHost()` in [1](#0-0)  is the function GitHub Desktop uses to decide whether a URL "belongs to" a GitHub host. Its fallback heuristic is a loose substring regex (`/(^|\.)(github)\./`) rather than a verified allow-list of trusted endpoints. This is structurally the same flaw as the `ShareToken`/`WhitelistToken` bug: a security-relevant classification (`isWhitelisted` / `isGitHubHost`) is permissive by default/heuristic instead of being backed by an actual verified trust store, so anything crafted to satisfy the loose pattern is treated as trusted.

### Finding Description
The credential trampoline uses `isGitHubHost` (via `getEndpointKind`) to decide how to authenticate a Git network request: [2](#0-1) 

If the request's `WWW-Authenticate` header is absent and there is no existing matching account, `getEndpointKind` falls through to `isGitHubHost(endpoint)`. Inside `isGitHubHost`, before any network verification is attempted, the function accepts the endpoint as GitHub-controlled if the hostname merely *contains* `github.` as a dot-delimited component: [3](#0-2) 

An attacker who controls a Git remote (e.g. a cloned repository, or a repo whose remote the user adds/pushes to) can register a hostname such as `github.attacker.com` or `foo.github.attacker.com`. That hostname will match the regex and be classified `'enterprise'` (a trusted GitHub host) with no further verification — the same `meta` endpoint probe used later in `isGitHubHost` is skipped entirely once the regex matches.

Once classified as `'enterprise'` with no known account, `getCredential` prompts the user to sign in: [4](#0-3) 

`promptForGitHubSignIn` then directly starts the GitHub Enterprise OAuth flow scoped to the attacker's origin, and shows the sign-in popup with `credentialHelperUrl` pointed at that origin: [5](#0-4) 

If the user proceeds, `authenticateWithBrowser` opens `getOAuthAuthorizationURL(endpoint, state)` — built directly from the attacker's origin — in the system browser: [6](#0-5) [7](#0-6) 

When the OAuth callback returns a code, `requestOAuthToken` POSTs the app's `client_id`/`client_secret` and the authorization code to `${endpoint}/login/oauth/access_token` — i.e., directly to the attacker-controlled host: [8](#0-7) 

The corrupted value is the trust classification returned by `isGitHubHost`/`getEndpointKind`: an attacker-chosen hostname is misclassified as a first-party GitHub endpoint. Existing guards do not stop this because `isGitHubHost`'s regex check happens *before* the connectivity/`x-github-request-id` verification and is treated as sufficient proof of trust on its own (an early `return true`).

### Impact Explanation
Successful exploitation causes GitHub Desktop's own OAuth application secret (`ClientSecret`) and a live authorization code to be sent to an attacker-controlled server during the token exchange, along with routing the user's sign-in flow to a domain the user never explicitly configured as their GitHub Enterprise instance. This is credential/token exfiltration and unauthorized account-binding to an attacker-supplied endpoint, initiated purely by the presence of a crafted remote hostname — no local access, malware, or leaked credentials required.

### Likelihood Explanation
The trigger condition (Git performing a network operation such as fetch/push against a remote whose hostname contains `github.` as a labeled component) is a normal, low-friction Desktop workflow once a user has added or cloned from an attacker-supplied remote URL. The only additional step is the user confirming the sign-in dialog that Desktop itself presents, which is expected/normal behavior for any legitimate first-time GHE credential prompt, making it easy to mistake for a real sign-in request. I was not able to fully trace `dispatcher.setSignInEndpoint` to confirm whether it performs the same syntactic/connectivity validation as `SignInStore.setEndpoint` before advancing state (source not retrieved in time), so the exact number of confirmations required before the OAuth URL opens is uncertain and should be verified against `app/src/ui/dispatcher/dispatcher.ts`.

### Recommendation
Replace the substring-based `isGitHubHost` heuristics in [9](#0-8)  with checks anchored to the full hostname (e.g., exact match or a verified suffix against configured/known enterprise endpoints), and never treat a positive regex match as sufficient trust — always require the authenticated `x-github-request-id` connectivity check (already implemented later in the same function) before classifying an unfamiliar host as GitHub-owned. Additionally, before opening a browser-based OAuth authorize URL or performing the `access_token` exchange in [8](#0-7) , require the endpoint to have completed the same URL validation/connectivity flow used in `SignInStore.setEndpoint` rather than accepting an unvalidated origin supplied via the credential trampoline.

### Proof of Concept
1. Attacker sets up a server at `github.attacker.com` that responds to arbitrary requests (no need to mimic a real GitHub API).
2. Attacker gets the victim to clone/add a remote pointing at `https://github.attacker.com/owner/name.git` (e.g., via a shared repo, PR, or deep link that adds this remote).
3. Victim performs any Git network operation against that remote in Desktop (fetch/push/pull) while not yet signed in to that host.
4. `getEndpointKind` calls `isGitHubHost('https://github.attacker.com')`; the hostname matches `/(^|\.)(github)\./`, so it returns `'enterprise'` without further verification (`app/src/lib/api.ts:2451-2454`).
5. `getCredential` invokes `ui.promptForGitHubSignIn('https://github.attacker.com')`, which begins the Enterprise sign-in flow scoped to `https://github.attacker.com` (`app/src/lib/trampoline/trampoline-ui-helper.ts:80-99`).
6. Victim confirms the sign-in dialog; Desktop opens `https://github.attacker.com/login/oauth/authorize?client_id=<real_client_id>&...` in the browser.
7. Attacker's server captures the flow and, once a code is produced/relayed back to Desktop, `requestOAuthToken` POSTs `client_id`, `client_secret`, and `code` to `https://github.attacker.com/login/oauth/access_token`, exfiltrating the app's OAuth secret and code to the attacker.

export async function requestOAuthToken(
  endpoint: string,
  code: string
): Promise<string | null> {
  try {
    const urlBase = getHTMLURL(endpoint)
    const response = await request(
      urlBase,
      null,
      'POST',
      'login/oauth/access_token',
      {
        client_id: ClientID,
        client_secret: ClientSecret,
        code: code,
      }
    )

    return result.access_token
  } catch (e) {
    log.warn(`requestOAuthToken: failed with endpoint ${endpoint}`, e)
    return null
  }
}

export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
