### Title
Server-Side Request Forgery in DataLayer mirror subscription sync via attacker-injected on-chain mirror URLs - (File: `chia/data_layer/data_layer.py`)

### Summary
Any chain participant can create a low-value "mirror" coin (puzzle hash `create_mirror_puzzle()`) whose memo encodes an arbitrary `launcher_id` and an arbitrary list of URL strings [1](#0-0) . A victim's `DataLayerWallet.coin_added()` tracks that mirror coin for *any* launcher_id it already tracks, storing the attacker-supplied URLs regardless of who created the coin (there is no signature/ownership check on the URLs, only an `ours` bookkeeping flag) [2](#0-1) . The victim's `DataLayer` service later reads back all mirrors — including non-owned ones — with no filtering, and feeds every URL into its subscription/download logic [3](#0-2) . Those URLs are subsequently used to make outbound HTTP GET requests from the server process in `fetch_and_validate()`/`http_download()`, allowing an attacker to force the victim node to issue arbitrary outbound HTTP requests (e.g., to internal services or cloud metadata endpoints).

### Finding Description
This mirrors the Chainlit SSRF pattern precisely: a low-privilege actor supplies a `url` value that is later fetched server-side by an outbound HTTP client, without validating that the URL is legitimate or that the requester is authorized to direct the server's network egress.

1. **Injection point** — `create_mirror_puzzle()` is a fixed, publicly-known puzzle (`P2_PARENT.curry(Program.to(1))`). Anyone can create a coin with that puzzle hash and place `[launcher_id, url1, url2, ...]` in the memo of the `CREATE_COIN` condition [1](#0-0) . This requires only a normal spend bundle with a dust-value coin sent to that puzzle hash — no special permission, and no relationship to the actual DataLayer store owner is required.

2. **Tracking without authorization check** — When any wallet syncing that coin sees the mirror-puzzle-hash coin, `DataLayerWallet.coin_added()` decodes `launcher_id` and `urls` from the parent spend and, provided the wallet already tracks that `launcher_id` (i.e., the victim is subscribed to or owns that store), inserts the mirror record into `dl_store` — the `ours` flag is computed only for bookkeeping, not as a trust gate [2](#0-1) .

3. **Unfiltered propagation to the DataLayer service** — `DataLayer.get_mirrors()`/`update_subscriptions_from_wallet()` retrieve *all* mirrors for a store from the wallet RPC and merge every URL (own and foreign) into the local subscription URL set with no origin check [4](#0-3) .

4. **Outbound request execution** — `fetch_and_validate()` iterates `get_available_servers_for_store()` (populated from those merged URLs) and passes the `url` into `insert_from_delta_file()` → `download_file()`, which performs `http_download()` (a raw outbound `aiohttp` GET to the attacker-chosen host/port/path) whenever no downloader plugin is registered [5](#0-4) [6](#0-5) .

The retrieved bytes are treated as an untrusted delta file that must reconstruct the wallet-advertised root before being accepted as committed data [7](#0-6) , so this analog does not directly forge store data — but the SSRF itself (arbitrary outbound HTTP request originating from the DataLayer server process, to attacker-chosen internal/external targets) is fully realized before any content validation occurs, matching the CWE-918 class in the reference advisory.

### Impact Explanation
An attacker who can broadcast a single cheap spend bundle (creating a mirror coin for any DataLayer store the victim tracks/owns) can force the victim's `data_layer` service to make outbound HTTP requests to attacker-chosen hosts, including internal network addresses or cloud metadata endpoints (e.g., `169.254.169.254`), from the DataLayer server's network context. This can be used for internal network reconnaissance/pivoting, cloud credential theft via metadata endpoints, or triggering unwanted requests against internal services reachable only from the node's network. Because it also causes repeated retries/backoff bookkeeping (`server_misses_file`, `received_incorrect_file`) tied to attacker-controlled URLs, it can additionally be used to keep the node making periodic outbound requests to attacker infrastructure.

### Likelihood Explanation
Likelihood is high for any operator running a DataLayer service that tracks (owns or subscribes to) at least one store: creating the mirror coin requires only a standard spend with a small XCH amount plus fee, and the victim's wallet automatically ingests and stores the URLs without validating the sender/owner. No cooperation or compromise of the DataLayer owner's keys is needed — the reference to attacker capability is limited to "an entity able to submit a spend bundle," which is explicitly in scope.

### Recommendation
- Do not merge mirror URLs from non-owned (`ours == False`) mirror coins into the fetch/subscription URL set used for outbound HTTP by default; require explicit user opt-in (e.g., an allowlist or a "trust untrusted mirrors" config flag) before treating third-party mirror URLs as fetchable servers.
- Validate/restrict mirror URLs before use: reject non-HTTP(S) schemes, private/loopback/link-local/metadata IP ranges (SSRF-style destination filtering) unless explicitly permitted by configuration, and require DNS-resolution-time checks (to also cover DNS rebinding).
- Consider gating outbound fetch attempts by a maximum-count / rate limit per launcher_id and per URL origin to reduce abuse even for legitimate mirrors.

### Proof of Concept
1. Attacker identifies a `launcher_id` that the victim's DataLayer wallet tracks (any publicly known/subscribed store id works, since store ids are not secret).
2. Attacker submits a standard wallet spend that creates a coin with puzzle hash `create_mirror_puzzle().get_tree_hash()` and memo `[launcher_id, b"http://169.254.169.254/latest/meta-data/", ...]` — this is a normal `CREATE_COIN` condition, reachable with a single signed spend bundle from any funded key [1](#0-0) .
3. Once confirmed, the victim's `DataLayerWallet.coin_added()` picks up the coin (since it matches `create_mirror_puzzle()` puzzle hash and a tracked `launcher_id`) and stores the attacker URL as a `Mirror` record [2](#0-1) .
4. During the victim's periodic sync loop, `update_subscriptions_from_wallet()` merges this URL into local subscriptions [3](#0-2) , and `fetch_and_validate()` eventually selects this server and calls `download_file()` → `http_download()`, issuing an outbound GET to the attacker-chosen URL from the victim node [8](#0-7) [6](#0-5) .

def create_mirror_puzzle() -> Program:
    return P2_PARENT.curry(Program.to(1))


MIRROR_PUZZLE_HASH = create_mirror_puzzle().get_tree_hash()


def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]

async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True
