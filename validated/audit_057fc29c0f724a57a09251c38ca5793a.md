### Title
Mempool queue-capacity DoS: sybil accounts with unfillable nonce-gapped transactions permanently occupy `NonExecSlotsAll` and block admission of new senders' transactions - (File: `blockchain/tx_pool.go`)

### Summary
Kaia's `TxPool` (`blockchain/tx_pool.go`) enforces global capacity through `ExecSlotsAll`/`NonExecSlotsAll` rather than Monad's `MAX_ADDRESSES`, but the same underlying flaw exists: eviction of over-capacity non-executable ("queue") transactions never removes an account's lowest-nonce transaction, and admission of a brand-new sender when the pool is full is rejected outright without any fee-based cross-account eviction. An attacker can therefore submit one deliberately nonce-gapped, minimally-funded transaction from many sybil accounts to permanently squat on the pool's non-executable slot capacity, denying legitimate new senders the ability to get their first transaction admitted, and this can be renewed indefinitely at negligible cost.

### Finding Description
Two structural gaps in the queue eviction/admission logic combine to reproduce the reported bug class:

1. **Admission-time cross-account eviction only applies to existing senders.** When the pool is at capacity, `add()` checks `pool.all.Slots()+numSlots(tx) > pool.config.ExecSlotsAll+pool.config.NonExecSlotsAll`. If the new transaction's sender has no existing queue entry (`pool.queue[from] == nil`), the transaction is rejected outright: [1](#0-0) 
   Only senders who already have a queued transaction get the benefit of the fee-based, global `pool.priced.Discard` eviction path (steps 3–4): [2](#0-1) 
   This means a genuinely new sender's higher-fee transaction can never displace an existing lower-fee squatter once the pool is saturated — the exact cross-address eviction gap called out in the source report (contrasted there with Geth's `legacypool.go#L743` behavior).

2. **Queue-cap eviction never removes an account's frontier (lowest-nonce) transaction**, so an address holding a single always-nonce-gapped transaction can never be forced out by the periodic capacity trim in `promoteExecutables`: [3](#0-2) 
   The inner loop explicitly stops at index `1` (`i >= 1`), deliberately preserving index `0` "so missing-nonce admission can heal it." If many sybil accounts each hold exactly one gapped transaction, this eviction pass makes no progress at all, and `queued` can remain above `NonExecSlotsAll` indefinitely.

3. **The only mechanism that fully clears a stuck account is `Lifetime`-based eviction**, gated by `pool.beats[addr]`, which is set only when the queue entry is first created: [4](#0-3) 
   and consumed by the ticker in `loop()`: [5](#0-4) 
   Because the beat is not refreshed on replacement, a squatting address is fully evicted only after `Lifetime` elapses — but the attacker can trivially resubmit a fresh (new-hash) nonce-gapped transaction from the same or a new sybil address just before/after that expiry, resetting the beat and renewing the squat indefinitely at negligible transaction cost.

Admission still requires the sender to cover `tx.Cost()` (value + gas*price): [6](#0-5) 
but this cost can be made arbitrarily small (near-zero value, minimum gas limit, minimum accepted gas price), so funding many sybil accounts is cheap relative to the denial-of-service achieved.

### Impact Explanation
An attacker who fills the queue's `NonExecSlotsAll` capacity with sybil accounts holding single, permanently nonce-gapped transactions denies all new (never-before-seen) senders the ability to get their first transaction into the pool, regardless of the fee they offer, because the fee-based `priced.Discard` eviction path is only reachable for senders that already occupy a queue slot. This is a network-wide denial-of-service against transaction admission reachable by any unprivileged, unfunded-beyond-trivial-amounts public RPC caller — no validator or node privilege required. It matches the "High Risk" categorization of the analogous Monad report: mempool capacity hogging that blocks legitimate transaction submission.

### Likelihood Explanation
The attack requires only ordinary `eth_sendRawTransaction`/`AddRemote` calls with intentionally nonce-gapped transactions and enough sybil private keys/funding to reach `NonExecSlotsAll` slots — no special privileges, timing races, or consensus-level access are needed. The only friction is the recurring cost of refreshing squatting transactions before `Lifetime` expires, which is minimal and can be automated cheaply. This is a straightforward, reproducible griefing vector.

### Recommendation
- In `add()`, when the pool is full and the sender has no existing entry, do not reject unconditionally — compare the incoming transaction's fee against the pool's globally cheapest transaction (via `pool.priced`) and admit/evict accordingly, mirroring the fee-based Discard logic already used for existing senders.
- In the `promoteExecutables` queue-cap eviction, allow full removal of an address's only (frontier) transaction when it has been nonce-gapped/non-executable for longer than a bounded grace period, rather than unconditionally preserving index 0 forever.
- Track and demote/evict addresses whose queue contains only non-executable (nonce-gapped) transactions more aggressively, independent of the `beats` refresh being resettable by resubmission (e.g., use a monotonic "first seen" watermark per nonce-gap rather than resetting on every re-creation).

### Proof of Concept
1. Configure/observe a node with `NonExecSlotsAll = N`.
2. Generate `N` sybil private keys, fund each with the minimal balance needed to cover `gas*price` for a trivial transaction (`value = 0`, minimal accepted `gasPrice`, minimal `gasLimit`).
3. From each sybil address, submit a single transaction with `nonce = currentNonce + 1` (a nonce gap), via `AddRemote`/`eth_sendRawTransaction`. Each lands in `pool.queue[addr]` as a one-element list; `queuedCount` reaches `N`.
4. Submit a transaction from a genuinely new address (`pool.queue[from] == nil`) with a high gas price. Observe it is rejected with `"txpool is full"` per `blockchain/tx_pool.go:1174`, with no attempt to compare its fee against the cheap sybil squatters.
5. Before `Lifetime` elapses for each sybil address, resubmit a new nonce-gapped transaction (new hash, e.g., bump gas price by 1) from the same sybil key to recreate `pool.queue[addr]` and refresh `pool.beats[addr]`, indefinitely preventing lifetime-based eviction while permanently denying admission to new, possibly higher-fee, senders.
