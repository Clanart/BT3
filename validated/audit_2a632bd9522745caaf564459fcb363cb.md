## Analysis

**Core broken invariant in the external report:** a permissionless "deliver work → prove delivery → get reimbursed" pipeline has an early-return branch that skips the state write which gates reimbursement, so the party that did the work (and paid gas) can never collect what it's owed.

**Local analog found:** `EvmHost.dispatchIncoming(PostRequest, address relayer)`.

### Title
Relayer delivery receipt is never recorded when the destination contract has no code, permanently blocking relayer fee reimbursement - (File: `evm/src/core/EvmHost.sol`)

### Summary
`dispatchIncoming(PostRequest memory request, address relayer)` is the handler-only entrypoint that `HandlerV2.handlePostRequests()` calls after a relayer has already paid gas to submit and verify a state proof for an incoming `PostRequest`. Before doing anything else, the function checks whether `request.to` has deployed code, and if not, returns immediately: [1](#0-0) 

```solidity
function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
    address destination = _bytesToAddress(request.to);
    uint256 size;
    assembly { size := extcodesize(destination) }
    if (size == 0) {
        // instead of reverting the entire batch, early return here.
        return;
    }

    // replay protection
    bytes32 commitment = request.hash();
    _requestReceipts[commitment] = relayer;
    ...
```

### Finding Description
`_requestReceipts[commitment] = relayer` is the on-chain fact that a relayer delivered this request. It is what the source-chain fee-claim/accumulation pipeline later proves via a destination state proof against the `RequestReceipts` slot to release the relayer's escrowed fee — exactly the same pattern used by the pallet-relayer outbound-delivery-reward claim, which fails the claim with `OutboundDeliveryNotProven` if the receipt slot is empty: [2](#0-1) 

Because the `size == 0` branch returns *before* `_requestReceipts[commitment]` is ever written, a relayer that:
1. observed a valid `PostRequest` whose `to` field encodes an address with no deployed contract code (an EOA, an address not yet deployed, or simply a bad/garbage `to` set by the sending application), and
2. spent real gas submitting `handlePostRequests()` (state proof verification, ~150k gas, plus calldata) so that Hyperbridge processed and accepted the message,

ends up with no receipt recorded at all. This is unlike the `onAccept` revert path a few lines below, which explicitly deletes the receipt "so it can be retried" — a documented, intentional retry semantic. The `size == 0` path has no such semantic: it neither writes nor clears a receipt, and there is no other code path that ever sets `_requestReceipts[commitment]` for this request again, since the message was already consumed from Hyperbridge's perspective (the state root/commitment for that height has already been used to prove delivery to the handler).

The consequence mirrors the Atlas report precisely: an early return skips the accounting step (`_releaseSolverLock()` in Atlas, `_requestReceipts[commitment] = relayer` here) that a downstream settlement function (`_settle()` in Atlas, the `OutboundRequestDeliveryClaim`/state-proof reimbursement flow here) depends on to reimburse the party who fronted gas.

### Impact Explanation
The relayer's escrowed fee (recorded on the source chain per [3](#0-2)  / `RequestPayments`/`FeeMetadata`) can never be claimed, because the claim/proof pipeline requires proving a non-empty `RequestReceipts[commitment]` slot on the destination, which will never exist. If `request.timeoutTimestamp` is `0` (no timeout, a valid and documented configuration) or the timeout has already elapsed at time of delivery, the escrowed relayer fee becomes permanently unclaimable and unrefundable — a genuine, protocol-level loss/lock of funds reachable without any privileged actor, malicious relayer, or malicious prover. Even when a timeout eventually fires, the relayer still loses the gas it already spent honestly delivering the message, with the fee being refunded to the payer instead of the relayer that did the work, which is a "wrong beneficiary" outcome, not a fair fund flow.

### Likelihood Explanation
Any application can dispatch a `PostRequest` whose `to` encodes an address without code (deliberately, by bug, or because the destination contract genuinely hasn't been deployed yet at that address on that chain), and delivery via `handlePostRequests()` is fully permissionless as documented: [4](#0-3) . No relayer collusion, admin action, or malicious prover is required — a single legitimate relayer processing a normal message batch that happens to include one bad `to` address triggers the bug.

### Recommendation
Before the `size == 0` early return, still record the delivery receipt (`_requestReceipts[commitment] = relayer`) so the relayer can later prove delivery and claim its fee, exactly as is already done for the successful-call path. Alternatively, revert the whole request/refuse it earlier in `HandlerV2` validation so it never reaches `dispatchIncoming` with an undeployed `to`, and ensure the relayer fee is reimbursed (or the request is explicitly failed) rather than silently dropped without any receipt.

### Proof of Concept
1. Application on chain A dispatches `DispatchPost{ to: <address with no code on chain B>, timeout: 0, fee: X }`.
2. Relayer observes the request, builds a valid state/consensus proof, and calls `HandlerV2.handlePostRequests()` on chain B, which internally invokes `EvmHost.dispatchIncoming(request, relayer)`.
3. `extcodesize(destination) == 0` → function returns at line 802 without setting `_requestReceipts[commitment]`.
4. `PostRequestHandled` event is never emitted; `_requestReceipts[commitment]` stays `address(0)` forever.
5. Relayer (or anyone) attempts the fee/reward claim flow that requires proving `RequestReceipts[commitment] != address(0)` on chain B — this proof can never be produced, so the escrowed relayer fee on chain A is permanently stuck (timeout `0`) or eventually refunded to the payer instead of the relayer who paid the delivery gas.

    function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
        address destination = _bytesToAddress(request.to);
        uint256 size;
        assembly {
            size := extcodesize(destination)
        }
        if (size == 0) {
            // instead of reverting the entire batch, early return here.
            return;
        }

        // replay protection
        bytes32 commitment = request.hash();
        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)
            .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));

        if (!success) {
            // so that it can be retried
            delete _requestReceipts[commitment];
            return;
        }
        emit PostRequestHandled({commitment: commitment, relayer: relayer});
    }
