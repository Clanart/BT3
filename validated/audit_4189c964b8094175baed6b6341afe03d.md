### Title
Silent remote-URL hijack via unvalidated GitHub API `clone_url` - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
The report's broken invariant is "an untrusted external data source (an oracle/API return value) is trusted and used to update critical state without validating it comes from a legitimate, expected source." The GitHub Desktop analog is `updateRemoteUrl()`, which automatically rewrites a repository's `origin` remote URL using `apiRepo.clone_url` — a field taken directly from a `IAPIRepository`/`IAPIFullRepository` object returned by the GitHub API — without verifying that the new URL still points at the expected host/account endpoint.

### Finding Description
`updateRemoteUrl` computes whether to auto-update the local `origin` remote based only on: (1) protocol scheme equality, and (2) whether the *previous* API-reported clone URL still matches the current remote: [1](#0-0) 

The comparison helper `urlMatchesRemote`/`parseRemote` only checks that owner+name+hostname of two URLs are internally consistent with each other; it never checks the new URL's hostname against the account's actual configured endpoint (e.g., the GHES server the user added): [2](#0-1) [3](#0-2) 

Because `IAPIRepository.clone_url` (and `ssh_url`) are plain strings returned by the API response object with no server-identity check: [4](#0-3) 

if the value of `clone_url`/`ssh_url` from a connected (GitHub Enterprise) account is attacker-influenced — an explicitly valid attacker primitive per the task ("a GitHub API object") — `updateRemoteUrl` will call `gitStore.setRemoteURL(...)`, which shells out to `git remote set-url` with that value taken verbatim: [5](#0-4) 

This is the corrupted value: the local `origin` remote URL, which subsequent `git fetch`/`git push`/`git pull` operations use, silently becomes attacker-controlled.

### Impact Explanation
If exploited, all future `git push`/`git fetch` traffic for the repository is silently redirected to a host the victim never chose, while the UI still shows the same repository/owner/name. This is a direct instance of "silent corruption of what the user commits or pushes" from the task's valid-impact list: credentials embedded in the push URL, or the delivered code, could be exfiltrated to an attacker server, and the developer's contributions could be diverted without any explicit approval dialog (the update happens automatically as part of repository/account refresh, not as a user-initiated "Repository Settings" edit like the guarded flow in `repository-settings.tsx`).

### Likelihood Explanation
The update only fires when `protocolsMatch && remoteUrlUnchanged && !urlsMatch` — i.e., when the user hasn't manually edited the remote away from what the API previously reported. This is the common case for most users (default remote as created by clone/API). The trigger is an automatic background refresh (`app-store.ts` invokes `updateRemoteUrl` as part of normal repository state refresh), requiring no user click beyond having previously added/authenticated against the (compromised or malicious) GitHub Enterprise account whose API responses feed this code path. No `--` argument-injection or local access is needed — the flaw is a pure missing-validation trust issue, directly parallel to the oracle report's core complaint ("no validation checks are performed on the retrieved price ... vulnerable to manipulation" and "no way to update/verify the oracle address is legitimate").

### Recommendation
Before calling `setRemoteURL`, validate that the new `clone_url`/`ssh_url` hostname matches the account's known endpoint (`gitHubRepository.endpoint` / the account that authenticated the API call), not just that it's internally consistent with the previous API value. Reject and log (rather than silently apply) any auto-update whose resolved hostname differs from the expected endpoint host, and require explicit user confirmation for any remote URL change that alters the hostname component.

### Proof of Concept
1. Add a GitHub Enterprise Server account in Desktop and clone a repository from it, creating `origin` pointing at `https://ghe.example.com/org/repo.git`.
2. Compromise or MITM the GHES instance (or have a malicious/rogue GHES admin) so that a subsequent `GET repos/org/repo` API call returns `clone_url: "https://evil.attacker.example/org/repo.git"` while leaving `owner`/`name` unchanged.
3. On the next automatic repository refresh, `app-store.ts` invokes `updateRemoteUrl(gitStore, gitHubRepository, apiRepo)`.
4. Since `protocolsMatch` is true (https==https) and `remoteUrlUnchanged` is true (user never manually edited the remote), the guard passes and `gitStore.setRemoteURL('origin', 'https://evil.attacker.example/org/repo.git')` is called, silently rewriting `origin` in `.git/config`.
5. The next `git push`/`git fetch` performed by the user through Desktop's UI (which still displays the original repository name) now transmits to `evil.attacker.example`. [6](#0-5)

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}

const remoteRegexes: ReadonlyArray<{ protocol: GitProtocol; regex: RegExp }> = [
  {
    protocol: 'https',
    regex: new RegExp(
      '^https?://(?:.+@)?(.+)/([^/]+)/([^/]+?)(?:/|\\.git/?)?$'
    ),
  },
  {
    protocol: 'ssh',
    regex: new RegExp('^git@(.+):([^/]+)/([^/]+?)(?:/|\\.git)?$'),
  },
  {
    protocol: 'ssh',
    regex: new RegExp(
      '^(?:.+)@(.+\\.ghe\\.com):([^/]+)/([^/]+?)(?:/|\\.git)?$'
    ),
  },
  {
    protocol: 'ssh',
    regex: new RegExp('^git:(.+)/([^/]+)/([^/]+?)(?:/|\\.git)?$'),
  },
  {
    protocol: 'ssh',
    regex: new RegExp('^ssh://git@(.+)/(.+)/(.+?)(?:/|\\.git)?$'),
  },
]

/** Parse the remote information from URL. */
export function parseRemote(url: string): IGitRemoteURL | null {
  for (const { protocol, regex } of remoteRegexes) {
    const match = regex.exec(url)
    if (match !== null && match.length >= 4) {
      return { protocol, hostname: match[1], owner: match[2], name: match[3] }
    }
  }

  return null
}
