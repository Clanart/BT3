### Title
Permanent, path-only `safe.directory` trust grants let a repo-jacked/attacker-controlled clone silently bypass Git's ownership-mismatch protection on "Clone Again" - (File: `app/src/lib/git/config.ts`)

### Summary
Desktop's "Trust Repository" flow permanently whitelists a local path in the global Git config via `addSafeDirectory`, and there is no code path anywhere in the app that ever removes an entry from `safe.directory`. Because the trust decision is bound only to a filesystem path (not to the identity/ownership of the content at that path), and because `MissingRepository.cloneAgain` re-clones into that exact same path using a GitHub API-derived `cloneURL`, an attacker who gains control of the GitHub repository referenced by that URL (e.g. via a repo-jacking/rename-and-reclaim attack) can have their malicious content cloned into a path that Desktop will never again flag as "unsafe," even though ownership/content has completely changed.

### Finding Description
`addSafeDirectory` adds a path to the global `safe.directory` Git config setting and is only ever additive: [1](#0-0) [2](#0-1) 

Both UI entry points that surface the "unsafe repository" warning call this same one-way function and never call anything to revoke it: [3](#0-2) [4](#0-3) 

A search of the codebase for a removal counterpart (`removeSafeDirectory`) returns no results — the only two hits for `safe.directory` are the config helper itself and a unit test, confirming there is no revocation mechanism.

Separately, when a tracked repository's local folder goes missing, `MissingRepository` offers "Clone Again," which re-clones using the GitHub-API-sourced `cloneURL` into the *same original local path*: [5](#0-4) 

The broken invariant mirrors the governance report exactly: a security-relevant decision ("this path/member is no longer trusted/removed") has no persisted history and can be silently overridden by a different actor (here, Git's ownership guard is overridden by Desktop's own irrevocable allow-list) re-establishing the previous state under new, attacker-controlled content — the path is the same, but who/what controls it has changed, and the system has no memory of that change.

### Impact Explanation
If the GitHub repository behind `cloneURL` is repo-jacked (deleted/renamed and reclaimed by an attacker under the same owner/name — a well-documented GitHub attack class), "Clone Again" will silently populate the user's already-safe-directory-listed path with attacker-controlled files. Because the path is already in `safe.directory`, Git's ownership-mismatch protection — the only defense-in-depth check against untrusted content in this exact scenario — is permanently bypassed for that path, regardless of who now controls the content there. This can lead to execution of attacker-supplied build tooling/hooks configuration once the user performs normal Desktop operations (commit, pull, etc.) that Desktop already treats as trusted.

### Likelihood Explanation
Moderate-to-low. It requires: (1) the user to have previously trusted a path via the "unsafe repository" prompt or missing-repository flow, (2) the original GitHub repository to later become available for takeover (rename/deletion) at the same owner/name, and (3) the user to use "Clone Again" rather than re-adding manually. No local/physical access or pre-existing malware is required — the trigger is entirely a GitHub-API-controlled object (the repository the `cloneURL` resolves to) which fits the accepted attacker model (attacker-controlled git remote/GitHub object).

### Recommendation
- Add a way to revoke `safe.directory` entries when a repository is removed from Desktop or when "Clone Again" targets a path previously trusted for a *different* repository/remote identity.
- Re-run the unsafe-ownership check after any reclone and re-prompt for trust rather than relying on a stale, path-only allow-list.
- Consider binding trust decisions to more than just the path (e.g., also validate that the cloned remote/owner identity matches what was previously trusted).

### Proof of Concept
1. User adds/clones repository `R` at local path `P`; Git flags ownership mismatch; user clicks "Trust Repository," calling `addSafeDirectory(P)`, permanently adding `P` to the global `safe.directory` list.
2. User's OS deletes `P` (e.g., disk cleanup) but Desktop still tracks `R` with its GitHub-derived `cloneURL`.
3. The upstream GitHub repository referenced by `cloneURL` is renamed/deleted and reclaimed by an attacker under the same owner/name (repo-jacking).
4. User clicks "Clone Again" in `MissingRepository`; Desktop clones the attacker's repository into `P` again.
5. Because `P` is already listed in `safe.directory`, Git raises no ownership warning and Desktop performs no re-validation, so the attacker's content is treated as fully trusted for all subsequent Desktop-driven git operations.

```typescript
/**
 * Adds a path to the `safe.directories` configuration variable if it's not
 * already present. Adding a path to `safe.directory` will cause Git to ignore
 * if the path is owner by a different user than the current.
 */
export async function addSafeDirectory(path: string) {
  // UNC-paths on Windows need to be prefixed with `%(prefix)/`, see
  // https://github.com/git-for-windows/git/commit/e394a16023cbb62784e380f70ad8a833fb960d68
  if (__WIN32__ && path[0] === '/') {
    path = `%(prefix)/${path}`
  }

  await addGlobalConfigValueIfMissing('safe.directory', path)
}
```

```typescript
/** Set the global config value by name. */
export async function addGlobalConfigValueIfMissing(
  name: string,
  value: string
): Promise<void> {
  const { stdout, exitCode } = await git(
    ['config', '--global', '-z', '--get-all', name, value],
    __dirname,
    'addGlobalConfigValue',
    { successExitCodes: new Set([0, 1]) }
  )

  if (exitCode === 1 || !stdout.split('\0').includes(value)) {
    await addGlobalConfigValue(name, value)
  }
}
```

```typescript
  private cloneAgain = async () => {
    const gitHubRepository = this.props.repository.gitHubRepository
    if (!gitHubRepository) {
      return
    }

    const cloneURL = gitHubRepository.cloneURL
    if (!cloneURL) {
      return
    }

    try {
      await this.props.dispatcher.cloneAgain(
        cloneURL,
        this.props.repository.path
      )
    } catch (error) {
      this.props.dispatcher.postError(error)
    }
  }
```
