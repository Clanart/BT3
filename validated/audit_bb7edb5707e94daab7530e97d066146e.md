### Title
`SignableTransaction::new` omits the OP_RETURN output from the weight/fee calculation, undercharging the fee and bypassing the max-weight check - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
`SignableTransaction::new` accepts an optional `data` argument which appends an OP_RETURN output of up to 80 bytes to the transaction. However, both calls to `calculate_weight_vbytes` only account for `payments` and `change` — the OP_RETURN output is pushed into `tx_outs` but never included in the transaction template used to derive `weight`, `vbytes`, and therefore `needed_fee`. The result is a fee charged below the requested `fee_per_vbyte` rate, and a `MAX_STANDARD_TX_WEIGHT` check evaluated against a smaller transaction than the one actually produced.

### Finding Description
In `SignableTransaction::new`, the OP_RETURN output is appended to `tx_outs` before the fee/weight calculation, but `calculate_weight_vbytes` is invoked with `payments` (which excludes the data output):

```rust
// networks/bitcoin/src/wallet/send.rs
if let Some(data) = data {
  tx_outs.push(TxOut { value: Amount::ZERO, script_pubkey: ScriptBuf::new_op_return(...) })
}
let (mut weight, vbytes) = Self::calculate_weight_vbytes(tx_ins.len(), payments, None);
let mut needed_fee = fee_per_vbyte * vbytes;
```

Inside `calculate_weight_vbytes`, `tx.output` is built solely from `payments` and the optional `change` — the OP_RETURN output contributes nothing to `weight`/`vbytes`. The second call for `fee_with_change` has the same omission. Consequently:

- `needed_fee = fee_per_vbyte * vbytes` is computed over a transaction missing up to ~89 bytes of output (1-byte value/length fields aside, an 80-byte OP_RETURN plus output overhead).
- The `TooLowFee` check (`needed_fee < DEFAULT_MIN_RELAY_TX_FEE * vbytes / 1000`) is evaluated against the underestimated size, so a transaction whose *actual* fee rate falls below the minimum relay fee can still be accepted.
- `weight > MAX_STANDARD_TX_WEIGHT` is checked on the reduced weight, so the function can return a `SignableTransaction` whose real weight exceeds the standardness limit.
- `needed_fee()`/`fee()` documentation states the actual fee is `sum(inputs) - sum(outputs)`; with a change output the change is computed as `input_sat - payment_sat - fee_with_change`, locking the fee to a value that does not reflect the true serialized size.

### Impact Explanation
Any caller passing `data` produces a transaction paying less than the specified fee rate — effectively a partially "free" output appended to the transaction, analogous to the reference bug where swap proceeds are not reduced by the charged fee while the protocol proceeds as if it were. Concretely:

- The effective sat/vbyte of the signed transaction is lower than `fee_per_vbyte`, and can silently drop below the minimum relay fee, causing the transaction to be rejected by the network (funds become temporarily unmovable until reconstructed without data).
- For transactions near `MAX_STANDARD_TX_WEIGHT`, the produced transaction can exceed the weight limit and be non-standard/unbroadcastable.
- With a change output, the change amount is inflated relative to what the true fee should leave (change absorbs the undercharged sats), so accounting of `needed_fee` vs. actual relay behavior diverges.

### Likelihood Explanation
The bug triggers deterministically whenever `data` is `Some` — no edge-case ordering or malicious counterparty required. The caller simply supplies up to 80 bytes of data and the resulting transaction is under-priced and potentially over-weight. Severity is bounded (maximum ~80 bytes of unaccounted data, so the effective fee deviation and weight overrun are limited), keeping this at Medium rather than High, but the accounting is unconditionally wrong whenever the feature is used.

### Recommendation
Include the OP_RETURN output in the size calculation — e.g., pass the already-constructed `tx_outs` (or an equivalent representation including the data output) into `calculate_weight_vbytes` instead of `payments`, for both the no-change and with-change calls.

### Proof of Concept
```rust
// networks/bitcoin/src/wallet/send.rs (conceptual test)
let inputs = vec![received_output]; // sufficiently funded input
let payments = vec![(p2tr_script_buf(key).unwrap(), 1000)];
let data = Some(vec![0u8; 80]);

let tx = SignableTransaction::new(inputs, &payments, None, data, fee_per_vbyte).unwrap();

// The serialized transaction includes the OP_RETURN output:
let real_vbytes = tx.transaction().vsize() as u64;
// needed_fee only covers vbytes *without* the OP_RETURN output:
assert!(tx.needed_fee() < fee_per_vbyte * real_vbytes);
// Effective fee rate is below the requested rate:
// tx.fee() / real_vbytes < fee_per_vbyte
```
