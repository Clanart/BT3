### Title
`ReceivedOutput::read` accepts an unvalidated spend-key `offset` not bound to the output's `script_pubkey`, letting crafted bytes register unspendable outputs as received - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The PostgreSQL advisory concerns an attacker-controlled artifact causing a trusted routine to write attacker-chosen content to an attacker-influenced location (symlink-following file overwrite). The structural analog in Serai is a deserialization sink that writes attacker-chosen fields into a trusted `ReceivedOutput` record — an `offset` scalar that dictates the key under which the output will later be spent — with no cryptographic binding between `offset`, `output.script_pubkey`, and `outpoint`. `ReceivedOutput::read` in `networks/bitcoin/src/wallet/mod.rs` is explicitly an untrusted-bytes entry point per the threat model, and it performs zero consistency checks.

### Finding Description
`Scanner` is the legitimate producer of `ReceivedOutput`s: `scan_transaction` only constructs one when `self.scripts.get(&output.script_pubkey)` matches a registered offset, so honestly-produced values always satisfy `script_pubkey == p2tr(key + G*offset)` [1](#0-0) . `ReceivedOutput::read`, however, deserializes `offset` (a `Scalar` via `Secp256k1::read_F`), a `TxOut`, and an `OutPoint` verbatim from the byte stream and returns them as a fully-formed `ReceivedOutput` [2](#0-1) . Nothing verifies that the encoded `script_pubkey` actually corresponds to `key + G*offset`, nor that the outpoint/output pair is real. The downstream spend path re-keys per input using `output.offset()` (the "scalar offset to obtain the key usable to spend this output" [3](#0-2) ), so a wrong offset produces a signature that cannot satisfy the actual Taproot key. Just as `pg_basebackup` trusted attacker-influenced file contents/paths, `ReceivedOutput::read` trusts attacker-influenced fields that later control which key signs for funds.

### Impact Explanation
Any consumer that ingests a serialized `ReceivedOutput` from an untrusted or corrupted source (network message, replicated state, forwarded backup of scanner state) can be made to (a) report a received balance for an output the multisig cannot spend — because the stored `offset` does not re-key to the output's actual script — satisfying the accepted "funds reported received that are not spendable" impact; or (b) cause the signing pipeline to produce invalid signatures for a real output, burning time/fees and effectively freezing funds routed through that input. There is also no verification that `outpoint` refers to a confirmed output, enabling phantom-balance reporting.

### Likelihood Explanation
The flaw requires attacker-controlled bytes to reach `ReceivedOutput::read`. Within the strict threat model (untrusted bytes fed to `ReceivedOutput::read`), this is reachable by design — the function is `pub` under `feature = "std"` and validates nothing. Exploitation severity depends on whether an integrator ever deserializes outputs from a less-trusted channel rather than generating them locally via `Scanner::scan_transaction`/`scan_block` [4](#0-3) . The cryptographic primitive misuse itself (accepting the tuple without consistency checks) is unconditional in the code.

### Recommendation
Either remove `read`/`write` from `ReceivedOutput`'s public API (treat it as an internal scanner product), or add a `verify(&self, key: &ProjectivePoint) -> bool` that checks `p2tr_script_buf(*key + (ProjectivePoint::GENERATOR * self.offset)) == Some(self.output.script_pubkey)` and call it after deserialization. Consumers should additionally confirm the `outpoint` exists and is mature on-chain before crediting value.

### Proof of Concept
```rust
// networks/bitcoin: attacker bytes reach ReceivedOutput::read
let mut buf = vec![];
buf.extend(Scalar::from(7u64).to_bytes());          // arbitrary offset, unrelated to output
buf.extend(serialize(&TxOut {
  value: Amount::from_sat(1_000_000),
  script_pubkey: victim_multisig_script,            // real script of the multisig's base key
}));
buf.extend(serialize(&OutPoint::new(fake_txid, 0)));
let forged = ReceivedOutput::read(&mut buf.as_slice()).unwrap();
// forged.value() == 1_000_000 reported received, yet offset != required tweak:
// spending re-keys to base_key + G*7, which is NOT the script's key -> signature invalid,
// output unspendable; no error is ever raised by read().
```

  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
