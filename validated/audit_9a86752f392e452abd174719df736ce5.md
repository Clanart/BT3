### Title
Ed448 point decoding accepts torsion points, enabling Schnorr signature forgery - ([File: crypto/ed448/src/point.rs](crypto/ed448/src/point.rs))

### Summary
Medium. Ed448 point deserialization intends to reject non-prime-order points, but `Point::is_torsion_free` is a tautology: it computes `(-P) + P` and checks whether the result is identity, which is true for every valid curve point. Consequently, canonical encodings of low-order Ed448 points pass `from_bytes`, `Ciphersuite::read_G`, and FROST’s stricter `Curve::read_G` as long as they are non-identity. This permits a forged Schnorr signature under a malformed order-2 public key whenever the challenge is even.

### Finding Description
`Point::is_torsion_free` is implemented as `((*self * (Scalar::ZERO - Scalar::ONE)) + self).is_identity()`. Since `Scalar::ZERO - Scalar::ONE` represents `q - 1`, this expression is `-P + P` for a prime-order point and therefore always identity for every group element, including points carrying Ed448’s cofactor torsion. [1](#0-0) 

`GroupEncoding::from_bytes` relies on that predicate as its final acceptance condition after decoding `y`, recovering `x`, and rejecting negative zero. [2](#0-1)  The generic `Ciphersuite::read_G` then accepts any `from_bytes` result whose serialization round-trips, so a canonical low-order point is accepted. [3](#0-2)  FROST’s `Curve::read_G` only adds an identity rejection and does not add a subgroup check. [4](#0-3) 

The order-2 point `(x, y) = (0, -1)` is particularly useful: it is not identity, encodes canonically with a zero sign bit, and should have been rejected by the torsion check. `SchnorrSignature::read` accepts attacker-controlled `R` and `s` through `C::read_G`/`C::read_F`, and verification accepts the equation `R + cA - sG = 0`. [5](#0-4) [6](#0-5)  With `A = (0, -1)`, `R = 0`, and `s = 0`, the equation reduces to `cA = 0`, which holds whenever the scalar challenge `c` is even.

### Impact Explanation
An attacker can deserialize a malformed Ed448 public key consisting of a low-order point and produce a signature that verifies without knowing a discrete logarithm for that key. For Fiat-Shamir Schnorr-style proofs where the challenge binds the key, nonce, and message, the attacker can vary the message or serialized proof context until the derived scalar is even, giving approximately a one-in-two success probability per attempt.

This undermines the `PrimeGroup` contract relied on by the in-scope signature, DKG, DLEq, and FROST code. It can turn point deserialization into acceptance of a key outside the prime-order group and can bypass proof-of-possession or signature checks that assume deserialization already established subgroup membership. `ThresholdKeys::read`, nonce commitments, encryption keys, and Schnorr signatures all consume these unchecked points through the common `read_G` path. [7](#0-6) [8](#0-7) [9](#0-8) 

### Likelihood Explanation
The malformed public key is a single fixed 57-byte encoding of `y = -1` with the sign bit clear. No curve arithmetic or secret information is needed to construct it. A deterministic verifier with an externally supplied challenge is immediately exploitable when `c` is even; a Fiat-Shamir verifier can be exploited by modifying attacker-controlled message bytes until the challenge has the required parity.

The attack does not directly compromise an already-established prime-order public key because the forged public key is a different group element. Its practical severity is therefore limited to protocols that accept attacker-supplied Ed448 keys, proofs of possession, or verification shares without an external trusted-key check.

### Recommendation
Replace the tautological test with an actual prime-order-subgroup test. For Ed448, `[q]P = 0` can be checked without representing `q` as a scalar by testing `[q - 1]P == -P`, for example by comparing `*self * (Scalar::ZERO - Scalar::ONE)` to `-*self`, rather than adding `self` and checking identity. Add regression vectors for at least identity, `(0, -1)`, the order-4 points, and non-canonical encodings, and assert `read_G` rejects each of them.

### Proof of Concept
```rust
use group::{Group, GroupEncoding};
use group::ff::PrimeField;
use ciphersuite::Ciphersuite;
use ed448::{Ed448, FieldElement, Point, Scalar};
use schnorr::SchnorrSignature;

// Canonical encoding of the order-2 point (x, y) = (0, -1).
let mut encoded = (FieldElement::ZERO - FieldElement::ONE).to_repr();
encoded.as_mut()[56] &= 0x7f;

// This should fail subgroup validation, but currently succeeds.
let malformed_key =
  <Ed448 as Ciphersuite>::read_G(&mut encoded.as_ref()).unwrap();
assert!(!bool::from(malformed_key.is_identity()));

// Since malformed_key has order 2, an even challenge annihilates it:
// R + cA - sG = 0 + 2A - 0G = 0.
let forged = SchnorrSignature::<Ed448> {
  R: Point::identity(),
  s: Scalar::ZERO,
};

assert!(forged.verify(malformed_key, Scalar::from(2u64)));
```

For a verifier deriving `c` from a transcript, repeat the submission with mutated attacker-controlled message/ciphertext bytes until the derived scalar is even.
