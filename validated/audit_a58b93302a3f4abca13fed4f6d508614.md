## Finding: Spoofed `WWW-Authenticate` header lets an attacker-controlled git remote trigger a GitHub Enterprise sign-in against its own origin

### Title
Attacker-controlled HTTPS remote can spoof `realm="GitHub"` to force Desktop's credential helper into an Enterprise sign-in flow pointed at the attacker's server - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The M02 report's underlying pattern is that a contract mixes two conceptually distinct value pools (stake vs. prepayment) with no hard boundary, letting an untrusted actor manipulate which pool is affected. The Desktop analog is `getEndpointKind()` in [1](#0-0)  which mixes two conceptually distinct trust classes — "verified GitHub host" vs. "arbitrary/generic host" — using an attacker-suppliable signal (the HTTP `WWW-Authenticate` header echoed back by git) as if it were a trusted boundary, without any authenticity check.

### Finding Description
When Git performs an unauthenticated HTTPS request and receives a `401` response, it forwards any `WWW-Authenticate` header values to the configured credential helper as `wwwauth[]=...` fields. Desktop's trampoline credential helper treats the presence of `realm="GitHub"` in that attacker-controlled header as sufficient evidence that the remote is a GitHub Enterprise host: [2](#0-1) 

This check runs *before* the actual network-based verification (`isGitHubHost(endpoint)`), and there is no cryptographic or otherwise-verified linkage between the header value and the real identity of the server. Any HTTPS git remote (or a MITM/malicious proxy) fully controls this header and can set it to `WWW-Authenticate: Basic realm="GitHub"`.

Once `getEndpointKind` returns `'enterprise'` for the attacker's host, and since no existing account matches that host, `getCredential` triggers a GitHub sign-in prompt directly for the attacker's endpoint: [3](#0-2) 

That calls `trampolineUIHelper.promptForGitHubSignIn(endpoint)`, which — for a non-`github.com` hostname — invokes `dispatcher.beginEnterpriseSignIn(cb)` and `dispatcher.setSignInEndpoint(origin)` using the **attacker-controlled origin**, then shows the sign-in popup: [4](#0-3) 

The enterprise sign-in flow subsequently performs API/OAuth-style authentication calls against that attacker-supplied origin. There is no code path re-validating that the origin used for sign-in is actually a legitimate GitHub Enterprise Server instance before initiating credential collection against it.

### Impact Explanation
If the user completes the prompted sign-in (enters a Personal Access Token, or goes through basic auth/OAuth against what looks like an Enterprise sign-in dialog), the credential material is sent to the attacker's server rather than a real GitHub Enterprise instance, resulting in token/credential exfiltration. Because the endpoint is attacker-chosen, this can also be used to make it appear a repository requires "GitHub Enterprise" authentication when the user simply cloned or fetched from a URL pointing at attacker infrastructure, which is unexpected UX that increases the likelihood a user will enter real GitHub credentials into it.

### Likelihood Explanation
The trigger requires only that the user perform an ordinary Git network operation (clone/fetch/push) against a remote the attacker controls or can intercept (e.g., a malicious/compromised HTTPS git server, or a proxy in a MITM position on an HTTP git URL that gets upgraded/redirected). No local access, no prior malware, and no unnatural steps beyond normal Desktop usage (adding/using a remote) are needed to reach the vulnerable code path; user interaction is required only to complete the resulting sign-in prompt, which is presented as a legitimate-looking Desktop dialog.

### Recommendation
Do not treat the `wwwauth[]` `realm="GitHub"` header as authoritative for classifying a host as an Enterprise GitHub instance. Either remove this heuristic entirely and always fall back to the verified `isGitHubHost(endpoint)` network check, or use the header purely as a hint that still requires the `isGitHubHost` verification (which itself should be hardened, e.g., checking a well-known GitHub-specific API response) before routing to `promptForGitHubSignIn`, so that only cryptographically/behaviorally verified GitHub Enterprise servers can trigger the sign-in flow.

### Proof of Concept
1. Attacker stands up an HTTPS server at `https://evil.example.com/some/repo.git`.
2. The server responds to unauthenticated Git HTTP requests with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
3. Victim adds/clones this URL in GitHub Desktop (e.g., via "Clone repository" with a URL, or an existing remote pointing there).
4. Git invokes Desktop's credential helper trampoline (`createCredentialHelperTrampolineHandler` in [5](#0-4) ) with `wwwauth[]=Basic realm="GitHub"` in the input.
5. `getEndpointKind` classifies `evil.example.com` as `'enterprise'` purely from the header per [6](#0-5) .
6. Since no existing account matches `evil.example.com`, `getCredential` calls `ui.promptForGitHubSignIn('https://evil.example.com')`, which calls `dispatcher.setSignInEndpoint('https://evil.example.com')` and opens the Enterprise sign-in dialog per [7](#0-6) .
7. If the victim enters credentials/PAT in the resulting dialog believing it's a normal GitHub Enterprise prompt, that secret is used against the attacker's origin.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

export const createCredentialHelperTrampolineHandler: (
  store: AccountsStore
) => TrampolineCommandHandler = (store: Store) => async command => {
  const firstParameter = command.parameters.at(0)
  if (!firstParameter) {
    return undefined
  }

  const { trampolineToken: token } = command
  const input = parseCredential(command.stdin)

  if (__DEV__) {
    debug(
      `${firstParameter}\n${command.stdin
        .replaceAll(/^password=.*$/gm, 'password=***')
        .replaceAll(/^(.*)$/gm, '  $1')
        .trimEnd()}`
    )
  }

  try {
    if (firstParameter === 'get') {
      const cred = await getCredential(input, store, token)
      if (!cred) {
        const endpoint = `${getCredentialUrl(input)}`
        info(`could not find credential for ${endpoint}`)
        setHasRejectedCredentialsForEndpoint(token, endpoint)
      }
      return cred ? formatCredential(cred) : undefined
    } else if (firstParameter === 'store') {
      await storeCredential(input, store, token)
    } else if (firstParameter === 'erase') {
      await eraseCredential(input, store, token)
    }
    return undefined
  } catch (e) {
    error(`${firstParameter} failed`, e)
    return undefined
  }
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
