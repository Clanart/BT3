## Analysis

The `SimplexPaymaster.sol` contract implements the exact same Chainlink price-fetching pattern as the reported bug: it validates `answer > 0` and staleness (`updatedAt`), but has no circuit-breaker check against the underlying aggregator's `minAnswer`/`maxAnswer` bounds.

### Title
Missing Chainlink `minAnswer`/`maxAnswer` circuit-breaker check in `SimplexPaymaster` lets users underpay gas fees during a stablecoin depeg, draining the paymaster's native deposit - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`_getOraclePrice` only checks `answer <= 0` and staleness (`block.timestamp - updatedAt > maxOracleAge`), but never checks the returned answer against the feed's aggregator-level `minAnswer`/`maxAnswer` bounds [1](#0-0) . This is the exact analog to the reported `chainlinkOracle.sol` finding: when a Chainlink feed's underlying price crashes past the aggregator's configured floor (e.g. a stablecoin depeg/bank-run event), the aggregator freezes and keeps returning `minAnswer` — a stale-but-"fresh" value that looks perfectly valid to this contract's checks.

### Finding Description
`_tokenPrice` derives the amount of ERC-20 token a UserOp sender must pay per unit of gas using both `nativeOracle` and the registered `tokenOracle` [2](#0-1) :

```
tokenPrice = (nativeUsd * 10^tokenDecimals * (10000+markupBps)) / (tokenUsd * 10000)
```

If the registered stablecoin's price feed (`cfg.tokenOracle`) hits its aggregator floor during a real depeg event (its true market price crashes below `minAnswer`), the feed keeps reporting `minAnswer` — a *higher* USD value than the token is actually worth — while continuously refreshing `updatedAt` so the staleness check never trips. Because `tokenUsd` is artificially inflated in the denominator, the computed `tokenPrice` is understated, meaning the sender is charged **fewer** ERC-20 tokens than the real USD-equivalent cost of the gas the paymaster pays out in native currency via `entryPoint().withdrawTo` / EntryPoint prefund flow.

This mispriced value flows directly into `_fetchDetails`, which is called during permissionless `validatePaymasterUserOp` for every UserOp — an unprivileged, public entrypoint reachable by any account [3](#0-2) . `PaymasterERC20` then computes `erc20Cost = weiCost * tokenPrice / 1e18` and collects only that (undervalued) amount from the sender, while the EntryPoint deposit funded by the paymaster still pays the full, real gas cost in native currency.

The existing guard set is:
```solidity
if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
if (block.timestamp - updatedAt > maxOracleAge) {
    revert StaleOraclePrice(address(oracle), updatedAt);
}
```
Neither guard detects a frozen `minAnswer`/`maxAnswer` value — both checks pass on the aggregator's floor price exactly as in the [M-02] report.

### Impact Explanation
During any real depeg of a registered fee-token (the contract explicitly supports "any token with a Chainlink feed"), an attacker (or every ordinary user, opportunistically) can submit UserOps that get charged a systematically discounted `tokenPrice`, extracting native-currency value from the paymaster's EntryPoint deposit at a rate faster than the treasury replenishes it via `swapAndDeposit`. This is direct, repeatable fund loss from the paymaster's EntryPoint balance, reachable through the fully public, permissionless `validatePaymasterUserOp`/`_postOp` flow with no privileged actor, relayer, or governance action required.

### Likelihood Explanation
Requires an actual stablecoin depeg event pushing the aggregator to its configured floor (comparable to the USDC/SVB or LUNA-class events cited in the source report) — not attacker-controlled, but a realistic and historically observed market condition. Once that condition occurs, exploitation is trivial and automatic for any UserOp sender using the affected token, with no additional privilege needed. `maxOracleAge` and the `answer > 0` check provide no protection against this specific failure mode.

### Recommendation
Configure and check `minAnswer`/`maxAnswer` bounds (fetched from the underlying `AggregatorV2V3Interface` via `aggregator()`, one level through the proxy) in `_getOraclePrice`, reverting when the answer is at or near those bounds, analogous to:
```solidity
require(answer < maxPrice, "Upper price bound breached");
require(answer > minPrice, "Lower price bound breached");
```
Alternatively, cross-check the feed's answer against a secondary/backup oracle before accepting it for fee pricing.

### Proof of Concept
1. Registered stablecoin `T` (`tokenOracle` = Chainlink `T/USD` feed with `minAnswer = 0.90e8`).
2. Market event causes `T`'s real value to crash to `$0.20`; Chainlink's aggregator floors the reported answer at `minAnswer = 0.90e8` and keeps refreshing `updatedAt`.
3. `_getOraclePrice(cfg.tokenOracle, ...)` returns `0.90e8` — passes both `answer > 0` and staleness checks [4](#0-3) .
4. `_tokenPrice` computes a `tokenPrice` based on `T` being worth `$0.90` when it is really worth `$0.20`, understating the true cost by ~4.5x.
5. Any account submits a UserOp with `paymasterData` mode `0x01`/`0x00` using token `T`; `_fetchDetails` returns the deflated `tokenPrice`, so `PaymasterERC20._erc20Cost` charges ~4.5x less `T` than the gas is actually worth [5](#0-4) .
6. Repeating this across many UserOps drains the paymaster's EntryPoint deposit relative to the (undervalued) `T` collected, which is only recyclable at the same broken price via `swapAndDeposit` [6](#0-5) .

```text
    /// @dev Returns the token to charge and its price relative to native gas.
    ///
    ///      PaymasterERC20 computes `erc20Cost = weiCost * tokenPrice / 1e18`,
    ///      so tokenPrice must be token base units per wei, scaled by 1e18:
    ///        tokenPrice = (nativeUsd * 10^tokenDecimals) / tokenUsd
    ///      e.g. BNB at $600, USDC at $1 with 6 decimals: 0.001 BNB (1e15 wei)
    ///      should cost 0.60 USDC (600000 units), giving tokenPrice = 6e8, which
    ///      is exactly (600e8 * 1e6) / 1e8. Markup is applied on top.
    function _fetchDetails(
        PackedUserOperation calldata userOp,
        bytes32 /* userOpHash */
    ) internal view override returns (uint256 validationData, IERC20 token, uint256 tokenPrice) {
        bytes calldata data = userOp.paymasterData();
        if (data.length < 21) revert InvalidPaymasterData(data.length);

        uint8 mode = uint8(data[0]);
        if (mode > 0x01) revert InvalidMode(mode);

        address tokenAddr = address(bytes20(data[1:21]));

        TokenConfig memory cfg = tokenConfigs[tokenAddr];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(tokenAddr);
        if (!cfg.active) revert TokenNotActive(tokenAddr);

        tokenPrice = _tokenPrice(cfg);
        token = IERC20(tokenAddr);
        validationData = 0; // no time-range restriction
    }
```

```text
    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer, , uint256 updatedAt, ) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
```
