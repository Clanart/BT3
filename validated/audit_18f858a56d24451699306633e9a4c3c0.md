### Title
Unauthenticated JSON-RPC `send_tx` + Zero-Input RBF Allows Wallet Drain — (`crates/clementine-tx-sender/src/jsonrpc/server.rs`, `crates/clementine-tx-sender/src/rbf.rs`)

---

### Summary

The tx-sender JSON-RPC server exposes `send_tx` with **no authentication**. An attacker who can reach the port submits a zero-input transaction with an attacker-controlled output and `fee_paying_type=RBF`. The `send_rbf_tx` path skips all input validation when `rbf_signing_info=None`, calls `create_funded_psbt` with `add_inputs=true`, lets the Bitcoin Core wallet add its own UTXOs, signs them via `wallet_process_psbt`, and broadcasts the result — transferring wallet BTC to the attacker.

---

### Finding Description

**1. No authentication on the JSON-RPC server**

`start_jsonrpc_server` uses a bare `ServerBuilder::default()` with no auth middleware, no mTLS, and no API-key check: [1](#0-0) 

The `send_tx` handler deserializes the caller-supplied transaction and calls `insert_try_to_send` without any identity check: [2](#0-1) 

The server can be bound to `0.0.0.0` (explicitly permitted by config), making it reachable from the network: [3](#0-2) 

**2. `insert_try_to_send` performs no structural validation**

The client stores the raw transaction as-is. A zero-input transaction is accepted without error: [4](#0-3) 

**3. Input validation in `send_rbf_tx` is gated on `rbf_signing_info.is_some()`**

The only check that would catch a zero-input transaction is inside an `if let Some(rbf_signing_info)` block. With `rbf_signing_info=None` (which the attacker supplies), the entire block is skipped: [5](#0-4) 

**4. `create_funded_psbt` unconditionally sets `add_inputs: Some(true)`**

With an empty input list, Bitcoin Core's wallet adds its own UTXOs to cover the attacker's output plus fees: [6](#0-5) [7](#0-6) 

**5. `wallet_process_psbt` signs the wallet inputs; `send_raw_transaction` broadcasts**

With `rbf_signing_info=None`, the wallet-signed PSBT is used directly and broadcast: [8](#0-7) [9](#0-8) [10](#0-9) 

**6. `serialize_tx_for_fund_raw` explicitly handles the zero-input case**

The codebase even has a helper that works around Bitcoin Core's segwit-flag deserialization issue for zero-input transactions, confirming this path is reachable: [11](#0-10) 

---

### Impact Explanation

The tx-sender wallet holds BTC used to fee-bump all bridge transactions (kickoff, payout, challenge, reimbursement). An attacker who drains it:
- Directly steals BTC from the tx-sender-managed balance.
- Prevents the bridge from fee-bumping any pending transaction, causing liveness failure across all active bridge flows.

This meets the "theft of tx-sender-managed balances" and "broken bridge liveness with material fund impact" criteria.

---

### Likelihood Explanation

- If `TX_SENDER_JSONRPC_BIND=0.0.0.0`, the endpoint is directly reachable from the network with no credentials.
- Even with the default `127.0.0.1`, any co-located process (SSRF, sidecar, shared pod) can exploit this.
- The attack requires only a single JSON-RPC call with a crafted transaction; no key material, no privileged role.

---

### Recommendation

1. **Add authentication** to the JSON-RPC server (shared secret, mTLS, or restrict callers to a known allowlist).
2. **Validate inputs before wallet funding**: in `send_rbf_tx`, reject any transaction with `tx.input.is_empty()` regardless of `rbf_signing_info`.
3. **Validate outputs**: before calling `create_funded_psbt`, verify that every output script matches an expected bridge script or is a known change address — not an arbitrary caller-supplied address.

pub(crate) fn serialize_tx_for_fund_raw(tx: &Transaction) -> Vec<u8> {
    if tx.input.is_empty() {
        use bitcoin::consensus::Encodable;

        let mut buf = Vec::new();
        // Serialize version
        tx.version
            .consensus_encode(&mut buf)
            .expect("Failed to serialize version");
        // Serialize inputs
        tx.input
            .consensus_encode(&mut buf)
            .expect("Failed to serialize inputs");
        // Serialize outputs
        tx.output
            .consensus_encode(&mut buf)
            .expect("Failed to serialize outputs");
        // Serialize locktime
        tx.lock_time
            .consensus_encode(&mut buf)
            .expect("Failed to serialize locktime");

        buf
    } else {
        bitcoin::consensus::encode::serialize(tx)
    }
}
