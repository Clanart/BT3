### Title
Understated `ReceivedOutput::value` from deserialized bytes silently burns the difference as miner fee - (networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput::read` accepts an attacker-supplied `TxOut` (including its `value`) without any verification that the claimed value matches the real on-chain UTXO. `SignableTransaction::new` then computes payments/change/fees entirely from these claimed values, and `SignableTransaction::multisig` only validates the `script_pubkey` against the offset group key — never the amount. If a `ReceivedOutput` understates the true UTXO value, the constructed transaction is still fully valid on-chain, but the discrepancy is paid out as an excess miner fee — a direct analog of the "fat-fingered value captured by the block producer" bug class.

### Finding Description
- `ReceivedOutput::read` decodes `offset`, `TxOut` (which carries `value`), and `OutPoint` straight from the reader with no consistency check against chain state ( [1](#0-0) ).
- `SignableTransaction::new` sums the claimed input values (`input_sat`) and derives `needed_fee`, the change amount (`input_sat - payment_sat - fee_with_change`), and the `NotEnoughFunds` check purely from those untrusted numbers ( [2](#0-1) ).
- `multisig` verifies only that `prevouts[i].script_pubkey` equals the P2TR script of the offset key; `prevouts[i].value` is never checked ( [3](#0-2) ).
- Signing commits to `Prevouts::All(&self.tx.prevouts)` with `TapSighashType::Default` ( [4](#0-3) ). BIP-341 commits to the prevout *amounts*, so the signatures are valid for whatever claimed values were supplied — but Bitcoin consensus determines the real fee as `sum(real UTXO values) - sum(tx outputs)`. Any gap between a real UTXO's value and the understated claimed value becomes fee paid to the miner.
- The processor deserializes `ReceivedOutput` inside `Output::read` from storage/IPC bytes ( [5](#0-4) ), making this reachable wherever these bytes cross a trust boundary.

### Impact Explanation
An unprivileged party who can feed crafted bytes to `ReceivedOutput::read` (e.g., a corrupted/malicious input source, DB tampering at a non-signer component, or any relayed output record) can cause the threshold signing group to sign a valid transaction that pays the value gap to miners as an unbounded fee — exactly the "excess value captured by the validator" outcome of the reference incident. Conversely, overstating the value produces a transaction that is invalid on-chain (DoS of the plan). Loss of funds is proportional to the value manipulation, up to the entire UTXO.

### Likelihood Explanation
Requires an attacker to control or corrupt the serialized `ReceivedOutput` consumed by a signing participant — in scope per the rules (untrusted bytes to `ReceivedOutput::read`). Within Serai's processor these records are normally self-derived from scanned blocks, so practical exploitability depends on whether replicas accept output data from less-trusted sources; the complete absence of a defense-in-depth check makes the primitive unsafe to expose. Medium-High severity: direct, quantifiable loss of funds with no signature failure or error raised.

### Recommendation
In `SignableTransaction::multisig` (or `new`), verify each `prevouts[i]` against the chain/RPC (`get_transaction` + vout) or require callers to pass outputs obtained only from `Scanner`/`get_outputs`, which derive values from actual blocks. At minimum, add a debug assertion comparing `prevouts[i]` to the real UTXO before signing, and document that `ReceivedOutput::read` must only be used on trusted data.

### Proof of Concept
1. Honest chain state: UTXO at `outpoint X` pays 100,000 sat to the group's P2TR script.
2. Attacker supplies bytes to `ReceivedOutput::read` encoding `offset = 0`, `outpoint = X`, but `TxOut { value: 60_000, script_pubkey: <group script> }`.
3. `SignableTransaction::new(vec![forged], payments=[(dest, 50_000)], change=None, None, fee_rate)` succeeds; `multisig` accepts since the script matches.
4. Participants sign with `Prevouts::All` committing to 60,000; transaction is valid; real fee = 100,000 − 50,000 = 50,000 sat instead of intended ~fee_rate·vbytes, and 40,000 sat is irrecoverably paid to the miner — with no error surfaced anywhere in the pipeline.
