### Title
Gasless Module's Lender Balance Check Is Performed Only Once at Startup, Not Verified When Bundling Lend Transactions - (File: `kaiax/gasless/impl/init.go`)

### Summary
The `kaiax/gasless` module lends gas fees to users via a `LendTxGenerator`-produced transaction funded from the block proposer's (consensus node's) own balance. The proposer's balance is checked for sufficiency only once, at module `Init()` time, and the module is permanently enabled/disabled based on that single snapshot. No balance re-check is performed afterward when `GetLendTxGenerator`/`ExtractTxBundles` builds and includes the lend transaction into a bundle for every subsequent block, mirroring the reported "approval granted without verifying available balance, leading to failed settlement for legitimate users" bug class from the OlympusTreasury report.

### Finding Description
`GaslessModule.Init()` checks the lender's (node's) KAIA balance against `GaslessLenderMinBal` exactly once and sets `GaslessConfig.Disable` accordingly: [1](#0-0) 

`IsDisabled()` simply returns this static flag, which is never updated again during the module's lifetime: [2](#0-1) 

Per-transaction admission (`GetCheckBalance`) validates the *sender's* token balance/allowance for `GaslessApproveTx`/`GaslessSwapTx`, but never re-validates the *lender's* (proposer's) native KAIA balance: [3](#0-2) 

When building blocks, `ExtractTxBundles` unconditionally prepends a `LendTxGenerator`-produced transaction funded from the node's key for every ready gasless approve/swap pair, without checking whether the node currently has sufficient balance to fund it: [4](#0-3) 

`GetLendTxGenerator` constructs a `LendTx` whose `value` equals `lendAmount(approveTxOrNil, swapTx)`, drawn from the node's key, again with no balance check at generation time: [5](#0-4) 

Because the balance check only occurs once at startup, a proposer's KAIA balance can fall below `GaslessLenderMinBal` after repeatedly funding lend transactions for multiple gasless users across many blocks (each `LendTx` deducts value from the proposer), yet the module remains enabled (`Disable` stays `false`), and it keeps constructing and bundling `LendTx`s that the proposer can no longer actually afford.

### Impact Explanation
This is directly analogous to the reported bug class: an approval/readiness decision (module enabled = "lending approved") is made without validating the current balance available to satisfy it. Legitimate gasless users whose `GaslessApproveTx`/`GaslessSwapTx` pair passes all the sender-side checks (`IsExecutable`, `VerifyExecutable`) can still have their bundle fail at inclusion time because the `LendTx` funded by the depleted proposer reverts/fails for insufficient balance. This causes wasted bundling effort, dropped/failed gasless transactions for otherwise valid users, and repeated failure across every block until the module is manually restarted (since `Disable` is never re-evaluated), representing a persistent denial of gasless-swap service for a subset of legitimate senders.

### Likelihood Explanation
Any consensus node running the gasless module with a balance near `GaslessLenderMinBal` (1 KAIA) will exhaust this buffer whenever it proposes several blocks containing multiple gasless swaps, since lend amounts are deducted from its own balance and never replenished/re-checked. This does not require any malicious actor — it is a routine operational condition reachable purely by legitimate gasless users continuing to submit swap requests, which is an in-scope trigger (gasless module, reachable by an unprivileged gasless swap submitter).

### Recommendation
Re-validate the lender's (proposer's) current balance against the cumulative `lendAmount` of all bundles being built for the current block (or at minimum, before generating each `LendTx`) rather than relying solely on the one-time check performed in `Init()`. If insufficient, exclude the affected bundle rather than allowing a doomed `LendTx` to be included, and consider dynamically re-evaluating `GaslessConfig.Disable` per block/per bundle rather than fixing it permanently at node startup.

### Proof of Concept
1. Start a consensus node with the gasless module enabled and a balance just above `GaslessLenderMinBal` (e.g., 1 KAIA + ε), per the check in `Init()`.
2. Have several distinct users submit valid `GaslessApproveTx`/`GaslessSwapTx` pairs across consecutive blocks.
3. For each block, `ExtractTxBundles` generates and bundles a `LendTx` funded from the proposer's key (`GetLendTxGenerator`), deducting real KAIA from the proposer with every gasless swap processed.
4. Once cumulative lending exceeds the proposer's remaining balance, subsequent `LendTx`s fail for insufficient funds even though `GaslessConfig.Disable` is still `false` (it was only checked once at startup), causing otherwise valid gasless bundles from legitimate users to fail inclusion/execution.

func (g *GaslessModule) GetCheckBalance() func(tx *types.Transaction) error {
	return func(tx *types.Transaction) error {
		if approveArgs, ok := decodeApproveTx(tx, g.signer); ok {
			return g.checkBalanceForApprove(approveArgs)
		}
		if swapArgs, ok := decodeSwapTx(tx, g.signer); ok {
			return g.checkBalanceForSwap(swapArgs, tx.Nonce())
		}
		return errors.New("not a gasless transaction") // should not happen because IsModuleTx is called before GetCheckBalance
	}
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}

// MakeLendTx creates a transaction with following properties:
// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)
// L2. LendTx.from = proposer
// L3. LendTx.to = SwapTx.from
// L4. LendTx.value = LendAmount(approveTxOrNil, swapTx)
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}
