### Title
A single malformed/offset-mismatched input aborts signing for every input and payment in the transaction - ([File: networks/bitcoin/src/wallet/send.rs])

### Summary
The reported bug class — one faulty recipient in a loop denying the entire payment batch — maps directly onto `SignableTransaction::multisig` in `networks/bitcoin/src/wallet/send.rs`. The function iterates over every input of the transaction and, on the first input whose `p2tr_script_buf(offset.group_key())` is `None` (odd/infinity tweaked key) or does not equal `self.prevouts[i].script_pubkey`, returns `None` via `None?`. That discards the `Some(TransactionMachine)` result for the entire transaction, so not just the offending input but *all* inputs and *all* payments in the transaction become unsignable in that attempt.

### Finding Description
In `multisig`, each `ReceivedOutput`'s `offset` is applied to the `ThresholdKeys` (`keys.clone().offset(self.offsets[i])`) and the resulting group key is converted to a P2TR script. `p2tr_script_buf` (networks/bitcoin/src/wallet/mod.rs:80-86) returns `None` whenever the point is not even-Y, and any mismatch against the prevout's `script_pubkey` also triggers `None?`. Because the check runs inside the `for i in 0 .. self.tx.input.len()` loop before any `AlgorithmMachine` is created, a single bad input poisons the whole batch — exactly like a reverting `transfer` recipient blocking `pay()`.

The `offset` field is attacker-influenceable: `ReceivedOutput::read` (mod.rs:122-134) deserializes `offset` and `output`/`outpoint` straight from untrusted bytes with no consistency check that `key + G*offset` is even or actually derives the output's `script_pubkey`. The consistency check only happens later, inside `multisig`, where failure aborts the entire transaction rather than rejecting just that output. There is no per-input fallback or claimable-style isolation; the failure mode is all-or-nothing.

### Impact Explanation
Any transaction built with a poisoned `ReceivedOutput` (bad offset, or an offset whose tweaked key is odd → `p2tr_script_buf` → `None`) makes `multisig` return `None`, so the whole `SignableTransaction` — including every other valid input and every payment — cannot produce a `TransactionMachine` and cannot be signed. This yields "funds reported received that are not spendable": scanned/deserialized outputs enter the input set, but constructing the signing machine fails for all of them. While inputs can in principle be re-planned excluding the bad output, nothing in this code path identifies which input was at fault (it returns bare `None` with no error type), so the caller cannot distinguish or prune the poisoned input, and repeated scheduling of the same input set will fail repeatedly.

### Likelihood Explanation
Reachable by an unprivileged party via `ReceivedOutput::read`-fed untrusted bytes (offset + script_pubkey fully attacker-controlled), or via any offset-registration inconsistency where `register_offset`'s increment-until-even behavior (mod.rs:180-196) diverges from the offset stored on the output. It requires the bad output to be included in the input vector of a transaction the wallet tries to sign — plausible since `scan_transaction`/`get_outputs` collect outputs and the scheduler batches them, and a single poisoned entry in `inputs` is sufficient. Impact is a liveness/funds-freeze DoS on the whole transaction, not key recovery or forgery.

### Recommendation
Reject invalid outputs at ingestion, not at signing time: have `ReceivedOutput` construction/`read` verify that `p2tr_script_buf(scanner_key + G*offset)` is `Some` and equals `output.script_pubkey`, so a bad output can never enter the input set. Additionally, change `multisig` to return a per-input error identifying `i` (e.g., `Result<_, UnspendableInput(usize)>`) so callers can drop the single poisoned input instead of losing the entire transaction — the analog of the recommended claimable/per-recipient isolation model.

### Proof of Concept
```rust
// Two inputs: input[0] valid (offset scanned to an even key), input[1] crafted so that
// keys.offset(bad_offset).group_key() is odd-Y (p2tr_script_buf returns None)
// or produces a script != prevouts[1].script_pubkey.

let inputs = vec![good_received_output, bad_received_output];
let stx = SignableTransaction::new(inputs, &payments, Some(change), None, fee_per_vbyte).unwrap();

// Fails entirely: returns None for the WHOLE transaction, not just input 1
assert!(stx.multisig(&keys).is_none());
// Even though input[0] and all payments were valid, no TransactionMachine exists.
```

Crafting `bad_received_output` via `ReceivedOutput::read`: supply `offset` such that `group_key + G*offset` is odd (~50% chance per offset) and set `output.script_pubkey` to any bytes; `multisig` hits `p2tr_script_buf(offset.group_key())?` → `None?` at send.rs:277-279, aborting the loop and discarding the machine for every input.
