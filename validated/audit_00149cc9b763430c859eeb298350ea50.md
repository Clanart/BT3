## Analysis Summary

The external report's core invariant is: *a verification/authorization value must bind to the actual on-chain entity being trusted, not to an unrelated/mutable proxy value.* In Aptos publish-path terms, this reduces to: *a "verify this on-chain code" flow must check the actual verified bytes committed on-chain, not merely self-declared metadata.*

I evaluated several candidates:
1. `code::check_dependencies` / `is_policy_exempted_address` wildcard — intentional design, not a bug.
2. `init.move` lazy self-init owner tracking (`record_deploy_owner` / `assert_may_self_initialize`) — this is itself a defensive fix pattern (binds signer-minting to the actual object root owner recorded at publish time), fails closed on missing records. No broken invariant found.
3. `aptos_vm.rs::validate_publish_request` / native `request_publish` allowed-deps enforcement — bytecode dependencies are checked against declared metadata correctly (`CODE_DEPENDENCY_CHECK` feature, tested in `code_publishing_faked_dependency`).
4. **`aptos move verify-package` (`VerifyPackage`) / `CachedPackageRegistry::verify`** — this is the strongest candidate and matches the Impact Gate's "mismatch between verified bytes, package metadata... and committed module bytes" bullet directly.

### Title
`aptos move verify-package` never compares on-chain bytecode, only self-declared source metadata — (File: `aptos-move/cli/src/stored_package.rs`, `aptos-move/cli/src/commands.rs`)

### Summary
The Aptos CLI's `verify-package` command is meant to let a user independently confirm that the bytecode actually running on-chain at a given address matches what would be produced by compiling the claimed source. In practice, the command fetches the on-chain `PackageRegistry` metadata with bytecode fetching explicitly disabled, and the `verify()` routine only diffs metadata fields (name, deps, `ModuleMetadata` source/source_map, manifest, upgrade policy, extension, source digest). It never fetches or compares the actual deployed module bytecode against the bytecode produced by the local build. A "Successfully verified" result therefore does not prove the deployed bytecode matches the audited/displayed source.

### Finding Description
`VerifyPackage::execute` builds the package locally to obtain `compiled_metadata`, then creates the on-chain registry view with bytecode fetching turned off: [1](#0-0) 

`CachedPackageRegistry::create` only populates `bytecode: BTreeMap` when `with_bytecode == true`; here it is called with `false`: [2](#0-1) 

`CachedPackageMetadata::verify` then compares only the following: `name`, `deps`, `modules` (each `ModuleMetadata`'s `name`/`source`/`source_map`/`extension` — not bytecode), `manifest`, `upgrade_policy`, `extension`, and `source_digest`: [3](#0-2) 

None of these fields is a hash of, or reference to, the actual compiled module bytes stored on-chain. `PackageMetadata`/`ModuleMetadata` (defined in `code.move`) carry only `source` (gzipped source text) and `source_map`, never bytecode or a bytecode hash: [4](#0-3) 

The `source_digest` is explicitly documented as a hash of *source files*, not compiled output: [5](#0-4) 

Although `CachedPackageRegistry::get_bytecode` and the REST `get_account_module` fetch exist and are wired up when `with_bytecode = true`, `VerifyPackage` never uses that path, so the actual deployed `.mv` bytes are never diffed against the freshly-built local bytecode.

### Impact Explanation
This is a code-safety verification gap rather than an on-chain state-mutation bug: an unprivileged package publisher can publish source metadata (and matching `source_digest`) that appears innocuous, while the deployed module bytecode was built with different compiler flags, a patched toolchain, or hand-crafted bytecode that is functionally divergent from what a naive recompilation of the displayed sources would produce (e.g., different constant folding, injected logic, or modified numeric/permission checks that a compiler bug or non-determinism could introduce, or a maliciously tampered build pipeline). Any downstream tool, auditor, or user relying solely on `aptos move verify-package` returning "Successfully verified source of package" is misled into trusting on-chain code that was never actually bytecode-checked. This directly matches the required-impact class "mismatch between verified bytes, package metadata, dependency declarations, and committed module bytes," and is high-severity because it undermines the sole first-party tool intended to establish code-publish trust for permissionless/immutable packages (the same tool explicitly refuses to verify `upgrade_policy = arbitrary` packages specifically because their bytes can change — implying the intended guarantee is byte-level, not source-declaration-level).

### Likelihood Explanation
Likelihood is high for the "false sense of security" scenario: nothing prevents a publisher from supplying a `PackageMetadata.source`/`source_digest` consistent with locally reproducible source, while the actually loaded/verified/deployed bytecode differs — especially since Move builds are not guaranteed bit-for-bit reproducible across toolchain versions, and there is no on-chain or CLI-side mechanism forcing bytecode-to-source equivalence beyond the VM's own bytecode verifier (which checks safety, not equivalence to a claimed source). Exploiting this requires no special privilege beyond being the package publisher, and the failure is entirely passive from the victim's perspective (they just run `verify-package` and trust the "Successfully verified" output).

### Recommendation
Update `VerifyPackage::execute` to call `CachedPackageRegistry::create(client, self.account, true)` and extend `CachedPackageMetadata::verify` (or a new check) to fetch each on-chain module's bytecode via `get_bytecode`, deserialize/normalize it, and byte-compare (or metadata-hash-compare) it against the bytecode produced by the local `BuiltPackage` build (`pack.extract_code()`), in addition to the existing source/metadata comparison. Document clearly that a "verified" result is only as strong as this bytecode-level check.

### Proof of Concept
1. Publish a package `P` at address `A` with source files `S` whose `source_digest` genuinely matches `S`, but where the submitted `code: vector<vector<u8>>` bytecode bundle in the same transaction was hand-modified/compiled differently from a straightforward build of `S` (the VM only checks bytecode-level safety/compatibility on `code::publish_package`, not equivalence to `S`).
2. Run `aptos move verify-package --account A` from a clean checkout of `S`.
3. Observe that the command builds `S` locally, fetches only `PackageRegistry` metadata (`with_bytecode = false`), compares `source_digest`/`modules`/`manifest`/etc., finds them equal (since they were crafted to match), and prints `"Successfully verified source of package"` — without ever having examined the deployed module bytes at `A`, which differ from what compiling `S` would produce.         // First build the package locally to get the package metadata
        let build_options = BuildOptions {
            install_dir: self.move_options.output_dir.clone(),
            bytecode_version: fix_bytecode_version(
                self.move_options.bytecode_version,
                self.move_options.language_version,
            ),
            ..self.included_artifacts.build_options(&self.move_options)?
        };
        let w = self.env.writer();
        let pack = BuiltPackage::build_to(&w, self.move_options.get_package_path()?, build_options)
            .map_err(|e| CliError::MoveCompilationError(format!("{:#}", e)))?;
        let compiled_metadata = pack.extract_metadata()?;

        // Now pull the compiled package
        let client = self.rest_options.client(&self.profile_options)?;
        let registry = CachedPackageRegistry::create(client, self.account, false).await?;
        let package = registry
            .get_package(pack.name())
            .await
            .map_err(|s| CliError::CommandArgumentError(s.to_string()))?;

        // We can't check the arbitrary, because it could change on us
        if package.upgrade_policy() == UpgradePolicy::arbitrary() {
            return Err(CliError::CommandArgumentError(
                "A package with upgrade policy `arbitrary` cannot be downloaded \
                since it is not safe to depend on such packages."
                    .to_owned(),
            ));
        }

        // Verify that the source digest matches
        package.verify(&compiled_metadata)?;

        Ok("Successfully verified source of package")
    }

impl CachedPackageRegistry {
    /// Creates a new registry.
    pub async fn create(
        client: Client,
        addr: AccountAddress,
        with_bytecode: bool,
    ) -> anyhow::Result<Self> {
        // Need to use a different type to deserialize JSON
        let inner = client
            .get_account_resource_bcs::<PackageRegistry>(addr, "0x1::code::PackageRegistry")
            .await?
            .into_inner();
        let mut bytecode = BTreeMap::new();
        if with_bytecode {
            for pack in &inner.packages {
                for module in &pack.modules {
                    let bytes = client
                        .get_account_module(addr, &module.name)
                        .await?
                        .into_inner()
                        .bytecode
                        .0;
                    bytecode.insert(module.name.clone(), bytes);
                }
            }
        }
        Ok(Self { inner, bytecode })
    }

        let self_metadata = self.metadata;

        if self_metadata.name != package_metadata.name {
            bail!(
                "Package name doesn't match {} : {}",
                package_metadata.name,
                self_metadata.name
            )
        } else if self_metadata.deps != package_metadata.deps {
            bail!(
                "Dependencies don't match {:?} : {:?}",
                package_metadata.deps,
                self_metadata.deps
            )
        } else if self_metadata.modules != package_metadata.modules {
            bail!(
                "Modules don't match {:?} : {:?}",
                package_metadata.modules,
                self_metadata.modules
            )
        } else if self_metadata.manifest != package_metadata.manifest {
            bail!(
                "Manifest doesn't match {:?} : {:?}",
                package_metadata.manifest,
                self_metadata.manifest
            )
        } else if self_metadata.upgrade_policy != package_metadata.upgrade_policy {
            bail!(
                "Upgrade policy doesn't match {:?} : {:?}",
                package_metadata.upgrade_policy,
                self_metadata.upgrade_policy
            )
        } else if self_metadata.extension != package_metadata.extension {
