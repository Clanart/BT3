### Title
Malformed `git status` output from a hostile repository throws an uncaught, unrecoverable parse exception that crashes Desktop and can recur on every subsequent launch - (File: `app/src/lib/status-parser.ts`)

### Summary
The External Report's broken invariant is: *an attacker-controlled object, reached during a routine, unprivileged operation, can force an unhandled revert that leaves the system permanently unusable ("bricked") until manual intervention.* The closest reachable analog in GitHub Desktop is the Git status parser. `parsePorcelainStatus()` and its per-entry parsers (`parseChangedEntry`, `parsedRenamedOrCopiedEntry`, `parseUnmergedEntry`) throw a synchronous `Error` whenever the `git status --porcelain=2 -z` output for an entry doesn't match a fixed regex or is missing an expected field [1](#0-0) . `getStatus()` calls this parser with no surrounding `try/catch` [2](#0-1) , and `getStatus()`/status refresh runs automatically and repeatedly on repositories that the app owns and that the user did not have to explicitly re-trigger (background fetch loop, refresh-after-fetch/pull/push, and — critically — on every app relaunch via the persisted "last selected repository" restore path).

### Finding Description
`git status --porcelain=2` output is a stream of NUL-separated records whose exact shape depends on the repository's on-disk refs/index/working tree — content that is fully controlled by whoever crafts the repository the user clones or opens (a git remote/proxy response is exactly this kind of attacker-controlled object). Desktop parses that stream with strict regexes:

- `changedEntryRe` for regular changes
- `renamedOrCopiedEntryRe` for renames/copies
- `unmergedEntryRe` for conflicts

If a status line for any entry type fails to match its regex (or, for rename/copy entries, if the old-path field is empty), the parser does **not** return an error object — it throws: [1](#0-0) [3](#0-2) [4](#0-3) 

`getStatus()` calls `parsePorcelainStatus(stdout)` directly, with no `try/catch` around it: [2](#0-1) . This function is invoked from `GitStore.loadStatus()` and from `AppStore._loadStatus()` which itself is called from many otherwise "safe" refresh paths (`_refreshRepository`, post-fetch/pull/push refreshes, background fetch, and conflict handling) — none of which special-case a thrown parse error the way `performFailableOperation` does for actual git command failures (which are converted to typed `GitError`s and can be retried/dismissed).

The unguarded throw becomes an uncaught exception in the renderer, which is treated by Desktop's global exception handler as fatal: `process.on('uncaughtException', onUncaughtException)` reports it and the app is expected to quit/relaunch [5](#0-4) . This differs from ordinary git errors (network failures, auth failures, merge conflicts) which are caught, classified, and surfaced through the recoverable `Dispatcher`/error-handler pipeline described in the project's own error-reporting documentation [6](#0-5) .

The "bricking" element comes from state persistence: the selected/most-recently-used repository ID is persisted (`LastSelectedRepositoryIDKey`) and is used to automatically re-select and refresh that repository on the next app start [7](#0-6) [8](#0-7) . If the malicious/malformed repository is the currently selected one, restarting Desktop causes it to reselect that repository and immediately re-run `_refreshRepository`/`_loadStatus`, hitting the same throwing status parse again — producing a crash-relaunch loop for that repository that a normal user cannot escape without external intervention (e.g., manually editing local storage, or launching Desktop and being fast enough to select a different repository before the crash), analogous to the auction house being permanently unusable once the winning bidder is set.

### Impact Explanation
Impact is high for the affected repository: opening/cloning/fetching a hostile or corrupted-on-purpose repository can force a hard renderer crash instead of a recoverable, dismissible error dialog, and — because the crash occurs inside the same automatic "restore last repository" flow that runs at every app launch — the user can be stuck in a repeated crash/relaunch cycle for that specific repository. This is a denial-of-service against the app's normal recoverable-error handling model, achieved purely by content the attacker controls (crafted git-status-producing repository state), without any local access, admin rights, or social engineering beyond the user opening/cloning/fetching the repository as they normally would.

### Likelihood Explanation
Likelihood is high on the surface (status refresh is one of the most frequently executed code paths in Desktop, running after nearly every git operation and via background timers) but the fact that a valid `git status --porcelain=2` engine would need to actually emit a line that doesn't satisfy the regexes is what needs concrete confirmation. The most concrete confirmed trigger is the rename/copy path, where the code explicitly anticipates and throws on a missing/empty `oldPath` field [9](#0-8)  — i.e., the developers already know this field can come back empty in some rename/copy scenario and chose to hard-throw rather than degrade gracefully. Exactly which repository content reliably reproduces this (e.g., unusual filenames with embedded control characters, git implementations/hooks that alter porcelain=2 output, or version-skew in `dugite`'s bundled git) was not verified against a live git binary in this investigation and should be confirmed with a proof-of-concept repository before treating this as a fully weaponized finding.

### Recommendation
- Wrap `parsePorcelainStatus()` (and the sub-parsers) so that a single malformed/unexpected status line degrades gracefully — e.g., skip the offending entry and log a diagnostic — rather than throwing, mirroring how actual git command failures are already converted into recoverable `GitError`s elsewhere in the codebase.
- At minimum, catch parse exceptions in `getStatus()` and treat them like the existing `exitCode === 128` "missing repository" case: return `null`/report a non-fatal error instead of letting the exception propagate to the global uncaught-exception handler.
- Guard the "restore last selected repository" startup path so a persistently-throwing repository does not repeatedly crash the whole app on launch — e.g., detect repeated status-refresh failures for a given repository and stop auto-selecting/auto-refreshing it until the user explicitly reopens it.

### Proof of Concept
Conceptual reproduction (not verified end-to-end against a live git binary in this session):
1. Craft or obtain a repository whose working tree/index state causes `git status --porcelain=2 -z` to emit a rename/copy (`2 ...`) record where the paired old-path token is empty or otherwise fails `renamedOrCopiedEntryRe` (e.g., via unusual filename encodings, embedded NUL-adjacent bytes, or copy-detection edge cases) — this is the `2 <XY> ... <path><sep><origPath>` format read by `parsedRenamedOrCopiedEntry` [10](#0-9) .
2. Have the victim clone or fetch this repository into Desktop and make it their selected repository (persisted via `LastSelectedRepositoryIDKey`).
3. Any status refresh (manual "Fetch", background fetch timer, or simply opening the app) calls `getStatus()` → `parsePorcelainStatus()`, which throws inside `parsedRenamedOrCopiedEntry`.
4. Because `getStatus()`/`_loadStatus()` have no try/catch around the parser, the exception surfaces as an uncaught exception, triggering `onUncaughtException` and app termination/relaunch [5](#0-4) .
5. On relaunch, `updateRepositorySelectionAfterRepositoriesChanged()` re-selects the same repository from `LastSelectedRepositoryIDKey` and re-triggers the refresh, reproducing the crash [7](#0-6) .

    statusCode: match[1],
    submoduleStatusCode: match[2],

    path: match[9],
  }
}

const onUncaughtException = (error: unknown) => {
  // This is a known issue with the ResizeObserver API in Chromium 132 which is
  // fixed in 133 that we can safely ignore.
  // See: https://issues.chromium.org/issues/391393420
  if (
    error === resizeLoopCompletedMessage ||
    (error &&
      typeof error === 'object' &&
      'message' in error &&
      error.message === resizeLoopCompletedMessage)
  ) {
    sendNonFatalException(
      'resizeObserverLoopCompleted',
      withSourceMappedStack(error)
    )
    return
  }

  sendErrorWithContext(error)
  reportUncaughtException(withSourceMappedStack(error))

  // We used to subscribe to uncaughtException using process.once but we want
  // to be able to ignore the resize observer error above so we need to
  // unsubscribe manually once we encounter an error we actually want to crash
  // the app for.
  process.off('uncaughtException', onUncaughtException)
}

  public async _selectRepository(
    repository: Repository | CloningRepository | null
  ): Promise<Repository | null> {
    const previouslySelectedRepository = this.selectedRepository

    // do this quick check to see if we have a tutorial repository
    // cause if its not we can quickly hide the tutorial pane
    // in the first `emitUpdate` below
    const previouslyInTutorial =
      this.currentOnboardingTutorialStep !== TutorialStep.NotApplicable
    if (
      previouslyInTutorial &&
      (!(repository instanceof Repository) || !repository.isTutorialRepository)
    ) {
      this.currentOnboardingTutorialStep = TutorialStep.NotApplicable
    }

    this.selectedRepository = repository

    this.emitUpdate()
    this.stopBackgroundFetching()
    this.stopPullRequestUpdater()
    this._clearBanner()
    this.stopBackgroundPruner()

    if (repository == null) {
      return Promise.resolve(null)
    }

    if (!(repository instanceof Repository)) {
      return Promise.resolve(null)
    }

    setNumber(LastSelectedRepositoryIDKey, repository.id)

    const previousRepositoryId = previouslySelectedRepository
      ? previouslySelectedRepository.id
      : null

    this.updateRecentRepositories(previousRepositoryId, repository.id)

    // if repository might be marked missing, try checking if it has been restored
    const refreshedRepository = await this.recoverMissingRepository(repository)
    if (refreshedRepository.missing) {
      // as the repository is no longer found on disk, cleaning this up
      // ensures we don't accidentally run any Git operations against the
      // wrong location if the user then relocates the `.git` folder elsewhere
      this.gitStoreCache.remove(repository)
      return Promise.resolve(null)
    }

    // This is now purely for metrics collection for `commitsToRepositoryWithBranchProtections`
    // Understanding how many users actually contribute to repos with branch protections gives us
    // insight into who our users are and what kinds of work they do
    this.updateBranchProtectionsFromAPI(repository)

    this.notificationsStore.selectRepository(repository)

    return this._selectRepositoryRefreshTasks(
      refreshedRepository,
      previouslySelectedRepository
    )
  }

  private updateRepositorySelectionAfterRepositoriesChanged() {
    const selectedRepository = this.selectedRepository
    let newSelectedRepository: Repository | CloningRepository | null =
      this.selectedRepository
    if (selectedRepository) {
      const r =
        this.repositories.find(
          r =>
            r.constructor === selectedRepository.constructor &&
            r.id === selectedRepository.id
        ) || null

      newSelectedRepository = r
    }

    if (newSelectedRepository === null && this.repositories.length > 0) {
      const lastSelectedID = getNumber(LastSelectedRepositoryIDKey, 0)
      if (lastSelectedID > 0) {
        newSelectedRepository =
          this.repositories.find(r => r.id === lastSelectedID) || null
      }

      if (!newSelectedRepository) {
        newSelectedRepository = this.repositories[0]
      }
    }

    const repositoryChanged =
      (selectedRepository &&
        newSelectedRepository &&
        selectedRepository.hash !== newSelectedRepository.hash) ||
      (selectedRepository && !newSelectedRepository) ||
      (!selectedRepository && newSelectedRepository)
    if (repositoryChanged) {
      this._selectRepository(newSelectedRepository)
