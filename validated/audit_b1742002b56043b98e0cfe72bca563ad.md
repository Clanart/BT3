### Title
Payout tx uses unbound SIGHASH_SINGLE|ANYONECANPAY, letting anyone reassign a fronted payout's OP_RETURN attribution to a different operator - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary
`create_payout_txhandler` builds the payout transaction's user-signed input with `SpendPath::KeySpend` and the user-supplied `in_signature.sighash_type`, which `Operator::withdraw` documents and expects to be `SinglePlusAnyoneCanPay`. Under this sighash flag, the Taproot signature only commits to input 0 and output 0; outputs 1 (anchor) and 2 (OP_RETURN operator xonly pk) are completely unauthenticated, so anyone observing the signed input/output-0 pair (visible once the tx is broadcast or sits in mempool) can rebuild a different, still-validly-signed transaction that swaps output 2 to name a different, real operator.

### Finding Description
The broken binding, stated as an equality that must hold but doesn't:
`operator_credited_by(update_finalized_payouts, payout_tx.output[2]) == operator_who_funded(payout_tx.output[0])`

Code path:
- `Operator::withdraw` (`core/src/operator.rs:560-637`) builds a payout tx via `create_payout_txhandler`, computes `sighash = payout_txhandler.calculate_sighash_txin(0, in_signature.sighash_type)`, and verifies the user's Schnorr signature against that sighash. The comment explicitly requires `SinglePlusAnyoneCanPay`. [1](#0-0) 
- `create_payout_txhandler` (`core/src/builder/transaction/operator_reimburse.rs:407-436`) constructs the tx with input 0 = withdrawal UTXO (key-spend), output 0 = user payout, output 1 = anchor, output 2 = OP_RETURN(`operator_xonly_pk`), and signs only input 0 with the caller-supplied signature/sighash type. [2](#0-1) 
- `TxHandler::calculate_pubkey_spend_sighash` (`core/src/builder/transaction/txhandler.rs:210-233`) computes the sighash strictly per BIP341/BIP143 semantics for the given `TapSighashType`. For `SinglePlusAnyoneCanPay`, per protocol semantics only prevout 0, input 0, and output 0 are committed — all other inputs/outputs (anchor, OP_RETURN operator pk, and any extra funding inputs added later by `fund_raw_transaction`) are unauthenticated and freely malleable by any third party. [3](#0-2) 
- `Operator::withdraw` funds the tx via `fund_raw_transaction` with RBF and broadcasts it, `change_position: Some(1)`, meaning extra operator-wallet inputs/outputs are added around a still SINGLE|ANYONECANPAY-signed input 0. [4](#0-3) 
- Once any version of this transaction appears on-chain (mined), `Verifier::update_finalized_payouts` blindly trusts whatever OP_RETURN happens to be in the version that got mined, extracting `operator_xonly_pk` and writing it as `payout_payer_operator_xonly_pk` in the `withdrawals` table with no cross-check against who actually funded output 0. [5](#0-4) 
- `PayoutCheckerTask::run_once` for operator B then picks this up via `get_first_unhandled_payout_by_operator_xonly_pk(B_pk)`, which only filters by `payout_payer_operator_xonly_pk = B_pk` and `is_payout_handled = FALSE`, with no additional binding check. [6](#0-5) [7](#0-6) 
- B then calls `handle_finalized_payout`, gets `mark_payout_handled` set with B's kickoff txid, permanently binding the DB row's `kickoff_txid`/attribution to B. [8](#0-7) 

The only existing self-consistency check, `Verifier::is_kickoff_malicious`, compares the OP_RETURN operator pk against `kickoff_data.operator_xonly_pk` — i.e., it verifies the kickoff-sender matches the payout's claimed payer, but it never verifies that the claimed payer is who actually funded output 0. Since the attacker names a legitimate, currently-active operator B in the OP_RETURN, and B's own state machine naturally proceeds to kick off (because from B's node's perspective this looks like a normal unhandled payout credited to B), this check passes trivially and does not catch the substitution. [9](#0-8) 

Root cause: the protocol relies on `SinglePlusAnyoneCanPay`, a sighash flag intentionally chosen to allow the operator to add funding inputs and a change output via RBF, but this flag also leaves the OP_RETURN attribution output completely outside the signed commitment, so the attribution of "who is credited/reimbursed" is not cryptographically bound to "who actually paid."

### Impact Explanation
This is a direct instance of the in-scope Critical impact "an operator reimbursed for a payout it never funded." Operator B, who never fronted a single satoshi of the withdrawal, ends up credited in `withdrawals.payout_payer_operator_xonly_pk`, triggers `handle_finalized_payout`, proceeds through the kickoff/reimburse pipeline, and is ultimately reimbursed from the deposit's move-to-vault UTXO for funds it never advanced. Meanwhile operator A, the true funder whose broadcast either never confirms (lost the fee race) or whose in_signature/input-0 is consumed by the substitute tx, has no path to reimbursement: the DB row `withdrawals` (keyed by `idx`) is now permanently bound to B's `payout_txid`/`kickoff_txid`, and A cannot re-claim it. This is repeatable for every withdrawal across every pair of active operators, as it depends only on generic protocol mechanics (SIGHASH_SINGLE|ANYONECANPAY + OP_RETURN parsing), not any specific deposit or configuration.

### Likelihood Explanation
Preconditions are modest for an unprivileged attacker: they need to observe a pending/mempool (or even just newly-mined, before other operators reorg it out) payout transaction — a broadcasting event that necessarily becomes public — and need a second, real registered operator B to exist (which is a normal multi-operator deployment configuration, not attacker-controlled). The attacker only needs to pay for their own transaction's fees/replacement-by-fee premium to get the substituted transaction mined instead of (or race against) the original. No signature forgery, no privileged key, and no Citrea-side manipulation are required — this is a pure Bitcoin-transaction-malleability attack enabled by the sighash flag choice, fully reachable through the "attacker can broadcast Bitcoin transactions and pay fees" capability defined in the threat model.

### Recommendation
Do not rely solely on `SinglePlusAnyoneCanPay` for the user's payout signature when attribution of the payout's OP_RETURN output must be trusted. Either:
1. Change the signed sighash type to `AllPlusAnyoneCanPay` or `All` and have the operator additionally co-sign (or otherwise commit) outputs 1 and 2 so the OP_RETURN operator pk is bound to the same transaction as output 0, or
2. Require an additional out-of-band, cryptographically bound assertion (e.g., have the operator's own funding input in the transaction directly tie back to the operator's own key, and have `update_finalized_payouts`/`is_kickoff_malicious` verify that at least one input of the mined payout tx is provably spent by the credited operator's own registered key, not merely trust the OP_RETURN bytes), or
3. At minimum, add a DB-level check when crediting `payout_payer_operator_xonly_pk` that cross-validates the OP_RETURN operator against evidence of actual funding (e.g., match against operator-specific funding UTXOs known to the verifier/operator infrastructure), rejecting attribution changes for a withdrawal `idx` once any operator has already been provisionally associated with funding it.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    pub fn calculate_pubkey_spend_sighash(
        &self,
        txin_index: usize,
        sighash_type: TapSighashType,
    ) -> Result<TapSighash, BridgeError> {
        let prevouts_vec: Vec<&TxOut> = self
            .txins
            .iter()
            .map(|s| s.get_spendable().get_prevout())
            .collect();
        let mut sighash_cache: SighashCache<&bitcoin::Transaction> =
            SighashCache::new(&self.cached_tx);
        let prevouts = match sighash_type {
            TapSighashType::SinglePlusAnyoneCanPay
            | TapSighashType::AllPlusAnyoneCanPay
            | TapSighashType::NonePlusAnyoneCanPay => {
                bitcoin::sighash::Prevouts::One(txin_index, prevouts_vec[txin_index])
            }
            _ => bitcoin::sighash::Prevouts::All(&prevouts_vec),
        };

        let sig_hash = sighash_cache
            .taproot_key_spend_signature_hash(txin_index, &prevouts, sighash_type)
            .wrap_err("Failed to calculate taproot sighash for key spend")?;

        &self,
        tx: Option<DatabaseTransaction<'_>>,

    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",

        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((

                        .expect("move_to_vault_txid Must be Some")
                        .0,

                        .expect("payout_tx_blockhash Must be Some")
                        .0,
