## Title
Contract-based governance parameter updates (KIP-81 `GovParam.setParam`/`setParamIn`) can bypass the one-epoch delay guaranteed by header governance, allowing fees such as `governance.unitprice` and KIP-71 base-fee bounds to change with arbitrary, attacker-chosen (including near-immediate) activation - (File: `kaiax/gov/contractgov/impl/getter.go`)

### Summary
The external report describes a class of bug where a privileged party can update a fee parameter and have it take effect almost immediately by exploiting insufficient delay between "update" and "activation," denying users time to react. In this codebase, header governance (`kaiax/gov/headergov`) enforces a strict, hard-coded delay: a vote ratified at epoch `k` only becomes effective at epoch `k+1`, guaranteeing a full epoch of advance notice [1](#0-0) . However, contract governance (`kaiax/gov/contractgov`), which takes precedence over header governance after the Kore hard fork [2](#0-1) , reads parameter values and their `activation` block directly from the `GovParam` contract via `getAllParamsAt(blockNumber)` [3](#0-2) , with no delay validation enforced by the Kaia client itself.

### Finding Description
The `GovParam` contract exposes `setParam(name, exists, val, activation)` and `setParamIn(name, exists, val, relativeActivation)`, where the caller supplies an arbitrary `activation` block number [4](#0-3) [5](#0-4) . The node-side `contractGovModule.GetParamSet`/`GetPartialParamSet` simply calls the contract's view function `getAllParamsAt(blockNum)` and trusts whatever "effective" value the contract computes for the requested block, with no independent check that the activation is sufficiently far in the future [6](#0-5) . The only architectural delay Kaia relies on for parameter changes is the header-governance epoch mechanism ("Parameter change ratified at k*epoch block takes effect starting from (k+1)*epoch block") [1](#0-0) , but this guarantee applies only to header governance, not to contract governance. Since contract governance parameters win over header governance parameters post-Kore [7](#0-6) , and the test suite itself demonstrates activation being set to essentially the very next block (`setParam(... , 1000)` becoming effective exactly at block `1000` with no minimum offset enforced) [8](#0-7) , a `GovParam` owner can set fee-related parameters (`governance.unitprice`, `kip71.lowerboundbasefee`, `kip71.upperboundbasefee`, etc.) with an activation just one or a few blocks ahead, circumventing the one-full-epoch notice period that header governance was designed to guarantee.

### Impact Explanation
Fee-related governance parameters (`governance.unitprice`, KIP-71 base-fee bounds/denominator) directly control the mandatory gas price users must pay, enforced in `TxPool.validateTx` (`ErrInvalidUnitPrice`, `ErrGasPriceBelowBaseFee`, `ErrFeeCapBelowBaseFee`) [9](#0-8) . An owner of the `GovParam` contract can raise `governance.unitprice`/base-fee bounds with only a few blocks of notice instead of the full epoch (up to 604,800 blocks on Mainnet) that header governance provides [10](#0-9) , instantly forcing higher fees on all pending/queued transactions and effectively denying users and dApps the adjustment window the header-governance design intentionally provides. This is a direct fee-abuse/fee-delegation-adjacent impact reachable by any transaction sender interacting with the chain at the moment of the parameter flip.

### Likelihood Explanation
Exploitation requires control of the `GovParam` contract owner key (a governance/GC-controlled contract per KIP-81) [11](#0-10) , so this is only exercisable by the governing entity, not an arbitrary unprivileged sender — but that governing entity is exactly the "manager" role analogous to the pool manager in the external report, and the client-side code performs no additional sanity check on the activation delay before trusting the contract's returned parameter set.

### Recommendation
Enforce a minimum activation delay (e.g., at least one full epoch, mirroring header governance) either in the `GovParam` contract's `setParam`/`setParamIn` functions or as a validation check in `contractGovModule.GetParamSet`/`GetPartialParamSet` before accepting contract-governance parameter values, particularly for fee-affecting parameters (`governance.unitprice`, `kip71.*`).

### Proof of Concept
1. Deploy/own the `GovParam` contract referenced by `governance.govparamcontract` post-Kore.
2. Call `setParam("governance.unitprice", true, <newHighFee>, activation=<currentBlock+2>)` as demonstrated in the test helper `setParam` [12](#0-11) .
3. On/after block `currentBlock+2`, `contractGovModule.GetParamSet` returns the new `UnitPrice` immediately [13](#0-12) , and `TxPool.validateTx` starts rejecting/require the new higher fee immediately, without the epoch-long grace period header governance would have provided.

Note: I could not locate the actual Solidity source of the `GovParam` contract (only its ABI/bytecode bindings are indexed), so I cannot fully confirm whether the contract itself enforces any minimum `activation` offset beyond what is visible in the bindings and tests. Due to index size limits, some file contents (e.g. `contracts/*/GovParam.sol` if it exists) may not be available — starting a full Devin session would allow inspecting the complete contract source to confirm whether a minimum-delay check already exists on-chain.

func (c *contractGovModule) GetParamSet(blockNum uint64) gov.ParamSet {
	m, err := c.contractGetAllParamsAt(blockNum)
	if err != nil {
		return *gov.GetDefaultGovernanceParamSet()
	}

	ret := *gov.GetDefaultGovernanceParamSet()
	for k, v := range m {
		err = ret.Set(k, v)
		if err != nil {
			return *gov.GetDefaultGovernanceParamSet()
		}
	}

	return ret
}

func (c *contractGovModule) GetPartialParamSet(blockNum uint64) gov.PartialParamSet {
	m, err := c.contractGetAllParamsAt(blockNum)
	if err != nil {
		return nil
	}
	return m
}

func (c *contractGovModule) contractGetAllParamsAt(blockNum uint64) (gov.PartialParamSet, error) {
	addr, err := c.contractAddrAt(blockNum)
	if err != nil {
		return nil, err
	}
	if common.EmptyAddress(addr) {
		logger.Trace("ContractEngine disabled: GovParamContract address not set")
		return nil, nil
	}

	return c.contractGetAllParamsAtFromAddr(blockNum, addr)
}
