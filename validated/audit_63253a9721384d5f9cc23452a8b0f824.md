## Analysis

**Claimed binding:** `deposit_txout_in_chain.script_pubkey == expected_scriptpubkey` (computed from `get_deposit_scripts`) is claimed to be insufficient to guarantee that the *set of spend paths* of the actual funded output equals the set of spend paths verifiers believe they're locking.

**Why this claim is false:** A Taproot output's `script_pubkey` is not an arbitrary aggregate value — it is the SEC-encoded tweaked output key `Q = P + t*G`, where `t = TapTweakHash(P || merkle_root)` and `merkle_root` is the root of the leaf-script Merkle tree built with `TapLeafHash`/`TapBranchHash` (tagged SHA-256). This is a cryptographically binding commitment over:
- The internal key `P` (fixed to the unspendable NUMS point `UNSPENDABLE_XONLY_PUBKEY` here, since `create_taproot_address(&deposit_scripts, None, network)` passes `internal_key = None`) [1](#0-0) 
- The exact multiset of leaf scripts and their positions/depths in the tree, as produced deterministically by `taproot_builder_with_scripts`/`calculate_taproot_leaf_depths` [2](#0-1) 

`Verifier::is_deposit_valid` computes `expected_scriptpubkey` from `deposit_data.get_deposit_scripts(...)` via this same `create_taproot_address` function, and rejects the deposit unless the on-chain output's `script_pubkey` matches byte-for-byte [3](#0-2) .

For an attacker to fund an output whose actual spend-path set differs (extra leaf, reordered leaves, different internal key) while still producing the *same* 32-byte output key that `expected_scriptpubkey` requires, they would need to find a second preimage/collision against the tagged-hash Merkle-tree commitment and the taproot tweak — this is a cryptographic hardness assumption break, not a logic bug in `core/src/deposit.rs` or `core/src/verifier.rs`. Any legitimate divergence (extra leaf, reorder, different internal key) changes `merkle_root` and therefore changes `Q`, causing `is_deposit_valid`'s script_pubkey comparison to fail deterministically.

The premise "only the aggregate `script_pubkey` is compared" mischaracterizes Taproot: the aggregate output key *is* the commitment to the full script tree by construction, so comparing it is exactly sufficient to enforce the stated invariant — it is not a shortcut that skips validation of the tree structure.

/// Calculates the depth of each leaf in a balanced Taproot tree structure.
/// The returned Vec contains the depth for each script at the corresponding index.
pub fn calculate_taproot_leaf_depths(num_scripts: usize) -> Vec<u8> {
    match num_scripts {
        0 => return vec![],
        1 => return vec![0],
        _ => {}
    }

    let deepest_layer_depth: u8 = ((num_scripts - 1).ilog2() + 1) as u8;

    let num_empty_nodes_in_final_depth = 2_usize.pow(deepest_layer_depth.into()) - num_scripts;
    let num_nodes_in_final_depth = num_scripts - num_empty_nodes_in_final_depth;

    (0..num_scripts)
        .map(|i| {
            let is_node_in_last_minus_one_depth = (i >= num_nodes_in_final_depth) as u8;
            deepest_layer_depth - is_node_in_last_minus_one_depth
        })
        .collect()
}

/// Creates a taproot address with given scripts and internal key.
pub fn create_taproot_address(
    scripts: &[ScriptBuf],
    internal_key: Option<XOnlyPublicKey>,
    network: bitcoin::Network,
) -> (Address, TaprootSpendInfo) {
    // Build script tree
    let taproot_builder = taproot_builder_with_scripts(scripts);
    // Finalize the tree
    let tree_info = match internal_key {
        Some(xonly_pk) => taproot_builder
            .finalize(&SECP, xonly_pk)
            .expect("builder return is finalizable"),
        None => taproot_builder
            .finalize(&SECP, *UNSPENDABLE_XONLY_PUBKEY)
            .expect("builder return is finalizable"),
    };

    // Create the address
    let taproot_address: Address = Address::p2tr_tweaked(tree_info.output_key(), network);

    (taproot_address, tree_info)
}
