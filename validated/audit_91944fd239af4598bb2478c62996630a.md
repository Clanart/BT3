### Title
Cached FROST preprocess never expires and is deterministically re-derived on every `share_internal` call: permanent nonce reuse leaks the validator's secret share - (File: crypto/frost/src/sign.rs)

### Summary
The invite-hash-never-expires class maps onto Serai as a signing artifact that never expires and is silently reused: `AlgorithmMachine::seeded_preprocess` derives the entire preprocess (nonces, commitments, addendum) deterministically from a 32-byte `CachedPreprocess` seed via `ChaCha20Rng::from_seed`, with no consumption flag, counter, session binding, or expiry [1](#0-0) . The only call site persists this seed in `CachedPreprocesses` keyed solely by `context` and never deletes it; `share_internal` calls `preprocess_internal` for every signing session, so the same seed — and therefore the same nonce pair `(d_i, e_i)` and identical published commitment — is reused indefinitely [2](#0-1) . Two shares produced under the same nonce but different `msg`/preprocess sets (different `rho` and `c`) satisfy `s1 - s2 = (Δd + Δρ·e) + (c1 - c2)·λ_i·x_i`, where the only unknown is `x_i`, recovering the signer's secret share.

### Finding Description
`seeded_preprocess` rebuilds `nonces` and `commitments` purely from `ChaCha20Rng::from_seed(*seed.0)` [3](#0-2) . `Curve::random_nonce` hashes `seed || secret_share`, so a fixed seed yields a fixed nonce [4](#0-3) . In `preprocess_internal`, the DB lookup `CachedPreprocesses::get(self.txn, &self.context)` is used as an infinite-lived cache: it is written only `if ... .is_none()` and is never cleared after `sign` produces a share [5](#0-4) . `share_internal` then re-executes `preprocess_internal` and calls `machine.sign(preprocesses, msg)` on attacker-influenced `preprocesses`/`msg` bytes parsed via `read_preprocess` [6](#0-5) . The header comment acknowledges the risk and notes the protective on-chain commitment check is only a `TODO` — i.e., unimplemented [7](#0-6) . The rho transcript binds `group_key`, `hash_msg(msg)`, and the `preprocesses` challenge, but nothing binds or invalidates the local nonce itself across sessions [8](#0-7) .

### Impact Explanation
An unprivileged counterparty who participates in (or observes) two signing sessions under the same `context` supplies different `msg`/`serialized_preprocesses` — public inputs to `read_preprocess`/`sign` — and obtains two shares from the same `(d_i, e_i)`. Since `rho_i` and `c` differ while the nonce is identical, solving the two linear share equations yields the victim's secret share `x_i`. With threshold-many victims compromised this way (or a validator-set key where the leaked share is itself a signing key), the group key is forgeable. The code itself states reuse "will presumably cause the signer to leak their secret share" [9](#0-8) .

### Likelihood Explanation
The reused artifact is permanent and context-scoped, exactly like a non-expiring invite hash: any repeated signing under the same `context` value re-serves the same nonce. Triggering requires only that `share_internal` run twice for the same context with differing peer preprocesses or messages — normal operation across two signing rounds, with no expiry or one-time-use enforcement anywhere in `crypto/frost` (`SignMachine::sign` consumes the machine but the persistent seed is what regenerates it) [10](#0-9) . I could not enumerate every `context` value passed in due to iteration limits, but the cache design guarantees reuse whenever the context repeats.

### Recommendation
Delete the `CachedPreprocesses` entry before publishing a signature share (consume-on-use), and add a defense-in-depth guard in `crypto/frost`: bind a monotonic session/attempt index into `seeded_preprocess` (e.g., hash `seed || session_id` into the ChaCha seed) so even a cache-handling bug cannot reproduce identical nonces. Implement the TODO'd on-chain check that published commitments match the presumed preprocess before emitting shares.

### Proof of Concept
1. Session A: peer preprocesses `P_A`, message `m_A` → `share_internal` decrypts seed `s` from `CachedPreprocesses[ctx]`, `seeded_preprocess` regenerates nonces `(d, e)`, emits share `z_A = (d + ρ_A·e) + c_A·λ_i·x_i`.
2. Session B (same `ctx`, e.g., a re-attempt or second sign before any eviction): peer preprocesses `P_B`, message `m_B` → same `(d, e)`, share `z_B = (d + ρ_B·e) + c_B·λ_i·x_i`.
3. `ρ_A`, `ρ_B`, `c_A`, `c_B`, `λ_i` are all publicly computable from the rho transcript and `hram` [8](#0-7) . Solve the two equations for the two unknowns `(d + ρ·e)`-adjusted terms and `x_i`, recovering the secret share — no privileged access, no leaked key material required.

  fn seeded_preprocess(
    self,
    seed: CachedPreprocess,
  ) -> (AlgorithmSignMachine<C, A>, Preprocess<C, A::Addendum>) {
    let mut params = self.params;

    let mut rng = ChaCha20Rng::from_seed(*seed.0);
    let (nonces, commitments) = Commitments::new::<_>(
      &mut rng,
      params.keys.original_secret_share(),
      &params.algorithm.nonces(),
    );
    let addendum = params.algorithm.preprocess_addendum(&mut rng, &params.keys);

    let preprocess = Preprocess { commitments, addendum };

    // Also obtain entropy to randomly sort the included participants if we need to identify blame
    let mut blame_entropy = [0; 32];
    rng.fill_bytes(&mut blame_entropy);
    (
      AlgorithmSignMachine { params, seed, nonces, preprocess: preprocess.clone(), blame_entropy },
      preprocess,
    )
  }

  fn share_internal(
    &mut self,
    participants: &[<Ristretto as Ciphersuite>::G],
    mut serialized_preprocesses: HashMap<Participant, Vec<u8>>,
    msg: &[u8],
  ) -> Result<(AlgorithmSignatureMachine<Ristretto, Schnorrkel>, [u8; 32]), Participant> {
    let machine = self.preprocess_internal(participants).0;

    let mut participants = serialized_preprocesses.keys().copied().collect::<Vec<_>>();
    participants.sort();
    let mut preprocesses = HashMap::new();
    for participant in participants {
      preprocesses.insert(
        participant,
        machine
          .read_preprocess(&mut serialized_preprocesses.remove(&participant).unwrap().as_slice())
          .map_err(|_| participant)?,
      );
    }

    let (machine, share) = machine.sign(preprocesses, msg).map_err(|e| match e {
      FrostError::InternalError(e) => unreachable!("FrostError::InternalError {e}"),
      FrostError::InvalidParticipant(_, _) |
      FrostError::InvalidSigningSet(_) |
      FrostError::InvalidParticipantQuantity(_, _) |
      FrostError::DuplicatedParticipant(_) |
      FrostError::MissingParticipant(_) => unreachable!("{e:?}"),
      FrostError::InvalidPreprocess(p) | FrostError::InvalidShare(p) => p,
    })?;

  fn random_nonce<R: RngCore + CryptoRng>(
    secret: &Zeroizing<Self::F>,
    rng: &mut R,
  ) -> Zeroizing<Self::F> {
    let mut seed = Zeroizing::new(vec![0; 32]);
    rng.fill_bytes(seed.as_mut());

    let mut repr = secret.to_repr();

    // Perform rejection sampling until we reach a non-zero nonce
    // While the IETF spec doesn't explicitly require this, generating a zero nonce will produce
    // commitments which will be rejected for being zero (and if they were used, leak the secret
    // share)
    // Rejection sampling here will prevent an honest participant from ever generating 'malicious'
    // values and ensure safety
    let mut res;
    while {
      seed.extend(repr.as_ref());
      res = Zeroizing::new(<Self as Curve>::hash_to_F(b"nonce", seed.deref()));
      res.ct_eq(&Self::F::ZERO).into()
    } {
      seed = Zeroizing::new(vec![0; 32]);
      rng.fill_bytes(&mut seed);
    }
    repr.as_mut().zeroize();

    res
  }
