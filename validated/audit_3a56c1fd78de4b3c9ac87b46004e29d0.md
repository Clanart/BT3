### Title
`isDiffTooLarge`/`MaxCharactersPerLine` gate suppresses the hidden-bidi-character warning on large diffs, letting a malicious commit's obfuscated changes be committed/pushed unreviewed - ([File: app/src/lib/git/diff.ts])

### Summary
GitHub Desktop's diff pipeline has a protective invariant: any hunk containing a line longer than `MaxCharactersPerLine` (5000 chars) is classified as `DiffType.LargeText` and hidden from the user behind a "Show Diff" button <cite repo="Kirstentat/desktop--008" path="app/src/lib/git/diff.ts" start="57,61" end="61,61" />. Separately, Desktop has a dedicated safety feature — the `HiddenBidiCharsRegex` check and `DiffContentsWarning` banner — meant to flag bidirectional/invisible Unicode characters that can make reviewed code look different from what is actually compiled/executed [1](#0-0) [2](#0-1) . Like the `maxRecordsPerTransaction` check in the report, the size-limiting logic exists for a different purpose (UI performance) but is implicitly treated as "safe/reviewed" once a user clicks "Show Diff" — while the underlying bidi-warning mechanism is never surfaced for the initial large-diff placeholder state, giving a false sense that the diff has been checked for hidden characters when it has not.

### Finding Description
When a diff (or a single hunk within it) exceeds `MaxReasonableDiffSize` or contains a line longer than `MaxCharactersPerLine`, `buildDiff` returns `DiffType.LargeText` instead of `DiffType.Text` [3](#0-2) . The UI then renders a placeholder ("The diff is too large to be displayed by default...") with a "Show Diff" button, and only calls `renderTextDiff` (which mounts `DiffContentsWarning`) after the user explicitly clicks through [4](#0-3) [5](#0-4) [6](#0-5) .

Critically, `hasHiddenBidiChars` **is already computed** at parse time for the whole diff (`HiddenBidiCharsRegex.test(text)` in `DiffParser.parse`) regardless of whether the diff is large [7](#0-6) , and it is carried through into the `ILargeTextDiff` object passed to the UI [8](#0-7) . However, the `renderLargeTextDiff()` placeholder view — the default view a reviewer sees for any diff over the size threshold — does **not** render `DiffContentsWarning` or otherwise surface `diff.hasHiddenBidiChars`; that warning only appears once `forceShowLargeDiff` is set and the "Show Diff" button is clicked to fall through to `renderLargeText` → `renderTextDiff` [5](#0-4) .

This means a malicious repository author can craft a commit containing one abnormally long line (or padding a file to exceed `MaxReasonableDiffSize`) specifically to force Desktop into the collapsed `LargeText` state. A user reviewing the Changes/History view is shown "diff too large" with the option to expand, and many users will commit/push, cherry-pick, or merge without clicking "Show Diff" — at which point the existing bidi-character protection (which the app already computed and has available) is silently skipped. The size-limit check, meant only to protect UI rendering performance, is effectively (mis)used by an attacker as a way to suppress the security-relevant bidi warning, exactly mirroring the reported pattern where a legitimate anti-abuse check ("maxRecordsPerTransaction") does not actually protect against the attack it's assumed to prevent and creates a false sense of security.

### Impact Explanation
Impact is Medium: this does not grant code execution directly inside Desktop, but it enables "silent corruption of what the user commits or pushes" — a user can be tricked into committing/pushing/merging a change containing hidden bidirectional Unicode trojan-source style obfuscation without ever seeing the warning banner that Desktop specifically built to protect against this class of attack, because the size gate hides the diff (and the warning inside it) by default.

### Likelihood Explanation
Likelihood is Medium: any contributor to a shared repo, or maintainer reviewing/merging a PR branch fetched into Desktop, can trigger this simply by including one long line or a large enough diff alongside their bidi-obfuscated payload — no admin rights, local access, or social engineering beyond a normal PR/commit is required, matching the "unprivileged attacker controls a cloned/fetched repository" threat model.

### Recommendation
Surface `diff.hasHiddenBidiChars` (and the `DiffContentsWarning`) in the collapsed `renderLargeTextDiff()` placeholder state as well, so users are warned about hidden bidi characters before they decide whether to expand and review the diff, rather than only after opting in. Alternatively, treat diffs with `hasHiddenBidiChars === true` as never eligible for the size-based collapse, forcing them to render (or at minimum show the warning) regardless of `MaxCharactersPerLine`/`MaxReasonableDiffSize`.

### Proof of Concept
1. Attacker creates a file with one line padded past 5,000 characters (or a diff totaling more than ~4.375MB) that also contains bidi override characters (e.g., U+202E) hiding malicious logic, per `HiddenBidiCharsRegex` [9](#0-8) .
2. Attacker opens a PR / pushes to a branch that the victim fetches/checks out in GitHub Desktop.
3. `buildDiff` classifies this as `DiffType.LargeText` because of the long line, even though `hasHiddenBidiChars` was computed as `true` [3](#0-2) .
4. The victim, viewing Changes/History, sees only "The diff is too large to be displayed by default" with a "Show Diff" button [10](#0-9)  — the `DiffContentsWarning` bidi banner is not shown at this stage.
5. Believing the file is just large/binary-like/uninteresting, the victim commits, merges, or pushes without clicking "Show Diff", silently propagating the obfuscated malicious content without ever seeing Desktop's own hidden-Unicode-character protection.

Note: I was not able to fully verify from the indexed code snippets whether any other code path (e.g., commit summary auto-generation or PR merge flows) independently re-checks `hasHiddenBidiChars` before committing/pushing; a full audit of `app/src/ui/diff/` and commit-flow components would be needed to confirm there is no secondary warning elsewhere in the app.

  private getTextDiffWarningItems(): ReadonlyArray<DiffContentsWarningItem> {
    const items = new Array<DiffContentsWarningItem>()
    const { diff } = this.props

    if (diff.hasHiddenBidiChars) {
      items.push({
        type: DiffContentsWarningType.UnicodeBidiCharacters,
      })
    }

    if (diff.lineEndingsChange) {
      items.push({
        type: DiffContentsWarningType.LineEndingsChange,
        lineEndingsChange: diff.lineEndingsChange,
      })
    }

    return items
  }
