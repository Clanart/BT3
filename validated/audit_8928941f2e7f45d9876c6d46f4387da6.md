Based on my investigation, I found a strong analog in the `kaiax/gasless` module (KIP-247 gasless transactions), which is reachable by an unprivileged gasless user / block proposer without needing any consensus-level privilege.

### Title
Stale swap-router/allowed-token cache in the gasless module lets a same-block admin change cause the proposer to lend gas that is never repaid - (File: kaiax/gasless/impl/getter.go, kaiax/gasless/impl/execution.go)

### Summary
The `GaslessModule` only refreshes its cached `swapRouter` address and `allowedTokens` set once per block, in `PostInsertBlock`, i.e. strictly *after* a block has already been committed [1](#0-0) . All mempool/bundle-building validation for the *next* block (`IsApproveTx`, `IsSwapTx`, `IsExecutable`) is performed against this one-block-stale cache [2](#0-1) . This is analogous to the reported pattern where an admin can change system parameters "just ahead of incoming transactions" with no warning or time-lock, causing unpredictable behavior for unprivileged users/proposers relying on the previous state.

### Finding Description
`updateAddresses` populates `g.swapRouter`/`g.allowedTokens` from the `GaslessSwapRouter` contract via the Registry/MultiCall contract, but it is invoked only from `PostInsertBlock`, once per inserted block [3](#0-2) . When the block builder assembles a candidate block, it uses this cached (previous-block) view to decide whether a transaction pair qualifies as a gasless bundle and to generate the `LendTx` that unconditionally transfers real KAIA from the block proposer to the user, prepended before the user's `ApproveTx`/`SwapTx` [4](#0-3) [5](#0-4) .

Because the on-chain `GaslessSwapRouter` owner can call `AddToken`/`RemoveToken` (owner-gated mutator functions confirmed in the generated bindings) [6](#0-5)  within the very block being built, the actual on-chain state at execution time can differ from the cached state used to decide the `LendTx`. The `LendTx` is a separate, unconditional transaction placed ahead of the swap in the bundle - it is not atomic with the swap's success, so if the router/token is invalidated on-chain in the same block, the subsequent `SwapTx` can fail/revert against the router while the `LendTx` value has already been irreversibly sent to the user.

### Impact Explanation
If exploited (whether maliciously by whoever controls the `GaslessSwapRouter`/Registry owner key, or simply through unlucky timing of a legitimate parameter update), the block proposer's `LendTx` funds are lost with no repayment, since the `checkBalanceForSwap`/`IsExecutable` gating and the generated `LendTx` were computed from a state that the actual on-chain execution no longer honors [7](#0-6) . This is a concrete fee-delegation/gasless-settlement value-loss scenario reachable purely by submitting normal gasless transactions and by ordinary owner-triggered configuration changes - no consensus-level or peer-level compromise is required.

### Likelihood Explanation
This does not require a malicious validator/peer; it only requires whoever administers the `GaslessSwapRouter` contract (or the party controlling the Registry entry for it) to call `addToken`/`removeToken`/register a new router in the same block window as pending gasless swaps, or for such a change to simply be made without any advance notice or time-lock. Given the module explicitly documents refreshing addresses only "every block" post-insertion [8](#0-7) , this one-block staleness window is a structural, always-present condition rather than a rare race.

### Recommendation
Introduce a mandatory delay/time-lock between an on-chain change to the `GaslessSwapRouter` address or its allowed-token list and the point at which that change takes effect for bundle building, and/or make the `LendTx` conditional on/atomic with the swap's success (e.g., verify router/token validity against the state root the block is being built on, not the previous block's cached snapshot, before generating the `LendTx`).

### Proof of Concept
1. GaslessSwapRouter owner (or the Registry entry maintainer) observes a pending `GaslessApproveTx`/`GaslessSwapTx` pair for token `T` in the mempool.
2. In the same block being assembled, the owner calls `removeToken(T)` on `GaslessSwapRouter` (owner-gated mutator, per bindings) [6](#0-5) .
3. Because `g.allowedTokens`/`g.swapRouter` were last refreshed in `PostInsertBlock` of the prior block [1](#0-0) , the builder still treats the user's transactions as a valid gasless bundle and prepends a `LendTx` sending real KAIA from the proposer to the user [5](#0-4) .
4. The user's `SwapTx` executes against the now-updated on-chain state where `T` is no longer allowed, causing it to fail/behave unexpectedly, while the `LendTx` value transfer to the user already succeeded and is not repaid.

Note: I could not locate the actual `GaslessSwapRouter.sol` source in the indexed contents (only the generated Go bindings were available), so I could not fully confirm the exact revert/repay semantics inside `swapForGas` on-chain. If a full audit of that exact revert path is needed, a Devin session with full repository access should be used to confirm.

func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}

func (g *GaslessModule) updateAddresses(header *types.Header) error {
	g.gaslessInfoMu.Lock()
	defer g.gaslessInfoMu.Unlock()

	swapRouter, tokens, err := getGaslessInfo(g.Chain, header)
	// proceed even if there is something wrong with multicall contract
	if err != nil {
		g.swapRouter = common.Address{}
		g.allowedTokens = map[common.Address]bool{}
		logger.Warn("there is something wrong with multicall contract", "err", err.Error())
		return nil
	}

	g.swapRouter = swapRouter

	g.allowedTokens = map[common.Address]bool{}
	for _, addr := range tokens {
		// all tokens are allowed if nil
		if g.GaslessConfig.AllowedTokens == nil {
			g.allowedTokens[addr] = true
		}
		for _, allowed := range g.GaslessConfig.AllowedTokens {
			if addr == allowed {
				g.allowedTokens[addr] = true
			}
		}
	}

	return nil
}

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {

		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// If SwapTx.nonce is the sender's next nonce, then there is no room for ApproveTx proceeding SwapTx.
		senderNonce := g.getCurrentStateNonce(swapArgs.Sender)
		noApproveTxPreceeds := swapNonce == senderNonce
		if noApproveTxPreceeds {
			// tx.token.allowance(sender, router) >= tx.amountIn
			approval, err := tokenContract.Allowance(nil, swapArgs.Sender, swapRouter)
			if err != nil {
				return err
			}
			if approval.Cmp(swapArgs.AmountIn) < 0 {
				return fmt.Errorf("insufficient approval: approval=%s, want=%s", approval.String(), swapArgs.AmountIn.String())
			}
		}

		// tx.token.balanceOf(sender) >= tx.amountIn
		balance, err := tokenContract.BalanceOf(nil, swapArgs.Sender)
		if err != nil {
			return err
		}
		if balance.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("insufficient balance: balance=%s, want=%s", balance.String(), swapArgs.AmountIn.String())
		}
	}

	// tx.deadline >= currentTimestamp
	deadline := swapArgs.Deadline
	if deadline.Cmp(g.Chain.CurrentBlock().Time()) < 0 {
		return fmt.Errorf("insufficient deadline: deadline=%s, want=%s", deadline.String(), g.Chain.CurrentBlock().Time().String())
	}

	return nil
}
