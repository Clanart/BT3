### Title
Git pathspec glob-magic in `_diff_pathspec`/`get_git_diff` lets a crafted filename widen the diff beyond the intended file, leaking unrelated file content to the remote reviewer - (File: `plugins/security-guidance/hooks/gitutil.py`)

### Summary
`get_git_diff` builds its `git diff -- <pathspec>` argument list from `_diff_pathspec`, which turns each touched/changed absolute path into a repo-relative string and splices it straight after `--` without disabling git's default pathspec "glob" and "magic-signature" semantics (no `--literal-pathspecs`, no `:(literal)` prefix, no escaping). A repository containing (or an attacker/prompt-injection causing Claude to touch) a file whose literal name embeds pathspec-special characters (`*`, `?`, `[...]`, or a leading `:`) causes that string to be interpreted as a glob/magic pathspec by `git diff` rather than a literal path, so the resulting diff can match and include content from files never intended to be in scope.

### Finding Description
`_diff_pathspec` (`plugins/security-guidance/hooks/gitutil.py:70-88`) correctly guards against absolute-path/symlink escape (via `os.path.realpath` + `relpath` + reject `..`), but it does nothing to neutralize git pathspec syntax in the resulting relative strings. `get_git_diff` (`plugins/security-guidance/hooks/gitutil.py:391-427`) then runs:

```
cmd = [*GIT_CMD, "diff", ..., baseline_sha] + [...] + pathspec
```

`GIT_CMD` (`gitutil.py:25-29`) never sets `--literal-pathspecs`/`core.literalPathspecs`, so every element after `--` is matched by git's default fnmatch-style glob pathspec engine, and a leading `:` triggers pathspec "magic" (`:(icase)`, `:(exclude)`, `:(glob)`, etc.).

The `paths` list ultimately comes from `compute_v2_review_set` (`plugins/security-guidance/hooks/diffstate.py:353-438`), which derives the "review set" from `git status --porcelain` / `git diff --name-only` output — i.e. real, repo-controlled filenames of files that are dirty/committed during the turn. Nothing filters these names for pathspec metacharacters before they are passed into `get_git_diff`'s `paths=`. A repo can legally contain filenames like `weird*name.py`, `config?.py`, or `:secrets.env` (valid on Linux); if such a file is the one Claude touches (directly, or via a prompt-injected instruction embedded in repo content), its relative path becomes an unescaped pathspec element. Git then expands the glob against the whole tree, so the diff picked up by `get_git_diff` can include unrelated files that happen to match the pattern — for example other files under the same directory, including ones holding secrets or credentials that were never part of the intended change.

That over-broad diff text flows through `parse_diff_into_files`/`extract_file_paths_from_diff` and is handed to the LLM-based commit/Stop-hook reviewer (`review_api.py`/`llm.py`), which is a remote network sink. This breaks the stated invariant ("git path scoping must never escape the intended repo target") purely through content that already exists in the repository — no elevated privilege, leaked credential, or admin access is required.

### Impact Explanation
An over-scoped pathspec can pull unrelated, potentially sensitive file diffs (secrets, tokens, other users' WIP) into the payload sent to the remote review LLM API, matching the "Sensitive code, prompt, token, diff, or local file disclosure to an unintended local or remote sink" impact category. The disclosure is silent (the extra files are folded into the same diff string) and the reviewer/CCR endpoint is outside the local trust boundary.

### Likelihood Explanation
Requires only that a repository (which the attacker can influence via ordinary content — a crafted filename committed to the repo, or one created as a side effect of a prompt-injected instruction) contains a file whose name embeds pathspec-special characters and that this file ends up in the touched/dirty set that seeds `get_git_diff`. No maintainer/admin privilege, no leaked credentials, and no social engineering of the operator is needed — an unprivileged contributor or a malicious file already checked into the tree is sufficient. This is straightforward to reproduce deterministically with a unit test.

### Recommendation
Disable pathspec magic entirely for these internal calls: prepend `-c core.literalPathspecs=true` (or pass `--literal-pathspecs`) to `GIT_CMD`/the `git diff` invocation in `get_git_diff`, or explicitly wrap every element produced by `_diff_pathspec` with the `:(literal)` magic prefix (`":(literal)" + r`) so each relative path is matched byte-for-byte regardless of embedded `*`, `?`, `[`, or a leading `:`.

### Proof of Concept
Unit/integration test plan for `gitutil.py`:
1. Create a temp git repo with two files: `dir/weirdXname.py` (pre-existing, committed, containing a fake secret) and `dir/weird*name.py` (the file actually touched this turn, committed with a trivial change).
2. Call `get_git_diff(cwd, baseline_sha, paths=[os.path.join(cwd, "dir/weird*name.py")])`.
3. Assert the returned diff contains **only** the `diff --git a/dir/weird*name.py b/dir/weird*name.py` hunk and does **not** contain `dir/weirdXname.py` or its "secret" content.
4. Before the fix, the glob `weird*name.py` also matches `weirdXname.py`, so the assertion fails (diff includes both files) — demonstrating the pathspec escape. After adding `--literal-pathspecs` / `:(literal)` prefixing, only the exact file is diffed.
