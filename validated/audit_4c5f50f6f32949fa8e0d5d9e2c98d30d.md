### Title
Missing `winternitz_log_d` Sanity Check in `ProtocolParamset` Parsing Silently Breaks the Disprove Path - (File: `crates/clementine-config/src/protocol.rs`)

### Summary
`ProtocolParamset::from_toml_file()` and `ProtocolParamset::from_env()` accept any value for `winternitz_log_d` without validating it equals the required constant `WINTERNITZ_LOG_D = 4`. The code explicitly documents this constraint but does not enforce it at parse time. If misconfigured, the disprove path fails at runtime, preventing verifiers from slashing a malicious operator and enabling theft of bridged BTC.

### Finding Description
`ProtocolParamset` contains a `winternitz_log_d` field that controls the Winternitz One-Time Signature (WOTS) parameter used throughout the bridge. The code explicitly documents:

> "Currently used in statics and thus cannot be different from `WINTERNITZ_LOG_D`."

The constant `WINTERNITZ_LOG_D = 4` is hardcoded in the BitVM static and is the only value the disprove extraction logic supports. [1](#0-0) 

However, neither `ProtocolParamset::from_toml_file()` nor `ProtocolParamset::from_env()` validate that `winternitz_log_d == WINTERNITZ_LOG_D`. The only validation performed at parse time is `finality_depth >= 1`: [2](#0-1) [3](#0-2) 

The runtime functions `extract_winternitz_commits()` and `extract_winternitz_commits_with_sigs()` do check `if paramset.winternitz_log_d != 4 { return Err(...) }`, but this guard fires during the disprove process — far too late: [4](#0-3) [5](#0-4) 

The inter-actor compatibility check (`CompatibilityParams::is_compatible()`) only verifies that all actors share the **same** `protocol_paramset` value — it does not verify the paramset is internally valid: [6](#0-5) 

If all actors are started with a shared misconfigured paramset file (e.g., `WINTERNITZ_LOG_D=5`), the compatibility check passes, the bridge starts normally, and the broken invariant is not detected until a disprove is attempted.

Additionally, `winternitz_log_d` is passed directly into `WinternitzCommit::new()` when building kickoff scripts: [7](#0-6) 

If `winternitz_log_d != 4`, the Bitcoin scripts are built with the wrong WOTS parameter, mismatching the BitVM static compiled with `WINTERNITZ_LOG_D = 4`. The disprove script is structurally wrong on-chain, and the extraction also fails at runtime.

The same missing-validation pattern applies to two other critical constraints with no enforcement at parse time:

- `num_signed_kickoffs <= num_kickoffs_per_round` — if violated, `get_kickoff_utxos_to_sign()` silently returns fewer indices than expected, breaking all deposit finalization: [8](#0-7) 

- Timelock ordering invariants (e.g., `assert_timeout_timelock < disprove_timeout_timelock`) — if `disprove_timeout_timelock < assert_timeout_timelock`, the disprove window closes before asserts are even submitted, allowing a malicious operator to escape slashing.

### Impact Explanation
If `winternitz_log_d` is misconfigured to any value other than 4, the disprove path is permanently broken for all kickoffs. A malicious operator can submit fraudulent BitVM assertions and not be slashed. The `disprove_timeout_txhandler` uses `paramset.disprove_timeout_timelock` as its sequence lock: [9](#0-8) 

Once the disprove timeout passes without a successful disprove, the operator's fraudulent withdrawal succeeds, stealing bridged BTC from the bridge. The operator's collateral is not slashed.

### Likelihood Explanation
The misconfiguration can occur when operators/verifiers share a single paramset TOML file or environment variable set. A single typo (e.g., `WINTERNITZ_LOG_D=40` instead of `4`) passes all startup checks, passes the inter-actor compatibility check, and is only detected when a disprove is attempted — at which point the bridge is already in a broken state. The `check_general_requirements()` function does not check `winternitz_log_d`: [10](#0-9) 

### Recommendation
Add the following validations in both `ProtocolParamset::from_toml_file()` and `ProtocolParamset::from_env()`:

```rust
if paramset.winternitz_log_d != WINTERNITZ_LOG_D {
    return Err(BridgeError::ConfigError(format!(
        "winternitz_log_d must be {} (got {})", WINTERNITZ_LOG_D, paramset.winternitz_log_d
    )));
}
if paramset.num_signed_kickoffs > paramset.num_kickoffs_per_round {
    return Err(BridgeError::ConfigError(
        "num_signed_kickoffs must be <= num_kickoffs_per_round".to_string()
    ));
}
if paramset.assert_timeout_timelock >= paramset.disprove_timeout_timelock {
    return Err(BridgeError::ConfigError(
        "assert_timeout_timelock must be < disprove_timeout_timelock".to_string()
    ));
}
// ... additional timelock ordering checks
```

Also extend `check_general_requirements()` to cover these invariants so they are validated at node startup.

### Proof of Concept
1. Set `WINTERNITZ_LOG_D=5` in the shared `protocol_paramset.toml` or environment.
2. Start all actors (operator, verifier, aggregator) with this paramset.
3. The compatibility check passes — all actors agree on `winternitz_log_d = 5`.
4. A malicious operator performs a fraudulent withdrawal: submits a kickoff, gets challenged, submits fraudulent BitVM asserts.
5. Verifiers attempt to disprove: `extract_winternitz_commits()` returns `Err("Only winternitz_log_d = 4 is supported")` at `core/src/builder/script.rs:63-64`.
6. The disprove transaction cannot be constructed. The disprove timeout (`disprove_timeout_timelock` blocks) passes.
7. The `disprove_timeout_txhandler` is spendable by the operator, who claims it and proceeds to reimbursement.
8. The malicious operator's fraudulent withdrawal succeeds; bridged BTC is stolen and operator collateral is not slashed. [11](#0-10) [12](#0-11)

    pub async fn check_general_requirements(&self) -> Result<(), BridgeError> {
        // check genesis state hash
        let rpc = ExtendedBitcoinRpc::connect(
            self.bitcoin_rpc_url.clone(),
            self.bitcoin_rpc_user.clone(),
            self.bitcoin_rpc_password.clone(),
            None,
        )
        .await
        .wrap_err("Failed to connect to Bitcoin RPC while checking general requirements")?;

        let genesis_chain_state = HeaderChainProver::get_chain_state_from_height(
            &rpc,
            self.protocol_paramset().genesis_height.into(),
            self.protocol_paramset().network,
        )
        .await
        .wrap_err("Failed to get genesis chain state while checking general requirements")?;

        let mut reasons = Vec::new();

        if genesis_chain_state.to_hash() != self.protocol_paramset().genesis_chain_state_hash {
            reasons.push(format!(
                "Genesis chain state hash mismatch, state hash generated from Bitcoin RPC ({}) does not match value in config ({})",
                hex::encode(genesis_chain_state.to_hash()),
                hex::encode(self.protocol_paramset().genesis_chain_state_hash)
            ));
        }

        if self.protocol_paramset().start_height < self.protocol_paramset().genesis_height {
            reasons.push(format!(
                "Start height is less than genesis height: {} < {}",
                self.protocol_paramset().start_height,
                self.protocol_paramset().genesis_height
            ));
        }

        if self.protocol_paramset().finality_depth < 1 {
            reasons.push(format!(
                "Finality depth ({}) cannot be less than 1",
                self.protocol_paramset().finality_depth
            ));
        }

        if !reasons.is_empty() {
            return Err(BridgeError::ConfigError(format!(
                "Invalid configuration due to: {}",
                reasons.join(" - ")
            )));
        }

        Ok(())
    }
