### Title
Sandwich-manipulable DEX swap output directly scales protocol-funded MGP bonus in `_bullMGP`, allowing attacker-controlled inflation of locked MGP relative to BUSD spent - ([File: wombat/ArbWomUp2.sol])

### Summary
`incentiveDeposit(_amount, _minMGPRec, true)` routes a protocol-funded, schedule-determined BUSD reward through a live PancakeRouter swap and then locks `amounts[1] * (DENOMINATOR + bullBonusRatio) / DENOMINATOR` MGP into `vlMGP`. Because `amounts[1]` is the raw output of a public, attacker-influenceable swap and `_minMGPRec` is a caller-supplied slippage parameter with no protocol-side minimum, an attacker can sandwich their own `incentiveDeposit(bullMode=true)` call to depress the BUSD/MGP price immediately beforehand, inflating `amounts[1]` and thus the bonus-scaled MGP locked, extracting more MGP from the protocol's bonus reserve than the BUSD reward schedule intends.

### Finding Description
`incentiveDeposit` computes `rewardToSend` from a fixed WOM-deposit-based tier schedule via `getRewardAmount` [1](#0-0) , which is deterministic and not swap-dependent. When `_bullMode` is true, this fixed BUSD amount is passed into `_bullMGP`, which swaps it for MGP through `ROUTER.swapExactTokensForTokens` and then computes the amount to lock as a multiple of the *actual swap output*, not of the fixed BUSD input converted at a fair/oracle price: [2](#0-1) 

`_minMGPRec` is fully attacker-controlled (passed straight through from `incentiveDeposit`'s caller-supplied parameter), so the attacker can set it to `0` or a trivially low value, removing any protocol-side floor on the swap price. The attacker can then:
1. Front-run by selling MGP into the BUSD/MGP pool, depressing MGP's price.
2. Call `incentiveDeposit(_amount, 0, true)` — the depressed price causes `swapExactTokensForTokens` to return an inflated `amounts[1]` for the same fixed BUSD input.
3. Back-run by buying MGP back, restoring the pool price (largely recovering the capital used to move the price, minus fees/temporary slippage cost).

Because `mgpAmountToLcok` is derived by multiplying the *manipulated* `amounts[1]` by `(DENOMINATOR + bullBonusRatio)/DENOMINATOR`, and the bonus portion above `amounts[1]` must be funded from the contract's own pre-existing MGP balance (it is not itself received from the swap), the attacker extracts additional MGP from the protocol's bonus reserve in direct proportion to how far they can move the pool price — a value not tied to the actual BUSD budget spent by the protocol. Existing guards (`whenNotPaused`, `nonReentrant`, `_checkAmount`) do not defend against this because they do not constrain swap-price integrity or enforce a protocol-side minimum output/TWAP check.

### Impact Explanation
This breaks the intended backing invariant: locked MGP should correspond to the protocol's BUSD-funded reward schedule, not to a manipulable AMM execution price. Each exploit iteration allows an attacker to convert a fixed BUSD reward into a larger MGP bonus than intended, directly draining the protocol's MGP reserve used to fund `bullBonusRatio` bonuses. Repeated over multiple deposits/tiers, this constitutes a quantifiable protocol-insolvency-style loss of MGP backing (Immunefi "Direct theft of protocol funds" / "Protocol insolvency").

### Likelihood Explanation
The attack requires only: (1) capital to move the BUSD/MGP pool price temporarily — obtainable via flash loan since no special role is needed for spot swaps, (2) calling the public `incentiveDeposit` with `_minMGPRec` set low/zero, and (3) reversing the price after. All actions are available to any unprivileged EOA/contract and are repeatable across separate WOM deposits/tiers, subject only to available WOM-deposit budget and pool liquidity/fees, making this practically feasible and repeatable, not merely theoretical.

### Recommendation
Do not scale the bonus off the live/manipulable swap output. Instead: (a) enforce a protocol-defined minimum acceptable output (e.g., TWAP-based or oracle-based fair price check) rather than trusting caller-supplied `_minMGPRec`; (b) compute `mgpAmountToLcok`'s bonus portion from the BUSD input converted at a fixed/oracle-derived rate rather than `amounts[1]`; or (c) cap the bonus multiplier applied against a sanity-checked expected output computed independently of the just-executed swap.

### Proof of Concept
Foundry fork test plan:
1. Fork BSC mainnet at a block with the real BUSD/MGP Pancake pool and deployed `ArbWomUp2`.
2. Baseline run: call `incentiveDeposit(amount, quotedMinOut, true)` under normal pool conditions; record `mgpAmountToLcok` from the `VLMGPRewarded` event.
3. Sandwich run: from a second attacker EOA, (a) swap a large amount of MGP for BUSD in the same pool to depress MGP price, (b) call `incentiveDeposit(amount, 0, true)` for the victim/attacker account, (c) swap BUSD back for MGP to restore price.
4. Assert that the `mgpAmountToLcok` locked in step 3 is materially larger than baseline for the identical BUSD reward budget (`rewardToSend`), demonstrating locked-MGP inflation disproportionate to protocol-funded BUSD spend.

    function incentiveDeposit(
        uint256 _amount, uint256 _minMGPRec, bool _bullMode
    ) external _checkAmount(_amount) whenNotPaused nonReentrant {
        if (_amount == 0) return;

        uint256 rewardToSend = this.getRewardAmount(_amount, msg.sender);
        _deposit(_amount);
        claimedReward[msg.sender] += rewardToSend;
        
        if (_bullMode) {
            _bullMGP(rewardToSend, _minMGPRec, msg.sender);
        } else {
            IERC20(busd).transfer(msg.sender, rewardToSend);
            emit BUSDRewarded(msg.sender, rewardToSend);
        }
    }

    function _bullMGP(uint256 _busdAmount, uint256 _minRec, address _account) internal {
        IERC20(busd).safeApprove(address(ROUTER), _busdAmount);
        
        address[] memory path = new address[](2);
        path[0] = busd;
        path[1] = mgp;
        uint256[] memory amounts = ROUTER.swapExactTokensForTokens(
            _busdAmount,
            _minRec,
            path,
            address(this),
            block.timestamp
        );

        uint256 mgpAmountToLcok = amounts[1] * (DENOMINATOR + bullBonusRatio) / DENOMINATOR; // get bull mode bonus
        IERC20(mgp).approve(address(vlMGP), mgpAmountToLcok);
        vlMGP.lockFor(mgpAmountToLcok, _account);

        emit VLMGPRewarded(_account, _busdAmount, mgpAmountToLcok);
    }
