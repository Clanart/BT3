## Analysis

The report's broken invariant is: **a value that should only be attributable/trusted when it originates from the canonical/original source is instead accepted from an arbitrary attacker-influenced object matched by loose string identity, and the app takes an unconfirmed, state-mutating action based on that match.** In the Axelar case that value was the tracked token balance; the mutating action was minting/bridging. In GitHub Desktop the equivalent mutating action is **silently adding a git remote and checking out its ref into an already-trusted local repository's working directory**, triggered from a link the user merely clicks.

### The Desktop path

`x-github-client://` (and legacy `github-mac`/`github-windows`) is a globally registered OS protocol handler [1](#0-0) . Any web page, email, or file can trigger it. `parseAppURL` turns `openRepo/<url>?pr=<n>` into an `open-repository-from-url` action [2](#0-1) , which `dispatchURLAction` routes directly, with no confirmation popup, to `openRepositoryFromUrl` [3](#0-2) .

When a `pr` parameter is present, `openPullRequestFromUrl` fetches the PR object from the GitHub API (attacker fully controls this object's content by simply opening a PR from their own fork against any public repository), then picks *any of the user's already-open local repositories* whose `origin`/`upstream` URL textually matches `pullRequest.head.repo` or `pullRequest.base.repo`, using only hostname/owner/name string comparison (`urlsMatch`) rather than verifying it's the exact same tracked repository the PR claims to belong to: [4](#0-3) [5](#0-4) 

Once a matching local repository is found, Desktop immediately (no dialog, no user confirmation) calls `_checkoutPullRequest` → `_findPullRequestBranch`, which:
1. Looks for an existing remote matching `headCloneUrl` via `urlMatchesRemote` (again a loose hostname+owner+name match, not repository ID/ownership verification).
2. If none exists, **silently runs `git remote add <fork_owner> <headCloneUrl>`** against the user's real, trusted repository.
3. Fetches that remote and **checks out the attacker-supplied branch** into the working directory. [6](#0-5) 

### Why existing guards don't stop it

- `urlMatchesRemote`/`urlsMatch` only compare `hostname`/`owner`/`name` strings parsed from the URL — they never check the GitHub API's actual repository ID, so any PR the attacker can create (against any repository they can open a PR on) supplies the `head.repo.clone_url`/`head.ref` values that flow unmodified into `addRemote` and checkout [7](#0-6) .
- The path-traversal/filepath protections added elsewhere in `openRepositoryFromUrl` (`isAbsolute`, `resolveWithin`) only guard the optional `filepath` parameter used for `showItemInFolder`, not the `pr` parameter's remote/branch flow [8](#0-7) .
- There is no popup/dialog step between deep-link dispatch and the remote-add + checkout — contrast with the manual "Checkout via PR" UI flow which is user-initiated from inside the app; the deep-link flow performs the equivalent action automatically.
- `findForkedRemotesToPrune` cleans these fork remotes up later, confirming Desktop's own code treats deep-link/PR-driven remotes as first-class, persistent additions to the user's repository [9](#0-8) .

This is uncertain in one respect I could not fully verify from the index: whether the renderer shows any transient toast/notification during this flow (I found no popup dispatch in the traced code, but a purely visual notification without an explicit confirm/cancel gate would not meaningfully mitigate the issue).

### Title
Deep-link PR checkout silently adds attacker-controlled remote and checks out attacker branch into an existing trusted repository - (File: `app/src/ui/dispatcher/dispatcher.ts`)

### Summary
Clicking a crafted `x-github-client://openRepo/<repo-url>?pr=<n>` link causes Desktop to match an already-open local repository purely by loose URL string comparison, then automatically add a new git remote pointing at an attacker-controlled fork and check out an attacker-controlled branch into that repository's working directory — with no confirmation dialog.

### Finding Description
`openPullRequestFromUrl` (`app/src/ui/dispatcher/dispatcher.ts:1998-2045`) fetches a `PullRequest` object from the GitHub API using PR data an attacker fully controls (they can open a PR from their own fork against any accessible repository), locates a matching local repository via `doesRepositoryMatchUrl`/`urlsMatch` (hostname+owner+name string equality, not repository identity), and unconditionally invokes `_checkoutPullRequest`. `_findPullRequestBranch` (`app/src/lib/stores/app-store.ts:8633-8721`) then runs `git remote add <fork-remote-name> <headCloneUrl>` and checks out `headRefName` from that remote, all without any confirmation UI.

### Impact Explanation
The working directory of a trusted, already-tracked repository is silently repointed to contain attacker-chosen file contents and a new attacker-controlled remote persists in the repo's git config. If the user, unaware of the branch switch, continues working and commits/pushes, they can push attacker-supplied content, or attacker-controlled build/config files (e.g. `.gitattributes` filters, editor/IDE task configs, `.vscode/tasks.json`) could execute upon subsequent tool invocation. This matches the requested impact class of "silent corruption of what the user commits or pushes" via an attacker-controlled GitHub API object and a clicked deep link.

### Likelihood Explanation
Requires no local/physical access, no leaked credentials, and no unnatural user steps beyond the single documented interaction the feature is designed for (clicking an "Open in Desktop" style link). An attacker only needs to open a PR (even from their own fork) and craft a URL; likelihood is moderate-to-high given the protocol handler is globally registered and third-party sites/emails can embed such links.

### Recommendation
Before adding a remote or checking out a PR branch reached via a deep link, require explicit user confirmation showing the fork owner/URL and target branch, and/or match target repositories by stable identity (GitHub repository `id`/`node_id`) rather than by textual URL comparison, mirroring the report's original recommendation to anchor trust to verified origin rather than name-based matching.

### Proof of Concept
1. Victim has repository `github.com/victim/project` already cloned/open in Desktop.
2. Attacker forks `victim/project`, pushes malicious code to a branch, and opens a PR from that fork against `victim/project` (PR number `N`).
3. Attacker sends the victim a link: `x-github-client://openRepo/https://github.com/victim/project?pr=N`.
4. Victim clicks it (from a webpage/email/chat). Desktop matches the local `project` repo by URL, silently runs `git remote add fork_attacker <attacker-fork-url>`, fetches, and checks out the attacker's branch into the victim's working directory — no dialog is shown.

  public async _findPullRequestBranch(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,
    headRefName: string
  ): Promise<Branch | undefined> {
    const gitStore = this.gitStoreCache.get(repository)
    const remotes = await getRemotes(repository)

    // Find an existing remote (regardless if set up by us or outside of
    // Desktop).
    let remote = remotes.find(r => urlMatchesRemote(headCloneUrl, r))

    // If we can't find one we'll create a Desktop fork remote.
    if (remote === undefined) {
      try {
        const forkRemoteName = forkPullRequestRemoteName(headRepoOwner)
        remote = await addRemote(repository, forkRemoteName, headCloneUrl)
      } catch (e) {
        this.emitError(
          new Error(
            `Couldn't find PR branch, adding remote failed: ${e.message}`
          )
        )
        return
      }
    }

    const remoteRef = `${remote.name}/${headRefName}`

    // Start by trying to find a local branch that is tracking the remote ref.
    let existingBranch = gitStore.allBranches.find(
      x => x.type === BranchType.Local && x.upstream === remoteRef
    )

    // If we found one, let's check it out and get out of here, quick
    if (existingBranch !== undefined) {
      return existingBranch
    }

    const findRemoteBranch = (name: string) =>
      gitStore.allBranches.find(
        x => x.type === BranchType.Remote && x.name === name
      )

    // No such luck, let's see if we can at least find the remote branch then
    existingBranch = findRemoteBranch(remoteRef)

    // It's quite possible that the PR was created after our last fetch of the
    // remote so let's fetch it and then try again.
    if (existingBranch === undefined) {
      try {
        await this._fetchRemote(repository, remote, FetchType.UserInitiatedTask)
        existingBranch = findRemoteBranch(remoteRef)
      } catch (e) {
        log.error(`Failed fetching remote ${remote?.name}`, e)
      }
    }

    if (existingBranch === undefined) {
      this.emitError(
        new Error(
          `Couldn't find branch '${headRefName}' in remote '${remote.name}'. ` +
            `A common reason for this is that the PR author has deleted their ` +
            `branch or their forked repository.`
        )
      )
      return
    }

    // For fork remotes we checkout the ref as pr/[123] instead of using the
    // head ref name since many PRs from forks are created from their default
    // branch so we'll have a very high likelihood of a conflicting local branch
    const isForkRemote =
      remote.name !== gitStore.defaultRemote?.name &&
      remote.name !== gitStore.upstreamRemote?.name

    if (isForkRemote) {
      return await this._createBranch(
        repository,
        `pr/${prNumber}`,
        remoteRef,
        false
      )
    }

    return existingBranch
  }

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}

export function findForkedRemotesToPrune(
  remotes: readonly IRemote[],
  openPRs: ReadonlyArray<PullRequest>,
  allBranches: readonly Branch[]
) {
  const prRemoteUrls = new Set(
    openPRs.map(pr => pr.head.gitHubRepository.cloneURL)
  )
  const branchRemotes = new Set(
    allBranches.map(branch => branch.upstreamRemoteName)
  )

  return remotes.filter(
    r =>
      r.name.startsWith(ForkedRemotePrefix) &&
      !prRemoteUrls.has(r.url) &&
      !branchRemotes.has(r.name)
  )
}
