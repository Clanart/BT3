## Finding: `git clone` explicitly disables Git's clone-time symlink/hook protection

The bug report's core pattern — an unchecked internal safety threshold that a remote-controlled/time-controlled input can push past, letting an attacker regain a dangerous state that "should never happen" — maps to a concrete GitHub Desktop analog: a *protection flag that Desktop actively force-disables* on every clone, re-opening a known Git RCE class for any attacker-controlled remote.

### Title
Desktop forces `GIT_CLONE_PROTECTION_ACTIVE=false` on every recursive clone, disabling Git's built-in clone-time symlink/hook protection - (File: `app/src/lib/git/clone.ts`)

### Summary
`clone()` builds the environment for every `git clone --recursive` invocation and unconditionally sets `GIT_CLONE_PROTECTION_ACTIVE: 'false'` [1](#0-0) . This environment variable is the runtime kill-switch Git added for the clone-time protections that prevent hostile repositories (including nested submodules, since `--recursive` is always passed) from writing into sensitive locations such as `.git/hooks` via symlink or case-insensitive filesystem tricks. Desktop is telling Git to *not* apply this protection on every single clone the user performs, regardless of who controls the remote.

### Finding Description
The clone path only guards against one class of attack — a path-traversal-derived destination directory landing in a sensitive host location (`isClonePathSensitive`) [2](#0-1) . That guard protects the *destination* the user chose, but does nothing about *content inside the repository being cloned* — which is exactly the attacker-controlled input in scope here (a cloned/fetched repository whose remote and content are fully under attacker control).

Immediately after that check, the function builds the git environment and explicitly disables Git's clone protection:
```
const env = {
  ...(await envForRemoteOperation(url)),
  GIT_CLONE_PROTECTION_ACTIVE: 'false',
}
...
const args = [
  '-c', `init.defaultBranch=${defaultBranch}`,
  'clone', '--recursive',
]
``` [1](#0-0) 

`--recursive` means submodules (potentially many layers deep, each independently attacker-controlled if the top-level repo is malicious) are cloned as part of the same operation [3](#0-2) . The submodule update path elsewhere in the codebase similarly always passes `--recursive` for `submodule update --init` [4](#0-3) , and can even append `-c protocol.file.allow=always` when `allowFileProtocol` is set, further loosening submodule URL restrictions [4](#0-3) .

None of the existing tests exercise or justify this specific disabling of clone protection — the clone tests only cover the sensitive-destination-path guard [5](#0-4) , so there is no evidence this is a deliberate, reviewed trade-off tied to a specific compatibility requirement.

### Impact Explanation
If Git's clone protection (the mechanism gated by `GIT_CLONE_PROTECTION_ACTIVE`) is what stands between a hostile repository/submodule tree and writes outside the intended working directory (e.g., into `.git/hooks`, which are then trivially executed by subsequent Git operations Desktop performs, such as `commit`, `pull`, or `checkout`), then explicitly disabling it converts "clone an attacker-controlled repository" into a code-execution primitive. This satisfies the report's required impact bar: attacker controls a cloned/fetched repository, and the result is code execution / file write outside the repo via a corrupted safety invariant that existing guards (the destination path check) do not cover.

### Likelihood Explanation
Every clone performed through Desktop's UI, CLI (`--cli-clone`), or "Open in Desktop" deep-link flow (`x-github-client://openRepo/...`, handled by `parseAppURL` / `openOrCloneRepository`) goes through this same `clone()` function [6](#0-5) [7](#0-6) . No user interaction beyond cloning a URL the attacker supplied (which is a completely normal, expected Desktop workflow) is required — there is no local access, admin rights, or prior compromise needed, matching the report's "unprivileged... attacker controls a cloned/fetched repository" scope.

### Recommendation
Remove the explicit `GIT_CLONE_PROTECTION_ACTIVE: 'false'` override so Git's default (protection-active) behavior applies to `clone()`. If there is a genuine compatibility reason for disabling it (e.g., a specific legitimate submodule/workflow that trips the protection), that reason should be documented and the override scoped as narrowly as possible (e.g., only for local/trusted `file://` clones), not applied unconditionally to every clone including ones from arbitrary attacker-supplied remotes.

### Proof of Concept
1. An attacker crafts a malicious Git repository (or a submodule referenced by one) exploiting the class of clone-time symlink/hooks vulnerability that `GIT_CLONE_PROTECTION_ACTIVE` is designed to prevent (case-insensitive filesystem or symlinked `.git`-alike path tricks during recursive submodule clone).
2. Victim clones this repository through GitHub Desktop — via the normal "Clone repository" dialog, `--cli-clone`, or by clicking an `x-github-client://openRepo/<attacker-url>` deep link, which Desktop resolves through `parseAppURL` → `dispatchURLAction` → `openOrCloneRepository` → `clone()` [8](#0-7) [9](#0-8) .
3. Because `clone()` sets `GIT_CLONE_PROTECTION_ACTIVE=false` and passes `--recursive` [1](#0-0) , Git performs the clone/submodule-init without the protection that would otherwise reject or sanitize the hostile paths, allowing the attacker's payload to land outside the intended repository tree (e.g., a hook executable) rather than being blocked.
4. Any subsequent Git operation Desktop triggers on that repository (commit, checkout, pull) can then execute the planted hook, achieving code execution on the victim's machine.

function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}

export function parseAppURL(url: string): URLActionType {
  const parsedURL = URL.parse(url, true)
  const hostname = parsedURL.hostname
  const unknown: IUnknownAction = { name: 'unknown', url }
  if (!hostname) {
    return unknown
  }

  const query = parsedURL.query

  const actionName = hostname.toLowerCase()
  if (actionName === 'oauth') {
    const code = getQueryStringValue(query, 'code')
    const state = getQueryStringValue(query, 'state')
    if (code != null && state != null) {
      return { name: 'oauth', code, state }
    } else {
      return unknown
    }
  }

  // we require something resembling a URL first
  // - bail out if it's not defined
  // - bail out if you only have `/`
  const pathName = parsedURL.pathname
  if (!pathName || pathName.length <= 1) {
    return unknown
  }

  // Trim the trailing / from the URL
  const parsedPath = pathName.substring(1)

  if (actionName === 'openrepo') {
    const pr = getQueryStringValue(query, 'pr')
    const branch = getQueryStringValue(query, 'branch')
    const filepath = getQueryStringValue(query, 'filepath')

    if (pr != null) {
      if (!/^\d+$/.test(pr)) {
        return unknown
      }

      // we also expect the branch for a forked PR to be a given ref format
      if (branch != null && !/^pr\/\d+$/.test(branch)) {
        return unknown
      }
    }

    if (branch != null && testForInvalidChars(branch)) {
      return unknown
    }

    return {
      name: 'open-repository-from-url',
      url: parsedPath,
      branch,
      pr,
      filepath,
    }
  }

  return unknown
}
