### Title
`RegisterPointer` lets any user create an "official" CW pointer for an unverified, potentially malicious EVM contract - (File: x/evm/keeper/msg_server.go)

### Summary
The Popcorn report describes a vault-deployment path where a user-supplied contract address (the "Staking" contract) is accepted and recorded into the protocol's official registry without any check that it was produced by a trusted factory/template. Any address supplied by the caller is trusted implicitly, so an attacker can plant a malicious contract that looks legitimate to end users. The same missing-validation pattern exists in Sei's `MsgRegisterPointer` flow: any unprivileged transaction sender can request a CW20/CW721/ERC1155 pointer for an arbitrary EVM address, and the module blindly instantiates and registers it as the canonical bridge contract without verifying the target implements the expected token interface (or is even a contract at all).

### Finding Description
`MsgRegisterPointer.ValidateBasic` only checks that `ErcAddress` is a syntactically valid hex address [1](#0-0) . It performs no check that the address contains contract code, let alone that it correctly implements ERC20/ERC721/ERC1155 semantics.

`RegisterPointer` in the msg server then unconditionally instantiates (or migrates) a system-owned CW pointer contract that is wired to proxy to this arbitrary `ErcAddress`, and stores the mapping in the canonical pointer registry (`SetCW20ERC20Pointer`, `SetCW721ERC721Pointer`, `SetCW1155ERC1155Pointer`), emitting `EventTypePointerRegistered`: [2](#0-1) 

This is asymmetric with the reverse direction (EVM->CW pointer creation via the `pointer` precompile), where at least a `QuerySmart` call (`token_info`/`contract_info`) is performed against the CosmWasm contract before a pointer is created, providing a minimal sanity check that the target actually behaves like the expected asset type: [3](#0-2) 

No equivalent check exists for `RegisterPointer`/`MsgRegisterPointer` — there is no verification that `msg.ErcAddress` is a deployed contract, nor that it correctly implements the ERC20/721/1155 interface it claims to represent. The only "trust" boundary is version-gating an already-registered pointer (`existingVersion >= currentVersion`), which does nothing to validate the underlying contract's behavior.

### Impact Explanation
Because the resulting pointer is instantiated using the module's own trusted CosmWasm code (via `GetStoredPointerCodeID`) and stored in the same on-chain registry that legitimate pointers use, wallets, dApps, and other CosmWasm contracts that query `GetCW20ERC20Pointer`/`GetCW721ERC721Pointer`/`GetCW1155ERC1155Pointer` (or the corresponding CLI/JSON-RPC surfaces) have no way to distinguish an attacker-registered pointer for a malformed/malicious/non-existent EVM contract from a pointer for a genuine token contract. Any downstream logic (transfers, balance queries, integrations) that proxies through this "official" pointer to the attacker-controlled `ErcAddress` inherits whatever backdoored or spoofed behavior the attacker built into that target contract (e.g., spoofed `balanceOf`/`ownerOf` responses, reverting/succeeding selectively, fake transfer semantics), which can mislead users interacting with what appears to be a system-sanctioned bridge asset into losing funds or being deceived about asset ownership/balances.

### Likelihood Explanation
The bug is trivially reachable: any account that can sign a `MsgRegisterPointer` transaction (no special permission required beyond `RegisterPointerDisabled` not being globally toggled off) can register a pointer for any address they choose, including a freshly-deployed malicious EVM contract that mimics the expected interface just well enough to pass casual inspection.

### Recommendation
Before instantiating/registering a CW pointer for an `ErcAddress`, `RegisterPointer` should verify that the address is a contract and, at minimum, query it (or statically validate bytecode/interface support, e.g. via `supportsInterface`/expected view functions like `balanceOf`, `ownerOf`, `totalSupply`) similarly to how the CW20/CW721 EVM-side pointer creation validates via `QuerySmart` before proceeding, rejecting addresses that do not conform to the claimed `PointerType`.

### Proof of Concept
1. Attacker deploys an EVM contract `Fake` at address `0xFAKE` that exposes just enough surface to avoid outright reverts but contains attacker-controlled logic (e.g., spoofed balances or a hidden admin-only drain path).
2. Attacker submits `MsgRegisterPointer{Sender: attacker, PointerType: PointerType_ERC20, ErcAddress: "0xFAKE"}`.
3. `ValidateBasic` only checks hex format [4](#0-3) , so the message passes.
4. `RegisterPointer` instantiates a system CW20 pointer contract pointing at `0xFAKE` and stores it via `SetCW20ERC20Pointer`, emitting `EventTypePointerRegistered` [5](#0-4) , with no verification `0xFAKE` implements ERC20 correctly.
5. Any tooling/dApp/contract that queries `GetCW20ERC20Pointer` for `0xFAKE` will treat the resulting CW contract as the canonical, protocol-registered representation of that token, unknowingly interacting with attacker-controlled logic.

func (msg *MsgRegisterPointer) ValidateBasic() error {
	_, err := sdk.AccAddressFromBech32(msg.Sender)
	if err != nil {
		return sdkerrors.Wrapf(sdkerrors.ErrInvalidAddress, "Invalid sender address (%s)", err)

	if !common.IsHexAddress(msg.ErcAddress) {
		return sdkerrors.ErrInvalidAddress
	}

	return nil
}

func (server msgServer) RegisterPointer(goCtx context.Context, msg *types.MsgRegisterPointer) (*types.MsgRegisterPointerResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)
	if server.GetRegisterPointerDisabled(ctx) {
		return nil, fmt.Errorf("registering CW->ERC pointers has been disabled")
	}
	var existingPointer sdk.AccAddress
	var existingVersion uint16
	var currentVersion uint16
	var exists bool
	switch msg.PointerType {
	case types.PointerType_ERC20:
		currentVersion = erc20.CurrentVersion
		existingPointer, existingVersion, exists = server.GetCW20ERC20Pointer(ctx, common.HexToAddress(msg.ErcAddress))
	case types.PointerType_ERC721:
		currentVersion = erc721.CurrentVersion
		existingPointer, existingVersion, exists = server.GetCW721ERC721Pointer(ctx, common.HexToAddress(msg.ErcAddress))
	case types.PointerType_ERC1155:
		currentVersion = erc1155.CurrentVersion
		existingPointer, existingVersion, exists = server.GetCW1155ERC1155Pointer(ctx, common.HexToAddress(msg.ErcAddress))
	default:
		panic("unknown pointer type")
	}
	if exists && existingVersion >= currentVersion {
		return nil, fmt.Errorf("pointer %s already registered at version %d", existingPointer.String(), existingVersion)
	}
	payload := map[string]interface{}{}
	switch msg.PointerType {
	case types.PointerType_ERC20:
		payload["erc20_address"] = msg.ErcAddress
	case types.PointerType_ERC721:
		payload["erc721_address"] = msg.ErcAddress
	case types.PointerType_ERC1155:
		payload["erc1155_address"] = msg.ErcAddress
	default:
		panic("unknown pointer type")
	}
	codeID := server.GetStoredPointerCodeID(ctx, msg.PointerType)
	moduleAcct := server.accountKeeper.GetModuleAddress(types.ModuleName)
	var err error
	var pointerAddr sdk.AccAddress
	if exists {
		bz, _ := json.Marshal(map[string]interface{}{})
		pointerAddr = existingPointer
		_, err = server.wasmKeeper.Migrate(ctx, existingPointer, moduleAcct, codeID, bz)
	} else {
		bz, jerr := json.Marshal(payload)
		if jerr != nil {
			return nil, jerr
		}
		pointerAddr, _, err = server.wasmKeeper.Instantiate(ctx, codeID, moduleAcct, moduleAcct, bz, fmt.Sprintf("Pointer of %s", msg.ErcAddress), sdk.NewCoins())
	}
	if err != nil {
		return nil, err
	}
	switch msg.PointerType {
	case types.PointerType_ERC20:
		err = server.SetCW20ERC20Pointer(ctx, common.HexToAddress(msg.ErcAddress), pointerAddr.String())
		ctx.EventManager().EmitEvent(sdk.NewEvent(
			types.EventTypePointerRegistered, sdk.NewAttribute(types.AttributeKeyPointerType, "erc20"),
			sdk.NewAttribute(types.AttributeKeyPointerAddress, pointerAddr.String()), sdk.NewAttribute(types.AttributeKeyPointee, msg.ErcAddress),
			sdk.NewAttribute(types.AttributeKeyPointerVersion, fmt.Sprintf("%d", erc20.CurrentVersion))))
	case types.PointerType_ERC721:
		err = server.SetCW721ERC721Pointer(ctx, common.HexToAddress(msg.ErcAddress), pointerAddr.String())
		ctx.EventManager().EmitEvent(sdk.NewEvent(
			types.EventTypePointerRegistered, sdk.NewAttribute(types.AttributeKeyPointerType, "erc721"),
			sdk.NewAttribute(types.AttributeKeyPointerAddress, pointerAddr.String()), sdk.NewAttribute(types.AttributeKeyPointee, msg.ErcAddress),
			sdk.NewAttribute(types.AttributeKeyPointerVersion, fmt.Sprintf("%d", erc721.CurrentVersion))))
	case types.PointerType_ERC1155:
		err = server.SetCW1155ERC1155Pointer(ctx, common.HexToAddress(msg.ErcAddress), pointerAddr.String())
		ctx.EventManager().EmitEvent(sdk.NewEvent(
			types.EventTypePointerRegistered, sdk.NewAttribute(types.AttributeKeyPointerType, "erc1155"),
			sdk.NewAttribute(types.AttributeKeyPointerAddress, pointerAddr.String()), sdk.NewAttribute(types.AttributeKeyPointee, msg.ErcAddress),
			sdk.NewAttribute(types.AttributeKeyPointerVersion, fmt.Sprintf("%d", erc1155.CurrentVersion))))
	default:
		panic("unknown pointer type")
	}
	return &types.MsgRegisterPointerResponse{PointerAddress: pointerAddr.String()}, err
