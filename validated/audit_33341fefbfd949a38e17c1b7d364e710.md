### Title
Unauthenticated `ReceivedOutput` deserialization permits phantom Bitcoin inputs to inflate spendable funds - ([File: networks/bitcoin/src/wallet/mod.rs])

### Summary
`ReceivedOutput::read` accepts an attacker-supplied scalar offset, `TxOut`, and `OutPoint` without proving that the outpoint exists on-chain or that its actual value/script matches the supplied `TxOut`. [1](#0-0)  `SignableTransaction::new` then treats each deserialized output’s claimed value as spendable input liquidity and uses the supplied outpoint as a transaction input. [2](#0-1) 

### Finding Description
The issue is analogous to counting unsettled funds as available liquidity: a serialized `ReceivedOutput` is only a claim that a UTXO exists and is spendable, yet deserialization authenticates neither that claim nor the claimed amount. [3](#0-2)  The parser reads the scalar with `Secp256k1::read_F`, then consensus-decodes the `TxOut` and `OutPoint`, and returns them directly. [4](#0-3) 

When constructing a spend, the claimed values are summed into `input_sat`, while the claimed outpoints are converted into `TxIn::previous_output`. [2](#0-1)  The balance check only compares that summed claimed value against payments plus fees, so duplicated or fabricated inputs can satisfy the check without corresponding unlocked funds. [5](#0-4) 

The later multisig check validates only that `p2tr_script_buf(offset.group_key())` equals the supplied prevout’s `script_pubkey`; it does not verify that the referenced outpoint exists, remains unspent, or carries the claimed value. [6](#0-5)  Signing then commits to the supplied prevout list through `Prevouts::All`, causing the resulting transaction to incorporate the unauthenticated input claim. [7](#0-6) 

### Impact Explanation
An unprivileged party who can feed bytes to `ReceivedOutput::read` can cause nonexistent, duplicated, or incorrectly valued UTXOs to be represented as spendable balance. [8](#0-7)  This can make the wallet accept a payment plan as funded when the real UTXO set cannot fund it, directly mirroring the phantom-liquidity accounting flaw. [9](#0-8) 

If the claimed script does match the threshold key under the supplied offset, the transaction proceeds to signing even though the outpoint or amount is false. [10](#0-9)  Bitcoin consensus will reject a transaction spending a nonexistent input, spending the same input twice, or committing an incorrect prevout amount through the Taproot sighash, so funds represented as available are not actually spendable and a batch of legitimate payments can be blocked. [11](#0-10) 

### Likelihood Explanation
The reachable input is an untrusted serialized `ReceivedOutput`, which the API explicitly exposes through `ReceivedOutput::read`. [1](#0-0)  Exploitation requires only bytes encoding a canonical scalar, a syntactically valid `TxOut`, and an attacker-chosen `OutPoint`; no validator compromise, key disclosure, collusion, or malformed cryptographic object is required. [4](#0-3) 

For the output to reach signing, the supplied `TxOut::script_pubkey` must equal the P2TR script derived from the threshold key plus the supplied offset. [12](#0-11)  That requirement is publicly computable because `p2tr_script_buf` exposes the script construction and the threshold group key is public. [13](#0-12) 

### Recommendation
Treat `ReceivedOutput` serialization as a cache or transport encoding, not as proof of spendability. Before funding a transaction, re-derive the expected script from the signer’s threshold key and the encoded offset, reject duplicate outpoints, and verify every referenced outpoint’s current existence, value, and script against a trusted chain view or signed scanner record. [2](#0-1)  At minimum, add a validation constructor/read path that binds the output to a confirmed block and rejects arbitrary `outpoint`-`TxOut` pairings before `SignableTransaction::new` accepts them. [4](#0-3) 

### Proof of Concept
```rust
use bitcoin::{OutPoint, TxOut, Amount, ScriptBuf, Txid};
use bitcoin_serai::wallet::{ReceivedOutput, SignableTransaction, p2tr_script_buf};
use frost::curve::Secp256k1;
use ciphersuite::Ciphersuite;
use k256::Scalar;

// Let `group_key` be the public threshold key and `payment_script` any
// attacker-selected payment destination.
let offset = Scalar::ZERO;
let script = p2tr_script_buf(group_key).unwrap();

// Fabricate an input claiming a large balance at an outpoint chosen by the
// attacker. It need not exist or carry this amount on-chain.
let fake_output = TxOut {
  value: Amount::from_sat(1_000_000_000),
  script_pubkey: script,
};
let fake_outpoint = OutPoint { txid: Txid::all_zeros(), vout: 0 };

let mut encoded = Vec::new();
encoded.extend_from_slice(&offset.to_bytes());
bitcoin::consensus::Encodable::consensus_encode(&fake_output, &mut encoded).unwrap();
bitcoin::consensus::Encodable::consensus_encode(&fake_outpoint, &mut encoded).unwrap();

// The parser accepts the unattested claim.
let phantom = ReceivedOutput::read(&mut encoded.as_slice()).unwrap();

// The claimed value is included in `input_sat`, so the transaction can pass
// the local funds check while referring to an unspendable input.
let tx = SignableTransaction::new(
  vec![phantom],
  &[(payment_script, 500_000_000)],
  None,
  None,
  10,
).unwrap();
```

The relevant behavior is that `read` performs no outpoint or amount authentication, while `SignableTransaction::new` sums the supplied values and installs the supplied outpoints before checking apparent sufficiency. [4](#0-3) [14](#0-13)

/// If the key is odd, this will return None.

  if key.to_encoded_point(true).tag() != Tag::CompressedEvenY {
    return None;
  }

  Some(ScriptBuf::new_p2tr_tweaked(TweakedPublicKey::dangerous_assume_tweaked(x_only(&key))))

  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
