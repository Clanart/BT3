Based on the investigation, I found a concrete analog in `updateRemoteUrl`.

### Title
GitHub Desktop silently rewrites the local `origin` remote URL based on GitHub API metadata, with no confirmation and no ownership/identity re-verification - (File: app/src/lib/stores/updates/update-remote-url.ts)

### Summary
The external report's broken invariant is: a lower-trust actor (manager) can silently overwrite an already-established, security-relevant value (`monthlyCPI`) without extra validation, letting stale/trusted state be replaced without user/administrator awareness. The Desktop analog is `updateRemoteUrl()`, which silently overwrites the local `origin` remote's URL using data returned by the GitHub API for the repository the user originally cloned, without any user confirmation and without re-validating repository identity beyond a name/owner+protocol match.

### Finding Description
`updateRemoteUrl` is called from `repositoryWithRefreshedGitHubRepository` in the app store whenever Desktop refreshes GitHub metadata for a repository [1](#0-0) . It fetches the repository from the GitHub API and, if the previously recorded clone URL no longer matches the current remote but the protocol is unchanged and the remote hasn't been "manually" altered from the last known GitHub clone URL, it calls `gitStore.setRemoteURL` to rewrite `origin` to the new `apiRepo.clone_url` with no user prompt: [2](#0-1) 

`setRemoteURL` then directly runs `git remote set-url` for that remote name, replacing whatever value was configured: [3](#0-2) [4](#0-3) 

The repository match feeding this flow is done by owner/name + account endpoint hostname, not by a stable repository ID, and the "unchanged" check is only a URL string comparison against the last cached `gitHubRepository.cloneURL`: [5](#0-4) 

Existing guards (protocol match, "remote URL unchanged from last known clone URL") do not stop this: they were designed to avoid clobbering a *manually customized* remote, but they do not stop the URL from being silently replaced when it still matches the last known GitHub value — which is exactly the case after a rename/transfer of the same owner/name pair server-side, or if the cached `cloneURL` is stale/attacker-influenced through the API response itself. There is no user-visible confirmation dialog analogous to `OverwriteStash` [6](#0-5)  guarding this remote rewrite, unlike the manual remote-URL edit path in Repository Settings, which does go through explicit user action [7](#0-6) .

### Impact Explanation
If the account controlling the origin repository the victim already cloned changes what `clone_url` the GitHub API reports for that owner/name (e.g., a repo transfer/rename to a different backing remote while keeping the API-visible identity Desktop tracks), Desktop will silently rewrite the user's local `origin` remote to point at the new URL on the next background metadata refresh, with no notification. Subsequent `git push`/`git fetch` operations then interact with a different remote endpoint than the one the user originally trusted and configured, without the user's knowledge — this is a silent corruption of what the user pushes/fetches to. The credential trampoline helper does add some mitigation for GitHub-hosted token leakage since it keys credential lookups on `isDotCom`/`isGHE` hostname checks [8](#0-7) , so outright OAuth token exfiltration to an arbitrary attacker host is not automatic, but the redirection of push/fetch traffic itself happens without consent.

### Likelihood Explanation
This path fires automatically as part of routine background refresh (`repositoryWithRefreshedGitHubRepository`), requiring no unusual user action beyond normal app usage of a repository whose GitHub-side identity/clone URL changes. It does require the entity in control of the tracked GitHub repository (owner/name) to change the reported clone URL, which is a realistic scenario for a compromised or malicious repo owner the victim has already added as a remote, but does not require local/physical access, admin rights, or leaked credentials.

### Recommendation
Do not silently rewrite an established remote URL from background API refresh. At minimum: require the update to be tied to a stable repository ID (not owner/name string matching) and require explicit user confirmation before mutating any git remote configuration outside of the Repository Settings UI, mirroring the existing `ConfirmOverwriteStash` pattern for other overwrite-style operations.

### Proof of Concept
1. Victim clones `https://github.com/attacker/foo` (added as `origin`).
2. Attacker later causes the GitHub API to report a different `clone_url` for the same owner/name identity Desktop tracked (e.g., via transfer/rename while Desktop still resolves owner/name the same way).
3. On the next periodic refresh, `repositoryWithRefreshedGitHubRepository` → `updateRemoteUrl` sees `protocolsMatch && remoteUrlUnchanged && !urlsMatch` and calls `gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)` [9](#0-8)  without any dialog or user consent.
4. The victim's next push/fetch now silently targets the new URL.

I was unable to fully verify, within the available iterations, the exact server-side conditions under which the GitHub API would return a different `clone_url` for a previously-matched owner/name pair (e.g., precise rename/transfer semantics), so the practical attacker-controllability of step 2 is asserted based on code behavior rather than confirmed end-to-end against live GitHub API semantics.

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

/** Try to use the list of users and a remote URL to guess a GitHub repository. */
export function matchGitHubRepository(
  accounts: ReadonlyArray<Account>,
  remote: string
): IMatchedGitHubRepository | null {
  for (const account of accounts) {
    const htmlURL = getHTMLURL(account.endpoint)
    const { hostname } = URL.parse(htmlURL)
    const parsedRemote = parseRemote(remote)

    if (parsedRemote !== null && hostname !== null) {
      if (parsedRemote.hostname.toLowerCase() === hostname.toLowerCase()) {
        return { name: parsedRemote.name, owner: parsedRemote.owner, account }
      }
    }
  }

  return null
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
