### Title
Deterministic CachedPreprocess re-derivation reuses FROST nonces across parallel signing sessions, enabling secret-share recovery - (File: coordinator/src/tributary/signing_protocol.rs)

### Summary
The Chrome CVE is a use-after-free in task scheduling: a resource consumed by one scheduled task is used again by another. The Serai analog is a one-time-use FROST nonce seed (`CachedPreprocess`) that is deterministically re-expanded on every signing attempt under the same context. `preprocess_internal` stores a single 32-byte seed per `context` and calls `AlgorithmSignMachine::from_cache` on every invocation, so `seeded_preprocess` regenerates identical `nonces` and identical published `commitments` each time. If two distinct `share_internal`/`sign` executions occur under that context — with different messages or different signing sets derived from attacker-supplied preprocess maps — the signer emits two signature shares over the same nonce. Two such shares linearly reveal the FROST nonce and then the secret share, exactly the "reused preprocess recovers your private key share" failure the FROST spec and `sign.rs` doc comments warn against, made reachable by scheduling rather than by integrator misuse.

### Finding Description
`AlgorithmMachine::seeded_preprocess` in `crypto/frost/src/sign.rs` derives all nonces deterministically from the cached seed via `ChaCha20Rng::from_seed(*seed.0)`, then `Commitments::new` and `preprocess_addendum`. `from_cache` rebuilds the machine from the same seed with no consumption marker. `SignMachine::from_cache` documents the invariant but provides no enforcement: [2](#0-1) 

The coordinator's `preprocess_internal` caches the seed keyed only by `self.context`, and `share_internal` calls `preprocess_internal` again for every signing request. The seed is never deleted or rotated after a `sign` consumes it, so each call under the same context re-generates the same `nonces` and rebroadcasts the same `commitments`. [3](#0-2) [4](#0-3) 

The signing set and the preprocesses fed into `machine.sign` are built from `serialized_preprocesses`, a map populated from participant messages — i.e., party-controlled input that determines `included`, the binding factors `rho`, and the challenge `c`, while the victim's nonce `k` stays constant. A FROST share has the form `s_i = k_i + λ_i·x_i·c·…`; with two shares using identical `k_i` but different `(signing set, msg)` the attacker solves for `k_i`, then for the secret share `x_i`.

### Impact Explanation
Recovery of a validator's FROST secret share `x_i` lets the attacker combine it with `t-1` cooperating (or subsequently compromised) shares to reconstruct the threshold key, or at minimum to compute valid share-forgeries for that participant. More directly, once `k_i` is known the attacker can compute the victim's share for any further message under that nonce, contributing to forged threshold signatures on arbitrary transactions (Bitcoin spends) — unauthorized signing of unintended messages and key-share recovery, both in the accepted-impact list.

### Likelihood Explanation
No collusion among threshold participants is required: the attacker only needs to cause two signing rounds under the same `context` with differing preprocess sets or messages and observe the two broadcast shares (shares are public protocol messages). Any party able to submit preprocesses for a different participant subset, or to trigger a retry/re-sign with a modified signing set, produces the second share. The determinism of `ChaCha20Rng::from_seed` makes the nonce collision guaranteed, not probabilistic.

### Recommendation
Bind the cached preprocess to a single sign attempt: record a consumed flag (or delete `CachedPreprocesses` entry) when `share_internal` runs, and include the full signing-session transcript (sorted `included` set and `msg` hash) in the cache key so a second attempt with different parameters either derives a fresh seed or is rejected. Alternatively, derive nonces as `H(seed || session_binding)` so cross-session nonce equality is impossible.

### Proof of Concept
1. Attacker participates in session A under context `C` with participant set `S1` and message `m1`; obtains victim share `s1 = k + f(x_i, c1, S1)`.
2. Attacker triggers session B under the same `C` (re-emitted sign request) with set `S2 ≠ S1` or message `m2`; `preprocess_internal` reloads the same seed → same `k`, same commitments.
3. From `s1`, `s2` and the public binding factors/challenges, solve `k = (s1 − s2 + λ·x·(c2 − c1)…) —` in practice first recover `k` via the differing `rho`/challenge terms, then `x_i = (s1 − k)/(λ_i·c1·…)` mod `l`. Secret share recovered; subsequent shares forgeable.

  fn seeded_preprocess(
    self,
    seed: CachedPreprocess,
  ) -> (AlgorithmSignMachine<C, A>, Preprocess<C, A::Addendum>) {
    let mut params = self.params;

    let mut rng = ChaCha20Rng::from_seed(*seed.0);
    let (nonces, commitments) = Commitments::new::<_>(
      &mut rng,
      params.keys.original_secret_share(),
      &params.algorithm.nonces(),
    );
    let addendum = params.algorithm.preprocess_addendum(&mut rng, &params.keys);

    let preprocess = Preprocess { commitments, addendum };

    // Also obtain entropy to randomly sort the included participants if we need to identify blame
    let mut blame_entropy = [0; 32];
    rng.fill_bytes(&mut blame_entropy);
    (
      AlgorithmSignMachine { params, seed, nonces, preprocess: preprocess.clone(), blame_entropy },
      preprocess,
    )
  }

  fn share_internal(
    &mut self,
    participants: &[<Ristretto as Ciphersuite>::G],
    mut serialized_preprocesses: HashMap<Participant, Vec<u8>>,
    msg: &[u8],
  ) -> Result<(AlgorithmSignatureMachine<Ristretto, Schnorrkel>, [u8; 32]), Participant> {
    let machine = self.preprocess_internal(participants).0;

    let mut participants = serialized_preprocesses.keys().copied().collect::<Vec<_>>();
    participants.sort();
    let mut preprocesses = HashMap::new();
    for participant in participants {
      preprocesses.insert(
        participant,
        machine
          .read_preprocess(&mut serialized_preprocesses.remove(&participant).unwrap().as_slice())
          .map_err(|_| participant)?,
      );
    }

    let (machine, share) = machine.sign(preprocesses, msg).map_err(|e| match e {
      FrostError::InternalError(e) => unreachable!("FrostError::InternalError {e}"),
      FrostError::InvalidParticipant(_, _) |
      FrostError::InvalidSigningSet(_) |
      FrostError::InvalidParticipantQuantity(_, _) |
      FrostError::DuplicatedParticipant(_) |
      FrostError::MissingParticipant(_) => unreachable!("{e:?}"),
      FrostError::InvalidPreprocess(p) | FrostError::InvalidShare(p) => p,
    })?;

    Ok((machine, share.serialize().try_into().unwrap()))
