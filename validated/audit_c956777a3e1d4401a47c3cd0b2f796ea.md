### Title
Spoofable GitHub-Enterprise host detection in the git credential-helper trampoline leads to unauthorized OAuth binding and token exfiltration to attacker-controlled remotes - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
Reducing the seed report to its core primitive: a piece of state (the "is this rebase-eligible / is this a trusted GitHub endpoint") is derived from **attacker-influenced input** and used to gate a value-releasing action (unstaking / releasing a real credential), without a strong, unspoofable check tying that classification to the actual trusted counterpart. In Desktop, the analogous broken invariant lives in the git credential-helper trampoline's `getEndpointKind` function [1](#0-0) , which decides whether an unknown HTTPS remote should be treated as a "GitHub Enterprise" endpoint using signals that are fully controlled by the remote server itself: an HTTP `WWW-Authenticate` header value and a heuristic `/meta` HEAD probe checking for an `x-github-request-id` response header [2](#0-1) . Neither signal is cryptographically bound to GitHub — any HTTPS server the attacker controls can emit them.

### Finding Description
When Git needs credentials for an HTTPS remote, it invokes Desktop's credential-helper trampoline, which calls `getCredential` → `getEndpointKind` [3](#0-2) . If the remote is not `github.com`/`ghe.com` and no already-bound account matches its literal origin, classification falls back to:

1. Checking for a `wwwauth[...]` credential field containing `realm="GitHub"` sent by the remote in its 401 response [4](#0-3) , or
2. `isGitHubHost(endpoint)`, which performs a `HEAD` request to `${endpoint}/meta` and trusts the presence of an `x-github-request-id` response header as proof of a genuine GitHub Enterprise Server [5](#0-4) .

Both signals are attacker-settable: an attacker's own HTTPS git server can simply respond `WWW-Authenticate: Basic realm="GitHub"` on the initial 401, or add an `x-github-request-id` header to the `/meta` probe response, causing `getEndpointKind` to return `'enterprise'`.

Once classified as `'enterprise'` with no existing bound account, `getCredential` triggers `ui.promptForGitHubSignIn(endpoint)` [6](#0-5) , which begins a GitHub sign-in/OAuth-style flow scoped to that attacker-controlled `endpoint`. Whatever `Account` results is merged back into the credential via `credWithAccount`, which sets the real `login`/`token` as the `username`/`password` fields [7](#0-6) . This credential map is returned to Git, which uses it as HTTP Basic Auth against the **actual remote host** — i.e., the attacker's server — during the fetch/clone/push HTTPS request that originally triggered the prompt.

This is the exact analog of the seed bug's broken invariant: a "settlement"/trust decision (rebase / is-this-really-GitHub) is derived from data the attacker supplies, and the "burn" step that should prevent value leakage (verifying the remote's identity out-of-band, or never returning a live token to an unverified host) is missing. Just as `instantUnstakeReserve` failed to burn `YIELD_TOKEN` before releasing value, the credential helper fails to cryptographically bind the OAuth/token release to a genuine GitHub identity before releasing it to an untrusted network peer.

### Impact Explanation
A successful exploitation results in the user's real GitHub credential/OAuth token being sent directly to an attacker-controlled server over HTTPS, and/or an unauthorized account being bound to Desktop against a spoofed "Enterprise" endpoint. This maps to two of the explicitly valid impact classes: **credential/token exfiltration** and **unauthorized OAuth or account binding**. The attacker's entry point — a git remote/repository the user clones, fetches, or that appears as a submodule URL — is exactly the attacker-controlled surface named in the task's Valid Impact scope ("a cloned/fetched repository ... or a git remote/proxy response").

### Likelihood Explanation
The attack requires only that the victim performs a normal git network operation (clone/fetch/push/submodule update) against a remote the attacker controls or has compromised — no local access, no malware, no leaked credentials, and no unnatural user steps beyond the sign-in prompt that Desktop itself displays. `isGitHubHost`'s own doc comment acknowledges it is a "best-effort" heuristic [8](#0-7) , indicating the developers were aware detection is imperfect, but the consequence of a false positive (releasing a live token to the misidentified host) is not otherwise mitigated in `getCredential`.

### Recommendation
- Never release a stored/OAuth-derived token to a host whose GitHub identity was determined only by response headers it can freely set (`WWW-Authenticate` realm, `x-github-request-id`).
- Require an authenticated, pinned discovery mechanism (e.g., matching against a user-configured GHE endpoint list, or requiring TLS-certificate/known endpoint confirmation) before treating an unknown host as "enterprise" in `getEndpointKind` [1](#0-0) .
- When falling back to the heuristic `isGitHubHost` check, surface a clear, unavoidable warning to the user showing the literal hostname before initiating any sign-in/OAuth flow, and never auto-fill the resulting token as Basic Auth credentials for that same unverified host without explicit reconfirmation.

### Proof of Concept
1. Attacker stands up an HTTPS server at `https://evil.example` that:
   - Responds `401` with header `WWW-Authenticate: Basic realm="GitHub"` for any git-over-HTTP request, or alternatively answers `HEAD /meta` with header `x-github-request-id: <anything>`.
   - Responds to a `git-upload-pack`/`git-receive-pack` request as any git-savvy server would (e.g., a lightweight custom smart-HTTP server).
2. Attacker gets the victim to clone/add this as a remote, e.g. via a repository whose `.gitmodules` submodule URL or `.git/config` remote points to `https://evil.example/foo.git`.
3. Victim performs `git fetch`/`git push` (through Desktop) against this remote. Git receives the 401 and forwards `wwwauth[]` to Desktop's credential helper.
4. `getEndpointKind` in `app/src/lib/trampoline/trampoline-credential-helper.ts:153-165` matches `realm="GitHub"` and returns `'enterprise'`; no existing account matches `evil.example`, so `getCredential` calls `ui.promptForGitHubSignIn('https://evil.example')`.
5. Victim completes the presented sign-in flow (or, if a valid account happens to already be bound to that exact endpoint due to previous exploitation, no prompt is even needed).
6. `credWithAccount` places the real account `login`/`token` into the credential returned to Git, and Git sends this Basic Auth pair to `https://evil.example` to complete the fetch/push, exfiltrating the token to the attacker.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}
