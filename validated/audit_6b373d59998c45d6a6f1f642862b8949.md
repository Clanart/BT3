### Title
GitHub-host classification can be spoofed via a crafted `WWW-Authenticate: realm="GitHub"` header, causing Desktop to treat an attacker-controlled remote as GitHub Enterprise - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
`getEndpointKind` decides whether a git remote is `github.com`, `ghe.com`, `enterprise`, or `generic`. This classification governs whether Desktop uses its internal account store/OAuth sign-in flow (treating the remote as first-party GitHub) or falls back to generic/external credential handling. The function contains a "happy-path" shortcut that trusts the git-forwarded `wwwauth[N]` credential fields (which originate directly from the remote server's HTTP `WWW-Authenticate` response header) without any cryptographic or DNS-based verification. [1](#0-0) 

### Finding Description
When git performs HTTP authentication against a remote, any `WWW-Authenticate` header returned by the server is captured by git and forwarded to the `git credential` helper as `wwwauth[0]`, `wwwauth[1]`, etc. `createCredentialHelperTrampolineHandler` parses this stdin into the `cred` map and passes it straight into `getEndpointKind`: [2](#0-1) 

Inside `getEndpointKind`, after the legitimate hostname checks (`isGist`, `isDotCom`, `isGHE`), the code iterates the raw `wwwauth[*]` values and, if any value matches `realm="GitHub"`, immediately returns `'enterprise'` — completely bypassing the real verification step that follows (`isGitHubHost(endpoint)`, an actual network probe): [3](#0-2) 

Because this header is attacker-controlled (any HTTP server responding to the git remote's HTTPS request can send an arbitrary `WWW-Authenticate` value), an attacker running a git remote at any hostname (e.g. `https://evil.example.com/repo.git`) can force `getEndpointKind` to return `'enterprise'` for that host simply by returning `WWW-Authenticate: Basic realm="GitHub"` on the 401 challenge — with no relation whatsoever to a real GitHub Enterprise Server.

This wrong classification feeds directly into `getCredential`: [4](#0-3) 

Since `endpointKind !== 'generic'` and no stored account matches the attacker's endpoint, Desktop calls `ui.promptForGitHubSignIn(endpoint)` with `endpoint` pointing at the attacker's host. This surfaces Desktop's native "Sign in to GitHub Enterprise" UI/OAuth flow scoped to the attacker-controlled origin, and any resulting `Account` (token) is stored keyed to that attacker endpoint via `credWithAccount`. It also suppresses the generic/external credential-helper path (`storeCredential`/`eraseCredential` short-circuit whenever `endpointKind !== 'generic'`), so credentials that should have gone through GCM or the generic auth store are silently dropped for hosts merely claiming to be "GitHub" via this header.

### Impact Explanation
This is an unauthorized "GitHub/GitHub Enterprise" classification and account-binding primitive driven entirely by attacker-controlled network response data:
- It causes Desktop to present its trusted first-party GitHub/GHE sign-in UI for an arbitrary, attacker-owned host, which the user has no independent way to distinguish from a legitimate enterprise sign-in prompt — a credential-phishing vector for OAuth tokens/PATs the user enters.
- Any account/token obtained through that flow is persisted in the accounts store as though it were a genuine GitHub account bound to that (attacker) endpoint, corrupting the intended endpoint↔account trust boundary that `isGitHubHost`'s real verification was meant to enforce.
- It also silently defeats the generic/external credential helper path for such hosts, since `storeCredential`/`eraseCredential` bail out whenever the spoofed classification isn't `'generic'`.

### Likelihood Explanation
Exploitation only requires the victim to add/clone from an attacker-controlled git remote and have Desktop attempt an HTTPS git operation against it (fetch/push/clone) — no local access, no malware, and no unnatural user steps beyond normal repository use. The attacker fully controls the response headers of their own server, so crafting `WWW-Authenticate: Basic realm="GitHub"` is trivial and 100% reliable.

### Recommendation
Do not treat the `wwwauth[*]` realm header as sufficient proof of a GitHub/GitHub Enterprise host. At minimum, use it only as a hint to prioritize calling `isGitHubHost(endpoint)` (the authoritative API-based check already present at line 178), rather than returning `'enterprise'`/`'generic'` directly from unauthenticated header content.

### Proof of Concept
1. Host a git-over-HTTPS repository at `https://evil.example.com/repo.git` whose server responds to unauthenticated requests with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
2. In GitHub Desktop, clone or add this remote and perform a fetch.
3. Git forwards the header via `wwwauth[0]=...realm="GitHub"...` to the credential trampoline; `getEndpointKind` (`app/src/lib/trampoline/trampoline-credential-helper.ts:157-165`) returns `'enterprise'` for `evil.example.com` without ever calling `isGitHubHost`.
4. `getCredential` finds no matching account for `evil.example.com` and invokes `ui.promptForGitHubSignIn('https://evil.example.com')`, presenting a native "Sign in to GitHub Enterprise" flow scoped to the attacker's host.

Note: I was not able to fully inspect `trampoline-ui-helper.ts`'s `promptForGitHubSignIn` implementation (dialog copy, OAuth vs PAT flow specifics) within the available tool budget, so the exact end-user-facing wording of the spoofed sign-in prompt is unverified — a Devin session with full file access would be needed to confirm those details.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
