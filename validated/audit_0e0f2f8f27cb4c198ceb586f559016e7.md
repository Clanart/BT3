## Title
Malicious Git Remote Can Force GitHub Enterprise Trust Classification via Loosely-Parsed `wwwauth[]` Credential Field, Bypassing Generic-Host Credential Isolation - ([File: app/src/lib/git/credential.ts])

### Summary
`parseCredential` in `app/src/lib/git/credential.ts` implements the git credential-helper wire protocol (`key=value` lines, `\0`/newline delimited) using the exact broken invariant described in the Tomcat trailer-parsing bug: any line that doesn't contain a delimiter (`=`) is silently skipped with `continue` rather than treated as a parse error or protocol violation. The same forgiving-parser pattern that let Tomcat merge/desync two logically distinct HTTP messages here lets attacker-influenced protocol lines (built from raw `WWW-Authenticate` response headers returned by any git remote server) survive unchecked into `getEndpointKind`'s trust decision instead of being rejected outright.

### Finding Description
`parseCredential` is used by `createCredentialHelperTrampolineHandler` (`app/src/lib/trampoline/trampoline-credential-helper.ts:229`) to parse `command.stdin`, the payload Git sends to `GIT_CONFIG_PARAMETERS 'credential.helper=desktop'` whenever it needs credentials for any remote — including plain HTTP(S) remotes with no association to GitHub at all. [1](#0-0) 

Git populates `wwwauth[]=` entries in this protocol directly from the `WWW-Authenticate` header(s) returned by the remote server on a 401 challenge. `getEndpointKind` in `trampoline-credential-helper.ts` inspects these attacker-controlled values with a naive substring/regex check to decide whether the remote should be treated as an "enterprise" (GitHub-trusted) host or a "generic" host: [2](#0-1) 

Because `parseCredential` never validates line structure and simply skips any malformed segment, any attacker-controlled server can return a header such as `WWW-Authenticate: Basic realm="GitHub"` and have its value pass straight through into the `wwwauth[0]` field, causing `getEndpointKind` to return `'enterprise'` for a completely unrelated, attacker-owned host. This reclassification changes `getCredential`'s behavior in `getCredential` (`trampoline-credential-helper.ts:94-135`): instead of going through the "generic" credential path (which respects `generic-git-auth` scoping and never invokes GitHub sign-in), the attacker's own domain is now routed into the GitHub/Enterprise sign-in branch, which calls `ui.promptForGitHubSignIn(endpoint)` with `endpoint` equal to the attacker's own URL — presenting the user a "Sign in" dialog that Desktop believes is a legitimate GitHub Enterprise instance, when it is in fact a server fully controlled by the attacker. [3](#0-2) 

This mirrors the underlying Tomcat flaw precisely: a protocol designed to be strictly delimited (colon-separated header / `=`-separated credential field) is parsed with silent skip-on-error recovery, letting attacker-supplied bytes be reinterpreted as trusted structured data that crosses a security boundary (trailer vs. next request in Tomcat; generic vs. GitHub-trusted host classification in Desktop).

### Impact Explanation
An attacker who controls (or MITMs, e.g. via a corporate/malicious proxy) any git HTTP(S) remote that the victim clones/fetches/pushes to can force Desktop to treat that arbitrary host as a "GitHub Enterprise" endpoint. Once classified as `enterprise`/non-generic, Desktop invokes its full GitHub Enterprise sign-in UI against the attacker's endpoint. Because this is presented through Desktop's normal, trusted sign-in chrome, a user could be led to enter GitHub Enterprise credentials, complete an OAuth device/browser flow, or otherwise supply account material believing they are authenticating against a legitimate GHE deployment. It also bypasses the "generic" credential storage isolation (`setGenericCredential`/`getGenericCredential`) that would normally apply to arbitrary non-GitHub git hosts, since `storeCredential`/`eraseCredential`/`getCredential` all gate on `getEndpointKind() !== 'generic'`. [4](#0-3) 

### Likelihood Explanation
Every clone/fetch/push against an attacker-controlled or MITM'd remote naturally triggers a credential-helper `get` round-trip whenever the server issues a `401` with a `WWW-Authenticate` header — this requires no unusual user action beyond adding/using a remote pointed at the attacker's server, which is squarely within the "attacker controls a git remote" threat model. No local access, admin rights, or pre-existing malware is required.

### Recommendation
- In `parseCredential`, treat lines without a `=` delimiter as a hard parse error (mirroring the fix direction taken for the Tomcat trailer bug) instead of silently skipping them, so malformed/attacker-crafted lines cannot be silently absorbed into the credential map.
- In `getEndpointKind`, do not trust `wwwauth[]` header content alone to elevate a host to `'enterprise'` trust; require a corroborating signal that cannot be trivially spoofed by the remote itself (e.g., only use `wwwauth[]` as a hint to *skip a network probe*, but still confirm via `isGitHubHost`/certificate identity before granting enterprise-tier UI/credential treatment, or restrict the check to hosts already recognized via `isDotCom`/`isGHE`/hostname heuristics).

### Proof of Concept
1. Stand up an HTTPS git server (e.g. via a malicious `smart HTTP` git-http-backend) whose only customization is to respond to unauthenticated requests with:
   ```
   HTTP/1.1 401 Unauthorized
   WWW-Authenticate: Basic realm="GitHub"
   ```
2. In GitHub Desktop, clone `https://attacker.example.com/some.git`.
3. Git invokes the desktop credential helper; `command.stdin` contains a line such as `wwwauth[]=Basic realm="GitHub"` among the standard `protocol=`, `host=`, etc. lines.
4. `parseCredential` parses this into `cred.get('wwwauth[0]')` unchanged (no validation).
5. `getEndpointKind` matches `realm="GitHub"` and returns `'enterprise'` for `attacker.example.com`.
6. `getCredential` finds no existing account for that endpoint and calls `ui.promptForGitHubSignIn('https://attacker.example.com/...')`, presenting the user a GitHub-branded sign-in flow scoped to the attacker's own domain.

Note: I was not able to trace the exact `ui.promptForGitHubSignIn` implementation or the enterprise sign-in dialog code in this pass (index limits/time did not allow deeper verification of that specific UI flow), so the precise wording/branding of the resulting dialog and whether any further OAuth token binding could occur should be verified with a full Devin session before treating this as fully confirmed end-to-end.

export const parseCredential = (value: string) => {
  const cred = new Map<string, string>()

  // The credential helper protocol is a simple key=value format but some of its
  // keys are actually arrays which are represented as multiple key[] entries.
  // Since we're currently storing credentials as a Map we need to handle this
  // and expand multiple key[] entries into a key[0], key[1]... key[n] sequence.
  // We then remove the number from the key when we're formatting the credential
  for (const line of value.split(/\r?\n/)) {
    const eqIx = line.indexOf('=')
    if (eqIx === -1) {
      continue
    }

    const k = line.slice(0, eqIx)
    const v = line.slice(eqIx + 1)

    if (k.endsWith('[]')) {
      let i = 0
      let newKey

      do {
        newKey = `${k.slice(0, -2)}[${i}]`
        i++
      } while (cred.has(newKey))

      cred.set(newKey, v)
    } else {
      cred.set(k, v)
    }
  }

  return cred
}

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

/** Implementation of the 'store' git credential helper command */
async function storeCredential(cred: Credential, store: Store, token: string) {
  if ((await getEndpointKind(cred, store)) !== 'generic') {
    return
  }

  return useExternalCredentialHelper()
    ? storeExternalCredential(cred, token)
    : setGenericCredential(
        urlWithoutCredentials(getCredentialUrl(cred)),
        forceUnwrap(`credential missing username`, cred.get('username')),
        forceUnwrap(`credential missing password`, cred.get('password'))
      )
}

const storeExternalCredential = (cred: Credential, token: string) => {
  const path = getTrampolineEnvironmentPath(token)
  return approveCredential(cred, path, getGcmEnv(token))
}

/** Implementation of the 'erase' git credential helper command */
async function eraseCredential(cred: Credential, store: Store, token: string) {
  if ((await getEndpointKind(cred, store)) !== 'generic') {
    return
  }

  return useExternalCredentialHelper()
    ? eraseExternalCredential(cred, token)
    : deleteGenericCredential(
        urlWithoutCredentials(getCredentialUrl(cred)),
        forceUnwrap(`credential missing username`, cred.get('username'))
      )
}
