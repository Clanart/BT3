### Title
DataLayer mirror URLs are never validated, allowing SSRF to loopback/RFC1918/link-local addresses on any subscribing Data Layer client - (File: chia/data_layer/data_layer.py)

### Summary
Any wallet holding a DataLayer store launcher can publish "mirror" coins whose `urls` field is fully attacker-controlled and completely unvalidated. Every other Data Layer client that subscribes to that store (a normal, expected DataLayer feature for replicating/mirroring data) will periodically issue outbound HTTP requests to those URLs from its own background sync loop, with no restriction on scheme/host, exactly the "loopback, localhost, RFC1918, link-local, ULA" bypass class described in the Roundcube report.

### Finding Description
`DataLayer.add_mirror()` only checks that the URL list is non-empty before broadcasting the urls on-chain via `dl_new_mirror`: [1](#0-0) 

The mirror urls are stored verbatim in a coin memo and later decoded by any node/wallet that reads the mirror coin (`get_mirror_info`) and persisted client-side: [2](#0-1) 

When a Data Layer node subscribes to that store, `update_subscriptions_from_wallet()` pulls these attacker-supplied URLs directly into the local subscription server list with no filtering (only trailing-slash stripping): [3](#0-2) 

`fetch_and_validate()` then randomly selects one of these servers and performs an HTTP fetch against it via `insert_from_delta_file()` → `download_file()` → `http_download()`: [4](#0-3) [5](#0-4) 

`http_download()` uses `aiohttp` with `session.get(server_info.url + "/" + filename, ...)` and no host/IP restriction, meaning `server_info.url` can be `http://127.0.0.1:<port>`, `http://169.254.169.254`, `http://10.x.x.x`, `http://[::1]`, etc. A search of `chia/data_layer/**` for any scheme/host allow-list, `ipaddress` checks, or `urlparse`-based filtering returns nothing in `data_layer.py`, `data_layer_wallet.py`, `dl_wallet_store.py`, or `download_data.py` — the only occurrences of such patterns in the module are unrelated (`s3_plugin_service.py`, `start_data_layer.py`, `data_layer_server.py` for its own bind address). This mirrors the Roundcube bug class: a value that should be treated as an untrusted remote pointer (mirror URL / HTML remote-content URL) is fetched without any private/loopback address exclusion.

The `.cursor/context/data-layer.md` notes explicitly acknowledge mirror/plugin URLs are "external trust inputs" for *downloaded content* verification, but the codebase never actually restricts *where* the outbound request itself is allowed to go: [6](#0-5) 

### Impact Explanation
Any user who creates or controls a DataLayer store (a normal, permissionless DataLayer wallet action reachable by any wallet with funds) can seed mirror URLs pointing at loopback/private/link-local addresses. Every third-party operator whose DataLayer node subscribes to that store (a standard, expected DataLayer replication flow) will have their node issue HTTP GET requests to those internal addresses on a periodic background cycle (`periodically_manage_data()`), with the requested filename attacker-influenced (`get_delta_filename`). This can be used to probe/attack internal-only services reachable from the victim's DataLayer host (local RPC endpoints, cloud metadata endpoints, other LAN services), and can also be leveraged as a DoS/resource vector by pointing many stores at the same internal target. Because DataLayer nodes run on hosts that often also run wallet/full-node RPC on localhost, this constitutes a genuine SSRF against a component reachable from a remote, unprivileged actor's on-chain action.

### Likelihood Explanation
High reachability, moderate exploitation complexity: creating a store and adding mirrors requires only a small XCH balance and no special permission (`add_mirror`/`dl_new_mirror` are ordinary wallet-signed spends), and victims must simply subscribe to (or already track/replicate) the malicious store, which is the intended way DataLayer content is shared/discovered. No validation exists anywhere in the fetch path to block private-network destinations.

### Recommendation
Validate and restrict mirror/subscription URLs before they are persisted as subscription servers or used for outbound fetches: reject `localhost`, loopback, RFC1918, link-local (including `169.254.169.254`), and ULA/IPv6 unique-local addresses (or provide an explicit opt-in allow-list/config flag for trusted internal mirrors), performed in `DataLayer.update_subscriptions_from_wallet()` / `DataStore.update_subscriptions_from_wallet()` before storing server URLs, and defensively again in `http_download()`/`download_file()` right before the request is issued (resolving DNS and re-checking the resulting IP to prevent DNS-rebinding).

### Proof of Concept
1. Attacker creates a DataLayer store and calls `dl_new_mirror` (or the RPC `add_mirror`) with `urls=["http://127.0.0.1:8555"]` (or an internal RFC1918 address of a target network), as shown in the test harness pattern: [7](#0-6) 
2. Victim's DataLayer service subscribes to the attacker's store id (normal replication use case).
3. Victim's background loop calls `update_subscription()` → `update_subscriptions_from_wallet()` (pulls `http://127.0.0.1:8555` into local subscription state) → `fetch_and_validate()` → `insert_from_delta_file()` → `download_file()` → `http_download()`, causing the victim's node to issue `GET http://127.0.0.1:8555/<delta-filename>`, hitting whatever local/internal service listens on that address/port.

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
