### Title
Blind SSRF via attacker-controlled DataLayer mirror URLs consumed without host/scheme validation - ([File: chia/data_layer/data_layer_wallet.py], [File: chia/data_layer/download_data.py])

### Summary
Any unprivileged spend-bundle submitter can create a coin that is recognized as a DataLayer "mirror" coin for *any* existing DataLayer singleton (store id/launcher id), embedding arbitrary attacker-chosen URLs in the coin's memos. `DataLayerWallet.coin_added()` accepts these URLs with no scheme/host validation and persists them as `Mirror` records for any wallet that is tracking that launcher id. `DataLayer.fetch_and_validate()` / `download_data.http_download()` later issue outbound HTTP requests to exactly these attacker-controlled URLs, with no localhost/private-network filtering — mirroring the webfinger.js class of bug (attacker fully controls host/port/path of a server-initiated request).

### Finding Description
`create_mirror_puzzle()` defines a fixed, publicly known puzzle (`P2_PARENT.curry(Program.to(1))`), and `MIRROR_PUZZLE_HASH` is its tree hash [1](#0-0) . `get_mirror_info()` extracts the target `launcher_id` and a list of raw memo bytes (treated as URLs) from a `CREATE_COIN` condition whose puzzle hash equals `MIRROR_PUZZLE_HASH`, with no validation of the memo contents beyond basic parsing [2](#0-1) .

Because `P2_PARENT` only requires a valid spend that creates a coin with this well-known puzzle hash and arbitrary memos, *any* coin owner can spend their own coin to create a "mirror coin" referencing *any* `launcher_id` they choose — they do not need to own or control that DataLayer store. `DataLayerWallet.coin_added()` is invoked by every wallet syncing chain state; when it observes such a coin, it checks only `is_launcher_tracked(launcher_id)` (i.e., whether the local wallet happens to track that store) and then persists the attacker-provided URLs verbatim as a `Mirror` record, without validating URL scheme, host, or target network range: [3](#0-2) .

These persisted mirror URLs flow into `DataStore`'s subscription/server tables via `DataLayer.update_subscriptions_from_wallet()` and `get_mirrors()` [4](#0-3) , and become `ServerInfo.url` entries returned by `get_available_servers_for_store()` [5](#0-4) .

`DataLayer.fetch_and_validate()` then iterates these server URLs and calls `insert_from_delta_file()` / `download_file()` with `url = server_info.url` taken directly from the attacker-supplied mirror memo [6](#0-5) . When no downloader plugin is configured, `download_file()` calls `http_download()` directly against that URL [7](#0-6) ; no code path in this flow checks for `localhost`, loopback, link-local, or RFC1918 addresses before issuing the HTTP GET, unlike the `is_localhost()`/`is_in_network()` SSRF-style guards used elsewhere in the codebase for peer connections (`chia/server/server.py`).

The `.cursor/context/data-layer.md` documentation explicitly acknowledges "mirror URLs... are never trust anchors" and states downloaded *data* is validated against the wallet-advertised root, but this only protects data integrity — it does nothing to prevent the outbound HTTP request itself (the SSRF vector) from being sent to an arbitrary attacker-chosen host/port/path before any content validation occurs.

### Impact Explanation
Any wallet user/node that syncs the chain and tracks a given DataLayer launcher id (e.g., an operator running DataLayer server sync for a public store) can be induced by an unrelated, unprivileged coin spend to issue outbound HTTP requests to attacker-chosen internal/loopback/LAN addresses and arbitrary paths (e.g., `http://127.0.0.1:<internal-admin-port>/...` or cloud metadata endpoints like `http://169.254.169.254/...`). This is a classic blind SSRF: the victim node acts as an unwitting proxy for the attacker's HTTP requests, which can be used to probe or interact with internal services not otherwise reachable from the network, potentially leaking metadata/credentials or triggering unintended side effects on internal-only HTTP APIs. This qualifies as Medium severity, consistent with the CVSS 4.0 vector in the original advisory (network-reachable, no privileges, low confidentiality impact via response timing/side-channel, no direct RCE).

### Likelihood Explanation
Likelihood is moderate-to-high for any node actively running the DataLayer service and tracking a launcher id that an attacker also targets: creating the malicious mirror coin requires only a standard, unprivileged coin spend (any owned coin, any amount) with a `CREATE_COIN` condition to the well-known `MIRROR_PUZZLE_HASH` and crafted memos — no special permissions, cost budget, or protocol knowledge beyond public puzzle definitions. The main precondition is that some victim wallet/DataLayer service is tracking the targeted launcher id, which is expected/common for any publicly consumed DataLayer store.

### Recommendation
- In `get_mirror_info()` / `DataLayerWallet.coin_added()`, validate mirror URL memos for scheme (`http`/`https` only) and reject hosts resolving to loopback, link-local, or private/reserved network ranges (reuse `chia/util/network.py`'s IP/CIDR helpers or the same `is_localhost()`/`is_in_network()` pattern already used in `chia/server/server.py`).
- Apply the same host/scheme allow-list check again immediately before making outbound HTTP requests in `download_data.http_download()`/`DataLayer.get_downloader()`, so DNS rebinding after storage cannot bypass validation performed at ingestion time.
- Consider requiring explicit user/operator opt-in (config allow-list) for mirror URL hosts rather than trusting any on-chain memo automatically.

### Proof of Concept
1. Attacker owns a standard XCH coin and knows the `launcher_id` of a DataLayer store that a victim node tracks (public knowledge for any published store).
2. Attacker builds a spend of their coin with a `CREATE_COIN` condition: puzzle_hash = `create_mirror_puzzle().get_tree_hash()`, amount = arbitrary, memos = `[launcher_id, b"http://127.0.0.1:8555/some/internal/admin/path"]` (or a LAN/cloud-metadata URL) and submits it via the standard mempool (`push_tx`).
3. Once confirmed, the victim's wallet processes the new coin in `DataLayerWallet.coin_added()`, finds `is_launcher_tracked(launcher_id) == True`, and stores the attacker's URL as a `Mirror`.
4. On the victim's next `periodically_manage_data()` cycle, `update_subscriptions_from_wallet()` pulls this URL into the store's `ServerInfo`, and `fetch_and_validate()`/`http_download()` issues an outbound GET to `http://127.0.0.1:8555/...` — an internal endpoint the attacker could not otherwise reach — completing the blind SSRF.

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
        mirrors: list[Mirror] = (await self.wallet_rpc.dl_get_mirrors(DLGetMirrors(launcher_id=store_id))).mirrors

    async def update_subscriptions_from_wallet(self, store_id: bytes32) -> None:
        mirrors: list[Mirror] = (await self.wallet_rpc.dl_get_mirrors(DLGetMirrors(launcher_id=store_id))).mirrors
        urls: list[str] = []
```

```python
    async def get_available_servers_for_store(self, store_id: bytes32, timestamp: int) -> list[ServerInfo]:
        subscriptions = await self.get_subscriptions()
        subscription = next((subscription for subscription in subscriptions if subscription.store_id == store_id), None)
        if subscription is None:
            return []
        servers_info = []
        for server_info in subscription.servers_info:
            if timestamp > server_info.ignore_till:
                servers_info.append(server_info)
        return servers_info
```
