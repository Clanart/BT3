### Title
Unchecked type assertion on attacker-controlled CW20/CW721/CW1155 metadata causes panic in pointer precompile - (File: precompiles/pointer/pointer.go)

### Summary
The `AddCW20`, `AddCW721`, and `AddCW1155` handlers of the CW→ERC pointer precompile (`0x000000000000000000000000000000000000100b`) query an arbitrary, caller-supplied CosmWasm contract address and blindly type-assert the resulting JSON fields `name`/`symbol` to `string` without checking existence or type.

### Finding Description
`AddCW20` performs an unauthenticated smart query against any bech32 address supplied by the caller, then does: [1](#0-0) 
`formattedRes["name"]` and `formattedRes["symbol"]` come straight from `json.Unmarshal` into a `map[string]interface{}`. If the queried contract's `token_info` response omits the `name`/`symbol` keys, `formattedRes["name"]` evaluates to a `nil` interface, and `nil.(string)` panics (`interface conversion: interface {} is nil, not string`). The same pattern exists in `AddCW721` and `AddCW1155` (querying `contract_info`) at [2](#0-1) [3](#0-2) 
and identically across every historical `precompiles/pointer/legacy/v5*/v6*/pointer.go` file. Because CosmWasm contract deployment and instantiation is permissionless, and the pointer precompile is reachable by any EVM caller with no delegatecall/staticcall restriction bypass required, an attacker can deploy a trivial CW20/CW721/CW1155 contract whose `token_info`/`contract_info` query handler returns a JSON object lacking `name` or `symbol` (or returning them as non-string types, e.g. a number or `null`), then call `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` on that address to trigger the panic. This is directly analogous to CVE-2018-20426's root cause: an unchecked/unvalidated pointer/field access on attacker-influenced data leading to a NULL/invalid dereference-style crash inside a security-relevant code path.

Unlike other precompiles in this codebase (e.g. `precompiles/addr/addr.go:93-99`, `precompiles/solo/solo.go:90-99`) which wrap `Execute` in a `defer recover()` specifically to convert panics into reverts, the pointer precompile's `Execute` (`precompiles/pointer/pointer.go:72-93`, and `DynamicGasPrecompile.RunAndCalculateGas` in `precompiles/common/precompiles.go:156-215`) has no such guard.

### Impact Explanation
Without a `recover()` in the pointer precompile itself, the panic unwinds through the EVM interpreter into `x/evm/keeper/msg_server.go`, whose top-level deferred handler at [4](#0-3) 
explicitly re-panics (`panic(pe)`) rather than converting it to a tx error, after only logging and incrementing a metric. I was only able to confirm recovery of this re-panic at higher application layers for the "Giga" synchronous execution path (`app/app.go:1436-1459`), which does catch and downgrades unclassified panics to an `ErrPanic` ABCI result. I could not verify with certainty from available code whether every other tx-processing path (legacy ABCI `DeliverTx`, `CheckTx`, and any RPC-side `eth_call`/`eth_estimateGas`/simulation paths that construct an EVM and invoke this precompile directly) also has an outer recover that fully isolates this panic without side effects. Given the explicit re-panic in `msg_server.go` and the absence of a local recover in this precompile (unlike `addr`, `solo`, etc.), this is a real robustness/DoS-class defect whose severity depends on which caller lacks an outer recover — worst case is a crash of a node process handling the tx (validator or RPC), best case is a correctly-recovered failed transaction.

### Likelihood Explanation
High likelihood of reachability: CosmWasm contract deployment is permissionless, the pointer precompile's `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` methods are callable by any external account or contract (only `readOnly`/self-delegatecall checks apply, per `precompiles/pointer/pointer.go:90-97`), and crafting a WASM contract whose query handler omits or mistypes `name`/`symbol` requires no special privilege.

### Recommendation
Replace the unchecked type assertions with safe, two-value checks (or explicit JSON struct decoding with validated fields) in `AddCW20`, `AddCW721`, and `AddCW1155` in `precompiles/pointer/pointer.go` (and all `precompiles/pointer/legacy/*/pointer.go` variants still in use), returning a proper error (e.g. `"pointee contract returned malformed metadata"`) instead of allowing the type assertion to panic. Additionally, wrap the pointer precompile's `Execute`/`RunAndCalculateGas` path with a `defer recover()` consistent with `precompiles/addr/addr.go` and `precompiles/solo/solo.go`, so that any future unchecked-assertion-style bug in this or other precompiles degrades to a reverted transaction rather than an unhandled panic that reaches `msg_server.go`'s re-panic.

### Proof of Concept
1. Deploy a minimal CosmWasm contract (permissionless) whose `token_info` query handler returns `{}` (or `{"name": 123}`) instead of the expected `{"name": "...", "symbol": "...", ...}`.
2. From any EVM account, call the pointer precompile at `0x000000000000000000000000000000000000100b` method `addCW20Pointer(<contract_bech32_address>)`.
3. Execution reaches `formattedRes["name"].(string)` in `AddCW20` (`precompiles/pointer/pointer.go:154`) with `formattedRes["name"] == nil`, causing a Go panic that unwinds into `msg_server.go`'s deferred handler, which logs and re-panics (`msg_server.go:82-89`) instead of converting it into a normal VM error/tx failure.
