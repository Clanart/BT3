### Title
`SignableTransaction` trusts attacker-declared `TxOut` values in `Prevouts::All` — signed inputs commit to fabricated amounts, burning or invalidating multisig funds - ([File: networks/bitcoin/src/wallet/send.rs](networks/bitcoin/src/wallet/send.rs))

### Summary
Analogous to Platypus's `emergencyWithdraw` — which validated an orthogonal condition (borrow limit) while acting on unvalidated user data — `SignableTransaction::new` validates dust, fee rate, and internal `input_sat >= payment_sat + fee` consistency, but never validates that the `value`/`outpoint` inside each `ReceivedOutput` corresponds to a real on-chain UTXO. `multisig()` only checks that `prevouts[i].script_pubkey` matches the derived group key's P2TR script, while `sign()` feeds the fabricated `prevouts` into `Prevouts::All`, so participants produce valid BIP-340 signatures over attacker-chosen input amounts. Because `ReceivedOutput::read` accepts fully attacker-controlled bytes (offset, `TxOut`, `OutPoint`), an unprivileged party can cause the threshold group to sign a transaction whose real fee is arbitrary, destroying vault funds, or whose sighash commits to inflated amounts making the transaction permanently unspendable.

### Finding Description
`ReceivedOutput::read` deserializes three untrusted fields with no consistency check: `offset`, `output` (`TxOut` = script_pubkey + value), and `outpoint` (txid + vout) [1](#0-0) .

`SignableTransaction::new` consumes these verbatim: `input_sat` is summed from the declared `input.output.value` and `prevouts` are built directly from the supplied `TxOut`s [2](#0-1) [3](#0-2) . All arithmetic — the `NotEnoughFunds` check, change sizing, fee accounting — operates on declared values, exactly like Platypus acting on deposit balances while checking an unrelated solvency flag [4](#0-3) .

The only "verification" is `multisig()`, which checks `p2tr_script_buf(offset.group_key()) == prevouts[i].script_pubkey` — a key-binding check trivially satisfied by an attacker who knows the public group key and sets `offset = 0` — while ignoring `value` and `outpoint` entirely [5](#0-4) .

At signing time, `taproot_key_spend_signature_hash(i, &prevouts, TapSighashType::Default)` commits the fake amounts into `Prevouts::All`, and every participant's FROST share signs that fabricated sighash [6](#0-5) .

### Impact Explanation
Two concrete outcomes:

1. **Deflated declared value**: attacker sets `outpoint` to a real multisig UTXO (say 1 BTC) but `value` to 0.001 BTC, with payments summing to ~0.001 BTC. The group produces a validly-signed transaction spending the real UTXO; the ~0.999 BTC difference becomes miner fee — permanent destruction of vault funds despite every signature being cryptographically valid.
2. **Inflated declared value**: declared `value` exceeds the real UTXO; change/payments are computed on phantom balance and the signed transaction is consensus-invalid — funds reported as spent become an unusable, burned-signing-round artifact.

The signatures are valid `SIGHASH_DEFAULT` key-spend signatures over `Prevouts::All`, so they cannot be distinguished post-hoc from honestly-constructed spends. Severity: **High** (unprivileged party causes the threshold group to sign transactions destroying or bricking real funds).

### Likelihood Explanation
The attack only requires feeding crafted bytes through `ReceivedOutput::read` into `SignableTransaction::new` — an explicitly in-scope untrusted-byte sink. The attacker needs no threshold position, no key material, and no collusion: `offset = Scalar::ZERO`, `script_pubkey = p2tr_script_buf(public_group_key)`, and a `value`/`outpoint` of their choosing satisfy every check in `new()` and `multisig()`. The sole mitigations are integrator-side validation that isn't enforced in this crate.

### Recommendation
Bind inputs to reality before signing:
- In `SignableTransaction::new` or `multisig()`, require each `ReceivedOutput` to be resolved against the UTXO set (RPC `gettxout` / `gettransaction`) and assert `output.value` and `output.script_pubkey` match the confirmed prevout, not just the key's script.
- Alternatively, have every participant independently re-derive prevouts from the chain and abort `sign()` on mismatch, since `Prevouts::All` already commits all participants to identical amounts.

```rust
    let mut v = vec![];

    v.extend(serialize(&TxOut {
        value: Amount::from_sat(100_000),                    // declared: 0.001 BTC (real: 1 BTC)

    v.as_slice()

// All checks pass; change/fee computed on fabricated 100k sats

// multisig() passes: script matches group key. sign() commits Prevouts::All
// to value=100_000 while the real input is 100_000_000 -> ~0.999 BTC burned as fee
```
