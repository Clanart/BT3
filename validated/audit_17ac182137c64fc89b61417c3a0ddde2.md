### Title
Malicious FROST preprocess can crash Bitcoin signing with an identity aggregate nonce - ([File: networks/bitcoin/src/crypto.rs](networks/bitcoin/src/crypto.rs))

### Summary
Bitcoin's FROST Schnorr algorithm does not reject an aggregate nonce equal to the point at infinity. An attacker who supplies a crafted preprocess after observing the victim's nonce commitments can make the aggregate `R` become infinity; `Hram::hram` then calls `x(R)`, which unconditionally unwraps the absent x-coordinate and panics. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`AlgorithmSignMachine::read_preprocess` deserializes attacker-controlled point commitments with `Commitments::read`, while `Curve::read_G` only rejects identity for each individual encoded point. [4](#0-3) [5](#0-4)  During `sign`, the commitments are combined through participant-specific binding factors into `Rs`, and `sign_share` receives `nonce_sums[0][0]` as the aggregate nonce `R`. [6](#0-5) [7](#0-6)  The Bitcoin HRAm hashes `x(R)`, but `x` calls `expect("point at infinity")` when the point has no affine x-coordinate. [8](#0-7) [3](#0-2) 

### Impact Explanation
A signing participant or another party able to submit a preprocess can reliably abort the victim's signing attempt by forcing `R` to infinity. [9](#0-8) [10](#0-9)  This is a remote denial of service against the signing operation and can prevent Bitcoin transaction authorization, matching the crafted-input null-pointer/DoS class of the referenced report. [11](#0-10) 

### Likelihood Explanation
The preprocess is explicit untrusted input read through `read_preprocess`, and participant identities, message bytes, and all commitments are bound before calculating the aggregate nonce. [4](#0-3) [12](#0-11)  An attacker who can wait for the victim's preprocess can choose a valid non-identity commitment that cancels the remaining aggregate contribution after applying the public binding factor; rejecting only serialized identity points does not prevent the resulting sum from being identity. [5](#0-4) [13](#0-12) 

### Recommendation
Reject an identity aggregate nonce before invoking `Hram::hram`, returning `FrostError::InvalidPreprocess` or `InvalidSigningSet` for the responsible participant. [1](#0-0)  Additionally, make `Hram::hram`, `x`, and `x_only` return `Option`/`Result` rather than panicking on infinity so malformed protocol inputs cannot terminate the signer. [14](#0-13) 

### Proof of Concept
1. Instantiate `AlgorithmMachine<Secp256k1, networks::bitcoin::crypto::Schnorr>` for a threshold signing set containing the victim and attacker. [15](#0-14) 
2. Obtain the victim's preprocess, calculate the attacker's public binding factor and nonce contribution, and submit a canonical non-identity commitment selected so the final `nonce_sums[0][0]` is `ProjectivePoint::IDENTITY`. [6](#0-5) 
3. Call `sign` with that preprocess and any message; execution reaches `Hram::hram`, calls `x(R)`, and panics on `expect("point at infinity")` instead of returning a `FrostError`. [7](#0-6) [3](#0-2)

/// Get the x coordinate of a non-infinity point.
///
/// Panics on invalid input.
fn x(key: &ProjectivePoint) -> [u8; 32] {
  let encoded = key.to_encoded_point(true);
  (*encoded.x().expect("point at infinity")).into()
}

/// Convert a non-infinity point to a XOnlyPublicKey (dropping its sign).
///
/// Panics on invalid input.
pub(crate) fn x_only(key: &ProjectivePoint) -> XOnlyPublicKey {
