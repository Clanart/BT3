### Title
Insufficient Cooldown on `PreAddTx` Known-Bundle-Tx Check Enables Rapid Resubmission of Gasless Bundle Transactions - ([File: kaiax/gasless/impl/tx_pool.go])

### Summary
The `kaiax/gasless` module implements a "cooldown"-style guard to prevent an already-known gasless bundle transaction (approve/swap) from being re-admitted to the pool, using `KnownTxTimeout = 30 * time.Second`, and drops bundle txs from `pending`/`queue` after only `PendingTimeout = 10 * time.Second` / `QueueTimeout = 10 * time.Second` [1](#0-0) . These windows are hard-coded, very short, and not tied to block time or finality, mirroring the reported bug class of an "insufficient cooldown period" that fails to prevent rapid resubmission/abuse.

### Finding Description
`PreAddTx` is the sole gate that prevents a resubmission of a gasless bundle transaction that the pool already knows about: [2](#0-1) 
It only rejects re-addition while `knownTx.elapsedPromotedOrAddedTime() < KnownTxTimeout` (30s). Once that fixed 30-second window elapses—or immediately for a tx that was demoted from `pending`/`queue` after only 10 seconds (`PendingTimeout`/`QueueTimeout`)—the same hash (or, more importantly, the same sender's approve/swap pair before nonce is finalized) can be freely reconsidered for bundling by `ExtractTxBundles`, which prepends a `LendTxGenerator` that has the block proposer front the gas fee on the sender's behalf [3](#0-2) .

Any unprivileged transaction sender fully controls the timing of resubmission (an RPC caller / gasless user), and a public RPC caller can simply keep re-broadcasting the swap/approve pair. Because the cooldown windows (10s/30s) are far shorter than typical multi-block reorg or fork-choice/finality windows on the network, and are wall-clock based (`time.Now()`), a chain reorg or even ordinary block-time variance can cause the same bundle to be treated as "new" again well before the underlying state (nonce, allowance, balances) has stabilized across the network. This is analogous to the reported issue: a bug class where a fixed, too-short cooldown is used as the sole defense against rapid repeated submission of a privileged/subsidized operation (there: cross-chain identity transfer; here: proposer-subsidized gasless-swap admission), undermining the intended anti-abuse/anti-race protections.

### Impact Explanation
If the cooldown is bypassed or expires too quickly relative to block/finality timing, a sender could cause the `LendTxGenerator` to be prepended and gas-fee lending to be attempted again for what is effectively the same nonce/tx during a reorg window, or could repeatedly force queue/pending churn of the same bundle to keep re-triggering `VerifyExecutable`/balance checks against `GaslessSwapRouter` state, creating repeated proposer-side gas subsidization attempts around a state that hasn't settled. This falls under "fee-delegation/gasless settlement abuse" in the accepted impact categories, since it affects the block proposer's lent gas fee accounting for the gasless-swap flow guarded only by this timing-based dedup logic.

### Likelihood Explanation
Likelihood is **moderate**: the attacker is a fully unprivileged gasless user/public RPC caller who need only resend transactions after ~10–30 seconds, which is trivial and requires no special access. However, exploiting it into an actual value-transfer/fee-abuse outcome further depends on the `VerifyExecutable`/`checkBalanceForSwap` checks (nonce equality, allowance, balance, deadline) still passing at execution time, which limits (but does not eliminate) the practical blast radius under reorg conditions.

### Recommendation
- Do not rely on fixed wall-clock cooldowns (`KnownTxTimeout`, `PendingTimeout`, `QueueTimeout`) as the anti-replay/anti-abuse mechanism for gasless bundle admission; tie the "known" status expiry to actual finality/block-confirmation depth rather than `time.Since(...)`.
- Increase `KnownTxTimeout`/`PendingTimeout`/`QueueTimeout` to be safely larger than expected reorg depth and block-time variance, and make them configurable/monitored rather than hard-coded 10s/30s constants at [1](#0-0) .
- Re-validate on-chain state (nonce, allowance) at the moment of re-bundling in `ExtractTxBundles`/`PreAddTx`, not solely rely on the elapsed-time gate, to close any race window regardless of cooldown length.

### Proof of Concept
1. Attacker (unprivileged sender) submits a valid `GaslessApproveTx` + `GaslessSwapTx` pair; pool marks them `knownTxs` with `TxStatusQueue`/`TxStatusPending`.
2. `PreAddTx` blocks exact resubmission only for `KnownTxTimeout` (30s) per [4](#0-3) ; and the pool itself evicts the bundle from `pending`/`queue` after only `PendingTimeout`/`QueueTimeout` (10s) via `PreReset` [5](#0-4) .
3. Attacker waits slightly over 10–30 seconds (well within normal network operation, and trivially satisfied during any reorg/latency event) and resubmits the same or a crafted follow-up approve/swap pair.
4. `ExtractTxBundles` treats it as a fresh bundle and prepends a new `LendTxGenerator`, re-triggering proposer-subsidized gas lending logic [6](#0-5)  before the previous submission's on-chain effects are guaranteed final, creating a window for double-processing/state-inconsistency between honest nodes that observe the "known" state differently based on local wall-clock timing.

*(Confidence note: this analog is on firmer footing for the "cooldown/timeout constant is too short and time-based rather than finality-based" bug class than for a fully proven concrete fund-theft exploit; the downstream `VerifyExecutable` checks in `getter.go` do add real state validation that may block simple double-spend attempts. This should be verified further with a live Devin session for exact reorg-depth/timing assumptions in the target network before treating this as fully confirmed.)*

func (g *GaslessModule) PreAddTx(tx *types.Transaction, local bool) error {
	g.knownTxsMu.RLock()
	defer g.knownTxsMu.RUnlock()

	if knownTx, ok := g.knownTxs.get(tx.Hash()); ok && knownTx.elapsedPromotedOrAddedTime() < KnownTxTimeout {
		return ErrUnableToAddKnownBundleTx
	}

	if g.IsBundleTx(tx) {
		if uint(g.knownTxs.numQueue()) >= g.GetMaxBundleTxsInQueue() {
			return ErrBundleTxQueueFull
		}
		g.knownTxs.add(tx, TxStatusQueue)
	}
	return nil
}

// PreReset removes timed out tx from the tx pool and knownTxs.
func (g *GaslessModule) PreReset(oldHead, newHead *types.Header) []common.Hash {
	g.knownTxsMu.Lock()
	defer g.knownTxsMu.Unlock()

	drops := make([]common.Hash, 0)

	for hash, knownTx := range *g.knownTxs {
		// remove pending timed out tx from tx pool
		if knownTx.status == TxStatusPending && knownTx.elapsedPromotedTime() >= PendingTimeout {
			drops = append(drops, hash)
		}
		// remove queue timed out tx from tx pool
		if knownTx.status == TxStatusQueue && knownTx.elapsedAddedTime() >= QueueTimeout {
			drops = append(drops, hash)
		}
		// remove known timed out tx from knownTxs
		if knownTx.elapsedPromotedOrAddedTime() >= KnownTxTimeout {
			g.knownTxs.delete(hash)
		}
	}

	return drops
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}
