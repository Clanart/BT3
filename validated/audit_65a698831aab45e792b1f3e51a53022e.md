### Title
Gasless bundle-tx queue admission counter is incremented in `PreAddTx` before pool validation, letting an attacker DoS bundle-tx admission with repeatedly-crafted invalid transactions - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The Nova advisory describes a resource that gets "claimed" (allocated) on an action (rebuild) but is never released if the follow-up processing fails or is repeated, letting an unprivileged actor inflate a tracked resource counter beyond its intended capacity and starve legitimate users (a DoS via untracked/over-counted resource). Kaia's gasless module has an analogous pattern: `GaslessModule.PreAddTx` unconditionally increments the `knownTxs` "queue" counter for any transaction that looks like a bundle tx (`IsBundleTx`), and this happens *before* the core `TxPool.add()` performs its real validation (`pool.validateTx`, balance/nonce/pool-full checks, etc.). If the transaction is subsequently rejected by the pool, the reservation in `knownTxs` is not rolled back immediately — it only expires after `QueueTimeout` (10s).

### Finding Description
`TxPool.add()` calls the registered module hook first, unconditionally, before any of its own admission checks: [1](#0-0) 

`GaslessModule.PreAddTx` increments the bundle-queue counter as soon as it sees a bundle-shaped tx (an "approve" tx as defined by `IsBundleTx`/`IsModuleTx`), gating admission only by `GetMaxBundleTxsInQueue()`: [2](#0-1) 

The counter (`knownTxs.numQueue()`) is a pure in-memory map keyed by tx hash with a status field; it is only cleaned up in two ways:
1. Time-based expiry in `PreReset`, which fires only on the next chain-head reset event and only after `QueueTimeout`/`KnownTxTimeout` elapse: [3](#0-2) 
2. Re-categorization in `PostReset`, which likewise depends on a chain-head reset cycle and simply demotes stale entries rather than deleting them: [4](#0-3) 

Because `PreAddTx` runs *before* `pool.validateTx`, the "already known" hash check, and the pool-full/underpriced/slot checks in `TxPool.add`, a transaction can be counted as "reserved" in the gasless queue even though it will be rejected moments later by the real transaction pool (e.g. `ErrInsufficientFundsFrom`, `ErrNonceTooLow`, `ErrUnderpriced`, `txpool is full`, etc.). There is no code path that decrements `knownTxs` when `pool.add()` subsequently fails — the entry simply sits there counted toward `GetMaxBundleTxsInQueue()` until `QueueTimeout` (10 seconds) passes.

This mirrors the Nova bug class precisely: an action that looks like a legitimate resource claim (bundle-tx queue slot / instance rebuild resource claim) is recorded immediately, but the corresponding release/rollback on failure is either absent or deferred, letting repeated invocations of the same action accumulate "untracked" claims that exceed the intended capacity and starve legitimate consumers.

### Impact Explanation
Any unauthenticated/unprivileged public-RPC caller who can submit transactions can craft a stream of syntactically-valid "approve" bundle transactions (matching `IsApproveTx`) that are guaranteed to fail deeper pool validation (e.g., zero balance sender, already-used nonce so `ErrAlreadyNonceExistInPool`/underpriced, or deliberately colliding hashes are irrelevant — distinct senders/nonces are trivial to generate) yet still pass `IsBundleTx` classification and get counted by `PreAddTx`. By repeatedly resubmitting fresh distinct bundle-shaped transactions faster than the 10-second `QueueTimeout`, the attacker can keep `knownTxs.numQueue()` pinned at `GetMaxBundleTxsInQueue()`, causing `ErrBundleTxQueueFull` to be returned for all legitimate gasless swap/approve bundle submissions network-wide — a persistent denial of service against the gasless subsystem, reachable purely via public RPC transaction submission with no cost beyond gas-less/zero-balance transaction construction (many rejected transactions cost nothing since they never enter the pool and are never broadcast/executed).

### Likelihood Explanation
High likelihood: the attack requires only the ability to submit transactions to a node's RPC (`SendTx`/`AddRemote`), constructing transactions that satisfy `IsApproveTx`/`IsBundleTx` classification (a fixed calldata/selector pattern) with an intentionally-invalid nonce or an account with insufficient balance so that they are rejected by `pool.validateTx` shortly after being counted. No special privileges, keys, or timing races beyond the fixed `QueueTimeout` window are needed, and the default `MaxBundleTxsInQueue` is a bounded config value that is easy to saturate with a modest transaction rate.

### Recommendation
Move the module admission hook (`PreAddTx`) to run only after `pool.validateTx` (and ideally after full admission, right before enqueue), or ensure `TxPool.add()` invokes a corresponding rollback hook (`module.OnAddFailed`/decrement) whenever any check after `PreAddTx` causes rejection, so the gasless `knownTxs` queue counter accurately reflects transactions that are actually admitted into `pool.queue`/`pool.pending`, not transactions that were merely offered and rejected.

### Proof of Concept
1. Deploy/point at a node with the gasless module enabled and a bounded `gasless.max-bundle-txs-in-queue` (e.g. default value).
2. Generate `N = MaxBundleTxsInQueue` distinct EOAs with zero balance (or otherwise guaranteed-to-fail state, e.g. wrong nonce).
3. For each EOA, craft and sign a transaction whose calldata matches the module's `IsApproveTx` selector (see `IsBundleTx`/`IsModuleTx` in `kaiax/gasless/impl/tx_pool.go`), targeting the gasless-recognized approve function, with nonce 0.
4. Submit all `N` transactions to the node's public RPC in rapid succession (well under `QueueTimeout` = 10s). Each call flows through `TxPool.add()` → `module.PreAddTx` (increments `knownTxs` queue counter to `N`) → `pool.validateTx` fails due to insufficient balance → `add()` returns error, but the `knownTxs` entry is *not* removed.
5. Immediately submit one more legitimate bundle transaction from a funded account; observe it is rejected with `ErrBundleTxQueueFull` even though the pool contains zero actual gasless bundle transactions.
6. Repeat step 3–5 every < 10 seconds to sustain the denial of service indefinitely.

func (g *GaslessModule) PreAddTx(tx *types.Transaction, local bool) error {
	g.knownTxsMu.RLock()
	defer g.knownTxsMu.RUnlock()

	if knownTx, ok := g.knownTxs.get(tx.Hash()); ok && knownTx.elapsedPromotedOrAddedTime() < KnownTxTimeout {
		return ErrUnableToAddKnownBundleTx
	}

	if g.IsBundleTx(tx) {
		if uint(g.knownTxs.numQueue()) >= g.GetMaxBundleTxsInQueue() {
			return ErrBundleTxQueueFull
		}
		g.knownTxs.add(tx, TxStatusQueue)
	}
	return nil
}

// PreReset removes timed out tx from the tx pool and knownTxs.
func (g *GaslessModule) PreReset(oldHead, newHead *types.Header) []common.Hash {
	g.knownTxsMu.Lock()
	defer g.knownTxsMu.Unlock()

	drops := make([]common.Hash, 0)

	for hash, knownTx := range *g.knownTxs {
		// remove pending timed out tx from tx pool
		if knownTx.status == TxStatusPending && knownTx.elapsedPromotedTime() >= PendingTimeout {
			drops = append(drops, hash)
		}
		// remove queue timed out tx from tx pool
		if knownTx.status == TxStatusQueue && knownTx.elapsedAddedTime() >= QueueTimeout {
			drops = append(drops, hash)
		}
		// remove known timed out tx from knownTxs
		if knownTx.elapsedPromotedOrAddedTime() >= KnownTxTimeout {
			g.knownTxs.delete(hash)
		}
	}

	return drops
}

// PostReset re-categorizes knownTxs based on the current txpool.queue and txpool.pending.
func (g *GaslessModule) PostReset(oldHead, newHead *types.Header, queue, pending map[common.Address]types.Transactions) {
	g.knownTxsMu.Lock()
	defer g.knownTxsMu.Unlock()

	flattenedQueue := make(map[common.Hash]*types.Transaction)
	flattenedPending := make(map[common.Hash]*types.Transaction)
	for _, txs := range queue {
		for _, tx := range txs {
			flattenedQueue[tx.Hash()] = tx
		}
	}
	for _, txs := range pending {
		for _, tx := range txs {
			flattenedPending[tx.Hash()] = tx
		}
	}

	for _, knownTx := range *g.knownTxs {
		if _, ok := flattenedQueue[knownTx.tx.Hash()]; ok {
			g.knownTxs.add(knownTx.tx, TxStatusQueue)
		} else if _, ok := flattenedPending[knownTx.tx.Hash()]; ok {
			g.knownTxs.add(knownTx.tx, TxStatusPending)
		} else {
			g.knownTxs.add(knownTx.tx, TxStatusDemoted)
		}
	}
