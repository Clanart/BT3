### Title
Unsigned OP_RETURN operator xonly_pk in payout tx lets anyone falsely credit an arbitrary operator as payer, enabling an uninvolved operator to be reimbursed for a payout it never funded - ([File: core/src/verifier.rs])

### Summary
`Verifier::update_finalized_payouts` and `parse_op_return_data` extract the "paying operator" xonly public key purely as unsigned OP_RETURN data from whichever transaction happens to spend the registered `withdrawal_utxo`, with no signature proving that operator actually authorized or funded the payout. Because the user's `SinglePlusAnyoneCanPay` payout signature only commits to input 0 / output 0, anyone completing the payout transaction can insert any real operator's x-only pubkey into the OP_RETURN, causing that operator to be wrongly credited as payer and become eligible for reimbursement via `validate_payer_is_operator`.

### Finding Description
The broken binding is: `withdrawals.payout_payer_operator_xonly_pk` (the operator credited as payer) == the operator whose own funds actually paid the withdrawal output. This should always hold but is not enforced anywhere.

`update_finalized_payouts` finds a payout tx spending a registered `withdrawal_utxo`, extracts the first OP_RETURN output, and parses raw bytes as the operator's xonly pubkey with no cryptographic check: [1](#0-0) 
`parse_op_return_data` is a pure, unauthenticated data-push parser: [2](#0-1) 

In the intended protocol, `create_payout_txhandler` builds the payout tx with a `KeySpend` input signed only by the withdrawing user (`SinglePlusAnyoneCanPay`), and the operator's xonly pk is written into an OP_RETURN output that is *not signed by the operator at all*: [3](#0-2) 

Because the sighash type is `SinglePlusAnyoneCanPay`, the signature only commits to input 0 and the matching-index output; it does not cover any other input or the OP_RETURN output. This is verified explicitly in `operator.withdraw()`, where only the input/output-0 pair is signature-checked: [4](#0-3) 

The withdrawal UTXO itself is chosen and registered from the Citrea `withdraw()` call, and the payout tx must spend exactly that UTXO: [5](#0-4) 

Since the attacker is unprivileged but is explicitly allowed to call `withdraw()` on the Citrea bridge contract, choose the withdrawal UTXO bytes, and produce a Schnorr signature/sighash flag, the attacker can be the legitimate owner/signer of the registered `withdrawal_utxo`. They can then construct and broadcast, entirely outside of any Clementine gRPC endpoint, a raw Bitcoin transaction that: (1) spends the registered `withdrawal_utxo` using their own valid `SinglePlusAnyoneCanPay` signature over input 0/output 0 (paying themselves the correct amount, i.e., genuinely fronting their own withdrawal), (2) adds their own funding input for fees, and (3) places a real operator Y's x-only pubkey bytes into the OP_RETURN output — none of which the signature constrains.

Once mined, every node (verifiers and each operator's own independent Citrea/Bitcoin sync) that runs `update_finalized_payouts` will parse this and set `payout_payer_operator_xonly_pk = Y`. Operator Y's own `PayoutCheckerTask`, reading its own DB, will find this "unhandled payout" credited to its own key and automatically call `handle_finalized_payout`, triggering a Kickoff and eventually a `Reimburse` transaction: [6](#0-5) 

Verifiers checking the resulting kickoff via `is_kickoff_malicious` only confirm that the OP_RETURN-parsed pubkey equals the kickoff's own `operator_xonly_pk` (trivially true here since both are Y) — they never confirm operator Y actually signed or funded the payout tx: [7](#0-6) 

The `Reimburse` transaction then pays operator Y directly from the deposit's `MoveToVault` UTXO — real bridge value: [8](#0-7) 

`validate_payer_is_operator` (used by `get_reimbursement_txs`, the manual/non-automated reimbursement path) performs the same flawed check — it only compares the DB-stored `payer_xonly_pk` against `self.signer.xonly_public_key`, never verifying an actual signature from that operator over the payout tx: [9](#0-8) 

No existing guard (`is_deposit_valid`, `SECP.verify_schnorr` in `withdraw`, `is_kickoff_malicious`, or DB uniqueness constraints) checks that the operator credited in the OP_RETURN actually signed any part of the payout transaction; all of them only check that the OP_RETURN bytes are internally consistent with the same (attacker-chosen) value.

### Impact Explanation
BTC leaves the deposit's `MoveToVault` UTXO via the `Reimburse` transaction and is paid to an operator (Y) who never funded or authorized the corresponding payout — matching the Critical bucket "an operator reimbursed for a payout it never funded" (and, from the bridge's perspective, BTC effectively moves out of the move-to-vault UTXO without the credited party having fronted the matching withdrawal). This is repeatable per withdrawal/deposit and can target any operator whose xonly pubkey is public knowledge, without needing that operator's cooperation or key.

### Likelihood Explanation
The attacker needs only: (1) to call `withdraw()` on the Citrea bridge contract as a normal user, choosing their own withdrawal UTXO/signature, and (2) to broadcast a self-crafted Bitcoin transaction directly to the network (not through any Clementine gRPC), paying themselves the correct withdrawal amount while embedding an arbitrary real operator's pubkey in the OP_RETURN. No special privileges, keys, or collusion with an operator are required, and the attacker's cost is exactly what they'd already pay for their own withdrawal (fees + the amount they receive), making this cheap and repeatable across many withdrawals/operators.

### Recommendation
Bind the OP_RETURN operator commitment to an actual signature from that operator (e.g., require the operator to co-sign the payout transaction, or require a separate signature over the OP_RETURN payload/txid by the claimed operator xonly_pk) before `update_finalized_payouts`/`is_kickoff_malicious`/`validate_payer_is_operator` treat that operator as the payer. Alternatively, restrict acceptance of payout txs to only those actually broadcast through the operator's own signed flow, and cross-check on-chain that the additional funding input(s) are demonstrably controlled by the claimed operator.

/// Parses the OP_RETURN data from a Bitcoin script. It retrieves the first data push after an OP_RETURN.
pub fn parse_op_return_data(script: &Script) -> Option<&[u8]> {
    let mut instructions = script.instructions();
    if let Some(Ok(Instruction::Op(opcodes::all::OP_RETURN))) = instructions.next() {
        if let Some(Ok(Instruction::PushBytes(data))) = instructions.next() {
            return Some(data.as_bytes());
        }
    }
    None
}

pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())
}

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// For a deposit_id checks that the payer for that deposit is the operator, and the payout blockhash and kickoff txid are set.
    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };
