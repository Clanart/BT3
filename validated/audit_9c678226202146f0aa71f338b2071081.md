### Title
Faulty encrypted DKG share reveals its ECDH key before message authentication is verified - (File: crypto/dkg/pedpop/src/lib.rs)

### Summary
`KeyMachine::calculate_share` returns an `EncryptionKeyProof` for a malformed decrypted share before verifying the `EncryptedMessage` proof of possession. An unprivileged party who can relay or supply protocol messages can alter a valid encrypted share, cause the recipient to emit the blame proof, and then use the disclosed ECDH key to decrypt the original share.

### Finding Description
`Encryption::decrypt` only queues the per-message Schnorr PoP into the supplied `BatchVerifier`; it then immediately performs ECDH with the recipient’s static encryption key and constructs an `EncryptionKeyProof` containing that shared key and a DLEq proof. [1](#0-0) 

`calculate_share` deserializes the decrypted bytes into a scalar before running the batch verifier. If those bytes are non-canonical, it immediately returns `InvalidShare` with `Some(blame)`, bypassing `batch.verify_with_vartime_blame()` and therefore bypassing authentication of the modified message’s PoP. [2](#0-1) 

The disclosed `EncryptionKeyProof.key` is the exact ECDH output used to derive the ChaCha20 stream key. `decrypt_with_proof` later treats that value as sufficient to decrypt the message after checking the DLEq against the registered encryption key. [3](#0-2) 

### Impact Explanation
An attacker can tamper with a delivered encrypted share so that it decrypts to a non-canonical scalar while preserving its per-message ECDH public key. The victim returns a blame proof containing the shared ECDH key for that same `msg.key`. [4](#0-3) 

Because ECDH depends only on the recipient’s private encryption key and `msg.key`, the disclosed shared key also decrypts the attacker’s original untampered ciphertext. The attacker therefore recovers another participant’s DKG secret share from public protocol traffic, satisfying the key-share-recovery impact class. [5](#0-4) 

### Likelihood Explanation
The attack requires only supplying a modified `EncryptedMessage` under the original sender’s participant identity. Mutating the fixed-width ciphertext produces effectively random plaintext; for scalar encodings much smaller than the representation space, such as a 252-bit field in a 256-bit representation, the result is non-canonical with high probability. In the non-canonical case, `calculate_share` exits before PoP verification. [6](#0-5) 

The processor propagates the blame object as serialized public data in `ProcessorMessage::InvalidShare`, making the ECDH proof available to the party observing or coordinating blame. [7](#0-6) 

### Recommendation
Do not create or expose an `EncryptionKeyProof` until the message’s PoP has passed verification. In `Encryption::decrypt`, verify the PoP synchronously before ECDH, or return a pending decryption artifact whose shared key is only materialized after the batch succeeds. Structurally, `calculate_share` should complete all authentication checks before any error path can return a blame proof. [8](#0-7) 

### Proof of Concept
1. Honest participant `A` sends participant `B` an encrypted share `E = { key: K, pop, msg: C }`.
2. An attacker forwards `E'` to `B`, preserving `K` but modifying `C` to `C'`.
3. `B` calls `calculate_share` with `E'` attributed to `A`.
4. `Encryption::decrypt` queues the now-invalid PoP, calculates `shared = x_B * K`, decrypts `C'`, and builds a valid DLEq-backed `EncryptionKeyProof` for `shared`. [1](#0-0) 
5. With high probability, the modified plaintext is a non-canonical scalar representation. `calculate_share` returns `InvalidShare { blame: Some(proof) }` before executing the queued PoP verification. [9](#0-8) 
6. The attacker obtains `proof.key = x_B * K`, reconstructs the same ChaCha20 key from the public DKG context, and applies it to the original ciphertext `C`, recovering `A`’s secret share for `B`. [5](#0-4)

  transcript.append_message(b"context", context);

  transcript.domain_separate(b"encryption_key");

  let mut ecdh = ecdh.to_bytes();
  transcript.append_message(b"shared_key", ecdh.as_ref());

  let mut challenge = transcript.challenge(b"key");

  // TODO: https://github.com/serai-dex/serai/issues/151
