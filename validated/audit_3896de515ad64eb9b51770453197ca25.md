Confirmed finding: the `CW721ERC721Pointer.transferFrom()` function omits the authorization check that OpenZeppelin's `ERC721` (and even the repo's own plain `contracts/src/ERC721.sol` reference implementation) enforces before moving a token.

### Title
Unauthorized NFT transfer due to missing caller-authorization check in `CW721ERC721Pointer.transferFrom()` - (File: contracts/src/CW721ERC721Pointer.sol)

### Summary
`CW721ERC721Pointer.sol` is the production CW721↔ERC721 pointer contract that lets EVM callers manage CosmWasm NFTs via the wasmd precompile [1](#0-0) . Its `transferFrom()` override verifies only that the `from` argument matches the token's current owner, but never checks that `msg.sender` is that owner or an approved spender/operator, unlike the OpenZeppelin base it inherits from and unlike the repo's own standalone `ERC721.sol` reference implementation which explicitly gates transfers with `_isApprovedOrOwner` [2](#0-1) [3](#0-2) .

### Finding Description
`transferFrom(address from, address to, uint256 tokenId)` only requires `from == ownerOf(tokenId)` and `to != address(0)`, then immediately builds a `transfer_nft` CosmWasm execute payload and dispatches it through the wasmd precompile via delegatecall, using `from`'s Sei-mapped address as the payload sender [4](#0-3) . No `require(msg.sender == from || isApprovedForAll(from, msg.sender) || getApproved(tokenId) == msg.sender)` (or equivalent) is present anywhere in the function or the internal `_execute` helper [5](#0-4) . Because `_execute` performs a `delegatecall` to the wasmd precompile, the resulting CosmWasm `execute` message is signed as if it came from the pointer contract acting on behalf of the token owner — the precompile has no independent way to verify that the actual EOA/contract invoking `transferFrom` is authorized, since that authorization is expected to be enforced in the Solidity wrapper itself. This mirrors the OlympusDAO `BondFixedExpiryTeller.redeem()` bug class cited in the report: a state-changing, asset-moving entry point fails to validate that the caller is entitled to act on the referenced asset before performing the transfer.

### Impact Explanation
Any unprivileged EVM account can call `pointer.transferFrom(victimOwner, attacker, tokenId)` for any CW721-backed NFT pointer to move a token away from its rightful owner without ever having been approved, resulting in unauthorized transfer of the underlying CosmWasm NFT — a direct violation of ownership guarantees and a form of asset theft/permanent loss for the victim. This matches the explicitly in-scope impact category "unauthorized transfer via precompile or pointer."

### Likelihood Explanation
The vulnerability is trivially and permissionlessly reachable: any address can call `transferFrom` on any deployed `CW721ERC721Pointer` instance for any `tokenId` whose current owner is known (owner is discoverable via the public `ownerOf` query) [6](#0-5) . No special privileges, races, or non-default configuration are required, and pointer contracts are a standard, chain-created bridging mechanism (CW<->EVM pointers) intended for public use.

### Recommendation
Add the standard ERC721 authorization check before building/executing the `transfer_nft` payload, e.g.:
```solidity
require(
    msg.sender == from ||
    isApprovedForAll(from, msg.sender) ||
    getApproved(tokenId) == msg.sender,
    "ERC721: caller is not token owner or approved"
);
```
This should be added immediately after the `from == ownerOf(tokenId)` check in `transferFrom()`, consistent with the authorization pattern already used in the repository's own `ERC721.sol` reference implementation.

### Proof of Concept
1. Deploy/identify a `CW721ERC721Pointer` instance pointing at a CW721 contract, with `tokenId` owned by `victim` (an EVM address mapped to a Sei address).
2. From an unrelated `attacker` account (no approval granted), call:
   ```solidity
   pointer.transferFrom(victim, attacker, tokenId);
   ```
3. The `require(from == ownerOf(tokenId), ...)` check passes because `from` is correctly the current owner; there is no check that `msg.sender == attacker` is authorized.
4. The contract executes the `transfer_nft` CosmWasm message via the wasmd precompile, moving the NFT from `victim` to `attacker`, confirmed by a subsequent `ownerOf(tokenId)` query returning `attacker`.

**Note on verification limits:** I was unable to fully trace how the wasmd precompile's `execute` call resolves the "sender" identity for the underlying CosmWasm `transfer_nft` message when invoked via `delegatecall` from the pointer contract (i.e., whether it uses the pointer contract's own Sei address or somehow re-derives `msg.sender`'s identity). This determines whether the precompile layer provides any secondary defense-in-depth check that might mitigate exploitability. Confirming this would require examining the wasmd precompile's `execute` implementation and delegatecall sender-resolution logic in more depth than the current index coverage allowed.

    function _isApprovedOrOwner(
        address owner,
        address spender,
        uint id
    ) internal view returns (bool) {
        return (spender == owner ||
        isApprovedForAll[owner][spender] ||
            spender == _approvals[id]);
    }

    function transferFrom(address from, address to, uint id) public {
        require(from == _ownerOf[id], "from != owner");
        require(to != address(0), "transfer to zero address");

        require(_isApprovedOrOwner(from, msg.sender, id), "not authorized");

        _balanceOf[from]--;
        _balanceOf[to]++;
        _ownerOf[id] = to;

        delete _approvals[id];

        emit Transfer(from, to, id);
    }
