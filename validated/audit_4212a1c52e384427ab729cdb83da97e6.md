# Finding: Gasless LendTx pays out KAIA unconditionally before SwapTx balance/allowance is re-verified, enabling proposer fund loss (TOCTOU)

## Summary
The FPG incident involved loss of funds due to insufficient safeguards before value was allowed to move out of the platform. The closest reachable analog in this codebase is in the `kaiax/gasless` module: a gasless-swap `LendTx` unconditionally transfers real KAIA from the block proposer to a user *before* the corresponding `GaslessSwapTx`'s token balance/allowance is re-validated at bundling/execution time, creating a window where a malicious gasless user can obtain proposer-funded KAIA that is never repaid if the swap subsequently reverts on-chain.

## Finding Description
`GaslessModule.GetLendTxGenerator` builds a `TxTypeEthereumDynamicFee` transaction that sends `lendAmount(approveTxOrNil, swapTx)` KAIA from the proposer's key directly to the swap sender, unconditionally: [1](#0-0) 

This generator is prepended to every gasless bundle by `ExtractTxBundles`, which decides whether to bundle a pair using only `IsExecutable`/`VerifyExecutable`: [2](#0-1) 

`VerifyExecutable` only checks nonce sequencing, token/spender/amount consistency between the approve/swap calldata, and the repay-amount formula — it never queries the sender's live on-chain token balance or ERC-20 allowance: [3](#0-2) 

The actual on-chain balance/allowance checks (`checkBalanceForApprove`, `checkBalanceForSwap`) exist only in `GetCheckBalance`, which is a separate, config-gated (`ShouldCheckToken`, `ShouldCheckSwapAmount`, `ShouldCheckSenderCode`) hook used for **tx-pool admission/readiness**, not for the bundling/block-building decision path: [4](#0-3) 

Because `LendTx` (a real value transfer) is placed *before* `ApproveTx`/`SwapTx` in the bundle and is generated/signed independently of whether the swap will actually succeed, and because the bundling step re-validates only static calldata consistency (not live balance/allowance), there is a time-of-check-to-time-of-use gap between when the pool admitted the tx (balance was checked, if the config flags were even enabled) and when the block is actually assembled and the bundle executed. If the user's token balance/allowance changes between pool admission and block inclusion (e.g., is drained/revoked by another transaction from the same sender in the same block, or the balance check was disabled via config), `SwapForGas` reverts on execution, but the preceding `LendTx` — which unconditionally paid out KAIA — has already succeeded and is not automatically reversed, since it's a separate, already-signed and gas-paid transaction, not an atomic sub-call of the swap.

## Impact Explanation
A successful exploitation directly drains KAIA from the block proposer (the gasless lender) with no repayment, since the `AmountRepay` is only enforced as part of the `swapForGas` router logic, which never executes/succeeds if the swap reverts. This is concrete unauthorized value movement / gasless settlement theft as called out in the validation criteria, and it is reachable by any unprivileged gasless user issuing ordinary transactions through the public RPC — no privileged role, node compromise, or consensus-message manipulation required.

## Likelihood Explanation
Exploitability depends on the operator's gasless configuration (`ShouldCheckToken`, `ShouldCheckSwapAmount`, `ShouldCheckSenderCode`) and on the attacker's ability to alter their balance/allowance state between pool admission and block inclusion (e.g., via a same-block preceding transaction, or a token contract with balance/allowance behavior that passes calldata-only checks in `VerifyExecutable` but fails the router's real transfer). This makes the likelihood **Medium**: it requires either a lax gasless configuration or a crafted token/timing sequence, but does not require any privileged access — only ordinary transaction submission from a public RPC endpoint.

## Recommendation
- Re-verify on-chain token balance, allowance, and (optionally) sender-code conditions inside `VerifyExecutable`/bundling, not only in the pool-admission `GetCheckBalance` hook, so the block-building decision uses fresh state immediately before bundling.
- Consider making the balance/allowance checks (`ShouldCheckToken`, `ShouldCheckSwapAmount`) mandatory (non-configurable) rather than optional, since disabling them removes the only safeguard against unrepaid lends.
- Explore restructuring the bundle so that `LendTx`'s value transfer is conditioned on the swap succeeding (e.g., via a single atomic contract call) rather than as an independent, unconditionally-successful transaction ahead of the swap.

## Proof of Concept
Conceptual sequence (not fully executable without a live testnet/config, since exact behavior depends on `GaslessConfig` flags which I could not fully trace to a single enforcement point in this session):
1. Attacker submits `GaslessApproveTx` + `GaslessSwapTx` for a whitelisted token/router pair that currently satisfies `VerifyExecutable`'s static checks (token/spender/amount/nonce consistency) and, if enabled, passes the pool's `GetCheckBalance` at admission time.
2. In the same block (or shortly after admission but before this bundle is picked for inclusion), attacker transfers away or revokes the approval/balance of the swap token via another ordinary transaction from the same account, or the operator runs with `ShouldCheckToken`/`ShouldCheckSwapAmount` disabled.
3. `ExtractTxBundles` still bundles `[LendTxGenerator, ApproveTx, SwapTx]` because `VerifyExecutable` at bundling time does not re-check live balance/allowance: [3](#0-2) 
4. The block executes `LendTx`, unconditionally crediting the attacker with `lendAmount` KAIA: [1](#0-0) 
5. `SwapForGas` reverts due to insufficient balance/allowance, so `AmountRepay` is never collected — the proposer's lent KAIA is permanently lost.

**Note on confidence**: I was unable to fully trace, within this session, the exact call site(s) where `GetCheckBalance` is invoked in `blockchain/tx_pool.go` relative to block building/re-validation, so I cannot state with certainty whether there is an additional re-check immediately before inclusion that would close this TOCTOU window. This should be verified against the actual `tx_pool.go`/miner worker code before treating this as a confirmed, unconditional vulnerability.

func (g *GaslessModule) IsExecutable(approveTxOrNil, swapTx *types.Transaction) bool {
	err := g.VerifyExecutable(approveTxOrNil, swapTx)
	if err != nil {
		return false
	}
	return true
}

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}

// MakeLendTx creates a transaction with following properties:
// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)
// L2. LendTx.from = proposer
// L3. LendTx.to = SwapTx.from
// L4. LendTx.value = LendAmount(approveTxOrNil, swapTx)
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}

func (g *GaslessModule) GetCheckBalance() func(tx *types.Transaction) error {
	return func(tx *types.Transaction) error {
		if approveArgs, ok := decodeApproveTx(tx, g.signer); ok {
			return g.checkBalanceForApprove(approveArgs)
		}
		if swapArgs, ok := decodeSwapTx(tx, g.signer); ok {
			return g.checkBalanceForSwap(swapArgs, tx.Nonce())
		}
		return errors.New("not a gasless transaction") // should not happen because IsModuleTx is called before GetCheckBalance
	}
}
