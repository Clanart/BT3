### Title
Data Layer mirror/plugin URLs are fetched via unrestricted outbound HTTP with no destination address validation, enabling SSRF - (File: `chia/data_layer/download_data.py`)

### Summary
Any wallet user can call `add_mirror` to publish an arbitrary list of URLs on-chain for a DataLayer store they own [1](#0-0) . Any other Data Layer client that subscribes to that store will have its local `DataLayer` service fetch delta/full files from those attacker-supplied URLs via `fetch_and_validate()` → `insert_from_delta_file()` → `download_file()` → `http_download()`, with no validation of the destination host (no private/link-local/loopback denylist, no IP-literal normalization checks) before the outbound `aiohttp` request is issued [2](#0-1) [3](#0-2) [4](#0-3) .

### Finding Description
`add_mirror` only checks that the URL list is non-empty; it performs no scheme, host, or IP-range validation and directly submits the URLs to the chain as coin memos for the store's mirror coin [1](#0-0) . When any Data Layer client (including automated infrastructure such as cloud-hosted full-node/DataLayer services) subscribes to that store, `update_subscription()`/`fetch_and_validate()` reads these mirror URLs from wallet state via `get_available_servers_for_store()` and iterates over them to download missing generations [5](#0-4) .

The actual HTTP fetch happens in `http_download()`, which builds the request directly from `server_info.url` and calls `session.get(server_info.url + "/" + filename, ...)` with no check that the resolved host is not loopback, link-local (e.g. `169.254.169.254`), or another internal/private address [4](#0-3) . This mirrors the CVE-2026-89049 bug class: an attacker-controlled destination value bypasses any destination allow/deny logic because none exists here at all — there is no equivalent-representation or private-address check comparable to `chia/util/network.py`'s `is_in_network()`/`is_localhost()` helpers, which are applied to peer connections elsewhere in the codebase (`chia/server/server.py`) [6](#0-5)  but are never used for Data Layer mirror/plugin URLs.

The same unrestricted fetch pattern applies to the plugin-downloader path, which POSTs the raw mirror URL to a locally configured plugin without validating it either [7](#0-6) .

### Impact Explanation
A malicious Data Layer store owner can publish a mirror URL pointing at an internal/link-local service (e.g. a cloud instance metadata endpoint, an internal admin API, or another service on the operator's private network) reachable from the machine running the victim's DataLayer service. Because `http_download()` performs the plain HTTP GET unconditionally, the victim's node becomes an SSRF proxy: it will issue outbound requests to whatever host the attacker specifies, and any content returned is written to a local `.dat` file location and even parsed as a delta/full file [8](#0-7) . On cloud-hosted operators, this could be used to attempt to reach the instance metadata service and exfiltrate the response (limited by the fact the response must round-trip through `is_filename_valid()`/tree-insertion parsing rather than being displayed directly, but the request itself is still made and errors/timing can be observed, and content-length/size and response bytes are processed before validation, so partial data leakage via side channels or crafted "valid-looking" delta content is plausible). This satisfies the required "concrete... transaction-processing" or confidentiality-impacting analog: an unprivileged Data Layer client (store subscriber) triggers unauthorized outbound requests to internal endpoints from another operator's infrastructure.

### Likelihood Explanation
Any user can create a Data Layer store and call `add_mirror` with arbitrary URLs at low cost (only requires the `amount`/`fee` for the mirror coin) [1](#0-0) . Any other participant who subscribes to that store (a normal, expected Data Layer workflow) will have their node automatically fetch from the attacker's URL during the periodic sync loop, with no operator interaction required [9](#0-8) .

### Recommendation
Validate mirror/plugin URLs before performing the outbound fetch in `download_file()`/`http_download()`: resolve the host and reject loopback, link-local, private, and multicast/reserved ranges (reusing logic similar to `chia/util/network.py`'s `is_in_network()`/`is_localhost()`), reject alternate/ambiguous address representations (decimal/octal/hex IPv4, IPv4-mapped IPv6, embedded credentials), and re-validate after any redirect. Consider making this policy configurable but secure-by-default, and apply the same validation to `add_mirror`/`update_subscriptions_from_wallet` so malicious URLs are rejected before being persisted or subscribed to.

### Proof of Concept
1. User A creates a Data Layer store and calls `add_mirror` with `urls=["http://169.254.169.254/latest/meta-data/iam/security-credentials/"]` (or any internal-only host of the target operator's network) [1](#0-0) .
2. User B (running DataLayer on cloud infrastructure) subscribes to User A's store via `add_mirror`/`subscribe` RPC.
3. During the next `periodically_manage_data()` cycle, User B's `fetch_and_validate()` calls `insert_from_delta_file()` → `download_file()` → `http_download()`, which issues `session.get("http://169.254.169.254/latest/meta-data/...")` from User B's node without any destination-address validation [5](#0-4) [4](#0-3) .

Note: I could not fully verify whether any additional filtering exists at the wallet DL puzzle/mirror-creation layer (`chia/wallet/db_wallet/`) since no matches were found there for URL validation, suggesting the check is indeed absent at that layer, but a full audit of `chia/wallet/db_wallet/dl_wallet.py` internals was not completed due to iteration limits.

async def insert_from_delta_file(
    data_store: DataStore,
    store_id: bytes32,
    existing_generation: int,
    target_generation: int,
    root_hashes: list[bytes32],
    server_info: ServerInfo,
    client_foldername: Path,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    group_files_by_store: bool = False,
    maximum_full_file_count: int = 1,
    max_delta_file_size: int = 250,
) -> bool:
    if group_files_by_store:
        client_foldername.joinpath(f"{store_id}").mkdir(parents=True, exist_ok=True)

    delta_reader: DeltaReader | None = None

    for root_hash in root_hashes:
        timestamp = int(time.time())
        existing_generation += 1
        target_filename_path = get_delta_filename_path(
            client_foldername, store_id, root_hash, existing_generation, group_files_by_store
        )
        filename_exists = target_filename_path.exists()
        for grouped_by_store in (False, True):
            success = await download_file(
                data_store=data_store,
                target_filename_path=target_filename_path,
                store_id=store_id,
                root_hash=root_hash,
                generation=existing_generation,
                server_info=server_info,
                proxy_url=proxy_url,
                downloader=downloader,
                timeout=timeout,
                client_foldername=client_foldername,
                timestamp=timestamp,
                log=log,
                grouped_by_store=grouped_by_store,
                group_downloaded_files_by_store=group_files_by_store,
                max_delta_file_size=max_delta_file_size,

        else:
            return False

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
