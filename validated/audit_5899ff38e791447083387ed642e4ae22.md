### Title
OAuth deep-link authorization code/state logged unconditionally on the "unknown URL action" fallback path - (`app/src/ui/dispatcher/dispatcher.ts`)

### Summary
Similar to the reported dApp SDK issue where a raw deeplink URL containing connection parameters is logged unconditionally on an error path, GitHub Desktop's URL-action dispatcher logs the entire parsed action object — including the raw `x-github-client://oauth?...` URL — whenever the OAuth deep link fails to match the expected shape, and it does so via `log.warn`, unconditionally (not gated behind a debug flag).

### Finding Description
`parseAppURL` handles the `oauth` deep-link action by extracting `code` and `state` from the query string. If either value is missing, it falls back to returning an `IUnknownAction` that still carries the **entire raw URL** string, including whatever `code`/`state` values were present in the query string: [1](#0-0) 

That `unknown` action is passed through to `Dispatcher.dispatchURLAction`, whose `default` branch serializes the full action (including the embedded raw URL/query string) with `JSON.stringify` and writes it to the log unconditionally via `log.warn`: [2](#0-1) 

`log.warn` in the renderer is proxied over IPC to the main process and always written to Winston's file transport (persisted to disk), regardless of whether debug/dev mode is enabled: [3](#0-2) [4](#0-3) 

This mirrors the reported bug class exactly: the `logger.error('Failed to handle connect deeplink:', error, url)` unconditional URL logging is analogous to Desktop's unconditional `log.warn` of the raw URL/query on any malformed OAuth callback, and the report's "gate behind debug flag or strip query parameters" recommendation applies identically here since Desktop's persistent file log is not gated by a debug flag for `warn`/`error` levels.

A related, simpler-to-trigger instance exists in the Windows protocol-launcher argument handling, where any string starting with a known protocol prefix that fails `new URL()` parsing is logged verbatim at `error` level, unconditionally, to the same persistent log: [5](#0-4) 

### Impact Explanation
An OAuth `code` is a short-lived, single-use authorization code that can be exchanged for an access token. If an attacker can induce this fallback path (e.g., a crafted deep link with a `code` param but no/invalid `state`, or non-ASCII/invalid characters that still preserve a readable `code=` fragment), the code ends up in Desktop's on-disk log file. Anyone with access to those logs (crash-report bundles, "Show Logs" support flows, log aggregation, or another local process during the code's validity window) could attempt to complete the OAuth exchange before the legitimate flow does, potentially leading to unauthorized account binding — one of the explicitly valid impact categories in this task (unauthorized OAuth/account binding via an attacker-controlled deep link).

### Likelihood Explanation
The trigger requires an attacker-controlled `x-github-client://oauth?...` deep link that the victim clicks — no local access, malware, or leaked credentials are needed, which fits the valid-impact criteria (a link/deep link the user clicks). The exact malformed-parameter condition needed to hit the `unknown` fallback (state missing/invalid while code is present) is a narrow but reachable input via `parseAppURL`'s query parsing, and the log call itself has no gating logic — the only variable is precisely triggering this particular parse branch versus the fully-valid `oauth` branch, so likelihood is moderate rather than certain.

### Recommendation
- In `parseAppURL`, when falling back to `IUnknownAction` for a hostname of `oauth`, strip or redact query string parameters (`code`, `state`) from the `url` field before returning.
- In `Dispatcher.dispatchURLAction`'s `default` branch, avoid `JSON.stringify(unknownAction)` for actions whose `name`/hostname indicates `oauth`; log only the action name, not the payload.
- Apply the same query-stripping to the Windows protocol-launcher `log.error(\`Unable to parse argument as URL: ${arg}\`)` call in `main.ts`.

### Proof of Concept
1. Register/observe the app handles `x-github-client://` deep links (see protocol registration in `app/src/main-process/main.ts`).
2. Craft a link such as `x-github-client://oauth?code=<victim_auth_code>&state=` (empty/missing `state`) and have the victim click it, or deliver it via `open-url`/CLI argument handling.
3. `parseAppURL` returns `{ name: 'unknown', url: 'x-github-client://oauth?code=<victim_auth_code>&state=' }` per `app/src/lib/parse-app-url.ts` lines 77-85.
4. `dispatchURLAction`'s default branch logs `Unknown URL action: unknown - payload: {"name":"unknown","url":"x-github-client://oauth?code=<victim_auth_code>&state="}` via `log.warn`, which is written to the persistent Winston log file unconditionally.
5. Inspect Desktop's log directory (or any crash/log-collection artifact) to recover the leaked `code`. [6](#0-5) [7](#0-6)

export function parseAppURL(url: string): URLActionType {
  const parsedURL = URL.parse(url, true)
  const hostname = parsedURL.hostname
  const unknown: IUnknownAction = { name: 'unknown', url }
  if (!hostname) {
    return unknown
  }

  const query = parsedURL.query

  const actionName = hostname.toLowerCase()
  if (actionName === 'oauth') {
    const code = getQueryStringValue(query, 'code')
    const state = getQueryStringValue(query, 'state')
    if (code != null && state != null) {
      return { name: 'oauth', code, state }
    } else {
      return unknown
    }
  }
