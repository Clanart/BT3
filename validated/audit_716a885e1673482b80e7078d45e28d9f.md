### Title
Unauthenticated classification of outputs by script_pubkey lets any sender forge Branch/Change/Forwarded output kinds - (File: processor/src/networks/bitcoin.rs)

### Summary
The GitLab CVE-2017-0920 bug class is an authorization bypass: an endpoint returns data it should only expose after an access check. In Serai, `Bitcoin::get_outputs` classifies every on-chain output solely by whether its `script_pubkey` matches one of the scanner's registered offset scripts (`External`, `Branch`, `Change`, `Forwarded`). There is no authorization step verifying that a `Branch`/`Change`/`Forwarded` output was actually produced by the multisig's own spending flow — any unprivileged party can craft a transaction paying directly to those well-known, publicly derivable script_pubkeys and have the processor treat the output as an internal kind it was never authorized to create.

### Finding Description
`scanner()` derives four fixed offset scalars (`ZERO`, `hash_to_F(KEY_DST, "branch")`, `"change"`, `"forward"`) and registers their tweaked P2TR scripts [1](#0-0) . `Scanner::scan_transaction` matches only `output.script_pubkey` against the registered scripts, returning a `ReceivedOutput` carrying the associated offset [2](#0-1) . `get_outputs` then looks up `kinds[offset_repr]` and stamps that `OutputType` on the emitted `Output`, unconditionally trusting the script match [3](#0-2) . The offsets are deterministic and publicly computable (`KEY_DST` and the labels are constants), so the Branch/Change/Forwarded addresses are public knowledge. Nothing binds a `Change` output to a transaction the multisig itself authored, nor a `Branch`/`Forwarded` output to the intended deposit flow — the only "authorization" is the script match, which anyone can satisfy.

### Impact Explanation
An attacker sends a normal Bitcoin transaction paying the Branch, Change, or Forwarded script_pubkey directly. The scanner reports a `ReceivedOutput` whose `offset` maps to that internal `OutputType`, and the processor emits an `Output` of kind `Change`/`Forwarded`/`Branch` even though the multisig never created it. Downstream accounting treats attacker-injected outputs as internal outputs (e.g., forwarded deposits or change belonging to the protocol), causing funds to be reported/credited under a classification the sender was not entitled to claim — an authorization bypass on output attribution. It can also poison `presumed_origin`/data handling since `External`-only data population is skipped for forged non-External kinds [4](#0-3) .

### Likelihood Explanation
Reachable by any unprivileged party with a public input explicitly permitted by scope: "Bitcoin transactions they send." The attacker only needs to compute `key + G*offset` for the constant offsets (`Secp256k1::hash_to_F("Serai Bitcoin Output Offset", "branch"/"change"/"forward")`), build the P2TR address, and broadcast a payment to it. The group `key` is public. No collusion, malicious validator, or key material is needed — just funds to send and one confirmed transaction.

### Recommendation
Authorize output kinds before emitting them: only accept `Change`/`Branch` outputs when they appear in a transaction the multisig itself signed (e.g., check the tx spends known multisig inputs or matches a pending SignableTransaction), and treat unexpected payments to internal script_pubkeys as `External` deposits or discard them. Alternatively, use per-purpose randomized offsets rather than global constants so internal addresses aren't publicly derivable.

const KEY_DST: &[u8] = b"Serai Bitcoin Output Offset";
static BRANCH_OFFSET: OnceLock<Scalar> = OnceLock::new();
static CHANGE_OFFSET: OnceLock<Scalar> = OnceLock::new();
static FORWARD_OFFSET: OnceLock<Scalar> = OnceLock::new();

// Always construct the full scanner in order to ensure there's no collisions
fn scanner(
  key: ProjectivePoint,
) -> (Scanner, HashMap<OutputType, Scalar>, HashMap<Vec<u8>, OutputType>) {
  let mut scanner = Scanner::new(key).unwrap();
  let mut offsets = HashMap::from([(OutputType::External, Scalar::ZERO)]);

  let zero = Scalar::ZERO.to_repr();
  let zero_ref: &[u8] = zero.as_ref();
  let mut kinds = HashMap::from([(zero_ref.to_vec(), OutputType::External)]);

  let mut register = |kind, offset| {
    let offset = scanner.register_offset(offset).expect("offset collision");
    offsets.insert(kind, offset);

    let offset = offset.to_repr();
    let offset_ref: &[u8] = offset.as_ref();
    kinds.insert(offset_ref.to_vec(), kind);
  };

  register(
    OutputType::Branch,
    *BRANCH_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"branch")),
  );
  register(
    OutputType::Change,
    *CHANGE_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"change")),
  );
  register(
    OutputType::Forwarded,
    *FORWARD_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"forward")),
  );

  (scanner, offsets, kinds)

  async fn get_outputs(&self, block: &Self::Block, key: ProjectivePoint) -> Vec<Output> {
    let (scanner, _, kinds) = scanner(key);

    let mut outputs = vec![];
    // Skip the coinbase transaction which is burdened by maturity
    for tx in &block.txdata[1 ..] {
      for output in scanner.scan_transaction(tx) {
        let offset_repr = output.offset().to_repr();
        let offset_repr_ref: &[u8] = offset_repr.as_ref();
        let kind = kinds[offset_repr_ref];

        let output = Output { kind, presumed_origin: None, output, data: vec![] };
        assert_eq!(output.tx_id(), tx.id());
        outputs.push(output);
      }

      if outputs.is_empty() {
        continue;
      }

      // populate the outputs with the origin and data
      let presumed_origin = {
        // This may identify the P2WSH output *embedding the InInstruction* as the origin, which
        // would be a bit trickier to spend that a traditional output...
        // There's no risk of the InInstruction going missing as it'd already be on-chain though
        // We *could* parse out the script *without the InInstruction prefix* and declare that the
        // origin
        // TODO
        let spent_output = {
          let input = &tx.input[0];
          let mut spent_tx = input.previous_output.txid.as_raw_hash().to_byte_array();
          spent_tx.reverse();
          let mut tx;
          while {
            tx = self.rpc.get_transaction(&spent_tx).await;
            tx.is_err()
          } {
            log::error!("couldn't get transaction from bitcoin node: {tx:?}");
            sleep(Duration::from_secs(5)).await;
          }
          tx.unwrap().output.swap_remove(usize::try_from(input.previous_output.vout).unwrap())
        };
        Address::new(spent_output.script_pubkey)
      };
      let data = Self::extract_serai_data(tx);
      for output in &mut outputs {
        if output.kind == OutputType::External {
          output.data.clone_from(&data);
        }
        output.presumed_origin.clone_from(&presumed_origin);
      }
    }

    outputs
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
