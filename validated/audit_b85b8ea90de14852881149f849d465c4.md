### Title
Payout OP_RETURN operator-attribution output is not covered by the mandatory `SinglePlusAnyoneCanPay` sighash, letting anyone reassign a confirmed payout's credited operator - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary
`create_payout_txhandler` places the user's payout output at index 0 and the operator-attribution OP_RETURN at index 2, but the only signature enforced on the withdrawal input is `TapSighashType::SinglePlusAnyoneCanPay`, which (per BIP-341/342) commits only to the input being signed and the output at the *same* index (index 0). The OP_RETURN output and any fee-funding inputs/outputs are therefore unauthenticated by the user's signature, so anyone who observes a broadcast-but-unconfirmed payout tx in the mempool can rebuild a competing transaction with the identical signed input/output-0 but a different OP_RETURN operator key and their own fee inputs, and win the confirmation race. `update_finalized_payouts` blindly trusts whatever OP_RETURN ends up in the transaction that actually spends the withdrawal UTXO on-chain, so the wrong operator gets credited in the DB and subsequently reimbursed via `PayoutCheckerTask`/`handle_finalized_payout`.

### Finding Description
Binding claimed and broken: `payout_payer_operator_xonly_pk` stored for withdrawal `j` (the value read by `get_first_unhandled_payout_by_operator_xonly_pk`) == the operator that actually fronted/funded withdrawal `j`'s payout (paid the withdrawal amount out of pocket). This binding is broken.

Root cause / path:
1. `create_payout_txhandler` builds the payout tx: input 0 = user's withdrawal UTXO (key-path spend), output 0 = user payout (committed), output 1 = anchor, output 2 = OP_RETURN carrying the operator's x-only pubkey that is supposed to identify who fronted the payout. [1](#0-0) 
2. The user's signature sighash type is force-normalized/enforced to `SinglePlusAnyoneCanPay`. [2](#0-1) 
3. `Operator::withdraw` verifies that signature against `sighash` computed over input 0 with that sighash type. [3](#0-2) 

`SIGHASH_SINGLE` only commits to the output at the same index as the signed input (index 0 here); `ANYONECANPAY` means no other inputs are committed either. Consequently outputs 1 (anchor) and 2 (OP_RETURN operator-attribution) — and any additional fee-funding inputs the front-running operator's wallet adds — are entirely outside what the signature authenticates. Once operator B broadcasts B's payout tx for withdrawal `j` to the Bitcoin network (a public, unprivileged-observable event, matching the attacker capability "broadcast Bitcoin transactions and pay fees"), an attacker can:
- lift the still-valid witness for input 0 and output 0 from B's mempool transaction,
- drop B's own fee-funding inputs (which the attacker cannot reuse anyway, but does not need to),
- add attacker-funded fee inputs/outputs,
- replace output 2's OP_RETURN payload with operator A's x-only pubkey instead of B's,
- broadcast this malleated transaction with a higher fee to win the confirmation race against B's original transaction.

When this malleated transaction confirms, `update_finalized_payouts` extracts the OP_RETURN from whichever transaction actually spends the tracked withdrawal UTXO in the confirmed block — it has no way to know which operator actually funded it, it only reads the bytes present on-chain — and stores `operator_xonly_pk = A` for withdrawal `j`. [4](#0-3) 

From here, `get_first_unhandled_payout_by_operator_xonly_pk(A)` (ordered `ASC LIMIT 1`) will surface withdrawal `j` for A once `i` is processed, since the WHERE clause filters strictly on the DB-stored `payout_payer_operator_xonly_pk`. [5](#0-4) 
`PayoutCheckerTask::run_once` running on A's node will then call `handle_finalized_payout` and `mark_payout_handled(j, ...)` for A, unconditionally trusting the DB attribution. [6](#0-5) 

Existing guard `is_kickoff_malicious` does not catch this: it only checks that the OP_RETURN-stored `operator_xonly_pk` matches the kickoff's claimed operator — since the OP_RETURN was already malleated to A, this check now trivially passes for A's kickoff. [7](#0-6) 
No code anywhere verifies that the fee-payer/broadcaster of the confirmed payout tx corresponds to the OP_RETURN pubkey; the OP_RETURN is treated as ground truth both in the verifier DB sync and in the bridge circuit (`bridge_circuit`/`host_deposit_constant`), which likewise parse the first OP_RETURN output to compute `deposit_constant` without any funding-source check. [8](#0-7) 
`is_payout_handled` is a one-shot boolean per withdrawal `idx`, so once falsely marked TRUE for A, B can never be credited for `j`. [9](#0-8) 

### Impact Explanation
A is reimbursed (via kickoff → Reimburse tx path triggered by `handle_finalized_payout`) for a withdrawal it never funded, extracting bridge value it did not front. B, who genuinely paid the user out of pocket, has `is_payout_handled` permanently TRUE for `j` and can never be reimbursed for that payout — a permanent, non-reversible loss of B's fronted principal. This is repeatable per withdrawal and independent of deposit content; the only requirement is winning one confirmation race on Bitcoin, which any unprivileged party with sufficient fee budget can attempt. This matches the "Critical" category: an operator reimbursed for a payout it never funded, and an honest operator permanently unable to be reimbursed.

### Likelihood Explanation
Preconditions: two honest operators A and B each genuinely front different withdrawals (i for A, j for B); the attacker only needs to observe B's payout tx in the mempool before it confirms and outbid it with a replacement carrying a different OP_RETURN. This requires no privileged role — only the ability to broadcast Bitcoin transactions and pay a competitive fee, both explicitly within the attacker's allowed capabilities. Cost is bounded by the fee delta needed to outbid B's transaction (attacker does not need to match the full withdrawal amount, only the fee). This is feasible on any network where transaction relay/replacement is possible (default mempool policies, RBF or first-seen relay races), and it is repeatable for every withdrawal an operator fronts.

### Recommendation
Bind the OP_RETURN operator-attribution output (and ideally the fee-input(s)/anchor) into the signed message. Concretely, either: (a) change the enforced sighash to a type/commitment scheme that covers all outputs (e.g., use `SIGHASH_ALL` semantics for a fixed-output template, or use a Taproot script path with a pre-committed full transaction template signed by aggregator-approved presigned data rather than a raw keypath signature over one output), or (b) have verifiers cross-check that the same operator whose xonly pk appears in the OP_RETURN also supplied/signed the transaction's fee-paying inputs (e.g., require the operator to also produce a signature over the entire payout transaction, including OP_RETURN and funding inputs, that verifiers check before accepting the DB attribution during Citrea/Bitcoin sync). At minimum, do not treat the on-chain OP_RETURN as authoritative for crediting reimbursement without an operator-specific commitment that cannot be malleated by third parties.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }

    async fn run_once(&mut self) -> Result<Self::Output, BridgeError> {
        let mut dbtx = self.db.begin_transaction().await?;
        let unhandled_payout = self
            .db
            .get_first_unhandled_payout_by_operator_xonly_pk(
                Some(&mut dbtx),
                self.operator.signer.xonly_public_key,
            )
            .await?;

        if unhandled_payout.is_none() {
            return Ok(false);
        }

        let (citrea_idx, move_to_vault_txid, payout_tx_blockhash) =
            unhandled_payout.expect("Must be Some");

        tracing::info!(
            "Unhandled payout found for withdrawal {}, move_txid: {}",
            citrea_idx,
            move_to_vault_txid
        );

        let deposit_data = self
            .db
            .get_deposit_data_with_move_tx(Some(&mut dbtx), move_to_vault_txid)
            .await?;
        if deposit_data.is_none() {
            return Err(eyre::eyre!("Fronted withdrawal for move tx {move_to_vault_txid} found, but the signatures for the deposit are not found in the db.").into());
        }

        let deposit_data = deposit_data.expect("Must be Some");

        let kickoff_txid = self
            .operator
            .handle_finalized_payout(
                &mut dbtx,
                deposit_data.get_deposit_outpoint(),
                payout_tx_blockhash,
            )
            .await?;

        // fetch and save the LCP for if we get challenged and need to provide proof of payout later
        let (_, payout_block_height) = self
            .operator
            .db
            .get_block_info_from_hash(Some(&mut dbtx), payout_tx_blockhash)
            .await?
            .ok_or_eyre("Couldn't find payout blockhash in bitcoin sync")?;

        let _ = self
            .operator
            .citrea_client
            .fetch_validate_and_store_lcp(
                payout_block_height as u64,
                citrea_idx,
                &self.operator.db,
                Some(&mut dbtx),
                self.operator.config.protocol_paramset(),
            )
            .await?;

        #[cfg(feature = "automation")]
        self.operator.end_round(&mut dbtx).await?;

        self.db
            .mark_payout_handled(Some(&mut dbtx), citrea_idx, kickoff_txid)
            .await?;

        dbtx.commit().await?;

        Ok(true)
    }
