### Title
Permissionless zero-cost purchases can evict a victim app's paid bandwidth via FIFO-cap eviction - (File: `modules/pallets/bandwidth/src/lib.rs`)

### Summary
`pallet-bandwidth`'s `on_accept` (the ISMP message handler for `BandwidthManager.purchase()` calls) never validates that `PurchaseMessage.months` is greater than zero before computing the credited size and duration, and `push_subscription` unconditionally appends the resulting subscription to a capped (1024-entry) FIFO list, evicting the oldest entry when full. Because `purchase()` is a public, permissionless entry point on the EVM `BandwidthManager` contract, any caller can submit purchases with `months = 0` (or with the cheapest configured tier) at negligible or zero cost, repeatedly pushing worthless (already-expired) subscriptions that silently evict real, already-paid-for allowance entries belonging to any `(app_chain, app)` pair.

### Finding Description
`on_accept` computes the credited size and duration directly from attacker-controlled `msg.months` with no lower bound check: [1](#0-0) 

```rust
let msg = PurchaseMessage::try_from(request.body.as_slice())?;
let tier = TierIndex::try_from(msg.tier)...;
let cfg = Tiers::<T>::get(tier)...;
let bytes = cfg.bytes.saturating_mul(msg.months as u128);
let duration = cfg.duration_secs.saturating_mul(msg.months as u64);
let key = AppKey::truncate_from(msg.app);
let expires_at = Self::push_subscription(&msg.chain, &key, tier, bytes, duration);
```

If `msg.months == 0`, `bytes == 0` and `duration == 0`, so `expires_at == now` — the subscription is dead on arrival. `push_subscription` still consumes a FIFO slot and, once the list is at its `MAX_SUBSCRIPTIONS` (1024) cap, evicts the oldest live entry regardless of how much real, unspent bandwidth it holds: [2](#0-1) 

The only gate on who can trigger `on_accept` is that `request.from` must equal the registered `BandwidthManager` address for `request.source` — this is a check on *which contract* relayed the message, not on *who called* `purchase()` on that contract: [3](#0-2) 

Per the documented flow, `purchase()` on `BandwidthManager.sol` is a public function callable by any buyer, and the fee dispatched with the resulting ISMP POST is `0` (no protocol fee) — the pallet's own accounting places no floor on how small a "purchase" can be: [4](#0-3) 

Because `Allowance` is keyed by `(app_chain, app)` taken from the purchase body — not by the caller's identity — anyone who knows a victim's `(app_chain, app)` pair (public information, since it's emitted in `BandwidthCredited`) can target that queue specifically.

### Impact Explanation
This breaks the bandwidth-accounting invariant that a paid-for allowance is only consumed by legitimate gate usage or natural expiry ("what you paid for is yours only until it expires" — per the module's own doc comment). An attacker can force premature eviction of another app's legitimately purchased, unexpired bandwidth by flooding the FIFO list with worthless zero-byte purchases, causing `SubscriptionEvicted` to fire for real paid entries. This is a direct loss-of-funds condition for the victim app (paid bandwidth destroyed before use) and can also be used to grief/DoS an app's message dispatch by exhausting its allowance, since `BandwidthGate::try_consume` will subsequently reject the app's real ISMP dispatches with `Insufficient`/`NoAllowance`.

### Likelihood Explanation
The attack requires no special privileges, no relayer/prover/admin collusion, and no proof forgery — only the ability to call the public `purchase()` function on the registered `BandwidthManager` contract with `months = 0` (or the cheapest available tier), and knowledge of the victim's public `(app_chain, app)` identifiers. Filling a 1024-entry FIFO queue is a bounded, cheap, and repeatable on-chain action (limited only by gas/relayer delivery of ISMP messages), making this practically exploitable by any unprivileged actor.

### Recommendation
- In `on_accept`, reject purchases where `msg.months == 0` (or where computed `bytes == 0` / `duration == 0`) before calling `push_subscription`.
- Consider evicting only expired entries first, and rejecting/queuing further pushes (rather than evicting live, unexpired entries) when the FIFO list is full of still-valid subscriptions.
- Consider requiring `BandwidthManager.sol` to enforce `months >= 1` and a non-zero payment at the source, so a zero-cost purchase message can never be constructed.

### Proof of Concept
1. Governance registers a `BandwidthManager` for chain `C` and configures at least one tier via `set_tier`.
2. Victim buys legitimate bandwidth: `BandwidthManager.purchase(app=V, tier, months=12)` → pallet's `on_accept` pushes a real `Subscription` onto `Allowance[(app_chain, V)]`.
3. Attacker (any account, no special role) repeatedly calls `BandwidthManager.purchase(app=V, tier, months=0)` (or the cheapest tier with `months=1`) 1024+ times.
4. Each call reaches `on_accept` → `push_subscription` appends a `bytes=0, duration=0` (or minimal) entry; once the list hits `MAX_SUBSCRIPTIONS`, the oldest entry — which may be the victim's real, unexpired, high-value subscription from step 2 — is evicted and `SubscriptionEvicted { lost_bytes: <victim's real bytes> }` is emitted.
5. Victim's subsequent ISMP dispatches through `BandwidthGate::try_consume` now fail with `Insufficient`/`NoAllowance` despite having legitimately paid for bandwidth that had not yet expired or been consumed. [5](#0-4)

		fn push_subscription(
			app_chain: &StateMachine,
			app: &AppKey,
			tier: TierIndex,
			bytes: BandwidthBytes,
			duration_secs: u64,
		) -> u64 {
			let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();
			let expires_at = now.saturating_add(duration_secs);
			let new_sub =
				Subscription { tier, remaining_bytes: bytes, expires_at, purchased_at: now };

			let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
				let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
					Some(list.remove(0))
				} else {
					None
				};
				// Capacity is now guaranteed; try_push can't fail.
				let _ = list.try_push(new_sub);
				evicted
			});

			if let Some(old) = evicted {
				Self::deposit_event(Event::SubscriptionEvicted {
					app_chain: *app_chain,
					app: app.clone(),
					tier: old.tier,
					lost_bytes: old.remaining_bytes,
				});
			}

			expires_at
		}

impl<T: Config> BandwidthGate for Pallet<T> {
	fn try_consume(
		source: &ismp::host::StateMachine,
		app: &[u8],
		bytes: u32,
	) -> Result<(), GateError> {
		let key = AppKey::truncate_from(app.to_vec());
		if Allowlist::<T>::contains_key(source, &key) {
			return Ok(());
		}

		let need: u128 = bytes.into();
		let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();

		let total = pallet::Allowance::<T>::mutate(source, &key, |list| {
			// Sweep expired in-place. Order-preserving.
			list.retain(|s| s.expires_at > now);

			if list.is_empty() {
				return Err(GateError::NoAllowance);
			}

			let total: u128 = list.iter().map(|s| s.remaining_bytes).sum();
			if total < need {
				return Err(GateError::Insufficient { remaining: total, required: need });
			}

			// Drain from the front in insertion order. Once a sub is
			// fully consumed, pop it and continue with the next.
			// `get_mut` defends against a malformed list that satisfies
			// the `total >= need` precheck but is structurally empty;
			// we'd otherwise panic via `list[0]`.
			let mut left = need;
			while left > 0 {
				let Some(head) = list.get_mut(0) else {
					return Err(GateError::NoAllowance);
				};
				let take = head.remaining_bytes.min(left);
				head.remaining_bytes = head.remaining_bytes.saturating_sub(take);
				left = left.saturating_sub(take);
				if head.remaining_bytes == 0 {
					list.remove(0);
				}
			}

			Ok(total)
		})?;
