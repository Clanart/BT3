### Title
Whitespace-sensitive custom YAML parser silently downgrades `action: block` rules to `action: warn`, breaking the deny-means-deny invariant - ([File: plugins/hookify/core/config_loader.py])

### Summary
The hand-rolled frontmatter parser in `extract_frontmatter` (`plugins/hookify/core/config_loader.py`) only recognizes a top-level `key: value` line when its indentation is exactly `0`, and only recognizes a "dict continuation" line when indentation is `> 2` and an `in_dict_item` state is active. Any `action: block` line that falls in the gap (indent 1–2, a stray leading space/tab, or nested under a preceding list item's continuation state) is silently dropped instead of raising an error, causing `Rule.from_dict` to fall back to its default `action = "warn"`.

### Finding Description
`extract_frontmatter` (`plugins/hookify/core/config_loader.py:87-195`) implements a line-based, indentation-driven parser instead of using a real YAML library:
- Top-level key/value detection requires `indent == 0` (`config_loader.py:125`).
- List-item continuation requires `indent > 2 and in_dict_item` (`config_loader.py:184-187`).
- There is no `else` branch — lines that don't match indent `0`, a list-item start, or the `>2` continuation window are silently ignored with no warning or exception.

A rule author intending strict enforcement writes a frontmatter block ending in `action: block`. If that line, or a preceding `conditions:` list block, has an off-by-one indentation (e.g. a single leading space, indent `1` or `2`, or a tab that visually looks like alignment but isn't caught by the `indent > 2` continuation check nor the `indent == 0` top-level check), the line matches none of the parser's branches and is dropped entirely. Because `Rule.from_dict` reads `action=frontmatter.get('action', 'warn')` (`config_loader.py:81`), the missing key silently resolves to `"warn"` rather than raising a parse error.

Alternatively, if the misindented `action: block` line falls inside the `indent > 2 and in_dict_item` window while a list (e.g. `conditions:`) is still open, it gets absorbed into `current_dict` as a spurious field of the last list item instead of being registered as the rule's top-level `action` (`config_loader.py:183-187`), again leaving `frontmatter['action']` unset and defaulting to `"warn"`.

This is loaded via `load_rules`/`load_rule_file` (`config_loader.py:198-274`) and consumed by `stop.py`, which calls `RuleEngine.evaluate_rules` (`plugins/hookify/core/rule_engine.py:53-58`), where `rule.action == 'block'` gates whether the Stop hook returns `{"decision": "block", ...}` versus a non-blocking `systemMessage`. Any rule silently downgraded to `warn` will never populate `blocking_rules`, so the operation proceeds with only a cosmetic warning message instead of being denied.

Because the parser fails open (silently drops unmatched lines rather than raising), a committed rule file can visually contain the literal text `action: block` yet have zero enforcement effect, with no error surfaced during `load_rule_file` — unlike genuine parse errors, which are caught and logged (`config_loader.py:266-274`). This divergence is asymmetric: default is always `"warn"`, so the bug can only ever silently weaken a `block` rule into a `warn`, never the reverse, directly matching the "deny means deny" violation described.

### Impact Explanation
A hookify rule file that is supposed to block dangerous Bash commands, file edits, or agent stop conditions (per the rule author's stated intent, "action: block") can be rendered non-blocking purely by whitespace, with no error or warning emitted. This defeats the enforcement guarantee the Stop hook is meant to provide, since `RuleEngine.evaluate_rules` (`rule_engine.py:60-71`) only blocks when `rule.action == 'block'`; a silently-warn-only rule allows disallowed transcripts/commands to proceed while giving the illusion of enforcement to anyone reading the frontmatter. This corresponds to a security-control/enforcement-bypass bug in a bounty program's plugin/hook trust-boundary category — a supposed deny-rule silently becomes a no-op guard.

### Likelihood Explanation
This requires only committing/PR-ing a `.claude/hookify.*.local.md` file with certain indentation (a single stray space/tab before `action:`, or `action:` nested at an unexpected depth under a `conditions:` list) — an action available to any unprivileged contributor able to add files to the repository. No special permissions, secrets, or social engineering are needed beyond normal repo content contribution, and the bug is 100% deterministic given the indentation pattern (not a race or timing issue), making it trivially reproducible.

### Recommendation
Replace the custom indentation-based parser with a real YAML parser (e.g., `yaml.safe_load`) for frontmatter parsing, or, at minimum, add strict validation: raise a fatal parse error (not a silent skip) for any line that doesn't match a recognized indentation level, and validate after parsing that `action` is one of the exact allowed literals (`"block"`/`"warn"`) sourced only from a top-level key — never inferred by default when a nested/malformed line is present. Also add a post-parse invariant check comparing the raw frontmatter text against a regex scan for `action:` to detect and hard-fail when the parsed dict disagrees with a plain-text presence check.

```python
from hookify.core.config_loader import extract_frontmatter, Rule

def test_misindented_block_action_is_dropped():
    content = """---
name: dangerous-block
enabled: true
event: bash
conditions:
  - field: command
    operator: regex_match
    pattern: "rm -rf"
 action: block
---
body
"""
    fm, _ = extract_frontmatter(content)
    ref = yaml.safe_load(content.split('---')[1])

    # Reference YAML parser correctly captures action: block
    assert ref.get('action') == 'block'

    # Custom parser silently drops it -> defaults to 'warn'
    rule = Rule.from_dict(fm, "")
    assert fm.get('action') != ref.get('action'), \
        "Divergence: custom parser dropped 'action: block' present in source"
    assert rule.action == 'warn'  # deny-means-deny invariant violated
```

```python
def extract_frontmatter(content: str) -> tuple[Dict[str, Any], str]:
    """Extract YAML frontmatter and message body from markdown.

    Returns (frontmatter_dict, message_body).

    Supports multi-line dictionary items in lists by preserving indentation.
    """
    if not content.startswith('---'):
        return {}, content

    # Split on --- markers
    parts = content.split('---', 2)
    if len(parts) < 3:
        return {}, content

    frontmatter_text = parts[1]
    message = parts[2].strip()

    # Simple YAML parser that handles indented list items
    frontmatter = {}
    lines = frontmatter_text.split('\n')

    current_key = None
    current_list = []
    current_dict = {}
    in_list = False
    in_dict_item = False

    for line in lines:
        # Skip empty lines and comments
        stripped = line.strip()
        if not stripped or stripped.startswith('#'):
            continue

        # Check indentation level
        indent = len(line) - len(line.lstrip())

        # Top-level key (no indentation or minimal)
        if indent == 0 and ':' in line and not line.strip().startswith('-'):
            # Save previous list/dict if any
            if in_list and current_key:
                if in_dict_item and current_dict:
                    current_list.append(current_dict)
                    current_dict = {}
                frontmatter[current_key] = current_list
                in_list = False
                in_dict_item = False
                current_list = []

            key, value = line.split(':', 1)
            key = key.strip()
            value = value.strip()

            if not value:
                # Empty value - list or nested structure follows
                current_key = key
                in_list = True
                current_list = []
            else:
                # Simple key-value pair
                value = value.strip('"').strip("'")
                if value.lower() == 'true':
                    value = True
                elif value.lower() == 'false':
                    value = False
                frontmatter[key] = value

        # List item (starts with -)
        elif stripped.startswith('-') and in_list:
            # Save previous dict item if any
            if in_dict_item and current_dict:
                current_list.append(current_dict)
                current_dict = {}

            item_text = stripped[1:].strip()

            # Check if this is an inline dict (key: value on same line)
            if ':' in item_text and ',' in item_text:
                # Inline comma-separated dict: "- field: command, operator: regex_match"
                item_dict = {}
                for part in item_text.split(','):
                    if ':' in part:
                        k, v = part.split(':', 1)
                        item_dict[k.strip()] = v.strip().strip('"').strip("'")
                current_list.append(item_dict)
                in_dict_item = False
            elif ':' in item_text:
                # Start of multi-line dict item: "- field: command"
                in_dict_item = True
                k, v = item_text.split(':', 1)
                current_dict = {k.strip(): v.strip().strip('"').strip("'")}
            else:
                # Simple list item
                current_list.append(item_text.strip('"').strip("'"))
                in_dict_item = False

        # Continuation of dict item (indented under list item)
        elif indent > 2 and in_dict_item and ':' in line:
            # This is a field of the current dict item
            k, v = stripped.split(':', 1)
            current_dict[k.strip()] = v.strip().strip('"').strip("'")

    # Save final list/dict if any
    if in_list and current_key:
        if in_dict_item and current_dict:
            current_list.append(current_dict)
        frontmatter[current_key] = current_list

    return frontmatter, message
```
