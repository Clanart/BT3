## Analog Found: Path-Prefix Bypass in `resolveWithin` Allows Repo-Boundary Escape

### Title
Sibling-directory prefix bypass in `resolveWithin()` allows reading files outside repository via crafted symlink - (File: `app/src/lib/path.ts`)

### Summary
The Solidity bug reduces to a broken invariant in a boundary/guard calculation: a comparison that was supposed to strictly bound a value instead lets out-of-range values pass. GitHub Desktop has a structurally identical class of bug in its repo-boundary containment check: `_resolveWithin()` verifies that a resolved path stays inside the repository root using `realResolved.startsWith(realRoot)` with no trailing path-separator normalization. [1](#0-0) 

### Finding Description
`resolveWithin()` is documented as guaranteeing the resolved path "reside[s] at, or underneath" `rootPath`, explicitly used as a defense against path traversal and symlink escapes. [2](#0-1) 

The actual containment check is a plain string prefix test on the `realpath`-resolved paths:
```ts
const realRoot = await realpath(normalizedRoot)
const realResolved = await realpath(resolved)
return realResolved.startsWith(realRoot) ? resolved : null
``` [3](#0-2) 

`String.prototype.startsWith` has no notion of path segments. If the repository lives at `/Users/foo/repo` and a symlink inside the repository (fully attacker-controlled, since it ships in the cloned/fetched repository content) resolves via `realpath` to a sibling directory such as `/Users/foo/repo-secrets/token.txt`, the check `"/Users/foo/repo-secrets/token.txt".startsWith("/Users/foo/repo")` evaluates to `true` even though that path is **not** nested under the repository root — it is a completely separate directory that merely shares a string prefix. The missing separator check (`realResolved === realRoot || realResolved.startsWith(realRoot + Path.sep)`) is exactly the kind of "wrong comparator" defect described in the seed report: the guard was meant to bound the value strictly inside a range but instead accepts values just outside it.

This primitive is exercised by `buildConflictContext`, which resolves conflicted-file paths (as reported by `git status`, which in turn can name symlinks that are part of the attacker-supplied repository) and then reads their contents to send to the Copilot conflict-resolution model: [4](#0-3) 

### Impact Explanation
An attacker who supplies a repository (via clone, fetch, or a shared branch that a victim merges/rebases) can plant a symlink whose target `realpath`-resolves to a sibling directory that shares the repository root's path prefix (e.g. a directory the user created alongside their repos, such as `~/projects/my-project` vs. a crafted repo at `~/projects/my-project-evil`, or more reliably by having the victim clone into a directory whose name is a prefix of another sensitive sibling path on disk). Content from outside the intended repository boundary can then be read and exfiltrated by being sent to the AI Copilot backend as part of conflict-resolution context — a file read outside the repository, and potential exfiltration of sensitive sibling-directory content to a third-party (Copilot) endpoint, which matches the "file read outside the repo" / "credential exfiltration" categories.

### Likelihood Explanation
Exploitability depends on directory-naming coincidences (one path being a literal string prefix of the other) which is not always attacker-controllable, since the victim chooses the root repo path on their own filesystem. This makes the primitive real but situational rather than reliably triggerable in the general case — it requires a specific relationship between the victim's clone location and another directory on disk that the attacker's symlink target can be crafted to hit. It is nonetheless a genuine logic flaw in a function explicitly documented and relied upon as a security boundary check, used in a code path that ingests attacker-influenced repository content (symlinks, conflicted file paths).

### Recommendation
Fix `_resolveWithin()` to require an exact match or a match followed by the path separator:
```ts
return realResolved === realRoot || realResolved.startsWith(realRoot + Path.sep)
  ? resolved
  : null
```
This closes the sibling-prefix bypass without weakening any of the existing traversal/symlink handling.

### Proof of Concept
1. Victim clones an attacker-supplied repository into `~/work/proj`.
2. The repository contains a symlink `evil -> /Users/victim/work/proj-secrets/secret.txt` (a sibling directory that shares the `…/proj` prefix, e.g. an unrelated directory `proj-secrets` the victim also has on disk, or one the attacker can predict/create via another vector).
3. A merge conflict touching `evil` is created; `buildConflictContext` calls `resolveWithin(workingDirectory, 'evil')`.
4. `realpath(resolved)` follows the symlink to `/Users/victim/work/proj-secrets/secret.txt`; `realResolved.startsWith(realRoot)` returns `true` because the string `"/Users/victim/work/proj-secrets/secret.txt"` starts with `"/Users/victim/work/proj"`, even though it is not nested under the repo directory.
5. The out-of-repo file's contents are read and forwarded to the Copilot conflict-resolution backend, exfiltrating data outside the repository boundary. [5](#0-4) [6](#0-5)

async function _resolveWithin(
  rootPath: string,
  pathSegments: string[],
  options: {
    join: (...pathSegments: string[]) => string
    normalize: (p: string) => string
    resolve: (...pathSegments: string[]) => string
  } = Path
) {
  // An empty root path would let all relative
  // paths through.
  if (rootPath.length === 0) {
    return null
  }

  const { join, normalize, resolve } = options

  const normalizedRoot = normalize(rootPath)
  const normalizedRelative = normalize(join(...pathSegments))

  // Null bytes has no place in paths.
  if (
    normalizedRoot.indexOf('\0') !== -1 ||
    normalizedRelative.indexOf('\0') !== -1
  ) {
    return null
  }

  // Resolve to an absolute path. Note that this will not contain
  // any directory traversal segments.
  const resolved = resolve(normalizedRoot, normalizedRelative)

  const realRoot = await realpath(normalizedRoot)
  const realResolved = await realpath(resolved)

  return realResolved.startsWith(realRoot) ? resolved : null
}
```
