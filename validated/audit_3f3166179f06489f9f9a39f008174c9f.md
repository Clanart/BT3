### Title
Unvalidated `Co-Authored-By` commit-message trailers from an untrusted commit are silently re-embedded into new commits the user creates - ([File: app/src/models/commit.ts])

### Summary
Like the Cairo `payload_type` field, which is attacker-supplied and never bound to the verified signature payload yet is trusted downstream by off-chain systems, Git Desktop extracts `Co-Authored-By` trailer values from arbitrary commit messages without any validation and then re-uses that unverified data both for UI display and, more seriously, for constructing brand-new commits that the local user goes on to commit and push.

### Finding Description
`extractCoAuthors` reads any `Co-Authored-By` trailer out of a commit's parsed trailers and blindly parses the free-text value with `GitAuthor.parse(trailer.value)`, with no check that the name/email correspond to any real account, collaborator, or the actual commit author: [1](#0-0) 

The trailer text itself comes straight from `git interpret-trailers --parse` over the commit message body, again without any authenticity or format enforcement beyond regex matching the token name: [2](#0-1) 

This is exactly analogous to `payload_type` in the report: a field that rides along in an otherwise-verified object (a commit, which is content-addressed by its own SHA) but is never itself checked against anything that would attest to its correctness — the trailer text is just a substring of the commit body, attacker-controlled in any commit they can get merged, fetched, or presented for amending.

The corrupted value doesn't stay confined to passive display. `git-store.ts`'s `loadCommitAndCoAuthors` re-derives `coAuthors` from a commit's trailers when restoring commit state (e.g. after an undo, or when amending): [3](#0-2) [4](#0-3) 

The commit UI then feeds these `coAuthors` back into `getCoAuthorTrailers()`, which re-serializes them as `Co-Authored-By` trailers and merges them into the **new** commit the user is about to make via `formatCommitMessage`/`onCreateCommit`: [5](#0-4) 

There is no check anywhere in this pipeline that the extracted co-author identity is a known/trusted collaborator before it gets echoed into the newly authored commit trailer (the "known vs unknown author" warning only gates a confirmation dialog, it does not validate the parsed value's origin/authenticity).

### Impact Explanation
An attacker who controls a commit the victim will amend, revert-undo, or otherwise interact with (e.g. a commit from a fork/PR branch fetched into the victim's repository, or a commit crafted to be amended) can embed a forged `Co-Authored-By: <arbitrary name> <arbitrary email>` trailer. When the victim performs an "Undo commit" followed by re-commit, or amends that commit, Desktop automatically re-populates and re-embeds that unverified attribution into the victim's own newly created, locally signed/authored commit — which is then pushed upstream. This silently corrupts the authorship/attribution metadata of what the user commits and pushes (falsely crediting or blaming an arbitrary email address, potentially impersonating a real maintainer or triggering downstream automation/analytics that key off `Co-Authored-By`), matching the "silent corruption of what the user commits or pushes" impact bucket.

### Likelihood Explanation
No special privileges are required — any commit message the user opens for amending/undoing (from a fetched branch, opened PR, or cloned repository) is a viable vector, since `extractCoAuthors`/`parseTrailers` apply no allow-listing, ownership check, or cross-reference to the repository's known contributors. The path is triggered through normal Desktop workflows (Undo, Amend) rather than unnatural steps.

### Recommendation
Do not blindly trust `Co-Authored-By` values parsed from arbitrary commit messages when repopulating the commit composer. At minimum:
- Cross-check extracted co-author name/email against `known` authors (GitHub collaborators/contributors of the repository) before treating them as `isKnownAuthor`, and require explicit user confirmation before re-embedding trailers sourced from a commit the user did not author.
- Surface provenance in the UI (e.g., "co-author extracted from an existing commit you are amending") so the user can visually verify the identity before it is folded into a new commit.

### Proof of Concept
1. Attacker crafts a commit on a branch/fork with message:
   ```
   Fix bug

   Co-Authored-By: Trusted Maintainer <maintainer@example.com>
   ```
   and gets the victim to fetch/open it in Desktop (e.g. via a PR checkout).
2. Victim uses "Undo" then re-commits, or chooses "Amend" on that commit in Desktop.
3. `loadCommitAndCoAuthors` (`app/src/lib/stores/git-store.ts:786-913`) extracts the forged trailer via `extractCoAuthors`/`GitAuthor.parse` (`app/src/models/commit.ts:39-52`) with no ownership validation, and populates `coAuthors` state.
4. On commit, `getCoAuthorTrailers()` (`app/src/ui/changes/commit-message.tsx:577-585`) re-serializes it and `formatCommitMessage` embeds `Co-Authored-By: Trusted Maintainer <maintainer@example.com>` into the victim's brand-new commit, which is then pushed — falsely attributing authorship to an arbitrary third party chosen by the attacker.

function extractCoAuthors(trailers: ReadonlyArray<ITrailer>) {
  const coAuthors = []

  for (const trailer of trailers) {
    if (isCoAuthoredByTrailer(trailer)) {
      const author = GitAuthor.parse(trailer.value)
      if (author) {
        coAuthors.push(author)
      }
    }
  }

  return coAuthors
}

export async function parseTrailers(
  repository: Repository,
  commitMessage: string
): Promise<ReadonlyArray<ITrailer>> {
  const result = await git(
    ['interpret-trailers', '--parse'],
    repository.path,
    'parseTrailers',
    {
      stdin: commitMessage,
    }
  )

  const trailers = result.stdout

  if (trailers.length === 0) {
    return []
  }

  const separators = await getTrailerSeparatorCharacters(repository)
  return parseRawUnfoldedTrailers(result.stdout, separators)
}

  private getCoAuthorTrailers() {
    const { coAuthors } = this.props
    const token = 'Co-Authored-By'
    return this.isCoAuthorInputEnabled
      ? coAuthors
          .filter(isKnownAuthor)
          .map(a => ({ token, value: `${a.name} <${a.email}>` }))
      : []
  }
