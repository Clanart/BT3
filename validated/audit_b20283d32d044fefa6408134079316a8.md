## Finding

The `clementine-tx-sender` component runs a completely separate transport from the mTLS-protected gRPC services (`ClementineOperator`, `ClementineVerifier`, `ClementineAggregator`), and that separate transport has no authentication at all.

### Title
Unauthenticated JSON-RPC `send_tx` method lets any caller insert and broadcast arbitrary transactions through the operator's tx-sender - (File: crates/clementine-tx-sender/src/jsonrpc/server.rs)

### Summary
While the gRPC services in this repo enforce mTLS with an `OnlyAggregatorAndSelf` interceptor that restricts every operator/verifier/aggregator RPC to the aggregator or the entity itself, [1](#0-0)  the tx-sender's JSON-RPC server started by `start_jsonrpc_server` registers `send_tx` (and `send_citrea_tx`) on a plain `jsonrpsee` HTTP server with no interceptor, no certificate check, and no API key. [2](#0-1) 

### Finding Description
`start_jsonrpc_server` builds a bare `ServerBuilder` and registers the `send_tx` async method directly, forwarding caller-supplied parameters straight into `TxSenderClient::insert_try_to_send` without any authentication or authorization check. [3](#0-2)  The bind address is configured via `TX_SENDER_JSONRPC_BIND`, which is explicitly allowed to be `0.0.0.0` (a documented, supported value, not a misconfiguration) as well as `127.0.0.1`. [4](#0-3) 

Every field of `InsertTryToSendParams` — `tx_metadata` (including `tx_type`, `deposit_outpoint`, `operator_xonly_pk`, `round_idx`, `kickoff_idx`), `signed_tx_hex`, `fee_paying_type`, `rbf_signing_info`, `cancel_outpoints`, `cancel_txids`, `activate_txids`, and `activate_outpoints` — is attacker-controlled when this port is reachable. [5](#0-4)  `insert_try_to_send` persists the record to the database and queues the transaction for CPFP/RBF fee-bumping, unconditionally accepting any syntactically valid Bitcoin transaction and any attacker-chosen metadata/cancel/activate entries. [6](#0-5) 

This directly matches the rubric's accepted High-impact category "an unauthenticated state-changing or broadcasting call": the `send_tx` JSON-RPC method is a state-changing, broadcasting endpoint reachable by an unprivileged network caller with zero authentication, in contrast to every equivalent gRPC endpoint in the codebase which is gated behind mTLS + `OnlyAggregatorAndSelf`.

### Impact Explanation
An unauthenticated caller who can reach the tx-sender JSON-RPC port can:
- Force the operator's tx-sender to accept and fee-bump (via the operator's own wallet, CPFP) transactions of the attacker's choosing.
- Inject arbitrary `tx_metadata` (fabricated `tx_type`, `deposit_outpoint`, `operator_xonly_pk`, `round_idx`, `kickoff_idx`) into the operator's persistent tx-sender bookkeeping, polluting the operator's internal transaction-tracking state that other automated logic (e.g., `TxSenderClientQueueExt::add_tx_to_queue`) relies on for cancellation/activation semantics tied to real protocol transaction types. [7](#0-6) 
- Supply attacker-chosen `cancel_outpoints`/`cancel_txids`/`activate_outpoints`/`activate_txids`, entangling the attacker's submitted entries with the same bookkeeping tables used to gate confirmation of legitimate deadline-bound transactions like `ChallengeTimeout`, `DisproveTimeout`, or `AssertTimeout`. [8](#0-7) 

### Likelihood Explanation
Any party with network access to the configured `TX_SENDER_JSONRPC_BIND:TX_SENDER_JSONRPC_PORT` (which the code explicitly supports setting to `0.0.0.0`) can call `send_tx` with no credentials — no certificate, no signature, no rate limit tied to identity. This requires no privileged role, no key compromise, and no social engineering, only network reachability to the endpoint.

### Recommendation
Apply the same authentication model used for the gRPC services (mTLS + `OnlyAggregatorAndSelf`-style interceptor, or equivalent) to the tx-sender JSON-RPC server, or otherwise require a caller-bound credential/signature before `insert_try_to_send` is invoked, so that only the local operator/aggregator process (not arbitrary network peers) can queue and broadcast transactions or write tx-sender metadata.

### Proof of Concept
1. Deploy `clementine-tx-sender` with `TX_SENDER_JSONRPC_BIND=0.0.0.0` (a documented, valid configuration per `config.rs`).
2. From an unauthenticated remote host, send an HTTP JSON-RPC request:
```
POST http://<target>:3030
{"jsonrpc":"2.0","id":1,"method":"send_tx","params":[{
  "tx_metadata": {"tx_type":"Reimburse","deposit_outpoint":{...},"operator_xonly_pk":"...","round_idx":0,"kickoff_idx":0},
  "signed_tx_hex": "<any syntactically valid signed tx hex>",
  "fee_paying_type": "CPFP",
  "rbf_signing_info": null,
  "cancel_outpoints": [...],
  "cancel_txids": [...],
  "activate_txids": [...],
  "activate_outpoints": [...]
}]}
```
3. The server accepts the request (as demonstrated by the project's own `run.sh` smoke test using an unauthenticated `curl` call), [9](#0-8)  inserts the record via `insert_try_to_send`, and queues the attacker-controlled transaction/metadata for broadcasting — with no verification that the caller is the aggregator or the operator itself.

pub async fn start_jsonrpc_server(
    tx_sender_client: TxSenderClient,
    bind_addr: SocketAddr,
) -> Result<TxSenderJsonRpcServer, BridgeError> {
    let server: Server = ServerBuilder::default()
        .max_request_body_size(MAX_JSONRPC_REQUEST_BODY_SIZE)
        .build(bind_addr)
        .await
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    let local_addr = server
        .local_addr()
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    let mut module = RpcModule::new(tx_sender_client.clone());
    module
        .register_async_method("send_tx", |params, client, _| async move {
            let req: InsertTryToSendParams = params.one().map_err(jsonrpc_err)?;

            let raw_tx = hex::decode(&req.signed_tx_hex).map_err(jsonrpc_err)?;
            let signed_tx: Transaction = consensus::deserialize(&raw_tx).map_err(jsonrpc_err)?;

            let mut dbtx = client.db.begin_transaction().await.map_err(jsonrpc_err)?;

            let try_to_send_id = client
                .insert_try_to_send(
                    &mut dbtx,
                    req.tx_metadata,
                    &signed_tx,
                    req.fee_paying_type,
                    req.rbf_signing_info,
                    &req.cancel_outpoints,
                    &req.cancel_txids,
                    &req.activate_txids,
                    &req.activate_outpoints,
                )
                .await
                .map_err(jsonrpc_err)?;

            client
                .db
                .commit_transaction(dbtx)
                .await
                .map_err(jsonrpc_err)?;

            Ok::<u32, ErrorObjectOwned>(try_to_send_id)
        })
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    pub async fn insert_try_to_send(
        &self,
        dbtx: &mut crate::TxSenderTransaction,
        tx_metadata: Option<TxMetadata>,
        signed_tx: &Transaction,
        fee_paying_type: FeePayingType,
        rbf_signing_info: Option<RbfSigningInfo>,
        cancel_outpoints: &[OutPoint],
        cancel_txids: &[Txid],
        activate_txids: &[ActivatedWithTxid],
        activate_outpoints: &[ActivatedWithOutpoint],
    ) -> Result<u32, BridgeError> {
        let txid = signed_tx.compute_txid();

        // do not add duplicate transactions to the txsender
        let tx_exists = self
            .db
            .check_if_tx_exists_on_txsender(Some(dbtx), txid)
            .await?;
        if let Some(try_to_send_id) = tx_exists {
            return Ok(try_to_send_id);
        }

        tracing::info!(
            "Added tx {} with txid {} to the queue",
            tx_metadata
                .as_ref()
                .map(|data| format!("{:?}", data.tx_type))
                .unwrap_or("N/A".to_string()),
            txid
        );

        let try_to_send_id = self
            .db
            .save_tx(
                dbtx,
                tx_metadata,
                signed_tx,
                fee_paying_type,
                txid,
                rbf_signing_info,
            )
            .await?;

        // only log the raw tx in tests so that logs do not contain sensitive information
        #[cfg(test)]
        tracing::debug!(target: "ci", "Saved tx to database with try_to_send_id: {try_to_send_id}, metadata: {tx_metadata:?}, raw tx: {}", hex::encode(bitcoin::consensus::serialize(signed_tx)));

        for input_outpoint in signed_tx.input.iter().map(|input| input.previous_output) {
            self.db
                .save_cancelled_outpoint(dbtx, try_to_send_id, input_outpoint)
                .await?;
        }

        for outpoint in cancel_outpoints {
            self.db
                .save_cancelled_outpoint(dbtx, try_to_send_id, *outpoint)
                .await?;
        }

        for txid in cancel_txids {
            self.db
                .save_cancelled_txid(dbtx, try_to_send_id, *txid)
                .await?;
        }

send_via_jsonrpc() {

import json, os
raw_tx_hex = os.environ["RAW_TX_HEX"]
payload = {
  "jsonrpc":"2.0",
  "id": 1,
  "method": "send_tx",
  "params": [{
    "tx_metadata": None,
    "signed_tx_hex": raw_tx_hex,
    "fee_paying_type": "NoFunding",
    "rbf_signing_info": None,
    "cancel_outpoints": [],
    "cancel_txids": [],
    "activate_txids": [],
    "activate_outpoints": [],
  }],
}
print(json.dumps(payload))
PY
)"

  curl -sS \
    -H 'content-type: application/json' \
    --data "${req}" \
    "${url}" \
    | python3 -c 'import sys, json; r=json.load(sys.stdin);
if "error" in r:
  raise SystemExit("JSON-RPC error: %s" % r["error"])
print(r["result"])'
}
