### Title
Stop-hook review set drops committed-and-amended changes from security review, letting dangerous diffs bypass LLM analysis - (File: plugins/security-guidance/hooks/diffstate.py)

### Summary
`compute_v2_review_set` only picks up committed content when HEAD advances *linearly* from `head_at_capture` (checked via `_is_ancestor`). A `git commit --amend` (or any history-rewriting op) breaks that ancestor relationship, so the amended file is excluded from `dirty_now`, and the subsequent intersection `dirty_now & changed_since` drops it from the review set even though its content clearly differs from the session baseline.

### Finding Description
`capture_git_baseline` (`plugins/security-guidance/hooks/diffstate.py:163-204`) is invoked from `handle_user_prompt_submit` in `security_reminder_hook.py` (lines 446-515) to snapshot `baseline_sha` (a `git stash create` SHA) and `head_at_capture` (`_git_rev_parse_head`) at the start of every user turn.

At Stop time, `compute_v2_review_set` (`diffstate.py:353-438`) builds the review set as:

```
dirty_now = tracked_dirty | new_untracked
if head_at_capture and current_head and head_at_capture != current_head
        and _is_ancestor(repo, head_at_capture, current_head):
    dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD") or set()
    diff_base = head_at_capture
...
changed_since = _git_name_only(repo, baseline_sha) | new_untracked  # (if baseline_sha)
review_set = (dirty_now & changed_since) if changed_since is not None else dirty_now
```
(`diffstate.py:401-426`)

If the dangerous edit is made and then committed with `git commit --amend` (a completely normal, "standard command input" git operation), the amended commit shares the *same parent* as the original committed HEAD rather than descending from it, so `_is_ancestor(head_at_capture, current_head)` returns `False` (`gitutil.py:377-387`, via `merge-base --is-ancestor`). Because the ancestor check fails:
- The commit-range term (`_git_name_only(head_at_capture..HEAD)`) is never unioned into `dirty_now`.
- The file is no longer "dirty" in `git status` since it is committed, so `tracked_dirty` also excludes it.
- `dirty_now` therefore has no entry for the dangerous file at all.

Meanwhile `changed_since` (diff against `baseline_sha`, the pre-turn stash) *does* contain the file, since its content differs from the pre-turn snapshot. But `review_set = dirty_now & changed_since` intersects the two sets, and since `dirty_now` is empty for that path, the dangerous file is silently dropped from `review_set` — the Stop hook's LLM review (`analyze_code_security`/`agentic_review`) never sees it. No existing check (workspace guard, session binding, path allowlist) catches this, because the omission happens purely inside the pure `compute_v2_review_set` set-arithmetic before any diff is even generated.

A single plain `git commit` does not trigger this (linear-history ancestor check succeeds and the commit range is unioned in), so the bug is specific to amend/rebase/reset-and-recommit style history rewrites — exactly the "normal git operations" called out in the exploit idea.

### Impact Explanation
This breaks the stated invariant that "the review set must stay bound to the right repo, baseline, and touched paths": a dangerous change that is genuinely new relative to the session baseline is treated as if it doesn't exist and skipped by the Stop-hook security review. This is a real security-control bypass in the plugin's core enforcement path (the Stop hook is the last automated check before the turn ends), matching an "approval bypass / unauthorized action reaching production undetected" class of impact — a vulnerable or malicious code change introduced by Claude (or by an attacker steering Claude via repository content/prompt injection into running `git commit --amend`) is committed to the repository without the plugin's LLM vulnerability scan or areas-of-concern analysis ever running against it.

### Likelihood Explanation
Highly reachable and repeatable: no privilege escalation is required, only ordinary git usage that agentic coding sessions perform routinely (fixing a commit message, squashing a WIP commit, or being told by repo content/CI conventions to "always commit --amend"). Any turn where Claude (a) edits a file, (b) commits it, and (c) amends that commit (or otherwise rewrites HEAD non-linearly, e.g. `git reset --soft` + recommit, interactive rebase) before Stop fires will reproduce the drop deterministically — it is pure git-state arithmetic, not timing-dependent.

### Recommendation
Do not gate committed-change detection on `_is_ancestor(head_at_capture, current_head)` alone. When HEAD has moved and `head_at_capture` is not an ancestor (history rewritten), fall back to diffing the *baseline_sha* (not `head_at_capture`) against current HEAD/worktree for committed content too — i.e., union `changed_since` into `dirty_now` (or drop the intersection when a non-linear HEAD change is detected) so that files changed relative to `baseline_sha` are never excluded merely because they were committed and then had their history rewritten. In general, `review_set` should be `changed_since` restricted to plausible touched paths, not intersected against a `dirty_now` computation that assumes linear commit history.

### Proof of Concept
Integration test in the vein of the existing diffstate tests:
1. Init a repo, make an initial commit (`base.py`).
2. Call `capture_git_baseline(cwd)` to get `baseline_sha`, and `_git_rev_parse_head(cwd)` to get `head_at_capture`.
3. Write a "dangerous" file/change (e.g. `os.system(user_input)` in `vuln.py`), `git add`, `git commit -m "wip"`.
4. `git commit --amend -m "final"` (no content change needed, or edit content again and amend).
5. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture, {})`.
6. Assert: `vuln.py` (converted to absolute path) IS present in the returned `review_paths` / review set.

Expected current (buggy) result: `vuln.py` is absent from `review_set` (assertion fails), demonstrating the dangerous change is skipped. After the fix, the same test should pass with `vuln.py` included.
