### Title
PlotNFT2 melt does not require unclaimed pool rewards to be swept first, risking permanent loss of pending reward coins - ([File: chia/wallet/plotnft_wallet/plotnft_wallet.py])

### Summary
This is analogous in shape to the Alchemix report (burning a position without first claiming its outstanding rewards), but I could not fully verify the root-cause mechanics within the available tool budget — specifically whether a `SingletonMember`-gated `PoolReward` coin becomes provably unclaimable once the originating singleton is melted, or whether some other recovery path (e.g. re-launching with the same `launcher_id`, or a permissionless timeout path) still allows the coin to be swept.

### Finding Description
`PlotNFT.melt()` [1](#0-0)  only guards against melting while `self.pooling` is true; it performs no check for, and no consolidation of, outstanding unclaimed `PoolReward` coins (tracked via `plotnft2_store.get_pool_rewards`) before creating the `CREATE_COIN 0 -113` melt condition that destroys the singleton. `PlotNFT2Wallet.melt_plotnft()` [2](#0-1)  likewise just builds the melt spend and does not call `claim_rewards()` first, unlike other flows in the same class such as `claim_rewards()` [3](#0-2)  which explicitly sweeps `pool_reward2s` entries before they can be lost, and the test at `test_plotnft_wallet.py` even has a section literally called "LOSE REWARDS" [4](#0-3)  demonstrating rewards not swept before a state change are dropped from wallet accounting.

The `PoolReward`/`RewardPuzzle` claim path (`claim_pool_rewards`) spends the reward coin via a `SingletonMember`-restricted puzzle that is authorized through a `SEND_MESSAGE`/`SendMessage` announcement originating from the live singleton spend [5](#0-4) . If the singleton coin has been melted (burned) via the `-113` melt condition before these reward coins are claimed, I was not able to confirm within the remaining budget whether the `SingletonMember` puzzle has any fallback authorization path (e.g., a lineage/lineage-proof exception, or a permissionless timeout) that would still allow sweeping already-farmed-but-unclaimed `PoolReward` coins after the singleton no longer exists on-chain.

### Impact Explanation
If confirmed, this would be a permanent-freezing-of-funds bug class matching the external report: a user-initiated action (melting a self-custodied Plot NFT) that destroys the authorizing singleton before unclaimed pool rewards are swept could leave those reward coins permanently unspendable, since the `SingletonMember` restriction puzzle depends on a live singleton announcement to authorize the spend.

### Likelihood Explanation
Uncertain without further verification. This requires: (1) the plot NFT to be in self-custody with outstanding unclaimed `PoolReward` coins, and (2) the user (or their wallet client) calling `melt_plotnft`/`plotnft_melt` without first calling `claim_rewards`. The CLI/RPC layer (`MeltPlotNFTCMD`, `plotnft_melt` RPC endpoint [6](#0-5) ) does not appear to enforce claiming first, so it is plausible a user could trigger this unintentionally.

### Recommendation
I could not complete the root-cause verification (specifically the `SingletonMember` puzzle's authorization semantics after singleton destruction) within the available tool iterations. Before treating this as a confirmed vulnerability, a Devin session should:
1. Inspect `chia/wallet/puzzles/custody/member_puzzles.py`'s `SingletonMember` CLVM/puzzle definition to determine whether reward-coin spends require a live singleton announcement or can be authorized some other way after melt.
2. If a live-singleton dependency is confirmed, add a check in `PlotNFT2Wallet.melt_plotnft()`/`PlotNFT.melt()` that queries `plotnft2_store.get_pool_rewards()` and either auto-claims outstanding rewards first or raises a `ValueError` (mirroring the `"Cannot melt a pooling PlotNFT"` guard) blocking melt until rewards are claimed.

### Proof of Concept
Not constructed — this requires confirming the `SingletonMember` puzzle's post-melt authorization behavior first, which was not completed. Given the uncertainty, I am not asserting this as a proven vulnerability.

    async def claim_rewards(
        self,
        *,
        action_scope: WalletActionScope,
        fee: uint64 = uint64(0),
        extra_conditions: tuple[Condition, ...] = tuple(),
    ) -> None:
        rewards_to_claim = await self.wallet_state_manager.plotnft2_store.get_pool_rewards(plotnft_id=self.plotnft_id)
        if len(rewards_to_claim) == 0:
            raise ValueError("No rewards to claim")
        total_reward_amount = uint64(sum(reward.coin.amount for reward in rewards_to_claim))
        if fee > total_reward_amount:
            raise ValueError("Fee is greater than the total amount of rewards")

        plotnft = await self.get_current_plotnft()
        coin_spends = plotnft.claim_pool_rewards(
            rewards_to_claim=rewards_to_claim,
            reward_delegated_puzzles_and_solutions=[
                DelegatedPuzzleAndSolution(
                    puzzle=self.xch_wallet.make_solution(
                        primaries=[
                            CreateCoin(
                                puzzle_hash=self.rewards_claim_puzhash,
                                amount=uint64(total_reward_amount - fee),
                            ),
                        ],
                        fee=fee,
                        conditions=(*extra_conditions, CreateCoinAnnouncement(b""))
                        if len(rewards_to_claim) > 1
                        else extra_conditions,
                    ).at("rf"),  # strips away to just the delegated puzzle (bit of a hack)
                    solution=Program.to(None),
                )
                if i == 0
                else DelegatedPuzzleAndSolution(
                    puzzle=Program.to(
                        (
                            1,
                            [
                                AssertCoinAnnouncement(
                                    asserted_id=rewards_to_claim[0].coin.name(), asserted_msg=b""
                                ).to_program()
                            ],
                        )
                    ),
                    solution=Program.to(None),
                )
                for i, reward in enumerate(rewards_to_claim)
            ],
        )

        spend_bundle = WalletSpendBundle(coin_spends, G2Element())

        async with action_scope.use() as interface:
            interface.side_effects.transactions.append(
                self.wallet_state_manager.new_outgoing_transaction(
                    wallet_id=self.id(),
                    puzzle_hash=self.rewards_claim_puzhash,
                    amount=total_reward_amount,
                    fee=fee,
                    spend_bundle=spend_bundle,
                    additions=[
                        Coin(
                            parent_coin_info=rewards_to_claim[0].coin.name(),
                            puzzle_hash=self.rewards_claim_puzhash,
                            amount=uint64(total_reward_amount - fee),
                        ),
                        Coin(
                            parent_coin_info=plotnft.coin.name(),
                            puzzle_hash=plotnft.puzzle_hash(nonce=uint64(0)),
                            amount=uint64(1),
                        ),
                    ],
                    removals=[reward.coin for reward in rewards_to_claim] + [plotnft.coin],
                    name=spend_bundle.name(),
                    extra_conditions=extra_conditions,
                )
            )

    async def melt_plotnft(
        self,
        *,
        action_scope: WalletActionScope,
        fee: uint64 = uint64(0),
        extra_conditions: tuple[Condition, ...] = tuple(),
    ) -> None:
        plotnft = await self.get_current_plotnft()
        fee_hook = CreateCoinAnnouncement(msg=b"", coin_id=plotnft.coin.name())
        coin_spends = plotnft.melt(extra_conditions=(fee_hook, *extra_conditions))
        if fee > 0:
            await self.xch_wallet.create_tandem_xch_tx(
                fee=fee,
                action_scope=action_scope,
                extra_conditions=(fee_hook.corresponding_assertion(),),
            )

        spend_bundle = WalletSpendBundle(coin_spends, G2Element())
        async with action_scope.use() as interface:
            interface.side_effects.transactions.append(
                self.wallet_state_manager.new_outgoing_transaction(
                    wallet_id=self.id(),
                    puzzle_hash=bytes32.zeros,
                    amount=uint64(1),
                    fee=fee,
                    spend_bundle=spend_bundle,
                    additions=[],
                    removals=[plotnft.coin],
                    name=spend_bundle.name(),
                    extra_conditions=extra_conditions,
                )
            )
