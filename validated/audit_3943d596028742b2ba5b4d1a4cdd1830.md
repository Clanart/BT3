### Title
Unauthorized DKG secret-share disclosure through premature blame proof release - ([File: crypto/dkg/pedpop/src/lib.rs])

### Summary
`KeyMachine::calculate_share` can return an `EncryptionKeyProof` before verifying the encrypted message’s proof of possession, allowing a malformed message that reuses another ciphertext’s ephemeral key to obtain that ciphertext’s ECDH key. [1](#0-0) 

### Finding Description
`EncryptedMessage::read` accepts an arbitrary group element as `key`, a syntactically valid Schnorr signature as `pop`, and arbitrary ciphertext bytes without authenticating their relationship. [2](#0-1)  The plaintext `SecretShare` is likewise read as raw field-encoding bytes and is only checked later with `C::F::from_repr`. [3](#0-2) 

`Encryption::decrypt` queues the PoP for later batch verification, then immediately derives `ECDH(victim_secret, msg.key)`, decrypts the payload, and returns an `EncryptionKeyProof` containing that ECDH point. [4](#0-3)  In `calculate_share`, a non-canonical decrypted representation immediately returns `PedPoPError::InvalidShare` with `blame: Some(blame)`, before `batch.verify_with_vartime_blame` can reject an invalid PoP. [5](#0-4) 

The code comments explicitly identify this threat: without enforcing PoP ownership, an observer can reuse Alice’s message key in a message to Bob and cause Bob’s blame proof to reveal the ECDH key for Alice’s message. [6](#0-5)  The early non-canonical-scalar path bypasses that protection because the queued PoP has not yet been verified when the proof is returned. [1](#0-0) 

### Impact Explanation
An unprivileged party who can observe a victim-bound `EncryptedMessage` can copy its public `key` into a malformed message under a participant index they control and submit it to the victim’s `calculate_share` API. [2](#0-1)  If the resulting decryption is non-canonical, the returned proof exposes the ECDH point for the copied key; the proof is publicly serializable as the shared point followed by its DLEq proof. [7](#0-6) 

That shared point is sufficient to derive the ChaCha20 keystream and decrypt the original ciphertext, since `decrypt_with_proof` uses the same `proof.key` to decrypt an encrypted share after validating the DLEq relation. [8](#0-7)  This discloses a secret Pedersen share intended for the victim, constituting unauthorized secret-share recovery and potentially aiding recovery of threshold key material. [9](#0-8) 

### Likelihood Explanation
The attacker needs a publicly observed victim-bound ciphertext and the ability to supply a malformed `EncryptedMessage` to `calculate_share`; they do not need the ephemeral private key or the victim’s long-term encryption key. [10](#0-9)  Random malformed ciphertext will frequently decrypt to a non-canonical field encoding, especially for fields substantially smaller than the encoding width, and the error’s `Some(blame)` versus `None` result allows the attacker to recognize successful attempts. [11](#0-10) 

The malformed message’s invalid PoP would normally suppress the blame proof, but only when batch verification is reached; the early `from_repr` return path bypasses that check. [12](#0-11) 

### Recommendation
Do not expose `EncryptionKeyProof` until the message’s PoP has been verified for the claimed sender and ciphertext. [13](#0-12)  `decrypt` should either synchronously verify the PoP before returning a proof for early deserialization failures or be split into an authentication phase followed by decryption and scalar validation. [4](#0-3)  `calculate_share` should also avoid returning blame material through any path that precedes `batch.verify_with_vartime_blame`. [14](#0-13) 

### Proof of Concept
1. Alice sends Bob a legitimate serialized encrypted share `(X_A, pop_A, c_A)`, where `X_A = x_A * G` and the ECDH key is `K_A = b_B * X_A`. [15](#0-14) 
2. Eve constructs an `EncryptedMessage` for her own participant index containing the same `key = X_A`, any parseable but invalid `pop`, and malformed ciphertext bytes; `EncryptedMessage::read` accepts this structure. [2](#0-1) 
3. Bob calls `calculate_share`; `Encryption::decrypt` computes `K_A`, decrypts the malformed bytes, and creates an `EncryptionKeyProof` containing `K_A`, while the invalid PoP is only queued. [16](#0-15) 
4. When the malformed plaintext fails `C::F::from_repr`, Bob returns `InvalidShare { blame: Some(proof) }` immediately, before the queued PoP can fail. [11](#0-10) 
5. Eve parses `proof.key` from `EncryptionKeyProof::serialize`, derives the ChaCha20 keystream for `K_A`, and decrypts Alice’s original ciphertext `c_A` to recover Alice’s secret share for Bob. [7](#0-6)

fn pop_challenge<C: Ciphersuite>(
  context: [u8; 32],
  nonce: C::G,
  key: C::G,
  sender: Participant,
  msg: &[u8],
) -> C::F {
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption Key Proof of Possession v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"proof_of_possession");

  transcript.append_message(b"nonce", nonce.to_bytes());
  transcript.append_message(b"key", key.to_bytes());
  // This is sufficient to prevent the attack this is meant to stop
  transcript.append_message(b"sender", sender.to_bytes());
  // This, as written above, doesn't hurt
  transcript.append_message(b"message", msg);
  // While this is a PoK and a PoP, it's called a PoP here since the important part is its owner
  // Elsewhere, where we use the term PoK, the important part is that it isn't some inverse, with
  // an unknown to anyone discrete log, breaking the system
  C::hash_to_F(b"DKG-encryption-proof_of_possession", &transcript.challenge(b"schnorr"))
}
