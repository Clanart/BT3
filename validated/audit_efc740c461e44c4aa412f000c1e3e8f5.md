### Title
`get_outputs` overwrites the `data`/`presumed_origin` of all previously scanned outputs with those of every later transaction in the same block - ([File: processor/src/networks/bitcoin.rs](https://github.com/blackvul/serai/blob/main/processor/src/networks/bitcoin.rs))

### Summary
The bug class of the reference report — a deposit/`receive()` path whose accounting is broken such that funds end up miscredited — has a direct analog in the Bitcoin `get_outputs` implementation. The results vector `outputs` is declared *outside* the per-transaction loop, but the block which populates `presumed_origin` and `data` is gated by `if outputs.is_empty()` and then mutates **all** outputs accumulated so far. Any later transaction in the same block (even one paying nothing to Serai) causes the earlier outputs' origin and InInstruction payload to be overwritten.

### Finding Description
In `get_outputs`, `outputs` is initialized once per block (`processor/src/networks/bitcoin.rs:689`), and each transaction in `block.txdata[1 ..]` pushes its scanned outputs into that shared vector (lines 691–699). The guard `if outputs.is_empty() { continue }` (line 702) only checks whether *any* output has been found in the whole block — not whether the current transaction produced one. The code then computes `presumed_origin` from `tx.input[0]` of the *current* transaction (lines 707–729), calls `Self::extract_serai_data(tx)` (line 730), and writes those values onto **every output in `outputs`** (lines 731–736):

```rust
for output in &mut outputs {
  if output.kind == OutputType::External {
    output.data.clone_from(&data);
  }
  output.presumed_origin.clone_from(&presumed_origin);
}
```

Two concrete consequences for an unprivileged sender:

1. **Data stripping**: Alice deposits BTC to the multisig with an `OP_RETURN` InInstruction in tx A (index 5 of block N). An attacker includes any unrelated transaction tx B at index 6 (or any index > 5 with no Serai outputs). When the loop reaches tx B, `outputs` is non-empty, `extract_serai_data(tx B)` returns empty, and `data` on Alice's `OutputType::External` output is cleared — her instruction is silently destroyed, turning a directed deposit into a data-less one.
2. **Origin hijack**: `presumed_origin` of Alice's output is replaced with the address of tx B's first input — i.e., the attacker's address. Per `spec/integrations/Bitcoin.md`, a failed/absent instruction falls back to the presumed origin for refunds; the attacker can therefore redirect any refund of Alice's output to themselves.

Additionally, the loop performs one `get_transaction` RPC call (lines 714–727) for *every* transaction after the first Serai-receiving tx in the block, even ones with no matching outputs.

### Impact Explanation
An unprivileged party who gets any Bitcoin transaction mined in the same block after a Serai-receiving transaction can erase the victim's InInstruction `data` and overwrite `presumed_origin` with their own address. Since failed/refundable instructions are refunded to the presumed origin, this enables theft of deposits whose instruction is wiped, or misattribution of the depositor. This is the same shape as the reference bug: the "receive" path exists but produces corrupted accounting of incoming funds.

### Likelihood Explanation
Requires only transaction ordering the attacker can influence via normal Bitcoin mempool/fees (send a tx in the same block after the deposit — trivially achieved by watching the mempool and broadcasting a self-payment with adequate fee). No privileged position needed. It does, however, require the refund path to credit `presumed_origin` for the misattribution to be profitable, and deposits with no attached instruction are unaffected in value terms (only origin attribution).

### Recommendation
Track the outputs per-transaction: collect `scan_transaction(tx)` results into a local `tx_outputs`, `continue` if that is empty, populate `data`/`presumed_origin` only on `tx_outputs`, then `outputs.extend(tx_outputs)`. Never mutate outputs attributed to earlier transactions.

### Proof of Concept
Within `processor/src/networks/bitcoin.rs:get_outputs`:

```rust
let mut outputs = vec![];            // line 689 — shared across all txs
for tx in &block.txdata[1 ..] {
  for output in scanner.scan_transaction(tx) { ... outputs.push(output); }  // 692-699

  if outputs.is_empty() { continue; }  // 702 — true only if NO prior tx had outputs

  let presumed_origin = /* tx.input[0]'s spent script_pubkey */;           // 707-729
  let data = Self::extract_serai_data(tx);                                 // 730
  for output in &mut outputs {          // 731-736 — mutates ALL prior outputs
    if output.kind == OutputType::External {
      output.data.clone_from(&data);
    }
    output.presumed_origin.clone_from(&presumed_origin);
  }
}
```

Scenario: block contains tx A (attacker-free deposit to the Serai external address with a valid `OP_RETURN` InInstruction) followed by tx B (attacker's unrelated self-transfer). At tx B, `outputs` is non-empty → the block runs → `data` becomes `extract_serai_data(tx B)` (empty) and `presumed_origin` becomes the attacker's input address, applied to Alice's `External` output. The processor then emits an output whose instruction data was stripped and whose refund origin points at the attacker.
