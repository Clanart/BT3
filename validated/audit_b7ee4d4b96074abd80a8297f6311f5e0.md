### Title
Payout attribution is derived from an unauthenticated OP_RETURN in the spending transaction, letting anyone credit an arbitrary operator for a withdrawal it never funded - (File: core/src/verifier.rs, core/src/database/verifier.rs, core/src/builder/transaction/operator_reimburse.rs)

### Summary
`create_payout_txhandler` builds the payout transaction so that the user's withdrawal UTXO is spent with `SIGHASH_SINGLE|ANYONECANPAY` [1](#0-0) , and it embeds the fronting operator's x-only pubkey in a plain, unsigned OP_RETURN output [2](#0-1) . The verifier's chain-sync logic (`update_finalized_payouts`) later reads *whatever* transaction spends the registered withdrawal UTXO and blindly trusts the OP_RETURN payload as the identity of the operator that "fronted" the withdrawal, storing it as `payout_payer_operator_xonly_pk` [3](#0-2) . This binding — "the operator credited" vs. "the party that actually paid" — is exactly the write/read mismatch pattern the external report describes for DNS zone/host versions: the value used to attribute credit (an operator pubkey pulled from an OP_RETURN in an arbitrary spending transaction) is not cryptographically tied to the entity that is credited, and is not validated against anything the operator actually signed.

### Finding Description
The withdrawal UTXO the user creates on Citrea is signed by the user with `SIGHASH_SINGLE|ANYONECANPAY` [4](#0-3) . This sighash flag commits only to the user's own input and the single (user payout) output — it explicitly allows anyone to attach arbitrary additional inputs/outputs to the transaction that spends it. `create_payout_txhandler` exploits this by construction: it adds an OP_RETURN output containing an `operator_xonly_pk` parameter [5](#0-4) , but nothing in the transaction — no signature, no script constraint — binds that OP_RETURN payload to the actual identity of whoever funded/broadcast the transaction. Since ANYONECANPAY lets any third party complete and broadcast the spending transaction (adding their own input to cover the payout amount, or even reusing an already-broadcast payout with a modified OP_RETURN via a new transaction if the user's partial signature is available off-chain), the OP_RETURN field is fully attacker-controlled.

On the read side, `update_finalized_payouts` finds the transaction that spent the withdrawal UTXO for a given `idx` [6](#0-5) , extracts the first OP_RETURN payload from that transaction, and — with no further validation of who supplied the funds — parses it directly as the crediting operator's x-only pubkey [7](#0-6) . This is persisted verbatim via `update_payout_txs_and_payer_operator_xonly_pk` [8](#0-7) .

Downstream, this attribution is treated as authoritative:
- `get_first_unhandled_payout_by_operator_xonly_pk` selects payouts to process strictly by matching `payout_payer_operator_xonly_pk` [9](#0-8) .
- `PayoutCheckerTask::run_once` picks up this record and calls `operator.handle_finalized_payout`, which creates/queues the Kickoff transaction that starts the reimbursement flow for that specific operator [10](#0-9) .
- `validate_payer_is_operator` (used by `get_reimbursement_txs`) trusts the same DB-stored `payout_payer_operator_xonly_pk` to authorize the reimbursement path for the calling operator, only checking that it equals the caller's own key — it never re-derives the value from cryptographic proof of funding [11](#0-10) .
- `is_kickoff_malicious` also keys off the same field to decide whether a kickoff's operator matches the recorded payer, again trusting the OP_RETURN-derived value rather than proof that the named operator's funds were spent [12](#0-11) .

The chain of trust is: *value that credits an operator* (OP_RETURN in the withdrawal-UTXO-spending tx) ≠ *value proving that operator actually paid* (no signature, script, or input tied to that operator's key exists in the payout transaction). Because the withdrawal UTXO's ANYONECANPAY signature allows any party to complete the spend, an attacker who fronts the withdrawal (or even reuses a withdrawal UTXO no operator has claimed yet) can insert any operator's xonly pubkey into the OP_RETURN, causing the system to credit an operator that never fronted the payout.

### Impact Explanation
This breaks the bridge-custody binding "operator credited == party that paid." An honest operator can be credited (and consequently kicked off into the reimbursement path, ultimately entitled to spend the move-to-vault UTXO via the Reimburse transaction) for a withdrawal it never funded, while the entity that actually fronted the payment receives no bridge credit. This matches the explicitly listed Critical impact class: "an operator reimbursed for a payout it never funded." It can also be used adversarially against an operator — attributing malicious/incorrect payouts to a target operator's key, potentially triggering `is_kickoff_malicious`/challenge flows against that operator when it does try to claim its legitimate reimbursement later, i.e. harming an honest operator's ability to be reimbursed.

### Likelihood Explanation
The withdrawal UTXO and its `SIGHASH_SINGLE|ANYONECANPAY` signature are, by protocol design, meant to be usable by any operator that wants to front the withdrawal; the user's off-chain signature is handed out to "operators" but nothing on-chain restricts who completes the transaction once it's known. Any actor capable of observing/completing this transaction (which is inherent to the ANYONECANPAY design) can choose the OP_RETURN payload freely — no additional secret, majority, or role is required. This is directly reachable by an unprivileged actor with no verifier/operator/watchtower authority, satisfying the required "unprivileged-attacker" bar.

### Recommendation
Do not derive payout attribution solely from an unsigned OP_RETURN field. Require the payout transaction to also prove operator authorization cryptographically — e.g., have the operator sign (or otherwise be a mandatory second input funded from a key-committed source) so that `payout_payer_operator_xonly_pk` can only be set to an operator that provably supplied funds for the output. Alternatively, verify that the OP_RETURN-declared operator's own UTXO/key was actually used as an input funding the payout output before persisting the attribution, and reject/mark-malicious any payout tx whose OP_RETURN operator key cannot be tied to the actual funding input.

### Proof of Concept
1. User creates a withdrawal request off-chain, producing `withdrawal_utxo` and a `SIGHASH_SINGLE|ANYONECANPAY` Schnorr signature over the payout output (script_pubkey/amount to the user) as in `operator.withdraw()` [13](#0-12) .
2. Instead of a legitimate operator, an attacker (or a competing/second operator with no funding relationship to the intended kickoff operator) constructs their own payout transaction using `create_payout_txhandler`, fronting the payment out of their own pocket but setting `operator_xonly_pk` to a *different*, target operator's key that the attacker never controls funds for [5](#0-4) .
3. Because the ANYONECANPAY signature only commits to the user's input/output, this modified transaction is fully valid on-chain.
4. Once mined, `update_finalized_payouts` scans the block, finds this transaction as the spender of `withdrawal_utxo`, and stores the attacker-chosen `operator_xonly_pk` as `payout_payer_operator_xonly_pk` for that withdrawal index [14](#0-13) .
5. `PayoutCheckerTask` for the falsely-credited operator picks this up via `get_first_unhandled_payout_by_operator_xonly_pk` and proceeds to call `handle_finalized_payout`, queuing a Kickoff transaction that will eventually let that operator claim the Reimburse output from the corresponding move-to-vault UTXO [10](#0-9)  — even though that operator never funded the withdrawal.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

    async fn run_once(&mut self) -> Result<Self::Output, BridgeError> {
        let mut dbtx = self.db.begin_transaction().await?;
        let unhandled_payout = self
            .db
            .get_first_unhandled_payout_by_operator_xonly_pk(
                Some(&mut dbtx),
                self.operator.signer.xonly_public_key,
            )
            .await?;

        if unhandled_payout.is_none() {
            return Ok(false);
        }

        let (citrea_idx, move_to_vault_txid, payout_tx_blockhash) =
            unhandled_payout.expect("Must be Some");

        tracing::info!(
            "Unhandled payout found for withdrawal {}, move_txid: {}",
            citrea_idx,
            move_to_vault_txid
        );

        let deposit_data = self
            .db
            .get_deposit_data_with_move_tx(Some(&mut dbtx), move_to_vault_txid)
            .await?;
        if deposit_data.is_none() {
            return Err(eyre::eyre!("Fronted withdrawal for move tx {move_to_vault_txid} found, but the signatures for the deposit are not found in the db.").into());
        }

        let deposit_data = deposit_data.expect("Must be Some");

        let kickoff_txid = self
            .operator
            .handle_finalized_payout(
                &mut dbtx,
                deposit_data.get_deposit_outpoint(),
                payout_tx_blockhash,
            )
            .await?;

        // fetch and save the LCP for if we get challenged and need to provide proof of payout later
        let (_, payout_block_height) = self
            .operator
            .db
            .get_block_info_from_hash(Some(&mut dbtx), payout_tx_blockhash)
            .await?
            .ok_or_eyre("Couldn't find payout blockhash in bitcoin sync")?;

        let _ = self
            .operator
            .citrea_client
            .fetch_validate_and_store_lcp(
                payout_block_height as u64,
                citrea_idx,
                &self.operator.db,
                Some(&mut dbtx),
                self.operator.config.protocol_paramset(),
            )
            .await?;

        #[cfg(feature = "automation")]
        self.operator.end_round(&mut dbtx).await?;

        self.db
            .mark_payout_handled(Some(&mut dbtx), citrea_idx, kickoff_txid)
            .await?;
