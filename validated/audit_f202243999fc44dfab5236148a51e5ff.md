### Title
`SchnorrAggregate::verify` returns `true` for an empty signature set — a vacuous-success forgery analogous to calling a non-existent contract — ([File: crypto/schnorr/src/aggregate.rs])

### Summary
The reported bug class is "a low-level operation returns success on an input that doesn't exist, so a check that was supposed to validate real work is bypassed." In Serai, `SchnorrAggregate::verify` exhibits the same shape: an aggregate signature containing **zero** `R` points and `s = 0` verifies successfully against an empty `keys_and_challenges` list, because the multiexp reduces to `(-0)·G == identity`. The verifier returns `true` without confirming that any signature actually exists.

### Finding Description
`SchnorrAggregate::read` accepts a 4-byte length of `0` followed by a zero scalar, with no minimum-length check:

```rust
// crypto/schnorr/src/aggregate.rs:77-88
pub fn read<R: Read>(reader: &mut R) -> io::Result<Self> {
  let mut len = [0; 4];
  reader.read_exact(&mut len)?;
  let mut Rs = vec![];
  for _ in 0 .. u32::from_le_bytes(len) {
    Rs.push(C::read_G(reader)?);
  }
  Ok(SchnorrAggregate { Rs, s: C::read_F(reader)? })
}
```

`verify` then only checks `Rs.len() == keys_and_challenges.len()` and evaluates `multiexp_vartime(pairs).is_identity()`:

```rust
// crypto/schnorr/src/aggregate.rs:127-146
if self.Rs.len() != keys_and_challenges.len() {
  return false;
}
// digest/weights computed over zero challenges -> no pairs pushed
let mut pairs = Vec::with_capacity((2 * keys_and_challenges.len()) + 1);
for ... { /* never executes */ }
pairs.push((-self.s, C::generator()));
multiexp_vartime(&pairs).is_identity().into()
```

With `Rs = []`, `keys_and_challenges = []`, and `s = 0`, the only pair is `(0, G)`, the multiexp is the identity, and `verify` returns `true`. The function's own doc comment already acknowledges it relies entirely on caller-supplied challenge correctness — but it additionally provides no ground that anything was verified at all. This is exactly the Solmate failure mode: a success value produced for a non-existent object of verification.

An attacker-controlled serialization (`00 00 00 00` + 32 zero bytes for a 32-byte scalar field) is a fully valid encoding reachable via `SchnorrAggregate::read`, i.e. via untrusted bytes.

### Impact Explanation
Any caller that builds `keys_and_challenges` dynamically (e.g., from a filtered or attacker-influenced set of signers/statements) can end up calling `verify` with an empty list; a forged empty aggregate signature then passes verification without any secret knowledge. This is a forged signature acceptance, not merely a correctness footnote: the verifier proves statements about a set that may be empty while returning `true`.

### Likelihood Explanation
Reachability requires a public adversary to cause a `verify` call where the challenge list is empty (or a caller that naïvely trusts `SchnorrAggregate::read` output and `verify` over a computed list). The bug is deterministic — no negligible probability, no collusion, no malicious validator assumption; it is reachable purely through untrusted bytes fed to `read`. Severity is bounded by whether any downstream protocol can be induced into the empty-set state, hence Medium rather than High.

### Recommendation
In `SchnorrAggregate::verify` (or `read`), reject `Rs.is_empty()` — an aggregate of zero signatures should never be considered valid. Optionally also reject `s == 0`. This mirrors the fix in the source report: check that the object actually exists before trusting the success result.

### Proof of Concept
```rust
use ciphersuite::Ciphersuite;
use ciphersuite::dalek_ff_group::Ed25519;
use schnorr::SchnorrAggregate;

// Encoding: len = 0 (u32 LE), s = 0 (32 zero bytes)
let mut bytes = vec![0u8; 4 + 32];

let agg = SchnorrAggregate::<Ed25519>::read(&mut bytes.as_slice()).unwrap();
assert!(agg.Rs().is_empty());

// Vacuously verifies: pairs = [(0, G)] -> multiexp is identity
assert!(agg.verify(b"any-dst", &[]));
```
No private key, nonce, or signature is needed — the verifier reports success over a signature set that does not exist, identically to `safeTransferFrom` returning success against an address with no code.
