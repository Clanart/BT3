### Title
Unauthorized Governance Takeover via Unrestricted `governance.governingnode` Vote Before the Permissionless Fork - (File: `kaiax/gov/headergov/impl/header.go`)

### Summary
In `single` governance mode, the `governance.governingnode` parameter is the on-chain equivalent of a chain-wide "administrator" — it exclusively controls ratification of governance/staking/fee parameters and validator set changes. Before the Permissionless hardfork is active, the vote-authorization and consistency checks in `headerGovModule.VerifyVote`/`checkConsistency` do **not** restrict who may propose a `governance.governingnode` change, nor do they validate the proposed new value. Any council member that is selected as block proposer for a single block can therefore cast (and get ratified) a vote that hands governing-node ("admin") status to an arbitrary address, including one outside the validator council.

### Finding Description
`VerifyVote` only restricts vote authorship to the current governing node when the Permissionless fork is enabled: [1](#0-0) 

Before that fork, any council member acting as the block proposer can write `header.Vote`, including a vote for `gov.GovernanceGoverningNode`, because the only gating in `VerifyVote` is "voter in council" and "voter == block author": [2](#0-1) 

The subsequent `checkConsistency` for `gov.GovernanceGoverningNode` only verifies that the *current* governing node is still in the council. It does not check that the vote's author is the current governing node, and — critically — it skips all validation of the *new* value (`vote.Value()`) unless the Permissionless fork is already active: [3](#0-2) 

Finally, ratification in `getExpectedGovernance` simply collects all votes made during the previous epoch and takes the last value per parameter name, with no re-check that the vote's author was authorized to set that parameter: [4](#0-3) 

Because of this combination, in `single` mode prior to Permissionless, any council member who is ever chosen as a block proposer can:
1. Submit a `governance_vote("governance.governingnode", <arbitrary address>)` via the public `governance_vote` RPC (implemented in `headerGovAPI.Vote`), which only blocks non-governing-node voters when the mode is `single`: [5](#0-4) 
   Note this same "single mode -> must be governing node" gate is applied only at proposal-preparation time to *reject casting the vote for a future header*, but the actual header-embedded vote goes through `VerifyVote`/`checkConsistency` above, which (pre-Permissionless) impose no such author restriction on the `GovernanceGoverningNode` parameter itself.
2. Have that vote embedded in `header.Vote` once they become proposer.
3. Have it ratified into `header.Governance` at the next epoch boundary via `getExpectedGovernance`, with the new (attacker-controlled) address becoming `governance.governingnode` — with no check that this address is even part of the validator council pre-Permissionless.

This grants the attacker exclusive control over ratifying `governance.unitprice`, `kip71.*` base-fee bounds, `reward.*` parameters, and `governance.addvalidator`/`removevalidator` — i.e., full administrative control over the chain's governance and validator set, obtained without ever having been the legitimate governing node.

### Impact Explanation
Gaining `governance.governingnode` status is equivalent to becoming the sole administrator of the chain's governance module. From there the attacker can unilaterally ratify changes to unit price, KIP-71 fee bounds, reward/staking parameters, and validator set membership (`AddValidator`/`RemoveValidator`), enabling fee manipulation, reward redirection, or validator set corruption — all classified as High severity value-movement / consensus-integrity impacts.

### Likelihood Explanation
The pre-Permissionless conditions (single governance mode, fork not yet active) reflect the documented default operating mode ("Mainnet and Kairos both operate in `single` mode"), and the only prerequisite for the attacker is to be a council member who becomes a block proposer once — a routine, expected event in round-robin/sticky/weighted-random proposer selection, not a privileged capability.

### Recommendation
Enforce the "only the governing node may vote/propose `governance.governingnode`" (and other governance/validator parameters in `single` mode) restriction in `VerifyVote`/`checkConsistency` unconditionally, rather than gating it behind `IsPermissionlessForkEnabled`. Additionally, validate the new governing-node address (non-empty, and a council member) in `checkConsistency` regardless of fork status, matching the post-Permissionless checks at [6](#0-5) .

### Proof of Concept
1. Deploy a chain with `governance.governancemode = "single"` and the Permissionless fork not yet activated (default for current Mainnet/Kairos per `kaiax/gov/headergov/README.md`).
2. As any non-governing-node council member, wait to be selected block proposer.
3. Call `governance_vote("governance.governingnode", <attacker_or_arbitrary_address>)` on that node right before it proposes; the produced header's `Vote` field passes `VerifyVote`/`checkConsistency` unchanged since neither checks the vote's author against the current governing node pre-Permissionless.
4. At the next epoch boundary, `getExpectedGovernance` ratifies the last vote for `governance.governingnode` in the epoch, setting it to the attacker's address in `header.Governance`.
5. The attacker's address is now `governance.governingnode` and can single-handedly ratify all further governance/staking/fee/validator-set parameter changes.

```go
func (h *headerGovModule) checkConsistency(blockNum uint64, vote headergov.VoteData) error {
	switch vote.Name() {
	case gov.GovernanceGoverningNode:
		params := h.GetParamSet(blockNum)

		// compare with governing node only in single mode.
		if params.GovernanceMode != "single" {
			return nil
		}

		council, err := h.ValSet.GetCouncil(blockNum)
		if err != nil {
			return err
		}

		if !slices.Contains(council, params.GoverningNode) {
			return ErrGovNodeNotInValSetList
		}
		if !h.ChainConfig.IsPermissionlessForkEnabled(new(big.Int).SetUint64(blockNum)) {
			return nil
		}

		// After Permissionless only the governing node may vote, so a successor outside the council could never vote again.
		newNode, ok := vote.Value().(common.Address)
		if !ok || common.EmptyAddress(newNode) {
			return ErrInvalidKeyValue
		}
		if !slices.Contains(council, newNode) {
			return ErrGovNodeNotInValSetList
		}
		return nil
```

```go
// The blockNum's epoch index must be greater than 0. That is, it must be blockNum >= epoch.
func (h *headerGovModule) getExpectedGovernance(blockNum uint64) headergov.GovData {
	prevEpochIdx := calcEpochIdx(blockNum, h.epoch) - 1
	prevEpochVotes := h.getVotesInEpoch(prevEpochIdx)
	govs := make(gov.PartialParamSet)

	sortedVoteBlocks := slices.Collect(maps.Keys(prevEpochVotes))
	slices.Sort(sortedVoteBlocks)

	for _, voteBlock := range sortedVoteBlocks {
		vote := prevEpochVotes[voteBlock]
		govs.Add(string(vote.Name()), vote.Value())
	}

	// assert(len(headergov.NewGovData(govs).Items()) == len(govs))
	return headergov.NewGovData(govs)
}
```
