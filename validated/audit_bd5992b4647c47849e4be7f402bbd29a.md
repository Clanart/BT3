### Title
Public EVM JSON-RPC endpoints (`eth_sign`, `eth_signTransaction`, `eth_sendTransaction`) sign with any private key found in the node's local `test`-backend keyring, letting any RPC caller impersonate and drain hosted accounts - (File: evmrpc/tx.go, evmrpc/send.go, evmrpc/utils.go)

### Summary
`evmrpc.TransactionAPI.Sign` and `evmrpc.SendAPI.SignTransaction`/`SendTransaction` load the node's local keyring via `getTestKeyring(homeDir)` and, given only a target `from` address supplied by an unauthenticated RPC caller, locate the matching private key with `getAddressPrivKeyMap(kb)` and sign arbitrary data or transactions with it, with no association between the RPC caller's identity and the address being signed for. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
This is analogous to the reported bug class: a stored/cached credential (here, a locally hosted private key) is reachable and usable by a party other than its rightful owner because the credential store is not scoped to the requester's identity. `getTestKeyring` opens the node process's local keyring using `keyring.BackendTest`, and `getAddressPrivKeyMap` decrypts and returns *every* Secp256k1 private key stored in that keyring, keyed by its derived address. `TransactionAPI.Sign` (`eth_sign`) and `SendAPI.signTransaction` (used by both `eth_signTransaction` and `eth_sendTransaction`) then look up the caller-supplied `from`/`addr` in that full map and sign with whatever key matches — there is no check that the RPC session belongs to that account, no per-caller keyring scoping, and no authentication of the RPC request itself. [4](#0-3) 

Any address whose key is present in the node's keyring (e.g. any account an operator, test harness, or another user has ever imported into that node's `test` keyring) can be signed for and its funds moved by an unrelated caller of the public JSON-RPC surface — exactly the "insufficiently protected credentials" pattern in the report, except here the isolation boundary crossed is per-account instead of per-tenant "space."

### Impact Explanation
If the `test` keyring backend is ever populated with a real account's key on a node exposing this RPC surface (e.g., shared devnets/testnets, CI nodes, or misconfigured validator/RPC nodes that reuse `keyring-backend=test` for operational convenience), any unauthenticated RPC client can call `eth_sendTransaction`/`eth_signTransaction`/`eth_sign` with that account's address and have the node sign and broadcast transactions moving its funds — a direct fund-loss vector, not merely information disclosure. This matches the report's "concrete fund loss" bar.

### Likelihood Explanation
Exploitability depends entirely on whether the node's `test`-backend keyring is populated with keys of value and whether the node's EVM RPC surface exposing `eth_sign`/`eth_sendTransaction`/`eth_signTransaction` is reachable by untrusted clients; production mainnet nodes are expected to use `os`/`file` backends and not carry funded keys in `test` keyring. I could not verify from the indexed code whether these RPC methods are gated behind a config flag (e.g., disabled unless `--dev` or `evm-only` test mode) or registered unconditionally on all RPC nodes — the api-registration wiring in `evmrpc/server.go` was only partially inspected before running out of search budget. This uncertainty materially affects likelihood: if these methods are compiled out or disabled by default outside of test harnesses, real-world exploitability is low; test files (`sign-unsupported.io`) suggest the method may return "method not supported" under some configurations. [5](#0-4) 

### Recommendation
- Confirm whether `eth_sign`, `eth_signTransaction`, and `eth_sendTransaction` are enabled on any node configuration that could carry a non-test, funded key in its local keyring, and disable them entirely in production/RPC-public builds.
- If these methods must remain for local dev/test convenience, restrict them to keys explicitly designated for that purpose (never allow blind lookup across the entire keyring), and require the RPC caller to have been authenticated/authorized for the specific address before it is used to sign.
- Consider removing `getAddressPrivKeyMap`'s blanket keyring-wide key enumeration and replace it with an address-scoped lookup that fails closed unless the caller is proven to control that address (e.g., local-only unix-socket restriction, not general JSON-RPC).

### Proof of Concept
1. Start a node with the EVM RPC surface enabled and any account's key present in the local `test`-backend keyring at the node's `homeDir` (this occurs, for example, on shared devnets/CI clusters that use `keyring-backend=test`, as the harness config in `inprocess/harness.go` sets `keyring-backend = "test"` for the RPC client). [6](#0-5) 
2. As an unrelated, unauthenticated RPC client, call:
   ```json
   {"jsonrpc":"2.0","id":1,"method":"eth_sendTransaction","params":[{"from":"<victim_address>","to":"<attacker_address>","value":"0x..."}]}
   ```
3. `SendAPI.SendTransaction` → `signTransaction` loads the full keyring via `getTestKeyring`/`getAddressPrivKeyMap` and, finding `<victim_address>` in the map, signs and broadcasts the transaction, transferring the victim's funds without their authorization. [7](#0-6)

func (t *TransactionAPI) Sign(ctx context.Context, addr common.Address, data hexutil.Bytes) (result hexutil.Bytes, returnErr error) {
	startTime := time.Now()
	defer func() {
		recordMetricsWithError(ctx, "eth_sign", t.connectionType, startTime, returnErr, recover())
	}()
	kb, err := getTestKeyring(t.homeDir)
	if err != nil {
		return nil, err
	}
	for taddr, privKey := range getAddressPrivKeyMap(kb) {
		if taddr != addr.Hex() {
			continue
		}
		dataHash := accounts.TextHash(data)
		return crypto.Sign(dataHash, privKey)
	}
	return nil, errors.New("address does not have hosted key")
}

func (s *SendAPI) SendTransaction(ctx context.Context, args export.TransactionArgs) (result common.Hash, returnErr error) {
	startTime := time.Now()
	defer func() {
		recordMetricsWithError(ctx, "eth_sendTransaction", s.connectionType, startTime, returnErr, recover())
	}()
	if err := args.SetDefaults(ctx, s.backend, false); err != nil {
		return common.Hash{}, err
	}
	var unsignedTx = args.ToTransaction(ethtypes.LegacyTxType)
	signedTx, err := s.signTransaction(unsignedTx, args.From.Hex())
	if err != nil {
		return common.Hash{}, err
	}
	data, err := signedTx.MarshalBinary()
	if err != nil {
		return common.Hash{}, err
	}
	return s.SendRawTransaction(ctx, data)
}

func (s *SendAPI) signTransaction(unsignedTx *ethtypes.Transaction, from string) (*ethtypes.Transaction, error) {
	kb, err := getTestKeyring(s.homeDir)
	if err != nil {
		return nil, err
	}
	privKey, ok := getAddressPrivKeyMap(kb)[from]
	if !ok {
		return nil, errors.New("from address does not have hosted key")
	}
	chainId := s.keeper.ChainID(s.ctxProvider(LatestCtxHeight))
	signer := ethtypes.LatestSignerForChainID(chainId)
	return ethtypes.SignTx(unsignedTx, signer, privKey)
}

func getTestKeyring(homeDir string) (keyring.Keyring, error) {
	clientCtx := client.Context{}.WithViper("").WithHomeDir(homeDir)
	clientCtx, err := config.ReadFromClientConfig(clientCtx)
	if err != nil {
		return nil, err
	}
	return client.NewKeyringFromBackend(clientCtx, keyring.BackendTest)
}

func getAddressPrivKeyMap(kb keyring.Keyring) map[string]*ecdsa.PrivateKey {
	res := map[string]*ecdsa.PrivateKey{}
	keys, err := kb.List()
	if err != nil {
		return res
	}
	for _, key := range keys {
		localInfo, ok := key.(keyring.LocalInfo)
		if !ok {
			// will only show local key
			continue
		}
		if localInfo.GetAlgo() != hd.Secp256k1Type {
			fmt.Printf("Skipping address %s because it isn't signed with secp256k1\n", localInfo.Name)
			continue
		}
		priv, err := legacy.PrivKeyFromBytes([]byte(localInfo.PrivKeyArmor))
		if err != nil {
			continue
		}
		privHex := hex.EncodeToString(priv.Bytes())
		privKey, err := crypto.HexToECDSA(privHex)
		if err != nil {
			continue
		}
		address := crypto.PubkeyToAddress(privKey.PublicKey)
		res[address.Hex()] = privKey
	}
	return res
}
