### Title
JSON Injection via Unescaped `Any.type_url` in PHP ProtoJSON Serialization - ([File: php/src/Google/Protobuf/Internal/Message.php])

### Summary
The PHP implementation's `Message::serializeToJsonStream()` special-cases `google.protobuf.Any` and writes the `type_url` field directly into the output JSON buffer via `writeRaw()` without any JSON string escaping, unlike every other string-valued field in the same codebase (and unlike the C++, C#, Java, and upb JSON encoders), which all route strings through dedicated escaping routines before emission.

### Finding Description
The DataHub CVE's failed invariant was: user-controlled data injected into a JSON string via naive string formatting, without escaping `"`/`\`, allows an attacker to break out of the intended string context and inject sibling keys/values into the JSON object sent downstream — leading to unintended field values reaching the backend.

In this PHP protobuf implementation, `Message::serializeToJsonStream()` [1](#0-0)  handles `Any` specially:
```php
$output->writeRaw("\"@type\":", 8);
$output->writeRaw("\"", 1);
$output->writeRaw($this->getTypeUrl(), strlen($this->getTypeUrl()));
$output->writeRaw("\"", 1);
```
`getTypeUrl()` returns the raw `type_url` string field value [2](#0-1)  with no escaping applied before being written between the surrounding quote characters.

Compare this to the normal string-field path in the same file, `GPBJsonWire`, which always escapes string values with `json_encode($value, JSON_UNESCAPED_UNICODE)` before writing them [3](#0-2) . It is also inconsistent with the upb-backed JSON encoders (used by the PHP C extension and Ruby), which call `jsonenc_string(e, type_url)` — a proper escaping routine — for the identical `@type` field [4](#0-3) [5](#0-4) . The C++ core JSON writer similarly always escapes the type URL through `MakeQuoted`, which calls into `WriteEscapedUtf8` [6](#0-5) [7](#0-6) .

`type_url` is an ordinary `string` field: `setTypeUrl()` only performs a UTF-8 validity check via `GPBUtil::checkString($var, true)`, with no restriction on `"` or `\` characters [8](#0-7) . It can be populated either directly by application code, or indirectly by decoding an attacker-supplied binary/JSON `Any` message (e.g. a message embedded as a submessage field inside a larger message decoded from client-supplied bytes) and then re-serializing that message to JSON for consumption elsewhere. Since `type_url` is documented to be an arbitrary URI string not restricted to `"` or `\` at the pure-PHP layer, an attacker who controls the bytes of an `Any.type_url` (e.g. `type.googleapis.com/foo","injected":"value` ) that later gets echoed back as ProtoJSON output can inject extra top-level JSON keys/values into the emitted object, exactly mirroring the DataHub "format string with user data → JSON string injection" pattern.

### Impact Explanation
If a downstream consumer trusts the ProtoJSON output of a PHP-serialized `Any`-containing message (e.g., forwards it to another JSON-consuming backend, similar to DataHub's AuthServiceClient forwarding crafted JSON to its own backend), the injected `"` in `type_url` breaks the intended string boundary and lets an attacker append or override arbitrary sibling JSON fields in the object being emitted. Depending on what the consuming application does with the additional fields (e.g., authorization flags, role fields), this could enable data integrity violations analogous to the "creation of colliding/attacker-controlled values" in the DataHub bug. Impact is scoped to the pure-PHP (`php/src/Google/Protobuf`) serialization path only — the PHP C extension and other language bindings correctly escape this field, so this is not a universal Protobuf vulnerability, only a differential defect in one backend's ProtoJSON writer.

### Likelihood Explanation
Likelihood is High for consumers relying specifically on the pure-PHP implementation's `serializeToJsonStream()` for `Any` messages that carry `type_url` values derived from untrusted input (parsed from an attacker-supplied message or set directly from an attacker-influenced string). No privileged access is required — an ordinary client providing a message with an `Any` submessage whose `type_url` contains `"` and following JSON reaches this vulnerable code path through the standard, public `serializeToJsonStream`/`Any::pack()`-independent path (i.e., a raw `setTypeUrl()` call or a decoded `Any` from binary input containing a crafted `type_url`).

### Recommendation
Escape `type_url` (and any other raw-`writeRaw` string emissions in `serializeToJsonStream`, such as via `GPBJsonWire::escapedJson()`/`json_encode`) before writing it into the JSON stream, matching the treatment already given to ordinary string fields in `GPBJsonWire` and to `Any.type_url` in the upb and C++ JSON encoders.

### Proof of Concept
Conceptual reproduction using only the pure-PHP implementation (`php/src/Google/Protobuf`, not the C extension):
1. Construct a message containing an `Any` field.
2. Call `setTypeUrl('type.googleapis.com/x","injected":"1')` on the `Any` instance (bypassing `pack()`, which would normally set a safe value, but directly reachable via the public setter or via decoding a crafted binary `Any` submessage from client input).
3. Call `serializeToJsonStream()` (invoked by the public `serializeToJsonString()`/`Message::jsonSerialize` APIs).
4. Observe the emitted JSON contains an injected `"injected":"1"` key at the top level of the `Any` object, because `getTypeUrl()`'s value was written raw between quotes at `php/src/Google/Protobuf/Internal/Message.php:1491-1494` with no escaping of the embedded `"` character.

void JsonWriter::WriteEscapedUtf8(absl::string_view str) {
  while (!str.empty()) {
    static constexpr absl::CharSet kUnsafeChars =
        ~absl::CharSet::AsciiPrintable() | absl::CharSet("\"\\<>");

    auto [safe_prefix, rest] = SplitAtFirst(str, kUnsafeChars);
    if (!safe_prefix.empty()) {
      Write(safe_prefix);
      str = rest;
      if (str.empty()) {
        break;
      }
    }

    auto scalar = ConsumeUtf8Scalar(str);
    absl::string_view custom_escape;

    if (!MustEscape(scalar.u32, custom_escape)) {
      Write(scalar.utf8);
      continue;
    }

    if (!custom_escape.empty()) {
      Write(custom_escape);
      continue;
    }

    if (scalar.u32 < 0x10000) {
      WriteUEscape(scalar.u32);
      continue;
    }

    uint16_t lo =
        (scalar.u32 & (kMaxLowSurrogate - kMinLowSurrogate)) + kMinLowSurrogate;
    uint16_t hi = (scalar.u32 >> 10) +
                  (kMinHighSurrogate - (kMinSupplementaryCodePoint >> 10));
    WriteUEscape(hi);
    WriteUEscape(lo);
  }
