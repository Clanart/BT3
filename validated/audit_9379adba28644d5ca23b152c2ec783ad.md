## Title
Permanent, unauthenticated cache of a GitHub-host determination lets a single spoofed response make Desktop trust an attacker-controlled server as a GitHub Enterprise host forever - ([File: app/src/lib/api.ts])

### Summary
`isGitHubHost()` in `app/src/lib/api.ts` decides whether a remote host should be treated as a trusted GitHub/GitHub Enterprise endpoint. Once a positive determination is made, it is cached indefinitely (`versionCache`/`localStorage`, via `getEndpointVersion`/`updateEndpointVersion` in `app/src/lib/endpoint-capabilities.ts`) with no TTL, no re-validation, and no invalidation path. This is the same broken-invariant pattern as the oracle report: a security-relevant value (host trust) is fetched once, cached, and then reused indefinitely by callers without ever checking whether it is still fresh/valid.

### Finding Description
`isGitHubHost` short-circuits on a cache hit: [1](#0-0) 

`getEndpointVersion` reads from an in-memory `Map` that is populated once and never expires or gets re-checked: [2](#0-1) 

The only way the cache is populated is via a single HEAD request to `${endpoint}/meta`, where TLS certificate errors are explicitly suppressed for the duration of that one request: [3](#0-2) 

`tryUpdateEndpointVersionFromResponse` writes `x-github-enterprise-version` straight from the response headers into the persistent cache with no further verification: [4](#0-3) 

This cached value is then consumed by `getEndpointKind` in the git credential trampoline to decide whether an endpoint is `'enterprise'` (trusted GitHub) or `'generic'` (untrusted third party): [5](#0-4) 

If `getEndpointKind` returns anything other than `'generic'` and no existing account matches the endpoint, `getCredential` triggers `ui.promptForGitHubSignIn(endpoint)`, which routes into the Enterprise OAuth/device sign-in flow (`beginEnterpriseSignIn` / `setSignInEndpoint`) against that endpoint: [6](#0-5) [7](#0-6) 

**Broken invariant**: "an endpoint has been verified to be a real GitHub/GHE host" is treated as permanent truth after a single successful check, when in reality DNS, network position, or the server itself can change at any time. Nothing in the code re-validates the cached determination — there is no expiry, no re-fetch on subsequent uses, and no check that the account/credential still legitimately belongs to that endpoint.

**Why existing guards don't stop this**: The certificate-error suppression (`suppressCertificateErrorFor`) is only meant to avoid noisy cert-error UI for a diagnostic probe, but it means the one-time discovery request accepts a response even from a host presenting an invalid/self-signed certificate — i.e., exactly the situation an on-path attacker (rogue Wi-Fi, corporate proxy compromise, DNS spoof during the user's very first connection to a private/enterprise git remote) is in. Once that single spoofed response includes an `x-github-enterprise-version` header, `updateEndpointVersion` persists it to `localStorage` and the in-memory `versionCache`/`rawVersionCache` — surviving indefinitely, across app restarts, with no mechanism to purge stale/incorrect entries when the attacker is no longer on-path.

### Impact Explanation
An attacker who can transiently intercept the very first HTTPS connection Desktop makes to a given hostname (e.g., during initial repository clone setup on an untrusted network, or via a compromised captive portal/proxy) can permanently poison Desktop's belief that this hostname is a legitimate GitHub Enterprise Server. Later — even after the attacker is no longer on-path and the real server (or a different, non-GitHub server) responds — Desktop will still treat the endpoint as an "enterprise" GitHub host. This can cause Desktop to initiate the GitHub Enterprise OAuth/sign-in flow against that host, and it changes credential handling logic (`storeCredential`/`eraseCredential`/`getCredential`) so that traffic to this host is handled by the "trusted GitHub" code path rather than the generic/untrusted path. This matches the "unauthorized OAuth or account binding" and stale-trust-decision impact classes: a single spoofed network response causes a durable, silent misclassification of trust that outlives the attacker's network position.

### Likelihood Explanation
Requires the attacker to be on-path (or otherwise able to spoof a TLS response, including with an invalid certificate) for a single HTTPS request to `${endpoint}/meta` the first time a user interacts with that hostname in Desktop (e.g., adding a new Enterprise account, or the credential helper probing an unrecognized HTTPS remote). This is a plausible network-attacker scenario (public Wi-Fi, compromised local network, malicious VPN/proxy) rather than requiring local machine access, malware, or leaked credentials — consistent with the "git remote/proxy response" attacker model. The persistence-without-expiry nature significantly raises severity because the window of attack (one MITM'd request) produces a permanent effect.

### Recommendation
- Do not cache `isGitHubHost`/enterprise-version determinations across app sessions in a way that skips future authenticity checks; treat the cached value only as a hint and periodically (or per credential-relevant operation) re-verify it with a fresh, certificate-validated request.
- Do not suppress certificate errors when using the response to make persistent trust decisions; if certificate error suppression is required for UX reasons, do not feed the resulting response into `updateEndpointVersion`/host-trust caches.
- Add explicit invalidation (e.g., tie the cache entry to the TLS certificate/public key seen, or expire after a bounded TTL) so a single spoofed response cannot produce indefinite trust.

### Proof of Concept
1. Attacker gains on-path position for the user's network (rogue AP, ARP/DNS spoofing, malicious proxy) before the user has ever connected Desktop to `git.internal-corp.example`.
2. User adds `git.internal-corp.example` as a remote or Enterprise account in Desktop. Desktop's credential trampoline calls `getEndpointKind` → `isGitHubHost('https://git.internal-corp.example')`.
3. Because no cached version exists yet, Desktop issues `HEAD https://git.internal-corp.example/meta` with certificate errors suppressed (`suppressCertificateErrorFor`). The attacker intercepts this and returns a response with `x-github-enterprise-version: 3.10.0` and `x-github-request-id` headers, using a self-signed certificate (accepted because errors are suppressed for this URL).
4. `tryUpdateEndpointVersionFromResponse` → `updateEndpointVersion` persists this into `localStorage` and `versionCache` permanently.
5. Attacker leaves the network. Weeks later, `getEndpointVersion(endpoint) !== null` returns true unconditionally in every subsequent `isGitHubHost` call for that host, so Desktop continues to treat it as a genuine GitHub Enterprise host and drives credential/sign-in flows (`getEndpointKind` → `'enterprise'` → `promptForGitHubSignIn`) accordingly, without ever re-checking the server's authenticity.

Note: I was not able to trace the full downstream OAuth device-flow code path (`beginEnterpriseSignIn`) in this pass to confirm exactly what data would be sent to the poisoned endpoint versus GitHub.com's OAuth broker; that would need further review (e.g., a Devin session with full repo access) to fully quantify token/credential exposure versus just an incorrect UI/flow classification.

export function getEndpointVersion(endpoint: string) {
  const key = endpointVersionKey(endpoint)
  const cached = versionCache.get(key)

  if (cached !== undefined) {
    return cached
  }

  const raw = localStorage.getItem(key)
  const parsed = raw === null ? null : semver.parse(raw)

  if (parsed !== null) {
    versionCache.set(key, parsed)
  }

  return parsed
}

/**
 * Update the known version number for a given endpoint
 */
export function updateEndpointVersion(endpoint: string, version: string) {
  const key = endpointVersionKey(endpoint)

  if (rawVersionCache.get(key) !== version) {
    const parsed = semver.parse(version)
    localStorage.setItem(key, version)
    rawVersionCache.set(key, version)
    versionCache.set(key, parsed)
  }
}

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
