### Title
Unauthenticated `internal_get_emergency_stop_tx` RPC leaks emergency-stop transactions when `client_verification = false` - ([File: core/src/rpc/interceptors.rs], [File: core/src/servers.rs])

### Summary
When an aggregator is deployed with `config.client_verification == false`, `create_grpc_server` installs `Interceptors::Noop`, which performs zero authentication/authorization on any RPC call, including methods intended to be restricted to internal (self-to-self) use via the `Internal` method-name convention checked by `only_aggregator_and_self`/`is_internal`. This lets any anonymous TCP client invoke `AggregatorServer::internal_get_emergency_stop_tx` and pull the stored (encrypted) emergency-stop transaction bytes for arbitrary move-to-vault txids.

### Finding Description
The intended binding is: **caller authority == is_internal(req) (self-only)**, enforced only by `only_aggregator_and_self` in [1](#0-0) . That function checks `leaf_cert == our_cert` for methods whose gRPC path starts with `"Internal"` [2](#0-1) .

`create_grpc_server` only installs `OnlyAggregatorAndSelf` when `config.client_verification` is `true`; otherwise it installs `Interceptors::Noop`, which simply returns `Ok(req)` for every request with no identity check whatsoever [3](#0-2) [4](#0-3) .

With Noop installed, `AggregatorServer::internal_get_emergency_stop_tx` is directly reachable by anyone who can open a TCP/TLS connection to the aggregator's port (TLS server identity is still presented, but no client certificate is required or checked). The handler parses attacker-supplied txids and returns whatever is stored in the `emergency_stop_sigs` table for those txids with no authorization gate at all [5](#0-4) [6](#0-5) .

This confirms the claimed CALLER_AUTHORITY break: the party invoking an `Internal`-prefixed method is not restricted to the aggregator/self as the naming convention and `is_internal` check intend — the restriction is simply never applied under this configuration.

### Impact Explanation
The returned column/field is named `emergency_stop_tx` / `encrypted_emergency_stop_txs`, which is consistent with the transaction bytes being encrypted (the config exposes an `emergency_stop_encryption_public_key` used elsewhere) rather than a raw broadcastable transaction. I was not able to fully trace the encryption/decryption path in the remaining tool budget, so I cannot confirm whether the leaked bytes are directly broadcastable by an outside attacker or require a private key held only by the security council. This materially affects severity:
- If the bytes are plaintext-broadcastable Bitcoin transactions, the attacker gains the ability to broadcast an emergency-stop transaction ahead of schedule and freeze a move-to-vault UTXO — a Critical-tier impact under the stated impact list.
- If the bytes are genuinely encrypted to a security-council key the attacker doesn't hold, the practical impact is limited to premature disclosure of the existence/ciphertext of a protocol commitment tied to specific move-to-vault txids (High-tier "premature disclosure of a protocol commitment"), without directly enabling broadcast.

Either way, the authorization bypass itself (Noop skipping all checks for `Internal`-prefixed RPCs, contrary to the method-naming/authorization convention enforced by `only_aggregator_and_self`) is a real, demonstrable defect reachable by an unauthenticated network attacker whenever `client_verification=false`, and is repeatable across every move-to-vault deposit whose txid the attacker can harvest from the Bitcoin chain.

### Likelihood Explanation
Requires the aggregator to be run with `client_verification=false` (this is the value set unless explicitly overridden, e.g., in `core/src/test/data/bridge_config.toml` and `scripts/docker/configs/testnet4/bridge_config.toml`, per the earlier grep). Confirming whether this is the shipped/production-recommended default (as opposed to a test-only convenience setting) requires reviewing the full config defaults and deployment docs, which I could not fully complete in the remaining tool budget. The attacker only needs network access to the aggregator's gRPC port and the ability to scan Bitcoin for N-of-N deposit scripts to harvest txids — no BTC spend or fee cost is required for the RPC call itself.

### Recommendation
Do not gate `Internal`-prefixed methods purely on whether TLS client verification is globally enabled. Either (a) reject/deny all `Internal`-prefixed RPCs unconditionally when `Interceptors::Noop` is active (fail closed instead of fail open), or (b) always require and check a peer certificate for `Internal` methods regardless of `client_verification`, so that disabling general client verification cannot silently disable the self-only restriction on internal RPCs.

### Proof of Concept
Not verifiable to a Critical/High-confidence conclusion within the available tooling — specifically, I could not confirm (1) whether `client_verification=false` is a documented default for production aggregator deployments versus a test-only setting, and (2) whether `encrypted_emergency_stop_txs` is genuinely encrypted such that an outside attacker cannot decrypt/broadcast it. A `cargo test` under `core/src/test` starting `create_grpc_server`/`create_aggregator_grpc_server` with `client_verification=false`, connecting via a `tonic::Channel` with no client certificate, and asserting `internal_get_emergency_stop_tx` succeeds would confirm the authorization bypass itself, but per the rules such tests are out of scope for citation/inclusion and the downstream broadcastability of the leaked bytes still needs to be established by tracing the emergency-stop-tx encryption code path (e.g., in `core/src/builder/transaction/mod.rs`) before a Critical/High severity determination can be made with full confidence.

}

    async fn internal_get_emergency_stop_tx(
        &self,
        request: Request<clementine::GetEmergencyStopTxRequest>,
    ) -> Result<Response<clementine::GetEmergencyStopTxResponse>, Status> {
        tracing::warn!("Get emergency stop tx rpc called");
        let inner_request = request.into_inner();
        let txids: Vec<Txid> = inner_request
            .txids
            .into_iter()
            .map(|txid| {
                Txid::from_slice(&txid.txid).map_err(|e| {
                    tonic::Status::invalid_argument(format!("Failed to parse txid: {e}"))
                })
            })
            .collect::<Result<Vec<_>, _>>()?;
        tracing::warn!(
            "Parsed get emergency stop tx rpc params, move txids: {:?}",
            txids
                .iter()
                .map(|txid| txid.to_string())
                .collect::<Vec<_>>()
        );

        let emergency_stop_txs = self.db.get_emergency_stop_txs(None, txids).await?;

        let (txids, encrypted_emergency_stop_txs): (Vec<Txid>, Vec<Vec<u8>>) =
            emergency_stop_txs.into_iter().unzip();

        Ok(Response::new(clementine::GetEmergencyStopTxResponse {
            txids: txids.into_iter().map(|txid| txid.into()).collect(),
            encrypted_emergency_stop_txs,
        }))
    }

    /// Gets emergency stop transactions for a list of move transaction IDs
    pub async fn get_emergency_stop_txs(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        move_txids: Vec<Txid>,
    ) -> Result<Vec<(Txid, Vec<u8>)>, BridgeError> {
        if move_txids.is_empty() {
            return Ok(Vec::new());
        }

        let mut query_builder = QueryBuilder::new(
            "SELECT move_txid, emergency_stop_tx FROM emergency_stop_sigs WHERE move_txid IN (",
        );

        let mut separated = query_builder.separated(", ");
        for txid in &move_txids {
            separated.push_bind(TxidDB(*txid));
        }
        query_builder.push(")");

        let query = query_builder.build_query_as::<(TxidDB, Vec<u8>)>();

        let results: Vec<(TxidDB, Vec<u8>)> =
            execute_query_with_tx!(self.connection, tx, query, fetch_all)?;

        Ok(results
            .into_iter()
            .map(|(txid, tx_data)| Ok((txid.0, tx_data)))
            .collect::<Result<_, eyre::Report>>()?)
    }
