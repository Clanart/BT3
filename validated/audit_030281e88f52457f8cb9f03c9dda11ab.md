## Title
Privileged "hidden puzzle" holder can unilaterally spend, redirect, or burn any user's RCAT/CR-CAT coin without their consent - (File: chia/wallet/vc_wallet/vc_drivers.py, chia/wallet/cat_wallet/r_cat_wallet.py)

## Summary
Chia's `RCATWallet` (Revocable CAT) and the underlying `VerifiedCredential` (VC) "provider backdoor" both wrap a user's inner puzzle in a `REVOCATION_LAYER` that is curried with a `hidden_puzzle_hash`. Whoever controls the pre-image of that `hidden_puzzle_hash` (typically the CAT issuer / DID provider) can spend the coin via the "hidden" solution path and unilaterally dictate its output conditions - including bricking the value or redirecting/burning it - without any signature or consent from the actual coin owner. This is structurally analogous to the `EthErc20.forceBurn()` `BURNER_ROLE` finding: a single privileged, centrally-controlled key can act on an arbitrary user's asset that it does not own.

## Finding Description
`create_revocation_layer` curries a `hidden_puzzle_hash` and the real owner's `inner_puzzle_hash` into the `REVOCATION_LAYER` puzzle: [1](#0-0) 

`RCATWallet` wraps every CAT coin's inner puzzle this way, with `hidden_puzzle_hash` chosen once at wallet/asset creation: [2](#0-1) 

The `solve_revocation_layer` solution takes a `hidden` boolean flag; when set, the spender supplies the hidden puzzle reveal instead of the owner's real inner puzzle, and that hidden puzzle's output conditions become the coin's spend conditions - completely bypassing the owner's actual inner puzzle/signature: [3](#0-2) 

The test suite explicitly demonstrates this "backdoor" mechanic: the hidden-puzzle holder spends a coin owned by an arbitrary control puzzle (`ACS`) and dictates an arbitrary output (creating a "brick" with amount 0, i.e. effectively burning/zeroing the value) without needing the owner's real inner puzzle signature at all: [4](#0-3) 

The same backdoor pattern is used by `VerifiedCredential.activate_backdoor`, where the DID provider can revoke/seize control of a user's VC singleton coin outside of the normal spend flow: [5](#0-4) 

## Impact Explanation
Any holder of the `hidden_puzzle_hash` pre-image (the issuer that minted the R-CAT, or the DID provider for a VC) can spend a user's coin outside of the owner's control, dictating arbitrary output conditions - up to and including creating a zero-value/"bricked" output that destroys the economic value of that specific coin, or redirecting it. This is a direct coin-level analog to `forceBurn`: an unprivileged holder's assets can be unilaterally destroyed or redirected by a centrally-configured privileged key, without the coin owner's signature or consent.

## Likelihood Explanation
This requires the asset (R-CAT or VC) to have been configured by its issuer with attacker-controlled/compromised `hidden_puzzle_hash` semantics, and only affects coins of that specific asset type. It does not affect ordinary CATs/XCH. Within the scope of R-CAT/VC holders, however, every single coin of that asset is reachable by the privileged party at any time with a simple, one-step spend bundle - identical to the disputed-but-validated SKALE finding, where the judge held that role/configuration-contingent centralization risk is still a valid Medium finding.

## Recommendation
- Clearly document and enforce that `hidden_puzzle_hash` for R-CATs and the provider backdoor for VCs are intentional, opt-in issuer/provider privileges, and ensure wallets prominently warn users before accepting such assets that a third party can revoke/brick their coin.
- Consider requiring an explicit user-side commitment/acknowledgement (e.g., recorded consent) before a wallet will hold R-CAT/VC-backed value, and provide tooling to easily detect the `hidden_puzzle_hash` a given coin is bound to before accepting funds.

## Proof of Concept [6](#0-5) 
The `test_revocation_layer` test creates a coin whose inner puzzle is `ACS` (accept-any-conditions) wrapped by `create_revocation_layer(hidden_puzzle_hash, ACS_PH)`. The test then spends this coin using only the `hidden_puzzle` (never touching `ACS`/the "owner" path) and successfully creates a new coin with amount `0` at an arbitrary `brick_hash`, i.e. the hidden-puzzle holder alone destroyed the value of a coin that, in a real deployment, would belong to an ordinary R-CAT holder.

def create_revocation_layer(hidden_puzzle_hash: bytes32, inner_puzzle_hash: bytes32) -> Program:
    return REVOCATION_LAYER.curry(
        REVOCATION_LAYER_HASH,
        hidden_puzzle_hash,
        inner_puzzle_hash,
    )


def match_revocation_layer(uncurried_puzzle: UnknownPuzzle) -> tuple[bytes32, bytes32] | None:
    if uncurried_puzzle.mod == REVOCATION_LAYER and uncurried_puzzle.curried_args is not None:
        return (
            bytes32(uncurried_puzzle.curried_args[1].as_atom()),
            bytes32(uncurried_puzzle.curried_args[2].as_atom()),
        )
    else:
        return None  # pragma: no cover


def solve_revocation_layer(puzzle_reveal: Program, inner_solution: Program, hidden: bool = False) -> Program:
    solution: Program = Program.to(
        [
            hidden,
            puzzle_reveal,
            inner_solution,
        ]
    )
    return solution

@pytest.mark.anyio
async def test_revocation_layer(cost_logger: CostLogger) -> None:
    async with sim_and_client() as (sim, client):
        # Setup and farm the puzzle
        hidden_puzzle: Program = Program.to((1, [[61, 1]]))  # assert a coin announcement that the solution tells us
        hidden_puzzle_hash: bytes32 = hidden_puzzle.get_tree_hash()
        p2_either_puzzle: Program = create_revocation_layer(hidden_puzzle_hash, ACS_PH)
        assert match_revocation_layer(UnknownPuzzle(known_program=p2_either_puzzle)) == (hidden_puzzle_hash, ACS_PH)

        await sim.farm_block(p2_either_puzzle.get_tree_hash())
        p2_either_coin: Coin = (
            await client.get_coin_records_by_puzzle_hashes(
                [p2_either_puzzle.get_tree_hash()], include_spent_coins=False
            )
        )[0].coin

        # Reveal the wrong puzzle
        result: tuple[MempoolInclusionStatus, Err | None] = await client.push_tx(
            WalletSpendBundle(
                [
                    make_spend(
                        p2_either_coin,
                        p2_either_puzzle,
                        solve_revocation_layer(
                            ACS,
                            Program.NIL,
                            hidden=True,
                        ),
                    )
                ],
                G2Element(),
            )
        )
        assert result == (MempoolInclusionStatus.FAILED, Err.GENERATOR_RUNTIME_ERROR)

        # Spend the hidden puzzle (make announcement fail)
        result = await client.push_tx(
            WalletSpendBundle(
                [
                    make_spend(
                        p2_either_coin,
                        p2_either_puzzle,
                        solve_revocation_layer(
                            hidden_puzzle,
                            Program.to(bytes32.zeros),
                            hidden=True,
                        ),
                    )
                ],
                G2Element(),
            )
        )
        assert result == (MempoolInclusionStatus.FAILED, Err.ASSERT_ANNOUNCE_CONSUMED_FAILED)

        # Spend the inner puzzle
        brick_hash: bytes32 = bytes32.zeros
        wrapped_brick_hash: bytes32 = create_revocation_layer(
            hidden_puzzle_hash,
            brick_hash,
        ).get_tree_hash()
        result = await client.push_tx(
            cost_logger.add_cost(
                "Viral backdoor spend - one create coin",
                WalletSpendBundle(
                    [
                        make_spend(
                            p2_either_coin,
                            p2_either_puzzle,
                            solve_revocation_layer(
                                ACS,
                                Program.to([[51, brick_hash, 0]]),
                            ),
                        )
                    ],
                    G2Element(),
                ),
            )
        )
        assert result == (MempoolInclusionStatus.SUCCESS, None)

        await sim.farm_block()

        assert len(await client.get_coin_records_by_puzzle_hashes([wrapped_brick_hash], include_spent_coins=False)) > 0
