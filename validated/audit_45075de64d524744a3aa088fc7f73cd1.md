### Title
Panic in `GeneratorPromotion::complete` via a proof map keyed under an unexpected `Participant` index - (File: crypto/dkg/promote/src/lib.rs)

### Summary
`GeneratorPromotion::complete` iterates over every participant index `1..=n` and calls `proofs.get(&i).unwrap()`. The only validation beforehand is that `proofs.len() == n - 1` and that every key is `<= n`. Nothing checks that the keys are exactly the expected set `{1..=n} \ {params.i()}`. A `proofs` map that substitutes the victim's own index `params.i()` (or any duplicate of another index) for a real participant passes both checks and then hits a `None.unwrap()` panic — a remotely triggerable denial of service, the analog of the Net-SNMP NULL-pointer dereference crash from CVE-2022-44793: malformed externally supplied data reaches a dereference/unwrap of absent state.

### Finding Description [1](#0-0) 

At `crypto/dkg/promote/src/lib.rs:125-136` the function validates:
- `proofs.len() == n - 1` (line 125)
- every key `<= n` (line 133)

Then at line 140-146 it loops `for i in 1 ..= params.n()`, skips `params.i()`, and does `proofs.get(&i).unwrap()`. If the map contains `params.i()` as a key (n-1 entries, all `<= n`), one legitimate participant `j` is necessarily missing, and `proofs.get(&j)` returns `None`, causing an unconditional panic. `unwrap()` on an attacker-influenced `HashMap` lookup is the Rust equivalent of the unvalidated dereference in `handle_ipv6IpForwarding`.

### Impact Explanation
`GeneratorPromotion` is in-scope (`crypto/dkg` family, `promote`) and processes per-participant `GeneratorProof` messages — inputs supplied by other DKG participants, i.e., untrusted parties the protocol is explicitly designed to survive (all other faults produce `PromotionError`). A single participant who registers their proof under the victim's `Participant` index (or otherwise arranges a map missing one participant while containing a spurious in-range key) crashes the victim's process instead of producing a `PromotionError`, aborting the key-promotion ceremony and denying service. A crash on crafted input maps directly to the CVE's impact (remote DoS via malformed packet → NULL deref crash). Severity: Medium.

### Likelihood Explanation
Triggering requires only that a counterparty's proof be inserted into the `proofs` map under a wrong-but-in-range `Participant` index — a one-field deviation from honest behavior with no cryptographic barrier. No collusion, no valid proof forgery, and no secret knowledge is needed; the panic occurs before any `DLEqProof::verify` call for the missing index. Likelihood is bounded only by requiring an active (misbehaving) participant in the promotion round, which is the standard threat model for this library.

### Recommendation
Replace the `unwrap()` at `crypto/dkg/promote/src/lib.rs:146` with a checked lookup that returns `Err(PromotionError::MissingParticipant(i))` (a variant like `DkgError`/`PedPoPError::MissingParticipant` already exists in sibling crates), or pre-validate that `proofs.keys()` equals `all_participant_indexes() minus params.i()`. The same pattern (`enc_keys`/`commitments`/`shares[&l]` indexing) is used elsewhere in the DKG crates under `validate_map` guards that do verify exact membership — `promote` simply lacks that guard.

### Proof of Concept
```rust
// Assume a 3-of-3 promotion where the victim is participant i = 1 (params.n() = 3).
// A malicious participant sends their GeneratorProof under the victim's index.
// The caller builds:
let mut proofs: HashMap<Participant, GeneratorProof<C1>> = HashMap::new();
proofs.insert(Participant::new(1).unwrap(), attacker_proof); // victim's own index
proofs.insert(Participant::new(2).unwrap(), p2_proof);       // honest participant 2
// participant 3's proof is absent
assert_eq!(proofs.len(), params.n() as usize - 1); // passes: 2 == 2
// all keys <= n                                    // passes
promotion.complete(&proofs);
// loop reaches i = 3 -> proofs.get(&Participant(3)) == None -> panic at line 146
```

The panic occurs at `crypto/dkg/promote/src/lib.rs:146` (`let proof = proofs.get(&i).unwrap();`), reachable purely from counterparty-controlled map construction, converting a malformed-input case that should be `PromotionError::MissingParticipant` into a process crash.
