## Finding

### Title
`IntentGatewayV2.onAccept` (Tron variant) authorizes governance actions by source chain only, not module identity — allowing unauthorized `UpdateParams`/`NewDeployment`/`SweepDust` execution - (File: `evm/tron/contracts/apps/IntentGatewayV2.sol`)

### Summary
The M-3 report's core invariant is "critical parameters get changed with no tracking/binding to who is allowed to change them." The Tron `IntentGatewayV2.onAccept` has a stronger version of that same defect: the governance-only branches (`UpdateParams`, `NewDeployment`, `SweepDust`) authorize purely by comparing the incoming request's `source` chain id to the configured Hyperbridge chain id, never checking `incoming.request.from` (the sending module/pallet identity on that chain).

### Finding Description
In `onAccept`, escrow paths call `authenticate(incoming.request)`, which validates that `request.from` matches a known `IntentGatewayV2` instance address via `instance(request.source)`: [1](#0-0) 

But the governance-only branches skip this and instead only check:
```solidity
if (keccak256(incoming.request.source) != keccak256(IDispatcher(host()).hyperbridge())) revert Unauthorized();
``` [2](#0-1) 

This confirms only that the message *originated from the Hyperbridge state machine*, never verifying *which module on that chain* sent it. Any account or contract on the Hyperbridge chain capable of dispatching an ISMP `PostRequest` targeting this gateway's address (with `source` correctly reflecting the Hyperbridge chain id, which is intrinsic to the chain the request comes from, not attacker-controlled) can set an arbitrary `from` field, since `from` identifies the sending application/pallet and is not restricted to the trusted `intents-coprocessor` pallet by this contract. As a result, `_params` (host, dispatcher, `protocolFeeBps`, `surplusShareBps`, `priceOracle`), `_instances` (trusted deployment registry used by `authenticate()` for escrow redemption), and dust-sweep beneficiaries can all be attacker-controlled without ever compromising governance, a relayer, or an admin key.

This directly maps to the required pivot: *"Cross-chain admin or host-management effects must not be reachable through malformed proofs, wrong module bindings, or unauthenticated message flow."*

By contrast, the mainline EVM `EvmHost.updateHostParams` requires `restrict(_hostParams.hostManager)` — i.e., binds to a specific authorized contract address, not merely a chain id: [3](#0-2) 

The Tron `IntentGatewayV2` never performs an equivalent module-address check for its own governance branches.

### Impact Explanation
- `UpdateParams` lets an attacker rewrite `_params.priceOracle`, `_params.dispatcher`, `_params.protocolFeeBps`/`surplusShareBps`, redirecting fee flows or bricking pricing/fee logic used in `placeOrder`/`fillOrder`.
- `NewDeployment` lets an attacker register an arbitrary address as the trusted `IntentGatewayV2` instance for any `stateMachineId`, which is exactly the value `authenticate()` trusts to release escrow (`RedeemEscrow`/`RefundEscrow`) — enabling theft of all future escrowed order funds routed through that "instance."
- `SweepDust` lets an attacker drain any protocol-owned dust balances directly to an attacker-chosen beneficiary.

This satisfies "stealing or loss of funds," "unauthorized transaction or execution," and "false proof/state acceptance" (accepting a message as authentic governance when it is not).

### Likelihood Explanation
The check only inspects `request.source` (immutable/chain-derived) and never `request.from` (application/pallet-derived, attacker-influenced depending on what the Hyperbridge-side dispatch primitive permits). Any path on the Hyperbridge chain that allows submitting an outbound ISMP `PostRequest` addressed to this Tron gateway with a chosen `from` value defeats the authorization entirely — no relayer collusion, no proof forgery, and no admin key compromise is required; the flaw is in the destination contract's own authorization logic.

### Recommendation
Bind governance-only branches (`UpdateParams`, `NewDeployment`, `SweepDust`) to a specific trusted module address on the Hyperbridge chain (e.g., the `intents-coprocessor` pallet id), analogous to `authenticate()`'s `instance(...)` check or `EvmHost`'s `restrict(_hostParams.hostManager)` pattern, instead of only validating the source chain id. Additionally, emit events for every `_params`/`_instances` mutation with old/new values (matching the M-3 recommendation) so any unauthorized change is detectable off-chain even before the authorization fix lands.

### Proof of Concept
1. Attacker (any account able to submit an ISMP outbound dispatch from the Hyperbridge chain, setting `from` to an arbitrary module identifier) constructs a `PostRequest` with:
   - `source` = Hyperbridge state machine id (matches `IDispatcher(host()).hyperbridge()`)
   - `dest`/`to` = the Tron `IntentGatewayV2` address
   - `from` = any value (not checked)
   - `body` = `bytes1(uint8(RequestKind.UpdateParams)) || abi.encode(ParamsUpdate({params: maliciousParams, destinationFees: []}))`
2. Relayer delivers the message; the local `IsmpHost` calls `onAccept` on the Tron gateway.
3. `onAccept` reaches the `kind == RequestKind.UpdateParams` branch: `keccak256(incoming.request.source) == keccak256(hyperbridge())` passes (true, since it only checks chain id), so `_params = update.params` is applied with attacker-chosen `priceOracle`/`dispatcher`/fee values, with no verification that `incoming.request.from` was the legitimate `intents-coprocessor` pallet.
4. Subsequent `placeOrder`/`fillOrder` calls now use attacker-controlled pricing/dispatch/fee configuration, or `NewDeployment` can be used to register a malicious "instance," which `authenticate()` will trust for future escrow releases. [4](#0-3)

     * @dev Checks that the request originates from a known instance of the IntentGateway.

    function authenticate(PostRequest calldata request) internal view {
        if (request.from.length != 20) revert InvalidInput();
        address module = address(bytes20(request.from));
        // IntentGateway only accepts incoming assets from itself or known instances
        if (instance(request.source) != module) revert Unauthorized();
    }

    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost {
        RequestKind kind = RequestKind(uint8(incoming.request.body[0]));
        if (kind == RequestKind.RedeemEscrow || kind == RequestKind.RefundEscrow) {
            authenticate(incoming.request);
            WithdrawalRequest memory body = abi.decode(incoming.request.body[1:], (WithdrawalRequest));
            return withdraw(body, kind == RequestKind.RefundEscrow);
        }

        // only hyperbridge is permitted to perfom these actions
        if (keccak256(incoming.request.source) != keccak256(IDispatcher(host()).hyperbridge())) revert Unauthorized();
        if (kind == RequestKind.NewDeployment) {
            NewDeployment memory body = abi.decode(incoming.request.body[1:], (NewDeployment));
            _instances[keccak256(body.stateMachineId)] = body.gateway;

            emit NewDeploymentAdded({stateMachineId: body.stateMachineId, gateway: body.gateway});
        } else if (kind == RequestKind.UpdateParams) {
            // Decode the body which includes optional destination-specific protocol fee updates
            ParamsUpdate memory update = abi.decode(incoming.request.body[1:], (ParamsUpdate));
            emit ParamsUpdated({previous: _params, current: update.params});
            _params = update.params;

            // Update destination-specific protocol fees if provided
            for (uint256 i; i < update.destinationFees.length;) {
                bytes32 stateMachineId = update.destinationFees[i].stateMachineId;
                uint256 feeBps = update.destinationFees[i].destinationFeeBps;
                _destinationProtocolFees[stateMachineId] = feeBps;

                unchecked {
                    ++i;
                }
                emit DestinationProtocolFeeUpdated(stateMachineId, feeBps);
            }
