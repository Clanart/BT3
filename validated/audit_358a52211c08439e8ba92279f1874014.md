### Title
Auctioneer signature does not bind to bid content, allowing metadata (e.g. `MaxGasPrice`) to be modified after signing without invalidating either signature - ([File: kaiax/auction/bid.go])

### Summary
The auction module's bid verification consists of two signatures: the searcher's EIP-712 signature over the bid content, and the auctioneer's signature that is only computed over the raw bytes of the searcher's signature (`GetEthSignedMessageHash`), not over the bid content itself. Separately, the searcher's own EIP-712 v2.1 struct hash (`auctionType`) omits the `MaxGasPrice` field entirely. As a result, `MaxGasPrice` metadata attached to a bid is not cryptographically bound by either signature when the v2.1 typehash is used, mirroring the GitLab CVE-2023-2030 pattern where signature verification did not cover all of the object's metadata, allowing that metadata to be altered post-signature while the signature still validates.

### Finding Description
`Bid.ValidateSearcherSig` recovers the signer from `GetHashTypedData(chainId, verifyingContract, version)` [1](#0-0) . For `AuctionVersionV2` ("0.0.1"), `GetHashTypedData` uses the plain `Bid.EncodeData()` struct hash [2](#0-1) , whose EIP-712 type string is `auctionType = "AuctionTx(bytes32 targetTxHash,uint256 blockNumber,address sender,address to,uint256 nonce,uint256 bid,uint256 callGasLimit,bytes data)"` and whose `EncodeData()` implementation likewise excludes `MaxGasPrice` [3](#0-2) . Only the newer `bidV3` typehash (`AuctionVersionV3`) includes `maxGasPrice` in both the type string and `EncodeData()` [4](#0-3) .

Separately, `Bid.ValidateAuctioneerSig` verifies the auctioneer's signature against `GetEthSignedMessageHash()`, which is computed purely from the bytes of `b.SearcherSig` — not from the bid's content fields at all: 
```go
func (b *Bid) GetEthSignedMessageHash() []byte {
	data := b.SearcherSig
	return crypto.Keccak256(fmt.Appendf(nil, "\x19Ethereum Signed Message:\n%d%s", len(data), data))
}
``` [5](#0-4) 

`BidPool.validateBidSigs` only calls `ValidateSearcherSig` (against the version-selected EIP-712 digest) and `ValidateAuctioneerSig` (against `GetEthSignedMessageHash`) [6](#0-5) . Neither check binds `MaxGasPrice` when `AuctionVersionV2` is active, since:
1. The searcher's EIP-712 digest for v2 never includes `MaxGasPrice`.
2. The auctioneer's signature only ever covers `SearcherSig` bytes, never any bid field directly, in any version.

`MaxGasPrice` is nonetheless a load-bearing field: it is marshaled into the RPC input structure `BidInput` and `ToBid` [7](#0-6) , and it is packed into the on-chain `call(AuctionTx)` calldata sent to the `AuctionEntryPoint` contract via `EncodeAuctionCallData` when v3 is active [8](#0-7) . Since the bid pool's signature checks (`validateBidSigs`) are version-based but the same `Bid` struct/RLP encoding carries `MaxGasPrice` regardless of version, and since `BidData` (including `MaxGasPrice`) is what gets gossiped, hashed for pool de-duplication (`bid.Hash()`), and eventually turned into on-chain calldata, an entity that controls submission of the bid to the node (e.g., a malicious/compromised RPC caller submitting via `auction_submitBid`, or a party who intercepts/relays a legitimately double-signed v2 bid) can attach or tamper with `MaxGasPrice` without invalidating `SearcherSig` or `AuctioneerSig`, because that field is outside what either signature actually authenticates under the v2.1 typehash.

### Impact Explanation
`MaxGasPrice` is intended to cap the gas price the searcher authorizes for their auction transaction. If it can be forged or removed post-signature (while the two required signatures still validate), a third party could submit a bid to the entry-point contract with a different/absent gas-price ceiling than what the searcher actually authorized, or bypass a protection the searcher/auctioneer expected to be cryptographically enforced. This falls under fee/auction settlement abuse: the bid's economic terms (via `MaxGasPrice`) diverge from what was actually signed, since the searcher's EIP-712 signature (v2.1) never covers it and the auctioneer's signature never covers any bid field. Given the module's own bindings show the same `Bid` object being encoded/decoded across ABI versions with `MaxGasPrice` preserved or dropped depending on version selection [9](#0-8) , this is a genuine metadata-integrity gap analogous to CVE-2023-2030.

### Likelihood Explanation
Exploitability depends on the currently-active `AuctionVersion` reported by the `AuctionEntryPoint` contract (`ReadAuctionVersion`) [10](#0-9) . While V3 is deployed, this is not exploitable because `MaxGasPrice` is included in the typehash. However, as long as V2.1 (`AuctionVersionV2`, the default fallback for "unknown version") remains supported/active on any deployment, or if `MaxGasPrice` is used/read by any tooling irrespective of protocol version, the gap is directly reachable by any unprivileged bid submitter through the public `auction_submitBid` RPC, requiring no special network position — only crafting a bid whose `MaxGasPrice` differs from what the searcher intended while reusing valid `SearcherSig`/`AuctioneerSig` bytes.

### Recommendation
Include `MaxGasPrice` in the EIP-712 type string and `EncodeData()` for all active/legacy auction versions (or reject/zero `MaxGasPrice` entirely when version v2.1 is active), and bind the auctioneer's approval to the actual bid content (e.g., sign the full EIP-712 digest or a hash of `BidData`, not merely the searcher's signature bytes) so both signatures fully commit to every field that is consumed downstream (calldata encoding, gas price capping, etc.).

### Proof of Concept
1. Attacker crafts a bid identical to a legitimately signed v2.1 bid `(TargetTxHash, BlockNumber, Sender, To, Nonce, Bid, CallGasLimit, Data)` and copies the victim's valid `SearcherSig` and `AuctioneerSig` unchanged.
2. Attacker sets `MaxGasPrice` to an arbitrary value (or a value different from what the searcher/auctioneer agreed upon out-of-band) since it is not part of the v2.1 `auctionType` struct hash — see `auctionType` omitting `maxGasPrice` [11](#0-10) .
3. Submit via `auction_submitBid` (`ToBid`) [12](#0-11) ; `BidPool.validateBidSigs` calls `ValidateSearcherSig`/`ValidateAuctioneerSig`, both of which pass because neither covers `MaxGasPrice` [6](#0-5) .
4. The tampered bid, with attacker-controlled `MaxGasPrice`, is accepted into the bid pool and later encoded into on-chain calldata via `EncodeAuctionCallData`, differing from what either signer actually authenticated.

func (b *Bid) ValidateSearcherSig(chainId *big.Int, verifyingContract common.Address, version string) error {
	if chainId == nil {
		return ErrNilChainId
	}

	if common.EmptyAddress(verifyingContract) {
		return ErrNilVerifyingContract
	}

	digest := b.GetHashTypedData(chainId, verifyingContract, version)

	recoveredSender, err := getSigner(b.SearcherSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover searcher sig: %v", err)
	}

	if recoveredSender != b.Sender {
		return fmt.Errorf("invalid searcher sig: expected %v, calculated %v", b.Sender.String(), recoveredSender.String())
	}

	return nil
}

func (d EIP712Domain) EncodeData() []byte {
	encoded := make([]byte, 0)
	encoded = append(encoded, d.NameHash.Bytes()...)
	encoded = append(encoded, d.VersionHash.Bytes()...)
	encoded = append(encoded, common.LeftPadBytes(d.ChainId.Bytes(), 32)...)

// GetHashTypedData returns the EIP-712 digest for the bid.
// version must match the on-chain AUCTION_VERSION of the entry-point contract
// the bid targets; "0.0.2" selects the v3.0 struct typehash (with maxGasPrice),
// any other value falls back to the v2.1 typehash.
func (b *Bid) GetHashTypedData(chainId *big.Int, verifyingContract common.Address, version string) []byte {
	if chainId == nil {
		return nil
	}

	domain := EIP712Domain{
		EIP712DomainTypeHash: eip712TypeHash,
		NameHash:             auctionNameHash,
		VersionHash:          crypto.Keccak256Hash([]byte(version)),
		ChainId:              chainId,
		VerifyingContract:    verifyingContract,
	}

	domainSeparator := EncodeEIP712(domain)

	var structHash []byte
	if version == AuctionVersionV3 {
		structHash = EncodeEIP712(bidV3{b})
	} else if version == AuctionVersionV2 {
		structHash = EncodeEIP712(b)
	} else {
		// Unknown version: default to v2.1 typehash.
		structHash = EncodeEIP712(b)
	}

	return crypto.Keccak256([]byte{0x19, 0x01}, domainSeparator, structHash)
}

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}

// ReadAuctionVersion reads the AUCTION_VERSION view from the given entry-point
// contract. The result distinguishes v2.1 ("0.0.1") from v3.0 ("0.0.2") so
// callers can pick the appropriate EIP-712 typehash and ABI.
//
// The v3.0 binding is used for the call: AUCTION_VERSION() is a public-constant
// getter with the same selector on both v2.1 and v3.0 contracts, so the same
// typed binding works against either deployment.
func ReadAuctionVersion(backend bind.ContractCaller, contractAddr common.Address, num *big.Int) (string, error) {
	caller, err := contractsv3.NewIAuctionEntryPointCaller(contractAddr, backend)
	if err != nil {
		return "", err
	}
	return caller.AUCTIONVERSION(&bind.CallOpts{BlockNumber: num})
}

func EncodeAuctionCallData(bid *auction.Bid, version string) ([]byte, error) {

		maxGasPrice := bid.MaxGasPrice
		if maxGasPrice == nil {
			maxGasPrice = new(big.Int)
		}
		input := contractsv3.IAuctionEntryPointAuctionTx{
			TargetTxHash:  bid.TargetTxHash,
			BlockNumber:   new(big.Int).SetUint64(bid.BlockNumber),
			Sender:        bid.Sender,
			To:            bid.To,
			Nonce:         new(big.Int).SetUint64(bid.Nonce),
			Bid:           bid.Bid,

			CallGasLimit:  new(big.Int).SetUint64(bid.CallGasLimit),
			Data:          bid.Data,
			SearcherSig:   bid.SearcherSig,
			AuctioneerSig: bid.AuctioneerSig,
		}

	}
