### Title
Unbounded index read on truncated CLVM puzzle/solution bytes in `is_atom_canonical` can raise an uncaught `IndexError` during spend-bundle admission - ([File: chia/full_node/mempool_manager.py])

### Summary
`MempoolManager.validate_spend_bundle` calls `is_clvm_canonical()` on the raw `puzzle_reveal` and `solution` bytes of every coin spend in a submitted `SpendBundle` before any other sanity check absorbs malformed length-prefix encodings. [1](#0-0)  The canonical-encoding check walks the buffer byte-by-byte using raw `bytes` indexing with no bounds checking against the declared multi-byte atom length prefix. [2](#0-1) 

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads the leading byte to determine how many additional length-prefix bytes follow (`prefix_len` up to 5), then loops `for i in range(prefix_len): offset += 1; atom_len |= clvm_buffer[offset]`. [3](#0-2)  If an attacker crafts a `puzzle_reveal` or `solution` whose final byte announces a multi-byte length prefix (e.g. the `0b11110000` pattern requiring 3 more prefix bytes) but the buffer ends before those bytes exist, indexing `clvm_buffer[offset]` past the end of a Python `bytes` object raises `IndexError`, which is an exception class not explicitly caught anywhere in this call path. `is_clvm_canonical()` itself has the same unguarded pattern in its outer loop (`b = clvm_buffer[offset]` on each iteration, with `offset` advanced by `is_atom_canonical`'s returned `atom_len`, which can also point past the buffer end for the *next* iteration). [4](#0-3) 

This check runs inside `MempoolManager.validate_spend_bundle`, invoked from `FullNode.add_transaction` via `MempoolManager.add_spend_bundle` under `blockchain.priority_mutex` — a path reachable from an unprivileged submitter via the RPC `push_tx` endpoint or the peer-facing `send_transaction`/`respond_transaction` handlers. [5](#0-4) [6](#0-5)  Unlike `pre_validate_spendbundle`, which is wrapped in a `try/except ValueError`/`except ValidationError` block in `add_transaction`, the `validate_spend_bundle` call that performs the `is_clvm_canonical` checks is not guarded by any such handler at this layer. [7](#0-6) 

This mirrors the CoreDNS bug class: a single crafted, short, malformed input (there a 28-byte PPv2 datagram; here a truncated CLVM atom length-prefix in a submitted spend) triggers an unguarded out-of-bounds/nil-like access deep in a low-level parsing routine before any higher-level validation/recovery wrapper can absorb it.

### Impact Explanation
If this uncaught `IndexError` propagates out of `validate_spend_bundle` while holding `blockchain.priority_mutex`, it can abort the low-priority transaction-processing coroutine mid-mutation and potentially leave mempool/lock state inconsistent, or (depending on asyncio task-exception handling at the call site) crash the processing task, producing a transaction-processing halt from a single spend-bundle submission — the "spend-triggered transaction-processing halt" impact class explicitly in scope.

### Likelihood Explanation
I could not fully confirm, within the available tool budget, whether an outer exception handler exists further up the call stack around `add_spend_bundle`/`validate_spend_bundle` (I found the `try/except` only around `pre_validate_spendbundle`, not around the later `add_spend_bundle` call at chia/full_node/full_node.py:3098). Without confirming whether `IndexError` is caught generically somewhere (e.g. an asyncio task-exception logger) versus truly crashing the mempool-processing path, the severity is uncertain — this needs verification in a live/full checkout, ideally with a Devin session that can run the full test suite and reproduce with a truncated `puzzle_reveal`/`solution` byte sequence.

### Recommendation
Add explicit bounds checks in `is_atom_canonical` and `is_clvm_canonical` before each `clvm_buffer[offset]` access (verifying `offset < len(clvm_buffer)`), returning "not canonical" instead of raising, and wrap `MempoolManager.add_spend_bundle`/`validate_spend_bundle` invocation in `FullNode.add_transaction` with a broad exception boundary so malformed submitted bytes cannot escape as unhandled exceptions.

### Proof of Concept
Construct a `CoinSpend` whose `puzzle_reveal` (or `solution`) serialized bytes end with a byte matching the `0b11110000` (or similar wide-prefix) pattern but with fewer trailing bytes than `prefix_len` requires (e.g., a 1-byte buffer `b"\xf0"` mimicking the length-prefix-needs-3-more-bytes case), place it in coin_spends of a `SpendBundle`, and submit via `push_tx` RPC; `is_clvm_canonical()` called from `validate_spend_bundle` will index past the buffer end and raise `IndexError`. Exact call-stack behavior (whether caught vs. crashing) needs live verification, which is not confirmable from static indexing alone.

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

```python
    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
