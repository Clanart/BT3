### Title
Attacker-controlled `_minMGPRec` combined with unprotected spot-price swap in `_bullMGP` allows flash-loan price manipulation to drain protocol MGP reserves via inflated `bullBonusRatio` payout - (File: `wombat/ArbWomUp2.sol`)

### Summary
`incentiveDeposit(_amount, _minMGPRec, _bullMode)` lets a caller set `_bullMode = true`, which routes their fixed BUSD reward through `_bullMGP`, a direct call to `ROUTER.swapExactTokensForTokens` using an attacker-supplied `_minMGPRec` as the only slippage protection. Since the caller both chooses the acceptable minimum and can manipulate the BUSD/MGP pool price in the same transaction (flash loan), the router's real-time spot price can be pushed to return an inflated `amounts[1]`, which directly inflates `mgpAmountToLcok = amounts[1] * (DENOMINATOR + bullBonusRatio) / DENOMINATOR` locked to the attacker via `vlMGP.lockFor`.

### Finding Description
`incentiveDeposit` computes a fixed BUSD `rewardToSend` from a tier table, independent of `_minMGPRec` or `_bullMode` [1](#0-0) . When `_bullMode` is true, this fixed BUSD amount is swapped for MGP:

```solidity
uint256[] memory amounts = ROUTER.swapExactTokensForTokens(
    _busdAmount, _minRec, path, address(this), block.timestamp
);
uint256 mgpAmountToLcok = amounts[1] * (DENOMINATOR + bullBonusRatio) / DENOMINATOR;
IERC20(mgp).approve(address(vlMGP), mgpAmountToLcok);
vlMGP.lockFor(mgpAmountToLcok, _account);
``` [2](#0-1) 

`vlMGP.lockFor` (`VLMGP._lock`) executes `MGP.safeTransferFrom(spender=ArbWomUp2, address(this), _amount)` [3](#0-2) , meaning `ArbWomUp2` must actually hold `mgpAmountToLcok` MGP — the portion above `amounts[1]` (the `bullBonusRatio` bonus) is paid out of the contract's own pre-funded MGP balance/reserve, not newly minted or sourced from the swap alone.

Because `_minRec` (`_minMGPRec`) is fully attacker-controlled and the swap uses the AMM's live spot price with no oracle/TWAP sanity check or maximum-output cap, an attacker can, within a single transaction: (1) flash-loan and dump MGP into the BUSD/MGP pool used by `ROUTER` to depress MGP's price relative to BUSD, (2) call `incentiveDeposit(amount, 0 or low _minMGPRec, true)` so the fixed `rewardToSend` BUSD buys an inflated quantity of MGP (`amounts[1]`) at the manipulated price, (3) restore the pool price and repay the flash loan. The inflated `amounts[1]` then inflates `mgpAmountToLcok` proportionally, so the protocol locks (and pays out from its own reserve) far more MGP for the attacker than the fixed BUSD reward is fairly worth. `nonReentrant`/`whenNotPaused` do not prevent this since it's a single, non-reentrant call; there is no price-deviation or oracle check anywhere in the path.

### Impact Explanation
This allows an unprivileged attacker to extract MGP from the protocol's reserve disproportionate to the BUSD reward actually consumed, directly draining protocol-owned MGP that would otherwise back `bullBonusRatio` incentives for legitimate users — a theft of protocol funds/unclaimed yield (Immunefi: "Direct theft of protocol funds"/"theft of unclaimed yield").

### Likelihood Explanation
Requires: (a) a qualifying WOM deposit to trigger a nonzero `rewardToSend`, (b) flash-loan capital against the specific BUSD/MGP pool wired into `ROUTER`, and (c) that pool having exploitable liquidity depth relative to `rewardToSend`. All of this is achievable by any EOA with no special privileges and is fully repeatable per qualifying deposit, making this an economically feasible, low-capital (flash-loanable) attack once a suitable low-liquidity BUSD/MGP pool is targeted.

### Recommendation
Do not let users control `_minMGPRec`/swap slippage for a system-funded bonus payout. Compute the swap's minimum acceptable output from a manipulation-resistant reference (e.g., TWAP oracle or a protocol-configured price band), cap `amounts[1]` used for bonus calculation to a fair-value ceiling, and/or remove attacker ability to influence which price is used to size `mgpAmountToLcok`.

### Proof of Concept
Foundry fork test:
1. Deploy `ArbWomUp2` wired to a real/mock PancakeSwap-style `ROUTER` and BUSD/MGP pool, fund the contract with WOM reward tiers, BUSD, and a MGP reserve balance for bonus payouts.
2. Attacker acquires a qualifying WOM deposit amount to generate `rewardToSend`.
3. Attacker flash-loans BUSD/MGP pool tokens, swaps to depress MGP price against BUSD.
4. Attacker calls `incentiveDeposit(amount, 0, true)`.
5. Record `amounts[1]` returned by `ROUTER.swapExactTokensForTokens` inside `_bullMGP` and compare `mgpAmountToLcok` against the MGP amount that `rewardToSend` BUSD would buy at the pre-manipulation (fair) price.
6. Attacker unwinds the sandwich, repays flash loan.
7. Assert `mgpAmountToLcok` (and the attacker's `vlMGP` locked balance) materially exceeds the fair-market MGP value of `rewardToSend`, and that the excess was funded from `ArbWomUp2`'s own MGP balance (`IERC20(mgp).balanceOf(address(ArbWomUp2))` decreases by more than `amounts[1]`'s bonus share expected at fair price).

        uint256 _amount, uint256 _minMGPRec, bool _bullMode
    ) external _checkAmount(_amount) whenNotPaused nonReentrant {

        _deposit(_amount);

        if (_bullMode) {
            _bullMGP(rewardToSend, _minMGPRec, msg.sender);
        } else {
            IERC20(busd).transfer(msg.sender, rewardToSend);
            emit BUSDRewarded(msg.sender, rewardToSend);
        }
    }
