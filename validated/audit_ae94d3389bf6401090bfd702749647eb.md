## Title
Any transient RocksDB/blockstore error while deciding a single pending informed-repair event permanently kills `BlockIdRepairService`, blocking all queued (non-erroring) repair events indefinitely - (File: core/src/repair/block_id_repair_service.rs)

## Summary
`BlockIdRepairService::run_repair_iteration` batches all pending informed-repair events (`RepairEvent::FetchBlock`) each loop and decides per-event whether to keep waiting, drop, or act. If evaluating *any single* event returns a `BlockstoreError`, the entire iteration aborts and the outer service loop breaks, terminating the repair thread for the life of the process — exactly mirroring the Perennial bug-class where an issue with one "requested" item permanently blocked processing of all other unrelated ("non-requested") queued items.

## Finding Description
`run_repair_iteration` collects decisions for every event in `state.pending_repair_events` via `retain`, calling `decide_pending_repair_event` for each: [1](#0-0) 

Once any single call to `decide_pending_repair_event` returns `Err`, `first_error` is set, all *remaining* events in this pass are short-circuited back to `KeepPending` (harmless), but critically the function itself propagates the error out of `run_repair_iteration`: [2](#0-1) 

The caller treats any such error as fatal: [3](#0-2) 

`decide_pending_repair_event` itself calls several blockstore lookups (`get_slot_meta_for_block_id`, `is_dead`, `get_double_merkle_root`) that can legitimately return `BlockstoreError` (e.g., `RocksDb`, `Io`, `WincodeRead/Write`) under ordinary operational conditions such as disk I/O hiccups, concurrent slot purges by `replay_stage`'s `clear_slots`/`dump_slots` racing with this read path, or other transient storage faults: [4](#0-3) [5](#0-4) 

Because a single failed evaluation for one event (analogous to a stuck "requested version") kills the whole service, every other pending event in the queue — including ones that were otherwise ready to `Act` (start repair / queue parent) — is never processed again. There is no retry-and-continue semantics; the thread simply exits.

## Impact Explanation
`BlockIdRepairService` is the mechanism by which a validator fetches alternate/duplicate versions of blocks needed for votor's `SafeToNotar`, switch-to-fork, and duplicate-block resolution flows (see callers in `votor/src/consensus_pool_service.rs` and `core/src/replay_stage.rs`, which enqueue `RepairEvent::FetchBlock` and depend on repair completing to emit `SafeToNotar`/`ParentReady`/fork-switch events). If this thread dies, the affected validator permanently loses the ability to repair alternate block versions for the remainder of the process lifetime, which can prevent it from resolving duplicate-block/fork-switch situations, stalling its own voting/consensus participation for those slots — a liveness degradation on the affected node, directly analogous to the Perennial bug where liquidations were blocked because one stuck requested item prevented processing of all others.

## Likelihood Explanation
This requires only an ordinary transient blockstore error (I/O error, RocksDB error, deserialization error) occurring while evaluating one queued repair event — a condition that is plausible during normal validator operation (disk contention, concurrent slot purge/dump races with `clear_slots`) and does not require a malicious peer, validator, or admin action. Given the current code, this is a single-event-triggered, whole-thread-fatal condition, so likelihood is moderate but the design is unconditionally fragile: there is no isolation between the failure domain of one event and the rest of the queue.

## Recommendation
Do not propagate a per-event `BlockstoreError` out of `run_repair_iteration` as fatal to the whole service. Instead:
- Log the error and drop/keep-pending only the offending event, allowing other independent events in `pending_repair_events` to continue being decided and acted upon in the same and subsequent iterations.
- Only treat truly unrecoverable errors (if any exist) as fatal, and reserve `Ok(false)`/thread exit for channel disconnection conditions, as already done elsewhere in the same function.

## Proof of Concept
1. Enqueue multiple independent `RepairEvent::FetchBlock` events for different blocks/slots into `BlockIdRepairService` (e.g., via votor's `process_pending_safe_to_notar` repair-event channel).
2. Cause `Blockstore::get_slot_meta_for_block_id` (or `is_dead`/`get_double_merkle_root`) to return `Err` for exactly one of the queued events — this can occur naturally from a RocksDB error or from a slot being concurrently purged by `replay_stage::clear_slots` while `decide_pending_repair_event` is mid-lookup for that slot.
3. Observe that `run_repair_iteration` returns `Err`, the outer loop in `BlockIdRepairService::run` logs "Blockstore error, exiting" and `break`s, terminating the `solBlockIdRep` thread.
4. All other pending `FetchBlock` events for unrelated, healthy slots — which had no error and were ready to be acted upon — are never processed for the remainder of the validator's process lifetime, since the thread that processes `state.pending_repair_events` no longer runs.

    /// Decide if we should keep a pending repair event or if we should act
    fn decide_pending_repair_event(
        my_pubkey: &Pubkey,
        event: RepairEvent,
        root: Slot,
        blockstore: &Blockstore,
        requested_blocks: &HashSet<Block>,
    ) -> Result<PendingRepairDecision, BlockstoreError> {
        if event.slot() <= root {
            return Ok(PendingRepairDecision::Drop);
        }

        match event {
            RepairEvent::FetchBlock { block } => {
                if requested_blocks.contains(&block) {
                    return Ok(PendingRepairDecision::Drop);
                }

                // Check if we already have the full block, if so queue fetching the parent.
                if let Some((slot_meta, _location)) =
                    blockstore.get_slot_meta_for_block_id(block.slot, block.block_id)?
                {
                    return Ok(PendingRepairDecision::Act(RepairAction::QueueParent {
                        slot_meta,
                    }));
                }

                // We don't have the block. Check if turbine failed (dead)
                // Note: we require the invariant that Turbine + Eager repair will either:
                // - Eventually fill in all shreds for a slot (slot_meta.is_full()) resulting in the DMR calculation
                // - Mark the slot as dead
                if blockstore.is_dead(block.slot) {
                    info!(
                        "{my_pubkey}: FetchBlock: slot {} is dead, starting repair for \
                         block_id={:?}",
                        block.slot, block.block_id
                    );
                    return Ok(PendingRepairDecision::Act(RepairAction::StartRepair {
                        block,
                    }));
                }

                // Turbine did not fail, check the progress
                match blockstore.get_double_merkle_root(block.slot, BlockLocation::Original)? {
                    None => {
                        // Turbine has not completed, defer and check again later
                        debug!(
                            "{my_pubkey}: FetchBlock: Turbine not complete for slot {}, deferring",
                            block.slot
                        );
                        Ok(PendingRepairDecision::KeepPending)
                    }
                    Some(turbine_block_id) if turbine_block_id != block.block_id => {
                        // Turbine has a different block
                        warn!(
                            "{my_pubkey}: FetchBlock: Turbine has different block \
                             {turbine_block_id:?} vs requested block {block:?}, starting repair"
                        );
                        Ok(PendingRepairDecision::Act(RepairAction::StartRepair {
                            block,
                        }))
                    }
                    Some(_) => {
                        // Turbine completed between when we checked for the block above and here
                        // Queue the parent
                        debug!(
                            "{my_pubkey}: FetchBlock: Turbine has correct block for slot {}, \
                             fetching parent",
                            block.slot
                        );
                        if let Some((slot_meta, _location)) =
                            blockstore.get_slot_meta_for_block_id(block.slot, block.block_id)?
                        {
                            Ok(PendingRepairDecision::Act(RepairAction::QueueParent {
                                slot_meta,
                            }))
                        } else {
                            Ok(PendingRepairDecision::KeepPending)
                        }
                    }
                }
            }
