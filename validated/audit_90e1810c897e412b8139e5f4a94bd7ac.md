### Title
Balance-handler `prevEventsLen` corruption on reentrant precompile calls causes StateDB/bank-keeper balance desync - (File: `precompiles/common/balance_handler.go`)

### Summary
The Cosmos EVM analog of the `assetsUtilized`/`whitelistUpdate()` bug (reading a derived accounting value without first refreshing the underlying state that produced it) is the `BalanceHandler` used by stateful precompiles to reconcile native `x/bank` coin movements into the EVM `StateDB`. `BalanceHandler.BeforeBalanceChange` [1](#0-0)  stores a single `prevEventsLen` checkpoint, and `AfterBalanceChange` [2](#0-1)  replays only the events emitted after that checkpoint into `StateDB.AddBalance`/`SubBalance`. If a precompile call re-enters (a precompile call triggers another precompile call before the outer one finishes, e.g. via nested `CallEVM`/`RunNativeAction`), and the `BalanceHandler` instance is not properly scoped per call, the inner call's `BeforeBalanceChange` overwrites `prevEventsLen` to a later index. When the outer call's `AfterBalanceChange` finally executes, it uses the now-advanced `prevEventsLen`, silently skipping the bank events that occurred between the outer checkpoint and the inner checkpoint — those coin-spent/coin-received/fractional-balance events are never applied to `StateDB`.

### Finding Description
The repository itself documents this exact defect class: an integration test explicitly titled "tests the balance handler bug where recursive precompile calls share the same BalanceHandler instance, causing `prevEventsLen` to be overwritten... leads to balance desync between native bank keeper and EVM stateDB" [3](#0-2) . The mechanics: `runNativeAction` in `precompiles/common/precompile.go` calls `balanceHandler.BeforeBalanceChange(ctx)` immediately before invoking the precompile's native action, and `balanceHandler.AfterBalanceChange(ctx, stateDB)` immediately after [4](#0-3) . This pairing assumes the `BalanceHandler` instance used for `Before`/`After` is exclusively owned by a single, non-reentrant precompile invocation. The debug/test precompile pattern (`p.GetBalanceHandler()`), and the generic factory pattern (`p.BalanceHandlerFactory.NewBalanceHandler()`), are the two code paths that determine whether a fresh handler is minted per call or a shared handler is reused. The test suite constructs a scenario deliberately using recursive precompile calls (`callback` on a caller contract invoking the debug precompile multiple times) and observes a mismatch in expected debug-precompile call counts (`10` vs `15` events) [5](#0-4) , consistent with the accounting-corruption class described.

Because `AfterBalanceChange` is the sole mechanism translating native bank-module `CoinSpent`/`CoinReceived`/`FractionalBalanceChange` events into `StateDB.AddBalance`/`SubBalance` calls [6](#0-5) , any window of events silently excluded due to a corrupted `prevEventsLen` means the EVM-visible balance of the sender/receiver diverges from the true bank-keeper balance for the remainder of the transaction (and permanently once `StateDB.Commit()` persists the desynced values back into `x/vm`/`x/bank` storage via `commitWithCtx` [7](#0-6) ).

### Impact Explanation
This maps to the "Critical unauthorized minting/duplication/irreversible accounting corruption of spendable user value across native balances, EVM balances… precompile-mediated assets" gate. A missed `CoinSpent` event means a spender's StateDB balance is never decremented even though real coins left their bank account, permitting the EVM-visible balance to exceed the actual backing bank balance — enabling double-spend of the same native coins from within the EVM (e.g., across chained precompile calls such as staking/distribution/ics20/gov precompiles that all use `BalanceHandlerFactory`, per the grep results showing this pattern is shared across `distribution.go`, `erc20.go`, `gov.go`, `ics20.go`, `slashing.go`, `staking.go`). Conversely, a missed `CoinReceived` event under-credits StateDB for a receiver despite real coins landing in their bank account, causing loss/freezing of spendable value from the EVM's perspective. Once committed, this corruption is written into persistent state and is not self-healing.

### Likelihood Explanation
Reachability depends on whether reentrant/recursive precompile invocations within a single EVM transaction actually share one `BalanceHandler` instance rather than instantiate a fresh one per call. The generic `RunNativeAction` path explicitly creates `balanceHandler = p.BalanceHandlerFactory.NewBalanceHandler()` fresh inside `runNativeAction` [8](#0-7) , which — if truly scoped per invocation — would not exhibit this bug for that code path. However, the repository's own test explicitly demonstrates and names this bug against the debug-precompile handler pattern, indicating at least one precompile registration path (or an older/parallel code path such as `p.GetBalanceHandler()`) reuses a single handler across nested calls. I was not able to fully inspect `evmd/tests/testdata/debug/debug.go`'s `GetBalanceHandler()` implementation before the tool budget ran out, so I cannot confirm with certainty whether this shared-instance pattern also exists in any of the production precompiles (`distribution`, `erc20`, `gov`, `ics20`, `slashing`, `staking`) or is confined to the test-only debug precompile. This is the key uncertainty: if only the test/debug precompile has a shared (non-factory) handler, the bug is a testing artifact, not a production vulnerability, and the impact would not meet the Critical bar for unprivileged, production-reachable exploitation.

### Recommendation
Regardless of which precompiles are ultimately affected, enforce that each precompile invocation obtains a strictly call-scoped `BalanceHandler` (never a receiver-level cached field), and defensively harden `AfterBalanceChange`/`BeforeBalanceChange` to be reentrancy-safe — e.g., by tracking event-index checkpoints on a call stack rather than a single scalar field, or by re-deriving `prevEventsLen` relative to the events already consumed by nested calls rather than absolute event-manager length. Add an invariant check post-`AfterBalanceChange` that reconciles the sum of applied `StateDB` balance deltas against the bank-module event log length actually consumed, failing the transaction if any events in the recorded window were skipped.

### Proof of Concept
The repository's own regression test is the concrete PoC skeleton: deploy `DebugPrecompileCaller`, register the debug precompile with a `BalanceHandler`, call `callback(0)` which recursively invokes the debug precompile through the caller contract, and observe the mismatch between expected total precompile invocations/events (`15` total events, `10` `debug_precompile` events) versus what a correctly-scoped `BeforeBalanceChange`/`AfterBalanceChange` pairing would produce [9](#0-8) . Extending this test to fund the caller contract, perform a value-transferring precompile action (e.g., `staking.Delegate` or `bank`-precompile equivalent) inside the recursive callback, and then diff `StateDB.GetBalance` against `x/bank`'s `GetBalance` for the sender/receiver after `Commit()` would demonstrate the exact corrupted value and confirm whether production precompiles are exposed. I was unable to complete this verification within the available tool budget; a Devin session with full file access (particularly `evmd/tests/testdata/debug/debug.go`'s `GetBalanceHandler()` and each production precompile's `NewPrecompile` constructor for `BalanceHandlerFactory` wiring) would be required to confirm whether this is exploitable via any non-test precompile.

func (bh *BalanceHandler) AfterBalanceChange(ctx sdk.Context, stateDB *statedb.StateDB) error {
	events := ctx.EventManager().Events()

	for _, event := range events[bh.prevEventsLen:] {
		switch event.Type {
		case banktypes.EventTypeCoinSpent:
			spenderAddr, err := ParseAddress(event, banktypes.AttributeKeySpender)
			if err != nil {
				return fmt.Errorf("failed to parse spender address from event %q: %w", banktypes.EventTypeCoinSpent, err)
			}
			if bh.bankKeeper.BlockedAddr(spenderAddr) {
				// Bypass blocked addresses
				continue
			}

			amount, err := ParseAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", banktypes.EventTypeCoinSpent, err)
			}

			stateDB.SubBalance(common.BytesToAddress(spenderAddr.Bytes()), amount, tracing.BalanceChangeUnspecified)

		case banktypes.EventTypeCoinReceived:
			receiverAddr, err := ParseAddress(event, banktypes.AttributeKeyReceiver)
			if err != nil {
				return fmt.Errorf("failed to parse receiver address from event %q: %w", banktypes.EventTypeCoinReceived, err)
			}
			if bh.bankKeeper.BlockedAddr(receiverAddr) {
				// Bypass blocked addresses
				continue
			}

			amount, err := ParseAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", banktypes.EventTypeCoinReceived, err)
			}

			stateDB.AddBalance(common.BytesToAddress(receiverAddr.Bytes()), amount, tracing.BalanceChangeUnspecified)

		case precisebanktypes.EventTypeFractionalBalanceChange:
			addr, err := ParseAddress(event, precisebanktypes.AttributeKeyAddress)
			if err != nil {
				return fmt.Errorf("failed to parse address from event %q: %w", precisebanktypes.EventTypeFractionalBalanceChange, err)
			}
			if bh.bankKeeper.BlockedAddr(addr) {
				// Bypass blocked addresses
				continue
			}

			delta, err := ParseFractionalAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", precisebanktypes.EventTypeFractionalBalanceChange, err)
			}

			deltaAbs, err := utils.Uint256FromBigInt(new(big.Int).Abs(delta))
			if err != nil {
				return fmt.Errorf("failed to convert delta to Uint256: %w", err)
			}

			if delta.Sign() == 1 {
				stateDB.AddBalance(common.BytesToAddress(addr.Bytes()), deltaAbs, tracing.BalanceChangeUnspecified)
			} else if delta.Sign() == -1 {
				stateDB.SubBalance(common.BytesToAddress(addr.Bytes()), deltaAbs, tracing.BalanceChangeUnspecified)
			}

// commitWithCtx writes the dirty states to keeper
// using the provided context
func (s *StateDB) commitWithCtx(ctx sdk.Context) error {
	for _, addr := range s.journal.sortedDirties() {
		obj := s.stateObjects[addr]
		if obj.selfDestructed {
			if err := s.keeper.DeleteAccount(ctx, obj.Address()); err != nil {
				return errorsmod.Wrapf(err, "failed to delete account %s", obj.Address())
			}
		} else {
			if obj.code != nil && obj.dirtyCode {
				if len(obj.code) == 0 {
					s.keeper.DeleteCode(ctx, obj.CodeHash())
				} else {
					s.keeper.SetCode(ctx, obj.CodeHash(), obj.code)
				}
			}
			if err := s.keeper.SetAccount(ctx, obj.Address(), obj.account); err != nil {
				return errorsmod.Wrap(err, "failed to set account")
			}

			for _, key := range obj.dirtyStorage.SortedKeys() {
				valueBytes := obj.dirtyStorage[key].Bytes()
				if len(valueBytes) == 0 {
					s.keeper.DeleteState(ctx, obj.Address(), key)
				} else {
					s.keeper.SetState(ctx, obj.Address(), key, valueBytes)
				}
			}
		}
	}
	return nil
