### Title
Identity ECDH point in PedPoP yields an all-zero shared secret and a publicly derivable ChaCha20 key for secret-share encryption - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
The netty advisory's bug class — a cryptographic operation that, on a "failure" input, yields a known/all-zero buffer which is then used directly as key material — maps onto PedPoP's ECDH. A participant's registered encryption key `enc_key` is read with `C::read_G` (the bare `Ciphersuite` reader), which accepts the identity point. `ecdh()` then computes `key * identity = identity`, `ecdh.to_bytes()` is the all-zero Ristretto encoding, and the resulting transcript challenge produces a deterministic, publicly computable ChaCha20 key encrypting every FROST secret share addressed to that participant.

### Finding Description
`EncryptionKeyMessage::read` deserializes the per-participant encryption key via `C::read_G(reader)` where `C: Ciphersuite` (`crypto/dkg/pedpop/src/encryption.rs:57-59`). Unlike `Curve::read_G` in `crypto/frost/src/curve/mod.rs:125-131`, which explicitly rejects identity points, the base `Ciphersuite::read_G` performs no identity check, and `Decryption::register` (`encryption.rs:351-362`) stores `msg.enc_key` unconditionally — only asserting non-re-registration.

When a share is sent to that participant, `encrypt()` calls `ecdh::<C>(&key, to)` = `to * key` (`encryption.rs:95-97,154`). With `to` = identity, the shared point is the identity, whose canonical Ristretto encoding is 32 zero bytes. `cipher()` appends those bytes as `b"shared_key"` into `RecommendedTranscript("DKG Encryption v0.2")` and derives the ChaCha20 key (`encryption.rs:101-133`). The context is a public `[u8; 32]` (derived from session/network strings, `processor/src/key_gen.rs:184-197`), so the cipher key is a pure function of public data — anyone can recompute it and XOR-decrypt the `SecretShare` ciphertext.

The decryption path is symmetric (`encryption.rs:487-488`), and the blame machinery confirms the design assumes the ECDH output is secret: `EncryptionKeyProof`/`decrypt_with_proof` reveal per-message ECDH results (`encryption.rs:366-397`), and the spec states "the ECDH key … can decrypt the message" (`spec/cryptography/Distributed Key Generation.md`).

Reachability: an unprivileged DKG participant submits `EncryptionKeyMessage` bytes with `enc_key` = identity encoding. These messages are read by every other participant via `EncryptionKeyMessage::<Ristretto, Commitments<Ristretto>>::read` (`processor/src/key_gen.rs:268`) and then used by all honest parties in `self.encryption.encrypt(rng, l, share_bytes)` (`crypto/dkg/pedpop/src/lib.rs:369`). For Secp256k1 the identity has no valid encoding, but for Ristretto — used for the substrate DKG — the all-zero encoding decodes to identity.

### Impact Explanation
Every `SecretShare` message addressed to the malicious participant is encrypted under a key anyone can derive. Since DKG shares are transported through the coordinator/tributary layer where messages are broadly observable (authenticated, not confidential — the spec notes the DKG "doesn't offer an authenticated channel" beyond signatures, `Distributed Key Generation.md`), an observer recovers that participant's aggregated FROST secret share `sum_i poly_i(l)`. This is a threshold-key secret-share disclosure: the effective security of the multisig is reduced and the leaked share combines with any other compromised shares. It is the same failure shape as the advisory — a degenerate/known ECDH result silently becoming deterministic cipher key material instead of being rejected.

### Likelihood Explanation
Requires only a malicious DKG participant broadcasting an identity `enc_key` in their round-1 commitments message — fully within an unprivileged party's public inputs. No PoP or validity proof is required on `enc_key` (PoP exists only per encrypted message, `encryption.rs:83-91`). No participant count or collusion is needed. The residual constraints: the channel observer must see the ciphertexts (true for publicly relayed/coordinator-mediated DKG traffic), and the attack only exposes shares addressed to the rogue participant's index.

### Recommendation
Reject identity encryption keys at ingest. Either call an identity-checking reader for `enc_key` in `EncryptionKeyMessage::read`/`Decryption::register` (e.g., mirror `Curve::read_G`'s `is_identity` check), or assert `!bool::from(msg.enc_key.is_identity())` in `Decryption::register` and surface a `PedPoPError::InvalidCommitments(participant)`. For defense in depth, also check `ecdh().is_identity()` inside `encrypt()`/`decrypt()` and fail rather than deriving a cipher from a known constant. The same identity check should apply to `EncryptedMessage.key` (`encryption.rs:173`) and to `EncryptionKeyProof.key` (`encryption.rs:268`), since identity there also produces degenerate ECDH/DLEq transcripts.

### Proof of Concept
```rust
// Attacker (participant L) in PedPoP round 1:
// Build an EncryptionKeyMessage with enc_key = identity for Ristretto.
let mut msg = commitments.serialize();           // honest Commitments + PoK
msg.extend(<Ristretto as Ciphersuite>::G::identity().to_bytes().as_ref()); // all-zero enc_key
// Broadcast msg as the EncryptionKeyMessage for participant L.

// Every honest sender i does:
//   EncryptionKeyMessage::<Ristretto, Commitments<Ristretto>>::read -> enc_key = identity
//   encryption.encrypt(rng, L, share_bytes)
//     -> ecdh(&key_i, identity) = identity
//     -> cipher(context, identity) : shared_key appended = [0u8; 32]
//     -> ChaCha20 key = public_fn(context)   // deterministic

// Observer who sees EncryptedMessage { key: pub_key, pop, msg: ciphertext }
// recomputes:
let mut t = RecommendedTranscript::new(b"DKG Encryption v0.2");
t.append_message(b"context", context);          // public session context
t.domain_separate(b"encryption_key");
t.append_message(b"shared_key", [0u8; 32]);     // identity encoding
let mut key = chacha20::Key::default();
key.copy_from_slice(&t.challenge(b"key")[..32]);
let mut iv = chacha20::Nonce::default();
iv.copy_from_slice(b"DKG IV v0.2\0");
ChaCha20::new(&key, &iv).apply_keystream(&mut ciphertext); // recovers SecretShare bytes
```
