### Title
Unsolicited dust outputs to scanned scripts are credited as spendable inputs, letting an attacker bloat transactions into `TooLargeTransaction` DoS or burn donated value as fee - ([File: networks/bitcoin/src/wallet/send.rs](networks/bitcoin/src/wallet/send.rs))

### Summary
Analogous to the Blueberry report (where the spell trusts `borrowToken.balanceOf(address(this))` instead of the user's declared `borrowAmount`, letting a whale donate tokens to push the balance over the strategy cap and revert other users' `openPosition`), `bitcoin-serai` credits *any* on-chain output paying to a registered script as a spendable `ReceivedOutput`, and `SignableTransaction::new` then sizes the transaction — and its fee — off the ambient sum of *all* provided inputs rather than the amount actually required for the intended payments.

### Finding Description
`Scanner::scan_transaction` / `scan_block` return a `ReceivedOutput` for every output whose `script_pubkey` is in `self.scripts`, with no authentication of who sent it or why — any unprivileged party can send Bitcoin transactions paying to Serai's public external/branch/change scripts [1](#0-0) .

`SignableTransaction::new` then computes `input_sat` as the sum of every input passed and builds a `TxIn` for each one [2](#0-1) . Two consequences follow directly from this "ambient balance" accounting rather than need-based input selection:

1. **Griefing DoS via weight.** Every forced input adds a fixed ~58 vbytes to the weight calculation [3](#0-2) . Once cumulative weight exceeds `MAX_STANDARD_TX_WEIGHT`, construction hard-fails with `TooLargeTransaction` [4](#0-3)  — the same shape as the Blueberry revert: the attacker's unsolicited deposit makes an otherwise-valid operation fail.
2. **Fee burn.** If the caller builds the transaction without a change output, the doc-comment itself states "all leftover funds will become part of the paid fee" [5](#0-4) , and `fee()` is literally `sum(prevouts) - sum(outputs)` [6](#0-5) . Attacker-donated inputs included in the ambient input set are silently converted to miner fees. Even with change, each extra input's marginal spend cost (`fee_per_vbyte * ~58`) can exceed a sub-546-sat output's value — the wallet has no per-input economic check (the `DUST` check only applies to *payments*, not inputs) [7](#0-6) .

### Impact Explanation
An unprivileged attacker who knows a Serai multisig's deposit scripts (public on-chain) can flood it with small outputs. A wallet/processor flow that consumes all scanned outputs — the ambient-balance model — will either (a) fail to construct any spend once aggregate weight crosses `MAX_STANDARD_TX_WEIGHT`, denying service to legitimate withdrawals, or (b) burn value as excess fee / spend dust inputs at a net loss. This is a concrete availability and economic-loss vector reachable purely by sending public Bitcoin transactions.

### Likelihood Explanation
The attack requires only standard Bitcoin sends to a known address — no collusion, no key material, no privileged position. Its cost is bounded by the dust and the attacker's own fees, making sustained DoS moderately expensive, but a one-shot `TooLargeTransaction` trigger around rotation/consolidation windows is cheap. Severity: Medium.

### Recommendation
- Select inputs by need: pick the minimal input set covering `payment_sat + needed_fee` rather than summing all scanned outputs, mirroring the Blueberry fix ("deposit the user's `borrowAmount`, not `balanceOf(this)`").
- Filter inputs whose value is below their marginal spend cost (`value < fee_per_vbyte * input_vbytes`) in `SignableTransaction::new`, not just at the processor layer.
- Bound the input count / weight budget up front and prefer dropping the smallest contributed outputs instead of failing the whole transaction.

### Proof of Concept
1. Compute the multisig's deposit script via `p2tr_script_buf(group_key)` / a registered offset — the address is public.
2. Broadcast a transaction creating many `>= 1`-sat outputs to that script. `Scanner::scan_transaction` returns each as a `ReceivedOutput` indistinguishable from honest deposits [8](#0-7) .
3. When the wallet constructs a spend passing all received outputs, `calculate_weight_vbytes` inflates linearly per input; with enough outputs `weight > MAX_STANDARD_TX_WEIGHT` and `SignableTransaction::new` returns `Err(TooLargeTransaction)`, reverting the legitimate spend — the direct analog of the Blueberry `openPosition` revert caused by a whale's donation [9](#0-8) .

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
