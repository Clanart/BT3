### Title
Immature coinbase outputs reported as spendable received funds by `Scanner::scan_block` — ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
The Bitcoin `Scanner` reports every output paying to a tracked `script_pubkey` as a `ReceivedOutput`, including coinbase outputs that consensus rules forbid spending for 100 blocks. `scan_block` iterates `block.txdata` in full, including `txdata[0]` (the coinbase), and `scan_transaction` matches on `script_pubkey` alone with no maturity or coinbase check [1](#0-0) . The resulting `ReceivedOutput` is the exact type consumed by `SignableTransaction::new`, so an immature output flows into signing as if it were spendable [2](#0-1) .

### Finding Description
Analogous to the LemMinX issue (untrusted input routed into a privileged context without a required policy check), `Scanner::scan_block` routes an attacker-influenced on-chain object — a coinbase output paying the multisig's P2TR script — into the "received, spendable funds" pipeline without enforcing the coinbase maturity rule. The code itself acknowledges the hazard: "This will also scan the coinbase transaction which is bound by maturity. If received outputs must be immediately spendable, a post-processing pass is needed" [3](#0-2) . However, the library provides no enforcement, no flag on `ReceivedOutput` marking coinbase origin, and no maturity metadata. The regtest test even demonstrates the full reachable path: `generatetoaddress` pays the scanner's key in a coinbase, `scan_block` returns it, and the caller must mine 100 blocks before it is usable [4](#0-3) . I was unable to verify within the available context whether `processor/src/networks/bitcoin.rs`'s `get_outputs` (called from `processor/src/multisigs/scanner.rs:562`) performs the required coinbase filtering; if it does not, the immature output is registered as a real received output by the processor.

### Impact Explanation
If the processor does not filter coinbase outputs, a `ReceivedOutput` pointing at an immature coinbase is treated as spendable treasury input. Any `SignableTransaction` built over it produces a transaction consensus-invalid until maturity (BIP-30/COINBASE_MATURITY = 100 confirmations), so the multisig either reports received funds that cannot actually be moved, or repeatedly signs/broadcasts transactions that are rejected — leaking which inputs the multisig intended to spend and stalling the payment pipeline. This is "funds reported received that are not spendable", an accepted impact class.

### Likelihood Explanation
Medium-to-low. Reaching the path requires a miner (an unprivileged party) to pay the multisig's scanned `script_pubkey` in a coinbase output. Miners can do this deliberately, but honest miners rarely pay arbitrary P2TR scripts in coinbase. The trigger is real but requires miner cooperation, and the impact is temporary unspendability/misreporting rather than permanent loss.

### Recommendation
In `Scanner::scan_block` (`networks/bitcoin/src/wallet/mod.rs:221`), either skip `block.txdata[0]` when `tx.is_coinbase()`, or tag `ReceivedOutput` with a `coinbase`/`maturity` flag and have the processor (`processor/src/networks/bitcoin.rs` `get_outputs`) reject or defer immature coinbase outputs before registering them as spendable.

### Proof of Concept
From `networks/bitcoin/tests/wallet.rs:41-70` (regtest): mine one block paying `p2tr_script_buf(scanner_key)`, then call `scanner.scan_block(&block)` — it returns one `ReceivedOutput` for the coinbase output at `txdata[0]` even though that output cannot be spent until 100 more blocks. Passing that `ReceivedOutput` to `SignableTransaction::new` succeeds and produces a transaction that `send_raw_transaction`/consensus will reject as immature.

Note: if `processor/src/networks/bitcoin.rs::get_outputs` already filters coinbase transactions before calling the scanner, this reduces to a documented caller obligation and the finding should be downgraded/dismissed; that call site could not be confirmed within this analysis.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  /// Scan a block.
  ///
  /// This will also scan the coinbase transaction which is bound by maturity. If received outputs
  /// must be immediately spendable, a post-processing pass is needed to remove those outputs.
  /// Alternatively, scan_transaction can be called on `block.txdata[1 ..]`.
  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }
