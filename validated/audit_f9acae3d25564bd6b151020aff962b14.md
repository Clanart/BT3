## Analysis

The Aave report's core issue is: **an unprivileged actor can trigger a privileged, funds-moving action on a third-party contract by supplying the "receiver" address, and the receiver has no way to verify who actually initiated the call.** The broken invariant is "the contract executing a sensitive action does not authenticate the initiator of the request."

The closest structural analog in GitHub Desktop is the **`x-github-client://openRepo/...` deep-link handler**, which lets any external actor (a link on a webpage, in a README, in an issue/PR comment, etc.) drive Desktop into performing git network operations (fetch + branch checkout) against a locally-open repository, with no confirmation step and no validation of who "triggered" the action.

### Title
Deep-link-triggered fetch and branch checkout execute automatically on the matching local repository without user confirmation - (File: app/src/ui/dispatcher/dispatcher.ts)

### Summary
Desktop registers OS-level custom protocol handlers (`x-github-client`, `github-mac`, `github-windows`, etc.) that route to `handleAppURL` → `parseAppURL` → `dispatchURLAction`, all triggerable by any link the user clicks (in a browser, chat client, or embedded in web content) or any other application invoking the registered scheme. [1](#0-0) [2](#0-1)  For the `open-repository-from-url` action, `Dispatcher.openRepositoryFromUrl` is invoked with attacker-supplied `url`, `branch`, and `pr` values parsed straight out of the URL. [3](#0-2) [4](#0-3) 

### Finding Description
When the URL contains a `branch` parameter, `openBranchNameFromUrl` is called, which unconditionally performs a **network fetch** and then a **local checkout** of the attacker-specified branch name against whatever local repository matches the given remote URL — with no dialog, prompt, or user confirmation gating either the fetch or the checkout: [5](#0-4) 

Similarly, `openPullRequestFromUrl` fetches PR metadata from the API and automatically checks out the PR's head ref from whatever `clone_url`/`ref` the API response provides, again without a confirmation step: [6](#0-5) 

The only receiver-side validation present is on `filepath` (guarding against absolute paths and path traversal via `resolveWithin`), which shows the developers are aware this deep-link surface is untrusted input — yet the same scrutiny was not applied to `branch`/checkout, which is arguably more consequential because it mutates the actual working tree content of a repository the user already trusts and works in: [7](#0-6) 

`doesRepositoryMatchUrl` only checks that the *origin or upstream URL string* matches — it does not verify that the click/link truly originated from an action the user intended, mirroring the Aave "receiver does not validate who triggered the call" pattern: the deep-link handler is the "unprotected receiver," and the OS-level protocol registration is the "anyone can call it" primitive. [8](#0-7) 

### Impact Explanation
If a user has a repository open in Desktop whose origin/upstream matches a public repo URL (a very common situation for contributors to popular OSS projects), any web page, chat message, or malicious issue/PR comment containing a specially crafted `x-github-client://openRepo/<matching-url>?branch=<attacker-branch>` link — once clicked — will cause Desktop to silently fetch and force-checkout an attacker-chosen branch into the user's working directory. This is a "silent corruption of what the user commits or pushes": if the user is unaware their working tree switched branches/content, subsequent commits, merges, or pushes can be made against attacker-planted content. Combined with the PR flow, an attacker can also cause the app to check out an arbitrary fork's ref automatically.

### Likelihood Explanation
The scheme registration is real and OS-wide (`app.setAsDefaultProtocolClient`), so any clickable link in any application (browser, email client, Slack, etc.) can invoke it. [9](#0-8)  The action requires no special privileges beyond having Desktop installed and the target repository already cloned/open with a matching remote — no local access, admin rights, or leaked credentials are needed, satisfying the "link the user clicks" attacker-controlled vector called out as valid impact.

### Recommendation
Require explicit, unambiguous user confirmation (a modal identifying the source URL, target repo, and destination branch/ref) before performing any fetch or checkout triggered via `open-repository-from-url`, especially the `branch` and `pr` code paths in `openBranchNameFromUrl`/`openPullRequestFromUrl`. Apply the same "treat as untrusted, validate before acting" posture already used for the `filepath` parameter to the branch/checkout parameters.

### Proof of Concept
1. Attacker hosts a link: `x-github-client://openRepo/https://github.com/victim/public-repo?branch=malicious-branch`.
2. Victim, who already has `public-repo` cloned in Desktop, clicks the link (e.g., embedded in a GitHub issue comment or external webpage).
3. `main.ts`'s `open-url` handler invokes `handleAppURL` → `dispatchURLAction` → `Dispatcher.openBranchNameFromUrl`, which calls `appStore._fetch` then `checkoutLocalBranch` with no confirmation dialog. [5](#0-4) 
4. The victim's working directory is silently switched to `malicious-branch`; any subsequent commit/push by the unaware user propagates the attacker's content.

  private doesRepositoryMatchUrl(
    repo: Repository | CloningRepository,
    url: string
  ): repo is RepositoryWithGitHubRepository {
    if (repo instanceof Repository && isRepositoryWithGitHubRepository(repo)) {
      const originRepoUrl = repo.gitHubRepository.htmlURL
      const upstreamRepoUrl = repo.gitHubRepository.parent?.htmlURL ?? null

      if (originRepoUrl !== null && urlsMatch(originRepoUrl, url)) {
        return true
      }

      if (upstreamRepoUrl !== null && urlsMatch(upstreamRepoUrl, url)) {
        return true
      }
    }

    return false
  }

  private async openBranchNameFromUrl(
    url: string,
    branchName: string
  ): Promise<Repository | null> {
    const repository = await this.openOrCloneRepository(url)

    if (repository === null) {
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    // if the repo has a remote, fetch before switching branches to ensure
    // the checkout will be successful. This operation could be a no-op.
    await this.appStore._fetch(repository, FetchType.UserInitiatedTask)

    await this.checkoutLocalBranch(repository, branchName)

    return repository
  }

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }
    if (!isRepositoryWithGitHubRepository(repository)) {
      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    if (pullRequest.head.repo === null) {
      return null
    }

    await this.appStore._checkoutPullRequest(
      repository,
      pullRequest.number,
      pullRequest.head.repo.owner.login,
      pullRequest.head.repo.clone_url,
      pullRequest.head.ref
    )

    return repository
  }
