### Title
Unbounded `io.ReadAll(r.Body)` in NewRelic/Datadog RPC middleware bypasses request-size limit, enabling memory-exhaustion DoS via public JSON-RPC HTTP endpoint - (File: networks/rpc/http_newrelic.go)

### Summary
When the operator enables APM instrumentation (NewRelic via `NEWRELIC_APP_NAME`/`NEWRELIC_LICENSE`, or Datadog via `DD_TRACE_ENABLED`), the HTTP handler chain is wrapped with `newNewRelicHTTPHandler`/`newDatadogHTTPHandler`, which both call `getRPCRequests(r)` before the request reaches the size-checked path. `getRPCRequests` reads the entire request body into memory with an unbounded `io.ReadAll(r.Body)`, with no `Content-Length` or `MaxRequestContentLength` check applied at that point.

### Finding Description
The normal HTTP JSON-RPC path enforces `common.MaxRequestContentLength` (default 512 KB) via `validateRequest` (Content-Length check) and `io.LimitReader` in `newHTTPServerConn`: [1](#0-0) [2](#0-1) 

However, this enforcement only happens deep inside `srv.ServeHTTP`. The APM middlewares are registered as outer wrappers around the entire handler chain in `NewHTTPServer`: [3](#0-2) 

Both `newNewRelicHTTPHandler` and `newDatadogHTTPHandler` unconditionally call `getRPCRequests(r)` as their first action, before any size validation or before the wrapped `handler.ServeHTTP` (which contains the real size checks) executes: [4](#0-3) [5](#0-4) 

`getRPCRequests` performs an unbounded read of the entire HTTP body into memory: [6](#0-5) 

This is structurally analogous to the reported CVE-2021-22095: just as Spring AMQP's `Message.toString()` unconditionally materialized the full message body into a `String` regardless of size (causing OOM), Kaia's `getRPCRequests` unconditionally materializes the full untrusted HTTP request body into a `[]byte` via `io.ReadAll`, ignoring `MaxRequestContentLength`, before any size gate is applied.

Because `net/http.Server` does not itself cap request body size (no `http.MaxBytesReader` is applied to `r.Body` prior to this point), a remote, unauthenticated caller can send an arbitrarily large HTTP POST body to the public JSON-RPC endpoint and force the node to allocate memory proportional to the attacker-controlled payload size, once per request, before the existing `MaxRequestContentLength` protection has a chance to reject it.

### Impact Explanation
This allows a public, unauthenticated RPC caller to cause memory exhaustion (OOM) / denial of service on any node that has NewRelic or Datadog APM tracing enabled — a normal production/operations configuration, not an operator-malicious action. Because RPC endpoints are typically exposed to load balancers/public clients in production deployments that use APM, and the node process could crash or become unresponsive, this can disrupt block production/serving availability for the affected node.

### Likelihood Explanation
Exploitation only requires:
1. The operator has enabled NewRelic (`NEWRELIC_APP_NAME`/`NEWRELIC_LICENSE`) or Datadog (`DD_TRACE_ENABLED=true`) tracing — a common, legitimate operational choice, not a "malicious operator" precondition.
2. A single unauthenticated HTTP POST with a large body sent to the RPC listener.

No authentication, special privileges, or crafted RLP/consensus data is required — only a large HTTP payload, making this straightforward to trigger repeatedly and inexpensively (e.g., multiple concurrent large requests could multiply the memory pressure).

### Recommendation
Apply the same size bound used elsewhere (`common.MaxRequestContentLength`) before/within `getRPCRequests`, e.g. wrap `r.Body` with `io.LimitReader(r.Body, int64(common.MaxRequestContentLength))` (or `http.MaxBytesReader`) prior to `io.ReadAll`, and reject/short-circuit oversized bodies with the same `413 Request Entity Too Large` behavior as `validateRequest`. This should be applied consistently in `getRPCRequests` used by both `http_newrelic.go` and `http_datadog.go`.

### Proof of Concept
1. Start a Kaia node with NewRelic tracing enabled: set `NEWRELIC_APP_NAME` and `NEWRELIC_LICENSE` environment variables so `newNewRelicApp()` returns non-nil and `NewHTTPServer` wraps the handler with `newNewRelicHTTPHandler`.
2. As an unauthenticated remote client, send an HTTP POST to the JSON-RPC HTTP endpoint with a body far exceeding `common.MaxRequestContentLength` (default 512 KB), e.g. several hundred MB or GB of arbitrary bytes with `Content-Type: application/json`.
3. Observe that `getRPCRequests` invoked inside `newNewRelicHTTPHandler` calls `io.ReadAll(r.Body)` and fully buffers the oversized body into memory before `validateRequest`'s Content-Length check (which lives further down inside `srv.ServeHTTP`) ever executes.
4. Repeating this with multiple concurrent connections drives up node memory usage, potentially leading to OOM and process termination — denial of service on the public RPC endpoint.

Note: I could not execute this PoC in a live environment (no runtime/tooling access here); the analysis is based on static code review of the cited files. [7](#0-6) [8](#0-7)

// newNewRelicHTTPHandler enables NewRelic web transaction monitor.
// It also prints error logs when RPC returns contains error messages.
func newNewRelicHTTPHandler(nrApp *newrelic.Application, handler http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		defer func() {
			if err := recover(); err != nil {
				logger.ErrorWithStack("NewRelic http handler panic", "err", err)
			}
		}()

		reqMethod := ""

		// parse RPC requests
		reqs, isBatch, err := getRPCRequests(r)
		if err != nil || len(reqs) < 1 {
			// The error will be handled in `handler.ServeHTTP()` and printed with `printRPCErrorLog()`
			logger.Debug("failed to parse RPC request", "err", err, "len(reqs)", len(reqs))
		} else {
			reqMethod = reqs[0].Method
			if isBatch {
				reqMethod += "_batch"
			}
		}

		// new relic transaction name contains the first API method of the request
		txn := nrApp.StartTransaction(r.Method + " " + r.URL.String() + " " + reqMethod)
		defer txn.End()

		w = txn.SetWebResponse(w)
		txn.SetWebRequestHTTP(r)
		r = newrelic.RequestWithTransactionContext(r, txn)

		// duplicate writer
		dupW := &dupWriter{
			ResponseWriter: w,
			body:           bytes.NewBufferString(""),
		}

		// serve HTTP
		handler.ServeHTTP(dupW, r)

		// print RPC error logs if errors exist
		if isBatch {
			var rpcReturns []interface{}
			if err := json.Unmarshal(dupW.body.Bytes(), &rpcReturns); err == nil {
				for i, rpcReturn := range rpcReturns {
					if data, err := json.Marshal(rpcReturn); err == nil {
						// TODO-Kaia: make the log level configurable or separate module name of the logger
						printRPCErrorLog(data, reqs[i].Method, r)
					}
				}
			}
		} else {
			// TODO-Kaia: make the log level configurable or separate module name of the logger
			printRPCErrorLog(dupW.body.Bytes(), reqMethod, r)
		}
	})
}

// getRPCRequests copies a http request body data and parses RPC requests from the data.
// It returns a slice of RPC request, an indication if these requests are in batch, and an error.
// Ethereum returns []*jsonrpcMessage, which replaces []rpcRequest
func getRPCRequests(r *http.Request) ([]*jsonrpcMessage, bool, error) {
	reqBody, err := io.ReadAll(r.Body)
	if err != nil {
		logger.Error("cannot read a request body", "err", err)
		return nil, false, err
	}

	r.Body = io.NopCloser(bytes.NewReader(reqBody))
	conn := &httpServerConn{Reader: io.NopCloser(bytes.NewReader(reqBody)), Writer: bytes.NewBufferString(""), r: r}

	codec := NewCodec(conn)

	defer codec.close()

	return codec.readBatch()
}
