### Title
Clone operation explicitly disables Git's native clone-time protection (`GIT_CLONE_PROTECTION_ACTIVE=false`) - (`File: app/src/lib/git/clone.ts`)

### Summary
GitHub Desktop's `clone()` function always sets `GIT_CLONE_PROTECTION_ACTIVE: 'false'` when invoking `git clone --recursive` for any repository URL the user clones (including forked/attacker-hosted repos, or repos reached via a "Clone repository" deep link/GitHub API object). [1](#0-0)  This variable exists in modern Git specifically to gate the hardening added after the 2024 clone-time RCE disclosures (CVE-2024-32002/32004), where a maliciously crafted repository (via nested/symlinked working trees, case-insensitive filesystem tricks, or submodules) could smuggle files into `.git/hooks` or otherwise get an attacker-controlled hook executed during `clone --recursive`. By force-disabling that protection on every clone, Desktop reintroduces exactly the attack surface that guard was built to close.

### Finding Description
`clone()` builds the environment for the `git clone` invocation and unconditionally merges in `GIT_CLONE_PROTECTION_ACTIVE: 'false'`: [2](#0-1) 

The command always passes `--recursive`, meaning submodules (whose URLs and paths are themselves attacker-controlled content embedded in the cloned repository's `.gitmodules`) are cloned and checked out as part of the same operation. [3](#0-2)  Git's `core.hooksPath`/hooks execution logic and the general "clone protection" mechanism were tightened specifically to stop scenarios where an untrusted repository (the thing an attacker fully controls, per the "cloned/fetched repository" trust boundary) writes a file that ends up being interpreted as an executable Git hook during the clone/checkout sequence — e.g., via crafted paths that collide with `.git/hooks/*` on case-insensitive or symlink-vulnerable filesystems, or via a submodule that plants a hook in the parent's or its own `.git` directory before checkout completes. Setting `GIT_CLONE_PROTECTION_ACTIVE=false` deliberately turns that guard off for every single Desktop-initiated clone, with no fallback re-enabling it, no scoping to "trusted" sources, and no compensating control elsewhere in this file (the only other guard, `isClonePathSensitive`, only checks the destination path on the local machine, not the content of the source repository). [4](#0-3) 

This is structurally the same class of flaw as the external report: a single kill-switch/flag (`isMintEnabled` in the report, `GIT_CLONE_PROTECTION_ACTIVE` here) that is meant to gate one thing but is wired so that disabling it also strips a critical safety invariant relied on by other operations (bridging funds vs. safe recursive clone/checkout), and there is no separate, narrower control to keep the safety behavior on while adjusting whatever the flag was originally meant to toggle.

### Impact Explanation
If exploitable in the current bundled Git version, cloning an attacker-hosted or attacker-forked repository through Desktop (a fully unprivileged action a user takes routinely — cloning a link, a search result, a PR fork) could result in arbitrary hook/code execution on the victim's machine during the clone, i.e. code execution triggered purely by cloning a repo the attacker controls, which is explicitly in-scope impact ("attacker controls a cloned/fetched repository ... result is code execution").

### Likelihood Explanation
Likelihood is uncertain without confirming: (1) which Git version is bundled with this build of Desktop and whether `GIT_CLONE_PROTECTION_ACTIVE` in that version still gates a live, unpatched-by-other-means vector, and (2) whether upstream Git 2.45.1+ closed the underlying CVEs at a layer that doesn't depend on this variable (in which case disabling it may be inert). I could not verify Git's exact semantics for this variable or the bundled `dugite`/Git version from the indexed files, so I cannot confirm this is currently exploitable versus a leftover/no-op override — this is the key open question a Devin session with full repo/dependency access should resolve (check `package.json`/`dugite` version pin and Git's release notes for `GIT_CLONE_PROTECTION_ACTIVE`).

### Recommendation
Do not blanket-disable `GIT_CLONE_PROTECTION_ACTIVE` for all clones. If it must be disabled for a specific compatibility reason, scope that override narrowly (e.g., only for the specific known-safe code path/version combination that needs it) and document why, rather than applying it unconditionally in the shared `clone()` helper used for every repository the user clones, including untrusted ones.

/**
 * Check whether a resolved clone path targets a sensitive location that
 * should never be used as a clone destination. This is a backstop against
 * path traversal attacks where a crafted URL tricks the UI into deriving
 * a clone path outside the intended base directory.
 */
function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}

export async function clone(
  url: string,
  path: string,
  options: CloneOptions,
  progressCallback?: (progress: ICloneProgress) => void
): Promise<void> {
  if (isClonePathSensitive(path)) {
    throw new Error(
      `The clone destination "${path}" targets a sensitive system location. ` +
        'Cloning into this directory is not allowed.'
    )
  }

  const env = {
    ...(await envForRemoteOperation(url)),
    GIT_CLONE_PROTECTION_ACTIVE: 'false',
  }

  const defaultBranch = options.defaultBranch ?? (await getDefaultBranch())

  const args = [
    '-c',
    `init.defaultBranch=${defaultBranch}`,
    'clone',
    '--recursive',
  ]
