### Title
Auction Bid EIP-712 v2.1 typehash omits `maxGasPrice`, allowing an unsigned bid field to be relayed on-chain without searcher authorization - (File: kaiax/auction/eip712.go)

### Summary
The Kaia auction module's EIP-712 struct hash for bids (`Bid.EncodeData()` in `kaiax/auction/eip712.go`) has two versions of the signed struct: the v2.1 typehash (`auctionType`) which does **not** include `maxGasPrice`, and the v3.0 typehash (`auctionTypeV3`) which does. `BidData.MaxGasPrice` is nonetheless a live field on every `Bid` that is carried through the pool, gossiped to peers, and packed into the on-chain calldata by `EncodeAuctionCallData` (`blockchain/system/auction.go`) whenever v3 ABI is used. This mirrors the AssignmentHook flaw described in the report: a field (`metaHash`/`maxGasPrice`) that materially affects execution/settlement is not bound by the party's own signature, so it can be altered after signing without invalidating that signature.

### Finding Description
`kaiax/auction/eip712.go` defines two struct encoders: [1](#0-0) 
`Bid.EncodeData()` (v2.1, used when `version == AuctionVersionV2` or version is unrecognized) hashes `targetTxHash, blockNumber, sender, to, nonce, bid, callGasLimit, data` — `maxGasPrice` is absent: [2](#0-1) 
Only `bidV3.EncodeData()` includes `maxGasPrice`: [3](#0-2) 

`ValidateSearcherSig` verifies the searcher's signature purely against whichever typehash is selected by the caller-supplied `version` string, with no independent enforcement that `maxGasPrice` was actually covered: [4](#0-3) 

`BidPool.validateBidSigs` passes `bp.auctionEntryPointVersion` — a value read from the currently active `AuctionEntryPoint` contract's `AUCTION_VERSION()` and cached, refreshed only once per block in `updateAuctionInfo`: [5](#0-4) [6](#0-5) 

`BidPool.validateBid` never separately validates or bounds `bid.MaxGasPrice`; only `bid.Bid`, `bid.Data` size, and `bid.CallGasLimit` are checked: [7](#0-6) 

Finally, `EncodeAuctionCallData` (used to build the actual on-chain transaction sent to the `AuctionEntryPoint`) packs `bid.MaxGasPrice` into the v3 calldata whenever `version == AuctionVersionV3`, independent of what typehash was used to validate the searcher's signature: [8](#0-7) 

Because `MaxGasPrice` is not part of the searcher-signed v2.1 struct hash, any party that can set/relay this field (the auctioneer via `auction_submitBid`, or a peer via `HandleBid`) can attach or modify a `maxGasPrice` value on a `Bid` whose `SearcherSig` was computed (and remains valid) against the v2.1 typehash. If the version tracked by a node (`bp.auctionEntryPointVersion`, refreshed only at block boundaries) is stale or mismatched relative to the entry-point contract actually being targeted (e.g., during/after a version upgrade of the entry point, or if a bid is relayed to a node whose cached version differs from the one used to build calldata), the node could validate the searcher's signature under v2.1 rules (ignoring `maxGasPrice`) while still emitting v3 calldata carrying an attacker-chosen `maxGasPrice` that the searcher never actually authorized.

### Impact Explanation
`maxGasPrice` directly constrains what gas price the searcher is willing to pay/accept for the auction-winning bid transaction. If this field is not bound to the searcher's signature under the v2.1 typehash, an unauthorized party (the auctioneer, or anyone able to submit/relay a bid) can effectively impose a `maxGasPrice` value the searcher never agreed to onto a transaction that will still validate as "signed by the searcher." This is a fee/settlement-abuse analog to the metaHash issue: a value with economic/execution consequences is manipulable post-signature, potentially causing the searcher to overpay, or causing bid execution to fail/behave differently than the searcher intended, without the searcher's authorization being properly bound.

### Likelihood Explanation
This requires either (a) an active version transition/mismatch between what `updateAuctionInfo` has cached for a given node versus what's used when constructing calldata for the actual target entry point, or (b) intentional selection of the weaker v2.1 typehash by whoever forms the EIP-712 digest presented to the searcher for signing (e.g., a malicious/compromised auctioneer front-end could ask searchers to sign v2.1 digests while the deployed entry point is actually v3.0, or while gossiping the bid to nodes that still treat it as v3). Since `Auctioneer` is a semi-trusted centralized off-chain service in this design (per `kaiax/auction/README.md`), and node-side version caching is refreshed once per block rather than atomically with contract state, a transition window plausibly exists. Exploitation does not require breaking any cryptography — only exploiting the type-hash version selection logic.

### Recommendation
Bind `maxGasPrice` in a single canonical EIP-712 struct hash for all bids (rather than maintaining two typehash variants where one silently omits the field), or make the omission fail closed: reject any bid whose `MaxGasPrice != nil` when the v2.1 typehash was used to validate `SearcherSig`. Additionally, ensure the auction-entry-point version used to validate a searcher's signature and the version used to encode on-chain calldata are always derived from the exact same on-chain read within the same validation path, rather than a value cached from a prior block.

### Proof of Concept
Not directly reproducible from the indexed code alone — a full PoC would require driving a version transition (or a divergent cached version between the digest signed by the searcher and the version used by `EncodeAuctionCallData`) and is not present in the current test suite. `kaiax/auction/eip712.go` (lines 26-36, 75-86, 102-118) and `blockchain/system/auction.go` (lines 83-119) show the code paths where the field is included/excluded differently depending on the `version` parameter, which is the mechanism an attacker would need to desynchronize between signing time and calldata-construction time.

func (b *Bid) ValidateSearcherSig(chainId *big.Int, verifyingContract common.Address, version string) error {
	if chainId == nil {
		return ErrNilChainId
	}

	if common.EmptyAddress(verifyingContract) {
		return ErrNilVerifyingContract
	}

	digest := b.GetHashTypedData(chainId, verifyingContract, version)

	recoveredSender, err := getSigner(b.SearcherSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover searcher sig: %v", err)
	}

	if recoveredSender != b.Sender {
		return fmt.Errorf("invalid searcher sig: expected %v, calculated %v", b.Sender.String(), recoveredSender.String())
	}

	return nil
}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}

// updateAuctionInfo updates the auctioneer address and auction entry point address for the given block number.
// It expects the `num` is after Randao fork.
// It returns true if the non-zero auctioneer address and auction entry point address are set, otherwise false.
func (a *AuctionModule) updateAuctionInfo(num *big.Int) bool {
	auctioneer := common.Address{}
	auctionEntryPointAddr := common.Address{}
	auctionEntryPointVersion := ""
	bidTxGasBuffer := uint64(0)

	defer func() {
		a.bidPool.updateAuctionInfo(auctioneer, auctionEntryPointAddr, auctionEntryPointVersion, bidTxGasBuffer)
	}()

	header := a.Chain.GetHeaderByNumber(num.Uint64())
	if header == nil {
		return false
	}
	_, err := a.Chain.StateAt(header.Root)
	if err != nil {
		return false
	}

	backend := backends.NewBlockchainContractBackend(a.Chain, nil, nil)

	// 1. Read auction entry point address
	auctionEntryPointAddr, err = system.ReadActiveAddressFromRegistry(backend, system.AuctionEntryPointName, num)
	if err != nil {
		return false
	}

	if auctionEntryPointAddr == (common.Address{}) {
		return false
	}

	// 2. Read auctioneer address
	auctioneer, err = system.ReadAuctioneer(backend, auctionEntryPointAddr, num)
	if err != nil {
		return false
	}

	if auctioneer == (common.Address{}) {
		return false
	}

	// 3. Read gas buffer estimate
	bidTxGasBuffer, err = system.ReadGasBufferEstimate(backend, auctionEntryPointAddr, num)
	if err != nil {
		return false
	}

	// 4. Read AUCTION_VERSION to pick the right EIP-712 typehash and ABI for bids targeting this entry point.
	auctionEntryPointVersion, err = system.ReadAuctionVersion(backend, auctionEntryPointAddr, num)
	if err != nil {
		return false
	}

	return true

func EncodeAuctionCallData(bid *auction.Bid, version string) ([]byte, error) {
	if version == auction.AuctionVersionV3 {
		maxGasPrice := bid.MaxGasPrice
		if maxGasPrice == nil {
			maxGasPrice = new(big.Int)
		}
		input := contractsv3.IAuctionEntryPointAuctionTx{
			TargetTxHash:  bid.TargetTxHash,
			BlockNumber:   new(big.Int).SetUint64(bid.BlockNumber),
			Sender:        bid.Sender,
			To:            bid.To,
			Nonce:         new(big.Int).SetUint64(bid.Nonce),
			Bid:           bid.Bid,
			MaxGasPrice:   maxGasPrice,
			CallGasLimit:  new(big.Int).SetUint64(bid.CallGasLimit),
			Data:          bid.Data,
			SearcherSig:   bid.SearcherSig,
			AuctioneerSig: bid.AuctioneerSig,
		}
		return abiV3.Pack("call", input)
	}

	// auction.AuctionVersionV2 or unknown version: default to v2.1 ABI.
	input := contracts.IAuctionEntryPointAuctionTx{
		TargetTxHash:  bid.TargetTxHash,
		BlockNumber:   new(big.Int).SetUint64(bid.BlockNumber),
		Sender:        bid.Sender,
		To:            bid.To,
		Nonce:         new(big.Int).SetUint64(bid.Nonce),
		Bid:           bid.Bid,
		CallGasLimit:  new(big.Int).SetUint64(bid.CallGasLimit),
		Data:          bid.Data,
		SearcherSig:   bid.SearcherSig,
		AuctioneerSig: bid.AuctioneerSig,
	}
	return abi.Pack("call", input)
}
