### Title
App Proxy signed requests never validate the `timestamp` parameter, allowing indefinite replay of a leaked signed URL - ([File: lib/shopify_app/controller_concerns/app_proxy_verification.rb])

### Summary
`ShopifyApp::AppProxyVerification#verify_proxy_request` only checks that the HMAC `signature` over the query string is valid; it never checks that the `timestamp` parameter included in that same signed query string is recent. This mirrors the reported bug class of relying on a value that can be captured/used well after the moment it was legitimately valid — instead of a "two-day low" price, here it is an unbounded-lifetime signed URL.

### Finding Description
`query_string_valid?` extracts every param except `signature`, recomputes the HMAC over the sorted params (which still includes `timestamp`), and compares it to the supplied `signature`: [1](#0-0) [2](#0-1) 

Nowhere in this module (or `verify_proxy_request`) is `timestamp` compared against `Time.now` to reject stale requests: [3](#0-2) 

Because the signature is a pure function of the query parameters (shop, path_prefix, timestamp, logged_in_customer_id, etc.) and the shared `secret`, any URL that was ever validly generated by Shopify's App Proxy for a merchant/customer remains permanently valid and replayable by anyone who obtains it (via browser history, server logs, Referer headers, proxies, or a shared link) — there is no expiry enforced by this gem.

### Impact Explanation
An attacker who captures one historical signed app-proxy URL (e.g., one containing `logged_in_customer_id` for a specific customer) can replay it indefinitely to reach app-proxy actions as that customer/shop context, long after the original request/session should have expired. This is a direct analog to the oracle report's core issue: a value meant to represent a fresh/current state (price, or here, a request's validity window) is trusted without enforcing recency, creating an extended attack/exploitation window using previously-valid data.

### Likelihood Explanation
Exploitation requires obtaining a previously-issued valid app-proxy URL (e.g., from logs, browser history, or a forwarded link) — this is realistic in shared/support/debugging scenarios where such URLs are commonly pasted or logged, and no additional secret knowledge is needed once captured.

### Recommendation
In `query_string_valid?`/`verify_proxy_request`, after confirming HMAC validity, also parse `timestamp` and reject the request if it falls outside a short allowed window (e.g., a few minutes) relative to the current server time, consistent with Shopify's documented app-proxy signature verification guidance.

### Proof of Concept
1. A merchant/customer visits an app-proxy URL such as `.../apps/my-app?shop=some-shop.myshopify.com&path_prefix=%2Fapps%2Fmy-app&timestamp=1466106083&logged_in_customer_id=123&signature=<valid_hmac>`; this URL is logged (server access logs, browser history, shared support ticket, etc.).
2. Any time later, an attacker resends the exact same query string to the app's app-proxy endpoint.
3. `query_string_valid?` recomputes the same HMAC over the same parameters and returns `true` because `timestamp` is never checked for staleness: [1](#0-0) 
4. The request is treated as an authentic, fresh Shopify app-proxy call indefinitely, as demonstrated by the existing test suite validating fixed, hard-coded timestamps without expiry assertions: [4](#0-3)

```ruby
    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end
```

```ruby
    def calculated_signature(query_hash_without_signature)
      sorted_params = query_hash_without_signature.collect { |k, v| "#{k}=#{Array(v).join(",")}" }.sort.join

      OpenSSL::HMAC.hexdigest(
        OpenSSL::Digest.new("sha256"),
        ShopifyApp.configuration.secret,
        sorted_params,
      )
    end
```
