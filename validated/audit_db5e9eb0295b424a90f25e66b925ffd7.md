### Title
Attacker-computable deterministic offsets let any third party forge "internal" (Branch/Change/Forwarded) outputs in the Bitcoin scanner - ([File: processor/src/networks/bitcoin.rs](processor/src/networks/bitcoin.rs))

### Summary
The reported bug class is an unvalidated composition of a trusted root with an untrusted pattern, letting an outside party place artifacts inside a restricted namespace. In `bitcoin-serai`, the analog is the `Scanner`/`get_outputs` path: outputs are authenticated solely by `script_pubkey` membership in `scripts`, and the scripts for the internal output kinds (`Branch`, `Change`, `Forwarded`) are derived from deterministic, publicly computable offsets (`Secp256k1::hash_to_F(KEY_DST, b"branch"/"change"/"forward")`). Anyone who knows the group key can compute these internal addresses and send a transaction that the processor will classify as an internally-generated output, "traversing" into a namespace the design assumes only the multisig itself can write to.

### Finding Description
`Scanner::new` and `Scanner::register_offset` build a `HashMap<ScriptBuf, Scalar>` and `scan_transaction` attributes any transaction output whose `script_pubkey` is in the map to the corresponding offset [1](#0-0) [2](#0-1) [3](#0-2) . In the processor, `scanner()` registers the `Branch`, `Change`, and `Forwarded` kinds from fixed offsets produced by `Secp256k1::hash_to_F(KEY_DST, ...)`, i.e., deterministic functions of public constants and the public group key [4](#0-3) . `get_outputs` then maps each scanned output's offset to `OutputType` via `kinds[offset_repr_ref]` and attaches `presumed_origin`/protocol `data` only to `OutputType::External` outputs [5](#0-4) . There is no check that an output classified as `Change`/`Branch`/`Forwarded` was actually created by the multisig (e.g., no binding to an expected internal transaction), exactly paralleling hyper-bump-it's missing "is the matched file inside the project root" check.

### Impact Explanation
An unprivileged party can craft a Bitcoin transaction paying a small amount to the multisig's deterministic `Change`, `Branch`, or `Forwarded` script and have it reported by `get_outputs` as an internal output kind rather than an external deposit [6](#0-5) . Consequences include: the processor treating attacker-created outputs as internal change/branch confirmations (spoofing confirmation of a spend that never occurred or feeding unexpected inputs into UTXO management), evading the `presumed_origin`/data attribution applied only to `External` outputs, and polluting the output set used by downstream aggregation/signing logic. Because the scripts genuinely resolve to the multisig key, the funds are technically spendable, but the classification/tracking confusion is exactly the "object placed outside its intended domain yet trusted as internal" consequence of the path-traversal class.

### Likelihood Explanation
Reachability is trivial: the group key is the multisig's public key, `KEY_DST` and the `"branch"`/`"change"`/`"forward"` labels are hard-coded public constants, so computing each internal address costs one `hash_to_F` plus `register_offset`'s parity-increment loop [7](#0-6) . The only cost to the attacker is a normal on-chain payment (which can be dust-sized above `DUST`). No collusion, leaked key, or malicious node is required.

### Recommendation
Do not treat `script_pubkey` membership alone as proof an output is internally generated. Track expected internal outputs (change/branch/forward) by outpoint/transaction the processor itself constructed, and classify unknown payments to internal offsets as attacker-controlled deposits (or reject them) rather than as `Change`/`Branch`/`Forwarded`. Alternatively, keep the internal offsets secret or derive them per-multisig with private material so external parties cannot compute the internal scripts.

### Proof of Concept
1. Observe the multisig's public group key `K` (publicly known, e.g., from its external address or coordinator state).
2. Compute `off_change = Secp256k1::hash_to_F(b"Serai Bitcoin Output Offset", b"change")` and run the `register_offset` even-parity increment to get the effective offset `o` [8](#0-7) [2](#0-1) .
3. Build `script = p2tr_script_buf(K + GENERATOR * o)` — the multisig's own change address [9](#0-8) .
4. Broadcast a transaction paying `script` any amount ≥ dust.
5. When the processor scans the block, `Scanner::scan_transaction` matches the output and `get_outputs` emits `Output { kind: OutputType::Change, .. }` with `presumed_origin`/`data` unset, indistinguishable from a change output the multisig created itself [5](#0-4) .

Caveat: the precise downstream damage depends on how the processor consumes `Output.kind` (UTXO management/eventualities are out of the listed in-scope dirs); the demonstrated, fully-supported primitive is unauthenticated injection of attacker-controlled outputs into the `Change`/`Branch`/`Forwarded` classification.

  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

const KEY_DST: &[u8] = b"Serai Bitcoin Output Offset";
static BRANCH_OFFSET: OnceLock<Scalar> = OnceLock::new();
static CHANGE_OFFSET: OnceLock<Scalar> = OnceLock::new();
static FORWARD_OFFSET: OnceLock<Scalar> = OnceLock::new();

// Always construct the full scanner in order to ensure there's no collisions
fn scanner(
  key: ProjectivePoint,
) -> (Scanner, HashMap<OutputType, Scalar>, HashMap<Vec<u8>, OutputType>) {
  let mut scanner = Scanner::new(key).unwrap();
  let mut offsets = HashMap::from([(OutputType::External, Scalar::ZERO)]);

  let zero = Scalar::ZERO.to_repr();
  let zero_ref: &[u8] = zero.as_ref();
  let mut kinds = HashMap::from([(zero_ref.to_vec(), OutputType::External)]);

  let mut register = |kind, offset| {
    let offset = scanner.register_offset(offset).expect("offset collision");
    offsets.insert(kind, offset);

    let offset = offset.to_repr();
    let offset_ref: &[u8] = offset.as_ref();
    kinds.insert(offset_ref.to_vec(), kind);
  };

  register(
    OutputType::Branch,
    *BRANCH_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"branch")),
  );
  register(
    OutputType::Change,
    *CHANGE_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"change")),
  );
  register(
    OutputType::Forwarded,
    *FORWARD_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"forward")),
  );

  (scanner, offsets, kinds)
}
