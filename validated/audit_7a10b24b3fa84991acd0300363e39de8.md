### Title
`parseAppURL()` branch validation omits leading `-`/`+` check, allowing git flag/argument injection via untrusted deep links - ([File: app/src/lib/parse-app-url.ts])

### Summary
The bug class in the report is a validator that checks *some* properties of untrusted input but omits a check for one specific, dangerous shape — allowing a case the validator was supposed to guard against to slip through. The closest Desktop analog is `parseAppURL()`'s handling of the `branch` query parameter for `openrepo`/`x-github-client` deep links: it validates the branch string with `testForInvalidChars()`, but that regex does not reject a leading `-`/`+`, even though the codebase's own ref-sanitizer (`sanitizedRefName()`) explicitly strips leading `-`/`+` because it recognizes them as unsafe. The validated-but-not-fully-sanitized `branch` value is then handed to `Dispatcher.openBranchNameFromUrl()` → `checkoutLocalBranch()`, which is a git-invoking operation.

### Finding Description
`parseAppURL()` is the entry point for handling untrusted, attacker-influenced deep links (`x-github-client://`, `github-mac://`, `github-windows://`) that a malicious or compromised website can cause the user to click, e.g. an "Open in Desktop" button. [1](#0-0) 

For the `openrepo` action it validates `pr` (must be digits) and `branch` (must not match `testForInvalidChars`), then returns the raw `branch` string unmodified: [2](#0-1) 

`testForInvalidChars()` is defined in `sanitize-ref-name.ts` and rejects control characters, space, DEL, and `~^:?*[\|""<>`, plus `@{`, consecutive dots, leading/trailing dot, `.lock` suffix, and trailing `/` — but it never rejects a leading `-` or `+`: [3](#0-2) 

Notably, the *same file* contains `sanitizedRefName()`, which explicitly strips a leading `-`/`+` (`.replace(/^[-\+]*/g, '')`) — demonstrating that the codebase is aware a leading dash in a ref/branch name is unsafe, yet the validator used specifically for the untrusted-URL code path (`testForInvalidChars`) does not enforce that same restriction: [4](#0-3) 

The unmodified `branch` value flows from `parseAppURL()` into `Dispatcher.dispatchURLAction()` → `openRepositoryFromUrl()` → `openBranchNameFromUrl()`, which calls `checkoutLocalBranch(repository, branchName)`: [5](#0-4) 

If the branch value beginning with `-` is passed as a bare positional argument to a `git` subcommand (e.g., `git checkout <branch>` or a branch-creation command) without a `--` end-of-options separator preceding it, git will interpret it as a command-line option/flag rather than a ref name, enabling flag/argument injection (for example forcing unexpected git options). This mirrors the reported bug class exactly: a security check (`checkTransaction`/`testForInvalidChars`) that validates "the input looks like an acceptable value" but fails to check for the one crafted shape (zero-length calldata / leading-dash ref) that lets a dangerous operation bypass the intended restriction, while a stricter sibling function in the same codebase (`whitelist` branch / `sanitizedRefName`) already handles that exact case correctly.

### Impact Explanation
If the downstream git invocation for branch checkout does not prepend `--` before the branch argument, an attacker who gets a victim to click a crafted `x-github-client://openRepo/<repo>?branch=-<flag>` link (via a webpage, email, or GitHub `.com`-hosted "Open in Desktop" button) could inject git command-line flags into the checkout/branch-creation invocation running on the user's machine, potentially altering repository state, disabling safety checks, or (depending on the exact flag surface available on the specific git subcommand used) achieving more severe effects. This fits the "attacker controls a link/deep link the user clicks... resulting in silent corruption of what the user commits or pushes / code execution" impact class in scope.

### Likelihood Explanation
Likelihood is moderate and depends on a detail I could not fully verify within this session: whether the specific git command invoked by `checkoutLocalBranch` (and any related branch-creation helpers reachable from this path) passes the branch name after a `--` separator. I confirmed the validation gap (`testForInvalidChars` not rejecting leading `-`/`+`) and the reachable, attacker-controlled data flow from `parseAppURL` to `checkoutLocalBranch`, but did not have remaining tool budget to inspect the exact `git checkout`/`git branch` argument-array construction in `app/src/lib/git/branch.ts` (or equivalent) to confirm whether a `--` guard already exists there. This should be verified before treating this as a fully confirmed exploit chain.

### Recommendation
In `parseAppURL()` (or in `testForInvalidChars`/a new dedicated validator used there), explicitly reject branch values that start with `-` or `+`, consistent with `sanitizedRefName()`'s existing behavior. Additionally, audit every git-invoking function that accepts a branch/ref name derived from untrusted input (URL actions, protocol handlers) to ensure a `--` end-of-options marker precedes the ref argument, defense-in-depth against argument injection regardless of upstream validation.

### Proof of Concept
1. Attacker hosts a page (or sends a link) with `<a href="x-github-client://openRepo/https://github.com/some/repo?branch=-upload-pack%3Dcalc">Open in Desktop</a>` (URL-encoded flag payload for illustration).
2. Victim, with GitHub Desktop installed and its protocol handler registered (confirmed at `possibleProtocols` in `app/src/main-process/main.ts`), clicks the link.
3. `handleAppURL` → `parseAppURL` is invoked; `branch = "-upload-pack=calc"` passes `testForInvalidChars` because `-` and `=` are not in the excluded character set. [6](#0-5) 
4. `dispatchURLAction` routes to `openRepositoryFromUrl` → `openBranchNameFromUrl(url, "-upload-pack=calc")` → `checkoutLocalBranch(repository, "-upload-pack=calc")`. [7](#0-6) 
5. If the underlying git invocation does not insert `--` before the branch argument, git parses `-upload-pack=calc` as an option rather than a ref name — the crafted value should have been rejected at step 3 the same way `sanitizedRefName` would strip it. [4](#0-3)

// See https://www.kernel.org/pub/software/scm/git/docs/git-check-ref-format.html
// ASCII Control chars and space, DEL, ~ ^ : ? * [ \
// | " < and > is technically a valid refname but not on Windows
// the magic sequence @{, consecutive dots, leading and trailing dot, ref ending in .lock
const invalidCharacterRegex =
  /[\x00-\x20\x7F~^:?*\[\\|""<>]+|@{|\.\.+|^\.|\.$|\.lock$|\/$/g

/** Sanitize a proposed reference name by replacing illegal characters. */
export function sanitizedRefName(name: string): string {
  return name.replace(invalidCharacterRegex, '-').replace(/^[-\+]*/g, '')
}

/** Validate that a reference does not contain any invalid characters */
export function testForInvalidChars(name: string): boolean {
  return invalidCharacterRegex.test(name)

  private async openRepositoryFromUrl(action: IOpenRepositoryFromURLAction) {
    const { url, pr, branch, filepath } = action

    let repository: Repository | null

    if (pr !== null) {
      repository = await this.openPullRequestFromUrl(url, pr)
    } else if (branch !== null) {
      repository = await this.openBranchNameFromUrl(url, branch)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      return
    }

    if (filepath !== null) {
      if (isAbsolute(filepath)) {
        log.error(`Refusing to open absolute path: ${filepath}`)
        return
      }

      const resolved = await resolveWithin(repository.path, filepath)

      if (resolved !== null) {
        shell.showItemInFolder(resolved)
      } else {
        log.error(
          `Prevented attempt to open path outside of the repository root: ${filepath}`
        )
      }
    }
  }

  private async openBranchNameFromUrl(
    url: string,
    branchName: string
  ): Promise<Repository | null> {
    const repository = await this.openOrCloneRepository(url)

    if (repository === null) {
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    // if the repo has a remote, fetch before switching branches to ensure
    // the checkout will be successful. This operation could be a no-op.
    await this.appStore._fetch(repository, FetchType.UserInitiatedTask)

    await this.checkoutLocalBranch(repository, branchName)

    return repository
  }
