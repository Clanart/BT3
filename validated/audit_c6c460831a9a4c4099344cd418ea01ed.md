### Title
`Scanner::scan_block` reports immature coinbase outputs as spendable - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_block` iterates over every transaction in a Bitcoin block, including `block.txdata[0]`, and returns matching coinbase outputs as ordinary `ReceivedOutput` values. Although a coinbase output cannot be spent until it reaches maturity, `SignableTransaction::new` has no maturity check and will accept the returned output as an input. A miner can therefore cause Serai’s Bitcoin wallet to report and potentially sign over an output that Bitcoin consensus will reject as unspendable. [1](#0-0) [2](#0-1) 

### Finding Description
`ReceivedOutput` is documented as “a spendable output,” but `Scanner::scan_transaction` creates it solely by matching `output.script_pubkey` against registered scripts. [3](#0-2) [4](#0-3) 

`Scanner::scan_block` applies that same logic to `block.txdata`, without skipping the coinbase transaction or checking its maturity. [1](#0-0) 

The resulting `ReceivedOutput` can be passed directly to `SignableTransaction::new`, which converts every supplied output into a transaction input without tracking whether it came from a coinbase. [5](#0-4) [2](#0-1) 

The transaction is then signed using `Prevouts::All`, so the invalid coinbase input becomes part of the signed transaction and cannot be removed without constructing and signing a different transaction. [6](#0-5) 

### Impact Explanation
An immature coinbase output is cryptographically controlled by the scanner’s key but is not spendable under Bitcoin consensus until maturity. A consumer that trusts `ReceivedOutput`’s “spendable output” contract may account for the funds as usable and construct a transaction that is guaranteed to fail relay/consensus while the output remains immature. This can cause incorrect balances, failed withdrawals, or repeated signing attempts over unavailable funds. [3](#0-2) [7](#0-6) 

### Likelihood Explanation
A miner can place a P2TR output matching a registered scanner script in its coinbase transaction; no private state or privileged protocol access is needed. The vulnerable path is reached whenever `scan_block` is used on that block, and the wallet already exposes this public API despite the maturity caveat. [8](#0-7) [7](#0-6) 

### Recommendation
Do not scan `block.txdata[0]` in `Scanner::scan_block`; iterate only over `block.txdata[1 ..]`, matching the processor-side implementation that explicitly skips the coinbase transaction. If coinbase scanning is intentionally exposed, return a separate immature-output type or require callers to provide the block height and suppress the output until maturity. [9](#0-8) 

### Proof of Concept
Conceptually:

```rust
let mut scanner = Scanner::new(group_key).unwrap();

// A miner creates a block whose coinbase pays to `p2tr_script_buf(group_key)`.
let block: Block = obtain_block_with_coinbase_payment();

// Serai returns the immature coinbase output as an ordinary spendable output.
let outputs = scanner.scan_block(&block);
assert_eq!(outputs.len(), 1);
assert_eq!(outputs[0].outpoint().txid, block.txdata[0].compute_txid());

// The wallet accepts it as an input without checking coinbase maturity.
let spend = SignableTransaction::new(
    outputs,
    &[(payment_script, payment_amount)],
    Some(change_script),
    None,
    fee_per_vbyte,
).unwrap();
```

The signed spend commits to the coinbase outpoint through `TxIn::previous_output`, making the transaction invalid until the coinbase reaches maturity. [10](#0-9) [11](#0-10)

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

          offset: *offset,
