### Title
Recursive clone explicitly disables Git's built-in hook-execution safety guard via `GIT_CLONE_PROTECTION_ACTIVE=false` - (File: `app/src/lib/git/clone.ts`)

### Summary
Desktop's `clone()` function unconditionally sets the environment variable `GIT_CLONE_PROTECTION_ACTIVE` to `'false'` on every `git clone --recursive` invocation, while all other hardening in the same file (sensitive-path checks, clone-path sanitization) is left intact. `GIT_CLONE_PROTECTION_ACTIVE` is the internal guard Git itself introduced (as part of the fix line for CVE-2024-32004/the recursive-submodule-clone hook execution family of bugs) to stop a maliciously crafted repository/submodule tree from causing hook scripts to execute local files during the clone of an untrusted, attacker-controlled remote. Forcing this flag to `false` deliberately re-opens that class of hook-execution-during-clone bugs for every repository a user clones through Desktop.

### Finding Description
`clone()` builds the execution environment as: [1](#0-0) 

```ts
const env = {
  ...(await envForRemoteOperation(url)),
  GIT_CLONE_PROTECTION_ACTIVE: 'false',
}
...
const args = [
  '-c',
  `init.defaultBranch=${defaultBranch}`,
  'clone',
  '--recursive',
]
```

Notice the contrast with the rest of the file: `isClonePathSensitive()` is an explicit, commented "backstop against path traversal attacks where a crafted URL tricks the UI into deriving a clone path outside the intended base directory" [2](#0-1) . That defensive posture is undermined by the single, uncommented line that force-disables Git's own clone-time protection flag before every `--recursive` clone.

`GIT_CLONE_PROTECTION_ACTIVE` exists in Git core specifically to prevent an attacker-controlled remote/submodule tree from smuggling a `.git`/hooks-directory alias (e.g. via crafted submodule paths, symlinked `.git` entries, or nested repository layouts) that gets treated as a legitimate hook location during a recursive clone, allowing hook scripts contained in the cloned content to run as if they were the user's own local hooks — the core mechanism behind CVE-2024-32004. By hard-setting this to `'false'` in the child process environment for `git clone --recursive`, Desktop opts every clone (including clones of arbitrary attacker-supplied URLs reached via "Clone repository", "Open in Desktop" deep links, and `--cli-clone`) out of the very check Git introduced to prevent that class of attack, regardless of the user's installed Git version otherwise defaulting to the safe behavior.

### Impact Explanation
Because Desktop uses `--recursive` on every clone [3](#0-2) , and submodule content is fully attacker-controlled once the user is pointed at a malicious or compromised remote (via a shared clone URL, an `x-github-client://openRepo/...` deep link parsed in `parseAppURL` [4](#0-3) , or a CLI clone request [5](#0-4) ), disabling this guard converts an otherwise-patched Git installation back into one vulnerable to hook-execution-during-clone. The result is arbitrary code execution on the user's machine as soon as they clone (or "Clone Again") a hostile repository — no interaction with the checked-out working tree is required beyond the clone itself.

### Likelihood Explanation
The unprivileged attacker only needs to get a victim to clone a URL they control — via a normal "Clone repository" flow, a crafted `x-github-client://openrepo/...` link (handled by `handleAppURL`/`openRepositoryFromUrl`), or a "Clone Again" action on a previously-known GitHub repo whose remote has since been repointed. This requires no local access, no admin rights, and no pre-existing malware, matching the "attacker controls a cloned/fetched repository ... or a link/deep link the user clicks" category directly. The override is unconditional (not feature-flagged, not limited to trusted hosts), so every clone path in the app is affected.

### Recommendation
Remove the `GIT_CLONE_PROTECTION_ACTIVE: 'false'` override in `app/src/lib/git/clone.ts` and let Git's own default (protection enabled) apply for `git clone --recursive`. If there is a legitimate operational reason to disable it (e.g. compatibility with older Git binaries), gate it behind an explicit, narrowly-scoped condition and document the security trade-off, rather than disabling it unconditionally for all recursive clones of arbitrary, potentially attacker-controlled URLs.

### Proof of Concept
1. Attacker crafts a Git repository whose submodule configuration/tree layout is designed to smuggle a hooks-directory alias, exploiting the same underlying condition addressed by Git's clone-protection guard (as in CVE-2024-32004-class issues).
2. Attacker distributes the clone URL to a victim (via a shared link, a `x-github-client://openrepo/<url>` deep link that resolves through `parseAppURL`/`openOrCloneRepository`, or by having the victim use "Clone Again" on a repo whose remote now points at the malicious URL).
3. Victim clones the repository in GitHub Desktop. `clone()` invokes `git -c init.defaultBranch=... clone --recursive -- <url> <path>` with `GIT_CLONE_PROTECTION_ACTIVE=false` set in the child process environment.
4. Because the protection flag is forced off, Git's guard against the hooks-execution-during-recursive-clone condition does not trigger, and the attacker-supplied hook content executes on the victim's machine as part of the clone/submodule-init process.

/**
 * Check whether a resolved clone path targets a sensitive location that
 * should never be used as a clone destination. This is a backstop against
 * path traversal attacks where a crafted URL tricks the UI into deriving
 * a clone path outside the intended base directory.
 */
function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}
