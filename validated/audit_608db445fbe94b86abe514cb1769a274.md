### Title
Server-Side Request Forgery in `isGitHubHost` via attacker-controlled git credential URL - (File: `app/src/lib/api.ts`)

### Summary
GitHub Desktop's git credential helper trampoline invokes `isGitHubHost()` [1](#0-0)  with a URL derived directly from the credential request Git sends during any HTTP(S) fetch/clone/push/submodule operation. That URL is attacker-influenced (via a remote/submodule URL configured in a cloned repository, or via a server's `WWW-Authenticate` response during authentication). When the "happy path" heuristics fail to classify the host, `isGitHubHost` performs a live outbound `fetch()` HEAD request to `${endpoint}/meta` from the trusted Electron process, with certificate validation intentionally suppressed for that exact URL [2](#0-1) . This is the same broken invariant as the Uppy SSRF: a network request is issued to a URL that isn't validated against being an internal/private resource, and the requester doesn't control which host actually gets contacted.

### Finding Description
When Git performs any HTTPS operation (fetch, clone, push, or submodule update) it may invoke the configured credential helper, which in Desktop's case is the trampoline handled in `createCredentialHelperTrampolineHandler` [3](#0-2) . The credential's `url`/`host`/`protocol` fields are parsed straight from Git's credential protocol stdin via `getCredentialUrl` [4](#0-3) , which in turn is populated by Git itself from the connection target (the configured remote URL, a submodule's remote URL, or the URL Git ended up connecting to after redirects/auth challenges).

`getCredential`/`storeCredential`/`eraseCredential` all call `getEndpointKind` [5](#0-4) , which tries several heuristics (dotcom, GHE, gist, `WWW-Authenticate` realm, known account) before falling back to an actual network probe:

```
// All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
// assume that this is not a GitHub host.
if (credentialUrl.protocol !== 'https:') {
  return 'generic'
}
return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
``` [6](#0-5) 

`isGitHubHost` then builds `metaUrl` directly from the attacker-influenced `endpoint` and issues a real network request:
```
const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`
...
suppressCertificateErrorFor(metaUrl)
const response = await fetch(metaUrl, {
  headers: { 'user-agent': getUserAgent() },
  signal: ac.signal,
  credentials: 'omit',
  method: 'HEAD',
  redirect: 'error',
})
``` [2](#0-1) 

Only the URL's scheme (`https:`) is checked; there is no validation that the hostname isn't a private/internal/link-local address (e.g. `169.254.169.254`, `10.x.x.x`, `localhost`, an internal-only HTTPS service, etc.), and no allow-list restricting the destination. Additionally, certificate errors for this specific probe URL are explicitly suppressed [7](#0-6) , so the attacker-controlled internal listener doesn't even need a valid TLS certificate — a self-signed cert on any internal HTTPS listener is enough to receive the probe.

### Impact Explanation
This lets an attacker who controls a cloned/fetched repository (via a remote URL, a `.gitmodules` submodule URL pointing at an internal address, or by controlling the git server and issuing an unexpected `WWW-Authenticate` realm/redirect) cause the trusted Desktop main/renderer process to send an authenticated-looking HEAD request to an arbitrary internal HTTPS host on the victim's network from inside their environment (corporate intranet, cloud VPC, etc.). While `credentials: 'omit'` prevents cookie/token leakage in this specific request and the request itself is a benign HEAD to `/meta`, it is a genuine SSRF primitive: it can be used to probe for the existence/reachability of internal HTTPS services (network reconnaissance/port-scanning primitive from inside a trusted process, bypassing normal user network boundaries), and abuse of `redirect: 'error'`/timeout behavior as an oracle to determine what's alive behind the corporate firewall. It does not, by itself, achieve direct code execution or credential exfiltration, so I classify it as a Medium-severity SSRF analog rather than a High one — but it satisfies the "attacker controls a git remote/proxy response" criterion from the task's valid-impact list.

### Likelihood Explanation
Every non-dotcom/non-GHE/non-gist HTTPS git operation without an already-known account and without a matching `WWW-Authenticate realm` triggers this path, meaning simply cloning or fetching from an untrusted HTTPS remote (or one containing a malicious submodule URL) is sufficient — no unusual user interaction beyond normal repository operations is required. This makes the likelihood high for anyone who fetches/clones from third-party or unknown HTTPS remotes.

### Recommendation
- Before making the `/meta` probe in `isGitHubHost`, resolve and reject requests targeting private/link-local/loopback IP ranges (RFC 1918, `127.0.0.0/8`, `169.254.0.0/16`, `::1`, etc.) unless the user has explicitly configured that endpoint as an Enterprise account.
- Avoid calling `suppressCertificateErrorFor` for hosts that haven't already been established as a trusted/known endpoint.
- Consider gating the network probe entirely behind explicit user confirmation ("Is this a GitHub Enterprise server?") rather than doing it silently as a side effect of credential resolution for arbitrary remotes.

### Proof of Concept
1. Set up an internal-only HTTPS listener (self-signed cert is fine) at `https://internal-service.local/` that would not normally be reachable/probed by an external actor, simulating an SSRF target inside the victim's network.
2. Create a public git repository whose `.gitmodules` (or a remote configured by the attacker via a README-suggested `git remote add`) references `https://internal-service.local/some/repo.git`.
3. Have the victim clone/add this remote and run `git fetch`/`git submodule update` in GitHub Desktop.
4. Git invokes Desktop's credential helper trampoline for `https://internal-service.local`; since it isn't dotcom/GHE/gist, has no cached account, and the server doesn't return a recognized `WWW-Authenticate` realm, `getEndpointKind` falls through to `isGitHubHost('https://internal-service.local')` [6](#0-5) .
5. Observe (e.g., via the internal listener's access log) that GitHub Desktop's process issued a `HEAD /meta?ghd=<uuid>` request to `internal-service.local`, confirming the SSRF — the app made a network request to an internal host purely as a side effect of resolving credentials for an attacker-supplied remote URL, with certificate validation suppressed for that request [2](#0-1) .

**Note on completeness:** I was not able to fully trace, within the tool budget available, the exact end-to-end path by which a `.gitmodules`-supplied submodule URL or a server-issued `WWW-Authenticate`/redirect ends up populating the credential's `url`/`host` fields that Git passes to the trampoline (this is standard Git credential-helper protocol behavior, but I did not locate Desktop-specific code that further sanitizes or restricts which URLs Git will invoke the helper for). If a Devin session or maintainer wants to confirm exploitability precisely, it would be worth verifying this with a live `git fetch` against a crafted submodule/remote in a sandboxed environment.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

export const createCredentialHelperTrampolineHandler: (
  store: AccountsStore
) => TrampolineCommandHandler = (store: Store) => async command => {
  const firstParameter = command.parameters.at(0)
  if (!firstParameter) {
    return undefined
  }

  const { trampolineToken: token } = command
  const input = parseCredential(command.stdin)

  if (__DEV__) {
    debug(
      `${firstParameter}\n${command.stdin
        .replaceAll(/^password=.*$/gm, 'password=***')
        .replaceAll(/^(.*)$/gm, '  $1')
        .trimEnd()}`
    )
  }

  try {
    if (firstParameter === 'get') {
      const cred = await getCredential(input, store, token)
      if (!cred) {
        const endpoint = `${getCredentialUrl(input)}`
        info(`could not find credential for ${endpoint}`)
        setHasRejectedCredentialsForEndpoint(token, endpoint)
      }
      return cred ? formatCredential(cred) : undefined
    } else if (firstParameter === 'store') {
      await storeCredential(input, store, token)
    } else if (firstParameter === 'erase') {
      await eraseCredential(input, store, token)
    }
    return undefined
  } catch (e) {
    error(`${firstParameter} failed`, e)
    return undefined
  }
}

export const getCredentialUrl = (cred: Map<string, string>) => {
  const u = cred.get('url')
  if (u) {
    return new URL(u)
  }

  const protocol = cred.get('protocol') ?? ''
  const username = cred.get('username')
  const user = username ? `${encodeURIComponent(username)}@` : ''
  const host = cred.get('host') ?? ''
  const path = cred.get('path') ?? ''

  return new URL(`${protocol}://${user}${host}/${path}`)
}
```
