### Title
TextFormat's `PrintAny` emits the `Any.type_url` field verbatim into the `[...]  { ... }` structural template without escaping delimiter characters — (File: `src/google/protobuf/text_format.cc`)

### Summary
`TextFormat::Printer::PrintAny` (C++), `TextFormat.printAny` (Java), and `_Printer._TryPrintAsAnyMessage` (Python) all print the attacker-controllable `Any.type_url` string field directly into the TextFormat output between the literal delimiters `[` and `]`, with no escaping of characters that are structurally significant in TextFormat syntax (`]`, `{`, `}`, `"`, newline, `#`). Because `type_url` is an ordinary `string` field populated from untrusted binary/ProtoJSON input, and only the suffix after the last `/` needs to resolve to a registered message type, the prefix portion is fully attacker-controlled and can contain arbitrary TextFormat-significant bytes. This mirrors the xmldom CDATA issue: attacker data is placed into a serialized "trusted" markup/structure without terminator-safe encoding, letting the attacker inject additional structure into the output that a downstream TextFormat consumer will parse differently than intended.

### Finding Description
`Any` is a well-known type with fields `string type_url = 1` and `bytes value = 2`. Both are ordinary fields with no built-in content restriction — the WHATWG/DOM-spec-analog restriction described in `any.proto`'s doc comment ("content ... must consist only of alphanumeric characters, percent-encoded escapes, and characters in `/-.~_!$&()*+,;=`") is documentation only; it is not enforced when constructing/parsing an `Any` via normal binary or ProtoJSON `ParseFrom*`. [1](#0-0) 

The only place this restriction is actually enforced is in the TextFormat *parser*, `ConsumeAnyTypeUrlOrFullTypeName`, which validates identifier characters in the type name portion after the last `/` — but this validation exists solely to accept round-tripped input, and it has no bearing on what `PrintAny` is permitted to *emit*. [2](#0-1) 

On the **write path**, `TextFormat::Printer::PrintAny` does:
```
generator->PrintLiteral("[");
generator->PrintString(type_url);
generator->PrintLiteral("]");
```
`type_url` is written with `PrintString`, which — unlike the general string-field printer (`FastFieldValuePrinter::PrintString`, which quotes and C-escapes values via `ContainsCharactersToCEscape`/`CEscape`) — performs **no escaping and no quoting** here; it is raw structural output, not a quoted string literal. [3](#0-2) 

Contrast this with the general string printer used for every other string field, which does escape control chars, quotes, and backslashes before printing: [4](#0-3) 

The same unescaped pattern exists in Java's `printAny`:
```
generator.print("[");
generator.print(typeUrl);
generator.print("]");
``` [5](#0-4) 

and in Python's `_TryPrintAsAnyMessage`:
```
self.out.write('%s[%s]%s ' % (self.indent * ' ', message.type_url, colon))
``` [6](#0-5) 

Reachability of `PrintAny`/`printAny` only requires: (1) the descriptor is recognized as `google.protobuf.Any` via `GetAnyFieldDescriptors`, which merely checks field numbers/types (1=string, 2=bytes) — it performs **no validation of the `type_url` content** [7](#0-6) ; and (2) the type-name suffix after the last `/` resolves in the type registry/pool and the `value` bytes parse successfully as that type — both fully satisfiable by an attacker who controls both the `type_url` and `value` bytes of the embedded `Any` submessage.

Because only the suffix after the last `/` is used for type resolution, everything before that final `/` is attacker-controlled free text that is echoed byte-for-byte into the TextFormat output. An attacker can craft, for example:
```
type_url = "evil\n}\ninjected_field: \"pwned\"\nfake {\ntype.googleapis.com/google.protobuf.StringValue"
```
which, once embedded in a larger message and printed with `TextFormat::PrintToString`/`DebugString`, produces output whose brace/field structure no longer matches the original message — precisely analogous to xmldom's `]]>` terminator breaking out of CDATA and injecting new markup.

### Impact Explanation
The invariant that fails to transfer safely is: *"data placed into a demarcated structural region of a serialized 'trusted' format must have its region-terminating sequences escaped."* In xmldom this was CDATA's `]]>`; here it is TextFormat's structural characters (`]`, `{`, `}`, newline, `"`, `#`). The impact is integrity of the generated TextFormat document: any downstream consumer that persists TextFormat debug/print output and later re-parses it with `TextFormat::Parse` (a documented, supported use case for TextFormat — e.g., snapshot/diff tooling, config generation from templates, test fixtures capturing "golden" text, or logging pipelines that store and later diff/re-ingest debug strings) will see attacker-injected fields, comments, or messages that were never present in the original protobuf message. This satisfies CWE-91-style structural injection, matching the "integrity of generated structured documents / business-logic injection" impact category of the report, without requiring memory corruption. It stays within "Impact: C:N/I:H/A:N" territory — no confidentiality or availability compromise, but a genuine integrity violation of the text-format representation.

### Likelihood Explanation
Requires only a bounded, valid `Any` submessage sent through a supported public parse API (`ParseFromString`/`MergeFrom`) with (a) a `type_url` whose suffix names a type present in the application's type registry/descriptor pool, and (b) `value` bytes that parse as that type — both attacker-controllable since the attacker supplies the whole `Any` submessage. The only precondition outside attacker control is that the consuming application later calls `TextFormat::PrintToString`/`DebugString` (or Java/Python equivalents) with Any-expansion enabled (default for these Printer paths using a type registry) and that some downstream process treats that output as re-parseable structured data. This is a plausible but not universal application pattern — TextFormat is documented as "not a stable, safe format to parse from untrusted input" but here the *attacker-influenced field is on the print side*, which is a materially different risk than the general Parse hardening advice.

### Recommendation
Escape or quote `type_url` before printing it inside the `[...]` delimiters in `TextFormat::Printer::PrintAny` (C++), `TextFormat.printAny` (Java), and `_Printer._TryPrintAsAnyMessage` (Python) — e.g., reuse the same C-escaping applied to ordinary string fields (`FastFieldValuePrinter::PrintString`'s `ContainsCharactersToCEscape`/`CEscape` logic) for the type-url segment, or reject/refuse to expand `Any` values whose `type_url` contains characters outside the documented safe set (`alphanumeric`, `%XX`, and `` /-.~_!$&()*+,;= ``) before attempting expansion, falling back to printing the raw `type_url`/`value` fields (which already go through the safe, escaping string printer).

### Proof of Concept
Conceptual reproduction (not run in this environment — the checkout provides source only, no build/test execution was performed; this should be validated with an actual build):
```cpp
// Trusted schema: any_test.proto (has TestAny.any_value : google.protobuf.Any)
// Attacker supplies these bytes over ParseFromString for the Any submessage:
google::protobuf::Any evil;
evil.set_type_url(
    "evil\n}\ninjected_field: \"pwned\"\nfake {\n"
    "type.googleapis.com/google.protobuf.StringValue");
google::protobuf::StringValue sv;
sv.set_value("x");
evil.set_value(sv.SerializeAsString());

TestAny msg;
*msg.mutable_any_value() = evil;   // attacker-controlled bytes, valid wire format

TextFormat::Printer printer;
printer.SetExpandAny(true);
std::string out;
printer.PrintToString(msg, &out);
// `out` now contains an unescaped '}' and injected field lines inside
// what should have been a single "[type_url] { ... }" block — the
// TextFormat structure is corrupted/injectable, analogous to the
// xmldom "]]>" CDATA terminator injection.
```
This demonstrates the failed invariant (unescaped structural delimiters in attacker-controlled `type_url`) and the missing check (no validation/escaping in `PrintAny`, contrasted with the escaping applied to every other string field via `FastFieldValuePrinter::PrintString`). Full compile/run verification was not performed here and should be done by a follow-up engineer with build tooling.

void TextFormat::FastFieldValuePrinter::PrintString(
    const std::string& val, BaseTextGenerator* generator) const {
  generator->PrintLiteral("\"");
  if (!val.empty()) {
    if (ABSL_PREDICT_FALSE(ContainsCharactersToCEscape(val))) {
      generator->PrintString(absl::CEscape(val));
    } else {
      generator->PrintString(val);
    }
  }
  generator->PrintLiteral("\"");
}

                            const FieldDescriptor * PROTOBUF_NULLABLE *
                                PROTOBUF_NONNULL type_url_field,
                            const FieldDescriptor * PROTOBUF_NULLABLE *
                                PROTOBUF_NONNULL value_field) {
  const Descriptor* descriptor = message.GetDescriptor();
  if (descriptor->full_name() != kAnyFullTypeName) {

  *type_url_field = descriptor->FindFieldByNumber(1);
  *value_field = descriptor->FindFieldByNumber(2);

          *value_field != nullptr &&

}
