### Title
Malformed nonce vector causes panic in Schnorrkel signature verification - (File: crypto/schnorrkel/src/lib.rs)

### Summary
`Schnorrkel::verify` dereferences `nonces[0][0]` without validating that the outer or inner vector is non-empty. An empty or malformed nonce vector therefore causes an index-out-of-bounds panic rather than returning `None` or an error. [1](#0-0) 

### Finding Description
The `Algorithm<Ristretto>::verify` implementation accepts `nonces: &[Vec<RistrettoPoint>]` as public input. Its first operation constructs a `SchnorrSignature` using `nonces[0][0]`. [1](#0-0) 

If `nonces` is empty, `nonces[0]` panics. If `nonces` contains an empty inner vector, `nonces[0][0]` also panics. Additionally, verification unconditionally unwraps `self.msg`, which is only populated by `sign_share`; calling `verify` on a newly constructed algorithm with a well-formed nonce vector can therefore reach another panic path. [2](#0-1) [3](#0-2) 

### Impact Explanation
An unprivileged caller able to supply nonce data to this public verification API can terminate the calling thread or process. In deployments where verification handles attacker-controlled protocol data without catching panics, this provides a denial of service analogous to the referenced NULL-pointer dereference. [4](#0-3) 

### Likelihood Explanation
The panic requires only an empty `Vec<Vec<RistrettoPoint>>` or a vector whose first element is empty. No valid key, signature, secret share, threshold participant, or protocol state is required. The normal FROST signing path normally constructs nonces internally, but the verifier remains publicly callable through the `Algorithm` trait with malformed input. [5](#0-4) [4](#0-3) 

### Recommendation
Validate the expected nonce shape before indexing. At minimum, reject an empty outer vector and an empty first nonce list. Also avoid storing message-dependent verification state implicitly in `self.msg`; either require the message as a `verify` argument or return `None` when verification is invoked before `sign_share`. [4](#0-3) 

### Proof of Concept
```rust
use frost_schnorrkel::Schnorrkel;
use frost::algorithm::Algorithm;
use ciphersuite::Ciphersuite;
use dalek_ff_group::{Ristretto, RistrettoPoint, Scalar};

let algorithm = Schnorrkel::new(b"context");
let nonces: &[Vec<RistrettoPoint>] = &[];

let _ = <Schnorrkel as Algorithm<Ristretto>>::verify(
    &algorithm,
    RistrettoPoint::generator(),
    nonces,
    Scalar::ZERO,
);
```

This panics at `nonces[0][0]` because the outer nonce vector is empty. [1](#0-0)
