Confirmed: `IsExecutable`/`VerifyExecutable` in `kaiax/gasless/impl/getter.go` (used by `ExtractTxBundles` in `kaiax/gasless/impl/builder.go`) does **not** check `SwapArgs.Deadline` at all at block-building time. The only deadline check is `checkBalanceForSwap()` in `kaiax/gasless/impl/tx_pool.go`, invoked via `GetCheckBalance()` during tx-pool promotion (`IsReady`), which compares `deadline` against `g.Chain.CurrentBlock().Time()` — the current head at admission time, not the block the swap will actually be executed in.

### Title
Gasless SwapTx deadline is checked only at tx-pool admission, not at bundle execution time - (File: kaiax/gasless/impl/tx_pool.go, kaiax/gasless/impl/getter.go)

### Summary
This mirrors the reported bug class: two logically-linked time-window checks (admission-time validity vs. execution-time validity) are inconsistent, allowing an action to proceed outside its intended window. In `TrufVesting`, `cancelVesting()`'s time boundary didn't match `claimable()`'s. In `kaiax/gasless`, the `SwapArgs.Deadline` is validated once when the swap transaction is promoted to the pending pool (`checkBalanceForSwap`, using `g.Chain.CurrentBlock().Time()`), but is never re-validated in `VerifyExecutable`/`IsExecutable` (`kaiax/gasless/impl/getter.go`) when the transaction is actually bundled and included in a block by `ExtractTxBundles` (`kaiax/gasless/impl/builder.go`).

### Finding Description
`checkBalanceForSwap` performs: [1](#0-0) 
This check happens only once, at the moment the tx is promoted to "ready" via `IsReady`. A swap transaction can sit in the pending pool across multiple blocks (it is a normal pending transaction, subject to gas price / nonce ordering like any other tx) before being selected into a block by the miner/proposer. When the block is finally assembled, `ExtractTxBundles` calls `IsExecutable`/`VerifyExecutable`: [2](#0-1) 
None of the checks in `VerifyExecutable` (Sx, AP1, SP1–SP4) re-validate `swapArgs.Deadline` against the block into which it is about to be included. Consequently, the swap can be bundled and its `LendTx`/`RepayTx` executed by the proposer even though the caller's declared `deadline` has already elapsed relative to the block time of inclusion.

### Impact Explanation
This allows execution of a gasless swap that the user intended to expire — the swap router-side deadline is caller-declared protection against stale price quotes/slippage during volatile markets. Bypassing it can result in the sender's swap executing at unfavorable (stale) exchange rates, forcing them to repay the proposer's lent gas (`RepayAmount`) for a swap they no longer authorized as valid, which is unauthorized value movement / fee-delegation abuse of the gasless module's lend-and-repay mechanism (`GetLendTxGenerator`/`repayAmount` in `kaiax/gasless/impl/getter.go`).

### Likelihood Explanation
Medium-High: this is reachable by any public transaction sender using the gasless swap feature — no special privilege needed. It requires only that a swap transaction remains pending across at least one block after its deadline before the proposer includes it, which can happen naturally under congestion, or could be deliberately induced by a proposer/searcher holding the transaction in its pool longer to extract value from stale pricing.

### Recommendation
Re-validate `swapArgs.Deadline` against the block time of the block currently being assembled (or the immediately following block) inside `VerifyExecutable` in `kaiax/gasless/impl/getter.go`, in addition to (not instead of) the pool-admission check in `checkBalanceForSwap`, ensuring the same time-window semantics are enforced consistently at both admission and execution.

### Proof of Concept
1. Submit an `ApproveTx` + `SwapTx` where `SwapTx`'s `deadline` is set to `currentBlockTime + 1` (passes admission check in `checkBalanceForSwap` since `CurrentBlock().Time()` at admission ≤ deadline).
2. Delay inclusion (e.g., via low gas price relative to other pending txs, or a busy mempool) so the swap remains pending for more than one block, until the chain's block time exceeds `deadline`.
3. When the proposer builds a block including this `SwapTx`, `ExtractTxBundles` → `IsExecutable`/`VerifyExecutable` is called; since it never inspects `Deadline`, the bundle (LendTx + ApproveTx + SwapTx) is still generated and executed against the stale/expired deadline, executing the underlying `swapForGas` call on-chain past the user's declared deadline.

func (g *GaslessModule) IsExecutable(approveTxOrNil, swapTx *types.Transaction) bool {
	err := g.VerifyExecutable(approveTxOrNil, swapTx)
	if err != nil {
		return false
	}
	return true
}

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}
