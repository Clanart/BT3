## Title
Reward forfeiture rate is retroactively applied to previously-accrued (non-expired) rewards - (File: rewards/vlMGPBaseRewarder.sol)

### Summary
`vlMGPBaseRewarder` (and its mirror `mWOMSVBaseRewarder`) forfeits a portion of a user's accrued MGP reward bucket whenever the user's current `vlMGP.getRewardablePercentWAD()` is less than 100%. This percentage is a single, current-timestamp snapshot that is applied to the **entire** pending reward bucket that has accumulated since the last checkpoint — even though part of that bucket was earned during a period when the user's rewardable percentage was 100% (fully locked or validly in cooldown). This is the same bug class as the Fraxlend finding: a "penalty/rate" that should only apply prospectively from the moment the qualifying condition starts is instead applied retroactively over an interval that predates it.

### Finding Description
Reward accrual in `vlMGPBaseRewarder` uses a standard `rewardPerTokenStored` checkpoint model. When a user's position is touched (via `getReward`/`getRewards`, triggered by `VLMGP.lock`/`startUnlock`/`unlock`/`forceUnLock` calling `multiclaimFor`), `_updateFor` computes the entire unclaimed reward since the last checkpoint in one shot: [1](#0-0) 

That single lump amount is then passed to `_sendReward`, which computes forfeiture using **the current** rewardable percentage from `VLMGP.getRewardablePercentWAD`: [2](#0-1) 

`getRewardablePercentWAD` in `VLMGP.sol` returns 100% weight for tokens still locked or still within an active cooldown window, but once a cooldown slot passes its `endTime` without the user calling `unlock()`, the weight for that slot begins decaying the longer the user waits: [3](#0-2) 

Because `_calExpireForfeit` is applied to the whole accumulated `userRewards` bucket rather than being pro-rated per sub-interval matching the rewardable state at the time each portion of reward accrued, any reward earned **before** a slot expired (i.e., while the user was fully entitled to 100% of rewards) is forfeited at the same decayed rate as reward earned long after expiry — exactly mirroring how FraxlendPair applied its post-maturity penalty rate to the pre-maturity interest-accrual period.

### Impact Explanation
An ordinary vlMGP holder who does not immediately call `unlock()` after a cooldown slot matures, and who does not otherwise touch their vlMGP position (no `lock`/`startUnlock`/`forceUnLock`) for an extended period, will have MGP reward tokens accrued during valid (fully-rewardable) time windows unnecessarily and permanently forfeited to the pool's `queuedRewards` when they finally trigger a claim. This is a direct, unprivileged-wallet-reachable loss of already-earned, unclaimed yield — the forfeited amount is never returned to the original earner. The same mechanism exists in `mWOMSVBaseRewarder`/`mWomSV.sol`.

### Likelihood Explanation
Reachable purely through normal user behavior: lock MGP, start an unlock, and simply delay calling `unlock()` after the cooldown ends (a very plausible, common user pattern — no adversarial or privileged action required). The longer the delay, the larger the retroactively-misapplied forfeit becomes, similar to the "user is a few minutes/days late" scenario discussed in the original Frax finding.

### Recommendation
Checkpoint and settle (or freeze) the forfeit-relevant rewardable percentage at the moment it changes (e.g., when a cooldown slot's `endTime` passes), so that only reward accrued *after* that point is subject to the decaying/expired-slot penalty. Alternatively, snapshot `rewardPerToken` and apply the forfeit percentage incrementally at each state transition instead of applying one current-time percentage to the full historical bucket.

### Proof of Concept
1. User locks 1000 MGP in `VLMGP` (`lock`) — `getRewardablePercentWAD` = 100%.
2. Rewards accrue in `vlMGPBaseRewarder` for 30 days via `queueNewRewards` increasing `rewardPerTokenStored`.
3. User calls `startUnlock(500)` — this triggers `multiclaimFor` (checkpointing the first 30 days' rewards at 100%, no forfeit) then opens a cooldown slot with `endTime = now + coolDownInSecs`.
4. Rewards keep accruing for a further period spanning both the valid cooldown window and well past its `endTime` (user never calls `unlock()`).
5. User eventually calls another VLMGP action (e.g., `lock(1)`), triggering `getReward` → `_updateFor` computes the full reward bucket since step 3's checkpoint in one lump sum, per [1](#0-0) .
6. `_sendReward`/`_calExpireForfeit` applies the *current*, decayed `getRewardablePercentWAD` (now low, because the slot has been expired for a long time) to that entire bucket, per [4](#0-3) , forfeiting a large chunk of reward that was actually earned while the slot was still validly within its cooldown window (deserving 100% reward).

            address rewardToken = rewardTokens[index];

            userRewardPerTokenPaid[rewardToken][_account] = rewardPerToken(rewardToken);

    function _sendReward(address _rewardToken, address _account, address _receiver) internal {
        uint256 forfeitAmount = _calExpireForfeit(_account, userRewards[_rewardToken][_account]);
        uint256 toSend = userRewards[_rewardToken][_account] - forfeitAmount;


        userRewards[_rewardToken][_account] = 0;
            
        if (toSend > 0) {
            IERC20(_rewardToken).safeTransfer(_receiver, toSend);
            emit RewardPaid(_account, _receiver, toSend, _rewardToken);
        }

        if(forfeitAmount > 0)
            _queueNewRewardsWithoutTransfer(forfeitAmount, _rewardToken);
    }

    function _earned(address _account, address _rewardToken, uint256 _userVlmgpShare) internal view returns (uint256) {
        return ((_userVlmgpShare *
                (rewardPerToken(_rewardToken) -
                    userRewardPerTokenPaid[_rewardToken][_account])) /
                10**vlMGPDecimal) + userRewards[_rewardToken][_account];
    }

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalVlmgp = fullyInLock + inCoolDown;
        if (userTotalVlmgp == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalVlmgp;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalVlmgp / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalVlmgp;
                }

            }
        }

        return percent;
    }
