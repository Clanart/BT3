### Title
Gasless module's "sender must not have code" check is a stale, one-time admission check that EIP-7702 delegation can bypass before block inclusion - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The gasless module's `checkBalanceForApprove`/`checkBalanceForSwap` enforce a "sender with code is not allowed" restriction using `getCurrentHasCode`, but this check is performed only once, at mempool admission time, against a snapshot state (`g.currentState`). It is never re-verified in `VerifyExecutable`/`IsExecutable`, which is the function actually used at block-building/bundling time. This is structurally the same bug class as the reported `rebalance()` EOA check: a point-in-time "caller/sender must be EOA (no code)" gate that can become stale/ineffective because Kaia natively supports EIP-7702 (`SetCode`) transactions, which let an EOA acquire delegated code between the time the gate is checked and the time the gated transaction is actually executed.

### Finding Description
`GetCheckBalance()` dispatches to `checkBalanceForApprove`/`checkBalanceForSwap`, which — when `BalanceCheckLevel == BalanceCheckLevelAll` (the **default** config, see `DefaultGaslessConfig`) — reject the gasless approve/swap tx if `getCurrentHasCode(sender)` is true: [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) 

This check runs only when the transaction is first admitted to the pool (`GetCheckBalance` is invoked from tx-pool validation). It is *not* part of `VerifyExecutable`, which is the authoritative function used later for both promotion readiness (`isApproveTxReady`/`isSwapTxReady`) and, critically, for bundle construction at block-building time (`ExtractTxBundles` → `IsExecutable` → `VerifyExecutable`): [5](#0-4) [6](#0-5) 

Kaia natively supports EIP-7702 `SetCode` transactions that let an EOA delegate to arbitrary code, verified by the codebase's own EIP-7702 test coverage (`TestEIP7702`, `sendSetCodeTx`) and by the gasless module's own test explicitly demonstrating this pattern for rejecting a tx "originating from an EOA with code" via a `SetCode` tx: [7](#0-6) 

Because the code-check is evaluated once, against whatever state existed when the tx was admitted to the pool, and is never re-checked at the moment the gasless bundle is actually executed by the block builder, an attacker-controlled EOA can:
1. Submit a `GaslessApproveTx`/`GaslessSwapTx` while it has no code (passes `getCurrentHasCode` at admission and enters the pool/`knownTxs` as queued).
2. Before the transaction is promoted/bundled, submit (or have delegated) an EIP-7702 `SetCode` transaction that installs delegated code on the same EOA.
3. When the block builder later calls `ExtractTxBundles`/`IsExecutable`/`VerifyExecutable` to assemble and include the bundle (`LendTxGenerator, ApproveTx, SwapTx`), no `getCurrentHasCode` check is performed — the transaction is bundled and executed with the block proposer's lent gas even though the sender's account now carries delegated (attacker) code.

This mirrors exactly the flagged bug class: an "EOA-only" gate implemented as a point-in-time state check (`tx.origin`-style / `GetCodeHash` check) that a native account-abstraction primitive (EIP-3074 `AUTH`/`AUTHCALL` in the original report, EIP-7702 `SetCode` here) can invalidate between check-time and execution-time, opening the path to contract-driven exploitation of a privileged, EOA-gated flow.

### Impact Explanation
The `sender-with-code` restriction exists specifically to prevent contract-controlled accounts from participating in the gasless swap/approve flow (e.g., to block callback/reentrancy tricks or price-manipulating flash-loan-style contracts from abusing the block-proposer-funded gas lending mechanism in `GetLendTxGenerator`). Bypassing it via a stale check allows an attacker's delegated contract logic to execute within the same trust context that the "EOA-only" restriction was meant to exclude, undermining the intended anti-abuse guarantee of the gasless module and risking fee-delegation/lend-repay abuse (the block proposer's lent KAIA is repaid based on a swap whose execution context the "no code" check was supposed to constrain). This qualifies as fee-delegation/gasless settlement abuse reachable purely from a submitted transaction sequence.

### Likelihood Explanation
Exploitation requires only the ability to submit transactions from a controlled EOA: a `SetCode` (EIP-7702) transaction plus timed submission of the gasless approve/swap transaction relative to pool promotion and block assembly — all achievable by any public RPC caller/unprivileged sender, with no validator, node, or governance privilege required. The window between admission-time state and block-building-time state is inherent to the tx-pool/knownTxs queuing design (`QueueTimeout`, `PendingTimeout` of up to 10s), giving a realistic timing window for the attacker to install code after passing the check.

### Recommendation
Re-validate `getCurrentHasCode(sender)` (or equivalent freshness check) inside `VerifyExecutable`/`IsExecutable`, i.e., at the point where the bundle is actually about to be built/executed (`ExtractTxBundles`, `isApproveTxReady`, `isSwapTxReady`), not only once at initial pool admission. Alternatively, invalidate/re-check known gasless txs in `PostReset`/`PreReset` whenever the sender's code hash changes (e.g., after a `SetCode` tx targeting that sender is observed), dropping them from `knownTxs` before they can be bundled.

### Proof of Concept
1. Attacker EOA `A` (no code) submits a `GaslessApproveTx` (and/or `GaslessSwapTx`) — passes `checkBalanceForApprove`/`checkBalanceForSwap`'s `getCurrentHasCode(A)` check at `kaiax/gasless/impl/tx_pool.go:78-82` and is added to `knownTxs` as `TxStatusQueue`.
2. Attacker submits an EIP-7702 `SetCode` transaction from `A` (the same mechanism validated by `tests/gasless_test.go:265`, `sendSetCodeTx`), installing delegated contract code on `A`.
3. Once nonce conditions are met, `isApproveTxReady`/`isSwapTxReady` (`kaiax/gasless/impl/tx_pool.go:252-290`) promote the txs to pending using only nonce and `VerifyExecutable` checks — no code check.
4. The block builder's `ExtractTxBundles` (`kaiax/gasless/impl/builder.go:28-72`) bundles `[LendTxGenerator, ApproveTx, SwapTx]` and the worker executes it via `commitBundleTransaction` (`work/worker.go:877-954`), running `A`'s now-delegated code within the proposer-funded gasless flow that the "no code" rule was designed to exclude.

func (g *GaslessModule) getCurrentHasCode(addr common.Address) bool {
	g.currentStateMu.Lock()
	defer g.currentStateMu.Unlock()

	return g.currentState.GetCodeHash(addr) != types.EmptyCodeHash
}

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}
