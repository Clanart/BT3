### Title
`ThresholdKeys::read` performs quadratic Lagrange interpolation over an attacker-controlled participant count, enabling CPU DoS - (File: crypto/dkg/src/lib.rs)

### Summary

The external report describes a bug class where cryptographic parsers accept pathologically large parameters (oversized RSA moduli / DSA values), turning signature verification into minutes of CPU work per attacker-supplied input. `ThresholdKeys::<C>::read` has the same shape: the `t`/`n` fields of a serialized `ThresholdKeys` blob are attacker-controlled u16s, and `ThresholdKeys::new` (called unconditionally at the end of `read`) computes the group key via per-participant Lagrange interpolation factors, each of which is itself O(t). The result is O(t²) field arithmetic — up to ~4.3 billion field multiplications for `t = n = 65535` — triggered by a single untrusted byte string of only ~2–4 MB.

### Finding Description

`ThresholdKeys::read` in `crypto/dkg/src/lib.rs` reads `t`, `n`, and `i` directly from the input stream, then reads `n` verification-share points and invokes `ThresholdKeys::new` (`crypto/dkg/src/lib.rs:574-631`). `ThresholdKeys::new` computes:

```rust
let t = (1 ..= params.t()).map(Participant).collect::<Vec<_>>();
let group_key =
  t.iter().map(|i| verification_shares[i] * interpolation.interpolation_factor(*i, &t)).sum();
```

(`crypto/dkg/src/lib.rs:376-378`)

With `Interpolation::Lagrange` (serialization tag `1`, fully attacker-selected at `crypto/dkg/src/lib.rs:604-616`), `interpolation_factor` iterates over the entire `included` slice performing one field multiplication, one field subtraction-multiplication, per element, plus a field inversion (`crypto/dkg/src/lib.rs:229-247`). Therefore `ThresholdKeys::new` costs Θ(t²) field multiplications plus t scalar multiplications. Since `t` is a raw u16 read from the wire, an attacker who supplies `t = n = 65535`, `i = 1`, and 65535 syntactically valid points forces ~4.3×10⁹ field multiplications and ~65k variable-time scalar multiplications inside a single `ThresholdKeys::read` call — tens of minutes to hours of CPU, directly analogous to the "several minutes of CPU" oversized-modulus issue in x/crypto.

There is no size limit: `ThresholdParams::new` only checks `t <= n` and `i <= n` (`crypto/dkg/src/lib.rs:166-178`), and `read` allocates `Vec::with_capacity(n)` and a `HashMap` with `n` entries regardless of what a sane deployment needs (FROST multisigs in Serai are capped far below 65535 participants in practice).

### Impact Explanation

Any context where `ThresholdKeys::read` — explicitly in scope as an untrusted-byte sink — is applied to data influenced by an unprivileged party yields a denial of service: one small input (~2.1 MB for Ristretto/Ed25519-class points) pins a CPU core for a very long time. This matches the advisory's impact (unauthenticated remote DoS via crafted key material). It also maps onto legitimate protocol surfaces: `ThresholdKeys` blobs are transported/stored by callers of the DKG (e.g., key-blob reloading paths such as `processor/src/key_gen.rs:56-61`, which `unwrap()`s the result — the panic after the expensive computation is a secondary availability concern, though the DoS itself occurs inside `read`/`new` regardless of the unwrap).

### Likelihood Explanation

Triggering requires only delivering a crafted serialized `ThresholdKeys` to any code path calling `ThresholdKeys::read` on non-local data — no signature validity, no threshold participation, and no collusion is required; the cost is incurred before any semantic check could reject the blob (the only prior checks are `t <= n` bounds). The input must contain `n` decodable points, which is cheap to generate (~32–64 bytes each; identity/any valid encoding suffices since validity isn't checked before the O(t²) loop — the points just need `read_G` to succeed). Likelihood is bounded by whether deployments accept such blobs from untrusted sources; where they do (gossiped/persisted DKG artifacts, key recovery inputs), a single message stalls the reader.

### Recommendation

- Enforce a protocol-level maximum on `t`/`n` in `ThresholdKeys::read`/`ThresholdParams::new` (e.g., the maximum key-shares-per-set constant used elsewhere, `MAX_KEY_SHARES_PER_SET`), rejecting blobs whose `n` exceeds it before reading points or interpolating.
- Alternatively/ additionally, compute the group key with a multiexponentiation (`multiexp`) over shared Lagrange denominators — the standard O(n log n) batch-inversion trick — so that even the maximum legal `n` is cheap.
- Fail fast in `read` if `n` is inconsistent with the remaining stream length (points are fixed-size), avoiding the large `Vec`/`HashMap` allocations for truncated inputs.

### Proof of Concept

```rust
// Construct a maximally-expensive ThresholdKeys blob for any Ciphersuite C.
// For t = n = 65535 with Lagrange interpolation, ThresholdKeys::new performs
// ~t * t = ~4.3e9 field multiplications inside interpolation_factor.

fn dos_blob<C: Ciphersuite>() -> Vec<u8> {
    let mut buf = vec![];
    // C::ID header (as written by ThresholdKeys::write)
    buf.extend(u32::try_from(C::ID.len()).unwrap().to_le_bytes());
    buf.extend(C::ID);
    // t = 65535, n = 65535, i = 1
    buf.extend(65535u16.to_le_bytes());
    buf.extend(65535u16.to_le_bytes());
    buf.extend(1u16.to_le_bytes());
    // Interpolation::Lagrange (tag 1): constant interpolation is rejected unless t == n,
    // but Lagrange forces the O(t^2) path regardless of t vs n.
    buf.push(1u8);
    // secret_share
    buf.extend(C::F::ONE.to_repr().as_ref());
    // n verification shares, all the (valid) generator encoding
    for _ in 0 .. 65535 {
        buf.extend(C::generator().to_bytes().as_ref());
    }
    buf
}

// Trigger: a ~2.1 MB input causes ~hours of field arithmetic inside
//   ThresholdKeys::<C>::read(&mut blob.as_slice())
// via ThresholdKeys::new -> interpolation_factor (O(t) per participant, t participants)
// at crypto/dkg/src/lib.rs:376-378 and crypto/dkg/src/lib.rs:229-247.
```

No secret material, valid signatures, or protocol position is required — only delivery of the blob to a `ThresholdKeys::read` call site.
