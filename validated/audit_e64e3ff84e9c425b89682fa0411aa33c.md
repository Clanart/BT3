### Title
Desktop treats any HTTP host as a GitHub/GitHub Enterprise server based solely on a spoofable `x-github-request-id` response header, corrupting the git credential-helper flow - (File: `app/src/lib/api.ts`, `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
This is the closest local analog to the Chainlink `latestAnswer` bug class: both cases take a *single, unvalidated field from an external data source* and trust it as ground truth without any secondary integrity check (staleness/roundId in the oracle case, cryptographic/TLS-bound proof of identity in this case). In Desktop, `isGitHubHost()` decides whether a remote git host is "GitHub" purely by checking for the presence of the `x-github-request-id` HTTP response header [1](#0-0) . That header is fully attacker-controlled — any server (including one operated by the owner of an arbitrary git remote/proxy the user has added) can simply add it to its HTTP responses. This value then flows directly into the git credential-helper's `getEndpointKind()` classification, which changes how Desktop stores/erases/looks-up credentials and whether it force-prompts a GitHub OAuth sign-in for that host [2](#0-1) .

### Finding Description
`getEndpointKind()` in `trampoline-credential-helper.ts` is invoked by the git credential helper (`getCredential`/`storeCredential`/`eraseCredential`) for every host git needs credentials for while cloning/fetching/pushing [3](#0-2) . It classifies a host as `'github.com'`, `'ghe.com'`, `'enterprise'`, or `'generic'` using several checks, ending with:

```
return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
``` [4](#0-3) 

`isGitHubHost()` itself is a "best effort" probe that, after a few string-based hostname heuristics, falls back to firing an unauthenticated `HEAD /meta` request to the host and trusting the *presence* of a header:

```
const response = await fetch(metaUrl, { ... redirect: 'error' })
tryUpdateEndpointVersionFromResponse(endpoint, response)
return response.headers.has('x-github-request-id')
``` [5](#0-4) 

There is no verification that this header actually originates from `api.github.com`/a genuine GHE instance — no signature, no TLS certificate pinning, no correlation with the `x-github-enterprise-version` header's plausibility, nothing beyond "did the response contain this string." Any git remote/proxy the attacker controls (the exact threat model called out in scope — "a git remote/proxy response") can trivially forge this header and be classified as `'enterprise'`.

The consequence of this misclassification propagates into credential handling:
- In `storeCredential`/`eraseCredential`, if `endpointKind !== 'generic'` the function returns early without ever calling the generic credential store [6](#0-5) . This means a legitimate, non-GitHub host that an attacker (via MITM proxy or a malicious remote server) tricks into being classified as `'enterprise'` will silently have its user-entered credentials **not stored**, with no error surfaced to the user — a silent corruption of the expected credential-persistence behavior.
- In `getCredential`, a spoofed `'enterprise'`/non-`'generic'` classification for a host with no matching account causes Desktop to invoke `ui.promptForGitHubSignIn(endpoint)`, initiating a GitHub OAuth flow scoped to that attacker-influenced `endpoint` [7](#0-6) , and the resulting account, once created, could subsequently be matched against other repositories via `endpoint` string equality logic used elsewhere in the codebase (e.g., `findAccountForRemoteURL`, `matchGitHubRepository`) [8](#0-7) [9](#0-8) .

The `getEndpointVersion(endpoint) !== null` short-circuit earlier in `isGitHubHost` compounds this: once any single spoofed response has poisoned `localStorage`'s per-endpoint version cache via `updateEndpointVersion` [10](#0-9) , every subsequent call for that same `endpoint` string skips the network probe entirely and is unconditionally treated as a GitHub host — the equivalent of the oracle's "stale data being trusted forever" once cached.

### Impact Explanation
This falls squarely in the "silent corruption of what the user commits/pushes"-adjacent and "unauthorized OAuth/account binding" categories called out as valid impact: credentials the user intends to store for a legitimate non-GitHub remote can be silently dropped, and OAuth sign-in flows can be triggered against attacker-influenced endpoints, purely because the attacker's server sent one forgeable header. No admin rights, local access, or pre-existing malware are required — only that the user has (or is prompted to add) a remote/proxy pointing at the attacker's server, which is within the accepted "attacker controls a git remote/proxy response" threat model.

### Likelihood Explanation
Likelihood is moderate: the attacker needs the victim to interact with a git host they control (a self-hosted remote, a corporate-proxy MITM position, or a spoofed enterprise git server) and to have git attempt HTTPS credential negotiation against it, which is a common real-world scenario (adding third-party/self-hosted remotes, working behind corporate proxies). No special timing or race condition is required — spoofing the header is a one-line server change.

### Recommendation
Do not classify a host as GitHub/GitHub Enterprise based solely on the unauthenticated presence of `x-github-request-id`. At minimum:
- Require corroborating signals (e.g., a successful `x-github-enterprise-version` header that also parses to a plausible semver, combined with the request having succeeded over a certificate chain that wasn't force-suppressed via `suppressCertificateErrorFor`), or
- Require the user to explicitly confirm/allowlist enterprise endpoints the first time (similar to how GHE accounts are set up today) rather than silently auto-classifying hosts from a probe response, and
- Never let a single unauthenticated response permanently poison the per-endpoint version/host-kind cache (`endpoint-capabilities.ts`) — cache entries derived from unauthenticated probes should be revalidated or scoped to a signed-in account association rather than a bare endpoint string.

### Proof of Concept
1. Attacker stands up an HTTP server that responds to `HEAD /meta?ghd=*` with any status and includes header `x-github-request-id: spoofed`.
2. Victim adds this server's URL as a git remote and attempts to fetch/push over HTTPS; git prompts the credential helper.
3. `getEndpointKind()` → `getEndpointVersion(endpoint) === null`, falls through to `isGitHubHost(endpoint)` [4](#0-3) .
4. `isGitHubHost` issues the probe request, sees `x-github-request-id` present, returns `true` [5](#0-4) .
5. `getEndpointKind` returns `'enterprise'`; subsequent `storeCredential` calls for this attacker host silently no-op instead of persisting the user's actual credentials [11](#0-10) , and/or `getCredential` triggers a GitHub OAuth sign-in prompt bound to the attacker's endpoint [12](#0-11) .

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

async function storeCredential(cred: Credential, store: Store, token: string) {
  if ((await getEndpointKind(cred, store)) !== 'generic') {
    return
  }

  return useExternalCredentialHelper()
    ? storeExternalCredential(cred, token)
    : setGenericCredential(
        urlWithoutCredentials(getCredentialUrl(cred)),
        forceUnwrap(`credential missing username`, cred.get('username')),
        forceUnwrap(`credential missing password`, cred.get('password'))
      )
}

const storeExternalCredential = (cred: Credential, token: string) => {
  const path = getTrampolineEnvironmentPath(token)

export function matchGitHubRepository(
  accounts: ReadonlyArray<Account>,
  remote: string
): IMatchedGitHubRepository | null {
  for (const account of accounts) {
    const htmlURL = getHTMLURL(account.endpoint)
    const { hostname } = URL.parse(htmlURL)
    const parsedRemote = parseRemote(remote)

    if (parsedRemote !== null && hostname !== null) {
      if (parsedRemote.hostname.toLowerCase() === hostname.toLowerCase()) {
        return { name: parsedRemote.name, owner: parsedRemote.owner, account }
      }
    }
  }

  return null
}

/**
 * Update the known version number for a given endpoint

export function updateEndpointVersion(endpoint: string, version: string) {
  const key = endpointVersionKey(endpoint)

  if (rawVersionCache.get(key) !== version) {
    const parsed = semver.parse(version)
    localStorage.setItem(key, version)
    rawVersionCache.set(key, version)
    versionCache.set(key, parsed)
  }
}
