### Title
Front-runnable forfeited-reward redistribution lets an attacker capture other lockers' yield via just-in-time `lockFor` - ([File: rewards/vlMGPBaseRewarder.sol])

### Summary
`_sendReward` → `_queueNewRewardsWithoutTransfer` injects a forfeiting user's forfeited reward into the pool by bumping `rewardPerTokenStored` using the *instantaneous* `totalStaked()` (`vlMGP.totalSupply()`), with no time-weighting or checkpoint delay. An attacker who sees a large pending `getReward`/forfeiture transaction in the mempool can front-run it with `VLMGP.lockFor()` to inflate their own vlMGP balance just before the injection, then immediately claim a share of the forfeited reward proportional to their new balance despite zero prior accrual time.

### Finding Description
`totalStaked()` reads `IERC20(address(vlMGP)).totalSupply()` live [1](#0-0) , and `balanceOf()` reads the account's live staked amount from `MasterMagpie.stakingInfo` [2](#0-1) . `_queueNewRewardsWithoutTransfer` distributes forfeited reward pro-rata to whatever `totalStaked()` is at the moment of the call, with no minimum holding period or time-weighted checkpointing: [3](#0-2) 

`getReward` calls `updateReward(_account)` then `_sendReward`, which computes the victim's forfeit via `_calExpireForfeit` (based on the victim's own cooldown state) and re-injects it: [4](#0-3) 

Exploit flow:
1. Attacker observes a mempool transaction that will trigger a large forfeiture (e.g. a user's `getReward`/`queueMGP` call for a MGP-in-cooldown user, whose `getRewardablePercentWAD` [5](#0-4)  yields a large forfeit).
2. Attacker front-runs with `VLMGP.lockFor(largeAmount, attacker)`, which calls `MasterMagpie._deposit` → `_harvestBaseRewarder` → `rewarder.updateFor(attacker)` **before** `user.amount` (and thus `balanceOf(attacker)`) and `vlMGP.totalSupply()` are increased [6](#0-5) . This checkpoints `userRewardPerTokenPaid[reward][attacker]` at the pre-injection `rewardPerTokenStored`, then the attacker's stake and `totalStaked()` are bumped up.
3. The victim's `getReward` lands next in the same block, computing forfeit and calling `_queueNewRewardsWithoutTransfer`, which raises `rewardPerTokenStored` using the now-inflated `totalStaked()` (which already includes attacker's stake).
4. Attacker immediately calls `getReward`/`getRewards` (via `MasterMagpie`) and receives `attackerBalance * (newRPT - oldRPT)` — a full pro-rata share of the forfeited reward — despite having staked for zero blocks.
5. Attacker can then `startUnlock`/`unlock` (waiting out the normal cooldown, incurring no penalty) to retrieve their principal MGP intact.

Existing checks (`onlyMasterMagpie`, `updateReward`/`updateRewards` modifiers, `nonReentrant` on `getRewards`) only gate access and prevent reentrancy; none of them time-weight the distribution or checkpoint stake duration, so they do not prevent this dilution/front-run.

### Impact Explanation
This is a real, quantifiable theft of unclaimed/forfeited yield from long-term lockers: capital that was staked for zero time captures a full pro-rata share of a reward injection that other stakers accrued exposure to over time. This matches the "theft of unclaimed yield" impact class — legitimate lockers' expected share of the forfeited reward is diluted and redirected to the front-running attacker.

### Likelihood Explanation
The attack requires: (a) mempool visibility of a pending large forfeiting `getReward`/`queueMGP` call, (b) attacker capital sufficient to temporarily lock a large amount of MGP (this capital is not permanently lost — only illiquid for the normal unlock cooldown, and can be repeated for every future large forfeiture event), and (c) same-block/adjacent-block transaction ordering (miner priority fee or same-block bundling). No privileged role is needed — `lockFor` and `getReward`/`getRewards` (via `MasterMagpie`) are open to any account. This is realistically repeatable whenever a sizeable cooling-down position claims rewards.

### Recommendation
Time-weight reward distribution instead of using instantaneous stake at injection time — e.g., checkpoint stake balances with a minimum staking duration before eligibility for a given reward epoch, stream forfeited rewards linearly over a vesting window (similar to Synthetix-style `rewardRate`/`periodFinish` streaming) rather than instantly bumping `rewardPerTokenStored`, or snapshot `totalStaked()`/eligible balances at the start of the block/epoch rather than reading live state at injection time.

### Proof of Concept
Foundry test plan:
1. Deploy `VLMGP`, `MasterMagpie`, `vlMGPBaseRewarder` with MGP as both staking source and (via `queueMGP`) reward token.
2. Set up victim: lock MGP, `startUnlock` a large amount, let it fully unlock cooldown (so `getRewardablePercentWAD` will yield a large forfeit if they later re-lock and unlock again, or use a partial-cooldown getReward scenario per `_calExpireForfeit`), and prepare a pending `getReward`/`queueMGP` call that forfeits a large MGP amount.
3. In the same block/transaction sequence: attacker calls `vlMGP.lockFor(largeAmount, attacker)` first.
4. Then execute victim's forfeiting call, triggering `_queueNewRewardsWithoutTransfer`.
5. Immediately call `getReward(attacker, attacker)` and assert `earned(attacker, MGP)` (or the transferred amount) is non-zero and approximately `largeAmount / totalStaked() * forfeitAmount`, despite attacker having zero prior blocks of accrual — confirming disproportionate capture relative to time staked.
6. Compare against a control run without the front-run lock to show the honest long-term stakers would have received a materially larger share absent the attacker's front-run.

    function _queueNewRewardsWithoutTransfer(uint256 _amountReward, address _rewardToken) internal
    {
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards = rewardInfo.historicalRewards + _amountReward;
        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**vlMGPDecimal) / totalStaked();
        }
        emit ForfeitRewardAdded(_amountReward, _rewardToken);
    }

    function _sendReward(address _rewardToken, address _account, address _receiver) internal {
        uint256 forfeitAmount = _calExpireForfeit(_account, userRewards[_rewardToken][_account]);
        uint256 toSend = userRewards[_rewardToken][_account] - forfeitAmount;


        userRewards[_rewardToken][_account] = 0;
            
        if (toSend > 0) {
            IERC20(_rewardToken).safeTransfer(_receiver, toSend);
            emit RewardPaid(_account, _receiver, toSend, _rewardToken);
        }

        if(forfeitAmount > 0)
            _queueNewRewardsWithoutTransfer(forfeitAmount, _rewardToken);
    }

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalVlmgp = fullyInLock + inCoolDown;
        if (userTotalVlmgp == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalVlmgp;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalVlmgp / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalVlmgp;
                }

            }
        }

        return percent;
    }
