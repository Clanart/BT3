### Title
Unvalidated `Any.type_url` Injected Raw into TextFormat Output Corrupts Message Framing — ([File: src/google/protobuf/text_format.cc])

### Summary
`google.protobuf.Any.type_url` is an ordinary `string` field with no character-set enforcement at binary-parse time. When a message containing an `Any` is later rendered with `TextFormat::PrintToString`/`DebugString` (or the Java/Python/C++ equivalents), the human-readable "expanded Any" syntax embeds `type_url` verbatim inside the `[...]` bracket token that delimits the pseudo-field name, without escaping structural characters (`]`, `{`, `}`, `\n`, `#`, quotes, etc.). [1](#0-0)  This mirrors the laminas-diactoros flaw: an attacker-controlled value that is supposed to be a constrained token (an HTTP header name / here, a URL-shaped `type_url`) is written unescaped into a position where it functions as syntax, not data, allowing an attacker to terminate/extend the enclosing structure and inject illegitimate content into the emitted representation.

### Finding Description
`Any.type_url` is documented as needing to consist "only of alphanumeric characters, percent-encoded escapes, and characters in `/-.~_!$&()*+,;=`" [2](#0-1)  — but this is a documentation-level contract, not an invariant enforced by `ParseFrom`. Any client can send a bounded, well-formed binary Protobuf message that sets `type_url` to an arbitrary byte string, e.g. containing `]`, newlines, quotes, or a fabricated field list.

The printer side treats `type_url` as trusted/pre-validated and writes it unescaped inside the `[...]` "field name" position:
- C++: `TextFormat::Printer::PrintAny` calls `generator->PrintString(type_url)` — using the raw `BaseTextGenerator::PrintString` path (distinct from `FastFieldValuePrinter::PrintString`, which does call `absl::CEscape`) so no escaping occurs. [3](#0-2) 
- Java: `TextFormat.Printer.printAny` does `generator.print(typeUrl);` with zero escaping. [4](#0-3) 
- Python: `_TryPrintAsAnyMessage` writes `'%s[%s]%s '.format(..., message.type_url, ...)`, again with no escaping. [5](#0-4) 

By contrast, the parser side (reading TextFormat *back* into a message) enforces a strict URL-character grammar for the same field — `ConsumeAnyTypeUrlOrFullTypeName` in C++ only accepts characters recognized as `TYPE_URL_CHARS` plus validated identifier segments and percent-escapes [6](#0-5) , and Java/Python parsers similarly restrict to identifier/`/`/`.` tokens [7](#0-6) . This asymmetry — strict validation on parse, none on print — is exactly the "accept-then-serialize-unsafely" pattern from the laminas-diactoros advisory: the value is validated only in the direction that matters for round-tripping through the same library, but not in the direction (binary-parse → text-emit) that an attacker actually controls.

### Impact Explanation
An attacker who controls the bytes of an `Any` submessage in a Protobuf payload accepted by any consuming application (a normal, expected trust boundary — Protobuf itself is not a network service) can set `type_url` to a value such as:
```
type.googleapis.com/x] { injected_field: 1 } 
extra_field: "
```
When that message is subsequently rendered via `TextFormat::DebugString()`/`PrintToString()` for logging, debugging UIs, error messages, or any downstream text-based pipeline, the emitted text is not syntactically well-formed and could be misparsed by anything that consumes that TextFormat output as structured data (log scrapers, TextFormat round-trip via `Merge`, snapshot/diff tooling based on `MessageDifferencer`'s comparison utilities, etc.). This can corrupt message framing, be misinterpreted by a downstream text-format consumer, or (as in the HTTP header-injection analog) let an attacker smuggle attacker-chosen "fields" into what looks like a legitimately-serialized debug/log record. This is a data-integrity/consuming-application-confusion issue rather than memory corruption; there is no RCE or unbounded resource growth implicated.

### Likelihood Explanation
Any application that logs or displays `TextFormat.DebugString()`/`printToString()` output for messages containing attacker-influenced `Any` fields is exposed, and doing so is an extremely common debugging/logging pattern in Protobuf-based services. No privileged access or hostile schema is required — only a normal, bounded, valid Protobuf payload with a crafted `type_url` string, which is fully within the "ordinary client sending bounded binary Protobuf" threat model.

### Recommendation
Apply the same character-set validation used by the TextFormat *parser* (`ConsumeAnyTypeUrlOrFullTypeName` / `_ConsumeAnyTypeUrl` / `mergeAnyFieldValue`'s identifier-based consumption) to the TextFormat *printer* path for `Any.type_url`: either reject/escape type URLs containing characters outside the documented allowed set before writing them into the `[...]` token, or fall back to the generic (non-expanded) `type_url`/`value` field rendering (already used when `type_url` cannot be resolved) whenever `type_url` contains structurally significant characters (`]`, `{`, `}`, newline, quote, `#`).

### Proof of Concept
This is a source-level finding based on reading the printer/parser implementations; I did not have execution access to run it, so treat the following as a minimal reproduction sketch rather than an executed test:
1. Construct any message `M` with a field `optional_any` of type `google.protobuf.Any`.
2. Build the binary payload manually (bypassing the TextFormat parser's validation) so that `Any.type_url = "type.googleapis.com/x] extra_field: 5 #"` and `Any.value` = a validly-encoded serialization of some registered message type `x`.
3. Feed this binary payload through `M::ParseFromString` (this succeeds — no character-set check exists on `type_url` at binary decode time).
4. Call `TextFormat::Printer().PrintToString(M, &out)` (or Java `TextFormat.printer().printToString(m)`, or Python `text_format.MessageToString(m)`), with a `TypeRegistry`/descriptor pool that resolves the type of `x`.
5. Observe that `out` contains `[type.googleapis.com/x] extra_field: 5 #] { ... }` — an ill-formed/injected TextFormat fragment — because `type_url` was written into the `[...]` token verbatim, contradicting the strict grammar the same library enforces on the parse side [8](#0-7) .

  bool ConsumeAnyTypeUrlOrFullTypeName(std::string& full_type_name,
                                       std::string& url_prefix) {
    // Collect all characters between [ and ] using the URL chars mode of
    // the tokenizer. The mode switch must happen first so that it is active
    // when we advance the tokenizer to the token following the "[" in the
    // consume call.
    tokenizer_.set_report_url_chars(true);
    Consume("[");

    std::string text;
    std::string url_chars;
    while (TryConsumeUrlChars(url_chars)) {
      text.append(url_chars);
    }

    // The mode switch must happen first so that it is active when we advance
    // the tokenizer to the token following the "]" in the consume call.
    tokenizer_.set_report_url_chars(false);
    DO(ConsumeBeforeWhitespace("]"));

    size_t last_slash_pos = text.find_last_of('/');

    if (last_slash_pos == std::string::npos) {
      // No slash found, this must be a type name.
      url_prefix = "";
      full_type_name = text;  // validated below
    } else {
      // Found a slash, this must be a type URL.
      url_prefix = text.substr(0, last_slash_pos + 1);
      full_type_name = text.substr(last_slash_pos + 1);  // validated below

      // Validate prefix
      if (url_prefix == "/") {
        ReportError("Type URL prefix is empty");
        return false;
      }

      if (url_prefix[0] == '/') {
        ReportError("Type URL starts with \"/\"");
        return false;
      }

      // Validate URL percent encodings in prefix: Every '%' needs to be
      // followed by two hex characters.
      for (size_t i = 0; i < url_prefix.size(); ++i) {
        static constexpr absl::CharSet kHexDigits =
            absl::CharSet::AsciiHexDigits();
        if (url_prefix[i] == '%' && (i + 2 >= url_prefix.size() ||
                                     !kHexDigits.contains(url_prefix[i + 1]) ||
                                     !kHexDigits.contains(url_prefix[i + 2]))) {
          ReportError(absl::StrFormat("Invalid percent encode, got: \"%s\"",
                                      url_prefix.substr(i, 3)));
          return false;
        }
      }
    }

    // Validate type name: Must be non-empty and consist of valid identifiers
    // separated by '.'.
    for (absl::string_view identifier : absl::StrSplit(full_type_name, '.')) {
      if (!tokenizer_.IsIdentifier(identifier)) {
        ReportError(absl::StrFormat(
            "Invalid identifier in type name, got: \"%s\"", identifier));
        return false;
      }
    }
