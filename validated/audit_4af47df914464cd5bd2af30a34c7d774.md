### Title
Ed448 point deserialization accepts non-torsion-free points because `is_torsion_free` always returns true - (crypto/ed448/src/point.rs)

### Summary
`Point::is_torsion_free` in `crypto/ed448/src/point.rs` is implemented as `((*self * (Scalar::ZERO - Scalar::ONE)) + self).is_identity()`. `Scalar::ZERO - Scalar::ONE` is `-1`, so the expression computes `-P + P`, which is the identity for *every* point. The torsion check is therefore vacuous, and `Point::from_bytes` (the `GroupEncoding` implementation reached by `Ciphersuite::read_G` / `Curve::read_G`) accepts attacker-supplied Ed448 points carrying a small-order (cofactor-4) torsion component, despite the code clearly intending to reject them (`not_negative_zero & point.is_torsion_free()`). [1](#0-0) 

### Finding Description
Ed448 has cofactor 4, so untrusted encodings can decompress to points with a nontrivial torsion component. The decode path in `Point::from_bytes` gates acceptance on `point.is_torsion_free()`, but that function multiplies the point by `-1` and adds the point back, yielding the identity unconditionally. The result is that the `CtOption` validity bit is determined solely by `not_negative_zero`; torsion is never checked. Any in-scope consumer that deserializes untrusted Ed448 points — `Ed448::read_G` in `crypto/frost/src/curve/mod.rs` (which only additionally rejects identity), `Commitments::read`/`read_preprocess`/`read_share` in FROST signing, `ThresholdKeys::read`, `SchnorrSignature::read`, `DLEqProof::read` — will accept points outside the prime-order subgroup.

### Impact Explanation
Subgroup-confinement attacks become possible against Ed448 operations. Concretely, a counterparty can submit preprocess commitments or verification shares with a torsion component; scalar multiplication then leaks `secret mod 4` information and pollutes aggregated commitments/`R` values, or a malicious signature/`R`/`A` with a torsion component can shift verification results by a low-order offset. This breaks the prime-order-group invariant the rest of the in-scope crypto (FROST binding-factor math, Schnorr verification, batch verification) relies on, enabling forged/altered acceptance of signature shares and potential partial key-share leakage — the same class of "attacker-controlled object accepted by deserialization" as the reference advisory.

### Likelihood Explanation
Any unprivileged peer who can send a preprocess, signature share, key material, or signature byte stream to an Ed448-using signer/verifier can craft a valid compressed encoding of a torsion-bearing point (the decompressor itself accepts it; only the vacuous check was meant to stop it). Exploitation requires only submitting malformed-but-canonical encodings, so it is reachable with public inputs.

### Recommendation
Implement a real torsion check for Ed448: multiply the candidate point by the cofactor (4) and require `is_identity()` on the result, e.g. `(self.double().double()).is_identity()`, or multiply by the prime-order `l` and check identity. Add a regression test that an encoding of `P + T` (with `T` a non-identity torsion point) is rejected by `from_bytes`/`Ed448::read_G`.

### Proof of Concept
```rust
// crypto/ed448/src/point.rs
fn is_torsion_free(&self) -> Choice {
  // Scalar::ZERO - Scalar::ONE == -1 (mod l)
  // (-1)*P + P == identity for ALL P, including torsion-bearing points
  ((*self * (Scalar::ZERO - Scalar::ONE)) + self).is_identity()
}
```
For any valid compressed encoding `E` of `Q = P + T` where `T` is a 2- or 4-torsion point, `Ed448::read_G(&mut E.as_ref())` returns `Ok(Q)`; the torsion component survives into `BoundCommitments`, `R`, and share-verification equations that assume prime-order operands.

impl GroupEncoding for Point {
  type Repr = <FieldElement as PrimeField>::Repr;

  fn from_bytes(bytes: &Self::Repr) -> CtOption<Self> {
    // Extract and clear the sign bit
    let sign = Choice::from(bytes[56] >> 7);
    let mut bytes = *bytes;
    let mut_ref: &mut [u8] = bytes.as_mut();
    mut_ref[56] &= !(1 << 7);

    // Parse y, recover x
    FieldElement::from_repr(bytes).and_then(|y| {
      recover_x(y).and_then(|mut x| {
        x.conditional_negate(x.is_odd().ct_eq(&!sign));
        let not_negative_zero = !(x.is_zero() & sign);
        let point = Point { x, y, z: FieldElement::ONE };
        CtOption::new(point, not_negative_zero & point.is_torsion_free())
      })
    })
