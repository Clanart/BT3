### Title
`_execute()` sweeps the CallDispatcher's raw token balance instead of the delta produced by the order's own call, letting stale/foreign balances be misappropriated as protocol dust — (File: `evm/src/apps/intentsv2/IntentsBase.sol`)

### Summary
The core flaw in the referenced report is that a post-action success/amount check reads absolute on-chain state (`ownerOf(tokenId) == address(this)`, balance delta) without first confirming that state wasn't *already true before the action*, letting an unrelated asset satisfy the check. The same class of bug appears in `IntentsBase._execute()`: after dispatching `order.output.call` through the shared `CallDispatcher`, it sweeps *whatever balance currently sits* on the dispatcher (`IERC20(token).balanceOf(dispatcher)` / `dispatcher.balance`) and treats 100% of it as this order's dust, with no `balanceBefore` snapshot.

### Finding Description
`_execute()` in `evm/src/apps/intentsv2/IntentsBase.sol` (lines 438-485) is invoked from both `_fillSameChain` and `_fillCrossChain` whenever an order carries output calldata: [1](#0-0) 

It calls `ICallDispatcher(dispatcher).dispatch(order.output.call)` and then reads `dispatcher.balance` / `IERC20(token).balanceOf(dispatcher)` directly, sweeping the *entire* observed balance as `DustCollected`, with zero attempt to snapshot the dispatcher's balance immediately before the call and subtract it (a delta check).

This is provably the wrong pattern in this codebase, because the sibling code path in `placeOrder` (same shared `CallDispatcher`, same contract family) does it correctly by recording `balancesBefore[i]` before sweeping and computing `received = balanceAfter - balancesBefore[i]`: [2](#0-1) 

`CallDispatcher` (`evm/src/utils/CallDispatcher.sol`) is a single, shared, stateless-execution contract used by *every* order's predispatch and postdispatch calldata across the whole gateway — it holds no per-order accounting and any token left on it persists until the next sweep: [3](#0-2) 

Because `_execute()` never snapshots the dispatcher's balance before invoking `order.output.call`, any token balance already resident on the dispatcher at that moment — left over from a different order's predispatch/postdispatch leg that failed to fully clear (e.g. a non-reverting `IERC20.transfer` that silently returns `false`, fee-on-transfer/rebasing tokens, or a swap that leaves rounding dust from a *different* user's order in the same token) — is swept in full and attributed as this order's `DustCollected`, exactly mirroring the NFT report's "does not check whether the asset was already present before crediting the action to this operation" flaw.

### Impact Explanation
Funds belonging to a different order/user that transiently sit on the shared `CallDispatcher` are misappropriated into the gateway's dust pool under an unrelated order's fill, rather than being returned to their rightful owner or left for the actual order that produced them. This is a loss-of-funds condition for whichever party's balance was already on the dispatcher, since it becomes indistinguishable from newly-produced surplus and is later swept by governance's `SweepDust` path with no way to reconcile which order it truly belonged to. It also breaks the accounting invariant that `DustCollected` for order X should equal only the residual produced by executing order X's own calldata — a wrong-amount/wrong-attribution outcome, the same "logic attack via missing pre-state check" pattern explicitly targeted by the bounty scope.

### Likelihood Explanation
This is reachable by any ordinary filler through the public, unprivileged `fillOrder` path whenever an order includes output calldata (`order.output.call.length > 0`), which is a normal, supported feature (documented DeFi-routing use case). No relayer, prover, or governance compromise is required — only that the shared `CallDispatcher` retain a nonzero balance of the relevant token from a prior operation, which can occur through ordinary non-atomic leftovers (fee-on-transfer tokens, non-reverting failed `transfer` calls using the raw `.call()` pattern seen elsewhere in this codebase, or partial swap dust from any concurrently in-flight order using the same token and same shared dispatcher).

### Recommendation
In `_execute()`, snapshot `dispatcher.balance` / `IERC20(token).balanceOf(dispatcher)` immediately before calling `ICallDispatcher(dispatcher).dispatch(order.output.call)`, then sweep and emit `DustCollected` only for the delta (`balanceAfter - balanceBefore`), matching the pattern already used in `placeOrder`'s predispatch handling. Any pre-existing balance found on the dispatcher before the call should not be attributed to the current order.

### Proof of Concept
Conceptual sequence (exact reproduction requires a testnet/foundry harness which is outside static analysis, but the logical PoC is direct from the code):
1. Order A is filled with output calldata that swaps through `CallDispatcher`; due to a fee-on-transfer output token or a `transfer()` call that returns `false` without reverting, 5 tokens remain stranded on `CallDispatcher` after Order A's `_execute()` sweep pass completes (the pass only sees a snapshot at that moment, but a subsequent incoming transfer to dispatcher — e.g. an async multi-hop swap leg — deposits more after the sweep loop already ran, or a second output asset in the same order's loop reads the pre-existing balance of an already-swept token from a still-executing external call).
2. Order B (any subsequent order using the same output token and the shared dispatcher) is filled with its own output calldata. Order B's `_execute()` reads `IERC20(token).balanceOf(dispatcher)`, which now includes the 5 tokens stranded from Order A plus Order B's own genuine residual, and sweeps the whole amount as `DustCollected` under Order B's fill.
3. Order A's rightful stranded balance is now folded into Order B's dust event and gateway-held dust, with no on-chain trail tying it back to Order A, and no mechanism to return it to Order A's beneficiary or protocol fee ledger correctly. [4](#0-3)

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
    }

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
