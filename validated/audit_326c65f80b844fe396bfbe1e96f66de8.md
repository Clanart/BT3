### Title
Unvalidated Attacker-Controlled Length Prefix Causes Out-of-Bounds Read in `is_atom_canonical()` During Mempool Admission - (File: chia/full_node/mempool_manager.py)

### Summary
`is_atom_canonical()` and `is_clvm_canonical()` parse the CLVM atom length-prefix bytes of a spend bundle's `puzzle_reveal` and `solution` without ever validating that the decoded prefix length or resulting `atom_len` stays within the bounds of the buffer before indexing into it, mirroring the CVE-2021-32489 pattern of trusting an embedded length field from untrusted input without validating it against the actual buffer size. [1](#0-0) 

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads `mask`/`prefix_len` from the first control byte, then loops `prefix_len` times incrementing `offset` and indexing `clvm_buffer[offset]` directly, with no check that `offset` remains `< len(clvm_buffer)`. [2](#0-1) 
`is_clvm_canonical()` then advances its own `offset` by the returned `atom_len` (which is attacker-controlled and can be arbitrarily large, e.g. up to 2^48) and re-enters the loop, indexing `clvm_buffer[offset]` again with no bounds check. [3](#0-2) 
This is invoked directly on every coin spend's `puzzle_reveal` and `solution` bytes during mempool admission in `validate_spend_bundle()`, which is reachable by any unprivileged spend-bundle submitter (`push_tx`/gossip path): [4](#0-3) 
A crafted puzzle_reveal/solution whose length-prefix byte(s) encode an atom size or prefix that exceeds the actual serialized buffer causes `clvm_buffer[offset]` to be indexed past the end of the bytes object, raising an unhandled `IndexError` inside the CLVM-canonical check — the Python analogue of the C-level "trusted embedded length field causes read past allocated buffer" defect in the CVE. Unlike all the other length-prefixed parsers in this codebase (`full_block_utils.py`'s `skip_bytes`/`skip_list`, `streamable.py`'s `parse_bytes`/`parse_list`), which explicitly compare the decoded length against remaining buffer size before consuming it, `is_atom_canonical`/`is_clvm_canonical` perform no such comparison. [5](#0-4) 

### Impact Explanation
Because Python bytes objects are memory-safe, the overrun does not cause memory corruption/segfault as in the original C/OpenSSL CVE; instead it raises an uncaught `IndexError` inside the mempool admission path (`validate_spend_bundle`, called from `add_spend_bundle`). Whether this propagates into a crash of the calling coroutine/task or is silently swallowed by a broader exception handler in `full_node.py`'s transaction-processing pipeline could not be conclusively confirmed within the available tool budget — that call chain (`full_node.py`'s handlers into `add_spend_bundle`) was only partially inspected before the iteration limit was reached. At minimum this is a spend-bundle-triggered exception in a core validation function that every submitted spend bundle passes through, and if uncaught by the caller it halts processing of that transaction (and potentially the enclosing task) rather than cleanly rejecting the malformed input with a normal validation error.

### Likelihood Explanation
High reachability: any wallet user, offer counterparty, or unauthenticated peer can submit a spend bundle with a hand-crafted `puzzle_reveal`/`solution` byte sequence whose CLVM atom length-prefix byte encodes a length exceeding the real buffer size. No signature or special privilege is required to reach `is_clvm_canonical()`, since it runs unconditionally on every coin spend during `validate_spend_bundle()`. [6](#0-5) 

### Recommendation
Add explicit bounds checks in both `is_atom_canonical()` and `is_clvm_canonical()`, analogous to the checks already used in `full_block_utils.py`/`streamable.py`: before indexing `clvm_buffer[offset]` inside the prefix-reading loop, verify `offset < len(clvm_buffer)`; and after computing `atom_len`, verify `1 + prefix_len + atom_len <= len(clvm_buffer) - start_offset` before returning it, returning a controlled "not canonical"/error result instead of letting an `IndexError` escape.

### Proof of Concept
Construct a `CoinSpend` whose `solution` (or `puzzle_reveal`) begins with a byte such as `0xC0` (5+8 bit length-prefix category) followed by a length byte encoding a size, e.g. `0xC0 0xFF`, but provide fewer total trailing bytes than `atom_len` requires (e.g. total buffer length 2). Submitting this via a `SpendBundle` to `add_spend_bundle()`/`validate_spend_bundle()` drives execution into `is_clvm_canonical(bytes(coin_spend.solution))` → `is_atom_canonical()`, where the loop over `prefix_len` or the subsequent `offset += atom_len` advance attempts to index `clvm_buffer[offset]` beyond `len(clvm_buffer)`, raising `IndexError` instead of returning a normal validation failure. def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value


def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)

def skip_list(buf: memoryview, skip_item: Callable[[memoryview], memoryview]) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"list count prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"list count {n} exceeds remaining buffer {len(buf)}")
    for _ in range(n):
        buf = skip_item(buf)
    return buf


def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
