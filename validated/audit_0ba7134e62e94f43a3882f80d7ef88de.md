Based on my investigation, I found an interesting analog: the gasless module's `checkBalanceForSwap` reads `g.swapRouter` from a cache (`g.gaslessInfoMu`) that is only updated by `updateAddresses()`, a function invoked at specific block-processing points, rather than being recomputed live from the current state for each check.### Title
Gasless module's cached `swapRouter`/`allowedTokens` snapshot goes stale for one block after registry update, allowing an invalid `SwapForGas` transaction to pass admission checks - (File: kaiax/gasless/impl/getter.go)

### Summary
This is a bug-class analog of the SwapUtils.sol finding: a value that should reflect the current authoritative state (a Solidity contract's storage / a real-time computed parameter) is instead cached and only refreshed on specific update triggers, so between the actual state change and the trigger firing, module logic operates on stale data.

### Finding Description
The gasless module caches the `GaslessSwapRouter` address and the set of `allowedTokens` in memory (`g.swapRouter`, `g.allowedTokens`), protected by `gaslessInfoMu`. This cache is populated once at `Init()` and is refreshed only inside `updateAddresses()`, which is invoked exclusively from `PostInsertBlock()` after a block has already been fully inserted: [1](#0-0) [2](#0-1) 

All admission-time checks for gasless transactions — `IsApproveTx`, `IsSwapTx`, and `checkBalanceForSwap` — read this cached snapshot rather than recomputing it from the current/pending state at check time: [3](#0-2) [4](#0-3) 

The real authoritative source is the `GaslessSwapRouter`/Registry system contract, queried live via `getGaslessInfo()` -> `MultiCallGaslessInfo` on demand: [5](#0-4) 

Because the cache is only refreshed at `PostInsertBlock` (i.e., once per block, after the block has been committed), any change to the router address or allowed-token list that occurs within a block (e.g., an `addToken`/`removeToken`/router-change call on the `GaslessSwapRouter`, or a Registry re-registration effective at a specific target block) will not be reflected in the gasless module's admission logic until the *next* `PostInsertBlock()` call completes — mirroring the SwapUtils.sol pattern where `tokenPrecisionMultipliers` lagged behind the actual `targetPrice` ramp until an explicit `rampTargetPrice()`/`stopRampTargetPrice()` call.

### Impact Explanation
If the cache is stale (e.g., a token was just removed from the allow-list, or the router address changed) the `IsSwapTx`/`IsApproveTx`/`checkBalanceForSwap` admission checks used to decide whether to countersign a `LendTx` (the CN/proposer lending KAIA gas to the sender in exchange for token repayment via `GetLendTxGenerator`) can accept transactions that should have been rejected under the up-to-date on-chain configuration, or reject transactions that should be valid. This can lead to the lender countersigning fee-delegation-like `LendTx` bundles against a router/token set that is no longer authoritative, exposing the CN's advanced KAIA to a swap under different bytecode/logic than expected, or a sender bypassing token allow-listing for one block window. This affects the fee-delegation counterparty (CN/lender) and gasless swap flow, but the severity is bounded to a single-block staleness window since it self-heals every block.

### Likelihood Explanation
Low-to-moderate likelihood: exploitation requires precise timing — the attacker (an unprivileged transaction sender) must submit an `ApproveTx`/`SwapTx` pair within the exact block(s) where the on-chain router/token configuration has already changed but `PostInsertBlock` for that block has not yet run (or during pending-block construction using a stale `g.swapRouter`/`g.allowedTokens` snapshot). This is a narrow race window dependent on block timing and requires cooperation of the module's own update cadence, so it is harder to reliably trigger compared to a purely stateless computation bug.

### Recommendation
Recompute `swapRouter` and `allowedTokens` from current chain state at the time of each admission check (`IsApproveTx`, `IsSwapTx`, `checkBalanceForSwap`) rather than relying solely on the `PostInsertBlock`-refreshed cache, or at minimum refresh the cache immediately before evaluating a pending transaction bundle (e.g., in `PreAddTx`/`IsModuleTx`) so that the snapshot used for validation is guaranteed to correspond to the state against which the transaction will actually execute.

### Proof of Concept
1. Deploy `GaslessSwapRouter` with token `T1` allowed and register it via the Registry as done in `tests/gasless_test.go`.
2. Wait for the gasless module's `g.swapRouter`/`g.allowedTokens` cache to be populated via `PostInsertBlock` at block `N`.
3. In block `N+1`, submit a transaction (from any account) calling `GaslessSwapRouter.removeToken(T1)` (or re-register a new `GaslessSwapRouter` via the Registry to take effect at block `N+1`), which is included in the block.
4. Before `PostInsertBlock` for block `N+1` completes and refreshes the cache (e.g., concurrently building the next pending block / txpool admission for block `N+2`), submit an `ApproveTx`+`SwapTx` pair referencing the now-removed token `T1` / stale router address.
5. Because `IsApproveTx`/`IsSwapTx`/`checkBalanceForSwap` consult the stale `g.swapRouter`/`g.allowedTokens` snapshot (as shown in `kaiax/gasless/impl/getter.go:79-103` and `kaiax/gasless/impl/tx_pool.go:107-142`), the transaction pair is incorrectly treated as a valid gasless bundle and a `LendTx` is generated against outdated router/token configuration — confirmed indirectly by the existing `TestPostInsertBlock` test in `kaiax/gasless/impl/execution_test.go:38-159`, which demonstrates the cache only updates on explicit `PostInsertBlock` calls and not in real time as the underlying contract state changes.

func (g *GaslessModule) updateAddresses(header *types.Header) error {
	g.gaslessInfoMu.Lock()
	defer g.gaslessInfoMu.Unlock()

	swapRouter, tokens, err := getGaslessInfo(g.Chain, header)
	// proceed even if there is something wrong with multicall contract
	if err != nil {
		g.swapRouter = common.Address{}
		g.allowedTokens = map[common.Address]bool{}
		logger.Warn("there is something wrong with multicall contract", "err", err.Error())
		return nil
	}

	g.swapRouter = swapRouter

	g.allowedTokens = map[common.Address]bool{}
	for _, addr := range tokens {
		// all tokens are allowed if nil
		if g.GaslessConfig.AllowedTokens == nil {
			g.allowedTokens[addr] = true
		}
		for _, allowed := range g.GaslessConfig.AllowedTokens {
			if addr == allowed {
				g.allowedTokens[addr] = true
			}
		}
	}

	return nil
}

func getGaslessInfo(bc backends.BlockChainForCaller, header *types.Header) (common.Address, []common.Address, error) {
	statedb, err := bc.StateAt(header.Root)
	if err != nil {
		return common.Address{}, nil, err
	}

	// If Registry is not installed, do not query GaslessSwapRouter contract.
	if statedb.GetCode(system.RegistryAddr) == nil || bc.Config().IsRandaoForkBlockParent(header.Number) {
		return common.Address{}, nil, nil
	}

	caller, err := system.NewMultiCallContractCaller(statedb, bc, header)
	if err != nil {
		return common.Address{}, nil, err
	}

	opts := &bind.CallOpts{BlockNumber: header.Number}
	info, err := caller.MultiCallGaslessInfo(opts)

	return info.Gsr, info.Tokens, err
}
