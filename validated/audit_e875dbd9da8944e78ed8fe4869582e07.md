### Title
Merging a Crafted Repeated Field Near INT_MAX Elements Aborts the Process via `ABSL_LOG(FATAL)` Instead of Returning a Parse Error - (File: `src/google/protobuf/port.cc`)

### Summary
The Vyper report shows a compiler that, instead of surfacing a handled, catchable compilation error when an expression's size calculation exceeds representable range, calls an internal panic (`CompilerPanic: out of range`) that crashes the tool. The transferable invariant is: *arithmetic performed on attacker/user-controlled sizes during processing of a value must fail gracefully (return an error) rather than abort the whole process*. In Protocol Buffers' C++ implementation, the analogous invariant is violated in `RepeatedField`/`RepeatedPtrField` growth and merge paths: when the *new* element count computed from an incoming (attacker-supplied) parse operation would overflow `int`, the library does not return a parse failure — it calls `internal::CheckedAdd`, which on overflow invokes `HandleAddOverflow()` → `ABSL_LOG(FATAL)`, terminating the process, exactly analogous to an uncatchable panic replacing a proper error return. [1](#0-0) 

### Finding Description
`RepeatedField<Element>::MergeFrom` computes the merged size using `internal::CheckedAdd(old_size, other_size)` before reserving capacity: [2](#0-1) 

Likewise, `AddForwardIterator` computes `new_size` the same way before growing: [3](#0-2) 

`CheckedAdd` is declared in `port.h`, and its overflow handler is defined in `port.cc`, where an overflow unconditionally triggers `ABSL_LOG(FATAL)`, which aborts the process rather than returning any error code to the caller: [1](#0-0) 

This is directly reachable from parsing: a message containing a repeated field can be merged into an in-memory message object that already holds close to `INT_MAX` elements (e.g., via repeated `ParseFrom`/`MergeFrom` calls, or a single message with `repeated_field.size()` already near `INT_MAX`, then receiving a subsequent binary payload that adds one more element to that field). The existing regression tests exercise exactly this scenario and assert the current (crashing) behavior with `EXPECT_DEATH`, confirming the invariant break is a known, intentional-but-unrecoverable design choice, not a corner case that is caught and converted into `InvalidProtocolBufferException`/`ParseFromString == false`: [4](#0-3) [5](#0-4) 

Notably, there is a disabled test with an explicit "TODO: Re-enable once parsing overflow is fixed" comment, showing the protobuf team is aware this overflow path during a normal `MergeFromString` parse is broken and currently disabled rather than fixed: [6](#0-5) 

This contrasts with the length/limit checks that *are* done correctly elsewhere in the wire-format parser — e.g., `ReadSizeFallback` in `parse_context.cc` explicitly rejects sizes that would overflow the limit arithmetic and returns `nullptr` (a graceful parse failure) instead of crashing: [7](#0-6) 

The Reserve/Grow size-calculation path (`CalculateReserveSize`) similarly clamps to `INT_MAX` gracefully when *capacity* growth alone would overflow: [8](#0-7) 

but the *pre-check* addition (`old_size + other_size` / `old_size + distance`) that happens **before** `Grow`/`Reserve` is invoked uses `CheckedAdd`, which has no graceful failure mode — it always aborts on overflow. This is the missing check: the sum computed for `new_size` should be validated and turned into a recoverable parse error (as is done for length-delimited field sizes in `parse_context.cc`), not a `LOG(FATAL)` abort.

### Impact Explanation
An attacker-controlled client sending a normal, bounded-size binary Protobuf payload cannot by itself force the field to already be near `INT_MAX` — the practical attack scenario requires the consuming application to accumulate many parses into a single message/field over time (e.g., `MergeFrom` used to append across repeated RPCs), a realistic pattern for streaming/append-style protobuf consumers. When the field's existing size reaches the threshold where the next incoming element causes `old_size + 1` (or `old_size + other_size`) to overflow `int`, feeding one more crafted message causes an immediate process abort (`ABSL_LOG(FATAL)`/abort) rather than a catchable parse failure. This is a Denial-of-Service against the consuming application: it is a crash of the entire process (not a memory-safety violation, not RCE), triggered by data the parser is expected to reject or handle gracefully like any other malformed/oversized input. Severity is Medium: it requires a specific (though realistic) precondition of extremely large accumulated repeated-field state, and it is a crash, not corruption.

### Likelihood Explanation
The precondition — a repeated field growing to within one element of `INT_MAX` — is unusual in typical single-message parses (bounded by the 2GB message-size convention), but it is directly reachable through the documented, intended `MergeFrom`/`AddEntriesFrom` code paths that applications use for streaming aggregation of repeated fields across multiple parsed messages, and the maintainers' own disabled test with a "TODO: fix" comment demonstrates this is a recognized, currently-unaddressed gap in this exact function on this exact attacker-reachable path, not a hypothetical.

### Recommendation
Replace the `CheckedAdd`-with-fatal-abort pattern in `RepeatedField<Element>::MergeFrom` and `AddForwardIterator`/`AddInputIterator` growth-size calculations with an overflow check that returns a recoverable parse failure (mirroring the treatment of `ReadSizeFallback` in `parse_context.cc`, which rejects overflow-prone sizes by returning `nullptr`/failure instead of aborting). Concretely, `WireFormatLite`/parsing entry points that call into `RepeatedField::MergeFrom` or `AddEntriesFrom` on untrusted input should detect an impending overflow before calling the fatal-checked arithmetic, and propagate a standard `ParseFromString == false` / `InvalidProtocolBufferException` instead of allowing `HandleAddOverflow` to reach `ABSL_LOG(FATAL)`.

### Proof of Concept
The existing (currently disabled) regression test in the repo already documents a minimal, near-production reproduction of this class of bug via ordinary `MergeFromString` on binary wire data: [6](#0-5) 
and the currently-enabled `EXPECT_DEATH` tests demonstrate the exact abort message and code path triggered by a normal `MergeFrom`/`Add` call once size arithmetic overflows: [9](#0-8) [5](#0-4)

template <typename Element>
template <typename ArenaProvider, typename Iter>
inline void RepeatedField<Element>::AddForwardIterator(
    ArenaProvider arena_provider, Iter begin, Iter end) {
  ABSL_DCHECK_EQ(ResolveArena(arena_provider), GetSerialArena());

  bool is_soo = this->is_soo();
  const int old_size = size();
  int capacity = Capacity(is_soo);
  Element* elem = unsafe_elements(is_soo);
  // Check for signed overflow.
  const size_t distance = std::distance(begin, end);
  ABSL_CHECK_LE(distance, static_cast<size_t>(std::numeric_limits<int>::max()))
      << "Input too large";
  // Check again for signed overflow.
  const int new_size =
      internal::CheckedAdd(old_size, static_cast<int>(distance));
  if (ABSL_PREDICT_FALSE(new_size > capacity)) {
    Grow(arena_provider, is_soo, old_size, new_size);
    is_soo = false;
    elem = unsafe_elements(is_soo);
    capacity = Capacity(is_soo);
  }
  UninitializedCopy(begin, end, elem + ExchangeCurrentSize(new_size));

template <typename Element>
inline void RepeatedField<Element>::MergeFrom(const RepeatedField& other) {
  if (ABSL_PREDICT_FALSE(&other == this)) {
    PROTOBUF_NO_MERGE internal::LogSelfMergeAndAbort();
  }
  const bool other_is_soo = other.is_soo();
  if (auto other_size = other.size()) {
    const int old_size = size();
    const int new_size = internal::CheckedAdd(old_size, other_size);
    Reserve(new_size);
    const bool is_soo = this->is_soo();
    Element* dst = elements(is_soo) + ExchangeCurrentSize(new_size);
    UninitializedCopyN(other.elements(other_is_soo), other_size, dst);
  }
}

template <typename T, int kHeapRepHeaderSize>
inline int CalculateReserveSize(int capacity, int new_size) {
  constexpr int lower_limit =
      RepeatedFieldLowerClampLimit<T, kHeapRepHeaderSize>();
  if (new_size < lower_limit) {
    // Clamp to smallest allowed size.
    return lower_limit;
  }
  constexpr int kMaxSizeBeforeClamp =
      (std::numeric_limits<int>::max() - kHeapRepHeaderSize) / 2;
  if (ABSL_PREDICT_FALSE(capacity > kMaxSizeBeforeClamp)) {
    return std::numeric_limits<int>::max();
  }
  constexpr int kSooCapacityElements = SooCapacityElements<T>();
  if (kSooCapacityElements > 0 && kSooCapacityElements < lower_limit) {
    // In this case, we need to set capacity to 0 here to ensure power-of-two
    // sized allocations.
    if (capacity < lower_limit) capacity = 0;
  } else {
    ABSL_DCHECK(capacity == 0 || capacity >= lower_limit)
        << capacity << " " << lower_limit;
  }
  // We want to double the number of bytes, not the number of elements, to try
  // to stay within power-of-two allocations.
  // The allocation has kHeapRepHeaderSize + sizeof(T) * capacity.
  int doubled_size = 2 * capacity + kHeapRepHeaderSize / sizeof(T);
  return std::max(doubled_size, new_size);
}

std::pair<const char*, int32_t> ReadSizeFallback(const char* p, uint32_t res) {
  for (std::uint32_t i = 1; i < 4; i++) {
    uint32_t byte = static_cast<uint8_t>(p[i]);
    res += (byte - 1) << (7 * i);
    if (ABSL_PREDICT_TRUE(byte < 128)) {
      return {p + i + 1, res};
    }
  }
  std::uint32_t byte = static_cast<uint8_t>(p[4]);
  if (ABSL_PREDICT_FALSE(byte >= 8)) return {nullptr, 0};  // size >= 2gb
  res += (byte - 1) << 28;
  // Protect against sign integer overflow in PushLimit. Limits are relative
  // to buffer ends and ptr could potential be kSlopBytes beyond a buffer end.
  // To protect against overflow we reject limits absurdly close to INT_MAX.
  if (ABSL_PREDICT_FALSE(res > INT_MAX - ParseContext::kSlopBytes)) {
    return {nullptr, 0};
  }
  return {p + 5, res};
}
