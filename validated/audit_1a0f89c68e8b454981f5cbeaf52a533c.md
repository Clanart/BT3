### Title
Sandwich-manipulable spot-price swap in `_bullMGP` lets attacker extract excess MGP funded by protocol BUSD - (File: wombat/ArbWomUp2.sol)

### Summary
`incentiveDeposit(_amount, _minMGPRec, true)` triggers `_bullMGP`, which swaps protocol-owned BUSD for MGP directly through `ROUTER.swapExactTokensForTokens` using the pool's current spot price, with no TWAP/oracle check and a caller-supplied `_minMGPRec` that only protects the caller, not the protocol. An attacker can manipulate the Pancake BUSD/MGP pool price within the same block (via a flash-loan-funded pre-trade) so that the protocol's fixed BUSD `rewardToSend` buys an inflated amount of MGP, then reverse the manipulation trade afterward to restore price and recoup most of their capital, netting a profit in locked vlMGP funded by the protocol's BUSD.

### Finding Description
`incentiveDeposit` computes `rewardToSend` from `getRewardAmount` and, when `_bullMode=true`, calls: [1](#0-0) 

`_bullMGP` performs the conversion: [2](#0-1) 

The amount of MGP received (`amounts[1]`) is determined entirely by the instantaneous reserves of the router pool at execution time — there is no TWAP, no oracle reference price, and no check that the received MGP corresponds to a "fair" BUSD valuation. The only bound is `_minRec` (`_minMGPRec`), which is supplied by the caller (`msg.sender`) and can trivially be set to `0` or a very low value, meaning it provides no floor protection for the protocol; it only lets the attacker avoid reverting due to their own manipulation.

Exploit flow:
1. Attacker (optionally using a flash loan) sells MGP into the BUSD/MGP pool, depressing MGP's price relative to BUSD in that pool.
2. In the same block, attacker calls `incentiveDeposit(_amount, _minMGPRec=0, true)`. The contract's fixed BUSD `rewardToSend` is swapped at the now-depressed MGP price, yielding an inflated `amounts[1]`, which after the `bullBonusRatio` bonus is locked into vlMGP for the attacker via `vlMGP.lockFor(mgpAmountToLcok, _account)`.
3. Attacker reverses the initial trade (buys back MGP with BUSD) to restore the pool price, recovering most of the capital used to manipulate it minus fees/slippage.

`nonReentrant` and `whenNotPaused` do not mitigate this — they guard against reentrancy and pausing, not against spot-price manipulation within a single block. There is no per-transaction cap on how much price deviation is tolerated relative to a trusted reference price.

### Impact Explanation
This is a theft of protocol-held BUSD value: unclaimed reward BUSD intended to back a proportional MGP buyback is converted into a MGP amount inflated beyond its fair BUSD value and permanently locked to the attacker's vlMGP position. This is a direct economic loss to the protocol (BUSD reserve depleted disproportionately to reward entitlement) and corresponds to "theft of unclaimed yield" funded by protocol-held funds.

### Likelihood Explanation
The attack requires only capital to move the BUSD/MGP pool price within one block (feasible via flash loan on BSC, no special permissions needed), and calling a public function (`incentiveDeposit`) that any WOM depositor can invoke since the wom deposit path (`_deposit`) has no access restriction beyond holding WOM tokens. It is repeatable each time `_bullMode=true` bull conversions are enabled and the pool has exploitable liquidity depth relative to the reward size, making it practically exploitable whenever bull-mode payouts are non-trivial.

### Recommendation
Do not rely on the router's instantaneous spot price for converting protocol funds. Enforce a protocol-side minimum-received check derived from a trusted price oracle or TWAP (not attacker-controlled `_minMGPRec`), and/or cap price impact per swap, and/or split large conversions or use a private/atomic-guarded pricing mechanism resistant to single-block manipulation.

### Proof of Concept
Foundry/Hardhat fork test plan:
1. Fork BSC mainnet at a block with the real Pancake BUSD/MGP pool and deploy/point `ArbWomUp2` at it with realistic `busd` balance and `bullBonusRatio` set.
2. Record a "fair" MGP-per-BUSD price from pool reserves before manipulation.
3. Attacker contract flash-loans BUSD (or uses pre-funded MGP) and swaps MGP->BUSD in the pool to depress MGP price.
4. In the same transaction/block, call `incentiveDeposit(_amount, _minMGPRec=0, true)` as the attacker (having deposited enough WOM to trigger `rewardToSend`), capturing `mgpAmountToLcok` locked via `vlMGP.lockFor`.
5. Attacker reverses the manipulation trade (BUSD->MGP) to restore pool price and repay flash loan.
6. Assert: `mgpAmountToLcok` (converted back to BUSD value at the fair pre-manipulation price) exceeds `rewardToSend` (the fair BUSD entitlement) by more than router/pool fee tolerance, demonstrating value extraction beyond fair conversion, and assert attacker's net BUSD spend (after reversing manipulation) is less than the BUSD-equivalent value of MGP locked to their vlMGP position.

    function _bullMGP(uint256 _busdAmount, uint256 _minRec, address _account) internal {
        IERC20(busd).safeApprove(address(ROUTER), _busdAmount);
        
        address[] memory path = new address[](2);
        path[0] = busd;
        path[1] = mgp;
        uint256[] memory amounts = ROUTER.swapExactTokensForTokens(
            _busdAmount,
            _minRec,
            path,
            address(this),
            block.timestamp
        );

        uint256 mgpAmountToLcok = amounts[1] * (DENOMINATOR + bullBonusRatio) / DENOMINATOR; // get bull mode bonus
        IERC20(mgp).approve(address(vlMGP), mgpAmountToLcok);
        vlMGP.lockFor(mgpAmountToLcok, _account);

        emit VLMGPRewarded(_account, _busdAmount, mgpAmountToLcok);
    }
