### Title
Gitignore rule injection via embedded newline in filenames processed by bulk "Ignore file" action - (File: `app/src/lib/git/gitignore.ts`)

### Summary
`appendIgnoreFile` escapes only Git glob special characters (`[`, `]`, `!`, `*`, `#`, `?`) but does not escape or reject newline (`\n`) characters, which are valid in POSIX filenames. When a user selects multiple changed files and invokes "Ignore Files (Add to .gitignore)" from the Changes list context menu, an attacker-controlled filename containing an embedded `\n` is joined together with other paths via `patterns.join('\n')`, silently injecting an extra, attacker-chosen `.gitignore` rule.

### Finding Description
The Changes list bulk-ignore action (`getDefaultContextMenu` in `app/src/ui/changes/filter-changes-list.tsx:730-746`) collects `paths` from user-selected `WorkingDirectoryFileChange` entries and calls `this.props.onIgnoreFile(paths)`. This flows through `sidebar.tsx`'s `onIgnoreFile` (`app/src/ui/changes/sidebar.tsx:269-271`) to `dispatcher.appendIgnoreFile`, and ultimately to `appendIgnoreFile` in `app/src/lib/git/gitignore.ts:86-99`: [1](#0-0) 

Each path is passed through `escapeGitSpecialCharacters`: [2](#0-1) 

This regex (`/[\[\]!\*\#\?]/g`) does not match `\n`. The escaped array is then passed to `appendIgnoreRule`, which joins the array elements with a literal newline: [3](#0-2) 

Because POSIX filesystems permit any byte except `/` and `NUL` in a filename, a repository can legitimately contain a file whose name includes a literal `\n`. If such a file is committed/cloned and appears as an untracked/modified change, and the user selects it (potentially along with other files) and chooses "Ignore Files", the embedded newline is not neutralized. It splits the single filename into two effective `.gitignore` lines: the intended file entry, and an attacker-controlled second line that can be any Git ignore pattern (e.g. `!important-security-file`, or a broad glob), because the attacker fully controls everything after the embedded `\n` character in the filename.

### Impact Explanation
This falls under "silent corruption of what the user commits or pushes": the resulting `.gitignore` contains a rule the user never intended and did not review carefully, which can cause unrelated files to silently stop being tracked by Git going forward, or (via a negation pattern like `!secret`) re-include files that other legitimate ignore rules were suppressing. Since `.gitignore` changes are typically committed and pushed to shared repositories, this can propagate to other collaborators.

### Likelihood Explanation
Requires an attacker to control repository content (a file with an embedded-newline filename), and a victim to actively right-click that file (or a selection including it) and choose "Ignore file(s)". This is a plausible but non-default user interaction; the victim must notice the crafted filename appearing in the Changes list and pick the ignore-file context action rather than another one. Embedded newlines in filenames are unusual and would likely appear visually broken in the UI, which may reduce (but not eliminate) the chance a user selects them without inspection.

### Recommendation
In `escapeGitSpecialCharacters` (or a new sanitation step in `appendIgnoreFile`), reject or escape filenames containing `\n`/`\r` before joining, e.g. throw/skip such entries, or escape the newline itself so it cannot introduce a new line in the resulting `.gitignore` content. Additionally, consider deduplicating and validating the full pattern list in `appendIgnoreRule` before writing.

### Proof of Concept
1. In a test/cloned repository, create a file whose name embeds a literal newline byte, e.g. via Node: `fs.writeFileSync('legit.txt\n!secret.env', 'x')` (valid on POSIX filesystems).
2. Open the repository in GitHub Desktop; the file appears in the Changes list.
3. Right-click the file (alone or as part of a multi-selection) and choose "Ignore file(s) (Add to .gitignore)".
4. Inspect `.gitignore`: it now contains two lines — `legit.txt` and `!secret.env` — the second of which was injected via the embedded newline and was never explicitly chosen by the user. [4](#0-3) [5](#0-4)

/** Escapes a string from special characters used in a gitignore file */
export function escapeGitSpecialCharacters(pattern: string): string {
  const specialCharacters = /[\[\]!\*\#\?]/g

  return pattern.replaceAll(specialCharacters, match => {
    return '\\' + match
  })
}
