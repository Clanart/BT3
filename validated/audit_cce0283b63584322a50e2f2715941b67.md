### Title
Forged serialized outputs report attacker-controlled funds as spendable - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput::read` accepts an arbitrary scalar offset, `TxOut`, and `OutPoint` without proving that the output belongs to the wallet key associated with the offset or that the value is a plausible Bitcoin output. Consequently, untrusted bytes can deserialize into a `ReceivedOutput` which reports an attacker-selected balance but cannot be spent by Serai’s threshold key.

### Finding Description
`ReceivedOutput` is documented and structured as a spendable output containing the scalar offset, Bitcoin output, and claimed outpoint. [1](#0-0)  Its deserializer only performs scalar, `TxOut`, and `OutPoint` decoding, then immediately returns the object. [2](#0-1)  It does not check that `output.script_pubkey == p2tr_script_buf(base_key + offset * G)`, does not require a Taproot output, and does not authenticate that the outpoint exists on Bitcoin. `value()` subsequently exposes the attacker-controlled `TxOut` amount directly. [3](#0-2) 

The later transaction-signing path detects a mismatched key by deriving the offset-adjusted key and comparing its P2TR script against the previous output’s script. [4](#0-3)  That check does not repair the earlier accounting error: callers of `ReceivedOutput::read` can already have recorded and reported the forged output as received funds.

### Impact Explanation
An attacker who can feed bytes to `ReceivedOutput::read` can inflate a reported balance with values up to `u64::MAX`, attach the record to a fabricated `OutPoint`, and use a script controlled by the attacker rather than the threshold wallet. This creates the concrete impact of funds reported received that are not spendable; attempting to spend them through `SignableTransaction::multisig` fails the script/key-consistency check. [4](#0-3) 

### Likelihood Explanation
The input is a short, fully attacker-controlled byte string and requires no valid UTXO, signature, block confirmation, or knowledge of the threshold private shares. Exploitability requires an integration path which passes untrusted serialized data to `ReceivedOutput::read`; when only trusted scanner-generated database records are supplied, the malformed record cannot be introduced through this route.

### Recommendation
Do not treat deserialized `ReceivedOutput` values as authenticated scanner results. Either authenticate this state at the storage boundary or include/bind the base wallet key in the persisted representation and verify `p2tr_script_buf(base_key + offset * G) == output.script_pubkey` during deserialization. Independently verify that the outpoint exists in a sufficiently confirmed transaction, reject non-P2TR scripts and amounts exceeding `Amount::MAX_MONEY`, and use checked arithmetic when aggregating output values in `SignableTransaction`. [5](#0-4)

```rust
// networks/bitcoin/src/wallet/mod.rs
use bitcoin::OutPoint;
use frost::curve::Secp256k1;
use k256::Scalar;

// Secp256k1 generator x-coordinate used as an attacker-controlled Taproot key.
const ATTACKER_XONLY: [u8; 32] = [
    0x79, 0xbe, 0x66, 0x7e, 0xf9, 0xdc, 0xbb, 0xac,
    0x55, 0xa0, 0x62, 0x95, 0xce, 0x87, 0x0b, 0x07,
    0x02, 0x9b, 0xfc, 0xdb, 0x2d, 0xce, 0x28, 0xd9,
    0x59, 0xf2, 0x81, 0x5b, 0x16, 0xf8, 0x17, 0x98,
];

let mut bytes = Vec::new();

// Attacker-selected offset.
bytes.extend_from_slice(Scalar::ONE.to_bytes().as_slice());

// TxOut: value = u64::MAX.
bytes.extend_from_slice(&u64::MAX.to_le_bytes());

// TxOut script_pubkey: OP_1 followed by a 32-byte x-only key.
bytes.push(34);
bytes.push(0x51);
bytes.push(0x20);
bytes.extend_from_slice(&ATTACKER_XONLY);

// Fabricated OutPoint: 32-byte txid followed by vout = 0.
bytes.extend_from_slice(&[0; 32]);
bytes.extend_from_slice(&0u32.to_le_bytes());

let forged = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();

// The forged object reports a received balance even though the outpoint
// does not have to exist and the output is not bound to Serai's key.
assert_eq!(forged.value(), u64::MAX);
assert_eq!(forged.outpoint(), &OutPoint::default());
```

```rust
  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }
```
