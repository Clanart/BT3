### Title
`ReceivedOutput::read` / `Output::key` accept an attacker-supplied offset without checking it actually derives the output's `script_pubkey`, allowing funds to be reported as received under a multisig key that cannot spend them - (networks/bitcoin/src/wallet/mod.rs)

### Summary
The external report describes a missing exclusion check that lets a caller pass the protocol's own privileged "vault address" as the `Account` being liquidated — i.e., an input that is *supposed* to identify a distinct, spendable entity is accepted without verifying it actually is one. The Serai analog lives in `networks/bitcoin`: a `ReceivedOutput` pairs a scalar `offset` with an arbitrary `TxOut`, and neither `ReceivedOutput::read` nor `Output::key` ever verifies that `output.script_pubkey == p2tr_script_buf(scanner_key + G * offset)`. The binding between the claimed offset and the actual output is asserted by construction in `Scanner::scan_transaction` but is never re-validated on deserialization or when the owning key is recovered.

### Finding Description
`Scanner::scan_transaction` produces `ReceivedOutput`s keyed by `script_pubkey` lookups, so legitimately-scanned outputs always satisfy `output.script_pubkey == p2tr_script_buf(key + G*offset)` [1](#0-0) . However, `ReceivedOutput::read` deserializes `offset`, `output`, and `outpoint` from untrusted bytes with no consistency check whatsoever [2](#0-1) . This object is then consumed by `Output::key` in the processor, which *derives* the attributed multisig key by subtracting `G * offset` from whatever x-only key is embedded in the claimed script: `Secp256k1::read_G(...) - (GENERATOR * self.output.offset())` [3](#0-2) . Just as `_authenticateDeleverage` fails to check that `account != vault`, nothing here checks that the claimed `offset` is actually the one registered for this `script_pubkey` — the two fields are independently attacker-controlled.

### Impact Explanation
An unprivileged party who can feed crafted bytes to `ReceivedOutput::read` (via `Output::read`) can fabricate an `Output` whose `key()` resolves to *any* active multisig key while the underlying `TxOut.script_pubkey` pays to a key the multisig does not control. The scanner/processor pipeline credits `output.balance()` (real BTC value) to that multisig key [4](#0-3) , causing the protocol to report funds as received that are not spendable by the credited key set — the exact "special entity passed as victim" confusion: the multisig vault's identity is substituted into a slot meant for an output it genuinely owns.

### Likelihood Explanation
`Output::read`/`ReceivedOutput::read` are public deserialization entry points explicitly in scope as untrusted-byte sinks, and the only validation present is `assert!(script.is_p2tr())` plus a syntactic x-only key parse [5](#0-4)  — any valid P2TR script passes, so the attack requires no cryptographic break, only choosing `offset := script_key_x - target_key`. Crafting it is deterministic and cheap.

### Recommendation
After deserialization (or in `Output::key`), verify the consistency invariant the `Scanner` guarantees at creation time: recompute `p2tr_script_buf(key() + GENERATOR * offset)` — or equivalently check that `output.script_pubkey` equals the script registered for `offset` — and reject `ReceivedOutput`s where `output.script_pubkey != p2tr_script_buf(derived_key)`, analogous to rejecting `account == vault` in `_authenticateDeleverage`.

### Proof of Concept
1. Attacker picks target multisig key `K` (public, from scanned outputs) and any key `P` they control with even-Y `P`.
2. Craft bytes: `offset = P_x - K_x` (scalar such that `K + G*offset`... concretely set `offset` so that `x_only(P) - G*offset = K` — i.e., `offset` as the scalar mapping), `output = TxOut{ value: large, script_pubkey: p2tr(P) }`, `outpoint = arbitrary`.
3. Feed to `Output::read` → `ReceivedOutput::read` succeeds; `output.key()` returns `K` [6](#0-5) ; `balance()` reports the large value as belonging to multisig `K`, which cannot spend the P2TR output paying to `P`.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
