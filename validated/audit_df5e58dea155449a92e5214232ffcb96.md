### Title
`Scanner::scan_block` reports immature coinbase outputs as spendable, enabling funds that cannot be spent (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_block` iterates over every transaction in a block, including `block.txdata[0]` (the coinbase). Any output paying to a registered Serai `script_pubkey` inside a coinbase transaction is returned as a `ReceivedOutput` indistinguishable from a normal output. Coinbase outputs are unspendable for 100 blocks (COINBASE_MATURITY), so a `SignableTransaction` built over such an output produces a transaction that consensus rejects (`bad-txns-premature-spend-of-coinbase`). The in-scope processor path (`get_outputs` → scanner → `save_outputs` → Batch) treats these as real received funds.

### Finding Description
`scan_block` calls `scan_transaction` for all `block.txdata`, including index 0 ( [1](#0-0) ). `scan_transaction` matches only on `script_pubkey` and pushes a `ReceivedOutput` with the outpoint ( [2](#0-1) ). Nothing checks `tx.is_coinbase()`. The doc comment acknowledges the maturity issue but leaves enforcement to callers; `SignableTransaction::new`/`multisig` perform no coinbase/maturity check either ( [3](#0-2) ). In the processor, scanned outputs above the dust threshold are saved and emitted as a Batch event ( [4](#0-3) ), and the scanner's own test explicitly asserts `scan_block` results equal scanning `txdata[0]` ( [5](#0-4) ).

### Impact Explanation
An unprivileged party who mines a block (or pools that let miners set coinbase outputs) can pay to Serai's external/branch/change/forward script in the coinbase. Serai reports the deposit as received, but any `SignableTransaction` spending it is consensus-invalid for 100 blocks; worse, batching it alongside valid inputs poisons the whole signed transaction, temporarily locking all co-spent outputs until the invalid input is manually excluded — there is no mechanism to drop a reported `ReceivedOutput`.

### Likelihood Explanation
Requires the attacker to mine a block that includes a payment to a watched script — feasible for any miner and cheap on low-difficulty windows; the trigger is purely public on-chain data. The failure mode (invalid spend, no drop mechanism) follows deterministically.

### Recommendation
Skip `block.txdata[0]` in `scan_block`, or tag `ReceivedOutput` with coinbase/immaturity metadata and have `SignableTransaction::new` reject immature coinbase outpoints. Add a processor-side filter mirroring the documented "post-processing pass".

### Proof of Concept
1. Create `Scanner::new(key)` for an even `key`.
2. Mine a block whose coinbase pays to `p2tr_script_buf(key)` (as `send_and_get_output` in `networks/bitcoin/tests/wallet.rs` already does).
3. `scanner.scan_block(&block)` returns a `ReceivedOutput` for the coinbase outpoint.
4. `SignableTransaction::new(vec![output], &payments, change, None, fee)` succeeds; the signed transaction is rejected by Bitcoin Core with `bad-txns-premature-spend-of-coinbase`.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }
