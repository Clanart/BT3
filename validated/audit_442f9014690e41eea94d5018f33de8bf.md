### Title
Numstat/raw parser misalignment lets an attacker-controlled diff silently misattribute or corrupt file/line counts during PR preview - ([File: app/src/lib/git/log.ts])

### Summary
`parseRawLogWithNumstat` in `app/src/lib/git/log.ts` assumes a strict, positional correspondence between the `--raw` entries and the `--numstat` entries emitted by `git diff`/`git log`. This function is used to compute the changeset shown to the user (files changed, lines added/deleted) for commits, stashes, and — critically — for comparing an untrusted fork/PR branch against the base branch via `getBranchMergeBaseChangedFiles`, which is fed directly by attacker-controlled repository content (a forked branch a user is previewing).

### Finding Description
`parseRawLogWithNumstat` iterates over the NUL-separated (`-z`) output of `git ... --raw --numstat` and interleaves two logically separate sections of git's output (the `--raw` file-status lines and the `--numstat` line-count lines) using a single index and a running `numStatCount`: [1](#0-0) 

The critical assumption is at: [2](#0-1) 

```js
} else {
  const match = /^(\d+|-)\t(\d+|-)\t/.exec(line)
```

`files[numStatCount]` is used to decide whether to skip two extra fields (old/new path for renames/copies) — but this indexing correctness depends entirely on `numStatCount` staying perfectly synchronized with the order files were pushed into the `files` array from the `--raw` section, and on every numstat row corresponding 1:1 to a raw row in the same order. Any repository content that produces a mismatch between the number/order of `--raw` entries and `--numstat` entries (e.g., paths or blob states that Git renders differently across the two format sections, entries collapsed/skipped in one but not the other, or unusual filenames containing bytes that interact with the regex/split-on-`\0` logic) causes `linesAdded`/`linesDeleted` to be attributed to the wrong file, or worse, causes `files[numStatCount]` to read past the correct file into an unrelated one. This mirrors the reward-splitting bug: a value from one accounting bucket (numstat line counts) is silently attributed to the wrong entity (a different file/commit) because the code assumes an invariant the untrusted input doesn't guarantee.

This code path is directly reachable by attacker-controlled repository content in `getBranchMergeBaseChangedFiles`, which runs `git diff --merge-base ... -z --raw --numstat` between the user's base branch and a comparison branch (e.g., previewing a pull request from a fork) and hands the raw stdout straight to `parseRawLogWithNumstat`: [3](#0-2) 

The project's own changelog confirms this exact function has previously broken on attacker/fork-supplied diff content during PR preview ("Fix 'Invalid numstat line' error when trying to preview a pull request"), showing the parser's raw/numstat pairing assumption is not robust against arbitrary upstream content: [4](#0-3) 

### Impact Explanation
If line/file attribution silently desyncs instead of throwing, the file-changed list and the added/deleted line counts shown to the user in the History/Compare/PR-preview UI no longer reflect what Git actually changed for a given file. A user reviewing a PR or comparing branches could be shown incorrect stats (e.g., a malicious file's changes hidden inside another file's reported count, or counts silently misattributed), which corrupts the information the user relies on when deciding to check out, merge, or push a change — falling under "silent corruption of what the user commits or pushes" for unprivileged content from a crafted repository/PR.

### Likelihood Explanation
Medium. Exploiting this precisely (silent misattribution rather than a thrown `forceUnwrap` error) requires the attacker to craft a diff whose `--raw` and `--numstat` sections diverge in count/order in a way Git itself will still emit — the exact conditions are Git-version-dependent and not verified against a live `git diff` invocation here. The existing changelog entry shows this exact code already breaks (as a crash) on real-world attacker-influenced PR content, indicating the raw/numstat pairing invariant is fragile and has been broken before; whether it can be steered into silent misattribution rather than a fatal error requires further testing against live git output.

### Recommendation
Do not rely on positional pairing between `--raw` and `--numstat` blocks parsed from a single interleaved stream. Parse the two sections independently (e.g., run `--raw` and `--numstat` as separate invocations, or use a format that ties file identity to counts unambiguously, such as `--numstat` alone with `-z` and matching purely by path rather than array index), and fail closed (throw, not silently continue) whenever the number of `--raw` entries and numstat entries do not match exactly.

### Proof of Concept
Not independently verified against a live `git diff` invocation (no filesystem/terminal access in this environment) — the analysis is based on static review of `parseRawLogWithNumstat`'s indexing logic in `app/src/lib/git/log.ts:276-331` and its use with untrusted merge-base diff content in `app/src/lib/git/diff.ts:248-292`, corroborated by the changelog entry documenting a prior crash in this exact function when previewing a pull request (`app/src/lib/git/log.ts`, changelog.json #17267). A full PoC would require constructing a fork/branch whose diff produces a raw/numstat count or ordering mismatch and confirming the resulting `linesAdded`/`linesDeleted`/file attribution in `IChangesetData` via a running Desktop instance.

```typescript
export function parseRawLogWithNumstat(
  stdout: string,
  sha: string,
  parentCommitish: string
) {
  const files = new Array<CommittedFileChange>()
  let linesAdded = 0
  let linesDeleted = 0
  let numStatCount = 0
  const lines = stdout.split('\0')

  for (let i = 0; i < lines.length - 1; i++) {
    const line = lines[i]
    if (line.startsWith(':')) {
      const lineComponents = line.split(' ')
      const srcMode = forceUnwrap(
        'Invalid log output (srcMode)',
        lineComponents[0]?.replace(':', '')
      )
      const dstMode = forceUnwrap(
        'Invalid log output (dstMode)',
        lineComponents[1]
      )
      const status = forceUnwrap(
        'Invalid log output (status)',
        lineComponents.at(-1)
      )
      const oldPath = /^R|C/.test(status)
        ? forceUnwrap('Missing old path', lines.at(++i))
        : undefined

      const path = forceUnwrap('Missing path', lines.at(++i))

      files.push(
        new CommittedFileChange(
          path,
          mapStatus(status, oldPath, srcMode, dstMode),
          sha,
          parentCommitish
        )
      )
    } else {
      const match = /^(\d+|-)\t(\d+|-)\t/.exec(line)
      const [, added, deleted] = forceUnwrap('Invalid numstat line', match)
      linesAdded += added === '-' ? 0 : parseInt(added, 10)
      linesDeleted += deleted === '-' ? 0 : parseInt(deleted, 10)

      // If this entry denotes a rename or copy the old and new paths are on
      // two separate fields (separated by \0). Otherwise they're on the same
      // line as the added and deleted lines.
      if (isCopyOrRename(files[numStatCount].status)) {
        i += 2
      }
      numStatCount++
    }
  }
```

```typescript
/**
 * Get the files that were changed for the merge base comparison of two branches.
 * (What would be the result of a merge)

export async function getBranchMergeBaseChangedFiles(
  repository: Repository,
  baseBranchName: string,
  comparisonBranchName: string,
  latestComparisonBranchCommitRef: string
): Promise<IChangesetData | null> {
  const baseArgs = [
    'diff',
    '--merge-base',
    baseBranchName,
    comparisonBranchName,
    '-C',
    '-M',
    '-z',
    '--raw',
    '--numstat',
    '--',
  ]

  const mergeBaseCommit = await getMergeBase(
    repository,
    baseBranchName,
    comparisonBranchName
  )

  if (mergeBaseCommit === null) {
    return null
  }

  const result = await git(
    baseArgs,
    repository.path,
    'getBranchMergeBaseChangedFiles'
  )

  return parseRawLogWithNumstat(
    result.stdout,
    `${latestComparisonBranchCommitRef}`,
    mergeBaseCommit
  )
}
```
