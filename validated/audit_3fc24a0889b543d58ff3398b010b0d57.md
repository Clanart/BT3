### Title
External parties can inject outputs classified as internal `Branch`/`Change`/`Forwarded` outputs due to script-only classification with publicly derivable offsets - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The Bitcoin `Scanner` attributes ownership and output type purely by matching `script_pubkey` against a fixed set of registered scripts derived from deterministic, publicly computable offsets (`hash_to_F(KEY_DST, "branch" | "change" | "forward")`). There is no check that a transaction paying to an internal-only script (Branch, Change) was actually produced by the multisig protocol. Any external party can compute these scripts and send a transaction to them, and `get_outputs` will report the output under the internal `OutputType` — analogous to the InLong flaw where any user could act on a resource (here: an internal output classification) that does not belong to them.

### Finding Description
`Scanner::register_offset` maps each registered offset to a P2TR script and `scan_transaction` returns a `ReceivedOutput` for any tx output whose `script_pubkey` is in `self.scripts`, with no provenance check [1](#0-0) . The processor reconstructs this scanner with fixed offsets for `OutputType::Branch`, `OutputType::Change`, and `OutputType::Forwarded`, all derived via the deterministic, public `Secp256k1::hash_to_F(KEY_DST, ...)` [2](#0-1) . `get_outputs` then assigns `kind` solely from the matched offset and pushes the output for downstream handling, checking only `output.tx_id() == tx.id()` — nothing binds the output to an internally-generated transaction [3](#0-2) . The `data`/`presumed_origin` fields are populated entirely from attacker-controlled transaction data (`tx.input[0]`'s spent output and `extract_serai_data(tx)`) [4](#0-3) .

### Impact Explanation
An unprivileged Bitcoin user can send funds directly to the publicly derivable `Branch`, `Change`, or `Forwarded` scripts. The processor will report these as internal outputs (e.g., `OutputType::Change` — outputs assumed to originate from the multisig's own spends), corrupting output accounting and causing externally-originated funds to be treated as protocol-internal funds. Conversely, a misdirected or malicious deposit to a non-`External` script is classified as internal, so the depositor's funds are reported as received but are never credited as a deposit — effectively funds received that are not spendable per the depositor's intent. This mirrors CWE-552: internal resources reachable/classifiable by external parties due to a missing origin/ownership check.

### Likelihood Explanation
The offsets are computed from a constant public DST (`b"Serai Bitcoin Output Offset"`) and fixed labels; any observer can derive all four script_pubkeys and send transactions to them permissionlessly. Exploitation requires only a standard Bitcoin transaction — no validator privileges, no collusion, and no control over Serai internals.

### Recommendation
Track which internal scripts/TXIDs the multisig itself created, and only classify a scanned output as `Branch`/`Change` (non-`External` internal kinds) if the funding transaction's inputs trace back to outputs the wallet itself controls (i.e., the tx spends our own outputs). At minimum, treat unexpected outputs at internal addresses as `External`-like deposits or alert/flag them rather than silently accepting the internal classification.

### Proof of Concept
1. Derive `change_offset = Secp256k1::hash_to_F(b"Serai Bitcoin Output Offset", b"change")` and `forward_offset = hash_to_F(..., b"forward")` — both computable by anyone since `KEY_DST` and the labels are public constants (`processor/src/networks/bitcoin.rs:308-344`).
2. Compute `change_script = p2tr_script_buf(group_key + G*change_offset)`; `register_offset` increments until an even point, so replicate the same loop to get the exact script (`networks/bitcoin/src/wallet/mod.rs:180-196`).
3. Broadcast a transaction paying to `change_script`. `get_outputs` scans it, `kinds[offset]` resolves to `OutputType::Change`, and the output is pushed as an internally-classified output with attacker-influenced `presumed_origin` (`processor/src/networks/bitcoin.rs:686-739`) — an external party successfully injecting a resource into an internal classification, with no authorization check anywhere in the scan path.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res

fn scanner(

) -> (Scanner, HashMap<OutputType, Scalar>, HashMap<Vec<u8>, OutputType>) {
  let mut scanner = Scanner::new(key).unwrap();
  let mut offsets = HashMap::from([(OutputType::External, Scalar::ZERO)]);

  let zero = Scalar::ZERO.to_repr();
  let zero_ref: &[u8] = zero.as_ref();
  let mut kinds = HashMap::from([(zero_ref.to_vec(), OutputType::External)]);

  let mut register = |kind, offset| {
    let offset = scanner.register_offset(offset).expect("offset collision");
    offsets.insert(kind, offset);

    let offset = offset.to_repr();
    let offset_ref: &[u8] = offset.as_ref();
    kinds.insert(offset_ref.to_vec(), kind);
  };

    OutputType::Branch,
    *BRANCH_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"branch")),
