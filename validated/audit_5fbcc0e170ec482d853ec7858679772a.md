Based on my investigation, I found a concrete architectural parallel to the Curve `get_virtual_price()` donation-and-skim pattern in Hyperbridge's shared `CallDispatcher` utility used by `IntentGatewayV2` (and other apps like `HyperFungibleToken`).

### Title
Permissionless `CallDispatcher.dispatch()` allows any address to steal tokens/ETH left in the shared dispatcher by intent order flows - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
`CallDispatcher` is a single, shared, publicly-documented contract instance reused by `IntentGatewayV2` (and other Hyperbridge apps) to execute user-supplied `predispatch`/`postdispatch` calldata while momentarily holding escrowed value. Its `dispatch()` entrypoint has **no caller restriction whatsoever**: any address can invoke it to move out whatever tokens or ETH the dispatcher currently holds.

### Finding Description
`CallDispatcher.dispatch()` is declared `external` with no modifier, ownership check, or allowlist of callers: [1](#0-0) 

`IntentGatewayV2.placeOrder()` transfers `order.predispatch.assets` into this shared dispatcher, executes the order-owner's arbitrary `predispatch.call`, and only afterwards sweeps back the balances of the tokens/ETH explicitly named in `order.inputs`: [2](#0-1) 

The sweep loop only iterates over `order.inputs[i].token` (and, symmetrically in `IntentsBase._execute`, only over `order.output.assets[i].token`): [3](#0-2) 

Any value that ends up in the dispatcher outside that fixed, known token set — e.g. leftover native ETH from a predispatch swap that under-consumes the funded amount (`order.predispatch.assets` includes ETH but `order.inputs` doesn't), reward/referral tokens returned by a DEX or lending protocol invoked via arbitrary calldata, or dust from any other integration that reuses this same documented, singleton contract — is never swept back and instead persists as a balance sitting in a fully public, permissionless contract. The docs explicitly acknowledge the dispatcher "holds tokens temporarily during execution" and warn integrators to use exact approvals, confirming this is a known, unmitigated residual-balance surface, not just a theoretical corner case.

This is structurally the same broken invariant as the Curve report: a shared pool of value (`CurveStableSwap` balances / `CallDispatcher` balance) can be topped up by an uncontrolled path (direct ERC20 transfer / any side-effect of arbitrary calldata execution), and a permissionless function (`exchange_received()` / `dispatch()`) exists that lets anyone extract whatever currently sits there — with no ownership or per-order accounting tying the balance to the party who is entitled to it.

### Impact Explanation
Any address (an MEV bot, or the very order-placer's own transaction) can drain ETH/tokens accidentally or unavoidably left in the shared `CallDispatcher` by another user's intent order. Because the contract is a single reused instance across the whole `IntentGatewayV2` deployment (and other apps per the docs), residual value from any user's predispatch/postdispatch calldata accumulates into a commonly-known, always-permissionless target, resulting in unauthorized loss of user funds with no relayer, prover, or admin compromise required — an ordinary unprivileged caller directly executes `dispatch()`.

### Likelihood Explanation
High for any order whose `predispatch`/`postdispatch` calldata interacts with tokens outside the declared `order.inputs`/`order.output.assets` set (very common in DeFi routing — reward tokens, dex-router refunds, over-funded native ETH legs). The attack requires no special access: `dispatch()` is a bare external function, watched by anyone monitoring the dispatcher's on-chain balance.

### Recommendation
Restrict `CallDispatcher.dispatch()` to a caller allowlist (e.g., `onlyRole`/`onlyRegisteredApp` for `IntentGatewayV2`, `HyperFungibleToken`, etc.), and/or make the dispatcher per-order (ephemeral/cloned) rather than a shared singleton, and extend the sweep logic in `IntentGatewayV2`/`IntentsBase` to reconcile *all* token/ETH balances the dispatcher could plausibly receive, not only the ones named in `order.inputs`/`order.output.assets`.

### Proof of Concept
1. User places an intent order whose `predispatch.assets` sends 1 ETH to `CallDispatcher`, and whose `predispatch.call` swaps only part of it (e.g., 0.9 ETH) into the DAI required by `order.inputs`, intentionally or due to slippage/rounding leaving 0.1 ETH in the dispatcher.
2. `IntentGatewayV2.placeOrder()`'s sweep loop (lines 232-256) only checks/sweeps the DAI balance (the token in `order.inputs`); the leftover 0.1 ETH is never touched.
3. Any external address calls `CallDispatcher.dispatch(abi.encode([Call({to: attacker, value: 0.1 ether, data: ""})]))` directly — this succeeds because `dispatch()` has no caller restriction — draining the stranded ETH to the attacker. [4](#0-3)

     *  @dev reverts if the target is not a contract or if any of the calls reverts.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {
            Call[] memory finalCalls = new Call[](sweepCount);
            for (uint256 i; i < sweepCount;) {
                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
    }
