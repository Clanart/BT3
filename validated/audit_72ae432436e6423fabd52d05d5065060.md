### Title
Front-running-style griefing of auction bids via unauthenticated `auction_submitBid` locks a searcher's per-block bid slot - (File: kaiax/auction/impl/bid_pool.go)

### Summary
The Kaia auction module accepts bids through the public JSON-RPC method `SubmitBid`, which takes a fully pre-signed `Bid` object (including `SearcherSig` and `AuctioneerSig`) and inserts it into the bid pool without ever verifying that the caller of the RPC is the bid's `Sender`. Once any single bid from a given sender is accepted for a block, the bid pool permanently locks that sender's "winner slot" for that block, rejecting any other (different) bid from the same sender — even a strictly better one for a different target transaction. This mirrors the reported `CrabNetting.checkOrder` bug class: possession of a validly signed message (an `Order`/`Bid`) lets any unprivileged caller "consume" the signer's slot ahead of the intended submission, DoS-ing the legitimate action.

### Finding Description
`AuctionAPI.SubmitBid` is a public-facing RPC entry point that decodes caller-supplied `BidInput`, converts it to a `Bid`, and calls `bidPool.AddBid(bid)` — with no check that `msg.sender`/RPC caller equals `bid.Sender`: [1](#0-0) 

Inside the pool, `insertBid` and `validateBid` key a "winner" record purely by `(blockNumber, sender)`, not by target transaction: [2](#0-1) 

`senderHasDifferentWinner` enforces that once a sender has *any* recorded winning bid for a block, subsequent bids from that same sender are rejected unless byte-for-byte identical to the stored one: [3](#0-2) 

Because the only signature verification performed is on the bid content itself (searcher/auctioneer EIP-712 signatures), and not on who calls the RPC, any party who obtains a copy of a validly-signed `Bid` (e.g., an earlier or lower "placeholder" bid a searcher signed and shared with the auctioneer, or one previously submitted and later intended to be replaced with a better bid for a different target tx) can resubmit that exact bid via `auction_submitBid` first. This "locks in" the sender's slot for that block. When the searcher's genuine, better bid (for the same or a different target tx) arrives afterward, `AddBid` returns `auction.ErrBidSenderExists` and the legitimate bid is dropped — exactly analogous to an attacker calling `checkOrder` to burn a nonce before the legitimate `depositAuction`/`withdrawAuction` transaction lands.

### Impact Explanation
This allows griefing/DoS of the MEV auction settlement path: a legitimate searcher's higher/valid bid for a block can be permanently excluded once any other (previously signed, potentially stale) bid from the same sender has been inserted by an unrelated third party. This can redirect the auction outcome (a lower or unintended bid stays "the winner" for that sender/block, or the sender is excluded from bidding altogether for that block), which constitutes gasless/auction-settlement manipulation and unauthorized denial of a legitimate value-bearing action, satisfying the "auction bidder" and "public RPC caller" reachable actor classes.

### Likelihood Explanation
The `SubmitBid` RPC performs no authentication tying the caller to `bid.Sender`, and no on-chain nonce/replay binding beyond the raw EIP-712 signed payload itself (block number is bound, but any bid signed and shared once — even if it was meant to be superseded — remains submittable by anyone who has seen it). Any environment where searchers/auctioneers exchange bid payloads off-chain, or where past bids become observable, exposes this path to an unprivileged caller with a single RPC call.

### Recommendation
Bind the winner-slot logic to a per-sender monotonic nonce/sequence that is verified on submission (similar to intended-but-unused `bid.Nonce` field), and/or authenticate the RPC caller against `bid.Sender` before accepting a `SubmitBid` call, so that only the actual searcher (or their delegated auctioneer channel) can occupy or update their own bid slot. Additionally, allow a sender's slot to be replaced by a strictly better signed bid rather than unconditionally rejecting any differing bid via `ErrBidSenderExists`.

### Proof of Concept
1. Searcher `S` signs (and shares with the auctioneer/broadcasts for co-signing) `bidA` targeting `targetTx1` for block `N`. The auctioneer co-signs it, producing a fully valid `Bid` object.
2. Before `S`'s real submission, or before `S`'s later, better `bidB` (e.g., targeting `targetTx2`, block `N`) is submitted, an unprivileged third party who has observed `bidA` (e.g., via a leaked auctioneer relay, mempool-adjacent channel, or reused test bid) calls `auction_submitBid` with `bidA`.
3. `bidA` passes `validateBidSigs` (both signatures are valid) and is inserted via `insertBid`, setting `bidWinnerMap[N][S] = hash(bidA)`.
4. When `S` (or the auctioneer) later submits `bidB` — a different, better bid from the same sender for the same block — `validateBid`/`insertBid` calls `senderHasDifferentWinner`, which returns `true` because `bidB != bidA`, causing `AddBid` to return `auction.ErrBidSenderExists`, per [4](#0-3) , and `S`'s legitimate bid is dropped.

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)
}

func (bp *BidPool) insertBid(bid *auction.Bid) error {
	bp.bidMu.Lock()
	defer bp.bidMu.Unlock()

	var (
		blockNumber  = bid.BlockNumber
		targetTxHash = bid.TargetTxHash
		sender       = bid.Sender
	)

	// Re-check bidWinnerMap here — two concurrent bids can pass validateBid together.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		return auction.ErrBidAlreadyExists
	}
	if bp.senderHasDifferentWinner(bid) {
		return auction.ErrBidSenderExists
	}

	// If same block number, same target tx hash exists, replace it if it's better
	if existingBid, ok := bp.bidTargetMap[blockNumber][targetTxHash]; ok {
		// FCFS if the bid is the same.
		if existingBid.Bid.Cmp(bid.Bid) >= 0 {
			return auction.ErrLowBid
		}

		logger.Trace("Replace bid", "old", existingBid.Hash(), "new", bid.Hash())
		delete(bp.bidMap, existingBid.Hash())
		delete(bp.bidWinnerMap[blockNumber], existingBid.Sender)
	} else {
		if int64(len(bp.bidMap)) >= bp.maxBidPoolSize {
			logger.Info("Bid pool is full", "maxBidPoolSize", bp.maxBidPoolSize, "bid", bid.Hash())
			return auction.ErrBidPoolFull
		}
	}

	hash := bid.Hash()

	bp.initializeBidMap(blockNumber)

	bp.bidMap[hash] = bid
	bp.bidTargetMap[blockNumber][targetTxHash] = bid
	bp.bidWinnerMap[blockNumber][sender] = hash

	numBidsGauge.Update(int64(len(bp.bidMap)))

	logger.Trace("Add bid", "bid", hash)

	return nil
}

// senderHasDifferentWinner reports whether a different bid from the same sender
// already exists in the winner list for this block. Caller must hold bidMu.
func (bp *BidPool) senderHasDifferentWinner(bid *auction.Bid) bool {
	hash, ok := bp.bidWinnerMap[bid.BlockNumber][bid.Sender]
	if !ok {
		return false
	}
	return !bid.Equals(bp.bidMap[hash])
}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
