### Title
Silent duplicate-key overwrite in NFT metadata parsing causes wallet/CLVM child-puzzle-hash divergence and coin-tracking halt - (File: chia/wallet/nft_wallet/nft_puzzle_utils.py)

### Summary
Chia's NFT metadata is represented on-chain as a CLVM key/value list `((k1 . v1) (k2 . v2) ...)` curried into the NFT state layer puzzle. The wallet-side Python helper `nft_program_to_metadata()` converts this list into a Python `dict`, which silently collapses duplicate keys to the last occurrence, exactly the "key overwrite" bug class described in the Fortigate/Graylog advisory (a key-value parser that lets an attacker overwrite or hide fields by injecting duplicate keys).

### Finding Description
`nft_program_to_metadata()` iterates the raw metadata program and builds a dict keyed by the metadata field name: [1](#0-0) 

Because a Python `dict` silently overwrites earlier entries with the same key, any metadata program that contains the same key atom (`b"u"`, `b"mu"`, `b"lu"`, etc.) more than once will have all but the last occurrence dropped when converted to `dict`. This is the direct analog of the Graylog advisory: a key/value message parser that lets a crafted duplicate-key structure silently overwrite/discard fields.

This dict is then mutated in `prepend_value()` and reserialized back to a CLVM program in `update_metadata()`, which the wallet uses to predict the resulting metadata (and therefore the resulting puzzle hash) of an NFT after an on-chain `-24` "metadata update" spend: [2](#0-1) 

This prediction is used in `get_metadata_and_phs()`, invoked from `puzzle_solution_received()`, to compute the child NFT coin's puzzle hash and locate the corresponding coin among the spend's additions: [3](#0-2) [4](#0-3) 

If the actual on-chain `NFT_METADATA_UPDATER`/state-layer CLVM code processes duplicate-keyed metadata lists differently than the Python dict-based reconstruction (e.g., CLVM list-search semantics typically match the *first* occurrence of a key, while Python `dict()` construction keeps the *last*), the wallet computes a `child_puzzle_hash` that differs from the coin actually created on-chain. `puzzle_solution_received()` then fails to match any addition to the predicted hash and raises:
```
raise ValueError("Couldn't generate child puzzle for NFT")
``` [5](#0-4) 

### Impact Explanation
An NFT can be minted or updated (by its owner, or received via a trade/offer from a counterparty) with a metadata program containing duplicate key entries. When any wallet subsequently processes a metadata-update spend for that NFT, the wallet's field-collapsing logic (last-key-wins) can diverge from the CLVM puzzle's actual behavior (first-key-wins, or a different match order), causing the wallet to compute the wrong expected puzzle hash for the child coin. This halts processing of that specific NFT coin spend in the receiving wallet (`ValueError` raised during `puzzle_solution_received`), and can cause the wallet to permanently lose track of an NFT it legitimately owns — a spend-triggered transaction-processing halt confined to NFT coin tracking, reachable purely by an unprivileged wallet user crafting/offering an NFT with duplicate metadata keys.

### Likelihood Explanation
Any unprivileged wallet user can mint an NFT with metadata containing duplicate key atoms (nothing in `metadata_to_program()`/mint flows rejects duplicate keys), and can then trade/gift/offer it. Triggering the divergence additionally requires the receiving wallet to process a subsequent `-24` metadata-update spend on that NFT, which is a normal NFT interaction. This is a self-contained wallet-side bug requiring no special privileges or malicious peer/network position, only a specially crafted NFT metadata program and a subsequent legitimate-looking update spend — a plausible medium-likelihood scenario for an unprivileged spend-bundle submitter/wallet user.

### Recommendation
Make `nft_program_to_metadata()` and `update_metadata()` reject or explicitly define handling of duplicate metadata keys (mirroring whatever precedence rule the on-chain `NFT_METADATA_UPDATER`/state-layer CLVM actually uses), so that the Python-side puzzle-hash prediction always matches on-chain behavior. Alternatively, preserve key order/duplicates through a list-of-tuples representation instead of collapsing to a `dict`, and only pick the update target using the exact same first/last-match semantics as the CLVM puzzle.

### Proof of Concept
1. Mint (or use an existing) NFT with metadata `((b"u" . ["url-A"]) (b"u" . ["url-B"]))` — i.e., a duplicate `"u"` key — via `metadata_to_program()`, which places no restriction on duplicate keys: [6](#0-5) 
2. Curry this metadata into the NFT state layer puzzle and confirm the coin on-chain, so the CLVM puzzle's real update logic operates on the true (duplicate-containing) list.
3. Perform an on-chain `-24` metadata update spend adding a new URI for key `"u"`.
4. Observe that the wallet's Python reconstruction (`nft_program_to_metadata`) only ever "sees" the last `"u"` entry (`url-B`), so `update_metadata()`/`prepend_value()` compute a different resulting metadata program (and therefore a different expected child puzzle hash) than what the actual CLVM puzzle produces from the full duplicate-containing list.
5. In `puzzle_solution_received()`, the loop over `compute_additions(...)` never finds a coin matching the wallet's mis-predicted `child_puzzle_hash`, and the wallet raises `ValueError("Couldn't generate child puzzle for NFT")`, halting further tracking of that NFT for the affected wallet.

def metadata_to_program(metadata: dict[bytes, Any]) -> Program:
    """
    Convert the metadata dict to a Chialisp program
    :param metadata: User defined metadata
    :return: Chialisp program
    """
    kv_list = []
    for key, value in metadata.items():
        kv_list.append((key, value))
    program: Program = Program.to(kv_list)
    return program

def nft_program_to_metadata(program: Program) -> dict[bytes, Any]:
    """
    Convert a program to a metadata dict
    :param program: Chialisp program contains the metadata
    :return: Metadata dict
    """
    metadata = {}
    for kv_pair in program.as_iter():
        metadata[kv_pair.first().as_atom()] = kv_pair.rest().as_python()
    return metadata
```

def prepend_value(key: bytes, value: Program, metadata: dict[bytes, Any]) -> None:
    """
    Prepend a value to a list in the metadata
    :param key: Key of the field
    :param value: Value want to add
    :param metadata: Metadata
    :return:
    """
    if value != Program.to(0):
        if metadata[key] == b"":
            metadata[key] = [value.as_python()]
        else:
            metadata[key].insert(0, value.as_python())


def update_metadata(metadata: Program, update_condition: Program) -> Program:
    """
    Apply conditions of metadata updater to the previous metadata
    :param metadata: Previous metadata
    :param update_condition: Update metadata conditions
    :return: Updated metadata
    """
    new_metadata: dict[bytes, Any] = nft_program_to_metadata(metadata)
    uri: Program = update_condition.rest().rest().first()
    prepend_value(uri.first().as_python(), uri.rest(), new_metadata)
    return metadata_to_program(new_metadata)

def get_metadata_and_phs(unft: UncurriedNFT, solution: SerializedProgram) -> tuple[Program, bytes32]:
    conditions = unft.p2_puzzle.run(unft.get_innermost_solution(Program.from_serialized(solution)))
    metadata = unft.metadata
    puzhash_for_derivation: bytes32 | None = None
    for condition in conditions.as_iter():
        if condition.list_len() < 2:
            # invalid condition
            continue
        condition_code = condition.first().as_int()
        log.debug("Checking condition code: %r", condition_code)
        if condition_code == -24:
            # metadata update
            metadata = update_metadata(metadata, condition)
            metadata = Program.to(metadata)
        elif condition_code == 51:
            atom = condition.rest().rest().first().as_int()

            if atom == 1:
                # destination puzhash
                if puzhash_for_derivation is not None:
                    # ignore duplicated create coin conditions
                    continue
                memo = bytes32(condition.at("rrrff").as_atom())
                puzhash_for_derivation = memo
                log.debug("Got back puzhash from solution: %s", puzhash_for_derivation)
    assert puzhash_for_derivation
    return metadata, puzhash_for_derivation
