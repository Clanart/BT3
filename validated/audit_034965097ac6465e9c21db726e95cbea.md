### Title
Auction `Bid.Equals()` compares only `BlockNumber`/`TargetTxHash`, allowing a searcher's original signed bid to be silently displaced by a different signed bid in the same slot - (File: kaiax/auction/bid.go)

### Summary
The reported bug class is a hash/identity-check that omits a field, so an operation meant to identify "the same transaction" instead matches a different one, breaking the intended access-control invariant. In the Kaia auction module (`kaiax/auction`), the analogous identity check is `Bid.Equals()`, which is used to decide whether a newly-submitted, fully-signed bid from a sender is "the same" as the sender's already-recorded winning bid for a block, or a distinct bid that must be rejected.

### Finding Description
`Bid.Equals()` only compares `BlockNumber` and `TargetTxHash`: [1](#0-0) 

This function is the sole gate used by `senderHasDifferentWinner()`, which is called both during `validateBid()` (pre-check) and again inside `insertBid()` (post-lock re-check) to enforce the rule documented in the module's README: *"The `bid.Sender` must not be in the winner list of the same block number if the new bid doesn't have the same target block and hash as the previous bid."* [2](#0-1) [3](#0-2) 

Because `Equals` ignores every other field of `BidData` — `Bid` (bid amount), `Nonce`, `To`, `Data`, `CallGasLimit`, `MaxGasPrice`, `SearcherSig`, `AuctioneerSig` — any two bids from the same sender that target the same tx/block are treated as identical for the purposes of this guard, even though they are cryptographically distinct, differently-signed bids with completely different payloads (different `Data`/`CallGasLimit`/`To`, i.e. a different post-target action) and different `Bid` amounts.

`insertBid()` then allows the second bid to *replace* the first purely based on the `Bid` amount comparison against `bidTargetMap`, using the second bid's own signatures (which were already validated against the second bid's own EIP-712 digest in `validateBidSigs`/`GetHashTypedData`): [4](#0-3) [5](#0-4) 

The signature validation itself (`ValidateSearcherSig`/`ValidateAuctioneerSig`) is correct and binds to the full `AuctionTx` struct fields via EIP-712 — it is not the "wrong hash" here. The bug is specifically in the equality/identity predicate used to gate replacement of a sender's committed slot: it under-specifies identity by dropping the payload/signature fields, mirroring the missing-parameter class of bug in the `QuickAccManager.cancel()` report (a hash/identity check that omits fields needed to correctly disambiguate the object being operated on).

### Impact Explanation
Because the auctioneer is a semi-trusted off-chain relay that forwards `Bid`s signed by `Sender` (the searcher) via `auction_submitBid`/`HandleBid`, a malicious or compromised auctioneer (or a searcher colluding across bids) can submit two different signed bids for the same `(BlockNumber, TargetTxHash, Sender)` — one with a low `Bid` amount used to win the earlier check pass, and another with a much lower/degenerate `Bid`, or a completely different `Data`/`To`/`CallGasLimit` payload that changes what gets executed on-chain — and freely swap between them (since `senderHasDifferentWinner` never blocks the swap because `Equals` says they're "the same"). The `Bid.Cmp` FCFS guard in `insertBid` only prevents downgrading the bid amount for a given target, but does not protect the *content* (`Data`, `To`, `CallGasLimit`) of the winning bid from being swapped for another equally- or higher-priced but functionally different signed bid from the same sender, undermining the auction's "one committed winning bid per sender per block" invariant and enabling a searcher to bait a higher price and settle a different low-value/degenerate action instead — i.e., fee/auction settlement abuse per the accepted impact categories.

### Likelihood Explanation
This requires only a single unprivileged-but-authorized data path: a searcher (or the auctioneer relaying searcher bids) submitting two valid, fully-signed bids through the standard `auction_submitBid` RPC / P2P bid gossip path, both targeting the same `(blockNumber, targetTxHash)` for the same sender. No node compromise, discovery, or consensus-message manipulation is needed — this is reachable purely from the public bid-submission surface, matching the "unprivileged transaction sender / auction bidder" reachability requirement.

### Recommendation
Extend `Bid.Equals()` to compare the full economically/functionally relevant fields (at minimum `Sender`, `To`, `Nonce`, `Bid`, `MaxGasPrice`, `CallGasLimit`, `Data`, and ideally the signature bytes or the computed EIP-712 digest / `Bid.Hash()`), so that `senderHasDifferentWinner()` correctly rejects any bid from a sender that isn't byte-for-byte the previously accepted winning bid for that block/target.

### Proof of Concept
1. Searcher `S` signs `Bid1{BlockNumber=N, TargetTxHash=T, Bid=100, To=RouterA, Data=actionA}` and it is submitted and accepted as the winner for `(N, T)`.
2. Searcher `S` (or a colluding auctioneer) then signs and submits `Bid2{BlockNumber=N, TargetTxHash=T, Bid=101, To=RouterB, Data=actionB}` — a valid, differently-signed bid with different execution payload.
3. `validateBid(Bid2)` calls `senderHasDifferentWinner(Bid2)` → `Equals(Bid1, Bid2)` returns `true` (only `BlockNumber`/`TargetTxHash` match) → guard passes.
4. `insertBid(Bid2)` sees `existingBid.Bid (100) < bid.Bid (101)` → replaces `Bid1` with `Bid2` in `bidTargetMap`/`bidMap`/`bidWinnerMap`.
5. At block-building time, `ExtractTxBundles` (`kaiax/auction/impl/builder.go`) picks `Bid2` from `bidTargetMap`, generating and settling `actionB` against `RouterB` instead of the originally expected `actionA`/`RouterA`, even though both bids came from `S` and were treated as "the same" bid by the pool's identity check. // senderHasDifferentWinner reports whether a different bid from the same sender
// already exists in the winner list for this block. Caller must hold bidMu.
func (bp *BidPool) senderHasDifferentWinner(bid *auction.Bid) bool {
	hash, ok := bp.bidWinnerMap[bid.BlockNumber][bid.Sender]
	if !ok {
		return false
	}
	return !bid.Equals(bp.bidMap[hash])
}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}

// GetHashTypedData returns the EIP-712 digest for the bid.
// version must match the on-chain AUCTION_VERSION of the entry-point contract
// the bid targets; "0.0.2" selects the v3.0 struct typehash (with maxGasPrice),
// any other value falls back to the v2.1 typehash.
func (b *Bid) GetHashTypedData(chainId *big.Int, verifyingContract common.Address, version string) []byte {
	if chainId == nil {
		return nil
	}

	domain := EIP712Domain{
		EIP712DomainTypeHash: eip712TypeHash,
		NameHash:             auctionNameHash,
		VersionHash:          crypto.Keccak256Hash([]byte(version)),
		ChainId:              chainId,
		VerifyingContract:    verifyingContract,
	}

	domainSeparator := EncodeEIP712(domain)

	var structHash []byte
	if version == AuctionVersionV3 {
		structHash = EncodeEIP712(bidV3{b})
	} else if version == AuctionVersionV2 {
		structHash = EncodeEIP712(b)
	} else {
		// Unknown version: default to v2.1 typehash.
		structHash = EncodeEIP712(b)
	}

	return crypto.Keccak256([]byte{0x19, 0x01}, domainSeparator, structHash)
}

func (a *AuctionModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	bundles := []*builder.Bundle{}
	curBlock := a.Chain.CurrentBlock()
	if curBlock == nil || atomic.LoadUint32(&a.bidPool.running) == 0 {
		return bundles
	}

	miningBlock := curBlock.NumberU64() + 1
	bidTargetMap := a.bidPool.GetTargetTxMap(miningBlock)
	if len(bidTargetMap) == 0 {
		return bundles
	}

	for _, tx := range txs {
		txHash := tx.Hash()
		bid, ok := bidTargetMap[txHash]
		if !ok {
			continue
		}
		b := builder.NewBundle(
			builder.NewTxOrGenList(a.GetBidTxGenerator(tx, bid)),
			txHash,
			true,
		)
