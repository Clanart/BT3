## Analysis

The JoJo report's core bug-class is: **a call that can fail is invoked without checking/propagating its failure status, so the caller believes the operation succeeded while data was actually silently dropped/corrupted.**

The closest genuine analog in this Protobuf checkout is in `LazyFieldLite`, used by generated Java messages for lazily-parsed message-typed fields (including `MessageSet` extensions and extension fields marked lazy). This is reached through the ordinary public parse API (`MessageLite.Builder.mergeFrom(CodedInputStream, ExtensionRegistryLite)` → generated parsing code → `LazyFieldLite`), i.e. fully attacker-controlled bounded bytes.

### Title
Lazy-field parse failures are silently swallowed, causing corrupted/incomplete message data to be reported as successfully parsed - (File: `java/core/src/main/java/com/google/protobuf/LazyFieldLite.java`)

### Summary
`LazyFieldLite.ensureInitialized`, `mergeFrom(CodedInputStream, ExtensionRegistryLite)`, and the private helper `mergeValueAndBytes` all catch `InvalidProtocolBufferException` internally when lazily parsing attacker-supplied bytes for a message-typed field, and silently discard the exception, substituting the default instance (or the pre-merge value) instead of propagating the failure to the caller. ### Finding Description
Overall message parsing (`parseFrom`) succeeds and returns normally even though a nested lazily-parsed field never actually decoded correctly. In `ensureInitialized`, when `defaultInstance.getParserForType().parseFrom(delayedBytes, extensionRegistry)` throws `InvalidProtocolBufferException` because the attacker-controlled `delayedBytes` are malformed, the code catches it, sets `this.value = defaultInstance`, `this.memoizedBytes = ByteString.EMPTY`, and merely flips an internal `corrupted` boolean that is package-private (`isCorrupted()`) and not exposed through any public getter used by generated code paths that consume the value. [4](#0-3)  The same silent-catch pattern repeats in `mergeFrom(CodedInputStream, ExtensionRegistryLite)` (comment explicitly states "Nothing is logged and no exceptions are thrown. Clients will be unaware that a proto was invalid.") and in `mergeValueAndBytes`. [5](#0-4) [3](#0-2) 

This mirrors the JoJo pattern exactly: the "transfer" (here, the parse operation) can fail, the failure signal (`InvalidProtocolBufferException` / `corrupted` flag) exists but is not checked or surfaced by the calling code path (analogous to the unchecked `bool` return of `safeTransferFrom`), and the outer operation proceeds as if it had succeeded, silently substituting/losing data (analogous to crediting a balance despite a failed transfer).

### Impact Explanation
A crafted message containing an invalid nested submessage in a lazily-parsed extension/`MessageSet` field will parse "successfully" at the top level, but the nested field silently becomes an empty/default instance instead of raising `InvalidProtocolBufferException`. Application code that relies on `parseFrom` throwing on malformed input to reject bad data will not detect the corruption for this specific field, and will proceed to operate on a message that silently lost/altered content — a data-integrity issue reachable purely through the public binary parse API with attacker-controlled bytes.

### Likelihood Explanation
This is reachable by any attacker who can submit a serialized protobuf message to an application using generated Java (non-Lite generation `LazyField`, or Lite `MessageSet`/extension lazy fields) — no privileged access or schema control needed, only a bounded, malformed nested submessage within an otherwise well-formed outer message, which is a common/likely construction to attempt. The catch blocks are explicit and deliberate in production code (not test/mock code), increasing confidence this is a real, currently-present behavior rather than a hypothetical.

### Recommendation
- Do not swallow `InvalidProtocolBufferException` in `ensureInitialized`, `mergeFrom(CodedInputStream, ExtensionRegistryLite)`, and `mergeValueAndBytes`; either propagate the exception to the caller of the enclosing `parseFrom`/`mergeFrom`, or reliably surface the `corrupted` state through a public, checked API that callers are required to consult before trusting the field's value.
- At minimum, expose `isCorrupted()` publicly and document that its callers (generated message accessors) must check it, or fail the overall `parseFrom` when any lazy sub-field is corrupted, matching the "require(success)" fix pattern recommended in the source report.

### Proof of Concept
1. Construct a message type with a lazily-parsed message-typed extension field (e.g. a `MessageSet` extension) using the standard generated Java API.
2. Serialize an outer message where the extension's length-delimited bytes are valid protobuf-wire-format-wise (correct varint length) but decode to an internally malformed submessage (e.g. a nested required field violation or invalid UTF-8 in a string subfield, or truncated nested message bytes that still fit the outer length prefix).
3. Call `OuterMessage.parseFrom(bytes)` from application code — the call returns normally (no exception).
4. Access the corrupted lazy field via its generated getter: it will return the message's default instance rather than throwing, and there is no indicator to the caller that parsing failed, confirming the silent-failure/return-value-swallowing pattern at `LazyFieldLite.ensureInitialized` (lines 477–495) and `mergeFrom` (lines 356–366).

  /** Might lazily parse the bytes that were previously passed in. Is thread-safe. */
  protected void ensureInitialized(MessageLite defaultInstance) {
    if (value != null) {
      return;
    }
    synchronized (this) {
      if (value != null) {
        return;
      }
      try {
        if (delayedBytes != null) {
          // The extensionRegistry shouldn't be null here since we have delayedBytes.
          MessageLite parsedValue =
              defaultInstance.getParserForType().parseFrom(delayedBytes, extensionRegistry);
          this.value = parsedValue;
          this.memoizedBytes = delayedBytes;
        } else {
          this.value = defaultInstance;
          this.memoizedBytes = ByteString.EMPTY;
        }
      } catch (InvalidProtocolBufferException e) {
        // Nothing is logged and no exceptions are thrown. Clients will be unaware that this proto
        // was invalid.
        this.corrupted = true;
        this.value = defaultInstance;
        this.memoizedBytes = ByteString.EMPTY;
      }
    }
