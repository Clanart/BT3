and the duplicate-check and registration both read/write using that same raw string: [2](#0-1) [3](#0-2)

### Title
Pointer registry keys CW20/CW721/CW1155 pointers by un-normalized bech32 string, allowing duplicate ERC pointer contracts for the same underlying CosmWasm contract via case-variant addresses - (File: x/evm/keeper/pointer.go)

### Summary
The `AddCW20`/`AddCW721`/`AddCW1155` precompile handlers (and the `RegisterPointer`-adjacent CW→EVM keeper setters) validate the caller-supplied CosmWasm contract address by Bech32-decoding it (`sdk.AccAddressFromBech32`) purely to query the contract, but store and look up the pointer registration using the raw literal string the caller supplied, via `types.PointerERC20CW20Key`/`PointerERC721CW721Key`/`PointerERC1155CW1155Key`. This is the same bug class as CVE-2022-35924: the "canonical" identity used for authorization/uniqueness checks (the decoded address) differs from the raw value used to key state, permitting different textual encodings of the same underlying identity to bypass the "already registered" and pointer-to-pointer checks.

### Finding Description
`GetTokenDenom`-style bech32 decoding is case-insensitive per BIP-173: `sdk.AccAddressFromBech32` will happily decode both an all-lowercase and an all-uppercase encoding of the identical address bytes. The precompile pointer-registration flow: [4](#0-3) 

checks `GetERC20CW20Pointer(ctx, cwAddr)` for existence using the *raw* `cwAddr` string, decodes it only to call `QuerySmart`, and finally persists the pointer with `SetERC20CW20Pointer(ctx, cwAddr, contractAddr)` — again using the raw string. The underlying keeper store keys are built directly from that string with no normalization: [5](#0-4) [1](#0-0) 

Because two different-case representations of the same bech32 address decode to an identical `sdk.AccAddress`/CosmWasm contract but hash to different store keys, a caller can invoke `addCW20Pointer`/`addCW721Pointer` twice — once with the address in canonical case and once with an alternate valid case-encoding — and have both succeed, since `exists` is checked against the mismatched raw-string key each time. This same raw-string keying is also used by `cwAddressIsPointer` (the pointer-to-pointer guard) via `PointerReverseRegistryKey(common.BytesToAddress([]byte(addr)))`, which further weakens the "pointer of a pointer" protection for non-canonical inputs.

### Impact Explanation
A single underlying CW20/CW721/CW1155 contract could end up with two independently deployed ERC20/ERC721/ERC1155 pointer contracts registered against it. Wallets, DEX integrations, and pointer-aware precompiles (e.g. `precompiles/bank`'s `GetERC20NativePointer`/pointer-based `send`) rely on a 1:1 mapping between the CW contract and its EVM pointer to authorize transfers (`only pointer %s can send %s`) and to track balances/supply consistently. Divergent lookups (raw-string keyed forward mapping vs. reverse mapping) between different code paths that resolve "the" pointer for a given CW contract can allow inconsistent authorization decisions and split/duplicated on-chain representations of the same asset, which can be leveraged toward unauthorized transfer via pointer or asset accounting confusion — matching the impact class called out in the validation criteria (unauthorized transfer via precompile or pointer).

### Likelihood Explanation
Reachable by any unprivileged EVM contract deployer/caller through the standard `addr`/`pointer` precompile ABI (`AddCW20`/`AddCW721`/`AddCW1155`), requiring only knowledge of a target CW20/CW721/CW1155 contract's bech32 address and the ability to re-encode it in the alternate valid bech32 case — no special privileges, governance, or validator collusion needed.

### Recommendation
Normalize the CW address argument (e.g., decode via `sdk.AccAddressFromBech32` and re-encode with `.String()`, or otherwise canonicalize case) *before* using it to build any pointer registry key (`PointerERC20CW20Key`, `PointerERC721CW721Key`, `PointerERC1155CW1155Key`, `PointerReverseRegistryKey` lookups via `cwAddressIsPointer`) and before persisting the pointee value, ensuring the same canonical string is used across `exists` checks, `Set*Pointer`, and `Get*Pointer` in `x/evm/keeper/pointer.go` and all precompile versions under `precompiles/pointer/**`.

### Proof of Concept
1. Deploy/identify a CW20 contract at bech32 address `sei1xyzabc...` (lowercase canonical form).
2. Call the `addr`/`pointer` precompile's `AddCW20` with `cwAddr = "sei1xyzabc..."`. `GetERC20CW20Pointer` returns not-found, so an ERC20 pointer contract `P1` is created and registered under raw key `"sei1xyzabc..."`.
3. Re-encode the same address in uppercase bech32 form, `"SEI1XYZABC..."` (a value that still decodes via `sdk.AccAddressFromBech32` to the identical `AccAddress` since bech32 is case-insensitive).
4. Call `AddCW20` again with `cwAddr = "SEI1XYZABC..."`. Because `GetERC20CW20Pointer` looks up the raw-string key `"SEI1XYZABC..."`, which was never written, `exists` is `false`, and a second, independent ERC20 pointer contract `P2` is created and registered for the *same* underlying CW20 contract.
5. `P1` and `P2` now both claim to be "the" ERC20 pointer for the same CW20 asset, resolvable inconsistently depending on which raw string a caller/integration uses to query `GetERC20CW20Pointer`/`GetAnyPointerInfo`.

func (k *Keeper) SetERC20CW20PointerWithVersion(ctx sdk.Context, cw20Address string, addr common.Address, version uint16) error {
	if k.cwAddressIsPointer(ctx, cw20Address) {
		return ErrorPointerToPointerNotAllowed
	}
	err := k.setPointerInfo(ctx, types.PointerERC20CW20Key(cw20Address), addr[:], version)
	if err != nil {
		return err
	}
	return k.setPointerInfo(ctx, types.PointerReverseRegistryKey(addr), []byte(cw20Address), version)
}

func (k *Keeper) GetERC20CW20Pointer(ctx sdk.Context, cw20Address string) (addr common.Address, version uint16, exists bool) {
	addrBz, version, exists := k.GetPointerInfo(ctx, types.PointerERC20CW20Key(cw20Address), cw20.CurrentVersion(ctx))
	if exists {
		addr = common.BytesToAddress(addrBz)
	}
	return
}
