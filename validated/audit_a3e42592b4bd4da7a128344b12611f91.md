The analog to the FactoryDAO `getRewards()` bug lives in `EvmHost.recordEpoch` / `_epochs` on the Hyperbridge side, where the "unset" sentinel value collides with epoch `0`, a legitimate value, exactly as receipt `id == 0` collided with the default (unwritten) receipt struct in the original report.

### Title
`recordEpoch` treats the legitimate first authority-set epoch (`0`) as already-recorded, permanently blocking the epoch‑0 relayer's outbound consensus delivery reward - (`evm/src/core/EvmHost.sol`)

### Summary
`EvmHost._currentEpoch` defaults to `0`, the same value used as the id for the very first authority-set rotation epoch. `recordEpoch`'s staleness guard (`authoritySetId <= _currentEpoch`) can never distinguish "epoch 0 has already been recorded" from "no epoch has ever been recorded", so the first legitimate call to record epoch 0 is silently dropped and `_epochs[0]` is never written.

### Finding Description
`EvmHost` maintains `_currentEpoch` (initialized to `0` by default) and `_epochs[authoritySetId] => relayer` to track who first delivered the consensus proof that rotated to a given authority set: [1](#0-0) 

`recordEpoch` is the only writer of `_epochs`, and its guard is a `<=` comparison against `_currentEpoch`: [2](#0-1) 

`HandlerV2.handleConsensus` computes the epoch id as `nextAuthoritySetId - 1` and calls `recordEpoch(epoch, relayer)` only when a rotation occurs: [3](#0-2) 

The first rotation in the contract's lifetime produces `epoch == 0` (since `_currentEpoch` and `nextAuthoritySetId` both start unrotated). At that moment `recordEpoch(0, relayer)` is called, but the guard evaluates `0 <= _currentEpoch (0)` as `true`, so the function returns before writing anything — `_epochs[0]` stays at its default value, `address(0)`, identical to a slot that was simply never touched. This is confirmed directly in the test suite: [4](#0-3) 

The Hyperbridge-side reward claim (`process_outbound_consensus_delivery_claim`) reads exactly this slot via a state proof and treats a zero address as "not proven yet": [5](#0-4) [6](#0-5) 

This is structurally the same defect class as the FactoryDAO finding: a sequential/monotonic identifier's legitimate first value (`receiptId == 0` there, `authoritySetId/epoch == 0` here) is indistinguishable from the mapping's built-in zero-default "uninitialized" sentinel, so a guard written as `<=`/`==` against that sentinel silently swallows the very first legitimate entry.

### Impact Explanation
The relayer that delivers the very first authority-set rotation proof to any `EvmHost` deployment can never have that delivery attributed on-chain, and therefore can never successfully submit `claim_outbound_consensus_delivery_reward` for epoch `0` — `OutboundDeliveryNotProven` fires unconditionally for `set_id = 0` on every affected destination, since the slot the state proof reads is permanently zero. This is a permanent, protocol-level loss of a configured `OutboundConsensusDeliveryReward` for that relayer/epoch pair, on every `EvmHost` that has ever undergone or will undergo its first rotation. It also permanently desynchronizes `relayerOf(0)`, which is documented and consumed elsewhere as "the relayer that first submitted the consensus proof for the given epoch" — any downstream logic or off-chain tooling relying on that view sees a false "never delivered" state for epoch 0 forever.

### Likelihood Explanation
This triggers deterministically and unconditionally the first time any `EvmHost` instance rotates its authority set — no attacker action, malicious relayer, or adversarial input is needed; it is a pure logic defect in the staleness guard's initial-value collision. Every current and future `EvmHost` deployment is affected identically at epoch 0.

### Recommendation
Track "has an epoch ever been recorded" separately from the epoch value itself (e.g. an explicit `bool` flag, or initialize `_currentEpoch` to a sentinel like `type(uint256).max`/`-1` that cannot collide with a real epoch id), so the guard in `recordEpoch` can correctly accept `authoritySetId == 0` on the first call. Equivalently, change the comparison to distinguish "never set" from "set to 0" by checking `_epochs[authoritySetId] == address(0)` in combination with a monotonicity check that doesn't rely on the mutable `_currentEpoch` default coinciding with a valid id.

### Proof of Concept
1. Deploy a fresh `EvmHost`; `_currentEpoch == 0` by default and `_epochs[0] == address(0)` (unwritten).
2. `HandlerV2.handleConsensus` processes a consensus proof whose `nextAuthoritySetId == 1` (the chain's first rotation), computing `epoch = nextAuthoritySetId - 1 = 0`, and calls `host.recordEpoch(0, relayerAddress)`.
3. Inside `recordEpoch`, `authoritySetId (0) <= _currentEpoch (0)` evaluates `true`, so the function returns immediately; `_epochs[0]` remains `address(0)` and `_currentEpoch` remains `0` — exactly as asserted by the existing test `testHandleConsensusV2NoEpochChange`, whose comment mislabels this as "no rotation occurred" case even though `epoch=0` is a real first rotation in `testHandleConsensusV2RecordsRelayerOnEpochChange`'s numbering scheme.
4. `relayerAddress` submits `OutboundConsensusDeliveryClaim { set_id: 0, ... }` to `pallet-relayer::process_outbound_consensus_delivery_claim`.
5. The pallet's state proof of `_epochs[0]` on the destination `EvmHost` returns the zero address; `decode_epochs_slot_address` returns `None`, and the claim reverts with `OutboundDeliveryNotProven` — permanently, since `_epochs[0]` can never be written by any future call (all subsequent `recordEpoch` calls use strictly increasing epoch ids `> 0`).

    /**
     * @dev Record the relayer that first submitted a consensus proof for a new authority set epoch.
     * Only callable by the configured handler. Stale or duplicate epoch IDs are ignored.
     * @param authoritySetId the new authority set / epoch ID
     * @param relayer the relayer that delivered the consensus proof
     */
    function recordEpoch(uint256 authoritySetId, address relayer) external restrict(_hostParams.handler) {
        if (authoritySetId <= _currentEpoch) return;
        _currentEpoch = authoritySetId;
        _epochs[authoritySetId] = relayer;
        emit NewEpoch({authoritySetId: authoritySetId, relayer: relayer});
    }

	pub fn decode_epochs_slot_address(
		state_id: ismp::host::StateMachine,
		raw: &[u8],
	) -> Option<Address> {
		use alloy_rlp::Decodable;
		if let Ok(addr) = Address::decode(&mut &*raw) {
			return if addr == Address::ZERO { None } else { Some(addr) };
		}
		if crate::is_pharos(&state_id) && raw.len() == 32 {
			let addr = Address::from_slice(&raw[12..]);
			return if addr == Address::ZERO { None } else { Some(addr) };
		}
		None
	}
