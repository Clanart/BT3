### Title
Race between `consume_stop_state` and `restore_unreviewed_stop_state` lets a UPS re-baseline past an unreviewed dangerous change, permanently excluding it from review - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`restore_unreviewed_stop_state` only restores `baseline_sha` when the state's current `baseline_sha` is falsy (`if baseline_sha and not state.get("baseline_sha")`) [1](#0-0) . Because `consume_stop_state` clears `touched_paths` up front (before any slow network work) [2](#0-1) , a concurrent `UserPromptSubmit` (from a retried/next turn) can run in the gap between the clear and the eventual restore call, see an empty `touched_paths`, skip its own preservation guard, and unconditionally overwrite `baseline_sha` with a fresh `git stash create` snapshot that already bakes in the still‑uncommitted dangerous change [3](#0-2) . When the original Stop hook later calls `restore_unreviewed_stop_state`, it sees `state.get("baseline_sha")` already truthy and silently keeps the new (post‑change) baseline instead of restoring the pre‑change one, so the dangerous file's content is treated as part of the baseline and dropped from `changed_since` in `compute_v2_review_set`, permanently hiding it from the review window.

### Finding Description
The Stop hook flow is:
1. `handle_stop_hook` calls `consume_stop_state`, which atomically snapshots `touched_paths`/`baseline_sha` and clears `touched_paths` on disk under a short-lived `flock` [4](#0-3) .
2. If a transient condition occurs afterward — e.g. `ensure_anthropic_reachable()` returns False, which is directly attacker-influenceable by making outbound network calls fail — the hook calls `_skip(10, restore=True)`, which invokes `restore_unreviewed_stop_state(session_id, touched_paths, snap_baseline)` [5](#0-4) .
3. Between steps 1 and 2 there is an unlocked window (each `with_locked_state` call independently acquires/releases the lock; nothing holds the lock across the whole Stop-hook body) during which a new turn's `UserPromptSubmit` handler can run and take its own lock.
4. `handle_user_prompt_submit`'s preservation guard is `if state.get("touched_paths") and state.get("baseline_sha")` [6](#0-5) . Since `consume_stop_state` already cleared `touched_paths` to `[]`, this guard is false, so UPS proceeds to overwrite `baseline_sha` with a brand-new `git stash create` SHA — which snapshots the *current* working tree, including the still-uncommitted dangerous edit.
5. When `restore_unreviewed_stop_state` finally runs, `state.get("baseline_sha")` is now truthy (the new SHA from step 4), so the `if baseline_sha and not state.get("baseline_sha")` condition is false and the old, pre-change `snap_baseline` is discarded. `touched_paths` is restored (informational only — it is not consulted by `compute_v2_review_set`), but `baseline_sha` is not.
6. On the next Stop run, `compute_v2_review_set` computes `changed_since = _git_name_only(repo, baseline_sha)` against the new baseline [7](#0-6) . Because the dangerous file's content is byte-identical to what was captured in the new stash-created baseline, `git diff` reports no change for that file, so it is excluded from `changed_since`, and thus from `review_set = dirty_now & changed_since`, even though the file is still uncommitted/dirty relative to `HEAD`. The dangerous change is never surfaced to the LLM security review.

The docstring of `restore_unreviewed_stop_state` explicitly assumes the preservation guard in UPS stays armed because `touched_paths` is still populated ("the next UPS would see an empty list, fall through the preservation guard, and re-baseline past the unreviewed edits") — but that is precisely the state `consume_stop_state` leaves on disk, so the documented failure mode is not actually prevented by the restore, it merely narrows (but does not close) the window.

### Impact Explanation
This lets a dangerous, currently-uncommitted change (e.g., an added malicious shell command or backdoor edit) be permanently excluded from the git-diff-derived review window that gates the LLM security review and the Stop-hook approval/deny flow. Since the security-guidance plugin is the mechanism enforcing review of Claude-authored edits before they are treated as accepted, an attacker (or an adversarial prompt-injected agent turn) that can trigger this race effectively bypasses local command/code review, matching "Unauthorized local command execution that bypasses Claude Code approval or deny controls."

### Likelihood Explanation
Exploitability requires only ordinary repo/session operations: making a change, causing the Stop hook's LLM call to fail transiently (network unreachable / CCR/Haiku HTTP error — both are things a local process or network-adjacent actor can induce or that occur naturally), and having a next turn's `UserPromptSubmit` fire in the narrow but real window between `consume_stop_state`'s clear and `restore_unreviewed_stop_state`'s restore. Because `with_locked_state` only locks per-call rather than across the whole retry sequence, this window is real and not merely theoretical, though it is timing-dependent and may require several attempts to win reliably.

### Recommendation
Make `restore_unreviewed_stop_state` unconditionally restore the pre-turn `baseline_sha` (or compare using a monotonic "captured before this Stop's snapshot" marker) rather than gating on `not state.get("baseline_sha")`, and/or have `consume_stop_state` retain a sentinel that keeps UPS's preservation guard armed even after `touched_paths` is cleared (e.g., a separate `pending_review` flag cleared only after a successful Stop review, not after the optimistic snapshot).

### Proof of Concept
Integration test plan (pytest style) against `diffstate.py`/`security_reminder_hook.py`:
1. Set up a temp git repo with an initial commit.
2. Simulate turn 1: call `save_baseline_sha(session_id, sha_A)` and `record_touched_path(session_id, "danger.py")`; write a dangerous edit to `danger.py` (uncommitted).
3. Call `consume_stop_state(session_id)` — assert `touched_paths` is now `[]` on disk while `baseline_sha` is still `sha_A`.
4. Before calling `restore_unreviewed_stop_state`, simulate the racing UPS: call the UPS `_save` logic directly (or `handle_user_prompt_submit`) with the current cwd — assert it overwrites `baseline_sha` to a new SHA `sha_B` (via `capture_git_baseline`) because `touched_paths` was empty.
5. Now call `restore_unreviewed_stop_state(session_id, ["danger.py"], sha_A)` and assert `load_baseline_sha(session_id) == sha_B` (bug) instead of `sha_A` (expected).
6. Call `compute_v2_review_set(cwd, sha_B, ...)` and assert `"danger.py"` is **missing** from the returned review set — demonstrating the dangerous change is silently excluded from the next Stop hook's review, even though it remains uncommitted and was never actually reviewed.
7. Expected (fixed) behavior: after step 5, `load_baseline_sha` should return `sha_A`, and step 6's review set should still contain `danger.py`.

def consume_stop_state(session_id):
    """Atomically snapshot all state the Stop hook needs and clear touched_paths.

    The Stop hook is asyncRewake — it runs in the background after Claude's
    turn ends. The user can submit a new prompt before this hook finishes its
    initial state read. Telemetry showed a meaningful share of would-be reviews lost when
    the next turn's UPS wiped touched_paths before Stop read it.

    Single locked read-then-clear closes that window: PostToolUse appends
    after this clear go into the next snapshot; UPS overwrites of baseline_sha
    after this snapshot are invisible to this Stop fire.
    """
    import time as _time
    now = _time.time()

    def _snap(state):
        fire_ts = state.get("stop_hook_fire_count_ts", 0)
        expired = (now - fire_ts) > STOP_LOOP_STATE_TTL_SEC
        findings_ts = state.get("previous_findings_ts", fire_ts)
        findings_expired = (now - findings_ts) > PREVIOUS_FINDINGS_TTL_SEC
        snap = {
            "touched_paths": list(state.get("touched_paths", [])),
            "baseline_sha": state.get("baseline_sha"),
            "head_at_capture": state.get("head_at_capture"),
            "untracked_at_baseline": (
                dict(state["untracked_at_baseline"])
                if isinstance(state.get("untracked_at_baseline"), dict) else {}
            ),
            "fire_count": 0 if expired else state.get("stop_hook_fire_count", 0),
            "fire_count_expired": expired and state.get("stop_hook_fire_count", 0) > 0,
            "previous_findings": [] if findings_expired else list(state.get("previous_findings", [])),
        }
        state["touched_paths"] = []
        return snap

    return with_locked_state(session_id, _snap) or {
        "touched_paths": [], "baseline_sha": None, "head_at_capture": None,
        "untracked_at_baseline": {},
        "fire_count": 0, "fire_count_expired": False, "previous_findings": [],
    }

def restore_unreviewed_stop_state(session_id, paths, baseline_sha):
    """Put consumed touched_paths back so the next Stop reviews them.

    consume_stop_state cleared touched_paths on disk; if Stop then exits
    early for a transient reason (CCR API unreachable, Haiku HTTP error)
    the next UPS would see an empty list, fall through the preservation
    guard, and re-baseline past the unreviewed edits. Restoring keeps the
    guard armed. Prepend+dedupe so any concurrent next-turn PostToolUse
    appends survive.
    """
    if not paths:
        return

    def _restore(state):
        existing = state.get("touched_paths", [])
        merged = list(dict.fromkeys(list(paths) + list(existing)))
        if len(merged) > 200:
            merged = merged[:200]
        state["touched_paths"] = merged
        if baseline_sha and not state.get("baseline_sha"):
            state["baseline_sha"] = baseline_sha
    with_locked_state(session_id, _restore)
