### Title
Immature coinbase outputs are reported as spendable, causing transaction failure and temporary fund lockup - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
`Scanner::scan_block` scans every transaction in `block.txdata`, including `block.txdata[0]`, the coinbase transaction. [1](#0-0)  Any scanner-controlled output created by that coinbase is returned as an ordinary `ReceivedOutput`, even though Bitcoin consensus prevents coinbase outputs from being spent until they are 100 blocks old. [2](#0-1)  `SignableTransaction::new` then accepts that `ReceivedOutput` without checking whether its outpoint belongs to an immature coinbase. [3](#0-2) 

### Finding Description
`ReceivedOutput` contains only an offset, output, and outpoint, with no maturity marker or block-height context. [2](#0-1)  `Scanner::scan_block` explicitly includes the coinbase transaction when constructing these spendable-looking outputs. [1](#0-0)  The transaction builder treats every supplied `ReceivedOutput` as immediately spendable, converts it directly into a `TxIn`, and never inspects coinbase maturity. [4](#0-3) 

A caller following the public wallet flow can therefore scan a block, receive a coinbase output, build a transaction spending it, and successfully produce signatures through `TransactionMachine::complete`. [5](#0-4)  Broadcast nevertheless fails when the node applies Bitcoin’s premature-coinbase-spend consensus rule. [6](#0-5) 

### Impact Explanation
The wallet reports funds as received and spendable when they cannot actually be spent until maturity. [7](#0-6)  The resulting transaction is signed but rejected at publication, so the payment operation fails and the selected funds remain unusable until the coinbase reaches maturity. [6](#0-5)  In an automated signer, this can repeatedly consume threshold-signing attempts and delay payouts unless the implementation separately tracks maturity.

### Likelihood Explanation
This requires a coinbase transaction to pay directly to a script registered in the scanner. That is less common than an ordinary external payment, but it is reachable by a miner or mining pool paying a Serai-controlled Taproot script. Once such a block is scanned, no malformed input or trusted-node misbehavior is needed: the normal `scan_block` → `SignableTransaction::new` → signing → `send_raw_transaction` path reaches the failure. [8](#0-7) [6](#0-5) 

### Recommendation
Record whether a `ReceivedOutput` originates from a coinbase transaction and the block height at which it was discovered. Prevent `SignableTransaction::new` from accepting immature coinbase outputs, or expose a maturity-aware scan API that withholds them until they have 100 confirmations. The existing warning requiring post-processing should be enforced by construction rather than left to callers. [9](#0-8)

```rust
// 1. A miner creates a block whose coinbase pays:
//    p2tr_script_buf(wallet_key).unwrap().
let block: Block = mined_block_with_coinbase_payment_to(wallet_key);

// 2. The public scanner path returns the coinbase output immediately.
let scanner = Scanner::new(wallet_key).unwrap();
let received = scanner.scan_block(&block);
assert_eq!(received.len(), 1);
assert_eq!(received[0].outpoint().vout, coinbase_vout);

// 3. The wallet API exposes no maturity flag, so callers naturally treat
//    this ReceivedOutput as spendable.
let tx = SignableTransaction::new(
    received,
    &[(destination_script, payment_amount)],
    Some(change_script),
    None,
    fee_per_vbyte,
).unwrap();

// 4. Signing succeeds because the output is controlled by the threshold key.
let signed_tx = complete_threshold_signing(tx, &keys);

// 5. Publication fails consensus validation while the coinbase has fewer
//    than 100 confirmations:
//    bad-txns-premature-spend-of-coinbase.
assert!(rpc.send_raw_transaction(&signed_tx).await.is_err());
```

The failing state is created entirely by the scanner: `scan_block` includes `block.txdata[0]`, while the downstream transaction builder has no information with which to reject the immature outpoint. [8](#0-7) [4](#0-3)

```rust
  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
```

```rust
  pub async fn send_raw_transaction(&self, tx: &Transaction) -> Result<Txid, RpcError> {
    let txid = match self.rpc_call("sendrawtransaction", json!([encode::serialize_hex(tx)])).await {
      Ok(txid) => txid,
      Err(e) => {
        // A const from Bitcoin's bitcoin/src/rpc/protocol.h
        const RPC_VERIFY_ALREADY_IN_CHAIN: isize = -27;
        // If this was already successfully published, consider this having succeeded
        if let RpcError::RequestError(Error { code, .. }) = e {
          if code == RPC_VERIFY_ALREADY_IN_CHAIN {
            return Ok(tx.compute_txid());
          }
        }
        Err(e)?
      }
    };
    if txid != tx.compute_txid() {
      Err(RpcError::InvalidResponse("returned TX ID inequals calculated TX ID"))?;
    }
    Ok(txid)
```
