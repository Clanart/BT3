### Title
Unauthenticated `OP_RETURN` payer attribution in payout transactions lets anyone credit an arbitrary operator with a withdrawal it never funded - (File: core/src/verifier.rs, core/src/builder/transaction/operator_reimburse.rs)

### Summary
The identity of the operator that is credited for fronting a withdrawal ("payer") is derived solely from an unsigned `OP_RETURN` output in the confirmed payout transaction. Because the user's withdrawal authorization uses `SIGHASH_SINGLE | SIGHASH_ANYONECANPAY`, that signature only commits to input #0 and output #0 of the payout transaction — it does not cover the `OP_RETURN` output that names the paying operator. Anyone who can see a broadcast/mempool payout transaction (or otherwise obtains the withdrawal signature) can therefore build their own competing transaction that spends the same user-authorized withdrawal UTXO, fund it with their own money, and stamp an arbitrary operator's x-only public key into the `OP_RETURN` output. If this transaction confirms, the bridge's verifier logic records that named operator as the "payer" in the database, and that operator's own automation will subsequently claim on-chain reimbursement from the N-of-N bridge funds for a withdrawal it never paid.

### Finding Description
`create_payout_txhandler` builds the payout transaction with:
- Input #0: user's withdrawal UTXO, spent with `SpendPath::KeySpend` using the user's pre-signed schnorr signature (`SinglePlusAnyoneCanPay` sighash type, enforced in `operator.rs`).
- Output #0: user payout output.
- Output #1: anchor output.
- Output #2: `OP_RETURN` output containing the operator's x-only public key claiming credit for the payout. [1](#0-0) 

Because the sighash type is `SIGHASH_SINGLE | SIGHASH_ANYONECANPAY`, the user's signature commits only to input #0 and the output at the same index (#0). Outputs #1 (anchor) and #2 (`OP_RETURN` payer attribution) are **not covered** by any signature, and additional funding inputs can be freely appended by anyone (that is the entire purpose of `ANYONECANPAY`). This is confirmed by the verification call in the operator's own `withdraw` flow, which explicitly requires `SinglePlusAnyoneCanPay`: [2](#0-1) 

The verifier's block-sync logic then trusts this unauthenticated `OP_RETURN` value as the ground truth for "who paid": [3](#0-2) 

This value is persisted as `payout_payer_operator_xonly_pk` with no further validation that the named operator actually funded or signed any part of the transaction: [4](#0-3) 

Each operator's own automated `PayoutCheckerTask` polls this same field, filtering only by "is this xonly_pk equal to mine", and if so, unconditionally proceeds to kick off the reimbursement flow: [5](#0-4) 

The operator-side gate before sending reimbursement transactions, `validate_payer_is_operator`, likewise only compares the DB-stored (attacker-controllable) `payer_xonly_pk` against `self.signer.xonly_public_key` — it never checks that the operator's own funds or signature appear anywhere in the confirmed payout transaction: [6](#0-5) 

### Impact Explanation
This breaks the binding "the operator credited versus the party that paid." An unprivileged party (not a registered operator, verifier, or aggregator) can:
1. Observe a pending/broadcast payout transaction for a withdrawal (the schnorr signature over input #0/output #0 becomes public once it appears in a transaction anywhere, e.g. mempool), or otherwise obtain it.
2. Construct a new transaction reusing the same signed input and output #0, funding all additional inputs from their own wallet, and set the `OP_RETURN` output to an arbitrary, real operator's x-only public key.
3. Get this transaction confirmed instead of (or in addition to, via replacement) the legitimate operator's own payout.

Once confirmed, the framed operator's `PayoutCheckerTask` will treat the withdrawal as one it fronted and automatically drive it through the round/kickoff/reimburse flow, claiming bridge funds it never spent. This matches the Critical impact category "an operator reimbursed for a payout it never funded," and can also be leveraged to deny the legitimate operator (who actually intended to front the withdrawal) its rightful, deterministic reimbursement slot, since `is_payout_handled`/`payout_payer_operator_xonly_pk` is a single value per withdrawal.

### Likelihood Explanation
No privileged role, key compromise, or majority hashrate is required — only the ability to observe a payout transaction's signed input (which is inherently public once it hits any node's mempool) and enough BTC to fund a competing transaction with a higher fee to win the race to confirmation. The `ANYONECANPAY` sighash flag was seemingly chosen to allow flexible RBF fee-bumping by the operator, but it also incidentally leaves the `OP_RETURN` attribution output completely unauthenticated.

### Recommendation
Bind the payer attribution to the actual signer/funder of the transaction rather than to unsigned transaction data. Options include:
- Requiring the operator to sign a commitment (e.g., an additional taproot input/output or an auxiliary signature) that cryptographically proves control of the `OP_RETURN` pubkey, rather than trusting arbitrary embedded data.
- Changing the sighash type so the operator's-identity output is covered by an operator-controlled signature (e.g. requiring the operator's own input to be present and covered under `SIGHASH_ALL`/`SIGHASH_DEFAULT` for at least the identity-bearing output).
- Cross-checking on-chain that the additional funding inputs of the payout transaction actually originate from the claimed operator's known wallet/collateral before honoring the `payer_xonly_pk` value for reimbursement purposes.

### Proof of Concept
1. Watcher observes a withdrawal payout transaction template signed by the user with `SIGHASH_SINGLE | SIGHASH_ANYONECANPAY` (visible once any operator broadcasts it, or is otherwise leaked, since only input #0 + output #0 are committed).
2. Attacker assembles a new transaction: input #0 = same signed user input; output #0 = same user payout (matches the sighash commitment); output #1 = arbitrary anchor amount; output #2 = `OP_RETURN` containing operator X's public x-only key (a real, unrelated operator). Attacker adds their own UTXO(s) as additional inputs (permitted by `ANYONECANPAY`) to cover fees/amount and signs those inputs themselves.
3. Attacker broadcasts this transaction with a competitive fee so it confirms.
4. `update_finalized_payouts` in `core/src/verifier.rs` parses the `OP_RETURN`, stores `payer_xonly_pk = operator X`.
5. Operator X's `PayoutCheckerTask` (`core/src/task/payout_checker.rs`) picks up the "unhandled payout" for its own key and proceeds through `handle_finalized_payout` → round/kickoff/reimburse, obtaining bridge reimbursement for a withdrawal operator X never funded.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
