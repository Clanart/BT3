### Title
Missing Timestamp Freshness Validation in App Proxy Request Verification Permits Indefinite Replay of Signed Requests - (File: `lib/shopify_app/controller_concerns/app_proxy_verification.rb`)

### Summary
`ShopifyApp::AppProxyVerification#query_string_valid?` verifies only the HMAC signature over the app-proxy query string; it never checks that the `timestamp` parameter included in that same query string is recent. This is analogous to the reported class of bug (trusting an external signal — an oracle price or, here, a signed request — without validating its liveness/freshness), where the code accepts data solely because a cryptographic check passed, without ensuring the data is still valid/current.

### Finding Description
The `AppProxyVerification` concern is used by controllers that accept requests forwarded by Shopify's App Proxy feature. It computes an HMAC over the sorted query parameters (which includes `timestamp`) and accepts the request purely if the signature matches: [1](#0-0) 

`timestamp` is treated only as one more signed field, never compared against the current server time or any freshness window. As a result, any request that was ever validly signed by Shopify (e.g., recorded from network logs, browser history, proxy/CDN logs, or accidentally leaked referrer headers) remains permanently "valid" and will be accepted by `verify_proxy_request` no matter how old it is: [2](#0-1) 

This mirrors the reported bug class: a security-relevant decision (accept signed data / act on it) is made without checking the "health"/freshness of the underlying signal, only its cryptographic integrity.

### Impact Explanation
An attacker who captures a previously valid, signed app-proxy query string (via logs, shared links, browser history, or a leaked URL) can replay it against the app-proxy endpoint indefinitely. Since app proxy requests carry `shop` and other request-controlling parameters that server-side app logic typically trusts (similarly to how the SubstanceUSD oracle output was trusted without a liveness check), this allows a form of accepted forged/stale signed request to reach app logic (e.g., re-triggering embedded merchant-facing pages/actions gated by the app-proxy signature) after it should no longer be valid to do so.

### Likelihood Explanation
Exploitation requires possession of a previously valid signed app-proxy request. This is realistic in practice: app-proxy URLs are exposed in the storefront (as full URLs with query strings, including `signature` and `timestamp`), can be crawled, cached by browsers/CDNs, or shared, and there is no code path in `shopify_app` that rejects them once they age out. The as-shipped gem provides no configuration option to enable a freshness check, so every app built on this concern inherits the gap.

### Recommendation
In `query_string_valid?` (or `verify_proxy_request`), after confirming the signature, parse the `timestamp` parameter and reject requests whose timestamp is outside an acceptable window (e.g., a few minutes), similar to replay-protection windows used elsewhere in signed-request verification schemes.

### Proof of Concept
1. Capture any valid app-proxy request URL served through a controller including `ShopifyApp::AppProxyVerification` (e.g., from a shared link, browser cache, or proxy log), containing `shop`, `path_prefix`, `timestamp`, and `signature` params.
2. Wait arbitrarily long after the original request's `timestamp`.
3. Replay the exact same query string against the app's app-proxy route.
4. Observe `verify_proxy_request` (`lib/shopify_app/controller_concerns/app_proxy_verification.rb:11-13`) still returns success and the request reaches the controller action, because `query_string_valid?` only checks the HMAC and never validates `timestamp` against current time — confirmed by the existing test suite, which asserts old, fixed timestamps (`"1466106083"`, from 2016) as still `valid?` with no age check: [3](#0-2)

```ruby
    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end

    def calculated_signature(query_hash_without_signature)
      sorted_params = query_hash_without_signature.collect { |k, v| "#{k}=#{Array(v).join(",")}" }.sort.join

      OpenSSL::HMAC.hexdigest(
        OpenSSL::Digest.new("sha256"),
        ShopifyApp.configuration.secret,
        sorted_params,
      )
    end
```
