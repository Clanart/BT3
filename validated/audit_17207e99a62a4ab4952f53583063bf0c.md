### Title
`ReceivedOutput::read` accepts untrusted bytes without binding `offset` to the output's `script_pubkey`, while `Scanner`/`multisig` enforce that binding — (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The bug class from the external report — the same externally supplied value is validated against a threshold/consistency check in one code path but consumed unchecked in sibling paths — maps onto `ReceivedOutput` in `networks/bitcoin`. `Scanner::scan_transaction` only produces a `ReceivedOutput` whose `offset` was registered against the exact `script_pubkey` (networks/bitcoin/src/wallet/mod.rs:205-211), and `SignableTransaction::multisig` re-verifies `p2tr_script_buf(offset.group_key()) == prevouts[i].script_pubkey` before constructing a signer (networks/bitcoin/src/wallet/send.rs:276-281). `ReceivedOutput::read`, however, deserializes `offset`, `output`, and `outpoint` from untrusted bytes with no check that the offset actually derives the key that locks the output (networks/bitcoin/src/wallet/mod.rs:122-134).

### Finding Description
`Scanner` maintains `scripts: HashMap<ScriptBuf, Scalar>` where every entry is inserted via `register_offset`, which only registers offsets for which `p2tr_script_buf(self.key + GENERATOR * offset)` yields a Some script (mod.rs:180-196). Scanning therefore guarantees `offset` is the discrete-log offset turning the group key into the key behind `output.script_pubkey`. `ReceivedOutput::read` reads a scalar via `Secp256k1::read_F`, a `TxOut`, and an `OutPoint` and returns the struct directly — no ownership of `self.key`, no consistency check, and no marker distinguishing scanner-produced outputs from attacker-crafted ones (mod.rs:122-134). An unprivileged party that can feed bytes to `ReceivedOutput::read` (a listed untrusted-input sink) can attach an arbitrary `offset` to any `TxOut`/`OutPoint`, including an output paying to a script the wallet does not control, or a real wallet output paired with a wrong offset.

### Impact Explanation
A deserialized `ReceivedOutput` is treated by downstream code as a spendable coin: `SignableTransaction::new` sums `input.output.value` as available funds (send.rs:175) and builds a transaction over it. When `multisig` is invoked, the offset mismatch causes `p2tr_script_buf(...) != script_pubkey`, returning `None` (send.rs:277-278) — the funds the wallet reported as received are not spendable through the signing path, matching the "funds reported received that are not spendable" acceptance criterion. Worse, an attacker can claim a `ReceivedOutput` for an `outpoint`/`TxOut` they do not own at all (the outpoint field is arbitrary consensus-decoded data); the wallet would account value for a UTXO it cannot spend, corrupting balance/fee accounting (`input_sat` drives change and `needed_fee` computation, send.rs:223-234).

### Likelihood Explanation
Reachability requires the integrator to deserialize `ReceivedOutput` from attacker-influenced storage or transport — plausible for any persistence/gossip of scanned outputs, since `read`/`serialize` are the exposed wire format. The missing check costs nothing to an attacker (any 32-byte scalar plus arbitrary consensus-encoded `TxOut`/`OutPoint` parses successfully). The failure only manifests at spend time, so inconsistent records can accumulate silently. Medium severity: no key leakage, but concrete misreporting of unspendable funds from untrusted input.

### Recommendation
Bind `offset` to `output.script_pubkey` at deserialization or construction. Since `ReceivedOutput::read` lacks the wallet key, either (a) give `read` a `&Scanner`/key parameter and verify `p2tr_script_buf(key + GENERATOR * offset) == Some(output.script_pubkey)`, or (b) remove the public `read`/`write` round-trip trust boundary and have callers re-validate via `Scanner` (e.g., re-scan or consult `scripts` map) before treating a deserialized `ReceivedOutput` as spendable.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  pub fn multisig(self, keys: &ThresholdKeys<Secp256k1>) -> Option<TransactionMachine> {
    let mut sigs = vec![];
    for i in 0 .. self.tx.input.len() {
      let offset = keys.clone().offset(self.offsets[i]);
      if p2tr_script_buf(offset.group_key())? != self.prevouts[i].script_pubkey {
        None?;
      }

      sigs.push(AlgorithmMachine::new(Schnorr::new(), keys.clone().offset(self.offsets[i])));
    }

    Some(TransactionMachine { tx: self, sigs })
  }
