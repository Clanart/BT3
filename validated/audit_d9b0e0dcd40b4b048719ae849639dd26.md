### Title
`CW721ERC721Pointer` does not override `safeTransferFrom()`, causing it to fall back to OpenZeppelin's default implementation that mutates local `ERC721` storage instead of executing the real `transfer_nft` on the backing CW721 contract - ([File: contracts/src/CW721ERC721Pointer.sol])

### Summary
`CW721ERC721Pointer` extends OpenZeppelin's `ERC721` and overrides `ownerOf`, `balanceOf`, `getApproved`, `isApprovedForAll`, `transferFrom`, `approve`, and `setApprovalForAll` to proxy all state to the underlying CosmWasm CW721 contract via the `WasmdPrecompile`. However, it does **not** override `safeTransferFrom(address,address,uint256)` or `safeTransferFrom(address,address,uint256,bytes)`. [1](#0-0) [2](#0-1) 

### Finding Description
The bug-class from the external report (misuse of `transferFrom`/`safeTransferFrom` on ERC721 leading to asset issues) maps here to the inverse and more severe problem: `CW721ERC721Pointer` overrides `transferFrom()` to route the request through the `WasmdPrecompile` to the real CW721 contract's `transfer_nft` message, but leaves the inherited OpenZeppelin `safeTransferFrom()` variants untouched. OpenZeppelin's default `safeTransferFrom` internally calls `_safeTransfer` → `_transfer`, which reads/writes the base contract's own `_owners`/`_balances` storage (via `ERC721.ownerOf(tokenId)`, a base-qualified, non-virtual call) rather than going through the pointer's overridden `ownerOf()`/`getApproved()` that query the real CW721 state. Since the pointer never populates `_owners` (its custom `transferFrom` never calls the base `_transfer`/`_mint`), calling `safeTransferFrom()` on the pointer either reverts unexpectedly (breaking a standard, widely-used ERC721 entry point that most NFT marketplaces and wallets call by default) or, if the internal state happens to be inconsistent, can silently manipulate `_owners`/`_balances` without ever invoking `transfer_nft` on the backing CW721 contract-meaning the emitted `Transfer` event and any success return do not correspond to unauthorized transfer via precompile or pointer any actual change in NFT ownership on the CW721 side. [3](#0-2) [4](#0-3) 

### Impact Explanation
`CW721ERC721Pointer` is the canonical EVM representation of a CW721 NFT and is expected by any EVM client, marketplace, or wallet to conform fully to ERC721, where `safeTransferFrom` is the recommended/primary transfer method. If callers use `safeTransferFrom` (as recommended by the very bug class cited in the report) instead of `transferFrom`, transfers either unexpectedly fail (denial of transfer functionality for a standard-conforming path) or can desynchronize the pointer's local bookkeeping from the true CW721 ownership recorded in the Cosmos module, producing incorrect `Transfer` events/state that downstream integrators (marketplaces, custodians) rely on for settlement - a mismatch between the pointer's reported state and actual ownership on the underlying CW721 store.

### Likelihood Explanation
High: `safeTransferFrom` is the standard, widely recommended ERC721 transfer function (this is precisely the function that auditors and integrators are instructed to prefer over `transferFrom`, per the very bug-class cited). Any wallet, marketplace, or third-party integration built against the ERC721 standard that calls `safeTransferFrom` on a Sei CW721↔ERC721 pointer contract will hit this codepath without any special conditions or privileges required beyond owning/being approved for the NFT.

### Recommendation
Override both `safeTransferFrom(address,address,uint256)` and `safeTransferFrom(address,address,uint256,bytes)` in `CW721ERC721Pointer` to route through `_execute`/`WasmdPrecompile` (mirroring the existing `transferFrom` override) and perform the ERC721 receiver check (`onERC721Received`) against the destination `to`, rather than relying on OpenZeppelin's inherited implementation which operates on the pointer's disconnected local storage.

### Proof of Concept
1. Deploy a `CW721ERC721Pointer` for an existing CW721 collection and let account `A` own `tokenId = 1` (verified via `ownerOf(1)` which queries the real CW721 contract). [5](#0-4) 
2. From account `A`, call `pointer.safeTransferFrom(A, B, 1)` instead of `pointer.transferFrom(A, B, 1)`.
3. Because `safeTransferFrom` is not overridden, execution proceeds through the inherited OpenZeppelin logic, which checks/mutates the base `_owners`/`_balances` mappings (never populated by the pointer's custom logic) instead of calling `_execute` against `WasmdPrecompile` with a `transfer_nft` message as `transferFrom` does. [6](#0-5) 
4. Observe that either the call reverts (e.g., "ERC721: transfer from incorrect owner") even though `A` is the legitimate CW721 owner, or - depending on prior state - the transaction succeeds and emits a `Transfer` event while `ownerOf(1)` (querying the real CW721 contract) still reports `A` as owner, demonstrating the pointer's ERC721 interface is not safely/correctly transfer-complete for the standard `safeTransferFrom` entry points.

    function ownerOf(uint256 tokenId) public view override returns (address) {
        string memory tId = _formatPayload("token_id", _doubleQuotes(Strings.toString(tokenId)));
        string memory req = _curlyBrace(_formatPayload("owner_of", _curlyBrace(tId)));
        bytes memory response = WasmdPrecompile.query(Cw721Address, bytes(req));
        bytes memory owner_ = JsonPrecompile.extractAsBytes(response, "owner");
        return AddrPrecompile.getEvmAddr(string(owner_));
    }

    function getApproved(uint256 tokenId) public view override returns (address) {
        string memory tId = _formatPayload("token_id", _doubleQuotes(Strings.toString(tokenId)));
        string memory req = _curlyBrace(_formatPayload("approvals", _curlyBrace(tId)));
        bytes memory response = WasmdPrecompile.query(Cw721Address, bytes(req));
        bytes[] memory approvals = JsonPrecompile.extractAsBytesList(response, "approvals");
        if (approvals.length > 0) {
            bytes memory res = JsonPrecompile.extractAsBytes(approvals[0], "spender");
            return AddrPrecompile.getEvmAddr(string(res));
        }
        return address(0);
    }

    function transferFrom(address from, address to, uint256 tokenId) public override {
        if (to == address(0)) {
            revert ERC721InvalidReceiver(address(0));
        }
        require(from == ownerOf(tokenId), "`from` must be the owner");
        string memory recipient = _formatPayload("recipient", _doubleQuotes(AddrPrecompile.getSeiAddr(to)));
        string memory tId = _formatPayload("token_id", _doubleQuotes(Strings.toString(tokenId)));
        string memory req = _curlyBrace(_formatPayload("transfer_nft", _curlyBrace(_join(recipient, tId, ","))));
        _execute(bytes(req));
    }

    function approve(address approved, uint256 tokenId) public override {
        string memory spender = _formatPayload("spender", _doubleQuotes(AddrPrecompile.getSeiAddr(approved)));
        string memory tId = _formatPayload("token_id", _doubleQuotes(Strings.toString(tokenId)));
        string memory req = _curlyBrace(_formatPayload("approve", _curlyBrace(_join(spender, tId, ","))));
        _execute(bytes(req));
    }

    function setApprovalForAll(address operator, bool approved) public override {
        string memory op = _curlyBrace(_formatPayload("operator", _doubleQuotes(AddrPrecompile.getSeiAddr(operator))));
        if (approved) {
            _execute(bytes(_curlyBrace(_formatPayload("approve_all", op))));
        } else {
            _execute(bytes(_curlyBrace(_formatPayload("revoke_all", op))));
        }
    }
