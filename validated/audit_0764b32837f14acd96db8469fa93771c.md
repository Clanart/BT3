### Title
Transaction-level InInstruction data and presumed_origin are applied to every scanned output, letting a co-spender hijack other depositors' funds - (File: processor/src/networks/bitcoin.rs)

### Summary
`Bitcoin::get_outputs` scans each non-coinbase transaction for outputs paying the multisig, then computes a single `presumed_origin` (from `tx.input[0]`) and a single `data` blob (from `extract_serai_data`) for the *whole transaction*, and stamps them onto **every** output of that transaction that matched the scanner — regardless of which output the depositor intended the instruction for. In a multi-party transaction (CoinJoin, batched deposits, any tx where an unprivileged attacker co-authors a transaction that also pays Serai's external address), the attacker's embedded `InInstruction` data and their controlled `tx.input[0]` origin are attributed to the victim's deposit.

### Finding Description [1](#0-0) 

`get_outputs` collects all `scanner.scan_transaction(tx)` matches into `outputs`. If any output matched, it derives `presumed_origin` from `tx.input[0]`'s spent output `script_pubkey` and `data = Self::extract_serai_data(tx)`, then loops over *all* outputs assigning `output.data` (for `OutputType::External`) and `output.presumed_origin`.

`extract_serai_data` returns attacker-influenceable bytes: it takes the last push of the first OP_RETURN output found (not restricted to the last output per spec `spec/integrations/Bitcoin.md`), or `witness[len-2]` of any input whose witness script matches the `OP_SHA256 <hash> OP_EQUALVERIFY` pattern — without verifying that the pushed hash equals `SHA256` of the extracted message. [2](#0-1) 

Downstream, `instruction_from_output` decodes that data into a `RefundableInInstruction` and pairs it with the output's full balance (`balance.amount.0 -= 2 * N::COST_TO_AGGREGATE`), preferring the instruction's explicit `origin` else `presumed_origin` for refunds. [3](#0-2) 

The bug class (stored attacker input later interpreted in a trusted context) maps directly: the OP_RETURN/witness payload is stored on-chain by the attacker and later interpreted by the processor as an authenticated instruction bound to coins the attacker did not deposit.

### Impact Explanation
In a shared transaction containing the attacker's input and both the attacker's and a victim's payments to Serai's external address:

- The attacker's `Shorthand`/`RefundableInInstruction` (e.g. `Transfer` to an attacker Serai address, or `Dex` call) is attached to the victim's `External` output, so the victim's deposited balance mints/executes for the attacker's benefit.
- If the instruction fails, `presumed_origin` (attackers can make `tx.input[0]` theirs) is used as the refund target, so the victim's coins are refunded to the attacker.

Either path lets an unprivileged Bitcoin user cause victim deposits to be credited/spent under attacker-chosen instructions or refunded to an attacker address — theft of deposited funds' utility.

### Likelihood Explanation
Requires the victim's deposit and the attacker's crafted data to live in the same confirmed transaction. This occurs naturally with coinjoins, exchange/batching services that sweep multiple users' deposits into one transaction, or any service constructing a tx with multiple pay-to-Serai outputs plus an OP_RETURN. The attacker needs only to be a participant able to add an OP_RETURN output or a qualifying witness input — low cost, no consensus involvement.

### Recommendation
Bind instruction data and origin to a specific output rather than the whole transaction: e.g., only attach `data` when the OP_RETURN/output ordering unambiguously identifies which deposit it belongs to (per spec, the transaction's *last* output), or require one external output per tx for instruction-bearing transactions and skip/refund-only otherwise. Verify the `OP_SHA256` hash commitment in `segwit_data_pattern` before trusting `witness[len-2]`. Consider only accepting `presumed_origin` from inputs proven to fund the specific matched output.

### Proof of Concept
1. Victim service constructs a batched deposit tx with inputs from several users, outputs `A` (victim → Serai external address) and `B` (attacker → Serai external address).
2. Attacker adds `tx.input[0]` from their own address and an OP_RETURN output containing `Shorthand::Raw(RefundableInInstruction { origin: None, instruction: InInstruction::Transfer(attacker_serai_addr) })`.
3. After `CONFIRMATIONS`, `get_outputs` returns both outputs with identical `data` and `presumed_origin` (attacker's address).
4. `instruction_from_output` turns both into `InInstructionWithBalance` crediting `attacker_serai_addr` for the sum of both deposits; on failure the refund goes to the attacker's `presumed_origin`.

  fn extract_serai_data(tx: &Transaction) -> Vec<u8> {
    // check outputs
    let mut data = (|| {
      for output in &tx.output {
        if output.script_pubkey.is_op_return() {
          match output.script_pubkey.instructions_minimal().last() {
            Some(Ok(Instruction::PushBytes(data))) => return data.as_bytes().to_vec(),
            _ => continue,
          }
        }
      }
      vec![]
    })();

    // check inputs
    if data.is_empty() {
      for input in &tx.input {
        let witness = input.witness.to_vec();
        // expected witness at least has to have 2 items, msg and the redeem script.
        if witness.len() >= 2 {
          let redeem_script = ScriptBuf::from_bytes(witness.last().unwrap().clone());
          if Self::segwit_data_pattern(&redeem_script) == Some(true) {
            data.clone_from(&witness[witness.len() - 2]); // len() - 1 is the redeem_script
            break;
          }
        }
      }
    }

    data.truncate(MAX_DATA_LEN.try_into().unwrap());
    data
  }

  async fn get_outputs(&self, block: &Self::Block, key: ProjectivePoint) -> Vec<Output> {
    let (scanner, _, kinds) = scanner(key);

    let mut outputs = vec![];
    // Skip the coinbase transaction which is burdened by maturity
    for tx in &block.txdata[1 ..] {
      for output in scanner.scan_transaction(tx) {
        let offset_repr = output.offset().to_repr();
        let offset_repr_ref: &[u8] = offset_repr.as_ref();
        let kind = kinds[offset_repr_ref];

        let output = Output { kind, presumed_origin: None, output, data: vec![] };
        assert_eq!(output.tx_id(), tx.id());
        outputs.push(output);
      }

      if outputs.is_empty() {
        continue;
      }

      // populate the outputs with the origin and data
      let presumed_origin = {
        // This may identify the P2WSH output *embedding the InInstruction* as the origin, which
        // would be a bit trickier to spend that a traditional output...
        // There's no risk of the InInstruction going missing as it'd already be on-chain though
        // We *could* parse out the script *without the InInstruction prefix* and declare that the
        // origin
        // TODO
        let spent_output = {
          let input = &tx.input[0];
          let mut spent_tx = input.previous_output.txid.as_raw_hash().to_byte_array();
          spent_tx.reverse();
          let mut tx;
          while {
            tx = self.rpc.get_transaction(&spent_tx).await;
            tx.is_err()
          } {
            log::error!("couldn't get transaction from bitcoin node: {tx:?}");
            sleep(Duration::from_secs(5)).await;
          }
          tx.unwrap().output.swap_remove(usize::try_from(input.previous_output.vout).unwrap())
        };
        Address::new(spent_output.script_pubkey)
      };
      let data = Self::extract_serai_data(tx);
      for output in &mut outputs {
        if output.kind == OutputType::External {
          output.data.clone_from(&data);
        }
        output.presumed_origin.clone_from(&presumed_origin);
      }
    }

    outputs
  }

fn instruction_from_output<N: Network>(
  output: &N::Output,
) -> (Option<ExternalAddress>, Option<InInstructionWithBalance>) {
  assert_eq!(output.kind(), OutputType::External);

  let presumed_origin = output.presumed_origin().map(|address| {
    ExternalAddress::new(
      address
        .try_into()
        .map_err(|_| ())
        .expect("presumed origin couldn't be converted to a Vec<u8>"),
    )
    .expect("presumed origin exceeded address limits")
  });

  let mut data = output.data();
  let max_data_len = usize::try_from(MAX_DATA_LEN).unwrap();
  if data.len() > max_data_len {
    error!(
      "data in output {} exceeded MAX_DATA_LEN ({MAX_DATA_LEN}): {}. skipping",
      hex::encode(output.id()),
      data.len(),
    );
    return (presumed_origin, None);
  }

  let shorthand = match Shorthand::decode(&mut data) {
    Ok(shorthand) => shorthand,
    Err(e) => {
      info!("data in output {} wasn't valid shorthand: {e:?}", hex::encode(output.id()));
      return (presumed_origin, None);
    }
  };
  let instruction = match RefundableInInstruction::try_from(shorthand) {
    Ok(instruction) => instruction,
    Err(e) => {
      info!(
        "shorthand in output {} wasn't convertible to a RefundableInInstruction: {e:?}",
        hex::encode(output.id())
      );
      return (presumed_origin, None);
    }
  };

  let mut balance = output.balance();
  // Deduct twice the cost to aggregate to prevent economic attacks by malicious miners against
  // other users
  balance.amount.0 -= 2 * N::COST_TO_AGGREGATE;

  (
    instruction.origin.or(presumed_origin),
    Some(InInstructionWithBalance { instruction: instruction.instruction, balance }),
  )
}
