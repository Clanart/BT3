## Analog Found

authentik's flaw: a signed credential (an OAuth access token) is accepted by a verifier that never checks which application/audience it was issued for, so a token signed for one purpose is replayed against a different provider. The `addr` precompile's `associate()` method exhibits the identical bug class: it recovers a signer's pubkey from an arbitrary `(v, r, s, customMessage)` tuple and, on success, unconditionally performs a **permanent, irreversible** identity/fund-migration action — with no verification that the signature was ever intended for "associate this Sei address" at all. ### Title
Unbound signature domain in the `addr` precompile's `associate()` lets any observed signature force a permanent, fund-migrating address association - (File: `precompiles/addr/addr.go`)

### Summary
The `associate(v, r, s, customMessage)` method of the `addr` precompile (`0x...1004`) recovers a pubkey from `keccak256(customMessage)` and, if recovery succeeds, calls `AssociateAddresses`, which permanently binds an EVM address to a Sei address, sets the account pubkey, and migrates all bank/wei balances from the direct-cast address to the derived Sei address. Nothing in `associate()` verifies that `customMessage` is actually the association prompt ("Please sign this message to link your EVM and Sei addresses...") — any string is accepted, and no chain ID, contract address, or purpose separator is baked into the signed hash.

### Finding Description
`associate()` derives `evmAddr`, `seiAddr`, and `pubkey` purely from an ECDSA recovery over `crypto.Keccak256Hash([]byte(customMessage))`: [2](#0-1) 

It then immediately performs the association and balance migration with no additional authorization from the target account: [3](#0-2) [4](#0-3) 

Because `customMessage` and the resulting hash are completely unconstrained, **any** signature a user has ever produced — a personal-sign login challenge, an EIP-2612 permit, a message signed for a totally different chain or dApp — can be lifted from any public source (mempool, a dApp backend, another chain's explorer) by an unrelated third party and replayed into `associate()`. The precompile has no way to distinguish "the user consented to associate their Sei identity" from "the user signed something else entirely."

This is the same audience/domain-confusion root cause as the authentik CVE: a credential is accepted without checking the context it was issued for. The codebase itself demonstrates the sei-chain team is aware this bug class is dangerous, since it built explicit chain ID/nonce/authority checks for the equivalent EIP-7702 path specifically to prevent this exact replay: [5](#0-4) 

That comment explicitly documents the impact of an unguarded forced association: *"migrating their direct-cast balance and orphaning staking/distribution state."* `associate()`'s personal-sign path has no analog of `AuthorityToPreAssociate`'s chain ID/nonce checks at all — it is strictly weaker than the already-hardened SetCode path.

`MigrateBalance` deletes the base account behind the cast address once its `LockedCoins` are zero: [6](#0-5) 

Because Cosmos staking/distribution state is keyed by the delegator's raw address rather than tied to the account object's existence, and association is a one-way, non-remappable operation (`associateAddresses` rejects any address that is already associated), any stake, unbonding, or distribution rewards outstanding under the direct-cast identity become permanently orphaned once a third party forces association using a leaked/replayed signature the victim never intended for Sei at all.

### Impact Explanation
A malicious actor who obtains any valid ECDSA signature from a victim (from any chain, any dApp, any purpose) can, without the victim's consent or even awareness that Sei exists, submit an `associate()` call that permanently and irreversibly links the victim's EVM address to their pubkey-derived Sei address. This:
- Force-migrates any funds sitting at the victim's direct-cast address.
- Permanently forecloses any future, intentional pre-association flow the victim might otherwise use.
- Can orphan staking/distribution state associated with the direct-cast identity, matching the "permanent freezing of funds" impact class, mirroring the exact harm the code's own comments describe for the (already-patched) SetCode authorization path.

### Likelihood Explanation
Reachability is trivial: `associate()` is a public, non-privileged EVM transaction on a deployed precompile at a fixed address (`0x...1004`), callable by anyone with no special role. The only prerequisite is possession of any ECDSA signature produced by the victim over any message — something routinely leaked in public transactions, permits, or off-chain signed messages across the broader Ethereum ecosystem, all of which use the same secp256k1 curve as Sei accounts.

### Recommendation
Bind the association signature to an explicit, on-chain-enforced domain: require `customMessage` to match a fixed, versioned, chain-ID-scoped template (e.g., include `chainID`, the precompile address, and a purpose tag such as `"SEI-ASSOCIATE"`), and reject any signature whose message does not match that exact template — analogous to the chain ID/nonce checks already implemented in `AuthorityToPreAssociate` for the EIP-7702 authorization path.

### Proof of Concept
1. Victim signs an unrelated personal-sign message on another chain/dApp (e.g., a SIWE login challenge or an EIP-2612 permit) using their EOA key; this signature/message pair becomes publicly visible (e.g., posted to a backend log, included in a public tx, or observed in a mempool).
2. Attacker decodes the message's `v/r/s` and raw message text, and calls the `addr` precompile:
   `addr.associate(v, r, s, <victim's unrelated signed message bytes>)`.
3. `crypto.Keccak256Hash([]byte(customMessage))` recovers the victim's pubkey exactly as `GetAddresses` would for a legitimate association request, since the message content is never validated.
4. `associateAddresses` → `AssociateAddresses` executes, permanently mapping the victim's EVM address to their Sei address, migrating any balance sitting at the direct-cast address, and precluding any future association — all without the victim ever intending to interact with Sei.

func (p PrecompileExecutor) associate(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}

	// v, r and s are components of a signature over the customMessage sent.
	// We use the signature to construct the user's pubkey to obtain their addresses.
	v := args[0].(string)
	r := args[1].(string)
	s := args[2].(string)
	customMessage := args[3].(string)

	rBytes, err := decodeHexString(r)
	if err != nil {
		return nil, 0, err
	}
	sBytes, err := decodeHexString(s)
	if err != nil {
		return nil, 0, err
	}
	vBytes, err := decodeHexString(v)
	if err != nil {
		return nil, 0, err
	}

	vBig := new(big.Int).SetBytes(vBytes)
	rBig := new(big.Int).SetBytes(rBytes)
	sBig := new(big.Int).SetBytes(sBytes)

	// Derive addresses
	vBig = new(big.Int).Add(vBig, utils.Big27)

	customMessageHash := crypto.Keccak256Hash([]byte(customMessage))
	evmAddr, seiAddr, pubkey, err := helpers.GetAddresses(vBig, rBig, sBig, customMessageHash)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p PrecompileExecutor) associateAddresses(ctx sdk.Context, method *abi.Method, evmAddr common.Address, seiAddr sdk.AccAddress, pubkey cryptotypes.PubKey) (ret []byte, remainingGas uint64, err error) {
	// Check that address is not already associated
	_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if found {
		return nil, 0, fmt.Errorf("address %s is already associated with evm address %s", seiAddr, evmAddr)
	}

	// Associate Addresses:
	associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.bankKeeper, p.accountKeeper)
	err = associationHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false)
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(seiAddr.String(), evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil

// already associated. Mirroring validateAuthorization is essential to security: the
// authorization sig hash is computed from the auth's own ChainID, so recovery and
// auth.Authority() succeed for an authorization signed for ANY chain. Without these checks a
// publicly-visible authorization a user signed for another chain (e.g. Ethereum mainnet)
// could be replayed in a sponsored Sei SetCode tx to force-associate them — migrating their
// direct-cast balance and orphaning staking/distribution state — even though the EVM skips
// the wrong-chain authorization and installs no delegation.
func AuthorityToPreAssociate(ctx sdk.Context, k AuthorizationStateReader, auth ethtypes.SetCodeAuthorization) (common.Address, sdk.AccAddress, cryptotypes.PubKey, bool) {
	// Chain ID must be null or match the local chain.
	if !auth.ChainID.IsZero() && auth.ChainID.CmpBig(k.ChainID(ctx)) != 0 {
		return common.Address{}, nil, nil, false
	}
	// Nonce must not overflow (EIP-2681).
	if auth.Nonce+1 < auth.Nonce {
		return common.Address{}, nil, nil, false
	}
	evmAddr, seiAddr, pubkey, err := RecoverAddressesFromAuthorization(auth)
	if err != nil {
		return common.Address{}, nil, nil, false
	}
	// Cross-check against go-ethereum's authoritative recovery so we only ever act on the
	// exact address SetCode would target during execution.
	if authAddr, aerr := auth.Authority(); aerr != nil || authAddr != evmAddr {
		return common.Address{}, nil, nil, false
	}
	// Authority must have no code, or only an existing delegation designator.
	if code := k.GetCode(ctx, evmAddr); len(code) != 0 {
		if _, ok := ethtypes.ParseDelegation(code); !ok {
			return common.Address{}, nil, nil, false
		}
	}
	// Authority account nonce must match the authorization nonce.
	if k.GetNonce(ctx, evmAddr) != auth.Nonce {
		return common.Address{}, nil, nil, false
	}
	// Already-associated authorities need no pre-association (and cannot be re-mapped).
	if _, associated := k.GetEVMAddress(ctx, seiAddr); associated {
		return common.Address{}, nil, nil, false
	}
	return evmAddr, seiAddr, pubkey, true
