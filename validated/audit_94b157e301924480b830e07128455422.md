### Title
Invalid-PoP PedPoP messages leak ECDH keys and DKG secret shares - (File: crypto/dkg/pedpop/src/lib.rs)

### Summary
`KeyMachine::calculate_share` can return an `EncryptionKeyProof` for an `EncryptedMessage` whose proof-of-possession has not yet been verified. A sender can copy the ephemeral key and ciphertext from another participant’s encrypted share, invalidate the copied message’s PoP, and malleate the ciphertext so it decrypts to a non-canonical scalar. The early scalar-decoding error then returns the ECDH blame proof before the queued PoP verification runs, allowing the attacker to decrypt the original copied share.

### Finding Description
`EncryptedMessage` explicitly relies on `pop` to prevent an observer from reusing another message’s key and causing the recipient to reveal the corresponding ECDH value. [1](#0-0) 

`EncryptedMessage::read` accepts the untrusted `key`, `pop`, and ciphertext without checking that the PoP verifies. [2](#0-1) 

`Encryption::decrypt` only queues `msg.pop` into a `BatchVerifier`; it then immediately calculates `ecdh(self.enc_key, msg.key)` and creates a DLEQ-backed `EncryptionKeyProof` containing that ECDH point. [3](#0-2) [4](#0-3) [5](#0-4) 

In `calculate_share`, `C::F::from_repr` failure exits immediately with `blame: Some(blame.clone())`, before `batch.verify_with_vartime_blame()` can identify the queued PoP failure and suppress the proof. [6](#0-5) [7](#0-6) 

The proof is externally serializable and writes the ECDH point before the DLEQ proof. [8](#0-7) [9](#0-8) 

For legitimate blame adjudication, `decrypt_with_proof` verifies the original message’s PoP, verifies the supplied ECDH key, and uses it to decrypt that original message. [10](#0-9) [11](#0-10) [12](#0-11) 

### Impact Explanation
This discloses a victim recipient’s ECDH shared key for another participant’s encrypted DKG share, and that key decrypts the copied ciphertext to reveal the original secret share. [13](#0-12) [12](#0-11) 

This breaks the confidentiality boundary intended for PedPoP secret shares and constitutes key-share recovery rather than mere metadata disclosure. [14](#0-13) 

### Likelihood Explanation
The attacker needs to supply one syntactically valid `EncryptedMessage` in the recipient’s `shares` map, while the remaining shares can be valid. [15](#0-14) 

No valid PoP for the copied ephemeral key is needed because the exploit exits before the batched PoP result is evaluated. [6](#0-5) 

The attack depends on the documented blame object being returned or published for adjudication; that is the normal reason `calculate_share` constructs and returns it. [16](#0-15) 

### Recommendation
Verify `msg.pop` before calculating the ECDH value or generating `EncryptionKeyProof`, and return an invalid-share error with `blame: None` when the PoP is invalid. [17](#0-16) 

Alternatively, retain batching but do not attach `blame` to early scalar-decoding failures until the queued PoP has been verified successfully. [6](#0-5) [7](#0-6) 

Add a regression test that copies a valid message’s `key`, supplies an invalid PoP, malleates the ciphertext into a non-canonical decrypted scalar, and asserts that `calculate_share` returns `blame: None`; the existing invalid-PoP test only covers reaching batch verification and therefore misses this early-return path. [18](#0-17) 

### Proof of Concept
For Ristretto, the serialized `EncryptedMessage` layout is a 32-byte point `key`, a 64-byte Schnorr signature, and a 32-byte encrypted scalar. [19](#0-18) 

```rust
// victim_msg: serialized EncryptedMessage<Ristretto, SecretShare<_>>
// from Alice to Bob, observed by the attacker.

let mut forged = victim_msg.clone();

// Keep Alice's 32-byte ephemeral key X at forged[0..32].
// Replace the PoP with syntactically valid but invalid signature bytes.
forged[32..64].copy_from_slice(Ristretto::generator().to_bytes().as_ref());
forged[64..96].copy_from_slice(Scalar::ZERO.to_repr().as_ref());

// Alice's plaintext scalar is canonical, so its top bit is zero.
// XORing the ciphertext's top bit makes Bob's decrypted scalar non-canonical.
forged[96 + 31] ^= 0x80;

let malicious = EncryptedMessage::<Ristretto, SecretShare<_>>::read(
  &mut forged.as_slice(),
  bob_params,
).unwrap();

let mut delivered = honest_shares_for_bob;
delivered.insert(attacker_participant, malicious);

let Err(PedPoPError::InvalidShare {
  blame: Some(leaked_proof),
  ..
}) = bob_key_machine.calculate_share(&mut rng, delivered) else {
  panic!("expected early non-canonical-share blame");
};

// The proof's first 32 serialized bytes are bX.
let shared_point =
  RistrettoPoint::from_bytes(&leaked_proof.serialize()[..32]).unwrap();

// Reproduce cipher(context, shared_point) and XOR its ChaCha20 stream with
// Alice's original ciphertext to recover Alice's secret share for Bob.
```

The forged PoP remains unverified because the non-canonical decrypted share exits at `from_repr` before the batch verifier is evaluated, while the serialized `leaked_proof` exposes `bX`. [6](#0-5) [8](#0-7)
