I have enough evidence now to write the final analog report.

`PuzzleWithRestrictions.from_memo()` in `chia/wallet/puzzles/custody/custody_architecture.py` recursively parses attacker-supplied `CREATE_COIN` memo data with no depth limit, and it is invoked from `PlotNFT.get_next_from_coin_spend()` in `chia/pools/plotnft_drivers.py` — a path reachable by anyone who creates a coin (via any spend bundle) with a crafted memo hint, causing unbounded Python recursion / stack-overflow crash in nodes/wallets parsing plotNFT or custody coin history. This mirrors CVE-2018-9259's "unbounded recursive box parsing crash" bug class, but the reachable path here is client-side/local-node processing rather than consensus, so severity and reachability need to be weighed carefully.

### Title
Unbounded recursion in `PuzzleWithRestrictions.from_memo()` allows an attacker-crafted coin memo to crash wallet/plotNFT-tracking clients via Python stack overflow - ([File: chia/wallet/puzzles/custody/custody_architecture.py])

### Summary
`PuzzleWithRestrictions.from_memo()` recursively reconstructs `MofN` puzzle trees from a `CREATE_COIN` memo blob without any depth or size bound. [1](#0-0) . Any unprivileged spend-bundle submitter can create a coin with `CREATE_COIN puzzle_hash amount memo`, where `memo` is a deeply nested `MofNHint` structure (`further_branching=True` with a single member repeatedly), and this memo is parsed by `from_memo` when consumed by PlotNFT lineage tracking.

### Finding Description
`from_memo()` inspects `further_branching_prog`; when set, it builds an `MofN` puzzle by calling `PuzzleWithRestrictions.from_memo(memo)` once per element of `member_memos`, and each of those can again set `further_branching=True`, causing unbounded recursion depth controlled entirely by the memo's nesting [2](#0-1) . There is no recursion-depth or memo-size cap anywhere in this parsing path, unlike `sha256_treehash()`, which was deliberately made iterative specifically "so we don't have to worry about blowing out the python stack" [3](#0-2) , and unlike the Data Layer's binary-tree ingestion, which explicitly raises `chia_rs.datalayer.RecursionDepthExceededError` for deep graphs [4](#0-3) . This memo path is reached in production via `PlotNFT.get_next_from_coin_spend()`, which calls `PuzzleWithRestrictions.from_memo(singleton_create_coin.memo_blob.rest())` directly on the memo taken from a `CREATE_COIN` condition parsed out of an arbitrary coin spend's inner puzzle output [5](#0-4) .

### Impact Explanation
A memo blob is fully attacker-controlled data attached to any coin creation; no signature or special privilege is required to include it in a `CREATE_COIN` condition. When a wallet/plotNFT client (or any code path relying on `PuzzleWithRestrictions.from_memo`) later parses such a coin's memo while syncing/tracking a plotNFT or custody-based singleton, it will recurse once per nested layer of the crafted `MofNHint` and can exhaust the Python call stack, crashing the process with an unrecoverable `RecursionError`. This is a client-side denial-of-service against wallet/plotNFT-tracking processes triggered purely by data broadcast on-chain by an unprivileged spender — matching the CVE's crash-via-unbounded-recursion class, though impacted here is availability of the local node/wallet process (not itself a fund-loss or consensus divergence bug).

### Likelihood Explanation
Constructing the malicious memo requires only assembling a `CREATE_COIN` condition with a deeply nested list as memo, something well within reach of any wallet/coin creator, and does not require the resulting spend to touch a "real" plotNFT for the crash to occur once `from_memo` is invoked on the data — the crash happens purely inside Python recursion in `from_memo`/`MofNHint.from_program` before any puzzle-hash cross-check runs.

### Recommendation
Add an explicit recursion-depth (or memo-size) limit inside `PuzzleWithRestrictions.from_memo()`/`MofNHint.from_program()`, raising a clear `ValueError` once a bound (e.g., matching CLVM's own practical singleton/custody nesting limits) is exceeded, mirroring the iterative-traversal or explicit `RecursionDepthExceededError` patterns already used elsewhere in the codebase (`sha256_treehash`, DataLayer ingestion).

### Proof of Concept
1. Build a `MofNHint` memo where `further_branching=1` and `member_memos` contains one entry that is itself a fully valid `CHIP-0043` memo with `further_branching=1`, repeated N times (e.g. N = 50,000, well under Python's default recursion limit multiplier needed to overflow the C stack given `from_memo`'s multi-frame-per-level call chain: `from_memo` → `MofNHint.from_program` → list comprehension → `from_memo`).
2. Emit a `CREATE_COIN <puzzle_hash> <amount> <memo>` condition from any spendable coin's inner puzzle solution, broadcasting a normal spend bundle (no special permissions needed) — the memo need not correspond to a puzzle hash that actually matches a real plotNFT/custody puzzle for the crash to trigger.
3. Have a client call `PuzzleWithRestrictions.from_memo(memo)` on the resulting `CreateCoin.memo_blob` (e.g. through `PlotNFT.get_next_from_coin_spend()` while syncing plotNFT state, as shown in `chia/_tests/pools/test_plotnft_v2_drivers.py:534-567`), causing a Python `RecursionError`/stack overflow and crashing the process.

@pytest.mark.anyio
@pytest.mark.parametrize("depth", [1000, 100_000])
async def test_insert_into_data_store_from_file_line_graph_depth(
    data_store: DataStore,
    store_id: bytes32,
    tmp_path: Path,
    depth: int,
) -> None:
    # Binary "line graph":
    #   1 -> leaf_1, 2
    #   2 -> leaf_2, 3
    #   ...
    #   depth -> leaf_depth, leaf_end
    #
    # This stresses depth/stack handling while staying strictly binary.
    #
    # Node IDs:
    # - internal nodes: 1..depth
    # - per-level leaf nodes: (depth+1)..(2*depth)
    # - final leaf: (2*depth+1)
    internal_first = 1
    internal_last = depth
    leaf_base = internal_last + 1
    leaf_end = (2 * depth) + 1

    edges: list[tuple[int, int]] = []
    for i in range(internal_first, internal_last):
        # Order matters: first edge is left child, second edge is right child.
        edges.append((i, leaf_base + (i - internal_first)))  # unique leaf for this internal node
        edges.append((i, i + 1))  # next internal node

    # last internal points to its leaf and a final leaf
    edges.append((internal_last, leaf_base + (internal_last - internal_first)))
    edges.append((internal_last, leaf_end))

    filename = tmp_path / f"line_graph_depth_{depth}.dat"
    root_hash = create_graph_util(filename, edges)

    with pytest.raises(chia_rs.datalayer.RecursionDepthExceededError):
        await data_store.insert_into_data_store_from_file(store_id, root_hash, filename)
