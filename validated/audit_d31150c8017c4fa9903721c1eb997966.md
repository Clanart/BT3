### Title
Unbounded recursive memo parsing in `PuzzleWithRestrictions.from_memo` allows a spend-triggered stack-overflow / wallet DoS - (File: chia/wallet/puzzles/custody/custody_architecture.py)

### Summary
`PuzzleWithRestrictions.from_memo()` reconstructs a custody puzzle tree from an on-chain memo by recursing into nested `MofN` members with no depth limit, mirroring the CVE-2021-45258 bug class (unbounded recursive list/proto decoding causing a stack overflow).

### Finding Description
`PuzzleWithRestrictions.from_memo()` decodes a `CHIP-0043` memo blob and, whenever the memo indicates "further branching," constructs a `MofN` whose members are built by calling `PuzzleWithRestrictions.from_memo()` again for every member memo: [1](#0-0) 

There is no maximum-depth check anywhere in this recursive chain, and the CLVM `Program` object it operates on can encode arbitrarily deep nesting of lists cheaply (as demonstrated by the deserializer/overflow tests in the same codebase area) [2](#0-1) . This function is the exact analog the tests describe as needing to "reconstruct unknown members/restrictions, including recursive `MofN`" when syncing an inner puzzle from chain data [3](#0-2) .

The consuming path is `PlotNFT.get_next_from_coin_spend()`, a plotnft/pool-transition function that takes the `memo_blob` from a `CREATE_COIN` condition emitted by spending a singleton and feeds it directly into `PuzzleWithRestrictions.from_memo()`: [4](#0-3) 

Because the memo content is attacker-controlled data taken from a coin's `CREATE_COIN` memo (part of a spend bundle a counterparty or pool operator can construct), a crafted memo with deeply nested `MofN` branching (`further_branching=1` at every level) will cause Python to recurse once for every nesting level in `from_memo` → `MofNHint.from_program` → list comprehension → `from_memo`, with no depth guard. Python's default recursion limit is far lower than the number of nesting levels that fit in the small memo blob, so a moderately deep memo triggers an uncaught `RecursionError` (or, at the interpreter/C-stack level, a hard crash) in whatever process is parsing/tracking the coin (the wallet during plotnft/singleton sync).

### Impact Explanation
No `sys.setrecursionlimit`/`RecursionError` handling exists anywhere in the codebase, so an uncaught `RecursionError` during coin-spend processing halts the plotnft/wallet syncing logic — a spend-triggered transaction-processing halt on the affected wallet, matching the accepted "Validate" impact category. This is reachable by any counterparty who can cause a singleton coin with such a memo to be created and observed by a victim wallet performing plotnft/pool state tracking.

### Likelihood Explanation
Medium: the attacker needs only craft a spend that creates a coin with a maliciously deep `CHIP-0043` memo (no signature over the memo semantics beyond the normal coin-creation conditions), then have a wallet that tracks plotnft/singleton state process the resulting coin spend via `get_next_from_coin_spend()`. No special privileges beyond normal spend-bundle submission are required.

### Recommendation
Add an explicit maximum-recursion/nesting-depth check in `PuzzleWithRestrictions.from_memo()` (and `MofNHint.from_program()`), rejecting memos that exceed a bounded depth, and/or convert the recursive walk into an iterative one (as already done for `sha256_treehash` in `chia/types/blockchain_format/tree_hash.py`) to avoid relying on Python's call stack for attacker-controlled data.

### Proof of Concept
Construct a memo program via nested calls, mirroring `PuzzleWithRestrictions.memo()`'s `MofNHint` shape, where each level sets `further_branching=1` (i.e., an `MofN` with a single member whose memo is itself another `MofN`-shaped memo), nested N times (N in the low hundreds, well within a `CREATE_COIN` memo size budget). Passing the outer memo blob (as would be extracted from `singleton_create_coin.memo_blob.rest()`) to `PuzzleWithRestrictions.from_memo()` — the exact call performed in `PlotNFT.get_next_from_coin_spend()` — raises an uncaught `RecursionError`, crashing/hanging the wallet's PlotNFT/pool sync coroutine that is processing the received coin spend.

        restriction_hints = [RestrictionHint.from_program(hint) for hint in restriction_hints_prog.as_iter()]
