### Title
Gasless swap transactions with expired deadlines can still be executed via `VerifyExecutable`/`ExtractTxBundles` bundling path - ([File: kaiax/gasless/impl/getter.go])

### Summary
`GaslessModule.VerifyExecutable` (invoked by `IsExecutable`, which gates whether a gasless approve+swap pair is bundled and executed via `ExtractTxBundles`) never validates `SwapArgs.Deadline` against the current block time. [4](#0-3)  The only place that checks the deadline is `checkBalanceForSwap`, exposed through `GetCheckBalance`, a distinct code path presumably used during tx-pool admission (`AddTx`), not during block assembly. [5](#0-4) 

### Finding Description
The gasless swap feature lets an unprivileged sender submit an `approve` + `swapForGas` transaction pair; the CN proposer fronts gas via a `LendTx` and is repaid from swap proceeds, contingent on `VerifyExecutable` returning success (S1–S4/AP1/SP1–SP4 checks documented in the function's comments). [6](#0-5)  The comment block explicitly enumerates the invariants checked (Sx, Ax, AP1, SP1–SP4) and `tx.deadline >= currentTimestamp` is conspicuously absent from that list and from the function body. [7](#0-6)  `ExtractTxBundles`, which builds the actual bundle of `[LendTx, ApproveTx?, SwapTx]` for block inclusion, relies solely on `IsExecutable` (→ `VerifyExecutable`) to decide bundling — it does not call `checkBalanceForSwap`/`GetCheckBalance`. [8](#0-7)  Because `checkBalanceForSwap`'s deadline check occurs only via `GetCheckBalance` (a tx-pool-facing hook, separate from `IsReady`/`ExtractTxBundles`), a swap transaction that passed the deadline check at admission time (or was queued before the deadline and later promoted) can still be deemed "executable" and bundled/executed after its `deadline` has elapsed, mirroring the reported EDC bug class where the actual consumption/execution path fails to re-validate a time-bound authorization that was only checked in a separate control-plane code path.

### Impact Explanation
If a stale/expired `swapForGas` transaction is bundled and executed, `swapArgs.MinAmountOut`/exchange-rate assumptions the sender relied on at signing time are no longer enforced against present-time constraints, allowing the swap to execute under conditions the sender did not consent to for that block (fee/value settlement occurring outside the sender's intended time window). This is a fee-delegation/gasless settlement integrity issue reachable by any public transaction sender interacting with the gasless module, matching the "gasless or auction settlement theft" and "fee-delegation abuse" categories in scope.

### Likelihood Explanation
Exploitability depends on whether a gasless transaction can remain in the pool (queue/pending) past its declared deadline before being promoted and bundled — the `isReady`/`isApproveTxReady`/`isSwapTxReady` promotion logic and `PreReset`/timeouts govern this, and `IsExecutable` is called at promotion time without a deadline re-check. Given `QueueTimeout`/`PendingTimeout` are only 10 seconds by default, exploitation requires a narrow timing window (e.g., signing with a deadline close to submission, then network delay/reordering causing promotion after expiry), or a malicious/lagging proposer intentionally delaying inclusion — making it plausible but requiring some timing control by the transaction submitter or block builder.

### Recommendation
Add an explicit `swapArgs.Deadline >= currentBlockTime` check inside `VerifyExecutable` in `kaiax/gasless/impl/getter.go`, so the deadline is enforced at the same point where bundling/execution eligibility is finally decided (`IsExecutable`/`ExtractTxBundles`), not only in the separate `checkBalanceForSwap` admission-time check.

### Proof of Concept
1. Submit an `approve` tx and a `swapForGas` tx with `deadline = currentBlockTime + 1` (minimal valid window) to a CN's tx pool; both pass `checkBalanceForSwap`'s deadline check at admission (`kaiax/gasless/impl/tx_pool.go:175-179`).
2. Delay promotion (e.g., via network conditions or by having other pending transactions occupy the nonce slot) until block time has advanced past `deadline`, but before `QueueTimeout`/`PendingTimeout` evict the transactions (`kaiax/gasless/impl/tx_pool.go:33-35, 292-315`).
3. When `IsReady` calls `isApproveTxReady`/`isSwapTxReady` → `IsExecutable` → `VerifyExecutable`, no deadline check occurs (`kaiax/gasless/impl/getter.go:203-266`), so the pair is marked ready.
4. `ExtractTxBundles` bundles and includes the expired swap in the block (`kaiax/gasless/impl/builder.go:28-72`), executing the swap after its declared deadline.

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}

		if err != nil {

			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}
