### Title
Crafted `ReceivedOutput` bytes with a mismatched offset report deposits as received that can never be spent - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput::read` deserializes `offset`, `output`, and `outpoint` independently, with no check that `key + offset * G` actually maps to `output.script_pubkey` under `p2tr_script_buf`. An attacker who feeds untrusted bytes into `ReceivedOutput::read` can attach a real, on-chain deposit's `TxOut`/`OutPoint` to a different scalar offset. The deposit is then recorded as received (matching the "deposit succeeds on-chain but is never credited to a spendable balance" class of the external report), yet the signing path in `SignableTransaction::multisig` silently rejects the output because `p2tr_script_buf(offset.group_key()) != self.prevouts[i].script_pubkey`, bricking the funds.

### Finding Description
`ReceivedOutput::read` (networks/bitcoin/src/wallet/mod.rs:122-134) reads three independent fields:

- `offset` via `Secp256k1::read_F` — any canonical scalar is accepted,
- `output` and `outpoint` via consensus decoding.

There is no consistency check binding `offset` to `output.script_pubkey`. Contrast with the only honest producer of `ReceivedOutput`s, `Scanner::scan_transaction` (lines 199-213), which derives `offset` solely from the `scripts` map keyed by `script_pubkey`, so `key + offset*G` and the script always correspond.

The consumer enforces consistency only implicitly, and only at spend time: `SignableTransaction::multisig` (send.rs:273-284) computes `keys.offset(self.offsets[i])` and returns `None` when `p2tr_script_buf(offset.group_key())` does not equal the prevout's script_pubkey. So a deserialized `ReceivedOutput` with a forged offset is accepted as a deposit, but the multisig machine cannot be constructed, and the transaction can never be signed.

### Impact Explanation
An attacker supplying crafted bytes to `ReceivedOutput::read` — a listed untrusted-input API — causes a deposit to be reported/accounted as received under a scalar offset that does not correspond to the output's actual spending key. This mirrors the external report exactly: the funds exist on-chain and are counted as received, yet they are unreachable — `multisig` fails to construct a signing machine for that input, so the credited balance is permanently unspendable unless the discrepancy is manually detected and the output re-derived with the correct offset. If such outputs are commingled as inputs to `SignableTransaction::new`, `multisig` returns `None` for the whole transaction (send.rs:277-279), stalling spending of the other, legitimate inputs as well.

### Likelihood Explanation
Likelihood is limited to flows where `ReceivedOutput` bytes cross a trust boundary (deserialized from peer/DB/serai-side messages rather than freshly produced by `Scanner::scan_transaction`). Where the scanner is the sole producer, the bug is unreachable; where serialized outputs are consumed from an untrusted source, a single malicious write suffices. This matches the "Low likelihood, High impact" profile of the source finding.

### Recommendation
Bind the offset to the output at deserialization or first use. Either:

1. In `ReceivedOutput::read`, accept the base `key: ProjectivePoint` (or a `&Scanner`) and verify `p2tr_script_buf(key + GENERATOR * offset) == Some(output.script_pubkey)`, rejecting inconsistent encodings; or
2. Store only `(outpoint, output)` and re-derive `offset` via `scanner.scripts[output.script_pubkey]` at read time, making forgery impossible.

### Proof of Concept
```rust
// In-scope: networks/bitcoin/src/wallet/mod.rs
// 1. Honest deposit exists on-chain to scanner script for offset `o`:
//    script = p2tr_script_buf(key + G*o).unwrap()
let real: ReceivedOutput = scanner.scan_transaction(&tx).remove(0);

// 2. Attacker serializes a forged ReceivedOutput: same output/outpoint,
//    arbitrary different offset o' (any canonical scalar passes read_F).
let mut forged_bytes = Vec::new();
forged_bytes.write_all(&Scalar::from(42u64).to_bytes()).unwrap(); // o' != o
forged_bytes.write_all(&serialize(real.output())).unwrap();
forged_bytes.write_all(&serialize(real.outpoint())).unwrap();

// 3. Deserialization succeeds — no offset/script binding check.
let forged = ReceivedOutput::read::<&[u8]>(&mut forged_bytes.as_ref()).unwrap();
assert_eq!(forged.value(), real.value()); // deposit counted as received

// 4. Spend attempt: multisig() returns None since
//    p2tr_script_buf(group_key + G*o') != prevout.script_pubkey.
//    The credited funds are unspendable — identical effect to the
//    HyperCore deposit that lands in an unactivated account.
assert!(SignableTransaction::new(vec![forged], &payments, None, None, FEE)
        .unwrap()
        .multisig(&keys)
        .is_none());
```
