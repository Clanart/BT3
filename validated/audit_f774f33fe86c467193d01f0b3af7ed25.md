### Title
Unauthenticated OP_RETURN in `payout_tx` lets anyone strip operator attribution via `SIGHASH_SINGLE|ANYONECANPAY` malleability, permanently denying reimbursement - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
`create_payout_txhandler` places the fronting operator's x-only pubkey in an OP_RETURN output (index 2) that is outside the scope of the withdrawer's `SinglePlusAnyoneCanPay` signature, which per BIP341/BIP118 only commits to input 0 and output 0 [1](#0-0) . Because ANYONECANPAY allows arbitrary extra inputs and SIGHASH_SINGLE only binds output 0, anyone who observes the broadcast (unconfirmed) `payout_tx` in the mempool can rebroadcast a variant that reuses the same input 0 + witness, preserves output 0 (the user's payout), but replaces/corrupts outputs 1 and 2 (anchor and OP_RETURN) and funds its own fees, racing the original tx into a block.

### Finding Description
The binding claimed broken: `withdrawals.payout_payer_operator_xonly_pk` (set by `update_finalized_payouts` from the mined payout tx's OP_RETURN) should equal the `operator_xonly_pk` that `SECP.verify_schnorr` accepted inside `Operator::withdraw` when admitting the original `payout_tx` to the mempool [2](#0-1) .

Root cause: `create_payout_txhandler` builds output 0 (user payout, signed via `SpendPath::KeySpend`), output 1 (anchor), and output 2 (OP_RETURN containing `operator_xonly_pk.serialize()`) [3](#0-2) ; only input 0's witness (the user's Schnorr signature) is checked, and the sighash type is expected/documented to be `SinglePlusAnyoneCanPay` (`wrap_err("... Ensure the signature uses SinglePlusAnyoneCanPay sighash type.")`) [4](#0-3) . Under SIGHASH_SINGLE|ANYONECANPAY, the signature commits only to input 0's own data and output at index 0 — not outputs 1/2, and not to any other inputs (ANYONECANPAY). This means an attacker can take the mempool tx, keep the same input 0 (outpoint + witness) and output 0 (unchanged, since that's covered), replace the anchor/OP_RETURN outputs and add their own fee-paying input(s)/change, and get their variant mined first — a standard transaction pinning/malleability attack enabled by the permissive sighash flag combined with an unauthenticated OP_RETURN.

When the attacker's corrupted tx confirms, `update_finalized_payouts` parses the OP_RETURN: if `parse_op_return_data` returns garbage bytes that fail `bytes.try_into::<[u8;32]>()` or `XOnlyPublicKey::from_slice` fails, `operator_xonly_pk` becomes `None`, and `payout_payer_operator_xonly_pk` is set to `NULL` in the DB [5](#0-4) [6](#0-5) .

This NULL then breaks every downstream attribution path:
- `PayoutCheckerTask` looks up unhandled payouts filtered `WHERE w.payout_payer_operator_xonly_pk = $1` [7](#0-6) , so the real operator's automation will never discover this payout and never call `handle_finalized_payout` to claim a kickoff connector.
- `validate_payer_is_operator`, used by the manual (`GetReimbursementTxs`) fallback path, requires `payer_xonly_pk`, `payout_blockhash`, and `kickoff_txid` all to be `Some`; with `payer_xonly_pk = None` it returns an error and the operator cannot manually claim reimbursement either [8](#0-7) .
- `Verifier::is_kickoff_malicious` also treats a missing `operator_xonly_pk` in payout info as "assume malicious" [9](#0-8) , so even if the operator manages to send a kickoff anyway (outside the normal flow), verifiers would flag it as malicious.

No existing guard checks that the OP_RETURN survived intact from the tx the operator actually broadcast — `update_finalized_payouts` only reads whatever transaction ended up confirmed at the withdrawal's spent outpoint, with no cross-check against a "canonical" payout tx recorded by the operator prior to confirmation.

### Impact Explanation
The operator that legitimately obtained a valid `SinglePlusAnyoneCanPay` signature from the withdrawer and funded output 0 becomes permanently unable to be attributed/credited for that withdrawal, because `payout_payer_operator_xonly_pk` is set to `NULL` and cannot be corrected retroactively (there is no repair/re-parse path once the block is finalized). This matches the listed Critical impact category "an honest operator permanently unable to be reimbursed." The attacker gains nothing directly (no funds diverted to them) — this is a pure griefing/DoS-on-attribution primitive, but the loss to the honest operator (their advanced payout capital, potentially large) is real and irrecoverable through the described code path. It is repeatable against any withdrawal for any operator, as long as the attacker can observe the mempool and outrace the original tx into a block.

### Likelihood Explanation
Preconditions: an operator has called `withdraw`/`internal_withdraw` and broadcast (but not yet confirmed) a `payout_tx`. The attacker needs no deposit, no withdrawal, no privileged role — only the ability to observe the Bitcoin mempool and pay a competitive fee, which matches the stated attacker capability set. The main uncertainty is feasibility of "beating" the original broadcaster's tx to confirmation given that the original operator can also RBF-bump fees (the funding uses `fund_raw_transaction` with dynamic fee rates) — this is a race/first-confirmation condition rather than a guaranteed win, and its likelihood is influenced by mempool dynamics, RBF settings, and miner selection, which are somewhat probabilistic and were not fully confirmed within available files (e.g., whether `payout_tx` opts into RBF explicitly, exact fee-bump cadence). This introduces some uncertainty about "attacker always wins," though the underlying signature-malleability bug (unauthenticated OP_RETURN under `SinglePlusAnyoneCanPay`) is real and file/fn-confirmed.

### Recommendation
Do not rely on sighash-uncommitted outputs for attribution. Options:
1. Move the operator attribution commitment inside the range covered by the signature — e.g., require the withdrawer to sign with a sighash type (or a script-path commitment) that also commits to the OP_RETURN output (such as `SIGHASH_ALL` restricted only to this input via a covenant, or a Taproot script path that commits operator identity into the leaf), so the operator pubkey cannot be altered without invalidating the withdrawer's own signature.
2. Alternatively, since `SinglePlusAnyoneCanPay` intentionally allows fee-input flexibility, restructure the protocol so the txid of the exact `payout_tx` the operator intends to send is committed by the operator up front (e.g., recorded in the DB at broadcast time), and `update_finalized_payouts` cross-checks the confirmed tx's txid against this pre-committed record before trusting/parsing the OP_RETURN — if a different (attacker-mutated) tx confirms instead, still attribute credit to the operator based on the pre-recorded commitment (as long as output 0 matches the signed withdrawal), rather than blindly trusting the OP_RETURN of whatever tx happened to be mined.
3. As a stopgap, allow correction/backfill: if a payout's OP_RETURN attribution is `NULL` but a separately-tracked (pre-broadcast) txid/operator association exists for that payout, still permit `PayoutCheckerTask`/`validate_payer_is_operator` to use that pre-broadcast attribution instead of solely relying on chain-parsed OP_RETURN data.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
