## Title
Optimistic `HostParams` Update Desyncs Hyperbridge's Governance State From the Live `EvmHost` on Cross-Chain Delivery Failure - (File: `modules/pallets/host-executive/src/lib.rs`)

### Summary
`pallet-ismp-host-executive::update_host_params` dispatches an ISMP `PostRequest` that instructs a remote `EvmHost` to apply new `HostParams`, and then **unconditionally** commits the same "new" params to its own local storage — before any confirmation that the message was ever delivered or successfully applied on the destination chain. This is the same broken invariant as the zkSync M-16 report: a governing side advances its recorded state assuming a remote-chain state transition succeeded, without verifying the remote execution outcome, and with no mechanism to reconcile the two if it didn't.

### Finding Description
`update_host_params` computes the new `HostParam`, dispatches it as a cross-chain `DispatchPost` to the target chain's `HostManager`, and immediately writes the new value into `HostParams::<T>`: [1](#0-0) 

This insert happens synchronously in the same extrinsic that dispatches the request — it does not wait for, or even later react to, the eventual response/timeout of that request. The pallet implements no `IsmpModule` (`on_response`/`on_timeout`) to reconcile `HostParams` if the message is never delivered or reverts on delivery, unlike the ISMP core pattern used elsewhere in the codebase where module state changes are only made durable once the callback succeeds (e.g. request/response/timeout handlers restore or delete state based on the destination module's actual return value): [2](#0-1) [3](#0-2) 

On the receiving side, the actual `HostParams` update in `EvmHost` is guarded by several validity checks that can legitimately revert, e.g. it forbids changing the fee token while the host still holds a nonzero balance of the *old* fee token: [4](#0-3) 

Any account can permissionlessly transfer a trivial amount of the current fee token directly to the `EvmHost` contract address (a plain ERC20 `transfer`, no privilege required). If governance later dispatches a `SetHostParam` update that changes the fee token, this griefing deposit causes `updateHostParamsInternal` to revert with `CannotChangeFeeToken`: [5](#0-4) 

`onAccept` in `HostManager.sol` forwards the ABI-decoded params straight into `updateHostParams`, so this revert bubbles up through the low-level `.call` in `dispatchIncoming`, which only marks the request receipt for retry — it does not, and cannot, notify the source chain that the state change was rejected: [6](#0-5) [7](#0-6) 

The result: `pallet-host-executive::HostParams` on Hyperbridge now reflects new parameters (new `feeToken`, `hostManager`, `handler`, `consensusClient`, `challengePeriod`, etc.) that were **never actually applied** on the destination `EvmHost`. There is no code path that detects or repairs this divergence.

### Impact Explanation
Downstream consumers of `pallet-host-executive::HostParams` trust it as ground truth for the live remote state:
- `update_host_params` itself computes future diffs (`inner.update(update)`) starting from the last "recorded" (but possibly never-applied) params, and routes the next cross-chain message's `to` field using the recorded (possibly stale/incorrect) `host_manager` address — potentially routing all future host-management messages to an address that was never actually authorized on-chain, permanently breaking the host-management channel for that state machine.
- `pallet-relayer`'s withdrawal flow reads `HostParams::<T>::get(dest_chain)` to build the `token` field of relayer fee withdrawal instructions sent to the `EvmHost.withdraw()` entrypoint: [8](#0-7) 
If the recorded `feeToken` diverges from what the `EvmHost` actually enforces, withdrawal instructions can reference the wrong token, causing relayer payouts to fail or to be executed against a token balance the host never intended for that purpose — i.e., an authenticated but factually-incorrect "beneficiary/amount/token" instruction, matching the bounty's "wrong beneficiary or amount" and "false state acceptance" categories.

This is a real desynchronization between the protocol's authoritative governance record and the actual on-chain execution outcome — precisely the M-16 bug class, applied to Hyperbridge's cross-chain host-parameter/revenue-management channel instead of zkSync's L1/L2 protocol version.

### Likelihood Explanation
Triggering the divergence requires no special privilege beyond normal ERC20 token transfers: any address can pre-fund the `EvmHost` with a small amount of the current fee token to force `CannotChangeFeeToken` on the very next legitimate `SetHostParam` update, at zero cost and with no detection mechanism. Even without an active griefer, transient failures (message timeout, relayer downtime, invalid params of any of the several revert conditions in `updateHostParamsInternal`) are sufficient and require no adversarial relayer, prover, or governance compromise — only that a single cross-chain delivery fails, which the protocol already anticipates as an ordinary operational condition (as documented for timeouts/response failures elsewhere in the codebase).

### Recommendation
Do not commit `HostParams::<T>::insert(state_machine, updated)` at dispatch time. Instead, register an `IsmpModule` for the host-executive pallet's module id and only commit the new params once a corresponding `on_response`/confirmation is received from the destination `HostManager`/`EvmHost` (or otherwise reconcile via a response-carrying `PostResponse`/`GetRequest` confirming the new params were actually applied), mirroring the "delete-then-restore-on-failure" pattern already used by `handlers/timeout.rs` and `handlers/response.rs`. Alternatively, have `HostManager.onAccept` emit a state-confirming response/log-back message on success only, and never leave `HostParams::<T>` reflecting an unconfirmed remote-state transition.

### Proof of Concept
1. Governance holds `HostParams::<T>` for `StateMachine::Evm(X)` with `feeToken = TokenA`.
2. Attacker calls `TokenA.transfer(evmHostAddress, 1)` — a permissionless ERC20 transfer, giving the `EvmHost` a nonzero `TokenA` balance.
3. Governance calls `pallet_host_executive::update_host_params(Evm(X), EvmHostParamUpdate{ fee_token: TokenB, .. })`.
4. `update_host_params` dispatches the `SetHostParam` `PostRequest` to `HostManager` on chain X, then immediately executes: [9](#0-8) 
   committing `feeToken = TokenB` to `pallet-host-executive::HostParams` on Hyperbridge.
5. When the request is relayed and delivered, `EvmHost.updateHostParamsInternal` reverts with `CannotChangeFeeToken` because of the attacker's step-2 deposit: [4](#0-3) 
   The low-level call in `dispatchIncoming` fails silently (marked retryable, no revert propagated to Hyperbridge): [10](#0-9) 
6. `EvmHost._hostParams.feeToken` on chain X remains `TokenA`, while Hyperbridge's `pallet-host-executive::HostParams` now (permanently) records `feeToken = TokenB` — a confirmed on-chain desync with no reconciliation path, exactly reproducing the M-16 "state advanced without confirmed remote execution" invariant break.

    /**
     * @dev Updates the HostParams. Will reset all fishermen accounts and initialize any new state machines.
     * @param params, the new host params.
     */
    function updateHostParamsInternal(HostParams memory params) internal {
        // check the params to prevent the host from getting bricked.
        if (
            params.hostManager == address(0) || address(params.hostManager).code.length == 0
                || !IERC165(params.hostManager).supportsInterface(type(IApp).interfaceId)
        ) {
            // otherwise cannot process new cross-chain governance requests
            revert InvalidHostManager();
        }

        if (
            params.handler == address(0) || address(params.handler).code.length == 0
                || !IERC165(params.handler).supportsInterface(type(IHandlerV2).interfaceId)
        ) {
            // otherwise cannot process new datagrams
            revert InvalidHandler();
        }

        if (
            params.consensusClient == address(0) || address(params.consensusClient).code.length == 0
                || !IERC165(params.consensusClient).supportsInterface(type(IConsensusV2).interfaceId)
        ) {
            // otherwise cannot process new consensus datagrams
            revert InvalidConsensusClient();
        }

        // otherwise cannot process new cross-chain governance requests
        if (keccak256(params.hyperbridge) == keccak256(bytes(""))) revert InvalidHyperbridgeId();

        // otherwise cannot process new datagrams
        uint256 stateMachinesLen = params.stateMachines.length;
        if (stateMachinesLen == 0) revert InvalidStateMachinesLength();

        // otherwise cannot process new datagrams
        if (1 days > params.unStakingPeriod) revert InvalidUnstakingPeriod();

        address oldFeeToken = feeToken();
        if (oldFeeToken != address(0) && oldFeeToken != params.feeToken) {
            uint256 balance = IERC20(oldFeeToken).balanceOf(address(this));
            if (balance != 0) revert CannotChangeFeeToken();
        }

    function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
        address destination = _bytesToAddress(request.to);
        uint256 size;
        assembly {
            size := extcodesize(destination)
        }
        if (size == 0) {
            // instead of reverting the entire batch, early return here.
            return;
        }

        // replay protection
        bytes32 commitment = request.hash();
        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)
            .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));

        if (!success) {
            // so that it can be retried
            delete _requestReceipts[commitment];
            return;
        }
        emit PostRequestHandled({commitment: commitment, relayer: relayer});
    }

    function onAccept(IncomingPostRequest calldata incoming) external override restrict(_params.host) {
        PostRequest calldata request = incoming.request;
        // Only the Hyperbridge parachain can send requests to this module.
        if (!request.source.equals(IHost(_params.host).hyperbridge())) revert UnauthorizedAction();

        OnAcceptActions action = OnAcceptActions(uint8(request.body[0]));
        if (action == OnAcceptActions.Withdraw) {
            // This is where governance & relayers can withdraw their revenue.
            WithdrawParams memory withdrawParams = abi.decode(request.body[1:], (WithdrawParams));
            IHostManager(_params.host).withdraw(withdrawParams);
        } else if (action == OnAcceptActions.SetHostParam) {
            HostParams memory hostParams = abi.decode(request.body[1:], (HostParams));
            IHostManager(_params.host).updateHostParams(hostParams);
        }
    }
