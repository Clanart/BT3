### Title
Unvalidated `filepath` parameter in "Open in Desktop" deep links enables path traversal outside the cloned repository - (File: `app/src/lib/parse-app-url.ts`)

### Summary
`parseAppURL` in `app/src/lib/parse-app-url.ts` parses the `x-github-client://openRepo/...` (and legacy `github-mac://`/`github-windows://`) protocol handler URLs that GitHub Desktop registers as its deep-link handler [1](#0-0) . For the `openrepo` action it validates the `pr` and `branch` query parameters with strict regexes and `testForInvalidChars`, but it takes the `filepath` query parameter as-is with no validation whatsoever before returning it as part of `IOpenRepositoryFromURLAction` [2](#0-1) . This mirrors the structure of the Velocimeter finding: one value (`branch`) is properly bounds-checked while a sibling value used for the same downstream operation (`filepath`) is not, letting an attacker-controlled input flow unchecked into a filesystem operation.

### Finding Description
`IOpenRepositoryFromURLAction.filepath` is documented as "the file to open after cloning the repository" [3](#0-2) . Unlike `branch`, which is passed through `testForInvalidChars` before being accepted [4](#0-3) , `filepath` is read straight from the query string with `getQueryStringValue` and returned unmodified [5](#0-4) . This value is attacker-controlled end-to-end: it originates from a URL that the victim clicks (e.g. a crafted "Open in Desktop" link on a malicious web page or GitHub Enterprise instance), is handled by the OS protocol launcher, and dispatched into the app via `handleAppURL`/`window.sendURLAction(action)` [6](#0-5) .

Downstream, this action is consumed by `app/src/ui/dispatcher/dispatcher.ts` (10 references to `filepath` were found there), where the documented behavior is to open the referenced file after the repository has been cloned. Because the value is never checked for `..` traversal segments, absolute-path prefixes, or being confined to the destination clone directory (the same class of check that exists elsewhere in the codebase, e.g. `resolveWithin` in `app/src/lib/path.ts` which explicitly guards against `..` and symlink escapes [7](#0-6) , and `sanitizeCloneName`/`isClonePathSensitive` which guard the clone destination path [8](#0-7) [9](#0-8) ), a crafted deep link such as
`x-github-client://openRepo/https://github.com/owner/repo?filepath=..%2F..%2F..%2F..%2F.ssh%2Fid_rsa`
can cause Desktop to construct a path outside the freshly cloned repository and act on it (open with default program / reveal in file manager / open in external editor), exactly the kind of "no bound check on an attacker-influenced value used in a filesystem/asset resolution" bug the Velocimeter report describes for `paymentAmountToAddLiquidity`/`lpAmount`.

### Impact Explanation
If the consuming code in `dispatcher.ts` joins `filepath` to the clone destination and passes the result to `shell.openPath`/`revealInFileManager`/the external editor launcher without confining it to the repository root, an attacker who gets a victim to click a link can cause Desktop to open or reveal an arbitrary file on the victim's filesystem chosen by the attacker (e.g., SSH keys, config files, or files that trigger OS "open with default program" behavior such as `.exe`/`.scr`/`.desktop` payloads, depending on `isSafeFileExtension` gating). This matches the requested impact classes: "the result is code execution, file write or read outside the repo" via "a link or deep link the user clicks."

### Likelihood Explanation
The attack requires only that the victim click a link (a normal, expected user action for the "Open in Desktop" feature — no local access, no admin rights, and no pre-existing compromise are required). The protocol handler is registered by default on all supported platforms [1](#0-0) , and the vulnerable code path (`filepath` bypassing validation while `branch`/`pr` are validated) is directly visible in `parse-app-url.ts`.

### Recommendation
Validate `filepath` the same way `branch` is validated (reject invalid/traversal characters), and additionally resolve the final on-disk path with a helper equivalent to `resolveWithin` (already present in `app/src/lib/path.ts`) against the repository's cloned root before performing any file-system operation (open, reveal, edit) on it. Reject the action if the resolved path is not contained within the repository directory.

### Proof of Concept
```
x-github-client://openRepo/https://github.com/owner/repo?filepath=..%2F..%2F..%2F..%2F.ssh%2Fid_rsa
```
1. Attacker hosts this link and lures the victim to click it (e.g., embedded in a webpage or email).
2. The OS invokes GitHub Desktop's registered `x-github-client` protocol handler, which calls `handleAppURL` → `parseAppURL` [6](#0-5) .
3. `parseAppURL` returns `{ name: 'open-repository-from-url', url, branch: null, pr: null, filepath: '../../../../.ssh/id_rsa' }` unchanged, since no validation is applied to `filepath` [10](#0-9) .
4. Desktop clones `owner/repo` and (per the documented intent of the field) opens the file at the given `filepath` relative to the clone root, which resolves outside the intended repository directory.

Note: I was able to confirm the unsanitized parsing in `parse-app-url.ts`, but tool access ended before I could read the exact join/open call inside `app/src/ui/dispatcher/dispatcher.ts` that consumes `filepath` (10 references were located but not retrieved). The exact sink function/line should be confirmed by a developer with full repository access before remediation.

/**
 * Check whether a resolved clone path targets a sensitive location that
 * should never be used as a clone destination. This is a backstop against
 * path traversal attacks where a crafted URL tricks the UI into deriving
 * a clone path outside the intended base directory.
 */
function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}
