### Title
Airdrop.updateEndRemainingAllocation() has no snapshot guard, allowing an unprivileged attacker to fix the bonus denominator to steal other users' forfeited-allocation bonus - (File: rewards/Airdrop.sol)

### Summary
`updateEndRemainingAllocation()` is `public`, unguarded by any role check, and has no "already-snapshotted" protection beyond the caller-side `if (totalEndRemainingAllocation == 0)` gate inside `claim()`. Because the function itself can be called directly by anyone at any time once `block.timestamp >= periodsEndTime[4]`, an attacker can time (or front-run) the call to fix `totalEndRemainingAllocation` at an artificially small value right before their own `claim()`, inflating their share of `totalBonus` at the expense of every other unclaimed holder.

### Finding Description
The bonus mechanism is: [1](#0-0) 

`getBonusAmount()` computes `bonusAmount = userAllocation * totalBonus / totalEndRemainingAllocation`, and `claim()` only auto-triggers the snapshot the first time it is zero: [2](#0-1) 

`updateEndRemainingAllocation()` itself has no access control and no check that the value hasn't already been set — it unconditionally overwrites `totalEndRemainingAllocation = totalRemainingAllocation` whenever called after `periodsEndTime[4]`: [3](#0-2) 

Because `totalRemainingAllocation` monotonically shrinks as each user calls `claim()` (each claim zeroes the caller's `allocations[msg.sender]` and subtracts it from `totalRemainingAllocation`), any account can wait until most other eligible users have already claimed (shrinking `totalRemainingAllocation` down to close to their own remaining allocation), then in a single transaction call `updateEndRemainingAllocation()` followed immediately by `claim()`. This re-snapshots `totalEndRemainingAllocation` to a much smaller denominator than the value that would have been fairly fixed at the moment `periodsEndTime[4]` was first reached, so `bonusAmount = userAllocation * totalBonus / totalEndRemainingAllocation` is inflated far beyond the attacker's fair proportional share of the forfeited pool (`totalBonus`). The `if(claimableAmount > aidropToken.balanceOf(address(this))) revert InsufficientBalance();` check only prevents a single transfer that exceeds the current contract balance — it does not stop the attacker from consuming a disproportionate share of `totalBonus`/token balance that was reserved for other still-unclaimed users, who will subsequently be unable to claim their full entitled amount (their `claimableAmount` will still be computed against the depleted/incorrect bonus pool and contract balance).

### Impact Explanation
This breaks the invariant that the bonus denominator must be fixed once and be independent of transaction ordering/timing. An attacker can extract a larger-than-entitled share of `totalBonus` (funds forfeited by other users who didn't claim before `periodsEndTime[4]`), directly reducing the funds available to legitimate remaining claimants — a direct theft of other users' unclaimed/forfeited-yield funds, matching Critical - Direct theft of user funds.

### Likelihood Explanation
No privileged role is required — `updateEndRemainingAllocation()` and `claim()` are both `external`/`public` with no modifiers restricting the caller. The attack requires only that the attacker hold some non-zero `allocations[attacker]` (i.e., be a registered airdrop recipient) and wait until `periodsEndTime[4]` has passed and other users have already claimed (shrinking `totalRemainingAllocation`), then batch `updateEndRemainingAllocation()` + `claim()` in one transaction. This is trivially repeatable by any registered recipient and requires no capital beyond gas.

### Recommendation
Snapshot `totalEndRemainingAllocation` exactly once, guarded so it can never be overwritten after being set (e.g., use a separate boolean flag `bool public endRemainingAllocationSet`, or check `totalEndRemainingAllocation == 0 && totalBonus == 0`-style one-shot logic), and restrict who/when the snapshot can be taken (e.g., only settable automatically at the exact `periodsEndTime[4]` boundary via a keeper/owner call, or compute it deterministically without needing a stored, callable snapshot at all).

### Proof of Concept
1. Deploy `Airdrop` with a small set of registered allocations (e.g., users A, B, C, attacker) via `register()`.
2. Warp time to/past `periodsEndTime[4]`.
3. Have users A and B call `claim()` normally, triggering the first `updateEndRemainingAllocation()` call inside `claim()`, forfeiting some allocation into `totalBonus`, and shrinking `totalRemainingAllocation`.
4. Attacker deploys a helper contract (or simply calls in sequence within one tx via a batched call) that:
   - Calls `updateEndRemainingAllocation()` directly, re-snapshotting `totalEndRemainingAllocation` to the now-shrunk `totalRemainingAllocation`.
   - Immediately calls `claim()`.
5. Assert `getBonusAmount(attacker)` (and the actual transferred `claimableAmount`) is significantly larger than `attacker's allocation * totalBonus / (naively expected totalEndRemainingAllocation taken at first-ever periodsEndTime[4] crossing)`.
6. Assert that after all remaining legitimate users (C, etc.) call `claim()`, the sum of amounts they can withdraw is less than their fair proportional share of `totalBonus`, or that `claim()` reverts with `InsufficientBalance` for them — demonstrating `sum of all allocations` no longer reconciles with `aidropToken.balanceOf(address(this))` and that the attacker withdrew more than their entitled share.

    function updateEndRemainingAllocation() public {

            totalEndRemainingAllocation = totalRemainingAllocation;

    /// @notice Claim MGP and forfeit remaining allocation
    function claim() external {
        if (totalEndRemainingAllocation == 0) {
            updateEndRemainingAllocation();
        }
        uint256 claimableAmount = getClaimableAmount(msg.sender);
        
        if(claimableAmount == 0) revert NothingToClaim();
        if(claimableAmount > aidropToken.balanceOf(address(this))) revert InsufficientBalance();

        uint256 userAllocation = allocations[msg.sender];
        allocations[msg.sender] = 0;
        totalRemainingAllocation -= userAllocation;
        if (claimableAmount <= userAllocation) {
            uint256 forfeited = userAllocation - claimableAmount;
            totalBonus += forfeited;
        }
        aidropToken.safeTransfer(msg.sender, claimableAmount);
    }
