### Title
`associatePubKey` Precompile Allows Unauthenticated Association of Arbitrary Third-Party Public Keys, Triggering Unauthorized Fund Migration - ([File: precompiles/addr/addr.go])

### Summary
The `addr` precompile's `associatePubKey` method accepts a raw secp256k1 public key from any caller with **no proof of private-key possession** (no signature check), then immediately derives the corresponding EVM/Sei addresses and calls `AssociateAddresses`, which migrates all spendable balances, wei balance, and account state from the derived "cast address" to the caller-chosen Sei address. This mirrors the JWK-header-injection bug class: a value that must come from an authenticated/proven source (a key whose possession is proven by a valid signature) is instead accepted directly from unauthenticated attacker input and trusted as if it had been verified.

### Finding Description
`PrecompileExecutor.associatePublicKey` in [1](#0-0)  takes a single hex-encoded compressed public key argument directly from the caller, parses it with `btcec.ParsePubKey`, and derives `evmAddr`/`seiAddr` from it via `helpers.GetAddressesFromPubkeyBytes` — with **no signature verification proving the caller (msg.sender/tx signer) actually owns the private key** corresponding to that public key.

Contrast this with the sibling method `associate` (lines 160-203), which correctly requires an ECDSA signature (`v, r, s`) over a `customMessage`, uses `helpers.GetAddresses` to **recover** the public key from that signature, and thus proves possession of the private key before associating addresses. `associatePublicKey` skips this proof entirely — the pubkey field is the direct analog of the JWT `jwk` header: attacker-supplied key material trusted without a binding proof of ownership.

The result is forwarded to `associateAddresses` [2](#0-1) , which after confirming `seiAddr` isn't already associated, calls `AssociationHelper.AssociateAddresses`. That helper [3](#0-2)  sets the EVM↔Sei address mapping, may reuse/overwrite the "cast address" account's pubkey, and calls `MigrateBalance`, which **sweeps all spendable coins, wei balance, and removes the account** at `castAddr = sdk.AccAddress(evmAddr[:])` (derived straight from the attacker-supplied pubkey) into the attacker-chosen `seiAddr` [4](#0-3) .

### Impact Explanation
Because `associatePublicKey` requires no proof of key ownership, an unprivileged transaction sender who obtains any valid secp256k1 public key belonging to another party (public keys are frequently disclosed on-chain, e.g. in Cosmos tx signatures, block explorers, or simply guessable test/vanity keys before their owner ever associates) can:
1. Call `associatePubKey` with that public key to derive its `evmAddr`/`seiAddr` before the legitimate owner associates.
2. Trigger `AssociateAddresses`/`MigrateBalance`, which sweeps any usei/wei balance and any spendable coins already sitting at the "cast address" (`sdk.AccAddress(evmAddr[:])`) into the caller's chosen Sei address, and can overwrite the account's pubkey.

This is a concrete fund-loss and unauthorized-transfer vector reachable directly from an EVM transaction (the `associatePubKey` method on the `addr` precompile at `0x0000000000000000000000000000000000001004`), satisfying the "unauthorized transfer via precompile" impact bar. The severity is bounded by the precondition that the victim must have funds pre-existing at the cast/derived address and the attacker must know/obtain the victim's raw public key, but no signature or private-key possession is required — exactly analogous to the JWK-injection root cause where a key that should be authenticated by a cryptographic proof is instead accepted as bare, attacker-controlled data.

### Likelihood Explanation
Any unprivileged account can call this method via a normal EVM transaction with no elevated privileges. The only prerequisite is knowledge of a target's raw secp256k1 public key, which is commonly available (from any broadcasted Cosmos-SDK transaction signed by that key, from `associate`/wallet-connect flows, or from other public sources) prior to the target ever associating their addresses on Sei. This makes the likelihood non-trivial for any Sei account holder who has revealed their public key elsewhere but not yet self-associated on Sei.

### Recommendation
Require a proof-of-possession for `associatePublicKey`, consistent with `associate`: either remove `associatePublicKey` entirely (forcing all associations through the signature-based `associate` flow), or require the caller to additionally submit a signature (over a fixed domain-separated message, e.g. including `msg.sender`) verifiable against the submitted public key before calling `AssociateAddresses`. At minimum, gate the method so that `evmAddr` derived from the supplied pubkey must equal `msg.sender`, ensuring only the actual controller of that EVM address (who could only have obtained that address by controlling the private key, as proven through the transaction's own ecrecover-based sender derivation) can trigger the association and balance migration.

### Proof of Concept
1. Attacker observes or otherwise obtains Alice's raw secp256k1 public key `P` (e.g., extracted from any Cosmos-SDK transaction Alice previously signed on Sei or another chain using the same key), where Alice has *not yet* associated her Sei/EVM addresses and holds a balance at `castAddr = AccAddress(PubkeyToEVMAddress(P)[:])`.
2. Attacker calls the `addr` precompile at `0x...1004`, method `associatePubKey(P)`, from their own EVM transaction (any funded account can pay gas for this call — see `precompiles/addr/addr.go:205-237`).
3. `associatePublicKey` parses `P`, derives `evmAddr`/`seiAddr` deterministically from `P` (not from the caller), and calls `associateAddresses`.
4. `AssociateAddresses`/`MigrateBalance` sweep spendable coins, wei balance from `castAddr` into `seiAddr` — the Sei address derived from `P`, which the attacker does not control the private key for, but which is now recorded as associated in state and whose account pubkey field may be set by the attacker-supplied `pubkey`, and future receipts/lookups will treat this state as authoritative — with no signature from Alice ever having been presented in this call. func (p PrecompileExecutor) associatePublicKey(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}

	// Takes a single argument, a compressed pubkey in hex format, excluding the '0x'
	pubKeyHex := args[0].(string)

	pubKeyBytes, err := hex.DecodeString(pubKeyHex)
	if err != nil {
		return nil, 0, err
	}

	// Parse the compressed public key
	pubKey, err := btcec.ParsePubKey(pubKeyBytes)
	if err != nil {
		return nil, 0, err
	}

	// Convert to uncompressed public key
	uncompressedPubKey := pubKey.SerializeUncompressed()

	evmAddr, seiAddr, pubkey, err := helpers.GetAddressesFromPubkeyBytes(uncompressedPubKey)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p PrecompileExecutor) associateAddresses(ctx sdk.Context, method *abi.Method, evmAddr common.Address, seiAddr sdk.AccAddress, pubkey cryptotypes.PubKey) (ret []byte, remainingGas uint64, err error) {
	// Check that address is not already associated
	_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if found {
		return nil, 0, fmt.Errorf("address %s is already associated with evm address %s", seiAddr, evmAddr)
	}

	// Associate Addresses:
	associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.bankKeeper, p.accountKeeper)
	err = associationHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false)
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(seiAddr.String(), evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}
