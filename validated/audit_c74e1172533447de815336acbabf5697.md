Confirmed vulnerability: static `Precompile.Prepare` (precompiles/common/precompiles.go:101-122) calls `method.Inputs.Unpack(argsBz)` directly, before any string-copy-proportional gas charge — gas is only checked against `RequiredGas`, which for the static path is a linear-in-calldata-length charge computed by each executor's `RequiredGas` (mirroring `DefaultGasCost`). Unlike the `DynamicGasPrecompile` path, which was explicitly hardened with `chargeDecodeGas`/`DecodeGasCost` in `precompiles/common/precompiles.go:217-247`, the static path has no such surcharge, so an attacker can craft ABI calldata (aliased offsets making one string body referenced by many array/tuple slots, exactly the pattern in `precompiles/common/decode_cost_test.go`'s `newAliasedVoteWeightedArgs`) whose `Unpack` copy volume is `O(len(input)^2)` while paid gas stays linear.

### Title
Static (non-dynamic-gas) Cosmos precompiles skip the O(n²) ABI-decode gas surcharge, enabling a calldata-driven CPU DoS - ([File: precompiles/common/precompiles.go])

### Summary
`Precompile.Prepare` unconditionally calls `method.Inputs.Unpack(argsBz)` on attacker-controlled EVM calldata for every static precompile (bank, staking, distribution, oracle, pointer, pointerview, wasmd, addr, auth, authz, etc.), while the only gas charged against that call is `RequiredGas`, a linear-in-length estimate. The codebase already recognizes and fixes this exact bug class for `DynamicGasPrecompile` via `chargeDecodeGas`/`DecodeGasCost`, but the static path was left unprotected.

### Finding Description
`go-ethereum`'s ABI unpacker materializes each `string`/`bytes32[]`-type payload via `string(output[begin:end])`; because a single dynamic payload's offset can be referenced by many array/tuple slots (aliasing), the total copy volume can be quadratic in `len(input)` even though the calldata itself is linear-sized. The repository's own comments and tests document this precisely: [1](#0-0) 
and it is exploited/tested in `newAliasedVoteWeightedArgs`/`craftAliasedVoteWeightedArgs`: [2](#0-1) 

For `DynamicGasPrecompile.RunAndCalculateGas`, this is explicitly mitigated: the method ID is resolved without decoding args, then `chargeDecodeGas` charges `DecodeGasCost` (linear scan + string-copy surcharge) against the gas meter *before* `method.Inputs.Unpack` is invoked: [3](#0-2) [4](#0-3) 

However, the static `Precompile.Prepare`/`Run` path — used by all non-dynamic-gas Cosmos precompiles — calls `Unpack` directly with no such surcharge: [5](#0-4) 
The EVM only enforces `RequiredGas(input)` before invoking `Run`, and `RequiredGas` for these precompiles is a simple per-byte linear charge (mirroring `DefaultGasCost`, not `DecodeGasCost`). A caller can therefore submit calldata sized to satisfy the cheap linear `RequiredGas` check yet whose ABI shape (any method taking `string`, `string[]`, or nested dynamic tuple/array arguments containing strings) causes `Unpack` to copy `O(len(input)^2)` bytes, exactly mirroring the Discourse `Base62.decode` O(n²) worker-exhaustion bug: a single crafted request ties up a block-processing worker for a duration wildly disproportionate to the gas paid.

### Impact Explanation
Because Sei's block processing is gas-metered but the *time* to service that gas is assumed near-linear, a quadratic-blowup call can consume tens of seconds of wall-clock CPU while charging only linear gas, delaying the block beyond the network's block-time budget (well over 2.5 seconds) and potentially stalling validators processing the same transaction (deterministic execution means every validator pays the same CPU cost). This matches the "block delay beyond 2.5 seconds" / "validator halt" acceptance criteria.

### Likelihood Explanation
Any unprivileged EVM transaction sender can invoke a static precompile with crafted calldata containing string-typed arguments; no special privilege, governance, or validator access is required. The attack primitive (aliased dynamic-type offsets) is already demonstrated working against the dynamic-gas path in the repo's own tests, confirming feasibility for any ABI method with a `string`/`string[]`/tuple-with-string argument on the static precompiles.

### Recommendation
Apply the same `chargeDecodeGas`/`DecodeGasCost` surcharge used by `DynamicGasPrecompile` to the static `Precompile.Prepare` path (or migrate all precompile executors whose methods contain string/dynamic-array arguments to the `DynamicGasPrecompile` model), charging the string-copy-proportional cost before calling `method.Inputs.Unpack`.

### Proof of Concept
1. Choose any static precompile method taking a `string[]` or tuple-with-string argument (e.g., an analogous method on `bank`, `staking`, `distribution`, `oracle`, `pointer`, or `wasmd` precompiles).
2. Build calldata using the same aliasing technique as `craftAliasedVoteWeightedArgs`/`newAliasedVoteWeightedArgs` ( [2](#0-1) ): make `k` array-tuple offsets all point at one shared dynamic-string body of length `s`, so calldata size is `O(k+s)` but `Unpack`'s copy volume is `O(k*s)`.
3. Submit an EVM transaction calling that method with gas just above the linear `RequiredGas(input)` estimate.
4. Observe that `Precompile.Prepare`'s `method.Inputs.Unpack(argsBz)` call performs `O(k*s)` byte copies, consuming CPU time far exceeding what the charged gas represents, without ever going through the `chargeDecodeGas` guard that protects the `DynamicGasPrecompile` path.

**Uncertainty**: I was not able to fully confirm within available searches which specific static precompile methods (bank/staking/distribution/oracle/pointer/wasmd/etc.) expose `string`, `string[]`, or nested dynamic-tuple-with-string ABI arguments reachable by an unprivileged caller — this would need to be verified per-precompile ABI to pick the highest-impact concrete PoC target, but the vulnerable code path (`precompiles/common/precompiles.go:101-122` lacking the `DecodeGasCost` surcharge that the dynamic-gas path applies) is confirmed structurally.

func craftAliasedVoteWeightedArgs(k, s uint64) []byte {
	tupleRel := 32 * k
	arrayPayload := make([]byte, 0, int(32*k+64+s))
	for range k {
		arrayPayload = append(arrayPayload, abiWord(tupleRel)...)
	}
	arrayPayload = append(arrayPayload, abiWord(s)...)
	arrayPayload = append(arrayPayload, abiWord(0)...)
	arrayPayload = append(arrayPayload, make([]byte, s)...)

	data := append(abiWord(1), abiWord(64)...)
	data = append(data, abiWord(k)...)
	data = append(data, arrayPayload...)
	return data
}

		return sdk.Context{}, nil, nil, err
	}

// chargeDecodeGas charges the (already-installed) gas meter for decoding the
// calldata, before it is decoded: a length-proportional scan cost that also
// bounds the DecodeGasCost scan, then the string-copy surcharge from
// DecodeGasCost. Its out-of-gas / overflow recovery is deliberately scoped to
// just these charges — a call that cannot afford the decode reverts here, while
// an executor that later exhausts its gas keeps its normal propagating
// out-of-gas semantics. Anything other than a gas-meter panic is re-raised.
func (d DynamicGasPrecompile) chargeDecodeGas(ctx sdk.Context, method *abi.Method, input []byte) (err error) {
	defer func() {
		if r := recover(); r != nil {
			switch r.(type) {
			case sdk.ErrorOutOfGas, sdk.ErrorGasOverflow:
				err = fmt.Errorf("%v", r)
			default:
				panic(r)
			}
		}
	}()
	scanCost := DefaultGasCost(input, false)
	ctx.GasMeter().ConsumeGas(scanCost, fmt.Sprintf("%s precompile calldata scan", d.name))
	decodeCost, ok := DecodeGasCost(method.Inputs, input)
	if !ok {
		// Calldata is structurally invalid (Unpack would reject it too); reject
		// now, without attempting the decode.
		return fmt.Errorf("invalid calldata encoding for %s", d.name)
	}
	// DecodeGasCost already includes scanCost; charge only the remaining
	// (string-copy) portion so the decode is priced exactly once.
	ctx.GasMeter().ConsumeGas(decodeCost-scanCost, fmt.Sprintf("%s precompile calldata decode", d.name))
	return nil
}
