### Title
Attacker-controlled `ReceivedOutput` deserialization binds an arbitrary offset to an arbitrary output, reporting funds as received which are not spendable - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
Analogous to CVE-2025-70084, where a crafted value fed to a getter reaches a sensitive sink unsanitized, `ReceivedOutput::read` (networks/bitcoin/src/wallet/mod.rs:122-134) decodes a scalar `offset`, a `TxOut`, and an `OutPoint` from untrusted bytes without ever validating that `offset` actually derives the `script_pubkey`'s key. The honest producer path (`Scanner::scan_transaction`, lines 199-214) always emits a triple where `script_pubkey == p2tr_script_buf(key + G*offset)`, but `read` accepts any combination, so a forged byte stream produces a `ReceivedOutput` that is "received" yet unspendable.

### Finding Description
`ReceivedOutput` is the type downstream code treats as a spendable output: `value()` (lines 116-118) reports the amount, and the consumer in `processor/src/networks/bitcoin.rs:686-700` maps `output.offset()` through a `kinds` table and later derives the spending key as `script_key - G*offset` (`Output::key`, lines 112-122). `read` at lines 122-133 performs only canonicality checks (`Secp256k1::read_F`) and consensus decoding of the `TxOut`/`OutPoint`; it never recomputes `p2tr_script_buf(key + G*offset)` against `output.script_pubkey`, and the base key isn't even part of the object. There is also no check that `script_pubkey` is P2TR, so `Output::key` will panic on a non-P2TR script (`assert!(script.is_p2tr())`, processor/src/networks/bitcoin.rs:114). This is the traversal analog: attacker-chosen "path components" (offset, script, outpoint) are concatenated into a security-relevant object without a canonicality/binding check at the boundary.

### Impact Explanation
A party feeding crafted bytes into `ReceivedOutput::read` can cause the wallet layer to report funds received (a balance via `value()`) that cannot be spent: the stored `offset` does not derive the taproot internal key embedded in `script_pubkey`, so the resulting `ThresholdKeys` offset will not produce signatures for that UTXO. Alternatively a non-P2TR script crashes the consumer's key derivation. This matches the report's class (crafted input reaching a sensitive operation gives access/deletion of resources not authorized) in Serai's shape: the resource is the registered scanner script set and the spending-key derivation, not a filesystem.

### Likelihood Explanation
Exploitation requires the attacker to control bytes passed to `ReceivedOutput::read` — untrusted serialized wallet data. The bug needs no secret, no collusion, and no malformed curve point (encodings are canonical); it is purely a missing structural validation. Severity is Medium: it causes unspendable-funds misreporting or a panic rather than direct key/signature compromise.

### Recommendation
Include the base key in the validation context: have `read` (or a new `read_for(scanner_or_key)`) recompute `p2tr_script_buf(key + ProjectivePoint::GENERATOR * offset)` and require it equals `output.script_pubkey`, rejecting non-P2TR scripts and unregistered scripts. Alternatively document `read` as trusted-inputs-only and add a `verify_against(&Scanner)` method consumers must call before crediting the output.

### Proof of Concept
```rust
// networks/bitcoin/src/wallet/mod.rs consumer scenario
// base key: let key: ProjectivePoint = ...; let scanner = Scanner::new(key).unwrap();

// Attacker crafts bytes: offset is random, script_pubkey is the real
// registered script (or an arbitrary non-P2TR script).
let evil_offset = Scalar::random(&mut OsRng); // does NOT satisfy p2tr(key + G*evil_offset) == script
let mut buf = Vec::new();
buf.extend(evil_offset.to_bytes());
buf.extend(serialize(&TxOut {
    value: Amount::from_sat(100_000),
    script_pubkey: p2tr_script_buf(key).unwrap(), // victim's script
}));
buf.extend(serialize(&OutPoint::new(Txid::all_zeros(), 0)));

let forged = ReceivedOutput::read(&mut buf.as_slice()).unwrap();
assert_eq!(forged.value(), 100_000); // reported as received
// key + G*forged.offset() != internal key of the script -> unspendable,
// and Output::key() would derive a wrong point; a non-P2TR script panics instead.
```
