This confirms the analog. The current `precompiles/pointer/pointer.go` `AddNative`/`AddCW20`/`AddCW721`/`AddCW1155` methods all call `Upsert*Pointer`, which resolves to `UpsertERCPointer` in `x/evm/keeper/pointer_upgrade.go`, and this function re-deploys/overwrites the bytecode at the *existing* pointer contract address whenever it's called again with new constructor args (name/symbol/decimals), without any restriction against calling it more than once.

### Title
Native/CW ERC20-Pointer contracts can have their immutable name/symbol/decimals silently rewritten via repeated `addNativePointer`/`addCW*Pointer` calls - ([File: x/evm/keeper/pointer_upgrade.go])

### Summary
The pointer precompile (`0x100b`) lets any EVM caller register or "upsert" an ERC20/721/1155 pointer contract for a native/tokenfactory denom or CW20/721/1155 contract. Unlike a normal one-time deployment, `UpsertERCPointer` detects an existing pointer and **redeploys the constructor bytecode over the same contract address**, meaning `name`, `symbol`, and `decimals` (baked into the immutable pointer bytecode) can be changed after the pointer has already been created and is in use by integrators.

### Finding Description
`AddNative` in [1](#0-0)  reads the *current* bank denom metadata (name/symbol/decimals) and calls `p.evmKeeper.UpsertERCNativePointer`, with no check on whether the caller is the original registrant or whether the pointer has been in use. `UpsertERCPointer` in [2](#0-1)  then does:

```
existingAddr, _, exists := getter(liveCtx(), pointee)
...
if exists {
    contractAddr = existingAddr
    ret, remainingGas, err = evm.GetDeploymentCode(evmModuleAddress, bin, suppliedGas, utils.Big0, existingAddr)
    ...
    k.SetCode(writeCtx, contractAddr, ret)
    ...
}
```

Instead of rejecting a repeat registration (as the CW20 pointer path in the legacy code did with an explicit `existingVersion >= 1` guard, see [3](#0-2) ), the current `UpsertERCPointer` unconditionally re-runs the constructor with the newly supplied `name`/`symbol`/`decimals` args and overwrites the deployed bytecode at the exact same address via `k.SetCode`.

Because the name/symbol/decimals fed into the constructor come straight from the bank denom metadata at call time (`p.bankKeeper.GetDenomMetaData`), any subsequent change to that metadata — e.g. a tokenfactory admin calling `MsgSetDenomMetadata`, gated only by per-denom `Admin` authority check in [4](#0-3)  — followed by anyone re-invoking `addNativePointer(denom)` on the public pointer precompile, silently rewrites the immutable identity fields of an already-deployed, already-integrated ERC20 pointer contract at its unchanged address. The same unconditional-upsert pattern applies to CW20/CW721/CW1155 pointers (`AddCW20`/`AddCW721`/`AddCW1155` in [5](#0-4) ), where name/symbol are simply re-queried from the CW contract's live `token_info`/`contract_info` and re-applied.

This is the direct analog of the reported `setInfo()` bug: an unrestricted, repeatable call path allows post-deployment mutation of a token's identity fields, with no "set once" guard.

### Impact Explanation
Downstream contracts, wallets, exchanges, and bridges that resolve a token's identity by its deployed pointer contract address rely on `name()`/`symbol()`/`decimals()` being immutable once integrated. Silently changing these values in place (a metamorphic-contract-style rewrite at the same address) enables token-identity spoofing/confusion attacks: a denom's admin can rebrand a pointer contract to mimic a different, trusted token's name/symbol after the pointer address has already been advertised and adopted, or change `decimals` to corrupt amount interpretation in integrators that cache metadata by address, potentially causing fund-handling errors or fraud against users who trust the address as belonging to a specific asset.

### Likelihood Explanation
Reachable by any unprivileged caller: the pointer precompile has no ACL beyond `ValidateNonPayable`/`ValidateArgsLength`, and denom metadata mutation only requires the tokenfactory per-denom admin role (attacker-controlled if the attacker owns the tokenfactory denom in question, or any denom admin who wants to rug integrators later). No governance action is required to trigger the pointer rewrite itself — only the initial `SetDenomMetadata`/CW state update plus a plain `addNativePointer`/`addCW20Pointer` call.

### Recommendation
Add a guard in `UpsertERCPointer` (and/or `AddNative`/`AddCW20`/`AddCW721`/`AddCW1155`) so that once a pointer exists for a given pointee, subsequent calls either no-op, fail, or only allow authorized/version-gated updates (mirroring the legacy `existingVersion >= 1` check that used to block re-registration), rather than unconditionally overwriting the deployed bytecode/constructor state at the existing address.

### Proof of Concept
1. Tokenfactory admin creates denom `factory/{admin}/COIN` and sets bank metadata `Name: "COIN", Symbol: "COIN"`.
2. Any user calls pointer precompile `addNativePointer("factory/{admin}/COIN")`; a pointer ERC20 contract is deployed at address `P` with `name()=="COIN"`, `symbol()=="COIN"`. Integrators/wallets record `P` as the ERC20 representation of COIN.
3. Admin calls `MsgSetDenomMetadata` on the same denom, changing `Name`/`Symbol` to e.g. `"USDC"`/`"USDC"` — allowed because the only check is `msg.Sender == authorityMetadata.Admin` [6](#0-5) .
4. Anyone calls `addNativePointer("factory/{admin}/COIN")` again; `UpsertERCPointer` finds `exists == true`, redeploys the constructor with the new name/symbol, and overwrites the bytecode at the same address `P` via `k.SetCode` [7](#0-6) .
5. `P.name()`/`P.symbol()` now return `"USDC"`/`"USDC"` even though every prior integration assumed `P` was the immutable pointer for `COIN`.

func (k *Keeper) UpsertERCPointer(
	ctx sdk.Context, evm *vm.EVM, typ string, args []interface{}, getter PointerGetter, setter PointerSetter,
) (contractAddr common.Address, err error) {
	pointee := args[0].(string)
	evmModuleAddress := k.GetEVMAddressOrDefault(ctx, k.AccountKeeper().GetModuleAddress(types.ModuleName))

	var bin []byte
	bin, err = artifacts.GetParsedABI(typ).Pack("", args...)
	if err != nil {
		panic(err)
	}
	bin = append(artifacts.GetBin(typ), bin...)
	// GetDeploymentCode / Create take EVM snapshots that Freeze() Multistore layers.
	// Exists-lookup and commits must use the live unfrozen top (sdb.Ctx): cachekv
	// forbids writing a frozen layer, and same-tx readers that skip frozen-empty
	// parents would miss those writes. The precompile Prepare `ctx` is that top at
	// Prepare time, but is frozen once this Upsert snapshots. Always attach the
	// caller's gas meter (finite precompile meter in deliver) — sdb.Ctx() alone
	// carries the infinite EVM meter.
	sdb := state.GetDBImpl(evm.StateDB)
	liveCtx := func() sdk.Context {
		if sdb == nil {
			return ctx
		}
		return sdb.Ctx().WithGasMeter(ctx.GasMeter())
	}
	existingAddr, _, exists := getter(liveCtx(), pointee)
	suppliedGas := k.getEvmGasLimitFromCtx(ctx)
	var remainingGas uint64
	if exists {
		var ret []byte
		contractAddr = existingAddr
		ret, remainingGas, err = evm.GetDeploymentCode(evmModuleAddress, bin, suppliedGas, utils.Big0, existingAddr)
		if err != nil {
			return
		}
		// Only write on success: a failed GetDeploymentCode can leave ret as nil or
		// revert data, which must not clobber live pointer bytecode (even transiently).
		writeCtx := liveCtx()
		k.SetCode(writeCtx, contractAddr, ret)
		if sdb != nil {
			sdb.RefreshCodeCache(contractAddr, ret)
		}
	} else {
		_, contractAddr, remainingGas, err = evm.Create(evmModuleAddress, bin, suppliedGas, uint256.NewInt(0))
	}
	if err != nil {
		return
	}
	ctx.GasMeter().ConsumeGas(k.GetCosmosGasLimitFromEVMGas(ctx, suppliedGas-remainingGas), "ERC pointer deployment")
	if err = setter(liveCtx(), pointee, contractAddr); err != nil {
		return
	}
