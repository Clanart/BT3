## Title
Sender is charged the base fee twice per EVM transaction — `RefundGas` burns `baseFee * gasUsed` directly from the sender in addition to the base fee already collected via the upfront fee deduction, causing systemic unauthorized extraction of user funds - (File: `x/vm/keeper/gas.go`)

### Summary
`RefundGas` in `x/vm/keeper/gas.go` burns `baseFee * gasUsed` directly from the transaction sender's account, on top of the fee already collected upfront by the ante handler at `gasLimit * effectivePrice` (where `effectivePrice = tip + baseFee`, capped by `gasFeeCap`). Because the upfront-collected amount already embeds the base-fee component for the gas ultimately used, this second burn is an unbudgeted deduction, extracting extra funds from the user beyond what they authorized when signing the transaction (`gasFeeCap * gasUsed`).

### Finding Description
For every EIP-1559 (dynamic fee) transaction, fees are handled in two independent places that must reconcile with each other:

1. **Ante handler — upfront collection.** `evmkeeper.VerifyFee` computes the fee to collect as `gas * (gasTip + baseFee)` (i.e., `gasLimit * effectivePrice`), and `ConsumeFeesAndEmitEvent` → `deductFees` → `DeductTxCostsFromUserBalance` moves that full amount from the sender to the `FeeCollector` module account: [1](#0-0) [2](#0-1) [3](#0-2) 

2. **Post-execution — `RefundGas`.** After EVM execution, `ApplyTransaction` calls `RefundGas` with the actual `leftoverGas`/`gasUsed`: [4](#0-3) 

Inside `RefundGas`:
- `remaining = leftoverGas * msg.GasPrice` is refunded from the `FeeCollector` back to the sender. Since `msg.GasPrice` is set to the effective price (`min(tip+baseFee, feeCap)`) by `MsgEthereumTx.AsMessage`, this correctly returns the unused portion, leaving the `FeeCollector` holding `gasUsed * effectivePrice` — which already includes both the tip and the base-fee component for `gasUsed`.
- Then, **in addition**, `baseFeeRefund = baseFee * gasUsed` is burned directly **from the sender's own account** via `k.bankWrapper.BurnAmountFromAccount(ctx, msg.From.Bytes(), baseFeeRefund)`. [5](#0-4) [6](#0-5) 

`BurnAmountFromAccount` performs a real transfer-and-burn from the sender's spendable balance: [7](#0-6) 

Net effect on the sender's balance for a single transaction:
- Upfront deduction: `-gasLimit * effectivePrice`
- Refund: `+leftoverGas * effectivePrice`
- Extra burn: `-baseFee * gasUsed`

Total removed from sender = `gasUsed * effectivePrice + baseFee * gasUsed = gasUsed * (tip + 2*baseFee)`.

This means the sender pays the base-fee component of `gasUsed` **twice**: once implicitly as part of the amount already sitting in `FeeCollector`, and again as a separate burn taken straight from the sender's remaining balance. The user only ever authorized paying up to `gasFeeCap * gasUsed`, but the protocol extracts more than that whenever `baseFee > 0`, which is the default state on any chain with the fee market enabled (`NoBaseFee=false`).

### Impact Explanation
This is a deterministic, unprivileged-user-triggered, unauthorized extraction of user funds that occurs on essentially every ordinary EVM transaction on a chain where the base fee is active (which is the default/expected configuration). It breaks the fundamental invariant that a transaction sender never pays more than the fee they cryptographically authorized (`gasFeeCap`). Over time this results in continuous, protocol-level over-extraction of value from every EVM user's balance, i.e., accounting corruption of spendable user value. This matches the required "Critical … unauthorized extraction of user funds … or irreversible accounting corruption of spendable user value across native balances" impact class, and is directly analogous to the referenced Paymaster bug where a mismatched/duplicated gas-cost calculation caused the payer to be charged (or to pay out) more than the correct, agreed amount.

### Likelihood Explanation
High likelihood/always-triggered: this path executes on every single dynamic-fee (EIP-1559 type) Ethereum transaction processed through `ApplyTransaction` → `RefundGas` whenever `baseFee > 0` and `gasUsed > 0`, with no special preconditions, privileged role, or adversarial setup required — it is simply the default state-transition flow for regular users.

### Recommendation
`RefundGas` should not burn `baseFee * gasUsed` from the sender's own account a second time. Instead:
- Either burn the base-fee portion from the `FeeCollector` module account (which already holds `gasUsed * effectivePrice` after the refund step), or
- Track a distinct, module-level burn of the base fee as part of standard EIP-1559 processing (separate from the per-transaction sender-side refund logic), ensuring the total amount ever removed from the sender's balance equals exactly `gasUsed * effectivePrice` (bounded by `gasFeeCap * gasUsed`), matching what was actually collected upfront.

### Proof of Concept
Conceptual trace (verifiable by code inspection since balances are computed deterministically):
1. User signs and submits a `DynamicFeeTx` with `gasLimit = G`, `gasFeeCap = F`, `gasTipCap = T`, on a block where `baseFee = B` (`B>0`), so `effectivePrice = min(T+B, F)`.
2. Ante handler (`mono_decorator.go`) computes `msgFees = VerifyFee(...) = G * effectivePrice` and deducts this entire amount from the sender to `FeeCollector`. [8](#0-7) 
3. EVM executes, consuming `gasUsed = U < G`, leaving `leftoverGas = G - U`.
4. `ApplyTransaction` calls `RefundGas(ctx, *msg, leftoverGas, U, baseFee, denom)`. [4](#0-3) 
5. Inside `RefundGas`:
   - `remaining = leftoverGas * effectivePrice` sent back from `FeeCollector` to sender. `FeeCollector` now net-holds `U * effectivePrice`.
   - `baseFeeRefund = B * U` is additionally **burned from the sender's account balance directly** (not from `FeeCollector`). [5](#0-4) 
6. Sender's net balance change = `-(G*effectivePrice) + (leftoverGas*effectivePrice) - (B*U) = -(U*effectivePrice) - (B*U) = -U*(T+B) - U*B = -U*(T+2B)`.
7. This exceeds the maximum amount the sender authorized for `U` gas units (`U * F`, since `effectivePrice ≤ F`), whenever `B>0`, demonstrating an unauthorized extraction of funds beyond the signed transaction's fee cap.

func (k *Keeper) RefundGas(ctx sdk.Context, msg core.Message, leftoverGas uint64, gasUsed uint64, baseFee *big.Int, denom string) error {
	// Return EVM tokens for remaining gas, exchanged at the original rate.
	remaining := new(big.Int).Mul(new(big.Int).SetUint64(leftoverGas), msg.GasPrice)

	// refundable amount for base fee: baseFee * gasUsed
	baseFeeRefund := big.NewInt(0)
	if msg.GasPrice.Sign() > 0 && baseFee != nil && baseFee.Sign() > 0 && gasUsed > 0 {
		baseFeeRefund = new(big.Int).Mul(baseFee, new(big.Int).SetUint64(gasUsed))
	}

	refundAmt := new(big.Int).Add(remaining, baseFeeRefund)

	switch refundAmt.Sign() {
	case -1:
		// negative refund errors
		return errorsmod.Wrapf(types.ErrInvalidRefund, "refunded amount value cannot be negative %d", refundAmt.Int64())
	case 1:
		// positive amount refund
		refundedCoins := sdk.Coins{sdk.NewCoin(denom, sdkmath.NewIntFromBigInt(refundAmt))}

		// refund to sender from the fee collector module account, which is the escrow account in charge of collecting tx fees
		err := k.bankWrapper.SendCoinsFromModuleToAccount(ctx, authtypes.FeeCollectorName, msg.From.Bytes(), refundedCoins)
		if err != nil {
			err = errorsmod.Wrapf(errortypes.ErrInsufficientFunds, "fee collector account failed to refund fees: %s", err.Error())
			return errorsmod.Wrapf(err, "failed to refund %d leftover gas (%s)", leftoverGas, refundedCoins.String())
		}
	default:
		// no refund, consume gas and update the tx gas meter
	}

	// burn baseFee * gasUsed from the sender account after refund
	if baseFeeRefund.Sign() > 0 {
		if err := k.bankWrapper.BurnAmountFromAccount(ctx, msg.From.Bytes(), baseFeeRefund); err != nil {
			return errorsmod.Wrapf(err, "failed to burn base fee from sender %s", msg.From.Hex())
		}
	}

// AsMessage vendors the core.TransactionToMessage function to avoid sender recovery,
// assume the From field is set correctly in the MsgEthereumTx.
func (msg MsgEthereumTx) AsMessage(baseFee *big.Int) *core.Message {
	tx := msg.AsTransaction()
	ethMsg := &core.Message{
		Nonce:                 tx.Nonce(),
		GasLimit:              tx.Gas(),
		GasPrice:              new(big.Int).Set(tx.GasPrice()),
		GasFeeCap:             new(big.Int).Set(tx.GasFeeCap()),
		GasTipCap:             new(big.Int).Set(tx.GasTipCap()),
		To:                    tx.To(),
		Value:                 tx.Value(),
		Data:                  tx.Data(),
		AccessList:            tx.AccessList(),
		SetCodeAuthorizations: tx.SetCodeAuthorizations(),
		SkipNonceChecks:       false,
		SkipFromEOACheck:      false,
		BlobHashes:            tx.BlobHashes(),
		BlobGasFeeCap:         tx.BlobGasFeeCap(),
	}
	// If baseFee provided, set gasPrice to effectiveGasPrice.
	if baseFee != nil {
		ethMsg.GasPrice = ethMsg.GasPrice.Add(ethMsg.GasTipCap, baseFee)
		if ethMsg.GasPrice.Cmp(ethMsg.GasFeeCap) > 0 {
			ethMsg.GasPrice = ethMsg.GasFeeCap
		}
	}
	ethMsg.From = msg.GetSender()
	return ethMsg
}

// BurnAmountFromAccount converts the given amount into the evm coin scaling
// the amount to the original decimals, then burns that quantity from the provided account.
func (w BankWrapper) BurnAmountFromAccount(ctx context.Context, account sdk.AccAddress, amt *big.Int) error {
	coin := sdk.Coin{Denom: types.GetEVMCoinDenom(), Amount: sdkmath.NewIntFromBigInt(amt)}

	convertedCoin, err := types.ConvertEvmCoinDenomToExtendedDenom(coin)
	if err != nil {
		return errors.Wrap(err, "failed to burn coins from account in bank wrapper")
	}

	coinsToBurn := sdk.Coins{convertedCoin}

	if err := w.BankKeeper.SendCoinsFromAccountToModule(ctx, account, types.ModuleName, coinsToBurn); err != nil {
		return errors.Wrap(err, "failed to burn coins from account in bank wrapper")
	}
	return w.BurnCoins(ctx, types.ModuleName, coinsToBurn)
}
