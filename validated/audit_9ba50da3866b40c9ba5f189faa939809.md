### Title
Payout OP_RETURN operator attribution is unauthenticated, allowing anyone to credit an uninvolved operator with a payout it never funded - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
The bridge's peg-out flow attributes reimbursement rights for a Citrea withdrawal to whichever operator's x-only pubkey is embedded in an OP_RETURN output of the on-chain payout transaction. That OP_RETURN value is never signed or otherwise cryptographically bound to whoever actually supplies the BTC that pays the user, because the only signature on the payout tx uses `SIGHASH_SINGLE|ANYONECANPAY`, which commits solely to input 0 and output 0. Any party who obtains the user's off-chain withdrawal signature (which, by design, is distributed to multiple/all operators) can construct and broadcast the payout transaction, fund it with their own money, and write an arbitrary operator's pubkey into the OP_RETURN. The protocol logic that decides who gets reimbursed (`is_kickoff_malicious`, `validate_payer_is_operator`, `PayoutCheckerTask`) trusts this unauthenticated OP_RETURN field as ground truth, breaking the binding "operator credited == party that paid."

### Finding Description
`create_payout_txhandler` builds the payout transaction with:
- input 0: the user's withdrawal UTXO, spent with `SpendPath::KeySpend`
- output 0: the user's payout
- an anchor output
- an OP_RETURN output containing an arbitrary `operator_xonly_pk` parameter [1](#0-0) 

The user's signature is verified with `SinglePlusAnyoneCanPay` sighash type: [2](#0-1) 

`SIGHASH_SINGLE|ANYONECANPAY` only commits to the input being spent and the output at the same index; it does **not** cover other outputs (the anchor and, critically, the OP_RETURN carrying `operator_xonly_pk`), nor other inputs. This is confirmed by the protocol's own funding flow, where the operator calls `fund_raw_transaction`/`sign_raw_transaction_with_wallet` to add its *own* extra inputs after the user's signature has already been fixed: [3](#0-2) 

Because the OP_RETURN is unsigned and outside the commitment of the only cryptographic authorization present (the user's key-spend signature), the `operator_xonly_pk` value is a self-declared claim: anyone who possesses the user's `SinglePlusAnyoneCanPay` signature and the fixed input/output-0 parameters (which are known to *all* operators the withdrawal is routed to, per the `Withdraw` RPC design, or to anyone able to observe/replace the transaction in the mempool since it uses `ANYONECANPAY` and is fee-bumpable) can construct a competing payout transaction that:
1. Reuses the same signed input/output-0.
2. Adds their own funding inputs (their own BTC pays the user).
3. Writes a *different* operator's `xonly_pk` into the OP_RETURN.

On the verifier side, this unauthenticated OP_RETURN value is parsed and persisted as ground truth for "who paid": [4](#0-3) [5](#0-4) 

The named operator's own automation then picks this up as "its" unhandled payout purely from this field, with no check that it actually funded the transaction: [6](#0-5) 

And the anti-fraud check `is_kickoff_malicious`, which is supposed to ensure "the operator who sent the kickoff matches the payout data," only compares the kickoff sender's pubkey against this same unauthenticated OP_RETURN value - it never verifies that the named operator's funds/signature were used in the payout's funding inputs: [7](#0-6) 

`validate_payer_is_operator` (used when the operator itself requests reimbursement txs) performs the same unauthenticated comparison: [8](#0-7) 

### Impact Explanation
This breaks the intended equality "operator credited for reimbursement == party that actually fronted the withdrawal." An unprivileged party (not a verifier, operator, watchtower, or key-holder in the N-of-N sense - simply anyone who can construct and broadcast a Bitcoin transaction using data that is, by protocol design, shared with all candidate operators) can:
- Pay the user's withdrawal with their own BTC while naming an uninvolved, honest operator in the OP_RETURN, causing that operator's round/kickoff flow to later reimburse the wrong operator from its own collateral for a payout it never made (Critical: "an operator reimbursed for a payout it never funded"), or
- Name a bogus/unregistered pubkey (or an operator that will never see/process it), permanently preventing any legitimate operator from ever being credited/attributable for that withdrawal, since `is_kickoff_malicious`/`validate_payer_is_operator` will reject any real operator's subsequent kickoff as "malicious" (mismatch against the OP_RETURN attribution) — matching the listed Critical impact "an honest operator permanently unable to be reimbursed."

### Likelihood Explanation
The withdrawal's `input_signature` and its fixed parameters (`input_outpoint`, `output_script_pubkey`, `output_amount`) are, per the protocol's own design and documentation, distributed to potentially all operators ("if the operator's xonly public keys list is empty, the withdrawal will be sent to all operators"), and the resulting payout transaction sits in the mempool as RBF-able (ANYONECANPAY-friendly) before confirmation. No secret key, verifier role, or aggregator credential is required to exploit this - only knowledge of already-broadcast/relayed public withdrawal parameters and the ability to fund a transaction with one's own BTC and set an arbitrary OP_RETURN value.

### Recommendation
Bind the OP_RETURN operator attribution to actual funding authorization, e.g., by requiring the operator's protocol signing key to sign (or otherwise cryptographically commit to) the whole payout transaction, including the OP_RETURN output and the specific funding inputs, rather than trusting a plain, unsigned OP_RETURN value. Alternatively, use a sighash type that commits to all outputs (e.g., `SIGHASH_ALL|ANYONECANPAY` is still input-flexible but the user cannot pre-commit to an unknown operator; a two-step protocol where the operator signs a commitment naming itself, verified against its own registered key, would close the gap) so `is_kickoff_malicious`/`validate_payer_is_operator` can trust the attribution.

### Proof of Concept
1. User creates the standard withdrawal request; `input_signature` (SinglePlusAnyoneCanPay over input 0/output 0) and the fixed withdrawal parameters are sent to the operator set (potentially all operators, or observable once broadcast).
2. Attacker E (not a registered operator, not a verifier) constructs a payout transaction using `create_payout_txhandler`-equivalent logic: same input UTXO + witness (reusing the valid user signature, which only commits to input 0/output 0), same output 0, but adds E's own funding UTXO(s) as additional ANYONECANPAY inputs, and sets the OP_RETURN to honest Operator H's `xonly_pk` instead of E's own.
3. E broadcasts this transaction (optionally RBF-replacing any operator's earlier attempt, since the signature and SIGHASH type permit differing additional inputs/outputs beyond output 0).
4. Verifiers observe the confirmed payout tx, parse the OP_RETURN, and record `payout_payer_operator_xonly_pk = H` via `update_finalized_payouts`/`update_payout_txs_and_payer_operator_xonly_pk`.
5. Operator H's `PayoutCheckerTask` picks up "its" unhandled payout (`get_first_unhandled_payout_by_operator_xonly_pk`) and proceeds through `handle_finalized_payout` → kickoff → `create_reimburse_txhandler`, being reimbursed from its own Round-tx collateral for a withdrawal it never actually funded (or, if E instead names a bogus/never-online pubkey, no real operator can ever pass `is_kickoff_malicious`/`validate_payer_is_operator` for this withdrawal, permanently blocking honest reimbursement).

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

        tracing::info!(
            "Payer xonly pk, payout blockhash and kickoff txid found and valid for own operator for the requested deposit id: {}, payer xonly pk: {:?}, payout blockhash: {:?}, kickoff txid: {:?}",
            deposit_id,
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid
        );

        Ok((payout_blockhash, kickoff_txid))

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
