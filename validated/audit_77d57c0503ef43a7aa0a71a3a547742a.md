### Title
Ante-surplus accounting bridge (usei/wei StateDB reconciliation) can silently desync bank total supply, mirroring Maya's chained accounting/false-subsidy bug class - (File: x/evm/keeper/ante.go)

### Summary
Sei-chain has no CACAO-style pool/Trade-Account subsystem, so there is no literal analog to Maya's liquidity-pool subsidy math. The closest reachable analog inside the allowed EVM/ante/fee-accounting surface is the **ante-surplus mechanism** that reconciles native `usei`/`wei` balance changes made inside the EVM `StateDB` with the Cosmos bank ledger. This is the same *class* of bug as Maya's: a chained, edge-case accounting path that can desynchronize "real" value from tracked ledger state, and it has already caused one confirmed production total-supply mismatch on `pacific-1`.

### Finding Description
Every EVM balance mutation (`SubBalance`/`AddBalance`) splits the amount into `usei`/`wei`, applies it to the bank keeper, and separately accumulates a `surplus` delta in `tempState.surplus`, journaled for potential revert: [1](#0-0) [2](#0-1) 

During the fee ante decorators, `stateDB.Finalize()` computes this per-tx surplus, and it is persisted into a **transient KV store keyed by the Ethereum transaction hash** via `AddAnteSurplus`: [3](#0-2) [4](#0-3) [5](#0-4) 

At `EndBlock`, all entries under this prefix are summed via `GetAnteSurplusSum` (a raw iterator over the transient store) and the aggregate is minted into the EVM module account through `AddCoins`/`AddWei`: [6](#0-5) [7](#0-6) 

Because the store is keyed by `etx.Hash()` rather than transaction index, any two ante-surplus writes within the same block that resolve to the **same key** (e.g., duplicate ante processing of an identical raw transaction reaching the pipeline twice, or replay/synthetic-tx paths that reuse a hash) result in **last-write-wins overwrite instead of accumulation**, silently dropping one transaction's surplus from the block's total. This is structurally the same bug shape as Maya's exploit: an edge case in per-transaction/per-event accounting (their "false subsidy" via chained Trade-Account/pool-math bugs) that desynchronizes the ledger's internal bookkeeping from actual value, later exploitable to extract real assets.

Critically, this exact code path is **not hypothetical** — it previously caused a real, confirmed accounting divergence on `pacific-1`, which required an explicit state migration to repair: [8](#0-7) 

The migration's own comment states it exists "to fix total supply mismatch caused by mishandled ante surplus," confirming the mechanism has already manifested this bug class in production.

### Impact Explanation
If the surplus-key collision (or any other edge case that causes `AddAnteSurplus` writes to overwrite rather than accumulate within a block) recurs, the `usei` total supply tracked by the bank module can silently diverge from the sum of real account balances plus outstanding EVM-side value. This is a supply-inflation/destruction class bug (bank invariant break), matching the "Accept" criteria for fund loss or supply corruption, and it uses the same code path that already required a governance-triggered on-chain fix once.

### Likelihood Explanation
Medium. A single attacker cannot trivially force a tx-hash collision or duplicate ante execution through a normal `eth_sendRawTransaction` call, so the trigger conditions are narrower than a fully unprivileged single-transaction exploit. However, the fact that this precise mechanism already produced a real total-supply mismatch in production (necessitating `FixTotalSupply`) demonstrates the code path is fragile under edge cases in the ante pipeline (e.g., replay/synthetic-tx handling, retried delivery, or the `EthReplayConfig`/`EthBlockTestConfig` code paths that reuse tx-processing logic), and the root cause — a map keyed by hash instead of an accumulating counter keyed by tx index — has not been structurally eliminated, only patched after the fact.

### Recommendation
- Key `AddAnteSurplus` by transaction index (already tracked elsewhere as `deferredInfo.TxIndex` in `abci.go`) instead of tx hash, or make it accumulate (read-modify-add) rather than overwrite, so that any duplicate-hash scenario cannot cause silent loss of surplus.
- Add a per-`EndBlock` bank-supply invariant check (extending `sei-cosmos/x/bank/keeper/invariants.go`) that asserts `GetSupply(usei)` equals the sum of tracked account balances plus wei-in-usei conversion, failing loudly instead of requiring a manual governance migration to detect drift after the fact.

### Proof of Concept
A full working PoC requires reproducing the exact historical trigger for the `FixTotalSupply` migration, which is not fully recoverable from static analysis alone. Conceptually: within a single block, cause two ante-surplus writes to collide on the same transient-store key (e.g., via the replay/synthetic-transaction code paths that reuse `EvmDeliverChargeFees`/`AddAnteSurplus`, or a scenario where the same raw transaction bytes are ante-processed twice before `EndBlock`). Each contributes a nonzero `surplus` from `stateDB.Finalize()`, but only the last write survives in the transient store, so `GetAnteSurplusSum` under-counts. `EndBlock` then mints less `usei`/`wei` into the EVM module account than was actually collected/burned from real user balances, permanently desynchronizing total bank supply from backing value — the same drift class that `x/evm/migrations/fix_total_supply.go` was written to repair.

func (k *Keeper) AddAnteSurplus(ctx sdk.Context, txHash common.Hash, surplus sdk.Int) error {
	store := prefix.NewStore(ctx.TransientStore(k.transientStoreKey), types.AnteSurplusPrefix)

		return err
	}

func (k *Keeper) GetAnteSurplusSum(ctx sdk.Context) sdk.Int {
	iter := prefix.NewStore(ctx.TransientStore(k.transientStoreKey), types.AnteSurplusPrefix).Iterator(nil, nil)
	defer func() { _ = iter.Close() }()
	res := sdk.ZeroInt()
	for ; iter.Valid(); iter.Next() {
		surplus := sdk.Int{}
		_ = surplus.Unmarshal(iter.Value())
		res = res.Add(surplus)
	}
	return res

// This migration is to fix total supply mismatch caused by mishandled
// ante surplus
func FixTotalSupply(ctx sdk.Context, k *keeper.Keeper) error {
	balances := k.BankKeeper().GetAccountsBalances(ctx)
	correctSupply := sdk.ZeroInt()
	for _, balance := range balances {
		correctSupply = correctSupply.Add(balance.Coins.AmountOf(sdk.MustGetBaseDenom()))
	}
	totalWeiBalance := sdk.ZeroInt()
	k.BankKeeper().IterateAllWeiBalances(ctx, func(aa sdk.AccAddress, i sdk.Int) bool {
		totalWeiBalance = totalWeiBalance.Add(i)
		return false
	})
	weiInUsei, weiRemainder := bankkeeper.SplitUseiWeiAmount(totalWeiBalance)
	if !weiRemainder.IsZero() {
		logger.Error("wei total supply has been compromised as well; rounding up and adding to reserve")
		if err := k.BankKeeper().AddWei(ctx, k.AccountKeeper().GetModuleAddress(types.ModuleName), bankkeeper.OneUseiInWei.Sub(weiRemainder)); err != nil {
			return err
		}
		weiInUsei = weiInUsei.Add(sdk.OneInt())
	}
	correctSupply = correctSupply.Add(weiInUsei)
	currentSupply := k.BankKeeper().GetSupply(ctx, sdk.MustGetBaseDenom()).Amount
	if !currentSupply.Equal(correctSupply) {
		k.BankKeeper().SetSupply(ctx, sdk.NewCoin(sdk.MustGetBaseDenom(), correctSupply))
	}
	return nil
