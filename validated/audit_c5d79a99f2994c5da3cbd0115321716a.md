### Title
Unauthenticated SSRF via attacker-controlled DataLayer mirror URLs in `DataLayer.fetch_and_validate` / `http_download` - ([File: chia/data_layer/data_layer_wallet.py])

### Summary
Any Chia wallet user can publish a "mirror" coin for **any** DataLayer store (`launcher_id`) they do not own, embedding arbitrary attacker-chosen URLs in the coin's memo field. Every node that tracks/subscribes to that store automatically pulls this URL into its subscription list and periodically issues outbound HTTP GET requests to it while trying to sync delta files — with no validation that the URL's publisher is the store owner, and no restriction on target host.

### Finding Description
1. `DataLayerWallet.create_new_mirror()` at `chia/data_layer/data_layer_wallet.py:687-703` creates a standard coin paying to `create_mirror_puzzle()` with `memos=[[launcher_id, *urls]]`. There is no check that the caller owns `launcher_id` — it's just a `generate_signed_transaction` call, callable by any wallet holding a small amount of XCH via the `add_mirror` RPC (`chia/data_layer/data_layer_rpc_api.py:468-475`, `chia/data_layer/data_layer.py:965-970`).
2. When any peer observes this coin, `DataLayerWallet.coin_added()` at `chia/data_layer/data_layer_wallet.py:775-800` decodes `launcher_id` and `urls` from the coin's parent spend via `get_mirror_info()` (`chia/wallet/db_wallet/db_wallet_puzzles.py:97-109`) and, if `is_launcher_tracked(launcher_id)` is true (i.e., the node is tracking that store at all — true for any subscriber or the legitimate owner), unconditionally records the mirror via `self.wallet_state_manager.dl_store.add_mirror(...)`. There is no verification that the mirror's creator is the store's owner.
3. `DataLayer.update_subscriptions_from_wallet()` (`chia/data_layer/data_layer.py:979-985`) pulls **all** mirrors for the store from wallet RPC and merges their URLs into the local subscription list (`DataStore.update_subscriptions_from_wallet`, `chia/data_layer/data_store.py:1668-1704`), with no origin/ownership filtering.
4. `DataLayer.fetch_and_validate()` (`chia/data_layer/data_layer.py:642-706`) then randomly selects one of these URLs and calls `insert_from_delta_file()` → `download_file()` → `http_download()` (`chia/data_layer/download_data.py:110-169, 298-346`), which performs `session.get(server_info.url + "/" + filename, ...)` using the fully attacker-controlled base URL, with no scheme allowlist, no rejection of loopback/link-local/private addresses, and no authentication required anywhere in this chain.

This mirrors the OpenDJ advisory's core defect: unauthenticated, unrestricted dereferencing of an attacker-supplied URI performed automatically by server-side logic.

### Impact Explanation
An unprivileged Chia user (any wallet holder able to pay a small mirror-coin fee) can force **every node that syncs a given DataLayer store** — including the store's legitimate owner and any third party who subscribes to it — to make periodic, automatic outbound HTTP requests to attacker-chosen hosts. This enables SSRF against internal services and cloud metadata endpoints (e.g. `169.254.169.254`) reachable from the victim's host/network, entirely without the victim's consent, triggered purely by an on-chain coin creation that the victim's `periodically_manage_data()` loop (`chia/data_layer/data_layer.py:1006-1086`) will pick up automatically. While a `max_delta_file_size` byte cap already limits the unbounded-read DoS variant present in the original OpenDJ bug (`chia/data_layer/download_data.py:320-336`), the SSRF component is fully reachable and unauthenticated.

### Likelihood Explanation
High. Creating a mirror coin costs only a wallet transaction fee and requires no special permission, ownership check, or interaction with the victim. Any store that has at least one subscriber (which is the normal operating mode of DataLayer) is exposed. The periodic sync loop runs automatically without user interaction on the victim side.

### Recommendation
Add an ownership/authorization check in `DataLayerWallet.coin_added()` before recording a mirror for a `launcher_id`, or at minimum validate at the `DataLayer` service layer (`update_subscriptions_from_wallet`) that mirror URLs come from a trusted/allowlisted source before merging them into the active subscription list used by `fetch_and_validate`. Additionally, apply scheme allowlisting (http/https only) and reject loopback/link-local/private/reserved destination addresses in `http_download()` (`chia/data_layer/download_data.py:298`), consistent with the OpenDJ 5.1.2 fix.

### Proof of Concept
1. Attacker wallet calls `add_mirror` RPC (or `dl_new_mirror`) with `launcher_id` set to a victim's known/public DataLayer store id and `urls=["http://169.254.169.254/latest/meta-data/"]`, paying a minimal fee — see test pattern at `chia/_tests/core/data_layer/test_data_rpc.py:2767-2801` (`data_rpc_api.add_mirror({"id": store_id.hex(), "urls": urls, ...})`), reachable by any wallet, not just the store owner.
2. The mirror coin confirms on-chain.
3. Any node tracking `store_id` observes the coin; `DataLayerWallet.coin_added()` (`chia/data_layer/data_layer_wallet.py:775-800`) records it as a mirror since `is_launcher_tracked(launcher_id)` is true.
4. During the victim's next `periodically_manage_data()` cycle, `update_subscriptions_from_wallet()` adds the attacker's URL to the victim's subscription list, and `fetch_and_validate()`/`http_download()` issues an outbound GET to `http://169.254.169.254/latest/meta-data/...` from the victim's machine.     """

    """

        async with session.get(

            progress_byte = 0
            progress_percentage = f"{0:.0%}"
            success = False
            try:
                with target_filename_path.open(mode="wb") as f:
                    async for chunk, _ in resp.content.iter_chunks():
                        f.write(chunk)
                        progress_byte += len(chunk)
                        if progress_byte > max_delta_file_size_bytes:
                            raise MaxDeltaFileSizeExceededError(
                                f"Maximum delta file size exceeded: {max_delta_file_size} MiB."

def create_mirror_puzzle() -> Program:
    return P2_PARENT.curry(Program.to(1))

def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
