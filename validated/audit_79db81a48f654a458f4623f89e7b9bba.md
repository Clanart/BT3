### Title
Checking out a Pull Request binds to the head *ref name*, not the reviewed *SHA*, letting a PR author silently swap commits between review and checkout - ([File: app/src/lib/stores/app-store.ts])

### Summary
The Monero report's broken invariant is: a participant approves an action after seeing state X, but the system executes the action against whatever state is *current* at execution time, with no binding between "what was reviewed/approved" and "what actually gets used." GitHub Desktop has a structurally identical gap in its pull-request-checkout flow: the user reviews a PR (title, diff, "Files Changed") anchored to a specific `head.sha` fetched from the GitHub API, but `_checkoutPullRequest` / `_findPullRequestBranch` resolves and checks out the branch purely by *ref name*, never verifying that the resulting branch tip matches the `sha` the user actually reviewed.

### Finding Description
`PullRequest`/`PullRequestRef` carry a `sha` field populated straight from the API response [1](#0-0) , and the local PR cache stores `head.sha`/`base.sha` per record [2](#0-1) . This SHA is only ever used to detect divergence for the *diff preview* (`nonLocalCommitSHA`), not to gate the actual checkout.

When the user (or a deep link / "View pull request" action) triggers a checkout, the flow is `checkoutPullRequest` → `_checkoutPullRequest` → `_findPullRequestBranch`: [3](#0-2) 

`_findPullRequestBranch` locates the branch purely by `headRefName`/`remoteRef`, fetching the remote if the ref isn't already known, and returns whatever branch currently exists — with no comparison to `pullRequest.head.sha`: [4](#0-3) 

Similarly, `isPullRequestAssociatedWithBranch`/`findAssociatedPullRequest`, which decide whether a locally checked-out branch "is" a given PR, match only on `ref` name and remote identity — never on `sha`: [5](#0-4) 

Because a PR's `head` lives in a repository the PR author controls (their fork, in the common "PR from fork" flow supported by `_findPullRequestBranch`'s fork-remote logic), the author can force-push new commits to that branch at any time between:
1. the moment the user inspects the PR (via the "Open Pull Request"/preview dialog, a GitHub notification, or a `x-github-client://openPullRequest` deep link that calls `openPullRequestFromUrl`, [6](#0-5) ), and
2. the moment Desktop actually performs `_fetchRemote` + checkout inside `_findPullRequestBranch`.

Desktop will silently fetch and check out whatever is on the ref *at execution time*, not the SHA the user reviewed, with no re-diff, no confirmation, and no mismatch warning.

### Impact Explanation
This is the direct analog of the Monero double-spend trick: the human's approval ("I reviewed this PR, let me check it out / build on it / merge it") is bound to a label (a ref name / PR number), not to the actual content, and the content can be swapped underneath that label by the party that controls it. Consequences:
- A user who reviewed PR head SHA `A` on GitHub.com, then triggers "Checkout PR" in Desktop, may unknowingly check out and start working on top of SHA `B` — attacker-controlled code they never reviewed.
- Any subsequent local commits, builds, or pushes the user performs are now built on unreviewed, attacker-supplied history, satisfying the "silent corruption of what the user commits or pushes" impact category.
- No local/physical access, admin rights, or leaked credentials are required — the only "privilege" needed is being the (unprivileged) author of a pull request/fork, which is the normal, expected capability of any external contributor.

### Likelihood Explanation
The precondition (time gap between "review" and "click checkout", PR author being able to force-push their own fork branch at will) is trivial to engineer and requires no unusual user behavior — it only requires normal delay between opening a PR notification/link and clicking "Checkout branch," which is common. `nonLocalCommitSHA` shows the team is aware that local/remote SHA divergence exists in this flow, but that mechanism only informs the *diff preview*, not the checkout path, so it does not close this gap.

### Recommendation
Before completing a PR checkout (and when deciding whether a local branch still "is" a given PR in `isPullRequestAssociatedWithBranch`), compare the fetched/resolved branch tip SHA against the `pullRequest.head.sha` that the user was shown. If they differ, warn the user that the PR has changed since they last viewed it (similar to the existing force-push confirmation UX) and require explicit re-confirmation before checking out or before silently reassociating stored PR state with a different physical commit.

### Proof of Concept
1. Attacker opens a PR from their fork against a victim's repository, with `head.sha = A` (benign diff).
2. Victim receives a notification / clicks a `x-github-client://openPullRequest` link, or opens the PR preview in Desktop, and reviews the diff for SHA `A` — decides to check it out later.
3. Before the victim clicks "Checkout branch," attacker force-pushes new, malicious commits to the same branch name in their fork, moving the ref to SHA `B`.
4. Victim clicks "Checkout branch" in Desktop. `_checkoutPullRequest` → `_findPullRequestBranch` resolves by ref name, fetches the fork, and checks out whatever is now at the tip (SHA `B`) — `app/src/lib/stores/app-store.ts:8613-8721` — with no comparison to the previously reviewed `A`.
5. Victim now has SHA `B`'s content checked out locally, believing it to be the reviewed PR, and may commit/build/push on top of it.

  public async _findPullRequestBranch(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,
    headRefName: string
  ): Promise<Branch | undefined> {
    const gitStore = this.gitStoreCache.get(repository)
    const remotes = await getRemotes(repository)

    // Find an existing remote (regardless if set up by us or outside of
    // Desktop).
    let remote = remotes.find(r => urlMatchesRemote(headCloneUrl, r))

    // If we can't find one we'll create a Desktop fork remote.
    if (remote === undefined) {
      try {
        const forkRemoteName = forkPullRequestRemoteName(headRepoOwner)
        remote = await addRemote(repository, forkRemoteName, headCloneUrl)
      } catch (e) {
        this.emitError(
          new Error(
            `Couldn't find PR branch, adding remote failed: ${e.message}`
          )
        )
        return
      }
    }

    const remoteRef = `${remote.name}/${headRefName}`

    // Start by trying to find a local branch that is tracking the remote ref.
    let existingBranch = gitStore.allBranches.find(
      x => x.type === BranchType.Local && x.upstream === remoteRef
    )

    // If we found one, let's check it out and get out of here, quick
    if (existingBranch !== undefined) {
      return existingBranch
    }

    const findRemoteBranch = (name: string) =>
      gitStore.allBranches.find(
        x => x.type === BranchType.Remote && x.name === name
      )

    // No such luck, let's see if we can at least find the remote branch then
    existingBranch = findRemoteBranch(remoteRef)

    // It's quite possible that the PR was created after our last fetch of the
    // remote so let's fetch it and then try again.
    if (existingBranch === undefined) {
      try {
        await this._fetchRemote(repository, remote, FetchType.UserInitiatedTask)
        existingBranch = findRemoteBranch(remoteRef)
      } catch (e) {
        log.error(`Failed fetching remote ${remote?.name}`, e)
      }
    }

    if (existingBranch === undefined) {
      this.emitError(
        new Error(
          `Couldn't find branch '${headRefName}' in remote '${remote.name}'. ` +
            `A common reason for this is that the PR author has deleted their ` +
            `branch or their forked repository.`
        )
      )
      return
    }

    // For fork remotes we checkout the ref as pr/[123] instead of using the
    // head ref name since many PRs from forks are created from their default
    // branch so we'll have a very high likelihood of a conflicting local branch
    const isForkRemote =
      remote.name !== gitStore.defaultRemote?.name &&
      remote.name !== gitStore.upstreamRemote?.name

    if (isForkRemote) {
      return await this._createBranch(
        repository,
        `pr/${prNumber}`,
        remoteRef,
        false
      )
    }

    return existingBranch
  }

export function isPullRequestAssociatedWithBranch(
  branch: Branch,
  pr: PullRequest,
  remote: IRemote
): boolean {
  return (
    pr.head.ref === branch.upstreamWithoutRemote &&
    repositoryMatchesRemote(pr.head.gitHubRepository, remote)
  )
}

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }
    if (!isRepositoryWithGitHubRepository(repository)) {
      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    if (pullRequest.head.repo === null) {
      return null
    }

    await this.appStore._checkoutPullRequest(
      repository,
      pullRequest.number,
      pullRequest.head.repo.owner.login,
      pullRequest.head.repo.clone_url,
      pullRequest.head.ref
    )

    return repository
  }
