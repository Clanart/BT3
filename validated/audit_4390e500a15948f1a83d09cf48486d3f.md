### Title
Governing Node Can Ratify Inconsistent KIP-71 Base Fee Bounds (LowerBoundBaseFee > UpperBoundBaseFee) via Stale Consistency Check - ([File: kaiax/gov/headergov/impl/header.go])

### Summary
`checkConsistency` in `kaiax/gov/headergov/impl/header.go` is intended to ensure that `Kip71LowerBoundBaseFee` and `Kip71UpperBoundBaseFee` votes never allow `LowerBoundBaseFee > UpperBoundBaseFee`. However each vote is checked independently against `h.GetParamSet(blockNum)` [1](#0-0) , which returns the ratified parameter set from the **previous epoch** [2](#0-1) , not the value implied by other votes already cast (but not yet ratified) within the *same* epoch. Because in `single` governance mode all votes in an epoch come from one governing node and are ratified together at the epoch boundary [3](#0-2) , the governing node can cast two votes in the same epoch — one lowering `UpperBoundBaseFee` and one raising `LowerBoundBaseFee` — each individually validated against the stale pre-epoch baseline, that together ratify into a state where `LowerBoundBaseFee > UpperBoundBaseFee`.

### Finding Description
The consistency check logic is:
```go
case gov.Kip71LowerBoundBaseFee:
    params := h.GetParamSet(blockNum)
    if vote.Value().(uint64) > params.UpperBoundBaseFee {
        return ErrLowerBoundBaseFee
    }
case gov.Kip71UpperBoundBaseFee:
    params := h.GetParamSet(blockNum)
    if vote.Value().(uint64) < params.LowerBoundBaseFee {
        return ErrUpperBoundBaseFee
    }
``` [1](#0-0) 

`GetParamSet(blockNum)` always resolves to the ratified values as of `PrevEpochStart(blockNum)` [2](#0-1) , i.e., it never reflects votes cast earlier in the *same* epoch that have not yet been ratified. All votes cast within an epoch are collected and, at the epoch boundary, ratified together, with the last vote per parameter name winning [3](#0-2) .

Concretely, with initial state `Lower=25e9`, `Upper=750e9`:
1. At block `b1` (within epoch `k`), governing node votes `UpperBoundBaseFee = 30e9`. Check: `30e9 < params.LowerBoundBaseFee(25e9)`? No → accepted, because it's checked against the stale pre-epoch `Lower=25e9`.
2. At block `b2` (same epoch `k`, `b2 > b1`), governing node votes `LowerBoundBaseFee = 500e9`. Check: `500e9 > params.UpperBoundBaseFee(750e9)`? No → accepted, because it's checked against the stale pre-epoch `Upper=750e9`, not the just-cast pending `Upper=30e9`.
3. At the epoch boundary, `getExpectedGovernance` ratifies both votes in block order via `govs.Add` [4](#0-3) , producing a ratified `ParamSet` with `Lower=500e9 > Upper=30e9`.

This inverted invariant then flows into `KIP71Config.NextMagmaBlockBaseFee`, the consensus-critical base-fee computation used by every node to compute and verify `header.BaseFee` [5](#0-4) . The clamping logic (`if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 { parentBaseFee = upperBoundBaseFee } else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 { parentBaseFee = lowerBoundBaseFee }`) [6](#0-5)  becomes ill-defined when `lowerBoundBaseFee > upperBoundBaseFee`, and the invariant asserted by tests (`even.Cmp(lowerBoundBaseFee) >= 0` and `even.Cmp(upperBoundBaseFee) <= 0`) [7](#0-6)  can no longer both hold, producing base fees outside the intended economic bounds for the entire epoch after ratification.

### Impact Explanation
This falls under the allowed "governance parameters" category and is reachable purely through the standard `governance_vote` transaction path (no privileged/off-chain access needed beyond being the governing node, which is the expected caller of this codepath). The impact is chain-wide: an inconsistent `[Lower, Upper]` bound corrupts the deterministic KIP-71 base-fee formula used by every block for an entire epoch, letting the governing node effectively force base fees to unintended extremes (e.g., pin fees far below the originally intended floor, or force degenerate clamping), undermining the protocol's fee-market design and enabling fee-abuse for the governing party's benefit (e.g., cheap transaction inclusion for favored actors) contrary to the design intent that `Lower <= Upper` must always hold.

### Likelihood Explanation
Requires the governing node (an unprivileged-from-chain's-perspective GC actor who is nonetheless a normal transaction/vote submitter) to cast two ordinary `governance_vote` transactions within the same epoch. No special conditions, timing races, or malicious peer/consensus manipulation are needed — a single actor with vote rights can trigger it deterministically, as the check only ever inspects the block's own pre-epoch snapshot.

### Recommendation
When validating `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee` votes in `checkConsistency`, compare against the *effective pending value* for the epoch (i.e., merge already-cast-but-not-yet-ratified votes for the counterpart parameter within the current epoch, not just `GetParamSet(blockNum)`), or perform a final cross-check of the full ratified `ParamSet` at ratification time (`VerifyGov`/`getExpectedGovernance`) to reject any epoch governance payload where `LowerBoundBaseFee > UpperBoundBaseFee`.

### Proof of Concept
1. Set genesis KIP-71 config: `LowerBoundBaseFee=25e9`, `UpperBoundBaseFee=750e9`, `governance.governancemode=single`, governing node = `G`.
2. At block `b1` in epoch `k`, have `G` submit `governance_vote("kip71.upperboundbasefee", 30000000000)`. `checkConsistency` compares `30e9 < 25e9` → false → vote accepted and included in `header.Vote`.
3. At block `b2 > b1` in the same epoch `k`, have `G` submit `governance_vote("kip71.lowerboundbasefee", 500000000000)`. `checkConsistency` compares `500e9 > 750e9` (the still-stale pre-epoch upper bound) → false → vote accepted.
4. At the epoch boundary block, `getExpectedGovernance` ratifies both votes, writing `header.Governance = {"kip71.lowerboundbasefee": 500000000000, "kip71.upperboundbasefee": 30000000000}`.
5. From `(k+1)*epoch` onward, `GetParamSet` returns `Lower=500e9 > Upper=30e9`; calling `NextMagmaBlockBaseFee` with any `parentBaseFee`/`parentGasUsed` produces a base fee that violates the intended `[Lower, Upper]` bound invariant, as demonstrated by the bound-invariant assertions in `params/kip71_config_test.go` (`TestEvenBaseFee`) failing under this configuration.

func (h *headerGovModule) getExpectedGovernance(blockNum uint64) headergov.GovData {
	prevEpochIdx := calcEpochIdx(blockNum, h.epoch) - 1
	prevEpochVotes := h.getVotesInEpoch(prevEpochIdx)
	govs := make(gov.PartialParamSet)

	sortedVoteBlocks := slices.Collect(maps.Keys(prevEpochVotes))
	slices.Sort(sortedVoteBlocks)

	for _, voteBlock := range sortedVoteBlocks {
		vote := prevEpochVotes[voteBlock]
		govs.Add(string(vote.Name()), vote.Value())
	}

	// assert(len(headergov.NewGovData(govs).Items()) == len(govs))
	return headergov.NewGovData(govs)
}

func (h *headerGovModule) GetParamSet(blockNum uint64) gov.ParamSet {
	h.mu.RLock()
	defer h.mu.RUnlock()

	prevEpochStart := PrevEpochStart(blockNum, h.epoch, h.isKoreHF(blockNum))
	gh := h.history
	gp, err := gh.Search(prevEpochStart)
	if err != nil {
		logger.Warn("No param set", "blockNum", blockNum, "prevEpochStart", prevEpochStart)
		return *gov.GetDefaultGovernanceParamSet()
	}
	return gp
}
