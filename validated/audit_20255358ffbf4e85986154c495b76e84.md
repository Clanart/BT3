### Title
Non-linear HEAD advancement (`git commit --amend`) zeroes the Stop-hook review set via empty `dirty_now` intersection - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`compute_v2_review_set` computes the reviewable file set as `dirty_now & changed_since`, where `dirty_now` is only populated from live `git status` plus a linear-ancestry diff `head_at_capture..HEAD`. A `git commit --amend` (or any commit-rewriting operation) makes the new HEAD a sibling, not a descendant, of `head_at_capture`, so the ancestry check fails, `dirty_now` collapses to empty (working tree is clean after a commit), and the intersection with a genuinely non-empty `changed_since` silently produces an empty review set. The dangerous change is fully committed and diffable against the baseline, but is never handed to the Stop-hook LLM review.

### Finding Description
In `compute_v2_review_set` (`plugins/security-guidance/hooks/diffstate.py`, lines 403–426):
- `dirty_now` starts as `tracked_dirty | new_untracked` from live `git status` [1](#0-0) .
- It is only widened with the turn's committed changes when `head_at_capture` is a strict ancestor of the current HEAD: `if (head_at_capture and current_head and head_at_capture != current_head and _is_ancestor(repo, head_at_capture, current_head))` [2](#0-1) .
- `review_set = (dirty_now & changed_since) if changed_since is not None else dirty_now` — this is a hard `AND`, not a union or fallback [3](#0-2) .

Attack flow (ordinary git operations available to Claude/attacker-controlled content within a session, no special privilege required):
1. A prior turn commits dangerous code as commit `C1` on top of baseline `C0`; the next `UserPromptSubmit` re-baselines `baseline_sha`/`head_at_capture` to `C1` (clean tree) as documented in `handle_user_prompt_submit` [4](#0-3) .
2. In the next turn, an amend (`git commit --amend`) rewrites `C1` into `C1'`, a sibling of `C1` sharing the same parent `C0`. `head_at_capture` (`C1`) is **not** an ancestor of `C1'`, so `_is_ancestor` returns `False` and the linear-advance branch that would otherwise pull in `head_at_capture..HEAD` is skipped entirely.
3. Because the amend committed directly, the working tree is clean, so live `git status` reports no dirty files — `dirty_now` is `∅`.
4. `changed_since = _git_name_only(repo, baseline_sha)` (diff of `baseline_sha` vs the current worktree) correctly still shows the dangerous file as changed, since content differs from `C1`'s baseline.
5. `review_set = ∅ ∩ {dangerous_file} = ∅`. The Stop hook computes zero files to review, and `Sensitive`/dangerous code introduced or hidden by the amend is never surfaced to the LLM review or to the user, even though `consume_stop_state`/`compute_v2_review_set` had all the git data needed to detect it.

No existing guard restores `dirty_now` when the ancestry check fails but `changed_since` is non-empty; the code comments only address the "linear commits" case and the "pre-existing untracked" exclusion, not the sibling-HEAD (amend/rebase/reset+recommit) case. This breaks the stated invariant that the review set must stay bound to the correct baseline and touched paths — the baseline effectively "moves" past the dangerous change without ever having reviewed it.

### Impact Explanation
This lets attacker-influenced repository content (a rewritten commit) silently escape Stop-hook security review. Any vulnerability, secret, or malicious code introduced via commit-amend (a completely normal, frequently-used git workflow) in a Claude Code session bypasses the plugin's LLM-based diff review, defeating the safety net that is supposed to catch sensitive code/prompt/diff issues before they land — matching the "Sensitive code, prompt, token, diff, or local file disclosure to an unintended local or remote sink" impact class, since dangerous or disclosive changes proceed unreviewed and can be committed/pushed without triggering the review-driven warnings.

### Likelihood Explanation
Highly reachable and repeatable: `git commit --amend` is an everyday, unprivileged git operation that Claude Code (and any user directing it) performs routinely, requiring no special access beyond normal repository writes. The only precondition is that the amended commit's parent equals `head_at_capture` (i.e., the commit being amended is the same one the last UPS baselined on, which is the common case for "fix and re-commit" workflows), making this trivially triggerable in ordinary sessions, not a contrived edge case.

### Recommendation
In `compute_v2_review_set`, don't gate committed-diff detection purely on strict linear ancestry. When HEAD has moved (`current_head != head_at_capture`) but is not a descendant, fall back to unioning in `_git_name_only(repo, f"{baseline_sha}..HEAD")` (or equivalently trust `changed_since` alone as the review set) rather than intersecting with a `dirty_now` that assumes a clean, un-widened working tree. More robust: define `review_set` as `changed_since` whenever it is available and non-None, using `dirty_now` only to add untracked-file information, instead of using `dirty_now` as a restrictive intersection mask.

### Proof of Concept
Unit/integration test plan (extends existing diffstate tests):
1. Init a repo with commit `C0` (baseline).
2. Commit `C1` on top of `C0` containing a clearly dangerous snippet (e.g., `os.system(user_input)`), simulating a first Claude turn; set `head_at_capture = C0`, `baseline_sha` = stash/HEAD of `C0`.
3. Simulate the next UPS re-baseline: set `baseline_sha = C1` (clean tree), `head_at_capture = C1`.
4. Run `git commit --amend -m "amended"` without touching the dangerous line (or while re-adding/modifying it), producing `C1'` (parent `C0`, sibling of `C1`).
5. Call `compute_v2_review_set(cwd, baseline_sha=C1, head_at_capture=C1)`.
6. Assert: `_is_ancestor(repo, C1, C1')` is `False` (sanity check on the precondition), `changed_since` (via `_git_name_only(repo, C1)`) contains the dangerous file, but current buggy behavior returns `review_paths == []` — i.e., the dangerous file is dropped from the review set despite being genuinely different from baseline. After the fix, assert the dangerous file **is** present in `review_paths`.

def handle_user_prompt_submit(input_data):
    """
    Handle UserPromptSubmit — capture git baseline SHA.
    Called on every user prompt. Updates the baseline so the stop hook
    only reviews changes made since the last prompt.

    Does NOT reset touched_paths/fire_count/previous_findings — those are
    consumed by Stop (consume_stop_state) and time-expired respectively.
    UPS racing the asyncRewake Stop hook caused a meaningful share of reviews
    to be lost when the wipe landed before Stop's state read.

    """
    cwd = input_data.get("cwd", "")
    if not cwd:
        debug_log("UPS: no cwd, skipping baseline capture")
        sys.exit(0)

    session_id = input_data.get("session_id", "default")
    # stash-create and ls-files both walk the worktree (~2-5s each in a very
    # large repo). Run them concurrently so UPS latency stays ≈ max(both).
    import concurrent.futures as _cf
    with _cf.ThreadPoolExecutor(max_workers=2) as _ex:
        _f_sha = _ex.submit(capture_git_baseline, cwd)
        _f_ut = _ex.submit(_list_untracked, cwd)
        sha = _f_sha.result()
        # Always capture the untracked snapshot. `git stash create` returns
        # empty when there are no TRACKED changes, but pre-existing untracked
        # files still need to be excluded from the next Stop's review_set —
        # otherwise an untracked-only working tree gets every untracked file
        # reviewed on every turn until something tracked is dirtied.
        untracked_now = _f_ut.result() or {}
    head = _git_rev_parse_head(cwd)

    # If the previous turn's Stop hook never ran (user interrupt, follow-up
    # during work, tool-reject, model crash, maxTurns, PostToolUse block…),
    # touched_paths is still populated because consume_stop_state is the only
    # consumer and it runs under the state lock. Overwriting baseline_sha now
    # would re-baseline *past* those unreviewed edits, making them permanently
    # invisible to the next Stop. Preserve the old baseline so the next Stop
    # diffs the aborted turn's edits plus the new turn's edits together.
    preserved = {"value": False}

    def _save(state):
        # Only preserve if there's actually an old baseline to preserve.
        # First UPS of a session can have touched_paths if PostToolUse
        # somehow ran first (print mode, odd harnesses) — in that case
        # we still need to capture a baseline.
        if state.get("touched_paths") and state.get("baseline_sha"):
            preserved["value"] = True
            return
        if sha:
            state["baseline_sha"] = sha
            state["head_at_capture"] = head
        # untracked_at_baseline is independent of whether the stash produced
        # a SHA — write it unconditionally so compute_v2_review_set's
        # preexisting-untracked exclusion works in untracked-only trees.
        state["untracked_at_baseline"] = untracked_now
    with_locked_state(session_id, _save)
