## Analysis

The reported bug class ("duplicate/uncoordinated logic that lets an invariant slip") has a concrete local analog in Hyperbridge's `GetRequest` lifecycle: two independent code paths consume the *same* `_requestCommitments[commitment]` fee/ownership record, but only one of them clears it, and the "is this request still open" check trusts *any* previously stored, never-pruned `StateCommitment` rather than requiring it be the freshest evidence.

### Title
Stale-height non-membership proof lets a delivered GetResponse be re-processed as a timeout, causing duplicate fee payout and duplicate module settlement - (File: `evm/src/core/EvmHost.sol`, `evm/src/core/HandlerV2.sol`)

### Summary
`EvmHost.dispatchIncoming(GetResponse, ...)` pays the relayer fee out of `_requestCommitments[commitment]` but never deletes that entry: [1](#0-0) . By contrast, the sibling timeout path `dispatchTimeOut(GetRequestTimeout, ...)` deletes `_requestCommitments[commitment]` for replay protection and then refunds the very same fee to `meta.sender`: [2](#0-1) . Because `HandlerV2.handleGetRequestTimeouts` only checks that `meta.sender != address(0)` (i.e., that a request commitment still exists) and never checks whether a `GetResponse` was already delivered on this host, an already-answered `GetRequest` can still be timed out later: [3](#0-2) .

### Finding Description
State commitments stored via `storeStateMachineCommitment` are never pruned by height — only a fisherman veto deletes one, and only if it is the *latest* height: [4](#0-3) . This means an old `StateMachineHeight` for Hyperbridge, whose `state.timestamp` already exceeds a given `GetRequest`'s `timeoutTimestamp` but whose state root pre-dates Hyperbridge recording the corresponding `ResponseReceipt`, remains permanently retrievable via `host.stateMachineCommitment(message.height)`.

`handleGetRequestTimeouts` accepts *any* stored height satisfying only:
1. `request.timeout() > state.timestamp` is false (i.e., timed out relative to that height's timestamp), and
2. a non-membership proof of `ResponseReceipts` at that (old) height, and
3. `host.requestCommitments(commitment).sender != address(0)`. [3](#0-2) 

None of these checks reference the EVM host's own `_responseReceipts` (which *does* correctly guard `handleGetResponses` against double delivery): [5](#0-4) . So if a `GetResponse` for a request is legitimately delivered and processed by `handleGetResponses` (paying the relayer fee and invoking `onGetResponse`), the `_requestCommitments[commitment]` entry for that request is *not* cleared: [1](#0-0) . A relayer can later submit a `GetTimeoutMessage` referencing an older, still-stored Hyperbridge `StateMachineHeight` whose state root predates the response being recorded, and whose `state.timestamp` already exceeds the request's timeout. `PolkadotTrie.VerifyProof` will validly show non-membership of the `ResponseReceipts` entry at that old height (because it genuinely didn't exist yet), satisfying every check in `handleGetRequestTimeouts`.

### Impact Explanation
This causes two concrete fund/logic-safety failures without needing any malicious relayer, prover, or admin — only replaying two independently-valid, honestly-obtained proofs:
- **Duplicate fee payment**: the same `meta.fee` is paid once to the relayer (via `dispatchIncoming(GetResponse,...)`) and a second time refunded to `meta.sender` (via `dispatchTimeOut(GetRequestTimeout,...)`), draining the fee token balance beyond what was escrowed for that request. [6](#0-5) 
- **Double settlement in application logic**: the destination application already received `onGetResponse` for this request/commitment, then subsequently receives `onGetTimeout` for the *same* commitment, violating the exactly-once request lifecycle guarantee that ISMP applications rely on. Any app that performs state changes (e.g., unlocking escrow, marking an intent solved) on both `onGetResponse` and `onGetTimeout` will execute conflicting or duplicate settlement.

### Likelihood Explanation
The precondition — an old, still-stored `StateMachineHeight`/`StateCommitment` on `EvmHost` whose timestamp exceeds a request's timeout but predates the corresponding `ResponseReceipts` entry — is a normal artifact of asynchronous cross-chain finality; consensus updates and response generation on Hyperbridge are not atomic with each other, and nothing in `storeStateMachineCommitment`/`handleConsensus` prunes or restricts which historical height's commitment may be used for a timeout proof: [7](#0-6) . Any permissionless relayer can submit `handleGetRequestTimeouts` with such a proof once it exists, requiring no special access or compromised infrastructure.

### Recommendation
`handleGetRequestTimeouts`/`dispatchTimeOut(GetRequestTimeout,...)` should reject timeouts for requests whose response has already been delivered — e.g., by checking `_responseReceipts[commitment].relayer == address(0)` before processing, and/or `dispatchIncoming(GetResponse,...)` should delete `_requestCommitments[commitment]` once the fee has been paid, mirroring the replay protection already used for POST timeouts and POST/GET responses.

### Proof of Concept
1. Dispatch a `GetRequest` from `EvmHost` with `fee = F` and `timeoutTimestamp = T`.
2. Hyperbridge processes the query; its overlay root containing the `GetResponse` leaf is finalized in a consensus update at Hyperbridge height `H1`, and the EVM relayer calls `handleGetResponses` — `dispatchIncoming(GetResponse,...)` pays fee `F` to the relayer, but `_requestCommitments[commitment]` is left intact (`evm/src/core/EvmHost.sol:824-847`).
3. Separately, `EvmHost` still stores (never pruned) an earlier Hyperbridge `StateCommitment` at height `H0 < H1` whose `state.timestamp > T`, from before Hyperbridge recorded the `ResponseReceipts` entry for this request.
4. Anyone builds a `GetTimeoutMessage` referencing height `H0`, with a genuine non-membership proof of `ResponseReceipts[commitment]` against that state root, and calls `handleGetRequestTimeouts`.
5. All checks pass (`request.timeout() <= state.timestamp`, `meta.sender != 0`, valid non-membership proof), so `dispatchTimeOut` executes: fee `F` is refunded a second time to `meta.sender`, and `onGetTimeout` fires on the destination module even though `onGetResponse` already fired for the same commitment.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    /**
     * @dev Dispatch an incoming GET timeout to the source module.
     * @notice Does not refund any protocol fees.
     * @param timeout - timed-out get request bundled with the relayer that submitted the timeout proof
     * @param meta - fee metadata for the original request
     * @param commitment - request commitment
     */
    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
