## Analysis

The external Zeno report's core flaw is: **a price-critical time check (`block.timestamp`) is used as if L2 block timestamps always progress in lockstep with the price feed being trusted, but a sequencer outage lets stale price/state data pass a staleness check that assumes normal liveness.**

The direct local analog is in `SimplexPaymaster.sol`, which is a permissionless ERC-4337 paymaster meant to be deployed across "any EVM-compatible chain" [1](#0-0)  and is explicitly tested against L2/L2-style token decimal profiles (Base-style 6-decimal USDC, BSC-style 18-decimal USDC, BNB native asset) [2](#0-1) . Its Chainlink price-freshness guard only checks staleness against `block.timestamp`, with **no Chainlink L2 Sequencer Uptime Feed check** anywhere in the contract or repo: [3](#0-2) 

A grep across the entire repository confirms `SimplexPaymaster` contains no sequencer-uptime handling — "Sequencer" only appears in unrelated Arbitrum rollup/consensus-client code (`arb-host`, `ismp-arbitrum`), never in the paymaster's oracle pricing path.

### Title
SimplexPaymaster Chainlink price staleness check has no L2 sequencer-uptime guard, letting gas be mispriced during/after an L2 sequencer outage - ([File: evm/src/utils/SimplexPaymaster.sol])

### Summary
`SimplexPaymaster._getOraclePrice()` validates a Chainlink answer only by comparing `block.timestamp - updatedAt` against `maxOracleAge`. On L2s this check is insufficient by itself — Chainlink explicitly recommends pairing it with the network's `SequencerUptimeFeed` because L2 block timestamps and Chainlink round updates can both stall together during a sequencer outage and then "catch up" together once the sequencer resumes, making an actually-stale price look fresh to a timestamp-only check. `SimplexPaymaster` implements neither the sequencer-uptime check nor any grace-period logic after a resumption.

### Finding Description
`_getOraclePrice` is the sole gatekeeper for the price used by `_tokenPrice` in `_fetchDetails`/`_validatePaymasterUserOp` (the ERC-4337 gas-sponsorship pricing path) and in `swapAndDeposit` (fee-recycling swaps): [4](#0-3) [5](#0-4) 

The guard is purely `block.timestamp - updatedAt > maxOracleAge` [6](#0-5) . This is the well-known "Chainlink oracle on an L2 without sequencer-uptime check" pattern, structurally identical to the reported Zeno bug: a time-window guard (`whenActive`/`maxOracleAge`) is assumed sufficient, but it silently trusts that the chain's own timestamp accurately reflects wall-clock elapsed time. When an L2 sequencer is down, `block.timestamp` on that chain does not advance either, so once the sequencer comes back online and processes the backlog, both the Chainlink round's `updatedAt` and the paymaster's `block.timestamp` can be close together again even though the *true* off-chain price staleness window (during which no legitimate price update reached the chain) was much larger. Any UserOperation submitted in that resumption window is priced off a stale answer that the staleness check does not catch, exactly mirroring how `getPrice()`/`whenActive` in the Zeno report let stale time state pass as valid.

The impact is direct fund loss: `_tokenPrice` computes `tokenPrice = nativeUsd * 10^decimals * (10000+markup) / (tokenUsd * 10000)`, and this value is used to charge the ERC-20 token amount that the paymaster collects to cover the native gas it fronts via the EntryPoint. A stale, favorable price lets an unprivileged UserOperation submitter pay less token value than the true native gas cost, draining the paymaster's ERC-20/native reserves over repeated submissions timed around sequencer downtime/resumption — with no privileged, relayer, or governance actor required.

### Impact Explanation
This falls squarely in the bounty's "stealing or loss of funds" and "transaction manipulation" categories: the paymaster is a shared, governance-administered contract holding pooled EntryPoint deposits and collected ERC-20 fees [7](#0-6) . Systematic mispricing during sequencer-restart windows lets ordinary users extract value from the paymaster's treasury/EntryPoint balance by paying artificially low token amounts for real gas sponsorship, which is a genuine on-chain fund-loss vector, not merely a griefing or availability issue.

### Likelihood Explanation
Likelihood depends on how often the deployment chain's sequencer experiences outages/restarts and how attractive the resulting price discrepancy is relative to gas costs of submitting UserOperations; this is a real, recurring operational condition on centralized-sequencer L2s (Base, Arbitrum, etc.), not a contrived edge case, and requires no privileged actor — any user can simply submit paymaster-sponsored UserOperations during/after a known outage.

### Recommendation
Add a Chainlink `SequencerUptimeFeed`-equivalent check (or an explicit governance-configurable grace period after sequencer resumption) to `_getOraclePrice`, reverting or falling back to a safe default when the sequencer has been down or has only recently resumed, mirroring Chainlink's official L2 integration guidance. Track this per configured chain via `Params`/`TokenConfig` since `SimplexPaymaster` is deployed across many different EVM/L2 chains.

### Proof of Concept
1. Deploy `SimplexPaymaster` on an L2 with a centralized sequencer (as intended, per its Base/BSC-oriented test fixtures).
2. Simulate a sequencer outage: freeze `block.timestamp` progression and the Chainlink feed's `updatedAt` together (as `MockOracle.setUpdatedAt` demonstrates is fully attacker/test-controllable in `evm/tests/foundry/SimplexPaymasterTest.t.sol` lines 33-56).
3. When the sequencer resumes, submit a UserOperation with `paymasterData` referencing a token whose Chainlink round is technically within `maxOracleAge` of the now-caught-up `block.timestamp`, but whose answer reflects a price from before/during the outage rather than the current market price.
4. `_getOraclePrice` accepts the stale answer because `block.timestamp - updatedAt <= maxOracleAge` [8](#0-7) , and `_tokenPrice` charges the sender based on this incorrect rate, letting the sender underpay for sponsored gas at the paymaster's expense.

```text
    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer, , uint256 updatedAt, ) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
```
