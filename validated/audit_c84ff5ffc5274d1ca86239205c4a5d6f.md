### Title
`ReceivedOutput::read` performs no validation linking `offset`, `output`, and `outpoint`, allowing attacker-supplied bytes to be accepted as spendable funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput::read` deserializes a scalar `offset`, a `TxOut`, and an `OutPoint` from a raw byte stream and returns them as a coherent `ReceivedOutput`, yet it never checks that the triple is internally consistent: that `output.script_pubkey` is the P2TR script derived from `scanner.key + offset * G`, that the script is a P2TR output at all, or that `outpoint` references an output that actually exists. `Scanner::scan_transaction`/`scan_block` are the only legitimate producers and they guarantee all of these invariants by construction; `read` bypasses every one of them.

### Finding Description
In `networks/bitcoin/src/wallet/mod.rs`:

```rust
pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output = TxOut::consensus_decode(&mut buf_r)...;
      outpoint = OutPoint::consensus_decode(&mut buf_r)...;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
}
``` [1](#0-0) 

Contrast with the legitimate construction path, where the output is only emitted because `self.scripts.get(&output.script_pubkey)` returned a registered `offset`, and the `outpoint` is computed from the real containing transaction: [2](#0-1) 

`read` accepts any canonical `TxOut` (e.g. a P2PKH or bare-multisig `script_pubkey` the threshold key can never satisfy), any `offset` (the derived key `key + offset*G` may have odd parity or simply not match the script), and any `outpoint` (pointing at another party's UTXO or a nonexistent one). There is no parity check like `p2tr_script_buf` performs and no binding between the three fields. [3](#0-2) 

### Impact Explanation
An unprivileged party who can feed serialized bytes into `ReceivedOutput::read` can cause the wallet to report funds as received that are not spendable. Concretely:

- A `TxOut` paying to an arbitrary `script_pubkey` (e.g. `OP_TRUE` or a third party's P2WPKH) paired with a fabricated `outpoint` and a random `offset` is returned as a valid `ReceivedOutput`. Any downstream accounting crediting `output.value` as wallet-controlled funds is corrupted: the wallet "holds" value it cannot sign for.
- A mismatched `offset` produces a `ReceivedOutput` whose script commits to a different (or unusable) tweaked key than `offset` implies; `offset()` then feeds the wrong scalar into the per-input re-keying used when constructing the spend, producing signatures that do not verify against the real key, or referencing a key the group does not possess.
- A forged `outpoint` pointing to an output not owned by the key causes the spend path (sighash `Prevouts::All` in `wallet/send.rs`) to build and sign a transaction over inputs that cannot be confirmed — the resulting transaction is invalid or spends someone else's funds.

The invariant that a `ReceivedOutput` is only ever created because a real chain output matched a registered script is silently dropped at the deserialization boundary, which is precisely the improper-input-validation class of the reference report.

### Likelihood Explanation
Reachability requires serialized `ReceivedOutput` bytes from an untrusted source reaching `ReceivedOutput::read` — e.g. outputs relayed between protocol components rather than produced locally by `Scanner`. Wherever that boundary exists, exploitation is trivial: the attacker controls all three fields and only needs to supply consensus-decodable data, no cryptographic work. Exploitation is gated on the integrator actually deserializing adversarial `ReceivedOutput`s rather than obtaining them from `Scanner` directly, which lowers likelihood but is a realistic data flow for a wallet whose received outputs are transmitted/coordinated across nodes.

### Recommendation
Make `ReceivedOutput` an opaque, self-validating type:

- Change `read` to take the scanning key (or the `Scanner`) and verify that `output.script_pubkey` equals the P2TR script derived from `key + offset*G` (via `p2tr_script_buf`), rejecting any output that does not match a registered offset.
- Reject `offset` values that do not yield an even-parity tweaked key, matching the invariant enforced in `register_offset`.
- Alternatively, remove `read`/`write` from the public API and require `ReceivedOutput`s to be obtained exclusively from `Scanner::scan_transaction`/`scan_block`, so the outpoint and script validity are guaranteed by chain data.
- At minimum, document loudly that `read` produces an unverified `ReceivedOutput` and that `offset`, `output`, and `outpoint` must be re-validated against the chain before the value is credited.

### Proof of Concept
```rust
use bitcoin::{
  absolute::LockTime, transaction::Version, Amount, OutPoint, ScriptBuf,
  Transaction, TxIn, TxOut, Txid, hashes::Hash,
};
use frost::curve::Secp256k1;
use ciphersuite::Ciphersuite;
use bitcoin_serai::wallet::ReceivedOutput;
use std::io::Write;

// Any 32-byte canonical scalar
let offset = <Secp256k1 as Ciphersuite>::F::random(&mut rand_core::OsRng);

// A TxOut paying to a script the threshold key can never satisfy
let output = TxOut {
  value: Amount::from_sat(1_000_000),
  script_pubkey: ScriptBuf::new_op_return(b"nobody can spend this"),
};

// An outpoint referencing an arbitrary/nonexistent UTXO
let outpoint = OutPoint::new(Txid::all_zeros(), 0);

let mut buf = offset.to_bytes().to_vec();
buf.extend(bitcoin::consensus::encode::serialize(&output));
buf.extend(bitcoin::consensus::encode::serialize(&outpoint));

// Accepted with no error: the wallet now holds a ReceivedOutput claiming
// 1,000,000 sats that the key has no ability to spend.
let received = ReceivedOutput::read(&mut buf.as_slice()).unwrap();
assert_eq!(received.value(), 1_000_000);
```

The analogous byte stream is rejected by `Scanner::scan_transaction` (the output's script is not in `self.scripts`), proving `read` admits a strictly larger — and invalid — input space than the type's only sound constructor.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
