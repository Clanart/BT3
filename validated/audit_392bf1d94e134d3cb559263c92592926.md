Based on my investigation, this is exactly the same bug class as the WIchiFarm report — an unvalidated, attacker-supplied contract response is trusted and cast without type checking, but instead of causing fund loss it causes an unrecovered Go panic reachable from a public EVM transaction.

### Title
Unvalidated CosmWasm `token_info`/`contract_info` response causes unrecovered panic in Pointer precompile, permitting a transaction-triggered node halt - (File: precompiles/pointer/pointer.go)

### Summary
`AddCW20`, `AddCW721`, and `AddCW1155` in the Pointer precompile query an attacker-chosen CosmWasm contract and blindly type-assert the returned `name`/`symbol` JSON fields as `string`, exactly mirroring the WIchiFarm pattern of trusting an unvalidated external contract's data without any type/shape check before acting on it.

### Finding Description
`AddCW20` takes a caller-supplied `cwAddr` (any bech32 address, not necessarily a real CW20 contract), queries it via `QuerySmartSafe(ctx, cwAddress, []byte("{\"token_info\":{}}"))`, unmarshals the JSON response into a generic `map[string]interface{}`, and then does:
```go
name := formattedRes["name"].(string)
symbol := formattedRes["symbol"].(string)
``` [1](#0-0) 
There is no `ok` check on the type assertion and no schema validation that the queried contract is actually a CW20 contract. Any wasm contract — including one deliberately crafted by an attacker, or simply a contract that happens to answer `{"token_info":{}}` with a `name`/`symbol` field that is a number, object, array, `null`, or omitted — will cause a Go runtime panic (`interface conversion: interface {} is float64, not string`) inside `AddCW20`. The identical pattern exists in `AddCW721`/`AddCW1155` [2](#0-1) [3](#0-2) , as well as in every legacy pointer precompile version (v552, v555, v600, v614, etc.) [4](#0-3) .

Unlike other precompiles in the codebase (e.g. `solo.go`) which wrap their `Execute` in a `defer recover()` specifically to catch panics and convert them into reverts [5](#0-4) , the Pointer precompile's `Execute` has no such recovery [6](#0-5) . The outer dynamic-gas-precompile wrapper (`precompiles/common/precompiles.go` `Run`) also does not `recover()` from generic panics — its comment and test (`TestDynamicGasPrecompileRepanicsNonGas`) explicitly confirm that only gas-meter panics are caught and converted to reverts, while any other panic (like this type assertion) is required to propagate rather than be masked [7](#0-6) .

### Impact Explanation
Because the panic is not recovered anywhere in the precompile call chain, it propagates out of `RunAndCalculateGas`/`Run` during EVM execution of the transaction. Whether this crashes the node process or is caught further up by the ante-handler/baseapp recovery machinery is not something I could fully confirm from the index (the `sei-cosmos/baseapp/recovery.go` layer does exist and generally catches panics per-transaction at the ABCI boundary), so the concrete worst-case (validator process crash vs. transaction-only failure) is uncertain without deeper tracing through `x/evm` message handling and the ABCI `DeliverTx` panic-recovery wrapper. If baseapp-level recovery does NOT catch it (which the pointer-specific and dynamic-gas-precompile tests suggest is the intended, unguarded behavior for non-gas panics), any unprivileged account could submit a single `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` transaction targeting a contract they control that returns malformed `token_info`/`contract_info`, deterministically panicking every validator that processes the block — a public-RPC-reachable, single-transaction DoS.

### Likelihood Explanation
High likelihood of reachability: `addCW20Pointer`, `addCW721Pointer`, and `addCW1155Pointer` are public precompile methods callable by any EVM transaction sender with no special permission, and the target CosmWasm contract is entirely attacker-controlled (any user can instantiate a wasm contract that responds to `token_info`/`contract_info` queries with a non-string `name` or `symbol`, or omits them entirely so `formattedRes["name"]` is `nil` and the assertion still panics).

### Recommendation
In `precompiles/pointer/pointer.go` (`AddCW20`, `AddCW721`, `AddCW1155`), use the comma-ok form of the type assertion and return an error instead of panicking, e.g.:
```go
name, ok := formattedRes["name"].(string)
if !ok {
    return nil, 0, fmt.Errorf("invalid token_info response: name is not a string")
}
symbol, ok := formattedRes["symbol"].(string)
if !ok {
    return nil, 0, fmt.Errorf("invalid token_info response: symbol is not a string")
}
```
Apply the same fix to all legacy versions of the pointer precompile that contain the identical pattern, and add a `defer recover()` in `Execute` as a defense-in-depth measure consistent with `precompiles/solo/solo.go`.

### Proof of Concept
1. Deploy (or use `wasmd` to instantiate) a CosmWasm contract whose `token_info` query handler returns `{"name": 12345, "symbol": "X", "decimals": 6, "total_supply": "0"}` (a JSON number instead of a string for `name`).
2. From any account, submit an EVM transaction calling `addCW20Pointer(cwAddr)` on the Pointer precompile (`0x000000000000000000000000000000000000100b`) with `cwAddr` set to the malicious contract's bech32 address.
3. `QuerySmartSafe` succeeds and returns the JSON above; `json.Unmarshal` decodes `"name": 12345` as `float64(12345)`.
4. `formattedRes["name"].(string)` panics with `interface conversion: interface {} is float64, not string` inside `AddCW20`, with no `recover()` anywhere in the call path (`pointer.go` `Execute`, `precompiles/common/precompiles.go` `Run`) to catch it — as confirmed by `TestDynamicGasPrecompileRepanicsNonGas` explicitly asserting non-gas panics must propagate [7](#0-6) .
