### Title
Pointer/wrapper contracts hardcode standard ERC721/CW721 transfer calls, permanently freezing NFTs from collections with custom transfer-restriction logic (Moonbird-style nesting) - ([File: contracts/src/CW721ERC721Pointer.sol], [File: example/cosmwasm/cw721/src/contract.rs])

### Summary
Sei's CW721↔ERC721 pointer/wrapper contracts always issue a hardcoded, standard `transferFrom`/`transfer_nft` call to move the underlying NFT, with no way to invoke any alternate transfer method a collection might require. Any NFT collection whose base contract restricts the standard transfer path while in a special state (the same pattern Moonbirds uses via `safeTransferWhileNesting`) becomes permanently untransferable through Sei's pointer bridge once it enters that state.

### Finding Description
On the CW→EVM pointer side, `CW721ERC721Pointer.transferFrom` unconditionally builds a `transfer_nft` CosmWasm message and executes it against the underlying CW721 contract — there is no alternate code path for tokens that need a different execute message to move while in a restricted state: [1](#0-0) 

On the EVM→CW wrapper side, the CosmWasm `cw721` wrapper's `transfer_nft` handler always requests a standard ERC721 `transferFrom` payload and executes it via `DelegateCallEvm` against the wrapped ERC721 contract — again with no support for any non-standard transfer entrypoint: [2](#0-1) 

The payload itself is generated by packing the fixed `transferFrom(address,address,uint256)` selector, with no alternative selector option: [3](#0-2) 

This mirrors the reported Ajna `ERC721Pool` issue exactly: any ERC721 collection that overrides `transferFrom`/`safeTransferFrom` to revert while a token is in a special mode (staking, nesting, locking, etc.) — as Moonbirds does via its `nestingStarted`/`_beforeTokenTransfers` check, requiring `safeTransferWhileNesting` instead — cannot be moved through Sei's pointer bridge, because the bridge code paths are hardcoded to the standard transfer call and have no fallback or alternate invocation mechanism.

### Impact Explanation
Once an NFT enters the restricted transfer state on its native chain/contract, any attempt to move it through the pointer (`transferFrom` on the ERC721 pointer, or `transfer_nft`/`send_nft` on the CW721 wrapper) will revert every time, since the underlying contract itself rejects the standard transfer call. Because the pointer/wrapper contracts expose no alternate execute path, the token becomes permanently non-transferable through this bridge — a form of permanent asset freezing for any holder who relies on the pointer representation to move or trade the NFT (e.g., listing on an EVM marketplace via the ERC721 pointer, or bridging into CosmWasm dApps via the CW721 wrapper).

### Likelihood Explanation
This requires no privileged action and no malicious actor — a normal pointer/wrapper user or any dApp integrator interacting with a collection that implements state-gated transfer restrictions (a known, real-world NFT design pattern, as used by Moonbirds and similar projects) will trigger this automatically. Likelihood scales with adoption of such collections through Sei's pointer/wrapper mechanism.

### Recommendation
Extend the pointer (`CW721ERC721Pointer.sol`) and wrapper (`example/cosmwasm/cw721/src/contract.rs`) transfer logic to support alternate/parameterized transfer entrypoints (e.g., allow specifying a custom function selector or calldata for the underlying transfer call), or document and gate registration of pointers/wrappers for known non-standard collections, and provide an escape hatch (e.g., a raw passthrough execute/call method) so users can invoke the collection's own required transfer method instead of being limited to the hardcoded standard transfer call.

### Proof of Concept
1. Deploy (or identify) an ERC721 collection that, like Moonbirds, overrides `transferFrom`/`safeTransferFrom` to revert whenever a token is in a "locked" state, requiring a special function to move it.
2. Register a CW721 wrapper for that ERC721 collection via the standard pointer registration flow, and put a token into the locked state via the collection's own native mechanism.
3. Attempt `transfer_nft`/`send_nft` on the CW721 wrapper (`example/cosmwasm/cw721/src/contract.rs`, `transfer_nft`); the delegated `transferFrom` call reverts because the underlying token is locked.
4. Observe there is no alternate execute message in the wrapper to invoke the collection's special unlock/transfer method — the token cannot be moved through the wrapper as long as it remains locked, constituting a permanent freeze of the wrapped representation's transferability.

    function transferFrom(address from, address to, uint256 tokenId) public override {
        if (to == address(0)) {
            revert ERC721InvalidReceiver(address(0));
        }
        require(from == ownerOf(tokenId), "`from` must be the owner");
        string memory recipient = _formatPayload("recipient", _doubleQuotes(AddrPrecompile.getSeiAddr(to)));
        string memory tId = _formatPayload("token_id", _doubleQuotes(Strings.toString(tokenId)));
        string memory req = _curlyBrace(_formatPayload("transfer_nft", _curlyBrace(_join(recipient, tId, ","))));
        _execute(bytes(req));
    }

fn transfer_nft(
    deps: DepsMut<EvmQueryWrapper>,
    info: &MessageInfo,
    recipient: &str,
    token_id: &str,
) -> Result<Response<EvmMsg>, ContractError> {
    deps.api.addr_validate(recipient)?;

    let erc_addr = ERC721_ADDRESS.load(deps.storage)?;

    let querier = EvmQuerier::new(&deps.querier);
    let owner = querier.erc721_owner(info.sender.to_string(), erc_addr.to_string(), token_id.to_string())?.owner;
    let payload = querier.erc721_transfer_payload(owner, recipient.to_string(), token_id.to_string())?;
    let msg = EvmMsg::DelegateCallEvm { to: erc_addr, data: payload.encoded_payload };
    let res = Response::new().add_message(msg);

    Ok(res)
}

func (h *EVMQueryHandler) HandleERC721TransferPayload(ctx sdk.Context, from string, recipient string, tokenId string) ([]byte, error) {
	abi, err := cw721.Cw721MetaData.GetAbi()
	if err != nil {
		return nil, err
	}
	fromEvmAddr, found := h.k.GetEVMAddress(ctx, sdk.MustAccAddressFromBech32(from))
	if !found {
		return nil, types.NewAssociationMissingErr(from)
	}
	toEvmAddr, found := h.k.GetEVMAddress(ctx, sdk.MustAccAddressFromBech32(recipient))
	if !found {
		return nil, types.NewAssociationMissingErr(recipient)
	}
	t, ok := sdk.NewIntFromString(tokenId)
	if !ok {
		return nil, errors.New("invalid token ID for ERC721, must be a big Int")
	}
	bz, err := abi.Pack("transferFrom", fromEvmAddr, toEvmAddr, t.BigInt())
	if err != nil {
		return nil, err
	}
	res := bindings.ERCPayloadResponse{EncodedPayload: base64.StdEncoding.EncodeToString(bz)}
	return json.Marshal(res)
}
