### Title
Attacker-controlled FROST preprocess can force the aggregate nonce to the point at infinity, panicking BIP-340 signing (denial of service) - ([File: networks/bitcoin/src/crypto.rs])

### Summary
CVE-2017-9745's bug class is "crafted input bytes reach a parser/computation that crashes (or worse)". The reachable Serai analog lives in the untrusted-preprocess → `sign_share` path: an unprivileged cosigner submits a `Preprocess` whose `Commitments` are chosen so the aggregated nonce `R = Σ (D_l + ρ_l·E_l)` is the group identity. `crypto/frost/src/nonce.rs::BindingFactor::nonces` performs no identity check on the result, and `networks/bitcoin/src/crypto.rs::Hram::hram` (via `x()`/`x_only()`) `expect`s a non-infinity point, so the honest signer's process panics mid-signing.

### Finding Description
`AlgorithmSignMachine::read_preprocess` accepts peer-supplied bytes into `Commitments::read` (`crypto/frost/src/sign.rs`, `crypto/frost/src/nonce.rs:133-139`). The aggregate nonce is computed in `BindingFactor::nonces` (`crypto/frost/src/nonce.rs:194-211`) as `D + multiexp_vartime(statements)` with no rejection of the identity result. The binding factor `ρ_l` is a deterministic transcript challenge over all commitments (`nonce.rs:161-173`), so a malicious participant who reads the other preprocesses first can compute the honest parties' contributions, pick arbitrary `E_i`, and solve `D_i = -(Σ honest bound commitments) - ρ_i·E_i`, forcing `R` to identity. The Bitcoin `Schnorr` algorithm then calls `self.0.sign_share(...)` → `Hram::hram` → `x(R)` (`networks/bitcoin/src/crypto.rs:13-16`), which executes `encoded.x().expect("point at infinity")` and panics. The same panic path exists in `x_only` (`crypto.rs:21-23`) and is documented ("If either `R` or `A` is the point at infinity, this will panic", `crypto.rs:54`).

### Impact Explanation
Every honest validator/processor executing `machine.sign(preprocesses, msg)` over the crafted preprocess set crashes. In `processor/src/batch_signer.rs`, `processor/src/signer.rs`, `processor/src/cosigner.rs`, and `processor/src/slash_report_signer.rs` the `FrostError` match arms never get a chance to return `InvalidParticipant` — the panic is inside the algorithm, before any error is produced. Result: the threshold signing session halts; batches/Bitcoin outputs cannot be signed, giving a remote, low-cost denial of service of the signing quorum (the same impact class as CVE-2017-9745's crash, plus sustained liveness loss for fund movement).

### Likelihood Explanation
Any participant able to submit a preprocess (a cosigning validator with public message bytes) can trigger it. The attack requires observing the other preprocesses for the session (or being last to publish, as preprocesses are collected into a `HashMap` and sorted), after which computing the cancelling commitment is a few group operations — no grinding, no collusion, no threshold assumption needed. One malicious preprocess aborts the whole attempt.

### Recommendation
In `BindingFactor::nonces` (`crypto/frost/src/nonce.rs:194-211`), reject/handle identity nonce sums (e.g., return a `FrostError::InvalidPreprocess(l)` blame or resample), rather than propagating an unusable `R` into the `Algorithm`. Alternatively/additionally, make `Hram::hram`/`x`/`x_only` (`networks/bitcoin/src/crypto.rs`) return `Result` and map identity `R`/`A` to `FrostError` instead of `expect`/panic, so a crafted preprocess produces attributable blame instead of a process abort.

### Proof of Concept
```rust
// In a signing session with planned nonce list `planned_nonces` and other
// preprocess commitments already collected:
// 1. Compute honest aggregate contribution for nonce 0, generator 0:
//      H = Σ_{l≠me} (D_l[0][0] + ρ_l * E_l[0][0])   // BindingFactor::nonces logic
// 2. Choose arbitrary E_i; compute ρ_i from the cloned transcript
//    (nonce.rs:161-173) over the commitment set including our own;
//    set D_i = -H - ρ_i * E_i.
// 3. Broadcast Preprocess{ commitments: { nonces: [[D_i, E_i], ...] }, .. }.
// 4. Each honest signer runs machine.read_preprocess(...) successfully
//    (bytes are well-formed; only semantics are malicious), then
//    machine.sign(preprocesses, msg) → BindingFactor::nonces returns R = G::identity()
//    → Schnorr::sign_share → IetfSchnorr::sign_share → Hram::hram(R, A, m)
//    → x(R) → `encoded.x().expect("point at infinity")` → panic (crash).
```
The byte-level reachability is `Preprocess` → `Commitments::read` → `NonceCommitments::read`/`GeneratorCommitments::read` (`crypto/frost/src/nonce.rs:34-80, 133-139`), all attacker-controlled, in-scope (`crypto/frost`, `networks/bitcoin/src/crypto.rs`).

Note: I could not fully verify whether some caller above `machine.sign` pre-filters commitments whose aggregate nonce is identity; the code inspected (`batch_signer.rs`, `sign.rs`, `nonce.rs`, `crypto.rs`) contains no such check.
