The report's "collateral shortfall/undercollateralization" bug class maps to a concrete custody-binding break in Clementine: **the on-chain attribution of reimbursement credit (`operator_xonly_pk`) is not cryptographically bound to whoever actually funds the payout**, because the payout transaction's `OP_RETURN` output is outside the committed sighash.

### Title
Unsigned OP_RETURN operator attribution in `payout_tx` lets any funder overwrite/nullify an honest operator's reimbursement credit - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
The `payout_tx` that fronts a Citrea withdrawal is signed by the user with `SinglePlusAnyoneCanPay` sighash, which only commits to the single input being spent and the output at the same index (the user payout). The transaction's `OP_RETURN` output — which is the *sole* source of truth the verifiers/operators use to decide **which operator gets credited with fronting the payout and is therefore eligible for reimbursement** — is completely unconstrained by that signature. Any party able to front the same shortfall amount can construct a competing, equally valid version of the payout transaction with a different (or invalid) `OP_RETURN`, and if it confirms instead of the honest operator's broadcast, the honest operator is permanently locked out of reimbursement for that deposit.

### Finding Description
`create_payout_txhandler` builds the payout transaction with the user-signed input at index 0 (key-spend), the user payout at output 0, an anchor output at index 1, and an `OP_RETURN` at index 2 carrying the *fronting* operator's x-only pubkey: [1](#0-0) 

The user's signature over this transaction is `SinglePlusAnyoneCanPay`, documented explicitly as only binding input 0 and output 0: [2](#0-1) 

Verifiers determine which operator is credited for a withdrawal purely by re-parsing the `OP_RETURN` of whichever transaction is later found on-chain spending the withdrawal UTXO — with no check that this transaction is the one the recorded operator actually built/broadcast: [3](#0-2) 

That value is persisted as `payout_payer_operator_xonly_pk` and is the equality the whole reimbursement path is keyed on: [4](#0-3) 

The operator's own reimbursement flow strictly requires this field to equal its own key, otherwise it errors out and reimbursement is unreachable for that deposit: [5](#0-4) 

and the automated payout-checker task only ever looks for payouts explicitly tagged with the operator's own xonly pubkey: [6](#0-5) 

**The binding that should hold:** `{operator credited for reimbursement}` == `{party that actually funded the shortfall (out_amount − input_amount) of the confirmed payout_tx}`.
**What actually holds:** `{operator credited}` == `{OP_RETURN bytes of whichever payout_tx version happens to confirm}`, and that OP_RETURN is not covered by any signature, so it can be freely rewritten by anyone who reconstructs an equivalent, equally-valid transaction (same signed input/output0, different unsigned outputs) and gets it confirmed first.

Because `output_amount` in `WithdrawParams`/`is_profitable` is deliberately structured so that the committed input (`in_outpoint`) is normally smaller than the payout, an honest operator funds the difference via its own wallet (`fund_raw_transaction` with `add_inputs: true`): [7](#0-6) [8](#0-7) 

An unprivileged party who observes this unconfirmed tx (e.g., in the mempool, or by intercepting the same off-chain user signature) can construct a rival transaction spending the exact same signed input to the exact same output-0 payout, but supplying the shortfall itself and replacing the `OP_RETURN` with garbage/an unrelated pubkey. If that version confirms instead, `update_finalized_payouts` records either `None` or a bogus operator pubkey as `payout_payer_operator_xonly_pk` — permanently and irreversibly, since there is no retry/override path once the withdrawal UTXO is spent — leaving the honest operator, who genuinely paid the user, with no way to claim reimbursement (`validate_payer_is_operator` fails forever, and `PayoutCheckerTask` never finds a matching entry for that operator).

### Impact Explanation
This breaks the Critical-tier custody binding "an honest operator permanently unable to be reimbursed": the operator that truly fronted BTC to the withdrawing user (the party that paid) can lose all entitlement to reimbursement because the credited identity is derived from a mutable, unsigned transaction field rather than from an authenticated claim tied to the actual funder.

### Likelihood Explanation
Exploitation requires only observing an unconfirmed `payout_tx` (standard, public mempool visibility, no operator/verifier role, no key compromise) and being willing/able to front the same BTC shortfall to win the confirmation race. No signing key, N-of-N role, or privileged RPC access is needed — only capital and network monitoring, which are attacker capabilities available to any unprivileged party.

### Recommendation
- **Short term:** Document/flag that `OP_RETURN` operator-attribution in `payout_tx` is unauthenticated, and consider rejecting/replacing conflicting unconfirmed payout candidates defensively (e.g., operator monitors mempool for competing spends of the same withdrawal UTXO and reacts before confirmation).
- **Long term:** Bind the reimbursement-credit output cryptographically to the funding party — e.g., include the `OP_RETURN` operator pubkey inside the sighash committed by the user (use `SIGHASH_ALL` variant or otherwise commit to all outputs), or otherwise ensure attribution cannot be altered without invalidating the user's authorization signature.

### Proof of Concept
1. Honest operator O calls `withdraw`/`internal_withdraw`, producing and broadcasting (unconfirmed) `payout_tx_O`: input = withdrawal UTXO (user-signed, `SinglePlusAnyoneCanPay`), output0 = user payout, output1 = anchor, output2 = `OP_RETURN(O_xonly_pk)`, funded by O's wallet inputs for the shortfall — see `core/src/operator.rs:560-675` and `core/src/builder/transaction/operator_reimburse.rs:407-436`.
2. Attacker A observes `payout_tx_O` in the mempool (or otherwise obtains the same `in_signature`/`in_outpoint`/`output_txout`), and constructs `payout_tx_A`: identical input+output0 (satisfying the same `SinglePlusAnyoneCanPay` signature), but its own wallet-funded extra inputs, and `OP_RETURN` replaced with an invalid/garbage value (or a different operator's key).
3. A broadcasts `payout_tx_A` with a competitive fee; it confirms instead of `payout_tx_O`.
4. `update_finalized_payouts` (`core/src/verifier.rs:2283-2353`) scans the confirming tx, parses its `OP_RETURN`, and stores `payout_payer_operator_xonly_pk` = garbage/`None`.
5. `validate_payer_is_operator` (`core/src/operator.rs:1686-1729`) subsequently errors for operator O ("Payer info not found" / mismatch), and `get_first_unhandled_payout_by_operator_xonly_pk` (`core/src/database/verifier.rs:282-313`) never surfaces this withdrawal for O — O paid the user but can never be reimbursed for this deposit.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

                payout_tx_blockhash = c.payout_tx_blockhash

                    .push_bind(block_hash);

        );

            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

    /// Prepares a withdrawal by:
    ///
    /// 1. Checking if the withdrawal has been made on Citrea
    /// 2. Verifying the given signature
    /// 3. Checking if the withdrawal is profitable or not
    /// 4. Funding the withdrawal transaction using TxSender RBF option
    ///
    /// # Parameters
    ///
    /// - `withdrawal_idx`: Citrea withdrawal UTXO index
    /// - `in_signature`: User's signature that is going to be used for signing
    ///   withdrawal transaction input
    /// - `in_outpoint`: User's input for the payout transaction
    /// - `out_script_pubkey`: User's script pubkey which will be used
    ///   in the payout transaction's output
    /// - `out_amount`: Payout transaction output's value
    ///
    /// # Returns
    ///
    /// - Ok(()) if the withdrawal checks are successful and a payout transaction is added to the TxSender
    /// - Err(BridgeError) if the withdrawal checks fail
    pub async fn withdraw(
        &self,
        withdrawal_index: u32,
        in_signature: taproot::Signature,
        in_outpoint: OutPoint,
        out_script_pubkey: ScriptBuf,
        out_amount: Amount,
    ) -> Result<Transaction, BridgeError> {
        tracing::info!(
            "Withdrawing with index: {}, in_signature: {:?}, in_outpoint: {:?}, out_script_pubkey: {}, out_amount: {}",
            withdrawal_index,
            in_signature,
            in_outpoint,
            out_script_pubkey,
            out_amount
        );

        // Prepare input and output of the payout transaction.
        let input_prevout = self.rpc.get_txout_from_outpoint(&in_outpoint).await?;
        let input_utxo = UTXO {
            outpoint: in_outpoint,
            txout: input_prevout,
        };
        let output_txout = TxOut {
            value: out_amount,
            script_pubkey: out_script_pubkey,
        };

        // Check Citrea for the withdrawal state.
        let withdrawal_utxo = self
            .db
            .get_withdrawal_utxo_from_citrea_withdrawal(None, withdrawal_index)
            .await?;

        if withdrawal_utxo != input_utxo.outpoint {
            return Err(eyre::eyre!("Input UTXO does not match withdrawal UTXO from Citrea: Input Outpoint: {0}, Withdrawal Outpoint (from Citrea): {1}", input_utxo.outpoint, withdrawal_utxo).into());
        }

        let operator_withdrawal_fee_sats =
            self.config
                .operator_withdrawal_fee_sats
                .ok_or(BridgeError::ConfigError(
                    "Operator withdrawal fee sats is not specified in configuration file"
                        .to_string(),
                ))?;
        if !Self::is_profitable(
            input_utxo.txout.value,
            output_txout.value,
            self.config.protocol_paramset().bridge_amount,
            operator_withdrawal_fee_sats,
        ) {
            return Err(eyre::eyre!("Not enough fee for operator").into());
        }

    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {

                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };
