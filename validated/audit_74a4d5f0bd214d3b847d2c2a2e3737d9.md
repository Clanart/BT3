### Title
Command Injection via Unescaped Repository Path in Windows "Open in Shell" (GitBash/Cygwin/Alacritty) - (File: app/src/lib/shells/win32.ts)

### Summary
This is the closest local analog to the OpenZeppelin Wizard bug (`opts.name`/`opts.uri` interpolated unescaped into generated code that later executes). In GitHub Desktop, the repository directory path is interpolated unescaped into shell command-line strings that are executed via Node's `child_process.spawn(..., { shell: true })`, exactly the same "string breaks out of its intended literal and is parsed as code" pattern as the report, except the "code" here is a Windows shell command line instead of a Hardhat/Foundry test file.

### Finding Description
`launch()` in [1](#0-0)  builds shell invocations by directly template-literal-interpolating the repository `path` into argument strings such as `` `--cd="${path}"` `` (GitBash) and `` `--working-directory "${path}"` `` (Alacritty), then passes them to `spawn(..., { shell: true, cwd: path })`. The Cygwin branch is worse, embedding `path` inside a full inline shell script: `` `/bin/sh -lc 'cd "$(cygpath "${path}")"; exec bash` `` [2](#0-1) . None of this code uses the escaping helpers that exist elsewhere in the codebase specifically for this purpose — `bashEscape`/`cmdEscape`/`powershellEscape` in [3](#0-2)  — which shows the project is otherwise aware that unescaped strings passed to a `shell: true` spawn are dangerous, but that guard was never applied to `win32.ts`'s `launch()`.

The `path` value that reaches this sink originates from the repository's local directory name, which for cloned repositories is derived from the repository name via `sanitizeCloneName()` in [4](#0-3) . That function only strips path-traversal segments and a trailing `.git` suffix — it does not strip or escape shell metacharacters such as `&`, `%`, `|`, `^`, `'`, backticks, or `$()`, all of which are valid characters in Windows/NTFS file and directory names (only `<>:"/\|?*` are illegal on NTFS, so `&`, `%`, `^` etc. survive). The Windows-specific sanitizer that does strip a few of these, `safeDirectoryName()` in [5](#0-4) , is only used by the "Create New Repository" flow, not by the clone flow that uses `sanitizeCloneName`.

### Impact Explanation
If a user clones a repository (or opens/adds a folder) whose resulting local directory name contains shell metacharacters permitted by NTFS (e.g. a folder named `repo & calc.exe & `), then chooses "Open in Git Bash" / "Open in Cygwin" / "Open in Alacritty" from Desktop's repository menu (`_openShell` → `launch`, wired via [6](#0-5)  and [7](#0-6) ), the injected metacharacters are interpreted by `cmd.exe` (invoked because of `shell: true`) as command separators, allowing arbitrary command execution on the victim's machine. This is unprompted/naturally-triggered code execution outside the repository sandbox, matching the "code execution via attacker-controlled repository name/path" impact class.

### Likelihood Explanation
Requires a normal, expected user action (cloning a repository and using the built-in "Open in Shell" feature), no admin rights, no pre-existing malware, and no unnatural steps — the attacker only needs to control the repository name that becomes the local clone folder name. This is comparable in likelihood to the original Wizard bug, which also required an ordinary "download and run tests" workflow.

### Recommendation
Apply the existing `cmdEscape`/`bashEscape` helpers from `app/src/lib/hooks/shell-escape.ts` (or equivalent proper quoting) to the `path` value before interpolating it into any command string in `win32.ts`'s `launch()`, for every branch (GitBash, Cygwin, Alacritty, PowerShell, Hyper, Warp, etc.), and audit `sanitizeCloneName` to also reject/replace shell-significant characters, not just path-traversal sequences.

### Proof of Concept
1. Attacker creates/renames a GitHub repository so its name, after `sanitizeCloneName`, becomes a folder name containing an NTFS-legal but shell-significant sequence, e.g. `repo & calc.exe & `.
2. Victim clones this repository in GitHub Desktop on Windows; the local path becomes `...\repo & calc.exe & `.
3. Victim right-clicks the repository and selects "Open in Git Bash" (or Cygwin/Alacritty).
4. `launch()` builds `spawn(gitBashPath, ['--cd="...\\repo & calc.exe & "'], { shell: true, cwd: path })`; `cmd.exe` parses the `&` as a command separator and executes `calc.exe` (or any attacker-chosen command) alongside launching the shell. [8](#0-7) 

Note: I was not able to fully verify within the available searches whether Windows folder-creation code paths anywhere else (outside `create-repository.tsx`) apply additional sanitization to clone-derived directory names before `mkdir`/`fs` calls; a Devin session with full repository access would be needed to trace every caller of `sanitizeCloneName` and confirm no additional filtering occurs before the directory is actually created on disk.

export function launch(
  foundShell: FoundShell<Shell>,
  path: string
): ChildProcess {
  const shell = foundShell.shell

  switch (shell) {
    case Shell.PowerShell:
      return spawn('START', ['"PowerShell"', `"${foundShell.path}"`], {
        shell: true,
        cwd: path,
      })
    case Shell.PowerShellCore:
      return spawn(
        'START',
        [
          '"PowerShell Core"',
          `"${foundShell.path}"`,
          '-WorkingDirectory',
          `"${path}"`,
        ],
        {
          shell: true,
          cwd: path,
        }
      )
    case Shell.Hyper:
      const hyperPath = `"${foundShell.path}"`
      log.info(`launching ${shell} at path: ${hyperPath}`)
      return spawn(hyperPath, [`"${path}"`], {
        shell: true,
        cwd: path,
      })
    case Shell.Alacritty:
      const alacrittyPath = `"${foundShell.path}"`
      log.info(`launching ${shell} at path: ${alacrittyPath}`)
      return spawn(alacrittyPath, [`--working-directory "${path}"`], {
        shell: true,
        cwd: path,
      })
    case Shell.GitBash:
      const gitBashPath = `"${foundShell.path}"`
      log.info(`launching ${shell} at path: ${gitBashPath}`)
      return spawn(gitBashPath, [`--cd="${path}"`], {
        shell: true,
        cwd: path,
      })
    case Shell.Cygwin:
      const cygwinPath = `"${foundShell.path}"`
      log.info(`launching ${shell} at path: ${cygwinPath}`)
      return spawn(
        cygwinPath,
        [`/bin/sh -lc 'cd "$(cygpath "${path}")"; exec bash`],
        {
          shell: true,
          cwd: path,
        }
      )

export function sanitizeCloneName(name: string): string | null {
  const components = name.split(/[/\\:]/)

  let lastComponent = ''
  for (let i = components.length - 1; i >= 0; i--) {
    if (components[i].length > 0) {
      lastComponent = components[i]
      break
    }
  }

  if (lastComponent.length === 0) {
    return null
  }

  if (lastComponent.endsWith('.git')) {
    lastComponent = lastComponent.slice(0, -4)
  }

  if (
    lastComponent === '..' ||
    lastComponent === '.' ||
    lastComponent.length === 0
  ) {
    return null
  }

  return lastComponent
}
