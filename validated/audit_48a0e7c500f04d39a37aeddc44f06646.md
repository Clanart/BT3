### Title
`LazyFieldLite`/`InternalLazyField` silently substitute a corrupted/invalid embedded message with the default instance, and the corruption signal is never exposed through the public `Message`/`MessageLite` API used by `getExtension` - ([File: java/core/src/main/java/com/google/protobuf/LazyFieldLite.java])

### Summary
Perennial's oracle bug boils down to: an "invalid" state is collapsed onto the same representation as a normal "valid, unchanged" state (price==0 check), so a consumer (`Market._processOrderGlobal`) that only inspects the observable value cannot tell "this is genuinely valid" from "this is a stand-in used because the real value could not be produced." The Protobuf analog is `LazyFieldLite.ensureInitialized()` (and its MessageSet‑aware sibling `InternalLazyField.ensureInitialized()`), which lazily parses an extension's serialized bytes on first access. If the bytes fail to parse (`InvalidProtocolBufferException`), the code sets an internal `corrupted` flag but then assigns `this.value = defaultInstance` — the exact same value that a legitimately-empty/absent extension would have. ` [1](#0-0) ` The `corrupted` flag is package-private (`boolean isCorrupted()`), never surfaced through `Message`, `MessageLite`, `getExtension(...)`, `hasExtension(...)`, or any other public accessor. ` [2](#0-1) ` A consuming application calling `msg.getExtension(fooExtension)` on a message containing a corrupted lazily-parsed extension therefore receives `Foo.getDefaultInstance()` indistinguishably from the case where the extension was never set, with no exception, no log, and no signal that the wire bytes were invalid.

### Finding Description
`LazyFieldLite` stores a MessageSet/extension field either as raw `delayedBytes` or as a parsed `value`. On first read, `ensureInitialized` attempts `defaultInstance.getParserForType().parseFrom(delayedBytes, extensionRegistry)`. On failure it does:
```
} catch (InvalidProtocolBufferException e) {
  // Nothing is logged and no exceptions are thrown. Clients will be unaware that this proto was invalid.
  this.corrupted = true;
  this.value = defaultInstance;
  this.memoizedBytes = ByteString.EMPTY;
}
```
` [3](#0-2) `
This is by design documented in the comment itself ("Clients will be unaware that this proto was invalid"). The same pattern exists in `mergeValueAndBytes` and `mergeFrom(CodedInputStream, ExtensionRegistryLite)`, which silently keep the previous (or default) value on a parse failure instead of surfacing the corruption. ` [4](#0-3) `

The equivalent full-runtime class, `InternalLazyField`, has the same invariant comment ("If corrupted is true, value must be null") and the same behavior on `ensureInitialized`, throwing only when `LAZY_VERIFY_ON_ACCESS` mode is explicitly enabled via the extension registry; the default mode silently substitutes the default instance. ` [5](#0-4) ` ` [6](#0-5) `

The test suite confirms this is intentional, non-error-signaling behavior for the default lazy mode: `testLoadCorruptedLazyField_getsReplacedWithEmptyMessage` shows that after loading a MessageSet with a corrupted extension payload, `messageSet.getExtension(...)` returns `TestMessageSetExtension1.getDefaultInstance()` with no thrown exception unless `LAZY_VERIFY_ON_ACCESS` mode is active. ` [7](#0-6) `

**External invariant that transfers:** "A value derived from invalid/unrecoverable input must be observably distinguishable from a value that represents legitimate default/absent state." In the oracle bug, `_prices[version.timestamp]` for an expired/invalid version is set to the previous valid price, and `KeeperOracle.at()` infers validity purely from `price != 0`, so the consumer (`Market`) cannot detect the invalidity. In Protobuf's default lazy-extension path, the corrupted state is likewise collapsed into the *same* value (`defaultInstance`) that represents legitimate absence, and the only bit that records the real state (`corrupted`) is deliberately hidden from the public API that application code actually calls (`getExtension`).

**Where the check fails to transfer perfectly (and why it's still Medium, not High):** Unlike the oracle case, this is a long-standing, explicitly documented design decision for the *default* (non-`LAZY_VERIFY_ON_ACCESS`) lazy-extension mode in Java protobuf, present specifically for lazily-parsed proto2 `MessageSet` extensions and general lazy message fields (`lazy = true` field option) — it is not a wire-format-wide parsing invariant violation for all Protobuf parsing paths (regular non-lazy fields parsed via `CodedInputStream`/`ArrayDecoders` do throw `InvalidProtocolBufferException` synchronously, immediately failing the whole `parseFrom` call). The vulnerability is confined to the opt-in lazy-parsing feature, and a stricter mode (`LAZY_VERIFY_ON_ACCESS`) already exists as a mitigation that applications can (and per upstream guidance, should) enable.

### Impact Explanation
An application that relies on a lazily-parsed extension (MessageSet-style extension, or a field annotated `[lazy=true]`) being either "correctly parsed" or "throwing on access" can instead silently receive a default-instance value when the underlying bytes are corrupted/truncated/malformed. If application logic treats "extension present with default value" and "extension corrupted/attacker-tampered" differently (e.g., using presence + non-default fields to gate authorization, feature flags, or policy decisions), an attacker who controls or can influence the serialized bytes of that lazy extension (e.g., through Any payloads, message concatenation/merge from network input, or any path where corrupted bytes reach a lazily-parsed extension) can force the application to silently fall back to default behavior instead of failing the parse — a state-confusion issue structurally identical to "invalid returned as valid" in the oracle case. Because throwing is opt-in and off by default, most consuming applications get the silent-fallback behavior.

### Likelihood Explanation
Reaching this path requires: (1) the schema declares a proto2 extension consumed via `MessageSet` semantics, or a message field marked `lazy=true`; (2) the wire bytes for that lazy region are corrupted/truncated (attacker-controlled or resulting from a legitimate merge of two incompatible partial byte-strings, e.g., via `LazyFieldLite.merge`/`mergeFrom` concatenation logic which itself can produce inconsistent concatenated bytes when extension registries differ); (3) the consuming application does not enable `LAZY_VERIFY_ON_ACCESS`. All three conditions are plausible for public parse APIs (`parseFrom`) operating on attacker-supplied bytes when the target schema uses lazy fields/MessageSet extensions, making this a realistic, bounded-input scenario reachable purely through the standard `parseFrom` / `mergeFrom` public entry points, without any privileged access.

### Recommendation
- Document prominently (and consider changing the default) that lazily-parsed fields/extensions using the default (non-`LAZY_VERIFY_ON_ACCESS`) mode can silently substitute a corrupted payload with the default instance, and that callers must not treat "field reads as default" as proof the field was absent/valid when lazy parsing is in play.
- Expose the corruption bit through a public, documented API (e.g., a `Message`-level `hasCorruptedLazyFields()`/exception-throwing accessor) rather than only via package-private `isCorrupted()`, so calling code can react instead of being unaware, consistent with the comment already present in the source ("Clients will be unaware that this proto was invalid").
- Recommend/encourage `ExtensionRegistryLite.LazyExtensionMode.LAZY_VERIFY_ON_ACCESS` as the default for any registry consuming untrusted input, matching the already-implemented stricter behavior that throws `InvalidProtobufRuntimeException`.

### Proof of Concept
Existing repository tests already demonstrate the exact silent-fallback behavior end-to-end via the public parsing API:

1. `LazilyParsedMessageSetTest.testLoadCorruptedLazyField_getsReplacedWithEmptyMessage` builds a `RawMessageSet` with a corrupted extension payload (`CORRUPTED_MESSAGE_PAYLOAD`), serializes it, and re-parses via the public `TestMessageSet.parseFrom(inputData, extensionRegistry)`. In default lazy mode, `messageSet.getExtension(TestMessageSetExtension1.messageSetExtension)` returns `TestMessageSetExtension1.getDefaultInstance()` — indistinguishable from "extension never set" — with no exception raised to the caller. ` [7](#0-6) `
2. `InternalLazyFieldTest.testInvalidFieldMergeFromBytesKeepsInvalid` shows the same silent behavior for `InternalLazyField.mergeFrom`: merging valid input bytes into an already-corrupted lazy field yields `getValue()` returning `TestAllTypes.getDefaultInstance()` in default mode rather than surfacing the underlying corruption. ` [8](#0-7) `

Both confirm that the *only* way to detect the invalid/corrupted state is to explicitly opt in to `LAZY_VERIFY_ON_ACCESS` mode; under the default mode reachable from ordinary `parseFrom`/`getExtension` calls, invalid lazy-field bytes are returned to the caller as if they were a normal, valid default value — directly analogous to the oracle report's "expired version returned as a normal valid version."

  /** Might lazily parse the bytes that were previously passed in. Is thread-safe. */
  protected void ensureInitialized(MessageLite defaultInstance) {
    if (value != null) {
      return;
    }
    synchronized (this) {
      if (value != null) {
        return;
      }
      try {
        if (delayedBytes != null) {
          // The extensionRegistry shouldn't be null here since we have delayedBytes.
          MessageLite parsedValue =
              defaultInstance.getParserForType().parseFrom(delayedBytes, extensionRegistry);
          this.value = parsedValue;
          this.memoizedBytes = delayedBytes;
        } else {
          this.value = defaultInstance;
          this.memoizedBytes = ByteString.EMPTY;
        }
      } catch (InvalidProtocolBufferException e) {
        // Nothing is logged and no exceptions are thrown. Clients will be unaware that this proto
        // was invalid.
        this.corrupted = true;
        this.value = defaultInstance;
        this.memoizedBytes = ByteString.EMPTY;
      }
    }
  }

  private void ensureInitialized() throws InvalidProtocolBufferException {
    if (value != null) {
      return;
    }

    synchronized (this) {
      if (corrupted) {
        throw new InvalidProtocolBufferException("Repeat access to corrupted lazy field");
      }
      try {
        // `bytes` is guaranteed to be non-null since `value` was null.
        CodedInputStream input = bytes.newCodedInput();
        input.enableAliasing(/* enabled= */ true);
        // When lazyExtensionEnabled() returns true, it means all extensions including MessageSet's
        // will be fully parsed. When it returns false, it basically implies this can only be a
        // MessageSet extension, and we should fall back to the old behavior of silently returning
        // the default instance on corrupted extensions i.e. a full parse.
        value =
            extensionRegistry.lazyExtensionEnabled()
                ? defaultInstance.getParserForType().parsePartialFrom(input, extensionRegistry)
                : defaultInstance.getParserForType().parseFrom(input, extensionRegistry);
        input.checkLastTagWas(0);
      } catch (InvalidProtocolBufferException e) {
        corrupted = true;
        throw e;
      }
    }
  }
