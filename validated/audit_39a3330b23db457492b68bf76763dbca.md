## Title
Unauthenticated bandwidth top-ups let anyone flood-evict a victim's paid `Subscription`, destroying pre-paid bandwidth balance before it drains - (File: `modules/pallets/bandwidth/src/lib.rs`)

### Summary
`pallet-bandwidth` keys its FIFO subscription list purely by `(app_chain, app)` — a payload field the purchaser controls — not by any relationship to the app's owner. `push_subscription` evicts the *oldest* entry once a bucket hits the 1024-entry cap, regardless of how many bytes remain unconsumed on it. Because purchases are permissionlessly "sponsorable" for any `(chain, app)` pair by design, an attacker can cheaply purchase 1024 minimal-tier subscriptions targeting the exact same `(app_chain, app)` bucket a victim just paid a large tier into, forcing the victim's unconsumed, already-paid-for subscription out of storage before the gate ever drains it.

### Finding Description
`Allowance<T>` is a `StorageDoubleMap<StateMachine, AppKey, SubscriptionList>` where `SubscriptionList` is a `BoundedVec<Subscription, 1024>` [1](#0-0) . Every accepted purchase message calls `push_subscription`, which appends unconditionally and, if the list is already full, silently evicts index `0` (the oldest entry, i.e., the FIFO head) via `list.remove(0)`: [2](#0-1) 

Critically, eviction is chosen strictly by insertion order — not by remaining bytes, expiry, or tier value. `on_accept` credits the `(app_chain, app)` pair taken *from the message body*, which is independent of `request.source`, explicitly to support cross-chain sponsorship of "any app deployed across many chains" [3](#0-2) . There is no check binding the sponsor to the app owner, no per-purchaser rate limit, and no minimum-value floor protecting an existing subscription from being pushed out.

This is the same broken invariant as the external report's DLL-head manipulation: an attacker can cheaply insert into a shared ordered structure to force a legitimate, already-committed position out before it can be honored — except here the "position" is prepaid, non-refundable bandwidth (real economic value the victim already transferred to the treasury), and the eviction is unconditional rather than requiring any block-gas race — 1024 low-cost purchase transactions guarantee the outcome deterministically, no mempool timing needed.

### Impact Explanation
`SubscriptionEvicted` explicitly documents that `lost_bytes` "is what the user paid for and won't get to use" [4](#0-3) . An attacker who buys 1024 cheap TierOne subscriptions (documented at $0.0005/byte on the $50 tier) targeting a competitor's or victim's `(app_chain, app)` can deterministically evict any subscription purchased before those 1024 attacker rows landed — including a large, expensive TierFour purchase — permanently destroying paid-for bandwidth that was never consumed. This is a direct loss-of-funds primitive against a legitimate paying party, reachable by any unprivileged caller who can call `purchase()` on any registered `BandwidthManager` for the target `(app_chain, app)` pair, with no admin, relayer, prover, or malicious-peer assumption required.

### Likelihood Explanation
Medium-High. The purchase path is fully permissionless by design (`BandwidthManager.purchase()` is public, and sponsorship of arbitrary `(app_chain, app)` pairs is an intended feature) [5](#0-4) . The attack requires no privileged role, no mempool race, and no cooperation from any other party — only capital to fund 1024 minimum-tier purchases (the cheapest tier is $50/purchase-batch scale, and tiers can likely be bought at `months=1` minimum quantities per call, so the attacker's cost scales with the number of pushes needed, bounded and predictable). Given `1024` is described in the docs as "years of headroom" under honest use, it is not hardened against adversarial flooding at all.

### Recommendation
- Evict by remaining value/least-value-at-risk rather than strict FIFO position, or better, cap subscriptions per `(app_chain, app)` per *purchaser* rather than sharing one global list writable by anyone.
- Require the purchaser (or a signed authorization from the app) to match the app being credited, removing the ability for an unrelated third party to push entries into another app's bucket at all, or gate third-party sponsorship behind an explicit allow-list set by the app owner.
- Alternatively, protect already-active/non-expired high-value subscriptions from eviction (e.g., only evict entries that are expired or below a dust threshold, and fail the purchase — refunding — if no evictable slot exists) rather than always evicting index 0 unconditionally.

### Proof of Concept
1. Victim's app on `EVM-8453` legitimately purchases `TierFour` (1024 rows currently below cap, victim's row lands at some index `k`).
2. Attacker (no relationship to the victim's app) calls `BandwidthManager.purchase(app=<victim_app>, tier=TierOne, months=1, chain="EVM-8453")` 1024 times (or enough times to push the bucket length to `1024` and roll past index `k`), each dispatching a purchase message accepted by `pallet-bandwidth::on_accept` and appended via `push_subscription` [3](#0-2) .
3. Once the bucket for `(EVM-8453, victim_app)` is at the 1024 cap, each further attacker purchase evicts index `0` per `push_subscription`'s `list.remove(0)` [6](#0-5) ; after enough pushes the victim's `TierFour` row (unconsumed, still funded) is evicted and `SubscriptionEvicted { lost_bytes }` is emitted for the victim's paid balance, which is now unrecoverable.
4. The victim's app subsequently fails the bandwidth gate (`GateError::NoAllowance`/`Insufficient`) despite having paid for a large tier that was never drained, confirming the fund loss.

*Note:* I could not verify from the indexed code whether `BandwidthManager.sol`'s `purchase()` enforces any per-call minimum spend or rate limiting that would raise the attacker's cost beyond the raw $50-tier price times number of pushes needed; a Devin session with full repo access would be needed to confirm exact attacker capital requirements and any existing mitigations in the EVM contract not surfaced by the index.

		/// Append a fresh subscription with a fixed expiry. If the list
		/// is already at `MaxSubscriptions`, evict the oldest entry and
		/// emit [`Event::SubscriptionEvicted`] so the lost bytes are
		/// auditable. Returns the new subscription's `expires_at`.
		fn push_subscription(
			app_chain: &StateMachine,
			app: &AppKey,
			tier: TierIndex,
			bytes: BandwidthBytes,
			duration_secs: u64,
		) -> u64 {
			let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();
			let expires_at = now.saturating_add(duration_secs);
			let new_sub =
				Subscription { tier, remaining_bytes: bytes, expires_at, purchased_at: now };

			let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
				let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
					Some(list.remove(0))
				} else {
					None
				};
				// Capacity is now guaranteed; try_push can't fail.
				let _ = list.try_push(new_sub);
				evicted
			});

			if let Some(old) = evicted {
				Self::deposit_event(Event::SubscriptionEvicted {
					app_chain: *app_chain,
					app: app.clone(),
					tier: old.tier,
					lost_bytes: old.remaining_bytes,
				});
			}

			expires_at
		}

	impl<T: Config> IsmpModule for Pallet<T> {
		fn on_accept(&self, request: PostRequest) -> Result<Weight, anyhow::Error> {
			let manager = BandwidthManager::<T>::get(&request.source).ok_or_else(|| {
				anyhow::anyhow!(format!("no bandwidth manager registered for {:?}", request.source))
			})?;

			if request.from != manager.0.to_vec() {
				return Err(anyhow::anyhow!(format!(
					"purchase from unauthorised sender on {:?}: expected {:x?}, got {:x?}",
					request.source, manager.0, request.from
				)));
			}

			let msg = PurchaseMessage::try_from(request.body.as_slice())?;
			let tier = TierIndex::try_from(msg.tier)
				.map_err(|_| anyhow::anyhow!(format!("unknown tier discriminant {}", msg.tier)))?;
			let cfg = Tiers::<T>::get(tier)
				.ok_or_else(|| anyhow::anyhow!(format!("tier {:?} is not configured", tier)))?;

			let bytes = cfg.bytes.saturating_mul(msg.months as u128);
			let duration = cfg.duration_secs.saturating_mul(msg.months as u64);

			let key = AppKey::truncate_from(msg.app);
			let expires_at = Self::push_subscription(&msg.chain, &key, tier, bytes, duration);

			Self::deposit_event(Event::BandwidthCredited {
				app_chain: msg.chain,
				app: key,
				paid_from: request.source,
				tier,
				bytes,
				expires_at,
			});

			Ok(Weight::zero())
		}
