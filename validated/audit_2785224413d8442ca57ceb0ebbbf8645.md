### Title
SignableTransaction does not validate consistency between a ReceivedOutput's `outpoint` and its claimed `output`, causing signers to sign sighashes for unspendable/mismatched transactions - (networks/bitcoin/src/wallet/send.rs)

### Summary
The report's bug class — two payloads where an outer field is validated while a different, inner field is what actually gets consumed — maps directly onto `ReceivedOutput` as consumed by `SignableTransaction` in `networks/bitcoin/src/wallet/send.rs`. A `ReceivedOutput` carries two independent claims: `outpoint` (the UTXO actually referenced by the produced `TxIn`) and `output` (the `TxOut` whose `script_pubkey` is validated against the signing key and whose `value` drives all accounting and the sighash's `Prevouts::All` commitment). Nothing ever checks that the claimed `output` is the output the `outpoint` actually points to.

### Finding Description
`ReceivedOutput` is a plain container of `offset`, `output`, and `outpoint`, and its `read` deserializer accepts all three fields verbatim from untrusted bytes with no cross-validation (`ReceivedOutput::read`, mod.rs:122-134).

`SignableTransaction::new` then uses the two fields independently:
- `input.outpoint` is placed into `TxIn::previous_output` (send.rs:177-185) — this is what the transaction actually spends.
- `input.output` is summed into `input_sat` for the funds check (send.rs:175), stored into `self.prevouts` (send.rs:253), and later committed in the sighash via `Prevouts::All(&self.tx.prevouts)` (send.rs:375).

The only consistency check that exists is in `multisig`, which verifies `p2tr_script_buf(offset.group_key()) == self.prevouts[i].script_pubkey` (send.rs:277) — i.e., it validates the *claimed* `output.script_pubkey` against the signing key, exactly analogous to the adapter validating `apiData.tokenFrom`. The `outpoint` — the analog of `swapData`'s actual token — is never checked against it.

An untrusted party (e.g., whoever supplies serialized `ReceivedOutput`s to a signing participant) can therefore craft `{ outpoint: <arbitrary UTXO>, output: TxOut { script_pubkey: <any registered offset key>, value: <arbitrary> } }`. `multisig()` succeeds because the claimed script matches an offset key, and every signer produces a valid FROST signature share over `taproot_key_spend_signature_hash(i, Prevouts::All(claimed_prevouts), Default)` (send.rs:383-390). The shares aggregate into a witness signature (send.rs:417-425) for a transaction whose `TxIn`s reference outpoints whose real on-chain scriptPubKeys/values do not match what was signed.

### Impact Explanation
Every honest participant that runs `sign` emits a signature share committing their FROST nonce and secret share to a sighash describing inputs that do not exist as declared — a concrete case of signing an unintended message. Because BIP-341 key-path signatures commit to the prevout amounts and the input's own scriptPubKey key must match the actual spent UTXO, any divergence between the claimed `output` and the real UTXO at `outpoint` makes the produced transaction permanently unbroadcastable: the witness signature will fail script verification on chain. The signing session's preprocesses are consumed on a doomed transaction, and outputs the signers believed they were spending (including attacker-influenced `payments`/`change` sized off the fabricated `input_sat` at send.rs:215-235) can never settle.

### Likelihood Explanation
Reachable by any party able to supply `ReceivedOutput` bytes to a signer (the `read` API is an explicitly in-scope untrusted-bytes sink). It requires no key material, no collusion, and no control over other participants — just control of the input list fed to `SignableTransaction::new`. However, the consequence is bounded: mismatched fields always yield an invalid-on-chain transaction rather than a stealthy theft, so the practical effect is a wasted/coerced signing session and denial of the spend, keeping this at Medium.

### Recommendation
In `SignableTransaction::new` (or a `ReceivedOutput` constructor enforcing the invariant), require the caller to prove consistency between `outpoint` and `output` — e.g., fetch/verify the actual `TxOut` at each `outpoint` before use, or have `Scanner::scan_transaction` be the sole producer of `ReceivedOutput` and reject deserialized instances that were not produced by scanning a confirmed transaction. At minimum, document that `ReceivedOutput::read` output must be re-validated against chain state before being fed to `SignableTransaction::new`/`multisig`.

### Proof of Concept
```rust
// Setup: scanner-derived honest output for reference
let honest = scanner.scan_transaction(&funding_tx).pop().unwrap();

// Attacker crafts an inconsistent ReceivedOutput (or serializes it for a signer
// to feed through ReceivedOutput::read)
let forged = ReceivedOutput::read(&mut {
    let mut buf = vec![];
    // offset: ZERO so claimed script must equal the base key's p2tr script
    Scalar::ZERO.write(&mut buf).unwrap();
    // claimed output: our script_pubkey, fabricated value
    serialize(&TxOut {
        value: Amount::from_sat(1_000_000),          // claims 1M sats
        script_pubkey: p2tr_script_buf(group_key).unwrap(),
    }).iter().for_each(|b| buf.push(*b));
    // outpoint: points to a DIFFERENT real UTXO (e.g., a 1-sat output we own,
    // an already-spent outpoint, or anyone's outpoint)
    serialize(&OutPoint::new(victim_txid, 0)).iter().for_each(|b| buf.push(*b));
    buf.as_slice()
}).unwrap();

// Funds check passes using the fabricated 1M-sat value
let tx = SignableTransaction::new(vec![forged], &payments, Some(change), None, fee).unwrap();

// multisig() succeeds: it only checks the *claimed* script_pubkey matches the offset key
let machine = tx.clone().multisig(&keys[&Participant::new(1).unwrap()]).unwrap();

// All honest signers emit shares over a sighash committing to the fabricated prevout
let signed = sign(&keys, &tx);

// The signed transaction references victim_txid:0 but its witness signature was
// produced by the offset-ZERO key over claimed prevouts — it is permanently
// invalid on-chain unless the real UTXO at that outpoint coincidentally matches,
// which the attacker controls precisely to ensure it does not.
assert!(rpc.send_raw_transaction(&signed).await.is_err()); // rejected by mempool/consensus
```
