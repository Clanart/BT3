### Title
OP_RETURN data output is omitted from the fee/weight estimation, so `SignableTransaction` systematically underpays its target fee rate - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
`SignableTransaction::new` appends the user-supplied `OP_RETURN` output to `tx_outs` before estimating transaction weight, yet calls `calculate_weight_vbytes` with only `payments` — the data output is excluded from `vbytes`. The resulting `needed_fee` and the `TooLowFee` relay-fee check are computed against an under-estimated size, so a signed transaction commits (via `Prevouts::All` key-spend sighash) to a fee lower than the requested `fee_per_vbyte` and possibly below the network's minimum relay fee.

### Finding Description
In `SignableTransaction::new`, the OP_RETURN output is pushed onto `tx_outs` first:

```rust
// networks/bitcoin/src/wallet/send.rs:194-202
if let Some(data) = data {
  tx_outs.push(TxOut { value: Amount::ZERO, script_pubkey: ScriptBuf::new_op_return(...) })
}
```

but the weight/vbyte estimation on line 204 passes `payments`, which does not contain the OP_RETURN output:

```rust
// networks/bitcoin/src/wallet/send.rs:204
let (mut weight, vbytes) = Self::calculate_weight_vbytes(tx_ins.len(), payments, None);
```

`calculate_weight_vbytes` builds the dummy transaction's output list solely from the `payments` slice (`send.rs:85-93`), so the extra ~9–90 byte OP_RETURN output is never counted in `vbytes`. The same omission applies to the change branch, which passes `payments` again (`send.rs:225-226`).

Consequences:
- `needed_fee = fee_per_vbyte * vbytes` (`send.rs:206`, `send.rs:227`) is systematically low whenever `data` is attached, so the actual paid fee is less than `fee_per_vbyte * actual_vsize`.
- The `TooLowFee` guard (`send.rs:211`) compares against the under-estimated `vbytes`; a transaction that is genuinely below `DEFAULT_MIN_RELAY_TX_FEE` for its real size can pass the check.
- The final `MAX_STANDARD_TX_WEIGHT` check (`send.rs:241`) uses `weight`, which also excludes the data output, so an oversized transaction can be admitted.

Because `TransactionSignMachine::sign` signs `taproot_key_spend_signature_hash` over `Prevouts::All` and the already-fixed `tx.output` (`send.rs:373-397`), all signers irrevocably commit to this under-funded, possibly non-relayable transaction; fee bumping requires producing a different transaction, which the threshold group must re-sign.

### Impact Explanation
An unprivileged party that can influence the `data` attached to a spend (e.g., a deposit/withdrawal metadata field) causes the multisig to produce a transaction whose real fee rate is lower than requested and potentially below the mempool's minimum relay rate. The transaction is validly signed but may never propagate or confirm, freezing the spent `ReceivedOutput`s as inputs to a stuck transaction — effectively unspendable funds until the group coordinates a re-sign with new inputs. This is a concrete incorrect-value/incorrect-commitment defect in fee math, within the documented "fee/change/dust math" bug class.

### Likelihood Explanation
Triggering requires only that `data` be supplied to `SignableTransaction::new` — a normal, supported code path (`TooMuchData` only bounds it at 80 bytes, `send.rs:171-173`). Every transaction constructed with `Some(data)` under-estimates its size by the full OP_RETURN output length (~13–95 vbytes), deterministically reducing the effective fee rate. No cryptographic break or collusion is needed.

### Recommendation
Include the OP_RETURN output in the weight/vbyte estimation. Either build `calculate_weight_vbytes` over the finalized `tx_outs` (payments + OP_RETURN + optional change), or pass a `payments` list extended with the zero-value OP_RETURN output so both the `needed_fee` and the `TooLowFee`/`MAX_STANDARD_TX_WEIGHT` checks reflect the transaction that will actually be signed. Recompute `weight` consistently when the change output is appended.

### Proof of Concept
```rust
// Conceptual: construct a SignableTransaction with an OP_RETURN payload
let data = vec![0u8; 80];
let tx = SignableTransaction::new(inputs, &payments, None, Some(data), fee_per_vbyte).unwrap();

// tx.needed_fee() == fee_per_vbyte * vbytes(without the OP_RETURN output)
// tx.transaction().weight() includes the OP_RETURN output (~95 extra bytes),
// so tx.fee() / actual_vsize < fee_per_vbyte, and if
// vbytes(without data) * fee_per_vbyte >= DEFAULT_MIN_RELAY_TX_FEE * vbytes / 1000
// while the true rate is below the relay minimum, the signed TX will be
// rejected by peers despite passing TooLowFee.
```
