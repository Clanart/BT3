## Title
Tron IntentGateway's `instance()` defaults unregistered source chains to `address(this)`, letting an attacker forge `RedeemEscrow`/`RefundEscrow` messages and drain escrowed funds — ([File: evm/tron/contracts/apps/IntentGatewayV2.sol])

### Summary
The core broken invariant in the seed report is: a function that should only ever be reachable by a trusted party (team/relayer) is instead open to anyone because the code path used the wrong default/authorization check. The Hyperbridge analog is in the Tron `IntentGatewayV2` contract's peer-authentication helper `instance()`, which silently trusts `address(this)` as the expected sender for any state machine that has never been explicitly registered as a peer, instead of rejecting it. Since `IntentGatewayV2` instances are deployed at deterministic (CREATE2) addresses across chains, this default effectively authenticates a forged cross-chain settlement message as if it came from the legitimate gateway peer, allowing an attacker to redeem or refund any live order's escrow to an address they control.

### Finding Description
`onAccept()` in the Tron `IntentGatewayV2` routes `RedeemEscrow`/`RefundEscrow` requests through `authenticate()` before calling `withdraw()`, which pays out escrowed input tokens and transaction fees: [1](#0-0) 

`authenticate()` validates the sender by comparing `request.from` (the address that dispatched the message on the *source* chain) against `instance(request.source)`: [2](#0-1) 

Crucially, `instance()` does not revert when the source chain has never been registered as a peer — it falls back to `address(this)`: [3](#0-2) 

`withdraw()` then transfers all escrowed tokens (and any transaction fees) for the given `commitment` to whatever `beneficiary` is embedded in the attacker-controlled request body: [4](#0-3) 

Because the gateway is deployed at an identical, deterministic CREATE2 address across chains (as documented for the sibling EVM contract, whose peers are "identical across chains under deterministic CREATE2, so no peer address is carried in the proxy's init data"): [5](#0-4) 

any chain for which this Tron gateway has *not* explicitly registered a peer (`_instances[keccak256(stateMachineId)]` still zero) resolves `instance(source)` to `address(this)` — i.e., the gateway's own deterministic CREATE2 address. An attacker only needs to redeploy the same bytecode with the same factory/salt at that exact address on any state machine that Hyperbridge can route ISMP messages from and that this Tron instance has not registered, then dispatch a forged `RedeemEscrow`/`RefundEscrow` PostRequest naming a real, currently-escrowed `commitment` with `beneficiary` set to themselves. `authenticate()` passes because `request.from == address(this) == instance(source)`, and `withdraw()` unconditionally pays out the escrow.

This contrasts with the primary (non-Tron) `IntentGatewayV2`/`IntentsBase`, whose analogous lookup is documented to revert with `UnknownInstance` for any unregistered chain rather than defaulting to self-trust — confirming the Tron variant's default-to-self behavior is a deviation, not an intentional design choice: [6](#0-5) 

### Impact Explanation
This is a direct fund-theft primitive matching the bounty's "stealing or loss of funds" and "false proof/state acceptance / unauthorized execution" categories: an unprivileged attacker can drain escrowed order inputs and transaction fees for any live cross-chain order on the Tron gateway by forging a settlement message from an unregistered source chain, without needing a malicious relayer, prover, or admin — only the ability to deploy a contract with a specific address on a state machine that Hyperbridge can carry messages from.

### Likelihood Explanation
The likelihood depends on whether an attacker can actually get an ISMP message with `request.from == address(this)` and `request.source` = an unregistered state machine delivered and accepted by the Tron host's `onAccept`. This requires (a) a state machine not yet registered via `NewDeployment` in `_instances`, and (b) the ability to deploy identical bytecode at the same CREATE2 address on that chain (or otherwise control an address matching the gateway's deterministic address) and dispatch a message through Hyperbridge's normal (permissionless) request-relay path. Given Hyperbridge is designed to onboard new EVM-compatible chains over time, and CREATE2 deployment addresses are public/reproducible by design, this is a realistic and not merely theoretical path once any chain exists that Hyperbridge can route from but that has not yet had `NewDeployment` called for this specific gateway.

### Recommendation
Change `instance()` to revert (e.g. `UnknownInstance`) when `_instances[keccak256(stateMachineId)] == address(0)` instead of defaulting to `address(this)`, matching the behavior of the primary `IntentGatewayV2`/`IntentsBase._instance()`. Peer authentication must be based on an explicit allow-list, never an implicit "trust self" fallback.

### Proof of Concept
1. Identify a state machine ID `X` that Hyperbridge can relay ISMP messages from but for which the Tron `IntentGatewayV2` has never received a `NewDeployment` message (so `_instances[keccak256(X)] == address(0)`).
2. Deploy a contract at the same address as the Tron gateway (`address(this)`) on state machine `X`, using the same CREATE2 factory and salt used for the legitimate deployment (documented as deterministic/identical across chains).
3. From that contract, dispatch a `PostRequest` to the Tron gateway with `source = X`, `from = <20-byte address(this)>`, `body = [RequestKind.RedeemEscrow] + abi.encode(WithdrawalRequest({commitment: <victim's real order commitment>, tokens: <victim's escrowed tokens>, beneficiary: <attacker address>}))`.
4. Once delivered through the ISMP handler and passed to `onAccept()` (`evm/tron/contracts/apps/IntentGatewayV2.sol:620`), `authenticate()` computes `instance(X)` → `address(this)` (line 281-284) which equals `request.from`, passing the check at line 293.
5. `withdraw()` (line 682) transfers the victim's escrowed input tokens/fees to the attacker's `beneficiary`, completing the theft.

Note: I was unable to directly view `IntentsBase.sol`'s `_instance()` implementation in this pass (only confirmed its existence and the `UnknownInstance` error via grep and the doc comment on the sibling contract), so the exact revert condition on the primary EVM contract is inferred from that comment rather than a direct code read. Recommend a Devin session with full file access to confirm this and to view the complete `IntentGatewayV2.sol` (Tron) `_instances`/`_addDeployment` logic before implementing the fix.

    function authenticate(PostRequest calldata request) internal view {
        if (request.from.length != 20) revert InvalidInput();
        address module = address(bytes20(request.from));
        // IntentGateway only accepts incoming assets from itself or known instances
        if (instance(request.source) != module) revert Unauthorized();

        _filled[body.commitment] = beneficiary;

        // redeem escrowed tokens
        uint256 len = body.tokens.length;
        for (uint256 i; i < len;) {
            address token = address(uint160(uint256(body.tokens[i].token)));
            uint256 amount = body.tokens[i].amount;
            if (_orders[body.commitment][token] == 0) revert UnknownOrder();

            if (token == address(0)) {
                (bool sent,) = beneficiary.call{value: amount}("");
                if (!sent) revert InsufficientNativeToken();
            } else {
                (bool success,) = token.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, amount));
                if (!success) revert TransferFailed();
            }

            _orders[body.commitment][token] -= amount;
            unchecked {
                ++i;
            }
        }

        // redeem tx fees
        uint256 fees = _orders[body.commitment][TRANSACTION_FEES];

            (bool success,) = feeToken.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, fees));
            if (!success) revert TransferFailed();
            delete _orders[body.commitment][TRANSACTION_FEES];
        }

        if (isRefund) {
            emit EscrowRefunded({commitment: body.commitment});
        } else {
            emit EscrowReleased({commitment: body.commitment});
