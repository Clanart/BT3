### Title
Cached FROST preprocess (nonce) is reused for every later signing attempt under the same context, enabling private key share recovery - (coordinator/src/tributary/signing_protocol.rs)

### Summary
Analogous to the Sablier bug — where a parameter fixed only at withdrawal time is applied retroactively to debt accrued earlier — `SigningProtocol::preprocess_internal` fixes a FROST nonce preprocess at cache time and then applies it to whatever preprocess set and message are supplied later. The cached seed deterministically regenerates identical nonces on every call, so each `share`/`complete` invocation signs with the same nonce regardless of which peers' preprocesses or `key_pair` arrive afterward. Two differing signing sessions under the same `context` yield two signature shares with a reused nonce, which is exactly the condition FROST's own documentation states "would enable a third-party to recover your private key share."

### Finding Description
In `coordinator/src/tributary/signing_protocol.rs`, `preprocess_internal` stores a preprocess in `CachedPreprocesses` keyed only by `context` (e.g., `(b"DkgConfirmer", attempt)`), and is never deleted after use (lines 123–145). On each call it XOR-decrypts the cached seed and rebuilds the machine via `AlgorithmSignMachine::from_cache` → `AlgorithmMachine::seeded_preprocess`. In `crypto/frost/src/sign.rs`, `seeded_preprocess` derives nonces purely as `ChaCha20Rng::from_seed(seed)` combined with `keys.original_secret_share()` and `algorithm.nonces()` — completely independent of the message and of which preprocesses later arrive. `DkgConfirmer::share` and `DkgConfirmer::complete` both call `share_internal` (lines 288–327) with attacker-supplied `preprocesses` and `key_pair` (the message is `set_keys_message(...)` built from the supplied `key_pair`). Because the cache persists, a validator that signs once and is later asked to sign again under the same context — with a different `key_pair`, a different preprocess set (different binding factors ρ), or during `complete` after an earlier `share` — emits a second share `s = d + e·ρ + λ·x·c` with identical `d`, `e` but different `ρ`/`c`. Two such shares form two linear equations in the secret share `x`, recovering it. This mirrors the Sablier shape exactly: an attacker-controlled later input (the peers' preprocesses / key_pair) is evaluated against state committed earlier (the cached nonce), rather than the nonce being bound to the session parameters when generated.

### Impact Explanation
Any peer able to trigger a second `share`/`complete` under the same `(context)` — different `key_pair`, different participant set, or a retry — obtains two FROST signature shares sharing one nonce. Recovering the validator's MuSig/FROST secret share compromises the tributary signing key, enabling forgery of subsequent validator-set signatures. This is key share recovery, a qualifying impact.

### Likelihood Explanation
Reachable by unprivileged protocol peers: `preprocesses` and `key_pair` are untrusted inputs fed to `read_preprocess`/`sign`. The seed cache is never consumed or rotated between `share` and `complete`, and `share` returns a share while `complete` internally signs again — so even normal protocol flow plus one republished/conflicting preprocess set produces reuse. Exploitation requires the same context to sign twice with differing inputs, which a peer can induce by sending different preprocess maps across rounds of the same attempt.

### Recommendation
Bind the preprocess to its session at generation time: include the intended message (or its hash) and the participant set in the `context` used for `CachedPreprocesses`, and delete/mark the cached seed consumed once a share has been emitted, refusing to re-derive nonces for a second `share`/`complete`. Alternatively, derive the nonce from `seed || msg || sorted-participants` so differing sessions cannot reuse it.

### Proof of Concept
```rust
// Same context => same CachedPreprocesses entry => identical nonces
let mut confirmer = DkgConfirmer::new(&key, &spec, &mut txn, attempt).unwrap();

// First signing attempt
let share1 = confirmer.share(preprocesses_a.clone(), &key_pair_a).unwrap();

// Attacker submits a different preprocess set / key_pair under the same attempt,
// or complete() is invoked with different preprocesses than share() used
let share2 = confirmer.share(preprocesses_b.clone(), &key_pair_b).unwrap();

// share1 = d + e*rho1 + lambda*x*c1 ; share2 = d + e*rho2 + lambda*x*c2
// => two equations in d, e, x -> recover secret share x
```
Root cause: `coordinator/src/tributary/signing_protocol.rs` lines 123–148 (seed cached once, reused forever) combined with `crypto/frost/src/sign.rs` lines 121–144 (`seeded_preprocess` derives nonces from the seed alone, independent of `msg`/`preprocesses`), reachable via `share`/`complete` at lines 288–327.
