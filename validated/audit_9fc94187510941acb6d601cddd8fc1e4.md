### Title
Unbounded recursive parsing of VC proof programs causes Python stack exhaustion - (File: `chia/wallet/vc_wallet/vc_store.py`)

### Summary
`VCProofs.from_program()` and `VCProofs.prove_keys()` in `chia/wallet/vc_wallet/vc_store.py` recursively walk an attacker-influenced CLVM `Program` tree (the Verified Credential "proofs" structure) with no depth bound, mirroring the CVE-2018-18484 bug class of unbounded recursive-descent parsing (`cplus_demangle_type`/`d_bare_function_type`/`d_function_type` in libiberty) that leads to stack exhaustion.

### Finding Description
`VCProofs.from_program()` parses a binary CLVM tree representing VC proof key/value pairs: [1](#0-0) 

For every internal node (both `first` and `rest` non-atoms) it recurses on both children with `VCProofs.from_program(first)` / `VCProofs.from_program(rest)`, and there is no maximum-depth check before recursing. `prove_keys()` has the same unbounded recursive structure on the same tree shape: [2](#0-1) 

Both functions are pure Python recursion (not the deliberately-iterative `sha256_treehash` pattern used elsewhere in the codebase for exactly this reason): [3](#0-2) 

The proofs `Program` these functions operate on is built from a VC coin's on-chain metadata (a CLVM cons-tree of key/value strings) that is reconstructed while syncing/interpreting a `VerifiedCredential` coin spend — i.e., data whose shape is controlled by whoever created or last spent that VC coin, not by the local wallet. A VC can be received by a wallet as part of a CR-CAT/VC transaction or offer counterparty flow (explicitly in the in-scope "CAT/CR-CAT/VC flow" surface), so a maliciously deep, unbalanced proofs tree can be crafted by any counterparty issuing/transferring a VC to the victim wallet.

### Impact Explanation
A crafted VC proofs program with a sufficiently deep, degenerate (skewed) binary tree drives `VCProofs.from_program()`/`prove_keys()` into deep Python recursion. Because each recursive call consumes a Python (and underlying C) stack frame with no bound related to CLVM cost accounting, an attacker can force either a `RecursionError` (denial of service for the wallet processing that VC) or, in more constrained embedded/stack-limited contexts, a native stack overflow crash. This halts VC-related transaction/spend processing for the affected wallet, matching the "spend-triggered transaction-processing halt" acceptance criterion in scope.

### Likelihood Explanation
Likelihood is limited by the fact that the trigger requires the victim wallet to receive/process a VC coin (e.g., via an accepted offer or CR-CAT/VC transfer) that contains an attacker-crafted, deeply nested proofs program — this is plausible for any wallet that interacts with untrusted VC issuers/counterparties, but it is not reachable from an arbitrary unauthenticated spend bundle against a full node; it requires the local wallet to actually parse a specific VC's proof data.

### Recommendation
Rewrite `VCProofs.from_program()` and `VCProofs.prove_keys()` to use an iterative, explicit-stack traversal (as already done in `sha256_treehash()`), and/or enforce a maximum tree depth before recursing, rejecting VC proof programs that exceed a sane depth/size bound.

### Proof of Concept
Construct a `Program` representing a heavily right- or left-skewed cons tree of depth N (e.g., `(("k1" . "v1") . (("k2" . "v2") . (... N levels ...)))`) and pass it to `VCProofs.from_program(prog)` (or call `VCProofs(...).prove_keys([...], tree=prog)`); for sufficiently large N (well within CLVM program size limits, e.g. tens of thousands of nested pairs), the call raises `RecursionError` or crashes the Python interpreter due to stack exhaustion, exactly analogous to the reported libiberty stack-consumption issue.

    def prove_keys(self, keys: list[str], tree: Program | None = None) -> Program:
        if tree is None:
            tree = self.as_program()

        first = tree.first()
        if first.atom is not None:
            if first.atom.decode("utf8") in keys:
                return tree
            else:
                tree_hash_as_atom: Program = Program.to(tree.get_tree_hash())
                return tree_hash_as_atom
        else:
            rest = tree.rest()
            first_tree = self.prove_keys(keys, first)
            rest_tree = self.prove_keys(keys, rest)
            if first_tree.atom is not None and rest_tree.atom is not None:
                tree_hash_as_atom = Program.to(
                    Program.to((first_tree, rest_tree)).get_tree_hash_precalc(
                        bytes32(first_tree.atom), bytes32(rest_tree.atom)
                    )
                )
                return tree_hash_as_atom
