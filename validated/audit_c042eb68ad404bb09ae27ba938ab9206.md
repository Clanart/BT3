### Title
Instant reward sniping of forfeited MGP via zero-cost lock() right before a victim's expiry forfeit is queued - (File: rewards/vlMGPBaseRewarder.sol)

### Summary
`vlMGPBaseRewarder` distributes any user's forfeited MGP pro-rata to whoever is currently staked, using an instantaneous balance snapshot with no minimum holding period or entry cost. An attacker can call `vlMGP.lock(largeAmount)` in the same block just before a victim's expired cooldown forfeit is queued, then immediately call `getReward`/`getRewards` to claim a disproportionate share of the forfeited MGP with zero elapsed time.

### Finding Description
`_calExpireForfeit` computes the forfeit strictly from the victim's own `vlMGP.getRewardablePercentWAD(_account)`, independent of any other actor [1](#0-0) . When a forfeit occurs — either via `queueMGP` (called by an authorized manager during `harvestMGP`/claim flows) or via `_sendReward` — the forfeited amount is pushed into the pool through `_queueNewRewardsWithoutTransfer`, which increases `rewardPerTokenStored` by `forfeitAmount * 1e18 / totalStaked()` [2](#0-1) [3](#0-2) .

Reward accrual for any account is `earned = balanceOf(account) * (rewardPerTokenStored - userRewardPerTokenPaid[account]) / 1e18 + userRewards[account]` [4](#0-3) . `balanceOf(account)` is the *live* stake amount registered in `MasterMagpie.stakingInfo(stakingToken, account)` [5](#0-4) , not a time-weighted or vested figure. There is no minimum-lock-duration gate on the *earning* side of the reward pool — the only vesting/forfeit logic (`getRewardablePercentWAD`) applies exclusively to the account whose reward is being paid out, not to how newly staked balance is treated when receiving redistributed forfeits.

Because `userRewardPerTokenPaid` for a brand-new or previously-caught-up account equals the `rewardPerTokenStored` value at the moment of the attacker's last interaction (i.e., right before locking, still pre-forfeit), and `lock()` increases `balanceOf` for the account without any cooldown, an attacker who locks a large amount of MGP in the block immediately preceding a victim's expiry-triggered forfeit will have their full new balance multiplied against the entire post-forfeit `rewardPerTokenStored` delta once they call `getReward`. This lets them capture a proportional share of yield they did not accrue over time.

Existing protections do not stop this: `nonReentrant` and `onlyManager`/`onlyMasterMagpie` guard against reentrancy and unauthorized callers but not against legitimate, permissionless `lock()` calls timed adversarially; `updateReward`/`updateRewards` modifiers only snapshot `userRewardPerTokenPaid` at each interaction — they do not check how long the current balance has been held before applying the new rate delta.

### Impact Explanation
This is a theft of unclaimed/forfeited yield: MGP that should be redistributed to long-term, genuinely time-weighted stakers is siphoned off by an opportunistic just-in-time locker with no holding-period cost, diluting the effective yield to honest long-term lockers. This matches the "theft of unclaimed yield" impact class. Note the attacker does not even need to unwind their lock to realize profit — `getReward` pays out the reward token (MGP) directly and immediately, independent of the locked principal's cooldown/unlock mechanics, so the stolen yield is realized instantly.

### Likelihood Explanation
Preconditions: attacker needs capital (MGP tokens) sized relative to the total staked supply to claim a meaningful share, and needs a forfeit event to occur (which is not attacker-controlled but is publicly observable, since it is triggered whenever a bot/victim calls `harvestMGP`/`multiclaimFor` for any account with an expired, unclaimed cooldown slot). This is fully repeatable and requires no special privileges — only calling public `lock()` and `getReward`/`getRewards`, both open to any MGP holder. The main constraint is capital size (needs to represent a meaningful fraction of `totalStaked()` to be worth the gas/opportunity cost of locking MGP that then sits in cooldown-eligible lock), which is a feasibility/economics factor rather than a technical barrier.

### Recommendation
Introduce a minimum eligibility delay before newly staked/locked balance can participate in forfeit redistribution — e.g., checkpoint each account's `balanceOf` contribution to `rewardPerTokenStored` accrual only from the time it was staked (time-weighted average balance), or require a minimum lock duration before a `lock()` increases the reward-eligible balance. Alternatively, redistribute forfeited amounts pro-rata only to balances that existed prior to the block in which the forfeit was queued (e.g., via a snapshot/checkpoint mechanism), rather than to the live `totalStaked()`/`balanceOf()` at claim time.

### Proof of Concept
Foundry test plan:
1. Deploy `VLMGP`, `MasterMagpie`, and `vlMGPBaseRewarder`; fund several "honest" long-term stakers who lock MGP and let cooldown slots expire without claiming for a long time.
2. Have a victim with an expired, unclaimed cooldown slot; trigger `MasterMagpie.multiclaimFor`/`harvestMGP` in a way that will call `vlMGPBaseRewarder.queueMGP` or `_sendReward`, producing a large `forfeitAmount` per `_calExpireForfeit`.
3. In the same block, before the forfeit-triggering call, have `attacker.lock(largeAmount)` via `vlMGP.lock`.
4. Execute the forfeit-triggering transaction.
5. Immediately call `getReward(attacker, attacker)` and assert the MGP reward received by the attacker is disproportionately large relative to zero holding time, e.g., compare `attackerReward / attackerBalance` accrual rate versus `honestStaker.earned(...)` accrued over their full staking duration, showing the attacker captures reward-per-token equal to long-term stakers despite 0 seconds of staking.

```text
    function queueMGP(uint256 _amount, address _account, address _receiver) override external onlyManager nonReentrant returns (bool) {
        IERC20(vlMGP.MGP()).safeTransferFrom(msg.sender, address(this), _amount);
        
        uint256 forfeitAmount = _calExpireForfeit(_account, _amount);
        uint256 rewardableAmount = _amount - forfeitAmount;
        
        if (forfeitAmount > 0)
            _queueNewRewardsWithoutTransfer(forfeitAmount, address(vlMGP.MGP()));

        if (rewardableAmount > 0) {
            IERC20(vlMGP.MGP()).safeTransfer(_receiver, rewardableAmount);
            emit MGPHarvested(_account, rewardableAmount, forfeitAmount);
        }

        return true;
    }
```

```text
    function _queueNewRewardsWithoutTransfer(uint256 _amountReward, address _rewardToken) internal
    {
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards = rewardInfo.historicalRewards + _amountReward;
        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**vlMGPDecimal) / totalStaked();
        }
        emit ForfeitRewardAdded(_amountReward, _rewardToken);
```

```text
    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }
```
