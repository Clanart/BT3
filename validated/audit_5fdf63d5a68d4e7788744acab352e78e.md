### Title
Encrypted DKG share messages are not bound to their recipient, letting any participant weaponize the blame protocol to frame an honest sender - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
Analogous to the Silverpeas IDOR (missing access control on a message ID parameter), PedPoP's `EncryptedMessage` authenticates the `sender` in its Schnorr proof-of-possession but never binds the intended `recipient`. The blame path (`Decryption::decrypt_with_proof` / `BlameMachine::blame_internal`) takes `recipient` as a caller-controlled parameter and decrypts under `enc_keys[recipient]`. Since all `DkgShares` are published on the tributary ledger, any DKG participant can take a share Alice honestly encrypted to Bob, accuse Alice under their own participant index, supply a valid self-made `EncryptionKeyProof`, and cause Alice — not themselves — to be identified as faulty.

### Finding Description
In `crypto/dkg/pedpop/src/encryption.rs`, `pop_challenge` (lines 302-324) binds `context`, `nonce`, `key`, `sender`, and `msg` into the PoP challenge — but not the recipient's identity or encryption key. `encrypt` (line 135) likewise only records `from`. In `decrypt_with_proof` (lines 366-397), the `decryptor: Participant` argument selects `self.enc_keys[&decryptor]` as the DLEq base point; nothing verifies that `msg` was actually encrypted to that participant. `blame_internal` in `crypto/dkg/pedpop/src/lib.rs` (lines 575-609) treats a non-canonical or invalid decrypted share as proof the *sender* is faulty.

An attacker Eve (a DKG participant) reads the publicly-broadcast `DkgShares` transaction containing `EncryptedMessage`s from Alice to all recipients. Eve submits a blame accusation `(sender=Alice, recipient=Eve, msg=share_for_Bob)` along with a `key = enc_priv_Eve * msg.key` and a valid DLEq over `(G, msg.key) → (enc_key_Eve, key)`, which Eve can produce knowing only her own private encryption key. The proof verifies, decryption yields garbage bytes, `C::F::from_repr` fails or share verification fails, and `blame_internal` returns `sender` — Alice is blamed. In `AdditionalBlameMachine` (usable by anyone, per its docs), the same trick works without Eve even participating in that DKG round's share receipt.

### Impact Explanation
An honest participant is cryptographically "proven" faulty via a blame statement that all other validators and `AdditionalBlameMachine::blame` callers will accept, triggering a fatal slash of Alice (per coordinator `handle.rs` `Transaction::InvalidDkgShare` handling) and aborting the DKG. Repeatable per attempt: an attacker can permanently grief every honest participant in rotation with only public on-chain data and their own encryption key. This converts a denial-of-availability primitive into an attacker-controlled slashing primitive — misattributed blame defeats the entire accountability property the blame protocol exists to provide.

### Likelihood Explanation
Requires only: (a) reading published `DkgShares` (public), (b) being a registered participant with an encryption key (to produce the DLEq). No collusion, no key compromise, no timing window. Every honest sender is exposed every DKG round.

### Recommendation
Bind the recipient into `pop_challenge` (e.g., append `recipient` Participant bytes or the recipient's `enc_key` to the transcript in `encrypt`/`decrypt`/`decrypt_with_proof`), so an `EncryptedMessage` cannot be replayed under a different `recipient` parameter. Additionally, `decrypt_with_proof` could reject proofs where the ciphertext doesn't decrypt to a canonical scalar for the claimed recipient before attributing sender fault — though transcript binding is the correct fix.

### Proof of Concept
1. Alice runs `generate_secret_shares`, producing `EncryptedMessage`s `m_B` (to Bob), `m_E` (to Eve), etc.; all are broadcast in `Transaction::DkgShares`.
2. Eve calls `BlameMachine::blame(sender=Alice, recipient=Eve, msg=m_B, proof=Some(p))` where `p.key = enc_key_Eve_priv * m_B.key` and `p.dleq = DLEqProof::prove(transcript, [G, m_B.key], enc_key_Eve_priv)`.
3. `decrypt_with_proof` verifies `m_B.pop` (passes — bound only to `sender=Alice` and ciphertext), verifies the DLEq against `enc_keys[Eve]` (passes — Eve's proof is genuinely correct for her key), decrypts `m_B.msg` under the wrong ECDH secret → garbage.
4. Garbage fails `C::F::from_repr` → `blame_internal` returns `Alice`. Honest Alice is blamed with a publicly verifiable proof. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)

fn encrypt<R: RngCore + CryptoRng, C: Ciphersuite, E: Encryptable>(
  rng: &mut R,
  context: [u8; 32],
  from: Participant,
  to: C::G,
  mut msg: Zeroizing<E>,
) -> EncryptedMessage<C, E> {
  /*
  The following code could be used to replace the requirement on an RNG here.
  It's just currently not an issue to require taking in an RNG here.
  let last = self.last_enc_key.to_bytes();
  self.last_enc_key = C::hash_to_F(b"encryption_base", last.as_ref());
  let key = C::hash_to_F(b"encryption_key", last.as_ref());
  last.as_mut().zeroize();
  */

  // Generate a new key for this message, satisfying cipher's requirement of distinct keys per
  // message, and enabling revealing this message without revealing any others
  let key = Zeroizing::new(C::random_nonzero_F(rng));
  cipher::<C>(context, &ecdh::<C>(&key, to)).apply_keystream(msg.as_mut().as_mut());

  let pub_key = C::generator() * key.deref();
  let nonce = Zeroizing::new(C::random_nonzero_F(rng));
  let pub_nonce = C::generator() * nonce.deref();
  EncryptedMessage {
    key: pub_key,
    pop: SchnorrSignature::sign(
      &key,
      nonce,
      pop_challenge::<C>(context, pub_nonce, pub_key, from, msg.deref().as_ref()),
    ),
    msg,
  }
}

fn pop_challenge<C: Ciphersuite>(
  context: [u8; 32],
  nonce: C::G,
  key: C::G,
  sender: Participant,
  msg: &[u8],
) -> C::F {
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption Key Proof of Possession v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"proof_of_possession");

  transcript.append_message(b"nonce", nonce.to_bytes());
  transcript.append_message(b"key", key.to_bytes());
  // This is sufficient to prevent the attack this is meant to stop
  transcript.append_message(b"sender", sender.to_bytes());
  // This, as written above, doesn't hurt
  transcript.append_message(b"message", msg);
  // While this is a PoK and a PoP, it's called a PoP here since the important part is its owner
  // Elsewhere, where we use the term PoK, the important part is that it isn't some inverse, with
  // an unknown to anyone discrete log, breaking the system
  C::hash_to_F(b"DKG-encryption-proof_of_possession", &transcript.challenge(b"schnorr"))
}

  pub(crate) fn decrypt_with_proof<E: Encryptable>(
    &self,
    from: Participant,
    decryptor: Participant,
    mut msg: EncryptedMessage<C, E>,
    // There's no encryption key proof if the accusation is of an invalid signature
    proof: Option<EncryptionKeyProof<C>>,
  ) -> Result<Zeroizing<E>, DecryptionError> {
    if !msg.pop.verify(
      msg.key,
      pop_challenge::<C>(self.context, msg.pop.R, msg.key, from, msg.msg.deref().as_ref()),
    ) {
      Err(DecryptionError::InvalidSignature)?;
    }

    if let Some(proof) = proof {
      // Verify this is the decryption key for this message
      proof
        .dleq
        .verify(
          &mut encryption_key_transcript(self.context),
          &[C::generator(), msg.key],
          &[self.enc_keys[&decryptor], *proof.key],
        )
        .map_err(|_| DecryptionError::InvalidProof)?;

      cipher::<C>(self.context, &proof.key).apply_keystream(msg.msg.as_mut().as_mut());
      Ok(msg.msg)
    } else {
      Err(DecryptionError::InvalidProof)
    }
  }

  fn blame_internal(
    &self,
    sender: Participant,
    recipient: Participant,
    msg: EncryptedMessage<C, SecretShare<C::F>>,
    proof: Option<EncryptionKeyProof<C>>,
  ) -> Participant {
    let share_bytes = match self.encryption.decrypt_with_proof(sender, recipient, msg, proof) {
      Ok(share_bytes) => share_bytes,
      // If there's an invalid signature, the sender did not send a properly formed message
      Err(DecryptionError::InvalidSignature) => return sender,
      // Decryption will fail if the provided ECDH key wasn't correct for the given message
      Err(DecryptionError::InvalidProof) => return recipient,
    };

    let Some(share) = Option::<C::F>::from(C::F::from_repr(share_bytes.0)) else {
      // If this isn't a valid scalar, the sender is faulty
      return sender;
    };

    // If this isn't a valid share, the sender is faulty
    if !bool::from(
      multiexp_vartime(&share_verification_statements::<C>(
        recipient,
        &self.commitments[&sender],
        Zeroizing::new(share),
      ))
      .is_identity(),
    ) {
      return sender;
    }

    // The share was canonical and valid
    recipient
  }
