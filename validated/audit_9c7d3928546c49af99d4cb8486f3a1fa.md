### Title
DataLayer mirror URLs are fetched over HTTP/S3 with no host/IP validation, enabling SSRF from any on-chain mirror-coin spend - (`File: chia/data_layer/download_data.py`, `chia/wallet/db_wallet/db_wallet_puzzles.py`)

### Summary
The GHSA report describes an SSRF caused by validating a URL's DNS resolution at one point in time and then letting the HTTP client re-resolve (and connect to) a different, unvalidated address later (DNS-rebinding TOCTOU). The chia-blockchain analog is stronger: DataLayer's mirror-URL fetch path performs **no host/IP validation at all**, at any point, and the mirror URL itself is attacker-controlled data that any unprivileged spend-bundle submitter can register on-chain for *any* store, not just their own.

### Finding Description
DataLayer mirror advertisements are stored as coins using an intentionally-unauthenticated puzzle: [1](#0-0) 

`create_mirror_puzzle()` curries `P2_PARENT` with a constant `1` — this is effectively an anyone-can-spend puzzle template. `get_mirror_info()` extracts `launcher_id` and the mirror `url` list directly from the `CREATE_COIN` condition's memo field with no cross-check that the spender is authorized to publish mirrors for that `launcher_id`. Any wallet user can construct a spend bundle that creates a coin with puzzle hash `MIRROR_PUZZLE_HASH` and memos `[launcher_id, url1, url2, ...]`, pointing at *any store*, with *any URL string* (including `http://169.254.169.254/...` or an internal RFC1918 address).

Once such a mirror coin is confirmed on chain, any node running the DataLayer service that is subscribed to (or owns) that store id will pick up the URL unconditionally: [2](#0-1) 

These URLs flow into `fetch_and_validate()`'s server selection and download logic with no filtering: [3](#0-2) 

The actual network fetch is a raw `aiohttp` GET with zero host/IP checks — no private-range blocking, no cloud-metadata blocking, no DNS validation whatsoever (unlike the ContextForge report, which at least attempted resolution-time validation before the TOCTOU gap): [4](#0-3) 

`download_file()` and `insert_from_delta_file()` route directly into this unauthenticated HTTP fetch: [5](#0-4) 

The module's own internal documentation acknowledges mirror/plugin URLs as untrusted inputs but only in the context of *data* integrity (verified against wallet-advertised Merkle roots), not in the context of *destination* safety for the HTTP request itself: [6](#0-5) [7](#0-6) 

### Impact Explanation
Any unprivileged party able to submit a spend bundle (the standard `dl_new_mirror` mirror-coin creation flow) can force every DataLayer node subscribed to a targeted store to issue outbound HTTP requests to attacker-chosen hosts — including link-local cloud metadata addresses (`169.254.169.254`) and internal RFC1918 services — with no operator action or admin privilege required beyond running the standard, default DataLayer sync loop (`periodically_manage_data()` / `update_subscription()`). This is a full SSRF primitive against any full-node/DataLayer host, reachable purely through normal on-chain mirror-coin creation, and is broader than the referenced report because there is no validation gap to race — there is no validation at all.

### Likelihood Explanation
High reachability: creating a mirror coin only requires standard mempool-accepted spend bundle submission (`dl_new_mirror`), no special roles, and the mirror puzzle (`P2_PARENT.curry(1)`) is designed to accept memo-supplied `launcher_id`/URL data from anyone. Any node that syncs the targeted store (owned or subscribed) will automatically attempt the fetch on its next `periodically_manage_data()` cycle.

### Recommendation
Before adding a URL to `data_store.subscribe`/`update_subscriptions_from_wallet` or issuing the `aiohttp` request in `http_download()`/`s3_plugin_service.download()`, resolve and validate the destination host against private/loopback/link-local/cloud-metadata ranges, and pin the validated IP for the actual connection (custom resolver/transport) rather than re-resolving the hostname at request time. Additionally, consider requiring mirror-coin creation to be tied to store ownership (e.g., an announcement assertion from the singleton) so arbitrary third parties cannot register mirror URLs for stores they do not own.

### Proof of Concept
1. Any wallet holder calls `dl_new_mirror` (`DLNewMirror(launcher_id=<victim_store_id>, urls=["http://169.254.169.254/latest/meta-data/"], amount=..., fee=..., push=True)`), producing a coin with puzzle hash `MIRROR_PUZZLE_HASH` and the attacker-chosen URL in the memo — this is a standard, unauthenticated spend that any node accepts into the mempool.
2. Once confirmed, any DataLayer node that is subscribed to `<victim_store_id>` (including the store owner's own node, via `update_subscriptions_from_wallet`) picks up the URL as an available mirror server.
3. On the next sync cycle, `fetch_and_validate()` → `insert_from_delta_file()` → `download_file()` → `http_download()` issues an unauthenticated `aiohttp.ClientSession().get("http://169.254.169.254/.../<filename>")` from the victim node, with no host/IP validation, potentially leaking cloud IAM credentials or probing internal services.

```python
def create_mirror_puzzle() -> Program:
    return P2_PARENT.curry(Program.to(1))


MIRROR_PUZZLE_HASH = create_mirror_puzzle().get_tree_hash()


def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
```
