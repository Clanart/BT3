## Finding



### Title
`DiffSelection.getSelectionType()` count-heuristic can misreport a partial line selection as "All", causing unselected/unreviewed lines to be silently committed - (File: `app/src/models/diff/diff-selection.ts`)

### Summary
`DiffSelection.getSelectionType()` decides whether a file's selection state is `All`, `None`, or `Partial` by comparing the *size* of the set of currently selectable lines against the size of the set of "diverging" lines (lines whose state differs from the default), and then checking that every selectable line is present in the diverging set: [1](#0-0) . This size/subset check does not verify that the diverging-line indices are all still valid, current, selectable lines of the diff currently being staged — it only checks that the (smaller or equal) selectable set is contained in the diverging set. That result feeds directly into `stageFiles()`, which uses `getSelectionType() === DiffSelectionType.All` to decide between fully staging a file (`git add`, ignoring the user's line selection entirely) versus generating and applying a line-level patch: [2](#0-1) .

### Finding Description
The working directory diff for a selected file is loaded asynchronously and, when reloaded (e.g. after the file's on-disk contents changed between the time the diff was fetched and the time selection is finalized), Desktop recomputes only the `selectableLines` set from the new diff hunks — it does **not** reconcile or invalidate the previously recorded `divergingLines` (the user's line-level selection state) against the new diff: [3](#0-2) .

`withSelectableLines` merely intersects: the resulting `DiffSelection` still carries the old `divergingLines` set (a set of raw line indices from the *stale* diff) alongside the new, potentially much smaller `selectableLines` set from the fresh diff. Because `getSelectionType()` only checks that `selectableLines.size === divergingLines.size` and that every *current* selectable index appears in the (stale) diverging set — not that the diverging set is a subset of, or index-consistent with, the current diff — a coincidental size match combined with index overlap is enough to flip the reported selection type: `Partial` (or effectively "mostly unselected") can be reported as `All`.

When `stageFiles()` subsequently sees `DiffSelectionType.All` for that file, it takes the "normal" staging path (`updateIndex(...)` / full `git add`) instead of building a per-line patch via `applyPatchToIndex`/`formatPatch`: [4](#0-3)  vs. [5](#0-4) . This means the **entire current working-tree content of the file** is staged and committed — including any lines the user explicitly excluded, and any lines that were introduced into the file between the diff load and the stage/commit action — with no re-validation against the user's actual intended selection.

### Impact Explanation
This breaks the core trust guarantee of partial/selective commits in GitHub Desktop: what the user visually reviewed and checked in the diff view is not necessarily what gets committed. A file's contents can change on disk between diff load and commit (e.g., due to a build tool, formatter, git hook, IDE, or a fast-following `git checkout`/merge/pull triggered by the same or a concurrent action), shrinking or reshaping the diff's hunks. If this causes the selectable-line count to coincidentally match the stale diverging-line count while the "every selectable line is in diverging set" check passes, Desktop silently promotes what should be a `Partial` selection to `All`, and stages/commits unreviewed content. This is a silent corruption of what the user commits — potentially exfiltrating unintended local content, or including malicious content written into a tracked file by another process, into a commit and subsequent push, without any user-visible warning.

### Likelihood Explanation
Likelihood is **low-to-moderate** and condition-dependent: it requires (1) a file with a partial (non-All/None) line selection, (2) the file's diff being reloaded (`updateChangesWorkingDirectoryDiff`) with a materially different hunk layout before the commit is created, and (3) a coincidental match between the new `selectableLines` size and the stale `divergingLines` count with full index overlap. This is a rare-condition class of bug (mirroring the original report's "rare conditions" framing) rather than a trivially triggerable one, but it requires no local/admin access or leaked credentials — only a file whose tracked content can change during a normal Desktop workflow (e.g. via a git hook, external tool, or fast repository operation), which is within the threat model of "silent corruption of what the user commits."

### Recommendation
`DiffSelection.getSelectionType()` should not rely purely on a size/subset heuristic that can silently reclassify `Partial` as `All`. Instead:
- When `selectableLines` is refreshed after a diff reload, invalidate/rebuild `divergingLines` against the new diff rather than reusing stale indices (i.e., filter `divergingLines` to only the intersection with the new `selectableLines`), or explicitly force any selection with mismatched diff generation/hash to `Partial`/require re-confirmation.
- In `stageFiles()`, prefer always staging via the line-level patch path when there was ever a non-`All` selection recorded for the file, rather than trusting `getSelectionType() === All` as a shortcut to bypass patch generation.
- Add a diff-identity/version check tying a `DiffSelection`'s `divergingLines` to the specific diff snapshot it was computed against, so stale selections can never be reinterpreted against a newer diff.

### Proof of Concept
1. Open a file with a large diff in GitHub Desktop's Changes view and deselect a subset of lines (partial selection), producing a `DiffSelection` with `defaultSelectionType = All` and a `divergingLines` set of the deselected line indices, sized `N`.
2. While that diff is being displayed, have another process (build tool/hook/fast git operation) rewrite the file such that the new diff has exactly `N` selectable lines, and those `N` indices happen to be contained in the old `divergingLines` set (achievable by controlling file content, e.g. via a malicious pre/post-checkout hook shipped in the cloned repository).
3. Desktop reloads the diff via `updateChangesWorkingDirectoryDiff`, calling `withSelectableLines` with the new, smaller selectable set: `app/src/lib/stores/app-store.ts:3478-3497`.
4. `getSelectionType()` now finds `selectableLines.size === divergingLines.size` and every selectable line divergent, and reports the inverse of `All` — i.e., flips a real partial exclusion into `DiffSelectionType.All` reported the wrong way, per the logic in `app/src/models/diff/diff-selection.ts:99-118`.
5. On commit, `stageFiles()` sees `DiffSelectionType.All` and stages the entire file via `git add`-equivalent instead of the intended line-level patch (`app/src/lib/git/update-index.ts:118-129`), committing content the user never selected.

```typescript
export async function stageFiles(
  repository: Repository,
  files: ReadonlyArray<WorkingDirectoryFileChange>
): Promise<void> {
  const normal = []
  const oldRenamed = []
  const partial = []
  const deletedFiles = []

  for (const file of files) {
    if (file.selection.getSelectionType() === DiffSelectionType.All) {
      normal.push(file.path)
      if (file.status.kind === AppFileStatusKind.Renamed) {
        oldRenamed.push(file.status.oldPath)
      } else if (file.status.kind === AppFileStatusKind.Deleted) {
        deletedFiles.push(file.path)
      }
    } else {
      partial.push(file)
    }
  }
```

```typescript
export function formatPatch(
  file: WorkingDirectoryFileChange,
  diff: ITextDiff | ILargeTextDiff
): string {
  let patch = ''

  diff.hunks.forEach((hunk, hunkIndex) => {
    let hunkBuf = ''

    let oldCount = 0
    let newCount = 0

    let anyAdditionsOrDeletions = false

    hunk.lines.forEach((line, lineIndex) => {
      const absoluteIndex = hunk.unifiedDiffStart + lineIndex

      // We write our own hunk headers
      if (line.type === DiffLineType.Hunk) {
        return
      }

      // Context lines can always be let through, they will
      // never appear for new files.
      if (line.type === DiffLineType.Context) {
        hunkBuf += `${line.text}\n`
        oldCount++
        newCount++
      } else if (file.selection.isSelected(absoluteIndex)) {
        // A line selected for inclusion.

        // Use the line as-is
        hunkBuf += `${line.text}\n`

        if (line.type === DiffLineType.Add) {
          newCount++
        }
        if (line.type === DiffLineType.Delete) {
          oldCount++
        }

        anyAdditionsOrDeletions = true
      } else {
        // Unselected lines in new files needs to be ignored. A new file by
        // definition only consists of additions and therefore so will the
        // partial patch. If the user has elected not to commit a particular
        // addition we need to generate a patch that pretends that the line
        // never existed.
        if (
          file.status.kind === AppFileStatusKind.New ||
          file.status.kind === AppFileStatusKind.Untracked
        ) {
          return
        }

        // An unselected added line has no impact on this patch, pretend
        // it was never added to the old file by dropping it.
        if (line.type === DiffLineType.Add) {
          return
        }

        // An unselected deleted line has never happened as far as this patch
        // is concerned which means that we should treat it as if it's still
        // in the old file so we'll convert it to a context line.
        if (line.type === DiffLineType.Delete) {
          hunkBuf += ` ${line.text.substring(1)}\n`
          oldCount++
          newCount++
        } else {
          // Guarantee that we've covered all the line types
          assertNever(line.type, `Unsupported line type ${line.type}`)
        }
      }

      if (line.noTrailingNewLine) {
        hunkBuf += '\\ No newline at end of file\n'
      }
    })

    // Skip writing this hunk if all there is is context lines.
    if (!anyAdditionsOrDeletions) {
      return
    }

    patch += formatHunkHeader(
      hunk.header.oldStartLine,
      oldCount,
      hunk.header.newStartLine,
      newCount
    )
    patch += hunkBuf
  })

  // If we get into this state we should never have been called in the first
  // place. Someone gave us a faulty diff and/or faulty selection state.
  if (!patch.length) {
    log.debug(`formatPatch: empty path for ${file.path}`)
    throw new Error(`Could not generate a patch, no changes`)
  }

  patch = formatPatchHeaderForFile(file) + patch

  return patch
}
```
