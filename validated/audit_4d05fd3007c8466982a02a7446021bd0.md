## Analysis Summary

The kernel CVE's failed invariant: a "reconfiguration" operation mutates shared per-CPU state (head bit, pages, reader_page) that a concurrent reader thread dereferences, with **no lock held by the mutator**, even though a `reader_lock` exists and is used elsewhere for exactly this data. <cite repo="bsaldua/protobuf--007" path="" start="" end="" />

I found a strong, evidenced analog in upb's lazy extension promotion path.

### Title
Unsynchronized mutation of message internal state during "read" extension access races with concurrent readers - (`upb/message/promote.c`)

### Summary
`upb_Message_GetOrPromoteExtension`, invoked from a semantically read-only "Get extension" API, mutates the message's internal aux-data slot array and its unknown-field list without any lock, in direct contradiction to protobuf's own documented thread-safety contract that "const"-looking operations which internally mutate must use locking to remain thread-safe.

### Finding Description
Protobuf's own documented invariant states: *"The implementation does contain some 'const' methods which actually modify the object behind the scenes -- e.g., to cache results -- but in these cases mutex locking is used to make the access thread-safe."* [1](#0-0) 

`upb_Message_GetOrPromoteExtension` is exactly such a "const-looking" get accessor, but it performs unlocked writes: it walks the message's unknown-field list, decodes matching bytes into a new sub-message, then calls `_upb_Message_GetOrCreateExtension` (which appends a new slot to `in->aux_data[in->size++]`) and repeatedly calls `upb_Message_DeleteUnknown2` to remove the now-promoted unknown-field records — all directly on the passed-in message, with no synchronization: [2](#0-1) 

The underlying storage mutated is a plain array (`in->aux_data`), grown via `_upb_Message_ReserveSlot`, and read by `_upb_Message_Getext` via a linear scan with no locking assumption at all: [3](#0-2) 

The upb team is aware this is unsafe: a dedicated, admittedly "temporary" locking shim exists only in the C++ `hpb` wrapper layer, explicitly because the *core* upb runtime has no such protection: *"TODO: Temporary locking api for cross-language concurrency issue around extension api that uses lazy promotion from unknown data to upb_MiniTableExtension. Will be replaced by a core runtime solution in the future."* [4](#0-3) 

`hpb::internal::GetOrPromoteExtension` explicitly casts away `const` and takes an external, optionally-registered lock before calling into `upb_Message_GetOrPromoteExtension`: [5](#0-4) 

Critically, this locking is opt-in via a global function-pointer hook (`upb_extension_locker_global`) that most consumers of upb never register. Any code path that calls `upb_Message_GetOrPromoteExtension` directly (or via generated PHP/Ruby accessors, which link against `php-upb.h`/`ruby-upb.h` containing the same symbol) gets **zero** protection. [6](#0-5) 

This mirrors the kernel bug precisely: a data-mutating "reconfiguration" (`ring_buffer_subbuf_order_set` / extension promotion) touches shared per-object state (`pages`/`reader_page` / `aux_data` array and unknown-field list) that a concurrent reader (`ring_buffer` reader / `_upb_Message_Getext`, `upb_Message_NextUnknown2`, serialization) dereferences without any lock coordination — the fix upstream added `reader_lock`; upb has only a bolt-on, opt-in lock in one language binding.

### Impact Explanation
This is a **consuming-application exposure**: protobuf's documented threading model explicitly promises that read-only access to a parsed message is safe from multiple threads simultaneously — this is the standard "parse once, read concurrently" pattern used by many services. If any thread triggers extension promotion (calling an extension getter for a field that was left as an "unknown"/non-canonical extension after parsing — a state fully controlled by an ordinary client via a crafted but valid, bounded wire payload) while another thread concurrently reads unknown fields, iterates extensions, or serializes the same message object, the unlocked array growth (`in->aux_data[in->size++]`, potential arena reallocation) and unknown-field list deletion can race with a concurrent reader walking the same structures, producing corrupted/stale pointers, use-after-free-style reads, or crashes (memory corruption / integrity and potential confidentiality impact), analogous to CVSS High severity in the original CVE.

### Likelihood Explanation
Moderate-to-High for applications that (a) use upb directly, or via PHP/Ruby bindings, and (b) follow protobuf's own documented "safe for concurrent const-style reads" guidance while lazily accessing extensions on a shared parsed message — a realistic and encouraged usage pattern, not application misuse. The bug is triggered purely by an ordinary client's payload shape (an extension field encoded as unknown/non-canonical data) plus ordinary concurrent read access by trusted application code; no privileged access or hostile schema is required.

### Recommendation
Add internal per-message (or per-arena) locking inside core upb's `upb_Message_GetOrPromoteExtension` / `_upb_Message_GetOrCreateExtension` / `upb_Message_DeleteUnknown2` paths (not just the optional `hpb` wrapper hook), or document and enforce that extension-promoting getters are NOT safe for concurrent const-style access, requiring callers to eagerly promote all extensions single-threaded before enabling concurrent reads.

### Proof of Concept
Not independently executed in this environment — no terminal access is available to compile/run upb. A minimal reproduction, consistent with the existing `hpb/internal/message_lock_test.cc` test pattern (which specifically exercises `GetOrPromoteExtension`, `Serialize`, and copy under concurrency using the *lock-enabled* wrapper) [7](#0-6) , would be: parse a message containing a non-registered/non-canonical extension via the *raw* upb C API (bypassing the `hpb` lock hook), then spawn two threads — one calling `upb_Message_GetOrPromoteExtension` for that field, the other calling `upb_Message_NextUnknown2`/`upb_Encode` on the same message — and run under ThreadSanitizer to observe the data race on `in->aux_data`/unknown-field list, matching the existing `TSAN`-oriented test style used elsewhere in the repo (e.g. `upb/mem/arena_test.cc` `FuzzRefArenaRace`). [8](#0-7)

// A note on thread-safety:
//
// Thread-safety in the Protocol Buffer library follows a simple rule:
// unless explicitly noted otherwise, it is always safe to use an object
// from multiple threads simultaneously as long as the object is declared
// const in all threads (or, it is only used in ways that would be allowed
// if it were declared const).  However, if an object is accessed in one
// thread in a way that would not be allowed if it were const, then it is
// not safe to access that object in any other thread simultaneously.
//
// Put simply, read-only access to an object can happen in multiple threads
// simultaneously, but write access can only happen in a single thread at
// a time.
//
// The implementation does contain some "const" methods which actually modify
// the object behind the scenes -- e.g., to cache results -- but in these cases
// mutex locking is used to make the access thread-safe.

upb_GetExtension_Status upb_Message_GetOrPromoteExtension(
    upb_Message* msg, const upb_MiniTableExtension* ext_table,
    int decode_options, upb_Arena* arena, upb_MessageValue* value) {
  UPB_ASSERT(!upb_Message_IsFrozen(msg));
  UPB_ASSERT(upb_MiniTableExtension_CType(ext_table) == kUpb_CType_Message);
  const upb_Extension* extension =
      UPB_PRIVATE(_upb_Message_Getext)(msg, ext_table);
  if (extension) {
    memcpy(value, &extension->data, sizeof(upb_MessageValue));
    return kUpb_GetExtension_Ok;
  }

  // Check unknown fields, if available promote.
  int found_count = 0;
  uint32_t field_number = upb_MiniTableExtension_Number(ext_table);
  const upb_MiniTable* extension_table =
      upb_MiniTableExtension_GetSubMessage(ext_table);
  // Will be populated on first parse and then reused
  upb_Message* extension_msg = NULL;
  int depth_limit = 100;
  uintptr_t iter = kUpb_Message_UnknownBegin;
  upb_MessageUnknown data;
  while (upb_Message_NextUnknown2(msg, &data, &iter)) {
    if (data.type == kUpb_MessageUnknownType_NonCanonicalExtension) {
      const upb_Extension* ext = (const upb_Extension*)data.value.extension;
      if (upb_MiniTableExtension_Number(ext->ext) == field_number) {
        found_count++;
        upb_UnknownToMessageRet parse_result =
            upb_MiniTable_ParseUnknownMessage(&data, extension_table,
                                              /* base_message= */ extension_msg,
                                              decode_options, arena);
        if (parse_result.status != kUpb_UnknownToMessage_Ok) {
          return upb_UnknownToMessage_ToGetExtensionStatus(parse_result.status);
        }
        extension_msg = parse_result.message;
      }
    } else {
      UPB_ASSERT(data.type == kUpb_MessageUnknownType_StringView);
      upb_StringView unknown_bytes = data.value.bytes;
      const char* ptr = unknown_bytes.data;
      upb_EpsCopyInputStream stream;
      upb_EpsCopyInputStream_Init(&stream, &ptr, unknown_bytes.size);
      while (!upb_EpsCopyInputStream_IsDone(&stream, &ptr)) {
        uint32_t tag;
        const char* unknown_begin = ptr;
        ptr = upb_WireReader_ReadTag(ptr, &tag, &stream);
        if (!ptr) return kUpb_GetExtension_ParseError;
        if (field_number == upb_WireReader_GetFieldNumber(tag)) {
          upb_StringView data;
          found_count++;
          upb_EpsCopyCapture capture;
          upb_EpsCopyCapture_Start(&capture, &stream, unknown_begin);
          ptr = _upb_WireReader_SkipValue(ptr, tag, depth_limit, &stream);
          if (!ptr || !upb_EpsCopyCapture_End(&capture, &stream, ptr, &data)) {
            return kUpb_GetExtension_ParseError;
          }
          upb_MessageUnknown unknown_item;
          unknown_item.type = kUpb_MessageUnknownType_StringView;
          unknown_item.value.bytes = data;
          upb_UnknownToMessageRet parse_result =
              upb_MiniTable_ParseUnknownMessage(
                  &unknown_item, extension_table,
                  /* base_message= */ extension_msg, decode_options, arena);
          if (parse_result.status != kUpb_UnknownToMessage_Ok) {
            return upb_UnknownToMessage_ToGetExtensionStatus(
                parse_result.status);
          }
          extension_msg = parse_result.message;
        } else {
          ptr = _upb_WireReader_SkipValue(ptr, tag, depth_limit, &stream);
          if (!ptr) return kUpb_GetExtension_ParseError;
        }
      }
    }
  }
  if (!extension_msg) {
    return kUpb_GetExtension_NotPresent;
  }

  upb_Extension* ext =
      UPB_PRIVATE(_upb_Message_GetOrCreateExtension)(msg, ext_table, arena);
  if (!ext) {
    return kUpb_GetExtension_OutOfMemory;
  }
  ext->data.msg_val = extension_msg;

  while (found_count > 0) {
    upb_FindUnknownRet2 found = upb_Message_FindUnknown2(msg, field_number, 0);
    UPB_ASSERT(found.status == kUpb_FindUnknown_Ok);
    if (upb_Message_DeleteUnknown2(msg, &found.unknown, &found.iter, arena) ==
        kUpb_DeleteUnknown_AllocFail) {
      return kUpb_GetExtension_OutOfMemory;
    }
    found_count--;
  }
  value->msg_val = extension_msg;
  return kUpb_GetExtension_Ok;
}

const upb_Extension* UPB_PRIVATE(_upb_Message_Getext)(
    const struct upb_Message* msg, const upb_MiniTableExtension* e) {
  upb_Message_Internal* in = UPB_PRIVATE(_upb_Message_GetInternal)(msg);
  if (!in) return NULL;

  for (size_t i = 0; i < in->size; i++) {
    upb_TaggedAuxPtr tagged_ptr = in->aux_data[i];
    if (upb_TaggedAuxPtr_IsCanonicalExtension(tagged_ptr)) {
      const upb_Extension* ext =
          upb_TaggedAuxPtr_CanonicalExtension(tagged_ptr);
      if (ext->ext == e) {
        return ext;
      }
    }
  }

  return NULL;
}

upb_Extension* UPB_PRIVATE(_upb_Message_GetOrCreateExtensionWithTag)(
    struct upb_Message* msg, const upb_MiniTableExtension* e, upb_Arena* a,
    upb_TaggedAuxType tag) {
  UPB_ASSERT(!upb_Message_IsFrozen(msg));
  // For Canonical Extensions, we check whether the extension has already been
  // set. If we find an extension with the same pointer and tag, we reuse it to
  // prevent duplicate entries for the same extension.
  //
  // For Non-Canonical Extensions, we do NOT reuse them, matching the behavior
  // of adding a unknown StringView (through `_upb_Message_AddUnknown`) which
  // accumulates.
  if (tag == kUpb_TaggedAuxType_CanonicalExtension) {
    upb_Extension* ext =
        (upb_Extension*)UPB_PRIVATE(_upb_Message_Getext)(msg, e);
    if (ext) return ext;
  }
  if (!UPB_PRIVATE(_upb_Message_ReserveSlot)(msg, a)) return NULL;
  upb_Message_Internal* in = UPB_PRIVATE(_upb_Message_GetInternal)(msg);
  upb_Extension* ext = upb_Arena_Malloc(a, sizeof(upb_Extension));
  if (!ext) return NULL;
  memset(ext, 0, sizeof(upb_Extension));
  ext->ext = e;
  in->aux_data[in->size++] = upb_TaggedAuxPtr_MakeExtension(ext, tag);
  return ext;
}

  Environment env;

  absl::Notification done;
  std::vector<std::thread> threads;
  for (int i = 0; i < 10; ++i) {
    threads.emplace_back([&]() {
      absl::BitGen gen;

      }

  auto end = absl::Now() + absl::Seconds(2);

    env.RandomRefArena(gen);
  }
  done.Notify();
  for (auto& t : threads) t.join();
