### Title
Arbitrary directory file write via unvalidated `foldername` in DataLayer `add_missing_files` RPC - (File: `chia/data_layer/data_layer_rpc_api.py`)

### Summary
The DataLayer RPC endpoint `add_missing_files` accepts a caller-supplied `foldername` string and passes it, unvalidated, all the way down to the file-writing routine that serializes local Merkle-tree data to disk. There is no check that the resulting path stays under the configured `server_files_location`, so any local RPC caller with access to this endpoint can force the DataLayer service to write `.dat` tree files into an arbitrary filesystem directory of their choosing.

### Finding Description
`DataLayerRpcApi.add_missing_files()` reads `foldername` straight from the JSON request body and wraps it in a `Path` with no canonicalization, allow-listing, or base-directory containment check: [1](#0-0) 

This value flows into `DataLayer.add_missing_files()`, which substitutes it directly for the service's normal, trusted `server_files_location`: [2](#0-1) 

That path is then handed to `write_files_for_root()`, which creates any missing parent directories and opens files for writing at the attacker-chosen location with no path validation: [3](#0-2) 

The written content (`write_tree_to_file`) serializes the local `DataStore` Merkle tree for the given store id/generation. Because store owners fully control the key/value pairs inserted into their own DataLayer store (via the `/insert` and `/batch_update` RPCs), the bytes written into these `.dat` files are attacker-influenced. Combined with the attacker-controlled destination directory, a caller with access to the DataLayer RPC can cause the service to place attacker-influenced binary content into a directory of their choosing outside the sandboxed `server_files_location` tree — the same bug class as CVE-2025-3125 (unvalidated upload destination in an admin-facing endpoint leading to file placement outside the intended storage root).

The resulting filenames follow the fixed `{store_id}-{node_hash}-{full|delta}-{generation}-v1.0.dat` convention (enforced elsewhere via `is_filename_valid()` for downloaded/mirrored files), so this is not a full arbitrary-filename primitive; the primitive here is an arbitrary write *location* with deterministic but attacker-influenced *content*.

### Impact Explanation
This lets a local, already-authenticated DataLayer RPC caller (a "Data Layer client" in scope per this review) write DataLayer-tree files, with attacker-controlled key/value payload, into any directory writable by the DataLayer process — not just under the sanctioned `server_files_location`. Depending on host configuration, this could overwrite or seed files in directories that are consumed by other local services/watchers, corrupt unrelated data, or be chained with other primitives to escalate impact. It breaks the assumption documented in the module's own context notes that "file path/name validation must stay strict" and that DataLayer files are confined to `server_files_location`.

### Likelihood Explanation
Requires reaching the DataLayer RPC surface (local, authenticated, per `rpc.md`'s "semi-trusted local/admin surface protected by private TLS") and control of at least one owned DataLayer store to shape file content — both are within the accepted "Data Layer client / local RPC caller" actor class for this review, with no need for CLI/host access beyond the RPC certs. The bug is a straightforward missing-validation issue triggered by a single RPC call.

### Recommendation
Validate `foldername` against an allow-list/resolved-path containment check (e.g., require it to resolve under a configured base directory, reject `..`/absolute overrides unless explicitly intended, and resolve symlinks before comparison) in `DataLayerRpcApi.add_missing_files()` before passing it into `DataLayer.add_missing_files()` / `write_files_for_root()`.

### Proof of Concept
1. As a DataLayer RPC caller, create/own a store and insert a chosen key/value payload via `/insert` or `/batch_update`.
2. Call `/add_missing_files` with `{"ids": ["<store_id>"], "foldername": "/some/arbitrary/writable/path"}`.
3. Observe `write_files_for_root()` creates `<node_hash>...v1.0.dat` files containing the serialized tree (including the attacker-chosen key/value bytes) at `/some/arbitrary/writable/path` instead of the configured `server_files_location`. [1](#0-0) [4](#0-3) [5](#0-4)

            subscriptions: list[Subscription] = await self.service.get_subscriptions()
            ids_bytes = [subscription.store_id for subscription in subscriptions]
        overwrite = request.get("overwrite", False)
        foldername: Path | None = None
        if "foldername" in request:
            foldername = Path(request["foldername"])
        for store_id in ids_bytes:
            await self.service.add_missing_files(store_id, overwrite, foldername)
        return {}

    async def add_missing_files(self, store_id: bytes32, overwrite: bool, foldername: Path | None) -> None:
        root = await self.data_store.get_tree_root(store_id=store_id)
        latest_generation = root.generation
        full_tree_first_publish_generation = max(0, latest_generation - self.maximum_full_file_count + 1)
        singleton_record = (
            await self.wallet_rpc.dl_latest_singleton(DLLatestSingleton(launcher_id=store_id, only_confirmed=True))
        ).singleton
        if singleton_record is None:
            self.log.error(f"No singleton record found for: {store_id}")
            return
        max_generation = min(singleton_record.generation, root.generation)
        server_files_location = foldername if foldername is not None else self.server_files_location
        files = []
        for generation in range(1, max_generation + 1):
            root = await self.data_store.get_tree_root(store_id=store_id, generation=generation)
            res = await write_files_for_root(
                self.data_store,
                store_id,
                root,
                server_files_location,
                full_tree_first_publish_generation,
                overwrite,
                self.group_files_by_store,
            )
            files.append(res.diff_tree.name)
            if res.full_tree is not None:
                files.append(res.full_tree.name)

    data_store: DataStore,

    overwrite: bool = False,

    if root.node_hash is not None:
        node_hash = root.node_hash

        node_hash = bytes32.zeros  # todo change

    filename_full_tree = get_full_tree_filename_path(foldername, store_id, node_hash, root.generation, group_by_store)
