## Analog Identified

The EigenLayer report's core defect is: **a value (native ETH + staking balance) that should be re-verified from live state before an accounting action (removing the node delegator from the queue) is instead trusted from a stale/cached assumption, corrupting a downstream valuation (`RSETH` price).**

The Agave analog is the **`StakesCache::check_and_store`** function, which updates a bank-level cache of vote/stake delegations used for stake-weighted consensus values (leader schedule, vote-account listings, rewards).

### Title
Stale delegated-stake cache entries when a cached stake/vote account's owner changes away from the stake/vote program - (`runtime/src/stakes.rs`)

### Summary
`StakesCache::check_and_store` only removes a cached vote/stake delegation entry when the account's lamports balance drops to zero. If a previously-cached stake or vote account is later observed with a **non-zero balance but an owner that is neither the stake program nor the vote program**, the function falls through both branches and does nothing — it neither refreshes nor evicts the existing cache entry.

### Finding Description
`check_and_store` branches only on `account.lamports() == 0` and `owner == vote_program`/`owner == stake_program`: [1](#0-0) 

The code contains an explicit acknowledged TODO stating this exact gap: [2](#0-1) 

referencing solana-labs/solana#24200's review discussion. A dedicated feature gate, `evict_invalid_stakes_cache_entries`, was declared to fix this: [3](#0-2) 

but no code in `stakes.rs` or `bank.rs` actually consults this feature id — `check_and_store` is unconditional and unaware of it, i.e., the fix described by the feature was never wired in for this path.

The bank invokes this cache update for every account touched by a successfully executed transaction, trusting `check_and_store` to keep the cache authoritative: [4](#0-3) 

An existing unit test explicitly documents that owner-change invalidation is **not** enforced today: [5](#0-4) [6](#0-5) 

The test asserts `vote_and_stake_accounts.len() == usize::from(!check_owner_change)`, i.e. with `check_owner_change = false`, a stake/vote account whose owner was reassigned to a bogus program is *still* returned as valid by the loader path used to bootstrap `Stakes` — confirming the cache/loader accepts stale entries rather than verifying current on-chain state.

### Impact Explanation
If an account cached as a delegated stake or vote account is reassigned to a different owner while retaining a non-zero balance, `StakesCache` keeps counting its old delegated-stake value toward `delegated_stakes`/`vote_accounts`, which feed leader-schedule computation, rewards, and RPC `getVoteAccounts` data. This is structurally identical to the eigenPod report: a downstream valuation (leader/vote weighting instead of `RSETH` price) is computed from cached state that is no longer verified against the account's real, current status.

### Likelihood Explanation
Likelihood is **Low** in the current builtin-program surface: neither the stake program nor the vote program expose any instruction that reassigns an account's owner away from itself while preserving a non-zero balance, and `BorrowedInstructionAccount::set_owner` requires the *current* owner program to authorize the change: [7](#0-6) 

So today this is a latent/defense-in-depth gap rather than a directly reachable unprivileged exploit — it would become live if any future builtin or the runtime itself allows owner reassignment of a funded stake/vote account (e.g., via a new CPI path, migration tooling, or a program upgrade), at which point the cache would silently retain stale stake weight with no existing guard to catch it.

### Recommendation
Extend `StakesCache::check_and_store` to always compare the account's current owner against the *previously cached* owner/kind for that pubkey, and evict the entry whenever the owner no longer matches the vote/stake program — regardless of the new balance — rather than only reacting to a zero-lamport transition. Wire the existing `evict_invalid_stakes_cache_entries` feature flag (or remove it and fix unconditionally) so the eviction is actually enforced, matching the recommendation from the referenced report style: verify the real, current state of an account before continuing to rely on it for a derived valuation.

### Proof of Concept
Using the existing test harness pattern in `runtime/src/bank/tests.rs::check_stake_vote_account_validity`:
1. Create a bank with a delegated stake/vote pair; confirm `bank.vote_accounts()`/loaded stake map includes them.
2. Directly mutate the stored account to change `owner` to an arbitrary pubkey while keeping `lamports() > 0` (simulating a future owner-reassignment path), then call `store_account`.
3. Observe (as the existing test does) that the entry is still counted by the vote/stake loader path, i.e. `check_and_store`/`_load_vote_and_stake_accounts` do not evict it: [8](#0-7) .

        &self,
        pubkey: &Pubkey,
        account: &impl ReadableAccount,
        new_rate_activation_epoch: Option<Epoch>,
        use_fixed_point_stake_math: bool,
    ) {
        // TODO: If the account is already cached as a vote or stake account
        // but the owner changes, then this needs to evict the account from
        // the cache. see:
        // https://github.com/solana-labs/solana/pull/24200#discussion_r849935444
        let owner = account.owner();
        // Zero lamport accounts are not stored in accounts-db
        // and so should be removed from cache as well.
        if account.lamports() == 0 {
            if solana_vote_program::check_id(owner) {
                let _old_vote_account = {
                    let mut stakes = self.0.write().unwrap();
                    stakes.remove_vote_account(pubkey)
                };
            } else if stake_program::check_id(owner) {
                let mut stakes = self.0.write().unwrap();
                stakes.remove_stake_delegation(
                    pubkey,
                    new_rate_activation_epoch,
                    use_fixed_point_stake_math,
                );
            }
            return;
        }
        debug_assert_ne!(account.lamports(), 0u64);
        if solana_vote_program::check_id(owner) {
            if VoteStateVersions::is_correct_size_and_initialized(account.data()) {
                match VoteAccount::try_from(create_account_shared_data(account)) {
                    Ok(vote_account) => {
                        // drop the old account after releasing the lock
                        let _old_vote_account = {
                            let mut stakes = self.0.write().unwrap();
                            stakes.upsert_vote_account(pubkey, vote_account)
                        };
                    }
                    Err(_) => {
                        // drop the old account after releasing the lock
                        let _old_vote_account = {
                            let mut stakes = self.0.write().unwrap();
                            stakes.remove_vote_account(pubkey)
                        };
                    }
                }
            } else {
                // drop the old account after releasing the lock
                let _old_vote_account = {
                    let mut stakes = self.0.write().unwrap();
                    stakes.remove_vote_account(pubkey)
                };
            };
        } else if stake_program::check_id(owner) {
            match StakeAccount::try_from(create_account_shared_data(account)) {
                Ok(stake_account) => {
                    let mut stakes = self.0.write().unwrap();
                    stakes.upsert_stake_delegation(
                        *pubkey,
                        stake_account,
                        new_rate_activation_epoch,
                        use_fixed_point_stake_math,
                    );

                    stakes.remove_stake_delegation(
                        pubkey,
                        new_rate_activation_epoch,
                        use_fixed_point_stake_math,
                    );
                }
            }
        }

    /// Assignes the owner of this account (transaction wide)
    pub fn set_owner(&mut self, pubkey: &[u8]) -> Result<(), InstructionError> {
        // Only the owner can assign a new owner
        if !self.is_owned_by_current_program() {
            return Err(InstructionError::ModifiedProgramId);
        }
        // and only if the account is writable
        if !self.is_writable() {
            return Err(InstructionError::ModifiedProgramId);
        }
        // and only if the data is zero-initialized or empty
        if !is_zeroed(self.get_data()) {
            return Err(InstructionError::ModifiedProgramId);
        }
        // don't touch the account if the owner does not change
        if self.get_owner().to_bytes() == pubkey {
            return Ok(());
        }
        self.touch()?;
        self.account.copy_into_owner_from_slice(pubkey);
        Ok(())
    }
