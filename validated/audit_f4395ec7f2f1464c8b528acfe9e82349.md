### Title
GaslessSwapRouter owner can unilaterally and instantly change `commissionRate` to front-run pending gasless swaps and redirect user value into commission - (File: `contracts/bindings/kip247/GaslessSwapRouter.go`)

### Summary
The KIP-247 `GaslessSwapRouter` contract exposes an owner-only `updateCommissionRate(uint256)` setter that changes the commission taken out of every `swapForGas` execution, with the change taking effect immediately (no cap, no timelock, no per-transaction pinning) and emitting only a `CommissionRateUpdated(oldRate, newRate)` event. This mirrors the Fractional `FERC1155.setRoyalties()` bug class: a single privileged party fully controls a fee parameter applied to third-party transfers/settlements and can change it at will between the time a user submits a transaction and the time it is executed, capturing value that the counterparty (the gasless user) reasonably expected to receive.

### Finding Description
`kaiax/gasless` is Kaia's own module implementing KIP-247 gasless transactions. It reads the active `GaslessSwapRouter` address from the system `Registry` [1](#0-0)  and uses it as the settlement target of every gasless swap bundle it builds: `[LendTxGenerator, GaslessApproveTx, GaslessSwapTx]` [2](#0-1) . The protocol-level repayment accounting computed by the module (`lendAmount`/`repayAmount`) is derived purely from gas fees and is independent of the router's internal commission logic [3](#0-2) .

The actual token-for-KAIA conversion and commission extraction happen inside `GaslessSwapRouter.swapForGas`, whose commission is set via the owner-only mutator: [4](#0-3) 

The contract emits a separate `commission` value distinct from what the user actually nets (`finalUserAmount`) in its settlement event: [5](#0-4) 

The `CommissionRateUpdated` event confirms the rate is a single scalar that can jump from any old value to any new value in one owner transaction, with no evidence (in the available bindings/ABI) of a maximum cap check or a delay before the new rate takes effect: [6](#0-5) 

Because gasless transactions are queued in the mempool and only bundled by the proposer at block-building time (`ExtractTxBundles`), there is a window in which the router owner can observe a pending, high-value `GaslessSwapTx` and submit `updateCommissionRate()` to raise the commission just before that swap is included, then lower it back afterward — the exact "frontrun/backrun" pattern described in the original Fractional report for `setRoyalties()`.

**Important caveat**: only the auto-generated Go bindings/ABI for `GaslessSwapRouter` were found in this index; the Solidity source (`GaslessSwapRouter.sol`) was not located, so the exact bounds-checking logic inside `updateCommissionRate` (e.g., whether a `MAX_COMMISSION_RATE` constant exists, as seen for `PublicDelegation.MAX_COMMISSION_RATE` in a different contract [7](#0-6) ) could not be directly verified from the code visible to me. This limits the certainty of the "uncapped" claim specifically for `GaslessSwapRouter`; a Devin session with full repository/source access would be needed to confirm this definitively.

### Impact Explanation
If `commissionRate` has no enforced cap and can be changed atomically and immediately (unlike `PublicDelegation`, which has an explicit `MAX_COMMISSION_RATE`), the router owner can extract an arbitrarily large share of every gasless swap's output at the exact moment a high-value swap is pending, redirecting value from gasless users (`finalUserAmount`) to the owner (`commission`/`CommissionClaimed`). This is a concrete instance of "gasless settlement theft" reachable by an ordinary public transaction from the owner account, harming unprivileged gasless-swap senders whose transactions were submitted in good faith at a known lower rate.

### Likelihood Explanation
Likelihood depends entirely on whether `updateCommissionRate` in the real Solidity source enforces a bound and/or a timelock, which I could not verify from the available bindings. If it lacks such protections (as with the FERC1155 `setRoyalties()` analog), the exploit requires only mempool visibility of pending swaps and a single owner-signed transaction, making it trivially and repeatedly exploitable by a malicious/compromised router owner.

### Recommendation
- Verify the actual `GaslessSwapRouter.sol` source (not available in this index) for `updateCommissionRate`'s bounds checks.
- If unbounded, enforce a hard-coded maximum commission rate (as done in `PublicDelegation.MAX_COMMISSION_RATE`).
- Add a timelock/delay between commission-rate change transactions and their effect, so pending gasless swaps cannot be front-run by a last-moment rate change.
- Consider pinning the commission rate used for a swap to the rate that was active when the corresponding `GaslessApproveTx`/`GaslessSwapTx` was signed/submitted, rather than the rate at execution time.

### Proof of Concept
Conceptual sequence (pending confirmation against actual Solidity source, since only bindings were available):
1. A gasless user signs and submits `GaslessApproveTx` + `GaslessSwapTx` with `minAmountOut` computed under the currently observed `commissionRate` (e.g., low rate).
2. The `GaslessSwapRouter` owner observes this pending, high-value swap in the mempool.
3. Owner calls `updateCommissionRate(_commissionRate)` [8](#0-7)  to spike the rate, timed to land in the block immediately before the victim's bundle (built per `ExtractTxBundles` [2](#0-1) ).
4. The victim's `swapForGas` executes at the new, higher commission rate, producing a smaller `finalUserAmount` and a larger `commission` credited to the owner, per the `SwappedForGas` event schema [5](#0-4) .
5. Owner calls `updateCommissionRate` again to restore the original low rate, then later calls to claim commission (`CommissionClaimed` event) [9](#0-8) .

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}
