### Title
Unvalidated offset causes negative-index slice panic in `consoleLog.decode` (DoS via crafted CONSOLE_LOG call) - (File: `blockchain/vm/contracts.go`)

### Summary
The `consoleLog` precompile's ABI-decoding routine, `(*consoleLog).decode`, computes a dynamic-type offset from raw, attacker-controlled call data and only checks that the offset is not *too large*, never that it is non-negative or otherwise well-formed before using it to slice the input buffer. A crafted `StringTy`/`BytesTy` argument can drive `start` to an out-of-range/negative value that later triggers a Go runtime slice-bounds panic when the value is used to index `params`, analogous to the icoutils `extract_icons` crash from a corrupted, boundary-violating input.

### Finding Description
`toLogString` selects a console-log signature from the call data and hands the remaining bytes to `decode`: [1](#0-0) 

Inside `decode`, for `StringTy` and `BytesTy` parameters, the "offset" word is read as an unsigned 32-byte big integer and truncated to a Go `int` via `big.Int.Int64()`: [2](#0-1) [3](#0-2) 

`big.Int.Int64()` is documented to produce an undefined (effectively 2's-complement-truncated) result when the value does not fit in an `int64`. Because the source bytes are read as an unsigned 32-byte word, an attacker fully controls the upper bits and can force `Int64()` to return a negative `int` for `start`. The subsequent bounds check `if len(params) < start+registerSize` is only a one-sided guard: when `start` is a large negative number, `start+registerSize` is also negative, so `len(params) < start+registerSize` evaluates to `false` and the check is bypassed. Execution then reaches `params[start:start+registerSize]` (and similarly `params[start+registerSize:start+size+registerSize]`), which panics with `slice bounds out of range [-N:]` because Go's runtime does not allow negative slice indices, rather than returning a controlled decode error.

This mirrors the CVE-2017-6010 bug class: a length/offset value parsed from untrusted input is used to index a buffer without validating that it is within the legal (non-negative, in-range) domain, leading to an out-of-bounds access and crash rather than an error return.

### Impact Explanation
A panic raised inside a precompiled contract's `Run` method during EVM execution is not a Solidity-level revert; it is a Go-level runtime panic. If this panic is not recovered somewhere in the EVM call stack (`vm.EVM.Call`/`RunPrecompiledContract`), it will unwind past the transaction-processing goroutine and crash the node process handling the transaction/block — a denial-of-service against any node that executes the malicious transaction, which is worse than a simple execution revert and could affect chain-wide processing consistency if triggered inside block import. Even in the best case where a `recover()` exists somewhere upstream, this still represents a functional defect: a crafted, deliberately malformed console-log call should be rejected with a clean decode error (as the rest of the function attempts to do), not crash the interpreter.

### Likelihood Explanation
Reachability is gated by `evm.Config.UseConsoleLog`; the `CONSOLE_LOG` precompile (`consoleLogContractAddress`) is only added to the active precompile map when this flag is enabled: [4](#0-3) 

This flag is intended for local/dev/test networks per the code comment ("implements solidity console.log for local networks"), and is exposed via node configuration (`cmd/utils/config.go`, `cmd/utils/flags.go`, `node/cn/config.go`). Whether it is enabled by default on any production Kaia network, or only opt-in, could not be fully confirmed from the available index; this is the main uncertainty affecting exploitability in a strict "unprivileged mainnet transaction sender" scenario. If any production/public-RPC node runs with `UseConsoleLog=true` (e.g., a testnet, or a misconfigured mainnet node), any unprivileged party can trigger the crash with a single crafted call to the console-log address — no special privileges, staking, or governance access required.

### Recommendation
- In `(*consoleLog).decode` (`blockchain/vm/contracts.go`), validate that `start` (and `start+size`) are non-negative and within `len(params)` using unsigned/bounded arithmetic (e.g., check `bigOffset.BitLen() <= 63` and compare against `len(params)` using `big.Int` comparisons, as is already done correctly in `accounts/abi/unpack.go`'s `lengthPrefixPointsTo`) before performing any Go slice operation.
- Ensure `RunPrecompiledContract`/`EVM.Call` wraps precompile execution in a `recover()` that converts any panic into a normal EVM execution error, so that no single malformed precompile input can crash node processing regardless of which precompile has a latent bug.
- Confirm and document whether `UseConsoleLog` can ever be enabled on production/public-RPC-exposed nodes; if so, treat this as directly exploitable and prioritize the fix accordingly.

### Proof of Concept
1. Run (or configure) a Kaia node with `UseConsoleLog` enabled.
2. Deploy or directly invoke a call to the console-log precompile address (`consoleLogContractAddress`) with data:
   - 4-byte selector matching a registered signature whose type list includes a `StringTy` or `BytesTy` argument (see `common.ConsoleLogSignatures`).
   - The 32-byte "offset" word for that argument set to a value whose high bit pattern causes `big.Int.Int64()` truncation to a negative `int`, e.g. `0xFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFF` (32 bytes of `0xff`), which as an unsigned big.Int is astronomically large and truncates to `-1` via `Int64()`.
3. Submit the call/transaction; `decode` computes `start = -1`, the bounds check `len(params) < start+registerSize` is bypassed, and `params[start:start+registerSize]` panics with a slice-bounds-out-of-range runtime error inside `consoleLog.Run`, crashing (or otherwise abnormally terminating) transaction execution on any node that has console.log enabled.

func (c *consoleLog) toLogString(input []byte) (string, error) {
	if len(input) < 4 {
		return "", errors.New("input too short")
	}
	selector := binary.BigEndian.Uint32(input[:4])
	params := input[4:]

	types, ok := common.ConsoleLogSignatures[selector]
	if !ok {
		return "", errors.New("unknown selector")
	}
	decoded, err := c.decode(params, types)
	if err != nil {
		return "", err
	}

	return strings.Join(decoded, " "), nil
}
