### Title
Reorg-Stale `transitionResultCache` Lets a Validator-Set Transition Computed From an Abandoned Fork Be Accepted as the Current Chain's Result - (File: kaiax/valset/impl/execution.go)

### Summary
`ValsetModule.transitionResultCache` caches the permissionless validator-set transition result (`*TransitionResult`, containing `NodeMap`) keyed solely by block number `num`, without any binding to the parent state root or block hash that produced it. `RewindTo` — the hook invoked by the blockchain on reorg — clears the vote-scanning cache but never purges `transitionResultCache`, unlike other kaiax modules (e.g. `kaiax/vrank/impl` explicitly purges `pfsCache`/`cpMatrixCache` on rewind, see `TestRewindTo_PurgesCache`).

### Finding Description
`getTransitionResult(num, parentStatedb)` first checks `transitionResultCache.Get(num)`; if present, it returns the cached `*TransitionResult` and **ignores the `parentStatedb` argument entirely** — there is no comparison between the state root that produced the cached entry and the state root of the `parentStatedb` passed on this call. [3](#0-2) 

The cache is populated speculatively by `postInsertBlockPermissionless`, which calls `getTransitionResult(nextNum, parentStatedb)` right after a block is inserted — i.e., speculatively computing and caching the transition for the *next* block number using the just-inserted block's state as parent. [4](#0-3) 

If the chain later reorgs away from that block (a competing block at the same height wins, or a deeper reorg replaces the chain segment), `RewindTo` is called, but it only touches `validatorVoteBlockNumsCache` and the DB-backed vote index — `transitionResultCache` is left untouched. [1](#0-0) 

Consequently, a subsequent `getTransitionResult(nextNum, newParentStatedb)` call — made while processing the block that now occupies height `nextNum` on the new (canonical) fork — will hit the stale cache entry and return the `TransitionResult` computed from the **abandoned fork's** `AddressBookV2` state (`abv2result.Nodes`, VRank scores, governance param set, etc.), instead of recomputing from the actual `newParentStatedb`.

This result feeds directly into `writeTransitionToABv2`, which computes `diffNodeStates(parentRes.Nodes, tr.Nodes)` and calls `processSystemTransition` via `SystemTxCall` to write validator lifecycle-state changes (`Active`/`Paused`/`removed`, timeouts) into `AddressBookV2` on-chain. [5](#0-4) 

It is also consumed by `VerifyHeader`, via `getQualifiedValidators` → `getNodes`, which compares the header's declared validator set against this (possibly stale) computed set to decide whether to accept a block. [6](#0-5) [7](#0-6) 

This mirrors the Lean CVE-2026-72711 bug class exactly: a type-checker cache answers a query using a value computed under one context (local-context/free-variable scope) after the surrounding context has since been restored/changed, because the cache lookup path skips the validity/membership check that the "cold" computation path performs. Here, the cache lookup path (`transitionResultCache.Get(num)`) skips the "does this result still correspond to the current parent state" check that the cold path (`applyTransition(parentHeader, parentStatedb)`) implicitly satisfies by construction.

### Impact Explanation
A reorg at or around the permissionless-validator-set boundary can cause the node to (a) write an incorrect validator-lifecycle diff into `AddressBookV2` (potential unauthorized activation/removal/pausing of validators, i.e., unauthorized state change to a system contract governing staking/consensus membership), or (b) accept/reject blocks in `VerifyHeader` based on a validator set that does not correspond to the actual canonical parent state, causing state divergence between nodes that experienced the reorg differently versus nodes that computed the transition fresh (nodes that never cached the losing fork's result). This is a concrete "acceptance of an invalid transaction/block" / state-divergence outcome reachable purely by ordinary chain reorg behavior (which any block producer/validator set can trigger via a competing block), not requiring a malicious peer message format bug.

### Likelihood Explanation
Requires a chain reorg to occur exactly at a block height for which the module already sped up an entry into `transitionResultCache` via `postInsertBlockPermissionless` before the reorg happened — i.e., reorgs of depth ≥1 around the permissionless-fork era. Reorgs of this shape (temporary fork, then reorg) are a normal, expected occurrence in any BFT/PoS-like production chain during network partitions or missed proposals, so the triggering condition is not exotic, though it depends on timing relative to the LRU cache's 128-entry retention window.

### Recommendation
Purge (or at minimum invalidate entries at/above the rewound height) `transitionResultCache` inside `RewindTo`/`RewindDelete`, matching the pattern already used in `kaiax/vrank/impl` for `pfsCache`/`cpMatrixCache`. Alternatively, key cache entries by `(num, parentStateRoot)` or validate the cached entry's provenance against the `parentStatedb` root before returning it in `getTransitionResult`.

### Proof of Concept
1. Node inserts block `N` on fork A; `postInsertBlockPermissionless` computes and caches `transitionResultCache[N+1]` using fork A's state at block `N`.
2. Fork B (a different block at height `N`, or a deeper ancestor) becomes canonical; blockchain layer calls `RewindTo` — `transitionResultCache` is not purged (`kaiax/valset/impl/execution.go:66-69`).
3. Node processes/verifies the new block at height `N+1` on fork B. `getTransitionResult(N+1, forkB_parentStatedb)` hits the cache and returns the fork-A-derived `TransitionResult` (`kaiax/valset/impl/transition.go:89-91`).
4. `writeTransitionToABv2` writes a validator-state diff derived from fork A's abandoned `AddressBookV2` data into fork B's `AddressBookV2`, and/or `VerifyHeader` accepts/rejects the new header using the wrong qualified validator set.

```go
func (v *ValsetModule) getNodes(num uint64) (valset.NodeMap, error) {
	if !v.Chain.Config().IsPermissionlessForkEnabled(new(big.Int).SetUint64(num)) {
		return nil, errPermissionlessDisabled
	}
	if cached, ok := v.transitionResultCache.Get(num); ok {
		return cached.(*TransitionResult).Nodes, nil
	}
	if num == 0 {
		// Block 0 has no parent; read ABv2 directly from genesis state.
		genesisHeader := v.Chain.GetHeaderByNumber(0)
		if genesisHeader == nil {
			return nil, errParentHeaderNotFound(num)
		}
		statedb, err := v.Chain.StateAt(genesisHeader.Root)
		if err != nil {
			return nil, fmt.Errorf("StateAt(%d) failed: %w", num, err)
		}
		result, err := system.ReadABv2Snapshot(statedb, v.Chain, genesisHeader)
		if err != nil {
			return nil, err
		}
		result.Nodes.MarkSuspended(result.SuspendedValidators)
		return result.Nodes, nil
	}
	parentHeader := v.Chain.GetHeaderByNumber(num - 1)
	if parentHeader == nil {
		return nil, errParentHeaderNotFound(num)
	}
	parentStatedb, err := v.Chain.StateAt(parentHeader.Root)
	if err != nil {
		return nil, fmt.Errorf("StateAt(%d) failed: %w", num-1, err)
	}
	result, err := v.getTransitionResult(num, parentStatedb)
	if err != nil {
		return nil, err
	}
	return result.Nodes, nil
}
```

```go
func (v *ValsetModule) getTransitionResult(num uint64, parentStatedb *state.StateDB) (*TransitionResult, error) {
	if num == 0 {
		return nil, errParentHeaderNotFound(num)
	}
	if cached, ok := v.transitionResultCache.Get(num); ok {
		return cached.(*TransitionResult), nil
	}

	// Read ABv2(N-1) + apply transitions for block N
	parentHeader := v.Chain.GetHeaderByNumber(num - 1)
	if parentHeader == nil {
		return nil, errParentHeaderNotFound(num)
	}
	result, err := v.applyTransition(parentHeader, parentStatedb)
	if err != nil {
		return nil, err
	}
	v.transitionResultCache.Add(num, result)
	return result, nil
}
```

```go
func (v *ValsetModule) writeTransitionToABv2(
	vmenv *vm.EVM,
	header *types.Header,
	statedb *state.StateDB,
) error {
	num := header.Number.Uint64()
	tr, err := v.getTransitionResult(num, statedb)
	if err != nil {
		return err
	}

	// Compute diff against committed ABv2(N-1) to get only applyTr(N-1) changes.
	parentHeader := v.Chain.GetHeaderByNumber(num - 1)
	if parentHeader == nil {
		return errParentHeaderNotFound(num)
	}
	parentRes, err := system.ReadABv2Snapshot(statedb, v.Chain, parentHeader)
	if err != nil {
		return fmt.Errorf("failed to read ABv2(N-1): %w", err)
	}
	diff := diffNodeStates(parentRes.Nodes, tr.Nodes)

	// Skip the call if no changes and not an epoch block (epoch blocks need
	// the epochVACount snapshot update regardless)
	if len(diff) == 0 && !v.isVrankEpoch(num) {
		return nil
	}

	config := v.Chain.Config()
	from, msg, err := system.EncodeProcessSystemTransition(config.Rules(header.Number), diff, tr.epochVACountForWrite)
	if err != nil {
		logger.Error("Failed to encode processSystemTransition", "number", header.Number.Uint64(), "err", err.Error(), "nodes", diff.String())
		return err
	}
	if ret, err := blockchain.SystemTxCall(msg, from, header, vmenv, statedb, config.Rules(header.Number)); err != nil {
		return fmt.Errorf("processSystemTransition failed: %w (ret=%s)", err, common.Bytes2Hex(ret))
	}
	return nil
```

```go
func (v *ValsetModule) VerifyHeader(header *types.Header, _ *types.Header) error {
	if !v.Chain.Config().IsPermissionlessForkEnabled(header.Number) {
		return nil
	}
	num := header.Number.Uint64()
	headerVals, err := v.Chain.Sealer().Validators(header)
	if err != nil {
		return err
	}
	qualified, err := v.getQualifiedValidators(num)
	if err != nil {
		return err
	}
	if !slices.Equal(headerVals, qualified.List()) {
		return errMismatchedValidators
	}
	return nil
}
```
