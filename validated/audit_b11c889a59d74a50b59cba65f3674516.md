### Title
Deep-link `filepath` parameter is unsanitized for path traversal, unlike `branch` - ([File: app/src/lib/parse-app-url.ts])

### Summary
The `x-github-client://openRepo/...` and `github-mac://openRepo/...` deep-link handlers parse attacker-controlled URL parameters to decide what GitHub Desktop should do after a clone completes. While the `branch` parameter is explicitly sanitized against invalid ref characters, the `filepath` parameter — documented as "the file to open after cloning the repository" — receives no validation at all, mirroring the report's core defect: a value that flows into a security-relevant sink is trusted without verifying it is safe, even though it is fully attacker-supplied.

### Finding Description
`parseAppURL` in [1](#0-0)  extracts `pr`, `branch`, and `filepath` from the query string of an `openrepo` deep link. `pr` is checked with a digit regex, and `branch` is checked both with a regex and with `testForInvalidChars` (imported from `sanitize-ref-name`) as shown at [2](#0-1) . `filepath`, however, is read via `getQueryStringValue` and passed straight through into the resulting `IOpenRepositoryFromURLAction` with zero validation: [3](#0-2) .

The interface comment for this field states its intended purpose explicitly: [4](#0-3) . This URL is routed from the OS-level protocol handler (`open-url` on macOS, `--protocol-launcher` on Windows) in [5](#0-4)  and [6](#0-5) , through IPC to the renderer's `dispatchURLAction` in [7](#0-6) , which calls `this.openRepositoryFromUrl(action)`.

This is directly analogous to the GNTDeposit bug class: a value with real consequences (there, a burn-destination address; here, a file path resolved and opened by the app) is accepted from an untrusted/attacker-influenced source without the same rigor applied to a sibling field (`branch`) that carries lower risk. The existing guard (`testForInvalidChars`) that would catch `../`-style traversal sequences is applied only to `branch`, not to `filepath`.

### Impact Explanation
If the code path that consumes `filepath` (in `openRepositoryFromUrl`/`dispatcher.ts`, not fully inspectable in this session) joins it with the freshly cloned repository directory without normalizing/re-validating it, a malicious deep link could cause GitHub Desktop to open a file outside the cloned repository (e.g., `filepath=../../../../.ssh/id_rsa` or an absolute path), which falls under "file read outside the repo" — one of the explicitly valid impact categories for this exercise.

### Likelihood Explanation
Likelihood is low-to-moderate: an attacker only needs to get a victim to click a crafted `x-github-client://openRepo/...` link (a normal, unprompted-by-malware user action explicitly allowed by the task's valid-impact criteria), which is a realistic phishing/social vector already acknowledged by Desktop's own protocol-handler design (external links are the intended trigger for this flow). No local access, admin rights, or pre-existing compromise is required.

### Recommendation
Apply the same sanitization used for `branch` (or stricter, path-specific checks such as rejecting `..`, absolute paths, and drive-letter/UNC prefixes) to the `filepath` field in `parseAppURL`, and re-validate/normalize the resolved path against the cloned repository root before any file-system read/open call, refusing to proceed if the resolved path escapes the repository directory — consistent with the report's underlying principle: don't trust externally supplied values for sensitive operations; validate them against a known-safe internal invariant instead of accepting them as-is.

### Proof of Concept
1. Attacker crafts: `x-github-client://openRepo/https://github.com/attacker/repo?filepath=../../../../.ssh/id_rsa`
2. Victim (with GitHub Desktop installed and registered as the protocol handler) clicks the link.
3. `handleAppURL` → `parseAppURL` → `open-repository-from-url` action is created with `filepath` unmodified (see [8](#0-7) ), unlike `branch`, which would have been rejected by `testForInvalidChars` if it contained similar traversal characters.
4. Dispatcher clones `attacker/repo` and (per the documented intent of the field) attempts to open the file at `filepath` relative to the clone — the unverified downstream consumption in `dispatcher.ts`/`openRepositoryFromUrl` is the piece that needs to be inspected/hardened to confirm full exploitability, since its exact implementation could not be retrieved in this session (index size limits truncated results). This should be independently verified with full repository access, e.g. via a Devin session that can read `app/src/ui/dispatcher/dispatcher.ts` in full to confirm the file-open sink.

```typescript
  if (actionName === 'openrepo') {
    const pr = getQueryStringValue(query, 'pr')
    const branch = getQueryStringValue(query, 'branch')
    const filepath = getQueryStringValue(query, 'filepath')

    if (pr != null) {
      if (!/^\d+$/.test(pr)) {
        return unknown
      }

      // we also expect the branch for a forked PR to be a given ref format
      if (branch != null && !/^pr\/\d+$/.test(branch)) {
        return unknown
      }
    }

    if (branch != null && testForInvalidChars(branch)) {
      return unknown
    }

    return {
      name: 'open-repository-from-url',
      url: parsedPath,
      branch,
      pr,
      filepath,
    }
```

```typescript
function handleAppURL(url: string) {
  log.info('Processing protocol url')
  const action = parseAppURL(url)
  onDidLoad(window => {
    // This manual focus call _shouldn't_ be necessary, but is for Chrome on
    // macOS. See https://github.com/desktop/desktop/issues/973.
    window.focus()
    window.sendURLAction(action)
  })
}
```

```typescript
  public async dispatchURLAction(action: URLActionType): Promise<void> {
    switch (action.name) {
      case 'oauth':

        if (__DARWIN__) {
          // workaround for user reports that the application doesn't receive focus
          // after completing the OAuth signin in the browser
          const isFocused = await isWindowFocused()
          if (!isFocused) {
            log.info(
              `refocusing the main window after the OAuth flow is completed`
            )
            window.focus()
          }
        }
        break

      case 'open-repository-from-url':
        this.openRepositoryFromUrl(action)
        break
```
