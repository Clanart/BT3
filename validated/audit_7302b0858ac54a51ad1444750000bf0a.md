### Title
Malicious auction/gasless target transaction can weaponize control-flow reverts to invalidate other senders' bundled transactions - (File: work/worker.go)

### Summary
Kaia's block builder bundles a searcher's `BidTx` (auction, KIP-249) or a proposer's `LendTxGenerator` (gasless, KIP-247) together with a user-controlled target/swap transaction, and treats the bundle atomically. If any transaction inside the bundle reverts or fails, the whole bundle is discarded and the concrete transactions in it are marked permanently unexecutable and dropped from the pool. This mirrors the CrossL2Inbox pattern where a party receiving control flow (here, the target contract executed inside a bundle) can force an "invalid" verdict that removes otherwise-valid, unrelated transactions from block inclusion.

### Finding Description
`ExtractBundlesAndIncorporate` combines an auction bid (`kaiax/auction/impl/builder.go`) or a gasless swap (`kaiax/gasless/impl/builder.go`) into a `Bundle` anchored to a `TargetTxHash` [1](#0-0) . For auction bundles, `TargetRequired = true` and the bundle (searcher's `BidTx`) is only executed immediately after its designated target transaction succeeds [2](#0-1) .

During block assembly, `shouldDiscardBundle` checks that the preceding target tx's receipt was successful; otherwise the bundle is discarded with an error [3](#0-2) . When a bundle transaction reverts inside `commitBundleTransaction`, the code explicitly rejects the *entire* bundle on any receipt status other than success and calls `markAllTxUnexecutable()`, which flags every concrete transaction in the bundle as permanently unexecutable via `tx.MarkUnexecutable(true)` [4](#0-3) . `MarkUnexecutable`-flagged transactions are later stripped from the pending/queued pool by `txList.Filter`/`FilterUnexecutable` [5](#0-4) , effectively excluding them from any future block, analogous to the Supervisor excluding an invalidated cross-chain message from inclusion in the original report.

Critically, the outcome of a bundled call depends on arbitrary user-supplied `data`/`to` execution: for auctions, `AuctionEntryPoint.call()` invokes `auctionTx.to.call{gas: callGasLimit}(auctionTx.data)` where `to` and `data` are attacker/searcher chosen (see the reference mock at `AuctionEntryPointMock.sol`) [6](#0-5) . For gasless swaps, the swap path calls into an ERC20 token and the `GaslessSwapRouter`, which are external, potentially attacker-influenced contracts whose reverting behavior determines bundle success [7](#0-6) .

Because bundle failure is all-or-nothing and marks every concrete tx in the bundle unexecutable, a party who can induce a revert in one leg of the bundle (e.g., a target contract behaving unexpectedly, or a token/router call reverting under adversarial conditions) can cause the co-bundled transaction(s) — which may belong to a different sender (the proposer's `BidTx`/`LendTxGenerator`, or another party's target tx) — to be dropped from the pool and excluded from future blocks, without that sender having done anything wrong.

### Impact Explanation
This breaks the assumption that a transaction's fate should depend only on its own signer/logic, not on the unrelated behavior of an external contract invoked in a bundle it did not construct. A target-transaction owner or a malicious contract placed at `auctionTx.to`/token address can unilaterally force exclusion of the bundle's other legs (searcher bid / gas-lending transaction), denying honest proposers/searchers their expected inclusion and fee capture, and repeatedly forcing transactions to be marked unexecutable and purged from the pool — a denial-of-service against specific senders' otherwise valid transactions. This is a Medium-severity liveness/fairness issue analogous to the reported CrossL2Inbox class: an untrusted callee can weaponize revert/validation-failure semantics to block transaction inclusion.

### Likelihood Explanation
Reachable by any unprivileged party who can be the target of a bid (via normal transaction submission) or whose token/router integrates a bundle (gasless swap), i.e., without needing validator, node, or auctioneer privileges. Because bid targets and swap participants are effectively chosen by ordinary users/dApps, and call targets/data for the auction bundle are attacker-supplied (`auctionTx.to`, `auctionTx.data`), triggering a controlled revert at the right moment is straightforward for a determined actor targeting a specific searcher/proposer bundle.

### Recommendation
Avoid propagating unexecutable-marking and pool eviction to bundle-external senders whose failure is not attributable to their own transaction. Specifically:
- Do not call `tx.MarkUnexecutable(true)` on bundle transactions whose failure is solely due to a different bundle member's revert (e.g., only mark the transaction that actually reverted, not the whole bundle, unless a true conflict exists).
- Re-evaluate whether atomic bundle rejection is appropriate when transactions belong to different senders with no genuine dependency, and consider isolating gas-refund/lending legs so a target-tx revert cannot cause the searcher/proposer's own valid transaction to be excluded from the pool.
- Add rate limiting / cooldown before permanently marking a transaction unexecutable due to bundle-partner failure, to prevent repeated weaponized denial of a specific counterparty's transactions.

### Proof of Concept
1. A searcher submits a winning `BidTx` targeting `TargetTxHash` = hash of a pending transaction `T` sent to attacker-controlled contract `C` (`kaiax/auction/impl/builder.go`, `ExtractTxBundles`).
2. The block builder forms `Bundle{BundleTxs: [BidTxGen], TargetTxHash: T.Hash(), TargetRequired: true}` and incorporates it right after `T` (`work/builder/builder.go`, `incorporate`).
3. During block assembly, `T` executes successfully but the attacker crafts `C`'s logic so that immediately following state (e.g., storage now depended upon by the bid's callback / a reentrant condition) causes the subsequent `AuctionEntryPoint.call` (executed as part of the bid) to revert non-trivially (`AuctionEntryPointMock.sol`, `call()`).
4. `commitBundleTransaction` sees `receipt.Status != types.ReceiptStatusSuccessful`, calls `markAllTxUnexecutable()`, and marks the searcher's bid transaction (and any other concrete tx in the bundle) unexecutable (`work/worker.go` lines 887-936).
5. On the next `demoteUnexecutables`/`Filter` pass, the searcher's transaction is permanently evicted from the tx pool via `IsMarkedUnexecutable()` (`blockchain/tx_list.go` lines 376-443), denying the searcher inclusion in any future block for that transaction, despite the searcher having done nothing invalid — the failure was solely due to `C`'s (attacker's) chosen revert behavior.

*Note: full exploitation requires precise gas/state control of `C`'s revert timing, which was not verified by execution in this analysis; the code paths establishing the atomic-bundle-eviction mechanism are directly cited above and confirmed to exist as described.*

func ExtractBundlesAndIncorporate(arrayTxs []*types.Transaction, txBundlingModules []TxBundlingModule) ([]*TxOrGen, []*Bundle) {
	// Detect bundles and add them to bundles
	bundles := []*Bundle{}
	flattenedTxs := []*TxOrGen{}
	if txBundlingModules == nil {
		for _, tx := range arrayTxs {
			flattenedTxs = append(flattenedTxs, NewTxOrGenFromTx(tx))
		}
		return flattenedTxs, nil
	}

	for _, txBundlingModule := range txBundlingModules {
		newBundles := txBundlingModule.ExtractTxBundles(arrayTxs, bundles)
		for _, newBundle := range newBundles {
			isConflict := false
			// Check for conflicts with all previous bundles
			for _, prevBundle := range bundles {
				isConflict = prevBundle.IsConflict(newBundle)
				if isConflict {
					break
				}
			}
			// Not allowing empty bundles
			if !isConflict && len(newBundle.BundleTxs) > 0 {
				bundles = append(bundles, newBundle)
			}
		}
	}

	// Coordinate target tx hash of bundles. It assumes the Gasless and Auction modules only currently.
	// This reordering does not break the execution result.
	// For example, if bundle reordering breaks the nonce ordering, the execution result will be different.
	bundles = coordinateTargetTxHash(bundles)

	incorporatedTxs, err := IncorporateBundleTx(arrayTxs, bundles)
	if err != nil {
		return flattenedTxs, nil
	}

	return incorporatedTxs, bundles
}

func (env *Task) shouldDiscardBundle(bundle *builder.Bundle) (bool, error) {
	if !bundle.TargetRequired {
		return false, nil
	}
	if env.tcount == 0 {
		return bundle.TargetTxHash != common.Hash{}, fmt.Errorf("target tx %s does not precede the bundle", bundle.TargetTxHash.Hex())
	} else {
		// if `env.tcount` is not zero, the `bundle.TargetTxHash` must not be empty hash
		if bundle.TargetTxHash != env.txs[env.tcount-1].Hash() {
			return true, fmt.Errorf("target tx %s does not precede the bundle", bundle.TargetTxHash.Hex())
		}
		if env.receipts[env.tcount-1].Status != types.ReceiptStatusSuccessful {
			return true, fmt.Errorf("target tx %s failed with status %d", bundle.TargetTxHash.Hex(), env.receipts[env.tcount-1].Status)
		}
	}
	return false, nil
}

func (l *txList) Filter(sender common.Address, pool *TxPool) (types.Transactions, types.Transactions) {
	// Filter out all the transactions above the account's funds
	removed := l.txs.Filter(func(tx *types.Transaction) bool {
		senderBalance := pool.getBalance(sender)
		// Drop a tx if it is marked as un-executable on block generation process.
		if tx.IsMarkedUnexecutable() {
			return true
		}
		// Since there are mutable values such as accountKey in the state, a tx can be invalidated with the state change.
		if tx.Validate(pool.currentState, pool.signer, pool.currentBlockNumber, true) != nil {
			return true
		}
		// In case of fee-delegated transactions, the comparison value should consider tx fee and fee ratio.
		if tx.IsFeeDelegatedTransaction() {
			feePayer, _ := tx.FeePayer()
			feePayerBalance := pool.getBalance(feePayer)
			feeRatio, isRatioTx := tx.FeeRatio()

			// Handling the special case when the sender and fee payer are the same.
			if sender == feePayer {
				return senderBalance.Cmp(tx.Cost()) < 0
			}
			if isRatioTx {
				feeByFeePayer, feeBySender := types.CalcFeeWithRatio(feeRatio, tx.Fee())
				return senderBalance.Cmp(new(big.Int).Add(tx.Value(), feeBySender)) < 0 || feePayerBalance.Cmp(feeByFeePayer) < 0
			} else {
				return senderBalance.Cmp(tx.Value()) < 0 || feePayerBalance.Cmp(tx.Fee()) < 0
			}
		}

		// balance check for module transaction
		for _, module := range pool.modules {
			if module.IsModuleTx(tx) {
				if checkBalance := module.GetCheckBalance(); checkBalance != nil {
					return checkBalance(tx) != nil
				}
				break
			}
		}

		// For other transactions, all tx cost should be payable by the sender.
		return senderBalance.Cmp(tx.Cost()) < 0
	})

	// If the list was strict, filter anything above the lowest nonce
	var invalids types.Transactions

	if l.strict && len(removed) > 0 {
		lowest := uint64(math.MaxUint64)
		for _, tx := range removed {
			if nonce := tx.Nonce(); lowest > nonce {
				lowest = nonce
			}
		}
		invalids = l.txs.Filter(func(tx *types.Transaction) bool { return tx.Nonce() > lowest })
	}
	return removed, invalids
}

// FilterUnexecutable removes all transactions marked as unexecutable.
func (l *txList) FilterUnexecutable() (types.Transactions, types.Transactions) {
	removed := l.txs.Filter(func(tx *types.Transaction) bool {
		// Drop a tx if it is marked as un-executable on block generation process.
		if tx.IsMarkedUnexecutable() {
			return true
		}
		return false
	})

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {

		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// If SwapTx.nonce is the sender's next nonce, then there is no room for ApproveTx proceeding SwapTx.
		senderNonce := g.getCurrentStateNonce(swapArgs.Sender)
		noApproveTxPreceeds := swapNonce == senderNonce
		if noApproveTxPreceeds {
			// tx.token.allowance(sender, router) >= tx.amountIn
			approval, err := tokenContract.Allowance(nil, swapArgs.Sender, swapRouter)
			if err != nil {
				return err
			}
			if approval.Cmp(swapArgs.AmountIn) < 0 {
				return fmt.Errorf("insufficient approval: approval=%s, want=%s", approval.String(), swapArgs.AmountIn.String())
			}
		}

		// tx.token.balanceOf(sender) >= tx.amountIn
		balance, err := tokenContract.BalanceOf(nil, swapArgs.Sender)
		if err != nil {
			return err
		}
		if balance.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("insufficient balance: balance=%s, want=%s", balance.String(), swapArgs.AmountIn.String())
		}
	}

	// tx.deadline >= currentTimestamp
	deadline := swapArgs.Deadline
	if deadline.Cmp(g.Chain.CurrentBlock().Time()) < 0 {
		return fmt.Errorf("insufficient deadline: deadline=%s, want=%s", deadline.String(), g.Chain.CurrentBlock().Time().String())
	}

	return nil
}
