### Title
Bid identity check via `Equals()` ignores signature and payload fields, enabling silent bid substitution in the auction bid pool - (File: kaiax/auction/impl/bid_pool.go, kaiax/auction/bid.go)

### Summary
The Royco report's root cause is that offer identity was checked using a partial/weak identifier (`offerID`, or an `abi.encodePacked()` hash that can collide across different payloads), allowing an attacker to substitute a legitimate offer with a malicious one that resolves to the same identifier. Kaia's auction `BidPool` has an analogous weak-identity check: `Bid.Equals()` only compares `BlockNumber` and `TargetTxHash`, not the full bid payload (sender/searcher aside), and this loose equality is used to gate whether a new bid from the same sender is treated as "the same bid" versus rejected.

### Finding Description
`Bid.Equals` is defined as: [1](#0-0) 
comparing only `BlockNumber` and `TargetTxHash`. This is used in `senderHasDifferentWinner`, which gates whether a bid from a sender who already has a recorded winning bid for that block is accepted: [2](#0-1) 
and is invoked both in `validateBid` (rule 1) and again in `insertBid`: [3](#0-2) [4](#0-3) 

Because `Equals()` disregards `Bid`, `CallGasLimit`, `Data`, `Nonce`, `MaxGasPrice`, `SearcherSig`, and `AuctioneerSig`, two bids with the same `(BlockNumber, TargetTxHash)` but wildly different bid amounts, call data, or gas limits are treated as "the same bid" by this equality check. Separately, actual insertion/replacement in `insertBid` is keyed by `(blockNumber, targetTxHash)` in `bidTargetMap`, with replacement gated only on `existingBid.Bid.Cmp(bid.Bid) >= 0` (i.e., pure bid-amount comparison), not on the actual content equivalence of the calls being auctioned: [5](#0-4) 

Every bid does still require a valid EIP-712 searcher signature (over the full `BidData` including block number, sender, `data` hash, etc.) and a valid auctioneer signature over the searcher signature, verified in `validateBidSigs`: [6](#0-5) 
using `ValidateSearcherSig`/`ValidateAuctioneerSig`: [7](#0-6) 

This signature requirement is the primary defense that prevents a third party from injecting a malicious bid, which is the strongest mitigating factor here (unlike Royco's `RecipeKernel.sol`, which had no such signature gate on IP offers). However, `senderHasDifferentWinner`'s `Equals()` check is still an internal identity-consistency bug: it can allow a bid pool to accept a "replacement" bid from the same sender for the same `(blockNumber, targetTxHash)` under conditions where the caller code assumes it's dealing with the same underlying bid content (e.g., logging/telemetry, or downstream consumers relying on `Equals()` for deduplication) when the actual bid amount, call data, or gas limit differs completely. Because `Equals()` is not tied to `Hash()` (which is a full RLP hash of `BidData`), code paths that rely on `Equals()` for "is this the bid I expect" checks are weaker than paths using `Hash()`, mirroring the exact structural flaw the Spearbit report flagged: comparing objects by a truncated/partial identity rather than a hash of the full canonical data.

### Impact Explanation
If any consumer of `senderHasDifferentWinner`/`Equals()` treats a `true` result (bids are "equal") as license to skip re-validating bid content (amount, gas limit, calldata), a same-sender resubmission with a drastically different `Bid` amount, `CallGasLimit`, or `Data` for the identical `(BlockNumber, TargetTxHash)` slot would not be flagged as a "different winner," potentially allowing stale/incorrect bid economics or call data to be assumed unchanged across a chain reorg or bid resubmission window, when in fact the auctioned call and bid price changed. This falls under acceptance-of-invalid-state / auction settlement inconsistency category (Medium), since actual insertion still uses `Hash()`-keyed maps and full signature verification, limiting exploitability to logic built directly atop `Equals()`.

### Likelihood Explanation
Likelihood is Medium: a searcher (an unprivileged public bidder who can call `SubmitBid`/gossip a bid) fully controls sender-side fields of a new bid, and can trivially construct a new bid with the same `BlockNumber`/`TargetTxHash` but different `Bid`, `Data`, or `CallGasLimit`, satisfying `Equals()`'s narrow definition while carrying entirely different semantics. Exploiting it further requires a code path elsewhere in the auction pipeline (or an external node/relay) trusting `Equals()` as a full-content equivalence check rather than `Hash()`.

### Recommendation
Redefine `Bid.Equals()` to compare either the full `Hash()` of the two bids (RLP hash of `BidData`) or, at minimum, all economically/execution-relevant fields (`Sender`, `To`, `Nonce`, `Bid`, `MaxGasPrice`, `CallGasLimit`, `Data`), not just `BlockNumber` and `TargetTxHash`. This aligns the auction module with the Spearbit recommendation to identify offers/bids by a hash of their full canonical struct rather than a partial key, preventing any future code path from mistakenly treating economically different bids as identical.

### Proof of Concept
1. A searcher submits bid B1 for `(blockNumber=N, targetTxHash=T)` with `Bid=100`, `Data=dataA`, signed correctly; it becomes the winner and is stored in `bidWinnerMap[N][sender] = hash(B1)`.
2. The same searcher (or an attacker controlling the same sender key, e.g., after a brief chain condition) submits bid B2 for the same `(N, T)` with `Bid=1`, `Data=dataB` (a completely different call), also validly signed.
3. `senderHasDifferentWinner(B2)` calls `B2.Equals(B1)`, which returns `true` because only `BlockNumber` and `TargetTxHash` match — despite `Bid` and `Data` being entirely different.
4. Any logic gating on this "equals" result (e.g., skip re-checking sender-winner constraints) treats B2 as the same bid as B1, even though the payload/economics differ, exposing the same "partial identity used to gate replacement" root cause highlighted in the external report for `RecipeKernel.sol`.

func (b *Bid) ValidateSearcherSig(chainId *big.Int, verifyingContract common.Address, version string) error {
	if chainId == nil {
		return ErrNilChainId
	}

	if common.EmptyAddress(verifyingContract) {
		return ErrNilVerifyingContract
	}

	digest := b.GetHashTypedData(chainId, verifyingContract, version)

	recoveredSender, err := getSigner(b.SearcherSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover searcher sig: %v", err)
	}

	if recoveredSender != b.Sender {
		return fmt.Errorf("invalid searcher sig: expected %v, calculated %v", b.Sender.String(), recoveredSender.String())
	}

	return nil
}

func (b *Bid) ValidateAuctioneerSig(auctioneer common.Address) error {
	digest := b.GetEthSignedMessageHash()

	recoveredAuctioneer, err := getSigner(b.AuctioneerSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover auctioneer sig: %v", err)
	}

	if recoveredAuctioneer != auctioneer {
		return fmt.Errorf("invalid auctioneer sig: expected %v, calculated %v", auctioneer.String(), recoveredAuctioneer.String())
	}

	return nil
}

	bp.bidMu.Lock()
	defer bp.bidMu.Unlock()

		blockNumber  = bid.BlockNumber
		targetTxHash = bid.TargetTxHash
		sender       = bid.Sender

		return auction.ErrBidAlreadyExists

		return auction.ErrBidSenderExists

// senderHasDifferentWinner reports whether a different bid from the same sender
// already exists in the winner list for this block. Caller must hold bidMu.
func (bp *BidPool) senderHasDifferentWinner(bid *auction.Bid) bool {
	hash, ok := bp.bidWinnerMap[bid.BlockNumber][bid.Sender]
	if !ok {
		return false
	}
	return !bid.Equals(bp.bidMap[hash])
}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}
