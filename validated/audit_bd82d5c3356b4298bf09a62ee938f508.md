## Analysis

The Cantina report's core invariant break is: **a low-level `call()` to an address with no code returns `success = true` per EVM semantics, even though nothing executed** — code that treats that `success` as proof the callee did its job will finalize state it shouldn't.

`EvmHost.sol` in this repo actually contains the *fix* for this exact bug in one place, but is missing it in three sibling functions that share the identical pattern.

### The guarded case (correct) [1](#0-0) 

`dispatchIncoming(PostRequest,...)` explicitly checks `extcodesize` on the destination before calling `IApp.onAccept`, and simply returns early (without persisting a receipt) if the target has no code.

### The unguarded cases (vulnerable)
`dispatchIncoming(GetResponse,...)`: [2](#0-1) 

`dispatchTimeOut(GetRequestTimeout,...)` and `dispatchTimeOut(PostRequestTimeout,...)`: [3](#0-2) 

None of these three functions performs an `extcodesize` check on `_bytesToAddress(...request.from)` before the `.call(...)`. The `from` address is attacker/caller-controlled at dispatch time — it's set to `abi.encodePacked(_msgSender())` when the original request is created: [4](#0-3) 

Because `dispatch(DispatchPost)` is a public entrypoint callable by any address — EOA or contract — `from` can legitimately be an EOA, or a contract that later self-destructs before the timeout/response is delivered.

### Why this breaks the protocol invariant

When the handler later calls `dispatchTimeOut`/`dispatchIncoming(GetResponse)` against that `from` address and it has no code:
- The low-level `.call()` returns `success = true` even though `onGetTimeout`/`onPostRequestTimeout`/`onGetResponse` never ran.
- Because `success == true`, the code takes the "handled successfully" branch: the request/response receipt is **permanently finalized** (deleted and not restored), and the relayer fee is unconditionally paid out via `IERC20(feeToken()).safeTransfer(...)`.
- Any actual application logic that was supposed to run on that callback — e.g. `HyperFungibleToken.onPostRequestTimeout` re-minting burned tokens as a refund — never executes: [5](#0-4) 

The protocol state now falsely records the timeout/response as fully and successfully handled (false state acceptance), the relayer/sender is paid a fee for a "delivery" that never happened, and the module-side funds refund/settlement logic is permanently skipped — a direct fund-loss/lock condition, and it is not retryable since the receipt was already finalized on the success path.

### Title
Missing contract-existence check in `EvmHost.dispatchTimeOut`/`dispatchIncoming(GetResponse)` lets calls to non-existent/self-destructed `from` addresses falsely finalize as successful - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatchIncoming(PostRequest,...)` correctly guards against calling a destination with no deployed code via an `extcodesize` check before invoking `IApp.onAccept`. The three sibling functions — `dispatchIncoming(GetResponse,...)`, `dispatchTimeOut(GetRequestTimeout,...)`, and `dispatchTimeOut(PostRequestTimeout,...)` — omit this check entirely and rely solely on the boolean `success` returned by a raw `.call()` to `_bytesToAddress(...request.from)`.

### Finding Description
Per EVM semantics, a `call` to an address with no code returns `success = true` without executing anything. `from` originates from `_msgSender()` at original dispatch time and can be an EOA or a contract that is later destroyed. When the timeout or GET response is later delivered to that address, the handler's `.call()` trivially "succeeds," so the code takes the success branch: it permanently commits the receipt deletion and pays out the relayer fee, while the actual downstream module logic (refunds, escrow release, state updates) never runs.

### Impact Explanation
This causes false on-chain state acceptance (a timeout/response is recorded as successfully processed when nothing executed) and permanent loss/lock of funds for whatever module logic depended on that callback (e.g. token refund-on-timeout in `HyperFungibleToken`/`WrappedHyperFungibleToken`, or escrow settlement callbacks in the intents apps). It also causes an unwarranted relayer fee/reward payout for a delivery that never actually occurred.

### Likelihood Explanation
This requires no malicious relayer, prover, or admin — only an ordinary permissionless caller of `dispatch(DispatchPost)` (which sets `from` to `_msgSender()`), or any deployed contract module that can self-destruct or be replaced. This is directly reachable through the normal ISMP request lifecycle already exercised by every app in the repo.

### Recommendation
Add the same `extcodesize` check used in `dispatchIncoming(PostRequest,...)` to `dispatchIncoming(GetResponse,...)`, `dispatchTimeOut(GetRequestTimeout,...)`, and `dispatchTimeOut(PostRequestTimeout,...)` before performing the low-level call, and treat a zero-code target the same way as a call failure (do not finalize the receipt, do not pay the relayer fee).

### Proof of Concept
1. An EOA (or a contract intended to be later destroyed) calls `IDispatcher(host).dispatch(DispatchPost{...})` directly, becoming `from` in the resulting `PostRequest`/`GetRequest`.
2. The request is dispatched and times out (or a GET response is delivered) without ever reaching a real `IApp` implementation, because `from` has no code.
3. A relayer submits the timeout/response proof; `EvmHost.dispatchTimeOut`/`dispatchIncoming(GetResponse)` executes `.call()` against the codeless `from` address, which returns `success = true`.
4. `_requestCommitments[commitment]` is permanently deleted and `meta.fee`/relayer reward is paid out, while no application-side refund/settlement logic ever ran — any escrowed value tied to that commitment is now unrecoverable, and the event log falsely shows `PostRequestTimeoutHandled`/`GetRequestHandled`.

    function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
        address destination = _bytesToAddress(request.to);
        uint256 size;
        assembly {
            size := extcodesize(destination)
        }
        if (size == 0) {
            // instead of reverting the entire batch, early return here.
            return;
        }

        // replay protection
        bytes32 commitment = request.hash();
        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)
            .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));

        if (!success) {
            // so that it can be retried
            delete _requestReceipts[commitment];
            return;
        }
        emit PostRequestHandled({commitment: commitment, relayer: relayer});
