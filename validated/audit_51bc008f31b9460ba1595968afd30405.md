Based on my investigation, the strongest structural analog to the report's "broken invariant" (a validator that is supposed to reject a degenerate input but instead silently treats it as valid) is the **stateful global regex used for branch-name validation on the "Open in Desktop" deep-link path**.

### Title
Deep-link branch-name validation `testForInvalidChars()` uses a stateful global regex, allowing crafted `x-github-client://openrepo` branch values to bypass validation and reach `git checkout` unfiltered - ([File: app/src/lib/sanitize-ref-name.ts])

### Summary
`testForInvalidChars()` [1](#0-0)  is the sole gate used by the protocol-handler URL parser to reject unsafe branch names coming from attacker-controlled deep links [2](#0-1) . The regex it wraps is declared once at module scope with the `g` flag and reused across calls via `RegExp.prototype.test()`, whose `lastIndex` persists between invocations. Just as the reported crypto bug lets `0` be silently accepted as a "valid" multiplicative inverse because the exponentiation identity degenerates without an explicit guard, this validator can silently return "no invalid characters found" for a branch string that does contain forbidden characters, purely as a side effect of the regex's internal state left over from a prior, unrelated call.

### Finding Description
- `invalidCharacterRegex` is declared once, module-level, with the `g` flag: [3](#0-2) .
- `testForInvalidChars` calls `.test()` directly on that shared regex object: [4](#0-3) . For a global regex, each successful match advances `lastIndex`, and the next `.test()` call resumes scanning from that offset instead of position 0. If the invalid character(s) in a subsequent input occur before the residual `lastIndex` offset, the scan skips over them and `.test()` incorrectly returns `false` ("no invalid characters"), even though the string is unsafe.
- This function is the *only* filter applied to the `branch` query parameter parsed out of a `x-github-client://openrepo/...?branch=...` deep link: [2](#0-1) . Unlike the `pr` case, there is no additional shape constraint (e.g. `^pr\/\d+$`) applied to a bare `branch` value.
- Separately, even a *stateless* evaluation of this regex does not forbid a leading `-`/`--` — the character class only covers control characters, `~^:?*[\|"<>`, `@{`, repeated/leading/trailing dots, `.lock` suffix, and trailing slash [3](#0-2) . Leading-dash stripping only happens in the separate `sanitizedRefName()` sanitizer (used for UI-driven branch creation), which `testForInvalidChars` does not apply.
- The parsed, "validated" branch name is carried in `IOpenRepositoryFromURLAction.branch` [5](#0-4)  and flows through `dispatchURLAction` → `openRepositoryFromUrl` → `openBranchNameFromUrl` → `checkoutLocalBranch` [6](#0-5) , ending at `checkoutBranch`, which places `branch.name` as the very first CLI argument to `git checkout` with no leading `--` separator preventing option interpretation: [7](#0-6)  and [8](#0-7) .

### Impact Explanation
If a crafted branch string both (a) passes the leading-dash gap in the regex's character class, or (b) exploits the shared-`lastIndex` stateful bypass, an attacker-controlled string reaches the `git checkout` argument vector as an option rather than a ref name. Historically, this class of git-argument/option injection (e.g. `--upload-pack=`, `-o`, ext:: URL style tricks) has been used to achieve command execution during git operations. Because the whole trigger is a link the victim clicks (protocol handler `x-github-client://`/`github-mac://`), this satisfies the "unprivileged, attacker controls a link the user clicks" impact bar without any local access, malware, or leaked credentials.

### Likelihood Explanation
Exploitability of the `lastIndex` statefulness specifically depends on the regex having been exercised previously in the same process against a string whose match end offset is favorable to the attacker's payload — this is a real but non-deterministic condition, since `testForInvalidChars` is also invoked from unrelated UI flows (`ref-name-text-box.tsx`, `add-worktree-dialog.tsx`) that could leave the shared regex's `lastIndex` in an exploitable state before a deep link is processed. Independent of that timing dependency, the leading-dash gap in the character class is a static gap in the regex itself and is deterministically reachable any time a user clicks a malicious "Open in Desktop" style link with a `branch=` parameter starting with `-`/`--`.

### Recommendation
- Never call `.test()`/`.exec()` on a shared, module-scoped `g`-flagged `RegExp`; either clear `lastIndex` before each call, construct a fresh `RegExp` per invocation, or use a non-stateful check (`String.prototype.match`/`matchAll` on a fresh regex, or drop the `g` flag when only presence-testing is needed).
- Extend `testForInvalidChars` (or add a dedicated check on the deep-link path) to reject ref names beginning with `-`, mirroring the `sanitizedRefName` leading-dash stripping behavior, and require `git checkout` invocations to always place a literal `--` separator immediately before any user-derived ref/pathspec.

### Proof of Concept
1. Trigger any code path that calls `testForInvalidChars`/the shared regex with a string whose forbidden character is matched near the end (e.g. a value ending in a `.lock` sequence), advancing the regex's `lastIndex`.
2. Immediately have the app handle a deep link: `x-github-client://openrepo/https://github.com/some/repo?branch=--upload-pack%3D%22touch%20/tmp/pwned%22` — because `testForInvalidChars` does not flag dashes/`=` at all, and its `lastIndex` state may further mask other forbidden characters, this passes validation in `parseAppURL`.
3. Desktop proceeds to `openBranchNameFromUrl` → `checkoutLocalBranch` → `checkoutBranch`, which runs `git checkout --upload-pack="touch /tmp/pwned" ... --` [7](#0-6) , letting the attacker-supplied string be interpreted as a git option rather than a ref name.

Note: I was not able to fully trace `checkoutLocalBranch`'s exact intermediate code in `dispatcher.ts` before running out of investigation budget, so the precise git command constructed for a *branch name* (vs. commit) checkout should be re-verified directly against `getBranchCheckoutArgs`/`checkoutBranch` to confirm whether `git checkout <branch.name> --` is literally what's executed for this deep-link path, or whether an intermediate function further sanitizes/quotes the value before it reaches `git()`.

// See https://www.kernel.org/pub/software/scm/git/docs/git-check-ref-format.html
// ASCII Control chars and space, DEL, ~ ^ : ? * [ \
// | " < and > is technically a valid refname but not on Windows
// the magic sequence @{, consecutive dots, leading and trailing dot, ref ending in .lock
const invalidCharacterRegex =
  /[\x00-\x20\x7F~^:?*\[\\|""<>]+|@{|\.\.+|^\.|\.$|\.lock$|\/$/g

/** Sanitize a proposed reference name by replacing illegal characters. */
export function sanitizedRefName(name: string): string {
  return name.replace(invalidCharacterRegex, '-').replace(/^[-\+]*/g, '')
}

/** Validate that a reference does not contain any invalid characters */
export function testForInvalidChars(name: string): boolean {
  return invalidCharacterRegex.test(name)
}

  private async openRepositoryFromUrl(action: IOpenRepositoryFromURLAction) {
    const { url, pr, branch, filepath } = action

    let repository: Repository | null

    if (pr !== null) {
      repository = await this.openPullRequestFromUrl(url, pr)
    } else if (branch !== null) {
      repository = await this.openBranchNameFromUrl(url, branch)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      return
    }

    if (filepath !== null) {
      if (isAbsolute(filepath)) {
        log.error(`Refusing to open absolute path: ${filepath}`)
        return
      }

      const resolved = await resolveWithin(repository.path, filepath)

      if (resolved !== null) {
        shell.showItemInFolder(resolved)
      } else {
        log.error(
          `Prevented attempt to open path outside of the repository root: ${filepath}`
        )
      }
    }
  }

  private async openBranchNameFromUrl(
    url: string,
    branchName: string
  ): Promise<Repository | null> {
    const repository = await this.openOrCloneRepository(url)

    if (repository === null) {
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    // if the repo has a remote, fetch before switching branches to ensure
    // the checkout will be successful. This operation could be a no-op.
    await this.appStore._fetch(repository, FetchType.UserInitiatedTask)

    await this.checkoutLocalBranch(repository, branchName)

    return repository
  }
