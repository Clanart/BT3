### Title
Attacker-supplied `ReceivedOutput` lets the multisig sign a Taproot sighash over fabricated prevout data — ([File: networks/bitcoin/src/wallet/send.rs](networks/bitcoin/src/wallet/send.rs))

### Summary
The reported bug class is trusting a "spot" value read directly from attacker-influenceable state (a pool's `globalState()` price) instead of a value bound to committed/accumulated data. In Serai, the same shape exists in the Bitcoin wallet: `SignableTransaction::new` consumes `ReceivedOutput`s — which can be deserialized from untrusted bytes via `ReceivedOutput::read` — and treats the embedded `TxOut` (value and `script_pubkey`) as ground truth for the prevouts committed to by the BIP-341 key-spend sighash (`Prevouts::All`). Nothing ever verifies that the claimed `TxOut` matches the actual UTXO at `outpoint`, nor that `script_pubkey` equals `p2tr_script_buf(key + G*offset)`. The FROST sign machines then sign a sighash committing to the fabricated prevout set.

### Finding Description
`ReceivedOutput::read` (`networks/bitcoin/src/wallet/mod.rs:122-134`) deserializes an arbitrary `offset`, an arbitrary `TxOut`, and an arbitrary `OutPoint` from raw bytes with no consistency checks. `SignableTransaction::new` (`send.rs:150-255`) then:

- takes `input.output.value.to_sat()` as the input amount for `input_sat` and the `NotEnoughFunds` check (`send.rs:175`, `send.rs:215`),
- computes change as `input_sat - payment_sat - fee_with_change` (`send.rs:228-234`),
- stores `input.output` verbatim into `prevouts` (`send.rs:253`).

At signing time, `TransactionSignMachine::sign` commits to all prevouts with `Prevouts::All(&self.tx.prevouts)` and calls `taproot_key_spend_signature_hash(i, &prevouts, TapSighashType::Default)` (`send.rs:373-390`). Under BIP-341, the sighash commits to every prevout's `script_pubkey` and `amount`. A forged `ReceivedOutput` therefore causes each honest participant's `sign_share` to produce a share for a message that commits to attacker-chosen prevout values/scripts — a message the group never intended to sign.

The analogous failure to the oracle bug: the actual UTXO's script and amount are the "accumulated"/consensus-committed truth; the bytes inside `ReceivedOutput` are a manipulable snapshot that the code treats as authoritative, exactly like reading `globalState().sqrtPriceX96` instead of a timepoint accumulator.

### Impact Explanation
An unprivileged party who can feed bytes to `ReceivedOutput::read` (or otherwise inject a `ReceivedOutput` into the input list) causes the threshold group to produce a signature that is consensus-invalid — the committed prevout amounts/scripts do not match the real UTXOs, so the transaction can never be mined. Every signing attempt on such a plan consumes the participants' single-use FROST preprocesses/nonces on a dead message, permanently stalling the associated plan/eventuality (`Eventuality(signable.txid())` in `processor/src/networks/bitcoin.rs:830` waits on a txid that can never confirm). If the forged `TxOut` inflates the input value, the fabricated change output and fee math further cause the group to sign a transaction spending funds it does not have. This is an unintended-message signing / unspendable-funds impact, not merely informational.

### Likelihood Explanation
Triggering only requires getting a crafted `ReceivedOutput` into `SignableTransaction::new`; the format is a public serialization (`offset || TxOut || OutPoint`) and the library exposes `read`/`serialize` round-trips for transport. However, exploitation requires a caller that accepts externally supplied `ReceivedOutput`s rather than only outputs produced by its own `Scanner`, and the result is a non-confirming transaction rather than direct theft — hence Medium likelihood.

### Recommendation
Verify, inside `SignableTransaction::new` or `multisig`, that each `ReceivedOutput` is internally consistent with the signing key: check `output.script_pubkey == p2tr_script_buf(key + GENERATOR * offset)` so a forged `TxOut`/`offset` pair cannot be bound into the sighash. Ideally, authenticate the prevout against the chain (the outpoint's real `TxOut`) before signing, rather than trusting deserialized bytes — the equivalent of using the accumulated timepoint data instead of spot state.

### Proof of Concept
```rust
// Attacker crafts bytes: real outpoint of a multisig UTXO,
// but a TxOut with an inflated value (or any script_pubkey).
let mut forged = Vec::new();
forged.extend(offset_scalar.to_bytes());           // e.g. Scalar::ZERO
forged.extend(serialize(&TxOut {
    value: Amount::from_sat(1_000_000_000),        // fabricated; real UTXO is 100_000
    script_pubkey: honest_p2tr_script.clone(),
}));
forged.extend(serialize(&real_outpoint));

let ro = ReceivedOutput::read(&mut forged.as_slice()).unwrap();

// NotEnoughFunds passes because input_sat uses the forged value.
let tx = SignableTransaction::new(vec![ro], &payments, Some(change), None, fee).unwrap();
// change output is inflated: 1_000_000_000 - payments - fee
// Each participant's sign_share signs a BIP-341 sighash committing to the fake
// prevout amount via Prevouts::All -> resulting signature is consensus-invalid,
// the eventuality txid never confirms, and the preprocesses are burned.
```
