## Finding [1](#0-0) 

### Title
Live re-derivation of mutable asset decimals lets a registered token's owner mint unbacked tokens on ISMP timeout refund - (File: `modules/pallets/hyper-fungible-token/src/module.rs`)

### Summary
The `hyper-fungible-token` pallet locks in an ERC20-denominated amount at `send()` time by converting the local balance using the *current* value of `<T::Assets as fungibles::metadata::Inspect>::decimals(asset_id)`, but this decimals value is not committed anywhere in the dispatched ISMP message. Both `on_accept` and `on_timeout` re-query the *live* decimals from `pallet-assets` metadata when converting the encoded ERC20 amount back to a local balance. Since `pallet-assets` metadata (including `decimals`) can be changed at any time by the asset's `Owner` via `set_metadata` — a role entirely outside this pallet's own `CreateOrigin` governance — a registered token's owner can inflate the decimals between `send()` and the corresponding `on_timeout`, causing the refund to mint far more tokens than were originally burned/escrowed.

### Finding Description
`send()` computes the wire amount using decimals fetched at call time: [2](#0-1) 

That `erc20_amount` (in `Message.amount`) is the only value carried in the cross-chain request body; the local decimals value used to compute it is *not* persisted alongside the request.

On timeout, the pallet decodes the same `message.amount` and converts it back to a local balance using decimals fetched live, at refund time: [3](#0-2) 

The conversion helpers are:
```
convert_to_erc20(value, erc_decimals, local_decimals) = value * 10^(erc_decimals - local_decimals)
convert_to_balance(value, erc_decimals, local_decimals) = value / 10^(erc_decimals - local_decimals)
``` [4](#0-3) 

If local decimals at send time is `D1` and at timeout time is `D2`, the refunded amount becomes `local_amount * 10^(D2 - D1)`. Increasing `D2` relative to `D1` inflates the refund arbitrarily (bounded only by `erc_decimals`).

The `ErcDecimalsBelowLocal` check only validates `erc_decimals >= local_decimals` at `register_token`/`update_token` time — it is never re-checked against the live, mutable metadata decimals used inside `on_accept`/`on_timeout`: [5](#0-4) 

For non-native (bridged/mint-burn) assets, the refund path calls `Assets::mint_into`, so an inflated refund amount is freshly minted tokens, not a redistribution of already-escrowed funds: [6](#0-5) 

Nothing in the `on_timeout`/`on_accept` flow requires the asset's `pallet-assets` `Owner` to be the same account as `T::CreateOrigin` that registered/updated the token in this pallet, so this is a permission mismatch: this pallet trusts a value it does not control.

### Impact Explanation
An entity that owns (or later obtains ownership of, e.g. via a token migration/handover) the underlying `pallet-assets` asset registered in `hyper-fungible-token` can mint unbacked tokens by manipulating `decimals` metadata between dispatch and timeout of their own cross-chain transfer. This is unauthorized minting / loss of backing for a bridged asset — directly matching the bounty's "stealing or loss of funds" / "false state acceptance leading to fund creation" impact class, since the pallet accepts a corrupted local decimals value as truth when settling the timeout.

### Likelihood Explanation
The attacker only needs: (1) to be the `Owner` of a `pallet-assets` asset that has been registered as non-native in `hyper-fungible-token` (a realistic setup for any project that self-registers and retains asset ownership), (2) to call `send()` with a short/attacker-chosen `timeout` targeting an address/contract that will not accept the message before expiry, and (3) to call `pallet_assets::set_metadata` to raise `decimals` before the timeout message is processed. All of these are ordinary, unprivileged (from this pallet's perspective) operations requiring no compromised relayer, prover, or Hyperbridge governance key.

### Recommendation
Persist the local decimals (and/or the already-computed local balance) used at `send()` time as part of the request context (e.g. in a `PendingTransfers` storage map keyed by commitment, or by encoding it into the dispatched message itself), and use that committed value — not a live re-query of mutable `pallet-assets` metadata — when reconciling `on_accept`/`on_timeout`. Alternatively, snapshot `Precisions`/local decimals into an immutable per-registration value that cannot change without invalidating in-flight requests, and reject metadata decimal changes for assets with outstanding un-settled requests.

### Proof of Concept
1. Runtime has `pallet-assets` asset `X` (owner = Alice) registered via `register_token` as `native: false`, `erc_decimals = 18`, current metadata `decimals = 6`.
2. Alice calls `send(asset_id=X, amount=1000, destination=Chain, timeout=short, ...)`. Pallet burns 1000 units of `X` from Alice and dispatches `Message.amount = 1000 * 10^(18-6) = 1e15`.
3. Alice deliberately targets a destination/timeout combination that guarantees the request expires undelivered.
4. Before the timeout message is processed, Alice calls `pallet_assets::set_metadata(X, decimals=18)`.
5. Anyone submits the ISMP timeout proof; `on_timeout` computes `refund = 1e15 / 10^(18-18) = 1e15` — Alice receives `1e15` units of `X` minted to her, versus the `1000` she originally burned, a 10^12x inflation of unbacked supply.

/// Converts an ERC20 U256 amount to a local balance type
///
/// Divides by 10^(erc_decimals - local_decimals) to scale down from ERC20 precision.
/// The target type must implement `FromStr`.
pub fn convert_to_balance<B: core::str::FromStr>(
	value: U256,
	erc_decimals: u8,
	local_decimals: u8,
) -> Result<B, B::Err> {
	let dec_str = (value /
		U256::from(10u128.pow(erc_decimals.saturating_sub(local_decimals) as u32)))
	.to_string();
	dec_str.parse::<B>()
}

/// Converts a local u128 balance to an ERC20 U256 amount
///
/// Multiplies by 10^(erc_decimals - local_decimals) to scale up to ERC20 precision
pub fn convert_to_erc20(value: u128, erc_decimals: u8, local_decimals: u8) -> U256 {
	U256::from(value) * U256::from(10u128.pow(erc_decimals.saturating_sub(local_decimals) as u32))
