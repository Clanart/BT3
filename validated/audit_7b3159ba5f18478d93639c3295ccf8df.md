### Title
Payout transaction's operator-attribution OP_RETURN output is unsigned, allowing anyone to malleate mempool payouts and misattribute reimbursement credit - (File: `core/src/builder/transaction/operator_reimburse.rs`)

### Summary
The `payout_tx` created by `create_payout_txhandler` embeds the fronting operator's x-only pubkey in an `OP_RETURN` output that is used later, chain-wide, as the sole source of truth for "who paid this withdrawal and therefore who gets reimbursed." The only signature on this transaction (the user's) is a Taproot key-spend signature using the `SIGHASH_SINGLE | SIGHASH_ANYONECANPAY` sighash type, which commits only to input 0 and the output at the same index (index 0, the user payout). The anchor output and, critically, the `OP_RETURN` operator-attribution output are outside the signed commitment. Any party that observes the broadcast-but-unconfirmed payout transaction can therefore replace it with a variant carrying an arbitrary operator xonly pubkey in the `OP_RETURN`, breaking the "operator credited" vs "party that actually paid" binding relied upon by the reimbursement pipeline.

### Finding Description
`create_payout_txhandler` builds a transaction with:
- input 0: the user's withdrawal UTXO, spent via `SpendPath::KeySpend` with only the user's signature,
- output 0: the user's payout,
- output 1: an anchor output,
- output 2: an `OP_RETURN` containing the fronting operator's x-only pubkey. [1](#0-0) 

`Operator::withdraw` verifies the user's signature against the sighash of only input 0: [2](#0-1) 

The accompanying comment explicitly documents the sighash type as `SinglePlusAnyoneCanPay`. Under BIP341, `SIGHASH_SINGLE` commits only to the output at the same index as the signed input (index 0), and `SIGHASH_ANYONECANPAY` removes any commitment to other inputs. Consequently, output 1 (anchor) and output 2 (`OP_RETURN` operator attribution) are not covered by the user's signature at all. After building this transaction, the operator funds and broadcasts it itself via Bitcoin Core RPC: [3](#0-2) 

While the transaction sits unconfirmed in the public Bitcoin mempool (any RBF-capable, standard broadcast), any unprivileged observer can construct a new transaction that:
- re-uses the exact same input 0 and witness (unchanged, since it is fully signed and immutable),
- keeps output 0 identical (still covered by `SIGHASH_SINGLE`),
- freely substitutes/adds fee-paying inputs (allowed by `ANYONECANPAY`),
- freely rewrites the `OP_RETURN` output (index 2) to declare an arbitrary operator xonly pubkey as the payer,

and replace-by-fee the original broadcast transaction, since none of these mutated fields are covered by the taproot signature.

This attribution is subsequently trusted verbatim by the protocol. `update_finalized_payouts` parses the mined payout transaction's `OP_RETURN` and stores whichever xonly pubkey is present as `payout_payer_operator_xonly_pk`: [4](#0-3) 

This value is later used to gate which operator is deemed to have paid, and hence which operator is entitled to reimbursement, in:
- `validate_payer_is_operator`, which errors for the true payer if the credited pubkey does not match: [5](#0-4) 
- `send_asserts`, which requires the payout OP_RETURN pubkey to equal the kickoff's operator pubkey before proceeding: [6](#0-5) 
- `is_kickoff_malicious`, which treats a mismatched OP_RETURN pubkey as grounds to flag/punish a kickoff: [7](#0-6) 
- `PayoutCheckerTask`, which drives the reimbursement flow strictly by `payout_payer_operator_xonly_pk`: [8](#0-7) 

### Impact Explanation
This breaks the binding "the operator credited" == "the party that paid." Because attribution is read purely from an unsigned `OP_RETURN` field:
- The operator who actually fronted the withdrawal (funded the payout, paid on-chain fees) can be permanently locked out of reimbursement, because `validate_payer_is_operator`/`send_asserts` will reject them once a different pubkey is recorded as payer — this matches the Critical impact "an honest operator permanently unable to be reimbursed."
- A different operator (attacker-controlled or targeted) can be credited as payer without having funded anything, and can subsequently attempt the kickoff/reimburse flow for a payout they never made — this matches the Critical impact "an operator reimbursed for a payout it never funded."

The mutation requires no privileged role — any party able to observe the mempool and broadcast a competing (RBF) transaction can perform it; it needs no verifier/operator/aggregator key or database access.

### Likelihood Explanation
Likelihood is moderate-to-high: the payout transaction is broadcast to the public Bitcoin network by the operator itself and is unconfirmed for at least one block interval, during which any mempool-observing party (miners, relay nodes, or simple RPC watchers) can craft and rebroadcast a fee-bumped conflicting transaction, since `SIGHASH_SINGLE|ANYONECANPAY` leaves the operator-attribution output entirely unauthenticated. No cryptographic secret or elevated role is required — only mempool visibility and the ability to pay a marginally higher fee.

### Recommendation
Bind the operator-attribution `OP_RETURN` output (and ideally the anchor output) to the user's signature, e.g. by using `SIGHASH_ALL` (or a custom scheme that hashes all outputs) instead of `SIGHASH_SINGLE|ANYONECANPAY` for the payout transaction, or by having verifiers/aggregator co-sign a commitment to the operator pubkey that is independently verifiable (e.g., requiring the fronting operator to pre-register the exact payout txid/outputs before broadcast so any malleated variant is rejected). At minimum, cross-check on-chain attribution against an off-chain, tamper-resistant record of which operator constructed and submitted the specific payout transaction before trusting the mined `OP_RETURN` value for reimbursement decisions.

### Proof of Concept
1. Operator A calls `Withdraw`/`InternalWithdraw`; `Operator::withdraw` builds and broadcasts `payout_tx` with `OP_RETURN` = Operator A's xonly pubkey, signed by the user under `SIGHASH_SINGLE|SIGHASH_ANYONECANPAY` (only input 0 and output 0 are committed) — see `create_payout_txhandler` and `Operator::withdraw` (`operator_reimburse.rs:407-436`, `operator.rs:620-691`).
2. Attacker watches the Bitcoin mempool, extracts the unconfirmed `payout_tx`.
3. Attacker builds `payout_tx'` that: reuses input 0 with the identical (still valid) witness, keeps output 0 unchanged, adds its own fee-paying input(s) (allowed by `ANYONECANPAY`), and replaces output 2's `OP_RETURN` with Operator B's xonly pubkey (or removes it).
4. Attacker broadcasts `payout_tx'` with a higher fee, triggering RBF replacement; `payout_tx'` confirms instead of `payout_tx`.
5. `update_finalized_payouts` reads the mined `payout_tx'`, extracts Operator B's pubkey from the `OP_RETURN`, and stores it as `payout_payer_operator_xonly_pk` (`verifier.rs:2312-2350`).
6. Operator A's later `get_reimbursement_txs`/`validate_payer_is_operator` call fails because the recorded payer no longer matches Operator A (`operator.rs:1703-1729`), permanently denying Operator A reimbursement for a withdrawal it actually funded, while Operator B (or nobody) is now recorded as the payer of record.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
