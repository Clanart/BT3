### Title
Auction bid parameters (gas buffer, auctioneer, entry-point version) are snapshotted once per block but remain valid for bids targeting up to 2 future blocks, making settlement unpredictable if governance changes them mid-window - (File: kaiax/auction/impl/execution.go, kaiax/auction/impl/bid_pool.go)

### Summary
The auction module caches `auctioneer`, `auctionEntryPoint`, `auctionEntryPointVersion`, and `bidTxGasBuffer` once per inserted block (`updateAuctionInfo`), and this single snapshot is used to validate and construct signed bids that may target the current block plus up to `allowFutureBlock` (2) blocks ahead. If any of these on-chain parameters change during that window (e.g., via `changeGasParameters`, `changeAuctioneer`, or an entry-point version upgrade), bids that were validated/signed against the old snapshot can be executed against a different live configuration, producing unpredictable settlement outcomes — the same bug class as the Bancor formula being changeable mid-batch.

### Finding Description
`PostInsertBlock` refreshes the bid pool's auction parameters exactly once, from the state at the block that was just inserted: [1](#0-0) 

`updateAuctionInfo` reads `auctioneer`, `auctionEntryPointAddr`, `bidTxGasBuffer`, and `auctionEntryPointVersion` from the state at block `num` and pushes them into the bid pool via `bidPool.updateAuctionInfo(...)`: [2](#0-1) 

These cached values are then used to (a) validate/verify a bid's EIP-712 signature, and (b) compute the bid transaction's gas limit, using the cached `auctionEntryPointVersion` and `bidTxGasBuffer`: [3](#0-2) 

Crucially, `validateBid` accepts bids for any `blockNumber` in `[currentBlockNumber+1, currentBlockNumber+allowFutureBlock]`, i.e., up to two blocks beyond the block whose state produced the current cached auction parameters: [4](#0-3) 

Because the cache is only refreshed on `PostInsertBlock` (one snapshot per block), a searcher's bid — signed and gas-limited according to the auctioneer/version/gasBuffer as of block N — can be scheduled for execution at block N+2. If a governance/owner transaction changes `gasBufferEstimate`, `auctioneer`, or the entry point version in block N+1 (which is entirely plausible since these are exposed as owner-controlled setters, e.g. `changeGasParameters`/`changeAuctioneer` seen in the auction contract bindings), the bid pool only detects and reacts to that change when block N+1 is inserted, clearing/rebuilding the pool. Any bid already accepted and propagated for block N+2 under the old parameters is now inconsistent with the parameters actually in force at execution time — mirroring exactly the reported Bancor issue where a formula (pricing rule) could be swapped mid-batch, making the batch's execution unpredictable relative to what participants signed up for. [5](#0-4) 

### Impact Explanation
An auction bidder submits a bid that is accepted and gas-limited based on stale auction parameters. If the entry point's live `gasBufferEstimate` or EIP-712 `AUCTION_VERSION` diverges from what was cached when the bid was validated/signed, the resulting on-chain auction settlement (bid win determination, signature verification, gas accounting inside `AuctionEntryPoint.call`) can behave unpredictably relative to the searcher's/auctioneer's expectations — analogous to the Bancor case where the price used to settle a batch could differ from what was expected when orders were placed. This can lead to bid settlement failures or execution against unintended parameters for legitimate, already-signed bids in the up-to-two-block validity window.

### Likelihood Explanation
Reaching this requires only: (1) a governance/owner-authorized change to the `AuctionEntryPoint`'s gas parameters, auctioneer, or version (a normal, expected operational action, not privileged-attacker-only from the searcher's perspective), and (2) a searcher submitting a bid for a block up to 2 blocks in the future via the public `auction_submitBid` RPC — both are within the reachable, unprivileged-sender / public-RPC-caller scope. The window is narrow (bounded by `allowFutureBlock = 2`), which limits but does not eliminate likelihood.

### Recommendation
Bind each bid to the specific auction parameter set (auctioneer, entry-point address/version, gas buffer) observed for its target block rather than a single most-recently-inserted-block snapshot shared across the entire `allowFutureBlock` window. Alternatively, re-validate/re-derive gas limits and signature parameters against the state of the bid's actual target block immediately before inclusion, and reject/re-queue bids whose cached parameters no longer match the live parameters at the target block — similar to storing a parameter reference alongside the "batch" as done in the referenced Bancor fix.

### Proof of Concept
1. Auctioneer/owner calls `changeGasParameters` (or `changeAuctioneer`) on `AuctionEntryPoint` in block N+1 to change `gasBufferEstimate`.
2. Before this transaction lands, at block N a searcher submits `auction_submitBid` targeting block N+2; `BidPool.AddBid` validates and computes `bid.GasLimit` using `bidTxGasBuffer` cached from block N's state (`kaiax/auction/impl/bid_pool.go` `getBidTxGasLimit`).
3. Block N+1 is inserted; `PostInsertBlock` detects the new `gasBufferEstimate` and calls `bidPool.updateAuctionInfo`, which — per `TestBidPool_UpdateAuctionInfo_DifferentGasBufferEstimate` — clears the bid pool's `bidMap`/`bidTargetMap`/`bidWinnerMap` (`kaiax/auction/impl/bid_pool_test.go:500-548`), but this happens only after the searcher's bid (already broadcast/propagated as a signed bid transaction with the stale gas limit) may already be in flight in the network or included by another node's block builder for N+2, using parameters that no longer match the live contract state.

func (a *AuctionModule) PostInsertBlock(block *types.Block) error {
	if a.Downloader.Synchronising() || !a.ChainConfig.IsRandaoForkEnabled(block.Number()) {
		atomic.CompareAndSwapUint32(&a.bidPool.running, 1, 0)
		return nil
	}

	if !a.updateAuctionInfo(block.Number()) {
		logger.Debug("stop auction since auctioneer or auction entry point is not set")
		atomic.CompareAndSwapUint32(&a.bidPool.running, 1, 0)
		return nil
	}

	atomic.CompareAndSwapUint32(&a.bidPool.running, 0, 1)

	txHashMap := make(map[common.Hash]struct{})
	for _, tx := range block.Transactions() {
		txHashMap[tx.Hash()] = struct{}{}
	}
	a.bidPool.removeOldBids(block.Number().Uint64(), txHashMap)

	return nil
}

// updateAuctionInfo updates the auctioneer address and auction entry point address for the given block number.
// It expects the `num` is after Randao fork.
// It returns true if the non-zero auctioneer address and auction entry point address are set, otherwise false.
func (a *AuctionModule) updateAuctionInfo(num *big.Int) bool {
	auctioneer := common.Address{}
	auctionEntryPointAddr := common.Address{}
	auctionEntryPointVersion := ""
	bidTxGasBuffer := uint64(0)

	defer func() {
		a.bidPool.updateAuctionInfo(auctioneer, auctionEntryPointAddr, auctionEntryPointVersion, bidTxGasBuffer)
	}()

	header := a.Chain.GetHeaderByNumber(num.Uint64())
	if header == nil {
		return false
	}
	_, err := a.Chain.StateAt(header.Root)
	if err != nil {
		return false
	}

	backend := backends.NewBlockchainContractBackend(a.Chain, nil, nil)

	// 1. Read auction entry point address
	auctionEntryPointAddr, err = system.ReadActiveAddressFromRegistry(backend, system.AuctionEntryPointName, num)
	if err != nil {
		return false
	}

	if auctionEntryPointAddr == (common.Address{}) {
		return false
	}

	// 2. Read auctioneer address
	auctioneer, err = system.ReadAuctioneer(backend, auctionEntryPointAddr, num)
	if err != nil {
		return false
	}

	if auctioneer == (common.Address{}) {
		return false
	}

	// 3. Read gas buffer estimate
	bidTxGasBuffer, err = system.ReadGasBufferEstimate(backend, auctionEntryPointAddr, num)
	if err != nil {
		return false
	}

	// 4. Read AUCTION_VERSION to pick the right EIP-712 typehash and ABI for bids targeting this entry point.
	auctionEntryPointVersion, err = system.ReadAuctionVersion(backend, auctionEntryPointAddr, num)
	if err != nil {
		return false
	}

	return true
}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

func (bp *BidPool) getBidTxGasLimit(bid *auction.Bid) (uint64, error) {
	bp.auctionInfoMu.RLock()
	buffer := bp.bidTxGasBuffer
	bp.auctionInfoMu.RUnlock()

	data, err := system.EncodeAuctionCallData(bid, bp.auctionEntryPointVersion)
	if err != nil {
		return 0, err
	}

	rules := bp.ChainConfig.Rules(big.NewInt(int64(bid.BlockNumber)))
	intrinsicGas, err := types.IntrinsicGas(data, nil, nil, false, rules)
	if err != nil {
		return 0, err
	}
	floorDataGas := uint64(0)
	if rules.IsPrague {
		floorDataGas, err = blockchain.FloorDataGas(types.TxTypeEthereumDynamicFee, data, 0)
		if err != nil {
			return 0, err
		}
	}

	return max(intrinsicGas+bid.CallGasLimit+buffer, floorDataGas), nil
}

func TestBidPool_UpdateAuctionInfo_DifferentGasBufferEstimate(t *testing.T) {
	var (
		mockCtrl = gomock.NewController(t)
		chain    = chain_mock.NewMockBlockChain(mockCtrl)
	)
	defer mockCtrl.Finish()

	block := types.NewBlockWithHeader(&types.Header{Number: big.NewInt(1)})
	chain.EXPECT().CurrentBlock().Return(block).AnyTimes()

	pool := NewBidPool(testChainConfig, chain, &auction.AuctionConfig{MaxBidPoolSize: 1024})
	require.NotNil(t, pool)

	// Start the auction
	pool.start()
	atomic.StoreUint32(&pool.running, 1)
	defer pool.stop()
	pool.auctioneer = testAuctioneer
	pool.auctionEntryPoint = testAuctionEntryPoint
	pool.auctionEntryPointVersion = auction.AuctionVersionV2
	pool.bidTxGasBuffer = 180_000

	// Add some bids
	for _, bid := range testBids[:3] {
		hash, err := pool.AddBid(bid)
		require.NoError(t, err)
		assert.Equal(t, bid.Hash(), hash)

		// Verify bid was added correctly
		assert.Equal(t, bid, pool.bidMap[hash])
		assert.Equal(t, bid, pool.bidTargetMap[bid.BlockNumber][bid.TargetTxHash])
		assert.Contains(t, pool.bidWinnerMap[bid.BlockNumber], bid.Sender)
	}

	// Update auction info with same addresses
	pool.updateAuctionInfo(testAuctioneer, testAuctionEntryPoint, auction.AuctionVersionV2, 180_000)
	assert.NotEmpty(t, pool.bidTargetMap)
	assert.NotEmpty(t, pool.bidWinnerMap)
	assert.NotEmpty(t, pool.bidMap)

	// Update auction info with different gas buffer estimate
	pool.updateAuctionInfo(testAuctioneer, testAuctionEntryPoint, auction.AuctionVersionV2, 160_000)

	// Verify pool was cleared and addresses were updated
	assert.Empty(t, pool.bidTargetMap)
	assert.Empty(t, pool.bidWinnerMap)
	assert.Empty(t, pool.bidMap)
	assert.Equal(t, uint64(160_000), pool.bidTxGasBuffer)
}
