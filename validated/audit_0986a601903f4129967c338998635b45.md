### Title
Stale native-ERC20 `TokenPair` mapping is only invalidated lazily, allowing a redeployed contract at the same address to hijack escrowed Coin↔ERC20 conversions - (File: x/erc20/keeper/msg_server.go, x/erc20/keeper/token_pairs.go)

### Summary
This is the direct analog of the "follow a deleted profile" bug class: Cosmos EVM's `x/erc20` module identifies a native-ERC20 `TokenPair` solely by the ERC20 contract *address*, and only checks whether that address still "exists" (has code) at the moment a conversion message is processed, never eagerly when the contract is destroyed. If a contract at that address is destroyed and a different contract is later deployed to the exact same address (fully possible via `CREATE2`, which is enabled on this chain, or by any permissionless registrant), the stale `TokenPair` record continues to be treated as valid and is silently re-bound to the new, unrelated bytecode.

### Finding Description
The `TokenPair` identity used throughout `x/erc20` is `Erc20Address + "|" + Denom` [1](#0-0) , and lookups are done purely via `GetERC20Map`/`GetTokenPairID` keyed on the raw `common.Address` bytes [2](#0-1) .

The only place that ever detects a destroyed native-ERC20 contract and deletes its `TokenPair` is inside the `ConvertERC20`/`ConvertCoin` message handlers, and only as a side effect of someone invoking those messages: [3](#0-2) [4](#0-3) 

The check is:
```go
acc := k.evmKeeper.GetAccountWithoutBalance(ctx, pair.GetERC20Contract())
if acc == nil || !acc.HasCodeHash() {
    k.DeleteTokenPair(ctx, pair)
    ...
}
```
This is a code-existence check performed *at call time*, not an event-driven invalidation tied to the original contract's identity (e.g., its original codehash/deploy nonce). Between the time a native ERC20 contract self-destructs (via `x/vm/keeper/statedb.go`'s `DeleteAccount`, which fully removes the account, code, storage and auth account [5](#0-4) ) and the time any user next calls `ConvertERC20`/`ConvertCoin` for that pair, an attacker can deploy an entirely different contract to the very same address using `CREATE2` (deterministic address = f(deployer, salt, initcode); `CREATE2` is a supported, unrestricted opcode in this EVM, and preinstalled infra such as the `Create2` factory at `0x4e59...` exists precisely to enable this) [6](#0-5) .

Once new code exists at that address, `acc.HasCodeHash()` is true again, so the "self-destructed" branch is skipped entirely — the stale `TokenPair`, with its original `Denom` and `Enabled=true`, remains bound to the address and is treated by the protocol as still representing the same trusted native ERC20 asset, even though the code is now arbitrary and attacker-controlled.

This stale binding is exploited through `ConvertCoinNativeERC20`, which is invoked both from `ConvertCoin` and from the IBC receive/timeout/ack callbacks (`OnRecvPacket`, `ConvertCoinToERC20FromPacket`) whenever a user redeems previously-escrowed Coin back into "ERC20" form [7](#0-6) [8](#0-7) [9](#0-8) . The function:
1. Escrows (removes) the user's real Coin balance from their account into the module (`SendCoinsFromAccountToModule`),
2. Calls `transfer(receiver, amount)` on the token-pair's contract address via `CallEVM`,
3. Re-queries `BalanceOf` on that same address to "verify" the transfer succeeded,
4. Burns the escrowed Coins.

Because steps 2 and 3 both target the attacker-controlled redeployed contract, the attacker fully controls both the "transfer" outcome and the "balanceOf" check result, and can trivially make the invariant checks in `ConvertCoinNativeERC20` (lines 284-297) pass without any real value ever moving. The user's real Coin (representing genuinely escrowed value, possibly received over IBC from another chain) is irrevocably burned in step 4, while what they receive back is a balance entry in a contract with no real economic backing.

### Impact Explanation
This breaks the 1:1 accounting invariant between the native Coin representation and the ERC20 asset that the `x/erc20` token-pair mechanism is designed to preserve. It results in permanent, unauthorized loss/extraction of user-held Coin value with no corresponding real asset returned — matching the Critical impact class "permanent freezing, locking, theft, or unauthorized extraction of user funds ... or token-pair-backed balances." An attacker who controls (or can register, if `PermissionlessRegistration` is enabled) a native ERC20 contract, entices deposits (real conversions from ERC20 to Coin), destroys the contract, and redeploys hostile bytecode at the same address can cause any subsequent `ConvertCoin`/IBC-triggered redemption against that token pair to burn real Coins while returning worthless attacker-controlled tokens.

### Likelihood Explanation
Reaching this requires: (1) an ERC20 contract registered as a native `TokenPair` (owner-external) — reachable permissionlessly if `params.PermissionlessRegistration` is true, or otherwise via any governance-approved contract that an attacker can still influence to self-destruct if it contains a (possibly hidden/backdoored) selfdestruct path; (2) `CREATE2` redeployment to the same address, which is a standard, unrestricted EVM capability; (3) at least one legitimate user holding/creating Coin balance for that denom via IBC/registration flow before the swap. Given `CREATE2` support and the purely lazy/code-existence based re-validation, this is reachable without any privileged access, though it depends on token-pair registration policy (permissionless vs governance) which could not be fully confirmed from the available index (params default value lookup was inconclusive within the tool budget).

### Recommendation
Bind `TokenPair` validity to the contract's *identity*, not merely to "code present at this address": store and check the original contract's codehash (or a deployment nonce/creation marker) alongside the `TokenPair`, and invalidate/`DeleteTokenPair` immediately and unconditionally whenever the codehash at that address changes from what it was at pair registration — not only lazily at conversion time. Additionally, perform this invalidation check eagerly (e.g., as part of EVM `SelfDestruct`/state-transition hooks or at the start of every `ConvertCoinNativeERC20` call) rather than only within `ConvertERC20`/`ConvertCoin`'s success path, and consider rejecting IBC-triggered redemptions entirely if the stored codehash no longer matches.

### Proof of Concept
1. Attacker deploys `EvilToken` (compliant ERC20 with a hidden admin-only `kill()` that calls `selfdestruct`) via `CREATE2` from a `Deployer` contract at address `A`, using salt `S1`.
2. Attacker (or governance, if permissionless registration is off) registers `EvilToken` at `A` as a native `TokenPair` with denom `D` via `RegisterERC20` [10](#0-9) .
3. Victim converts real `EvilToken` balance into native Coin `D` via `ConvertERC20`, escrowing tokens at the module address and minting Coin `D` to the victim [11](#0-10) .
4. Attacker calls `kill()` → `EvilToken` self-destructs at `A`, wiping code/storage/balance via `DeleteAccount` [5](#0-4) .
5. Attacker uses the `Deployer` (still at its original address, unaffected) to `CREATE2` a new `FakeToken` with the same salt `S1` at the identical address `A`, whose `transfer`/`balanceOf` always report success/expected values regardless of real movement.
6. Victim (or attacker, having acquired the Coin `D`) calls `MsgConvertCoin` for denom `D`; since `acc.HasCodeHash()` is now true again, `DeleteTokenPair` is skipped, `ConvertCoinNativeERC20` runs against `FakeToken`, burns the victim's real Coin `D`, and the balance checks pass trivially against the attacker's own contract [7](#0-6) .
7. Victim's Coin `D` is permanently gone with no genuine underlying asset recovered.

func (k Keeper) convertERC20IntoCoinsForNativeToken(
	ctx sdk.Context,
	pair types.TokenPair,
	msg *types.MsgConvertERC20,
	receiver sdk.AccAddress,
	sender common.Address,
) (*types.MsgConvertERC20Response, error) {
	erc20 := contracts.ERC20MinterBurnerDecimalsContract.ABI
	contract := pair.GetERC20Contract()
	balanceCoin := k.bankKeeper.GetBalance(ctx, receiver, pair.Denom)
	balanceToken := k.BalanceOf(ctx, erc20, contract, types.ModuleAddress)
	if balanceToken == nil {
		return nil, sdkerrors.Wrap(types.ErrEVMCall, "failed to retrieve balance")
	}

	// Escrow tokens on module account
	transferData, err := erc20.Pack("transfer", types.ModuleAddress, msg.Amount.BigInt())
	if err != nil {
		return nil, err
	}

	res, err := k.evmKeeper.CallEVMWithData(ctx, sender, &contract, transferData, true, nil)
	if err != nil {
		return nil, err
	}

	// Check evm call response
	var unpackedRet types.ERC20BoolResponse
	if len(res.Ret) == 0 {
		// if the token does not return a value, check for the transfer event in logs
		if err := validateTransferEventExists(res.Logs, contract); err != nil {
			return nil, err
		}
	} else {
		if err := erc20.UnpackIntoInterface(&unpackedRet, "transfer", res.Ret); err != nil {
			return nil, err
		}
		if !unpackedRet.Value {
			return nil, sdkerrors.Wrap(errortypes.ErrLogic, "failed to execute transfer")
		}
	}

	// Check expected escrow balance after transfer execution
	// NOTE: coin fields already validated in the ValidateBasic() of the message
	coins := sdk.Coins{sdk.Coin{Denom: pair.Denom, Amount: msg.Amount}}
	tokens := coins[0].Amount.BigInt()
	balanceTokenAfter := k.BalanceOf(ctx, erc20, contract, types.ModuleAddress)
	if balanceTokenAfter == nil {
		return nil, sdkerrors.Wrap(types.ErrEVMCall, "failed to retrieve balance")
	}

	expToken := big.NewInt(0).Add(balanceToken, tokens)

	if r := balanceTokenAfter.Cmp(expToken); r != 0 {
		return nil, sdkerrors.Wrapf(
			types.ErrBalanceInvariance,
			"invalid token balance - expected: %v, actual: %v",
			expToken, balanceTokenAfter,
		)
	}

	// Mint coins
	if err := k.bankKeeper.MintCoins(ctx, types.ModuleName, coins); err != nil {
		return nil, err
	}

	// Send minted coins to the receiver
	if err := k.bankKeeper.SendCoinsFromModuleToAccount(ctx, types.ModuleName, receiver, coins); err != nil {
		return nil, err
	}

	// Check expected receiver balance after transfer
	balanceCoinAfter := k.bankKeeper.GetBalance(ctx, receiver, pair.Denom)
	expCoin := balanceCoin.Add(coins[0])

	if ok := balanceCoinAfter.Equal(expCoin); !ok {
		return nil, sdkerrors.Wrapf(
			types.ErrBalanceInvariance,
			"invalid coin balance - expected: %v, actual: %v",
			expCoin, balanceCoinAfter,
		)
	}

	defer func() {
		telemetry.IncrCounterWithLabels(
			[]string{"tx", "msg", "convert", "erc20", "total"},
			1,
			[]metrics.Label{
				telemetry.NewLabel("coin", pair.Denom),
			},
		)

		if msg.Amount.IsInt64() {
			telemetry.IncrCounterWithLabels(
				[]string{"tx", "msg", "convert", "erc20", "amount", "total"},
				float32(msg.Amount.Int64()),
				[]metrics.Label{
					telemetry.NewLabel("denom", pair.Denom),
				},
			)
		}
	}()

	ctx.EventManager().EmitEvents(
		sdk.Events{
			sdk.NewEvent(
				types.EventTypeConvertERC20,
				sdk.NewAttribute(sdk.AttributeKeySender, msg.Sender),
				sdk.NewAttribute(types.AttributeKeyReceiver, msg.Receiver),
				sdk.NewAttribute(sdk.AttributeKeyAmount, msg.Amount.String()),
				sdk.NewAttribute(types.AttributeKeyCosmosCoin, pair.Denom),
				sdk.NewAttribute(types.AttributeKeyERC20Token, msg.ContractAddress),
			),
		},
	)

	return &types.MsgConvertERC20Response{}, nil
}

func (k Keeper) ConvertCoinNativeERC20(
	ctx sdk.Context,
	pair types.TokenPair,
	amount math.Int,
	receiver common.Address,
	sender sdk.AccAddress,
) error {
	if !amount.IsPositive() {
		return sdkerrors.Wrap(types.ErrNegativeToken, "converted coin amount must be positive")
	}

	erc20 := contracts.ERC20MinterBurnerDecimalsContract.ABI
	contract := pair.GetERC20Contract()

	balanceToken := k.BalanceOf(ctx, erc20, contract, receiver)
	if balanceToken == nil {
		return sdkerrors.Wrap(types.ErrEVMCall, "failed to retrieve balance")
	}

	// Escrow Coins on module account
	coins := sdk.Coins{{Denom: pair.Denom, Amount: amount}}
	if err := k.bankKeeper.SendCoinsFromAccountToModule(ctx, sender, types.ModuleName, coins); err != nil {
		return sdkerrors.Wrap(err, "failed to escrow coins")
	}

	// Unescrow Tokens and send to receiver
	res, err := k.evmKeeper.CallEVM(ctx, erc20, types.ModuleAddress, contract, true, nil, "transfer", receiver, amount.BigInt())
	if err != nil {
		return err
	}

	// Check unpackedRet execution
	var unpackedRet types.ERC20BoolResponse
	if len(res.Ret) == 0 {
		// if the token does not return a value, check for the transfer event in logs
		if err := validateTransferEventExists(res.Logs, contract); err != nil {
			return err
		}
	} else {
		if err := erc20.UnpackIntoInterface(&unpackedRet, "transfer", res.Ret); err != nil {
			return err
		}
		if !unpackedRet.Value {
			return sdkerrors.Wrap(errortypes.ErrLogic, "failed to execute unescrow tokens from user")
		}
	}

	// Check expected Receiver balance after transfer execution
	balanceTokenAfter := k.BalanceOf(ctx, erc20, contract, receiver)
	if balanceTokenAfter == nil {
		return sdkerrors.Wrap(types.ErrEVMCall, "failed to retrieve balance")
	}

	exp := big.NewInt(0).Add(balanceToken, amount.BigInt())

	if r := balanceTokenAfter.Cmp(exp); r != 0 {
		return sdkerrors.Wrapf(
			types.ErrBalanceInvariance,
			"invalid token balance - expected: %v, actual: %v", exp, balanceTokenAfter,
		)
	}

	// Burn escrowed Coins
	err = k.bankKeeper.BurnCoins(ctx, types.ModuleName, coins)
	if err != nil {
		return sdkerrors.Wrap(err, "failed to burn coins")
	}

	return nil
}

// RegisterERC20 implements the gRPC MsgServer interface. Any account can permissionlessly
// register a native ERC20 contract to map to a Cosmos Coin.
func (k *Keeper) RegisterERC20(goCtx context.Context, req *types.MsgRegisterERC20) (*types.MsgRegisterERC20Response, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	params := k.GetParams(ctx)

	if !params.PermissionlessRegistration {
		if err := k.validateAuthority(req.Signer); err != nil {
			return nil, err
		}
	}

	// Check if the conversion is globally enabled
	if !k.IsERC20Enabled(ctx) {
		return nil, types.ErrERC20Disabled.Wrap("registration is currently disabled by governance")
	}

	for _, addr := range req.Erc20Addresses {
		if !common.IsHexAddress(addr) {
			return nil, errortypes.ErrInvalidAddress.Wrapf("invalid ERC20 contract address: %s", addr)
		}

		pair, err := k.registerERC20(ctx, common.HexToAddress(addr))
		if err != nil {
			return nil, err
		}

		ctx.EventManager().EmitEvent(
			sdk.NewEvent(
				types.EventTypeRegisterERC20,
				sdk.NewAttribute(types.AttributeKeyCosmosCoin, pair.Denom),
				sdk.NewAttribute(types.AttributeKeyERC20Token, pair.Erc20Address),
			),
		)
	}

	return &types.MsgRegisterERC20Response{}, nil
}

// DeleteAccount handles contract's suicide call:
// - clear balance
// - remove code
// - remove states
// - remove the code hash
// - remove auth account
func (k *Keeper) DeleteAccount(ctx sdk.Context, addr common.Address) error {
	cosmosAddr := sdk.AccAddress(addr.Bytes())
	acct := k.accountKeeper.GetAccount(ctx, cosmosAddr)
	if acct == nil {
		return nil
	}

	// NOTE: only Ethereum contracts can be self-destructed
	if !k.IsContract(ctx, addr) {
		return errors.New("only smart contracts can be self-destructed")
	}

	// set account to a base account to set the whole balance as spendable
	baseAccount := k.accountKeeper.GetAccount(ctx, cosmosAddr)
	k.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(cosmosAddr, baseAccount.GetPubKey(), baseAccount.GetAccountNumber(), baseAccount.GetSequence()))

	// clear balance
	if err := k.SetBalance(ctx, addr, new(uint256.Int)); err != nil {
		return err
	}

	var keys []common.Hash

	// clear storage
	k.ForEachStorage(ctx, addr, func(key, _ common.Hash) bool {
		keys = append(keys, key)
		return true
	})

	for _, key := range keys {
		k.DeleteState(ctx, addr, key)
	}

	// clear code hash
	k.DeleteCodeHash(ctx, addr)

	// remove auth account
	k.accountKeeper.RemoveAccount(ctx, acct)

	k.Logger(ctx).Debug(
		"account suicided",
		"ethereum-address", addr.Hex(),
		"cosmos-address", cosmosAddr.String(),
	)

	return nil
}
