### Title
Transferring a PlotNFT without first claiming pending pool rewards permanently strands the accrued reward coins - (File: `chia/wallet/plotnft_wallet/plotnft_wallet.py`)

### Summary
`PlotNFT2Wallet.transfer_plotnft` re-keys the plot NFT singleton's `UserConfig` (owner synthetic pubkey) to a brand-new wallet fingerprint, but it does not check for or sweep any already-farmed, unclaimed pool-reward coins sitting at `p2_singleton_puzzle_hash` before doing so. [1](#0-0)  Once the singleton's owner key changes, those pending reward coins can no longer be swept using the previous owner's signature, mirroring the reported `TrufVesting.migrateUser` bug class where migrating an account's control leaves behind rewards that only the old, now-unusable, credential could claim.

### Finding Description
`PlotNFT.claim_pool_rewards` / `PlotNFT2Wallet.claim_rewards` requires a delegated puzzle signed under the *current* singleton inner puzzle (tied to `UserConfig.synthetic_pubkey`) to sweep unspent p2-singleton reward coins into the plot NFT's own coin. [2](#0-1)  `transfer_plotnft` builds a `new_user_config` from the *target* fingerprint's key and spends the plot NFT with `plotnft.new_user_config(...)`, updating the singleton's owner key/inner puzzle in a single transaction with no check for, or claiming of, outstanding pool rewards first. [3](#0-2) 

The test suite explicitly demonstrates that once a state-changing singleton spend happens while pool-reward coins are still unclaimed, those specific reward coins become unclaimable ("LOSE REWARDS") because `forward_pool_reward`/`claim_pool_rewards` puzzles are bound to the singleton state at the moment the rewards were farmed; advancing the singleton (via join/leave/self-pool/transfer) without sweeping first orphans them. [4](#0-3)  The same risk applies to `transfer_plotnft`: it advances (re-keys) the singleton exactly like the other state transitions, with no reward-sweep step, and unlike `join_pool`, there is no `ValueError` guard preventing the transfer while rewards are outstanding.

`p2_singleton_puzzle_hash` is derived purely from `plotnft_id` (the launcher id), not from the current owner key, so reward coins keep flowing to the same address across ownership changes. [5](#0-4)  But claiming those coins requires signing with the owner key active *at the time the claim spend is built* against the *current* singleton inner puzzle — after `transfer_plotnft` runs, that is the new fingerprint's key, and any rewards farmed/accrued under the old key's singleton state before the transfer are exposed to the same orphaning behavior confirmed by the "LOSE REWARDS" test.

### Impact Explanation
Unclaimed, already-farmed pool-reward XCH belonging to the plot NFT owner can be permanently stranded/unclaimable as a direct consequence of a normal wallet action (`plotnft transfer`), with no warning or guard in the code path. This is a concrete, spend-triggered loss of coin value for the calling wallet — the same "migrating owner forgets/loses the claimable tokens" bug class as the reported Truflation finding, adapted to Chia's plot-NFT/pool singleton architecture.

### Likelihood Explanation
Any user who runs `chia plotnft transfer` (RPC `plotnft_transfer` / `PlotNFT2Wallet.transfer_plotnft`) while pool rewards are pending unclaimed at the p2-singleton address (which the code and docstring explicitly acknowledge is a common expected operation for moving a plot NFT between one's own wallets) will trigger this loss. No malicious peer or privileged actor is required — it is triggered purely by the plot-NFT owner's own transfer action.

### Recommendation
In `transfer_plotnft`, check `wallet_state_manager.plotnft2_store.get_pool_rewards(plotnft_id=...)` before building the ownership-change spend; if unclaimed rewards exist, either automatically claim/forward them in the same transaction (chained before the `new_user_config` spend, similar to how `join_pool`/`leave_pool` compose flows), or raise a `ValueError` (as is already done for the "cannot claim while pooling" case) instructing the caller to claim rewards first.

### Proof of Concept
1. Create a plot NFT (`PlotNFT2Wallet.create_new`) and farm several blocks to `plotnft_wallet.p2_singleton_puzzle_hash` so unclaimed pool-reward coins accumulate (as done in the test's "RECEIVE REWARDS" step). [6](#0-5) 
2. Do not call `claim_rewards`; instead immediately call `transfer_plotnft(action_scope=..., target_wallet_fingerprint=<new_fingerprint>)`. [7](#0-6) 
3. After the transfer spend confirms, the plot NFT singleton's inner puzzle now requires the new fingerprint's key. Attempting `forward_pool_reward`/`claim_pool_rewards` for the pre-transfer reward coins with the old key's delegated puzzle fails, matching the orphaning behavior already demonstrated by the "LOSE REWARDS" sequence in the lifecycle test. [4](#0-3)

    async def claim_rewards(
        self,
        *,
        action_scope: WalletActionScope,
        fee: uint64 = uint64(0),
        extra_conditions: tuple[Condition, ...] = tuple(),
    ) -> None:
        rewards_to_claim = await self.wallet_state_manager.plotnft2_store.get_pool_rewards(plotnft_id=self.plotnft_id)
        if len(rewards_to_claim) == 0:
            raise ValueError("No rewards to claim")
        total_reward_amount = uint64(sum(reward.coin.amount for reward in rewards_to_claim))
        if fee > total_reward_amount:
            raise ValueError("Fee is greater than the total amount of rewards")

        plotnft = await self.get_current_plotnft()
        coin_spends = plotnft.claim_pool_rewards(
            rewards_to_claim=rewards_to_claim,
            reward_delegated_puzzles_and_solutions=[
                DelegatedPuzzleAndSolution(
                    puzzle=self.xch_wallet.make_solution(
                        primaries=[
                            CreateCoin(
                                puzzle_hash=self.rewards_claim_puzhash,
                                amount=uint64(total_reward_amount - fee),
                            ),
                        ],
                        fee=fee,
                        conditions=(*extra_conditions, CreateCoinAnnouncement(b""))
                        if len(rewards_to_claim) > 1
                        else extra_conditions,
                    ).at("rf"),  # strips away to just the delegated puzzle (bit of a hack)
                    solution=Program.to(None),
                )
                if i == 0
                else DelegatedPuzzleAndSolution(
                    puzzle=Program.to(
                        (
                            1,
                            [
                                AssertCoinAnnouncement(
                                    asserted_id=rewards_to_claim[0].coin.name(), asserted_msg=b""
                                ).to_program()
                            ],
                        )
                    ),
                    solution=Program.to(None),
                )
                for i, reward in enumerate(rewards_to_claim)
            ],
        )

    async def transfer_plotnft(
        self,
        *,
        action_scope: WalletActionScope,
        target_wallet_fingerprint: int,
        fee: uint64 = uint64(0),
        extra_conditions: tuple[Condition, ...] = tuple(),
    ) -> None:
        """
        Because the wallet doesn't have broad support for MIPS-style custody, transferring using addresses is
        a bit complicated because transferring to the wrong kind of address could leave the wallet unable to
        sync/spend the PlotNFT. As a guard, we implement this endpoint as a transfer between local keys to make
        sure that we generate the correct kind of inner puzzle.

        This is not necessarily a permanent restriction, but solves the primary use case of transferring between
        a user's own wallets and keeps the implementation relatively simple for now.
        """
        plotnft = await self.get_current_plotnft()
        fee_hook = CreateCoinAnnouncement(msg=b"", coin_id=plotnft.coin.name())
        root_pubkey = await self.wallet_state_manager.wallet_node.keychain_proxy.get_key_for_fingerprint(
            fingerprint=target_wallet_fingerprint, private=False
        )
        if root_pubkey is None:
            raise RuntimeError(f"Error retrieving key for fingerprint {target_wallet_fingerprint}")
        wallet_pubkey = master_pk_to_wallet_pk_unhardened(root_pubkey, index=uint32(0))
        synthetic_pubkey = self.xch_wallet.convert_public_key_to_synthetic(wallet_pubkey)
        hint = self.xch_wallet.puzzle_hash_for_pk(wallet_pubkey)
        new_user_config = UserConfig(synthetic_pubkey=synthetic_pubkey)
        coin_spends = plotnft.new_user_config(
            user_config=new_user_config,
            hint=hint,
            extra_conditions=(fee_hook, *extra_conditions),
        )
        if fee > 0:
            await self.xch_wallet.create_tandem_xch_tx(
                fee=fee,
                action_scope=action_scope,
                extra_conditions=(fee_hook.corresponding_assertion(),),
            )

        spend_bundle = WalletSpendBundle(coin_spends, G2Element())
