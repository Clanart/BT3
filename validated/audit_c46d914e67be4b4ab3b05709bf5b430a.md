### Title
Gasless swap commission-rate front-run allows the `GaslessSwapRouter` owner to skim user swap output - ([File: kaiax/gasless/impl/tx_pool.go])

### Summary
The KIP-247 gasless-swap flow lets a block proposer front-run a submitted `GaslessSwapTx` and increase `commissionRate` on the `GaslessSwapRouter` contract via its owner-only `updateCommissionRate` function immediately before executing the swap, thereby diverting a larger share of the swap output as `Commission` and reducing `FinalUserAmount`, without the pool's admission checks re-validating the commission rate the user implicitly assumed.

### Finding Description
`kaiax/gasless` promotes a `GaslessSwapTx` when `checkBalanceForSwap` passes. This function only validates `minAmountOut >= amountRepay`, that `amountIn` is sufficient for `minAmountOut` per the router's current exchange rate, that token allowance/balance are sufficient, and that the deadline has not passed [1](#0-0) . None of these checks reference or bound `commissionRate` from `GaslessSwapRouter`. The router itself exposes `updateCommissionRate(uint256 _commissionRate)` and emits `CommissionRateUpdated(oldRate, newRate)` [2](#0-1) [3](#0-2) , and `swapForGas` settlement emits `SwappedForGas(proposer, amountRepaid, user, finalUserAmount, commission)` where `commission` is deducted from the swap proceeds before `finalUserAmount` is credited to the user [4](#0-3) .

Since `GaslessSwapTx` is a plain legacy transaction sent to a public mempool/RPC and the swap parameters (`amountIn`, `minAmountOut`, `amountRepay`, `deadline`) are fixed at signing time [5](#0-4) , the contract owner (who could be the block proposer or coordinate with one) can observe a pending `GaslessSwapTx`, submit `updateCommissionRate` with a much higher rate, and have it included in the same or prior block so it executes before the swap. Because `minAmountOut` is checked against the DEX exchange rate only (not against the post-commission user payout), and `amountRepay` is a fixed value repaid to the lending proposer, raising the commission rate reduces `finalUserAmount` — the actual KAIA credited to the user — without failing any of the pool's admission checks. This mirrors the `DropEngineV2.setPrimarySaleFeeBps` front-run pattern: an owner-mutable fee percentage, applied at settlement time rather than validated against the value the counterparty expected when constructing their transaction.

### Impact Explanation
If exploited, the router owner (or a colluding block proposer) can silently redirect a large portion of a gasless-swap user's token proceeds to themselves as inflated "commission," directly reducing the KAIA amount a legitimate gasless-swap user receives, i.e., unauthorized value extraction/fee abuse in the gasless settlement path. This matches the accepted class of "fee or fee-delegation abuse" / "gasless...settlement theft."

### Likelihood Explanation
Likelihood is low-to-medium: it requires control of (or collusion with) the `GaslessSwapRouter` owner key and the ability to have the `updateCommissionRate` transaction land before the target `GaslessSwapTx` within the same block — feasible for a malicious/compromised owner who is also a block proposer, or via a simple front-running bundle, similar to the low-likelihood-but-high-impact characterization in the original report.

### Recommendation
- Cap `commissionRate` to a fixed sensible maximum in the router contract (as the original report recommends limiting `primarySaleFeeBps`), and/or add a timelock/delay before rate changes take effect.
- Have `kaiax/gasless`'s `checkBalanceForSwap` read the router's current `commissionRate` and require it to match (or not exceed) a rate that keeps `finalUserAmount` above a user-specified minimum, rather than only checking `minAmountOut` against the DEX quote.
- Alternatively, let `GaslessSwapTx` include an explicit maximum acceptable commission rate/expected `finalUserAmount`, and have the swap revert on-chain if the live commission rate exceeds that value at execution time.

### Proof of Concept
Conceptual PoC (cannot be fully executed without the router's Solidity source, which is not present in this repo — only compiled bindings in `contracts/bindings/kip247/GaslessSwapRouter.go` are available; deeper verification of the exact commission-application order requires that source or a Devin session with full repo access):
1. User signs and broadcasts `GaslessApproveTx` + `GaslessSwapTx` (`amountIn`, `minAmountOut`, `amountRepay`, `deadline`) per `kaiax/gasless` rules [6](#0-5) .
2. Router owner observes the pending swap and calls `updateCommissionRate(newHighRate)` [2](#0-1) , ensuring it is mined before the swap.
3. `swapForGas` executes with the elevated commission; `SwappedForGas` shows a much larger `Commission` and reduced `FinalUserAmount` than the user expected when signing, while all `kaiax/gasless` pool checks (`minAmountOut`, `amountIn`, allowance/balance, deadline) still pass [1](#0-0) .

// IsGaslessPattern checks following conditions:
// Ax. IsApproveTx conditions (if ApproveTx != nil)
// Sx. IsSwapTx conditions
// AP1. ApproveTx.from == SwapTx.from
// SP1. ApproveTx.to == SwapTx.token
// SP2. ApproveTx.amount >= SwapTx.amountIn
// SP3. ApproveTx.nonce+1 == SwapTx.nonce and Gasless transactions are head for nonce
// SP4. SwapTx.amountRepay = RepayAmount(ApproveTx, SwapTx)
func (g *GaslessModule) IsExecutable(approveTxOrNil, swapTx *types.Transaction) bool {
	err := g.VerifyExecutable(approveTxOrNil, swapTx)
	if err != nil {
		return false
	}
	return true
}

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}
