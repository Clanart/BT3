### Title
Unbounded recursive JSON/RLP expansion in `AccountKey` deserialization allows stack-overflow DoS via public RPC - ([File: blockchain/types/accountkey/account_key_role_based.go])

### Summary
`KaiaAPI.EncodeAccountKey` (exposed as the public `kaia_encodeAccountKey` RPC method) accepts a `accountkey.AccountKeyJSON` and recursively unmarshals it into a concrete `AccountKey` without any depth limit, mirroring the protobufjs `Root.fromJSON()`/`Namespace.addJSON()` unbounded-recursion bug class (CVE-2026-45740).

### Finding Description
The `AccountKeySerializer.UnmarshalJSON` method reads a `keyType` and a raw `key` field, constructs a concrete `AccountKey` via `NewAccountKey`, and then calls `json.Unmarshal(keyJSON.Key, serializer.key)` recursively: [1](#0-0) 

When the concrete type is `AccountKeyRoleBased`, its own `UnmarshalJSON` unmarshals a JSON array of `*AccountKeySerializer`, each of which can again itself be `AccountKeyTypeRoleBased`, recursing back into the same code path: [2](#0-1) 

`NewAccountKey` places no restriction on which `AccountKeyType` can be nested inside a `RoleBased` key at decode time — it simply dispatches on the type tag: [3](#0-2) 

The only guard against nested `RoleBased` keys (`checkAccountKeyZeroValues` returning `"roleBasedKey cannot contains a roleBasedKey as a role key"`, and `CheckInstallable`'s `IsCompositeType` check) runs **after** the full JSON tree has already been recursively unmarshalled: [4](#0-3) [5](#0-4) [6](#0-5) 

Because the rejection happens only after the fact, a sufficiently deeply nested JSON payload (e.g. `{"keyType":5,"key":[{"keyType":5,"key":[{"keyType":5,"key":[...]}]}]}`) will exhaust the Go goroutine call stack **during unmarshalling**, before validation ever executes. A Go stack-overflow ("goroutine stack exceeds ... limit") is a fatal, unrecoverable runtime error — it cannot be caught by `recover()` and terminates the whole process, unlike an ordinary panic in an RPC handler.

### Impact Explanation
`kaia_encodeAccountKey` is served by `KaiaAPI`, which is explicitly documented as offering "only methods that operate on public data that is freely available to anyone" [7](#0-6) , i.e. it requires no authentication, unlocked wallet, or special privilege — any public JSON-RPC caller can invoke it. A single malicious call with a deeply nested `key` field can crash the entire Kaia node process (denial of service against RPC and, if the RPC node is also a consensus/validator node, against block production). This matches the "Availability: Low/High" impact class of the referenced advisory (CWE-674 uncontrolled recursion) but reachable here directly by an untrusted, unprivileged public RPC caller with a single API call, which is a stronger reachability profile than the npm-library case.

### Likelihood Explanation
Likelihood is high: the vulnerable method is public, requires no funds, no signature, no prior state, and only a crafted JSON body of moderate size (each nesting level only costs a few bytes of JSON, so a tractable request of a few hundred KB can encode tens of thousands of nesting levels — far beyond Go's default goroutine stack growth limit of ~1GB, but recursion through `encoding/json`+reflection consumes many stack frames per level, making crashes achievable well within normal HTTP/WS request size limits).

### Recommendation
- Add an explicit recursion/nesting depth limit to `AccountKeySerializer.UnmarshalJSON` / `AccountKeyRoleBased.UnmarshalJSON` (and the analogous `DecodeRLP` paths) that is enforced *during* decoding rather than only after the structure has been fully materialized.
- Alternatively, reject any `AccountKeyTypeRoleBased` value encountered while already decoding within a `RoleBased` context at the point of type dispatch in `NewAccountKey`/`UnmarshalJSON`, rather than deferring the check to `checkAccountKeyZeroValues`/`CheckInstallable`.
- Consider imposing an overall maximum JSON body size / nesting depth check on `AccountKeyJSON` inputs accepted by public RPC methods (`EncodeAccountKey`), and audit `DecodeAccountKey`'s RLP path (`AccountKeyRoleBased.DecodeRLP`, which recursively calls `rlp.DecodeBytes` per nested element) for the same unbounded-recursion issue.

### Proof of Concept
Send the following to the public `kaia_encodeAccountKey` RPC method (depth illustrative; a real PoC would nest this pattern tens of thousands of times, which is easy to generate programmatically and stays within normal HTTP/WS body-size limits):

```json
{
  "jsonrpc": "2.0",
  "method": "kaia_encodeAccountKey",
  "params": [{
    "keyType": 5,
    "key": [
      { "keyType": 5, "key": [
        { "keyType": 5, "key": [
          "... repeated tens of thousands of times ..."
        ]}
      ]}
    ]
  }],
  "id": 1
}
```

This drives execution into `KaiaAPI.EncodeAccountKey` → `json.Unmarshal(accKey.Key, key)` → `AccountKeyRoleBased.UnmarshalJSON` → `AccountKeySerializer.UnmarshalJSON` → ... recursively, with the nested-`RoleBased` rejection in `checkAccountKeyZeroValues` never reached because the stack overflows first, crashing the node process handling the RPC request.

func (serializer *AccountKeySerializer) UnmarshalJSON(b []byte) error {
	var keyJSON AccountKeyJSON

	if err := json.Unmarshal(b, &keyJSON); err != nil {
		return err
	}

	if keyJSON.KeyType == nil {
		return errNoKeyType
	}
	serializer.keyType = *keyJSON.KeyType

	var err error
	serializer.key, err = NewAccountKey(serializer.keyType)
	if err != nil {
		return err
	}

	return json.Unmarshal(keyJSON.Key, serializer.key)
}

func (a *AccountKeyRoleBased) UnmarshalJSON(b []byte) error {
	var serializers []*AccountKeySerializer
	if err := json.Unmarshal(b, &serializers); err != nil {
		return err
	}

	*a = make(AccountKeyRoleBased, len(serializers))
	for i, s := range serializers {
		(*a)[i] = s.key
	}

	return nil
}

func (a *AccountKeyRoleBased) CheckInstallable(currentBlockNumber uint64) error {
	// A zero-role key is not allowed.
	if len(*a) == 0 {
		return kerrors.ErrZeroLength
	}
	// Do not allow undefined roles.
	if len(*a) > (int)(RoleLast) {
		return kerrors.ErrLengthTooLong
	}
	for i := 0; i < len(*a); i++ {
		// A composite key is not allowed.
		if (*a)[i].IsCompositeType() {
			return kerrors.ErrNestedCompositeType
		}
		// If any key in the role cannot be initialized, return an error.
		if err := (*a)[i].CheckInstallable(currentBlockNumber); err != nil {
			return err
		}
	}
	return nil
}

// EncodeAccountKey gets an account key of JSON format and returns RLP encoded bytes of the key.
func (s *KaiaAPI) EncodeAccountKey(accKey accountkey.AccountKeyJSON) (hexutil.Bytes, error) {
	if accKey.KeyType == nil {
		return nil, errors.New("key type is not specified")
	}
	key, err := accountkey.NewAccountKey(*accKey.KeyType)
	if err != nil {
		return nil, err
	}
	if err := json.Unmarshal(accKey.Key, key); err != nil {
		return nil, err
	}
	// Invalidate zero values of threshold and weight to prevent users' mistake
	// JSON unmarshalling sets zero for those values if they are not exist on JSON input
	if err := checkAccountKeyZeroValues(key, false); err != nil {
		return nil, err
	}
	accKeySerializer := accountkey.NewAccountKeySerializerWithAccountKey(key)
	encodedKey, err := rlp.EncodeToBytes(accKeySerializer)
	if err != nil {
		return nil, errors.New("the key probably contains an invalid public key: " + err.Error())
	}
	return (hexutil.Bytes)(encodedKey), nil
}

func checkAccountKeyZeroValues(key accountkey.AccountKey, isNested bool) error {
	switch key.Type() {
	case accountkey.AccountKeyTypeWeightedMultiSig:
		multiSigKey, _ := key.(*accountkey.AccountKeyWeightedMultiSig)
		if multiSigKey.Threshold == 0 {
			return errors.New("invalid threshold of the multiSigKey")
		}
		for _, weightedKey := range multiSigKey.Keys {
			if weightedKey.Weight == 0 {
				return errors.New("invalid weight of the multiSigKey")
			}
		}
	case accountkey.AccountKeyTypeRoleBased:
		if isNested {
			return errors.New("roleBasedKey cannot contains a roleBasedKey as a role key")
		}
		roleBasedKey, _ := key.(*accountkey.AccountKeyRoleBased)
		for _, roleKey := range *roleBasedKey {
			if err := checkAccountKeyZeroValues(roleKey, true); err != nil {
				return err
			}
		}
	}
	return nil
}
