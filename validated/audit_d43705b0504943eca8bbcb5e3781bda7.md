### Title
Unprotected zero-slippage swap in bribe-fee-to-BNB conversion allows value extraction from bribe rewards - (File: wombat/WombatBribeManager.sol)

### Summary
`WombatBribeManager._swapFeesForBnb` swaps collected bribe reward tokens into BNB via `IBNBZapper(PancakeZapper).zapInToken` but hardcodes the minimum-received parameter to `0`, meaning the swap's output is never validated against a meaningful minimum. This is the same bug class as the referenced report (swap functions called without checking/enforcing a minimum received amount to guard against slippage), reachable through an unprivileged, incentivized function.

### Finding Description
`_swapFeesForBnb` iterates over harvested bribe reward tokens and swaps each non-zero balance for BNB: [1](#0-0) 

The call to `zapInToken` passes `0` as the minimum output amount, so there is no slippage/minimum-received protection on this swap, mirroring the DODO `sellQuote`/`sellBase` finding where return values controlling received-amount are not checked against an expected minimum.

This function is reachable by any unprivileged wallet: `castVotes(swapForBnb)` is invoked from the external, permissionless functions `voteAndCast` and `castVotesAndClaimBribes`, both of which are explicitly designed to be called by any caller (a caller fee is paid as incentive for gas-intensive harvesting): [2](#0-1) [3](#0-2) 

Since `swapForBnb` is a caller-supplied boolean and the swap path/minimum is not further constrained, any address can trigger the zero-min swap of the protocol's freshly harvested bribe reward tokens at any time, including immediately after front-running/sandwiching the pool used by `PancakeZapper`.

### Impact Explanation
The bribe reward tokens being swapped belong to the protocol (destined to reward pools / callers as fee distribution) rather than any single depositor's principal, but they represent unclaimed yield collected on behalf of voters. Because the swap enforces no minimum received amount, an attacker can sandwich the swap (front-run to move the pool price, let the zero-slippage swap execute at a bad rate, then back-run) and extract value that would otherwise flow to the bribe reward distribution, i.e. a theft of unclaimed yield.

### Likelihood Explanation
The function is permissionless and callable by any wallet at any time via `voteAndCast`/`castVotesAndClaimBribes`, and the attacker does not need any special privilege—only capital to manipulate the swap pool and knowledge of when caster transactions are pending in the mempool. This makes the likelihood non-trivial, though it depends on the liquidity/depth of the `PancakeZapper` swap path and MEV competition.

### Recommendation
Compute an off-chain or on-chain-derived minimum acceptable output (e.g., via a TWAP oracle or a caller-supplied `minRec` parameter validated against a sane bound) instead of hardcoding `0` in the `zapInToken` call within `_swapFeesForBnb`.

### Proof of Concept
1. Bribe rewards accumulate in `WombatBribeManager` from `wombatStaking.vote(...)`.
2. Any wallet calls `voteAndCast(_lps, _deltas, true)` (or `castVotesAndClaimBribes(lps, true)`), setting `swapForBnb = true`.
3. This triggers `castVotes(true)` → `_swapFeesForBnb(rewardTokens, feeAmounts)`.
4. For each reward token/amount pair, `IBNBZapper(PancakeZapper).zapInToken(token, amount, 0, msg.sender)` executes with no minimum-out check.
5. An attacker who has front-run the underlying swap pool used by `PancakeZapper` (e.g., via a large swap to move price) causes the zero-slippage swap to execute at an unfavorable rate, extracting value from the bribe rewards before back-running to restore price, profiting at the expense of bribe reward recipients.

    function _swapFeesForBnb(address[][] memory rewardTokens, uint256[][] memory feeAmounts)
        internal
        returns (uint256 bnbAmount)
    {
        if(PancakeZapper == address(0)) revert PancakeZapperNotSet();
        uint256 bribeLength = rewardTokens.length;
        for (uint256 i; i < bribeLength; i++) {
            uint256 rewardLength = rewardTokens[i].length;
            for (uint256 j; j < rewardLength; j++) {
                if (rewardTokens[i][j] != address(0) && feeAmounts[i][j] > 0) {
                    _approveTokenIfNeeded(rewardTokens[i][j], PancakeZapper, feeAmounts[i][j]);
                    bnbAmount += IBNBZapper(PancakeZapper).zapInToken(
                        rewardTokens[i][j],
                        feeAmounts[i][j],
                        0,
                        msg.sender
                    );
                }
            }
        }
    }
