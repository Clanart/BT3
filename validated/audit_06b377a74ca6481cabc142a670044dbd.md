### Title
Blame proofs expose ECDH keys before encrypted-share PoP verification - (File: crypto/dkg/pedpop/src/lib.rs)

### Summary
`calculate_share` can return an `EncryptionKeyProof` before verifying the Schnorr proof-of-possession that binds an `EncryptedMessage` to its sender, key, and ciphertext. An attacker can copy the per-message key from an observed encrypted share, submit a modified ciphertext under their own participant ID, and cause the victim to emit a blame proof containing the ECDH shared point needed to decrypt the original message. This leaks a protected DKG secret share.

### Finding Description
`EncryptedMessage::read` deserializes `key`, `pop`, and the encrypted payload without authenticating them. [1](#0-0) 

During share calculation, `Encryption::decrypt` only queues the PoP for later batch verification, then immediately computes `self.enc_key * msg.key`, decrypts the payload, and constructs an `EncryptionKeyProof` for that shared point. [2](#0-1) [3](#0-2) 

`calculate_share` then attempts to decode the decrypted bytes as a canonical scalar and returns `PedPoPError::InvalidShare` with the generated blame proof before reaching `batch.verify_with_vartime_blame`, so an invalid PoP does not stop disclosure of the proof. [4](#0-3) [5](#0-4) 

The code explicitly documents this copied-key threat: without a valid PoP, an attacker can claim an honest message’s key, induce a blame argument, reveal the ECDH output, and expose the honest participant’s message. [6](#0-5) 

`EncryptionKeyProof` serializes the shared ECDH point, so publishing the returned blame proof gives the attacker the value required by the ChaCha20 derivation. [7](#0-6) [8](#0-7) 

### Impact Explanation
An unencrypted-message observer can recover the plaintext of another participant’s PedPoP secret-share message addressed to the victim. The disclosure is of private DKG share material rather than merely invalid-message metadata, and it directly defeats the protection described for per-message encryption keys. [6](#0-5) 

### Likelihood Explanation
The attacker only needs an observed ciphertext and the ability to submit a share message to the victim. Copying the per-message key and modifying the ciphertext requires no private key or proof generation. [1](#0-0) 

For fields with unused high encoding bits, such as the 25519 scalar field used by Ristretto, flipping the ciphertext’s most significant plaintext bit guarantees a non-canonical scalar representation and triggers the vulnerable early return. [9](#0-8) [10](#0-9) 

### Recommendation
Verify `msg.pop` synchronously inside `Encryption::decrypt` before computing the ECDH output, decrypting the payload, or constructing `EncryptionKeyProof`. Alternatively, delay every error path that can return a blame proof until after the queued PoP batch verification has succeeded, although authentication before decryption is the safer structure. Add a regression test that reuses an honest message key, mutates its ciphertext, leaves the PoP invalid, and asserts that no `EncryptionKeyProof` is returned.
