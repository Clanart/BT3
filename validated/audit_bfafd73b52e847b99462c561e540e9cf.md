### Title
Attacker-controlled diff padding causes `cap_diff_for_prompt` to fully omit the truly dangerous file from the LLM review prompt - (File: `plugins/security-guidance/hooks/review_api.py`)

### Summary
`cap_diff_for_prompt` (and its `llm.py` twin `_cap_files_for_prompt`) enforces `DIFF_PER_FILE_BYTES`/`DIFF_TOTAL_BYTES` by iterating `files` in caller-supplied order and greedily consuming a shared byte budget, replacing any file that arrives after the budget is exhausted with a placeholder string `"[omitted by security-guidance: total diff byte cap reached]"`. Because file order and per-file size are both derived from attacker-controlled repository content (new/padded files in the same diff), an attacker can place several inflated decoy files ahead of the genuinely dangerous file in the diff so the budget is exhausted before the reviewer ever sees the dangerous file's content.

### Finding Description
`cap_diff_for_prompt` processes `files: list[tuple[str, str]]` strictly in the order it receives them, tracking a running `total` against `DIFF_TOTAL_BYTES` (default 400000 bytes): [1](#0-0) 

Once `room <= 0`, every subsequent file is replaced entirely with an omission placeholder and never reaches the model — there is no re-ranking by "how dangerous does this file look" once the budget is spent. This capped output feeds directly into `build_investigate_prompt`, which is the sole assembler of the investigate-stage prompt: [2](#0-1) 

The identical pattern exists in `llm.py`'s `_cap_files_for_prompt`, used by the single-shot `analyze_code_security` (the Stop hook's only reviewer, and the commit-review/push-sweep fallback path when the agentic SDK is unavailable): [3](#0-2) 

File ordering only gets risk-aware re-sorting via `_prioritize_diff_files` in `gitutil.py`, and only when the file count exceeds `MAX_DIFF_FILES` (30): [4](#0-3) 

For diffs at or below that count — the common case for the Stop hook, which fires on ordinary uncommitted edits — no re-ranking happens at all; files are capped in whatever order `parse_diff_into_files` returns them (effectively git's path order). An attacker who controls repository content being edited in the same turn (e.g., a handful of large generated/padding files with innocuous names sorted before the vulnerable file, or `DIFF_PER_FILE_BYTES`-sized filler content) can consume the entire 400000-byte total budget with `~5` files at the 80000-byte per-file cap, guaranteeing the actual dangerous file is entirely replaced by the omission placeholder before it is packed into the prompt.

This matters most for the single-shot path (`analyze_code_security`/Stop hook): that reviewer has no filesystem tool access — it only ever sees the text handed to it in `files_text`, so an omitted file is invisible to it with no fallback. The agentic `build_investigate_prompt` path is partially mitigated because `touched_paths` (a separate, non-byte-capped list of file paths) is still listed and the agent has Read/Grep tools, so it *could* independently discover the omitted file — but nothing in the prompt flags that the diff for that path was dropped, so there's no explicit signal directing the agent to actually go read it.

Existing validation (self-refute stage, severity filtering, `_prioritize_diff_files`) does not protect against this: `_prioritize_diff_files` only engages above the 30-file threshold, and even when it does engage, its scoring heuristic (substring path-token match + counted `+` lines) is itself attacker-influenceable, since the attacker names and sizes every file in the diff.

### Impact Explanation
This breaks the stated invariant that prompt assembly must not let untrusted repo content suppress review of dangerous changes: the dangerous file's content is completely absent from the text the reviewer model analyzes, so no vulnerability in it can ever be flagged, and (for the Stop-hook single-shot path) there is no secondary mechanism to catch it. The practical effect is that a dangerous change (e.g., an injected backdoor, credential leak, or command injection) can pass the security-guidance review undetected purely because of low-cost sibling padding files in the same diff, which is the underlying mechanism the review pipeline exists to prevent.

### Likelihood Explanation
This requires no privilege beyond being able to influence what files/content end up in a reviewed diff — i.e., ordinary repository-controlled content in a session (large generated/scaffold files, or a crafted PR/commit) that the diff-review hooks process. It is fully deterministic and reproducible: byte counts and iteration order are fixed and attacker-computable, so the omission point can be engineered precisely (e.g., 5 files of exactly `DIFF_PER_FILE_BYTES` each = 400000 bytes = `DIFF_TOTAL_BYTES`).

### Recommendation
Do not apply the byte budget in raw file-list order. Either: (1) always run `_prioritize_diff_files`-style risk ranking before `cap_diff_for_prompt`/`_cap_files_for_prompt` regardless of file count, so budget is spent on the highest-risk files first; (2) allocate the total budget proportionally/fairly across files (e.g., a fixed minimum guaranteed slice per file) rather than greedily first-come-first-served, so no file is ever fully omitted; or (3) when a file is fully omitted due to budget exhaustion, surface its path prominently in a manner that forces (not just permits) the agentic reviewer to `Read` it directly, and treat full-omission Stop-hook fires as "unreviewed" rather than silently succeeding.

### Proof of Concept
Unit test plan for `cap_diff_for_prompt` in `review_api.py`:
1. Construct `files = [(f"decoy_{i}.py", "A" * DIFF_PER_FILE_BYTES) for i in range(6)] + [("dangerous.py", "+os.system(user_input)")]` (6 decoys × 80000 bytes = 480000 > `DIFF_TOTAL_BYTES` 400000).
2. Call `capped, dropped = cap_diff_for_prompt(files)`.
3. Assert that the tuple for `"dangerous.py"` in `capped` equals `("dangerous.py", "[omitted by security-guidance: total diff byte cap reached]")` — i.e., the dangerous content string `"os.system(user_input)"` is NOT present anywhere in `capped`'s concatenated content.
4. Build the full prompt via `build_investigate_prompt(["dangerous.py"], files)` and assert `"os.system(user_input)"` is absent from the resulting prompt string, demonstrating the reviewer never receives the dangerous code regardless of file ordering/decoy composition.

```python
def cap_diff_for_prompt(
    files: list[tuple[str, str]],
) -> tuple[list[tuple[str, str]], int]:
    """Cap per-file and total diff bytes; return (capped_files, bytes_dropped).

    Truncation markers are written inside the content so the reviewer
    knows the file is incomplete.
    """
    out: list[tuple[str, str]] = []
    dropped = 0
    total = 0
    for fp, content in files:
        if len(content) > DIFF_PER_FILE_BYTES:
            dropped += len(content) - DIFF_PER_FILE_BYTES
            content = (
                content[:DIFF_PER_FILE_BYTES]
                + "\n... [truncated by security-guidance: file exceeds per-file byte cap]"
            )
        room = DIFF_TOTAL_BYTES - total
        if room <= 0:
            dropped += len(content)
            out.append(
                (fp, "[omitted by security-guidance: total diff byte cap reached]")
            )
            continue
        if len(content) > room:
            dropped += len(content) - room
            content = (
                content[:room]
                + "\n... [truncated by security-guidance: total diff byte cap reached]"
            )
        total += len(content)
        out.append((fp, content))
    return out, dropped
```

```python
def build_investigate_prompt(
    touched_paths: list[str],
    diff_files: list[tuple[str, str]],
    *,
    context_note: str = "",
) -> str:
    capped, _ = cap_diff_for_prompt(diff_files)
    diff_text = "\n\n".join(
        f"=== DIFF: {fp} ===\n{content}" for fp, content in capped
    )
    return (
        "Review this change for security vulnerabilities.\n\n"
        "Changed files (you may Read these and any other file in the repo):\n"
        + "\n".join(f"  - {p}" for p in touched_paths[:50])
        + context_note
        + "\n\nUnified diff (only + lines are new):\n\n"
        + diff_text
        + extensibility.guidance_block()
        + "\n\nInvestigate per the method in your instructions, then return "
        "the findings list."
    )
```

```python
def _cap_files_for_prompt(files):
```

```python
def _prioritize_diff_files(diff_files, cap):
    """When `diff_files` exceeds `cap`, return the top-`cap` by security
    relevance plus the count dropped. Otherwise return (diff_files, 0).

    Score = (risk_tokens_in_path, not_low_priority, added_lines). The
    added-lines proxy is `content.count('\\n+')` which counts diff additions
    cheaply without re-parsing hunks. This is a heuristic, not a guarantee —
    the goal is to review the likely-dangerous subset of an over-cap diff
    instead of reviewing nothing. Diffs that exceed the cap are typically
    large multi-file scaffolds, and the cross-file source→sink vulnerabilities
    in them concentrate in a handful of api/client/route files.
    """
    if len(diff_files) <= cap:
        return diff_files, 0

    def _score(item):
        fp, content = item
        low = fp.lower()
        # Prepend "/" so leading-slash patterns in _LOW_PRIORITY_PATH_TOKENS
        # match top-level dirs (git diff paths are repo-root-relative, e.g.
        # `migrations/001.py` not `/migrations/001.py`). Same trick as
        # _is_reviewable_source.
        low_slashed = "/" + low
        risk = sum(1 for t in _SECURITY_RISK_PATH_TOKENS if t in low)
        low_prio = (
            fp.endswith(_LOW_PRIORITY_SUFFIXES)
            or any(t in low_slashed for t in _LOW_PRIORITY_PATH_TOKENS)
        )
        # added_lines: count('\n+') over-counts by including '+++' header and
        # any literal '+' at line start in context, but it's a consistent
        # ordinal across files in the same diff which is all we need.
        added = content.count("\n+")
        return (risk, not low_prio, added)

    ranked = sorted(diff_files, key=_score, reverse=True)
    return ranked[:cap], len(diff_files) - cap
```
