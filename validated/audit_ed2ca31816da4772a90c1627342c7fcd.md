### Title
Empty aggregate Schnorr signature bypasses verification - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::read` accepts a serialized aggregate containing zero nonces, while `SchnorrAggregate::verify` accepts an empty `keys_and_challenges` list. For a zero-length aggregate with `s = 0`, the verifier constructs only the identity term `-0 * G`, causing verification to succeed without any constituent signature or public key authorization. [1](#0-0) [2](#0-1) 

### Finding Description
Deserialization reads a 32-bit nonce count and accepts `0` without enforcing a minimum aggregate size. Verification then only checks that the number of nonces equals the number of supplied key/challenge pairs; an attacker can satisfy that check with two empty collections. Because no random weights or signature statements are generated and zero is added as the final scalar, the resulting multiexponentiation is the identity and `verify` returns `true`. [3](#0-2) [4](#0-3) 

This behavior contradicts the aggregation API’s own invariant: `SchnorrAggregator::complete` returns `None` when no signatures were aggregated, but deserialization bypasses that restriction and creates the impossible empty aggregate directly. [5](#0-4) 

### Impact Explanation
An unprivileged party can submit a 36-byte forged aggregate signature that verifies against an empty authorization/policy statement. In a caller that derives the expected `keys_and_challenges` collection from attacker-influenced request state and permits it to be empty, this produces a forged aggregate signature accepted without authorization from any private key. [2](#0-1) 

### Likelihood Explanation
The bypass is deterministic and requires only untrusted bytes reaching `SchnorrAggregate::read` followed by verification with an empty expected-signer list. Its reachability is narrower than a normal nonempty-signature forgery because the calling context must admit an empty policy, but the primitive itself fails to preserve the “at least one aggregated signature” boundary established by `SchnorrAggregator::complete`. [1](#0-0) [5](#0-4) 

### Recommendation
Reject zero-length aggregates in `SchnorrAggregate::read` and independently return `false` in `SchnorrAggregate::verify` when `Rs` or `keys_and_challenges` is empty. Alternatively, provide a fallible constructor/parser that guarantees every accepted `SchnorrAggregate` contains at least one nonce. [1](#0-0) [2](#0-1) 

### Proof of Concept
For any `Ciphersuite` whose zero scalar has the canonical serialization `C::F::ZERO.to_repr()`:

```rust
use schnorr::SchnorrAggregate;
use ciphersuite::group::ff::Field;

let mut encoded = Vec::new();
encoded.extend(0u32.to_le_bytes());                     // zero Rs
encoded.extend(C::F::ZERO.to_repr().as_ref());          // s = 0

let aggregate =
  SchnorrAggregate::<C>::read(&mut encoded.as_slice()).unwrap();

assert!(aggregate.verify(b"application-authorization-dst", &[]));
```

The verifier reaches `multiexp_vartime(&[(-0, G)])`, evaluates the identity, and accepts the forged empty aggregate. [3](#0-2) [6](#0-5)
