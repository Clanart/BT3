## Finding

### Title
Payout attribution (OP_RETURN operator xonly-pubkey) is unsigned and mutable, letting an unprivileged party strip/rewrite it and permanently orphan the fronting operator's reimbursement - (File: `core/src/builder/transaction/operator_reimburse.rs`)

### Summary
`create_payout_txhandler` builds the payout transaction with a `SIGHASH_SINGLE | SIGHASH_ANYONECANPAY` user signature that only commits to input 0 and output 0 (the user's payout output). The OP_RETURN output that records which operator fronted the payout is output index 2 and is **not covered by that signature**, so it can be replaced or stripped by anyone who observes the signed input before it confirms, while the transaction remains fully valid.

### Finding Description
`create_payout_txhandler` places the attribution data in an unsigned position: [1](#0-0) 

The user's signature is explicitly required and verified to use `SinglePlusAnyoneCanPay`: [2](#0-1) 

`SIGHASH_SINGLE | SIGHASH_ANYONECANPAY` commits only to the single signed input and the output at the same index (index 0, the user's payout). It commits to nothing about output 1 (anchor) or output 2 (OP_RETURN with the operator's xonly pubkey). Consequently, once the honest operator broadcasts the payout transaction (which pays out the user correctly and truthfully claims credit via its own `self.signer.xonly_public_key` in the OP_RETURN), an unprivileged third party who observes this transaction in the mempool can construct a *new*, still fully valid, competing transaction that reuses the exact same signed input/output-0 pair but drops, corrupts, or replaces the OP_RETURN output (and the fee-paying/anchor inputs), since none of that is covered by the signature.

On the verifier side, this OP_RETURN is the sole source of attribution used to credit the operator that fronted the payout: [3](#0-2) 

If the OP_RETURN is missing or unparsable, `operator_xonly_pk` becomes `None` and is persisted as `NULL`: [4](#0-3) 

The lookup that lets an operator find its own unhandled payout to begin the reimbursement (kickoff) process requires an exact match on `payout_payer_operator_xonly_pk`: [5](#0-4) 

A `NULL` value can never satisfy `= $1`, so no operator (including the true, honest one who actually paid the user) can ever be matched to that payout and thus can never enter the kickoff/reimbursement flow for the BTC it already fronted.

### Impact Explanation
This breaks the binding "the operator credited == the operator that fronted the withdrawal." An unprivileged attacker with no protocol role (no operator/verifier/aggregator key) can:
- Observe an honest operator's broadcasted-but-unconfirmed payout transaction (public mempool data),
- Rebuild a still-valid competing transaction using the same signed `(input 0, output 0)` pair (valid under `SIGHASH_SINGLE|ANYONECANPAY`) with a corrupted or absent OP_RETURN,
- Get this transaction confirmed instead of (or racing) the operator's original transaction.

The practical outcome is that the honest operator, who already sent real BTC to the withdrawing user, becomes permanently unable to be reimbursed via the documented kickoff/reimburse flow, because the on-chain record the verifiers rely on to attribute the payout no longer names any operator. This matches the Critical impact category "an honest operator permanently unable to be reimbursed," with no operator, verifier, or other privileged role required by the attacker.

### Likelihood Explanation
Exploitation requires only: (1) monitoring the mempool for a payout transaction (public), (2) reconstructing a transaction with the same signed input and output 0, replacing the unsigned outputs, and (3) getting it broadcast/mined before the original transaction — feasible via full-RBF-supporting relays/miners or by simply out-racing the original broadcast, since no signature commitment prevents it. No cryptographic secret or privileged role is needed; the only requirement is visibility of a signed, not-yet-confirmed transaction, which is inherent to how Bitcoin mempools work.

### Recommendation
Do not rely on unsigned outputs for protocol-critical attribution. Either:
- Change the payout transaction's sighash to cover the OP_RETURN output (e.g., `SIGHASH_ALL` for the relevant portion, or commit to a hash of the operator pubkey inside the signed message/covenant), or
- Move operator attribution off-chain/into a covenant-enforced output that is bound by the same signature as the user payout, or
- Require the reimbursement/kickoff flow to independently prove operator identity (e.g., via a presigned commitment made before broadcasting) rather than trusting an unauthenticated OP_RETURN read back from the confirmed chain.

### Proof of Concept
1. Honest operator O calls `withdraw()`, producing a payout tx `T` with:
   - input 0: the user's withdrawal UTXO, signed by the user with `SinglePlusAnyoneCanPay`,
   - output 0: user's payout (script/amount from `WithdrawParams`),
   - output 1: anchor,
   - output 2: OP_RETURN containing O's xonly pubkey (`operator.rs:620-626`, `operator_reimburse.rs:418,432`).
2. O broadcasts `T` (funded via `fund_raw_transaction`) to the network; `T` sits in the mempool unconfirmed.
3. Attacker A (no protocol role) observes `T`, extracts input 0 (outpoint + witness/signature) and output 0, and builds `T'`:
   - input 0: same outpoint/witness as `T` (still valid — signature only committed to input 0/output 0),
   - output 0: identical to `T`'s output 0 (satisfies the sighash commitment),
   - any inputs/outputs A wants for fees, and no OP_RETURN (or a garbage OP_RETURN).
4. A broadcasts `T'` with a higher feerate (or otherwise gets it mined first); `T'` confirms instead of `T`.
5. Verifier's `update_finalized_payouts` scans the confirmed payout tx, finds no valid operator OP_RETURN, and stores `payout_payer_operator_xonly_pk = NULL` (`verifier.rs:2312-2343`, `database/verifier.rs:198-251`).
6. Operator O calls `get_reimbursement_txs`/relies on `get_first_unhandled_payout_by_operator_xonly_pk`, which filters on `payout_payer_operator_xonly_pk = $1` (`database/verifier.rs:282-296`) — this never matches `NULL`, so O can never be routed into the kickoff/reimburse flow for the BTC it already paid the user, permanently losing its fronted funds.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {

                        .0,

                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
