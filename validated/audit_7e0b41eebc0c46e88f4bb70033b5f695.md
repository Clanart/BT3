### Title
Removing a pool from `WombatBribeManager` permanently strands its real Wombat votes and future bribes - ([File: wombat/WombatBribeManager.sol])

### Summary
`WombatBribeManager.removePool()` only removes the pool's address from the `pools` array, but never sets `poolInfos[_lp].isActive = false`, never zeroes `poolInfos[_lp].totalVoteInVlmgp`, and never issues a compensating vote to reduce the pool's real allocation on the underlying Wombat `voter`. Because `castVotes()` is the *only* function that can push updated vote deltas to `wombatStaking.vote()` → `voter.vote()`, and it iterates solely over the `pools` array, any veWOM votes already cast toward a removed pool become permanently frozen at the Wombat protocol level, and all future bribes/emissions accruing to that pool can never again be harvested into the local `BribeRewardPool`.

### Finding Description
`addPool()` registers a pool both in the `pools` array and in `poolInfos[_lp]` with `isActive: true`: [1](#0-0) 

`removePool()` however only shrinks the `pools` array; it does not touch `poolInfos[_lp]`: [2](#0-1) 

The real, on-chain vote weight at the Wombat `voter` contract is only ever adjusted inside `castVotes()`, which computes `targetVote` vs `currentVote` for each entry of the `pools` array and forwards the delta to `wombatStaking.vote()`: [3](#0-2) 

`WombatStaking.vote()` in turn calls `voter.vote(_lpVote, _deltas)` only for the LPs it is given, and harvests/distributes bribes for exactly those LPs into their respective `rewarder` (`BribeRewardPool`): [4](#0-3) 

Once a pool is removed from the `pools` array:
- Its real vote weight recorded on the Wombat `voter` is frozen at whatever it was at the last `castVotes()` call, because it is never again included in the `_pools`/`votes` arrays passed to `wombatStaking.vote()`. There is no mechanism to reduce it to zero.
- `usedVote()`/`remainingVotes()` accounting (`veWom.usedVote(address(wombatStaking))`) permanently reflects this stranded allocation, reducing the vlMGP-holder-controlled voting capacity forever.
- Any new bribes/WOM emissions that continue to accrue on the underlying Wombat gauge for that pool are never harvested into `poolInfos[_lp].rewarder` again (since harvesting only happens through `castVotes()`/`WombatStaking.vote()` for LPs in the `pools` array), so any user who still has a vote position (`userVotedForPoolInVlmgp`) recorded against that removed pool permanently loses access to new yield.
- `unvote()` and `vote()` still succeed for the removed pool because they check only `poolInfos[_lp].isActive`, which remains `true` forever (never reset by `removePool()`); this lets internal state (`totalVoteInVlmgp`, `userVotedForPoolInVlmgp`) drift arbitrarily out of sync with the real, now-unmanageable Wombat vote, but can never actually retract the real vote already cast.

This directly mirrors the reported bug class: a pool "kill"/removal action leaves residual votes on-chain that continue to lock voting capacity and to accrue unclaimable rewards, with no path provided to reclaim or redirect them.

### Impact Explanation
This is not a theoretical griefing scenario triggered by a malicious actor — `removePool()` is a normal, expected maintenance action (e.g., deprecating an LP/gauge). Any pool with outstanding votes at the time of removal will have that portion of the DAO's total veWOM voting power permanently stuck pointed at a stale gauge, and any vlMGP holders who voted for it lose access to future bribe/emission yield indefinitely, since the removed pool is never revisited by `castVotes()` again. This satisfies both "permanent freezing of funds/yield" and effectively distorts governance voting result outcomes by making a portion of total voting power permanently non-reallocatable.

### Likelihood Explanation
Likelihood is high in normal operation: pool deprecation/removal is an anticipated lifecycle event for LP-based bribe systems, and any pool that has ever received votes before being removed triggers this condition automatically, with no special conditions or attacker required.

### Recommendation
Before/when removing a pool in `removePool()`:
1. Zero out the pool's real Wombat vote allocation by issuing a final `wombatStaking.vote()` call with a delta that brings its `currentVote` to 0, or require `totalVoteInVlmgp == 0` (and enforce all users have unvoted) as a precondition to removal.
2. Set `poolInfos[_lp].isActive = false` upon removal so `vote()`/`unvote()` correctly reflect the pool's retired status.
3. Ensure any remaining bribes/claimable rewards already distributed to the pool's `rewarder` before removal remain claimable via `claimBribe()`, and consider a fallback mechanism (as suggested for `killGauge`) to sweep any un-attributable rewards back to a safe destination rather than leaving them unreachable.

### Proof of Concept
1. Owner calls `addPool(lpA, rewarderA, "PoolA")`, registering `lpA` in `pools` and `poolInfos`.
2. Vlmgp holder Alice calls `vote([lpA], [1000e18])`, staking her vlMGP into `rewarderA` and setting `poolInfos[lpA].totalVoteInVlmgp = 1000e18`.
3. Owner calls `castVotes(false)`, which forwards `+1000e18` delta for `lpA` to `wombatStaking.vote()` → `voter.vote()`, so `lpA` now holds `1000e18` real veWOM votes on Wombat, and bribes begin flowing into `rewarderA`.
4. Owner calls `removePool(indexOfLpA)`. `lpA` is removed from the `pools` array, but `poolInfos[lpA]` (including `isActive = true` and `totalVoteInVlmgp = 1000e18`) is untouched.
5. From this point on, every subsequent `castVotes()` call iterates only over the remaining `pools` array — `lpA` is never included again, so its `1000e18` real vote at the Wombat `voter` can never be reduced, and no new bribes for `lpA` are ever harvested into `rewarderA` again.
6. Alice still shows `userVotedForPoolInVlmgp[Alice][lpA] = 1000e18` and can call `unvote(lpA)` (since `isActive` was never reset) to update local accounting and withdraw her stake from `rewarderA`, but this has zero effect on the real, permanently-stuck `1000e18` vote allocation sitting on the Wombat `voter` contract — that portion of the protocol's total voting power, and any further yield tied to it, is unrecoverable.

    function castVotes(bool swapForBnb)
        override public
        returns (address[][] memory finalRewardTokens, uint256[][] memory finalFeeAmounts)
    {
        lastCastTime = block.timestamp;
        uint256 length = pools.length;
        address[] memory _pools = new address[](length);
        int256[] memory votes = new int256[](length);
        address[] memory rewarders = new address[](length);

        for (uint256 i; i < length; i++) {
            Pool storage pool = poolInfos[pools[i]];
            _pools[i] = pool.poolAddress;
            rewarders[i] = pool.rewarder;

            uint256 currentVote = getVoteForLp(pool.poolAddress);
            uint256 targetVoteInLMGP = pool.totalVoteInVlmgp;
            uint256 targetVote = 0;

            if (totalVlMgpInVote != 0) {
                targetVote = targetVoteInLMGP * totalVotes() / totalVlMgpInVote;
            }

            if (targetVote >= currentVote) {
                votes[i] = int256(targetVote - currentVote);
            } else {
                votes[i] = int256(targetVote) - int256(currentVote);
            }
        }

        (address[][] memory rewardTokens, uint256[][] memory feeAmounts) = wombatStaking.vote(
            _pools,
            votes,
            rewarders,
            msg.sender
        );
