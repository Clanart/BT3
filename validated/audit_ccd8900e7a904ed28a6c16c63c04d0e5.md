### Title
Permissionless `MsgAssociateContractAddress` lets any account bind an arbitrary CosmWasm contract's identity, hijacking pointer/asset registrations - (File: x/evm/keeper/msg_server.go)

### Summary
`MsgAssociateContractAddress` is processed by `AssociateContractAddress` without verifying that `msg.Sender` has any authority over the target contract `msg.Address`. The handler only checks that a wasm contract exists at the address and that no association exists yet, then calls `SetAddressMapping` to permanently bind the contract's direct-cast EVM address to its Sei address. ### Finding Description
`MsgAssociateContractAddress.ValidateBasic` only validates that `Sender` and `Address` are well-formed bech32 addresses; it performs no ownership check. [2](#0-1) 
`GetSigners` returns the `Sender` (any account that signs the tx), which is unrelated to `msg.Address` (the CW contract being associated). [3](#0-2) 
The keeper handler then verifies only that a contract exists at `msg.Address` and that it is not already associated — never that `msg.Sender` is the contract's admin, creator, or the contract itself:
```go
func (server msgServer) AssociateContractAddress(goCtx context.Context, msg *types.MsgAssociateContractAddress) (*types.MsgAssociateContractAddressResponse, error) {
	...
	if server.wasmViewKeeper.GetContractInfo(ctx, addr) == nil {
		return nil, errors.New("no wasm contract found at the given address")
	}
	evmAddr := common.BytesToAddress(addr)
	existingEvmAddr, ok := server.GetEVMAddress(ctx, addr)
	if ok { ... return nil, errors.New("contract already has an associated address") }
	server.SetAddressMapping(ctx, addr, evmAddr)
	...
}
``` [4](#0-3) 
`SetAddressMapping` writes a bidirectional, permanent Sei⟷EVM address mapping and creates the underlying account if missing — the very same primitive used to bind user wallets and pointer contracts throughout the EVM subsystem. [5](#0-4) 
This mirrors the Kanboard CVE pattern exactly: a message accepts a client-supplied `sender` and a target resource identifier (`address`), but the authorization check only confirms the target resource exists — not that the sender is entitled to modify/associate it. Any unprivileged account can race to call `AssociateContractAddress` for a CosmWasm contract deployed by someone else (e.g., a token, DEX, or vault contract) before the legitimate deployer/integration does so, permanently claiming the association slot for that contract's canonical EVM identity.

### Impact Explanation
Because the association is one-time and enforced as immutable (`"contract already has an associated address"`), a griefer can permanently occupy the EVM↔Sei mapping for any not-yet-associated CW contract. Any downstream tooling, precompile flow, or off-chain integration that assumes `AssociateContractAddress`/`GetEVMAddress` reflects a deliberate action by the contract owner is misled. While in the current implementation the mapping value itself is deterministic (`common.BytesToAddress(addr)`, i.e. it can't redirect funds to a different address), it still blocks the legitimate owner from ever calling this message again for that contract and permanently emits/asserts an association state that was never sanctioned by the contract's controller — a permanent, unauthorized state change performed on behalf of a resource the caller does not own, directly matching the "authenticated user can add information to a private object of another user without authorization" bug class from the CVE.

### Likelihood Explanation
Trivial and cheap to exploit: any funded account can submit `MsgAssociateContractAddress` for any wasm contract address at any time, requiring only knowledge of the target address (which is public on-chain data) and no special permission.

### Recommendation
Require that `msg.Sender` equal the contract's admin (from `wasmViewKeeper.GetContractInfo(ctx, addr).Admin`) or the contract's own address (self-association performed via the contract's `Execute`), rejecting the message otherwise. Alternatively, restrict `AssociateContractAddress` to be invoked internally (e.g., only from within the module or gated by governance) rather than as an open user-submitted message.

### Proof of Concept
1. Contract `C` (any CW20/CW721/custom contract) is deployed by user Alice and not yet associated.
2. Attacker Bob (unrelated to `C`) submits `MsgAssociateContractAddress{Sender: Bob, Address: C}`.
3. `AssociateContractAddress` finds `C` exists and has no association, and calls `SetAddressMapping(ctx, C, common.BytesToAddress(C))`, permanently locking the association.
4. Alice later attempts to associate `C` for legitimate integration purposes and receives `"contract already has an associated address"`, permanently denying her the ability to (re-)establish this mapping through her own action — despite never having consented, matching the CVE's "add ... to a private [resource] of another user" pattern via unauthenticated/unauthorized form-field manipulation (`Sender`/`Address`). func (server msgServer) AssociateContractAddress(goCtx context.Context, msg *types.MsgAssociateContractAddress) (*types.MsgAssociateContractAddressResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)
	addr := sdk.MustAccAddressFromBech32(msg.Address) // already validated
	// check if address is for a contract
	if server.wasmViewKeeper.GetContractInfo(ctx, addr) == nil {
		return nil, errors.New("no wasm contract found at the given address")
	}
	evmAddr := common.BytesToAddress(addr)
	existingEvmAddr, ok := server.GetEVMAddress(ctx, addr)
	if ok {
		if existingEvmAddr.Cmp(evmAddr) != 0 {
			logger.Error("unexpected associated EVM address exists for contract", "existing", existingEvmAddr, "contract", addr, "expected", evmAddr)
		}
		return nil, errors.New("contract already has an associated address")
	}
	server.SetAddressMapping(ctx, addr, evmAddr)
	return &types.MsgAssociateContractAddressResponse{}, nil
}

func (msg *MsgAssociateContractAddress) ValidateBasic() error {
	_, err := sdk.AccAddressFromBech32(msg.Sender)
	if err != nil {
		return sdkerrors.Wrapf(sdkerrors.ErrInvalidAddress, "Invalid sender address (%s)", err)
	}

	if _, err := sdk.AccAddressFromBech32(msg.Address); err != nil {
		return sdkerrors.ErrInvalidAddress
	}

	return nil
}

func (k *Keeper) SetAddressMapping(ctx sdk.Context, seiAddress sdk.AccAddress, evmAddress common.Address) {
	store := ctx.KVStore(k.storeKey)
	store.Set(types.EVMAddressToSeiAddressKey(evmAddress), seiAddress)
	store.Set(types.SeiAddressToEVMAddressKey(seiAddress), evmAddress[:])
	if !k.accountKeeper.HasAccount(ctx, seiAddress) {
		k.accountKeeper.SetAccount(ctx, k.accountKeeper.NewAccountWithAddress(ctx, seiAddress))
	}
	ctx.EventManager().EmitEvent(sdk.NewEvent(
		types.EventTypeAddressAssociated,
		sdk.NewAttribute(types.AttributeKeySeiAddress, seiAddress.String()),
		sdk.NewAttribute(types.AttributeKeyEvmAddress, evmAddress.Hex()),
	))
}

func TestAssociateContractAddress(t *testing.T) {
	k, ctx := testkeeper.MockEVMKeeper(t)
	msgServer := keeper.NewMsgServerImpl(k)
	dummySeiAddr, dummyEvmAddr := testkeeper.MockAddressPair()
	res, err := msgServer.RegisterPointer(sdk.WrapSDKContext(ctx), &types.MsgRegisterPointer{
		Sender:      dummySeiAddr.String(),
		PointerType: types.PointerType_ERC20,
		ErcAddress:  dummyEvmAddr.Hex(),
	})
	require.Nil(t, err)
	_, err = msgServer.AssociateContractAddress(sdk.WrapSDKContext(ctx), &types.MsgAssociateContractAddress{
		Sender:  dummySeiAddr.String(),
		Address: res.PointerAddress,
	})
	require.Nil(t, err)
	associatedEvmAddr, found := k.GetEVMAddress(ctx, sdk.MustAccAddressFromBech32(res.PointerAddress))
	require.True(t, found)
	require.Equal(t, common.BytesToAddress(sdk.MustAccAddressFromBech32(res.PointerAddress)), associatedEvmAddr)
	associatedSeiAddr, found := k.GetSeiAddress(ctx, associatedEvmAddr)
	require.True(t, found)
	require.Equal(t, res.PointerAddress, associatedSeiAddr.String())
	// setting for an associated address would fail
	_, err = msgServer.AssociateContractAddress(sdk.WrapSDKContext(ctx), &types.MsgAssociateContractAddress{
		Sender:  dummySeiAddr.String(),
		Address: res.PointerAddress,
	})
	require.NotNil(t, err)
	require.Contains(t, err.Error(), "contract already has an associated address")
	// setting for a non-contract would fail
	_, err = msgServer.AssociateContractAddress(sdk.WrapSDKContext(ctx), &types.MsgAssociateContractAddress{
		Sender:  dummySeiAddr.String(),
		Address: dummySeiAddr.String(),
	})
	require.NotNil(t, err)
	require.Contains(t, err.Error(), "no wasm contract found at the given address")
}
