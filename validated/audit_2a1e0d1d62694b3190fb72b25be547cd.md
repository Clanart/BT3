### Title
Unauthenticated tx-sender JSON-RPC `send_tx` Endpoint Allows Unauthorized Transaction Queue Injection — (`File: crates/clementine-tx-sender/src/jsonrpc/server.rs`)

### Summary

The standalone tx-sender service exposes a JSON-RPC server (`send_tx`, `send_citrea_tx`) with zero authentication. Any party that can reach the bind address can insert arbitrary transactions — including with `FeePayingType::CPFP` — into the bridge's sending queue. The tx-sender will then attempt to fee-bump those transactions using the operator's wallet UTXOs, draining the fee wallet and starving legitimate challenge, disprove, and kickoff transactions of fee-bumping capacity, breaking bridge liveness.

### Finding Description

`crates/clementine-tx-sender/src/jsonrpc/server.rs` starts a plain `jsonrpsee` HTTP server with no authentication middleware:

```rust
let server: Server = ServerBuilder::default()
    .max_request_body_size(MAX_JSONRPC_REQUEST_BODY_SIZE)
    .build(bind_addr)
    .await ...;
``` [1](#0-0) 

The `send_tx` handler accepts a fully-caller-controlled `InsertTryToSendParams` — including `fee_paying_type`, `rbf_signing_info`, `cancel_outpoints`, `cancel_txids`, `activate_txids`, and `activate_outpoints` — and passes them directly to `TxSenderClient::insert_try_to_send` without any identity or authorization check:

```rust

    ...

            req.fee_paying_type,
            req.rbf_signing_info,
            &req.cancel_outpoints,
            ...

        .await
        .map_err(jsonrpc_err)?;
``` [2](#0-1) 

The bind address is configurable to `0.0.0.0`, making the server publicly reachable:

The `run.sh` script documents `TX_SENDER_JSONRPC_BIND` as a first-class configuration knob: [4](#0-3) 

By contrast, the gRPC servers for verifier and operator enforce mTLS and the `OnlyAggregatorAndSelf` interceptor when `client_verification = true`. The tx-sender JSON-RPC has no equivalent guard at any layer. [5](#0-4) [6](#0-5) 

### Impact Explanation

The tx-sender is the sole mechanism for broadcasting and fee-bumping every bridge transaction type: `Kickoff`, `Challenge`, `Disprove`, `Payout`, `ReadyToReimburse`, `Round`, `WatchtowerChallenge`, etc. [7](#0-6) 

For `FeePayingType::CPFP`, the tx-sender creates fee-payer UTXOs funded from the operator's wallet and tracks them in `tx_sender_fee_payer_utxos`: [8](#0-7) 

An attacker who submits a stream of valid Bitcoin transactions (spending their own UTXOs) with `FeePayingType::CPFP` forces the tx-sender to attempt to create fee-payer child transactions for each one, draining the operator's wallet. Once the wallet is exhausted:

- `Challenge` and `WatchtowerChallenge` transactions cannot be fee-bumped and fail to confirm within the challenge window.
- Fraudulent operator kickoffs go unchallenged.
- Operator collateral and bridged BTC are at risk.

The `cancel_txids` / `cancel_outpoints` fields also allow the attacker to register cancellation conditions that interfere with the tx-sender's internal dependency graph for legitimate bridge transactions. [9](#0-8) 

### Likelihood Explanation

- The JSON-RPC server is explicitly designed for standalone deployment and is documented with `TX_SENDER_JSONRPC_BIND=0.0.0.0` as a valid option.
- No API key, token, IP allowlist, or TLS is applied.
- The attacker needs only HTTP access to the bind address and a small amount of Bitcoin to submit valid CPFP transactions.
- The attack is fully unprivileged and requires no knowledge of bridge internals beyond the public JSON-RPC schema.

### Recommendation

1. **Add authentication** to the JSON-RPC server (e.g., a shared secret / bearer token, IP allowlist, or mTLS equivalent) before any `send_tx` or `send_citrea_tx` call is processed.
2. **Restrict the bind address** to `127.0.0.1` by default and emit a loud warning (or refuse to start) if `0.0.0.0` is configured without an explicit auth mechanism.
3. **Validate caller identity** inside `start_jsonrpc_server` using a middleware layer analogous to the `OnlyAggregatorAndSelf` interceptor used on the gRPC servers.

### Proof of Concept

```bash
# Attacker submits a valid CPFP transaction to the unauthenticated endpoint
# (TX_SENDER_JSONRPC_BIND=0.0.0.0, TX_SENDER_JSONRPC_PORT=3030)

curl -s -X POST http://<operator-ip>:3030 \
  -H 'Content-Type: application/json' \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "send_tx",
    "params": [{
      "tx_metadata": null,
      "signed_tx_hex": "<hex of valid attacker-signed tx>",
      "fee_paying_type": "cpfp",
      "rbf_signing_info": null,
      "cancel_outpoints": [],
      "cancel_txids": [],
      "activate_txids": [],
      "activate_outpoints": []
    }]
  }'
# Returns {"result": <try_to_send_id>, ...}
# Repeat at scale → operator fee wallet drained →
# challenge/disprove transactions cannot be fee-bumped →
# bridge liveness broken
```

The `send_tx` method is callable by any HTTP client with no credentials, directly analogous to the `afterLockUpdate` pattern in the seed report: a privileged state-mutating function (inserting transactions into the bridge's broadcast queue) is reachable by any unauthenticated party. /// Starts a JSON-RPC server exposing `send_tx` and `send_citrea_tx` methods.
/// `send_tx` and `send_citrea_tx` are transactional: it begins a DB transaction, calls
/// `TxSenderClient::insert_try_to_send` or `TxSenderClient::send_citrea_tx`, and commits on success.
pub async fn start_jsonrpc_server(
    tx_sender_client: TxSenderClient,
    bind_addr: SocketAddr,
) -> Result<TxSenderJsonRpcServer, BridgeError> {
    let server: Server = ServerBuilder::default()
        .max_request_body_size(MAX_JSONRPC_REQUEST_BODY_SIZE)
        .build(bind_addr)
        .await
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    let local_addr = server
        .local_addr()
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    let mut module = RpcModule::new(tx_sender_client.clone());
    module
        .register_async_method("send_tx", |params, client, _| async move {
            let req: InsertTryToSendParams = params.one().map_err(jsonrpc_err)?;

            let raw_tx = hex::decode(&req.signed_tx_hex).map_err(jsonrpc_err)?;
            let signed_tx: Transaction = consensus::deserialize(&raw_tx).map_err(jsonrpc_err)?;

            let mut dbtx = client.db.begin_transaction().await.map_err(jsonrpc_err)?;

            let try_to_send_id = client
                .insert_try_to_send(
                    &mut dbtx,
                    req.tx_metadata,
                    &signed_tx,
                    req.fee_paying_type,
                    req.rbf_signing_info,
                    &req.cancel_outpoints,
                    &req.cancel_txids,
                    &req.activate_txids,
                    &req.activate_outpoints,
                )
                .await
                .map_err(jsonrpc_err)?;

            client
                .db
                .commit_transaction(dbtx)
                .await
                .map_err(jsonrpc_err)?;

            Ok::<u32, ErrorObjectOwned>(try_to_send_id)
        })
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    // Citrea-specific RPCs.
    #[cfg(feature = "citrea")]
    {
        module
            .register_async_method("send_citrea_tx", |params, client, _| async move {
                let req: InsertCitreaRawTxParams = params.one().map_err(jsonrpc_err)?;

                let insertion_id = client
                    .send_citrea_tx(req.citrea_tx_request)
                    .await
                    .map_err(jsonrpc_err)?;

                Ok::<i64, ErrorObjectOwned>(insertion_id)
            })
            .map_err(|e| BridgeError::Eyre(e.into()))?;
    }

    let handle = server.start(module);

    Ok(TxSenderJsonRpcServer { handle, local_addr })
}

    pub async fn insert_try_to_send(
        &self,
        tx_metadata: Option<TxMetadata>,
        signed_tx: &Transaction,
        fee_paying_type: FeePayingType,
        rbf_signing_info: Option<RbfSigningInfo>,
        cancel_outpoints: &[OutPoint],
        cancel_txids: &[Txid],
        activate_txids: &[ActivatedWithTxid],
        activate_outpoints: &[ActivatedWithOutpoint],
    ) -> Result<u32, JsonRpcError> {
        let signed_tx_hex = consensus::encode::serialize_hex(signed_tx);

        let req = InsertTryToSendParams {
            tx_metadata,
            signed_tx_hex,
            fee_paying_type,
            rbf_signing_info,
            cancel_outpoints: cancel_outpoints.to_vec(),
            cancel_txids: cancel_txids.to_vec(),
            activate_txids: activate_txids.to_vec(),
            activate_outpoints: activate_outpoints.to_vec(),
        };

        self.inner
            .request::<u32, _>("send_tx", rpc_params![req])
            .await
    }
