### Title
`ReceivedOutput::read` deserializes an unbound `(offset, script_pubkey)` pair, letting forged outputs mis-attribute spends to arbitrary registered keys - (File: `networks/bitcoin/src/wallet/mod.rs`)

### Summary
`ReceivedOutput::read` accepts a `Scalar` offset, a `TxOut`, and an `OutPoint` purely as untrusted bytes, with no check that the offset is consistent with the output's `script_pubkey`. The ownership key is *recomputed* downstream as `xonly(script_pubkey) - offset·G` in `Output::key()` (`processor/src/networks/bitcoin.rs:112-122`). This is the same bug class as the unbound `l1Recipient` parameter in `cancelDeposit()`: a caller-supplied parameter that is not bound to the resource it claims to unlock, letting an attacker re-target attribution to a different principal.

### Finding Description
`Scanner::scan_transaction` produces `ReceivedOutput` by matching `output.script_pubkey` against the registered `scripts` map, which guarantees `script == p2tr(key + offset·G)` for honestly produced values (`networks/bitcoin/src/wallet/mod.rs:199-214`). However, `ReceivedOutput::read` (`networks/bitcoin/src/wallet/mod.rs:122-134`) performs no such consistency check: it reads any `Scalar` via `Secp256k1::read_F` and any `TxOut`/`OutPoint` via consensus decoding. The binding between `offset` and `script_pubkey` — the analog of the missing `msg.sender` binding in the report — exists only in the `Scanner`'s map and is silently dropped on deserialization.

Downstream, `Output::key()` trusts the deserialized pair: it parses the x-only key out of `script_pubkey`, asserts P2TR, and subtracts `offset·G` (`processor/src/networks/bitcoin.rs:112-122`). A `ReceivedOutput` read from attacker-controlled bytes is therefore accepted as belonging to whatever key `key()` computes, not the key the script actually pays to. The serialized `ReceivedOutput` is also what feeds `SignableTransaction::new`, where the offset re-keys the signing commitment per input — an offset that doesn't match the script key produces a valid-looking plan whose signature can never spend the output.

### Impact Explanation
An unprivileged party who can feed bytes to `ReceivedOutput::read`/`Output::read` (e.g., a forged or mutated stored/relayed output record) can cause funds to be reported received under a key that cannot spend them: a genuine Serai deposit output paired with a mismatched offset is attributed to a different registered/retired multisig key, and any spend constructed from it produces a threshold signature for the wrong tweaked key — permanently unspendable until manual recovery. This satisfies "funds reported received that are not spendable". Cross-key mis-attribution requires no discrete log: the attacker picks the offset freely and `key()` deterministically derives the mis-attributed key from public data.

### Likelihood Explanation
The reachability boundary is the `ReceivedOutput::read` / `Output::read` deserialization path, which the task's threat model explicitly lists as untrusted-byte-reachable. Exploitation requires only the ability to write or corrupt a serialized `ReceivedOutput` (choose `offset`, `output`, `outpoint` independently) — a public-input operation requiring no keys, no collusion, and no invalid curve points. It is a Medium: it causes mis-attribution/unspendability rather than direct theft, and requires a deserializer to consume attacker-influenced records rather than scanner-produced ones.

### Recommendation
Make the `offset → script_pubkey` binding intrinsic, as the corrected report binds `msg.sender` into the payload. Either (a) store the owning key in `ReceivedOutput` and have `key()` (or `read`) verify `p2tr_script_buf(key + offset·G) == output.script_pubkey`, rejecting the record on mismatch; or (b) drop `offset` from the serialized form and re-derive it via a `Scanner` lookup at read time, so the `scripts` map remains the single source of truth. Asserting `script.is_p2tr()` inside `read` is necessary but not sufficient — the equality check against the registered offset is what closes the substitution.

### Proof of Concept
```rust
// Given an honest output paying to key K with true offset o:
let honest: ReceivedOutput = scanner.scan_transaction(&tx).remove(0);

// Attacker serializes a forgery: same real TxOut/outpoint, arbitrary offset o'
let mut forged = Vec::new();
forged.extend(Scalar::ONE.to_bytes());          // attacker-chosen offset
forged.extend(serialize(honest.output()));      // real Serai script_pubkey
forged.extend(serialize(honest.outpoint()));    // real outpoint

// ReceivedOutput::read accepts it — no binding check exists
let fake = ReceivedOutput::read::<&[u8]>(&mut forged.as_ref()).unwrap();
// Output::key() now reports K + o·G - 1·G (a different registered/retired key)
// Any SignableTransaction built on `fake` signs with the wrong tweak => unspendable
```
