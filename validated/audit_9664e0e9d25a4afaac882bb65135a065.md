### Title
`ReceivedOutput::read` accepts outputs with no binding between `offset`, `script_pubkey`, and `outpoint`, letting untrusted bytes report received funds that are not spendable - ([File: networks/bitcoin/src/wallet/mod.rs])

### Summary
Analogous to CVE-2022-23612 (a request satisfied without sanitizing which resource it resolves to), `ReceivedOutput::read` deserializes an arbitrary attacker-supplied triple — scalar `offset`, `TxOut`, `OutPoint` — and returns it as a "received output" without any check that the `TxOut`'s `script_pubkey` actually corresponds to the wallet's key plus the claimed offset (i.e., matches one of the `Scanner`-registered scripts). A `ReceivedOutput` produced by `Scanner::scan_transaction` is guaranteed to satisfy `output.script_pubkey == p2tr(key + offset*G)` because the scanner only emits outputs it matched against registered scripts, but `read` provides no such guarantee for deserialized data.

### Finding Description
`ReceivedOutput::read` performs only canonical-scalar validation on the offset and consensus decoding of the `TxOut`/`OutPoint`; it never validates that the output is even P2TR, let alone that it pays to a key derivable from `offset`:

```rust
// networks/bitcoin/src/wallet/mod.rs
pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
}
``` [1](#0-0) 

By contrast, the legitimate construction path in `Scanner::scan_transaction` only emits outputs whose `script_pubkey` is present in `self.scripts`, binding each output to a known offset: [2](#0-1) 

`SignableTransaction::new` / `TransactionSignMachine` then treat every `ReceivedOutput` in `inputs` as a spendable input, deriving per-input signing keys via `offset` and committing to `Prevouts::All`: [3](#0-2) 

### Impact Explanation
An attacker who can feed crafted bytes into `ReceivedOutput::read` (the deserialization sink explicitly exposed for untrusted data) can cause a consumer to accept a "received" output that pays to an arbitrary script — e.g., a P2TR key the multisig cannot sign for, an unrelated script type, or an outpoint that does not exist on-chain. Consequences include: wallets reporting/queueing deposits that are unspendable, `SignableTransaction` building transactions around inputs it can never actually unlock, and FROST signing sessions being burned on `Prevouts::All`-committed sighashes for a transaction that can never be valid. This is the direct structural analog of the OpenMRS flaw: bytes from an untrusted source are resolved into a sensitive resource reference (a claimed spendable output) without sanitizing the resolution.

### Likelihood Explanation
Reachable by any unprivileged party who can supply serialized `ReceivedOutput` blobs to a component that deserializes them (the API is `pub` and intended for persisted/transferred outputs). It requires a consumer that trusts deserialized `ReceivedOutput`s as spendable inputs rather than re-deriving them via `Scanner`, which the type's own invariants invite. Impact is constrained to integrity of the funding/spend pipeline (no direct key leakage), placing this at Medium.

### Recommendation
Bind deserialization to the same invariant as scanning. Either make `ReceivedOutput` construction private (only `Scanner` may create it) and document that `read` output must be re-validated, or add a `ReceivedOutput::verify(key)` / `scan`-consistent check that recomputes `p2tr_script_buf(key + GENERATOR * offset)` and compares it to `output.script_pubkey`, rejecting mismatches. Consumers should re-scan rather than trust decoded `TxOut`/`OutPoint`/`offset` triples.

### Proof of Concept
```rust
use bitcoin::{TxOut, OutPoint, Amount, ScriptBuf, absolute::LockTime, transaction::Version, Transaction, Txid};
use ciphersuite::{Ciphersuite, Secp256k1, group::ff::Field};
use std::io::Write;
use bitcoin::consensus::Encodable;

// Craft bytes claiming an output paying to an arbitrary script
// (e.g. OP_RETURN) under offset 0.
let mut buf = vec![];
buf.extend(Secp256k1::F::ZERO.to_repr().as_ref()); // offset = 0
TxOut { value: Amount::from_sat(1_000_000), script_pubkey: ScriptBuf::new_op_return(&[]) }
  .consensus_encode(&mut buf).unwrap();
OutPoint { txid: Txid::all_zeros(), vout: 0 }
  .consensus_encode(&mut buf).unwrap();

let output = ReceivedOutput::read(&mut buf.as_slice()).unwrap();
// `output` is accepted and reports value() == 1_000_000 sat,
// despite paying to an unspendable OP_RETURN and never matching
// any Scanner-registered script for any key.
```

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
