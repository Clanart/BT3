This confirms the mechanism. `create_payout_txhandler` (`core/src/builder/transaction/operator_reimburse.rs:407-436`) builds the payout tx with only a **single input** spent via `SpendPath::KeySpend` using the withdrawer's own `SinglePlusAnyoneCanPay` signature over just that one input/output pair, and separately appends an OP_RETURN output containing an arbitrary `operator_xonly_pk` chosen by whoever completes the transaction:### Title
Payout attribution trusts an unauthenticated OP_RETURN, letting anyone frame an operator into being reimbursed for a payout it never funded - ([File: core/src/verifier.rs])

### Summary
`Verifier::update_finalized_payouts` attributes a payout to whichever `operator_xonly_pk` happens to be encoded in the first OP_RETURN output of the transaction that ends up spending the tracked withdrawal UTXO, with no check that this pubkey belongs to the party who actually funded the payout output. Because the withdrawer's authorization signature uses `SIGHASH_SINGLE|ANYONECANPAY`, anyone (including the withdrawer/attacker) can complete and broadcast that transaction with an arbitrary OP_RETURN, causing an unrelated honest operator to be credited and later reimbursed for a payout it never made.

### Finding Description
The binding this system is supposed to preserve is:
`payout_payer_operator_xonly_pk == xonly_pk(entity whose funds actually left to pay the withdrawal output)`.

In practice `core/src/verifier.rs` `update_finalized_payouts` (lines 2283-2353) only recovers whatever bytes happen to sit in the payout tx's OP_RETURN: [1](#0-0) 
and stores it unconditionally via `Database::update_payout_txs_and_payer_operator_xonly_pk` [2](#0-1) .

The payout tx itself (`create_payout_txhandler`, `core/src/builder/transaction/operator_reimburse.rs:407-436`) has a single Key-Spend input authorized by the withdrawer's own signature, plus a payer-supplied OP_RETURN output that is *not* covered by that signature: [3](#0-2) 

Crucially, this signature is required to use `SinglePlusAnyoneCanPay` (enforced in `parse_withdrawal_sig_params`): [4](#0-3) 

`SIGHASH_SINGLE|ANYONECANPAY` only commits to input #0 and the matching output #0 (the user's payment). It does **not** commit to any other input or output added to the finished transaction — including whichever additional funding inputs are used to cover the payout amount, the fee, or the OP_RETURN output containing the claimed `operator_xonly_pk`. Since the withdrawer (an unprivileged attacker per the rules, who can legitimately call Citrea's `withdraw()` and therefore knows/controls this signature and the `withdrawal_utxo` bytes) can complete this transaction themselves — funding the payout amount from their own wallet (paying themselves) — and attach an OP_RETURN naming an arbitrary honest operator A, this transaction is fully valid Bitcoin and will be mined.

When `update_finalized_payouts` scans the finalizing block, it finds this transaction spends the tracked `withdrawal_utxo` (via `get_payout_txs_for_withdrawal_utxos`, matched purely by outpoint) and blindly parses A's pubkey from the spoofed OP_RETURN, writing `payout_payer_operator_xonly_pk = A` into the `withdrawals` table.

`PayoutCheckerTask::run_once` (which queries `get_first_unhandled_payout_by_operator_xonly_pk` filtered by the operator's own key) then picks this row up for operator A and calls `Operator::handle_finalized_payout`, kicking off the kickoff/reimbursement flow for a payout A never funded: [5](#0-4) 

Downstream, `Verifier::is_kickoff_malicious` only checks that the recorded `operator_xonly_pk` equals `kickoff_data.operator_xonly_pk`: [6](#0-5) 
and the zk bridge circuit itself re-derives `operator_xonlypk` from the very same untrusted OP_RETURN and only checks structural/SPV/storage-proof consistency, never that the named operator actually supplied the funds: [7](#0-6) 

None of the existing guards (`is_kickoff_malicious`, the bridge circuit's SPV/storage-proof checks, `SECP.verify_schnorr` on the withdrawer's own signature) validate that the OP_RETURN pubkey corresponds to whoever actually paid — they only validate that the withdrawal outpoint/amount/address are correct and that the claiming kickoff's operator key matches the DB row, which was itself derived from attacker-controlled data.

### Impact Explanation
This directly matches the listed Critical category "an operator credited/reimbursed for a payout it never funded." An attacker (the withdrawer) can self-fund their own withdrawal payout (a wash for themselves) while stamping an arbitrary honest operator's xonly pubkey into the OP_RETURN. That operator's automation will subsequently drive a kickoff and, absent challenge, receive the Reimburse output (`create_reimburse_txhandler`, `core/src/builder/transaction/operator_reimburse.rs:341-385`) drawing real BTC from the `MoveToVaultTx` deposit UTXO — funds the named operator never advanced. This is repeatable across every withdrawal and every operator, is a pure race against the intended operator's own `withdraw()` broadcast (whoever's completed transaction is mined first wins, since only one tx can spend the withdrawal UTXO), and requires no verifier/operator privileges, keys, or collateral.

### Likelihood Explanation
Preconditions are all satisfied by an unprivileged actor: the attacker (as the withdrawer) already knows the `withdrawal_utxo`, the `SinglePlusAnyoneCanPay` signature, and the withdrawal parameters, because they generated the withdrawal themselves via Citrea's `withdraw()` and/or via `WithdrawParams`/`OptimisticWithdrawParams` gRPC flows. Constructing the completing transaction requires only standard Bitcoin transaction-building knowledge and funding the withdrawal amount from a wallet the attacker controls (a wash, since the attacker is also the withdrawal recipient) plus normal miner fees. The race against the honest operator's own broadcast is winnable with higher fees or timing. This is fully reproducible in a `regtest`-based `cargo test` without mainnet or a live Citrea network.

### Recommendation
Do not trust the OP_RETURN payer pubkey as an unauthenticated attribution signal. Either (a) require operators to additionally sign a distinct, operator-specific input (e.g., an extra input from the operator's own wallet or a dedicated operator-controlled UTXO) whose presence/signature the verifier checks before attributing the payout to that operator, or (b) require that the fee-paying/completing input(s) of the payout tx be spendable only by the specific operator's key (so that ANYONECANPAY cannot let a third party substitute a different operator's OP_RETURN), or (c) have `update_finalized_payouts`/`is_kickoff_malicious` additionally verify that the operator claiming reimbursement actually contributed real value to the payout output (e.g., by checking that at least one of the payout tx's non-`ANYONECANPAY`-exempt inputs is controlled by the claimed operator xonly pubkey).

                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
