### Title
GET request double-delivery: `onGetResponse` and `onGetTimeout` can both fire for the same request because `dispatchIncoming(GetResponse)` never clears `_requestCommitments` - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatchIncoming(GetResponse, address)` pays the relayer fee for a successfully delivered GET response but never deletes the corresponding `_requestCommitments[commitment]` entry. `HandlerV2.handleGetRequestTimeouts` — the entry point used to later deliver a timeout for the same request — never checks the source chain's own `responseReceipts` mapping before invoking `IApp.onGetTimeout`. The only "already delivered" guard it uses is a non-membership proof against the destination chain's `RESPONSE_RECEIPTS_STORAGE_PREFIX` slot, a slot that GET requests never populate on the destination in the first place, since GET responses are delivered to the source purely via a storage proof (the destination never "processes" a GET). The combination lets a request that already received `onGetResponse` also receive `onGetTimeout`, once its `timeout_timestamp` is exceeded on the destination host's timestamp.

### Finding Description
`dispatchIncoming(GetResponse memory response, address relayer)`: [1](#0-0) 
sets `_responseReceipts[commitment]` (source-chain replay guard for `handleGetResponses`) and, on a successful `onGetResponse` callback, pays the relayer fee out of `_requestCommitments[commitment].fee` — but it never deletes `_requestCommitments[commitment]`. Compare this to the sibling timeout dispatchers, which explicitly `delete _requestCommitments[commitment]` as "replay protection" before invoking the app callback: [2](#0-1) 

`HandlerV2.handleGetRequestTimeouts` is the only gate standing between a relayer and `host.dispatchTimeOut(GetRequestTimeout...)`: [3](#0-2) 
It checks `meta.sender == address(0)` (i.e. whether `_requestCommitments[commitment]` still exists — which it does, because `dispatchIncoming(GetResponse)` never cleared it) and a non-membership proof of `RESPONSE_RECEIPTS_STORAGE_PREFIX || commitment` on the *destination's* state trie. GET requests are stateless reads that are answered by proving destination storage directly back to the source (`handleGetResponses`); the destination chain never writes any `_responseReceipts` entry for a GET, so that non-membership check is trivially satisfied regardless of whether the response was already delivered on the source. There is no check anywhere in `handleGetRequestTimeouts`/`dispatchTimeOut(GetRequestTimeout...)` against the source chain's own `_responseReceipts[commitment]`, which is the mapping that actually records "this GET was already answered."

The net effect: once `request.timeout()` has elapsed relative to the destination's reported timestamp, any permissionless relayer can submit a `GetTimeoutMessage` for a commitment whose GET response was already successfully delivered, causing `IApp.onGetTimeout` to be invoked on an application that already processed `IApp.onGetResponse` for the exact same request.

### Impact Explanation
ISMP's contract with `IApp` implementers is exactly-once delivery per request: either a response or a timeout, never both. Any application built on GET requests (intent settlement confirmations, paymaster/escrow release logic, bandwidth/reward accounting that finalizes state in `onGetResponse` and reverses/refunds in `onGetTimeout`) can be driven into a double-processed state — e.g., an app that releases funds in `onGetResponse` and refunds the payer in `onGetTimeout` would pay out twice. This is a logic attack / duplicate-settlement primitive at the protocol layer, exploitable by any unprivileged relayer using genuine proofs; it does not require a malicious relayer, prover, or admin — only that the response's genuine timeout condition eventually holds true relative to the destination host's timestamp.

### Likelihood Explanation
Reaching this path requires only: (1) a legitimately delivered `GetResponse` via `handleGetResponses`, and (2) later constructing a normal `GetTimeoutMessage` with a valid non-membership proof against the destination's untouched `RESPONSE_RECEIPTS_STORAGE_PREFIX` slot (trivial, since that slot is never written for GETs) once `request.timeout()` has elapsed. Both are standard, permissionless relayer operations already exercised by the existing self-relay/timeout tooling in the SDK, making this reachable without any privileged or adversarial infrastructure assumption.

### Recommendation
In `dispatchIncoming(GetResponse memory response, address relayer)`, delete `_requestCommitments[commitment]` immediately after (or as part of) successful delivery, mirroring the replay protection already used in `dispatchTimeOut`. Additionally, `handleGetRequestTimeouts` (or `dispatchTimeOut(GetRequestTimeout...)`) should explicitly reject timeouts for commitments where `_responseReceipts[commitment]` is already set on the source host, independent of the destination-side non-membership proof.

### Proof of Concept
1. App `A` dispatches a `GetRequest` with `timeout_timestamp = T` and a relayer fee `F`; `_requestCommitments[commitment] = {sender: A, fee: F}` is recorded on the source `EvmHost`.
2. Before `T`, a relayer submits a valid `GetResponseMessage`; `HandlerV2.handleGetResponses` calls `host.dispatchIncoming(response, relayer)`, which sets `_responseReceipts[commitment]`, calls `A.onGetResponse(...)` successfully, and pays `F` to the relayer — but leaves `_requestCommitments[commitment]` intact (`evm/src/core/EvmHost.sol:824-847`).
3. After the destination host's reported timestamp passes `T`, any relayer builds a `GetTimeoutMessage` for the same request with a non-membership proof of the (never-written) `RESPONSE_RECEIPTS_STORAGE_PREFIX || commitment` slot on the destination — this proof succeeds trivially since GET requests never write that slot on the destination.
4. `HandlerV2.handleGetRequestTimeouts` passes all its checks (`meta.sender != address(0)` because `_requestCommitments[commitment]` was never deleted) and calls `host.dispatchTimeOut(GetRequestTimeout(request, relayer2), meta, commitment)` (`evm/src/core/HandlerV2.sol:293-321`), which invokes `A.onGetTimeout(request)`.
5. App `A` now processes both `onGetResponse` and `onGetTimeout` for the identical GET request, breaking the exactly-once ISMP delivery invariant.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    /**
     * @dev Check the provided Get request timeouts, then dispatch to modules
     * @param host - Ismp host
     * @param message - batch get request timeouts
     */
    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
