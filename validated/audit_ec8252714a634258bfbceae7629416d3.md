### Title
Economically unspendable dust outputs are scanned and accepted as spendable inputs - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
Serai’s Bitcoin wallet treats relay-dust as spendable value: `Scanner::scan_transaction` returns any output whose `script_pubkey` matches, regardless of amount, while `SignableTransaction::new` only enforces `DUST` on payments/change and never filters inputs by whether they are worth spending. An unprivileged sender can therefore create recognized dust deposits that later consume more fee than their value when included. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`Scanner::scan_transaction` pushes a `ReceivedOutput` solely on `self.scripts.get(&output.script_pubkey)`, with no `output.value` check. `SignableTransaction::new` sums every supplied `ReceivedOutput` into `input_sat`, creates a `TxIn` for each, and rejects only payment outputs below `DUST`; change is emitted only when `value >= DUST`, but inputs are never subjected to an economic-spendability check. Each Taproot input is modeled as fixed witness/weight cost, so a 546-sat input still adds its input weight to `needed_fee`. [4](#0-3) [5](#0-4) [6](#0-5) [7](#0-6) 

### Impact Explanation
Funds can be reported received that are not economically spendable: a received output can be consensus-valid yet worth less than the incremental fee required to spend it. When such outputs are supplied to `SignableTransaction::new`, the wallet either signs a transaction whose fee is inflated by net-negative inputs or fails with `NotEnoughFunds`/policy limits after dust accumulates. This mirrors the dust-CDP class: the protocol permits positions/UTXOs small enough that redemption or spending becomes unprofitable. [8](#0-7) [9](#0-8) [10](#0-9) 

### Likelihood Explanation
Any party who knows a registered deposit/branch/change script can send a low-value P2TR output to it; `register_offset` documents that offsets are registered to scan for derived scripts, and `scan_transaction` accepts matching scripts without considering value. The issue requires only normal on-chain payments and ordinary wallet operation that later consumes scanned outputs. [11](#0-10) [1](#0-0) 

### Recommendation
Define a network-level economically spendable threshold above relay `DUST` and apply it to inbound scanning and input admission: ignore or quarantine `output.value` below that threshold in `Scanner`, and reject `ReceivedOutput`s whose value is less than the marginal fee to spend them in `SignableTransaction::new`. Keep consensus dust checks for created outputs, but do not equate relay-minimum with profitable spendability. [2](#0-1) [4](#0-3) 

### Proof of Concept
1. Register or learn a Serai P2TR script via `Scanner::new`/`register_offset`. Send it a confirmed output of `546` satoshis. `scan_transaction` returns it as a `ReceivedOutput` because only `script_pubkey` is checked. Build `SignableTransaction::new(vec![dust_output], &payments, change, None, fee_per_vbyte)`; the dust input is included in `tx_ins` and `input_sat` while `needed_fee` grows by the modeled input weight. At moderate `fee_per_vbyte`, the added input costs more than 546 sats, reducing spendable value or triggering `NotEnoughFunds`. [12](#0-11) [4](#0-3) [13](#0-12) [14](#0-13)

  ///
  /// Due to Bitcoin's requirement that points are even, not every offset may be used.
  /// If an offset isn't usable, it will be incremented until it is. If this offset is already
  /// present, None is returned. Else, Some(offset) will be, with the used offset.
  ///
  /// This means offsets are surjective, not bijective, and the order offsets are registered in
  /// may determine the validity of future offsets.
  ///
  /// The offsets registered must be securely generated. Arbitrary offsets may introduce a script
  /// path into the output, allowing the output to be spent by satisfaction of an arbitrary script
  /// (not by the signature of the key).
  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
