## Analysis

The reported bug's core invariant is: **a privileged party can accept/retain value while bypassing the authenticity check that should gate irreversible state changes**. The local analog in this repo is not in the intent-escrow release path (which is authenticated per-module via `_instance(request.source) == module`), but in the **governance/host-management branch of `onAccept()`** in the IntentGateway contracts.

### Title
Missing `from`-field authentication on IntentGateway governance messages allows unauthenticated contract upgrade/hijack - (File: `evm/src/apps/intentsv2/ExtrinsicIntents.sol`)

### Summary
`onAccept()` authenticates `RedeemEscrow`/`RefundEscrow` requests by checking that `request.from` matches the registered gateway instance for `request.source`. But for `NewDeployment`, `UpdateParams`, `SweepDust`, and `UpgradeContract` — the governance/host-management branch — it only checks that `request.source` equals the Hyperbridge chain id, and never checks `request.from` at all. [1](#0-0) 

### Finding Description
`_authenticate()` verifies the `from` module address against the registered instance, but is only invoked for the escrow-release kinds: [2](#0-1) 

For the governance kinds, the only check performed is:
```
if (keccak256(incoming.request.source) != keccak256(IDispatcher(host()).hyperbridge())) revert Unauthorized();
```
This checks *which chain* the message came from, not *which pallet/module on that chain* dispatched it. On the Substrate side, `request.source` is populated unconditionally by `pallet-ismp`'s `dispatch_request` to `self.host_state_machine()` for **every** dispatching pallet, regardless of which pallet or origin triggered it: [3](#0-2) 

Any pallet on the Hyperbridge chain configured with an `IsmpDispatcher` and a signed (non-privileged) extrinsic can build a `DispatchPost` with an attacker-chosen `to` (the IntentGateway address on any destination) and attacker-chosen `body`. The repo's own example pallet demonstrates this exact permissionless pattern — `ensure_signed(origin)` is the only gate, and `to`/`body`/`dest` are fully caller-supplied: [4](#0-3) 

Because `onAccept()` never checks `request.from` for governance kinds, a message dispatched by *any* such pallet — not just the legitimate governance/host-executive module — will pass authentication as long as `request.source` resolves to the Hyperbridge chain. An attacker can therefore craft `body = bytes1(RequestKind.UpgradeContract) ++ abi.encode(maliciousImpl, maliciousInitCalldata)` and have it accepted, triggering:

```
ERC1967Utils.upgradeToAndCall(newImpl, initData);
``` [5](#0-4) 

This is a full proxy takeover of the IntentGateway, giving the attacker control of every escrowed user asset (`_orders[commitment][token]` balances) sitting in the contract — directly analogous to the "recipient can rug and keep funds with no recourse" bug class, but escalated to unauthenticated remote code execution/asset theft rather than mere fund retention.

The same missing `from` check exists in the Tron variant: [6](#0-5) 

### Impact Explanation
A successful `UpgradeContract` message lets the attacker replace the IntentGateway implementation with malicious logic that drains all escrowed `_orders` balances for every open order across every state machine that instance serves — false state acceptance leading directly to theft of bridged/escrowed funds, matching the bounty's "unauthorized transaction or execution" and "false proof/state acceptance" categories. `SweepDust` and `NewDeployment` are lesser but still real: `SweepDust` sends the protocol's swept balances to an attacker-chosen beneficiary, and `NewDeployment` can redirect the trusted instance address for a state machine, corrupting the `_instance()` lookup used everywhere else (including the "authenticated" `RedeemEscrow`/`RefundEscrow` path) to point at an attacker-controlled contract, indirectly compromising the very check that seemed strong.

### Likelihood Explanation
The exploit path requires only: (1) a signed, unprivileged account on the Hyperbridge chain, and (2) access to any pallet configured with `IsmpDispatcher` that permits caller-controlled `to`/`body`/`dest` (the repo demonstrates this exact shape as a first-class extension pattern for pallets, not a hidden edge case). No relayer collusion, no admin key, no consensus/state-proof forgery is needed — the message is a legitimate ISMP-delivered message; the flaw is purely in the destination contract's authentication logic accepting it based on chain identity alone.

### Recommendation
In `onAccept()`, require `request.from` to equal a governance-registered module id (e.g., the host-executive/token-governor module address) for `NewDeployment`, `UpdateParams`, `SweepDust`, and `UpgradeContract`, exactly as is already done via `_authenticate()`/`_instance()` for `RedeemEscrow`/`RefundEscrow`. Do not treat "source chain == hyperbridge" as sufficient authorization for privileged actions; bind to the specific module identifier that is permitted to issue them.

### Proof of Concept
1. On the Hyperbridge chain, any signed account calls a pallet extrinsic that internally does:
```rust
let post = DispatchPost {
    dest: StateMachine::Evm(<intentgateway_chain_id>),
    from: <attacker_pallet_module_id>,
    to: <IntentGateway_address_bytes>,
    timeout: 0,
    body: [RequestKind.UpgradeContract as u8]
        .concat(abi_encode(malicious_impl, malicious_init_calldata)),
};
dispatcher.dispatch_request(DispatchRequest::Post(post), fee)?;
```
2. `pallet-ismp`'s `dispatch_request` sets `request.source = self.host_state_machine()` unconditionally (`modules/pallets/ismp/src/dispatcher.rs:130`).
3. Once relayed and delivered, `IntentGateway.onAccept()` checks only `keccak256(incoming.request.source) == keccak256(IDispatcher(host()).hyperbridge())`, which is true, and never checks `incoming.request.from`.
4. `ERC1967Utils.upgradeToAndCall(newImpl, initData)` executes, handing the attacker full control of the contract holding all escrowed order funds.

    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost {
        RequestKind kind = RequestKind(uint8(incoming.request.body[0]));
        if (kind == RequestKind.RedeemEscrow || kind == RequestKind.RefundEscrow) {
            authenticate(incoming.request);
            WithdrawalRequest memory body = abi.decode(incoming.request.body[1:], (WithdrawalRequest));
            return withdraw(body, kind == RequestKind.RefundEscrow);
        }

        // only hyperbridge is permitted to perfom these actions
        if (keccak256(incoming.request.source) != keccak256(IDispatcher(host()).hyperbridge())) revert Unauthorized();
        if (kind == RequestKind.NewDeployment) {
            NewDeployment memory body = abi.decode(incoming.request.body[1:], (NewDeployment));
            _instances[keccak256(body.stateMachineId)] = body.gateway;

            emit NewDeploymentAdded({stateMachineId: body.stateMachineId, gateway: body.gateway});
        } else if (kind == RequestKind.UpdateParams) {
            // Decode the body which includes optional destination-specific protocol fee updates
            ParamsUpdate memory update = abi.decode(incoming.request.body[1:], (ParamsUpdate));
            emit ParamsUpdated({previous: _params, current: update.params});
            _params = update.params;

            // Update destination-specific protocol fees if provided
            for (uint256 i; i < update.destinationFees.length;) {
                bytes32 stateMachineId = update.destinationFees[i].stateMachineId;
                uint256 feeBps = update.destinationFees[i].destinationFeeBps;
                _destinationProtocolFees[stateMachineId] = feeBps;

                unchecked {
                    ++i;
                }
                emit DestinationProtocolFeeUpdated(stateMachineId, feeBps);
            }
        } else if (kind == RequestKind.SweepDust) {
            SweepDust memory req = abi.decode(incoming.request.body[1:], (SweepDust));

            uint256 outputsLen = req.outputs.length;
            for (uint256 i; i < outputsLen;) {
                TokenInfo memory info = req.outputs[i];
                address token = address(uint160(uint256(info.token)));
                uint256 amount = info.amount;

                if (token == address(0)) {
                    (bool sent,) = req.beneficiary.call{value: amount}("");
                    if (!sent) revert InsufficientNativeToken();
                } else {
                    (bool success,) = token.call(abi.encodeWithSelector(IERC20.transfer.selector, req.beneficiary, amount));
                    if (!success) revert TransferFailed();
                }
                unchecked {
                    ++i;
                }
                emit DustSwept(token, amount, req.beneficiary);
            }
        }
    }
