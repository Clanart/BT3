### Title
Gasless proposer can suffer unrecoverable value loss when `LendTx` is unconditionally applied before `SwapTx` repayment can fail on execution - ([File: kaiax/gasless/impl/builder.go])

### Summary
The `kaiax/gasless` module implements KIP-247 gasless transactions by having the block proposer front real KAIA to a user via a `LendTx`, expecting to be repaid through the user's `SwapTx` executed against a `GaslessSwapRouter` AMM. The repay amount is fixed at pool-admission time from `swapTx.Fee()` / `GasPrice()`, while the actual token-for-KAIA exchange happens later on-chain against a live AMM price. Because the `LendTx` is placed first and unconditionally in the bundle, ahead of the `SwapTx` that is supposed to fund it, a price move (or self-induced slippage) between validation and execution can cause the `SwapTx` to revert against its own `minAmountOut` check while the `LendTx`'s value transfer to the user has already been irreversibly committed - directly mirroring the report's "market insolvency from a quick price move during high congestion" scenario, but concretely instantiated as proposer fund loss.

### Finding Description
`kaiax/gasless` docs state the mechanism explicitly: "the gas fee of gasless transaction's is funded by block proposer... and user repays the lent amount during gasless swap" [1](#0-0) . The block-building bundling logic constructs the bundle as `[LendTxGenerator, ApproveTx?, SwapTx]`, where the `LendTx` is prepended and included first: [2](#0-1) 

`repayAmount`/`lendAmount` are computed purely from the transactions' declared gas fee fields (`Fee()`), not from any confirmation that the AMM swap will actually yield that much value: [3](#0-2) 

The only economic safety checks are performed in `VerifyExecutable`/`checkBalanceForSwap`, which are static/pool-time checks: `minAmountOut >= amountRepay` and `amountIn >= gsr.getAmountIn(minAmountOut)` computed against the *current* router state at admission time, gated by optional config flags (`ShouldCheckSwapAmount`, `ShouldCheckToken`): [4](#0-3) [5](#0-4) 

Because the on-chain `swapForGas` call independently re-checks `minAmountOut` against the *actual* AMM output at execution time (confirmed by test assertions such as `"insufficient minAmountOut"` reverting on-chain), any price movement of the swap token between mempool admission/bundling and the point the `SwapTx` actually executes in the block can cause the swap to revert: [6](#0-5) 

Since `LendTx` is a separate, already-mined transaction that unconditionally transfers KAIA to the user's address before `SwapTx` runs, a reverted `SwapTx` does not undo the `LendTx` value transfer. The user keeps the lent KAIA with no repayment, and the block proposer absorbs the loss - functionally identical to a lending market becoming "insolvent" because collateral/repayment could not be realized before the debt was extended.

### Impact Explanation
This allows a gasless-transaction sender (an unprivileged, permissionless role explicitly in scope) to extract real KAIA value from the block proposer with no repayment, by causing their own `SwapTx` to revert after the `LendTx` has already paid out. This is a concrete, reachable "fee-delegation/gasless settlement theft" (unauthorized value movement from the proposer to the attacker), which the validation rules explicitly call out as an acceptable impact category.

### Likelihood Explanation
The `IsExecutable`/`checkBalanceForSwap` checks re-run at block-building time (in `ExtractTxBundles`) narrow, but do not eliminate, the window: they check declared amounts against the *current* on-chain router quote, but do not simulate the actual `swapForGas` execution against the state the swap will run in (which can differ due to other transactions ordered earlier in the same block, including transactions from the same attacker, or normal AMM price drift within the block-building window). Because `ShouldCheckSwapAmount`/`ShouldCheckToken` are configurable and the repay amount is derived only from gas fee accounting (not validated against a simulated swap outcome), the safety of `LendTx` depends entirely on `SwapTx` succeeding later, which is not guaranteed.

Note: I was not able to fully inspect `work/worker.go`'s `shouldDiscardBundle` function body (only reference locations were found, not its full implementation) to conclusively confirm whether any block-level atomicity/rollback exists that could mitigate this by discarding a bundle if an earlier included tx in the *same* bundle fails, versus only guarding against previously-processed *target* bundles failing. This is a gap in my verification and should be validated directly against `work/worker.go`'s `shouldDiscardBundle` and the surrounding `ApplyTransactions` loop before treating this as fully confirmed.

### Recommendation
- Make `LendTx` inclusion conditional/atomic with `SwapTx` success (e.g., only broadcast/apply `LendTx` if a simulated dry-run of the swap at current block state guarantees at least `amountRepay` output, or restructure so repayment is verified/collected before or atomically with the lend).
- Re-simulate the actual swap execution (not just a router quote call) immediately before committing the bundle in the same block context, accounting for any transactions already applied earlier in that block.
- Consider requiring the proposer to recover the lent amount from the swap token balance directly rather than relying on the `SwapTx` succeeding independently.

### Proof of Concept
1. Attacker (gasless user) submits a valid `ApproveTx` + `SwapTx` pair that passes `VerifyExecutable`/`checkBalanceForSwap` at pool-admission time, with `minAmountOut` set at the current AMM quote.
2. Before/while the proposer builds the block containing this bundle, the attacker (or market conditions) shifts the AMM pool price for the swap token (e.g., via another transaction ordered earlier in the same block) such that the actual output of `swapForGas` would fall below `minAmountOut`.
3. The block proposer's bundle `[LendTxGenerator, ApproveTx, SwapTx]` is built per [2](#0-1) ; `LendTx` executes first and unconditionally transfers `lendAmount` KAIA to the attacker.
4. `SwapTx` executes and reverts on-chain with `"insufficient minAmountOut"` (as demonstrated for the legitimate-rejection case in [6](#0-5) ).
5. The attacker retains the KAIA received from `LendTx` with no repayment, at the block proposer's expense.

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}
