### Title
Forged `ReceivedOutput` bytes report nonexistent Bitcoin as spendable funds - ([File: `networks/bitcoin/src/wallet/mod.rs`])

### Summary
`ReceivedOutput` is documented as “a spendable output,” but `ReceivedOutput::read` accepts an arbitrary scalar offset, `TxOut`, and `OutPoint` without proving that the outpoint exists, carries the claimed amount, or belongs to the referenced output. [1](#0-0) [2](#0-1) 

### Finding Description
An unprivileged party can serialize an arbitrary `OutPoint`, an arbitrary satoshi amount, and a Taproot script derived from the wallet’s public group key, then feed those bytes to `ReceivedOutput::read`. [2](#0-1) 

The decoder returns the forged value as a `ReceivedOutput`, and `value()` exposes the attacker-selected amount without any ledger authentication. [3](#0-2) 

`SignableTransaction::new` then trusts both the claimed output value and claimed outpoint when constructing inputs. [4](#0-3) 

The forged `TxOut` is retained as the transaction’s `Prevouts::All` commitment and is committed into the Taproot sighash during signing. [5](#0-4) [6](#0-5) 

`multisig` only checks that the supplied script equals the derived Taproot script for the supplied offset; it does not authenticate that the claimed `OutPoint` exists or funds that script. [7](#0-6) 

### Impact Explanation
A forged input can be reported as Bitcoin balance even though the referenced UTXO is nonexistent or carries a different amount. [3](#0-2) 

If the deserialized value is used for accounting before independent chain verification, an attacker can obtain credit for funds that were never received or trigger threshold signing of a transaction that can never be accepted by Bitcoin. [4](#0-3) [6](#0-5) 

### Likelihood Explanation
The attacker only needs the wallet’s public Taproot script or group key and control over bytes passed to `ReceivedOutput::read`; using offset zero makes the forged script equal the wallet’s normal external address. [8](#0-7) [2](#0-1) 

The forged object passes the only spendability check performed before signing because the attacker can legitimately derive the expected Taproot script without knowing the private key. [7](#0-6) 

### Recommendation
Treat `ReceivedOutput::read` as an unauthenticated transport encoding rather than proof of receipt, and only create spendable `ReceivedOutput` values through `Scanner::scan_transaction` or equivalent authenticated blockchain data. [9](#0-8) 

Rename or gate the public decoder as a raw representation type, require callers to authenticate the outpoint and value against confirmed blockchain state before accounting for it, and validate the output script against the expected key before accepting it. [2](#0-1) [7](#0-6) 

### Proof of Concept
```rust
// `keys` is the wallet's ThresholdKeys<Secp256k1>.
let offset = Scalar::ZERO;

// Attacker derives the wallet's normal external Taproot script.
let script = p2tr_script_buf(keys.group_key()).unwrap();

// The outpoint does not need to exist.
let fake_outpoint = OutPoint {
  txid: attacker_selected_txid,
  vout: 0,
};

// The amount is attacker-controlled.
let fake_txout = TxOut {
  value: Amount::from_sat(100_000),
  script_pubkey: script,
};

// Encode exactly what ReceivedOutput::read consumes:
// scalar || consensus TxOut || consensus OutPoint.
let mut bytes = offset.to_bytes().to_vec();
fake_txout.consensus_encode(&mut bytes).unwrap();
fake_outpoint.consensus_encode(&mut bytes).unwrap();

let forged = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();

// The forged object reports the nonexistent 100_000 sats.
assert_eq!(forged.value(), 100_000);

// This builds a transaction spending the nonexistent outpoint.
let signable = SignableTransaction::new(
  vec![forged],
  &[(attacker_payment_script, 50_000)],
  None,
  None,
  10,
).unwrap();

// The script check succeeds because the forged output uses the wallet's
// actual derived Taproot script.
let machine = signable.multisig(&keys).unwrap();

// Completing the FROST protocol produces a signed transaction spending a
// nonexistent UTXO; it is invalid on-chain despite being treated as funded.
```

The critical steps are that deserialization preserves the attacker’s amount and outpoint, `SignableTransaction` uses both without ledger authentication, and the derived-script check only proves address ownership—not UTXO existence. [2](#0-1) [4](#0-3) [7](#0-6)
