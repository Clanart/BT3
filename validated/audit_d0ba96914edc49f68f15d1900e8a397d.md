## Finding: Valid

### Title
Missing HTTPS-scheme validation lets a repository-controlled `http://github.com` remote obtain a genuine GitHub.com OAuth token that is then transmitted over cleartext HTTP - (File: `app/src/lib/trampoline/trampoline-ui-helper.ts`, `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
`promptForGitHubSignIn` derives `hostname`/`origin` from `new URL(endpoint)` without checking `protocol`, so an `endpoint` of `http://github.com` is routed to `beginDotComSignIn` exactly like `https://github.com`. [1](#0-0) 

The `endpoint` value itself is attacker-influenced: it comes straight from the credential-helper's parsed git credential URL (`protocol`/`host` fields Git sends for the remote it is authenticating), which for a `.gitmodules`-declared submodule of `http://github.com/...` (fully repository content) would be `http://github.com`. [2](#0-1) 

### Finding Description
In `getEndpointKind`, `isDotCom(endpoint)` is evaluated **before** the later `credentialUrl.protocol !== 'https:'` guard, and `isDotCom` itself only checks `hostname`, not scheme: [3](#0-2) [4](#0-3) 

So `http://github.com` is classified as `'github.com'` (not `'generic'`), and if no existing GitHub.com account is already stored for the API endpoint, `getCredential` calls `ui.promptForGitHubSignIn(endpoint)` with the unmodified `http://` endpoint: [5](#0-4) 

`promptForGitHubSignIn` then matches `hostname === 'github.com'` (scheme-agnostic) and calls `dispatcher.beginDotComSignIn(cb)`. [6](#0-5) 

Note that `beginDotComSignIn` itself is safe in isolation — it always uses the fixed, real `getDotComAPIEndpoint()` (`https://api.github.com`) for the OAuth flow, not the attacker-supplied `endpoint`: [7](#0-6) 

The vulnerability is therefore not that the sign-in itself is hijacked, but that the **resulting legitimate Account/token** is handed back to `getCredential`, merged into the git credential (`credWithAccount(cred, account)`), and returned to Git as the answer for the original `http://github.com` credential request: [8](#0-7) [9](#0-8) 

Git will then use this valid GitHub token via HTTP Basic Auth over the plaintext channel implied by the original `http://` remote URL, because nothing in this path rejects or upgrades non-HTTPS GitHub.com credential requests.

### Impact Explanation
An on-path network attacker (public Wi-Fi, malicious/compromised proxy, ISP-level MITM) who can observe the victim's plaintext HTTP traffic to `github.com` can capture the Basic-Auth header containing the user's real GitHub.com OAuth token. That token can then be replayed against the GitHub API to impersonate the user (read private repos, push code, etc.), which is a credential-exfiltration / unauthorized-account-use impact.

### Likelihood Explanation
Exploitation requires: (1) the victim to already be (or to become, via the flow itself) signed in to GitHub.com in Desktop, and (2) a malicious repository to declare a submodule/remote using `http://github.com/...` (achievable purely through repository content such as `.gitmodules`), triggering a credential-helper lookup for that URL during clone/fetch/submodule update. No scheme check anywhere in `getEndpointKind`, `isDotCom`, or `promptForGitHubSignIn` blocks this, so the path is fully reachable from unprivileged repository content.

### Recommendation
- In `getEndpointKind` (`app/src/lib/trampoline/trampoline-credential-helper.ts`), check `credentialUrl.protocol !== 'https:'` before calling `isDotCom`/`isGHE`, and classify any non-HTTPS URL as `'generic'` regardless of hostname.
- In `promptForGitHubSignIn` (`app/src/lib/trampoline/trampoline-ui-helper.ts`), validate `new URL(endpoint).protocol === 'https:'` before dispatching to `beginDotComSignIn`/`beginEnterpriseSignIn`, and refuse (resolve `undefined`) otherwise.
- More generally, ensure GitHub.com/GHE credentials are never attached to a credential-helper response when the original request's protocol is not `https:`.

### Proof of Concept
1. Create a malicious repository containing a `.gitmodules` entry: `url = http://github.com/attacker/foo`.
2. Victim (with no `api.github.com` account yet stored, or forced through re-auth) runs `git submodule update --init --recursive` inside GitHub Desktop's managed Git.
3. Git invokes the `desktop` credential helper with `protocol=http host=github.com`.
4. `getEndpointKind` returns `'github.com'` (via `isDotCom`), bypassing the HTTPS-only branch; `getCredential` calls `ui.promptForGitHubSignIn('http://github.com')`.
5. `promptForGitHubSignIn` matches `hostname === 'github.com'` and starts `beginDotComSignIn`; user completes the (secure) OAuth flow.
6. The resulting `Account` token is merged into the credential map and returned to Git, which sends it as `Authorization: Basic ...` over the plaintext `http://github.com` connection — capturable by any on-path attacker.

export const getCredentialUrl = (cred: Map<string, string>) => {
  const u = cred.get('url')
  if (u) {
    return new URL(u)
  }

  const protocol = cred.get('protocol') ?? ''
  const username = cred.get('username')
  const user = username ? `${encodeURIComponent(username)}@` : ''
  const host = cred.get('host') ?? ''
  const path = cred.get('path') ?? ''

  return new URL(`${protocol}://${user}${host}/${path}`)
}

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
