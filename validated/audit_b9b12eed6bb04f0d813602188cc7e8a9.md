### Title
Lack of safety margin in gasless swap admission check enables proposer fund loss via price movement between tx-pool validation and bundle execution - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
`checkBalanceForSwap` admits a `GaslessSwapTx` into the pool if `amountIn >= gsr.GetAmountIn(token, minAmountOut)`, evaluated against the exchange rate at check time, with no safety buffer. [1](#0-0)  Once admitted, the gasless builder unconditionally prepends a `LendTxGenerator` transaction that irrevocably transfers KAIA from the block proposer to the sender before the swap is attempted, as part of the same bundle. [2](#0-1) [3](#0-2) 

### Finding Description
The admission check computes `requiredAmountIn := routerContract.GetAmountIn(nil, token, minAmountOut)` from the router's current on-chain state and compares it against the sender-declared `amountIn`, exactly at the boundary (`>=`), without any tolerance/buffer for price movement. [1](#0-0) 
This is the same root-cause pattern as the referenced report's `_checkLoanIsHealthy`: a boundary health/sufficiency check performed against a live, manipulable on-chain price with no safety margin, so a transaction that is marginally "valid" at check time can become invalid the moment the underlying price moves.

The consequence here differs from a simple revert because of how the gasless mechanism is wired to block building:
- The `GetLendTxGenerator` produces a `LendTx` from the proposer's own key/balance, unconditionally funding `lendAmount(approveTxOrNil, swapTx)` (repay-amount worth of KAIA) to the sender. [4](#0-3) [5](#0-4) 
- The `ExtractTxBundles` logic always builds the bundle as `[LendTxGenerator, ApproveTx?, SwapTx]`, i.e. the lend happens before the swap is known to succeed. [3](#0-2) 
- If the actual on-chain swap (`swapForGas`) fails to produce enough output to cover `amountRepay` at execution time — because the pool's real-time exchange rate has moved between the mempool admission check and the block-building/execution moment (either through natural volatility or a searcher sandwiching the swap) — the `SwapForGas` call will revert (since the router itself must still enforce `minAmountOut`), yet the `LendTx` inside the same bundle has already transferred KAIA out of the proposer's balance to the sender.

Because the admission check has no safety buffer, a swap that is only *marginally* passing at pool-validation time is exactly the kind of transaction likely to flip to failing at execution time, causing the proposer's advanced KAIA (the lend) to not be recouped by a successful repay-swap.

### Impact Explanation
This directly matches the "gasless...settlement theft"/fee-delegation-abuse category in scope. An attacker (any public actor capable of moving the swap-router's pool price, e.g., a searcher submitting an ordinary swap transaction against the same DEX pool used by `GaslessSwapRouter`) can, without any special privilege, cause validated-but-marginal gasless swap transactions to fail their real on-chain swap after the block proposer has already lent KAIA to the sender. This is uncompensated value leakage from the block proposer, achievable by any transaction sender/public RPC caller — squarely within the reachable attack surface defined by the rules (unprivileged tx sender, gasless user, public RPC caller).

### Likelihood Explanation
Likelihood is Medium: the admission check is re-evaluated close to block-building time (using `g.Chain.CurrentBlock()`), which narrows but does not eliminate the window; a same-block or same-slot sandwich swap against the underlying DEX pool immediately before the bundle executes is sufficient to shift `GetAmountIn` unfavorably and flip a borderline-passing check into an execution-time shortfall. No special privileges, validator collusion, or off-chain compromise are required — only ordinary transaction submission capability against the DEX pool backing `GaslessSwapRouter`.

### Recommendation
Add an explicit safety buffer/margin in `checkBalanceForSwap` (e.g., require `amountIn >= requiredAmountIn * (1 + buffer_bps/10000)`) so that only swaps with sufficient headroom against the current exchange rate are admitted into gasless bundles, mirroring the mitigation adopted upstream (adding a safety buffer for borrow-type health checks) in the referenced report. Additionally, consider ensuring the `LendTx` transfer and the swap's success are atomic (e.g., revert the whole bundle, including the lend, if the swap fails) rather than relying purely on a pre-execution estimate.

### Proof of Concept
Conceptual PoC (not executed, derived from code paths only):
1. Attacker observes a pending `GaslessSwapTx` in the mempool with `amountIn` only marginally above `GetAmountIn(token, minAmountOut)` computed at submission time — this passes `checkBalanceForSwap`. [1](#0-0) 
2. Attacker submits an ordinary swap transaction on the same underlying DEX pool that `GaslessSwapRouter` uses to compute `GetAmountIn`/execute `swapForGas`, shifting the exchange rate unfavorably for the pending gasless tx.
3. When the proposer builds the block, `ExtractTxBundles` still includes `[LendTxGenerator, ApproveTx?, SwapTx]` for the gasless tx, and the `LendTx` unconditionally transfers KAIA from the proposer to the sender. [3](#0-2) 
4. The subsequent `swapForGas` call reverts or produces less than `amountRepay` because of the shifted price, leaving the proposer's lent KAIA unrecovered.

Note: I could not locate the on-chain `GaslessSwapRouter.sol` source (only ABI/bindings are indexed) to confirm exactly how `swapForGas` handles partial-failure/repay-shortfall at the Solidity level; a Devin session with full repo access would be needed to inspect `contracts/**/GaslessSwapRouter.sol` and confirm whether any additional on-chain safeguard (e.g., an internal buffer or atomic revert-of-lend) already exists that isn't visible in the indexed bindings.

// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)

func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {

	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}
