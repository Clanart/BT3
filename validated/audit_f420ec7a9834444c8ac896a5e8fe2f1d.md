Confirmed: `onAccept` for `RedeemEscrow`/`RefundEscrow` calls `authenticate(incoming.request)` directly, and `authenticate` relies on `instance()`, which returns `address(this)` instead of reverting for an unregistered source chain [1](#0-0) .

### Title
`instance()` returns a fallback address instead of reverting for unregistered source chains, enabling spoofed escrow redemption/refund authentication - (File: `evm/tron/contracts/apps/IntentGatewayV2.sol`)

### Summary
`IntentGatewayV2.instance()` on the Tron build silently falls back to `address(this)` when a state machine ID has no registered gateway, instead of reverting like the corrected EVM implementation does. This default value is then used as the trust anchor in `authenticate()`, which gates `RedeemEscrow` and `RefundEscrow` message processing in `onAccept`.

### Finding Description
`instance()` looks up `_instances[keccak256(stateMachineId)]` and, if unset, returns `address(this)` rather than reverting: [2](#0-1) 

This is used by `authenticate()` to validate the sender of an incoming cross-chain post request: [3](#0-2) 

`authenticate()` derives `module` from the attacker-controlled `request.from` field and compares it to `instance(request.source)`. Because `instance()` returns `address(this)` for any `stateMachineId` that was never registered via a `NewDeployment` governance message, an attacker who originates a genuine ISMP message from an *unregistered* source chain, setting `request.from = abi.encodePacked(address(thisGatewayContract))`, causes `authenticate()` to compare `address(this) != address(this)`, which is false — authentication succeeds even though no legitimate gateway was ever deployed on that chain.

This is the exact same bug class as the reported `tokenURI()` EIP-721 non-compliance: returning a default/sentinel value for a non-existent key instead of reverting, which downstream code then treats as if it were a valid, authenticated value. In the audit report this caused ambiguity for ERC-721 clients; here the analogous silent default is consumed directly by a security check gating fund movement, which is strictly more severe.

By contrast, the newer `IntentsBase.sol` used elsewhere in the repo already fixes this exact pattern by reverting with `UnknownInstance()`: [4](#0-3) 

This confirms the Tron `IntentGatewayV2.sol` still contains the vulnerable, non-reverting variant.

### Impact Explanation
`onAccept` gates `RedeemEscrow` and `RefundEscrow` solely behind `authenticate()`: [1](#0-0) 

Once `authenticate()` is bypassed, `withdraw()` executes unconditionally, transferring the escrowed input tokens (and any accumulated protocol fees) to the `beneficiary` address decoded from the attacker-supplied `WithdrawalRequest` body: [5](#0-4) 

An attacker who controls any commitment/order with escrowed funds (their own or, if the commitment/token amounts can be guessed or observed on-chain, someone else's) can forge a message from an unregistered chain, spoof `from` as the gateway's own address, and redeem/refund escrow to an arbitrary beneficiary — a direct theft/loss-of-funds and unauthorized execution primitive that matches the bounty's "stealing or loss of funds" and "unauthorized transaction or execution" categories.

### Likelihood Explanation
The attacker needs only: (1) the ability to originate a genuine ISMP message from *any* state machine that the Tron `IntentGatewayV2` has not explicitly registered via `NewDeployment` (trivially true for most chains, since registration is opt-in governance), and (2) knowledge of a valid `commitment` with non-zero `_orders[commitment][token]` balance (visible on-chain). No relayer collusion, prover compromise, or admin/governance action is required — this is exploitable by any unprivileged party able to dispatch a message that is delivered through the standard ISMP handler pipeline, since the flaw is in the app-level authentication logic, not the consensus/state-proof layer.

### Recommendation
Change `instance()` to revert when no gateway is registered for the given `stateMachineId`, mirroring the already-fixed `IntentsBase._instance()`:
```solidity
function instance(bytes calldata stateMachineId) public view returns (address) {
    address gateway = _instances[keccak256(stateMachineId)];
    if (gateway == address(0)) revert UnknownInstance();
    return gateway;
}
```
Audit all other callers of `instance()` in this file (e.g., the `CancelOptions` dispatch paths) to ensure they tolerate the revert instead of relying on the `address(this)` fallback.

### Proof of Concept
1. Confirm chain `X` has never had a `NewDeployment` message processed by the target `IntentGatewayV2` (Tron) instance, so `_instances[keccak256(X)] == address(0)`.
2. From chain `X`, dispatch (via any ISMP-compatible contract the attacker controls) a `PostRequest` to the target gateway with:
   - `source = X`
   - `from = abi.encodePacked(address(targetIntentGatewayV2))`
   - `body = abi.encodePacked(uint8(RequestKind.RedeemEscrow)) ++ abi.encode(WithdrawalRequest({commitment: knownCommitment, tokens: knownTokens, beneficiary: attackerAddress}))`
3. Once delivered and accepted by the ISMP host (a standard, permissionless relay of a real proof from chain `X`), `onAccept` calls `authenticate(request)`.
4. `instance(X)` returns `address(this)` (fallback, since `X` is unregistered); `module` decoded from `from` also equals `address(this)`; the equality check passes, bypassing the intended "must come from a registered gateway" guard.
5. `withdraw()` executes, transferring the escrowed tokens for `knownCommitment` to `attackerAddress`. [6](#0-5) [1](#0-0)

        if (request.from.length != 20) revert InvalidInput();
        address module = address(bytes20(request.from));
        // IntentGateway only accepts incoming assets from itself or known instances
        if (instance(request.source) != module) revert Unauthorized();

        _filled[body.commitment] = beneficiary;

        // redeem escrowed tokens
        uint256 len = body.tokens.length;
        for (uint256 i; i < len;) {
            address token = address(uint160(uint256(body.tokens[i].token)));
            uint256 amount = body.tokens[i].amount;
            if (_orders[body.commitment][token] == 0) revert UnknownOrder();

            if (token == address(0)) {
                (bool sent,) = beneficiary.call{value: amount}("");
                if (!sent) revert InsufficientNativeToken();
            } else {
                (bool success,) = token.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, amount));
                if (!success) revert TransferFailed();
            }

            _orders[body.commitment][token] -= amount;
            unchecked {
                ++i;
            }
        }

        // redeem tx fees
        uint256 fees = _orders[body.commitment][TRANSACTION_FEES];
        if (fees > 0) {
            address feeToken = IDispatcher(host()).feeToken();
            (bool success,) = feeToken.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, fees));
            if (!success) revert TransferFailed();
            delete _orders[body.commitment][TRANSACTION_FEES];
        }

            emit EscrowRefunded({commitment: body.commitment});
        } else {
