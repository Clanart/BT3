## Finding

Kaia's auction bid pool contains an unsynchronized read of a mutex-protected field, directly analogous to the ath12k bug class (a lock-protected shared value read outside its critical section by a handler that races with a concurrent writer).

### Title
Unsynchronized read of lock-protected `auctionEntryPointVersion` in bid gas-limit computation causes data race and possible bid-tx gas/encoding inconsistency - (File: kaiax/auction/impl/bid_pool.go)

### Summary
`BidPool.getBidTxGasLimit` partially releases `auctionInfoMu` before finishing its read of the fields it protects, reading `bp.auctionEntryPointVersion` without holding the lock while a concurrent block-insertion goroutine can be writing that same field.

### Finding Description
`BidPool` protects `auctioneer`, `auctionEntryPoint`, `auctionEntryPointVersion`, and `bidTxGasBuffer` with `auctionInfoMu` [1](#0-0) . Every other accessor (`GetAuctionEntryPoint`, `GetAuctionEntryPointVersion`, `validateBidSigs`) correctly holds `auctionInfoMu.RLock()` for the whole duration of use [2](#0-1) [3](#0-2) .

However, `getBidTxGasLimit` takes the read lock only to copy `bidTxGasBuffer`, releases it, and then reads `bp.auctionEntryPointVersion` unprotected to build the ABI-encoded call data used for intrinsic-gas computation: [4](#0-3) 

This function is invoked from `AddBid`, which runs concurrently from multiple goroutines — the network bid-message handler goroutine (`handleBidMsg`) and the direct `SubmitBid` API path [5](#0-4) [6](#0-5) .

Meanwhile, `auctionEntryPointVersion` is rewritten under the write lock every time a new block is inserted, via `AuctionModule.PostInsertBlock` → `updateAuctionInfo` → `BidPool.updateAuctionInfo` [7](#0-6) [8](#0-7) , which also clears the whole bid pool as a side effect of a version/entry-point change.

This is the same bug class as the ath12k CVE: a value guarded by a lock (RCU there, `sync.RWMutex` here) is read by a handler that runs concurrently with the writer but omits the read-side critical section for part of the access, creating a data race between an unprivileged/attacker-triggerable event (submitting a bid) and a system event (block insertion changing the auction version).

### Impact Explanation
An unprivileged auction bidder submitting `SubmitBid` transactions concurrently with block production can race with `updateAuctionInfo`. If the auction entry point's version changes at a block boundary (a governance-controlled but externally observable event), the encoded call data used to compute intrinsic gas in `getBidTxGasLimit` can be built with a `bidTxGasBuffer` from one version epoch and an `auctionEntryPointVersion` from a different epoch, or the race can be flagged/exploited to produce inconsistent gas-limit computations between the goroutine racing on this field. Because different validating/proposing nodes may observe this race differently depending on scheduling, this can lead to divergent computed `bid.CallGasLimit`, feeding inconsistent auction settlement transactions into block assembly and risking state divergence between honest nodes around auction version transitions.

### Likelihood Explanation
The race window opens naturally at every block boundary where the auction contract's version, entry point, or gas buffer changes, and is reachable simply by submitting bids (`SubmitBid`/gossip) at a normal cadence — no privileged access required. Because bid processing runs on background goroutines independent of block-insertion, the timing window recurs on every relevant block, though the version actually changing is comparatively rare (governance-driven), and `Read` races on Go's essentially-atomic string-header copies limit the odds of a torn read causing a hard crash rather than a logically stale value.

### Recommendation
Hold `auctionInfoMu.RLock()` for the entire body of `getBidTxGasLimit`, including the `EncodeAuctionCallData` call, so `bidTxGasBuffer` and `auctionEntryPointVersion` are read as a consistent snapshot, mirroring the pattern already used in `validateBidSigs` and `GetAuctionEntryPointVersion`.

### Proof of Concept
1. Start the auction module with an entry-point version `"v1"`.
2. Goroutine A: continuously call `bp.AddBid(bid)` (reachable via `SubmitBid` RPC or gossiped bids), which calls `getBidTxGasLimit` reading `bp.auctionEntryPointVersion` unlocked at [9](#0-8) .
3. Goroutine B: on block insertion, call `PostInsertBlock` → `updateAuctionInfo`, which takes the write lock and swaps `auctionEntryPointVersion` to `"v2"` (and buffers) via `bp.updateAuctionInfo(...)` [8](#0-7) .
4. Running both loops with `go test -race` reproduces a detected data race on `auctionEntryPointVersion`, demonstrating the unlocked read used to compute gas-critical encoded call data for a bid transaction that will later be embedded in block assembly.

func (bp *BidPool) updateAuctionInfo(auctioneer common.Address, auctionEntryPoint common.Address, auctionEntryPointVersion string, bidTxGasBuffer uint64) {
	bp.auctionInfoMu.Lock()
	defer bp.auctionInfoMu.Unlock()

	if bp.auctioneer == auctioneer && bp.auctionEntryPoint == auctionEntryPoint && bp.auctionEntryPointVersion == auctionEntryPointVersion && bp.bidTxGasBuffer == bidTxGasBuffer {
		return
	}

	// Clear the existing auction pool since the auctioneer or auction entry point address is changed.
	bp.clearBidPool()

	bp.auctioneer = auctioneer
	bp.auctionEntryPoint = auctionEntryPoint
	bp.auctionEntryPointVersion = auctionEntryPointVersion
	bp.bidTxGasBuffer = bidTxGasBuffer

	logger.Info("Update auction info", "auctioneer", auctioneer, "auctionEntryPoint", auctionEntryPoint, "auctionEntryPointVersion", auctionEntryPointVersion, "bidTxGasBuffer", bidTxGasBuffer)
}

func (bp *BidPool) AddBid(bid *auction.Bid) (common.Hash, error) {
	if atomic.LoadUint32(&bp.running) == 0 {
		return common.Hash{}, auction.ErrAuctionPaused
	}

	if err := bp.validateBid(bid); err != nil {
		return common.Hash{}, err
	}

	if err := bp.insertBid(bid); err != nil {
		return common.Hash{}, err
	}

	gasLimit, err := bp.getBidTxGasLimit(bid)
	if err != nil {
		return common.Hash{}, err
	}
	bid.SetGasLimit(gasLimit)

	bp.newBidCh <- bid

	return bid.Hash(), nil
}

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}

func (a *AuctionModule) PostInsertBlock(block *types.Block) error {
	if a.Downloader.Synchronising() || !a.ChainConfig.IsRandaoForkEnabled(block.Number()) {
		atomic.CompareAndSwapUint32(&a.bidPool.running, 1, 0)
		return nil
	}

	if !a.updateAuctionInfo(block.Number()) {
		logger.Debug("stop auction since auctioneer or auction entry point is not set")
		atomic.CompareAndSwapUint32(&a.bidPool.running, 1, 0)
		return nil
	}

	atomic.CompareAndSwapUint32(&a.bidPool.running, 0, 1)

	txHashMap := make(map[common.Hash]struct{})
	for _, tx := range block.Transactions() {
		txHashMap[tx.Hash()] = struct{}{}
	}
	a.bidPool.removeOldBids(block.Number().Uint64(), txHashMap)

	return nil
}

// updateAuctionInfo updates the auctioneer address and auction entry point address for the given block number.
// It expects the `num` is after Randao fork.
// It returns true if the non-zero auctioneer address and auction entry point address are set, otherwise false.
