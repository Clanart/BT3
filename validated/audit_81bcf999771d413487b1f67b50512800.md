### Title
Ephemeral string reads in upb's fast-path decoder can copy uninitialized patch-buffer bytes into a parsed field before the truncation error is detected - (File: `upb/wire/internal/eps_copy_input_stream.h`)

### Summary
The GD `gdImageCreateFromXbm()` bug (ALPINE-CVE-2019-11038) discloses stack memory because a code path uses a value before verifying that it was actually initialized from attacker input, and no failure path clears/validates it before it becomes observable. The closest actual Protobuf analog is `upb_EpsCopyInputStream_ReadStringEphemeral()`, whose own header comment documents that a truncated length-delimited field can cause "garbage bytes from the patch buffer" to be copied into a `upb_StringView` and "result in nonsense bytes ending up in the output" — the truncation error is only detected *after* the value has already been consumed by the caller (e.g. copied into a message field or callback). [1](#0-0) 

### Finding Description
`upb_EpsCopyInputStream_ReadStringEphemeral()` is an optimization used by upb's fast wire decoder to read a length-delimited value (string/bytes/unknown field capture) directly out of the 32-byte `patch` buffer without first checking that `size` fits within the actual, valid remaining input: [2](#0-1) 

The only bound enforced is that `size` does not exceed `e->end + kUpb_EpsCopyInputStream_SlopBytes`, i.e. it only prevents reading past the *allocated* patch buffer, not past the actual valid data length (`e->limit`). This mirrors the GD bug's invariant failure: the check that exists (`size <= limit - ptr`, buffer bounds) is not the same as the check that matters (was this byte actually supplied by input / is it initialized to something derived from the real payload). The `patch` buffer (`char patch[kUpb_EpsCopyInputStream_SlopBytes * 2]`) is `memset` to 0 only when the *entire remaining input* is small enough to fit in it during `InitWithErrorHandler` — for interior calls happening deeper in decoding, whatever bytes happen to reside past the legitimate end-of-limit position (stale content from a previous buffer refill / previous field's tail) can be returned as the string's content. [3](#0-2) [4](#0-3) 

The header comment for this function is explicit about the consuming-code contract that must transfer to callers: the *decoder must not surface the ephemeral value* until `upb_EpsCopyInputStream_IsDone()` is subsequently called and detects the mismatched end position:
"This error will be detected later, when calling `upb_EpsCopyInputStream_IsDone()`… but it may result in nonsense bytes ending up in the output." [5](#0-4) 

This is used by the fast string field decoder path (`upb/wire/decode_fast/field_string.c`) and by unknown-field capture logic in `python/unknown_fields.c` and `upb/message/internal/compare_unknown.c`, all of which call `ReadStringEphemeral` and then must independently re-validate via `IsDone`/limit checks before committing the value. If any call site consumes/copies the `upb_StringView` (e.g., into a message string field, or into unknown-field storage that later gets serialized back out or exposed via reflection) *before* performing that follow-up validation, the disclosed bytes become part of the parsed message and can leak to the attacker on any subsequent access/serialization of that message — precisely analogous to GD returning an uninitialized/stale value from `gdImageCreateFromXbm()` before validating the input actually supplied it.

### Impact Explanation
If reachable, this is a Medium-severity information-disclosure issue, structurally identical in class to the GD analog: a bounded, low-privilege parse of attacker-supplied bytes could cause a few bytes of stale/leftover process memory (previous buffer contents, not attacker controlled) to be copied into a string/bytes field or unknown-field record of the parsed message, which the host application might then log, echo back, or re-serialize, disclosing memory contents unrelated to the current message. It does not directly grant code execution or corrupt memory beyond the size of `kUpb_EpsCopyInputStream_SlopBytes` (16 bytes), and it requires the field to actually be truncated (exceed the real remaining input) while still fitting the physical patch buffer.

### Likelihood Explanation
I could not, within this investigation, definitively confirm a call site that fails to perform the required follow-up `IsDone()`/limit check before committing the ephemeral value to persistent message state — the function's own documentation asserts the error "will be detected later," implying upstream call sites are expected to (and likely do) check this before the value escapes. I was not able to fully trace every consumer (`upb/wire/decode_fast/field_string.c`, `python/unknown_fields.c`, `upb/message/internal/compare_unknown.c`, `upb/text/internal/encode.c`, `upb/wire/internal/decoder.h`) to prove or disprove that the mandatory follow-up check is always performed before the ephemeral bytes are copied out. This is a genuine open question that requires deeper tracing of the fast decoder's control flow (specifically whether `field_string.c`'s use of the ephemeral read commits data to the message struct before or after the enclosing `IsDone`/limit re-check).

### Recommendation
Trace all callers of `upb_EpsCopyInputStream_ReadStringEphemeral` to confirm that the returned `upb_StringView` is never copied into persistent/observable state (message fields, unknown-field buffers) until the decoder has re-validated the stream position via `upb_EpsCopyInputStream_IsDone()` or an equivalent limit check within the same field-parsing step. If any path copies-then-validates in the wrong order, reorder to validate-then-copy, or zero the patch buffer defensively before use in these deeper (non-init) invocations.

### Proof of Concept
I was not able to construct and run a concrete minimal reproduction within this investigation (no filesystem/build access in this ask-only session). A follow-up engineering session with full repository/build access would be needed to: (1) instrument `upb_EpsCopyInputStream_ReadStringEphemeral` call sites in `upb/wire/decode_fast/field_string.c`, (2) craft a binary protobuf payload whose final length-delimited field's declared size extends a few bytes past the true end of the buffer but stays within the 16-byte slop region, and (3) check under MSAN/ASAN whether uninitialized/stale bytes from the patch buffer become observable in the resulting `upb_Message`'s string field before the truncation is reported as a decode error.

// Returns NULL if size extends beyond the end of the current buffer (which may

struct upb_EpsCopyInputStream {
  const char* end;        // Can read up to SlopBytes bytes beyond this.
  const char* limit_ptr;  // For bounds checks, = end + UPB_MIN(limit, 0)
  uintptr_t input_delta;  // Diff between the original input pointer and patch
  const char* buffer_start;  // Pointer to the original input buffer
  ptrdiff_t limit;           // Submessage limit relative to end
  upb_ErrorHandler* err;     // Error handler to use when things go wrong.
  bool error;                // To distinguish between EOF and error.
#ifndef NDEBUG
  int guaranteed_bytes;
#endif
  // Allocate double the size of what's required; this permits a fixed-size copy
  // from the input buffer, regardless of how many bytes actually remain in the
  // input buffer.
  char patch[kUpb_EpsCopyInputStream_SlopBytes * 2];
};

UPB_INLINE void upb_EpsCopyInputStream_InitWithErrorHandler(
    struct upb_EpsCopyInputStream* e, const char** ptr, size_t size,
    upb_ErrorHandler* err) {
  e->buffer_start = *ptr;
  e->err = err;
  if (size <= kUpb_EpsCopyInputStream_SlopBytes) {
    memset(&e->patch, 0, 32);
    if (size) memcpy(&e->patch, *ptr, size);
    e->input_delta = (uintptr_t)*ptr - (uintptr_t)e->patch;
    *ptr = e->patch;
    e->end = *ptr + size;
    e->limit = 0;
  } else {
    e->end = *ptr + size - kUpb_EpsCopyInputStream_SlopBytes;
    e->limit = kUpb_EpsCopyInputStream_SlopBytes;
    e->input_delta = 0;
  }
  e->limit_ptr = e->end;
  e->error = false;
  UPB_PRIVATE(upb_EpsCopyInputStream_BoundsChecked)(e);
}

UPB_INLINE const char* upb_EpsCopyInputStream_ReadStringEphemeral(
    struct upb_EpsCopyInputStream* e, const char* ptr, size_t size,
    upb_StringView* sv) {
  UPB_ASSERT(size <= PTRDIFF_MAX);
  // Size must be within the current buffer (including slop bytes).
  const char* limit = e->end + kUpb_EpsCopyInputStream_SlopBytes;
  if ((ptrdiff_t)size > limit - ptr) {
    // For the moment, we consider this an error.  In a multi-buffer world,
    // it could be that the requested string extends into the next buffer, which
    // is not an error and should be recoverable.
    return UPB_PRIVATE(upb_EpsCopyInputStream_ReturnError)(e);
  }
  *sv = upb_StringView_FromDataAndSize(ptr, size);
  return ptr + size;
}
