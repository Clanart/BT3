### Title
Unvalidated `ReceivedOutput` offset allows untrusted data to claim unspendable funds - ([File: networks/bitcoin/src/wallet/mod.rs])

### Summary
`ReceivedOutput::read` deserializes the scalar offset, `TxOut`, and `OutPoint` but never verifies that the serialized `offset` actually derives the Taproot key committed by `output.script_pubkey`. [1](#0-0)  Although `ReceivedOutput` is documented as “a spendable output,” the read path accepts a tuple missing the key context needed to establish that invariant. [2](#0-1) 

### Finding Description
A `ReceivedOutput` consists only of an offset, a claimed previous output, and its outpoint. [2](#0-1)  `ReceivedOutput::read` performs canonical scalar decoding and consensus decoding, but it performs no P2TR check and no comparison between `p2tr_script_buf(key + offset * G)` and `output.script_pubkey`. [1](#0-0)  The subsequent transaction builder trusts the encoded `value` and `outpoint` when constructing an input and calculating available funds. [3](#0-2)  The offset-to-script relationship is only checked later in `SignableTransaction::multisig`, which returns `None` if the provided offset does not derive the previous output’s Taproot key. [4](#0-3) 

### Impact Explanation
An unprivileged party who can supply serialized `ReceivedOutput` bytes can cause another party’s output to be represented as spendable even though Serai does not possess the corresponding spend key. [1](#0-0)  This can lead to funds being reported received or included in transaction funding calculations while the resulting input cannot be signed. [3](#0-2)  The late `multisig` rejection prevents producing an invalid spend transaction, but it does not repair the violated semantic invariant established when the malformed object was accepted. [4](#0-3) 

### Likelihood Explanation
The attack requires only untrusted bytes reaching `ReceivedOutput::read`, which is one of the public-input paths considered reachable for this codebase. [1](#0-0)  The attacker needs a canonical scalar encoding plus consensus-valid `TxOut` and `OutPoint` data, which can describe a real output controlled by the attacker or another unrelated P2TR output. [5](#0-4)  Exploitation depends on a caller persisting or accounting for deserialized `ReceivedOutput`s before confirming spendability. [3](#0-2) 

### Recommendation
Do not allow `ReceivedOutput::read` to establish the “spendable output” invariant without the scanner’s base key or equivalent verification context. [2](#0-1)  Change deserialization to require the expected base key and reject the input unless `output.script_pubkey` equals `p2tr_script_buf(base_key + generator * offset)` and that function returns `Some`. [6](#0-5)  Alternatively, separate a raw untrusted serialization type from `ReceivedOutput` and only construct the latter after the scanner verifies the script and offset relationship. [7](#0-6) 

### Proof of Concept
```rust
// Construct bytes for: offset || TxOut || OutPoint.
// `offset` is a canonical Secp256k1 scalar such as 1.
// `attacker_txout` is an actual UTXO whose script_pubkey belongs to the attacker.
let forged = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();

// The parser accepts it and exposes the claimed value.
assert_eq!(forged.value(), attacker_txout.value.to_sat());
assert_eq!(forged.offset(), Scalar::ONE);

// The transaction builder trusts the claimed value and outpoint.
let signable = SignableTransaction::new(
  vec![forged],
  payments,
  change,
  data,
  fee_per_vbyte,
).unwrap();

// Only later does signing reject that `offset` does not derive the output script.
assert!(signable.multisig(&serai_threshold_keys).is_none());
```
`ReceivedOutput::read` accepts these fields without deriving or checking the corresponding P2TR script. [1](#0-0)  `SignableTransaction::new` then counts the claimed `TxOut` value and creates an input for the supplied outpoint. [3](#0-2)  `multisig` detects the mismatch only when signing is attempted and therefore demonstrates that the accepted object represented funds Serai could not spend. [4](#0-3)

  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
