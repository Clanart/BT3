### Title
Identity encryption key accepted by PedPoP deserialization makes all DKG secret shares encrypted to that participant publicly decryptable - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
`EncryptionKeyMessage::read` deserializes each participant's ECDH encryption key via `Ciphersuite::read_G`, which validates canonicity but does **not** reject the identity point (identity rejection only exists in `frost::Curve::read_G`, which PedPoP does not use). The encryption key carries no proof of possession. A participant who registers `enc_key = identity` causes every `EncryptedMessage` addressed to them to be encrypted under the publicly known ECDH shared point `k * identity = identity`, so any observer of the ciphertext can derive the ChaCha20 key and decrypt the secret shares.

### Finding Description
`Ciphersuite::read_G` only checks canonical encoding; identity is a valid canonical, torsion-free point and passes [1](#0-0) . The identity rejection exists only in `Curve::read_G` for FROST, which PedPoP never calls [2](#0-1) . `EncryptionKeyMessage::read` reads `enc_key` with the unchecked `C::read_G` and attaches no PoP (unlike `EncryptedMessage`, which has `pop`) [3](#0-2) . `Decryption::register` stores it without validation [4](#0-3) . `Encryption::encrypt` then computes `ecdh(key, to)` where `to` is the registered key [5](#0-4) , and `cipher` derives the ChaCha20 key solely from `context || ecdh.to_bytes()` with a fixed IV [6](#0-5) . With `to = identity`, the shared point is `identity`, whose byte encoding is public and constant — the "encryption" is to a key everyone knows.

### Impact Explanation
Every secret share `f_j(m)` sent to malicious participant `m` is encrypted to the public shared point and is therefore decryptable by any party that obtains the ciphertext (shares are routed peer-to-peer, so all other participants see/transmit them, and the broadcasted commitments message itself is public). Any other participant `p` thus learns `m`'s full received share set in addition to their own — i.e., two secret shares instead of one. Where `t = 2`, or where two participants share their observations, this yields `t` shares and full recovery of the threshold group's secret key — key share recovery well below the threshold. This is the direct analog of the CVE's class: deserialization of untrusted bytes accepting a value (identity point) outside the intended domain, silently downgrading the security primitive.

### Likelihood Explanation
Reachable entirely with public inputs: the attacker is an ordinary DKG participant broadcasting a malformed `EncryptionKeyMessage` — no validator privilege, key access, or protocol deviation detectable by `verify_r1` (the PoK batch verifies `commitments[0]`, not `enc_key`) [7](#0-6) . The malformed message serializes/deserializes cleanly, so it also survives any store-and-forward or persistence layers using `read`.

### Recommendation
Reject the identity point when reading `enc_key` in `EncryptionKeyMessage::read` (and `key`/`proof.key` in `EncryptedMessage::read`/`EncryptionKeyProof::read` for defense in depth), e.g., by checking `is_identity()` after `C::read_G` or routing through a non-identity `read_G`. Alternatively/additionally, require a Schnorr proof of possession on the encryption key itself.

### Proof of Concept
```
// Participant m broadcasts EncryptionKeyMessage with:
//   commitments: t valid points + valid PoK sig
//   enc_key:     C::G::identity().to_bytes()  (canonical 32-byte encoding)
// EncryptionKeyMessage::read succeeds; register(m, msg) stores identity.
// Each sender j calls encrypt(rng, m, share_j):
//   ecdh = share_key * identity = identity
//   ChaCha20 key = H(context || identity.to_bytes())  // publicly derivable
// Any observer of msg_j computes the same keystream and recovers f_j(m).
// Attacker collects f_j(m) for all j => m's aggregated secret share,
// bypassing threshold confidentiality.
```

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
  }

fn cipher<C: Ciphersuite>(context: [u8; 32], ecdh: &Zeroizing<C::G>) -> ChaCha20 {
  // Ideally, we'd box this transcript with ZAlloc, yet that's only possible on nightly
  // TODO: https://github.com/serai-dex/serai/issues/151
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"encryption_key");

  let mut ecdh = ecdh.to_bytes();
  transcript.append_message(b"shared_key", ecdh.as_ref());
  ecdh.as_mut().zeroize();

  let zeroize = |buf: &mut [u8]| buf.zeroize();

  let mut key = Cc20Key::default();
  let mut challenge = transcript.challenge(b"key");
  key.copy_from_slice(&challenge[.. 32]);
  zeroize(challenge.as_mut());

  // Since the key is single-use, it doesn't matter what we use for the IV
  // The issue is key + IV reuse. If we never reuse the key, we can't have the opportunity to
  // reuse a nonce
  // Use a static IV in acknowledgement of this
  let mut iv = Cc20Iv::default();
  // The \0 is to satisfy the length requirement (12), not to be null terminated
  iv.copy_from_slice(b"DKG IV v0.2\0");

  // ChaCha20 has the same commentary as the transcript regarding ZAlloc
  // TODO: https://github.com/serai-dex/serai/issues/151
  let res = ChaCha20::new(&key, &iv);
  zeroize(key.as_mut());
  res
}
