### Title
`ReceivedOutput` prevout values are trusted, letting fabricated amounts burn multisig funds as fees or produce invalid signatures - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The audit hint concerns an actor spending pool funds without accounting for amounts already owed to users. The Serai analog lives in the Bitcoin transaction-signing path: `ReceivedOutput::read` accepts an arbitrary `TxOut` (including its `value`) from untrusted bytes, and neither `SignableTransaction::new` nor `SignableTransaction::multisig` verifies that value against the actual outpoint. The fabricated amount is baked into the fee/change math and committed into every input's BIP-341 sighash via `Prevouts::All`, so a party feeding crafted `ReceivedOutput`s can cause a fully valid signed transaction that silently burns real UTXO value as miner fees, or a transaction whose signatures are invalid on-chain.

### Finding Description
`ReceivedOutput::read` deserializes `offset`, `output` (a full `TxOut` with attacker-chosen `value`), and `outpoint` directly from the byte stream with no consistency check [1](#0-0) . In `SignableTransaction::new`, the claimed `input.output.value` is summed into `input_sat` and used both for the `NotEnoughFunds` check and to size the change output [2](#0-1) [3](#0-2) . `multisig()` only verifies that the offset key maps to `prevout.script_pubkey`; it never checks the amount [4](#0-3) . Finally, `sign` commits to `Prevouts::All(&self.tx.prevouts)` — i.e., the fabricated `TxOut`s — for every input's sighash [5](#0-4) .

Two consequences:

- **Understated value:** if a supplied `ReceivedOutput` claims less than the real UTXO, consensus still sees the true input amount, so `actual_inputs - outputs` exceeds the computed `needed_fee`. The difference is paid to miners, and with a large enough understatement the change branch is skipped entirely (`value < DUST`), dumping the whole remainder into fees. The signatures are valid — the network accepts the transaction and the excess is unrecoverable.
- **Overstated value:** the sighash commits to an amount that doesn't exist on-chain, so every input signature fails BIP-341 verification; the transaction is rejected, wasting a nonce/preprocess round and enabling targeted DoS of specific payments.

### Impact Explanation
Like the original finding, funds effectively reserved for one purpose (honest fee + change back to the multisig) are consumed by an unintended action because the spender trusts a balance figure that was never reconciled with the real available balance. An unprivileged party able to supply serialized `ReceivedOutput`s (e.g., the coordinator path feeding `ReceivedOutput::read`) can permanently burn arbitrary amounts of multisig-held BTC as miner fees, or selectively invalidate transactions the threshold group produces.

### Likelihood Explanation
Requires an attacker in the position of supplying `ReceivedOutput` bytes or driving `SignableTransaction` construction for signers. The honest scanning path produces correct values, so exploitation depends on that channel being attacker-influenced; when it is, no additional collusion or privileged on-chain access is needed. Medium.

### Recommendation
When building `SignableTransaction`, require each `ReceivedOutput`'s `outpoint` to be resolved against a trusted UTXO source (or include a consensus proof) rather than trusting the embedded `TxOut.value`; at minimum, have `multisig()`/`sign` refuse prevouts whose values were not independently confirmed, and bound the effective fee (`fee()`) to `needed_fee` before completing signatures.

### Proof of Concept
1. Attacker crafts bytes for `ReceivedOutput::read` with a real multisig `outpoint`, correct `offset`, but `output.value = 1 sat` while the actual UTXO holds 1 BTC.
2. `SignableTransaction::new` computes `input_sat` from the fake value, deems the change below `DUST`, and builds a tx with a modest declared fee.
3. Signers run `TransactionSignMachine::sign`; each sighash commits to `Prevouts::All` containing the fake 1-sat prevout.
4. The signed transaction is broadcast; consensus uses the real 1 BTC input, so ~1 BTC minus outputs is paid as a miner fee. Funds are irreversibly lost despite every signature being valid.
