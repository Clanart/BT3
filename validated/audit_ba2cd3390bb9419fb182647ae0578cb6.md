### Title
Malformed FROST preprocess can panic a Bitcoin signer by forcing an identity nonce - (File: networks/bitcoin/src/crypto.rs)

### Summary
**Medium severity.** An untrusted participant can submit canonical but maliciously selected nonce commitments whose aggregate FROST nonce is the point at infinity, causing the Bitcoin BIP-340 challenge implementation to panic while producing a signature share. [1](#0-0) [2](#0-1) 

### Finding Description
`TransactionSignMachine::read_preprocess` accepts each participant’s serialized preprocess and delegates parsing to `AlgorithmSignMachine::read_preprocess`. [3](#0-2) [4](#0-3) 

For the Bitcoin Schnorr algorithm, each preprocess contains one pair of group commitments, `D` and `E`, parsed with `C::read_G`. [5](#0-4) [6](#0-5) 

`C::read_G` verifies that the point encoding is canonical, but does not reject points selected to cancel other participants’ commitments. [7](#0-6) 

During signing, Serai sums all `D` values and adds a binding-factor-weighted sum of all `E` values to form the aggregate nonce. [1](#0-0) 

A participant who observes the other selected preprocesses can set their own `D` and `E` to the negations of the other parties’ sums, making both aggregate values the point at infinity. [1](#0-0) 

The Bitcoin Schnorr implementation then calls `Hram::hram` with that aggregate nonce, and `x` unconditionally expects an x-coordinate, which the point at infinity does not have. [8](#0-7) [2](#0-1) [9](#0-8) 

### Impact Explanation
The malformed preprocess causes a panic before the victim emits its signature share, aborting the signing operation or crashing the signer task/process if the panic is not caught. [8](#0-7) [2](#0-1) 

This is a remote denial of service against transaction signing and can be reached through the explicitly supported `read_preprocess` input path. [3](#0-2) [4](#0-3) 

### Likelihood Explanation
The attacker must be able to submit a preprocess for the relevant signing set and must choose their commitments after learning the other selected commitments. [10](#0-9) [1](#0-0) 

The malicious encoding consists only of canonical curve points, so parsing succeeds and the failure occurs later during signing. [7](#0-6) [11](#0-10) 

### Recommendation
Reject any aggregate nonce equal to the identity before invoking algorithm-specific challenge generation, and return a structured `FrostError::InvalidPreprocess` for the participant whose commitments made the aggregate invalid. [1](#0-0) [12](#0-11) 

The identity check should occur in generic FROST signing code after `B.nonces` is calculated rather than inside the Bitcoin HRAm, because other algorithms may also assume non-identity nonces. [12](#0-11) [8](#0-7) 

Additionally, rejecting individual identity `D` or `E` commitments during `GeneratorCommitments::read` would provide defense in depth, although it would not by itself prevent cancellation across multiple valid non-identity commitments. [5](#0-4) [1](#0-0) 

### Proof of Concept
For a single-input Bitcoin transaction, each serialized preprocess consists of the participant’s `D` and `E` encoded consecutively because the Bitcoin Schnorr algorithm specifies one nonce and one generator. [13](#0-12) [6](#0-5) 

```rust
// machine: TransactionSignMachine
// honest: serialized Preprocess for each selected honest participant
// malicious_i: Participant identifier controlled by the attacker

// For each input, decode the honest parties' D and E values from their
// serialized preprocesses, then submit negated commitments.
let malicious_preprocess_bytes = {
    let mut bytes = Vec::new();

    for honest_serialized_preprocess in honest {
        let mut d_bytes = &honest_serialized_preprocess[0 .. 33];
        let mut e_bytes = &honest_serialized_preprocess[33 .. 66];

        let d = Secp256k1::read_G(&mut d_bytes).unwrap();
        let e = Secp256k1::read_G(&mut e_bytes).unwrap();

        // For multiple honest preprocesses, negate the sum rather than only
        // negating the first observed commitment.
        bytes.extend_from_slice((-d).to_bytes().as_ref());
        bytes.extend_from_slice((-e).to_bytes().as_ref());
    }

    bytes
};

let mut reader = malicious_preprocess_bytes.as_slice();
let malicious_preprocess = machine.read_preprocess(&mut reader).unwrap();

let mut preprocesses = HashMap::new();
preprocesses.insert(malicious_i, malicious_preprocess);

// Panics inside x() because the aggregate nonce R is the point at infinity.
let _ = machine.sign(preprocesses, &[]);
```

The crafted points pass deserialization because they are canonical non-identity points, while the aggregate `D` and binding-factor-weighted `E` become identity during signing. [7](#0-6) [1](#0-0) 

The panic is reached through `Schnorr::sign_share`, which passes `nonce_sums[0][0]` to `Hram::hram`, whose `x` helper panics on a point without an x-coordinate. [8](#0-7) [2](#0-1)
