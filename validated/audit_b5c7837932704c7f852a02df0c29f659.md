### Title
App Proxy request signature verification lacks timestamp freshness check, permitting indefinite replay of validly signed proxy requests - (File: lib/shopify_app/controller_concerns/app_proxy_verification.rb)

### Summary
`ShopifyApp::AppProxyVerification#query_string_valid?` validates only that the HMAC `signature` query parameter matches the recomputed HMAC over the sorted query string, but never checks the `timestamp` parameter that Shopify includes in every signed app-proxy request. [1](#0-0) 

### Finding Description
The `query_string_valid?` method removes the `signature` param, recomputes an HMAC-SHA256 over the remaining sorted query parameters (which include `shop`, `path_prefix`, and `timestamp`), and compares it via `secure_compare`. [2](#0-1)  This exactly mirrors the reported bug class: a signed payload contains a `timestamp` field, but the verifying code checks only the signature validity and never bounds the timestamp against the current time (neither a maximum age nor, as in the original report, a minimum). As a result, any request/query string that was ever validly signed by Shopify for this app's proxy endpoint remains valid forever — there is no mechanism in `AppProxyVerification` (nor anywhere else in the repo, as confirmed by searching for `expire`/`stale`/timestamp-bound checks) that rejects an old, previously-captured, but fully valid signed app-proxy query string.

### Impact Explanation
Because `verify_proxy_request` is the sole gate (`before_action :verify_proxy_request`) protecting any controller including `ShopifyApp::AppProxyVerification`, an attacker who captures a legitimately-signed app-proxy URL (e.g., via browser history, logs, referrer headers, or a shared/public link) can replay that exact request indefinitely to re-trigger the app's proxy action for that shop, even long after the original request. [3](#0-2)  For app-proxy endpoints that perform state-changing actions (order operations, form submissions, discount application, etc. — as is common for app proxy usage), this permits a CSRF-like replay of a stale, captured request without needing to forge Shopify's HMAC secret.

### Likelihood Explanation
Exploitation requires the attacker to obtain a previously valid signed app-proxy request URL (no secret needed) — realistic for URLs stored in browser history, shared logs, or leaked referrers, since query strings (including `signature`) are commonly exposed this way. No modification of the signed shop/path/timestamp is needed, only replay, so the missing time-bound check is directly exploitable once such a URL is obtained.

### Recommendation
Add a timestamp freshness check in `query_string_valid?`/`verify_proxy_request`: reject requests whose `timestamp` query parameter is older than an acceptable window (e.g., a few minutes) relative to `Time.now.to_i`, in addition to the existing HMAC check, mirroring the fix recommended in the source report (bound the signed timestamp to a valid window rather than trusting the signature alone).

### Proof of Concept
1. Configure an app with app-proxy enabled and `ShopifyApp.configuration.secret` set.
2. Capture (or compute, given the shared secret is not needed by the attacker — only the resulting signed URL) a valid app-proxy request, e.g. `shop=some-store.myshopify.com&path_prefix=%2Fapps%2Fmy-app&timestamp=1466106083&signature=<valid-hmac>` as demonstrated in the existing test fixtures. [4](#0-3) 
3. Replay this exact query string against the app's proxy endpoint at any later date. `query_string_valid?` still returns `true` because it only recomputes and compares the HMAC, never checking that `timestamp` (1466106083, an old Unix timestamp from 2016) is anywhere close to `Time.now`. [5](#0-4) 
4. The stale request is accepted and processed as if freshly issued by Shopify.

# frozen_string_literal: true

module ShopifyApp
  module AppProxyVerification
    extend ActiveSupport::Concern
    included do
      skip_before_action :verify_authenticity_token, raise: false
      before_action :verify_proxy_request
    end

    def verify_proxy_request
      head(:forbidden) unless query_string_valid?(request.query_string)
    end

    private

    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end

    def calculated_signature(query_hash_without_signature)
      sorted_params = query_hash_without_signature.collect { |k, v| "#{k}=#{Array(v).join(",")}" }.sort.join

      OpenSSL::HMAC.hexdigest(
        OpenSSL::Digest.new("sha256"),
        ShopifyApp.configuration.secret,
        sorted_params,
      )
    end
