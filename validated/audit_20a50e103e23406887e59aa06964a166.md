### Title
Unparsed-scalar early return in `KeyMachine::calculate_share` skips the queued proof-of-possession check, letting a forged `EncryptedMessage` elicit a blame proof that reveals a third party's ECDH key - (File: crypto/dkg/pedpop/src/lib.rs)

### Summary
`KeyMachine::calculate_share` decrypts each incoming `EncryptedMessage` and queues the per-message Schnorr proof-of-possession (`msg.pop`) into a shared `BatchVerifier`, but only runs `batch.verify_with_vartime_blame()` after all shares are parsed. If a decrypted share fails `C::F::from_repr`, the function returns `PedPoPError::InvalidShare` early — with `blame: Some(EncryptionKeyProof)` — without ever verifying the queued PoP. This mirrors the OpenClaw bug class: a "non-simple" input shape (ciphertext that decrypts to a non-canonical scalar) takes a path where preflight authentication (the PoP) is silently skipped.

### Finding Description
In `Encryption::decrypt`, the message's PoP is queued into the caller's batch verifier under `BatchId::Decryption(l)`, the ECDH key `k = enc_key * msg.key` is computed immediately, and an `EncryptionKeyProof { key, dleq }` attesting to `k` is returned unconditionally [1](#0-0) . In `calculate_share`, the returned plaintext is fed to `C::F::from_repr`; on failure the code returns `InvalidShare { participant: l, blame: Some(blame) }` — before the `batch.verify_with_vartime_blame()` call at line 493 ever checks the PoP [2](#0-1) .

This is precisely the attack the PoP was designed to prevent, documented in `EncryptedMessage`'s own comments: without a PoP, Eve can copy Alice's observed per-message key `X` into her own message to Bob; the message fails to decrypt, Bob issues blame revealing `b·X`, and that published key also decrypts Alice's real message to Bob [3](#0-2) . The PoP is the sole guard; on the `from_repr`-failure path it is queued but never verified, so the guard fails open exactly when the message is malformed in this specific way.

The emitted `EncryptionKeyProof` is cryptographically valid regardless: its DLEq proves `enc_key` consistency over `[G, msg.key] → [enc_pub_key, key]`, and the processor will forward `blame` in `ProcessorMessage::InvalidShare` and re-check it in `VerifyBlame` [4](#0-3) [5](#0-4) . Third-party `decrypt_with_proof` will later blame the sender for the invalid signature, but by then the ECDH key is already public.

### Impact Explanation
An unprivileged DKG participant (reachable via public `EncryptedMessage` bytes fed to `EncryptedMessage::read` and `calculate_share`) can cause publication of the ECDH shared key `b·X` for a per-message key `X` they do not own. If `X` is a key another honest sender actually used to encrypt a secret share to the victim, that share becomes publicly decryptable — disclosure of a Pedersen/Feldman secret share that contributes to the victim's `ThresholdKeys` secret. This converts a defense-in-depth PoP into a fail-open check on adversarially shaped messages, leaking protocol secrets the PoP explicitly exists to protect.

### Likelihood Explanation
The attacker only needs to observe one honest `EncryptedMessage` (to copy `msg.key`), then send a message with that key, any garbage PoP, and a payload that decrypts to bytes outside the scalar field — trivially constructible by encrypting 0xff-filled bytes under a key they control, or sending random ciphertext (a random 32-byte string fails `from_repr` for Ristretto/ed25519-class fields with probability ≈ 1 − 2^−3). The victim's `calculate_share` then emits a valid, publishable blame proof revealing the shared key. No collusion or validator privilege is required; only participation in or observation of a key-generation session.

### Recommendation
Verify the PoP before disclosing anything derived from the message. Concretely: in `calculate_share`, do not attach `Some(blame)` on the `from_repr` early-return path until the queued batch (including `BatchId::Decryption(l)`) has been verified — e.g., run `batch.verify_with_vartime_blame()` first and map a `Decryption(l)` failure to `InvalidShare { participant: l, blame: None }`, only attaching the `EncryptionKeyProof` once the PoP is known-valid. Alternatively, have `Encryption::decrypt` verify `msg.pop` inline (as `decrypt_with_proof` already does) and refuse to produce the ECDH proof for unauthenticated messages.

### Proof of Concept
1. Alice (participant `a`) honestly sends Bob (participant `b`) `Enc_b(share_{a→b})` with per-message key `X`, PoP `σ_a`.
2. Mallory observes `X` (public in the message encoding) and crafts `msg' = { key: X, pop: garbage, msg: <32 bytes that decode under b·X to ≥ field modulus> }`. Mallory cannot produce a valid PoP for `X`, but does not need to.
3. Bob runs `machine.calculate_share(rng, shares)` where `shares[Mallory] = EncryptedMessage::read(msg')`. `decrypt` queues Mallory's PoP into `batch` under `Decryption(Mallory)` and returns the `EncryptionKeyProof` for `k = b·X`.
4. `C::F::from_repr` fails on the decrypted garbage → `InvalidShare { participant: Mallory, blame: Some(proof) }` returned at lib.rs:480-482; `batch.verify_with_vartime_blame()` at lib.rs:493 is never reached, so the invalid PoP is never detected on this path.
5. Bob's processor publishes `InvalidShare` with the blame; `k = b·X` is now public. Anyone (including Mallory) uses `k` with `cipher::<C>(context, k)` to decrypt Alice's genuine ciphertext to Bob, recovering Alice's secret share contribution — the exact disclosure the PoP comment block at encryption.rs:83-91 was added to prevent.
