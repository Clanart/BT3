## Analysis

`handle_unsigned` is a fully permissionless, `ensure_none` unsigned extrinsic accepting an arbitrary `Vec<Message>` in any order, and consensus messages are public/independently verifiable proofs that anyone can resubmit. [1](#0-0) 

`Pallet::execute` runs `handle_incoming_message` over every message in the batch, flattens **all** resulting events (including every `StateMachineUpdated` from every message), and passes the entire flattened `events` vector alongside `messages_with_weights` to a single `FeeHandler::on_executed(messages, events)` call — there is no per-message correlation preserved between an individual message and the events it produced. [2](#0-1) 

In `pallet-consensus-incentives`, `on_executed` derives `relayer_account` **exclusively from `messages[0]`** (recovering the sr25519 pubkey from that single message's signature), then loops over **every** `StateMachineUpdated` event in the whole batch — regardless of which message produced it — crediting `relayer_account` for each one via `process_message`. [3](#0-2) 

Because `messages[1..N]`'s validity is checked independently by `handle_incoming_message` (real, valid consensus proofs from other relayers), an attacker can prepend a single self-signed, minimal/no-op `Message::Consensus` (any consensus message that passes the client's proof check, even one advancing 0 blocks or trivial recert) as `messages[0]`, then append genuine, previously-broadcast valid consensus proofs for unrelated state machines as `messages[1..N]`. All of these messages independently pass verification in `execute`, all their `StateMachineUpdated` events get flattened into the shared `events` vector, and `on_executed` attributes every one of them to the attacker's `relayer_account` recovered from `messages[0]` alone — including chains/state machines the attacker's own message never touched.

The reward-calculation watermark (`LastRewardedHeight`) prevents double-payment for the same height across separate calls, but it does not prevent misattribution of *which account* is paid within a single batch — the attacker still receives the reward that would have paid the actual submitters of `messages[1..N]`.

### Title
Consensus-incentive reward misattribution via batch relayer-derivation from `messages[0]` only - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`FeeHandler::on_executed` for consensus incentives recovers the rewarded relayer identity solely from `messages[0]`'s signature, but pays out for every `StateMachineUpdated` event in the entire batch, letting an attacker's trivial self-signed consensus message hijack rewards earned by other relayers' unrelated consensus messages bundled in the same `handle_unsigned` call.

### Finding Description
`Pallet::execute` in `pallet-ismp` verifies each message in a submitted batch independently, but merges all resulting events into one flat list before invoking `T::FeeHandler::on_executed(messages_with_weights, events)`. [4](#0-3) 
`pallet-consensus-incentives::on_executed` then extracts `maybe_relayer_account` from `messages.get(0)` only, and if it is a valid `Message::Consensus` with a recoverable signature, iterates the *entire* batch's `StateMachineUpdated` events (deduplicated per state machine to the highest height) and rewards that single account for each one. [5](#0-4) 
Since `handle_unsigned` is an unsigned, permissionless extrinsic accepting a free-form `Vec<Message>`, any caller can construct such a batch by prepending a trivial self-signed consensus message and appending unrelated but valid consensus proofs already produced by real relayers. [6](#0-5) 

### Impact Explanation
The attacker diverts `RelayerRewarded` treasury payouts and reputation-asset mints for state-machine updates they did not produce, at the direct expense of the honest relayers whose consensus proofs were absorbed into the batch. This is a wrong-beneficiary/stolen-relayer-incentive outcome matching the "wrong beneficiary or amount" and "logic attacks" impact categories.

### Likelihood Explanation
High: the extrinsic is `ensure_none` and free to call by anyone; consensus proofs for other state machines are public once broadcast (or can be independently re-derived), so an attacker only needs to bundle their own signed message first in the `Vec<Message>` argument — no privileged access, front-running, or infrastructure compromise required.

### Recommendation
Attribute rewards per-message rather than per-batch: track which `Message::Consensus` entry produced which `StateMachineUpdated` event (e.g., by correlating each consensus message's target `state_machine_id`/`consensus_state_id` before dispatch, and recovering a distinct relayer identity per message), so `process_message` only pays the signer whose own message actually advanced that specific state machine.

### Proof of Concept
1. Attacker crafts `msg0 = Message::Consensus(trivial_proof)` signed with their own key, valid against the consensus client but advancing state machine `A` by 0 (or minimal) blocks.
2. Attacker collects `msg1..msgN`, valid `Message::Consensus` proofs for state machines `B, C, D` originally broadcast/relayed by other parties.
3. Attacker submits `handle_unsigned(origin: none, messages: [msg0, msg1, ..., msgN])`.
4. `Pallet::execute` verifies all messages, emits `StateMachineUpdated` for `A, B, C, D`, and calls `on_executed(messages_with_weights, [StateMachineUpdated{A}, StateMachineUpdated{B}, ...])`.
5. `on_executed` recovers `relayer_account` from `msg0`'s signature only, then loops over all four `StateMachineUpdated` events and calls `process_message` for `B, C, D` too, transferring treasury rewards and minting reputation to the attacker's account for state machines their own message never advanced. [7](#0-6)

			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

			.iter()
			.zip(messages)

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}
