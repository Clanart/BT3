### Title
Unprivileged bandwidth-subscription eviction lets an attacker destroy a victim's prepaid bandwidth via the uncapped-cost, capped-array FIFO in `pallet-bandwidth` - (File: `modules/pallets/bandwidth/src/lib.rs`)

### Summary
`pallet-bandwidth` stores prepaid bandwidth as a FIFO `BoundedVec<Subscription, MAX_SUBSCRIPTIONS>` (cap 1024) per `(app_chain, app)` key [1](#0-0) . Any external account can call the public `purchase()` function on `BandwidthManager.sol` and freely choose the target `chain`/`app` to credit — this is the intended "sponsorship" feature [2](#0-1) . When the target's list is at cap, `push_subscription` unconditionally evicts index 0 (the oldest entry) irrespective of its remaining byte value, to make room for the new (attacker-chosen, cheapest-tier) entry [3](#0-2) . This mirrors the M-15 pattern exactly: a capped array (1024, same magnitude as `MAX_DELEGATES`) that any unprivileged party can push into for someone else's account/key, with an inherent cost asymmetry — cheap repeated small purchases can evict a victim's expensive, unconsumed subscription.

### Finding Description
- `Allowance` is a `StorageDoubleMap<StateMachine, AppKey, SubscriptionList>` where `SubscriptionList = BoundedVec<Subscription, ConstU32<1024>>` [4](#0-3) .
- `push_subscription` is called from `on_accept` on every successful purchase message, keyed by `msg.chain` and `msg.app` taken directly from the attacker-supplied purchase payload, not from `request.source`: "Keyed by `app_chain` from the purchase message — *not* `request.source` — so a payer chain can sponsor an app that lives elsewhere" [5](#0-4) .
- When the list is already at `MAX_SUBSCRIPTIONS`, the oldest entry (`list.remove(0)`) is evicted unconditionally, with no check on how much of that entry's `remaining_bytes` is unused, and no consent from or benefit to the party that originally paid for it [6](#0-5) .
- `purchase()` on `BandwidthManager.sol` has no access control on `app`/`chain` beyond non-empty checks, and dispatches with `payer: address(this)` and `fee: 0`, meaning the only cost to the attacker is the tier price of the cheapest configured SKU, e.g. $50 for the smallest tier per the docs [7](#0-6) [8](#0-7) .
- The maintainers' own documentation acknowledges the eviction mechanic exists but dismisses it as only occurring "under pathological repeat-buy behavior," reasoning from *legitimate* usage patterns rather than an adversarial one where any account can target another's queue [9](#0-8) .

This is the direct analog to the M-15 pattern: a bounded, per-key array that (a) any unprivileged actor can append to for a key they don't own, and (b) evicts existing paid-for state without regard to value, with attacker cost far below victim's loss once the queue nears capacity (e.g., a victim who just bought a large multi-month top-up, or whose queue has organically filled up over normal operation, can have that entry evicted by a handful of minimum-tier purchases from any account).

### Impact Explanation
An attacker can force-evict a victim app's unconsumed, already-paid-for bandwidth subscription by targeting the victim's `(chain, app)` key with cheap tier-1 purchases once the FIFO queue is near or at capacity. The victim's app then experiences message rejection (`GateError::NoAllowance`/`Insufficient`) once its legitimate allowance is prematurely drained, effectively a loss of the funds spent on the evicted subscription and a denial of service to the app's cross-chain message flow — matching the "bandwidth balances must move exactly once and only to the rightful beneficiary and amount" and "fund loss" criteria in the impact gate.

### Likelihood Explanation
Medium-to-Low but concretely provable and requires no privileged role, relayer, prover, or governance action — only a series of ordinary `purchase()` calls from any account, which is exactly the codepath meant to be public. The main constraint is that eviction only triggers once the target's queue is at the 1024 cap; how quickly that happens depends on how frequently the target app/chain pair is topped up (repurchases don't stack, they queue, per the module docs), which under sustained usage or targeted spam is achievable. The per-purchase cost is a real payment (tier price), not free, but it can still be far cheaper than the value being destroyed once the queue is near-full.

### Recommendation
Do not evict unconditionally by FIFO age alone. Options: (1) evict by remaining-value/lowest-value heuristic instead of pure insertion order, (2) require the caller purchasing on behalf of another app/chain to be the same `request.from`/an authorized sponsor for that `(chain, app)`, removing the free-for-all targeting, (3) refund or otherwise compensate the evicted subscription's unused bytes rather than silently destroying them, or (4) increase `MAX_SUBSCRIPTIONS` cost-effectively or rate-limit purchases per `(chain, app)` from non-owning payers to prevent cheap queue-filling attacks.

### Proof of Concept
1. Governance registers a `BandwidthManager` on chain `C` and configures at least one cheap tier (e.g., Tier 1, $50/100KB) and one expensive tier (e.g., Tier 4, $1000/8MB).
2. Victim app `A` on `C` legitimately purchases a large Tier-4 top-up; this becomes the newest entry in `Allowance[C][A]` once earlier organic purchases have already filled the list close to 1024 entries (or the attacker first fills the queue themselves with 1024 minimum-tier purchases targeting `(C, A)` before the victim ever buys).
3. Attacker (any unrelated account, no relationship to app `A`) repeatedly calls `BandwidthManager.purchase(app=A, tier=1, months=1, chain=C)`, paying only the Tier-1 price each time.
4. Once `Allowance[C][A].len() == MAX_SUBSCRIPTIONS`, each subsequent attacker purchase evicts the oldest entry via `push_subscription`'s `list.remove(0)` [6](#0-5) , regardless of whether that oldest entry still has substantial `remaining_bytes` the victim paid for and hasn't consumed.
5. Result: the victim's paid-for allowance is destroyed by a third party who spent comparatively little, and `BandwidthConsumed`/`NoAllowance` failures start appearing for app `A`'s legitimate ISMP traffic through the `BandwidthGate::try_consume` path [10](#0-9) .

Note: I was not able to fully verify the exact economics of how quickly a real-world queue reaches the 1024 cap under production purchase volume — this depends on operational data (purchase frequency per app) not present in the indexed code, so the precise cost-to-attacker vs. value-destroyed ratio in a live deployment is an assumption rather than a directly-observed fact.

    /// `(chain, app)` bucket bounded by tier `bytes` × `months`.

    /// @param tier Tier discriminant; must be configured via `SetTiers`.
    /// @param months Number of tier-windows to credit; must be > 0.

        external
        returns (bytes32 commitment)
    {
        if (app.length == 0 || chain.length == 0 || months == 0) revert InvalidPurchase();
        uint256 price18d = tierPrice[tier];
        if (price18d == 0) revert UnknownTier();

        uint256 total18d = price18d * months;
        address feeToken = IDispatcher(_host).feeToken();
        uint8 dec = IERC20Metadata(feeToken).decimals();
        uint256 scale = 10 ** (18 - dec);
        if (total18d % scale != 0) revert PriceNotRepresentable();

        IERC20(feeToken).safeTransferFrom(msg.sender, address(this), amount);

        BandwidthPurchaseMsg memory body = BandwidthPurchaseMsg({
            app: app,
            tier: tier,
            months: months,
            chain: chain
        });

        commitment = IDispatcher(_host).dispatch(
            DispatchPost({
                dest: IDispatcher(_host).hyperbridge(),
                to: PALLET_BANDWIDTH_MODULE_ID,
                body: abi.encode(body),
                timeout: 0,
                fee: 0,
                payer: address(this)
            })

		/// Append a fresh subscription with a fixed expiry. If the list
		/// is already at `MaxSubscriptions`, evict the oldest entry and
		/// emit [`Event::SubscriptionEvicted`] so the lost bytes are
		/// auditable. Returns the new subscription's `expires_at`.
		fn push_subscription(
			app_chain: &StateMachine,
			app: &AppKey,
			tier: TierIndex,
			bytes: BandwidthBytes,
			duration_secs: u64,
		) -> u64 {
			let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();
			let expires_at = now.saturating_add(duration_secs);
			let new_sub =
				Subscription { tier, remaining_bytes: bytes, expires_at, purchased_at: now };

			let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
				let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
					Some(list.remove(0))
				} else {
					None
				};
				// Capacity is now guaranteed; try_push can't fail.
				let _ = list.try_push(new_sub);
				evicted
			});

			if let Some(old) = evicted {
				Self::deposit_event(Event::SubscriptionEvicted {
					app_chain: *app_chain,
					app: app.clone(),
					tier: old.tier,
					lost_bytes: old.remaining_bytes,
				});
			}

			expires_at
		}

impl<T: Config> BandwidthGate for Pallet<T> {
	fn try_consume(
		source: &ismp::host::StateMachine,
		app: &[u8],
		bytes: u32,
	) -> Result<(), GateError> {
		let key = AppKey::truncate_from(app.to_vec());
		if Allowlist::<T>::contains_key(source, &key) {
			return Ok(());
		}

		let need: u128 = bytes.into();
		let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();

		let total = pallet::Allowance::<T>::mutate(source, &key, |list| {
			// Sweep expired in-place. Order-preserving.
			list.retain(|s| s.expires_at > now);

			if list.is_empty() {
				return Err(GateError::NoAllowance);
			}

			let total: u128 = list.iter().map(|s| s.remaining_bytes).sum();
			if total < need {
				return Err(GateError::Insufficient { remaining: total, required: need });
			}

			// Drain from the front in insertion order. Once a sub is
			// fully consumed, pop it and continue with the next.
			// `get_mut` defends against a malformed list that satisfies
			// the `total >= need` precheck but is structurally empty;
			// we'd otherwise panic via `list[0]`.
			let mut left = need;
			while left > 0 {
				let Some(head) = list.get_mut(0) else {
					return Err(GateError::NoAllowance);
				};
				let take = head.remaining_bytes.min(left);
				head.remaining_bytes = head.remaining_bytes.saturating_sub(take);
				left = left.saturating_sub(take);
				if head.remaining_bytes == 0 {
					list.remove(0);
				}
			}

			Ok(total)
		})?;

		Self::deposit_event(Event::BandwidthConsumed {
			source: *source,
			app: key,
			bytes: need,
			remaining: total - need,
		});
		Ok(())
	}
