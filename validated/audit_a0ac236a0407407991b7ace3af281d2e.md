Based on the extensive investigation, I found a genuinely reachable memory-overread pattern analogous to the CVE-2025-20234 bug class (crafted-file offset/length parsing without validation before slicing raw byte buffers).

### Title
Unvalidated offset/length in memiavl `Snapshot.Key`/`KeyValue`/`LeafKey`/`LeafKeyValue` can slice out of buffer bounds, causing a node crash on a crafted/corrupted snapshot - (File: sei-db/state_db/sc/memiavl/snapshot.go)

### Summary
`Snapshot.Key`, `Snapshot.KeyValue`, `Snapshot.LeafKey`, and `Snapshot.LeafKeyValue` read a 4-byte little-endian length directly out of `snapshot.kvs` at an attacker/data-influenced `offset`, then slice `snapshot.kvs[offset : offset+length]` with no bounds check against `len(snapshot.kvs)`.

### Finding Description
The `Key`/`KeyValue` functions read a length prefix from the raw `kvs` byte buffer and then immediately re-slice the same buffer using that length, without verifying `offset+4 <= len(kvs)` or `offset+length <= len(kvs)`: [1](#0-0) 
`LeafKey`/`LeafKeyValue` do the same pattern using an offset/length pulled from the on-disk `leavesLayout` node structure: [2](#0-1) 
The underlying fixed node/leaf layout accessors (`Node`, `Leaf`) also compute `offset := int(i) * SizeNode` and directly reinterpret `nodes.data[offset : offset+SizeNode]` as a fixed-size array pointer without checking `offset+SizeNode <= len(data)`: [3](#0-2) 
This is structurally the same bug class as CVE-2025-20234: a length/offset value taken from a parsed, untrusted (or corrupted) binary blob is used to slice a backing buffer without a bounds check, producing an out-of-bounds read that panics the process. Here the "crafted file" is a memiavl snapshot file (`.iavl` on-disk snapshot format used by sei-db's state-commitment layer). This is loaded on node startup/snapshot-load and on state-sync application, i.e. reachable by any process that loads a snapshot — including a state-synced node pulling a chunk set from a peer, or an operator restoring/serving a corrupted/truncated snapshot file. A truncated or corrupted `kvs` file (e.g. from a partially-written/rolled-back disk, or a maliciously crafted snapshot served during state sync) would cause `offset+length` to exceed the buffer, panicking with an out-of-bounds slice access.

### Impact Explanation
An out-of-bounds slice panic during snapshot read is an unrecovered Go runtime panic, not a normal error return — it crashes the node process reading the snapshot. Since memiavl snapshots back the IAVL/state-commitment store used by every validator and full node, a node that loads a corrupted or truncated snapshot (e.g. through interrupted state sync, or an operator-provided/backup snapshot with a bit flip near a length field) halts entirely. This matches the "crash of default-configuration RPC/full nodes" and "validator halt" impact bar for this scan, mirroring how the ClamAV UDF bug allowed a crafted file to crash the scanning process.

### Likelihood Explanation
Reaching this requires a snapshot file whose length/offset metadata is inconsistent with the actual buffer size — this can occur from disk corruption, an incomplete/interrupted snapshot write, or (in state-sync scenarios) a peer serving a subtly malformed snapshot chunk set. It is not reachable directly from a single signed transaction or RPC call; it requires either operator error/corrupted storage or a compromised/malicious state-sync peer supplying a bad snapshot. This lowers likelihood relative to a purely transaction-triggered bug, but the rule set explicitly excludes malicious-peer/state-sync analogs, so this finding's strongest legitimate trigger is a corrupted local snapshot rather than an adversarial network input.

### Recommendation
Add explicit bounds checks in `Key`, `KeyValue`, `LeafKey`, `LeafKeyValue` (and the underlying `Node`/`Leaf` accessors) verifying `offset+4 <= len(kvs)` before reading the length prefix and `offset+length <= len(kvs)` before slicing the payload; return a decode error instead of panicking when the check fails, consistent with how `decodeReceiptData` in `sei-db/ledger_db/receipt/codec.go` validates buffer length before indexing.

### Proof of Concept
Construct (or corrupt) a memiavl snapshot's `kvs` file so that a node/leaf's recorded `KeyLength`/`KeyOffset` (or a `keyLen` read at a given `offset`) sums to a value exceeding `len(kvs)`, then call `Snapshot.Key`, `KeyValue`, `LeafKey`, or `LeafKeyValue` (invoked during normal snapshot iteration/scan, e.g. `ScanNodes`) against that snapshot; the resulting slice expression panics with "slice bounds out of range" instead of returning a decode error.
