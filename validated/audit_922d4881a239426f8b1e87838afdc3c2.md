### Title
Excess native-token overpayment in `EvmHost.dispatch`/`fundRequest` is misrouted to the Host contract instead of refunded to the caller - ([File: evm/src/core/EvmHost.sol])

### Summary
This is a direct local analog of the GovernorAlpha bug: the external report showed ETH landing at the wrong holder (`msg.sender` instead of `Timelock`) because a swap/transfer step didn't account for whose balance actually received leftover value. In `EvmHost`, every native-token-funded dispatch path (`dispatch(DispatchPost)`, `dispatch(DispatchGet)`, and `fundRequest`) swaps `msg.value` through Uniswap V2's `swapETHForExactTokens` for an *exact* `fee`/`amount` of `feeToken`, but the swap is invoked by the `EvmHost` contract itself, not by the original caller. [1](#0-0) 

### Finding Description
`dispatch(DispatchPost memory post)` does:
```solidity
IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
    post.fee, path, address(this), block.timestamp
);
``` [1](#0-0) 

Standard `UniswapV2Router02.swapETHForExactTokens` refunds any unused native token (`msg.value - amountIn`) to `msg.sender` of the swap call. Because `EvmHost` itself calls the router with `{value: msg.value}`, `msg.sender` from the router's perspective is `EvmHost`, not the account that originally called `dispatch`/`fundRequest`. Any ETH sent in excess of what's needed to buy exactly `post.fee` worth of `feeToken` is refunded back into `EvmHost`'s own balance rather than to `_msgSender()` (the depositor).

The same pattern repeats in `dispatch(DispatchGet)` and `fundRequest`: [2](#0-1) [3](#0-2) 

There is no code path in `dispatch`/`fundRequest` that forwards or accounts for this refund back to the caller. The only way this stray ETH can leave the contract is through the privileged `IHostManager.withdraw` path, which is reserved for the authorized `hostManager` (governance) — an ordinary user who overpays `msg.value` (e.g., due to normal price-slippage buffering, since callers must estimate `nativeFee` off-chain and typically add a safety margin, as documented in the SDK examples) permanently loses the ability to reclaim their own excess funds through any user-facing entrypoint. [4](#0-3) 

This mirrors the GovernorAlpha analog exactly: a value-forwarding step silently redirects funds to the calling contract's own balance instead of the intended party, and only a privileged actor (Timelock's owner-equivalent / here, `hostManager`) can move it afterward — the affected user has no recourse.

### Impact Explanation
Any user who dispatches a request or funds one with native token and slightly overestimates `nativeFee` (which the docs' `quote()` -> `send{value: nativeFee}` pattern all but guarantees under any price movement between quoting and mining) has their excess ETH swept into `EvmHost`'s balance instead of refunded. This is a direct, unauthorized-by-consent loss of user funds — the excess is not stolen by an attacker, but it is misappropriated by contract logic error into the protocol's own balance without the user's knowledge or ability to reclaim it, which matches the "stealing or loss of funds" bounty class.

### Likelihood Explanation
This triggers on the ordinary, unprivileged, single-transaction happy path — any `dispatch`/`fundRequest` caller who pays with native token and supplies `msg.value` even marginally above the exact-output requirement (a near-certainty in production due to price movement between off-chain quoting and on-chain execution) loses the difference. No malicious peer, relayer, or governance actor is required.

### Recommendation
After the `swapETHForExactTokens` call, compute the actual native-token spent (`msg.value` minus the router's return value / or track balance delta) and refund the remainder to `_msgSender()` (or `post.payer`), mirroring the fix pattern already used correctly in `UniV4UniswapV2Wrapper.swapETHForExactTokens`, which snapshots balance and explicitly forwards `refundETH` back to `msg.sender`: [5](#0-4) 

### Proof of Concept
1. User calls `EvmHost.dispatch{value: X}(post)` where `post.fee = F` and `X > amountIn required to buy F feeToken` (realistic since `X` is estimated off-chain via `quote()` and typically padded for slippage).
2. `swapETHForExactTokens{value: X}(F, path, address(this), ...)` buys exactly `F` feeToken; the router refunds `X - amountIn` in ETH to `msg.sender`, which is `EvmHost`.
3. The refunded ETH accumulates in `EvmHost`'s balance. `dispatch` returns normally; the user's dispatched request succeeds, but the leftover ETH is now unrecoverable by the user — it can only be moved out via `IHostManager.withdraw`, callable exclusively by the privileged `hostManager` contract.
