### Title
`commitMentionUrl` regex lacks a start-anchor and relies on loose owner/name validation, allowing arbitrary attacker-hosted URLs to be relabeled as trusted commit references - (File: `app/src/lib/markdown-filters/commit-mention-link-filter.ts`)

### Summary
`CommitMentionLinkFilter` builds `commitMentionUrl` by concatenating `escapeRegExp(gitHubURL)` with the `nameWithOwner` sub-pattern and the commit/pull/compare path, but never anchors the whole expression with `^`/`$`. Combined with the loose `nameWithOwner` pattern (`-?[a-z0-9][a-z0-9\-_]*\/(?:\w|\.|\-)+`), `commitMentionUrl.test(el.href)` returns `true` as soon as the literal substring `https://github.com/<owner>/<name>/(commit|pull|compare)/<sha>` appears *anywhere* inside the href — even deep inside the path or query string of a completely different, attacker-controlled host. [1](#0-0) [2](#0-1) 

### Finding Description
`CommitMentionLinkFilter.createFilterTreeWalker` only accepts anchor elements whose `href` equals their `innerText` and whose `href` matches `commitMentionUrl`: [3](#0-2) 

Because GitHub-flavored markdown auto-links bare URLs into `<a href="X">X</a>` (href === innerText), an attacker can supply a plain-text URL such as:

```
https://evil.example.com/track?next=https://github.com/octocat/Hello-World/commit/aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa
```

as PR/issue body text, PR/issue comment text, or a commit message on an attacker-controlled repository. This content is rendered through `buildCustomMarkDownNodeFilterPipe`, which applies `CommitMentionLinkFilter` for `PullRequest`, `PullRequestComment`, `IssueComment`, and `Commit` markdown contexts: [4](#0-3) 

Because `commitMentionUrl` has no `^` anchor, `.test()` matches the substring `https://github.com/octocat/Hello-World/commit/aaaa...` located inside the query string of the `evil.example.com` URL, even though the real host of the href is `evil.example.com`. The `nameWithOwner` sub-pattern's loose character classes (`[a-z0-9\-_]*` for owner, `(?:\w|\.|\-)+` for name) do not add extra protection here — they simply make it easier for an attacker to also use owner/name values containing a leading hyphen or other characters that still parse via `new URL(text).pathname.split('/', 3)` in `filter()`, but the decisive bug enabling the exploit is the missing start anchor, not the hyphen tolerance by itself.

Once matched, `filter()` re-parses `el.innerText` (which is identical to href) with `new URL(text)` and rewrites the anchor's **visible text** to the short, trusted-looking form `owner/name@sha` (or just the short sha if it belongs to the current repo): [5](#0-4) [6](#0-5) 

Critically, the filter only replaces `newNode.innerHTML`; it never touches the anchor's `href` attribute. The final DOM node retains `href="https://evil.example.com/track?next=https://github.com/octocat/Hello-World/commit/aaaa..."` while displaying only `octocat/Hello-World@aaaaaaa` as the clickable text — laundering the attacker's link through a trusted-looking, GitHub-style commit reference.

### Impact Explanation
A user viewing a PR/issue/commit description in GitHub Desktop's sandboxed markdown viewer sees what looks like a normal, safe commit reference (`owner/name@sha`), but clicking it navigates to an arbitrary attacker-controlled URL rather than to GitHub. This can be used for phishing (e.g., fake GitHub login pages to steal credentials/OAuth tokens) or to funnel the user to a malicious download, achieving link-spoofing under the guise of a trusted repository reference — a link the user is far more likely to click than an unfamiliar raw URL.

### Likelihood Explanation
Exploitation only requires the attacker to control markdown content rendered by Desktop (a PR body/comment, issue comment, or commit message) on a repository the victim opens in Desktop — well within the stated unprivileged threat model (attacker-controlled GitHub API object/repository content). No special user interaction beyond a normal click on what looks like a legitimate commit reference is required.

### Recommendation
Anchor `commitMentionUrl` at the start of the string (and ideally scope it to the URL's origin/pathname rather than the raw href string), e.g. build and test against `url.origin + url.pathname` with a `^`/`$`-anchored regex, so a match can't occur on a substring embedded inside an unrelated host's path or query. Additionally, tighten `nameWithOwner` to match GitHub's actual owner-name rules (no leading hyphen) as defense in depth, and verify `new URL(el.href).host === new URL(gitHubURL).host` before treating the link as a genuine GitHub commit/PR/compare reference.

### Proof of Concept
1. Craft a comment/PR body containing the bare text:
   `https://evil.example.com/track?next=https://github.com/octocat/Hello-World/commit/aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa`
2. GFM auto-linking turns this into `<a href="https://evil.example.com/track?next=https://github.com/octocat/Hello-World/commit/aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa">https://evil.example.com/track?next=https://github.com/octocat/Hello-World/commit/aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa</a>` (href === innerText).
3. `commitMentionUrl.test(el.href)` returns `true` because the substring `https://github.com/octocat/Hello-World/commit/aaaaaaa...` is found (no `^` anchor forces a start-of-string match).
4. `filter()` rewrites the visible text to `octocat/Hello-World@aaaaaaa`, but the anchor's `href` attribute (and thus the actual navigation target) remains `https://evil.example.com/track?next=...`.
5. Inspecting the rendered DOM node's `href` property confirms the host is `evil.example.com`, not `github.com`, despite the trusted-looking label.

  private get commitMentionUrl(): RegExp {
    const gitHubURL = getHTMLURL(this.repository.endpoint)
    return new RegExp(
      escapeRegExp(gitHubURL) +
        '/' +
        this.nameWithOwner.source +
        '/' +
        /(commit|pull|compare)/.source +
        '/' +
        /(\d+\/commits\/)?/.source +
        /([0-9a-f]{7,40})/.source +
        /\b/.source
    )
  }

  public createFilterTreeWalker(doc: Document): TreeWalker {
    return doc.createTreeWalker(doc.body, NodeFilter.SHOW_ELEMENT, {
      acceptNode: (el: Element) => {
        return (el.parentNode !== null &&
          ['CODE', 'PRE', 'A'].includes(el.parentNode.nodeName)) ||
          !isElement(el, 'a') ||
          el.href !== el.innerText ||
          !this.commitMentionUrl.test(el.href)
          ? NodeFilter.FILTER_SKIP
          : NodeFilter.FILTER_ACCEPT
      },
    })
  }

  private getCommitMentionRef(
    owner: string,
    name: string,
    shaRef: string,
    filePath?: string
  ) {
    const ownerRepo =
      owner !== this.repository.owner.login || name !== this.repository.name
        ? `${owner}/${name}@`
        : ''
    const trimmedSha = this.trimCommitSha(shaRef)
    return `${ownerRepo}<tt>${trimmedSha}</tt>${filePath ?? ''}`
  }
