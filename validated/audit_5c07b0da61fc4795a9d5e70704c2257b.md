**Analysis:**

`_setParams` is only invoked from `onAccept`, which is gated by two independent checks: the `onlyHost` modifier (inherited from `HyperApp`) requires `msg.sender == host()` [1](#0-0) , and the function body additionally requires the ISMP request's `source` to equal the local host's registered `hyperbridge()` governance module id [2](#0-1) . Only when both checks pass does `_setParams(abi.decode(payload, (Params)))` execute for `RequestKind.UpdateParams` [3](#0-2) .

There is no public/external setter that reaches `_setParams` directly, and no reentrant path exists from `_executePermit` or `swapAndDeposit`: `_executePermit` only calls the token's `permit()` and never touches `_setParams` or `treasury` [4](#0-3) , and `swapAndDeposit` is itself gated by `msg.sender != treasury` revert, so it cannot be triggered by an arbitrary caller either [5](#0-4) .

Consequently, setting an attacker-controlled `treasury` via `UpdateParams` requires the message to be delivered by the legitimate local ISMP host *and* to have `source` equal to Hyperbridge's own governance module — i.e., it requires a forged/false consensus proof accepted by the host, or compromise of Hyperbridge governance itself. Under this bounty's scope, false proof acceptance by the ISMP host/consensus layer is a separate, already-covered concern (proof/state-commitment verification), and no unprivileged call path in `SimplexPaymaster.sol` itself allows bypassing these two checks. The described attack path requires privileged/infrastructure compromise, which is out of scope per the Decision Standard and Review Path rejection criteria (governance/auth checks already stop the path).
