### Title
Commit author identity spoofing via unverified stealth-email pattern match lets a malicious commit be displayed as authored by "Copilot" - (File: `app/src/models/avatar.ts`)

### Summary
`getAvatarUsersForCommit` special-cases any commit whose author/committer/co-author *name* string is exactly `copilot-swe-agent[bot]`: it feeds the corresponding *email* (also attacker-controlled, taken straight from the commit object) into `parseStealthEmail`, and if that function's regex match yields the literal login `Copilot`, Desktop overwrites the displayed name from `copilot-swe-agent[bot]` to `Copilot` [3](#0-2) . `parseStealthEmail` performs no verification against the GitHub API or any account list — it is a pure regex match on the email string plus a host-suffix comparison [2](#0-1) . Any commit — including one in a maliciously crafted, fetched/cloned repository or fork PR — that sets `author.name = "copilot-swe-agent[bot]"` and `author.email = "<anything>+Copilot@users.noreply.github.com"` (or the GHES-equivalent host) will pass this check and be rendered in the commit list, commit summary, and avatar tooltips as authored by `"Copilot"`.

### Finding Description
The broken invariant: Desktop treats "the commit author's name equals a specific bot string and the email pattern-matches a stealth-email format for login `Copilot`" as sufficient proof that the commit was actually authored by GitHub's Copilot coding agent. In reality, both `commit.author.name` and `commit.author.email` are values read directly out of arbitrary git commit metadata via `getCommits`/`CommitIdentity.parseIdentity` [4](#0-3) , which git allows to be set to any attacker-chosen string when the attacker controls the repository/commit (e.g., a repo the user clones/fetches, or a PR branch checked out from a fork). `parseStealthEmail` is a local, offline regex parser with no server round-trip, no signature check, and no GitHub account lookup — it only confirms the string *shape* looks like a stealth email and that the host suffix matches the endpoint [2](#0-1) . Nothing ties the parsed "login" back to a real, verified account id — the numeric id portion (if present) is not validated. The existing guard that differentiates real GitHub-attributed emails from spoofed ones (`isAttributableEmailFor`, used elsewhere for the user's *own* account) is never applied here; the Copilot-name matching path in `getAvatarUsersForCommit` bypasses any such check entirely and unconditionally trusts the local string parse.

### Impact Explanation
This allows any contributor to a repository (fork PR author, malicious remote maintainer, or anyone who can get a user to fetch/clone a crafted repo) to make an arbitrary commit visually appear in GitHub Desktop's UI as if it were authored by GitHub's official `Copilot` bot, rather than showing the true `copilot-swe-agent[bot]` bot name or an unknown identity. This is a legitimate social/trust deception primitive within the required impact category (misleading trust indicator derived from attacker-controlled repository content, no local/admin access needed) — a reviewer could be led to trust/merge a commit believing it was automated/reviewed by Copilot when it was actually crafted by an untrusted third party. It does not achieve code execution or credential exfiltration by itself, so its severity is that of a UI trust-indicator spoof, but it directly corrupts what the user believes about "what was committed" — a misrepresentation of authorship that could be leveraged in social-engineering-adjacent review/approval workflows.

### Likelihood Explanation
Likelihood is fairly high for triggering the display bug itself: it requires no special git tooling — `git commit --author="copilot-swe-agent[bot] <NNNN+Copilot@users.noreply.github.com>"` is enough, and the malicious commit only needs to be fetched or checked out by the victim (e.g., viewing a fork's PR in Desktop, or pulling a compromised branch) — a normal, expected Desktop workflow, not an unnatural user step.

### Recommendation
Do not resolve a bot's friendly display name from data embedded in arbitrary commit metadata. Only apply the `copilot-swe-agent[bot]` → `Copilot` relabeling when the commit's committer identity has independently been verified as the GitHub web-flow/API committer for the associated `GitHubRepository` (similar to how `isWebFlowCommitter` is scoped to trusted committer name/email pairs tied to `getDotComAPIEndpoint()` [5](#0-4) ), or better, resolve the author against the GitHub API-backed account/mentionable-user data rather than trusting a locally-parsed stealth email pattern.

### Proof of Concept
1. In a repository connected to a `GitHubRepository`, create a commit with:
   ```
   git commit --allow-empty \
     -m "Legit-looking change" \
     --author="copilot-swe-agent[bot] <1+Copilot@users.noreply.github.com>"
   ```
2. Push/fetch this commit into a Desktop-tracked repository (e.g., as a fork PR branch) and view it in Desktop's commit list/history or commit summary.
3. `getAvatarUsersForCommit` matches `au.name === 'copilot-swe-agent[bot]'` and `parseStealthEmail('1+Copilot@users.noreply.github.com', endpoint)?.login === 'Copilot'`, so it renames the author to `"Copilot"` in the UI [6](#0-5) , even though no real GitHub Copilot account created this commit.

const StealthEmailRegexp = /^(?:(\d+)\+)?(.+?)@(users\.noreply\..+)$/i

export const parseStealthEmail = (email: string, endpoint: string) => {
  const stealthEmailHost = getStealthEmailHostForEndpoint(endpoint)
  const match = StealthEmailRegexp.exec(email)

  if (!match || stealthEmailHost !== match[3]) {
    return null
  }

  const [, id, login] = match
  return { id: id ? parseInt(id, 10) : undefined, login }
}

export function isWebFlowCommitter(
  commit: Commit,
  gitHubRepository: GitHubRepository
) {
  if (!gitHubRepository) {
    return false
  }

  const endpoint = gitHubRepository.owner.endpoint
  const { name, email } = commit.committer

  if (
    endpoint === getDotComAPIEndpoint() &&
    name === 'GitHub' &&
    email === 'noreply@github.com'
  ) {
    return true
  }

  if (endpoint !== getDotComAPIEndpoint() && name === 'GitHub Enterprise') {
    // We can't assume that the email address will match any specific format
    // here since the web flow committer email address on GHES is the same as
    // the noreply email which can be configured by domain administrators so
    // we'll just have to assume that for a GitHub hosted repository (but not
    // GitHub.com) a commit author of the name 'GitHub Enterprise' is the web
    // flow author.
    //
    // Hello future contributor: Turns out the web flow committer name is based
    // on the "flavor" of GitHub so it's possible that you're here wondering why
    // this isn't working and chances are it's because we've updated the
    // GHES branding or introduced some new flavor.
    return true
  }

  return false
