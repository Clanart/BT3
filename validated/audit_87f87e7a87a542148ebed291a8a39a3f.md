### Title
Unbounded buffer index reads in `is_atom_canonical` allow a crafted spend bundle to crash mempool admission via unhandled `IndexError` - (File: chia/full_node/mempool_manager.py)

### Summary
`is_atom_canonical()` reads length-prefix continuation bytes from a CLVM-serialized buffer using raw index accesses (`clvm_buffer[offset]`) with no bounds checking against `len(clvm_buffer)`, analogous to the unchecked `memmove`/struct-remap read in CVE-2018-19416's `remap_struct` in sysstat's `sa_common.c`. [1](#0-0) 

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` decodes a CLVM atom's variable-length size prefix (1–6 bytes depending on the leading byte's high bits) and then loops `prefix_len` times, each time incrementing `offset` and reading `clvm_buffer[offset]` to accumulate `atom_len`, with no check that `offset` stays within `len(clvm_buffer)`: [2](#0-1) 

This function is invoked by `is_clvm_canonical()`, which walks an entire CLVM-serialized buffer atom-by-atom without first validating that any atom's declared prefix length fits inside the remaining buffer: [3](#0-2) 

`is_clvm_canonical()` is called unconditionally on every coin spend's `puzzle_reveal` and `solution` during spend bundle admission to the mempool, i.e., directly reachable by any unprivileged party submitting a spend bundle via RPC or protocol message: [4](#0-3) 

By crafting a puzzle reveal or solution whose final bytes end with a large-prefix atom marker (e.g. `0xFC`–`0xFF`, indicating a 4–6 byte trailing length prefix) but only include 1 truncated byte before the buffer ends, the loop in `is_atom_canonical` will attempt to read `clvm_buffer[offset]` for an `offset >= len(clvm_buffer)`, raising an unhandled `IndexError` inside `validate_spend_bundle`. Unlike the C-level OOB read in the CVE (silent memory disclosure/crash), Python raises an exception, but nothing in the call chain shown catches `IndexError` around this call, so the exception propagates out of `is_clvm_canonical` / `validate_spend_bundle`.

### Impact Explanation
An uncaught exception during `validate_spend_bundle` for any submitted spend bundle can abort or corrupt the transaction admission path for the full node, since this validation runs directly in the mempool admission flow that every wallet transaction and offer settlement depends on. If the exception is not caught by a broader try/except somewhere higher up the call stack (which requires code inspection beyond this snippet to confirm definitively), a single malformed but easily crafted spend bundle from any unprivileged submitter could halt or disrupt mempool processing for that node, constituting a spend-triggered transaction-processing denial of service.

### Likelihood Explanation
Likelihood is high for triggering the code path (any RPC caller or peer can submit a `SpendBundle` with an arbitrary puzzle_reveal/solution byte string ending in a truncated multi-byte atom length prefix), but the ultimate severity depends on whether an enclosing exception handler in the mempool manager's `add_spend_bundle`/`pre_validate_spendbundle` pipeline converts this `IndexError` into a graceful rejection (e.g. `Err.INVALID_COIN_SOLUTION`) rather than crashing the node process or leaving mempool state inconsistent. That surrounding exception-handling behavior was not visible in the reviewed snippets and needs verification.

### Recommendation
Add explicit bounds checks in `is_atom_canonical` before each `clvm_buffer[offset]` access (verifying `offset < len(clvm_buffer)` for the initial byte and each of the `prefix_len` continuation bytes), returning/raising a well-defined validation error instead of allowing an `IndexError` to propagate. Ensure `validate_spend_bundle` (and any caller of `is_clvm_canonical`) explicitly catches malformed-buffer conditions and maps them to `Err.INVALID_COIN_SOLUTION` deterministically, matching existing tests such as `test_mempool_requires_canonical_clvm`. [5](#0-4) 

### Proof of Concept
Construct a `puzzle_reveal` or `solution` byte buffer whose last byte is `0xFC` (indicating a 4-byte trailing length prefix per `is_atom_canonical`'s `0b11111100` mask branch) with zero or one trailing bytes, e.g. `bytes([0xFC])`. Passing this as a `CoinSpend.solution` in a `SpendBundle` and submitting it through `push_tx`/`add_spend_bundle` drives execution into `is_clvm_canonical(bytes(coin_spend.solution))` → `is_atom_canonical(clvm_buffer, offset=0)`, which enters the `prefix_len = 4` branch and attempts `clvm_buffer[1]`, `clvm_buffer[2]`, `clvm_buffer[3]`, `clvm_buffer[4]` against a 1-byte buffer, raising `IndexError: index out of range` inside `validate_spend_bundle`. def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
