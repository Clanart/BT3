## Confirmed analog

The `Push()`/`Pop()` recursion counter in `JsonLexer` at [1](#0-0)  decrements a `recursion_depth` field that lives in `options_`, a *member of a single `JsonLexer` instance*. In `ParseAny`, when a nested `google.protobuf.Any` is encountered, the code builds a brand-new `JsonLexer any_lex(&in, lex.options(), &lex.path(), mark.loc);` from a fresh `io::ArrayInputStream` over the buffered `@type` payload, as seen at [2](#0-1) . The comment there ("Copying lex.options() is important; it inherits the recursion limit") is the key assumption to test — but `lex.options()` is copied *by value at the time `ParseAny` starts*, i.e., before any of the outer lexer's `Push()` calls for the current nesting level have been "spent" against the new lexer. Because C++ call-stack recursion is what's actually happening (`ParseAny` → `ParseMessage<Traits>` on the new `any_lex` → possibly another `ParseAny` if the inner Any recurses again), each `Any` boundary resets the recursion-depth *budget* to a fresh full value copied from the outer options at that point, while the underlying native C++ call stack keeps growing across every `Any` level.

This mirrors the CVE-2019-20924 pattern precisely: an internal invariant ("depth is bounded so recursion is safe") holds only within a single object's local bookkeeping and is silently violated once the abstraction is nested/chained by attacker-controlled structure (there, index bounds per single query stage; here, recursion counting per single lexer instance). A client sending nested `Any{"@type":"...", "value": {<nested Any>...}}` JSON through the public `JsonStringToMessage`/`protobuf::json::JsonToBinaryStream` API can force unbounded C++ stack recursion (each level: `ParseAny` → `VisitObject` callback → `ParseUtf8`/`SkipValue` buffering the whole object → recursive `ParseMessage<Traits>` on a new `any_lex`), since each `Any` boundary gets its own full `kDefaultDepth` (100) budget, so the actual native recursion depth is `(#Any layers) × (up to 100 nested non-Any levels each)`, unbounded by attacker-chosen nesting count of Anys — leading to stack-overflow crash (DoS), which is a **memory-safety/undefined-behavior invariant violation** (not merely an "allowed interpretation difference"), analogous to the reachable `ABSL_CHECK(false) << "unreachable"` invariant in `JsonLexer::SkipValue()` at [3](#0-2)  that I flagged as a secondary candidate but could not prove reachable (I was unable to fully enumerate `PeekKind()`'s Kind values to confirm whether all lexer states are exhaustively handled by the switch, given the final-iteration cutoff).

### Title
Per-`Any`-layer reset of JSON recursion-depth budget allows unbounded native stack recursion via nested `google.protobuf.Any` in ProtoJSON parsing - (File: src/google/protobuf/json/internal/parser.cc)

### Summary
`ParseAny<Traits>` constructs a fresh `JsonLexer` (with a fresh copy of `ParseOptions::recursion_depth`, default 100) for each `Any` value it decodes, rather than propagating the *already-consumed* recursion budget from the enclosing lexer. Chaining `Any` messages inside `Any.value` fields therefore resets the nesting counter at every `Any` boundary while the real C++ call stack keeps growing, defeating the recursion-depth invariant meant to bound stack usage during ProtoJSON parsing of attacker-supplied input.

### Finding Description
`JsonLexer::Push()`/`Pop()` at [1](#0-0)  implement the sole recursion-depth invariant for JSON parsing: object/array nesting decrements a per-instance counter and refuses to recurse further once it hits zero. This design assumes the counter accurately reflects the true native stack depth for the whole document. `ParseAny` at [4](#0-3)  breaks that assumption: to reparse the buffered `Any` payload with its resolved dynamic type, it builds `JsonLexer any_lex(&in, lex.options(), ...)`, copying `lex.options()` by value. Since `options_.recursion_depth` in the *outer* lexer was only decremented for object/array nesting *inside* the outer `Any`'s JSON object (the `VisitObject`/`SkipValue` calls used to scan for `@type` do call `Push()`/`Pop()`, but they are balanced/undone by the time `ParseAny` finishes buffering), the copied `options()` handed to `any_lex` starts with a budget close to the original `kDefaultDepth` again. Recursively nesting `Any` inside `Any.value` (each carrying a nested message that is itself an `Any`) causes `ParseAny → ParseMessage<Traits> → ParseAny → ...` to recurse on the actual C++ call stack without the depth counter reflecting cumulative depth across `Any` boundaries.

### Impact Explanation
Attacker-controlled, boundedly small ProtoJSON payload (e.g., ~100 nested `Any` wrappers, or fewer if paired with a few levels of non-Any nesting per layer to exceed available stack per frame) can drive unbounded native recursion, causing a stack-overflow crash of the parsing process — a denial-of-service impacting any consuming application that calls `google::protobuf::json::JsonToBinaryStream`/`JsonStringToMessage` on data containing an `Any` field, directly analogous to the invariant-violation DoS in CVE-2019-20924 (an ordinary, schema-valid but structurally crafted request corrupts an internal safety invariant and crashes the process).

### Likelihood Explanation
Reaching this requires only: (1) a schema with at least one `google.protobuf.Any` field reachable from the top-level message (very common, e.g., anything using `Any` for extensibility), and (2) an attacker able to submit arbitrary ProtoJSON to that endpoint — matching the stated threat model of an ordinary client sending bounded input through the public parse API. No privileged access or malicious schema is required.

### Recommendation
Propagate the *remaining* recursion budget (not a fresh copy) across `Any` boundaries, e.g., by threading a single shared depth-tracking object/counter reference through `ParseAny`'s `any_lex` construction instead of copying `ParseOptions` by value, or by explicitly calling `Push()` on the outer lexer before constructing `any_lex` and holding it until the inner parse completes, so that the total real recursion depth (across all `Any` layers) is bounded by `kDefaultDepth`/`recursion_depth` regardless of how nesting is distributed between plain objects/arrays and `Any` reparses.

### Proof of Concept
Not executed — reproduction would require constructing a ProtoJSON document with a message containing an `Any` field whose `value` recursively contains another `Any`-typed message, nested to a depth sufficient to overflow the process stack (concretely: `{"@type":"type.googleapis.com/google.protobuf.Any","value":{"@type":"...","value": {...} } }` repeated N times), then calling `google::protobuf::util::JsonToBinaryStream` (or equivalent public API) on it and observing a crash rather than a graceful `INVALID_ARGUMENT`/"too deeply nested" error. I was not able to run this due to the tool-call budget for this session; this should be validated with an actual harness before treating it as confirmed.
