## Title
Credential helper trusts an attacker-supplied `WWW-Authenticate` header to classify a host as GitHub Enterprise without the HTTPS-verified check other paths require - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The bug-class in the report is: a code path takes a shortcut that skips a mandatory verification/adjustment step that all *other* code paths perform, letting attacker-influenced input flow through unchecked. In `PerpEngine::fill`, the "zero prepayment" branch skipped applying the referral discount that the other branch applied. The Desktop analog is in `getEndpointKind` in [1](#0-0)  where one branch classifies a remote endpoint as a trusted GitHub host purely from a `WWW-Authenticate` response header, bypassing the HTTPS-verified `isGitHubHost()` check that every other branch relies on.

### Finding Description
`getEndpointKind` decides, for a git credential request, whether the target endpoint is `'github.com'`, `'ghe.com'`, `'enterprise'`, or `'generic'`: [2](#0-1) 

Every legitimate classification path either matches a hardcoded hostname pattern (`isGist`, `isDotCom`, `isGHE`) or, for the fallback "maybe enterprise" case, requires an actual verified network round trip via `isGitHubHost(endpoint)` before returning `'enterprise'`. But the `wwwauth[...]` branch short-circuits this: if any credential field starting with `wwwauth[` contains the substring `realm="GitHub"`, the function immediately returns `'enterprise'` — with no HTTPS check, no call to `isGitHubHost`, and no verification of the response's authenticity. The comment even says this exists as a "happy-path" heuristic, but it is reachable with fully attacker-controlled data: the `WWW-Authenticate` header on an HTTP(S) response is set by whatever server (or MITM proxy) git is talking to.

This classification result feeds directly into `getCredential`: [3](#0-2) 

Once `endpointKind !== 'generic'`, and no existing account matches the endpoint, the code calls `ui.promptForGitHubSignIn(endpoint)` for an arbitrary attacker-chosen `endpoint` string, and whatever account results is merged into the outgoing git credential via `credWithAccount`. Subsequent lookups for that same origin go through `findGitHubTrampolineAccount`, which matches purely by URL origin: [4](#0-3) . So once a user completes a GitHub sign-in prompted for an attacker-controlled endpoint, Desktop will subsequently treat that endpoint as a "GitHub" endpoint eligible to receive the stored account's OAuth token on future `git fetch`/`push` operations to that same host — with the entire trust decision anchored on a self-reported HTTP response header, not on any cryptographic or first-party verification.

### Impact Explanation
An attacker who controls a git remote (or a proxy/MITM on the path to one) can respond to Desktop's credential request with a crafted `WWW-Authenticate: Basic realm="GitHub"` header. This causes Desktop to treat the remote as `'enterprise'` without the HTTPS-verified `isGitHubHost` check other classification paths enforce, and can lead the user through a GitHub sign-in prompt bound to the attacker's endpoint. Once that account/endpoint association is persisted, Desktop's credential helper will automatically supply the associated OAuth token to that same origin on future git operations (`findGitHubTrampolineAccount` matches by origin only), resulting in credential/token exfiltration to a host the user never intended to trust as a genuine GitHub Enterprise server. This matches the "credential/token exfiltration" and "attacker controls a git remote/proxy response" categories in the impact criteria.

### Likelihood Explanation
Exploitation requires the victim to add/use a remote pointing at (or being MITM'd/proxied to) the attacker's server and to complete a sign-in prompt that appears to be for a GitHub endpoint — this is a real but non-trivial user-interaction requirement, and the attacker needs control of the HTTP response for that remote (a plausible scenario for compromised proxies, self-hosted "GitHub-like" mirrors, or MITM on non-TLS transports). The other classification branches in the same function (`isGHE`, and the final `isGitHubHost` fallback) exist specifically because header/hostname claims alone are not trustworthy, underscoring that this branch is the one path where that safeguard was omitted.

### Recommendation
Remove or gate the `wwwauth[...]` "realm=GitHub" shortcut so it does not bypass the same HTTPS-verified `isGitHubHost()` check used by the fallback path; at minimum, treat a `realm="GitHub"` header as at most a hint that should still be confirmed via `isGitHubHost(endpoint)` (or an equivalent authenticated check) before classifying the endpoint as `'enterprise'` and before allowing any stored account/token to be associated with or sent to that origin.

### Proof of Concept
1. Configure a remote/proxy that answers git's HTTP authentication challenge with a header `WWW-Authenticate: Basic realm="GitHub"` for an arbitrary attacker-controlled host.
2. Trigger a `git fetch`/`push` in Desktop against that remote so the trampoline credential helper's `get` command runs; `getEndpointKind` reaches the `wwwauth[` branch at [5](#0-4)  and returns `'enterprise'` without ever calling `isGitHubHost`.
3. Because no account matches yet, `getCredential` calls `ui.promptForGitHubSignIn(endpoint)` for the attacker's endpoint; if the user completes it, the resulting account becomes associated with that origin.
4. On subsequent operations, `findGitHubTrampolineAccount` matches by origin alone and Desktop supplies the account's token to the attacker's server via `credWithAccount`.

Note: I was not able to inspect the full implementation of `isGitHubHost()` or `ui.promptForGitHubSignIn` within the indexed context, so the exact verification strength of the bypassed fallback path and the full UI flow of the sign-in prompt could not be fully confirmed from local code alone — a Devin session with full repo access would be needed to trace those definitively.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

export async function findGitHubTrampolineAccount(
  accountsStore: AccountsStore,
  remoteUrl: string
): Promise<Account | undefined> {
  const accounts = await accountsStore.getAll()
  const parsedUrl = new URL(remoteUrl)
  return accounts.find(
    a => new URL(getHTMLURL(a.endpoint)).origin === parsedUrl.origin
  )
}
