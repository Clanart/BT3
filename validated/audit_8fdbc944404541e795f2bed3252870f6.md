### Title
Missing bounds check in CLVM atom length-prefix parsing causes unhandled `IndexError` and mempool transaction-processing halt - ([File: chia/full_node/mempool_manager.py])

### Summary
`is_atom_canonical()` and its caller `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` parse the CLVM serialization length prefix of every atom in a submitted spend bundle's `puzzle_reveal` and `solution` without verifying that the computed prefix bytes (and the atom payload) actually fit inside the buffer. This mirrors the CVE-2019-14437 bug class in VLC's `xiph_SplitHeaders` (array bounds not checked before indexing a length-derived offset into a buffer), just realized in Python as an unguarded index access rather than raw memory access.

### Finding Description
`is_atom_canonical` reads the length-prefix byte at `offset` and, depending on its high bits, decides it needs 0–5 additional prefix bytes: [1](#0-0) 

The loop `for i in range(prefix_len): ... offset += 1; atom_len |= clvm_buffer[offset]` never checks that `offset` stays within `len(clvm_buffer)` before indexing. If the buffer ends exactly at (or before) the last prefix byte, `clvm_buffer[offset]` raises an unhandled `IndexError`.

The caller `is_clvm_canonical` drives this in a loop over the whole buffer and has the same class of issue: after computing `atom_len`, it does `offset += atom_len` without checking that `offset + atom_len <= len(clvm_buffer)` before the next iteration reads `clvm_buffer[offset]` again: [2](#0-1) 

This is reachable directly from an unprivileged spend-bundle submitter: `MempoolManager.validate_spend_bundle()` calls `is_clvm_canonical()` on the raw bytes of every `coin_spend.puzzle_reveal` and `coin_spend.solution` in the bundle, unconditionally, before any other CLVM-level validation of the buffer's internal consistency happens: [3](#0-2) 

Because a `puzzle_reveal`/`solution` blob is attacker-controlled CLVM serialization data, a submitter only needs to craft a trailing byte sequence whose high bits indicate a multi-byte length prefix (e.g. `0xF8`–`0xFB`) but omit the trailing length bytes (or arrange for `atom_len` to overshoot the remaining buffer), and the parse throws `IndexError` instead of returning a clean "not canonical" result.

Tracing the call chain, `validate_spend_bundle()` is invoked from `add_spend_bundle()` with no surrounding `try/except IndexError`: [4](#0-3) 

Unlike the `full_block_utils.py` parsers in the same repo (`skip_bytes`, `skip_list`, `generator_from_block`, `block_info_from_block`), which were explicitly hardened with `ValueError` bounds checks (`"byte length X exceeds remaining buffer Y"`, etc.): [5](#0-4) 
`is_atom_canonical`/`is_clvm_canonical` received no equivalent bounds validation, making them the outlier "unchecked array index" path analogous to the VLC `xiph_SplitHeaders` bug — the fix pattern that was already applied elsewhere in the codebase was not applied here.

### Impact Explanation
An `IndexError` raised deep inside `is_clvm_canonical()`/`is_atom_canonical()` is not caught anywhere along the `add_spend_bundle → validate_spend_bundle` path. If this exception propagates out of the coroutine handling transaction admission without a generic handler further up the stack, it can abort processing of that RPC/gossip call and, depending on how the calling task is supervised, disrupt the full node's spend-bundle admission pipeline for that request — a spend-triggered transaction-processing halt. This is a reachable, single-spend-bundle-triggerable crash path rather than a memory-corruption read (Python bounds-checks array indexing, so it cannot leak adjacent heap memory the way the original C VLC bug could), which caps the severity below the original CVE but keeps it in the Medium/High DoS category defined by the scan rules.

### Likelihood Explanation
High likelihood of reachability: this code executes on every spend bundle submitted to the mempool, with attacker-fully-controlled `puzzle_reveal`/`solution` bytes, and is invoked before any signature or full CLVM-cost validation gates it. Crafting a byte string ending in a truncated multi-byte atom-length prefix is trivial and deterministic.

### Recommendation
Add explicit bounds checks in `is_atom_canonical` before indexing `clvm_buffer[offset]` for each of the `prefix_len` bytes (verify `offset < len(clvm_buffer)` at each step, matching the pattern already used in `full_block_utils.py`'s `skip_bytes`/`skip_list`). Additionally, in `is_clvm_canonical`, verify `offset + atom_len <= len(clvm_buffer)` after computing `atom_len` before continuing the loop, and convert out-of-range conditions into a clean "not canonical"/rejection result (or a caught `ValidationError`/`Err.INVALID_COIN_SOLUTION`) rather than letting an `IndexError` escape uncaught.

### Proof of Concept
Construct a `CoinSpend` whose `solution` (or `puzzle_reveal`) program serialization ends with a byte such as `0xF8` (indicating a 4-byte length prefix per the `elif (b & 0b11111100) == 0b11111000` branch) but provide zero trailing bytes, e.g. append `b"\xf8"` as the final byte of the buffer. When `MempoolManager.validate_spend_bundle()` calls `is_clvm_canonical(bytes(coin_spend.solution))`, the parser reads the `0xF8` byte, computes `prefix_len = 4`, then attempts `offset += 1; atom_len |= clvm_buffer[offset]` on an offset beyond the buffer end, raising `IndexError` instead of returning `(length, False)`. Submit this spend bundle via the standard mempool add path (`add_spend_bundle`) to trigger the unhandled exception during admission processing.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

def skip_list(buf: memoryview, skip_item: Callable[[memoryview], memoryview]) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"list count prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"list count {n} exceeds remaining buffer {len(buf)}")
    for _ in range(n):
        buf = skip_item(buf)
    return buf


def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
