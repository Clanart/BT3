I found a strong, concrete analog. GitHub Desktop's clone implementation explicitly disables an upstream Git security protection for every clone it performs.

### Title
Git's clone-time protection against malicious submodule/hardlink attacks is explicitly disabled by Desktop - (File: app/src/lib/git/clone.ts)

### Summary
Desktop's `clone()` function unconditionally sets the environment variable `GIT_CLONE_PROTECTION_ACTIVE` to `'false'` on every invocation of `git clone --recursive`, for every repository the user clones through the app. [1](#0-0) 

### Finding Description
Upstream Git added the `GIT_CLONE_PROTECTION_ACTIVE` guard as part of the fix for the local-clone/submodule attack class (the family of issues around CVE-2024-32004 and related hardlink/symlink attacks during recursive clones of untrusted repositories). The protection is meant to prevent a maliciously crafted repository — one containing crafted submodule entries, symlinks pointing into `.git`, or hook files reachable via a local/embedded submodule path — from causing Git to hardlink or otherwise process attacker-controlled files from within `.git` during a `clone --recursive` operation, which can result in hook execution or file writes outside the intended clone destination.

By hardcoding `GIT_CLONE_PROTECTION_ACTIVE: 'false'` in `clone()`, Desktop actively turns this protection off instead of relying on Git's default-safe behavior, for every clone operation — including recursive submodule clones of repositories that are entirely attacker-controlled (any public repo URL, a forked repo, or a repo referenced by a submodule).

This is the same *class* of bug as the audit report: a defensive/consistency mechanism that the underlying system relies on (there: updating global liquidation accounting after closing a position; here: Git's clone-time hardlink/symlink protection) is bypassed by the calling code, which "closes the loop" without honoring the invariant the rest of the system depends on. In the original report, skipping the update let the protocol treat unliquidated/liquidated collateral as still available, silently breaking bookkeeping. Here, skipping the protection lets Desktop treat a malicious recursive-submodule clone as safe when Git itself would have refused/guarded the operation, silently reintroducing a known file-write/code-execution primitive against `.git` internals.

The other guard in the same file, `isClonePathSensitive()`, only checks the *destination* directory the user chose — it does nothing to constrain what a malicious *submodule* inside the cloned repository can do during the recursive clone, so it does not mitigate this. [2](#0-1) 

### Impact Explanation
The attacker fully controls the object here: a git remote/repository (including its `.gitmodules` file and nested submodules) is exactly the "attacker controls a cloned/fetched repository" primitive called out as valid. If Git's clone protection would have blocked/neutralized a crafted submodule/symlink layout, forcing `GIT_CLONE_PROTECTION_ACTIVE=false` removes that backstop for all Desktop users cloning any repository (including forks, or nested submodules pulled in transitively), which can lead to file writes outside the intended repository directory or code execution during the recursive clone — squarely matching the "file write or read outside the repo" / "code execution" impact categories.

### Likelihood Explanation
No local access, admin rights, prior malware, or unnatural user steps are required — the only action needed is the completely ordinary Desktop workflow of cloning (or recursively fetching submodules for) a repository that the attacker controls or has contributed a malicious submodule reference to. Because the disabling is unconditional and hardcoded (not behind any user-configurable safety switch), every clone via Desktop is affected.

### Recommendation
Remove the explicit override of `GIT_CLONE_PROTECTION_ACTIVE` and let Git use its own safe default (protection active) unless there is a narrowly scoped, well-justified reason to disable it for a specific trusted flow. If some legitimate Desktop flow truly required disabling it, that should be scoped as tightly as possible (e.g., only for local, already-trusted paths) rather than applied globally to every clone, and should be re-audited against the specific CVE(s) the flag was introduced to mitigate.

### Proof of Concept
1. Attacker publishes (or gets a victim to add as a submodule) a repository containing a `.gitmodules` entry and a crafted submodule directory designed to abuse the hardlink/symlink clone-protection bypass that `GIT_CLONE_PROTECTION_ACTIVE` was introduced to prevent.
2. Victim uses GitHub Desktop to clone the parent repository (Desktop always passes `--recursive`, per `app/src/lib/git/clone.ts:88-93`).
3. Because Desktop sets `GIT_CLONE_PROTECTION_ACTIVE: 'false'` in the clone environment (`app/src/lib/git/clone.ts:83`), Git does not apply the safety check it otherwise would, and the crafted submodule content is processed as if the protection were absent — enabling the underlying hardlink/symlink attack against `.git` internals that the flag exists to stop. /**
 * Check whether a resolved clone path targets a sensitive location that
 * should never be used as a clone destination. This is a backstop against
 * path traversal attacks where a crafted URL tricks the UI into deriving
 * a clone path outside the intended base directory.
 */
function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}

    '-c',
