### Title
Stale on-chain state used for gasless swap admission check enables lender (proposer) fund loss - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The `[H-02]` HyperLiquid bug is a "sanity check passes on stale data, but the irreversible downstream action can still fail/succeed inconsistently" pattern: a value-movement precondition is verified against data that is not updated per-transaction within a block, so multiple transactions can each pass the check even though only one can actually be honored. Kaia's gasless (KIP-247) module has a structurally similar pattern: `GaslessModule.GetCheckBalance()` validates a `GaslessSwapTx` using values fetched from the last **committed** chain state via `backends.NewBlockchainContractBackend(g.Chain, nil, nil)` (see `checkBalanceForSwap` in `kaiax/gasless/impl/tx_pool.go`), including the AMM router's `GetAmountIn` quote and the token `Allowance`/`BalanceOf`. This check does not reflect state changes made by other gasless bundles that will execute earlier within the *same* block being built, yet the block-building logic (`ExtractTxBundles` in `kaiax/gasless/impl/builder.go`) unconditionally prepends a `LendTx` that pays out KAIA gas fees to the swap sender *before* the `ApproveTx`/`SwapTx` are executed.

### Finding Description
`GaslessModule.checkBalanceForSwap` (`kaiax/gasless/impl/tx_pool.go`, lines ~107-182) is the sole admission/inclusion check used by `TxPool.validateTx` (`blockchain/tx_pool.go:918-932`, via `module.GetCheckBalance()`), replacing the ordinary sender-balance check for gasless transactions: [1](#0-0) 

This check reads live contract state (allowance, balance, router quote) through `backends.NewBlockchainContractBackend(g.Chain, nil, nil)`, which resolves calls against the blockchain's latest **canonical (committed)** state, not a state that reflects other gasless bundles already sequenced ahead of it in the block currently being assembled: [2](#0-1) 

Meanwhile, `GaslessModule.ExtractTxBundles` builds a bundle of `[LendTxGenerator, ApproveTx(optional), SwapTx]` for every ready gasless sender found in the same pending-tx set, independent of one another: [3](#0-2) 

`GetLendTxGenerator` unconditionally constructs and signs a `LendTx` that transfers `lendAmount(approveTxOrNil, swapTx)` KAIA from the block proposer to the swap sender, computed purely from the transactions' declared fees—independent of whether the subsequent `ApproveTx`/`SwapTx` will actually succeed on-chain: [4](#0-3) 

Because each bundle's admission-time `checkBalanceForSwap`/`checkBalanceForApprove` is evaluated independently against the same stale, pre-block canonical state (not the intermediate state after earlier bundles in the same block have executed), several bundles that individually appear valid at admission time can, when actually sequenced together in one block, have their `SwapTx` revert on-chain (e.g., AMM reserves shifted by an earlier swap in the same block causing `GetAmountIn`'s quoted `requiredAmountIn` to be stale, or a shared spender/allowance/balance state consumed by an earlier included transaction). The `LendTx` that already paid out KAIA to the sender, however, is a separate, already-valid, already-included transaction that is not automatically rolled back when the paired `SwapTx` reverts.

This is the same root-cause class as the reported bug: a security/solvency precondition ("the searcher/user can actually repay because the checked balance/rate is current") is validated against data that is not guaranteed to be current with respect to other transactions landing in the same block, and the actual value transfer (LendTx payout) is executed unconditionally before the compensating leg (SwapTx repayment) is confirmed to succeed with fresh state.

### Impact Explanation
If the `SwapTx` reverts after the `LendTx` has already paid out the lent gas amount to the sender, the block proposer/lender loses the lent KAIA with no repayment—this is direct value loss for the CN (proposer) analogous to the escrow's asset shortfall in the original report, and constitutes "gasless … settlement theft" as explicitly listed as an acceptable impact category. This can be repeated by any unprivileged sender submitting multiple gasless swap bundles engineered to race against each other's underlying AMM state within a single block, at no cost beyond normal transaction fees. Given repeated abuse potential and direct funds loss to CN, impact is assessed as **High**.

### Likelihood Explanation
Exploitation requires an attacker (or colluding senders) to submit multiple `GaslessApproveTx`/`GaslessSwapTx` bundles that reference the same swap pool/route such that execution of one shifts AMM state (or shared allowance/balance) enough to break the admission-time assumptions of a later one, all landing in the same block. This is achievable by any public RPC caller submitting ordinary transactions and does not require special privileges, consensus position, or node compromise—only timing/ordering within block construction, which is influenceable by transaction submission timing and gas price. Likelihood is assessed as **Medium**, since it depends on specific market/pool conditions (thin liquidity, multiple simultaneous gasless swaps on the same pool) to reliably trigger, but the precondition (stale-state check + unconditional pre-payment) is present unconditionally in the code.

### Recommendation
- Re-validate `checkBalanceForSwap`/`checkBalanceForApprove` against the state that reflects previously-included bundles within the block currently being assembled (e.g., simulate against the intermediate `state.StateDB` used during block building), not merely the latest committed block.
- Make `LendTx` payout conditional on (or atomically bundled with, with automatic rollback/refund) the success of the paired `ApproveTx`/`SwapTx`—e.g., verify actual repayment occurred before finalizing the bundle in the block, or design the bundle so a failing `SwapTx` also reverts/excludes the `LendTx`.
- Add worker/builder-level re-simulation of the whole bundle (not just the mempool admission-time check) immediately before inclusion, so that inter-bundle state dependencies (e.g., shared AMM reserves) are accounted for.

### Proof of Concept
Conceptual scenario (exact reproduction requires a background Devin session to run the code and confirm the revert behavior end-to-end):
1. A liquidity pool token `T` has thin reserves such that `GaslessSwapRouter.GetAmountIn(T, minAmountOut)` at the current committed block returns `X`.
2. Sender A submits `ApproveTxA`/`SwapTxA` with `amountIn = X`, satisfying `checkBalanceForSwap` (uses the same committed-state quote).
3. Sender B, in the same tx-pool snapshot, submits `ApproveTxB`/`SwapTxB` also with `amountIn = X` against the same pool, and also passes `checkBalanceForSwap` because the check is evaluated independently against the same stale committed state (not accounting for A's swap).
4. `ExtractTxBundles` (`kaiax/gasless/impl/builder.go:28-72`) produces two independent bundles `[LendTxA, ApproveTxA, SwapTxA]` and `[LendTxB, ApproveTxB, SwapTxB]`, both included in the same block.
5. During block execution, `SwapTxA` executes first, shifting the pool's reserves so that the actual required `amountIn` for B's desired `minAmountOut` is now greater than `X`. `SwapTxB` reverts on-chain (slippage/insufficient output), but `LendTxB` (a standalone, valid KAIA transfer to sender B) has already executed successfully and irreversibly, since bundle transactions are not atomic against each other at the ledger level.
6. The CN/proposer has paid out `lendAmount(ApproveTxB, SwapTxB)` in KAIA to sender B with no compensating repayment, resulting in a direct loss to the lender.

Note: I was not able to fully confirm within the available tooling whether `work/builder` enforces atomicity across a bundle's constituent transactions (i.e., whether a reverted `SwapTx` would cause the block builder to drop the whole bundle including the already-broadcast `LendTx`). This is an important detail to verify with the actual code/tests (`work/builder/builder.go`, `work/builder/bundle.go`) before treating this as fully confirmed; a Devin session with build/test tooling would be needed to trace `IncorporateBundleTx`/bundle conflict-checking logic and any revert-then-exclude behavior at block-assembly time.

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}

// MakeLendTx creates a transaction with following properties:
// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)
// L2. LendTx.from = proposer
// L3. LendTx.to = SwapTx.from
// L4. LendTx.value = LendAmount(approveTxOrNil, swapTx)
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}
