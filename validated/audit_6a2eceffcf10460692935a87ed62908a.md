### Title
Conflict-marker parsing in `extractConflictHunks` can be desynchronized by attacker-controlled content, causing Copilot to resolve (and silently write) the wrong hunk boundaries - (File: `app/src/lib/copilot-conflict-context.ts`)

### Summary
The report's underlying bug class is an **invariant that assumes a simple, attacker-immune state boundary** (`totalSupply == 0` after burn) but which can be desynchronized by attacker-controlled input arriving between the check and its consumption, corrupting the outcome for a legitimate actor. The closest verified analog in this codebase is in the Copilot merge-conflict resolution pipeline: `extractConflictHunks` splits a conflicted file into ours/base/theirs regions using **bare regex marker matching** with no validation that the markers are actually well-formed/paired, so a crafted "theirs" or "ours" branch that itself contains marker-like text will desynchronize the parser's hunk boundaries, and that corrupted boundary is what gets sent to, and written back from, the AI resolution flow.

### Finding Description
`extractConflictHunks` in [1](#0-0)  walks a conflicted file top-to-bottom using four regexes: [2](#0-1) 

These match on `^<{7}`, `^\|{7}`, `^={7}`, `^>{7}` — i.e. any line that merely starts with seven of those characters, anywhere in the file, is treated as a structural conflict boundary. There is no verification that a `<<<<<<<` found is actually paired with a subsequent `=======`/`>>>>>>>` that belongs to the same hunk, and no check that the "ours"/"theirs" content collected between the assumed boundaries doesn't itself contain nested marker-like lines from legitimate file content (e.g. a documentation file explaining git conflict resolution, a fixture/test file containing sample conflict markers, a minified diff embedded as a string literal, or ASCII-art banners).

Because the "theirs" side of a real merge conflict is fully attacker-controlled (it is whatever content exists on the branch/PR/fetched ref the user merges), an attacker can craft a file where the genuine conflict region contains an embedded line that incidentally matches `separatorMarker`/`oursMarker`/`theirsMarker`. This causes the linear scanner to terminate `oursLines`/`theirsLines` collection early at the wrong line (lines 202–237), silently truncating or misattributing content into the wrong hunk before context extraction and skip-reason gating are even applied. This is the exact analog of the report's broken invariant: the guard (`require(cache.totalSupply == 0 || > 1e5)`) assumed a benign state transition, but an attacker-controlled intervening event (a 1-wei deposit) violated that assumption and broke correctness for the legitimate transaction. Here, the guard (marker regex used as ground truth for hunk boundaries) assumes conflict markers are always structurally genuine, but attacker-controlled branch content can inject look-alike markers that break the parser's positional assumptions.

The result: `buildConflictContext` ( [3](#0-2) ) sends the model an ours/theirs split that does not correspond to the real hunk, and the size/length gating in `getHunkSkipReason` ( [4](#0-3)  ) operates on this already-corrupted split rather than the true conflict content, so it cannot catch the desync.

### Impact Explanation
If the AI-generated resolution is written back to disk and staged using the corrupted hunk boundaries (the write path is `app/src/lib/stores/app-store.ts:7233-7259`, which does `writeFile(absolutePath, resolution.resolvedContent, 'utf8')` followed by `git add`), the user's on-disk file can end up containing content that does not match either side of the real merge, or can silently drop legitimate changes from "ours" or "theirs" without any error being surfaced — the pipeline has no indication the parser desynchronized. This satisfies the "silent corruption of what the user commits or pushes" impact category: the user reviews and accepts an AI resolution believing it correctly reflects both sides of the conflict, but the underlying hunk extraction was already wrong due to attacker-crafted content in the merged branch.

### Likelihood Explanation
Medium. It requires the victim to merge/rebase against a branch or PR containing attacker-controlled file content (a routine, expected Desktop action — "attacker controls a... fetched repository" per the valid-impact criteria) and for that content to contain a line matching a 7-character marker pattern followed by whitespace or end-of-line, inside the real conflict region. This is a plausible, low-effort crafting task (e.g., a documentation file about merge conflicts, or a test fixture with embedded `=======`-style separators) and does not require any local access, malware, or social engineering beyond a normal merge/PR review flow that Desktop already supports via Copilot conflict resolution.

### Recommendation
- Validate that each collected hunk's marker triad (`<<<<<<<`, optional `|||||||`, `=======`, `>>>>>>>`) is well-formed and that no marker-like line appears in content collected as `oursLines`/`baseLines`/`theirsLines`; treat any embedded marker-like line inside a hunk body as ambiguous and skip the whole file with a `skippedReason` instead of guessing.
- Cross-check the parsed hunk count/boundaries against `git status`/`git diff --check` or a stricter git-native conflict-marker parser before sending content to the model.
- After reassembly, diff the final written file against the original conflict markers removed to assert no unexpected leftover marker lines or unintended content changes before staging with `git add`.

### Proof of Concept
1. Attacker opens a PR/branch whose file `notes.md` intentionally conflicts with the victim's local changes to the same file.
2. Inside the "theirs" content of that real conflict, the attacker includes a benign-looking documentation line that starts with seven `=` characters (e.g., `=======` used as a Markdown-style divider) instead of only inside the true separator.
3. Victim opens Desktop, hits the conflict, and uses "Resolve with Copilot."
4. `extractConflictHunks` (`app/src/lib/copilot-conflict-context.ts:179-279`) reaches the embedded `=======`-look-alike line first and treats it as the hunk separator, truncating `theirsLines` early and misclassifying the remainder of the attacker's real content as unrelated trailing text.
5. The model is shown a shortened/incorrect "theirs" section, generates a resolution based on that incomplete view, and the resolution is written verbatim via `writeFile` in `app-store.ts:7258` and staged with `git add` — the victim commits content that silently differs from what a correct hunk-boundary parse would have produced, with no warning surfaced anywhere in the flow.

*Note: I was not able to fully inspect `app/src/lib/copilot-conflict-resolution.ts`, which performs the actual splicing of the model's per-hunk resolution back into `rawContent`, due to iteration limits. Confirming exactly how resolved content is spliced back (and whether it re-derives hunk boundaries the same way, compounding the desync) would strengthen this finding and should be verified by reading that file directly.*

export function extractConflictHunks(
  fileContent: string,
  contextLines: number = 3
): ReadonlyArray<IConflictHunk> {
  const lines = fileContent.split(/\r?\n/)
  const hunks: Array<IConflictHunk> = []

  let i = 0
  while (i < lines.length) {
    if (!oursMarker.test(lines[i])) {
      i++
      continue
    }

    const oursStart = i + 1
    const oursLines: Array<string> = []
    const baseLines: Array<string> = []
    let hasBase = false
    const theirsLines: Array<string> = []
    let hunkEnd = -1

    i = oursStart
    // Collect ours content
    while (i < lines.length) {
      if (baseMarker.test(lines[i])) {
        hasBase = true
        i++
        break
      }
      if (separatorMarker.test(lines[i])) {
        i++
        break
      }
      oursLines.push(lines[i])
      i++
    }

    // If diff3, collect base content until separator
    if (hasBase) {
      while (i < lines.length) {
        if (separatorMarker.test(lines[i])) {
          i++
          break
        }
        baseLines.push(lines[i])
        i++
      }
    }

    // Collect theirs content until closing marker
    while (i < lines.length) {
      if (theirsMarker.test(lines[i])) {
        hunkEnd = i
        i++
        break
      }
      theirsLines.push(lines[i])
      i++
    }

    // If we never found the closing marker, skip this malformed hunk
    if (hunkEnd === -1) {
      continue
    }

    // The ours marker line is at oursStart - 1
    const markerStart = oursStart - 1
    const contextStart = Math.max(0, markerStart - contextLines)
    const contextEnd = Math.min(lines.length - 1, hunkEnd + contextLines)

    // Clamp context to not include conflict markers from adjacent hunks
    const contextBeforeLines: Array<string> = []
    for (let j = markerStart - 1; j >= contextStart; j--) {
      if (isConflictMarker(lines[j])) {
        break
      }
      contextBeforeLines.unshift(lines[j])
    }

    const contextAfterLines: Array<string> = []
    for (let j = hunkEnd + 1; j <= contextEnd; j++) {
      if (isConflictMarker(lines[j])) {
        break
      }
      contextAfterLines.push(lines[j])
    }

    const contextBefore = contextBeforeLines.join('\n')
    const contextAfter = contextAfterLines.join('\n')

    hunks.push({
      oursContent: oursLines.join('\n'),
      theirsContent: theirsLines.join('\n'),
      baseContent: hasBase ? baseLines.join('\n') : null,
      contextBefore,
      contextAfter,
    })
  }

  return hunks
}

export function getHunkSkipReason(
  hunks: ReadonlyArray<IConflictHunk>
): string | null {
  let totalContent = 0

  for (const hunk of hunks) {
    const sides = [hunk.oursContent, hunk.theirsContent, hunk.baseContent ?? '']
    for (const side of sides) {
      totalContent += side.length
      for (const line of side.split('\n')) {
        if (line.length > MAX_CONFLICT_LINE_LENGTH) {
          return 'Conflict contains lines too long to resolve automatically'
        }
      }
    }
    if (totalContent > MAX_CONFLICT_CONTENT_SIZE) {
      return 'Conflict region too large to resolve automatically'
    }
  }

  return null
}

export async function buildConflictContext(
  ourLabel: string,
  theirLabel: string,
  workingDirectory: string,
  files: ReadonlyArray<{
    readonly path: string
    /** Which side deleted the file (for delete-vs-modify conflicts). */
    readonly deletedSide?: 'ours' | 'theirs'
  }>
): Promise<ICopilotConflictContext> {
  const results = await Promise.all(
    files.map(async (file): Promise<IFileConflictContext> => {
      // Delete-vs-modify conflicts have no text markers on disk. Include
      // them in the context with metadata so the model can recommend
      // keep or delete — no file content is needed.
      if (file.deletedSide !== undefined) {
        return {
          path: file.path,
          hunks: [],
          deleteConflict: { deletedSide: file.deletedSide },
        }
      }

      // Guard against path traversal and symlink escapes (cross-platform)
      let absolutePath: string | null
      try {
        absolutePath = await resolveWithin(workingDirectory, file.path)
      } catch {
        return {
          path: file.path,
          hunks: [],
          skippedReason: 'File path could not be resolved safely',
        }
      }
      if (absolutePath === null) {
        return {
          path: file.path,
          hunks: [],
          skippedReason: 'File path is outside the repository',
        }
      }

      // Guard against reading pathologically large files into memory. This is
      // a memory-safety bound only — resolvability is decided from the conflict
      // hunks below, not the whole-file size.
      try {
        const fileStat = await stat(absolutePath)
        if (fileStat.size > MAX_CONFLICT_FILE_READ_SIZE) {
          return {
            path: file.path,
            hunks: [],
            skippedReason: 'File too large to resolve automatically',
          }
        }
      } catch {
        return {
          path: file.path,
          hunks: [],
          skippedReason: 'File could not be read',
        }
      }

      let content: string
      try {
        content = await readFile(absolutePath, 'utf8')
      } catch {
        return {
          path: file.path,
          hunks: [],
          skippedReason: 'File could not be read',
        }
      }

      const hunks = extractConflictHunks(content)
      if (hunks.length === 0) {
        return {
          path: file.path,
          hunks: [],
          skippedReason: 'No conflict markers found',
        }
      }

      // Gate on the size of the conflict content we'd actually send to the
      // model, not the whole-file size.
      const hunkSkipReason = getHunkSkipReason(hunks)
      if (hunkSkipReason !== null) {
        return {
          path: file.path,
          hunks: [],
          skippedReason: hunkSkipReason,
        }
      }

      return { path: file.path, hunks, rawContent: content }
    })
  )

  return {
    ourLabel,
    theirLabel,
    files: results,
  }
}
