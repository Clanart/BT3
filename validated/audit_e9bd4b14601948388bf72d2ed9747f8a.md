### Title
Dust-denom griefing of unassociated addresses forces costly `SpendableCoins` balance migration and OCC parallel-execution fallback on every EVM transaction touching the victim - (File: `x/evm/ante/preprocess.go`, `utils/helpers/associate.go`)

### Summary
Any account can create an unlimited number of tokenfactory denoms at negligible cost (the denom-creation fee param was removed) and use them to dust an unassociated EVM cast address (or any Sei address the attacker doesn't control) with tiny balances of hundreds of distinct denoms. `EVMPreprocessDecorator.AnteHandle` unconditionally calls `AssociationHelper.AssociateAddresses` → `MigrateBalance`, which pulls the account's **entire** `SpendableCoins` set (all denoms) and moves them in a single `SendCoins` call, every time an unassociated address is touched by an EVM transaction. Sei's OCC/giga parallel executor additionally treats "cast address holds multiple denominations" as an abort condition and falls back to slow sequential (`v2`) execution for the whole block. An attacker can therefore force any transaction that first touches a griefed address to (a) pay for iterating/moving an attacker-chosen number of dust coin entries and (b) push the containing block out of the optimistic parallel path into sequential fallback, without the victim being able to avoid it.

### Finding Description
- Tokenfactory denom creation has no minimum fee: migration `Migrate2to3` explicitly removed the "denom creation fee whitelist" and reset params, and current `CreateDenom`/`createDenomAfterValidation` in `x/tokenfactory/keeper/createdenom.go` performs no minimum-balance/fee check [1](#0-0) , [2](#0-1) .
- Every unassociated EVM sender is force-migrated on the ante path: `EVMPreprocessDecorator.AnteHandle` calls `associateHelper.AssociateAddresses` for any sender that is not yet associated [3](#0-2) .
- `AssociateAddresses`/`MigrateBalance` reads the account's full `SpendableCoins` (i.e., every denom balance on the account) and sends them all in one `SendCoins` call, with no cap on the number of denoms [4](#0-3) .
- The parallel OCC executor ("giga") explicitly detects this exact scenario — an unassociated cast address holding multiple denominations — and aborts, falling back to the slower sequential `v2` execution path for correctness, as documented and tested in `TestGigaVsGeth_BalanceMigrationMultipleDenoms` [5](#0-4) .

Because denom creation is free/cheap and there is no limit on how many denoms can be dusted into a target address, an attacker can pre-seed an arbitrary number of near-zero-value tokenfactory denoms onto a cast address before its owner ever submits an EVM transaction (or onto any address the attacker anticipates will be used). The first EVM transaction from that address will unconditionally trigger `MigrateBalance` over all of them, and the containing block is forced onto the sequential execution path in giga.

### Impact Explanation
This is the direct sei-chain analog of the reported bug class: absence of a minimum-value/whitelist threshold lets an attacker cheaply create many "dust positions" (tokenfactory denoms with dust balances) that another party — here, any unassociated address's owner, and by extension the block containing their transaction — is forced to process/clean up in full, at a cost the attacker chose but the victim pays. Concretely:
- The victim's own EVM transaction incurs extra iteration/gas cost for a `SendCoins` covering N attacker-chosen denoms, even though the victim never solicited or wants those tokens.
- Blocks containing such a transaction lose the performance benefit of OCC parallel execution and are forced onto the slower sequential fallback path, which is an accepted impact category (degradation of the OCC parallel execution/store layering path) and, if repeated across many addresses/blocks by an attacker, can push block processing time upward, directly bearing on the block-time SLA.

### Likelihood Explanation
Likelihood is high: creating tokenfactory denoms and sending 1 unit of each to a target address is a fully unprivileged, cheap, and repeatable operation (only ordinary gas/fees are required, since the create-denom fee/whitelist was removed). No special permissions, precompile access, or validator cooperation are needed; the attacker only needs to know or predict the cast address of a soon-to-be-used EVM account (which is deterministic — direct byte-cast of the EVM address) and pre-fund it with many denoms before the owner's first EVM transaction.

### Recommendation
- Reintroduce a minimum-fee or bounded-supply requirement for `x/tokenfactory` denom creation to raise the cost of mass denom spam.
- Cap the number of distinct denoms considered/migrated per `MigrateBalance`/`AssociateAddresses` call (e.g., migrate only denoms above a dust threshold, or split migration across multiple transactions/blocks), and correspondingly bound gas charged proportional to the number of denoms actually moved.
- Reconsider the giga abort heuristic so that an attacker cannot cheaply force sequential fallback merely by dusting many denoms onto an address; e.g., detect and skip/ignore dust-value denoms below a floor when deciding whether multi-denom migration requires an abort.

### Proof of Concept
1. Attacker calls `MsgCreateDenom` (via `x/tokenfactory`) repeatedly to create N distinct denoms cheaply, since no minimum fee/whitelist currently applies [2](#0-1) .
2. Attacker mints 1 unit of each denom and sends it to `castAddr = sdk.AccAddress(victimEvmAddr[:])`, the deterministic cast address of a victim's not-yet-associated EVM account.
3. When the victim later submits any EVM transaction, `EVMPreprocessDecorator.AnteHandle` triggers `AssociateAddresses` → `MigrateBalance`, which must gather and move all N dust denoms in a single `SendCoins` call [3](#0-2) [6](#0-5) .
4. If the block is processed under giga/OCC, the executor detects the multi-denom cast address and aborts, falling back to full sequential execution for the block, exactly as exercised by `TestGigaVsGeth_BalanceMigrationMultipleDenoms` [7](#0-6) .

func (m Migrator) Migrate2to3(ctx sdk.Context) error {
	// Reset params after removing the denom creation fee param
	defaultParams := types.Params{}
	m.keeper.paramSpace.SetParamSet(ctx, &defaultParams)

	// We remove the denom creation fee whitelist in this migration
	store := ctx.KVStore(m.keeper.storeKey)
	oldCreateDenomFeeWhitelistKey := "createdenomfeewhitelist"

	oldCreateDenomFeeWhitelistPrefix := []byte(strings.Join([]string{oldCreateDenomFeeWhitelistKey, ""}, KeySeparator))
	iter := sdk.KVStorePrefixIterator(store, oldCreateDenomFeeWhitelistPrefix)
	defer func() { _ = iter.Close() }()
	for ; iter.Valid(); iter.Next() {
		store.Delete(iter.Key())
	}
	return nil

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil

// TestGigaVsGeth_BalanceMigrationMultipleDenoms verifies that when giga encounters an
// unassociated address holding multiple token denominations, it correctly aborts and
// falls back to v2, which performs the full balance migration. The results must match
// a pure v2 execution for consensus parity.
func TestGigaVsGeth_BalanceMigrationMultipleDenoms(t *testing.T) {
	blockTime := time.Now()
	accts := utils.NewTestAccounts(5)

	signer := utils.NewSigner()
	recipient := utils.NewSigner()

	// The cast address is the EVM address bytes interpreted as a Cosmos address.
	// Before association, funds sent to this "address" need to be migrated.
	castAddr := sdk.AccAddress(signer.EvmAddress[:])

	// Fund the cast address with MULTIPLE denominations — this is the key scenario.
	// Balance migration must move all denoms, not just usei.
	multiDenomCoins := sdk.NewCoins(
		sdk.NewCoin("usei", sdk.NewInt(1000000000000000000)), // 1e18 usei (enough for gas + transfer)
		sdk.NewCoin("uusdc", sdk.NewInt(500000000)),          // 500 uusdc
	)

	// --- V2 baseline (handles migration natively) ---
	v2Ctx := NewGigaTestContext(t, accts, blockTime, 1, ModeV2Sequential)
	err := v2Ctx.TestApp.BankKeeper.MintCoins(v2Ctx.Ctx, "mint", multiDenomCoins)
	require.NoError(t, err)
	err = v2Ctx.TestApp.BankKeeper.SendCoinsFromModuleToAccount(v2Ctx.Ctx, "mint", castAddr, multiDenomCoins)
	require.NoError(t, err)
	// DO NOT associate — this forces the preprocess ante handler to migrate balances

	v2Tx := createUnassociatedEVMTx(t, v2Ctx, signer, recipient.EvmAddress, big.NewInt(1000), 0)
	_, v2Results, v2Err := RunBlock(t, v2Ctx, [][]byte{v2Tx})
	require.NoError(t, v2Err)
	require.Len(t, v2Results, 1)

	// --- Giga Sequential (should abort and fall back to v2) ---
	gigaCtx := NewGigaTestContext(t, accts, blockTime, 1, ModeGigaSequential)
	err = gigaCtx.TestApp.BankKeeper.MintCoins(gigaCtx.Ctx, "mint", multiDenomCoins)
	require.NoError(t, err)
	err = gigaCtx.TestApp.BankKeeper.SendCoinsFromModuleToAccount(gigaCtx.Ctx, "mint", castAddr, multiDenomCoins)
	require.NoError(t, err)
	// DO NOT associate — giga should detect this and abort

	gigaTx := createUnassociatedEVMTx(t, gigaCtx, signer, recipient.EvmAddress, big.NewInt(1000), 0)
	_, gigaResults, gigaErr := RunBlock(t, gigaCtx, [][]byte{gigaTx})
	require.NoError(t, gigaErr)
	require.Len(t, gigaResults, 1)

	// Both should succeed — giga fell back to v2 which handled migration
	require.Equal(t, uint32(0), v2Results[0].Code, "V2 tx should succeed: %s", v2Results[0].Log)
	require.Equal(t, uint32(0), gigaResults[0].Code, "Giga tx should succeed (via v2 fallback): %s", gigaResults[0].Log)
