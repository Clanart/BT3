## Analog Found

### Title
Out-of-bounds/unhandled-exception read while parsing an untrusted CLVM atom length prefix in mempool canonical-form checking - (File: chia/full_node/mempool_manager.py)

### Summary
The CVE describes an out-of-bounds read in `libarchive`'s `lha_read_file_header_1()` caused by trusting an attacker-controlled header/length field while parsing untrusted archive data without validating that the declared length stays within the buffer. The same bug class — reading a multi-byte length-prefix field from untrusted input without checking that the read offset stays inside the buffer bounds — exists in `is_atom_canonical()` in `chia/full_node/mempool_manager.py`.

### Finding Description
`is_atom_canonical()` decodes a CLVM atom's length prefix directly from attacker-supplied bytes: [1](#0-0) 

The function reads `clvm_buffer[offset]` and, depending on the top bits of the first byte, determines `prefix_len` (0–5 additional bytes to consume). It then loops `prefix_len` times, each time incrementing `offset` and indexing `clvm_buffer[offset]` — **without ever checking that `offset` is still within `len(clvm_buffer)`**:

```python
atom_len = b & mask
for i in range(prefix_len):
    atom_len <<= 8
    offset += 1
    atom_len |= clvm_buffer[offset]
```

Its caller, `is_clvm_canonical()`, likewise advances `offset` through the buffer based on decoded atom lengths and only asserts `clvm_buffer != b""` up front — it never validates that `offset` remains a valid index before dereferencing `clvm_buffer[offset]`: [2](#0-1) 

If a crafted buffer ends with a truncated multi-byte atom-length header (e.g., the last byte declares a 5-byte length prefix but fewer than 5 bytes remain), the loop indexes past the end of `clvm_buffer`. In Python this raises an unhandled `IndexError` rather than silently reading adjacent memory, but the root cause is identical to the CVE: a length-prefixed parser trusts the untrusted header value to determine how many further bytes to read, instead of first validating it against the remaining buffer length. This mirrors the class of defect already fixed elsewhere in the codebase — e.g. `full_block_utils.py`'s `skip_bytes()`/`skip_list()` explicitly check `n > len(buf)` before consuming, and `chia/util/streamable.py`'s `parse_bytes()` reads exactly the declared size and asserts the read matched — showing the project is aware this pattern requires bounds checks, but `is_atom_canonical`/`is_clvm_canonical` were not written defensively: [3](#0-2) [4](#0-3) 

### Impact Explanation
An unhandled `IndexError` raised deep inside mempool processing of a submitted spend bundle's CLVM data would propagate as an unexpected exception rather than a well-formed `ValidationError`/`Err` result. Depending on where in the call chain this exception surfaces (it is exercised directly in the test suite alongside other mempool-manager helpers, see `chia/_tests/core/mempool/test_mempool_manager.py`), it can crash or abort in-flight transaction processing instead of cleanly rejecting the malformed bundle, which is a spend-triggered transaction-processing halt/DoS condition consistent with the “Validate” criteria for this scan (a crash triggered by a malicious but otherwise syntactically-plausible submitted spend bundle).

### Likelihood Explanation
The buffer these functions operate on originates from serialized CLVM data (puzzle reveal/solution bytes) inside a spend bundle, which is fully attacker-controlled content submitted by any unprivileged wallet/RPC caller via `push_tx`/`add_transaction`. Constructing a buffer whose final atom declares a multi-byte length prefix but is truncated right at the buffer boundary is trivial and requires no cryptographic material or elevated privilege.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before dereferencing `clvm_buffer[offset]` in the prefix-length loop (mirroring the `n > len(buf)` checks used in `full_block_utils.py`), and add a bounds check in `is_clvm_canonical()`'s main loop before reading `clvm_buffer[offset]`, raising a controlled `ValidationError`/returning `False` rather than allowing an `IndexError` to propagate.

### Proof of Concept
Construct a CLVM buffer whose last atom-header byte declares the 5-byte-extension length prefix (`0b11111100` pattern, i.e. `0xFC`) but supply fewer than 5 trailing bytes, e.g.:
```python
buf = b"\xfc"  # declares 5 additional length bytes but buffer ends here
is_clvm_canonical(buf)  # raises IndexError instead of returning False/raising ValidationError
```
Embedding such a buffer as (part of) a coin spend's `puzzle_reveal`/`solution` in a submitted `SpendBundle` and driving it through the code path that invokes `is_clvm_canonical()`/`is_atom_canonical()` during mempool processing triggers the unhandled exception.

**Note on verification limits:** within the available search iterations I confirmed the vulnerable parsing logic and its lack of bounds checks in `chia/full_node/mempool_manager.py` (lines 144–227), and confirmed these functions are exercised directly by `chia/_tests/core/mempool/test_mempool_manager.py`, but I was not able to pinpoint the exact call site(s) that invoke `is_clvm_canonical()`/`is_atom_canonical()` from within `MempoolManager`'s spend-bundle processing pipeline (e.g., fast-forward/dedup eligibility checks) before running out of iterations. A Devin session with full-file access would be needed to trace that call site precisely and confirm the exact reachable trigger path.

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

```python
def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

```python
def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
```
