### Title
Bribe reward sniping via front-run vote()/unvote() around castVotes() harvest - ([File: wombat/WombatBribeManager.sol], [File: rewards/BribeRewardPool.sol], [File: rewards/BaseRewardPoolV2.sol])

### Summary
An unprivileged vlMGP holder can front-run a scheduled `castVotes(bool)` call by shifting votes into a pool whose `IWombatBribe` balance already has a large unharvested bribe, letting `castVotes` harvest that bribe and distribute it pro-rata to the pool's *current* vote share, then immediately `unvote()` to claim a share of rewards that accrued mostly before the attacker ever voted. This dilutes the fair, time-weighted entitlement of the pool's genuine long-term voters.

### Finding Description
`WombatBribeManager.vote()` lets any vlMGP holder shift `pool.totalVoteInVlmgp` and calls `IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, delta)` [1](#0-0) . `BribeRewardPool.stakeFor` only snapshots `userRewardPerTokenPaid` under the `updateRewards` modifier and then increases `totalSupply`/`_balances[_for]` [2](#0-1)  — there is no cooldown, minimum holding period, or time-weighting.

When `castVotes(bool)` is later called by anyone, it recomputes target votes per pool from `pool.totalVoteInVlmgp` (now inflated by the attacker's front-run) and calls `wombatStaking.vote(...)`, which harvests Wombat bribes and ultimately calls `BribeRewardPool.queueNewRewards` → `_provisionReward`, which increases `rewardPerTokenStored` by `amountReward * 10**decimals / totalStaked()` [3](#0-2) . Because `totalStaked()` here is `totalSupply` at the moment of harvest — i.e., includes the attacker's just-added vote — the entire newly harvested bribe (which accrued over the *whole* prior period, mostly while the attacker held no votes in this pool) is split pro-rata among whoever holds votes at that instant, including the attacker.

The attacker then calls `unvote()`, which calls `withdrawFor(_for, currentVote, true)`, immediately claiming the reward via `_getReward` [4](#0-3) [5](#0-4) . No modifier, reentrancy guard, or accounting mechanism ties a user's reward entitlement to the duration they actually held votes for that specific pool — `rewardPerToken` is a single global accumulator updated in lump sum at harvest time, not time-weighted.

### Impact Explanation
This is theft of unclaimed yield: the attacker extracts a share of a bribe payment proportional to their vote weight at the moment of harvest, despite having held that vote weight for a negligible fraction of the accrual period. This directly reduces the payout that genuine long-term voters for that pool would otherwise receive, matching the Immunefi "theft of unclaimed yield" impact class.

### Likelihood Explanation
Feasibility requires the attacker to already hold locked vlMGP (a precondition explicitly given), and to observe a pool with a large pending/unharvested `IWombatBribe` balance (visible via `previewBribes`/on-chain state) and an upcoming `castVotes` call. The sequence `vote()` → (anyone calls) `castVotes()` → `unvote()` requires no special privileges, no flash loan of principal is required for the exploit mechanics themselves (only pre-existing locked vlMGP), and is repeatable every time a pool accumulates an unharvested bribe before the next `castVotes`. The only friction is timing the front-run relative to `castVotes`, which is realistically achievable via mempool monitoring since `castVotes` is a public function callable by anyone.

### Recommendation
Introduce a minimum holding/lock period between `vote()` and `unvote()` for a given pool (e.g., require votes to remain until at least one `castVotes` cycle has elapsed since the vote was cast), or switch to time-weighted reward accrual (e.g., checkpoint-based streaming rather than lump-sum `rewardPerTokenStored` updates at harvest), or restrict `unvote()` for a cooldown window after `castVotes` harvests a reward the user's vote contributed to diluting.

### Proof of Concept
Hardhat fork test plan:
1. Deploy/fork the Magpie + Wombat staking stack; have Voter A lock vlMGP and vote a large amount into Pool X well before any harvest, letting a bribe accrue in `IWombatBribe` for Pool X over multiple days without calling `castVotes`.
2. Confirm via `previewBribes`/bribe contract state that Pool X has a large unharvested bribe balance.
3. Have Attacker (holding a modest pre-locked vlMGP amount) call `vote([X], [delta])` immediately before a `castVotes(false)` transaction (simulate front-running by ordering it in the same block via Hardhat's manual mining).
4. Call `castVotes(false)` (as any third party), triggering `wombatStaking.vote()` → bribe harvest → `queueNewRewards` on Pool X's `BribeRewardPool`.
5. Immediately have Attacker call `unvote(X)`.
6. Assert: Attacker's claimed reward (via `RewardPaid` event/token balance delta) is non-zero and its ratio to `attacker.delta / totalVoteInVlmgp(X)` at harvest time significantly exceeds Attacker's time-weighted share of the bribe accrual period (e.g., attacker held votes for <1% of accrual duration but received >X% of the harvested bribe), and that Voter A's `earned()` for the same reward token is correspondingly reduced versus a control run without the attacker's front-run.

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;

        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingTokenDecimals) /
                totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
