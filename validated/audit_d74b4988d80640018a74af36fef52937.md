### Title
`InternalLazyField.getValue()` silently substitutes a corrupted MessageSet extension with the default instance instead of surfacing invalidity - (File: `java/core/src/main/java/com/google/protobuf/InternalLazyField.java`)

### Summary
The Optimism report's failed invariant is: an external signal that a data source has "resolved incorrectly" (`disputeGameBlacklist`) exists, but the consuming verifier assumes that signal is scoped to a narrower purpose (withdrawals) and therefore never checks it before trusting the data, so callers observe presence/validity without the underlying corruption. The closest Protobuf analog is in `InternalLazyField`, where a lazy MessageSet extension that fails to parse is marked `corrupted`, but `getValue()` (the API surface application code actually consumes) discards that invalidity signal in the legacy/non-lazy-extension mode and silently returns `defaultInstance` — while `hasExtension()`-style presence checks elsewhere in the codebase still report the field as *set*. Application code built on this API therefore reads "present but actually empty/default" data with no way to detect it was corrupted, mirroring the OP verifier trusting data whose validity flag it never inspected.

### Finding Description
`InternalLazyField` stores an extension's raw bytes and lazily parses them on first access [1](#0-0) . When parsing fails, `ensureInitialized()` sets the internal `corrupted` flag and rethrows [2](#0-1) .

The public accessor `getValue()` is the only place that decides what to do with that signal:

```java
MessageLite getValue() {
  try {
    ensureInitialized();
    return value;
  } catch (InvalidProtocolBufferException e) {
    if (extensionRegistry.lazyExtensionEnabled()) {
      // New behavior: runtime exception on corrupted extensions.
      throw new InvalidProtobufRuntimeException(e);
    } else {
      // Old behavior: silently return the default instance.
      return defaultInstance;
    }
  }
}
``` [3](#0-2) 

In the legacy (`lazyExtensionEnabled() == false`) mode, the corruption signal is dropped entirely — no exception, no logging — and the caller receives `defaultInstance` as if the field had never been set to anything invalid. Meanwhile, higher-level accessors such as `hasExtension()`/`FieldSet` presence checks continue to report the field as present, because presence is tracked independently of whether the lazily-parsed payload is valid. This divergence is demonstrated directly in `LazilyParsedMessageSetTest`, where a `TestMessageSet` item with `CORRUPTED_MESSAGE_PAYLOAD` still returns `true` from `hasExtension(TestMessageSetExtension1...)` [4](#0-3) , and the round-tripped bytes for that same corrupted item are preserved unchanged rather than surfaced as invalid [5](#0-4) .

This exactly maps the external invariant: like the Optimism blacklist, which the sponsor argued was "only for withdrawals" and thus safe to omit from verification logic — while the report showed the flag actually encodes "this data resolved incorrectly" — `corrupted` in `InternalLazyField` encodes "this payload failed to parse/is invalid," yet the code path that exists specifically to preserve backward-compatible behavior chooses not to propagate that fact to the consumer that only calls `getValue()`/`hasExtension()`. An application that checks `hasExtension()` before trusting `getExtension()` (a common and reasonable pattern, directly analogous to the verifier trusting `gameAtIndex()`'s non-zero-`blockNumber` result) is misled into treating attacker-supplied malformed extension bytes as "present but legitimately empty," instead of detecting that its input was corrupt.

### Impact Explanation
This is a data-integrity issue rather than a crash or memory-safety bug: a bounded, attacker-controlled MessageSet extension payload that is intentionally malformed (e.g., a single invalid byte, as in the test) causes the runtime to silently substitute a default instance in place of the real (unparseable) value, while presence bits/extension registries still indicate the field was set. Consuming application logic that branches on "has this extension" without separately verifying `getValue()` succeeded can make security- or business-logic-relevant decisions (e.g., treating an important nested policy/config message as "default/empty" instead of rejecting the whole message as malformed) purely because this legacy compatibility mode chooses silence over signaling. Severity is bounded by the fact that this only applies to the legacy MessageSet lazy-extension path (`lazyExtensionEnabled() == false`), not the default binary/JSON message parsing path used by most applications, and does not itself corrupt memory or defeat the outer message's overall `ParseFrom` success/failure semantics for non-MessageSet fields.

### Likelihood Explanation
Reachable by any ordinary client sending a bounded binary Protobuf message containing a proto2 `MessageSet`-style extension whose serialized payload is intentionally malformed at the wire level (as little as one invalid byte suffices, per the existing regression test). No special registry, plugin, or privileged access is required — only a supported public parse API (`ParseFrom`/extension access) on a schema that declares MessageSet-compatible extensions, and use of the legacy (non-`lazyExtensionEnabled`) mode, which is exercised by the codebase's own parameterized test suite and documented as still-supported "old behavior."

### Recommendation
Ensure any code path that returns a substitute/default value on lazy-field corruption also exposes that fact to callers who query presence: either (a) make `hasExtension()`/`FieldSet` treat a corrupted lazy field as absent/invalid consistently with what `getValue()` returns, or (b) deprecate/remove the silent "old behavior" branch in `InternalLazyField.getValue()` in favor of always throwing (the "new behavior" already implemented for `lazyExtensionEnabled()`), so presence and value validity can never diverge for a consumer that has not explicitly opted into legacy silent-corruption semantics.

### Proof of Concept
Using the existing test fixture pattern in `LazilyParsedMessageSetTest`:
1. Build a `RawMessageSet` with one item using a real extension `TYPE_ID_1` but payload `CORRUPTED_MESSAGE_PAYLOAD = {0xFF}` (invalid wire bytes) [6](#0-5) .
2. Parse it as `TestMessageSet` with `LazyExtensionMode` in the legacy (non-eager, non-lazy-verify) configuration.
3. Observe `messageSet.hasExtension(TestMessageSetExtension1.messageSetExtension)` returns `true` [4](#0-3) , while `getExtension(...)` (which goes through `InternalLazyField.getValue()`) silently returns the default instance rather than throwing or indicating corruption, per the documented "Old behavior" branch [7](#0-6) .

I was not able to fully trace every call site across `FieldSet`, `MessageReflection`, `GeneratedMessage`, and `MessageSchema` (66/20/11/11 matches respectively) within the available iterations to enumerate every application-facing accessor affected beyond the extension case demonstrated by the existing test; a full audit of those call sites would be needed to bound the exact scope of consumer code that could be misled by this presence/validity divergence.

```java
  private void ensureInitialized() throws InvalidProtocolBufferException {
    if (value != null) {
      return;
    }

    synchronized (this) {
      if (corrupted) {
        throw new InvalidProtocolBufferException("Repeat access to corrupted lazy field");
      }
      try {
        // `bytes` is guaranteed to be non-null since `value` was null.
        CodedInputStream input = bytes.newCodedInput();
        input.enableAliasing(/* enabled= */ true);
        // When lazyExtensionEnabled() returns true, it means all extensions including MessageSet's
        // will be fully parsed. When it returns false, it basically implies this can only be a
        // MessageSet extension, and we should fall back to the old behavior of silently returning
        // the default instance on corrupted extensions i.e. a full parse.
        value =
            extensionRegistry.lazyExtensionEnabled()
                ? defaultInstance.getParserForType().parsePartialFrom(input, extensionRegistry)
                : defaultInstance.getParserForType().parseFrom(input, extensionRegistry);
        input.checkLastTagWas(0);
      } catch (InvalidProtocolBufferException e) {
        corrupted = true;
        throw e;
      }
    }
  }
