## Title
Ambiguous CW→EVM pointer type resolution allows silent misrouting of token identity in `GetAnyPointeeInfo` - (File: x/evm/keeper/pointer.go)

### Summary
`GetAnyPointeeInfo` resolves an EVM pointer address for a CW address by checking, in a fixed hardcoded order, whether an ERC20↔CW20, ERC721↔CW721, or ERC1155↔CW1155 pointer exists, returning the first match. Because nothing in the system enforces that a single CW address can only ever qualify for exactly one pointer type/registry, it is possible for more than one of these pointer records to exist simultaneously for the same `cwAddress`. In that case, callers of `GetAnyPointeeInfo` silently receive whichever pointer type happens to win the hardcoded ERC20 > ERC721 > ERC1155 priority order, rather than an authoritative, unambiguous answer — this mirrors the Capgo bug class where multiple coexisting "channels" (here, pointer-type registrations) for the same identity cause an implicit, hidden "winner" to be chosen for unqualified lookups. [1](#0-0) 

### Finding Description
`GetAnyPointeeInfo(ctx, cwAddress)` checks `GetERC20CW20Pointer`, then `GetERC721CW721Pointer`, then `GetERC1155CW1155Pointer` for the given `cwAddress` and returns the first that exists: [1](#0-0) 

The three pointer registries (`PointerCW20ERC20Key`/reverse, `PointerCW721ERC721Key`, `PointerCW1155ERC1155Key`) are independent keyspaces set via `SetERC20CW20Pointer`, `SetERC721CW721Pointer`, and `SetERC1155CW1155Pointer` respectively, each populated by the corresponding `AddCW20`/`AddCW721`/`AddCW1155` pointer-precompile handlers, which only check for an existing pointer *of the same type* before writing: [2](#0-1) [3](#0-2) [4](#0-3) 

There is no cross-type check preventing the same `cwAddr` from acquiring an ERC20 pointer, an ERC721 pointer, and an ERC1155 pointer all at once (the only guard, `ErrorPointerToPointerNotAllowed`, prevents chaining a pointer *of* a pointer, not multiple pointer types on the same underlying address). The project's own test suite explicitly documents and accepts this ambiguity: [5](#0-4) 

Because `AddCW20`/`AddCW721`/`AddCW1155` each independently call `wasmdKeeper.QuerySmart` with a type-specific query (`token_info` for CW20, `contract_info` for CW721) and merely require the query to return a JSON object containing `name`/`symbol` fields, a contract author can craft a CosmWasm contract whose `token_info` and `contract_info` (and CW1155 equivalent) queries all succeed, allowing all three pointer types to be registered for the same `cwAddr` by any unprivileged caller through the public `pointer` precompile (`0x100b`) `AddCW20Pointer`/`AddCW721Pointer`/`AddCW1155Pointer` methods — a fully permissionless, unprivileged-EVM-caller-reachable action.

Once multiple pointer types exist for one CW address, any caller of `GetAnyPointeeInfo` (used by `evmrpc/block.go` for reverse pointer resolution in the JSON-RPC surface) receives a hidden, priority-order "winner" rather than the pointer type that actually matches how the contract is currently being interacted with, exactly analogous to the Capgo bug where multiple coexisting public channels caused unnamed `/updates` requests to resolve to an unpredictable hidden winner channel.

### Impact Explanation
`GetAnyPointeeInfo` feeds pointer/pointee resolution used by the EVM JSON-RPC surface (`evmrpc/block.go`) to decide which pointer/ERC-standard representation is associated with a CW contract address. If a malicious CW contract author registers pointers of multiple types for the same address, RPC clients, indexers, and wallets relying on this resolution can be misled about which token standard (ERC20 vs ERC721 vs ERC1155) governs the address, causing them to decode balances/logs/transfers incorrectly (e.g., treating fungible balances as NFT ownership or vice versa). This breaks the integrity/predictability of pointer-based CW↔EVM routing that downstream tooling and potentially other contracts depend on, which corresponds to the "unauthorized transfer via precompile or pointer" / integrity-of-routing impact class named in scope.

### Likelihood Explanation
Registering a pointer is a fully permissionless action reachable by any EVM caller via the `pointer` precompile's `AddCW20Pointer`, `AddCW721Pointer`, and `AddCW1155Pointer` methods, requiring only that the target CW contract answer the relevant `QuerySmart` probes with a `name`/`symbol` field. An attacker who controls (or deploys) the CW contract can trivially make it answer all three probes, then call all three `Add*Pointer` methods from an ordinary account, with no special privilege required. The condition is exercised and acknowledged in-repo by `x/evm/keeper/pointer_test.go`'s `TestGetAnyPointeeInfo` "Multiple pointers exist" case.

### Recommendation
Enforce exclusivity across pointer types for a given CW address: before registering an ERC20/ERC721/ERC1155 pointer for a `cwAddr`, check that no pointer of a *different* type already exists for that same address (not just same-type re-registration), and reject the registration (or require explicit governance/admin resolution) if a conflict is detected. Alternatively, make `GetAnyPointeeInfo` return an explicit ambiguity error/flag when more than one pointer type exists for the same address rather than silently returning the first match in a fixed priority order.

### Proof of Concept
1. Deploy a CosmWasm contract `C` whose smart queries `{"token_info":{}}`, `{"contract_info":{}}`, and the CW1155 info query all return a JSON object containing `name` and `symbol` fields (trivial to implement by simply returning the same static payload for all three query variants).
2. From any unprivileged EVM account, call the `pointer` precompile (`0x100b`):
   - `AddCW20Pointer(C)` → succeeds, sets `ERC20CW20Pointer[C] = P1` [6](#0-5) 
   - `AddCW721Pointer(C)` → succeeds, sets `ERC721CW721Pointer[C] = P2` [7](#0-6) 
   - `AddCW1155Pointer(C)` → succeeds (analogous handler, sets `ERC1155CW1155Pointer[C] = P3`).
3. Call `GetAnyPointeeInfo(ctx, C)` (exercised via `evmrpc/block.go` or directly in-keeper) — it always returns `P1` (the ERC20 pointer) regardless of which pointer a client actually intended to resolve, silently hiding the existence of `P2`/`P3`, exactly as demonstrated by the repo's own `TestGetAnyPointeeInfo` "Test case 5: Multiple pointers exist - should return first match" assertion. [5](#0-4)

func (k *Keeper) GetAnyPointeeInfo(ctx sdk.Context, cwAddress string) (common.Address, uint16, bool) {
	addr, version, exists := k.GetERC20CW20Pointer(ctx, cwAddress)
	if exists {
		return addr, version, true
	}
	addr, version, exists = k.GetERC721CW721Pointer(ctx, cwAddress)
	if exists {
		return addr, version, true
	}
	addr, version, exists = k.GetERC1155CW1155Pointer(ctx, cwAddress)
	if exists {
		return addr, version, true
	}
	return common.Address{}, 0, false
}

func (p PrecompileExecutor) AddCW20(ctx sdk.Context, method *ethabi.Method, caller common.Address, args []interface{}, value *big.Int, evm *vm.EVM, suppliedGas uint64, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	cwAddr := args[0].(string)
	existingAddr, existingVersion, exists := p.evmKeeper.GetERC20CW20Pointer(ctx, cwAddr)
	if exists && existingVersion >= 1 {
		return nil, 0, fmt.Errorf("pointer at %s with version %d exists when trying to set pointer for version %d", existingAddr.Hex(), existingVersion, cw20.CurrentVersion(ctx))
	}
	cwAddress, err := sdk.AccAddressFromBech32(cwAddr)
	if err != nil {
		return nil, 0, err
	}
	res, err := p.wasmdKeeper.QuerySmart(ctx, cwAddress, []byte("{\"token_info\":{}}"))
	if err != nil {
		return nil, 0, err
	}
	formattedRes := map[string]interface{}{}
	if err := json.Unmarshal(res, &formattedRes); err != nil {
		return nil, 0, err
	}
	name := formattedRes["name"].(string)
	symbol := formattedRes["symbol"].(string)
	constructorArguments := []interface{}{
		cwAddr, name, symbol,
	}

	packedArgs, err := cw20.GetParsedABI().Pack("", constructorArguments...)
	if err != nil {
		panic(err)
	}
	bin := append(cw20.GetBin(), packedArgs...)
	if value == nil {
		value = utils.Big0
	}
	ret, contractAddr, remainingGas, err := evm.Create(caller, bin, suppliedGas, uint256.MustFromBig(value))
	if err != nil {
		return
	}
	err = p.evmKeeper.SetERC20CW20Pointer(ctx, cwAddr, contractAddr)
	if err != nil {
		return
	}

	ctx.EventManager().EmitEvent(sdk.NewEvent(
		types.EventTypePointerRegistered, sdk.NewAttribute(types.AttributeKeyPointerType, "cw20"),
		sdk.NewAttribute(types.AttributeKeyPointerAddress, contractAddr.Hex()), sdk.NewAttribute(types.AttributeKeyPointee, cwAddr),
		sdk.NewAttribute(types.AttributeKeyPointerVersion, fmt.Sprintf("%d", cw20.CurrentVersion(ctx)))))
	ret, err = method.Outputs.Pack(contractAddr)
	return
