## Finding: Stale `prevEventsLen` in shared `BalanceHandler` causes EVM StateDB balances to desync from `x/bank` truth during nested/recursive precompile calls

### Title
Recursive precompile calls sharing a single `BalanceHandler` corrupt `prevEventsLen`, causing EVM StateDB balances to diverge from x/bank ledger - (File: `precompiles/common/balance_handler.go`)

### Summary
The Sherlock report describes a stale cached value (`pos.underlyingAmount`) that is never refreshed to reflect the true underlying state (accrued interest), causing a downstream accounting computation (liquidation threshold) to be wrong. The direct structural analog in this repository is `BalanceHandler.prevEventsLen` in [1](#0-0)  — a single mutable "high-water mark" field that is supposed to bound which `x/bank`/`x/precisebank` events get replayed into the EVM `StateDB`, but gets clobbered when the same `BalanceHandler` instance is reused across nested/recursive precompile invocations within one EVM call frame.

### Finding Description
`BeforeBalanceChange` records the current event count as a snapshot boundary, and `AfterBalanceChange` later replays only the events emitted after that boundary into the EVM `StateDB` via `AddBalance`/`SubBalance`: [2](#0-1) [3](#0-2) 

This mirrors the pattern in the report: a single stored scalar (`underlyingAmount` / `prevEventsLen`) is treated as the authoritative baseline for a later delta computation, but nothing guards against that baseline being advanced out from under an outer/enclosing operation. If a precompile call (e.g. `distribution`, `erc20`, `staking`, `ics20`, `gov`, `slashing` — all found wired to this same handler mechanism, [4](#0-3) [5](#0-4) [6](#0-5) ) is triggered recursively (a contract callback re-enters another precompile call within the same top-level call), and both invocations use the *same* `BalanceHandler` instance, the inner call's `BeforeBalanceChange` overwrites `prevEventsLen` to a later index. When the outer call subsequently runs `AfterBalanceChange`, it now replays events starting from the *inner* call's boundary instead of its own original boundary — silently skipping the outer call's own bank events (or double-counting some), producing a stateDB balance that no longer matches the real `x/bank` (or extended `x/precisebank`) balance for the affected addresses.

The repository itself already contains a dedicated regression test explicitly documenting this exact failure mode: [7](#0-6) 
which drives it via a debug precompile and a caller contract performing recursive `callback` calls [8](#0-7) .

### Impact Explanation
`StateDB` balances are the values used within the remainder of the same EVM execution for opcode-level reads (`BALANCE`), value-bearing internal `CALL`s, and any logic a contract implements around perceived token balances. A silent divergence between the real `x/bank`/`x/precisebank` balance and the EVM's cached `StateDB` balance for an address is exactly the class of "irreversible accounting corruption of spendable user value across native balances ... EVM balances" called out in the allowed impact gate — it can let a contract observe (and act on) an inflated or deflated balance relative to on-chain truth, or leave residual EVM-visible balance that doesn't correspond to any real backing coin (or vice versa, losing track of coins that were actually moved).

### Likelihood Explanation
The trigger requires only an unprivileged user deploying/calling a contract that re-enters a Cosmos EVM precompile (e.g., a contract that calls a precompile, and inside that call — via a callback or a second call — invokes another (or the same) precompile again within the same transaction). This is a standard, permissionless composition pattern (contract calling back into itself or another contract that calls a precompile), not a privileged or validator-only action. The existence of a purpose-built test suite reproducing "recursive precompile calls" strongly suggests this was identified as reachable in normal usage.

### Recommendation
`BalanceHandler` should not use a single mutable `prevEventsLen` scalar shared across nested calls. Options:
- Use a stack (push/pop) of event-length boundaries so each nested `BeforeBalanceChange`/`AfterBalanceChange` pair operates on its own boundary and restores the enclosing boundary on return.
- Or instantiate a fresh `BalanceHandler` (via `BalanceHandlerFactory`) per precompile invocation frame instead of reusing one instance across nested calls, and ensure each frame processes only its own event slice before control returns to the caller frame.
- Add invariant checks (as already done for other flows, e.g. `ErrBalanceInvariance` in [9](#0-8) ) comparing expected vs. actual `StateDB` balance after precompile execution to catch desync before it can be exploited.

```go
// BalanceHandler is a struct that handles balance changes in the Cosmos SDK context.
type BalanceHandler struct {
	bankKeeper    BankKeeper
	prevEventsLen int
}

// BeforeBalanceChange is called before any balance changes by precompile methods.
// It records the current number of events in the context to later process balance changes
// using the recorded events.
func (bh *BalanceHandler) BeforeBalanceChange(ctx sdk.Context) {
	bh.prevEventsLen = len(ctx.EventManager().Events())
}
```

```go
func (bh *BalanceHandler) AfterBalanceChange(ctx sdk.Context, stateDB *statedb.StateDB) error {
	events := ctx.EventManager().Events()

	for _, event := range events[bh.prevEventsLen:] {
		switch event.Type {
		case banktypes.EventTypeCoinSpent:
			spenderAddr, err := ParseAddress(event, banktypes.AttributeKeySpender)
			if err != nil {
				return fmt.Errorf("failed to parse spender address from event %q: %w", banktypes.EventTypeCoinSpent, err)
			}
			if bh.bankKeeper.BlockedAddr(spenderAddr) {
				// Bypass blocked addresses
				continue
			}

			amount, err := ParseAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", banktypes.EventTypeCoinSpent, err)
			}

			stateDB.SubBalance(common.BytesToAddress(spenderAddr.Bytes()), amount, tracing.BalanceChangeUnspecified)
```

```go
// TestRecursivePrecompileCallsWithDebugPrecompile demonstrates the balance handler bug
// by triggering recursive calls that share the same BalanceHandler instance.
func (s *BalanceHandlerTestSuite) TestRecursivePrecompileCallsWithDebugPrecompile() {
	evmApp := s.chain.App.(evm.EvmApp)
	ctx := s.chain.GetContext()

	// Create and register debug precompile
	debugPrec := debugprecompile.NewPrecompile(evmApp.GetBankKeeper(), evmApp.GetEVMKeeper())
	// Set the precompile directly in the EVM keeper's precompile map
	evmApp.GetEVMKeeper().RegisterStaticPrecompile(debugPrec.Address(), debugPrec)
	err := evmApp.GetEVMKeeper().EnableStaticPrecompiles(ctx, debugPrec.Address())
	s.Require().NoError(err)

	a, b, c := evmApp.GetEVMKeeper().GetPrecompileInstance(ctx, debugPrec.Address())
	fmt.Println(a, b, c)

	// Deploy caller contract
	callerContract, err := contracts.LoadDebugPrecompileCaller()
	s.Require().NoError(err)

	deploymentData := testutiltypes.ContractDeploymentData{
		Contract:        callerContract,
		ConstructorArgs: []interface{}{},
	}

	// Use local helper function
	callerAddr, err := DeployContract(s.T(), s.chain, deploymentData)
	s.Require().NoError(err)
	s.chain.NextBlock()

	s.T().Logf("Deployed caller contract at %s", callerAddr.Hex())
	s.T().Logf("Debug precompile at %s", debugPrec.Address().Hex())

	// Pack the input for callback(0)
	input, err := callerContract.ABI.Pack("callback", big.NewInt(0))
	s.Require().NoError(err)

	// Fund Contract
	err = evmApp.GetBankKeeper().SendCoins(ctx, s.chain.SenderAccounts[0].SenderAccount.GetAddress(), callerAddr.Bytes(), types.NewCoins(types.NewCoin("aatom", sdkmath.NewInt(10000000))))
	s.Require().NoError(err)

	res, _, _, err := s.chain.SendEvmTx(
		s.chain.SenderAccounts[0],
		0,             // sender index
		callerAddr,    // to address
		big.NewInt(0), // value
		input,         // data
		0,             // gas price multiplier
	)
	s.Require().NoError(err, "callback transaction should succeed")
	s.Require().False(res.IsErr(), "callback should not fail: %s", res.Events)

	s.Require().Equal(len(res.Events), 15, "callback should have 15 events")
	debug_count := 0
	for _, event := range res.Events {
		if event.Type == "debug_precompile" {
			debug_count++
		}
	}
	s.Require().Equal(10, debug_count, "callback should have 1 debug precompile")
```
