### Title
Unclaimed self-pooled rewards get redirected to a new pool when a PlotNFT owner joins a pool before claiming them - ([File: chia/pools/plotnft_drivers.py])

### Summary
When a `PlotNFT` transitions from self-pooling to farming-to-pool (i.e., "joins" a pool), any previously accrued, unclaimed self-pooling reward coins can no longer be claimed to the owner. They can only be swept via `forward_pool_reward`/`forward_pool_rewards`, which sends *all* pending reward coins - including ones earned before the pool join - to the pool's `pool_puzzle_hash`, not to the owner.

### Finding Description
`PlotNFT.claim_pool_rewards()` [1](#0-0)  is the only path that pays reward coins to the owner, and it explicitly refuses to run whenever the singleton is in a pooling state:
```
if self.pooling:
    raise ValueError("Cannot claim rewards while pooling. If you're a pool, try `forward_pool_rewards`")
```
This restriction is not just a convenience check - it mirrors the on-chain puzzle structure. When `pool_config` is set (`self.pooling` is `True`), `puzzle_with_restrictions()` becomes an `MofN(m=1, members=[user_puzzle_with_restrictions(), pool_puzzle_with_restrictions()])` [2](#0-1) . The user branch always carries `SendMessageBanned()` while pooling (both in the farming-to-pool and leaving/waiting-room sub-states) [3](#0-2) , which is the condition required to authorize a direct-to-owner reward claim. The only branch capable of claiming reward coins while pooling is `pool_puzzle_with_restrictions()`, a `FixedPuzzleMember` fixed to the `claim_pool_reward_dpuz` hash [4](#0-3) , and it is only ever exercised through `forward_pool_reward()` [5](#0-4) , which unconditionally sends the reward amount to `self.guaranteed_pool_config.pool_puzzle_hash` via `forward_pool_reward_dpuz()` [6](#0-5) .

Crucially, the reward-coin puzzle (`RewardPuzzle`) is keyed only by `singleton_id` (the launcher id), not by the pool state that was active when the reward was farmed [7](#0-6) . This means unclaimed reward coins earned while self-pooling are indistinguishable, at the puzzle level, from rewards earned after joining a pool - they are swept by the exact same `forward_pool_reward`/`forward_pool_rewards` mechanism once the plotnft transitions into a pooling state, and all get routed to the pool's `pool_puzzle_hash` rather than back to the owner.

This is confirmed by the "LOSE REWARDS (while leaving)" test in the existing test suite, which demonstrates a pool reward being force-forwarded to the pool and disappearing from the owner's plotnft balance even in the leaving-pool sub-state [8](#0-7) , and by the explicit `ValueError` guard blocking the owner-claim path while pooling [1](#0-0) .

This is analogous to the M-8 report's root cause: a function that pays out previously-accrued rewards is gated by a state/role check (`onlyStaker` in the report; `SendMessageBanned`/pooling-state member selection here) that becomes unsatisfiable once the actor transitions away from the state in which the rewards were earned, permanently losing access to funds that were rightfully theirs. Here the mechanism is worse than simple loss: the funds are not just frozen, they are actively redirected to a third party (the new pool) as soon as any sweep of the p2-singleton coins occurs.

### Impact Explanation
Any XCH farmed to a self-pooling PlotNFT that is not claimed before the owner joins a pool becomes unclaimable by the owner and is instead paid out to the pool operator the next time `forward_pool_rewards`/`pw_absorb_rewards` sweeps p2-singleton reward coins. This is a direct, spend-triggered reward redirection / unauthorized transfer of value away from the rightful owner to an unrelated third party (the pool), satisfying the "reward redirection" and "unauthorized coin movement" acceptance criteria. The wallet-side UX flow (`join_pool`, CLI `plotnft join`) does not appear to require or warn that pending self-pooled rewards must be claimed first, so an ordinary user simply joining a pool while a farmed block reward is still sitting unclaimed will lose that reward to the pool.

### Likelihood Explanation
This requires no attacker, malicious peer, or special privileges - it is triggered purely by ordinary wallet-user behavior: farm a self-pooling block reward, then join a pool before claiming it (or leave/re-join in quick succession). Because pool rewards accrue over time and users routinely switch pools, the window in which an unclaimed self-pooling reward exists at the moment of joining a pool is realistic, especially for users who batch-claim rewards infrequently.

### Recommendation
- Require the PlotNFT to have zero unclaimed self-pooling `PoolReward`s before allowing a transition into a pooling state (`join_pool`), or automatically claim all pending self-pooling rewards to the owner as part of the join transaction.
- Alternatively, make `forward_pool_reward`/`forward_pool_rewards` only forward reward coins whose puzzle hash/height postdate the pool-join transition, and provide a separate, always-available claim path for rewards earned while self-pooling regardless of the singleton's current pooling state.
- Add wallet-level warnings/checks in `plotnft_wallet.py`'s join/leave-pool flows surfacing any unclaimed reward balance before allowing the state transition.

### Proof of Concept
Conceptual repro derived from the existing test `test_plotnft_lifecycle` in `chia/_tests/wallet/plotnft_wallet/test_plotnft_wallet.py`:
1. Create a self-pooling PlotNFT and farm blocks to its `p2_singleton_puzzle_hash`, accruing unclaimed `PoolReward` coins (as in lines 160-205 before the `claim_rewards` call is made).
2. Before calling `claim_rewards`, transition the PlotNFT into a pool (`join_pool`), moving it into `FARMING_TO_POOL`/`LEAVING_POOL` state.
3. Attempt `plotnft_wallet.claim_rewards(...)` → raises `ValueError("Cannot claim rewards while pooling...")` as shown at [9](#0-8) .
4. Use `plotnft.forward_pool_reward(pool_reward)` on the previously self-pooled `PoolReward` - the coin spend succeeds and the value is deducted from the plotnft's balance and paid to the pool's `pool_puzzle_hash`, exactly as demonstrated in the "LOSE REWARDS (while leaving)" block at [10](#0-9) , confirming the previously self-earned reward is unrecoverable by the owner and lands with the pool instead.

    def forward_pool_reward(self, reward: PoolReward) -> list[CoinSpend]:
        if not self.pooling:
            raise ValueError("Cannot forward pool reward while self pooling. Try `claim_pool_rewards`")
        return [
            self.singleton_action_spend(inner_solution=self.forward_pool_reward_inner_solution(reward)),
            make_spend(
                coin=reward.coin,
                puzzle_reveal=reward.puzzle(),
                solution=reward.solve(

                    delegated_puzzle_and_solution=DelegatedPuzzleAndSolution(
                        puzzle=self.forward_pool_reward_dpuz(),
                        solution=Program.to([reward.coin.amount]),
                    ),
                ),
            ),
        ]
