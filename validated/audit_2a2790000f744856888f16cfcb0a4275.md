## Finding: Valid

### Title
Hardcoded `": "` trailer-removal string in `trimCoAuthorsTrailers` fails to strip Co-Authored-By trailers with non-canonical spacing/separators, letting attacker text leak into squashed commit descriptions - (File: `app/src/models/commit.ts`)

### Summary
`Commit.bodyNoCoAuthors` is supposed to be a "co-author-free" version of a commit body, and `getSquashedCommitDescription` relies on that invariant when concatenating multiple commits' bodies during a squash. The stripping logic in `trimCoAuthorsTrailers` does a literal string replace of `` `${token}: ${value}` `` against the raw, un-normalized commit body, but the `token`/`value` pair comes from git's already-parsed/normalized trailer output. Any mismatch between the literal formatting git normalized the trailer to and the exact raw text in the body (different separator character, missing/extra whitespace around the separator, folded/continuation lines) makes the `.replace()` a no-op, leaving the full co-author trailer line intact in `bodyNoCoAuthors`.

### Finding Description
`Commit.bodyNoCoAuthors` is computed in the constructor: [1](#0-0) 

via `trimCoAuthorsTrailers`, which performs a hardcoded exact-string removal: [2](#0-1) 

`token` and `value` here originate from `parseTrailers`, which runs `git interpret-trailers --parse` and re-splits the (already git-normalized/unfolded) output using `parseSingleUnfoldedTrailer`: [3](#0-2) [4](#0-3) 

`parseSingleUnfoldedTrailer` uses `line.indexOf(separator)` and trims the resulting token/value, so it tolerates variations in whitespace or the separator character configured via `trailer.separators` (defaulting to `:` when unconfigured, see `getTrailerSeparatorCharacters`, lines 75-79). Git itself is similarly lenient about optional whitespace surrounding a trailer separator when recognizing trailers in a raw commit body.

However, `trimCoAuthorsTrailers` reconstructs the search string as the fixed literal `` `${token}: ${value}` `` (colon immediately followed by exactly one space) and searches for it in the **raw, un-normalized** `body` field passed into the `Commit` constructor. Any commit whose raw trailer line does not exactly match `Token: value` — e.g. `Co-Authored-By:name <email>` (no space), `Co-Authored-By :  name <email>` (extra/differently-placed spaces), or a trailer using a different configured separator character — will still be correctly recognized and parsed as a co-author trailer (so it appears in `coAuthors` and drives UI behavior like "showCoAuthoredBy"), but the `.replace()` call will silently fail to find a match, leaving the entire trailer line present in `bodyNoCoAuthors`.

`getSquashedCommitDescription` then concatenates `c.bodyNoCoAuthors.trim()` for every commit being squashed, trusting that co-author trailers have been fully stripped: [5](#0-4) 

The squash flow is triggered from `onSquash` in `compare.tsx`, which passes attacker-fetched commits (`toSquashSansSquashOnto`) directly into `getSquashedCommitDescription` and prepopulates the result as the description in the commit-message popup: [6](#0-5) 

### Impact Explanation
If a user fetches/clones a repository containing an attacker-crafted commit with a co-author trailer whose literal formatting deviates from `Token: value` (differing whitespace or separator), and later squashes that commit (a common workflow when tidying history before pushing), the un-stripped trailer text will silently remain embedded in the new squashed commit's description. The user may not notice the extra line buried among multiple commit bodies in the commit-message textarea, and it becomes part of the new commit's permanent message once pushed — corrupting the resulting authored/pushed content with attacker-controlled text (e.g., a fabricated `Co-Authored-By` line pointing to an arbitrary name/email, or arbitrary trailing text appended after it). This fits the "silent corruption of what the user commits or pushes" impact bucket, though it is a content-integrity issue rather than code execution or credential exposure, and the text is still visible (not hidden) in the confirmation dialog before the user submits.

### Likelihood Explanation
Exploitation only requires the attacker to control one commit that ends up fetched into the victim's repository (e.g., a branch/PR the victim fetches) and the victim choosing to squash a range of commits that includes it. Crafting a trailer with unconventional spacing (`Co-Authored-By:x <x>` with no space, or extra spaces) is trivial and git's own trailer parser is lenient enough to still recognize it as a valid trailer, so the parse/strip mismatch is realistic. Exploiting a custom separator character additionally requires the target repository to have a non-default `trailer.separators` git config, which is a narrower condition.

### Recommendation
Do not reconstruct the trailer text with a hardcoded `: ` literal. Instead, either:
- Use the same lenient matching used to originally recognize the trailer (e.g. a regex built from the actual separator characters and optional surrounding whitespace) when stripping it from the raw body, or
- Perform the stripping using `git interpret-trailers` itself (which already understands the repository's `trailer.separators` and whitespace/folding rules) rather than a manual string replace, so the invariant "`bodyNoCoAuthors` fully strips co-author trailers" is actually preserved for all valid trailer formats.

### Proof of Concept
1. Attacker crafts a commit with a body such as:
```
Fixes the bug.

Co-Authored-By:evil <evil@example.com>
```
(no space after the colon — still a syntactically valid trailer that `git interpret-trailers --parse` and `parseSingleUnfoldedTrailer` will correctly parse into `{ token: 'Co-Authored-By', value: 'evil <evil@example.com>' }`).
2. Victim fetches this commit into their local repository.
3. Victim selects this commit along with others and invokes "Squash Commits" in the history/compare view, hitting `onSquash` → `getSquashedCommitDescription`.
4. `trimCoAuthorsTrailers` attempts `body.replace('Co-Authored-By: evil <evil@example.com>', '')` (colon+space) against the raw body text `Co-Authored-By:evil <evil@example.com>` (no space) — no match occurs, so `bodyNoCoAuthors` for this commit still contains the full trailer line.
5. `getSquashedCommitDescription` concatenates this into the new squashed description, prepopulating the commit-message dialog with the attacker's residual trailer text intact; if the user pushes without carefully re-reading the merged description, the injected line becomes part of the pushed commit history.

export function parseSingleUnfoldedTrailer(
  line: string,
  separators: string
): ITrailer | null {
  for (const separator of separators) {
    const ix = line.indexOf(separator)
    if (ix > 0) {
      return {
        token: line.substring(0, ix).trim(),
        value: line.substring(ix + 1).trim(),
      }
    }
  }

  return null
}

export async function parseTrailers(
  repository: Repository,
  commitMessage: string
): Promise<ReadonlyArray<ITrailer>> {
  const result = await git(
    ['interpret-trailers', '--parse'],
    repository.path,
    'parseTrailers',
    {
      stdin: commitMessage,
    }
  )

  const trailers = result.stdout

  if (trailers.length === 0) {
    return []
  }

  const separators = await getTrailerSeparatorCharacters(repository)
  return parseRawUnfoldedTrailers(result.stdout, separators)
}

import { Commit } from '../../models/commit'

export function getSquashedCommitDescription(
  commits: ReadonlyArray<Commit>,
  squashOnto: Commit
): string {
  const commitMessages = commits.map(
    c => `${c.summary.trim()}\n\n${c.bodyNoCoAuthors.trim()}`
  )

  const descriptions = [
    squashOnto.bodyNoCoAuthors.trim(),
    ...commitMessages,
  ].filter(d => d.trim() !== '')

  return descriptions.join('\n\n')
}
