### Title
Malformed Ed448 `EncryptedMessage` with identity key crashes share decryption - ([File: crypto/dkg/pedpop/src/encryption.rs](crypto/dkg/pedpop/src/encryption.rs))

### Summary
An attacker-controlled serialized `EncryptedMessage<Ed448, _>` can use the canonical Ed448 identity encoding as its ephemeral key. `EncryptedMessage::read` accepts it because `Ciphersuite::read_G` performs canonical-point validation but does not reject identity, while the FROST-specific `Curve::read_G` identity rejection is not used on this path. During decryption, Serai performs ECDH before waiting for the queued proof-of-possession batch check, yielding the Ed448 identity point; serializing that point calls `Ed448::Point::to_bytes`, which unconditionally unwraps inversion of `z = 0` and panics. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) 

### Finding Description
`EncryptedMessage::read` accepts an arbitrary group element for `key`, including identity for suites whose generic `Ciphersuite::read_G` allows it. [3](#0-2) 

`Encryption::decrypt` queues the attacker-controlled Schnorr proof for later batch verification, but immediately computes `msg.key * enc_key` and passes the result into `cipher`. [5](#0-4) 

`cipher` serializes the shared point with `ecdh.to_bytes()`. [6](#0-5) 

For Ed448, identity is a valid canonical, torsion-free point, but `Point::to_bytes` calls `self.z.invert().unwrap()`. Identity has `z = 0`, so serialization panics. [7](#0-6) [4](#0-3) 

### Impact Explanation
A party able to submit an encrypted DKG message can abort the victim process handling that message. This is remotely triggered application termination from malformed public input, analogous to CVE-2018-10778’s attacker-controlled malformed-input crash. [5](#0-4) 

### Likelihood Explanation
No secret or protocol privilege is required beyond supplying bytes accepted by `EncryptedMessage::read`. The payload can consist of an identity key followed by syntactically valid signature and ciphertext fields; even an invalid proof does not prevent the panic because ECDH and serialization happen before the queued proof is checked. [3](#0-2) [5](#0-4) 

### Recommendation
Reject identity points in `EncryptedMessage::read`, `EncryptionKeyMessage::read`, `EncryptionKeyProof::read`, and other DKG parsers where an identity point is semantically invalid. As defense in depth, make Ed448 point serialization return an encoding for identity or otherwise ensure callers never serialize identity where the implementation cannot represent it. [3](#0-2) [8](#0-7) [4](#0-3) 

### Proof of Concept
Conceptually, build an `EncryptedMessage<Ed448, SecretShare<...>>` byte stream containing:

```text
key = Ed448 identity encoding       // 57-byte compressed identity
pop.R = arbitrary canonical point
pop.s = arbitrary canonical scalar
msg   = fixed-width SecretShare bytes
```

`read` accepts the identity key, `decrypt` computes `enc_key * identity = identity`, and `cipher` invokes `Point::to_bytes` on identity, reaching `invert().unwrap()` and panicking. [5](#0-4) [4](#0-3)
