Found a concrete analog in the `BandwidthManager.onAccept` handler.

### Title
`BandwidthManager.onAccept` accepts `Withdraw` action from any request whose `source` equals hyperbridge, without checking the sender module identity, allowing unauthorized draining of purchased bandwidth funds - (File: evm/src/apps/BandwidthManager.sol)

### Summary
`BandwidthManager.onAccept` is the inbound handler for governance messages arriving from `pallet-bandwidth` on Hyperbridge. Its only origin check is `request.source.equals(IDispatcher(_host).hyperbridge())` [1](#0-0) . Unlike `ExtrinsicIntents._authenticate`, which additionally checks that `request.from` matches the specific registered module address for the source chain [2](#0-1) , `BandwidthManager` never inspects `request.from` at all. It only verifies the chain-level `source`, not the specific pallet/module identity that dispatched the message on that chain.

### Finding Description
`onAccept` decodes the first body byte as `OnAcceptActions` and, for `Withdraw`, immediately transfers `w.amount` of `w.token` (or native ETH) to `w.beneficiary`, sourced entirely from attacker-controlled payload fields, with no additional authorization: [3](#0-2) . The guard `onlyHost` only ensures the call comes from the configured `IsmpHost` (which is the generic dispatch entry point for *any* message reaching this state machine from Hyperbridge), and `request.source.equals(hyperbridge())` only ensures the message originated from the Hyperbridge parachain, not from `pallet-bandwidth` specifically. Any other module on Hyperbridge (or a pallet reachable by an unprivileged extrinsic that can dispatch an ISMP POST request with `to = PALLET_BANDWIDTH_MODULE_ID` and arbitrary `from`) can craft a POST request whose `source` is Hyperbridge and whose body begins with `OnAcceptActions.Withdraw`, causing `BandwidthManager` to transfer out any ERC20 balance or native ETH it holds (i.e., all funds paid in by legitimate `purchase()` callers) to an attacker-chosen beneficiary.

This mirrors the external report's core broken invariant: a value that should bind the acceptance of state-changing action to a specific, unforgeable origin/context (there, partyA/partyB nonces; here, the specific sending module/pallet identity) is omitted, so a message that passes the check performed (nonce validity / `source==hyperbridge`) can still carry state that was never validated as coming from the intended counterparty (the correct partyB action / `pallet-bandwidth`'s own governance decision).

### Impact Explanation
This directly matches the required impact class "unauthorized transaction or execution" and "stealing or loss of funds": funds escrowed in `BandwidthManager` from all `purchase()` calls can be swept to an attacker's address via a spoofed `Withdraw` action, without any admin, relayer, or prover compromise — only the ability to get any message accepted by the host whose `source` resolves to the Hyperbridge state machine and whose `to` is `PALLET_BANDWIDTH_MODULE_ID`.

### Likelihood Explanation
Exploitability depends on whether `pallet-bandwidth` or any other pallet/pathway on the Hyperbridge state machine can be induced to (or already does) dispatch a POST request to this destination/module id with attacker-influenced body content, or whether `request.from` can be forged by any unprivileged actor able to route through Hyperbridge to this module. I could not fully verify, within available context, whether `pallet-bandwidth`'s dispatch logic restricts `from`/module binding on the Hyperbridge side, since that pallet's source was not indexed/available. Given the missing local `from`-module binding on the EVM side (in contrast to `ExtrinsicIntents._authenticate`, which explicitly checks it), the vulnerability is a real gap in defense-in-depth regardless of whether the Substrate side currently constrains it — a single-sided authentication check.

### Recommendation
Add an explicit `request.from` check in `BandwidthManager.onAccept`, analogous to `ExtrinsicIntents._authenticate`, verifying that `request.from` equals the specific pallet account/module id authorized to issue `SetTiers`/`Withdraw` actions, not merely that `request.source` is Hyperbridge.

### Proof of Concept
Conceptual (cannot be fully demonstrated without the Substrate-side `pallet-bandwidth` dispatch code, which was not available in this index):
1. Any actor capable of dispatching an ISMP POST request from the Hyperbridge state machine with `to = "BWMARKET"` and body `abi.encodePacked(uint8(1), abi.encode(Withdrawal({token: feeToken, beneficiary: attacker, amount: type(uint256).max})))` triggers relaying to `BandwidthManager`.
2. `EvmHost.dispatchIncoming` invokes `onAccept` via `IApp.onAccept.selector` [4](#0-3) .
3. `onAccept` checks only `request.source.equals(hyperbridge())` [1](#0-0)  and, seeing `OnAcceptActions.Withdraw`, transfers the entire fee-token balance to `attacker` [3](#0-2) . [5](#0-4)

    /// @notice Inbound governance from `pallet-bandwidth`. The first
    /// body byte selects `OnAcceptActions`; the remainder is the
    /// action's ABI-encoded payload.
    /// @dev Only the configured host may invoke (`onlyHost`); the
    /// request's `source` must additionally equal hyperbridge.
    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost {
        PostRequest calldata request = incoming.request;

        if (!request.source.equals(IDispatcher(_host).hyperbridge())) revert UnauthorizedAction();

        OnAcceptActions action = OnAcceptActions(uint8(request.body[0]));
        if (action == OnAcceptActions.SetTiers) {
            Tier[] memory updates = abi.decode(request.body[1:], (Tier[]));
            for (uint256 i = 0; i < updates.length; i++) {
                tierPrice[updates[i].tier] = updates[i].price;
                emit TierSet(updates[i].tier, updates[i].price);
            }
        } else if (action == OnAcceptActions.Withdraw) {
            Withdrawal memory w = abi.decode(request.body[1:], (Withdrawal));
            if (w.token != address(0)) {
                IERC20(w.token).safeTransfer(w.beneficiary, w.amount);
            } else {
                (bool sent,) = w.beneficiary.call{value: w.amount}("");
                if (!sent) revert InsufficientNativeToken();
            }
            emit Withdrawn(w.token, w.beneficiary, w.amount);
        } else {
            revert UnauthorizedAction();
        }
    }
