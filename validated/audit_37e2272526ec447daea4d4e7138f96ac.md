## Title
Consensus-incentive reward rate changes apply retroactively to the entire unpaid block backlog, allowing relayers to capture inflated treasury payouts - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet-consensus-incentives` computes relayer rewards as `(latest_height - LastRewardedHeight_watermark) * current_cost_per_block`. The `cost_per_block` rate used is always the value read *at settlement time*, never a rate that was locked in as blocks accrued. This is the same broken invariant described in TOKE-27: a newly set rate is applied to a past span instead of only to the span going forward, because the pallet never settles/pays out the pending backlog at the old rate before the rate changes.

### Finding Description
`update_cost_per_block` simply overwrites the stored rate with no side effects: [1](#0-0) 

The reward calculation reads the *current* rate and multiplies it by the entire unpaid span since the last watermark: [2](#0-1) 

`LastRewardedHeight` only advances when a reward is actually paid out via `process_message`: [3](#0-2) 

There is no mechanism analogous to `AutopoolFees`'s recommended fix (call `updateDebtReporting`/settle-then-change) that forces a "checkpoint" reward payout at the old rate for any already-accrued, unrewarded block span before `update_cost_per_block` takes effect. Any block span that accrued under the old (e.g. lower) rate but has not yet been claimed will be paid out entirely at the new rate once the next `ConsensusMessage` is processed. Because relayers control *when* they submit the next consensus update (there is no deadline or per-height rate snapshot forcing timely submission), a relayer can simply withhold submitting an update for a chain, wait for governance to raise `cost_per_block`, and then submit — collecting the higher rate for blocks that advanced entirely under the old, lower rate. Conversely, if the rate is lowered, the treasury benefits at the relayer's expense for blocks it should have paid more for — either direction is a fund-accounting error, not just a griefing vector.

### Impact Explanation
This causes direct, quantifiable loss of treasury funds: `T::Currency::transfer` moves treasury balance to the relayer for a reward whose size is a function of a rate that never applied during most of the rewarded span: [4](#0-3) 

Because there is no cap tying the backlog size to a bounded window (LastRewardedHeight can lag arbitrarily far behind `latest_height` if a relayer simply doesn't submit), the magnitude of the overpayment scales with however long the relayer chooses to withhold submission before/around a rate increase, directly draining the `TreasuryAccount`.

### Likelihood Explanation
No privileged access or malicious governance intent is required from the exploiting party — the relayer only needs to observe a public, on-chain `update_cost_per_block` call (or any expected upward rate change) and time their own unprivileged `ConsensusMessage` submission accordingly, which is a normal permissionless action already available in `pallet_ismp::Pallet::handle_unsigned`. This mirrors the original TOKE-27 scenario exactly: a "fixed" fee-rate update is not synced to the present before taking effect, so it silently reaches back into an unsettled past window.

### Recommendation
Before `update_cost_per_block` mutates `StateMachinesCostPerBlock`, force a settlement of any pending/unpaid block span for that `state_machine_id` at the *old* rate — i.e., pay out `(latest_height - LastRewardedHeight) * old_cost_per_block` and advance the watermark to `latest_height`, then apply the new rate. This is the direct analog of the AutopoolFees remediation ("sync fee up to the present via `updateDebtReporting` before changing the rate").

### Proof of Concept
1. Governance sets `cost_per_block = 10` for `state_machine_id`.
2. State machine height advances from 1000 → 2000 via consensus updates, but the relayer withholds calling `handle_unsigned` with the corresponding `ConsensusMessage` (nothing forces immediate submission; `LastRewardedHeight` stays at 1000).
3. Governance later raises `cost_per_block` to 1000 (a routine parameter update, as demonstrated in `test_incentivize_relayer`/`update_cost_per_block`, see `modules/pallets/testsuite/src/tests/pallet_consensus_incentives.rs:130-135`).
4. Relayer now submits the withheld `ConsensusMessage`. `calculate_reward` computes `blocks = 2000 - 1000 = 1000` and `reward = 1000 * 1000 = 1,000,000`, all paid from `TreasuryAccount`, even though those 1000 blocks accrued entirely under the old rate of 10 (expected fair payout: `1000 * 10 = 10,000`).
5. The relayer collects a 100x windfall funded by the treasury, purely by timing when to submit an otherwise-honest, permissionless consensus update.

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}
