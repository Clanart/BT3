## Title
GitHub Desktop's credential helper trusts an attacker-controlled `WWW-Authenticate` header to classify a remote as a "GitHub" host, bypassing real host verification — (`app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The C4 finding's broken invariant is: a callback to untrusted, attacker-influenced code/data happens *before* the state/checks that should gate a sensitive effect are completed, letting the untrusted party influence a decision that hasn't been fully validated yet. The closest Desktop analog is in the git credential-helper trampoline's host classification logic: `getEndpointKind()` treats a `WWW-Authenticate` HTTP header — data that comes verbatim from whatever server the user's git remote points to — as sufficient proof the host is "GitHub"/"GitHub Enterprise", and this "happy path" short-circuits the one check (`isGitHubHost()`) that actually validates the claim by talking to the real API.

### Finding Description
When Git needs credentials for an HTTPS remote, it invokes Desktop's credential helper (`createCredentialHelperTrampolineHandler`) and forwards any `WWW-Authenticate` response headers it received from the remote server as `wwwauth[...]` fields in the credential protocol payload [1](#0-0) .

In `getEndpointKind`, before falling back to the actual verification helper `isGitHubHost(endpoint)` (which performs a real network check), the function scans these attacker-suppliable `wwwauth[...]` values and, if any contains `realm="GitHub"`, immediately classifies the endpoint as `'enterprise'` — a real network call to confirm this is skipped entirely: [2](#0-1) 

This classification feeds directly into `getCredential`, which — if no existing account matches the (attacker-controlled) endpoint — opens Desktop's own "Sign in to GitHub Enterprise" dialog scoped to that attacker endpoint: [3](#0-2) 

That prompt is rendered by Desktop's native chrome via `trampolineUIHelper.promptForGitHubSignIn`, which starts an Enterprise sign-in flow bound to the attacker's origin and shows a credential-helper-specific dialog stating "Git requesting credentials to access `<url>`": [4](#0-3) [5](#0-4) 

Whatever account results from that flow then has its token attached directly as the git password and handed back to Git, which sends it to the attacker's server over the same connection: [6](#0-5) 

The comment in the code itself acknowledges the header is being used as an unverified shortcut ("happy-path... without having to resort to making a request ourselves") [7](#0-6) , i.e., the effect (invoking a "GitHub" branded sign-in/credential flow) is triggered by attacker data before the app's own verification check would have run.

### Impact Explanation
Any git server the user's remote points at (a malicious/compromised host, or a MITM/proxy sitting on the network path, per the stated threat model) can spoof `WWW-Authenticate: ... realm="GitHub"` on a 401 response to force Desktop's credential helper into `'enterprise'` classification without the intended verification step ever running. This lets an attacker cause Desktop's own UI to present a "GitHub Enterprise sign-in"/credential-request flow scoped to their host, and whatever OAuth/PAT credential the user supplies (or an already-signed-in account's token if the attacker-controlled endpoint happens to collide with the account's derived API endpoint) is then transmitted back to the attacker's server as the git password. This matches the report's category of an attacker-controlled remote/proxy response leading to unauthorized OAuth/account binding and credential/token exfiltration.

### Likelihood Explanation
The header is fully attacker-controlled server response data and requires no special git configuration or local access — it's exactly the "attacker controls... a git remote/proxy response" primitive named in the valid-impact criteria. It does require the user to complete a sign-in prompt, but that prompt is a normal, expected part of the git-over-HTTPS authentication UX in Desktop, not an out-of-band social-engineering step.

### Recommendation
Do not let the `wwwauth[...]` `realm="GitHub"` hint alone decide the `'enterprise'` classification. Always run the real verification (`isGitHubHost(endpoint)`) before deciding to prompt for/attach a GitHub-scoped credential, and only use the header as a hint to prioritize which check to run first, not as a substitute for it.

### Proof of Concept
1. Attacker sets up (or MITMs/proxies) an HTTPS git server at `https://attacker.example.com/victim/repo.git`.
2. On any git-over-HTTPS request requiring auth, the server responds `401` with header `WWW-Authenticate: Basic realm="GitHub"`.
3. Git forwards this as `wwwauth[0]=Basic realm="GitHub"` to Desktop's credential helper.
4. `getEndpointKind` matches the realm string and returns `'enterprise'` without calling `isGitHubHost` [8](#0-7) .
5. Since no existing account matches `attacker.example.com`, Desktop calls `ui.promptForGitHubSignIn('https://attacker.example.com/...')`, popping a native "Sign in to GitHub Enterprise" dialog bound to the attacker's origin [9](#0-8) .
6. Whatever account the user authenticates results in `credWithAccount` attaching that account's token as the git password sent back to the attacker's server [6](#0-5) .

```typescript
/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }
```

```typescript
const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
```

```typescript
  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
```
