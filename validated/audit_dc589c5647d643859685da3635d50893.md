### Title
`ThresholdView`/`ThresholdKeys` `Debug` impls print ephemeral secret scalar and offset tweaks in clear text - (File: crypto/dkg/src/lib.rs)

### Summary
The zhmcclient advisory is a clear-text-secret-in-logs bug: sensitive values are written to optional log output. The Serai analog lives in `crypto/dkg`: `ThresholdKeys` derives `Debug` and `ThresholdView` manually implements `Debug`, and both emit the `scalar` and `offset` fields — the very tweak values the API explicitly keeps out of serialization because they are ephemeral secrets — while the same impls deliberately suppress the actual `secret_share` via `finish_non_exhaustive`. Any consumer that `{:?}`-formats or logs these types (common during signer debugging) writes the secret tweaks to logs.

### Finding Description
`ThresholdKeys` derives `Debug` (`crypto/dkg/src/lib.rs:291`), so a derived impl prints every field: `core`, `scalar`, and `offset`. The manual `Debug for ThresholdView` (`crypto/dkg/src/lib.rs:316-329`) explicitly calls `.field("scalar", &self.scalar)` and `.field("offset", &self.offset)` before `finish_non_exhaustive()`. The same code carefully excludes `secret_share` — proof the authors intended to redact secret material — yet `scalar` and `offset` are treated as printable.

These fields are secret-bearing by design:

- `ThresholdKeys::scale` (`crypto/dkg/src/lib.rs:400-407`) multiplies the key by a caller-supplied scalar "to allow for various account and privacy schemes" and documents the scalar as *"ephemeral and will not be included when these keys are serialized."*
- `ThresholdKeys::offset` (`crypto/dkg/src/lib.rs:414-417`) adds a tweak documented the same way.
- `ThresholdKeys::write` (`crypto/dkg/src/lib.rs:535-560`) explicitly omits scalar/offset ("This will not include the ephemeral scalar/offset"), confirming they are not meant to be persisted or exposed — yet `Debug` exposes them.
- In `view()` (`crypto/dkg/src/lib.rs:494-521`), the secret share is computed as `interpolation_factor * scalar * secret_share` and `offset` is added to `included[0]`'s share — i.e., these values are combined directly with the private key share.

`C::F` (e.g., `dalek_ff_group::Scalar`, `ed448::Scalar`) implements `Debug` via the field's byte representation, so the emitted value is the full secret scalar in clear text — exactly the CWE-312 class from the advisory.

### Impact Explanation
Any integration that logs or formats a `ThresholdKeys`/`ThresholdView` (panic messages, `tracing`/`log` spans, error paths using `{:?}`) leaks the multiplicative/additive key tweaks. With `offset` known, an observer can strip the offset's contribution from a broadcast signature share (`s = d + e·ρ + c·(share + offset)` for participant `included[0]`), and knowledge of `scalar`/`offset` defeats the privacy/account schemes these tweaks exist to provide (e.g., unlinkable derived keys become linkable/recoverable). Combined with a single observed signature share, recovery of the tweaked share reduces to recovering the raw secret share — the marginal secrecy the offset provided is destroyed. This is local secret-material disclosure via diagnostic output, reachable purely through public-facing log configuration, matching the advisory's "only affects users that have enabled logging" precondition.

### Likelihood Explanation
Medium likelihood, mirroring the original advisory: it requires an integrator to `Debug`-format these structures, but the type publicly implements `Debug` and sits on the hot path of every FROST signing operation (`AlgorithmSignMachine` holds `ThresholdKeys`; `AlgorithmSignatureMachine` holds `ThresholdView` at `crypto/frost/src/sign.rs:431-438`), so debugging instrumentation naturally touches it. Severity Medium: leaks secret tweak material, not the raw `secret_share` directly.

### Recommendation
Remove `Debug` from `ThresholdKeys`' derive list and implement a manual impl that prints only `core` (whose own Debug already redacts `secret_share`) and `finish_non_exhaustive()`; drop `.field("scalar", …)` / `.field("offset", …)` from `impl Debug for ThresholdView`, matching the treatment already given to `secret_share`.

### Proof of Concept
```rust
// crypto/dkg/src/lib.rs — ThresholdKeys derives Debug (line 291), printing `scalar`/`offset`.
// ThresholdView::fmt explicitly prints them (lines 320-322).
let keys = ThresholdKeys::<Ed25519>::new(params, interp, share, vshares).unwrap()
  .scale(secret_scalar).unwrap()   // ephemeral secret tweak, excluded from write()
  .offset(secret_offset);
println!("{keys:?}");              // prints scalar and offset in clear text
let view = keys.view(included).unwrap();
log::debug!("{view:?}");           // .field("scalar", ...).field("offset", ...) leaks both
```
`ThresholdKeys::write` omits these fields precisely because they are secret; `Debug` re-exposes them.
