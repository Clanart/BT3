### Title
Participant-order confusion lets a fabricated blame message blame an innocent DKG participant - (File: `processor/src/key_gen.rs`)

### Summary
`VerifyBlame` passes `accuser` as the PedPoP `sender` and `accused` as the `recipient`, reversing the `BlameMachine::blame` argument order. This makes the blame verifier validate the message’s proof-of-possession against the accuser as sender, then return the accused as the “recipient” when no valid decryption proof is supplied. A public participant can therefore forge a blame statement that causes the processor to blame an innocent accused party.

### Finding Description
`AdditionalBlameMachine::blame` expects `(sender, recipient, msg, proof)` and internally returns `recipient` when the supplied decryption proof is absent or invalid. [1](#0-0)  In `decrypt_with_proof`, a valid per-message Schnorr proof-of-possession is checked with `sender` bound into `pop_challenge`, while `None` for the proof produces `InvalidProof`. [2](#0-1)  The processor calls `blame(accuser, accused, ...)`, instead of `blame(accused, accuser, ...)`. [3](#0-2) 

### Impact Explanation
An attacker can create a syntactically valid `EncryptedMessage` whose PoP is bound to the attacker as `sender`, submit it through `VerifyBlame` with an arbitrary victim as `accused`, and omit the decryption proof. The processor then returns `ProcessorMessage::Blame { participant: accused }`, effectively accepting a forged fault claim against a participant who did not create the message. [4](#0-3) 

### Likelihood Explanation
The attacker only needs public protocol inputs: participant IDs and serialized bytes accepted by `EncryptedMessage::read`. `EncryptedMessage::read` parses an attacker-controlled message key, Schnorr PoP, and payload without authenticating the original sender itself. [5](#0-4)  Because the PoP challenge deliberately includes the claimed sender, the attacker can generate a valid PoP for `sender = accuser` and trigger the incorrect recipient-blame path deterministically. [6](#0-5) 

### Recommendation
Swap the blame arguments so `AdditionalBlameMachine::blame` receives `accused` as `sender` and `accuser` as `recipient`. Add a regression test showing that a fabricated message cannot produce blame against the accused, and that a genuine malformed share from the accused is still attributed to the accused.

### Proof of Concept
1. Attacker `A` chooses victim `B` and a valid DKG `context`.
2. `A` constructs an `EncryptedMessage<C, SecretShare<C::F>>` containing:
   - `key = kG` for attacker-known scalar `k`,
   - ciphertext bytes of the expected scalar length,
   - `pop = SchnorrSignature::sign(k, r, pop_challenge(context, rG, kG, A, ciphertext))`.
3. `A` submits `VerifyBlame { accuser: A, accused: B, share: serialize(message), blame: None }`.
4. `pop_challenge` is evaluated with `sender = A`, so the forged PoP verifies. [7](#0-6) 
5. `proof == None` returns `InvalidProof`, causing `blame_internal` to return the supplied `recipient`, which is `B`. [8](#0-7) 
6. `VerifyBlame` emits blame for `B` despite `B` never sending the message. [9](#0-8)

fn pop_challenge<C: Ciphersuite>(
  context: [u8; 32],
  nonce: C::G,
  key: C::G,
  sender: Participant,
  msg: &[u8],
) -> C::F {
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption Key Proof of Possession v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"proof_of_possession");

  transcript.append_message(b"nonce", nonce.to_bytes());
  transcript.append_message(b"key", key.to_bytes());
  // This is sufficient to prevent the attack this is meant to stop
  transcript.append_message(b"sender", sender.to_bytes());
  // This, as written above, doesn't hurt
  transcript.append_message(b"message", msg);
  // While this is a PoK and a PoP, it's called a PoP here since the important part is its owner
  // Elsewhere, where we use the term PoK, the important part is that it isn't some inverse, with
  // an unknown to anyone discrete log, breaking the system
  C::hash_to_F(b"DKG-encryption-proof_of_possession", &transcript.challenge(b"schnorr"))

  pub(crate) fn decrypt_with_proof<E: Encryptable>(
    &self,
    from: Participant,
    decryptor: Participant,
    mut msg: EncryptedMessage<C, E>,
    // There's no encryption key proof if the accusation is of an invalid signature
    proof: Option<EncryptionKeyProof<C>>,
  ) -> Result<Zeroizing<E>, DecryptionError> {
    if !msg.pop.verify(
      msg.key,
      pop_challenge::<C>(self.context, msg.pop.R, msg.key, from, msg.msg.deref().as_ref()),
    ) {
      Err(DecryptionError::InvalidSignature)?;
    }

    if let Some(proof) = proof {
      // Verify this is the decryption key for this message
      proof
        .dleq
        .verify(
          &mut encryption_key_transcript(self.context),
          &[C::generator(), msg.key],
          &[self.enc_keys[&decryptor], *proof.key],
        )
        .map_err(|_| DecryptionError::InvalidProof)?;

      cipher::<C>(self.context, &proof.key).apply_keystream(msg.msg.as_mut().as_mut());
      Ok(msg.msg)
    } else {
      Err(DecryptionError::InvalidProof)
    }
