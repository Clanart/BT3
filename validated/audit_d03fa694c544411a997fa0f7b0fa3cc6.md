### Title
Unrestricted sighash flag on the withdrawer's `user_sig` lets an attacker replace the operator's payout OP_RETURN, permanently starving `PayoutCheckerTask` and freezing the operator's reimbursement path - (File: `core/src/task/payout_checker.rs`, `core/src/database/verifier.rs`, `core/src/builder/transaction/operator_reimburse.rs`, `core/src/operator.rs`)

### Summary
`create_payout_txhandler` builds the payout transaction with a single key-spend input signed by the withdrawer's own `user_sig` (`core/src/builder/transaction/operator_reimburse.rs:407-436`), and nothing in `Operator::withdraw` (`core/src/operator.rs:560-627`) restricts the `sighash_type` embedded in that `taproot::Signature`. If the withdrawer supplies a signature with a non-output-committing sighash flag (e.g. `SIGHASH_NONE`/`ANYONECANPAY` variants), the same signature validly spends the withdrawal UTXO in an alternative transaction that drops or corrupts the OP_RETURN output, and if that variant confirms instead of the honest operator's transaction, `payout_payer_operator_xonly_pk` is written as `NULL`.

### Finding Description
Binding claimed broken: `payout_payer_operator_xonly_pk == honest_operator.xonly_pk` for the withdrawal the operator fronted.

`update_finalized_payouts` (`core/src/verifier.rs:2283-2353`) parses whichever payout transaction actually confirms for a given withdrawal UTXO, extracting the operator xonly pk strictly from the first OP_RETURN output via `parse_op_return_data`/`get_first_op_return_output`; if the OP_RETURN is missing or unparsable, `operator_xonly_pk` becomes `None` and is persisted as SQL `NULL` (`verifier.rs:2319-2323`).

`create_payout_txhandler` (`core/src/builder/transaction/operator_reimburse.rs:407-436`) builds the payout tx with a single `SpendPath::KeySpend` input and finalizes the witness using the caller-supplied `user_sig` (`operator_reimburse.rs:434`). This `user_sig` is a `taproot::Signature`, which encodes its own `sighash_type`; the withdrawer (an unprivileged attacker per the given threat model, who is explicitly granted control over "a Schnorr signature and its sighash flag") produces it off-chain and hands it to the operator. Nothing in `Operator::withdraw` (`core/src/operator.rs:560-627`) checks or fixes this sighash type before it is used to authorize spending. If the signature's sighash flag does not commit to all outputs (e.g. `SIGHASH_NONE` or an `ANYONECANPAY` variant), the same 64-byte signature remains valid for any alternative transaction spending the same input with a different output set — including one that swaps out the operator's OP_RETURN (which carries `operator_xonly_pk`, `operator_reimburse.rs:418`) for a missing or malformed OP_RETURN. Whichever variant gets mined determines the on-chain payout tx that `update_finalized_payouts` later parses.

Once the malicious variant confirms, `get_first_unhandled_payout_by_operator_xonly_pk` (`core/src/database/verifier.rs:282-313`) filters strictly `WHERE payout_payer_operator_xonly_pk = $1`; a `NULL` value never matches any bound `XOnlyPublicKey`, so `PayoutCheckerTask::run_once` (`core/src/task/payout_checker.rs:39-51`) permanently returns `Ok(false)` for that withdrawal, and `handle_finalized_payout`/`mark_payout_handled` are never invoked. Separately, `validate_payer_is_operator` (`core/src/operator.rs:1686-1740`) requires `payer_xonly_pk == self.signer.xonly_public_key` and errors with "Payer info not found for deposit" when `payer_xonly_pk` is `None`, so `get_reimbursement_txs` (`operator.rs:2098-2150`) also permanently fails for this deposit. No existing guard (`is_kickoff_malicious`, `validate_payer_is_operator`, `SECP.verify_schnorr`, or a DB uniqueness constraint) inspects or restricts the sighash type of the payout input's spending signature before it is used, so this divergence is not caught anywhere in the pipeline.

### Impact Explanation
The honest operator fronts BTC to the withdrawing user but ends up with no on-chain data linking that BTC outlay to their operator identity, because the confirmed payout tx's OP_RETURN was swapped out via signature malleability. This permanently blocks that operator's only reachable path to reimbursement for this specific withdrawal — the move-to-vault UTXO's value for the corresponding deposit is frozen from the honest operator's perspective (they fronted BTC but cannot ever trigger `Round -> Kickoff -> ReadyToReimburse -> Reimburse`). This matches "Critical - a move-to-vault UTXO permanently frozen" / "an honest operator permanently unable to be reimbursed." The attack is repeatable per withdrawal by any withdrawer choosing a malicious sighash flag for their own withdrawal signature.

### Likelihood Explanation
Feasibility hinges entirely on whether `Operator::withdraw` or any upstream verification (aggregator-side withdrawal signature check, if any) enforces that the withdrawer's `user_sig` sighash type commits to all outputs. I was unable to locate, within the code inspected, any explicit sighash-type validation on `in_signature` prior to its use in `create_payout_txhandler` in `core/src/operator.rs`. This is a material unknown: if such a check does exist elsewhere (e.g. in signature-verification code paths in `core/src/actor.rs` or citrea-side withdrawal signature validation not fully reviewed here), the vulnerability does not exist. The attacker cost is minimal (their own withdrawal fee/relay fee to race a competing transaction), and it is fully repeatable across withdrawals/operators if the underlying sighash gap is real.

### Recommendation
Reject withdrawal/payout signatures whose `sighash_type` does not commit to all outputs (require `SIGHASH_DEFAULT`/`SIGHASH_ALL`, non-`ANYONECANPAY`) before constructing or broadcasting the payout transaction in `Operator::withdraw`. Additionally, treat a confirmed payout tx with a `NULL`/malformed OP_RETURN for a withdrawal that already has a known committed operator (e.g., via off-chain withdrawal record) as an anomaly requiring manual/operator-side recovery rather than silent permanent starvation.

### Proof of Concept
Not conclusively reproducible without confirming the missing sighash-type check; the following `cargo test` would validate or falsify the finding:
1. In a regtest e2e harness (`core/src/test/deposit_and_withdraw_e2e.rs` style), perform a deposit and call `withdraw` with an `in_signature` whose `sighash_type` is `SIGHASH_NONE | ANYONECANPAY` (or similar non-committing type) instead of `SIGHASH_DEFAULT`.
2. Confirm whether `Operator::withdraw` accepts it (asserting no error is currently returned for non-default sighash types).
3. If accepted, construct and broadcast an alternative transaction spending the same withdrawal input with the same signature but with the OP_RETURN output stripped/corrupted; confirm it via `rpc.mine_blocks`.
4. Loop `PayoutCheckerTask::run_once` for the honest operator with a timeout and assert it always returns `Ok(false)`.

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// For a deposit_id checks that the payer for that deposit is the operator, and the payout blockhash and kickoff txid are set.
    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

        tracing::info!(
            "Payer xonly pk, payout blockhash and kickoff txid found and valid for own operator for the requested deposit id: {}, payer xonly pk: {:?}, payout blockhash: {:?}, kickoff txid: {:?}",
            deposit_id,
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid
        );

        Ok((payout_blockhash, kickoff_txid))
    }
