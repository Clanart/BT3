### Title
Debt on assets not held as collateral is silently valued at zero in `get-notional-evaluation`, reachable via `collateral-remove` - (File: mainnet/contracts/market/v0-4-market.clar)

### Summary
`collateral-remove`'s has-debt branch prices a position by calling `get-assets(position-mask)` and folding `get-notional-evaluation` over the returned asset list [1](#0-0) . `get-assets` derives that list solely from the collateral-range bits of the mask via `mask-to-list-collateral`, which only inspects bit positions 0–63 [2](#0-1) [3](#0-2) . Any asset for which the user has a debt bit but no collateral bit (position 64+asset-id set, position asset-id not set — the normal state for "I borrowed USDC but only deposited STX") is invisible to that asset list, so `calculate-asset-notional-value` never runs for it and its scaled debt contributes `u0` to `debt-total` [4](#0-3) .

### Finding Description
The vault's `debt` bit is set independently of the `collateral` bit for the same asset id (`mask-pos asset-id false` = `DEBT-OFFSET + asset-id`) [5](#0-4) , and `debt-add-scaled` sets only the debt-range bit, never requiring the matching collateral bit [6](#0-5) . `get-position` correctly retrieves the full debt list regardless of the enabled mask (it hardcodes `MAX-U128` for the debt lookup) [7](#0-6) , so `has-debt` in `collateral-remove` is a true indicator that debt rows exist [8](#0-7) .

Once inside the has-debt branch, however, the code resolves prices/asset metadata via `get-assets(position-mask)`, which internally calls `mask-to-list-collateral` on the (enabled-masked) position mask, scanning only bit offsets 0–63 [2](#0-1) [3](#0-2) [9](#0-8) . Debt-range bits (64+asset-id) are outside this scan and are never turned into asset entries. `get-notional-evaluation` then folds `calculate-asset-notional-value` only over that truncated `assets` list [10](#0-9) . Inside the fold, `debt-notional` for a given asset is only computed when that asset's entry appears in `assets` (the fold iterates `assets`, not `debt-list`) [4](#0-3) . Consequently, any debt on an asset the user did not also enable as collateral is completely excluded from `debt-total`, i.e. priced as `u0`.

The resulting `debt-value` is then used directly in the health checks: `is-healthy collateral-value debt-value current-ltvb` and the disabled/enabled collateral branches in `collateral-remove` [11](#0-10) . Since real debt is invisible to these checks, a user who borrows an asset without also holding it as collateral can withdraw all of their actual collateral while their real, uncounted debt remains outstanding — no gate downstream (round-up, slippage bound, oracle freshness check) inspects the raw debt-list independent of the `assets` resolution, so nothing recovers the omission before funds move.

### Impact Explanation
Debt is undervalued to zero for any asset borrowed without matching collateral enablement, which is the ordinary "borrow asset A against collateral B" case in a lending market. The attacker (borrower) profits by extracting collateral that should have been locked against outstanding debt, while the protocol/lenders absorb the shortfall — direct theft of user/protocol funds at rest, matching Critical severity (theft of funds / protocol insolvency).

### Likelihood Explanation
No privileged access or unusual capital is required: any ordinary user who borrows asset A while collateralizing only with asset B (a completely standard money-market usage pattern) puts their position into the vulnerable state. The exploit is reachable through the public, unprivileged `collateral-remove` entrypoint [12](#0-11)  and is repeatable by any account with an open borrow.

### Recommendation
Build the `assets` list passed into `get-notional-evaluation` from the union of collateral-range and debt-range bits of the position mask (i.e., resolve assets for both `mask-to-list-collateral` and `mask-to-list-debt`), or have `get-notional-evaluation`/`calculate-asset-notional-value` fold over the union of `collateral-list` and `debt-list` asset ids rather than over the externally-supplied `assets` array alone, ensuring every debt row is matched to a priced asset entry regardless of whether the user also holds that asset as collateral.

### Proof of Concept
On a local Clarinet/vitest simnet fork:
1. Enable two assets in `v0-assets`/`v0-egroup` (e.g. STX as collateral-only-usable, USDC as debt-usable), with correct price feeds.
2. As an unprivileged account: `collateral-add` STX only (no USDC collateral).
3. `debt-add`/borrow USDC against the STX collateral (sets debt bit at `DEBT-OFFSET + USDC-id`, no collateral bit for USDC).
4. Call `get-position` on the account and confirm `debt` list contains the USDC row.
5. Call `get-assets(position-mask)` directly (or trace `collateral-remove`) and confirm the returned asset list omits USDC (only STX present) because `mask-to-list-collateral` only scans bits 0–63.
6. Call `get-notional-evaluation` with that position/assets pair and assert `debt-total = u0` despite nonzero USDC scaled debt.
7. Call `collateral-remove` to withdraw all STX collateral; assert it succeeds (`is-healthy` passes with `debt-value = 0`) even though real USDC debt remains outstanding — demonstrating direct extraction of collateral that should be locked against debt.
