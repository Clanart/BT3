### Title
stSTXbtc collateral/debt is priced using the STX/USD feed instead of BTC/USD, mispricing a BTC-denominated asset — (File: `mainnet/contracts/utility/v0-1-data.clar`)

### Summary
In `get-asset-price`, the branches for `stSTXbtc` and `zstSTXbtc` are commented as returning "BTC price" but actually call `get-pyth-price PYTH-STX` (the STX/USD feed) instead of `get-pyth-price PYTH-BTC`. This is the same class of bug as the reference report: a branch is checked/labeled for one category (BTC) but the code path executes for a different, wrong one (STX), producing an incorrect valuation for the asset in question.

### Finding Description
`get-asset-price` resolves a price per asset id through a long `if/is-eq` chain [1](#0-0) . For `stSTXbtc`, the comment explicitly states "BTC price (liquid staked STX with BTC yield)", yet the code fetches `PYTH-STX`, the STX/USD Pyth feed, not `PYTH-BTC`: [2](#0-1) 

The bug is repeated for the wrapped/z-token variant `zstSTXbtc`, which multiplies a variable literally named `btc-price` by the liquidity index, but that "btc-price" is itself computed from `PYTH-STX`: [3](#0-2) 

For contrast, every other BTC-denominated branch in the same function correctly calls `PYTH-BTC` (e.g. `sBTC` and `zsBTC`): [4](#0-3) [5](#0-4) 

This is a "price attached to the wrong asset" defect: `get-asset-price` is the function consumed to compute collateral notional value and debt notional value for health/LTV checks, per the sibling market contract pattern shown in `calculate-asset-notional-value` [6](#0-5) , so an incorrect feed here directly corrupts collateral valuation used for borrow/liquidation health.

### Impact Explanation
STX/USD and BTC/USD are uncorrelated price series that move independently. If `stSTXbtc`/`zstSTXbtc` collateral value is computed from the STX price rather than the BTC price:
- When BTC price > STX price (the normal case, BTC trades at a much higher unit price than STX), the mispriced collateral is dramatically undervalued or overvalued depending on which direction STX has moved relative to BTC, producing an incorrect health/LTV verdict.
- If STX price is used and happens to be higher (in relative terms) than the true BTC-based value at a given moment, users can borrow more against `stSTXbtc`/`zstSTXbtc` collateral than the asset is actually worth, up to protocol insolvency for that vault — a direct theft/undercollateralized-borrowing vector.
- Conversely, if STX price is lower than true BTC value, positions can be wrongly deemed unhealthy and liquidated at a loss to depositors — a form of unfair fund freezing/loss for legitimate holders.
Given the asset is explicitly documented as BTC-yield-bearing, this mispricing directly satisfies the in-scope "wrong health verdict" / "price attached to the wrong asset" impact category, landing in the **Critical** (protocol insolvency / theft of collateral value) impact class.

### Likelihood Explanation
This triggers on every single valuation of `stSTXbtc` or `zstSTXbtc` collateral or debt — there is no special precondition, external manipulation, or DAO action required; it is a deterministic, always-on logic error reachable by any user holding or borrowing against this asset. Likelihood is high.

### Recommendation
Change the `stSTXbtc` and `zstSTXbtc` branches in `get-asset-price` to call `get-pyth-price PYTH-BTC` instead of `get-pyth-price PYTH-STX`, matching the comment and matching the pattern used for `sBTC`/`zsBTC`. Additionally, add a regression test asserting that `stSTXbtc` pricing tracks the BTC feed and diverges from the STX feed under a synthetic price divergence, and audit `v0-4-market.clar`'s oracle-id/callcode configuration for this asset for the same mismatch.

### Proof of Concept
1. Register/observe `stSTXbtc` as collateral for a borrow position.
2. Set the Pyth STX/USD feed price high (or observe a period where STX/USD > true BTC-equivalent value of stSTXbtc) while BTC/USD is comparatively low.
3. Call `get-asset-price(stSTXbtc-aid)` — observe it returns a value equal to the STX/USD price (scaled), not a BTC/USD-derived value, per [2](#0-1) .
4. Use this inflated (STX-based) valuation as collateral to borrow other assets up to the erroneously computed LTV — funds borrowed exceed the true BTC-denominated collateral value, extracting value from the protocol/other depositors.
