### Title
Unbounded `governance.removevalidator` header-vote can collapse the qualified validator set below quorum, halting consensus - (File: kaiax/valset/impl/getter_council.go)

### Summary
`applyVote` (invoked from `ValsetModule.applyBlock`) processes `governance.removevalidator` header votes and unconditionally removes any listed, non-governing-node address from the council, with no lower bound on the resulting council/committee size [3](#0-2) . This mirrors the reported `CollateralManager.removeCollateral()` pattern: a single privileged removal action (a governance vote from the governing node) can instantaneously and severely degrade a health-determining ratio — here, the qualified-validator-to-committee-size ratio that determines consensus quorum — without any guard checks.

### Finding Description
The `kaiax/valset` module derives the block committee/quorum from the "qualified validators," which is `Council(N) - DemotedValidators(N)`, and `Council(N)` is built incrementally by applying `governance.addvalidator`/`governance.removevalidator` votes recorded in `header.Vote` [4](#0-3) . `RemoveValidator`'s parameter definition uses `validatorAddressListCanonicalizer` and `noopFormatChecker`, meaning the vote value (an arbitrary list of addresses) is accepted with no bound on the number of addresses, and no check relates it to current council size [5](#0-4) .

`applyVote` then removes every valid address from the council in a loop, the only exclusions being the governing node and addresses not already in the council [6](#0-5) . Consensus quorum and fault tolerance are computed directly from the resulting qualified/committee size: `calcQuorumSize`/`calcFaultTolerance` in `consensus/istanbul/core/core.go` and `Quorum`/`F` in `consensus/istanbul/sealer.go` scale down proportionally as the effective size shrinks [7](#0-6) [8](#0-7) . If a single epoch's votes from the governing node remove enough validators (e.g., down to 1 or a small set below the previously configured `istanbul.committeesize`), the "effective committee" and quorum collapse abruptly for the very next block, analogous to a trove's ICR going to zero when its sole collateral type is removed. Unlike the post-Permissionless path, which explicitly guards against leaving zero active validators (`applyEpochTransition` retains the previous active set if none would remain) [9](#0-8) , the pre-Permissionless `applyVote` path used by `RemoveValidator` has no analogous protection.

### Impact Explanation
A sudden reduction of the qualified/council set changes the quorum size (`ceil(2N/3)`) and fault tolerance (`ceil(N/3)-1`) discontinuously between consecutive blocks [7](#0-6) . If the removal is large relative to the remaining honest/available validators, this can strand in-flight rounds that were sized for the old committee, or make the required quorum unreachable if too many of the surviving addresses are offline, stalling block production (a liveness/availability failure analogous to the report's "multiple troves liquidated / recovery mode triggered" cascading effect). This is reachable purely through the standard governance-vote path (no separate contract-migration/guard mechanism exists for the header-vote removal path), matching the report's core complaint that removal lacks guard checks against protocol-health collapse.

### Likelihood Explanation
This requires a valid vote from the governing node (single-mode governance) or GC quorum (none-mode), which is the documented, expected mechanism for validator set changes and is a "governance parameters" surface explicitly in scope. No malicious peer/validator behavior or out-of-scope privilege is required beyond the intended governance actor invoking the already-documented `governance_vote`/`RemoveValidator` capability with an oversized or unchecked address list.

### Recommendation
Add a guard, analogous to the Permissionless-era `applyEpochTransition` protection, to the pre-Permissionless `applyVote`/`applyBlock` path: reject or partially apply a `RemoveValidator` vote if it would reduce the qualified council below `istanbul.committeesize` (or some safe minimum, e.g., enough to sustain `f >= 1`). Alternatively, validate the vote's cardinality against current council size at ratification time in `kaiax/gov` (`FormatChecker` for `RemoveValidator`) rather than accepting any address list unconditionally.

### Proof of Concept
1. Assume `istanbul.committeesize = 13` and a council of 20 validators under `single` governance mode.
2. The governing node casts a `governance.removevalidator` vote in one epoch listing 18 non-governing-node addresses (all but itself and one other), which passes `NewVoteData`'s canonicalizer/`noopFormatChecker` unchanged [1](#0-0) .
3. At the next epoch's `applyBlock`/`applyVote`, all 18 addresses are removed from the council with no size check [6](#0-5) .
4. `getRoundCommitteeState`/`calcQuorumSize` now compute quorum and fault tolerance over an effective size of 2, drastically different from the prior size of 20 [10](#0-9) , potentially halting consensus if the remaining validators are unavailable or disagree, with no on-chain safeguard preventing this drastic, sudden change from a single governance vote.

// applyVote modifies the given council *in-place* by the validator vote in the given header.
// governingNode, if specified, is not affected by the vote.
// Returns true if the council is modified, false otherwise.
func applyVote(header *types.Header, council *valset.AddressSet, governingNode common.Address) bool {
	voteKey, addresses, ok := parseValidatorVote(header)
	if !ok {
		return false
	}

	originalSize := council.Len()
	for _, address := range addresses {
		if address == governingNode {
			continue
		}
		switch voteKey {
		case gov.AddValidator:
			if !council.Contains(address) {
				council.Add(address)
			}
		case gov.RemoveValidator:
			if council.Contains(address) {
				council.Remove(address)
			}
		}
	}
	return originalSize != council.Len()
}

func getRoundCommitteeState(c *core, seq, r uint64) (qualified *valset.AddressSet, committeeSet *valset.AddressSet, proposer common.Address, committeeSize uint64, requiredMsgCnt int, fNum int, err error) {
	if c.valsetModule == nil || c.govModule == nil {
		return nil, nil, common.Address{}, 0, 0, 0, istanbul.ErrNoEssentialModule
	}
	council, err := c.valsetModule.GetCouncil(seq)
	if err != nil {
		return nil, nil, common.Address{}, 0, 0, 0, err
	}
	demoted, err := c.valsetModule.GetDemotedValidators(seq)
	if err != nil {
		return nil, nil, common.Address{}, 0, 0, 0, err
	}
	// NOTE: don't use GetQualifiedValidators here because it duplicates the logic of GetDemotedValidators.
	qualified = valset.NewAddressSet(council).Subtract(valset.NewAddressSet(demoted))
	committeeAddrs, err := c.valsetModule.GetCommittee(seq, r)
	if err != nil {
		return nil, nil, common.Address{}, 0, 0, 0, err
	}
	proposer, err = c.valsetModule.GetProposer(seq, r)
	if err != nil {
		return nil, nil, common.Address{}, 0, 0, 0, err
	}
	committeeSet = valset.NewAddressSet(committeeAddrs)
	committeeSize = uint64(committeeSet.Len())

	qLen := qualified.Len()
	requiredMsgCnt = calcQuorumSize(qLen, committeeSize)
	fNum = calcFaultTolerance(qLen, committeeSize)
	return qualified, committeeSet, proposer, committeeSize, requiredMsgCnt, fNum, nil
}

// calcQuorumSize returns the minimum number of messages required to proceed (QBFT quorum).
// qualifiedLen is the number of qualified validators, committeeSize is the committee size.
// For less than 4 validators, quorum size equals the effective size;
// otherwise it is ceil(2 * min(qualifiedLen, committeeSize) / 3).
func calcQuorumSize(qualifiedLen int, committeeSize uint64) int {
	size := min(qualifiedLen, int(committeeSize))
	if size < 4 {
		return size
	}
	return int(math.Ceil(float64(2*size) / 3))
}

func calcFaultTolerance(qualifiedLen int, committeeSize uint64) int {
	if qualifiedLen > int(committeeSize) {
		return int(math.Ceil(float64(committeeSize)/3)) - 1
	}
	return int(math.Ceil(float64(qualifiedLen)/3)) - 1
}

	if qualifiedLen > int(committeeSize) {

	}

// Quorum returns the quorum: ceil(2N/3) over the effective size
// N = min(qualifiedlen, committeeSize), or N for tiny committees. This matches
// calcQuorumSize used by the consensus core.
// Pre-permissionless sealer quorum: 2f+1
func (m *IstanbulSealer) Quorum(_ uint64, qualifiedlen, committeeSize int) int {
	n := min(qualifiedlen, committeeSize)
	if n < 4 {
		return n
	}
	return int(math.Ceil(float64(2*n) / 3))
}
