### Title
`emergencyWithdraw` in `MasterMagpie` does not sync/reduce the user's balance in the base reward pool, letting withdrawn users keep earning pool rewards - (File: rewards/MasterMagpie.sol)

### Summary
`MasterMagpie.emergencyWithdraw` follows the same bug pattern as the referenced GoGoPool `recordStakingError` finding: an accounting counter/balance that is supposed to reflect a user's active stake is left un-decremented on an exit path, letting the user retain reward eligibility/weight they should no longer have.

### Finding Description
In the normal withdrawal flow, `_withdraw` → `_harvestAndUnstake` explicitly harvests MGP and calls `_harvestBaseRewarder(_stakingToken, _account)` before reducing `user.amount`/`user.available`, ensuring the external base reward pool (e.g. `BaseRewardPoolV2`/`BribeRewardPool`) is kept in sync with the user's real staked balance: [1](#0-0) 

By contrast, `emergencyWithdraw` only zeroes `user.available`/`user.amount` inside `MasterMagpie`'s own `userInfo` mapping and transfers the staking token back to the user, but never calls `_harvestBaseRewarder` (or any equivalent call into the base reward pool to reduce the user's balance there): [2](#0-1) 

Because reward pools such as `BaseRewardPoolV2`/`BribeRewardPool` maintain their own independent `_balances[_account]`/`totalSupply` state that is only updated via explicit `stakeFor`/`withdrawFor` calls from the operator (`MasterMagpie`): [3](#0-2) 

skipping this call in `emergencyWithdraw` leaves the user's balance entry in the reward pool unchanged even though they have already withdrawn their principal staking token from `MasterMagpie`. This is directly analogous to `MinipoolManager.recordStakingError` failing to call `staking.decreaseMinipoolCount`, leaving a stale accounting value that continues to grant rewards/eligibility that should have been revoked.

### Impact Explanation
Because `_balances` in the reward pool is not reduced, the withdrawn user continues to accrue and can later claim a share of the pool's reward emissions (`rewardPerToken` is computed off `totalSupply`/`_balances`) as if their tokens were still staked. This inflates the reward-weight denominator incorrectly relative to actual staked funds and results in theft of unclaimed yield from other legitimate stakers in that reward pool, since the emergency-withdrawn user keeps drawing a portion of rewards they are no longer entitled to.

### Likelihood Explanation
`emergencyWithdraw` is a normal, unprivileged, user-callable function (only gated by `whenPaused`, which is an operational/pause state, not an admin-permissioned call on the caller side) that any staker can invoke at any time the contract is paused, which is an expected operational scenario (e.g., during upgrades or incident response). No special privileges are required to trigger the mismatch.

### Recommendation
Have `emergencyWithdraw` call `_harvestBaseRewarder(_stakingToken, msg.sender)` (or an equivalent `withdrawFor` call to the pool's rewarder) before/while zeroing `user.available`/`user.amount`, so that the external reward pool's `_balances`/`totalSupply` stay consistent with the user's actual remaining stake, mirroring the fix pattern of decreasing the stale counter recommended in the referenced report.

### Proof of Concept
1. User deposits staking token via `MasterMagpie.deposit`, which increases both `userInfo[_stakingToken][user].amount` and the corresponding base reward pool's `_balances[user]` (via the normal deposit/harvest flow).
2. Contract owner pauses `MasterMagpie` (`whenPaused` modifier allows `emergencyWithdraw`).
3. User calls `emergencyWithdraw(_stakingToken)`. Per [4](#0-3) , `user.available` and `user.amount` in `MasterMagpie` are zeroed and the staking token is transferred back to the user — but `_harvestBaseRewarder` is never invoked.
4. The base reward pool's `_balances[user]` and `totalSupply` remain unchanged, so the user still shows up as an active staker with full balance in `BaseRewardPoolV2`/`BribeRewardPool` per [5](#0-4) .
5. When rewards for that pool are later distributed/claimed (`getReward`/`_getReward`), the emergency-withdrawn user is still entitled to a proportional share of rewards despite holding no actual stake, diluting/stealing yield that should accrue solely to genuine remaining stakers.

```text
    /// @notice Withdraw all available tokens without caring about rewards. EMERGENCY ONLY. 
    ///         Locked Token can not be emergent withdraw.
    /// @param _stakingToken Staking token of the pool
    /// @dev withdrawFor of the rewarder with the third param at false is an emergency withdraw
    function emergencyWithdraw(address _stakingToken) external whenPaused {
        PoolInfo storage pool = tokenToPoolInfo[_stakingToken];
        UserInfo storage user = userInfo[_stakingToken][msg.sender];
        uint256 availableaAmount = user.available;
        user.available = 0;
        IERC20(pool.stakingToken).safeTransfer(address(msg.sender), availableaAmount);
        emit EmergencyWithdraw(msg.sender, _stakingToken, availableaAmount);
        user.amount = user.amount - availableaAmount;
        user.rewardDebt = (user.amount * pool.accMGPPerShare) / 1e12;
    }
```

```text
    function _harvestAndUnstake(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        updatePool(_stakingToken);

        UserInfo storage user = userInfo[_stakingToken][_account];

        if (!_isVlMgp && user.available < _amount)
            revert WithdrawAmountExceedsStaked();
        else if(user.amount < _amount && _isVlMgp)
            revert UnlockAmountExceedsLocked();
        
        _harvestMGP(_stakingToken, _account);
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount - _amount;
        
        if(!_isVlMgp)
            user.available = user.available - _amount;
        user.rewardDebt = (user.amount * tokenToPoolInfo[_stakingToken].accMGPPerShare) / 1e12;
```

```text
        external
        virtual
        onlyOperator
        updateRewards(_for, rewardTokens)

        totalSupply = totalSupply + _amount;
        _balances[_for] = _balances[_for] + _amount;

    /// @notice Updates informaiton for a user in case of a withdraw. Can only be called by the Masterchief operator
    /// @param _for Address account
    /// @param _amount Amount of withdrawed tokens by the user on masterchief
    function withdrawFor(
        address _for,
        uint256 _amount,
        bool claim
    ) external virtual onlyOperator updateRewards(_for, rewardTokens) {
        totalSupply = totalSupply - _amount;
        _balances[_for] = _balances[_for] - _amount;

        emit Withdrawn(_for, _amount);

        if (claim) {
            _getReward(_for);
        }
    }
```
