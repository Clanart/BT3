### Title
DLEq proofs over an empty generator set verify successfully, allowing vacuous proof forgery - ([File: crypto/dleq/src/lib.rs](crypto/dleq/src/lib.rs))

### Summary

`DLEqProof::verify` accepts an empty `generators`/`points` pair because it only checks that their lengths are equal before deriving the challenge. A proof can therefore be created without proving knowledge of any discrete logarithm and still pass verification. [1](#0-0) 

### Finding Description

The verifier rejects mismatched statement lengths, but does not reject zero statements. [2](#0-1)  With empty inputs, no `verify_statement` calls occur; the transcript contains only the `dleq` domain separator, and verification succeeds when the supplied `c` equals the resulting deterministic challenge. [3](#0-2) 

The prover has the same issue: `DLEqProof::prove` permits an empty generator slice and computes `s = c * scalar + r` even though no relation involving `scalar` is ever committed. [4](#0-3)  Thus, an arbitrary scalar can be used to produce a proof that verifies successfully while proving nothing.

The proof can also enter through untrusted bytes because `DLEqProof::read` deserializes the two public scalars without enforcing that the proof corresponds to at least one statement. [5](#0-4) 

### Impact Explanation

A caller that uses `DLEqProof::verify` as an authorization or consistency check can accept a forged proof for an empty statement list. This is analogous to the missing-authorization scheduler write: an attacker-controlled object passes the security check and reaches downstream state-changing logic despite having demonstrated no secret knowledge. [1](#0-0) 

### Likelihood Explanation

The vulnerability is reachable whenever untrusted callers can cause verification with empty `generators` and `points` vectors, including through a decoded `DLEqProof` supplied to the public `verify` API. [6](#0-5)  The proof is deterministic and computable without knowing any discrete logarithm, so exploitation requires no cryptanalytic work or privileged position.

### Recommendation

Reject empty statement vectors in both `prove` and `verify` before applying the transcript domain separator or computing the challenge. The verifier should require `generators.len() == points.len()` and `!generators.is_empty()`, while `prove` should similarly assert that at least one generator was supplied. [7](#0-6) 

### Proof of Concept

From `crypto/dleq/src/lib.rs`:

```rust
use zeroize::Zeroizing;
use transcript::RecommendedTranscript;
use dleq::DLEqProof;
use k256::{ProjectivePoint, Scalar};

let mut rng = rand_core::OsRng;
let mut prover_transcript = RecommendedTranscript::new(b"example");

// An arbitrary scalar works because the proof commits to no generators/points.
let arbitrary_scalar = Zeroizing::new(Scalar::ONE);
let proof = DLEqProof::<ProjectivePoint>::prove(
    &mut rng,
    &mut prover_transcript,
    &[],
    &arbitrary_scalar,
);

let mut verifier_transcript = RecommendedTranscript::new(b"example");
assert!(proof.verify(&mut verifier_transcript, &[], &[]).is_ok());
```

The proof verifies despite committing to no generator or point because the iteration over paired statements never executes and only the challenge comparison remains. [8](#0-7) [3](#0-2)

  pub fn prove<R: RngCore + CryptoRng, T: Transcript>(
    rng: &mut R,
    transcript: &mut T,
    generators: &[G],
    scalar: &Zeroizing<G::Scalar>,
  ) -> DLEqProof<G> {
    let r = Zeroizing::new(G::Scalar::random(rng));

    transcript.domain_separate(b"dleq");
    for generator in generators {
      // R, A
      Self::transcript(transcript, *generator, *generator * r.deref(), *generator * scalar.deref());
    }

    let c = challenge(transcript);
    // r + ca
    let s = (c * scalar.deref()) + r.deref();

    DLEqProof { c, s }
  }

  // Transcript a specific generator/nonce/point (G/R/A), as used when verifying a proof.
  // This takes in the generator/point, and then the challenge and solution to calculate the nonce.
  fn verify_statement<T: Transcript>(
    transcript: &mut T,
    generator: G,
    point: G,
    c: G::Scalar,
    s: G::Scalar,
  ) {
    // s = r + ca
    // sG - cA = R
    // R, A
    Self::transcript(transcript, generator, (generator * s) - (point * c), point);
  }

  /// Verify the specified points share a discrete logarithm across the specified generators.
  pub fn verify<T: Transcript>(
    &self,
    transcript: &mut T,
    generators: &[G],
    points: &[G],
  ) -> Result<(), DLEqError> {
    if generators.len() != points.len() {
      Err(DLEqError::InvalidProof)?;
    }

    transcript.domain_separate(b"dleq");
    for (generator, point) in generators.iter().zip(points) {
      Self::verify_statement(transcript, *generator, *point, self.c, self.s);
    }

    if self.c != challenge(transcript) {
      Err(DLEqError::InvalidProof)?;
    }

    Ok(())
  }

  /// Write a DLEq proof to something implementing Write.
  #[cfg(feature = "serialize")]
  pub fn write<W: Write>(&self, w: &mut W) -> io::Result<()> {
    w.write_all(self.c.to_repr().as_ref())?;
    w.write_all(self.s.to_repr().as_ref())
  }

  /// Read a DLEq proof from something implementing Read.
  #[cfg(feature = "serialize")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<DLEqProof<G>> {
    Ok(DLEqProof { c: read_scalar(r)?, s: read_scalar(r)? })
  }
