### Title
`ThresholdView` `Debug` implementation leaks secret interpolation coefficients, scalar, and offset to logs - (File: crypto/dkg/src/lib.rs)

### Summary
`ThresholdView<C>` implements `fmt::Debug` manually and explicitly serializes the `interpolation`, `scalar`, and `offset` fields. `Interpolation::Constant` is a `Vec<F>` of field elements that are the secret coefficients (the per-participant secret shares themselves when `t == n`), and it derives `Debug`. Any `{:?}` / `debug!("{view:?}")` / error formatting of a `ThresholdView` therefore writes secret key material into log output — the same bug class as CVE-2025-12910 (sensitive information exposed via debug logs), but with direct private-key-share disclosure rather than incidental metadata.

### Finding Description
In `crypto/dkg/src/lib.rs`, `ThresholdView` deliberately redacts `secret_share` via `finish_non_exhaustive()`, showing the author intended the `Debug` impl to be safe — yet it leaks equivalently sensitive fields: [1](#0-0) 

- `interpolation`: `Interpolation<F>` is `#[derive(Debug)]` at `crypto/dkg/src/lib.rs:211`, and `Interpolation::Constant(Vec<F>)` holds one secret scalar coefficient per key share (`crypto/dkg/src/lib.rs:219`). For `t == n` keys (the only case `Constant` is permitted, enforced at `crypto/dkg/src/lib.rs:369-371`), these constants are exactly the secret shares used to compute each participant's effective key (`interpolation_factor` indexes `c[i-1]` at `crypto/dkg/src/lib.rs:228`). Logging a `ThresholdView` for a constant-interpolated key prints all secret shares in the clear.
- `scalar` / `offset`: these are ephemeral secret linear-combination terms applied on top of the secret share (`scale`/`offset` at `crypto/dkg/src/lib.rs:400-417`). With the group key public, `scalar * share + offset` is trivially recoverable for anyone who also learns a single signature share or the share itself; printing them leaks part of the private state used to derive child/tweaked keys.

The FROST view is produced by `ThresholdKeys::view`, i.e. it exists on every signing operation, so the leak is on the hot path of every threshold signature.

### Impact Explanation
An attacker with read access to logs (a local unprivileged process, a log aggregation pipeline, or crash/error reporting that formats the view) recovers:
- all secret coefficients under `Interpolation::Constant`, equivalent to the full set of secret shares → complete private key reconstruction for `t == n` keys;
- the secret `scalar`/`offset` tweaks → recovery of tweaked/derived private keys from any corresponding signature share.

This is unambiguous secret-key material disclosure, satisfying the "key share recovery" acceptance criterion.

### Likelihood Explanation
No malicious protocol participant is required: the exposure occurs whenever `ThresholdView` is formatted with `{:?}` — in tracing/logging, panic messages, `unwrap_err`/`expect` formatting on error types embedding it, or `assert!` failure messages. The processor/coordinator crates log extensively via `info!`/`debug!` (e.g., `processor/src/key_gen.rs`, `processor/src/multisigs/mod.rs`), so any downstream formatting of a view reaches persistent logs readable by local parties. Likelihood is moderate-to-high in any deployment with debug logging enabled and well above "informational" because the leaked bytes are the shares themselves.

### Recommendation
Remove `interpolation`, `scalar`, and `offset` from the `Debug` impl, or print only non-secret metadata (e.g., `group_key`, `included`):

```rust
// crypto/dkg/src/lib.rs, impl fmt::Debug for ThresholdView<C>
fmt
  .debug_struct("ThresholdView")
  .field("group_key", &self.group_key)
  .field("included", &self.included)
  .finish_non_exhaustive()
```

Additionally, do not derive `Debug` on `Interpolation<F>` (or manually implement it to redact the `Constant` vector), and audit `SecretShareMachine`'s Debug and `Encryption`'s Debug in `crypto/dkg/pedpop/src/lib.rs:285-295` / `crypto/dkg/pedpop/src/encryption.rs` for the same class.

### Proof of Concept
```rust
// Conceptual: any constant-interpolated ThresholdView logged via Debug
let params = ThresholdParams::new(2, 2, Participant::new(1).unwrap()).unwrap();
let interpolation = Interpolation::Constant(vec![secret_a, secret_b]); // secret scalars
let keys = ThresholdKeys::new(params, interpolation, secret_share, verification_shares).unwrap();
let view = keys.view(included_set).unwrap();
log::debug!("signing view: {view:?}");
// Output contains: interpolation: Constant([<secret_a>, <secret_b>]),
//                  scalar: <scalar>, offset: <offset>
// => all secret shares for a 2-of-2 key written to logs verbatim
```
