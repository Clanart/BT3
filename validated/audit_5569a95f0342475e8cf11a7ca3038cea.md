## Title
Missing path-traversal/symlink-escape guard in `getResolutionDiff` allows reading files outside the repository — ([File: app/src/lib/git/diff.ts])

### Summary
`getResolutionDiff` in [1](#0-0)  builds the "base" side of a Copilot-conflict-resolution diff by doing `readFile(Path.join(repository.path, filePath), 'utf8')` directly, using `filePath` values that come straight from `WorkingDirectoryFileChange.path` / merge-conflict status entries — i.e., data whose on-disk resolution is controlled by the content of a repository the user cloned, fetched, or merged. No traversal/symlink check is applied at this call site, unlike the two other places in the same feature that consume the identical kind of untrusted conflict path and explicitly guard it with `resolveWithin`.

### Finding Description
The app already recognizes this exact bug class and defends against it in two sibling code paths that consume conflicted-file paths from the working directory:

- `buildConflictContext` resolves each conflicted file path with `resolveWithin(workingDirectory, file.path)` before reading it, explicitly commenting "Guard against path traversal and symlink escapes (cross-platform)": [2](#0-1) 
- `app-store.ts`'s Copilot-resolution write path does the same before writing resolved content back to disk: [3](#0-2) 

`resolveWithin` (in `app/src/lib/path.ts`) resolves the path and then calls `realpath` on both the root and the resolved path, rejecting anything whose real, symlink-resolved location falls outside the repository root — this is the only defense that actually stops symlink-based directory-escape attacks, since a plain `Path.join`/`Path.normalize` on a relative git path (which git already forbids from containing literal `..` components) says nothing about intermediate path components that are themselves symlinks pointing outside the repo. [4](#0-3) 

`getResolutionDiff`, however, is called from the "Changes" tab of the Copilot conflict-resolution dialog with the very same `file.path` values (sourced from `conflictedFiles`/`WorkingDirectoryFileChange`) and skips this guard entirely: [5](#0-4)  and [6](#0-5) .

Because a conflicted working-tree entry can be, or be nested under, a symlink that a malicious merge/branch checked out (git tracks and checks out symlinks as ordinary blobs with mode `120000`, and a symlink whose target is `/` or `..` is perfectly valid git content), an attacker who gets the victim to merge/checkout a branch containing such a symlink can cause the seemingly repo-relative conflict path to resolve, via Node's `fs.readFile` (which follows symlinks), to an arbitrary location on the victim's filesystem.

### Impact Explanation
The content read from outside the repository is used as `oldContents` for the diff, is fed into `writeFile(tempBase, ...)` for `git diff --no-index`, and is ultimately rendered/exposed to the user (and to file-content buffers used by syntax highlighting) inside the Copilot conflict-resolution "Changes" view — i.e., an out-of-repo file read/disclosure whose content is surfaced back into the application UI. Depending on what the symlink targets (SSH keys, `.netrc`, other repositories' credential files, etc.), this can leak sensitive local files. This matches the "file read...outside the repo" category of valid impact, driven purely by an attacker-controlled cloned/merged repository, with no local access or social engineering beyond the normal act of merging/reviewing a branch.

### Likelihood Explanation
Reaching this code requires the user to be in an active merge/conflict state involving a maliciously crafted branch that includes a symlink component and to open the Copilot conflict-resolution dialog for the file behind that symlink — a plausible workflow for anyone reviewing/merging PRs or branches from untrusted collaborators, since Desktop's conflict UI and Copilot resolution feature are specifically designed to be used while resolving merges from external content. It requires no elevated privileges, no prior compromise, and no unusual steps beyond normal merge-conflict handling.

### Recommendation
Route `filePath` through `resolveWithin(repository.path, filePath)` in `getResolutionDiff` (mirroring `copilot-conflict-context.ts` and `app-store.ts`) before calling `readFile`, and treat a `null` result (path escapes the repository) as an error/skip condition rather than reading it.

### Proof of Concept
1. Attacker prepares a branch where a tracked entry `link` is a symlink (mode `120000`) pointing to `/` (or to a sensitive directory such as the user's home directory), and includes a conflicting file at `link/secret_target` that will produce a merge conflict against the victim's branch.
2. Victim fetches/merges this branch in Desktop, producing a conflict whose `WorkingDirectoryFileChange.path` is `link/secret_target`.
3. Victim opens the Copilot Conflict Resolution dialog's "Changes" tab for that file, which calls `getResolutionDiff(repository, 'link/secret_target', ...)`.
4. `Path.join(repository.path, 'link/secret_target')` resolves through the on-disk symlink `link` to `/secret_target` (or wherever the symlink points), and `readFile` returns the *external* file's contents, which are then diffed and rendered in the UI — disclosing content outside the repository.

```typescript
async function _resolveWithin(
  rootPath: string,
  pathSegments: string[],
  options: {
    join: (...pathSegments: string[]) => string
    normalize: (p: string) => string
    resolve: (...pathSegments: string[]) => string
  } = Path
) {
  // An empty root path would let all relative
  // paths through.
  if (rootPath.length === 0) {
    return null
  }

  const { join, normalize, resolve } = options

  const normalizedRoot = normalize(rootPath)
  const normalizedRelative = normalize(join(...pathSegments))

  // Null bytes has no place in paths.
  if (
    normalizedRoot.indexOf('\0') !== -1 ||
    normalizedRelative.indexOf('\0') !== -1
  ) {
    return null
  }

  // Resolve to an absolute path. Note that this will not contain
  // any directory traversal segments.
  const resolved = resolve(normalizedRoot, normalizedRelative)

  const realRoot = await realpath(normalizedRoot)
  const realResolved = await realpath(resolved)

  return realResolved.startsWith(realRoot) ? resolved : null
```
