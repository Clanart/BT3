### Title
`aptos move verify-package` never compares on-chain compiled bytecode, only self-reported metadata, allowing "verified" packages to run bytecode unrelated to the shown/compiled source - (File: aptos-move/cli/src/stored_package.rs)

### Summary
The CLI's `verify-package` command is documented and named as if it cryptographically confirms that the bytecode running on-chain matches a local compilation of the claimed source. In reality, `CachedPackageMetadata::verify()` only diff-checks `PackageMetadata` fields (name, deps, `modules` records, manifest, upgrade policy, extension, `source_digest`) and never fetches or compares actual on-chain compiled module bytes against the bytes produced by the local build.

### Finding Description
`VerifyPackage::execute` builds the package locally, extracts `compiled_metadata`, downloads the on-chain `PackageRegistry` via `CachedPackageRegistry::create(client, self.account, false)` — note the `with_bytecode` argument is `false` — and calls `package.verify(&compiled_metadata)`. [2](#0-1) 

`CachedPackageRegistry::create` only populates `self.bytecode` (actual `.mv` module bytes fetched via `client.get_account_module`) when `with_bytecode` is `true`; here it's always `false`, so `self.bytecode` stays empty. [3](#0-2) 

`verify()` then only compares `PackageMetadata` struct fields — `name`, `deps`, `modules`, `manifest`, `upgrade_policy`, `extension`, `source_digest` — between the on-chain metadata and the locally compiled metadata. None of these fields is the actual compiled bytecode; `ModuleMetadata` only carries `name`, `source` (gzipped source text, publisher-supplied), `source_map`, and `extension`. [4](#0-3) [5](#0-4) 

On-chain, `code::publish_package` and the native `request_publish`/`request_publish_with_allowed_deps` only bind metadata to bytecode by module *name* matching (`expected_modules.remove(m.self_id().name()...)` in `validate_publish_request`), never by hashing the metadata's `source`/`source_map` fields against the actual `CompiledModule` bytes being published. [6](#0-5) [7](#0-6) 

Because both the metadata's `source` text and the deployed bytecode are fully attacker-controlled and never cryptographically tied together by the protocol, a publisher can submit metadata whose `source`/`source_digest` correspond to an innocuous Move source tree while shipping a completely different (malicious) compiled bytecode bundle in the same transaction. A reviewer who runs `aptos move verify-package --account <attacker>` after locally building that same innocuous source will get "Successfully verified source of package" even though the bytecode actually executing on-chain does not correspond to the "verified" source at all.

### Impact Explanation
This breaks the core code-safety invariant the tool advertises: "verify that the bytecode matches a local compilation" (per `third_party/move/documentation/book/src/cli-deploy.md`). [8](#0-7)  Users, auditors, and integrators relying on this command to gain trust in an on-chain package (e.g., before depending on it, integrating with it, or granting it capabilities) can be misled into believing arbitrary malicious bytecode is safe/audited source, when the tool never actually inspected the deployed bytecode. This is a real trust/verification bypass tied to the publish/verification flow, not a cosmetic issue.

### Likelihood Explanation
High likelihood of triggering under normal usage: any attacker who wants to pass off malicious bytecode as reviewed/open-source code can do so unconditionally — the mismatch requires no race condition, no privileged access, and no on-chain enforcement gap beyond what already exists (metadata `source` is always self-reported and unchecked against bytecode). The only work required is constructing a transaction with mismatched `metadata_serialized`/`code` bundles, which the framework's `publish_package_txn` accepts as long as module names match.

### Recommendation
- Make `CachedPackageRegistry::create` in `verify-package`'s flow always fetch bytecode (`with_bytecode = true`), and extend `CachedPackageMetadata::verify()` to fetch and byte-compare each on-chain module (`get_bytecode`) against the freshly compiled module bytes from the local `BuiltPackage`.
- Consider requiring/optionally storing a hash of compiled bytecode in `ModuleMetadata` (or deriving/checking it against `source_digest`) so the protocol itself can enforce a binding between claimed source and deployed code, closing the gap rather than relying solely on client tooling.

### Proof of Concept
1. Attacker crafts package `evil`: `Move.toml`/source files describe an innocuous module `m` (e.g., "hello world").
2. Attacker compiles a *different*, malicious bytecode file for module `m` by hand (or via a modified/malicious compiler), keeping the module's fully-qualified name identical to `m`.
3. Attacker builds `metadata_serialized` (via `BuiltPackage::extract_metadata`) from the innocuous source tree (yielding a genuine `source_digest`/`source` for the benign code), but submits the malicious compiled bytecode as `code` in the same `publish_package_txn`/`object_code_deployment::publish` call. On-chain validation (`validate_publish_request`) only checks that the published `CompiledModule`'s self name (`m`) is registered in `expected_modules` — it never checks that the bytecode corresponds to `metadata.modules[0].source`. [9](#0-8) 
4. A reviewer downloads the innocuous source, compiles it locally, and runs `aptos move verify-package --account <attacker>`. `VerifyPackage::execute` compares only metadata fields (never bytecode, since `with_bytecode=false`), and the innocuous source's compiled metadata matches the on-chain metadata's `source`/`source_digest`/etc., so the command prints `"Successfully verified source of package"`. [10](#0-9) 
5. The reviewer now believes the malicious bytecode is the audited innocuous code, when in fact different bytecode is executing at that address.

    pub fn verify(&self, package_metadata: &PackageMetadata) -> anyhow::Result<()> {
        let self_metadata = self.metadata;

        if self_metadata.name != package_metadata.name {
            bail!(
                "Package name doesn't match {} : {}",
                package_metadata.name,
                self_metadata.name
            )
        } else if self_metadata.deps != package_metadata.deps {
            bail!(
                "Dependencies don't match {:?} : {:?}",
                package_metadata.deps,
                self_metadata.deps
            )
        } else if self_metadata.modules != package_metadata.modules {
            bail!(
                "Modules don't match {:?} : {:?}",
                package_metadata.modules,
                self_metadata.modules
            )
        } else if self_metadata.manifest != package_metadata.manifest {
            bail!(
                "Manifest doesn't match {:?} : {:?}",
                package_metadata.manifest,
                self_metadata.manifest
            )
        } else if self_metadata.upgrade_policy != package_metadata.upgrade_policy {
            bail!(
                "Upgrade policy doesn't match {:?} : {:?}",
                package_metadata.upgrade_policy,
                self_metadata.upgrade_policy
            )
        } else if self_metadata.extension != package_metadata.extension {
            bail!(
                "Extensions doesn't match {:?} : {:?}",
                package_metadata.extension,
                self_metadata.extension
            )
        } else if self_metadata.source_digest != package_metadata.source_digest {
            bail!(
                "Source digests doesn't match {:?} : {:?}",
                package_metadata.source_digest,
                self_metadata.source_digest
            )
        }

        Ok(())
    }

fn native_request_publish(
    context: &mut SafeNativeContext,
    _ty_args: &[Type],
    mut args: VecDeque<Value>,
) -> SafeNativeResult<SmallVec<[Value; 1]>> {
    debug_assert!(matches!(args.len(), 4 | 5));
    let with_allowed_deps = args.len() == 5;

    context.charge(CODE_REQUEST_PUBLISH_BASE)?;

    let policy = safely_pop_arg!(args, u8);
    let mut code = vec![];
    for module in safely_pop_arg!(args, Vec<Value>) {
        let module_code = module.value_as::<Vec<u8>>()?;

        context.charge(CODE_REQUEST_PUBLISH_PER_BYTE * NumBytes::new(module_code.len() as u64))?;
        code.push(module_code);
    }

    let allowed_deps = if with_allowed_deps {
        let mut allowed_deps: BTreeMap<AccountAddress, BTreeSet<String>> = BTreeMap::new();

        for dep in safely_pop_arg!(args, Vec<Value>) {
            let (account, module_name) = unpack_allowed_dep(dep)?;

            let entry = allowed_deps.entry(account);

            if let Entry::Vacant(_) = &entry {
                // TODO: Is the 32 here supposed to indicate the length of an account address in bytes?
                context.charge(CODE_REQUEST_PUBLISH_PER_BYTE * NumBytes::new(32))?;
            }

            context
                .charge(CODE_REQUEST_PUBLISH_PER_BYTE * NumBytes::new(module_name.len() as u64))?;
            entry.or_default().insert(module_name);
        }

        Some(allowed_deps)
    } else {
        None
    };

    let mut expected_modules = BTreeSet::new();
    for name in safely_pop_arg!(args, Vec<Value>) {
        let str = get_move_string(name)?;

        // TODO(Gas): fine tune the gas formula
        context.charge(CODE_REQUEST_PUBLISH_PER_BYTE * NumBytes::new(str.len() as u64))?;
        expected_modules.insert(str);
    }

    let destination = safely_pop_arg!(args, AccountAddress);

    // Add own modules to allowed deps
    let allowed_deps = allowed_deps.map(|mut allowed| {
        allowed
            .entry(destination)
            .or_default()
            .extend(expected_modules.clone());
        allowed
    });

    let code_context = context.extensions_mut().get_mut::<NativeCodeContext>();
    if code_context.requested_module_bundle.is_some() || !code_context.enabled {
        // Can't request second time or if publish requests are not allowed.
        return Err(SafeNativeError::abort(EALREADY_REQUESTED));
    }
    code_context.requested_module_bundle = Some(PublishRequest {
        destination,
        bundle: ModuleBundle::new(code),
        expected_modules,
        allowed_deps,
        check_compat: policy != ARBITRARY_POLICY,
    });

## `aptos move verify-package`

Build the package locally and verify that the on-chain copy matches.

```shellscript filename="Terminal"
aptos move verify-package --account 0xABC...123
```

| Flag | Meaning |
|---|---|
| `--account <ADDR>` | Address of the on-chain package to verify against. |
| `--included-artifacts <none\|sparse\|all>` | Match what was used at publish time. |

A package published with `upgrade_policy = "arbitrary"` cannot be verified — its content can change at any time, so the verifier refuses to depend on it.
