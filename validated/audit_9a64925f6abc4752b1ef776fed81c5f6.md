### Title
Unanchored string removal of commit trailers can silently corrupt the message body during commit amend - (`File: app/src/models/commit.ts`)

### Summary
`Commit.bodyNoCoAuthors` is derived by calling `trimCoAuthorsTrailers`, which removes each `Co-Authored-By` trailer from the raw commit body using a literal, unanchored `String.prototype.replace()` call rather than validating/matching the trailer's actual position at the end of the message. [1](#0-0) 
This mirrors the Aave bug class: a variable-length, attacker-influenced value (`value`) is spliced into a broader "field" (the commit body) without validating that it corresponds to the intended, bounded location, allowing it to corrupt unrelated content.

### Finding Description
`extractCoAuthors`/`trimCoAuthorsTrailers` are invoked unconditionally in the `Commit` constructor for every commit parsed from a cloned/fetched repository's history: [2](#0-1) 
`trimCoAuthorsTrailers` builds the exact literal text `${token}: ${value}` (e.g. `Co-Authored-By: Evil Name <a@b.com>`) from a `Co-Authored-By` trailer parsed out of the commit's trailing trailer block, and calls `body.replace(literal, '')`. `String.replace` with a string argument replaces only the **first** occurrence of that literal substring in `body`, and it is not anchored to the end of the message where trailers actually live. If the attacker (who fully controls the content of a commit they push/host and that the victim clones or fetches) crafts a commit body that contains that exact literal text earlier in the body — e.g. as quoted/reproduced text, a code block, or a decoy paragraph — before the real trailer at the very end, the replace call strips the wrong occurrence. The real trailer line at the end is left untouched in `bodyNoCoAuthors`, while unrelated content earlier in the body is silently deleted.

`bodyNoCoAuthors` is the text Desktop shows and prepopulates in the commit message editor when the user amends/re-commits (co-authors are re-added as structured UI chips and reappended as trailers on the next commit). There is no length/position validation ensuring the removed substring actually is the trailing trailer instance — the exact analog of Aave's missing bit-length check before packing a value into a fixed field, letting an unchecked value bleed into and corrupt an unrelated part of the structure.

### Impact Explanation
This can silently corrupt the message body of a commit the user amends and pushes: content the user never intended to delete disappears from the body, and/or the literal, unstripped `Co-Authored-By:` line remains duplicated in the final commit message once the trailer is regenerated. Because this happens purely from cloning/fetching an attacker-authored commit and clicking "amend" in Desktop's normal UI flow, it satisfies the "silent corruption of what the user commits or pushes" impact class without requiring local access, elevated privileges, or social engineering beyond the ordinary act of cloning/fetching a repo and using Desktop's amend feature.

### Likelihood Explanation
The attacker needs no special access — any public commit they push to any branch/PR the victim fetches is sufficient, and the crafted commit only needs a body that reproduces the literal trailer text earlier in the message (a plausible, low-effort construction, e.g. quoting a previous commit message as changelog text). The victim needs to amend that specific commit through Desktop's UI, which is a standard workflow, not an "unnatural user step." No existing guard checks that the matched/removed substring is the one located in the trailing trailer block; `String.replace` with a literal will happily match an earlier decoy string.

### Recommendation
Do not use a literal substring match to trim trailers from a body. Instead, verify the trailer text appears at the trailing trailer block (e.g., only strip from the tail of the body, matching the same trailer parsing/positions used by `git interpret-trailers`/`parseRawUnfoldedTrailers`), or use the trailer's known start offset returned by trailer parsing rather than an ad hoc string search, so that untrusted body content earlier in the message can never be matched instead of the real trailer.

### Proof of Concept
1. Attacker creates and pushes a commit whose body is:
```
Note: earlier reviewers used the line
Co-Authored-By: Evil Name <a@b.com>
as an example format.

Some real explanation text.

Co-Authored-By: Evil Name <a@b.com>
```
2. Victim clones/fetches the repository containing this commit in GitHub Desktop and selects "Amend commit" on it.
3. `trimCoAuthorsTrailers` calls `body.replace('Co-Authored-By: Evil Name <a@b.com>', '')`, which removes the **first** ("Note: earlier reviewers…" example line context), not the actual trailing trailer.
4. The commit-message editor now shows a body missing the "Note: earlier reviewers…" content but still containing the literal trailing `Co-Authored-By:` line, and/or a duplicated trailer is produced when Desktop reappends the extracted co-author — corrupting the message the user amends and subsequently pushes, without any warning. function extractCoAuthors(trailers: ReadonlyArray<ITrailer>) {
  const coAuthors = []

  for (const trailer of trailers) {
    if (isCoAuthoredByTrailer(trailer)) {
      const author = GitAuthor.parse(trailer.value)
      if (author) {
        coAuthors.push(author)
      }
    }
  }

  return coAuthors
}

function trimCoAuthorsTrailers(
  trailers: ReadonlyArray<ITrailer>,
  body: string
) {
  let trimmedCoAuthors = body

  trailers.filter(isCoAuthoredByTrailer).forEach(({ token, value }) => {
    trimmedCoAuthors = trimmedCoAuthors.replace(`${token}: ${value}`, '')
  })

  return trimmedCoAuthors
}
