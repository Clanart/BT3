## Confirmed root cause

The `Payout` transaction's `KeySpend` witness only covers the single input (the withdrawal dust UTXO) via `SIGHASH_SINGLE|ANYONECANPAY` (`Ensure the signature uses SinglePlusAnyoneCanPay sighash type` at [1](#0-0) ). `SIGHASH_SINGLE|ANYONECANPAY` only commits the signer to input #0 and output #0 — it does **not** commit to output #2, the `OP_RETURN` output that carries the attributed `operator_xonly_pk` ( [2](#0-1) ). Any unprivileged party holding the user's off-chain-provided signature can therefore construct and broadcast their own `Payout` transaction directly to Bitcoin — bypassing every operator's `withdraw`/`InternalWithdraw` RPC entirely — while writing an arbitrary honest operator's `xonly_pk` into the `OP_RETURN` output.

On the verifier side, `update_finalized_payouts` blindly trusts this attacker-controlled `OP_RETURN` field as the "payer" attribution with no signature or authorization check: [3](#0-2) 

This value is persisted as `payout_payer_operator_xonly_pk` ( [4](#0-3) ) and later read back by `validate_payer_is_operator`, which only checks that the DB-recorded payer equals `self.signer.xonly_public_key` — it never re-validates that the named operator actually funded the payout output: [5](#0-4) 

## Binding broken

The intended equality is: **operator credited for reimbursement == operator whose funds actually left an operator-controlled UTXO to fulfill the withdrawal**. An attacker can make this false: *operator credited (victim, chosen from OP_RETURN) ≠ party that paid (attacker's own wallet, spending the pre-signed dust UTXO)*.

### Title
Unauthenticated attribution of `Payout` transactions lets any party frame an honest operator for reimbursement it never funded - (File: core/src/builder/transaction/operator_reimburse.rs, core/src/verifier.rs)

### Summary
The `Payout` transaction is signed by the withdrawing user with `SIGHASH_SINGLE|ANYONECANPAY`, which only commits to the withdrawal input and the user's payout output, not to the third output (`OP_RETURN` carrying `operator_xonly_pk`). Verifiers use this unsigned field as the sole source of truth to decide which operator "fronted" the withdrawal, and that operator is later automatically dispatched a kickoff/reimbursement obligation for a payment they never made.

### Finding Description
1. `create_payout_txhandler` builds the payout tx with inputs/outputs where only input 0 is signed by the user via `set_p2tr_key_spend_witness`, and the signature type must be `SinglePlusAnyoneCanPay` per the check in `Operator::withdraw` ( [1](#0-0) ). Because of `ANYONECANPAY`, anyone possessing the withdrawal UTXO's signature (given to operators, but transmitted off-chain to fulfil the withdrawal) can rebuild the transaction with a *different* set of outputs/fee, including a forged `op_return_txout(operator_xonly_pk)` ( [2](#0-1) ), and directly broadcast it to the Bitcoin network — no operator RPC call is required at all.
2. When this transaction confirms, `Verifier::update_finalized_payouts` extracts the operator identity purely from the `OP_RETURN` bytes with no cryptographic binding to who actually paid: [3](#0-2) .
3. This attacker-chosen `operator_xonly_pk` is written to `withdrawals.payout_payer_operator_xonly_pk` via `update_payout_txs_and_payer_operator_xonly_pk` ( [4](#0-3) ).
4. `Operator::validate_payer_is_operator`, invoked from `get_reimbursement_txs`/`handle_finalized_payout`, only compares the stored payer key to the local operator's own key — it treats the DB value as ground truth ( [5](#0-4) , [6](#0-5) ). The named (victim) operator's automation, or the operator itself via `GetReimbursementTxs`, will then proceed through Round → Kickoff → Reimburse, ultimately spending its `MoveToVaultTx` deposit output to its own `reimburse_addr` ( [7](#0-6) ) for a withdrawal it never funded.

The custody binding "operator reimbursed == operator that paid the withdrawal" is broken because the attribution mechanism (`OP_RETURN`) is not covered by any signature and is not gated behind a privileged/authenticated call.

### Impact Explanation
This matches the Critical bucket "an operator reimbursed for a payout it never funded": an unprivileged attacker can (a) steal the reimbursement path away from the operator that actually should be entitled to it (denial of legitimate reimbursement / misattribution) and (b) force an arbitrary named operator into an unwanted kickoff/challenge cycle for a payment it did not make, consuming that operator's round/kickoff slot and collateral cycle without their consent, and potentially causing the named operator to be reimbursed (to their own address) for BTC they never spent — an inflation of that operator's claim against the vault relative to funds they actually fronted.

### Likelihood Explanation
High likelihood given only two black-box preconditions, both satisfiable by any external party: (1) obtain the user's off-chain withdrawal signature (which must be shared with operators anyway to service the withdrawal, and its `ANYONECANPAY` type is a documented requirement, not a mistake) and (2) craft/broadcast a standard Bitcoin transaction — no verifier/operator/aggregator privilege, no key compromise, and no interaction with any Clementine RPC is required.

### Recommendation
Bind the `OP_RETURN` operator attribution to the actual signer/funder of the payout transaction cryptographically, e.g. by requiring the operator to co-sign the full transaction (covering the `OP_RETURN` output) with `SIGHASH_ALL` for their own leg, or by deriving the payer attribution from which operator's `tx_sender`/wallet actually broadcast/funded the transaction rather than trusting an unauthenticated `OP_RETURN` payload. At minimum, `update_finalized_payouts` should reject/ignore `OP_RETURN` attributions that cannot be tied to a verifiable, operator-signed commitment.

### Proof of Concept
1. User requests a withdrawal and gives an operator (or leaks) the `SIGHASH_SINGLE|ANYONECANPAY` signature over the withdrawal dust UTXO, along with the desired payout output.
2. Attacker (any party, not a listed operator) builds a `Payout`-shaped transaction using `create_payout_txhandler`-equivalent logic: input = the dust UTXO with the leaked signature, output 0 = user's payout, output 1 = anchor, output 2 = `OP_RETURN` containing victim-operator's `xonly_pk` instead of their own.
3. Attacker broadcasts this transaction directly via Bitcoin RPC (no Clementine RPC call at all).
4. Once finalized, `Verifier::update_finalized_payouts` records `payout_payer_operator_xonly_pk = victim` ( [3](#0-2) ).
5. Victim operator's automation (or manual `GetReimbursementTxs` call) sees itself as the payer in `validate_payer_is_operator` ( [5](#0-4) ) and proceeds to spend its kickoff/round path to reimburse itself for a withdrawal it never paid for.

            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set

            payer_xonly_pk,

                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

        tracing::info!(
            "Payer xonly pk, payout blockhash and kickoff txid found and valid for own operator for the requested deposit id: {}, payer xonly pk: {:?}, payout blockhash: {:?}, kickoff txid: {:?}",
            deposit_id,
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid
        );

        Ok((payout_blockhash, kickoff_txid))
    }

pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())
}

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
