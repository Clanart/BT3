### Title
YAML billion-laughs DoS via unbounded `security-patterns.yaml` parsed with `yaml.safe_load` - ([File: plugins/security-guidance/hooks/extensibility.py])

### Summary
`_read_config` reads a project-committed `security-patterns.yaml`/`.yml` file with no size cap and feeds the raw text directly into `yaml.safe_load`. `yaml.safe_load` prevents arbitrary Python object construction (`!!python/object`), but it does not limit anchor/alias expansion, so a "billion laughs" style payload can still cause exponential memory/CPU blow-up on every hook invocation that loads project config.

### Finding Description
`_load_user_patterns` calls `_read_config(candidate)` for each candidate path returned by `_config_paths(cwd, "security-patterns")`, which includes `<cwd>/.claude/security-patterns.yaml` — a path that is part of the repository and can be introduced by an attacker via a malicious PR/commit [1](#0-0) . `_read_config` reads the entire file into `raw` with no byte cap (unlike the guidance markdown path, which enforces `GUIDANCE_MAX_BYTES`), then, for YAML files, calls `yaml.safe_load(raw)` inside a bare `try/except yaml.YAMLError` [2](#0-1) .

`yaml.safe_load` does correctly restrict tag resolution to a safe subset (so `!!python/object` is rejected, addressing the type-confusion part of the question), but anchors (`&`) and aliases (`*`) are core YAML syntax processed by the composer/constructor regardless of `Loader` class. A classic "billion laughs" payload (nested anchor references, e.g. `a: &a ["x","x",...]`, `b: &b [*a,*a,...]`, repeated ~10 levels) expands to an astronomically large in-memory structure or takes exponential time to construct, even under `safe_load`. Because there is no size limit on `raw` before parsing and no timeout/resource guard around the `yaml.safe_load` call, a small (few-KB) crafted file can hang the process or exhaust memory.

This is reachable in normal Claude Code operation: `load_for_session(cwd)` is called from the hook's `main()` before dispatching on essentially every `PostToolUse` invocation, and it wraps `_load_user_patterns` in a `try/except Exception` [3](#0-2) . That `try/except` only protects against exceptions escaping — it does nothing against a hang (infinite/very long CPU loop) or an out-of-memory condition, both of which do not raise a catchable Python exception in a way that lets the process continue; a large-enough expansion causes the process to be OOM-killed or to block indefinitely, well before any exception handler runs.

### Impact Explanation
An attacker who can land a `.claude/security-patterns.yaml` file into a repository (e.g., via a pull request, as explicitly permitted by the "project, committed" discovery tier) can cause denial-of-service against any developer who runs Claude Code hooks against that checkout: the `security-guidance` PostToolUse hook will attempt to parse the file on effectively every tool invocation, hanging or OOM-crashing the hook process repeatedly. This matches a resource-exhaustion / DoS impact class rather than remote code execution or data exfiltration — it degrades or blocks the security-guidance hook (and potentially the surrounding tool-call flow) for anyone working in that repository.

### Likelihood Explanation
Preconditions are minimal and match the stated attacker model: no special privileges are needed beyond the ability to get a file merged/checked out into the target repository's `.claude/` directory (a normal PR/commit), which is exactly the "project, committed" precedence tier the module documents. The payload is a few lines of standard YAML (no exotic tags), so it is trivial to construct and is fully reproducible on every hook run for that project, not just once.

### Recommendation
- Enforce a byte-size cap (analogous to `GUIDANCE_MAX_BYTES`) on `raw` in `_read_config` before invoking `yaml.safe_load`/`json.loads`.
- Use a YAML loader/constructor that limits alias/anchor expansion depth or total node count (e.g., PyYAML's `Loader` with a custom composer that caps `flatten_mapping`/alias counts, or switch to `yaml.load` with a hardened `SafeLoader` subclass that limits `compose_node` recursion and total constructed size), or reject files containing more than a small number of anchors/aliases via a pre-parse text scan similar to the existing ReDoS heuristic (`_has_redos_structure`).
- Wrap the YAML parse in a hard wall-clock/CPU timeout (e.g., `signal.alarm` on POSIX or a subprocess with a timeout) so a hang cannot block `load_for_session` indefinitely.

### Proof of Concept
Unit test to add near `_read_config`:
```python
def test_read_config_rejects_yaml_bomb(tmp_path):
    payload = "a: &a [\"lol\",\"lol\",\"lol\",\"lol\",\"lol\",\"lol\",\"lol\",\"lol\",\"lol\"]\n"
    for i in range(9):
        payload += f"b{i}: &b{i} [*{'a' if i==0 else f'b{i-1}'}, *{'a' if i==0 else f'b{i-1}'}, *{'a' if i==0 else f'b{i-1}'}, *{'a' if i==0 else f'b{i-1}'}, *{'a' if i==0 else f'b{i-1}'}, *{'a' if i==0 else f'b{i-1}'}, *{'a' if i==0 else f'b{i-1}'}, *{'a' if i==0 else f'b{i-1}'}, *{'a' if i==0 else f'b{i-1}'}]\n"
    f = tmp_path / "security-patterns.yaml"
    f.write_text(payload)

    import multiprocessing, time
    def run(q):
        q.put(_read_config(str(f)))
    q = multiprocessing.Queue()
    p = multiprocessing.Process(target=run, args=(q,))
    p.start()
    p.join(timeout=5)
    assert not p.is_alive(), "yaml.safe_load did not terminate within 5s on billion-laughs payload"
    p.terminate()
```
Expected (failing) behavior today: the subprocess is still alive after the timeout (or memory usage spikes dramatically), demonstrating that `_read_config`/`load_for_session` has no protection against anchor/alias expansion despite using `yaml.safe_load`. A fixed implementation should either raise/return `None` quickly (rejecting the file) or complete within the timeout with bounded memory.

```python
def _config_paths(cwd: Optional[str], basename: str) -> List[Tuple[str, str]]:
    """Existing config file paths, lowest precedence first (so concat reads in
    precedence order user → project → project-local). Truncation is done on
    the concatenated string, so lowest-precedence content is dropped last."""
    paths = [("User", os.path.expanduser(os.path.join("~", ".claude", basename)))]
    if cwd:
        paths.append(("Project", os.path.join(cwd, ".claude", basename)))
        # claude-security-guidance.local.md / security-patterns.local.yaml
        stem, ext = os.path.splitext(basename)
        paths.append(("Project (local)", os.path.join(cwd, ".claude", f"{stem}.local{ext}")))
    return paths
```

```python
def _read_config(path: str) -> Optional[Dict[str, Any]]:
    """Read a YAML or JSON config file. Returns None on missing/malformed."""
    try:
        with open(path, encoding="utf-8") as f:
            raw = f.read()
    except OSError:
        return None
    if not raw.strip():
        return None
    if path.endswith(".json"):
        try:
            return json.loads(raw)
        except ValueError as e:
            debug_log(f"extensibility: skipping {path}: invalid JSON: {e}")
            return None
    # YAML: import lazily so the hook works without PyYAML (JSON still works).
    try:
        import yaml  # type: ignore
    except ImportError:
        debug_log(f"extensibility: skipping {path}: PyYAML not installed (use .json)")
        return None
    try:
        return yaml.safe_load(raw)
    except yaml.YAMLError as e:  # type: ignore
        debug_log(f"extensibility: skipping {path}: invalid YAML: {e}")
        return None
```
