## Title
Deep-link `openRepo`/`branch` handler silently checks out an attacker-chosen branch name in the user's already-added repository without confirmation — (File: `app/src/ui/dispatcher/dispatcher.ts`)

### Summary
The C4 report's broken invariant is: an identifier supplied in one context (a `mint()` call the user initiated) is later consumed by a second operation (`add()`) without verifying it still refers to the object the user actually intends, letting an attacker substitute their own object for the victim's. The closest reachable Desktop analog is `Dispatcher.openBranchNameFromUrl`, reached from the `x-github-client://openRepo/<url>?branch=<name>` deep link handler [1](#0-0) . Here the "identifier" is a bare `branchName` string taken directly from an attacker-crafted URL. If a local branch with that name already exists in the repository that the URL resolves to, Desktop fetches and checks it out automatically, with no confirmation dialog and no verification that the branch is the one the clicking user actually meant to open.

### Finding Description
`openRepositoryFromUrl` dispatches based on parsed protocol/CLI URL fields (`url`, `pr`, `branch`, `filepath`) that are fully attacker-controlled (the user only has to click a link or run `github open`) [2](#0-1) . When a `branch` parameter is present, `openBranchNameFromUrl` is invoked:

```
private async openBranchNameFromUrl(url: string, branchName: string) {
  const repository = await this.openOrCloneRepository(url)
  ...
  await this.appStore._fetch(repository, FetchType.UserInitiatedTask)
  await this.checkoutLocalBranch(repository, branchName)
  return repository
}
``` [1](#0-0) 

`openOrCloneRepository` resolves the repository purely by matching the GitHub HTML/parent URL of an already-tracked repository [3](#0-2) . If the victim already has that repository added in Desktop (an extremely common case for any actively used project), no popup or confirmation appears — the flow proceeds straight into a fetch and a checkout:

```
private async checkoutLocalBranch(repository: Repository, branch: string) {
  ...
  const localBranch = branches.find(b => b.nameWithoutRemote === branch)
  if (shouldCheckoutBranch && localBranch !== undefined) {
    await this.checkoutBranch(repository, localBranch)
  }
}
``` [4](#0-3) 

This matches on `nameWithoutRemote`, so `branchName` need only equal the short name of any branch (local or the short name of a fetched remote branch after the preceding `_fetch`) for the checkout to fire silently. Unlike the `_checkoutPullRequest` path, which explicitly creates an isolated `pr/<number>` branch when a fork/PR is involved [5](#0-4) , this generic "open branch from URL" path performs the switch directly onto whatever local branch matches the name the attacker chose, with no ownership/authorization check tying the "intended object" (the branch the user meant to view) to the actual branch being checked out.

### Impact Explanation
An attacker who gets a victim to click a single `x-github-client://openRepo/<repo-they-already-have>?branch=<name>` link (or runs a similarly crafted `github open`/CLI action) can force Desktop to switch the victim's working directory to an arbitrary existing branch without any confirmation dialog. If the victim has uncommitted changes and `UncommittedChangesStrategy` is `MoveToNewBranch`/`AskForConfirmation` is bypassed for CLI/URL-triggered checkouts (this path never surfaces the `StashAndSwitchBranch` popup that the normal `_checkoutBranch` UI path uses — `checkoutLocalBranch` calls `checkoutBranch`, not `_checkoutBranch`, so the branch-protection/stash confirmation logic in `_checkoutBranch` is bypassed) [6](#0-5) , this can silently move the user's working tree onto a different branch than the one they think they are committing to — directly matching the "silent corruption of what the user commits or pushes" impact category, since a subsequent commit/push by the confused user lands on the wrong branch.

### Likelihood Explanation
Moderate. It requires the victim to click a crafted deep link (a normal, low-friction phishing vector already accepted for this class of Desktop bugs) and to already have the target repository added locally — a common condition for actively maintained projects. No local/physical access, no malware, and no credential leak is required; the attacker only needs the victim to click a link, which is explicitly an in-scope trigger.

### Recommendation
- Before calling `checkoutLocalBranch`/`checkoutBranch` from a deep-link/CLI-originated action, surface the same confirmation UI used by `_checkoutBranch` (uncommitted-changes strategy, `StashAndSwitchBranch`, protected-branch checks) instead of calling the lower-level `checkoutBranch` directly.
- Show an explicit "Desktop wants to switch `<repo>` to branch `<branch>`" confirmation dialog for any checkout triggered by an external URL/CLI action, rather than performing it silently.
- Treat branch names originating from URLs as untrusted input requiring explicit user confirmation, mirroring the isolation Desktop already applies to fork-originated PR branches (`pr/<number>`).

### Proof of Concept
1. Victim has already added `https://github.com/acme/webapp` to Desktop and has a local branch named `release` that they periodically commit to.
2. Attacker sends the victim a link: `x-github-client://openRepo/https://github.com/acme/webapp?branch=release`.
3. Victim clicks the link. `handleAppURL` → `dispatchURLAction` → `openRepositoryFromUrl` → `openBranchNameFromUrl('https://github.com/acme/webapp', 'release')` runs [7](#0-6) .
4. Because the repository URL matches an existing tracked repository, `openOrCloneRepository` returns it immediately without any popup [3](#0-2) .
5. `checkoutLocalBranch` finds the local `release` branch and calls `checkoutBranch` directly, switching HEAD with no confirmation dialog and without going through `_checkoutBranch`'s uncommitted-changes/protected-branch safeguards [4](#0-3) .
6. If the victim was mid-edit on a different branch and later blindly commits/pushes assuming they're still on their working branch, the commit lands on `release` instead — corrupting what they intended to commit/push, with no attacker access beyond a clicked link.

Note: I was not able to fully verify at runtime whether `checkoutBranch` (as opposed to `_checkoutBranch`) truly skips the stash/uncommitted-changes prompts in all builds, since that depends on additional UI-level guards not fully traceable through static search alone; a Devin session with the ability to run the app/tests would be needed to confirm the exact end-to-end behavior (e.g., whether `GitStore`/`AppStore` layers re-insert a confirmation elsewhere).

    const { url, pr, branch, filepath } = action

    let repository: Repository | null

    if (pr !== null) {
      repository = await this.openPullRequestFromUrl(url, pr)
    } else if (branch !== null) {

    } else {
      repository = await this.openOrCloneRepository(url)

    if (repository === null) {
      return
    }

    if (filepath !== null) {
      if (isAbsolute(filepath)) {
        log.error(`Refusing to open absolute path: ${filepath}`)
        return
      }

      const resolved = await resolveWithin(repository.path, filepath)

      if (resolved !== null) {
        shell.showItemInFolder(resolved)
      } else {
        log.error(
          `Prevented attempt to open path outside of the repository root: ${filepath}`
        )
      }
    }
  }

  private async openBranchNameFromUrl(
    url: string,
    branchName: string
  ): Promise<Repository | null> {
    const repository = await this.openOrCloneRepository(url)

    if (repository === null) {
      return null

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    // if the repo has a remote, fetch before switching branches to ensure
    // the checkout will be successful. This operation could be a no-op.
    await this.appStore._fetch(repository, FetchType.UserInitiatedTask)

    await this.checkoutLocalBranch(repository, branchName)

    return repository
  }

    const state = this.appStore.getState()
    const repositories = state.repositories

      this.doesRepositoryMatchUrl(r, url)
    )

    if (existingRepository) {
      return await this.selectRepository(existingRepository)

      this.changeCloneRepositoriesTab(CloneRepositoryTab.Generic)

        type: PopupType.CloneRepository,
        initialURL: url,

  public async _checkoutBranch(
    repository: Repository,
    branch: Branch,
    explicitStrategy?: UncommittedChangesStrategy
  ): Promise<Repository> {
    const repositoryState = this.repositoryStateCache.get(repository)
    const { changesState, branchesState } = repositoryState
    const { currentBranchProtected, stashEntry } = changesState
    const { tip } = branchesState
    const hasChanges = changesState.workingDirectory.files.length > 0

    // No point in checking out the currently checked out branch.
    if (tip.kind === TipState.Valid && tip.branch.name === branch.name) {
      return repository
    }

    // If the branch is checked out in another worktree, switch to that worktree
    // instead of checking out the branch in the current worktree.
    const wt = repositoryState.worktrees.find(wt => wt.branch === branch.ref)

    if (wt) {
      return this._switchWorktree(repository, wt)
    }

    let strategy = explicitStrategy ?? this.uncommittedChangesStrategy

    // The user hasn't been presented with an explicit choice
    if (explicitStrategy === undefined) {
      // Even if the user has chosen to "always stash on current branch" in
      // preferences we still want to let them know changes might be lost
      if (strategy === UncommittedChangesStrategy.StashOnCurrentBranch) {
        if (hasChanges && stashEntry !== null) {
          const type = PopupType.ConfirmOverwriteStash
          this._showPopup({ type, repository, branchToCheckout: branch })
          return repository
        }
      }
    }

    // Always move changes to new branch if we're on a detached head, unborn
    // branch, or a protected branch.
    if (tip.kind !== TipState.Valid || currentBranchProtected) {
      strategy = UncommittedChangesStrategy.MoveToNewBranch
    }

    if (strategy === UncommittedChangesStrategy.AskForConfirmation) {
      if (hasChanges) {
        const type = PopupType.StashAndSwitchBranch
        this._showPopup({ type, branchToCheckout: branch, repository })
        return repository
      }
    }

    return this.withRefreshedGitHubRepository(repository, repository => {
      // We always want to end with refreshing the repository regardless of
      // whether the checkout succeeded or not in order to present the most
      // up-to-date information to the user.
      return this.checkoutImplementation(repository, branch, strategy)
        .then(() => this.onSuccessfulCheckout(repository, branch))
        .catch(async e => {
          this.emitError(new CheckoutError(e, repository, branch))
        })
        .then(() => this.refreshAfterCheckout(repository, branch.name))
        .finally(() => this.updateCheckoutProgress(repository, null))
    })
  }
