### Title
Unprivileged Bitcoin senders can hijack internal offset addresses, causing outputs to be misclassified and pending forwarding instructions to be deleted - (networks/bitcoin/src/wallet/mod.rs)

### Summary
GLPI CVE-2026-42318 lets a low-privilege user delete an arbitrary object because an endpoint maps an attacker-supplied identifier to an object without checking ownership. The Serai analog lives in the Bitcoin scanner: `Scanner` matches outputs solely by `script_pubkey` against a `HashMap<ScriptBuf, Scalar>` of registered offsets, and `get_outputs` then derives the `OutputType` (`External`, `Branch`, `Change`, `Forwarded`) purely from which offset's script matched. The Branch/Change/Forwarded offsets are deterministic (`hash_to_F(KEY_DST, b"branch" | b"change" | b"forward")`), so any unprivileged on-chain party can compute and pay to these internal addresses. The processor then trusts the derived `kind` and, for `Forwarded` outputs, calls `ForwardedOutputDb::take_forwarded_output(txn, output.balance())` — deleting a stored `InInstruction` keyed only by amount — and for `Branch`/`Change` kinds silently drops the deposit via `outputs.retain(|o| o.kind() == OutputType::External)`. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`Scanner::scan_transaction` pushes a `ReceivedOutput` whenever `self.scripts.get(&output.script_pubkey)` hits, with no distinction between an output that *the protocol itself* created (a change output, a forwarded output) and an output an arbitrary third party sent to the same address. `get_outputs` in `processor/src/networks/bitcoin.rs` maps the matched offset back to an `OutputType` via `kinds[offset_repr]` and assigns `presumed_origin`/`data` only to `External` outputs. An attacker-controlled transaction therefore produces an `Output` whose `kind` is attacker-selected among `Branch`/`Change`/`Forwarded` simply by paying to `p2tr_script_buf(key + G*offset)` for the publicly derivable offsets in `scanner()` (lines 333-344). Downstream in `scanner_event_to_multisig_event`, a `Forwarded` output triggers `ForwardedOutputDb::take_forwarded_output(txn, output.balance())` — a delete of a pending instruction keyed by `(balance)` — letting the attacker choose *which* stored instruction is consumed by choosing the amount, exactly the "attacker-chosen identifier deletes an arbitrary object" shape of the GLPI bug. Non-`External` attacker outputs are then dropped by the `retain` filter. [4](#0-3) [5](#0-4) 

### Impact Explanation
Two impacts: (1) An attacker who sends coins to the Change or Branch script_pubkey produces an output the multisig controls but which is classified `Change`/`Branch` and filtered out before ever becoming an `External` instruction — real funds received on-chain that the processor never credits or spends (funds reported in the wallet yet unspendable through the protocol). (2) An attacker who sends to the Forwarded script_pubkey with a chosen amount causes `take_forwarded_output` to remove and bind a stored `InInstruction` that belongs to a *different*, legitimately forwarded output whose amount collides — deleting that pending instruction and mis-associating its `refund_to`/data with the attacker's output, so the original forwarded output's instruction is destroyed and its handling corrupted. [6](#0-5) 

### Likelihood Explanation
The offsets are deterministic public constants (`Secp256k1::hash_to_F(KEY_DST, b"branch"/"change"/"forward")`) and the group key is public, so the internal addresses are computable by anyone. Triggering only requires broadcasting a standard P2TR Bitcoin transaction — reachable by any unprivileged party with public transaction data, matching the reachability rule for Bitcoin transactions sent by third parties. Amount collision for the deletion path is trivially chosen by the attacker. [7](#0-6) [8](#0-7) 

### Recommendation
Distinguish self-generated outputs from externally received ones: tag `ReceivedOutput`s produced by `SignableTransaction`/forwarding plans (e.g., record outpoints of protocol-constructed transactions or attach a provenance marker in the Scanner/Output type) instead of deriving `kind` solely from `script_pubkey`. For `Forwarded` outputs, require confirmation that the outpoint belongs to a transaction the multisig itself broadcast before calling `take_forwarded_output`, and key the forwarded-output DB by outpoint/ID rather than by amount alone. [9](#0-8) 

### Proof of Concept
1. Observe the multisig group key `K` (public). Compute `fwd = K + G*hash_to_F(b"Serai Bitcoin Output Offset", b"forward")` (incrementing until even, per `register_offset`) and form `addr = p2tr_script_buf(fwd)`.
2. Wait for/observe a legitimate pending forwarded output with amount `A` (visible on-chain), so `ForwardedOutputDb` holds an `InInstruction` keyed by balance `A`.
3. Broadcast a transaction paying `A` sats to `addr`. `get_outputs` returns `Output { kind: Forwarded, ... }`; `scanner_event_to_multisig_event` calls `ForwardedOutputDb::take_forwarded_output(txn, A)`, deleting the legitimate output's stored instruction and emitting it under the attacker's output — the attacker's `Forwarded` output is then planned/spent while the original instruction is destroyed.
4. Variant: pay to the `change`/`branch` addresses; the deposit is classified `Change`/`Branch` and dropped by the `retain` filter, so funds on-chain are never credited — received but unspendable from the protocol's perspective. [10](#0-9) [11](#0-10)

  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }

  let mut scanner = Scanner::new(key).unwrap();
  let mut offsets = HashMap::from([(OutputType::External, Scalar::ZERO)]);

  let zero = Scalar::ZERO.to_repr();
  let zero_ref: &[u8] = zero.as_ref();
  let mut kinds = HashMap::from([(zero_ref.to_vec(), OutputType::External)]);

  let mut register = |kind, offset| {
    let offset = scanner.register_offset(offset).expect("offset collision");
    offsets.insert(kind, offset);

    let offset = offset.to_repr();
    let offset_ref: &[u8] = offset.as_ref();
    kinds.insert(offset_ref.to_vec(), kind);
  };

    OutputType::Branch,
    *BRANCH_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"branch")),
