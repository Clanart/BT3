### Title
`ReceivedOutput::read` accepts an attacker-controlled offset/script pairing, bypassing the Scanner's offset-to-script binding and enabling unspendable outputs to be treated as spendable funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner` enforces a strict invariant: every `ReceivedOutput` it yields carries an `offset` such that `p2tr_script_buf(key + G*offset) == output.script_pubkey` (`scan_transaction` looks up `output.script_pubkey` in `self.scripts`, which is only populated by `register_offset` with exactly that binding) [1](#0-0) . `ReceivedOutput::read`, however, deserializes `offset`, `output` (`TxOut`), and `outpoint` from raw bytes with no check that the offset actually derives the `script_pubkey` under the wallet key [2](#0-1) . This is the direct analog of the Suricata `load`+`save` issue: a restriction enforced on the production path (scan) is silently bypassed on the deserialization (load) path, and the malformed object is then consumed by downstream signing code as if it were legitimate.

### Finding Description
Downstream, the offset is cryptographically load-bearing:

- `Output::key()` in `processor/src/networks/bitcoin.rs` recovers the spendable key by computing `read_G(script_pubkey key) - G*offset`, implicitly assuming the offset/script binding [3](#0-2) .
- `SignableTransaction::new` counts `output.value` toward spendable input value and the `TransactionMachine`/`tweak_keys` path re-keys the threshold shares by each input's offset to produce the per-input BIP-340 signature [4](#0-3) .

If a `ReceivedOutput` is loaded with an `offset` that does not match its `script_pubkey` under the group key (e.g., offset `0` paired with an attacker-chosen P2TR script, or a script derived from a different offset/key), the processor will:

1. Report the output's value as a received balance (`balance()` returns `self.output.value()` [5](#0-4) ).
2. Include it as an input to a `SignableTransaction` and produce a threshold signature for a key that does not correspond to the actual on-chain script — the resulting witness signature will not validate against the real output key, so the "received" funds are not spendable, while the honest inputs co-spent in the same transaction are still consumed.

The read path performs only scalar canonicity (`Secp256k1::read_F`) and consensus decoding of `TxOut`/`OutPoint`; there is no re-derivation of the script from `(key, offset)` because `read` doesn't take the key — the invariant is only implicitly guaranteed when all serialized `ReceivedOutput`s originate from `Scanner::scan_transaction`.

### Impact Explanation
An unprivileged party able to feed crafted bytes to `ReceivedOutput::read` (or to a consuming `Output::read`, which delegates to it [6](#0-5) ) can cause the coordinator/processor to treat funds as received that are not spendable by the threshold key, and to co-sign transactions that burn genuine inputs alongside phantom ones. This matches the accepted impact class "funds reported received that are not spendable" and mirrors CVE-2026-45767's structure: validation exists on one path but the load path admits objects violating it, with the harmful effect realized at use time.

### Likelihood Explanation
Reachability requires an attacker to control the serialized bytes passed to `ReceivedOutput::read`/`Output::read`. The scanner pipeline itself produces consistent objects, so exploitation depends on an integration path where outputs are persisted/relayed and reloaded from a store an attacker can influence (e.g., a re-fed DB snapshot, an untrusted output relay, or a manually restored state). The cryptographic primitives remain sound — the defect is the missing re-validation of the offset↔script binding on load — which is precisely why it can slip in silently rather than failing loudly. Severity: Medium.

### Recommendation
Bind the offset to the script at deserialization or first use:

- Add `ReceivedOutput::read_for_key(key, reader)` (or a `verify(key)` method) that recomputes `p2tr_script_buf(key + G*offset)` and rejects the object unless it equals `output.script_pubkey`, treating a `None` result (odd point) as invalid.
- Have `Output::read`/the processor call this verification with the multisig group key before the output is admitted into the scanner DB or used in `SignableTransaction::new`, so the Scanner's invariant holds regardless of which path produced the bytes.

### Proof of Concept
Conceptual, in scope of `networks/bitcoin`:

```rust
// Given group key `K` (even Y), Scanner registers script S0 = p2tr(K + 0*G).
// Attacker crafts serialized bytes:
//   offset   = <any scalar d != 0>
//   output   = TxOut { value: 1_000_000, script_pubkey: S0 }  // script really pays K
//   outpoint = <arbitrary valid OutPoint>
let forged = ReceivedOutput::read(&mut crafted.as_slice()).unwrap();
// read succeeds: offset is canonical, TxOut/OutPoint decode cleanly.
// Downstream: balance() reports 1_000_000 sat; Output::key() computes
//   read_G(xonly(S0)) - G*d = K - G*d   (wrong key)
// TransactionMachine signs with shares tweaked by d, producing a signature
// under K - G*d, which does not satisfy S0's actual key K.
// The input is counted as spendable but the broadcast spend is invalid —
// funds reported received are not spendable.
```

  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
