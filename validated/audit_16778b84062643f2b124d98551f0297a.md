## Title
Silent auto-rewrite of local git remote URL based on trusted GitHub API `clone_url` field, with no user confirmation - (`File: app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
The external report's broken invariant is: a safety-critical action (slashing) silently fails to execute because it trusts a gate (`whenNotPaused`) controlled by state outside the caller's awareness, with no fallback or explicit user/operator confirmation. The GitHub Desktop analog is the inverse but structurally identical failure: a safety-critical action (rewriting the user's git remote URL, which determines where future `git push` operations go) is silently *executed* based entirely on data returned by the GitHub API, with no user confirmation, and the guard conditions that are supposed to prevent unintended rewrites can be satisfied by the same untrusted data source they're meant to validate against.

### Finding Description
`updateRemoteUrl` in [1](#0-0)  compares the repository's current git remote URL against `apiRepo.clone_url` (a field returned by the GitHub API) and, if the protocols match and the "old" clone URL (`gitHubRepository.cloneURL`, itself cached from a previous API response) still matches the current remote, it silently calls `gitStore.setRemoteURL` to rewrite the on-disk git remote:

```
if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
}
```

The guard `remoteUrlUnchanged` is computed by calling `urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)` [2](#0-1)  — but `gitHubRepository.cloneURL` is itself data previously fetched from the same GitHub API. There is no independent, out-of-band verification (e.g., cryptographic repo identity, user confirmation dialog) that the "new" `clone_url` genuinely represents an intentional user-authorized rename/transfer of the same repository rather than a value supplied by a compromised or spoofed API endpoint (e.g., a malicious/compromised GitHub Enterprise server, or a repo transfer performed by a malicious collaborator/organization admin who has legitimate API-level rights but not the local user's informed consent).

This mirrors the report's bug class exactly: a security-relevant operation is gated by a check that is trivially satisfied under attacker influence, causing the intended protection (here: "never silently repoint the remote a user pushes to") to be bypassed.

### Impact Explanation
If this rewrite is triggered by an attacker-influenced API response (rename/transfer to an attacker-controlled destination, or a malicious/rogue enterprise server), the user's local git remote is silently changed with no dialog or confirmation. Subsequent `git push` operations from Desktop will then send the user's commits — potentially including proprietary source code — to a different, attacker-controlled destination without the user's knowledge. This satisfies "silent corruption of what the user commits or pushes" from the valid-impact list, and the trigger is an attacker-controlled "GitHub API object" (`apiRepo.clone_url`), also on the valid-impact list.

### Likelihood Explanation
This code path only executes for repositories the user already has tracked with a matched `GitHubRepository`, and requires the "before" and "after" URLs to differ while the protocol stays the same — a scenario that legitimately occurs on rename/transfer, meaning the code path is exercised in normal operation, not just as a theoretical edge case. The main uncertainty (not fully verifiable via static/indexed search) is the exact caller context in `app-store.ts` — i.e., precisely when and how often `updateRemoteUrl` runs during repository refresh, and whether Desktop performs any additional server identity/ownership verification upstream of this call that I could not locate in the indexed code. This should be confirmed by reading the full call sites in `app/src/lib/stores/app-store.ts` (3 references) before treating this as a confirmed, exploitable issue.

### Recommendation
Never silently rewrite a tracked remote URL based solely on GitHub API data. At minimum, require explicit user confirmation before changing the destination of `git push`, and independently verify repository identity (e.g., via a stable, attacker-non-controllable ID such as repo `id` first observed at clone time) rather than comparing only URL strings sourced from the same API being trusted.

### Proof of Concept
Conceptual PoC (not verifiable end-to-end from the index alone):
1. User has repo `origin` = `https://github.com/org/repo.git`, tracked as a `GitHubRepository` with cached `cloneURL` = same value.
2. A rename/transfer occurs via the GitHub API such that a subsequent `fetchRepository`/refresh call returns `clone_url` = `https://github.com/attacker/repo.git` (e.g., attacker-controlled/compromised API response, or a legitimate-looking transfer performed without the local user's knowledge).
3. On the next repository refresh, `updateRemoteUrl` is invoked: `remoteUrlUnchanged` is `true` (old cached `cloneURL` still matches current local remote), `protocolsMatch` is `true` (both `https:`), `urlsMatch` is `false` (new API URL differs) → the function silently calls `gitStore.setRemoteURL('origin', 'https://github.com/attacker/repo.git')`.

import { IAPIRepository } from '../../api'
import { GitStore } from '../git-store'
import { urlMatchesRemote } from '../../repository-matching'
import * as URL from 'url'
import { GitHubRepository } from '../../../models/github-repository'

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

export function repositoryMatchesRemote(

  return (
    urlMatchesRemote(gitHubRepository.htmlURL, remote) ||
    urlMatchesRemote(gitHubRepository.cloneURL, remote)
  )

/**
 * Check whether or not a GitHub repository URL matches a given remote, by
 * parsing and comparing the structure of the each URL.
 *
 * @param url a URL associated with the GitHub repository
 * @param remote the remote details found in the Git repository
 */
export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}
