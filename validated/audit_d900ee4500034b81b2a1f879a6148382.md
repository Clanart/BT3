### Title
Spoofable `WWW-Authenticate` header lets an attacker-controlled git remote silently trigger a real GitHub/Enterprise Sign-In prompt for an arbitrary attacker endpoint - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
This is the same broken-invariant class as the Brave/BAT bug: a value that is supposed to come from a trusted, privileged source (Brave's allocation should never enter the "investor refund" pool) is instead accepted unchecked from an untrusted source and fed into a privileged code path. In GitHub Desktop, the credential-helper trampoline decides whether an unknown git remote should be treated as a "GitHub"/"enterprise" endpoint — and therefore worthy of popping the real GitHub Sign-In dialog — based in part on a `WWW-Authenticate` header value that is fully controlled by the remote git server itself.

### Finding Description
`getEndpointKind` in `app/src/lib/trampoline/trampoline-credential-helper.ts` classifies the credential-request endpoint using several heuristics. Among them: [1](#0-0) 

```
// When Git attempts to authenticate with a host it captures any
// WWW-Authenticate headers and forwards them to the credential helper. We
// use them as a happy-path to determine if the host is a GitHub host without
// having to resort to making a request ourselves.
for (const [k, v] of cred.entries()) {
  if (k.startsWith('wwwauth[')) {
    if (v.includes('realm="GitHub"')) {
      return 'enterprise'
    } ...
  }
}
```

This value is populated directly from the HTTP response headers of the remote the app is talking to (Git captures `WWW-Authenticate` on a 401 and forwards it verbatim to the credential helper). It is not authenticated, signed, or otherwise verified — it is attacker-controlled data coming straight from a "git remote/proxy response," one of the explicitly valid attacker primitives for this analysis.

If this heuristic fires, `getCredential` treats the unknown host as `'enterprise'`: [2](#0-1) 

Since no account exists for that made-up endpoint, Desktop calls `ui.promptForGitHubSignIn(endpoint)`, which — for a non-`github.com` hostname — directly begins the real Enterprise Sign-In flow and pre-populates the sign-in endpoint with the attacker-supplied URL, without ever going through the normal, deliberate "Add Enterprise Account" dialog where a user consciously types in a server address: [3](#0-2) 

The other classification signals (`isDotCom`, `isGHE`, matching an existing stored account, protocol check, or the network-based `isGitHubHost` fallback) are all either based on locally-trusted configuration or on a live TLS-authenticated request to the real endpoint. The `wwwauth[]` header check is the one signal in this function that is taken purely from data the remote server chooses to send back, with no cross-check against the actual identity of the host.

### Impact Explanation
This corresponds to "unauthorized OAuth or account binding" in the accepted impact set: an attacker who merely controls the server behind a git remote (e.g., a public repository, submodule URL, or hosted proxy the user fetches/clones/pushes to) can, without any unusual click from the user beyond a normal git operation, cause GitHub Desktop's own trusted Sign-In UI to be invoked and pointed at the attacker's chosen origin. Because this dialog is rendered by GitHub Desktop itself (not a browser tab), it inherits legitimacy in the user's eyes, and depending on the enterprise auth flow reached (basic auth vs. OAuth redirect), the user may be induced to hand over corporate/enterprise credentials or complete an OAuth grant against an attacker-controlled "GitHub Enterprise" endpoint, or bind an attacker endpoint into their trusted account list.

### Likelihood Explanation
The trigger requires only that the user perform an ordinary git network operation (clone/fetch/push/pull) against a repository whose remote (or a redirect/proxy in front of it) is controlled by the attacker and returns a 401 response with a crafted `WWW-Authenticate: ... realm="GitHub" ...` header — no local access, no prior malware, no leaked credentials, and no unnatural user steps are needed, satisfying the valid-impact criteria for this analysis.

### Recommendation
Do not trust the `wwwauth[]` realm string as sufficient evidence to classify an unknown host as a GitHub/Enterprise endpoint. Either drop this heuristic entirely and rely solely on the network-verified `isGitHubHost()` check (which requires an actual TLS response with `x-github-request-id`), or require that heuristic to only ever narrow down to prompting the *generic* git-auth dialog (which does not claim to be GitHub) instead of invoking the privileged `promptForGitHubSignIn`/enterprise OAuth flow.

### Proof of Concept
1. Host a git-accessible HTTPS server (e.g., `https://attacker.example`) that responds to authentication attempts with `WWW-Authenticate: Basic realm="GitHub"`.
2. Get a victim to add this URL as a remote or submodule and perform any operation requiring auth (`git fetch`, `git clone` with submodules, etc.) through GitHub Desktop.
3. Git forwards the `WWW-Authenticate` header to Desktop's credential helper (`trampoline-credential-helper.ts`), `getEndpointKind` returns `'enterprise'` due to the `realm="GitHub"` match, and since no account matches `attacker.example`, `ui.promptForGitHubSignIn('https://attacker.example')` fires — presenting the victim with GitHub Desktop's native Enterprise Sign-In dialog pointed at the attacker's server.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
