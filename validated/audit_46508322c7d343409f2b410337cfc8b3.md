### Title
Aggregator's `Noop` interceptor bypasses `is_internal`/`only_aggregator_and_self` gating, exposing `internal_get_emergency_stop_tx` to unauthenticated callers - ([File: core/src/rpc/interceptors.rs], [File: core/src/servers.rs])

### Summary
When `client_verification` is `false`, `create_grpc_server` wires the aggregator's gRPC service with `Interceptors::Noop`, which unconditionally passes every request through with no certificate or method-prefix check. This means the `Internal`-prefixed `internal_get_emergency_stop_tx` RPC, which is designed to only be reachable by the aggregator calling itself (`only_aggregator_and_self`), becomes reachable by any unauthenticated caller who can reach the aggregator's public gRPC port.

### Finding Description
The intended binding is: `caller_identity_reaching_Internal_method == our_cert` (the aggregator's own self certificate), enforced by `only_aggregator_and_self` in `core/src/rpc/interceptors.rs:36-77`, which checks `is_internal(&req)` (line 62, gated on the `grpc-method` header starting with `b"Internal"`) and then compares the peer's leaf certificate against `our_cert`.

This binding is only enforced when the interceptor variant is `Interceptors::OnlyAggregatorAndSelf`. The variant selection happens in `create_grpc_server` (`core/src/servers.rs:106-138`): if `config.client_verification` is `false`, the server is built with `ServerTlsConfig::new().identity(server_identity)` (no `client_ca_root`) and the service is wrapped with `Interceptors::Noop` instead of `OnlyAggregatorAndSelf`. `Noop`'s `call` implementation is `Ok(req)` unconditionally (`core/src/rpc/interceptors.rs:30`) — it performs no `is_internal` check and no certificate comparison at all.

`create_aggregator_grpc_server` (`core/src/servers.rs:293-317`) only emits a warning if `client_verification` is `true`; it does not enforce or require verification for the aggregator, and delegates entirely to the shared `create_grpc_server` logic above. Consequently, in any deployment with `client_verification=false`, the equality `caller == our_cert` is never evaluated — the gate simply does not exist for that connection, and `internal_get_emergency_stop_tx` (implemented on `AggregatorServer` in `core/src/rpc/aggregator.rs`, wired through `ClementineAggregator`) is reachable by anyone who can connect to the aggregator's TCP/TLS listener, with no cert, and issue a `GetEmergencyStopTxRequest`.

The handler ultimately calls into the database's `get_emergency_stop_txs`-family lookups (`core/src/database/aggregator.rs`) and returns `encrypted_emergency_stop_txs`. An attacker can scan the public Bitcoin chain to learn `move_txid`s and query for their corresponding encrypted emergency-stop transactions before they are otherwise revealed by the protocol's own disclosure schedule.

### Impact Explanation
The attacker obtains `encrypted_emergency_stop_tx` blobs ahead of their intended reveal/trigger condition for every move-to-vault deposit whose txid it can enumerate from chain data — this is a premature disclosure of a protocol commitment, repeatable across every deposit in the system with a single unauthenticated request each time. This matches the "High" impact category (premature disclosure of a protocol commitment). It does not by itself move BTC or credit a reimbursement (the payload remains encrypted with `emergency_stop_encryption_public_key`, requiring the security council's decryption key to act on it), so it does not independently rise to "Critical" unless combined with a separate key-compromise finding, which is out of scope per the rules (key compromise is excluded).

### Likelihood Explanation
This requires the deployment to run the aggregator with `client_verification=false` — a configuration option that exists and is toggled per-deployment in `BridgeConfig` (`core/src/config/mod.rs`, referenced from `core/src/servers.rs:106`), and the code path explicitly warns (but does not prevent) this for the aggregator (`core/src/servers.rs:306-308`). Given this precondition, the attack costs nothing beyond a single gRPC call (no fees, no on-chain action beyond passively scanning move txids from the public chain) and is fully repeatable for every known/enumerable move txid.

### Recommendation
Do not allow `Interceptors::Noop` to be selected for any server exposing `Internal`-prefixed methods, or make `is_internal` enforcement independent of the TLS-based interceptor variant (e.g., always reject requests whose `grpc-method` header starts with `Internal` unless the connection is verified as self, regardless of `client_verification`). At minimum, `create_aggregator_grpc_server` should hard-require `client_verification=true` (or an equivalent non-TLS self-auth mechanism) and refuse to start otherwise, rather than merely logging a warning.

fn only_aggregator_and_self(
    req: Request<()>,
    our_cert: &CertificateDer<'static>,
    aggregator_cert: &CertificateDer<'static>,
) -> Result<Request<()>, Status> {
    let Some(peer_certs) = req.peer_certs() else {
        if cfg!(test) {
            // Test mode, we don't need to verify peer certificates
            return Ok(req);
        } else {
            // If we're not in test mode, we need to check peer certificates
            return Err(Status::unauthenticated(
                "Failed to verify peer certificate, is TLS enabled?",
            ));
        }
    };

    // IMPORTANT: Only check the leaf (end-entity) certificate, which is always the first
    // certificate in the chain. The leaf is the only certificate whose private key the peer
    // proved possession of during the TLS handshake. Checking anywhere else in the chain
    // would allow identity spoofing: an attacker could include a pinned cert as an
    // intermediate in their chain without possessing its private key.
    let Some(leaf_cert) = peer_certs.first() else {
        return Err(Status::unauthenticated("Peer certificate chain is empty"));
    };

    if is_internal(&req) {
        if leaf_cert == our_cert {
            Ok(req)
        } else {
            Err(Status::unauthenticated(
                "Unauthorized call to internal method (not self)",
            ))
        }
    } else if leaf_cert == aggregator_cert || leaf_cert == our_cert {
        Ok(req)
    } else {
        Err(Status::unauthenticated(
            "Unauthorized call to method (not aggregator or self)",
        ))
    }
}

pub async fn create_aggregator_grpc_server(
    config: BridgeConfig,
) -> Result<(std::net::SocketAddr, oneshot::Sender<()>), BridgeError> {
    let addr: std::net::SocketAddr = format!("{}:{}", config.host, config.port)
        .parse()
        .wrap_err("Failed to parse address")?;
    let aggregator_server = AggregatorServer::new(config.clone()).await?;
    aggregator_server.start_background_tasks().await?;

    let svc = ClementineAggregatorServer::new(aggregator_server)
        .max_encoding_message_size(config.grpc.max_message_size)
        .max_decoding_message_size(config.grpc.max_message_size);

    if config.client_verification {
        tracing::warn!("Client verification is enabled on aggregator gRPC server",);
    }

    let (server_addr, shutdown_tx) =
        create_grpc_server(addr.into(), svc, "Aggregator", &config).await?;

    match server_addr {
        ServerAddr::Tcp(socket_addr) => Ok((socket_addr, shutdown_tx)),
        _ => Err(BridgeError::ConfigError("Expected TCP address".into())),
    }
}
