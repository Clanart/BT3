### Title
`Scanner::scan_transaction` reports dust outputs as spendable received funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_transaction` and `Scanner::scan_block` flag any transaction output whose `script_pubkey` matches a registered Taproot script as a `ReceivedOutput`, with no check on the output value. An unprivileged third party can send outputs below the dust threshold (or otherwise unspendable amounts) to a Serai deposit address, and the scanner will report them as received, spendable funds — a mismatch between reported and actual spendability, analogous to CVE-2023-5616 (gnome-control-center misreporting SSH exposure status).

### Finding Description
`scan_transaction` iterates `tx.output`, looks up `output.script_pubkey` in the `scripts` map, and unconditionally pushes a `ReceivedOutput` cloning the `TxOut` [1](#0-0) . `ReceivedOutput` is documented as "A spendable output" and exposes `value()` [2](#0-1) . Yet `send.rs` defines `DUST: u64 = 546` and refuses to construct any transaction creating a sub-546 output (`DustPayment`), acknowledging such outputs cannot be relayed/spent under standard policy [3](#0-2) . Spending a dust input is also uneconomic: at any nonzero fee rate the input's value is less than the ~57.5 vbytes it adds, so `SignableTransaction::new` will either error `TooLowFee`/`NotEnoughFunds` or burn other inputs [4](#0-3) . The coinbase-maturity gap is at least documented for `scan_block` [5](#0-4) ; the dust gap is not.

### Impact Explanation
Any party who learns a deposit script (public on-chain) can send dust outputs to it at negligible cost. The scanner reports them as received funds credited to the matching offset. Integrators crediting balances from `scan_transaction`/`scan_block` will account value that can never be spent, and `SignableTransaction` cannot construct a standard spend of those inputs — the reported "received" status diverges from reality, exactly the bug class of the reference CVE (reported state contradicting actual exposure/availability).

### Likelihood Explanation
Reachable by any unprivileged network participant sending a Bitcoin transaction — squarely within the allowed public-input surface. Cost is bounded by the dust amount (≥1 sat, unspendable anyway) plus one fee. It requires an integrator to rely on `Scanner` output without a dust filter, which is plausible since the crate itself enforces `DUST` on the send path but never on the receive path.

### Recommendation
Filter scanned outputs in `scan_transaction` (and therefore `scan_block`) by `output.value.to_sat() >= DUST`, or add a documented `ReceivedOutput::is_dust`/`spendable` accessor and reject sub-dust outputs at scan time so reported receipts are guaranteed spendable.

### Proof of Concept
1. Build a `Scanner` for an even `group_key` (`Scanner::new(key)`), giving script `S = p2tr_script_buf(key)`.
2. Attacker crafts a transaction with a `TxOut { value: 100 sats (< DUST), script_pubkey: S }` and broadcasts it; it confirms (sub-dust P2TR outputs can appear in blocks even if nonstandard to relay, e.g. via direct miner submission or as change-shaped outputs).
3. `scanner.scan_transaction(&tx)` returns a `ReceivedOutput` with `value() == 100`, reported as spendable.
4. Feeding it to `SignableTransaction::new(vec![output], &payments, ...)` fails `NotEnoughFunds`/`TooLowFee` for any payment ≥ 546 sats, and even alone the input cannot cover its own witness weight — the reported funds are unspendable.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();

  pub fn new(
    mut inputs: Vec<ReceivedOutput>,
    payments: &[(ScriptBuf, u64)],
    change: Option<ScriptBuf>,
    data: Option<Vec<u8>>,
    fee_per_vbyte: u64,
  ) -> Result<SignableTransaction, TransactionError> {
    if inputs.is_empty() {
      Err(TransactionError::NoInputs)?;
    }

    if payments.is_empty() && change.is_none() && data.is_none() {
      Err(TransactionError::NoOutputs)?;
    }

    for (_, amount) in payments {
      if *amount < DUST {
        Err(TransactionError::DustPayment)?;
      }
    }

    if data.as_ref().map_or(0, Vec::len) > 80 {
      Err(TransactionError::TooMuchData)?;
    }

    let input_sat = inputs.iter().map(|input| input.output.value.to_sat()).sum::<u64>();
    let offsets = inputs.iter().map(|input| input.offset).collect();
    let tx_ins = inputs
      .iter()
      .map(|input| TxIn {
        previous_output: input.outpoint,
        script_sig: ScriptBuf::new(),
        sequence: Sequence::MAX,
        witness: Witness::new(),
      })
      .collect::<Vec<_>>();

    let payment_sat = payments.iter().map(|payment| payment.1).sum::<u64>();
    let mut tx_outs = payments
      .iter()
      .map(|payment| TxOut { value: Amount::from_sat(payment.1), script_pubkey: payment.0.clone() })
      .collect::<Vec<_>>();

    // Add the OP_RETURN output
    if let Some(data) = data {
      tx_outs.push(TxOut {
        value: Amount::ZERO,
        script_pubkey: ScriptBuf::new_op_return(
          PushBytesBuf::try_from(data)
            .expect("data didn't fit into PushBytes depsite being checked"),
        ),
      })
    }

    let (mut weight, vbytes) = Self::calculate_weight_vbytes(tx_ins.len(), payments, None);

    let mut needed_fee = fee_per_vbyte * vbytes;
    // Technically, if there isn't change, this TX may still pay enough of a fee to pass the
    // minimum fee. Such edge cases aren't worth programming when they go against intent, as the
    // specified fee rate is too low to be valid
    // bitcoin::policy::DEFAULT_MIN_RELAY_TX_FEE is in sats/kilo-vbyte
    if needed_fee < ((u64::from(bitcoin::policy::DEFAULT_MIN_RELAY_TX_FEE) * vbytes) / 1000) {
      Err(TransactionError::TooLowFee)?;
    }

    if input_sat < (payment_sat + needed_fee) {
      Err(TransactionError::NotEnoughFunds {
        inputs: input_sat,
        payments: payment_sat,
        fee: needed_fee,
      })?;
    }
