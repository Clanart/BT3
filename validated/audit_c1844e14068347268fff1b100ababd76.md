### Title
Forged ERC20 `Transfer`/`Approval` log synthesis for CosmWasm pointer contracts based on unverified `wasm` event attributes - ([File: app/receipt.go])

### Summary
`AddCosmosEventsToEVMReceiptIfApplicable` synthesizes ERC20/721/1155-style EVM logs from raw `wasm` module events whenever the emitting contract address matches a registered pointer. The synthesis logic in `translateCW20Event`/`GetActionsFromWasmEvent` trusts the `action`, `from`, `to`, `amount` attribute *strings* on any `wasm` event emitted by the pointee contract, without validating them against the contract's actual balance/allowance state. Because pointer registration (`AddCW20`/`AddCW721`/`RegisterPointer`) is permissionless and can target any CosmWasm contract address supplied by the caller, an attacker can deploy an arbitrary CosmWasm contract that emits `wasm` events shaped like `action=transfer/mint/burn`, `from=...`, `to=...`, `amount=...` without any real token movement, causing the chain to synthesize legitimate-looking `Transfer`/`Approval` EVM logs at the pointer address. This is analogous to the 1inch `OrderCancelled` bug: a shared event-emission code path fires a semantically strong event (here, an ERC20-style `Transfer` log) that does not correspond to the real underlying action, deceiving off-chain consumers (indexers, DEXs, bridges) who read `eth_getLogs`/receipts and trust the `Transfer` topic as proof of an actual balance change.

### Finding Description
When a CosmWasm transaction produces `wasm`-type events, `AddCosmosEventsToEVMReceiptIfApplicable` looks up whether the emitting contract address has a registered ERC20/721/1155 pointer via `GetERC20CW20Pointer`/`GetERC721CW721Pointer`/`GetERC1155CW1155Pointer` [1](#0-0) . If a pointer exists, it calls `translateCW20Event`, which iterates over "actions" parsed purely from the wasm event's key/value attribute strings and emits an `ERC20TransferTopic`/`ERC20ApprovalTopic` synthetic `ethtypes.Log` for any action typed `mint`, `burn`, `send`, `transfer`, `transfer_from`, `send_from`, `burn_from` [2](#0-1) .

The attribute extraction in `GetActionsFromWasmEvent` blindly trusts whatever `action`/`from`/`to`/`amount` attribute values appear in the event — it performs no cross-check against the contract's queried balance, allowance, or total supply, and no verification that the reported `action.Type` actually corresponds to a state transition that occurred [3](#0-2) .

Pointer registration for a CW20 (or CW721/CW1155) contract is permissionless: any caller can invoke the pointer precompile's `AddCW20Pointer` (or the `MsgRegisterPointer` message) for any CosmWasm contract address of their choosing, subject only to the target contract responding correctly to a `token_info` query — which the attacker's own malicious contract fully controls [4](#0-3) . There is no requirement that the CosmWasm contract be a genuine, unmodified CW20 implementation.

Consequently, an attacker can:
1. Deploy a custom CosmWasm contract that, on any `execute` call, arbitrarily emits a `wasm` event with `_contract_address=<self>`, `action=transfer`, `from=<arbitrary>`, `to=<arbitrary>`, `amount=<arbitrary>` (or `mint`/`burn`) regardless of whether any real balance changed.
2. Register that contract as a CW20 pointer via the permissionless pointer precompile.
3. Call an arbitrary method on the contract to trigger these fabricated `wasm` events.
4. The synthetic-log pipeline in `app/receipt.go` will convert these into standard-looking ERC20 `Transfer`/`Approval` logs at the pointer's EVM address, indistinguishable in shape from a genuine CW20 pointer transfer (confirmed by the same code path exercised in `TestEvmEventsForCw20`) [5](#0-4) , and observable via `eth_getLogs`/`eth_getTransactionReceipt` exactly like the legitimate case demonstrated in the integration test `'indexes a CW20 ERC20 pointer transfer as a standard Transfer log'` [6](#0-5) .

### Impact Explanation
Off-chain systems (DEX aggregators, bridges, indexers, wallets) that rely on `eth_getLogs`/receipt logs to track ERC20 balances/transfers for CW20 pointer tokens can be fed forged `Transfer`/`Approval` events that never corresponded to a real balance change. This can be leveraged to fake deposits into custodial/bridge systems that key off `Transfer` logs to a specific address, to manipulate price/volume analytics that key off `Transfer` events, or to desynchronize any accounting system that assumes pointer-address `Transfer` logs are truthful proof of value movement. This does not directly move Sei-chain-held funds by itself, but it produces a **forged, chain-recorded** event that off-chain systems treat as an unforgeable record of asset movement — matching the impact class described in the 1inch report (indexer/off-chain confusion and potential exploitation by malicious actors), and could plausibly enable fund loss for third-party integrations that trust these logs.

### Likelihood Explanation
Likelihood is high: pointer registration is permissionless, requires only a self-controlled `token_info` query response, and the synthetic log generation performs no cross-validation against real contract state — any user can trigger this with an ordinary `MsgExecuteContract` transaction against their own malicious CW20-pointer contract.

### Recommendation
When synthesizing ERC20/721/1155 logs from `wasm` events for pointer contracts, cross-validate the reported action (e.g., query the contract's `balance`/`allowance`/`token_info` before and after execution, or at minimum verify the reported `from`/`to`/`amount` against the CW20/721/1155 spec-defined event format emitted by the *canonical* cw20-base/cw721-base/cw1155-base implementations) rather than trusting arbitrary attribute strings on any `wasm` event from the pointee address. Alternatively, restrict pointer registration to contracts whose code matches a known-good, audited CW20/721/1155 code ID, or maintain an allowlist/verification step so that arbitrary user-authored contracts cannot masquerade as pointees capable of producing synthetic value-transfer logs.

### Proof of Concept
1. Deploy a CosmWasm contract `FakeCW20` that implements `{"token_info":{}}` returning any `name`/`symbol` (to satisfy `AddCW20`'s constructor query) but whose `execute` entrypoint, for any message, unconditionally emits:
   ```
   wasm event: _contract_address=<FakeCW20>, action=transfer, from=<attacker>, to=<victim>, amount=<huge>
   ```
   without performing any real balance mutation.
2. Call the EVM pointer precompile's `addCW20Pointer(FakeCW20)` (permissionless) to register a pointer address for `FakeCW20` [4](#0-3) .
3. Submit a `MsgExecuteContract` against `FakeCW20` triggering the fabricated `action=transfer` wasm event.
4. Query `eth_getLogs`/`eth_getTransactionReceipt` for the pointer address; observe a standards-shaped `Transfer(from, to, amount)` log synthesized by `translateCW20Event` [7](#0-6) , even though no real CW20 balance changed — reproducing the same code path validated (for legitimate transfers) in `TestEvmEventsForCw20` [5](#0-4) .

func (app *App) GetActionsFromWasmEvent(ctx sdk.Context, event abci.Event) (actions []*Action) {
	for _, attr := range event.Attributes {
		key := string(attr.Key)
		value := string(attr.Value)
		if key == "action" {
			actions = append(actions, &Action{Type: value})
			continue
		}
		if len(actions) == 0 {
			continue
		}
		curAction := actions[len(actions)-1]
		switch key {
		case "amount":
			curAction.Amount = safeBigIntFromString(value)
		case "amounts":
			curAction.Amounts = utils.Map(strings.Split(value, ","), safeBigIntFromString)
		case "token_id":
			curAction.TokenId = safeBigIntFromString(value)
		case "token_ids":
			curAction.TokenIds = utils.Map(strings.Split(value, ","), safeBigIntFromString)
		case "sender":
			curAction.Sender = app.GetEvmAddressHash(ctx, value)
		case "recipient":
			curAction.Recipient = app.GetEvmAddressHash(ctx, value)
		case "spender":
			curAction.Spender = app.GetEvmAddressHash(ctx, value)
		case "operator":
			curAction.Operator = app.GetEvmAddressHash(ctx, value)
		case "owner":
			curAction.Owner = app.GetEvmAddressHash(ctx, value)
		case "from":
			curAction.From = app.GetEvmAddressHash(ctx, value)
		case "to":
			curAction.To = app.GetEvmAddressHash(ctx, value)
		}
	}
	return
}

func (p PrecompileExecutor) AddCW20(ctx sdk.Context, method *ethabi.Method, caller common.Address, args []interface{}, value *big.Int, evm *vm.EVM, suppliedGas uint64, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	cwAddr := args[0].(string)
	existingAddr, existingVersion, exists := p.evmKeeper.GetERC20CW20Pointer(ctx, cwAddr)
	if exists && existingVersion >= 1 {
		return nil, 0, fmt.Errorf("pointer at %s with version %d exists when trying to set pointer for version %d", existingAddr.Hex(), existingVersion, cw20.CurrentVersion(ctx))
	}
	cwAddress, err := sdk.AccAddressFromBech32(cwAddr)
	if err != nil {
		return nil, 0, err
	}
	res, err := p.wasmdKeeper.QuerySmart(ctx, cwAddress, []byte("{\"token_info\":{}}"))
	if err != nil {
		return nil, 0, err
	}
	formattedRes := map[string]interface{}{}
	if err := json.Unmarshal(res, &formattedRes); err != nil {
		return nil, 0, err
	}
	name := formattedRes["name"].(string)
	symbol := formattedRes["symbol"].(string)
	constructorArguments := []interface{}{
		cwAddr, name, symbol,
	}

	packedArgs, err := cw20.GetParsedABI().Pack("", constructorArguments...)
	if err != nil {
		panic(err)
	}
	bin := append(cw20.GetBin(), packedArgs...)
	if value == nil {
		value = utils.Big0
	}
	ret, contractAddr, remainingGas, err := evm.Create(caller, bin, suppliedGas, uint256.MustFromBig(value))
	if err != nil {
		return
	}
	err = p.evmKeeper.SetERC20CW20Pointer(ctx, cwAddr, contractAddr)
	if err != nil {
		return
	}

	ctx.EventManager().EmitEvent(sdk.NewEvent(
		types.EventTypePointerRegistered, sdk.NewAttribute(types.AttributeKeyPointerType, "cw20"),
		sdk.NewAttribute(types.AttributeKeyPointerAddress, contractAddr.Hex()), sdk.NewAttribute(types.AttributeKeyPointee, cwAddr),
		sdk.NewAttribute(types.AttributeKeyPointerVersion, fmt.Sprintf("%d", cw20.CurrentVersion(ctx)))))
	ret, err = method.Outputs.Pack(contractAddr)
	return
}
