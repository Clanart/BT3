### Title
Untrusted `ReceivedOutput` bytes can claim arbitrary Bitcoin UTXOs - (File: `networks/bitcoin/src/wallet/mod.rs`)

### Summary
`ReceivedOutput::read` accepts an offset, `TxOut`, and `OutPoint` without verifying that the referenced outpoint exists on-chain or contains the declared output. Downstream transaction construction trusts those fields as spendable wallet inputs, while `SignableTransaction::multisig` only checks that the declared `TxOut` script matches the key derived from the supplied offset.

### Finding Description
`ReceivedOutput::read` deserializes an arbitrary scalar offset, transaction output, and outpoint directly into the spendable-output representation. [1](#0-0)  Unlike `Scanner::scan_transaction`, which creates this object only after matching an on-chain transaction output to a registered wallet script, the deserialization path performs no ownership, consistency, or chain-backed UTXO validation. [2](#0-1) 

`SignableTransaction::new` subsequently trusts the serialized outpoint as the transaction input and uses the serialized `TxOut` value as available input funds. [3](#0-2)  Before creating the FROST transaction machine, `SignableTransaction::multisig` checks only that the declared previous-output script equals the Taproot script for the offset key; it does not validate that `previous_output` references an existing UTXO containing that `TxOut`. [4](#0-3) 

This permits an attacker-controlled serialized `ReceivedOutput` to claim ownership of a nonexistent or unrelated Bitcoin outpoint by pairing it with a script that the wallet can sign for.

### Impact Explanation
A wallet service accepting serialized `ReceivedOutput` values can report and attempt to spend funds that are not actually spendable. The fabricated input can inflate the wallet's apparent balance and can drive a threshold-signing round for a transaction that Bitcoin consensus will reject because the referenced UTXO does not exist or does not contain the declared output. This is a direct loss of funds availability and can poison wallet state or payment scheduling.

### Likelihood Explanation
The attacker only needs to provide bytes to `ReceivedOutput::read` and know a wallet-controlled script. Wallet scripts and addresses are public by design, and the fabricated `OutPoint` can name an arbitrary or nonexistent transaction output. The exploit does not require controlling a validator, learning a secret share, or convincing Bitcoin miners to accept an invalid transaction.

### Recommendation
Do not deserialize bytes directly into the trusted spendable-output type. Either:

- keep the serialized record as an unverified claimed output and require `Scanner::scan_transaction` or an equivalent chain lookup to promote it to `ReceivedOutput`; or
- include and verify the wallet key/context during deserialization, then resolve `outpoint` against Bitcoin and require the resolved output to equal the serialized `TxOut` exactly; and
- reject offset/script pairs that are not registered for that wallet.

### Proof of Concept
```rust
use bitcoin::{Amount, OutPoint, Transaction, TxOut, Txid};
use bitcoin::hashes::Hash;
use bitcoin_serai::wallet::{p2tr_script_buf, ReceivedOutput, SignableTransaction};
use frost::curve::Secp256k1;
use k256::{ProjectivePoint, Scalar};
use std::io::Write;

// `wallet_key` and `keys` are the public group key and threshold keys.
let wallet_script = p2tr_script_buf(wallet_key).unwrap();

// The attacker chooses any outpoint; it need not exist or belong to the wallet.
let fake_outpoint = OutPoint {
    txid: Txid::all_zeros(),
    vout: 0,
};

let mut encoded = Vec::new();
encoded.write_all(&Scalar::ZERO.to_bytes()).unwrap();
encoded.extend(bitcoin::consensus::serialize(&TxOut {
    value: Amount::from_sat(1_000_000),
    script_pubkey: wallet_script.clone(),
}));
encoded.extend(bitcoin::consensus::serialize(&fake_outpoint));

// Accepted as a ReceivedOutput without querying Bitcoin or proving ownership.
let fake = ReceivedOutput::read(&mut encoded.as_slice()).unwrap();
assert_eq!(fake.outpoint(), &fake_outpoint);
assert_eq!(fake.value(), 1_000_000);

// Transaction construction trusts the fake value and outpoint.
let spend = SignableTransaction::new(
    vec![fake],
    &[(wallet_script, 500_000)],
    None,
    None,
    10,
)
.unwrap();

// The ownership check passes because only the declared script is compared
// against the key derived from the declared offset.
assert!(spend.multisig(&keys).is_some());
```
