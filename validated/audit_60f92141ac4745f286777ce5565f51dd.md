## Analysis

The UNCX bug pattern — "sweep the entire `balanceOf` of a contract instead of only the funds belonging to the current operation" — has a direct analog in `IntentGatewayV2`'s interaction with the shared `CallDispatcher`.

### The shared, persistent sweep target

`_params.dispatcher` is a single `CallDispatcher` instance shared across **all** orders/users of a gateway. [1](#0-0)  Its `dispatch` function has no access control and no bookkeeping of "whose" balance is inside it — it is a generic call-forwarder that can accumulate arbitrary token balances (from predispatch/output calls that produce more of a token than the order needs, or from tokens sent to it directly by mistake), exactly the "accidentally sent to the contract" scenario in the original report.

### The over-broad sweep

In `placeOrder`, when an order carries `predispatch.call`, the gateway sweeps the dispatcher's **full current balance** of each input token back into escrow rather than only the amount produced by the caller's own predispatch call: [2](#0-1) 

The only guard is a lower-bound check (`balance < requiredAmount`), not an upper bound tied to what this specific caller's call actually generated: [3](#0-2) 

If `received <= order.inputs[i].amount`, the swept amount — which can include stray balance left by a *previous, unrelated* order or a stray/misdirected transfer — is credited straight into `order.inputs[i].amount`, i.e. directly into the caller's own escrow, funded partly or wholly by someone else's tokens. The identical pattern exists in the fill-side sweep in `IntentsBase._execute`, which sweeps the dispatcher's entire balance of each output token as "dust" after `order.output.call` runs: [4](#0-3)  and on the Tron variant of `IntentGatewayV2`: [5](#0-4) .

### Why this matters

Any token produced by an `order.output.call`/`predispatch.call` that isn't one of the explicitly listed `order.output.assets`/`order.inputs` tokens for that transaction (e.g. reward/bonus tokens from a DEX swap, referral tokens, or a plain mis-sent transfer to the dispatcher) is left stranded in the shared `CallDispatcher`. The next arbitrary, unprivileged caller who places (or fills) an order referencing that exact token can have it swept wholesale into their own escrow via the "full balance" sweep logic, effectively appropriating funds that were never theirs — mirroring the UNCX `_convertPositionToFullRange` bug where the entire contract balance (not just the position's own proceeds) was redeposited/redirected by whoever called `lock`.

This satisfies the impact gate's "stealing or loss of funds" / "wrong beneficiary or amount" criteria through a purely unprivileged, public entrypoint (`placeOrder`/`fillOrder`), with no dependency on a malicious relayer, prover, or admin.

### Title
Full-balance sweep of the shared CallDispatcher lets any order credit itself with stray/foreign token balances - (`evm/src/apps/IntentGatewayV2.sol`, `evm/src/apps/intentsv2/IntentsBase.sol`)

### Summary
`placeOrder`'s predispatch-sweep and `_execute`'s output-sweep both pull the **entire current `balanceOf(dispatcher)`** for a token rather than only the delta produced by the current caller's own predispatch/output call, crediting the swept amount into the caller's own escrow or classifying it as protocol dust owned by whichever gateway swept it first.

### Finding Description
`CallDispatcher` is a single shared, stateful, access-control-free contract used by all orders. [1](#0-0)  Any token left in it — from a prior order's over-produced output, a stray/mistaken transfer, or an incomplete multi-call composition — persists across transactions. `placeOrder` computes the amount to sweep as `IERC20(token).balanceOf(dispatcher)` with only a `>= requiredAmount` lower-bound check, then transfers that whole balance to the gateway and (if it doesn't exceed `order.inputs[i].amount`) credits it directly as the order's escrowed input. [6](#0-5)  There is no snapshot/delta isolating funds attributable solely to the current caller's own predispatch call versus pre-existing stray balance.

### Impact Explanation
An attacker can place an order requiring a small `predispatch` amount for a token that is known/observed to have stray balance sitting in the shared `CallDispatcher` (from prior legitimate order flows or accidental sends), and have that stray balance swept wholesale into their own order's escrow, funding an order with value they never contributed. Because escrowed orders are later fulfilled cross-chain/same-chain for real output value, this constitutes unauthorized appropriation of funds belonging to the protocol or other users — a direct funds-theft/loss-of-funds vector.

### Likelihood Explanation
Any user with any predispatch/output call that legitimately produces excess or unlisted token balance (e.g., DEX swap dust, rounding, bonus tokens) will unintentionally leave funds in the shared dispatcher; an attacker only needs to monitor the dispatcher's token balances and craft a subsequent order referencing that token to capture it — no privileged role, relayer collusion, or governance action required.

### Recommendation
Snapshot the dispatcher's balance of each relevant token immediately before executing the current caller's own predispatch/output call, and sweep/credit only the resulting delta, not the dispatcher's absolute balance. Any unexplained residual should remain attributable to protocol-controlled dust accounting only after being proven to originate from the current transaction, or should require a separate, permissioned reconciliation path.

### Proof of Concept
1. A prior order's `predispatch.call` performs a swap that yields slightly more of token `X` than `order.inputs` required; the excess `X` remains in `CallDispatcher` (not part of any tracked `order.inputs`/`order.output.assets` list for that order).
2. Attacker calls `placeOrder` with `order.inputs = [{token: X, amount: requiredAmount}]` and a no-op/minimal `predispatch.call` that transfers `0` or a trivial amount of `X` to the dispatcher.
3. In the sweep step, `balance = IERC20(X).balanceOf(dispatcher)` includes the stray leftover plus attacker's trivial deposit, satisfying `balance >= requiredAmount`.
4. The entire balance is swept to the gateway and, since `received <= order.inputs[i].amount` is not guaranteed to fail, gets credited into the attacker's escrow as `order.inputs[i].amount`. [7](#0-6) 
5. Attacker's order is now escrowed and fulfillable for real output value, funded in part by tokens the attacker never actually deposited.

contract CallDispatcher is ICallDispatcher {
    /**
     * @dev error thrown when the target is not a contract.
     */
    error NotContract(address target);

    /**
     * @dev error thrown when a call fails.
     */
    error CallFailed(address target, bytes result);

    /**
     * @dev Receive function to accept ETH transfers
     */
    receive() external payable {}

    /**
     *  @dev reverts if the target is not a contract or if any of the calls reverts.
     */
    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
