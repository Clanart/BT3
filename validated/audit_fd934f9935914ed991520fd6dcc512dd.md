Based on my investigation, I found a concrete local analog: `EvmHost.sol` inconsistently guards its low-level `.call()` dispatches to app modules. One sibling function checks for contract code before calling; three others do not, silently treating a call to a non-contract address as a successful application callback.

### Title
Unchecked low-level call to non-contract module lets GET-response/timeout delivery finalize and pay fees without genuine `IApp` execution - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatchIncoming(PostRequest, address)` explicitly checks `extcodesize` on the destination before invoking it via a raw `.call()`, and returns early (no receipt, no event) if the target has no code. Its siblings — `dispatchIncoming(GetResponse, address)`, `dispatchTimeOut(GetRequestTimeout, ...)`, and `dispatchTimeOut(PostRequestTimeout, ...)` — omit this check entirely and rely solely on the raw `.call()`'s boolean `success` return value.

### Finding Description
In `evm/src/core/EvmHost.sol:794-818`, the POST-request path is defended: [1](#0-0) 

But the GET-response path at `evm/src/core/EvmHost.sol:824-847` has no such guard: [2](#0-1) 

And both timeout paths repeat the same unguarded pattern: [3](#0-2) [4](#0-3) 

Solidity's low-level `address.call(...)` returns `success = true` when the target address has no deployed code, regardless of the calldata — this is the exact "untyped/unchecked low-level call" defect class described in the external report (calling through raw `.call` instead of a checked, typed interface invocation). The developers clearly recognized this risk for the POST-request path (adding the explicit `extcodesize` check), but did not apply the same defense to `dispatchIncoming(GetResponse,...)`, `dispatchTimeOut(GetRequestTimeout,...)`, or `dispatchTimeOut(PostRequestTimeout,...)`.

As a result, if `response.request.from` / `timeout.request.from` resolves to an address with no code (e.g., an EOA, a not-yet-deployed address, or a self-destructed former module), the `.call()` unconditionally reports `success = true` even though `IApp.onGetResponse`/`onGetTimeout`/`onPostRequestTimeout` was never actually executed. The code then proceeds down the "success" branch:
- for GET responses: transfers `_requestCommitments[commitment].fee` to `relayer` and emits `GetRequestHandled`, permanently finalizing delivery,
- for GET/POST timeouts: refunds `meta.fee` to `meta.sender` and permanently finalizes the timeout, with the request's commitment already deleted and never restored for retry.

The retry/repair mechanism that exists specifically to handle a failed callback (`delete _responseReceipts[commitment]` / `_requestCommitments[commitment] = meta`) is bypassed, because the low-level call artifact makes failure indistinguishable from success.

### Impact Explanation
This produces false "delivery succeeded" state acceptance for requests/responses whose origin module never actually processed the incoming message — the receipt/commitment bookkeeping and the relayer-fee/refund payouts are irreversibly finalized despite no genuine module execution. This directly maps to the bounty's "false proof or state acceptance" and can move fee-token funds ( `feeToken()` ) based on a spoofed "success" that the guarded sibling function on the very same contract was written to prevent.

### Likelihood Explanation
Whether this is triggerable by an unprivileged actor depends on whether `request.from` is strictly bound to `msg.sender` at request-dispatch time (I was not able to confirm this from the code I could access before running out of iterations — the `dispatch(DispatchGet)`/`dispatch(DispatchPost)` implementation that sets `from` was not located). If `from` is set to `msg.sender` of the dispatch call and an EOA is permitted to call the dispatcher directly (no requirement that the caller be a contract), then any user can dispatch a GET request or POST request from their own EOA, and the corresponding response/timeout delivery will always take the "false success" path described above — fully attacker-triggerable, no privileged actor needed.

### Recommendation
Add the same `extcodesize`-based guard used in `dispatchIncoming(PostRequest, address)` to `dispatchIncoming(GetResponse, address)`, `dispatchTimeOut(GetRequestTimeout, ...)`, and `dispatchTimeOut(PostRequestTimeout, ...)` before performing the low-level `.call()`, so that a no-code destination is treated identically across all four dispatch paths (early return without finalizing receipts/commitments or moving fee funds).

### Proof of Concept
1. Confirm (via the currently-unlocated `dispatch(DispatchGet)`/`dispatch(DispatchPost)` code) whether `request.from`/`response.request.from` is set to `msg.sender` without requiring the caller to be a contract.
2. If so, from an EOA, call the ISMP dispatcher to send a `GetRequest` (or `PostRequest`) with `from = <attacker EOA>`, paying the associated fee.
3. Have the request time out (or produce a response), and submit the corresponding message through `IHandlerV2` so that `EvmHost.dispatchTimeOut(GetRequestTimeout,...)` (or `dispatchIncoming(GetResponse,...)`) is invoked with `timeout.request.from` / `response.request.from` = the attacker's EOA.
4. Observe that `(bool success,) = <EOA>.call(...)` returns `success = true` even though no `IApp` callback logic ran, causing the fee/refund transfer and permanent commitment/receipt finalization to proceed exactly as if a legitimate module had processed the callback.

Because I could not verify step 1 with certainty within the remaining budget, this should be validated against `IDispatcher`'s concrete implementation before treating the finding as fully confirmed exploitable end-to-end; the code-level inconsistency itself (missing `extcodesize` check present on the sibling function) is directly verified and cited above.

    function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
        address destination = _bytesToAddress(request.to);
        uint256 size;
        assembly {
            size := extcodesize(destination)
        }
        if (size == 0) {
            // instead of reverting the entire batch, early return here.
            return;
        }

        // replay protection
        bytes32 commitment = request.hash();
        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)
            .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));

        if (!success) {
            // so that it can be retried
            delete _requestReceipts[commitment];
            return;
        }
        emit PostRequestHandled({commitment: commitment, relayer: relayer});
