### Title
Unvalidated DataLayer mirror URLs enable SSRF against subscribing peers' internal network - (File: chia/data_layer/download_data.py)

### Summary
A DataLayer store owner can register arbitrary "mirror" URLs for their store via the wallet RPC (`dl_new_mirror`). These URLs are propagated on-chain as memos on a mirror coin and are later consumed by any other node that subscribes to that store, causing that node's `DataLayer` service to make outbound HTTP requests to the attacker-chosen URL with no destination validation — mirroring the FastGPT bug class of a stored, unvalidated remote endpoint being used later by a backend "workflow runner" without revalidation.

### Finding Description
A wallet user creates a mirror for their own DataLayer singleton via `DataLayerWallet.create_new_mirror()`, which spends a coin to the mirror puzzle with the target URLs encoded as memos: [1](#0-0) 

The URLs are not validated at all — `add_mirror` in `DataLayer` only checks that the list is non-empty, and the RPC path (`dl_new_mirror` in `wallet_rpc_api.py`) simply forwards the caller-supplied `urls` straight into the transaction: [2](#0-1) [3](#0-2) 

When any other node's wallet syncs the chain, `coin_added()` in `DataLayerWallet` decodes the mirror coin's memos into a `Mirror` record (`launcher_id`, `urls`) and persists it with no URL scheme/host filtering: [4](#0-3) 

That subscribing node's `DataLayer` service periodically calls `update_subscriptions_from_wallet()`, which pulls those raw mirror URLs from the wallet and feeds them straight into the local subscription server list with no validation: [5](#0-4) 

`fetch_and_validate()` then picks one of these URLs and passes it into `insert_from_delta_file()` → `download_file()`, which, when no plugin downloader is configured, calls `http_download()` directly against the stored URL using `aiohttp.ClientSession`: [6](#0-5) [7](#0-6) 

Nowhere in this chain — `add_mirror`, `dl_new_mirror`, `coin_added`, `update_subscriptions_from_wallet`, or `download_file`/`http_download` — is the URL checked against internal/private network ranges (e.g. `127.0.0.1`, `localhost`, RFC1918 ranges) or restricted to `http(s)`. A repo test even demonstrates that a raw loopback URL (`http://127.0.0.1/8000`) is accepted and stored unmodified as a mirror URL: [8](#0-7) 

This is architecturally the same "inconsistent SSRF protection gap" as the FastGPT MCP issue: a store/create-style RPC (`dl_new_mirror`/mirror coin creation) accepts and durably persists (on-chain, and then into every subscriber's local DB) an attacker-chosen destination URL, and a separate execution path (`fetch_and_validate`/`download_file`) later dereferences that stored URL without revalidating it against SSRF-sensitive destinations.

### Impact Explanation
Any subscribing DataLayer node — a normal, unprivileged Data Layer client that merely subscribes to a store — will have its own `data_layer` service issue outbound HTTP(S) `GET`/`POST` requests to a URL fully controlled by the store owner. This can be used to probe or reach services that are otherwise only reachable from the victim's local network/loopback (internal admin APIs, other locally-bound services, cloud metadata endpoints, etc.), and can be used for internal network reconnaissance, port scanning, or triggering unintended side effects on internal-only HTTP services from the DataLayer node's network position. Because the URL also gets retried repeatedly by the periodic sync loop (`periodically_manage_data()`), this can additionally be leveraged for a modest denial-of-service/resource-consumption effect against the internal target endpoint. This satisfies the medium-severity SSRF bug class scoped to a reachable Data Layer client actor.

### Likelihood Explanation
Likelihood is moderate-to-high: creating a mirror is a normal, unprivileged wallet/DataLayer action available to anyone who owns/controls a DataLayer singleton, requiring only a standard fee-bearing transaction (`dl_new_mirror`). Any peer that chooses to subscribe to that store (a routine DataLayer operation) will automatically pull and use the malicious mirror URL the next time its sync loop runs, without any user interaction or additional privilege beyond "subscribe to a store."

### Recommendation
Validate mirror URLs both at creation time (`DataLayer.add_mirror` / `WalletRpcApi.dl_new_mirror`) and again at the point of use in `download_file`/`http_download` in `chia/data_layer/download_data.py`: enforce an allowed scheme (`http`/`https` only), resolve and reject destinations that resolve to loopback, link-local, or RFC1918 private ranges (and other SSRF-sensitive ranges) unless explicitly configured for trusted/testing use, and apply this check consistently on every code path that dereferences a stored mirror or plugin URL, not just at a single entry point.

### Proof of Concept
1. Attacker creates a DataLayer store and calls `dl_new_mirror` (or `DataLayerRpcApi.add_mirror`) with `urls=["http://127.0.0.1:<internal-port>/..."]` (or an internal RFC1918 address), as accepted unmodified per the existing test at `chia/_tests/core/data_layer/test_data_rpc.py:2782-2790`.
2. A victim node subscribes to the attacker's store id via the normal DataLayer subscription flow.
3. The victim's `DataLayer.update_subscriptions_from_wallet()` pulls the malicious URL into its local subscription server list (`chia/data_layer/data_layer.py:979-985`).
4. On the next sync cycle, `fetch_and_validate()` → `insert_from_delta_file()` → `download_file()` → `http_download()` causes the victim's node to issue an HTTP request to the attacker-chosen internal URL (`chia/data_layer/data_layer.py:642-694`, `chia/data_layer/download_data.py:110-145`), demonstrating SSRF into the victim's local network.

    async def dl_new_mirror(
        self,
        request: DLNewMirror,
        action_scope: WalletActionScope,
        extra_conditions: tuple[Condition, ...] = tuple(),
    ) -> DLNewMirrorResponse:
        """Add a new on chain message for a specific singleton"""
        if self.service.wallet_state_manager is None:
            raise ValueError("The wallet service is not currently initialized")

        dl_wallet = await self.service.wallet_state_manager.get_dl_wallet()
        async with self.service.wallet_state_manager.lock:

                request.launcher_id,
                request.amount,
                Mirror.encode_urls(request.urls),
                action_scope,
                fee=request.fee,
                extra_conditions=extra_conditions,
            )

async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True

@pytest.mark.limit_consensus_modes(reason="does not depend on consensus rules")
@pytest.mark.anyio
async def test_mirrors(
    self_hostname: str, one_wallet_and_one_simulator_services: SimulatorsAndWalletsServices, tmp_path: Path
) -> None:
    wallet_rpc_api, full_node_api, wallet_rpc_port, ph, bt = await init_wallet_and_node(
        self_hostname, one_wallet_and_one_simulator_services
    )
    async with init_data_layer(wallet_rpc_port=wallet_rpc_port, bt=bt, db_path=tmp_path) as data_layer:
        data_rpc_api = DataLayerRpcApi(data_layer)
        res = await data_rpc_api.create_data_store({})
        assert res is not None
        store_id = bytes32.from_hexstr(res["id"])
        await farm_block_check_singleton(data_layer, full_node_api, ph, store_id, wallet=wallet_rpc_api.service)

        urls = ["http://127.0.0.1/8000", "http://127.0.0.1/8001"]
        res = await data_rpc_api.add_mirror({"id": store_id.hex(), "urls": urls, "amount": 1, "fee": 1})

        await farm_block_check_singleton(data_layer, full_node_api, ph, store_id, wallet=wallet_rpc_api.service)
        mirrors = await data_rpc_api.get_mirrors({"id": store_id.hex()})
        mirror_list = mirrors["mirrors"]
        assert len(mirror_list) == 1
        mirror = mirror_list[0]
        assert mirror["urls"] == ["http://127.0.0.1/8000", "http://127.0.0.1/8001"]
        coin_id = mirror["coin_id"]

        res = await data_rpc_api.delete_mirror({"coin_id": coin_id, "fee": 1})
        await farm_block_check_singleton(data_layer, full_node_api, ph, store_id, wallet=wallet_rpc_api.service)
        mirrors = await data_rpc_api.get_mirrors({"id": store_id.hex()})
        mirror_list = mirrors["mirrors"]
        assert len(mirror_list) == 0

        with pytest.raises(RuntimeError, match="URL list can't be empty"):
            res = await data_rpc_api.add_mirror({"id": store_id.hex(), "urls": [], "amount": 1, "fee": 1})
