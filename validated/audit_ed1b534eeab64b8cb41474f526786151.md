### Title
`ThresholdKeys` accepts a zero secret share and identity verification shares, yielding a permanently committed group key of identity for which anyone can forge signatures - (File: crypto/dkg/src/lib.rs)

### Summary
`ThresholdKeys::new` validates the *count* and *range* of verification shares but never checks that the provided `secret_share` is nonzero nor that any verification share (or the resulting `group_key`) is non-identity. The serialized form read by `ThresholdKeys::read` therefore lets attacker-supplied bytes instantiate keys whose group key is the identity point — a "pool" that is permanently initialized to a known private key of `0`, directly analogous to `deposit()` locking the pair with zero reserves.

### Finding Description
In `crypto/dkg/src/lib.rs`, `ThresholdKeys::new` checks:

- `verification_shares.len() == n` (lines 355–360)
- each participant index `<= n` (lines 361–365)
- `Interpolation::Constant` only when `t == n` (lines 367–374)

It then computes `group_key` as the interpolated sum over participants `1..=t` of `verification_shares[i] * interpolation_factor(i, t)` (lines 376–378) and stores it unconditionally. There is no check that `secret_share != 0`, that any `verification_shares[i]` is non-identity, or that `group_key` is non-identity.

`ThresholdKeys::read` (lines 574–632) is explicitly listed as an untrusted-bytes entry point. It reads `t`, `n`, `i`, an `Interpolation` (including `Constant` with `n` arbitrary field elements via `C::read_F`), a `secret_share` via `C::read_F`, and `n` verification shares via `C::read_G`, then calls `ThresholdKeys::new`. An attacker can therefore supply:

- `t = n = 1`, `i = 1`, `Interpolation::Constant([1])` (or `Lagrange`),
- `secret_share = 0`,
- `verification_shares = {1: identity}`.

`ThresholdKeys::new` accepts this: `group_key = identity * 1 = identity`. The resulting `ThresholdKeys` serializes/deserializes cleanly and `view()`/`group_key()` return the identity group key. `scale()`/`offset()` can shift it, but the original committed key is a publicly known scalar (`0`), so any Schnorr/FROST signature under it is forgeable by anyone (`s = c*0 + r` style forgery against a zero public key). Like `deposit()` setting `deposited = true` on zero reserves, the structure is permanently committed to a degenerate, attacker-controlled state with no possibility of repair.

The same missing checks exist for `secret_share` alone: a nonzero `group_key` with `secret_share = 0` produces a participant whose signature share verifies (verification share identity × factor, consistent) while contributing nothing — a degenerate share silently accepted rather than rejected.

### Impact Explanation
Anywhere `ThresholdKeys::read` consumes untrusted bytes (key-share exchange, recovery, multisig setup), an attacker can commit a threshold "key" whose group key is the identity point. Funds addressed to that group key are spendable by anyone, since the discrete log of the group key is `0`. This is a forged-signature / unspendable-or-stealable-funds condition, satisfying the Critical/High bar: concrete signature forgery against a publicly known private key.

### Likelihood Explanation
The path is fully reachable from public input bytes (`ThresholdKeys::read`) with no privileged position required — precisely the untrusted-read surface the scope rules designate. It requires an integrator to deserialize attacker-controlled `ThresholdKeys` (e.g., during recovery or share distribution); no malformed curve encodings or internal misbehavior are needed, only accepted-as-valid zero/identity values.

### Recommendation
In `ThresholdKeys::new`, reject `secret_share.is_zero()` and any `verification_shares` value that `is_identity()`, and after computing `group_key`, reject `group_key.is_identity()`. This mirrors the report's fix: require a minimum nonzero "deposit" rather than assuming well-formed inputs.

### Proof of Concept
```rust
use std::{collections::HashMap, io};
use zeroize::Zeroizing;
use dalek_ff_group::{Ristretto, Scalar, EdwardsPoint};
use ciphersuite::{group::{ff::Field, GroupEncoding}, Ciphersuite};
use dkg::{Participant, ThresholdParams, ThresholdKeys, Interpolation};

// Crafted bytes: t=1, n=1, i=1, Constant([1]), secret=0, share=identity
let mut buf = vec![];
let id = <Ristretto as Ciphersuite>::ID;
buf.extend(u32::try_from(id.len()).unwrap().to_le_bytes());
buf.extend(id);
buf.extend(1u16.to_le_bytes()); // t
buf.extend(1u16.to_le_bytes()); // n
buf.extend(1u16.to_le_bytes()); // i
buf.push(0); // Constant interpolation
buf.extend(Scalar::ONE.to_repr().as_ref());   // coefficient
buf.extend(Scalar::ZERO.to_repr().as_ref());  // secret_share = 0
buf.extend(EdwardsPoint::identity().to_bytes().as_ref()); // verification share

let keys = ThresholdKeys::<Ristretto>::read(&mut buf.as_slice()).unwrap();
assert!(bool::from(keys.group_key().is_identity()));
// group_key == identity ⇒ the corresponding private key is 0,
// so Schnorr signatures for this key are forgeable by anyone.
```
