### Title
Untrusted serialized Bitcoin outputs can claim arbitrary unspendable deposits - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput::read` deserializes the scalar offset, `TxOut`, and `OutPoint` independently without proving the outpoint exists or that the embedded output was produced by `Scanner` for the expected key. [1](#0-0) 

### Finding Description
A legitimate `ReceivedOutput` is normally created by `Scanner::scan_transaction`, which derives the offset only when a transaction's `script_pubkey` is registered for the scanner's key. [2](#0-1) 

The deserializer lacks that scanner context entirely, so arbitrary bytes can encode a victim-controlled Taproot script, any value, and a fabricated outpoint while retaining a valid in-memory `ReceivedOutput`. [1](#0-0) 

The Bitcoin `Output` wrapper inherits this behavior through `Output::read`, while `key()` reconstructs a plausible base key from the embedded script and offset and `balance()` reports the attacker-supplied amount. [3](#0-2) [4](#0-3) 

`SignableTransaction::new` then uses the supplied `output.value`, `offset`, and `outpoint` as spendable input data. [5](#0-4) 

### Impact Explanation
An unprivileged party can cause the wallet layer to report funds as received even though no corresponding spendable UTXO exists. If the fake record uses the victim's real Taproot script and corresponding offset, `SignableTransaction::multisig` accepts it because it only verifies that the offset-derived group key produces the recorded `script_pubkey`, not that the claimed outpoint resolves to that output on-chain. [6](#0-5) 

The resulting transaction is signed over the fabricated prevout metadata using `Prevouts::All`, but cannot be validly published when the outpoint is absent or does not contain the claimed `TxOut`. [7](#0-6) 

### Likelihood Explanation
The attack requires only control of bytes passed to `ReceivedOutput::read` or `Output::read`, both of which are explicit untrusted-input deserialization surfaces. The forged record needs only a canonical scalar, a consensus-decodable `TxOut`, and a consensus-decodable `OutPoint`; no signature, private key, validator control, or malformed curve encoding is required. [1](#0-0) [8](#0-7) 

### Recommendation
Do not treat deserialized `ReceivedOutput` values as scanner-authenticated facts. Accept an expected base key or `Scanner` during deserialization and reject records whose `script_pubkey` does not equal `p2tr_script_buf(expected_key + G * offset)`. [9](#0-8) [10](#0-9) 

Before accounting for or spending a loaded output, additionally verify that its outpoint exists, is unspent, and resolves to the exact embedded `TxOut`. [5](#0-4) 

### Proof of Concept
```rust
use bitcoin::{
  Amount, OutPoint, ScriptBuf, TxOut,
  consensus::encode::Encodable,
  hashes::Hash,
};
use bitcoin_serai::wallet::{p2tr_script_buf, ReceivedOutput};
use k256::{ProjectivePoint, Scalar};

let victim_key = ProjectivePoint::GENERATOR;
let victim_script = p2tr_script_buf(victim_key).unwrap();

let mut bytes = Vec::new();
// offset = 0
bytes.extend(Scalar::ZERO.to_repr().as_ref());

// Arbitrary amount assigned to the victim's Taproot script.
TxOut {
  value: Amount::from_sat(1_000_000),
  script_pubkey: victim_script,
}
.consensus_encode(&mut bytes)
.unwrap();

// Outpoint which need not exist on-chain.
OutPoint { txid: bitcoin::Txid::all_zeros(), vout: 0 }
  .consensus_encode(&mut bytes)
  .unwrap();

let forged = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();
assert_eq!(forged.value(), 1_000_000);
```

`forged` reports one BTC and passes the wallet's script/offset consistency check, despite being constructed entirely from attacker-supplied bytes rather than a scanned Bitcoin transaction. [1](#0-0) [6](#0-5)
