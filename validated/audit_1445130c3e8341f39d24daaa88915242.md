### Title
Bitcoin `get_outputs` applies the last transaction's origin/data to every output scanned in the block — ([File: processor/src/networks/bitcoin.rs])

### Summary
Analogous to CVE-2017-11114's "attacker-crafted input causes a read past the intended boundary," Serai's Bitcoin `get_outputs` reads transaction metadata (`tx.input[0]`'s spent output and `extract_serai_data`) past the boundary of the transaction that actually produced each scanned output. Because the accumulator `outputs` is never cleared per-transaction, every `ReceivedOutput` found in a block is stamped with the `presumed_origin` and `data` of whichever transaction was processed last, not the transaction that paid it.

### Finding Description
In `get_outputs`, `outputs` is declared once before iterating `block.txdata[1 ..]` and is never partitioned by transaction:

```rust
let mut outputs = vec![];
for tx in &block.txdata[1 ..] {
  for output in scanner.scan_transaction(tx) { ... outputs.push(output); }
  if outputs.is_empty() { continue; }
  // populate the outputs with the origin and data
  let presumed_origin = { let input = &tx.input[0]; ... };
  let data = Self::extract_serai_data(tx);
  for output in &mut outputs { ... }
}
``` [1](#0-0) 

Two defects result:

1. **Cross-transaction metadata bleed**: `for output in &mut outputs` mutates *all* outputs accumulated so far, not only those produced by the current `tx`. Each subsequent transaction in the block re-runs the population block (since `outputs` is non-empty once any match was found) and overwrites `presumed_origin` and `data` for outputs belonging to earlier, unrelated transactions. The final value is derived from `tx.input[0].previous_output` and the OP_RETURN/witness data of the *last* transaction in the block — which need not pay Serai at all.
2. **Unnecessary RPC/panic surface**: the population block executes for every transaction after the first Serai-paying one, including transactions with zero Serai outputs, fetching `tx.input[0]`'s parent over RPC and setting `presumed_origin` on already-finalized outputs.

`presumed_origin` is used to attribute funds to their origin (e.g., for refunds via `instruction_from_output`), and `data` carries the `InInstruction` for `External` outputs. Both are stored on the `Output` and later consumed by `Plan`/scheduler logic.

### Impact Explanation
An unprivileged party controls which transactions appear in a block and their ordering relative to other payments to Serai's scanner keys. By broadcasting a transaction positioned after a victim's deposit in the same block — with an attacker-chosen input (controlling `presumed_origin`) and attacker-chosen OP_RETURN/witness payload (controlling `data`) — the attacker overwrites the victim output's origin and instruction data. Concretely this can misattribute an `External` deposit's `InInstruction`/refund origin to data the depositor never sent, causing the processor to build plans (e.g., refunds or forwarding instructions) against metadata belonging to a different transaction — funds received under instructions the sender never authorized.

### Likelihood Explanation
Requires only that a block contain ≥2 transactions after a Serai-paying output is first detected — trivially satisfiable by any Bitcoin user who can broadcast a transaction (no miner cooperation needed beyond normal inclusion ordering, which the attacker can influence or simply wait for). No special access is required; the inputs are ordinary on-chain Bitcoin transactions.

### Recommendation
Scope the population block to the per-transaction results: collect `let tx_outputs: Vec<Output> = scanner.scan_transaction(tx).map(...)` and only populate/extend `outputs` when `tx_outputs` is non-empty, so `presumed_origin` and `data` are bound to the `tx` that created them. Restructure as:

```rust
for tx in &block.txdata[1 ..] {
  let mut tx_outputs = vec![];
  for output in scanner.scan_transaction(tx) { ... tx_outputs.push(...) }
  if tx_outputs.is_empty() { continue; }
  // compute presumed_origin and data for *this* tx, then apply only to tx_outputs
  outputs.extend(tx_outputs);
}
```

### Proof of Concept
1. Serai registers group key `K`; `scanner(key)` yields kinds {External, Branch, Change, Forwarded}.
2. Victim broadcasts tx `A` paying `address_from_key(K)` (External) with OP_RETURN data `d_v` and origin address `o_v`.
3. Attacker broadcasts tx `B` — any transaction, even paying an unrelated address — mined after `A` in the same block, whose `input[0]` spends an output with script `s_a` (→ `presumed_origin = Address::new(s_a)`) and whose OP_RETURN/witness encodes `d_a`.
4. `get_outputs` scans `A`, pushes the External output, populates it with `o_v`/`d_v`; then scans `B`, finds nothing new, but since `outputs` is non-empty re-executes the population block using `B`, overwriting the victim output's `presumed_origin` to `o_a` and — if the output's kind is `External` — its `data` to `d_a`.
5. The victim's deposit is reported with attacker-controlled origin/instruction data, and any downstream refund/instruction derived from `output.data()` or `output.presumed_origin()` operates on bytes from the wrong transaction.

```rust
  async fn get_outputs(&self, block: &Self::Block, key: ProjectivePoint) -> Vec<Output> {
    let (scanner, _, kinds) = scanner(key);

    let mut outputs = vec![];
    // Skip the coinbase transaction which is burdened by maturity
    for tx in &block.txdata[1 ..] {
      for output in scanner.scan_transaction(tx) {
        let offset_repr = output.offset().to_repr();
        let offset_repr_ref: &[u8] = offset_repr.as_ref();
        let kind = kinds[offset_repr_ref];

        let output = Output { kind, presumed_origin: None, output, data: vec![] };
        assert_eq!(output.tx_id(), tx.id());
        outputs.push(output);
      }

      if outputs.is_empty() {
        continue;
      }

      // populate the outputs with the origin and data
      let presumed_origin = {
        // This may identify the P2WSH output *embedding the InInstruction* as the origin, which
        // would be a bit trickier to spend that a traditional output...
        // There's no risk of the InInstruction going missing as it'd already be on-chain though
        // We *could* parse out the script *without the InInstruction prefix* and declare that the
        // origin
        // TODO
        let spent_output = {
          let input = &tx.input[0];
          let mut spent_tx = input.previous_output.txid.as_raw_hash().to_byte_array();
          spent_tx.reverse();
          let mut tx;
          while {
            tx = self.rpc.get_transaction(&spent_tx).await;
            tx.is_err()
          } {
            log::error!("couldn't get transaction from bitcoin node: {tx:?}");
            sleep(Duration::from_secs(5)).await;
          }
          tx.unwrap().output.swap_remove(usize::try_from(input.previous_output.vout).unwrap())
        };
        Address::new(spent_output.script_pubkey)
      };
      let data = Self::extract_serai_data(tx);
      for output in &mut outputs {
        if output.kind == OutputType::External {
          output.data.clone_from(&data);
        }
        output.presumed_origin.clone_from(&presumed_origin);
      }
    }

    outputs
  }
