### Title

Ed448 point decompression accepts torsion components, enabling forged Schnorr proofs - ([File: crypto/ed448/src/point.rs](crypto/ed448/src/point.rs))

### Summary

The Ed448 `GroupEncoding` implementation intends to reject points outside the prime-order subgroup, but `Point::is_torsion_free` is implemented as `(-P) + P == identity`, which is true for every valid group element. As a result, compressed Ed448 encodings of torsion-bearing points are accepted as `PrimeGroup` elements. Those points can then be supplied through public deserialization APIs such as `Ed448::read_G`, `SchnorrSignature::read`, `Commitments::read`, `EncryptedMessage::read`, and `DLEqProof`-carrying messages.

### Finding Description

`crypto/ed448/src/point.rs` defines:

```rust
fn is_torsion_free(&self) -> Choice {
  ((*self * (Scalar::ZERO - Scalar::ONE)) + self).is_identity()
}
```

This expression is always zero for any valid point: multiplying by `-1` produces `-P`, and adding `P` necessarily yields the identity. It does not test membership in the prime-order subgroup.

`Point::from_bytes` then accepts the decompressed point when `point.is_torsion_free()` returns true, so the intended torsion rejection is ineffective. This directly contradicts the crate's documented security boundary: Ed448 is described as “rejecting torsion to achieve a PrimeGroup definition.”

The analogous bug class is malformed compressed input crossing a deserialization boundary: a compressed encodings parser accepts an object that violates the invariant required by downstream cryptographic code.

### Impact Explanation

Ed448 has a non-trivial cofactor, and downstream code assumes `PrimeGroup` means decoded points are prime-order. Accepting torsion components breaks that invariant and enables proof/signature manipulations unavailable on a true prime-order group.

A concrete reachability path is:

- `Ed448::read_G` reads a fixed compressed representation and calls `Point::from_bytes`.
- `Point::from_bytes` accepts a non-prime-order point because `is_torsion_free` is tautological.
- `SchnorrSignature::<Ed448>::verify` evaluates `R + cA - sG == 0` without an additional torsion or subgroup check.
- An attacker can choose a torsion-bearing public key or nonce encoding and exploit the small-order component to satisfy verification relations without knowledge of a prime-order discrete logarithm.

The simplest special case is the identity point: the generic `Ciphersuite::read_G` accepts it, and `SchnorrSignature::read` likewise accepts it. For a verifier accepting identity as `A`, `(R = identity, s = 0)` satisfies `identity + c·identity - 0·G = identity` for every challenge. Other non-identity torsion points are also accepted because the subgroup test never rejects them.

This can also affect DLEq verification. `DLEqProof::verify` computes each nonce as `sG - cA`; if `A` carries a low-order component, the effective challenge space on that component is reduced, weakening the equality proof relative to the `PrimeGroup` contract.

### Likelihood Explanation

An unprivileged party can reach this by supplying compressed Ed448 point encodings to public parsing APIs. No malformed length field, unsafe memory access, leaked key, or malicious local node is required; the flaw is entirely in the algebraic validation of a validly encoded curve point.

Exploitability depends on the surrounding protocol accepting an attacker-selected Ed448 point as a public key, commitment, nonce, or proof element. Serai explicitly exposes these parsers for untrusted messages, and the PedPoP/FROST paths deserialize participant-controlled commitments and proof values. The bug is deterministic rather than probabilistic.

### Recommendation

Replace `is_torsion_free` with a real prime-order subgroup check, such as multiplying by the prime subgroup order and requiring the result to be the identity. For Ed448, the check should explicitly multiply by the large prime order of the intended subgroup, not merely test `P - P`.

Additionally:

- Reject the identity point in all public-key/proof deserialization paths where identity is not a valid semantic value, not only in `Curve::read_G`.
- Add regression vectors containing the known Ed448 torsion point already used by the test module, plus identity and representative low-order encodings.
- Assert `Point::from_bytes` rejects those encodings and `read_G`-based wrappers propagate the rejection.
- Audit call sites relying on `PrimeGroup` to ensure no caller assumes subgroup membership without validation.

### Proof of Concept

The existing test fixture already demonstrates the defect: `crypto/ed448/src/point.rs` constructs `old` from the “originally suggested generator which had torsion” and asserts `!old.is_torsion_free()`. Under the current implementation, that assertion is expected to fail because:

```rust
(old * -1) + old == identity
```

for every valid point, including torsion-bearing points.

A minimal serialized-input proof is to pass the compressed encoding of that known torsion point through:

```rust
<Point as GroupEncoding>::from_bytes(&encoding)
```

and observe `CtOption::is_some() == true`, despite the point not being torsion-free. Feeding the same encoding through `<Ed448 as Ciphersuite>::read_G` exposes the invalid point to the generic cryptographic APIs.
