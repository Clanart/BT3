### Title
`Scanner::scan_block` reports coinbase outputs as spendable `ReceivedOutput`s, though they cannot be spent for 100 blocks - (File: `networks/bitcoin/src/wallet/mod.rs`)

### Summary
The bug class is "funds accepted that cannot be paid/spent". `TieredFixedBounty` accepted arbitrary ERC20 deposits it could not distribute, locking funds until expiry. The Serai analog: `Scanner::scan_block` in the Bitcoin wallet scans the coinbase transaction alongside regular transactions and emits `ReceivedOutput`s for it, but coinbase outputs are immature and unspendable for 100 blocks. `ReceivedOutput` carries no maturity marker, and `SignableTransaction::new`/`multisig` have no way to detect that a provided prevout is an immature coinbase — the library accepts the output as spendable while any transaction spending it is consensus-invalid.

### Finding Description
`scan_transaction` matches outputs purely by `script_pubkey` and wraps any match into a `ReceivedOutput` (`networks/bitcoin/src/wallet/mod.rs:199-213`). `scan_block` iterates `block.txdata` including `txdata[0]`, the coinbase (`mod.rs:221-227`). The resulting `ReceivedOutput` is indistinguishable from a normal output — it has `offset`, `output`, `outpoint` only (`mod.rs:90-97`).

On the spend path, `SignableTransaction::new` takes `Vec<ReceivedOutput>` and builds `TxIn`s with `sequence: Sequence::MAX` and no maturity check (`send.rs:150-185`). `TransactionSignMachine::sign` produces a signature over `Prevouts::All` (`send.rs:373-390`). Nothing in either function can distinguish a coinbase prevout, so the wallet will happily construct and threshold-sign a transaction spending an immature coinbase output — which every Bitcoin node rejects (`bad-txns-premature-spend-of-coinbase`). The only guard is a doc comment on `scan_block` telling the caller to post-filter (`mod.rs:216-220`); the type system and API enforce nothing.

### Impact Explanation
An unprivileged miner (or mining pool) can craft a coinbase transaction paying the Serai multisig's P2TR address. That output is scanned, persisted, and reported as received funds, yet it cannot be spent for 100 blocks. If included in a spend plan, the resulting transaction is consensus-invalid: the signing ceremony produces a transaction that cannot be broadcast, and the "received" funds are locked until maturity — the same "deposited but not payable" shape as the source finding.

### Likelihood Explanation
Requires an attacker to mine a block paying the vault address, or a pool to do so incidentally. Scanning the coinbase is the default behavior of the public `scan_block` API, and the only mitigation is a documentation note rather than code. Medium likelihood for misuse; real-world exploitation requires block production.

### Recommendation
Either have `scan_block` skip `block.txdata[0]` (the doc comment already suggests scanning `txdata[1 ..]`), or mark `ReceivedOutput`s derived from coinbase transactions and enforce maturity in `SignableTransaction::new`/`multisig` — e.g., store a `coinbase: bool` on `ReceivedOutput` and reject inputs that are immature at construction time, so unscannable-for-spend outputs are never accepted as inputs.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res

  /// Scan a block.
  ///
  /// This will also scan the coinbase transaction which is bound by maturity. If received outputs
  /// must be immediately spendable, a post-processing pass is needed to remove those outputs.
  /// Alternatively, scan_transaction can be called on `block.txdata[1 ..]`.
  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }
