### Title
SIGHASH_SINGLE|ANYONECANPAY leaves the payout OP_RETURN unauthenticated, letting an attacker null out `payout_payer_operator_xonly_pk` and permanently block operator reimbursement - (File: core/src/verifier.rs, core/src/builder/transaction/operator_reimburse.rs)

### Summary
The user's payout signature (`SinglePlusAnyoneCanPay`) only commits to input 0 and output 0 of the payout transaction, leaving the anchor output and the operator-identifying OP_RETURN output completely unauthenticated. An attacker who observes an honest operator's unconfirmed payout transaction can rebroadcast a variant that keeps input 0/output 0 identical but replaces the OP_RETURN with garbage, and if that variant is the one that gets mined, `update_finalized_payouts` records `payout_payer_operator_xonly_pk = NULL` for that withdrawal, permanently breaking the DB binding that `PayoutCheckerTask::run_once` relies on to trigger operator reimbursement.

### Finding Description
The binding claimed to hold is:
`withdrawals.payout_payer_operator_xonly_pk == operator.signer.xonly_public_key` for the operator who actually funded withdrawal `idx`.

`create_payout_txhandler` builds the payout tx with output 0 = user payout, output 1 = anchor, output 2 = OP_RETURN(operator xonly pk): [1](#0-0) 

The withdrawal UTXO input is spent with the user's `SinglePlusAnyoneCanPay` signature, verified only against `sighash_type = SinglePlusAnyoneCanPay` (input 0 + output 0): [2](#0-1) 

By Bitcoin sighash semantics, `SIGHASH_SINGLE|ANYONECANPAY` commits only to input 0 and the output at the same index (output 0); all other outputs (anchor, OP_RETURN) and any additional inputs are unauthenticated and can be freely rearranged by anyone who has the signed witness for input 0. An attacker who observes the operator's broadcast (but unconfirmed) payout tx can copy the witness for input 0, keep output 0 byte-identical, and build a competing transaction with different funding inputs, a different anchor, and an OP_RETURN containing 32 zero bytes (or any bytes that fail `XOnlyPublicKey::from_slice`). If this attacker-controlled variant is the one that gets confirmed, `update_finalized_payouts` parses the OP_RETURN and stores `None`: [3](#0-2) [4](#0-3) 

`PayoutCheckerTask::run_once` is the sole automated trigger that causes the operator to call `handle_finalized_payout` (which builds/sends the kickoff and eventually reimburses the operator). It looks up unhandled payouts by exact equality against `operator.signer.xonly_public_key`: [5](#0-4) [6](#0-5) 

Because the query filters `WHERE payout_payer_operator_xonly_pk = $1`, a `NULL` value can never match any operator's xonly pubkey, so the operator's own automation never picks up this withdrawal, `handle_finalized_payout` is never invoked, and no kickoff is ever sent for it. Since the OP_RETURN bytes are now permanently fixed on-chain (the tx is mined), no later resync can "fix" this record — the corruption is irreversible for that withdrawal index. Note this failure occurs before/independently of `is_kickoff_malicious` (verifier.rs:1859-1915), which is a separate check that only matters if a kickoff is ever sent; here no kickoff is sent at all, so that guard is irrelevant. `Verifier::is_deposit_valid`, `SECP.verify_schnorr` and `SPV::verify` all operate correctly and do not protect the OP_RETURN field, since it is intentionally excluded from the signed sighash by design (`SinglePlusAnyoneCanPay`).

### Impact Explanation
The user still receives their payout (output 0 is protected and unchanged), so no funds are stolen from the withdrawal itself. However, the operator who genuinely fronted the payout is permanently prevented from having their reimbursement flow triggered for that withdrawal index, because the DB record that `PayoutCheckerTask` depends on can never equal their pubkey again once nulled. This matches the Critical category "an honest operator permanently unable to be reimbursed." The attack is repeatable per withdrawal/per operator: any observed unconfirmed payout transaction from any operator, for any withdrawal, is a target, so the blast radius spans all operators and all withdrawals processed by the bridge.

### Likelihood Explanation
The attacker needs only to: (1) monitor the Bitcoin mempool for payout transactions (public information), (2) extract the witness of input 0, (3) construct and broadcast a competing transaction with identical input 0/output 0 but a corrupted OP_RETURN, funded by their own UTXOs/fees, and (4) get it mined ahead of or instead of the honest broadcast. This requires no compromise of any protocol keys, no verifier/operator privilege, and only standard Bitcoin transacting ability plus fee-paying BTC — consistent with the "unprivileged attacker" threat model. The main uncertainty is Bitcoin mempool propagation/relay policy (RBF signaling of the sequence used in `create_payout_txhandler`, whether nodes enforce first-seen relay vs. full-RBF), which affects how reliably the attacker's variant reaches miners first; this is a network-level factor outside this repository's code and was not fully verified (the exact `DEFAULT_SEQUENCE` constant value used for input 0 was not confirmed within the available context). Regardless of propagation nuances, the underlying vulnerability — the OP_RETURN and anchor outputs being unauthenticated by the payout sighash — is a certain, reproducible property of the transaction construction itself.

### Recommendation
Do not rely on an unauthenticated OP_RETURN output to identify the paying operator. Either (a) have the operator additionally co-sign/commit to the OP_RETURN content out-of-band (e.g., store the operator identity keyed by the payout txid and input 0 outpoint rather than by parsing mutable transaction bytes), or (b) have `PayoutCheckerTask` (and any DB write of `payout_payer_operator_xonly_pk`) fall back to matching by `withdrawal_utxo`/`deposit_id` plus operator claim rather than requiring an on-chain OP_RETURN parse to succeed and match exactly, so that a corrupted/missing OP_RETURN does not silently and permanently disable the reimbursement trigger for the operator who actually funded the payout.

Test plan (assertions on both sides of the equality):
1. Set up a deposit and withdrawal as in existing e2e helpers (`core/src/test/common/setup_utils.rs::generate_withdrawal_transaction_and_signature`) to get a `dust_utxo`, signed `SinglePlusAnyoneCanPay` witness, and `output_txout`.
2. Build the honest payout tx via `create_payout_txhandler` with the operator's real xonly pk in the OP_RETURN; do not broadcast it yet.
3. Build an "attacker" variant tx reusing the same input 0 (same outpoint + witness) and output 0 (byte-identical), but replace output 2 (OP_RETURN) with `[0u8; 32]` and fund with a different attacker-controlled input for fees.
4. Broadcast only the attacker variant; mine it to finality.
5. Call `Verifier::update_finalized_payouts` (via the normal block sync path) and assert:
   - `db.get_payout_info_from_move_txid(...)` returns `operator_xonly_pk == None` (left side becomes `None`).
6. Call `PayoutCheckerTask::run_once` for the honest operator and assert it returns `Ok(false)` (never finds the unhandled payout), demonstrating `self.operator.signer.xonly_public_key != None`, i.e., the binding is permanently broken and reimbursement is never triggered.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,

    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {

            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {

                        .0,

                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
