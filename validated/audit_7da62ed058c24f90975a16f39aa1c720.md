### Title
Operator reimbursed via automated PayoutCheckerTask for a payout it never funded due to unauthenticated OP_RETURN operator attribution - (File: core/src/task/payout_checker.rs)

### Summary
The withdrawal signature is enforced to use `SIGHASH_SINGLE|ANYONECANPAY` [4](#0-3) , which commits only to the dust input and the user's payout output, leaving both the funding input(s) and the OP_RETURN operator attribution byte string completely unauthenticated. Any unprivileged actor who can broadcast Bitcoin transactions can fund the payout output themselves and write an arbitrary, unrelated operator's x-only pubkey into the OP_RETURN of `create_payout_txhandler` [5](#0-4) . `PayoutCheckerTask` on that framed operator's own node then blindly picks this up via `get_first_unhandled_payout_by_operator_xonly_pk` and automatically issues a real kickoff/reimbursement claim for a payout that operator never funded.

### Finding Description
The broken binding: `MOVE_TXID (deposit A's vault identity, from storage proof) == ATTRIBUTION_OPERATOR (whoever actually supplied real BTC to pay the withdrawal)` is never checked anywhere on the money-movement side. `deposit_constant` in `circuits-lib/src/bridge_circuit/mod.rs`/`storage_proof.rs` only checks that the payout tx correctly spends the specific withdrawal outpoint recorded on Citrea for that deposit (via `verify_storage_proofs` and the `assert_eq!` against `payout_spv.transaction.input[payout_input_index].previous_output`) [6](#0-5) ; it never checks that `operator_xonlypk` parsed from the OP_RETURN [7](#0-6)  corresponds to whoever actually supplied the real BTC value in the payout tx's other input(s).

Because the sighash is `SinglePlusAnyoneCanPay`, the OP_RETURN output (added after the covered output) and any additional funding inputs are outside the signed message, so an unprivileged attacker can construct and broadcast a valid payout tx that: (1) satisfies the exact withdrawal outpoint/amount for deposit A recorded on Citrea, funded with the attacker's own BTC, and (2) carries operator X's (an honest, uninvolved operator's) x-only pubkey in the OP_RETURN.

On-chain, `update_finalized_payouts` parses that OP_RETURN with no further validation and records `payout_payer_operator_xonly_pk = X` in the `withdrawals` table [8](#0-7) . Operator X's own `PayoutCheckerTask::run_once` then queries `get_first_unhandled_payout_by_operator_xonly_pk(X)`, finds this attacker-funded payout, and calls `self.operator.handle_finalized_payout(...)` which builds and signs a genuine kickoff transaction and enters the reimbursement/round flow for deposit A on X's behalf [9](#0-8) . The subsequent verifier-side sanity checks (`is_kickoff_malicious`, `send_asserts`'s `payout_op_xonly_pk != kickoff_data.operator_xonly_pk` check) only compare the OP_RETURN-derived DB value against the kickoff sender's own key [10](#0-9) [11](#0-10)  - since X is genuinely the kickoff sender and the DB already (wrongly) says X paid, these checks pass. Nothing in the presigned transaction graph, MuSig2 session, or bridge_circuit binds "who actually supplied the funding input(s) of the payout tx" to "who is named in the OP_RETURN"; the deposit_constant hash the question focuses on binds move_txid to the OP_RETURN operator only for the purpose of matching a pre-committed additional-disprove script for whichever operator's round the kickoff is spent from - it is not, and never was, a proof of who funded the payout.

### Impact Explanation
Operator X ends up spending its own round-tx collateral / kickoff sequence and claiming a real BTC reimbursement (via the Reimburse tx path) for a withdrawal it never actually funded, while the attacker's BTC (used to pay the user) is not reimbursed to the attacker at all - X's collateral-backed reimbursement flow is triggered by attacker-controlled data. This matches the Critical category "an operator reimbursed for a payout it never funded." It is repeatable against any operator for any withdrawal the attacker chooses to front with someone else's pubkey, and also permanently denies the withdrawal to whichever operator might have legitimately intended to front it (the withdrawal UTXO is spent once). The blast radius covers every operator running `PayoutCheckerTask` with automation enabled and every deposit/withdrawal, since the attack requires nothing but observing an unhandled withdrawal and broadcasting a funded payout tx with a forged OP_RETURN.

### Likelihood Explanation
Preconditions: automation-enabled operators running `PayoutCheckerTask`; a pending Citrea withdrawal whose `SinglePlusAnyoneCanPay` signature and dust input are already known/derivable by anyone with gRPC/Citrea read access (the signature and outpoint for withdrawals are effectively public once the withdraw request is submitted, since `ANYONECANPAY` means the attacker doesn't need any private data to add funding). Cost is simply the withdrawal amount worth of BTC plus fees, which the attacker fully spends (this is a griefing-with-collateral-effect attack, not a profit-extraction attack for the attacker, but the framed operator is harmed and the attacker only needs to want to burn funds to damage a specific operator, or could be an operator harming a competitor at attacker cost). Fully reproducible with `cargo test` in circuits-lib/core without mainnet or live Citrea by mocking the DB rows and OP_RETURN mismatch.

### Recommendation
Bind attribution cryptographically to funding: require the operator claiming reimbursement to prove they supplied the payout's value, e.g. by requiring the OP_RETURN commitment (or an accompanying signature) to be covered by a signature from the named operator's own key over the full payout tx (all inputs/outputs), or by requiring `PayoutCheckerTask`/`handle_finalized_payout` to independently verify that at least one non-dust input of the payout tx is provably controlled/funded by the operator itself (e.g., checking that the operator's own wallet indeed broadcast it, or moving to a scheme where the operator pre-registers or signs the specific payout tx before broadcast so an unrelated third party cannot inject a foreign pubkey into the OP_RETURN of a still-unsigned-for-that-part transaction).

### Proof of Concept
1. In `core/src/test`, set up two operators (X = honest, attacker = no collateral) sharing a deposit A already registered on Citrea with a pending withdrawal (`withdrawal_utxo`, `SinglePlusAnyoneCanPay` signature `sig`, correct `output_txout`).
2. Have the "attacker" (any Bitcoin RPC caller, not operator X) build the transaction via `create_payout_txhandler(input_utxo, output_txout, X.xonly_public_key, sig, network)` (using X's pubkey though X never called this), fund it with `fund_raw_transaction` using attacker's own wallet, and broadcast it directly via RPC (bypassing operator X's `withdraw` gRPC entirely).
3. Mine to finality; confirm `update_finalized_payouts` records `payout_payer_operator_xonly_pk = X` for withdrawal A in the DB even though X's process never called `withdraw`/`create_payout_txhandler`.
4. Run X's `PayoutCheckerTask::run_once` and assert it returns `Ok(true)`, that `handle_finalized_payout` produced a real `kickoff_txid`, and that `is_kickoff_malicious` returns `false` for that kickoff, demonstrating X's collateral-backed reimbursement flow proceeds for a payout it never funded - asserting on both sides of the equality: `db.get_payout_info_from_move_txid(move_txid).0 == Some(X)` (ATTRIBUTION_OPERATOR) while `attacker_broadcast_the_funding_tx == true` and `X_never_called_withdraw == true` (i.e. MINT_AUTHORITY move_txid for deposit A is genuinely bound to X's claim, but X did not supply the funds), showing the mismatch is never caught.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
