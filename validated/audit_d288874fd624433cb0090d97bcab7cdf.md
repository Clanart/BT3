### Title
Attacker-Controlled Remote Spoofs `WWW-Authenticate` Header to Force Unauthorized GitHub Enterprise OAuth Sign-In - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
The report's underlying bug class is "a critical routing decision is made from data the attacker fully controls, with no independent verification, so the wrong action is taken and something sensitive is exposed/misdirected" (there, `tokenDistribution`; here, the classification of a git remote as a trusted "GitHub"/"enterprise" endpoint). In GitHub Desktop's git-credential trampoline, `getEndpointKind()` in [1](#0-0)  trusts the `wwwauth[*]` values that Git forwards from a remote server's HTTP `WWW-Authenticate` response header as a "happy path" to decide if a host is GitHub, without any cryptographic or independent verification of that claim.

### Finding Description
When Git performs an HTTP(S) operation (`clone`/`fetch`/`push`) against a remote and receives a `401` response, it captures any `WWW-Authenticate` header(s) and passes them to the configured credential helper as `wwwauth[N]=...` fields on stdin [2](#0-1) . Desktop's `getEndpointKind()` treats a header value containing `realm="GitHub"` as sufficient proof that the endpoint is a GitHub Enterprise host, short-circuiting the actual verification that would otherwise happen via `isGitHubHost()` (which performs a real network probe against `/meta` and checks for the `x-github-request-id` response header) at [3](#0-2) .

Because this `realm` string is attacker-supplied HTTP response content from a git remote the user added (or a malicious proxy/MITM on an unencrypted or attacker-controlled path), an attacker fully controls the value that decides `endpointKind`. In `getCredential()`, once `endpointKind !== 'generic'` and no existing account matches that endpoint, Desktop calls `ui.promptForGitHubSignIn(endpoint)` [4](#0-3) , which in turn calls `dispatcher.beginEnterpriseSignIn(cb)` followed by `dispatcher.setSignInEndpoint(origin)` [5](#0-4) . This starts a full OAuth "Sign in to GitHub Enterprise" flow (`SignInStore.setEndpoint` → `SignInStore.authenticateWithBrowser` → `shell.openExternal(getOAuthAuthorizationURL(...))`) directed at the attacker-controlled host [6](#0-5) .

The corrupted value is the `endpointKind` classification result: instead of correctly falling into `generic` (a simple username/password prompt, scoped to that single host), the attacker forces `enterprise` classification purely by echoing a crafted `WWW-Authenticate` header, without needing to actually run GitHub Enterprise Server software. Existing guards do not stop this: the WWW-Authenticate check is deliberately placed *before* the real `isGitHubHost()` probe as a shortcut "to avoid making a request", so a spoofed header bypasses the one check (`x-github-request-id`) that would otherwise catch it.

### Impact Explanation
This results in an unauthorized/unintended OAuth sign-in flow (`beginEnterpriseSignIn` + browser-based OAuth) being triggered for an arbitrary attacker-controlled host that the user never asked to authenticate against, satisfying the "unauthorized OAuth or account binding" impact category. If the user completes the flow, a new "GitHub Enterprise" `Account` is bound into Desktop's `AccountsStore` for the attacker's host and is subsequently used by `findGitHubTrampolineAccount` to auto-supply credentials for future git operations to that same origin, and the account can also surface in other Desktop UI/API-driven flows scoped to that endpoint.

### Likelihood Explanation
The attacker only needs to control (or be a MITM for) a single git remote that the victim already interacts with (clone/fetch/push over HTTP(S)); no leaked credentials, local access, or malware are required. Returning a `401` with a crafted `WWW-Authenticate: Basic realm="GitHub"` header is trivial for any HTTP server the attacker operates, so this is fully attacker-triggerable from the network/remote side of a normal git operation.

### Recommendation
Do not trust the `WWW-Authenticate` `realm` value as sufficient evidence of a GitHub host. Either remove this shortcut entirely and always fall back to the network-verified `isGitHubHost()` check, or treat a `realm="GitHub"` match only as a weak hint that still requires the `isGitHubHost()` verification (checking `x-github-request-id`) before classifying the endpoint as `enterprise` and before triggering `promptForGitHubSignIn`.

### Proof of Concept
1. Attacker stands up an HTTPS git server at `https://evil.example.com/foo.git` and adds it as a remote the victim is asked to clone/fetch/push.
2. When Git attempts authenticated access, the attacker's server responds `401 Unauthorized` with header `WWW-Authenticate: Basic realm="GitHub"`.
3. Git forwards this to Desktop's credential helper as `wwwauth[0]=Basic realm="GitHub"` on the `get` command.
4. `getEndpointKind()` matches `realm="GitHub"` and returns `'enterprise'` without calling `isGitHubHost()` [7](#0-6) .
5. Since no account is stored for `evil.example.com`, `getCredential()` calls `ui.promptForGitHubSignIn('https://evil.example.com/...')`, which shows a "Sign in to your GitHub Enterprise" dialog and, on submission, opens an OAuth authorize URL and stores a resulting `Account` bound to `evil.example.com` in Desktop's account store [5](#0-4) .

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {

      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }
