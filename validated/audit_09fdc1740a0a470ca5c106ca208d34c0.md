**Rationale:**

`isWebFlowCommitter` only returns `true` when the commit's committer `name`/`email` exactly match GitHub's known web-flow bot identities (`GitHub`/`noreply@github.com` for dotcom, or `GitHub Enterprise` for GHES) and the endpoint matches the repository's endpoint [1](#0-0) . An attacker can certainly forge a local commit's committer name/email to match these values (git committer identity is just metadata), but this only affects whether a *duplicate avatar* for the committer is appended in `getAvatarUsersForCommit` [2](#0-1) .

Critically, this codebase has no "verified GitHub" signature/verification badge tied to `isWebFlowCommitter` or to the avatar list. A search for `verified` across the repo shows only unrelated matches (email verification in git config, account store auth, etc.) — there is no GPG/commit-signature verification UI gated by this function [3](#0-2) . The consumers of `getAvatarUsersForCommit` (`CommitListItem`, `expandable-commit-summary.tsx`, `commit-list.tsx` tooltip) only use it to render avatar images and author attribution text — a cosmetic UI feature, not a trust/security signal [4](#0-3) .

Furthermore, the actual commit author (always shown, never suppressed) and commit summary/SHA are unaffected by this logic — so no identity is truly "hidden" from the commit view, only a potentially-duplicate committer avatar is omitted, matching the intended behavior for real GitHub web-flow merge commits (to avoid always showing a spurious "GitHub" bot avatar on every PR merge). Nothing about what the user actually commits/pushes is altered — `isWebFlowCommitter`'s result never touches commit content, git objects, or push/sign flows. This does not meet the required impact bar (code execution, file read/write outside repo, credential exfiltration, unauthorized OAuth, IPC/sandbox escape, or silent corruption of committed/pushed content).

```typescript
export function isWebFlowCommitter(
  commit: Commit,
  gitHubRepository: GitHubRepository
) {
  if (!gitHubRepository) {
    return false
  }

  const endpoint = gitHubRepository.owner.endpoint
  const { name, email } = commit.committer

  if (
    endpoint === getDotComAPIEndpoint() &&
    name === 'GitHub' &&
    email === 'noreply@github.com'
  ) {
    return true
  }

  if (endpoint !== getDotComAPIEndpoint() && name === 'GitHub Enterprise') {
    // We can't assume that the email address will match any specific format
    // here since the web flow committer email address on GHES is the same as
    // the noreply email which can be configured by domain administrators so
    // we'll just have to assume that for a GitHub hosted repository (but not
    // GitHub.com) a commit author of the name 'GitHub Enterprise' is the web
    // flow author.
    //
    // Hello future contributor: Turns out the web flow committer name is based
    // on the "flavor" of GitHub so it's possible that you're here wondering why
    // this isn't working and chances are it's because we've updated the
    // GHES branding or introduced some new flavor.
    return true
  }

  return false
```
