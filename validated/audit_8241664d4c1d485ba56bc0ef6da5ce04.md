### Title
Unvalidated attacker-controlled DataLayer mirror URLs enable Server-Side Request Forgery - (File: `chia/data_layer/data_layer.py`, `chia/data_layer/download_data.py`, `chia/data_layer/data_layer_wallet.py`)

### Summary
The referenced GitLab SSRF (CVE-2021-22178) let an attacker supply a URL that GitLab's server would fetch on its behalf (Prometheus integration). Chia's DataLayer has an analogous pattern: mirror URLs are read from arbitrary on-chain memo data attached to a fixed, publicly spendable "mirror" puzzle, are never validated for scheme/host, and are later fetched by the local `DataLayer` service via outbound HTTP requests.

### Finding Description
Any coin whose puzzle hash equals `create_mirror_puzzle().get_tree_hash()` (a fixed, globally known puzzle hash — `MIRROR_PUZZLE_HASH`) is treated by every node's wallet as a "mirror" declaration for whatever `launcher_id` is encoded in its memos: [1](#0-0) 

`DataLayerWallet.coin_added` watches for coins with this exact puzzle hash, decodes `launcher_id` and a list of raw URL strings straight from the spend's memos, and — as long as the `launcher_id` is already tracked by that node's wallet (e.g. because the node subscribes to or owns that DataLayer store) — persists those URLs as a legitimate mirror record, with **no validation of URL scheme/host and no requirement that the spender own or control the target singleton**: [2](#0-1) 

Any unprivileged spend-bundle submitter can trigger this: they only need to include a `CREATE_COIN` condition to `MIRROR_PUZZLE_HASH` with memos `[launcher_id, url_bytes, ...]` in a standard, self-funded spend — no special authority over the targeted DataLayer store is required.

Once such a mirror is confirmed, `DataLayer.update_subscriptions_from_wallet` pulls these attacker-chosen URLs from wallet RPC into the local subscription table for that store: [3](#0-2) 

The periodic sync loop then uses these URLs to issue outbound requests via `fetch_and_validate` → `insert_from_delta_file` → `http_download`: [4](#0-3) 

`http_download` performs a raw `aiohttp` GET to `server_info.url + "/" + filename` with no restriction on scheme, host, or IP range (no blocking of loopback/link-local/internal addresses): [5](#0-4) 

This is the same bug class as the GitLab report: a low-privilege actor supplies a URL that is stored server-side and later fetched by the victim's own backend process, without host/scheme allowlisting.

### Impact Explanation
A node's local `DataLayer` process can be coerced into making outbound HTTP requests to attacker-chosen destinations (e.g., cloud metadata endpoints, internal admin services, `localhost` ports for the node's own RPC/S3-plugin daemons, or other internal-network hosts), purely by an unprivileged party broadcasting a normal spend bundle. This can be used to probe/attack internal services reachable from the DataLayer host, exfiltrate response data indirectly (via error/log behavior and file-size limits), or perform internal network reconnaissance/port scanning against infrastructure the victim node can reach but the attacker cannot reach directly. This maps to the "spend-triggered transaction-processing" and internal-service-reachable class of impact accepted by the validation rules.

### Likelihood Explanation
No signature or authorization is needed beyond a valid, self-funded spend bundle creating a coin at the fixed `MIRROR_PUZZLE_HASH` with attacker-chosen memos; the only gating condition is that the `launcher_id` in the memo already be tracked by the target's wallet (true for any node subscribing to or owning that DataLayer store, which is a common, discoverable condition for popular/public stores). The URL itself is never validated for scheme or destination before being dereferenced by `http_download`.

### Recommendation
Validate and restrict mirror URLs before persisting or dereferencing them: enforce an `http(s)` scheme allowlist, reject loopback/link-local/private/multicast/metadata-service IP ranges (and hostnames resolving to them) both when storing mirrors in `DataLayerWallet.coin_added`/`dl_wallet_store.py` and again at fetch time in `http_download`/`download_file`. Consider requiring mirror URLs to be pinned to an operator-approved allowlist rather than trusting arbitrary on-chain memo content.

### Proof of Concept
1. Attacker identifies a `launcher_id` for a DataLayer store that is tracked by many nodes (e.g., a popular public store).
2. Attacker crafts and broadcasts an ordinary spend bundle from a coin they own, adding a `CREATE_COIN` condition to `MIRROR_PUZZLE_HASH` (`create_mirror_puzzle().get_tree_hash()` in `chia/wallet/db_wallet/db_wallet_puzzles.py`) with memos `[launcher_id, b"http://169.254.169.254/latest/meta-data/"]` (or any internal target URL/port).
3. Once the spend confirms, any node tracking `launcher_id` picks it up in `DataLayerWallet.coin_added` (`chia/data_layer/data_layer_wallet.py:775-800`) and stores it as a mirror via `dl_wallet_store.add_mirror`.
4. On the next sync cycle, `DataLayer.update_subscriptions_from_wallet` and `fetch_and_validate`/`update_subscription` (`chia/data_layer/data_layer.py`) select this URL and call `http_download` (`chia/data_layer/download_data.py:298-324`), causing the victim node to issue an outbound HTTP GET to the attacker-chosen internal target.

def create_mirror_puzzle() -> Program:
    return P2_PARENT.curry(Program.to(1))


MIRROR_PUZZLE_HASH = create_mirror_puzzle().get_tree_hash()


def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
