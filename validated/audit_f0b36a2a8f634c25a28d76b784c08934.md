### Title
Auction bid's `MaxGasPrice` field is not committed by either the searcher or auctioneer EIP-712/ECDSA signature under `AuctionVersionV2`, allowing signature-preserving tampering of bid data - ([File: kaiax/auction/eip712.go])

### Summary
This is the same class of bug as the Superfluid "fake ctx" exploit: a data structure that flows through multiple trust boundaries (host → agreement in Superfluid; bidder → bid-pool → block-builder in Kaia) is only partially authenticated. In Superfluid, `ctx` was decoded without re-validating its stamp against the field set the host actually signed. In Kaia's auction module, `BidData.MaxGasPrice` is a real, wire-format field of the `Bid`/`BidData` struct that is silently excluded from the EIP-712 struct hash the searcher signs (and from the message the auctioneer signs), so it can be forged/altered after signing without invalidating either signature.

### Finding Description
`kaiax/auction/bid.go` defines `BidData` with a `MaxGasPrice *big.Int` field alongside `TargetTxHash`, `Sender`, `Nonce`, `Bid`, `CallGasLimit`, `Data`, etc. [1](#0-0) 

`kaiax/auction/eip712.go` defines two EIP-712 type strings/typehashes for the `AuctionTx` struct: the V2 type (`auctionType`) omits `maxGasPrice`, while the V3 type (`auctionTypeV3`) includes it. [2](#0-1) 

The default `Bid.EncodeData()` (used for `AuctionVersionV2`) never touches `b.MaxGasPrice` at all - it only hashes `TargetTxHash`, `BlockNumber`, `Sender`, `To`, `Nonce`, `Bid`, `CallGasLimit`, and `Data`: [3](#0-2) 

`GetHashTypedData` dispatches on the `version` string; only `AuctionVersionV3` uses the `bidV3` encoder that folds in `MaxGasPrice`. Any other/legacy/unknown version falls back to the V2 encoder that excludes it: [4](#0-3) 

`Bid.ValidateSearcherSig` simply recovers the signer from this (possibly `MaxGasPrice`-excluding) digest and checks it equals `b.Sender` - it never separately checks that `MaxGasPrice` is bound to anything: [5](#0-4) 

Worse, `Bid.ValidateAuctioneerSig`/`GetEthSignedMessageHash` do not sign over `BidData` at all - they sign over the raw bytes of `SearcherSig`: [6](#0-5) [7](#0-6) 

So the auctioneer's authentication chain is: "I trust whatever `SearcherSig` bytes I saw," not "I trust these specific `BidData` field values." Any field not covered by the searcher's own EIP-712 digest (i.e., `MaxGasPrice` under V2) is therefore unauthenticated by *both* signatures simultaneously, exactly mirroring Superfluid's situation where the host trusted an internally-consistent-looking `ctx` blob without re-verifying which fields were actually inside the stamped/authenticated portion.

Reachability: an unprivileged auction bidder submits a bid via the public RPC entrypoint `SubmitBid`, which decodes `BidInput` into a `Bid` and inserts it into the pool after `validateBid`/`validateBidSigs` - both of which only check signature *validity*, not field-completeness of what was signed: [8](#0-7) [9](#0-8) 

The stored `Bid` (including its `MaxGasPrice`) is later used to build the winning auction transaction via `GetBidTxGenerator`/`EncodeAuctionCallData` for on-chain settlement: [10](#0-9) 

### Impact Explanation
If a node/relay/proposer path operates under (or is downgraded to) `AuctionVersionV2`, `MaxGasPrice` travels with the bid but is not cryptographically bound to the searcher's identity or to the auctioneer's approval. Any party that can influence the `Bid` object between signing and pool insertion/execution (e.g., a malicious relay, a compromised or buggy RPC intermediary, or the bidder itself re-submitting a "signature-preserving" mutated bid) can alter `MaxGasPrice` used downstream for fee/price-related decisions in auction settlement without invalidating `SearcherSig` or `AuctioneerSig`. This falls under "fee or fee-delegation abuse" / "auction settlement theft" categories the task explicitly allows, since it lets an attacker manipulate a value that both signers believed was authenticated.

### Likelihood Explanation
Likelihood is High whenever `AuctionVersionV2` (`"0.0.1"`) is the active/configured version, since the vulnerable code path (`b.EncodeData()`/legacy typehash) is the default fallback for any version string other than exactly `"0.0.2"`, including empty/unset strings. The path is reachable purely through the public `SubmitBid` RPC by any auction bidder — no privileged role required. I was not able to fully trace, within the available tool budget, every downstream consumer of `BidData.MaxGasPrice` (e.g., in `blockchain/system/auction.go`) to confirm the exact on-chain financial consequence of a forged value, so the precise monetary impact of tampering this specific field is not fully verified — this should be confirmed by inspecting `blockchain/system/auction.go` and `kaiax/auction/impl/execution.go` where `MaxGasPrice` is consumed.

### Recommendation
- Always include `MaxGasPrice` in the EIP-712 struct hash regardless of version (make V2 struct hash a strict subset only when the entry point contract truly predates the field), or better, deprecate/remove the version-gated omission entirely.
- Have the auctioneer's signature cover the full `BidData` (or at least a hash of all fields, including `MaxGasPrice`) rather than merely re-signing the searcher's raw signature bytes, so the auctioneer's approval is bound to the actual bid content, not just to "a signature that once existed."
- Add an explicit check in `validateBidSigs` that rejects bids whose `MaxGasPrice` is non-zero/set when the negotiated `auctionEntryPointVersion` is V2 (since V2 signers never committed to it), preventing any use of an unauthenticated field.

### Proof of Concept
1. Configure/observe a bid pool operating with `auctionEntryPointVersion = AuctionVersionV2` ("0.0.1").
2. A searcher signs a legitimate `Bid` (with `MaxGasPrice = nil`/some value X) using `GetHashTypedData(chainId, verifyingContract, AuctionVersionV2)` → produces `SearcherSig`.
3. The auctioneer signs `GetEthSignedMessageHash()`, i.e., only over the bytes of `SearcherSig`, producing `AuctioneerSig`.
4. Any party in possession of the fully-signed `Bid` object (relay, RPC intermediary, or the bidder itself before final submission) changes `BidData.MaxGasPrice` to an arbitrary value Y.
5. Submit the mutated bid to `SubmitBid`. `validateBid` → `validateBidSigs` → `ValidateSearcherSig` recomputes the V2 digest (which never included `MaxGasPrice`), still recovers `b.Sender` correctly, and `ValidateAuctioneerSig` still recovers the auctioneer correctly (it only checked `SearcherSig` bytes, unchanged). Both checks pass.
6. `insertBid` stores the tampered bid; downstream logic (`GetBidTxGenerator`, `EncodeAuctionCallData`, execution) operates on the attacker-controlled `MaxGasPrice` value Y as if it had been authenticated by both signers.

func (b *Bid) ValidateSearcherSig(chainId *big.Int, verifyingContract common.Address, version string) error {
	if chainId == nil {
		return ErrNilChainId
	}

	if common.EmptyAddress(verifyingContract) {
		return ErrNilVerifyingContract
	}

	digest := b.GetHashTypedData(chainId, verifyingContract, version)

	recoveredSender, err := getSigner(b.SearcherSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover searcher sig: %v", err)
	}

	if recoveredSender != b.Sender {
		return fmt.Errorf("invalid searcher sig: expected %v, calculated %v", b.Sender.String(), recoveredSender.String())
	}

	return nil
}

func (b *Bid) EncodeData() []byte {
	encoded := make([]byte, 0)
	encoded = append(encoded, b.TargetTxHash.Bytes()...)
	encoded = append(encoded, common.LeftPadBytes(common.Int64ToByteBigEndian(b.BlockNumber), 32)...)
	encoded = append(encoded, common.LeftPadBytes(b.Sender.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(b.To.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(common.Int64ToByteBigEndian(b.Nonce), 32)...)
	encoded = append(encoded, common.LeftPadBytes(b.Bid.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(common.Int64ToByteBigEndian(b.CallGasLimit), 32)...)
	encoded = append(encoded, crypto.Keccak256Hash(b.Data).Bytes()...)
	return encoded
}

// GetHashTypedData returns the EIP-712 digest for the bid.
// version must match the on-chain AUCTION_VERSION of the entry-point contract
// the bid targets; "0.0.2" selects the v3.0 struct typehash (with maxGasPrice),
// any other value falls back to the v2.1 typehash.
func (b *Bid) GetHashTypedData(chainId *big.Int, verifyingContract common.Address, version string) []byte {
	if chainId == nil {
		return nil
	}

	domain := EIP712Domain{
		EIP712DomainTypeHash: eip712TypeHash,
		NameHash:             auctionNameHash,
		VersionHash:          crypto.Keccak256Hash([]byte(version)),
		ChainId:              chainId,
		VerifyingContract:    verifyingContract,
	}

	domainSeparator := EncodeEIP712(domain)

	var structHash []byte
	if version == AuctionVersionV3 {
		structHash = EncodeEIP712(bidV3{b})
	} else if version == AuctionVersionV2 {
		structHash = EncodeEIP712(b)
	} else {
		// Unknown version: default to v2.1 typehash.
		structHash = EncodeEIP712(b)
	}

	return crypto.Keccak256([]byte{0x19, 0x01}, domainSeparator, structHash)

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)
}

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}

func (a *AuctionModule) GetBidTxGenerator(tx *types.Transaction, bid *auction.Bid) *builder.TxOrGen {
	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId           = a.InitOpts.ChainConfig.ChainID
			signer            = types.LatestSignerForChainID(chainId)
			auctionEntryPoint = a.bidPool.GetAuctionEntryPoint()
			key               = a.InitOpts.NodeKey
		)

		data, err := system.EncodeAuctionCallData(bid, a.bidPool.GetAuctionEntryPointVersion())
		if err != nil {
			return nil, err
		}

		if bid.GetGasLimit() == 0 {
			gasLimit, err := a.bidPool.getBidTxGasLimit(bid)
			if err != nil {
				return nil, err
			}
			bid.SetGasLimit(gasLimit)
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &auctionEntryPoint,
			types.TxValueKeyAmount:     common.Big0,
			types.TxValueKeyData:       data,
			types.TxValueKeyGasLimit:   bid.GetGasLimit(),
			types.TxValueKeyGasFeeCap:  tx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  tx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)

		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bid.Hash())
