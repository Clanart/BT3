### Title
Unbounded recursive `AccountKey` decoding in `AccountKeyRoleBased.DecodeRLP` allows stack-overflow DoS via a crafted `TxTypeAccountUpdate` transaction - (File: blockchain/types/accountkey/account_key_role_based.go)

### Summary
`AccountKeyRoleBased.DecodeRLP` recursively decodes nested `AccountKey` values through `AccountKeySerializer.DecodeRLP` with no depth limit. Because a `RoleBased` key element can itself be another `RoleBased` key, an attacker can submit a single `TxTypeAccountUpdate` (or fee-delegated variant) transaction whose `Key` field encodes thousands of nested `RoleBased` levels. RLP decoding recurses once per nesting level *before* any composite-type restriction is enforced, which only happens in `CheckInstallable`/`CheckUpdatable` after decoding completes. This mirrors the reported bug class (recursive-descent parser with no nesting-depth guard causing a stack overflow), but here the "parser" is Kaia's RLP `AccountKey` decoder reachable from an ordinary, unprivileged transaction.

### Finding Description
`AccountKeyRoleBased` is decoded as follows: [1](#0-0) 

Each element `b` is independently RLP-decoded through `AccountKeySerializer`, which reads a `keyType` tag and then decodes the concrete key value into whatever type that tag names, via `s.Decode(serializer.key)`: [2](#0-1) 

If `serializer.key` created by `NewAccountKey(serializer.keyType)` is itself `*AccountKeyRoleBased`, then `s.Decode` calls back into `AccountKeyRoleBased.DecodeRLP`, which again loops over its encoded byte slices and again invokes `AccountKeySerializer.DecodeRLP` — an unbounded mutual recursion whose depth is entirely controlled by how the attacker nests `RoleBased` entries inside the transaction's encoded `Key` bytes.

The only defense against nested composite keys is a **post-decode** structural check: [3](#0-2) 

This `IsCompositeType()` rejection in `CheckInstallable` runs only after the entire (potentially deeply nested) structure has already been fully RLP-decoded — i.e., after the recursive call stack has already been built and unwound (or has already crashed). There is no recursion-depth counter or maximum-nesting check anywhere in the RLP `Stream`/`AccountKey` decoding path (`rlp/decode.go`, `account_key_role_based.go`, `account_key_serializer.go`).

### Impact Explanation
Because Go's runtime treats an unrecoverable goroutine stack overflow (exceeding `maxstacksize`, default ~1GB) as a **fatal, unrecoverable process crash** (not a normal panic that `recover()` can catch), a single malicious transaction can crash an entire full node process that attempts to decode it — whether received via `eth_sendRawTransaction`/`SendRawTransaction` RPC, `TxPool.AddRemote`, or transaction propagation (`handleTxMsg` → `msg.Decode(&txs)`). This is a state/service-divergence and availability impact reachable by any unprivileged transaction sender or RPC caller, satisfying "state divergence between honest nodes" / node crash from an ordinary transaction, which is in-scope as an accepted impact class.

### Likelihood Explanation
Likelihood is high for a network with public RPC endpoints and open transaction propagation: constructing the malicious nested `AccountKeyRoleBased` payload requires only crafting raw RLP bytes (no valid signature is even strictly required to trigger the crash, since decoding happens before signature/sender validation in `Transaction.DecodeRLP` → `TxInternalDataSerializer.DecodeRLP` → account-update internal data decode → `AccountKeySerializer`/`AccountKeyRoleBased` decode). The size of the nested-encoding payload needed to exhaust the stack is modest relative to node-imposed transaction size caps, since each recursion level only costs a small number of RLP bytes but a full function-call stack frame set (`DecodeRLP` → `rlp.DecodeBytes` → `Stream.Decode` → nested `DecodeRLP`, etc.).

### Recommendation
Add an explicit maximum-nesting-depth guard (e.g., pass/track a recursion counter through `AccountKeyRoleBased.DecodeRLP` / `AccountKeySerializer.DecodeRLP`, or reject decoding once `keyType == AccountKeyTypeRoleBased` is seen while already inside a `RoleBased` decode) so composite-type nesting is rejected *during* decoding, not only afterward in `CheckInstallable`. This mirrors the upstream CPython Expat fix, which added an explicit content-model nesting depth limit inside the parser itself rather than relying on post-parse validation.

### Proof of Concept
1. Construct nested `AccountKey` bytes recursively: let `K0 = RLP(AccountKeyTypeNil-or-similar)`; for `i` in `1..N`: `Ki = RLP([keyType=AccountKeyTypeRoleBased, RLP([K(i-1)])])` (i.e., each level is an `AccountKeySerializer`-encoded `RoleBased` key containing exactly one nested serialized key).
2. Set `N` in the thousands (tunable to exceed the node's goroutine stack limit while decoding).
3. Embed the resulting deepest-level bytes as the `Key` field of a `TxTypeAccountUpdate` (or fee-delegated variant) transaction, RLP-encode the full transaction.
4. Submit via `eth_sendRawTransaction` or broadcast over the tx-propagation p2p channel.
5. Node calls `rlp.DecodeBytes(rawTx, tx)` (`Transaction.DecodeRLP`) which eventually reaches `AccountKeyRoleBased.DecodeRLP`, recursing `N` times before any `CheckInstallable`/size validation runs, causing `fatal error: stack overflow` and crashing the node process.

func (a *AccountKeyRoleBased) DecodeRLP(s *rlp.Stream) error {
	enc := [][]byte{}
	if err := s.Decode(&enc); err != nil {
		return err
	}

	keys := make([]AccountKey, len(enc))
	for i, b := range enc {
		serializer := NewAccountKeySerializer()
		if err := rlp.DecodeBytes(b, &serializer); err != nil {
			return err
		}
		keys[i] = serializer.key
	}

	*a = (AccountKeyRoleBased)(keys)

	return nil
}

func (a *AccountKeyRoleBased) CheckInstallable(currentBlockNumber uint64) error {
	// A zero-role key is not allowed.
	if len(*a) == 0 {
		return kerrors.ErrZeroLength
	}
	// Do not allow undefined roles.
	if len(*a) > (int)(RoleLast) {
		return kerrors.ErrLengthTooLong
	}
	for i := 0; i < len(*a); i++ {
		// A composite key is not allowed.
		if (*a)[i].IsCompositeType() {
			return kerrors.ErrNestedCompositeType
		}
		// If any key in the role cannot be initialized, return an error.
		if err := (*a)[i].CheckInstallable(currentBlockNumber); err != nil {
			return err
		}
	}
	return nil
}

func (serializer *AccountKeySerializer) DecodeRLP(s *rlp.Stream) error {
	if err := s.Decode(&serializer.keyType); err != nil {
		return err
	}

	var err error
	serializer.key, err = NewAccountKey(serializer.keyType)
	if err != nil {
		return err
	}

	return s.Decode(serializer.key)
}
