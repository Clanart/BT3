## Finding on `pallet-consensus-incentives` reward attribution in batched `handle_unsigned`

### Title
Consensus relayer reward misattribution allows theft of other relayers' rewards via batched `handle_unsigned` - ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
`pallet-consensus-incentives::on_executed` recovers the reward recipient from **only the first message** in a batch (`messages.get(0)`), but then pays out a reward for **every** `StateMachineUpdated` event produced by the whole batch, regardless of which message/signature actually produced that event.

### Finding Description
`handle_unsigned` on `pallet-ismp` is a permissionless, unsigned extrinsic that accepts an arbitrary `Vec<Message>` and executes them all in one transactional call: [1](#0-0) 

Consensus proofs and their signatures are public once submitted/observed (any relayer can see them via RPC/events and re-encode them into a new batch). `FeeHandler::on_executed` is invoked after the whole batch executes, and it derives the sole reward recipient like this: [2](#0-1) 

It then collapses **all** `StateMachineUpdated` events from the batch (which can come from multiple distinct `Message::Consensus` entries, each with its own valid signature) into a per-state-machine map and pays a reward for each one — attributing every single one of them to `relayer_account`, the signer of `messages[0]` only: [3](#0-2) 

Nothing in `handle_unsigned` or in `on_executed` verifies that the account credited actually produced the additional consensus updates beyond the first message. An attacker can:
1. Take one (or more) already-broadcast, valid `Message::Consensus` proofs authored by other relayers (proofs are public data on the wire/tx pool/RPC — no privileged access needed).
2. Craft their own tiny valid consensus message as `messages[0]`, signed with their own key.
3. Append the other relayers' proofs as subsequent entries in the same `handle_unsigned` batch.
4. Submit the batch. All state machines advance correctly (proofs are cryptographically valid, so no false state is accepted), but `on_executed` pays the **attacker** for every `StateMachineUpdated` event in the batch, not just their own.

This directly parallels the reported bug's core broken invariant — a reward/index computation binds to the wrong account/holder because of "who is checked" vs. "who benefits" mismatch (there it was a starting-index of 0 wrongly zeroing legitimate rewards; here it's a first-signer sentinel wrongly redirecting other relayers' legitimate rewards).

### Impact Explanation
This is a direct fund-diversion bug: treasury BRIDGE tokens and reputation-asset mints intended for the relayer who actually raced to deliver a given consensus update are instead paid to whichever address happens to be first in the batch. An unprivileged attacker can systematically front-run/steal consensus-relaying rewards from every other relayer by batching public proofs behind their own message, at zero cost beyond gas/tx fees for one trivial proof. Because rewards also mint `ReputationAsset` 1:1, and reputation feeds into collator selection (per the relayer docs), this also lets an attacker inflate their own collator-selection weight illegitimately.

### Likelihood Explanation
High. `handle_unsigned` is explicitly designed to accept arbitrary unsigned batches from any caller with valid proofs, and the docs describe it as "anyone execute ISMP messages for free, provided they have valid proofs." Proofs are inherently public once created, so acquiring "someone else's" valid consensus proof requires no privileged access, compromised key, or malicious relayer collusion — an attacker can simply observe the network. This satisfies the pivots (reward/state-transfer paths must bind identity correctly) and the "unprivileged attacker" requirement.

### Recommendation
Attribute each `StateMachineUpdated` event's reward to the signer of the specific `Message::Consensus` that produced it, not to `messages[0]`'s signer. This requires either:
- Passing the executed `messages` alongside their originating event indices/state-machine-ids through to `on_executed` so each update can be matched back to its own message's signature, or
- Restricting `on_executed`'s consensus-reward path to only run when the batch contains exactly one `Message::Consensus` (rejecting/ignoring rewards for multi-consensus-message batches), forcing attribution to be unambiguous.

### Proof of Concept
1. Relayer A submits `handle_unsigned([Message::Consensus(proof_for_chain_X, signed_by_A)])`. This is observable on-chain/tx pool before finalization.
2. Attacker B copies `proof_for_chain_X` (still valid, unconsumed) and crafts their own trivial `Message::Consensus(proof_for_chain_Y, signed_by_B)` for a different/cheap state machine update.
3. Attacker B submits `handle_unsigned([Message::Consensus(proof_for_chain_Y, signed_by_B), Message::Consensus(proof_for_chain_X, signed_by_A)])` before A's transaction lands (or simply wins the race for inclusion).
4. `execute` processes both messages, producing two `StateMachineUpdated` events (for chain_Y and chain_X).
5. `on_executed` recovers only B's pubkey from `messages[0]`, then loops over both events and pays B the reward (and mints reputation) for **both** chain_Y and chain_X advances — including the chain_X reward that should have gone to A.
6. As implemented, `LastRewardedHeight` (test at `modules/pallets/testsuite/src/tests/pallet_consensus_incentives.rs:121-219`) only guards against double-payment for the *same* span, not against *misattribution* to the wrong relayer — confirming the watermark logic does not address this path. 	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();

				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);

#[test]
fn reward_covers_only_unpaid_heights_after_rollback() {
	let mut ext = new_test_ext();
	ext.execute_with(|| {
		const BLOCK_COST: u128 = 100;
		let host = Ismp::default();
		let state_machine_id = setup_state_machine();
		let treasury_account: AccountId32 = PalletId(*b"treasury").into_account_truncating();

		pallet_consensus_incentives::Pallet::<Test>::update_cost_per_block(
			RuntimeOrigin::root(),
			state_machine_id,
			BLOCK_COST,
		)
		.unwrap();

		let (consensus_message, relayer_account) = setup_host_and_message(&host);
		let message = MessageWithWeight { message: consensus_message, weight: Weight::zero() };
		let updated = |height: u64| {
			vec![IsmpEvent::StateMachineUpdated(StateMachineUpdated {
				state_machine_id,
				latest_height: height,
			})]
		};

		// The chain has already advanced to 1025 and every block up to it has been rewarded once.
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1024 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1024,
		})
		.unwrap();
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1025 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1025,
		})
		.unwrap();

		let treasury_before_first = Balances::balance(&treasury_account);
		<pallet_consensus_incentives::Pallet<Test> as FeeHandler>::on_executed(
			vec![message.clone()],
			updated(1025),
		)
		.unwrap();

		assert_eq!(Balances::balance(&treasury_account), treasury_before_first - BLOCK_COST);
		assert_eq!(
			pallet_consensus_incentives::LastRewardedHeight::<Test>::get(state_machine_id),
			Some(1025)
		);

		// The previous-height pointer references an older height whose commitment is no longer
		// retained in the bounded map.
		pallet_ismp::PreviousStateMachineHeight::<Test>::insert(state_machine_id, 1);

		// Deleting the latest commitment rolls the latest height back to that previous pointer.
		host.delete_state_commitment(StateMachineHeight { id: state_machine_id, height: 1025 })
			.unwrap();
		assert_eq!(host.latest_commitment_height(state_machine_id).unwrap(), 1);

		// The next honest consensus update advances to 1030, carrying the stale pointer forward as
		// the new previous height.
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1030 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1030,
		})
		.unwrap();
		assert_eq!(host.previous_commitment_height(state_machine_id), Some(1));

		let treasury_before_second = Balances::balance(&treasury_account);
		<pallet_consensus_incentives::Pallet<Test> as FeeHandler>::on_executed(
			vec![message],
			updated(1030),
		)
		.unwrap();

		// The real advance is 1025 -> 1030, so only the 5 new blocks are paid rather than the full
		// span back to the previous pointer.
		assert_eq!(Balances::balance(&treasury_account), treasury_before_second - 5 * BLOCK_COST);
		assert_eq!(
			pallet_consensus_incentives::LastRewardedHeight::<Test>::get(state_machine_id),
			Some(1030)
		);
	})
}
