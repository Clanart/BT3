## Title
SSRF via attacker-created DataLayer mirror coins causing unauthenticated outbound HTTP requests from a victim's DataLayer service - (File: chia/data_layer/data_layer_wallet.py, chia/data_layer/download_data.py)

### Summary
GPT Academic's CVE-2024-11030 SSRF stems from a plugin fetching attacker-influenced URLs without sanitization. Chia's DataLayer subsystem has an analogous pattern: mirror coins that store arbitrary URLs can be created by **any unprivileged spend-bundle submitter**, are picked up by a victim's `DataLayerWallet.coin_added()`, persisted as trusted mirror server records, and later fed directly into an unauthenticated `aiohttp` GET/POST request issued by the victim's DataLayer server process (`http_download()` / `get_downloader()`).

### Finding Description
`DataLayerWallet.coin_added()` recognizes any coin sent to the well-known mirror puzzle hash (`create_mirror_puzzle().get_tree_hash()`) as a DataLayer "mirror" coin: [1](#0-0) 

The URL list embedded in that coin's spend solution is decoded via `get_mirror_info()`/`Mirror.decode_urls()` and stored unconditionally into the wallet's `dl_store` as long as the `launcher_id` (store id) is already tracked by the wallet — there is no check that the mirror coin was created by the store owner, or any validation of the URL's scheme/host (no allow-list, no blocking of `localhost`/RFC1918/link-local/cloud-metadata addresses).

Any actor who can construct and submit a spend bundle can create a coin paying to the mirror puzzle hash, with an arbitrary URL of their choosing, for a `launcher_id` corresponding to a DataLayer store the victim happens to track/subscribe to. Once this mirror coin confirms on-chain, the victim's `DataLayerWallet` ingests the URL as shown above.

That stored server URL later flows into the DataLayer service's synchronization loop (`update_subscription()` → `fetch_and_validate()`), which selects servers via `get_available_servers_for_store()` and issues outbound network calls with `http_download()`: [2](#0-1) 

or, if a downloader plugin is configured, forwards the attacker-supplied URL to that plugin over HTTP with no host restriction: [3](#0-2) 

The `DataLayer` service's own `.cursor` documentation explicitly acknowledges this trust boundary and that it is only partially mitigated: "Plugin and mirror URLs are external trust inputs. Downloaded data must continue to be verified against wallet-advertised roots, and file path/name validation must stay strict." [4](#0-3) 

Notably, the content that is fetched is verified against the wallet-advertised Merkle root, but the *URL itself* (and thus the destination the DataLayer node's process reaches out to, using its own network position/credentials) is never validated. This is precisely the SSRF pattern in the referenced report: an attacker-controlled URL is consumed by a server-side HTTP fetch without sanitization of the target host/scheme.

### Impact Explanation
An unprivileged attacker who can submit a spend bundle (i.e., anyone who can create the mirror coin, no special privileges needed) can force a victim node running the DataLayer service to make outbound HTTP requests to attacker-chosen hosts (e.g., internal-network services, `127.0.0.1`, cloud metadata endpoints, or ports used by other local services on the victim's host). Because the request is made by the DataLayer server process using its own network context, this can be used to probe/interact with services not otherwise reachable by the attacker (classic SSRF impact), and can also be used to trigger repeated backoff/log noise or plugin-forwarded requests, potentially against internal downloader plugins that trust supplied `url`/`client_folder` fields.

### Likelihood Explanation
Likelihood is elevated but bounded: it requires (1) the victim to be running the DataLayer service and to already be tracking/subscribed to the specific `launcher_id` (store), and (2) the attacker to submit a spend to the mirror puzzle hash for that store id — both of which are reachable by an ordinary, unprivileged chain participant without any authorization from the store owner. No signature from the store owner, no admin RPC access, and no special network position are required to create the mirror coin.

### Recommendation
- Validate/sanitize mirror and downloader URLs before storing and before issuing HTTP requests: enforce an allow-listed scheme (`http`/`https`) and reject requests to loopback, link-local, private/internal IP ranges, and cloud metadata addresses (e.g., via DNS/IP resolution checks at request time, not just string parsing).
- Consider requiring mirror URLs to be confirmed/opted-in by the store owner (e.g., signed attestation tied to the DataLayer wallet key) rather than accepting any URL embedded by an arbitrary spend to the mirror puzzle.
- Apply the same SSRF-hardening (`aiohttp` request restrictions, e.g., disabling redirects to internal hosts, restricting resolved IPs) uniformly across `http_download()`, `get_downloader()`, and `add_missing_files()` upload/download HTTP calls.

### Proof of Concept
1. Attacker identifies a `launcher_id`/store id that the victim node is subscribed to or otherwise tracking via `dl_track_new`.
2. Attacker constructs a spend bundle creating a coin with puzzle hash `create_mirror_puzzle().get_tree_hash()`, whose puzzle reveal/solution encode `(launcher_id, [attacker_url])` per `get_mirror_info()`'s expected format, e.g. `attacker_url = "http://169.254.169.254/latest/meta-data/"` or `"http://127.0.0.1:<internal-port>/"`.
3. Attacker submits the spend bundle to the mempool; once confirmed, the victim's `DataLayerWallet.coin_added()` detects the mirror coin and calls `dl_store.add_mirror(Mirror(coin.name(), launcher_id, amount, Mirror.decode_urls(urls), ours, height))` [5](#0-4) 
4. On the next periodic sync cycle, the victim's DataLayer service calls `update_subscription()`/`fetch_and_validate()`, selects the attacker's URL from `get_available_servers_for_store()`, and issues an outbound `aiohttp` GET to it via `http_download()` [6](#0-5) 
achieving SSRF from the victim's DataLayer node.

Note: I was not able to directly view `get_mirror_info()`/`Mirror.decode_urls()`/`create_mirror_puzzle()` implementations or the exact wire format required in the coin solution due to index/search limitations — confirming the precise puzzle/solution encoding needed to trigger this would require examining `chia/data_layer/data_layer_wallet.py` and `chia/wallet/db_wallet/db_wallet_puzzles.py` directly (a Devin session with full file access would be needed to verify exact field layout for constructing the PoC spend).

        self, coin: Coin, height: uint32, peer: WSChiaConnection, coin_data: object | None, sync_scope: WalletSyncScope
    ) -> None:
        if coin.puzzle_hash == create_mirror_puzzle().get_tree_hash():
            parent_state: CoinState = (
                await self.wallet_state_manager.wallet_node.get_coin_state([coin.parent_coin_info], peer=peer)
            )[0]
            parent_spend = await fetch_coin_spend(height, parent_state.coin, peer)
            assert parent_spend is not None
            launcher_id, urls = get_mirror_info(parent_spend.puzzle_reveal, parent_spend.solution)
            # Don't track mirrors with empty url list.
            if not urls:
                return
            if await self.wallet_state_manager.dl_store.is_launcher_tracked(launcher_id):
                ours: bool = await self.wallet_state_manager.get_wallet_for_coin(coin.parent_coin_info) is not None
                await self.wallet_state_manager.dl_store.add_mirror(
                    Mirror(
                        coin.name(),
                        launcher_id,
                        uint64(coin.amount),
                        Mirror.decode_urls(urls),
                        ours,
                        height,
                    )
                )
                await self.wallet_state_manager.add_interested_coin_ids([coin.name()])

async def http_download(
    target_filename_path: Path,

    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()

    async def get_downloader(self, store_id: bytes32, url: str) -> PluginRemote | None:
        request_json = {"store_id": store_id.hex(), "url": url}
        for d in self.downloaders:
            async with aiohttp.ClientSession() as session:
                try:
                    async with session.post(
                        d.url + "/handle_download",
                        json=request_json,
                        headers=d.headers,
                        timeout=self.client_timeout,
                    ) as response:
                        res_json = await response.json()
                        if res_json["handle_download"]:
                            return d
                except Exception as e:
                    self.log.error(f"get_downloader could not get response: {type(e).__name__}: {e}")
        return None
