### Title
Out-of-Bounds Read via Missing Bounds Checks in CLVM Canonical-Encoding Parser During Spend Bundle Admission - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_clvm_canonical()` and `is_atom_canonical()` in `chia/full_node/mempool_manager.py` parse the raw, attacker-supplied bytes of `coin_spend.puzzle_reveal` and `coin_spend.solution` during mempool admission (`validate_spend_bundle()`), advancing a byte offset based on length-prefix bits read directly from the buffer, with no check that the offset stays within the buffer before each read [1](#0-0) . This mirrors the SWUpdate bug class: a length/offset value derived from attacker-controlled input is used to index into a buffer without validating it stays within the buffer's actual bounds, producing an out-of-bounds read that can crash the parsing routine.

### Finding Description
`validate_spend_bundle()` calls `is_clvm_canonical(bytes(coin_spend.puzzle_reveal))` and `is_clvm_canonical(bytes(coin_spend.solution))` for every coin spend in every submitted `SpendBundle`, before any cost/coin-record checks reject it [2](#0-1) . These bytes come directly from an unauthenticated caller submitting a spend bundle to the mempool.

Inside `is_clvm_canonical()`, the loop reads `b = clvm_buffer[offset]` and, depending on `b`, either increments `offset` by 1 (pair/small-atom case) or delegates to `is_atom_canonical(clvm_buffer, offset)` to compute an atom length and advance `offset` by that amount [3](#0-2) . Critically:

- The loop's own top read, `b = clvm_buffer[offset]`, is never bounds-checked before being executed on each iteration; only after fully consuming all logical tokens does the code check `offset == len(clvm_buffer)` [3](#0-2) .
- `is_atom_canonical()` reads `clvm_buffer[offset]` and then, in a loop keyed off the multi-byte length-prefix encoding (`prefix_len` up to 5), performs `offset += 1; atom_len |= clvm_buffer[offset]` for each prefix byte, again with no check that `offset < len(clvm_buffer)` [1](#0-0) .

This is the same bug class described in the external report: a buffer/length calculation used to index into a receive buffer without verifying it remains within the allocated bounds. In the Chia codebase, `chia/full_node/full_block_utils.py`'s equivalent parsers (`skip_bytes`, `skip_list`, `generator_from_block`, `block_info_from_block`) were explicitly hardened with bounds checks and raise descriptive `ValueError`s when a length or count would exceed the remaining buffer [4](#0-3) , and this hardening is covered by an extensive dedicated test suite in `chia/_tests/util/test_full_block_utils.py` [5](#0-4) . `is_atom_canonical()`/`is_clvm_canonical()`, which process untrusted mempool input, do not have the equivalent protection.

A crafted `puzzle_reveal` or `solution` byte string ending immediately after a pair marker (`0xff`) or ending mid-way through a multi-byte atom length prefix (e.g. the byte pattern `0xf8` with no following bytes) will cause `clvm_buffer[offset]` to be evaluated with `offset >= len(clvm_buffer)`, raising an `IndexError` in Python.

### Impact Explanation
`validate_spend_bundle()` is on the mempool admission path (`add_spend_bundle()` → `validate_spend_bundle()`) invoked for every spend bundle a wallet, offer counterparty, or any unprivileged submitter sends to a full node [6](#0-5) . If the resulting `IndexError` is not caught by an outer handler in the network/RPC dispatch path, this becomes a remotely-triggerable, spend-triggered exception during transaction processing — a denial-of-service condition matching the CVSS `VA:H` (availability-high) impact in the reference CVE. Full confirmation of whether an uncaught exception propagates to crash the full node process (vs. being caught by a broader try/except in the caller) requires runtime tracing of the full spend-bundle ingestion call chain, which was not exhaustively verified in this review.

### Likelihood Explanation
High reachability: any wallet user, offer counterparty, or unauthenticated RPC/P2P submitter of a spend bundle can supply arbitrary bytes as `puzzle_reveal`/`solution` on a `CoinSpend`; these are checked for canonical CLVM form before cost or signature validation completes for every coin spend in the bundle. Crafting the malformed byte sequence (e.g., a solution consisting of a single `0xff` byte, or a truncated multi-byte atom length prefix) requires no cryptographic material and can be done deterministically.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` and `is_clvm_canonical()` before every buffer index, mirroring the pattern already used in `chia/full_node/full_block_utils.py` (`skip_bytes`, `skip_list`), raising a caught/handled error (e.g., treat as non-canonical / reject with `Err.INVALID_COIN_SOLUTION`) rather than allowing a raw `IndexError` to propagate. Additionally, verify that all callers of `validate_spend_bundle()`/`add_spend_bundle()` wrap CLVM-buffer parsing in an exception boundary that converts unexpected parsing exceptions into a mempool rejection rather than letting them escape to crash node processing.

### Proof of Concept
1. Construct a `CoinSpend` whose `solution` is the single byte `b"\xff"` (a pair marker with no subsequent bytes) or whose `puzzle_reveal`/`solution` ends with a truncated multi-byte atom length prefix, e.g. `b"\xf8"` (declares a 5-byte length prefix but supplies none).
2. Wrap it in a `SpendBundle` and submit it via the normal transaction-submission path so it reaches `MempoolManager.add_spend_bundle()` → `validate_spend_bundle()`.
3. `is_clvm_canonical(bytes(coin_spend.solution))` is invoked at [2](#0-1) , which calls `is_atom_canonical()`/loops on `clvm_buffer[offset]` past the end of the buffer, raising `IndexError` inside the mempool-admission call path [7](#0-6) .

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value


def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)

def skip_list(buf: memoryview, skip_item: Callable[[memoryview], memoryview]) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"list count prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"list count {n} exceeds remaining buffer {len(buf)}")
    for _ in range(n):
        buf = skip_item(buf)
    return buf


def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
