## Title
Attacker-controlled Git remote can spoof GitHub/Enterprise host detection to trigger a phishing "Sign in to GitHub" credential prompt - (`File: app/src/lib/api.ts`)

### Summary
GitHub Desktop's credential-helper trampoline decides whether a failed Git authentication attempt belongs to "GitHub"/"GitHub Enterprise" (and should therefore surface Desktop's native GitHub sign-in UI) using a heuristic hostname regex rather than a strict, canonical host allow-list. Because the regex only checks for the literal substring `github.` preceded by `.` or start-of-string, any attacker-registered domain containing a `github.` label (e.g. `sub.github.attacker.com`) is misclassified as a genuine GitHub Enterprise host. This is the same broken-invariant class as the pyUmbral report: a security-relevant decision ("which trust domain am I operating in?") is derived from an implicit, best-effort inference instead of being tied unambiguously to the actual endpoint the operation is targeting.

### Finding Description
`isGitHubHost` in `app/src/lib/api.ts` classifies a host as GitHub/Enterprise using, among other checks, a loose regex: [1](#0-0) 

`/(^|\.)(github)\./.test(hostname)` matches any hostname where `github.` appears as its own DNS label preceded by a dot or by the start of the string — it does not anchor to the end of the hostname or validate that `github` is the registrable domain owner. A domain such as `sub.github.attacker.com`, fully owned and controlled by an attacker, satisfies this check and is treated as an "enterprise" GitHub host.

This function feeds directly into `getEndpointKind` in the trampoline credential helper, which decides how to respond to a Git credential request coming from a remote/submodule host: [2](#0-1) 

When `getEndpointKind` returns `'enterprise'` and no existing account matches that endpoint, `getCredential` calls `ui.promptForGitHubSignIn(endpoint)`: [3](#0-2) 

`promptForGitHubSignIn` then drives the real GitHub Enterprise sign-in flow against the attacker's endpoint: [4](#0-3) 

`beginEnterpriseSignIn` + `setSignInEndpoint` place the sign-in store in the `Authentication` step for that exact attacker-controlled origin: [5](#0-4) 

From there the authentication UI (`AuthenticationForm`, reachable via `SignIn`) allows either a browser-based OAuth flow or direct username/PAT entry, both of which are sent to the attacker's endpoint: [6](#0-5) 

The root cause is identical in shape to the pyUmbral bug: instead of a single canonical definition of "is this endpoint one of our known GitHub/Enterprise hosts" (e.g., an explicit accounts-store lookup or strict `*.` suffix match against a registered endpoint), the classification is inferred heuristically per call site, and that heuristic is exploitable by anyone who can pick a hostname.

### Impact Explanation
An attacker who controls a Git remote or a submodule referenced by a repository the victim clones/fetches (a fully in-scope, unprivileged primitive) can host that submodule at a domain such as `sub.github.attacker.com` whose HTTPS server always challenges for credentials (401). When GitHub Desktop's Git subprocess (via `desktop-trampoline`/credential helper) requests credentials for that host, `isGitHubHost`'s loose regex misclassifies it as GitHub Enterprise, and Desktop pops its native "Sign in to GitHub Enterprise" dialog pointed at the attacker's domain — inside what looks like a normal clone/fetch operation. A victim who completes that sign-in (browser OAuth redirect or username/PAT form) sends their credentials directly to the attacker's server. This matches the "unauthorized OAuth or account binding" / "credential/token exfiltration" impact categories for an attacker-controlled cloned/fetched repository.

### Likelihood Explanation
Exploitation only requires the victim to clone or fetch a repository (with a malicious submodule/remote) that the attacker controls and to complete the resulting sign-in prompt — no local access, elevated privileges, or pre-existing compromise is needed. The trigger path (credential helper invoked on any authenticated HTTPS Git request) is a normal part of every clone/fetch/push operation, so the attacker fully controls when the 401 challenge (and thus the prompt) occurs. The remaining dependency is a user completing the sign-in dialog, which is a natural, expected action in Desktop's UI flow (not an unnatural manual step), making this a realistic, if UI-dependent, path.

### Recommendation
- Do not use heuristic hostname pattern matching (`/(^|\.)(github)\./`) to decide trust. Only treat a host as GitHub/GitHub Enterprise if it matches a canonical, previously-verified endpoint (an account already added in `AccountsStore`, or the `x-github-request-id`/`/meta` verification result), never based on a substring pattern in the hostname.
- When no account exists for a host and heuristics are inconclusive, default to the generic credential path (as already used for unknown hosts) rather than assuming "enterprise" and surfacing GitHub-branded sign-in UI.
- Surface the exact hostname prominently in `promptForGitHubSignIn`'s UI so users can visually verify they're not authenticating to a look-alike domain.
- As with the pyUmbral recommendation, centralize "is this a GitHub/Enterprise endpoint" in one canonical, strict function, and make the "unknown host" state impossible to mistake for a verified GitHub endpoint.

### Proof of Concept
1. Attacker creates a public repository containing a `.gitmodules` entry pointing to `https://sub.github.attacker.com/evil.git`.
2. Attacker's server at `sub.github.attacker.com` requires HTTP Basic authentication (responds `401` with a `WWW-Authenticate` header not matching the `realm="GitHub"` special case, forcing the generic path to fall through to `isGitHubHost`).
3. Victim clones the attacker's repository (or fetches submodules) in GitHub Desktop.
4. Git invokes Desktop's credential helper for `sub.github.attacker.com`; `getEndpointKind` calls `isGitHubHost`, whose regex `/(^|\.)(github)\./` matches `sub.github.attacker.com`, returning `'enterprise'`.
5. Since no account exists for that endpoint, Desktop calls `ui.promptForGitHubSignIn('https://sub.github.attacker.com')`, showing a native "Sign in to your GitHub Enterprise" dialog.
6. Victim, believing this is a legitimate GitHub Enterprise prompt triggered by their own clone action, enters a username/PAT or completes browser OAuth — credentials are sent to the attacker's server.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })

  public async setEndpoint(url: string): Promise<void> {
    const currentState = this.state

    if (
      currentState?.kind !== SignInStep.EndpointEntry &&
      currentState?.kind !== SignInStep.ExistingAccountWarning
    ) {
      const stepText = currentState ? currentState.kind : 'null'
      return fatalError(
        `Sign in step '${stepText}' not compatible with endpoint entry`
      )
    }

    /**
     * If the user enters a github.com url in the GitHub Enterprise sign-in
     * flow we'll redirect them to the GitHub.com sign-in flow.
     */
    if (/^(?:https:\/\/)?(?:api\.)?github\.com($|\/)/.test(url)) {
      this.beginDotComSignIn(currentState.resultCallback)
      return
    }

    this.setState({ ...currentState, loading: true })

    let validUrl: string
    try {
      validUrl = validateURL(url)
    } catch (e) {
      let error = e
      if (e.name === InvalidURLErrorName) {
        error = new Error(
          `The GitHub Enterprise instance address doesn't appear to be a valid URL. We're expecting something like https://example.ghe.com.`
        )
      } else if (e.name === InvalidProtocolErrorName) {
        error = new Error(
          'Unsupported protocol. Only https is supported when authenticating with GitHub Enterprise instances.'
        )
      }

      this.setState({ ...currentState, loading: false, error })
      return
    }

    const endpoint = getEnterpriseAPIURL(validUrl)

    const existingAccount = this.accounts.find(x => x.endpoint === endpoint)

    if (existingAccount) {
      this.setState({
        kind: SignInStep.ExistingAccountWarning,
        endpoint,
        existingAccount,
        error: null,
        loading: false,
        resultCallback: currentState.resultCallback,
      })
    } else {
      this.setState({
        kind: SignInStep.Authentication,
        endpoint,
        error: null,
        loading: false,
        resultCallback: currentState.resultCallback,
      })
    }
  }
