### Title
Permission Bypass of the Authz-Nested-EVM Guard via CosmWasm Stargate Message Dispatch - ([File: sei-wasmd/x/wasm/keeper/handler_plugin_encoders.go])

### Summary
Sei enforces a chain-wide rule that `x/authz` `MsgExec` may never be used to wrap and execute a `MsgEVMTransaction`, because EVM transactions must go through the dedicated EVM ante pipeline (fee/gas accounting, nonce checks, address association, receipt writing) rather than the generic Cosmos message-server path. This rule is implemented as a **static, tx-top-level scan** in two places — `CosmosStatelessChecks` (`app/ante/cosmos_checktx.go`) and `AuthzNestedMessageDecorator` (`app/antedecorators/authz_nested_message.go`) — both calling `CheckAuthzContainsEvm`, which only inspects `tx.GetMsgs()` of the *outer* transaction. CosmWasm contracts, however, can emit `CosmosMsg::Stargate` messages that are unpacked and routed at **runtime**, deep inside contract execution, via `EncodeStargateMsg`/`SDKMessageHandler.handleSdkMessage` (`sei-wasmd/x/wasm/keeper/handler_plugin_encoders.go`, `handler_plugin.go`) — a code path the ante-level scanner never sees. This is the same bug class as the n8n advisory: a static/validation check and the actual runtime resolution/execution engine disagree about what a message resolves to, letting a permission the validator was designed to block slip through at execution time.

Both only walk `tx.GetMsgs()` — the outer transaction's message list — and recurse into nested `authz.MsgExec` values reachable from *that* list via `authzMsg.GetMessages()`: [3](#0-2) 

This check has no visibility into messages that a CosmWasm contract dispatches internally during execution. A contract's `Execute`/`Instantiate`/`Reply` can return a `CosmosMsg::Stargate{ TypeURL, Value }`, which is decoded via `EncodeStargateMsg` using the raw type-URL/`AnyUnpacker`, with no allow-list restricting which message types may be produced this way: [4](#0-3) 

The decoded `sdk.Msg` is then routed and executed via the normal `MsgServiceRouter`, with only a signer-equals-contract check, not an EVM-nesting check: [5](#0-4) 

If the type URL resolves to `/cosmos.authz.v1beta1.MsgExec` (or Sei's equivalent), `handler_plugin.go`'s `handleSdkMessage` finds the authz `MsgServer.Exec` handler through `router.Handler(msg)` and invokes it directly — with the contract address as `grantee`. If any account has ever granted that contract (or an address the contract can act as) a generic authorization for `MsgEVMTransaction` (e.g. via the `x/authz` precompile's `GrantAuthorizations`, `precompiles/common/authorization.go`), the nested `MsgEVMTransaction` executes through `x/evm/keeper/msg_server.go`'s `EVMTransaction` handler — completely bypassing `EvmCheckTxAnte`/`EvmStatelessChecks` (fee floor checks, nonce checks, chain-ID validation, address association ordering) that every legitimately-submitted EVM transaction is required to pass: [6](#0-5) 

The ante-level guard was clearly written specifically to prevent `MsgEVMTransaction` from ever reaching `msgServer.EVMTransaction` through any path other than the dedicated EVM ante handler (`EvmCheckTxAnte`/`EvmCheckAndChargeFees`/`CheckNonce`), and the CosmWasm `Stargate` dispatch path is a second, unguarded runtime resolver for exactly the same message type the ante-time validator was built to block.

### Impact Explanation
Bypassing the EVM ante pipeline for a `MsgEVMTransaction` executed via a CW contract's `Stargate`→`authz.MsgExec` path skips: base-fee/minimum-fee enforcement (`EvmCheckAndChargeFees`), nonce sequencing (`CheckNonce`), and the association/priority context normally set by `DecorateContext`. Depending on grant configuration this can let a wasm contract execute arbitrary EVM messages on behalf of a granter without paying the fees the protocol otherwise mandates, or execute EVM state transitions in a context the receipt/gas-accounting bookkeeping does not expect, since `PrepareCtxForEVMTransaction`/`WriteReceipt` assume the transaction arrived through the standard path. This constitutes fee/refund abuse and inconsistent EVM state-transition accounting reachable purely from a submitted CosmWasm execute message.

### Likelihood Explanation
Exploitation requires only (a) a deployed CosmWasm contract capable of emitting a `Stargate` `CosmosMsg` (any contract with `stargate` feature enabled, which Sei enables by default — `supportedFeatures := "iterator,staking,stargate,sei"` in `app/app.go`), and (b) an existing `authz` generic-authorization grant for `MsgEVMTransaction` from some account to that contract's address (obtainable via the standard `x/authz` `MsgGrant` or the `authz` precompile). Both preconditions are reachable by an ordinary transaction sender/contract deployer without special privileges, making this a plausible attack path once a grant exists.

### Recommendation
Move the nested-EVM-message rejection from an ante-time, top-level-only scan into the actual message-dispatch layer that both the top-level tx router and the CosmWasm `SDKMessageHandler`/`EncodeStargateMsg` share (or add an equivalent recursive check inside `handleSdkMessage`/`EncodeStargateMsg` for any `authz.MsgExec` and `MsgEVMTransaction` type URLs). At minimum, block `/cosmos.authz.v1beta1.MsgExec` (and any type URL that unpacks to `*evmtypes.MsgEVMTransaction`) from the wasm `Stargate` encoder's accepted type set, or run the same `CheckAuthzContainsEvm` walk against every `sdk.Msg` produced by `wasmkeeper.Messenger.DispatchMsg` before routing.

### Proof of Concept
1. Account `A` grants a deployed CosmWasm contract `C` a generic `authz` authorization for `/x.evm.MsgEVMTransaction` (via `x/authz` `MsgGrant` or the `authz` precompile's `GrantAuthorizations`).
2. Submit a single top-level `MsgExecuteContract` calling `C`, which contains no `authz.MsgExec` or EVM message directly — passing `CosmosStatelessChecks`/`AuthzNestedMessageDecorator` cleanly since `tx.GetMsgs()` shows only the `MsgExecuteContract`.
3. Inside its `execute` entry point, `C` returns a `Response` with a `CosmosMsg::Stargate{ type_url: "/cosmos.authz.v1beta1.MsgExec", value: <MsgExec{ grantee: C, msgs: [Any{MsgEVMTransaction}] }> }`.
4. `EncodeStargateMsg` unpacks it to an `authz.MsgExec`; `handleSdkMessage` verifies `GetSigners() == C` and routes it to the authz `MsgServer.Exec` handler, which finds the grant from step 1 and dispatches the nested `MsgEVMTransaction` straight into `x/evm/keeper/msg_server.go`'s `EVMTransaction`, entirely bypassing `EvmCheckTxAnte`, fee checks, and nonce checks that every top-level EVM transaction is normally required to pass.

func CheckAuthzContainsEvm(authzMsg *authz.MsgExec, nestedLvl int) (bool, error) {
	if nestedLvl >= maxNestedMsgs {
		return false, errors.New("permission denied, more nested msgs than permitted")
	}
	msgs, err := authzMsg.GetMessages()
	if err != nil {
		return false, err
	}
	for _, msg := range msgs {
		// check if message type is authz exec or evm
		switch m := msg.(type) {
		case *evmtypes.MsgEVMTransaction:
			return true, nil
		case *authz.MsgExec:
			// find nested to check for evm
			valid, err := CheckAuthzContainsEvm(m, nestedLvl+1)
			if err != nil {
				return false, err
			}
			if valid {
				return true, nil
			}
		default:
			continue
		}
	}
	return false, nil
}

func EncodeStargateMsg(unpacker codectypes.AnyUnpacker) StargateEncoder {
	return func(sender sdk.AccAddress, msg *wasmvmtypes.StargateMsg) ([]sdk.Msg, error) {
		any := codectypes.Any{
			TypeUrl: msg.TypeURL,
			Value:   msg.Value,
		}
		var sdkMsg sdk.Msg
		if err := unpacker.UnpackAny(&any, &sdkMsg); err != nil {
			return nil, sdkerrors.Wrap(types.ErrInvalidMsg, fmt.Sprintf("Cannot unpack proto message with type URL: %s", msg.TypeURL))
		}
		if err := codectypes.UnpackInterfaces(sdkMsg, unpacker); err != nil {
			return nil, sdkerrors.Wrap(types.ErrInvalidMsg, fmt.Sprintf("UnpackInterfaces inside msg: %s", err))
		}
		return []sdk.Msg{sdkMsg}, nil
	}
}

func (h SDKMessageHandler) handleSdkMessage(ctx sdk.Context, contractAddr sdk.Address, msg sdk.Msg) (*sdk.Result, error) {
	if err := msg.ValidateBasic(); err != nil {
		return nil, err
	}
	// make sure this account can send it
	for _, acct := range msg.GetSigners() {
		if !acct.Equals(contractAddr) {
			return nil, sdkerrors.Wrap(sdkerrors.ErrUnauthorized, "contract doesn't have permission")
		}
	}

	// find the handler and execute it
	if handler := h.router.Handler(msg); handler != nil {
		// ADR 031 request type routing
		msgResult, err := handler(ctx, msg)
		return msgResult, err
	}
	// legacy sdk.Msg routing
	// Assuming that the app developer has migrated all their Msgs to
	// proto messages and has registered all `Msg services`, then this
	// path should never be called, because all those Msgs should be
	// registered within the `msgServiceRouter` already.
	return nil, sdkerrors.Wrapf(sdkerrors.ErrUnknownRequest, "can't route message %+v", msg)
}
