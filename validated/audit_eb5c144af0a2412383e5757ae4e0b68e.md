### Title
WSEI.withdraw() permanently locks funds for contract holders via 2300-gas `.transfer()` - ([File: contracts/src/WSEI.sol])

### Summary
`WSEI.sol`, the canonical wrapped-SEI ERC20 contract whose bytecode/ABI is embedded and shipped as an on-chain artifact in `x/evm/artifacts/wsei/artifacts.go`, implements `withdraw()` using Solidity's `.transfer()`, which hard-codes a 2300 gas stipend to the recipient. [1](#0-0) [2](#0-1) 

### Finding Description
`withdraw(uint wad)` debits the caller's `balanceOf` and then sends native SEI back via `payable(msg.sender).transfer(wad)`: [1](#0-0) 

`.transfer()` forwards only 2300 gas to the recipient's `receive`/`fallback`. Because `wad` was already deducted before the external call, and Solidity reverts the entire transaction if the 2300-gas call fails, the visible effect is that the transaction reverts and `balanceOf` is restored — but the caller is permanently prevented from ever unwrapping their WSEI back to native SEI if:
- `msg.sender` is a smart contract (multisig, proxy, smart-contract wallet, DeFi vault, etc.) whose `receive`/`fallback` legitimately needs >2300 gas (e.g., it emits events, updates storage, or delegates through a proxy), or
- protocol/EVM gas-cost changes (e.g., SLOAD repricing under EIP-1884-style changes) push previously-fine fallback logic over the 2300 gas ceiling.

Since WSEI has no alternative unwrap path (no `call`-based withdrawal, no way to specify extra gas, no fallback function that accepts arbitrary calldata to redirect funds), any contract holding WSEI whose receive logic exceeds the 2300 gas stipend has its WSEI balance permanently frozen — it can never be redeemed for native SEI through this contract. Given that WSEI is deployed as a system/genesis-level artifact (embedded ABI/bytecode referenced from `x/evm/client/cli/tx.go`), it is expected to be used broadly as the canonical wrapped-native token across DeFi integrations (AMMs, vaults, aggregators) that are typically smart contracts, not EOAs, making this an externally-reachable and realistic scenario for any contract-based `withdraw()` caller.

### Impact Explanation
This is a permanent freezing-of-funds bug: any contract-based holder of WSEI whose receive/fallback logic costs more than 2300 gas cannot ever call `withdraw()` successfully, and there is no alternate recovery mechanism in the contract. Because WSEI is a chain-level embedded artifact intended for broad DeFi composability, this qualifies as a Medium/High severity fund-freezing issue matching the "permanent freezing" acceptance criterion.

### Likelihood Explanation
Likelihood is realistic but conditional: it triggers whenever a smart-contract address (not a plain EOA) holds WSEI and its receive path exceeds 2300 gas — a common situation for proxy wallets, multisigs, or contracts using non-trivial `receive()`/`fallback()` logic. No privileged access or malicious actor is required; any normal contract-integrated DeFi user can hit it simply by calling `withdraw()`.

### Recommendation
Replace `payable(msg.sender).transfer(wad)` in `withdraw()` with a low-level `call` that forwards all remaining gas and checks the return value, e.g.:
```solidity
(bool success, ) = msg.sender.call{value: wad}("");
require(success, "WSEI: withdraw transfer failed");
```
Apply the CEI (checks-effects-interactions) pattern consistently (balance is already decremented before the call, so this is safe against reentrancy once the gas stipend limitation is removed).

### Proof of Concept
1. Deploy a contract `Recipient` with a `receive()` function that performs a storage write consuming >2300 gas (e.g., `receive() external payable { someState = block.timestamp; }`).
2. `Recipient` calls `WSEI.deposit{value: 1 ether}()`, then calls `WSEI.withdraw(1 ether)`.
3. The internal `payable(msg.sender).transfer(wad)` call runs out of the fixed 2300 gas stipend during the storage write in `receive()`, causing the transfer to fail and the whole `withdraw` transaction to revert.
4. `Recipient`'s WSEI balance can never be withdrawn to native SEI through this contract — funds are permanently stuck.
