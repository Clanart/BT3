### Title
Unbounded `authorized_providers` list curried into CR-CAT/credential-restriction puzzle can cause CLVM cost blow-up, permanently freezing coin spends - (File: chia/wallet/vc_wallet/cr_cat_drivers.py)

### Summary
The credential-restricted CAT (CR-CAT) layer curries a caller-supplied `authorized_providers: list[bytes32]` directly into the on-chain puzzle with no length restriction anywhere in the driver code. This is directly analogous to the reported `SellOrder.whitelist` issue: a value fully controlled by the coin's creator, of unbounded size, is stored on-chain and must be iterated/searched by the CLVM program on every future spend — imposing unbounded CLVM cost on whoever spends the coin, not on the party who chose the list size.

### Finding Description
`construct_cr_layer` curries `authorized_providers` (and `proofs_checker`) straight into the `CREDENTIAL_RESTRICTION` puzzle with no cap on list length: [1](#0-0) 

This same unrestricted list is accepted by `CRCAT.launch` (used to mint/launch a new CR-CAT), by `CRCATWallet.get_or_create_wallet_for_cat`, and is round-tripped through `match_cr_layer`/`get_next_from_coin_spend` on every sync — none of these code paths enforce a maximum number of providers: [2](#0-1) [3](#0-2) 

The `CREDENTIAL_RESTRICTION` puzzle's job at spend time is to validate that the spender presents a valid VC from a provider that is a member of `authorized_providers` (see `solve_cr_layer`, which threads `provider_id`/`proof_of_inclusions` into the inner CLVM program): [4](#0-3) 

Because `authorized_providers` is compiled bytecode from `chia_puzzles_py` (not visible as `.clsp` source in this repo), the exact membership-check algorithm could not be directly inspected in this pass, but the Python driver treats it as a full list that is curried in as data and must be traversed/checked by CLVM at spend time (`extra_unknown_puzzle.curried_args[1].as_iter()` in `match_cr_layer` confirms it is stored/iterated as a flat list of atoms): [5](#0-4) 

Any wallet user minting a CR-CAT (via `CRCATWallet.get_or_create_wallet_for_cat` / `CRCAT.launch`) fully controls the size of this list at coin-creation time, but the CLVM cost of validating it is paid by whoever spends the coin later — which can be a completely different party (e.g., the counterparty in an offer settlement, or the CAT's recipient after a transfer), exactly mirroring the "hot NFT holder crafts thousands-of-address whitelist, buyer pays the gas" scenario in the reported bug.

### Impact Explanation
If a malicious or careless minter creates a CR-CAT with an extremely large `authorized_providers` list, every future spend of that coin (transfer, offer settlement, VC-authorized approval flow in `VCWallet`) incurs CLVM execution cost proportional to the list size. Because Chia enforces a hard `MAX_BLOCK_COST_CLVM` / per-spend-bundle cost ceiling in `mempool_manager.py`, a sufficiently large `authorized_providers` list can push a single coin's spend cost above the mempool/block cost limit. That coin then becomes **permanently unspendable** — a spend-triggered transaction-processing halt for that specific coin/asset, effectively freezing the recipient's funds with no way to move them (since any spend requires re-validating the same oversized curried list). This also degrades network-wide performance/verification cost for every node re-validating spends of that asset, an amplification vector unrelated to the actual value transferred.

### Likelihood Explanation
Any unprivileged wallet user can mint a CR-CAT via `CRCATWallet.get_or_create_wallet_for_cat` / `CRCAT.launch` and choose an arbitrarily large `authorized_providers` list — no validation exists in the driver, wallet, or (as far as could be determined) puzzle layer to reject or cap it. An attacker distributing such a CR-CAT (e.g., via an airdrop, or as the "maker" side of an offer as seen in `test_cat_trades.py`) can grief any counterparty who accepts it into holding a coin they can no longer economically or technically spend.

### Recommendation
- Enforce a maximum length for `authorized_providers` (and similarly for any other unbounded curried lists such as DID `backup_ids`) at CR-CAT creation/mint time in `CRCATWallet.get_or_create_wallet_for_cat` / `CRCAT.launch`, rejecting lists beyond a safe bound.
- Consider replacing the flat curried list with a Merkle-root-based membership proof (as recommended in the source report) so that CLVM cost per spend is `O(log n)` instead of `O(n)`, decoupling the wallet-chosen provider-set size from per-spend cost.
- Add a client-side check (in wallet RPC / CAT wallet creation flow) that estimates and rejects puzzle reveals whose curried `authorized_providers` would push the spend bundle's cost above a configurable safety margin below `MAX_BLOCK_COST_CLVM`.

### Proof of Concept
1. Call `CRCATWallet.get_or_create_wallet_for_cat` (or directly `CRCAT.launch`) with an `authorized_providers` list containing, e.g., 50,000+ distinct `bytes32` provider IDs — nothing in `cr_cat_drivers.py` or `cr_cat_wallet.py` rejects this.
2. Mint/launch the CR-CAT and transfer it to a victim wallet (or offer it in a trade, as exercised in `chia/_tests/wallet/cat_wallet/test_trades.py`).
3. Have the victim attempt to spend the coin (transfer, or settle the offer). The CLVM execution of `CREDENTIAL_RESTRICTION` must process the full `authorized_providers` list; with a large enough list the resulting spend bundle cost exceeds `MAX_BLOCK_COST_CLVM`/mempool per-spend limits enforced in `chia/full_node/mempool_manager.py`, and the spend is rejected by the mempool indefinitely, leaving the victim's coin unspendable.

*Note: the exact CLVM opcodes of `CREDENTIAL_RESTRICTION` (from `chia_puzzles_py`) were not directly viewable in this index, so the precise cost-per-provider figure could not be measured here — this should be verified empirically (e.g., via `cost_logger` used in `test_vc_lifecycle.py`) by a Devin session with full repository/tooling access before finalizing severity.

```python
def construct_cr_layer(
    authorized_providers: list[bytes32],
    proofs_checker: Program,
    inner_puzzle: Program,
) -> Program:
    first_curry: Program = CREDENTIAL_RESTRICTION.curry(
        CREDENTIAL_STRUCT,
        authorized_providers,
        proofs_checker,
    )
    return first_curry.curry(first_curry.get_tree_hash(), inner_puzzle)
```

```python
def match_cr_layer(
    unknown_puzzle: UnknownPuzzle,
) -> tuple[list[bytes32], Program, Program] | None:
    if unknown_puzzle.mod is None or unknown_puzzle.curried_args is None:
        return None
    extra_unknown_puzzle = UnknownPuzzle(known_program=unknown_puzzle.mod)
    if extra_unknown_puzzle.mod == CREDENTIAL_RESTRICTION and extra_unknown_puzzle.curried_args is not None:
        return (
            [bytes32(provider.as_atom()) for provider in extra_unknown_puzzle.curried_args[1].as_iter()],
            extra_unknown_puzzle.curried_args[2],
            unknown_puzzle.curried_args[1],
        )
    else:
        return None
```

```python
    @classmethod
    async def get_or_create_wallet_for_cat(
        cls,
        wallet_state_manager: WalletStateManager,
        wallet: Wallet,
        limitations_program_hash: bytes32,
        name: str | None = None,
        authorized_providers: list[bytes32] | None = None,
        proofs_checker: ProofsChecker | None = None,
    ) -> Self:
        if authorized_providers is None or proofs_checker is None:  # pragma: no cover
            raise ValueError("get_or_create_wallet_for_cat was call on CRCATWallet without proper arguments")
        self = cls()
        self.standard_wallet = wallet
        if name is None:
            name = self.default_wallet_name_for_unknown_cat(limitations_program_hash)
        self.log = logging.getLogger(name)

        for id, w in wallet_state_manager.wallets.items():
            if w.type() == cls.type():
                assert isinstance(w, cls)
                if w.get_asset_id() == limitations_program_hash:
                    self.log.warning("Not creating wallet for already existing CR-CAT wallet")
                    return w

        self.wallet_state_manager = wallet_state_manager

        self.info = CRCATInfo(limitations_program_hash, None, authorized_providers, proofs_checker)
        info_as_string = bytes(self.info).hex()
        self.wallet_info = await wallet_state_manager.user_store.create_wallet(name, WalletType.CRCAT, info_as_string)

        await self.wallet_state_manager.add_new_wallet(self)
        self.tail_hash = self.info.limitations_program_hash
        return self
```
