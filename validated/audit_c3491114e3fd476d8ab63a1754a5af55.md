## Analysis

The OpenLeverage finding is about a safety check (anti-flash-loan TWAP guard) whose failure mode blocks a critical settlement path while leaving stale escrowed state around, opening a window for the protocol to lose funds. The concrete local analog in Hyperbridge is a fee-accounting bug in the GET-request lifecycle on `EvmHost.sol`: the request's escrowed fee metadata is never cleared after a `GetResponse` is successfully delivered, so the same escrowed fee can later be paid out a second time via the timeout path.

### Title
Double payment of GET request relayer fee via `dispatchIncoming(GetResponse)` + `dispatchTimeOut(GetRequestTimeout)` - (File: evm/src/core/EvmHost.sol)

### Summary
`EvmHost.dispatchIncoming(GetResponse, ...)` pays the relayer fee for a delivered `GetResponse` but never deletes the corresponding `_requestCommitments[commitment]` entry. `EvmHost.dispatchTimeOut(GetRequestTimeout, ...)` later refunds the *same* fee to `meta.sender` and only then deletes the commitment. Because the non-membership proof checked by `handleGetRequestTimeouts` is evaluated against a different state machine's storage/clock (the destination being queried) than the one used to accept the response, both payout paths can independently satisfy their own preconditions, letting the same escrowed fee be paid out twice.

### Finding Description
When a GET request is dispatched, its fee is escrowed on the source host: [1](#0-0) 

When the response is delivered back to the source and successfully handled, the relayer is paid, but the request-commitment/fee metadata is **not deleted**: [2](#0-1) 

Compare this with `dispatchTimeOut(PostRequestTimeout, ...)` and `dispatchTimeOut(GetRequestTimeout, ...)`, both of which delete `_requestCommitments[commitment]` as "replay protection" *before* paying out the fee to `meta.sender`: [3](#0-2) 

`handleGetRequestTimeouts` in the handler gates the timeout on: (a) the challenge period having elapsed, (b) `request.timeout() > state.timestamp` being false (i.e., the request looks timed out *according to the destination's committed state timestamp*), (c) a request commitment still existing (`meta.sender != address(0)`), and (d) a non-membership proof of a response receipt in the destination's state trie at `message.height`: [4](#0-3) 

Meanwhile, `handleGetResponses` accepts and pays for a response by verifying inclusion in Hyperbridge's own MMR overlay root and checking that a "known request" exists (`meta.sender != address(0)`) — it does not consult the destination's state trie at all: [5](#0-4) 

Because these two acceptance checks read from *independent* data sources (Hyperbridge's message-inclusion proof vs. the destination chain's own state-trie snapshot at some `message.height`), and because `dispatchIncoming(GetResponse)` leaves `_requestCommitments[commitment]` intact after paying the relayer, it is possible for:
1. A relayer to deliver the `GetResponse` early (before Hyperbridge's own clock considered the request timed out) and be paid the fee via `dispatchIncoming(GetResponse)`.
2. Someone to later submit `handleGetRequestTimeouts` with a `message.height` snapshot of the destination chain whose committed timestamp is past the request's `timeoutTimestamp`, and whose state trie at that height still shows no response receipt (this storage is unrelated to whatever caused Hyperbridge to accept the response) — satisfying every guard in `HandlerV2.handleGetRequestTimeouts`, and triggering a second payout of the same `meta.fee` via `dispatchTimeOut(GetRequestTimeout)`.

No malicious relayer, prover, or admin is required — both calls are documented as permissionless, and the exploit only depends on ordinary clock/height skew between Hyperbridge's view of "timed out" and the destination chain's committed state timestamp, which is normal cross-chain operating behavior, not an attacker-controlled fault.

### Impact Explanation
This is a direct double-claim/double-settlement of escrowed relayer fees: the `feeToken` balance held by `EvmHost` for one request gets paid out twice — once to the relayer that delivered the response, and once as a "timeout refund" to the original payer — draining the contract's fee-token reserves that back other users' pending requests. This matches the bounty's core impact category of "stealing or loss of funds" / "replay/double-claim/double-settlement," reached through the ordinary permissionless request/response/timeout handler paths.

### Likelihood Explanation
Both `handleGetResponses` and `handleGetRequestTimeouts` are explicitly permissionless entry points. The only requirement is a legitimate, valid state proof of the destination chain at a height whose timestamp exceeds the GET request's timeout, submitted after (or racing with) an already-paid response — a realistic scenario whenever GET response delivery is close to the request's timeout window, which is a normal and expected condition, not an edge case requiring privileged access.

### Recommendation
Delete (or zero out) `_requestCommitments[commitment]` in `dispatchIncoming(GetResponse, ...)` immediately after determining the response was successfully handled, mirroring the replay protection already applied in `dispatchTimeOut`. Additionally, `handleGetRequestTimeouts` should check `host.responseReceipts(commitment)` (the source-side receipt already used for duplicate detection in `handleGetResponses`) is unset before allowing a timeout refund, so a response processed on the source can never be followed by a timeout refund for the same commitment.

### Proof of Concept
1. App dispatches a `GetRequest` via `EvmHost.dispatch(DispatchGet)`; fee `F` is escrowed and `_requestCommitments[commitment] = {sender: payer, fee: F}` (evm/src/core/EvmHost.sol:987 area, `_requestCommitments` assignment analogous to line 948).
2. A relayer submits a valid `GetResponseMessage` shortly before Hyperbridge's clock considers the request timed out; `HandlerV2.handleGetResponses` verifies the MMR proof and calls `host.dispatchIncoming(response, relayer)`, which pays `F` to the relayer via `IERC20(feeToken()).safeTransfer(relayer, fee)` — `_requestCommitments[commitment]` remains untouched (evm/src/core/EvmHost.sol:824-847).
3. Anyone submits a `GetTimeoutMessage` for the same request, using a `message.height` for the destination chain whose committed `state.timestamp` is past `request.timeoutTimestamp`, together with a valid non-membership proof (of the unrelated `RESPONSE_RECEIPTS_STORAGE_PREFIX` slot on that snapshot) — all checks in `HandlerV2.handleGetRequestTimeouts` pass since `meta.sender` is still non-zero (evm/src/core/HandlerV2.sol:293-321).
4. `host.dispatchTimeOut(GetRequestTimeout, meta, commitment)` pays `F` a second time to `meta.sender` (the payer) before finally deleting the commitment (evm/src/core/EvmHost.sol:856-877).
5. Net effect: `2F` paid out of `EvmHost`'s fee-token balance for a single `F` escrowed — a double-claim draining shared reserves.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetResponses(IHost host, GetResponseMessage calldata message) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(message.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 responsesLength = message.responses.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](responsesLength);

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // don't check for timeouts because it's checked on Hyperbridge

            // known request? also serves as source check
            FeeMetadata memory meta = host.requestCommitments(leaf.response.request.hash());
            if (meta.sender == address(0)) revert UnknownMessage();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.response.hash());
        }

        bytes32 root = host.stateMachineCommitment(message.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, message.proof.multiproof, leaves, message.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < responsesLength; ++i) {
            GetResponseLeaf memory leaf = message.responses[i];
            // duplicate response?
            if (host.responseReceipts(leaf.response.request.hash()).relayer != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.response, _msgSender());
        }
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
