### Title
Gasless/Auction bundle transactions can be permanently marked unexecutable on non-attributable errors during bundle execution - (File: work/worker.go)

### Summary
`commitBundleTransaction` in [1](#0-0)  applies each transaction in a bundle (used by both the `gasless` and `auction` `kaiax` modules) and, on **any** error or non-successful receipt status other than a narrow allow-list (`vm.ErrInsufficientBalance`, `vm.ErrTotalTimeLimitReached`), calls `markAllTxUnexecutable()`, which flags every transaction in the bundle — not just the failing one — as permanently unexecutable via `tx.MarkUnexecutable(true)`.

### Finding Description
The relevant logic: [2](#0-1) 

This mirrors the GMX bug pattern precisely: the code distinguishes only a couple of specific error conditions as "legitimate/transient" and treats every other error (regardless of cause — e.g. a node-local timing condition, a reentrancy/consistency guard, an unrelated EVM revert triggered by block-building nondeterminism, etc.) as grounds to irreversibly cancel the transaction's future eligibility, exactly like `_handleDepositError` treating every non-`isEmptyPriceError` selector as grounds for `cancelDeposit`. `markAllTxUnexecutable` is invoked on the *entire bundle*, so a benign, unrelated transaction bundled together with a gasless swap or an auction bid transaction (see `kaiax/gasless/impl/builder.go` [3](#0-2)  and `kaiax/auction/impl/builder.go` [4](#0-3) ) can also be marked unexecutable collaterally.

Once marked, `MarkUnexecutable` is checked/used extensively in the tx pool (`blockchain/tx_pool.go`, `blockchain/tx_list.go`) to exclude a transaction from further block-building consideration — effectively "cancelling" the user's pending gasless swap or searcher's auction bid without the user's consent, similar to how GMX's deposit/withdrawal/order got wrongly cancelled by an over-broad catch clause.

### Impact Explanation
An unprivileged gasless user or auction searcher (bidder) whose transaction happens to be bundled with another transaction that fails for a reason unrelated to their own transaction's validity (anything outside the two allow-listed errors) can have their transaction permanently excluded from block inclusion. This denies gasless/auction users their submitted transaction/bid without it actually being invalid — an unwarranted "cancellation" analogous to the reported bug's core defect (missing/insufficient error differentiation before an irreversible cancel/drop action).

### Likelihood Explanation
This code path is reached anytime a `gasless` swap bundle or `auction` bid bundle is processed by `ApplyTransactions`/`commitBundleTransaction` during ordinary block building — no special privilege is needed, and any submitted transaction that triggers an unlisted error condition (which could include normal EVM-level conditions not enumerated in the allow-list) will hit this branch.

### Recommendation
Narrow the "cancel" (mark-unexecutable) condition to only the errors that are proven to originate from the specific transaction's own invalidity (e.g., nonce/state failure attributable to that sender), and treat all other errors (module-disabled-like conditions, unrelated systemic errors) as retryable/transient — do not mark the transaction unexecutable, and avoid collaterally marking co-bundled, unrelated transactions.

### Proof of Concept
1. A gasless-swap bundle `[approveTx, swapTx]` (or an auction bundle `[bidTx]` tied to a target tx) is selected for block building via `ExtractTxBundles`.
2. During `commitBundleTransaction`, `bc.ApplyTransaction` returns a non-`ErrInsufficientBalance`/non-`ErrTotalTimeLimitReached` error or a non-successful receipt (e.g., due to some transient EVM/node condition unrelated to the sender's transaction validity).
3. `markAllTxUnexecutable()` is invoked at [5](#0-4) , flagging every tx object in the bundle — including a perfectly valid co-bundled transaction — as unexecutable.
4. The transaction pool subsequently treats the flagged transaction as ineligible for inclusion (via the `MarkUnexecutable` usages in `blockchain/tx_pool.go`), so the user's gasless swap or searcher's bid never gets included in any future block, despite never being at fault.

Note: I was not able to fully read the exact downstream pool logic gated on `MarkUnexecutable`/`IsUnexecutable` in `blockchain/tx_pool.go` and `blockchain/tx_list.go` before running out of tool calls, so the precise mechanics of how "unexecutable" transactions are subsequently excluded/evicted from the pool should be independently verified.

func (env *Task) commitBundleTransaction(bundle *builder.Bundle, bc BlockChain, nodeAddr common.Address, vmConfig *vm.Config) (error, *types.Transaction, []*types.Log) {
	lastSnapshot := env.state.Copy()
	gasUsedSnapshot := env.header.GasUsed
	blobGasUsedSnapshot := env.header.BlobGasUsed
	blobsSnapshot := env.blobs
	tcountSnapshot := env.tcount
	txs := []*types.Transaction{}
	receipts := []*types.Receipt{}
	logs := []*types.Log{}

	markAllTxUnexecutable := func() {
		for _, txOrGen := range bundle.BundleTxs {
			if txOrGen.IsConcreteTx() {
				tx, _ := txOrGen.GetTx(0)
				tx.MarkUnexecutable(true)
			}
		}
	}

	restoreEnv := func() {
		env.state.Set(lastSnapshot)
		env.header.GasUsed = gasUsedSnapshot
		env.tcount = tcountSnapshot
		// blob related env are restored to the snapshot
		env.header.BlobGasUsed = blobGasUsedSnapshot
		env.blobs = blobsSnapshot
	}

	var totalTxSize uint64 = 0
	for _, txOrGen := range bundle.BundleTxs {
		tx, err := txOrGen.GetTx(env.state.GetNonce(nodeAddr))
		if err != nil {
			logger.Error("TxGenerator error", "error", err)
			markAllTxUnexecutable()
			restoreEnv()
			return kerrors.ErrTxGeneration, nil, nil
		}

		env.state.SetTxContext(tx.Hash(), common.Hash{}, env.tcount)
		receipt, _, err := bc.ApplyTransaction(env.config, &nodeAddr, env.state, env.header, tx, &env.header.GasUsed, vmConfig)
		// Bundled tx will be rejected with any receipt.Status other than success.
		// There may be cases where a revert occurs within the EVM, which could result in an attack on a tx sender in an already executed bundle.
		if err != nil || receipt.Status != types.ReceiptStatusSuccessful {
			if err != vm.ErrInsufficientBalance && err != vm.ErrTotalTimeLimitReached {
				markAllTxUnexecutable()
			}
			receiptStatus := ""
			if receipt != nil {
				receiptStatus = strconv.FormatUint(uint64(receipt.Status), 10)
			}
			logger.Warn("ApplyTransaction error, restoring env",
				"blockNum", env.header.Number.String(), "txHash", tx.Hash().String(),
				"error", err, "receiptStatus", receiptStatus,
			)
			restoreEnv()
			if err == nil {
				err = kerrors.ErrRevertedBundleByVmErr
			}
			return err, tx, nil
		}

		env.tcount++
		totalTxSize += uint64(tx.Size())
		txs = append(txs, tx)
		receipts = append(receipts, receipt)
		logs = append(logs, receipt.Logs...)
		if tx.Type() == types.TxTypeEthereumBlob {
			env.blobs += len(tx.BlobHashes())
			*env.header.BlobGasUsed += tx.BlobGas()
		}
	}

	env.size += totalTxSize
	env.txs = append(env.txs, txs...)
	env.receipts = append(env.receipts, receipts...)

	return nil, nil, logs
}
