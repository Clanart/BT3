### Title
Missing path binding and freshness checks in `query_string_valid?` allow replay of a captured signed app-proxy request against unrelated actions - (File: `lib/shopify_app/controller_concerns/app_proxy_verification.rb`)

### Summary
`ShopifyApp::AppProxyVerification#query_string_valid?` verifies only that the HMAC over the raw query string matches; it never checks that the query string's `path_prefix`/actual path corresponds to the controller action actually being invoked, nor that the `timestamp` param is recent. Any legitimate signed app-proxy URL observed once by an attacker can therefore be replayed verbatim against any other controller action in the host app that also includes this same concern, indefinitely, as long as the same shared secret is in effect.

### Finding Description
`query_string_valid?` [1](#0-0)  only re-derives the HMAC from the query hash (`calculated_signature`) and compares it against the supplied `signature` using `secure_compare`. It never inspects `request.path`, never compares it to the signed `path_prefix` parameter, and never checks `timestamp` against `Time.now` for staleness. `verify_proxy_request` simply calls this check as a `before_action` on whichever controller includes the concern [2](#0-1) .

Because each controller independently mixes in `AppProxyVerification` and Rails routing decides which action is invoked, the validity of the signature is completely decoupled from the destination route: the same `shop=...&path_prefix=...&timestamp=...&signature=...` query string that was originally issued by Shopify for one mounted action will validate identically when replayed against a different action/controller that also includes the module, as confirmed by the existing test harness pattern where `query_string_valid?` is checked independent of the actual request path [3](#0-2) . There is no code anywhere in this file (or its test) that ties the signed `path_prefix` value to `request.fullpath`/`request.path`, and no expiry/staleness enforcement on `timestamp`.

### Impact Explanation
An attacker who observes one legitimate signed app-proxy URL (e.g., via browser history, referer leakage, logs, or a shared link) can replay that exact query string against a different action mounted under the app that also uses `ShopifyApp::AppProxyVerification`, causing the app to treat the forged/misdirected request as a Shopify-authenticated app-proxy call. This maps to Shopify's "forged app-proxy request" impact class: the app cannot distinguish between the request Shopify actually intended to authorize for a given endpoint and an attacker-redirected replay to an unrelated endpoint, and the same captured signature remains valid indefinitely (no timestamp freshness enforcement), widening the replay window.

### Likelihood Explanation
Exploitability requires only that the attacker previously obtain one valid signed app-proxy query string for the shop (a low bar, since proxy URLs are exposed in the browser and often logged/cached) and that the host app expose more than one controller/action guarded by this shared concern. No secret, session, or Shopify-side compromise is required beyond passively capturing one URL. The replay is fully repeatable since the signature never expires and is not bound to a specific action.

### Recommendation
In `query_string_valid?`/`verify_proxy_request`, additionally validate that `query_hash["path_prefix"]` matches the current request's path (or the expected mount path for that controller), and reject requests where `timestamp` is older than a small tolerance window (e.g., a few minutes), in addition to the existing HMAC check.

### Proof of Concept
```ruby
class OtherProxyController < ActionController::Base
  include ShopifyApp::AppProxyVerification
  def other_action
    head(:ok)
  end
end

test "captured signature for one action is accepted on an unrelated action" do
  with_routing do |set|
    set.draw do
      get "/app_proxy/basic" => "app_proxy_verification#basic"
      get "/app_proxy/other" => "other_proxy#other_action"
    end

    valid_params = {
      shop: "some-random-store.myshopify.com",
      path_prefix: "/apps/my-app",
      timestamp: "1466106083",
      signature: "f5cd7233558b1c50102a6f33c0b63ad1e1072a2fc126cb58d4500f75223cefcd",
    }

    # Originally captured/valid for one action
    get "/app_proxy/basic", params: valid_params
    assert_response :ok

    # Same exact query string replayed against a completely different action/route
    get "/app_proxy/other", params: valid_params
    assert_response :ok # currently PASSES - demonstrates the replay/no-path-binding weakness
  end
end
```

    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end
