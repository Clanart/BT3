## Finding

### Title
Attacker-controlled `WWW-Authenticate` header from any git remote can spoof Desktop's GitHub credential classification and trigger an unsolicited GitHub sign-in/account-binding prompt - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
Desktop's git credential-helper trampoline classifies the "kind" of endpoint a git operation is authenticating against (`'github.com' | 'ghe.com' | 'enterprise' | 'generic'`) before deciding how to source credentials. For hosts that don't match the known GitHub.com/GHE URL patterns, the classifier falls back to trusting the `WWW-Authenticate` HTTP response header that git itself forwards from the remote server, unauthenticated and unverified: if the header contains `realm="GitHub"`, the endpoint is unconditionally classified as `'enterprise'`. [1](#0-0) 

Because this value is emitted by the remote HTTP server responding to the git operation, any git remote (or a proxy/MITM sitting in front of one) fully controls it — this maps directly to the report's attacker primitive of "a git remote/proxy response."

### Finding Description
`createCredentialHelperTrampolineHandler` invokes `getCredential`, which calls `getEndpointKind(cred, store)` to decide how to source the credential Git is asking for: [2](#0-1) 

`getEndpointKind` first checks `isDotCom`/`isGHE` against the *actual* hostname (safe), but if those don't match, it inspects `wwwauth[...]` credential fields — values that originate from the `WWW-Authenticate` header of the HTTP response the remote server sent back to Git — and classifies the host as `'enterprise'` purely because the header string contains `realm="GitHub"`: [3](#0-2) 

Back in `getCredential`, when the classification is not `'generic'` and no account is already stored for that exact endpoint, Desktop calls `ui.promptForGitHubSignIn(endpoint)`: [4](#0-3) 

`promptForGitHubSignIn` then unconditionally kicks off a GitHub-branded sign-in flow (dotcom or enterprise) for the attacker-controlled `endpoint`, and shows the `PopupType.SignIn` dialog with `isCredentialHelperSignIn: true`, telling the user that "Git [is] requesting credentials to access <endpoint>": [5](#0-4) [6](#0-5) 

No guard verifies that the host actually is a GitHub Enterprise deployment before this classification/prompt path is reached — the only "authority" behind the `'enterprise'` designation is a header value the remote chose to send.

### Impact Explanation
Any git remote the user clones/fetches/pushes to — including a completely generic, non-GitHub host, or a network position that can inject a `WWW-Authenticate: Basic realm="GitHub"` response on an HTTP 401 — can force Desktop to:
- Treat an arbitrary attacker domain as a legitimate GitHub Enterprise endpoint (`endpointKind = 'enterprise'`).
- Spontaneously surface Desktop's trusted, GitHub-branded native sign-in dialog for that domain during an otherwise ordinary git operation the user did not request.
- Drive the user into an OAuth/account-binding flow (`beginEnterpriseSignIn` → `setSignInEndpoint(origin)` → browser-based OAuth) scoped to the attacker's host, with Desktop presenting it as a routine GitHub authentication step.

This satisfies "unauthorized OAuth or account binding" triggered purely by an attacker-controlled remote/proxy response, without any local access, admin rights, or prior compromise — the only requirement is that the user perform a normal git operation (clone/fetch/push) against a repository whose remote is attacker-controlled or reachable by a MITM/proxy.

### Likelihood Explanation
Likelihood is moderate-to-high for any workflow where Desktop is used against self-hosted/third-party git servers or where network-level response tampering (e.g., a compromised corporate proxy, malicious Wi-Fi, or a rogue git server offered as a "helpful mirror") is feasible. No sophisticated payload is required — a single `WWW-Authenticate: Basic realm="GitHub"` header on any authenticated HTTP git response is sufficient, and Git already forwards this header verbatim to credential helpers as part of its normal protocol, so no protocol violation or Git-side special casing is needed by the attacker.

### Recommendation
- Do not classify an endpoint as GitHub/`'enterprise'` based solely on a `WWW-Authenticate` header emitted by the remote. At minimum, require independent, verifiable confirmation (e.g., the same `isGitHubHost` network probe already used elsewhere in `api.ts`, restricted to an explicit user opt-in) before treating an unfamiliar host as a GitHub Enterprise instance.
- If the header-based fast path is kept for UX reasons, surface it as a lower-trust hint only, and require explicit user confirmation of the actual hostname before initiating any sign-in/account-binding flow, rather than auto-launching the credential-helper-triggered `SignIn` popup.

### Proof of Concept
1. Stand up (or MITM/proxy) a git-over-HTTP(S) server at `https://attacker.example`.
2. Configure it to respond to Git's credential probe (`GET /info/refs...` or the initial unauthenticated request) with `401 Unauthorized` and header `WWW-Authenticate: Basic realm="GitHub"`.
3. In GitHub Desktop, clone or add `https://attacker.example/foo.git` as a remote and perform a fetch/push.
4. Git forwards the captured header to Desktop's credential helper as a `wwwauth[...]` credential field; `getEndpointKind` (`app/src/lib/trampoline/trampoline-credential-helper.ts:157-165`) returns `'enterprise'`.
5. Since no account exists for `attacker.example`, `getCredential` calls `ui.promptForGitHubSignIn('https://attacker.example')`, and Desktop shows its native "Sign in" dialog claiming "Git [is] requesting credentials to access https://attacker.example," beginning an Enterprise OAuth/account-binding flow scoped to the attacker's domain.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
