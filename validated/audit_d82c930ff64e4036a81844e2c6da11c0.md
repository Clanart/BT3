### Title
Server-Side Request Forgery via unrestricted DataLayer mirror URLs fetched by subscribing peers - (File: `chia/data_layer/download_data.py`)

### Summary
Any wallet user can publish an on-chain "mirror" record for a DataLayer store containing arbitrary, attacker-controlled URL strings. Any other Chia node that later subscribes to that store id will have its DataLayer service fetch those URLs via outbound HTTP requests, with no restriction on scheme, host, or destination (including internal/link-local/cloud-metadata addresses). This mirrors the CVE-2020-23534 bug class: a user-supplied "source"/URL value is used server-side to make an outbound request without validation, enabling SSRF.

### Finding Description
`DataLayerWallet.create_new_mirror()` lets any wallet owner create a mirror coin whose puzzle memos embed a launcher id and an arbitrary list of URL strings, with the only server-side check being "not empty": [1](#0-0) [2](#0-1) 

These URLs are recorded verbatim as chain data (memos on a `create_mirror_puzzle()` coin) and picked up by any node tracking that launcher id through `coin_added()`, with zero validation of URL scheme/host: [3](#0-2) 

Any peer's `DataLayer` service that later subscribes to the same store id pulls these URLs via `update_subscriptions_from_wallet()`: [4](#0-3) 

and then `fetch_and_validate()` shuffles the eligible mirror URLs and performs outbound HTTP GETs against them using `http_download()`, which builds the request target directly from `server_info.url` with no scheme/host allow-listing, blocking of private/link-local ranges, or SSRF protections: [5](#0-4) [6](#0-5) 

The only validation performed anywhere in this path (`is_filename_valid()`) checks the *filename* format, not the URL/host being connected to: [7](#0-6) 

This lets any wallet participant (an "unprivileged" DataLayer client relative to victims) coerce every peer subscribing to that store — a normal, expected DataLayer client action — into issuing server-initiated HTTP requests to attacker-chosen destinations (e.g., internal services, `169.254.169.254` cloud metadata, or other localhost ports on the victim host), matching the "SSRF via unvalidated source/URL parameter" bug class described in the referenced CVE.

### Impact Explanation
A DataLayer node is coerced into making outbound HTTP requests to arbitrary attacker-chosen endpoints as a background, automatic consequence of subscribing to a store — no explicit user click or confirmation is required beyond the routine subscribe/mirror-sync action. This can be used to probe/attack internal network services reachable only from the victim's host, hit cloud-metadata endpoints to potentially exfiltrate credentials, or perform request smuggling/DoS against internal infrastructure that trusts requests originating from the DataLayer host. It does not directly enable coin theft, but it is a genuine, network-reachable SSRF triggered purely by data an unprivileged chain participant controls.

### Likelihood Explanation
High. Creating a mirror with attacker-chosen URLs only requires standard wallet RPC access and a normal `dl_new_mirror` transaction (`chia dl add_mirror`), which any wallet holder can execute. Any node that subscribes to that store (a routine, expected DataLayer operation, and also happens automatically for owned/pseudo-subscribed and multi-store scenarios) will then fetch the URL(s) with no gating.

### Recommendation
Validate mirror/server URLs before they are used to originate outbound requests: enforce an allowed URL scheme (e.g., only `http`/`https`, explicitly reject other schemes), resolve and reject destinations in private/link-local/loopback/metadata ranges unless explicitly opted in (similar to typical SSRF mitigations), and consider requiring subscribers to confirm/allow-list mirror hosts rather than trusting on-chain mirror data implicitly. Apply the same validation both to `http_download()` in `chia/data_layer/download_data.py` and to the `get_downloader()`/plugin dispatch path in `chia/data_layer/data_layer.py`.

### Proof of Concept
1. Attacker wallet creates a DataLayer store and calls `dl_new_mirror` (via RPC or `chia data add_mirror`) with `urls=["http://169.254.169.254/latest/meta-data/", "http://internal-service.local:9999/admin"]`, per `chia/data_layer/data_layer_wallet.py:687-703` and `chia/data_layer/data_layer.py:965-970`.
2. The mirror coin confirms on-chain; any victim node syncing the chain records the mirror via `coin_added()` in `chia/data_layer/data_layer_wallet.py:775-800`.
3. Victim operator subscribes their DataLayer service to the same store id (a normal, expected action for a Data Layer client wanting the dataset).
4. During the periodic sync loop, `update_subscriptions_from_wallet()` pulls the attacker URLs (`chia/data_layer/data_layer.py:979-985`), and `fetch_and_validate()`/`http_download()` issue outbound HTTP requests to them (`chia/data_layer/data_layer.py:642-694`, `chia/data_layer/download_data.py:298-324`), demonstrating SSRF from the victim's DataLayer host to attacker-chosen destinations.

```python
def is_filename_valid(filename: str, group_by_store: bool = False) -> bool:
    if group_by_store:
        if filename.count("/") != 1:
            return False
        filename = filename.replace("/", "-")

    split = filename.split("-")

    try:
        raw_store_id, raw_node_hash, file_type, raw_generation, raw_version, *rest = split
        store_id = bytes32(bytes.fromhex(raw_store_id))
        node_hash = bytes32(bytes.fromhex(raw_node_hash))
        generation = int(raw_generation)
    except ValueError:
        return False

    if len(rest) > 0:
        return False

    # TODO: versions should probably be centrally defined
    if raw_version != "v1.0.dat":
        return False

    if file_type not in {"delta", "full"}:
        return False

    generate_file_func = get_delta_filename if file_type == "delta" else get_full_tree_filename
    reformatted = generate_file_func(
        store_id=store_id, node_hash=node_hash, generation=generation, group_by_store=False
    )

    return reformatted == filename
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
