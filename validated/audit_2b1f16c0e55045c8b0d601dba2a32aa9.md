## Title
Reward-watermark desync when `pallet-consensus-incentives` incentives are removed and re-added lets a single relayer drain the treasury for the entire dormant span - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet-consensus-incentives` pays relayers `(latest_height - baseline) * cost_per_block` for advancing a state machine's consensus height, where `baseline` comes from the `LastRewardedHeight` watermark [1](#0-0) . When governance removes a chain's `cost_per_block` (via `remove_incentives`) the `process_message` early-returns before ever touching `LastRewardedHeight`, so the watermark freezes while the chain keeps advancing on unpaid consensus updates [2](#0-1) . When incentives are later re-enabled with `update_cost_per_block`, the very next relayer to submit a single consensus proof is paid for the *entire* height span that accumulated while incentives were off, not just their own contribution.

### Finding Description
This is a direct local analog of the `GaugeExtraRewarder` bug: an auxiliary accounting ledger (`LastRewardedHeight`) tracks state that must stay in sync with the authoritative source of truth (`IsmpHost`'s `latest_commitment_height`), but the update path is gated behind a togglable condition (`cost_per_block` configured or not — the "pause" analog). While the ledger update is skipped, the authoritative state keeps moving. Once the gate reopens, the stale ledger causes the reward formula to pay out based on the full accumulated drift rather than the actual work done by the relayer being paid.

Concretely:
- `process_message` only runs its body — including the `LastRewardedHeight::mutate` watermark bump — inside `if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id)` [3](#0-2) .
- `remove_incentives` deletes `StateMachinesCostPerBlock` for a chain [4](#0-3) . While removed, `pallet_ismp`/consensus clients still accept and advance `latest_commitment_height` via ordinary unsigned consensus message submission — this is a normal, permissionless, unprivileged path (`pallet_ismp::Pallet::handle_unsigned`), not an admin action.
- `calculate_reward` computes `baseline = LastRewardedHeight::get(state_machine_id).unwrap_or(previous_height)` and `reward = (latest_height - baseline) * block_cost` [5](#0-4) . Because the watermark never moved during the incentive-off window, `baseline` is stale by the entire dormant span.
- When governance calls `update_cost_per_block` to re-enable rewards, the very next unprivileged relayer to submit any qualifying consensus message triggers `process_message`, which pays `(current_latest_height - stale_baseline) * cost_per_block` — a reward sized to the whole unpaid backlog, not to the single update this relayer actually delivered.

This mirrors the report's core broken invariant precisely: "if any deposits/withdrawals happen while paused, the tracking function does not fire, so internal accounting diverges from the authoritative source; the divergence is realized incorrectly once un-paused." Here, "deposits/withdrawals" are consensus height advances, "pause" is `cost_per_block` removal, and the "internal accounting" is `LastRewardedHeight`.

### Impact Explanation
The treasury (`T::TreasuryAccount`) pays out `T::Currency::transfer` for the inflated reward and mints an equal amount of `ReputationAsset` [6](#0-5) , with no cap tied to the submitting relayer's actual marginal contribution. An unprivileged relayer that merely watches for `StateMachineCostPerBlockUpdated` events and races to submit the first consensus message afterward can collect a reward proportional to the entire span the chain advanced while incentives were off — potentially orders of magnitude larger than the intended per-update reward, and disproportionate reputation minting that feeds into collator-selection weighting. This is a direct treasury fund-loss / logic-attack vector reachable through a normal, permissionless entrypoint (`handle_unsigned` consensus submission), not requiring a compromised admin.

### Likelihood Explanation
`remove_incentives`/`update_cost_per_block` toggling is a legitimate, foreseeable governance operation (e.g., temporarily disabling rewards for a chain during maintenance, cost review, or a client migration) — it is not a malicious-governance scenario. The exploiting relayer needs no special privilege: it only needs to observe the public `StateMachineCostPerBlockUpdated` event and be first to submit the next consensus message, which is exactly the permissionless, competitive relaying model the protocol already documents ("first relayer to submit... is rewarded"). Any chain that experiences a pause/resume cycle in its incentive configuration is affected the first time rewards resume.

### Recommendation
Update `LastRewardedHeight` to the chain's current `latest_commitment_height` at the moment incentives are removed (in `remove_incentives`) so the watermark cannot go stale, or alternatively re-baseline it to the current height when `update_cost_per_block` re-enables a chain (in `update_cost_per_block`), so that a subsequent reward computation only covers blocks advanced *after* incentives resumed. Either fix keeps the reward calculation bound to genuine post-resume relayer work instead of the entire dormant span.

### Proof of Concept
1. Governance sets `cost_per_block = 100` for `state_machine_id = X`, chain is at height 1000, watermark `LastRewardedHeight(X) = 1000` (from a prior reward).
2. Governance calls `remove_incentives(X)` (e.g., temporary cost-control decision).
3. Over the following period, ordinary unprivileged relayers submit consensus proofs advancing `X`'s `latest_commitment_height` from 1000 to 100000 (100,000 fresh blocks) via `pallet_ismp::handle_unsigned`. No rewards are paid and `LastRewardedHeight(X)` stays at 1000 because `process_message`'s body — including the watermark mutate — never executes (`StateMachinesCostPerBlock::get(X)` is `None`).
4. Governance calls `update_cost_per_block(X, 100)` to resume incentives.
5. An unprivileged relayer submits one more consensus message, advancing the height from 100000 to 100001.
6. `calculate_reward` computes `baseline = LastRewardedHeight(X) = 1000`, `blocks = 100001 - 1000 = 99001`, `reward = 99001 * 100 = 9,900,100` — paid entirely to the single relayer who happened to submit the resuming update, funded from the treasury, plus an equal reputation mint, despite that relayer having done ~1 block of actual incremental work.

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}
