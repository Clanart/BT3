### Title
Loose hostname heuristic in `isGitHubHost()` lets an attacker-controlled remote be misclassified as a trusted GitHub/GHE host - (File: app/src/lib/api.ts)

### Summary
The Sherlock report's root cause is a broken-identity check: `FaultDisputeGame`/`DisputeGameFactory` trusts `tx.origin` — a value an attacker can substitute — instead of verifying the actual authorized caller, letting an attacker be misattributed as the legitimate party. The Desktop analog is `isGitHubHost()`, which decides whether a git remote/credential-helper request belongs to "GitHub" using a regex that can be satisfied by any domain an attacker controls, rather than verifying real GitHub/GHE identity. That misclassification feeds directly into the credential-helper trust decision (`getEndpointKind`) that governs whether Desktop treats a host as GitHub Enterprise and offers to sign the user in.

### Finding Description
`isGitHubHost()` in `app/src/lib/api.ts:2429-2491` is used as a best-effort classifier for "is this remote a GitHub host". Part of its logic is: [1](#0-0) 

```
  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }
```

The regex `/(^|\.)(github)\./` only checks for the literal label `github` followed by a dot, anchored to the start of the hostname or a preceding dot. It does not check that the domain is actually `github.com`, `*.ghe.com`, or a GHE instance the user configured — any attacker-registered domain containing a `github.` label (e.g. `foo.github.attacker-domain.com`) satisfies it, as long as it isn't already on the small `isKnownThirdPartyHost` denylist.

This function feeds `getEndpointKind()` in the credential-helper trampoline, which decides how Desktop treats a git host during an authenticated operation: [2](#0-1) 

If `isGitHubHost()` wrongly returns `true`, the host is classified `'enterprise'` instead of `'generic'`. Then in `getCredential()`: [3](#0-2) 

Since there is no existing `Account` for this attacker-controlled endpoint, Desktop calls `ui.promptForGitHubSignIn(endpoint)`, which opens the native "Sign in to GitHub Enterprise" dialog and begins the OAuth sign-in flow *against the attacker's own domain*: [4](#0-3) 

This is the exact same class of bug as the report: a trust/identity decision (“is this the legitimate counterparty?”) is derived from an attacker-influenceable value (a domain name pattern the attacker fully controls) instead of a robust check (an allow-listed configured endpoint or verified GitHub API response), so the attacker can impersonate the trusted party from Desktop's point of view. Additionally, because `'enterprise'`/`'github.com'` classifications are excluded from generic credential storage/erasure (`storeCredential`/`eraseCredential` both bail when `endpointKind !== 'generic'`), the misclassification also silently breaks normal generic-git-auth credential handling for such hosts.

### Impact Explanation
An attacker who controls a domain matching the loose `github.` pattern (trivial — they can register any subdomain they like) and gets a victim to add/fetch/push to a remote pointing at that domain (e.g., via a cloned repository with a malicious `origin`/`upstream`, a submodule URL, or a CLI-clone/deep-link URL) can cause Desktop to:
- misclassify the remote as a legitimate GitHub Enterprise host, and
- surface Desktop's own "Sign in to GitHub Enterprise" / OAuth flow scoped to the attacker's domain, lending false platform-level legitimacy to what is really an attacker-hosted phishing/credential harvesting page rendered as part of the trusted Desktop sign-in UI.

This is not full "code execution", but it is a genuine identity/trust confusion bug in the same class as the report: Desktop's authorization logic accepts an attacker-supplied value as proof of being "GitHub" the same way the FDG accepted `tx.origin` as proof of being the legitimate claimant.

### Likelihood Explanation
Likelihood is limited by the fact that the endpoint URL is visible in the sign-in dialog (a user paying attention could notice the domain is not `github.com`/their real GHE host), and interactive prompts are suppressed for background tasks (`getIsBackgroundTaskEnvironment`), so it only triggers on foreground, user-initiated git operations against the malicious remote. It requires the victim to add a remote pointing at the attacker's crafted hostname, which is a normal, unprompted action (adding/cloning a repo with an existing remote configuration, or opening a deep link) rather than local/physical access or prior malware.

### Recommendation
Replace the substring/regex heuristic in `isGitHubHost()` with a check against the actual configured endpoints (`isDotCom`, `isGHE`, and the user's explicitly-added GHE endpoints) plus, when unknown, rely solely on the authoritative network probe (`x-github-request-id` header check) rather than a guessable hostname pattern. Do not treat an unrecognized domain as GitHub/GHE merely because it contains the substring `github.`.

### Proof of Concept
1. Attacker registers `sync.github.corp-updates.com` and hosts an HTTPS git server that requires authentication and does not set any of the known third-party `WWW-Authenticate` realms.
2. Attacker gets a victim to add this URL as a remote (e.g., in a cloned repository's `.gitmodules`, or via `x-github-client://openrepo/https://sync.github.corp-updates.com/foo/bar` handled by `parseAppURL`/`openOrCloneRepository`), then the victim clones/fetches it through Desktop's UI (foreground, interactive).
3. Git invokes the credential helper trampoline; `getCredentialUrl(cred)` resolves to `https://sync.github.corp-updates.com`.
4. `getEndpointKind()` calls `isGitHubHost()`, whose regex `/(^|\.)(github)\./` matches `sync.github.corp-updates.com`, returning `true`, so the endpoint is classified `'enterprise'`.
5. No `Account` exists for this endpoint, so `ui.promptForGitHubSignIn()` is invoked, opening Desktop's native "Sign in to GitHub Enterprise" popup and beginning an OAuth flow whose authorize/token endpoints are entirely controlled by the attacker's server, rendered as a first-party Desktop sign-in experience.

Note: I was not able to fully trace every downstream consumer of `isGitHubHost()` within the available indexed code (some files may be truncated by index limits), so there may be additional trust decisions gated on this same flawed check; a full Devin session with complete repository access would be needed to enumerate every call site.

```typescript
const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
```

```typescript
  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
```
