### Title
Unsanitized `params[:shop]` comparison in `session_shop_conflicts_with_params` allows cross-shop session confusion to bypass forced re-login - ([File: lib/shopify_app/controller_concerns/login_protection.rb])

### Summary
`login_again_if_different_user_or_shop` is the guard responsible for detecting when the `shop`/`session` query params sent by the Admin iframe no longer match the currently active cookie session, and forcing a fresh login/session reset if they diverge. The shop-side check, `session_shop_conflicts_with_params`, compares `current_shopify_session.shop` (a normalized, canonical `*.myshopify.com` value) directly against the raw, unsanitized `params[:shop]`, instead of using the gem's own `sanitize_shop_param`/`sanitize_shop_domain` normalization that every other shop-comparison path in this concern uses.

### Finding Description
`session_shop_conflicts_with_params` performs a raw string inequality check: [1](#0-0) 

This is invoked from `login_again_if_different_user_or_shop`: [2](#0-1) 

Note the contrast with the sibling method `shop_session`, which correctly normalizes the shop param before use: [3](#0-2) 

and with `SanitizedParams#sanitize_shop_param`, which routes through `ShopifyApp::Utils.sanitize_shop_domain`: [4](#0-3) 

`sanitize_shop_domain` normalizes many different textual representations of the same shop domain into one canonical value — lower-casing, stripping scheme, adding `.myshopify.com` suffix, handling unified-admin URLs, etc.: [5](#0-4) [6](#0-5) 

Because `session_shop_conflicts_with_params` skips this normalization step and instead does a literal `!=` comparison between `current_shopify_session.shop` (always canonical, e.g. `"my-shop.myshopify.com"`) and `params[:shop]` (attacker/merchant-controlled, arbitrary casing/format, e.g. `"MY-SHOP.MYSHOPIFY.COM"`, `"https://my-shop.myshopify.com"`, or any other of the equivalent forms the test suite in `utils_test.rb` explicitly documents as accepted-but-different-looking), a request whose `shop` param is a differently-formatted but semantically identical (or intentionally crafted "close but not equal") value will:
- either be treated as a **false conflict** when it is actually the same shop (denial-of-service on legitimate flows), mirroring the OFT bug class exactly — a validity check that compares two representations of the same underlying value without normalizing them first, causing correct operations to be rejected; or
- be treated as **no conflict** even though the string differs from the canonical stored session shop in a way that should have triggered re-authentication, if an attacker can supply a `shop` value that Ruby's `!=` considers equal to the session's shop but that would sanitize to a *different* shop (this direction depends on exact casing normalization elsewhere but the check provides no defense-in-depth here since it never calls `sanitize_shop_domain`).

The concrete, provable defect is the first case: the comparison is done against raw, non-normalized user input while the rest of the codebase treats shop identity as only meaningful post-sanitization. This is the direct structural analog of the OFT issue: the check assumes both sides of an equality test are already expressed in the same canonical "representation" and fails silently/incorrectly when they aren't.

### Impact Explanation
This method is the sole mechanism (together with `session_id_conflicts_with_params`) that forces `clear_shopify_session` + redirect-to-login when the browser is showing a `shop` param inconsistent with the active session cookie — a defense against session/shop confusion. A broken equality check here reduces the reliability of that defense: legitimate shop switches may not trigger a required re-login when the params representation differs from the canonical form (silently keeping a stale/incorrect session active for the request), which is a session-integrity weakness rather than a full authentication bypass, since `current_shopify_session` itself is still derived from the encrypted cookie or a validated JWT, not from `params[:shop]`.

### Likelihood Explanation
Any HTTP request into an app-embedding page with a `shop` query parameter is unauthenticated/anonymous-reachable (Shopify Admin passes `shop`, but any caller can also set this parameter directly). No secrets or special access are needed to trigger the mismatched-comparison path — it's a plain GET/POST with a `shop` param formatted differently from the stored session's canonical shop value.

### Recommendation
Normalize both sides before comparing, mirroring the pattern already used by `shop_session`/`SanitizedParams`:
```ruby
def session_shop_conflicts_with_params
  return false unless current_shopify_session
  requested = sanitize_shop_param(params)
  requested.present? && current_shopify_session.shop != requested
end
```

### Proof of Concept
Not independently verifiable from static code review alone — a full PoC would require exercising `login_again_if_different_user_or_shop` in a live controller with an active cookie session while varying `params[:shop]` casing/format (e.g. `MY-SHOP.MYSHOPIFY.COM` vs. stored `my-shop.myshopify.com`) to confirm the conflict check's behavior diverges from the sanitized comparison used elsewhere; the test suite in `test/shopify_app/utils_test.rb` (lines 10-54) documents the range of equivalent representations `sanitize_shop_domain` normalizes, which is the input space this raw comparison fails to account for.       def sanitize_shop_domain(shop_domain)
        uri = uri_from_shop_domain(shop_domain)
        return if uri.nil? || uri.host.nil?

        trusted_domains.each do |trusted_domain|
          no_shop_name_in_subdomain = uri.host == trusted_domain
          from_trusted_domain = trusted_domain == uri.domain

          return myshopify_domain_from_unified_admin(uri) if unified_admin?(uri) && from_trusted_domain
          return nil if no_shop_name_in_subdomain || uri.host&.empty?
          return uri.host if from_trusted_domain
        end
        nil
      end

      def uri_from_shop_domain(shop_domain)
        name = shop_domain.to_s.downcase.strip
        name += ".#{myshopify_domain}" if !name.include?(myshopify_domain.to_s) && !name.include?(".")
        uri = Addressable::URI.parse(name)

        if uri.scheme.nil?
          name = "https://" + name
          uri = Addressable::URI.parse(name)
        end

        uri
      rescue Addressable::URI::InvalidURIError
        nil
      end
