### Title
`host_deposit_constant` passes `deposit_value_bytes` instead of `move_txid` as the 4th argument, causing permanent journal-hash mismatch that prevents operators from generating valid bridge circuit proofs — (`bridge-circuit-host/src/structs.rs`)

---

### Summary

The host-side `host_deposit_constant` function in `bridge-circuit-host/src/structs.rs` passes `deposit_value_bytes` (the deposit amount from the EIP-1186 storage proof) as the 4th argument to `deposit_constant()`, but the 4th parameter of that function is `move_txid`. The zkVM guest circuit passes the actual `move_txid` from `verify_storage_proofs`. This produces two permanently divergent `deposit_constant` values, causing the journal-hash mismatch check in `prove_bridge_circuit` to always fail. An operator challenged on any kickoff can never generate a valid bridge circuit proof and cannot defend their collateral.

---

### Finding Description

The `deposit_constant` function has the following signature:

```rust
pub fn deposit_constant(
    operator_xonlypk: [u8; 32],
    watchtower_challenge_connector_start_idx: u32,
    watchtower_pubkeys: &[[u8; 32]],
    move_txid: [u8; 32],        // ← 4th parameter
    round_txid: [u8; 32],
    kickoff_round_vout: u32,
    genesis_state_hash: [u8; 32],
) -> DepositConstant
```

**In the zkVM guest circuit** (`circuits-lib/src/bridge_circuit/mod.rs`, lines 221–229), the 4th argument is the actual `move_txid` obtained from `verify_storage_proofs`:

```rust
let deposit_constant = deposit_constant(
    operator_xonlypk,
    input.watchtower_challenge_connector_start_idx,
    &input.all_tweaked_watchtower_pubkeys,
    *move_txid,          // ← correct: actual move-to-vault txid
    round_txid,
    kickoff_round_vout,
    input.hcp.genesis_state_hash,
);
``` [1](#0-0) 

**In the host-side `host_deposit_constant`** (`bridge-circuit-host/src/structs.rs`, lines 505–515), the 4th argument is `deposit_value_bytes` — the deposit amount encoded as a 32-byte big-endian integer — not `move_txid`:

```rust
let deposit_value_bytes: [u8; 32] = deposit_storage_proof.value.to_be_bytes::<32>();

Ok(deposit_constant(
    operator_xonlypk,
    input.watchtower_challenge_connector_start_idx,
    &input.all_tweaked_watchtower_pubkeys,
    deposit_value_bytes,  // ← WRONG: deposit amount, not move_txid
    round_txid,
    kickoff_round_vout,
    input.hcp.genesis_state_hash,
))
``` [2](#0-1) 

The host then computes a `journal_hash` from this wrong `deposit_constant` and checks it against the journal committed by the circuit:

```rust
if *journal_hash.as_bytes() != succinct_receipt_journal {
    return Err(eyre!("Journal hash mismatch"));
}
``` [3](#0-2) 

Because `deposit_value_bytes` (a BTC amount, e.g. `0x000...3B9ACA00` for 1 BTC) is always different from `move_txid` (a Bitcoin transaction hash), the two `deposit_constant` values will never match, and `prove_bridge_circuit` always returns an error before producing any proof.

The `deposit_constant` is correctly computed with `move_txid` in every other call site — `creator.rs` and `verifier.rs` — confirming the host function is the sole outlier: [4](#0-3) [5](#0-4) 

---

### Impact Explanation

When a challenger spends the challenge connector on a kickoff transaction, the operator must call `send_asserts`, which internally calls `prove_bridge_circuit` to generate the Groth16 proof that defends their payout claim. [6](#0-5) 

Because `prove_bridge_circuit` always fails with "Journal hash mismatch", the operator can never post valid assert transactions. Any challenger can then spend the disprove connector after the assert timeout, burning the operator's collateral. The operator loses their full collateral (`collateral_funding_amount`, configured at 90–200 million satoshis in production configs) for every challenged kickoff. [7](#0-6) 

This is a permanent, unconditional failure: no valid bridge circuit proof can ever be generated by any operator on any network, for any withdrawal.

---

### Likelihood Explanation

The bug is triggered by any challenger spending a challenge connector on any kickoff transaction. Challengers are economically incentivized to do so (they receive the operator's collateral). The code path is reachable by any unprivileged on-chain actor. No special conditions are required beyond a normal withdrawal flow reaching the challenge phase.

---

### Recommendation

In `host_deposit_constant` (`bridge-circuit-host/src/structs.rs`), replace `deposit_value_bytes` with the actual `move_txid` as the 4th argument to `deposit_constant()`. The `move_txid` must be obtained from the storage proof output (as the circuit does via `verify_storage_proofs`), not from the deposit amount:

```rust
// Remove:
let deposit_value_bytes: [u8; 32] = deposit_storage_proof.value.to_be_bytes::<32>();

// Add: derive move_txid from the storage proof
let move_txid: [u8; 32] = /* extract from deposit_storage_proof or input.sp */;

Ok(deposit_constant(
    operator_xonlypk,
    input.watchtower_challenge_connector_start_idx,
    &input.all_tweaked_watchtower_pubkeys,
    move_txid,           // ← correct
    round_txid,
    kickoff_round_vout,
    input.hcp.genesis_state_hash,
))
```

The `move_txid` is available from `verify_storage_proofs` in the circuit; the host should extract it from the same storage proof data (`input.sp`) to maintain consistency.

---

### Proof of Concept

1. Operator performs a valid payout for a withdrawal and sends a kickoff transaction.
2. Any challenger spends the challenge connector.
3. Operator calls `send_asserts`, which calls `prove_bridge_circuit`.
4. Inside `prove_bridge_circuit`:
   - The zkVM circuit runs and commits `journal_hash(payout_tx_blockhash, latest_blockhash, challenge_sending_watchtowers, deposit_constant(move_txid=<actual_txid>, ...))`.
   - The host computes `journal_hash(payout_tx_blockhash, latest_blockhash, challenge_sending_watchtowers, deposit_constant(move_txid=<deposit_value_bytes>, ...))`.
   - `deposit_value_bytes` ≠ `actual_txid` → the two `deposit_constant` values differ → the two `journal_hash` values differ.
   - Check at line 239 fails: `"Journal hash mismatch"`.
5. `prove_bridge_circuit` returns `Err`, operator cannot post assert transactions.
6. After `assert_timeout_timelock` blocks, challenger spends the disprove connector and burns operator collateral. [8](#0-7) [9](#0-8)

pub fn deposit_constant(
    operator_xonlypk: [u8; 32],
    watchtower_challenge_connector_start_idx: u32,
    watchtower_pubkeys: &[[u8; 32]],
    move_txid: [u8; 32],
    round_txid: [u8; 32],
    kickoff_round_vout: u32,
    genesis_state_hash: [u8; 32],
) -> DepositConstant {
    // pubkeys are 32 bytes long
    let pubkey_concat = watchtower_pubkeys
        .iter()
        .flat_map(|pubkey| pubkey.to_vec())
        .collect::<Vec<u8>>();

    let watchtower_pubkeys_digest: [u8; 32] = Sha256::digest(&pubkey_concat).into();

    let pre_deposit_constant = [
        &move_txid,
        &watchtower_pubkeys_digest,
        &operator_xonlypk,
        &watchtower_challenge_connector_start_idx.to_be_bytes()[..],
        &round_txid,
        &kickoff_round_vout.to_be_bytes()[..],
        &genesis_state_hash,
    ]
    .concat();

    DepositConstant(Sha256::digest(&pre_deposit_constant).into())
}

pub fn prove_bridge_circuit(
    bridge_circuit_host_params: BridgeCircuitHostParams,
    bridge_circuit_elf: &[u8],
) -> Result<(
    ark_groth16::Proof<Bn254>,
    [u8; 31],
    BridgeCircuitBitvmInputs,
)> {
    tracing::info!("Starting bridge circuit proof generation");
    let bridge_circuit_input = bridge_circuit_host_params
        .clone()
        .into_bridge_circuit_input();

    let header_chain_proof_output_serialized = borsh::to_vec(&bridge_circuit_input.hcp)
        .wrap_err("Could not serialize header chain output")?;

    if bridge_circuit_input.lcp.lc_journal != bridge_circuit_host_params.lcp_receipt.journal.bytes {
        return Err(eyre!("Light client proof output mismatch"));
    }

    tracing::debug!(target: "ci", "Watchtower challenges: {:?}",
        bridge_circuit_input.watchtower_inputs);

    let lc_image_id = match bridge_circuit_host_params.network.0 {
        bitcoin::Network::Bitcoin => MAINNET_LC_IMAGE_ID,
        bitcoin::Network::Testnet4 => TESTNET4_LC_IMAGE_ID,
        bitcoin::Network::Signet => DEVNET_LC_IMAGE_ID,
        bitcoin::Network::Regtest => REGTEST_LC_IMAGE_ID,
        _ => return Err(eyre!("Unsupported network")),
    };

    let is_regtest = bridge_circuit_host_params.network.0 == bitcoin::Network::Regtest;

    // Verify light client proof
    if !is_regtest {
        bridge_circuit_host_params
            .lcp_receipt
            .verify(lc_image_id)
            .map_err(|_| eyre!("Light client proof verification failed"))?;
    }

    // Header chain verification
    if header_chain_proof_output_serialized
        != bridge_circuit_host_params.headerchain_receipt.journal.bytes
    {
        return Err(eyre!("Header chain proof output mismatch"));
    }

    let header_chain_method_id = match bridge_circuit_host_params.network.0 {
        bitcoin::Network::Bitcoin => MAINNET_HEADER_CHAIN_METHOD_ID,
        bitcoin::Network::Testnet4 => TESTNET4_HEADER_CHAIN_METHOD_ID,
        bitcoin::Network::Signet => SIGNET_HEADER_CHAIN_METHOD_ID,
        bitcoin::Network::Regtest => REGTEST_HEADER_CHAIN_METHOD_ID,
        _ => return Err(eyre!("Unsupported network")),
    };

    // Check for headerchain receipt
    if bridge_circuit_host_params
        .headerchain_receipt
        .verify(header_chain_method_id)
        .is_err()
    {
        return Err(eyre!("Header chain receipt verification failed"));
    }

    // SPV verification
    if !bridge_circuit_input.payout_spv.verify(
        bridge_circuit_input
            .hcp
            .chain_state
            .block_hashes_mmr
            .clone(),
    ) {
        return Err(eyre!("SPV verification failed"));
    }

    // Make sure the L1 block hash of the LightClientCircuitOutput matches the payout tx block hash
    let lc_output: LightClientCircuitOutput = borsh::from_slice(
        bridge_circuit_host_params
            .lcp_receipt
            .journal
            .bytes
            .as_slice(),
    )
    .wrap_err("Failed to deserialize light client circuit output")?;

    let lc_l1_block_hash = lc_output.latest_da_state.block_hash;

    let spv_l1_block_hash = bridge_circuit_input
        .payout_spv
        .block_header
        .compute_block_hash();

    if lc_l1_block_hash != spv_l1_block_hash {
        return Err(eyre!(
            "L1 block hash mismatch: expected {:?}, got {:?}",
            lc_l1_block_hash,
            spv_l1_block_hash
        ));
    }

    let public_inputs: SuccinctBridgeCircuitPublicInputs =
        SuccinctBridgeCircuitPublicInputs::new(bridge_circuit_input.clone())?;

    let journal_hash = public_inputs.host_journal_hash();

    let mut binding = ExecutorEnv::builder();
    let env = binding
        .write_slice(
            &borsh::to_vec(&bridge_circuit_input)
                .wrap_err("Failed to serialize bridge circuit input")?,
        )
        .add_assumption(bridge_circuit_host_params.headerchain_receipt)
        .add_assumption(bridge_circuit_host_params.lcp_receipt)
        .build()
        .map_err(|e| eyre!("Failed to build execution environment: {}", e))?;

    let prover = default_prover();

    tracing::info!("Checks complete, proving bridge circuit to generate STARK proof");

    let succinct_receipt = prover
        .prove_with_opts(env, bridge_circuit_elf, &ProverOpts::succinct())
        .map_err(|e| eyre!("Failed to generate bridge circuit proof: {}", e))?
        .receipt;

    tracing::info!("Bridge circuit proof (STARK) generated");

    let succinct_receipt_journal: [u8; 32] = succinct_receipt
        .clone()
        .journal
        .bytes
        .try_into()
        .map_err(|_| eyre!("Failed to convert journal bytes to array"))?;

    if *journal_hash.as_bytes() != succinct_receipt_journal {
        return Err(eyre!("Journal hash mismatch"));
    }
