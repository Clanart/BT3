### Title
Payout tx's operator-attribution OP_RETURN is unsigned, letting anyone reassign a withdrawal's fronting-operator credit after broadcast - (File: core/src/verifier.rs, core/src/builder/transaction/operator_reimburse.rs)

### Summary
`Verifier::update_finalized_payouts` trusts the OP_RETURN payload of whichever transaction ends up confirmed spending a withdrawal UTXO as proof of which operator fronted that withdrawal. Because the user's payout signature uses `SinglePlusAnyoneCanPay` (BIP-341 SIGHASH_SINGLE|ANYONECANPAY), it only commits to input 0 and output 0; the anchor output and the OP_RETURN carrying `operator_xonly_pk` are completely unsigned, so anyone who observes the broadcast tx can rebuild a variant with the same input0/output0 but a different (unrelated, non-consenting) operator's xonly pubkey in the OP_RETURN and get it mined instead, silently reassigning the reimbursement credit for that withdrawal to an operator who never funded it.

### Finding Description
The claimed binding is:
`operator_xonly_pk stored in withdrawals.payout_payer_operator_xonly_pk for idx i == xonly_pk of the operator whose funds actually paid output0 of the mined payout tx`.

The payout transaction is built in `create_payout_txhandler` [1](#0-0) , with output0 = user payout, output1 = anchor, output2 = OP_RETURN(operator_xonly_pk). The user's signature is checked against the `SinglePlusAnyoneCanPay` sighash for input0 only in `Operator::withdraw` [2](#0-1) . Per BIP-341, `SIGHASH_SINGLE|ANYONECANPAY` commits only to input0 and the output at the same index (output0); outputs 1 and 2, and any other inputs, are not covered by this signature at all.

Later, `Verifier::update_finalized_payouts` looks at whichever transaction actually spent the withdrawal UTXO on-chain, and blindly parses its first OP_RETURN as the "payer operator" for that withdrawal index, storing it via `update_payout_txs_and_payer_operator_xonly_pk`: [3](#0-2) 

No check exists anywhere that ties the OP_RETURN pubkey to any signature, funding input, or other cryptographic commitment — it is pure unauthenticated data in the mined transaction.

Exploit flow: after the honest operator broadcasts a valid payout tx (input0 = withdrawal UTXO with the user's `SinglePlusAnyoneCanPay` witness, output0 = the exact registered payout script/amount, output1 = anchor, output2 = OP_RETURN(honest operator's pubkey)) via `fund_raw_transaction`/RBF [4](#0-3) , the attacker copies the still-valid witness for input0 (the S+AP signature remains valid for any tx that keeps input0/output0 unchanged), builds a new transaction with their own funding input (which they sign themselves) and a new OP_RETURN containing a different, arbitrary, but public registered operator's xonly pubkey, and gets it mined first or via a higher-fee RBF replacement (the payout tx is queued as `FeePayingType::RBF` [5](#0-4) , and `fund_raw_transaction` is called with `replaceable: None`, which defaults to Bitcoin Core's RBF-enabled wallet setting).

Once mined, `get_payout_txs_for_withdrawal_utxos` finds this attacker tx as the spender of the withdrawal UTXO, and `update_finalized_payouts` credits the substituted, unrelated operator's pubkey as the payer for that Citrea withdrawal index.

### Impact Explanation
- The honest operator who actually fronted the withdrawal amount can never be credited: their own `PayoutCheckerTask::run_once`, via `get_first_unhandled_payout_by_operator_xonly_pk`, will never find idx i under their own key [6](#0-5) , and any kickoff they later send for that deposit will be marked malicious by `is_kickoff_malicious` because the DB-stored `operator_xonly_pk` no longer matches their kickoff's `operator_xonly_pk` [7](#0-6) , exposing their kickoff to Challenge/Disprove and burning their collateral.
- Simultaneously, the unrelated ("framed") operator — whose xonly pubkey is public knowledge (published/fetchable operator keys) — is automatically credited by every verifier's DB as the payer of that withdrawal. If that operator runs standard automation, `PayoutCheckerTask` will pick up this "unhandled payout" as its own and proceed through `handle_finalized_payout`/kickoff/reimburse, receiving bridge collateral reimbursement for a withdrawal it never funded — matching the Critical category "an operator reimbursed for a payout it never funded" and "an honest operator permanently unable to be reimbursed."
- Repeatable per withdrawal/operator; the attacker only needs fee funds and knowledge of any registered operator's public xonly key, both trivially available to an unprivileged attacker.

### Likelihood Explanation
No special privilege is required: the attacker only needs to observe a broadcast (unconfirmed) payout transaction (mempool-visible, or even race the honest operator's own broadcast), own some BTC to fund a competing/replacement transaction, and know a registered operator's public xonly key (obtainable via `fetch_operator_keys`/aggregator or CLI). The only environmental precondition is a mempool/RBF policy allowing replacement or a first-seen race window on the withdrawal UTXO before it confirms — both realistic on mainnet/testnet Bitcoin, especially since the payout tx is deliberately sent via the RBF fee-paying type by Clementine's own tx sender.

### Recommendation
Do not use an unsigned OP_RETURN as the sole source of truth for "who funded this payout." Instead, cryptographically bind the payer-operator commitment to the signed portion of the transaction — e.g., commit the operator xonly pubkey (or a hash including it) into output0's script/amount or otherwise force it under the `SIGHASH_SINGLE` output/input coverage, or require an operator-signed input (whose signature covers the OP_RETURN output) rather than trusting arbitrary unsigned OP_RETURN bytes in `update_finalized_payouts`.

### Proof of Concept

6. Assert `PayoutCheckerTask::run_once` for operator A never processes idx i (returns false / no unhandled payout found for A).

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
