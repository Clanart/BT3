## Title
ERC721 pointer NFTs can be permanently bricked by transferring the underlying CW721 token to an unassociated Sei address - ([File: contracts/src/CW721ERC721Pointer.sol])

### Summary
`CW721ERC721Pointer` (the ERC721 wrapper Sei creates for a native CW721 collection) derives `ownerOf()` by querying the CW721 contract for the current Cosmos owner and then converting that Sei address to an EVM address via the `Addr` precompile's `getEvmAddr`. That precompile call **hard-reverts** if the owner's Sei address has never been associated with an EVM address. Because any holder of the underlying CW721 token can transfer it natively (bypassing the EVM pointer entirely) to an arbitrary Sei address that will never self-associate, the pointer's `ownerOf`/`balanceOf`/`tokenURI`/`transferFrom` become permanently unusable for that token, freezing any EVM-side logic (e.g. lending/marketplace collateral) built on top of the pointer.

### Finding Description
`ownerOf()` resolves the CW721 owner and unconditionally calls `AddrPrecompile.getEvmAddr(owner_)`: [1](#0-0) 

`getEvmAddr` in the `addr` precompile returns a hard error (no fallback/default mapping) when the Sei address has no EVM association: [2](#0-1) 

`transferFrom()` itself calls `ownerOf(tokenId)` to validate `from`, so it inherits the same revert: [3](#0-2) 

The underlying CW721 contract's `transfer_nft`/`send_nft` execute messages accept any bech32 Sei address as recipient with no requirement that it be EVM-associated, and can be invoked directly against the native CW721 contract (not through the pointer), so the pointer has no ability to prevent or react to this. The `GetEVMAddress` lookup used by `getEvmAddr` has no default-mapping fallback (unlike `GetEVMAddressOrDefault`, which the pointer does not use): [4](#0-3) 

Sei's own integration test suite explicitly documents that pointer ERC721 operations fail for unassociated addresses ("Currently does not allow listing or buying erc721 pointer by unassociated users"), confirming this is reachable, observed behavior rather than a theoretical corner case: [5](#0-4) 

### Impact Explanation
Any smart contract that integrates with a CW721 collection through its auto-generated ERC721 pointer (e.g., an EVM lending protocol accepting the pointer NFT as collateral, or a marketplace) can have that NFT's `ownerOf`/`transferFrom` permanently revert once the token's Cosmos-side owner is an address with no EVM association. Since transferring the underlying CW721 token natively to such an address is a single unprivileged wasm execute message (`transfer_nft`/`send_nft`) fully within the current owner's control, a malicious borrower/seller can deliberately send the token to a "dead" Sei address (one nobody holds keys for, or a module/contract address that structurally can never call `associate`) to permanently break any EVM logic depending on `ownerOf`/`transferFrom` for that token — freezing collateral or listed assets, mirroring the underlying report's "collateral locked by sending to unreceivable address" bug class.

### Likelihood Explanation
Reaching this requires only a standard CW721 `transfer_nft`/`send_nft` message from the current token owner — no special privileges, no third-party cooperation, and no reliance on a p2p/validator/governance actor. Any EVM contract that trusts the pointer's `ownerOf`/`transferFrom` as ground truth (rather than querying the CW721 contract directly) is exposed.

### Recommendation
Have `CW721ERC721Pointer.ownerOf()` (and `balanceOf`/`getApproved`/`isApprovedForAll`) fall back to a deterministic cast address (analogous to `GetEVMAddressOrDefault`/`GetSeiAddressOrDefault`) instead of reverting when the Cosmos owner has no EVM association, so pointer state stays queryable and transferable even for non-associated owners, and dependent EVM contracts cannot be permanently bricked by an ordinary CW721 transfer.

### Proof of Concept
1. Register an ERC721 pointer for a CW721 collection via the pointer precompile (`AddCW721`). [6](#0-5) 
2. An EVM contract (e.g., a lending protocol) accepts token `id` via `pointer.transferFrom(borrower, lendingContract, id)`, relying on `ownerOf`/`transferFrom` for later liquidation/repayment logic.
3. Have the borrower (who still ultimately controls the CW721 asset through Cosmos-side authorization, or a colluding party who becomes the CW721 owner through the normal flow) issue a native `transfer_nft`/`send_nft` execute message directly against the CW721 contract, moving the token to a Sei address that has never sent an EVM transaction or called `associate` (e.g., a randomly generated bech32 address whose key is discarded).
4. Any subsequent call to `pointer.ownerOf(id)` or `pointer.transferFrom(...)` reverts with `"sei address ... is not associated"` from the `Addr` precompile, permanently, since nothing forces that Sei address to ever associate. [7](#0-6) 
5. The lending/marketplace contract can no longer verify ownership or transfer the collateral NFT through the pointer, freezing it.

func (p PrecompileExecutor) getEvmAddr(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}

	seiAddr, err := sdk.AccAddressFromBech32(args[0].(string))
	if err != nil {
		return nil, 0, err
	}

	evmAddr, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if !found {
		metrics.IncrementAssociationError("getEvmAddr", types.NewAssociationMissingErr(args[0].(string)))
		return nil, 0, fmt.Errorf("sei address %s is not associated", args[0].(string))
	}
	ret, err = method.Outputs.Pack(evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

func (k *Keeper) GetEVMAddress(ctx sdk.Context, seiAddress sdk.AccAddress) (common.Address, bool) {
	store := ctx.KVStore(k.storeKey)
	bz := store.Get(types.SeiAddressToEVMAddressKey(seiAddress))
	addr := common.Address{}
	if bz == nil {
		return addr, false
	}
	copy(addr[:], bz)
	return addr, true
}

func (k *Keeper) GetEVMAddressOrDefault(ctx sdk.Context, seiAddress sdk.AccAddress) common.Address {
	addr, ok := k.GetEVMAddress(ctx, seiAddress)
	if ok {
		return addr
	}
	return common.BytesToAddress(seiAddress)
}
