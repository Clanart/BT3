### Title
Permanent freezing of unbonding stake for cast/unassociated EVM delegator addresses whose cast address later becomes CanSendTo-blocked - (File: sei-cosmos/x/staking/keeper/delegation.go)

### Summary
When an EVM user delegates/undelegates through Sei's implicit "cast address" (the raw byte-derived Sei address for an unassociated EVM address), and that EVM address is later associated to a real Sei bech32 address, the cast address becomes permanently blocked from receiving funds via `BaseKeeper.CanSendTo`. If an `UnbondingDelegation` for that cast address matures after the association happens, `CompleteUnbonding` fails to pay out the funds, and the maturity entry is dequeued without being retried, permanently freezing the delegator's principal in the `NotBondedPool`.

### Finding Description
Sei allows EVM addresses that have not yet been explicitly associated with a Sei account to transact using an implicit "cast address" — the raw 20 bytes of the EVM address treated directly as an `sdk.AccAddress`. Staking operations (e.g. via the staking precompile) performed from such an address record the delegator/unbonding-delegation using that cast address.

The bank keeper exposes `CanSendTo`, which is consulted before completing an undelegation: [1](#0-0) 

Once the same EVM address is later associated with a real Sei address via `EvmKeeper.SetAddressMapping`, the raw cast address stops being a valid receive target — `CanSendTo` starts returning `false` for it, exactly as demonstrated for the distribution module's withdraw-address flow: [2](#0-1) 

The staking module hits the identical trap for in-flight unbonding delegations. `CompleteUnbonding` transfers matured entries from the not-bonded pool to the delegator via `UndelegateCoinsFromModuleToAccount` → `UndelegateCoins`, which performs the same `CanSendTo` gate: [3](#0-2) 

The regression test `TestEndBlockRetainsUnbondingForInvalidRecipient` reproduces this exact scenario: an unbonding delegation is queued for a cast address, the EVM address behind it is then associated (making `CanSendTo` false for the cast address), and `EndBlocker` runs without panicking — but the coins are never delivered (pool balance unchanged, delegator balance stays zero) and, critically, the maturity entry is removed from the `UBDQueue` (the iterator for that maturity time is no longer valid) even though the `UnbondingDelegation` object is retained unprocessed: [4](#0-3) 

Because the queue entry that would trigger a retry is gone, and Sei address associations are one-way/permanent (an EVM address cannot be "un-associated" back to a state where its cast address is payable again), the delegator's staked principal held in the `NotBondedPool` becomes unrecoverable by any subsequent transaction — the delegator has no path to reclaim it, matching the reported bug class: a state change (asset delisting there; address association here) blocks a withdrawal/completion path that should still be honored for funds committed before that state change.

### Impact Explanation
This results in permanent freezing of user funds: principal that was validly delegated/undelegated by a not-yet-associated EVM user becomes permanently stuck in the staking `NotBondedPool`, with no message or code path able to retrigger delivery once the maturity entry is dropped from the `UBDQueue`. This is a direct "permanent freezing" impact as accepted by the scan's validation criteria.

### Likelihood Explanation
Reachable by an ordinary, unprivileged flow: (1) an EVM user who has not associated their address delegates and later calls `undelegate` on the staking precompile from that unassociated address (using the implicit cast address as delegator), and (2) at any point before maturity, the same EVM address becomes associated with a Sei address — an action that can be triggered by the user themselves (e.g., sending any Sei-native tx, or another party invoking the association precompile/mechanism for that EVM address, depending on how association is triggered in this codebase). This does not require governance, validator collusion, or any privileged actor — only two ordinary transactions in sequence — making it independently and cheaply triggerable, including potentially by a user against their own funds or inadvertently through normal usage patterns (associating after having staked from an EVM wallet).

### Recommendation
When a matured `UnbondingDelegation` (or `Redelegation`) entry fails to pay out because `CanSendTo`/`BlockedAddr` rejects the recipient, the entry should not be silently dequeued and abandoned. Instead:
- Re-insert the entry into the `UBDQueue` for retry (e.g., at the next block or after a bounded delay), so that once/if the recipient becomes payable again the funds are delivered automatically, or
- Fall back to sending the matured funds to the properly associated Sei address for that EVM address (mirroring the reasoning already applied to `AfterValidatorRemoved`'s withdraw-address fallback), or
- Reject/disallow undelegations from cast (unassociated) addresses in the first place, forcing association prior to permitting staking actions from EVM-only senders, avoiding the case entirely.

### Proof of Concept
The existing test in the repository already demonstrates the freeze condition end-to-end: [4](#0-3) 
1. An `UnbondingDelegation` is created for `delegator = sdk.AccAddress(evmAddr[:])` (the cast address of an EVM address) with `SetUnbondingDelegationEntry`/`InsertUBDQueue`.
2. `EvmKeeper.SetAddressMapping` associates `evmAddr` with a (different) real Sei address, causing `app.BankKeeper.CanSendTo(ctx, delegator)` to become `false`.
3. `staking.EndBlocker` runs at maturity without panicking, but: the `NotBondedPool` balance is unchanged, the delegator's bank balance stays zero, the `UnbondingDelegation` is retained unprocessed in the store, and the `UBDQueue` iterator for that maturity time is no longer valid (entry consumed/dropped) — meaning the funds will never be retried or delivered through any subsequent block processing.

func (k BaseKeeper) UndelegateCoins(ctx sdk.Context, moduleAccAddr, delegatorAddr sdk.AccAddress, amt sdk.Coins) error {
	moduleAcc := k.ak.GetAccount(ctx, moduleAccAddr)
	if moduleAcc == nil {
		return sdkerrors.Wrapf(sdkerrors.ErrUnknownAddress, "module account %s does not exist", moduleAccAddr)
	}

	if !amt.IsValid() {
		return sdkerrors.Wrap(sdkerrors.ErrInvalidCoins, amt.String())
	}
	if !k.CanSendTo(ctx, delegatorAddr) {
		return sdkerrors.ErrInvalidRecipient
	}

	err := k.SubUnlockedCoins(ctx, moduleAccAddr, amt, true)
	if err != nil {
		return err
	}

	if err := k.trackUndelegation(ctx, delegatorAddr, amt); err != nil {
		return sdkerrors.Wrap(err, "failed to track undelegation")
	}

	err = k.AddCoins(ctx, delegatorAddr, amt, true)
	if err != nil {
		return err
	}

	return nil
}

// CompleteUnbonding completes the unbonding of all mature entries in the
// retrieved unbonding delegation object and returns the total unbonding balance
// or an error upon failure.
func (k Keeper) CompleteUnbonding(ctx sdk.Context, delAddr sdk.AccAddress, valAddr sdk.ValAddress) (sdk.Coins, error) {
	ubd, found := k.GetUnbondingDelegation(ctx, delAddr, valAddr)
	if !found {
		return nil, types.ErrNoUnbondingDelegation
	}

	bondDenom := k.GetParams(ctx).BondDenom
	balances := sdk.NewCoins()
	ctxTime := ctx.BlockHeader().Time

	delegatorAddress, err := sdk.AccAddressFromBech32(ubd.DelegatorAddress)
	if err != nil {
		return nil, err
	}

	// loop through all the entries and complete unbonding mature entries
	for i := 0; i < len(ubd.Entries); i++ {
		entry := ubd.Entries[i]
		if entry.IsMature(ctxTime) {
			ubd.RemoveEntry(int64(i))
			i--

			// track undelegation only when remaining or truncated shares are non-zero
			if !entry.Balance.IsZero() {
				amt := sdk.NewCoin(bondDenom, entry.Balance)
				if err := k.bankKeeper.UndelegateCoinsFromModuleToAccount(
					ctx, types.NotBondedPoolName, delegatorAddress, sdk.NewCoins(amt),
				); err != nil {
					return nil, err
				}

				balances = balances.Add(amt)
			}
		}
	}

	// set the unbonding delegation or remove it if there are no more entries
	if len(ubd.Entries) == 0 {
		k.RemoveUnbondingDelegation(ctx, ubd)
	} else {
		k.SetUnbondingDelegation(ctx, ubd)
	}

	return balances, nil
}

func TestEndBlockRetainsUnbondingForInvalidRecipient(t *testing.T) {
	_, app, ctx := createTestInput(t)
	maturity := time.Unix(1, 0).UTC()
	ctx = ctx.WithBlockTime(maturity)
	evmAddr := common.HexToAddress("0x3333333333333333333333333333333333333333")
	delegator := sdk.AccAddress(evmAddr[:])
	app.EvmKeeper.SetAddressMapping(ctx, delegator, evmAddr)
	app.EvmKeeper.SetAddressMapping(
		ctx,
		sdk.AccAddress(common.HexToAddress("0x4444444444444444444444444444444444444444").Bytes()),
		evmAddr,
	)
	validator := sdk.ValAddress(seiapp.AddTestAddrsIncremental(app, ctx, 1, sdk.NewInt(10000))[0])
	amount := sdk.NewInt(40)
	bondDenom := app.StakingKeeper.BondDenom(ctx)
	notBondedPool := app.StakingKeeper.GetNotBondedPool(ctx)
	coins := sdk.NewCoins(sdk.NewCoin(bondDenom, amount))

	require.NoError(t, apptesting.FundModuleAccount(
		app.BankKeeper,
		ctx,
		notBondedPool.GetName(),
		coins,
	))

	unbonding := types.NewUnbondingDelegation(delegator, validator, 0, maturity, amount)
	app.StakingKeeper.SetUnbondingDelegation(ctx, unbonding)
	app.StakingKeeper.InsertUBDQueue(ctx, unbonding, maturity)
	require.False(t, app.BankKeeper.CanSendTo(ctx, delegator))

	poolBalanceBefore := app.BankKeeper.GetBalance(ctx, notBondedPool.GetAddress(), bondDenom)
	require.NotPanics(t, func() {
		staking.EndBlocker(ctx, app.StakingKeeper)
	})

	poolBalanceAfter := app.BankKeeper.GetBalance(ctx, notBondedPool.GetAddress(), bondDenom)
	require.Equal(t, poolBalanceBefore, poolBalanceAfter)
	require.True(t, app.BankKeeper.GetBalance(ctx, delegator, bondDenom).IsZero())
	retained, found := app.StakingKeeper.GetUnbondingDelegation(ctx, delegator, validator)
	require.True(t, found)
	require.Equal(t, unbonding, retained)

	iterator := app.StakingKeeper.UBDQueueIterator(ctx, maturity)
	require.False(t, iterator.Valid())
	require.NoError(t, iterator.Close())
}
