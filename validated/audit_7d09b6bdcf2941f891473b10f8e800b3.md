### Title
Out-of-bounds read / unhandled `IndexError` in CLVM canonical-encoding check crashes spend-bundle validation - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_clvm_canonical()` and its helper `is_atom_canonical()` in `chia/full_node/mempool_manager.py` parse the raw CLVM byte-serialization of a coin spend's `puzzle_reveal` and `solution` without validating that the declared atom length-prefix stays within the buffer bounds. A crafted, truncated CLVM buffer causes these functions to index past the end of the `bytes` object, raising an unhandled `IndexError` instead of returning a controlled validation error. This is directly analogous to CVE-2019-11372, where `MediaInfoLib::File__Tags_Helper::Synched_Test` read past a buffer boundary while scanning a length-prefixed tag structure, leading to a crash.

### Finding Description
`validate_spend_bundle()` calls `is_clvm_canonical()` on every `coin_spend.puzzle_reveal` and `coin_spend.solution` in an incoming spend bundle before it is admitted to the mempool: [1](#0-0) 

`is_clvm_canonical()` walks the buffer byte-by-byte, reading `clvm_buffer[offset]` on every iteration without ever checking `offset < len(clvm_buffer)`: [2](#0-1) 

For multi-byte atom length prefixes, `is_atom_canonical()` advances `offset` and reads `clvm_buffer[offset]` for each length-prefix byte, again with no bounds check against the buffer length: [3](#0-2) 

Both functions assume the buffer is well-formed enough to contain a full pair/atom token stream. Because `coin_spend.puzzle_reveal` and `coin_spend.solution` are attacker-supplied bytes coming directly from a submitted `SpendBundle`, an attacker can construct a buffer that:
- ends immediately after a lone `0xFF` pair marker (empty pair, no children bytes), or
- ends immediately after a multi-byte atom length-prefix byte (e.g. `0xC0`) without supplying the remaining length-prefix or payload bytes.

In either case, the next `clvm_buffer[offset]` access indexes past the end of the `bytes` object and Python raises `IndexError`, which is not caught anywhere in this call path (`validate_spend_bundle()` → `is_clvm_canonical()` → `is_atom_canonical()`). This mirrors the CVE's out-of-bounds-read-triggers-crash bug class, except here the crash surfaces as an unhandled Python exception during mempool admission of an unprivileged, single submitted spend bundle.

### Impact Explanation
If the exception is not caught by an outer handler around spend-bundle validation, it terminates/crashes the transaction-processing task on any full node (or `SpendSim`) that receives the malformed spend bundle, i.e. a spend-triggered halt of the node's transaction processing path reachable by any unprivileged spend-bundle submitter — no signature, funds, or special privilege required beyond submitting a transaction. This matches the "spend-triggered transaction-processing halt" acceptance criterion.

### Likelihood Explanation
The check runs unconditionally on every coin spend in `validate_spend_bundle()`, so any RPC client or peer capable of submitting a `SpendBundle` (e.g., via `push_tx`) can reach this code with attacker-controlled `puzzle_reveal`/`solution` bytes. Constructing the two truncated byte patterns described above is trivial and requires no cryptographic material.

### Recommendation
Add explicit bounds checks in `is_clvm_canonical()` and `is_atom_canonical()` before every buffer index access (e.g., verify `offset < len(clvm_buffer)` before reading, and verify enough bytes remain for the declared length-prefix before advancing), returning `False`/raising a handled `ValidationError`/`Err.INVALID_COIN_SOLUTION` rather than allowing a raw `IndexError` to propagate.

### Proof of Concept
```python
from chia.full_node.mempool_manager import is_clvm_canonical

# Lone pair marker with no children bytes -> IndexError instead of False
is_clvm_canonical(b"\xff")

# Multi-byte atom length prefix truncated immediately after the prefix byte
is_clvm_canonical(b"\xc0")
```
Both calls raise `IndexError: index out of range` instead of returning `False`. Submitting a coin spend whose `puzzle_reveal` or `solution` serializes to one of these truncated forms via `push_tx`/`SpendBundle` reaches `validate_spend_bundle()`'s `is_clvm_canonical(...)` call [1](#0-0)  and triggers the same unhandled exception during mempool admission.

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```
