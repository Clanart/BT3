### Title
Untrusted `ReceivedOutput` deserialization bypasses scanner provenance and enables signing transactions for nonexistent UTXOs - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
`ReceivedOutput::read` accepts an offset, `TxOut`, and `OutPoint` as independent, unauthenticated fields, while `Scanner::scan_transaction` is the only in-scope path that establishes that an on-chain transaction actually created an output matching a watched script. [1](#0-0) [2](#0-1)  `SignableTransaction::multisig` later validates only that `keys.offset(offset).group_key()` maps to the supplied `TxOut.script_pubkey`; it does not prove that `outpoint` exists, references that `TxOut`, or is mature/spendable. [3](#0-2) 

### Finding Description
A legitimate `ReceivedOutput` produced by `Scanner` carries provenance: the scanner selected a registered script, observed a matching transaction output, and constructed the corresponding `OutPoint`. [4](#0-3) [5](#0-4)  Deserialization bypasses that read-only discovery gate and converts arbitrary attacker bytes into the same privileged “received and spendable” representation. [1](#0-0) 

The transaction builder trusts the deserialized `output.value`, `output.script_pubkey`, `offset`, and `outpoint` when computing funds and constructing inputs. [6](#0-5)  During signing setup, the only ownership check compares the declared previous output’s `script_pubkey` against the tweaked threshold key, so a forged output using the group’s own P2TR script and a fabricated `OutPoint` passes. [7](#0-6)  The resulting signature hash commits to the fabricated prevout set through `Prevouts::All`. [8](#0-7) 

### Impact Explanation
An unprivileged party who knows a wallet’s public group key and a valid offset, including the always-registered zero offset, can submit serialized `ReceivedOutput` bytes claiming that a nonexistent or unrelated UTXO belongs to the threshold wallet. [9](#0-8) [1](#0-0)  If an integration forwards such outputs to signing participants, the participants produce FROST shares for a transaction spending an output that cannot actually be spent. [10](#0-9) 

This causes funds to be reported as received when they are not spendable and can consume one-time signing rounds/nonces on a transaction that Bitcoin consensus will reject. [11](#0-10) [12](#0-11)  The issue does not directly reveal a private share, but it bypasses the scanner’s authorization/provenance boundary and can corrupt wallet accounting or stall signing operations. [13](#0-12) 

### Likelihood Explanation
The attack is reachable wherever serialized `ReceivedOutput` values are accepted from a coordinator, remote wallet service, synchronized database, or other untrusted source rather than only from a locally trusted `Scanner`. [14](#0-13)  Constructing the bytes requires no secret material because the group P2TR script is public and the zero-offset script is automatically registered by `Scanner::new`. [15](#0-14) [9](#0-8) 

The likelihood is deployment-dependent: callers that only deserialize outputs previously written by their own trusted scanner are not exposed to forged provenance, but callers treating `ReceivedOutput::read` as validation are vulnerable. [16](#0-15) 

### Recommendation
- Split untrusted serialized claims from authenticated scanner results, or authenticate `ReceivedOutput` storage with a MAC/signature bound to the wallet, script, `TxOut`, and `OutPoint`.
- Before creating `SignableTransaction`, resolve every `OutPoint` against a trusted Bitcoin node and require the chain’s UTXO to equal the supplied `TxOut`.
- Reject immature coinbase outputs, nonstandard/unconfirmed spends, and any output whose script was not derived through the expected scanner registration.
- Rename or restrict `ReceivedOutput::read` so it cannot be mistaken for validation of received funds.

### Proof of Concept
The following concept assumes the signer’s `ThresholdKeys<Secp256k1>` are available to the wallet integration, while the serialized `ReceivedOutput` comes from an attacker.

```rust
use bitcoin::{
  consensus::encode::serialize,
  hashes::Hash,
  Amount, OutPoint, ScriptBuf, Transaction, TxOut, Txid,
};
use k256::Scalar;
use serai_bitcoin::wallet::{p2tr_script_buf, ReceivedOutput, SignableTransaction};

// Known public threshold wallet key.
let group_key = keys.group_key();

// Script corresponding to the wallet's zero-offset P2TR output.
let wallet_script: ScriptBuf = p2tr_script_buf(group_key).unwrap();

// Claim a large UTXO exists even though this OutPoint is fabricated.
let fake_output = TxOut {
  value: Amount::from_sat(1_000_000),
  script_pubkey: wallet_script,
};
let fake_outpoint = OutPoint::new(Txid::all_zeros(), 0);

// Manually encode the format accepted by ReceivedOutput::read:
// Scalar || consensus TxOut || consensus OutPoint.
let mut bytes = Vec::new();
bytes.extend(Scalar::ZERO.to_bytes());
bytes.extend(serialize(&fake_output));
bytes.extend(serialize(&fake_outpoint));

let forged = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();

// The attacker supplies a valid payment destination and fee parameters.
let tx = SignableTransaction::new(
  vec![forged],
  &[(attacker_script, 546)],
  None,
  None,
  1,
).unwrap();

// This succeeds because only script_pubkey is compared with keys + offset.
let machine = tx.multisig(&keys).unwrap();
```

The resulting signing session commits each participant to a Taproot sighash over the fabricated `OutPoint` and `TxOut`, producing shares for a spend that the Bitcoin network cannot accept. [8](#0-7)

  /// Read a ReceivedOutput from a generic satisfying Read.
  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  /// Write a ReceivedOutput to a generic satisfying Write.
  pub fn write<W: Write>(&self, w: &mut W) -> io::Result<()> {
    w.write_all(&self.offset.to_bytes())?;
    w.write_all(&serialize(&self.output))?;
    w.write_all(&serialize(&self.outpoint))
  }

  /// Serialize a ReceivedOutput to a `Vec<u8>`.
  pub fn serialize(&self) -> Vec<u8> {
    let mut res = Vec::new();
    self.write(&mut res).unwrap();
    res
  }
