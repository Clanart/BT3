### Title
Unsigned Operator Attribution in `Payout` Transaction Allows Reimbursement Credit For A Withdrawal Never Funded By That Operator - (File: `core/src/builder/transaction/operator_reimburse.rs`)

### Summary
`create_payout_txhandler` builds the `Payout` transaction with an `OP_RETURN` output that records the `operator_xonly_pk` credited as having "fronted" the withdrawal, but that output is never covered by the only real signature on the transaction. The only witness on the transaction is the user's own key-spend signature over the withdrawal UTXO input, and per the code's own comment it is expected to use `SIGHASH_SINGLE|ANYONECANPAY`. That sighash type commits only to input 0 and its correspondingly-indexed output (the user's payout output), leaving the anchor output and the `OP_RETURN` output completely unauthenticated and freely rewritable by anyone in possession of the user's presigned signature.

### Finding Description
`create_payout_txhandler` builds: [1](#0-0) 

The transaction has a single signed input (`SpendPath::KeySpend`) using the user's `taproot::Signature`, and the sighash actually verified is computed using the sighash type embedded in that user signature: [2](#0-1) 

The doc comment explicitly states the expected type is `SinglePlusAnyoneCanPay`, i.e. `SIGHASH_SINGLE|ANYONECANPAY` — which authenticates only txin #0 and its matching output index (the user payout output), not the `OP_RETURN` output that carries `operator_xonly_pk` nor the anchor output. Anyone who has (or can observe, e.g. from a broadcast/mempool transaction) this user signature can therefore reconstruct an equally-valid `Payout` transaction spending the same withdrawal UTXO, keep the user's output untouched (so the signature still verifies) and freely substitute an arbitrary `operator_xonly_pk` value into the `OP_RETURN`.

Downstream, this `OP_RETURN` value is trusted as ground truth for attributing which operator fronted the payout: [3](#0-2) [4](#0-3) 

That stored `payout_payer_operator_xonly_pk` is then used unconditionally to select which operator's automated `PayoutCheckerTask` claims reimbursement: [5](#0-4) [6](#0-5) [7](#0-6) 

There is no check anywhere in this chain that the credited `operator_xonly_pk` actually authorized, signed, or funded the confirmed `Payout` transaction — the value is taken purely from unauthenticated OP_RETURN bytes.

### Impact Explanation
Binding broken: "the operator credited" (`payout_payer_operator_xonly_pk` in the `withdrawals` table) must equal "the party that paid" (the entity whose funds/signature actually fronted the withdrawal). Before the attack, only the operator that genuinely funds/broadcasts a `Payout` transaction should end up matching its own `xonly_pk` in the `OP_RETURN`. After the attack, an unprivileged actor holding the user's presigned withdrawal signature can forge the `OP_RETURN` to name any operator xonly_pk (including one that never signed, funded, or even saw the transaction). The named operator's own automated `PayoutCheckerTask`/`handle_finalized_payout` flow will then pick up this payout and proceed to build/send the reimbursement (`Reimburse`) transaction path for a withdrawal it never fronted, since the on-chain proof of "payer" checked later is exactly this OP_RETURN pubkey. This is a direct instance of "an operator reimbursed for a payout it never funded" — Critical impact — and can equally be used to grief an honest operator (framing it as the payer for a withdrawal so its automation consumes a kickoff/round slot and collateral for a payout it never made).

### Likelihood Explanation
The only requirement is possession of the user's presigned `SIGHASH_SINGLE|ANYONECANPAY` withdrawal signature, which by design is distributed off-chain to multiple parties for the "race to front" mechanism, and additionally becomes publicly visible the moment any `Payout` transaction spending that UTXO reaches the mempool (the witness is public). No verifier, aggregator, watchtower or privileged role is required to exploit it — any party who observes the broadcast signature can construct a competing/rewritten transaction with a forged `OP_RETURN` before the honest transaction confirms.

### Recommendation
Bind the credited `operator_xonly_pk` cryptographically to the actual funding of the transaction, e.g., require the operator to co-sign (or include an additional signed input) that commits to the entire transaction including the `OP_RETURN` output (`SIGHASH_ALL`/`SIGHASH_DEFAULT` for at least one input controlled by the credited operator), or move the payer attribution into a script path that requires the named operator's signature rather than relying on unauthenticated `OP_RETURN` data.

### Proof of Concept
1. A withdrawal UTXO and its `SIGHASH_SINGLE|ANYONECANPAY` user signature exist (shared off-chain to enable operator competition), matching `output_txout` (the user's payout) at index 0 — see `create_payout_txhandler` at `core/src/builder/transaction/operator_reimburse.rs:407-436`.
2. Any party (not necessarily the actual funding operator) observes this signature once broadcast to the mempool or otherwise obtained.
3. That party constructs a new `Payout` transaction with the identical input/witness and identical output 0 (so the SINGLE|ANYONECANPAY signature still verifies), but with an `OP_RETURN` output at index 2 containing an arbitrary victim `operator_xonly_pk`, and gets it confirmed first.
4. `update_finalized_payouts` (`core/src/verifier.rs:2283-2353`) parses the OP_RETURN and stores the victim's pubkey as `payout_payer_operator_xonly_pk` via `update_payout_txs_and_payer_operator_xonly_pk` (`core/src/database/verifier.rs:198-251`).
5. The victim operator's own `PayoutCheckerTask` (`core/src/task/payout_checker.rs:41-79`) picks this payout up via `get_first_unhandled_payout_by_operator_xonly_pk` (`core/src/database/verifier.rs:282-313`) and proceeds through `handle_finalized_payout`/reimbursement automation for a withdrawal it never funded.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self

            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(

                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

        tracing::info!(
            "Payer xonly pk, payout blockhash and kickoff txid found and valid for own operator for the requested deposit id: {}, payer xonly pk: {:?}, payout blockhash: {:?}, kickoff txid: {:?}",
            deposit_id,
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid
        );

        Ok((payout_blockhash, kickoff_txid))
    }

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }
