### Title
Data Layer Mirror URLs Are Never Validated, Allowing Any Store Owner to Trigger SSRF Against Subscriber Nodes - ([File: chia/data_layer/download_data.py])

### Summary
`DataLayer.add_mirror()` accepts arbitrary attacker-supplied URL strings and publishes them on-chain with no allow/deny-list validation. Any DataLayer node that later subscribes to that store will have its `periodically_manage_data()` sync loop feed the untrusted URL straight into an outbound HTTP request via `http_download()`, with no restriction on scheme, host, or destination IP (loopback, link-local, RFC1918/private, cloud metadata endpoints, etc.). This is the same bug class as the referenced Kibana CVE: an "Incomplete List of Disallowed Inputs" that lets a user-controlled value bypass intended network egress restrictions, resulting in SSRF from the victim process.

### Finding Description
`add_mirror()` only checks that the URL list is non-empty; it performs no validation of the URL contents before publishing it to chain via `dl_new_mirror`: [1](#0-0) 

Any DataLayer store owner (an unprivileged local RPC/Data-Layer client acting on their own singleton) can call `add_mirror` with URLs pointing at internal services, e.g. `http://127.0.0.1:<port>/...`, `http://169.254.169.254/...` (cloud metadata), or any internal-network host/port.

These mirror URLs are pulled from wallet state and written into `ServerInfo` records used for sync: [2](#0-1) 

During the periodic sync loop, `fetch_and_validate()` iterates over available servers (which include the attacker-controlled mirror URL) and calls `insert_from_delta_file()`: [3](#0-2) 

`insert_from_delta_file()` calls `download_file()`, which — when no plugin `downloader` is configured (the default HTTP path) — calls `http_download()` directly with `server_info.url`: [4](#0-3) 

`http_download()` performs the actual outbound request with zero validation of the destination host/IP: [5](#0-4) 

No component in this chain — `add_mirror`, `update_subscriptions_from_wallet`, `fetch_and_validate`, `download_file`, or `http_download` — checks whether the resolved host is private, loopback, link-local, or otherwise disallowed. The `.cursor/context/data-layer.md` notes explicitly confirm mirror/plugin URLs are treated as untrusted data sources for content, but nowhere is there a corresponding network-egress restriction on the URL destination itself: [6](#0-5) 

By contrast, elsewhere in the codebase (`chia/server/address_manager.py`, `chia/util/ip_address.py`) there is an established pattern of rejecting private/internal addresses (`is_private` checks, `allow_private_subnets` gating) for peer networking — but this pattern is completely absent from the DataLayer mirror/HTTP-fetch path: [7](#0-6) [8](#0-7) 

### Impact Explanation
An unprivileged Data Layer client (any wallet/store owner able to call `add_mirror`) can force any other DataLayer node that subscribes to that store to issue arbitrary outbound HTTP GET requests to attacker-chosen internal network destinations, including localhost services, internal RPC ports, or cloud metadata services. Because responses are written to disk as delta files and then parsed/inserted by `DataStore.insert_into_data_store_from_file()`, this could also be leveraged to probe internal service behavior, port-scan the victim's internal network (via error/timeout differentials), or interact with internal HTTP APIs that trust localhost/internal-origin callers. This qualifies as Medium severity SSRF impact matching the reference report's bug class.

### Likelihood Explanation
Likelihood is high for any DataLayer deployment that subscribes to third-party stores: mirror URLs are chain-published data, fully attacker-controlled by the store's owning wallet, and consumed automatically by the periodic background sync (`periodically_manage_data()` → `update_subscription()` → `fetch_and_validate()`) without any operator interaction or opt-in beyond subscribing to the store.

### Recommendation
Validate and restrict mirror URLs at the point they are accepted (`DataLayer.add_mirror()`) and/or immediately before use in `http_download()`/`download_file()`: enforce an allowed scheme list (http/https), resolve the hostname, and reject private/loopback/link-local/multicast/reserved IP ranges (reusing the existing `IPAddress.is_private` pattern from `chia/util/ip_address.py`) unless explicitly permitted by configuration, mirroring the `allow_private_subnets` pattern already used in `AddressManager`.

### Proof of Concept
1. Run a DataLayer node and create a store; call `add_mirror` with `urls=["http://127.0.0.1:<internal-rpc-port>/some-path"]` (or a private/internal IP reachable from a victim node), per `chia/data_layer/data_layer.py:965-970`.
2. A second DataLayer node subscribes to that store id (`subscribe` RPC) and runs its normal periodic sync loop.
3. During `fetch_and_validate()` (`chia/data_layer/data_layer.py:642-694`), the victim node selects the malicious mirror URL from `get_available_servers_for_store()` and calls `insert_from_delta_file()` → `download_file()` → `http_download()` (`chia/data_layer/download_data.py:298-324`), issuing an HTTP GET to `http://127.0.0.1:<port>/<delta-filename>` from the victim process — demonstrating SSRF against internal services with no destination validation.

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
