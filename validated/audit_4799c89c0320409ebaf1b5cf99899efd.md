## Analog Found: GitHub host classification trusts an attacker-controlled `WWW-Authenticate` header, enabling forced GitHub Enterprise sign-in against an arbitrary remote

### Title
Attacker-Controlled `WWW-Authenticate` Realm Header Forces GitHub Sign-In Flow Against Untrusted Remote - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The external report's root cause is that `_createLeaf()` derives an authorization decision from data that omits a critical discriminator (the hook address), letting an attacker-controlled encoding collide with a different, more privileged code path. The same bug class exists in Desktop's Git credential-helper trampoline: `getEndpointKind()` decides whether a remote host should be treated as a "GitHub"/"enterprise" identity — a decision that gates which authentication UI/flow is triggered — based on a `WWW-Authenticate` header value that is *entirely attacker-supplied* by the remote Git server, without any binding to the actual host identity.

### Finding Description
`getEndpointKind()` is used by `getCredential()`/`storeCredential()`/`eraseCredential()` in the credential-helper trampoline to classify a Git remote endpoint before deciding how to authenticate: [1](#0-0) 

Notice the heuristic block:
```
for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
}
```
The `wwwauth[...]` credential fields originate from the `WWW-Authenticate` HTTP response header that Git captures during an authentication challenge and forwards to the credential helper — this is fully controlled by whatever server answers the git-http request (the remote, or any proxy/MITM sitting on that HTTP(S) connection). There is no cross-check against the actual host (e.g. `isDotCom`/`isGHE`/`isGitHubHost`) before trusting this string; those real checks (`isGist`, `isDotCom`, `isGHE`, `isGitHubHost`) are only consulted *before or after* this attacker-controlled branch, and the `realm="GitHub"` match short-circuits straight to `'enterprise'` regardless of the actual hostname.

This is structurally identical to the reported bug: an identity/authorization decision (`_createLeaf` leaf value / here, `endpointKind`) is computed from attacker-influenced data (`hookArgs` / here, the HTTP response header) while omitting the one piece of data that actually distinguishes trusted from untrusted context (`hookAddress` / here, the real remote hostname).

Once `endpointKind` returns `'enterprise'` for a host that is not actually GitHub Enterprise: [2](#0-1) 
- If no existing account matches that endpoint, Desktop calls `ui.promptForGitHubSignIn(endpoint)` — invoking the full GitHub/GitHub-Enterprise OAuth sign-in flow targeted at the attacker's arbitrary domain.
- `storeCredential`/`eraseCredential` refuse to run the generic (Basic-auth) credential path for this host (`if (endpointKind !== 'generic') return`), forcing the user down the OAuth-branded flow instead of the normal username/password prompt they'd expect for a non-GitHub server.

### Impact Explanation
This lets any Git server the victim adds as a remote (e.g., in a maliciously crafted cloned repository, or a MITM/rogue proxy terminating an `http://`/misconfigured `https://` git connection) force GitHub Desktop's authentication UI to present a "sign in to GitHub"-style OAuth flow bound to the attacker's endpoint, rather than a generic credential prompt. This matches the allowed impact category "unauthorized OAuth or account binding": Desktop's own trust decision about which auth surface to expose is corrupted by attacker-controlled protocol data, and can also be leveraged to suppress storage/reuse of the user's actual generic Git credentials for that host (denial of the intended generic-auth path), which was the security boundary the generic/GitHub distinction was meant to enforce.

### Likelihood Explanation
The trigger requires nothing beyond a normal Desktop workflow already covered as a valid attacker channel per the task's scope: the victim adds/clones a repository with a remote pointing at an attacker-controlled or MITM'd HTTP(S) Git server and performs an ordinary fetch/push/clone. Sending a crafted `WWW-Authenticate: Basic realm="GitHub"` header on the initial auth challenge is trivial for any server the attacker controls, and Git will forward it verbatim to Desktop's trampoline via the `wwwauth[]` credential field — no special privileges or local access needed.

### Recommendation
Do not trust the `WWW-Authenticate` realm string as a standalone identity signal. It should only be used as a weak hint that triggers an *additional* verification step (e.g., the existing `isGitHubHost(endpoint)` API probe) rather than short-circuiting directly to `'enterprise'` classification. At minimum, require that the host also pass `isGHES`/`isGitHubHost` validation before honoring a `realm="GitHub"` header, so the classification is bound to the true endpoint identity rather than to attacker-suppliable response data — mirroring the report's recommendation to bind the leaf to `hookAddress` in addition to the (attacker-influenced) `hookArgs`.

### Proof of Concept
1. Attacker stands up an HTTP(S) Git server at `https://evil.example.com/some-repo.git` that, on any `git-upload-pack`/`git-receive-pack` auth challenge, responds with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
2. Attacker gets the victim to add this URL as a remote (e.g., embedded in a cloned repository's `.git/config`, or a repo README instructing `git remote add`) — no elevated or unusual interaction beyond normal remote usage.
3. Victim performs a normal `fetch`/`push` in GitHub Desktop against that remote.
4. Git invokes the credential helper trampoline; `parseCredential` picks up the `wwwauth[0]=Basic realm="GitHub"` field; `getEndpointKind()` at [3](#0-2)  matches `realm="GitHub"` and returns `'enterprise'` even though `evil.example.com` is not a GitHub Enterprise host.
5. `getCredential()` at [4](#0-3)  finds no matching account and calls `ui.promptForGitHubSignIn('https://evil.example.com')`, launching the OAuth/device sign-in UI against the attacker-controlled domain instead of the expected generic Basic-auth prompt.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }
