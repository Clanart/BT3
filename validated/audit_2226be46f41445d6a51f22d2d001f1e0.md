### Title
Ungaurded `Kip71GasTarget = 0` in Governance Vote Causes Division-by-Zero Panic in Magma Base Fee Calculation - ([File: params/kip71_config.go])

### Summary
`Kip71GasTarget` is validated only by `noopFormatChecker` (no minimum-value check) when set via `governance_vote`, and `checkConsistency` in `kaiax/gov/headergov/impl/header.go` performs no cross-check on it either. Once `GasTarget` becomes `0` and is ratified into `header.Governance` at the next epoch, `KIP71Config.NextMagmaBlockBaseFee` divides by `gasTarget` unconditionally, causing a runtime panic on every node computing the following block's base fee.

### Finding Description
`gov.Params[Kip71GasTarget]` is defined with `FormatChecker: noopFormatChecker` [1](#0-0) , unlike the sibling `Kip71BaseFeeDenominator`, whose checker explicitly rejects zero (`return ok && v != 0`) [2](#0-1) . `NewVoteData` only runs `param.Canonicalizer` and `param.FormatChecker`, so a vote of `Kip71GasTarget = 0` passes cleanly [3](#0-2) .

The consensus-level `checkConsistency` function, which cross-checks a few parameters (e.g., `Kip71LowerBoundBaseFee` vs `Kip71UpperBoundBaseFee`), places `gov.Kip71GasTarget` in the bucket of params that pass with "no more checks here" [4](#0-3) .

Once the value is ratified (the governing node's vote is aggregated into `header.Governance` at the epoch boundary and later read via `ParamSet`), `KIP71Config.NextMagmaBlockBaseFee` uses `gasTarget := kc.GasTarget` directly as a divisor at two call sites, with no zero-guard analogous to the one protecting `BaseFeeDenominator`: [5](#0-4) [6](#0-5) 

Every node computing/verifying a header after the epoch turnover — via `BlockValidator.validateHeader` → `govParamSet.ToKip71Config().VerifyMagmaHeader(...)` → `NextMagmaBlockBaseFee` — will panic with a division by zero as long as `parentGasUsed != gasTarget` (which is guaranteed once `gasTarget=0` unless a block uses exactly 0 gas) [7](#0-6) .

### Impact Explanation
This causes a consensus-wide node crash/DoS: every full node, not just a subset, panics while validating the very next block after the malicious `GasTarget=0` value takes effect via governance, since base-fee verification is mandatory for all post-Magma blocks. This is more severe than the underlying report's "blocked minting" scenario — it is a chain halt affecting all honest nodes simultaneously, which the rules classify as acceptance of consensus-breaking input / state divergence risk (all nodes crash identically here, but the underlying flaw is unguarded division from an ungated governance parameter reaching a hot consensus path).

### Likelihood Explanation
The setter of the value is the governing node casting a `governance_vote` (or aggregated council vote before Permissionless fork) — an intended, in-protocol action, not a compromised node exploiting a bug in message handling. The bug is that the system fails to bound-check a governance-settable integer that is later used as an unguarded divisor, exactly mirroring the reported pattern where `RoyaltyModule.sol`/`IpNFT.sol` failed to bound `duration`/`price`/`royaltyBps` before using them in downstream calculations. Given `BaseFeeDenominator` was explicitly hardened against zero (`if kc.BaseFeeDenominator == 0 { ... }`), the omission of the same guard for `GasTarget` (and reliance on a `noopFormatChecker`) appears to be an oversight rather than intended design.

### Recommendation
Add a `FormatChecker` for `Kip71GasTarget` (and ideally `Kip71MaxBlockGasUsedForBaseFee`) that rejects `0`, mirroring `Kip71BaseFeeDenominator`'s `v != 0` check, and/or add a defensive zero-guard inside `NextMagmaBlockBaseFee` around the `gasTarget` divisor (as already done for `baseFeeDenominator`), falling back to a safe default when `gasTarget == 0`.

### Proof of Concept
1. Governing node casts `governance_vote("kip71.gastarget", 0)`. `NewVoteData` accepts it since `FormatChecker` is `noopFormatChecker` [1](#0-0) .
2. `VerifyVote`'s `checkConsistency` performs no additional check for `Kip71GasTarget`, so the vote is accepted into `header.Vote` [8](#0-7) .
3. At the next epoch boundary the vote is ratified into `header.Governance`, updating the effective `ParamSet.GasTarget` to `0`.
4. On the following block, any parent block with `parentGasUsed != 0` triggers `NextMagmaBlockBaseFee`'s branch `parentGasUsed > gasTarget` (or `<`), executing `x.Div(x, new(big.Int).SetUint64(gasTarget))` with `gasTarget = 0` [9](#0-8) , causing a `big.Int` division-by-zero panic in every node's `BlockValidator.validateHeader` call [7](#0-6) , halting the chain.

func NewVoteData(voter common.Address, name string, value any) VoteData {
	param, ok := gov.Params[gov.ParamName(name)]
	if !ok {
		param, ok = gov.ValidatorParams[gov.ParamName(name)]
		if !ok {
			logger.Error("Invalid vote name", "name", name)
			return nil
		}
	}

	cv, err := param.Canonicalizer(value)
	if err != nil {
		logger.Error("Canonicalize error", "name", name, "value", value, "err", err)
		return nil
	}

	if !param.FormatChecker(cv) {
		logger.Error("Format check error", "name", name, "value", value)
		return nil
	}

	return &voteData{
		voter: voter,
		name:  gov.ParamName(name),
		value: cv,
	}
}
