### Title
Malicious FROST preprocess with identity nonce commitments panics the BIP-340 signer via `x()` on the point at infinity - ([File: networks/bitcoin/src/crypto.rs])

### Summary
A remote participant in a Bitcoin FROST signing session can send a crafted `Preprocess` whose nonce commitments sum to the point at infinity. During `sign_share`/`verify`, `Hram::hram` calls `x()`/`x_only()`, which `expect()`s a non-infinity point and panics, crashing the signer — a denial of service directly analogous to CVE-2018-10882 (crafted input reaches an unhandled edge case → crash/DoS).

### Finding Description
`crypto.rs` defines helpers used by the Taproot/BIP-340 FROST `Algorithm`:

- `x()` panics on the point at infinity via `encoded.x().expect("point at infinity")` (networks/bitcoin/src/crypto.rs:13-16).
- `x_only()` `.expect()`s a non-infinity, odd-checked point (networks/bitcoin/src/crypto.rs:21-23).
- `Hram::hram` invokes `x(R)` and `x(A)` on every sign/verify call (crypto.rs:59-73), and `needs_negation`/`verify` post-process `sig.R` (crypto.rs:139-150). The doc comments explicitly admit: "If either `R` or `A` is the point at infinity, this will panic" and "`verify`, `verify_share` MUST be called after `sign_share` ... this library MAY panic" (crypto.rs:54, 78-83).

On the read path, `AlgorithmSignMachine::read_preprocess` calls `Commitments::read(reader, &self.params.algorithm.nonces())`, which calls `NonceCommitments::read` → `C::read_G` per commitment (crypto/frost/src/sign.rs:276-281, crypto/frost/src/nonce.rs:133-139). `Secp256k1::read_G` performs canonical-decoding only; nothing in the FROST preprocess pipeline rejects identity (`O`) nonce commitments, unlike RFC 9591 which mandates `Identity`-element checks on commitments.

The group nonce `R` is the sum of all participants' commitments. A malicious participant who observes the other preprocesses for a signing set (or mounts a ROS-style parallel session) chooses their commitment as the negation of the aggregate of the honest commitments, making `nonce_sums`/the committed `R` the identity. When honest signers reach `sign_share`/`verify_share`, `Hram::hram` calls `x(&R)` and the process panics.

### Impact Explanation
Every honest validator that includes the malicious preprocess crashes (panic) mid-signing. This is a remote, unauthenticated-input-driven denial of service against the Bitcoin signing pipeline: the validator set cannot complete the multisig session, stalling withdrawals/rotations until restart, and the attacker can repeat it on each attempt. This matches the "incorrect verifier/signer formula reachable panic → DoS" class; severity Medium per the rubric.

### Likelihood Explanation
The trigger only requires the attacker to be a participant (or to inject a preprocess as a named participant) who can set both of their nonce commitments. Since preprocesses are broadcast before `sign`, a reactive attacker can compute `-(sum of other commitments)` and submit it; no collusion or key material is needed. The panic path is documented in the code itself ("will panic"), and no identity check exists in `Commitments::read`/`read_G` to stop it earlier.

### Recommendation
- In `Commitments::read` / `NonceCommitments::read` (crypto/frost/src/nonce.rs) reject identity points per RFC 9591 (`InvalidPreprocess`), and/or in `IetfSchnorr::sign_share`/`verify_share` check `nonce_sums`/aggregated `R` for `is_identity()` and return `FrostError::InvalidPreprocess(l)` instead of proceeding.
- Alternatively/additionally, make `Hram::hram`/`x`/`x_only` return `Option`/`Result` and propagate `FrostError` rather than panicking, so malformed preprocess bytes can never abort the signer.

### Proof of Concept
1. Honest signers `p1..pt` broadcast preprocesses; commitments for nonce index j are `D_j, E_j`.
2. Attacker `pa` computes `S = Σ_{i≠a} D_i` and sends preprocess with `D_a = -S`, `E_a = -(Σ_{i≠a} E_i)` (both valid canonical SEC1 encodings, so `read_G` accepts them).
3. Each honest signer's `machines.read_preprocess(...)` succeeds; `sign(preprocesses, msg)` computes `nonce_sums[j][0] = Σ D_i = O` (identity).
4. `IetfSchnorr::sign_share` → `Hram::hram(&R = O, &A, msg)` → `x(&O)` → `encoded.x()` returns `None` → `expect("point at infinity")` panics at `networks/bitcoin/src/crypto.rs:15`. The signer process aborts; the signing round can never complete while the attacker's preprocess is included.
