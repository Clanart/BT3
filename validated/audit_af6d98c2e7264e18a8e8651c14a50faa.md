## Finding

The binding claimed to hold is:
`withdrawals.payout_payer_operator_xonly_pk` (set by `Verifier::update_finalized_payouts`, `core/src/verifier.rs:2319-2321`) `== operator_xonly_pk` of the party whose funds actually paid `output_txout`'s value (the party that supplied the majority of the payout tx's inputs via `fund_raw_transaction`/`add_inputs: true` in `Operator::withdraw`, `core/src/operator.rs:620-673`).

Tracing the code confirms this binding can be broken.

### Title
Payout-tx attribution is unauthenticated — SIGHASH_SINGLE|ANYONECANPAY lets anyone hijack operator credit for a payout by rebroadcasting a competing spend with a different OP_RETURN - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary
`create_payout_txhandler` signs input 0 with the user's `SinglePlusAnyoneCanPay` signature, which under BIP-341/342 rules commits only to input 0 and output 0 [1](#0-0) . The OP_RETURN output carrying `operator_xonly_pk` (output index 2) and any additional funding inputs are completely outside the signed data [2](#0-1) . Anyone who observes the honest operator's unconfirmed payout tx can copy that witness into a new transaction with the same input 0 / output 0, add their own funding inputs to cover `output_txout.value`, put their own key in the OP_RETURN, and race it into a block with a higher fee.

### Finding Description
`Operator::withdraw` builds the payout tx from a small "dust" UTXO (as low as 550 sats, see `generate_withdrawal_utxo`, `core/src/test/common/setup_utils.rs:480-497`) as input 0, and uses `fund_raw_transaction` with `add_inputs: true` to supply the real value needed for `output_txout` (near the full bridge amount) [3](#0-2) . The user's signature over input 0 uses `SinglePlusAnyoneCanPay`, verified only against `sighash = calculate_sighash_txin(0, in_signature.sighash_type)` [4](#0-3) . That sighash type commits to: input 0 only (ANYONECANPAY) and output 0 only (SINGLE) — it does not cover the OP_RETURN output (index 2, carrying `operator_xonly_pk`) or any other funding inputs.

Once the honest operator broadcasts this payout tx, an unprivileged attacker who observes it in the mempool can extract the witness for input 0 and construct a new transaction that: reuses that same witness/signature over the same input 0 and same output 0, adds attacker-supplied funding inputs sufficient to cover `output_txout.value`, and sets the OP_RETURN to `attacker_xonly_pk` — then broadcasts with a higher fee. Because both transactions spend the same input-0 outpoint, only one can confirm.

`Verifier::update_finalized_payouts` determines attribution purely by which transaction actually confirms spending the withdrawal UTXO: `get_payout_txs_for_withdrawal_utxos` joins `bitcoin_syncer_spent_utxos` on the withdrawal outpoint [5](#0-4) , then the OP_RETURN of whichever tx confirmed is parsed as `operator_xonly_pk`, with no cross-check against who actually contributed the funding [6](#0-5) . This value is written to `payout_payer_operator_xonly_pk` unconditionally [7](#0-6) .

Downstream, `Verifier::is_kickoff_malicious` requires `operator_xonly_pk == kickoff_data.operator_xonly_pk` from this same DB value or marks the kickoff malicious [8](#0-7) . If the attacker's key (or an invalid/None value) is recorded instead of the honest operator's, the honest operator's future kickoff for this withdrawal will always fail this check, permanently blocking their reimbursement for that withdrawal index.

No existing guard prevents this: `SECP.verify_schnorr` in `Operator::withdraw` only checks the SinglePlusAnyoneCanPay signature is valid for input/output 0 (which it still is, since the attacker did not need to re-sign anything) [9](#0-8) ; there is no covenant/script-path commitment binding the OP_RETURN to the same authorization as the payout output.

### Impact Explanation
The attacker does not steal bridge principal directly (the user's `output_txout` is fixed by the signature and is paid regardless of who wins the race), but they can permanently redirect the *operator-of-record* credit for a withdrawal to an arbitrary key by outbidding the fee of the honest operator's in-flight payout tx. This satisfies "an honest operator permanently unable to be reimbursed" (Critical), because once `payout_payer_operator_xonly_pk` is set to the attacker's (unregistered) key, `is_kickoff_malicious` will reject the honest operator's kickoff for that withdrawal forever, with no code path to correct the DB attribution afterward. This is repeatable per-withdrawal, and does not require the attacker to hold any privileged role — only capital to cover the funding gap and higher fees, and visibility into the mempool.

### Likelihood Explanation
Preconditions: an honest operator must have broadcast (but not yet confirmed) their payout tx — a routine event in the `withdraw` flow. The attacker needs capital roughly equal to `output_txout.value` (near the bridge amount minus fee) plus a competitive fee bump, and the ability to broadcast a Bitcoin transaction/observe the mempool — both explicitly in-scope attacker capabilities. No verifier/operator/aggregator compromise, no majority hashrate, and no malicious peer assumption is required; this is a direct consequence of the payout tx's `SinglePlusAnyoneCanPay` malleability by design.

### Recommendation
Bind the OP_RETURN (operator attribution) output to the same signature that authorizes the spend, e.g., by using `SIGHASH_ALL` (or `SIGHASH_SINGLE` covering all outputs, or a script-path commitment) for a portion of the payout tx's structure, or by having the aggregator/verifiers register a reservation for which operator is authorized to complete a given withdrawal before broadcast, and have `update_finalized_payouts` cross check that against the confirmed OP_RETURN rather than trusting it unconditionally.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    pub async fn update_payout_txs_and_payer_operator_xonly_pk(

            Option<XOnlyPublicKey>,

        )>,

        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;
