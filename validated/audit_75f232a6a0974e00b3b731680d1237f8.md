## Analysis

The kernel CVE's bug class is: **state mutation (ring buffer reconfiguration) and a related "clear" flag were not synchronized under the same lock**, letting a reader/other codepath observe the flag published *before* the ring config, dereferencing stale/inconsistent state.

The closest reachable analog in this codebase is in the **auction bid pool** (`kaiax/auction/impl/bid_pool.go`), which is directly reachable by an unprivileged, unauthenticated `auction_submitBid` RPC caller / gossiped bid.

### Title
Bid validation and bid-pool reconfiguration are not synchronized, allowing bids authorized under a stale auctioneer/entry-point to be admitted after rotation - (`File: kaiax/auction/impl/bid_pool.go`)

### Summary
`BidPool.AddBid()` performs `validateBid()` (which checks the bid's signatures against the *current* `auctioneer`/`auctionEntryPoint` under `auctionInfoMu`) and `insertBid()` (which writes into `bidMap`/`bidTargetMap`/`bidWinnerMap` under `bidMu`) as two separate, non-atomic critical sections. `updateAuctionInfo()` — invoked every block from `PostInsertBlock` — can run concurrently between these two steps, rotate `auctioneer`/`auctionEntryPoint`/`auctionEntryPointVersion`, and call `clearBidPool()`.

### Finding Description [1](#0-0) 
`AddBid` calls `validateBid` then `insertBid` as two distinct locked sections, with no lock held across both: [2](#0-1) 
`validateBidSigs`, called from `validateBid`, checks the bid's signature against `bp.auctioneer`/`bp.auctionEntryPoint` only briefly under `auctionInfoMu.RLock()`: [3](#0-2) 

Meanwhile, `updateAuctionInfo` (called every block from `execution.go`'s `PostInsertBlock`) can concurrently swap the auctioneer/entry point and wipe the pool: [4](#0-3) [5](#0-4) 

Because `validateBid` and `insertBid` are not atomic with respect to `updateAuctionInfo`, the following interleaving is possible:
1. Searcher submits bid B, signed/authorized for the *current* `auctioneer`/`auctionEntryPoint`.
2. `AddBid` → `validateBid(B)` passes (signature checks succeed against current auction info).
3. Concurrently, block N is inserted; `PostInsertBlock` detects a governance/registry change and calls `updateAuctionInfo`, which rotates `auctioneer`/`auctionEntryPoint` (e.g., due to a compromised auctioneer key being revoked) and clears the pool via `clearBidPool()`.
4. `AddBid` resumes and calls `insertBid(B)`, which acquires the (now-fresh, empty) `bidMu` and inserts B unconditionally — there is no re-validation against the *new* auction info after the reconfiguration.

The bid B, authorized under the *old, now-revoked* auctioneer, is now live in the pool for the new auction epoch. Additionally, `getBidTxGasLimit` reads `bp.auctionEntryPointVersion` outside of any lock after releasing `auctionInfoMu`: [6](#0-5) 
This is a genuine unsynchronized read racing with `updateAuctionInfo`'s writer under `auctionInfoMu.Lock()`.

When `ExtractTxBundles`/`GetBidTxGenerator` later build the winning bid transaction, they always use the *current* `GetAuctionEntryPoint()`/`GetAuctionEntryPointVersion()` — not the values the bid was actually validated against — so a stale bid can be encoded and submitted against the new entry point without having ever been authorized by the current, rotated auctioneer: [7](#0-6) [8](#0-7) 

### Impact Explanation
An auctioneer key rotation (the exact mechanism KIP-249 provides for revoking a compromised/misbehaving auctioneer) does not reliably invalidate in-flight bids that were authorized under the old key/entry point, because the pool-clear and info-swap are not serialized against concurrently-in-progress `AddBid` calls. A bid signed by a since-revoked auctioneer can still be admitted, win the auction, and be executed on-chain — undermining the auction settlement's authorization guarantee and enabling continued extraction of value (auction settlement theft) by an actor who should have been locked out by the rotation.

### Likelihood Explanation
This requires a race window between per-block `PostInsertBlock`/`updateAuctionInfo` execution and an in-flight `AddBid` call — both are triggered by ordinary, attacker-influenceable events (submitting a bid right before/around block insertion, which happens continuously). No special privileges are needed; an unprivileged bid submitter via `auction_submitBid` or gossiped `HandleBid` can trigger `AddBid`. The window is narrow but reproducible given block cadence and bid submission timing, and `getBidTxGasLimit`'s unlocked read is a plain data race triggerable on every block where auction info changes.

### Recommendation
Hold a single lock (or a version/epoch counter checked under the same lock as the pool mutation) across the full validate-then-insert sequence in `AddBid`, so that `insertBid` re-validates the bid against the auction info that was current at commit time — analogous to the kernel fix, which moved the hook assignment into the same lock section as the ring-state update instead of publishing it afterward. Additionally, fix the unsynchronized read of `bp.auctionEntryPointVersion` in `getBidTxGasLimit`.

### Proof of Concept
1. Start the auction module with `auctioneer = A1`, `entryPoint = E1`.
2. Searcher sends bid B signed for `(A1, E1)` via `auction_submitBid`; `AddBid(B)` enters `validateBid` and passes signature checks against `(A1, E1)`.
3. Before `insertBid(B)` runs, a new block is processed and the system registry rotates to `(A2, E2)`; `PostInsertBlock` → `updateAuctionInfo` clears the pool and sets `auctioneer=A2, auctionEntryPoint=E2`.
4. `insertBid(B)` proceeds and inserts B into the freshly-cleared pool — no re-check against `(A2, E2)` occurs.
5. On the next `ExtractTxBundles`/`GetBidTxGenerator` call, B (authorized only under revoked `A1`/old `E1`) is built into a transaction targeting the *current* `E2` and submitted, despite never having been authorized by `A2`. [9](#0-8)

// updateAuctionInfo updates the auction info if the auctioneer or auction entry point address is changed.
func (bp *BidPool) updateAuctionInfo(auctioneer common.Address, auctionEntryPoint common.Address, auctionEntryPointVersion string, bidTxGasBuffer uint64) {
	bp.auctionInfoMu.Lock()
	defer bp.auctionInfoMu.Unlock()

	if bp.auctioneer == auctioneer && bp.auctionEntryPoint == auctionEntryPoint && bp.auctionEntryPointVersion == auctionEntryPointVersion && bp.bidTxGasBuffer == bidTxGasBuffer {
		return
	}

	// Clear the existing auction pool since the auctioneer or auction entry point address is changed.
	bp.clearBidPool()

	bp.auctioneer = auctioneer
	bp.auctionEntryPoint = auctionEntryPoint
	bp.auctionEntryPointVersion = auctionEntryPointVersion
	bp.bidTxGasBuffer = bidTxGasBuffer

	logger.Info("Update auction info", "auctioneer", auctioneer, "auctionEntryPoint", auctionEntryPoint, "auctionEntryPointVersion", auctionEntryPointVersion, "bidTxGasBuffer", bidTxGasBuffer)
}

// AddBid adds a bid to the bid pool.
// Required mutex is locked in each function.
func (bp *BidPool) AddBid(bid *auction.Bid) (common.Hash, error) {
	if atomic.LoadUint32(&bp.running) == 0 {
		return common.Hash{}, auction.ErrAuctionPaused
	}

	if err := bp.validateBid(bid); err != nil {
		return common.Hash{}, err
	}

	if err := bp.insertBid(bid); err != nil {
		return common.Hash{}, err
	}

	gasLimit, err := bp.getBidTxGasLimit(bid)
	if err != nil {
		return common.Hash{}, err
	}
	bid.SetGasLimit(gasLimit)

	bp.newBidCh <- bid

	return bid.Hash(), nil
}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}

func (a *AuctionModule) PostInsertBlock(block *types.Block) error {
	if a.Downloader.Synchronising() || !a.ChainConfig.IsRandaoForkEnabled(block.Number()) {
		atomic.CompareAndSwapUint32(&a.bidPool.running, 1, 0)
		return nil
	}

	if !a.updateAuctionInfo(block.Number()) {
		logger.Debug("stop auction since auctioneer or auction entry point is not set")
		atomic.CompareAndSwapUint32(&a.bidPool.running, 1, 0)
		return nil
	}

	atomic.CompareAndSwapUint32(&a.bidPool.running, 0, 1)

	txHashMap := make(map[common.Hash]struct{})
	for _, tx := range block.Transactions() {
		txHashMap[tx.Hash()] = struct{}{}
	}
	a.bidPool.removeOldBids(block.Number().Uint64(), txHashMap)

	return nil
}

func (a *AuctionModule) GetBidTxGenerator(tx *types.Transaction, bid *auction.Bid) *builder.TxOrGen {
	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId           = a.InitOpts.ChainConfig.ChainID
			signer            = types.LatestSignerForChainID(chainId)
			auctionEntryPoint = a.bidPool.GetAuctionEntryPoint()
			key               = a.InitOpts.NodeKey
		)

		data, err := system.EncodeAuctionCallData(bid, a.bidPool.GetAuctionEntryPointVersion())
		if err != nil {
			return nil, err
		}

		if bid.GetGasLimit() == 0 {
			gasLimit, err := a.bidPool.getBidTxGasLimit(bid)
			if err != nil {
				return nil, err
			}
			bid.SetGasLimit(gasLimit)
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &auctionEntryPoint,
			types.TxValueKeyAmount:     common.Big0,
			types.TxValueKeyData:       data,
			types.TxValueKeyGasLimit:   bid.GetGasLimit(),
			types.TxValueKeyGasFeeCap:  tx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  tx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)

		return tx, err
	}
