Confirmed: `Kip71GasTarget`'s `FormatChecker` is `noopFormatChecker`, meaning a value of `0` passes canonicalization and is accepted into the `ParamSet` unlike `Kip71BaseFeeDenominator`, which explicitly rejects zero (`v != 0`).

### Title
Zero-value `kip71.gastarget` governance vote causes division-by-zero panic in base fee calculation - (File: `params/kip71_config.go`)

### Summary
`Kip71GasTarget` is a mutable governance parameter votable via header governance (and post-Kore, contract governance) with no lower-bound validation, since its `FormatChecker` is `noopFormatChecker`. A value of `0` is accepted and later used as a divisor in `KIP71Config.NextMagmaBlockBaseFee`, causing a `big.Int` division-by-zero panic on every node computing the next block's base fee.

### Finding Description
`gov.Params[Kip71GasTarget]` uses `noopFormatChecker`, which always returns `true` regardless of value: [1](#0-0) 

Unlike `Kip71BaseFeeDenominator`, which explicitly rejects zero (`return ok && v != 0`), `Kip71GasTarget` has no such guard: [2](#0-1) 

This parameter is not in the `AlwaysDeprecated` map, so it remains a legitimately votable, mutable governance parameter (confirmed as `<mutable parameters>` in the module README) and is not rejected by `checkConsistency`/`VerifyVote`: [3](#0-2) 

Once set, `GasTarget` flows into `KIP71Config.NextMagmaBlockBaseFee`, where it is used unguarded as a divisor: [4](#0-3) 

If `gasTarget == 0` and the parent block used any gas (`parentGasUsed > 0`), execution takes the `parentGasUsed > gasTarget` branch and computes `x.Div(x, new(big.Int).SetUint64(gasTarget))` with a zero divisor, which panics in Go's `math/big` package.

### Impact Explanation
`NextMagmaBlockBaseFee` is called by every full node/validator processing headers post-Magma to verify and compute base fees. A panic here is a deterministic, network-wide crash triggered by a single vote transaction/header once the vote takes effect (i.e., once `kip71.gastarget` becomes `0` in the effective `ParamSet`), since it affects header verification and block assembly universally — not merely a single node. This qualifies as acceptance of an invalid parameter that leads to a network-wide state-processing crash, distinct from a normal accounting error, and directly maps to the "block assembly" / "governance parameters" reachable-path categories.

### Likelihood Explanation
Exploitability depends on the governance mode: on `single` governance mode (Kaia mainnet/Kairos-style config), only the governing node can cast header votes, and post-Kore, contract governance additionally allows parameter updates via the `GovParam` contract, which may have broader (e.g., council-voted) write access depending on deployment. In either path, the value passes straight through `Canonicalizer`/`FormatChecker`/`checkConsistency` with no numeric floor, so any actor with governance-vote or contract-governance-write privilege (not necessarily the chain operator) can trigger the crash. Given the value is validated nowhere along the path, the likelihood of the underlying zero being accepted is high; the likelihood of an adversarial or accidental governance actor submitting it depends on privilege distribution in the specific network's governance configuration, which is outside the scope of this repo's default code paths.

### Recommendation
Add an explicit `FormatChecker` for `Kip71GasTarget` (and other unbounded KIP-71/reward parameters using `noopFormatChecker`, e.g., `Kip71LowerBoundBaseFee`, `Kip71MaxBlockGasUsedForBaseFee`, `GovernanceUnitPrice`) that rejects `0` at minimum, mirroring the existing `Kip71BaseFeeDenominator` pattern:
```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0
    },
    ...
}
```
Additionally, consider a defensive guard inside `NextMagmaBlockBaseFee` (analogous to the existing `BaseFeeDenominator == 0` fallback) so a malformed/legacy config cannot crash block processing even if validation is bypassed elsewhere: [5](#0-4) 

### Proof of Concept
1. On a network where the governing node (single mode) or contract-governance write-role can update `kip71.gastarget`, submit a header vote (pre-Kore) or `GovParam` contract call (post-Kore) setting `kip71.gastarget = 0`.
2. The vote passes `NewVoteData`/`checkConsistency` since `Kip71GasTarget`'s `FormatChecker` is `noopFormatChecker` and it is absent from `AlwaysDeprecated`.
3. Once the parameter takes effect at block `N`, any node computing `NextMagmaBlockBaseFee` for a parent block with `parentHeaderGasUsed > 0` executes:
   ```go
   gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget) // = parentGasUsed
   x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
   y := x.Div(x, new(big.Int).SetUint64(gasTarget)) // gasTarget = 0 -> panic: division by zero
   ```
   causing the node process to panic while verifying/assembling block `N+1`, halting block production/verification network-wide.
