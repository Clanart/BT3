## Title
SSRF via unauthenticated DataLayer mirror URLs fetched by `http_download` / `download_file` - ([File: chia/data_layer/download_data.py])

### Summary
The `create_mirror_puzzle()` coin used to publish DataLayer mirror server URLs on-chain has no ownership binding to the store it advertises. Anyone who can get a `CREATE_COIN` condition into a confirmed spend (any wallet user, not the DataLayer store owner) can create a "mirror" coin whose memo encodes an arbitrary `launcher_id` (any store id, including stores they don't own) and arbitrary attacker-controlled URLs. Any node that is tracking/owns that store id will then pull those URLs via wallet RPC `dl_get_mirrors`/`update_subscriptions_from_wallet` and issue an unauthenticated `aiohttp` GET (or POST to a "downloader" plugin) against them in `chia/data_layer/download_data.py`'s `http_download()`/`download_file()`, without validating scheme, host, port, or resolved IP — the same bug class described in the JunoClaw `computeDataVerify` SSRF report.

### Finding Description
`create_mirror_puzzle()` curries `P2_PARENT` with `Program.to(1)` (i.e., "return the solution/conditions as-is"), so the mirror coin's spend conditions are entirely attacker-controlled — there is no signature, singleton, or store-ownership check tying the coin to the DataLayer launcher it claims to mirror: [1](#0-0) 

`get_mirror_info()` simply extracts `launcher_id` and URL list straight from the `CREATE_COIN` memo of any coin with the mirror puzzle hash, with no verification that the creator controls that launcher_id: [2](#0-1) 

The DataLayer service's background loop periodically pulls these attacker-supplied URLs from chain via `update_subscriptions_from_wallet()` for every subscribed/owned store and merges them into the active subscription list without validating them: [3](#0-2) [4](#0-3) 

`update_subscription()` runs this sync step immediately before `fetch_and_validate()`, which then issues HTTP requests to the server URLs: [5](#0-4) [6](#0-5) 

The actual network fetch is `http_download()` in `download_data.py`, which performs `aiohttp` `session.get(server_info.url + "/" + filename, ...)` with no scheme allow-list, no port restriction, and no check against internal/loopback/link-local (cloud metadata) IP ranges — the URL is used exactly as supplied on-chain: [7](#0-6) 

This is reachable purely by submitting a normal, unprivileged spend bundle that creates a `MIRROR_PUZZLE_HASH` coin with the desired memo — no special permissions, wallet RPC access, or ownership of the targeted store are required. Every full node/DataLayer instance that is subscribed to or owns the targeted `store_id` will independently and periodically fetch the attacker-chosen URL.

### Impact Explanation
This lets an unprivileged chain participant force any DataLayer node (owner or subscriber of a given store) to make outbound HTTP requests to attacker-chosen destinations, including:
- Internal/loopback services on the node's LAN (`http://127.0.0.1:<port>/...`, `http://10.x.x.x/...`).
- Cloud instance-metadata endpoints (e.g., `http://169.254.169.254/...`) if the node runs on a cloud VM, potentially leaking credentials.
- Port-scanning and probing arbitrary internal endpoints by observing success/failure (backoff/miss tracking) as an oracle.
The plugin/downloader path (`download_file` -> `session.post(downloader.url + "/download", ...)`) similarly forwards attacker-controlled URLs to a local plugin service. This meets the High severity bar for SSRF against internal services from an unprivileged on-chain actor, consistent with the reported bug class (CVSS 8.2, C:H).

### Likelihood Explanation
High. Creating a mirror coin only requires a standard, unprivileged spend bundle with a `CREATE_COIN` condition to the known `MIRROR_PUZZLE_HASH` and a memo of `[launcher_id, url, ...]` — no fee-exempt or privileged operation is needed, and it doesn't require controlling the target store's singleton. Any node subscribed to (or owning) that store will pick up the URL automatically on its next `manage_data_interval` cycle.

### Recommendation
- Validate mirror/subscription URLs before use in `http_download`/`download_file`: enforce an allow-listed scheme (`http`/`https`), disallow private/loopback/link-local/metadata IP ranges (resolve DNS and check the resulting IP, not just the hostname string), and enforce expected ports.
- Consider requiring that mirror coins be verifiably tied to store ownership (e.g., only trust mirrors whose creation is signed by/associated with the DL wallet that owns the singleton) before treating their URLs as fetch targets, or clearly document/gate this trust boundary and make outbound fetches opt-in per store.
- Apply the same URL validation to the `PluginRemote`/downloader POST path in `download_file()` and to `get_downloader()`'s POST to `d.url + "/handle_download"`.

### Proof of Concept
1. Attacker submits an ordinary spend bundle that creates a coin with puzzle hash `create_mirror_puzzle().get_tree_hash()`, amount arbitrary, and memo `[victim_store_id, b"http://169.254.169.254/latest/meta-data/", ...]` — no ownership of `victim_store_id`'s singleton required (`chia/wallet/db_wallet/db_wallet_puzzles.py:90-110`).
2. Once confirmed, any DataLayer node subscribed to or owning `victim_store_id` calls `dl_get_mirrors` -> `update_subscriptions_from_wallet` on its next management cycle, absorbing the attacker's URL as a subscription server (`chia/data_layer/data_layer.py:979-985`, `chia/data_layer/data_store.py:1668-1704`).
3. `update_subscription()` -> `fetch_and_validate()` -> `insert_from_delta_file()` -> `download_file()` -> `http_download()` issues an unauthenticated `aiohttp.ClientSession().get("http://169.254.169.254/latest/meta-data/..." )` from the victim node (`chia/data_layer/download_data.py:298-324`), demonstrating SSRF against the node's internal/cloud network.

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
    async def update_subscriptions_from_wallet(self, store_id: bytes32, new_urls: list[str]) -> None:
        async with self.db_wrapper.writer() as writer:
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 1 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            old_urls = [row["url"] async for row in cursor]
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 0 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            from_subscriptions_urls = {row["url"] async for row in cursor}
            additions = {url for url in new_urls if url not in old_urls}
            removals = [url for url in old_urls if url not in new_urls]
            for url in removals:
                await writer.execute(
                    "DELETE FROM subscriptions WHERE url == :url AND tree_id == :tree_id",
                    {
                        "url": url,
                        "tree_id": store_id,
                    },
                )
            for url in additions:
                if url not in from_subscriptions_urls:
                    await writer.execute(
                        "INSERT INTO subscriptions(tree_id, url, ignore_till, num_consecutive_failures, from_wallet) "
                        "VALUES (:tree_id, :url, 0, 0, 1)",
                        {
                            "tree_id": store_id,
                            "url": url,
                        },
                    )
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
