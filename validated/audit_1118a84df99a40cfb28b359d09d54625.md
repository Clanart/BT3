Based on my investigation, I found a genuine analog of the reported bug class in the Kaia auction module: a field (`MaxGasPrice`) that exists in the signed data structure but whose inclusion in the EIP-712 signature hash is conditional on a version parameter that is *not* itself bound into the signed data.

### Title
Auctioneer/relayer can strip `MaxGasPrice` protection from a searcher's signed bid without invalidating the searcher signature - ([File: kaiax/auction/bid.go], [File: kaiax/auction/eip712.go], [File: kaiax/auction/impl/bid_pool.go])

### Summary
`Bid.MaxGasPrice` is a field in `BidData` [1](#0-0)  that is only included in the EIP-712 struct hash when the entry-point `version` passed to `GetHashTypedData` equals `AuctionVersionV3` [2](#0-1) . The `version` used for validation, `bp.auctionEntryPointVersion`, is a governance/config parameter fetched independently of the bid payload itself [3](#0-2) , not something cryptographically bound to the specific bid. This mirrors the reported Nexus bug: a parameter (`moduleType` there, `MaxGasPrice`/`version` selection here) that governs how a security-relevant field is interpreted/validated is not itself covered by the signature that's supposed to authorize it.

### Finding Description
`Bid.EncodeData()` (V2/`auctionType`) excludes `MaxGasPrice` from the signed struct entirely, while `bidV3.EncodeData()` (V3/`auctionTypeV3`) includes it [4](#0-3) [5](#0-4) . `ValidateSearcherSig` simply recomputes the digest using whichever version string is supplied and checks the ECDSA recovery matches `b.Sender` [6](#0-5) . The `BidPool.validateBidSigs` calls this with `bp.auctionEntryPointVersion`, a value read from module config/state rather than derived from the bid itself [3](#0-2) .

Because `MaxGasPrice` is carried in `BidData` (and thus in the bid's RLP hash/identity [7](#0-6) ) independently of whether it was actually part of what the searcher cryptographically committed to, a relayer/auctioneer that forwards a searcher's V2-style signature (excludes `MaxGasPrice`) can pair it with an attacker-chosen `MaxGasPrice` value while the pool is configured for V2. The searcher's ECDSA signature over the V2 digest remains valid because `MaxGasPrice` was never part of that digest, so `ValidateSearcherSig` passes even though `MaxGasPrice` has been tampered with by a third party. This is structurally identical to the reported issue: a security-relevant parameter is decoupled from the value actually authorized by the off-chain signer.

### Impact Explanation
`MaxGasPrice` in an auction bid represents the searcher's cap on the gas price they're willing to pay for their bid to be executed on their behalf by the proposer/auctioneer. If this field can be modified by the relaying auctioneer without invalidating the searcher's own signature (when running with `AuctionVersionV2`), the auctioneer/proposer can effectively force the searcher's transaction to be included at a materially different (higher) gas price/cost than the searcher actually authorized, since the signature the searcher produced never bound that value. This is a fee-abuse / unauthorized-value-movement style issue reachable by any bidder/relayer participating in Kaia's built-in auction module, which is explicitly in-scope per the rules (auction/gasless modules, staker/bidder-reachable paths).

### Likelihood Explanation
Exploitability depends entirely on the deployed `auctionEntryPointVersion` being V2 (`"0.0.1"`), in which case any auctioneer relaying a bid can tamper with `MaxGasPrice`. This requires the network/entry-point to be configured for the older version and an auctioneer or intermediate relayer willing to alter the bid before submission — a role that is not the untrusted "malicious validator/peer" category excluded by the rules, but rather the fee-delegation/auction counterparty explicitly permitted to be modeled as an attacker.

### Recommendation
Always include `MaxGasPrice` in the signed EIP-712 struct regardless of version (e.g., default to zero/sentinel consistently across V2 and V3 encodings), or derive/commit the `version` selector itself as part of the signed payload so a relayer cannot silently reinterpret a signature under a weaker schema. Alternatively, deprecate the V2 (`auctionType`) hash entirely once `MaxGasPrice` is a supported/used field, since any legacy struct hash that omits a security-relevant field will always be strippable by an intermediate party.

### Proof of Concept
Not independently executed against a live node; based on static code review:
1. Searcher builds a `BidData` with `MaxGasPrice = X` and signs `GetHashTypedData(chainId, entryPoint, AuctionVersionV2)` — this digest excludes `MaxGasPrice` per `Bid.EncodeData()` [8](#0-7) .
2. A malicious auctioneer/relayer receives this `SearcherSig`, then constructs a modified `BidData` with `MaxGasPrice = Y` (any value) but keeps the same `SearcherSig`.
3. Submits to `BidPool.validateBidSigs`, which is configured with `auctionEntryPointVersion = AuctionVersionV2` [3](#0-2) ; `ValidateSearcherSig` recomputes the V2 digest (still excluding `MaxGasPrice`) and the recovered signer still equals `b.Sender`, so validation succeeds despite `MaxGasPrice` being altered.

**Uncertainty:** I was not able to verify (due to index/time limits) whether `MaxGasPrice` is currently consumed anywhere in on-chain execution/gas-charging logic for V2-configured deployments (i.e., whether it is actually enforced downstream), which would confirm concrete economic impact versus a latent inconsistency. I found references to `MaxGasPrice` in `blockchain/system/auction.go` and `contracts/bindings/auctionv3/Kip249V3.go` that I did not have iterations left to inspect. A Devin session with full repository access should verify how `MaxGasPrice` is consumed on the execution/settlement path under `AuctionVersionV2` to confirm whether this is actively exploitable in production or only relevant once V3 is the sole active version.

func (b *Bid) ValidateSearcherSig(chainId *big.Int, verifyingContract common.Address, version string) error {
	if chainId == nil {
		return ErrNilChainId
	}

	if common.EmptyAddress(verifyingContract) {
		return ErrNilVerifyingContract
	}

	digest := b.GetHashTypedData(chainId, verifyingContract, version)

	recoveredSender, err := getSigner(b.SearcherSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover searcher sig: %v", err)
	}

	if recoveredSender != b.Sender {
		return fmt.Errorf("invalid searcher sig: expected %v, calculated %v", b.Sender.String(), recoveredSender.String())
	}

	return nil
}

// EncodeEIP712 encodes any EIP712Encoder according to EIP-712 specification
func EncodeEIP712(encoder EIP712Encoder) []byte {
	encoded := make([]byte, 0)
	encoded = append(encoded, encoder.EncodeType()...)
	encoded = append(encoded, encoder.EncodeData()...)
	return crypto.Keccak256Hash(encoded).Bytes()
}

// GetHashTypedData returns the EIP-712 digest for the bid.
// version must match the on-chain AUCTION_VERSION of the entry-point contract
// the bid targets; "0.0.2" selects the v3.0 struct typehash (with maxGasPrice),
// any other value falls back to the v2.1 typehash.
func (b *Bid) GetHashTypedData(chainId *big.Int, verifyingContract common.Address, version string) []byte {
	if chainId == nil {
		return nil
	}

	domain := EIP712Domain{
		EIP712DomainTypeHash: eip712TypeHash,
		NameHash:             auctionNameHash,
		VersionHash:          crypto.Keccak256Hash([]byte(version)),
		ChainId:              chainId,
		VerifyingContract:    verifyingContract,
	}

	domainSeparator := EncodeEIP712(domain)

	var structHash []byte
	if version == AuctionVersionV3 {
		structHash = EncodeEIP712(bidV3{b})
	} else if version == AuctionVersionV2 {
		structHash = EncodeEIP712(b)
	} else {
		// Unknown version: default to v2.1 typehash.
		structHash = EncodeEIP712(b)
	}

	return crypto.Keccak256([]byte{0x19, 0x01}, domainSeparator, structHash)
}

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}
