### Title
Operator can be falsely credited as a payout's fronting party because `is_kickoff_malicious` trusts the payout tx's OP_RETURN with no re-derivation from the payout tx's actual funding inputs - (File: core/src/verifier.rs, core/src/states/kickoff.rs)

### Summary
`Verifier::is_kickoff_malicious` decides whether a kickoff is malicious solely by comparing `kickoff_data.operator_xonly_pk` against an `operator_xonly_pk` value that was parsed unauthenticated from the payout transaction's OP_RETURN output. Because the payout transaction's user signature uses `SIGHASH_SINGLE | SIGHASH_ANYONECANPAY`, that signature covers only input 0 and output 0, leaving the OP_RETURN output (and any extra funding inputs) completely unauthenticated and replaceable by anyone, so the "payer" attribution consumed by `KickoffStateMachine`/`CheckIfKickoffMalicious` can diverge from who actually funded the payout.

### Finding Description
The broken binding is: `payout_info.operator_xonly_pk` (written into the DB from the payout tx OP_RETURN by `Verifier::update_finalized_payouts`, core/src/verifier.rs:2312-2342) == the operator that actually funded/broadcast the payout tx. This equality is assumed but never independently verified.

- `update_finalized_payouts` extracts the fronting operator purely from `get_first_op_return_output` / `parse_op_return_data` on the mined payout tx, with no signature or input-ownership check: `core/src/verifier.rs:2312-2321`.
- `is_kickoff_malicious` (core/src/verifier.rs:1859-1914) then uses this DB value as ground truth: it only checks `operator_xonly_pk != kickoff_data.operator_xonly_pk` and the Winternitz-committed truncated blockhash; if both match it returns `Ok(false)` (non-malicious), causing no `Challenge` tx to be queued (`core/src/verifier.rs:1966-2024`).
- `KickoffStateMachine`/`StateManager::check_if_kickoff_malicious` (core/src/states/event.rs:339-402) and the `CheckIfKickoffMalicious` duty (core/src/states/context.rs:53-67) blindly forward this witness/DB-derived data with no re-derivation from the payout transaction's non-index-0 funding inputs.
- The payout transaction (`create_payout_txhandler`, core/src/builder/transaction/operator_reimburse.rs:407-436) has a single signed input (index 0, the withdrawal UTXO) signed by the user with `SinglePlusAnyoneCanPay` (enforced in `Operator::withdraw`, core/src/operator.rs:630-637). `SIGHASH_SINGLE` binds input 0 only to output 0; `ANYONECANPAY` lets anyone add unsigned funding inputs. Neither covers the OP_RETURN output (output index 2) or any extra funding input's ownership.

Exploit flow: an unprivileged attacker withdraws through the Citrea bridge (or observes an existing, still-unconfirmed payout tx broadcast by a real operator), reconstructs a competing transaction that reuses the signed input-0/output-0 pair (still valid because ANYONECANPAY/SINGLE doesn't invalidate it), replaces the OP_RETURN with an arbitrary target operator's x-only pubkey, adds its own fee-paying input, and gets this variant confirmed instead (e.g. via a fee-race). Once mined, `update_finalized_payouts` records the attacker-chosen operator as payer. When that operator later performs a routine, honestly-motivated kickoff for the deposit's assigned kickoff slot, `is_kickoff_malicious` reads the forged attribution, matches it against `kickoff_data.operator_xonly_pk`, and returns `false` — no challenge is ever queued, even though that operator never funded the payout.

No existing guard closes this: `is_kickoff_malicious` does not call `SPV::verify` against funding-input ownership, does not inspect any input beyond index 0, and `verify_storage_proofs`/`total_work_and_watchtower_flags` are unrelated to payer attribution.

### Impact Explanation
This lets a party who is not a registered operator (and holds no collateral) redirect Bitcoin-bridge reimbursement credit to any chosen registered operator's kickoff, letting that operator claim the presigned `Reimburse` tx (core/src/builder/transaction/operator_reimburse.rs:341-385, draining `DepositInMove`, i.e. bridge value) for a payout it never funded, matching the Critical category "an operator reimbursed for a payout it never funded." The blast radius spans every deposit/withdrawal and every operator, since the same unauthenticated-OP_RETURN trust path is used for all payouts.

### Likelihood Explanation
Requires only fee-paying capability and the ability to construct/broadcast a competing Bitcoin transaction that reuses a `SIGHASH_SINGLE|ANYONECANPAY` signature — no verifier, operator, or aggregator privilege, key share, or collateral needed. Cost is limited to Bitcoin transaction fees. It is repeatable across every withdrawal/payout event.

### Recommendation
Do not trust the OP_RETURN alone for payer attribution. Bind the payer's identity cryptographically to the actual funding of the payout — e.g., require the payout tx's fee-funding input(s) to be signed by/spendable only by the claimed operator's key, or require the operator to co-sign (with their own key, covered by SIGHASH_ALL) the entire payout transaction including the OP_RETURN output, so the attribution cannot be altered independently of the signed funding.

Plan: construct a payout tx with the legitimate user SIGHASH_SINGLE|ANYONECANPAY signature over input 0/output 0, then build two variants that both confirm this signed pair but differ only in the OP_RETURN (one naming the real funding operator, one naming a different operator) and in an added ANYONECANPAY funding input from a different key. Feed both through `update_finalized_payouts`-equivalent parsing and `Verifier::is_kickoff_malicious`. Assert that `is_kickoff_malicious` returns `false` for the variant whose OP_RETURN names the same operator as `kickoff_data.operator_xonly_pk`, regardless of which party supplied the funding input signature — demonstrating the check never consults or verifies the non-index-0 funding input's signer against the claimed operator. pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    async fn check_if_kickoff_malicious(
        &mut self,
        payout_blockhash: &Witness,
        kickoff_data: &KickoffData,
        deposit_data: &DepositData,
        context: &mut StateContext<T>,
    ) -> Result<(), BridgeError> {
        // Pull the current round state data first to avoid holding a mutable borrow of self
        // while calling into owner duties (which require an immutable borrow of self.owner).
        let was_challenged_before = {
            let round_machine = self
                .get_round_machine(&kickoff_data.operator_xonly_pk)
                .ok_or_else(|| {
                    eyre::eyre!(
                        "Round machine not found for operator {} while checking if kickoff is malicious",
                        kickoff_data.operator_xonly_pk
                    )
                })?;

            round_machine
                .challenged_rounds
                .contains(&kickoff_data.round_idx)
        };

        let duty = super::Duty::CheckIfKickoffMalicious {
            kickoff_data: *kickoff_data,
            deposit_data: deposit_data.clone(),
            kickoff_witness: payout_blockhash.clone(),
            challenged_before: was_challenged_before,
        };

        let res = context
            .dispatch_duty(duty)
            .await
            .wrap_err("Error while checking if kickoff is malicious")?;

        match res {
            DutyResult::CheckIfKickoffMalicious { challenged } => {
                if challenged && !was_challenged_before {
                    // Reacquire the round machine mutably to update the challenged flag
                    if let Some(round_machine) =
                        self.get_round_machine(&kickoff_data.operator_xonly_pk)
                    {
                        round_machine
                            .handle_with_context(
                                &RoundEvent::SetChallenged {
                                    round_idx: kickoff_data.round_idx,
                                },
                                context,
                            )
                            .await;
                    }
                }
            }
            other => {
                return Err(eyre::eyre!(
                    "Expected CheckIfKickoffMalicious duty result, got {other:?}"
                )
                .into());
            }
        }

        Ok(())
    }
