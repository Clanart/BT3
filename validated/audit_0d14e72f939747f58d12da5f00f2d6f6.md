### Title
Unprivileged senders can mint internally-classified `Change`/`Branch`/`Forwarded` outputs via public offset addresses - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The Keycloak bug class (improper privilege management: a low-privilege principal exercising a privileged capability) maps onto Serai's Bitcoin output classification. `bitcoin-serai`'s `Scanner` classifies received outputs purely by `script_pubkey`, and `processor`'s `get_outputs` translates the matched offset into an `OutputType` (`External`, `Branch`, `Change`, `Forwarded`). The Branch/Change/Forwarded offsets are deterministically derived from public constants (`hash_to_F(KEY_DST, b"branch" | b"change" | b"forward")`) and the multisig's public group key, so any external Bitcoin user can compute those P2TR addresses and deposit to them, causing the processor to record attacker-created outputs with internal-only classifications.

### Finding Description
`Scanner::new`/`register_offset` build a `scripts: HashMap<ScriptBuf, Scalar>` map, and `scan_transaction` matches an output if `self.scripts.get(&output.script_pubkey)` hits — the *only* check is the script, with no notion of who created the output [1](#0-0) . `processor`'s `scanner()` registers three protocol-internal offsets: `Branch`, `Change`, `Forwarded`, each derived via `Secp256k1::hash_to_F(KEY_DST, <public label>)` [2](#0-1) . `forward_address` exposes the forwarded address publicly [3](#0-2) . `get_outputs` then does `let kind = kinds[offset_repr_ref]` to assign `output.kind` for any on-chain output paying to any registered script [4](#0-3) .

Nothing binds a Branch/Change/Forwarded output to an internally-generated transaction. `register_offset`'s own docs warn the mechanism is "surjective" and ordering-dependent [5](#0-4) , and `Output::key()`/`balance()` happily reconstruct and value any such output [6](#0-5) . Serai-context data is only attached for `OutputType::External`, and `presumed_origin` is attacker-controlled (parsed from `tx.input[0]`), so an attacker fully controls the provenance metadata of these internally-typed outputs [7](#0-6) .

### Impact Explanation
Privilege analog: a random chain user — with no Serai credential — can inject outputs that the processor treats as protocol-internal `Branch`/`Change`/`Forwarded` UTXOs. These outputs are spendable by the multisig (offset keys are derivable), so they enter the internal UTXO pool and can be selected as inputs/change in processor-constructed transactions, corrupting fund accounting: attacker funds get accounted as internal change/branch liquidity (or internal flows get conflated with dust-sized attacker deposits). This is "funds reported received" under a classification the depositor had no authority to assert — the same shape as a `view-profile` user modifying account resources.

### Likelihood Explanation
Trivially reachable: the attacker only needs the public multisig key and the public `KEY_DST`/labels to compute the P2TR script for any internal offset, then sends an ordinary Bitcoin transaction paying to it. `scan_transaction` runs on every transaction in every scanned block and performs no authorization check.

### Recommendation
When classifying scanned outputs, bind the output to its intended use: e.g., only accept `Change`/`Branch`/`Forwarded` outputs appearing in transactions the processor itself constructed (check `tx.compute_txid()`/`OutPoint` against a record of internally broadcast transactions), or require a protocol-bound data commitment in the transaction before assigning a non-`External` `OutputType`. At minimum, treat unattributed deposits to internal offset addresses as `External` (or ignore them) rather than honoring the internal classification.

### Proof of Concept
1. Learn the multisig's group key `K` (public).
2. Compute `offset = hash_to_F(b"Serai Bitcoin Output Offset", b"change")`, then `P2TR(K + offset*G)` — exactly what `register_offset`/`scanner()` compute [8](#0-7) .
3. Broadcast any Bitcoin transaction with an output to that script.
4. `get_outputs` scans the block, `scan_transaction` matches the `script_pubkey`, and `kinds[offset_repr]` yields `OutputType::Change` [9](#0-8) . The attacker-created output is now recorded as protocol change — an internal classification an external party was never authorized to produce.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
