### Title
`ThresholdKeys::read` accepts inconsistent verification metadata, allowing restored keys to advertise an unspendable group key - ([File: crypto/dkg/src/lib.rs](crypto/dkg/src/lib.rs))

### Summary
`ThresholdKeys::read` deserializes a secret share and all participant verification shares from attacker-controlled bytes, then constructs a `ThresholdKeys` object without checking that the supplied secret share corresponds to the verification share for `params.i()` [1](#0-0) . `ThresholdKeys::new` validates only participant counts, participant bounds, and the interpolation mode before deriving `group_key` from the attacker-supplied verification shares [2](#0-1) .

### Finding Description
The serialized format stores the local `secret_share` and the verification metadata in the same unauthenticated object [3](#0-2) . During deserialization, every field is syntactically parsed and passed to `ThresholdKeys::new`, but no equation such as `verification_shares[i] == G * secret_share` is enforced [4](#0-3) .

Because `group_key` is derived solely from the first `t` attacker-controlled `verification_shares`, the restored object can advertise a group key that does not correspond to the retained secret share [5](#0-4) . A subsequent `view` similarly combines the serialized secret share with the tampered verification metadata [6](#0-5) .

The FROST completion path recognizes this state as possible only through deserializing semantically invalid keys: all shares can verify against the supplied metadata while the final signature still fails for the advertised group key [7](#0-6) .

### Impact Explanation
An attacker who can supply or alter a serialized `ThresholdKeys` object can cause the caller to advertise and receive funds to a group key that the supplied secret share cannot control [5](#0-4) . This is a loss-of-funds condition: the output appears to belong to the advertised key, while signing cannot produce a valid signature because the secret share and verification metadata are inconsistent [8](#0-7) .

The same weakness can break signing recovery and cause the signing protocol to reach its internal inconsistent-key error rather than rejecting the malformed key material at restore time [9](#0-8) .

### Likelihood Explanation
The attacker only needs to control bytes passed to the explicitly public `ThresholdKeys::read` deserialization API [10](#0-9) . No private key, threshold collusion, or invalid curve encoding is required: all malformed points and scalars can remain canonical while the object is semantically inconsistent [11](#0-10) .

For the simplest demonstration, a `t = 1, n = 1, i = 1` object can contain secret share `1` and verification share `2G`; deserialization succeeds and reports group key `2G`, even though `secret_share * G = G` [12](#0-11) .

### Recommendation
`ThresholdKeys::new` should reject a secret share that does not satisfy `verification_shares[params.i()] == C::generator() * secret_share` [13](#0-12) . `ThresholdKeys::read` should not return an object until this semantic validation succeeds [4](#0-3) .

If serialized key material may cross an untrusted boundary, it should also be protected by an external authenticity mechanism; consistency checking prevents malformed state, but cannot establish that attacker-generated key material was the intended backup [9](#0-8) .

### Proof of Concept
Conceptually, serialize a Ristretto `ThresholdKeys` payload with the following fields:

```rust
curve_id        = Ristretto::ID
t               = 1
n               = 1
i               = 1
interpolation   = Lagrange
secret_share    = 1
verification_1  = 2 * G
```

`ThresholdKeys::<Ristretto>::read` accepts this payload because it checks only syntax, parameter bounds, and metadata shape [14](#0-13) . The resulting object reports `group_key() == 2G`, while `secret_share() == 1`, so a signature produced under that secret cannot verify for `2G` [15](#0-14) . During completion, the final signature check fails and the implementation explicitly attributes the remaining case to semantically invalid deserialized keys [7](#0-6) .
