### Title
Payout OP_RETURN operator-attribution is unauthenticated under `SinglePlusAnyoneCanPay`, letting anyone malleate the honest operator's payout tx to permanently orphan and burn their collateral - (File: core/src/verifier.rs)

### Summary
`Operator::withdraw` builds the payout transaction's user-signature check (`SECP.verify_schnorr`) over a `TapSighashType::SinglePlusAnyoneCanPay` sighash that only commits to input 0 and output 0; it never covers output 2 (the OP_RETURN carrying the operator's x-only pubkey) [1](#0-0) [2](#0-1) . Because SIGHASH_SINGLE|ANYONECANPAY does not commit to any output beyond the matching index, anyone who observes the honest operator's broadcast/mempool transaction can reuse the exact same witness on input 0 and construct a conflicting transaction that keeps output 0 (the user payout) but replaces the OP_RETURN with a 32-byte value that parses syntactically but fails `XOnlyPublicKey::from_slice`. If this variant gets mined instead, `Verifier::update_finalized_payouts` permanently records `payout_payer_operator_xonly_pk = NULL` for that withdrawal, and `Verifier::is_kickoff_malicious` treats every future kickoff by the true funding operator for that deposit as malicious, leading to Challenge/Disprove and collateral loss for an honest operator.

### Finding Description
The binding that must hold is: `payout_payer_operator_xonly_pk` for withdrawal `idx` == `Some(A)`, where A is the operator whose funds actually paid output 0 of the mined payout transaction. This binding is broken because the value is derived purely from parsing an OP_RETURN output that carries no cryptographic binding to the rest of the transaction under the sighash flag used.

- `create_payout_txhandler` builds outputs `[user payout, anchor, OP_RETURN(operator_xonly_pk)]` and signs only input 0 with the user's signature, whose sighash type is enforced to be `SinglePlusAnyoneCanPay` [3](#0-2) .
- `calculate_script_spend_sighash`/`calculate_sighash_txin` (used for key-spend as well) uses `Prevouts::One` for `*PlusAnyoneCanPay` sighash types [4](#0-3) , and Bitcoin consensus rules for `SIGHASH_SINGLE|ANYONECANPAY` commit only to the single input being signed and the output at the same index (output 0). Outputs 1 (anchor) and 2 (OP_RETURN) are entirely unauthenticated by this signature.
- `Verifier::update_finalized_payouts` finds whichever transaction actually spends the withdrawal UTXO in the finalized block via `get_payout_txs_for_withdrawal_utxos`, which joins on `bitcoin_syncer_spent_utxos` purely by outpoint, with no check that it is the operator's originally-intended transaction [5](#0-4) . It then extracts `operator_xonly_pk` by parsing the OP_RETURN and attempting `XOnlyPublicKey::from_slice`; on failure, it stores `NULL` [6](#0-5) .
- `Verifier::is_kickoff_malicious` treats a `NULL`/`None` `operator_xonly_pk_opt` as an unconditional malicious verdict, with no distinguishing of "optimistic payout" vs "attacker-malleated OP_RETURN" vs "honest operator whose OP_RETURN got overwritten" [7](#0-6) .

Exploit flow: honest operator A broadcasts the correctly-formed payout tx (input 0 = user's signed withdrawal UTXO, output 0 = user payout, output 2 = OP_RETURN with A's x-only pubkey). Because that transaction is public once it enters the mempool, any unprivileged attacker extracts input 0's witness (valid under ANYONECANPAY for any other input/output set) and constructs a new transaction that: reuses input 0's witness verbatim, reproduces output 0 exactly (so the withdrawal is still serviced and looks legitimate), and swaps the OP_RETURN payload for 32 bytes that fail `XOnlyPublicKey::from_slice` (e.g., all-zero, which is not a valid x-only field element under secp256k1). The attacker funds this variant with their own inputs/fee and gets it mined instead of (or in place of) A's original transaction — a standard double-spend/fee race enabled purely by the ANYONECANPAY signature's lack of commitment to non-index-0 outputs. Once finalized, A's `payout_payer_operator_xonly_pk` is permanently `None`, and any subsequent kickoff by A for that deposit is judged malicious forever.

No existing guard prevents this: `SECP.verify_schnorr` in `withdraw` only checks input 0/output 0 [1](#0-0) ; `is_kickoff_malicious` has no fallback path to recover attribution once `None` is recorded [8](#0-7) ; and the payout-tx identification (`get_payout_txs_for_withdrawal_utxos`) is purely outpoint-based with no consensus-level linkage to a specific operator's intended transaction [5](#0-4) .

### Impact Explanation
The attacker permanently prevents the true funding operator from being reimbursed and causes their collateral to be burned via the standard Challenge/Disprove flow (`is_kickoff_malicious` → `Ok(true)` forever for that deposit) [9](#0-8) , matching the Critical categories "an honest operator permanently unable to be reimbursed" and "an honest operator's collateral burned." This is repeatable against any operator, for any withdrawal, whenever the attacker can win a fee/propagation race against the honest operator's broadcast — no special role or key material is needed, only mempool visibility and the ability to broadcast a competing Bitcoin transaction.

### Likelihood Explanation
Preconditions are modest: a pending withdrawal with an honest operator's payout tx broadcast but not yet deeply confirmed. The attacker's cost is the fee needed to win a double-spend/propagation race (a few sats/vByte above the operator's fee, since the attacker's tx does not need to alter output 0). No RBF or protocol privilege is strictly required to attempt the race; success probability increases with mempool visibility and prevalence of full-RBF policy adoption among miners/nodes, both of which are realistic in current Bitcoin infrastructure. The attack is fully repeatable across every withdrawal handled by every operator, since the flaw is structural (missing coverage of output 2 by the signature) rather than tied to one deposit or operator.

### Recommendation
Extend the user's signature commitment to cover the OP_RETURN output identifying the operator, e.g., by switching to `SIGHASH_ALL` (or `AllPlusAnyoneCanPay`) for the payout input so all outputs are committed, or by having the *user* additionally co-sign/commit to the specific operator pubkey when registering the withdrawal on Citrea, so a malleated OP_RETURN cannot be substituted while keeping a valid signature. Additionally, treat a syntactically-invalid/missing operator pubkey OP_RETURN in `update_finalized_payouts` distinctly from "optimistic payout" so it does not automatically doom every future kickoff for that deposit to be judged malicious (e.g., allow a secondary attribution/dispute mechanism instead of an irrevocable `None`).

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

            "Input signature has wrong sighash type, SinglePlusAnyoneCanPay expected, got {}",

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_all)?;

        results
            .into_iter()
            .map(|(idx, txid)| {
                Ok((
                    u32::try_from(idx).wrap_err("Failed to convert withdrawal index to u32")?,
                    txid.0,
                ))
            })
            .collect()
    }

    /// Checks if the kickoff is malicious and sends the appropriate txs if it is.
    /// Returns true if the kickoff is malicious.
    /// Sends a challenge tx if the kickoff is first malicious one in the current round, and the network is not mainnet or testnet4.
    pub async fn handle_kickoff<'a>(
        &'a self,
        dbtx: DatabaseTransaction<'a>,
        kickoff_witness: Witness,
        mut deposit_data: DepositData,
        kickoff_data: KickoffData,
        challenged_before: bool,
    ) -> Result<bool, BridgeError> {
        let is_malicious = self
            .is_kickoff_malicious(kickoff_witness, &mut deposit_data, kickoff_data, dbtx)
            .await?;

        let deposit_outpoint = deposit_data.get_deposit_outpoint();

        let (_signed_txs, tx_metadata, challenge_tx) = self
            .get_signed_txs_for_kickoff(dbtx, kickoff_data, deposit_data)
            .await?;

        if is_malicious {
            tracing::warn!(
                "Malicious {} detected. {} Challenge tx: {} for deposit {}",
                kickoff_data,
                match challenged_before {
                    false => "This is the first malicious kickoff in the current round.",
                    true => "This is not the first malicious kickoff in the current round.",
                },
                bitcoin::consensus::encode::serialize_hex(&challenge_tx),
                deposit_outpoint
            );
            // do not automatically send challenge txs on mainnet or testnet4
            if !challenged_before
                && !matches!(
                    self.config.protocol_paramset().network,
                    bitcoin::Network::Bitcoin | bitcoin::Network::Testnet4
                )
            {
                #[cfg(feature = "automation")]
                self.tx_sender
                    .add_tx_to_queue(
                        dbtx,
                        TransactionType::Challenge,
                        &challenge_tx,
                        &[],
                        Some(tx_metadata),
                        self.config.protocol_paramset(),
                        None,
                    )
                    .await?;
            }
