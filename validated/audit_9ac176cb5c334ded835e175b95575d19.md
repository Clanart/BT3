### Title
Unauthenticated crash via FROST preprocess forcing the aggregated nonce to the point at infinity — (File: networks/bitcoin/src/crypto.rs)

### Summary
`bitcoin-serai`'s BIP-340 `Hram::hram` (and its helper `x()`) panics when the aggregated nonce point `R` is the point at infinity. A participant in a FROST signing session can feed crafted bytes to `read_preprocess`/`Commitments::read` — commitments that are canonical encodings of the identity element or otherwise chosen so the session's summed nonce `D + E·rho` equals identity. Every honest signer who calls `sign()` then dereferences `x(R)` on the identity point and panics (`expect("point at infinity")`), crashing the signing process. This is the Serai analog of CVE-2020-1763: untrusted protocol messages cause an out-of-bounds/invalid-state condition that crashes the daemon.

### Finding Description
In `crypto/frost/src/nonce.rs`, `Commitments::read` reads per-generator `(D, E)` commitment pairs via `read_G`, which only enforces canonical encoding — it does **not** reject the point at infinity (`crypto/ciphersuite/src/lib.rs:91-101`). There is no identity rejection anywhere in the preprocess path.

In `AlgorithmSignMachine::sign` (`crypto/frost/src/sign.rs:315-398`):
1. Each participant's preprocess is transcripted and binding factors `rho_l` are computed via `B.calculate_binding_factors(&rho_transcript)`.
2. `B.nonces(&nonces)` (nonce.rs:194-211) computes the aggregate nonce point as `Σ_l (D_l + E_l·rho_l)` per generator.

An attacker who contributes their preprocess last knows all honest preprocesses and can fully evaluate the `rho` transcript. For each nonce/generator index they compute `S = Σ_{l≠a}(D_l + E_l·rho_l)`, then set their own commitments to `E_a = identity` (canonical zero encoding) and `D_a = -S`. The resulting aggregate nonce `R` is the point at infinity.

`sign_share` for `bitcoin::crypto::Schnorr` delegates to `FrostSchnorr`, which calls `Hram::hram(&R, &A, msg)` (`networks/bitcoin/src/crypto.rs:59`). `hram` calls `x(R)` (crypto.rs:13-16), which executes `key.to_encoded_point(true)` then `.x().expect("point at infinity")` — a hard panic on identity `R`. The doc comment on `Hram` (crypto.rs:54) even states "this will panic," while the `Schnorr` doc (crypto.rs:78-80) incorrectly claims the probability is negligible "even with malicious participants present" — it is deterministic, not negligible.

### Impact Explanation
Every honest signer that processes the malicious preprocess panics inside `sign()` → `sign_share` → `Hram::hram` → `x()`. In Serai, these signers back Bitcoin multisig wallets; crashing them halts signing of withdrawal/spend transactions, a liveness/availability failure of the threshold-signing layer. The panic is in production (`std`) code reached by `SignatureMachine`/`SignMachine` APIs on attacker-supplied bytes — exactly the reachable surfaces allowed (untrusted bytes to `read_preprocess`/`Commitments::read`).

### Likelihood Explanation
Any participant included in a signing session can mount this. They need only choose their preprocess last (or retry preprocess selection) and compute the `rho` transcript locally — no private state is required. The malicious bytes are a syntactically valid, canonically encoded preprocess, so nothing in `read_preprocess`, `validate_map`, or `read_G` rejects it. One crafted preprocess deterministically crashes every co-signer.

### Recommendation
Reject non-prime-order/identity group elements when reading FROST commitments: in `Commitments`/`GeneratorCommitments::read` (`crypto/frost/src/nonce.rs:34-36`), return an `io::Error` if `D` or `E` `is_identity()`. Additionally, in `bitcoin-serai`'s `Hram`/`x()`, handle the identity point gracefully (e.g., make `hram` return a `Option`/`Result` or treat identity `R` per BIP-340 as verification failure) instead of `expect()`, since `R` is derived from untrusted preprocess data.

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
  }
