## Finding

The external "code-size limit" report is really about a hard cap being exceeded with a silent, destructive consequence (deployment becomes impossible). The concrete local analog is the hard-capped FIFO in `pallet-bandwidth`: pushing past the `MAX_SUBSCRIPTIONS = 1024` cap silently evicts the **oldest** entry regardless of its value, and the purchase path lets *any* unrelated caller target *any* victim's `(chain, app)` bucket for a trivial fee. This lets an attacker grief-evict a victim's already-paid bandwidth allowance — a real loss-of-funds primitive reachable by an unprivileged actor. [1](#0-0) [2](#0-1) 

### Title
Unbounded permissionless sponsorship lets an attacker grief-evict a victim's paid bandwidth subscriptions - (File: modules/pallets/bandwidth/src/lib.rs)

### Summary
`pallet-bandwidth`'s `push_subscription` enforces a hard 1024-entry FIFO cap per `(app_chain, app)` bucket. When the cap is hit, the **oldest** subscription is unconditionally evicted — no matter how much bandwidth or value it still holds — and the loss is only logged via `SubscriptionEvicted`, with no refund path. Any address can trigger a credit into *any* `(chain, app)` bucket by calling `BandwidthManager.purchase()` with an arbitrary `app`/`chain` pair (the "sponsorship" feature is intentionally unrestricted), and `pallet_bandwidth::Pallet::on_accept` performs no check that the purchaser is related to the app being credited — only that the message came from the registered `BandwidthManager` contract for the *source* chain. [3](#0-2) [4](#0-3) 

### Finding Description
`purchase()` on `BandwidthManager.sol` takes an arbitrary `app` and `chain` supplied by `msg.sender` with no relationship enforced to the caller's own identity — this is documented and intended, to allow a treasury to "sponsor" bandwidth for an app on another chain. [5](#0-4) 

On the pallet side, `on_accept` only validates that `request.from` matches the registered `BandwidthManager` for `request.source` — it never checks that the `msg.app` being credited belongs to, or was authorized by, the caller of `purchase()`. It then calls `push_subscription`, which appends unconditionally and, if the target bucket is already at the 1024 cap, evicts the single **oldest** entry (`list.remove(0)`), independent of that entry's `remaining_bytes` or `expires_at`. [6](#0-5) [7](#0-6) 

Because insertion order (FIFO), not remaining value, determines eviction order, an attacker can:
1. Identify a victim `(chain, app)` pair that already holds a valuable subscription (e.g. a large `TierFour`, long-duration purchase the victim paid real money for).
2. Repeatedly call `purchase()` targeting that exact `(chain, app)` with the cheapest configured tier (`TierOne`, `months = 1`), each time paying only `tierPrice[1]`.
3. After 1024 such cheap purchases, the victim's original subscription — being the oldest entry — is evicted (`SubscriptionEvicted`), and the bucket is now filled entirely with the attacker's worthless entries.

The "no mutation on insufficient" property documented for `try_consume` protects against races on *consumption*, but there is no analogous protection against griefing on the *credit* path — `push_subscription` has no owner/authorization check and no minimum-value protection for eviction candidates. [8](#0-7) 

This is the same "hard cap silently destroys already-committed state" bug shape as the seed report (contract exceeding the 24576-byte deployment cap), translated to a live protocol accounting structure: exceeding `MAX_SUBSCRIPTIONS` silently destroys previously paid-for state instead of merely failing a deployment.

### Impact Explanation
The victim app's already-paid bandwidth allowance (potentially a large, expensive, long-duration tier) can be forcibly and irrecoverably evicted by an unrelated, unprivileged attacker for the cost of `1024 × tierPrice[cheapest tier]`. There is no refund mechanism for evicted subscriptions — `lost_bytes` is only emitted for audit, not recovered. This is a direct loss-of-funds/loss-of-service vector against bandwidth-accounting balances, matching the "bandwidth balances must move exactly once and only to the rightful beneficiary" pivot: the victim's paid-for capacity is destroyed by a party with no claim to it.

### Likelihood Explanation
The attack requires no privileged role, no malicious relayer/prover, and no front-running — only calling the public, permissionless `BandwidthManager.purchase()` function 1024 times with a cheap tier, targeting a chosen `(chain, app)`. Cost scales linearly with the cheapest configured tier price and is bounded (not proportional to the value being destroyed), making it economically attractive whenever a high-value subscription exists for a target app.

### Recommendation
- Restrict `purchase()` sponsorship so that `app` must be `msg.sender` (or an explicitly authorized delegate) unless the transaction is flagged/verified as legitimate sponsorship (e.g., require an on-chain allowlist or signed authorization from the app being credited).
- Alternatively, keep sponsorship open but change eviction policy in `push_subscription` to protect subscriptions above a value/remaining-duration threshold, or track sponsor-vs-self-funded subscriptions separately so a griefer cannot cheaply push out high-value entries.
- Consider a per-`(chain, app)` rate limit or minimum-tier-price floor per unique payer to raise the cost of a griefing flood proportionally to the damage caused.

### Proof of Concept
1. Governance configures `TierOne` with a low price and `TierFour` with a high price/duration on `pallet-bandwidth` and the corresponding `BandwidthManager`.
2. Victim (legitimate app operator) calls `BandwidthManager.purchase(app=VICTIM_APP, tier=4, months=12, chain="EVM-8453")`, crediting a valuable, long subscription into `Allowance[EVM-8453][VICTIM_APP]` at index 0.
3. Attacker calls `BandwidthManager.purchase(app=VICTIM_APP, tier=1, months=1, chain="EVM-8453")` 1024 times (any `msg.sender`, since `app`/`chain` are attacker-controlled parameters, not tied to `msg.sender`).
4. Each purchase reaches `pallet_bandwidth::on_accept` → `push_subscription`, which appends to `Allowance::<T>::get(EVM-8453, VICTIM_APP)`; on the 1025th relevant push (attacker's 1024th purchase after the victim's own), the FIFO cap is hit and `list.remove(0)` evicts the victim's tier-4 subscription, firing `SubscriptionEvicted { lost_bytes: <victim's large allowance> }`.
5. The victim's bucket now holds 1024 near-worthless `TierOne` entries; the victim's paid bandwidth is unrecoverably gone, verifiable against the eviction test pattern already present in the test suite (`subscription_cap_evicts_oldest`), which confirms oldest-first eviction on cap regardless of value. 		/// Append a fresh subscription with a fixed expiry. If the list
		/// is already at `MaxSubscriptions`, evict the oldest entry and
		/// emit [`Event::SubscriptionEvicted`] so the lost bytes are
		/// auditable. Returns the new subscription's `expires_at`.
		fn push_subscription(
			app_chain: &StateMachine,
			app: &AppKey,
			tier: TierIndex,
			bytes: BandwidthBytes,
			duration_secs: u64,
		) -> u64 {
			let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();
			let expires_at = now.saturating_add(duration_secs);
			let new_sub =
				Subscription { tier, remaining_bytes: bytes, expires_at, purchased_at: now };

			let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
				let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
					Some(list.remove(0))
				} else {
					None
				};
				// Capacity is now guaranteed; try_push can't fail.
				let _ = list.try_push(new_sub);
				evicted
			});

			if let Some(old) = evicted {
				Self::deposit_event(Event::SubscriptionEvicted {
					app_chain: *app_chain,
					app: app.clone(),
					tier: old.tier,
					lost_bytes: old.remaining_bytes,
				});
			}

			expires_at
		}

	impl<T: Config> IsmpModule for Pallet<T> {
		fn on_accept(&self, request: PostRequest) -> Result<Weight, anyhow::Error> {
			let manager = BandwidthManager::<T>::get(&request.source).ok_or_else(|| {
				anyhow::anyhow!(format!("no bandwidth manager registered for {:?}", request.source))
			})?;

			if request.from != manager.0.to_vec() {
				return Err(anyhow::anyhow!(format!(
					"purchase from unauthorised sender on {:?}: expected {:x?}, got {:x?}",
					request.source, manager.0, request.from
				)));
			}

			let msg = PurchaseMessage::try_from(request.body.as_slice())?;
			let tier = TierIndex::try_from(msg.tier)
				.map_err(|_| anyhow::anyhow!(format!("unknown tier discriminant {}", msg.tier)))?;
			let cfg = Tiers::<T>::get(tier)
				.ok_or_else(|| anyhow::anyhow!(format!("tier {:?} is not configured", tier)))?;

			let bytes = cfg.bytes.saturating_mul(msg.months as u128);
			let duration = cfg.duration_secs.saturating_mul(msg.months as u64);

			let key = AppKey::truncate_from(msg.app);
			let expires_at = Self::push_subscription(&msg.chain, &key, tier, bytes, duration);

			Self::deposit_event(Event::BandwidthCredited {
				app_chain: msg.chain,
				app: key,
				paid_from: request.source,
				tier,
				bytes,
				expires_at,
			});

			Ok(Weight::zero())
		}

impl<T: Config> BandwidthGate for Pallet<T> {
	fn try_consume(
		source: &ismp::host::StateMachine,
		app: &[u8],
		bytes: u32,
	) -> Result<(), GateError> {
		let key = AppKey::truncate_from(app.to_vec());
		if Allowlist::<T>::contains_key(source, &key) {
			return Ok(());
		}

		let need: u128 = bytes.into();
		let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();

		let total = pallet::Allowance::<T>::mutate(source, &key, |list| {
			// Sweep expired in-place. Order-preserving.
			list.retain(|s| s.expires_at > now);

			if list.is_empty() {
				return Err(GateError::NoAllowance);
			}

			let total: u128 = list.iter().map(|s| s.remaining_bytes).sum();
			if total < need {
				return Err(GateError::Insufficient { remaining: total, required: need });
			}

			// Drain from the front in insertion order. Once a sub is
			// fully consumed, pop it and continue with the next.
			// `get_mut` defends against a malformed list that satisfies
			// the `total >= need` precheck but is structurally empty;
			// we'd otherwise panic via `list[0]`.
			let mut left = need;
			while left > 0 {
				let Some(head) = list.get_mut(0) else {
					return Err(GateError::NoAllowance);
				};
				let take = head.remaining_bytes.min(left);
				head.remaining_bytes = head.remaining_bytes.saturating_sub(take);
				left = left.saturating_sub(take);
				if head.remaining_bytes == 0 {
					list.remove(0);
				}
			}

			Ok(total)
		})?;

    function purchase(bytes calldata app, uint256 tier, uint256 months, bytes calldata chain)
        external
        returns (bytes32 commitment)
    {
        if (app.length == 0 || chain.length == 0 || months == 0) revert InvalidPurchase();
        uint256 price18d = tierPrice[tier];
        if (price18d == 0) revert UnknownTier();

        uint256 total18d = price18d * months;
        address feeToken = IDispatcher(_host).feeToken();
        uint8 dec = IERC20Metadata(feeToken).decimals();
        uint256 scale = 10 ** (18 - dec);
        if (total18d % scale != 0) revert PriceNotRepresentable();
        uint256 amount = total18d / scale;

        IERC20(feeToken).safeTransferFrom(msg.sender, address(this), amount);

        BandwidthPurchaseMsg memory body = BandwidthPurchaseMsg({
            app: app,
            tier: tier,
            months: months,
            chain: chain
        });

        commitment = IDispatcher(_host).dispatch(
            DispatchPost({
                dest: IDispatcher(_host).hyperbridge(),
                to: PALLET_BANDWIDTH_MODULE_ID,
                body: abi.encode(body),
                timeout: 0,
                fee: 0,
                payer: address(this)
            })
        );

/// The 1024-sub cap evicts the oldest entry. force_credit reuses the
/// same push path as purchase, so this also covers the purchase cap.
#[test]
fn subscription_cap_evicts_oldest() {
	new_test_ext().execute_with(|| {
		jump_to(T0);
		let cap = MAX_SUBSCRIPTIONS as u128;

		// Fill the list to exactly the cap. `bytes` encodes the index
		// so we can prove which one got evicted.
		for i in 0..cap {
			Bandwidth::force_credit(
				RuntimeOrigin::root(),
				ForceCreditParams {
					app_chain: APP_CHAIN,
					app: app_key(),
					tier: TIER1,
					bytes: i + 1,
					duration_secs: MONTH_SECS,
				},
			)
			.unwrap();
		}
		assert_eq!(sub_count(APP_CHAIN), cap as usize);
		assert_eq!(sub_at(APP_CHAIN, 0).unwrap().remaining_bytes, 1, "oldest is index 1");

		// One more push: evicts the oldest, appends the new one.
		Bandwidth::force_credit(
			RuntimeOrigin::root(),
			ForceCreditParams {
				app_chain: APP_CHAIN,
				app: app_key(),
				tier: TIER1,
				bytes: cap + 1,
				duration_secs: MONTH_SECS,
			},
		)
		.unwrap();

		assert_eq!(sub_count(APP_CHAIN), cap as usize, "still capped");
		assert_eq!(
			sub_at(APP_CHAIN, 0).unwrap().remaining_bytes,
			2,
			"former second-oldest is now front",
		);
		assert_eq!(
			sub_at(APP_CHAIN, (cap - 1) as usize).unwrap().remaining_bytes,
			cap + 1,
			"new sub is at the back",
		);
	});
}
