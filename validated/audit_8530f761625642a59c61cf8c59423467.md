## Finding: Credential-helper trusts spoofed `WWW-Authenticate` header to trigger GitHub sign-in against an attacker-controlled endpoint

### Title
Spoofed `WWW-Authenticate` realm from a git remote/proxy triggers GitHub sign-in flow against an attacker-controlled endpoint - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
GitHub Desktop's git credential helper trampoline classifies a remote host as a GitHub endpoint (`'enterprise'`) based on an unauthenticated `WWW-Authenticate` header value forwarded by git, without any verification against the real GitHub API. If no account is stored for that host, Desktop automatically opens its GitHub/Enterprise sign-in flow pointed at the attacker's URL.

### Finding Description
`getEndpointKind` is used by the trampoline credential helper (invoked by git itself during clone/fetch/push) to decide how to treat a host asking for credentials: [1](#0-0) 

Git forwards any `WWW-Authenticate` response headers it receives from the remote server as `wwwauth[]` credential-protocol fields. `getEndpointKind` treats a header containing `realm="GitHub"` as sufficient evidence that the host is a GitHub Enterprise server — this is explicitly documented as a "happy path... without having to resort to making a request ourselves." This bypasses the actual verification path, `isGitHubHost(endpoint)`, which is only reached as a fallback.

The classification directly drives `getCredential`: [2](#0-1) 

When `endpointKind !== 'generic'` and no stored account matches the endpoint, Desktop calls `ui.promptForGitHubSignIn(endpoint)` with `endpoint` derived directly from the credential URL supplied by git for the (attacker-controlled) remote — i.e., a value the attacker fully controls via the git server's URL/host and the spoofed header. `getCredentialUrl` builds this URL straight from the `host`/`protocol`/`path` fields git handed it: [3](#0-2) 

There is no check that the header actually originated from `github.com`/a genuine GHE instance before it is used to decide "prompt the user to sign in to this endpoint."

### Impact Explanation
This breaks the invariant that GitHub Desktop only initiates its trusted GitHub/GHE sign-in (OAuth/device flow) against endpoints it has verified as genuine GitHub hosts. An attacker who controls a git remote (or a network proxy/MITM in front of an HTTP git server the user is fetching/cloning from) can add a single response header (`WWW-Authenticate: Basic realm="GitHub"`) to force Desktop to treat their arbitrary server as an "enterprise" GitHub endpoint and surface a native "Sign in to GitHub Enterprise" prompt whose target endpoint is the attacker's own server. Because the prompt is presented by Desktop itself (not a browser popup from the remote), the origin-based trust cues a user would normally rely on are absent, enabling credential/OAuth-token phishing or capture of an authorization code intended for a legitimate GHE tenant.

### Likelihood Explanation
The attacker only needs to control (or proxy) the git remote the user is fetching/cloning/pushing to — no local access, no prior malware, no leaked credentials, and no unusual user action beyond a normal git operation against an attacker-supplied remote/proxy response, which matches the "attacker controls a git remote/proxy response" impact class. The header-based shortcut is explicitly implemented as an optimization to avoid a network round-trip, so it is reached on every credential request before the safer `isGitHubHost` check is attempted.

### Recommendation
Do not trust the `wwwauth[]` `realm="GitHub"` heuristic to short-circuit endpoint classification for hosts Desktop doesn't already recognize as `github.com`/an enrolled GHE endpoint. Always fall back to `isGitHubHost(endpoint)` (an actual verification request) before offering the built-in GitHub sign-in UI, or at minimum require that verification for any endpoint not already present in `AccountsStore`.

### Proof of Concept
1. Attacker sets up an HTTP git server (or MITM proxy in front of any HTTP git remote) at `https://attacker.example.com/victim/repo.git`.
2. Victim adds/uses this as a remote in GitHub Desktop and performs a fetch/clone.
3. On the initial unauthenticated request, the attacker's server responds `401` with header `WWW-Authenticate: Basic realm="GitHub"`.
4. Git forwards this as `wwwauth[0]=Basic realm="GitHub"` to Desktop's credential helper (`createCredentialHelperTrampolineHandler` → `getCredential` → `getEndpointKind`), which returns `'enterprise'` based solely on that string match: [4](#0-3) 
5. Since no account exists for `attacker.example.com`, Desktop calls `ui.promptForGitHubSignIn('https://attacker.example.com/...')`, presenting the user with a native "Sign in to GitHub Enterprise" flow that targets the attacker's server instead of a genuine GHE instance. [5](#0-4) 

Note: I was not able to inspect `trampoline-ui-helper.ts`/`promptForGitHubSignIn`'s exact OAuth implementation within the remaining tool budget, so the precise downstream mechanics of what gets sent to the attacker's endpoint (device code vs. full OAuth authorize redirect) are unverified — this would need to be confirmed to fully quantify what is exfiltrated.

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

export const getCredentialUrl = (cred: Map<string, string>) => {
  const u = cred.get('url')
  if (u) {
    return new URL(u)
  }

  const protocol = cred.get('protocol') ?? ''
  const username = cred.get('username')
  const user = username ? `${encodeURIComponent(username)}@` : ''
  const host = cred.get('host') ?? ''
  const path = cred.get('path') ?? ''

  return new URL(`${protocol}://${user}${host}/${path}`)
}
