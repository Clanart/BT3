### Title
`debug_redact` Sensitive-Field Protection Is Not Enforced by ProtoJSON Serialization (`MessageToJsonString`/`MessageToJsonStream`) - ([File: src/google/protobuf/json/internal/unparser.cc])

### Summary
Protobuf implements a field-level redaction mechanism (`FieldOptions.debug_redact`) intended to prevent sensitive values (passwords, tokens, PII) from being disclosed when a message is serialized for diagnostic/debugging purposes. This mechanism is fully implemented for `TextFormat`/`DebugString` in C++ and Java, but the ProtoJSON serializer (`google::protobuf::json::MessageToJsonString`/`MessageToJsonStream`, backed by `json/internal/unparser.cc`) contains no equivalent check. A field annotated `debug_redact = true` is masked when printed via `DebugString()`/`TextFormat::Printer`, but is emitted in full, plaintext form when the identical message is serialized to JSON via the public `MessageToJsonString` API. This mirrors the ESPHome analog: one serialization surface (`state`) correctly masks a sensitive value while a parallel surface (`value`) sharing the same underlying data unconditionally discloses it.

### Finding Description
The redaction invariant is defined on `FieldOptions.debug_redact` and enforced only inside the TextFormat printer path:
- C++: `TextFormat::Printer::TryRedactFieldValue` computes `TextFormat::GetRedactionState(field)` and substitutes `[REDACTED]` when `redact_debug_string_` is set. [1](#0-0) 
- The redaction state derivation (`TextFormat::GetRedactionState`/`IsOptionSensitive`) walks `debug_redact` on the field and on nested/enum options. [2](#0-1) 
- Java has the identical mechanism in `TextFormat.Printer.shouldRedact` / `FieldDescriptor.getRedactionState`, gated by `enablingSafeDebugFormat`. [3](#0-2) [4](#0-3) 

By contrast, the ProtoJSON writer path — the code that backs the public `google::protobuf::json::MessageToJsonString`/`MessageToJsonStream` API (also aliased into `google::protobuf::util::MessageToJsonString`) — walks fields and writes their values with no reference to `debug_redact`, `RedactionState`, or any sensitivity check anywhere in the file: [5](#0-4) [6](#0-5) [7](#0-6) 

A repo-wide search confirms `debug_redact` is referenced only in descriptor/options plumbing, `command_line_interface.cc`, unit tests, and the two `TextFormat` implementations (C++ and Java) — it does not appear in `json/internal/unparser.cc`, `upb/json/encode.c` (upb's JSON encoder used by PHP/Python/Ruby bindings), or the PHP `jsonenc_fieldval`/`jsonenc_msgfields` functions, all of which unconditionally serialize field values. This shows the gap is structural and spans multiple language runtimes (C++ core, upb-based PHP), not a single accidental oversight in one file. [8](#0-7) [9](#0-8) 

**Failed invariant:** "Fields marked `debug_redact = true` must never appear in plaintext in any diagnostic/serialization output derived from the message." **Attacker-controlled value:** none needed from an attacker — the disclosure is triggered purely by the consuming application calling the trusted, documented `MessageToJsonString` API on a message that contains a field the *schema author* explicitly marked sensitive via `debug_redact = true`, expecting it to be protected the same way it is in `DebugString()`. **Missing check:** `WriteFields`/`WriteSingular`/`jsonenc_fieldval` never queries `FieldOptions.debug_redact()` before emitting the field value. **Impact:** any application that logs, exposes via API, or otherwise treats `MessageToJsonString` output the same way it treats `DebugString` output (a reasonable and common assumption, since both are advertised as "diagnostic" serializations for the same message and options struct) will leak sensitive values that the schema explicitly tried to protect.

### Impact Explanation
This is a genuine confidentiality violation (matches CVSS vector C:H/I:N/A:N from the analog): a value the message author designated as sensitive is disclosed through a supported, documented serialization API. It is not a memory-safety or crash bug — it is a silent policy bypass, directly analogous to ESPHome's `WebServer::text_json_` writing the raw password into `value` while masking `state`. The severity is capped at Medium (not High/Critical) because: (1) there is no memory corruption or RCE; (2) `debug_redact` was never formally specified as a promise for the ProtoJSON encoder — its documented contract is scoped to "debug formats" (`TextFormat`/`DebugString`), so this is a documentation/consistency gap rather than a violated hard security guarantee; (3) exploitation requires the consuming application to actually call `MessageToJsonString` on a message containing a `debug_redact` field and expose that output, which is an application-level assumption, not something Protobuf's parse APIs do automatically.

### Likelihood Explanation
Likelihood is Medium-High for consuming applications. `debug_redact` fields are, by definition, high-value secrets (the field option comment explicitly states "e.g. when the field contains sensitive credentials"), and `MessageToJsonString`/`util::MessageToJsonString` is a routine, widely-used serialization path (logging, HTTP APIs, gRPC-JSON transcoding). Developers who apply `debug_redact` to a field reasonably assume it is redacted across *all* protobuf-provided "diagnostic" serializers, given that `TextFormat`'s own documentation and the field's own doc comment ("should not be printed out when using debug formats") do not scope the protection to TextFormat specifically. No special attacker capability is needed; the trigger is simply calling the public JSON serializer.

### Recommendation
1. Add a redaction check in `json/internal/unparser.cc`'s field-writing logic (`WriteFields`/`WriteSingular`) that inspects `field->options().debug_redact()` (mirroring `TextFormat::GetRedactionState`) and substitutes a redacted placeholder or omits/errors when a `JsonPrintOptions`-equivalent "safe debug" mode is requested — or, at minimum, document clearly and loudly that `MessageToJsonString` does **not** honor `debug_redact` and must never be used for logging/debugging of messages containing sensitive fields.
2. Apply the same fix to `upb/json/encode.c` and the PHP/Python/Ruby JSON encoders derived from upb, since they share the same gap.
3. Add regression tests in `json_test.cc` analogous to `TextFormatTest.ShortFormat`/`Utf8Format` (which validate `RedactedFields`/`TestNestedMessageRedaction` proto messages) to assert that ProtoJSON output either matches TextFormat's redaction behavior in a "safe" print mode or that the non-redaction is explicitly and permanently documented as a known limitation.

This is inferred from static code inspection of the checked-out source; I recommend running this exact snippet against the built library to confirm the plaintext leak empirically.

TextFormat::RedactionState TextFormat::GetRedactionState(
    const FieldDescriptor* field) {
  auto options = field->options();
  auto state = TextFormat::RedactionState{options.debug_redact(), false};
  std::vector<const FieldDescriptor*> field_options;
  const Reflection* reflection = options.GetReflection();
  reflection->ListFields(options, &field_options);
  for (const FieldDescriptor* option : field_options) {
    auto result = TextFormat::IsOptionSensitive(options, reflection, option);
    state = TextFormat::RedactionState{state.redact || result.redact,
                                       state.report || result.report};
  }
  return state;
}

bool TextFormat::Printer::TryRedactFieldValue(
    const Message& message, const FieldDescriptor* field,
    BaseTextGenerator* generator, bool insert_value_separator) const {
  TextFormat::RedactionState redaction_state =
      DescriptorPool::MemoizeProjection(
          field, [](const FieldDescriptor* field) {
            return TextFormat::GetRedactionState(field);
          });
  if (redaction_state.redact) {
    if (redact_debug_string_) {
      IncrementRedactedFieldCounter();
      if (insert_value_separator) {
        generator->PrintMaybeWithMarker(MarkerToken(), ": ");
      }
      generator->PrintString(kFieldValueReplacement);
      if (insert_value_separator) {
        if (single_line_mode_) {
          generator->PrintLiteral(" ");
        } else {
          generator->PrintLiteral("\n");
        }
      }
      return true;
    }
  }
  return false;
}

    RedactionState getRedactionState() {
      RedactionState state = redactionState;
      if (state == null) {
        // If the field is directly marked with debug_redact=true, then it is sensitive.
        synchronized (this) {
          state = redactionState;
          if (state == null) {
            FieldOptions options = getOptions();
            state = RedactionState.of(options.getDebugRedact());
            // Check if the FieldOptions contain any enums that are marked as debug_redact=true,
            // either directly or indirectly via a message option.
            for (Map.Entry<Descriptors.FieldDescriptor, Object> entry :
                options.getAllFields().entrySet()) {
              state =

                      state, isOptionSensitive(entry.getKey(), entry.getValue()));
              if (state.redact) {
                break;
              }
            }
            redactionState = state;
          }
        }
      }

template <typename Traits>
absl::Status WriteMessage(JsonWriter& writer, const Msg<Traits>& msg,
                          const Desc<Traits>& desc, bool is_top_level) {
  switch (ClassifyMessage(Traits::TypeName(desc))) {
    case MessageType::kAny:
      return WriteAny<Traits>(writer, msg, desc);
    case MessageType::kWrapper: {
      auto field = Traits::MustHaveField(desc, 1);
      if (Traits::GetSize(field, msg) == 0) {
        return WriteSingular<Traits>(writer, field);
      }
      return WriteSingular<Traits>(writer, field, msg);
    }
    case MessageType::kValue:
      return WriteValue<Traits>(writer, msg, desc, is_top_level);
    case MessageType::kStruct:
      return WriteStructValue<Traits>(writer, msg, desc);
    case MessageType::kList:
      return WriteListValue<Traits>(writer, msg, desc);
    case MessageType::kTimestamp:
      return WriteTimestamp<Traits>(writer, msg, desc);
    case MessageType::kDuration:
      return WriteDuration<Traits>(writer, msg, desc);
    case MessageType::kFieldMask:
      return WriteFieldMask<Traits>(writer, msg, desc);
    default: {
      writer.Write("{");
      writer.Push();
      bool first = true;
      RETURN_IF_ERROR(WriteFields<Traits>(writer, msg, desc, first));
      writer.Pop();
      if (!first) {
        writer.NewLine();
      }
      writer.Write("}");
      return absl::OkStatus();
    }
  }
}

static void jsonenc_fieldval(jsonenc* e, const upb_FieldDef* f,
                             upb_MessageValue val, bool* first) {
  const char* name;

  jsonenc_putsep(e, ",", first);

  if (upb_FieldDef_IsExtension(f)) {
    // TODO: For MessageSet, I would have expected this to print the message
    // name here, but Python doesn't appear to do this. We should do more
    // research here about what various implementations do.
    jsonenc_printf(e, "\"[%s]\":", upb_FieldDef_FullName(f));
  } else {
    if (e->options & upb_JsonEncode_UseProtoNames) {
      name = upb_FieldDef_Name(f);
    } else {
      name = upb_FieldDef_JsonName(f);
    }
    jsonenc_printf(e, "\"%s\":", name);
  }

  if (upb_FieldDef_IsMap(f)) {
    jsonenc_map(e, val.map_val, f);
  } else if (upb_FieldDef_IsRepeated(f)) {
    jsonenc_array(e, val.array_val, f);
  } else {
    jsonenc_scalar(e, val, f);
  }
}

static void jsonenc_msgfields(jsonenc* e, const upb_Message* msg,
                              const upb_MessageDef* m, bool first) {
  upb_MessageValue val;
  const upb_FieldDef* f;

  if (e->options & upb_JsonEncode_EmitDefaults) {
    /* Iterate over all fields. */
    int i = 0;
    int n = upb_MessageDef_FieldCount(m);
    for (i = 0; i < n; i++) {
      f = upb_MessageDef_Field(m, i);
      if (!upb_FieldDef_HasPresence(f) || upb_Message_HasFieldByDef(msg, f)) {
        jsonenc_fieldval(e, f, upb_Message_GetFieldByDef(msg, f), &first);
      }
    }
  } else {
    /* Iterate over non-empty fields. */
    size_t iter = kUpb_Message_Begin;
    while (upb_Message_Next(msg, m, e->ext_pool, &f, &val, &iter)) {
      jsonenc_fieldval(e, f, val, &first);
    }
  }
}
