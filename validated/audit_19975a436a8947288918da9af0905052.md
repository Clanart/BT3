### Title
Unauthenticated third party can spend a withdrawal UTXO with an OP_RETURN-less clone, permanently blacklisting the honest operator via `is_kickoff_malicious` - (File: core/src/verifier.rs)

### Summary
Because the withdrawer's payout signature uses `SinglePlusAnyoneCanPay`, it only commits to input 0 and output 0; anyone who observes the outpoint, signature, and payout output (all public once the operator calls `withdraw`, or even derivable from the Citrea `withdraw` call parameters) can construct their own transaction spending the same outpoint to the same output 0, omitting the operator's OP_RETURN and adding their own inputs/fees. If this clone confirms first, `update_finalized_payouts` records it as the canonical payout with `operator_xonly_pk = None`, and `Verifier::is_kickoff_malicious` unconditionally treats the operator's later, real kickoff as malicious.

### Finding Description
The claimed binding is: `withdrawals.payout_payer_operator_xonly_pk` for withdrawal `i` == the operator that funded `output 0` with the withdrawal amount from its own collateral. This binding is broken because the value is derived from whichever transaction is first observed spending `withdrawal_utxo_txid:vout`, not from a signature over which entity is entitled to a reimbursement claim.

Path:
1. `update_finalized_payouts` in `core/src/verifier.rs:2283-2353` finds all txids that spent tracked `withdrawal_utxo` outpoints in a block via `get_payout_txs_for_withdrawal_utxos` (`core/src/database/verifier.rs:170-196`), which is a pure SQL join on `bitcoin_syncer_spent_utxos.txid/vout`. Any transaction confirming on Bitcoin that consumes that outpoint is recorded there via `save_transaction_spent_utxos`/`insert_spent_utxo` (`core/src/bitcoin_syncer.rs:143-164`), with no check of who created it or whether it originated from an operator's `withdraw` RPC call.
2. `update_finalized_payouts` parses the first OP_RETURN output of *that* transaction to extract `operator_xonly_pk`; if missing or invalid, it stores `NULL`/`None` (`core/src/verifier.rs:2312-2328`).
3. Later, `Verifier::is_kickoff_malicious` (`core/src/verifier.rs:1859-1915`) looks up payout info by `move_txid` and, on the `None` branch of `operator_xonly_pk_opt`, unconditionally returns `Ok(true)` ("assuming malicious"), with no fallback check against `kickoff_data.operator_xonly_pk` or the actual output-0 recipient.
4. `create_payout_txhandler` (`core/src/builder/transaction/operator_reimburse.rs:407-436`) signs the payout input with `SpendPath::KeySpend` using the withdrawer-provided `user_sig` over a sighash computed with `TapSighashType::SinglePlusAnyoneCanPay`, which is enforced at the RPC layer (`parse_withdrawal_sig_params`, `core/src/rpc/parser/operator.rs:174-187`). By BIP-341 semantics, `SIGHASH_SINGLE | ANYONECANPAY` only commits input 0 and output 0 of the actual signed message; it does **not** constrain the total number of transaction outputs, other outputs, other inputs, locktime interactions across inputs, or transaction version beyond what's needed to reconstruct the corresponding output-0/input-0 pair. An attacker who obtains `(input_outpoint, in_signature, output_script_pubkey, output_amount)` — visible in the aggregator/operator `withdraw` gRPC request, or derivable by simply calling `withdraw` on the Citrea Bridge contract themselves per the standard withdrawal flow — can build a 2-output transaction (payout + anchor, no OP_RETURN), fund it themselves, and race-broadcast/mine it ahead of the honest operator's real `Payout` transaction.
5. Since the attacker's transaction is a valid alternative spend of the exact same outpoint, once it confirms it becomes the *only* possible spend of that outpoint (Bitcoin double-spend rules) — the honest operator's real payout can never confirm afterward. The withdrawal is now recorded with `operator_xonly_pk = None` permanently. Any operator who later attempts to front the withdrawal via a kickoff for this deposit (e.g., because they had already broadcast, or later attempt to prepare a new payout for a still-un-fronted deposit) is judged malicious unconditionally.

No existing guard intercepts this: `Verifier::is_deposit_valid` and `verify_storage_proofs` validate the deposit/withdrawal indices on the Citrea side, not the shape of the Bitcoin-side spend of the payout UTXO; `SECP.verify_schnorr` in `Operator::withdraw` (`core/src/operator.rs:630-637`) only checks the signature is valid for the operator's own payout tx before broadcasting, it doesn't prevent someone else from broadcasting a competing valid spend first; and `is_kickoff_malicious`'s `None` branch treats "attacker griefed the OP_RETURN away" identically to "operator genuinely built a malformed payout," with no distinction and no way to recover.

### Impact Explanation
An operator that legitimately intends to front a withdrawal (or one that already fronted a competing kickoff attempt) can have its 10 BTC-class collateral become permanently unreimbursable/challengeable, satisfying "an honest operator permanently unable to be reimbursed" / "an honest operator's collateral burned." Because the withdrawal UTXO is fully consumed by the attacker's transaction, no operator can ever complete this withdrawal's real payout, and any subsequent kickoff tied to this `move_txid` is deterministically flagged malicious and challenged. This is repeatable per withdrawal at negligible cost (only fees for the attacker's own transaction, no bridge value or collateral required), and does not require compromising any privileged role.

### Likelihood Explanation
The attacker only needs: (a) knowledge of a pending withdrawal's `input_outpoint`, `in_signature`, `output_script_pubkey`, `output_amount` — obtainable either by calling `withdraw` on the Citrea bridge contract themselves as an ordinary user (they possess their own withdrawal signature) or by observing operator/aggregator's public `withdraw` gRPC traffic, and (b) the ability to broadcast a standard Bitcoin transaction with sufficient fees to be mined ahead of the honest payout. No verifier/operator/aggregator privilege, no key compromise, and no majority hashrate are needed — only being marginally faster/cheaper in fee-bidding for a single transaction. This is fully within the described unprivileged attacker capabilities and reproducible on regtest without mainnet or live Citrea.

### Recommendation
Do not rely solely on "spends the withdrawal outpoint" to identify the payout transaction. Options: (1) require the payout transaction to be shaped/validated (e.g., recompute the expected `Payout` transaction via `create_payout_txhandler` for every currently-known operator and compare full txid/structure, rather than trusting whatever transaction the syncer observed spending the outpoint) before writing to `withdrawals.payout_txid`; (2) in `is_kickoff_malicious`'s `None` branch, before declaring malicious, verify whether the transaction that actually spent the outpoint matches the kickoff's claimed operator by structure (output-0 recipient, no attacker OP_RETURN stripping) and distinguish "no operator info because payout is optimistic" (a known/expected None case) from "OP_RETURN unexpectedly missing/malformed"; (3) at minimum, don't automatically challenge/blacklist kickoffs whose payout was recorded with `None` operator pk unless corroborated by other evidence that the *kickoff's* operator did not fund output 0.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
