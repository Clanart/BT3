### Title
`addr` precompile `associate`/`associatePubKey` signature has no chain-ID/domain binding and no expiration, enabling cross-chain signature replay - (File: `precompiles/addr/addr.go`)

### Summary
The `addr` precompile's `associate` method (and its `AssociateTx` counterpart used in the ante handler) authorizes a security-sensitive state change — creating a permanent EVM↔Sei address mapping and migrating the balance of the EVM-derived account to the Sei account — based solely on an ECDSA signature over an arbitrary `customMessage` string. Exactly like the `NodeRegistry.registerNodeFor()` bug class described in the report, the signed payload contains no domain separator (no chain ID, no precompile/contract address) and no expiration, so a signature produced for one chain/deployment can be replayed on another.

### Finding Description
`associate()` recovers a public key from `(v, r, s)` over `keccak256(customMessage)` and directly derives both the EVM address and the Sei address from that recovered key: [1](#0-0) 

The hash committed to by the signature is computed purely from the caller-supplied `customMessage` string — there is no inclusion of the chain ID, the precompile address, or any expiry/nonce field: [2](#0-1) 

The same pattern is reused by the `AssociateTx` path invoked directly from the ante handler for both `CheckTx` and `DeliverTx`, again hashing only `atx.CustomMessage` with no chain-ID binding before deriving addresses and performing the association: [3](#0-2) 

Once addresses are derived, `AssociateAddresses` unconditionally migrates all spendable coins and wei balance from the EVM-derived "cast" account to the Sei account and removes the cast account, using only the association call as authorization — no separate transaction signed by the cast account is required: [4](#0-3) 

Because the signed hash omits the chain ID (unlike ordinary EVM transactions, which are chain-ID bound per `EvmStatelessChecks`): [5](#0-4) 

a valid `associate`/`associatePubKey` signature (or `AssociateTx`) produced for one network (e.g., testnet, or any other chain instance running this codebase) is equally valid on every other Sei-derived chain that shares the same address-derivation and precompile ABI. There is also no expiration field, so a signature can be captured (e.g., from a public testnet faucet flow, a leaked mempool transaction, or a previously-used but not-yet-broadcast signature) and replayed indefinitely.

### Impact Explanation
An attacker who observes a user's `associate`/`AssociateTx` signature on one chain (testnet, a fork, or a future redeployment) can resubmit it on another Sei chain instance before the legitimate user does. This:
- Forces the permanent EVM↔Sei address mapping and the irreversible balance migration (`MigrateBalance`) to occur on a chain/context the signer never intended, front-running the user's own intended association.
- Permanently blocks the legitimate association on that chain, since `associateAddresses` rejects a second association attempt once one exists (`address ... is already associated`), effectively freezing the user's ability to link their addresses and access funds sent to the EVM-cast address in the expected way.
- Because `MigrateBalance` moves funds and removes the source account as a side effect of a replayed signature, this can move/lock user funds on a network the user did not sign for, matching the "permanent freezing" / "unauthorized transfer via precompile" impact classes.

### Likelihood Explanation
Likelihood is moderate: exploitation requires an attacker to obtain a previously-produced valid `(v, r, s, customMessage)` tuple (e.g., from a public testnet, a different Sei-based chain, or a broadcast-but-not-yet-mined signature) and resubmit it against another live chain sharing the same precompile/ante logic — a straightforward, unprivileged `eth_call`/transaction from any account, requiring no special privileges, matching the "unprivileged transaction sender" reachability constraint.

### Recommendation
Bind the signed hash to chain-specific and purpose-specific context, mirroring the report's recommendation for `NodeRegistry`:
- Include the chain ID (and optionally the precompile address / a fixed domain tag) inside the hash committed to by `customMessage`/`CustomMessage` before signing, so a signature is only valid for the intended chain.
- Add an expiration timestamp or nonce that is checked and consumed on association, preventing indefinite replay of a captured signature.
- Apply the fix consistently to both the `addr` precompile's `associate`/`associatePubKey` methods and the `AssociateTx` handling in `app/ante/evm_checktx.go`.

### Proof of Concept
1. On Chain A (e.g., Sei testnet), a user signs `customMessage = "link my address"` producing `(v, r, s)` and calls `associate(v, r, s, customMessage)` via the `addr` precompile at `0x0000000000000000000000000000000000001004`, or submits an `AssociateTx`.
2. An observer captures this `(v, r, s, customMessage)` tuple from the public mempool/block.
3. On Chain B (a different Sei-derived chain instance, e.g. mainnet or another fork sharing the same genesis/precompile code), the observer submits the identical `associate(v, r, s, customMessage)` call before the legitimate user does so on Chain B.
4. Because `customMessageHash := crypto.Keccak256Hash([]byte(customMessage))` contains no chain ID, `helpers.GetAddresses` recovers the same key and re-derives the same EVM/Sei address pair on Chain B, and `associateAddresses` → `AssociateAddresses` executes the mapping and balance migration on Chain B without the user ever having signed anything specifically authorizing that action on Chain B — see `precompiles/addr/addr.go:169-202` and `utils/helpers/associate.go:34-83`.
5. The legitimate user's subsequent attempt to associate on Chain B is rejected with `"address %s is already associated with evm address %s"`, permanently blocking their intended association on that chain.

func GetAddresses(V *big.Int, R *big.Int, S *big.Int, data common.Hash) (common.Address, sdk.AccAddress, cryptotypes.PubKey, error) {
	pubkey, err := RecoverPubkey(data, R, S, V, true)
	if err != nil {
		return common.Address{}, sdk.AccAddress{}, nil, err
	}

	evmAddr, err := PubkeyToEVMAddress(pubkey)
	if err != nil {
		return common.Address{}, sdk.AccAddress{}, nil, err
	}
	seiPubkey := PubkeyBytesToSeiPubKey(pubkey)
	seiAddr := sdk.AccAddress(seiPubkey.Address())
	return evmAddr, seiAddr, &seiPubkey, nil
}

func HandleAssociateTx(ctx sdk.Context, ek *evmkeeper.Keeper, atx *ethtx.AssociateTx, readOnly bool) (sdk.Context, error) {
	V, R, S := atx.GetRawSignatureValues()
	V = new(big.Int).Add(V, utils.Big27)
	// Hash custom message passed in
	customMessageHash := crypto.Keccak256Hash([]byte(atx.CustomMessage))
	evmAddr, seiAddr, seiPubkey, err := helpers.GetAddresses(V, R, S, customMessageHash)
	if err != nil {
		return ctx, err
	}
	_, isAssociated := ek.GetEVMAddress(ctx, seiAddr)
	if isAssociated {
		return ctx, sdkerrors.Wrap(sdkerrors.ErrInvalidRequest, "account already has association set")
	}
	if !IsAccountBalancePositive(ctx, ek, seiAddr, evmAddr) {
		return ctx, sdkerrors.Wrap(sdkerrors.ErrInsufficientFunds, "account needs to have at least 1 wei to force association")
	}
	if !readOnly {
		if err := AssociateAddress(ctx, ek, evmAddr, seiAddr, seiPubkey); err != nil {
			return ctx, err
		}
	}
	return ctx.WithPriority(antedecorators.EVMAssociatePriority), nil
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}
