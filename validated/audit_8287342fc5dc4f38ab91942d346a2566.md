### Title
Removal of a Gasless-Swap Token Mid-Block Can Strand the Proposer's Lent Gas Fee - ([File: kaiax/gasless/impl/getter.go])

### Summary
The Kaia gasless-transaction mechanism (KIP-247) lets a block proposer pre-fund a user's gas ("Lend") and expects to be repaid inside the same bundled `GaslessSwapTx`. The set of tokens/router eligible for this flow is cached once per block from the on-chain `GaslessSwapRouter` registry and is only refreshed *after* a block is inserted. An admin call to `GaslessSwapRouter.removeToken()` executed earlier in the *same* block as a pending gasless swap for that token can desynchronize the proposer's stale eligibility cache from the router's live state, letting the `LendTx` unconditionally transfer value to the user while the paired `SwapTx` (which now targets a de-listed token) fails to repay it — an unauthorized, uncompensated value transfer analogous to the reported "removeCollateral() strands user funds" bug class.

### Finding Description
`GaslessSwapRouter.RemoveToken` [1](#0-0)  allows the router owner to instantly delist a token from the supported set, emitting `TokenRemoved`.

The `kaiax/gasless` module tracks the router's supported tokens and swap-router address in an in-memory cache (`g.allowedTokens`, `g.swapRouter`) that is refreshed **only once per block**, in `PostInsertBlock`, i.e., strictly *after* a block has already been finalized: [2](#0-1) . The refresh logic (`updateAddresses`) pulls a fresh snapshot from `MultiCallGaslessInfo` at the given header: [3](#0-2) .

Transaction eligibility for gasless treatment — `isApproveTx`/`isSwapTx` — is gated purely on this cached map, not on live state at block-building time: [4](#0-3) .

When a proposer decides to sponsor a gasless swap, it generates a `LendTx` that unconditionally transfers KAIA value to the swap sender before the actual swap executes, based purely on `lendAmount`/`repayAmount` fee arithmetic — with no dependency on whether the underlying token is still supported by the router at execution time: [5](#0-4) [6](#0-5) .

Because the eligibility cache used for bundling (from the *previous* block) can be stale relative to the live router state during the *current* block, a sequence like: (1) `removeToken(T)` tx included early in block N, (2) a pending `GaslessApproveTx`/`GaslessSwapTx` pair for token `T` — already classified as gasless using the stale, pre-removal cache — bundled later in the same block N, produces: the `LendTx` (a plain value transfer, unconditioned on router state) succeeds and pays out KAIA to the user, while the `SwapTx` call into the now-delisted-token path on the live `GaslessSwapRouter` reverts or fails to complete the expected repayment, i.e., the proposer's lent value is not recouped. This mirrors the audited defect where `removeCollateral()`/`setEToken()` changes the "supported" state out from under in-flight user positions, causing value to become unrecoverable without an explicit safeguard.

### Impact Explanation
If exploitable, this results in unauthorized value movement (loss of the sponsoring CN/proposer's KAIA) for gasless transactions whose bundling window straddles a `removeToken`/router-change transaction, without requiring any privileged access — an ordinary user only needs to have a pending gasless swap for a token that a router owner happens to deregister in the same block. This falls under the explicitly in-scope "gasless and auction modules...gasless...settlement theft" category.

### Likelihood Explanation
Likelihood depends on timing precision: the attacker (or an opportunistic normal user) needs a pending gasless swap for token `T` to be selected for bundling in the exact block where `removeToken(T)` is also included, and needs the router's live path to actually reject/short-circuit the swap post-removal (unverified from source, only bindings were available). This requires influence over transaction submission timing but no special privileges — a public, unprivileged submitter can craft/submit an approve+swap pair speculatively and repeat across blocks/tokens to look for a race window, or simply observe pending `removeToken` calls in the mempool and race a swap ahead of it in the same block.

### Recommendation
- Re-validate token/router eligibility using the **current** state at bundle-build/inclusion time, not a cache lagging by a full block (analogous to enforcing "no removal effects on already-admitted positions" in the source report).
- Make the `LendTx`/`SwapTx` bundle atomic with respect to router support checks — abort/skip building the `LendTx` if the `GaslessSwapRouter`'s live `isTokenSupported`/router address disagrees with the module's cached snapshot for that block.
- Consider requiring a timelock/announcement period before `removeToken()`/router updates take effect (the same mitigation the original report's vendor applied to `removeCollateral()`), so in-flight gasless bundles cannot be invalidated mid-block.

### Proof of Concept
Conceptual PoC (exact live-contract revert behavior on a delisted token was not verifiable from bindings alone within the scope of this review):
1. User A submits `GaslessApproveTx(nonce=k)` + `GaslessSwapTx(nonce=k+1, token=T)`; both pass `IsExecutable`/pool admission using the block-(N-1) cached `allowedTokens` set that still contains `T`.
2. Router owner submits `removeToken(T)` in block N, ordered before A's bundle.
3. Proposer, still relying on the stale per-block cache, builds `[LendTxGenerator, ApproveTx, SwapTx]` for A's bundle and includes it after the `removeToken` tx in block N (per `GetLendTxGenerator`/`ExtractTxBundles` ordering logic in `kaiax/gasless/impl/builder.go` and `kaiax/gasless/impl/getter.go` lines 268-313).
4. `LendTx` executes unconditionally, paying KAIA to A. `SwapTx`, now executing against the router with `T` delisted, fails to complete the intended `swapForGas` flow/repayment.
5. Proposer bears the lent amount with no repayment — value loss without any error being surfaced by the cached-eligibility checks in `kaiax/gasless/impl/getter.go:79-103`. [2](#0-1) [4](#0-3) [5](#0-4) [1](#0-0) 

**Note on uncertainty:** I could not directly inspect the Solidity source of `GaslessSwapRouter` (only Go bindings were indexed), so I cannot confirm with certainty that `swapForGas` actually reverts on a delisted token rather than, e.g., silently succeeding with degraded pricing, nor could I fully trace `ExtractTxBundles`/mempool re-validation ordering guarantees for the gasless module within the available iterations. If a Devin session with full repository access can confirm (a) the exact `swapForGas` require/revert conditions on `isTokenSupported`, and (b) whether bundle-building performs any live re-check immediately before inclusion, this would either substantiate or rule out the described race.

func (g *GaslessModule) isApproveTx(args *ApproveArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.allowedTokens[args.Token] && // A1
		g.swapRouter == args.Spender && // A3
		args.Amount.Cmp(abi.MaxUint256) == 0 // A4
}

// IsSwapTx checks following conditions:
// S1. tx.to is a whitelisted SwapRouter contract.
// S2. tx.data is `swapForGas(token, amountIn, minAmountOut, amountRepay)`.
// S3. token is a whitelisted ERC20 token.
func (g *GaslessModule) IsSwapTx(tx *types.Transaction) bool {
	args, ok := decodeSwapTx(tx, g.signer)
	return ok && g.isSwapTx(args)
}

func (g *GaslessModule) isSwapTx(args *SwapArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.swapRouter == args.Router && // S1
		g.allowedTokens[args.Token] // S3
}

// MakeLendTx creates a transaction with following properties:
// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)
// L2. LendTx.from = proposer
// L3. LendTx.to = SwapTx.from
// L4. LendTx.value = LendAmount(approveTxOrNil, swapTx)
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}

func (g *GaslessModule) updateAddresses(header *types.Header) error {
	g.gaslessInfoMu.Lock()
	defer g.gaslessInfoMu.Unlock()

	swapRouter, tokens, err := getGaslessInfo(g.Chain, header)
	// proceed even if there is something wrong with multicall contract
	if err != nil {
		g.swapRouter = common.Address{}
		g.allowedTokens = map[common.Address]bool{}
		logger.Warn("there is something wrong with multicall contract", "err", err.Error())
		return nil
	}

	g.swapRouter = swapRouter

	g.allowedTokens = map[common.Address]bool{}
	for _, addr := range tokens {
		// all tokens are allowed if nil
		if g.GaslessConfig.AllowedTokens == nil {
			g.allowedTokens[addr] = true
		}
		for _, allowed := range g.GaslessConfig.AllowedTokens {
			if addr == allowed {
				g.allowedTokens[addr] = true
			}
		}
	}

	return nil
}

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}
