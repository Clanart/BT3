This confirms the vulnerability: `pallet_ismp::Pallet::<T>::dispatch_request` is a generic capability exposed to **any pallet** on the Hyperbridge (Nexus) chain (and via demo/example pallets, any signed extrinsic wrapping it) that sets `from` to whatever module id the caller chooses. `HostManager.onAccept` on the EVM side only checks the request's **source chain** (`request.source == hyperbridge`), never the **sending module id** (`request.from`). This is the direct structural analog of the Vault report: governance/asset-moving logic (`migrateStrategy`) is reachable through an insufficiently-scoped caller check, exactly like `HostManager.onAccept` accepts `Withdraw` / `SetHostParam` actions from *any* module on the source chain instead of only the intended privileged pallet (e.g. `pallet-ismp-relayer` / `pallet-ismp-host-executive`).

### Title
`HostManager.onAccept` authorizes fund withdrawal and host-param takeover from any Hyperbridge-chain module, not just the intended privileged pallet - ([File: evm/src/core/HostManager.sol])

### Summary
`HostManager.onAccept` is the single entrypoint EVM hosts use to execute privileged, fund-moving and configuration-changing actions (`Withdraw`, `SetHostParam`) originating from the Hyperbridge coprocessor chain. It authenticates the request purely by **which chain** it came from, never **which pallet/module on that chain** dispatched it.

### Finding Description
`HostManager.onAccept` performs:
```solidity
if (!request.source.equals(IHost(_params.host).hyperbridge())) revert UnauthorizedAction();
OnAcceptActions action = OnAcceptActions(uint8(request.body[0]));
if (action == OnAcceptActions.Withdraw) {
    IHostManager(_params.host).withdraw(withdrawParams);
} else if (action == OnAcceptActions.SetHostParam) {
    IHostManager(_params.host).updateHostParams(hostParams);
}
``` [1](#0-0) 

This mirrors `Strategy(oldVersion).migrate(newVersion)` being reachable via a path that checks the wrong scope (governance vs. vault context) instead of the correct one. Here, the correct scope should be "did the designated privileged pallet (`pallet-ismp-relayer` for withdrawals, `pallet-ismp-host-executive` for `SetHostParam`) dispatch this," but the code only checks the coprocessor chain identity.

On the Substrate side, `IsmpDispatcher::dispatch_request` is a generic, permissionless capability: any pallet — including a custom/example pallet reachable by a signed extrinsic — can set `from` to an arbitrary module id and `to` to the target `HostManager` address on any EVM chain: [2](#0-1) 

Documentation confirms this is the generic, intended integration surface for any pallet wanting to dispatch cross-chain messages, with `from`/`to` fully controlled by the calling pallet: [3](#0-2) 

Compare this to the legitimate `pallet-ismp-host-executive::update_host_params`, which correctly builds and signs the `SetHostParam`-shaped body only under `T::HostExecutiveOrigin::ensure_origin(origin)?` privileged governance: [4](#0-3) 

The `HostManager` contract has no equivalent check that `request.from` equals the known `pallet-ismp-host-executive` / `pallet-ismp-relayer` module id. As long as an attacker (or a compromised/malicious low-privilege pallet integrated into the Hyperbridge runtime, or in the worst case a permissionless pallet call that lets a user control `from`/`to`/`body` freely) can get a `PostRequest` with `source == hyperbridge`, `to == hostManager address`, and a correctly ABI-encoded `WithdrawParams`/`HostParams` body delivered to the EVM chain, `HostManager.onAccept` will execute it — draining accrued host revenue (`withdraw`) to an attacker-chosen beneficiary, or replacing `hostManager`/`handler`/`consensusClient`/`feeToken` (`updateHostParams`) to fully hijack the bridge's trust root on that chain.

### Impact Explanation
This is a direct match for the bounty's "stealing or loss of funds" and "unauthorized transaction or execution" categories: an attacker able to dispatch an arbitrarily-labeled ISMP POST from the Hyperbridge chain to a connected EVM `HostManager` can (a) withdraw the host's accumulated revenue (`EvmHost.withdraw`, restricted only to `hostManager`, which trusts this unchecked `onAccept`) to any beneficiary, or (b) rewrite `HostParams` — including `hostManager`, `handler`, and `consensusClient` — effectively taking over the host's cross-chain governance and consensus verification path, since `updateHostParamsInternal`'s only validation is that the new addresses are non-zero contracts implementing the right interface, not that the caller is legitimate: [5](#0-4) [6](#0-5) 

### Likelihood Explanation
The missing `request.from` allowlist check in `onAccept` is unconditional and always reachable whenever any message from the Hyperbridge state machine lands at the `HostManager` address; there is no additional relayer/prover/admin trust assumption required beyond what ISMP already provides for message delivery. The severity depends on how tightly the Hyperbridge runtime restricts which pallets/extrinsics can freely choose `from`/`to`/`body` in `dispatch_request` — the demo/example pallets in this repo show this is a documented, generic, low-friction pattern for any pallet author, and no source-searchable authorization gate exists at the destination.

### Recommendation
- **Short term:** In `HostManager.onAccept`, in addition to checking `request.source == hyperbridge`, require `request.from` to equal an allowlisted module id (e.g., the `pallet-ismp-relayer` id for `Withdraw` and the `pallet-ismp-host-executive` id for `SetHostParam`), mirroring the report's recommendation to avoid ambiguous authorization scope.
- **Long term:** Audit every `IIsmpModule::onAccept` implementation across the codebase (EVM and Substrate) for reliance on `request.source` (chain-level) alone, and require both source-chain and source-module (`request.from`) checks for any handler that triggers privileged, fund-moving, or config-changing logic — the same class of issue the reference report calls out for over-broad migration authority.

### Proof of Concept
1. On the Hyperbridge (Nexus) parachain, any pallet with access to `pallet_ismp::Pallet::<T>::dispatch_request` (or a signed extrinsic wrapping it, as shown by the demo pallet's `dispatch_to_evm`) constructs:
   ```rust

       dest: StateMachine::Evm(<target_chain_id>),
       from: b"ANY-MODULE".to_vec(),          // unchecked by HostManager
       to: <hostManager_address_bytes>,
       timeout: 0,
       body: {
           let mut b = vec![0u8]; // OnAcceptActions.Withdraw
           b.extend(WithdrawParams { token: <feeToken>, beneficiary: <attacker>, amount: <hostBalance> }.abi_encode());
           b
       },
   };
   dispatcher.dispatch_request(DispatchRequest::Post(post), fee)?;
   ```
2. Once the relayer delivers this POST request to the destination EVM chain and it is routed to `HostManager.onAccept`, the only check performed is `request.source.equals(hyperbridge)` [7](#0-6) , which passes because the request genuinely originates from the Hyperbridge chain.
3. `IHostManager(_params.host).withdraw(withdrawParams)` executes, transferring the host's accrued revenue to the attacker-controlled `beneficiary` [8](#0-7) .
4. The same technique with `action = SetHostParam` and a `HostParams` payload naming an attacker-controlled `hostManager`/`handler`/`consensusClient` hijacks the host's entire trust configuration going forward.

**Uncertainty note:** I was not able to fully confirm within the available context whether the Nexus/Gargantua production runtime configuration actually wires any permissionless or low-privilege pallet's `dispatch_request` path to allow attacker-chosen `from`/`to`/`body` reaching a real `HostManager` deployment (the demo pallet shown is illustrative/example code, not necessarily deployed on mainnet). Verifying the exact set of pallets integrated into the production Nexus runtime and their `IsmpDispatcher` access would require inspecting `parachain/runtimes/nexus/src/lib.rs` and its pallet configuration in more depth than the current index coverage allowed. Regardless, the `HostManager.onAccept` authorization gap itself (missing `request.from` check) is confirmed directly in source and is a latent defense-in-depth failure independent of what currently happens to be wired into the runtime.

        PostRequest calldata request = incoming.request;
        // Only the Hyperbridge parachain can send requests to this module.

		&self,
		request: DispatchRequest,
		fee: FeeMetadata<T>,
	) -> Result<H256, anyhow::Error> {
		// collect payment for the request
		if fee.fee != Zero::zero() {
			T::Currency::transfer(
				&fee.payer,
				&RELAYER_FEE_ACCOUNT.into_account_truncating(),
				fee.fee,
				Preservation::Expendable,
			)
			.map_err(|err| IsmpError::Custom(format!("Error withdrawing request fees: {err:?}")))?;
		}

		let request = match request {
			DispatchRequest::Get(dispatch_get) => {
				let get = GetRequest {
					source: self.host_state_machine(),
					dest: dispatch_get.dest,
					nonce: self.next_nonce(),
					from: dispatch_get.from,
					keys: dispatch_get.keys,
					height: dispatch_get.height,
					context: dispatch_get.context,
					timeout_timestamp: if dispatch_get.timeout == 0 {
						0
					} else {
						<T::TimestampProvider as UnixTime>::now()
							.as_secs()
							.saturating_add(dispatch_get.timeout)
					},
				};
				Request::Get(get)
			},
			DispatchRequest::Post(dispatch_post) => {
				let post = PostRequest {
					source: self.host_state_machine(),
					dest: dispatch_post.dest,
					nonce: self.next_nonce(),
					from: dispatch_post.from,

						0
					} else {
						<T::TimestampProvider as UnixTime>::now()
							.as_secs()
							.saturating_add(dispatch_post.timeout)
					},
					body: dispatch_post.body,
				};
				Request::Post(post)
			},
		};

    function updateHostParamsInternal(HostParams memory params) internal {
        // check the params to prevent the host from getting bricked.
        if (
            params.hostManager == address(0) || address(params.hostManager).code.length == 0
                || !IERC165(params.hostManager).supportsInterface(type(IApp).interfaceId)
        ) {
            // otherwise cannot process new cross-chain governance requests
            revert InvalidHostManager();
        }

        if (
            params.handler == address(0) || address(params.handler).code.length == 0
                || !IERC165(params.handler).supportsInterface(type(IHandlerV2).interfaceId)
        ) {
            // otherwise cannot process new datagrams
            revert InvalidHandler();
        }

        if (
            params.consensusClient == address(0) || address(params.consensusClient).code.length == 0
                || !IERC165(params.consensusClient).supportsInterface(type(IConsensusV2).interfaceId)
        ) {
            // otherwise cannot process new consensus datagrams
            revert InvalidConsensusClient();
        }

        // otherwise cannot process new cross-chain governance requests
        if (keccak256(params.hyperbridge) == keccak256(bytes(""))) revert InvalidHyperbridgeId();

        // otherwise cannot process new datagrams
        uint256 stateMachinesLen = params.stateMachines.length;
        if (stateMachinesLen == 0) revert InvalidStateMachinesLength();

        // otherwise cannot process new datagrams
        if (1 days > params.unStakingPeriod) revert InvalidUnstakingPeriod();

        address oldFeeToken = feeToken();
        if (oldFeeToken != address(0) && oldFeeToken != params.feeToken) {
            uint256 balance = IERC20(oldFeeToken).balanceOf(address(this));
            if (balance != 0) revert CannotChangeFeeToken();
        }

        // safe to emit here because invariants have already been checked
        // and don't want to store a temp variable for the old params
        emit HostParamsUpdated({oldParams: _hostParams, newParams: params});

        _hostParams.feeToken = params.feeToken;
        _hostParams.admin = params.admin;
        _hostParams.handler = params.handler;
        _hostParams.hostManager = params.hostManager;
        _hostParams.uniswapV2 = params.uniswapV2;

        _hostParams.consensusClient = params.consensusClient;

        for (uint256 i = 0; i < stateMachinesLen; ++i) {

                _latestStateMachineHeight[params.stateMachines[i]] = 1;
