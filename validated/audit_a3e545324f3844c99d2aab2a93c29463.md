### Title
Payout tx malleability under `SinglePlusAnyoneCanPay` sighash lets an attacker inject a fake OP_RETURN, causing `get_first_op_return_output` to misattribute the payout and let `is_kickoff_malicious` wrongfully challenge an honest operator - ([File: core/src/verifier.rs], [File: circuits-lib/src/bridge_circuit/mod.rs], [File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
The binding claimed to hold is: `operator_xonly_pk parsed from get_first_op_return_output(payout_tx)` == `operator_xonly_pk that create_payout_txhandler actually placed in the payout tx's OP_RETURN output (index 2)`. Because the user's withdrawal signature uses `TapSighashType::SinglePlusAnyoneCanPay`, which commits only to input 0 and output 0, any observer of the broadcast/unconfirmed payout transaction can rebuild a competing transaction that keeps output 0 identical (so the signature stays valid) while freely adding an earlier OP_RETURN output with arbitrary data. `get_first_op_return_output` (`circuits-lib/src/bridge_circuit/mod.rs:688`) just returns the first OP_RETURN by iteration order, so `Verifier::update_finalized_payouts` (`core/src/verifier.rs:2283-2353`) would record the attacker's fake pubkey instead of the true operator's pubkey from `create_payout_txhandler`'s output 2 (`core/src/builder/transaction/operator_reimburse.rs:407-436`).

### Finding Description
Binding (claimed): `parse_op_return_data(get_first_op_return_output(payout_tx).script_pubkey)` == `operator_xonly_pk` encoded by `create_payout_txhandler` at its output index 2 [1](#0-0) .

Root cause - sighash scope: `Operator::withdraw` verifies the user's signature over `payout_txhandler.calculate_sighash_txin(0, in_signature.sighash_type)`, and the aggregator/operator RPC parser hard-enforces `TapSighashType::SinglePlusAnyoneCanPay` [2](#0-1) , verified in `Operator::withdraw` [3](#0-2) . Under BIP341, `SIGHASH_SINGLE | SIGHASH_ANYONECANPAY` commits only to: the single spent input, and the single output at the same index (output 0, the user payout output). It does not commit to the number, order, or content of any other outputs (the anchor at index 1 and the operator-attribution OP_RETURN at index 2), nor to any other inputs.

Exploit path: Once the operator broadcasts the payout tx (visible on the P2P network/mempool before it confirms - "broadcast Bitcoin transactions" is an explicit unprivileged attacker capability), the attacker copies the same input (outpoint + witness signature) and output 0 verbatim, adds their own funding input(s) to cover fees (permitted by ANYONECANPAY), and constructs new outputs: e.g. output 1 = an attacker-chosen OP_RETURN (with a different/arbitrary xonly-pubkey payload), followed by the original anchor and the real operator's OP_RETURN pushed further down. The Schnorr signature over the SIGHASH_SINGLE|ANYONECANPAY digest remains valid because output 0 and the spent input are unchanged. If the operator's payout tx signals RBF (typical bitcoind wallet-funded default), the attacker can replace it in the mempool by paying a higher fee; otherwise they can race to get their variant mined first.

Downstream failure: `Verifier::update_finalized_payouts` scans the confirmed payout tx with `get_first_op_return_output`, which does a linear `.find()` for the first OP_RETURN output with no fixed-index or content binding to the transaction actually built by `create_payout_txhandler` [4](#0-3) [5](#0-4) . It then persists the parsed (now attacker-controlled) pubkey via `update_payout_txs_and_payer_operator_xonly_pk` into `withdrawals.payout_payer_operator_xonly_pk` [6](#0-5) .

Later, `Verifier::is_kickoff_malicious` compares this DB value against `kickoff_data.operator_xonly_pk` from the operator's real kickoff [7](#0-6) . Since the DB now holds the attacker-injected pubkey rather than the true operator's, the comparison fails and the function returns `true` ("malicious"), which triggers `handle_kickoff` to queue a `Challenge` transaction against the honest operator's kickoff [8](#0-7) , and per the BitVM2 disprove path documented, an unanswered/failed challenge cascade ultimately can lead to collateral burn for the operator that actually funded the withdrawal.

Why existing guards fail: `is_deposit_valid`, `SECP.verify_schnorr`, and the sighash type enforcement all check only that the *signature* is valid for the specific input/output-0 pair; none of them constrain the remaining outputs of the payout transaction, and `get_first_op_return_output` has no mechanism (fixed vout, exact-match against the expected operator pubkey, or count check) to reject extra/foreign OP_RETURN outputs.

### Impact Explanation
The honest operator that genuinely fronted the withdrawal (paid the user from their own funds, matching output 0 exactly) can be misattributed by the verifiers' database to a different (attacker-chosen, possibly nonexistent or another operator's) xonly pubkey. This causes `is_kickoff_malicious` to wrongfully flag the true operator's legitimate kickoff as malicious, triggering a Challenge against them - and if not resolved by a costly BitVM2 dispute path, risks the honest operator's collateral being burned via the Disprove path, and/or permanently prevents the honest operator's `Reimburse` transaction from being accepted (since `send_asserts`/reimbursement flow also relies on matching `payout_op_xonly_pk` to `kickoff_data.operator_xonly_pk`, see `core/src/operator.rs:1284-1295`). This matches the Critical categories "an honest operator's collateral burned" and "an honest operator permanently unable to be reimbursed." The attack is repeatable for any withdrawal/operator as long as the attacker can observe the unconfirmed payout tx and either win a mining race or successfully RBF-replace it.

### Likelihood Explanation
Preconditions: (1) the payout tx must be observable pre-confirmation (always true - it must be broadcast to be mined), and (2) the attacker must get their modified variant confirmed instead of the operator's original, either via RBF replacement (requires the tx to signal replaceability, which is the common wallet/bitcoind default used by `fund_raw_transaction`/`sign_raw_transaction_with_wallet` in `Operator::withdraw`, `core/src/operator.rs:652-681`) or by racing for block inclusion. The attacker pays for fees/replacement bump (cost bounded by dust amounts used in withdrawals and prevailing fee rates) - well within the described unprivileged attacker capabilities ("broadcast Bitcoin transactions and pay fees", "choose ... a Schnorr signature and its sighash flag"). No key compromise, no majority hashrate, and no privileged role is required, only mempool visibility and fee competition, making this feasible and repeatable across different withdrawals and operators. I was not able to fully verify from the retrieved code whether the operator's `fund_raw_transaction` call explicitly disables RBF (`replaceable: None` defers to node/wallet defaults), so likelihood depends on the deployed bitcoind's default RBF policy - this is a caveat on exact deployability but does not change the underlying sighash-malleability defect.

### Recommendation
Do not rely on scanning for "the first OP_RETURN" to recover protocol-critical attribution data from a transaction only partially covered by the user's signature. Either (a) bind the operator's payout OP_RETURN to a fixed, protocol-defined vout (e.g., always index 2, matching what `create_payout_txhandler` produces) and reject transactions where that fixed vout is not the expected OP_RETURN/does not match the expected operator; or (b) require the user's withdrawal signature to use a sighash type that covers all outputs (`SIGHASH_ALL` or `SIGHASH_ALL|ANYONECANPAY`) so the operator-attribution OP_RETURN and its position cannot be altered without invalidating the signature, while still allowing additional funding inputs via `ANYONECANPAY`. At minimum, `get_first_op_return_output`/`update_finalized_payouts` and the bridge-circuit's `host_deposit_constant`/`bridge_circuit` functions should validate that the OP_RETURN sits at the exact expected output index and that no other extraneous OP_RETURN outputs exist before that index.

### Proof of Concept
```rust
// core/src/verifier.rs (or a new test module) - cargo test
// Goal: show get_first_op_return_output + parse_op_return_data can return an
// attacker-injected pubkey instead of the one create_payout_txhandler encoded,
// while the SinglePlusAnyoneCanPay signature over output 0 remains valid.

#[tokio::test]
async fn test_op_return_malleability_misattribution() {
    // 1. Build the legitimate payout tx via create_payout_txhandler with
    //    operator_xonly_pk = OP_A, sign input 0 with SinglePlusAnyoneCanPay.
    let legit_tx_handler = create_payout_txhandler(
        input_utxo.clone(), output_txout.clone(), op_a_xonly_pk, user_sig, network,
    ).unwrap();
    let legit_tx = legit_tx_handler.get_cached_tx().clone();
    // sanity: legit tx's OP_RETURN (output[2]) encodes OP_A
    let legit_or = get_first_op_return_output(&CircuitTransaction::from(legit_tx.clone())).unwrap();
    assert_eq!(parse_op_return_data(&legit_or.script_pubkey).unwrap(), op_a_xonly_pk.serialize());

    // 2. Attacker builds a malleated tx: same input[0] + witness (signature unchanged),
    //    same output[0] (user payout, byte-for-byte identical - required by SIGHASH_SINGLE),
    //    but inserts an extra attacker-funded input + a NEW OP_RETURN (encoding OP_B, a
    //    different/attacker-chosen xonly pk) at output index 1, BEFORE the anchor and the
    //    real OP_RETURN (now shifted to index 3).
    let mut malleated_tx = legit_tx.clone();
    malleated_tx.input.push(attacker_funding_input);
    malleated_tx.output.insert(1, op_return_txout(PushBytesBuf::from(op_b_xonly_pk.serialize())));

    // 3. Confirm the original signature is still valid for input 0 under
    //    SinglePlusAnyoneCanPay against the malleated tx (output 0 & input 0 unchanged).
    let sighash_cache = SighashCache::new(&malleated_tx);
    let prevouts = Prevouts::One(0, &input_utxo.txout);
    let digest = sighash_cache
        .taproot_key_spend_signature_hash(0, &prevouts, TapSighashType::SinglePlusAnyoneCanPay)
        .unwrap();
    SECP.verify_schnorr(&user_sig.signature, &Message::from_digest(*digest.as_byte_array()), &user_xonly_pk)
        .expect("signature must still verify on malleated tx");

    // 4. Simulate Verifier::update_finalized_payouts logic directly:
    let circuit_tx = CircuitTransaction::from(malleated_tx.clone());
    let first_or = get_first_op_return_output(&circuit_tx).unwrap();
    let attributed_pk = parse_op_return_data(&first_or.script_pubkey)
        .and_then(|b| XOnlyPublicKey::from_slice(b).ok())
        .unwrap();

    // BUG: attribution diverges from the operator that actually funded the payout (OP_A).
    assert_ne!(attributed_pk, op_a_xonly_pk, "should differ from real payer if unpatched");
    assert_eq!(attributed_pk, op_b_xonly_pk, "attacker's injected OP_RETURN wins attribution");
}
```
This demonstrates the divergence between the binding's two sides (`get_first_op_return_output` result vs. `create_payout_txhandler`'s actual attribution output), fully within the `SinglePlusAnyoneCanPay` signature validity, without any mainnet/live Citrea dependency.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
