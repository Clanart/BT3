## Analysis

The external report's core broken invariant is: **an external callback used for critical state finalization can be bypassed (return "success" without executing) when the callee has no bytecode (via `selfdestruct`), while the caller still marks the operation as permanently completed.** In Teller, `try/catch` reverted on non-contract callees; here Hyperbridge uses raw `.call()` instead — but raw `.call()` to an address with no bytecode trivially returns `success = true` in the EVM, which is the *inverse* failure mode of the same root cause: insufficient validation of the callee before treating the external call's result as authoritative for irreversible bookkeeping.

`EvmHost.sol` applies an `extcodesize` guard **only** in one of the four symmetric dispatch-to-module paths: [1](#0-0) 

The sibling functions — `dispatchIncoming(GetResponse ...)`, `dispatchTimeOut(GetRequestTimeout ...)`, and `dispatchTimeOut(PostRequestTimeout ...)` — perform the exact same `.call()` pattern but **without** the `extcodesize` check: [2](#0-1) 

### Title
Missing `extcodesize` guard before low-level `.call()` in `dispatchIncoming(GetResponse)` / `dispatchTimeOut` lets a self-destructed module trivially "succeed", permanently deleting commitments/receipts and paying out fees without executing app logic - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatchIncoming(PostRequest, ...)` explicitly checks `extcodesize(destination) == 0` before invoking `IApp.onAccept` and returns early (without deleting state or paying fees) if the destination has no code. This same guard is absent from `dispatchIncoming(GetResponse, ...)`, `dispatchTimeOut(GetRequestTimeout, ...)`, and `dispatchTimeOut(PostRequestTimeout, ...)`. In all three, a low-level `.call()` targeting an address with no deployed bytecode returns `success = true` trivially (a CALL to an empty account is a documented EVM no-op that always succeeds), even though no application logic actually ran.

### Finding Description
In `dispatchTimeOut(PostRequestTimeout ...)`: [3](#0-2) 

the flow is: delete `_requestCommitments[commitment]` first, then `.call()` the module at `timeout.request.from`, and only *restore* the commitment (`_requestCommitments[commitment] = meta`) if `success` is `false`. If `timeout.request.from` has no bytecode — because the module contract self-destructed after the original request was dispatched but before the timeout is proven — the `.call()` returns `success = true` without executing any of the module's `onPostRequestTimeout` cleanup logic (e.g. unlocking escrowed collateral, crediting refunds, releasing bridged-asset custody). The commitment deletion is never rolled back, `meta.fee` is paid out, and `PostRequestTimeoutHandled` is emitted as if the module correctly processed the timeout.

The identical pattern exists in `dispatchIncoming(GetResponse, ...)` (permanently deletes ability to retry via the stored `_responseReceipts`, and pays the relayer fee) and `dispatchTimeOut(GetRequestTimeout, ...)`.

This directly mirrors the reported bug class: an external call whose "did it actually run application logic" signal is corrupted by the callee having no code, but the caller treats that corrupted signal as ground truth for irreversible state transitions (deleting commitments/receipts, one-time payouts) — exactly the "insufficient validation before trusting the external call outcome" root cause from the Teller finding, just manifesting as false-success instead of false-revert.

### Impact Explanation
Any state that a module's `on_timeout`/`on_response` callback is responsible for reverting or finalizing (refunds, unlocking custody, crediting balances) is silently skipped, yet the protocol marks the corresponding request/response as permanently handled — the commitment/receipt is deleted with no retry path. This is a false-state-acceptance / fund-lock outcome: user funds that were meant to be released or refunded through the timeout callback become permanently unrecoverable because the bookkeeping already reports the operation as completed. This matches the required impact class of "loss of funds" and "false proof/state acceptance" via corrupted execution-result handling in a public entrypoint path (`handlePostRequests`/`handleGetResponses`/`handleTimeouts` → `dispatchIncoming`/`dispatchTimeOut`), reachable without any relayer, prover, or admin collusion — the attacker only needs to control the module contract they registered as `from`/`to` and trigger its own `selfdestruct` before the corresponding proof is submitted.

### Likelihood Explanation
Any unprivileged actor can deploy a module contract that includes a `selfdestruct` path, dispatch a POST/GET request from it, and destroy it before the relayer submits the timeout/response proof (well within the normal window between dispatch and proof submission/challenge period). No relayer or prover misbehavior is required — the relayer is simply doing its normal job of submitting a valid proof for a request whose destination module no longer has code.

### Recommendation
Apply the same `extcodesize` guard used in `dispatchIncoming(PostRequest, ...)` (evm/src/core/EvmHost.sol:794-803) uniformly to `dispatchIncoming(GetResponse, ...)`, `dispatchTimeOut(GetRequestTimeout, ...)`, and `dispatchTimeOut(PostRequestTimeout, ...)`: check `extcodesize` of the target module address before issuing the `.call()`, and treat a zero-code destination the same as a failed call (i.e., do not delete the commitment/receipt, do not pay out fees) so the message remains retryable rather than being silently finalized against a non-existent callee.

### Proof of Concept
1. Deploy `EvilModule` implementing `IApp.onPostRequestTimeout` normally but with an owner-only `kill()` function calling `selfdestruct`.
2. From `EvilModule`, call `IDispatcher(host).dispatch(...)` to send a POST request with a short `timeout`.
3. Before any relayer submits the timeout proof, call `EvilModule.kill()`.
4. After the timeout window elapses, a relayer (or the attacker itself, self-relaying) submits a valid timeout proof via the handler, which calls `EvmHost.dispatchTimeOut(PostRequestTimeout, ...)`.
5. Observe: `_bytesToAddress(timeout.request.from).call(...)` targets `EvilModule` (now empty bytecode) and returns `success = true`; `_requestCommitments[commitment]` stays deleted (no restoration), `meta.fee` is transferred out, and `PostRequestTimeoutHandled` is emitted — despite `onPostRequestTimeout`'s refund/cleanup logic never executing.

    function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
        address destination = _bytesToAddress(request.to);
        uint256 size;
        assembly {
            size := extcodesize(destination)
        }
        if (size == 0) {
            // instead of reverting the entire batch, early return here.
            return;
        }

        // replay protection
        bytes32 commitment = request.hash();
        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)
            .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));

        if (!success) {
            // so that it can be retried
            delete _requestReceipts[commitment];
            return;
        }
        emit PostRequestHandled({commitment: commitment, relayer: relayer});
    }

    /**
     * @dev Dispatch an incoming GET response to source module
     * @param response - get response
     */
    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }
