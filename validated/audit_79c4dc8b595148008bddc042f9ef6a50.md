### Title
CosmWasm ERC20-pointer contracts do not check the boolean return value of delegated ERC20 `transfer`/`transferFrom` calls, allowing accounting to succeed while the underlying token transfer silently fails - ([File: example/cosmwasm/cw20/src/contract.rs])

### Summary
The `example/cosmwasm/cw20` CosmWasm CW20-over-ERC20 pointer contract executes ERC20 `transfer`/`transferFrom` by encoding an ABI payload and dispatching it as an `EvmMsg::DelegateCallEvm` Cosmos message, but neither the contract nor the Go-side handler that processes this message inspects the ABI-decoded boolean success value returned by the ERC20 `transfer`/`transferFrom` functions.

### Finding Description
`transfer` and `transfer_from` in `example/cosmwasm/cw20/src/contract.rs` build an ERC20 `transfer`/`transferFrom` calldata payload via `EvmQuerier::erc20_transfer_payload` / `erc20_transfer_from_payload` and wrap it in `EvmMsg::DelegateCallEvm { to: erc_addr, data: payload.encoded_payload }` [1](#0-0) , [2](#0-1) . This message is routed via `wasmbinding/encoder.go`'s `CustomEncoder` to `evmwasm.EncodeDelegateCallEVM`, which builds `types.MsgInternalEVMDelegateCall` [3](#0-2) . That message is handled by `Keeper.HandleInternalEVMDelegateCall`, which calls `Keeper.CallEVM` and returns success as long as `res.Err == nil` [4](#0-3) . `CallEVM` only checks `res.Err` (i.e., whether the EVM execution reverted) and returns the raw `res.ReturnData` without decoding/validating the ABI-encoded `bool` that ERC20 `transfer`/`transferFrom` are supposed to return [5](#0-4) . Because `add_message` results in a CosmWasm submessage that is only judged by whether the SDK message handler returned an error, a token whose `transfer`/`transferFrom` implementation returns `false` on failure (rather than reverting, per common ERC20 non-compliant implementations) will make the whole CW20-wrapper operation appear successful, even though no tokens moved. This mirrors the reported bug class (unchecked ERC20 transfer return value) but in this codebase's context, and is reachable purely from a CosmWasm contract execution that any user can invoke.

By contrast, the analogous Solidity `CW20ERC20Pointer.sol` (CW20-as-ERC20 direction) properly requires `success` from the underlying wasmd precompile `execute` call in `_execute` [6](#0-5) , and the Go-side bank precompile `send` functions properly propagate errors from `SendCoins`/`bankMsgServer.Send` [7](#0-6) . The unchecked path is specifically the ERC20-boolean-return path traversed by `CallEVM`/`HandleInternalEVMDelegateCall`.

### Impact Explanation
If the underlying ERC20 token (`ERC20_ADDRESS`) returns `false` instead of reverting on a failed transfer (e.g., insufficient balance/allowance edge cases in a non-standard-compliant token, or any custom token registered behind the pointer), the CW20 wrapper's `transfer`/`transfer_from` calls will still emit success attributes/events and any dependent submessages (e.g., `send_from` triggering `Cw20ReceiveMsg`) will proceed as if the transfer succeeded, even though the recipient never received tokens. This can lead to accounting desynchronization and potential fund loss for the party expecting the transfer, or unauthorized crediting via `send_from` flows without the corresponding tokens actually moving.

### Likelihood Explanation
This requires an ERC20 contract behind the pointer to implement `transfer`/`transferFrom` in the non-reverting, boolean-return style (common in many real-world tokens, e.g., older USDT-style behavior or a deliberately malicious token deployed by a user and later pointed to by others). Because pointer creation and the CW20 wrapper contract are permissionlessly deployable by any user against any ERC20 token address, an attacker/token deployer fully controls whether this condition is triggered, making exploitation straightforward once such a token is used with this wrapper pattern.

### Recommendation
In `Keeper.CallEVM` (or specifically in `HandleInternalEVMDelegateCall`), ABI-decode the return data for known ERC20-style calls (`transfer`, `transferFrom`, `approve`) and treat a decoded `false` boolean as a call failure that returns an error, matching the Solidity `require(success, ...)` pattern already used elsewhere in the codebase. Alternatively, adjust the CosmWasm wrapper's payload-generation contract to require/validate the decoded return value before treating the submessage as successful.

### Proof of Concept
1. Deploy or point to an ERC20 token whose `transfer(address,uint256)` function returns `false` on failure paths (e.g., insufficient balance) instead of reverting.
2. Deploy the CW20 wrapper contract (`example/cosmwasm/cw20`) pointing `ERC20_ADDRESS` to that token.
3. Call the CW20 wrapper's `transfer` or `transfer_from` execute message with parameters that cause the underlying ERC20 to return `false` (but not revert).
4. Observe that `HandleInternalEVMDelegateCall` -> `CallEVM` returns no error (since `res.Err == nil`), so the wasm message succeeds, the CW20 wrapper emits a success response with `transfer`/`transfer_from` attributes, and any downstream CW20 logic (e.g., `send_from`'s `Cw20ReceiveMsg`) proceeds, despite the token balance not actually changing.

func EncodeDelegateCallEVM(rawMsg json.RawMessage, sender sdk.AccAddress, info wasmvmtypes.MessageInfo, codeInfo wasmtypes.CodeInfo) ([]sdk.Msg, error) {
	encodedCallEVM := bindings.DelegateCallEVM{}
	if err := json.Unmarshal(rawMsg, &encodedCallEVM); err != nil {
		return []sdk.Msg{}, err
	}
	decodedData, err := base64.StdEncoding.DecodeString(encodedCallEVM.Data)
	if err != nil {
		return []sdk.Msg{}, err
	}
	s := sender
	if origSender, err := sdk.AccAddressFromBech32(info.Sender); err == nil {
		s = origSender
	}
	internalCallEVMMsg := types.MsgInternalEVMDelegateCall{
		Sender:       s.String(),
		To:           encodedCallEVM.To,
		CodeHash:     codeInfo.CodeHash,
		Data:         decodedData,
		FromContract: sender.String(),
	}
	return []sdk.Msg{&internalCallEVMMsg}, nil
}

func (k *Keeper) HandleInternalEVMDelegateCall(ctx sdk.Context, req *types.MsgInternalEVMDelegateCall) (*sdk.Result, error) {
	var to *common.Address
	if req.To != "" {
		addr := common.HexToAddress(req.To)
		to = &addr
	} else {
		return nil, errors.New("cannot use a CosmWasm contract to delegate-create an EVM contract")
	}
	addr, _, exists := k.GetAnyPointerInfo(ctx, types.PointerReverseRegistryKey(common.BytesToAddress([]byte(req.FromContract))))
	if !exists || common.BytesToAddress(addr).Cmp(*to) != 0 {
		return nil, errors.New("only pointer contract can make delegatecalls")
	}
	zeroInt := sdk.ZeroInt()
	senderAddr, err := sdk.AccAddressFromBech32(req.Sender)
	if err != nil {
		return nil, err
	}
	// delegatecall caller must be associated; otherwise any state change on EVM contract will be lost
	// after they asssociate.
	senderEvmAddr, found := k.GetEVMAddress(ctx, senderAddr)
	if !found {
		err := types.NewAssociationMissingErr(req.Sender)
		evmKeeperMetrics.associationError.Add(ctx.Context(), 1, otelmetric.WithAttributes(attribute.String("scenario", "evm_handle_internal_evm_delegate_call"), attribute.String("type", err.AddressType())))
		return nil, err
	}
	ret, err := k.CallEVM(ctx, senderEvmAddr, to, &zeroInt, req.Data)
	if err != nil {
		return nil, err
	}
	return &sdk.Result{Data: ret}, nil
}

func (p PrecompileExecutor) send(ctx sdk.Context, caller common.Address, method *abi.Method, args []interface{}, value *big.Int, readOnly bool) ([]byte, uint64, error) {
	if readOnly {
		return nil, 0, errors.New("cannot call send from staticcall")
	}
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}
	denom := args[2].(string)
	if denom == "" {
		return nil, 0, errors.New("invalid denom")
	}
	pointer, _, exists := p.evmKeeper.GetERC20NativePointer(ctx, denom)
	if !exists || pointer.Cmp(caller) != 0 {
		return nil, 0, fmt.Errorf("only pointer %s can send %s but got %s", pointer.Hex(), denom, caller.Hex())
	}
	amount := args[3].(*big.Int)
	if amount.Cmp(utils.Big0) == 0 {
		// short circuit
		bz, err := method.Outputs.Pack(true)
		return bz, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
	}
	senderSeiAddr, err := p.accAddressFromArg(ctx, args[0])
	if err != nil {
		return nil, 0, err
	}
	receiverSeiAddr, err := p.accAddressFromArg(ctx, args[1])
	if err != nil {
		return nil, 0, err
	}

	msg := &banktypes.MsgSend{
		FromAddress: senderSeiAddr.String(),
		ToAddress:   receiverSeiAddr.String(),
		Amount:      sdk.NewCoins(sdk.NewCoin(denom, sdk.NewIntFromBigInt(amount))),
	}

	err = msg.ValidateBasic()
	if err != nil {
		return nil, 0, err
	}

	if _, err = p.bankMsgServer.Send(sdk.WrapSDKContext(ctx), msg); err != nil {
		return nil, 0, err
	}

	bz, err := method.Outputs.Pack(true)
	return bz, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}
