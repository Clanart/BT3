### Title
`StacksTransaction::consensus_deserialize_with_len` masks the version byte's low 7 bits, breaking serialize(deserialize(b)) == b - (File: `stacks-codec/src/transaction.rs`)

### Summary
`StacksTransaction::consensus_deserialize_with_len` reads a raw `version_u8` byte from the wire and only inspects its high bit (`version_u8 & 0x80`) to pick `TransactionVersion::Mainnet` (0x00) or `TransactionVersion::Testnet` (0x80), discarding the low 7 bits. Because `TransactionVersion::Mainnet as u8 == 0x00`, any accepted byte in `{0x00..0x7F}` gets deserialized to the same `Mainnet` variant and, when re-serialized (including inside `txid()`), always emits `0x00`. This means `consensus_serialize(consensus_deserialize(b)) != b` whenever the attacker sets a non-canonical version byte (e.g. `0x01`), i.e. an accepted transaction can be produced whose txid (computed by the node via re-serialization) does not correspond to a SHA512/256 hash of the exact bytes that were POSTed/transmitted. [1](#0-0) 

### Finding Description
Equality claimed to hold: `consensus_serialize(consensus_deserialize(b)) == b` for every `b` accepted by `StacksTransaction::consensus_deserialize`.

Trace:
1. `StacksTransaction::consensus_deserialize` delegates to `consensus_deserialize_with_len`, which reads `version_u8: u8` and later computes `version = if (version_u8 & 0x80) == 0 { Mainnet } else { Testnet }`. [1](#0-0) 
2. `TransactionVersion` is `#[repr(u8)]` with `Mainnet = 0x00`, `Testnet = 0x80` — there is no representation for any other byte value. [2](#0-1) 
3. `consensus_serialize` writes `self.version as u8` verbatim: `write_next(fd, &(self.version as u8))?;`. [3](#0-2) 
4. `txid()` is computed by re-serializing the in-memory struct, not by hashing the originally-received bytes: `self.consensus_serialize(&mut bytes)... Txid::from_stacks_tx(&bytes)`. [4](#0-3) 

So if an attacker crafts and signs a transaction whose first byte is `0x01` (any value with the high bit clear other than `0x00`), the node accepts it (deserializes to `Mainnet`) but any subsequent re-serialization (used for `txid()`, mempool storage bytes reconstituted from the parsed struct, relay of the "canonical" tx, block inclusion, event-dispatcher's `raw_tx`, etc.) emits `0x00` in that position. The bytes fed into the sha512/256 for the txid therefore differ from the bytes the attacker actually transmitted and signed over (the signature itself does not cover the version byte at all — signing only commits to fee/nonce fields via `sign_and_append`/`next_signature`, and the version byte sits outside the auth's signed sighash construction). This satisfies the stated invariant break: "`consensus_deserialize` accepts bytes that re-serialize differently."

Why guards don't catch this:
- `process_transaction_precheck` / `check_transaction_version` in `process_transaction_payload`'s call path check `tx.version == chainstate mainnet flag` (i.e., `Mainnet`/`Testnet` semantic equality), which is unaffected — the semantic version is still valid (`Mainnet`), so the transaction is not rejected for a bad version.
- No code path re-validates that `version_u8` is exactly `0x00` or `0x80`; the mask discards the information permanently at decode time.
- `check_transaction_postconditions`, nonce/fee checks, and signature verification (`verify_origin`/`next_signature`) never touch the raw wire bytes, so they cannot detect the mismatch between the transmitted bytes and the reserialized bytes.

### Impact Explanation
This is a High-severity "txid/sighash over different bytes than transmitted" class issue per the rubric. Concretely:
- A block explorer, mempool relay tool, or any external system that computes a transaction's identity by hashing the raw bytes it received/broadcast (rather than round-tripping through `consensus_deserialize`→`consensus_serialize`) will compute a different id than the one the Stacks node reports via `/v2/transactions` or stores as the tx's `txid`. This creates relay/indexing confusion: the same semantic transaction can be represented by multiple distinct byte strings (`0x00` through `0x7F` in the version position) that are indistinguishable to the node (all map to `Mainnet`) but hash differently outside the node's own re-serialization path.
- This does not, by itself, let an attacker steal funds, forge a signature, or bypass post-conditions — the signature and asset movement logic are unaffected because deserialization is deterministic per input byte and the semantic `Mainnet`/`Testnet` value is preserved correctly for chain-id/version checks. The impact is confined to txid ambiguity / bookkeeping confusion between raw bytes and the canonical txid, matching the "High" bucket in the rubric rather than "Critical".
- Repeatable: an attacker can produce any number of such variant-byte transactions (each valid, each with a legitimate signature over the same signed content), all colliding to the same node-computed txid space issue.

### Likelihood Explanation
- Precondition: none beyond being able to craft and sign a raw transaction and POST it, which is exactly the unprivileged attacker capability granted by this audit's scope.
- Cost: trivial — flipping bits 0–6 of the first transaction byte to any value other than `0x00`/`0x80` before signing (the signature does not cover this byte the way sighash commitments are constructed over fee/nonce fields, not the leading version byte) requires no special resources.
- Feasibility confirmed by test-suite comments elsewhere in the codebase pinning `TransactionVersion::Mainnet as u8 == 0x00` and `Testnet as u8 == 0x80`, and explicit unit tests asserting these wire values, but I found no test asserting that `version_u8` values in `0x01..=0x7F` or `0x81..=0xFF` are rejected — the decode path unconditionally accepts them via the bitmask. [5](#0-4) 
- I was not able to fully verify, within the available tool budget, whether the `/v2/transactions` RPC handler itself echoes back a hash of the raw POST body anywhere (I only confirmed that `txid()` used throughout the codebase re-serializes), so I cannot say with certainty this manifests as an operator-visible bug in the stock RPC response today — but any external tool/observer (indexers, wallets reburoadcasting raw bytes, or bridges) that hashes the wire bytes directly rather than trusting the node's txid is exposed.

### Recommendation
In `StacksTransaction::consensus_deserialize_with_len` (`stacks-codec/src/transaction.rs`), require `version_u8` to be exactly one of the defined `TransactionVersion` discriminants (`0x00` or `0x80`) and return a `DeserializeError` for any other byte value, mirroring how `anchor_mode_u8` and `post_condition_mode_u8` are already strictly validated in the same function. This restores the round-trip invariant `consensus_serialize(consensus_deserialize(b)) == b`.

### Proof of Concept
```rust
// stacks-codec/src/transaction.rs (test module)
#[test]
fn tx_version_byte_does_not_round_trip() {
    // Build a normally-signed, valid Mainnet transaction.
    let privk = StacksPrivateKey::random();
    let auth = TransactionAuth::from_p2pkh(&privk).unwrap();
    let tx = StacksTransaction::new(
        TransactionVersion::Mainnet,
        auth,
        TransactionPayload::TokenTransfer(
            StacksAddress::new(0, Hash160([0xaa; 20])).unwrap().into(),
            1,
            TokenTransferMemo([0u8; 34]),
        ),
    );

    let mut tx_bytes = vec![];
    tx.consensus_serialize(&mut tx_bytes).unwrap();
    assert_eq!(tx_bytes[0], 0x00); // canonical Mainnet byte

    // Attacker mutates only the version byte's low bits (high bit stays 0 => still "Mainnet")
    let mut mutated_bytes = tx_bytes.clone();
    mutated_bytes[0] = 0x01;

    // consensus_deserialize ACCEPTS the mutated bytes.
    let decoded = StacksTransaction::consensus_deserialize(&mut &mutated_bytes[..])
        .expect("mutated version byte must be accepted per current code");

    // Re-serializing the decoded tx yields the canonical 0x00 byte, NOT the transmitted 0x01.
    let mut reserialized = vec![];
    decoded.consensus_serialize(&mut reserialized).unwrap();

    // BROKEN INVARIANT: reserialized != mutated_bytes
    assert_ne!(reserialized, mutated_bytes, "round-trip broken: reserialized bytes differ from transmitted bytes");

    // Consequence: txid() (computed via reserialization) differs from hash of raw transmitted bytes.
    let txid_from_node = decoded.txid();
    let txid_from_raw_bytes = Txid::from_stacks_tx(&mutated_bytes);
    assert_ne!(txid_from_node, txid_from_raw_bytes,
        "node's txid diverges from a naive hash of the exact bytes the attacker transmitted");
}
```
This test directly exercises the equality stated in the rules ("serialize(deserialize(b)) == b") and shows it fails for `b` with a non-canonical version byte, and additionally shows the resulting txid divergence between the node's internal `txid()` and a hash computed over the raw transmitted bytes `b`.
