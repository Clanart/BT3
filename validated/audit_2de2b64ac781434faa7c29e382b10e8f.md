### Title
Double-claim of GET-request relayer fee escrow via missing `_requestCommitments` cleanup on successful response delivery — ([File: evm/src/core/EvmHost.sol])

### Summary
`EvmHost.dispatchIncoming(GetResponse)` pays the escrowed relayer fee out of `_requestCommitments[commitment]` when a `GetResponse` is successfully delivered, but never deletes that `FeeMetadata` entry afterward. `dispatchTimeOut(GetRequestTimeout)` treats a non-zero `_requestCommitments[commitment]` entry as its only "is this request still outstanding" guard before refunding the same escrowed fee to the original payer. Because the response path leaves the entry intact, a permissionless caller can later submit a `GetRequestTimeout` message (with a non-membership proof at any historical, still-stored state height that precedes the actual response delivery but postdates the request's timeout timestamp) and trigger a second payout of the same fee.

### Finding Description
`_requestCommitments` is the escrow map used for **both** completion paths of a dispatched `GetRequest`: [1](#0-0) 

On successful response delivery, the fee is paid to the relayer but the map entry is left untouched: [2](#0-1) 

On timeout, the *only* replay guard is deleting `_requestCommitments[commitment]` right before invoking the app callback and refunding the fee to `meta.sender`: [3](#0-2) 

`HandlerV2.handleGetRequestTimeouts` gates the timeout dispatch only on:
1. `meta.sender != address(0)` (i.e., `_requestCommitments[commitment]` still exists), and
2. a non-membership proof that the destination's `ResponseReceipts` trie does not contain an entry for this commitment **at the specific proof height supplied by the caller**, with the sole freshness requirement being `request.timeout() <= state.timestamp`: [4](#0-3) 

There is no requirement that the proof height be the *latest* height, nor any check against `_responseReceipts` on the EVM host itself. Since `EvmHost.storeStateMachineCommitment` retains state commitments for all recorded heights (not just the newest) until explicitly vetoed, an attacker can pick any earlier stored height whose timestamp already exceeds the request's timeout but which predates the block where the `GetResponse` was actually delivered and its receipt written. At that earlier height the response-receipt non-membership proof is genuinely valid (the response hadn't been recorded yet), so `handleGetRequestTimeouts` passes and calls `dispatchTimeOut`, which — because `_requestCommitments[commitment]` was never cleared by the earlier successful `dispatchIncoming(GetResponse)` — refunds the escrowed fee a second time to `meta.sender`.

This is the same bug class as the Nibiru report: state that should be invalidated/consumed exactly once by one execution path (`dispatchIncoming(GetResponse)` clearing the escrow) is instead left dangling, and a second, independently-gated path (`dispatchTimeOut`) treats the stale state as still valid, causing divergent/duplicate effects depending on message ordering — a call-ordering-dependent double payout rather than a strictly deterministic one.

### Impact Explanation
This is a direct fund-duplication bug on the production `EvmHost` contract: the relayer fee escrowed for a `GetRequest` can be paid out twice — once to the relayer that delivered the `GetResponse`, and again as a "timeout refund" to the original fee payer — for the exact same request commitment. Each occurrence drains `feeToken()` balance held by the host beyond what was actually escrowed for that request, at the expense of the host's other users/protocol funds. This falls squarely under "stealing or loss of funds" and "replay/double-claim/double-settlement" in the bounty's impact gate.

### Likelihood Explanation
`handleGetRequestTimeouts` is explicitly documented as permissionless ("Access: Permissionless (can be called by anyone)"), and the attacker only needs: (1) a legitimately dispatched `GetRequest` with a nonzero fee, (2) the corresponding response already delivered via `dispatchIncoming(GetResponse)`, and (3) an already-existing, non-vetoed state commitment at some height between the request's timeout timestamp and the response's actual delivery height. No malicious relayer, prover, or governance actor is required — an honest relayer's normal timeout-submission tooling could trigger this unintentionally if it ever races against response delivery, and an attacker can deliberately withhold submitting the timeout until convenient older height data is available.

### Recommendation
Delete `_requestCommitments[commitment]` in `dispatchIncoming(GetResponse)` immediately after (or atomically with) transferring the relayer fee, mirroring the replay protection already used for POST requests (`_requestReceipts`) and for `dispatchTimeOut` itself. Additionally, `handleGetRequestTimeouts`/`dispatchTimeOut` should verify against the *latest* known response-receipt state (or otherwise ensure the non-membership proof height cannot precede a height at which the response was already recorded) rather than accepting any historical non-membership proof.

### Proof of Concept
1. App dispatches a `GetRequest` from chain A with a nonzero `fee`; `EvmHost` stores `_requestCommitments[commitment] = FeeMetadata{sender: payer, fee: F}`.
2. Hyperbridge/coprocessor produces the `GetResponse`; a relayer submits it via `HandlerV2.handleGetResponses` → `EvmHost.dispatchIncoming(GetResponse)`. This pays `F` in `feeToken()` to the relayer and sets `_responseReceipts[commitment]`, but leaves `_requestCommitments[commitment]` unchanged (still `{payer, F}`).
3. Attacker fetches a state commitment for the relevant destination height that was recorded **before** the response was delivered (still retrievable via `stateMachineCommitment(height)` since it isn't deleted unless vetoed) and whose `timestamp` already exceeds the `GetRequest`'s `timeoutTimestamp`.
4. Attacker builds a non-membership proof of `ResponseReceipts[commitment]` at that earlier height (valid, since the response hadn't been written to that snapshot) and calls `HandlerV2.handleGetRequestTimeouts`.
5. `meta.sender != address(0)` still holds because step 2 never cleared it; the non-membership proof at the chosen height verifies; `EvmHost.dispatchTimeOut` executes, deletes `_requestCommitments[commitment]`, and transfers `F` in `feeToken()` to `payer` again — a second payout of the same escrowed fee for one request.

    /**
     * @dev Dispatch an incoming GET response to source module
     * @param response - get response
     */
    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    /**
     * @dev Dispatch an incoming GET timeout to the source module.
     * @notice Does not refund any protocol fees.
     * @param timeout - timed-out get request bundled with the relayer that submitted the timeout proof
     * @param meta - fee metadata for the original request
     * @param commitment - request commitment
     */
    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
