### Title
Attacker-controlled DataLayer mirror URLs cause unvalidated automatic outbound HTTP requests (SSRF / information disclosure) - ([File: chia/data_layer/data_layer.py])

### Summary
Any wallet holder can publish a "mirror" record for **any** DataLayer store id (not necessarily one they own or created) by spending a small amount of XCH through `create_new_mirror()`, embedding arbitrary attacker-chosen strings as the mirror's `urls` memo. Any node/service that is subscribed to or owns that store automatically reads these on-chain, attacker-supplied URLs and issues real outbound HTTP connections to them without any scheme, host, or destination validation — directly analogous to CVE-2018-10583, where a malicious document caused automatic, unprompted network connections to an attacker-chosen endpoint (`file://192.168.0.2/...`), leaking information about the victim's local network.

### Finding Description
`DataLayerWallet.create_new_mirror()` creates an on-chain "mirror" coin whose puzzle is `create_mirror_puzzle()` and whose memo directly encodes `[launcher_id, *urls]` with no validation of the URL contents: [1](#0-0) 

This is exposed to any wallet user through `add_mirror`/`dl_new_mirror` RPCs with only an empty-list check, no scheme allow-list, and no check that the caller owns the target `launcher_id`: [2](#0-1) [3](#0-2) 

Once published on-chain, any DataLayer service tracking that store id pulls these mirror URLs unconditionally into its local subscription table: [4](#0-3) [5](#0-4) 

The periodic sync loop then automatically initiates outbound connections to these attacker-chosen URLs via `fetch_and_validate()` → `insert_from_delta_file()` → `download_file()` → `http_download()`, with no restriction on target host/port/scheme (beyond what `aiohttp.ClientSession().get()` will attempt): [6](#0-5) [7](#0-6) 

The `.cursor/context/data-layer.md` notes explicitly flag mirror/plugin URLs as "external trust inputs," but the trust boundary is only enforced on the *content* returned (validated against the wallet-advertised root), not on *where the request is sent* — the SSRF-style automatic connection itself is unmitigated: [8](#0-7) 

### Impact Explanation
This lets an unprivileged attacker force any DataLayer-enabled node that subscribes to (or owns) a given store to automatically make outbound TCP/HTTP connections to arbitrary internal or external addresses of the attacker's choosing, for the small cost of a mirror-coin fee. This can be used to:
- Probe/map internal network topology and reachable services behind the victim's NAT/firewall (classic SSRF information disclosure, matching the CVE's bug class).
- Fingerprint the victim node's IP/timing by directing connections to attacker-controlled listeners.
- Potentially reach internal-only HTTP endpoints (metadata services, internal admin panels) if the DataLayer service runs in a cloud/containerized environment.

This is a genuine automatic, spend-triggered network side effect reachable by any wallet user with no privileges over the target store, satisfying the "no-impact" exclusion bar because it produces concrete unauthorized network disclosure, not merely a benign side effect.

### Likelihood Explanation
Likelihood is high given how little is required: an attacker only needs to know a store's `launcher_id` (public, since DataLayer store ids/root updates are on-chain and typically advertised for discovery/subscription) and pay a small transaction fee to call `dl_new_mirror`. No ownership of the store, no privileged RPC access, and no cooperation from the victim is needed — the victim's own periodic `update_subscription()`/`fetch_and_validate()` loop does the work automatically once it observes the mirror via `dl_get_mirrors`.

### Recommendation
- Validate mirror/subscription URLs before storing or using them: enforce an allow-list of schemes (`http`/`https` only), reject loopback/link-local/private IP ranges (or require operator opt-in for private-network mirrors), and consider requiring DNS resolution checks at request time to prevent SSRF via redirects/rebinding.
- Consider restricting which URLs a subscriber will actually contact by requiring per-node operator allow-listing of mirror hosts rather than blindly trusting anything published on-chain for a tracked store.
- Rate-limit/backoff logic already exists for failed servers (`server_misses_file`), but this only mitigates repeated hits, not the initial SSRF attempt — add pre-flight validation, not just post-failure banning.

### Proof of Concept
1. Attacker identifies (or creates) a DataLayer store `launcher_id` that a victim node subscribes to (subscription/tracking is by design and store ids are shared for discovery).
2. Attacker calls `dl_new_mirror` (via the `add_mirror` RPC/CLI) specifying that `launcher_id` and `urls=["http://169.254.169.254/latest/meta-data/", "http://10.0.0.5:8080/admin"]` — see `chia/data_layer/data_layer_wallet.py:687-704` and `chia/wallet/wallet_rpc_api.py:3255-3274`, which perform no host/scheme validation.
3. Attacker's transaction confirms on chain, creating a `Mirror` coin with these URLs.
4. On the victim node, `periodically_manage_data()` → `update_subscription()` → `update_subscriptions_from_wallet()` (`chia/data_layer/data_layer.py:979-985`) pulls the malicious mirror URLs into the local subscription table (`chia/data_layer/data_store.py:1668-1704`).
5. `fetch_and_validate()` (`chia/data_layer/data_layer.py:642-694`) selects one of these server URLs and calls `insert_from_delta_file()` → `download_file()` → `http_download()` (`chia/data_layer/download_data.py:298-324`), causing the victim node to automatically issue an outbound HTTP GET to the attacker-chosen internal/external address — without any user interaction or scheme/host validation.

```python
        async with self.db_wrapper.writer() as writer:
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 1 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            old_urls = [row["url"] async for row in cursor]
            cursor = await writer.execute(
                "SELECT * FROM subscriptions WHERE from_wallet == 0 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            from_subscriptions_urls = {row["url"] async for row in cursor}
            additions = {url for url in new_urls if url not in old_urls}
            removals = [url for url in old_urls if url not in new_urls]
            for url in removals:
                await writer.execute(
                    "DELETE FROM subscriptions WHERE url == :url AND tree_id == :tree_id",
                    {
                        "url": url,
                        "tree_id": store_id,
                    },
                )

                if url not in from_subscriptions_urls:
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
