### Title
Unbounded buffer index in `is_atom_canonical`/`is_clvm_canonical` causes a spend-triggered `IndexError` crash during mempool admission - ([File: chia/full_node/mempool_manager.py])

### Summary
`is_clvm_canonical()` and its helper `is_atom_canonical()` in `chia/full_node/mempool_manager.py` parse a raw CLVM byte buffer to decide whether a coin spend's puzzle/solution serialization is "canonical," which gates DEDUP fast-forward eligibility during spend-bundle admission. Both functions index into the buffer (`clvm_buffer[offset]`) while decoding multi-byte atom length prefixes without ever checking that `offset` stays within the buffer's bounds. This mirrors the CVE-2018-1303 bug class: data is read out of the expected bounds while being "prepared"/parsed from an untrusted, attacker-controlled buffer.

### Finding Description
`is_atom_canonical()` decodes the CLVM atom length-prefix encoding directly from `clvm_buffer` at increasing offsets: [1](#0-0) 

For each of the multi-byte prefix cases (`prefix_len` from 1 to 5), the loop does:
```
for i in range(prefix_len):
    atom_len <<= 8
    offset += 1
    atom_len |= clvm_buffer[offset]
```
There is no check that `offset < len(clvm_buffer)` before this dereference. If the final byte(s) of the buffer end exactly on (or a byte prefix claims more bytes than remain in) a multi-byte length-prefix marker (e.g. `0b11111100`..`0b11111110` requiring 5 more bytes), `clvm_buffer[offset]` will index past the end of the buffer.

`is_clvm_canonical()`, the caller, has the same unguarded pattern for `clvm_buffer[offset]` at the top of its loop: [2](#0-1) 

This function is invoked on data taken directly from a submitted `SpendBundle`'s puzzle reveal/solution while `MempoolManager` decides DEDUP eligibility during `validate_spend_bundle()` admission processing: [3](#0-2) 

Because Python raises `IndexError` on out-of-range `bytes` indexing (rather than a silent C-style OOB read), a maliciously crafted puzzle reveal/solution byte sequence — a short buffer whose final byte is a length-prefix marker demanding more trailing bytes than exist — will raise an unhandled `IndexError` inside the synchronous admission path. This is directly reachable by any unprivileged party who can submit a spend bundle via `push_tx`, since `validate_spend_bundle()` is the standard entry point invoked from RPC/peer transaction handling, and the routine runs under the node's blockchain lock.

### Impact Explanation
An unhandled `IndexError` raised while the blockchain lock is held during spend-bundle validation would propagate out of `validate_spend_bundle()`/`add_spend_bundle()`. Depending on how the calling task handler manages exceptions, this can crash or wedge the transaction-processing path for the full node (denial of service against a node's mempool/transaction ingestion), matching the DoS impact class of the referenced Apache CVE ("crash the ... server ... due to an out of bound read while preparing data").

### Likelihood Explanation
Likelihood is high for a determined submitter: constructing a spend bundle whose puzzle reveal or solution bytes end mid length-prefix requires only crafting a short CLVM atom encoding, no special privileges, no signature bypass, and no consensus-level access — just a spend bundle sent to `push_tx`/mempool admission. The check exists specifically to detect non-canonical DEDUP-eligible serializations, so it is exercised on attacker-supplied bytes by design.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before each `clvm_buffer[offset]` access (and in `is_clvm_canonical()`'s main loop), returning "not canonical" (or raising a handled validation error) instead of allowing `IndexError` to propagate. Wrap the call site in `validate_spend_bundle()` in a try/except that treats malformed buffers as a normal validation failure (e.g., `Err.INVALID_SPEND_BUNDLE`) rather than letting the exception escape the admission pipeline.

### Proof of Concept
Construct a CLVM buffer whose last byte is a length-prefix marker requiring trailing length bytes that are not present, e.g.:
```python
from chia.full_node.mempool_manager import is_clvm_canonical

# 0b11111100 marker indicates a 5-byte length prefix follows,
# but the buffer ends immediately after this byte.
buf = bytes([0b11111100])
is_clvm_canonical(buf)  # raises IndexError: index out of range
```
Embedding such a byte sequence as the tail of a coin spend's puzzle reveal or solution in a submitted `SpendBundle` drives execution into this code path during `MempoolManager.validate_spend_bundle()`'s DEDUP-eligibility check, causing an unhandled `IndexError` during admission of that spend bundle.

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

```python
def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
