### Title
Gasless swapForGas admission relies on unprotected instantaneous AMM spot price, enabling same-block price manipulation to drain the underlying liquidity pool - (File: `kaiax/gasless/impl/tx_pool.go`)

### Summary
The `kaiax/gasless` module (KIP-247) lets any unprivileged sender submit a gasless `swapForGas` transaction that is admitted to the pool and later executed by paying gas via swapping ERC-20 tokens for KAIA/WKAIA through a Uniswap-V2-style router. The admission check and the on-chain contract both price the swap using the router's live reserve-based quote function (`GetAmountIn`/`GetAmountsOut`), with no TWAP, price-impact bound, or manipulation resistance — the same bug class as the RodeoFinance exploit, where a Camelot V2 spot/TWAP price feeding a financial calculation was manipulated to bypass a value check.

### Finding Description
`checkBalanceForSwap` in [1](#0-0)  enforces that a submitted `swapForGas` transaction's `amountIn` is at least `routerContract.GetAmountIn(nil, token, minAmountOut)`, i.e. a live call against the Uniswap-V2 style router's current reserves: [2](#0-1) 

This `GetAmountIn` query (Uniswap V2 constant-product formula, bound to `contracts/bindings/uniswap/router/UniswapV2Router02.go`) is not a TWAP and has no slippage/price-impact guard; it simply reflects the reserves at the moment of the call. The decoded swap arguments (`token`, `amountIn`, `minAmountOut`, `amountRepay`, `deadline`) come directly from attacker-controlled calldata via `decodeSwapTx` in [3](#0-2) , and the only invariant enforced against the true fee value is `minAmountOut >= amountRepay` where `amountRepay` is required to equal `repayAmount()` computed purely from gas price × gas used, not from any market-price safety margin: [4](#0-3) 

Because both the admission check (`GetAmountIn`) and the actual on-chain `GaslessSwapRouter.swapForGas` execute the swap against the same manipulable AMM pool, a sender who can shift the pool's reserves within the same block (e.g., by front-running with another swap against the same pool, then executing `swapForGas`, then reversing the swap) can make the `GetAmountIn` quote artificially favorable. This lets the attacker supply a token `amountIn` that is cheap relative to fair market value yet still satisfy the "sufficient input" check, extracting real KAIA/WKAIA value from the pool's liquidity providers at manipulated pricing — directly analogous to how RodeoFinance's Investor.earn() health-factor check was bypassed by manipulating a Camelot V2 pool's price used for LP valuation.

### Impact Explanation
Any transaction sender reachable via the public RPC (`gasless_isGaslessTx` / normal tx submission) or via a bundle can submit a manipulative sequence of transactions targeting the pool backing the `GaslessSwapRouter`. Successful manipulation results in unauthorized value extraction from the AMM pool's liquidity providers and/or from the KAIA reserves that back gasless fee payment, i.e., concrete unauthorized value movement analogous to the reported DeFi exploit class.

### Likelihood Explanation
Exploitability requires the attacker to have (or borrow) enough capital to move the specific token/WKAIA pool's reserves meaningfully within a single block before their `swapForGas` transaction executes, and for the module's `ShouldCheckSwapAmount()` gate to be enabled with real liquidity behind it (`GaslessConfig`, see [5](#0-4) ). This is feasible for an ordinary EN/RPC submitter given typical AMM liquidity depth, similar to the flash-loan/sandwich technique used in the RodeoFinance incident, though it is somewhat mitigated by needing same-block ordering control (e.g. via the sender's own bundle of sequential nonces) rather than arbitrary insertion.

### Recommendation
Replace or supplement the instantaneous `GetAmountIn`/`GetAmountsOut` reserve query with a manipulation-resistant price source (TWAP over multiple blocks, or a bounded maximum price-impact check per swap) both in `checkBalanceForSwap` (`kaiax/gasless/impl/tx_pool.go`) and in the on-chain `GaslessSwapRouter` contract logic that ultimately executes `swapForGas`. Additionally, consider capping per-transaction swap size relative to pool depth and rejecting swaps whose observed price deviates significantly from a longer-window reference price.

### Proof of Concept
Conceptual PoC (mirrors `RodeoTest.testExploit`):
1. Attacker deploys/funds a large swap against the token/WKAIA pool backing `GaslessSwapRouter` to shift reserves favorably (front-run leg), in the same block as their planned `swapForGas` tx (e.g., using sequential nonces or a searcher bundle).
2. Attacker submits a `swapForGas(token, amountIn, minAmountOut, amountRepay, deadline)` transaction with `amountIn` computed to just satisfy `amountIn >= GetAmountIn(token, minAmountOut)` at the manipulated reserve state (checked in `checkBalanceForSwap`, [2](#0-1) ), while `minAmountOut` is set to just cover `amountRepay` (`kaiax/gasless/impl/getter.go:361-367`).
3. Attacker reverses the initial swap (back-run leg) restoring the pool to its original price, netting profit from the artificially cheap `amountIn` accepted by the manipulated quote, at the expense of pool liquidity providers.

Note: the actual Solidity source of `GaslessSwapRouter` (KIP-247) is not present in this repository — only Go bindings (`contracts/bindings/kip247/GaslessSwapRouter.go`) and the `kaiax/gasless` Go module are indexed here, so full on-chain slippage-protection logic inside the contract itself could not be fully verified from this codebase; a Devin session with full repository access should confirm whether the on-chain contract adds any additional TWAP/price-impact protection beyond what `checkBalanceForSwap` performs.

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}
