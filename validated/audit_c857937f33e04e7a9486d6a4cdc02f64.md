### Title
Unbounded cycle in `object::root_owner()` allows permanent Denial-of-Service on code-object publish/upgrade (via `code::publish_package`'s lazy-init owner recording) - (File: `aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
`object::root_owner()` walks the object ownership chain with no depth bound or cycle guard, unlike the sibling functions `owns()` and `verify_ungated_and_descendant()`, which both enforce `MAXIMUM_OBJECT_NESTING`. An object owner can legitimately construct a 2-object ownership cycle using only the standard `transfer`/`transfer_raw` entry points, because those functions validate that the caller currently, transitively owns the object being moved, but never validate that the new destination is not itself a descendant of that object. Once a cycle exists, any call to `root_owner()` on either object infinite-loops until the transaction runs out of gas. This function is invoked unconditionally by `code::publish_package` when publishing/upgrading a package to an object address with the `LAZY_MODULE_INITIALIZATION` feature enabled, and by `init::assert_may_self_initialize` on every lazy self-init call — turning a client-side ownership mistake/attack into a permanent inability to publish, upgrade, or freeze code at that object address.

### Finding Description
`root_owner()` is defined with an unguarded `while` loop: [1](#0-0) 

Compare this to `owns()` and `verify_ungated_and_descendant()`, both of which use a `count`/`MAXIMUM_OBJECT_NESTING` guard specifically because "objects may have cyclic dependencies": [2](#0-1) [3](#0-2) 

A cycle can be created with ordinary, unprivileged transfer calls: `transfer_raw` only checks that the object being moved is currently (transitively) owned by the signer — it places no constraint on the destination address: [4](#0-3) 

Concretely: an account `A` creates `Obj1` (owner = `A`) and `Obj2` (owner = `A`). `A` transfers `Obj1` to `Obj2` (now `Obj1.owner = Obj2`; still transitively owned by `A`). `A` then transfers `Obj2` to `Obj1` — `verify_ungated_and_descendant(A, Obj2)` passes because `Obj2.owner == A` directly — producing `Obj2.owner = Obj1`. The result is a genuine 2-cycle: `Obj1 → Obj2 → Obj1`, with no account at the root.

`root_owner()` is invoked in the code-publishing path in `code::publish_package`, specifically for the lazy module-initialization owner bookkeeping: [5](#0-4) 

and again on every self-init check in `init::assert_may_self_initialize`: [6](#0-5) 

If either `Obj1` or `Obj2` (or any code object nested under such a cycle) hosts a package, calling `code::publish_package` (i.e. publishing, upgrading, or the dependency-check pass in `freeze_code_object`) with the `LAZY_MODULE_INITIALIZATION` feature enabled will call `root_owner()` on the cyclic chain, causing the transaction to loop until gas is exhausted and abort — permanently, since the on-chain cycle persists across attempts.

### Impact Explanation
This breaks a publish-path code-safety invariant: `code::publish_package` (used for both first publish and every subsequent upgrade under `object_code_deployment::publish/upgrade`, and by `freeze_code_object`) can be made permanently un-callable for a given code object once an attacker (or the object owner acting against their own future ability to upgrade, or a bug in tooling that inadvertently creates such a chain) sets up a two-node ownership cycle involving that code object's address. Because the write-set/publish flow reaches this native/Move code before any module bytes are validated or stored, the effect is denial of code upgrade/freeze/publish for that address — an availability failure in the on-chain code-management invariant "upgrade authority holders must still be able to exercise upgrade/freeze," classified as High under the Publish Impact Gate ("verifier, module-init, native validation, or write-set-publish failure that reaches protected state mutation").

### Likelihood Explanation
Triggering the cycle requires only two ordinary `object::transfer` calls by whoever owns the two objects involved (no special privilege). The DoS only manifests when the `LAZY_MODULE_INITIALIZATION` feature flag is enabled (it is off by default per test harness comments: `MoveHarness::new_with_features(vec![FeatureFlag::LAZY_MODULE_INITIALIZATION], vec![])`), so current mainnet relevance depends on that flag's rollout status, which could not be verified from the code searched. Regardless of feature rollout, the underlying `root_owner()` unbounded-loop bug is a genuine defect independent of any external report and is directly reachable from the publish path once the feature is active.

### Recommendation
Bound `root_owner()`'s traversal the same way `owns()` and `verify_ungated_and_descendant()` are bounded, e.g.:
```move
public fun root_owner<T: key>(self: Object<T>): address {
    let obj_owner = self.owner();
    let count = 0;
    while (is_object(obj_owner)) {
        count += 1;
        assert!(count < MAXIMUM_OBJECT_NESTING, error::out_of_range(EMAXIMUM_NESTING));
        obj_owner = address_to_object<ObjectCore>(obj_owner).owner();
    };
    obj_owner
}
```
Additionally, consider preventing cycle creation at transfer time (e.g., have `transfer_raw`/`transfer` reject a `to` that is a descendant of `object`), which would close the root cause rather than only bounding its consequence.

### Proof of Concept
1. Enable `FeatureFlag::LAZY_MODULE_INITIALIZATION`.
2. Account `A` calls `object::create_object(A)` twice to get `Obj1`, `Obj2` (both owned by `A`, `allow_ungated_transfer = true`).
3. `A` calls `object::transfer(A, Obj1, Obj2_addr)` → `Obj1.owner = Obj2`.
4. `A` calls `object::transfer(A, Obj2, Obj1_addr)` → passes `verify_ungated_and_descendant(A, Obj2_addr)` trivially since `Obj2.owner == A`; sets `Obj2.owner = Obj1`. Now `Obj1 ⇄ Obj2` cycle exists.
5. Deploy a package to `Obj1` (e.g. via `object_code_deployment::publish`) so `code::publish_package` records `deploy_owner` via `object::address_to_object<ObjectCore>(Obj1).root_owner()`. This call now loops indefinitely over `Obj1 → Obj2 → Obj1 → …` until the transaction's gas is exhausted, aborting every publish/upgrade/freeze attempt against `Obj1`. [1](#0-0) [5](#0-4)

    /// This checks that the destination address is eventually owned by the owner and that each
    /// object between the two allows for ungated transfers. Note, this is limited to a depth of 8
    /// objects may have cyclic dependencies.
    fun verify_ungated_and_descendant(owner: address, destination: address) {
        let current_address = destination;
        assert!(
            exists<ObjectCore>(current_address),
            error::not_found(EOBJECT_DOES_NOT_EXIST),
        );

        let object = borrow_global<ObjectCore>(current_address);
        assert!(
            object.allow_ungated_transfer,
            error::permission_denied(ENO_UNGATED_TRANSFERS),
        );

        let current_address = object.owner;
        let count = 0;
        while (owner != current_address) {
            count += 1;
            assert!(count < MAXIMUM_OBJECT_NESTING, error::out_of_range(EMAXIMUM_NESTING));
            // At this point, the first object exists and so the more likely case is that the
            // object's owner is not an object. So we return a more sensible error.
            assert!(
                exists<ObjectCore>(current_address),
                error::permission_denied(ENOT_OBJECT_OWNER),
            );
            let object = borrow_global<ObjectCore>(current_address);
            assert!(
                object.allow_ungated_transfer,
                error::permission_denied(ENO_UNGATED_TRANSFERS),
            );
            current_address = object.owner;
        };
    }

    /// Return true if the provided address has indirect or direct ownership of the provided object.
    ///
    /// Note: intentionally not using `self` as first argument, as a.owns(b) syntax would be ambiguous.
    public fun owns<T: key>(object: Object<T>, owner: address): bool {
        let current_address = object.object_address();

        assert!(
            exists<ObjectCore>(current_address),
            error::not_found(EOBJECT_DOES_NOT_EXIST),
        );

        if (current_address == owner) {
            return true
        };

        let object = borrow_global<ObjectCore>(current_address);
        let current_address = object.owner;

        let count = 0;
        while (owner != current_address) {
            count += 1;
            assert!(count < MAXIMUM_OBJECT_NESTING, error::out_of_range(EMAXIMUM_NESTING));
            if (!exists<ObjectCore>(current_address)) {
                return false
            };

            let object = borrow_global<ObjectCore>(current_address);
            current_address = object.owner;
        };
        true
    }
