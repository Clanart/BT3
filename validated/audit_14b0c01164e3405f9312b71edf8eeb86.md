## Title
Global singleton `SignInStore` state allows a concurrent credential-helper prompt to clobber (and hijack) another in-flight GitHub sign-in flow - (File: `app/src/lib/stores/sign-in-store.ts`)

### Summary
The reported yToken.sol issue is a classic reentrancy pattern: an external call is made before the contract finalizes/guards its own state, letting the callee re-enter and corrupt shared state. The closest verified analog in GitHub Desktop is not a memory-safety bug but a *shared, unscoped singleton state* bug: `SignInStore` keeps a single `this.state` field for the entire application, and `beginDotComSignIn` / `beginEnterpriseSignIn` unconditionally call `this.reset()`/`this.setState()` on that shared field whenever invoked, discarding whatever sign-in flow (and its `resultCallback`) was already in progress [1](#0-0) . This function is reachable from git-credential-helper trampoline processing, which is driven by an attacker-influenced remote/host (`trampolineUIHelper.promptForGitHubSignIn`) [2](#0-1) , which in turn is triggered whenever Git needs credentials for an unknown "GitHub-looking" host while fetching/cloning/pulling — including hosts discovered through submodule URLs, LFS endpoints, or repository content that Desktop cannot fully control the timing of [3](#0-2) .

### Finding Description
`getCredential()` in `trampoline-credential-helper.ts` calls `ui.promptForGitHubSignIn(endpoint)` whenever the credential helper decides an unrecognized remote endpoint "looks like" a GitHub Enterprise host (based on `WWW-Authenticate` headers or a network probe in `isGitHubHost`) and no account exists for it yet [4](#0-3) [5](#0-4) .

`promptForGitHubSignIn` calls into the single global `Dispatcher`/`SignInStore`:
```
if (hostname === 'github.com') {
  this.dispatcher.beginDotComSignIn(cb)
} else {
  this.dispatcher.beginEnterpriseSignIn(cb)
  await this.dispatcher.setSignInEndpoint(origin)
}
this.dispatcher.showPopup({ type: PopupType.SignIn, ... credentialHelperUrl: endpoint })
``` [6](#0-5) 

`beginEnterpriseSignIn` (and `beginDotComSignIn`) reset the *singleton* `this.state` and overwrite the `resultCallback` field it holds, without any per-request/per-token identity:
```
public beginEnterpriseSignIn(resultCallback?: (result: SignInResult) => void) {
  if (this.state !== null) {
    this.reset()
  }
  this.setState({ kind: SignInStep.EndpointEntry, ..., resultCallback: resultCallback ?? noop })
}
``` [1](#0-0) 

Because the trampoline server spawns a *new askpass/credential-helper connection per subprocess* and multiple Git subprocesses (parallel submodule fetches, LFS smudge filters, concurrent fetch/clone operations) can be in flight at once, each hitting `trampolineServer.processCommand` independently and awaiting its own handler [7](#0-6) , nothing prevents two `getCredential()` calls for two *different* endpoints from being in-flight concurrently. If Endpoint A (e.g. a legitimate GHE server the user is trying to sign into) triggers `beginEnterpriseSignIn(cbA)` and, before the user finishes that flow, Endpoint B (attacker-controlled host discovered via a malicious submodule URL, LFS endpoint, or crafted redirect that satisfies `isGitHubHost`'s heuristics) triggers a second `getCredential()` call, the second call's `beginEnterpriseSignIn(cbB)`/`beginDotComSignIn(cbB)` will call `this.reset()` and overwrite `this.state.resultCallback` with `cbB` — silently discarding `cbA` and re-pointing the *entire in-progress OAuth/PAT sign-in UI* (which the user is still looking at, still believing corresponds to Endpoint A) to resolve into `cbB`, i.e. the attacker-influenced endpoint's credential request. There is no guard comparable to `trampolineTokens`' per-operation token set (`app/src/lib/trampoline/trampoline-tokens.ts`) protecting `SignInStore.state`; the "check-then-act" (`if (this.state !== null) reset()` then `setState(...)`) is exactly the reentrancy-style broken invariant: an attacker-triggered second call is allowed to intervene between the first call's state guard and its resolution.

### Impact Explanation
If successful, the token/credential the user believes they are granting to a trusted endpoint (e.g., their real GHE instance) can instead be delivered to `getCredential()`'s caller for the attacker-controlled endpoint, because `resultCallback` was swapped underneath the still-open `PopupType.SignIn` dialog. This is a form of unauthorized account/credential binding: the user's OAuth/PAT completion gets routed to an endpoint they did not intend, potentially exfiltrating a valid GitHub/GHE access token to an attacker-controlled host via the credential helper's `formatCredential`/`git credential` protocol response [8](#0-7) . This matches the valid-impact category "unauthorized OAuth or account binding" / "credential/token exfiltration."

### Likelihood Explanation
This requires precise timing: two concurrent credential-helper requests for two different unauthenticated "GitHub-like" hosts, one legitimate and one attacker-controlled, arriving close enough together that the user has not yet completed the first sign-in dialog when the second overwrites `SignInStore.state`. Such concurrency is plausible during operations that spawn many git subprocesses in parallel (submodule recursion, LFS batch fetch, background fetch racing with a user-initiated clone of a different repo containing a malicious submodule/LFS endpoint), but it is not trivially triggerable by a single crafted repository in isolation, and depends on `isGitHubHost`'s heuristics classifying the attacker's host as GitHub-like and on the user actively being mid-flow on a legitimate enterprise sign-in at that moment. I was not able to fully verify, from the indexed portions of the codebase, whether the UI additionally blocks/queues a second `PopupType.SignIn` popup while one is already open (which would reduce but not eliminate the underlying state-clobbering issue, since `resultCallback` is overwritten regardless of popup stacking behavior).

### Recommendation
Scope `SignInStore` state per sign-in request instead of using a single global mutable field, e.g., key in-flight sign-in sessions by a unique request/trampoline token (mirroring `trampolineTokens.ts`'s per-operation token set) and reject/queue a `beginEnterpriseSignIn`/`beginDotComSignIn` call that would clobber another still-active session's `resultCallback` rather than silently resetting it. Additionally, `promptForGitHubSignIn` should verify that the endpoint associated with the eventual `resultCallback` invocation still matches the endpoint that initiated the request before returning the account/token pair to `getCredential()`.

### Proof of Concept
1. Attacker prepares Repository X containing a `.gitmodules` entry (or Git LFS `.lfsconfig`) pointing at `https://attacker-lookalike-ghe.example` — a host that mimics enough GitHub Enterprise signals (e.g. returns a `WWW-Authenticate` header with `realm="GitHub"`, satisfying `getEndpointKind`'s heuristic at `app/src/lib/trampoline/trampoline-credential-helper.ts:153-165`) to be classified as `'enterprise'`.
2. Victim, who has a real (unauthenticated-yet) GHE server `https://victim-ghe.example` they are in the process of signing into via Desktop (dialog open, waiting for OAuth callback), clones/fetches Repository X (or a repository referencing it as a submodule) at the same time, causing a submodule/LFS fetch to `attacker-lookalike-ghe.example`.
3. The credential helper for the submodule fetch calls `getCredential()` → `ui.promptForGitHubSignIn('https://attacker-lookalike-ghe.example')` → `dispatcher.beginEnterpriseSignIn(cbAttacker)`, which resets `SignInStore.state` and overwrites `resultCallback` with `cbAttacker`, all while the victim's still-open sign-in popup for `victim-ghe.example` is bound to the same underlying `SignInStore.state.resultCallback`.
4. When the victim completes OAuth/PAT entry in the (still visually labeled as victim-ghe.example, if the popup itself wasn't refreshed) dialog, `SignInStore` resolves with the now-overwritten `resultCallback`, i.e. `cbAttacker`, delivering the freshly minted account/token to the credential helper flow for `attacker-lookalike-ghe.example`, which returns it to the Git subprocess as the credential for that untrusted host — exfiltrating the token off-network to the attacker's server via subsequent Git operations against it.

Note: full confirmation of exploitability requires dynamic testing of popup-stacking behavior and the exact conditions under which `isGitHubHost`/`getEndpointKind` classify an attacker host as `'enterprise'`; these were inspected via static code only.

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}

export const formatCredential = (credential: Map<string, string>) => {
  const lines = []
  for (const [k, v] of credential) {
    if (v.includes('\n') || v.includes('\0')) {
      throw new Error(`forbidden characters in credential value: ${k}`)
    }
    lines.push(`${k.replace(/\[\d+\]$/, '[]')}=${v}\n`)
  }

  return lines.join('')
}
