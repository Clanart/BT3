### Title
Race between `consume_stop_state` clear and `restore_unreviewed_stop_state` restore lets a concurrent UPS baseline capture permanently hide unreviewed edits - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`handle_stop_hook` reads and clears `touched_paths` via `consume_stop_state`, and only restores them via `restore_unreviewed_stop_state` after a possibly slow transient-failure check (`ensure_anthropic_reachable`). If the next turn's `UserPromptSubmit` (`handle_user_prompt_submit`) fires during this window, its "preservation guard" sees an already-emptied `touched_paths` list and advances `baseline_sha` to a fresh `git stash create` snapshot that already contains the unreviewed edit. When `restore_unreviewed_stop_state` finally runs, it restores `touched_paths` but does **not** roll back `baseline_sha` because its guard only fires `if baseline_sha and not state.get("baseline_sha")` — i.e., it only fills in a baseline when none exists, not when a newer one has already raced ahead. On the next Stop fire, `compute_v2_review_set` diffs against this advanced baseline, so the previously-touched dangerous file no longer appears in `changed_since`, and it is silently dropped from `review_set` even though it is still uncommitted/dirty and still recorded in `touched_paths`.

### Finding Description
The intended invariant (per the `restore_unreviewed_stop_state` docstring) is: "the next UPS would see an empty list, fall through the preservation guard, and re-baseline past the unreviewed edits. Restoring keeps the guard armed" [1](#0-0) . But this only re-arms `touched_paths`; it does not protect `baseline_sha` from having already advanced.

Sequence:
1. Turn N: UPS captures `baseline_sha = B1` [2](#0-1) . Claude edits a dangerous file; `PostToolUse` calls `record_touched_path`.
2. `Stop` fires (asyncRewake) and calls `consume_stop_state`, which atomically snapshots `touched_paths` and clears it on disk (`state["touched_paths"] = []`) but leaves `baseline_sha` untouched at `B1` [3](#0-2) .
3. `Stop` then hits `ensure_anthropic_reachable()` failure (a transient condition) and calls `_skip(10, restore=True)`, which invokes `restore_unreviewed_stop_state(session_id, touched_paths, snap_baseline)` [4](#0-3) .
4. In the window between step 2 and step 3, if the user (or Claude, prompted by adversarial content) submits the next turn, `handle_user_prompt_submit` runs. Its preservation guard checks `if state.get("touched_paths") and state.get("baseline_sha")` — but `touched_paths` on disk is currently `[]` (cleared in step 2), so the guard does **not** trip, and UPS overwrites `baseline_sha` to a fresh `B2 = git stash create` snapshot that already includes the Turn-N edit [5](#0-4) .
5. `restore_unreviewed_stop_state` now runs (step 3) and restores `touched_paths` (merging the dangerous file back in), but its baseline-restore line `if baseline_sha and not state.get("baseline_sha"): state["baseline_sha"] = baseline_sha` is a no-op because `state["baseline_sha"]` is already truthy (`B2`) [6](#0-5) .
6. On the next Stop fire, `compute_v2_review_set(cwd, baseline_sha=B2, ...)` computes `changed_since = _git_name_only(repo, B2)`. Since the dangerous file's content already matches the `B2` snapshot (no further edits made to that specific file during turn N+1), it is excluded from `changed_since`, and `review_set = dirty_now & changed_since` drops it even though `dirty_now` (git status vs HEAD) and `touched_paths` both still include it [7](#0-6) .

The result: the dangerous, still-uncommitted change is never diffed/reviewed by the LLM security check, and Stop hook silently skips with `skip_reason=9` ("empty review set") [8](#0-7) , letting the change through without the `exit(2)` guidance/blocking that the Stop hook normally provides.

### Impact Explanation
This breaks the stated invariant that "the review set must stay bound to the right repo, baseline, and touched paths." A dangerous edit (e.g., a command-injection payload, a malicious script, or a change that weakens security-hook config) made during a turn whose Stop hook hit a transient failure can be permanently excluded from LLM security review if a new turn's UPS races the baseline forward before the restore completes. Since the Stop hook's LLM review is the mechanism that forces Claude to reconsider/fix flagged risky code (`exit(2)` + guidance), silently dropping the file from the review set causes an unreviewed dangerous change to proceed as if it were pre-existing/old — matching the "Unauthorized local command execution that bypasses Claude Code approval or deny controls" impact category, since the security-guidance layer is one of the local gates meant to catch such changes before they execute or get committed.

### Likelihood Explanation
This requires: (1) a transient failure hitting the specific `restore=True` skip path (`ensure_anthropic_reachable` failing, e.g., transient network issue to `api.anthropic.com`), and (2) a next-turn `UserPromptSubmit` firing in the narrow window between `consume_stop_state`'s clear and `restore_unreviewed_stop_state`'s restore. This is a genuine TOCTOU race rather than a deterministically attacker-triggered path — the attacker (adversarial repo content via prompt injection) cannot directly force network unreachability or precisely time the race, but can increase the odds by prompting Claude to continue quickly, or by exploiting normal session/network flakiness. It is timing-dependent and not reliably reproducible on demand, which lowers, but does not eliminate, real-world exploitability.

### Recommendation
Make `restore_unreviewed_stop_state` unconditionally restore the pre-Stop baseline (not just fill it in when absent), or better: have it detect that `state["baseline_sha"]` has advanced past `snap_baseline` (e.g., by comparing SHAs or storing a monotonic epoch/version) and revert it to `snap_baseline` in that case, so a racing UPS cannot silently absorb an unreviewed edit into the new baseline. Alternatively, close the race at the source: have `handle_user_prompt_submit`'s preservation guard check a persisted "last consumed but not yet reviewed" flag rather than the momentarily-empty on-disk `touched_paths`, so the guard stays armed across the `consume_stop_state` → `restore_unreviewed_stop_state` window.

### Proof of Concept
Integration/invariant test plan (pytest style, using existing session_state helpers):
1. Simulate Turn N: call `save_baseline_sha(session_id, B1)`, `record_touched_path(session_id, "dangerous.py")`, and make an uncommitted edit to `dangerous.py` in a fresh git repo fixture.
2. Call `consume_stop_state(session_id)` to snapshot and clear `touched_paths` (simulating Stop hook start), capturing `snap_baseline = B1`.
3. Before calling `restore_unreviewed_stop_state`, simulate a racing UPS: call the UPS `_save` logic directly (or `handle_user_prompt_submit`) which sees `touched_paths == []` on disk and overwrites `baseline_sha` to `B2 = capture_git_baseline(cwd)` (now including `dangerous.py`'s edit).
4. Now call `restore_unreviewed_stop_state(session_id, ["dangerous.py"], B1)`.
5. Assert: `load_baseline_sha(session_id) == B2` (not `B1`) — demonstrating the baseline was NOT rolled back despite the restore call.
6. Call `compute_v2_review_set(cwd, B2, head_at_capture, {})` and assert `"dangerous.py"` is **absent** from the returned `review_paths`, even though the file is still dirty (`git status` shows it modified) and was in `touched_paths` — proving the dangerous change is skipped from review, violating the "review set stays bound to touched paths" invariant.

```python
def restore_unreviewed_stop_state(session_id, paths, baseline_sha):
    """Put consumed touched_paths back so the next Stop reviews them.

    consume_stop_state cleared touched_paths on disk; if Stop then exits
    early for a transient reason (CCR API unreachable, Haiku HTTP error)
    the next UPS would see an empty list, fall through the preservation
    guard, and re-baseline past the unreviewed edits. Restoring keeps the
    guard armed. Prepend+dedupe so any concurrent next-turn PostToolUse
    appends survive.
    """
    if not paths:
        return

    def _restore(state):
        existing = state.get("touched_paths", [])
        merged = list(dict.fromkeys(list(paths) + list(existing)))
        if len(merged) > 200:
            merged = merged[:200]
        state["touched_paths"] = merged
        if baseline_sha and not state.get("baseline_sha"):
            state["baseline_sha"] = baseline_sha
    with_locked_state(session_id, _restore)
```
