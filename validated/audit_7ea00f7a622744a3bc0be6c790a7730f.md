### Title
`HostManager.onAccept` authenticates the cross-chain governance message by source **chain** only, never by source **module** - ([File: evm/src/core/HostManager.sol])

### Summary
`HostManager.onAccept` is the sole entry point through which the Hyperbridge (Nexus) parachain instructs a connected EVM chain to withdraw accrued protocol/relayer revenue or overwrite the entire `HostParams` struct of `EvmHost` (fee token, admin, handler, hostManager, consensus client, challenge period, whitelisted state machines, etc.). The only authentication performed is that the ISMP `PostRequest.source` state machine equals the configured `hyperbridge` id. It never checks `PostRequest.from`, i.e. which pallet/module on that chain actually dispatched the message. This is the same class of defect as the LlamaCore report: a coarse-grained identity check (any role / any chain-level sender) is substituted for the fine-grained check the security model actually requires (the specific approval role / the specific privileged module).

### Finding Description
`HostManager.onAccept` in `evm/src/core/HostManager.sol`: [1](#0-0) 

only verifies:
1. `msg.sender == host` (via `restrict(_params.host)`), and
2. `request.source.equals(IHost(_params.host).hyperbridge())`.

It then blindly decodes `request.body[0]` into `OnAcceptActions` and forwards to `IHostManager(host).withdraw(...)` or `updateHostParams(...)` — both privileged calls on `EvmHost` gated only by `restrict(_hostParams.hostManager)`: [2](#0-1) [3](#0-2) 

`request.source` only proves *which chain* the message originated from (Hyperbridge/Nexus). It says nothing about which module on that chain produced it. On the Hyperbridge/Nexus side, the intended sole originator is `pallet-ismp-host-executive`, which is gated by `T::HostExecutiveOrigin::ensure_origin` (root/governance) and stamps `from: PALLET_ID.to_bytes()`: [4](#0-3) 

However, **any** pallet on that same chain that has access to `IsmpDispatcher::dispatch_request` can construct an outgoing `DispatchPost` with an attacker/pallet-chosen `to` (module/contract address on the destination) and an arbitrary `body`, all stamped with `source = host_state_machine()` by the dispatcher itself — a value `HostManager.onAccept` will always accept. The demo pallet illustrates the exact shape of this unrestricted, signed-extrinsic dispatch path: [5](#0-4) 

Here `params.module` (destination address) is fully attacker-controlled, and the message reaches `dest = StateMachine::Evm(params.destination)` with `from = PALLET_ID.to_bytes()` (a module identity that is *not* the host-executive's). If this or any future permissionless/module-scoped pallet on the Nexus chain is able to (a) target an arbitrary `to` address and (b) control the request body, it can produce a `PostRequest` that is bit-for-bit indistinguishable — under `HostManager.onAccept`'s check — from a genuine governance instruction, because `HostManager` never verifies `request.from`. The intents coprocessor pallet shows the same generic pattern of dispatching to an attacker/caller-chosen `to: H160` with a caller/pallet-composed `body`: [6](#0-5) 

Compare this to `pallet_ismp::dispatcher::HyperbridgeWithdrawalModule::on_accept`, which correctly narrows trust to a specific configured module (`T::Coprocessor`) rather than merely the source chain: [7](#0-6) 

`HostManager.onAccept` has no equivalent check against a specific expected `from` (e.g., `HOST_EXECUTIVE_PALLET_ID`).

### Impact Explanation
`HostManager` fans out into two maximally privileged actions on every connected `EvmHost`:
- `withdraw(WithdrawParams)` — sends the accrued fee-token/native balance of the entire host contract to an attacker-chosen `beneficiary`, for an attacker-chosen `amount` and `token` (limited only by `IERC20.safeTransfer`/native-transfer success), directly draining protocol/relayer revenue held by `EvmHost`.
- `updateHostParams(HostParams)` — rewrites `admin`, `handler`, `consensusClient`, `hostManager`, `feeToken`, `challengePeriod`, `unStakingPeriod`, and the whitelisted `stateMachines` set. Overwriting `handler`/`consensusClient`/`hostManager` to attacker-controlled contracts would let an attacker subsequently forge state commitments, bypass challenge periods, or redirect all future governance/withdraw traffic — a full compromise of the bridge's trust root on that chain.

Both are exactly the "false state acceptance / unauthorized execution / stealing or loss of funds" classes the bounty targets, reachable purely because the destination-side authorization check is scoped to the wrong granularity (chain, not module).

### Likelihood Explanation
The exploitability depends on whether any pallet with (1) a permissionless/low-privilege call path, (2) an attacker- or pallet-controlled `to` address, and (3) attacker- or pallet-composed `body` bytes exists (or is later added) on the production Nexus/Hyperbridge runtime with access to the shared `IsmpDispatcher`. The repository's own example/demo and intents-coprocessor pallets demonstrate this exact shape (`dispatch_to_evm`, `dispatch`) is an established and even documented pattern for building Hyperbridge-integrated pallets, meaning the pattern is expected to recur across pallets, not a one-off. Regardless of whether `pallet-ismp-demo` itself is deployed on mainnet Nexus, the underlying `HostManager` contract deployed on every connected EVM chain contains this authorization gap today and will accept a forged governance message from *any* current or future non-governance module on Hyperbridge/Nexus, making this a structural defect rather than a one-time misconfiguration.

### Recommendation
Add an explicit module-identity check in `HostManager.onAccept`, analogous to `HyperbridgeWithdrawalModule::on_accept`'s `Coprocessor` check:
```solidity
bytes constant HOST_EXECUTIVE_MODULE_ID = ...; // fixed, matches PALLET_ID on Nexus
...
function onAccept(IncomingPostRequest calldata incoming) external override restrict(_params.host) {
    PostRequest calldata request = incoming.request;
    if (!request.source.equals(IHost(_params.host).hyperbridge())) revert UnauthorizedAction();
    if (keccak256(request.from) != keccak256(HOST_EXECUTIVE_MODULE_ID)) revert UnauthorizedAction();
    ...
}
```
`HOST_EXECUTIVE_MODULE_ID` should be configurable (like `hyperbridge()`/`hostManager()`) rather than hard-coded, so it can be rotated the same way other host params are, but it must always be checked, not merely optional.

### Proof of Concept
1. On Hyperbridge/Nexus, any signed account (or any pallet reachable by an unprivileged extrinsic) calls a dispatch entry point that builds a `DispatchPost{ dest: StateMachine::Evm(<target_chain>), from: <arbitrary_non_host_executive_module_id>, to: <HostManager_address_on_target_chain>, body: <0x00 || abi.encode(WithdrawParams{ beneficiary: attacker, amount: type(uint256).max, token: feeToken })> }` and dispatches it via `IsmpDispatcher::dispatch_request` (the pattern shown in `modules/pallets/demo/src/lib.rs::dispatch_to_evm` / `modules/pallets/intents-coprocessor/src/lib.rs::dispatch`, both of which let the caller/pallet control `to` and `body`).
2. The ISMP dispatcher stamps `source = host_state_machine()` (Nexus's own state machine id) on the outgoing request, per protocol invariant.
3. A relayer delivers the request; on the destination `EvmHost.dispatchIncoming` forwards to `HostManager.onAccept`.
4. `HostManager.onAccept` checks only `request.source.equals(hyperbridge())`, which is true (it always is, for any Nexus-originated message), and never checks `request.from`.
5. The action byte `0x00` decodes to `OnAcceptActions.Withdraw`; `IHostManager(host).withdraw(withdrawParams)` executes, transferring the host's fee-token balance to the attacker-controlled `beneficiary`.

I could not directly confirm from the indexed contents whether `pallet-ismp-demo` (or another pallet with fully attacker/pallet-controlled `to`+`body`) is included in the actual mainnet Nexus runtime configuration (as opposed to `gargantua`/testnet runtimes) — a Devin session with full repo/runtime-config access would be needed to enumerate every pallet wired into the Nexus `construct_runtime!` and confirm at least one has this call shape in production.

    function onAccept(IncomingPostRequest calldata incoming) external override restrict(_params.host) {
        PostRequest calldata request = incoming.request;
        // Only the Hyperbridge parachain can send requests to this module.
        if (!request.source.equals(IHost(_params.host).hyperbridge())) revert UnauthorizedAction();

        OnAcceptActions action = OnAcceptActions(uint8(request.body[0]));
        if (action == OnAcceptActions.Withdraw) {
            // This is where governance & relayers can withdraw their revenue.
            WithdrawParams memory withdrawParams = abi.decode(request.body[1:], (WithdrawParams));
            IHostManager(_params.host).withdraw(withdrawParams);
        } else if (action == OnAcceptActions.SetHostParam) {
            HostParams memory hostParams = abi.decode(request.body[1:], (HostParams));
            IHostManager(_params.host).updateHostParams(hostParams);
        }
    }
