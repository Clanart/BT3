## Title
Broken forfeiture logic in `mWOMSVBaseRewarder._calExpireForfeit` allows 100% reward claim during unlock cooldown, stealing yield reserved for fully-locked stakers - (File: `rewards/mWOMSVBaseRewarder.sol`)

### Summary
`mWOMSVBaseRewarder._calExpireForfeit` never queries `mWomSV.getRewardablePercentWAD(_account)`, unlike its sibling implementation in `vlMGPBaseRewarder.sol`. As written, it always computes `rewardableAmount = _amount` and therefore `forfeitAmount = 0` for every account, regardless of whether the account is still fully locked or already in `startUnlock` cooldown. This means the reward-forfeiture mechanism designed to penalize/reduce rewards for users who begin unlocking (and redistribute the forfeited portion to fully-locked, "loyal" stakers) never functions.

### Finding Description
In `rewards/mWOMSVBaseRewarder.sol`, `_sendReward` computes the amount to forfeit via `_calExpireForfeit`: [1](#0-0) 

`_calExpireForfeit` is supposed to reduce a user's payable reward proportionally to how much of their `mWomSV` balance is in cooldown/unlocking (as `vlMGPBaseRewarder._calExpireForfeit` correctly does by multiplying by `vlMGP.getRewardablePercentWAD(_account)`): [2](#0-1) 

But the `mWOMSVBaseRewarder` version omits the call to `mWOMSV.getRewardablePercentWAD(_account)` entirely, setting `rewardableAmount = _amount` unconditionally, so `forfeitAmount` is always `0`: [3](#0-2) 

`mWomSV.getRewardablePercentWAD` exists and correctly computes a percent < 1e18 for accounts with amounts in cooldown (via `startUnlock`), so the intended design is clearly to scale down rewards for such accounts: [4](#0-3) 

Because the forfeiture calculation is dead/no-op code, any account — including one that has called `lock()` then immediately `startUnlock(fullBalance)` to enter cooldown — still receives 100% of `userRewards[token][account]` when reward distribution eventually reaches `_sendReward` (e.g., via `getReward`, which is `onlyMasterMagpie`-gated but reachable through MasterMagpie's permissionless claim/multiclaim flow that any staker can trigger for themselves). No existing modifier (`onlyMasterMagpie`, `updateReward`) prevents this, since none of them re-check unlock status — the vulnerability is purely in the missing percentage lookup.

### Impact Explanation
This is a theft/misappropriation of unclaimed yield: forfeited rewards are meant to be re-queued into the pool via `_queueNewRewardsWithoutTransfer(forfeitAmount, _rewardToken)`, increasing `rewardPerTokenStored` for remaining fully-locked stakers. Since `forfeitAmount` is always `0`, that redistribution never occurs, and any user in cooldown (who should receive a reduced, time-weighted share) instead extracts their full accrued reward — permanently diverting yield that fully-locked accounts were entitled to. This matches the "theft of unclaimed yield" impact class.

### Likelihood Explanation
This requires no special privilege or capital beyond holding some `mWOM`/`mWomSV` balance: any depositor can call `lock`, `startUnlock`, then trigger a reward claim. It is deterministic and repeatable for every claim cycle, on every account, since the bug is unconditional (not dependent on timing or race conditions) — the forfeiture logic simply never activates for anyone in this reward pool.

### Recommendation
Fix `_calExpireForfeit` in `rewards/mWOMSVBaseRewarder.sol` to mirror `vlMGPBaseRewarder.sol`'s logic: `uint256 rewardablePercentWAD = mWOMSV.getRewardablePercentWAD(_account); uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;` before computing `forfeitAmount = _amount - rewardableAmount`.

### Proof of Concept
Hardhat test plan:
1. Deploy `mWomSV`, `mWOMSVBaseRewarder`, and `MasterMagpie` mocks/fixtures with a reward token.
2. Have attacker account deposit/lock `mWOM` via `mWomSV.lock(amount)` and stake into MasterMagpie so `mWOMSVBaseRewarder.balanceOf(attacker) == amount`.
3. Queue rewards to the pool (`_queueNewRewardsWithoutTransfer` / owner path) so `userRewards[token][attacker] > 0` after accrual.
4. Call `mWomSV.startUnlock(amount)` (full balance) to put 100% of balance into cooldown; verify `mWomSV.getRewardablePercentWAD(attacker) < 1e18` (should be less than 100%, since fully in cooldown/not fully locked).
5. Before `endTime`, trigger `getReward(attacker, receiver)` (via MasterMagpie's multiclaim path acting as `masterMagpie`).
6. Assert `toSend == userRewards[token][attacker]` pre-claim (i.e., no forfeiture applied) despite `getRewardablePercentWAD(attacker) < 1e18`, and assert `rewards[token].queuedRewards`/`historicalRewards` show no forfeited amount was re-queued — confirming full reward leakage.

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardableAmount = _amount;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalmWomSV = fullyInLock + inCoolDown;
        if (userTotalmWomSV == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalmWomSV;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalmWomSV / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalmWomSV;
                }

            }
        }

        return percent;
    }
