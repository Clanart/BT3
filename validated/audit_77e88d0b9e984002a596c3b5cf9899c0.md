### Title
Out-of-bounds buffer indexing in `is_atom_canonical()` during untrusted CLVM canonical-encoding checks - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_atom_canonical()` decodes CLVM atom length prefixes from attacker-controlled bytes without validating that the computed prefix length or resulting atom length stays within the buffer bounds, mirroring the GSS-NTLMSSP bug class (untrusted length-field decoding without bounds checks leading to out-of-bounds reads). This function is invoked directly on the raw `puzzle_reveal` and `solution` bytes of every coin spend in a submitted spend bundle, before any other structural validation of those buffers is guaranteed to have occurred in this code path.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads `clvm_buffer[offset]` to determine a length-prefix category and a `prefix_len` (0–5), then loops `prefix_len` times reading successive bytes to build `atom_len`, advancing `offset` each iteration with no check that `offset` remains `< len(clvm_buffer)`: [1](#0-0) 

This function is called from `is_clvm_canonical()`, which walks a CLVM-serialized buffer token by token and calls `is_atom_canonical(clvm_buffer, offset)` whenever it encounters an atom marker byte, again without pre-checking that enough bytes remain for the indicated prefix length: [2](#0-1) 

`is_clvm_canonical()` is invoked directly in `MempoolManager.validate_spend_bundle()` on the raw serialized `puzzle_reveal` and `solution` of every coin spend inside an untrusted, attacker-submitted `SpendBundle`: [3](#0-2) 

Because CLVM atoms with a large declared length can legitimately end with a short trailing byte sequence, a crafted `puzzle_reveal`/`solution` can present a length-prefix marker byte (e.g. `0xFC`, indicating a 5-byte length field) at or near the very end of the buffer, causing the `for i in range(prefix_len)` loop to index past `len(clvm_buffer)`. In CPython, `bytes.__getitem__` is bounds-checked and raises `IndexError` rather than reading adjacent process memory (unlike the C-level unmapped-memory read in the GSS-NTLMSSP advisory), so the practical consequence here is an unhandled `IndexError` rather than an out-of-bounds memory read.

I was unable to fully trace whether `add_spend_bundle()`/`validate_spend_bundle()` callers in `full_node.py` (or the RPC/mempool ingestion path) wrap this call in a broad `except Exception` that would degrade this to a rejected transaction versus letting the `IndexError` propagate and disrupt the task processing that spend bundle; the excerpt I reviewed shows a `try/except ValueError` only around the separate `validate_clvm_and_signature` call in `pre_validate_spendbundle()`, not around `validate_spend_bundle()`'s canonical-encoding check in `add_spend_bundle()`: [4](#0-3) 

### Impact Explanation
If the `IndexError` from `is_atom_canonical()` is not caught by an enclosing broad exception handler on the mempool ingestion path, a single crafted spend bundle from any unprivileged submitter could raise an unhandled exception in the coroutine processing spend-bundle admission, which is a spend-triggered transaction-processing disruption. Confirming the exact severity (isolated per-request failure vs. broader task/loop disruption) requires inspecting the calling code in `full_node.py` and the RPC endpoint, which is outside what I could verify with the available index.

### Likelihood Explanation
The path is trivially reachable: any wallet, RPC caller, or mempool peer can submit a `SpendBundle` with a `puzzle_reveal`/`solution` whose bytes are crafted to have a length-prefix byte near the end of the buffer, since `is_clvm_canonical()` is unconditionally executed for every coin spend in `validate_spend_bundle()` before deeper CLVM execution occurs.

### Recommendation
Add bounds checks in both `is_atom_canonical()` and `is_clvm_canonical()` before indexing `clvm_buffer[offset]`, verifying `offset < len(clvm_buffer)` prior to each read (as is already done defensively in the analogous `full_block_utils.py` skip helpers, e.g. `skip_bytes`/`skip_list`), and raise a well-defined, caught validation error (e.g. `Err.INVALID_COIN_SOLUTION`) instead of allowing an `IndexError` to propagate.

### Proof of Concept
Construct a coin spend whose `puzzle_reveal` or `solution` serialized bytes end with a length-prefix marker byte indicating multiple trailing length bytes but with insufficient bytes actually remaining, e.g. a buffer ending in `...\xfc` (5-byte length prefix marker) with zero or few bytes following it, then submit it as part of a `SpendBundle` via the standard mempool submission path so that `MempoolManager.validate_spend_bundle()` calls `is_clvm_canonical(bytes(coin_spend.puzzle_reveal))`/`is_clvm_canonical(bytes(coin_spend.solution))`, triggering `clvm_buffer[offset]` indexing past the end of the buffer in `is_atom_canonical()`.

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```
