### Title
Silent automatic rewrite of a Git remote URL based on unverified GitHub API `clone_url` - ([File: app/src/lib/stores/updates/update-remote-url.ts])

### Summary
`updateRemoteUrl` rewrites the local repository's default remote URL to whatever `clone_url` the GitHub API currently returns for the `owner/name` pair matched from the existing remote, with no user prompt or confirmation. This is invoked automatically as part of the repository-refresh flow (`repositoryWithRefreshedGitHubRepository` in `app-store.ts`), so it can run silently in the background (e.g., during periodic/background fetch), meaning a change in what the GitHub API reports for a given owner/name can redirect the user's local `origin` remote without any explicit action.

### Finding Description
The repository is matched to a GitHub account/API endpoint purely by hostname and by `owner`/`name` extracted from the existing remote URL, via `matchGitHubRepository` [1](#0-0)  and consumed in `matchGitHubRepository` on `AppStore` [2](#0-1) .

`repositoryWithRefreshedGitHubRepository` uses that match to call `api.fetchRepository(owner, name)` and, if the repository already had a `gitHubRepository`, unconditionally calls `updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)` with whatever the API just returned [3](#0-2) .

Inside `updateRemoteUrl`, the only real guard is that the *previously stored* `gitHubRepository.cloneURL` must match the current local remote URL (`remoteUrlUnchanged`) and that the URL protocol (http/https/ssh-like) hasn't changed; if so, and the freshly-fetched `apiRepo.clone_url` differs from the current remote, the code silently calls `gitStore.setRemoteURL(...)` to rewrite the remote [4](#0-3) .

Crucially, `apiRepo.clone_url` is attacker-influenceable data returned from the GitHub API for the same `owner/name` pair — for example when a repository is deleted and its `owner/name` combination is later reused/recreated by a different account (a known "repojacking"/name-squatting pattern), or when the API endpoint being queried is a GitHub Enterprise server under attacker influence. Because the match is done by hostname + owner + name only (not by any stable repository ID), and the update happens without any diff/prompt shown to the user, this constitutes a "broken invariant" analogous to the SetToken report: once bound, the remote reference is supposed to be a trusted, user-controlled value, but the code re-derives and silently overwrites it based on an external, attacker-reachable object (the GitHub API repository response).

### Impact Explanation
If exploited, the user's `origin` remote is silently repointed to a URL of the attacker's choosing (as returned in `clone_url`), while the UI still shows the repository under its original name/history. Subsequent `git fetch`/`git pull`/`git push` operations (including ones triggered by background fetch, which calls into this refresh path via `shouldBackgroundFetch`/`withRefreshedGitHubRepository`) would silently interact with the attacker-controlled remote instead of the legitimate one — this can result in the user unknowingly pushing commits (and potentially credentials via credential helper flows scoped to the new host) to an attacker's server, or fetching/merging attacker-supplied history into their local repository without any visible indication that the remote changed. This matches the "silent corruption of what the user commits or pushes" impact category.

### Likelihood Explanation
The trigger conditions are narrow but realistic and require no local access or admin rights: an attacker needs to control what `clone_url` the GitHub API returns for the exact `owner/name` that a victim's remote already points to (e.g., by re-registering an abandoned GitHub org/user name and recreating a repo with the same name — a well-documented "repo-jacking" technique — or by controlling an Enterprise Server the victim is configured against). The refresh path (`repositoryWithRefreshedGitHubRepository` → `withRefreshedGitHubRepository`) is exercised during normal background operations, not just user-initiated actions, so the update can happen without any user interaction beyond having previously added the repository. This is a real but conditional path; I could not fully trace every caller of `withRefreshedGitHubRepository`/background fetch scheduling within the available index to confirm exact automatic-trigger frequency, so some detail of "how often/under what UI states this fires silently" remains unverified from the indexed code alone.

### Recommendation
- Short term: Do not silently rewrite the remote URL based solely on `owner/name` + protocol matching. Require confirmation from the user (a diff/prompt similar to other destructive changes) before changing `origin`'s URL, and/or verify repository identity via a stable GitHub repository ID (`apiRepo.id`) rather than trusting `owner/name` continuity.
- Long term: Persist and compare the GitHub repository's immutable `id` field across refreshes; if the `id` returned for a given `owner/name` changes from what was previously recorded, treat this as a strong signal of repository takeover and surface a warning to the user instead of auto-migrating the remote URL.

### Proof of Concept
1. Victim adds a GitHub repository `attacker-org/foo` in Desktop; Desktop stores `gitHubRepository.cloneURL` matching the local `origin` remote (verified in `update-remote-url-test.ts` scenarios) [5](#0-4) .
2. The `attacker-org/foo` repository is later deleted and re-created (or the org/name is transferred) by a different party who controls the same `owner/name`, and the new repo's `clone_url` points to an attacker-hosted or attacker-controlled clone target with the same protocol.
3. On the next automatic repository refresh (e.g., triggered by background fetch calling into `withRefreshedGitHubRepository` → `repositoryWithRefreshedGitHubRepository`), Desktop calls `api.fetchRepository('attacker-org','foo')`, gets the new `clone_url`, and since `remoteUrlUnchanged` and `protocolsMatch` hold while `urlsMatch` is now false, `updateRemoteUrl` calls `gitStore.setRemoteURL(...)` silently [6](#0-5) .
4. The victim's next `git push`/`fetch` operation now targets the attacker's remote with no on-screen warning that `origin` changed.

export function matchGitHubRepository(
  accounts: ReadonlyArray<Account>,
  remote: string
): IMatchedGitHubRepository | null {
  for (const account of accounts) {
    const htmlURL = getHTMLURL(account.endpoint)
    const { hostname } = URL.parse(htmlURL)
    const parsedRemote = parseRemote(remote)

    if (parsedRemote !== null && hostname !== null) {
      if (parsedRemote.hostname.toLowerCase() === hostname.toLowerCase()) {
        return { name: parsedRemote.name, owner: parsedRemote.owner, account }
      }
    }
  }

  return null
}

  private async matchGitHubRepository(
    repository: Repository
  ): Promise<IMatchedGitHubRepository | null> {
    const gitStore = this.gitStoreCache.get(repository)

    if (!gitStore.defaultRemote) {
      await gitStore.loadRemotes()
    }

    const remote = gitStore.defaultRemote
    return remote !== null
      ? matchGitHubRepository(this.accounts, remote.url)
      : null
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
