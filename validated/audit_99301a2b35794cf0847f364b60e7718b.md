## Analysis Result

### Title
Auction bid `MaxGasPrice` is excluded from the v2.1 EIP-712 signature hash, letting a searcher mutate an economically-relevant bid field without invalidating either signature - (File: `kaiax/auction/eip712.go`)

### Summary
The bug class described in the Gondi report is a signing/verification hash that omits a fee-relevant struct field (`protocolFee`), so that field can be changed after signing without the on-chain hash check (`_baseLoanChecks`) noticing, letting a party dodge fees or corrupt accounting. The Kaia repository contains a structurally identical pattern in the `kaiax/auction` bid-signing scheme: the `Bid.MaxGasPrice` field is part of the persistent `BidData` struct and of the RLP hash used for pool bookkeeping, but it is intentionally left out of the v2.1 EIP-712 struct hash used to validate the searcher's own signature.

### Finding Description
`BidData` carries a `MaxGasPrice` field alongside all the other economically meaningful auction parameters (`TargetTxHash`, `BlockNumber`, `Sender`, `To`, `Nonce`, `Bid`, `CallGasLimit`, `Data`): [1](#0-0) 

The v2.1 EIP-712 type string used to build the searcher's signing digest deliberately excludes `maxGasPrice`, while the v3.0 type string includes it: [2](#0-1) 

`Bid.EncodeData()` (used for the v2.1/`AuctionVersionV2` digest) never serializes `MaxGasPrice` into the struct hash, whereas `bidV3.EncodeData()` does: [3](#0-2) 

`GetHashTypedData` selects the struct hash purely based on the caller-supplied/on-chain-read `version` string, defaulting to the v2.1 (no-`MaxGasPrice`) hash for anything other than `AuctionVersionV3`: [4](#0-3) 

Signature validation in `ValidateSearcherSig` only checks that the recovered signer of this (version-dependent) digest matches `Sender`; it does not independently check `MaxGasPrice`: [5](#0-4) 

Additionally, the auctioneer's own co-signature is computed only over the raw bytes of `SearcherSig`, not over any field of `BidData` at all: [6](#0-5) 

`BidPool.validateBidSigs` calls exactly these two checks and nothing else to admit a bid into the pool: [7](#0-6) 

Meanwhile, the pool's identity/dedup hash (`bid.Hash()`) is a plain RLP hash over the *entire* `BidData`, including `MaxGasPrice`: [8](#0-7) 

This is exactly the analog of the reported bug class: an economically-relevant field (`MaxGasPrice`, analogous to `protocolFee`) exists in the data structure and is used downstream (`EncodeAuctionCallData` includes `MaxGasPrice` in the v3.0 calldata) but is not covered by the hash that both signatures are built to protect, when the active protocol version is v2.1: [9](#0-8) 

As a direct consequence, a bidder (an "auction bidder"/public-RPC caller reachable actor, submitting through `AuctionAPI.SubmitBid`) can take a single valid `(SearcherSig, AuctioneerSig)` pair and freely resubmit it with an arbitrary `MaxGasPrice` value, since neither signature check depends on that field under `AuctionVersionV2`: [10](#0-9) 
Because `bid.Hash()` (the pool's dedup/identity key) *does* include `MaxGasPrice`, each such mutation is treated as a brand-new, independently-valid bid rather than being rejected as a duplicate: [11](#0-10) 

### Impact Explanation
Under the currently-modeled v2.1 auction entry point, `EncodeAuctionCallData` never places `MaxGasPrice` into the v2.1 ABI call, so a v2.1-targeted mutation has no direct on-chain effect today. However, the vulnerability is a genuine violation of the intended invariant that "a valid searcher/auctioneer signature pair commits to all bid parameters." This becomes concretely exploitable the moment the bid pool observes a stale or mismatched `auctionEntryPointVersion` relative to the version active when a bid is later encoded/executed (`GetBidTxGenerator`/`getBidTxGasLimit` re-derive calldata from the *current* `bp.auctionEntryPointVersion` at generation time, not the version at signature-validation time), because `MaxGasPrice` would then be silently included in the v3.0 calldata despite never having been committed to by the searcher's signature under v2.1. This mirrors the Gondi finding's confirmed impact: an unauthenticated/unauthorized field can be substituted to escape a fee/price constraint or desynchronize the value actually acted upon from the value that was cryptographically approved.

### Likelihood Explanation
Reaching this requires only a normal, unprivileged auction bidder submitting a bid via the public `auction_sendBid`/`SubmitBid` RPC with a tampered `MaxGasPrice` while reusing a previously obtained valid `SearcherSig`/`AuctioneerSig` pair — no p2p manipulation, validator collusion, or privileged access is needed. The main mitigating factor is that the impact is currently latent, requiring either an entry-point version transition (v2.1 → v3.0) mid-flight for a queued bid (bids can live up to `allowFutureBlock = 2` blocks), or any future code path that trusts `MaxGasPrice` under v2.1 validation state.

### Recommendation
Include `MaxGasPrice` (or an explicit `hasMaxGasPrice` marker with the value pinned to `0`) in the v2.1 EIP-712 struct hash as well, so both the searcher and auctioneer signatures always commit to the full set of fields that `EncodeAuctionCallData`/on-chain execution can ever consume, regardless of the currently active auction version. Alternatively, reject/zero out `MaxGasPrice` at intake time whenever `auctionEntryPointVersion != AuctionVersionV3`, and re-validate bid signatures against the version active at the actual block-inclusion time rather than only at pool-admission time.

### Proof of Concept
1. Auctioneer and searcher agree off-chain on a bid with `MaxGasPrice = 0` (or unset) and the auction entry point currently reports `AUCTION_VERSION() == "0.0.1"`.
2. Searcher computes `GetHashTypedData(chainId, entryPoint, AuctionVersionV2)` (excludes `MaxGasPrice`) and obtains `SearcherSig`; auctioneer signs `GetEthSignedMessageHash()` (only over `SearcherSig` bytes) to produce `AuctioneerSig`.
3. Bidder submits the bid via `AuctionAPI.SubmitBid` with the original `SearcherSig`/`AuctioneerSig` but an attacker-chosen `MaxGasPrice` (e.g., `type(uint256).max`); `validateBidSigs` passes because neither signature depends on `MaxGasPrice` under v2.1.
4. `bid.Hash()` differs from any prior submission (since it's computed over full `BidData` including `MaxGasPrice`), so it is accepted into the pool as a distinct, "validly signed" bid rather than being rejected as a duplicate or unauthorized modification.
5. If/when the bid pool's cached `auctionEntryPointVersion` for that block window is (or transitions to) `AuctionVersionV3`, `EncodeAuctionCallData`/`GetBidTxGenerator` will encode this attacker-chosen `MaxGasPrice` into the v3.0 calldata, even though it was never actually committed to by the searcher's v3.0-style signature.

func (b *Bid) ValidateSearcherSig(chainId *big.Int, verifyingContract common.Address, version string) error {
	if chainId == nil {
		return ErrNilChainId
	}

	if common.EmptyAddress(verifyingContract) {
		return ErrNilVerifyingContract
	}

	digest := b.GetHashTypedData(chainId, verifyingContract, version)

	recoveredSender, err := getSigner(b.SearcherSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover searcher sig: %v", err)
	}

	if recoveredSender != b.Sender {
		return fmt.Errorf("invalid searcher sig: expected %v, calculated %v", b.Sender.String(), recoveredSender.String())
	}

	return nil
}

// EncodeEIP712 encodes any EIP712Encoder according to EIP-712 specification
func EncodeEIP712(encoder EIP712Encoder) []byte {
	encoded := make([]byte, 0)
	encoded = append(encoded, encoder.EncodeType()...)
	encoded = append(encoded, encoder.EncodeData()...)
	return crypto.Keccak256Hash(encoded).Bytes()
}

// GetHashTypedData returns the EIP-712 digest for the bid.
// version must match the on-chain AUCTION_VERSION of the entry-point contract
// the bid targets; "0.0.2" selects the v3.0 struct typehash (with maxGasPrice),
// any other value falls back to the v2.1 typehash.
func (b *Bid) GetHashTypedData(chainId *big.Int, verifyingContract common.Address, version string) []byte {
	if chainId == nil {
		return nil
	}

	domain := EIP712Domain{
		EIP712DomainTypeHash: eip712TypeHash,
		NameHash:             auctionNameHash,
		VersionHash:          crypto.Keccak256Hash([]byte(version)),
		ChainId:              chainId,
		VerifyingContract:    verifyingContract,
	}

	domainSeparator := EncodeEIP712(domain)

	var structHash []byte
	if version == AuctionVersionV3 {
		structHash = EncodeEIP712(bidV3{b})
	} else if version == AuctionVersionV2 {
		structHash = EncodeEIP712(b)
	} else {
		// Unknown version: default to v2.1 typehash.
		structHash = EncodeEIP712(b)
	}

	return crypto.Keccak256([]byte{0x19, 0x01}, domainSeparator, structHash)
}

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)
}
