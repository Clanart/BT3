### Title
Broken forfeit calculation in `mWOMSVBaseRewarder` bypasses the early-exit reward penalty - (File: rewards/mWOMSVBaseRewarder.sol)

### Summary
`mWOMSVBaseRewarder._calExpireForfeit` never actually derives the user's rewardable percentage: it sets `rewardableAmount = _amount` unconditionally, guaranteeing `forfeitAmount = 0` on every call, regardless of the caller's actual lock/cooldown state.

### Finding Description
The sibling contract `vlMGPBaseRewarder` computes the forfeit correctly by querying the locker for the caller's actual rewardable share: [1](#0-0) 

`mWOMSVBaseRewarder` is structurally identical (same `ILocker mWOMSV` reference, same reward-distribution flow via `_sendReward`), and `mWomSV.sol` even exposes the equivalent `getRewardablePercentWAD` function needed to compute the real forfeit. However, its `_calExpireForfeit` never calls into the locker at all — it just assigns the input amount to itself: [2](#0-1) 

Because `rewardableAmount` is always set equal to `_amount`, the check `if (rewardableAmount > _amount)` can never be true (dead code, analogous to the always-failing downcast in the reference report), and `forfeitAmount = _amount - rewardableAmount` is always `0`. The forfeit-enforcement mechanism — meant to penalize users who exit reward accrual early/without full commitment to the mWomSV lock, and redirect the forfeited portion back into the pool for `ForfeitRewardAdded` — is silently disabled on every call path: [3](#0-2) 

Both `getReward` and `getRewards`, callable by any ordinary staked wallet through `MasterMagpie`, hit this broken function on every claim: [4](#0-3) 

### Impact Explanation
The forfeit mechanism exists to claw back a portion of unearned/ineligible rewards from users who don't meet the full rewardable-percentage condition, and to redistribute it (`_queueNewRewardsWithoutTransfer`) to the remaining honest long-term stakers of the mWomSV reward pool. With this check permanently disabled, every user always receives 100% of `userRewards[...]` with zero forfeiture, meaning:
- Users who should be penalized are paid in full, and
- The protocol/pool permanently loses the yield redistribution that honest stakers were entitled to receive from those forfeitures.

This constitutes a permanent, protocol-wide loss of unclaimed/forfeited yield owed to remaining stakers — reachable by any ordinary wallet simply calling the standard claim path (`getReward`/`getRewards`), with no privileged or admin action required.

### Likelihood Explanation
High likelihood: this triggers on every single reward claim from `mWOMSVBaseRewarder`, since the broken logic is unconditional and not gated by any edge case or attacker-specific action. No special conditions, front-running, or privileged role is needed — normal usage of the protocol's mWomSV reward claim flow reproduces the loss every time.

### Recommendation
Fix `_calExpireForfeit` in `rewards/mWOMSVBaseRewarder.sol` to mirror `vlMGPBaseRewarder`'s logic, querying `mWOMSV.getRewardablePercentWAD(_account)` (or the mWomSV-equivalent) to compute the real rewardable amount before deriving `forfeitAmount`, instead of trivially assigning `rewardableAmount = _amount`.

### Proof of Concept
1. A user stakes mWomSV and accrues rewards in the `mWOMSVBaseRewarder` pool tracked via `queueNewRewards`/`donateRewards`.
2. The user calls `getReward` (via `MasterMagpie`), which invokes `_sendReward` → `_calExpireForfeit(_account, userRewards[...])`. [5](#0-4) 
3. Regardless of the user's actual lock/cooldown percentage in `mWomSV`, `_calExpireForfeit` returns `0`, so `toSend = userRewards[...] - 0` is transferred in full. [2](#0-1) 
4. No amount is ever routed to `_queueNewRewardsWithoutTransfer`, so the pool of remaining stakers permanently loses the forfeiture-based yield redistribution the protocol design intends.

```text
    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardableAmount = _amount;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }
```
