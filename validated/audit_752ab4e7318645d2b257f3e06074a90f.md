### Title
`balanceOf` on the CW721↔ERC721 pointer contract does unbounded on-chain pagination scaling with attacker-inflated token count, causing gas-limit DoS for the owner address - ([File: contracts/src/CW721ERC721Pointer.sol])

### Summary
The `CW721ERC721Pointer.balanceOf` override loops through the underlying CosmWasm CW721 contract's `tokens` query in pages of 1000, continuing until it receives an empty list. The number of loop iterations (and thus gas cost) scales linearly and unboundedly with however many CW721 tokens are owned by the queried address — and *any* unprivileged actor can inflate that count by minting or transferring many cheap/no-value NFTs to a target address they don't control, without the target's consent.

### Finding Description
`balanceOf` is overridden to be computed on the fly via repeated cross-VM `WasmdPrecompile.query` calls instead of relying on ERC721's local `_balances` bookkeeping: [1](#0-0) 

Each iteration performs a `tokens` query with `limit: 1000` and a `start_after` cursor, and the `while` loop only terminates when the CW721 contract returns an empty token list for that owner. There is no upper bound on the number of iterations, and every iteration costs real EVM gas (compiling the JSON payload, invoking the wasmd precompile cross-VM query, and parsing/hashing the response).

Any unprivileged EVM/CosmWasm actor who can `transfer_nft` or `mint` (if the underlying CW721 contract allows open minting, or simply by repeatedly transferring tokens they own) into a victim address can grow that victim's CW721 token count arbitrarily — the attacker never needs the victim's permission, since transfers/mints target an arbitrary recipient address. This is directly analogous to the reported Biconomy `LiquidityFarming.deposit` bug: an attacker pushes entries into a per-user collection they don't own, inflating an unbounded loop that the victim (or anything relying on the victim's `balanceOf`) must later traverse.

Because `balanceOf` is a standard ERC721 interface function, other on-chain contracts (marketplaces, lending/collateral protocols, airdrop distributors, or any composed EVM contract that calls `IERC721(pointer).balanceOf(victim)` as part of a state-changing transaction) will consume gas proportional to the attacker-inflated count. Once the count is large enough that a full pagination sweep exceeds the caller's available gas (or the EVM call/query gas cap enforced on the wasmd precompile query path), any transaction path that touches `balanceOf(victim)` reverts.

### Impact Explanation
This meets the Medium bar for "permanent freezing" of a specific address's interoperability with the pointer contract: once inflated past the gas-exhaustion threshold, `balanceOf(victim)` (and any transaction logic depending on it) permanently reverts for that address until token count is somehow reduced — which the victim cannot control since the attacker made the deposits. This can freeze integrations (e.g., collateral checks, marketplace listings, airdrop eligibility checks) that call `balanceOf` on-chain for the targeted address, and it degrades the pointer contract's usability generally since `balanceOf` cost is unbounded and attacker-controllable per address.

### Likelihood Explanation
Likelihood is Medium: it requires either (a) an openly mintable underlying CW721 contract, or (b) the attacker owning/acquiring enough distinct token IDs to transfer into the victim address. Both are realistic for permissionless CW721 collections deployed by third parties and pointed at via Sei's automatic pointer creation. No special privileges beyond ordinary token transfer/mint rights on the underlying CW721 contract are needed, and the attack costs only the attacker's own gas for the mint/transfer calls, not the victim's.

### Recommendation
- Do not compute `balanceOf` by paginating the full token list on every call. Cap the number of pages traversed (revert or return a bounded "at least N" style approximation past a fixed iteration limit), or
- Track balance incrementally in local EVM storage (mirroring OZ's default `_balances` accounting) updated on `transferFrom`/mint/burn synthetic events from the CW721 side, rather than re-deriving it via unbounded cross-VM pagination on every read, or
- Impose a hard cap on iterations (e.g., a small fixed number of pages) and document that `balanceOf` may under-report for extremely large collections rather than being unboundedly gas-expensive.

### Proof of Concept
1. Deploy/point to a CW721 contract with either open minting or attacker-owned large token supply.
2. Attacker calls `mint`/`transfer_nft` (`CW721ERC721Pointer.transferFrom`-equivalent CW message) repeatedly to send, e.g., 200,000 distinct token IDs to victim address `V` (200 pages of 1000 tokens each) — cost borne entirely by the attacker.
3. Any subsequent call to `CW721ERC721Pointer.balanceOf(V)` — whether from `eth_call`/RPC with a bounded gas cap, or invoked on-chain by another contract inside a transaction with a normal gas limit — must execute 200 sequential wasmd precompile queries plus JSON parsing in a single call frame, exceeding typical gas budgets and causing the call to run out of gas and revert, as shown in the loop at: [2](#0-1)

    function balanceOf(address owner_) public view override returns (uint256) {
        if (owner_ == address(0)) {
            revert ERC721InvalidOwner(address(0));
        }
        uint256 numTokens = 0;
        string memory startAfter;
        string memory qb = string.concat(
            string.concat("\"limit\":1000,\"owner\":\"", AddrPrecompile.getSeiAddr(owner_)),
            "\""
        );
        bytes32 terminator = keccak256("{\"tokens\":[]}");

        bytes[] memory tokens;
        uint256 tokensLength;
        string memory req = string.concat(string.concat("{\"tokens\":{", qb), "}}");
        bytes memory response = WasmdPrecompile.query(Cw721Address, bytes(req));
        while (keccak256(response) != terminator) {
            tokens = JsonPrecompile.extractAsBytesList(response, "tokens");
            tokensLength = tokens.length;
            numTokens += tokensLength;
            startAfter = string.concat(",\"start_after\":", string(tokens[tokensLength-1]));
            req = string.concat(
                string.concat("{\"tokens\":{", string.concat(qb, startAfter)),
                "}}"
            );
            response = WasmdPrecompile.query(Cw721Address, bytes(req));
        }
        return numTokens;
    }
