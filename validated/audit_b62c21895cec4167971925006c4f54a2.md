### Title
Governance-settable `GasTarget = 0` causes a division-by-zero panic in KIP-71 base fee calculation, halting all nodes - (File: params/kip71_config.go)

### Summary
`KIP71Config.NextMagmaBlockBaseFee` divides by the governance parameter `GasTarget` when calculating the next block's base fee. The `Kip71GasTarget` governance parameter uses `noopFormatChecker` with no zero-value validation, unlike other divisor-like parameters (e.g. `BaseFeeDenominator` has an explicit zero-guard). If `GasTarget` is ever set to `0` via a governance vote, every node computing/verifying a post-Magma block panics on `big.Int` division by zero, an unrecoverable crash affecting the entire network.

### Finding Description
`NextMagmaBlockBaseFee` computes `baseFeeDelta` using `gasTarget := kc.GasTarget` as a divisor in two branches (gas used above/below target): [1](#0-0) [2](#0-1) 

Unlike `BaseFeeDenominator`, which has an explicit zero fallback: [3](#0-2) 

`GasTarget` has no such protection - it is used raw as `new(big.Int).SetUint64(gasTarget)` divisor. Go's `big.Int.Div` panics on division by zero (analogous to the reported GoPro `GPMF_Decompress` division-by-zero crash on unchecked input).

The governance parameter registry defines `Kip71GasTarget` with `FormatChecker: noopFormatChecker`, performing no validation that the value is non-zero: [4](#0-3) 

This differs from parameters like `Kip71BaseFeeDenominator`, which does enforce `v != 0`: [5](#0-4) 

Once `GasTarget=0` is accepted by governance and activated in the `ParamSet`, `ToKip71Config()` propagates it directly into `KIP71Config.GasTarget`: [6](#0-5) 

`NextMagmaBlockBaseFee` is called on every block header construction/verification after the Magma hardfork (block assembly and header validation), and also by RPC gas-price/fee-history endpoints: [7](#0-6) [8](#0-7) 

With `GasTarget = 0`, any block with `parentGasUsed > 0` (virtually all blocks) takes the `parentGasUsed > gasTarget` branch and executes `x.Div(x, new(big.Int).SetUint64(gasTarget))` with a zero divisor, panicking the process.

### Impact Explanation
This is a consensus-critical divide-by-zero: every full node (miners, validators, RPC nodes serving `eth_gasPrice`/`eth_feeHistory`) that processes a block after the malicious parameter takes effect will panic and crash simultaneously, producing a total network halt - a much stronger impact than the referenced parser crash, since it affects blockchain liveness/availability network-wide rather than a single decoder process.

### Likelihood Explanation
Governance parameter changes go through the on-chain vote mechanism, and the vote/parameter value undergoes only the registered `FormatChecker` for that parameter. Because `Kip71GasTarget`'s checker is a no-op, a vote setting `GasTarget=0` would pass validation and be accepted as a valid governance parameter change, with no additional guard anywhere in `NextMagmaBlockBaseFee` to prevent the resulting division by zero. This requires triggering the on-chain governance parameter update path, but no other check in the codebase (contract deployer/tx sender/RPC caller cannot directly set this parameter; it is governance-only) prevents zero from being accepted.

### Recommendation
Add a `FormatChecker` for `Kip71GasTarget` in `kaiax/gov/param.go` that rejects `v == 0` (mirroring the check used for `Kip71BaseFeeDenominator`), and/or add a defensive zero-guard fallback for `GasTarget` inside `NextMagmaBlockBaseFee` in `params/kip71_config.go`, analogous to the existing `BaseFeeDenominator` zero-fallback, before it is used as a divisor.

### Proof of Concept
1. Submit/pass a governance vote setting `kip71.gastarget` (`gov.Kip71GasTarget`) to `0`.
2. Once the parameter activates at the next epoch/governance interval, any block produced with `GasUsed > 0` causes `ParamSet.ToKip71Config()` to yield `GasTarget=0`.
3. On the next call to `KIP71Config.NextMagmaBlockBaseFee` (during block assembly, header verification, or `eth_gasPrice`/`eth_feeHistory` RPC calls), the code executes:
   `y := x.Div(x, new(big.Int).SetUint64(gasTarget))` with `gasTarget = 0`, which panics with "division by zero" in Go's `math/big` package, crashing the node process. [1](#0-0)

func (kc *KIP71Config) VerifyMagmaHeader(headerBaseFee *big.Int, parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) error {
	if headerBaseFee == nil {
		return fmt.Errorf("header is missing baseFee")
	}
	// Verify the baseFee is correct based on the parent header.
	expectedBaseFee := kc.NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)
	if headerBaseFee.Cmp(expectedBaseFee) != 0 {
		return fmt.Errorf("invalid baseFee: have %s, want %s, parentBaseFee %s, parentGasUsed %d",
			headerBaseFee, expectedBaseFee, parentHeaderBaseFee, parentHeaderGasUsed)
	}
	return nil
}
