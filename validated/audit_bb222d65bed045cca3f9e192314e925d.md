### Title
`ThresholdKeys::new`/`read` accepts a zero secret share and identity verification shares, yielding an identity group key - (File: crypto/dkg/src/lib.rs)

### Summary
The bug class from the external report is "missing validation lets a security-critical parameter be set to the zero value". The direct analog in Serai is `ThresholdKeys::new` (and therefore `ThresholdKeys::read`, which is reachable via untrusted bytes): it validates only the count and participant indexes of `verification_shares`, never that the `secret_share` is non-zero, never that `verification_shares[i] == generator * secret_share`, and never that the interpolated `group_key` is non-identity. Because `dkg` deserializes points with `Ciphersuite::read_G` — which checks only canonical encoding, not identity — a serialized `ThresholdKeys` blob with all-identity verification shares deserializes successfully and produces `group_key == identity`. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
- `ThresholdKeys::new` checks `verification_shares.len() == n` and `participant <= n`, then computes `group_key = Σ verification_shares[i] * interpolation_factor(i, 1..=t)` with no identity or consistency checks. [4](#0-3) 
- `ThresholdKeys::read` reads `secret_share` via `C::read_F` (accepts zero) and each verification share via `C::read_G` (accepts the identity encoding), then feeds them straight into `ThresholdKeys::new`. [5](#0-4) 
- `Ciphersuite::read_G` only rejects invalid/non-canonical encodings; identity rejection exists solely in `Curve::read_G` for FROST message points, not for key material. [6](#0-5) [7](#0-6) 
- `view()` then derives `secret_share`, `verification_shares`, and `group_key` from this unvalidated core and is used to produce FROST signature shares. [8](#0-7) 

### Impact Explanation
If `verification_shares` are all identity, `group_key` becomes the identity point. A Schnorr signature `(R = identity, s = 0)` satisfies `s·G == R + c·Y` for `Y = identity`, so any party can forge signatures for that group key — funds attributed to it are spendable by an attacker while honest signers produce shares over a key they do not control. Alternatively, a zero `secret_share` makes this participant's share signature omit the `c·λ_i·s_i` term, corrupting every signing session the key is used in. This mirrors the report's "immutable set to zero → broken / attacker-controlled behavior" impact, with the zero value being the group key rather than an address.

### Likelihood Explanation
Requires attacker-controlled bytes to reach `ThresholdKeys::read` (e.g., a tampered/rolled key-share backup, or any path where serialized `ThresholdKeys` crosses a trust boundary) — the same trust assumption the scan rules explicitly allow for `read`/`verify` APIs. The malformed input parses cleanly; there is no checksum binding `secret_share` to `verification_shares[i]` or rejecting `group_key == identity`. It is not exploitable purely over the DKG protocol itself (PedPoP checks shares against commitments), which bounds it to Medium rather than High.

### Recommendation
In `ThresholdKeys::new`:
- Reject `secret_share.is_zero()`.
- Reject identity `group_key` (and ideally identity entries in `verification_shares`).
- Optionally verify `generator * secret_share == verification_shares[params.i()]` to catch inconsistent key material.

### Proof of Concept
1. Serialize a `ThresholdKeys` blob where every verification share encodes the identity point (valid canonical encoding, e.g., `0x00…00` for Ristretto) and `secret_share` is an arbitrary scalar.
2. `ThresholdKeys::read::<Ristretto>` succeeds; `keys.group_key() == identity`.
3. For any message `m`, `(R = identity, s = 0)` verifies under Schnorr verification since `0·G == identity + H(...)·identity`.
4. Alternatively set `secret_share = 0` with honest verification shares: `view()` returns an interpolated share of zero, and every FROST signing session this key participates in emits an invalid aggregated signature.

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();

      Err(io::Error::other("non-canonical point"))?;
