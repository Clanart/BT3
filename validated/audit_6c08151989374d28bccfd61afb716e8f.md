No sanitization exists anywhere in the codebase (`GIT_ALLOW_PROTOCOL` is never set, and no `protocol.ext.allow`/URL-scheme allow-list was found) for the clone URLs that flow from a GitHub API pull-request object into `git remote add` and `git fetch`. That is the concrete, exploitable analog of the reentrancy report's core lesson ("an attacker-controlled value flows unchecked into a privileged operation that the victim treats as safe").

### Title
Unsanitized PR head `clone_url` from the GitHub API reaches `git remote add`/`fetch`, allowing arbitrary command execution via Git's `ext::` transport - (File: `app/src/lib/stores/app-store.ts`)

### Summary
`_findPullRequestBranch` (called from `_checkoutPullRequest`, which is reachable both from the in-app pull request list and from the `x-github-client://openRepo/...` deep-link handler) takes `headCloneUrl` straight from the GitHub API's `pr.head.repo.clone_url` field (or from the deep link's URL/PR lookup) and passes it unmodified to `addRemote`, which shells out to `git remote add <name> <url>`. That remote is then fetched with `_fetchRemote`. Nowhere in this path, nor in `app/src/lib/git/remote.ts`, `app/src/lib/git/clone.ts`, or `app/src/lib/git/environment.ts`, is the URL scheme restricted. Git supports the `ext::<command>` remote helper transport, which executes an arbitrary shell command when Git tries to connect to it (fetch/clone). Because Desktop never sets `GIT_ALLOW_PROTOCOL` nor passes `-c protocol.ext.allow=never` (or equivalent) when adding/fetching remotes derived from external/API data, a crafted `clone_url` of the form `ext::sh -c "...attacker command..."` would be accepted by `addRemote` and then executed on `git fetch`. [1](#0-0) [2](#0-1) 

### Finding Description
The attacker primitive here is identical in shape to the reentrancy report's root cause: **an untrusted, attacker-influenced value (there: `YIELD_TOKEN` balance manipulated via a reentrant callback; here: `clone_url` supplied by a GitHub API response/PR object) is consumed by a privileged operation without validating that it stays within the expected trust boundary.**

- `_findPullRequestBranch` receives `headCloneUrl` as a plain string and, if no existing remote matches it via `urlMatchesRemote`, calls `addRemote(repository, forkRemoteName, headCloneUrl)`. [3](#0-2) 
- `addRemote` passes the URL directly as an argument to `git remote add`, with no scheme/protocol check. [2](#0-1) 
- Immediately afterward `_fetchRemote` is invoked on that remote, which will cause Git to actually connect using whatever transport the URL specifies. [4](#0-3) 
- The URL originates either from the GitHub API `pull.head.repo.clone_url` field via `openPullRequestFromUrl`/`_checkoutPullRequest`, or from the user-facing PR list via `checkoutPullRequest`. Both are external-data code paths, not user-typed local paths. [5](#0-4) [6](#0-5) 
- No code path calls `envForRemoteOperation` or the `git` invocation with `GIT_ALLOW_PROTOCOL`, nor is `protocol.ext.allow`/`protocol.file.allow` restricted for these operations (the only place `protocol.file.allow=always` is even set is for submodule updates, which actually *widens* allowed protocols rather than restricting them). [7](#0-6) [8](#0-7) 

Compare this to `clone.ts`, which *does* have a dedicated defensive check (`isClonePathSensitive`) against a different attacker vector (path traversal on the destination), showing the project is aware that URL-derived values need scrutiny, but that scrutiny was never applied to the transport/protocol dimension of these fork/remote URLs. [9](#0-8) 

### Impact Explanation
If an attacker can get a `clone_url` of `ext::...` (or `fd::`, or other command-executing Git transport helpers) into a pull request object that Desktop consumes — e.g., through a malicious/compromised GitHub Enterprise Server, a man-in-the-middle on the API response, or any endpoint whose PR data isn't fully trusted — opening/checking out that PR causes Desktop to invoke `git remote add` followed by a fetch that executes attacker-supplied shell commands on the victim's machine with the user's privileges. This is remote code execution triggered purely by viewing/checking out a pull request, i.e. code execution from an attacker-controlled GitHub API object, matching the required impact class exactly.

### Likelihood Explanation
The path is reachable via completely ordinary, expected user actions — clicking "Checkout" on a PR in Desktop's PR list, or clicking a `x-github-client://openRepo/...?pr=NNN` deep link — with no unnatural steps, no local access, and no pre-existing malware required. The gating factor is solely whether the attacker can influence the `clone_url` value returned for `pr.head.repo`, which is plausible in environments using GitHub Enterprise Server, an API proxy, or any scenario where the API response is not from a hardened, unmodifiable source. Because no code anywhere restricts protocols for these remote operations, existing guards (`urlMatchesRemote`, `sanitizeCloneName`, `isClonePathSensitive`) do not intercept this value — they check hostname/owner/name matching or destination-path safety, never the URL scheme itself.

### Recommendation
Before calling `addRemote`/`git fetch`/`git clone` with any URL sourced from the GitHub API, deep links, or other external input, restrict the transport to the known-safe set (`https`, `ssh`, `git`) — e.g. by validating the URL scheme in `remote-parsing.ts`/`repository-matching.ts` before use, and/or by passing `GIT_ALLOW_PROTOCOL=http:https:ssh:git` (or the equivalent `-c protocol.ext.allow=never` / `protocol.*.allow=never` config) in `envForRemoteOperation` for every git invocation that touches such URLs, mirroring the existing `isClonePathSensitive` defensive pattern already used for clone destinations.

### Proof of Concept
1. Set up a mock/compromised GitHub Enterprise API (or intercept the API response) such that a pull request's `head.repo.clone_url` is `ext::sh -c "touch /tmp/pwned"` instead of a normal `https://...` URL.
2. In Desktop, open that PR (via the PR list "Checkout" action, which calls `dispatcher.checkoutPullRequest` → `_checkoutPullRequest` → `_findPullRequestBranch`, or via the `x-github-client://openRepo/...?pr=NNN` deep link → `openPullRequestFromUrl` → `_checkoutPullRequest`).
3. `_findPullRequestBranch` finds no existing remote matching the URL and calls `addRemote(repository, forkRemoteName, 'ext::sh -c "touch /tmp/pwned"')`, then `_fetchRemote`.
4. Git executes the `ext::` helper command during the fetch, running `sh -c "touch /tmp/pwned"` on the victim's machine.

      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    if (pullRequest.head.repo === null) {
      return null

      repository,
      pullRequest.number,
      pullRequest.head.repo.owner.login,
      pullRequest.head.repo.clone_url,
      pullRequest.head.ref
    )

    return repository

/**
 * Check whether a resolved clone path targets a sensitive location that
 * should never be used as a clone destination. This is a backstop against
 * path traversal attacks where a crafted URL tricks the UI into deriving
 * a clone path outside the intended base directory.
 */
function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}
