### Title
`dispatch(DispatchPost)` accepts an unbound `payer` address that later receives third-party `fundRequest` fee contributions on timeout - ([File: evm/src/core/EvmHost.sol])

### Summary
`EvmHost.dispatch(DispatchPost memory post)` is a public entrypoint that stores an attacker-supplied `post.payer` as the sole timeout-refund beneficiary for a request commitment, with no check that `post.payer == msg.sender` or any other authorization binding. `EvmHost.fundRequest` then lets *any* address top up the fee for *any* existing commitment. On timeout, `dispatchTimeOut` refunds the **entire accumulated fee** to the single stored `meta.sender`, ignoring who actually supplied the funds via `fundRequest`. This is the same root defect as the reported `sponsor` bug: a fund-moving function takes an attacker-controlled address parameter with no authorization/ownership check, letting the caller redirect another party's tokens.

### Finding Description
`dispatch(DispatchPost memory post)` is declared `external payable` with no restriction on caller [1](#0-0) . The fee-metadata `sender` field, later used exclusively as the timeout-refund address, is set directly from the caller-supplied `post.payer` without verifying `post.payer == _msgSender()`: [2](#0-1) 

`fundRequest(bytes32 commitment, uint256 amount)` is likewise callable by anyone, for any existing commitment, and simply increases `metadata.fee` while pulling `amount` in feeToken from the caller [3](#0-2) . It never records who contributed each portion of the fee — `metadata.sender` (the refund beneficiary) is untouched.

When the request times out, `dispatchTimeOut` refunds the *whole* `meta.fee` to `meta.sender` only: [4](#0-3) 

So the corrupted value is `_requestCommitments[commitment].sender`: it is set once at dispatch time to an arbitrary, attacker-chosen address, is never re-validated, and becomes the exclusive recipient of all fee tokens later added by unrelated third parties through `fundRequest`.

Contrast this with `dispatch(DispatchGet memory get)`, where `sender` is hard-set to `_msgSender()` [5](#0-4)  — showing the POST path's `post.payer` acceptance is the inconsistent, unguarded entrypoint, exactly analogous to the missing `msg.sender == factory` check in the original `sponsor` bug.

### Impact Explanation
An attacker can:
1. Call `dispatch(DispatchPost)` directly (bypassing the intended app-layer wrapper, which the docs only recommend, not enforce) with `post.fee = 0` and `post.payer = attackerAddr2`, dispatching a request to a destination/module that is guaranteed to fail or never be delivered (e.g., an app whose `onAccept` always reverts, or simply picking a timeout window they control off-chain by not relaying it).
2. Any other user or relayer-incentivizer who wants the message delivered faster calls `fundRequest(commitment, amount)`, paying real feeToken from their own balance to bump `metadata.fee`.
3. When the request times out, `dispatchTimeOut` sends **all** of `metadata.fee` — including the funder's contribution — to `attackerAddr2`, not to the funder who supplied it.

This is unauthorized transfer / theft of another party's escrowed fee tokens through the bridge's own paymaster-style accounting, matching the bounty's "stealing or loss of funds" and "wrong beneficiary" criteria. No malicious relayer, prover, or governance actor is required — only two unprivileged EOAs interacting with public entrypoints.

### Likelihood Explanation
Both `dispatch(DispatchPost)` and `fundRequest` are unauthenticated, public, and take attacker-supplied parameters (`payer`, `commitment`) with no ownership check. Nothing prevents an attacker from directly calling the low-level `IDispatcher(host).dispatch()` (the "EOAs should not do this directly" guidance is documentation-only, not enforced on-chain) [6](#0-5) . The only precondition is that a third party voluntarily calls `fundRequest` on the attacker's commitment — plausible in incentivized relaying/self-relay scenarios where any account may "sponsor" faster delivery of a pending cross-chain request.

### Recommendation
- In `dispatch(DispatchPost)`, require `post.payer == _msgSender()`, or otherwise validate the payer is an approved/whitelisted delegate of the caller (mirroring the `sponsor` fix's "must be called by an authorized party" pattern).
- Track fee contributions per-funder (e.g., a mapping from `commitment => funder => amount`) so `dispatchTimeOut`/timeout refunds are distributed proportionally to whoever actually paid, rather than exclusively to the original `meta.sender`.

### Proof of Concept
1. Attacker deploys/uses two addresses, `A` (caller) and `V` (arbitrary payer, could even be attacker's own second wallet).
2. `A` calls `IDispatcher(host).dispatch(DispatchPost({dest: someDest, to: someApp, body: ..., timeout: T, fee: 0, payer: V}))` directly. No feeToken is pulled from `A` since `post.fee == 0` and `msg.value == 0`. `_requestCommitments[commitment] = FeeMetadata({sender: V, fee: 0})` is recorded per [2](#0-1) .
3. Victim funder `F`, wanting the message relayed, calls `host.fundRequest(commitment, 1000e18)`, paying `1000e18` feeToken from their own balance; `metadata.fee` becomes `1000e18` while `metadata.sender` remains `V` [7](#0-6) .
4. The request is never delivered (destination app rejects it, or `A` never has it relayed) and times out.
5. The handler calls `dispatchTimeOut(...)`, which executes `IERC20(feeToken()).safeTransfer(meta.sender, meta.fee)`, sending the full `1000e18` to `V` [8](#0-7) . `F` receives nothing back despite being the sole funder.

    function dispatchTimeOut(
        PostRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onPostRequestTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit PostRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function fundRequest(bytes32 commitment, uint256 amount) external payable notFrozen {
        if (msg.value > 0) {
            address[] memory path = new address[](2);
            address uniswapV2 = _hostParams.uniswapV2;
            path[0] = IUniswapV2Router02(uniswapV2).WETH();
            path[1] = feeToken();
            IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
                amount, path, address(this), block.timestamp
            );
        } else {
            IERC20(feeToken()).safeTransferFrom(_msgSender(), address(this), amount);
        }

        FeeMetadata memory metadata = _requestCommitments[commitment];
        if (metadata.sender == address(0)) revert UnknownRequest();

        metadata.fee += amount;
        _requestCommitments[commitment] = metadata;

        emit RequestFunded({commitment: commitment, newFee: metadata.fee});
    }
