### Title
TextFormat `Any` Printer Embeds Unvalidated `type_url` Inside `[...]` Field-Name Syntax, Enabling Structural Injection - (File: `src/google/protobuf/text_format.cc`)

### Summary
`TextFormat::Printer::PrintAny` prints an `Any` message's `type_url` field literally, unescaped, between the `[` and `]` delimiters that TextFormat's own grammar uses to denote an extension/Any field name. Because `type_url` is an ordinary attacker-controlled string field of the `Any` message (populated by parsing untrusted binary or ProtoJSON input), a value containing `]`, whitespace, `{`, `#`, or newline characters can break out of the intended "type-URL" token and inject additional TextFormat syntax (fake field assignments, comments, or block starts) into the printed output — the same bug class as the xmldom advisory, where an attacker-controlled "target" token was emitted unescaped inside a syntactic delimiter (`<? ... ?>`), letting it break the intended token boundary and inject structure into the surrounding document.

### Finding Description
`google.protobuf.Any.type_url` has no character restriction enforced by the wire format or by `Message::ParseFrom*`; it is simply a `bytes`/`string` field, so any client sending a bounded, well-formed Protobuf or ProtoJSON payload can set it to an arbitrary string (e.g. containing `]`, `\n`, `{`, `#`, or `"`).

When such a message is later rendered with `TextFormat::Printer::PrintAny`, the code does: [1](#0-0) 

```
const std::string& type_url = reflection->GetString(message, type_url_field);
...
if (!internal::ParseAnyTypeUrl(type_url, &url_prefix, &full_type_name)) {
  return false;
}
...
generator->PrintLiteral("[");
generator->PrintString(type_url);
generator->PrintLiteral("]");
``` [2](#0-1) 

`ParseAnyTypeUrl` only splits the string on the last `/` to separate a URL prefix from a "full type name" — it performs no validation that the resulting substring (or the `type_url` as a whole, which is what actually gets printed) is a syntactically legal TextFormat field-name token. Unlike normal field names (`field->name()`/`field->full_name()`), which originate from the *trusted schema/descriptor* and are therefore excluded from this analysis, `type_url` is a **runtime message value** taken directly from attacker input — the exact same trust boundary that failed in the xmldom case (an unvalidated, attacker-supplied token embedded verbatim inside the format's own delimiter syntax).

By contrast, ordinary string *field values* printed by TextFormat go through `FastFieldValuePrinter::PrintString`, which explicitly escapes dangerous characters via `absl::CEscape` before quoting: [3](#0-2) 

The `Any` type-URL path bypasses this escaping entirely because it is treated as a "field name" token (bracket-delimited) rather than as a string *value*, and no equivalent validation/escaping exists for that bracket token.

### Impact Explanation
If the printed TextFormat is later consumed by any downstream system that expects it to be well-formed TextFormat (e.g., logs re-parsed by tooling, debug dumps fed back into `TextFormat::Parse`, or diff/merge utilities), a crafted `type_url` such as:
```
type.googleapis.com/x] extra_field: 999 #
```
would render as:
```
[type.googleapis.com/x] extra_field: 999 #] {
  ...
}
```
This closes the intended `[...]` token early and injects a spurious `extra_field: 999` assignment while commenting out the remainder of the line — a structural/content injection into the serialized representation, analogous to the PI-target injection breaking the `<?...?>` boundary in xmldom. This does not itself corrupt memory or crash the process (excluded per rules), but it is an integrity failure of the "requireWellFormed"-equivalent guarantee that TextFormat output should always be parseable as the intended field-name/value structure.

### Likelihood Explanation
Reachable via any standard, supported public parsing API (`Any::ParseFromString`, `Message::MergeFromString`, or ProtoJSON `@type`/`value` parsing) — no privileged access or hostile schema is required; only `google.protobuf.Any`, a widely-used, standard trusted schema, is needed. The only prerequisite is that the application later calls `TextFormat::PrintToString`/`DebugString` on the resulting message with `expand_any` enabled and passes the type-url through unfiltered, which is a common pattern in logging/debugging code.

### Recommendation
Validate `type_url` before printing it inside `[...]` in `TextFormat::Printer::PrintAny` — e.g., reject/escape it if it contains characters outside the set valid for a URI/TextFormat token (whitespace, `]`, `{`, `#`, `"`, control characters), falling back to the default (non-expanded) `type_url`/`value` field printing rather than emitting the raw value inside the bracket delimiter, mirroring how `PrintString` already escapes dangerous characters for ordinary string field values.

### Proof of Concept
Conceptual reproduction (not executed, but derivable directly from the code path shown):
1. Construct any message containing a `google.protobuf.Any` field.
2. Set `Any.type_url = "type.googleapis.com/x] injected_field: 1 #"` and `Any.value` to a validly-serialized instance of some resolvable message type `x`.
3. Call `TextFormat::Printer` with `SetExpandAny(true)` and print the message.
4. Observe the output contains `[type.googleapis.com/x] injected_field: 1 #] { ... }` — the bracket boundary is broken and an unintended field assignment/comment is injected into the TextFormat text, as shown by the unescaped `generator->PrintString(type_url)` call at `text_format.cc:2565`.

I was not able to fully trace whether other language implementations (Java, Python, C#, PHP) have an equivalent Any-in-TextFormat printer with the same unescaped-bracket pattern, or whether `internal::ParseAnyTypeUrl` in `any_lite.cc` performs any character-set validation beyond splitting on `/` — the index did not return the body of that function. bool ContainsCharactersToCEscape(absl::string_view val) {
  bool needs_escape = false;
  for (unsigned char c : val) {
    needs_escape |=
        ((c < 32) | (c > 126) | (c == '"') | (c == '\'') | (c == '\\'));
  }
  return needs_escape;
}

}  // namespace

void TextFormat::FastFieldValuePrinter::PrintString(
    const std::string& val, BaseTextGenerator* generator) const {
  generator->PrintLiteral("\"");
  if (!val.empty()) {
    if (ABSL_PREDICT_FALSE(ContainsCharactersToCEscape(val))) {
      generator->PrintString(absl::CEscape(val));
    } else {
      generator->PrintString(val);
    }
  }
  generator->PrintLiteral("\"");
}

bool TextFormat::Printer::PrintAny(const Message& message,
                                   BaseTextGenerator* generator) const {
  const FieldDescriptor* type_url_field;
  const FieldDescriptor* value_field;
  if (!internal::GetAnyFieldDescriptors(message, &type_url_field,
                                        &value_field)) {
    return false;
  }

  const Reflection* reflection = message.GetReflection();

  // Extract the full type name from the type_url field.
  const std::string& type_url = reflection->GetString(message, type_url_field);
  std::string url_prefix;
  std::string full_type_name;

  if (!internal::ParseAnyTypeUrl(type_url, &url_prefix, &full_type_name)) {
    return false;
  }

  // Print the "value" in text.
  const Descriptor* value_descriptor =
      finder_ ? finder_->FindAnyType(message, url_prefix, full_type_name)
              : DefaultFinderFindAnyType(message, url_prefix, full_type_name);
  if (value_descriptor == nullptr) {
    ABSL_LOG(WARNING) << "Can't print proto content: proto type " << type_url
                      << " not found";
    return false;
  }
  DynamicMessageFactory factory;
  std::unique_ptr<Message> value_message(
      factory.GetPrototype(value_descriptor)->New());
  std::string serialized_value = reflection->GetString(message, value_field);
  if (!value_message->ParseFromString(serialized_value)) {
    ABSL_LOG(WARNING) << type_url << ": failed to parse contents";
    return false;
  }
  generator->PrintLiteral("[");
  generator->PrintString(type_url);
  generator->PrintLiteral("]");
  const FastFieldValuePrinter* printer = GetFieldPrinter(value_field);
  printer->PrintMessageStart(message, -1, 0, single_line_mode_, generator);
  generator->Indent();
  Print(*value_message, generator);
  generator->Outdent();
  printer->PrintMessageEnd(message, -1, 0, single_line_mode_, generator);
  return true;
}
