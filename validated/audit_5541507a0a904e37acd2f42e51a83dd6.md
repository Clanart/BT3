### Title
mWomSV Reward Forfeiture Mechanism Is Broken, Allowing Early Unlockers to Steal Loyalty Yield Meant for Long-Term Lockers - ([File: rewards/mWOMSVBaseRewarder.sol])

### Summary
The Mango `HealthRegion` bug is a class of "missing/incorrect enforcement of an economic invariant that is supposed to penalize a user for taking an unprivileged action," letting an attacker keep value that should have been forfeited. The Magpie codebase contains a direct analog: `mWOMSVBaseRewarder._calExpireForfeit` never actually computes a forfeiture based on the user's lock/cooldown status, so users who start unlocking their `mWomSV` position keep 100% of their loyalty rewards instead of forfeiting the pro-rata portion the protocol design requires.

### Finding Description
`mWomSV` implements a lock/cooldown loyalty-vault pattern identical to `VLMGP`: users `lock()` mWOM, and can later call `startUnlock()` to move a portion into a cooldown slot before eventually calling `unlock()`. Both `mWomSV` and `VLMGP` expose `getRewardablePercentWAD(_user)`, which computes the percentage of a user's rewards that should remain "rewardable" based on how much of their balance is still fully locked vs. in cooldown/expired: [1](#0-0) 

The companion reward contract for `VLMGP`, `vlMGPBaseRewarder`, correctly uses this percentage to compute the amount that must be forfeited back into the pool when a user claims rewards: [2](#0-1) 

However, the analogous function in `mWOMSVBaseRewarder`, `_calExpireForfeit`, never calls `mWOMSV.getRewardablePercentWAD(_account)` at all. It simply sets `rewardableAmount = _amount`, guaranteeing `forfeitAmount` is always `0`: [3](#0-2) 

This value feeds directly into `_sendReward`, which is invoked whenever `getReward`/`getRewards` is called (reachable via `MasterMagpie.multiclaim`/`multiclaimFor`, which any staking wallet can trigger, including automatically inside `mWomSV.startUnlock()` and `mWomSV.unlock()`): [4](#0-3) 

Because `forfeitAmount` is always zero, the `_queueNewRewardsWithoutTransfer` redistribution path (which would otherwise route the forfeited share back to remaining long-term lockers) is never exercised for `mWomSV`.

### Impact Explanation
The intended design (demonstrated by the parallel, correctly-implemented `vlMGPBaseRewarder`) is that rewards are shared out by `getRewardablePercentWAD`: users who begin unwinding their lock via `startUnlock` should progressively forfeit a portion of their pending rewards, and that forfeited portion should be redistributed to users who keep their tokens fully locked. Because `_calExpireForfeit` is a no-op in `mWOMSVBaseRewarder`, every `mWomSV` staker keeps 100% of their accrued rewards regardless of lock status. This is a direct theft of yield that should have accrued to committed long-term lockers — an ordinary wallet can lock, accumulate rewards, immediately call `startUnlock`, and later `unlock`/claim without ever suffering the intended forfeiture, permanently diverting yield away from the pool of long-term stakers who were supposed to receive it.

### Likelihood Explanation
This requires no privileged role, oracle manipulation, or governance action — any wallet holding mWOM can `lock()`, wait for reward accrual, then call `startUnlock()`/`claim` to realize full rewards with zero forfeiture. The path is triggered automatically on every `startUnlock`/`unlock` call (which internally calls `multiclaimFor`), so it is trivially and repeatedly reachable by any user, not a one-off edge case.

### Recommendation
Fix `mWOMSVBaseRewarder._calExpireForfeit` to mirror `vlMGPBaseRewarder._calExpireForfeit`, i.e., compute `rewardableAmount` using `mWOMSV.getRewardablePercentWAD(_account)`:
```solidity
function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
    uint256 rewardablePercentWAD = mWOMSV.getRewardablePercentWAD(_account);
    uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
    ...
}
```

### Proof of Concept
1. User locks mWOM via `mWomSV.lock(amount)`, which deposits into `MasterMagpie` and begins accruing rewards in `mWOMSVBaseRewarder`.
2. Time passes; rewards accrue proportional to `balanceOf(user)` in `mWOMSVBaseRewarder.earned`.
3. User calls `mWomSV.startUnlock(amount)`, which internally triggers `IMasterMagpie(masterMagpie).multiclaimFor(...)` and thus `mWOMSVBaseRewarder.getReward`/`_sendReward`.
4. `_sendReward` calls `_calExpireForfeit(_account, userRewards[...])`, which returns `0` regardless of the user now being in cooldown, per [3](#0-2) .
5. User receives the full reward amount (`toSend = userRewards - 0`), instead of a reduced amount reflecting their `getRewardablePercentWAD`, and no forfeited amount is redistributed to remaining lockers — confirming the forfeiture invariant is never enforced.

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalmWomSV = fullyInLock + inCoolDown;
        if (userTotalmWomSV == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalmWomSV;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalmWomSV / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalmWomSV;
                }

            }
        }

        return percent;
    }

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }
