## Title
Deep link `openRepo?pr=` action forces an already-open trusted repository to add an attacker-chosen remote and check out attacker-controlled code without confirmation - (File: app/src/ui/dispatcher/dispatcher.ts)

### Summary
The `x-github-client://openRepo/...` protocol handler is registered as a system-wide URL scheme, so any web page, email, or other application can invoke it non-interactively (a single user click on a link is sufficient) and drive Desktop's `dispatchURLAction` → `openRepositoryFromUrl` flow. When the URL includes a `pr` query parameter, Desktop calls the GitHub API for that PR and, if it finds an already-open local repository whose *base* (not just head) matches the URL, it will automatically add a remote for the PR's `head.repo.clone_url` and check out that branch - all attacker-selected values, with no re-confirmation that the user actually intends to pull code from an arbitrary fork into their already-cloned, trusted working copy.

### Finding Description
`parseAppURL` in [1](#0-0)  accepts an arbitrary `pr` (validated only as `^\d+$`) and `url` (essentially unrestricted path segment) from any external caller invoking the registered protocol (`x-github-client`, `github-mac`, `github-windows`), as seen in the protocol registration at [2](#0-1)  and the `open-url`/`--protocol-launcher` handling at [3](#0-2) .

That parsed action flows to `Dispatcher.openRepositoryFromUrl`, which for `pr !== null` calls `openPullRequestFromUrl(url, pr)`: [4](#0-3) 

`openPullRequestFromUrl` fetches the PR from the API using the attacker-supplied `url`/`pr` pair, then tries to match it to an **already-open** local repository via `getRepositoryFromPullRequest`, which matches on either the PR's `head` **or** `base` repo URL: [5](#0-4) 

Because matching succeeds against the *base* URL, an attacker only needs to know a repository the victim already has open (e.g. a well-known public repo) and reference any PR number opened against it - the PR's `head.repo` (the fork) can be entirely attacker-controlled (their own fork, their own branch, any content). Once matched, Desktop silently calls `_checkoutPullRequest`, which adds a new remote pointing at `pullRequest.head.repo.clone_url` and fetches/checks it out: [6](#0-5) [7](#0-6) 

This mirrors the `VoterProxy.deposit` pattern: the function accepts caller-controlled identifiers (`_token`/`_gauge` ↔ here, `url`/`pr` and by extension the API-returned `head.repo.clone_url`) and performs a privileged action (adding a remote and mutating the working tree of an already-trusted repository) without validating that the supplied "gauge" (fork) is one the user actually intended to trust, and without any confirmation prompt gating the checkout of a totally different codebase into a directory the user already trusts.

### Impact Explanation
An attacker who gets a victim to click a single crafted link can force GitHub Desktop to fetch a remote controlled entirely by the attacker and check out attacker-authored code into a **pre-existing, trusted** local repository directory (e.g., `desktop/desktop` if the victim happens to have it open), silently swapping the working tree contents. If the victim subsequently builds/runs/commits from that directory (a normal workflow action, not an "unnatural step"), this can lead to execution of attacker-supplied code, or corruption of what the user later commits/pushes - matching the "silent corruption of what the user commits or pushes" impact class explicitly called out as valid.

### Likelihood Explanation
The only precondition is the victim clicking a link while GitHub Desktop is installed and having any repository open whose GitHub base/head URL the attacker can guess or discover (trivial for public repos, since the PR's `base` matches the target repo's URL, which is public knowledge). No local access, no leaked credentials, and no unusual manual steps beyond the single click are required - the whole chain from `open-url` to checkout is automatic.

### Recommendation
- Do not auto-select and mutate an already-open repository purely because the PR's *base* URL matches; at minimum require confirmation before adding a new remote/fetching from a fork URL that isn't already a known remote of the repository.
- Present an explicit consent dialog showing the fork owner/URL and target branch before calling `_checkoutPullRequest` when triggered via an external URL action (as opposed to a PR selected by the user inside the app's PR list).
- Consider validating `pr`/`url` combinations against a expected format tied to a specific already-authenticated GitHub account/session rather than trusting arbitrary externally supplied PR numbers.

### Proof of Concept
1. Victim has GitHub Desktop installed and has `github.com/desktop/desktop` open locally.
2. Attacker hosts a link: `x-github-client://openRepo/https://github.com/desktop/desktop?pr=<attacker_pr_number>` where `<attacker_pr_number>` is a real, attacker-opened PR against `desktop/desktop` from the attacker's own fork containing malicious content.
3. Victim clicks the link (e.g., embedded in a webpage or email).
4. `main.ts`'s `open-url` handler invokes `parseAppURL` → `dispatchURLAction` → `openRepositoryFromUrl` → `openPullRequestFromUrl`, which matches the victim's already-open `desktop/desktop` repository via the PR's `base` URL, adds a `github-desktop-<attacker>` remote pointing to the attacker's fork, fetches it, and checks out the attacker's branch into the victim's working directory - all without any explicit confirmation dialog specific to this cross-fork action.

**Note:** I could not fully verify from the indexed code whether any additional UI-level confirmation dialog intercepts this specific external-URL-triggered PR checkout path (e.g., a "trust this action" prompt might exist elsewhere in the UI layer that wasn't returned by search). If such a confirmation exists, this reduces likelihood but the underlying matching-on-`base`-URL design issue (trusting the wrong repo owner) remains.

async function handleCommandLineArguments(argv: string[]) {
  const args = parseCommandLineArgs(argv, {
    boolean: ['protocol-launcher'],
  })

  // Desktop registers it's protocol handler callback on Windows as
  // `[executable path] --protocol-launcher "%1"`. Note that extra command
  // line arguments might be added by Chromium
  // (https://electronjs.org/docs/api/app#event-second-instance).

  if (__WIN32__ && args['protocol-launcher'] === true) {
    // On Windows we'll end up getting called with something like
    // `--protocol-launcher --allow-file-access-from-files x-github-client://..`
    // which minimist naturally interprets as
    // `--allow-file-access-from-files=x:/github-client`. This is due to
    // Chromium's hot take on parsing command line arguments, see:
    // https://github.com/electron/electron/issues/20322#issuecomment-534137321
    // So while we could add '--allow-file...' as a boolean we can't know for
    // sure that Chromium won't add more switches later on which is why we have
    // to resort to looking through all arguments looking for something that
    // appears to be an app url.
    const prefixes = Array.from(possibleProtocols, p => `${p}://`)
    const matchingUrl = argv.find(arg => {
      if (prefixes.some(p => arg.startsWith(p))) {
        try {
          new URL(arg)
          return true
        } catch (e) {
          log.error(`Unable to parse argument as URL: ${arg}`)
        }
      }
      return false
    })

    if (matchingUrl) {
      handleAppURL(matchingUrl)
    } else {
      log.error(`Encountered --protocol-launcher without app url`)
    }
    // If --protocol-launcher is present we always want to bail and not
    // risk a smuggled cli switch
    return
  }

  private getRepositoryFromPullRequest(
    pullRequest: IAPIPullRequest
  ): RepositoryWithGitHubRepository | null {
    const state = this.appStore.getState()
    const repositories = state.repositories
    const headUrl = pullRequest.head.repo?.clone_url
    const baseUrl = pullRequest.base.repo?.clone_url

    // This likely means that the base repository has been deleted
    // and we don't support checking out from refs/pulls/NNN/head
    // yet so we'll bail for now.
    if (headUrl === undefined || baseUrl === undefined) {
      return null
    }

    for (const repository of repositories) {
      if (this.doesRepositoryMatchUrl(repository, headUrl)) {
        return repository
      }
    }

    for (const repository of repositories) {
      if (this.doesRepositoryMatchUrl(repository, baseUrl)) {
        return repository
      }
    }

    return null
  }

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }
    if (!isRepositoryWithGitHubRepository(repository)) {
      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    if (pullRequest.head.repo === null) {
      return null
    }

    await this.appStore._checkoutPullRequest(
      repository,
      pullRequest.number,
      pullRequest.head.repo.owner.login,
      pullRequest.head.repo.clone_url,
      pullRequest.head.ref
    )

    return repository
  }

  public async _checkoutPullRequest(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,
    headRefName: string
  ): Promise<void> {
    const prBranch = await this._findPullRequestBranch(
      repository,
      prNumber,
      headRepoOwner,
      headCloneUrl,
      headRefName
    )
    if (prBranch !== undefined) {
      await this._checkoutBranch(repository, prBranch)
      this.statsStore.increment('prBranchCheckouts')
    }
  }

  public async _findPullRequestBranch(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,
    headRefName: string
  ): Promise<Branch | undefined> {
    const gitStore = this.gitStoreCache.get(repository)
    const remotes = await getRemotes(repository)

    // Find an existing remote (regardless if set up by us or outside of
    // Desktop).
    let remote = remotes.find(r => urlMatchesRemote(headCloneUrl, r))

    // If we can't find one we'll create a Desktop fork remote.
    if (remote === undefined) {
      try {
        const forkRemoteName = forkPullRequestRemoteName(headRepoOwner)
        remote = await addRemote(repository, forkRemoteName, headCloneUrl)
      } catch (e) {
        this.emitError(
          new Error(
            `Couldn't find PR branch, adding remote failed: ${e.message}`
          )
        )
        return
      }
    }

    const remoteRef = `${remote.name}/${headRefName}`

    // Start by trying to find a local branch that is tracking the remote ref.
    let existingBranch = gitStore.allBranches.find(
      x => x.type === BranchType.Local && x.upstream === remoteRef
    )

    // If we found one, let's check it out and get out of here, quick
    if (existingBranch !== undefined) {
      return existingBranch
    }

    const findRemoteBranch = (name: string) =>
      gitStore.allBranches.find(
        x => x.type === BranchType.Remote && x.name === name
      )

    // No such luck, let's see if we can at least find the remote branch then
    existingBranch = findRemoteBranch(remoteRef)

    // It's quite possible that the PR was created after our last fetch of the
    // remote so let's fetch it and then try again.
    if (existingBranch === undefined) {
      try {
        await this._fetchRemote(repository, remote, FetchType.UserInitiatedTask)
        existingBranch = findRemoteBranch(remoteRef)
      } catch (e) {
        log.error(`Failed fetching remote ${remote?.name}`, e)
      }
    }

    if (existingBranch === undefined) {
      this.emitError(
        new Error(
          `Couldn't find branch '${headRefName}' in remote '${remote.name}'. ` +
            `A common reason for this is that the PR author has deleted their ` +
            `branch or their forked repository.`
        )
      )
      return
    }

    // For fork remotes we checkout the ref as pr/[123] instead of using the
    // head ref name since many PRs from forks are created from their default
    // branch so we'll have a very high likelihood of a conflicting local branch
    const isForkRemote =
      remote.name !== gitStore.defaultRemote?.name &&
      remote.name !== gitStore.upstreamRemote?.name

    if (isForkRemote) {
      return await this._createBranch(
        repository,
        `pr/${prNumber}`,
        remoteRef,
        false
      )
    }

    return existingBranch
  }
