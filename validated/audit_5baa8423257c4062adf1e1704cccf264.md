### Title
Unhandled `AssertionError` DoS when parsing a malformed offer from a counterparty - (File: `chia/wallet/trading/offer.py`)

### Summary
CVE-2023-37010 crashes the Open5GS MME via an `assert` that fires when a required field is missing from an attacker-supplied protocol message. The closest reachable analog in this codebase is `Offer._get_offered_coins()` in [1](#0-0) , which is invoked while a wallet parses an **offer file received from an untrusted counterparty** (via `take_offer`/`get_offer_summary` RPCs and CLI paths). It uses bare Python `assert` statements — `assert inner_puzzle is not None and inner_solution is not None` (line 260) and `assert cost_left >= puzzle_cost` (line 264) — on data (`puzzle_reveal`/`solution`) taken directly from the offer's coin spends, rather than raising a handled `ValueError`/`ValidationError`.

### Finding Description
`Offer.get_offered_coins()`/`_get_offered_coins()` iterates over `self._bundle.coin_spends` from a received offer, matches the outer puzzle via `match_puzzle()`, then calls the corresponding driver's `get_inner_puzzle`/`get_inner_solution` [2](#0-1) . If a crafted counterparty offer contains a puzzle reveal that superficially matches a known outer-puzzle mod (CAT/singleton/ownership/CR layer, etc.) but has an inconsistent/malformed inner structure or solution shape, the corresponding driver can return `None` for the inner puzzle or inner solution (or diverge from what `assert cost_left >= puzzle_cost` expects), tripping the bare `assert` instead of a caught exception type. Unlike `ValueError`/`ValidationError`, which are explicitly handled elsewhere in the wallet's transaction/offer pipeline (see the `add_transaction` and `pre_validate_spendbundle` exception handling pattern at [3](#0-2)  for the general design pattern the codebase relies on to convert error states into controlled failures), a Python `AssertionError` is not treated specially by these callers and propagates up uncaught.

### Impact Explanation
When Python runs with assertions enabled (the default for the installed wallet/daemon), an `AssertionError` raised while parsing a remotely-supplied offer is an unhandled exception. Depending on the call path (RPC handler, CLI command, or async task), this either surfaces as an ungraceful failure of the RPC request or, if not caught by a wrapping handler, terminates the coroutine/task processing the offer — a spend/offer-triggered transaction-processing halt reachable by any offer counterparty, directly analogous to the S1AP assertion DoS in the CVE.

### Likelihood Explanation
An attacker only needs to construct and send/share a single malformed offer (no privileged access required) to a wallet user who inspects or attempts to take it (`get_offer_summary`/`take_offer`). Crafting a puzzle reveal that matches an outer-puzzle mod's curry shape while breaking the driver's inner-puzzle/inner-solution assumptions is a purely local, low-cost data-shaping exercise.

### Recommendation
Replace the bare `assert` statements in `Offer._get_offered_coins()` with explicit `raise ValueError(...)`/`ValidationError` checks so malformed counterparty-supplied offers fail gracefully instead of raising `AssertionError`, and audit other outer-puzzle drivers (`chia/wallet/nft_wallet/*_outer_puzzle.py`, `chia/wallet/vc_wallet/cr_outer_puzzle.py`, `chia/wallet/cat_wallet/cat_outer_puzzle.py`) for the same bare-`assert`-on-untrusted-data pattern.

### Proof of Concept
1. Construct an `Offer`/`WalletSpendBundle` whose `coin_spends` include a puzzle reveal that uncurries to a recognized outer-puzzle mod (e.g., the CR layer or singleton mod) but whose curried inner-puzzle/solution layout is truncated or restructured so that the corresponding driver's `get_inner_puzzle`/`get_inner_solution` returns `None`, or so that `inner_puzzle.run_with_cost` reports a cost exceeding `cost_left`.
2. Serialize this as an offer file/string and share it with a victim wallet.
3. Have the victim call `get_offer_summary` or `take_offer` (RPC or CLI) on the malformed offer; this reaches `Offer._get_offered_coins()` and trips one of the bare `assert` statements at [4](#0-3) , raising an uncaught `AssertionError`.

    def _get_offered_coins(self) -> dict[bytes32 | None, list[Coin]]:
        offered_coins: dict[bytes32 | None, list[Coin]] = {}

        cost_left = INFINITE_COST
        for parent_spend in self._bundle.coin_spends:
            coins_for_this_spend: list[Coin] = []

            parent_puzzle: UnknownPuzzle = UnknownPuzzle(known_program=parent_spend.puzzle_reveal)
            parent_solution = Program.from_serialized(parent_spend.solution)
            additions: list[Coin] = self._additions[parent_spend.coin]

            puzzle_driver = match_puzzle(parent_puzzle)
            if puzzle_driver is not None:
                asset_id = create_asset_id(puzzle_driver)
                inner_puzzle: Program | None = get_inner_puzzle(puzzle_driver, parent_puzzle, parent_solution)
                inner_solution: Program | None = get_inner_solution(puzzle_driver, parent_solution)
                assert inner_puzzle is not None and inner_solution is not None

                # We're going to look at the conditions created by the inner puzzle
                puzzle_cost, conditions = inner_puzzle.run_with_cost(cost_left, inner_solution)
                assert cost_left >= puzzle_cost
                cost_left -= puzzle_cost
                expected_num_matches: int = 0
                offered_amounts: list[int] = []
                for condition in conditions.as_iter():
                    if condition.first() == 51 and condition.rest().first() == OFFER_MOD_HASH:
                        expected_num_matches += 1
                        offered_amounts.append(condition.rest().rest().first().as_int())

                # Start by filtering additions that match the amount
                matching_spend_additions = [a for a in additions if a.amount in offered_amounts]

                if len(matching_spend_additions) == expected_num_matches:
                    coins_for_this_spend.extend(matching_spend_additions)
                # We didn't quite get there so now lets narrow it down by puzzle hash
                else:
                    # If we narrowed down too much, we can't trust the amounts so start over with all additions
                    if len(matching_spend_additions) < expected_num_matches:
                        matching_spend_additions = additions
                    matching_spend_additions = [
                        a
                        for a in matching_spend_additions
                        if a.puzzle_hash == construct_puzzle(puzzle_driver, OFFER_MOD).get_tree_hash()
                    ]
                    if len(matching_spend_additions) == expected_num_matches:
                        coins_for_this_spend.extend(matching_spend_additions)
                    else:
                        raise ValueError("Could not properly guess offered coins from parent spend")
