### Title
PedPoG DKG accepts identity encryption keys, exposing encrypted secret shares to all observers - ([File: crypto/dkg/pedpop/src/encryption.rs](crypto/dkg/pedpop/src/encryption.rs))

### Summary
`EncryptionKeyMessage::read` deserializes the recipient's ECDH public key (`enc_key`) with `C::read_G`, which enforces only canonical point encoding — not non-identity — and `Decryption::register` stores it without any validity check. A malicious DKG participant can broadcast an `EncryptionKeyMessage` whose `enc_key` is the identity point. Every honest sender's `Encryption::encrypt` then computes `ecdh = enc_key * key = identity`, a shared secret whose value is publicly known, so the ChaCha20 key wrapping that participant's FROST secret share is derivable by anyone who observes the ciphertext. This maps the CVE's "load a maliciously crafted structure → compromise" class onto Serai's untrusted-bytes deserialization surface. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
In `crypto/dkg/pedpop/src/encryption.rs`, `EncryptionKeyMessage::read` performs `enc_key: C::read_G(reader)?`. `Ciphersuite::read_G` (`crypto/ciphersuite/src/lib.rs:91`) only checks that the encoding is a valid canonical point; it explicitly allows the identity element (contrast with `Curve::read_G` in `crypto/frost/src/curve/mod.rs:125`, which rejects identity but is only used in the FROST signing path, not PedPoP). `Decryption::register` (`encryption.rs:351-362`) then inserts `msg.enc_key` into `enc_keys` with no check. When an honest participant later calls `Encryption::encrypt` → `encrypt(...)` (`encryption.rs:460-467, 135-168`), the shared secret is `ecdh(&key, to) = to * key`. If `to` is the identity, the result is always the identity point regardless of `key`, so `cipher::<C>(context, &identity)` produces a ChaCha20 keystream keyed on a constant, publicly computable value. The `EncryptedMessage` PoP (`pop`) authenticates the per-message key `key*G`, not the recipient key, so the sender cannot detect the substitution — the sender encrypts to whatever was registered. ### Impact Explanation
The PedPoP DKG sends each participant's `SecretShare` encrypted under an ECDH key so only the intended recipient can read it (`SecretShareMachine::generate_secret_shares`, `pedpop/src/lib.rs:366-369`). With an identity `enc_key`, every share addressed to the malicious participant is encrypted under the known point `identity`, meaning any party that observes the `EncryptedMessage` (the messages are only assumed authenticated, not confidential — the comment at `encryption.rs:300-301` explicitly states the DKG does not offer a confidential channel) can derive the ChaCha20 key and recover that participant's secret share plaintext. An adversary controlling `t-1` DKG participants therefore only needs to passively observe one additional victim's share to reconstruct the full group private key, instead of needing `t` colluders. This is key-share recovery / secret leakage reachable purely by an unprivileged participant submitting crafted public bytes. [8](#0-7) [9](#0-8) [10](#0-9) 

### Likelihood Explanation
The attack requires only that a DKG participant broadcast a well-formed `EncryptionKeyMessage` whose trailing `enc_key` bytes encode the identity point — fully within the reach of any protocol participant, with no collusion, no broken BFT assumptions, and no leaked keys. The honest-side code path (`verify_r1` → `register` → `encrypt`) performs zero validation of the point beyond canonical decoding, so the attack succeeds deterministically whenever the library is used with a malicious participant and share messages transit any channel observable by an attacker (which the code itself assumes, since it added per-message PoPs precisely because the channel is not confidential). [11](#0-10) [12](#0-11) 

### Recommendation
Reject the identity point when reading the encryption key in `EncryptionKeyMessage::read` (e.g., `if enc_key.is_identity().into() { Err(...) }` or use a `read_G` variant that rejects identity as `Curve::read_G` does), and additionally reject identity `key`/`pop.R` in `EncryptedMessage::read`/`decrypt`/`decrypt_with_proof` to prevent trivially-known ECDH secrets. Optionally require a proof of possession for the registered `enc_key`. [13](#0-12) 

### Proof of Concept
1. Attacker (participant `l`) runs `KeyGenMachine::generate_coefficients` normally but crafts its `EncryptionKeyMessage` serialization by appending the identity encoding (`[0;32]` for Ristretto/Ed25519 `from_bytes` yields identity — wait, for Ristretto identity encodes as 32 zero bytes) in place of `enc_key`. `Commitments` PoK is unaffected since `enc_key` is not covered by `challenge()`. [14](#0-13) 
2. Each honest participant's `verify_r1` accepts the message: `C::read_G` decodes identity fine, `register` stores it, PoK verification passes. [15](#0-14) 
3. Each honest sender calls `self.encryption.encrypt(rng, l, share_bytes)`; internally `ecdh(&key, identity) = identity`, so `cipher(context, identity)` produces keystream `ChaCha20(transcript("DKG Encryption v0.2" | context | identity.to_bytes()))`. [16](#0-15) 
4. Anyone observing the emitted `EncryptedMessage` recomputes the same keystream (all inputs are public: `context`, and the ECDH output is always the constant identity encoding) and XORs it against `msg` to recover the victim's FROST secret share. [17](#0-16) 

Caveat: I could not exhaustively confirm there is no identity check upstream of `register` in a calling crate; within the in-scope pedpop code shown, no such check exists.

fn cipher<C: Ciphersuite>(context: [u8; 32], ecdh: &Zeroizing<C::G>) -> ChaCha20 {
  // Ideally, we'd box this transcript with ZAlloc, yet that's only possible on nightly
  // TODO: https://github.com/serai-dex/serai/issues/151
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"encryption_key");

  let mut ecdh = ecdh.to_bytes();
  transcript.append_message(b"shared_key", ecdh.as_ref());
  ecdh.as_mut().zeroize();

  let zeroize = |buf: &mut [u8]| buf.zeroize();

  let mut key = Cc20Key::default();
  let mut challenge = transcript.challenge(b"key");
  key.copy_from_slice(&challenge[.. 32]);
  zeroize(challenge.as_mut());

  // Since the key is single-use, it doesn't matter what we use for the IV
  // The issue is key + IV reuse. If we never reuse the key, we can't have the opportunity to
  // reuse a nonce
  // Use a static IV in acknowledgement of this
  let mut iv = Cc20Iv::default();
  // The \0 is to satisfy the length requirement (12), not to be null terminated
  iv.copy_from_slice(b"DKG IV v0.2\0");

  // ChaCha20 has the same commentary as the transcript regarding ZAlloc
  // TODO: https://github.com/serai-dex/serai/issues/151
  let res = ChaCha20::new(&key, &iv);
  zeroize(key.as_mut());
  res
}

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
  }
