### Title
Unbounded recursive puzzle-driver matching causes stack exhaustion (Python `RecursionError`) on attacker-crafted nested outer puzzles - ([File: chia/wallet/outer_puzzles.py])

### Summary
`chia/wallet/outer_puzzles.py::match_puzzle()` and the family of outer-puzzle driver classes (`CATOuterPuzzle`, `SingletonOuterPuzzle`, `OwnershipOuterPuzzle`, `CROuterPuzzle`, etc.) recursively descend into nested "also" puzzle layers with no depth limit. An attacker who supplies a `CoinSpend`/`SpendBundle` (e.g., inside an offer file, or any coin whose puzzle reveal is parsed by wallet/offer code) can nest an arbitrary number of matched outer-puzzle layers (e.g., CAT-wrapping-CAT, as already demonstrated in `chia/_tests/wallet/cat_wallet/test_cat_outer_puzzle.py`) to drive Python recursion to thousands of frames, causing a `RecursionError`/native stack exhaustion. This mirrors the qpdf `CVE-2017-11625` bug class — an unbounded recursive resolver crashing on a crafted, deeply nested input — except here the analog is Python-side puzzle-layer resolution rather than PDF object resolution.

### Finding Description
`match_puzzle()` iterates driver classes and calls `driver.match(puzzle)`: [1](#0-0) 

Each driver's `match()` method (e.g. `CROuterPuzzle.match`, and analogously `CATOuterPuzzle`, `SingletonOuterPuzzle`, `OwnershipOuterPuzzle`) recurses into the next inner puzzle layer via `self._match(...)`, which is bound to the same top-level `match_puzzle` function: [2](#0-1) 

The `also()` chaining pattern is used uniformly across `construct`, `solve`, `get_inner_puzzle`, and `get_inner_solution` as well, so all of these recurse to the same depth as the number of nested outer-puzzle layers present in the puzzle reveal: [3](#0-2) 

Nothing bounds how many outer-puzzle layers a puzzle reveal can contain — `Program.uncurry()` and `as_iter()` themselves are not depth-limited, and this is unlike `sha256_treehash()`, whose docstring explicitly states it was made non-recursive "so we don't have to worry about blowing out the Python stack": [4](#0-3) 

The reachable path from untrusted input is through offer/spend-bundle parsing. `Offer.from_spend_bundle()` calls `match_puzzle()` directly on each `coin_spend.puzzle_reveal` taken from an attacker-supplied `SpendBundle` (e.g., a maliciously crafted offer file accepted by a wallet or RPC caller): [5](#0-4) 

and `Offer._get_offered_coins()` similarly calls `match_puzzle`, `get_inner_puzzle`, `get_inner_solution`, and `construct_puzzle` on parent-spend puzzle reveals pulled straight from the offer/spend bundle: [6](#0-5) 

An attacker can construct a puzzle reveal consisting of, e.g., N nested `CAT_MOD` curry layers (confirmed feasible and already exercised at small scale by `test_cat_outer_puzzle`, which builds a `double_cat_puzzle`): [7](#0-6) 

By scaling N past Python's default recursion limit (~1000), `match_puzzle`/`construct_puzzle`/`get_inner_puzzle`/`get_inner_solution` recursion chains will raise `RecursionError`, crashing whichever process (wallet, RPC handler) is parsing the offer/spend bundle.

### Impact Explanation
This is a spend-bundle/offer-triggered denial of service: a wallet user or RPC caller who inspects, accepts, or otherwise processes an attacker-supplied offer or spend bundle containing a deeply nested outer-puzzle chain can crash their wallet process with an unhandled `RecursionError` while `match_puzzle`/`Offer.from_spend_bundle`/`Offer.get_offered_coins` recurse through the layers. This qualifies as a spend-triggered transaction-processing halt for the affected wallet process, matching the CVE's stack-exhaustion/DoS bug class, though it is scoped to Python-side wallet/offer parsing rather than full-node consensus validation (CLVM execution itself remains cost-bounded and safe).

### Likelihood Explanation
Likelihood is fairly high for the wallet/offer path: constructing nested CAT/singleton/ownership/CR layers only requires standard `curry()` calls on already-public puzzle mods, no signatures or special permissions are needed to author an offer file, and a victim wallet processing any untrusted offer (a normal wallet workflow) triggers `match_puzzle` unconditionally on the attacker's puzzle reveal.

### Recommendation
Add an explicit recursion-depth bound (e.g., a `max_depth`/`also()`-chain-length check) in `match_puzzle`, `construct_puzzle`, `solve_puzzle`, `get_inner_puzzle`, and `get_inner_solution` in `chia/wallet/outer_puzzles.py`, and reject or convert to an iterative implementation (similar to `sha256_treehash`) once puzzle nesting exceeds a safe threshold, rather than allowing unbounded Python recursion driven by attacker-controlled puzzle structure.

### Proof of Concept
1. Construct a puzzle reveal `P_N` consisting of `N` nested `CAT_MOD` curry layers around an inner "always spend" puzzle, analogous to `double_cat_puzzle` in `test_cat_outer_puzzle` but repeated `N` times (e.g., `N = 2000`).
2. Build a `CoinSpend`/`SpendBundle` using `P_N` as `puzzle_reveal` (no valid signature needed to trigger the parsing path, since `match_puzzle`/`Offer.from_spend_bundle` run before signature checks).
3. Package it as an offer file or hand it to a wallet RPC that calls `Offer.from_spend_bundle()`/`Offer.get_offered_coins()`, or directly call `match_puzzle(UnknownPuzzle(known_program=P_N))`.
4. Observe that the recursive `match`/`get_inner_puzzle`/`get_inner_solution`/`construct` chain across `chia/wallet/outer_puzzles.py` and driver classes raises `RecursionError`, crashing the process handling the offer.

def test_cat_outer_puzzle() -> None:

    tail = bytes32.zeros
    cat_puzzle: Program = construct_cat_puzzle(CAT_MOD, tail, ACS)
    double_cat_puzzle: Program = construct_cat_puzzle(CAT_MOD, tail, cat_puzzle)

    cat_driver: PuzzleInfo | None = match_puzzle(uncurried_cat_puzzle)

    assert cat_driver is not None
    assert cat_driver.type() == "CAT"
    assert cat_driver["tail"] == tail
    inside_cat_driver: PuzzleInfo | None = cat_driver.also()
    assert inside_cat_driver is not None
    assert inside_cat_driver.type() == "CAT"
    assert inside_cat_driver["tail"] == tail
