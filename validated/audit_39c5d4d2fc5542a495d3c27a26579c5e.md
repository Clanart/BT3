## Title
Unbound reputation minting via self-declared `signer` on permissionless `handle_unsigned` lets an unprivileged attacker cheaply buy collator selection and fisherman veto power — (File: `modules/pallets/messaging-incentives/src/lib.rs`)

## Summary
`pallet-messaging-incentives` mints `ReputationAsset` — the sole ranking metric for collator selection (`pallet-collator-manager`) and thus for who gets fisherman veto power (`pallet-fishermen`) — proportionally to message byte-size, with **no rate limiter, no cap, and no verification that the credited account actually bore the cost or risk of delivering the message**. This is the direct local analog of the C4 report: a mint path that bypasses `RateLimitedMinter`-style throttling and lets anyone cheaply acquire an asset that carries outsized governance/authority weight.

## Finding Description
`Pallet::relayer_for` recovers the reputation beneficiary purely from a self-supplied `signer` field embedded in the `Message::Request`/`Message::Response` payload: [1](#0-0) 

That signature is checked only for *validity* (a correct sr25519 signature over `keccak256(encode(requests))`) — never for correspondence to the account that actually delivered the message, paid a relayer fee, or bore any risk. Since `pallet-ismp::handle_unsigned` is deliberately unsigned and permissionless ("permits anyone execute ISMP messages for free, provided they have valid proofs and the messages have not been previously processed"): [2](#0-1) 

...any actor who can produce a valid `RequestMessage` + membership proof can also choose whatever `signer` value they like — including a signature from a key they personally control — with zero connection to whoever paid gas or dispatched the original request. `on_executed` then mints `bytes × MintPerByte` straight to that self-chosen account with no cap: [3](#0-2) 

`ReputationAsset` is the exclusive ranking key for the next collator set: [4](#0-3) 

And being a collator grants unilateral, proof-free authority to delete any state commitment via `pallet-fishermen::veto_state_commitment`, gated only by `IsCollator`, no evidence required: [5](#0-4) 

Existing guards do **not** stop this: the proof-validity check on `handle_unsigned` only confirms the *requests* (source, dest, body, nonce) are real and unprocessed — it never binds `msg.signer` to the extrinsic submitter or to the entity that incurred delivery cost. There is no per-account/per-block cap on reputation minting (`MintPerByte` scales linearly and unboundedly with `bytes`), unlike `RateLimitedMinter`'s `hardCap`/buffer used elsewhere in similar minting contexts.

## Impact Explanation
An unprivileged attacker who controls two apps on already-connected chains can dispatch cheap, self-to-self POST requests with maximal body size, fetch the resulting membership proof (public data), and submit `handle_unsigned` themselves with a `signer` field pointing to their own key. This attributes the reputation mint intended for genuine relayer economics to the attacker, at a cost bounded only by gas + message-size, not by any real delivery risk or protocol fee (fees are optional per the `fund_message` design). Accumulated reputation displaces legitimate collators in `new_session` selection, and once seated as a collator the attacker gains unilateral fisherman veto power — the ability to delete *any* state commitment, including valid ones, with no proof requirement. This is a logic attack enabling unauthorized/false state manipulation (deletion of legitimate state commitments), directly matching the required impact category, and mirrors the original report's core defect: an un-rate-limited mint of an asset that buys outsized governance/veto power cheaply.

## Likelihood Explanation
No privileged role, relayer status, or compromised key is required — `handle_unsigned` is explicitly permissionless by design, and the `signer` field is attacker-controlled data with no binding to actual delivery. The only cost is ordinary cross-chain message gas plus waiting out the challenge period, which is cheap and repeatable at will, especially against low-fee source/destination chains already registered with Hyperbridge.

## Recommendation
Bind the reputation-mint beneficiary to a value the pallet can actually trust — e.g., the account that submitted the `handle_unsigned` extrinsic (if `pallet-ismp` is changed to carry that context) or a relayer identity cryptographically tied to the proof-of-delivery pipeline (similar to the `OutboundRequestDeliveryClaim` signature-attribution model used in `modules/pallets/relayer/src/outbound_request.rs`, which recovers the signer from a receipt proven on the destination chain rather than trusting a self-declared field). Additionally, introduce a rate-limited/capped mint (per-account or per-block) analogous to `RateLimitedMinter`, so no single account can accumulate reputation faster than genuine, cost-bearing relaying activity would allow.

## Proof of Concept
1. Attacker deploys a trivial ISMP app on chain A and chain B, both already connected to Hyperbridge (no privileged setup needed).
2. Attacker dispatches a POST request from their app on A to their app on B with as large a body as economically tolerable, `fee: 0`.
3. Attacker waits for the destination consensus/challenge period, then independently constructs the `RequestMessage { requests, proof, signer }`, computing `signer` as `Signature::Sr25519 { public_key: attacker_pubkey, signature: sign(keccak256(encode(requests))) }` using a key they own — this requires no coordination with the tesseract relayer or any registered operator.
4. Attacker submits `Ismp::handle_unsigned([Message::Request(request_message)])` directly — permissionless, unsigned, free.
5. `pallet-messaging-incentives::on_executed` computes `bytes = max(body.len(), 32)`, mints `bytes × MintPerByte` `ReputationAsset` to the attacker's account per `Self::relayer_for`.
6. Repeat cheaply across many blocks/messages to accumulate a `ReputationAsset` balance exceeding legitimate collator candidates.
7. At the next session boundary, `pallet-collator-manager::new_session` ranks candidates by this balance; the attacker's controller account is selected as collator.
8. As a collator, the attacker calls `pallet-fishermen::veto_state_commitment` to delete an arbitrary, legitimately-finalized state commitment with no proof obligation, disrupting or manipulating cross-chain settlement for real users.

	fn relayer_for(message: &Message) -> Option<T::AccountId> {
		let (signer, signed) = match message {
			Message::Request(msg) =>
				(&msg.signer, sp_io::hashing::keccak_256(&msg.requests.encode())),
			Message::Response(msg) =>
				(&msg.signer, sp_io::hashing::keccak_256(&msg.requests.encode())),
			_ => return None,
		};
		Signature::decode(&mut &signer[..])
			.ok()?
			.verify_and_get_sr25519_pubkey(&signed, None)
			.ok()
			.map(T::AccountId::from)
	}

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		_events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let rate = MintPerByte::<T>::get();
		if !rate.is_zero() {
			for mw in &messages {
				let bytes = Self::message_bytes(&mw.message);
				let bytes_balance: BalanceOf<T> = (bytes as u128).saturated_into();
				let amount = rate.saturating_mul(bytes_balance);
				if amount.is_zero() {
					continue;
				}
				if let Some(relayer) = Self::relayer_for(&mw.message) {
					match T::ReputationAsset::mint_into(&relayer, amount) {
						Ok(_) =>
							Self::deposit_event(Event::ReputationMinted { relayer, bytes, amount }),
						Err(err) => log::warn!(
							target: "messaging-incentives",
							"reputation mint failed for {bytes}b: {err:?}",
						),
					}
				}
			}
		}
		Ok(PostDispatchInfo { actual_weight: None, pays_fee: Pays::No })
	}
