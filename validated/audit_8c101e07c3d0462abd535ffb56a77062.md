### Title
Governance-settable `GasTarget=0` causes division-by-zero panic in `NextMagmaBlockBaseFee` — ([File: params/kip71_config.go])

### Summary
`KIP71Config.NextMagmaBlockBaseFee` divides by the governance-controlled `GasTarget` parameter without checking for zero, unlike the sibling `BaseFeeDenominator` parameter which is explicitly guarded against zero. The `Kip71GasTarget` governance parameter uses a `noopFormatChecker`, meaning it can be set to `0` through a normal governance vote. Once set to zero, any block whose gas usage is nonzero triggers a `big.Int` division-by-zero panic, exactly analogous to the reported `ad9832_calc_freqreg()` CVE pattern (unchecked divisor derived from external/attacker-influenced input).

### Finding Description
In `params/kip71_config.go`, `NextMagmaBlockBaseFee` computes the base-fee delta using `gasTarget := kc.GasTarget` as a divisor: [1](#0-0) 

```go
var baseFeeDenominator *big.Int
if kc.BaseFeeDenominator == 0 {
    // To avoid panic, set the fluctuation range small
    baseFeeDenominator = new(big.Int).SetUint64(64)
} else {
    baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
}
gasTarget := kc.GasTarget
upperGasLimit := kc.MaxBlockGasUsedForBaseFee
```

Note the explicit comment "To avoid panic" for `BaseFeeDenominator == 0`, but there is no equivalent guard for `gasTarget == 0`. Further down, when the parent block's gas usage exceeds `gasTarget`: [2](#0-1) 

```go
parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
if parentGasUsed == gasTarget {
    return makeEvenByFloor(parentBaseFee)
} else if parentGasUsed > gasTarget {
    ...
    gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
    x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
    y := x.Div(x, new(big.Int).SetUint64(gasTarget))
    baseFeeDelta := math.BigMax(x.Div(y, baseFeeDenominator), common.Big1)
```

If `gasTarget == 0` and `parentGasUsed > 0` (i.e., `MaxBlockGasUsedForBaseFee > 0` and actual gas used is nonzero), the branch `parentGasUsed > gasTarget` is taken and `x.Div(x, new(big.Int).SetUint64(0))` is executed. Go's `math/big.Int.Div` panics with `"division by zero"` when the divisor is zero.

The root cause is that `GasTarget` is a governance parameter validated by a no-op format checker instead of a zero-rejecting one, in contrast with `BaseFeeDenominator`: [3](#0-2) 

```go
Kip71BaseFeeDenominator: {
    ...
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0
    },
    ...
},
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: noopFormatChecker,
    ...
},
```

This means governance can legitimately vote `GasTarget = 0` into the chain config, and the code path that guards against a zero denominator elsewhere does nothing to protect this divisor.

### Impact Explanation
Once `GasTarget = 0` becomes active in the chain configuration (post-Magma fork), `NextMagmaBlockBaseFee` panics whenever a block's gas usage is nonzero. This function is invoked from:
- `node/cn/gasprice/feehistory.go` (`processBlock`), which is reachable by any **public RPC caller** via `eth_feeHistory` — the query itself, using the next block's `KIP71Config` and current header data, can trigger the panic without submitting any transaction.
- `node/cn/gasprice/gasprice.go`, part of gas price suggestion (`SuggestPrice`), also reachable via RPC.
- Block header verification (`VerifyMagmaHeader`) and block assembly paths that consume `NextMagmaBlockBaseFee`, meaning normal block processing/production after the malicious parameter takes effect would also panic on all nodes.

A panic in these paths crashes the node process (denial of service), and if triggered during block validation/production it can crash all honest nodes simultaneously (chain halt), which maps to the CVSS `A:H` (availability impact) component of the source CVE. This satisfies "acceptance of an invalid transaction or block" / "state divergence between honest nodes" style impact via a node-crashing DoS reachable from block processing and public RPC queries.

### Likelihood Explanation
Setting `GasTarget = 0` requires a successful governance vote (single governance mode with `GoverningNode`, or KIP governance quorum). This raises the bar compared to a fully unauthenticated attacker, but the codebase explicitly categorizes governance parameters as an in-scope reachable path, and the vulnerability is a straightforward oversight: the same file already guards the analogous `BaseFeeDenominator == 0` case with an explicit "to avoid panic" comment, but omits the identical guard for `GasTarget`. Any governance node (malicious, compromised, or simply misconfigured) can trigger a chain-wide panic, and any public RPC caller can trigger the panic via `eth_feeHistory` once the value is set — no privileged access is needed for the RPC-triggered crash after the parameter change occurs.

### Recommendation
Add a zero-check for `GasTarget` in `NextMagmaBlockBaseFee`, mirroring the existing safeguard for `BaseFeeDenominator` (e.g., fall back to a safe default value or return early with the current/lower/upper bound base fee when `gasTarget == 0`). Additionally, update the `Kip71GasTarget` parameter's `FormatChecker` in `kaiax/gov/param.go` to reject `0`, consistent with `Kip71BaseFeeDenominator`.

### Proof of Concept
1. Via governance, vote `kip71.gastarget = 0` (and ensure `kip71.maxblockgasusedforbasefee > 0`) so it becomes the active `ParamSet` value at some future block.
2. Once active, any block with nonzero `GasUsed` causes:
   - Block processing/validation to call `KIP71Config.NextMagmaBlockBaseFee(parentNumber, parentBaseFee, parentGasUsed)` with `gasTarget = 0` and `parentGasUsed > 0`.
   - Execution reaches `x.Div(x, new(big.Int).SetUint64(gasTarget))` with `gasTarget = 0`.
3. `math/big.Int.Div` panics with `division by zero`, crashing the node process. The same panic can independently be triggered by any public RPC caller invoking `eth_feeHistory`, since `node/cn/gasprice/feehistory.go`'s `processBlock` calls `kip71Config.NextMagmaBlockBaseFee(bf.header.Number, bf.header.BaseFee, bf.header.GasUsed)` unconditionally when `isNextBlockMagma` is true.
