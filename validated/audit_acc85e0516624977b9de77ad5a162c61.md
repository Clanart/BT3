### Title
`Scanner::scan_transaction` reports arbitrarily small (sub-dust) outputs as received funds which are not economically spendable - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The bug class in the reference report is a swap executing without a minimum-amount-out check, letting a counterparty push the trade to a value worse than the user would accept. The Serai analog lives in the Bitcoin wallet's receive path: `Scanner::scan_transaction` credits any output whose `script_pubkey` matches a registered vault script, with no lower bound on `output.value`. An unprivileged attacker can send a valid (or merely consensus-valid) transaction paying the vault's P2TR script with a sub-dust amount. The scanner reports it as a `ReceivedOutput`, even though spending it costs more in fees than it is worth — and below ~546 sats the spend transaction is not even relayed by standard nodes, making the credited funds unspendable.

### Finding Description
`scan_transaction` performs a single check: `self.scripts.get(&output.script_pubkey)` [1](#0-0) . Whatever value is attached to the output is cloned into the returned `ReceivedOutput` verbatim. `ReceivedOutput::value()` then reports this amount as received value [2](#0-1) .

The crate itself acknowledges the economic minimum elsewhere: `send.rs` defines `DUST: u64 = 546` and refuses to *create* payments below it, because such outputs cannot be spent under standard relay policy [3](#0-2) . The receive side has no symmetric check. An output of 1 sat (or even 0 sats, consensus-valid though non-standard) to the vault script is reported as a valid `ReceivedOutput`.

There is also no value sanity check in `ReceivedOutput::read`, which deserializes attacker-influenced bytes into a `TxOut` — any `Amount` is accepted [4](#0-3) .

### Impact Explanation
Exactly mirroring the reference finding, the "received amount" is unbounded below: an attacker determines the effective value of the deposit at broadcast time. A `ReceivedOutput` under 546 sats cannot fund a relayable spend transaction (a Taproot input alone is ~57 vbytes, requiring ≥ 57 sats at minimum relay fee just for itself, plus outputs and overhead — exceeding any sub-dust value). Funds are reported received by the scanner that are not spendable, and any downstream accounting crediting `output.value()` overstates recoverable funds; dust outputs effectively become a permanent accounting liability (unspendable UTXOs that pollute the input set and force `SignableTransaction::new` into `NotEnoughFunds` or wasted-fee paths).

### Likelihood Explanation
Any third party can send a Bitcoin transaction paying to the vault's publicly-known P2TR script; no authentication, key material, or collusion is required. Crafting a sub-dust output is trivially cheap.

### Recommendation
In `scan_transaction` (and/or `ReceivedOutput::read`), reject outputs with `value < DUST` — or at minimum flag them so callers do not treat them as spendable. Alternatively, track received-but-uneconomical outputs separately so they are never fed to `SignableTransaction::new` as inputs nor credited as received balance.

### Proof of Concept
```rust
// Attacker knows the vault's tweaked key / script_pubkey (public).
let victim_script = p2tr_script_buf(vault_key).unwrap();
let mut scanner = Scanner::new(vault_key).unwrap();

// Attacker broadcasts a tx with a 1-sat output to the vault script.
let attacker_tx = Transaction {
  version: Version(2),
  lock_time: LockTime::ZERO,
  input: vec![/* any spendable input */],
  output: vec![TxOut {
    value: Amount::from_sat(1),              // far below DUST = 546
    script_pubkey: victim_script,
  }],
};

let outputs = scanner.scan_transaction(&attacker_tx);
assert_eq!(outputs.len(), 1);                 // credited as received
assert_eq!(outputs[0].value(), 1);            // reports 1 sat received
// Spending this output requires >1 sat of fee: the "funds" are unspendable
// under relay policy, yet the scanner credited them as a ReceivedOutput.
```

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
