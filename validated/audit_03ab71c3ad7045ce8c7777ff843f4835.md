### Title
DNS-rebinding-style bypass of EVM JSON-RPC access control via hardcoded wildcard Vhosts and default wildcard CORS - (File: evmrpc/server.go)

### Summary
The Sei EVM JSON-RPC HTTP server binds to `0.0.0.0` on port 8545 and constructs its `HTTPConfig` with `Vhosts: []string{"*"}` hardcoded (not configurable) and a default `CORSOrigins` of `"*"`. This is architecturally the same bug class as CVE-2018-5702: Transmission relied on a browser-reachable header for RPC access control that a DNS-rebinding attacker could forge from any origin. Here, the two mitigations that go-ethereum's RPC stack normally relies on to block browser-driven / DNS-rebinding attacks against a locally-bound JSON-RPC endpoint — Host header (vhost) validation and CORS origin restriction — are both effectively disabled by default in sei-chain's EVM RPC server.

### Finding Description
`NewEVMHTTPServer` builds the HTTP RPC config with: [1](#0-0) 

`Vhosts` is unconditionally set to `["*"]` with no configuration knob, meaning `virtualHostHandler.ServeHTTP` will always match the wildcard and forward every request regardless of the `Host` header presented by the client: [2](#0-1) 

Additionally, `CORSOrigins` defaults to `"*"`: [3](#0-2) 

which is split and fed into `newCorsHandler` via `NewHTTPHandlerStack`: [4](#0-3) 

The combined effect: (1) any hostname can reach the RPC listener because Host-header validation is disabled by design (the classic DNS-rebinding defense that Firefox/Chrome's Fetch/XHR same-origin model would otherwise be bypassed with — an attacker registers a domain, gets a victim's browser to resolve it to the node's local/internal IP after initial same-origin checks, i.e., "DNS rebinding"), and (2) CORS is wide open by default so a malicious webpage's JavaScript can read the JSON response back (unlike a plain form POST), which is exactly the mechanism CVE-2018-5702 exploited against Transmission's `/transmission/rpc`.

Unlike stock go-ethereum, which defaults `Vhosts` to `"localhost"` and expects operators to widen it deliberately, sei-chain's server.go hardcodes the permissive value with no override, removing the operator's ability to close this attack surface via configuration.

Practically, an attacker-controlled webpage visited by anyone whose browser can reach an EVM RPC-enabled sei-chain node (e.g., a node operator's admin machine on the same LAN/VPC as an RPC/full node with port 8545 reachable, or the node itself if 0.0.0.0 is exposed) can, via DNS rebinding, issue arbitrary JSON-RPC calls (`eth_sendRawTransaction`, `debug_*`, `txpool_*`, etc. — the full API surface registered in `apis`, including the `debug` namespace) as if it were a legitimate local client, and read the responses due to the open CORS policy.

### Impact Explanation
If reached, this allows a remote attacker's web page to interact with a node's local EVM JSON-RPC surface as a trusted local client, including calling `eth_sendRawTransaction` (broadcasting attacker-supplied, already-signed transactions is not itself privileged, but leaks the victim's ability to spy on/interfere with node-local RPC state) and any `debug_*`/`txpool_*` methods exposed by `debugAPI`/`NewTxPoolAPI`, which can affect node behavior, disclose internal chain state, or be combined with other node-local trust assumptions (e.g., if any local tooling or account-management proxy sits behind this same endpoint expecting the Host/CORS checks to gate access). Because JWT auth (`config.JwtSecret`) is optional and off by default, there is no independent auth layer stopping this once Host/CORS checks are bypassed.

### Likelihood Explanation
Exploitation requires a victim operator's browser to visit an attacker page while their browser has network access to the node's RPC port (LAN, cloud internal network, or misconfigured public exposure of 8545) — this mirrors the original CVE's prerequisites closely. Given `Vhosts` is hardcoded to `*` (cannot be fixed by operators via config) and CORS defaults to `*` (must be explicitly hardened by every operator), likelihood of an exposed, exploitable instance is non-trivial across the fleet of RPC nodes unless operators have manually restricted `cors_origins` in `app.toml`.

### Recommendation
- Make `Vhosts` configurable and default it to a safe value (e.g., `localhost`, `127.0.0.1`, or the node's own configured hostname) instead of hardcoding `"*"` in `evmrpc/server.go`.
- Change the default `CORSOrigins` in `evmrpc/config/config.go` from `"*"` to an empty/deny-by-default value, requiring explicit opt-in for cross-origin access, consistent with the Tendermint RPC's own `cors-allowed-origins` default of `[]`.
- Document that JWT auth (`JwtSecret`) should be required for any RPC endpoint reachable from environments where browser-originated requests are possible.

### Proof of Concept
1. Operate a sei-chain EVM RPC node with default config (`cors_origins = "*"`, hardcoded `Vhosts = ["*"]`), reachable at `http://<node-ip>:8545` from a victim's browser (e.g., same LAN/VPC).
2. Attacker registers a domain and sets up DNS rebinding: initial resolution passes SOP checks, then DNS answer is rebound to `<node-ip>`.
3. Victim visits the attacker's page; the page's JavaScript issues a `fetch()` POST to `http://attacker-domain:8545` (now resolving to the node) with a JSON-RPC payload (e.g., `{"jsonrpc":"2.0","method":"txpool_content","params":[],"id":1}` or `debug_*` methods).
4. Because `virtualHostHandler` allows any `Host` header (`Vhosts` wildcard) and CORS allows any `Origin` (`CORSOrigins` wildcard), the request is processed and the JSON response is readable by the attacker's script, confirming cross-origin, cross-host access to node-local JSON-RPC — the same abuse pattern as CVE-2018-5702.

```go
// NewHTTPHandlerStack returns wrapped http-related handlers.
func NewHTTPHandlerStack(srv http.Handler, cors []string, vhosts []string, JwtSecret []byte) http.Handler {
	// Wrap the CORS-handler within a host-handler
	handler := newCorsHandler(srv, cors)
	handler = newVHostHandler(vhosts, handler)
	if len(JwtSecret) != 0 {
		handler = newJWTHandler(JwtSecret, handler)
	}
	return NewGzipHandler(handler)
}
```

```go
func newVHostHandler(vhosts []string, next http.Handler) http.Handler {
	vhostMap := make(map[string]struct{})
	for _, allowedHost := range vhosts {
		vhostMap[strings.ToLower(allowedHost)] = struct{}{}
	}
	return &virtualHostHandler{vhostMap, next}
}

// ServeHTTP serves JSON-RPC requests over HTTP, implements http.Handler
func (h *virtualHostHandler) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	// if r.Host is not set, we can continue serving since a browser would set the Host header
	if r.Host == "" {
		h.next.ServeHTTP(w, r)
		return
	}
	host, _, err := net.SplitHostPort(r.Host)
	if err != nil {
		// Either invalid (too many colons) or no port specified
		host = r.Host
	}
	if ipAddr := net.ParseIP(host); ipAddr != nil {
		// It's an IP address, we can serve that
		h.next.ServeHTTP(w, r)
		return
	}
	// Not an IP address, but a hostname. Need to validate
	if _, exist := h.vhosts["*"]; exist {
		h.next.ServeHTTP(w, r)
		return
	}
	if _, exist := h.vhosts[host]; exist {
		h.next.ServeHTTP(w, r)
		return
	}
	http.Error(w, "invalid host specified", http.StatusForbidden)
```
