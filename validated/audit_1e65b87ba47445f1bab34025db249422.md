### Title
Operator payout attribution is derived from an unsigned OP_RETURN, letting an unprivileged funder stamp a real operator's xonly pubkey and get that operator wrongly credited/reimbursed - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary
The `payout_tx`'s OP_RETURN output (which carries the `operator_xonly_pk` used later to decide who gets reimbursed) is **not covered** by the user's `SinglePlusAnyoneCanPay` signature, since that sighash flag only commits to the input and the output at the same index (output 0, the user's payment). Any party who funds/broadcasts a valid payout transaction for a given withdrawal can therefore write an arbitrary 32 bytes — including a real, unrelated operator's xonly pubkey — into the OP_RETURN, and `update_finalized_payouts`/`get_first_unhandled_payout_by_operator_xonly_pk` will trust that value as ground truth of "who funded this payout."

### Finding Description
The binding that should hold is:

`withdrawals.payout_payer_operator_xonly_pk (for idx i)` == `the xonly pubkey of the party whose BTC actually funded output[0] of the payout tx for idx i`

Trace:
1. `create_payout_txhandler` builds the payout transaction with output 0 = user payout (covered by the user's signature), output 1 = anchor, output 2 = OP_RETURN with `operator_xonly_pk`: [1](#0-0) 
2. The user's signature is required to be `TapSighashType::SinglePlusAnyoneCanPay`: [2](#0-1) . `SIGHASH_SINGLE` only commits to the output at the *same index* as the signed input (index 0); `ANYONECANPAY` leaves all other inputs unconstrained. This means outputs 1 and 2 (including the OP_RETURN operator pubkey) are **not signed by anyone** and can be freely rewritten by whoever assembles/broadcasts the final transaction, as long as output 0 still matches exactly what the user signed. `Operator::withdraw` itself computes/verifies the sighash only over input 0: [3](#0-2) 
3. Once such a transaction confirms, `update_finalized_payouts` parses the OP_RETURN and blindly stores whatever xonly pubkey is present as `payout_payer_operator_xonly_pk`, with only a well-formed-xonly-pubkey check — no signature or ownership check: [4](#0-3) , persisted via [5](#0-4) .
4. The victim operator's own automation (`PayoutCheckerTask`) queries `get_first_unhandled_payout_by_operator_xonly_pk`, which selects strictly by `payout_payer_operator_xonly_pk = $1 ... ORDER BY idx ASC LIMIT 1` — it has no way to distinguish a genuinely self-funded payout from an attacker-forged one: [6](#0-5) . It then calls `handle_finalized_payout` for whichever deposit_outpoint corresponds to that row and issues a real, validly-signed kickoff/Reimburse flow for it: [7](#0-6) [8](#0-7) .
5. `is_kickoff_malicious` only checks that the OP_RETURN-derived `operator_xonly_pk` equals the kickoff's own `operator_xonly_pk` — it cannot detect that the OP_RETURN value was forged by a third party rather than genuinely written by that operator, since nothing cryptographically binds it to the actual funder: [9](#0-8) .

Exploit flow: an attacker (needs only unprivileged access to a pending withdrawal's UTXO/outpoint and its `SinglePlusAnyoneCanPay` signature, obtainable from a Citrea `withdraw` call — their own or any user's, or by observing the operator's own pre-broadcast payout tx in the mempool) constructs a competing/replacement payout transaction that: pays output 0 exactly as signed (satisfying the signature), funds the rest of the transaction with the attacker's own BTC via the ANYONECANPAY-permitted extra inputs, and sets the OP_RETURN to a targeted, real operator's xonly pubkey instead of the attacker's own. Once mined, this forges the DB row's attribution to the targeted operator for a payout that operator never funded. That operator's own automation will then legitimately claim reimbursement for it.

### Impact Explanation
This directly matches the Critical category "an operator reimbursed for a payout it never funded." The targeted operator's kickoff/Reimburse machinery pays out bridge/collateral funds attributing credit for a withdrawal it did not finance, while the attacker (or whoever actually funded the forged payout) receives no protocol credit for the BTC they spent. This breaks the ATTRIBUTION invariant that "the operator credited and reimbursed for withdrawal i == the party who funded it," is repeatable across any deposit/withdrawal and any operator whose xonly pubkey is public (all registered operator keys are public), and can also be used to reorder/displace a targeted operator's real in-flight payout in the `ORDER BY idx ASC LIMIT 1` selection, delaying its own legitimate reimbursement.

### Likelihood Explanation
No privileged role, key, or collateral is required — only the ability to observe/obtain a pending withdrawal's signed input (public once a Citrea `withdraw()` call and/or the aggregator's `withdraw` gRPC call has produced it) and to broadcast a Bitcoin transaction with sufficient own funds/fees to cover the payout amount and win the race (or simply be first, if no legitimate payout has been broadcast yet for that withdrawal). The cost to the attacker is the BTC amount they front for the payout plus fees; the operator-key value being forged is fully public. This is a low-complexity, protocol-level design gap (unsigned OP_RETURN) rather than a bug requiring rare conditions.

### Recommendation
Cryptographically bind the payout's OP_RETURN (operator attribution) to the funding party, e.g. by covering it under a signature (use `SIGHASH_ALL`/`SIGHASH_NONE` variant covering all outputs for the operator-controlled portion, or have the operator co-sign a commitment to their own pubkey with a key only they hold), or by validating on the verifier/aggregator side that the operator broadcasting/claiming the payout is the one who actually supplied the additional funding inputs of that specific payout transaction (e.g. checking that the extra funding UTXOs trace back to that operator's registered wallet) before trusting `payout_payer_operator_xonly_pk` for reimbursement purposes.

### Proof of Concept
`cargo test` plan (core/src/database/verifier.rs, extending the existing test module):
1. Set up two withdrawal rows in `withdrawals` for the same `operator_xonly_pk` (a real registered operator's key), with distinct `idx` values, both having `payout_txid` set, `is_payout_handled = false`.
2. Row A (idx = 5): represents the operator's own legitimate payout (for a real, different deposit it fronted).
3. Row B (idx = 2): represents the attacker-forged payout — insert with the *same* `payout_payer_operator_xonly_pk` value even though, in the full end-to-end scenario, it was populated by `update_finalized_payouts` parsing an OP_RETURN from a transaction the attacker funded (not the operator).
4. Call `db.get_first_unhandled_payout_by_operator_xonly_pk(None, operator_xonly_pk)` and assert it returns idx = 2 (Row B — the forged one) rather than idx = 5, demonstrating the query cannot distinguish genuine vs. forged attribution and always yields whichever idx is lower regardless of actual funder.
5. (Extended, transaction-level PoC) In `core/src/test/deposit_and_withdraw_e2e.rs`-style setup, construct a `payout_tx` via `create_payout_txhandler` using a genuine user `SinglePlusAnyoneCanPay` signature/outpoint, but substitute a *different* operator's `operator_xonly_pk` in the OP_RETURN and fund the remaining inputs from a non-operator wallet; broadcast, mine, run `update_finalized_payouts`, and assert the DB row's `payout_payer_operator_xonly_pk` equals the substituted (uninvolved) operator's key, proving the forgery succeeds without invalidating the signature.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
