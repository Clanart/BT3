## Analysis Result: Valid Finding

### Title
GitHub-issue reference filter fails to anchor its match regex, allowing an autolinked malicious URL to be relabeled as a trusted `#N` issue reference while retaining the attacker's original `href` - (`app/src/lib/markdown-filters/issue-link-filter.ts`)

### Summary
`IssueLinkFilter.filter()` decides whether an autolinked anchor "looks like" a GitHub issue/PR/discussion link using `issueUrl()`, a `RegExp` built without `^`/`$` anchors. Because the regex is unanchored, `String.prototype.match`/`test` succeed if the GitHub-issue URL pattern appears *anywhere* inside the string, not just when the whole `href`/text *is* that URL. `filter()` then clones the original anchor (`node.cloneNode(true)`, preserving the original, unvalidated `href` attribute) and only overwrites `newNode.textContent` with a clean `#1234`-style label. The real navigation target used later by `setupLinkInterceptor` is `a.href`, which is untouched.

### Finding Description
- `createFilterTreeWalker` only requires `el.href === el.innerText` (i.e., this operates on markdown's auto-linked bare URLs) and that `isGitHubIssuePullDiscussionLink` returns true. [1](#0-0) 
- `isGitHubIssuePullDiscussionLink` ultimately relies on `issueUrl(this.repository).test(anchor.href)`, and `issueUrl()` builds a regex from `escapeRegExp(gitHubURL) + '/' + owner/repo + '/' + (issues|pull|discussions) + '/' + number` **with no `^` anchor at the start**. [2](#0-1) [3](#0-2) 
- `filter()` matches on `node.textContent` with the same unanchored regex, then clones the *original* node (keeping its original `href` attribute) and rewrites only `textContent`: [4](#0-3) 
- The resulting anchor is later clicked through `setupLinkInterceptor`, which reads `a.href` directly (the DOM-resolved absolute URL of whatever the original `href` attribute was) and forwards it, unmodified and unre-verified against the displayed text, to `onMarkdownLinkClicked`: [5](#0-4) 
- Because DOMPurify only restricts URL *protocols* (http/https/etc.), not hosts, a bare autolinked string such as `https://evil.example.com/x?u=https://github.com/owner/repo/issues/1234` survives sanitation with `href === innerText` intact. [6](#0-5) 
- Because `github.com/owner/repo/issues/1234` appears as a *substring* of that URL, the unanchored regex in both `isGitHubIssuePullDiscussionLink` and `filter()` matches it, so the node passes the filter and its display text is rewritten to `#1234`, while its `href` attribute (cloned unmodified) is still the full malicious `https://evil.example.com/...` URL.
- Consequently, `onMarkdownLinkClicked` (wired in multiple call sites to `dispatcher.openInBrowser(url)` or `shell.openExternal(url)`) receives the attacker-chosen destination even though the UI displays a trusted-looking `#1234` reference: [7](#0-6) [8](#0-7) [9](#0-8) 

The premise in the question is confirmed: `filter()` never re-validates or strips the original `href`; it only rewrites `textContent` via `cloneNode(true)`, so the diff of the anchor's `href` attribute before/after `applyFilters()` is empty even when the visible text changes from the raw malicious URL to `#N`.

### Impact Explanation
This is a link-spoofing / trust-indicator forgery bug rather than direct code execution: an attacker who controls PR/issue/PR-review/Copilot-conflict-summary markdown body text can make an untrusted, attacker-chosen `https://` URL visually indistinguishable from a legitimate internal GitHub issue reference (`#1234`), specifically undermining the one place where Desktop deliberately "cleans up" a raw pasted URL to look authoritative. When the user clicks the seemingly-safe `#1234` link, Desktop opens the attacker's URL in the system browser via `shell.openExternal`/`dispatcher.openInBrowser`, with no additional confirmation dialog showing the true destination. This can be used for phishing (e.g., a fake GitHub sign-in page) or to drive the user to attacker infrastructure while the app's own UI actively vouches for it as a "#N" reference.

### Likelihood Explanation
Moderate. Exploitation only requires the attacker to post a single crafted line of text in a PR/issue/review/Copilot resolution-summary body containing an https URL whose query string or path embeds a valid `github.com/<owner>/<repo>/issues|pull|discussions/<num>` substring — no special privileges beyond commenting/opening a PR/issue are needed, and markdown's bare-URL autolinking plus DOMPurify's protocol-only allow-list do not block it.

### Recommendation
Anchor the `issueUrl()` regex to the full string (`^...$`, or verify `match.index === 0 && match[0].length === text.length`) so it only accepts hrefs/text that are *entirely* a GitHub issue/PR/discussion URL, not URLs that merely contain one as a substring. Additionally, `filter()` should validate that `newNode`'s cloned `href` is identical to (or was derived from) the same string that produced the match, and/or explicitly re-set `href` from the parsed match rather than trusting the cloned attribute, ensuring the displayed `#N` text can never diverge from the actual navigation target.

### Proof of Concept
1. Add a comment/PR body containing the bare (unbracketed) URL:
   `https://evil-phish.example/login?next=https://github.com/owner/repo/issues/1234`
2. Marked's GFM autolinker turns this into `<a href="https://evil-phish.example/login?next=https://github.com/owner/repo/issues/1234">https://evil-phish.example/login?next=https://github.com/owner/repo/issues/1234</a>`; `href === innerText`, and DOMPurify keeps the `https:` href.
3. `isGitHubIssuePullDiscussionLink` and `filter()`'s `issueUrl(repository)` regex (unanchored) both match on the embedded `github.com/owner/repo/issues/1234` substring.
4. `filter()` clones the anchor (`href` unchanged) and sets `newNode.textContent = '#1234'`.
5. Diffing the anchor element's `outerHTML`/`href` attribute before and after `applyFilters()` shows `href` is unchanged (`https://evil-phish.example/...`) while the visible text changed from the full malicious URL to `#1234`.
6. Clicking the rendered `#1234` link triggers `setupLinkInterceptor`, which passes `a.href` (`https://evil-phish.example/...`) to `onMarkdownLinkClicked`, and the registered handler opens it in the external browser.

export function issueUrl(repository: GitHubRepository): RegExp {
  const gitHubURL = getHTMLURL(repository.endpoint)
  return new RegExp(
    escapeRegExp(gitHubURL) +

      '/' +
      /** A regexp that searches for the number and #anchor of an issue reference */

  )
}

  private isGitHubIssuePullDiscussionLink(anchor: HTMLAnchorElement) {
    const isIssuePullOrDiscussion = /(issue|pull|discussion)/.test(anchor.href)
    if (!isIssuePullOrDiscussion) {
      return false
    }

    const isPullRequestTab = /\d+\/(files|commits|conflicts|checks)/.test(
      anchor.href
    )
    if (isPullRequestTab) {
      return false
    }

    const isURlCustomFormat = /\.[a-z]+\z/.test(anchor.href)
    if (isURlCustomFormat) {
      return false
    }

    return issueUrl(this.repository).test(anchor.href)
  }

  public async filter(node: Node): Promise<ReadonlyArray<Node> | null> {
    const { textContent: text } = node
    if (!isElement(node, 'a') || text === null) {
      return null
    }

    const match = text.match(issueUrl(this.repository))
    if (match === null || match.groups === undefined) {
      return null
    }

    const { refNumber, anchor } = match.groups
    const newNode = node.cloneNode(true)
    newNode.textContent = this.getConsistentIssueReferenceText(
      refNumber,
      anchor
    )

    return [newNode]
  }

  /**
   * We still want to be able to navigate to links provided in the markdown.
   * However, we want to intercept them an verify they are valid links first.
   */
  private setupLinkInterceptor(doc: Document): void {
    doc.addEventListener('click', ev => {
      if (doc.defaultView && ev.target instanceof doc.defaultView.Element) {
        const a = ev.target.closest('a')
        if (a !== null) {
          ev.preventDefault()

          if (/^https?:/.test(a.protocol)) {
            this.props.onMarkdownLinkClicked?.(a.href)
          }
        }
      }
    })
  }
