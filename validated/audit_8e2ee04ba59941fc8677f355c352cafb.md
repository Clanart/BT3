## Title
kaiax ExecutionModule.PostInsertBlock() errors are silently swallowed on the block-proposer path, causing permanent module-state divergence — ([File: work/worker.go])

### Summary
Kaia's `kaiax.ExecutionModule` interface requires every registered module (gasless, auction, supply, valset, gov/headergov, randao, vrank) to implement `PostInsertBlock(block) error`, which persists per-block state derived from the just-inserted block [1](#0-0) . There are two independent call sites for this hook that handle the returned error inconsistently, exactly mirroring the Canto `processEvents`/`PostTxProcessing` bug class where one caller silently drops an error that should have aborted the block.

### Finding Description
When a block is imported via the normal chain-insertion path (`blockchain.go: insertChain`), a `PostInsertBlock` error is treated as fatal — the whole `insertChain` call aborts and returns the error, so the block effectively fails to be fully committed as canonical from the module's perspective: [2](#0-1) 

However, when the local node is the block proposer and finalizes its own sealed block (`work/worker.go: handleFinalizedBlock`), the exact same hook is invoked but its error is only logged — execution continues, the block is already written to the chain via `WriteBlockWithState`, and the chain head event is posted regardless: [3](#0-2) 

This is the same bug class as the External Report: one caller (`PostTxProcessing`/`insertChain`) propagates the error and reverts/aborts, while the other (`processEvents`/`handleFinalizedBlock`) only logs it and lets the surrounding flow proceed as if nothing happened. Modules affected by `PostInsertBlock` persist critical per-block bookkeeping directly from state/registry reads, e.g.:
- `GaslessModule.PostInsertBlock` refreshes the cached swap-router address and allowed-token whitelist used to validate every subsequent gasless swap/approve transaction [4](#0-3) .
- `SupplyModule.PostInsertBlock` advances the running supply checkpoint used for public supply accounting [5](#0-4) .
- `ValsetModule.PostInsertBlock` persists validator-council changes and permissionless transition results [6](#0-5) .
- `AuctionModule.PostInsertBlock` updates auctioneer/entry-point/gas-buffer parameters used to admit and settle every subsequent bid [7](#0-6) .

If any of these hooks returns an error while running on the proposer's own finalized-block path (e.g., a transient `StateAt`/registry-read failure at the exact block where the module reads on-chain configuration such as the GSR address, allowed tokens, or auctioneer address), the proposer silently keeps stale in-memory module state (`g.swapRouter`, `g.allowedTokens`, auction info, supply checkpoint, validator council) while every other honest node that receives and validates that same block through `insertChain` either successfully updates the identical state or aborts insertion entirely on the same error. This produces a durable module-state fork between the proposer and its peers that never self-heals, because `handleFinalizedBlock` never retries or reverts — analogous to how the Canto bug left `Register`/`Assign` events permanently unprocessed once one `evt` failed mid-loop.

### Impact Explanation
Once the proposer's local `GaslessModule`/`AuctionModule`/`ValsetModule`/`SupplyModule` state silently desyncs from the rest of the network:
- Gasless swap/approve transactions validated by that proposer's stale `allowedTokens`/`swapRouter` cache can be accepted or rejected inconsistently with other nodes, enabling gasless settlement manipulation or unfair transaction admission for that proposer's blocks.
- Auction bid admission/settlement parameters (auctioneer, entry point, gas buffer) diverging on the proposer vs. other CNs can let bids be validated against outdated auction rules, enabling settlement abuse for blocks it proposes.
- Validator-council/staking bookkeeping and public supply accounting can silently diverge, corrupting reward distribution and supply reporting that depends on this state being consistent across all nodes.

This matches the "state divergence between honest nodes" and "gasless/auction settlement theft" impact categories called out in scope.

### Likelihood Explanation
`PostInsertBlock` runs on every single block for every registered `ExecutionModule`, and its failure conditions are ordinary Go errors from state/registry reads (`Chain.StateAt`, `system.ReadActiveAddressFromRegistry`, etc.) rather than exotic conditions — any transient read failure, edge-case contract state, or unexpected value during registry decoding at exactly the block the proposer seals is enough to trigger it. No special privilege beyond normal block-proposal duty (already held by any active consensus node) is needed to hit this path, and normal user activity (gasless swaps, auction bids, staking) is what drives these modules' state changes each block.

### Recommendation
Make the error-handling behavior of `PostInsertBlock` consistent between `work/worker.go: handleFinalizedBlock` and `blockchain.go: insertChain`. If an execution module fails during `PostInsertBlock` for a self-finalized block, the finalize/commit sequence should be treated the same way as it is by `insertChain` — either abort committing that block as canonical, or explicitly and safely retry/re-derive the module state so a proposer never runs with module state that differs from what a normal `insertChain` validation would produce for the same block.

### Proof of Concept
1. Compare the two call sites: `blockchain.go` returns/aborts on `PostInsertBlock` error [2](#0-1) ; `work/worker.go` only logs it and proceeds [8](#0-7) .
2. Force `GaslessModule.PostInsertBlock` (or any other `ExecutionModule`) to return an error at the moment a node is finalizing its own sealed block (e.g., transient failure in `Chain.StateAt` or `system.ReadActiveAddressFromRegistry` inside `updateAddresses`) [4](#0-3) .
3. Observe that the proposer's block is nevertheless written and its chain head advances (`self.chain.WriteBlockWithState` already succeeded before the hook ran), while the module's cached whitelist/router/auction/council data is left stale relative to peers that process the identical block through `insertChain`.
4. Subsequent gasless/auction transactions validated against the proposer's stale module cache diverge from validation performed by peer nodes on the same chain state.

func (g *GaslessModule) PostInsertBlock(block *types.Block) error {
	currentState, err := g.Chain.StateAt(block.Header().Root)
	if err != nil {
		return err
	}
	g.setCurrentState(currentState)
	return g.updateAddresses(block.Header())
}

func (s *SupplyModule) PostInsertBlock(block *types.Block) error {
	s.mu.Lock()
	defer s.mu.Unlock()

	newNum := block.NumberU64()
	if s.lastAccNum+1 == newNum && s.lastAccReward != nil {
		newCheckpoint, err := s.accumulateRewards(s.lastAccNum, newNum, s.lastAccReward, true)
		if err != nil {
			return err
		}
		s.lastAccNum = newNum
		s.lastAccReward = newCheckpoint
	}
	return nil
}

func (v *ValsetModule) PostInsertBlock(block *types.Block) error {
	num := block.Header().Number.Uint64()
	if num == 0 {
		return nil
	}
	if !v.Chain.Config().IsPermissionlessForkEnabled(new(big.Int).SetUint64(num)) {
		return v.postInsertBlockPermissioned(block)
	}
	return v.postInsertBlockPermissionless(block)
}

func (v *ValsetModule) postInsertBlockPermissionless(block *types.Block) error {
	header := block.Header()
	nextNum := header.Number.Uint64() + 1
	parentStatedb, err := v.Chain.StateAt(header.Root)
	if err != nil {
		return err
	}
	_, err = v.getTransitionResult(nextNum, parentStatedb) // to cache the transition result
	return err
}

func (a *AuctionModule) PostInsertBlock(block *types.Block) error {
	if a.Downloader.Synchronising() || !a.ChainConfig.IsRandaoForkEnabled(block.Number()) {
		atomic.CompareAndSwapUint32(&a.bidPool.running, 1, 0)
		return nil
	}

	if !a.updateAuctionInfo(block.Number()) {
		logger.Debug("stop auction since auctioneer or auction entry point is not set")
		atomic.CompareAndSwapUint32(&a.bidPool.running, 1, 0)
		return nil
	}

	atomic.CompareAndSwapUint32(&a.bidPool.running, 0, 1)

	txHashMap := make(map[common.Hash]struct{})
	for _, tx := range block.Transactions() {
		txHashMap[tx.Hash()] = struct{}{}
	}
	a.bidPool.removeOldBids(block.Number().Uint64(), txHashMap)

	return nil
}
