### Title
Malicious DID ("club") NFT seller can honeypot offer buyers by stripping DID-owned NFT ownership before the sale settles - (File: chia/wallet/nft_wallet/nft_wallet.py, chia/wallet/nft_wallet/nft_puzzle_utils.py, chia/wallet/did_wallet/did_wallet.py)

### Summary
Chia's DID/NFT "ownership" model records which DID owns an NFT purely as curried metadata (`current_owner`) inside the NFT's ownership layer puzzle. This ownership assignment is not cryptographically bound to the DID coin itself, and can be cleared or reassigned unilaterally by whoever controls the NFT's `p2_puzzle` key, without any cooperation or lock from the DID. A seller can advertise a DID for sale (analogous to FootiumClub's "club" NFT) by showcasing the valuable NFTs it currently owns, accept payment via an offer, and front-run the buyer's accept-offer transaction by stripping/reassigning those NFTs' `owner_did` field before the sale confirms — leaving the buyer with only the empty DID singleton.

### Finding Description
The ownership layer puzzle is constructed with `current_owner` simply curried in as data, with no enforcement that the DID must cooperate to relinquish ownership: [1](#0-0) 

Changing/clearing an NFT's owner is done via the magic `-10` condition, which can be emitted by anyone who can spend the NFT's inner `p2_puzzle` (i.e., whoever controls that NFT's own key), independent of the DID: [2](#0-1) 

`NFTWallet.bulk_transfer_nft` and `NFTWallet.set_nft_did` both allow a holder to clear an NFT's DID ownership (`new_owner=b""`) with zero DID-side approval required: [3](#0-2) 

`get_did_approval_info` is only invoked when *assigning* ownership *to* a DID (i.e. the new owner must approve via announcement) — there is no symmetric requirement that the *current* DID owner approve losing that NFT: [4](#0-3) 

`generate_unsigned_spendbundle` shows the `-10` change-owner condition is entirely determined by whatever `new_owner` value the NFT-controller's transaction supplies, signed only under the NFT's own `p2_puzzle`: [5](#0-4) 

Meanwhile, selling the DID itself only moves the DID singleton coin (`DIDWallet.transfer_did`), which has no linkage whatsoever to any NFT coins that reference it as `owner_did`: [6](#0-5) 

And when a buyer accepts an offer for a DID via `TradeManager.respond_to_offer`, validity is only checked against whether the offer's own removals are still unspent — it has no way to know or lock the state of NFTs elsewhere that were merely referencing the DID as `owner_did`: [7](#0-6) 

### Impact Explanation
A buyer paying for a DID under the impression that valuable NFTs are permanently or provably tied to it can be defrauded: the seller retains full unilateral ability to strip or reassign those NFTs' `owner_did` at any time — including specifically front-running the buyer's accept-offer spend bundle visible in the mempool — since ownership assignment requires no DID-side lock or timelock to relinquish. This results in a buyer paying full price and receiving only a "hollowed out" DID coin while the seller keeps (or resells) the truly valuable NFTs, i.e., an offer-settlement value-theft against an unprivileged offer counterparty.

### Likelihood Explanation
Any wallet user creating/accepting an offer for a DID is exposed; the attack requires no special privileges — only that the malicious seller controls the p2_puzzle keys of the NFTs assigned to their own DID (which sellers of such a "collection" naturally do) and observes the buyer's accept-offer spend bundle in the mempool to front-run it, which is a standard capability of any transaction submitter/miner-observer.

### Recommendation
Require the DID's approval (via the same puzzle-announcement mechanism already used in `get_did_approval_info` when *assigning* ownership) whenever an NFT's ownership is being *cleared or removed* from that DID, not only when it is newly assigned. Alternatively, when constructing/accepting offers involving a DID, the wallet should present and optionally lock (via coin-announcement assertions in the offer) the specific set of NFT coins the buyer believes are associated with that DID, so acceptance can be made atomic with — or explicitly independent of — those NFT coins' states.

### Proof of Concept
1. Seller creates DID `D` and mints/assigns several valuable NFTs to it via `NFTWallet.generate_new_nft`/`set_nft_did`, so each NFT's ownership layer has `current_owner == D`.
2. Seller lists DID `D` for sale via `TradeManager.create_offer_for_ids`.
3. Buyer sees the DID and its associated NFTs and submits `TradeManager.respond_to_offer` to buy `D` for a high price; this spend bundle enters the mempool.
4. Seller observes the pending buy transaction and immediately broadcasts `NFTWallet.bulk_transfer_nft`/`set_nft_did` spends for each valuable NFT, changing `owner_did` to `""` or to a different DID they control — using only their own NFT p2_puzzle keys, no cooperation from DID `D` needed.
5. Once the seller's stripping transactions confirm ahead of (or in the same block as) the buyer's DID purchase, the buyer's DID `D` no longer has any of the previously showcased valuable NFTs, while the seller has been paid in full.

def get_new_owner_did(unft: UncurriedNFT, solution: Program) -> Literal[b""] | bytes32 | None:
    conditions = unft.p2_puzzle.run(unft.get_innermost_solution(solution))
    new_did_id: Literal[b""] | bytes32 | None = None
    for condition in conditions.as_iter():
        if condition.first().as_int() == -10:
            # this is the change owner magic condition
            atom = condition.at("rf").as_atom()
            if atom == b"":
                new_did_id = b""
            else:
                new_did_id = bytes32(atom)
    return new_did_id

    async def get_did_approval_info(
        self,
        nft_ids: list[bytes32],
        action_scope: WalletActionScope,
        did_id: bytes32 | None = None,
    ) -> bytes32:
        """Get DID spend with announcement created we need to transfer NFT with did with current inner hash of DID

        We also store `did_id` and then iterate to find the did wallet as we'd otherwise have to subscribe to
        any changes to DID wallet and storing wallet_id is not guaranteed to be consistent on wallet crash/reset.
        """
        if did_id is None:
            did_id = self.did_id
        did_inner_hash: bytes32
        for _, wallet in self.wallet_state_manager.wallets.items():
            self.log.debug("Checking wallet type %s", wallet.type())
            if wallet.type() == WalletType.DECENTRALIZED_ID:
                self.log.debug("Found a DID wallet, checking did: %r == %r", wallet.get_my_DID(), did_id)
                if bytes32.fromhex(wallet.get_my_DID()) == did_id:
                    self.log.debug("Creating announcement from DID for nft_ids: %s", nft_ids)
                    await wallet.create_message_spend(
                        action_scope, extra_conditions=(CreatePuzzleAnnouncement(id) for id in nft_ids)
                    )
                    did_inner_hash = wallet.did_info.current_inner.get_tree_hash()
                    break
        else:
            raise ValueError(f"Missing DID Wallet for did_id: {did_id}")
        return did_inner_hash

    async def check_offer_validity(self, offer: Offer, peer: WSChiaConnection) -> bool:
        all_removals: list[Coin] = offer.removals()
        all_removal_names: list[bytes32] = [c.name() for c in all_removals]
        non_ephemeral_removals: list[Coin] = list(
            filter(lambda c: c.parent_coin_info not in all_removal_names, all_removals)
        )
        coin_states = await self.wallet_state_manager.wallet_node.get_coin_state(
            [c.name() for c in non_ephemeral_removals], peer=peer
        )

        return len(coin_states) == len(non_ephemeral_removals) and all([cs.spent_height is None for cs in coin_states])
