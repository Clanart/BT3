### Title
Forged `ReceivedOutput` records can inflate received BTC and create unspendable inputs - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput::read` deserializes an arbitrary scalar offset, `TxOut`, and `OutPoint` without authenticating that the outpoint exists, is unspent, belongs to the claimed key, or contains the declared value. Untrusted bytes can therefore create a “spendable” output with an attacker-chosen balance and fake UTXO reference. Downstream transaction construction trusts that balance for input-value accounting, while signing only checks that the supplied `TxOut` script corresponds to the declared offset—not that the referenced on-chain UTXO matches it.

### Finding Description
`ReceivedOutput` is documented as “a spendable output,” but its parser only reads an offset, consensus-decodes a `TxOut`, and consensus-decodes an `OutPoint`; it performs no UTXO provenance or ownership verification. [1](#0-0) [2](#0-1) 

The decoded balance is exposed directly through `ReceivedOutput::value`, and `SignableTransaction::new` sums all supplied claimed values as `input_sat`. [3](#0-2) [4](#0-3) 

Payment feasibility and change are calculated from that unauthenticated total. [5](#0-4) [6](#0-5) 

When the transaction machine is constructed, `SignableTransaction::multisig` verifies only that `p2tr_script_buf(key + offset)` equals the deserialized `prevouts[i].script_pubkey`; it does not compare that `TxOut` with the UTXO actually referenced by `tx.input[i].previous_output`. [7](#0-6) 

### Impact Explanation
An unprivileged party who can submit serialized `ReceivedOutput` bytes can report a vault output of arbitrary value at a nonexistent, already-spent, or unrelated outpoint. A scanner/accounting consumer sees `value()` as available BTC, and transaction preparation treats the forged amount as spendable collateral.

The resulting transaction is not redeemable: either the fake outpoint has no UTXO, or the real UTXO’s amount/script differs from the forged `TxOut`, making the Taproot prevout commitment invalid. If the forged outpoint references a real output not controlled by Serai, the constructed input is likewise unspendable. This is an accounting/provenance violation analogous to an exchange-value mismatch: attacker-supplied transaction data causes a nonexistent asset balance to be accepted as real.

### Likelihood Explanation
Likelihood depends on whether an integration accepts serialized `ReceivedOutput` objects across an untrusted boundary. Within this codebase, the parser is a public API and accepts exactly the raw fields needed for forgery; no proof, block inclusion check, UTXO lookup, or callback validation is required before `value()`, `balance()` consumers, or `SignableTransaction::new` use it. A crafted byte string is sufficient.

### Recommendation
Do not let `ReceivedOutput::read` represent validated chain state. Either:

- Make it explicitly an untrusted wire representation and require confirmation against a trusted UTXO source before exposing it as spendable.
- Add a constructor such as `ReceivedOutput::verified(scanner, tx, vout)` that recomputes the offset/script association and derives the outpoint and `TxOut` from the confirmed transaction.
- Before creating a `SignableTransaction`, fetch `input.previous_output.txid`, verify `vout` exists and is unspent, and require byte-equality between the chain `TxOut` and the serialized `TxOut`.
- Reject `ReceivedOutput` values that did not originate from `Scanner::scan_transaction` or an equivalent authenticated source.

### Proof of Concept
A forged record can be produced entirely from public data:

```rust
// Conceptual PoC against networks/bitcoin/src/wallet/mod.rs and send.rs.
use bitcoin::{
  consensus::encode::serialize,
  transaction::{Txid, TxOut},
  Amount, OutPoint, ScriptBuf,
};
use frost::curve::Secp256k1;
use k256::{ProjectivePoint, Scalar};
use bitcoin_serai::wallet::{p2tr_script_buf, ReceivedOutput, SignableTransaction};

fn forged_received_output(multisig_key: ProjectivePoint) -> ReceivedOutput {
  let mut bytes = Vec::new();

  // Offset zero maps the claimed script to the base multisig key.
  bytes.extend(Scalar::ZERO.to_bytes());

  // Claim the referenced UTXO paid 1 BTC to the multisig.
  let claimed_txout = TxOut {
    value: Amount::from_sat(100_000_000),
    script_pubkey: p2tr_script_buf(multisig_key).unwrap(),
  };
  bytes.extend(serialize(&claimed_txout));

  // Reference a nonexistent or unrelated UTXO.
  let fake_outpoint = OutPoint {
    txid: Txid::from_byte_array([0x41; 32]),
    vout: 0,
  };
  bytes.extend(serialize(&fake_outpoint));

  let output = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();
  assert_eq!(output.value(), 100_000_000);
  output
}
```

`SignableTransaction::new(vec![forged], payments, change, None, fee)` uses the forged `100_000_000` satoshi value in `input_sat`, even though no corresponding spendable UTXO has been proven to exist. `multisig()` also succeeds if `claimed_txout.script_pubkey` matches `key + offset`; ownership of `fake_outpoint` is never checked during that check.

    let output;
