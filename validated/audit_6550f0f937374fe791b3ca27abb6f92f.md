### Title
Sandwich attack on GaslessSwapTx causes irrecoverable loss of proposer-lent KAIA due to non-atomic LendTx/SwapTx execution - (File: `kaiax/gasless/impl/builder.go`, `kaiax/gasless/impl/getter.go`, `kaiax/gasless/impl/tx_pool.go`)

### Summary
The gasless module (KIP-247) lends KAIA to a sender via an unconditional `LendTx` before the sender's `GaslessSwapTx` executes and repays the loan through an on-chain AMM swap. The swap's slippage protection (`minAmountOut`) is only enforced inside the `swapForGas` contract call at execution time against the live pool reserves, while the mempool admission check uses the same manipulable spot price. Because `LendTx` and `SwapTx` are distinct transactions rather than an atomic, all-or-nothing execution unit, any sandwich attack that pushes the DEX pool price past the user's `minAmountOut` tolerance causes `SwapTx` to revert (no repayment) while the preceding `LendTx` has already unconditionally transferred KAIA to the sender — an unrecoverable value loss for the block proposer.

### Finding Description
`ExtractTxBundles` builds a bundle of `[LendTxGenerator, GaslessApproveTx?, GaslessSwapTx]` for every detected gasless pattern: [1](#0-0) 

`GetLendTxGenerator` creates a transaction that unconditionally sends `lendAmount(approveTxOrNil, swapTx)` KAIA from the node's own key to the sender, independent of whether the following `SwapTx` succeeds: [2](#0-1) [3](#0-2) 

The only pre-execution safety check on the swap is `checkBalanceForSwap`, which validates `amountIn >= gsr.getAmountIn(minAmountOut)` against the router's *current* (spot) exchange rate — a value that is trivially manipulable within the same or an adjacent block via ordinary swaps against the underlying DEX pool: [4](#0-3) 

This check happens once at tx-pool admission time. It provides no guarantee that the AMM reserves will be unchanged by the time the block is actually built and `SwapTx` executes. The router's actual slippage protection (`minAmountOut`) is enforced only inside the `swapForGas` execution itself, which can revert if the pool price has moved.

Because `LendTx` is a separate transaction (not atomically bound with `SwapTx` such that a `SwapTx` revert rolls back `LendTx`), a revert of `SwapTx` leaves the already-executed `LendTx` value transfer intact — the sender keeps the lent KAIA with no possibility of the repayment (which only happens as a side-effect inside a successful `swapForGas` call) ever occurring.

This mirrors the root cause of the referenced report class: safety of a protocol-critical value-transfer flow is derived from a manipulable, unauthenticated, spot on-chain price feed (the AMM reserves here, playing the role of the "oracle" in the referenced Aave finding) rather than a mechanism that guarantees atomic settlement or repayment.

### Impact Explanation
A successful sandwich against the DEX pool backing `GaslessSwapRouter` causes the corresponding `swapForGas` transaction to revert after the proposer/node has already unconditionally lent KAIA to the sender via `LendTx`. Since repayment logic lives entirely inside the (now-reverted) swap call, the lent KAIA is permanently lost to the block proposer with no recovery path — this is a direct, unauthorized value transfer that can be reliably triggered without any protocol privilege, satisfying the "gasless... settlement theft" and "unauthorized value movement" impact criteria.

### Likelihood Explanation
No special privilege is required: any public RPC caller can submit a `GaslessApproveTx`/`GaslessSwapTx` pair with `minAmountOut` set tightly against the current pool price (to pass admission), while a second, entirely unprivileged party (or the same attacker, or a colluding auction bidder given the co-located auction module) trades against the same DEX pool in an adjacent block/transaction slot to move the price beyond the `minAmountOut` tolerance before the bundle is sealed. Because the tx-pool check and bundle construction do not re-simulate the whole atomic outcome immediately before inclusion, and `LendTx` execution is unconditional, this is a repeatable griefing/theft vector rather than a low-probability edge case.

### Recommendation
- Make `LendTx` conditional on the success of the subsequent `SwapTx`/`ApproveTx` (e.g., by requiring atomic all-or-nothing execution semantics for the whole gasless bundle, or by using a single contract call that performs the lend, swap, and repay steps atomically instead of independent EOA-level transactions).
- Alternatively, simulate the full bundle (including `LendTx` + `ApproveTx` + `SwapTx`) against the exact state the bundle will be executed on immediately before block sealing, and drop the bundle (not just the swap) if `SwapTx` would revert.
- Consider widening the admission-time slippage check margin or re-validating swap executability right before inclusion in `ExtractTxBundles`, rather than relying solely on the tx-pool-time AMM spot price snapshot.

### Proof of Concept
1. Attacker (or any unrelated actor) observes a pending `GaslessApproveTx` + `GaslessSwapTx` pair in the mempool for `token -> WKAIA` via `GaslessSwapRouter.swapForGas`, with `minAmountOut` computed against the current pool price with a small margin (as in [5](#0-4) ).
2. Attacker submits a normal swap transaction against the same underlying DEX pool that shifts reserves enough to make the victim's `minAmountOut` unreachable.
3. The block proposer's `ExtractTxBundles` still bundles `[LendTxGenerator, GaslessApproveTx, GaslessSwapTx]` as before ( [1](#0-0) ), because bundle construction does not re-check the swap's viability against the attacker's pending price-moving transaction.
4. In block execution order: `LendTx` executes first and unconditionally credits the sender with `lendAmount` KAIA ( [6](#0-5) ). The attacker's price-moving tx executes before `SwapTx` (or in the block immediately prior). `SwapTx` then reverts inside the router due to the on-chain `minAmountOut` check failing against the shifted pool price.
5. Result: the sender retains the lent KAIA balance with a failed/reverted `SwapTx` receipt, and the repayment to the block proposer never occurs — a permanent, unauthorized loss of proposer funds.

// MakeLendTx creates a transaction with following properties:
// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)
// L2. LendTx.from = proposer
// L3. LendTx.to = SwapTx.from
// L4. LendTx.value = LendAmount(approveTxOrNil, swapTx)
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}

	if approveTxOrNil != nil {

	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}
