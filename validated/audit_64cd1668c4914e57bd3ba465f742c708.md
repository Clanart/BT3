### Title
Untrusted `ReceivedOutput` bytes can permanently block spending of all inputs in a withdrawal transaction - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The external report describes a safety mechanism (`whenNotPaused`, meant to gate deposits) that also blocks the withdrawal path. The Serai analog lives in the Bitcoin wallet: `ReceivedOutput::read` accepts an attacker-supplied `offset`/`TxOut`/`OutPoint` triple with no consistency check, `SignableTransaction::new` consumes those offsets blindly, and `SignableTransaction::multisig` then aborts the *entire* transaction (`None?`) if any single input's offset does not reproduce its `script_pubkey`. A single malformed `ReceivedOutput` therefore gates — and permanently blocks — the withdrawal/signing path for every other valid input in the transaction, exactly mirroring "the pause meant for deposits also freezes withdrawals".

### Finding Description
`ReceivedOutput::read` deserializes `offset`, `output` (TxOut) and `outpoint` from a byte stream with no validation that the offset actually derives the output's `script_pubkey` under the scanner's key: [1](#0-0) 

`SignableTransaction::new` copies `input.offset` straight into the transaction's `offsets` vector without any check: [2](#0-1) 

`SignableTransaction::multisig` then iterates inputs, re-keys the threshold keys by each offset, and returns `None` for the whole transaction the first time `p2tr_script_buf(offset.group_key()) != prevouts[i].script_pubkey`: [3](#0-2) 

There is no path that skips or isolates the bad input — one inconsistent `ReceivedOutput` vetoes spending of all other inputs in the same `SignableTransaction`. This is the structural equivalent of the `LpToken` report: a consistency guard that exists to protect correctness of the deposit/scan path (`scan_transaction` matching `script_pubkey` at mod.rs:205) is enforced on the withdrawal path as an all-or-nothing abort.

### Impact Explanation
An unprivileged party who can feed bytes to `ReceivedOutput::read` (per scope: untrusted bytes to `ReceivedOutput::read` are an accepted input channel) supplies an output whose `offset` is nonzero/mismatched (e.g., `offset = 1` paired with the base-key P2TR script). Any `SignableTransaction` incorporating it cannot produce a `TransactionMachine` (`multisig` returns `None`), so the withdrawal transaction — and every legitimate input bundled with it — is unspendable, a funds-received-but-not-spendable / withdrawal DoS. Note `multisig` returning `None` is indistinguishable from "wrong keys" to the caller, so the poisoned output may repeatedly poison reconstruction attempts if it is persisted alongside genuine scanned outputs.

### Likelihood Explanation
Medium. Triggering requires an attacker-controlled or corrupted `ReceivedOutput` byte string to reach a consumer that builds transactions. Legitimately, `scan_transaction` only emits consistent (offset, script) pairs, so this requires the untrusted-deserialization channel — which is precisely why `ReceivedOutput::read` is exposed as a public `read` API. Once a poisoned record is mixed into an input set, the DoS is deterministic and total for that transaction; there is no error surfaced identifying which input failed (`multisig` returns `Option`, not an error).

### Recommendation
Validate the binding between `offset` and `output.script_pubkey` at deserialization or transaction construction time. Either:
- In `ReceivedOutput`, store/derive the script from `(key, offset)` so inconsistency is impossible, or
- In `SignableTransaction::new`/`multisig`, verify `p2tr_script_buf(key + G*offset) == output.script_pubkey` per input and return a per-input error (e.g., `TransactionError::InvalidInput(usize)`) instead of silently returning `None` for the whole transaction, so one bad input cannot veto the rest.

### Proof of Concept
```rust
// Conceptual: deserialize a ReceivedOutput whose offset does not match its script_pubkey.
// `read` performs no consistency check between `offset` and `output.script_pubkey`.
let mut bytes = Vec::new();
bytes.extend(Scalar::ONE.to_bytes());              // wrong offset: base key needs Scalar::ZERO
bytes.extend(serialize(&TxOut {                    // script paying to key + G*0 (base P2TR)
    value: Amount::from_sat(100_000),
    script_pubkey: p2tr_script_buf(base_key).unwrap(),
}));
bytes.extend(serialize(&OutPoint::default()));
let poisoned = ReceivedOutput::read(&mut bytes.as_slice()).unwrap(); // succeeds

// Build a transaction mixing the poisoned input with a legitimate scanned input.
let tx = SignableTransaction::new(
    vec![honest_output, poisoned],
    &[(payment_script, 50_000)],
    None, None, FEE,
).unwrap(); // construction succeeds — no check on offset/script consistency

// multisig returns None because input 1 fails p2tr_script_buf(key + G*1) != script_pubkey.
// The honest input's funds are unspendable through this transaction.
assert!(tx.multisig(&keys).is_none());
```

  pub fn multisig(self, keys: &ThresholdKeys<Secp256k1>) -> Option<TransactionMachine> {
    let mut sigs = vec![];
    for i in 0 .. self.tx.input.len() {
      let offset = keys.clone().offset(self.offsets[i]);
      if p2tr_script_buf(offset.group_key())? != self.prevouts[i].script_pubkey {
        None?;
      }

      sigs.push(AlgorithmMachine::new(Schnorr::new(), keys.clone().offset(self.offsets[i])));
    }

    Some(TransactionMachine { tx: self, sigs })
  }
