### Title
Permissionless third-party bandwidth purchases can evict a victim app's paid, unexpired subscriptions before they are consumed - ([File: modules/pallets/bandwidth/src/lib.rs])

### Summary
`pallet-bandwidth`'s `Allowance` ledger is a FIFO list capped at `MAX_SUBSCRIPTIONS = 1024` per `(app_chain, app)` key [1](#0-0) . `push_subscription` silently evicts the oldest, still-unexpired entry once the cap is hit, destroying its `remaining_bytes` with no refund path — only an audit event is emitted [2](#0-1) . Crucially, `BandwidthManager.purchase()` on the EVM side is fully permissionless as to *who* it credits: any caller supplies an arbitrary `(app, chain)` pair that has no relationship to `msg.sender`, and the pallet keys the credit purely off the message body's `app_chain`/`app`, not off the payer [3](#0-2) [4](#0-3) . This is the same "unique-key multiplication against a bounded, shared resource forces eviction of legitimate state" primitive as the external report's decoder-cache exhaustion vector, but here the evicted resource is prepaid customer funds rather than memory.

### Finding Description
Any unprivileged external account can call `purchase(app, tier, months, chain)` for an `app`/`chain` pair it does not own or control [5](#0-4) . The dispatched `BandwidthPurchaseMsg` is accepted by `on_accept` as long as `request.from` matches the registered manager for the *source* chain — there is no check that the payer is related to the target `app` [6](#0-5) . Each accepted purchase calls `push_subscription`, which, once the victim's `(app_chain, app)` FIFO list is at the 1024-entry cap, pops index `0` — the oldest subscription — regardless of who paid for it or how much of it is unconsumed, and emits `SubscriptionEvicted` with the lost bytes as the only trace [7](#0-6) .

The gate (`BandwidthGate::try_consume`) never mutates on insufficient balance [8](#0-7) , so the only path back to "no allowance" for an app that has already paid is precisely this eviction path being exploited by an unrelated third party.

Nothing in `on_accept`, `push_subscription`, or `purchase()` binds the pushed subscription's beneficiary to the payer, and nothing rate-limits or economically disincentivizes filling a victim's queue beyond the raw tier price the attacker must pay per push.

### Impact Explanation
This directly causes loss of funds for the victim app: bandwidth is bought once (`BandwidthCredited`) and irrevocably destroyed later by an unrelated party's cheap purchases, with the app's remaining paid-for byte allowance permanently gone and no compensation mechanism (`force_credit` is `AdminOrigin`-only) [9](#0-8) . The victim discovers this only after their ISMP dispatches start failing with `GateError::NoAllowance`/`Insufficient` despite having paid, and the loss is not attributable to any protocol fault of their own — it is caused entirely by a permissionless purchase targeting their `(chain, app)` key.

### Likelihood Explanation
The attack is unprivileged (needs only enough of the fee token to place purchases; no relayer, prover, or admin role required) and requires no malformed proof — it uses the intended purchase path exactly as designed. Likelihood is tempered by cost: the attacker must pay the configured tier price per push and must reach the 1024-entry cap on the specific victim's queue before eviction begins, which is expensive against a well-funded, actively-topped-up victim (the docs themselves note this "only happens under pathological repeat-buy behavior"). However, for any app that keeps a modest number of live subscriptions (the realistic common case, since 1024 is described as "years of headroom" under *normal* one-purchase-per-cycle usage), the number of attacker pushes needed to reach the cap and start evicting is far smaller, and the attacker never needs the total attack cost to be less than the value destroyed — it is pure griefing against a targetable, permissionless entrypoint with no per-victim protection.

### Recommendation
- Require the target `app` (or an app-registered delegate) to authorize third-party top-ups, or at minimum let an app opt out of unsolicited third-party purchases so only self- or explicitly-sponsored credits can push onto its list.
- Consider keying eviction priority by remaining value or `purchased_at` age combined with a minimum "protected" window, or reject a push if it would evict a subscription with non-trivial `remaining_bytes` still unconsumed rather than silently evicting the head regardless of value.
- Alternatively, raise the cap dynamically or move to a byte-accumulator model rather than a fixed FIFO array cap, removing the eviction primitive entirely.

### Proof of Concept
1. Governance registers `BandwidthManager` for `EVM-8453` and configures `TierOne`.
2. Victim app `A` on `EVM-8453` buys, say, 5 subscriptions over time via legitimate `purchase()` calls, none expired, sitting in `Allowance[EVM-8453][A]`.
3. Attacker, with no relation to `A`, repeatedly calls `BandwidthManager.purchase(app = A, tier = TierOne, months = 1, chain = "EVM-8453")` from any account, paying the tier price each time [3](#0-2) .
4. Each delivered purchase message is accepted by `on_accept` (source/manager checks only look at the dispatching manager contract, not the payer's relation to `A`) and appended via `push_subscription` [6](#0-5) .
5. Once `Allowance[EVM-8453][A]` reaches 1024 entries, every further attacker purchase evicts the oldest unexpired subscription — including `A`'s legitimately paid-for, unconsumed subscriptions bought in step 2 — emitting `SubscriptionEvicted { lost_bytes }` with no refund [7](#0-6) .
6. `A`'s prepaid bandwidth is irreversibly destroyed by a third party it never authorized, with no on-chain remedy short of a manual admin `force_credit`.

		/// Append a fresh subscription with a fixed expiry. If the list
		/// is already at `MaxSubscriptions`, evict the oldest entry and
		/// emit [`Event::SubscriptionEvicted`] so the lost bytes are
		/// auditable. Returns the new subscription's `expires_at`.
		fn push_subscription(
			app_chain: &StateMachine,
			app: &AppKey,
			tier: TierIndex,
			bytes: BandwidthBytes,
			duration_secs: u64,
		) -> u64 {
			let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();
			let expires_at = now.saturating_add(duration_secs);
			let new_sub =
				Subscription { tier, remaining_bytes: bytes, expires_at, purchased_at: now };

			let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
				let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
					Some(list.remove(0))
				} else {
					None
				};
				// Capacity is now guaranteed; try_push can't fail.
				let _ = list.try_push(new_sub);
				evicted
			});

			if let Some(old) = evicted {
				Self::deposit_event(Event::SubscriptionEvicted {
					app_chain: *app_chain,
					app: app.clone(),
					tier: old.tier,
					lost_bytes: old.remaining_bytes,
				});
			}

			expires_at
		}
