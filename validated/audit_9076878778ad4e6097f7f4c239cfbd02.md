## Analysis: Analog Found

### Title
Unbounded Recursive RLP Decoding of Nested `AccountKeyRoleBased` Causes Stack-Consumption DoS - (File: `blockchain/types/accountkey/account_key_role_based.go`)

### Summary
CVE-2017-5950 describes a stack-consumption DoS in `yaml-cpp`'s recursive node parser (`SingleDocParser::HandleNode`), where a crafted, deeply-nested document drives unbounded recursive calls until the process stack is exhausted. The kaia codebase has an analogous unbounded-recursion pattern in the `AccountKey` RLP decoding path: `AccountKeyRoleBased.DecodeRLP` can recursively decode another `AccountKeyRoleBased` (or any other key type) inside itself, with no depth limit enforced during decoding.

### Finding Description
`AccountKeyRoleBased.DecodeRLP` decodes a list of raw byte blobs and, for each blob, invokes `rlp.DecodeBytes(b, &serializer)` on a fresh `AccountKeySerializer`: [1](#0-0) 

`AccountKeySerializer.DecodeRLP` reads a `keyType` tag, calls `NewAccountKey(serializer.keyType)` to allocate a concrete `AccountKey` implementation, and then decodes into it via `s.Decode(serializer.key)`: [2](#0-1) 

If the encoded `keyType` is `AccountKeyTypeRoleBased` again, `s.Decode` dispatches back into `AccountKeyRoleBased.DecodeRLP`, which in turn calls `rlp.DecodeBytes` on another nested blob — recursing indefinitely as long as the attacker keeps nesting `RoleBased` (or other composite) keys inside the byte payload. The only guard against nested composite keys — `IsCompositeType()` / `CheckInstallable` / `CheckUpdatable` — is applied *after* the full RLP decode completes: [3](#0-2) 

Because each nesting level only costs a small constant number of RLP bytes (list/length prefix + type tag), an attacker can pack thousands of nesting levels into a single, size-limited transaction payload, driving the decoder's native Go call stack to overflow before validation logic ever runs.

### Impact Explanation
A crafted `TxTypeAccountUpdate` (or any fee-delegated variant) transaction containing a deeply nested `AccountKeyRoleBased` structure can crash any kaia node that RLP-decodes it — including nodes performing basic pool admission or block execution — via stack exhaustion (Go runtime fatal error, unrecoverable by `recover()`), a denial-of-service condition consistent with the CVSS profile of the reference CVE (`AV:L/AC:L/PR:N/UI:R/S:U/C:N/I:N/A:H`, i.e., availability impact only).

### Likelihood Explanation
The nested key blob is fully attacker-controlled and reachable from any unprivileged sender submitting a transaction through public RPC (`eth_sendRawTransaction`) or the tx pool, requiring only that the crafted transaction reach `DecodeRLP`; no special privilege or validator collusion is required.

### Recommendation
Enforce a maximum recursion/nesting depth for `AccountKey` decoding (e.g., reject `AccountKeyTypeRoleBased`/composite types found while already decoding within a `RoleBased` context) directly inside `AccountKeySerializer.DecodeRLP` / `AccountKeyRoleBased.DecodeRLP`, before recursing, rather than deferring the composite-type check to `CheckInstallable`/`CheckUpdatable` which run only after decoding succeeds.

### Proof of Concept
Construct a byte blob `B0` encoding a leaf `AccountKeyNil`/`AccountKeyPublic`. Wrap it as `B1 = RLP([keyType=RoleBased, RLP([B0])])`, then `B2 = RLP([keyType=RoleBased, RLP([B1])])`, and repeat this wrapping thousands of times to produce `Bn`. Submit a `TxTypeAccountUpdate` transaction whose `key` field is `Bn` via `eth_sendRawTransaction`. When the node calls `tx.DecodeRLP` → ... → `AccountKeyRoleBased.DecodeRLP`, the recursive chain of `rlp.DecodeBytes` → `AccountKeySerializer.DecodeRLP` → `NewAccountKey` → `s.Decode` → `AccountKeyRoleBased.DecodeRLP` repeats `n` times, exhausting the goroutine stack and crashing the node before `CheckInstallable` can reject the nested composite type.

func (a *AccountKeyRoleBased) DecodeRLP(s *rlp.Stream) error {
	enc := [][]byte{}
	if err := s.Decode(&enc); err != nil {
		return err
	}

	keys := make([]AccountKey, len(enc))
	for i, b := range enc {
		serializer := NewAccountKeySerializer()
		if err := rlp.DecodeBytes(b, &serializer); err != nil {
			return err
		}
		keys[i] = serializer.key
	}

	*a = (AccountKeyRoleBased)(keys)

	return nil
}

func (a *AccountKeyRoleBased) CheckInstallable(currentBlockNumber uint64) error {
	// A zero-role key is not allowed.
	if len(*a) == 0 {
		return kerrors.ErrZeroLength
	}
	// Do not allow undefined roles.
	if len(*a) > (int)(RoleLast) {
		return kerrors.ErrLengthTooLong
	}
	for i := 0; i < len(*a); i++ {
		// A composite key is not allowed.
		if (*a)[i].IsCompositeType() {
			return kerrors.ErrNestedCompositeType
		}
		// If any key in the role cannot be initialized, return an error.
		if err := (*a)[i].CheckInstallable(currentBlockNumber); err != nil {
			return err
		}
	}
	return nil
}

func (serializer *AccountKeySerializer) DecodeRLP(s *rlp.Stream) error {
	if err := s.Decode(&serializer.keyType); err != nil {
		return err
	}

	var err error
	serializer.key, err = NewAccountKey(serializer.keyType)
	if err != nil {
		return err
	}

	return s.Decode(serializer.key)
}
