### Title
Public `addNativePointer`/`addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` calls silently mutate the immutable `name`/`symbol` of an already-deployed ERC20/ERC721/ERC1155 pointer contract - (File: precompiles/pointer/pointer.go, x/evm/keeper/pointer_upgrade.go)

### Summary
Any unprivileged EVM caller can invoke the `pointer` precompile's `addNativePointer` (or `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer`) method for a token/CW20/CW721/CW1155 address that already has a pointer contract deployed. Because the keeper treats this as an "upsert," instead of reverting when a pointer already exists, it redeploys the pointer's init code at the *same* contract address and overwrites its bytecode/state with whatever `name`/`symbol` currently sits in the source-of-truth metadata (bank denom metadata for native tokens, or CW20/CW721/CW1155 `token_info`/`contract_info` query results). This is directly analogous to the reported `ERC20Ubiquity.setSymbol` issue: values that ERC20/ERC721 consumers assume are immutable per contract address can change during the contract's lifetime, and here the trigger is a *public, permissionless* transaction rather than an admin-only call.

### Finding Description
`AddNative` in [1](#0-0)  reads the current bank denom metadata for `token` and calls `p.evmKeeper.UpsertERCNativePointer(ctx, evm, token, utils.ERCMetadata{Name: name, Symbol: symbol, Decimals: decimals})`. The analogous CW20/CW721/CW1155 handlers do the same using live CosmWasm query results [2](#0-1) [3](#0-2) .

`UpsertERCPointer` in the keeper checks whether a pointer already exists for the pointee; if it does, instead of failing it re-packs the constructor arguments (name/symbol/decimals) into new init/deployment code and overwrites the *existing* contract's bytecode in place via `evm.GetDeploymentCode` + `k.SetCode(...)`, without creating a new address: [4](#0-3) 

Unlike the older legacy pointer implementations (e.g. `precompiles/pointer/legacy/v552/pointer.go` and `v555/pointer.go`), which explicitly reject re-registration once a pointer version `>= 1` exists (`"pointer at %s with version %d exists when trying to set pointer for version %d"`) [5](#0-4) , the current `UpsertERCPointer` path removed that guard entirely and always allows overwriting.

The upstream metadata itself is admin-controlled and can legitimately change post-creation:
- Native token metadata (`Name`/`Symbol`) can be changed at any time by the tokenfactory denom admin via `MsgSetDenomMetadata`, handled in `SetDenomMetadata` [6](#0-5) .
- CW20/CW721/CW1155 contracts can likewise expose different `name`/`symbol` over their lifetime if their own contract logic allows migration or state mutation of `token_info`/`contract_info` (queried live in `AddCW20`/`AddCW721`/`AddCW1155`).

Because `AddNative`/`AddCW20`/`AddCW721`/`AddCW1155` are all reachable by any externally-owned account calling the precompile at `0x000000000000000000000000000000000000100b` with no access control (only `readOnly`/delegatecall checks are enforced) [7](#0-6) , any user can trigger a resync/overwrite of the pointer contract's stored `name`/`symbol` at will, any number of times, as soon as the underlying metadata diverges from what was baked in originally.

### Impact Explanation
ERC20/ERC721 tokens are conventionally assumed by other integrated systems (DEXs, wallets, other smart contracts, off-chain indexers/price oracles matching by symbol, integrators caching `symbol()`/`name()` at pointer-creation time) to have immutable identity metadata for a given contract address. Silently rewriting the bytecode/state of an already-integrated pointer contract to serve a different `name`/`symbol` (with the same address) can:
- Break systems that use `symbol`/`name` as part of listing, pricing feeds, or trust decisions, potentially routing funds/logic against the wrong token identity.
- Enable a form of "asset re-branding"/spoofing attack on an already-integrated pointer: an attacker who controls or colludes with a tokenfactory denom admin (or a CW20/CW721 contract with mutable metadata) can rename a well-known/trusted pointer contract's exposed symbol to impersonate another established asset without needing a new contract address, misleading integrators that whitelist by address alone but display/rely on `symbol()`.
- Cause unexpected accounting/parsing failures in downstream EVM contracts that treat `symbol()`/`name()` as constant per address (as flagged by the original report and the linked Trail of Bits Token Integration Checklist).

This matches "unauthorized transfer via precompile or pointer" style impact by corrupting identity assumptions integrators rely on for a live, already-adopted pointer contract, and it is reachable from a single public transaction with no privileged role, satisfying Medium severity.

### Likelihood Explanation
High reachability: the `addNativePointer`/`addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` methods are public precompile entry points callable by any EVM transaction sender with no special permission, and the "upsert" logic path is always exercised whenever the pointer already exists — there is no opt-out or governance gate to prevent overwriting a live pointer's identity metadata once the underlying denom/contract metadata is legitimately altered by its own admin. The only prerequisite is that the token's bank metadata (or CW20/CW721/CW1155 introspection data) changes after the pointer was first created, which is an expected/normal admin operation (tokenfactory `MsgSetDenomMetadata` is a documented, first-class capability) — not a contrived edge case.

### Recommendation
- Reintroduce the version/guard check (as legacy `v552`/`v555` did) to prevent silently overwriting an existing pointer's constructor-encoded `name`/`symbol`/`decimals` once already deployed, or explicitly version-bump the pointer contract address when metadata changes so identity is never mutated in place.
- If in-place refresh is intentional (e.g., to fix decimals/typos), gate `UpsertERCPointer` overwrites behind an explicit governance/admin-controlled flag or require the denom/CW admin's signature, rather than any public caller.
- Emit clearer, distinguishable events (e.g., `PointerMetadataUpdated`) so downstream integrators can detect and react to identity changes rather than silently trusting `symbol()`/`name()` as immutable.

### Proof of Concept
1. A tokenfactory denom `factory/{admin}/foo` is created and given bank metadata `{name: "Foo", symbol: "FOO"}`.
2. Any user calls the pointer precompile's `addNativePointer("factory/{admin}/foo")`; `AddNative` creates an ERC20 pointer contract `P` with `name="Foo"`, `symbol="FOO"` baked into its bytecode via `evm.Create` in `UpsertERCPointer` (exists == false branch) [8](#0-7) .
3. Integrators register `P` as "FOO" token (DEX listing, wallet display, other contract logic keyed by `symbol()`).
4. The tokenfactory admin calls `MsgSetDenomMetadata` to change the denom's metadata to `{name: "Bar", symbol: "BAR"}` [6](#0-5) .
5. Any user (not necessarily the admin) calls `addNativePointer("factory/{admin}/foo")` again. `UpsertERCPointer` finds the pointer exists, and instead of reverting, redeploys init code with the new args, overwriting `P`'s bytecode via `k.SetCode` [9](#0-8) .
6. `P.symbol()`/`P.name()` now return `"BAR"`/`"Bar"` at the exact same address `P` that integrators had already trusted/listed as "FOO", with no new deployment and no signal beyond a generic `PointerRegistered` event that reuses the same type/attribute shape as initial creation.

func (p PrecompileExecutor) AddNative(ctx sdk.Context, method *ethabi.Method, caller common.Address, args []interface{}, value *big.Int, evm *vm.EVM, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	token := args[0].(string)
	metadata, metadataExists := p.bankKeeper.GetDenomMetaData(ctx, token)
	if !metadataExists {
		return nil, 0, fmt.Errorf("denom %s does not have metadata stored and thus can only have its pointer set through gov proposal", token)
	}
	name := metadata.Name
	symbol := metadata.Symbol
	var decimals uint8
	for _, denomUnit := range metadata.DenomUnits {
		if denomUnit.Exponent > uint32(decimals) && denomUnit.Exponent <= math.MaxUint8 {
			decimals = uint8(denomUnit.Exponent)
			name = denomUnit.Denom
			symbol = denomUnit.Denom
			if len(denomUnit.Aliases) > 0 {
				name = denomUnit.Aliases[0]
			}
		}
	}
	contractAddr, err := p.evmKeeper.UpsertERCNativePointer(ctx, evm, token, utils.ERCMetadata{Name: name, Symbol: symbol, Decimals: decimals})
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(contractAddr)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}

func (k *Keeper) UpsertERCPointer(
	ctx sdk.Context, evm *vm.EVM, typ string, args []interface{}, getter PointerGetter, setter PointerSetter,
) (contractAddr common.Address, err error) {
	pointee := args[0].(string)
	evmModuleAddress := k.GetEVMAddressOrDefault(ctx, k.AccountKeeper().GetModuleAddress(types.ModuleName))

	var bin []byte
	bin, err = artifacts.GetParsedABI(typ).Pack("", args...)
	if err != nil {
		panic(err)
	}
	bin = append(artifacts.GetBin(typ), bin...)
	// GetDeploymentCode / Create take EVM snapshots that Freeze() Multistore layers.
	// Exists-lookup and commits must use the live unfrozen top (sdb.Ctx): cachekv
	// forbids writing a frozen layer, and same-tx readers that skip frozen-empty
	// parents would miss those writes. The precompile Prepare `ctx` is that top at
	// Prepare time, but is frozen once this Upsert snapshots. Always attach the
	// caller's gas meter (finite precompile meter in deliver) — sdb.Ctx() alone
	// carries the infinite EVM meter.
	sdb := state.GetDBImpl(evm.StateDB)
	liveCtx := func() sdk.Context {
		if sdb == nil {
			return ctx
		}
		return sdb.Ctx().WithGasMeter(ctx.GasMeter())
	}
	existingAddr, _, exists := getter(liveCtx(), pointee)
	suppliedGas := k.getEvmGasLimitFromCtx(ctx)
	var remainingGas uint64
	if exists {
		var ret []byte
		contractAddr = existingAddr
		ret, remainingGas, err = evm.GetDeploymentCode(evmModuleAddress, bin, suppliedGas, utils.Big0, existingAddr)
		if err != nil {
			return
		}
		// Only write on success: a failed GetDeploymentCode can leave ret as nil or
		// revert data, which must not clobber live pointer bytecode (even transiently).
		writeCtx := liveCtx()
		k.SetCode(writeCtx, contractAddr, ret)
		if sdb != nil {
			sdb.RefreshCodeCache(contractAddr, ret)
		}
	} else {
		_, contractAddr, remainingGas, err = evm.Create(evmModuleAddress, bin, suppliedGas, uint256.NewInt(0))
	}

func (server msgServer) SetDenomMetadata(goCtx context.Context, msg *types.MsgSetDenomMetadata) (*types.MsgSetDenomMetadataResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	// Defense in depth validation of metadata
	err := msg.Metadata.Validate()
	if err != nil {
		return nil, err
	}

	authorityMetadata, err := server.GetAuthorityMetadata(ctx, msg.Metadata.Base)
	if err != nil {
		return nil, err
	}

	if msg.Sender != authorityMetadata.GetAdmin() {
		return nil, types.ErrUnauthorized
	}

	server.bankKeeper.SetDenomMetaData(ctx, msg.Metadata)

	ctx.EventManager().EmitEvents(sdk.Events{
		sdk.NewEvent(
			types.TypeMsgSetDenomMetadata,
			sdk.NewAttribute(types.AttributeDenom, msg.Metadata.Base),
			sdk.NewAttribute(types.AttributeDenomMetadata, msg.Metadata.String()),
		),
	})

	return &types.MsgSetDenomMetadataResponse{}, nil
}
