### Title
Global (non-per-sender) gasless bundle-tx queue/pending caps allow a fee-free DoS of the gasless swap pipeline - (File: `kaiax/gasless/impl/tx_pool.go`)

### Summary
The `Teleportation` bug is a global, unauthenticated, cheap-to-trigger resource limit (`maxTransferAmountPerDay`) that any unprivileged caller can exhaust to block all other users for a fixed window. The `kaiax/gasless` module contains a structurally identical pattern: `MaxBundleTxsInQueue`/`MaxBundleTxsInPending` are pool-wide counters (not per-sender) that gate whether *any* gasless bundle tx can be accepted or promoted, and gasless senders are explicitly exempt from the native-KAIA balance/gas check that normally deters spam.

### Finding Description
`PreAddTx` rejects a new gasless bundle tx once the pool-wide queued-bundle count reaches `GetMaxBundleTxsInQueue()`: [1](#0-0) 

`IsReady` applies the same pool-wide gating for promotion into `pending` via `GetMaxBundleTxsInPending()` and `knownTxs.numExecutable()`: [2](#0-1) 

Both counters are computed over the *entire* `knownTxs` map, not scoped per sender/address: [3](#0-2) 

Critically, the README states the sender KAIA balance check — the normal deterrent against spamming the tx pool — is explicitly skipped for gasless transactions, because the block proposer lends the gas fee: [4](#0-3) 

`GetCheckBalance` only validates ERC20 token balance/allowance/deadline via `checkBalanceForApprove`/`checkBalanceForSwap` — no requirement that the sender hold any KAIA at all: [5](#0-4) [6](#0-5) 

Default caps are small (100 pending / 200 queued) and, like `maxTransferAmountPerDay`, are simple global thresholds with no per-sender quota, priority, or fee scaling: [7](#0-6) 

### Impact Explanation
An attacker who can obtain a minimal amount of any single whitelisted ERC20 token (e.g., a few wei of a low-value/self-created listed token, or simply reusing a small balance across many throwaway EOAs since only `balanceOf(sender) > 0`/`allowance` is checked, not aggregate spend) can generate many `GaslessApproveTx`/`GaslessSwapTx` pairs from many addresses. None of these addresses need any KAIA, since:
1. The sender balance check is explicitly bypassed for module (gasless) transactions in the general tx-pool filter logic, deferring to the module's own `GetCheckBalance`.
2. `GetCheckBalance` for gasless never requires the sender to hold KAIA.

By continuously submitting such bundle txs, the attacker can keep `numQueue()`/`numExecutable()` pinned at the configured maxima, causing `PreAddTx` to return `ErrBundleTxQueueFull` and `IsReady` to refuse promotion for legitimate users' gasless swaps — a denial of service against the entire gasless subsystem for as long as the attacker sustains the flood (bounded only by `QueueTimeout`/`PendingTimeout`/`KnownTxTimeout`, i.e. tens of seconds per wave, making it a persistent/renewable DoS, analogous to a "daily limit" but repeatable far more frequently). This is a direct denial-of-service/value-lock analog to the reported Teleportation issue: legitimate users relying on gasless (fee-less) transactions are prevented from using the feature, and the block proposer's lent gas is a value flow that a griefer can indirectly monopolize/waste by keeping the queue full with worthless bundles that ultimately fail balance/executability checks and get dropped after timeout, repeatedly consuming proposer lend-tx attempts and pool slots.

### Likelihood Explanation
Likelihood is high: the attack requires only trivial ERC20 token balance/allowance (attacker fully controls this, e.g., a token they mint/approve to themselves) and standard transaction submission through the public RPC — no special privilege, no native KAIA gas budget beyond what any address needs to be a "module tx" sender (which is explicitly not checked here). The queue/pending limits are global integers with no per-address quota, so a single actor (or a small Sybil set) can trivially saturate them.

### Recommendation
- Scope `MaxBundleTxsInQueue`/`MaxBundleTxsInPending` per-sender in addition to (or instead of) a pure global counter, or add a minimum lending-cost/fee-bond requirement per gasless bundle so proposers/other users aren't griefed for free.
- Require gasless bundle senders to also satisfy some minimal, non-trivial economic cost (e.g., proportional to the number of concurrently pending gasless bundle txs from the same sender) to raise the cost of flooding.
- Consider rate-limiting bundle tx acceptance per sender/IP at the RPC layer in addition to the pool-level cap.

### Proof of Concept
1. Deploy/select a whitelisted ERC20 token and mint/hold a minimal nonzero balance across N throwaway EOAs (no KAIA needed on any of them).
2. For each EOA, submit a `GaslessApproveTx` (approve `MaxUint256` to the whitelisted `SwapRouter`) followed by a `GaslessSwapTx` referencing that token, satisfying only the module's `checkBalanceForApprove`/`checkBalanceForSwap` (token balance > 0, allowance ≥ amountIn, deadline in future) — no KAIA balance is checked per `kaiax/gasless/impl/tx_pool.go:62-182`.
3. Repeat submission from N ≥ `MaxBundleTxsInQueue` (default 200) distinct senders faster than `QueueTimeout` (10s) expiry, keeping `knownTxs.numQueue()` at the cap.
4. Observe `PreAddTx` return `ErrBundleTxQueueFull` (`kaiax/gasless/impl/tx_pool.go:46-52`) for legitimate gasless bundle submissions from other users, and/or `IsReady` refusing promotion once `numExecutable()+numSeqTxs > MaxBundleTxsInPending` (`kaiax/gasless/impl/tx_pool.go:206-224`), confirming legitimate gasless users are blocked while the attacker pays no KAIA fee.

```go
func (g *GaslessModule) GetCheckBalance() func(tx *types.Transaction) error {
	return func(tx *types.Transaction) error {
		if approveArgs, ok := decodeApproveTx(tx, g.signer); ok {
			return g.checkBalanceForApprove(approveArgs)
		}
		if swapArgs, ok := decodeSwapTx(tx, g.signer); ok {
			return g.checkBalanceForSwap(swapArgs, tx.Nonce())
		}
		return errors.New("not a gasless transaction") // should not happen because IsModuleTx is called before GetCheckBalance
	}
}

func (g *GaslessModule) checkBalanceForApprove(approveArgs *ApproveArgs) error {
	token := approveArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(approveArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {
		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// tx.token.balanceOf(sender) > 0
		tokenBalance, err := tokenContract.BalanceOf(nil, approveArgs.Sender)
		if err != nil {
			return err
		}
		if tokenBalance.Sign() <= 0 {
			return fmt.Errorf("insufficient sender token balance: token=%s, have=%s, want=nonzero", token.Hex(), tokenBalance.String())
		}
	}
	return nil
}
```

```go
func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {

		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// If SwapTx.nonce is the sender's next nonce, then there is no room for ApproveTx proceeding SwapTx.
		senderNonce := g.getCurrentStateNonce(swapArgs.Sender)
		noApproveTxPreceeds := swapNonce == senderNonce
		if noApproveTxPreceeds {
			// tx.token.allowance(sender, router) >= tx.amountIn
			approval, err := tokenContract.Allowance(nil, swapArgs.Sender, swapRouter)
			if err != nil {
				return err
			}
			if approval.Cmp(swapArgs.AmountIn) < 0 {
				return fmt.Errorf("insufficient approval: approval=%s, want=%s", approval.String(), swapArgs.AmountIn.String())
			}
		}

		// tx.token.balanceOf(sender) >= tx.amountIn
		balance, err := tokenContract.BalanceOf(nil, swapArgs.Sender)
		if err != nil {
			return err
		}
		if balance.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("insufficient balance: balance=%s, want=%s", balance.String(), swapArgs.AmountIn.String())
		}
	}

	// tx.deadline >= currentTimestamp
	deadline := swapArgs.Deadline
	if deadline.Cmp(g.Chain.CurrentBlock().Time()) < 0 {
		return fmt.Errorf("insufficient deadline: deadline=%s, want=%s", deadline.String(), g.Chain.CurrentBlock().Time().String())
	}

	return nil
}
```

```go
func (k knownTxs) numExecutable() int {
	num := 0
	for _, knownTx := range k {
		if knownTx.status == TxStatusPending && !knownTx.tx.IsMarkedUnexecutable() {
			num++
		}
	}
	return num
}

func (k knownTxs) numQueue() int {
	num := 0
	for _, knownTx := range k {
		if knownTx.status == TxStatusQueue {
			num++
		}
	}
	return num
}
```

```markdown
Note that gasless transaction does not mean the gas prices of gasless transactions are zero, but it means that proposer will lend the user with gas fee and user will pay back during gasless swap.

The gas fee of gasless transaction's is funded by block proposer (i.e., lend transaction generated by `GetLendTxGenerator`), and user repays the lent amount during gasless swap.

### Transaction pool rules

#### Ready

This module is responsible for promoting gasless transactions.
Sender's nonce of GaslessSwapTx is checked to distinguish if GaslessApproveTx is expected. If `tx.nonce == GetNonce(sender) + 1`, GaslessApproveTx is expected. If `tx.nonce == GetNonce(sender)`, GaslessApproveTx is not expected.

If GaslessApproveTx is expected, GaslessApproveTx and GaslessSwapTx can be promoted when they are both ready for execution.
Otherwise, GaslessSwapTx can be promoted when it is ready for execution.

See ready condition [KIP-247](https://kips.kaia.io/KIPs/kip-247) and the implementation `IsExecutable(approveTxOrNil, swapTx *types.Transaction) bool`.

#### Balance check

Sender balance check is omitted for gasless transactions (see `GetCheckBalance()`).
```
