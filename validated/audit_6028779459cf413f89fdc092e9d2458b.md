### Title
Batched bribe-harvesting in `castVotes()`/`WombatStaking.vote()` can be permanently DoS'd by a single blacklist-capable bribe reward token - (File: `wombat/WombatStaking.sol`)

### Summary
`WombatBribeManager.castVotes()` is a fully public, unprivileged entry point that aggregates **all** active pools into one transaction and calls `WombatStaking.vote()`, which loops over every pool's bribe reward tokens and unconditionally `safeTransfer`s protocol/caller fees to fixed addresses (`bribeFeeCollector`, `bribeManager`). Because this is all done in a single all-or-nothing loop with no isolation between pools, one reward token that reverts on transfer to a fixed address (e.g. an OpenZeppelin-style blacklist/pausable ERC20, common among stablecoin-style bribe tokens) blocks the entire batch, freezing bribe reward distribution for every pool and every voter, not just the one associated with the bad token.

### Finding Description
`castVotes()` builds arrays covering the *entire* `pools` list and forwards them to `wombatStaking.vote()`: [3](#0-2) 

Inside `vote()`, for every pool in the batch, protocol fee and caller fee are sent via `safeTransfer` to hardcoded addresses (`bribeFeeCollector`, `bribeManager`) before the remainder is queued to that pool's rewarder: [4](#0-3) 

The reward tokens iterated here (`IWombatBribe(bribesContract).rewardTokens()`) are arbitrary ERC20s registered by third-party bribers on the external Wombat voter/bribe contracts — not validated or allow-listed by this codebase. If any single one of these tokens reverts a transfer to `bribeFeeCollector` (or `bribeManager`) — e.g., a USDC/USDT-style token that blacklists that address, or simply reverts on transfers to a contract for any reason — the `safeTransfer` call reverts, unwinding the entire `vote()` call and therefore the entire `castVotes()` transaction, since there is no per-pool try/catch or skip mechanism.

Because `castVotes()` is the sole path by which bribe rewards are harvested and pushed into each pool's `IBribeRewardPool` (so voters can later call `claimBribe`/`claimAllBribes`), a permanently reverting token belonging to just one pool blocks harvesting for **all** pools and **all** voters, indefinitely, until an owner calls `removePool` to excise the offending pool from the `pools` array — an admin-dependent remediation, so the freeze persists for an unbounded period for all unprivileged voters in the meantime.

### Impact Explanation
This is a shared, unprivileged batch: any voter (or an outsider) calling `castVotes()` triggers processing of every registered pool's bribes in one atomic transaction. A single non-conforming/blacklisting reward token used by one bribe pool halts bribe reward accrual and distribution system-wide, causing a protocol-wide freeze of unclaimed bribe yield for all voters across all pools — well beyond a 24-hour window, since remediation requires an owner-only `removePool` call.

### Likelihood Explanation
Reward tokens are supplied by external, third-party bribe creators via the Wombat voter/bribe contracts and are not filtered or validated by `WombatStaking` or `WombatBribeManager`. Using blacklist-style/compliance tokens (e.g. USDC/USDT-like tokens) as bribe incentives is common, and `castVotes()` can be triggered by anyone at any time, so the failure condition is easily reachable without any privileged action once such a token is used as a bribe reward and the fixed fee-collector/bribe-manager address becomes unable to receive it.

### Recommendation
Isolate per-pool reward processing (e.g. wrap each pool's fee transfer/`queueNewRewards` call in a `try/catch`, or process pools independently rather than in one shared loop/transaction) so a single misbehaving reward token cannot revert the harvesting of unrelated pools. Additionally, consider allowing a pool/token to be flagged inactive automatically or via permissionless mechanism when its transfer reverts, rather than requiring only owner-gated `removePool`.

### Proof of Concept
1. A briber registers a blacklist-capable ERC20 (e.g., a `USDC`-like token) as a bribe reward token for `PoolX` on the external Wombat voter/bribe contract.
2. The token issuer (or any mechanism causing a revert on transfer to `bribeFeeCollector`) blocks transfers to `WombatStaking.bribeFeeCollector` for that token.
3. Any user calls `WombatBribeManager.castVotes(false)`.
4. `castVotes()` iterates all `pools` and calls `wombatStaking.vote(...)`, which reaches `PoolX`'s reward token and attempts `IERC20(rewardTokens[i][j]).safeTransfer(bribeFeeCollector, protocolFee)` at [5](#0-4) , which reverts.
5. The revert propagates through `vote()` and `castVotes()`, so no pool's rewards (including unrelated, healthy pools) are queued to their `IBribeRewardPool` rewarders — freezing bribe reward accrual for every voter until the owner removes `PoolX` from `pools`.

        rewardTokens = new IERC20[][](rewardAmounts.length);
        callerFeeAmounts = new uint256[][](rewardAmounts.length);

        for (uint256 i; i < rewardAmounts.length; i++) {

            address bribesContract = address(voter.infos(_lpVote[i]).bribe);

            if (bribesContract != address(0)) {
                rewardTokens[i] = IWombatBribe(bribesContract).rewardTokens();
                callerFeeAmounts[i] = new uint256[](rewardAmounts[i].length);

                for (uint256 j; j < rewardAmounts[i].length; j++) {
                    uint256 rewardAmount = rewardAmounts[i][j];
                    uint256 callerFeeAmount = 0;

                    if (rewardAmount > 0) {
                        // if reward token is bnb, wrap it first
                        if (address(rewardTokens[i][j]) == address(0)) {
                            Address.sendValue(payable(wbnb), rewardAmount);
                            rewardTokens[i][j] = IERC20(wbnb);
                        }

                        uint256 protocolFee = (rewardAmount * bribeProtocolFee) / DENOMINATOR;

                        if (protocolFee > 0) {

                    callerFeeAmounts[i][j] = callerFeeAmount;
