### Title
Delayed `unlock()` after cooldown expiry lets a user keep collecting a decaying-but-nonzero reward eligibility bonus on already-matured MGP - ([File: contracts/VLMGP.sol])

### Summary
`VLMGP.getRewardablePercentWAD` never zeroes an unlock slot's `amountInCoolDown` once `endTime` has passed; it only clears it inside `unlock()`. As a result, a user who lets a slot sit expired-but-unfinalized keeps that slot counted in `userTotalVlmgp` and keeps receiving a nonzero, slowly-decaying "fully unlocked" bonus term in `getRewardablePercentWAD`, which is consumed by `vlMGPBaseRewarder._calExpireForfeit` to reduce the forfeiture applied to that user's harvested rewards, at the expense of the forfeiture pool that would otherwise be redistributed to other vlMGP holders via `_queueNewRewardsWithoutTransfer`.

### Finding Description
`getRewardablePercentWAD` ( [1](#0-0) ) computes:
- `userTotalVlmgp = fullyInLock + inCoolDown`, where `inCoolDown = getUserAmountInCoolDown(_user)` sums `amountInCoolDown` across *all* slots, including expired ones, because `amountInCoolDown` is only reset to `0` inside `unlock()` ( [2](#0-1) ).
- `percent = fullyInLock * 1e18 / userTotalVlmgp` as the base term.
- For each slot with `amountInCoolDown > 0`: if `block.timestamp > endTime` ("fully unlocked" but not yet claimed), it adds `amountInCoolDown * 1e18 * (endTime - startTime) / userTotalVlmgp / (timeNow - startTime)`.

This added term equals the slot's full weight (`amountInCoolDown * 1e18 / userTotalVlmgp`) exactly at `timeNow == endTime`, and decays toward `0` as `timeNow` grows, but is never actually forced to `0` — it stays strictly positive for as long as the user withholds calling `unlock()`. Because `amountInCoolDown` (and thus the slot) is still included in `userTotalVlmgp`'s denominator, the user's rewardable percentage remains materially higher during this decay window than it would be immediately after a prompt `unlock()` call (which removes the slot's amount from `userTotalVlmgp` entirely and pulls the tokens out via `IMasterMagpie(masterMagpie).withdrawVlMGPFor` in `_unlock`, see [3](#0-2) ).

`vlMGPBaseRewarder._calExpireForfeit` uses this percent directly to determine how much of a user's accrued reward is forfeited vs. paid out: `rewardableAmount = _amount * rewardablePercentWAD / 1e18` ( [4](#0-3) ), and the forfeited remainder is recycled into the pool for all other stakers via `_queueNewRewardsWithoutTransfer` in `_sendReward` ( [5](#0-4) ). No modifier, `nonReentrant` guard, or accounting check prevents a user from calling `startUnlock` ( [6](#0-5) ), letting the slot pass `endTime`, and repeatedly calling `getReward`/harvesting for an extended period without ever calling `unlock()`.

### Impact Explanation
This is a real, quantifiable "theft of unclaimed yield" impact class: rewards that should be forfeited and redistributed to other reward-pool participants (via `_queueNewRewardsWithoutTransfer`) are instead retained by the delaying user because `getRewardablePercentWAD` keeps crediting an expired-but-unfinalized cooldown slot. The magnitude is bounded and decaying (it asymptotically converges to the value a promptly-exited user would have), so it is not an unbounded drain, but it is a concrete, quantifiable diversion of yield from the collective forfeiture pool to any user who simply postpones calling `unlock()`.

### Likelihood Explanation
Trivial to trigger and fully reachable by an unprivileged EOA: `startUnlock` → wait past `coolDownInSecs` → repeatedly call the reward harvesting entrypoint without calling `unlock()`. No special capital, roles, or timing precision beyond normal transaction submission is required, and it is repeatable across every reward-harvest cycle for as long as the user chooses to leave the slot unfinalized.

### Recommendation
In `getRewardablePercentWAD`, once a slot is past `endTime`, either exclude its `amountInCoolDown` from both `userTotalVlmgp` and the added bonus term entirely (treat it as already fully withdrawn for reward-eligibility purposes), or cap/expire the decaying term to `0` after a bounded grace period so it cannot indefinitely dilute the forfeiture pool. Alternatively, have `getUserAmountInCoolDown`/`getFullyUnlock` distinguish "still cooling down" from "matured, awaiting `unlock()`" and treat matured amounts as not contributing to `rewardablePercentWAD` at all.

### Proof of Concept
Foundry test plan:
1. Deploy `VLMGP`, `MasterMagpie`, and `vlMGPBaseRewarder`; fund a reward token and queue rewards each "cycle".
2. User A and User B each `lock()` the same MGP amount, then both call `startUnlock(X)` at the same timestamp `t0` with the same `coolDownInSecs`.
3. At `t0 + coolDownInSecs` (endTime), User A immediately calls `unlock(slotIndex)`.
4. User B does not call `unlock()`.
5. Advance time in several increments (e.g., weekly), queue new rewards each cycle, and have both users call `getReward` at each increment.
6. Assert that User B's cumulative claimed reward (sum of `RewardPaid` amounts) strictly exceeds User A's cumulative claimed reward for the same accrued reward stream, and that the `ForfeitRewardAdded`/queued-forfeit amount attributable to User B is correspondingly smaller than expected had `unlock()` been called at `endTime`, demonstrating the extra yield extracted purely by delaying `unlock()`.

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalVlmgp = fullyInLock + inCoolDown;
        if (userTotalVlmgp == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalVlmgp;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalVlmgp / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalVlmgp;
                }

            }
        }

        return percent;
    }

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }
