### Title
Division-by-zero panic in KIP-71 base fee calculation when `GasTarget` governance parameter is set to zero - ([File: params/kip71_config.go])

### Summary
The `Kip71GasTarget` governance parameter is registered with a `noopFormatChecker`, meaning it accepts any `uint64` value, including `0`. Unlike the sibling parameter `Kip71BaseFeeDenominator`, which explicitly rejects zero (`v != 0`), `GasTarget` has no such guard. `GasTarget` is used unconditionally as a divisor in `KIP71Config.NextMagmaBlockBaseFee`, so setting it to `0` via governance causes every subsequent block's base-fee computation to panic with a Go runtime "division by zero" error rather than gracefully reverting.

### Finding Description
`Kip71GasTarget`'s parameter definition uses `noopFormatChecker` with no zero check: [1](#0-0) 

Compare this to `Kip71BaseFeeDenominator`, which explicitly guards against zero: [2](#0-1) 

`NextMagmaBlockBaseFee` reads `gasTarget := kc.GasTarget` with no zero check and then uses it directly as a divisor via `big.Int.Div` in both the "gas used above target" and "gas used below target" branches: [3](#0-2) [4](#0-3) 

Note that `BaseFeeDenominator` has an explicit zero-fallback (`baseFeeDenominator = 64` if zero) at lines 71-76, but `GasTarget` has no equivalent fallback. `math/big`'s `Int.Div`/`Int.DivMod` panic (not return an error) when the divisor is zero, so this is a hard runtime panic, not a Solidity-style `require` revert as in the referenced report — the impact is a node crash / chain halt rather than a single-transaction revert.

This function is called from `VerifyMagmaHeader`, which is invoked during block header verification: [5](#0-4) 
and referenced in `blockchain/block_validator.go` as part of standard block validation for every block after Magma is active.

### Impact Explanation
If `GasTarget` is set to `0` through the governance parameter voting mechanism (a normal, unprivileged-reachable governance vote path per the KIP-71 parameter set), every node computing or validating the next block's base fee will panic in `NextMagmaBlockBaseFee` (as long as `parentGasUsed != 0`, i.e., almost every block). Because this function is called during block header validation for all blocks, this causes a consensus-wide crash/halt across all honest nodes — a severe availability failure of the network rather than a localized revert, satisfying the "state divergence / invalid transaction or block acceptance"-adjacent class of impact (in this case, complete inability to process any further blocks).

### Likelihood Explanation
Reachability requires a governance parameter change setting `Kip71GasTarget` to `0`. This is validated only by `noopFormatChecker`, so the parameter system itself will accept the malicious/erroneous value without any additional validation layer catching it before it's committed to `ChainConfig`. Given governance voting is an explicitly in-scope reachable path (per the listed categories) and no other check exists to prevent zero, likelihood is non-trivial once a vote for `GasTarget=0` passes.

### Recommendation
Add a zero-check to the `Kip71GasTarget` `FormatChecker` in `kaiax/gov/param.go` (mirroring `Kip71BaseFeeDenominator`'s `v != 0` check), and/or add a defensive zero-check with a safe fallback (similar to the existing `BaseFeeDenominator` zero-fallback) inside `NextMagmaBlockBaseFee` in `params/kip71_config.go` before using `gasTarget` as a divisor.

### Proof of Concept
1. Submit and pass a governance vote setting `governance.kip71.gastarget` (param name `Kip71GasTarget`) to `0`. `FormatChecker: noopFormatChecker` accepts this value. [1](#0-0) 
2. Once the parameter takes effect at the next epoch, any block whose parent has `GasUsed != 0` triggers the `else`/`else if` branches in `NextMagmaBlockBaseFee`, which compute `x.Div(x, new(big.Int).SetUint64(gasTarget))` with `gasTarget == 0`. [6](#0-5) 
3. `math/big.Int.Div` panics on divide-by-zero, crashing every node that validates the header (`VerifyMagmaHeader`) or proposes the next block, halting the chain.

func (kc *KIP71Config) VerifyMagmaHeader(headerBaseFee *big.Int, parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) error {
	if headerBaseFee == nil {
		return fmt.Errorf("header is missing baseFee")
	}
	// Verify the baseFee is correct based on the parent header.
	expectedBaseFee := kc.NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)
	if headerBaseFee.Cmp(expectedBaseFee) != 0 {
		return fmt.Errorf("invalid baseFee: have %s, want %s, parentBaseFee %s, parentGasUsed %d",
			headerBaseFee, expectedBaseFee, parentHeaderBaseFee, parentHeaderGasUsed)
	}
	return nil
}
