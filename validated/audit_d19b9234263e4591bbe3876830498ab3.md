### Title
`clone()` explicitly disables Git's clone-time hook-execution protection (`GIT_CLONE_PROTECTION_ACTIVE=false`) while recursively cloning attacker-controlled repositories - ([File: app/src/lib/git/clone.ts])

### Summary
The external report's broken invariant is "code from an unverified, attacker-controlled callback is executed without any integrity check." The closest concrete Desktop analog is that GitHub Desktop's `clone()` helper unconditionally sets `GIT_CLONE_PROTECTION_ACTIVE: 'false'` in the child-process environment for every `git clone --recursive` invocation, which turns off Git's own defense-in-depth check (added for the class of clone-time hook/symlink-execution vulnerabilities, e.g. CVE-2024-32004) that would otherwise refuse to complete a clone when a repository's on-disk layout looks unsafe (e.g. symlinked `.git`, embedded repositories, or submodule constructs that could let hook scripts execute during checkout).

### Finding Description
`clone()` builds the environment for the underlying `git clone` invocation like this: [1](#0-0) 

`GIT_CLONE_PROTECTION_ACTIVE` is a real Git environment toggle used by upstream Git's clone-safety hardening; setting it to `'false'` deliberately turns that hardening off for every clone Desktop performs, including `--recursive` clones (submodules). The clone target `url` is attacker-controlled input in several unprivileged flows:

- The `x-github-client://openRepo/<url>` deep-link handler, parsed with no allow-listing of protocol/content, flows straight into `openOrCloneRepository(url)` → clone popup → `clone()`: [2](#0-1) [3](#0-2) 

- The "Open PR from Desktop" flow takes `pullRequest.head.repo.clone_url` from the GitHub API response (attacker fully controls this by opening a PR from a malicious fork) and calls into the same clone path: [4](#0-3) 

With submodule recursion (`--recursive`) enabled and the clone-time protection explicitly disabled, a malicious repository (or a malicious submodule referenced by `.gitmodules` inside it) can rely on the exact class of on-disk trick that Git's protection exists to reject — resulting in code execution on the victim's machine during the clone/checkout of an untrusted repository, without any local access, admin rights, or social engineering beyond clicking an "Open in Desktop" link or opening a PR from a fork.

Unlike the other paths in this codebase, which show clear hardening (`isClonePathSensitive`, `sanitizeCloneName`, `resolveWithin`, OAuth CSRF `state` check), this line takes the opposite action: it actively turns off an upstream Git safety check rather than adding one.

### Impact Explanation
If the disabled protection would have blocked a malicious repository layout, an attacker who gets a victim to click a `x-github-client://openRepo/...` link (or open a Desktop PR handoff from a malicious fork) can achieve code execution on the victim's machine during clone, matching the report's core violated invariant of "untrusted external content executed without verification." This is within the accepted impact category: attacker controls a cloned/fetched repository or a link the user clicks, and the result is code execution outside the intended repo sandbox.

### Likelihood Explanation
The trigger requires only a single click on an attacker-supplied deep link or PR, with no local access, no leaked credentials, and no unnatural manual steps — this satisfies the "unprivileged" and "attacker controls a cloned/fetched repository / a link the user clicks" criteria. The `--recursive` flag guarantees submodule URLs from the attacker's `.gitmodules` are also fetched under the same weakened protection.

### Recommendation
Remove the `GIT_CLONE_PROTECTION_ACTIVE: 'false'` override so Desktop uses Git's default (protection-active) behavior for all clones, especially `--recursive` clones of untrusted, user-supplied or API-supplied URLs. If a specific compatibility issue motivated disabling it, gate that override behind an explicit, narrowly-scoped condition rather than applying it unconditionally to every clone.

### Proof of Concept
1. Attacker crafts a malicious public GitHub repository containing a submodule/`.gitmodules` entry or on-disk structure designed to exploit the class of vulnerability that `GIT_CLONE_PROTECTION_ACTIVE` guards against (as in upstream Git's CVE-2024-32004 class of issues).
2. Attacker sends the victim a link of the form `x-github-client://openRepo/https://github.com/attacker/evil-repo` (or opens a PR from `evil-repo` and shares the "Open in Desktop" PR link).
3. Victim clicks the link; `parseAppURL` recognizes `openRepo` and returns an `open-repository-from-url` action with no further validation of the target content: [3](#0-2) 
4. `dispatchURLAction` → `openRepositoryFromUrl` → `openOrCloneRepository` → clone popup → `clone()` is invoked with `--recursive` and `GIT_CLONE_PROTECTION_ACTIVE=false`: [5](#0-4) 
5. Because the safety check is disabled, the malicious repository/submodule layout that would normally be rejected is allowed to complete, potentially executing attacker-controlled hook code on the victim's machine during clone/checkout.

Note: I could not verify from the local index which exact bundled Git/dugite version ships with this build of Desktop, so I cannot confirm whether the underlying Git binary is otherwise patched for the specific CVE the `GIT_CLONE_PROTECTION_ACTIVE` variable governs — but regardless of patch level, explicitly setting this flag to `'false'` defeats the intended protection by design, which is the concrete, file-level evidence supporting this finding.

  url: string,
  path: string,
  options: CloneOptions,
  progressCallback?: (progress: ICloneProgress) => void

  if (isClonePathSensitive(path)) {
    throw new Error(
      `The clone destination "${path}" targets a sensitive system location. ` +
        'Cloning into this directory is not allowed.'
    )
  }

  const env = {
    ...(await envForRemoteOperation(url)),
    GIT_CLONE_PROTECTION_ACTIVE: 'false',
  }

  const defaultBranch = options.defaultBranch ?? (await getDefaultBranch())

  const args = [
    '-c',
    `init.defaultBranch=${defaultBranch}`,
    'clone',
    '--recursive',
  ]

  private async openOrCloneRepository(url: string): Promise<Repository | null> {
    const state = this.appStore.getState()
    const repositories = state.repositories
    const existingRepository = repositories.find(r =>
      this.doesRepositoryMatchUrl(r, url)
    )

    if (existingRepository) {
      return await this.selectRepository(existingRepository)
    }

    return this.appStore._startOpenInDesktop(() => {
      this.changeCloneRepositoriesTab(CloneRepositoryTab.Generic)
      this.showPopup({
        type: PopupType.CloneRepository,
