Based on my investigation, I found a plausible analog: a missing-validation pattern on a value sourced from an untrusted GitHub API response, which then flows into a security-sensitive parameter (an environment variable controlling which host the bundled Copilot CLI talks to), while the real account token is handed to that same process.

### Title
Unvalidated `copilotEndpoints.api` from GraphQL response is used as `GH_HOST` for the Copilot CLI subprocess, alongside the user's real GitHub token - (File: `app/src/lib/api.ts`, `app/src/lib/stores/copilot-store.ts`)

### Summary
`API.fetchUserCopilotInfo` takes the `copilotEndpoints.api` field straight out of a GraphQL response and returns it as `copilotEndpoint` with no format/host validation, mirroring the original report's pattern of "parameter that drives contract workflow is never validated at the point of assignment." [1](#0-0) 

That value is stored unchecked on the `Account` model via the constructor parameter `copilotEndpoint`. [2](#0-1) 

It is later passed into `getCopilotGHHost(account)` and set as the `GH_HOST` environment variable for the spawned Copilot CLI process, in the same call that hands the process the user's real `account.token` as `gitHubToken`. [3](#0-2) 

### Finding Description
The broken invariant is the same class as the report: a value that is foundational to a downstream trust decision (`BOOSTER` address in the Sherlock finding; `copilotEndpoint`/`GH_HOST` here) is accepted with no sanity check at the point where it enters the system. In `fetchUserCopilotInfo`, the code does `const { viewer } = json.data` and then `viewer.copilotEndpoints.api` directly, with no verification that the value is a well-formed URL, uses `https`, or matches an expected/allow-listed host (e.g., the account's own endpoint or a `github.com`/`ghe.com` domain). [4](#0-3) 

This value round-trips through `Account.copilotEndpoint` and is consumed later to set `GH_HOST` for the Copilot CLI child process created in `createClient`, which is invoked with the account's real GitHub token (`gitHubToken: account.token`). [3](#0-2) 

If a GraphQL response comes back with an attacker-influenced `copilotEndpoints.api` (e.g., a compromised or malicious GitHub Enterprise Server the user has already added as an account, or a MITM/compromised network path to a GHES instance not enforcing TLS pinning), the Desktop client would set `GH_HOST` to an attacker-controlled host for the CLI process it spawns with the real account token, without ever validating the endpoint shape or origin.

### Impact Explanation
`GH_HOST` is used by the Copilot CLI/SDK to determine which host to talk to for its own API/auth flows. If it is pointed at an attacker-controlled host, and that CLI process is simultaneously configured with the real `gitHubToken`, this creates a path for the token to be exfiltrated to a non-GitHub destination — a credential-exfiltration primitive that matches the "unprivileged issue where the attacker controls a GitHub API object … resulting in credential/token exfiltration" criterion. Compare this to the report's core complaint: an unchecked address/endpoint value silently propagates into a critical operation that relies on it being trustworthy.

### Likelihood Explanation
Exploitability requires the victim's Desktop app to fetch `fetchUserCopilotInfo` against an endpoint (typically GHES) that is attacker-influenced — this is plausible in an enterprise/compromised-GHES threat model, but it is not exploitable against unmodified github.com traffic under normal TLS assumptions. I was not able to inspect the implementation of `getCopilotGHHost` itself within the available tool budget (only its call site was found), so I cannot confirm with certainty whether it derives directly from `account.copilotEndpoint`, applies its own validation, or falls back to a hardcoded default in some cases. This uncertainty should be resolved before treating this as fully confirmed.

### Recommendation
Validate `copilotEndpoints.api` at the point it is parsed in `fetchUserCopilotInfo` — require `https:`, and either allow-list it against the account's own endpoint/host family (`github.com`, `*.ghe.com`, or the configured GHES origin) or reject/ignore unexpected values rather than propagating them into `Account.copilotEndpoint`. Additionally, review `getCopilotGHHost` to ensure `GH_HOST` cannot be set to an arbitrary attacker-influenced value while the same process is given the live GitHub token.

### Proof of Concept
1. Attacker controls or compromises a GitHub Enterprise Server instance (or an already-added GHES account's network path).
2. When Desktop calls the Copilot GraphQL query in `fetchUserCopilotInfo`, the malicious server responds with `data.viewer.copilotEndpoints.api = "https://attacker.example.com"`. [5](#0-4) 
3. This value is stored on the `Account` object unchanged and later passed into `getCopilotGHHost(account)` as `GH_HOST` when spawning the Copilot CLI, in the same call that supplies `gitHubToken: account.token`. [3](#0-2) 
4. Depending on `getCopilotGHHost`'s exact behavior (unverified), the CLI process could direct its authenticated requests, including the token, to `attacker.example.com` instead of the legitimate GitHub/GHES host.

  public async fetchUserCopilotInfo(): Promise<UserCopilotInfo | undefined> {
    // Copilot is not available on GHES
    if (isGHES(this.endpoint)) {
      return undefined
    }

    const graphql = `
    {
      viewer {
        copilotEndpoints {
          api
        }

        copilotLicenseType
        isCopilotDesktopEnabled
      }
    }
    `

    try {
      const response = await this.ghRequest('POST', '/graphql', {
        body: { query: graphql },
        customHeaders: {
          'GraphQL-Features': 'copilot_iap_max_sku',
        },
      })
      if (response === null) {
        return undefined
      }

      const json: ViewerCopilotResponse =
        (await response.json()) as ViewerCopilotResponse
      const { viewer } = json.data
      return {
        copilotEndpoint: viewer.copilotEndpoints.api,
        isCopilotDesktopEnabled: viewer.isCopilotDesktopEnabled,
        copilotLicenseType: viewer.copilotLicenseType,
      }
