### Title
Silent, unreviewable fast-forward of all local tracking branches on background fetch allows a malicious/compromised remote to move committed history out from under the user without any diff or confirmation - (File: `app/src/lib/stores/app-store.ts`)

### Summary
The Sherlock report's broken invariant is: a value that stops updating for a period (sequencer feed) suddenly delivers a large, unreviewed batch of changes all at once, with no grace period for the user to react before an automatic, consequential action (liquidation) is taken on their behalf. The Desktop analog is `AppStore.fastForwardBranches()` / `getBranchesDifferingFromUpstream()`, which is invoked automatically after *every* fetch — including unattended background fetches — and silently rewrites the tip of every local branch that has an upstream to match whatever `refs/remotes/*` state was just fetched, with zero diff, zero confirmation dialog, and no way for the user to inspect what changed before it lands in their working copy.

There is no check comparable to a Chainlink-style "grace period," no confirmation prompt, and no diff review step between "remote-tracking ref moved" and "local branch ref moved to match it." If a remote has been unreachable, rate-limited, or intentionally delayed by an attacker-controlled/compromised server (a git host, a malicious fork added as a remote, or a MITM proxy sitting between Desktop and the real remote) and then suddenly serves a large batch of new commits, all of a user's local branches tracking that remote are moved forward to the new tips in one shot, silently, the next time the background fetcher fires — potentially while the user is mid-edit on another branch, unaware that the branch they're about to switch to or build on top of no longer points at the commit they last reviewed.

### Impact Explanation
This falls under "silent corruption of what the user commits or pushes." A user who has reviewed and trusts the tip of a local branch (e.g., `release`, or a colleague's branch they track) can have that branch's ref moved forward, without a diff, without a prompt, purely as a side effect of a background timer. If the user subsequently switches to that branch, builds a commit on top of it, and pushes, they push on top of remote content they never reviewed. Because `getBranchesDifferingFromUpstream` walks *every* local branch with an upstream (not just the checked-out one), the blast radius is the entire set of tracked branches in the repository, not just the active one — directly mirroring the oracle bug's "all queued updates land at once, leaving no time to react."

### Likelihood Explanation
No special privileges are required beyond being able to serve/alter what a configured remote returns for `refs/*` — a scenario the threat model explicitly includes (attacker-controlled fetched repository / remote or proxy response). Background fetching is enabled by default and runs unattended once a repository is open in Desktop, so the fast-forward will fire automatically without any user action beyond having previously added/cloned the remote.

### Recommendation
- Do not silently fast-forward local branches that are not currently checked out as an unconditional side effect of every fetch; at minimum, surface a notification/diff summary of what changed and let the user opt in per branch, similar to how `pull` surfaces progress and conflicts for the current branch.
- When a remote-tracking ref has advanced by an unusually large number of commits since the last successful fetch (analogous to a "stale-then-burst" update), require explicit user acknowledgement before fast-forwarding non-current local branches.
- Consider scoping automatic fast-forward to branches the user has explicitly marked as "always sync," rather than every branch with an upstream.

### Proof of Concept
1. Clone a repository in Desktop and let a local branch `feature` track `origin/feature`, with `feature` currently a few commits behind but not checked out.
2. Compromise or MITM the `origin` remote (or point it at an attacker-controlled fork with the same ref names) so that fetches against it silently return no new data for a period.
3. After the background fetch interval elapses (`DefaultFetchInterval`/`MinimumInterval` in `app/src/lib/stores/helpers/background-fetcher.ts`), have the attacker's remote suddenly serve a burst of new commits on `feature`.
4. On the next unattended `BackgroundFetcher` tick, `performFetch` → `fastForwardBranches` (`app/src/lib/stores/app-store.ts:5614-5624`) runs automatically and moves local `feature` to the attacker-supplied tip with no diff shown and no prompt.
5. The user later checks out `feature`, commits on top, and pushes — now shipping on top of commits they never reviewed.

/**
 * Gets all branches that differ from their upstream (i.e. they're ahead,
 * behind or both), excluding the current branch.
 * Useful to narrow down a list of branches that could potentially be fast
 * forwarded.
 *
 * @param repository Repository to get the branches from.
 */
export async function getBranchesDifferingFromUpstream(
  repository: Repository
): Promise<ReadonlyArray<ITrackingBranch>> {
  const { formatArgs, parse } = createForEachRefParser({
    fullName: '%(refname)',
    sha: '%(objectname)', // SHA
    upstream: '%(upstream)',
    symref: '%(symref)',
    head: '%(HEAD)',
  })

  const prefixes = ['refs/heads', 'refs/remotes']

  const result = await git(
    ['for-each-ref', ...formatArgs, ...prefixes],
    repository.path,
    'getBranchesDifferingFromUpstream',
    { expectedErrors: new Set([GitError.NotAGitRepository]) }
  )

  if (result.gitError === GitError.NotAGitRepository) {
    return []
  }

  const localBranches = []
  const remoteBranchShas = new Map<string, string>()

  // First we need to collect the relevant info from the command output:
  // - For local branches with upstream: name, ref, SHA and the upstream.
  // - For remote branches we only need the sha (and the ref as key).
  for (const ref of parse(result.stdout)) {
    if (ref.symref.length > 0 || ref.head === '*') {
      // Exclude symbolic refs and the current branch
      continue
    }

    if (ref.fullName.startsWith('refs/heads')) {
      if (ref.upstream.length === 0) {
        // Exclude local branches without upstream
        continue
      }

      localBranches.push({
        ref: ref.fullName,
        sha: ref.sha,
        upstream: ref.upstream,
      })
    } else {
      remoteBranchShas.set(ref.fullName, ref.sha)
    }
  }

  const eligibleBranches = new Array<ITrackingBranch>()

  // Compare the SHA of every local branch with the SHA of its upstream and
  // collect the names of local branches that differ from their upstream.
  for (const branch of localBranches) {
    const remoteSha = remoteBranchShas.get(branch.upstream)

    if (remoteSha !== undefined && remoteSha !== branch.sha) {
      eligibleBranches.push({
        ref: branch.ref,
        sha: branch.sha,
        upstreamRef: branch.upstream,
        upstreamSha: remoteSha,
      })
    }
  }

export async function fastForwardBranches(
  repository: Repository,
  branches: ReadonlyArray<ITrackingBranch>
): Promise<void> {
  if (branches.length === 0) {
    return
  }

  const refPairs = branches.map(branch => `${branch.upstreamRef}:${branch.ref}`)

  await git(
    [
      'fetch',
      '.',
      // Make sure we don't try to update branches that can't be fast-forwarded
      // even if the user disabled this via the git config option
      // `fetch.showForcedUpdates`
      '--show-forced-updates',
      // Prevent `git fetch` from touching the `FETCH_HEAD`
      '--no-write-fetch-head',
      // Take branch refs from stdin to circumvent shell max line length
      // limitations (mainly on Windows)
      '--stdin',
    ],
    repository.path,
    'fastForwardBranches',
    {
      // Fetch exits with an exit code of 1 if one or more refs failed to update
      // which is what we expect will happen
      successExitCodes: new Set([0, 1]),
      env: {
        // This will make sure the reflog entries are correct after
        // fast-forwarding the branches.
        GIT_REFLOG_ACTION: 'pull',
      },
      stdin: refPairs.join('\n'),
    }
  )
}

  /** Perform a fetch and schedule the next one. */
  private async performAndScheduleFetch(
    repository: GitHubRepository
  ): Promise<void> {
    if (this.stopped) {
      return
    }

    const shouldFetch = await this.shouldPerformFetch(this.repository)

    if (this.stopped) {
      return
    }

    if (shouldFetch) {
      try {
        await this.fetch(this.repository)
      } catch (e) {
        const ghRepo = this.repository.gitHubRepository
        const repoName =
          ghRepo !== null ? ghRepo.fullName : this.repository.name

        log.error(`Error performing periodic fetch for '${repoName}'`, e)
      }
    }

    if (this.stopped) {
      return
    }

    const interval = await this.getFetchInterval(repository)
    if (this.stopped) {
      return
    }

    this.timeoutHandle = window.setTimeout(
      () => this.performAndScheduleFetch(repository),
      interval
    )
  }
