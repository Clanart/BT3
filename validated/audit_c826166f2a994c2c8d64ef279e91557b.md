### Title
`ReceivedOutput::read` accepts outputs whose `script_pubkey` is not Taproot, causing a guaranteed panic (DoS) when the output is later keyed - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput::read` performs no validation that the decoded `TxOut`'s `script_pubkey` is a pay-to-Taproot script matching the serialized scalar `offset`. The only consumer-side key derivation, `Output::key()`, asserts `script.is_p2tr()` and unconditionally unwraps the script's last instruction. Any `ReceivedOutput` encoding a non-P2TR `TxOut` deserializes successfully and then panics the process on first use — the same bug class as the hookshot report: a missing check on accepted data producing a crash.

### Finding Description
`ReceivedOutput::read` decodes three fields and returns `Ok` unconditionally:

```rust
// networks/bitcoin/src/wallet/mod.rs:122-134
pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
  let offset = Secp256k1::read_F(r)?;
  let output;
  let outpoint;
  {
    let mut buf_r = BufReader::with_capacity(0, r);
    output =
      TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
    outpoint =
      OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
  }
  Ok(ReceivedOutput { offset, output, outpoint })
}
```

There is no check that `output.script_pubkey` is P2TR, that it equals `p2tr_script_buf(key + offset*G)`, or even that the script is well-formed for key extraction. `scan_transaction` (mod.rs:199-214) only ever constructs `ReceivedOutput`s from `scripts` registered as P2TR, so the invariant is enforced on the scan path but silently assumed on the deserialization path.

The decoded value is then consumed by `Output::key()`:

```rust
// processor/src/networks/bitcoin.rs:112-122
fn key(&self) -> ProjectivePoint {
  let script = &self.output.output().script_pubkey;
  assert!(script.is_p2tr());
  let Instruction::PushBytes(key) = script.instructions_minimal().last().unwrap().unwrap() else {
    panic!("last item in v1 Taproot script wasn't bytes")
  };
  let key = XOnlyPublicKey::from_slice(key.as_ref())
    .expect("last item in v1 Taproot script wasn't x-only public key");
  Secp256k1::read_G(&mut key.public_key(Parity::Even).serialize().as_slice()).unwrap() -
    (ProjectivePoint::GENERATOR * self.output.offset())
}
```

`assert!(script.is_p2tr())` fires for any deserialized `ReceivedOutput` carrying a non-Taproot `script_pubkey` (e.g. OP_TRUE, P2PKH, or an arbitrary script). Because `ReceivedOutput::read` is reachable through `Output::read` (processor/src/networks/bitcoin.rs:145-166), which is in turn invoked by `Plan::read`/`PlanFromScanning::read` whenever stored or peer-delivered bytes are decoded, the malformed output only needs to be fed to `ReceivedOutput::read` once; every subsequent `key()` call on it aborts the thread.

### Impact Explanation
A single malformed `ReceivedOutput` — accepted cleanly by the reader — causes an unconditional panic when the output's spend key is derived. This permanently poisons any plan or DB entry containing it: re-reading or re-processing it crashes again, mirroring the hookshot crash-on-restart DoS. The validator/processor hosting the code halts on the input, taking down signing progress for the affected multisig until the entry is manually removed.

### Likelihood Explanation
Reachability requires untrusted bytes to reach `ReceivedOutput::read`, which the scope explicitly enumerates as an attacker-controlled entry point. The exploit is trivial to construct: a canonical scalar, a `TxOut` with any non-P2TR `script_pubkey`, and any `OutPoint` encode successfully — no hash grinding, no threshold collusion, and no privileged position is needed to craft the bytes. The panic is deterministic, not probabilistic.

### Recommendation
Validate in `ReceivedOutput::read` that `output.script_pubkey` is P2TR and, where the base group key is known, that it equals `p2tr_script_buf(key + GENERATOR * offset)`. At minimum, reject non-P2TR scripts at deserialization (`Err(io::Error::other("non-Taproot output"))`) so the invariant `key()` assumes is established at the trust boundary instead of asserted at the point of use.

### Proof of Concept
```rust
use bitcoin::{
  Amount, OutPoint, ScriptBuf, TxOut, Txid, hashes::Hash,
  consensus::encode::serialize,
};
use k256::Scalar;
use serai_bitcoin::wallet::ReceivedOutput;

// Build a ReceivedOutput whose TxOut is OP_TRUE, not P2TR
let offset = Scalar::ONE;
let output = TxOut {
  value: Amount::from_sat(100_000),
  script_pubkey: ScriptBuf::new_op_return(&[]), // any non-P2TR script
};
let outpoint = OutPoint::new(Txid::all_zeros(), 0);

let mut bytes = offset.to_bytes().to_vec();
bytes.extend(serialize(&output));
bytes.extend(serialize(&outpoint));

// Deserialization succeeds — the missing check
let recv = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();

// Wrapping it in processor's Output and calling .key() hits
// `assert!(script.is_p2tr())` at processor/src/networks/bitcoin.rs:114
// -> thread panic, every time the entry is reloaded.
```

Note: the panic site (`Output::key`) lives in the processor crate; the missing validation — the actual defect — is in the in-scope `ReceivedOutput::read`. If the processor is considered strictly out of scope for impact, the same gap still means `read` admits outputs `SignableTransaction::multisig`/`p2tr_script_buf` can never bind to a key, i.e. funds "received" that are unspendable — but the clean, demonstrated consequence is the guaranteed panic above.
