### Title
Uncaught TypeError in `CommitMentionLinkFilter.getRefFromComparePath` from a crafted compare link inside remotely-sourced markdown - (File: `app/src/lib/markdown-filters/commit-mention-link-filter.ts`)

### Summary
`getRefFromComparePath` splits an attacker-controlled URL path fragment on `'...'` and only validates the *upper* bound of the resulting array (`shas.length > 2`), never the lower bound. If the path does not contain the `...` separator, `shas` has length 1 and `shas[1]` is `undefined`, so the subsequent `shas[1].indexOf('/')` throws a `TypeError`. This mirrors the reported bug class exactly: an externally-configurable "schedule"/array length is trusted without checking it is within the expected bounds before indexing into it.

### Finding Description
`CommitMentionLinkFilter` is registered in the repository-aware markdown filter pipeline used to render commit, PR, and issue body/comment content fetched from the GitHub API (`app/src/lib/markdown-filters/node-filter.ts:69-90`, wired into `SandboxedMarkdownParser` in `app/src/ui/lib/sandboxed-markdown.tsx:342-382`).

The filter scans anchor elements whose `href` matches `commitMentionUrl` (`app/src/lib/markdown-filters/commit-mention-link-filter.ts:67-80`) — a regex without `^$` anchors that only needs to find a `.../compare/<7-40 hex chars>` (or `.../compare/<digits>/commits/<hex>`) substring somewhere in the URL, and `\b` terminates the match on any non-word boundary such as `/`. Because of this, an href like:

```
https://github.com/owner/repo/compare/abcdef1234567/anything
```

still satisfies `commitMentionUrl.test()`.

`filter()` then derives `path` from `url.pathname` and calls `getRefFromComparePath(path)`:

```
app/src/lib/markdown-filters/commit-mention-link-filter.ts:200-224
const shas = range.split('...')
if (shas.length > 2) {
  return null
}

const slashIndex = shas[1].indexOf('/')   // shas[1] can be undefined
```

`range` is captured by `comparePath = /^compare\/(?<range>.+)$/` (line 55), i.e., "everything after `compare/`" with no requirement that it contain `...`. When the href/text is `.../compare/abcdef1234567/anything`, `range` = `"abcdef1234567/anything"`, `range.split('...')` yields a single-element array, and `shas[1]` is `undefined`. Calling `.indexOf('/')` on `undefined` throws a `TypeError`, which is never caught anywhere in the call chain (`filter()` → `applyFilters()` in `sandboxed-markdown.tsx:342-382`, no try/catch around `nodeFilter.filter(node)`).

This is the same broken-invariant pattern as the `AaveDistributionManager.configureAssets` bug: an externally supplied array/length (`emissionSchedule` there, `shas` here) is only bounds-checked on one side (`> DISTRIBUTION_DURATION` / `> 2`) and then indexed without verifying it actually has the minimum required elements, leading to an out-of-bounds/undefined access.

### Impact Explanation
The corrupted value is the `shas` array produced from attacker-supplied markdown link text/href (sourced from a commit message, PR/issue body, or comment retrieved via the GitHub API for a repository the user has cloned or is viewing). Triggering the exception aborts the `applyFilters` loop for that markdown document mid-way, meaning the remaining node filters in the pipe (e.g. `VideoTagFilter`, `VideoLinkFilter`, and any filters ordered after `CommitMentionLinkFilter`) are skipped for that render pass. This produces incorrect/unfiltered rendering of the markdown shown to the user (e.g. unresolved mention text, unconverted video links) rather than a hard app crash, since the exception occurs inside a promise chain from `nodeFilter.filter(node)` inside `applyFilters`, which itself is invoked without a surrounding try/catch, so it will surface as an unhandled promise rejection in that renderer context.

I was not able to confirm from local code whether this unhandled rejection escalates beyond a broken/partial render of the specific content (e.g., whether it destabilizes the sandboxed iframe or the wider renderer process) — that would need to be verified by exercising the actual Electron renderer at runtime.

### Likelihood Explanation
High: the trigger requires only that the attacker control commit/PR/issue text that Desktop renders as markdown for a repository the victim has open — e.g., a commit message in a cloned repository, or a PR/issue/comment body fetched via the API — containing a link whose visible text equals its href and matches `.../compare/<hex>/<anything>`. No git/GitHub validation step in the existing filters checks for the presence of `...` before this code path runs, and the only existing guard (`shas.length > 2`) does not protect against this malformed input.

### Recommendation
Add an explicit lower-bound check before indexing:
```ts
const shas = range.split('...')
if (shas.length !== 2) {
  return null
}
```
This ensures `shas[0]` and `shas[1]` are always defined before any `.indexOf`/`.slice` calls, matching the same fix pattern recommended for `AaveDistributionManager.configureAssets` (validate array length matches the exact expected shape before use).

### Proof of Concept
1. In a repository, produce (via commit message, PR body, or issue/comment body fetched from the GitHub API) a markdown-rendered link where the visible text equals the href and the href matches:
   ```
   https://github.com/<owner>/<repo>/compare/abcdef1234567/x
   ```
   (a valid 7+ char hex "sha" immediately after `compare/`, followed by `/` and arbitrary text, but with no `...` anywhere in the path).
2. When Desktop renders this content through `SandboxedMarkdownParser` (e.g., viewing the commit/PR/issue in the app), `buildCustomMarkDownNodeFilterPipe` runs `CommitMentionLinkFilter.filter()` on the matched anchor.
3. `getRefFromComparePath` computes `range = "abcdef1234567/x"`, `shas = ["abcdef1234567/x"]` (length 1, passes the `> 2` check), and then executes `shas[1].indexOf('/')`, throwing `TypeError: Cannot read properties of undefined (reading 'indexOf')`.
4. The exception propagates out of the `filter` pipeline, causing an unhandled rejection and skipping/breaking the remainder of the markdown filtering for that node/document. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)

  private getRefFromComparePath(path: string) {
    const match = path.match(this.comparePath)
    if (match === null || match.groups === undefined) {
      return null
    }

    const { range } = match.groups

    if (/\.(diff|path)$/.test(range)) {
      return null
    }

    const shas = range.split('...')
    if (shas.length > 2) {
      return null
    }

    const slashIndex = shas[1].indexOf('/')
    const secondSha = slashIndex >= 0 ? shas[1].slice(0, slashIndex) : shas[1]

    return {
      ref: `${this.trimCommitSha(shas[0])}...${this.trimCommitSha(secondSha)}`,
      filepathToAppend: slashIndex >= 0 ? shas[1].slice(slashIndex) : undefined,
    }
  }

  private async applyFilters(doc: Document) {
    const { emoji, repository, markdownContext } = this.props
    const filters = buildCustomMarkDownNodeFilterPipe({
      emoji,
      repository,
      markdownContext,
    })

    for (const nodeFilter of filters) {
      let docMutated = false
      const walker = nodeFilter.createFilterTreeWalker(doc)

      let node = walker.nextNode()
      while (node !== null) {
        const replacementNodes = await nodeFilter.filter(node)

        if (this.currentDocument !== doc) {
          // Abort, the document has changed
          return
        }

        const currentNode = node
        node = walker.nextNode()

        if (replacementNodes === null) {
          continue
        }

        docMutated = true

        for (const replacementNode of replacementNodes) {
          currentNode.parentNode?.insertBefore(replacementNode, currentNode)
        }
        currentNode.parentNode?.removeChild(currentNode)
      }

      if (docMutated) {
        this.refreshHeight()
      }
    }
  }
