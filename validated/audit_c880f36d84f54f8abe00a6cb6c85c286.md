### Title
Gasless swap transactions (`swapForGas`) accept an unbounded, self-declared `minAmountOut` with no market-price floor, enabling auction-bidder sandwich extraction against gasless users - (File: `kaiax/gasless/impl/tx_pool.go`)

### Summary
The KIP-247 gasless-swap flow lets a transaction sender fully control the `minAmountOut` slippage parameter of `swapForGas`, and the tx-pool only enforces that `minAmountOut >= amountRepay` plus a floor on `amountIn` — never a ceiling tied to the real market price. Because the underlying swap executes against a live DEX pool inside `GaslessSwapRouter`, and the KIP-249 auction module lets any bidder buy the right to insert a transaction immediately after a chosen target transaction, an auction bidder can construct the back-run half of a sandwich around a pending `GaslessSwapTx`, extracting value from the victim exactly as described in the referenced report (attacker controls a swap-adjacent slippage/price parameter that is never checked against a real oracle price).

### Finding Description
`GaslessModule.checkBalanceForSwap` is the only protocol-level guard on the swap parameters of a gasless swap transaction: [1](#0-0) 

It only verifies:
1. `minAmountOut >= amountRepay` (so the repay leg is covered), and
2. `amountIn >= GetAmountIn(token, minAmountOut)` computed against the *current* spot price of the DEX pool referenced by `GaslessSwapRouter`.

Neither check bounds `minAmountOut` from above relative to the token's fair/oracle price — the value is entirely user (transaction signer)-supplied: [2](#0-1) [3](#0-2) 

The actual on-chain swap is performed by `GaslessSwapRouter.swapForGas(token, amountIn, minAmountOut, amountRepay, deadline)`, which routes the trade through the token's registered DEX (`getDEXInfo`) — a live AMM pool subject to price impact: [4](#0-3) 

Separately, the KIP-249 auction module explicitly grants any bidder ("Auctioneer"-submitted winning bid) the ability to have a transaction executed *immediately after* an arbitrary target transaction of their choosing: [5](#0-4) 

and the block-builder enforces this adjacency by construction: [6](#0-5) 

Combining these two facts: an attacker can (a) observe a pending `GaslessSwapTx` in the mempool with a `minAmountOut` that only guarantees repayment coverage, not fair-price protection, (b) submit a normal higher-priority transaction that trades against the same pool right before the target to move the price, and (c) win the KIP-249 auction slot to have their own transaction executed immediately after the target swap to reverse the price move and capture the difference — a textbook sandwich, exactly analogous to the cited `AutoPxGmx.compound` finding where a caller-controlled swap parameter with no oracle-anchored floor/ceiling enabled sandwiching. Just as in the original report, the root cause is the same: the module accepts a caller-supplied slippage bound that is checked only against an internal, manipulable spot-price call (`GetAmountIn`) rather than an external price oracle.

### Impact Explanation
A successful sandwich against a `GaslessSwapTx` directly extracts value from the gasless user's token balance during the swap leg of the transaction (the user receives less WKAIA/token than fair value, while the sandwicher profits from the price round-trip). Since `GaslessSwapRouter` handles real user funds and the swap is a required, automatically-bundled step of every gasless transaction (per `kaiax/gasless/impl/builder.go`), this constitutes concrete unauthorized value movement out of end users on every gasless swap that uses a thin-margin `minAmountOut` (which the reference test itself uses only a 1% margin, illustrating a realistic user configuration): [7](#0-6) 

### Likelihood Explanation
Likelihood is Medium: it requires (1) a pending `GaslessSwapTx` with insufficient slippage margin, (2) a monitoring bot/auction bidder willing to front-run via ordinary transaction submission, and (3) winning the KIP-249 auction slot targeting that swap tx. All three actions are available to any unprivileged auction bidder or public RPC caller, and the auction protocol is explicitly designed to let a bidder attach to any target transaction, removing the need for validator/proposer collusion.

### Recommendation
- Require `minAmountOut` be validated against an on-chain price oracle (or a bounded deviation from a TWAP) rather than solely against `amountRepay`/spot `GetAmountIn`, similar to the original report's recommendation of using a price oracle to compute a safe `amountOutMinimum`.
- Alternatively, restrict eligible DEX pools/tokens for `GaslessSwapRouter` to sufficiently liquid, allow-listed pools and enforce a maximum acceptable slippage percentage at the contract level (not merely a repay floor).
- Consider disallowing auction bids that target a `GaslessSwapTx`'s hash directly, or require gasless swaps and their surrounding bids to be atomically bundled/simulated for price-impact bounds before acceptance.

### Proof of Concept
1. User submits a valid `GaslessApproveTx` + `GaslessSwapTx` pair with `minAmountOut` set only slightly above `amountRepay` (default wallet behavior, e.g., 1% margin as in `tests/gasless_test.go`).
2. Attacker observes the pending `GaslessSwapTx` and submits a same-block, higher-fee transaction that swaps into the same DEX pool used by `GaslessSwapRouter.getDEXInfo(token)`, moving the price against the pending swap.
3. Attacker submits a winning KIP-249 bid via `auction_submitBid` targeting the `GaslessSwapTx` hash, so their reversing transaction is bundled immediately after it (`kaiax/auction/impl/builder.go` `ExtractTxBundles`).
4. Block is built: front-run tx → GaslessSwapTx (executes at worse price, but still passes `checkBalanceForSwap` because that only checks the repay floor) → attacker's bid tx reverses the price and captures the spread.
5. The gasless user receives less value than fair market price for their swap; attacker profits from the sandwich, with no protocol-level check having prevented it.

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

func (a *AuctionModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	bundles := []*builder.Bundle{}
	curBlock := a.Chain.CurrentBlock()
	if curBlock == nil || atomic.LoadUint32(&a.bidPool.running) == 0 {
		return bundles
	}

	miningBlock := curBlock.NumberU64() + 1
	bidTargetMap := a.bidPool.GetTargetTxMap(miningBlock)
	if len(bidTargetMap) == 0 {
		return bundles
	}

	for _, tx := range txs {
		txHash := tx.Hash()
		bid, ok := bidTargetMap[txHash]
		if !ok {
			continue
		}
		b := builder.NewBundle(
			builder.NewTxOrGenList(a.GetBidTxGenerator(tx, bid)),
			txHash,
			true,
		)
