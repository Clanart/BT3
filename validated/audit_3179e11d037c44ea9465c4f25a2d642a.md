### Title
Giga executor pre-charges EVM gas fee against the shared block cache-store before validation completes, causing a double gas-fee debit on V2 fallback - ([File: app/app.go])

### Summary
`executeEVMTxWithGigaExecutor` debits the sender's gas fee via `stateDB.SubBalance` *before* the transaction is actually executed and validated to completion. If the giga path subsequently aborts (self-destruct, EIP-7623 floor-gas failure, etc.) and the caller falls back to re-running the same transaction through the V2 ante-handler pipeline, the fee is charged a second time, because the first debit was never rolled back.

### Finding Description
In `ProcessTxsSynchronousGiga`, a single `CacheMultiStore` (`ms`) is created once for the whole block and is only written to the parent store via a single deferred `ms.Write()` at function exit: [1](#0-0) 

For each EVM transaction, `executeEVMTxWithGigaExecutor` builds a `stateDB` bound to this shared `ctx`/`ms`, and immediately pre-charges the gas fee via `stateDB.SubBalance`, which writes directly through `BankKeeper.SubUnlockedCoins`/`SubWei` into the shared cache store — *before* `ExecuteTransactionFeeCharged` runs and before any of the later abort checks (self-destruct, execution failure) are evaluated: [2](#0-1) 

The bank-store writes performed inside `SubBalance` go through the *regular* (non-giga) `ctx.KVStore()`/`ms`, whereas only the isolated “giga” KV layer is explicitly discarded/committed via `WriteGiga()`: [3](#0-2) 

`stateDB.Cleanup()` (deferred at the top of `executeEVMTxWithGigaExecutor`) only tears down the stateDB's own transient journal/tempState; it does not — and, based on the comment at lines 1959‑1961, is explicitly *not intended to* — revert bank-keeper mutations already applied to `ctx`'s real store: [4](#0-3) [5](#0-4) 

When `execErr` is one of the "abort" classes, the caller re-executes the *same* transaction bytes through the full V2 `DeliverTxWithResult` path, which independently runs the ante handler and charges/collects the gas fee again through the normal fee-deduction flow, then commits the result via `ms.Write()` at the outer level: [6](#0-5) 

Because the block-level `ms` is never rolled back between the giga attempt and the V2 fallback attempt (only a single deferred `ms.Write()` exists for the entire block), the sender's earlier giga-side `SubBalance` debit and the V2 ante handler's fee debit both land in the same cache-store and both get persisted at block commit. This mirrors the `scratchpad` bug class: ownership/effect of a resource (the fee balance mutation) is duplicated across two code paths that both assume they are the sole owner of applying it, and an "unwind" (the giga abort/fallback) does not undo the first application before the second one runs.

### Impact Explanation
This causes concrete, permanent fund loss for the affected transaction sender: the same gas fee is deducted from their account twice for a single transaction, with no compensating refund. Because this occurs during ordinary `DeliverTx`/block processing (not a malicious actor path — any transaction that legitimately triggers one of the giga-abort conditions such as self-destruct or the EIP-7623 floor-gas check can trigger it), it is reachable by an ordinary EVM transaction sender. It also risks state/AppHash divergence between giga-enabled and non-giga-enabled nodes, since fee accounting differs depending on whether a node hit the giga path or not, potentially contributing to consensus/halting issues on mixed fleets (the code comments themselves reference `LastResultsHash`/`AppHash` divergence risk, e.g. CON‑368).

### Likelihood Explanation
The abort paths that trigger fallback (`ErrSelfDestructUnsupported`, `ErrExecutionFailed` from EIP-7623 floor-gas checks, `ErrBalanceMigrationRequired`, `ErrValidationFailed`) are all reachable through normal, unprivileged EVM transaction construction (e.g., a contract that self-destructs, or a transaction crafted to fail the floor-data-gas check) — no special privileges are required, only that the Giga executor path is enabled (`GigaExecutorEnabled`/`EnableOCC` synchronous-giga mode). This makes the likelihood of triggering the double-charge moderate-to-high in any deployment running the giga executor.

### Recommendation
Ensure the gas-fee pre-charge performed in `executeEVMTxWithGigaExecutor` is isolated to a per-transaction cache/branch (e.g., via `ctx.CacheContext()` or an explicit undo/journal entry) that is discarded whenever the function returns a fallback/abort error, mirroring how `stateDB.Cleanup()` already discards the giga-only state. Alternatively, defer the fee charge until after all abort conditions (`AnySelfDestructed`, `execErr` checks) have been evaluated, or explicitly reverse the `SubBalance` fee debit before returning any error that triggers a V2 re-run.

### Proof of Concept
Conceptual reproduction (cannot be executed without the full runtime, but derivable directly from the code path):
1. Enable the giga synchronous/OCC executor (`GigaExecutorEnabled=true`) so `ProcessTxsSynchronousGiga` is used for block processing.
2. Submit an EVM transaction that giga will accept validation for (passes `validateGigaEVMTx`, is associated, doesn't need SetCode authority association) but that ultimately triggers a giga-abort condition post-execution, e.g., a transaction whose target contract self-destructs (`stateDB.AnySelfDestructed()` becomes true) or one that fails the EIP-7623 floor-data-gas check (`execErr != nil` at line 1954).
3. Observe that `stateDB.SubBalance(sender, gasFee, ...)` at line 1934 already committed a fee debit into the shared block `ms` cache.
4. Observe `executeEVMTxWithGigaExecutor` returns `(nil, gigaprecompiles.ErrSelfDestructUnsupported)` / `(nil, gigautils.ErrExecutionFailed)`.
5. `ProcessTxsSynchronousGiga` detects `gigautils.ShouldExecutionAbort(execErr)` and re-runs the same tx via `app.DeliverTxWithResult`, which performs its own independent fee charge through the standard ante handler.
6. At block commit (`ms.Write()`), both fee debits are persisted — the sender's account balance is reduced by roughly 2x the intended gas fee for a single transaction.
