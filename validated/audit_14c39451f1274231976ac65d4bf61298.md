### Title
Spoofed `WWW-Authenticate` header from a malicious git remote can make Desktop treat an untrusted host as a trusted "GitHub Enterprise" endpoint - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
The underlying bug class in the Solidity report is: a lookup that fails to find a real match silently falls back to a value that the code treats as a legitimate, trusted special case (`assetIndex_ == 0` defaulting to the hardcoded, trusted USDC index). The GitHub Desktop analog is `getEndpointKind` in the git-credential trampoline: it classifies an unknown remote host as `'enterprise'` (a trusted, first‑party GitHub kind) based on an **attacker-controlled** signal — the `WWW-Authenticate` header that git forwards from the remote/proxy response — without any independent verification of the host at that point in the check order.

### Finding Description
`getEndpointKind` decides whether a credential request is for `'github.com'`, `'ghe.com'`, `'enterprise'`, or `'generic'`: [1](#0-0) 

The comment itself states the header is attacker-influenceable: *"When Git attempts to authenticate with a host it captures any WWW-Authenticate headers and forwards them to the credential helper. We use them as a happy-path to determine if the host is a GitHub host without having to resort to making a request ourselves."* If `v.includes('realm="GitHub"')` the function immediately returns `'enterprise'` — no hostname allow-list, no TLS/cert check, no call to `isGitHubHost`. A malicious git server (or a MITM proxy sitting on an HTTP(S) remote/proxy path) fully controls the HTTP response headers it sends back to git, and can simply emit `WWW-Authenticate: Basic realm="GitHub"` for any arbitrary hostname to force this "happy path" to trigger before the real network probe (`isGitHubHost`) at the bottom of the function is ever reached: [2](#0-1) 

This is structurally the same flaw as the Solidity bug: a value that should require positive proof of trust (real index registration / real verification that the host runs GitHub Enterprise) is instead derived from a cheap, attacker-forgeable shortcut, and downstream code trusts the resulting classification as if it had been properly validated.

Downstream, `getCredential` uses this classification to decide whether to prompt the user to sign in to GitHub for that endpoint: [3](#0-2) 

If `endpointKind !== 'generic'` and no existing account matches the (attacker) endpoint, Desktop calls `ui.promptForGitHubSignIn(endpoint)`, which ultimately builds an OAuth authorize URL directly from the untrusted endpoint string via `getHTMLURL`/`getOAuthAuthorizationURL`: [4](#0-3) 

Because `endpoint` here is derived from the attacker-controlled remote/proxy URL (not validated against a known GitHub host), the OAuth `client_id`/`scope`/redirect flow is initiated against a host that the user has no reason to distrust ("GitHub Enterprise sign-in"), when in fact it was only classified that way because of a forged header.

### Impact Explanation
An attacker who runs (or MITMs) a git remote can spoof the credential classification and cause Desktop to present a "sign in to GitHub Enterprise" prompt for their own domain, and drive the OAuth authorization flow toward it. This can lead to credential/token capture or misleading account-binding UI, matching the "unauthorized OAuth or account binding" / "credential exfiltration" categories called out as valid impact. This requires no local access, admin rights, or pre-existing malware — only that the user add/fetch from an attacker-controlled remote (a normal, expected Desktop workflow).

### Likelihood Explanation
Likelihood is high for triggering the classification (spoofing an HTTP response header is trivial for anyone controlling the remote endpoint), but the ultimate severity depends on user interaction with the resulting sign-in prompt. The check order in `getEndpointKind` means this forged-header shortcut is evaluated *before* the legitimate `isGitHubHost` network verification, so it isn't caught by the existing safety net — the actual network probe is the last resort, never reached once the header condition matches.

### Recommendation
Do not derive a trust classification (`'enterprise'`) solely from response headers surfaced by the remote itself. Either remove the `WWW-Authenticate` "happy path" short-circuit entirely, or require it to be corroborated by the same `isGitHubHost`/TLS-based verification used as the fallback, before allowing the classification to influence sign-in prompts or OAuth URL construction.

### Proof of Concept
1. Attacker stands up an HTTP(S) git server (or a MITM proxy in front of one) for `https://evil.example.com/some/repo.git`.
2. Victim adds this as a remote and Desktop attempts a fetch/clone requiring authentication.
3. Git captures the server's `401` response, which includes header `WWW-Authenticate: Basic realm="GitHub"`, and forwards it to the trampoline credential helper.
4. `getEndpointKind` (app/src/lib/trampoline/trampoline-credential-helper.ts:157-165) matches `realm="GitHub"` and returns `'enterprise'` without ever calling `isGitHubHost`.
5. `getCredential` sees no existing account for `evil.example.com` and calls `ui.promptForGitHubSignIn('https://evil.example.com')`, which builds a GitHub-style OAuth authorize URL rooted at the attacker's domain via `getHTMLURL`/`getOAuthAuthorizationURL` (app/src/lib/api.ts:2357-2368).

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }
