### Title
Scanner reports dust/zero-value outputs as received funds, blocking economically viable spends - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
Analogous to the lending protocol counting 1-wei collateral as "active" and thereby blocking deficit reporting, `Scanner::scan_transaction` counts *any* transaction output paying to a registered script as a received output, regardless of value — including 1-sat dust that costs more to spend than it is worth. `SignableTransaction::new` then consumes those `ReceivedOutput`s as inputs without any economic-value check, so dust can be forced into transactions, inflating the required fee and producing unspendable or under-funded transactions.

### Finding Description
`Scanner::scan_transaction` matches only on `output.script_pubkey` and pushes a `ReceivedOutput` for every match, with no minimum-value (dust) filter:

```rust
if let Some(offset) = self.scripts.get(&output.script_pubkey) {
  res.push(ReceivedOutput { offset: *offset, output: output.clone(), outpoint: ... });
}
``` [1](#0-0) 

The same applies to `scan_block`, which just iterates transactions. [2](#0-1) 

On the spending side, `SignableTransaction::new` rejects dust *payments* (`*amount < DUST` → `DustPayment`) but never checks whether an *input* `ReceivedOutput` is below the dust threshold or below the marginal fee cost of spending it (~68+ vbytes per Taproot key-spend input at `fee_per_vbyte`). [3](#0-2) 

Fee accounting sums all input values into `input_sat` and sizes the transaction with all inputs, so each dust input adds ~67.5 vbytes of weight but negligible value:

```rust
let input_sat = inputs.iter().map(|input| input.output.value.to_sat()).sum::<u64>();
``` [4](#0-3) [5](#0-4) 

The wallet crate itself defines `DUST = 546` but only enforces it on payment outputs and the change output — never on scanned inputs. [6](#0-5) 

### Impact Explanation
- An unprivileged party can send arbitrarily many sub-dust outputs (1 sat, or even a 0-value output, which is consensus-valid) to the publicly known P2TR address of a registered key or offset. The scanner reports these as `ReceivedOutput`s — funds "received" that are not economically spendable, since spending a 1-sat input costs ~135+ sats in fees at 2 sat/vB.
- If a caller feeds scanned outputs into `SignableTransaction::new` (the natural flow, as in `test_send`), dust inputs inflate `needed_fee` and tx weight while contributing almost nothing to `input_sat`, which can flip an otherwise-fundable transaction into `NotEnoughFunds` — a griefing DoS mirroring the report's "dust legs block the transition".
- If dust is spent, the fee paid exceeds the dust value, i.e., net value loss; if accumulated, many dust inputs can push weight past `MAX_STANDARD_TX_WEIGHT`, making the UTXO set unspendable in a single transaction.

### Likelihood Explanation
Sending dust to a taproot address requires only the key/script, which is public on-chain once used, and costs the attacker only the dust value plus their own fees — cheap and repeatable. Anyone scanning with this `Scanner` and spending via `SignableTransaction` hits the path automatically. Severity is Medium: real DoS/loss of spendability, but bounded by the attacker's dust spend and recoverable by manually filtering inputs.

### Recommendation
Filter outputs by a minimum value in `Scanner::scan_transaction` (e.g., `output.value.to_sat() >= DUST`), mirroring the report's "treat collateral below a dust threshold as inactive" recommendation. Additionally, `SignableTransaction::new` should skip or reject inputs whose value is below the marginal fee cost of spending them (`fee_per_vbyte` × per-input vbytes), so dust can never force fee inflation or unspendable input sets.

### Proof of Concept
```rust
// Attacker knows the multisig's P2TR script (public after first receive).
let mut scanner = Scanner::new(key).unwrap();
let dust_addr = p2tr_script_buf(key).unwrap();

// Attacker broadcasts a tx with a 1-sat (or 0-sat) output to dust_addr.
// Scanner reports it as a received output:
let outputs = scanner.scan_transaction(&attacker_tx);
assert_eq!(outputs.len(), 1);
assert_eq!(outputs[0].value(), 1); // reported as received, not spendable

// Spending flow includes it; each input costs ~67.5 vb * fee_per_vbyte,
// exceeding its 1-sat value; sufficient dust inputs cause
// NotEnoughFunds or TooLargeTransaction.
let res = SignableTransaction::new(dust_outputs, &payments, change, None, 2);
// => Err(NotEnoughFunds) or a transaction whose fee exceeds input value
```

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
```
