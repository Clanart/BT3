## Title
Overbroad `github.` hostname regex in `isGitHubHost` lets an attacker-controlled git remote host be misclassified as GitHub, triggering the credential-helper's GitHub sign-in flow against that host - (File: `app/src/lib/api.ts`)

### Summary
`isGitHubHost()` decides whether an unknown git remote should be treated as a first-party/GitHub-Enterprise host. One of its heuristics is a bare substring-style regex, `/(^|\.)(github)\./`, which matches any hostname whose first label is literally `github` followed by a dot — e.g. `github.attacker.example`, `github.evil.io`, or even a self-hosted `github.local`. This function feeds directly into the git credential-helper's endpoint classification (`getEndpointKind` in `app/src/lib/trampoline/trampoline-credential-helper.ts`), which decides whether to prompt the user for a GitHub sign-in against that remote's origin.

### Finding Description
`isGitHubHost(url)` in [1](#0-0)  is documented as a "best-effort" GitHub host detector. After ruling out `dotcom`/`GHE` and known third-party hosts, it applies:

```
// github.example.com,
if (/(^|\.)(github)\./.test(hostname)) {
  return true
}
```

This regex only checks that a label equal to `github` is followed by a dot somewhere in the hostname — it does not anchor to a real GHE naming convention, does not require `github.com` as a suffix, and does not validate a TLS certificate or any cryptographic identity. Any hostname an attacker controls and names to start (or contain a label) with `github.` — such as `github.attacker.com` used as a git remote (`https://github.attacker.com/foo.git`) — satisfies this check and is classified as `isGitHubHost === true` before any network round trip is attempted.

This function is consumed by `getEndpointKind()` in [2](#0-1) , which is invoked by Git's credential helper flow whenever git needs auth for a remote (clone, fetch, push). If the WWW-Authenticate-based heuristics don't already classify the host, `isGitHubHost(endpoint)` is called; a `true` result marks the endpoint `'enterprise'`. Then in `getCredential()` [3](#0-2) , if no account already exists for that (attacker) endpoint, Desktop calls `ui.promptForGitHubSignIn(endpoint)` [4](#0-3) , which routes into the Enterprise sign-in flow bound to the attacker's origin and opens a sign-in dialog whose `credentialHelperUrl` is the attacker's URL.

The upstream trigger requires no privileged access: cloning or fetching from (or simply configuring) an attacker-named remote such as `https://github.attacker.example/x.git` is enough to reach this code path, matching the "attacker controls a git remote" threat model.

### Impact Explanation
A user who clones/fetches from a maliciously-named host is steered into GitHub Desktop's native "sign in to GitHub Enterprise" dialog, pre-populated for the attacker's domain, instead of a generic-credential prompt or an outright rejection. This lends false legitimacy (GitHub Desktop's own official sign-in UI) to a host that is not actually GitHub-affiliated, materially increasing the odds a user completes a GitHub OAuth/PAT sign-in flow that is now bound to (`setSignInEndpoint`) the attacker's origin, priming subsequent credential storage/lookup (`findGitHubTrampolineAccount`, keyed by endpoint origin) to be associated with that attacker-controlled endpoint. This is analogous to the report's theme — a broken/incorrect classification constant/threshold silently loosens a security-relevant gate (here, "is this really GitHub" identity classification) which downstream logic trusts without further verification.

### Likelihood Explanation
Likelihood is moderate: it requires the victim to add or open a repository whose remote hostname contains a `github.` label (easy for an attacker to register, e.g. `github.<attacker-domain>`), and it still surfaces a sign-in dialog rather than silently exfiltrating a token outright — the user must actively complete sign-in. This is not "unprompted" in the sense of zero user interaction, but it doesn't require any unnatural steps beyond normal clone/fetch/push and clicking through a dialog that Desktop itself presents as trustworthy, so it doesn't rise to social-engineering-only status the same way a raw phishing link would.

### Recommendation
Remove the loose substring heuristic or replace it with a strict allow-list/suffix check (e.g., require the endpoint to match a configured GHE domain, or drop this heuristic and rely solely on the `x-github-request-id` HEAD-probe confirmation already implemented later in the same function). At minimum, anchor the regex to validate a proper right-hand-side domain component (e.g. `hostname.endsWith('.github.com')`/exact known-enterprise domains) instead of matching an arbitrary `github.` label appearing anywhere in the hostname.

### Proof of Concept
1. Register/control a domain such as `github.attacker.example` and stand up a normal git server on it (no need to spoof `x-github-request-id`).
2. In GitHub Desktop, clone or add remote `https://github.attacker.example/repo.git`.
3. When Git requests credentials, the trampoline credential helper calls `getEndpointKind()` → `isGitHubHost('https://github.attacker.example')`.
4. `isDotCom`/`isGHE`/`isKnownThirdPartyHost` all return false, but `/(^|\.)(github)\./.test('github.attacker.example')` returns `true` because the hostname begins with the label `github.` — `isGitHubHost` short-circuits to `true` without ever reaching the certificate/`x-github-request-id` verification step.
5. `getEndpointKind` returns `'enterprise'`; since no account exists for `https://api.attacker.example/...`, `getCredential()` calls `ui.promptForGitHubSignIn('https://github.attacker.example')`, which shows Desktop's native GitHub sign-in dialog bound to the attacker's host. /**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
