### Title
Unbounded per-denom balance migration during EVM address association can be forced into an expensive, gas-unmetered loop by dust-token spam - (File: `utils/helpers/associate.go`, `x/evm/ante/preprocess.go`, `sei-cosmos/x/bank/keeper/send.go`)

### Summary
`EVMPreprocessDecorator.AnteHandle` runs `AssociationHelper.MigrateBalance` for every first-time EVM sender, which fetches **all** denominations held by the sender's un-associated "cast" address via `bankKeeper.SpendableCoins` and then sweeps them with `SendCoins`. Both operations loop over the full list of coin denominations held by that address with no upper bound, and — critically — this entire migration path executes under an **infinite gas meter** that the ante handler installs just before calling it. An attacker can pre-fund a victim's cast address with dust from an unbounded number of distinct denominations (e.g., permissionlessly created `tokenfactory` denoms, or many IBC denoms) before the victim ever sends an EVM transaction. When the victim eventually submits any EVM tx, the resulting association/migration step must iterate and transfer every one of those attacker-planted denominations, with cost proportional to the attacker-chosen list length and with no gas metering to cap it. This mirrors the reported bug class (`processYield()`/`distributeYield()` looping unboundedly over an attacker-inflatable list of reward tokens), but is worse here because the loop is gas-unmetered, so it cannot even revert cleanly on out-of-gas — it simply consumes real wall-clock CPU time proportional to attacker input.

### Finding Description
- `EVMPreprocessDecorator.AnteHandle` installs an infinite gas meter (`ctx = ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx))`) and then, for any sender who is not yet associated, calls `associateHelper.AssociateAddresses(...)`, which in turn calls `MigrateBalance`. [1](#0-0) 

- `MigrateBalance` fetches the entire coin set of the cast address with `p.bankKeeper.SpendableCoins(ctx, castAddr)` (unbounded over all denoms the address holds) and then calls `SendCoins` on that full set. [2](#0-1) 

- `SpendableCoins`/`GetAllBalances` are backed by `IterateAccountBalances`, which iterates every balance entry stored for the address with no cap. [3](#0-2) 

- The subsequent `SendCoins` call loops per-coin through `SubUnlockedCoins`/`AddCoins`, each doing a store read/write per denom. [4](#0-3) 

- `EVMAddressDecorator` performs the same unbounded `MigrateBalance` call for every Cosmos-signed tx signer that becomes associated for the first time, providing a second unprivileged trigger path. [5](#0-4) 

Because this executes under an infinite gas meter (set specifically so "EVM handles gas checking from within"), the number of denominations processed is not bounded by any gas limit — the cost scales purely with how many distinct denoms an attacker chooses to dust the victim's cast address with. `tokenfactory` denom creation is permissionless and inexpensive, so an attacker can create a very large number of unique denoms and airdrop 1 unit of each to the victim's cast address ahead of time.

### Impact Explanation
When the victim eventually submits a normal EVM (or Cosmos) transaction, the ante-handler-triggered migration must read and transfer every attacker-planted denomination in a single, unmetered pass. With a sufficiently large attacker-chosen denom count, this single ante-handler step can consume enough CPU/store I/O to materially delay block production for that transaction (potentially beyond the 2.5-second target), since it runs synchronously in the ante pipeline before the EVM ever gets a chance to meter gas. This is a block-delay / validator-liveness risk directly attributable to an unprivileged actor's ability to inflate a per-account "extra list" (denominations) that a state-changing routine must unconditionally process, closely analogous to the referenced `processYield()`/`distributeYield()` finding.

### Likelihood Explanation
Likelihood is moderate: it requires (1) permissionless creation of many token denominations (available via `tokenfactory`, or reuse of existing many-denom IBC assets) and (2) sending dust of each to a target's un-associated EVM cast address, both of which are ordinary, low-privilege, low-cost bank/tokenfactory operations reachable by any user. The attack does not require any special timing beyond acting before the victim's first EVM transaction/association.

### Recommendation
Bound the number of denominations processed by `MigrateBalance`/`AssociateAddresses` (e.g., cap or paginate `SpendableCoins` iteration with an explicit offset/length as recommended in the original report, or apply real gas metering to this specific step instead of running it under an infinite gas meter), and/or reject/queue migrations for accounts holding an excessive number of distinct denominations rather than processing them unconditionally inline in the ante handler.

### Proof of Concept
1. Attacker creates `N` distinct `tokenfactory` denoms (permissionless, one-time creation fee each).
2. Attacker sends `1` unit of each of the `N` denoms to `sdk.AccAddress(victimEvmAddr[:])` (the victim's un-associated "cast" address), which requires no special permission.
3. Victim later submits any ordinary EVM transaction. `EVMPreprocessDecorator.AnteHandle` detects the sender is unassociated and calls `AssociateAddresses` → `MigrateBalance`, which calls `SpendableCoins` (iterates all `N` balance entries) then `SendCoins` (iterates and moves all `N` denoms) — all under an infinite gas meter.
4. As `N` grows, this ante-handler step consumes CPU/store-I/O time proportional to `N`, with no gas-based upper bound, delaying processing of the block containing the victim's transaction.

func (p *EVMPreprocessDecorator) AnteHandle(ctx sdk.Context, tx sdk.Tx, simulate bool, next sdk.AnteHandler) (sdk.Context, error) {
	msg := evmtypes.MustGetEVMTransactionMessage(tx)
	if err := Preprocess(ctx, msg, p.evmKeeper.ChainID(ctx), p.evmKeeper.EthBlockTestConfig.Enabled); err != nil {
		return ctx, err
	}

	// use infinite gas meter for EVM transaction because EVM handles gas checking from within
	ctx = ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx))

	derived := msg.Derived
	seiAddr := derived.SenderSeiAddr
	evmAddr := derived.SenderEVMAddr
	ctx.EventManager().EmitEvent(sdk.NewEvent(evmtypes.EventTypeSigner,
		sdk.NewAttribute(evmtypes.AttributeKeyEvmAddress, evmAddr.Hex()),
		sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, seiAddr.String())))
	pubkey := derived.PubKey
	isAssociateTx := derived.IsAssociate
	associateHelper := helpers.NewAssociationHelper(p.evmKeeper, p.evmKeeper.BankKeeper(), p.accountKeeper)
	_, isAssociated := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if isAssociateTx && isAssociated {
		return ctx, sdkerrors.Wrap(sdkerrors.ErrInvalidRequest, "account already has association set")
	} else if isAssociateTx {
		// check if the account has enough balance (without charging)
		if !p.IsAccountBalancePositive(ctx, seiAddr, evmAddr) {
			assocErr := evmtypes.NewAssociationMissingErr(seiAddr.String())
			evmAnteMetrics.associationError.Add(ctx.Context(), 1, otelmetric.WithAttributes(attribute.String("scenario", "associate_tx_insufficient_funds"), attribute.String("type", assocErr.AddressType())))
			return ctx, sdkerrors.Wrap(sdkerrors.ErrInsufficientFunds, "account needs to have at least 1 wei to force association")
		}
		if err := associateHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false); err != nil {
			return ctx, err
		}

		return ctx.WithPriority(antedecorators.EVMAssociatePriority), nil // short-circuit without calling next
	} else if isAssociated {
		// noop; for readability
	} else {
		// not associatedTx and not already associated
		if err := associateHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false); err != nil {
			return ctx, err
		}

func (p *EVMAddressDecorator) AnteHandle(ctx sdk.Context, tx sdk.Tx, simulate bool, next sdk.AnteHandler) (sdk.Context, error) {
	sigTx, ok := tx.(authsigning.SigVerifiableTx)
	if !ok {
		return ctx, sdkerrors.Wrap(sdkerrors.ErrTxDecode, "invalid tx type")
	}
	signers := sigTx.GetSigners()
	for _, signer := range signers {
		if evmAddr, associated := p.evmKeeper.GetEVMAddress(ctx, signer); associated {
			ctx.EventManager().EmitEvent(sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeyEvmAddress, evmAddr.Hex()),
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		acc := p.accountKeeper.GetAccount(ctx, signer)
		if acc.GetPubKey() == nil {
			logger.Error("missing pubkey for signer", "signer", signer)
			ctx.EventManager().EmitEvent(sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		pk, err := btcec.ParsePubKey(acc.GetPubKey().Bytes())
		if err != nil {
			logger.Debug("failed to parse pubkey for account, likely due to the fact that it isn't on secp256k1 curve", "account", acc.GetPubKey(), "err", err)
			ctx.EventManager().EmitEvent(sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		evmAddr, err := helpers.PubkeyToEVMAddress(pk.SerializeUncompressed())
		if err != nil {
			logger.Error("failed to get EVM address from pubkey", "err", err)
			ctx.EventManager().EmitEvent(sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		ctx.EventManager().EmitEvent(sdk.NewEvent(evmtypes.EventTypeSigner,
			sdk.NewAttribute(evmtypes.AttributeKeyEvmAddress, evmAddr.Hex()),
			sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
		p.evmKeeper.SetAddressMapping(ctx, signer, evmAddr)
		associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.evmKeeper.BankKeeper(), p.accountKeeper)
		if err := associationHelper.MigrateBalance(ctx, evmAddr, signer, false); err != nil {
			logger.Error("failed to migrate EVM address balance", "address", evmAddr, "err", err)
			return ctx, err
		}
	}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}

// GetAllBalances returns all the account balances for the given account address.
func (k BaseViewKeeper) GetAllBalances(ctx sdk.Context, addr sdk.AccAddress) sdk.Coins {
	balances := sdk.NewCoins()
	k.IterateAccountBalances(ctx, addr, func(balance sdk.Coin) bool {
		balances = append(balances, balance)
		return false
	})

	return balances.Sort()
}

// AddCoins increase the addr balance by the given amt. Fails if the provided amt is invalid.
// It emits a coin received event.
func (k BaseSendKeeper) AddCoins(ctx sdk.Context, addr sdk.AccAddress, amt sdk.Coins, checkNeg bool) error {
	if !k.CanSendTo(ctx, addr) {
		return sdkerrors.ErrInvalidRecipient
	}
	if !amt.IsValid() {
		return sdkerrors.Wrap(sdkerrors.ErrInvalidCoins, amt.String())
	}

	for _, coin := range amt {
		balance := k.GetBalance(ctx, addr, coin.Denom)
		newBalance := balance.Add(coin)

		err := k.setBalance(ctx, addr, newBalance, checkNeg)
		if err != nil {
			return err
		}
	}
