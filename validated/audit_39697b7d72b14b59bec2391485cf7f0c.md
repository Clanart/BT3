### Title
Honest operator's collateral burnable via malleation of unsigned Payout-tx OP_RETURN under SIGHASH_SINGLE|ANYONECANPAY - (File: core/src/verifier.rs, core/src/builder/transaction/operator_reimburse.rs)

### Summary
The user's withdrawal signature (`TapSighashType::SinglePlusAnyoneCanPay`) only commits to the payout tx's single input and the output at index 0 (the user's payout output); the anchor output (index 1) and the OP_RETURN output carrying the operator's x-only pubkey (index 2) are never signed by anyone. Any unprivileged party who observes the operator's broadcast-but-unconfirmed Payout tx can rebroadcast a fee-bumped variant that keeps the signed input and output 0 intact but replaces the OP_RETURN with garbage, causing `update_finalized_payouts` to record `operator_xonly_pk = NULL` for that withdrawal even though the correct operator genuinely fronted it. `Verifier::is_kickoff_malicious` then treats this NULL as an unconditional "assume malicious" signal and triggers a Challenge against the honest operator.

### Finding Description
The broken binding: `Verifier::is_kickoff_malicious` implicitly claims `operator_xonly_pk_opt == None ⟺ operator deviated`. In reality, `operator_xonly_pk_opt` is derived from unauthenticated transaction metadata that any third party can rewrite.

`create_payout_txhandler` builds the Payout tx with three outputs: output 0 = user payout, output 1 = anchor, output 2 = OP_RETURN(operator_xonly_pk) [1](#0-0) . The only signature over this transaction is the user's, using `TapSighashType::SinglePlusAnyoneCanPay`, enforced in `parse_withdrawal_sig_params` [2](#0-1)  and verified in `Operator::withdraw` against `sighash = payout_txhandler.calculate_sighash_txin(0, ...)` [3](#0-2) .

Per BIP341/the codebase's own sighash-encoding logic, `AnyoneCanPay` means only the specific signed input (its outpoint/value/scriptPubKey/sequence) is committed, and `Single` means only the output at the signed input's index (index 0) is committed — outputs at other indices are excluded entirely: [4](#0-3) . Consequently, output 1 (anchor) and output 2 (OP_RETURN operator pubkey) are unauthenticated and can be freely rewritten by anyone re-signing/re-fee-bumping the same signed input, without invalidating the user's Schnorr signature.

`update_finalized_payouts` then scans the block for the tx that actually spends `withdrawal_utxo_txid/vout`, parses its OP_RETURN, and if parsing/pubkey-extraction fails, writes `operator_xonly_pk = NULL` via `update_payout_txs_and_payer_operator_xonly_pk` [5](#0-4) . `get_payout_txs_for_withdrawal_utxos` matches purely on the withdrawal outpoint being spent in that block, independent of which specific txid the operator originally constructed [6](#0-5) .

Finally, `is_kickoff_malicious` reads this via `get_payout_info_from_move_txid` and short-circuits to `Ok(true)` the moment `operator_xonly_pk_opt` is `None`, without any cryptographic proof that the operator (rather than a third party mutating unsigned outputs) caused the anomaly [7](#0-6) . `handle_kickoff` then queues a Challenge tx against the operator's kickoff [8](#0-7) , dispatched from the round/kickoff state machine's `CheckIfKickoffMalicious` duty [9](#0-8) .

No existing guard rejects this: `Verifier::is_deposit_valid`/`SECP.verify_schnorr` only validate the user's signature over the withdrawal amount/destination, never the OP_RETURN metadata; there is no operator signature over the Payout tx at all.

### Impact Explanation
An honest operator that genuinely and correctly fronted a withdrawal (paid the exact registered amount to the exact registered script pubkey at output 0) can have its Challenge/Disprove/ChallengeNACK sequence triggered purely because an unrelated party mutated the unsigned OP_RETURN/anchor outputs of the still-unconfirmed Payout transaction before it was mined. This satisfies the "Critical: an honest operator's collateral burned" category. The attack requires no special privileges — it only requires observing the mempool (or even just knowing the withdrawal_utxo, output script/amount, and the user's signature, which are visible once the operator broadcasts) and constructing a competing, fee-bumped transaction. It is repeatable per withdrawal/operator, since it only depends on the structural lack of authentication over outputs 1 and 2 of every Payout tx, not on any per-deposit secret.

### Likelihood Explanation
Feasibility requires: (1) the operator's Payout tx to be visible unconfirmed (normal operation, since it must propagate to be mined), (2) the transaction to use RBF-signalling sequence and BIP125-compatible fee rules so a mutated, higher-fee variant can replace it in miner mempools, and (3) the attacker to add extra fee via `AnyoneCanPay`-permitted additional inputs. The attacker only pays ordinary Bitcoin transaction fees; no bridge collateral, keys, or protocol privileges are needed. This is a structural weakness present on every Payout transaction, not a one-off timing coincidence, making it broadly repeatable across withdrawals and operators.

### Recommendation
Bind the operator's identity cryptographically to the Payout transaction instead of relying on an unauthenticated OP_RETURN output: e.g., require the operator to also sign (or have the N-of-N/verifier set co-sign) a commitment covering the OP_RETURN output, or change the sighash used for verification to cover all outputs (`AllPlusAnyoneCanPay` for the operator's own commitment, potentially via a second, operator-controlled input/signature), or record/trust the operator's identity from the operator's own submission at `withdraw()` time (already known to the DB) rather than only from OP_RETURN parsing during `update_finalized_payouts`, treating OP_RETURN as corroborating rather than authoritative when a matching operator record exists.

### Proof of Concept
`cargo test` plan (regtest, no mainnet/Citrea):
1. Set up a withdrawal (`withdrawal_utxo`, correct `output_script_pubkey`/`output_amount`) and have the honest operator call `withdraw()`, producing a valid signed Payout tx `T` (SIGHASH_SINGLE|ANYONECANPAY over input 0/output 0) with `T.output[2]` = OP_RETURN(operator_xonly_pk).
2. Before `T` confirms, construct `T'` by copying `T.input[0]` (same outpoint, witness untouched) and `T.output[0]` (unchanged), but replacing `T.output[2]`'s OP_RETURN payload with random 32 bytes, and adding an attacker-funded extra input/output for fee-bumping (permitted by `AnyoneCanPay`). Assert `T'` still passes `SECP.verify_schnorr` against the same sighash (`payout_txhandler.calculate_sighash_txin(0, SinglePlusAnyoneCanPay)`), proving the signature does not cover the mutated output.
3. Broadcast and mine `T'` instead of `T` (simulate via directly inserting `T'` into the synced block instead of `T`).
4. Run `update_finalized_payouts`; assert `get_payout_info_from_move_txid` returns `operator_xonly_pk_opt == None` for this withdrawal (left side of the binding: real payer = honest operator; right side: DB-recorded payer = None — binding broken).
5. Have the honest operator send its real Kickoff tx for this deposit; drive the state machine to dispatch `CheckIfKickoffMalicious`; assert `Verifier::is_kickoff_malicious` returns `Ok(true)` and that `handle_kickoff` queues a `Challenge` tx against the honest operator's kickoff, despite `T.output[0]`/`T'.output[0]` correctly paying the registered withdrawal.

    pub async fn get_payout_txs_for_withdrawal_utxos(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        block_id: u32,
    ) -> Result<Vec<(u32, Txid)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, TxidDB)>(
            "SELECT w.idx, bsu.spending_txid
             FROM withdrawals w
             JOIN bitcoin_syncer_spent_utxos bsu
                ON bsu.txid = w.withdrawal_utxo_txid
                AND bsu.vout = w.withdrawal_utxo_vout
             WHERE bsu.block_id = $1",
        )
        .bind(i32::try_from(block_id).wrap_err("Failed to convert block id to i32")?);

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_all)?;

        results
            .into_iter()
            .map(|(idx, txid)| {
                Ok((
                    u32::try_from(idx).wrap_err("Failed to convert withdrawal index to u32")?,
                    txid.0,
                ))
            })
            .collect()
    }
