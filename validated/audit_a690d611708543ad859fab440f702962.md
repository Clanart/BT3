## Title
Unregistered attacker can forge `operator_xonly_pk` payer-attribution in `withdrawals.payout_payer_operator_xonly_pk` via unauthenticated OP_RETURN, causing an operator to be reimbursed for a payout it never funded - (File: core/src/verifier.rs)

## Summary
`update_finalized_payouts` derives `operator_xonly_pk` solely from `parse_op_return_data` + `XOnlyPublicKey::from_slice` on the confirmed payout tx's OP_RETURN, with no check against `fetch_operator_keys`/registered operators, and no check that the bytes correspond to a wallet that actually signed/funded the tx. Because the withdrawal UTXO is spent under `SIGHASH_SINGLE|SIGHASH_ANYONECANPAY` (only input 0 and output 0 are committed), an unprivileged attacker can front-run the payout, self-fund the required output, and freely choose the OP_RETURN bytes to equal any real operator's `xonly_pk` copied from the public `OperatorKeys` gRPC response.

## Finding Description
The binding assumed by the protocol is: `withdrawals.payout_payer_operator_xonly_pk` (idx) == xonly_pk of the wallet whose funds actually left for output 0 of the confirmed `payout_tx`.

`update_finalized_payouts` [1](#0-0)  extracts `operator_xonly_pk` purely from `get_first_op_return_output` + `parse_op_return_data` + `XOnlyPublicKey::from_slice`, and commits it via `update_payout_txs_and_payer_operator_xonly_pk` [2](#0-1) . `fetch_operator_keys` is never consulted to check that the bytes correspond to a currently-registered operator, and there is no check binding the OP_RETURN bytes to any signature actually present in the transaction.

The real `payout_tx` template signs only the withdrawal input under key-spend, and its OP_RETURN with `operator_xonly_pk` is added by the honest operator without any commitment covering it in the user's signature: [3](#0-2) . Because the input UTXO's spending signature model uses `SIGHASH_SINGLE|ANYONECANPAY` (per the question's premise and consistent with `NotStored`/`KeySpend` single-input construction here), only input 0 and output 0 are covered by the user's committed signature — additional inputs (attacker-funded fees), additional outputs, and the OP_RETURN script are all attacker-controlled in a self-funded replacement transaction that still spends the exact same withdrawal UTXO.

Exploit flow:
1. Attacker observes a pending withdrawal (`withdrawal_utxo`, user signature) and a target registered operator's `xonly_pk` (fetched from the aggregator's public `OperatorKeys` gRPC).
2. Attacker constructs and broadcasts (front-running the real operator) a `payout_tx` that spends `withdrawal_utxo` with the user's signature, funds output 0 correctly from their own wallet, and places the target operator's `xonly_pk` bytes in the OP_RETURN output.
3. Once confirmed, `update_finalized_payouts` matches this attacker tx as the payout for withdrawal `idx` (matched by spent-UTXO, not payer identity) and records the target operator's `xonly_pk` as `payout_payer_operator_xonly_pk` in the DB.
4. The target operator's own automation (`PayoutCheckerTask::run_once`) queries `get_first_unhandled_payout_by_operator_xonly_pk` keyed only on `self.operator.signer.xonly_public_key` [4](#0-3) , finds this record, and proceeds to `handle_finalized_payout` → kickoff → `Reimburse` without ever checking that its own wallet produced the signed/funding input of the payout tx.
5. `is_kickoff_malicious`, the verifier-side guard that would otherwise flag a mismatched kickoff, only checks `operator_xonly_pk == kickoff_data.operator_xonly_pk` and the committed payout blockhash [5](#0-4)  — both of which trivially match because the attacker deliberately stamped the target operator's real key and the payout genuinely occurred in the recorded block. Nothing here re-derives payer identity from the actual signing wallet.
6. `Reimburse` tx spends the deposit's `MoveToVault` `DepositInMove` output to the operator's reimbursement address [6](#0-5) , releasing bridge-held collateral to the operator even though the operator never funded the withdrawal.

## Impact Explanation
This matches the listed Critical category "an operator reimbursed for a payout it never funded." The deposit's `MoveToVault` funds are released to a party (the framed operator) who did not spend anything to satisfy the withdrawal; the withdrawal was actually funded by the unprivileged attacker's own BTC. This breaks the attribution binding that `update_payout_txs_and_payer_operator_xonly_pk` is supposed to preserve, and it is repeatable per withdrawal and per targeted operator — any withdrawal not yet fronted by its intended operator is a candidate, and any currently-registered operator's public key (learnable via gRPC) can be the target.

## Likelihood Explanation
Preconditions: an operator with `automation` feature enabled that blindly trusts DB-recorded attribution (no independent check that its own wallet broadcast the payout). The attacker needs to front-run the specific withdrawal UTXO spend and pay the full withdrawal amount themselves (real BTC cost, no mainnet needed for PoC — regtest suffices), plus normal fees. No verifier/operator/aggregator privilege, TLS cert, or key share is required — only public gRPC read access to learn a target operator's `xonly_pk`, and the ability to build/sign a transaction spending a UTXO whose signature covers only input/output index 0.

## Recommendation
`update_finalized_payouts` must validate that `operator_xonly_pk` parsed from OP_RETURN corresponds to a currently-registered operator (cross-check against `fetch_operator_keys`), and — more fundamentally — the reimbursement/kickoff-acceptance logic (`is_kickoff_malicious`, `handle_finalized_payout`, `PayoutCheckerTask`) must additionally verify that the claiming operator's own signing key actually authorized/funded the payout transaction's non-committed inputs/outputs (e.g., require the operator to co-sign or independently attest broadcasting the specific `payout_txid`, rather than trusting an unauthenticated OP_RETURN byte string extracted from a transaction that anyone can shape via `SIGHASH_SINGLE|ANYONECANPAY`).

    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
            ));
        }

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())
}

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
