### Title
Cross-Session/Cross-Project Security-State Key Collision via `CLAUDE_CODE_REMOTE_SESSION_ID` - ([File: plugins/security-guidance/hooks/session_state.py])

### Summary
The `security-guidance` plugin's per-session state file (used for warning dedup, vulnerability-finding dedup, and rate limiting) is keyed by `_state_key()`, which prefers the environment variable `CLAUDE_CODE_REMOTE_SESSION_ID` over the hook-provided `session_id` whenever it is set. [1](#0-0)  This mirrors the report's bug class: a storage key that is supposed to scope state per distinct logical unit (there: per IBC channel; here: per Claude Code session/project) instead collapses onto a coarser identifier (there: `counterpartyChainId`; here: the stable remote-session id), causing state from one context to silently overwrite/mask state that should belong to another.

### Finding Description
`get_state_file()` and `get_lock_file()` both derive their path solely from `_state_key(session_id)`, and that function explicitly falls back to `CLAUDE_CODE_REMOTE_SESSION_ID` when present, discarding the hook's own `session_id` entirely: [1](#0-0)  — with the comment noting the intent is that in CCR (Claude Code Remote) "each user turn is a new CC process with a fresh session_id; the remote session ID is stable across those restarts." That design assumption only holds if a single `CLAUDE_CODE_REMOTE_SESSION_ID` value is guaranteed to correspond to one project/workspace for its entire lifetime. There is no directory, project path, or workspace identifier folded into the key — unlike the vulnerable Solidity ledger keyed only by `counterpartyChainId` and sequence and missing a channel identifier, this key is missing any project/workspace discriminator.

All of the security-guidance dedup/rate-limit primitives share this single state bucket per key:
- `atomic_check_and_mark_warning` / `atomic_check_counter` / `atomic_check_rate_limit` (shown-warning, counter, and rolling rate-limit tracking) [2](#0-1) 
- `record_pending_warnings` / `sweep_pending_warnings`, keyed by `"<file_path>:<rule>"` with no project/repo prefix [3](#0-2) 
- The commit-review dedup path, which records new findings keyed on `(filePath, category)` and treats anything already present as "already known, skip" [4](#0-3) 

If two distinct working directories/projects are ever driven under the same `CLAUDE_CODE_REMOTE_SESSION_ID` (e.g., a remote-control session that changes project directory mid-session, or two independent background/agent processes that inherit the same remote-session env var), their security-guidance state — shown warnings, rate-limit buckets, and most importantly the vulnerability-finding dedup cache — collapses into the identical file. A relative file path like `src/index.js` or `app.py` collides trivially across unrelated repositories.

### Impact Explanation
The most severe consequence is on the commit-review vulnerability dedup logic: once a `(filePath, category)` pair has been flagged in one project's state file, a genuinely new and unrelated vulnerability with the same relative path/category in a different project sharing the same state key would be treated as `already known, skipping` and the finding would never be surfaced to the user. [5](#0-4)  This is a direct security-disclosure suppression: a real vulnerability (e.g., a hardcoded secret or command injection) in project B goes unreported because project A previously tripped the same rule on a same-named file, silently defeating the security review hook that is supposed to flag exactly this class of issue. Rate-limit and shown-warning bleed are lower severity but still cause cross-project state pollution (e.g., one project's activity exhausting the shared rolling-window quota for another project's review calls).

### Likelihood Explanation
Exploitability/triggering depends entirely on whether `CLAUDE_CODE_REMOTE_SESSION_ID` can, in practice, be shared across two distinct projects/working directories within its lifetime (e.g., a Remote Control session that switches directories, or concurrently-spawned processes inheriting the same env var). This could not be fully confirmed from the indexed code — the CHANGELOG references directory-switch handling for Remote Control sessions and project isolation fixes (e.g., "Fixed long (>200 char) project paths resolving to another project's session directory under a shared sanitized prefix" for a related but distinct component) [6](#0-5) , suggesting cross-project bleed is a recognized general risk category in this codebase, but I could not verify within the available index whether `CLAUDE_CODE_REMOTE_SESSION_ID` itself is ever reused across differing project directories in a single remote-control lifetime. Given the index size limits noted for this codebase, the full definition/lifecycle of `CLAUDE_CODE_REMOTE_SESSION_ID` outside this plugin was not retrievable, so likelihood cannot be conclusively rated without a live Devin session to trace where this variable is set and whether it survives a `/cd`-style project change.

### Recommendation
Fold a stable project/workspace discriminator (e.g., a hash of the working directory or `CLAUDE_PROJECT_DIR`) into `_state_key()` alongside `CLAUDE_CODE_REMOTE_SESSION_ID`, so state for different projects can never collapse into the same file even when the remote session id persists across a directory change. Additionally, scope the commit-review dedup key (`filePath`, `category`) to include the project root so identical relative paths in different repositories cannot suppress each other's findings.

### Proof of Concept
Not independently reproducible from the indexed files alone (the mechanism that sets/propagates `CLAUDE_CODE_REMOTE_SESSION_ID` across directory changes lives outside the `security-guidance` plugin and was not available in the index). Conceptually:
1. Start a Remote Control / CCR session in project A with `CLAUDE_CODE_REMOTE_SESSION_ID=X` set; trigger a commit-review finding on `src/index.js` for category `hardcoded-secret`, recorded into `security_warnings_state_X.json`.
2. Switch the same remote session to project B (different repo, unrelated `src/index.js` with a different, unrelated hardcoded-secret finding) while `CLAUDE_CODE_REMOTE_SESSION_ID` remains `X`.
3. The dedup check in `_dedup_against_state`/`handle_commit_review_posttooluse` sees `(src/index.js, hardcoded-secret)` already in `previous_findings` from project A and drops project B's new, unrelated finding as "already known," per [4](#0-3) , silently suppressing the security warning in project B.

def _state_key(session_id):
    # In CCR each user turn is a new CC process with a fresh session_id; the
    # remote session ID is stable across those restarts. Prefer it so the
    # pending-warnings sweep and any unprocessed touched_paths survive.
    key = os.environ.get("CLAUDE_CODE_REMOTE_SESSION_ID") or session_id
    # The key becomes a filename component under the state dir. CC session ids
    # are UUIDs (sanitization is a no-op for them), but nothing in the hook
    # protocol guarantees that, so strip path separators and anything else
    # that could escape the state dir, and bound the length.
    return re.sub(r"[^A-Za-z0-9._-]", "_", str(key))[:128]

def atomic_check_and_mark_warning(session_id, warning_key):
    """
    Atomically check if a warning has been shown and mark it as shown if not.
    Returns True if this is the first time seeing this warning (should show it),
    False if it was already shown (should skip it).
    """
    def _check(state):
        warnings = state["shown_warnings"]
        if warning_key in warnings:
            return False
        warnings.append(warning_key)
        return True

    result = with_locked_state(session_id, _check)
    return result if result is not None else True

def atomic_check_counter(session_id, counter_key, max_count):
    """
    Atomically check if a counter has reached its limit and increment if not.
    Returns True if the counter is below max_count (should proceed),
    False if it has reached or exceeded max_count (should skip).
    """
    def _check(state):
        counters = state.get("counters", {})
        current = counters.get(counter_key, 0)
        if current >= max_count:
            return False
        counters[counter_key] = current + 1
        state["counters"] = counters
        return True

    result = with_locked_state(session_id, _check)
    return result if result is not None else True

def atomic_check_rate_limit(session_id, key, max_per_window, window_s):
    """Rolling-window rate limit: allow at most `max_per_window` calls per
    `window_s` seconds, per (session_id, key).

    Returns (allowed: bool, count_in_window: int). count_in_window is the
    post-decision count (i.e., includes this call if allowed) so callers can
    emit it directly as a telemetry gauge.

    Replaces session-lifetime `atomic_check_counter` for commit-review and
    push-sweep. Telemetry showed a small but persistent share of sessions hit
    the lifetime cap, and those were multi-day persistent sessions that then
    lost coverage for many subsequent commits — not burst abusers. A rolling
    hour keeps the same cost ceiling for any 1h window while letting long
    sessions regain coverage.

    State key: rate_limits: {"<key>": [ts, ts, ...]}. Timestamps are pruned
    on every call so the list is bounded by max_per_window; no migration
    needed from the old `counters` dict — different key.
    """
    import time as _time
    now = _time.time()
    cutoff = now - window_s

    def _check(state):
        buckets = state.setdefault("rate_limits", {})
        ts_list = buckets.get(key, [])
        # Prune; tolerate non-numeric junk from a corrupted state file.
        ts_list = [t for t in ts_list if isinstance(t, (int, float)) and t > cutoff]
        if len(ts_list) >= max_per_window:
            buckets[key] = ts_list
            return False, len(ts_list)
        ts_list.append(now)
        buckets[key] = ts_list
        return True, len(ts_list)

    result = with_locked_state(session_id, _check)
    # State unavailable → fail-open (same posture as atomic_check_counter).
    return result if result is not None else (True, 0)

def record_pending_warnings(session_id, file_path, rule_names):
    """Mark file:rule pairs as pending for the Stop-hook outcome sweep."""
    def _record(state):
        pending = state.get("pending_warnings")
        if not isinstance(pending, dict):
            pending = {}
            state["pending_warnings"] = pending
        for rule in rule_names:
            pending[f"{file_path}:{rule}"] = True
    with_locked_state(session_id, _record)

def sweep_pending_warnings(session_id):
    """
    Stop-hook final sweep. Re-read every file in pending_warnings, re-check
    patterns, and return (fixed, unresolved, unresolved_mask). Clears state.
    A file that's been deleted counts as fixed — the dangerous code is gone.
    Never raises — this is telemetry and must not break the Stop hook.
    """
    def _sweep(state):
        try:
            pending = state.get("pending_warnings")
            if not isinstance(pending, dict) or not pending:
                return 0, 0, 0

            by_file = {}
            for key in pending:
                if not isinstance(key, str) or ":" not in key:
                    continue
                fp, _, rule = key.rpartition(":")
                by_file.setdefault(fp, set()).add(rule)

            unresolved = []
            fixed = 0
            for fp, rules in by_file.items():
                try:
                    with open(fp, "r", errors="replace") as f:
                        still_matching = {r for r, _ in check_patterns(fp, f.read())}
                except (OSError, IOError):
                    still_matching = set()
                for rule in rules:
                    if rule in still_matching:
                        unresolved.append(rule)
                    else:
                        fixed += 1

            state["pending_warnings"] = {}
            # Filter to known rules so a renamed/removed rule in old state
            # doesn't KeyError rule_names_to_mask.
            known = [r for r in unresolved if r in _RULE_NAME_TO_ID]
            return fixed, len(unresolved), rule_names_to_mask(known)
        except Exception as e:
            debug_log(f"sweep_pending_warnings failed: {e}")
            return 0, 0, 0

    result = with_locked_state(session_id, _sweep)
    return result if result is not None else (0, 0, 0)
