## Finding

### Title
Out-of-bounds buffer read due to missing bound-checking when parsing CLVM atom length-prefixes in `is_atom_canonical()` - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_atom_canonical()` and its caller `is_clvm_canonical()` in [1](#0-0)  parse the variable-length CLVM atom-length prefix of a submitted spend bundle's puzzle reveal/solution bytes without ever checking that `offset` stays within the bounds of `clvm_buffer` before indexing into it. This mirrors the CVE-2019-1789 bug class: a length-prefixed/packed binary format parser walks attacker-controlled bytes using a multi-byte header (Aspack length fields in ClamAV vs. the 1–6 byte CLVM atom length-prefix here) and advances an offset/counter based on that header without validating it against the remaining buffer size, producing an out-of-bounds read.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads `b = clvm_buffer[offset]` and, depending on the high bits of `b`, determines `prefix_len` (0 to 5 extra bytes) for the CLVM atom length encoding: [1](#0-0) 

It then loops `prefix_len` times, incrementing `offset` and reading `clvm_buffer[offset]` each iteration — with **no check that `offset` is still `< len(clvm_buffer)`**:
```
atom_len = b & mask
for i in range(prefix_len):
    atom_len <<= 8
    offset += 1
    atom_len |= clvm_buffer[offset]
```
Its caller, `is_clvm_canonical()`, also indexes `clvm_buffer[offset]` in a loop and calls `is_atom_canonical()` for any high-bit-set atom byte, similarly advancing `offset` by the returned (unchecked) atom length before verifying the running offset against the buffer length only at the very end of the loop: [2](#0-1) 

If a crafted, submitted puzzle-reveal/solution buffer ends with a truncated multi-byte length-prefix atom (e.g., the last byte is `0xFC`–`0xFF`, signalling a 6-byte length field but only 0–5 bytes remain in the buffer), the loop in `is_atom_canonical()` will index past the end of `clvm_buffer`. Per the codebase's own documentation, this function is invoked on CLVM byte buffers to determine DEDUP eligibility of spends: [3](#0-2) .

### Impact Explanation
This function operates directly on bytes derived from a spend bundle submitted by an unprivileged party (the puzzle reveal/solution of a coin spend), which is exactly the trust boundary the CVE analog targets (attacker-controlled, "packed"/length-prefixed binary parsed with inadequate bounds checks). Because Python raises `IndexError` on out-of-range indexing rather than reading adjacent heap memory, the concrete manifestation here is an unhandled exception rather than memory disclosure — but it is directly reachable from crafted, mempool-submitted spend-bundle bytes and can abort the validation code path that is checking dedup/canonical-encoding eligibility for that spend. If this exception is not caught somewhere up the call stack, it could interrupt mempool-manager processing for that spend bundle (a spend-triggered processing halt), which is one of the accepted impact categories for this analog class.

### Likelihood Explanation
Likelihood is high in the sense that triggering the malformed input is trivial: an attacker only needs to submit a spend bundle whose puzzle reveal or solution program ends with a truncated variable-length atom header. The severity of the ultimate impact (crash vs. safely-caught rejection) depends on exception handling in the caller of `is_clvm_canonical()`, which I was not able to fully trace to its exact invocation site (e.g., inside `pre_validate_spendbundle()`) and whether that call is wrapped in a broad `try/except` before this analysis ran out of tool budget. This is an important open question that should be verified against the exact call site and its exception handling before treating this as a confirmed DoS.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before each indexed read (`if offset >= len(clvm_buffer): raise ValueError(...)`), and in `is_clvm_canonical()` before reading `clvm_buffer[offset]` in the main loop, mirroring the defensive length checks already used elsewhere in this codebase (e.g., `chia/full_node/full_block_utils.py`'s `skip_list`/`skip_bytes` explicitly validate `n > len(buf)` before slicing: [4](#0-3) ). Additionally, confirm/ensure that any exception from `is_clvm_canonical()` is caught and converted into a normal "non-canonical/ineligible for dedup" or "reject spend bundle" result rather than propagating as an unhandled exception in the mempool-manager thread pool.

### Proof of Concept
Construct a spend bundle whose puzzle reveal or solution CLVM buffer ends in a truncated atom-length header, e.g., a buffer whose last byte is `0xFC` (indicating a 6-byte length prefix) with fewer than 5 trailing bytes available:
```python
from chia.full_node.mempool_manager import is_clvm_canonical

# 0xFC signals a 6-byte length prefix, but buffer ends immediately after it
buf = b"\xfc"
is_clvm_canonical(buf)  # raises IndexError: index out of range, instead of a graceful rejection
```
Submitting a spend bundle whose puzzle reveal/solution bytes are engineered this way reaches this code path when the mempool manager evaluates dedup/canonical-encoding eligibility for the spend.

**Note on confidence**: I was unable to fully trace the exact call site invoking `is_clvm_canonical()` (its wrapping exception handling) within the remaining tool budget, so I cannot definitively confirm whether this always results in a full processing halt versus a caught/logged rejection. This should be verified directly against `pre_validate_spendbundle()` and its callers before relying on this as a confirmed DoS.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

## Canonical serialization

**Location**: `mempool_manager.py:185`

### `is_clvm_canonical(clvm_buffer)`

Checks that a CLVM program uses shortest-form atom encoding:

- No unnecessary length prefix bytes
- No back-references (`0xFE` byte)
- No trailing garbage

### When enforced

Required for DEDUP-eligible spends. Without canonical form, identical
solutions could have different serializations, breaking dedup.

### `is_atom_canonical(clvm_buffer, offset)`

Validates a single atom's length prefix encoding. The CLVM format uses
variable-length prefixes (1-6 bytes) based on atom size. Each prefix
length has a minimum atom size threshold.

def skip_list(buf: memoryview, skip_item: Callable[[memoryview], memoryview]) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"list count prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"list count {n} exceeds remaining buffer {len(buf)}")
    for _ in range(n):
        buf = skip_item(buf)
    return buf


def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
