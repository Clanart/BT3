### Title
Payout attribution derived from unauthenticated OP_RETURN allows crediting an uninvolved operator with reimbursement for a withdrawal it never funded - (File: core/src/verifier.rs)

### Summary
`update_finalized_payouts` in `core/src/verifier.rs` sets `payout_payer_operator_xonly_pk` solely from `parse_op_return_data(get_first_op_return_output(payout_tx))`, a field that is never covered by the `SinglePlusAnyoneCanPay` signature enforced on the withdrawal input. Anyone who controls the withdrawal (including the withdrawer itself, who trivially "self-funds" their own already-entitled payout) can reuse the same signature in a different transaction and stamp an arbitrary registered operator's x-only pubkey into the OP_RETURN, causing that operator's automation to later pull the full deposit amount out of the `MoveToVault` UTXO via `Reimburse` even though it never fronted anything.

### Finding Description
The broken binding, stated as an equality that must hold but does not:
`payout_payer_operator_xonly_pk` (written by `update_finalized_payouts`, read later by `PayoutCheckerTask`/`handle_finalized_payout`/`validate_payer_is_operator`) **==** the operator whose own funds actually paid the user in the mined payout transaction.

Code path:
- The withdrawal signature is required to be `TapSighashType::SinglePlusAnyoneCanPay`, enforced in `parse_withdrawal_sig_params` [1](#0-0) .
- `create_payout_txhandler` builds the payout tx with output 0 = user payment, output 1 = anchor, output 2 = OP_RETURN(operator_xonly_pk) [2](#0-1) .
- `SinglePlusAnyoneCanPay` = `SIGHASH_SINGLE|ANYONECANPAY`: it commits only to input 0 (the withdrawal UTXO) and to output 0 (the paid user output). It commits to nothing else — no other inputs, and critically not the OP_RETURN output. This is visible in the sighash computation used elsewhere in the codebase [3](#0-2) .
- On chain, `update_finalized_payouts` scans the mined payout tx, takes the *first* OP_RETURN output, and blindly trusts its content as the payer identity, with no signature or ownership check tying it to whoever actually funded the transaction [4](#0-3) .
- This value is persisted via `update_payout_txs_and_payer_operator_xonly_pk` [5](#0-4)  and later consumed by every operator's own `PayoutCheckerTask::run_once`, which queries `get_first_unhandled_payout_by_operator_xonly_pk(self.operator.signer.xonly_public_key)` and, if it matches, automatically calls `handle_finalized_payout` [6](#0-5) .
- `handle_finalized_payout` looks up an *already pre-signed* kickoff/reimburse slot for that operator via `get_unused_and_signed_kickoff_connector` [7](#0-6)  — these signatures exist for every operator that was part of the deposit's N-of-N set at deposit time, regardless of whether they ever intended to front this particular withdrawal.
- `create_reimburse_txhandler` then pays the operator's reimbursement address an amount exactly equal to the `MoveToVault` deposit output value, spent directly from the vault UTXO (`UtxoVout::DepositInMove`) [8](#0-7) . This is real deposited BTC leaving the vault, not merely a release of the operator's own collateral.

Exploit flow: the attacker is the withdrawer itself (has a legitimate Citrea `withdraw()` and thus a legitimate `SinglePlusAnyoneCanPay` signature over the withdrawal UTXO and payout output). Instead of waiting for an operator (or using the cooperative optimistic-payout path), the attacker constructs and broadcasts its own payout-shaped transaction: input = withdrawal UTXO + user signature, output 0 = itself (unchanged, as required by SIGHASH_SINGLE), any funding/fee inputs it likes, and OP_RETURN = a targeted, currently-registered, uninvolved operator's public `xonly_pk` (obtained via `GetParams`). Once mined, `update_finalized_payouts` attributes the payout to that operator, and that operator's own automation subsequently drains the deposit's `bridge_amount` from the vault to itself via kickoff → Reimburse, without ever having fronted the withdrawal.

No existing guard catches this: `SECP.verify_schnorr` in `Operator::withdraw`/`sign_optimistic_payout` only validates the *withdrawer's* signature over input+output 0, never the OP_RETURN; the bridge/disprove ZK circuit (`circuits-lib/src/bridge_circuit/mod.rs`) re-derives `operator_xonlypk` from the exact same untrusted `get_first_op_return_output`/`parse_op_return_data` call on the payout tx [9](#0-8) , so it is self-consistent with the attacker's forged attribution and cannot detect the mismatch between who paid and who is named.

### Impact Explanation
The deposit's full `bridge_amount` leaves the `MoveToVault` UTXO to an operator that never fronted the withdrawal, while the withdrawer already received its payout by self-funding the transaction — effectively doubling the value extracted for a single deposit (once to the withdrawer via self-front, once to the falsely-credited operator via `Reimburse`). This matches the listed Critical categories: "BTC leaving a move-to-vault UTXO without a matching fronted withdrawal" and "an operator reimbursed for a payout it never funded." It is also repeatable: the attack requires only a legitimate withdrawal request per exploitation and any currently-registered operator's public key as the target, so it can be repeated across every deposit/withdrawal the attacker controls. Additionally, once the fake tx confirms, `is_utxo_spent(withdrawal_utxo)` becomes true, permanently precluding any subsequent, honest fronting of that same withdrawal by a real operator.

### Likelihood Explanation
Preconditions are all attacker-controllable and cheap: a genuine deposit/withdrawal on Citrea (attacker's own funds), knowledge of the withdrawal UTXO and its own SinglePlusAnyoneCanPay signature (which the attacker creates itself when requesting withdrawal), and any registered operator's public `xonly_pk` (published via `GetParams`, no privileged access needed). Cost is limited to Bitcoin network fees for the self-funded transaction; no majority hashrate, no compromised keys, no TLS interception. Feasibility is high and requires no race against verifiers/operators since the attacker is simply broadcasting its own transaction with a forged label. The only operational dependency is that the automation for the named operator is enabled and picks up the falsely-attributed payout automatically, which is the default automation flow in this codebase.

### Recommendation
Do not derive payer attribution from an unauthenticated OP_RETURN alone. Bind the OP_RETURN commitment cryptographically to the transaction, e.g., by covering the OP_RETURN output with the withdrawal signature (drop `AnyoneCanPay`/`Single` in favor of a sighash type that commits to all outputs, or add a second, fully-committed signature/covenant proving that whoever supplied the funding inputs also authored the OP_RETURN), or require the operator's own signature over the OP_RETURN payload (e.g., an operator-provided Schnorr signature over the payout txid embedded/verified at `update_finalized_payouts` time) before crediting `payout_payer_operator_xonly_pk`.

### Proof of Concept

3. Instead of calling `operator.withdraw()`, manually build a payout-shaped transaction using `create_payout_txhandler` with the same `input_utxo`, the same `user_sig`, but `operator_xonly_pk = A.xonly_public_key` (a registered operator that never touched this withdrawal), fund extra inputs from the attacker's own wallet, and broadcast+mine it directly via `rpc.send_raw_transaction`/`rpc.mine_blocks`.
4. Wait for verifier/operator block sync to run `update_finalized_payouts`, then assert:
   - `operator_db.get_payout_info_from_move_txid(...).0 == Some(A.xonly_public_key)` (the equality check on the "before" side: expected payer should be `None`/uninvolved, but is now `A`).
   - `operator_A_db.get_first_unhandled_payout_by_operator_xonly_pk(A.xonly_public_key)` returns the withdrawal index for a payout A never authored.
5. Let A's `PayoutCheckerTask` run (or call `handle_finalized_payout` directly) and drive the kickoff/Reimburse flow to completion (as in `core/src/test/manual_reimbursement.rs`); assert the `Reimburse` tx's output pays A's reimbursement address the full deposit `bridge_amount`, while A never broadcast or funded the original payout transaction — proving the attribution equality is violated and real BTC left the vault without a matching fronted payment by A.

pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

    pub async fn get_unused_and_signed_kickoff_connector(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(RoundIndex, u32)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, i32)>(
            "WITH current_round AS (
                    SELECT round_idx
                    FROM current_round_index
                    WHERE id = 1
                )
                SELECT
                    ds.round_idx as round_idx,
                    ds.kickoff_idx as kickoff_connector_idx
                FROM deposit_signatures ds
                CROSS JOIN current_round cr
                WHERE ds.deposit_id = $1  -- Parameter for deposit_id
                    AND ds.operator_xonly_pk = $2
                    AND ds.round_idx >= cr.round_idx
                    AND NOT EXISTS (
                        SELECT 1
                        FROM used_kickoff_connectors ukc
                        WHERE ukc.round_idx = ds.round_idx
                        AND ukc.kickoff_connector_idx = ds.kickoff_idx
                    )
                ORDER BY ds.round_idx ASC
                LIMIT 1;",
        )
        .bind(i32::try_from(deposit_id).wrap_err("Failed to convert deposit id to i32")?)
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let result = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        match result {
            Some((round_idx, kickoff_connector_idx)) => Ok(Some((
                RoundIndex::from_index(
                    usize::try_from(round_idx).wrap_err("Failed to convert round idx to u32")?,
                ),
                u32::try_from(kickoff_connector_idx)
                    .wrap_err("Failed to convert kickoff connector idx to u32")?,
            ))),
            None => Ok(None),
        }
    }
