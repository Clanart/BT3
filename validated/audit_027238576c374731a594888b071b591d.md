## Title
Copilot merge-conflict resolutions are written/committed even when the diff review is suppressed as "too large" - (File: `app/src/ui/multi-commit-operation/dialog/copilot-conflicts-changes.tsx`)

### Summary
GitHub Desktop's Copilot-assisted merge/rebase/cherry-pick conflict resolution feature lets an LLM propose per-hunk resolutions, which are spliced back into the working file by `reassembleResolvedFile` [1](#0-0)  and previewed to the user through the same diff-rendering pipeline used elsewhere in the app. That pipeline silently hides any diff containing a line longer than `MaxCharactersPerLine` (or a buffer over `MaxReasonableDiffSize`), replacing it with a "diff too large to display by default" placeholder that requires an extra click to reveal [2](#0-1) [3](#0-2) . This is the same class of bug as the reported Uniswap issue: material information about what will actually be written/committed (the resolved file content) is not shown to the user by default, so they can approve an operation based on incomplete information.

### Finding Description
- `CopilotConflictsChanges` renders the AI's proposed resolution diff via `getResolutionDiff` and `SeamlessDiffSwitcher`/`Diff` [4](#0-3) .
- `getResolutionDiff` classifies the diff as `DiffType.LargeText` (not rendered by default) whenever `isDiffTooLarge` returns true, i.e. any line in the diff exceeds `MaxCharactersPerLine` [5](#0-4) .
- The `Diff` component defaults `forceShowLargeDiff` to `false` and shows only a generic placeholder ("The diff is too large to be displayed by default... performance may be negatively impacted") with a button the user must proactively click to actually see the content [6](#0-5) .
- Meanwhile, the underlying resolved content that will be written to the file/commit is *not* gated by this same guard — `reassembleResolvedFile` splices the model's `resolvedContent` for each conflict hunk directly into the file regardless of line length [7](#0-6) . There is a separate, much larger threshold (`MAX_CONFLICT_LINE_LENGTH = 5000`) that gates whether a hunk is sent to the model at all [8](#0-7) , but nothing prevents the model from *returning* a resolution containing a long, single-line/minified payload that trips the diff renderer's much smaller line-length threshold and gets hidden from review, while still being spliced into the file and applied.
- The attacker primitive: a malicious or compromised branch/PR that is merged/rebased/cherry-picked (attacker controls the "theirs" side content and commit/PR context that is fed into the LLM prompt, per `buildConflictContext`/`formatConflictContextForPrompt` [9](#0-8) ) can shape the conflicting hunk (or influence the model via prompt-injected PR/commit text) so that the resulting resolved content contains an extremely long line. That resolution is rendered as a suppressed "large diff" in the review UI by default, so the user is very unlikely to expand and inspect it, yet clicking through the conflict-resolution flow will still commit that exact content.

### Impact Explanation
If a user accepts a Copilot resolution without manually expanding the hidden "large diff" (the default UI state), attacker-influenced content that never appeared in the visible diff becomes part of the merge commit and gets pushed to the remote/shared history — a silent corruption of what the user actually reviews and commits. This matches the "Valid Impact" criteria: attacker controls a git remote/branch/PR content that another user merges, and the result is silent corruption of what gets committed/pushed, without any local/physical access, admin rights, or social engineering beyond a normal merge/rebase workflow.

### Likelihood Explanation
Medium-High. The user has to be using the (apparently in-development/fork-specific) Copilot conflict-resolution feature and have a genuine conflict against attacker-influenced content — a realistic scenario for any repo that merges external PRs or branches. The "large diff hidden by default" behavior is the existing, unconditional behavior of the diff renderer (`isDiffTooLarge`/`renderLargeTextDiff`) that applies uniformly across the app, so no special bypass is needed — it is simply not overridden for this new review surface. This is an area of the codebase (`copilot-conflict-resolution.ts`, `copilot-conflict-context.ts`, `copilot-conflicts-changes.tsx`) that appears to be recently added/fork-specific, so I could not fully trace the final "accept/continue" write path (`copilot-conflicts-dialog.tsx`, `copilot-in-memory-session-fs-provider.ts`) within the available tool budget; whether there is an additional confirmation step at commit time that surfaces full content is unconfirmed.

### Recommendation
- Do not allow the "large diff" suppression to apply to AI-generated conflict resolutions without an explicit, distinct warning (equivalent to Desktop's existing `hidden-changes-warning` pattern used in `filter-changes-list.tsx` [10](#0-9) ) so users cannot proceed to accept/commit a resolution whose diff has never been rendered.
- Align the diff-rendering line-length threshold with (or make it stricter than) `MAX_CONFLICT_LINE_LENGTH`, or force `forceShowLargeDiff = true` specifically in the Copilot resolution review flow.
- Add a blocking confirmation ("You have not reviewed N files because their diffs are too large to display — do you want to continue?") before applying any resolution whose diff was never expanded by the user.

### Proof of Concept
1. Set up a repository and create a merge/rebase conflict where the "theirs" (attacker-controlled) side of a conflicted hunk contains, or can induce the model to produce, a resolution with one extremely long line (e.g., minified/obfuscated malicious code exceeding `MaxCharactersPerLine`, but under the 5000-char `MAX_CONFLICT_LINE_LENGTH` hunk-skip gate).
2. Trigger Copilot conflict resolution in Desktop; the resolution diff for that file renders as `DiffType.LargeText` and is hidden by default per `renderLargeTextDiff` [3](#0-2) .
3. Without clicking "Show Diff", accept/continue the conflict resolution.
4. Verify (via `git show`/`git log -p`) that the hidden long-line content was written into the resolved file and included in the resulting commit exactly as returned by the model, confirming it was never actually displayed to the user before being committed.

**Note:** Given index-size limits, I was unable to fully retrieve `copilot-conflicts-dialog.tsx` and `copilot-in-memory-session-fs-provider.ts`, which contain the final accept/write logic. A Devin session with full repository access would be needed to confirm the exact commit/write call site and any additional safeguards that may already exist there.

export function reassembleResolvedFile(
  rawContent: string,
  hunkResolutions: ReadonlyArray<IHunkResolution>
): string {
  const eol = rawContent.includes('\r\n') ? '\r\n' : '\n'
  const lines = rawContent.split(/\r?\n/)
  const resultLines: Array<string> = []
  let hunkIndex = 0
  let i = 0

  while (i < lines.length) {
    if (reassemblyOursMarker.test(lines[i])) {
      // Look ahead to verify this is a well-formed conflict block:
      // must have a ======= separator and a >>>>>>> closing marker.
      let hasSeparator = false
      let closingIndex = -1
      for (let j = i + 1; j < lines.length; j++) {
        if (reassemblySeparatorMarker.test(lines[j])) {
          hasSeparator = true
        } else if (reassemblyTheirsMarker.test(lines[j])) {
          closingIndex = j
          break
        }
      }

      if (!hasSeparator || closingIndex === -1) {
        // Malformed marker — copy through as regular content
        resultLines.push(lines[i])
        i++
        continue
      }

      // Skip through the entire conflict marker block
      i = closingIndex + 1

      // Splice in the resolved content for this hunk
      if (hunkIndex < hunkResolutions.length) {
        const resolved = hunkResolutions[hunkIndex].resolvedContent
        if (resolved.length > 0) {
          resultLines.push(...resolved.split(/\r?\n/))
        }
      }
      hunkIndex++
    } else {
      resultLines.push(lines[i])
      i++
    }
  }

  return resultLines.join(eol)
}

/** Is the diff too large for us to reasonably represent? */
function isDiffTooLarge(diff: IRawDiff) {
  for (const hunk of diff.hunks) {
    for (const line of hunk.lines) {
      if (line.text.length > MaxCharactersPerLine) {
        return true
      }
    }
  }

  return false
}

export class Diff extends React.Component<IDiffProps, IDiffState> {
  public constructor(props: IDiffProps) {
    super(props)

    this.state = {
      forceShowLargeDiff: false,
    }
  }

  public render() {
    const diff = this.props.diff

    switch (diff.kind) {
      case DiffType.Text:
        return this.renderText(diff)
      case DiffType.Binary:
        return this.renderBinaryFile()
      case DiffType.Submodule:
        return this.renderSubmoduleDiff(diff)
      case DiffType.Image:
        return this.renderImage(diff)
      case DiffType.LargeText: {
        return this.state.forceShowLargeDiff
          ? this.renderLargeText(diff)
          : this.renderLargeTextDiff()
      }
      case DiffType.Unrenderable:
        return this.renderUnrenderableDiff()
      default:
        return assertNever(diff, `Unsupported diff type: ${diff}`)
    }
  }

  private renderImage(imageDiff: IImageDiff) {
    if (imageDiff.current && imageDiff.previous) {
      return (
        <ModifiedImageDiff
          onChangeDiffType={this.props.onChangeImageDiffType}
          diffType={this.props.imageDiffType}
          current={imageDiff.current}
          previous={imageDiff.previous}
        />
      )
    }

    if (
      imageDiff.current &&
      (this.props.file.status.kind === AppFileStatusKind.New ||
        this.props.file.status.kind === AppFileStatusKind.Untracked)
    ) {
      return <NewImageDiff current={imageDiff.current} />
    }

    if (
      imageDiff.previous &&
      this.props.file.status.kind === AppFileStatusKind.Deleted
    ) {
      return <DeletedImageDiff previous={imageDiff.previous} />
    }

    return null
  }

  private renderLargeTextDiff() {
    return (
      <div className="panel empty large-diff">
        <img src={NoDiffImage} className="blankslate-image" alt="" />
        <div className="description">
          <p>The diff is too large to be displayed by default.</p>
          <p>
            You can try to show it anyway, but performance may be negatively
            impacted.
          </p>
        </div>
        <Button onClick={this.showLargeDiff}>
          {__DARWIN__ ? 'Show Diff' : 'Show diff'}
        </Button>
      </div>
    )
  }

export async function buildConflictContext(
  ourLabel: string,
  theirLabel: string,
  workingDirectory: string,
  files: ReadonlyArray<{
    readonly path: string
    /** Which side deleted the file (for delete-vs-modify conflicts). */
    readonly deletedSide?: 'ours' | 'theirs'
  }>
): Promise<ICopilotConflictContext> {
  const results = await Promise.all(
    files.map(async (file): Promise<IFileConflictContext> => {
      // Delete-vs-modify conflicts have no text markers on disk. Include
      // them in the context with metadata so the model can recommend
      // keep or delete — no file content is needed.
      if (file.deletedSide !== undefined) {
        return {
          path: file.path,
          hunks: [],
          deleteConflict: { deletedSide: file.deletedSide },
        }
      }

      // Guard against path traversal and symlink escapes (cross-platform)
      let absolutePath: string | null
      try {
        absolutePath = await resolveWithin(workingDirectory, file.path)
      } catch {
        return {
          path: file.path,
          hunks: [],
          skippedReason: 'File path could not be resolved safely',
        }
      }
      if (absolutePath === null) {
        return {
          path: file.path,
          hunks: [],
          skippedReason: 'File path is outside the repository',
        }
      }

      // Guard against reading pathologically large files into memory. This is
      // a memory-safety bound only — resolvability is decided from the conflict
      // hunks below, not the whole-file size.
      try {
        const fileStat = await stat(absolutePath)
        if (fileStat.size > MAX_CONFLICT_FILE_READ_SIZE) {
          return {
            path: file.path,
            hunks: [],
            skippedReason: 'File too large to resolve automatically',
          }
        }
      } catch {
        return {
          path: file.path,
          hunks: [],
          skippedReason: 'File could not be read',
        }
      }

      let content: string
      try {
        content = await readFile(absolutePath, 'utf8')
      } catch {
        return {
          path: file.path,
          hunks: [],
          skippedReason: 'File could not be read',
        }
      }

      const hunks = extractConflictHunks(content)
      if (hunks.length === 0) {
        return {
          path: file.path,
          hunks: [],
          skippedReason: 'No conflict markers found',
        }
      }

      // Gate on the size of the conflict content we'd actually send to the
      // model, not the whole-file size.
      const hunkSkipReason = getHunkSkipReason(hunks)
      if (hunkSkipReason !== null) {
        return {
          path: file.path,
          hunks: [],
          skippedReason: hunkSkipReason,
        }
      }

      return { path: file.path, hunks, rawContent: content }
    })
  )

  return {
    ourLabel,
    theirLabel,
    files: results,
  }
}
