### Title
EVM JSON-RPC HTTP server disables DNS-rebinding host validation by hardcoding `Vhosts: []string{"*"}` - (File: evmrpc/server.go)

### Summary
`NewEVMHTTPServer` in `evmrpc/server.go` unconditionally sets `Vhosts: []string{"*"}` [1](#0-0) , which disables the virtual-host (Host-header) validation that `virtualHostHandler` is specifically designed to provide.

### Finding Description
The EVM JSON-RPC HTTP handler stack wraps requests in `newVHostHandler`, whose documented purpose is exactly the class of bug in the external report: preventing DNS rebinding attacks where an attacker-controlled DNS name is rebound to resolve to `127.0.0.1`/loopback, letting a malicious webpage's JavaScript bypass CORS and talk directly to a node's local RPC port [2](#0-1) . The handler's logic allows any request whose `Host` header parses as a literal IP, but for hostnames it only proceeds if the hostname is in the allow-list, or if `"*"` is in that allow-list [3](#0-2) .

However, `NewEVMHTTPServer`, which constructs the production EVM JSON-RPC server used by every sei-chain node, always passes `Vhosts: []string{"*"}` into `HTTPConfig` [1](#0-0) . This wildcard entry causes the vhost check at line 513-516 of `rpcstack.go` to always short-circuit and allow the request regardless of the `Host` header value [4](#0-3) . The protection mechanism exists in the code (mirroring go-ethereum's original defense against exactly this CWE-346/CWE-940 DNS-rebinding class), but it is neutralized by this hardcoded default before it ever reaches the RPC server's HTTP listener at `0.0.0.0:<HTTPPort>` [5](#0-4) [6](#0-5) .

There is no config knob wired through `evmrpcconfig.Config` to override this — `Vhosts` is not derived from any user-settable config field, only `CorsAllowedOrigins` is (`config.CORSOrigins`) [7](#0-6) . So a node operator cannot restrict this even if they wanted to, without patching the binary.

### Impact Explanation
Because CORS (`AllowedOrigins`) only affects browser-enforced same-origin restrictions and does not stop non-browser or DNS-rebinding-based access, and because the `virtualHostHandler` is the only remaining defense-in-depth layer against a browser-based attacker rebinding a hostname to the node's loopback/internal address, disabling it via `"*"` means any website visited by someone on the same host/network segment as an EVM RPC node (e.g., a validator operator's machine, or any internal service reachable at `HTTPPort`) can potentially reach the JSON-RPC endpoint by DNS rebinding a domain to that internal address, bypassing CORS entirely regardless of `config.CORSOrigins` settings. The reachable JSON-RPC surface includes wallet-adjacent methods like `eth_sendTransaction`-style send APIs (`sendAPI`), account/state queries, debug/trace APIs, etc., registered in the same `apis` list [8](#0-7) . This matches the "public EVM JSON-RPC surface" exposure explicitly listed as in-scope.

### Likelihood Explanation
Exploitation still requires a victim's browser or an internal network position to reach the node's RPC-bound address (default listens on `0.0.0.0`) and successfully DNS-rebind a domain to that address, the same precondition as the SillyTavern PoC. This is a real, reachable attack surface for any node operator exposing the EVM JSON-RPC port on `0.0.0.0` (the hardcoded `LocalAddress` default at line 28) without an additional reverse-proxy/firewall Host check in front of it.

### Recommendation
Do not hardcode `Vhosts: []string{"*"}` in `NewEVMHTTPServer`. Wire a configurable, sane-default (e.g., `localhost`, `127.0.0.1`, and any explicitly configured RPC hostnames) allow-list through `evmrpcconfig.Config`, mirroring how `CORSOrigins` is already externally configurable, so operators can restrict acceptable `Host` header values the same way go-ethereum's `--http.vhosts` flag does.

### Proof of Concept
1. Run a sei-chain node with the EVM JSON-RPC HTTP server enabled (default `LocalAddress = "0.0.0.0"`, some `HTTPPort`), reachable from a victim's LAN/host.
2. Host an attacker webpage that uses a DNS-rebinding service (per the report's PoC) to rebind an attacker-controlled domain to the node's RPC IP.
3. From the victim's browser, once rebound, issue `fetch("http://[attacker-domain]:<HTTPPort>/", {method:"POST", headers:{"content-type":"application/json"}, body: JSON.stringify({jsonrpc:"2.0",id:1,method:"eth_accounts",params:[]})})`.
4. Because `Vhosts` contains `"*"`, `virtualHostHandler.ServeHTTP` at `evmrpc/rpcstack.go` lines 512-516 passes the request straight to the underlying RPC handler regardless of the rebound `Host` header, returning EVM RPC data/allowing state-changing calls that CORS alone would have blocked in a same-origin-restricted browser context.

```go
// virtualHostHandler is a handler which validates the Host-header of incoming requests.
// Using virtual hosts can help prevent DNS rebinding attacks, where a 'random' domain name points to
// the service ip address (but without CORS headers). By verifying the targeted virtual host, we can
// ensure that it's a destination that the node operator has defined.
type virtualHostHandler struct {
	vhosts map[string]struct{}
	next   http.Handler
}

func newVHostHandler(vhosts []string, next http.Handler) http.Handler {
	vhostMap := make(map[string]struct{})
	for _, allowedHost := range vhosts {
		vhostMap[strings.ToLower(allowedHost)] = struct{}{}
	}
	return &virtualHostHandler{vhostMap, next}
}
```

```go
// ServeHTTP serves JSON-RPC requests over HTTP, implements http.Handler
func (h *virtualHostHandler) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	// if r.Host is not set, we can continue serving since a browser would set the Host header
	if r.Host == "" {
		h.next.ServeHTTP(w, r)
		return
	}
	host, _, err := net.SplitHostPort(r.Host)
	if err != nil {
		// Either invalid (too many colons) or no port specified
		host = r.Host
	}
	if ipAddr := net.ParseIP(host); ipAddr != nil {
		// It's an IP address, we can serve that
		h.next.ServeHTTP(w, r)
		return
	}
	// Not an IP address, but a hostname. Need to validate
	if _, exist := h.vhosts["*"]; exist {
		h.next.ServeHTTP(w, r)
		return
	}
	if _, exist := h.vhosts[host]; exist {
		h.next.ServeHTTP(w, r)
		return
	}
	http.Error(w, "invalid host specified", http.StatusForbidden)
}
```
