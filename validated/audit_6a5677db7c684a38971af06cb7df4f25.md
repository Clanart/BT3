### Title
Cached FROST preprocess is reused across `sign()` calls under the same context, enabling nonce reuse and secret share recovery - (File: coordinator/src/tributary/signing_protocol.rs)

### Summary
`SigningProtocol::preprocess_internal` caches a `CachedPreprocess` seed keyed by `context` in `CachedPreprocesses`, then reloads that same seed on every subsequent call without ever invalidating or rotating it. `AlgorithmSignMachine::from_cache` deterministically re-derives identical FROST nonces from the seed via `ChaCha20Rng::from_seed` + `Commitments::new`. The "checkpoint" of the nonce — marking it consumed after a signature share is produced — is missing: each `share_internal` call re-runs `preprocess_internal`, rebuilds a machine with the same nonces, and signs again. If two signing rounds under the same context differ in the preprocess set (attacker-controlled commitment bytes) or the message, the victim emits two shares with identical nonces but different binding factors/challenges, yielding a linear system that recovers the victim's secret share — the direct analog of duplicating a credited balance by transferring before a checkpoint updates the sender.

### Finding Description
In `preprocess_internal`, the seed is generated once per `context` and stored:

```rust
if CachedPreprocesses::get(self.txn, &self.context).is_none() {
  let (machine, _) = AlgorithmMachine::new(algorithm.clone(), keys.clone()).preprocess(&mut OsRng);
  ...
  CachedPreprocesses::set(self.txn, &self.context, &cache.0);
}
let cached = CachedPreprocesses::get(self.txn, &self.context).unwrap();
```

There is no `del`, no one-time-use flag, no counter — the same seed is decrypted and passed to `AlgorithmSignMachine::from_cache` on every call (lines 123–145). `from_cache` → `seeded_preprocess` derives `nonces` purely from `ChaCha20Rng::from_seed(*seed.0)` (`crypto/frost/src/sign.rs:127-132`), so the nonces are a deterministic function of the seed. `sign()` drains `self.nonces` and computes `share = sign_share(view, Rs, base + rho*actual, msg)` (`sign.rs:386-398`), but because the machine is reconstructed from the DB on each `share_internal` invocation, the drain is per-call only — the nonce "balance" is never debited globally.

`share_internal` (lines 150–181) calls `preprocess_internal` fresh each time, then `machine.sign(preprocesses, msg)` where `preprocesses` are deserialized from `HashMap<Participant, Vec<u8>>` supplied by the caller — untrusted coordinator/validator-provided bytes fed to `read_preprocess` (line 165). Both the signing set `included` and each participant's commitment bytes feed the rho transcript and the challenge (`sign.rs:325-379`), so a second call with different attacker bytes or a different `included` set produces a different `rho`/challenge while the victim's nonces stay identical.

Concrete reachable context: `DkgConfirmer` uses `context = (b"DkgConfirmer", self.attempt)` (line 275), and `share()` / `complete()` both route through `share_internal`, so `share_internal` is invoked at least twice per attempt (once for `share`, once inside `complete` at line 322). While `complete` re-uses the same inputs, any second `share()` for the same attempt — e.g., a re-driven confirmation flow receiving a different preprocess set assembled from tributary data, where a malicious validator changed their commitment bytes — re-signs with identical nonces under a different binding factor and challenge.

Math: share `z_i = d_i + e_i·ρ_i + λ_i·s_i·c`. Two shares `z_i, z_i'` with same `d_i, e_i`, different `ρ_i, c` → two equations in unknowns `d_i, e_i, s_i`; combined with the public relation of commitments, `s_i` (the victim's FROST secret share) is recoverable, identical to the ROS/nonce-reuse attack class the spec warns about (`spec/cryptography/FROST.md:51-62` explicitly states reuse "will enable a third-party to recover your private key share").

### Impact Explanation
Recovery of a validator's `Ristretto` secret share breaks the confidentiality assumption of the MuSig/FROST layer used to confirm DKG results (`set_keys_message` signatures). Combined with threshold-many compromised or replayed shares it degrades the validator-set key's security; at minimum it converts a one-time-signing assumption into full share disclosure for any validator whose context is signed under twice with differing attacker-controlled inputs.

### Likelihood Explanation
Requires the victim's `share_internal` (or `preprocess_internal`→`sign`) to execute more than once under the same `(context)` with attacker-influenced `preprocesses` or `msg`. The preprocess bytes are provided by validators through the tributary (`serialized_preprocesses` map at line 154), and `complete()` demonstrably re-invokes `share_internal`, proving the cached seed is loaded multiple times per context by design. Whether a distinct second `share()` call with divergent inputs is reachable within one attempt depends on the `handle.rs` dispatch flow, which I was unable to fully enumerate in this analysis — if the protocol guarantees exactly one share computation per context, severity drops; the structural nonce-reuse hazard remains regardless.

### Recommendation
After `machine.sign()` succeeds (or fails fatally), consume the cached seed: delete `CachedPreprocesses` for `context`, or store a monotonically increasing counter/used-flag in the DB entry and refuse to sign with a seed marked used. Alternatively, incorporate a per-signing-round unique identifier (distinct from the cache key) into the seed derivation so that even repeated loads cannot yield identical nonces.

### Proof of Concept
1. Victim validator runs `DkgConfirmer::share(preprocesses_A, key_pair)` for attempt `a`; context `(b"DkgConfirmer", a)` loads seed `S`, derives nonces `(d, e)`, emits share `z = d + e·ρ + λ·s·c`.
2. Malicious validator causes a second invocation for the same attempt with `preprocesses_B` (their commitment bytes altered, or a different included set). `preprocess_internal` reloads the same `S` → same `(d, e)`; sign computes `z' = d + e·ρ' + λ·s·c'` with `ρ ≠ ρ'`, `c ≠ c'`.
3. Attacker solves the resulting linear system (with the public commitment relation `D + ρE` known from the victim's published `Preprocess`) to recover `s`, the victim's secret share.
