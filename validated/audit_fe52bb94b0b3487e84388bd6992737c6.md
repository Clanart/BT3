### Title
Order-Independent Multisig Verification Allows Txid Malleability Without Invalidating Signatures - (File: stacks-codec/src/transaction.rs)

### Summary
`OrderIndependentMultisigSpendingCondition::verify` checks every signature field against the same, unchained `initial_sighash` and only requires `num_sigs >= signatures_required` [1](#0-0) . Because the sighash is never chained through the auth fields (unlike the sequential `MultisigSpendingCondition::verify`, which folds each signature into `cur_sighash` [2](#0-1) ), and `sign_and_append` for this variant returns the sighash unchanged after appending a signature [3](#0-2) , no signature (origin's or a sponsor's, if the sponsor signs afterward over the resulting sighash) ever commits to the exact set, order, or superset of auth fields ultimately included in the serialized transaction. Any party holding a validly-signed transaction can add/remove/reorder additional valid signature or public-key fields (when the origin's account allows more signers than the required threshold, or simply reorder fields) while keeping every signature check and the address-derivation check passing, producing a different byte-serialization and therefore a different `txid` for an otherwise identical, still-authorized transaction.

### Impact Explanation
This matches the enumerated High-impact category "a txid/sighash over different bytes than transmitted." The mempool's replace-by-fee/replace-by-nonce logic identifies "the same" pending transaction purely by `(origin_address, origin_nonce)` (or sponsor) rather than by txid [4](#0-3) , and RPC broadcast/monitoring flows key off the txid computed by the submitting client (`tx.txid()`) [5](#0-4) . A relayer or miner that mutates the auth-field ordering/superset of an order-independent-multisig transaction before it reaches the mempool or a block produces a still-valid transaction with a *different* txid than the one the origin/sponsor/client observed and is tracking, even though it spends the same nonce and has the identical economic effect. This is a divergence between the transaction identity a client/API observes and the one actually admitted/mined — the exact "txid over different bytes than transmitted" scenario called out as valid High severity.

### Likelihood Explanation
Exploitability requires only observing a broadcast, fully-signed transaction that uses `TransactionSpendingCondition::OrderIndependentMultisig` (available since Epoch 3.0, `is_supported_in_epoch` [6](#0-5) ) with either (a) more signatures/pubkeys present than `signatures_required` (oversigned, a supported and tested configuration [7](#0-6) ) or (b) a reorderable field list, and re-serializing it with the fields permuted/pruned before relaying. No private keys are needed, since all the signatures/pubkeys are already public in the observed transaction bytes; the attacker is simply a relayer or block-producer with normal network access, not any privileged/miner-collusion assumption beyond posting bytes.

### Recommendation
Bind the auth field list itself into the signature commitment for `OrderIndependentMultisigSpendingCondition` — e.g., incorporate a canonical encoding/hash of the full field set (or at least the count and ordering actually used) into the presign hash each signer signs over, or otherwise make mempool/RPC tx-identity tracking robust to any valid rearrangement (e.g., dedupe/replace by canonicalized auth content rather than solely by nonce+address) so that a semantically identical, still-authorized transaction cannot silently acquire a different txid post-broadcast.

### Proof of Concept
1. Build an origin `TransactionSpendingCondition::new_multisig_order_independent_p2sh(2, vec![pubk_1, pubk_2, pubk_3])` (2-of-3), as constructed in the existing test `tx_stacks_transaction_sign_verify_standard_order_independent_p2sh_extra_signers` [7](#0-6) .
2. Sign with all three keys against the same `initial_sig_hash` (`sign_no_append_origin`), producing `sig1, sig2, sig3`, and append all three signatures — this is a valid, fully-verifying, "oversigned" transaction with `txid = T1`.
3. Broadcast/observe `T1`. An intermediary removes one signature (e.g., `sig3`) from the fields vector, or reorders the fields, producing a new serialization.
4. Recompute `verify()`: `num_sigs` is still `>= 2 == signatures_required`, `StacksAddress::from_public_keys` over the reduced/reordered pubkey set still yields the original signer hash (since address derivation only depends on the *set* used and `signatures_required`, and the check tolerates supersets), so the mutated transaction passes `TransactionSpendingCondition::verify` and `StacksTransaction::verify_origin` with **`txid = T2 != T1`**, despite consuming the same account nonce and having identical payload/post-conditions/fee.
5. Submit `T2` to the mempool: `MemPoolDB::try_add_tx`'s lookup by `(origin_address, origin_nonce)` treats it as replacing/conflicting with any pending record of `T1` [8](#0-7) , confirming the txid the original signer/broadcaster tracked (`T1`) is no longer what ends up admitted/mined.

    pub fn verify(
        &self,
        initial_sighash: &Txid,
        cond_code: &TransactionAuthFlags,
        mode: TransactionAuthVerificationMode,
    ) -> Result<Txid, AuthError> {
        let mut pubkeys = vec![];
        let mut cur_sighash = initial_sighash.clone();
        let mut num_sigs: u16 = 0;
        let mut have_uncompressed = false;
        for field in self.fields.iter() {
            let pubkey = match field {
                TransactionAuthField::PublicKey(ref pubkey) => {
                    if !pubkey.compressed() {
                        have_uncompressed = true;
                    }
                    pubkey.clone()
                }
                TransactionAuthField::Signature(ref pubkey_encoding, ref sigbuf) => {
                    if *pubkey_encoding == TransactionPublicKeyEncoding::Uncompressed {
                        have_uncompressed = true;
                    }

                    let (pubkey, next_sighash) = TransactionSpendingCondition::next_verification(
                        &cur_sighash,
                        cond_code,
                        self.tx_fee,
                        self.nonce,
                        pubkey_encoding,
                        sigbuf,
                        mode,
                    )?;
                    cur_sighash = next_sighash;
                    num_sigs = num_sigs
                        .checked_add(1)
                        .ok_or(AuthError::VerifyingError("Too many signatures".to_string()))?;
                    pubkey
                }
            };
            pubkeys.push(pubkey);
        }

        if num_sigs != self.signatures_required {
            return Err(AuthError::VerifyingError(
                "Incorrect number of signatures".to_string(),
            ));
        }

        if have_uncompressed && self.hash_mode == MultisigHashMode::P2WSH {
            return Err(AuthError::VerifyingError(
                "Uncompressed keys are not allowed in this hash mode".to_string(),
            ));
        }

        let addr = StacksAddress::from_public_keys(
            0,
            &self.hash_mode.to_address_hash_mode(),
            self.signatures_required as usize,
            &pubkeys,
        )
        .ok_or_else(|| {
            AuthError::VerifyingError("Failed to generate address from public keys".to_string())
        })?;

        if addr.bytes() != &self.signer {
            return Err(AuthError::VerifyingError(format!(
                "Signer hash does not equal hash of public key(s): {} != {}",
                addr.bytes(),
                self.signer
            )));
        }

        Ok(cur_sighash)
    }
