## Finding

Within the Java runtime's lazy-field parsing path, `LazyFieldLite.mergeFrom(CodedInputStream, ExtensionRegistryLite)` and `LazyFieldLite.ensureInitialized()` swallow `InvalidProtocolBufferException` and silently substitute a default/empty value, with no exception propagated and no return-value signal to the caller. ### Title
Silent swallowing of parse failures in `LazyFieldLite` masks corrupted/invalid embedded messages as valid defaults - (File: `java/core/src/main/java/com/google/protobuf/LazyFieldLite.java`)

### Summary
Lido's LDO token contract returns `false` instead of reverting on an invalid transfer, letting a caller that ignores the return value believe a transfer succeeded ("false top-up"). The transferable invariant is: *a failed operation must not be observable as indistinguishable from success to a consumer that inspects only the "happy path" result*. `LazyFieldLite` (used for lazily-parsed embedded/extension message fields in Java lite-runtime messages) reproduces this pattern for Protobuf binary parsing: when the delayed bytes fail to parse (`InvalidProtocolBufferException`), the code catches the exception, discards it, and substitutes `defaultInstance`/unmodified `value` — the caller sees no exception and no distinguishing signal that the field's contents were dropped.

### Finding Description
`LazyFieldLite` stores an embedded message's bytes (`delayedBytes`) and lazily parses it into `value` on first access via `ensureInitialized`. If the attacker-controlled bytes fail to parse, the catch block sets `this.corrupted = true`, `this.value = defaultInstance`, and returns normally: [3](#0-2) 

Similarly, `mergeFrom(CodedInputStream, ExtensionRegistryLite)` and the helper `mergeValueAndBytes` catch `InvalidProtocolBufferException` from a nested/merged submessage and comment explicitly that "Nothing is logged and no exceptions are thrown. Clients will be unaware that a proto was invalid": [1](#0-0) [4](#0-3) 

The only signal of failure, the `corrupted` flag exposed via package-private `isCorrupted()`, has no caller anywhere in the production runtime — it is defined but unused outside its own file, so no generated/application code can detect that a field silently reverted to a default instance.

This differs from the standard `MessageLite.ParseFrom*`/`MergeFrom*` contract, which returns `false` or throws `InvalidProtocolBufferException` on malformed input so callers can check the boolean/`@CheckReturnValue` result or catch the exception (as documented at `message_lite.h` and exercised extensively in `message_unittest.inc`). `LazyFieldLite` deliberately bypasses that contract for a subset of embedded/extension fields.

### Impact Explanation
A consuming application that trusts a message containing a lazy/extension submessage field may believe the field was successfully parsed/merged and use the (silently substituted) default instance's semantics — e.g., treating an absent/zeroed value as "no override," "no permission," or "default amount" — while the attacker actually supplied a malformed payload that was dropped rather than rejected. Because no exception or false return is surfaced, and the internal `corrupted` flag is unreachable from application code, downstream logic cannot distinguish "field legitimately empty" from "field corrupted and dropped." This is a direct integrity-of-result analog to the LDO false top-up class: the failure is invisible to the caller inspecting only the parse outcome.

### Likelihood Explanation
Reachable via any ordinary client sending a bounded, malformed embedded/extension message inside an otherwise valid outer message that uses lazy fields (a supported, documented feature of the lite Java runtime, e.g. `MessageLiteOrBuilder` extension fields marked lazy). No privileged access or hostile schema is required — only a schema that legitimately declares a lazy or extension field and a bounded corrupted payload for that sub-field.

### Recommendation
Propagate parse failures out of `LazyFieldLite.mergeFrom` and `ensureInitialized`/`mergeValueAndBytes` (e.g., rethrow `InvalidProtocolBufferException` or expose `isCorrupted()` through a public, checked API that generated code and applications can query), rather than silently substituting a default instance. At minimum, wire the existing `corrupted` flag into a public accessor and document that callers must check it after accessing lazily-parsed fields whose bytes originated from untrusted input.

### Proof of Concept
1. Construct a schema with a message `Outer` containing an extension/lazy field of type `Inner`.
2. Serialize `Outer` with a legitimately-tagged length-delimited field for the lazy `Inner` slot, but fill its payload with bytes that fail to parse as `Inner` (e.g., a truncated/invalid varint as used in `LazyFieldLiteTest`'s corruption tests).
3. Call `Outer.parseFrom(bytes)` — parsing of `Outer` completes successfully; the lazy field lookup (`getInner()`) internally calls `ensureInitialized`, hits the catch block at lines 488–494, sets `corrupted = true` internally, and returns `Inner.getDefaultInstance()` with no exception.
4. Application code calling `outer.getInner()` observes a normal default `Inner` instance and no error signal, identical in effect to `field1.merge(field2)`/`mergeFrom` cases exercised in `LazyFieldLiteTest.java:131-198`, confirming the corrupted-but-silent-success behavior.
