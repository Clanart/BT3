Uncaught `TypeError` from unchecked `range.split('...')` length crashes markdown rendering pipeline on attacker-controlled compare links - ([File: app/src/lib/markdown-filters/commit-mention-link-filter.ts])

### Summary
`CommitMentionLinkFilter.getRefFromComparePath` splits the `compare/<range>` URL path segment on `'...'` and indexes into `shas[1]` without verifying the array actually has two elements, mirroring the reported `paths[i]` length-not-checked underflow pattern. When the range contains no `'...'`, `shas` has length 1 and `shas[1]` is `undefined`, so the subsequent `shas[1].indexOf('/')` throws a `TypeError`.

### Finding Description
`getRefFromComparePath` is reached from `filter()` for any `<a>` element whose `href === innerText` and whose href matches `commitMentionUrl`, a regex requiring only `(commit|pull|compare)/(optional pr prefix)/[0-9a-f]{7,40}\b` — it does **not** require an actual `sha1...sha2` range for the `compare` case: [1](#0-0) 

In `getRefFromComparePath`, the code only rejects when `shas.length > 2`, never checking for `shas.length < 2`: [2](#0-1) 

A link such as `https://github.com/<owner>/<repo>/compare/1234567` (a single 7-40 char hex string, no `...`) satisfies `commitMentionUrl` (the `compare` branch accepts a bare sha) but produces `range = "1234567"`, so `range.split('...')` yields `["1234567"]`. `shas[1]` is `undefined`, and `shas[1].indexOf('/')` throws.

This filter is invoked from `applyFilters` in `SandboxedMarkdown` with no per-filter try/catch around `await nodeFilter.filter(node)`: [3](#0-2) 

The markdown content rendered here (commit messages, PR/issue bodies, comments) originates from GitHub API data, which is attacker-controlled if the attacker can author a commit message, PR description, or comment in a repository the victim views in Desktop (their own repo, a fork, or a PR from an external contributor). The href/innerText pair is produced automatically by the markdown auto-linker from raw URL text pasted into the message, so the attacker only needs to include a URL string like `https://github.com/owner/repo/compare/1234567` in commit/PR/comment text — no unnatural interaction required, and no local access needed.

### Impact Explanation
The uncaught `TypeError` occurs inside `applyFilters`, an `async` method invoked from `onDocumentDOMContentLoaded` without a wrapping try/catch. This throws inside the markdown-rendering pipeline of `SandboxedMarkdown`, used to render commit summaries/bodies, PR descriptions, and comments throughout the Desktop UI. Depending on how the surrounding promise rejection is handled by Electron's renderer, this can produce an unhandled promise rejection that halts the remaining filter pipeline (subsequent filters such as `VideoTagFilter`/`VideoLinkFilter` never run) and leaves the rendered content in a partially-processed, inconsistent state, silently corrupting how commit/PR content is displayed to the user. This does not achieve code execution or sandbox escape by itself, but it is a reliable, remotely-triggerable renderer crash/rendering corruption caused by attacker-supplied repository content — consistent with the reported bug class of an unchecked array length leading to out-of-bounds/undefined access.

### Likelihood Explanation
High. No admin rights, local access, or social engineering beyond normal repository interaction (viewing a commit, PR, or comment containing the crafted URL) is required. The malformed compare URL is trivial to construct and passes the `commitMentionUrl` regex check because that regex does not require the `sha...sha` compare format, only a `compare/<hex 7-40>` prefix.

### Recommendation
In `getRefFromComparePath`, validate `shas.length === 2` (reject otherwise, matching the intent of the `compare/<sha1>...<sha2>` format) before indexing `shas[1]`, e.g.:
```ts
if (shas.length !== 2) {
  return null
}
```
Additionally, wrap the `await nodeFilter.filter(node)` call in `applyFilters` (`app/src/ui/lib/sandboxed-markdown.tsx`) in a try/catch so a single malformed filter input cannot abort the remainder of the markdown rendering pipeline.

### Proof of Concept
1. Create/receive a commit message, PR description, or PR/issue comment containing the raw URL text:
   `https://github.com/<owner>/<repo>/compare/1234567`
   (any 7–40 character hex string, no `...`).
2. GitHub's markdown auto-linker (and Desktop's rendering of the fetched markdown) will turn this into an `<a href="...">https://github.com/<owner>/<repo>/compare/1234567</a>` element where `href === innerText`.
3. Desktop renders this content via `SandboxedMarkdown`, which calls `applyFilters` → `CommitMentionLinkFilter.filter` → `getRefFromComparePath`.
4. `range.split('...')` returns `['1234567']`; `shas[1].indexOf('/')` throws `TypeError: Cannot read properties of undefined (reading 'indexOf')`, aborting the remainder of the node-filter pipeline for that render pass. [4](#0-3)

  private getRefFromComparePath(path: string) {
    const match = path.match(this.comparePath)
    if (match === null || match.groups === undefined) {
      return null
    }

    const { range } = match.groups

    if (/\.(diff|path)$/.test(range)) {
      return null
    }

    const shas = range.split('...')
    if (shas.length > 2) {
      return null
    }

    const slashIndex = shas[1].indexOf('/')
    const secondSha = slashIndex >= 0 ? shas[1].slice(0, slashIndex) : shas[1]

    return {
      ref: `${this.trimCommitSha(shas[0])}...${this.trimCommitSha(secondSha)}`,
      filepathToAppend: slashIndex >= 0 ? shas[1].slice(slashIndex) : undefined,
    }
  }
