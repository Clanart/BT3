## Analysis

The Goldilocks bug is a **stale-authorization-reuse** flaw: a per-account trust decision (`boostMagnitude`, computed from NFTs verified at grant time) is cached and re-applied on a later, related action (extending the boost) without re-validating the underlying inputs, even though those inputs were invalidated in the interim.

GitHub Desktop has the same class of bug in its "unsafe repository / dubious ownership" trust flow.

### Title
Directory-scoped "Trust Repository" exception is never revoked and is silently reused for a different, later repository occupying the same path - ([File: app/src/lib/git/config.ts])

### Summary
When Git detects a repository owned by a different user (`dubious ownership`), Desktop shows an "unsafe repository" warning and offers a **"Trust Repository"** action. Clicking it calls `addSafeDirectory(path)`, which permanently adds the literal path string to the global `safe.directory` git config entry. This exception is keyed only on **path**, is **never removed**, and is never re-validated against the identity/content of the repository actually occupying that path at the time of a later git operation.

### Finding Description
`addSafeDirectory` writes the trusted path directly into the user's global gitconfig with no expiry and no binding to repository identity (remote URL, first commit, etc.): [1](#0-0) 

It is invoked from the "unsafe repository" recovery UI, both for missing repositories and when adding an existing repository, as a one-time user action: [2](#0-1) [3](#0-2) 

The unsafe/ownership check itself (`getRepositoryType`) only inspects the *current* directory at that *path* via `git rev-parse` and Git's own dubious-ownership detection — it has no way to know, and Desktop never records, *which* repository content the user actually approved: [4](#0-3) 

Critically, when a repository is removed from Desktop (`_removeRepository`) or relocated (`_relocateRepository`), the corresponding `safe.directory` entry is **never cleaned up** — only the Desktop-local repository record is deleted/updated: [5](#0-4) 

This mirrors the `_buildBoost` bug exactly: the "magnitude" (here, the trust exception) is computed once from validated input (the directory's ownership at approval time), then carried forward and reused on every subsequent access to that key (the path), even after the underlying object it was computed from has changed or been invalidated (the directory now holds different, attacker-controlled content). There is no mechanism analogous to `adjustBoosts()`'s invalidation being honored — the trust is honored forever, and there is no "re-evaluate" step comparable to what the report recommends for NFTs.

### Impact Explanation
Once a path is trusted, Git will skip the ownership safety check for any future repository placed at that exact path — including one dropped there by a synced/shared folder (OneDrive, Dropbox, a mounted network share, a shared CI/build machine, WSL-mounted paths, or a decompressed archive from a link/download) that is owned by a different (attacker-controlled) identity. Git's own documentation calls out that adding untrusted directories to `safe.directory` "may automatically execute files in the repository" — this is precisely the warning Desktop shows the user once, but subverts by never re-showing it for future occupants of that path. This can lead to execution of attacker-supplied hooks/config (`core.fsmonitor`, `.git/hooks/*`, filters) the next time Desktop performs a git operation against that path, i.e., code execution outside the sandbox with no user-visible warning at the moment of actual exploitation.

### Likelihood Explanation
Users routinely reuse the same clone directory names/paths (e.g., a default "Projects" or company-standard checkout path, or synced folders across machines/VMs). If a user once legitimately trusted a directory (e.g., a repo on a shared drive owned by a colleague), and that same path later comes to be populated by a different, attacker-controlled repository (shared-drive takeover, restored/extracted archive, symlink swap, container/VM template reuse), Desktop will perform git operations there without ever re-prompting, since the exception is permanent and keyed only by string path.

### Recommendation
Do not treat a `safe.directory` grant as permanent/global. At minimum:
- Remove the corresponding `safe.directory` entry when the repository is removed from Desktop (`_removeRepository`) or its path changes (`_relocateRepository`).
- Bind trust to something stronger than the literal path (e.g., re-check ownership/identity — such as first-commit SHA or `.git` directory inode — at each session start) rather than relying solely on Git's path-based `safe.directory` mechanism.
- Re-surface the "unsafe repository" warning if the directory's ownership changes after a trust exception was granted, instead of relying on Git to silently suppress the check forever.

### Proof of Concept
1. User adds/clones a repository at `~/shared/project`, which happens to be on a shared/synced folder owned by another local user; Desktop shows "unsafe repository," user clicks **Trust Repository** → `addSafeDirectory('~/shared/project')` permanently whitelists that path.
2. User later removes the repository from Desktop (`_removeRepository`) — the `safe.directory` entry is not cleaned up.
3. An attacker (with access to the same shared/synced folder, e.g., a compromised collaborator, malicious sync conflict, or restored backup) replaces the directory at `~/shared/project` with a different, malicious repository containing hostile hooks/config, owned by a different user.
4. User re-adds or re-clones into the same path, or Desktop still has another repository record pointing at that path; Git's ownership check is bypassed entirely because the path is already in `safe.directory`, so Desktop performs git operations against the attacker's repository without any warning, potentially triggering hostile hooks/filters.

```typescript
/**
 * Adds a path to the `safe.directories` configuration variable if it's not
 * already present. Adding a path to `safe.directory` will cause Git to ignore
 * if the path is owner by a different user than the current.
 */
export async function addSafeDirectory(path: string) {
  // UNC-paths on Windows need to be prefixed with `%(prefix)/`, see
  // https://github.com/git-for-windows/git/commit/e394a16023cbb62784e380f70ad8a833fb960d68
  if (__WIN32__ && path[0] === '/') {
    path = `%(prefix)/${path}`
  }

  await addGlobalConfigValueIfMissing('safe.directory', path)
}
```

```typescript
export async function getRepositoryType(path: string): Promise<RepositoryType> {
  if (!(await directoryExists(path))) {
    return { kind: 'missing' }
  }

  try {
    const result = await git(
      ['rev-parse', '--is-bare-repository', '--show-cdup', '--git-dir'],
      path,
      'getRepositoryType',
      { successExitCodes: new Set([0, 128]) }
    )

    if (result.exitCode === 0) {
      // Bare repositories will not include gitdir so we handle that separately
      if (result.stdout.startsWith('true\n')) {
        return { kind: 'bare' }
      }

      // --is-bare-repository and --show-cdup each produce a single line but
      // --git-dir could theoretically contain newlines so we parse the known
      // fields first and treat the remainder as the git dir. We use [\s\S]*
      // instead of .* for the git dir capture group because .* doesn't match
      // newlines whereas [\s\S]* matches any character including newlines.
      const match = result.stdout.match(/^(true|false)\n(.*)\n([\s\S]*)\n$/)

      if (match) {
        const [, isBare, cdup, gitDir] = match

        return isBare === 'true'
          ? { kind: 'bare' }
          : {
              kind: 'regular',
              topLevelWorkingDirectory: resolve(path, cdup),
              gitDir: resolve(path, gitDir),
            }
      }
    }

    const unsafeMatch =
      /fatal: detected dubious ownership in repository at '(.+)'/.exec(
        result.stderr
      )
    if (unsafeMatch) {
      return { kind: 'unsafe', path: unsafeMatch[1] }
    }

    return { kind: 'missing' }
```

```typescript
  public async _relocateRepository(repository: Repository): Promise<void> {
    const path = await showOpenDialog({ properties: ['openDirectory'] })

    if (path === null) {
      return
    }

    const rt = await getRepositoryType(path)

    if (rt.kind === 'regular') {
      // The repository has moved, so any main worktree we recorded before now
      // points at where it used to be. Resolve it again from the new location.
      await this.repositoriesStore.updateRepositoryPath(
        repository,
        rt.topLevelWorkingDirectory,
        rt.gitDir,
        await this.findMainWorktreePath(rt.topLevelWorkingDirectory)
      )
    } else if (rt.kind === 'unsafe') {
      // Git refuses to run in a repository it considers unsafe, so there's no
      // resolving the main worktree here. Drop the recorded path rather than
      // keep one we know is stale.
      await this.repositoriesStore.updateRepositoryPath(
        repository,
        path,
        undefined,
        undefined,
        true
      )
    } else {
      this.emitError(new Error(this.getInvalidRepoPathsMessage([path])))
    }
  }

  public async _removeRepository(
    repository: Repository | CloningRepository,
    moveToTrash: boolean
  ): Promise<void> {
    try {
      if (moveToTrash) {
        try {
          await shell.moveItemToTrash(repository.path)
        } catch (error) {
          log.error('Failed moving repository to trash', error)

          this.emitError(
            new Error(
              `Failed to move the repository directory to ${TrashNameLabel}.\n\nA common reason for this is that the directory or one of its files is open in another program.`
            )
          )
          return
        }
      }

      if (repository instanceof CloningRepository) {
        this._removeCloningRepository(repository)
      } else {
        await this.repositoriesStore.removeRepository(repository)
      }
    } catch (err) {
      this.emitError(err)
      return
    }

    const allRepositories = await this.repositoriesStore.getAll()
    if (allRepositories.length === 0) {
      this._closeFoldout(FoldoutType.Repository)
    } else {
      this._showFoldout({ type: FoldoutType.Repository })
    }
  }
```
