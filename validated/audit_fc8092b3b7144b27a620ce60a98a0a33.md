## Title
Unvalidated deep-link PR checkout silently fetches and checks out attacker-controlled fork content into an already-trusted repository - (File: `app/src/ui/dispatcher/dispatcher.ts`)

### Summary
The `x-github-client://openRepo/...?pr=N` deep-link handler resolves a PR number supplied entirely by the link, matches it against an already-open, trusted local repository purely by comparing clone URLs, and then automatically adds a new git remote and checks out the PR author's branch — with no confirmation step and no verification that the "head" repository/ref pair is anything the user actually intended to trust. This mirrors the `handleSenderPrepare` bug class: an externally supplied object (the bid / here, the PR object from the GitHub API) is trusted and acted upon without validating that its parameters are safe/expected for the resource being mutated (the router's config / here, the user's already-cloned repository).

### Finding Description
`parseAppURL` accepts an `openRepo` action with a `pr` query parameter, requiring only that it match `/^\d+$/`: [1](#0-0) 

This action is dispatched to `Dispatcher.openRepositoryFromUrl`, which routes PR-bearing links to `openPullRequestFromUrl`: [2](#0-1) 

`openPullRequestFromUrl` fetches the PR object from the GitHub API using the attacker-supplied `url` and `pr`, then tries to find an *existing, already-trusted* repository whose origin or upstream remote matches either the PR's head or base clone URL: [3](#0-2) [4](#0-3) 

Because the match is done against the **base** repo URL too (not just head), any public repository the victim already has cloned in Desktop can be targeted: an attacker opens a PR from their own fork against that public repo, then crafts a link with that PR number. Once the local repository is matched, Desktop unconditionally calls `_checkoutPullRequest` using the PR's `head.repo.owner.login`, `head.repo.clone_url`, and `head.ref` — all fields taken from the externally-fetched PR object: [5](#0-4) 

`_checkoutPullRequest`/`_findPullRequestBranch` then adds a new remote (prefixed `github-desktop-`) pointing at the attacker's fork, fetches it, and creates/checks out a local branch tracking it — all without any user prompt or validation that this is the PR/fork the user intended to open: [6](#0-5) 

This is exactly the missing-validation pattern from the report: like the router accepting bid parameters from an untrusted source without confirming they're still valid/expected for the current configuration, Desktop accepts a PR object's `head` fields from the API (whose contents are fully attacker-controlled since anyone can open a PR against a public repo) and uses them to mutate a repository the user already trusts, without any allow-list, ownership check, or confirmation dialog. No repo-level protections (e.g., verifying the PR author has write access, or requiring confirmation before adding a new remote and switching the working tree to foreign content) gate this path — the only checks present are for `pr`/`branch` format and `filepath` traversal, none of which validate whether the resulting checkout target is something the user should trust.

### Impact Explanation
Because the deep-link scheme is registered system-wide, *any* website, email, or chat message the user clicks can trigger this flow — not only github.com. A successful click causes Desktop to silently:
- Add a new remote to an existing, trusted local repository.
- Fetch and check out an attacker-controlled branch as the working tree content.

If the checked-out content includes build/config files that get executed later (e.g. npm/yarn scripts, editor task runners, CI configs the user might run locally), this becomes a path to code execution on the victim's machine, entirely driven by content the user never reviewed. At minimum, it silently swaps the working directory contents of a trusted repository for attacker-controlled code without any explicit user confirmation — a form of unauthorized/silent corruption of repository state.

### Likelihood Explanation
Likelihood is limited by preconditions: the victim must (a) have GitHub Desktop with the protocol handler registered (default install), (b) already have the targeted repository open/cloned locally, and (c) click the crafted link. All three are realistic for popular public repositories (the attacker can pick any repo the target is known to use, e.g. their own employer's open-source project) and require no credentials, no local access, and no unusual technical steps from the victim — just a single click, matching the "unprivileged... link or deep link the user clicks" impact criteria.

### Recommendation
- Before adding a remote/fetching/checking out a PR triggered via a deep link, show an explicit confirmation dialog naming the fork owner/URL and branch that will be fetched and checked out.
- Do not match against the PR's `base` repository URL as a proxy for "this action is safe" — matching against an already-open repo does not imply the *head* content is trusted.
- Consider only auto-fulfilling deep-link PR checkouts when the PR was authored by an account the user is authenticated as (self-service "Open in Desktop" from one's own PR), rejecting or requiring confirmation for third-party PRs.
- Rate-limit/deduplicate concurrent invocations of `openPullRequestFromUrl` for the same PR to avoid overlapping remote-add/fetch/checkout races.

### Proof of Concept
1. Attacker forks `github.com/victim-org/public-repo` and opens a pull request from a branch containing malicious working-tree content (e.g., a modified `package.json` postinstall script or task runner config) against `victim-org/public-repo`.
2. Victim already has `victim-org/public-repo` cloned locally in GitHub Desktop.
3. Attacker sends the victim a link (via any website/email/chat):
   `x-github-client://openRepo/https://github.com/victim-org/public-repo?pr=<attacker_pr_number>`
4. Victim clicks the link. Desktop's `handleAppURL` → `parseAppURL` → `dispatchURLAction` → `openRepositoryFromUrl` → `openPullRequestFromUrl` runs:
   - Fetches the PR via `appStore.fetchPullRequest`.
   - Matches the existing local `victim-org/public-repo` repository via its base URL.
   - Calls `_checkoutPullRequest` with the attacker's fork clone URL/ref, adding a `github-desktop-<attacker>` remote, fetching it, and checking out `pr/<n>` locally — with no prompt shown to the victim.
5. The victim's working directory for their trusted repo now contains attacker-controlled content, which the victim may unknowingly build/run.

Note: I was not able to fully verify (due to index/time limits) whether any confirmation dialog exists elsewhere in the UI layer that intercepts this specific flow before checkout completes; my search for confirmation/warning components (`ConfirmForkedRemote`, `UntrustedRemote`, etc.) returned no matches in the indexed code, but a full repository search via a Devin session would be needed to rule this out definitively.

  private getRepositoryFromPullRequest(
    pullRequest: IAPIPullRequest
  ): RepositoryWithGitHubRepository | null {
    const state = this.appStore.getState()
    const repositories = state.repositories
    const headUrl = pullRequest.head.repo?.clone_url
    const baseUrl = pullRequest.base.repo?.clone_url

    // This likely means that the base repository has been deleted
    // and we don't support checking out from refs/pulls/NNN/head
    // yet so we'll bail for now.
    if (headUrl === undefined || baseUrl === undefined) {
      return null
    }

    for (const repository of repositories) {
      if (this.doesRepositoryMatchUrl(repository, headUrl)) {
        return repository
      }
    }

    for (const repository of repositories) {
      if (this.doesRepositoryMatchUrl(repository, baseUrl)) {
        return repository
      }
    }

    return null
  }

  private doesRepositoryMatchUrl(
    repo: Repository | CloningRepository,
    url: string
  ): repo is RepositoryWithGitHubRepository {
    if (repo instanceof Repository && isRepositoryWithGitHubRepository(repo)) {
      const originRepoUrl = repo.gitHubRepository.htmlURL
      const upstreamRepoUrl = repo.gitHubRepository.parent?.htmlURL ?? null

      if (originRepoUrl !== null && urlsMatch(originRepoUrl, url)) {
        return true
      }

      if (upstreamRepoUrl !== null && urlsMatch(upstreamRepoUrl, url)) {
        return true
      }
    }

    return false
  }

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

  public async _checkoutPullRequest(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,
    headRefName: string
  ): Promise<void> {
    const prBranch = await this._findPullRequestBranch(
      repository,
      prNumber,
      headRepoOwner,
      headCloneUrl,
      headRefName
    )
    if (prBranch !== undefined) {
      await this._checkoutBranch(repository, prBranch)
      this.statsStore.increment('prBranchCheckouts')
    }
  }

  public async _findPullRequestBranch(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,
    headRefName: string
  ): Promise<Branch | undefined> {
    const gitStore = this.gitStoreCache.get(repository)
    const remotes = await getRemotes(repository)

    // Find an existing remote (regardless if set up by us or outside of
    // Desktop).
    let remote = remotes.find(r => urlMatchesRemote(headCloneUrl, r))

    // If we can't find one we'll create a Desktop fork remote.
    if (remote === undefined) {
      try {
        const forkRemoteName = forkPullRequestRemoteName(headRepoOwner)
        remote = await addRemote(repository, forkRemoteName, headCloneUrl)
      } catch (e) {
        this.emitError(
          new Error(
            `Couldn't find PR branch, adding remote failed: ${e.message}`
          )
        )
        return
      }
    }

    const remoteRef = `${remote.name}/${headRefName}`

    // Start by trying to find a local branch that is tracking the remote ref.
    let existingBranch = gitStore.allBranches.find(
      x => x.type === BranchType.Local && x.upstream === remoteRef
    )

    // If we found one, let's check it out and get out of here, quick
    if (existingBranch !== undefined) {
      return existingBranch
    }

    const findRemoteBranch = (name: string) =>
      gitStore.allBranches.find(
        x => x.type === BranchType.Remote && x.name === name
      )

    // No such luck, let's see if we can at least find the remote branch then
    existingBranch = findRemoteBranch(remoteRef)

    // It's quite possible that the PR was created after our last fetch of the
    // remote so let's fetch it and then try again.
    if (existingBranch === undefined) {
      try {
        await this._fetchRemote(repository, remote, FetchType.UserInitiatedTask)
        existingBranch = findRemoteBranch(remoteRef)
      } catch (e) {
        log.error(`Failed fetching remote ${remote?.name}`, e)
      }
    }

    if (existingBranch === undefined) {
      this.emitError(
        new Error(
          `Couldn't find branch '${headRefName}' in remote '${remote.name}'. ` +
            `A common reason for this is that the PR author has deleted their ` +
            `branch or their forked repository.`
        )
      )
      return
    }

    // For fork remotes we checkout the ref as pr/[123] instead of using the
    // head ref name since many PRs from forks are created from their default
    // branch so we'll have a very high likelihood of a conflicting local branch
    const isForkRemote =
      remote.name !== gitStore.defaultRemote?.name &&
      remote.name !== gitStore.upstreamRemote?.name

    if (isForkRemote) {
      return await this._createBranch(
        repository,
        `pr/${prNumber}`,
        remoteRef,
        false
      )
    }

    return existingBranch
  }
