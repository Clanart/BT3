### Title
Permanent Account/Fund Freezing via Unbounded Balance-Store Iteration During Sei↔EVM Address Association - ([File: utils/helpers/associate.go])

### Summary
The Sei↔EVM address-association flow, executed automatically in the ante pipeline for every not-yet-associated account, calls `AssociationHelper.MigrateBalance`, which invokes `bankKeeper.SpendableCoins`/`GetAllBalances` on the deterministic "cast address" (`sdk.AccAddress(evmAddr[:])`). This performs an unbounded KVStore iteration over every denom balance held at that address. Because tokenfactory denom creation and bank transfers are permissionless and cheap, an attacker can pre-seed a victim's cast address with an unbounded number of dust denom balances, causing this iteration to consume gas proportional to attacker-controlled input, mirroring the reported Compound bug class where an unbounded, permissionlessly-grown list (`allMarkets`/`accountAssets`) is fully iterated by a critical path and can push it out of gas.

### Finding Description
`AssociationHelper.MigrateBalance` unconditionally reads all balances of the cast address before every association: [1](#0-0) 

`SpendableCoins` internally calls `GetAllBalances`, which performs `IterateAccountBalances` — an unbounded iterator over every denom entry stored under that address's balance prefix: [2](#0-1) 

This migration path is triggered automatically:
- For every Cosmos tx from a signer not yet associated with an EVM address, in `EVMAddressDecorator.AnteHandle` (part of the *finite*-gas-metered `anteDecorators` chain in `app/ante.go`): [3](#0-2) 
- For every EVM tx from an unassociated sender, in `EVMPreprocessDecorator.AnteHandle` (though this path switches to an infinite gas meter before calling `MigrateBalance`, mitigating pure OOG there): [4](#0-3) 
- For every signer update inside `UpdateSigners` used by the checkTx path: [5](#0-4) 

The "cast address" — `sdk.AccAddress(evmAddr[:])`, i.e. the target's *future* EVM address bytes reinterpreted as a Sei address — is fully deterministic from a target's secp256k1 public key via `PubkeyToEVMAddress`. Once any account's pubkey is known on-chain (set after its first signed tx, or already publicly known from reuse on another chain), an attacker can:
1. Permissionlessly create many tokenfactory denoms (`x/tokenfactory` `CreateDenom` requires only a small fee and is explicitly designed to be open to any account): [6](#0-5) 
2. Mint/send tiny dust amounts of each denom to the victim's deterministic cast address via ordinary `MsgSend`, with no consent from the recipient required.

The Cosmos-tx ante path (`app/ante.go`'s `anteDecorators`, which runs `EVMAddressDecorator` under the tx's own bounded gas meter set by `NewSetUpContextDecorator`) then attempts `MigrateBalance` on *every* subsequent Cosmos transaction from that unassociated victim account, and aborts the entire `AnteHandle` chain (returning the error, never calling `next`) if the balance iteration fails/consumes excessive gas: [7](#0-6) [8](#0-7) 

This is directly analogous to the reported bug class: `allMarkets`/`accountAssets` in Compound are unbounded lists that grow via permissionless user actions (adding markets / entering markets) and are later fully iterated by essential operations (`claimComp()`, liquidation checks), risking out-of-gas failure once the list grows large enough. Here, the "list" is the set of denom balances at an address, which grows via a fully permissionless, cheap mechanism (tokenfactory denom creation + bank transfer), and the essential operation that iterates it unconditionally (balance migration during Sei↔EVM association) runs on the finite-gas Cosmos ante path for *every* transaction of an affected account.

### Impact Explanation
If an attacker dusts a target's cast address with enough distinct denoms before the target ever associates with an EVM address, every future Cosmos transaction from that account will attempt the same unbounded balance iteration inside the ante handler. Once the iteration's gas cost exceeds what the tx's gas limit (and realistically the block gas limit) can accommodate, the account is permanently unable to complete association or any ordinary Cosmos transaction, because `EVMAddressDecorator.AnteHandle` returns the error and never proceeds to `next`. Any of the account's genuine funds sitting in the cast address (which is exactly where funds land whenever anything is sent to that address before association, including the "cast" EVM balance itself) become permanently unmigratable and effectively frozen, since the only path to reclaim them (`MigrateBalance`) is the operation that fails. This satisfies the "permanent freezing of funds" bar for a Medium/High-severity finding.

### Likelihood Explanation
The precondition — the victim's pubkey being publicly known — is common (it's set the moment an account makes its first transaction, and is often already public due to key reuse across other Cosmos/EVM chains sharing the same secp256k1 key). Both prerequisite actions (tokenfactory `CreateDenom` and `MsgSend`) are unprivileged, cheap, and explicitly designed to be open to any account, making the attack straightforward and inexpensive to mount against any targeted address whose public key is known.

### Recommendation
Cap the number of distinct denoms that `MigrateBalance`/`SpendableCoins`/`GetAllBalances` will iterate over inside the association ante-handler path, or move the migration off the finite-gas Cosmos ante path entirely (e.g., defer it to an infinite-gas context as is already done for the EVM tx path in `EVMPreprocessDecorator`). Alternatively, bound the total number of denoms an unassociated address may accumulate before association is forced/rejected, or make balance migration resumable/batched (as is already done elsewhere in the codebase for other unbounded operations, e.g., `PruneZeroStorageSlots`'s batched cleanup) so a single dusted account cannot deterministically and permanently block its own ante-handler execution.

### Proof of Concept
1. Attacker observes a target Sei address `S` whose secp256k1 public key `P` is known (e.g., already transacted once, or key reused from another chain).
2. Attacker computes the deterministic future EVM address `E = PubkeyToEVMAddress(P)` and the corresponding cast address `C = sdk.AccAddress(E[:])`.
3. Attacker repeatedly calls `MsgCreateDenom` (tokenfactory) to mint N distinct denoms (cheap, permissionless), then `MsgSend`s 1 unit of each of the N denoms to `C`.
4. When `S` later submits any ordinary Cosmos transaction, `EVMAddressDecorator.AnteHandle` detects `S` is unassociated, derives `E` from `S`'s now-known pubkey, and calls `AssociationHelper.MigrateBalance(ctx, E, S, false)`, which calls `SpendableCoins(ctx, C)` → `GetAllBalances(ctx, C)` → `IterateAccountBalances`, iterating all N dust denom entries under the finite tx gas meter set by `NewSetUpContextDecorator`.
5. For sufficiently large N (bounded only by how much dust the attacker is willing to fund, which is cheap), this iteration consumes enough gas to exceed the tx's/block's gas limit, causing the ante handler to fail and `S`'s transaction (and all future transactions) to be permanently rejected, freezing `S`'s ability to transact and any funds already resting in `C`.

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}

// IterateAccountBalances iterates over the balances of a single account and
// provides the token balance to a callback. If true is returned from the
// callback, iteration is halted.
func (k BaseViewKeeper) IterateAccountBalances(ctx sdk.Context, addr sdk.AccAddress, cb func(sdk.Coin) bool) {
	accountStore := k.getAccountStore(ctx, addr)

	iterator := accountStore.Iterator(nil, nil)
	defer func() { _ = iterator.Close() }()

	for ; iterator.Valid(); iterator.Next() {
		var balance sdk.Coin
		k.cdc.MustUnmarshal(iterator.Value(), &balance)

		if cb(balance) {
			break
		}
	}
}

func UpdateSigners(ctx sdk.Context, tx sdk.Tx, accountKeeper authkeeper.AccountKeeper, evmKeeper *evmkeeper.Keeper) (sdk.Events, error) {
	signers := tx.(authsigning.SigVerifiableTx).GetSigners()
	var events sdk.Events
	for _, signer := range signers {
		acc := accountKeeper.GetAccount(ctx, signer)
		if err := acc.SetSequence(acc.GetSequence() + 1); err != nil {
			panic(err)
		}

		accountKeeper.SetAccount(ctx, acc)
		if evmAddr, associated := evmKeeper.GetEVMAddress(ctx, signer); associated {
			events = append(events, sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeyEvmAddress, evmAddr.Hex()),
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		if acc.GetPubKey() == nil {
			logger.Error("missing pubkey for signer", "signer", signer)
			events = append(events, sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		pk, err := btcec.ParsePubKey(acc.GetPubKey().Bytes())
		if err != nil {
			logger.Debug("failed to parse pubkey, likely due to the fact that it isn't on secp256k1 curve", "pub-key", acc.GetPubKey(), "err", err)
			events = append(events, sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		evmAddr, err := helpers.PubkeyToEVMAddress(pk.SerializeUncompressed())
		if err != nil {
			logger.Error("failed to get EVM address from pubkey", "err", err)
			events = append(events, sdk.NewEvent(evmtypes.EventTypeSigner,
				sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
			continue
		}
		events = append(events, sdk.NewEvent(evmtypes.EventTypeSigner,
			sdk.NewAttribute(evmtypes.AttributeKeyEvmAddress, evmAddr.Hex()),
			sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, signer.String())))
		evmKeeper.SetAddressMapping(ctx, signer, evmAddr)
		associationHelper := helpers.NewAssociationHelper(evmKeeper, evmKeeper.BankKeeper(), accountKeeper)
		if err := associationHelper.MigrateBalance(ctx, evmAddr, signer, false); err != nil {
			logger.Error("failed to migrate EVM address balance", "address", evmAddr, "err", err)
			return nil, err
		}
