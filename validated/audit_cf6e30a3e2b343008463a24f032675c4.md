### Title
Blind SSRF via unauthenticated DataLayer mirror coin URL injection - (File: chia/data_layer/data_layer_wallet.py, chia/data_layer/download_data.py)

### Summary
Any wallet user can create a permissionless "mirror" coin on-chain that claims an arbitrary `launcher_id` (DataLayer store id) it doesn't own, embedding an attacker-chosen URL in the coin memos. Victim nodes that track that store's DL wallet ingest the mirror unconditionally, and the DataLayer service later performs outbound HTTP requests to that URL when syncing/fetching data, without any allowlisting, scheme restriction, or private-IP filtering — a classic blind SSRF.

### Finding Description
`create_mirror_puzzle()` returns `P2_PARENT.curry(Program.to(1))`, a puzzle hash anyone can pay to; the puzzle itself performs no authorization check tying the coin to store ownership [2](#0-1) . `get_mirror_info()` extracts `launcher_id` and `urls` purely from the `CREATE_COIN` condition's memos with no validation against who created the coin [3](#0-2) .

When such a coin is seen, `DataLayerWallet.coin_added()` checks only `is_launcher_tracked(launcher_id)` — i.e., whether the *victim* already tracks that store — and then unconditionally records the mirror with attacker-supplied URLs into the local `mirrors` table: [4](#0-3) 

`DataLayer.update_subscriptions_from_wallet()` pulls all mirror URLs (regardless of who published them) and feeds them into the store's active server/subscription list: [5](#0-4) 

`fetch_and_validate()` later randomly selects from these servers and attempts delta downloads, calling `insert_from_delta_file` → `download_file` → `http_download`, which issues a raw `aiohttp` GET to `server_info.url + "/" + filename` with no scheme/host restrictions: [6](#0-5) [7](#0-6) 

Additionally, `get_downloader()` and `get_uploaders()` POST JSON (including the attacker URL) to any configured plugin, and if no plugin handles it, the direct HTTP path is used — the attacker-controlled URL is never checked for internal/loopback/link-local addresses. [8](#0-7) 

### Impact Explanation
A victim running a DataLayer node that subscribes to (or owns) a given store id can be made to issue outbound HTTP requests to arbitrary attacker-chosen hosts/ports by anyone submitting a single, cheap, standard spend bundle (a mirror-coin creation) on chain — no compromise of the victim's keys or node is required. This enables internal network/port scanning from the victim's host, SSRF against internal services (e.g., localhost RPC ports, cloud metadata endpoints if the DataLayer node runs in a cloud VM), and can be used to trigger repeated outbound connection attempts. While it does not directly move funds, it is a genuine, remotely triggerable server-side request forgery reachable via ordinary Data Layer client operation, matching the reported bug class exactly (blind SSRF via a URL-controlled `ping`/download-style endpoint).

### Likelihood Explanation
Likelihood is moderate-to-high for any node that subscribes to third-party DataLayer stores (the common use case for DL, e.g., subscribing to public data feeds): creating a mirror coin requires only a small XCH amount and a standard signed spend, no special privilege, no cooperation from the store owner, and no coordination with the victim. The victim need only be tracking (subscribed to or owning) the targeted `launcher_id`; DataLayer subscription is explicitly designed for this scenario. The `.cursor/context/data-layer.md` documentation itself flags "Plugin and mirror URLs are external trust inputs" as a known fragility area, indicating this is a real, acknowledged trust boundary rather than a purely theoretical concern. [9](#0-8) 

### Recommendation
- Validate/authorize mirror coin authorship before trusting embedded `launcher_id`/URL pairs, e.g., require the mirror coin's URL to be published by a party that also proves control of/relation to the store (or otherwise clearly mark unauthenticated mirrors as untrusted and require explicit user opt-in per URL).
- Before making any outbound request (`http_download`, `get_downloader`, `get_uploaders`), resolve and validate the target host against a deny-list of private/loopback/link-local/metadata IP ranges, and restrict allowed schemes to `http`/`https` only.
- Consider requiring operator confirmation (allowlist) before a newly discovered mirror URL is added to the active subscription/download rotation, rather than auto-trusting any coin found on-chain.

### Proof of Concept
1. Attacker identifies a `launcher_id` (store id) that the victim's DataLayer node subscribes to or owns (this is discoverable, since subscriptions/ownership are part of normal DL usage).
2. Attacker spends a small amount of XCH to create a `CREATE_COIN` output at `create_mirror_puzzle().get_tree_hash()` with memos `[launcher_id, b"http://169.254.169.254/latest/meta-data/"]` (or any internal target), matching the format expected by `get_mirror_info()`.
3. Victim's wallet syncs the new coin; `DataLayerWallet.coin_added()` sees the mirror puzzle hash, calls `get_mirror_info()`, confirms `is_launcher_tracked(launcher_id)` is true, and inserts the attacker's URL into the `mirrors` table via `dl_store.add_mirror()`.
4. Victim's `DataLayer.update_subscriptions_from_wallet()` copies this URL into the store's subscription server list.
5. On the next `fetch_and_validate()` cycle, the victim's DataLayer service issues an HTTP GET (via `http_download`) to the attacker-chosen URL, completing the blind SSRF. [4](#0-3) [7](#0-6)

def create_mirror_puzzle() -> Program:
    return P2_PARENT.curry(Program.to(1))


MIRROR_PUZZLE_HASH = create_mirror_puzzle().get_tree_hash()


def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
