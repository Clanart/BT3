### Title
`stSTXbtc`/`zstSTXbtc` collateral and debt valued using the STX price feed instead of the BTC price feed - (File: `mainnet/contracts/utility/v0-1-data.clar`)

### Summary
`get-asset-price` in `v0-1-data.clar` prices `stSTXbtc` and `zstSTXbtc` (BTC-yield-bearing, liquid-staked assets) by calling `get-pyth-price PYTH-STX` instead of `get-pyth-price PYTH-BTC`, i.e. it attaches the STX/USD price to a BTC-denominated asset.

### Finding Description
The helper `get-asset-price` resolves per-asset USD prices for use in position/health-factor computations. For every other asset the correct Pyth feed constant is used consistently with the asset's underlying denomination (e.g. `sBTC` → `PYTH-BTC`, `USDC` → `PYTH-USDC`). For `stSTXbtc` and `zstSTXbtc`, however, the code explicitly comments "BTC price (liquid staked STX with BTC yield)" / "stSTXbtc price x liquidity index" but calls `(get-pyth-price PYTH-STX)`: [1](#0-0) 

Compare with the correctly-implemented sibling branches for `sBTC`/`zsBTC`, which use `PYTH-BTC`: [2](#0-1) [3](#0-2) 

This function feeds `sum-collateral-usd` and `sum-debt-usd`, which compute the USD value used to build a user's LTV / health-factor / liquidatability view: [4](#0-3) 

The same bug is duplicated verbatim in the mirrored local-testing helper `protocol-data.clar`: [5](#0-4) 

### Impact Explanation
`stSTXbtc`/`zstSTXbtc` is a BTC-pegged, staking-yield-bearing asset (per the asset naming and the surrounding comments — “liquid staked STX with BTC yield”). Pricing it off the STX/USD feed instead of BTC/USD means any position holding `stSTXbtc`/`zstSTXbtc` as collateral or debt is valued using a completely unrelated, more volatile asset's price. Since STX and BTC prices diverge continuously and independently, this can:
- Overstate collateral value (STX price higher relative to BTC-equivalent value) → understate LTV / mark a position as healthy/non-liquidatable when it is actually undercollateralized, letting borrowers extract more value than their real BTC-denominated collateral backs (bad debt / protocol insolvency risk).
- Understate collateral value → cause premature/incorrect liquidation flags.

The direction of the error moves with relative STX/BTC price drift and is not attacker-controlled market data corruption — it's a hardcoded wrong constant in the protocol's own code, not "third-party oracle data" or "DAO misconfiguration" (the price feed IDs and mapping logic are protocol code, not DAO-set registry values). This lands on the in-scope impact class of protocol insolvency / permanent freezing of funds via mispriced positions being marked healthy or forced into incorrect liquidation.

### Likelihood Explanation
This triggers on every call to `get-asset-price` for `aid == stSTXbtc` or `aid == zstSTXbtc` — i.e., unconditionally whenever the protocol has any user with this asset in collateral or debt. No special preconditions or attacker action are needed; it is deterministic given normal protocol usage of the `stSTXbtc` vault.

### Recommendation
Change `(get-pyth-price PYTH-STX)` to `(get-pyth-price PYTH-BTC)` in both branches (`stSTXbtc` and `zstSTXbtc`) of `get-asset-price` in `mainnet/contracts/utility/v0-1-data.clar` (lines 582 and 585) and the equivalent branches in `local-testing/contracts/utility/protocol-data.clar`.

### Proof of Concept
1. Register/hold a position with `stSTXbtc` or `zstSTXbtc` as collateral.
2. Call the read path that invokes `get-asset-price(stSTXbtc)` / `get-asset-price(zstSTXbtc)` (e.g. via `sum-collateral-usd`/`sum-debt-usd` used in the position/health-data builder around [6](#0-5) ).
3. Observe the returned USD value is `STX_price` (not `BTC_price`) multiplied by the liquidity index for `zstSTXbtc`, or raw `STX_price` for `stSTXbtc` — diverging from the actual BTC-denominated value of the holding, directly corrupting the LTV/health-factor/`is-liquidatable` computation for that position.

;; Helper: Sum collateral USD values
(define-private (sum-collateral-usd (entry { aid: uint, amount: uint }) (acc uint))
  (let ((aid (get aid entry))
        (amount (get amount entry))
        (asset-data (unwrap-panic (contract-call? .v0-assets get-status aid)))
        (decimals (get decimals asset-data))
        (price (get-asset-price aid)))
    (+ acc (/ (* amount price) (pow u10 decimals)))))

;; Helper: Find specific asset amount in collateral list
(define-private (find-collateral-amount-iter
  (entry { aid: uint, amount: uint })
  (acc { target: uint, amount: uint }))
  (if (is-eq (get aid entry) (get target acc))
      { target: (get target acc), amount: (get amount entry) }
      acc))

;; Helper: Sum debt USD values
(define-private (sum-debt-usd (entry { aid: uint, scaled: uint }) (acc uint))

        (scaled (get scaled entry))

        (actual (mul-div-down scaled borrow-index INDEX-PRECISION))
        (price (get-asset-price aid)))
