## Finding: Dead pause flag – `_paused` in `IntentsBase.sol` never gates any state-changing entrypoint

### Title
Intent Gateway `_paused` flag is declared but never enforced, so orders can be placed/filled/cancelled during an incident - (File: `evm/src/apps/intentsv2/IntentsBase.sol`)

### Summary
`IntentsBase.sol` declares a boolean pause flag, `_paused`, explicitly intended as an emergency-stop mechanism for the Intent Gateway. However, this flag is never read by any `whenNotPaused`-style modifier or manual check anywhere in the codebase, and there is no `pause()`/`unpause()` setter function that flips it. As a result, none of the fund-custody entrypoints — `placeOrder`, `fillOrder`, `cancelOrder` (and its internal routes `_cancelSameChain`/`_cancelFromSource`/`_cancelFromDest`), or the cross-chain `onAccept` handler that releases/refunds escrow — are actually protected by any pause mechanism, contradicting the storage variable's evident purpose.

### Finding Description

The comment "Appended last to preserve existing storage slots" indicates this was added as an upgrade to support pausability. Yet across the entire `evm/src/apps/intentsv2` and `evm/src/apps/IntentGatewayV2.sol` code paths, `_paused` is never referenced again — no modifier reads it, and no external function sets it. The order lifecycle functions that move escrowed value all execute unconditionally:

- `cancelOrder` dispatches to same-chain/source/destination cancel logic without any pause check: [2](#0-1) 
- `_cancelFromSource` and `_cancelFromDest` release/refund escrow with no pause gate: [3](#0-2) 
- `onAccept` processes `RedeemEscrow`/`RefundEscrow` and calls `_withdraw` to move tokens out, again with no pause check: [4](#0-3) 
- The core `_withdraw` fund-movement routine that all cancel/fill/redeem paths funnel into has no pause gate either: [5](#0-4) 

This is the direct local analog of the external report's bug class ("orders can be cancelled while contract is paused" due to a missing `whenNotPaused()` modifier). Here the situation is broader and unmitigated: not just `cancelOrder` but every escrow-moving function (`placeOrder`, `fillOrder`, `cancelOrder`, `onAccept`) is unprotected, because the pause primitive itself is non-functional dead state. By contrast, the sibling contract `HyperFungibleToken.sol` correctly wires `Pausable`/`whenNotPaused` into its `onAccept` and `onPostRequestTimeout` callbacks: [6](#0-5) [7](#0-6)  — confirming that pausability is a recognized, intended safety control in this codebase's app contracts, but it was left unimplemented (or removed) for the Intent Gateway despite the storage slot for it.

### Impact Explanation
If governance/ops ever needed to halt the Intent Gateway during an active incident (e.g., a discovered exploit in the fill/select/cancel logic, a compromised price oracle, or a bug in `_withdraw`/escrow accounting), setting `_paused = true` would have zero effect: attackers or automated exploit transactions could continue to `placeOrder` (escrowing/losing further user funds into a compromised system), `fillOrder`/`cancelOrder` (continuing to drain or misdirect escrow), and cross-chain `onAccept` redemptions/refunds would keep executing. This directly maps to the required impact of "stealing or loss of funds" and "unauthorized transaction or execution" because the intended circuit-breaker for fund-custody logic does not exist in practice, leaving escrowed assets exposed for the full duration of any incident.

### Likelihood Explanation
This is not a hypothetical: the flag is present, named, and positioned as "appended last to preserve existing storage slots" (i.e., deliberately added post-deployment), which strongly indicates it was meant to be wired into the fund-movement functions but the enforcement wiring was never completed. Any incident response relying on pausing the Intent Gateway would silently fail, and this can be verified by code inspection alone — no attacker action or malicious actor is required to trigger the underlying condition; it is a standing latent security gap in the deployed contract logic.

### Recommendation
Add an enforced `whenNotPaused` modifier (checking `_paused`) to all state-changing, fund-moving entrypoints in the Intent Gateway family: `placeOrder`, `fillOrder`, `select`, `cancelOrder` (and its internal `_cancelSameChain`/`_cancelFromSource`/`_cancelFromDest` routes), and the `onAccept` handler in `ExtrinsicIntents.sol`/`IntrinsicIntents.sol`. Implement corresponding `pause()`/`unpause()` functions restricted to the appropriate governance/admin role, mirroring the pattern already used correctly in `HyperFungibleToken.sol`.

### Proof of Concept
1. Deploy/observe the Intent Gateway; confirm via storage read that `_paused` exists at its declared slot in `IntentsBase.sol`.
2. Have governance (or an emergency admin) attempt to "pause" the gateway by setting `_paused = true` (no such setter exists, but even simulating direct storage manipulation in a fork test to set the slot to `true` demonstrates the gap).
3. Call `placeOrder`, `fillOrder`, or `cancelOrder` after the flag is set — in Foundry, `IntentGatewayV2Test.sol`/`IntentGatewayV2SameChainTest.sol` can be extended to set the storage slot and observe these calls succeed unimpeded, since no code path anywhere checks `_paused`. [2](#0-1)

        address beneficiary = address(uint160(uint256(body.beneficiary)));
        if (finalize) _filled[body.commitment] = beneficiary;

        uint256 len = body.tokens.length;
        for (uint256 i; i < len; i++) {
            address token = address(uint160(uint256(body.tokens[i].token)));
            uint256 amount = body.tokens[i].amount;
            if (amount == 0) continue;

            uint256 escrowed = _orders[body.commitment][token];
            if (escrowed == 0) revert UnknownOrder();

            _orders[body.commitment][token] = escrowed - amount;
            if (token == address(0)) {
                (bool sent,) = beneficiary.call{value: amount}("");
                if (!sent) revert InsufficientNativeToken();
            } else {
                IERC20(token).safeTransfer(beneficiary, amount);
            }
        }

        if (finalize) {
            uint256 fees = _orders[body.commitment][TRANSACTION_FEES];
            if (fees > 0) {
                delete _orders[body.commitment][TRANSACTION_FEES];
                IERC20(IDispatcher(host()).feeToken()).safeTransfer(beneficiary, fees);
            }

            if (isRefund) {
                emit EscrowRefunded({commitment: body.commitment, tokens: body.tokens});
            } else {
                emit EscrowReleased({commitment: body.commitment, tokens: body.tokens});
            }
        }

    function cancelOrder(Order calldata order, CancelOptions calldata options) public payable nonReentrant {
        bytes32 commitment = keccak256(abi.encode(order));

        if (_filled[commitment] != address(0)) revert Filled();

        address hostAddr = host();
        bytes32 currentChain = keccak256(IDispatcher(hostAddr).host());
        bytes32 orderSource = keccak256(order.source);
        bytes32 orderDest = keccak256(order.destination);
        bool isSameChain = orderSource == orderDest;

        if (isSameChain) {
            _cancelSameChain(order, commitment);
        } else if (currentChain == orderSource) {
            _cancelFromSource(order, options, commitment);
        } else if (currentChain == orderDest) {
            _cancelFromDest(order, options, commitment);
        } else {
            revert WrongChain();
        }
    }

    function _cancelFromSource(Order calldata order, CancelOptions calldata options, bytes32 commitment) internal {
        if (order.user != bytes32(uint256(uint160(msg.sender)))) revert Unauthorized();

        if (options.height <= order.deadline) revert NotExpired();

        uint256 inputsLen = order.inputs.length;
        for (uint256 i; i < inputsLen;) {
            if (_orders[commitment][address(uint160(uint256(order.inputs[i].token)))] == 0) revert UnknownOrder();

            unchecked {
                ++i;
            }
        }

        bytes memory context =
            abi.encode(WithdrawalRequest({commitment: commitment, tokens: order.inputs, beneficiary: order.user}));

        bytes[] memory keys = new bytes[](1);
        keys[0] = bytes.concat(abi.encodePacked(_instance(order.destination)), _calculateCommitmentSlotHash(commitment));
        DispatchGet memory request = DispatchGet({
            dest: order.destination,
            keys: keys,
            timeout: 0,
            height: options.height,
            fee: options.relayerFee,
            context: context,
            payer: msg.sender
        });

        address hostAddr = host();
        if (msg.value > 0) {
            IDispatcher(hostAddr).dispatch{value: msg.value}(request);
        } else {
            dispatchWithFeeToken(request);
        }
    }

     * Marks the order as filled (to prevent future fill attempts) and dispatches a

     *
     * @param order The order to cancel.
     * @param options Cancel options including the relayer fee.
     * @param commitment The keccak256 hash of the ABI-encoded order.

    function _cancelFromDest(Order calldata order, CancelOptions calldata options, bytes32 commitment) internal {
        if (order.deadline >= _blockNumber()) {
            if (order.user != bytes32(uint256(uint160(msg.sender)))) revert Unauthorized();
        }

        _filled[commitment] = address(uint160(uint256(order.user)));

        bytes memory body = bytes.concat(
            bytes1(uint8(RequestKind.RefundEscrow)),
            abi.encode(WithdrawalRequest({commitment: commitment, tokens: order.inputs, beneficiary: order.user}))
        );

        DispatchPost memory request = DispatchPost({
            dest: order.source,
            to: abi.encodePacked(_instance(order.source)),
            body: body,
            timeout: 0,
            fee: options.relayerFee,
            payer: msg.sender
        });

        address hostAddr = host();
        if (msg.value > 0) {
            IDispatcher(hostAddr).dispatch{value: msg.value}(request);
        } else {
            dispatchWithFeeToken(request);
        }
