## Analysis

The upstream bug class is: a shared field is mutated by one thread while another thread reads it **without the synchronization that guarantees the write is visible/complete**, allowing a reader to observe a torn/inconsistent value and dereference/interpret it incorrectly (nil-pointer dereference in the kernel case).

The Kaia auction bid pool contains the same bug-class: `BidPool.auctionEntryPointVersion` is a `string` field protected by `auctionInfoMu`, but `getBidTxGasLimit` reads it directly, unsynchronized, outside the lock, while a concurrent writer (`updateAuctionInfo`, invoked every block via `PostInsertBlock`) mutates it under the lock. ### Title
Unsynchronized read of `BidPool.auctionEntryPointVersion` outside its mutex causes a data race / possible corrupted-string crash reachable from public bid submission - (File: kaiax/auction/impl/bid_pool.go)

### Summary
`BidPool.getBidTxGasLimit` reads `bp.auctionEntryPointVersion` directly (line 490) without holding `bp.auctionInfoMu`, while `updateAuctionInfo` (line 196-213) writes this same field under `auctionInfoMu.Lock()`. This is a data race on a Go `string` header (pointer+length), which is not read/written atomically. A concurrent writer changing the field mid-read can produce a torn value in the reading goroutine (mismatched pointer/length pair), which is then passed into `system.EncodeAuctionCallData` to select ABI encoding — an operation that can panic or read out-of-bounds memory when handed a corrupted string.

### Finding Description
`auctionEntryPointVersion` is nominally protected by `bp.auctionInfoMu` (`RLock`/`RUnlock` is used correctly in `GetAuctionEntryPointVersion` at lines 234-238, and in `validateBidSigs` at lines 397-419). However, `getBidTxGasLimit` only takes the lock to snapshot `bidTxGasBuffer` (lines 486-488) and then reads `bp.auctionEntryPointVersion` unlocked at line 490, right after releasing the lock. Meanwhile `updateAuctionInfo`, called once per inserted block via `AuctionModule.PostInsertBlock` → `a.updateAuctionInfo` → `bp.updateAuctionInfo`, writes this field under the lock (line 209) whenever the on-chain auctioneer/entry-point/version/gas-buffer registry values change. This is exactly the CVE's root-cause pattern: a value is updated by one path while another path consumes it without the ordering guarantee that would make the update atomic/visible as a whole, so the consumer can observe a half-updated (torn) value.

### Impact Explanation
Because `AddBid` (and thus `getBidTxGasLimit`) runs on every `SubmitBid` RPC call — reachable by any unprivileged auction searcher/bidder — and `updateAuctionInfo` runs on every new block from the node's own block-processing pipeline, this race is trivially reachable in normal operation without any special timing control needed by the attacker: it fires naturally whenever a bid is submitted around block boundaries where the auction registry parameters change. Under Go's race detector this is UB; in practice a torn string read that is subsequently indexed/compared inside `system.EncodeAuctionCallData` can cause an out-of-bounds slice access panic, crashing the node process — a denial-of-service impact on any node processing gasless/auction bids, consistent with the "High" bug class of the analog (invalid memory access due to missing synchronization on a state transition affecting all subsequent readers).

### Likelihood Explanation
The race requires only two ordinary, frequently-occurring conditions to coincide: (1) a searcher submitting a bid via the public `auction_submitBid` RPC and (2) a block being processed that changes the on-chain auction entry point version (e.g., an operator upgrading the `AuctionEntryPoint` system contract, or fork/registry migrations). Both are externally triggerable/observable events; an attacker can maximize the race window by flooding `SubmitBid` calls to increase the probability of hitting the update window.

### Recommendation
Take `bp.auctionInfoMu.RLock()` around every read of `auctionEntryPointVersion` (and `auctioneer`/`auctionEntryPoint`) that occurs outside the already-locked `validateBidSigs`, in particular in `getBidTxGasLimit`. Snapshot all four related fields (`auctioneer`, `auctionEntryPoint`, `auctionEntryPointVersion`, `bidTxGasBuffer`) atomically under a single lock acquisition rather than reading `bidTxGasBuffer` under lock and `auctionEntryPointVersion` unlocked immediately after, so the values used within one call are mutually consistent and race-free.

### Proof of Concept
1. Start the node with the auction module enabled and `auctionEntryPointVersion = "v1"`.
2. Goroutine A: repeatedly submit valid bids via `auction_submitBid` RPC, driving `AddBid` → `getBidTxGasLimit` to read `bp.auctionEntryPointVersion` unlocked.
3. Goroutine B: process a block that changes the auction entry point/version in the on-chain registry, triggering `PostInsertBlock` → `updateAuctionInfo` → `bp.updateAuctionInfo`, which locks `auctionInfoMu` and overwrites `auctionEntryPointVersion` to `"v2"`.
4. Running under `go test -race` (or under sustained load) demonstrates the concurrent unsynchronized access; on a real build, the torn read can be passed into `system.EncodeAuctionCallData`, triggering a panic/crash in the RPC-handling goroutine and destabilizing the node process.

func (bp *BidPool) updateAuctionInfo(auctioneer common.Address, auctionEntryPoint common.Address, auctionEntryPointVersion string, bidTxGasBuffer uint64) {
	bp.auctionInfoMu.Lock()
	defer bp.auctionInfoMu.Unlock()

	if bp.auctioneer == auctioneer && bp.auctionEntryPoint == auctionEntryPoint && bp.auctionEntryPointVersion == auctionEntryPointVersion && bp.bidTxGasBuffer == bidTxGasBuffer {
		return
	}

	// Clear the existing auction pool since the auctioneer or auction entry point address is changed.
	bp.clearBidPool()

	bp.auctioneer = auctioneer
	bp.auctionEntryPoint = auctionEntryPoint
	bp.auctionEntryPointVersion = auctionEntryPointVersion
	bp.bidTxGasBuffer = bidTxGasBuffer

	logger.Info("Update auction info", "auctioneer", auctioneer, "auctionEntryPoint", auctionEntryPoint, "auctionEntryPointVersion", auctionEntryPointVersion, "bidTxGasBuffer", bidTxGasBuffer)
}

func (bp *BidPool) AddBid(bid *auction.Bid) (common.Hash, error) {
	if atomic.LoadUint32(&bp.running) == 0 {
		return common.Hash{}, auction.ErrAuctionPaused
	}

	if err := bp.validateBid(bid); err != nil {
		return common.Hash{}, err
	}

	if err := bp.insertBid(bid); err != nil {
		return common.Hash{}, err
	}

	gasLimit, err := bp.getBidTxGasLimit(bid)
	if err != nil {
		return common.Hash{}, err
	}
	bid.SetGasLimit(gasLimit)

	bp.newBidCh <- bid

	return bid.Hash(), nil
}

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)
}

func (a *AuctionModule) PostInsertBlock(block *types.Block) error {
	if a.Downloader.Synchronising() || !a.ChainConfig.IsRandaoForkEnabled(block.Number()) {
		atomic.CompareAndSwapUint32(&a.bidPool.running, 1, 0)
		return nil
	}

	if !a.updateAuctionInfo(block.Number()) {
		logger.Debug("stop auction since auctioneer or auction entry point is not set")
		atomic.CompareAndSwapUint32(&a.bidPool.running, 1, 0)
		return nil
	}

	atomic.CompareAndSwapUint32(&a.bidPool.running, 0, 1)

	txHashMap := make(map[common.Hash]struct{})
	for _, tx := range block.Transactions() {
		txHashMap[tx.Hash()] = struct{}{}
	}
	a.bidPool.removeOldBids(block.Number().Uint64(), txHashMap)

	return nil
}
