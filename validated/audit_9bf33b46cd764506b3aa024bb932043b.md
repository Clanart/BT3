### Title
Gasless swap deadline is enforced only at tx-pool admission, not re-validated before block inclusion, allowing stale/MEV-exploitable execution of `swapForGas` past its user-signed deadline - (File: `kaiax/gasless/impl/tx_pool.go`)

### Summary
The `kaiax/gasless` module implements a Uniswap-style swap-for-gas flow where a user signs a `swapForGas(token, amountIn, minAmountOut, amountRepay, deadline)` transaction. The `deadline` field is only checked once, at the moment the transaction is first admitted into the transaction pool via `GetCheckBalance()` → `checkBalanceForSwap()`, which compares `swapArgs.Deadline` against `g.Chain.CurrentBlock().Time()` at admission time. [1](#0-0) 

### Finding Description
The gasless module's swap deadline check is invoked from `pool.validateTx()` only when a transaction is newly added to the pool (`module.IsModuleTx(tx)` → `module.GetCheckBalance()`). [2](#0-1) 

However, once a swap transaction is accepted into the pending pool, subsequent re-validation performed by `demoteUnexecutables()` explicitly documents that only a **limited number** of pending transactions get "full validation" (`list.Filter`); beyond that limit it falls back to `list.FilterUnexecutable()`, which — per its name and the surrounding nonce/balance-only logic — does not re-invoke the kaiax module's `GetCheckBalance` (and therefore the deadline check) for every pending transaction on every new block. [3](#0-2) 

This mirrors the reported bug class exactly: the deadline is a value baked into the *signed calldata* of the transaction, and it is enforced by an off-chain heuristic (pool admission time) rather than being continuously enforced up to the point of actual block inclusion/execution. If the pool is under load (many senders exceeding `demoteUnexecutablesFullValidationTxLimit`) or if a transaction sits in the pending set across many block resets without triggering a full re-check, a `swapForGas` transaction whose `deadline` has since elapsed can still be selected for block execution as long as it was valid nonce-wise. There is no code path shown that re-validates `checkBalanceForSwap` (and thus the deadline) inside the miner/worker's transaction-selection or execution path (`ApplyTransaction`) — the deadline is purely a tx-pool admission-time heuristic, not a consensus-level invariant enforced at execution.

This is architecturally analogous to the reported Rubicon issue: `minOutputAmount`/`deadline` guarantees signed by the user can become stale relative to current market/chain state by the time the transaction is actually executed, because the guarantee is only checked far earlier than execution.

### Impact Explanation
If a stale `swapForGas` transaction (with an expired deadline) is executed:
- The swap price/exchange-rate check (`ShouldCheckSwapAmount`, comparing `AmountIn` against `GetAmountIn(minAmountOut)`) is *also* only evaluated at admission time in `checkBalanceForSwap`, using contract state (AMM reserves) at that moment — not at inclusion time. Reserves can shift materially by the time of actual inclusion.
- Because the gasless flow immediately follows with the node's own `GetLendTxGenerator`-produced KAIA-lending transaction sized to the `Fee()` of the approve/swap pair (see `TestGetLendTxGenerator`), a stale swap executed under different AMM conditions can yield token/KAIA amounts diverging from what the sender intended when signing, potentially resulting in fee/repayment shortfalls or unintended value transfer to the swap counterparty/router at the sender's expense. [4](#0-3) 

This satisfies the "unauthorized value movement" bar because a party (the fee-payer/lender flow or the AMM counterparty) can realize value based on stale user-signed parameters that no longer reflect the sender's intended execution window, without the sender's fresh consent.

### Likelihood Explanation
Medium likelihood: this requires either (a) sustained tx-pool congestion sufficient to push a sender's swap transaction beyond `demoteUnexecutablesFullValidationTxLimit`'s full-validation cutoff across multiple pool resets, or (b) some other path where the pending swap tx survives repeated `demoteUnexecutables`/`promoteExecutables` cycles without the deadline being re-checked before it is finally included by a block-producing CN. This is directly analogous to the original finding's "low gas fee causing indefinite mempool residency" scenario, adapted to Kaia's tx-pool internals. I was not able to fully verify (due to tool/iteration limits) whether the miner/worker explicitly re-invokes `GetCheckBalance` immediately before including a transaction in a block, which would close this gap; this remains an area requiring further verification.

### Recommendation
- Re-invoke each kaiax module's `GetCheckBalance` (or at minimum the gasless module's deadline check) as part of every `demoteUnexecutables`/`FilterUnexecutable` pass, not only within the bounded "full validation" count, so stale deadlines are pruned regardless of pool size.
- Additionally/alternatively, enforce the `deadline` check inside the `GaslessSwapRouter` contract's `swapForGas` execution path itself (a `require(deadline >= block.timestamp)` at execution time), so the guarantee is a consensus-level invariant rather than solely a tx-pool heuristic — consistent with how the report describes the need for on-chain deadline enforcement to eliminate mempool-based staleness/MEV risk.

### Proof of Concept
1. A sender crafts and signs a `swapForGas(token, amountIn, minAmountOut, amountRepay, deadline)` transaction with `deadline = currentBlockTime + 300`.
2. At submission, `checkBalanceForSwap` accepts it because `deadline >= currentBlock.Time()`. [5](#0-4) 
3. Due to congestion (many senders' transactions exceeding `demoteUnexecutablesFullValidationTxLimit`), the pool's periodic re-validation for this account falls back to `FilterUnexecutable()` on subsequent `demoteUnexecutables()` calls across many blocks, skipping the module-level `GetCheckBalance`/deadline re-check. [6](#0-5) 
4. Several blocks later (well past `deadline`), the transaction is still nonce-valid and gets selected by a block-producing CN and executed by the `GaslessSwapRouter` contract (which — as far as observed in the binding/tests — has no on-chain `deadline` enforcement of its own beyond what is passed as a swap parameter used by the off-chain pool check).
5. The AMM state (reserves) at actual execution time may differ materially from what was true when the sender signed the deadline-bound swap, resulting in an outcome the sender never explicitly re-approved.

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {

		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// If SwapTx.nonce is the sender's next nonce, then there is no room for ApproveTx proceeding SwapTx.
		senderNonce := g.getCurrentStateNonce(swapArgs.Sender)
		noApproveTxPreceeds := swapNonce == senderNonce
		if noApproveTxPreceeds {
			// tx.token.allowance(sender, router) >= tx.amountIn
			approval, err := tokenContract.Allowance(nil, swapArgs.Sender, swapRouter)
			if err != nil {
				return err
			}
			if approval.Cmp(swapArgs.AmountIn) < 0 {
				return fmt.Errorf("insufficient approval: approval=%s, want=%s", approval.String(), swapArgs.AmountIn.String())
			}
		}

		// tx.token.balanceOf(sender) >= tx.amountIn
		balance, err := tokenContract.BalanceOf(nil, swapArgs.Sender)
		if err != nil {
			return err
		}
		if balance.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("insufficient balance: balance=%s, want=%s", balance.String(), swapArgs.AmountIn.String())
		}
	}

	// tx.deadline >= currentTimestamp
	deadline := swapArgs.Deadline
	if deadline.Cmp(g.Chain.CurrentBlock().Time()) < 0 {
		return fmt.Errorf("insufficient deadline: deadline=%s, want=%s", deadline.String(), g.Chain.CurrentBlock().Time().String())
	}

	return nil

func (pool *TxPool) demoteUnexecutables() {
	pool.txMu.Lock()
	defer pool.txMu.Unlock()

	// full-validation count. demoteUnexecutables does full-validation for a limited number of txs.
	cnt := 0
	// Iterate over all accounts and demote any non-executable transactions
	for addr, list := range pool.pending {
		nonce := pool.getNonce(addr)
		var drops, invalids types.Transactions

		// Drop all transactions that are deemed too old (low nonce)
		forwarded := list.Forward(nonce)
		pool.pendingCount -= uint64(len(forwarded))
		for _, tx := range forwarded {
			hash := tx.Hash()
			logger.Trace("Removed old pending transaction", "hash", hash)
			pool.all.Remove(hash)
			pool.priced.Removed()
		}

		// demoteUnexecutables does full-validation for a limited number of txs. Otherwise, it only validate nonce.
		// The logic below loosely checks the tx count for the efficiency and the simplicity.
		if cnt < demoteUnexecutablesFullValidationTxLimit {
			cnt += list.Len()
			drops, invalids = list.Filter(addr, pool)
		} else {
			drops, invalids = list.FilterUnexecutable()
		}
