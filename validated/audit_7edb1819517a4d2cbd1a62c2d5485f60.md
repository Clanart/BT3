### Title
Unauthenticated SSRF via attacker-controlled mirror URLs fetched by DataLayer client with no host/IP validation - (File: `chia/data_layer/download_data.py`)

### Summary
Budibase's report describes a REST datasource whose `fields.path` is passed unvalidated into a server-side HTTP fetch (`node-fetch`), letting any authenticated caller reach loopback/RFC1918/link-local/cloud-metadata addresses. Chia's DataLayer module has an analogous unvalidated server-side fetch: `http_download()` in `chia/data_layer/download_data.py` issues `aiohttp` GET requests to `server_info.url + "/" + filename` with no scheme/host/IP validation. The `server_info.url` values originate from **mirror coins**, which are created purely by an on-chain `CREATE_COIN` to `MIRROR_PUZZLE_HASH` with memos `[launcher_id, url1, url2, ...]` (see `create_mirror_puzzle()`/`get_mirror_info()` in `chia/wallet/db_wallet/db_wallet_puzzles.py:90-109`). Any coin owner can construct and submit such a spend bundle directly (independent of the `dl_new_mirror` RPC convenience wrapper), embedding an arbitrary URL string as a memo. Any DataLayer node that syncs/subscribes to that store's singleton will ingest the mirror URL via `update_subscriptions_from_wallet()` (`chia/data_layer/data_layer.py:979-985`) and `data_store.update_subscriptions_from_wallet()`, and will later call `fetch_and_validate()` → `insert_from_delta_file()` → `download_file()` → `http_download()`, which performs the outbound request with no restriction on destination host/IP.

### Finding Description
- `chia/data_layer/download_data.py:298-319` (`http_download`) builds the request target directly from `server_info.url` and calls `session.get(server_info.url + "/" + filename, headers=headers, timeout=timeout, proxy=proxy_url)`. There is no check against loopback (`127.0.0.1`), RFC1918 ranges, link-local/metadata addresses (`169.254.169.254`), or any host allowlist.
- Mirror URLs are supplied entirely by whoever spends a coin to `MIRROR_PUZZLE_HASH` with the desired memos — see `create_mirror_puzzle()` and `get_mirror_info()` in `chia/wallet/db_wallet/db_wallet_puzzles.py:90-109`, which simply decode `memos[1:]` as URL strings from a `CREATE_COIN` condition. This mechanism is reachable from a bare CLVM spend bundle; the `dl_new_mirror` wallet RPC (`chia/wallet/wallet_rpc_api.py:3255-3274`) is only one convenience path, not a gate.
- `DataLayer.add_mirror()` (`chia/data_layer/data_layer.py:965-970`) only checks that the URL list is non-empty — no scheme/host validation exists at any layer (RPC API `chia/data_layer/data_layer_rpc_api.py:468-475`, wallet layer, or fetch layer).
- Once a store is tracked/subscribed, `DataLayer.update_subscriptions_from_wallet()` (`chia/data_layer/data_layer.py:979-985`) pulls all mirror URLs unconditionally into the local `DataStore`'s server list, and `fetch_and_validate()` (`chia/data_layer/data_layer.py:642-705`) randomly picks a server and calls `insert_from_delta_file()` → `download_file()` → `http_download()` to fetch attacker-chosen URLs.
- Unlike the S3 plugin path (`chia/data_layer/s3_plugin_service.py`), which restricts to `scheme == "s3"` and validates the URL is in a configured `store.urls` allowlist, the plain HTTP path used when no downloader plugin is configured has no equivalent restriction.

### Impact Explanation
Any DataLayer node that tracks/subscribes to a store can be coerced into issuing outbound GET requests to attacker-chosen hosts/ports purely by observing an on-chain mirror coin spend — no interaction with the victim node's own RPC or wallet is required beyond passively syncing the chain and following that store. This enables internal network reconnaissance/enumeration from the node's vantage point (reaching internal services, loopback ports, or other hosts on the node's private network) and can be used to probe internal infrastructure reachable from wherever the DataLayer service is deployed. Because path/query cannot be fully attacker-controlled beyond `url + "/" + filename` and headers are fixed (`accept-encoding: gzip`), classic cloud-metadata token theft requiring a custom header (e.g., `Metadata-Flavor: Google`) is not directly achievable, which somewhat limits severity relative to the Budibase report, but arbitrary-host reachability and internal service probing remain a real SSRF exposure with no mitigating validation anywhere in the fetch path.

### Likelihood Explanation
Triggering the mirror coin creation requires only a standard coin spend to `MIRROR_PUZZLE_HASH` with the desired memo URL, which any wallet user/spend-bundle submitter can construct without special privileges. The victim impact is conditioned on that victim's DataLayer node voluntarily tracking/subscribing to the specific store (a normal, expected DataLayer usage pattern for consuming public mirrored stores), making this a realistic but not fully unconditional SSRF (unlike Budibase's admin-scoped preview endpoint, which is directly reachable by any authenticated builder).

### Recommendation
Add hostname/IP validation before dispatching any outbound request in `http_download()` (and the plugin `get_downloader`/`get_uploaders`/`get_plugin_info` HTTP calls) in `chia/data_layer/download_data.py` and `chia/data_layer/data_layer.py`: resolve the URL's host and reject loopback, link-local (`169.254.0.0/16`), RFC1918 private ranges, and other non-routable/metadata addresses unless explicitly allowed via configuration. Consider requiring an operator-configurable allowlist for mirror hosts, similar to the `store.urls` allowlist already enforced in the S3 plugin path, and re-validate on redirect responses to prevent DNS-rebinding bypass.

### Proof of Concept
1. Attacker crafts and broadcasts a standard coin spend bundle that creates a coin with puzzle hash `MIRROR_PUZZLE_HASH` (`create_mirror_puzzle()` in `chia/wallet/db_wallet/db_wallet_puzzles.py:90-91`) and a `CREATE_COIN` condition whose memos are `[launcher_id, "http://127.0.0.1:<internal-port>/"]` (or any internal/link-local target), for a `store_id` that a victim node subscribes to.
2. Once confirmed on chain, any DataLayer node tracking that `launcher_id` picks up the mirror via wallet RPC `dl_get_mirrors` and `DataLayer.update_subscriptions_from_wallet()` (`chia/data_layer/data_layer.py:979-985`), storing the attacker URL as an available server for that store.
3. On the next sync cycle, `fetch_and_validate()` (`chia/data_layer/data_layer.py:642-705`) selects this server and calls `insert_from_delta_file()` → `download_file()` → `http_download()` (`chia/data_layer/download_data.py:298-319`), issuing `GET http://127.0.0.1:<internal-port>/<delta-filename>` from the victim node's process with no host validation, confirming outbound requests to attacker-chosen internal targets. async def http_download(
    target_filename_path: Path,

    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()

def create_mirror_puzzle() -> Program:
    return P2_PARENT.curry(Program.to(1))


MIRROR_PUZZLE_HASH = create_mirror_puzzle().get_tree_hash()


def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]

    async def handle_download(self, request: web.Request) -> web.Response:
        self.update_instance_from_config()
        try:
            data = await request.json()
        except Exception as e:
            log.error(f"failed parsing request {request} {type(e).__name__} {e}")
            return web.json_response({"handle_download": False})

        store_id = bytes32.from_hexstr(data["store_id"])
        parse_result = urlparse(data["url"])
        for store in self.stores:
            if store.id == store_id and parse_result.scheme == "s3" and data["url"] in store.urls:
                return web.json_response({"handle_download": True, "urls": list(store.urls)})

        return web.json_response({"handle_download": False})

    async def download(self, request: web.Request) -> web.Response:
        try:
            data = await request.json()
            url = data["url"]
            filename = data["filename"]
            group_files_by_store = data.get("group_files_by_store", False)
            max_delta_file_size = data.get("max_delta_file_size")
            if not isinstance(max_delta_file_size, int) or max_delta_file_size <= 0:
                max_delta_file_size = 250

            # filename must follow the DataLayer naming convention
            if not is_filename_valid(filename, group_files_by_store):
                return web.json_response({"downloaded": False})

            # Pull the store_id from the filename to make sure we only download for configured stores
            filename_store_id = bytes32.fromhex(filename[:64])
            parse_result = urlparse(url)
            should_download = False
            for store in self.stores:
                if store.id == filename_store_id and parse_result.scheme == "s3" and url in store.urls:
                    should_download = True
                    break

            if not should_download:
                return web.json_response({"downloaded": False})
