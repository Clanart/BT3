### Title
Unhandled `IndexError` in `is_atom_canonical()`/`is_clvm_canonical()` on malformed puzzle_reveal/solution causes mempool spend-bundle processing to crash - (File: chia/full_node/mempool_manager.py)

### Summary
`is_atom_canonical()` parses a CLVM atom length-prefix byte and then unconditionally indexes further bytes out of `clvm_buffer` based on the decoded prefix length, without ever checking that the buffer actually contains that many bytes. [2](#0-1) 
It is invoked from `is_clvm_canonical()`, which is called unconditionally on every coin spend's `puzzle_reveal` and `solution` bytes inside `MempoolManager.validate_spend_bundle()` as part of ordinary mempool admission of a submitted `SpendBundle`. [3](#0-2) [4](#0-3) 

### Finding Description
This is analogous to CVE-2016-10325's root cause: a length field taken from attacker-controlled serialized data is used to index/read further bytes without validating it against the actual buffer size, in a hand-rolled low-level parser that runs on untrusted input before any other structural validation of that region completes.

In `is_atom_canonical(clvm_buffer, offset)`, the number of additional length-prefix bytes (`prefix_len`, up to 5) is derived purely from the top bits of a single byte at `offset`. The function then loops `prefix_len` times, each iteration doing `offset += 1; atom_len |= clvm_buffer[offset]` with no bound check against `len(clvm_buffer)`. [5](#0-4) 
Likewise, `is_clvm_canonical()`'s outer loop reads `b = clvm_buffer[offset]` at the top of every iteration and advances `offset` by `atom_len` (an attacker-controlled value with no upper bound check against remaining buffer length) after processing an atom, then loops back to index `clvm_buffer[offset]` again. [6](#0-5) 

Because Python `bytes` objects raise `IndexError` on out-of-range access rather than performing an unchecked memory read (unlike the C-level heap overflow in libosip2), the practical consequence in this codebase is not memory corruption but an unhandled Python exception. The call site in `validate_spend_bundle()` does not wrap `is_clvm_canonical(...)` in any `try/except`. [1](#0-0) 
An uncaught `IndexError` propagating out of `validate_spend_bundle()`/`add_spend_bundle()` would abort mempool processing of that spend bundle without producing the expected `SpendBundleAddInfo`/`Err` result, which is a spend-triggered transaction-processing halt for that code path, reachable by any unprivileged submitter of a crafted `SpendBundle`.

### Impact Explanation
A single unprivileged party can submit a `SpendBundle` whose `puzzle_reveal` or `solution` bytes are shaped so a decoded atom-length prefix byte claims more prefix bytes than actually remain in the buffer (e.g., ending the buffer right after such a length-prefix byte, or making `atom_len`/`offset` walk past the end after a pair token). This triggers an unhandled `IndexError` inside mempool admission instead of the intended `INVALID_COIN_SOLUTION` rejection, disrupting processing of that bundle and, depending on how the exception propagates through the mempool manager's calling code/task, potentially the surrounding mempool-processing task.

### Likelihood Explanation
The parser is reachable by any peer/wallet capable of submitting a spend bundle, requires no signature validity or special coin ownership (the check runs before/alongside other spend validation on raw `puzzle_reveal`/`solution` bytes), and the crafted encoding needed (a truncated multi-byte atom length prefix, or the pair/offset-walk scenario in `is_clvm_canonical`) is trivial to construct by hand, as evidenced by the existing test suite's dedicated non-canonical/overflow test vectors for exactly this parser. [7](#0-6) 

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before each `clvm_buffer[offset]` access (raise/return a canonical=False result once `offset >= len(clvm_buffer)` instead of indexing), and add an equivalent bound check in the `is_clvm_canonical()` main loop before dereferencing `clvm_buffer[offset]` on every iteration, mirroring the defensive `len(buf) < N` / `n > len(buf)` checks already used elsewhere in the codebase's binary parsers (e.g., `chia/full_node/full_block_utils.py`'s `skip_bytes`/`skip_list`). [8](#0-7) 
As defense in depth, wrap the `is_clvm_canonical(...)` calls in `validate_spend_bundle()` to translate any unexpected exception into `Err.INVALID_COIN_SOLUTION` rather than letting it propagate.

### Proof of Concept
Construct a `puzzle_reveal` (or `solution`) byte string ending immediately after a multi-byte atom length-prefix marker, e.g. `bytes.fromhex("f8")` (a 5-length-prefix-byte marker with zero trailing bytes) or `bytes.fromhex("f800")` (only 1 of 4 required trailing length bytes present). Submitting a `SpendBundle` whose `coin_spend.puzzle_reveal`/`solution` equals such a truncated blob and calling `is_clvm_canonical(blob)` (as done automatically in `MempoolManager.validate_spend_bundle()`) raises an unhandled `IndexError` instead of returning `False`/triggering `Err.INVALID_COIN_SOLUTION`, since the existing non-canonical test vectors only exercise buffers with the full (but oversized) length-prefix bytes present and do not test truncation short of that. [7](#0-6)

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

```python
def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

```python
def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
```
