## Analysis

The CVE describes a division/floating-point exception due to unvalidated input causing a crash (DoS). Searching the Kaia codebase for an analogous unguarded-division bug reachable through an in-scope governance parameter, I found one in the KIP-71 (Magma) dynamic base fee calculation.

### Title
Division-by-zero panic in KIP-71 base fee calculation when GasTarget governance parameter is set to zero - (File: params/kip71_config.go)

### Summary
`KIP71Config.NextMagmaBlockBaseFee` divides by the governance-controlled `GasTarget` parameter without checking for zero, unlike the sibling `BaseFeeDenominator` parameter which is explicitly guarded against a zero value.

### Finding Description
In `NextMagmaBlockBaseFee`, when the parent block's gas usage differs from `gasTarget`, the code computes:
```go
gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget) // or gasTarget - parentGasUsed
x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
y := x.Div(x, new(big.Int).SetUint64(gasTarget))
``` [1](#0-0) 

Note that `BaseFeeDenominator` is explicitly protected against zero (falling back to 64) a few lines earlier:
```go
if kc.BaseFeeDenominator == 0 {
    baseFeeDenominator = new(big.Int).SetUint64(64)
} else {
    baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
}
gasTarget := kc.GasTarget
``` [2](#0-1) 

`gasTarget`, however, has no equivalent guard. If `gasTarget == 0`, any block whose `parentGasUsed != 0` (i.e., almost every real block, since it will be `> gasTarget`) enters the `parentGasUsed > gasTarget` branch and divides by `big.NewInt(0)`, which triggers a runtime panic in Go's `math/big.Int.Div` (division by zero).

This is directly reachable because `GasTarget` is a mutable governance parameter, `Kip71GasTarget`, and its format checker performs no validation at all:
```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: noopFormatChecker,
    ...
    DefaultValue: uint64(30000000),
},
``` [3](#0-2) 

By contrast, `Kip71BaseFeeDenominator`'s format checker explicitly rejects zero:
```go
Kip71BaseFeeDenominator: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0
    },
    ...
},
``` [4](#0-3) 

This asymmetry confirms the missing check is a genuine oversight rather than an intentional design choice.

`NextMagmaBlockBaseFee` is invoked on every block by all core paths that must agree on the network state: block assembly in `work/worker.go`, header verification in the KIP-71 config's `VerifyMagmaHeader`, the fee-history/gas-price oracle in `node/cn/gasprice/feehistory.go` and `node/cn/gasprice/gasprice.go`, transaction pool pricing in `blockchain/tx_pool.go`, and block generation helpers in `blockchain/chain_makers.go`. [5](#0-4) 

### Impact Explanation
If governance sets `Kip71GasTarget` to `0` (accepted because of the missing format check), every full node computing the next block's base fee — during block production, block header verification, `eth_feeHistory`/gas price suggestion RPCs, or mempool admission — will panic with a division-by-zero as soon as a block with non-zero gas usage is processed. Because this logic executes identically on every honest node (it is a deterministic protocol computation, not attacker-supplied data), the result is a synchronized crash of the entire network — a consensus-halting denial of service, not merely a single node's DoS.

### Likelihood Explanation
Requires a governance parameter change (`Kip71GasTarget = 0`) to be voted in, which is an in-scope "governance parameters" pathway per the assessment rules. Once the value is accepted (nothing in the code path rejects it), the panic is deterministic and unavoidable on the very next block that uses any gas, making exploitation certain once the parameter is set.

### Recommendation
Add a zero-check for `GasTarget` in `NextMagmaBlockBaseFee` analogous to the existing `BaseFeeDenominator` guard (fail closed to a safe default or reject the value), and/or update the `Kip71GasTarget` `FormatChecker` in `kaiax/gov/param.go` to reject `v == 0`, mirroring `Kip71BaseFeeDenominator`.

### Proof of Concept
1. Submit and pass a governance vote (or set genesis config) that sets `governance.kip71.gastarget` (`Kip71GasTarget`) to `0`. The `noopFormatChecker` accepts this value without error. [3](#0-2) 
2. Once the parameter takes effect at the next epoch, any subsequent block with `GasUsed > 0` causes `NextMagmaBlockBaseFee` to execute `x.Div(x, new(big.Int).SetUint64(0))`. [6](#0-5) 
3. This function is called by every node during block assembly/validation (`work/worker.go`, header verification, `node/cn/gasprice`), so all nodes panic simultaneously, halting the chain.
