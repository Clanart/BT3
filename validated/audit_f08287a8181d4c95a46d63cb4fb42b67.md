### Title
Empty aggregate Schnorr signature verifies as valid - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::verify` accepts an aggregate containing zero nonces and a zero scalar when the caller supplies an empty signer/challenge list. An attacker-controlled serialization consisting of a zero `Rs` length followed by a canonical zero scalar therefore verifies successfully, even though `SchnorrAggregator::complete` explicitly refuses to construct an empty aggregate. [1](#0-0) [2](#0-1) 

### Finding Description
`SchnorrAggregate::read` accepts a length prefix of zero, leaving `Rs` empty, and then reads `s` normally. [1](#0-0) 

During verification, the only consistency check is `self.Rs.len() == keys_and_challenges.len()`. [3](#0-2) 

For an empty signature and empty signer list, no per-signer statements are added; verification reduces to checking that `-0 * G` is the identity, which always succeeds. [4](#0-3) 

This contradicts the constructor path, where `SchnorrAggregator::complete` returns `None` if no signatures were aggregated. [5](#0-4) 

### Impact Explanation
An unprivileged party can forge an aggregate signature for an empty signer set. Any verifier that calls `SchnorrAggregate::verify` without separately enforcing at least one authorized signer can treat a byte string representing `([], 0)` as a successful authorization. [6](#0-5) 

### Likelihood Explanation
The attack requires an application to verify an aggregate against an empty signer set without enforcing a nonzero quorum elsewhere. The exposed verification API does not perform that check itself, and callers passing untrusted `signers`/aggregate bytes can reach the condition directly. [7](#0-6) 

### Recommendation
Reject empty aggregates in both `SchnorrAggregate::read`/`verify` or require `keys_and_challenges.len() > 0` before accepting the identity equation. The deserialization and verification behavior should match `SchnorrAggregator::complete`, which already treats an empty aggregation as invalid. [2](#0-1) 

### Proof of Concept
For a ciphersuite whose canonical zero scalar encoding is 32 zero bytes, the serialized malicious aggregate is:

```rust
let mut encoded = Vec::new();
encoded.extend_from_slice(&0u32.to_le_bytes()); // zero Rs
encoded.extend_from_slice(&[0u8; 32]);          // s = 0

let aggregate = SchnorrAggregate::<Ristretto>::read(&mut encoded.as_slice()).unwrap();
assert!(aggregate.verify(b"application-dst", &[]));
```

The assertion succeeds because `read` accepts zero `Rs`, `verify` accepts matching empty lists, and the resulting multiexponentiation contains only `-0 * G`, which is the identity. [1](#0-0) [6](#0-5)
