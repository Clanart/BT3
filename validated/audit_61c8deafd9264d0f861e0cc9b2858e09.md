## Analog Found

### Title
Bank Precompile `sendNative` Bypasses `BlockedAddr` and Send-Enabled Policy Checks by Calling `SendCoinsAndWei` Directly - (File: precompiles/bank/bank.go)

### Summary
The HackerOne report describes a policy bypass where a low-level, unrestricted binding (`process.binding`) is used to perform an operation that a higher-level, policy-checked API (`require`) would otherwise reject. In sei-chain, the same bug class exists in the EVM bank precompile: `MsgSend`, processed through `bank/keeper/msg_server.go`, enforces `IsSendEnabledCoins`, `IsInDenomAllowList`, and `BlockedAddr` before moving funds [1](#0-0) . But the `sendNative` method of the bank precompile — the path EVM value-transfer transactions actually go through — calls `BankKeeper.SendCoinsAndWei` directly, skipping those checks entirely.

### Finding Description
`x/bank`'s `SendKeeper` interface exposes both a policy-enforcing message-server entrypoint and lower-level primitives (`SendCoins`, `SendCoinsAndWei`) that perform no policy checks themselves [2](#0-1) . The Cosmos SDK convention is that `BlockedAddr`, `IsSendEnabledCoins`, and `IsInDenomAllowList` are enforced once, at the `msgServer.Send`/`MultiSend` layer, immediately before calling `SendCoins`: [1](#0-0) 

The EVM bank precompile's `send` method (used for ERC20-native-pointer transfers) correctly routes through this checked entrypoint via `p.bankMsgServer.Send(...)`: [3](#0-2) 

However, `sendNative` — the method invoked whenever an EVM transaction carries `value` (i.e. any plain native-usei/wei transfer made through the EVM, which is the default fund-movement path for every EVM transaction) — calls `p.bankKeeper.SendCoinsAndWei` directly, with no `BlockedAddr` check and no `IsSendEnabledCoins` check on the receiver or sender: [4](#0-3) 

`BlockedAddr` exists specifically to stop external actors from pushing funds into fixed module accounts (fee collector, distribution, gov, etc.) that assume all their balance changes are mediated by the owning module's own accounting logic; a direct, unmediated transfer into such an account is the state-machine equivalent of what `policy.json`'s `dependencies: {}` was supposed to prevent — arbitrary code (here, an arbitrary receiver) reaching a keeper method that the "policy" layer (`msgServer.Send`) was designed to gate.

### Impact Explanation
Since every plain-value EVM transaction goes through the bank precompile's `sendNative` path (this is how usei/wei transfers are represented at the EVM level), any EVM sender can send native `usei`/`wei` to any Cosmos module account normally protected by `BlockedAddr` (e.g. `distribution`, `gov`, `mint`, `feecollector`), bypassing the same restriction that a plain `MsgSend` would enforce. Landing funds in these accounts outside of the module's own bookkeeping can corrupt module invariants that assume "only I move my own balance" (e.g., fee-collector or distribution pool balances used in end-block distribution math), leading to unaccounted-for balances, invariant-check panics/chain halts on `assertInvariants`-style checks, or funds becoming permanently stuck/unspendable by the intended module logic. It also silently bypasses the `IsSendEnabledCoins` governance-controlled kill switch for the base denom, letting a sender move `usei` through the EVM even after governance has disabled `usei` transfers via `Params.DefaultSendEnabled`/`SendEnabled`.

### Likelihood Explanation
Trivially reachable by any unprivileged EVM transaction sender: simply send a normal value-carrying EVM transaction (or call `bank.sendNative` directly) targeting a known module account's associated Sei/EVM address. No special privileges, no CosmWasm, no precompile whitelisting — this is the default fund-movement path for the EVM side of the chain.

### Recommendation
In `precompiles/bank/bank.go`'s `sendNative` (and any other precompile/internal path that calls `SendCoinsAndWei`/`SendCoins` directly rather than through `msgServer.Send`), add the same `BlockedAddr(receiverSeiAddr)` and `IsSendEnabledCoins` checks that `msgServer.Send` performs before allowing the transfer, or centralize these checks inside `BaseSendKeeper.SendCoinsAndWei`/`SendCoins` themselves so no caller can bypass them by using the lower-level keeper API directly.

### Proof of Concept
1. Identify a Cosmos module account registered in `blockedAddrs` (e.g. the `distribution` or `gov` module account) and derive/associate its EVM address (or use the `addr` precompile's `getEvmAddress`).
2. From any funded EVM account, send a plain value transaction (or call the bank precompile's `sendNative(receiver)` payable method) with that module account's Sei address as `receiver` and `msg.value` set to a nonzero wei amount.
3. Observe the transfer succeeds and credits the module account's `usei` balance, whereas the equivalent `MsgSend` via `bank/keeper/msg_server.go` would fail with `"... is not allowed to receive funds"` because of the `BlockedAddr` check [5](#0-4) .

Note: I was not able to fully trace end-to-end whether every well-known module account is actually populated in `blockedAddrs` at app-wiring time (that wiring lives in `app.go` and wasn't inspected in this session), nor confirm a specific invariant-panic scenario triggered by such a credit — a Devin session with full repo access would be needed to enumerate the exact `blockedAddrs` set and demonstrate concrete on-chain impact.

func (k msgServer) Send(goCtx context.Context, msg *types.MsgSend) (*types.MsgSendResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	if err := k.IsSendEnabledCoins(ctx, msg.Amount...); err != nil {
		return nil, err
	}

	from, err := sdk.AccAddressFromBech32(msg.FromAddress)
	if err != nil {
		return nil, err
	}
	to, err := sdk.AccAddressFromBech32(msg.ToAddress)
	if err != nil {
		return nil, err
	}

	allowListCache := make(map[string]AllowedAddresses)
	if !k.IsInDenomAllowList(ctx, from, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to send funds", msg.FromAddress)
	}

	if k.BlockedAddr(to) || !k.IsInDenomAllowList(ctx, to, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", msg.ToAddress)
	}

func (p PrecompileExecutor) sendNative(ctx sdk.Context, method *abi.Method, args []interface{}, caller common.Address, callingContract common.Address, value *big.Int, readOnly bool, hooks *tracing.Hooks, evm *vm.EVM) ([]byte, uint64, error) {
	if readOnly {
		return nil, 0, errors.New("cannot call sendNative from staticcall")
	}
	if ctx.EVMPrecompileCalledFromDelegateCall() {
		return nil, 0, errors.New("cannot delegatecall sendNative")
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	if value == nil || value.Sign() == 0 {
		return nil, 0, errors.New("set `value` field to non-zero to send")
	}

	senderSeiAddr, ok := p.evmKeeper.GetSeiAddress(ctx, caller)
	if !ok {
		return nil, 0, errors.New("invalid addr")
	}

	receiverAddr, ok := (args[0]).(string)
	if !ok || receiverAddr == "" {
		return nil, 0, errors.New("invalid addr")
	}

	receiverSeiAddr, err := sdk.AccAddressFromBech32(receiverAddr)
	if err != nil {
		return nil, 0, err
	}

	usei, wei, err := pcommon.HandlePaymentUseiWei(ctx, p.evmKeeper.GetSeiAddressOrDefault(ctx, p.address), senderSeiAddr, value, p.bankKeeper, p.evmKeeper, hooks, evm.GetDepth())
	if err != nil {
		return nil, 0, err
	}

	if err := p.bankKeeper.SendCoinsAndWei(ctx, senderSeiAddr, receiverSeiAddr, usei, wei); err != nil {
		return nil, 0, err
	}
	accExists := p.accountKeeper.HasAccount(ctx, receiverSeiAddr)
	if !accExists {
		defer metrics.RecordBankNewAccount(ctx.Context())
		p.accountKeeper.SetAccount(ctx, p.accountKeeper.NewAccountWithAddress(ctx, receiverSeiAddr))
	}

	if hooks != nil {
		newCtx := ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx))
		remainingGas := pcommon.GetRemainingGas(newCtx, p.evmKeeper)
		if hooks.OnEnter != nil {
			hooks.OnEnter(evm.GetDepth()+1, byte(vm.CALL), caller, p.evmKeeper.GetEVMAddressOrDefault(newCtx, receiverSeiAddr), []byte{}, remainingGas, value)
		}
		defer func() {
			if hooks.OnExit != nil {
				hooks.OnExit(evm.GetDepth()+1, []byte{}, 0, nil, false)
			}
		}()
	}

	bz, err := method.Outputs.Pack(true)
	return bz, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
