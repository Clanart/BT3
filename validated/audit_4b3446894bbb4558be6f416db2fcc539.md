## Answer

`writeGitAttributes` performs **no `lstat`/symlink check at all**. It simply joins the path and calls Node's `writeFile`, which follows symlinks by default: [1](#0-0) 

The only pre-write guard is in the caller, `createRepository` in `create-repository.tsx`, which checks `pathExists(gitAttributes)` before invoking `writeGitAttributes`: [2](#0-1) 

`pathExists` is implemented via `fs.access`, which resolves symlinks and only reports whether the resolved target exists — it never distinguishes a regular file from a symlink: [3](#0-2) 

### Proof idea confirmed
If `.gitattributes` inside the target folder is a **symlink whose target does not yet exist**, `access()` fails to resolve it, so `pathExists` returns `false`. `gitAttributesExists` is then `false`, and `writeGitAttributes(fullPath)` is invoked. Node's `fs.promises.writeFile` opens the path with default flags (`O_CREAT | O_TRUNC | O_WRONLY`, no `O_NOFOLLOW`), so it follows the symlink and creates/writes the file at whatever location the symlink points to — outside the repository directory, if the parent directory of the symlink's target exists and is writable by the current process. If the symlink target already exists, `pathExists` returns `true` and the write is skipped, but that just avoids clobbering existing files — it doesn't add any symlink-type rejection.

### Title
Arbitrary file write via symlinked `.gitattributes` when creating a repository from untrusted folder content - (File: `git-attributes.ts`)

### Summary
`writeGitAttributes` writes to the `.gitattributes` path without checking whether that path is a symlink. The only existence guard in `create-repository.tsx` uses `pathExists`, which follows symlinks and checks only for target existence, not link type, so it cannot prevent the write from following a symlink to a location outside the repository.

### Finding Description
When a user creates a new repository from an existing folder (`File > New Repository`, pointing at a folder that already has files but no `.git`), Desktop calls `writeGitAttributes(fullPath)` unless `pathExists` reports the `.gitattributes` file already exists. If an attacker plants a symlink named `.gitattributes` in that folder (e.g. distributed as a zip/tarball or otherwise attacker-controlled content the victim extracts and then points "Create Repository" at) pointing to a not-yet-existing path such as a startup script, shell profile, or other writable location whose parent directory exists, `pathExists` resolves the symlink, finds the target missing, and returns `false`. `writeGitAttributes` then calls `writeFile(fullPath, contents)` which follows the symlink and creates/writes the attacker-chosen target file with fixed content controlled by Desktop (`# Auto detect text files...`) at the symlink's destination.

### Impact Explanation
This allows an attacker who controls the initial folder content to cause Desktop to create/write a file at an arbitrary filesystem location reachable by the user (limited to locations where the parent directory exists and the process has write permission), outside the repository directory. Depending on the target chosen (e.g. a shell rc file, autostart entry), this can escalate to code execution on next shell/session start.

### Likelihood Explanation
Requires the victim to run "Create Repository" (not "Add existing repository") against a folder whose content is attacker-controlled and that is not already a `.git` repository (e.g. extracted from a downloaded archive/template). This is a plausible but non-trivial user workflow, and the write is limited to fixed, non-attacker-controlled content and requires the parent directory of the symlink target to pre-exist.

### Recommendation
Before calling `writeFile` in `writeGitAttributes` (and in the `pathExists` check in `create-repository.tsx`), use `fs.lstat`/`fs.promises.lstat` on the `.gitattributes` path to detect a symlink and reject/abort instead of following it, or open the file with the `wx` flag combined with an `O_NOFOLLOW`-equivalent check.

### Proof of Concept
1. Create a folder `demo/` containing a symlink `demo/.gitattributes -> /some/writable/not-yet-existing/target`.
2. In GitHub Desktop, choose `File > New Repository`, set the path to `demo/`.
3. Observe `pathExists(join(demo, '.gitattributes'))` returns `false` (target doesn't exist yet), so `writeGitAttributes(demo)` runs and `writeFile` follows the symlink, creating `/some/writable/not-yet-existing/target` with Desktop's default `.gitattributes` content.

```typescript
import { access } from 'fs/promises'
import constant from 'lodash/constant'

/**
 * Returns a value indicating whether or not the provided path exists (as in
 * whether it's visible to the current process or not).
 */
export const pathExists = (path: string) =>
  access(path).then(constant(true), constant(false))
```
