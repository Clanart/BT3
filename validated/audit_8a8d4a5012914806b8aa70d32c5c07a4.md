### Title
GaslessSwapRouter owner can front-run a pending `swapForGas` transaction by remapping a token's AMM route, stealing gasless-swap proceeds - (File: `kaiax/gasless/impl/getter.go`, `kaiax/gasless/impl/tx_pool.go`, `contracts/bindings/kip247/GaslessSwapRouter.go`)

### Summary
The `GaslessSwapRouter` contract's owner controls per-token routing (`addToken(token, factory, router)` / `removeToken(token)`), and the Kaia node's `kaiax/gasless` module re-reads this router/token configuration from chain state on every block to decide whether an `approve` + `swapForGas` transaction pair is a valid "gasless" bundle eligible for gas-lending and execution. Because the on-chain routing/whitelist can be changed by the router owner at any time — including in direct response to seeing a pending gasless swap in the mempool — the owner can race-condition a user's signed `swapForGas` transaction: front-run it with `addToken`/`removeToken` to redirect the swap through an attacker-controlled factory/router pair (or invalidate the token) and capture the swap proceeds or grief the user, exactly analogous to the reported `TellerV2Context` "trusted forwarder" race condition where a privileged owner changes routing configuration to intercept an in-flight signed transaction.

### Finding Description
The `GaslessSwapRouter` exposes owner-only administrative functions to (re)configure per-token trading routes and the allowed token set: [1](#0-0) [2](#0-1) 

The `kaiax/gasless` module reads the current `swapRouter` address and `allowedTokens` set directly from live chain state (via the system Registry/MultiCall contract) once per block header, and uses that snapshot to validate whether a pending `approve`/`swapForGas` transaction is a legitimate gasless bundle: [3](#0-2) 

The validity checks (`isApproveTx`, `isSwapTx`) depend entirely on this mutable, owner-controlled state (`g.allowedTokens`, `g.swapRouter`), which can change between the time a user signs and submits `approve`+`swapForGas`, and the time the swap is actually executed by a block proposer: [4](#0-3) 

Additionally, `checkBalanceForSwap` calls the live `GaslessSwapRouter` contract (`GetAmountIn`) at validation time to compute the required `amountIn`, meaning the swap's expected exchange rate/route is whatever the router currently reports — which the owner can change (e.g., via `addToken` remapping a token to a different `factory`/`router` pair) right before the swap is executed: [5](#0-4) 

Because the user's signed `swapForGas` transaction only fixes `token`, `amountIn`, `minAmountOut`, `amountRepay`, and `deadline` — not the AMM factory/router pair used internally by `GaslessSwapRouter` for that token — the owner can front-run the pending, already-signed swap transaction with an `addToken(token, maliciousFactory, maliciousRouter)` call. When the user's transaction subsequently executes, `swapForGas` will route the trade through the attacker-controlled pair, allowing the owner to extract value from the swap (e.g., sandwich the trade or divert output) while still satisfying the `minAmountOut`/`amountRepay` constraints checked at submission time (since those were computed against the router's state *before* the owner's front-run).

This mirrors the reported class of bug precisely: a privileged, non-consensus-critical role (here, the router owner, analogous to the "market owner" in the original report) can observe a signed, in-flight, gas-delegated transaction in the mempool and unilaterally change trusted routing/forwarder configuration to intercept or invalidate it before it lands on-chain.

### Impact Explanation
An attacker who is the `GaslessSwapRouter` owner can:
1. Grief users by front-running a pending `swapForGas` with `removeToken`, causing the previously-validated gasless bundle to be dropped by the `kaiax/gasless` module's `isSwapTx`/`isApproveTx` checks (denial of gas-lending service), stranding a user's already-executed `approve` transaction.
2. More severely, front-run with `addToken` to swap in a malicious `factory`/`router` for the token, causing the user's already-signed `swapForGas` execution to trade against an attacker-controlled AMM pair and extract value from the trade — concrete unauthorized value movement / gasless-swap settlement theft, which falls squarely within the accepted impact categories (gasless settlement theft).

### Likelihood Explanation
The owner of `GaslessSwapRouter` is an ordinary, unprivileged-relative-to-consensus EOA (an `Ownable` contract admin), reachable purely by submitting normal transactions (`addToken`/`removeToken`) — no node, validator, or P2P privilege is required. Any pending `swapForGas` transaction is visible in the public mempool before inclusion, so the owner can trivially observe and front-run it with a higher-fee `addToken`/`removeToken` call. This requires no special timing beyond normal transaction ordering/fee bidding, making the race condition straightforward to execute for anyone controlling the router's ownership key.

### Recommendation
Bind the token's factory/router pair (or a commitment/hash of it) into the user-signed `swapForGas` call itself (e.g., pass expected `factory`/`router` as parameters and revert if they don't match current storage), so a change by the owner between signing and execution causes the transaction to revert rather than silently execute through a different route. Alternatively, enforce a timelock/delay on `addToken`/`removeToken` changes so in-flight transactions have a guaranteed window to either execute against the old configuration or be safely invalidated before the new configuration takes effect.

### Proof of Concept
1. User signs and broadcasts `approve(router, MaxUint)` followed by `swapForGas(token, amountIn, minAmountOut, amountRepay, deadline)` for `token` currently mapped to `factory_A`/`router_A` (per `kip247.GaslessSwapRouter.AddToken`). [1](#0-0) 
2. The `kaiax/gasless` module validates the pair against the current on-chain snapshot (`g.swapRouter`, `g.allowedTokens`, and a live `GetAmountIn` call), which are refreshed per-block from chain state. [3](#0-2) [6](#0-5) 
3. Before the user's `swapForGas` is included, the router owner submits `addToken(token, factory_B, router_B)` (attacker-controlled pair) with sufficient gas price to be mined first. [1](#0-0) 
4. When the user's `swapForGas` executes afterward, it settles through `factory_B`/`router_B`, letting the owner capture value from the trade or manipulate `minAmountOut` fulfillment, while the user's transaction still nominally satisfies the checks performed against the router's now-current (attacker-favorable) state.

Note: The exact internal logic of `GaslessSwapRouter.swapForGas` (Solidity source) was not available in the indexed codebase — only its compiled bytecode and Go bindings were found — so the precise on-chain mechanics of how `factory`/`router` per token affect swap execution could not be fully verified from source. This is inferred from the `AddToken(token, factory, router)`/`RemoveToken(token)` ABI surface and the module's dependence on live, owner-mutable router state for transaction validation.

func (g *GaslessModule) isApproveTx(args *ApproveArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.allowedTokens[args.Token] && // A1
		g.swapRouter == args.Spender && // A3
		args.Amount.Cmp(abi.MaxUint256) == 0 // A4
}

// IsSwapTx checks following conditions:
// S1. tx.to is a whitelisted SwapRouter contract.

func (g *GaslessModule) IsSwapTx(tx *types.Transaction) bool {

	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.swapRouter == args.Router && // S1

func (g *GaslessModule) updateAddresses(header *types.Header) error {
	g.gaslessInfoMu.Lock()
	defer g.gaslessInfoMu.Unlock()

	swapRouter, tokens, err := getGaslessInfo(g.Chain, header)
	// proceed even if there is something wrong with multicall contract
	if err != nil {
		g.swapRouter = common.Address{}
		g.allowedTokens = map[common.Address]bool{}
		logger.Warn("there is something wrong with multicall contract", "err", err.Error())
		return nil
	}

	g.swapRouter = swapRouter

	g.allowedTokens = map[common.Address]bool{}
	for _, addr := range tokens {
		// all tokens are allowed if nil
		if g.GaslessConfig.AllowedTokens == nil {
			g.allowedTokens[addr] = true
		}
		for _, allowed := range g.GaslessConfig.AllowedTokens {
			if addr == allowed {
				g.allowedTokens[addr] = true
			}
		}
	}

	return nil
}

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
