### Title
Untracked/touched filenames are passed as unescaped git pathspecs, letting a crafted filename widen `git add --intent-to-add` / `git diff` scope beyond the intended files - (File: `plugins/security-guidance/hooks/gitutil.py`)

### Summary
`_temp_index` and `_diff_pathspec` build `git add --intent-to-add -- <paths>` and `git diff ... -- <paths>` argument lists directly from on-disk filenames (untracked paths from `git status --porcelain`, or repo-relative paths from `_diff_pathspec`) without disabling git's pathspec magic. A filename containing glob wildcards (`*`, `?`, `[...]`) or beginning with `:` (pathspec magic signature, e.g. `:(exclude)`, `:(icase)`, `:!`) is a legal POSIX filename but is re-interpreted by git as a pattern/magic pathspec rather than a literal path, letting an attacker-controlled filename widen or redirect which files get intent-to-added and diffed.

### Finding Description
`_temp_index` (`plugins/security-guidance/hooks/gitutil.py:91-141`) receives `untracked_paths` (repo-root-relative paths sourced from `git status --porcelain` via `compute_v2_review_set`/`_git_status_porcelain` in `diffstate.py`), filters only for existence with `os.path.lexists`, and then runs: [1](#0-0) 

```
add_args = ["--"] + surviving if surviving else None
...
subprocess.run([*GIT_CMD, "add", "--intent-to-add"] + add_args, cwd=cwd, ..., env=env)
```

None of `GIT_CMD`, this call, or `_diff_pathspec` (`gitutil.py:70-88`) set `--literal-pathspecs`, `GIT_LITERAL_PATHSPECS=1`, or prefix entries with `:(literal)`. Git's default pathspec grammar treats `*`, `?`, `[]` as glob wildcards and a leading `:` as the start of pathspec "magic" (`:(exclude)`, `:(icase)`, `:(glob)`, `:!`, etc.), even after the `--` separator. Both `*` and a leading `:` are valid characters in POSIX filenames, so an attacker who can get a maliciously-named untracked file into the worktree (e.g. via a crafted repo, archive, or generated content that Claude/the user later touches) creates a filename that git will parse as a pattern instead of a literal path.

Concretely:
- An untracked file literally named `*` (or `*.env`, `**`) passed to `git add --intent-to-add -- *` will match and intent-to-add every currently-untracked file in the worktree that matches the glob, not just the single crafted file, widening the "untracked-file inclusion for diff review" set beyond what `compute_v2_review_set` intended.
- A filename beginning with `:` can be parsed as pathspec magic (e.g. `:(exclude)...`, `:!...`), changing include/exclude semantics of the whole pathspec list passed after `--` to `git add`/`git diff`.
- The same unescaped construction is used in `_diff_pathspec` (`get_git_diff`, `gitutil.py:391-427`) for the actual `git diff -- <pathspec>` restriction, so a touched/on-disk path with these characters can also broaden the diff pathspec used for the LLM review.

The result: the diff/temp-index content handed to `get_git_diff` → `analyze_code_security`/`agentic_review` (which sends the diff to the Anthropic API) can include files outside the intended repo-diff scope — breaking the stated invariant that "git path scoping must never escape the intended repo target."

Existing checks (`os.path.lexists` survival filter, `_diff_pathspec`'s realpath/`..`-prefix drop) only guard against missing files or paths escaping `cwd` via `..`/symlinks; they do not sanitize or escape glob/magic pathspec characters embedded in a legitimate, existing, in-repo filename.

### Impact Explanation
If exploited, extra in-repo files (potentially containing secrets, credentials, or other unrelated source) get intent-to-added and included in the diff that is sent to the Anthropic API for review, and/or unrelated files get excluded from review via `:(exclude)` magic, silencing intended review coverage. This matches the "Sensitive code, prompt, token, diff, or local file disclosure to an unintended local or remote sink" bounty impact category, since the diff payload is the direct input to a networked LLM call.

### Likelihood Explanation
Requires the attacker to get a specifically-named file (matching glob/magic pathspec syntax) into the target repository's worktree as an untracked or touched file — feasible via a malicious repository, generated artifact, downloaded archive, or content that a user/agent extracts without renaming. No admin/maintainer privilege or credential leak is needed; only the ability to introduce a file with a crafted name into the repo, which is a normal "repo-controlled file paths" scenario. The bug is deterministic and repeatable given such a filename.

### Recommendation
Force literal pathspec interpretation everywhere a filename-derived list is spliced into a git command: run these subprocess calls with `env={"GIT_LITERAL_PATHSPECS": "1", ...}` (or pass `--literal-pathspecs` as a global git option in `GIT_CMD`), or prefix every path element with the `:(literal)` magic explicitly, in both `_temp_index`'s `git add --intent-to-add` call and `_diff_pathspec`'s pathspec list consumed by `get_git_diff`.

### Proof of Concept
Integration test plan (pytest style) for `plugins/security-guidance/hooks/gitutil.py`:
1. Init a temp git repo with one commit, plus a legitimate secret file `secret.env` (untracked, NOT intended to be part of the review).
2. Create the "in-scope" untracked file the caller actually wants reviewed, named with a glob wildcard, e.g. `*.env` (valid on Linux/macOS filesystems).
3. Call `_temp_index(cwd, untracked_paths=["*.env"])` and inside the context run `git status --porcelain` against the temp index (or inspect `git ls-files -- ':(literal)*.env'` intent-to-add markers).
4. Assert (current buggy behavior): `secret.env` is ALSO marked intent-to-add even though only `*.env` was passed — i.e., the pathspec glob-matched an out-of-scope file.
5. After applying the fix (`GIT_LITERAL_PATHSPECS=1`), rerun the same test and assert only the literal file `*.env` is intent-to-added, and `secret.env` remains untouched/absent from the temp index diff.
6. A parallel test for `_diff_pathspec`/`get_git_diff`: create `weird:(exclude)name.py` and a normal `app.py`, pass both as `paths`, and assert the resulting diff still contains `app.py`'s hunk after the fix (pre-fix, the magic prefix could suppress or redirect matching).
