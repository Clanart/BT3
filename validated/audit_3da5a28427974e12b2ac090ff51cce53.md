### Title
Payout OP_RETURN operator-attribution output is unsigned and mutable, allowing reassignment of reimbursement credit - (File: core/src/builder/transaction/operator_reimburse.rs)

### Summary
The `payout_tx`'s user signature uses `TapSighashType::SinglePlusAnyoneCanPay`, which under BIP341/BIP343 only commits to input 0 and output 0. Outputs 1 (anchor) and 2 (`OP_RETURN(operator_xonly_pk)`) are entirely outside the signed message, so anyone who observes the broadcast `payout_tx` can rebroadcast a mutated version that reuses the exact same signed input/output pair but swaps the OP_RETURN payload to name a different operator, and this still passes Bitcoin's script verification. Since the bridge's off-chain accounting (`Verifier::update_finalized_payouts`) trusts the on-chain OP_RETURN bytes as the sole source of truth for "who funded this payout," this lets an attacker redirect reimbursement credit to an arbitrary operator.

### Finding Description
The binding the protocol needs to hold is:

`operator_xonly_pk recorded in DB for withdrawal i (via update_finalized_payouts/get_first_op_return_output/parse_op_return_data)` == `the operator whose funds actually paid output 0 of the confirmed payout_tx`.

`create_payout_txhandler` builds the payout transaction as: input 0 = withdrawal UTXO (KeySpend), output 0 = user payout, output 1 = anchor, output 2 = `OP_RETURN(operator_xonly_pk.serialize())`: [1](#0-0) 

The user's signature enforced by the aggregator is required to be `SinglePlusAnyoneCanPay`: [2](#0-1) 

and `Operator::withdraw` verifies it over `calculate_sighash_txin(0, in_signature.sighash_type)`: [3](#0-2) 

`SIGHASH_SINGLE` only commits to the output whose index matches the signed input (index 0); `ANYONECANPAY` commits only to that one input. Neither commits to output 1 (anchor) nor output 2 (the OP_RETURN operator attribution). This means the digest that is actually signed, and thus the script validity of the mined transaction, is completely independent of the OP_RETURN payload. An attacker who sees operator A's unconfirmed `payout_tx` in the mempool can extract input 0's witness (the valid Schnorr signature), reconstruct a transaction with the same input 0/witness and same output 0, arbitrary fee-bumping inputs/outputs, and an OP_RETURN pointing to operator B's pubkey instead of A's. This new transaction is fully valid Bitcoin-consensus-wise (the signature still verifies against the unchanged sighash) and can be pushed to confirmation first via RBF with a higher fee.

Once mined, `Verifier::update_finalized_payouts` scans the block, extracts the operator attribution purely from `get_first_op_return_output`/`parse_op_return_data` on the confirmed transaction bytes, and persists it as the "payer" for withdrawal index i with no cross-check against who actually funded output 0: [4](#0-3) 

`PayoutCheckerTask::run_once` (running under operator B) then queries `get_first_unhandled_payout_by_operator_xonly_pk(B)`, which is driven solely by the DB column populated above: [5](#0-4) [6](#0-5) 

`Operator::handle_finalized_payout` builds and signs B's Kickoff purely from `deposit_outpoint`/`payout_tx_blockhash`, without validating who paid the withdrawal UTXO: [7](#0-6) 

Critically, the only consistency guard that exists, `Verifier::is_kickoff_malicious`, compares the kickoff's operator against `get_payout_info_from_move_txid`, but that function reads the same tainted `payout_payer_operator_xonly_pk` column populated straight from the mutable OP_RETURN — it is not an independent source of truth and does not detect the substitution: [8](#0-7) 

Thus no existing guard (`SECP.verify_schnorr`, `is_kickoff_malicious`, `verify_storage_proofs`, the bridge circuit's `deposit_constant`) actually ties the OP_RETURN operator pubkey to who funded output 0 of the payout; they all derive attribution transitively from the same unsigned byte range.

### Impact Explanation
Operator B, who never spent any BTC funding the user's withdrawal, is credited in the database as the payer and can subsequently run its normal Kickoff/Reimburse flow to claim reimbursement out of the round/collateral UTXOs it controls for that deposit's operator set — i.e., "an operator reimbursed for a payout it never funded." Simultaneously, operator A, who genuinely fronted the BTC in output 0, is permanently unable to be credited for that withdrawal index because the DB row for withdrawal i is now bound to B (`payout_payer_operator_xonly_pk = B`), and `get_first_unhandled_payout_by_operator_xonly_pk(A)` will never return this withdrawal — "an honest operator permanently unable to be reimbursed." This is repeatable for every withdrawal any operator makes, against any registered operator xonly pubkey, as long as the attacker observes the mempool and can win an RBF race; it is not limited to a single deposit/operator pair.

### Likelihood Explanation
Preconditions are modest: RBF/mempool visibility (explicitly true in the stated regtest configuration and generally true for any Bitcoin mempool), an operator that has broadcast an unconfirmed `payout_tx`, and enough attacker fee budget to win the fee race for one transaction. The attacker needs no bridge privileges — only the ability to observe/rebroadcast a public mempool transaction and pay a bitcoin transaction fee, which matches the declared "unprivileged attacker" model exactly. The construction requires no signature forgery, only wire-level malleation of unsigned output bytes, which is straightforward with any bitcoin transaction library.

### Recommendation
Change the payout signature scheme so that the OP_RETURN operator-attribution output (and ideally the anchor output) is committed by the signature — e.g. require `SIGHASH_ALL` (or `SIGHASH_ALL|ANYONECANPAY` if additional funding inputs must remain addable) for the withdrawal signature so all outputs, including the OP_RETURN, are covered; or otherwise bind the operator attribution to something enforced independently on-chain (e.g., have the operator commit to the payout by including its own signature/pubkey in the spending witness path itself rather than in a free-form, unsigned OP_RETURN output) so it cannot be rewritten without invalidating the existing user signature.

### Proof of Concept
Cargo test plan (regtest, no mainnet, no live Citrea):
1. Bring up an aggregator/operator A + operator B + verifiers test harness (existing `core/src/test` scaffolding), do a deposit and move-to-vault.
2. Call `Operator::withdraw` on operator A for withdrawal index i; capture the broadcast, unconfirmed `payout_tx` from the regtest mempool via RPC (`getmempoolentry`/`getrawtransaction`).
3. Assert on both sides of the binding before mutation:
   - `payout_tx.output[2]` OP_RETURN payload == A's `xonly_public_key`.
4. Programmatically decode `payout_tx`, keep `input[0]` (including its witness) and `output[0]` unchanged, replace `output[2]`'s OP_RETURN payload with B's xonly pubkey, add a higher-fee funding input/change output from a throwaway wallet, and rebroadcast as `payout_tx'` via `sendrawtransaction`/RBF.
5. Mine `payout_tx'` to confirmation depth; run block sync so `Verifier::update_finalized_payouts` processes it.
6. Assert on both sides of the binding after mutation:
   - DB `payout_payer_operator_xonly_pk` for withdrawal i == B's xonly pubkey (not A's), demonstrating the equality is broken.
   - `db.get_first_unhandled_payout_by_operator_xonly_pk(B)` returns `Some((i, move_txid, blockhash))`.
   - `db.get_first_unhandled_payout_by_operator_xonly_pk(A)` returns `None` (and stays `None` after `PayoutCheckerTask` runs for A).
7. Run `PayoutCheckerTask::run_once` for operator B and assert it succeeds, calling `Operator::handle_finalized_payout` for B and producing a broadcastable Kickoff transaction for B for a payout A funded.
8. Assert that operator A's attempt to call `handle_finalized_payout` (or the corresponding automation) for this deposit/withdrawal either errors (`RowNotFound`/no unhandled payout) or never triggers.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

                .get_cached_tx()
                .compute_txid();

        let payout_info = self
            .db
            .get_payout_info_from_move_txid(Some(dbtx), move_txid)
            .await?;
        let Some((operator_xonly_pk_opt, payout_blockhash, _, _)) = payout_info else {
            tracing::warn!(
                "No payout info found in db for move txid {move_txid}, assuming malicious"
            );
            return Ok(true);
        };

        let Some(operator_xonly_pk) = operator_xonly_pk_opt else {
            tracing::warn!("No operator xonly pk found in payout tx OP_RETURN, assuming malicious");
            return Ok(true);
        };

        if operator_xonly_pk != kickoff_data.operator_xonly_pk {
            tracing::warn!("Operator xonly pk for the payout does not match with the kickoff_data");
            return Ok(true);

            kickoff_data.round_idx,
            kickoff_data.kickoff_idx,
            self.config.protocol_paramset(),

            kickoff_witness,
            &[wt_derive_path],
            self.config.protocol_paramset(),
        )?;
        let blockhash_data = commits.first();
        // only last 20 bytes of the blockhash is committed
        let truncated_blockhash = &payout_blockhash[12..];
        if let Some(committed_blockhash) = blockhash_data {
            if committed_blockhash != truncated_blockhash {
                tracing::warn!("Payout blockhash does not match committed hash: committed: {:?}, truncated payout blockhash: {:?}",
                        blockhash_data, truncated_blockhash);
                return Ok(true);
            }
        } else {
            return Err(eyre::eyre!("Couldn't retrieve committed data from witness").into());
        }
        Ok(false)
    }

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }
