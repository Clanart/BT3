### Title
`updateRemoteUrl` silently repoints a repository's git remote to whatever `clone_url` the GitHub API returns, with no user confirmation - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
The report's broken invariant is: a function that fully controls where a user's git operations point (yield source ↔ git remote) trusts a single external input (an arbitrary "depositToken" contract ↔ an API-supplied `clone_url`) and swaps to it automatically, with only a shallow structural check and no ownership/user confirmation. In GitHub Desktop, `updateRemoteUrl` performs this exact pattern for the `origin` remote of a tracked repository.

### Finding Description
`updateRemoteUrl` is invoked with a `GitHubRepository` (cached local metadata) and a freshly-fetched `IAPIRepository` (`apiRepo`) coming back from the GitHub API. It compares the current `origin` remote URL to `apiRepo.clone_url` and, if the protocol scheme is unchanged and the remote had not been "manually" altered from the previously cached clone URL, it calls `gitStore.setRemoteURL(...)` and rewrites `origin` to `apiRepo.clone_url` without any user prompt: [1](#0-0) 

The only safety checks are:
1. `protocolsMatch` — https stays https, ssh stays ssh.
2. `remoteUrlUnchanged` — the current remote must still structurally match the *previously cached* `gitHubRepository.cloneURL` (via `urlMatchesRemote`, which only compares `hostname`/`owner`/`name` tokens parsed out of the URL string): [2](#0-1) 

Neither check verifies that the *new* `owner`/`name` pair returned by the API is the *same repository identity* the user originally added — it only prevents rewriting a remote the user has hand-edited to something already divergent from GitHub's records. If the API begins returning a `clone_url` with a different owner and/or name (which GitHub itself does automatically, e.g., after repository renames or transfers, or in a repo-squatting scenario where a deleted/renamed repository's old owner/name is reclaimed by a different party), Desktop will silently execute `git remote set-url origin <new-url>` — no dialog, no diff, no user acknowledgment — the exact "swap the destination for all future funds/data flow to something new because a single external signal said so" pattern from the report.

### Impact Explanation
`origin` is the destination for virtually every git push and the source for every fetch. Silently rewriting it means:
- The next `git push` a user performs can be silently redirected to a different repository than the one they believe they're pushing to, exfiltrating source code/commits to an attacker-controlled remote.
- The next `git fetch`/`pull` can silently source branches/commits from an attacker-controlled repository, corrupting what the user believes they are merging/reviewing.

This mirrors the "silent corruption of what the user commits/pushes" impact class explicitly called out as valid.

### Likelihood Explanation
The trigger condition (API returning a `clone_url` with a different owner/name than previously cached, while the local remote still matches the old cached value) is not purely hypothetical — GitHub's own rename/transfer mechanics naturally produce this. Combined with GitHub's historical repo-squatting problem (a repository name/owner can be reclaimed by a different account after deletion or after the original owner is removed), an attacker who can get a victim's cached repository to become "stale" (deleted/renamed origin) and then registers the vacated owner/name can have their `clone_url` returned by the API on the victim's next refresh, causing Desktop to auto-adopt it. I was not able to fully trace, within the available iterations, whether the app fetches this API repository record by internal ID (which would make owner/name changes benign follow-along renames) or by owner/name lookup (which would make squatting directly exploitable) — this distinction determines whether the primitive is merely "auto-follow legitimate renames" (low severity, arguably intended) or "silently adopt an attacker-controlled destination" (high severity). This should be verified against the call sites of `updateRemoteUrl` in `app/src/lib/stores/app-store.ts` before treating this as a confirmed high-severity issue.

### Recommendation
- Never silently rewrite `origin` when the API-reported owner changes; require explicit user confirmation whenever both the owner and the underlying identity (e.g., GitHub repository numeric ID) diverge from what was previously known.
- Track and compare the GitHub repository's immutable ID (not just owner/name string matching) so a renamed-then-reclaimed owner/name cannot be silently treated as "the same repository."
- Surface a visible prompt/banner ("This repository's remote has changed from X to Y, update?") instead of a fully automatic `setRemoteURL` call.

### Proof of Concept
1. User clones `https://github.com/alice/project` in Desktop; Desktop caches `GitHubRepository.cloneURL = https://github.com/alice/project`.
2. `alice` deletes/renames away from `project`, releasing the `alice/project` namespace (or the API begins reporting a different owner/name for the cached identity due to a lookup-by-name reconciliation).
3. An attacker registers `alice/project` (or otherwise causes the API to return their own repository) so that fetching repository metadata for the cached identifier returns `clone_url: https://github.com/attacker/project`.
4. On the next background refresh, `updateRemoteUrl` runs: `protocolsMatch` is true (both https), `remoteUrlUnchanged` is true (local origin still equals the old cached `alice/project` URL), and `urlsMatch` is false (owner differs) — all conditions for the silent rewrite are satisfied at `app/src/lib/stores/updates/update-remote-url.ts:42-44`.
5. Desktop calls `gitStore.setRemoteURL('origin', 'https://github.com/attacker/project')` with no user prompt; the user's next push/fetch silently targets the attacker's repository. [3](#0-2)

import { IAPIRepository } from '../../api'
import { GitStore } from '../git-store'
import { urlMatchesRemote } from '../../repository-matching'
import * as URL from 'url'
import { GitHubRepository } from '../../../models/github-repository'

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}
