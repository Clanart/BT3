### Title
DLEq verification accepts empty statements, allowing a reusable forged proof - (File: crypto/dleq/src/lib.rs)

### Summary
`DLEqProof::verify` only checks that `generators.len() == points.len()`, then iterates over the two lists before comparing `self.c` with the transcript challenge. [1](#0-0)  When both lists are empty, no generator, nonce, or point is appended to the transcript and `s` is never constrained by any verification equation. [2](#0-1) 

### Finding Description
`DLEqProof::read` deserializes an attacker-controlled `c` and `s` pair without any minimum-statement requirement. [3](#0-2)  `verify` treats an empty generator/point pair as valid because the equality check permits zero and the loop performs no work. [4](#0-3)  The resulting proof is bound only to the externally supplied transcript domain, not to any public key, generator, scalar, or statement. [5](#0-4) 

The same validation gap exists in `MultiDLEqProof::verify`: zero discrete logarithms and per-series empty lists pass the length checks, after which only the fixed challenge is checked. [6](#0-5) 

### Impact Explanation
A caller that accepts an attacker-supplied DLEq proof over a variable statement can accept a proof which does not establish discrete-log equality for any point. This is a forged proof accepted by an untrusted `DLEqProof::read` input followed by `verify`, rather than merely malformed input being rejected. [7](#0-6) 

### Likelihood Explanation
Exploitation requires a verifier to call `DLEqProof::verify` or `MultiDLEqProof::verify` with zero statements, or with an empty per-series statement for `MultiDLEqProof`. [8](#0-7)  Existing in-repository call sites with fixed non-empty generator arrays are not exposed to this empty-statement case, but the public verifier permits it and the in-crate tests explicitly exercise and accept `i == 0`. [9](#0-8) 

### Recommendation
Reject empty statements in `DLEqProof::verify`, and reject both zero discrete logarithms and empty per-series generator/point lists in `MultiDLEqProof::verify`. [10](#0-9)  Add regression tests asserting that empty statements return `InvalidProof`. [11](#0-10) 

### Proof of Concept
```rust

  &mut OsRng,
  &mut RecommendedTranscript::new(b"attacker context"),
  &[],                              // no generators
  &Zeroizing::new(Scalar::ZERO),    // no secret knowledge needed
);

let encoded = proof.serialize();
let decoded =
  DLEqProof::<ProjectivePoint>::read::<&[u8]>(&mut encoded.as_slice()).unwrap();

decoded
  .verify(
    &mut RecommendedTranscript::new(b"attacker context"),
    &[], // no generators
    &[], // no points/keys
  )
  .unwrap();
```

`prove` only transcripts each supplied generator-derived `R`/point pair, so an empty slice produces a challenge independent of the claimed secret or any public key. [12](#0-11)  `verify` then performs zero statement checks and accepts the matching challenge. [13](#0-12)

  pub fn verify<T: Transcript>(
    &self,
    transcript: &mut T,
    generators: &[G],
    points: &[G],
  ) -> Result<(), DLEqError> {
    if generators.len() != points.len() {
      Err(DLEqError::InvalidProof)?;
    }

    transcript.domain_separate(b"dleq");
    for (generator, point) in generators.iter().zip(points) {
      Self::verify_statement(transcript, *generator, *point, self.c, self.s);
    }

    if self.c != challenge(transcript) {
      Err(DLEqError::InvalidProof)?;
    }

    Ok(())
  }
