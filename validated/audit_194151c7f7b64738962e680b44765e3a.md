### Title
Unbounded recursive outer-puzzle matching over attacker-controlled offer/CAT/NFT layer nesting can exhaust the Python call stack - ([File: chia/wallet/outer_puzzles.py])

### Summary
CVE-2017-9208 is a QPDF bug where a crafted PDF causes unbounded recursion (`releaseResolved`) leading to stack exhaustion. The Chia codebase explicitly engineered around this exact bug class for tree-hashing: `sha256_treehash()` in `chia/types/blockchain_format/tree_hash.py` is deliberately implemented as an iterative stack machine "so we don't have to worry about blowing out the python stack." [1](#0-0)  That defensive design is not applied consistently across the wallet's puzzle-driver layer, which recurses in Python once per nested puzzle "layer" (`also`) with no depth limit.

### Finding Description
`chia/wallet/outer_puzzles.py:match_puzzle()` iterates over registered outer-puzzle drivers (`CAT`, `singleton`, `metadata`, `ownership`, `CR`, etc.) and calls `driver.match(puzzle)`. [2](#0-1)  Each driver's `match()` implementation, on recognizing its own layer, uncurries one level and recursively calls back into `self._match` (which is `match_puzzle` itself) on the *inner* puzzle to build a nested `PuzzleInfo` chain — for example `CATOuterPuzzle.match()` [3](#0-2) , `SingletonOuterPuzzle.match()` [4](#0-3) , `MetadataOuterPuzzle.match()` [5](#0-4) , and `CROuterPuzzle.match()` [6](#0-5) . There is no maximum-layer-depth check anywhere in this chain.

This code path is exercised on attacker-supplied puzzle reveals when a wallet inspects an incoming offer or NFT/CAT puzzle to determine its `driver_dict`/`PuzzleInfo`, e.g. `match_puzzle(UnknownPuzzle(known_program=...))` used from `chia/wallet/trading/offer.py` and `chia/wallet/nft_wallet/nft_wallet.py`. [7](#0-6)  An offer maker or any counterparty can construct a coin whose puzzle reveal is a legitimately-curried, valid CLVM program consisting of thousands of nested CAT/singleton/metadata/ownership/CR layers (each layer is cheap to construct and cheap to uncurry — `Program.uncurry()` itself is iterative, not recursive [8](#0-7) ). When the victim wallet calls `match_puzzle()` to inspect this puzzle (e.g., while parsing an offer file or NFT info before deciding to accept/display it), each nesting level adds one Python stack frame across `match_puzzle -> driver.match -> self._match(match_puzzle) -> ...`, eventually raising `RecursionError` and aborting/crashing the wallet's offer/NFT-processing flow — a spend/offer-triggered, client-side, transaction-processing halt analogous to the QPDF "infinite recursion / stack consumption" bug class.

### Impact Explanation
This is reachable purely by an offer counterparty or NFT-transfer sender constructing a coin/puzzle with deep (but individually valid) curry nesting — no signature or fee is required to have the victim wallet attempt to parse the puzzle via `match_puzzle`. Triggering a `RecursionError` denial-of-service against a wallet process/RPC call qualifies as a spend-triggered transaction-processing halt, matching the "Validate" criteria (spend-triggered transaction-processing halt) allowed by the report's rules.

### Likelihood Explanation
Constructing deeply nested, but syntactically valid, curried puzzle layers (CAT-in-CAT-in-singleton-in-metadata, etc.) is inexpensive for an attacker and does not require breaking any cryptographic or consensus rule; it only needs to be presented to a victim wallet as an offer, NFT transfer, or similar puzzle reveal that gets fed into `match_puzzle()`. The likelihood of hitting Python's default recursion limit (~1000) with a moderately sized nested structure is high, and no guard exists in this code path.

### Recommendation
Convert the `match_puzzle`/`driver.match()`/`get_inner_puzzle`/`get_inner_solution`/`solve_puzzle` recursive-descent chain in `chia/wallet/outer_puzzles.py` and the individual driver classes (`CATOuterPuzzle`, `SingletonOuterPuzzle`, `MetadataOuterPuzzle`, `OwnershipOuterPuzzle`, `CROuterPuzzle`, `TransferProgramPuzzle`) into an iterative, stack-based traversal (mirroring the design already used in `sha256_treehash`), or impose and enforce an explicit maximum nesting-depth limit before recursing, raising a controlled error instead of allowing unbounded Python-level recursion when parsing untrusted puzzle reveals.

### Proof of Concept
Conceptual construction (cannot be executed in this read-only analysis, but derivable from the cited code):
1. Take an arbitrary inner puzzle `P0` (e.g., `Program.to(1)`).
2. Recursively wrap it N times (N ≈ 2000–5000) using `construct_cat_puzzle(CAT_MOD, tail, Pi)` to build `P1..PN` (exactly as done for two layers in `chia/_tests/wallet/cat_wallet/test_cat_outer_puzzle.py`, generalized to N layers). [9](#0-8) 
3. Create a coin with puzzle hash `PN.get_tree_hash()` and present it (e.g., inside an offer file or as an NFT puzzle reveal) to a victim wallet.
4. When the wallet calls `match_puzzle(UnknownPuzzle(known_program=PN))` to classify the asset (as done in `chia/wallet/trading/offer.py`), the call chain recurses N times through `match_puzzle -> CATOuterPuzzle.match -> self._match(...)`, exceeding Python's recursion limit and raising `RecursionError`, aborting offer/NFT processing on the victim's wallet.

    def uncurry(self) -> tuple[Program, Program]:
        def match(o: CLVMStorage, expected: bytes) -> None:
            if o.atom != expected:
                raise ValueError(f"expected: {expected.hex()}")

        try:
            # (2 (1 . <mod>) <args>)
            ev, quoted_inner, args_list = self.as_iter()
            match(ev, b"\x02")
            if TYPE_CHECKING:
                # this being False is presently handled in the TypeError exception handler below
                assert quoted_inner.pair is not None
            match(quoted_inner.pair[0], b"\x01")
            mod = quoted_inner.pair[1]
            args = []
            while args_list.pair is not None:
                # (4 (1 . <arg>) <rest>)
                cons, quoted_arg, rest = args_list.as_iter()
                match(cons, b"\x04")
                if TYPE_CHECKING:
                    # this being False is presently handled in the TypeError exception handler below
                    assert quoted_arg.pair is not None
                match(quoted_arg.pair[0], b"\x01")
                args.append(quoted_arg.pair[1])
                args_list = rest
            match(args_list, b"\x01")
            return Program.to(mod), Program.to(args)
        except ValueError:  # too many values to unpack
            # when unpacking as_iter()
            # or when a match() fails
            return self, self.to(0)
        except TypeError:  # NoneType not subscriptable
            # when an object is not a pair or atom as expected
            return self, self.to(0)
        except EvalError:  # first of non-cons
            # when as_iter() fails
            return self, self.to(0)
