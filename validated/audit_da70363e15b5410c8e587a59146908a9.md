### Title
App proxy signature verification has no timestamp/freshness check, allowing unbounded replay - ([File: lib/shopify_app/controller_concerns/app_proxy_verification.rb])

### Summary
`ShopifyApp::AppProxyVerification#verify_proxy_request` only validates that the HMAC signature matches the query parameters via `query_string_valid?`/`calculated_signature`. The `timestamp` parameter is treated as just another signed field and is never compared against the current time or any expiry window, so a previously valid `query_string` + `signature` pair remains valid forever.

### Finding Description
`verify_proxy_request` calls `query_string_valid?(request.query_string)`, which parses the query string, extracts the `signature`, recomputes the HMAC over the remaining sorted params via `calculated_signature`, and does a `secure_compare`. [3](#0-2)  Nowhere in this method (or anywhere else in the concern) is `query_hash["timestamp"]` read and compared to `Time.now` or bounded by a max-age window. `calculated_signature` simply builds `sorted_params` from whatever key/value pairs remain and HMACs them [4](#0-3) . Since HMAC verification is purely a function of the (shop, path_prefix, timestamp, ...) tuple and the shared secret, any request with an identical query string will always produce the same valid signature check, regardless of how long ago it was issued. The test suite even demonstrates that a fixed `timestamp=1466106083` (year 2016) query string with its matching signature still passes `assert_response :ok` today, confirming there is no expiry enforcement. [2](#0-1)  An attacker who captures one valid app-proxy query string (via browser history, server/proxy logs, network capture on a non-TLS hop, or a public storefront request) can replay the identical GET request indefinitely and it will continue to pass verification and reach the app-proxy controller action as that shop.

### Impact Explanation
This allows unauthenticated replay of a captured app-proxy request to repeatedly invoke app-proxy actions on behalf of the shop, corresponding to Shopify's "forged app-proxy request" impact class. Because app-proxy actions run without a session/token and only rely on this signature check as authentication, indefinite replay is the same as forging valid app-proxy calls for that shop after the original signing capability is gone — enabling repeated read/write actions against that shop's app-proxy resources without further authorization checks (scoped to whatever the specific app-proxy controller does).

### Likelihood Explanation
Feasible: the attacker only needs to observe one legitimate signed query string once (e.g., from a browser history entry, access/error logs, a `Referer` header leak, or by making a normal storefront request and reading their own browser's outgoing request). No secret, session, or privileged access is required, and the replay is trivially repeatable with the exact same GET request.

### Recommendation
Add a freshness check in `query_string_valid?` (or `verify_proxy_request`) that extracts `timestamp` from the query hash, rejects requests without a `timestamp`, and rejects requests where `Time.now.to_i - timestamp.to_i` exceeds a bounded validity window (e.g., a few minutes), before or in addition to the HMAC comparison.

### Proof of Concept
```ruby
test "stale but validly-signed proxy request should still be rejected" do
  with_test_routes do
    valid_params = {
      shop: "some-random-store.myshopify.com",
      path_prefix: "/apps/my-app",
      timestamp: "1466106083", # 2016-06-16, long expired
      signature: "f5cd7233558b1c50102a6f33c0b63ad1e1072a2fc126cb58d4500f75223cefcd",
    }
    get :basic, params: valid_params
    # Currently returns :ok because there is no expiry check -
    # expected behavior should be :forbidden for stale timestamps.
    assert_response :forbidden
  end
end
```
Running this against the current implementation shows `assert_response :ok` (as in the existing `"request with a valid signature should pass"` test) rather than `:forbidden`, confirming unbounded replay is accepted. [2](#0-1)

    def verify_proxy_request
      head(:forbidden) unless query_string_valid?(request.query_string)
    end

    private

    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end

    def calculated_signature(query_hash_without_signature)
      sorted_params = query_hash_without_signature.collect { |k, v| "#{k}=#{Array(v).join(",")}" }.sort.join

      OpenSSL::HMAC.hexdigest(
        OpenSSL::Digest.new("sha256"),
        ShopifyApp.configuration.secret,
        sorted_params,
      )
    end
