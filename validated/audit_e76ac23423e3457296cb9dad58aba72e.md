### Title
Withdrawal payout attribution can be nulled/hijacked because the user's payout signature (SIGHASH_SINGLE|ANYONECANPAY) does not cover the operator-attribution OP_RETURN output - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
The user's withdrawal signature only commits to the payout output (index 0) via a `SIGHASH_SINGLE`-family sighash. The operator-attribution `OP_RETURN` output and the CPFP anchor output are not covered by that signature, so any unprivileged party who observes a broadcast (or otherwise obtains) payout transaction can rebroadcast a competing, still-validly-signed variant that pays the same user output but carries a different (or no) operator attribution, before the legitimate transaction confirms. Whichever variant confirms is the one used by `AuctionInternal`-analogous bookkeeping in Clementine (`update_finalized_payouts`) to decide which operator gets credited for fronting the withdrawal.

### Finding Description
`create_payout_txhandler` builds the payout transaction with three outputs — the user's payout output (0), an anchor output (1), and an `OP_RETURN` output carrying the fronting operator's x-only pubkey (2) — but signs only input 0 with the user's signature at a sighash type chosen by the caller (typically `SIGHASH_SINGLE|SIGHASH_ANYONECANPAY`): [1](#0-0) 

Because `SIGHASH_SINGLE` only commits to the output at the same index as the signed input, outputs 1 and 2 (anchor + `OP_RETURN` attribution) are unconstrained by the user's signature. The verification code even reuses the caller-supplied `sighash_type` to recompute and check the sighash, confirming that only output 0 is bound: [2](#0-1) 

On-chain finalization walks confirmed blocks and derives the fronting operator strictly from whatever `OP_RETURN` output ends up in the transaction that actually confirms — not from what the legitimate operator intended to broadcast: [3](#0-2) 

If the `OP_RETURN` is missing or unparsable, `operator_xonly_pk` is stored as `NULL`: [4](#0-3) 

Automated reimbursement discovery for an operator strictly filters on `payout_payer_operator_xonly_pk = self` and will never find rows where this is `NULL` or a different key: [5](#0-4) 

Manual reimbursement is likewise gated on the payer's xonly pubkey matching the operator's own key, and errors out otherwise: [6](#0-5) 

Attack sequence (fully unprivileged — requires no verifier/operator/aggregator/watchtower role):
1. The real operator O funds withdrawal by broadcasting `payout_tx_O` (input = withdrawal UTXO, output0 = user payout, output1 = anchor, output2 = OP_RETURN(O_pubkey)), signed with the user's SIGHASH_SINGLE|ANYONECANPAY signature.
2. Before it confirms, an attacker observes `payout_tx_O` in the mempool (or otherwise learns the user's signature/outpoint) and constructs `payout_tx_X`: identical input and output0 (so the signature stays valid), but a mutated/removed output2 `OP_RETURN` (and possibly a different anchor amount/spender for their own CPFP fee bump).
3. The attacker gets `payout_tx_X` confirmed instead (e.g., by attaching a higher-fee CPFP spend of the anchor, or simply relaying earlier/with better fee visibility), double-spending the same withdrawal UTXO input that `payout_tx_O` also spends.
4. `update_finalized_payouts` scans the confirmed block, finds `payout_tx_X`, and stores `operator_xonly_pk = NULL` (or an attacker-chosen key) for that withdrawal index.
5. The real operator O now can never be matched by `get_first_unhandled_payout_by_operator_xonly_pk` (automation) nor pass `validate_payer_is_operator` (manual `get_reimbursement_txs`), because the DB no longer attributes the payout to O.
6. O has spent real BTC to pay the user but has no path to reimbursement — the binding "party that actually paid == operator credited for reimbursement" is broken.

### Impact Explanation
This breaks the core bridge-custody invariant that the operator whose funds actually paid a withdrawal is the one credited/reimbursed. The consequence matches the Critical impact classes: "an operator reimbursed for a payout it never funded" (if attacker substitutes a different, e.g. their own, operator key) or "an honest operator permanently unable to be reimbursed" / "an honest operator's collateral burned" (if the attribution is nulled). Since Clementine's automated (`PayoutCheckerTask`) and manual (`get_reimbursement_txs`) reimbursement flows both hard-require an exact `payout_payer_operator_xonly_pk` match, there is no fallback recovery path once the wrong transaction confirms.

### Likelihood Explanation
The attacker needs only to observe a public, unconfirmed payout transaction (mempool visibility) and win a fee/CPFP race to get their variant confirmed instead — no special role, key, or insider access is required. The payout transaction is explicitly non-standard-fee / CPFP-driven (anchor output), so fee-bumping races are an expected and easy mechanism, making the race practically achievable rather than purely theoretical.

### Recommendation
Bind the operator-attribution output (and ideally the anchor output) to the signature the user provides for the payout transaction, e.g. by requiring `SIGHASH_ALL` (or a custom covenant/commitment) so all outputs — including the `OP_RETURN` attribution — are covered and cannot be altered by a third party without invalidating the signature. Alternatively, commit the intended operator's pubkey into the presigned message/covenant used to authorize the withdrawal so that any competing transaction with a different attribution fails signature verification.

### Proof of Concept
Conceptual PoC (cannot be executed here, but derivable from the cited code paths):
1. Run the existing e2e helper `payout_and_start_kickoff` in `core/src/test/common/clementine_utils.rs` to have operator O produce and broadcast a valid `payout_tx_O` for a withdrawal.
2. Before it confirms, construct `payout_tx_X` reusing `create_payout_txhandler`'s input/output0/witness from `payout_tx_O`, but pass a different (or omitted) `operator_xonly_pk` argument when building output2, and a self-controlled anchor spend for fee bumping.
3. Broadcast `payout_tx_X` with a higher CPFP fee so it confirms in place of `payout_tx_O`.
4. Observe that `update_finalized_payouts` (`core/src/verifier.rs`) records `payout_payer_operator_xonly_pk` as `NULL` or the attacker's chosen key for that withdrawal index, and that `get_first_unhandled_payout_by_operator_xonly_pk` / `validate_payer_is_operator` for operator O no longer surface this withdrawal, confirming O cannot be reimbursed despite having funded the payout via the intercepted signature.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }

    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
