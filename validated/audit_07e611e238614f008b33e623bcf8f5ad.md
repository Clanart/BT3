### Title
Excess native `msg.value` on `dispatch()`/`fundRequest()` Uniswap swaps is refunded to `EvmHost` itself, permanently stranding user overpayments - (File: evm/src/core/EvmHost.sol)

### Summary
`EvmHost.dispatch(DispatchPost)`, `dispatch(DispatchGet)`, and `fundRequest()` are all `payable` and, when `msg.value > 0`, forward the entire `msg.value` into `IUniswapV2Router02.swapETHForExactTokens{value: msg.value}(fee, path, address(this), block.timestamp)`. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`swapETHForExactTokens` only consumes `amounts[0] <= msg.value` (the exact ETH needed to buy `fee` units of `feeToken()`), and Uniswap's router refunds any dust `msg.value - amounts[0]` via `TransferHelper.safeTransferETH(msg.sender, ...)`. Because `EvmHost` itself is the caller of the router (`address(this)` is passed as `to`, and the router is invoked directly, not via delegatecall), that refund goes to **`EvmHost`**, not to the original caller of `dispatch()`/`fundRequest()`. Any overpayment of native token — whether from imprecise off-chain fee estimation, slippage between quote-time and execution-time, or a user simply attaching more ETH "to be safe" — is silently absorbed into `EvmHost`'s own balance instead of being returned to the user.

This is the direct structural analog of the `Executor.sol` bug in the external report: a `payable` entry point (`swap()` / here `dispatch()`/`fundRequest()`) forwards `msg.value` into a downstream call without validating that the exact amount is consumed or refunding the excess to the sender, so extra native token becomes stuck in a contract that was never meant to hold user float. The docs even explicitly warn about this: "Slippage: Yes (Uniswap swap)" and instruct callers to estimate off-chain, but nothing enforces `msg.value == amounts[0]` or refunds the sender on-chain. [4](#0-3) 

Unlike the ERC20 fee-token path — which uses `safeTransferFrom` for the *exact* `post.fee`/`get.fee`/`amount` and therefore cannot overcollect — the native-token path has no analogous exactness guarantee for the leftover ETH.

### Impact Explanation
Every user who dispatches a POST/GET request or funds a request with native token and overestimates the required ETH (which is expected behavior given documented slippage) permanently loses the excess to the `EvmHost` contract. There is no user-facing function to reclaim this stranded value; it can only leave the contract via the privileged `withdraw()` path gated by `IHostManager`/governance (`_hostParams.hostManager`), meaning ordinary users have no recourse and the surplus is effectively expropriated as unintended "bridge revenue" rather than returned to its rightful owner. Given that `dispatch()` and `fundRequest()` are core, high-traffic permissionless entry points used by every app integrating Hyperbridge (including `HyperFungibleToken.send()`, `WrappedHyperFungibleToken.send()`, and `IntentGatewayV2` dispatch paths that all forward `msg.value` through this same code), the aggregate value at risk across the bridge is significant and recurring, not a one-off edge case. [5](#0-4) [6](#0-5) 

### Likelihood Explanation
High likelihood: this triggers on ordinary, unprivileged usage with no attacker required. The documentation itself acknowledges the swap is subject to slippage and instructs developers to estimate fees off-chain, which guarantees mismatches between the estimated `msg.value` and the actual `amounts[0]` consumed by the router at execution time — every such mismatch results in a fund loss for the caller. [7](#0-6) 

### Recommendation
After each `swapETHForExactTokens` call in `dispatch(DispatchPost)`, `dispatch(DispatchGet)`, and `fundRequest()`, refund any leftover ETH to `_msgSender()` (or use `swapETHForExactTokens` return value / `address(this).balance` delta to compute and forward the unspent amount), e.g.:
```solidity
uint256[] memory amounts = IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
    post.fee, path, address(this), block.timestamp
);
if (msg.value > amounts[0]) {
    payable(_msgSender()).transfer(msg.value - amounts[0]);
}
```

### Proof of Concept
1. Off-chain, a caller quotes `nativeCost` for a `DispatchPost` with `fee = X` feeToken units via the documented `quote()` helper.
2. Due to normal slippage/timing drift between the quote and the transaction's execution (block reordering, other swaps in the mempool moving the pool price), the caller sends `msg.value = nativeCost` but the actual `amounts[0]` required by `swapETHForExactTokens` at execution time is `nativeCost - delta` (cheaper) or the caller simply pads `msg.value` for safety margin as commonly recommended.
3. `EvmHost.dispatch()` executes `swapETHForExactTokens{value: msg.value}(post.fee, path, address(this), block.timestamp)`; the router consumes only `amounts[0]` and refunds `msg.value - amounts[0]` to `msg.sender`, which is `EvmHost`.
4. The dust ETH is now part of `EvmHost`'s balance with no on-chain record tying it back to the caller; the caller receives no refund and cannot withdraw it. Only a governance-authorized `withdraw()` call (via `IHostManager`) can move it out, and it is not credited back to the depositing user. [1](#0-0)

```text
    /**
     * @dev Dispatch a POST request to Hyperbridge
     *
     * @notice Payment for the request can be made with either the native token or the feeToken.
     * If native tokens are supplied, it will perform a swap under the hood using the local uniswap router.
     * Will revert if enough native tokens are not provided.
     *
     * If no native tokens are provided then it will try to collect payment from the calling contract in
     * the feeToken.
     *
     * @param post - post request
     * @return commitment - the request commitment
     */
    function dispatch(DispatchPost memory post) external payable notFrozen returns (bytes32 commitment) {
        if (msg.value > 0) {
            address[] memory path = new address[](2);
            address uniswapV2 = _hostParams.uniswapV2;
            path[0] = IUniswapV2Router02(uniswapV2).WETH();
            path[1] = feeToken();
            IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
                post.fee, path, address(this), block.timestamp
            );
        } else if (post.fee > 0) {
            IERC20(feeToken()).safeTransferFrom(_msgSender(), address(this), post.fee);
        }
```
