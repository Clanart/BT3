Based on my research, I found a concrete local analog of the isOwner/onlyOwner sender-confusion bug class: **incomplete identity verification in cross-chain governance callbacks — chain-level identity is checked but module/pallet-level identity is not**, mirroring the original bug's core defect (authenticating on an incomplete/wrong signal).

### Title
Governance callbacks (`HostManager.onAccept`, `BandwidthManager.onAccept`) authenticate only the source **chain**, never the source **module**, allowing any Hyperbridge-side dispatcher to impersonate privileged governance actions - (File: `evm/src/core/HostManager.sol`)

### Summary
`HostManager.onAccept` and `BandwidthManager.onAccept` are the EVM-side receivers for cross-chain governance actions (revenue withdrawal, host-param updates, tier pricing, treasury drains). Both authenticate an incoming `PostRequest` solely by comparing `request.source` against the configured Hyperbridge chain id. Neither checks `request.from` (the specific pallet/module id on the Hyperbridge parachain that produced the message). This is structurally the same flaw as the C4 report: the code trusts one identity signal (chain) while silently omitting the more specific one (module), which is exactly the field an attacker would need to control to forge a privileged call.

### Finding Description
`HostManager.onAccept` at [1](#0-0)  only validates:
```solidity
if (!request.source.equals(IHost(_params.host).hyperbridge())) revert UnauthorizedAction();
```
before decoding `request.body[0]` as an `OnAcceptActions` discriminant and executing `Withdraw` or `SetHostParam` against the host. There is no check that `request.from` equals a specific, trusted pallet id (e.g. `pallet-ismp-host-executive`'s `PALLET_ID`).

The docs explicitly acknowledge the identical pattern for `BandwidthManager`: [2](#0-1) 
"`BandwidthManager.onAccept` checks `request.source == IDispatcher(_host).hyperbridge()`. Only messages dispatched from Hyperbridge are honored. The `to` field is the manager's address — no module-id lookup."

The `DispatchPost` structure that any Hyperbridge-side pallet can construct freely includes attacker/pallet-controlled `from`, `to`, and `body` fields, e.g. [3](#0-2) . The receiving contract has no way to distinguish a message legitimately produced by `pallet-ismp-host-executive` from one produced by any other pallet/module on the same chain that also has `IsmpDispatcher` access and sets `to` = the victim `HostManager`/`BandwidthManager` address with a forged `body` (`[0, WithdrawParams]` or `[1, HostParams]`).

This is the same root cause as the ERC721H/ERC20H bug: `isOwner`/`onlyOwner` trusted the last 32 bytes of calldata without confirming which code path (fallback vs. direct call) appended them; here, `onAccept` trusts `request.source` (chain) without confirming which pallet (`request.from`) actually authored the payload.

### Impact Explanation
If any Hyperbridge-side pallet or future extension can be induced to dispatch an ISMP `PostRequest` with a `to` field pointing at a deployed `HostManager` or `BandwidthManager` on a connected chain, the forged body is accepted as legitimate governance:
- `Withdraw`/`dispatch_withdraw` path drains the entire accrued fee-token/native balance of the `IHost` (`EvmHost.withdraw`, [4](#0-3) ) or the `BandwidthManager` treasury to an attacker-chosen beneficiary.
- `SetHostParam` can rewrite `handler`, `consensusClient`, `admin`, or `hostManager` itself ( [5](#0-4) ), which is a full host takeover — every subsequent proof verification and dispatch on that chain becomes attacker-controlled.

This satisfies the bounty's "unauthorized execution / stealing or loss of funds / logic attack via wrong module bindings" category directly, since it is the receiving contract's own authorization gap, not a compromised relayer/prover/admin.

### Likelihood Explanation
Exploitability depends entirely on whether any pallet compiled into the Hyperbridge runtime allows a caller to set an arbitrary destination `to` and arbitrary `body` for an outbound ISMP dispatch (a "send raw cross-chain message" capability). I was not able to confirm, within the indexed portion of the repo, a currently-shipped permissionless extrinsic that grants a normal user this level of control (the extrinsics I could inspect, e.g. `pallet-ismp-host-executive::withdraw`/`update_host_params`/`dispatch_withdraw` on `pallet-bandwidth`, are gated by `AdminOrigin`/`HostExecutiveOrigin`). However, the vulnerability is a genuine design gap independent of that: **any current or future module with dispatch access is implicitly trusted by every `HostManager`/`BandwidthManager` on every connected chain**, because the receiving side never pins the expected sender module id. This is a latent authorization weakness that should be fixed at the contract level regardless of which pallet currently has (or later gains) dispatch capability, exactly as the original C4 finding was confirmed and fixed by the Holograph team even though no direct unprivileged exploit path was proven at judging time.

### Recommendation
Add an explicit `request.from == EXPECTED_MODULE_ID` check (mirroring the `bandwidth` pallet's inbound check "the pallet rejects any purchase whose `request.from` doesn't equal the address stored under `BandwidthManager<T>::get(request.source)`", [2](#0-1) ) to `HostManager.onAccept` and `BandwidthManager.onAccept`, pinning the trusted pallet id (e.g. `pallet-ismp-host-executive`'s `PALLET_ID`) as a constructor/`setHost`-time parameter, so chain-level trust is never treated as a substitute for module-level trust.

### Proof of Concept
Conceptual forged message (assuming any dispatcher with `to`/`body` control exists or is later added on the Hyperbridge parachain):
```rust
let post = PostRequest {
    source: HYPERBRIDGE_CHAIN_ID,              // passes request.source.equals(hyperbridge)
    dest: StateMachine::Evm(TARGET_CHAIN),
    from: ATTACKER_CONTROLLED_PALLET_ID,       // never checked by HostManager.onAccept
    to: HOST_MANAGER_ADDRESS,                  // victim's HostManager on TARGET_CHAIN
    body: [0u8].chain(abi_encode(WithdrawParams {
        beneficiary: ATTACKER_ADDR,
        amount: MAX_BALANCE,
        token: FEE_TOKEN,
    })),
    ..
};
```
Once relayed and accepted by `EvmHost.dispatchIncoming` (which itself only checks destination address existence, not module provenance, [6](#0-5) ), `HostManager.onAccept` executes `IHostManager(host).withdraw(withdrawParams)` because its only guard — `request.source.equals(hyperbridge)` — is satisfied, draining protocol revenue to the attacker.

        PostRequest calldata request = incoming.request;
        // Only the Hyperbridge parachain can send requests to this module.
        if (!request.source.equals(IHost(_params.host).hyperbridge())) revert UnauthorizedAction();

        // check the params to prevent the host from getting bricked.
        if (
            params.hostManager == address(0) || address(params.hostManager).code.length == 0
                || !IERC165(params.hostManager).supportsInterface(type(IApp).interfaceId)
        ) {
            // otherwise cannot process new cross-chain governance requests
            revert InvalidHostManager();
        }

        if (
            params.handler == address(0) || address(params.handler).code.length == 0
                || !IERC165(params.handler).supportsInterface(type(IHandlerV2).interfaceId)
        ) {
            // otherwise cannot process new datagrams
            revert InvalidHandler();
        }

        if (
            params.consensusClient == address(0) || address(params.consensusClient).code.length == 0
                || !IERC165(params.consensusClient).supportsInterface(type(IConsensusV2).interfaceId)
        ) {
            // otherwise cannot process new consensus datagrams
            revert InvalidConsensusClient();
        }

        // otherwise cannot process new cross-chain governance requests
        if (keccak256(params.hyperbridge) == keccak256(bytes(""))) revert InvalidHyperbridgeId();

        // otherwise cannot process new datagrams
        uint256 stateMachinesLen = params.stateMachines.length;
        if (stateMachinesLen == 0) revert InvalidStateMachinesLength();

        // otherwise cannot process new datagrams
        if (1 days > params.unStakingPeriod) revert InvalidUnstakingPeriod();

        address oldFeeToken = feeToken();
        if (oldFeeToken != address(0) && oldFeeToken != params.feeToken) {
            uint256 balance = IERC20(oldFeeToken).balanceOf(address(this));
            if (balance != 0) revert CannotChangeFeeToken();
        }

        // safe to emit here because invariants have already been checked
        // and don't want to store a temp variable for the old params
        emit HostParamsUpdated({oldParams: _hostParams, newParams: params});

        _hostParams.feeToken = params.feeToken;
        _hostParams.admin = params.admin;
        _hostParams.handler = params.handler;
        _hostParams.hostManager = params.hostManager;
        _hostParams.uniswapV2 = params.uniswapV2;
        _hostParams.unStakingPeriod = params.unStakingPeriod;
        _hostParams.challengePeriod = params.challengePeriod;
        _hostParams.consensusClient = params.consensusClient;
        _hostParams.stateMachines = params.stateMachines;
        _hostParams.hyperbridge = params.hyperbridge;

        // add whitelisted state machines
        for (uint256 i = 0; i < stateMachinesLen; ++i) {
            // create if it doesn't already exist
            if (_latestStateMachineHeight[params.stateMachines[i]] == 0) {
                _latestStateMachineHeight[params.stateMachines[i]] = 1;
            }
        }

    function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
        address destination = _bytesToAddress(request.to);
        uint256 size;
        assembly {
            size := extcodesize(destination)
        }
        if (size == 0) {
            // instead of reverting the entire batch, early return here.
            return;
        }

        // replay protection
        bytes32 commitment = request.hash();
        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)
            .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));

        if (!success) {
            // so that it can be retried
            delete _requestReceipts[commitment];
            return;
        }
        emit PostRequestHandled({commitment: commitment, relayer: relayer});
    }
