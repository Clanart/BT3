The `SECP.verify_schnorr` at `core/src/operator.rs:632-637` verifies that `in_signature` (the withdrawer's own Schnorr signature) is valid over the sighash of `payout_txhandler` computed at `core/src/operator.rs:630` via `calculate_sighash_txin(0, in_signature.sighash_type)`. Because the withdrawer's signature uses `SinglePlusAnyoneCanPay`, the sighash it signs over commits exactly to output index 0 — the payout output's `script_pubkey` and `value`. So any attempt by the fronting operator (or an attacker submitting parameters) to substitute a lower `out_amount`/different `out_script_pubkey` than what the withdrawer actually signed will produce a different sighash, causing `SECP.verify_schnorr` to fail and the request to be rejected with `wrap_err("Failed to verify signature received from user for payout txin...")`. This happens before any Bitcoin broadcast, and even if bypassed, Bitcoin Core script/signature validation on `send_raw_transaction` would reject the transaction outright since the witness signature would not validate against the actual on-chain sighash.
