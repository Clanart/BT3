### Title
`SchnorrAggregate::verify` uses deterministic weights independent of the nonces, allowing forgery of aggregate signatures - (File: crypto/schnorr/src/aggregate.rs)

### Summary

The analog to the Haven incident — a verifier accepting proofs it should reject — maps onto Serai's half-aggregation verifier. `SchnorrAggregate::verify` computes the per-signature aggregation weights via `weight()`, which derives them from a `DigestTranscript` containing only the DST and the list of challenges [1](#0-0) . The nonces `Rs` — the attacker-controlled half of the signature — are never appended to the digest, so the weights `z_i` are fully predictable to the prover before they choose `Rs`.

The verification equation is `Σ z_i·R_i + Σ z_i·c_i·A_i − s·G == 0` [2](#0-1) . Since `z_i` are known constants and `R_i`, `s` are free attacker inputs, the equation is linear and solvable: pick any `s`, pick arbitrary `R_1..R_{n-1}`, then set `R_n = z_n⁻¹·(s·G − Σ_{i<n} z_i·(R_i + c_i·A_i)) − c_n·A_n`. The aggregate verifies without the attacker knowing any of the discrete logs of `A_i`, i.e., without any valid constituent signature existing.

### Finding Description

`weight()` produces a scalar from a transcript that commits only to `keys_and_challenges`' challenges [3](#0-2) [1](#0-0) . For half-aggregation to be sound, the randomizing weights must be unpredictable to the prover at the time the nonces are fixed — otherwise the prover can solve the single linear verification equation for its free variables. Here the attacker serializes the forgery with `SchnorrAggregate::write`/`serialize` and a verifier parses it via `SchnorrAggregate::read` [4](#0-3) , which performs only canonical-encoding checks before `verify` accepts the solved statement.

### Impact Explanation

A forged aggregate signature: an unprivileged party produces `(Rs, s)` that `verify` accepts for public keys whose private keys they do not know and for which no valid individual Schnorr signatures exist. Any caller relying on `SchnorrAggregate::verify` as proof that all listed key/challenge pairs were signed is defeated.

### Likelihood Explanation

Fully deterministic forgery requiring only arithmetic over public values (challenges, keys, weights). Reachable entirely through attacker-supplied bytes via `SchnorrAggregate::read`. No collusion, no leaked key, no timing.

### Recommendation

Bind the nonces into the weight derivation — append each `Rs[i]` (and ideally the public key) to the transcript before drawing each weight, or derive weights from a commitment over the full `Rs` vector (e.g., `digest.append_message(b"nonce", R.to_bytes())` per signature inside the loop at lines 139-143). Alternatively, follow the randomized-weight design used by `BatchVerifier::queue`, which uses RNG-derived nonzero weights so the prover cannot solve the equation in advance [5](#0-4) .

### Proof of Concept

Given `keys_and_challenges = [(A_1, c_1), ..., (A_n, c_n)]` for `n ≥ 1`:

1. Reconstruct the verifier's digest: `DigestTranscript::<C::H>::new(dst)`, `domain_separate(b"signatures")`, append each `c_i`, then compute `z_i = weight(&mut digest)` for each `i` (all deterministic, `Rs`-independent).
2. Choose `s = 0` (or any scalar) and arbitrary `R_1..R_{n-1}` (e.g., `identity` / `generator`).
3. Compute `T = s·G − Σ_{i=1}^{n-1} z_i·(R_i + c_i·A_i)`, then set `R_n = z_n⁻¹·T − c_n·A_n` — all operations are scalar/point arithmetic on public values.
4. Emit `SchnorrAggregate { Rs: [R_1..R_n], s }`. `verify` computes `Σ z_i·(R_i + c_i·A_i) − s·G = z_n·(R_n + c_n·A_n) + Σ_{i<n} z_i·(R_i + c_i·A_i) − s·G = 0` → accepted, despite no signer participation.
