Based on the investigation, I found a strong analog: a permissive regex used to classify whether a remote host is a trusted GitHub host, gating credential/sign-in behavior — the same "regex matches a substring in the wrong place, at the wrong length" class of bug as the Celo `bytecode.ts` metadata-stripping issue.

### Title
Overly-permissive `github.` prefix regex in `isGitHubHost` lets an attacker-controlled remote be misclassified as a trusted GitHub Enterprise host, triggering GitHub sign-in against it - (File: `app/src/lib/api.ts`)

### Summary
`isGitHubHost()` uses the regex `/(^|\.)(github)\./` to decide, as a fast heuristic, whether an arbitrary remote hostname "is" a GitHub host. [1](#0-0) 
Like the Celo `.*`-based metadata regex, this pattern is unanchored at the end and only checks that the literal `github.` appears at the start of the string or right after a dot — it never validates the rest of the domain. Any hostname of the form `github.<anything-attacker-controls>` (e.g. `github.evil-domain.com`) satisfies `(^|\.)(github)\.` and is therefore treated as a genuine GitHub Enterprise host.

### Finding Description
`isGitHubHost` first checks `isDotCom`/`isGHE` (exact-suffix checks on `github.com`/`api.github.com`/`*.ghe.com`), then checks a hardcoded `isKnownThirdPartyHost` denylist, then falls back to the loose prefix regex before it ever attempts a network probe: [2](#0-1) 

This function is consumed by the git credential trampoline's `getEndpointKind`, which classifies a credential request's target host as `'github.com'`, `'ghe.com'`, `'enterprise'`, or `'generic'`: [3](#0-2) 

When git attempts to authenticate against a URL that reaches this fallback (no `wwwauth[...]` header hint, no existing account, HTTPS protocol), `isGitHubHost(endpoint)` is awaited and, for a hostname like `github.attacker.com`, the regex check returns `true` synchronously via the short-circuit at line ~2452-2454 before any real network verification path is required to fail safely. The endpoint is then treated as `'enterprise'`: [4](#0-3) 

Back in `getCredential`, an `'enterprise'`-classified endpoint with no matching stored account causes Desktop to actively prompt the user to sign in to GitHub against that (attacker) endpoint: [5](#0-4) 

The broken invariant: the "is this a GitHub host" trust decision is derived from a substring/position match on the literal token `github` rather than validating the full registrable domain. Existing guards (`isDotCom`, `isGHE`, `isKnownThirdPartyHost`) only cover known-good/known-bad exact domains; they do nothing to stop a domain that merely starts with `github.` followed by an attacker-chosen suffix.

### Impact Explanation
An attacker who controls a git remote/host reachable by the victim (e.g. a cloned repository's remote URL, or a URL the victim is induced to `git clone`/`fetch` from, such as `https://github.<attacker>.com/...`) can cause Git to attempt HTTPS authentication against that host. Desktop's credential helper misclassifies the host as `'enterprise'` and surfaces a native "Sign in to GitHub Enterprise" prompt scoped to the attacker's endpoint. If the user proceeds (a normal, in-flow action Desktop itself solicits — not an unnatural step), the enterprise sign-in/OAuth flow is initiated against the attacker-controlled endpoint, exposing credentials/tokens to that host. This matches the accepted impact class: "a git remote/proxy response" leading to "unauthorized OAuth or account binding, credential/token exfiltration."

### Likelihood Explanation
Moderate-to-high: no special privileges, admin access, or pre-existing malware are required — only that the victim's git operation touches a host whose hostname begins with `github.` (trivially attacker-registerable, e.g. `github.attacker-domain.com`) and that git subsequently invokes the credential helper for that host. The regex fallback path is reached whenever the host doesn't produce a recognizable `WWW-Authenticate: realm="GitHub"`/`GitLab`/`Gitea`/`Atlassian Bitbucket` header and there's no cached account, which is exactly the state on first contact with a new attacker host over HTTPS.

### Recommendation
Replace the substring/prefix-based check `/(^|\.)(github)\./.test(hostname)` with a check that validates the full effective/registrable domain (e.g., using a public-suffix-aware comparison, or requiring the hostname to end with a small explicit allowlist such as `.github.com`, or requiring exact match/allow-listed suffixes configured by the user for their known GHE instances) rather than allowing any suffix after `github.`. At minimum, do not let this heuristic short-circuit to `true`; require the subsequent network confirmation (the `/meta` request checking for `x-github-request-id`) to succeed before trusting the host as GitHub-capable, mirroring the `stripMetadata` recommendation of not assuming a loose match is the intended target.

### Proof of Concept
1. Attacker stands up a server at `github.attacker.com` presenting a normal HTTPS git smart-http endpoint that returns a 401 without a `WWW-Authenticate: realm="GitHub"` header (or any recognizable realm).
2. Victim runs `git clone https://github.attacker.com/foo/bar.git` (or the repo's origin remote is set to this URL, e.g. via a malicious fork/PR checkout flow) inside GitHub Desktop.
3. Git invokes Desktop's credential trampoline `get` command for `github.attacker.com`; `getEndpointKind` falls through `isGist`/`isDotCom`/`isGHE`/`wwwauth` checks to `isGitHubHost('https://github.attacker.com')`.
4. Inside `isGitHubHost`, `hostname = 'github.attacker.com'` fails `isKnownThirdPartyHost`, then matches `/(^|\.)(github)\./` and returns `true` without any network round trip. [4](#0-3) 
5. `getEndpointKind` returns `'enterprise'`; since no account exists for that endpoint, `getCredential` calls `ui.promptForGitHubSignIn('https://github.attacker.com')`. [6](#0-5) 
6. The victim, believing this is a legitimate Desktop-initiated GitHub Enterprise sign-in prompt, completes authentication, sending credentials/OAuth material to the attacker's host.

Note: I was not able to fully trace the downstream enterprise-sign-in/OAuth request-construction code (`ui.promptForGitHubSignIn` → `_beginEnterpriseSignIn`/OAuth authorization URL builder) within the indexed context to confirm the exact network call target beyond `getEndpointKind`/`isGitHubHost`; a full Devin session with complete file access would be needed to verify the exact OAuth request payload sent to the attacker endpoint.

export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
