### Title
Early-unlock "expire forfeit" penalty on vlMGP reward claims is returned to the same unique locker, allowing bypass of the forfeit penalty - (File: rewards/vlMGPBaseRewarder.sol)

### Summary
`vlMGPBaseRewarder._sendReward` and `queueMGP` compute a "forfeit" penalty on a claimant's pending reward based on how much of their vlMGP is still locked (`_calExpireForfeit`), and re-queue that forfeited amount back into the *same* reward pool via `_queueNewRewardsWithoutTransfer`, which is distributed pro-rata to `totalStaked()`. If the claiming account is (or becomes) the sole/majority staker recorded by `IMasterMagpie(masterMagpie).stakingInfo` for that vlMGP rewarder, the "forfeited" reward is credited right back to that same account's `rewardPerToken` share, letting them reclaim their own penalty by repeatedly calling the claim path.

### Finding Description
`_sendReward` computes `forfeitAmount = _calExpireForfeit(_account, userRewards[...])` and sends `toSend = userRewards - forfeitAmount` to the receiver, then calls `_queueNewRewardsWithoutTransfer(forfeitAmount, _rewardToken)`: [1](#0-0) 

`_queueNewRewardsWithoutTransfer` distributes this forfeited amount across `totalStaked()`, which is defined as `IERC20(address(vlMGP)).totalSupply()`: [2](#0-1) [3](#0-2) 

The forfeit fraction itself is derived from `vlMGP.getRewardablePercentWAD(_account)`, i.e. the fraction of the account's vlMGP that is still fully locked (not mid-unlock or already unlocked): [4](#0-3) [5](#0-4) 

This is the same bug class as the Sherlock `FluidLocker._instantUnlock` finding: a penalty computed on a user's own claim is "distributed" back into a pool that is keyed by that same user's stake share. In `FluidLocker`, if the caller is the sole staker/LP in `STAKER_DISTRIBUTION_POOL`/`LP_DISTRIBUTION_POOL`, the "distributed" penalty flows straight back to the caller's locker. Here, if the claiming account is the sole (or dominant) staker of vlMGP as measured by `balanceOf()` (`IMasterMagpie.stakingInfo`), the re-queued `forfeitAmount` increases `rewardPerTokenStored` and is credited almost entirely back to that same account on the next `earned()`/`getReward` call, since `_earned` scales by the caller's own `balanceOf` share of `totalStaked()`: [6](#0-5) [7](#0-6) 

By repeatedly triggering the reward-update/claim path (each call re-queues the residual forfeit and immediately credits the dominant share of it back to the same account), an unprivileged wallet that controls (or has cornered) the vlMGP supply for this rewarder can iteratively extract almost the entirety of what should have been forfeited to long-term lockers, leaving only dust behind — mirroring the "repeated unlock, geometrically shrinking penalty" attack path described in the referenced report.

### Impact Explanation
This results in theft/permanent misdirection of yield that should accrue to genuine long-term (fully-locked) vlMGP holders: the intended forfeit penalty (meant to discourage early/partial unlocking and reward patient lockers) is instead reclaimed by the account that triggered the forfeit, at the expense of the honest locker pool's expected rewards. This is a direct theft of protocol-distributed yield via a reachable, unprivileged contract path (`getReward`/`getRewards`/`queueMGP`, invoked through `MasterMagpie`'s claim flow), analogous to the accepted bug class of "distribute-to-pool returns penalty to the same unique staker."

### Likelihood Explanation
Requires the attacker's vlMGP balance to represent all or a dominant fraction of `totalStaked()` for the specific vlMGP rewarder instance at claim time — realistic in a newly deployed rewarder, a low-adoption reward token, or through the attacker temporarily dominating supply (e.g., being an early/major locker). This mirrors the "unique staker/LP" precondition explicitly called out as in-scope for VLMGP lock slots and forfeits.

### Recommendation
When re-queuing the forfeited amount via `_queueNewRewardsWithoutTransfer`, exclude the forfeiting account's own share of `totalStaked()` from the distribution base (or send the forfeited amount to a fixed protocol/treasury destination instead of back into the pro-rata reward pool), and/or explicitly check that `totalStaked() > balanceOf(_account)` before allowing the forfeited amount to be redistributed within the same pool, reverting or diverting the penalty when the account is the sole staker.

### Proof of Concept
1. Attacker becomes the (near) sole vlMGP locker feeding a given `vlMGPBaseRewarder` (small pools/new reward tokens make this cheap): `balanceOf(attacker) ≈ totalStaked()` per [8](#0-7) .
2. Reward accrues for the token (`queueNewRewards`), and attacker's vlMGP is only partially/not fully locked so `getRewardablePercentWAD` < 100%, producing a forfeit fraction on `earned()`.
3. Attacker calls the claim path (`getReward`/`getRewards`, routed from `MasterMagpie`) invoking `_sendReward`: they receive `toSend`, and `forfeitAmount` is queued back via `_queueNewRewardsWithoutTransfer` [1](#0-0) , which increases `rewardPerTokenStored` almost entirely attributable to the attacker's own share.
4. Attacker repeats the claim call; each iteration the residual forfeited amount is claimed back (minus a shrinking new forfeit), converging to attacker recovering nearly 100% of the originally-forfeited reward, bypassing the intended penalty.

```text
    function _queueNewRewardsWithoutTransfer(uint256 _amountReward, address _rewardToken) internal
    {
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards = rewardInfo.historicalRewards + _amountReward;
        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**vlMGPDecimal) / totalStaked();
        }
        emit ForfeitRewardAdded(_amountReward, _rewardToken);
    }
```

```text
        uint256 forfeitAmount = _calExpireForfeit(_account, userRewards[_rewardToken][_account]);
        uint256 toSend = userRewards[_rewardToken][_account] - forfeitAmount;


        userRewards[_rewardToken][_account] = 0;

            IERC20(_rewardToken).safeTransfer(_receiver, toSend);

    }
```

```text
    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }
```

```text
    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalVlmgp = fullyInLock + inCoolDown;
        if (userTotalVlmgp == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalVlmgp;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalVlmgp / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalVlmgp;
                }

            }
        }

        return percent;
    }
```
