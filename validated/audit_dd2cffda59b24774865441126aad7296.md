### Title
Third-party output tampering via `SinglePlusAnyoneCanPay` payout signature lets an attacker null out `operator_xonly_pk` and force an honest operator's kickoff to be marked malicious - ([File: core/src/verifier.rs])

### Summary
The user's withdrawal signature is required to use `TapSighashType::SinglePlusAnyoneCanPay` [1](#0-0) , which commits only to input 0 and output 0 of `payout_tx`, leaving the anchor output and the operator-identifying OP_RETURN output completely unsigned by the user and never touched by the operator's own (separately, fully-covering) signature unless the attacker reuses the operator's exact set of inputs. An attacker can therefore build a competing, still-validly-signed transaction that spends the same withdrawal UTXO, keeps output 0 identical, but replaces output 2's OP_RETURN with a garbage-length push so `XOnlyPublicKey::from_slice` fails, causing `Verifier::update_finalized_payouts` to store `NULL` for `payout_payer_operator_xonly_pk`, which in turn makes `Verifier::is_kickoff_malicious` unconditionally treat the honest operator's kickoff as malicious.

### Finding Description
Binding claimed to hold: for withdrawal index `i`, `payout_payer_operator_xonly_pk[i] == Some(A)` whenever operator `A` is the party whose `payout_tx` actually pays out that withdrawal (i.e., whichever transaction the chain records as spending `withdrawals.withdrawal_utxo_{txid,vout}`, per `Verifier::get_payout_txs_for_withdrawal_utxos` [2](#0-1) ).

Root cause: `create_payout_txhandler` builds `payout_tx` with output 0 = user payout, output 1 = anchor, output 2 = OP_RETURN(operator xonly pk) [3](#0-2) , and the *only* cryptographic binding required from the withdrawing user is a `SinglePlusAnyoneCanPay` Schnorr signature, enforced explicitly by `parse_withdrawal_sig_params` [4](#0-3)  and verified in `Operator::withdraw` [5](#0-4) . Per BIP-341/342 sighash semantics, `SINGLE|ANYONECANPAY` commits only to the signed input and the single output at the same index; it does not commit to any other input or output. Consequently, output 1 (anchor) and output 2 (OP_RETURN operator pubkey) are entirely outside the signature's coverage, and any additional funding inputs the operator adds via `fund_raw_transaction` (`add_inputs: true`, `change_position: 1`) [6](#0-5)  are signed separately by the operator's wallet, not the user.

An attacker who observes the broadcast/mempool `payout_tx` (its raw bytes are public once relayed, or returned directly to the RPC caller as `RawSignedTx`) can extract the user's `SinglePlusAnyoneCanPay` signature over input 0/output 0 and construct a new transaction that: (1) reuses the same withdrawal input and signature (still valid because ANYONECANPAY does not bind it to any specific set of co-inputs), (2) keeps output 0 byte-identical (required to keep the signature valid), (3) supplies its own funding input(s) to cover the payout amount instead of operator A's, and (4) replaces output 2's OP_RETURN with a push of the wrong length (e.g., 31 or 33 bytes). `parse_op_return_data` still succeeds (it only checks for `OP_RETURN` followed by any push) [7](#0-6) , but `XOnlyPublicKey::from_slice(bytes)` fails on the wrong length, so `Verifier::update_finalized_payouts` computes `operator_xonly_pk = None` and persists `NULL` [8](#0-7) .

If this attacker variant confirms in place of A's original (a race/RBF outcome, since the tx is unconfirmed in the window before finality depth), `get_payout_txs_for_withdrawal_utxos` records it as the spending tx for that withdrawal index purely based on on-chain confirmation, with no operator preference. When A later sends its (legitimately funded, from A's perspective) kickoff for the same deposit, `Verifier::is_kickoff_malicious` looks up payout info by `move_txid`, finds `operator_xonly_pk_opt = None`, and the second `let Some(operator_xonly_pk) = operator_xonly_pk_opt else { ...assuming malicious... }` unconditionally returns `true` [9](#0-8) , regardless of `kickoff_data.operator_xonly_pk == A`. `Verifier::handle_kickoff` then queues a `Challenge` tx against A's kickoff [10](#0-9) , and the round machine records `challenged_rounds` via `check_if_kickoff_malicious` [11](#0-10) , which drives Challenge/Disprove flows that burn A's collateral.

No existing guard prevents this: `is_deposit_valid`, `Operator::is_profitable`, and `SECP.verify_schnorr` only validate that *a* valid `SinglePlusAnyoneCanPay` signature exists for output 0 - none of them constrain the OP_RETURN content or the other inputs/outputs of whichever transaction ultimately confirms.

### Impact Explanation
If the attacker's garbled-OP_RETURN variant confirms instead of operator A's original payout, `payout_payer_operator_xonly_pk` for that withdrawal is permanently `NULL` in the DB. This causes:
- `Verifier::is_kickoff_malicious` to unconditionally treat A's subsequent, otherwise-correct kickoff as malicious, triggering Challenge/Disprove and burning A's collateral - matching the Critical category "an honest operator's collateral burned."
- `Operator::get_first_unhandled_payout_by_operator_xonly_pk` (used by `PayoutCheckerTask`) filters on `payout_payer_operator_xonly_pk = $1` [12](#0-11) , so no operator (including whichever party actually funded the confirmed output 0) can ever be automatically reimbursed for that withdrawal - matching "an honest operator permanently unable to be reimbursed."

This is repeatable per withdrawal/operator as long as the attacker can win the race/replacement before the payout tx reaches finality depth, so the blast radius scales with the number of withdrawals an attacker is willing to fund.

### Likelihood Explanation
The attacker needs no privileged role - only the ability to observe a broadcast/mempool `payout_tx` (public data) and to fund and broadcast a competing transaction, exactly matching the stated unprivileged-attacker capabilities. The main cost is that the attacker must supply the *entire* payout amount themselves (since the reused signature only covers input 0/output 0, and the operator's own SIGHASH_ALL-signed funding inputs cannot be reused without invalidating the operator's signature) plus fees to win the fee race/RBF against A's transaction before it reaches finality depth. This makes the attack costly in BTC terms (proportional to the withdrawal amount) but requires no special access, no key compromise, and no majority hashrate - only mempool-level transaction replacement, which is standard, permissionless Bitcoin behavior.

### Recommendation
Require the operator's OP_RETURN output (and ideally the anchor output) to be committed by a signature that any party modifying the transaction cannot forge - e.g., have the operator co-sign the full transaction with `SIGHASH_ALL` over inputs/outputs that include the OP_RETURN, and reject/ignore for payout-attribution purposes any confirmed transaction whose structure does not match the exact template the operator originally signed (validate the operator's own signature over the OP_RETURN output, not just the user's `SinglePlusAnyoneCanPay` signature over output 0). Additionally, treat the "operator_xonly_pk resolves to None" case in `is_kickoff_malicious` more conservatively than "assume malicious" - e.g., require independent proof from the actual kickoff-owning operator (e.g., a signed statement or Winternitz commitment tying the kickoff to the specific confirmed payout txid) before concluding maliciousness, so a third party corrupting an unrelated output cannot trigger it.

pub fn parse_withdrawal_sig_params(
    params: WithdrawParams,
) -> Result<(u32, taproot::Signature, OutPoint, ScriptBuf, Amount), Status> {
    let mut input_signature =
        taproot::Signature::from_slice(&params.input_signature).map_err(|e| {
            Status::invalid_argument(format!("Can't convert input to taproot Signature - {e}"))
        })?;

    // If the Taproot sighash type is Default (no explicit type attached; i.e. a 64-byte
    // signature without a sighash flag), normalize it to SinglePlusAnyoneCanPay.
    // Prior to v0.5 this was Clementine's implicit behavior; we retain it here for
    // backwards compatibility when a 64-byte signature is provided.
    if input_signature.sighash_type == TapSighashType::Default {
        tracing::warn!(
            "Input signature for withdrawal {} has sighash type default, setting to SinglePlusAnyoneCanPay", params.withdrawal_id,
        );
        input_signature.sighash_type = TapSighashType::SinglePlusAnyoneCanPay;
    }

    // enforce sighash type here
    if input_signature.sighash_type != TapSighashType::SinglePlusAnyoneCanPay {
        return Err(Status::invalid_argument(format!(
            "Input signature has wrong sighash type, SinglePlusAnyoneCanPay expected, got {}",
            input_signature.sighash_type
        )));
    }

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,

    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

/// Parses the OP_RETURN data from a Bitcoin script. It retrieves the first data push after an OP_RETURN.
pub fn parse_op_return_data(script: &Script) -> Option<&[u8]> {
    let mut instructions = script.instructions();
    if let Some(Ok(Instruction::Op(opcodes::all::OP_RETURN))) = instructions.next() {
        if let Some(Ok(Instruction::PushBytes(data))) = instructions.next() {
            return Some(data.as_bytes());
        }
    }
    None
}

    pub async fn handle_kickoff<'a>(
        &'a self,
        dbtx: DatabaseTransaction<'a>,
        kickoff_witness: Witness,
        mut deposit_data: DepositData,
        kickoff_data: KickoffData,
        challenged_before: bool,
    ) -> Result<bool, BridgeError> {
        let is_malicious = self
            .is_kickoff_malicious(kickoff_witness, &mut deposit_data, kickoff_data, dbtx)
            .await?;

        let deposit_outpoint = deposit_data.get_deposit_outpoint();

        let (_signed_txs, tx_metadata, challenge_tx) = self
            .get_signed_txs_for_kickoff(dbtx, kickoff_data, deposit_data)
            .await?;

        if is_malicious {
            tracing::warn!(
                "Malicious {} detected. {} Challenge tx: {} for deposit {}",
                kickoff_data,
                match challenged_before {
                    false => "This is the first malicious kickoff in the current round.",
                    true => "This is not the first malicious kickoff in the current round.",
                },
                bitcoin::consensus::encode::serialize_hex(&challenge_tx),
                deposit_outpoint
            );
            // do not automatically send challenge txs on mainnet or testnet4
            if !challenged_before
                && !matches!(
                    self.config.protocol_paramset().network,
                    bitcoin::Network::Bitcoin | bitcoin::Network::Testnet4
                )
            {
                #[cfg(feature = "automation")]
                self.tx_sender
                    .add_tx_to_queue(
                        dbtx,
                        TransactionType::Challenge,
                        &challenge_tx,
                        &[],
                        Some(tx_metadata),
                        self.config.protocol_paramset(),
                        None,
                    )
                    .await?;
            }
        } else {
            tracing::debug!(
                "Non-malicious {} detected, challenge tx: {}",
                kickoff_data,
                bitcoin::consensus::encode::serialize_hex(&challenge_tx)
            );
        }

        Ok(is_malicious)
    }
