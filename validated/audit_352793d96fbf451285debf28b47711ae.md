### Title
`HostManager.onAccept` fails to authenticate the sending module on Hyperbridge, allowing any pallet/account able to dispatch a POST to forge host-governance actions - ([File: evm/src/core/HostManager.sol])

### Summary
The external report's core defect is that a critical backend component is reachable without proper access control — network exposure alone is treated as sufficient trust. The local analog is `HostManager.onAccept()` in `evm/src/core/HostManager.sol`, which only authenticates the **chain-level** origin of an incoming ISMP POST (`request.source.equals(hyperbridge)`), but never checks the **module-level** origin (`request.from`). Any Substrate pallet — or, if a generic dispatch path exists, any account — capable of dispatching a POST request from the Hyperbridge parachain with `to` set to the `HostManager` contract address can trigger privileged `Withdraw` or `SetHostParam` actions.

### Finding Description
`HostManager.onAccept` is defined as: [1](#0-0) 

It is guarded by `restrict(_params.host)` (only the local `EvmHost` may call it) and checks `request.source.equals(IHost(_params.host).hyperbridge())` — i.e., that the message originated from the Hyperbridge parachain state machine. However, it never inspects `request.from`, the module identifier of the *sender pallet* on that chain. Compare this to `pallet_hyper_fungible_token::on_accept`, which explicitly authenticates the sender via `ContractToAsset::<T>::get(source, &from)` before acting: [2](#0-1) 

`HostManager` has no equivalent binding check against the expected sender pallet (`pallet-host-executive`'s `PALLET_ID`, seen constructing these exact governance POSTs): [3](#0-2) 

Because `HostManager.onAccept` trusts *any* module on the Hyperbridge state machine, the invariant "cross-chain admin/host-management effects must not be reachable through ... wrong module bindings ... or unauthenticated message flow" (per the bounty pivots) is violated at the binding-check layer — mirroring the Redpanda report's pattern of trusting network/chain-level reachability as a substitute for endpoint-level authentication.

The action byte controls behavior: [4](#0-3) 
- `OnAcceptActions.Withdraw` → calls `IHostManager(_params.host).withdraw(withdrawParams)`, moving bridge revenue to `withdrawParams.beneficiary`.
- `OnAcceptActions.SetHostParam` → calls `updateHostParams`, which can rotate `admin`, `hostManager`, `handler`, `consensusClient`, `feeToken`, etc. (see the parameter set in `EvmHost.sol`): [5](#0-4) 

Since `EvmHost.updateHostParams` and `withdraw` are gated only by `restrict(_hostParams.hostManager)` (the `HostManager` contract address) and `HostManager` performs no module-identity check inward, the entire authorization chain from "any Hyperbridge-chain sender" to "rewrite EvmHost governance/admin/consensus client and drain revenue" collapses to a single, unauthenticated chain-ID equality check.

### Impact Explanation
If any component on the Hyperbridge parachain other than the intended `pallet-host-executive` can cause a POST request with `to = HostManager address` and attacker-chosen `body` to be dispatched (e.g., via a permissionless/unfiltered ISMP dispatch surface, a misconfigured proxy module routing, or a future pallet reusing the generic `IsmpDispatcher::dispatch_request` without restricting `to`), the attacker can:
- Withdraw all bridge revenue held by `EvmHost` to an attacker-controlled `beneficiary` (`WithdrawParams`), directly satisfying "stealing or loss of funds."
- Overwrite `admin`, `hostManager`, `consensusClient`, or `handler` in `HostParams`, enabling follow-on false-state acceptance or unauthorized execution — satisfying "false proof/state acceptance" and "unauthorized transaction or execution."

### Likelihood Explanation
This requires local confirmation of a reachable unauthenticated dispatch path from the Hyperbridge chain to an attacker-chosen `to`/`body` (e.g., a permissionless pallet extrinsic that forwards user-supplied `DispatchPost` verbatim, as shown in the `dispatching.mdx` `send_message` pattern). I could not fully confirm within the indexed code whether such a generic, unrestricted-`to` dispatch extrinsic is wired into the production Hyperbridge/Gargantua/Nexus runtimes as opposed to only pallets that hardcode fixed `to`/`from` values (`pallet-host-executive`, `pallet-relayer`, `pallet-hyper-fungible-token` all use fixed, pallet-controlled `to`/`from`). This is a genuine gap in the defense-in-depth (missing module-binding check on `HostManager` itself, independent of whether a current caller can already reach it), but likelihood of a fully unprivileged exploit chain existing today in production runtime configuration is uncertain from the index alone.

### Recommendation
- **Short term**: In `HostManager.onAccept`, additionally verify `request.from` equals the well-known module ID of the trusted governance-sending pallet (e.g., `pallet-host-executive`'s `PALLET_ID`) before acting, mirroring the authentication pattern already used in `pallet_hyper_fungible_token::on_accept` (`ContractToAsset::get(source, &from)`).
- **Long term**: Apply the "never trust chain-level origin alone" principle uniformly across all `IApp`/`IsmpModule::on_accept` implementations that gate privileged actions — always bind on `(source, from)` pairs, not `source` alone, and audit any pallet extrinsic that allows a caller-supplied `to`/`body` `DispatchPost` to ensure it cannot target privileged destination modules like `HostManager`.

    function onAccept(IncomingPostRequest calldata incoming) external override restrict(_params.host) {
        PostRequest calldata request = incoming.request;
        // Only the Hyperbridge parachain can send requests to this module.
        if (!request.source.equals(IHost(_params.host).hyperbridge())) revert UnauthorizedAction();

        OnAcceptActions action = OnAcceptActions(uint8(request.body[0]));
        if (action == OnAcceptActions.Withdraw) {
            // This is where governance & relayers can withdraw their revenue.
            WithdrawParams memory withdrawParams = abi.decode(request.body[1:], (WithdrawParams));
            IHostManager(_params.host).withdraw(withdrawParams);
        } else if (action == OnAcceptActions.SetHostParam) {
            HostParams memory hostParams = abi.decode(request.body[1:], (HostParams));
            IHostManager(_params.host).updateHostParams(hostParams);
        }
    }

    function withdraw(WithdrawParams memory params) external restrict(_hostParams.hostManager) {
        if (params.token == address(0)) {
            // this is safe because re-entrancy is mitigated before dispatching requests
            (bool sent,) = params.beneficiary.call{value: params.amount}("");
            if (!sent) revert WithdrawalFailed();
        } else {
            IERC20(params.token).safeTransfer(params.beneficiary, params.amount);
        }
        emit HostWithdrawal({beneficiary: params.beneficiary, amount: params.amount, token: params.token});
    }
