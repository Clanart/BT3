### Title
Static (non-dynamic-gas) Cosmos precompiles decode ABI calldata without the superlinear-decode gas charge applied to dynamic-gas precompiles - ([File: precompiles/common/precompiles.go])

### Summary
`sei-chain`'s precompile framework has two execution paths for EVM calls into Cosmos precompiles: the static-gas `Precompile.Prepare` path and the `DynamicGasPrecompile.RunAndCalculateGas` path. Only the latter charges `DecodeGasCost`/`chargeDecodeGas` before calling `method.Inputs.Unpack`, a defense the code's own comments say exists specifically because go-ethereum's ABI decoder can perform O(len(input)^2) work (a single `string` payload referenced by many array/tuple offsets gets re-copied for every reference) while the visible calldata size only charges O(len(input)) gas. The static path skips this charge entirely.

### Finding Description
`DynamicGasPrecompile.chargeDecodeGas` explicitly prices the decode before unpacking because "ABI decoding of attacker-controlled calldata can cost far more than len(input)": [1](#0-0)  It calls `DecodeGasCost`, which walks the ABI tree and computes the actual string-copy volume the decoder will perform, explicitly noting the "worst case ~len(input)^2" blow-up from aliased offsets: [2](#0-1)  A test (`newAliasedVoteWeightedArgs`) demonstrates constructing calldata where many array slots share one offset, making decoded copy volume `O(k*s)` while calldata stays `O(k+s)` — this is structurally the same "shared/aliased index" trick as the Micronaut `authors[1]` / `authors[0]` descending-index example: a small serialized payload forces a much larger amount of internal work. [3](#0-2) 

In contrast, the static-gas path (`Precompile.Prepare`, used by precompiles constructed via `NewPrecompile`, e.g. `bank.go`, `auth.go`, `authz.go`, `addr.go`, `distribution.go`) calls `method.Inputs.Unpack(argsBz)` directly with no equivalent cost accounting: [4](#0-3)  For these precompiles, gas is only charged via `RequiredGas`, and most implementations return `pcommon.DefaultGasCost(input, ...)`, a purely linear function of calldata length (e.g. `precompiles/addr/legacy/v603/addr.go:86-91` computing `DefaultGasCost(input, ...)`). The EVM's own precompile gas-metering (`vm.RunPrecompiledContract`) only checks this linear `RequiredGas` figure against the caller's remaining gas before invoking `Run`/`Prepare`; it has no visibility into the decoder's actual super-linear cost.

### Impact Explanation
If any static-gas precompile ABI method exposes a dynamic array of dynamic-sized elements containing `string` (an array of tuples/strings), an attacker can submit an EVM transaction whose calldata is small/cheap under `RequiredGas`/`DefaultGasCost` but whose ABI decode performs quadratic work inside `Prepare`, analogous to the Micronaut DoS. Because precompile execution happens inside normal EVM state-transition processing (not just an RPC-only code path), this decode work runs on every validator applying the block, not merely a public RPC node — a successful trigger could cause a shared block-processing delay across the network (risking the "block delay beyond 2.5 seconds" threshold) rather than a single-node crash.

### Likelihood Explanation
The gap is proven at the code level: `chargeDecodeGas`/`DecodeGasCost` is applied only in `DynamicGasPrecompile.RunAndCalculateGas` [5](#0-4) , and is absent from `Precompile.Prepare`, which is the path used by the static, `NewPrecompile`-constructed precompiles (`bank`, `auth`, `authz`, `addr`, `distribution`, etc.). I was not able to fully enumerate, within the remaining search budget, whether any *currently shipped* static-gas precompile ABI actually exposes a method whose arguments include a dynamic array of dynamic tuples/strings (the `gov` `voteWeighted`-style shape used in the aliasing test appears to live behind the dynamic-gas path, which is protected). This limits confidence in immediate exploitability versus the architecture being merely latent/fragile — I flag this uncertainty explicitly rather than asserting a specific exploitable ABI method.

### Recommendation
Move the `chargeDecodeGas`/`DecodeGasCost` charge (or an equivalent) into the shared code path used by `Precompile.Prepare`, not just `DynamicGasPrecompile.RunAndCalculateGas`, so every precompile — static or dynamic gas — prices ABI decode by its actual (potentially super-linear) cost rather than relying solely on a linear `RequiredGas`/`DefaultGasCost` estimate. Alternatively, ensure `RequiredGas` for any static precompile method whose ABI can contain nested dynamic types (arrays of tuples/strings) itself calls `DecodeGasCost` before `Prepare`/`Unpack` runs.

### Proof of Concept
Conceptual PoC (needs confirmation against a concrete static-gas precompile ABI with an array-of-dynamic-tuple parameter, which could not be enumerated within the available search budget):
1. Identify a static-gas precompile (constructed via `NewPrecompile`, e.g. under `precompiles/bank`, `precompiles/auth`, `precompiles/authz`) whose ABI method accepts a dynamic array whose elements are dynamic tuples/strings.
2. Craft calldata analogous to `newAliasedVoteWeightedArgs` in `precompiles/common/decode_cost_test.go` — many array-element offsets pointing at one shared large string payload — so that on-wire calldata size is small (cheap under `DefaultGasCost`) but decoded string-copy volume is `O(k*s)`.
3. Submit as an EVM transaction calling that precompile. Because `Prepare` unpacks with no equivalent to `DecodeGasCost`, the decode executes with only the linear `RequiredGas` charged, consuming disproportionate CPU during block processing on every validator.

	operation := fmt.Sprintf("%s_unknown", d.name)
	defer func() {
		HandlePrecompileError(err, evm, operation)
		if err != nil {
			fmt.Printf("precompile %s encountered error: %v\n", d.name, err)
			err = vm.ErrExecutionReverted
		}
	}()
	ctxer := state.GetDBImpl(evm.StateDB)
	if ctxer == nil {
		return nil, 0, errors.New("cannot get context from EVM")
	}
	// Resolve the target method from the 4-byte selector only. The argument
	// payload is intentionally NOT decoded yet: ABI decoding of attacker-
	// controlled calldata can cost far more than len(input) (a single string can
	// be referenced by many array/tuple slots), so it must be paid for out of the
	// gas the caller supplied. The static-precompile path charges RequiredGas in
	// vm.RunPrecompiledContract before running; that step is skipped for
	// dynamic-gas precompiles, so we apply the equivalent charge here.
	methodID, err := ExtractMethodID(input)
	if err != nil {
		return nil, 0, err
	}
	method, err := d.MethodById(methodID)
	if err != nil {
		return nil, 0, err
	}
	operation = method.Name

	ctx := ctxer.Ctx()
	// Install the gas meter derived from the supplied EVM gas, then charge for
	// decoding the calldata BEFORE decoding it. A call that cannot afford the
	// decode is rejected here, before the parse/allocation work is performed.
	// chargeDecodeGas scopes the out-of-gas recovery to just these charges, so an
	// executor that later exhausts its gas keeps its normal (propagating)
	// out-of-gas semantics.
	gasLimit := d.executor.EVMKeeper().GetCosmosGasLimitFromEVMGas(ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx)), suppliedGas)
	ctx = ctx.WithGasMeter(sdk.NewGasMeterWithMultiplier(ctx, gasLimit))
	if err = d.chargeDecodeGas(ctx, method, input); err != nil {
		return nil, 0, err
	}

	args, err := method.Inputs.Unpack(input[4:])
	if err != nil {
		return nil, 0, err
	}
	em := ctx.EventManager()
	ctx = ctx.WithEventManager(sdk.NewEventManager())
	ctx = ctx.WithEVMPrecompileCalledFromDelegateCall(isFromDelegateCall)
	ret, remainingGas, err = d.executor.Execute(ctx, method, caller, callingContract, args, value, readOnly, evm, suppliedGas, hooks)
	if err != nil {
		return ret, remainingGas, err
	}
	events := ctx.EventManager().Events()
	if len(events) > 0 {
		em.EmitEvents(ctx.EventManager().Events())
	}
	return ret, remainingGas, err
}

//
// The Go ABI decoder's cost is dominated by copying `string` payloads: it
// materializes each string via string(output[begin:end]), and because a single
// string can be referenced by many array/tuple slots, the copied volume can be
// super-linear in len(input) (worst case ~len(input)^2). `bytes` values are
// excluded because the decoder reslices them without copying. The charge is
// therefore a linear pass over the input (DefaultGasCost) plus the string-copy
// volume the decoder would produce, priced at the KV read-per-byte rate.
func DecodeGasCost(args abi.Arguments, input []byte) (uint64, bool) {
	base := DefaultGasCost(input, false)
	if len(input) < 4 {
		return base, true
	}
	strBytes, ok := decodeStringCopyBytes(args, input[4:])
	if !ok {
		return 0, false
	}
	return satAdd(base, satMul(storetypes.KVGasConfig().ReadCostPerByte, strBytes)), true

// newAliasedVoteWeightedArgs builds non-canonical voteWeighted argument
// bytes: k dynamic-tuple offsets all point at one shared (option, weight) body
// whose weight string has length s. Calldata stays O(k+s); decoded copy volume
// is O(k*s).
func newAliasedVoteWeightedArgs(k, s uint64) []byte {
	tupleRel := 32 * k // offset within the array payload (after the length word)
	arrayPayload := make([]byte, 0, int(32*k+64+s))
	for range k {
		arrayPayload = append(arrayPayload, abiWord(tupleRel)...)
	}
	// Shared dynamic tuple: word0 = s (option / string length via offset 0),
	// word1 = 0 (string offset), then s payload bytes starting at tuple+32.
	arrayPayload = append(arrayPayload, abiWord(s)...)
	arrayPayload = append(arrayPayload, abiWord(0)...)
	arrayPayload = append(arrayPayload, make([]byte, s)...)

	data := append(abiWord(1), abiWord(64)...) // proposalID, options offset
	data = append(data, abiWord(k)...)
	data = append(data, arrayPayload...)
	return data
}
