### Title
Fungible/Non-fungible tokens literally named `"*"` collide with the `restrict-assets?`/`as-contract?` wildcard sentinel, letting assets move past their declared allowance - (File: clarity/src/vm/functions/post_conditions.rs)

### Summary
`with-ft` / `with-nft` allowances are keyed purely by the literal `asset_name` string parsed from user input, and the value `"*"` is simultaneously the reserved wildcard sentinel *and* a syntactically legal Clarity token name. Because the allowance map and the movement-check code use plain string/`AssetIdentifier` equality with no separate "is-wildcard" flag, a token that is actually named `*` is indistinguishable from an intentional wildcard grant, so a single `with-ft`/`with-nft` allowance can silently authorize movement of every fungible/non-fungible token defined in a contract rather than the one asset it was meant to scope.

### Finding Description
`eval_allowance` builds an `Allowance::Ft`/`Allowance::Nft` from the raw ASCII string supplied to `with-ft`/`with-nft`, converting it to a `ClarityName` with no special handling of `"*"`: [1](#0-0) [2](#0-1) 

`ClarityName::try_from("*")` is accepted as a valid identifier, confirming a real `define-fungible-token`/`define-non-fungible-token` may legitimately be named `*`: [3](#0-2) 

The parsed allowance is stored in a `HashMap<AssetIdentifier, ...>` keyed by the literal `(contract_identifier, asset_name)` pair, with no distinction between "the token literally named `*`" and "the wildcard for all tokens in this contract": [4](#0-3) 

When checking actual asset movement, `check_allowances` looks up both the asset's own key and a second lookup built by force-substituting `asset_name` with the literal string `"*"` to find "wildcard" allowances, merging any hits together: [5](#0-4) 

Because the wildcard-lookup key is constructed identically to how a real `*`-named asset's key would look, the map entry created by `(with-ft contract-id "*" amount)` is exactly the entry that `check_allowances` also treats as "the wildcard covering every FT in `contract-id`." The documentation for `with-ft`/`with-nft` even states this is intentional design ("When `"*"` is used for the token name, the allowance applies to **all** FTs/NFTs defined in `contract-id`") — but nothing prevents a contract from actually defining a token whose real name is `*`, at which point the two meanings of the string collide and cannot be disambiguated by the equality check that `restrict-assets?`/`as-contract?` rely on.

### Impact Explanation
This breaks the core equality the allowance mechanism is supposed to enforce: "assets moved == assets explicitly authorized by the allowance list." A caller (or contract author) who intends to grant a narrow allowance for one specific asset — a fungible/non-fungible token that happens to be named `*` — unknowingly grants unlimited allowance for every other FT/NFT defined in that same contract, because the lookup mechanism cannot tell "the actual token named `*`" apart from "the wildcard sentinel." Any other token moved by the protected body during that `restrict-assets?`/`as-contract?` call passes the check even though it was never explicitly authorized, i.e., an asset moves past its post-conditions/allowances. This matches the Critical impact category "an asset moving past its post-conditions."

### Likelihood Explanation
Exploitation only requires an ordinary, unprivileged token deployer to name a `define-fungible-token`/`define-non-fungible-token` literally `*` (which the language allows per the `ClarityName` grammar), and requires a caller/contract to write a `with-ft`/`with-nft` allowance targeting that specific `*`-named asset (e.g., relying on the on-chain token name shown by tooling/UI, or copying the name programmatically). No governance, admin, miner, or signer involvement is needed — any wallet/contract that grants an allowance scoped to a `*`-named asset is silently exposed. The scenario is realistic because nothing in the syntax layer rejects `*` as an asset name, and the collision is invisible unless a developer specifically audits for it.

### Recommendation
Disallow `*` as a valid token name at `define-fungible-token`/`define-non-fungible-token` definition time (reserve it exclusively as the wildcard sentinel), or represent the wildcard using a dedicated `Allowance` variant/flag (e.g., `FtAllowance { asset_or_wildcard: Either<AssetIdentifier, ContractIdentifier> }`) instead of overloading the `asset_name` string, so wildcard grants can never structurally collide with a real asset's `AssetIdentifier`.

### Proof of Concept
1. Deploy contract `evil` containing `(define-fungible-token * )` and `(define-fungible-token real-token)`, minting both to `tx-sender`.
2. A victim contract/wallet writes an allowance intended to scope only to the asterisk-named token:
   ```
   (restrict-assets? tx-sender
     ((with-ft .evil "*" u1))
     (begin
       (try! (ft-transfer? real-token u1000000 tx-sender attacker))
       (ok true)))
   ```
3. Per `check_allowances`, the moved asset `real-token` is looked up both under its own `AssetIdentifier` (no entry) and under the wildcard key `AssetIdentifier{contract_identifier: .evil, asset_name: "*"}` — which matches the allowance the victim believed only covered the literal `*` token — so the merged allowance list is non-empty and the `u1000000` transfer of `real-token` passes unchecked, confirmed by the merge logic at: [6](#0-5)

    if let Some(ft_moved) = assets.get_all_fungible_tokens(owner) {
        for (asset, amount_moved) in ft_moved {
            // Build merged allowance list: exact-match entries + wildcard entries for the same contract
            let mut merged: Vec<(usize, u128)> = Vec::new();

            if let Some(allowance_vec) = ft_allowances.get(asset) {
                merged.extend(allowance_vec.iter().cloned());
            }

            if let Some(wildcard_vec) = ft_allowances.get(&AssetIdentifier {
                contract_identifier: asset.contract_identifier.clone(),
                asset_name: ClarityName::from_literal("*"),
            }) {
                merged.extend(wildcard_vec.iter().cloned());
            }

            if merged.is_empty() {
                // No allowance for this asset, any movement is a violation
                record_violation(&mut earliest_violation, MAX_ALLOWANCES as u128);
                continue;
            }

            for (index, allowance) in merged {
                if *amount_moved > allowance {
                    record_violation(&mut earliest_violation, index as u128);
                }
            }
        }
    }
