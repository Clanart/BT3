### Title
Panic in legacy precompile `RequiredGas` on short calldata crashes EVM-trace RPC nodes - (File: `precompiles/common/legacy/v552/precompiles.go`)

### Summary
Every "legacy" (historical) implementation of the shared `Precompile.RequiredGas` helper slices the raw EVM calldata with `input[4:]` before validating that `input` is at least 4 bytes long. When the EVM historically executed a transaction whose calldata to a custom precompile (bank, addr, pointer, pointerview, wasmd, staking, oracle, json, etc.) was shorter than 4 bytes, replaying that transaction through the trace/debug JSON-RPC path re-selects the exact legacy precompile version that was active at that historical height and re-invokes its unsafe `RequiredGas`, causing an unrecovered Go slice-bounds panic.

### Finding Description
The current (non-legacy) precompile implementation validates the selector before slicing: [1](#0-0) 
Here `ExtractMethodID` is called first and only on success is `input[4:]` computed, so a call with `len(input) < 4` safely falls back to `UnknownMethodCallGas`.

The legacy copies of this same type, however, skip that check entirely in their `RequiredGas` method: [2](#0-1) 
`argsBz := input[4:]` executes unconditionally on the raw `input` byte slice supplied by the EVM interpreter, before any length validation. If `input` has 0–3 bytes (a perfectly valid, EVM-legal calldata payload for a call to a precompile address), this line panics with "slice bounds out of range".

These legacy `Precompile` structs are still compiled into the binary and are reachable at runtime through the keeper's historical-version resolution logic: [3](#0-2) 
`CustomPrecompiles(ctx)` returns the fast-path (safe) `latestCustomPrecompiles` map only when `!ctx.IsTracing()`. When `ctx.IsTracing()` is true (i.e., during `debug_traceTransaction`, `debug_traceBlockByNumber`/`debug_traceBlockByHash`, or similar trace replays), `GetCustomPrecompilesVersions` picks the precompile version that was active at the *historical* block height of the traced transaction — which can be any of the `v5.5.2` … `v6.6` legacy implementations registered in each precompile's `setup.go` (e.g. `precompiles/bank/setup.go`, `precompiles/pointer/setup.go`, `precompiles/wasmd/setup.go`, etc.).

### Impact Explanation
An unprivileged EVM transaction sender can, at any point in the past (or going forward, until the corresponding version is superseded), send a call to a custom precompile address (e.g. the bank precompile at `0x1002`, addr precompile at `0x1004`, pointer/pointerview/wasmd/staking/oracle addresses) with calldata shorter than 4 bytes. This transaction is cheap, requires no special privilege, and is a normal, otherwise-valid EVM call. Later, when any full/RPC node serves a `debug`/`trace` JSON-RPC request that replays that transaction (a routine operation for block explorers, indexers, and monitoring tooling), the node's EVM keeper resolves the historically-active legacy precompile version and invokes its `RequiredGas`, which panics. This crashes the RPC/trace goroutine and, depending on panic-recovery boundaries in the ABCI/RPC server, can bring down the node process — a denial-of-service against public RPC infrastructure.

### Likelihood Explanation
Likelihood is moderate: it requires (1) a transaction with sub-4-byte calldata sent to a custom precompile address at some point while a vulnerable legacy version tag was the active version (all of `v5.5.2` through `v6.6`), and (2) that transaction subsequently being replayed via a trace/debug RPC call. Sending the triggering transaction costs only ordinary EVM gas and is trivially crafted by any address. The trigger step (a trace RPC call) is commonly exercised by explorers and monitoring services rather than the attacker directly, but the attacker fully controls whether such a "landmine" transaction exists on-chain for any node to later step on. Availability of `debug`/`trace` namespaces varies by node operator configuration, which is the main source of uncertainty in this analysis — this could not be verified further given the current toolset.

### Recommendation
Add a length guard to every legacy `Precompile.RequiredGas` before slicing `input[4:]` (mirroring `ExtractMethodID`'s validation used elsewhere), e.g. return `UnknownMethodCallGas` when `len(input) < 4`, and apply the same fix consistently across all legacy version directories (`v552`, `v555`, `v562`, `v575`, `v580`, `v600`, `v601`, `v603`, `v605`, `v606`, `v610`, `v614`, `v620`, `v630`, `v640`, `v65`, `v66`, `v67`) as well as the `DynamicGasPrecompile` variants that similarly assume `len(input) >= 4`.

### Proof of Concept
1. Submit an EVM transaction whose `to` is a custom precompile address (e.g. the bank precompile) with `data` of 0–3 bytes; this is included in a block while a legacy precompile version (`v5.5.2`…`v6.6`) is the historically-active version for that address.
2. Have any node execute `debug_traceTransaction` (or `debug_traceBlockByNumber`/`trace_replayBlockTransactions`) for the block containing that transaction.
3. `Keeper.CustomPrecompiles(ctx)` detects `ctx.IsTracing() == true`, resolves the historical legacy version via `GetCustomPrecompilesVersions`, and the EVM interpreter calls that legacy precompile's `RequiredGas(input)` with the short `input`.
4. `argsBz := input[4:]` panics with a slice-out-of-range error, crashing the trace execution path.

func (p Precompile) RequiredGas(input []byte) uint64 {
	methodID, err := ExtractMethodID(input)
	if err != nil {
		return UnknownMethodCallGas
	}

	method, err := p.MethodById(methodID)
	if err != nil {
		// This should never happen since this method is going to fail during Run
		return UnknownMethodCallGas
	}
	return p.executor.RequiredGas(input[4:], method)
}

func (p Precompile) RequiredGas(input []byte, isTransaction bool) uint64 {
	argsBz := input[4:] // first four bytes are method ID

	if isTransaction {
		return storetypes.KVGasConfig().WriteCostFlat + (storetypes.KVGasConfig().WriteCostPerByte * uint64(len(argsBz)))
	}

	return storetypes.KVGasConfig().ReadCostFlat + (storetypes.KVGasConfig().ReadCostPerByte * uint64(len(argsBz)))
}

func (k *Keeper) SetCustomPrecompiles(cp map[common.Address]putils.VersionedPrecompiles, latestUpgrade string) {
	k.customPrecompiles = cp
	k.latestUpgrade = latestUpgrade
	k.latestCustomPrecompiles = make(map[common.Address]vm.PrecompiledContract, len(cp))
	for addr, versioned := range cp {
		k.latestCustomPrecompiles[addr] = versioned[latestUpgrade]
	}
}

func (k *Keeper) CustomPrecompiles(ctx sdk.Context) map[common.Address]vm.PrecompiledContract {
	if !ctx.IsTracing() {
		return k.latestCustomPrecompiles
	}
	versions := k.GetCustomPrecompilesVersions(ctx)
	cp := make(map[common.Address]vm.PrecompiledContract, len(k.customPrecompiles))
	for addr, versioned := range k.customPrecompiles {
		cp[addr] = versioned[versions[addr]]
	}
	return cp
}

func (k *Keeper) GetCustomPrecompilesVersions(ctx sdk.Context) map[common.Address]string {
	height := ctx.BlockHeight()
	cp := make(map[common.Address]string, len(k.customPrecompiles))
	for addr, versioned := range k.customPrecompiles {
		mostRecentUpgradeHeight := int64(0)
		noForkHistory := true
		for upgrade := range versioned {
			upgradeHeight := k.upgradeKeeper.GetDoneHeight(ctx, upgrade)
			if upgradeHeight != 0 {
				noForkHistory = false
			}
			if height < upgradeHeight {
				// requested height hasn't seen this upgrade version yet.
				continue
			}
			if upgradeHeight > mostRecentUpgradeHeight {
				mostRecentUpgradeHeight = upgradeHeight
				cp[addr] = upgrade
			}
		}
		if noForkHistory {
			cp[addr] = k.latestUpgrade
		}
	}
	return cp
}
