## Title
Re-enabling `pallet-consensus-incentives` after `remove_incentives` pays a stale reward backlog to the next relayer — ([File: modules/pallets/consensus-incentives/src/lib.rs, modules/pallets/consensus-incentives/src/impls.rs])

### Summary
`pallet-consensus-incentives` pays relayers `(latest_height - baseline) * cost_per_block` for delivering consensus updates, where `baseline` is a persisted watermark (`LastRewardedHeight`) [1](#0-0) . When incentives for a state machine are removed via `remove_incentives`, the state-machine height keeps advancing through ordinary ISMP consensus updates (which do not depend on this pallet), but `LastRewardedHeight` is never touched because `process_message` only runs when a `cost_per_block` is configured [2](#0-1) . When governance later re-enables incentives with `update_cost_per_block`, the very next consensus message submitter is paid the entire accumulated block span (potentially thousands of blocks) at the new rate — a lump-sum treasury payout nobody intended, exactly mirroring the `TokenFaucet` refill bug (a stale "last drip" timestamp letting a fresh top-up be drained instantly).

### Finding Description
- `StateMachinesCostPerBlock` gates whether `process_message` runs at all: if `None`, the function returns `Ok(())` immediately without touching `LastRewardedHeight`. [2](#0-1) 
- `remove_incentives` clears only `StateMachinesCostPerBlock`; it does not reset or freeze `LastRewardedHeight` to the current chain height. [3](#0-2) 
- While incentives are disabled, the underlying `IsmpHost`'s `latest_commitment_height` continues to advance via ordinary consensus message processing — that mechanism is independent of this pallet's reward logic.
- `update_cost_per_block` simply (re)sets the cost with no reconciliation of the watermark. [4](#0-3) 
- On the first `on_executed` call after re-enabling, `calculate_reward` computes `baseline = LastRewardedHeight::get(...).unwrap_or(previous_height)` — this reads the **stale, pre-disable** watermark — and `reward = (latest_height - baseline) * block_cost`, transferring the full backlog from `TreasuryAccount` to whichever relayer's signature is on that message. [5](#0-4) 

This is the direct structural analog of the `TokenFaucet` issue: a rate-times-elapsed-time (here, elapsed-height) formula whose "last update" reference point silently goes stale while the mechanism is paused, and a subsequent "refill" (`update_cost_per_block`) unlocks the full backlog to whoever happens to interact next, rather than to the actual, intended per-update recipients.

### Impact Explanation
This is fund loss from the protocol treasury: an amount far larger than any single legitimate consensus-delivery reward is paid out in one transaction to one relayer, at governance's expense, purely because of a stale watermark left behind by `remove_incentives`. It fits the bounty's "stealing or loss of funds" / "logic attacks" categories — no relayer, prover, or admin collusion is required; any relayer that happens to submit the next signed `ConsensusMessage` after re-enablement collects the windfall.

### Likelihood Explanation
This requires only a normal, expected governance action sequence (`remove_incentives` followed later by `update_cost_per_block`) — a realistic operational pattern (e.g., temporarily pausing rewards for budget reasons then resuming them) — combined with the state machine's height continuing to progress in the interim, which happens automatically as part of ordinary ISMP operation. No attacker privilege or malicious actor is needed beyond an ordinary relayer submitting the next consensus message, which is the pallet's normal call path.

### Recommendation
When `remove_incentives` is called, snapshot `LastRewardedHeight` to the state machine's current `latest_commitment_height` (or otherwise mark the pause boundary) so that re-enabling via `update_cost_per_block` only accrues rewards for blocks processed *after* incentives resume. Alternatively, cap the reward span to a maximum number of blocks per payout, or require an explicit "resume" that resets `LastRewardedHeight` to the current height rather than relying on a possibly stale historical watermark.

### Proof of Concept
1. Incentives active for `state_machine_id` with `cost_per_block = C`; chain progresses to height `H0`; `LastRewardedHeight = H0` after a normal reward.
2. Governance calls `remove_incentives(state_machine_id)` — `StateMachinesCostPerBlock` cleared, `LastRewardedHeight` untouched at `H0`.
3. Over time, ordinary ISMP consensus updates advance the chain's `latest_commitment_height` to `H1` (`H1 >> H0`), with no rewards paid since `process_message` never runs.
4. Governance calls `update_cost_per_block(state_machine_id, C')` to resume incentives.
5. The next relayer submits any valid `ConsensusMessage` advancing the height further to `H2`. `calculate_reward` computes `baseline = LastRewardedHeight (H0)`, `blocks = H2 - H0` (includes the entire disabled-era span `H1 - H0`), and pays `reward = (H2 - H0) * C'` from the treasury to that single relayer — a payout many times larger than intended for a single update.

	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

		/// Update cost per block for a state machine
		#[pallet::call_index(0)]
		#[pallet::weight(T::WeightInfo::update_cost_per_block())]
		pub fn update_cost_per_block(
			origin: OriginFor<T>,
			state_machine_id: StateMachineId,
			cost_per_block: <T as pallet_ismp::Config>::Balance,
		) -> DispatchResult {
			T::IncentivesOrigin::ensure_origin(origin)?;

			StateMachinesCostPerBlock::<T>::mutate(state_machine_id.clone(), |maybe_cost| {
				*maybe_cost = Some(cost_per_block);
			});

			Self::deposit_event(Event::<T>::StateMachineCostPerBlockUpdated {
				state_machine_id,
				cost_per_block,
			});

			Ok(())
		}
