## Analysis Summary

The ImageMagick MVG bug's core invariant is: **recursive "open sub-document and render" logic checked bounds only within a single sub-document, not across the chain of nested references**, letting attacker-controlled nesting bypass any per-document safety check and overflow the C stack.

In this Protobuf checkout, every genuinely *parsing* recursion path (binary `ParseContext`/`CodedInputStream`, JSON `Merge`/`jsondec_push`, and `TextFormat::Parser`) enforces a depth counter, and the codebase even contains regression tests and comments showing Any-in-Any bypasses were previously found and fixed in Java (`mergeAnyMessage`), Python (`_ConvertAnyMessage`), and C# (`JsonReplayTokenizer`) [1](#0-0) [2](#0-1) [3](#0-2) . However, the **printing** side of C++ `TextFormat::Printer` when `Any` expansion is enabled does not carry this same fix.

### Title
Unbounded recursion in `TextFormat::Printer::PrintAny` when expanding nested `google.protobuf.Any` causes stack overflow - (`src/google/protobuf/text_format.cc`)

### Summary
`TextFormat::Printer::SetExpandAny(true)` causes `PrintAny()` to reflectively unpack an `Any.value` byte string into a new message and recursively call `Print()` on it. Because the wire-format `value` field of `Any` is an opaque `bytes` field (not a recursively-tracked embedded message), an attacker can nest `Any{value: <serialized Any>}` arbitrarily deep while the initial `ParseFromString`/`MergeFrom` call sees only depth 1 at the binary-parsing level. When the resulting message is later printed with `expand_any_` enabled, `Print → PrintMessage → PrintAny → Print → …` recurses once per nesting level with **no recursion-depth counter**, unlike every other recursive traversal in the codebase (binary parse, JSON parse, TextFormat parse, and even `PrintUnknownFields`), leading to an uncatchable C++ stack overflow.

### Finding Description
`TextFormat::Printer::PrintMessage()` special-cases `Any` and dispatches to `PrintAny()`: [4](#0-3) 

`PrintAny()` parses the attacker-controlled `value` bytes into a fresh `DynamicMessage` and calls `Print()` on it, which — if that value is itself an `Any` — re-enters `PrintAny()`: [5](#0-4) 

Neither `Print()`, `PrintMessage()`, `PrintField()`, nor `PrintFieldValue()` thread any recursion-budget/depth parameter through this call chain: [6](#0-5) 

This is in sharp contrast to:
- `PrintUnknownFields`, which explicitly threads a `recursion_budget` parameter and decrements it on every nested parse: [7](#0-6) 
- `TextFormat::Parser`'s own recursion limit, which is specifically tested against nested `Any` expansion during *parsing*: [8](#0-7) 
- Binary `CodedInputStream`/`ParseContext` recursion limits (default 100), which govern *embedded message* fields, not opaque `bytes` fields: [9](#0-8) 
- JSON/Java/Python/C# fixes that explicitly propagate depth across `Any`-body boundaries specifically to prevent this exact bypass class: [10](#0-9) 

Because `Any.value` is wire-encoded as a plain length-delimited `bytes` field (not a message field that triggers `ReadMessage`'s recursion-depth increment), an attacker can nest `Any{value: <bytes containing serialized Any>}` to any depth while the **initial** `ParseFromString`/`MergeFrom` binary parse of the outer message only ever sees depth 1 — the recursion-limit check in `ParsingPrimitivesMessages.ReadMessage`/`ParseContext::ParseMessage` never fires because the nested Any bytes are simply copied, not recursively parsed, at that time: [11](#0-10) . The recursion only actually happens later, one level at a time, inside `PrintAny`'s own internal `ParseFromString` calls plus the `Print()`/`PrintMessage()`/`PrintAny()` call chain — which has no counter at all.

### Impact Explanation
Calling `TextFormat::Printer::PrintToString`/`PrintToStream` (or `Message::DebugString()`/`ShortDebugString()` if the caller has set `SetExpandAny(true)`, a documented, commonly-used feature for human-readable dumping/logging of `Any`-wrapped messages, and even used internally by protobuf's own `UnredactedDebugFormatForTest` helper: [12](#0-11) ) on an attacker-supplied `Any` message causes uncontrolled C++ stack recursion and a crash (stack overflow), matching CWE-674 and the availability-only (`A:L`) impact of the reported ImageMagick advisory. This is a Denial-of-Service against any service that logs/debugs/serializes untrusted `Any` payloads with Any-expansion enabled.

### Likelihood Explanation
Likelihood is credible but conditional: it requires the consuming application to (a) accept an `Any`-typed (or `Any`-containing) message from an untrusted client via a normal bounded `ParseFrom*` call, and (b) subsequently print/debug that message with `TextFormat::Printer::SetExpandAny(true)`. This is a realistic and documented usage pattern (debug logging, admin tooling, gRPC reflection debug endpoints), though it is a narrower trigger surface than a bug reachable from parsing alone.

### Recommendation
Thread an explicit recursion-depth/budget parameter through `TextFormat::Printer::Print`, `PrintMessage`, `PrintField`, `PrintFieldValue`, and `PrintAny` (mirroring the existing `recursion_budget` pattern already used in `PrintUnknownFields`), and fail gracefully (return `false`/emit an error) once a configurable depth limit (e.g. matching the parser's default of 100) is exceeded, specifically counting each `PrintAny` unwrap as one level of depth regardless of the fact that `Any.value` is wire-opaque.

### Proof of Concept
1. Programmatically (or via a fuzz/attacker client) construct, bottom-up, a chain of `google.protobuf.Any` messages where each level's `value` field is the serialized bytes of the previous level's `Any`, to a large depth N (e.g., 50,000–200,000), each level adding only the fixed `Any` field overhead (`type_url` string + `value` bytes tag/length) — total payload size stays in the single-digit-MB range, not "huge".
2. Deliver this as a normal bounded `Any` payload to a service, which decodes it via `Any::ParseFromString`/`MergeFrom` — this succeeds without hitting the wire-format recursion limit because at binary-parse time only a single opaque `bytes` field is being read (`ParsingPrimitivesMessages.ReadMessage`/`ParseContext::ParseMessage` are never invoked for depth N).
3. The victim application then calls `TextFormat::Printer` with `SetExpandAny(true)` (or `DebugString()`-equivalent with Any-expansion) on the resulting `Any` object, per `text_format.cc:2601-2610` and `2527-2574`.
4. `PrintMessage → PrintAny → Print → PrintMessage → PrintAny → …` recurses N times with no depth counter, exhausting the C++ call stack and crashing the process — an uncatchable stack overflow, analogous to ImageMagick's `AddressSanitizer: DEADLYSIGNAL` from unchecked MVG-to-MVG recursive `RenderMVGContent`/`DrawImage` calls.

const char* ParseContext::ParseMessage(MessageLite* msg, const char* ptr) {
  LimitToken old;
  ptr = ReadSizeAndPushLimitAndDepth(ptr, &old);
  if (ptr == nullptr) return ptr;
  auto old_depth = depth_;
  ptr = msg->_InternalParse(ptr, this);
  if (ptr != nullptr) ABSL_DCHECK_EQ(old_depth, depth_);
  depth_++;
  if (!PopLimit(std::move(old))) return nullptr;
  return ptr;
}
