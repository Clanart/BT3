### Title
Stray KAIA sent to `GaslessSwapRouter` via `receive()` is irrecoverable by the sender and is swept by the owner through `claimCommission()` - (File: `contracts/bindings/kip247/GaslessSwapRouter.go`)

### Summary
`GaslessSwapRouter`, the KIP-247 gasless-swap system contract used by the `kaiax/gasless` module, defines a public `receive()` function that accepts KAIA from any address [1](#0-0)  but has no user-facing rescue/withdraw path for KAIA that was not sent as part of a legitimate `swapForGas` repayment. The only function that moves the contract's KAIA balance out is `claimCommission()`, which is restricted to the contract owner and sweeps the **entire** `address(this).balance` (confirmed by the `BALANCE` opcode `0x47` immediately preceding the low-level `.call` in the compiled runtime) to the owner [2](#0-1) [3](#0-2) . Any unprivileged user (gasless-swap sender or anyone else) who accidentally sends KAIA directly to `GaslessSwapRouter` therefore permanently loses that KAIA: it cannot be distinguished from, and cannot be separately withdrawn apart from, the legitimate commission that the owner is entitled to claim.

### Finding Description
`GaslessSwapRouter` is deployed as the KIP-247 swap router and is registered in the `SystemRegistry` so that the `kaiax/gasless` module can route gasless swaps through it [4](#0-3) . The router's `swapForGas(token, amountIn, minAmountOut, amountRepay, deadline)` entry point converts a whitelisted ERC20 token into KAIA and repays the block proposer's lent gas, with the router retaining the KAIA "commission" difference [5](#0-4) . Because the contract also exposes a bare `receive()` function [6](#0-5) , any externally-owned account (including ordinary gasless-swap senders who mistype an address, or any third party) can send KAIA directly to the router by mistake.

There is no function in the ABI to identify or return such mistakenly-sent KAIA to its original sender — the ABI exposes only `addToken`, `claimCommission`, `swapForGas`, ownership functions, and `updateCommissionRate` [7](#0-6) . `claimCommission()` unconditionally reads `address(this).balance` and forwards the whole amount to the owner via a low-level call, exactly the same "no way to distinguish own funds vs errantly transferred funds" defect described in the reference report: [3](#0-2) 

This mirrors the reported bug class: a payable contract that lacks a recovery mechanism for funds sent outside its intended accounting path, where the funds end up being appropriated by a privileged party's normal withdrawal function instead of being returned to the mistaken sender.

### Impact Explanation
Any KAIA an unprivileged account sends directly to the `GaslessSwapRouter` address (e.g., due to wallet misuse, integration bugs, or confusing the router with the intended recipient) is permanently and irreversibly merged into the pool that `claimCommission()` sweeps to the owner. This is a concrete unauthorized value movement: KAIA that was never earned as commission is transferred out of the reach of its rightful sender and into the owner's control the next time `claimCommission()` is invoked, with no on-chain accounting differentiating "earned commission" from "stray deposits." Because this contract sits on the hot path of the gasless-transaction system (registered via `SystemRegistry` and driving `kaiax/gasless` block-building logic), the router's balance is expected to be non-trivial, increasing the practical impact of any misdirected transfers.

### Likelihood Explanation
Likelihood is moderate: sending KAIA to a contract address by mistake is a common user error (copy-paste errors, confusing a router address with a wallet address, or an integrator naively "topping up" the router). Unlike a targeted exploit, this requires no adversarial coordination — a single ordinary transaction from any unprivileged sender to the router's address triggers the loss, and the owner does not even need special intent to eventually collect the misdirected funds, since `claimCommission()` is a normal, expected operational call.

### Recommendation
Add a mechanism (e.g., an owner-only or governance-gated `rescueKAIA(address payable to, uint256 amount)` function or an explicit tracked "commission accrued" accounting variable) so that `claimCommission()` only transfers the KAIA legitimately earned through `swapForGas` repayments, and any accidental transfers can be identified and returned to the original sender rather than being silently swept as commission. Alternatively, remove the bare `receive()` function so stray KAIA transfers revert instead of being accepted.

### Proof of Concept
1. An unprivileged user (or a misconfigured integrator) sends a plain KAIA transfer to the deployed `GaslessSwapRouter` contract address — this succeeds because of the unguarded `receive()` function [6](#0-5) .
2. The transferred KAIA increases `address(this).balance` but is not tracked separately from commissions accrued via `swapForGas`.
3. The contract owner later calls `claimCommission()`; the function reads the full `address(this).balance` and transfers it entirely to the owner [3](#0-2) .
4. The originally mistaken sender has no function available to reclaim their KAIA — it has been irreversibly transferred to the owner as if it were legitimate commission.
