### Title
Git pathspec magic in `_diff_pathspec` lets an attacker-named file suppress security-review diff output - (File: `plugins/security-guidance/hooks/gitutil.py`)

### Summary
`_diff_pathspec` converts touched-file paths into arguments spliced after `--` for `git diff`, but it never neutralizes git's pathspec "magic" syntax (arguments beginning with `:`, e.g. `:(exclude)…`, `:(glob)…`). A repo-controlled file whose repo-relative path begins with `:` is passed through unescaped, letting the pathspec's meaning be hijacked from "diff this specific file" to a magic directive (e.g. an exclude/glob pattern) that can zero out or otherwise distort the file set `git diff` actually returns to the security reviewer.

### Finding Description
`_diff_pathspec` (`plugins/security-guidance/hooks/gitutil.py:70-88`) only guards against paths resolving outside the repo root: [1](#0-0) 
It computes `r = os.path.relpath(os.path.realpath(p), cwd_abs)` and drops it only if it starts with `..`. It does nothing to prevent `r` itself from beginning with `:`. Git's pathspec parser treats any argument after `--` that starts with `:` as "magic" pathspec syntax (short forms like `:!`/`:(exclude)`, `:(glob)`, `:(icase)`, etc.) rather than as a literal filename, unless the caller passes `--literal-pathspecs` / sets `core.literalPathspecs=true`, or the path is written with a `./` prefix. Neither is done anywhere in this module — `GIT_CMD` (`plugins/security-guidance/hooks/gitutil.py:25-29`) only sets `core.fsmonitor=false` and `core.hooksPath=/dev/null`.

The resulting `pathspec` list is spliced directly into the `git diff` argv in `get_git_diff` (`plugins/security-guidance/hooks/gitutil.py:391-419`): [2](#0-1) 

The `paths` fed into `_diff_pathspec` originate from repo-controlled file listings, not from any name-sanitizing layer: `compute_v2_review_set` in `diffstate.py` builds the touched/review set from `git status --porcelain` (`tracked_dirty`, `untracked`) and `git diff --name-only` output, i.e. literal filesystem paths already present in the attacker's repo/branch. A malicious repository or branch that a user has Claude interact with (checkout, pull, merge, or simply edit alongside) can therefore contain a file literally named e.g. `:(exclude)*` or `:(glob)**/*.py`. Once that path becomes part of the "changed since baseline" set (e.g. because the branch introduces it as a new/modified file), it flows unmodified through `_diff_pathspec` into the `git diff -- ... :(exclude)* ...` argv.

Git combines the pathspec set as `union(non-exclude pathspecs) − union(exclude pathspecs)`. An exclude/glob magic token in this list can subtract the genuinely-modified files (including unrelated ones) from the diff `git diff` returns, or make the whole command exit non‑zero on a malformed magic signature. Both outcomes are silently swallowed by the caller: `get_git_diff` returns `""`/`None` on a git failure or empty diff (`plugins/security-guidance/hooks/gitutil.py:420-427`), which the Stop/commit-review pipeline treats as "nothing to review" and advances the baseline as if the turn were reviewed. No existing check (relpath/realpath traversal guard, `_is_reviewable_source`, `SKIP_PATH_PATTERNS`) inspects the pathspec string for a leading `:`; the only path-shape filtering happens *after* the diff is produced, so by the time filtering would matter, the security-relevant file content has already been excluded from `git diff`'s output.

### Impact Explanation
This is a security-control bypass: the Stop-hook / commit-review pipeline exists specifically to force an LLM review of every changed file before Claude finishes a turn or commits. By crafting a single specially-named file in the repository, an attacker can cause `git diff` to omit other genuinely-modified files (or fail outright) from the reviewed diff, silently defeating the review/blocking mechanism while the plugin still records the turn as reviewed (baseline advances, `reviewed_shas`/state updated). This matches the stated Immunefi impact category: "Security-control bypass that silently disables or routes around blocking, review, or permission boundaries."

### Likelihood Explanation
Preconditions are minimal and match the stated attacker model (unprivileged, no credentials/social engineering needed): the attacker only needs the ability to introduce a file with a `:`-prefixed name into a repository that Claude Code will later diff (e.g., via a pull request, branch, or any repo content the victim checks out and asks Claude to work with). `:` is a legal filename character on Linux/macOS, so crafting such a filename is trivial, and the resulting pathspec-magic behavior is deterministic native `git` behavior, not a race or timing-dependent condition — reproducible on every run once the file exists in the diffed range.

### Recommendation
Neutralize pathspec magic for every path emitted by `_diff_pathspec`:
- Prefix each relative path with `./` before returning it (git treats `./foo` as forcing literal path interpretation, disabling the leading-`:` magic parse), or
- Add `-c core.literalPathspecs=true` (or pass `--literal-pathspecs` globally) to `GIT_CMD` so all git invocations in this module treat pathspec arguments literally.
Either fix should be applied at the single choke point (`_diff_pathspec`/`GIT_CMD`) so all callers (`get_git_diff`, `_git_name_only`, `_git_status_porcelain`, etc.) inherit the protection.

### Proof of Concept
Unit test plan for `plugins/security-guidance/hooks/gitutil.py`:
1. Create a temp git repo; commit an initial baseline file `a.py` with content `X`.
2. Create two more files in the same commit-to-be-diffed range: `sensitive.py` (contains a real vulnerability marker string) and a file literally named `:(exclude)*`.
3. Call `_diff_pathspec(cwd, [abs_path_to_sensitive_py, abs_path_to_colon_file])` and assert the returned list still causes `git diff -- <list>` to include `sensitive.py` in its output.
4. Run `get_git_diff(cwd, baseline_sha, paths=[sensitive_py_abs, colon_file_abs])` and assert the returned diff text contains the marker string from `sensitive.py`.
   - Expected failure (pre-fix): the diff omits `sensitive.py` entirely (or `git diff` errors, returning `None`), because `:(exclude)*` pathspec magic subtracts all files from the match set.
   - Expected pass (post-fix, with `./` prefixing or `core.literalPathspecs=true`): `sensitive.py`'s changes are present in the diff, and the colon-named file is treated as a literal (non-matching) path rather than magic syntax.

def _diff_pathspec(cwd, paths):
    """Convert absolute touched-paths to repo-relative pathspec args for
    git diff. Paths outside cwd (e.g. ~/.claude/…) are dropped. Returns the
    list to splice after `--`, or [] for an unrestricted diff. realpath both
    sides so the macOS /var ↔ /private/var symlink doesn't make in-repo
    paths look external."""
    if not paths:
        return []
    cwd_abs = os.path.realpath(cwd)
    rel = []
    for p in paths:
        try:
            r = os.path.relpath(os.path.realpath(p), cwd_abs)
        except ValueError:
            continue
        if r.startswith(".."):
            continue
        rel.append(r)
    return ["--"] + rel if rel else []
