### Title
Users can front-run their own harvest with a free `cancelUnlock` to escape MGP reward forfeiture meant to be redistributed to other lockers - (File: rewards/vlMGPBaseRewarder.sol)

### Summary
`vlMGPBaseRewarder.queueMGP` computes the forfeit rate for freshly vested MGP by reading `VLMGP.getRewardablePercentWAD(_account)` *at call time*, but any vlMGP holder with an active cooldown slot can call the free, no-penalty `VLMGP.cancelUnlock(slot)` immediately before triggering their `MasterMagpie.multiclaim`, instantly resetting their cooldown weight to 100% "fully locked" and zeroing the forfeit that should have applied. The forfeited MGP normally gets redistributed to other lockers via `_queueNewRewardsWithoutTransfer`; escaping it lets the attacker keep the full harvest at the other lockers' expense.

### Finding Description
`_calExpireForfeit` in [1](#0-0)  derives the forfeit percentage purely from the *current* value of `vlMGP.getRewardablePercentWAD(_account)`, which in turn is computed live from `userUnlockings[_user]` in [2](#0-1) : a slot still in cooldown contributes less than full weight (either linearly decayed if still cooling, or zero forfeit if already past `endTime`), while fully-locked balance always contributes 100%.

`VLMGP.cancelUnlock` in [3](#0-2)  lets `msg.sender` zero out `slot.amountInCoolDown` for any slot still in cooldown, with no fee, no time delay, and no `nonReentrant`/cooldown-completion requirement — only `_checkInCoolDown`. Because `balanceOf` is invariant (`getUserTotalLocked + getUserAmountInCoolDown` always equals the amount staked in MasterMagpie, per [4](#0-3) ), cancelling a cooldown slot instantly reclassifies that balance from "decaying cooldown" to "fully locked" for the purpose of `getRewardablePercentWAD`, at zero cost.

Exploit flow:
1. Attacker has vlMGP staked in MasterMagpie's vlmgp pool with an active cooldown slot and an eligible MGP harvest.
2. In the same transaction (or same block), attacker calls `VLMGP.cancelUnlock(slot)`.
3. Attacker calls `MasterMagpie.multiclaim(vlmgpPool)`, which internally calls `_sendMGPForVlMGPPool` → `IvlmgpPBaseRewarder(vlMGPRewarder).queueMGP(_amount, _account, _receiver)` per [5](#0-4) .
4. `queueMGP` calls `_calExpireForfeit(_account, _amount)` [6](#0-5) , which now sees the post-cancel state (100% locked) instead of the pre-cancel decayed cooldown state, yielding `forfeitAmount = 0` (or far less than the true expected forfeit).
5. Attacker can later call `startUnlock` again to resume the cooldown for eventual unlock, having paid nothing.

This is repeatable on every harvest, entirely bypassing the intended vesting-based forfeiture and depriving other lockers of the redistributed forfeit amount that `_queueNewRewardsWithoutTransfer` would otherwise have queued into `rewards[token].rewardPerTokenStored` for all vlMGP stakers.

### Impact Explanation
This is a theft of unclaimed yield: forfeited MGP that should be redistributed among all vlMGP lockers (via `_queueNewRewardsWithoutTransfer`, [7](#0-6) ) is instead retained entirely by the attacker. It also degrades the reward-sharing mechanism protocol-wide since anyone in cooldown can escape their intended contribution before every claim.

### Likelihood Explanation
No special privilege or capital is required — only being a normal vlMGP staker with a cooldown slot open, which any user can create by calling `startUnlock`. `cancelUnlock` has no cost, no cooldown, and can be called any number of times, then re-entered via `startUnlock`, making the exploit trivially repeatable before every single harvest.

### Recommendation
Snapshot the rewardable percent (or the cooldown state used to compute it) at the time the reward became claimable (e.g., at harvest-triggering block for `_calNewMGP`/`unClaimedMgp` accrual), rather than reading live state in `_calExpireForfeit`. Alternatively, apply a minimum delay/cooldown on `cancelUnlock` itself, or compute forfeiture based on a time-weighted average of cooldown state rather than the instantaneous value, so it cannot be reset for free immediately before a claim.

### Proof of Concept
Foundry test outline:
1. Deploy VLMGP, MasterMagpie, vlMGPBaseRewarder per project test harness; lock MGP for attacker and other stakers.
2. Have attacker call `startUnlock(amount)` to enter cooldown for one slot, advance time partway through `coolDownInSecs` so `getRewardablePercentWAD` would yield a nonzero forfeit if harvested now.
3. Path A (baseline): call `MasterMagpie.multiclaim(vlmgpPool)` directly without cancelling; record `forfeitAmount` emitted in `MGPHarvested`.
4. Path B (exploit): in the same block, call `VLMGP.cancelUnlock(slot)` then `MasterMagpie.multiclaim(vlmgpPool)`; record `forfeitAmount`.
5. Assert Path B's `forfeitAmount == 0` (or significantly less) while Path A's `forfeitAmount > 0`, proving the attacker unilaterally nullified the expected forfeiture with a same-block, cost-free `cancelUnlock` call.

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalVlmgp = fullyInLock + inCoolDown;
        if (userTotalVlmgp == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalVlmgp;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalVlmgp / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalVlmgp;
                }

            }
        }

        return percent;
    }
