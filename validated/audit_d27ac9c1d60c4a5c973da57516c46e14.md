### Title
Ed448 point decoding accepts non-prime-order points, bypassing the library’s group-membership boundary - (File: crypto/ed448/src/point.rs)

### Summary
`Point::is_torsion_free` is implemented as an identity comparison against `(-P) + P`, which is always true. As a result, `GroupEncoding::from_bytes` accepts any decodable non-identity Ed448 point, including low-order/torsion points, while exposing the result as `PrimeGroup`.

### Finding Description
`Point::is_torsion_free` computes:

```rust
((*self * (Scalar::ZERO - Scalar::ONE)) + self).is_identity()
```

`Scalar::ZERO - Scalar::ONE` is `-1`, so this is always `(-P) + P == identity`, regardless of whether `P` has torsion. `GroupEncoding::from_bytes` then ANDs this vacuous check into decoding:

```rust
CtOption::new(point, not_negative_zero & point.is_torsion_free())
```

This means public input passed to `Ed448::read_G` / `Ciphersuite::read_G` can deserialize to a nonzero torsion point even though the generic `Ciphersuite` API requires `G: PrimeGroup`.

Downstream FROST code rejects only the identity point in `Curve::read_G`; it relies on the ciphersuite decoder for canonicality and prime-group membership. Therefore an unprivileged participant can place a small-order commitment where a valid Ed448 group element is required.

### Impact Explanation
The concrete impact is acceptance of protocol messages violating the prime-order group invariant. Such points can be supplied as FROST nonce commitments, PedPoP commitments/encryption keys, DLEq inputs, or other externally deserialized Ed448 points. This can invalidate the intended verification model and can cause signatures or proofs involving torsion components to be accepted by a decoder that explicitly promises `PrimeGroup`.

### Likelihood Explanation
Any Ed448 encoded point supplied to the affected readers can trigger this. The attacker does not need private state; they only need to submit a canonical encoding of a non-prime-order point. The check is deterministic and always returns true for every decoded point.

### Recommendation
Implement an actual subgroup membership check for Ed448, for example by multiplying the decoded point by the prime subgroup order and requiring the result to be identity, while continuing to reject negative zero and non-canonical encodings. Add regression tests asserting every nonzero torsion component is rejected by `Point::from_bytes`, `Ed448::read_G`, and FROST’s `Curve::read_G`.

### Proof of Concept
The bug is directly visible in the implementation:

```rust
impl Point {
  fn is_torsion_free(&self) -> Choice {
    ((*self * (Scalar::ZERO - Scalar::ONE)) + self).is_identity()
  }
}
```

Because `Scalar::ZERO - Scalar::ONE == -1`, this reduces to `(-self + self).is_identity()`, which is always true. The malformed check is used as the only subgroup filter in `from_bytes`, so a validly encoded nonzero torsion point is accepted.
