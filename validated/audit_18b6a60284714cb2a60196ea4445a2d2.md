### Title
Unhandled `CommitIdentity.parseIdentity` throw on malformed commit author/committer date freezes commit history loading - ([File: app/src/lib/git/log.ts])

### Summary
The Cosmos Gravity Bridge bug freezes the whole bridge because a permissionless, attacker-controlled input (a non-UTF8 token name) fails a strict parser (`String::from_utf8`) with no fallback, and the resulting hard error is returned from the event-log parsing path, which then blocks the orchestrator from ever advancing past that event nonce. The structural analog in GitHub Desktop is `CommitIdentity.parseIdentity` in [1](#0-0) , which throws an uncaught `Error` when a commit's author/committer identity string does not match a strict regex. This function is invoked unconditionally, without a try/catch, for every commit returned by `getCommits`, on data that ultimately originates from the cloned/fetched repository (an untrusted source once you consider a malicious remote or a repo containing hand-crafted commit objects).

### Finding Description
`getCommits` in [2](#0-1)  runs `git log` with a custom format (`%an <%ae> %ad` / `%cn <%ce> %cd`, `--date=raw`) and then, for every parsed commit, calls:
```
CommitIdentity.parseIdentity(commit.author.toString()),
CommitIdentity.parseIdentity(commit.committer.toString()),
``` [3](#0-2) 

`CommitIdentity.parseIdentity` requires the identity string to match:
```
/^(.*?) <(.*?)> (\d+) (\+|-)?(\d{2})(\d{2})/
```
and it also validates that the parsed epoch seconds produce a non-`NaN` `Date`:
```
const m = identity.match(/^(.*?) <(.*?)> (\d+) (\+|-)?(\d{2})(\d{2})/)
if (!m) {
  throw new Error(`Couldn't parse identity ${identity}`)
}
...
if (isNaN(date.valueOf())) {
  throw new Error(`Couldn't parse identity ${identity}, invalid date`)
}
``` [4](#0-3) 

Git commit objects are free-form text; the author/committer line format (`NAME <EMAIL> TIMESTAMP TZ`) is not cryptographically or structurally enforced by Git itself when a commit object is fabricated directly (e.g., via `git hash-object -t commit` / `git commit-tree` with a crafted raw object, or via a maliciously-generated pack pushed to a remote/mirrored repo that the victim then clones or fetches). A commit whose author/committer line lacks the well-formed `<email>` delimiters, or whose date field is not a plain decimal epoch with a `+`/`-`HHMM offset (e.g. missing offset, non-numeric epoch, or a date so large/malformed that `new Date()` yields `NaN`), will fail this regex or the `NaN` check and throw.

Unlike `getAuthorIdentity` in [5](#0-4) , which wraps the same `parseIdentity` call in a `try/catch` and returns `null` on failure, `getCommits` has no such guard around the two `parseIdentity` calls inside its `.map()`. The thrown exception propagates out of `getCommits`, out of the git-store's `loadCommitBatch` / `loadLocalCommits` / `getCommitsBetweenBranches`, all of which route the call through `performFailableOperation` in `git-store.ts`. Unlike the Gravity Bridge case, this doesn't literally "freeze the bridge" forever, but it reproduces the same broken invariant: a single crafted, attacker-supplied value silently breaks a parser that the rest of the pipeline assumes will always succeed, and the failure surfaces as a hard, unhandled exception on the exact commit needed to render history/diff/blame instead of degrading gracefully (unlike its sibling function `getAuthorIdentity`, which the codebase's own author clearly intended to guard).

### Impact Explanation
Every code path that loads commit history for a branch containing the malicious commit (`_executeCompare` → `loadCommitBatch`, `_loadNextCommitBatch` → `loadLocalCommits`/`loadCommitBatch`, `getCommitsBetweenBranches`, `getCommit`, `getAuthors`) will hit this exception whenever that malicious commit is included in the requested revision range [6](#0-5) [7](#0-6) . Because the commit stays in the repository's history permanently (it's a real, reachable commit object), every subsequent attempt to view history/diffs/blame for that branch repeats the same failure — a repeatable, deterministic denial-of-service against the History/Compare views for that repository, triggered purely by cloning or fetching a repository that an attacker controls. This matches the "unprivileged, attacker controls a cloned/fetched repository, results in silent/hard corruption of an assumed-safe pipeline" class of the seed report, though the blast radius is scoped to the affected repository's history UI rather than an entire network.

### Likelihood Explanation
The attacker only needs write access to some repository the victim later clones or fetches (a common Desktop threat model: a malicious/compromised open-source repo, or a repo the user is invited to collaborate on). Crafting a commit with a non-conforming author/committer line is straightforward using low-level Git plumbing (`git hash-object -w -t commit`, `git update-ref`) — it requires no special privileges on the victim's machine, no social engineering beyond "clone/open this repository," and no dependency vulnerability. This is a realistic, low-cost attack surface, comparable in spirit to the H-02 report's "manual insertion of a crafted value into a normally well-formed field."

### Recommendation
Wrap the two `CommitIdentity.parseIdentity` calls in `getCommits` (and the `.map(CommitIdentity.parseIdentity)` call in `getAuthors`) in a try/catch, mirroring the defensive pattern already used in `getAuthorIdentity`, and fall back to a placeholder/best-effort `CommitIdentity` (e.g., unknown name/email, `Date` = epoch or commit's raw fields) rather than letting the exception propagate and abort the whole batch of commits. Consider making `CommitIdentity.parseIdentity` itself more permissive (e.g., default the timezone/date fields when they don't parse) so a single malformed commit does not block loading of an entire history page.

### Proof of Concept
Not independently executed against the running app (index-based analysis only), but the reachable path is:
1. In a scratch repository, create a commit whose author line breaks `CommitIdentity`'s regex, e.g. using `git commit-tree` with a raw commit object where the author line is `Mallory <mallory@example.com> notanumber` (non-decimal timestamp) or omits the timezone offset entirely.
2. Push/host that repository and have the victim clone or fetch it in GitHub Desktop.
3. Open the repository in Desktop and view the History tab (or trigger `git-store.ts`'s `loadCommitBatch`/`loadLocalCommits`).
4. `getCommits` (`app/src/lib/git/log.ts:191-192`) calls `CommitIdentity.parseIdentity(commit.author.toString())` on the crafted author line, the regex fails to match (or the date is `NaN`), and an uncaught `Error` is thrown, aborting the commit-loading operation for that branch every time it is attempted.   public static parseIdentity(identity: string): CommitIdentity {
    // See fmt_ident in ident.c:
    //  https://github.com/git/git/blob/3ef7618e6/ident.c#L346
    //
    // Format is "NAME <EMAIL> DATE"
    //  Markus Olsson <j.markus.olsson@gmail.com> 1475670580 +0200
    //
    // Note that `git var` will strip any < and > from the name and email, see:
    //  https://github.com/git/git/blob/3ef7618e6/ident.c#L396
    //
    // Note also that this expects a date formatted with the RAW option in git see:
    //  https://github.com/git/git/blob/35f6318d4/date.c#L191
    //
    const m = identity.match(/^(.*?) <(.*?)> (\d+) (\+|-)?(\d{2})(\d{2})/)
    if (!m) {
      throw new Error(`Couldn't parse identity ${identity}`)
    }

    const name = m[1]
    const email = m[2]
    // The date is specified as seconds from the epoch,
    // Date() expects milliseconds since the epoch.
    const date = new Date(parseInt(m[3], 10) * 1000)

    if (isNaN(date.valueOf())) {
      throw new Error(`Couldn't parse identity ${identity}, invalid date`)
    }

export async function getCommits(
  repository: Repository,
  revisionRange?: string,
  limit?: number,
  skip?: number,
  additionalArgs: ReadonlyArray<string> = []
): Promise<ReadonlyArray<Commit>> {
  const { formatArgs, parse } = createLogParser({
    sha: '%H', // SHA
    shortSha: '%h', // short SHA
    summary: '%s', // summary
    body: '%b', // body
    // author identity string, matching format of GIT_AUTHOR_IDENT.
    //   author name <author email> <author date>
    // author date format dependent on --date arg, should be raw
    author: '%an <%ae> %ad',
    committer: '%cn <%ce> %cd',
    parents: '%P', // parent SHAs,
    trailers: '%(trailers:unfold,only)',
    refs: '%D',
  })

  const args = ['log']

  if (revisionRange !== undefined) {
    args.push(revisionRange)
  }

  args.push('--date=raw')

  if (limit !== undefined) {
    args.push(`--max-count=${limit}`)
  }

  if (skip !== undefined) {
    args.push(`--skip=${skip}`)
  }

  args.push(
    ...formatArgs,
    '--no-show-signature',
    '--no-color',
    ...additionalArgs,
    '--'
  )
  const result = await git(args, repository.path, 'getCommits', {
    successExitCodes: new Set([0, 128]),
    encoding: 'buffer',
  })

  // if the repository has an unborn HEAD, return an empty history of commits
  if (result.exitCode === 128) {
    return new Array<Commit>()
  }

  const parsed = parse(result.stdout)

  return parsed.map(commit => {
    // Ref is of the format: (HEAD -> master, tag: some-tag-name, tag: some-other-tag,with-a-comma, origin/master, origin/HEAD)
    // Refs are comma separated, but some like tags can also contain commas in the name, so we split on the pattern ", " and then
    // check each ref for the tag prefix. We used to use the regex /tag: ([^\s,]+)/g)`, but will clip a tag with a comma short.
    const tags = commit.refs
      .toString()
      .split(', ')
      .flatMap(ref => (ref.startsWith('tag: ') ? ref.substring(5) : []))

    return new Commit(
      commit.sha.toString(),
      commit.shortSha.toString(),
      commit.summary.subarray(0, 100 * 1024).toString(),
      commit.body.subarray(0, 100 * 1024).toString(),
      CommitIdentity.parseIdentity(commit.author.toString()),
      CommitIdentity.parseIdentity(commit.committer.toString()),
      commit.parents.length > 0 ? commit.parents.toString().split(' ') : [],
      // We know for sure that the trailer separator will be ':' since we got
      // them from %(trailers:unfold) above, see `git help log`:
      //
      //   "key_value_separator=<SEP>: specify a separator inserted between
      //    trailer lines. When this option is not given each trailer key-value
      //    pair is separated by ": ". Otherwise it shares the same semantics as
      //    separator=<SEP> above."
      parseRawUnfoldedTrailers(commit.trailers.toString(), ':'),
      tags
    )
  })
}

export async function getAuthorIdentity(
  repository: Repository
): Promise<CommitIdentity | null> {
  const result = await git(
    ['var', 'GIT_AUTHOR_IDENT'],
    repository.path,
    'getAuthorIdentity',
    {
      successExitCodes: new Set([0, 128]),
    }
  )

  // If user.user.useconfigonly is set and no user.name or user.email
  if (result.exitCode === 128) {
    return null
  }

  try {
    return CommitIdentity.parseIdentity(result.stdout)
  } catch (err) {
    return null
  }
}

  /** Load a batch of commits from the repository, using a given commitish object as the starting point */
  public async loadCommitBatch(commitish: string, skip: number) {
    if (this.requestsInFight.has(LoadingHistoryRequestKey)) {
      return null
    }

    const requestKey = `history/compare/${commitish}/skip/${skip}`
    if (this.requestsInFight.has(requestKey)) {
      return null
    }

    this.requestsInFight.add(requestKey)

    const commits = await this.performFailableOperation(() =>
      getCommits(this.repository, commitish, CommitBatchSize, skip)
    )

    this.requestsInFight.delete(requestKey)
    if (!commits) {
      return null
    }

    this.storeCommits(commits)
    return commits.map(c => c.sha)
  }

  public async loadLocalCommits(
    branch: Branch | null,
    skip?: number
  ): Promise<string[] | null> {
    if (branch === null) {

      return null
    }

    let localCommits: ReadonlyArray<Commit> | undefined

        getCommits(this.repository, range, CommitBatchSize, skip)

        getCommits(this.repository, 'HEAD', CommitBatchSize, skip, [
          '--not',
          '--remotes',
        ])
      )
    }

    if (!localCommits) {
      return null
    }

    this.storeCommits(localCommits)
