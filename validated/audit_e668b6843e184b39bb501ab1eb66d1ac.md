### Title
Deep-link `openRepo…?pr=` silently checks out an attacker-controlled fork branch with no user confirmation - ([File: app/src/ui/dispatcher/dispatcher.ts])

### Summary
`parseAppURL` in `app/src/lib/parse-app-url.ts` accepts a `pr` query parameter on `x-github-client://openRepo/<url>?pr=<n>` deep links and packages it into an `IOpenRepositoryFromURLAction`, which `Dispatcher.dispatchURLAction`/`openRepositoryFromUrl` routes straight into `openPullRequestFromUrl` with no gating flag or user-confirmation step, similar to how the Poseidon2 `end_top_level` flag was not properly constrained to gate the execution-bus interaction. If the corresponding GitHub repository is already added in Desktop, the whole PR-checkout pipeline (`_checkoutPullRequest` → `_findPullRequestBranch` → `addRemote`/`_fetchRemote`/`_createBranch` → `_checkoutBranch`) runs automatically, mutating the user's working directory and remotes without any dialog. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`openPullRequestFromUrl(url, pr)` fetches the PR object from the GitHub API for the attacker-supplied `url`/`pr` pair, resolves it to a locally-known repository via `getRepositoryFromPullRequest`, and — critically — if that repository is found, it does **not** ask the user before proceeding: [4](#0-3) 

It then unconditionally calls `_checkoutPullRequest(repository, pullRequest.number, head.repo.owner.login, head.repo.clone_url, head.ref)`: [5](#0-4) 

`_checkoutPullRequest` → `_findPullRequestBranch` will silently add a new remote pointing at the attacker-controlled `headCloneUrl` (the fork), fetch it, create a local `pr/<n>` branch, and `_checkoutPullRequest` immediately checks it out: [6](#0-5) [7](#0-6) 

Unlike the equivalent user-initiated path (`pull-request-list.tsx` → `dispatcher.checkoutPullRequest`, which is only reachable via an explicit click inside the app on a PR the user selected), the deep-link path reaches the identical `_checkoutPullRequest` sink from an untrusted `url-action` IPC message originating from an OS-level protocol handler with a single condition ("repository already known to Desktop") and zero interactive confirmation — there is no `is_valid`/`enabled`-style gate analogous to `assert_bool(enabled)` in the Poseidon2 fix requiring the action to correspond to a real, user-approved top-level operation. [8](#0-7) [9](#0-8) 

The `pr` value is only validated for shape (`/^\d+$/`), and the `branch` for a PR is only checked to match `/^pr\/\d+$/` — neither check restricts *who* can create the PR or what fork it originates from, so any GitHub user can open a PR against a public repo the victim has cloned and then send them a crafted deep link: [10](#0-9) 

### Impact Explanation
This silently rewrites the victim's checked-out branch and working directory contents to an attacker-chosen fork/ref, and adds an attacker-controlled remote (`github-desktop-<owner>`) to the repository — matching the "silent corruption of what the user commits or pushes" impact class. If the victim subsequently stages/commits/pushes without noticing they are no longer on their intended branch, they could push attacker-authored content, or unknowingly build/run code from the attacker's branch if their workflow auto-builds on checkout.

### Likelihood Explanation
The only precondition is that the victim already has the targeted repository added in GitHub Desktop and clicks a single external link (in a browser, email, chat message, or GitHub UI) that opens `x-github-client://openRepo/<repo-url>?pr=<n>`. The attacker only needs to open a PR against a public repository (or any repo they can also access) — no privileged access, no local/physical access, and no social-engineering beyond a normal-looking link click.

### Recommendation
Before automatically checking out a PR reached via `open-repository-from-url`, `openPullRequestFromUrl` should surface an explicit confirmation dialog (as is already the pattern used for `ConfirmOverwriteStash`/`StashAndSwitchBranch` in `_checkoutBranch`), showing the fork owner/URL and ref being checked out, and require the user to opt in, rather than calling `_checkoutPullRequest` unconditionally when `pr` is present in the deep link.

### Proof of Concept
1. Victim has `github.com/victim-org/project` added in GitHub Desktop.
2. Attacker opens a pull request (PR #999) against `victim-org/project` from `attacker/project` with a branch containing malicious changes.
3. Attacker sends the victim a link: `x-github-client://openRepo/https://github.com/victim-org/project?pr=999`.
4. Victim clicks the link (in browser/chat/email). Desktop's `open-url`/`handleAppURL` → `parseAppURL` → `dispatchURLAction` → `openRepositoryFromUrl` → `openPullRequestFromUrl` fires.
5. Because the repository already exists locally, Desktop silently adds remote `github-desktop-attacker` pointing at `attacker/project`, fetches it, creates/checks out branch `pr/999`, with no confirmation dialog shown to the victim, per `_checkoutPullRequest`/`_findPullRequestBranch`.

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }
    if (!isRepositoryWithGitHubRepository(repository)) {
      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    if (pullRequest.head.repo === null) {
      return null
    }

    await this.appStore._checkoutPullRequest(
      repository,
      pullRequest.number,
      pullRequest.head.repo.owner.login,
      pullRequest.head.repo.clone_url,
      pullRequest.head.ref
    )

    return repository
  }
