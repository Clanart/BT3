### Title
`ReceivedOutput`/`Scanner` attribute outputs to a key without verifying the offset actually controls the `script_pubkey`, so funds can be reported received that are not spendable - (networks/bitcoin/src/wallet/mod.rs)

### Summary
The referenced ZetaChain bug is a state-flag-set-before-success flaw: `IsAbortRefunded` is set regardless of whether the refund deposit succeeded, permanently blocking manual recovery and losing user funds. In `bitcoin-serai`, the analogous trust gap is that an output is *declared* owned/spendable based solely on an `offset` ↔ `script_pubkey` association that is never validated on the deserialization path. `ReceivedOutput::read` (`networks/bitcoin/src/wallet/mod.rs:122-134`) accepts three independent, attacker-controlled fields — a scalar `offset`, a `TxOut`, and an `OutPoint` — and returns a `ReceivedOutput` that downstream code treats as spendable by `key + offset·G`. Nothing checks that `p2tr_script_buf(key + offset·G) == output.script_pubkey`.

### Finding Description
- `Scanner::scan_transaction` (`wallet/mod.rs:199-214`) constructs `ReceivedOutput` with a correct offset looked up from `scripts: HashMap<ScriptBuf, Scalar>` populated by `Scanner::new`/`register_offset` — that path is internally consistent.
- `ReceivedOutput::read` (`wallet/mod.rs:122-134`), however, is an explicitly in-scope untrusted-bytes entry point. It reads `offset` via `Secp256k1::read_F` and `output`/`outpoint` via `consensus_decode`, then pairs them unconditionally. Any `ReceivedOutput` deserialized from coordinator/tributary-communicated bytes can therefore claim an arbitrary `script_pubkey` under an arbitrary `offset`.
- Because the spend path derives the signing key from `output.offset()` while Bitcoin consensus enforces the real `script_pubkey`, a mismatched pair produces an input whose Schnorr signature can never satisfy the output. The UTXO is still counted as received (it enters the output set used to build/sign plans), yet is unspendable — the same "marked done, actually failed, no recovery" shape as the ZetaChain bug.

### Impact Explanation
An unprivileged party who can get crafted `ReceivedOutput` bytes into a plan (e.g., via a message they cause to be processed that carries serialized outputs, or bytes fed to `ReceivedOutput::read`) causes the multisig to treat funds as controlled when they are not: a plan/TX is built and signed against a prevout whose script the derived key cannot unlock. The result is concrete loss: real outputs can be committed into an invalid transaction (burning their value in a non-broadcastable/non-confirming TX), or phantom balance is reported as received while never spendable. This matches the accepted impact "funds reported received that are not spendable".

### Likelihood Explanation
Reachability depends on whether `ReceivedOutput::read` output crosses a trust boundary — i.e., whether outputs are serialized into coordinator/tributary messages or DB state influenced by peer-supplied data rather than produced exclusively by the local `Scanner`. If outputs only ever originate from `scan_transaction` locally, the practical severity drops toward Medium/Low because the mis-binding is only self-inflicted. If serialized `ReceivedOutput`s are exchanged or stored from less-trusted input, the attacker's cost is just crafting `offset`/`TxOut`/`OutPoint` triples — no collusion needed.

### Recommendation
Bind the offset to the output on read and on use: after constructing a `ReceivedOutput`, verify `p2tr_script_buf(scanner_key + GENERATOR * offset) == Some(output.script_pubkey)` (or store the key alongside and check it before `prepare_send`/`SignableTransaction` uses the input). Alternatively, stop serializing `offset` and re-derive it via `Scanner`'s script map from `output.script_pubkey`, making the trusted scanner the sole source of the offset↔script binding — the analog of "only set `IsAbortRefunded` when the refund actually succeeded".

### Proof of Concept
```
// Attacker-controlled bytes handed to ReceivedOutput::read:
let mut bytes = Vec::new();
bytes.extend(Scalar::ZERO.to_bytes());          // offset = 0 => claims group key
// TxOut paying to an unrelated P2TR key the attacker chose:
let victim_out = TxOut { value: Amount::from_sat(100_000), script_pubkey: attacker_script };
bytes.extend(serialize(&victim_out));
bytes.extend(serialize(&OutPoint { txid: real_txid, vout: 0 })); // a real prevout

let ro = ReceivedOutput::read(&mut &bytes[..]).unwrap();
// ro.offset() == 0 => signer derives the group key, but the prevout's
// script_pubkey requires attacker_script's key. The input is counted as
// spendable balance yet any TX spending it is invalid: funds reported
// received that are not spendable, with no flag/dirty state to allow retry.
```
<Caveat> Full confirmation requires inspecting consumers of `ReceivedOutput` in `wallet/send.rs` and the processor's plan flow to verify the deserialized binding is never re-checked; within the indexed scope, `read` performs no such validation and `Scanner` is the only component that establishes the offset↔script mapping. </Caveat> [1](#0-0) [2](#0-1) [3](#0-2)

  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
