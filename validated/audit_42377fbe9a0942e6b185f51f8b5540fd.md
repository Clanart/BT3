### Title
Empty aggregate Schnorr signature bypasses signature verification - ([File: crypto/schnorr/src/aggregate.rs](crypto/schnorr/src/aggregate.rs))

### Summary
`SchnorrAggregate::verify` accepts a zero-signer aggregate whose scalar is zero. `SchnorrAggregate::read` permits an attacker to deserialize this structure directly from public bytes, while `SchnorrAggregator::complete` explicitly refuses to produce an empty aggregate, indicating that an empty aggregate is not intended to be a valid signature. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
`SchnorrAggregate::read` trusts the encoded `Rs` length and returns an aggregate containing zero nonces when the encoded length is zero. [4](#0-3) 

During verification, the implementation only checks that the encoded nonce count equals `keys_and_challenges.len()`. When both are empty, the loop adding nonce and public-key statements does not execute. The sole remaining verification statement is `-s * G`, so an attacker can set `s = 0` and make the multiexp result the identity. [2](#0-1) 

The legitimate aggregation path rejects this case because `SchnorrAggregator::complete` returns `None` when no signatures were aggregated. The verifier therefore accepts a forgery that the library’s own aggregator cannot legitimately produce. [3](#0-2) 

### Impact Explanation
An unprivileged attacker can feed `SchnorrAggregate::read` a short byte string representing `Rs = []` and `s = 0`, then call `SchnorrAggregate::verify` with an empty `keys_and_challenges` list and receive `true`. This is a forged aggregate signature: it verifies without any signer, nonce, private key, or prior signature. [1](#0-0) [5](#0-4) 

Any protocol path that treats `SchnorrAggregate::verify(dst, &[])` as proof of authorization may accept an attacker-controlled aggregate as authentic. The verifier itself performs no minimum-signer check and no semantic distinction between “aggregate of zero valid signatures” and a valid authorization token. [6](#0-5) 

### Likelihood Explanation
The exploit is deterministic and requires no interaction with honest signers. The attacker only needs to supply canonical zero-length aggregate bytes and a canonical zero scalar; `read` does not reject the empty vector and `verify` reduces the statement to `0 * G == identity`. [1](#0-0) [5](#0-4) 

The likelihood depends on a caller invoking `verify` with an empty signer list. Since the API exposes a public byte reader and public verifier, the vulnerable condition is reachable entirely through attacker-controlled serialized input. [7](#0-6) 

### Recommendation
Reject empty aggregates in `SchnorrAggregate::verify` before evaluating the multiexp, mirroring `SchnorrAggregator::complete`’s refusal to emit an empty aggregate. The verification path should additionally reject empty `keys_and_challenges`, even if the serialized `Rs` list is empty. [8](#0-7) [9](#0-8) 

For defense in depth, `SchnorrAggregate::read` should either reject a zero nonce count or document that deserialization may produce a value that `verify` must reject. A regression test should deserialize an all-zero minimal aggregate and assert that verification returns `false`. [1](#0-0) 

### Proof of Concept
For a ciphersuite with a 32-byte scalar representation, such as Ristretto, the forged encoding is:

```text
00 00 00 00                                      // Rs.len() = 0
00 00 ... 00                                     // s = 0, 32 bytes
```

Conceptual Rust demonstration:

```rust
use ciphersuite::{group::ff::PrimeField, Ciphersuite};
use schnorr::aggregate::SchnorrAggregate;

fn forge_empty_aggregate<C: Ciphersuite>(dst: &'static [u8]) -> bool {
  let mut encoded = Vec::new();
  encoded.extend(0u32.to_le_bytes());
  encoded.extend(C::F::ZERO.to_repr().as_ref());

  let aggregate =
    SchnorrAggregate::<C>::read(&mut encoded.as_slice()).unwrap();

  aggregate.verify(dst, &[])
}
```

`read` accepts the empty nonce vector and zero scalar. `verify` then builds only the `(-0) * G` statement, whose multiexp result is the identity, so it returns `true`. [1](#0-0) [5](#0-4)
