### Title
Blind SSRF via Unvalidated Redirects in Data Layer Mirror/Downloader HTTP Fetches - (File: chia/data_layer/download_data.py)

### Summary
Chia's DataLayer sync path fetches delta/full-tree files from mirror server URLs using `aiohttp.ClientSession` without disabling redirects or validating the resolved/redirected destination address. Mirror URLs are stored as "external trust inputs" (per `.cursor/context/data-layer.md`) and are populated into the local subscriptions table from on-chain mirror coin data via `update_subscriptions_from_wallet()`. Any peer that advertises itself as a mirror for a store can supply a URL that responds with an HTTP redirect to an internal address (e.g. `127.0.0.1`, cloud metadata service, or another internal-only service), and a syncing DataLayer node will follow that redirect and issue the resulting GET/POST request — exactly the SSRF-via-redirect bug class described in the Directus advisory (CWE-918), but here reachable through DataLayer's peer/mirror sync flow rather than a file-import URL field.

Because there is no check on the final resolved host/IP of the request (no DNS-resolution/IP-range validation before connecting, and no rejection of a redirect `Location` pointing to a private/loopback/link-local address), a malicious mirror can point the client at a public redirector that 302s to `http://127.0.0.1:<port>/...` or other internal-only endpoints, and the DataLayer node running `fetch_and_validate()` → `insert_from_delta_file()` → `download_file()` → `http_download()` will transparently follow it and issue the resulting HTTP request from the victim node. ### Impact Explanation
An attacker who can get their URL registered as a mirror/subscription server for a store (a normal, low-privilege DataLayer/wallet operation, not an operator-only or malicious-peer action) can force any node that subscribes to or owns that store to make blind outbound HTTP GET/POST requests to attacker-chosen internal or loopback addresses whenever `periodically_manage_data()` runs its subscription-update cycle. This can be used to probe or trigger GET-based side effects on internal services reachable from the DataLayer host (local RPC endpoints, internal metadata services, other local daemons), consistent with the Medium/Blind-SSRF classification of the referenced Directus advisory. The response is not returned to the attacker directly (blind), but as with the original report the impact is not neutralized by blindness — it enables request forgery against any GET-reachable internal target.

### Likelihood Explanation
Likelihood is moderate-to-high for any environment where DataLayer is enabled and where a node subscribes to third-party stores or accepts third-party mirror URLs, since:
- No code path disables redirects (`allow_redirects` never set to `False` anywhere in the module).
- No IP-range/DNS validation is performed on the mirror or plugin URL before or after connecting.
- The sync loop (`periodically_manage_data()` / `update_subscription()` / `fetch_and_validate()`) runs automatically and repeatedly without user interaction once a subscription exists.

### Recommendation
- Disable automatic redirect following (`allow_redirects=False`) for all outbound HTTP requests in `chia/data_layer/download_data.py` (`http_download`) and `chia/data_layer/data_layer.py` (`get_downloader`, `upload_files`, `add_missing_files`), and explicitly reject/re-validate any `Location` header before manually following a redirect.
- Before connecting (and after any redirect), resolve the target hostname and reject requests whose resolved IP falls in private/loopback/link-local/multicast ranges, mirroring the original Directus SSRF fix.
- Consider allow-listing mirror/plugin URL schemes and hosts, or requiring explicit user opt-in per mirror URL rather than automatic use of wallet-reported mirror lists.

### Proof of Concept
1. Stand up a public HTTP server that responds to `GET /<any-path>` with `302 Found` and `Location: http://127.0.0.1:<internal-port>/<path>` (or `http://169.254.169.254/...`).
2. Register this server as a mirror URL for a DataLayer store via the normal wallet/DataLayer mirror-registration flow so it is stored via `update_subscriptions_from_wallet()` and surfaced by `get_available_servers_for_store()`.
3. Have a victim node subscribe to (or otherwise sync) that store; on the next `periodically_manage_data()` cycle, `fetch_and_validate()` → `insert_from_delta_file()` → `download_file()` → `http_download()` issues `session.get(server_info.url + "/" + filename, ...)` against the attacker's server.
4. Because `allow_redirects` is left at its aiohttp default (`True`), the client transparently follows the 302 to the internal target and issues the resulting GET request from the victim node's network context, confirming SSRF via redirect exactly as in the Directus PoC.

        async with self.db_wrapper.writer() as writer:

                {
                    "tree_id": store_id,

                "SELECT * FROM subscriptions WHERE from_wallet == 0 AND tree_id == :tree_id",
                {
                    "tree_id": store_id,
                },
            )
            from_subscriptions_urls = {row["url"] async for row in cursor}
            additions = {url for url in new_urls if url not in old_urls}
            removals = [url for url in old_urls if url not in new_urls]

                    "DELETE FROM subscriptions WHERE url == :url AND tree_id == :tree_id",
                    {
                        "url": url,
                        "tree_id": store_id,
                    },
                )

                if url not in from_subscriptions_urls:
                    await writer.execute(
                        "INSERT INTO subscriptions(tree_id, url, ignore_till, num_consecutive_failures, from_wallet) "
                        "VALUES (:tree_id, :url, 0, 0, 1)",
                        {
                            "tree_id": store_id,
                            "url": url,

    async def get_available_servers_for_store(self, store_id: bytes32, timestamp: int) -> list[ServerInfo]:
        subscriptions = await self.get_subscriptions()
        subscription = next((subscription for subscription in subscriptions if subscription.store_id == store_id), None)
        if subscription is None:
            return []
        servers_info = []
        for server_info in subscription.servers_info:
            if timestamp > server_info.ignore_till:
                servers_info.append(server_info)
        return servers_info
