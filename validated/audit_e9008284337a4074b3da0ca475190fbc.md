### Title
`CallDispatcher` is a shared, permission-less contract, so tokens stranded in it after intent settlement calldata execution can be pulled out by anyone — (File: `evm/src/utils/CallDispatcher.sol`, `evm/src/apps/intentsv2/IntentsBase.sol`)

### Summary
The external report's core broken invariant is: a bridge/receiver contract executes an external call whose outcome can leave tokens sitting in a shared address, and because that address accepts unrestricted external calls, an unprivileged attacker can pull the tokens. Hyperbridge's `IntentGatewayV2`/`ExtrinsicIntents`/`IntrinsicIntents` postdispatch flow reproduces this exact pattern with `CallDispatcher`, which is a single shared contract used for every order's arbitrary calldata execution and has **no access control on `dispatch()`**.

### Finding Description
`_execute()` in `evm/src/apps/intentsv2/IntentsBase.sol:438-485` routes solver output through the singleton `CallDispatcher` (`_params.dispatcher`) for arbitrary DeFi calldata execution (swap-then-pay patterns), then sweeps back residual balances: [1](#0-0) 

The sweep loop only iterates over `order.output.assets[i]` for `i < outputsLen` — i.e. only the tokens explicitly declared as the order's *output* tokens are swept back to the gateway: [2](#0-1) 

Any token balance that ends up on the `CallDispatcher` which is **not** one of `order.output.assets` — e.g. an intermediate/reward token produced by a multi-hop swap, referral tokens, airdropped dust, or leftover approval-triggered transfers from the arbitrary calldata the order itself specified — is never accounted for or swept. It simply remains on the `CallDispatcher`.

Critically, `CallDispatcher.dispatch()` itself has **no caller restriction**: [3](#0-2) 

It is `external` with no `onlyOwner`/`onlyGateway`/`msg.sender` check, and the contract also has an unrestricted `receive()`: [4](#0-3) 

Because the same `CallDispatcher` instance is shared across every order fill and every `IntentGatewayV2` deployment that references it (`_params.dispatcher`), any address on-chain can call `CallDispatcher.dispatch(...)` directly with a `Call[]` that transfers out whatever balance currently sits on it — this exactly matches the external report's exploit shape: a shared "receiver" contract that (a) can end up holding tokens after a partial/incomplete settlement path, and (b) accepts unrestricted external calls, allowing anyone to sweep those tokens before the protocol's own governance-gated `SweepDust` path ever runs.

### Impact Explanation
This directly matches the bounty's "stealing or loss of funds" and "unauthorized transaction or execution" categories. An unprivileged attacker can drain any token balance left on the shared `CallDispatcher` — including balances resulting from a legitimate solver's own postdispatch calldata execution (e.g., swap dust/rewards not declared as `output.assets`) — before the protocol has a chance to account for or sweep it via governance (`SweepDust`). Because `CallDispatcher` is shared across the whole gateway (all orders, potentially multiple app contracts), the attack surface is not scoped to one order; any dust from any concurrent or historical fill is a target.

### Likelihood Explanation
No malicious peer, relayer, prover, or admin is required — the attacker only needs to observe an on-chain event (`DustCollected` is even emitted for the amounts swept, but nothing prevents residual non-listed-token balances from existing) and call the public `CallDispatcher.dispatch()` function directly. This is a pure unprivileged public-entrypoint attack: `dispatch()` performs no `msg.sender` check and the contract's whole purpose is to blindly execute whatever `Call[]` is supplied.

### Recommendation
- Add an access-control check to `CallDispatcher.dispatch()` restricting the caller to the registered `IntentGatewayV2`/gateway contract(s) that are permitted to route escrowed value through it (e.g., an `onlyGateway` modifier configured at construction).
- Alternatively, deploy a fresh, ephemeral `CallDispatcher` per order (e.g., via `CREATE2` keyed on the order commitment) rather than sharing a single singleton across all orders, so no cross-order dust or balance can ever coexist with an attacker-controlled window.
- In `_execute()`, sweep the *full* token balance of the dispatcher for any token touched by the calldata (not just the declared `output.assets`), or require postdispatch calldata to whitelist all tokens it can produce so they are all accounted for in `DustCollected`/escrow.

### Proof of Concept
1. A solver fills a cross-chain or same-chain order whose `output.call` performs a multi-hop swap through the `CallDispatcher` (e.g., swap token A → B → C, but the order's declared `output.assets` list only includes token C).
2. Due to slippage/fee mechanics of the DEX route, a small amount of the intermediate token B remains on the `CallDispatcher` after the swap completes. `_execute()`'s sweep loop (`evm/src/apps/intentsv2/IntentsBase.sol:447-473`) never inspects token B because it isn't in `order.output.assets`, so it is left on the `CallDispatcher`.
3. Any external address (attacker) calls `CallDispatcher.dispatch(abi.encode(calls))` directly, where `calls` is `[{to: tokenB, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, balance)}]`.
4. Since `dispatch()` performs no caller check (`evm/src/utils/CallDispatcher.sol:44-62`), the call succeeds and token B is transferred to the attacker, permanently bypassing the protocol's `SweepDust`/governance-controlled dust-recovery flow.

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {
            Call[] memory finalCalls = new Call[](sweepCount);
            for (uint256 i; i < sweepCount;) {
                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
    }

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
