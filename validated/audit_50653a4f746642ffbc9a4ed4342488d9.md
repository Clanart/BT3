### Title
Attacker-controlled `WWW-Authenticate` realm header spoofs GitHub Enterprise endpoint classification, triggering unsolicited OAuth sign-in flow - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The Presale bug is a "trust the wrong/loosely-typed value for a security decision" pattern (comparing a precise `ERC20` contract handle against a bare `address(0x0)` constant, letting attacker-influenced state slip past a check). The closest analog in GitHub Desktop is in `getEndpointKind` in `app/src/lib/trampoline/trampoline-credential-helper.ts`, where the classification of a git remote host as "GitHub Enterprise" vs. "generic" is derived from a raw string comparison against the `WWW-Authenticate` header text that the remote server itself supplies — a value that is fully attacker-controlled when the remote is a malicious/compromised git host.

### Finding Description
When Git needs credentials for a remote, our trampoline credential helper decides how to treat the request via `getEndpointKind`: [1](#0-0) 

Git forwards any `WWW-Authenticate` response headers it receives from the remote as `wwwauth[...]` credential fields. The code trusts the literal contents of that attacker-suppliable header (`realm="GitHub"`) to conclude the endpoint is `'enterprise'`, i.e., a legitimate GitHub Enterprise server, purely from a substring match — with no verification that the host is actually a GitHub product (no TLS cert check, no `/api/v3/meta` probe, no allowlist).

That classification then feeds directly into a security-relevant branch in `getCredential`: [2](#0-1) 

Because `endpointKind !== 'generic'` and no stored account matches the malicious host's `apiEndpoint`, Desktop invokes `ui.promptForGitHubSignIn(endpoint)`, which opens the app's native `SignIn` popup and, for non-`github.com` hosts, calls `dispatcher.beginEnterpriseSignIn` and `setSignInEndpoint(origin)` using the attacker's own origin: [3](#0-2) 

This is effectively an invalid/insufficient comparison: a security decision (is this endpoint a trustworthy GitHub Enterprise instance that should be offered a real Desktop OAuth sign-in?) is decided by a bare string containment check on data the remote endpoint fully controls, exactly mirroring the Solidity bug's root cause of trusting a loosely-compared, attacker-influenced value for an authorization-relevant branch.

### Impact Explanation
An attacker who controls a git remote/proxy (e.g., a malicious clone URL, a compromised mirror, a MITM on an internal network, or a submodule URL embedded in a cloned repository) can respond to Git's HTTP authentication probe with `WWW-Authenticate: Basic realm="GitHub"`. When the user performs any git operation against that host through Desktop (clone, fetch, push, submodule update), Desktop will:
- Misclassify the arbitrary host as GitHub Enterprise, and
- Pop the legitimate-looking Desktop "Sign in to GitHub Enterprise" dialog pointed at the attacker's origin, initiating a real OAuth/device flow against attacker infrastructure.

This satisfies the "unauthorized OAuth or account binding" impact category from a git remote/proxy response the attacker controls — Desktop is tricking the user, via its own trusted UI chrome, into starting an authentication flow with an untrusted host, which can be used to phish GitHub Enterprise credentials or bind an "account" entry under the attacker's chosen endpoint.

### Likelihood Explanation
Reaching `getEndpointKind`'s header-trust branch requires only that: (1) the endpoint is not already `isDotCom`/`isGHE`/`isGist`, and (2) no `findGitHubTrampolineAccount` match exists for that host — both trivially true for an attacker-controlled origin the user has never signed into. The header value is entirely the server's choice on any HTTPS 401 response to Git's credential probe, so no privileged position, malware, or unusual user action is required beyond visiting/cloning an attacker-supplied repository/remote URL, which is within the defined valid-impact model (attacker controls the git remote/proxy response).

### Recommendation
Do not use unauthenticated, attacker-supplied header content as sole evidence of a host's identity/trust level. At minimum:
- Require corroborating verification before classifying a host as `'enterprise'` from a `WWW-Authenticate` realm string — e.g., only accept the header hint as a hint to fall back to `isGitHubHost(endpoint)` (an actual API probe), rather than an immediate authoritative classification.
- Never auto-populate `setSignInEndpoint`/`beginEnterpriseSignIn` with an arbitrary, previously-unknown origin without an explicit user confirmation step showing the exact host being connected to.

### Proof of Concept
1. Stand up an HTTPS server that responds to Git's credential-probe request with header `WWW-Authenticate: Basic realm="GitHub"` for any path.
2. In GitHub Desktop, clone or add a remote pointing to `https://attacker.example.com/foo/bar.git` (or embed it as a submodule URL in an otherwise innocuous repository) and trigger a fetch/clone.
3. Desktop's trampoline credential helper calls `getEndpointKind`, sees `realm="GitHub"` in the forwarded `wwwauth[...]` field, and returns `'enterprise'`.
4. Since no account is registered for `attacker.example.com`, `getCredential` calls `ui.promptForGitHubSignIn('https://attacker.example.com/...')`, which shows the trusted "Sign in to GitHub Enterprise" dialog wired to the attacker's origin via `setSignInEndpoint(origin)`. [4](#0-3)

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
