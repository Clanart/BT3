I found a clear analog: `bid_pool.go`'s `validateBid` documents 6 validation rules (per its own README and rule comments), but silently omits enforcing `bid.MaxGasPrice` — a field that exists on `BidData` and is meant to bound the gas price the searcher is willing to pay, yet it is never checked anywhere in `validateBid`, `validateBidSigs`, or the EIP-712 digest computation used for v2-signed bids.

### Title
`MaxGasPrice` bid constraint is signed conditionally but never validated by the bid pool, allowing gas-price-unbounded auction execution - ([File: kaiax/auction/impl/bid_pool.go])

### Summary
`auction.BidData.MaxGasPrice` [1](#0-0)  is a field intended to cap the gas price a searcher's bid execution may use, analogous to `certificateOIDs` in the sigstore advisory: it is part of the documented data model and is even included in the EIP-712 v3.0 signature typehash [2](#0-1) , but the bid pool's actual admission/validation logic (`validateBid`) never reads or enforces it.

### Finding Description
`BidPool.validateBid` explicitly enumerates and enforces exactly six rules mirrored from the module's own README (sender-winner uniqueness, block-number range, bid > 0, data size cap, call-gas-limit cap, and signature validity) [3](#0-2)  and the README documents the same six checks with no mention of `MaxGasPrice` [4](#0-3) . Nowhere in `validateBid`, `validateBidSigs`, `insertBid`, or `getBidTxGasLimit`/bid tx generation is `bid.MaxGasPrice` read or compared against anything (e.g., the current base fee, the tx pool's configured gas price, or the gas price actually used when constructing/executing the bid transaction).

The field is only ever touched in two places: (1) building the EIP-712 v3.0 digest for signature recovery [5](#0-4) , and (2) round-tripping through `EncodeAuctionCallData`/`DecodeAuctionCallData`/`ToBid` for the on-chain calldata and RPC input [6](#0-5) [7](#0-6) . This is precisely the sigstore bug pattern: a security-relevant constraint field exists in the data structure and is even carried through signing/encoding, but the component responsible for enforcing it (`validateBid`, analogous to `createVerificationPolicy`) silently drops it and never asserts it against the actual execution parameters used when the bid is accepted and later included in a block.

Further compounding this, when the version is unknown/empty, `GetHashTypedData` falls back to the v2.1 typehash which excludes `MaxGasPrice` entirely from the signed digest [8](#0-7) , meaning a searcher's stated `MaxGasPrice` constraint is not even cryptographically bound to their signature in that path, let alone checked by the pool.

### Impact Explanation
An unprivileged auction bidder (searcher) or the auctioneer forwarding a bid can submit a bid with an unbounded or arbitrary `MaxGasPrice` value that is never validated against reality. Since the bid pool accepts the bid purely based on `bid.Bid > 0`, size/gas-limit caps, and signature validity, the intended gas-price safety bound is unenforced, allowing the bid execution flow to proceed without the guardrail the field is meant to provide. This can result in the bid's generated transaction being processed at a gas price/cost the searcher did not actually authorize to be checked, undermining the auction's fee-safety guarantee — a concrete fee/settlement-abuse risk within the auction module's transaction-inclusion path (a single submitted bid via `auction_submitBid` RPC).

### Likelihood Explanation
High reachability: any external caller of the public `auction_submitBid` RPC (`AuctionAPI.SubmitBid` → `ToBid` → `BidPool.AddBid` → `validateBid`) [9](#0-8)  can supply an arbitrary `MaxGasPrice` in `BidInput` [10](#0-9) , and it passes straight through the entire validation pipeline unchecked, requiring no special privilege beyond being able to produce a valid searcher/auctioneer signature over the rest of the bid fields.

### Recommendation
Add an explicit check in `BidPool.validateBid` (or `validateBidSigs`) that enforces `bid.MaxGasPrice` against the intended bound (e.g., current base fee / pool gas price policy) whenever it is set, matching the documented intent of the field, and ensure the v2.1 fallback path either rejects bids carrying `MaxGasPrice` or always uses the v3.0 typehash so the constraint is cryptographically bound to the signature.

### Proof of Concept
1. Call `auction_submitBid` with a `BidInput` containing a valid `targetTxRaw`/`targetTxHash`, valid `searcherSig`/`auctioneerSig`, and an arbitrary/huge `maxGasPrice` (or omit it since it's optional).
2. `ToBid` copies the value into `BidData.MaxGasPrice` [11](#0-10) .
3. `BidPool.AddBid` → `validateBid` runs all six documented checks and accepts the bid without ever inspecting `MaxGasPrice` [3](#0-2) , confirming the constraint is silently dropped and never enforced, regardless of its value.

	maxGasPrice := b.MaxGasPrice
	if maxGasPrice == nil {
		maxGasPrice = new(big.Int)
	}
	encoded := make([]byte, 0, 10*32)
	encoded = append(encoded, b.TargetTxHash.Bytes()...)
	encoded = append(encoded, common.LeftPadBytes(common.Int64ToByteBigEndian(b.BlockNumber), 32)...)
	encoded = append(encoded, common.LeftPadBytes(b.Sender.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(b.To.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(common.Int64ToByteBigEndian(b.Nonce), 32)...)
	encoded = append(encoded, common.LeftPadBytes(b.BidData.Bid.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(maxGasPrice.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(common.Int64ToByteBigEndian(b.CallGasLimit), 32)...)
	encoded = append(encoded, crypto.Keccak256Hash(b.Data).Bytes()...)
	return encoded
}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}

## Bid pool validation rules

A bid pool is responsible for managing the valid bids from the `Auctioneer`. The bid must satisfy the following rules:

1. The `bid.Sender` must not be in the winner list of the same block number if the new bid doesn't have the same target block and hash as the previous bid.

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)
}
