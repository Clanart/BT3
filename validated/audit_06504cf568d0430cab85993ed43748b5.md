## Verdict: Valid vulnerability

### Title
Deep-link `openRepo?url=ext::...` pre-fills the Clone dialog with an unvalidated URL, allowing `git clone` to invoke `ext::` remote helper and execute arbitrary commands - (File: `app/src/ui/clone-repository/clone-repository.tsx`)

### Summary
`parseAppURL` extracts the raw path segment from an `x-github-client://openRepo/<url>` deep link and returns it verbatim as `IOpenRepositoryFromURLAction.url` with no scheme restriction beyond requiring a non-empty path segment. [1](#0-0) 

### Finding Description
The deep-link handler passes this untrusted `url` straight through `Dispatcher.openRepositoryFromUrl` → `openOrCloneRepository`, which opens the `CloneRepository` popup with `initialURL: url` and no validation of the URL's transport/scheme: [2](#0-1) 

`CloneRepository` then pre-fills the "Generic" tab's URL state directly from `props.initialURL` both in the constructor and in `componentDidMount`/`componentDidUpdate`, with no allowlist of git transports (e.g. `https:`, `ssh:`, `git:`): [3](#0-2) [4](#0-3) 

`updateUrl` only parses the string for a repository identifier/name to compute a clone-destination folder name; it performs no scheme/protocol check: [5](#0-4) 

When the user clicks "Clone", `resolveCloneInfo` returns `{ url }` unchanged whenever the URL doesn't match a known GitHub account/repo (which is the case for an `ext::` URL), and `cloneImpl` forwards it unmodified to `dispatcher.clone`: [6](#0-5) [7](#0-6) 

The URL finally reaches `git/clone.ts`, which builds `args.push('--', url, path)` before spawning `git clone`: [8](#0-7) 

The `--` separator only prevents the URL from being parsed as a **command-line flag** (option injection) — it does nothing to stop git from honoring its `ext::<command>` remote-helper transport, which is a legitimate git feature that executes an arbitrary shell command specified in the URL itself. Git treats `ext`/`file` protocols as `protocol.<name>.allow = user` by default, meaning they are permitted for a directly user-initiated `git clone` (as opposed to a transitively-triggered submodule fetch, which is treated as "auto" and blocked by default). Since this whole path is triggered by a single click (deep link → auto-filled URL → "Clone" button), git will execute the `ext::` command with no additional confirmation. I did not find any `GIT_ALLOW_PROTOCOL` environment variable, `protocol.allow` git config override, or scheme allowlist set anywhere in `envForRemoteOperation`, `clone.ts`, `dispatcher.ts`, or `clone-repository.tsx` that would block this.

### Impact Explanation
An attacker-controlled link (e.g. served via a website, chat message, or malicious page) using the scheme `x-github-client://openRepo/ext::sh%20-c%20calc` pre-fills the clone URL. A single click on "Clone" causes GitHub Desktop to spawn `git clone -- 'ext::sh -c calc' <path>`, resulting in arbitrary command execution under the user's privileges — full compromise of confidentiality/integrity/availability, matching this program's "Attacker-controlled text reaching git invocation is parsed... so git runs attacker-chosen commands" impact class.

### Likelihood Explanation
Likelihood is high for the deep-link vector: it requires only that the victim be running GitHub Desktop and click a link that registers the `x-github-client://` protocol handler, then click the pre-populated "Clone" button. There is no interstitial warning, confirmation dialog, or scheme check shown to the user distinguishing a legitimate git remote from an `ext::` command string.

### Recommendation
Add an explicit allowlist of accepted URL schemes/transports (e.g. `https:`, `http:`, `ssh:`, `git:`, and the GitHub SCP-like `git@host:owner/repo` form) at the point where `initialURL` is consumed in `clone-repository.tsx` (`updateUrl`/`componentDidMount`/`componentDidUpdate`) and/or centrally in `parseAppURL`/`openOrCloneRepository`, rejecting any URL matching `ext::`, `fd::`, `file://`, or other non-network transports before it is ever placed into UI state or passed to `dispatcher.clone`. Defense in depth: also set `GIT_ALLOW_PROTOCOL=http:https:ssh:git` in `envForRemoteOperation` for the clone/fetch/push code paths so git itself refuses disallowed transports regardless of UI-level checks.

### Proof of Concept
1. Host/send a link: `x-github-client://openRepo/ext::sh%20-c%20calc`.
2. Victim (with GitHub Desktop registered as the protocol handler) clicks it.
3. `parseAppURL` returns `{ name: 'open-repository-from-url', url: 'ext::sh -c calc', branch: null, pr: null, filepath: null }` (no rejection, since only `pr`/`branch` are validated) — [1](#0-0) .
4. `Dispatcher.openRepositoryFromUrl` → `openOrCloneRepository('ext::sh -c calc')` opens `CloneRepository` with `initialURL: 'ext::sh -c calc'` — [2](#0-1) .
5. `CloneRepository.componentDidMount` calls `updateUrl('ext::sh -c calc')`, setting `urlTabState.url` to the raw string — [9](#0-8) .
6. Victim clicks "Clone"; `clone()` → `resolveCloneInfo()` returns `{ url: 'ext::sh -c calc' }` unchanged → `cloneImpl` → `dispatcher.clone(...)` → `git/clone.ts` spawns `git -c init.defaultBranch=... clone --recursive -- 'ext::sh -c calc' <path>`, executing `sh -c calc`.

A regression test could construct a `CloneRepository` instance with `initialURL='ext::sh -c id'` and assert that `state.urlTabState.url` is rejected/sanitized (currently it is not) rather than passed to `props.dispatcher.clone`.

  private updateUrl = async (url: string) => {
    const parsed = parseRepositoryIdentifier(url)
    const tabState = this.getSelectedTabState()
    const lastParsedIdentifier = tabState.lastParsedIdentifier

    // If there is no path yet, just update the url
    if (tabState.path === null) {
      this.setSelectedTabState({ url }, this.validatePath)
      return
    }

    const safeName = parsed ? sanitizeCloneName(parsed.name) : null

    let newPath: string

    const dirPath = tabState.path
    if (lastParsedIdentifier) {
      if (safeName) {
        newPath = Path.join(Path.dirname(dirPath), safeName)
      } else {
        newPath = Path.dirname(dirPath)
      }
    } else if (safeName) {
      newPath = Path.join(dirPath, safeName)
    } else {
      newPath = dirPath
    }

    this.setSelectedTabState(
      {
        url,
        lastParsedIdentifier: parsed,
        path: newPath,
      },
      this.validatePath
    )
  }

  private clone = async () => {
    this.setState({ loading: true })

    const cloneInfo = await this.resolveCloneInfo()
    const { path } = this.getSelectedTabState()

    if (path == null) {
      const error = new Error(`Directory could not be created at this path.`)
      this.setState({ loading: false })
      this.setSelectedTabState({ error })
      return
    }

    if (!cloneInfo) {
      const error = new Error(
        `We couldn't find that repository. Check that you are logged in, the network is accessible, and the URL or repository alias are spelled correctly.`
      )
      this.setState({ loading: false })
      this.setSelectedTabState({ error })
      return
    }

    const { url, defaultBranch } = cloneInfo

    this.props.dispatcher.closeFoldout(FoldoutType.Repository)
    try {
      this.cloneImpl(url.trim(), path, defaultBranch)
    } catch (e) {
      log.error(`CloneRepository: clone failed to complete to ${path}`, e)
      this.setState({ loading: false })
      this.setSelectedTabState({ error: e })
    }
  }

  private cloneImpl(url: string, path: string, defaultBranch?: string) {
    this.props.dispatcher.clone(url, path, { defaultBranch })
    this.props.onDismissed()

    setDefaultDir(Path.resolve(path, '..'))
  }
