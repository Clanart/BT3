### Title
Gasless swap admission relies on the DEX's instantaneous spot price (`GetAmountIn`), allowing sandwich manipulation of the required `amountIn` check - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The reported Sherlock issue is that `getQuoteAtTick()` derives a price directly from Uniswap V3's `slot0`, a single manipulable spot-price data point, instead of a TWAP. The analogous pattern in this Kaia repo is `GaslessModule.checkBalanceForSwap`, which validates a gasless `SwapTx` by calling the on-chain `GaslessSwapRouter.GetAmountIn(token, minAmountOut)` — a view call that (based on the Uniswap V2 bindings vendored in this repo, e.g. `getAmountOut`/`getAmountIn` computed from `getReserves()`) reflects the pool's current, single-block reserves rather than any time-weighted price. This value gates whether a gasless bundle (approve+swap, fee-delegated by the proposer) is admitted to the pool/block.

### Finding Description
`GaslessModule.checkBalanceForSwap` in [1](#0-0)  is the mempool/tx-pool admission check for a gasless `SwapTx`. When `ShouldCheckSwapAmount()` is enabled (`BalanceCheckLevel >= BalanceCheckLevelSwapAmount`, which is the default level, `BalanceCheckLevelAll`, per [2](#0-1) ), it calls: [3](#0-2) 

`routerContract.GetAmountIn(nil, token, minAmountOut)` queries the deployed `GaslessSwapRouter` contract (bindings in [4](#0-3) ), which internally resolves the DEX pair for the token (`dexAddress`/`getDEXInfo`, [5](#0-4) ) and computes the required input amount from the pair's current reserves — the same pattern as Uniswap V2's `getAmountIn(amountOut, reserveIn, reserveOut)` shown in the vendored bindings [6](#0-5) , which is a `pure` function over `getReserves()` ( [7](#0-6) ) — an instantaneous, single-block price with no TWAP smoothing.

This is architecturally identical to the reported bug class: a single, latest-state price read (`slot0` in the original report, `getReserves()`/spot price here) is used to gate a security-relevant decision (admission of the gasless swap into the block) without any manipulation resistance. An attacker who can influence the pool's reserves in the same block (e.g., via a preceding trade within the same block/bundle, or coordination with the block proposer who assembles the gasless bundle) can shift the instantaneous exchange rate so that `GetAmountIn` returns an artificially low `requiredAmountIn`, letting a swap with insufficient real backing amount pass the `swapArgs.AmountIn.Cmp(requiredAmountIn) < 0` check at [8](#0-7) . Conversely, the deployed `GaslessSwapRouter.swapForGas` contract call that actually executes the swap (paid mutator, executed at inclusion time, not in this Go repo) re-derives the amount at execution, so the practical exploitation window is any transient reserve shift between admission-time check and inclusion-time settlement within the same block/bundle — which the proposer, as the single entity assembling gasless bundles alongside other transactions in the block, is in a unique position to engineer.

### Impact Explanation
The `swapForGas` flow determines how much of a user's token is swapped to KAIA to reimburse the fee-delegating proposer for gas advanced (`amountRepay`), and any surplus goes to the user (`SwappedForGas`/`FinalUserAmount`, referenced in tests at [9](#0-8) ). If the spot-price check can be manipulated to under-estimate `requiredAmountIn`, a gasless swap could be admitted and processed with a token amount insufficient to cover the actual proposer's gas repayment obligation at settlement, or with a user swap that clears validation but is unfavorable to the user post-manipulation — resulting in the proposer being under-compensated for advanced gas (fee-delegation abuse) or the user's swap value being redirected/eroded through proposer-controlled sequencing. This falls into "fee-delegation abuse" / "gasless settlement" value-movement categories from the accepted impact list.

### Likelihood Explanation
Medium likelihood. The check is gated behind `BalanceCheckLevelSwapAmount`, but this is enabled by default (`DefaultGaslessConfig.BalanceCheckLevel = BalanceCheckLevelAll`, which is `>= BalanceCheckLevelSwapAmount`), so it is on-path in the default configuration. Exploiting it requires influencing the DEX pool's reserves at the moment the check executes and again favorably at settlement, which is most reliably achievable by the block proposer itself (who controls tx/bundle ordering via `FilterTxs`/`ExtractTxBundles`-style flows) or by a searcher colluding with the proposer — both are within the "unprivileged transaction sender" / "proposer" reach permitted by the rules. It is not a trivial single-transaction free exploit for an arbitrary outsider because it depends on pool liquidity depth and same-block ordering control, which lowers likelihood from High to Medium.

### Recommendation
Do not rely solely on the DEX's instantaneous `getReserves()`/spot-derived `GetAmountIn` for the gasless swap admission check in `checkBalanceForSwap`. Either (a) add a TWAP-based or multi-block sanity bound around the returned `requiredAmountIn` before accepting the swap, (b) re-validate the amount check atomically at the point of inclusion within the same execution context used for settlement (so admission-time and settlement-time price reads cannot diverge), or (c) bound the allowed slippage between the pre-admission quote and the final execution quote so that reserve manipulation within a block cannot materially reduce the effective `amountIn` requirement.

### Proof of Concept
Not independently reproducible from the indexed Go repo alone: the actual `GaslessSwapRouter.getAmountIn`/`swapForGas` Solidity source (which would confirm whether it reads live reserves without TWAP protection) is not present in this repository's index — only its ABI bindings are. This should be verified by examining the deployed `GaslessSwapRouter` contract source (or via a Devin session with full repo access) to confirm `getAmountIn` computes off `getReserves()` at call time with no time-weighting, which would fully confirm the manipulation vector described above.

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}
