### Title
`balanceOf` on the CW721→ERC721 pointer performs an unbounded owner-token-paging loop that can be forced to run out of gas - (File: contracts/src/CW721ERC721Pointer.sol)

### Summary
`CW721ERC721Pointer.balanceOf()` determines an owner's NFT count by repeatedly querying the underlying CW721 contract in pages of 1000 tokens, looping until an empty page is returned. Just like `CamelotRewardsAdapter.claimRewards`, which loops `harvestPosition` once per NFT position owned by the caller, this function's number of loop iterations (and therefore its gas cost) is proportional to the number of tokens an address owns on the wrapped CW721 contract, with no upper bound or pagination limit exposed to the caller.

### Finding Description
`balanceOf` builds a `{"tokens":{"limit":1000,"owner":"..."}}` query, sends it through `WasmdPrecompile.query`, and loops via `while (keccak256(response) != terminator)`, appending `numTokens += tokensLength` and re-querying with `start_after` set to the last returned token, until the CW721 contract returns an empty `tokens` list: [1](#0-0) 

Each iteration costs a cross-VM wasmd precompile query plus JSON parsing (`JsonPrecompile.extractAsBytesList`), so the total gas consumed by a single `balanceOf` call grows linearly, unbounded, with the number of NFTs the queried address owns in the wrapped CW721 collection. There is no cap on how many tokens an owner can accumulate (an attacker can mint or transfer to itself an arbitrarily large number of NFTs on the underlying CW721 contract if it is permissionless, or simply be a heavy legitimate user of a popular collection), so this loop can be driven past the gas limit of any transaction or query context that invokes it.

This mirrors the `CamelotRewardsAdapter.claimRewards` root cause exactly: a length-dependent loop over items owned by an address (there: NFT positions to harvest; here: NFT token pages to count) with no bound, size limit, or pagination parameter under caller control.

### Impact Explanation
Because `balanceOf` is a standard `ERC721` interface method, any EVM contract that calls it (marketplaces, other pointer/wrapper contracts, batch operations, `ERC721Enumerable`-style integrations, or future logic inside the Sei pointer/bridge stack that relies on `IERC721.balanceOf`) can be permanently reverted with an out-of-gas failure once the queried owner's token count on the underlying CW721 collection grows large enough. This can permanently deny functionality that depends on `balanceOf` succeeding for that owner (e.g., balance checks gating other operations), which is a Medium-severity availability/DoS issue analogous to the original report's "claims may permanently fail" scenario. Because the pointer is a core CW↔EVM interoperability primitive listed in the pointer contract system, its balance computation being unbounded is a design flaw that scales with adoption/usage of a collection rather than being a corner case.

### Likelihood Explanation
Likelihood is Medium: it requires an owner to accumulate a sufficiently large number of NFTs in the underlying CW721 collection (either organically through popular collections or by a user/attacker minting/self-transferring many tokens into one address, which is feasible without any privileged access since minting/CW721 usage is permissionless from an unprivileged CosmWasm user's perspective). No malicious validator, node, or privileged actor is required — only ordinary use of the pointer contract by any public caller.

### Recommendation
Bound the `balanceOf` loop, e.g., by capping the number of pages traversed and reverting/returning a sentinel when the cap is exceeded, or by requiring the underlying CW721 contract to expose (and the pointer to use) an O(1) balance query instead of manual token enumeration. Alternatively, expose pagination parameters to callers (similar to `tokenOfOwnerByIndex`) so gas cost is caller-controlled rather than owner-state-controlled, and document/enforce a maximum supported balance size.

### Proof of Concept
1. Deploy a CW721 contract and register a `CW721ERC721Pointer` for it (as in `contracts/test/CW721ERC721PointerTest.t.sol`).
2. Mint (or transfer) a very large number of tokens (tens of thousands) to a single owner address on the underlying CW721 contract — this is permissionless for any CosmWasm user interacting with a public/permissionless CW721 contract.
3. Call `pointer.balanceOf(owner)` from an EVM contract or via `eth_call`; because the loop in lines 51-79 of `CW721ERC721Pointer.sol` issues one wasmd precompile query + JSON extraction per 1000 tokens with no bound, the call's gas consumption scales linearly and will eventually exceed any block/tx gas limit or query gas cap, causing `balanceOf` (and anything depending on it) to revert deterministically for that owner going forward.

```text
    function balanceOf(address owner_) public view override returns (uint256) {
        if (owner_ == address(0)) {
            revert ERC721InvalidOwner(address(0));
        }
        uint256 numTokens = 0;
        string memory startAfter;
        string memory qb = string.concat(
            string.concat("\"limit\":1000,\"owner\":\"", AddrPrecompile.getSeiAddr(owner_)),
            "\""
        );
        bytes32 terminator = keccak256("{\"tokens\":[]}");

        bytes[] memory tokens;
        uint256 tokensLength;
        string memory req = string.concat(string.concat("{\"tokens\":{", qb), "}}");
        bytes memory response = WasmdPrecompile.query(Cw721Address, bytes(req));
        while (keccak256(response) != terminator) {
            tokens = JsonPrecompile.extractAsBytesList(response, "tokens");
            tokensLength = tokens.length;
            numTokens += tokensLength;
            startAfter = string.concat(",\"start_after\":", string(tokens[tokensLength-1]));
            req = string.concat(
                string.concat("{\"tokens\":{", string.concat(qb, startAfter)),
                "}}"
            );
            response = WasmdPrecompile.query(Cw721Address, bytes(req));
        }
        return numTokens;
    }
```
