### Title
Deserialized empty `SchnorrAggregate` verifies successfully - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::read` accepts an aggregate containing zero nonce commitments, and `SchnorrAggregate::verify` accepts it when the verifier's statement list is also empty. The normal aggregation API refuses to construct an empty aggregate, but this invariant is not enforced during deserialization or verification.

### Finding Description
`SchnorrAggregate::read` reads an attacker-controlled count, iterates zero times when it is `0`, and then reads the scalar `s`. [1](#0-0)  `verify` only checks that `Rs.len() == keys_and_challenges.len()`, so an empty serialized aggregate matches an empty statement list. [2](#0-1)  It then queues only `(-s) * G`; with `s = 0`, the multiexponentiation result is the identity and verification returns true. [3](#0-2) 

This bypasses the invariant enforced by `SchnorrAggregator::complete`, which returns `None` when no signatures were aggregated. [4](#0-3) 

### Impact Explanation
An unprivileged party can supply bytes that deserialize to a syntactically valid `SchnorrAggregate` and pass verification without any underlying signer, public key, nonce commitment, or Schnorr signature. If an integrator treats `verify(...) == true` as proof that at least one signature was verified, this is a forged aggregate signature caused by missing empty-input validation.

### Likelihood Explanation
The trigger requires only public bytes: a four-byte little-endian zero length followed by the canonical encoding of scalar zero, passed to `SchnorrAggregate::read`, followed by `verify(dst, &[])`. The issue depends on an integration permitting an empty verification batch; the primitive itself does not reject that state.

### Recommendation
Reject empty aggregates consistently. Either make `SchnorrAggregate::read` fail when the encoded `Rs` length is zero, or make `verify` return false when `self.Rs.is_empty()` / `keys_and_challenges.is_empty()`. Enforcing the check in `verify` is the safer defense-in-depth option because it also protects manually constructed values.

### Proof of Concept
```rust
use ciphersuite::Ciphersuite;
use schnorr::SchnorrAggregate;

fn empty_aggregate_forge<C: Ciphersuite>() {
  let mut encoded = Vec::from(0u32.to_le_bytes());
  encoded.extend(C::F::ZERO.to_repr().as_ref());

  let aggregate =
    SchnorrAggregate::<C>::read::<&[u8]>(&mut encoded.as_slice()).unwrap();

  // The constructor API rejects empty aggregates, but this deserialized one verifies.
  assert!(aggregate.verify(b"application-specific-dst", &[]));
}
```
