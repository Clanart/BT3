### Title
Empty aggregate signatures verify successfully - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::read` accepts an aggregate containing zero nonces followed by a zero scalar, and `verify` then evaluates only `-sG`, which is the identity for `s = 0`. [1](#0-0) [2](#0-1) 

### Finding Description
The verifier only checks that `self.Rs.len() == keys_and_challenges.len()` before building its weighted verification equation. [3](#0-2)  For an empty aggregate and an empty signer/challenge list, the loop adds no statement pairs and the only remaining statement is `(-self.s) * G`; with serialized `s = 0`, this evaluates to identity and returns true. [4](#0-3)  This conflicts with the aggregation API's own invariant: `SchnorrAggregator::complete` deliberately refuses to emit an aggregate when no signatures were supplied. [5](#0-4) 

### Impact Explanation
An attacker can forge an aggregate signature accepted for zero signers without possessing any private key. [1](#0-0) [4](#0-3)  Any caller that treats a successful `SchnorrAggregate::verify` as evidence that its supplied signer set authorized a message receives incorrect verifier behavior when that supplied set is empty.

### Likelihood Explanation
The byte sequence is deterministic and does not require a hash collision, private-key knowledge, signer cooperation, or malformed encodings. [1](#0-0)  Exploitation requires a caller to accept an empty `keys_and_challenges` list, but the public API performs no such validation and therefore cannot safely serve as the sole authentication check for that boundary. [3](#0-2) 

### Recommendation
Reject empty aggregates in `SchnorrAggregate::verify`, and preferably reject zero-length `Rs` during `SchnorrAggregate::read`. [1](#0-0) [3](#0-2)  Add a regression test asserting that a serialized empty aggregate with `s = 0` fails verification.

### Proof of Concept
For a 32-byte scalar ciphersuite such as Ristretto, serialize an empty `Rs` vector followed by the canonical zero scalar:

```rust
let mut encoded = vec![0; 4 + 32];
let aggregate =
  SchnorrAggregate::<Ristretto>::read(&mut encoded.as_slice()).unwrap();

assert!(aggregate.verify(b"example", &[]));
```

The four zero bytes decode as `Rs.len() == 0`, the following 32 zero bytes decode as `s == 0`, and verification succeeds because the resulting multiexponentiation is empty except for `-0 * G`. [1](#0-0) [4](#0-3)
