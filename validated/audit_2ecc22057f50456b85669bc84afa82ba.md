### Title
Excess ETH sent to `MultiSender.batchTransferEqualAmount()` / `batchTransfer()` is not refunded and becomes permanently stuck - (File: contracts/src/MultiSender.sol)

### Summary
`MultiSender.sol`, a payable utility contract shipped in the sei-chain EVM contracts directory, accepts `msg.value` in both `batchTransferEqualAmount()` and `batchTransfer()` but only checks that `msg.value >= totalAmount`. It never computes or refunds the difference between `msg.value` and the actual amount distributed to recipients, so any excess ETH sent by the caller is permanently trapped in the contract with no withdrawal mechanism.

### Finding Description
Both payable functions in `MultiSender.sol` follow the same pattern: they use `require(msg.value >= totalAmount, ...)` as a lower-bound check, then loop over recipients sending exactly `amount`/`amounts[i]` each via `.send()`. Nowhere in either function is `msg.value - totalAmount` computed or returned to `msg.sender`. [1](#0-0) [2](#0-1) 

Since the contract has no `receive()`/`fallback()` withdrawal path, no owner-sweep function, and no refund logic, any wei sent above `totalAmount` is irrecoverably locked in the contract balance — this is functionally identical to the Footium `mintPlayers()` bug: a payable function that accepts `msg.value >= requiredAmount` without returning the delta.

### Impact Explanation
Any unprivileged EVM caller (an ordinary transaction sender or a UI/wallet integration built on top of `MultiSender`) who overestimates gas/value and sends more ETH than `totalAmount` permanently loses the excess — the funds sit in the contract with no owner or user recovery path. This is a direct, permanent loss of user funds (fund loss / permanent freezing), matching the audit's "Medium" acceptance criteria for concrete fund loss.

### Likelihood Explanation
Likelihood is non-trivial: `batchTransferEqualAmount`/`batchTransfer` are the kind of "send exact value" APIs where off-by-one rounding, front-end miscalculation, or intentionally overpaying (e.g., to cover potential gas variance) commonly occurs. Any caller who sends `msg.value` strictly greater than the computed `totalAmount` triggers the loss on every single call — no special conditions, no race, no privileged setup required.

### Recommendation
Refund the excess ETH to `msg.sender` after distributing to recipients in both functions, e.g.:
```solidity
uint256 totalAmount = amount * recipients.length;
require(msg.value >= totalAmount, "Insufficient amount sent");
... // distribute
uint256 excess = msg.value - totalAmount;
if (excess > 0) {
    (bool refunded, ) = msg.sender.call{value: excess}("");
    require(refunded, "Refund failed");
}
```
Apply the equivalent fix to `batchTransfer()` using its own `totalAmount`.

### Proof of Concept
1. Caller invokes `batchTransferEqualAmount([r1, r2], 1 ether)` with `msg.value = 3 ether` (`totalAmount = 2 ether`).
2. The `require(msg.value >= totalAmount)` check passes (3 ether ≥ 2 ether).
3. The loop sends `1 ether` to each of `r1` and `r2` (total `2 ether` spent).
4. The remaining `1 ether` stays in the `MultiSender` contract's balance; no code path returns it to the caller, and there is no admin/withdraw function to reclaim it — the `1 ether` is permanently lost to the caller.

  function batchTransferEqualAmount(
    address[] calldata recipients,
    uint256 amount
  ) external payable {
    uint256 totalAmount = amount * recipients.length;
    require(msg.value >= totalAmount, "Insufficient amount sent");

    for (uint256 i = 0; i < recipients.length; i++) {
      bool success = payable(recipients[i]).send(amount);
      require(success, "Failed to send Ether");
      emit SendSuccessful(msg.sender, recipients[i], amount);
    }
  }

  function batchTransfer(
    address[] calldata recipients,
    uint256[] calldata amounts
  ) external payable {
    require(
      recipients.length == amounts.length,
      "Recipients and amounts do not match"
    );
    uint256 totalAmount = 0;
    for (uint256 i = 0; i < amounts.length; i++) {
      totalAmount += amounts[i];
    }

    require(msg.value >= totalAmount, "Insufficient amount sent");

    for (uint256 i = 0; i < recipients.length; i++) {
      bool success = payable(recipients[i]).send(amounts[i]);
      require(success, "Failed to send Ether");
      emit SendSuccessful(msg.sender, recipients[i], amounts[i]);
    }
  }
}
