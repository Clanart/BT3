### Title
DataLayer `add_missing_files` RPC accepts an unrestricted `foldername`, allowing local RPC callers to write DataLayer tree files outside the intended `server_files_location` - (File: chia/data_layer/data_layer_rpc_api.py)

### Summary
The DataLayer RPC endpoint `add_missing_files` takes a caller-supplied `foldername` string and turns it directly into a `Path` with no validation that it stays under the DataLayer's configured `server_files_location`. That path is then used as the write target for full-tree and delta `.dat` files containing the store's serialized Merkle/key-value data. This mirrors the UberFire advisory's root cause: a service accepts a client-supplied filesystem path/filename and uses it to perform file I/O without restricting it to an intended base directory, enabling writes to attacker-chosen locations.

### Finding Description
`DataLayerRpcApi.add_missing_files()` builds the write target straight from the request body: [1](#0-0) 

`foldername: Path | None = None; if "foldername" in request: foldername = Path(request["foldername"])` is passed unchanged into `DataLayer.add_missing_files()`, which uses it (or the default `server_files_location`) as the base folder for every generation's files: [2](#0-1) 

That folder is handed to `write_files_for_root()`, which opens files under it directly (`open(filename_full_tree, mode)` / `open(filename_diff_tree, mode)`), where `mode` is `"wb"` (truncate/overwrite) when `overwrite=True` is passed in the same RPC request: [3](#0-2) 

Unlike `DataLayerServer.file_handler`/`folder_handler`, which validate the filename strictly against `is_filename_valid()` (hex `store_id`/`node_hash` round-trip, no path separators survive), the `add_missing_files` RPC path performs no such containment on the *directory* component at all — `foldername` can be any absolute or relative path (including `..` traversal) reachable by the daemon process. The file content itself is the serialized DataLayer store's key/value data, which the caller substantially controls if they own the target `store_id` (via `batch_insert`/`insert` before calling this RPC), so both the write location and much of the written content are attacker-influenced.

### Impact Explanation
An authenticated local RPC caller (any process holding a valid DataLayer RPC client cert/key, not necessarily the CLI operator) can direct the DataLayer service to write (and with `overwrite=True`, truncate/overwrite) files at an arbitrary filesystem path reachable by the `chia_data_layer` process, using content it substantially controls through its own store's key/value data. This can corrupt or plant files outside the DataLayer's intended `server_files_location` directory, a clear violation of the same "improperly restricted path" class as the CVE (arbitrary file write via unrestricted path parameter), and can lead to local file corruption/DoS or, depending on target path and OS/file permissions, more serious tampering.

### Likelihood Explanation
Requires access to the DataLayer RPC (local RPC caller, an in-scope actor for this analysis) and ownership of at least one DataLayer store to control written content, both of which are readily obtainable by any local wallet/DataLayer user. No additional race conditions or privileged access are required beyond the already-permitted RPC actor category.

### Recommendation
Validate and normalize `foldername` against an allow-listed base directory (e.g., require it to resolve under `server_files_location` or a configured safe root) before use, rejecting any path that escapes that root (reject `..` components, symlink escapes, and absolute paths outside the allowed root), consistent with how `DataLayerServer` already validates filenames via `is_filename_valid()`.

### Proof of Concept
1. As a local, authenticated DataLayer RPC client, create/own a DataLayer store and insert attacker-chosen key/value data via the normal `batch_update`/`insert` RPCs.
2. Call the `add_missing_files` RPC with `{"ids": ["<owned_store_id>"], "overwrite": true, "foldername": "/path/outside/server_files_location"}`.
3. Observe that `DataLayer.add_missing_files()` writes/overwrites `.dat` files (embedding the attacker's key/value bytes) directly under the attacker-supplied `foldername`, with no containment check verifying it is within `server_files_location`.

    async def add_missing_files(self, request: dict[str, Any]) -> EndpointResult:
        """
        complete the data server files.
        """
        if "ids" in request:
            store_ids = request["ids"]
            ids_bytes = [bytes32.from_hexstr(id) for id in store_ids]
        else:
            subscriptions: list[Subscription] = await self.service.get_subscriptions()
            ids_bytes = [subscription.store_id for subscription in subscriptions]
        overwrite = request.get("overwrite", False)
        foldername: Path | None = None
        if "foldername" in request:
            foldername = Path(request["foldername"])
        for store_id in ids_bytes:
            await self.service.add_missing_files(store_id, overwrite, foldername)
        return {}

    async def add_missing_files(self, store_id: bytes32, overwrite: bool, foldername: Path | None) -> None:
        root = await self.data_store.get_tree_root(store_id=store_id)
        latest_generation = root.generation
        full_tree_first_publish_generation = max(0, latest_generation - self.maximum_full_file_count + 1)
        singleton_record = (
            await self.wallet_rpc.dl_latest_singleton(DLLatestSingleton(launcher_id=store_id, only_confirmed=True))
        ).singleton
        if singleton_record is None:
            self.log.error(f"No singleton record found for: {store_id}")
            return
        max_generation = min(singleton_record.generation, root.generation)
        server_files_location = foldername if foldername is not None else self.server_files_location
        files = []
        for generation in range(1, max_generation + 1):
            root = await self.data_store.get_tree_root(store_id=store_id, generation=generation)
            res = await write_files_for_root(
                self.data_store,
                store_id,
                root,
                server_files_location,
                full_tree_first_publish_generation,
                overwrite,
                self.group_files_by_store,
            )
            files.append(res.diff_tree.name)
            if res.full_tree is not None:
                files.append(res.full_tree.name)

async def write_files_for_root(
    data_store: DataStore,
    store_id: bytes32,
    root: Root,
    foldername: Path,
    full_tree_first_publish_generation: int,
    overwrite: bool = False,
    group_by_store: bool = False,
) -> WriteFilesResult:
    if root.node_hash is not None:
        node_hash = root.node_hash
    else:
        node_hash = bytes32.zeros  # todo change

    filename_full_tree = get_full_tree_filename_path(foldername, store_id, node_hash, root.generation, group_by_store)
    filename_diff_tree = get_delta_filename_path(foldername, store_id, node_hash, root.generation, group_by_store)
    filename_full_tree.parent.mkdir(parents=True, exist_ok=True)

    written = False
    mode: Literal["wb", "xb"] = "wb" if overwrite else "xb"

    written_full_file = False
    if root.generation >= full_tree_first_publish_generation:
        try:
            with open(filename_full_tree, mode) as writer:
                await data_store.write_tree_to_file(root, node_hash, store_id, False, writer)
            written = True
            written_full_file = True
        except FileExistsError:
            pass

    try:
        with open(filename_diff_tree, mode) as writer:
            await data_store.write_tree_to_file(root, node_hash, store_id, True, writer)
        written = True
    except FileExistsError:
        pass

    return WriteFilesResult(written, filename_full_tree if written_full_file else None, filename_diff_tree)
