### Title
Automatic remote-URL rewrite trusts unvalidated hostname from GitHub API repository object, allowing silent push/fetch redirection - ([File: app/src/lib/stores/updates/update-remote-url.ts])

### Summary
`updateRemoteUrl` automatically overwrites a tracked repository's `origin` remote URL whenever the cached GitHub API repository object's `clone_url` changes, but it only verifies that the *protocol* (http vs https) is unchanged — it never verifies that the *hostname* of the new `clone_url` still matches the trusted GitHub endpoint (github.com or the specific GHES host) the repository is associated with. [1](#0-0) 

### Finding Description
The broken invariant, analogous to the StrongBlock report's core lesson ("a component silently trusts a value that came from an attacker-reachable input and uses it to redistribute privileged state without re-verifying the trust anchor"), is here: Desktop treats `apiRepo.clone_url` — a value returned by a network response tied to a `GitHubRepository`/endpoint — as an authoritative replacement for the user's configured git remote, as long as:
1. the current remote hasn't been manually customized away from what the API previously reported (`remoteUrlUnchanged`), and
2. the URL "protocol" (`http:`/`https:`) of old vs. new matches (`protocolsMatch`). [2](#0-1) 

Critically, `protocolsMatch` is computed with `URL.parse(...).protocol`, which only compares the scheme string, not `host`/`hostname`: [3](#0-2) 

There is no call anywhere in this function to `urlMatchesRemote`, `repositoryMatchesRemote`, or any check that the new `clone_url`'s hostname equals the hostname of `gitHubRepository.endpoint`/`htmlURL`. Note that `urlMatchesRemote` (which *does* do host/owner/name comparisons) exists in the codebase and is used elsewhere for exactly this kind of validation, but it is used here only to detect whether the *old* remote is "unchanged" from the *old* API url — never to validate that the incoming *new* url is still on the same trusted host. [4](#0-3) 

Because `apiRepo` (an `IAPIFullRepository`/`IAPIRepository`) is populated from a live GitHub API response, any actor who can influence that JSON — a malicious/compromised GitHub Enterprise Server the user is signed into, a network path that can tamper with the API response, or a repository object returned through a path the app trusts without additional pinning — can set `clone_url` to `https://attacker.example.com/anything/anything`. Since the scheme is still `https`, `protocolsMatch` is `true`, and if the user hasn't hand-edited their remote, `remoteUrlUnchanged` is also `true`, so Desktop calls `gitStore.setRemoteURL(...)` and silently rewrites `origin` to the attacker's host. [5](#0-4) 

From that point forward, all `fetch`/`push`/`pull` operations for the repository target the attacker-controlled host transparently, with no dialog, confirmation, or warning shown to the user.

### Impact Explanation
This corrupts the value that determines "where the user's commits/pushes go" — the git `origin` remote URL — entirely silently, matching the report's "silent corruption of what the user commits or pushes" impact class. Depending on how Git resolves credentials for the rewritten host, this can also cause the user's push (and any embedded auth material Git sends during the HTTPS handshake, e.g., Basic-Auth-style credential probing) to be transmitted to the attacker's server, and it can be used to man-in-the-middle future clones/fetches of "the same" tracked repository, enabling injection of malicious history/commits back into what the user believes is their GitHub-hosted repository.

### Likelihood Explanation
Exploitation requires only that the app is being pointed at a GitHub Enterprise (or otherwise non-github.com) endpoint that can serve a manipulated repository API object, or a network position able to tamper with that specific response — no local access, no admin rights, and no separate credential leak are required. The unprivileged conditions match the task's valid-impact bucket ("attacker controls... a GitHub API object..., or a git remote/proxy response").  I was not able to fully verify, within the tool budget, exactly how Desktop's credential/trampoline layer maps hostnames to stored tokens when the remote URL diverges from the account's endpoint host, so the credential-exfiltration portion of the impact should be treated as a secondary, unconfirmed consequence; the primary, confirmed consequence is the silent remote hijack itself.

### Recommendation
In `updateRemoteUrl`, before calling `gitStore.setRemoteURL`, additionally require that the new `clone_url`'s hostname matches the hostname of `gitHubRepository.endpoint` (or `getHTMLURL(gitHubRepository.endpoint)`), using the existing `urlMatchesRemote`/host-comparison helpers rather than only comparing URL protocol strings. If the hostname differs, either refuse the automatic rewrite or prompt the user for explicit confirmation before changing `origin`.

### Proof of Concept
Conceptual PoC (network/API-level, no local access needed):
1. User has a tracked repository whose `GitHubRepository` is associated with a GHES endpoint the attacker can influence (compromised/malicious GHES instance, or a tamperable proxy/MITM position on that endpoint's API traffic), matching `IAPIFullRepository.clone_url = https://ghes.example.com/org/repo`.
2. Desktop's next repository-info refresh receives a manipulated API response where `clone_url` is changed to `https://attacker.example.com/org/repo` (scheme still `https`).
3. `updateRemoteUrl` runs: `protocolsMatch` is `true` (https == https), `remoteUrlUnchanged` is `true` (user never touched the remote), `urlsMatch` is `false` (different host) → `gitStore.setRemoteURL('origin', 'https://attacker.example.com/org/repo')` executes.
4. The user's next `git push`/`git fetch` in Desktop silently targets `attacker.example.com` with no UI indication that `origin` changed. [6](#0-5)

import { IAPIRepository } from '../../api'
import { GitStore } from '../git-store'
import { urlMatchesRemote } from '../../repository-matching'
import * as URL from 'url'
import { GitHubRepository } from '../../../models/github-repository'

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}
