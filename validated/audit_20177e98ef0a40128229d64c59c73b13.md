## Finding Confirmed

Static trace confirms `findDefaultRemote` performs **no validation or sanitization whatsoever**, and there is no sanitization function anywhere in the call chain from `getRemotes()` → `loadRemotes()` → `push()`/`fetch()`/`pull()`.

### Title
Argument Injection via Malicious Git Remote Name Reaching `git push`/`fetch`/`pull` Argv — ([File: `app/src/lib/stores/helpers/find-default-remote.ts`])

### Summary
`IRemote.name` is sourced verbatim from parsing `git remote -v` output and is never validated against option-like prefixes (e.g. `-`, `--`) before being placed as a bare positional argument in the `git push`/`fetch`/`pull` argv, with no `--` end-of-options separator inserted anywhere in the call chain.

### Finding Description
`getRemotes()` builds `IRemote` objects purely by regex-parsing the raw text output of `git remote -v`, with no filtering of the captured `name`/`url` groups: [1](#0-0) 

`findDefaultRemote` simply picks the remote named `'origin'` or falls back to the first entry — it performs no escaping, whitelisting, or rejection of malformed names: [2](#0-1) 

`GitStore.loadRemotes()` wires these two functions together directly, with nothing in between: [3](#0-2) 

The resulting `IRemote` then flows unchanged into the git command builders:
- `push()` places `remote.name` as a bare positional argv element with no `--` separator: [4](#0-3) 
- `fetch()`'s `getFetchArgs()` places `remote` as the last bare argv element: [5](#0-4) 
- `pull()` places `remote.name` as the last bare argv element: [6](#0-5) 

A `.git/config` `[remote "<name>"]` subsection header can contain almost arbitrary characters (spaces, `=`, `-`, `/`), so a repository shipped with a crafted `.git/config` (e.g. distributed as an archive/bundle a user extracts and then adds via "Add Local Repository", triggering `_addRepositories` → `gitStore.loadRemotes()`) can define a remote whose name is a git option string such as `--upload-pack=/tmp/evil.sh`: [7](#0-6) 

Because git's own `git remote add` uses getopt-style parsing (so Desktop-created remotes via `addRemote()` can't easily produce such names), but nothing stops a name from being introduced directly via the config file on disk. Once loaded, `findDefaultRemote` will select this malicious remote as `defaultRemote` (if no legitimate `origin` exists or it's removed/renamed), after which it is used transparently in fetch/push/pull operations, including background auto-fetch and the "Fetch/Push/Pull" UI actions.

Notably, the codebase already contains sanitization helpers for other git-derived strings that explicitly guard against leading `-`/`+` characters (e.g. `sanitizedRefName`, `sanitizeCloneName`), demonstrating the team is aware of this exact injection class — but no equivalent guard exists for remote names: [8](#0-7) [9](#0-8) 

### Impact Explanation
If a remote name resolves to an option like `--upload-pack=<path>` or `--receive-pack=<path>` and the corresponding remote URL is a local path, `git fetch`/`git push` will invoke the attacker-specified program locally as the "server-side" helper process for the local transport, resulting in arbitrary code execution when the victim opens/adds the malicious repository and performs (or auto-triggers) a fetch/push/pull.

### Likelihood Explanation
Requires the victim to add/open a repository whose `.git/config` was crafted by the attacker (e.g., distributed as a zip/tarball or bundle including `.git`), which falls within the defined scope of "attacker controls a cloned/fetched repository / repository content." No further unnatural user interaction beyond adding the repository and a subsequent fetch (which can occur automatically via background refresh) is required.

### Recommendation
Validate/reject `IRemote.name` values that start with `-` (or otherwise don't match a safe remote-name pattern) in `getRemotes()`/`findDefaultRemote`, and additionally insert a `--` end-of-options separator before the remote name argument in `push.ts`, `fetch.ts`, and `pull.ts` argv construction so that even a malformed name cannot be interpreted as an option.

### Proof of Concept
1. Create a Git repository containing a `.git/config` with:
```
[remote "--upload-pack=/tmp/evil.sh"]
    url = /some/local/path
    fetch = +refs/heads/*:refs/remotes/x/*
```
2. Package this as an archive/bundle and have the victim extract it and add it via "Add Local Repository" in GitHub Desktop (or open a folder containing this `.git`).
3. `gitStore.loadRemotes()` runs, `findDefaultRemote` selects this remote as `defaultRemote` (e.g. because no `origin` remote exists).
4. On the next fetch/push/pull (manual or automatic background fetch), `git(['fetch', '--prune', '--recurse-submodules=on-demand', '--upload-pack=/tmp/evil.sh'], ...)` is executed, causing `/tmp/evil.sh` to run as the transport helper.

export async function getRemotes(
  repository: Repository
): Promise<ReadonlyArray<IRemote>> {
  const result = await git(['remote', '-v'], repository.path, 'getRemotes', {
    expectedErrors: new Set([GitError.NotAGitRepository]),
  })

  if (result.gitError === GitError.NotAGitRepository) {
    return []
  }

  return [...result.stdout.matchAll(/^(.+)\t(.+)\s\(fetch\)/gm)].map(
    ([, name, url]) => ({ name, url })
  )
}

export function sanitizeCloneName(name: string): string | null {
  const components = name.split(/[/\\:]/)

  let lastComponent = ''
  for (let i = components.length - 1; i >= 0; i--) {
    if (components[i].length > 0) {
      lastComponent = components[i]
      break
    }
  }

  if (lastComponent.length === 0) {
    return null
  }

  if (lastComponent.endsWith('.git')) {
    lastComponent = lastComponent.slice(0, -4)
  }

  if (
    lastComponent === '..' ||
    lastComponent === '.' ||
    lastComponent.length === 0
  ) {
    return null
  }

  return lastComponent
}
