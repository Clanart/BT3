### Title
`SignableTransaction::new` computes the fee and weight on a transaction that omits the OP_RETURN data output, underpaying the requested fee rate — (`File: networks/bitcoin/src/wallet/send.rs`)

### Summary
`SignableTransaction::new` pushes the `data` OP_RETURN output into `tx_outs` (lines 194–202), but then computes the transaction's weight/vbytes — and therefore `needed_fee` — via `calculate_weight_vbytes`, which only models inputs, `payments`, and (optionally) change. The OP_RETURN output (up to ~91 weight-bound bytes for the 80-byte data limit) is never accounted for. This mirrors the Dinari bug class: the accounting step subtracts/bills against the wrong quantity (a transaction smaller than the one actually produced), so the actual transaction's effective fee rate is lower than the `fee_per_vbyte` the caller paid for, and can even fall below Bitcoin's minimum relay fee while still passing the `TooLowFee` check.

### Finding Description [1](#0-0) 

`calculate_weight_vbytes` builds a template `Transaction` whose `output` is populated solely from `payments` plus an optional `change` output [2](#0-1) . The OP_RETURN output appended to `tx_outs` at line 195 is absent from that template, so:

1. `vbytes` (line 204) is too small.
2. `needed_fee = fee_per_vbyte * vbytes` (line 206) is too small.
3. The `TooLowFee` minimum-relay check (line 211) is validated against the wrong (smaller) size.
4. The change computation `input_sat - (payment_sat + fee_with_change)` (line 228) uses the understated fee, meaning `fee()` — `sum(inputs) - sum(outputs)` [3](#0-2)  — still equals the understated `needed_fee`, while the actual transaction is larger. The effective sat/vbyte rate drops, and if `fee_per_vbyte` was chosen at/near `DEFAULT_MIN_RELAY_TX_FEE`, the real transaction falls below the minimum relay feerate.
5. The `MAX_STANDARD_TX_WEIGHT` check (line 241) also uses the understated `weight`, so a transaction that exceeds the standard weight limit can be constructed.

The resulting `Transaction` is exactly what `TransactionSignMachine::sign` commits to via `taproot_key_spend_signature_hash` with `Prevouts::All` [4](#0-3) , so the threshold signature binds to a transaction whose fee was miscalculated — the signed artifact is valid but does not achieve the fee rate it was constructed to pay.

### Impact Explanation
For any call to `SignableTransaction::new` with `data.is_some()` and a fee rate at or near minimum relay, the produced transaction will have an effective feerate below `DEFAULT_MIN_RELAY_TX_FEE` and be rejected/dropped by standard Bitcoin nodes, or simply confirm far slower than specified. Funds are not directly stolen, but UTXOs controlled by the threshold key are committed to an unrelayable/stuck transaction, requiring fee-bumping or reconstruction — a concrete loss-of-liveness on funds matching the Dinari report's Medium severity (wrong amount accounted in producing the final artifact). The error magnitude is `fee_per_vbyte * (vbytes of the omitted OP_RETURN output)`.

### Likelihood Explanation
Any constructor call combining a `data` payload with a conservative `fee_per_vbyte` triggers it deterministically — no attacker sophistication needed; it is an arithmetic omission reachable through the public `SignableTransaction::new` API whenever integrators attach OP_RETURN data (as Serai's own flows do for instructions).

### Recommendation
Include the OP_RETURN output in the size calculation: extend `calculate_weight_vbytes` to take the already-built `tx_outs` (or `payments` plus an optional data `ScriptBuf::new_op_return(...)`), and perform the `needed_fee`, `TooLowFee`, change-amount, and `MAX_STANDARD_TX_WEIGHT` checks against the complete output set.

### Proof of Concept
```rust
// In-scope: networks/bitcoin/src/wallet/send.rs
// Construct inputs/payments such that input_sat == payment_sat + fee_per_vbyte * vbytes_exact.
// Call SignableTransaction::new with data = Some(vec![0u8; 80]) and no change,
// fee_per_vbyte chosen so needed_fee == DEFAULT_MIN_RELAY_TX_FEE * vbytes / 1000 exactly.
//
// The call succeeds (TooLowFee check passes against the undersized template).
// The final tx contains an extra ~91-weight-unit OP_RETURN output:
//   actual_vsize > vbytes used for the check
//   tx.fee() == needed_fee  ->  tx.fee() / actual_vsize < min relay feerate
// bitcoind rejects the signed transaction with "min relay fee not met",
// while SignableTransaction claimed the fee was sufficient.
```
Adding a debug assertion `assert_eq!(tx.weight().to_wu(), weight)` at the end of `SignableTransaction::new` fails for any `data.is_some()` input, demonstrating the computed `weight`/`needed_fee` never accounted for the OP_RETURN output.
