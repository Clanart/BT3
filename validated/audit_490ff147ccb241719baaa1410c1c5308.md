### Title
PedPoP `Commitments::read` accepts the identity point for `commitments[0]`, making the Schnorr proof-of-knowledge trivially forgeable and bypassing the rogue-key defense - (File: crypto/dkg/pedpop/src/lib.rs)

### Summary
The PedPoP DKG's sole defense against rogue-key contributions is a Schnorr PoK verified against `commitments[0]` (the participant's constant-term commitment). `Commitments::read` deserializes these points with `Ciphersuite::read_G`, which rejects non-canonical encodings but permits the identity point. FROST's `Curve::read_G` explicitly rejects identity, but PedPoP (generic over `Ciphersuite`, not `Curve`) never applies that check. Because the PoK is verified against whatever `commitments[0]` the attacker supplies — analogous to relying on a client-side filter while accepting the uploaded object server-side — a malicious participant can submit `commitments[0] = identity` and forge the "proof of knowledge" for a commitment whose discrete logarithm does not exist.

### Finding Description
- `Commitments::<C>::read` reads `params.t()` points via `C::read_G` where `C: Ciphersuite`. `Ciphersuite::read_G` only checks canonicality/validity of the encoding; it does not reject the identity [1](#0-0) . The FROST-aware `Curve::read_G` rejects identity, but PedPoP is parameterized over `Ciphersuite` and cannot call it [2](#0-1) .
- In `verify_r1`, the PoK signature is batch-verified with `msg.commitments[0]` as the public key and challenge `challenge(context, l, R, cached_msg)` [3](#0-2) .
- A Schnorr signature `(R, s)` verifies when `s*G == R + c*A`. With `A = commitments[0] = identity`, the equation reduces to `s*G == R`, so the attacker picks any `s`, sets `R = s*G`, and the forged PoK passes `batch_verify` — a proof of knowledge of a discrete logarithm that does not exist (identity has no dlog).
- This directly defeats the mechanism the spec describes as preventing rogue-key attacks (per `spec/cryptography/Distributed Key Generation.md`, the Schnorr PoK on coefficient zero is what prevents rogue keys).

### Impact Explanation
An unprivileged DKG participant can pass the round-1 verification with a constant-term commitment of identity, i.e., without proving knowledge of their secret contribution. While setting `A0 = identity` alone only removes their contribution to the group secret, the bypass means the proof-of-knowledge check — the only thing binding the participant to knowledge of their polynomial — is vacuous for any attacker-supplied `commitments[0]` lacking a known dlog relative to whatever transcript/challenge structure a composing protocol or future variant uses. Concretely: the verifier accepts a forged proof of knowledge, and the anti-rogue-key guarantee the protocol advertises is not enforced server-side.

### Likelihood Explanation
Any participant in a PedPoP key-generation session can reach this: they serialize `Commitments` with an identity first point and a forged signature. `EncryptionKeyMessage<Commitments>::read` → `Commitments::read` → `verify_r1` accepts it; the batch verifier's Schnorr statement is satisfied trivially. No collusion required.

### Recommendation
Reject identity (and any non-prime-order or otherwise degenerate point) in `Commitments::read` / `verify_r1` — e.g., check `commitments[0].is_identity()` (and ideally every coefficient) before queuing the PoK, mirroring `Curve::read_G`'s identity rejection [2](#0-1) .

### Proof of Concept
1. Attacker (participant `l`) constructs `Commitments` with `commitments[0] = C::G::identity()` and arbitrary `G*c_j` for `j ≥ 1`.
2. Attacker chooses `s` randomly, sets `R = C::generator() * s`, computes `c = challenge::<C>(context, l, R.to_bytes(), &cached_msg)` — but the verification `s*G == R + c*identity = R` holds for **any** `c`, so `SchnorrSignature { R, s }` is a valid forgery.
3. `Commitments::read` accepts the encoding (identity is a canonical point under `Ciphersuite::read_G`), and `verify_r1`'s `batch_verify` succeeds, admitting commitments with no proof of knowledge.

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
  }
