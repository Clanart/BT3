### Title
Non-20-byte bech32 receiver addresses in IBC ERC20 conversion silently truncate to attacker-chosen EVM address - (File: x/erc20/keeper/ibc_callbacks.go, encoding/address/address_codec.go)

### Summary
`evmCodec.StringToBytes` [1](#0-0)  decodes a bech32 string and only validates it via `sdk.VerifyAddressFormat`, which (per the SDK) only rejects empty or >255-byte addresses — it does **not** enforce the 20-byte length that this EVM-compatible codec otherwise assumes for hex addresses. The decoded bytes are then used directly as an `sdk.AccAddress` and, in `OnRecvPacket`, fed into `common.BytesToAddress(recipient.Bytes())` [2](#0-1)  to determine the ERC20 mint target. Go-ethereum's `common.Address.SetBytes` truncates any input longer than 20 bytes by keeping only the **last** 20 bytes (and left-pads shorter inputs) — this is structurally identical to the reported `HexUtils.hexStringToBytes32()` bug: no length check before combining a variable-length byte slice into a fixed 20/32-byte value.

### Finding Description
The `evmCodec` is used as the IBC transfer address codec (`app.TransferKeeper.SetAddressCodec(evmaddress.NewEvmCodec(...))`) [3](#0-2)  and as `k.addrCodec` in the ERC20 IBC middleware. When an IBC packet arrives, `OnRecvPacket` decodes `data.Receiver` with this codec: hex addresses are validated for exactly 20 bytes via `common.IsHexAddress`, but the bech32 branch has no such check — any bech32 string whose data part decodes to 1–255 bytes and matches the local HRP is accepted [4](#0-3) . The resulting `recipient sdk.AccAddress` is used both to receive the native bank coin `MintingEnabled`/mint check and, critically, converted via `common.BytesToAddress(recipient.Bytes())` to pick the ERC20 mint destination [5](#0-4) .

Because `common.BytesToAddress` on an input >20 bytes drops the leading bytes and keeps only the trailing 20, a receiver string that bech32-encodes `X || victim20Bytes` (where `X` is arbitrary padding and `victim20Bytes` is any target 20-byte value) decodes into a distinct, long `AccAddress`, yet the ERC20 mint recipient computed from it collapses to exactly `victim20Bytes`. This same collapsing bug is analogous to `HexUtils`'s "read out-of-range"/"discard excess data" cases from the referenced report.

### Impact Explanation
This breaks the intended 1:1 bijection between Cosmos accounts and EVM addresses that the whole EVM compatibility layer relies on. An attacker fully controls the choice of a 20-byte suffix; since the mint call `k.ConvertCoinNativeERC20(...common.BytesToAddress(recipient.Bytes()), recipient)` mints ERC20 balance to the truncated 20-byte address while the bank-side accounting/`MintingEnabled` check and module-account guard operate on the untouched long `recipient` AccAddress, the ERC20 balance ends up minted to an address the attacker did not derive through the standard hex/bech32 correspondence, and which is not the AccAddress that actually "owns" the escrowed/received coin from the bank's perspective. This can be used to mint ERC20 balance directly into any target EVM address of the attacker's choosing (e.g., a victim's real wallet, a precompile-adjacent address, or an escrow/module-derived address) without the attacker controlling that account — corrupting the accounting invariant between the credited Cosmos coin and the corresponding ERC20 view of it, and potentially enabling ERC20 balance injection that a victim did not consent to receive, confusing downstream systems that assume the ERC20 balance and bank coin balance for the same "recipient" always correspond to the same account.

### Likelihood Explanation
This is triggerable by anyone able to construct or relay an IBC transfer packet with a controlled `receiver` field (an ordinary IBC user, or in permissioned/testnet cases a channel where the attacker is the sender on the counterparty chain) — no special privileges are required beyond sending a standard `MsgTransfer`/packet with a crafted bech32 receiver string encoding non-20 bytes matching the local HRP.

### Recommendation
In `evmCodec.StringToBytes` (`encoding/address/address_codec.go`), after `bech32.DecodeAndConvert`, explicitly require `len(bz) == 20` (or the length required by the specific codec use, e.g. validator/consensus addresses) and reject otherwise, instead of relying solely on `sdk.VerifyAddressFormat`'s generic 1–255 byte bound. Additionally, in `x/erc20/keeper/ibc_callbacks.go`, avoid using `common.BytesToAddress` on an `AccAddress` whose length has not been asserted to be exactly 20 bytes.

### Proof of Concept
1. Construct `bz = append(paddingBytes, victimEVMAddressBytes[:20]...)` where `paddingBytes` is arbitrary and non-empty, e.g. total length 30 bytes.
2. Bech32-encode `bz` with the chain's account HRP to get a receiver string `data.Receiver`.
3. Send an IBC transfer packet whose `FungibleTokenPacketData.Receiver` is this string, for a registered native-ERC20 token pair.
4. `k.addrCodec.StringToBytes(data.Receiver)` returns the full 30-byte `bz` (passes `VerifyAddressFormat` since 1 ≤ 30 ≤ 255) [4](#0-3) .
5. `OnRecvPacket` computes `common.BytesToAddress(recipient.Bytes())`, which truncates to the last 20 bytes — i.e., `victimEVMAddressBytes` — and mints ERC20 tokens there via `ConvertCoinNativeERC20` [6](#0-5) , while the underlying bank coin was minted/checked against the 30-byte `recipient` AccAddress, not the victim's real 20-byte account.

// StringToBytes decodes text to bytes using either hex or bech32 encoding
func (bc evmCodec) StringToBytes(text string) ([]byte, error) {
	if len(strings.TrimSpace(text)) == 0 {
		return []byte{}, sdkerrors.ErrInvalidAddress.Wrap("empty address string is not allowed")
	}

	switch {
	case common.IsHexAddress(text):
		return common.HexToAddress(text).Bytes(), nil
	case utils.IsBech32Address(text):
		hrp, bz, err := bech32.DecodeAndConvert(text)
		if err != nil {
			return nil, err
		}
		if hrp != bc.bech32Prefix {
			return nil, sdkerrors.ErrLogic.Wrapf("hrp does not match bech32 prefix: expected '%s' got '%s'", bc.bech32Prefix, hrp)
		}
		if err := sdk.VerifyAddressFormat(bz); err != nil {
			return nil, err
		}
		return bz, nil
	default:
		return nil, sdkerrors.ErrUnknownAddress.Wrapf("unknown address format: %s", text)
	}
}
