## Title
Single global `maxOracleAge` shared across mismatched Chainlink heartbeats lets stale price data drain the paymaster - (`evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster` reproduces the exact broken invariant from the external Chainlink report: instead of a per-feed staleness bound, it enforces one governance-set `maxOracleAge` against **every** Chainlink feed it consults — the volatile `nativeOracle` (e.g. ETH/USD, hourly heartbeat) and every registered stablecoin `tokenOracle` (which the contract's own comment says can have up to a 24h heartbeat) — even though these feeds update on very different cadences.

### Finding Description
`_getOraclePrice` is the sole staleness gate for both oracle legs used in pricing: [1](#0-0) 

It is called identically for the native leg and the token leg from `_tokenPrice`: [2](#0-1) 

There is only one staleness parameter, `maxOracleAge`, stored globally and validated only against a hard ceiling (`MAX_ORACLE_AGE = 7 days`), with no per-oracle override analogous to the original report's `customizedDelay`: [3](#0-2) 

The contract's own documentation acknowledges the heartbeat mismatch this creates but does not address it structurally — it just says the governance-set value must be picked to fit all feeds: [4](#0-3) 

Because `maxOracleAge` must be large enough to avoid spuriously reverting on the slowest-updating feed the deployment supports (per-comment, up to 24h for some stablecoin feeds on Base/Ethereum), that same wide window is also applied to the fast-updating `nativeOracle`. This lets `_getOraclePrice(nativeOracle, ...)` accept an ETH/USD (or BNB/USD) quote that is many hours old, even though the native asset can move materially within that window — unlike the original `PriceOracle.sol` bug this is not merely a revert/DoS issue, it is a silent acceptance of outdated native-asset pricing that feeds directly into `tokenPrice`, which determines exactly how much ERC-20 the paymaster charges per unit of gas in `_fetchDetails`: [5](#0-4) 

### Impact Explanation
`tokenPrice = (nativeUsd * 10^tokenDecimals * (10000+markupBps)) / (tokenUsd * 10000)` is used by the inherited `PaymasterERC20` to compute how many stablecoins to pull from the user for a given amount of native gas. If the cached `nativeUsd` is stale by up to `maxOracleAge` (sized for the slower token feed, not the native feed), a user operation submitted while the true native price has since risen materially will be charged the paymaster's stale (lower) rate — i.e., the paymaster pays real, current-price gas but collects stablecoins priced against outdated, cheaper `nativeUsd`. This is a direct economic drain on the treasury/paymaster funds, reachable by any unprivileged UserOp sender who times a submission after a large native-asset price move but before the stale oracle round is superseded — no relayer, prover, or admin compromise required.

### Likelihood Explanation
The condition is not a rare edge case: it is guaranteed by design whenever governance sets `maxOracleAge` large enough to accommodate a registered token oracle with a slow heartbeat (explicitly anticipated in the code's own comments, "Base/Ethereum stablecoins up to 24h"), which simultaneously loosens the staleness bound for the native oracle. An attacker only needs to watch for a native-asset price movement and submit (or have already pending) a UserOp before the paymaster's next observed Chainlink round for `nativeOracle`, well within the multi-hour/24h window permitted by the shared `maxOracleAge`.

### Recommendation
Add a per-oracle staleness bound (mirroring the recommended fix in the original report's `customizedDelay`) — at minimum a separate `maxOracleAge` for `nativeOracle` distinct from `tokenOracle.maxOracleAge`, ideally a `TokenConfig.maxAge` field settable per registered token/native pair matching each feed's actual heartbeat, so a slow stablecoin feed's staleness allowance can no longer be used to smuggle in stale pricing for the fast-moving native asset leg.

### Proof of Concept
1. Governance registers a token (e.g., a Base/Ethereum stablecoin) whose Chainlink feed has a 24h heartbeat, and must set `maxOracleAge` ≥ ~24h to avoid `StaleOraclePrice` reverts on every `_fetchDetails` call for that token (see `_setParams` bound check, lines 219, and `_getOraclePrice`'s check at line 432).
2. `nativeOracle` (ETH/USD, hourly heartbeat) is still checked with that same 24h `maxOracleAge`.
3. ETH price rises sharply; `nativeOracle.latestRoundData()` has not yet been updated but is still well within the 24h window, so `_getOraclePrice(nativeOracle, ...)` returns the stale, lower price without reverting.
4. Attacker submits a UserOp with `paymasterData` pointing at the registered stablecoin. `_fetchDetails` → `_tokenPrice` computes `tokenPrice` using the stale, undervalued `nativeUsd`, so the attacker is charged stablecoins priced against the old (cheaper) ETH price while the paymaster actually spends gas at the new (higher) ETH price — a realized loss to the paymaster/treasury on every such operation until the oracle round updates.     function _fetchDetails(
        PackedUserOperation calldata userOp,
        bytes32 /* userOpHash */
    ) internal view override returns (uint256 validationData, IERC20 token, uint256 tokenPrice) {
        bytes calldata data = userOp.paymasterData();
        if (data.length < 21) revert InvalidPaymasterData(data.length);

        uint8 mode = uint8(data[0]);
        if (mode > 0x01) revert InvalidMode(mode);

        address tokenAddr = address(bytes20(data[1:21]));

        TokenConfig memory cfg = tokenConfigs[tokenAddr];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(tokenAddr);
        if (!cfg.active) revert TokenNotActive(tokenAddr);

        tokenPrice = _tokenPrice(cfg);
        token = IERC20(tokenAddr);
        validationData = 0; // no time-range restriction
    }

    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer, , uint256 updatedAt, ) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
