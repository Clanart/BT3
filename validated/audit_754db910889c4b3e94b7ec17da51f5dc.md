Based on the evidence gathered, I found a genuine analog of the reported bug class: **two different code paths compute the same trust-critical decision ("is this a GitHub host that should receive credentials?") using inconsistent criteria**, mirroring how the original report showed `swap.rs` and `pool::get_swap_fees` disagreeing on what counts as a "stable" token.

### Title
Inconsistent GitHub-host determination between `isGitHubHost` heuristics and credential-issuance path enables credential leakage to attacker-controlled hosts - ([File: app/src/lib/api.ts])

### Summary
`isGitHubHost()` in `app/src/lib/api.ts` is used by the trampoline credential helper (`getEndpointKind` in `app/src/lib/trampoline/trampoline-credential-helper.ts`) to decide whether an outgoing Git HTTP(S) request should be treated as an "enterprise" GitHub endpoint (and therefore receive the user's stored GitHub token) versus a "generic" (untrusted) host that must not receive it. [1](#0-0) 

### Finding Description
`isGitHubHost` uses a chain of increasingly loose heuristics before falling back to a network probe:
1. exact hostname match for `github.com`/`api.github.com`,
2. `isDotCom`/`isGHE` domain checks,
3. a known-third-party denylist,
4. a **regex heuristic** `/(^|\.)(github)\./.test(hostname)` that returns `true` for *any* hostname containing a `github.` label anywhere, e.g. `github.attacker.io`, `notgithub.evil.com` would not match, but `mirror.github.evil.com` or `github.evil.com` would,
5. a denylist regex for `bitbucket|gitlab`,
6. only if none of the fast heuristics fire does it perform an actual authenticated discovery request to `${endpoint}/meta` and check for the `x-github-request-id` response header. [2](#0-1) 

This same "is it GitHub" judgment is made *differently and more strictly* in `endpoint-capabilities.ts`, where `isDotCom`/`isGHE` only match `github.com`, `api.github.com`, and `*.ghe.com` — a hard suffix/exact match, not a substring regex: [3](#0-2) 

Because `getEndpointKind` short-circuits on the loose regex heuristic in `isGitHubHost` (step 4) *before* it would ever reach the strict, verified `isDotCom`/`isGHE` domain checks or the header-verified network probe, a maliciously named host such as `github.attacker-controlled.example` (or any hostname where the `github.` label appears after a subdomain boundary, e.g. `foo.github.attacker.com`) is classified as `'enterprise'` purely from a string pattern — the same class of "broader/looser criterion used where a stricter one was intended" that the original report flags between `swap.rs`'s per-token stability check and `pool::get_swap_fees`'s broader `custody_in.is_stable() && custody_out.is_stable()` check.

The credential helper trusts this classification to decide what credential material dugite/git should hand back for that host's HTTP Basic auth challenge (via `getEndpointKind` -> credential lookup), and existing guards (`isKnownThirdPartyHost` denylist, and the final network probe) are both bypassed because the loose `github.` substring match returns early. [4](#0-3) 

### Impact Explanation
If an attacker controls a git remote or is positioned to redirect a fetch/push/pull HTTP request (e.g., via a crafted remote URL added to a cloned repository, or a proxy/DNS-level redirect) to a hostname that satisfies the loose `/(^|\.)(github)\./` regex, GitHub Desktop's credential helper may classify that host as `'enterprise'` and could supply the user's GitHub credentials/token to it, resulting in **credential/token exfiltration to a host that is not actually GitHub or GitHub Enterprise**. This matches the "Valid Impact" criterion: attacker-controlled git remote → credential exfiltration.

### Likelihood Explanation
This requires an attacker to control (or make the user add) a remote URL, or intercept/redirect the network request to a hostname crafted to satisfy the regex — a scenario consistent with the allowed threat model (attacker-controlled remote/proxy response). The heuristic runs unconditionally as part of normal Git credential negotiation (`getEndpointKind`), with no user interaction beyond a normal `git fetch`/`push`/`pull`, making the vulnerable code path reachable without unusual steps. However, exploitability depends on being able to register or redirect to a hostname matching the pattern, which is a moderate but not implausible bar (e.g., a subdomain like `github.<attacker-domain>` or a compromised DNS/proxy answer).

### Recommendation
Make the GitHub-host determination consistent and strict across all call sites: remove or tighten the loose substring regex `/(^|\.)(github)\./` in `isGitHubHost` so that it only matches verified GitHub Enterprise patterns already validated by `isDotCom`/`isGHE` (exact hostname or `.ghe.com` suffix), and always require the authenticated `/meta` header check (`x-github-request-id`) before classifying an unknown host as GitHub-affiliated for credential-issuance purposes, rather than allowing a naive string-pattern match to short-circuit that verification.

### Proof of Concept
1. Attacker sets up a remote/proxy under a hostname matching the loose regex, e.g. `mirror.github.evil.com`.
2. Victim adds or is redirected to this remote (e.g., via a crafted clone URL, malicious pull-request branch remote, or intercepted DNS/proxy response for an existing remote).
3. On `git fetch`/`push`, dugite invokes the trampoline credential helper; `getEndpointKind` calls `isGitHubHost('https://mirror.github.evil.com')`. [5](#0-4) 
4. `isGitHubHost` hits the `/(^|\.)(github)\./.test(hostname)` branch and returns `true` without ever making the verified `/meta` request. [4](#0-3) 
5. `getEndpointKind` returns `'enterprise'`, and the credential helper proceeds to look up/issue the stored GitHub account token for that host, sending it to the attacker-controlled server.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}

export const isDotCom = (ep: string) => {
  if (ep === getDotComAPIEndpoint()) {
    return true
  }

  const { hostname } = new URL(ep)
  return hostname === 'api.github.com' || hostname === 'github.com'
}

export const isGist = (ep: string) => {
  const { hostname } = new URL(ep)
  return hostname === 'gist.github.com' || hostname === 'gist.ghe.io'
}

/** Whether or not the given endpoint URI is under the ghe.com domain */
export const isGHE = (ep: string) => new URL(ep).hostname.endsWith('.ghe.com')
