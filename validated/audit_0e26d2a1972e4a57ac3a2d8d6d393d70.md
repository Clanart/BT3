### Title
Unauthenticated deep links silently trigger repository fetch/branch-checkout/PR-checkout with no user confirmation - (File: `app/src/ui/dispatcher/dispatcher.ts`)

### Summary
GitHub Desktop registers OS-level custom URL protocols (`x-github-client://`, `github-mac://`, `github-windows://`) that any website or link can invoke [1](#0-0) . When the OS delivers such a URL, `handleAppURL` parses it and forwards the parsed action straight to the renderer without any authorization or provenance check on who issued the link [2](#0-1) . `parseAppURL` only validates syntax (query params, path shape), not trust [3](#0-2) . The renderer's `dispatchURLAction` then unconditionally executes the `open-repository-from-url` action for any caller [4](#0-3) .

### Finding Description
`openRepositoryFromUrl`/`openBranchNameFromUrl` resolve the attacker-supplied `url` to an already-cloned repository on disk (via a loose hostname/owner/name match, `doesRepositoryMatchUrl`), then automatically run `_fetch` against the network and `checkoutLocalBranch` to the attacker-chosen branch name — with zero confirmation dialog, dirty-worktree check, or authorization gate [5](#0-4) . Similarly, `openPullRequestFromUrl` calls `fetchPullRequest`, then `_checkoutPullRequest` using `pullRequest.head.repo.clone_url`/`ref` taken from the API response for a PR number supplied entirely by the link, again with no confirmation step [6](#0-5) .

The broken invariant mirrors the external report exactly: a function that performs a state-changing, trust-sensitive operation (fetch + checkout against a locally cloned repository, or clone a new one) is reachable by an unauthenticated external trigger — here, an OS deep link that any web page or message can invoke — without a preceding permission/confirmation check. The existing IPC hardening (`isTrustedIPCSender`, `addTrustedIPCSender`) only protects renderer↔main IPC channels [7](#0-6) [8](#0-7) ; it does nothing for the OS-protocol entry point, which is exactly where the untrusted input enters (`open-url`/`open-file` handlers in `main.ts`) [9](#0-8) . There is no equivalent "is this action allowed to run automatically" check anywhere between `parseAppURL` and the destructive `checkoutLocalBranch`/`_fetch`/`_checkoutPullRequest` calls.

### Impact Explanation
The corrupted value is the working-directory state of a repository the victim already has open in Desktop: an attacker-crafted link (e.g., embedded in a webpage, chat message, or malicious "Open in Desktop" button) can force a silent `git fetch` + branch checkout to an attacker-chosen ref/fork, changing what files are on disk right before the user's next commit — i.e., silent corruption of what the user commits or pushes, one of the explicitly valid impact classes. It also causes the client to fetch from and trust remote content (a PR head fork's `clone_url`) chosen entirely by the link, without any indication to the user that this happened outside their explicit intent.

### Likelihood Explanation
Triggering these code paths requires nothing more than the victim clicking a link (the deep-link protocols are registered by default and OS-invocable from any browser) — precisely the "link or deep link the user clicks" trigger the task scope validates as unprivileged and in-scope. No local access, no prior malware, and no credentials are needed.

### Recommendation
Before executing any state-mutating action originating from `dispatchURLAction` (fetch, checkout, clone), surface an explicit confirmation UI showing the target repository/branch/PR and require the user to approve, and/or refuse to silently checkout into a repository with uncommitted changes. Track provenance of the deep-link invocation similarly to how `isTrustedIPCSender` gates IPC, so unauthenticated OS-level invocations cannot silently mutate existing repository state.

### Proof of Concept
1. Attacker hosts a page with `<a href="x-github-client://openRepo/https://github.com/victim/repo?branch=pr%2F1337">Open in Desktop</a>` where `victim/repo` matches a repository already cloned by the target.
2. Victim clicks the link; the OS invokes GitHub Desktop with this URL.
3. `handleAppURL` → `parseAppURL` → `dispatchURLAction('open-repository-from-url', …)` → `openBranchNameFromUrl` runs `_fetch` and `checkoutLocalBranch('pr/1337')` on the victim's existing local clone with no prompt [5](#0-4) .
4. The victim's working directory is now silently switched to attacker-controlled content before their next commit/push.

function handleAppURL(url: string) {
  log.info('Processing protocol url')
  const action = parseAppURL(url)
  onDidLoad(window => {
    // This manual focus call _shouldn't_ be necessary, but is for Chrome on
    // macOS. See https://github.com/desktop/desktop/issues/973.
    window.focus()
    window.sendURLAction(action)
  })
}

  private async openBranchNameFromUrl(
    url: string,
    branchName: string
  ): Promise<Repository | null> {
    const repository = await this.openOrCloneRepository(url)

    if (repository === null) {
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    // if the repo has a remote, fetch before switching branches to ensure
    // the checkout will be successful. This operation could be a no-op.
    await this.appStore._fetch(repository, FetchType.UserInitiatedTask)

    await this.checkoutLocalBranch(repository, branchName)

    return repository
  }

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }
    if (!isRepositoryWithGitHubRepository(repository)) {
      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    if (pullRequest.head.repo === null) {
      return null
    }

    await this.appStore._checkoutPullRequest(
      repository,
      pullRequest.number,
      pullRequest.head.repo.owner.login,
      pullRequest.head.repo.clone_url,
      pullRequest.head.ref
    )

    return repository
  }

/** Adds a WebContents instance to the set of trusted IPC senders. */
export const addTrustedIPCSender = (wc: WebContents) => {
  trustedSenders.add(wc.id)
  wc.on('destroyed', () => trustedSenders.delete(wc.id))
}

/** Returns true if the given WebContents is a trusted sender of IPC messages. */
export const isTrustedIPCSender = (wc: WebContents) => trustedSenders.has(wc.id)
