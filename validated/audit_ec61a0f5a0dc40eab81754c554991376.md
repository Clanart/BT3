### Title
Payout tx anchor/OP_RETURN outputs are unsigned under `SinglePlusAnyoneCanPay`, letting anyone strip the operator's identity from a mined payout - (`core/src/builder/transaction/operator_reimburse.rs`)

### Summary
`create_payout_txhandler` builds the payout transaction with the user's `SIGHASH_SINGLE|ANYONECANPAY` signature only over input 0, which under BIP-341 taproot sighash rules commits solely to output index 0. Outputs 1 (anchor) and 2 (OP_RETURN operator xonly-pk) are not committed by that signature at all, so whenever the operator's own funding call adds no extra (SIGHASH_ALL-signed) input, anyone who has the raw signature/outpoint/output — all protocol-public per the docstring, or simply observable in the mempool — can rewrite those two outputs and get a variant mined that lacks a valid OP_RETURN, breaking the `payout_payer_operator_xonly_pk` binding used to attribute the payout to the fronting operator.

### Finding Description
The broken binding: `withdrawals.payout_payer_operator_xonly_pk` for index `i` **must equal** the `XOnlyPublicKey` of the operator whose wallet funded input 0 of the transaction that actually gets mined for that withdrawal.

This binding is established *only* via the OP_RETURN output built in `create_payout_txhandler`: [1](#0-0) 
which appends `operator_xonly_pk` as output index 2 (`op_return_txout`), after output 0 (user payout) and output 1 (anchor). The transaction is then signed key-path only for input 0:
```
txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
```

Crucially, `Operator::withdraw` enforces the user's signature to be `TapSighashType::SinglePlusAnyoneCanPay`: [2](#0-1) 
and verifies it with `SECP.verify_schnorr` over the sighash of only input 0: [3](#0-2) 

Per BIP-341, `SIGHASH_SINGLE` commits *only* to the output at the same index as the signed input (index 0). It does **not** commit to any other output. Consequently, output 1 (anchor) and output 2 (OP_RETURN with the operator's xonly pk) are entirely uncommitted by this signature.

The only thing that could additionally protect outputs 1/2 is another transaction input added and signed with `SIGHASH_ALL` by the operator's own wallet during funding: [4](#0-3) 
(`fund_raw_transaction` then `sign_raw_transaction_with_wallet`). But `add_inputs` is only exercised when the single withdrawal UTXO (input 0) does not already cover the payout amount, anchor amount and required fee — which is the expected/common case, since `operator_withdrawal_fee_sats` and the withdrawal amounts are chosen specifically so the withdrawal UTXO funds the whole payout. When no extra input is needed, **no signature in the final transaction commits to outputs 1 or 2 at all**.

Exploit flow: an attacker (or anyone who is handed `in_signature`, "given to all operators off-chain" per the docstring, or who simply observes any operator's broadcast tx in the public mempool) takes the exact bytes of input 0 and output 0, keeps the witness for input 0 unchanged (it remains valid because the sighash it commits to is unaffected), and rewrites output 1 (taking dust from the anchor amount if needed for balance) and output 2 to a non-OP_RETURN script (e.g., P2WSH dust). This new transaction is still fully validly signed and can be relayed/mined (subject to standardness/relay policy for the `NON_STANDARD_V3` version, which a sufficiently motivated attacker can still get to a miner directly).

Once mined, the on-chain scan in `update_finalized_payouts` runs: [5](#0-4) 
`get_first_op_return_output` returns `None` (no `is_op_return()` output exists): [6](#0-5) 
so `operator_xonly_pk` becomes `None`, and `update_payout_txs_and_payer_operator_xonly_pk` writes `payout_payer_operator_xonly_pk = NULL`: [7](#0-6) 

Downstream, `get_payout_info_from_move_txid` returns `operator_xonly_pk_opt = None` for this withdrawal, and `is_kickoff_malicious` treats this as an automatic malicious verdict for *any* operator kickoff on this deposit: [8](#0-7) 
Additionally, `get_first_unhandled_payout_by_operator_xonly_pk` filters `WHERE payout_payer_operator_xonly_pk = $1`, so `NULL` never matches any operator, meaning the automated reimbursement path never even queues this withdrawal for the fronting operator: [9](#0-8) 

None of the existing guards prevent this: `is_profitable` and the Citrea-withdrawal-UTXO check in `Operator::withdraw` (`core/src/operator.rs:594-612`) only validate input 0/output 0 against Citrea state before the honest operator broadcasts — they do not protect the mined chain state once an attacker resubmits a modified variant with a still-valid input-0 witness. `SECP.verify_schnorr` in `Operator::withdraw` only checks input 0's sighash, which (by protocol design of `SinglePlusAnyoneCanPay`) never covered outputs 1/2 to begin with.

### Impact Explanation
The fronting operator, who legitimately spent their own BTC to pay the Citrea withdrawal, is (a) permanently unable to be picked up by the automatic reimbursement path (`get_first_unhandled_payout_by_operator_xonly_pk` never matches `NULL`), and (b) any kickoff they later send manually for this deposit is flagged `is_kickoff_malicious == true`, which is treated by verifiers as a malicious kickoff — putting the operator's collateral at risk of being burned through the challenge/disprove path despite having genuinely fronted the withdrawal. This matches the Critical categories "an honest operator permanently unable to be reimbursed" and "an honest operator's collateral burned." The attack is repeatable against every withdrawal/operator pair where the withdrawal UTXO alone funds the payout tx (the common/expected configuration), since the exploit only depends on the universal, protocol-defined `SinglePlusAnyoneCanPay` sighash gap, not on any operator-specific mistake.

### Likelihood Explanation
Preconditions: attacker needs read access to any operator's broadcast (unconfirmed) payout tx in the public mempool (or the `in_signature` itself, which per the docstring is handed to all operators off-chain and thus reachable by many parties) — no privileged role or key compromise required. The attack succeeds whenever `fund_raw_transaction` does not need to add an extra SIGHASH_ALL-signed input, which is the intended/common case given `operator_withdrawal_fee_sats` is configured to make the withdrawal UTXO self-sufficient. Attacker cost is limited to constructing and relaying/mining a variant transaction and possibly funding a small amount of fee via the anchor's CPFP path; feasibility depends on getting a non-standard v3 transaction relayed or submitted directly to a miner, which is achievable for a motivated attacker. The attack is fully repeatable across withdrawals and operators.

### Recommendation
Change the user's payout signature to `SIGHASH_ALL` (or `AllPlusAnyoneCanPay`) so it commits to every output of the payout transaction, including the anchor and OP_RETURN outputs, preventing any output modification after signing while still allowing additional inputs to be added by the operator (`AnyoneCanPay`). Alternatively, commit the operator's xonly pubkey via a mechanism that does not depend on an unauthenticated output (e.g., derive/verify the payer identity from the actual funding input signer rather than a freely-rewritable OP_RETURN), and make `is_kickoff_malicious`/the reimbursement lookup key off of the input funder identity instead of an easily-strippable output.

### Proof of Concept

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
