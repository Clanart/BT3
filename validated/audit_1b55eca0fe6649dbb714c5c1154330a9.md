### Title
Front-runnable global `totalVlMgpInVote` denominator in `castVotes()` allows vote-share manipulation across all pools - ([File: wombat/WombatBribeManager.sol])

### Summary
`castVotes()` computes each pool's real target vote as `targetVoteInLMGP * totalVotes() / totalVlMgpInVote`, where `totalVlMgpInVote` is a single global value shared by every pool in the same call. An attacker can front-run the harvester's `castVotes()` transaction with a large `vote()` into their chosen pool, inflating both that pool's `totalVoteInVlmgp` and the shared `totalVlMgpInVote` denominator, which mathematically increases their pool's share of the fixed total `totalVotes()` while decreasing every other pool's share — then call `unvote()` right after to reclaim their vlMGP.

### Finding Description
In `wombat/WombatBribeManager.sol`, `vote()` [1](#0-0)  lets any vlMGP holder freely increase `pool.totalVoteInVlmgp` and the global `totalVlMgpInVote` with no cooldown, minimum holding time, or per-block restriction, and `unvote()` immediately allows full withdrawal of that same amount from an active pool [2](#0-1) .

`castVotes()` then computes, for every pool `i`, `targetVote_i = pool.totalVoteInVlmgp * totalVotes() / totalVlMgpInVote` using the single global `totalVlMgpInVote` denominator at call time [3](#0-2) . Because `sum(targetVote_i) = totalVotes()` is invariant (it always sums to `totalVotes()` regardless of how `totalVlMgpInVote` is split), injecting an additional amount `d` into a single pool `A` (raising both the numerator for A and the shared denominator for all pools) strictly increases pool A's share `(a+d)/(V+d)` at the expense of every other pool `b_i/(V+d)`, as long as pool A didn't already hold all the votes. This lets an attacker: 1) call `vote()` to add a large delta to their chosen pool right before the harvester's `castVotes()` transaction lands in the same block (front-running), 2) let `castVotes()` execute and call `wombatStaking.vote()` → `voter.vote()` on the real Wombat voter with the skewed `votes[]` deltas [4](#0-3) , permanently recording the skewed real vote allocation on-chain until the next `castVotes()` call, then 3) call `unvote()` to reclaim their vlMGP for other uses [2](#0-1) .

No modifier, cooldown, `nonReentrant`, or time-weighting exists in `vote()`/`unvote()`/`castVotes()` to prevent this same-block sequence, and `WombatStaking.vote()` only checks `msg.sender == bribeManager`, performing no sanity check on how recently vote weights changed [5](#0-4) . Because the real Wombat gauge allocation persists until the bribe manager's next `castVotes()` call (which is gas-intensive and typically called periodically, not every block), the skew can persist and redirect real Wombat gauge/bribe accrual away from other pools' honest voters for an extended window.

### Impact Explanation
This is a governance voting result manipulation: the attacker permanently (until the next `castVotes()` rebalance) redirects a disproportionate share of the real Wombat gauge vote weight — and therefore future bribe accrual routed to `pool.rewarder` — from pools that other, genuine long-term vlMGP voters selected, to a pool of the attacker's choosing, without committing genuine locked capital for that period. This matches the "governance voting result manipulation" / "theft of unclaimed yield" impact classes, since the accrual differential benefits whoever remains staked in the manipulated pool's rewarder at the expense of other pools' stakers.

### Likelihood Explanation
The attack requires the attacker to already hold/lock enough vlMGP to materially shift `totalVlMgpInVote` for one block, and the ability to front-run (observe the harvester's `castVotes()` transaction in the mempool and land a `vote()` transaction immediately before it) — both explicitly listed as acceptable unprivileged-attacker capabilities. Since `castVotes()` is a public function anyone (including MEV bots) can call and observe, and there is no time-lock/cooldown on `vote()`/`unvote()`, this is realistically repeatable every time `castVotes()` is invoked.

### Recommendation
Do not use a single mutable global `totalVlMgpInVote` snapshotted at call time as the shared denominator for all pools within `castVotes()`. Instead, either (a) compute vote weights using a time-weighted or snapshotted `totalVlMgpInVote`/`pool.totalVoteInVlmgp` (e.g., checkpointed some delay before `castVotes()`), (b) impose a minimum holding period between `vote()` and `unvote()` for the same user/pool, or (c) require `vote()` changes to only take effect after a cooldown so they cannot be reversed within the same block/epoch as a `castVotes()` call.

### Proof of Concept
Foundry test plan:
1. Deploy `WombatBribeManager` with two active pools A and B, and seed honest votes: user1 votes X vlMGP for pool A, user2 votes Y vlMGP for pool B, establishing `totalVlMgpInVote = X + Y`.
2. Compute expected `targetVote_A`/`targetVote_B` via the formula in `castVotes()` before manipulation, and record real votes that would be cast on the mocked Wombat voter.
3. Attacker (holding large idle vlMGP) calls `vote()` adding delta `d` to pool A in the same block, right before the harvester's `castVotes()` tx.
4. Call `castVotes()`; capture the actual `votes[]` array passed to `wombatStaking.vote()`/`voter.vote()`.
5. Attacker calls `unvote()` for pool A immediately after, reclaiming `d`.
6. Assert: `targetVote_A` after manipulation is measurably greater than the pre-manipulation `targetVote_A` and greater than what `X/(X+Y) * totalVotes()` would produce, while `targetVote_B` is measurably reduced below `Y/(X+Y) * totalVotes()` — demonstrating that pool B's honest voters lost real vote share purely due to attacker's transient, unbacked vote in pool A, with no lasting stake retained by the attacker after `unvote()`.

    function vote(address[] calldata _lps, int256[] calldata _deltas) override public {
        if (_lps.length != _deltas.length)
            revert LengthMismatch();

        uint256 length = _lps.length;
        int256 totalUserVote;

        for (uint256 i; i < length; i++) {
            Pool storage pool = poolInfos[_lps[i]];
            if (!pool.isActive)
                revert PoolNotActive();
            int256 delta = _deltas[i];
            totalUserVote += delta;
            if (delta != 0) {
                if (delta > 0) {
                    pool.totalVoteInVlmgp += uint256(delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] += uint256(delta);
                    IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, uint256(delta));
                } else {
                    pool.totalVoteInVlmgp -= uint256(-delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] -= uint256(-delta);
                    IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(-delta), false);
                }
            }
        }

        if (msg.sender != delegatedPool) {
            if (totalUserVote > 0) {
                userTotalVotedInVlmgp[msg.sender] += uint256(totalUserVote);
                totalVlMgpInVote += uint256(totalUserVote);
            } else {
                userTotalVotedInVlmgp[msg.sender] -= uint256(-totalUserVote);
                totalVlMgpInVote -= uint256(-totalUserVote);
            }
        }

        if (userTotalVotedInVlmgp[msg.sender] > getUserVotable(msg.sender))
            revert NotEnoughVote();
    }
