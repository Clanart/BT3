### Title
Unhandled `IndexError` in CLVM canonical-form length-prefix parsing during mempool admission - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_atom_canonical()` / `is_clvm_canonical()` parse the CLVM atom length-prefix encoding by indexing into the raw `bytes` buffer for each additional prefix byte without ever checking that `offset` stays within the buffer bounds. This mirrors the PJSIP H.264 unpacketizer bug class: a multi-byte size field is read assuming both/all bytes are present in the buffer, with no bounds check before the read. In this codebase the analogous read is `clvm_buffer[offset]` inside the `for i in range(prefix_len)` loop of `is_atom_canonical`.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` decodes a CLVM atom's length prefix, which can be 1–6 bytes depending on the top bits of the first byte: [1](#0-0) 

The prefix-length decoding branches (`prefix_len` up to 5) determine how many *additional* bytes must be read after the first byte, but the subsequent loop reads `clvm_buffer[offset]` for each of those bytes with no check that `offset < len(clvm_buffer)`:

```python
atom_len = b & mask
for i in range(prefix_len):
    atom_len <<= 8
    offset += 1
    atom_len |= clvm_buffer[offset]
```

`is_clvm_canonical()`, which calls this function, is itself missing any bounds check for the initial `clvm_buffer[offset]` read at the top of its own loop before dispatching to `is_atom_canonical`: [2](#0-1) 

Both functions are invoked directly on attacker-supplied bytes — the `puzzle_reveal` and `solution` of every coin spend in a submitted `SpendBundle` — during mempool admission in `validate_spend_bundle()`: [3](#0-2) 

If a submitter crafts a `puzzle_reveal` or `solution` whose CLVM byte stream ends exactly on (or just before) a multi-byte length-prefix byte (e.g., the last byte is `0xC0`–`0xFF`, signalling 1–5 more prefix bytes follow, but the buffer has fewer trailing bytes than required), `is_atom_canonical`/`is_clvm_canonical` will index past the end of the `bytes` object and raise an unhandled `IndexError`, rather than raising a `ValueError`/returning a controlled `Err` as the surrounding code expects.

### Impact Explanation
`validate_spend_bundle()` is on the mempool admission path reached by any unprivileged spend-bundle submitter (via RPC or peer gossip of a transaction). No caller in the shown code path wraps this call in a `try/except IndexError`; the function's contract is to return `(Err, MempoolItem | None, list[bytes32])` or raise `Err`-typed failures, not raw Python exceptions. An unhandled `IndexError` propagating out of `validate_spend_bundle()` would abort processing of that mempool-admission code path instead of cleanly rejecting the malformed spend bundle, i.e., a spend-triggered transaction-processing halt/crash of the mempool manager's admission flow for that bundle (and potentially the enclosing task/coroutine handling it).

### Likelihood Explanation
Any unprivileged party who can submit a spend bundle (wallet RPC caller, offer counterparty broadcasting a transaction, mempool peer) fully controls `puzzle_reveal` and `solution` bytes for their own coin spends. Constructing a byte string that ends mid-length-prefix is trivial and requires no cryptographic material or privileged access — it's a pure serialization-format edge case exactly analogous to the PJSIP NAL-size-field truncation.

### Recommendation
Add explicit bounds checks in `is_atom_canonical` before each `clvm_buffer[offset]` read (e.g., verify `offset < len(clvm_buffer)` prior to incrementing/indexing, treating a truncated prefix as non-canonical rather than raising), and add the same guard at the top of the `is_clvm_canonical` loop for `clvm_buffer[offset]`. Ensure `validate_spend_bundle()` (or its caller) converts any parsing exception from these helpers into the existing `Err.INVALID_COIN_SOLUTION` control-flow path instead of allowing an unhandled exception to propagate.

### Proof of Concept
Submit a `SpendBundle` whose `solution` (or `puzzle_reveal`) is a truncated multi-byte-length atom, e.g. a buffer ending in `0xC0` (5+8-bit prefix requiring 1 more byte) with zero trailing bytes: `bytes([0xC0])`. When `validate_spend_bundle()` calls `is_clvm_canonical(bytes(coin_spend.solution))`, `is_atom_canonical` will execute `offset += 1; atom_len |= clvm_buffer[offset]` where `offset == len(clvm_buffer)`, raising `IndexError: index out of range` instead of returning a canonical/non-canonical verdict.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
