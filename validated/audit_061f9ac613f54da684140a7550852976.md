### Title
Fake `WWW-Authenticate: realm="GitHub"` header from an untrusted remote/submodule bypasses host verification and triggers a spoofed GitHub Enterprise OAuth flow - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
GitHub Desktop's credential-helper trampoline decides whether an unknown host is a real GitHub/GHE endpoint (and therefore whether to launch its OAuth sign-in flow) based on an HTTP response header (`WWW-Authenticate`) that is fully controlled by the remote server Git is talking to. If that header contains `realm="GitHub"`, Desktop skips its real verification (`isGitHubHost`, which does a network probe) and treats an arbitrary attacker-controlled host as a legitimate GitHub Enterprise endpoint, prompting the user to sign in via OAuth against that host.

### Finding Description
`getEndpointKind()` classifies the endpoint associated with a credential request. Before falling back to the network-verified `isGitHubHost(endpoint)` check, it inspects the `wwwauth[...]` entries copied verbatim from the credential/Git response and short-circuits to `'enterprise'` if any value contains `realm="GitHub"`: [1](#0-0) 

This value originates from the git credential protocol's `wwwauth[]` fields, which Git populates from the `WWW-Authenticate` response header sent by whatever server it is talking to for that particular network operation. Because a single Desktop-driven `git` invocation can touch multiple hosts beyond the primary remote (submodules, Git LFS servers, redirected URLs), an attacker who controls any one of those secondary endpoints - e.g. a malicious submodule URL or LFS server referenced by a cloned repository - can make that endpoint respond with `WWW-Authenticate: realm="GitHub"` and be classified as `'enterprise'` without ever going through the legitimate `isGitHubHost` verification path.

Once classified as non-generic, `getCredential()` checks whether an existing account already matches that endpoint; if not (which it won't, since it's an attacker's server), Desktop calls `ui.promptForGitHubSignIn(endpoint)`: [2](#0-1) 

`promptForGitHubSignIn` then starts the Enterprise sign-in flow using the attacker-controlled `endpoint` as the sign-in origin and shows the standard sign-in dialog: [3](#0-2) 

If the user proceeds (believing they are being asked to authenticate to a corporate/enterprise GitHub instance related to the repository they just opened), `authenticateWithBrowser()` opens the OAuth authorize URL built from that attacker endpoint using Desktop's real, bundled OAuth `client_id`: [4](#0-3) [5](#0-4) 

Completing the flow causes `requestOAuthToken()` to POST the bundled `client_id`/`client_secret` and the authorization `code` directly to the attacker-controlled host in order to exchange for an access token: [6](#0-5) 

This is the same broken-invariant pattern as the reported smart-contract bug: a security-relevant decision (which "identity"/endpoint to trust and act on behalf of) is derived from a value that should never be treated as authoritative — in the contract it was `msg.sender` after being routed through an intermediary instead of the originally supplied `_sender`; here it is an attacker-suppliable HTTP header instead of an out-of-band, network-verified host check. The existing guard that should stop this (`isGitHubHost`, an actual request to the candidate host to confirm it's really GitHub-flavored) is bypassed entirely by the `wwwauth[]` shortcut.

### Impact Explanation
Successful exploitation results in Desktop's real OAuth `client_id`/`client_secret` being sent to a server the attacker controls, and the OAuth authorization flow (with Desktop's genuine scopes: `repo`, `user`, `workflow`) being initiated against that server via the user's browser. Depending on how the attacker leverages the leaked client secret / captured flow (e.g., replaying against the true `github.com`/GHE token endpoint, or harvesting the authorization `code` if they also control a plausible redirect), this can lead to unauthorized OAuth token issuance/account binding without the user knowingly signing in to an attacker's service — matching the "unauthorized OAuth" impact category. It also serves as a strong phishing primitive: Desktop itself vouches for the (fake) "GitHub Enterprise" sign-in prompt.

### Likelihood Explanation
The trigger requires only that a victim clone/open/fetch a repository whose submodule URL, LFS endpoint, or other secondary remote points at an attacker-controlled server that answers HTTP requests with a crafted `WWW-Authenticate: realm="GitHub"` header — no local access, no prior credentials, and no unnatural user steps beyond normal repository usage and (once) approving a familiar-looking Desktop sign-in dialog. This fits squarely within the allowed attacker model ("attacker controls ... a git remote/proxy response").

### Recommendation
Do not classify an endpoint as GitHub/Enterprise based solely on the `wwwauth[]` header value supplied by the remote. Either remove this shortcut entirely and always rely on the network-verified `isGitHubHost(endpoint)` check, or additionally require that the endpoint be reachable and independently confirmed via the same probe used by `isGitHubHost` before ever invoking `promptForGitHubSignIn`. At minimum, the sign-in prompt triggered from the credential-helper path should clearly disclose that the request originated from an unverified host discovered mid-operation (e.g., a submodule/LFS URL), not the primary repository remote the user intended to interact with.

### Proof of Concept
1. Attacker publishes a public repository containing a `.gitmodules` entry (or Git LFS `.lfsconfig`) pointing to `https://attacker.example/evil`.
2. `attacker.example` is configured to respond to any Git HTTP credential probe with `HTTP 401` and header `WWW-Authenticate: Basic realm="GitHub"`.
3. Victim clones the repository in GitHub Desktop and Desktop performs a submodule/LFS fetch against `attacker.example`.
4. Git's credential protocol forwards the `wwwauth[]` value to Desktop's credential helper; `getEndpointKind()` returns `'enterprise'` for `attacker.example` without ever calling `isGitHubHost`. [7](#0-6) 
5. Since no stored account matches `attacker.example`, Desktop calls `ui.promptForGitHubSignIn('https://attacker.example')`, showing the normal "Sign in to GitHub Enterprise" dialog with that origin.
6. If the victim proceeds, `beginEnterpriseSignIn`/`authenticateWithBrowser` opens `https://attacker.example/login/oauth/authorize?client_id=<real_client_id>&scope=repo+user+workflow&state=...` in the browser, and upon a crafted redirect back to Desktop, `requestOAuthToken` POSTs `client_id`/`client_secret`/`code` to `https://attacker.example/login/oauth/access_token`, handing Desktop's OAuth secret and the flow to the attacker's server.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'

  public async authenticateWithBrowser() {
    const currentState = this.state

    if (
      currentState?.kind !== SignInStep.Authentication &&
      currentState?.kind !== SignInStep.ExistingAccountWarning
    ) {
      const stepText = currentState ? currentState.kind : 'null'
      return fatalError(
        `Sign in step '${stepText}' not compatible with browser authentication`
      )
    }

    this.setState({ ...currentState, loading: true })

    if (currentState.kind === SignInStep.ExistingAccountWarning) {
      const { existingAccount } = currentState
      // Try to avoid emitting an error out of AccountsStore if the account
      // is already gone.
      if (this.accounts.find(x => x.endpoint === existingAccount.endpoint)) {
        await this.accountStore.removeAccount(existingAccount)
      }
    }

    const csrfToken = crypto.randomUUID()

    new Promise<Account>((resolve, reject) => {
      const { endpoint, resultCallback } = currentState
      log.info('[SignInStore] initializing OAuth flow')
      this.setState({
        kind: SignInStep.Authentication,
        endpoint,
        resultCallback,
        error: null,
        loading: true,
        oauthState: {
          state: csrfToken,
          endpoint,
          onAuthCompleted: resolve,
          onAuthError: reject,
        },
      })
      shell.openExternal(getOAuthAuthorizationURL(endpoint, csrfToken))
    })

export function getOAuthAuthorizationURL(
  endpoint: string,
  state: string
): string {
  const urlBase = getHTMLURL(endpoint)
  const scope = encodeURIComponent(oauthScopes.join(' '))

  return new window.URL(

    urlBase
  ).toString()

export async function requestOAuthToken(
  endpoint: string,
  code: string
): Promise<string | null> {
  try {
    const urlBase = getHTMLURL(endpoint)
    const response = await request(
      urlBase,
      null,
      'POST',
      'login/oauth/access_token',
      {
        client_id: ClientID,
        client_secret: ClientSecret,
        code: code,
      }
    )
    tryUpdateEndpointVersionFromResponse(endpoint, response)

    const result = await parsedResponse<IAPIAccessToken>(response)
    return result.access_token
  } catch (e) {
    log.warn(`requestOAuthToken: failed with endpoint ${endpoint}`, e)
    return null
  }
}
