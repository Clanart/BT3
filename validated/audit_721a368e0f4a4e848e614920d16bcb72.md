## Finding: Agave Analog of the VUSD "silently‑lost withdrawal" bug — Epoch inflation rewards for stake accounts closed during the multi‑block distribution window are permanently burned instead of retried

### Title
Calculated stake rewards are permanently burned (never paid, never retried) if the stake account is closed before its partition's distribution block - ([File: `runtime/src/bank/partitioned_epoch_rewards/distribution.rs`])

### Summary
The Sherlock report describes a pattern where a legitimately owed payout (`VUSD#processWithdrawals`) that fails to be delivered is simply logged via an event and then dropped forever, with no retry mechanism. Agave's partitioned epoch-rewards distribution path has the same structural defect: once a stake account's reward is *calculated* (at the reward-calculation boundary), the actual credit is deferred and spread across many subsequent blocks (`distribute_partitioned_epoch_rewards`). If, by the time a given stake account's partition is processed, the account can no longer be loaded (e.g., it was closed via `Withdraw` in the intervening blocks), `build_updated_stake_reward` returns `DistributionError::AccountNotFound`, and `store_stake_accounts_in_partition` responds by logging an `error!` and adding the reward to `stake_reward_lamports_burned` — the calculated reward is discarded with no retry or fallback payment path.

### Finding Description
Reward distribution happens in two phases:
1. **Calculation** — `redeem_delegation_rewards` in `runtime/src/bank/partitioned_epoch_rewards/calculation.rs` computes each stake account's reward and reserves the lamports out of the epoch's inflation budget.
2. **Distribution** — spread over many blocks via `distribute_partitioned_epoch_rewards` (`runtime/src/bank/partitioned_epoch_rewards/distribution.rs:80-171`), which processes one partition of `partition_indices` per block over `distribution_end_exclusive - distribution_starting_block_height` blocks. [1](#0-0) 

The actual crediting for a given stake account can therefore happen many blocks after the reward was calculated. When its partition's block arrives, `store_stake_accounts_in_partition` looks the account up in the live `stakes_cache` and calls `build_updated_stake_reward`: [2](#0-1) 

If the stake account cannot be found (for example the staker fully withdrew/deactivated-and-closed the account in a block between the calculation boundary and its partition's distribution block), the function returns `Err(DistributionError::AccountNotFound)`: [3](#0-2) 

`store_stake_accounts_in_partition` handles this exactly like the VUSD pattern — emit a diagnostic and move on, permanently discarding the payment: [4](#0-3) 

The code comment directly above this loop states the expectation that this path should be unreachable in normal operation: [5](#0-4) 

but the `Err(DistributionError::AccountNotFound)` branch exists specifically to handle the case where that assumption is violated — i.e., the account really was removed from the stakes cache/store between calculation and the account's specific partition block. This is exactly the scenario the withdrawal-loss bug class describes: a reward that was already computed/reserved fails to be delivered to its rightful owner, and instead of being cached for retry or redirected back to the recipient by another means, it is unconditionally burned (`stake_reward_lamports_burned`), reducing what is actually paid out versus what was promised by `point_value.rewards`.

The analogous commission-account payout path (`load_and_reward_commission_accounts` in `calculation.rs`) has the same "on failure, burn and move on" structure, but it is explicitly documented and tested as intentional per SIMD-0232 (see `test_invalid_inflation_rewards_collector_burns_sysvar_rewards`), whereas the stake-account `AccountNotFound` path in `distribution.rs` is presented as an unexpected/should-never-happen edge case with no compensating retry logic — i.e., an unhandled failure mode rather than a designed one.

### Impact Explanation
Any staker can unprivilegedly trigger the loss of their own already-computed reward by closing (fully withdrawing) their stake account during the multi-block reward-distribution window, before their specific partition's block is reached. There is no mechanism to re-credit, re-queue, or otherwise recover the burned lamports; the reward is gone permanently, exactly mirroring the "funds lost forever" impact of the reported VUSD bug. While self-inflicted rather than a theft from a third party, it is a genuine and non-recoverable loss of value legitimately owed to the account under the protocol's own accounting (`point_value.rewards`), and it silently reduces total lamports actually distributed relative to what the inflation schedule computed.

### Likelihood Explanation
This requires no privileged access, malicious validator, or trusted process — any holder of stake can trigger it by issuing a normal `Withdraw`/deactivate-then-close sequence against their own stake account timed to land within the reward-distribution block window (which can span many blocks depending on `num_partitions`). It is a low-effort, self-serviceable action, though the resulting loss only affects the actor's own reward (no cross-account theft), which somewhat limits severity but does not eliminate the fund-loss impact.

### Recommendation
Rather than unconditionally burning the reward on `AccountNotFound` (or any other `DistributionError`), either:
- Detect stake-account closures at reward-calculation time and exclude/adjust affected entries before committing to the point-value-based budget, or
- Redirect the un-deliverable reward lamports to a well-defined fallback (e.g., leave them in the epoch-rewards sysvar / incinerator with an accounting entry that is explicitly reconciled) instead of silently classifying them as "burned" via a path documented as "should never happen".

### Proof of Concept
1. Enter an epoch's reward-calculation phase; `redeem_delegation_rewards` computes a positive `stake_reward` for stake account `S`, and it is included in `all_stake_rewards`/`partition_indices` as done in `distribute_partitioned_epoch_rewards`.
2. Before the block height corresponding to `S`'s partition index is reached (`distribution_starting_block_height + partition_index`), submit a transaction that deactivates and fully withdraws `S`, removing it from `stakes_cache`.
3. When `S`'s partition block arrives, `store_stake_accounts_in_partition` calls `build_updated_stake_reward`, which returns `Err(DistributionError::AccountNotFound)` because `stakes_cache_accounts.get(&S)` is `None` (see `runtime/src/bank/partitioned_epoch_rewards/distribution.rs:249-252`).
4. The `match` in `store_stake_accounts_in_partition` (`runtime/src/bank/partitioned_epoch_rewards/distribution.rs:393-407`) logs the failure and adds `stake_reward_amount` to `stake_reward_lamports_burned` — the reward that was calculated for `S` is never paid to any account and cannot be retried.     fn store_stake_accounts_in_partition(
        &self,
        partition_rewards: &StartBlockHeightAndPartitionedRewards,
        partition_index: u64,
    ) -> DistributionResults {
        let feature_snapshot = self.feature_set.snapshot();
        // Name intentionally doesn't match -- "adjust delegations for rent" is
        // part of relaxing post-exec min balance checks.
        let adjust_delegations_for_rent = feature_snapshot.relax_post_exec_min_balance_check;
        let use_fixed_point_stake_math = feature_snapshot.upgrade_bpf_stake_program_to_v5_1;

        let mut stake_reward_lamports_minted = 0;
        let mut stake_reward_lamports_burned = 0;
        let mut block_reward_lamports_distributed = 0;
        let mut block_reward_lamports_burned = 0;
        let indices = partition_rewards
            .partition_indices
            .get(partition_index as usize)
            .unwrap_or_else(|| {
                panic!(
                    "partition index out of bound: {partition_index} >= {}",
                    partition_rewards.partition_indices.len()
                )
            });
        let mut updated_stake_rewards = Vec::with_capacity(indices.len());
        let stakes_cache = self.stakes_cache.stakes();
        let stakes_cache_accounts = stakes_cache.stake_delegations();
        let stake_history = stakes_cache.history();
        let new_warmup_cooldown_rate_epoch = self.new_warmup_cooldown_rate_epoch();
        let rent = &self.rent_collector.rent;
        for index in indices {
            let partitioned_stake_reward = partition_rewards
                .all_stake_rewards
                .get(*index)
                .unwrap_or_else(|| {
                    panic!(
                        "partition reward out of bound: {index} >= {}",
                        partition_rewards.all_stake_rewards.total_len()
                    )
                })
                .as_ref()
                .unwrap_or_else(|| {
                    panic!("partition reward {index} is empty");
                });
            let stake_pubkey = partitioned_stake_reward.stake_pubkey;
            let stake_reward_amount = partitioned_stake_reward.inflation.stake_reward;
            let block_reward_amount = partitioned_stake_reward.block_reward;

            match Self::build_updated_stake_reward(
                self.epoch,
                stake_history,
                new_warmup_cooldown_rate_epoch,
                stakes_cache_accounts,
                partitioned_stake_reward,
                rent,
                adjust_delegations_for_rent,
                use_fixed_point_stake_math,
            ) {
                Ok(stake_reward) => {
                    stake_reward_lamports_minted += stake_reward_amount;
                    block_reward_lamports_distributed += block_reward_amount;
                    updated_stake_rewards.push(stake_reward);
                }
                Err(err) => {
                    error!(
                        "bank::distribution::store_stake_accounts_in_partition() failed for \
                         {stake_pubkey}, {stake_reward_amount} lamports burned: {err:?}"
                    );
                    stake_reward_lamports_burned += stake_reward_amount;
                    block_reward_lamports_burned += block_reward_amount;
                }
            }
        }
        drop(stakes_cache);
        self.store_accounts(
            (self.slot(), &updated_stake_rewards[..]),
            // Reuse the rewards calculation thread pool to parallelize
            // loading the previous versions of the stake accounts.
            Some(crate::bank::rewards_calculation_thread_pool()),
        );
        DistributionResults {
            stake_reward_lamports_minted,
            stake_reward_lamports_burned,
            block_reward_lamports_distributed,
            block_reward_lamports_burned,
            updated_stake_rewards,
        }
    }
