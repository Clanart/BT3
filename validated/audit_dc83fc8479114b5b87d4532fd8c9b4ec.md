### Title
Reward attribution in `pallet-consensus-incentives::on_executed` credits whichever consensus message occupies batch index 0, letting an unprivileged caller divert treasury-funded relayer rewards to an arbitrary key - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet-ismp`'s `handle_unsigned` extrinsic is fully permissionless and unsigned: any caller can submit an arbitrary, arbitrarily-ordered `Vec<Message>` batch, and `Pallet::execute` processes every message in the batch and hands the whole batch plus the union of resulting events to `FeeHandler::on_executed` in one call. [1](#0-0) [2](#0-1) 

`pallet-consensus-incentives::on_executed` determines *who gets paid* for every `StateMachineUpdated` event in that entire batch by looking at only `messages.get(0)`, recovering a signer from whatever `Message::Consensus` happens to sit at index 0, and then paying that single recovered account the reward for **every** state-machine advance found anywhere in the batch's event list: [3](#0-2) 

### Finding Description
The reward-attribution logic never checks that the message at index 0 is the message that actually produced a given `StateMachineUpdated` event - it only checks that index 0 *is a* `Message::Consensus` at all:

```rust
let maybe_relayer_account = messages.get(0).and_then(|first_message| {
    if let Message::Consensus(consensus_msg) = &first_message.message {
        ...recover pubkey from consensus_msg.signer...
    } else { None }
});
``` [4](#0-3) 

Because `handle_unsigned` takes the message vector verbatim from any unsigned caller and simply concatenates the resulting events across the whole batch, the mapping between "who submitted the proof that advanced state machine X" and "who gets paid for advancing state machine X" is broken as soon as a batch contains more than one `Message::Consensus`, or a `Message::Consensus` followed by unrelated messages that still cause a `StateMachineUpdated` event via a different consensus client instance in the same call. The pallet's own `process_message`/`calculate_reward` correctly guards against re-paying the *same* block span twice (via the `LastRewardedHeight` watermark), but that protection only stops double-payment for the same span - it does nothing to ensure the payee is the party whose proof actually did the work. [5](#0-4) 

The extrinsic itself is intentionally open to anyone with no signature requirement:
```rust
pub fn handle_unsigned(origin: OriginFor<T>, messages: Vec<Message>) -> DispatchResultWithPostInfo {
    ensure_none(origin)?;
    Self::execute(messages.clone())?;
    Ok(().into())
}
``` [1](#0-0) 

so the attacker controls the full ordering of `messages` in their own call. Any batch containing a cheap/self-signed `Message::Consensus` at position 0 (e.g., a resubmission of an already-verified proof that is accepted as a valid `Message::Consensus` variant but advances nothing new) followed by any other `Message::Consensus` for a *different* consensus client/state machine that does advance state, causes the entire reward for that second update to be paid to the index-0 signer instead of whoever built/owns the second proof.

### Impact Explanation
This is a direct "wrong beneficiary" fund-movement bug against the `TreasuryAccount`: BRIDGE/native treasury funds intended to compensate the relayer who actually delivered a state-advancing consensus proof are instead transferred, via `T::Currency::transfer`, to an account chosen solely by whoever crafted the message ordering of the unsigned extrinsic. [6](#0-5) 
Reputation-asset minting (`T::ReputationAsset::mint_into`) is likewise misattributed. This falls squarely under "relayer rewards ... must move exactly once and only to the rightful beneficiary" from the bounty scope, and it is reachable purely through the public, unsigned `handle_unsigned` entrypoint - no relayer collusion, prover compromise, or governance action is required.

### Likelihood Explanation
`handle_unsigned` is explicitly documented as usable "for free" by anyone with a valid proof, and its `ValidateUnsigned::validate_unsigned` implementation only checks proof/message validity and de-duplication tags - it does not constrain message ordering or the relationship between message index and which state machine each message updates. [7](#0-6) 
Any party capable of assembling two independently-valid `Message::Consensus` payloads (which is inherent to being a relayer at all, and does not require secret keys or privileged access) can trigger the misattribution deterministically; no race condition against a third party's transaction is required if the attacker submits two of their own consensus updates for different tracked state machines in one batch and only the second is meant to be attributed to a different treasury payee key, or - more importantly - if the attacker observes any second, already-public, not-yet-submitted valid consensus proof (source-chain data is public, not secret) and simply places it after their own trivial message in the same `Vec<Message>` they submit.

### Recommendation
Do not derive a single "relayer for the whole batch" from `messages[0]`. Instead, pair each `IsmpEvent::StateMachineUpdated` with the specific `Message::Consensus` in the batch whose processing produced it (e.g., by having `MessageResult::ConsensusMessage` return `(events, message_index)` or by having `execute` zip per-message event slices to the corresponding message before invoking `FeeHandler::on_executed`), and recover the reward signer from that specific message's signature rather than the batch's first entry.

### Proof of Concept
1. Attacker holds a valid `Message::Consensus` proof `A` (self-signed, e.g. a re-submission of a proof already accepted earlier, or trivially-produced from public source-chain data) that produces no new `StateMachineUpdated` event but is still parsed as `Message::Consensus`.
2. Attacker obtains a second, independently valid `Message::Consensus` proof `B` for a tracked state machine that *does* advance the chain's commitment height (this proof is derived from public source-chain header/consensus data - building it requires no secret or privileged relationship).
3. Attacker submits `Ismp::handle_unsigned(None, vec![A, B])`.
4. `Pallet::execute` processes both messages; `B`'s processing yields an `IsmpEvent::StateMachineUpdated` for the advanced state machine. [2](#0-1) 
5. `consensus-incentives::on_executed` reads `messages[0]` (`A`), recovers the attacker's own sr25519 pubkey from `A`'s signer field, and pays the full `(latest_height - baseline) * block_cost` reward for the update produced by `B` to the attacker's account, along with minting reputation to the attacker. [8](#0-7) 
6. The rightful beneficiary of proof `B`'s work (whoever built/owns it) receives nothing.

This part of the exploit was confirmed directly from code; I was not able to fully verify within the remaining budget whether other FeeHandler consumers in the runtime (e.g., `parachain/runtimes/*`) impose additional filtering on `handle_unsigned` batches that might restrict multi-`Message::Consensus` batches in production - `nexus`'s `IsmpCallFilter` only rejects batches containing a BEEFY consensus message outright, not multi-message batches with a leading decoy, so this restriction does not close the gap for other consensus clients. [9](#0-8)

		let host = Pallet::<T>::default();

		let message_results = messages
			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		let messages_with_weights = message_results
			.iter()
			.zip(messages)
			.map(|(result, message)| MessageWithWeight { message, weight: result.weight() })
			.collect::<Vec<_>>();

		let events = message_results
			.into_iter()
			// check that requests will be successfully dispatched
			// so we can not be spammed with failing txs
			.map(|result| match result {

				MessageResult::Response { events, .. } |

				MessageResult::ConsensusMessage(events) => events.into_iter().map(Ok).collect(),

			})?;

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}

/// Allowing raw updates through `handle_unsigned` would bypass that requirement entirely, so
/// any batch that carries a BEEFY consensus message is rejected here. `fund_message` is also
/// disabled because it will change the child trie root allowing beefy proofs that have no economic
/// value
///
/// A consensus message only names the state it updates, so we ask the host which client owns
/// that state and compare against BEEFY. Reading from the host remains correct even as more
/// states (Polkadot, Paseo) are bound to the same client over time.
pub struct IsmpCallFilter;
impl Contains<RuntimeCall> for IsmpCallFilter {
	fn contains(call: &RuntimeCall) -> bool {
		use ::ismp::{host::IsmpHost, messaging::Message};
		match call {
			RuntimeCall::Ismp(pallet_ismp::Call::fund_message { .. }) => false,
			RuntimeCall::Ismp(pallet_ismp::Call::handle_unsigned { messages }) => {
				let host = Ismp::default();
				!messages.iter().any(|message| match message {
					Message::Consensus(consensus) =>
						host.consensus_client_id(consensus.consensus_state_id) ==
							Some(ismp_beefy::BEEFY_CONSENSUS_ID),
					_ => false,
				})
			},
			_ => true,
		}
	}
}
