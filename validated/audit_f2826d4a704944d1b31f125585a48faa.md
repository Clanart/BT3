### Title
Governance can set `kip71.gastarget` to 0, causing a division-by-zero panic in the KIP-71 base fee calculation - ([File: params/kip71_config.go])

### Summary
The `kip71.gastarget` governance parameter has no lower-bound (or non-zero) validation anywhere in the vote/param pipeline. A governance council member can vote to set `GasTarget = 0`, which is accepted by `NewVoteData`/`checkConsistency`, becomes an active parameter, and is then used as a divisor in `KIP71Config.NextMagmaBlockBaseFee`, causing a `big.Int` division-by-zero panic on every node that computes the next block's base fee — deterministically halting the chain.

### Finding Description
`Kip71GasTarget`'s `FormatChecker` is a no-op that accepts any `uint64`, including `0`: [1](#0-0) 

When a council member casts a `kip71.gastarget` vote, `checkConsistency` in the header governance module performs no additional bound checking for this parameter — it is explicitly grouped with parameters that "are valid as long as it passes the format checks in NewVoteData()": [2](#0-1) 

Unlike `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee`, which have explicit cross-parameter consistency checks (`ErrLowerBoundBaseFee`/`ErrUpperBoundBaseFee`): [3](#0-2) 

`GasTarget` is used directly as a divisor in `NextMagmaBlockBaseFee` in both the "gas used above target" and "gas used below target" branches: [4](#0-3) 

If `GasTarget == 0`, then for any block where `parentGasUsed > 0` (i.e., essentially any normal block), the code enters the `parentGasUsed > gasTarget` branch and executes `x.Div(x, new(big.Int).SetUint64(gasTarget))` with a zero divisor. Go's `math/big.Int.Div` panics on division by zero. This is the same bug class as the reported AMM issue: an unbounded governance/admin-controlled coefficient (there, `emaAlpha`; here, `GasTarget`) is used unchecked as an input to a mathematical operation (there, `wln()` producing out-of-range/negative values; here, integer division producing a runtime panic) that the rest of the system assumes is always within a safe range.

Note: the `BaseFeeDenominator` parameter *does* have a `!= 0` check (`Kip71BaseFeeDenominator` FormatChecker at `kaiax/gov/param.go`), and the code even defensively substitutes `64` if `BaseFeeDenominator == 0` inside `NextMagmaBlockBaseFee`, showing the developers were aware of this exact class of division-by-zero risk — but the same defensive treatment was not applied to `GasTarget`.

### Impact Explanation
`NextMagmaBlockBaseFee` is called during header validation/verification and block assembly (Magma/KIP-71 base-fee computation) on every node processing a block after the parameter takes effect at the epoch boundary. Because all honest nodes compute this deterministically, all of them panic simultaneously — this is a full network chain-halt / denial-of-service triggered by a single governance parameter update, not merely a local resource issue. This satisfies the "state divergence between honest nodes" / "acceptance of invalid state" impact bar because it produces a hard node crash across the network rather than resource exhaustion of a single participant.

### Likelihood Explanation
Any current validator/council member with voting rights can cast this single header vote (`kip71.gastarget = 0`); no special privilege beyond ordinary governance voting rights (already an explicitly in-scope category per the rules) is required, and no existing validation rejects the value. Once the vote is included and reaches the next epoch's effective parameter set, the very next block with nonzero gas usage triggers the panic on all nodes.

### Recommendation
Add a `FormatChecker` for `Kip71GasTarget` that rejects `0` (and ideally enforces `0 < GasTarget <= MaxBlockGasUsedForBaseFee`), analogous to the existing `Kip71BaseFeeDenominator` check. Additionally, add defensive handling in `NextMagmaBlockBaseFee` (similar to the existing `BaseFeeDenominator == 0` fallback) so that a zero `GasTarget` cannot cause a panic even if it slips through governance validation.

### Proof of Concept
1. A council member submits a header vote: `NewVoteData(voterAddr, "kip71.gastarget", uint64(0))`. This passes `NewVoteData`/`FormatChecker` (no-op) and `checkConsistency` (no cross-check for this param).
2. At the next epoch boundary, `GovModule.GetParamSet` returns `GasTarget = 0` as the active parameter.
3. On the next block where `parentHeaderGasUsed > 0` (essentially guaranteed), `NextMagmaBlockBaseFee` executes the `parentGasUsed > gasTarget` branch:
   `y := x.Div(x, new(big.Int).SetUint64(gasTarget))` with `gasTarget = 0`.
4. `big.Int.Div` panics on division by zero, crashing every node that validates or assembles that block — chain halt.
