### Title
Flash-voting into `BribeRewardPool` to skim freshly-harvested bribe rewards without holding-period exposure - (File: `wombat/WombatBribeManager.sol`, `rewards/BribeRewardPool.sol`)

### Summary
`WombatBribeManager.vote()` immediately calls `IBribeRewardPool(pool.rewarder).stakeFor()`, crediting the caller's virtual stake in the target `BribeRewardPool` before any actual Wombat vote/harvest occurs. Because `castVotes()` distributes newly harvested bribe rewards pro-rata over `totalStaked()` at harvest time, and `unvote()`/negative `vote()` let the caller immediately withdraw (with reward `claim=true`), an attacker can vote right before `castVotes()`'s `queueNewRewards` call and unvote right after, capturing a full pro-rata share of the harvest despite zero holding-period exposure.

### Finding Description
- `vote()` (`wombat/WombatBribeManager.sol:182-220`) increases `pool.totalVoteInVlmgp` and calls `IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, uint256(delta))` synchronously, with no cooldown or minimum holding time.
- `stakeFor` (`rewards/BribeRewardPool.sol:57-67`) runs the `updateRewards(_for, rewardTokens)` modifier (from `rewards/BaseRewardPoolV2.sol:107-120`) which snapshots `userRewardPerTokenPaid` at the current `rewardPerToken`, then immediately increases `totalSupply`/`_balances[_for]` — the attacker's balance is fully "live" for the very next reward distribution.
- `castVotes()` (`wombat/WombatBribeManager.sol:241-296`), callable by anyone, triggers `WombatStaking.vote()` (`wombat/WombatStaking.sol:363-418`), which calls `IBaseRewardPool(_rewarders[i]).queueNewRewards(rewardAmount, token)`. This increments `rewardPerTokenStored` proportionally to `totalStaked()` at that instant (`rewards/BaseRewardPoolV2.sol:301-313`) — a value that already includes the attacker's just-added stake.
- Immediately after, the attacker calls `unvote()` (`wombat/WombatBribeManager.sol:223-237`) or `vote()` with a negative delta, which calls `withdrawFor(msg.sender, amount, true)` (`rewards/BribeRewardPool.sol:72-85`). The `updateRewards` modifier computes `_earned()` using the post-harvest `rewardPerToken`, crediting the attacker's full pro-rata share of the just-queued reward, and `claim=true` immediately transfers it out via `_getReward`.
- No code path enforces a minimum staking duration, vesting, or time-weighted average balance for reward eligibility — `earned()`/`_earned()` (`rewards/BaseRewardPoolV2.sol:316-321`) is a pure function of current balance and `rewardPerToken` delta, independent of when the balance was set. This is the root cause: reward entitlement is snapshot-based, not duration-based.

### Impact Explanation
This is theft of unclaimed yield from long-term voters: pro-rata dilution of the harvested bribe reward pool. Every unit of vlMGP an attacker flash-votes with immediately before a harvest and withdraws immediately after siphons a proportional share of that harvest away from voters who actually held the position through the period the bribes were earned. This matches the "theft of unclaimed yield" impact class from the audit scope.

### Likelihood Explanation
- Requires only unprivileged capability: holding already-locked vlMGP (a normal user precondition, `getUserVotable()` in `wombat/WombatBribeManager.sol:102-104`), and calling public functions `vote`, `castVotes` (or front-running someone else's `castVotes`), and `unvote`/`vote` with negative delta.
- `castVotes()` is public and can be predicted/front-run in the mempool, or the attacker can simply be the one calling it (`voteAndCast` even bundles vote+cast in one call, `wombat/WombatBribeManager.sol:315-322`), making it trivially repeatable every harvest cycle for any pool with meaningful bribes.
- No reentrancy or time-lock guard blocks this sequence.

### Recommendation
Introduce a duration-weighted reward accounting mechanism (e.g., checkpoint balances by time, require a minimum staking period before a stake counts toward `queueNewRewards` distribution) or enforce a lock/cooldown between `vote()` and `unvote()`/negative `vote()` (e.g., disallow unvoting or reducing a vote within the same block/epoch as the last `castVotes()`, or require unvote calls to only affect balances credited from `updateRewards` calls prior to the last harvest). Alternatively, snapshot `totalStaked()` used in `queueNewRewards` at the start of the voting epoch rather than at harvest time so late stakers can't dilute rewards they didn't help earn.

### Proof of Concept

1. Deploy `WombatBribeManager`, `WombatStaking`, `BribeRewardPool` (or use existing test fixtures), configure one active pool with a bribe reward token.
2. Set up "Voter A" (long-term holder) who locks vlMGP and calls `vote()` on the pool well before any harvest, and leaves the position staked.
3. Simulate a bribe becoming claimable in the underlying Wombat voter/bribe contract for that pool.
4. In the same test, have "Attacker" (freshly locked vlMGP, no prior exposure) call `vote()` on the same pool for a non-trivial delta, immediately followed (same block or next block) by `castVotes()` (attacker can call this itself), then immediately call `unvote()`.

   - `BribeRewardPool.earned(attacker, rewardToken) > 0` after `unvote()`'s internal reward computation (or check reward token balance transferred to attacker via `withdrawFor(..., true)`).

        if (_lps.length != _deltas.length)
            revert LengthMismatch();

        uint256 length = _lps.length;
        int256 totalUserVote;

        for (uint256 i; i < length; i++) {
            Pool storage pool = poolInfos[_lps[i]];
            if (!pool.isActive)
                revert PoolNotActive();
            int256 delta = _deltas[i];
            totalUserVote += delta;
            if (delta != 0) {
                if (delta > 0) {
                    pool.totalVoteInVlmgp += uint256(delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] += uint256(delta);
                    IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, uint256(delta));
                } else {
                    pool.totalVoteInVlmgp -= uint256(-delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] -= uint256(-delta);
                    IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(-delta), false);
                }
            }
        }

        if (msg.sender != delegatedPool) {
            if (totalUserVote > 0) {
                userTotalVotedInVlmgp[msg.sender] += uint256(totalUserVote);
                totalVlMgpInVote += uint256(totalUserVote);

                userTotalVotedInVlmgp[msg.sender] -= uint256(-totalUserVote);
                totalVlMgpInVote -= uint256(-totalUserVote);
            }
        }

    /// @notice Unvote from an inactive pool. This makes it so that deleting a pool, or changing a rewarder doesn't block users from withdrawing
    function unvote(address _lp) public {
        Pool storage pool = poolInfos[_lp];
        uint256 currentVote = userVotedForPoolInVlmgp[msg.sender][pool.poolAddress];
        if(!pool.isActive)
            revert PoolNotActive();
        
        pool.totalVoteInVlmgp -= uint256(currentVote);
        userTotalVotedInVlmgp[msg.sender] -= uint256(currentVote);
        userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] = 0;
        if (msg.sender != delegatedPool) {
            totalVlMgpInVote -= currentVote;
        }
        
        IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(currentVote), true);
    }

    function stakeFor(address _for, uint256 _amount)
        external
        virtual
        onlyOperator
        updateRewards(_for, rewardTokens)
    {
        totalSupply = totalSupply + _amount;
        _balances[_for] = _balances[_for] + _amount;

        emit Staked(_for, _amount);
    }

    /// @notice Updates informaiton for a user in case of a withdraw. Can only be called by the Masterchief operator
    /// @param _for Address account
    /// @param _amount Amount of withdrawed tokens by the user on masterchief
    function withdrawFor(
        address _for,
        uint256 _amount,
        bool claim
    ) external virtual onlyOperator updateRewards(_for, rewardTokens) {
        totalSupply = totalSupply - _amount;
        _balances[_for] = _balances[_for] - _amount;

        emit Withdrawn(_for, _amount);

        if (claim) {
            _getReward(_for);
        }
    }

    modifier updateRewards(address _account, address[] memory _rewards) {
        uint256 length = _rewards.length;
        uint256 userShare = balanceOf(_account);
        
        for (uint256 index = 0; index < length; ++index) {
            address rewardToken = _rewards[index];
            // if a reward stopped queuing, no need to recalculate to save gas fee
            if (userRewardPerTokenPaid[rewardToken][_account] == rewardPerToken(rewardToken))
                continue;
            userRewards[rewardToken][_account] = _earned(_account, rewardToken, userShare);
            userRewardPerTokenPaid[rewardToken][_account] = rewardPerToken(rewardToken);
        }
        _;
    }
