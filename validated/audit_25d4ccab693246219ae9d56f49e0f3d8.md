### Title
Unhandled UnicodeDecodeError in DID metadata parsing crashes wallet sync on malformed on-chain metadata - (File: chia/wallet/did_wallet/did_wallet_puzzles.py)

### Summary
`did_program_to_metadata()` decodes every key/value pair of a DID's on-chain metadata as UTF-8 with no validation or exception handling. Any coin creator can curry a DID inner puzzle with metadata containing non-UTF-8 byte strings; when a wallet syncs and processes that DID coin, the raw `UnicodeDecodeError` propagates unhandled through the wallet coin-processing pipeline. This mirrors the CVE-2020-35652 bug class: an unvalidated, attacker-controlled structured field (there, a `tel-uri` in a SIP header; here, a metadata value in a CLVM program) that is blindly decoded/parsed and crashes the receiving process instead of being rejected gracefully.

### Finding Description
`did_program_to_metadata()` iterates the metadata program's key/value pairs and force-decodes both as UTF-8 without a `try/except`: [1](#0-0) 

This metadata comes directly from the curried DID puzzle, which is fully attacker-controlled — any coin spend can curry `DID_INNERPUZ_MOD` with arbitrary bytes as the `metadata` parameter, and any counterparty (or malicious sender doing a DID transfer/gift) can cause such a coin to be created and hinted to a victim wallet.

`did_program_to_metadata()` is invoked, without any surrounding exception handling for `UnicodeDecodeError`, at multiple points reached automatically during normal wallet sync:
- `DIDWallet.create_new_did_wallet_from_coin_spend()` (auto-creation of a new DID wallet when a DID is received): [2](#0-1) 
- `DIDWallet.coin_added()` (invoked every time a tracked DID coin is added, from `WalletStateManager.coin_added()`): [3](#0-2) 
- `WalletStateManager.find_lost_did()` metadata update path: [4](#0-3) 

These call sites are reached through `WalletStateManager.determine_coin_type()` → `DIDWallet.identify()` → `create_new_did_wallet_from_coin_spend()`, which runs as part of ordinary coin-state processing for any coin hinted to the wallet: [5](#0-4)  and `coin_added()` is called from the wallet's coin-processing routine on every new coin: [6](#0-5) 

Because none of these paths catch `UnicodeDecodeError`, a single malicious/malformed DID coin observed during sync raises an unhandled exception inside the wallet's coin-processing flow.

### Impact Explanation
An unhandled exception during coin processing in the wallet sync path is a spend-triggered halt of transaction/coin processing for the affected wallet: any wallet that becomes aware of (or is hinted) such a malformed DID coin will fail while trying to record it, potentially repeatedly on resync, blocking normal coin/balance state updates for that wallet until manually recovered. This matches the "spend-triggered transaction-processing halt" impact category called out in the validation rules, analogous to the crash-on-malformed-field bug class of CVE-2020-35652.

### Likelihood Explanation
Likelihood is high for any actor able to spend a coin to create/transfer a DID: metadata is fully attacker-chosen CLVM data (arbitrary bytes), and it requires no special privilege — just a normal DID launch/transfer spend with non-UTF-8 bytes in a metadata value, sent/hinted to any wallet that syncs DID coins.

### Recommendation
Wrap the decode logic in `did_program_to_metadata()` in a try/except (catching `UnicodeDecodeError`/`ValueError`) and skip or replace undecodable entries (mirroring how `compute_memos`/`compute_memos_for_spend` gracefully skip malformed memo entries: [7](#0-6) ), or store raw bytes with a fallback representation instead of raising, so a malformed DID coin cannot abort wallet coin processing.

### Proof of Concept
1. Curry `DID_INNERPUZ_MOD` with a metadata program `Program.to([("k", b"\xff\xfe")])` (or any non-UTF-8 byte string) as the metadata parameter, and create/launch (or transfer) a DID coin with this puzzle, hinting it to a target wallet's puzzle hash.
2. The victim wallet syncs and observes the new coin; `WalletStateManager.determine_coin_type()`/`coin_added()` routes it to `DIDWallet.identify()`/`create_new_did_wallet_from_coin_spend()` or `DIDWallet.coin_added()`.
3. `did_program_to_metadata(metadata)` executes `str(val, "utf-8")` on `b"\xfe"`-style bytes and raises `UnicodeDecodeError`, unhandled, aborting the wallet's coin-processing call for that update.

```python
def did_program_to_metadata(program: Program) -> dict[str, str]:
    """
    Convert a program to a metadata dict
    :param program: Chialisp program contains the metadata
    :return: Metadata dict
    """
    metadata = {}
    for key, val in program.as_python():
        metadata[str(key, "utf-8")] = str(val, "utf-8")
    return metadata
```

```python
def compute_memos_for_spend(coin_spend: CoinSpend) -> dict[bytes32, list[bytes]]:
    _, result = run_with_cost(coin_spend.puzzle_reveal, INFINITE_COST, coin_spend.solution)
    memos: dict[bytes32, list[bytes]] = {}
    for condition in result.as_python():
        if condition[0] == ConditionOpcode.CREATE_COIN and len(condition) >= 4:
            # If only 3 elements (opcode + 2 args), there is no memo, this is ph, amount
            coin_added = Coin(coin_spend.coin.name(), bytes32(condition[1]), uint64(int_from_bytes(condition[2])))
            if type(condition[3]) is not list:
                # If it's not a list, it's not the correct format
                continue
            memos[coin_added.name()] = [mem for mem in condition[3] if isinstance(mem, bytes)]
    return memos
```
