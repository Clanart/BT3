### Title
Attacker can DOS the gasless bundle queue for all users by flooding it with cheap approve/swap transactions from many addresses - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The gasless module admits any KIP-247 `GaslessApproveTx`/`GaslessSwapTx` into a single, **global** counter (`knownTxs.numQueue()`) gated only by `MaxBundleTxsInQueue` (default 200), with no per-sender quota. Any unprivileged transaction sender who can construct a valid-looking approve/swap pair for a whitelisted token can occupy queue slots until the global cap is reached, causing legitimate users' gasless bundle transactions to be rejected with `ErrBundleTxQueueFull`, exactly analogous to the OpenQ bug where an attacker fills a shared, size-limited list (there: `tokenAddresses`, here: the gasless `knownTxs` queue) to block legitimate use by others.

### Finding Description
`GaslessModule.PreAddTx` is the sole gate for adding a gasless-classified tx to the shared `knownTxs` map: [1](#0-0) 

It checks `g.knownTxs.numQueue() >= g.GetMaxBundleTxsInQueue()` — a single global count across *all* senders — before allowing a new bundle tx (`IsApproveTx` or `IsSwapTx`) into the queue: [2](#0-1) 

The default limit is 200 (`MaxBundleTxsInQueue`), configurable but with no per-account/per-sender sub-limit: [3](#0-2) [4](#0-3) 

A queued entry only leaves the count after `QueueTimeout` (10s) via `PreReset`, or on promotion timeout: [5](#0-4) 

The classification checks (`isApproveTx`/`isSwapTx`) require only that the token is on the (governance/registry-controlled) `allowedTokens` whitelist and the router/spender match — they do not require the sender to actually hold a balance or approval at admission time (`ShouldCheckToken`/`ShouldCheckSwapAmount` balance checks are done elsewhere, in `GetCheckBalance`, but `PreAddTx`'s queue-slot consumption happens unconditionally for any tx matching the ABI signature and whitelisted addresses): [6](#0-5) 

Because `PreAddTx` runs before/alongside the more expensive balance validation and only enforces the pool-wide numeric cap, an attacker can generate many distinct EOAs (cheap — key generation only), each crafting one valid-format `approve`/`swapForGas` transaction addressed to the whitelisted token/router pair, and continuously resubmit these across the 10-second `QueueTimeout` window to keep the shared queue saturated at `MaxBundleTxsInQueue`. This is directly analogous to the OpenQ report: a shared, globally-limited resource (`tokenAddresses` set there, `knownTxs` queue count here) that any unprivileged caller can populate to block legitimate use by others, since there is no per-actor sub-allocation of the resource.

### Impact Explanation
Once the queue cap is reached, legitimate users' genuine gasless approve/swap transactions are rejected at admission (`ErrBundleTxQueueFull`), denying them fee-delegated ("gasless") transaction service network-wide for as long as the attacker keeps refilling the queue. This is a griefing/DOS on a public-facing feature (gasless transactions) reachable by any transaction sender, matching the "Medium" severity class of the original report (temporary denial of service / griefing on a shared resource, not fund theft).

### Likelihood Explanation
Likelihood is moderate-to-high: the attacker only needs to generate throwaway EOA addresses (no funds strictly required to pass `PreAddTx`'s admission counter check, since the balance/allowance checks are a separate gate from the queue-count gate) and repeatedly submit ABI-matching approve/swap-shaped transactions naming a whitelisted token/router. The 10-second `QueueTimeout` means the attacker must sustain a moderate transaction rate to keep the queue saturated, but this is well within reach of a single unprivileged actor with public RPC access.

### Recommendation
Enforce a per-sender (or per-address-set) sub-limit within `knownTxs`/`PreAddTx`, in addition to the global `MaxBundleTxsInQueue`, so that no single sender (or small set of sender addresses controlled by one actor) can consume a disproportionate share of the shared gasless-bundle queue. Alternatively, require the balance/allowance pre-check (`ShouldCheckToken`) to be satisfied at admission time (not merely at build time) so that non-funded throwaway senders cannot occupy queue slots at all.

### Proof of Concept
1. Attacker enumerates N ≈ `MaxBundleTxsInQueue` (default 200) fresh EOA private keys.
2. For each key, attacker crafts a `GaslessApproveTx` (`approve(spender=whitelisted GaslessSwapRouter, amount=MaxUint256)` to a whitelisted token) or `GaslessSwapTx`, matching the ABI signatures checked by `isApproveTx`/`isSwapTx` (`kaiax/gasless/impl/getter.go:74-103`).
3. Attacker submits all N transactions to the public RPC/txpool; each passes `PreAddTx`'s ABI/whitelist checks and increments `knownTxs.numQueue()` (`kaiax/gasless/impl/tx_pool.go:38-53`, `kaiax/gasless/impl/tx_counter.go:114-122`) until `numQueue() >= MaxBundleTxsInQueue`.
4. A legitimate user submits a real gasless approve/swap transaction; `PreAddTx` returns `ErrBundleTxQueueFull`, and the tx is rejected from becoming a queued bundle candidate.
5. Attacker resubmits fresh throwaway transactions every `QueueTimeout` (10s) window to keep the queue perpetually full, sustaining the DOS on the gasless feature for all other users.

func (g *GaslessModule) PreAddTx(tx *types.Transaction, local bool) error {
	g.knownTxsMu.RLock()
	defer g.knownTxsMu.RUnlock()

	if knownTx, ok := g.knownTxs.get(tx.Hash()); ok && knownTx.elapsedPromotedOrAddedTime() < KnownTxTimeout {
		return ErrUnableToAddKnownBundleTx
	}

	if g.IsBundleTx(tx) {
		if uint(g.knownTxs.numQueue()) >= g.GetMaxBundleTxsInQueue() {
			return ErrBundleTxQueueFull
		}
		g.knownTxs.add(tx, TxStatusQueue)
	}
	return nil
}

// PreReset removes timed out tx from the tx pool and knownTxs.
func (g *GaslessModule) PreReset(oldHead, newHead *types.Header) []common.Hash {
	g.knownTxsMu.Lock()
	defer g.knownTxsMu.Unlock()

	drops := make([]common.Hash, 0)

	for hash, knownTx := range *g.knownTxs {
		// remove pending timed out tx from tx pool
		if knownTx.status == TxStatusPending && knownTx.elapsedPromotedTime() >= PendingTimeout {
			drops = append(drops, hash)
		}
		// remove queue timed out tx from tx pool
		if knownTx.status == TxStatusQueue && knownTx.elapsedAddedTime() >= QueueTimeout {
			drops = append(drops, hash)
		}
		// remove known timed out tx from knownTxs
		if knownTx.elapsedPromotedOrAddedTime() >= KnownTxTimeout {
			g.knownTxs.delete(hash)
		}
	}

	return drops
}

// IsApproveTx checks following conditions:
// A1. tx.to is a whitelisted ERC20 token.
// A2. tx.data is `approve(spender, amount)`.
// A3. spender is a whitelisted SwapRouter contract.
// A4. amount is MaxUint.
func (g *GaslessModule) IsApproveTx(tx *types.Transaction) bool {
	args, ok := decodeApproveTx(tx, g.signer)
	return ok && g.isApproveTx(args)
}

func (g *GaslessModule) isApproveTx(args *ApproveArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.allowedTokens[args.Token] && // A1
		g.swapRouter == args.Spender && // A3
		args.Amount.Cmp(abi.MaxUint256) == 0 // A4
}

// IsSwapTx checks following conditions:
// S1. tx.to is a whitelisted SwapRouter contract.
// S2. tx.data is `swapForGas(token, amountIn, minAmountOut, amountRepay)`.
// S3. token is a whitelisted ERC20 token.
func (g *GaslessModule) IsSwapTx(tx *types.Transaction) bool {
	args, ok := decodeSwapTx(tx, g.signer)
	return ok && g.isSwapTx(args)
}

func (g *GaslessModule) isSwapTx(args *SwapArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.swapRouter == args.Router && // S1
		g.allowedTokens[args.Token] // S3
}
