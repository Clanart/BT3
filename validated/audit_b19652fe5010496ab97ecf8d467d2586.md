## Title
Relayer-fee refund on POST-request timeout goes to caller-supplied `payer`, not the actual fee payer - (File: `evm/src/core/EvmHost.sol`)

## Summary
`EvmHost.dispatch(DispatchPost)` stores an attacker/caller-controlled `post.payer` value as the `FeeMetadata.sender` that later receives the relayer-fee refund when the request times out, while the fee itself is actually collected from `_msgSender()` (or from `msg.value`). Because these two addresses are never required to match, whoever calls `dispatch()` can permanently misdirect the timeout refund away from whoever actually funded the request — the exact "stake/fee returned to wrong address" pattern described in the external report, reproduced natively in Hyperbridge's own POST-request fee-refund path.

## Finding Description
For POST requests, `EvmHost.dispatch` collects the fee from the actual caller and then stores an unrelated, caller-supplied address as the refund recipient: [1](#0-0) 

Specifically:
- Fee is pulled from `_msgSender()` via `safeTransferFrom` (or paid with `msg.value` swapped by the contract itself) — line 931.
- The commitment's `FeeMetadata` is built as `FeeMetadata({sender: post.payer, fee: post.fee})` — line 948 — where `post.payer` is a plain field of the `DispatchPost` struct supplied entirely by the caller, with no check that it equals `_msgSender()` or any actual value source.

Contrast this with the GET-request dispatch path in the very same contract, which correctly derives the refund address from the authenticated caller instead of trusting an arbitrary parameter: [2](#0-1) 

On timeout, the stored `meta.sender` (i.e., the untrusted `post.payer`) is the one credited with the refund: [3](#0-2) 

This is confirmed as a genuinely free-form, un-validated field: other in-repo integrations that build `DispatchPost` set `payer` to whatever suits them (e.g., `BandwidthManager.purchase()` hardcodes `payer: address(this)` even though the manager itself pulled the fee from `msg.sender`): [4](#0-3) 

There is no invariant anywhere in `dispatch(DispatchPost)` binding `post.payer` to the entity that actually supplied the fee. Any unprivileged caller of the public `dispatch()` entrypoint — directly, or via any intermediary/router contract that forwards `payer` from user input — can set `post.payer` to an address of their choosing while the fee is still charged to the genuine payer (`_msgSender()` or the ETH sender). If the request subsequently times out (a routine, expected outcome, not requiring any malicious relayer/prover), the relayer fee is refunded to the attacker-chosen `payer` address rather than to whoever actually funded the dispatch.

This mirrors the root cause of the external report exactly: a fund-return path keys off a party-supplied "beneficiary/receiver" field instead of the party that actually staked/paid, letting the payer's value leak to an unrelated address.

## Impact Explanation
Every POST dispatch through Hyperbridge's core `EvmHost` is exposed: relayer fees (which can be arbitrarily large, unlike the fixed 0.01 ETH stake in the seed report) are refundable to a wrong, attacker-controlled address whenever a request times out. Any integrator contract that (a) pulls a fee from a real payer and (b) forwards a caller-controlled `payer` value into `DispatchPost.payer` (a natural pattern for any multi-tenant relayer/dispatcher wrapper) loses the entire relayer fee to whichever address is passed at dispatch time. This is a direct, protocol-level "funds routed to unauthorized beneficiary" bug in the fee-refund settlement path, which the Hyperbridge Impact Gate explicitly calls in scope ("relayer rewards... must move exactly once and only to the rightful beneficiary").

## Likelihood Explanation
High. `dispatch(DispatchPost)` is a fully public, unprivileged entrypoint on every EVM host deployment; no malicious relayer, prover, or admin is required — only a timeout, which is an ordinary and expected outcome of cross-chain messaging (identical prerequisite class to the original report: "perform withdrawal/refund on behalf of another party"). Any wrapper contract, aggregator, or even a directly-calling EOA that separates "who pays" from "who is credited on timeout" will trigger the loss.

## Recommendation
Do not accept an arbitrary `payer` field for POST dispatch. Either:
- Remove `payer` from `DispatchPost` and always set `FeeMetadata.sender = _msgSender()` (mirroring the GET dispatch path), or
- If a distinct payer is a required feature (e.g. paymaster-style sponsorship), require `post.payer == _msgSender()` unless the caller supplies proof of authorization from the real value source (e.g. an explicit `permit`/allowance/signature binding `payer` to the fee-collection step), so the refund can never be redirected away from whoever actually funded the request.

## Proof of Concept
1. Attacker (or a compromised/careless integrator contract) calls `EvmHost.dispatch(DispatchPost{ dest, to, body, timeout, fee: F, payer: ATTACKER })` while approving/holding `F` fee tokens as `_msgSender()`.
2. `EvmHost.dispatch` pulls `F` fee tokens from `_msgSender()` (line 931) but stores `FeeMetadata({sender: ATTACKER, fee: F})` (line 948).
3. The request is never delivered before `timeoutTimestamp` (ordinary occurrence — network delay, no relayer picks it up, destination reverts, etc.).
4. A timeout proof is submitted; `EvmHost.dispatchTimeOut(PostRequestTimeout, meta, commitment)` runs the app's `onPostRequestTimeout` callback and, on success, executes `IERC20(feeToken()).safeTransfer(meta.sender, meta.fee)` — refunding the fee `F` to `ATTACKER`, not to whoever actually paid it in step 1 (lines 901-904).     function dispatchTimeOut(
        PostRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onPostRequestTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit PostRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function dispatch(DispatchPost memory post) external payable notFrozen returns (bytes32 commitment) {
        if (msg.value > 0) {
            address[] memory path = new address[](2);
            address uniswapV2 = _hostParams.uniswapV2;
            path[0] = IUniswapV2Router02(uniswapV2).WETH();
            path[1] = feeToken();
            IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
                post.fee, path, address(this), block.timestamp
            );
        } else if (post.fee > 0) {
            IERC20(feeToken()).safeTransferFrom(_msgSender(), address(this), post.fee);
        }

        // adjust the timeout
        uint64 timeoutTimestamp = post.timeout == 0 ? 0 : uint64(block.timestamp) + uint64(post.timeout);
        PostRequest memory request = PostRequest({
            source: host(),
            dest: post.dest,
            nonce: uint64(_nextNonce()),
            from: abi.encodePacked(_msgSender()),
            to: post.to,
            timeoutTimestamp: timeoutTimestamp,
            body: post.body
        });

        // make the commitment
        commitment = request.hash();
        _requestCommitments[commitment] = FeeMetadata({sender: post.payer, fee: post.fee});
