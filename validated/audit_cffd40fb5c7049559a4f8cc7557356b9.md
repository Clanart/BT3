### Title
FROST signing accepts identity nonce commitments, letting a signer bypass the binding factor and fully control their nonce contribution - (File: crypto/frost/src/nonce.rs)

### Summary
`Commitments::read` / `GeneratorCommitments::read` in `crypto/frost/src/nonce.rs` accept any canonical point, including the group identity. `AlgorithmSignMachine::sign` in `crypto/frost/src/sign.rs` never rejects identity (or otherwise degenerate) nonce commitments before computing `B.nonces()` and producing a signature share. A malicious participant can submit `(D, E) = (identity, identity)` or `E = identity`, making their effective bound nonce `D + rho * E` a value entirely of their choosing, independent of the binding factor `rho`. This bypasses FROST's core anti-ROS restriction — that every signer's nonce contribution is bound to the transcript and unpredictable — analogous to CVE-2023-2314's "insufficient data validation allows bypassing a restriction on untrusted input."

### Finding Description
In `crypto/frost/src/nonce.rs` lines 34-36, `GeneratorCommitments::read` reads two points via `C::read_G` with no semantic check. `C::read_G` (crypto/ciphersuite/src/lib.rs:91-100) enforces only canonical encoding — it accepts the identity element and any valid point. Nothing downstream validates the commitments either: in `crypto/frost/src/sign.rs` lines 325-359, every preprocess's `commitments` are transcripted and inserted into `B` unconditionally; `BindingFactor::bound` (nonce.rs:180-190) computes `generator.0[0] + generator.0[1] * rho`, and `BindingFactor::nonces` (nonce.rs:194-212) sums these into the group nonce `Rs`.

If a signer submits `E = identity`, their bound nonce contribution is exactly `D` — a value the attacker picked directly, completely unaffected by `rho` and therefore unaffected by the `preprocesses` challenge, the group key, or the message. The binding factor exists specifically so that no signer can pre-commit to a chosen effective nonce; an `identity` second commitment makes that protection a no-op for that signer. If both `D` and `E` are `identity`, the signer contributes `0` to the group nonce.

In Serai's asynchronous preprocess exchange, a signer that sends its preprocess last observes all honest `B` contributions before choosing `D`. With `E = identity`, the attacker can solve for a `D` that places the *group* nonce `R` at any attacker-selected offset relative to the honest contributions, with full knowledge (no hash grinding needed for their own component, since `rho` never applies).

### Impact Explanation
FROST's security against parallel-session (ROS/Wagner-style) forgery relies on each signer's nonce contribution being randomized by a binding factor derived from all commitments and the message. An attacker-controlled signer that neutralizes its own binding factor (`E = identity`) regains the ability to set its nonce contribution adaptively after observing honest preprocesses — the exact precondition for ROS-type attacks across concurrently opened signing sessions. Concretely reachable: any participant in a Serai threshold signing session delivers their preprocess bytes to `read_preprocess` → `Commitments::read` → `sign`, which are the public-input paths in scope. The result is a valid signature over a message/challenge relation the signer influenced through a nonce contribution the protocol intended to forbid, breaking unforgeability assumptions for the multisig (e.g., Bitcoin multisig spends) across parallel sessions.

### Likelihood Explanation
Exploitation requires the attacker to be a participant in a signing set (so their preprocess is accepted) and to run multiple concurrent signing sessions — both normal operating conditions for Serai validators/co-signers. No consensus-level or collusion assumptions are needed; a single rogue signer bypasses the binding for their own contribution. Mounting a full ROS forgery additionally requires the standard parallel-session setup, which the protocol's async design permits.

### Recommendation
In `GeneratorCommitments::read` (crypto/frost/src/nonce.rs:34-36), reject the identity element for both `D` and `E` (e.g., `if bool::from(point.is_identity()) { Err(...) }`). Optionally also check in `AlgorithmSignMachine::sign` that each participant's bound nonce `D + rho*E` is non-identity before computing `Rs`, as a defense-in-depth measure matching FROST's requirement that signers abort on identity commitments.
