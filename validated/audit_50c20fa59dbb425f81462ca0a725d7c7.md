## Analysis

The external report's core invariant — *"never let native value be silently absorbed by a contract path that has no mechanism to return or account for it"* — maps directly onto the WERC20 precompile in this repo.

### The Guard That Exists (and gets bypassed)

The base `erc20.Precompile.Execute` includes exactly the kind of guard recommended in the NestedFactory report: it rejects any call carrying `msg.value > 0` because the ERC20 precompile has no mechanism to refund or account for native value. [1](#0-0) 

However, `werc20.Precompile` overrides `Execute` entirely and, for anything other than `deposit`/`withdraw`/fallback/receive, calls `p.HandleMethod` **directly**, completely bypassing the embedded `erc20.Precompile.Execute` (and therefore its `contract.Value().Sign() == 1` check): [2](#0-1) 

### Root Cause

`transfer`, `transferFrom`, and `approve` on the WERC20 precompile are reached via `HandleMethod` -> `p.transfer`/`p.Approve` in `precompiles/erc20/tx.go`, none of which reference `contract.Value()` at all: [3](#0-2) 

Only `Deposit` actually consumes and forwards `contract.Value()` back to the caller via `BankKeeper.SendCoins`: [4](#0-3) 

Since the standard Solidity-generated ABI for `transfer`/`transferFrom`/`approve` is non-`payable`, a normal contract call can't attach value — but this is only a *compiler-level* restriction. The EVM itself performs the native value transfer at the `CALL` opcode level (crediting the WERC20 precompile's address balance in the StateDB) **before** the precompile's `Run`/`Execute` is even invoked, regardless of which function selector is dispatched. Any caller using a raw/low-level call (e.g., `addr.call{value: x}(abi.encodeWithSelector(IERC20.transfer.selector, ...))`) can attach `msg.value` to a `transfer` call on the WERC20 precompile address.

### Impact

Because `werc20.Execute` skips the `erc20.Execute` guard for these methods, the attached native value:
1. Is credited to the precompile's address balance in the EVM StateDB by the standard call-value-transfer mechanics.
2. Is never touched by `p.transfer`/`p.Approve` (which only move the *tokenPair.Denom* amount via a bank `Send` message).
3. Has no recovery path — the precompile is not an EOA, has no private key, and only `Deposit` contains logic to forward `contract.Value()` back to the sender.

This results in permanent, unrecoverable loss of the user's native token, triggered by an ordinary unprivileged EVM call — matching the report's "permanent freezing/locking of user funds" class, but here specific to the WERC20 precompile's inherited ERC20 methods.

### Recommendation

`werc20.Precompile.Execute` should reject non-zero `contract.Value()` for any method other than `Deposit`/fallback/receive (mirroring the `erc20.Precompile.Execute` guard), e.g. by calling the embedded `erc20.Precompile.Execute` for the `default` branch instead of `HandleMethod` directly, or by adding the same `ErrCannotReceiveFunds` check before dispatching to `HandleMethod`. [5](#0-4)

func (p Precompile) Execute(ctx sdk.Context, stateDB vm.StateDB, contract *vm.Contract, readOnly bool) ([]byte, error) {
	method, args, err := cmn.SetupABI(p.ABI, contract, readOnly, p.IsTransaction)
	if err != nil {
		return nil, err
	}

	var bz []byte

	switch {
	case method.Type == abi.Fallback,
		method.Type == abi.Receive,
		method.Name == DepositMethod:
		bz, err = p.Deposit(ctx, contract, stateDB)
	case method.Name == WithdrawMethod:
		bz, err = p.Withdraw(ctx, contract, stateDB, args)
	default:
		// ERC20 transactions and queries
		bz, err = p.HandleMethod(ctx, contract, stateDB, method, args)
	}

	return bz, err
}

// Deposit handles the payable deposit function. It retrieves the deposited amount
// and sends it back to the sender using the bank keeper.
func (p Precompile) Deposit(
	ctx sdk.Context,
	contract *vm.Contract,
	stateDB vm.StateDB,
) ([]byte, error) {
	caller := contract.Caller()
	depositedAmount := contract.Value()

	callerAccAddress := sdk.AccAddress(caller.Bytes())
	precompileAccAddr := sdk.AccAddress(p.Address().Bytes())

	// Send the coins back to the sender
	if err := p.BankKeeper.SendCoins(
		ctx,
		precompileAccAddr,
		callerAccAddress,
		sdk.NewCoins(sdk.Coin{
			Denom:  evmtypes.GetEVMCoinExtendedDenom(),
			Amount: math.NewIntFromBigInt(depositedAmount.ToBig()),
		}),
	); err != nil {
		return nil, err
	}

	if err := p.EmitDepositEvent(ctx, stateDB, caller, depositedAmount.ToBig()); err != nil {
		return nil, err
	}

	return nil, nil
}
