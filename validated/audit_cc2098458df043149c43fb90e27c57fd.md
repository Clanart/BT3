### Title
Unauthenticated `internal_withdraw` RPC allows forcing an operator to fund a payout without aggregator authorization — ([File: core/src/rpc/operator.rs])

### Summary
`Operator::withdraw` (`core/src/operator.rs`) is the function that fronts BTC to a user by broadcasting a payout transaction, later reimbursed from the bridge's move-to-vault funds. The `withdraw` gRPC handler enforces an aggregator ECDSA "verification signature" check (`recover_address_from_ecdsa_signature::<OperatorWithdrawalMessage>` against `aggregator_verification_address`) before calling `self.operator.withdraw(...)`, exactly mirroring the pattern used by `optimistic_payout`/`sign_optimistic_payout`. However, the sibling handler `internal_withdraw` calls the identical `self.operator.withdraw(...)` path with **no verification-signature check at all**. [1](#0-0) [2](#0-1) 

### Finding Description
This is the same bug class as the reported issue: an invariant/authorization check ( `_checkBalances()` vs. the ECDSA verification-signature gate) is applied on one code path (`withdraw`) but not on the sibling path (`internal_withdraw`) that reaches the exact same state-changing operation (`Operator::withdraw`, which funds and RBF-broadcasts a real payout transaction via `fund_raw_transaction`).

`Operator::withdraw` itself only validates: (1) that the input outpoint matches Citrea's recorded withdrawal UTXO, (2) that the user's Schnorr signature over the payout tx is valid, and (3) that `is_profitable` holds. None of these three checks require the request to originate from the aggregator — they only require possession of a user-signed withdrawal request, which by protocol design is intended to be relayed by the aggregator after the ECDSA authorization gate. `internal_withdraw` skips that gate entirely, so any unauthenticated caller who can present a valid Citrea withdrawal (or, before Citrea confirms it, front-run using their own withdrawal parameters) can invoke `internal_withdraw` directly on the operator's gRPC endpoint and cause the operator to broadcast a real BTC payout, bypassing the aggregator-side authorization control that `withdraw` enforces. [3](#0-2) 

### Impact Explanation
This breaks the binding "the operator is reimbursed only for a payout it actually fronted **and was authorized to front**" — the aggregator verification-signature mechanism exists specifically to gate who may trigger `Operator::withdraw`'s fund-committing RBF broadcast. `internal_withdraw` reaching the same fund-committing call without that gate lets an unauthenticated caller trigger operator BTC outflow outside the intended authorization flow. Given the described impact taxonomy, this is closest to "an unauthenticated state-changing or broadcasting call" (High), since it is a gRPC method that performs a real Bitcoin broadcast (`fund_raw_transaction` + RBF send) without the authentication check present on its sibling endpoint.

### Likelihood Explanation
Likelihood depends on whether `internal_withdraw` is actually exposed on a network-reachable, unauthenticated gRPC listener in production deployments, versus being an internal/loopback-only method (its name and the `internal_` prefix, similar to `internal_finalized_payout` which is explicitly gated with `if !cfg!(test)`, suggest it may be intended as a test-only or internal-only helper — but unlike `internal_finalized_payout`, `internal_withdraw` has **no** such guard). Whether this is reachable by an unprivileged external attacker depends on operator gRPC endpoint exposure/deployment configuration, which cannot be fully verified from this static analysis alone.

### Recommendation
Add the same aggregator ECDSA verification-signature check present in `withdraw` to `internal_withdraw`, or remove/gate `internal_withdraw` behind a `cfg!(test)` guard analogous to `internal_finalized_payout`, so that both entry points into `Operator::withdraw` enforce identical authorization.

### Proof of Concept
1. An unprivileged caller obtains a valid Citrea withdrawal (`withdrawal_id`, `input_signature`, `input_outpoint`, `output_script_pubkey`, `output_amount`) — this is public/observable data once a user submits a withdrawal on Citrea.
2. The caller calls the operator's `internal_withdraw` gRPC method directly with these parameters (no `verification_signature` field exists on this RPC's request type at all).
3. `Operator::withdraw` proceeds: verifies the withdrawal UTXO matches Citrea state, verifies the user signature, checks `is_profitable`, and if all pass, funds and broadcasts the payout transaction — identical effect to calling the aggregator-gated `withdraw` RPC, but skipping the aggregator authorization check that `withdraw` enforces.     async fn withdraw(
        &self,
        request: Request<WithdrawParamsWithSig>,
    ) -> Result<Response<RawSignedTx>, Status> {
        tracing::info!("Withdraw rpc called");
        let params = request.into_inner();
        let withdraw_params = params.withdrawal.ok_or(Status::invalid_argument(
            "Withdrawal params not found for withdrawal",
        ))?;
        let (withdrawal_id, input_signature, input_outpoint, output_script_pubkey, output_amount) =
            parser::operator::parse_withdrawal_sig_params(withdraw_params)?;

        tracing::warn!(
            "Parsed withdraw rpc params, withdrawal id: {:?}, input signature: {:?}, input outpoint: {:?}, output script pubkey: {:?}, output amount: {:?}, verification signature: {:?}", withdrawal_id, input_signature, input_outpoint, output_script_pubkey, output_amount, params.verification_signature
        );

        // if verification address is set in config, check if verification signature is valid
        if let Some(address_in_config) = self.operator.config.aggregator_verification_address {
            let verification_signature = params
                .verification_signature
                .map(|sig| {
                    PrimitiveSignature::from_str(&sig).map_err(|e| {
                        Status::invalid_argument(format!("Invalid verification signature: {e}"))
                    })
                })
                .transpose()?;
            // check if verification signature is provided by aggregator
            if let Some(verification_signature) = verification_signature {
                let address_from_sig =
                    recover_address_from_ecdsa_signature::<OperatorWithdrawalMessage>(
                        withdrawal_id,
                        input_signature,
                        input_outpoint,
                        output_script_pubkey.clone(),
                        output_amount,
                        verification_signature,
                    )?;

                // check if verification signature is signed by the address in config
                if address_from_sig != address_in_config {
                    return Err(BridgeError::InvalidECDSAVerificationSignature).map_to_status();
                }
            } else {
                // if verification signature is not provided, but verification address is set in config, return error
                return Err(BridgeError::ECDSAVerificationSignatureMissing).map_to_status();
            }
        }

        let payout_tx = self
            .operator
            .withdraw(
                withdrawal_id,
                input_signature,
                input_outpoint,
                output_script_pubkey,
                output_amount,
            )
            .await?;

        tracing::info!(
            "Withdrawing with index: {}, in_signature: {:?}, in_outpoint: {:?}, out_script_pubkey: {}, out_amount: {}",

            in_signature,
            in_outpoint,
            out_script_pubkey,
            out_amount
        );

        // Prepare input and output of the payout transaction.
        let input_prevout = self.rpc.get_txout_from_outpoint(&in_outpoint).await?;
        let input_utxo = UTXO {
            outpoint: in_outpoint,
            txout: input_prevout,
        };
        let output_txout = TxOut {
            value: out_amount,
            script_pubkey: out_script_pubkey,
        };

        // Check Citrea for the withdrawal state.
        let withdrawal_utxo = self

            .await?;
