### Title
`_upb_Decoder_DecodeFixedPacked` trusts `upb_EpsCopyInputStream_ReadStringEphemeral`'s ephemeral buffer as if `size` were fully validated, causing endianness-swap conversion to read/consume garbage patch-buffer bytes before the truncation error is detected - (File: `upb/wire/decode.c`)

### Summary
The BakerFi bug is a "trusted return value" defect: `undeploy()` treats a callee's return value as if it always equals the caller-requested amount, then performs a bounded operation (`safeTransfer`) using that unchecked assumption, which fails when the callee actually did less work than requested. The Protobuf analog in `upb`'s wire decoder is structurally identical: `_upb_Decoder_DecodeFixedPacked` (in `upb/wire/decode.c`) calls `upb_EpsCopyInputStream_ReadStringEphemeral()` and immediately treats the returned `upb_StringView` as containing `val->size` bytes of legitimate, fully-available input data — copying/converting all of it — even though the function's own contract explicitly says it does **not** validate that the requested size is actually available and may return **garbage bytes from the patch buffer**, with the real validation deferred to a later, unrelated call (`upb_EpsCopyInputStream_IsDone`).

### Finding Description
`upb_EpsCopyInputStream_ReadStringEphemeral` is documented in [1](#0-0)  as follows: it only checks that `size` fits within the *current buffer including slop bytes* (`e->end + kUpb_EpsCopyInputStream_SlopBytes`), not that `size` fits within the actual delimited field limit or true end of stream. The implementation performs exactly that limited check: [2](#0-1)  — if `size` exceeds the slop-adjusted buffer bound it errors, but otherwise it happily returns `*sv = {ptr, size}` even when `size` extends past the legitimate end of input into the "patch buffer" area, which can contain **uninitialized/stale data from a previous buffer**, not real input bytes. The header explicitly warns: "the returned data may contain garbage bytes from the patch buffer... This error will be detected later, when calling `upb_EpsCopyInputStream_IsDone()`... but it may result in nonsense bytes ending up in the output."

The caller `_upb_Decoder_DecodeFixedPacked` does not defer use of the data until after that later validation — it uses the string view (`sv.data`, `sv.size`) immediately to reserve array capacity and `memcpy`/byte-swap the "read" bytes straight into the message's packed-fixed array: [3](#0-2) . Only after this write does control return to the outer loop that eventually calls `upb_EpsCopyInputStream_IsDone`, which is where the truncation is finally detected and an error thrown. By that point the (possibly garbage/patch-buffer) bytes have already been fully copied into (and, on big-endian targets, byte-swapped into) the destination array that becomes part of a parsed, in-arena message.

This mirrors the BakerFi flaw precisely:
- BakerFi: `_undeploy(amount)` returns a value that the caller (`undeploy`) treats as "the full `amount` was processed," used to drive `safeTransfer`, when the real amount could be less.
- upb: `ReadStringEphemeral(..., size, &sv)` returns a `upb_StringView` that the caller treats as "there are truly `size` valid input bytes at `sv.data`," used to drive a `memcpy`/byte-swap copy, when the real availability could be less (function explicitly does not check against the actual field/stream limit).

The failed invariant in both cases: "the value returned by the callee accurately reflects what was actually available/consumed," when in fact the callee's contract only guarantees a *weaker* property (requested-vs-buffer-bound check, not requested-vs-true-limit check), and the immediate caller does not re-validate before acting on it.

### Impact Explanation
On the ordinary supported binary-wire parse path (`upb_Decode`/`upb_Decode_Bounded` public parse APIs, which any consuming application exposes to untrusted binary Protobuf input for packed fixed32/fixed64/float/double repeated fields), a maliciously truncated message can cause the decoder to copy stale patch-buffer bytes into the destination array before the truncation is caught. Because the patch buffer is a fixed, small (`kPatchBufferSize`) scratch region reused across buffer boundaries within the same decode operation, the "garbage" is bounded to data left over from earlier in the *same* parse (not cross-request heap disclosure), but it still means parsed numeric field values can be populated with attacker-uncontrolled leftover bytes from the input stream state, not deterministically derived from the declared field bytes — a parsing-differential/data-integrity issue rather than a clean-fail. Because the error is ultimately still raised (`upb_ErrorHandler_ThrowError(... kUpb_DecodeStatus_Malformed)` once `IsDone` notices the limit mismatch), the message is rejected — so this is not a "successful parse with corrupted data" scenario, but a "before-final-validation use of unvalidated buffer bytes" issue, similar in class to the BakerFi bug where the caller trusts a return value that hasn't been validated against the true consumed/available amount, even though the top-level operation eventually reverts/fails.

### Likelihood Explanation
Reachable by any attacker who can submit a bounded, standard-conforming-looking binary protobuf payload containing a truncated packed fixed-width repeated field (fixed32/fixed64/float/double/sfixed32/sfixed64) to a public `upb` decode entry point (`upb_Decode`) with a schema containing such a field — no privileged access, hostile schema, or huge input required. The path is a normal fast-path helper (`_upb_Decoder_DecodeFixedPacked`) hit on ordinary packed-fixed field parsing, not an edge-case-only branch, so likelihood of *reaching* the code is high; the question is only whether "patch buffer leftover" is exploitable beyond the eventual parse failure — given the function's own documentation calling this out as an explicit known caveat ("garbage bytes... nonsense bytes ending up in output"), it's a real, acknowledged property of the implementation, not a hypothetical.

### Recommendation
In `_upb_Decoder_DecodeFixedPacked` (and any other caller of `upb_EpsCopyInputStream_ReadStringEphemeral`, e.g. the unknown-field skip path in `_upb_Decoder_DecodeUnknowns`), do not perform the destination copy/byte-swap based on the returned `upb_StringView` until the size has been confirmed to lie within the real field/stream limit — either by calling `upb_EpsCopyInputStream_CheckSize`/pushing a limit and checking `IsDone` before consuming `sv.data`, or by switching this call site to `upb_EpsCopyInputStream_ReadStringAlwaysAlias`, which does perform the buffer-bound check against `e->end` (and correctly refuses slop-byte use whenever the pointer originates from the patch buffer) before returning the view, matching the documented safer contract in [4](#0-3) .

UPB_INLINE const char* upb_EpsCopyInputStream_ReadStringAlwaysAlias(
    struct upb_EpsCopyInputStream* e, const char* ptr, size_t size,
    upb_StringView* sv) {
  UPB_ASSERT(size <= PTRDIFF_MAX);
  // The `size` must be within the input buffer. If `ptr` is in the input
  // buffer, then using the slop bytes is fine (because they are real bytes from
  // the tail of the input buffer). If `ptr` is in the patch buffer, then slop
  // bytes represent bytes that do not actually exist in the original input
  // buffer, so we must fail if the size extends into the slop bytes.
  const char* limit =
      e->end + (e->input_delta == 0) * kUpb_EpsCopyInputStream_SlopBytes;
  if ((ptrdiff_t)size > limit - ptr) {
    // For the moment, we consider this an error.  In a multi-buffer world,
    // it could be that the requested string extends into the next buffer, which
    // is not an error and should be recoverable.
    return UPB_PRIVATE(upb_EpsCopyInputStream_ReturnError)(e);
  }
  const char* input = UPB_PRIVATE(upb_EpsCopyInputStream_GetInputPtr)(e, ptr);
  *sv = upb_StringView_FromDataAndSize(input, size);
  return ptr + size;
}

UPB_FORCEINLINE
const char* _upb_Decoder_DecodeFixedPacked(upb_Decoder* d, const char* ptr,
                                           upb_Array* arr, wireval* val,
                                           const upb_MiniTableField* field,
                                           int lg2) {
  upb_StringView sv;
  ptr = upb_EpsCopyInputStream_ReadStringEphemeral(&d->input, ptr, val->size,
                                                   &sv);
  if (!ptr) upb_ErrorHandler_ThrowError(d->err, kUpb_DecodeStatus_Malformed);
  int mask = (1 << lg2) - 1;
  if (UPB_UNLIKELY((val->size & mask) != 0 || ptr == NULL)) {
    upb_ErrorHandler_ThrowError(d->err, kUpb_DecodeStatus_Malformed);
  }
  size_t count = val->size >> lg2;
  if (count == 0) return ptr;
  _upb_Decoder_Reserve(d, arr, count);
  void* mem = UPB_PTR_AT(upb_Array_MutableDataPtr(arr),
                         arr->UPB_PRIVATE(size) << lg2, void);
  arr->UPB_PRIVATE(size) += count;
  if (upb_IsLittleEndian()) {
    memcpy(mem, sv.data, sv.size);
  } else {
    const char* src = sv.data;
    const char* src_end = src + sv.size;
    char* dst = mem;
    if (lg2 == 2) {
      for (; src < src_end; src += 4, dst += 4) {
        uint32_t x;
        memcpy(&x, src, 4);
        x = upb_BigEndian32(x);
        memcpy(dst, &x, 4);
      }
    } else {
      UPB_ASSERT(lg2 == 3);
      for (; src < src_end; src += 8, dst += 8) {
        uint64_t x;
        memcpy(&x, src, 8);
        x = upb_BigEndian64(x);
        memcpy(dst, &x, 8);
      }
    }
  }

  return ptr;
}
