### Title
Gasless swap admission trusts a manipulable live AMM spot quote (`GetAmountIn`) to bound gas-lending repayment - ([File: kaiax/gasless/impl/tx_pool.go])

### Summary
`GaslessModule.checkBalanceForSwap()` validates a KIP-247 gasless swap transaction by querying the `GaslessSwapRouter` contract's `getAmountIn(token, minAmountOut)` — a live, on-chain AMM-derived spot quote — and only requires `swapArgs.AmountIn >= requiredAmountIn`. This is structurally the same bug class as the FoxMarket incident: a critical financial precondition (how much of a manipulable asset must be supplied) is computed from a single, unprotected DEX price read rather than a TWAP or otherwise-manipulation-resistant source. [1](#0-0) 

### Finding Description
The gasless flow works as follows: a proposer/block-builder extends credit to a gasless-swap sender via a generated `LendTx` (`GetLendTxGenerator`/`lendAmount`), which fronts the KAIA needed to pay the swap+approve transaction fees, and expects to be repaid via the token→KAIA `swapForGas` call executed atomically in the same bundle. [2](#0-1) [3](#0-2) 

Before promoting/admitting the `SwapTx` into the pool/bundle, `checkBalanceForSwap` is the only sanity check that ties the sender-declared `AmountIn` (how much ERC-20 token the sender is willing to give up) to the sender-declared `MinAmountOut`/`AmountRepay` (how much KAIA the proposer expects back). This check calls the `GaslessSwapRouter.getAmountIn(token, minAmountOut)` view function, which internally derives price from the underlying DEX pool's reserves (Uniswap/Pancake-style `getAmountIn(amountOut, reserveIn, reserveOut)`) at the current head state. [1](#0-0) [4](#0-3) 

This is exactly the FoxMarket bug class: the amount required to satisfy a settlement obligation (there, `_stakeAmount` for `FoxLpBondsPool.stake()`; here, `requiredAmountIn` for gasless-swap admission and `swapForGas` execution) is fixed from a single spot-price call to a constant-product AMM pool rather than a manipulation-resistant oracle (TWAP, multi-block average, or a router path with slippage protection tied to a trusted reference price). Because `SwapTx`, `ApproveTx`, and the proposer's `LendTx` are bundled and executed atomically within one block by the same actor who controls the bundle contents (the gasless-swap sender crafts `AmountIn`/`MinAmountOut`/`AmountRepay`), and because the underlying DEX reserves used by `getAmountIn` can be skewed within the same block/bundle (e.g., a large swap against the pool immediately preceding the gasless swap, analogous to FoxMarket's flash-loan-driven Pancake-pair skew), a sender can construct a bundle where the admission check passes (`AmountIn >= requiredAmountIn` computed against manipulated reserves) while the actual token value transferred is worth far less than the KAIA repaid by/lent to the proposer.

### Impact Explanation
If exploitable, this allows an unprivileged gasless-swap sender to under-collateralize the gas loan advanced by the block proposer: the proposer's `LendTx` fronts KAIA gas fees expecting to be repaid `amountRepay` worth of value from the swap, but the admission check that is supposed to guarantee `AmountIn` is "enough" token for the declared `MinAmountOut`/`AmountRepay` is based on a spot price that the sender (or a colluding party) can skew within the same bundle/block. This is a fee-delegation/gasless-settlement value-transfer abuse — the proposer effectively subsidizes an artificially cheap swap, losing the lent KAIA gas fee with no genuine value backing it, which maps to the required "gasless or auction settlement theft" impact category. This is rated Medium given it targets the KIP-247 gasless module rather than direct chain consensus, and requires an on-chain DEX pool wired into `GaslessSwapRouter` with insufficient liquidity/slippage protection.

### Likelihood Explanation
Reachability is straightforward for any unprivileged public RPC caller: the flow is triggered purely by submitting a normal `ApproveTx`/`SwapTx` gasless bundle via `auction`/gasless mempool paths, no special privilege is required. `ShouldCheckSwapAmount()` in `GaslessConfig` gates this check — if this check is the only quantity guard (as shown by the code comment "tx.amountIn >= gsr.getAmountIn(minAmountOut)"), and the `getAmountIn` price is read live rather than via a manipulation-resistant reference, then any sender able to skew the underlying pool reserves in the same block (self-funded large swap, flash loan, or coordination with a searcher/bundle) can pass admission with a low `AmountIn` while claiming a high `MinAmountOut`/`AmountRepay`. The exact severity depends on liquidity depth of pools wired into `GaslessSwapRouter.dexAddress(token)` and on whether `swapForGas`'s on-chain execution independently re-verifies output against a manipulation-resistant price (this Solidity source was not found in the indexed codebase, so the actual execution-time guard could not be fully confirmed).

### Recommendation
- Do not rely solely on a live single-block AMM spot quote (`getAmountIn`) for admission or settlement guarantees; use TWAP pricing, a whitelisted price oracle, or require multi-block price stability checks.
- Enforce the amountIn/amountOut invariant using the actual DEX router's execution-time slippage protection (e.g., `amountOutMin` passed into `swapExactTokensForETH`) rather than trusting a value computed from current reserves that can move within the same bundle.
- Consider bounding the maximum price impact allowed for a single swapForGas call, and reject bundles when the swap would move the pool price beyond a configured threshold.
- Add sanity checks comparing computed spot price against a trusted external reference (e.g., governance-configured floor price) before granting gas credit via `LendTx`.

### Proof of Concept
Conceptual PoC (execution-time contract source for `GaslessSwapRouter.sol` was not available in the indexed codebase, so exact call sequence within `swapForGas` could not be fully verified):
1. Attacker (gasless-swap sender) identifies the DEX pool backing `token` registered via `GaslessSwapRouter.dexAddress(token)`.
2. In the same bundle/block, attacker (or accomplice) performs a large swap against that pool (optionally via flash loan) to skew reserves so that `getAmountIn(token, minAmountOut)` returns an artificially low `requiredAmountIn`.
3. Attacker submits `ApproveTx` + `SwapTx` with `AmountIn` set just above the skewed `requiredAmountIn`, and `MinAmountOut`/`AmountRepay` set to the desired (higher) KAIA repayment value.
4. `checkBalanceForSwap` admits the transaction because `swapArgs.AmountIn.Cmp(requiredAmountIn) >= 0` against the manipulated quote: [1](#0-0) 
5. The proposer's `LendTx` fronts KAIA gas based on `lendAmount` (transaction fees), and the bundle executes atomically, resulting in the proposer receiving less real value than the declared `amountRepay` would suggest, while the attacker escapes with tokens (or reward) under-priced relative to true market value.

// MakeLendTx creates a transaction with following properties:
// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)
// L2. LendTx.from = proposer
// L3. LendTx.to = SwapTx.from
// L4. LendTx.value = LendAmount(approveTxOrNil, swapTx)
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}
