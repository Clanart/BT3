### Title
Zero Threshold Allowed in `SecurityCouncil` Bypasses Multisig Guard on Emergency-Stop and Replacement-Deposit UTXOs — (`core/src/deposit.rs`)

---

### Summary

`SecurityCouncil::from_str` accepts `threshold = 0` without error. When this value flows into `Multisig::to_script_buf`, the generated Bitcoin tapscript uses `OP_NUMEQUAL 0`, which is satisfied by providing empty (null) signatures for every key — no security-council member needs to sign. Any party can then spend the emergency-stop output (which holds the full bridge amount) or unlock a replacement-deposit UTXO without authorization.

---

### Finding Description

`SecurityCouncil::from_str` in `core/src/deposit.rs` validates two constraints:

```
pks.is_empty()          → error
threshold > pks.len()   → error
```

but **never checks `threshold >= 1`**. [1](#0-0) 

The parsed `SecurityCouncil` is stored in `BridgeConfig` and propagated into every deposit. `Multisig::from_security_council` copies the threshold verbatim into the Bitcoin script builder:

```rust
script_builder = script_builder.push_int(self.threshold as i64);
script_builder = script_builder.push_opcode(OP_NUMEQUAL);
``` [2](#0-1) 

With `threshold = 0` the emitted script is:

```
<pk1> OP_CHECKSIG <pk2> OP_CHECKSIGADD … <pkN> OP_CHECKSIGADD 0 OP_NUMEQUAL
```

In Bitcoin tapscript, an empty-byte signature passed to `OP_CHECKSIG`/`OP_CHECKSIGADD` counts as 0 (no error, no abort). The running count therefore stays 0, `0 OP_NUMEQUAL` pushes `1` (true), and the script succeeds — **no real signature is required**.

This script is embedded in two critical places:

1. **Emergency-stop TX output** — `create_emergency_stop_txhandler` locks the full bridge amount (minus fees) to a `Multisig::from_security_council` output. With threshold 0, anyone can drain it. [3](#0-2) 

2. **Replacement-deposit address** — `generate_replacement_deposit_address` embeds the same multisig as a taproot leaf on the move-to-vault UTXO. With threshold 0, anyone can spend the UTXO via the security-council script path and redirect bridge funds. [4](#0-3) 

---

### Impact Explanation

- **Emergency-stop path**: After an emergency stop is broadcast, the output holding the bridge amount (10 BTC denomination) is protected only by the zero-threshold multisig. Any on-chain observer can immediately sweep it with a transaction that provides empty witnesses for all security-council key slots.
- **Replacement-deposit path**: The move-to-vault UTXO has the security-council script as a taproot spend path. With threshold 0, an attacker can spend it without the council's consent, permanently diverting the deposited BTC.

Both cases result in **permanent, irrecoverable loss of bridged BTC** from the vault.

---

### Likelihood Explanation

The trigger is an operator setting `security_council = "0:<pk1>,<pk2>,…"` in the bridge config. The code accepts this silently — no startup error, no compatibility-check rejection. The `CompatibilityParams::is_compatible` check only compares the security council for equality between actors; it does not independently validate that the threshold is non-zero. [5](#0-4) 

An accidental misconfiguration (analogous to the external report's proposer accidentally setting threshold to 0) is the realistic trigger. Because the config is parsed at startup and the invalid value propagates silently into every deposit's tapscript, the window of exposure is the entire lifetime of the bridge deployment.

---

### Recommendation

**Short term:** Add a `threshold >= 1` guard in `SecurityCouncil::from_str`:

```rust
if threshold == 0 {
    return Err(eyre::eyre!("Threshold must be at least 1"));
}
``` [6](#0-5) 

**Long term:** Add a corresponding validation in `Multisig::new` / `Multisig::from_security_council` as a defense-in-depth assertion, and add a startup sanity check in `BridgeConfig` validation that rejects any `SecurityCouncil` with `threshold == 0` before any deposit address is generated.

---

### Proof of Concept

1. Configure the bridge with `SECURITY_COUNCIL="0:<pk1>,<pk2>,<pk3>"` (threshold = 0, three valid public keys).
2. `SecurityCouncil::from_str` parses this successfully — `threshold = 0`, `pks.len() = 3`, both existing checks pass.
3. A deposit is processed; `create_emergency_stop_txhandler` creates an output locked to the resulting `Multisig` script.
4. Construct a spending transaction with a witness containing three empty byte-vectors (one per key slot) plus the script and control block for the taproot script path.
5. Bitcoin evaluates: `0 OP_CHECKSIG` → 0; `<pk2> OP_CHECKSIGADD` → 0; `<pk3> OP_CHECKSIGADD` → 0; `0 OP_NUMEQUAL` → 1. Script succeeds.
6. The full bridge amount is transferred to the attacker's address with no security-council involvement. [7](#0-6) [8](#0-7)

impl std::str::FromStr for SecurityCouncil {
    type Err = eyre::Report;

    fn from_str(s: &str) -> Result<Self, Self::Err> {
        let mut parts = s.split(':');
        let threshold_str = parts
            .next()
            .ok_or_else(|| eyre::eyre!("Missing threshold"))?;
        let pks_str = parts
            .next()
            .ok_or_else(|| eyre::eyre!("Missing public keys"))?;

        if parts.next().is_some() {
            return Err(eyre::eyre!("Too many parts in security council string"));
        }

        let threshold = threshold_str
            .parse::<u32>()
            .map_err(|e| eyre::eyre!("Invalid threshold: {}", e))?;

        let pks: Result<Vec<XOnlyPublicKey>, _> = pks_str
            .split(',')
            .map(|pk_str| {
                let bytes = hex::decode(pk_str)
                    .map_err(|e| eyre::eyre!("Invalid hex in public key: {}", e))?;
                XOnlyPublicKey::from_slice(&bytes)
                    .map_err(|e| eyre::eyre!("Invalid public key: {}", e))
            })
            .collect();

        let pks = pks?;

        if pks.is_empty() {
            return Err(eyre::eyre!("No public keys provided"));
        }

        if threshold > pks.len() as u32 {
            return Err(eyre::eyre!(
                "Threshold cannot be greater than number of public keys"
            ));
        }

        Ok(SecurityCouncil { pks, threshold })
    }
```
