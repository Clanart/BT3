### Title
Gasless swap lending occurs before atomic verification of on-chain fund availability, allowing sender to receive lent gas KAIA without repayment - (File: kaiax/gasless/impl/tx_pool.go, kaiax/gasless/impl/getter.go)

### Summary
The `kaiax/gasless` module lends KAIA to a transaction sender via a proposer-generated `LendTx` before the sender's `GaslessSwapTx` actually executes and repays that amount. The decision to lend funds is based on a balance/allowance/swap-amount check (`checkBalanceForApprove` / `checkBalanceForSwap`) performed against a snapshot of chain state at tx-pool admission/filtering time, not atomically guaranteed at the moment the bundle `[LendTxGenerator, ApproveTx, SwapTx]` is actually executed in a block. This is structurally the same class of bug as the OpenQ report: a party (the bounty issuer / here, the block proposer acting as lender) advances value based on a "funds are available" check that is not re-verified or enforced atomically before the payout obligation is fulfilled.

### Finding Description
`GetCheckBalance()` in `kaiax/gasless/impl/tx_pool.go` (lines 62-100) dispatches to `checkBalanceForApprove` and `checkBalanceForSwap`, which validate token balance, allowance, and required swap amount using `bc := backends.NewBlockchainContractBackend(...)` queries against current/pending state [1](#0-0) . The depth of these checks is governed entirely by `GaslessConfig.BalanceCheckLevel` [2](#0-1) , which can range from `BalanceCheckLevelStatic` (only deadline/amount relation checks) up to `BalanceCheckLevelAll`.

Regardless of the configured level, once a `GaslessApproveTx`/`GaslessSwapTx` pair (or lone swap) is judged "executable" (`IsExecutable`/`VerifyExecutable`, `kaiax/gasless/impl/getter.go` lines 211-266), the block-builder unconditionally prepends a `LendTx` that unconditionally transfers `lendAmount(approveTxOrNil, swapTx)` KAIA from the proposer's node key to the sender [3](#0-2) , before the `SwapTx`'s actual on-chain repayment (`swapForGas`) has been confirmed to succeed. This mirrors the OpenQ pattern of the state changing to an "active"/"open" (here, "lend executed") state without a hard, atomic guarantee that the downstream obligation (token repayment via swap) will be fulfilled.

The balance/allowance/swap-amount checks in `checkBalanceForSwap` (lines 107-182) are performed once at tx admission/filter time (`blockchain/tx_list.go` `Filter`, lines 406-414, and `blockchain/tx_pool.go` `validateTx`, lines 918-932) using the pool's `currentState`, not re-verified atomically immediately before the `LendTx`+`SwapTx` sequence is committed into a block. Because ERC20 `balanceOf`/`allowance` are mutable and the sender fully controls their own token account, the sender can alter these values (e.g., transfer away the token, revoke approval) after the admission-time check passes but before the bundle is actually included, causing `swapForGas` to revert on execution while the preceding `LendTx` — which is a separate, independently-valued transaction — has already unconditionally transferred lent KAIA to the sender.

### Impact Explanation
If the `LendTx` and `SwapTx` are not enforced as a single atomic unit at the EVM/state-transition level (only "bundled" for ordering/inclusion purposes via `builder.Bundle`, per `kaiax/gasless/impl/builder.go`), a sender can obtain free KAIA funded by the block proposer without ever completing the repayment swap, resulting in direct unauthorized value movement from the proposer (lender) to the sender. This is a fee/gasless-settlement theft matching the required impact criteria: unauthorized value movement / gasless settlement theft.

### Likelihood Explanation
Exploitability depends on: (1) whether `LendTx` and `SwapTx` execution is atomic within the same state transition (if not, this is directly exploitable by any gasless-tx sender); and (2) how quickly token balance/allowance can be manipulated by the sender between the pool's balance check and actual block inclusion. I was not able to fully confirm within the available context whether `work/worker.go`'s bundle commitment logic enforces atomicity (revert-all-on-failure) for the `[LendTxGenerator, ApproveTx, SwapTx]` bundle — this bundling and commit-atomicity code (`work/worker.go`, `work/builder/builder.go`) needs further review to establish definitive exploitability. If bundles are committed atomically (all txs revert together on any failure), this specific vector would not result in fund loss.

### Recommendation
Ensure the `LendTx` is only executed as part of a single atomic state transition together with the `ApproveTx`/`SwapTx`, such that if the swap ultimately fails (insufficient balance, allowance, or repay amount) the lend transfer is also reverted. Additionally, re-verify balance/allowance directly before the lend is committed in the block-building pipeline (not solely at pool admission time) to close the TOCTOU window between `checkBalanceForSwap` and actual inclusion.

### Proof of Concept
Not fully constructible without confirming bundle-execution atomicity in `work/worker.go` / `work/builder/builder.go`. Conceptual PoC: sender submits `GaslessApproveTx` + `GaslessSwapTx` with sufficient token balance/allowance to pass `checkBalanceForSwap`; sender is admitted to the pool and the module schedules `[LendTxGenerator, ApproveTx, SwapTx]`. Before the bundle is committed into a block, the sender submits (and gets mined first, e.g. via higher gas price) a separate transaction transferring away or reducing their token balance/allowance. If the bundle is not atomic, `LendTx` still credits the sender with KAIA while `SwapTx` reverts for insufficient balance, leaving the lent KAIA unrepaid. [4](#0-3) [3](#0-2) [5](#0-4)

func (g *GaslessModule) GetCheckBalance() func(tx *types.Transaction) error {
	return func(tx *types.Transaction) error {
		if approveArgs, ok := decodeApproveTx(tx, g.signer); ok {
			return g.checkBalanceForApprove(approveArgs)
		}
		if swapArgs, ok := decodeSwapTx(tx, g.signer); ok {
			return g.checkBalanceForSwap(swapArgs, tx.Nonce())
		}
		return errors.New("not a gasless transaction") // should not happen because IsModuleTx is called before GetCheckBalance
	}
}

func (g *GaslessModule) checkBalanceForApprove(approveArgs *ApproveArgs) error {
	token := approveArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(approveArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {
		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// tx.token.balanceOf(sender) > 0
		tokenBalance, err := tokenContract.BalanceOf(nil, approveArgs.Sender)
		if err != nil {
			return err
		}
		if tokenBalance.Sign() <= 0 {
			return fmt.Errorf("insufficient sender token balance: token=%s, have=%s, want=nonzero", token.Hex(), tokenBalance.String())
		}
	}
	return nil
}

// MakeLendTx creates a transaction with following properties:
// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)
// L2. LendTx.from = proposer
// L3. LendTx.to = SwapTx.from
// L4. LendTx.value = LendAmount(approveTxOrNil, swapTx)
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}
