### Title
Unauthenticated `ReceivedOutput` deserialization allows nonexistent or third-party outpoints to be reported and signed as wallet-owned funds - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary

`ReceivedOutput::read` accepts an attacker-controlled scalar offset, `TxOut`, and `OutPoint` as three independent fields, without proving that the referenced outpoint actually contains the supplied output or belongs to the wallet. [1](#0-0)  The only wallet-ownership check performed later verifies that the claimed `script_pubkey` equals the script derived from `ThresholdKeys` plus the supplied offset; it does not verify that the claimed `TxOut` is the real contents of the referenced outpoint. [2](#0-1) 

### Finding Description

A legitimately scanned output binds all three fields together from an actual transaction: the scanner selects a chain output, records the matching script’s registered offset, and derives the outpoint from that transaction’s ID and output index. [3](#0-2)  `ReceivedOutput::read` bypasses that construction and creates the same “spendable output” representation from unauthenticated bytes by independently decoding `offset`, `output`, and `outpoint`. [1](#0-0) 

`SignableTransaction::new` then trusts the supplied `output.value` for its input total and places the supplied `outpoint` into the transaction inputs. [4](#0-3)  It stores the claimed `TxOut` objects in `prevouts`, preserving the forged association for later signing. [5](#0-4) 

Before creating a signing machine, `multisig` derives the wallet key for the attacker-selected offset and compares it only with the claimed `prevouts[i].script_pubkey`. [2](#0-1)  Signing then commits to those attacker-supplied prevouts through `Prevouts::All`. [6](#0-5)  No code compares the serialized outpoint with the transaction containing the serialized output, so a forged record can describe wallet-controlled script bytes while naming a nonexistent, spent, or third-party outpoint. [1](#0-0) [2](#0-1) 

### Impact Explanation

An unprivileged supplier of serialized wallet outputs can cause the wallet to treat unavailable funds as spendable by presenting a wallet `script_pubkey` and arbitrary amount alongside an outpoint that does not contain that output. [1](#0-0) [4](#0-3)  This can inflate balances, satisfy `NotEnoughFunds` checks using unavailable value, and drive threshold participants to produce valid shares for a transaction that Bitcoin consensus cannot accept because the sighash commits to false prevout data or the outpoint is not spendable by the wallet. [7](#0-6) [6](#0-5) 

### Likelihood Explanation

The attack only requires control of bytes passed to `ReceivedOutput::read` and selection of a `TxOut` whose script matches a wallet-owned offset. [1](#0-0)  It does not require knowledge of the wallet secret because `multisig` checks only the public script derived from the offset, not ownership of the actual outpoint on chain. [2](#0-1) 

### Recommendation

Keep deserialized `ReceivedOutput` values explicitly unverified, or remove the public unauthenticated reader for objects documented as spendable outputs. [8](#0-7)  Before accounting or signing, resolve every `outpoint` against a trusted chain source and require the returned transaction output to equal the stored `TxOut`; additionally preserve the scanner-derived binding between `offset`, `output`, and `outpoint` rather than accepting the fields independently. [3](#0-2) [2](#0-1) 

### Proof of Concept

```rust
use bitcoin::{
  consensus::Encodable,
  Amount, OutPoint, TxOut, Transaction, Txid,
};
use frost::curve::Secp256k1;
use k256::Scalar;
use bitcoin_serai::wallet::{
  p2tr_script_buf, ReceivedOutput, SignableTransaction,
};

// `wallet_key` is the wallet's even-y Taproot key.
let wallet_script = p2tr_script_buf(wallet_key).unwrap();

// This outpoint can name a nonexistent, spent, or third-party UTXO.
let false_outpoint = OutPoint {
  txid: Txid::all_zeros(),
  vout: 0,
};

// The claimed output is nevertheless made payable to the wallet.
let claimed_output = TxOut {
  value: Amount::from_sat(100_000),
  script_pubkey: wallet_script,
};

let mut bytes = Vec::new();
bytes.extend(Scalar::ZERO.to_bytes());
claimed_output.consensus_encode(&mut bytes).unwrap();
false_outpoint.consensus_encode(&mut bytes).unwrap();

// Accepted without checking that false_outpoint contains claimed_output.
let forged = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();

// The forged value is treated as spendable input value.
let spend = SignableTransaction::new(
  vec![forged],
  &payments,
  None,
  None,
  fee_per_vbyte,
).unwrap();

// This succeeds if `wallet_keys` corresponds to `wallet_script`.
let machine = spend.multisig(&wallet_keys).unwrap();
```

The encoded object is accepted even though its `OutPoint` was chosen independently from its `TxOut`. [1](#0-0)  `SignableTransaction::new` uses the forged `value` and `outpoint` directly, while `multisig` validates only the claimed script against the wallet key. [4](#0-3) [2](#0-1)  The resulting signing session commits to the forged prevout list through `Prevouts::All`, producing shares for an unintended or unspendable transaction. [6](#0-5)
