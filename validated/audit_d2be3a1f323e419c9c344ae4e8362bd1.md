### Title
Attacker-sent dust outputs are reported as received funds but cost more in fees to spend than they are worth, draining the wallet - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_transaction` registers every output paying to a registered script as a `ReceivedOutput`, regardless of its value. `SignableTransaction::new` enforces a dust minimum on *payments* (`DustPayment`) and on the *change output*, but never checks the value of *inputs*. An unprivileged party can send dust outputs to a scanned address; the wallet reports them as received funds, yet each such input adds ~58 vbytes to any spending transaction — costing more in fees than the output's value. Spending the wallet's "received" funds therefore burns value on net, analogously to the GMX report where dust-sized ADL calls make the treasury subsidize unprofitable gas.

### Finding Description
The GMX bug class is: *a permissionless/repeatable action with a dust-sized amount forces the system to pay a cost (gas) that exceeds the value moved, draining a subsidizing treasury.*

In Serai's Bitcoin wallet:

- `Scanner::scan_transaction` accepts any output whose `script_pubkey` matches a registered script, with no minimum-value filter: `networks/bitcoin/src/wallet/mod.rs:199-214`. [1](#0-0) 
- `SignableTransaction::new` checks `*amount < DUST` only for outgoing payments, and `value >= DUST` only for the change output: `networks/bitcoin/src/wallet/send.rs:165-169` and `:224-234`. [2](#0-1) 
- Input value is only summed into `input_sat` for the aggregate solvency check `input_sat < payment_sat + needed_fee`: `networks/bitcoin/src/wallet/send.rs:175` and `:215`. [3](#0-2) 
- Every input unconditionally contributes its full weight to `needed_fee` via `calculate_weight_vbytes` (a Taproot key-spend input is ~57.5 vbytes): `networks/bitcoin/src/wallet/send.rs:68-83`, `:204-206`. [4](#0-3) 

There is no notion of "unspendable/uneconomical input". A `ReceivedOutput` of, e.g., 300 sats is indistinguishable from a valuable one, yet spending it at even 10 sat/vB costs ~575 sats — a net loss of ~275 sats drawn from the wallet's other inputs. Because `scripts` in `Scanner` persists, an attacker can repeat this arbitrarily: send N dust outputs to the tweaked key or any registered offset, each one a small liability recorded as an asset.

### Impact Explanation
- Funds are reported received (`Scanner` returns them as `ReceivedOutput`s, spendable via `SignableTransaction`/`TransactionMachine`) that are not economically spendable — each dust input is net-negative at any plausible fee rate.
- An attacker can batch-dust the wallet at fixed, low cost (one transaction can create hundreds of dust outputs to the same/offset addresses), forcing the coordinator to either permanently track unspendable UTXOs or burn treasury funds consolidating/spending them.
- If the selection logic naively uses "all received outputs" or oldest-first, dust is automatically included and the fee (`fee()` = `sum(inputs) - sum(outputs)`, `send.rs:138-141`) silently inflates, leaking wallet funds to miners. [5](#0-4) 

### Likelihood Explanation
- Reachable by any unprivileged party: sending a Bitcoin transaction to the wallet's P2TR script requires no privileges, only paying the dust amount plus a one-time fee — directly analogous to the malicious keeper's repeated cheap calls.
- Cost to attacker is bounded and small (~546 sats/output max, batchable in one tx); cost to the wallet is unbounded as it scales with the number of dusted outputs and the prevailing fee rate.
- No cryptographic assumption, validator misbehavior, or collusion is required — it relies only on the missing minimum-value check on scanned inputs.

### Recommendation
- In `Scanner::scan_transaction`, skip (or flag) outputs whose `value` is below the marginal spend cost: `output.value < marginal_input_vbytes * current_fee_rate` (or, conservatively, below `DUST` = 546 sats).
- Alternatively/additionally, in `SignableTransaction::new`, reject or exclude any `ReceivedOutput` whose value is less than the fee contribution it adds (`fee_per_vbyte * input_vbytes`), returning an error variant such as `UneconomicalInput`, so the change/solvency math never silently absorbs attacker-controlled dust.
- Document that integrators should prune dust-valued `ReceivedOutput`s before constructing transactions if they retain them for accounting.

### Proof of Concept
```rust
// networks/bitcoin context: wallet for tweaked ThresholdKeys<Secp256k1>
let mut scanner = Scanner::new(tweaked_group_key).unwrap();

// Attacker crafts ONE transaction with 100 outputs of 300 sats each,
// all paying to the wallet's p2tr script (or registered offsets).
let dust_script = p2tr_script_buf(tweaked_group_key).unwrap();
let attack_tx = Transaction {
    version: Version(2),
    lock_time: LockTime::ZERO,
    input: vec![/* attacker-funded input */],
    output: (0..100).map(|_| TxOut {
        value: Amount::from_sat(300),            // < DUST is also accepted
        script_pubkey: dust_script.clone(),
    }).collect(),
};

// Scanner reports all 100 dust outputs as received funds — no value filter.
let received = scanner.scan_transaction(&attack_tx); // len == 100
assert_eq!(received.len(), 100);
assert_eq!(received[0].value(), 300);                  // mod.rs:116-118

// Later, the wallet builds a transaction including these inputs.
// Each input adds ~57.5 vbytes (send.rs:68-83); at fee_per_vbyte = 10,
// each 300-sat input costs ~575 sats to spend — net -275 sats each.
// SignableTransaction::new never rejects this: only payments/change
// are dust-checked (send.rs:165-169, 229).
let stx = SignableTransaction::new(received, &payments, change, None, 10).unwrap();
// stx.fee() = sum(inputs) - sum(outputs) silently includes the ~27_500-sat
// loss on the dusted inputs, paid to miners out of the wallet's funds.
```

Concrete numbers: a single ~$1-cost attacker transaction creates 100 liabilities; the wallet either permanently carries 100 unscannable-in-practice-but-recorded UTXOs or loses ~27,500 sats spending them — repeatable indefinitely, matching the "treasury drained by repeated dust-sized invocations" pattern of the original report.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
