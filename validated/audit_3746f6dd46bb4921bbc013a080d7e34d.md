### Title
Broken expiry-forfeit calculation permanently disables reward slashing in mWOMSVBaseRewarder - (File: rewards/mWOMSVBaseRewarder.sol)

### Summary
`mWOMSVBaseRewarder::_calExpireForfeit` contains a self-referential comparison that can never evaluate to the intended slashing condition, so the "forfeit unearned/expired reward" mechanism that the sibling contract `vlMGPBaseRewarder` correctly implements is completely dead code in the mWOMSV reward pool. This is the same class of bug as the reported Pyth issue: a guard/comparison meant to gate a value (there, "ignore negative fluctuations beyond confidence interval"; here, "forfeit reward beyond the user's rewardable percentage") is implemented incorrectly and never rejects/adjusts anything, letting the un-gated value through unconditionally.

### Finding Description
`_calExpireForfeit` in `mWOMSVBaseRewarder.sol` is supposed to compute how much of a user's accrued reward must be forfeited based on how much of their `mWomSV` balance is actually locked vs. in cooldown/unlocking (mirroring `vlMGPBaseRewarder::_calExpireForfeit`, which correctly calls `vlMGP.getRewardablePercentWAD(_account)` to scale the rewardable amount): [1](#0-0) 

In `mWOMSVBaseRewarder.sol`, however, the equivalent function never queries the actual rewardable percentage — it sets `rewardableAmount = _amount` directly, meaning the subsequent guard `if (rewardableAmount > _amount) revert InvalidRewardableAmount();` is a tautology that can never fire, and `forfeitAmount = _amount - rewardableAmount` is always `0`: [2](#0-1) 

This is called from `_sendReward`, which is invoked on every `getReward`/`getRewards` call for `mWomSV` holders: [3](#0-2) 

Because `forfeitAmount` is always zero, the `_queueNewRewardsWithoutTransfer(forfeitAmount, ...)` branch that redistributes the forfeited share back into the reward pool for compliant/fully-locked stakers is never exercised, unlike the design intent shown by the analogous, correctly implemented `vlMGPBaseRewarder` and `VLMGP::getRewardablePercentWAD` logic: [4](#0-3) [5](#0-4) 

### Impact Explanation
Any ordinary wallet holding `mWomSV` — including one that has already started unlocking / is fully in cooldown — receives 100% of its accrued reward share with zero forfeiture, when the protocol's own economic design (as implemented identically for `vlMGP`) dictates that a partially-unlocked/expired position should forfeit a portion of yield back to the pool for fully-locked stakers. This is a direct theft of unclaimed yield from compliant long-term lockers, redirected/retained by users who partially exit their lock, and it is triggered through completely ordinary, unprivileged `getReward`/`getRewards` calls — no admin or oracle involvement required.

### Likelihood Explanation
High. The flawed function is reached on every normal reward claim by any `mWomSV` holder; no special preconditions, privileged role, or governance action is needed to trigger it — a user only needs to hold `mWomSV`, start unlocking, and call `getReward`.

### Recommendation
Mirror `vlMGPBaseRewarder::_calExpireForfeit`: compute `rewardableAmount` from the actual rewardable percentage of the user's `mWomSV` position (e.g., via `mWomSV.getRewardablePercentWAD(_account)`) rather than assigning `rewardableAmount = _amount`, so the forfeiture check and redistribution logic function as intended.

### Proof of Concept
1. User A locks `mWomSV` and starts an unlock (`startUnlock`), moving part of their balance into cooldown while a `mWOMSVBaseRewarder` accrues rewards for their full `mWomSV` balance.
2. Before the cooldown period completes, User A calls `getReward`/`getRewards`.
3. `_sendReward` → `_calExpireForfeit` returns `forfeitAmount == 0` regardless of how much of the user's balance is actually eligible, per [2](#0-1) .
4. User A receives the entire `userRewards[...]` amount uncut, and no forfeited amount is ever queued back via `_queueNewRewardsWithoutTransfer`, meaning fully-locked stakers permanently lose the yield share they were entitled to under the intended forfeiture design.

        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardableAmount = _amount;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalmWomSV = fullyInLock + inCoolDown;
        if (userTotalmWomSV == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalmWomSV;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalmWomSV / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalmWomSV;
                }

            }
        }

        return percent;
    }
