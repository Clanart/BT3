### Title
Unrecovered panic in `pointer` precompile's CW20/CW721 pointer registration via untrusted contract-query JSON - (File: precompiles/pointer/pointer.go, precompiles/pointer/legacy/v640/pointer.go, precompiles/pointer/legacy/v65-v67/pointer.go)

### Summary
`AddCW20`/`AddCW721` in the `pointer` precompile blindly `json.Unmarshal` the response of a `QuerySmart`/`QuerySmartSafe` call to an attacker-supplied CosmWasm contract address, then perform unchecked type assertions (`formattedRes["name"].(string)`, `formattedRes["symbol"].(string)`) on the decoded `map[string]interface{}`. Unlike every other precompile executor in this codebase (`addr`, `oracle`, `solo`, `wasmd`), `pointer.PrecompileExecutor.Execute` has no `recover()` guarding the call into `AddCW20`/`AddCW721`/`AddCW1155`.

### Finding Description
Any caller can invoke `addCW20Pointer`/`addCW721Pointer` on the pointer precompile (`0x...100b`) with the address of a CosmWasm contract they control. That contract's `token_info`/`contract_info` query response is JSON-decoded into `map[string]interface{}{}`, and the code immediately does: [1](#0-0) 
`name := formattedRes["name"].(string)` and `symbol := formattedRes["symbol"].(string)`. If the attacker's contract returns a JSON object where `name`/`symbol` are absent (map lookup yields untyped `nil`), or are non-string types (number, bool, object), the type assertion panics — this is functionally the same class of bug as CVE-2018-20195: an unchecked/untyped external input is dereferenced/type-asserted without validation, causing a crash.

Critically, the outer dispatcher `PrecompileExecutor.Execute` in `precompiles/pointer/pointer.go` (and its legacy variants such as `v640`, `v67`) does not wrap the call into `AddCW20`/`AddCW721` with a `recover()`, whereas the equivalent dispatchers for `addr`, `oracle`, and `solo` precompiles all do: [2](#0-1) [3](#0-2) [4](#0-3) 

By contrast: [5](#0-4) 

The panic then propagates up through `DynamicGasPrecompile.RunAndCalculateGas`, whose own `defer` only calls `HandlePrecompileError` on a non-nil `err` return value — it does not `recover()` the panic itself: [6](#0-5) 

### Impact Explanation
Whether this panic is fatal to node liveness depends on whether an outer layer (EVM interpreter's `RunPrecompiledContract`, or the ante/msg-server panic-recovery wrappers seen in `app/app.go`'s `makeGigaDeliverTx`/`ProcessTxsSynchronousGiga`) ultimately catches it and converts it to a reverted call / failed tx. Those app-level wrappers do log-and-convert generic panics ("nil deref from malformed protobuf") into `ErrPanic` ABCI responses rather than crashing the process: [7](#0-6) 
If that is indeed the last line of defense reached, the practical impact is a single failed transaction (denial of service limited to the caller's own tx, not a validator halt or RPC crash) — a low/medium finding, not a node-crashing one. I could not fully verify whether `evmrpc`'s `eth_call`/`eth_estimateGas` paths (used by public RPC, e.g. `evmrpc/simulate.go`) have an equivalent recover before invoking the EVM, though `SimulationAPI.Call` does have its own `recover()` guard: [8](#0-7) 
Given these outer recover layers exist at both the block-processing and JSON-RPC-simulation boundaries, this bug most plausibly manifests as a reliable, cheap way to make a single tx/call fail with an unhandled-panic error rather than a validator-halting or public-RPC-crashing defect — it does not clearly meet the "crash of default-configuration RPC nodes" or "validator halt" bar required by this scan's validation criteria.

### Likelihood Explanation
Trivial to trigger: deploy any CosmWasm contract (e.g., a stub returning `{}` for `token_info`/`contract_info`), call `addCW20Pointer`/`addCW721Pointer` on the pointer precompile with that contract's address. No special privilege needed — this is directly reachable by any CW/EVM user.

### Recommendation
Add the same `defer func() { recover() }()` guard used elsewhere (`addr`, `oracle`, `solo`, `wasmd` executors) around `pointer.PrecompileExecutor.Execute`, and additionally use safe map-based extraction with `ok` checks instead of unchecked type assertions for `formattedRes["name"]`/`formattedRes["symbol"]` in `AddCW20`/`AddCW721` across all pointer precompile versions (`precompiles/pointer/pointer.go` and its `legacy/v552`…`v640` variants).

### Proof of Concept
1. Deploy a CosmWasm contract whose `token_info`/`contract_info` query handler returns `{}` (or `{"name": 123, "symbol": null}`) instead of the expected `{"name": "...", "symbol": "..."}`.
2. From any EOA, call `addCW20Pointer(cwContractAddress)` (or `addCW721Pointer`) on precompile address `0x000000000000000000000000000000000000100b`.
3. `p.wasmdKeeper.QuerySmart` returns the crafted JSON; `json.Unmarshal` succeeds into `formattedRes`; `formattedRes["name"].(string)` panics because the value is `nil`/non-string.
4. Because `pointer.PrecompileExecutor.Execute` has no `recover()`, the panic propagates further than in sibling precompiles, relying entirely on outer framework/app-level recovery to avoid affecting more than the single transaction — behavior that should be explicitly verified/tested rather than relied on implicitly.
