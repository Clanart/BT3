### Title
Missing `debug_redact` enforcement in upb's Text/Debug-String Encoder Leaks Fields Marked Sensitive in the Schema - (File: `upb/text/internal/encode.c`, `upb/text/encode.c`)

### Summary
The upb C runtime's text/debug-string encoders (`upb_TextEncode` and `upb_DebugString`, backed by `_upb_TextEncode_Msg`/`_upb_MessageDebugString`/`_upb_FieldDebugString`) print every field's value unconditionally and never consult the `FieldOptions.debug_redact` annotation. In the C++ and Java implementations of `TextFormat`, this annotation is the explicit, load-bearing mechanism that prevents fields the schema author marked sensitive from appearing in debug/log output. Because upb is the backend for Ruby, PHP, Python (via the upb kernel), Lua, and Rust bindings, any consuming application that logs/dumps an attacker-populated message using these upb-backed debug APIs will disclose data the schema explicitly designates as sensitive.

### Finding Description
Protobuf's `debug_redact` field option is a supported, documented security control (CWE-200 mitigation) whose entire purpose is to prevent “sensitive” fields from being written into debug/text output that might reach logs, crash reports, or other diagnostic channels an attacker or downstream reader can observe.

The C++ reference implementation enforces this invariant explicitly: [1](#0-0) 
which is driven by `TextFormat::GetRedactionState`/`IsOptionSensitive`: [2](#0-1) 
and by the redaction constant used to replace sensitive values: [3](#0-2) 

The Java implementation enforces the identical invariant via `shouldRedact`/`getRedactionState`: [4](#0-3) [5](#0-4) 

A schema explicitly opts fields into this protection, e.g.: [6](#0-5) 

In stark contrast, upb's text/debug-string encoder path never checks `debug_redact` (or any `FieldOptions`) at all. `_upb_FieldDebugString` prints the scalar/message value directly with no redaction gate: [7](#0-6) 
and the top-level per-message walker (`_upb_MessageDebugString`), used by the public `upb_DebugString` API, simply iterates every base field, extension, and unknown field and prints them unconditionally: [8](#0-7) 
The public entry point that documents this as a debug/text-encoding API with no mention of redaction: [9](#0-8) [10](#0-9) 
The non-debug `upb_TextEncode` path (`_upb_TextEncode_Msg`, used by Python/Ruby/Lua bindings for text output) has the identical unconditional printing behavior, again with no `debug_redact` check: [11](#0-10) 

I confirmed via search that no `redact`-related logic exists anywhere in the `upb/` tree outside of generated descriptor accessors for the `debug_redact` option field itself (i.e., the option is *readable* via generated code but never *consulted* by the encoder).

**Failed invariant:** "Fields annotated `debug_redact = true` in the schema must never appear in plaintext in any supported debug/text output API." 
**Attacker-controlled value:** the content of a field the application schema marks `debug_redact = true` (e.g., password, token, PII), populated via an ordinary bounded Protobuf/ProtoJSON parse into a message that the consuming application later logs via `upb_DebugString`/`upb_TextEncode`.
**Missing check:** no lookup of `FieldOptions.debug_redact` (or transitively-sensitive enum options, as C++/Java do) before emitting a field's value.
**Impact:** the sensitive value is written verbatim into logs/diagnostic output that a lower-privileged operator, log-aggregation system, or attacker with log access can read — directly matching the OPC UA advisory's CWE-200/209 exposure-of-sensitive-information class, where a request causes sensitive information to be revealed through a response/diagnostic channel that should have been protected.

### Impact Explanation
This is a genuine confidentiality bypass of a documented protobuf security feature (`debug_redact`), not merely a difference in "allowed interpretation." Any language runtime built on upb (Ruby, PHP, Python-upb, Lua, and Rust bindings that call into `upb_TextEncode`/`upb_DebugString`) silently loses this protection relative to C++/Java, even though the same `.proto` schema and the same `debug_redact` annotations are shared across languages/generators. Applications that rely on `debug_redact` for compliance (e.g., not leaking PII/secrets into logs) are exposed cross-language without any code change on their part — the vulnerability is purely in the runtime backend they happen to use. Severity is Medium, matching the analog's CVSS profile (confidentiality-only, no integrity/availability impact, network-reachable via ordinary data flow, no privileges required).

### Likelihood Explanation
Likelihood is high for any application using upb-backed language bindings that (a) mark at least one field `debug_redact = true` and (b) call the language's standard debug/inspect/to-text function (which maps to `upb_DebugString`/`upb_TextEncode`) on messages that were populated by parsing ordinary, attacker-supplied bounded input. No special privileges, malicious schema, or crafted MiniTable is required — this is the default, documented behavior path.

### Recommendation
Port the C++/Java redaction logic (`TextFormat::GetRedactionState`/`IsOptionSensitive`/`TryRedactFieldValue`) into upb's text encoders: before printing a field's value in `_upb_FieldDebugString` (and the analogous `_upb_TextEncode_Field`), consult the field's `FieldOptions.debug_redact` (and recursively check enum-valued options for `debug_redact`), and substitute a `[REDACTED]`-style marker when true — mirroring the existing C++ `kFieldValueReplacement` behavior. This should apply uniformly to `upb_DebugString`, `upb_TextEncode`, and any downstream language binding (Ruby, PHP, Python, Lua, Rust) that exposes message-to-text/debug functionality via upb.

TextFormat::RedactionState TextFormat::GetRedactionState(
    const FieldDescriptor* field) {
  auto options = field->options();
  auto state = TextFormat::RedactionState{options.debug_redact(), false};
  std::vector<const FieldDescriptor*> field_options;
  const Reflection* reflection = options.GetReflection();
  reflection->ListFields(options, &field_options);
  for (const FieldDescriptor* option : field_options) {
    auto result = TextFormat::IsOptionSensitive(options, reflection, option);
    state = TextFormat::RedactionState{state.redact || result.redact,
                                       state.report || result.report};
  }
  return state;
}

bool TextFormat::Printer::TryRedactFieldValue(
    const Message& message, const FieldDescriptor* field,
    BaseTextGenerator* generator, bool insert_value_separator) const {
  TextFormat::RedactionState redaction_state =
      DescriptorPool::MemoizeProjection(
          field, [](const FieldDescriptor* field) {
            return TextFormat::GetRedactionState(field);
          });
  if (redaction_state.redact) {
    if (redact_debug_string_) {
      IncrementRedactedFieldCounter();
      if (insert_value_separator) {
        generator->PrintMaybeWithMarker(MarkerToken(), ": ");
      }
      generator->PrintString(kFieldValueReplacement);
      if (insert_value_separator) {
        if (single_line_mode_) {
          generator->PrintLiteral(" ");
        } else {
          generator->PrintLiteral("\n");
        }
      }
      return true;
    }
  }
  return false;
}

                                  const upb_MiniTableField* f,
                                  const upb_MiniTable* mt, const char* label,
                                  const upb_MiniTableExtension* ext) {
  UPB_PRIVATE(_upb_TextEncode_Indent)(e);
  const upb_CType ctype = upb_MiniTableField_CType(f);
  const bool is_ext = upb_MiniTableField_IsExtension(f);
  char number[10];  // A 32-bit integer can hold up to 10 digits.
  snprintf(number, sizeof(number), "%" PRIu32, upb_MiniTableField_Number(f));
  // label is to pass down whether we're dealing with a "key" of a map or
  // a "value" of a map.
  if (!label) label = number;

  if (is_ext) {
    UPB_PRIVATE(_upb_TextEncode_Printf)(e, "[%s]", label);
  } else {
    UPB_PRIVATE(_upb_TextEncode_Printf)(e, "%s", label);
  }

  if (ctype == kUpb_CType_Message) {
    UPB_PRIVATE(_upb_TextEncode_Printf)(e, " {");
    UPB_PRIVATE(_upb_TextEncode_EndField)(e);
    e->indent_depth++;
    const upb_MiniTable* subm = ext ? upb_MiniTableExtension_GetSubMessage(ext)
                                    : upb_MiniTable_SubMessage(f);
    UPB_PRIVATE(_upb_MessageDebugString)(e, val.msg_val, subm);
    e->indent_depth--;
    UPB_PRIVATE(_upb_TextEncode_Indent)(e);
    UPB_PRIVATE(_upb_TextEncode_PutStr)(e, "}");
    UPB_PRIVATE(_upb_TextEncode_EndField)(e);
    return;
  }

  UPB_PRIVATE(_upb_TextEncode_Printf)(e, ": ");

  if (ctype ==
      kUpb_CType_Enum) {  // Enum has to be processed separately because of
                          // divergent behavior between encoders
    UPB_PRIVATE(_upb_TextEncode_Printf)(e, "%" PRId32, val.int32_val);
  } else {
    UPB_PRIVATE(_upb_TextEncode_Scalar)(e, val, ctype);
  }

  UPB_PRIVATE(_upb_TextEncode_EndField)(e);
}

void UPB_PRIVATE(_upb_MessageDebugString)(txtenc* e, const upb_Message* msg,
                                          const upb_MiniTable* mt) {
  size_t iter = kUpb_BaseField_Begin;
  const upb_MiniTableField* f;
  upb_MessageValue val;

  // Base fields will be printed out first, followed by extension fields, and
  // finally unknown fields.

  while (UPB_PRIVATE(_upb_Message_NextBaseField)(msg, mt, &f, &val, &iter)) {
    if (upb_MiniTableField_IsMap(f)) {
      _upb_MapDebugString(e, val.map_val, f, mt);
    } else if (upb_MiniTableField_IsArray(f)) {
      // ext set to NULL as we're not dealing with extensions yet
      _upb_ArrayDebugString(e, val.array_val, f, mt, NULL);
    } else {
      // ext set to NULL as we're not dealing with extensions yet
      // label set to NULL as we're not currently working with a MapEntry
      _upb_FieldDebugString(e, val, f, mt, NULL, NULL);
    }
  }

  const upb_MiniTableExtension* ext;
  upb_MessageValue val_ext;
  iter = kUpb_Message_ExtensionBegin;
  while (upb_Message_NextExtension(msg, &ext, &val_ext, &iter)) {
    const upb_MiniTableField* f = &ext->UPB_PRIVATE(field);
    // It is not sufficient to only pass |f| as we lose valuable information
    // about sub-messages. It is required that we pass |ext|.
    if (upb_MiniTableField_IsMap(f)) {
      UPB_UNREACHABLE();  // Maps cannot be extensions.
      break;
    } else if (upb_MiniTableField_IsArray(f)) {
      _upb_ArrayDebugString(e, val_ext.array_val, f, mt, ext);
    } else {
      // label set to NULL as we're not currently working with a MapEntry
      _upb_FieldDebugString(e, val_ext, f, mt, NULL, ext);
    }
  }

  UPB_PRIVATE(_upb_TextEncode_ParseUnknown)(e, msg);
}

size_t upb_DebugString(const upb_Message* msg, const upb_MiniTable* mt,

  e.ptr = buf;
  e.end = UPB_PTRADD(buf, size);
  e.overflow = 0;
  e.indent_depth = 0;

static void _upb_TextEncode_Msg(txtenc* e, const upb_Message* msg,
                                const upb_MessageDef* m) {
  size_t iter = kUpb_Message_Begin;
  const upb_FieldDef* f;
  upb_MessageValue val;

  while (upb_Message_Next(msg, m, e->ext_pool, &f, &val, &iter)) {
    if (upb_FieldDef_IsMap(f)) {
      _upb_TextEncode_Map(e, val.map_val, f);
    } else if (upb_FieldDef_IsRepeated(f)) {
      _upb_TextEncode_Array(e, val.array_val, f);
    } else {
      _upb_TextEncode_Field(e, val, f);
    }
  }

  UPB_PRIVATE(_upb_TextEncode_ParseUnknown)(e, msg);
}
