### Title
Unauthenticated OP_RETURN operator-pubkey in Payout transaction lets an unprivileged attacker permanently orphan a withdrawal's reimbursement path - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
`create_payout_txhandler` places the operator's x-only pubkey in a plain OP_RETURN output that is not covered by the user's `SinglePlusAnyoneCanPay` signature and is not authenticated in any other way. Anyone who can spend the withdrawal UTXO (including the withdrawing user themselves, since they hold their own signature) can construct their own Payout transaction with the same input/output-0 but an arbitrary OP_RETURN value, get it confirmed first, and permanently determine (or erase) which operator, if any, `Verifier::update_finalized_payouts` will ever bind to that withdrawal index.

### Finding Description
The binding the protocol relies on is:
`operator_xonly_pk_recorded(i)` (the value `Verifier::update_finalized_payouts` writes to `withdrawals.payout_payer_operator_xonly_pk` for withdrawal index `i`) `==` `xonly_pk_of_party_who_actually_fronted_output_0(i)`.

Tracing the code:
- `create_payout_txhandler` builds the Payout tx with input 0 = the user's withdrawal UTXO (SIGHASH_SINGLE|AnyoneCanPay, `SpendPath::KeySpend`), output 0 = user payout, output 1 = anchor, output 2 = `op_return_txout(operator_xonly_pk.serialize())`. [1](#0-0) 
- `SinglePlusAnyoneCanPay` only commits to input 0's own prevout and output index 0; it does **not** cover output 1 or output 2 (the OP_RETURN), nor does it constrain what other inputs/outputs the final broadcaster adds. [2](#0-1) 
- `Operator::withdraw` verifies the user signature only against input 0 and then relies on `fund_raw_transaction`/RBF to add its own funding inputs (signed with default SIGHASH_ALL, covering the whole tx) — but nothing prevents a third party from building an entirely different, self-funded transaction that reuses the same signed input 0 and output 0, with any OP_RETURN payload, since they don't need the operator's signature at all if they fund the output themselves. [3](#0-2) 
- `Verifier::update_finalized_payouts` blindly parses whatever OP_RETURN happens to be in the tx that ends up spending `withdrawal_utxo_txid/vout`, with no check against the param

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
