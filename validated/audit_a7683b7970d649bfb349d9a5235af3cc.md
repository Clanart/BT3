The reported issue concerns ERC4626 share-price slippage in a yield vault (assets/shares ratio drifting from 1:1), which has no analog in Clementine's architecture. Clementine's deposit and withdrawal paths use fixed, exact-amount bindings rather than share-based pricing: the move-to-vault transaction always moves exactly `paramset.bridge_amount` [1](#0-0) , and this is enforced again when the aggregator relays it via `send_move_to_vault_tx`, which explicitly checks the output value equals `bridge_amount` [2](#0-1) . Withdrawals are similarly bound to an exact, pre-committed amount verified against the Citrea-registered withdrawal UTXO and signed off-chain by the user, with profitability (not a variable exchange rate) checked before funding [3](#0-2) , and optimistic payouts likewise validate the exact withdrawal UTXO and amount ceiling against the bridge amount [4](#0-3) .

Since there is no share/asset exchange rate that can be manipulated between request and execution, there is no custody-binding equality (e.g., BTC leaving a move-to-vault UTXO vs. a fronted withdrawal) that an MEV-style sandwich attack could break in this codebase.
