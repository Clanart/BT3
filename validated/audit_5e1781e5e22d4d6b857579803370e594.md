### Title
Unauthenticated deep-link / "Open PR from browser" URL action silently checks out attacker-chosen branches or fork PRs in an existing local repository - (File: `app/src/ui/dispatcher/dispatcher.ts`)

### Summary
GitHub Desktop registers custom protocol handlers (`x-github-client://`, `github-mac://`, `github-windows://`, `x-github-desktop-auth://`) and routes any URL received through them straight into `handleAppURL` → `dispatchURLAction`, with no verification that the URL actually originated from github.com or from any trusted context. [1](#0-0) [2](#0-1)  For the `open-repository-from-url` action, if the URL matches a repository the victim already has open in Desktop, Desktop will automatically fetch and **silently checkout** an attacker-specified branch or an attacker-controlled pull-request head, with zero confirmation dialog when the working tree is clean. [3](#0-2) 

### Finding Description
This is the same broken invariant as the Liquity flashloan report: a "callback"/entry point that is supposed to be reachable only by a trusted initiator (Balancer flashloan → the Zapper contract; here, the `openRepo`/PR deep link → GitHub.com's "Open in Desktop"/"View in Desktop" button) is instead reachable by **any untrusted party**, and the receiving code performs a privileged operation on a resource it doesn't verify ownership/initiation of ("Troves we don't own" → "the user's already-cloned repository").

Concretely:
- `parseAppURL` accepts `openRepo/<url>?branch=<name>` and `openRepo/<url>?pr=<number>` from any process that can invoke the registered custom protocol, i.e. any website, email client, chat app, or malicious application on the machine that can trigger `x-github-client://openRepo/...` or `github-mac://openRepo/...`. [4](#0-3) 
- `dispatchURLAction` routes this to `openRepositoryFromUrl`, which — if a **matching repository is already present in the user's repo list** — calls `openBranchNameFromUrl` or `openPullRequestFromUrl` instead of showing the normal "Clone Repository" popup. [5](#0-4) [6](#0-5) 
- `openBranchNameFromUrl` fetches and then calls `checkoutLocalBranch`, which invokes `checkoutBranch` directly — no explicit strategy — meaning if there are no local uncommitted changes, `_checkoutBranch` proceeds straight to `checkoutImplementation` with **no popup at all**. [7](#0-6) [8](#0-7) [9](#0-8) 
- `openPullRequestFromUrl` is worse: it takes `pr` from the attacker-controlled URL, fetches the real PR object via the API (so the PR itself is real, but its head repo/ref is fully attacker-controlled since anyone can open a PR from their own fork), then automatically calls `_checkoutPullRequest`, which **adds a new remote pointing at the attacker's fork** (`addRemote(repository, forkRemoteName, headCloneUrl)`) and checks out that fork's branch — again with no confirmation when the tree is clean. [10](#0-9) [11](#0-10) 
- The only guard analogous to the Liquity `msg.sender == flashLoanProvider` check is `isTrustedIPCSender`, which protects **renderer→main IPC**, not the **OS-level protocol handler → main** boundary; that boundary has no trust check at all. [12](#0-11) [2](#0-1) 

The corrupted value is the repository's checked-out ref/HEAD and its remote list — state the user believes reflects only their own actions but which is actually attacker-controlled input flowing straight from a clicked link.

### Impact Explanation
An attacker who gets a victim to click a crafted link (`x-github-client://openRepo/https://github.com/<org>/<repo>?branch=<attacker-branch>` or `...?pr=<attacker-pr>`) can, for any repository the victim already has open in Desktop:
- Force a silent branch switch to an attacker-chosen branch/fork, so the victim's next commit/push lands on the wrong branch, potentially pushing private/unreleased code into a public fork (data leak) or corrupting what gets pushed/merged.
- Silently add an untrusted remote (`github-desktop-<owner>`) to the local repo config.
- Cause a subsequent build, test run, or commit against attacker-supplied source. Many JS/monorepo projects configure `core.hooksPath` (e.g. via Husky) checked into the repo; switching to a branch that ships a malicious hook file can result in code execution the next time the victim commits, all without the victim ever choosing "checkout" in the UI.

This satisfies the in-scope impact classes: silent corruption of what the user commits/pushes, and a realistic path to code execution via repo-tracked git hooks, triggered purely by an attacker-controlled link — no local access, no leaked credentials, no malware required.

### Likelihood Explanation
Moderate-to-high. The prerequisite is simply that the victim already has the target repository cloned/open in Desktop (very common for popular OSS repos or company monorepos) and clicks a link — the classic "Open in Desktop" style deep link is a normal, expected UX pattern that users are trained to click, making social-engineering-free delivery plausible (e.g., embedded in a README, GitHub comment, or any webpage). The only user action required is a single click; no dialogs are shown to distinguish this from routine GitHub.com "Open in Desktop" usage.

### Recommendation
Do not let the protocol-handler/URL-action path perform destructive/state-changing operations (checkout, remote creation) without explicit user confirmation, mirroring how `_checkoutBranch` already gates on uncommitted changes:
- Always show a confirmation dialog (repository name, target branch/PR, and the fact that a remote will be created) before checking out a branch/PR reached via `open-repository-from-url`, regardless of whether the working tree is clean.
- Treat `openBranchNameFromUrl`/`openPullRequestFromUrl` checkout the same as the `AskForConfirmation`/`StashAndSwitchBranch` popup path instead of calling `checkoutBranch` unconditionally.
- Consider binding a one-time, app-generated correlation token to legitimate "Open in Desktop" links (as GitHub.com already knows the Desktop client) so unsolicited third-party links cannot trigger the flow at all — the same mitigation pattern (transient operation id / trusted-initiator check) proposed in the original report.

### Proof of Concept
1. Victim clones `https://github.com/acme/private-tool` in GitHub Desktop and keeps the app running.
2. Attacker crafts and delivers (e.g., in a chat message, doc, or malicious webpage) a link:
   `x-github-client://openRepo/https://github.com/acme/private-tool?branch=malicious-branch`
   (branch previously pushed by the attacker to a public/permissioned ref, or via `?pr=<number>` pointing at the attacker's own fork PR against `acme/private-tool`).
3. Victim clicks the link (e.g., in a README rendered on GitHub, which will happily linkify a registered custom protocol).
4. `handleAppURL` → `parseAppURL` → `dispatchURLAction('open-repository-from-url')` → `openRepositoryFromUrl` finds the already-open `acme/private-tool` repository and, since the working tree is clean, silently fetches and checks out `malicious-branch` (or adds the attacker's fork remote and checks out the PR head) with **no dialog shown**. [3](#0-2) 
5. The victim, unaware their working copy changed, continues working/committing/pushing on top of attacker-controlled content, or a repo-tracked hook (e.g. Husky `pre-commit`) shipped in that branch executes on the victim's next `git commit`.

  private async openBranchNameFromUrl(
    url: string,
    branchName: string
  ): Promise<Repository | null> {
    const repository = await this.openOrCloneRepository(url)

    if (repository === null) {
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    // if the repo has a remote, fetch before switching branches to ensure
    // the checkout will be successful. This operation could be a no-op.
    await this.appStore._fetch(repository, FetchType.UserInitiatedTask)

    await this.checkoutLocalBranch(repository, branchName)

    return repository
  }

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }
    if (!isRepositoryWithGitHubRepository(repository)) {
      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    if (pullRequest.head.repo === null) {
      return null
    }

    await this.appStore._checkoutPullRequest(
      repository,
      pullRequest.number,
      pullRequest.head.repo.owner.login,
      pullRequest.head.repo.clone_url,
      pullRequest.head.ref
    )

    return repository
  }

  private async checkoutLocalBranch(repository: Repository, branch: string) {
    let shouldCheckoutBranch = true

    const state = this.repositoryStateManager.get(repository)
    const branches = state.branchesState.allBranches

    const { tip } = state.branchesState

    if (tip.kind === TipState.Valid) {
      shouldCheckoutBranch = tip.branch.nameWithoutRemote !== branch
    }

    const localBranch = branches.find(b => b.nameWithoutRemote === branch)

    // N.B: This looks weird, and it is. _checkoutBranch used
    // to behave this way (silently ignoring checkout) when given
    // a branch name string that does not correspond to a local branch
    // in the git store. When rewriting _checkoutBranch
    // to remove the support for string branch names the behavior
    // was moved up to this method to not alter the current behavior.
    //
    // https://youtu.be/IjmtVKOAHPM
    if (shouldCheckoutBranch && localBranch !== undefined) {
      await this.checkoutBranch(repository, localBranch)
    }
  }

  public async _checkoutPullRequest(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,
    headRefName: string
  ): Promise<void> {
    const prBranch = await this._findPullRequestBranch(
      repository,
      prNumber,
      headRepoOwner,
      headCloneUrl,
      headRefName
    )
    if (prBranch !== undefined) {
      await this._checkoutBranch(repository, prBranch)
      this.statsStore.increment('prBranchCheckouts')
    }
  }

  public async _findPullRequestBranch(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,
    headRefName: string
  ): Promise<Branch | undefined> {
    const gitStore = this.gitStoreCache.get(repository)
    const remotes = await getRemotes(repository)

    // Find an existing remote (regardless if set up by us or outside of
    // Desktop).
    let remote = remotes.find(r => urlMatchesRemote(headCloneUrl, r))

    // If we can't find one we'll create a Desktop fork remote.
    if (remote === undefined) {
      try {
        const forkRemoteName = forkPullRequestRemoteName(headRepoOwner)
        remote = await addRemote(repository, forkRemoteName, headCloneUrl)
      } catch (e) {
        this.emitError(
          new Error(
            `Couldn't find PR branch, adding remote failed: ${e.message}`
          )
        )
        return
      }
    }

    const remoteRef = `${remote.name}/${headRefName}`

    // Start by trying to find a local branch that is tracking the remote ref.
    let existingBranch = gitStore.allBranches.find(
      x => x.type === BranchType.Local && x.upstream === remoteRef
    )

    // If we found one, let's check it out and get out of here, quick
    if (existingBranch !== undefined) {
      return existingBranch
    }

    const findRemoteBranch = (name: string) =>
      gitStore.allBranches.find(
        x => x.type === BranchType.Remote && x.name === name
      )

    // No such luck, let's see if we can at least find the remote branch then
    existingBranch = findRemoteBranch(remoteRef)

    // It's quite possible that the PR was created after our last fetch of the
    // remote so let's fetch it and then try again.
    if (existingBranch === undefined) {
      try {
        await this._fetchRemote(repository, remote, FetchType.UserInitiatedTask)
        existingBranch = findRemoteBranch(remoteRef)
      } catch (e) {
        log.error(`Failed fetching remote ${remote?.name}`, e)
      }
    }

    if (existingBranch === undefined) {
      this.emitError(
        new Error(
          `Couldn't find branch '${headRefName}' in remote '${remote.name}'. ` +
            `A common reason for this is that the PR author has deleted their ` +
            `branch or their forked repository.`
        )
      )
      return
    }

    // For fork remotes we checkout the ref as pr/[123] instead of using the
    // head ref name since many PRs from forks are created from their default
    // branch so we'll have a very high likelihood of a conflicting local branch
    const isForkRemote =
      remote.name !== gitStore.defaultRemote?.name &&
      remote.name !== gitStore.upstreamRemote?.name

    if (isForkRemote) {
      return await this._createBranch(
        repository,
        `pr/${prNumber}`,
        remoteRef,
        false
      )
    }

    return existingBranch
  }

import { WebContents } from 'electron'

// WebContents id of trusted senders of IPC messages. This is used to verify
// that only IPC messages sent from trusted senders are handled, as recommended
// by the Electron security documentation:
// https://github.com/electron/electron/blob/main/docs/tutorial/security.md#17-validate-the-sender-of-all-ipc-messages
const trustedSenders = new Set<number>()

/** Adds a WebContents instance to the set of trusted IPC senders. */
export const addTrustedIPCSender = (wc: WebContents) => {
  trustedSenders.add(wc.id)
  wc.on('destroyed', () => trustedSenders.delete(wc.id))
}

/** Returns true if the given WebContents is a trusted sender of IPC messages. */
export const isTrustedIPCSender = (wc: WebContents) => trustedSenders.has(wc.id)
