## Title
Permanently cached, unauthenticated "is this a GitHub host" signal is trusted without revalidation, letting a hijacked/MITM endpoint keep GitHub-Enterprise trust status forever - (File: `app/src/lib/endpoint-capabilities.ts`, `app/src/lib/api.ts`, `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The external report's root cause is generic: a security-relevant value fetched from an external source is cached and trusted indefinitely with no timestamp/staleness check. Desktop has a structurally identical pattern: the "is this endpoint a GitHub/GHE host" determination and its associated version fingerprint are fetched once, written to `localStorage`, and then trusted forever — the exact code path that decides whether Desktop's Git credential trampoline treats an endpoint as GitHub-authenticated.

### Finding Description
`getEndpointVersion`/`updateEndpointVersion` in `app/src/lib/endpoint-capabilities.ts:70-100` persist the `x-github-enterprise-version` response header to `localStorage`, keyed only by the endpoint string, with no expiry, no timestamp, and no revalidation logic: [1](#0-0) 

`isGitHubHost` in `app/src/lib/api.ts` uses this cache as a fast-path: if any version was ever recorded for the endpoint, it returns `true` without making a new request at all: [2](#0-1) 

Only on cache miss does it perform a live check, and that live check is a single unauthenticated `HEAD /meta` request with certificate-error suppression enabled for exactly that URL: [3](#0-2) [4](#0-3) 

This "is-GitHub" signal is not cosmetic — it feeds the credential trampoline's trust decision. `getEndpointKind` in `app/src/lib/trampoline/trampoline-credential-helper.ts` calls `isGitHubHost(endpoint)` and classifies the endpoint as `'enterprise'` (i.e., a first-party GitHub credential domain) purely based on this cached/unauthenticated signal: [5](#0-4) 

Once classified as `'enterprise'`, `getCredential` either hands over a stored GitHub account's token via `findGitHubTrampolineAccount` (matched only by URL origin, not by any freshness/identity pinning) or prompts the user with the trusted "Sign in to GitHub" UI instead of a generic credential prompt: [6](#0-5) [7](#0-6) 

Just like the oracle bug (a price fetched once and trusted forever regardless of age), this "is GitHub" fingerprint is fetched once and trusted forever regardless of whether the host behind that domain has since changed (domain expiry/re-registration, subdomain takeover, DNS change, or a MITM proxy the user's git traffic passes through). Nothing in `getEndpointVersion` or `isGitHubHost` ever re-checks or expires the record — there is no "max staleness" concept anywhere in this cache.

### Impact Explanation
If a domain that Desktop previously recorded as a GitHub/GHE host (e.g., a company's `github.example.com` GHE instance the user signed into, or a proxy/relay presenting itself as one) is later taken over by an attacker — via DNS hijack, subdomain takeover after decommissioning, or a MITM position on the network path — Desktop will continue treating that endpoint as an authenticated-GitHub-domain forever, because the cache never expires and is never revalidated. This causes the credential trampoline to keep classifying `git` operations against that host as `'enterprise'` rather than `'generic'`, which:
- Skips the generic-credential-helper/prompt path entirely (`storeCredential`/`eraseCredential` also gate on the same `getEndpointKind` classification), and
- Continues to source credentials from `findGitHubTrampolineAccount`, sending whichever stored GitHub token matches that origin to the now-attacker-controlled server.

This is credential exfiltration to an attacker-controlled git endpoint with the trust decision made from stale, unauthenticated, un-timestamped data.

### Likelihood Explanation
Moderate-to-low but plausible: it requires the attacker to gain control of the network path or the domain behind a previously-legitimate GHE endpoint (subdomain takeover / DNS hijack / on-path proxy), which is squarely a "git remote/proxy response" attacker model rather than local/physical access or leaked credentials. The bug is not that an attacker can arbitrarily choose a target — it's that Desktop's guard against a compromised endpoint (fetching and re-checking `isGitHubHost`) is permanently bypassed once one legitimate response has ever been seen, removing the only mitigating control an app of this design has against exactly this class of takeover.

### Recommendation
- Add an expiry/TTL (and ideally a fetch timestamp) to the `endpoint-capabilities.ts` version cache, and re-validate `isGitHubHost` periodically instead of short-circuiting forever once a version has been observed.
- Do not let a purely cached, unauthenticated HEAD-request signal gate credential-trampoline trust classification (`getEndpointKind`) — require either a live check per credential request or binding to the account's own recorded endpoint/certificate rather than hostname-only matching.
- Consider pinning GHE endpoint identity (e.g., certificate fingerprint) at the time of sign-in and invalidating the cached "is GitHub host" state if that identity changes.

### Proof of Concept
1. User adds/signs into a GHE endpoint `github.example.com`; Desktop performs the `HEAD /meta` check in `isGitHubHost` (`app/src/lib/api.ts:2467-2483`), the server returns `x-github-enterprise-version` and `x-github-request-id`, and `updateEndpointVersion` permanently caches this in `localStorage` (`app/src/lib/endpoint-capabilities.ts:91-99`).
2. Time passes; the company decommissions the box, and the DNS record/subdomain is later taken over by an attacker (or the user's traffic to that host is now intercepted by a malicious proxy).
3. User performs a `git fetch/push` against a remote at that same hostname. The trampoline credential helper calls `getEndpointKind`, which calls `isGitHubHost(endpoint)`; because `getEndpointVersion(endpoint) !== null` from the stale cache, it returns `true` immediately with **no new network request and no revalidation** (`app/src/lib/api.ts:2461-2463`).
4. `getEndpointKind` returns `'enterprise'`; `getCredential` looks up the account via `findGitHubTrampolineAccount` matching solely on origin (`app/src/lib/trampoline/find-account.ts:26-28`) and hands the stored GitHub token to the now-attacker-controlled server as part of the git credential protocol (`app/src/lib/trampoline/trampoline-credential-helper.ts:50-57, 94-99`).

The attacker never had to be online at the time the cache was written, and the user is not tricked into any unnatural step — the stale trust decision, not attacker cleverness, is what leaks the token.

export function getEndpointVersion(endpoint: string) {
  const key = endpointVersionKey(endpoint)
  const cached = versionCache.get(key)

  if (cached !== undefined) {
    return cached
  }

  const raw = localStorage.getItem(key)
  const parsed = raw === null ? null : semver.parse(raw)

  if (parsed !== null) {
    versionCache.set(key, parsed)
  }

  return parsed
}

/**
 * Update the known version number for a given endpoint
 */
export function updateEndpointVersion(endpoint: string, version: string) {
  const key = endpointVersionKey(endpoint)

  if (rawVersionCache.get(key) !== version) {
    const parsed = semver.parse(version)
    localStorage.setItem(key, version)
    rawVersionCache.set(key, version)
    versionCache.set(key, parsed)
  }
}

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

export async function findGitHubTrampolineAccount(
  accountsStore: AccountsStore,
  remoteUrl: string

  const accounts = await accountsStore.getAll()
