Confirmed: `create_new_mirror()` in `chia/data_layer/data_layer_wallet.py` places `launcher_id` as a plain memo on a coin sent to the fixed `create_mirror_puzzle()` puzzle hash — it does not check that the caller owns or controls that `launcher_id`/store. Any wallet user can therefore mint a mirror "announcement" for **any** existing DataLayer store id, embedding arbitrary URLs.

### Title
Unauthenticated SSRF via arbitrary Data Layer mirror URLs consumed by `fetch_and_validate()` / `http_download()` - (File: `chia/data_layer/data_layer_wallet.py`)

### Summary
The DataLayer mirror mechanism lets any wallet holder publish an on-chain "mirror" coin that associates a completely attacker-chosen list of URLs with any store's `launcher_id`, with no ownership check. Any other node that subscribes to (or owns/tracks) that store id will automatically pull these URLs into its local server list and issue outbound HTTP GET requests to them from `http_download()`, exactly analogous to the Pydio remote-link SSRF (CVE-2019-15033), where a user-controlled `file=` parameter caused the server to fetch attacker-specified (including internal) addresses.

### Finding Description
`DataLayerWallet.create_new_mirror()` [1](#0-0)  builds a standard coin spend to the fixed `create_mirror_puzzle()` puzzle hash with `memos=[[launcher_id, *(url for url in urls)]]` — `launcher_id` is taken directly from the RPC caller's request and is never checked against the caller's own owned singletons (`get_owned_singletons()` is a separate, unrelated codepath) [2](#0-1) .

The `dl_new_mirror` wallet RPC directly forwards `request.launcher_id` from the caller into `create_new_mirror()` with no ownership validation: [3](#0-2) . The DataLayer service's `add_mirror()` RPC likewise only validates that the URL list is non-empty: [4](#0-3) .

When a mirror coin is created, any peer wallet tracking that `launcher_id` decodes and stores the URLs unconditionally via `coin_added()`: [5](#0-4) . These URLs then flow into `update_subscriptions_from_wallet()` [6](#0-5)  and are subsequently used by `fetch_and_validate()` to pick a server and download from it via `insert_from_delta_file()` → `download_file()` → `http_download()`, which performs a raw `aiohttp` GET to `server_info.url + "/" + filename` with a user/attacker-controlled host: [7](#0-6) , invoked from `DataLayer.fetch_and_validate()` [8](#0-7) .

The `.cursor/context/data-layer.md` design notes explicitly acknowledge mirror/plugin URLs as "external trust inputs," but the trust boundary described there covers file-content validation, not the SSRF risk of the outbound request destination itself [9](#0-8) .

### Impact Explanation
Any Chia user (unprivileged wallet holder, no special permissions) can, for the cost of a mirror-coin transaction fee, cause every other node that syncs/subscribes to a targeted DataLayer store to issue automatic outbound HTTP requests to attacker-chosen addresses — including RFC1918 intranet addresses, cloud metadata endpoints (e.g., `169.254.169.254`), or other internal services reachable from the victim's `chia data_layer` process. This is a server-side request forgery that can be used for internal network reconnaissance/pivoting, or to trigger effects on internal HTTP endpoints, from a remote, unauthenticated (relative to the victim) attacker. It does not directly forge coins or breach consensus, but it is a genuine network-reachable vulnerability triggered by ordinary wallet/DL actions, matching the class and severity profile of the reference CVE.

### Likelihood Explanation
Likelihood is high for any Chia user who runs `chia data_layer` and subscribes to third-party stores (a normal use case for DataLayer, which is explicitly designed for cross-user store sharing). The attacker only needs to spend a small amount plus a fee to publish a mirror coin for a target `launcher_id`; no cooperation from the store owner is required since `create_new_mirror` performs no ownership check.

### Recommendation
- In `DataLayerWallet.create_new_mirror()` / the `dl_new_mirror` RPC path, restrict mirror creation to store ids owned by the caller's wallet (mirroring the existing "ownership" check pattern used elsewhere, e.g. `batch_insert()`'s DataLayer-wallet ownership guard).
- Independently, treat mirror/subscription URLs as untrusted network destinations in `http_download()`/`get_downloader()`: resolve and validate hostnames against private/loopback/link-local ranges before connecting, and support an opt-in allow-list or a `deny_private_networks` config similar to standard SSRF mitigations.
- Consider requiring explicit user confirmation before adding a discovered mirror URL to the active server list.

### Proof of Concept
1. Attacker wallet (no relationship to store `S`) calls `dl_new_mirror` (or DataLayer RPC `add_mirror`) with `launcher_id = S`, `urls = ["http://169.254.169.254/latest/meta-data/", "http://10.0.0.5:8080/admin"]`, and a small amount/fee.
2. The mirror coin confirms on-chain; any node tracking `S` (e.g., a wallet that has run `dl_track_new` or subscribed via `chia data layer subscribe`) picks up the mirror through `coin_added()` → `update_subscriptions_from_wallet()`.
3. On its next `periodically_manage_data()` cycle, the victim's DataLayer service calls `fetch_and_validate(S)`, which selects the malicious URL from `get_available_servers_for_store()` and calls `http_download()`, issuing an outbound GET to the attacker-chosen internal address from the victim host.

        self,
        request: DLNewMirror,
        action_scope: WalletActionScope,
        extra_conditions: tuple[Condition, ...] = tuple(),
    ) -> DLNewMirrorResponse:
        """Add a new on chain message for a specific singleton"""
        if self.service.wallet_state_manager is None:
            raise ValueError("The wallet service is not currently initialized")

        dl_wallet = await self.service.wallet_state_manager.get_dl_wallet()
        async with self.service.wallet_state_manager.lock:
            await dl_wallet.create_new_mirror(
                request.launcher_id,
                request.amount,
                Mirror.encode_urls(request.urls),
                action_scope,
                fee=request.fee,
                extra_conditions=extra_conditions,
            )

        # tx_endpoint will take care of default values here
        return DLNewMirrorResponse(unsigned_transactions=[], transactions=[])

async def http_download(
    target_filename_path: Path,

    server_info: ServerInfo,

    log: logging.Logger,
    max_delta_file_size: int,

    """

    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
