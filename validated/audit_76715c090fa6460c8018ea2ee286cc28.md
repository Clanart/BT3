### Title
Unclaimed self-pool rewards are not settled on PlotNFT ownership transfer, letting the new owner claim rewards earned by the previous owner - (File: chia/wallet/plotnft_wallet/plotnft_wallet.py)

### Summary
`PlotNFT2Wallet.transfer_plotnft()` changes only the `user_config` (owner key) on the PlotNFT singleton, but does not spend, forward, or otherwise settle the unclaimed self-pooling reward coins already sitting at the plotnft's `p2_singleton_puzzle_hash`. Because `p2_singleton_puzzle_hash` is a function of the singleton's `launcher_id` only, and `claim_rewards()` later sweeps *all* unspent reward coins recorded for that `plotnft_id` to whatever `rewards_claim_puzhash`/`payout_instructions` is configured at claim time, the new owner (post-transfer) inherits and can claim rewards that accrued while the previous owner held the PlotNFT — with no mechanism for the prior owner to claim their share first or be compensated.

### Finding Description
- `p2_singleton_puzzle_hash` is derived solely from `plotnft_id` (`RewardPuzzle(singleton_id=self.plotnft_id).puzzle_hash()`), so it never changes across an ownership transfer: [1](#0-0) 
- `transfer_plotnft()` builds a spend that only replaces `user_config` on the singleton (`plotnft.new_user_config(...)`), leaving any already-farmed-but-unclaimed reward coins at the old `p2_singleton_puzzle_hash` completely untouched by the transfer transaction: [2](#0-1) 
- `claim_rewards()` looks up all currently-tracked, unclaimed `PoolReward`s for `self.plotnft_id` via `plotnft2_store.get_pool_rewards`, sums them, and pays the total to `self.rewards_claim_puzhash` — it has no concept of "who owned the PlotNFT when this reward accrued": [3](#0-2) 
- `rewards_claim_puzhash` is read from a `PoolingShareState` config entry keyed only by `p2_singleton_puzzle_hash`, and that YAML mirror's `payout_instructions`/`owner_public_key` gets overwritten on the new owner's sync of the post-transfer coin (`coin_added` updates `pool_config.owner_public_key`/`key_derivation_index` for the same `p2_singleton_puzzle_hash` entry): [4](#0-3) 
- This is structurally analogous to the reported Arrakis issue: a privilege/role change on a shared value-accruing position (`manager` in Arrakis, PlotNFT `user_config` owner here) happens without first settling the value that already accrued to that position (`managerBalance0/1` and pool fees in Arrakis; unclaimed p2-singleton pool rewards here), so the party who earned it can lose it to whoever holds control after the change.

### Impact Explanation
If a PlotNFT owner farms self-pooled blocks and then transfers the PlotNFT to another of their own wallets (or, more importantly, sells/transfers it to a third party) before calling `claim_rewards()`, the previously-farmed-but-unclaimed reward coins at the (unchanged) `p2_singleton_puzzle_hash` become claimable exclusively by whoever now controls the singleton's inner puzzle (the new owner key), since claiming requires spending authority tied to the current `user_config` synthetic pubkey. The prior owner has no path to recover their share once the transfer confirms — this is a direct, spend-triggered loss of previously-earned XCH rewards for one party and an unearned gain for the other, satisfying "concrete unsigned or unauthorized coin movement" from the prior owner's perspective (their earned funds move to the new owner without their added consent to give up rewards).

### Likelihood Explanation
This requires only normal use of the documented `plotnft_transfer` wallet RPC/CLI feature (`chia/cmds/plotnft.py` `TransferPlotNFTCMD`, `chia/wallet/wallet_rpc_api.py:plotnft_transfer`) combined with the also-normal practice of not immediately claiming self-pool rewards after every block. Since self-pooled rewards can accumulate over many blocks before a user runs `claim`, and transfer is a supported, low-friction operation (single fee, single spend), the window where unclaimed rewards exist at transfer time is realistic and likely to occur in ordinary use, especially in any marketplace/sale-of-PlotNFT scenario.

### Recommendation
Before allowing `transfer_plotnft()` to proceed, require that all currently-tracked unclaimed pool rewards for the PlotNFT (`plotnft2_store.get_pool_rewards`) be claimed to the current owner first (fail the transfer, or auto-claim as an atomic part of the transfer spend bundle, paying to the current `rewards_claim_puzhash` before the ownership-changing spend is broadcast). Alternatively, block transfer while `get_pool_rewards()` is non-empty, mirroring how other pool-wallet operations already gate on "unconfirmed"/pending state.

### Proof of Concept
1. Create a PlotNFT2 in self-pooling mode and farm several blocks to it so that multiple `PoolReward` coins accumulate at `p2_singleton_puzzle_hash` (see farming setup pattern used in `chia/_tests/pools/test_pool_rpc.py:632-712`, adapted to `PlotNFT2Wallet`).
2. Do not call `claim_rewards`/`pw_absorb_rewards`.
3. Call `plotnft_transfer` (`TransferPlotNFTCMD` / `PlotNFT2Wallet.transfer_plotnft`) to move ownership to a different local (or, conceptually, third-party) fingerprint, as exercised in `chia/_tests/wallet/plotnft_wallet/test_plotnft_wallet.py:514-543` and `chia/_tests/pools/test_pool_cmdline.py:834-904`.
4. Confirm the transfer transaction.
5. From the new-owner wallet, call `pw_absorb_rewards` → `PlotNFT2Wallet.claim_rewards()`; observe that the full accumulated reward total (including rewards farmed before the transfer under the old owner) is paid out to the new owner's `rewards_claim_puzhash`, with no compensation path back to the original owner.

    async def transfer_plotnft(
        self,
        *,
        action_scope: WalletActionScope,
        target_wallet_fingerprint: int,
        fee: uint64 = uint64(0),
        extra_conditions: tuple[Condition, ...] = tuple(),
    ) -> None:
        """
        Because the wallet doesn't have broad support for MIPS-style custody, transferring using addresses is
        a bit complicated because transferring to the wrong kind of address could leave the wallet unable to
        sync/spend the PlotNFT. As a guard, we implement this endpoint as a transfer between local keys to make
        sure that we generate the correct kind of inner puzzle.

        This is not necessarily a permanent restriction, but solves the primary use case of transferring between
        a user's own wallets and keeps the implementation relatively simple for now.
        """
        plotnft = await self.get_current_plotnft()
        fee_hook = CreateCoinAnnouncement(msg=b"", coin_id=plotnft.coin.name())
        root_pubkey = await self.wallet_state_manager.wallet_node.keychain_proxy.get_key_for_fingerprint(
            fingerprint=target_wallet_fingerprint, private=False
        )
        if root_pubkey is None:
            raise RuntimeError(f"Error retrieving key for fingerprint {target_wallet_fingerprint}")
        wallet_pubkey = master_pk_to_wallet_pk_unhardened(root_pubkey, index=uint32(0))
        synthetic_pubkey = self.xch_wallet.convert_public_key_to_synthetic(wallet_pubkey)
        hint = self.xch_wallet.puzzle_hash_for_pk(wallet_pubkey)
        new_user_config = UserConfig(synthetic_pubkey=synthetic_pubkey)
        coin_spends = plotnft.new_user_config(
            user_config=new_user_config,
            hint=hint,
            extra_conditions=(fee_hook, *extra_conditions),
        )
        if fee > 0:
            await self.xch_wallet.create_tandem_xch_tx(
                fee=fee,
                action_scope=action_scope,
                extra_conditions=(fee_hook.corresponding_assertion(),),
            )

        spend_bundle = WalletSpendBundle(coin_spends, G2Element())
