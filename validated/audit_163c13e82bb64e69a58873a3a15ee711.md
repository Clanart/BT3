### Title
Unmetered PDA derivation in `translate_signers` allows CPI signer verification cost to scale without corresponding compute charge - (File: `program-runtime/src/cpi.rs`)

### Summary
`translate_signers` performs one `Pubkey::create_program_address` call per signer-seed-set supplied to a CPI (up to `MAX_SIGNERS` sets, each with up to `MAX_SEEDS` seeds), but unlike the standalone `sol_create_program_address` syscall it never charges `create_program_address_units` for any of these derivations. `cpi_common` only charges the flat `invoke_units` cost once per CPI call, so an attacker can force many SHA256-based PDA derivations per CPI invocation for a cost that does not scale with the amount of derivation work actually performed.

### Finding Description
`cpi_common` charges compute for the CPI call exactly once via the flat `invoke_units` fee: [1](#0-0) 

It then calls `translate_signers`, which iterates over up to `MAX_SIGNERS` seed sets and, for each one, translates the seed slices and calls `Pubkey::create_program_address` directly — with no `invoke_context.compute_meter.consume_checked(...)` call anywhere in this function: [2](#0-1) 

Compare this to the dedicated `SyscallCreateProgramAddress` syscall, which explicitly meters every derivation attempt with `create_program_address_units` before doing the same `Pubkey::create_program_address` work: [3](#0-2) 

and `SyscallTryFindProgramAddress`, which charges `create_program_address_units` for every bump-seed iteration it tries: [4](#0-3) 

`ComputeBudget`/`SVMTransactionExecutionCost` explicitly document `create_program_address_units` as "Number of compute units consumed by a create_program_address call," implying every such call should be priced: [5](#0-4) 

Because `translate_signers` calls `Pubkey::create_program_address` (a SHA256-based, non-trivial elliptic-curve-off-curve check) once per signer-seed-set without any metering, an attacker-controlled sBPF program can pass `signers_seeds_len` up to `MAX_SIGNERS` with maximal seed counts/sizes on every single CPI call, causing up to `MAX_SIGNERS` PDA derivations to execute per CPI while the compute meter is only debited the single flat `invoke_units` charge (plus unrelated translation-cost charges for instruction data/account metas, which do not account for signer-seed derivation work). This is a real accounting gap: the only bound on `translate_signers`'s CPU work is the transaction-wide `MAX_SIGNERS`/`MAX_SEEDS`/`MAX_SEED_LEN` limits, not compute-unit metering, meaning the number of hashing operations performed for signer verification is decoupled from the number of compute units actually charged for that work.

### Impact Explanation
This is a materially underpriced compute-cost bug: the on-chain price (`invoke_units`, a fixed CPI overhead) does not scale with the actual CPU work performed in `translate_signers` when maximal signer-seed sets are supplied, unlike the direct-syscall path which correctly charges `create_program_address_units` per attempt. An attacker's own unprivileged sBPF program can repeatedly issue CPIs with maxed-out `signers_seeds_len`/seed sizes within its compute budget, executing more actual PDA-derivation hashing work per compute unit charged than the fee schedule intends, degrading validator processing efficiency relative to the CU price paid. This maps to the "materially underpriced compute" bounty category referenced in the rules.

### Likelihood Explanation
This requires only an unprivileged attacker who deploys their own sBPF program and calls a CPI (`invoke_signed`) with attacker-controlled seed data — no special privileges, staked node, or leader control needed. The relevant call path (`cpi_common` → `translate_signers`) is on every signed CPI, making the missing charge deterministically reproducible on every invocation with non-trivial seed sets.

### Recommendation
Add a `create_program_address_units` charge via `invoke_context.compute_meter.consume_checked(...)` inside `translate_signers` for each `Pubkey::create_program_address` invocation (i.e., once per signer-seed-set processed), mirroring the metering already done in `SyscallCreateProgramAddress`/`SyscallTryFindProgramAddress`, so the CU cost of CPI signer verification scales with `signers_seeds_len` and the number of derivations actually attempted.

#[test]
fn test_translate_signers_unmetered_pda_derivation() {
    // Build an invoke_context/mock memory mapping identical to `test_translate_signers`,
    // but populate MAX_SIGNERS signer-seed sets, each with MAX_SEEDS seeds of MAX_SEED_LEN bytes.
    let transaction_accounts =
        transaction_with_one_writable_instruction_account(b"foo".to_vec());
    mock_invoke_context!(
        invoke_context, transaction_context, b"instruction data",
        transaction_accounts, 0, &[1]
    );

    let program_id = Pubkey::new_unique();
    // construct `signers_seeds_len` = MAX_SIGNERS worth of maximal seed sets in VM memory
    // (extend `mock_signers` helper to accept multiple seed sets).

    let remaining_before = invoke_context.compute_meter.0.get();
    let create_pda_cost = invoke_context.get_execution_cost().create_program_address_units;

    let _signers = translate_signers(
        &program_id, vm_addr, MAX_SIGNERS as u64, &invoke_context,
    ).unwrap();

    let consumed = remaining_before - invoke_context.compute_meter.0.get();

    // EXPECTED (if properly metered): consumed >= create_pda_cost * MAX_SIGNERS
    // ACTUAL (current code): consumed == 0, because translate_signers never calls
    // compute_meter.consume_checked for create_program_address calls.
    assert!(
        consumed >= create_pda_cost.saturating_mul(MAX_SIGNERS as u64),
        "translate_signers performed {} PDA derivations but charged only {} CU (expected >= {})",
        MAX_SIGNERS, consumed, create_pda_cost.saturating_mul(MAX_SIGNERS as u64)
    );
}

pub fn translate_signers(
    program_id: &Pubkey,
    signers_seeds_addr: u64,
    signers_seeds_len: u64,
    invoke_context: &InvokeContext,
) -> Result<Vec<Pubkey>, Error> {
    let check_aligned = invoke_context.get_check_aligned();
    let memory_mapping = invoke_context.memory_contexts.memory_mapping()?;
    if signers_seeds_len > 0 {
        let signers_seeds = translate_slice::<VmSlice<VmSlice<u8>>>(
            memory_mapping,
            signers_seeds_addr,
            signers_seeds_len,
            check_aligned,
        )?;
        if signers_seeds.len() > MAX_SIGNERS {
            return Err(Box::new(CpiError::TooManySigners));
        }
        Ok(signers_seeds
            .iter()
            .map(|signer_seeds| {
                let untranslated_seeds = translate_slice::<VmSlice<u8>>(
                    memory_mapping,
                    signer_seeds.ptr(),
                    signer_seeds.len(),
                    check_aligned,
                )?;
                if untranslated_seeds.len() > MAX_SEEDS {
                    return Err(Box::new(InstructionError::MaxSeedLengthExceeded) as Error);
                }
                let seeds_bytes = untranslated_seeds
                    .iter()
                    .map(|untranslated_seed| {
                        translate_vm_slice(untranslated_seed, memory_mapping, check_aligned)
                    })
                    .collect::<Result<Vec<_>, Error>>()?;
                Pubkey::create_program_address(&seeds_bytes, program_id)
                    .map_err(|err| Box::new(CpiError::BadSeeds(err)) as Error)
            })
            .collect::<Result<Vec<_>, Error>>()?)
    } else {
        Ok(vec![])
    }
}
