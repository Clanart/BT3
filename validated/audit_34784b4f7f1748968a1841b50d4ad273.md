## Analog Found

### Title
Missing non-payable check on `distribution.rewards()` permanently strands wei sent to the precompile - (File: precompiles/distribution/distribution.go)

### Summary
The distribution precompile validates `msg.value` with `pcommon.ValidateNonPayable` on every state-mutating and view method except one: `rewards()`. Unlike the `CEtherDelegator` bug (a spurious non-payable check on a function that must accept ETH), this is the mirror-image defect — a spurious *missing* non-payable check on a function that must never accept value, and the distribution precompile has no mechanism to refund or use ether/usei sent to it via this path.

### Finding Description
`PrecompileExecutor.Execute` dispatches `RewardsMethod` straight to `p.rewards(ctx, method, args)` without passing `value` through `validateInput`/`ValidateNonPayable`, unlike every sibling query (`params`, `validatorOutstandingRewards`, `validatorCommission`, `validatorSlashes`, `delegationRewards`, `delegatorValidators`, `delegatorWithdrawAddress`, `communityPool`), which all call `p.validateInput(value, args, n)` → `pcommon.ValidateNonPayable(value)`: [1](#0-0) 

`rewards()` itself never checks `value` at all: [2](#0-1) 

This is a known, deliberately-documented quirk in the test suite: [3](#0-2) 

The distribution precompile address (`0x...1007`) is also *not* listed in `payablePrecompiles`, which only contains bank/staking/gov/wasmd: [4](#0-3) 

Because the EVM transfers `msg.value` to the callee's balance as part of `CALL` semantics before/independent of the precompile's own Go logic (the `ValidateNonPayable` checks used elsewhere exist precisely to reject value before it can be stranded — see the `ibc`, `oracle`, `staking`, `json`, `pointerview` precompiles, all of which reject value-bearing calls), the absence of this same guard on `rewards()` means a value-bearing call to `rewards()` will not be rejected, and the distribution precompile exposes no corresponding "refund" or "withdraw" logic like `HandlePaymentUsei`/`HandlePaymentUseiWei` (used by `wasmd`) to route the received value back out: [5](#0-4) 

This is structurally identical to the CEther bug class: an inconsistency between what a delegator/precompile *should* enforce for a given call path and what it actually does, causing funds sent along that specific call path to become unrecoverable.

### Impact Explanation
Any EVM account (or contract) calling `rewards(delegatorAddress)` on the distribution precompile with nonzero `msg.value` will have that value debited from its EVM balance and credited to the precompile's associated account address, with no code path in the distribution precompile to return, use, or withdraw it. This constitutes permanent freezing of user funds (usei/wei) for any transaction sender who (mistakenly or via a poorly-encoded integrator/wallet call) attaches value to this specific read-only call.

### Likelihood Explanation
This requires an unprivileged, single transaction from any EOA or contract calling `rewards(address)` on `0x0000000000000000000000000000000000001007` with `value > 0`. No special privilege, wasm gating, or governance is needed — it is directly reachable via a public JSON-RPC `eth_sendRawTransaction`/contract-call to a known precompile address. Likelihood of user error is non-trivial given other distribution/staking calls (e.g., `delegate`) are legitimately payable, increasing the chance an integrator mis-attaches value to `rewards()`.

### Recommendation
Add `if err := pcommon.ValidateNonPayable(value); err != nil { return nil, 0, err }` (or route through `validateInput`) inside `rewards()` in `precompiles/distribution/distribution.go`, consistent with every other query method on this precompile, so value-bearing calls to `rewards()` revert instead of stranding funds. Apply the same audit to any other precompile method that omits the non-payable check on a purely-read path.

### Proof of Concept
1. From an EOA with an EVM balance and an associated Sei address, send a raw EVM transaction to `0x0000000000000000000000000000000000001007` (distribution precompile) calling `rewards(delegatorEvmAddress)` (or via `PrecompileCaller.callTarget`) with `value = 1e18` wei attached and sufficient gas.
2. Observe the transaction succeeds (status = 1) instead of reverting like every other distribution view method with value attached, as demonstrated by the `distribution.spec.ts` comment noting `rewards()` is deliberately excluded from the "view rejects value" test: [6](#0-5) 
3. Query the EVM balance of the precompile's associated address afterward and confirm the sent value now resides there with no distribution-precompile method able to move it out.

Note: I was not able to fully trace the exact low-level EVM `Call` implementation that performs the StateDB balance transfer for precompile calls (to confirm definitively that value transfer occurs even when the precompile signature doesn't mark itself payable in Solidity terms) within the indexed context; this should be verified directly against `x/evm/keeper` and go-ethereum's `vm.EVM.Call` value-transfer step in a full checkout before treating this as fully proven.

func (p PrecompileExecutor) rewards(ctx sdk.Context, method *abi.Method, args []interface{}) (ret []byte, remainingGas uint64, rerr error) {
	defer func() {
		if err := recover(); err != nil {
			ret = nil
			remainingGas = 0
			rerr = fmt.Errorf("%s", err)
			return
		}
	}()

	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		rerr = err
		return
	}

	seiDelegatorAddress, err := p.accAddressFromArg(ctx, args[0])
	if err != nil {
		rerr = err
		return
	}

	req := &distrtypes.QueryDelegationTotalRewardsRequest{
		DelegatorAddress: seiDelegatorAddress.String(),
	}

	wrappedC := sdk.WrapSDKContext(ctx)
	response, err := p.distrKeeper.DelegationTotalRewards(wrappedC, req)
	if err != nil {
		rerr = err
		return
	}

	rewardsOutput := getResponseOutput(response)
	ret, rerr = method.Outputs.Pack(rewardsOutput)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}

func ValidateNonPayable(value *big.Int) error {
	if value != nil && value.Sign() != 0 {
		return errors.New("sending funds to a non-payable function")
	}

	return nil
}

func HandlePaymentUsei(ctx sdk.Context, precompileAddr sdk.AccAddress, payer sdk.AccAddress, value *big.Int, bankKeeper putils.BankKeeper, evmKeeper putils.EVMKeeper, hooks *tracing.Hooks, depth int) (sdk.Coin, error) {
	usei, wei := state.SplitUseiWeiAmount(value)
	if !wei.IsZero() {
		return sdk.Coin{}, fmt.Errorf("selected precompile function does not allow payment with non-zero wei remainder: received %s", value)
	}
	coin := sdk.NewCoin(sdk.MustGetBaseDenom(), usei)
	// refund payer because the following precompile logic will debit the payments from payer's account
	// this creates a new event manager to avoid surfacing these as cosmos events
	if err := bankKeeper.SendCoins(ctx.WithEventManager(sdk.NewEventManager()), precompileAddr, payer, sdk.NewCoins(coin)); err != nil {
		return sdk.Coin{}, err
	}
	if hooks != nil {
		newCtx := ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx))
		if hooks.OnEnter != nil {
			hooks.OnEnter(depth+1, byte(vm.CALL), evmKeeper.GetEVMAddressOrDefault(newCtx, precompileAddr), evmKeeper.GetEVMAddressOrDefault(newCtx, payer), []byte{}, GetRemainingGas(newCtx, evmKeeper), value)
		}
		if hooks.OnExit != nil {
			hooks.OnExit(depth+1, []byte{}, 0, nil, false)
		}
	}
	return coin, nil
}
