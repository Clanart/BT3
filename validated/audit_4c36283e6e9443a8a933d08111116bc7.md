### Title
`ReceivedOutput::read` accepts arbitrary scalar offset without verifying it corresponds to the output's `script_pubkey` — injected unspendable "received" outputs - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The external report concerns insufficient validation of attacker-controlled input producing content the application treats as legitimate (CVE-2025-55173, CWE-20). The Serai analog is `ReceivedOutput::read` in `crypto`-adjacent `bitcoin-serai` wallet code: it deserializes a scalar `offset`, a `TxOut`, and an `OutPoint` purely from the byte stream, with no check that `scanner_key + offset * G` actually maps to `output.script_pubkey`. A `ReceivedOutput` is the type the rest of the pipeline treats as proof of ownership of a UTXO (it carries `offset()`, `output()`, `outpoint()`, `value()`), yet the deserialization accepts any internally-consistent triplet.

### Finding Description
`Scanner::scan_transaction` is the only constructor that correctly establishes the `script_pubkey ↔ offset` binding: it only emits a `ReceivedOutput` when `self.scripts.get(&output.script_pubkey)` returns the registered offset ( [1](#0-0) ). `register_offset` likewise derives the script from `key + offset * G` ( [2](#0-1) ).

`ReceivedOutput::read`, however, reconstructs the struct from untrusted bytes — `Secp256k1::read_F` for the offset, then `TxOut::consensus_decode` and `OutPoint::consensus_decode` — and returns it without any consistency check ( [3](#0-2) ). Nothing ties the claimed `offset` to the claimed `script_pubkey`. An attacker supplying the serialized bytes (a peer, coordinator component, or any party able to feed `ReceivedOutput::read`) can inject an output that:

- claims an arbitrary `offset`, so the derived spend key does not correspond to the output's script — the output is reported as received but is unspendable, or
- wraps a `TxOut`/`OutPoint` belonging to a different key with an offset chosen to make key-recovery logic (e.g., `key()` in the processor, which subtracts `GENERATOR * offset` from the script key) attribute it incorrectly.

The deserialization layer is precisely where this validation must live, because after `read` the invariant established only inside `Scanner` is assumed to hold.

### Impact Explanation
Medium. Any consumer that persists, relays, or accepts a serialized `ReceivedOutput` will treat attacker-injected bytes as a spendable owned output. Consequences:

- Funds reported received that are not spendable: an output scanned-in or loaded with a bogus offset cannot be signed for (the signer uses `offset()` to derive the per-input key in `SignableTransaction`/`tweak_keys`-style re-keying), causing signing failure or, worse, signing an unintended effective key.
- Misattribution: a crafted `(offset, TxOut)` pair can cause `key()`-style recovery to return a wrong group key, polluting balance/ownership accounting.
- DoS of the spend path: an unspendable output selected as an input aborts or wastes fee budget in constructed transactions.

### Likelihood Explanation
Reachable by any unprivileged party who can cause `ReceivedOutput::read` to be invoked on bytes they control — the type exposes `serialize`/`write` and is explicitly designed to cross trust boundaries (it is read back in `Output::read` in the processor and used in tests round-tripping serialized outputs, e.g., [4](#0-3) ). Exploitation requires no key material, only the ability to write 32 offset bytes plus a consensus-encoded `TxOut`/`OutPoint`. It is bounded by whether integrators feed untrusted serialized outputs into `read`, which is a plausible storage/IPC pattern but not guaranteed — hence Medium rather than High.

### Recommendation
In `ReceivedOutput::read`, after decoding, re-derive the expected script. Since `read` does not know the scanner's root key, either:

- extend `read` to take the root `ProjectivePoint` and assert `p2tr_script_buf(key + GENERATOR * offset) == Some(output.script_pubkey)`, or
- store the expected script binding explicitly and have callers re-validate `offset` against `output.script_pubkey` (e.g., a `verify(key)` method) before the value is used for spending or accounting.

At minimum, document on `read` that the offset/script binding is not verified and must be checked by the caller.

### Proof of Concept
```rust
use bitcoin_serai::{
  bitcoin::{TxOut, OutPoint, Amount, ScriptBuf, Txid, hashes::Hash},
  wallet::ReceivedOutput,
};
use frost::curve::Secp256k1;
use ciphersuite::Ciphersuite;
use k256::{Scalar, ProjectivePoint};
use rand_core::OsRng;

// Honest output for `key` with offset 0:
let key = loop {
  let k = ProjectivePoint::random(&mut OsRng);
  if let Some(script) = bitcoin_serai::wallet::p2tr_script_buf(k) { break (k, script); }
};

// Attacker crafts a serialized ReceivedOutput claiming offset = 1 for an output
// whose script_pubkey only belongs to offset = 0.
let honest = ReceivedOutput /* obtained via Scanner::scan_transaction */;
let mut forged_bytes = vec![];
forged_bytes.extend(Scalar::ONE.to_repr().as_ref());          // bogus offset
forged_bytes.extend(bitcoin_serai::bitcoin::consensus::serialize(honest.output()));
forged_bytes.extend(bitcoin_serai::bitcoin::consensus::serialize(honest.outpoint()));

let forged = ReceivedOutput::read(&mut forged_bytes.as_slice()).unwrap(); // succeeds
// forged.offset() == 1, yet script_pubkey corresponds to offset 0:
// key + 1*G != script key → derived spend key cannot spend `forged`,
// but the type reports it as a received output with `value()`.
assert_eq!(forged.offset(), Scalar::ONE);
assert_eq!(forged.output(), honest.output()); // no error raised by read
```

  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
