### Title
Unauthenticated `WWW-Authenticate` realm value spoofs GitHub-endpoint classification in the credential helper - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
Desktop's git-credential trampoline decides whether a remote endpoint should be treated as "GitHub Enterprise" purely by inspecting the `wwwauth[...]` header values that git forwards from the remote server's HTTP response, with no cryptographic or DNS-based verification of the claim. A malicious or compromised remote/proxy can set `WWW-Authenticate: realm="GitHub"` and cause Desktop to treat an arbitrary host as an "enterprise" GitHub endpoint, driving it into the GitHub sign-in flow (potentially binding a new "enterprise" account to an attacker-chosen origin) instead of the safe generic-credential path.

### Finding Description
`getEndpointKind` classifies a credential-helper request's target host by, in order: known GitHub.com/GHE hostname checks, then a scan of the credential map for keys beginning with `wwwauth[`, and finally an API probe: [1](#0-0) 

The comment on lines 153–156 explicitly states that this is a "happy path" that trusts headers coming back from whatever server Git connected to, "without having to resort to making a request ourselves." Those `wwwauth[N]` values are placed into the credential-helper protocol's stdin by Git itself, sourced directly from the HTTP response of the remote/proxy the user is fetching, pushing, or cloning from — i.e., attacker-controlled data, exactly analogous to the pool contract trusting a user-supplied `ownerAddress` field to decide whether a privileged bypass applies.

This classification directly feeds `getCredential`, which — when `endpointKind !== 'generic'` and no existing account matches the endpoint — invokes `ui.promptForGitHubSignIn(endpoint)`: [2](#0-1) 

`promptForGitHubSignIn` then starts an "Enterprise" sign-in flow bound to the attacker-controlled `origin`: [3](#0-2) 

There is no verification step in between that the server genuinely implements GitHub's OAuth/device or PAT-based Enterprise authentication contract, nor that the header wasn't spoofed by an untrusted party in a MITM/proxy position. The only "guard" is the fallback `isGitHubHost(endpoint)` probe used when no `wwwauth[]` header is present at all (line 178) — but that check is entirely skipped once an attacker supplies the spoofed header, bypassing the one place where a real network confirmation would otherwise occur.

### Impact Explanation
An attacker who controls a git remote (e.g. a malicious repo host, a compromised self-hosted git server, or a network position able to answer HTTP auth challenges for a repository the user clones/fetches/pushes to) can:
- Force Desktop to route unauthenticated-credential requests into the GitHub Enterprise sign-in UI for an arbitrary host, misleading the user into believing they are authenticating to a legitimate corporate GitHub Enterprise instance.
- Cause account binding (`_setSignInEndpoint`/`beginEnterpriseSignIn`) to an attacker-chosen origin, setting up a phishing/credential-harvesting flow disguised as Desktop's native sign-in dialog rather than a generic HTTP Basic auth prompt, which is normally the only UI shown for unknown hosts.
- Divert what should be a generic-git-credential prompt (clearly showing a "remote URL" login box) into a trusted-looking "Sign in to GitHub Enterprise" flow, increasing the odds a user unknowingly starts an OAuth/PAT exchange against the attacker's server, satisfying the "unauthorized OAuth or account binding" impact category.

The attacker does not need any local access, prior malware, or leaked credentials — only the ability to answer the HTTP request for the repository being cloned/fetched, which is the normal position of any git host or a MITM/proxy on that host.

### Likelihood Explanation
Likelihood is moderate: the attacker simply needs to control (or spoof) HTTP responses for a git remote the victim adds, which is a common capability for anyone offering a malicious/compromised clone URL. No user interaction beyond a normal `git fetch`/`clone`/`push` against that remote is required for the header to be evaluated; the header is inspected on essentially every credential-helper `get` request for an otherwise-unclassified host.

### Recommendation
Do not treat `WWW-Authenticate` realm strings as authoritative proof of a GitHub identity. At minimum:
- Remove or heavily downgrade the `wwwauth[]` "happy path" and always fall back to the authenticated `isGitHubHost(endpoint)` API probe (which performs an actual, verifiable request) before classifying an endpoint as `'enterprise'`.
- If the header-based happy path is kept for performance, require it to only ever *skip* extra API calls to confirm a *negative* (non-GitHub) classification, never to *positively* assert `'enterprise'` status that leads to launching an account sign-in/binding flow.
- Ensure the GitHub Enterprise sign-in flow can only be initiated for endpoints that have passed a genuine server-side capability check (e.g., successfully hitting a known GitHub API route), not a client-supplied/relayed header string.

### Proof of Concept
1. Stand up a malicious git-over-HTTPS server (or an HTTP proxy positioned in front of a legitimate-looking remote) that, on any authentication challenge, responds with `WWW-Authenticate: Basic realm="GitHub"`.
2. Have the victim add this server as a remote in GitHub Desktop and perform any operation that requires credentials (`fetch`, `push`, `pull`).
3. Git captures the `WWW-Authenticate` header and forwards it to Desktop's credential helper as a `wwwauth[0]=...` field in the credential protocol.
4. `getEndpointKind` matches `realm="GitHub"` and returns `'enterprise'` (`app/src/lib/trampoline/trampoline-credential-helper.ts:159-160`), even though `isDotCom`/`isGHE` checks failed and no real GitHub API verification occurred.
5. Since no account matches this arbitrary endpoint, `getCredential` calls `ui.promptForGitHubSignIn(endpoint)`, which opens Desktop's native "Sign in to your GitHub Enterprise" dialog bound to the attacker's origin (`app/src/lib/trampoline/trampoline-ui-helper.ts:80-99`), instead of the expected generic HTTP-credential prompt.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
