### Title
Unbounded bid pool growth (default `MaxBidPoolSize = math.MaxInt64`) can cause per-block DoS in auction block-building path - ([File: kaiax/auction/config.go], [File: kaiax/auction/impl/bid_pool.go], [File: kaiax/auction/impl/builder.go])

### Summary
The Kaia auction module's bid pool has no default size cap (`DefaultMaxBidPoolSize = math.MaxInt64`), unless a node operator explicitly sets `auction.max-bid-pool-size`. Each valid `auction_submitBid` RPC call (submitted by a searcher/bidder together with a co-signature from the configured `Auctioneer`) inserts an entry into `bp.bidMap` / `bp.bidTargetMap[blockNumber]` / `bp.bidWinnerMap[blockNumber]`, and this insertion is only rejected once `len(bp.bidMap) >= bp.maxBidPoolSize`. [1](#0-0) [2](#0-1) 

### Finding Description
`insertBid()` only enforces the pool-size cap in the "new target" branch (`bp.bidTargetMap[blockNumber][targetTxHash]` not already present); the check `len(bp.bidMap) >= bp.maxBidPoolSize` uses the operator-configured `maxBidPoolSize`, which defaults to `math.MaxInt64` — i.e. effectively unbounded — unless the node explicitly sets `--auction.max-bid-pool-size`. [3](#0-2) 

A bid only requires a valid EIP-712 searcher signature and a valid `Auctioneer` signature (`validateBidSigs`), and a `TargetTxHash` that is **not checked against any real pending transaction** at insertion time — it can be any arbitrary hash. [4](#0-3) [5](#0-4) 

Because different senders are allowed to each hold a winning bid per block (`bidWinnerMap[blockNumber][sender]`), an attacker able to obtain (or collude with) auctioneer co-signatures can flood `bidTargetMap[blockNumber]` with a very large number of distinct fabricated `targetTxHash` entries for the next few allowed blocks (`[currentBlockNumber+1, currentBlockNumber+allowFutureBlock]`), all through the public `auction_submitBid` RPC/`AddBid` path. [6](#0-5) 

Every block-building attempt then calls `GetTargetTxMap`/`getTargetTxHashMap` to build a per-block lookup map from this (potentially huge) bid set, and `FilterTxs` runs this per proposer-candidate transaction group. [7](#0-6) [8](#0-7) 

Additionally, `removeOldBids`, which is presumably invoked on each new block/head event, iterates over all entries in `bp.bidWinnerMap`/`bp.bidTargetMap` for the target block window to prune them; a very large in-window map means this pruning work scales with the (attacker-controlled) size of the pool for that block-window, executed on the hot block-processing path. [9](#0-8) 

### Impact Explanation
If an unbounded number of bids accumulate for upcoming blocks (because the operator has not manually tightened `MaxBidPoolSize` from its unbounded default), the per-block cost of building/pruning the bid-target maps in `ExtractTxBundles`, `FilterTxs`, and `removeOldBids` grows with pool size, executed by every consensus node on every block-building attempt. This can degrade or stall block production (a liveness/DoS issue analogous to the reported unbounded `orderbook` loop in `_processOrders()`), rather than causing loss of funds directly.

### Likelihood Explanation
Exploitation requires the attacker to get valid `AuctioneerSig` co-signatures for a very large number of distinct bids within the same small block window (`allowFutureBlock`), since `validateBidSigs` strictly requires both a valid searcher signature and a valid auctioneer signature. This constrains the attack to scenarios where the `Auctioneer` service co-signs excessively (either compromised, misconfigured, or willing to sign arbitrary/spam bids), which is a meaningfully different trust assumption from a purely "unprivileged tx sender" attack. Absent auctioneer cooperation, an outside attacker cannot pass `validateBidSigs` and cannot grow the pool. This materially reduces the practical likelihood compared to the original Solidity `_processOrders()` bug, where any user's limit orders alone could grow the orderbook.

### Recommendation
Not applicable for this ask-only analysis; would require (1) enforcing a sane, non-`MaxInt64` default for `MaxBidPoolSize`, (2) bounding the number of bids per block-number window independent of total pool size, and (3) validating `targetTxHash` against real transactions before allowing insertion, to prevent map growth from unauthenticated/fabricated target hashes.

### Proof of Concept
Not independently verified against a running node; based on static code reading of `kaiax/auction/impl/bid_pool.go`, `kaiax/auction/impl/builder.go`, and `kaiax/auction/config.go`. I could not confirm from the indexed code exactly how frequently `removeOldBids` and `GetTargetTxMap`/`getTargetTxHashMap` are invoked per block-building cycle, nor the concrete gas/CPU cost bound of `Chain.CurrentBlock()`-triggered pruning; these would need runtime verification. Given the added trust dependency on the `Auctioneer` co-signature (which is not purely an "unprivileged transaction sender" capability), I'm not fully confident this rises to the same severity as the original Sherlock finding. // removeOldBids removes the old bids for the given block number.
func (bp *BidPool) removeOldBids(num uint64, txHashMap map[common.Hash]struct{}) {
	bp.bidMu.Lock()
	defer bp.bidMu.Unlock()

	// Remove the old bids.
	for bn := range bp.bidWinnerMap {
		if bn > num {
			continue
		}

		for _, bh := range bp.bidWinnerMap[bn] {
			delete(bp.bidMap, bh)
		}
		delete(bp.bidTargetMap, bn)
		delete(bp.bidWinnerMap, bn)
	}

	// Remove the bid which target tx is in the txHashMap.
	toBlock := num + allowFutureBlock
	for blockNum := num + 1; blockNum <= toBlock; blockNum++ {
		targetMap := bp.bidTargetMap[blockNum]
		if targetMap == nil {
			continue
		}

		// Collect bids to remove first to avoid modifying map during iteration
		var bidsToRemove []*auction.Bid
		for _, bid := range targetMap {
			if _, ok := txHashMap[bid.TargetTxHash]; ok {
				bidsToRemove = append(bidsToRemove, bid)
			}
		}

		// Remove collected bids
		for _, bid := range bidsToRemove {
			delete(targetMap, bid.TargetTxHash)
			delete(bp.bidWinnerMap[blockNum], bid.Sender)
			delete(bp.bidMap, bid.Hash())
		}
	}

	numBidsGauge.Update(int64(len(bp.bidMap)))
}

func (bp *BidPool) insertBid(bid *auction.Bid) error {
	bp.bidMu.Lock()
	defer bp.bidMu.Unlock()

	var (
		blockNumber  = bid.BlockNumber
		targetTxHash = bid.TargetTxHash
		sender       = bid.Sender
	)

	// Re-check bidWinnerMap here — two concurrent bids can pass validateBid together.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		return auction.ErrBidAlreadyExists
	}
	if bp.senderHasDifferentWinner(bid) {
		return auction.ErrBidSenderExists
	}

	// If same block number, same target tx hash exists, replace it if it's better
	if existingBid, ok := bp.bidTargetMap[blockNumber][targetTxHash]; ok {
		// FCFS if the bid is the same.
		if existingBid.Bid.Cmp(bid.Bid) >= 0 {
			return auction.ErrLowBid
		}

		logger.Trace("Replace bid", "old", existingBid.Hash(), "new", bid.Hash())
		delete(bp.bidMap, existingBid.Hash())
		delete(bp.bidWinnerMap[blockNumber], existingBid.Sender)
	} else {
		if int64(len(bp.bidMap)) >= bp.maxBidPoolSize {
			logger.Info("Bid pool is full", "maxBidPoolSize", bp.maxBidPoolSize, "bid", bid.Hash())
			return auction.ErrBidPoolFull
		}
	}

	hash := bid.Hash()

	bp.initializeBidMap(blockNumber)

	bp.bidMap[hash] = bid
	bp.bidTargetMap[blockNumber][targetTxHash] = bid
	bp.bidWinnerMap[blockNumber][sender] = hash

	numBidsGauge.Update(int64(len(bp.bidMap)))

	logger.Trace("Add bid", "bid", hash)

	return nil
}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}

func (a *AuctionModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	bundles := []*builder.Bundle{}
	curBlock := a.Chain.CurrentBlock()
	if curBlock == nil || atomic.LoadUint32(&a.bidPool.running) == 0 {
		return bundles
	}

	miningBlock := curBlock.NumberU64() + 1
	bidTargetMap := a.bidPool.GetTargetTxMap(miningBlock)
	if len(bidTargetMap) == 0 {
		return bundles
	}

func (a *AuctionModule) FilterTxs(txs map[common.Address]types.Transactions) {
	if atomic.LoadUint32(&a.bidPool.running) == 0 {
		return
	}

	curBlock := a.Chain.CurrentBlock()
	if curBlock == nil {
		return
	}

	targetTxHashMap := a.bidPool.getTargetTxHashMap(curBlock.NumberU64() + 1)
	edOffset := a.AuctionConfig.EDOffset

	now := time.Now()
	deadline := now.Add(-edOffset)
	// filter txs that are after the auction early deadline
	for addr, list := range txs {
		for i, tx := range list {
			if tx.Time().After(deadline) && !a.isGaslessTx(tx) {
				// if the tx is a target tx, skip it
				if _, ok := targetTxHashMap[tx.Hash()]; ok {
					continue
				}

				if i == 0 {
					// if first transaction exceeds deadline, remove the address
					delete(txs, addr)
				} else {
					// keep only transactions before the deadline
					txs[addr] = list[:i]
				}
				break
			}
		}
	}
