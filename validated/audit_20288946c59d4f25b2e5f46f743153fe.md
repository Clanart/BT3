### Title
Global gasless bundle-tx queue limit can be permissionlessly exhausted with spam ApproveTx to brick legitimate gasless transactions - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The gasless module enforces a single, global limit on the number of pending gasless "bundle" transactions (`GaslessApproveTx`/`GaslessSwapTx`) that may sit in the tx pool's queue at once, via `GetMaxBundleTxsInQueue()` (default 200). Any unprivileged sender who can construct a syntactically valid `GaslessApproveTx` (which requires no KAIA balance and only a self-created ERC20 token with a positive balance) can submit enough spam approve transactions from many throwaway keys to hit this shared cap. Once the cap is reached, `PreAddTx` rejects all further gasless bundle transactions with `ErrBundleTxQueueFull`, denying legitimate users' gasless approve/swap transactions network-wide — the exact "frontrun-with-spam-to-hit-a-shared-counter" bug class described in the report, just applied to Kaia's gasless module instead of an OpenQ bounty contract.

### Finding Description
`PreAddTx` is the tx-pool admission hook for the gasless module: [1](#0-0) 

It checks a single, un-partitioned counter `g.knownTxs.numQueue()` against `GetMaxBundleTxsInQueue()` (default 200, configurable via `--gasless.max-bundle-txs-in-queue`): [2](#0-1) [3](#0-2) 

The counter `numQueue()` simply iterates the shared `knownTxs` map and counts entries with `TxStatusQueue`, with no per-sender partitioning or fairness mechanism: [4](#0-3) 

To be classified as a bundle tx and consume a queue slot, a transaction only needs to pass `IsApproveTx`, which requires: (A1) `tx.to` is an allow-listed ERC20 token, (A2) calldata is `approve(spender, amount)`, (A3) spender is the whitelisted swap router, (A4) amount is `MaxUint256`: [5](#0-4) 

Crucially, `GetCheckBalance()` (invoked by the tx pool in lieu of a normal sender-balance check, per the module's design of "sender balance check is omitted for gasless transactions") only requires the sender to hold a nonzero balance of *some* token, and default `AllowedTokens` config is `nil`, meaning "allow all tokens": [6](#0-5) [7](#0-6) 

Because the sender's KAIA balance is not checked for gasless bundle txs (the balance check is replaced with `GetCheckBalance`), and only a self-deployed/self-minted worthless ERC20 token with balance > 0 is required, an attacker can generate an arbitrary number of throwaway EOA keys, deploy trivial ERC20 tokens, mint themselves a nonzero balance, and submit `approve(swapRouter, MaxUint256)` calls from each key. Each such transaction is classified `IsApproveTx() == true` and is admitted into `knownTxs` with `TxStatusQueue`, consuming a slot in the shared `MaxBundleTxsInQueue` budget until `QueueTimeout` (10s) elapses: [8](#0-7) 

By continuously resubmitting spam approve transactions (new keys/new tokens each time, since the 10-second `QueueTimeout` window only evicts them after some delay) faster than the eviction cadence, an attacker can keep the shared counter saturated indefinitely, causing `PreAddTx` to reject every legitimate user's `GaslessApproveTx`/`GaslessSwapTx` with `ErrBundleTxQueueFull` — this is confirmed by the existing test showing the limit is a hard global gate: [9](#0-8) 

This mirrors the reported OpenQ bug class precisely: a shared, length-based admission check (`tokenAddressLimitReached` there, `numQueue() >= MaxBundleTxsInQueue` here) that any unprivileged party can drive to its limit with cheap spam objects (junk tokens there, junk approve-txs from throwaway keys here), permanently starving legitimate users of a shared resource slot.

### Impact Explanation
This is a availability/DoS vulnerability against the entire gasless (KIP-247) feature on affected nodes: legitimate users attempting gasless approve/swap transactions will have them rejected at admission (`ErrBundleTxQueueFull`), effectively bricking gas-sponsored transactions network-wide for as long as the attacker sustains the spam. Because gasless swaps are advertised as a first-class UX feature (letting users transact without holding native KAIA), a sustained DoS against it denies a promised service to all users, and could be used opportunistically to front-run/deny a specific victim's gasless transaction by keeping the queue full at the moment the victim tries to submit. No funds are directly stolen, but this is a concrete, unauthenticated, reachable acceptance-denial of legitimate transactions matching the "gasless...settlement" and "acceptance of an invalid/legitimate transaction" impact categories in scope.

### Likelihood Explanation
The attack requires no special privileges, no KAIA balance (per `GetCheckBalance` skipping normal balance checks for gasless txs), and only trivial ERC20 contract deployment/minting plus generating many EOA keys — an extremely low-cost, easily automatable attack reachable purely via public RPC transaction submission (`eth_sendRawTransaction`). The default `MaxBundleTxsInQueue` is only 200, a small number that is trivially reachable. The only mitigating factor is the 10-second `QueueTimeout` eviction, which the attacker must simply keep pace with by continuously resubmitting, which is cheap given gasless approve txs do not consume the attacker's own KAIA.

### Recommendation
Partition the `MaxBundleTxsInQueue` (and `MaxBundleTxsInPending`) admission check per-sender (or per some Sybil-resistant identity) rather than as one global counter, similar to how the core tx pool already limits `NonExecSlotsAccount`/`ExecSlotsAccount` per account. Additionally, consider requiring a minimum real economic cost (e.g., checking that the sender token balance is not obtained from a just-deployed, unlisted token, or applying `AllowedTokens` more restrictively by default) and/or evicting/penalizing repeat offenders faster than legitimate users, and shortening `QueueTimeout` or adding rate limiting per sender address/IP for gasless bundle tx submission at the RPC layer.

### Proof of Concept
1. Deploy N trivial ERC20 contracts (or one contract, mint to N accounts), N ≈ `MaxBundleTxsInQueue` (default 200).
2. Generate N throwaway private keys; for each, mint a nonzero balance of the token from step 1.
3. From each key, submit a legacy transaction: `to = <allow-listed token or any token satisfying `allowedTokens`>`, `data = approve(swapRouter, MaxUint256)`. Since `AllowedTokens` defaults to "all", any ERC20 the module discovers via `MultiCallGaslessInfo` works if included, otherwise use one of the actually-allowed tokens per `updateAddresses`.
4. No KAIA balance is required by these senders because `GetCheckBalance()` for gasless approve txs only checks token balance/sender-code, not KAIA balance (`kaiax/gasless/impl/tx_pool.go:74-99`).
5. Confirm via `PreAddTx` (`kaiax/gasless/impl/tx_pool.go:46-50`) that `g.knownTxs.numQueue()` reaches `MaxBundleTxsInQueue`.
6. Submit a legitimate `GaslessApproveTx`/`GaslessSwapTx` from a normal user and observe it is rejected with `ErrBundleTxQueueFull`, as directly exercised by the existing unit test `TestPreAddTxQueueLimit` ("finite limit still enforced") at `kaiax/gasless/impl/tx_pool_test.go:121-125`.
7. Continuously resubmit fresh spam approve txs (new keys/tokens) faster than the 10-second `QueueTimeout` eviction (`kaiax/gasless/impl/tx_pool.go:33`, `292-315`) to sustain the DoS indefinitely.

func (g *GaslessModule) PreAddTx(tx *types.Transaction, local bool) error {
	g.knownTxsMu.RLock()
	defer g.knownTxsMu.RUnlock()

	if knownTx, ok := g.knownTxs.get(tx.Hash()); ok && knownTx.elapsedPromotedOrAddedTime() < KnownTxTimeout {
		return ErrUnableToAddKnownBundleTx
	}

	if g.IsBundleTx(tx) {
		if uint(g.knownTxs.numQueue()) >= g.GetMaxBundleTxsInQueue() {
			return ErrBundleTxQueueFull
		}
		g.knownTxs.add(tx, TxStatusQueue)
	}
	return nil
}

// PreReset removes timed out tx from the tx pool and knownTxs.
func (g *GaslessModule) PreReset(oldHead, newHead *types.Header) []common.Hash {
	g.knownTxsMu.Lock()
	defer g.knownTxsMu.Unlock()

	drops := make([]common.Hash, 0)

	for hash, knownTx := range *g.knownTxs {
		// remove pending timed out tx from tx pool
		if knownTx.status == TxStatusPending && knownTx.elapsedPromotedTime() >= PendingTimeout {
			drops = append(drops, hash)
		}
		// remove queue timed out tx from tx pool
		if knownTx.status == TxStatusQueue && knownTx.elapsedAddedTime() >= QueueTimeout {
			drops = append(drops, hash)
		}
		// remove known timed out tx from knownTxs
		if knownTx.elapsedPromotedOrAddedTime() >= KnownTxTimeout {
			g.knownTxs.delete(hash)
		}
	}

	return drops
}

// IsApproveTx checks following conditions:
// A1. tx.to is a whitelisted ERC20 token.
// A2. tx.data is `approve(spender, amount)`.
// A3. spender is a whitelisted SwapRouter contract.
// A4. amount is MaxUint.
func (g *GaslessModule) IsApproveTx(tx *types.Transaction) bool {
	args, ok := decodeApproveTx(tx, g.signer)
	return ok && g.isApproveTx(args)
}

func (g *GaslessModule) isApproveTx(args *ApproveArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.allowedTokens[args.Token] && // A1
		g.swapRouter == args.Spender && // A3
		args.Amount.Cmp(abi.MaxUint256) == 0 // A4
}
