### Title
`ReceivedOutput::read` deserializes unverified (offset, TxOut, outpoint) tuples, letting untrusted bytes fabricate "received" outputs that are not spendable - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
Analogous to CVE-2017-8829 (crafted serialized input accepted by a review pipeline), `ReceivedOutput::read` accepts arbitrary bytes and constructs a spendable-output object with no semantic validation. The three fields — the HDKD `offset`, the `TxOut`, and the `OutPoint` — are deserialized independently and never checked against each other or against the scanning key. In particular, nothing verifies that `output.script_pubkey` equals the P2TR script derived from `key + offset·G`, which is the only invariant that makes the output actually spendable by the wallet.

### Finding Description
`Scanner::scan_transaction` establishes the spendability invariant by construction: it only emits a `ReceivedOutput` when `self.scripts.get(&output.script_pubkey)` returns a registered offset, meaning `output.script_pubkey == p2tr_script_buf(key + G·offset)` for an even-y tweaked point (networks/bitcoin/src/wallet/mod.rs:199-214, 180-196).

`ReceivedOutput::read` bypasses this entirely: it reads a scalar via `Secp256k1::read_F`, then consensus-decodes an arbitrary `TxOut` and `OutPoint`, and returns them as a spendable output (networks/bitcoin/src/wallet/mod.rs:122-134). There is no reference to the wallet `key`, no recomputation of `key + G·offset`, no check that the resulting point is even-y, and no check that `outpoint` references `output`. Because `read` is a public constructor reachable wherever serialized outputs cross a trust boundary (the same crate exposes `serialize`/`write` intended for transport), any party able to supply those bytes can inject a `ReceivedOutput` claiming an arbitrary value at an arbitrary outpoint bound to an offset that does not spend it.

### Impact Explanation
A deserialized `ReceivedOutput` is later spent via the offset: the wallet offsets the threshold keys by `offset`, tweaks, and produces a Schnorr/Taproot signature for the input's script_pubkey. If `output.script_pubkey` was attacker-chosen and does not match `p2tr_script_buf(key + G·offset)` (or the offset isn't the one that yields even-y), the signature cannot spend that UTXO. The result is funds reported received that are not spendable: balance/UTXO accounting is corrupted, the wallet may select unspendable inputs in `send`, producing transactions that fail relay or (worse) burn legitimate co-spent inputs' fees in constructed transactions that must be abandoned. This matches the accepted "funds reported received that are not spendable" impact class.

### Likelihood Explanation
The vulnerability requires untrusted bytes to reach `ReceivedOutput::read` — i.e., any flow where received outputs are transported between components or persisted and reloaded from a store an attacker can influence. The type's `read`/`write`/`serialize` API exists precisely for such transport, and no integrity/authenticity check is performed in-band (no MAC, no key binding, no invariant check). No cryptographic break, collusion, or privileged position is needed — only the ability to supply the serialized blob. Impact is bounded to accounting/availability (unspendable reported funds and wasted fees), not key recovery, warranting Medium severity.

### Recommendation
Bind `ReceivedOutput` to its derivation context. Either (a) require the scanner key (or expected `ScriptBuf` set) as a parameter to `read` and reject outputs whose `script_pubkey` is not derivable as `p2tr_script_buf(key + G·offset)`, mirroring the check `scan_transaction` performs; or (b) document `read` as trusted-input-only and authenticate the byte stream (MAC/signature over the serialized form) at the transport layer. Option (a) is preferable since the check is cheap (one scalar multiplication, one hash) and makes the type self-validating.

### Proof of Concept
```rust
// networks/bitcoin/src/wallet/mod.rs
// Attacker-controlled blob: any valid scalar, any TxOut/script_pubkey.
let offset_bytes = [1u8; 32]; // arbitrary canonical scalar != real offset
let mut blob = offset_bytes.to_vec();
// TxOut paying to an attacker P2TR key, value = 100_000 sats
blob.extend(serialize(&TxOut {
    value: Amount::from_sat(100_000),
    script_pubkey: attacker_p2tr_script, // not derivable from wallet key + offset
}));
blob.extend(serialize(&OutPoint::new(real_txid, 0)));

let output = ReceivedOutput::read(&mut blob.as_slice()).unwrap(); // accepted
assert_eq!(output.value(), 100_000); // reported as received
// Wallet spends with keys.offset(1): signature is invalid for
// attacker_p2tr_script — the reported funds can never be moved.
```
