## Title
Delegator loses staked tokens (unbonded to zero) on `Unbond`/`Undelegate` due to unchecked truncation of shares-to-tokens conversion - ([File: sei-cosmos/x/staking/keeper/delegation.go])

## Summary
`Keeper.Unbond` converts a delegator's `sharesAmount` into a token amount via `RemoveValidatorTokensAndShares`, which internally truncates the shares→tokens exchange-rate division. For sufficiently small `sharesAmount` relative to the validator's tokens/shares ratio, the resulting `amount` can truncate to zero while the delegator's shares are still burned from their delegation and the validator's `DelegatorShares`. This mirrors the Notional `nTokenRedeemAction` bug: the redeemer's claim is destroyed with no compensating value returned.

## Finding Description
`Undelegate` (a standard, unprivileged user transaction, `MsgUndelegate`) calls `Keeper.Unbond`: [1](#0-0) 

Inside `Unbond`, the delegator's `shares` are unconditionally subtracted from the `Delegation.Shares` and from the validator's `DelegatorShares`/`Tokens` via `RemoveValidatorTokensAndShares`, with no check that the resulting `amount` (token value redeemed) is greater than zero: [2](#0-1) 

The token value is computed by `Validator.RemoveDelShares`, which truncates the shares→tokens conversion:
```go
issuedTokens = v.TokensFromShares(delShares).TruncateInt()
``` [3](#0-2) 

`TokensFromShares` performs `(shares.MulInt(v.Tokens)).Quo(v.DelegatorShares)`, a Dec division that can legitimately round toward zero for a delegator holding a tiny fraction of shares relative to a validator with a large token/share pool: [4](#0-3) 

`Undelegate` then proceeds regardless of whether `returnAmount` is zero, creating an unbonding-delegation entry with a zero `Balance`: [5](#0-4) 

When that entry matures, `CompleteUnbonding` explicitly skips sending any coins back to the delegator if the entry's balance is zero, confirming that a zero-value unbonding is silently accepted and never refunds anything to the user: [6](#0-5) 

This is the direct analog of the reported Notional issue: a proportional-share redemption computation whose truncating division can yield zero output for a positive input amount, with no zero-check guard before the input (shares/nTokens) is irrevocably burned.

## Impact Explanation
A delegator can lose delegation shares (and thus a proportional stake in the validator, ultimately backed by real `usei`/bond-denom tokens) with zero tokens returned, either immediately (if the validator is `Unbonded`, funds are sent directly and skipped when zero) or after the unbonding period (`CompleteUnbonding` silently drops zero-balance entries). This is a direct, permanent loss of user funds — the shares are destroyed and the corresponding token value is never credited to the delegator, effectively burning value without compensation. This can occur naturally on validators with very large `Tokens`/`DelegatorShares` ratios (e.g., due to accumulated rounding residue in `AddTokensFromDel`/`RemoveDelShares` over the validator's lifetime) whenever a delegator issues a small `MsgUndelegate` amount.

## Likelihood Explanation
Reachable by any unprivileged account via a plain `MsgUndelegate` transaction — no special privileges, validator cooperation, or governance action required. The likelihood of hitting the zero-truncation case depends on the validator's exchange rate (Tokens/DelegatorShares) and the amount being unbonded; it becomes increasingly likely for validators that have accumulated a large tokens-per-share ratio and for delegators unbonding very small amounts (including amounts a UI might auto-generate, e.g. redeeming a rounding remainder).

## Recommendation
In `Keeper.Unbond` (sei-cosmos/x/staking/keeper/delegation.go), after computing `amount` from `RemoveValidatorTokensAndShares`, reject the operation (return an error) if `amount.IsZero()` while `shares` is positive, so that delegators cannot burn shares for zero token value. Alternatively, enforce a minimum-token-value check in `ValidateUnbondAmount`/`MsgUndelegate` handling before calling `Unbond`.

## Proof of Concept
1. A validator accumulates tokens such that `Tokens / DelegatorShares` results in many shares being required to represent 1 unit of token (e.g., due to historical truncation in `RemoveDelShares`/`AddTokensFromDel` leaving excess tokens locked against fewer shares... in the inverse direction: a validator whose `DelegatorShares` is large relative to `Tokens`).
2. A delegator holding a small number of shares in that validator calls `MsgUndelegate` with a `sharesAmount` computed (via `ValidateUnbondAmount`) from a very small token `amt`.
3. `TokensFromShares(delShares).TruncateInt()` in `RemoveDelShares` truncates to `0`.
4. `Unbond` still subtracts `shares` from the delegation and validator, and `Undelegate` still creates an `UnbondingDelegationEntry` with `Balance = 0`.
5. After the unbonding period, `CompleteUnbonding` skips sending coins (`entry.Balance.IsZero()`), and the delegator's shares are permanently gone with zero tokens received.

func (k Keeper) Unbond(
	ctx sdk.Context, delAddr sdk.AccAddress, valAddr sdk.ValAddress, shares sdk.Dec,
) (amount sdk.Int, err error) {
	// check if a delegation object exists in the store
	delegation, found := k.GetDelegation(ctx, delAddr, valAddr)
	if !found {
		return amount, types.ErrNoDelegatorForAddress
	}

	// call the before-delegation-modified hook
	k.BeforeDelegationSharesModified(ctx, delAddr, valAddr)

	// ensure that we have enough shares to remove
	if delegation.Shares.LT(shares) {
		return amount, sdkerrors.Wrap(types.ErrNotEnoughDelegationShares, delegation.Shares.String())
	}

	// get validator
	validator, found := k.GetValidator(ctx, valAddr)
	if !found {
		return amount, types.ErrNoValidatorFound
	}

	// subtract shares from delegation
	delegation.Shares = delegation.Shares.Sub(shares)

	delegatorAddress, err := sdk.AccAddressFromBech32(delegation.DelegatorAddress)
	if err != nil {
		return amount, err
	}

	isValidatorOperator := delegatorAddress.Equals(validator.GetOperator())

	// If the delegation is the operator of the validator and undelegating will decrease the validator's
	// self-delegation below their minimum, we jail the validator.
	if isValidatorOperator && !validator.Jailed &&
		validator.TokensFromShares(delegation.Shares).TruncateInt().LT(validator.MinSelfDelegation) {
		k.jailValidator(ctx, validator)
		validator = k.mustGetValidator(ctx, validator.GetOperator())
	}

	// remove the delegation
	if delegation.Shares.IsZero() {
		k.RemoveDelegation(ctx, delegation)
	} else {
		k.SetDelegation(ctx, delegation)
		// call the after delegation modification hook
		k.AfterDelegationModified(ctx, delegatorAddress, delegation.GetValidatorAddr())
	}

	// remove the shares and coins from the validator
	// NOTE that the amount is later (in keeper.Delegation) moved between staking module pools
	validator, amount = k.RemoveValidatorTokensAndShares(ctx, validator, shares)

	if validator.DelegatorShares.IsZero() && validator.IsUnbonded() {
		// if not unbonded, we must instead remove validator in EndBlocker once it finishes its unbonding period
		k.RemoveValidator(ctx, validator.GetOperator())
	}

	return amount, nil
}

func (k Keeper) Undelegate(
	ctx sdk.Context, delAddr sdk.AccAddress, valAddr sdk.ValAddress, sharesAmount sdk.Dec,
) (time.Time, error) {
	validator, found := k.GetValidator(ctx, valAddr)
	if !found {
		return time.Time{}, types.ErrNoDelegatorForAddress
	}

	if k.HasMaxUnbondingDelegationEntries(ctx, delAddr, valAddr) {
		return time.Time{}, types.ErrMaxUnbondingDelegationEntries
	}

	returnAmount, err := k.Unbond(ctx, delAddr, valAddr, sharesAmount)
	if err != nil {
		return time.Time{}, err
	}

	// transfer the validator tokens to the not bonded pool
	if validator.IsBonded() {
		k.bondedTokensToNotBonded(ctx, returnAmount)
	}

	completionTime := ctx.BlockHeader().Time.Add(k.UnbondingTime(ctx))
	ubd := k.SetUnbondingDelegationEntry(ctx, delAddr, valAddr, ctx.BlockHeight(), completionTime, returnAmount)
	k.InsertUBDQueue(ctx, ubd, completionTime)

	return completionTime, nil
}

// RemoveDelShares removes delegator shares from a validator.
// NOTE: because token fractions are left in the valiadator,
//
//	the exchange rate of future shares of this validator can increase.
func (v Validator) RemoveDelShares(delShares sdk.Dec) (Validator, sdk.Int) {
	remainingShares := v.DelegatorShares.Sub(delShares)

	var issuedTokens sdk.Int
	if remainingShares.IsZero() {
		// last delegation share gets any trimmings
		issuedTokens = v.Tokens
		v.Tokens = sdk.ZeroInt()
	} else {
		// leave excess tokens in the validator
		// however fully use all the delegator shares
		issuedTokens = v.TokensFromShares(delShares).TruncateInt()
		v.Tokens = v.Tokens.Sub(issuedTokens)

		if v.Tokens.IsNegative() {
			panic("attempting to remove more tokens than available in validator")
		}
	}

	v.DelegatorShares = remainingShares

	return v, issuedTokens
}
