### Title
Direct ERC20 donation to MasterMagpie inflates `_calLpSupply()` denominator, permanently diluting `accMGPPerShare` and freezing unclaimed MGP yield - (File: rewards/MasterMagpie.sol)

### Summary
`_calLpSupply()` uses `IERC20(_stakingToken).balanceOf(address(this))` as the reward-distribution denominator for every pool except the `vlmgp`/`mWomSV` special cases. Any unprivileged actor can transfer the pool's staking/receipt token directly to `MasterMagpie` without calling `deposit()`, inflating the balance-based supply while crediting no `UserInfo.amount`, which is then consumed the next time `updatePool()` runs (e.g., triggered by any `deposit`/`withdraw`/`withdrawFor` call, including a victim's pending deposit).

### Finding Description
`updatePool()` computes `lpSupply = _calLpSupply(_stakingToken)` and divides the freshly emitted `mgpReward` by that value to increment `pool.accMGPPerShare`: [1](#0-0) 

`_calLpSupply()` for any ordinary pool simply returns the raw token balance of the contract rather than an internally tracked, deposit-credited total: [2](#0-1) 

Because `PoolInfo`/`UserInfo` do not maintain a separate `totalStaked` counter reconciled with real deposits — `UserInfo.amount` is only incremented inside `_deposit()` via `safeTransferFrom` — an attacker can call `IERC20(stakingToken).transfer(masterMagpie, amount)` directly (a plain token transfer, not through `deposit()` or `withdraw()`) to raise `balanceOf(masterMagpie)` without raising the sum of `UserInfo.amount` for that pool: [3](#0-2) 

The inflated balance is not realized into `accMGPPerShare` until the next `updatePool()` call, which happens inside `_deposit`/`_withdraw`/`_harvestAndUnstake` (and therefore also inside `withdraw()`/`withdrawFor()`): [4](#0-3) 

When this happens (e.g., while a victim's large `deposit()` is pending in the mempool, or on any subsequent `withdraw()` call by any user), the MGP emitted for that time interval (`multiplier * mgpPerSec * pool.allocPoint / totalAllocPoint`) is divided by an artificially large `lpSupply`, so `accMGPPerShare` increases by less than it should relative to the real staked amount. The shortfall is not recoverable: `mgpPerSec` emission is a fixed rate independent of `accMGPPerShare`, so the portion of newly minted/allocated MGP that should have accrued to real stakers during that interval is permanently unaccounted for in any `UserInfo.rewardDebt`/pending-reward calculation, effectively freezing that yield.

Note on the stated entry point: `withdraw(address _stakingToken, uint256 _amount)` itself does not perform the donation — the actual attacker action is a raw `IERC20.transfer()` call on the staking token directly to `MasterMagpie`, which requires no special role. `withdraw()` (or any other call that triggers `updatePool()`) is merely the mechanism that "locks in" the dilution into `accMGPPerShare`. `nonReentrant`/`whenNotPaused` modifiers and the `user.available < _amount` check in `_harvestAndUnstake` do not prevent this, since they only validate the caller's own withdrawal amount and do not defend against balance manipulation of the shared `_calLpSupply()` denominator.

### Impact Explanation
This matches "High - Permanent freezing of unclaimed yield." Since MGP emission per interval is fixed by `mgpPerSec`, any dilution of `accMGPPerShare`'s denominator via donated tokens permanently reduces the MGP credited to genuine stakers for that interval, with no mechanism to reclaim or redistribute the shortfall later. Repeated donations before every `updatePool()`-triggering call can compound this loss across the pool's lifetime, and the effect is worse when timed around a large pending deposit (maximizing the temporary inflation of `balanceOf`).

### Likelihood Explanation
The attacker needs only enough of the pool's staking token to perform a transfer (which, for many wombat/LP receipt tokens, can be obtained cheaply via flash mint/loan or minimal capital, and does not require holding it for long — a single-block donation right before a `updatePool()`-triggering transaction suffices). No privileged role is required, the action is a plain `IERC20.transfer()`, and it is repeatable on any pool that falls into the `_calLpSupply()` balance-based branch (i.e., any pool that is not `vlmgp` or `mWomSV`).

### Recommendation
Replace the balance-based `_calLpSupply()` fallback with an internally tracked, monotonic `pool.totalStaked` value that is only incremented/decremented inside `_deposit()`/`_withdraw()` in lockstep with `UserInfo.amount` changes, so that reward math is never affected by direct token transfers into the contract.

### Proof of Concept
Hardhat/Foundry test plan:
1. Deploy `MasterMagpie` with a registered ERC20 pool (`stakingToken`), set `mgpPerSec` and `allocPoint`.
2. Have a "victim" deposit tx prepared (`deposit(stakingToken, largeAmount)`).
3. Before the victim's tx is mined, have the attacker `stakingToken.transfer(masterMagpie, donationAmount)` directly (no `deposit()` call), then let a block pass so `updatePool()` runs on the victim's `deposit()`.
4. Assert: `tokenToPoolInfo[stakingToken].accMGPPerShare` after the victim's deposit is strictly less than it would have been absent the donation (compute expected value via `mgpReward * 1e12 / realStakedSupply` vs. actual using inflated `balanceOf`).
5. Assert: sum of all users' claimable MGP (via `_calMGPReward`) over time never reaches the total MGP that should have been emitted (`elapsed * mgpPerSec * allocPoint / totalAllocPoint`), demonstrating a permanent, unclaimable gap — i.e., `_calLpSupply(stakingToken) != realStakedSum` while `IERC20(stakingToken).balanceOf(masterMagpie)` includes the un-credited donation.

    function updatePool(address _stakingToken) public whenNotPaused {
        PoolInfo storage pool = tokenToPoolInfo[_stakingToken];
        if (block.timestamp <= pool.lastRewardTimestamp || totalAllocPoint == 0) {
            return;
        }
        uint256 lpSupply = _calLpSupply(_stakingToken);
        if (lpSupply == 0) {
            pool.lastRewardTimestamp = block.timestamp;
            return;
        }        
        uint256 multiplier = block.timestamp - pool.lastRewardTimestamp;
        uint256 mgpReward = (multiplier * mgpPerSec * pool.allocPoint) / totalAllocPoint;
        
        pool.accMGPPerShare = pool.accMGPPerShare + ((mgpReward * 1e12) / lpSupply);
        pool.lastRewardTimestamp = block.timestamp;

        emit UpdatePool(
            _stakingToken,
            pool.lastRewardTimestamp,
            lpSupply,
            pool.accMGPPerShare
        );
    }

    /// @notice internal function to deal with deposit staking token
    function _deposit(address _stakingToken, address _account, uint256 _amount, bool _isVlmgp) internal {
        updatePool(_stakingToken);

        PoolInfo storage pool = tokenToPoolInfo[_stakingToken];
        UserInfo storage user = userInfo[_stakingToken][_account];

        if (user.amount > 0) {
            _harvestMGP(_stakingToken, _account);
        }
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount + _amount;
        if (!_isVlmgp) {
            user.available = user.available + _amount;
            IERC20(pool.stakingToken).safeTransferFrom(address(msg.sender), address(this), _amount);
        }
        user.rewardDebt = (user.amount * pool.accMGPPerShare) / 1e12;

        if (_amount > 0)
            if (!_isVlmgp)
                emit Deposit(_account, _stakingToken, _amount);
            else
                emit DepositNotAvailable(_account, _stakingToken, _amount);
    }

    function _withdraw(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        _harvestAndUnstake(_stakingToken, _account, _amount, _isVlMgp);

        if (!_isVlMgp)
            IERC20(tokenToPoolInfo[_stakingToken].stakingToken).safeTransfer(address(msg.sender), _amount);
        emit Withdraw(_account, _stakingToken, _amount);
    }

    function _harvestAndUnstake(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        updatePool(_stakingToken);

        UserInfo storage user = userInfo[_stakingToken][_account];

        if (!_isVlMgp && user.available < _amount)
            revert WithdrawAmountExceedsStaked();
        else if(user.amount < _amount && _isVlMgp)
            revert UnlockAmountExceedsLocked();
        
        _harvestMGP(_stakingToken, _account);
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount - _amount;
        
        if(!_isVlMgp)
            user.available = user.available - _amount;
        user.rewardDebt = (user.amount * tokenToPoolInfo[_stakingToken].accMGPPerShare) / 1e12;
    }

    function _calLpSupply(address _stakingToken) internal view returns (uint256) {
        if (_stakingToken == address(vlmgp)) {
            return IERC20(address(vlmgp)).totalSupply();
        }
        if (_stakingToken == address(mWomSV)) {
            return IERC20(address(mWomSV)).totalSupply();
        }
        return IERC20(_stakingToken).balanceOf(address(this));
