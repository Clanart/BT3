### Title
`mWOMSVBaseRewarder` never applies the documented reward forfeiture, permanently denying long-term lockers their share of forfeited yield - (File: `rewards/mWOMSVBaseRewarder.sol`)

### Summary
The analogous vulnerability class from the Holograph report — a slashing/penalty calculation that ignores the documented percentage-based mechanism and instead always uses the "full" (unslashed) value — is reproduced in `rewards/mWOMSVBaseRewarder.sol::_calExpireForfeit`. Unlike its sibling contract `rewards/vlMGPBaseRewarder.sol`, which correctly computes a forfeit based on the user's rewardable percentage, the `mWOMSVBaseRewarder` version is hard-coded to never forfeit anything.

### Finding Description
Magpie implements a lock/cooldown + reward-forfeiture mechanism for both `VLMGP` and `mWomSV` lockers, mirrored by two reward contracts, `vlMGPBaseRewarder.sol` and `mWOMSVBaseRewarder.sol`. In the correct implementation, `_calExpireForfeit` asks the locker contract for the "rewardable percent" of the user (based on how much is fully locked vs. still unwinding through cooldown) and forfeits the complement: [1](#0-0) 

This queries `vlMGP.getRewardablePercentWAD(_account)`, which is implemented in `VLMGP.sol` and computes a time/amount-weighted percentage reflecting how much of a user's rewards they should keep versus forfeit while in cooldown: [2](#0-1) 

The `mWomSV` locker (`wombat/mWomSV.sol`) implements the identical `getRewardablePercentWAD` function, indicating the same forfeiture mechanism was intended for mWOMSV holders: [3](#0-2) 

However, `mWOMSVBaseRewarder.sol::_calExpireForfeit` never calls this function. Instead it hardcodes `rewardableAmount = _amount`, meaning the forfeit is always zero regardless of the user's actual lock/cooldown state: [4](#0-3) 

This function is invoked from `_sendReward`, which is reached whenever any unprivileged mWOMSV staker claims rewards: [5](#0-4) 

### Impact Explanation
The forfeit mechanism exists so that a portion of the rewards belonging to users who are unwinding/exiting their lock early is redirected back into the reward pool (via `_queueNewRewardsWithoutTransfer`) for redistribution to remaining, fully-committed long-term lockers. Because `_calExpireForfeit` in `mWOMSVBaseRewarder.sol` always returns 0, this redistribution never occurs for mWOMSV: exiting stakers keep 100% of accrued rewards instead of the documented reduced share, and long-term lockers permanently lose the forfeited yield they are otherwise entitled to receive. This is a permanent freezing/loss of unclaimed yield for the remaining locker population, reachable purely through ordinary staker/claim transactions with no privileged role required.

### Likelihood Explanation
Any unprivileged mWOMSV holder who starts an unlock (enters cooldown) and then claims/harvests rewards through `MasterMagpie`/`mWOMSVBaseRewarder` before their cooldown fully matures will trigger `_sendReward` → `_calExpireForfeit`, always receiving the full reward with zero forfeiture. This requires no special conditions beyond normal lock/unlock/claim usage, making the likelihood high.

### Recommendation
Update `_calExpireForfeit` in `rewards/mWOMSVBaseRewarder.sol` to mirror `vlMGPBaseRewarder.sol`: query `ILocker(mWOMSV).getRewardablePercentWAD(_account)` (or extend `ILocker` to expose this) and compute `rewardableAmount = _amount * rewardablePercentWAD / 1e18` before deriving `forfeitAmount`, so that the documented percentage-based forfeiture is actually applied and redistributed to remaining lockers.

### Proof of Concept
1. User locks mWOM into `mWomSV` and later calls `startUnlock` to begin a cooldown slot (`wombat/mWomSV.sol` `startUnlock`), leaving less than 100% of their balance "fully locked."
2. Rewards accrue to the user's mWOMSV balance in `mWOMSVBaseRewarder` via `_earned`.
3. User claims rewards (through `MasterMagpie`), triggering `_sendReward` → `_calExpireForfeit(_account, userRewards[...])`.
4. Because `_calExpireForfeit` sets `rewardableAmount = _amount` unconditionally (`rewards/mWOMSVBaseRewarder.sol:385-398`), `forfeitAmount` is always `0`, and the user receives 100% of the reward regardless of their in-cooldown status — contrary to the intended behavior demonstrated by the parallel `vlMGPBaseRewarder.sol` implementation that reduces payout based on `getRewardablePercentWAD`.
5. No forfeited amount is ever queued back via `_queueNewRewardsWithoutTransfer` for mWOMSV, so long-term lockers permanently lose the redistribution share they are documented to receive.

```text
    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
```

```text
    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalVlmgp = fullyInLock + inCoolDown;
        if (userTotalVlmgp == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalVlmgp;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalVlmgp / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalVlmgp;
                }

            }
        }

        return percent;
    }
```
