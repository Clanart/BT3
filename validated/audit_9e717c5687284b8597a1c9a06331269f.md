Found a concrete analog: in the auction bid path, the EIP-712 struct hash that the searcher signs over (`bidV3.EncodeData()` / `Bid.EncodeData()`) never includes `bid.MaxGasPrice`'s enforcement against the validated fields, and more importantly the struct-hash chosen for signature verification is selected by an *externally-declared* `version` string rather than by data actually present/used, mirroring the RuniverseLand pattern where an "authoritative" declared value diverges from the value actually used to compute the effect.

### Title
Auction bid `MaxGasPrice` field is not bound by the `ValidateSearcherSig` EIP-712 v2 digest, letting the field be spoofed / omitted from what the searcher signed - (File: kaiax/auction/bid.go, kaiax/auction/eip712.go)

### Summary
`BidPool.validateBidSigs` (`kaiax/auction/impl/bid_pool.go`) verifies the searcher's signature via `bid.ValidateSearcherSig`, which calls `GetHashTypedData` [1](#0-0) . The digest is chosen based on `bp.auctionEntryPointVersion` [2](#0-1) . When the version is v2.1 (`AuctionVersionV2`/anything not `"0.0.2"`), the struct hash comes from `Bid.EncodeData()`, which does **not** include `MaxGasPrice` at all [3](#0-2) . Yet `BidData.MaxGasPrice` is still a settable field on every `Bid` submitted through the public `auction_submitBid` RPC [4](#0-3) .

### Finding Description
The core issue mirrors the referenced report: a value that is used elsewhere for consequential decisions (`MaxGasPrice`, later packed into the actual on-chain calldata that triggers execution — see `EncodeAuctionCallData` for v3 [5](#0-4) ) is never bound to/verified against the value that was cryptographically committed to by the signer, when the pool operates under a "declared" version identifier that does not force consistency between signed and unsigned fields.

Concretely:
- `SubmitBid` accepts a `Bid` (including `MaxGasPrice`) directly from any RPC caller [6](#0-5) .
- `validateBidSigs` only checks `bid.SearcherSig`/`bid.AuctioneerSig` recover to the expected addresses; it never separately validates that `MaxGasPrice` was part of what the searcher actually signed when `auctionEntryPointVersion` is not `"0.0.2"` [7](#0-6) .
- If a pool session/version mismatch occurs (e.g., a node's cached `auctionEntryPointVersion` differs from the version the searcher intended, or an operator/auctioneer forwards a v2-signed bid with an attacker/auctioneer-modified `MaxGasPrice` populated), `ValidateSearcherSig` will still pass because the v2 EIP-712 typehash/`EncodeData()` simply ignores `MaxGasPrice` — the signature says nothing about that field's value.
- The unsigned `MaxGasPrice` then flows unchanged into `EncodeAuctionCallData`/`getBidTxGasLimit` (used for gas accounting) if the module later builds/encodes the bid tx assuming v3 semantics [5](#0-4) [8](#0-7) .

This is the same bug class as the RuniverseLand finding: a field/parameter that determines execution/limits (`MaxGasPrice`, analogous to `plotSize`) is not cross-checked against the value actually authenticated/committed elsewhere (the EIP-712 signature, analogous to the tokenId-encoded plotSize), so the two can silently diverge.

### Impact Explanation
If `MaxGasPrice` can diverge from what the searcher actually authorized, an attacker (or a compromised/malicious auctioneer relay, which per this module's trust model is external to the CN and only its signature is checked) could submit a bid whose signed core fields (`bid`, `callGasLimit`, `data`, etc.) are legitimately signed by a searcher, but with an unauthorized/modified `MaxGasPrice` spliced in, since that field is outside the v2 signed payload. This can lead to incorrect gas-price capping/fee accounting for that bid's settlement, i.e., fee-delegation/gasless-adjacent value miscalculation in the auction settlement path — a concrete "fee or fee-delegation abuse" scenario in the auction module.

### Likelihood Explanation
Requires the auction pool to be actively operating in (or transiently fall back to) v2.1 signature-verification mode while `MaxGasPrice` is nonzero/used downstream, and requires a submitter who controls the unsigned envelope around an otherwise validly-signed bid (the `auctioneer`/relay role, which per the trust model is untrusted beyond its own signature check). This is a narrower likelihood than the original C4 finding (which required no such version-mode condition), so I rate this Medium and flag it as unconfirmed without dynamic testing.

### Recommendation
Always include `MaxGasPrice` in the EIP-712 struct hash (or explicitly reject/zero it) regardless of `version`, so the field can never be set without being part of what the searcher cryptographically committed to; alternatively, reject bids carrying a nonzero `MaxGasPrice` whenever `auctionEntryPointVersion != AuctionVersionV3`.

### Proof of Concept
Not independently executed; based on static code review of `kaiax/auction/bid.go`, `kaiax/auction/eip712.go`, `kaiax/auction/impl/bid_pool.go`, and `blockchain/system/auction.go`. I could not fully verify (within the available static index) whether any downstream caller actually forwards `MaxGasPrice` from a v2-validated bid into `EncodeAuctionCallData` with `AuctionVersionV3` semantics in the same code path, so likelihood/impact should be confirmed with a live Devin session that can trace `GetBidTxGenerator`/`getBidTxGasLimit` call sites end-to-end and, if warranted, reproduce with a unit test that submits a v2-format-signed bid with a spoofed `MaxGasPrice`.

func (b *Bid) ValidateSearcherSig(chainId *big.Int, verifyingContract common.Address, version string) error {
	if chainId == nil {
		return ErrNilChainId
	}

	if common.EmptyAddress(verifyingContract) {
		return ErrNilVerifyingContract
	}

	digest := b.GetHashTypedData(chainId, verifyingContract, version)

	recoveredSender, err := getSigner(b.SearcherSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover searcher sig: %v", err)
	}

	if recoveredSender != b.Sender {
		return fmt.Errorf("invalid searcher sig: expected %v, calculated %v", b.Sender.String(), recoveredSender.String())
	}

	return nil
}

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}

func (bp *BidPool) getBidTxGasLimit(bid *auction.Bid) (uint64, error) {
	bp.auctionInfoMu.RLock()
	buffer := bp.bidTxGasBuffer
	bp.auctionInfoMu.RUnlock()

	data, err := system.EncodeAuctionCallData(bid, bp.auctionEntryPointVersion)
	if err != nil {
		return 0, err
	}

	rules := bp.ChainConfig.Rules(big.NewInt(int64(bid.BlockNumber)))
	intrinsicGas, err := types.IntrinsicGas(data, nil, nil, false, rules)
	if err != nil {
		return 0, err
	}
	floorDataGas := uint64(0)
	if rules.IsPrague {
		floorDataGas, err = blockchain.FloorDataGas(types.TxTypeEthereumDynamicFee, data, 0)
		if err != nil {
			return 0, err
		}
	}

	return max(intrinsicGas+bid.CallGasLimit+buffer, floorDataGas), nil
}

func (b *Bid) EncodeData() []byte {
	encoded := make([]byte, 0)
	encoded = append(encoded, b.TargetTxHash.Bytes()...)
	encoded = append(encoded, common.LeftPadBytes(common.Int64ToByteBigEndian(b.BlockNumber), 32)...)
	encoded = append(encoded, common.LeftPadBytes(b.Sender.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(b.To.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(common.Int64ToByteBigEndian(b.Nonce), 32)...)
	encoded = append(encoded, common.LeftPadBytes(b.Bid.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(common.Int64ToByteBigEndian(b.CallGasLimit), 32)...)
	encoded = append(encoded, crypto.Keccak256Hash(b.Data).Bytes()...)
	return encoded
}

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)
}
