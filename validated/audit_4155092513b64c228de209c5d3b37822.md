### Title
Unsynchronized mutation and read of shared `*auction.Bid.GasLimit` after bid pool lock release causes a data race that can produce non-deterministic auction bundle transactions - (File: `kaiax/auction/impl/bid_pool.go`, `kaiax/auction/impl/getter.go`)

### Summary
`BidPool.AddBid()` inserts a `*auction.Bid` pointer into the shared `bidMap`/`bidTargetMap` while holding `bidMu`, then releases the lock and mutates the same bid object's `GasLimit` field via `bid.SetGasLimit(gasLimit)` **without holding `bidMu`**. Concurrently, the block-building path (`ExtractTxBundles` → `GetBidTxGenerator`) reads and can also write the same field through `bid.GetGasLimit()`/`bid.SetGasLimit()`, also without holding `bidMu`. This mirrors the reported bug class in the Linux `net/iucv` CVE: an object is looked up/published under a lock, the lock is dropped, and the object is then accessed by another code path without a proper reference/synchronization, permitting a use of the object in an inconsistent state.

### Finding Description
`BidPool.insertBid()` publishes the bid pointer into `bp.bidMap` / `bp.bidTargetMap` while `bp.bidMu` is held: [1](#0-0) 

Immediately after `insertBid()` returns (lock released), `AddBid()` computes the gas limit and stores it on the *same, already-published* bid object with no lock protection: [2](#0-1) 

Meanwhile, on the block-building path, `ExtractTxBundles()` retrieves a snapshot of bid pointers from `bidTargetMap` via `GetTargetTxMap()` (which only RLocks long enough to copy the map, not to protect field access on the bid objects themselves): [3](#0-2) [4](#0-3) 

The retrieved bid is then passed to `GetBidTxGenerator`, which reads `bid.GetGasLimit()` and, if it is still zero, computes and writes a new gas limit via `bid.SetGasLimit(gasLimit)` — again without any lock: [5](#0-4) 

Because the bid is published into the pool (and thus reachable by `ExtractTxBundles`/the miner goroutine) before `AddBid()` finishes writing its `GasLimit`, and because both `AddBid()` and `GetBidTxGenerator()` mutate `GasLimit` on the same object without synchronization, there is a genuine, reachable race window: the object is "handed off" into a shared, concurrently-accessed structure under a lock and then touched from two independent goroutines with no reference-count/lock discipline protecting the field — the same root-cause pattern (lookup under lock → release → unsynchronized use of the shared object) that the Linux CVE-2026-68397 report highlights for `afiucv_hs_rcv()`.

### Impact Explanation
An unprivileged/external `Auctioneer`-submitted bid can trigger a race between the RPC-submission goroutine (`auction_submitBid` → `AddBid`) and the block-building goroutine that runs `ExtractTxBundles` concurrently while assembling a block. Depending on scheduling:
- The bid's `GasLimit` field can be read as `0` by `GetBidTxGenerator` in one node while being concurrently set to a nonzero value in another goroutine (classic unsynchronized read/write on a shared field), yielding different generated `BidTx` gas limits (and thus different transaction hashes/content) on different validating nodes for the same underlying bid.
- Because the `BidTx` generated by `GetBidTxGenerator` is included in the block bundle and ultimately affects the produced block, this can lead to state/block divergence between honest nodes that process the same bid at different times relative to the unsynchronized write — a consensus-relevant condition, not merely a benign race.

This satisfies the "state divergence between honest nodes" criterion required for a valid analog, and is reachable purely through the public `auction_submitBid` RPC combined with normal concurrent block building — no privileged/validator-only access is required to submit the racing bid.

### Likelihood Explanation
The race window is narrow but reliably reachable: `AddBid()`'s unlocked `bid.SetGasLimit()` call happens on essentially every successful bid submission, and `ExtractTxBundles()` (invoked by the miner during block assembly) runs concurrently and continuously as blocks are being built. Any bid landing in the target block window (`allowFutureBlock = 2`) is immediately visible to `GetTargetTxMap()` before `AddBid()`'s subsequent `SetGasLimit` completes, so the race is triggered under normal, unprivileged auction usage rather than requiring contrived timing control by an attacker.

### Recommendation
Move the `bid.SetGasLimit(gasLimit)` call in `BidPool.AddBid()` to happen **before** the bid is published into `bp.bidMap`/`bp.bidTargetMap` inside `insertBid()` (i.e., compute and set the gas limit while still holding `bidMu`, prior to making the bid visible), or protect all reads/writes of `Bid.GasLimit` with the bid pool's mutex (or a per-bid lock/atomic) so that no goroutine can observe a partially-initialized bid once it is reachable via `bidMap`/`bidTargetMap`. The same synchronization should be extended to `GetBidTxGenerator`'s conditional `SetGasLimit` call in `kaiax/auction/impl/getter.go`.

### Proof of Concept
1. Submit a valid bid via `auction_submitBid` targeting the next mineable block; `BidPool.AddBid()` calls `insertBid()` which publishes the bid pointer into `bidTargetMap` under `bidMu`, then releases the lock and calls `bid.SetGasLimit(gasLimit)` unlocked.
2. Concurrently, have the miner's block-building goroutine call `ExtractTxBundles()` (which happens continuously in production), which calls `GetTargetTxMap()` and immediately observes the just-published bid pointer, then calls `GetBidTxGenerator(tx, bid)`.
3. If `GetBidTxGenerator` executes its `bid.GetGasLimit() == 0` check before step 1's `SetGasLimit` completes, `GetBidTxGenerator` itself calls `bid.SetGasLimit(gasLimit)` concurrently with the original `AddBid` goroutine's write — an unsynchronized concurrent write (data race, detectable with `go test -race`), and depending on scheduling, different nodes processing the same bid may observe different `GasLimit` values, producing different `BidTx` transactions from the same bid for the same target block.

func (bp *BidPool) AddBid(bid *auction.Bid) (common.Hash, error) {
	if atomic.LoadUint32(&bp.running) == 0 {
		return common.Hash{}, auction.ErrAuctionPaused
	}

	if err := bp.validateBid(bid); err != nil {
		return common.Hash{}, err
	}

	if err := bp.insertBid(bid); err != nil {
		return common.Hash{}, err
	}

	gasLimit, err := bp.getBidTxGasLimit(bid)
	if err != nil {
		return common.Hash{}, err
	}
	bid.SetGasLimit(gasLimit)

	bp.newBidCh <- bid

	return bid.Hash(), nil
}

func (bp *BidPool) insertBid(bid *auction.Bid) error {
	bp.bidMu.Lock()
	defer bp.bidMu.Unlock()

	var (
		blockNumber  = bid.BlockNumber
		targetTxHash = bid.TargetTxHash
		sender       = bid.Sender
	)

	// Re-check bidWinnerMap here — two concurrent bids can pass validateBid together.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		return auction.ErrBidAlreadyExists
	}
	if bp.senderHasDifferentWinner(bid) {
		return auction.ErrBidSenderExists
	}

	// If same block number, same target tx hash exists, replace it if it's better
	if existingBid, ok := bp.bidTargetMap[blockNumber][targetTxHash]; ok {
		// FCFS if the bid is the same.
		if existingBid.Bid.Cmp(bid.Bid) >= 0 {
			return auction.ErrLowBid
		}

		logger.Trace("Replace bid", "old", existingBid.Hash(), "new", bid.Hash())
		delete(bp.bidMap, existingBid.Hash())
		delete(bp.bidWinnerMap[blockNumber], existingBid.Sender)
	} else {
		if int64(len(bp.bidMap)) >= bp.maxBidPoolSize {
			logger.Info("Bid pool is full", "maxBidPoolSize", bp.maxBidPoolSize, "bid", bid.Hash())
			return auction.ErrBidPoolFull
		}
	}

	hash := bid.Hash()

	bp.initializeBidMap(blockNumber)

	bp.bidMap[hash] = bid
	bp.bidTargetMap[blockNumber][targetTxHash] = bid
	bp.bidWinnerMap[blockNumber][sender] = hash

	numBidsGauge.Update(int64(len(bp.bidMap)))

	logger.Trace("Add bid", "bid", hash)

	return nil
}

func (a *AuctionModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	bundles := []*builder.Bundle{}
	curBlock := a.Chain.CurrentBlock()
	if curBlock == nil || atomic.LoadUint32(&a.bidPool.running) == 0 {
		return bundles
	}

	miningBlock := curBlock.NumberU64() + 1
	bidTargetMap := a.bidPool.GetTargetTxMap(miningBlock)
	if len(bidTargetMap) == 0 {
		return bundles
	}

	for _, tx := range txs {
		txHash := tx.Hash()
		bid, ok := bidTargetMap[txHash]
		if !ok {
			continue
		}
		b := builder.NewBundle(
			builder.NewTxOrGenList(a.GetBidTxGenerator(tx, bid)),
			txHash,
			true,
		)
