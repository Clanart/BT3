### Title
Gasless swap repayment is computed from declared gas-limit fees, not actual gas used, structurally overcharging users in favor of the proposer - (File: kaiax/gasless/impl/getter.go)

### Summary
In Kaia's KIP-247 gasless-transaction flow, the amount a gasless user must repay the block proposer (`AmountRepay`) is computed entirely from the *declared* transaction fees (`GasLimit * GasPrice`) of the lend/approve/swap transactions, not from the gas actually consumed on-chain. Because Kaia's standard gas-refund mechanism already returns unused gas (`GasLimit - GasUsed`) to the paying account, the value "locked" into the repay obligation and the value that is actually spent by the proposer on gas necessarily diverge — mirroring the Lyra `lockedCollateral.base` vs. `sETH balance` divergence, where a committed/locked accounting value is not kept in sync with the real balance movement it is supposed to track.

### Finding Description
`lendAmount()` and `repayAmount()` in `kaiax/gasless/impl/getter.go` compute the amount the proposer lends and the amount the user must repay purely from `tx.Fee()` (i.e., `GasLimit * GasPrice`) of the `ApproveTx`/`SwapTx`, plus a fixed `21000 * GasPrice` component for the lend transaction itself: [1](#0-0) 

This `AmountRepay` is embedded by the user (or the wallet/proposer tooling constructing the bundle) into the swap calldata and enforced against the router contract via `VerifyExecutable`'s SP4 check: [2](#0-1) 

However, Kaia's core gas-accounting model (`buyGas`) always charges the *maximum* possible fee up front and later refunds unused gas back to whichever account paid for gas: [3](#0-2) 

The project's own test harness independently confirms that the declared/estimated fee (used to compute `AmountRepay` and `lendAmount`) systematically diverges from the actual fee paid, requiring an explicit post-hoc reconciliation step (`AdjustFeesByReceipts`) that exists only in test code, not in the production settlement path: [4](#0-3) 

In other words, exactly like the Lyra `lockedCollateral.base` figure that is bumped optimistically but never reliably reconciled against the real `sETH` balance, the `AmountRepay`/`lendAmount` values baked into a gasless bundle are computed from the conservative gas-limit-based fee estimate and are never reconciled against the real gas cost actually incurred for `LendTx`/`ApproveTx`/`SwapTx`. Since `GasLimit` is set with headroom above actual execution cost (as acknowledged by the very comment "Execution overhead ... is not captured by IntrinsicGas"), the repay amount collected from the user's swap output is structurally inflated relative to the proposer's real gas expenditure, and the excess is captured by the proposer/router rather than being refunded to the user.

### Impact Explanation
Every gasless user is forced, by protocol-enforced calldata validation (SP4), to repay a fee computed from the pessimistic gas-limit estimate rather than the real gas used. The gap between `GasLimit` and actual `GasUsed` is systematically pocketed as extra value transferred to the proposer (in addition to any declared `commission`), rather than returned to the user who initiated the swap — this is an unauthorized/uncapped value transfer baked into every gasless swap, not an isolated edge case.

### Likelihood Explanation
This triggers on every ordinary gasless approve+swap transaction pair submitted by any unprivileged user via public RPC (`debug_isGaslessTx`/normal tx submission) — no special conditions, malicious peer, or privileged role required. The divergence between `GasLimit` and `GasUsed` is the normal case in practice, since callers must add safety margin to gas limits.

### Recommendation
Compute `AmountRepay` (and the `LendTxGenerator`'s lend value) from the actual gas consumed by `ApproveTx`/`SwapTx` execution (or refund the delta back to the user post-execution), analogous to how `AdjustFeesByReceipts` reconciles estimated vs. actual fees in the test harness — but as an on-chain/protocol-level guarantee rather than a test-only correction.

### Proof of Concept
1. A gasless user submits `ApproveTx` (nonce n) + `SwapTx` (nonce n+1) with typical safety-margin gas limits (e.g., `GasLimit` set to 150% of expected usage).
2. `repayAmount()` computes `AmountRepay = GasPrice*21000 + ApproveTx.Fee() + SwapTx.Fee()`, using the full `GasLimit*GasPrice` for each transaction.
3. `VerifyExecutable`'s SP4 check enforces that the swap's `AmountRepay` matches this gas-limit-based figure exactly.
4. On execution, `buyGas`/gas-refund logic returns unused gas `(GasLimit - GasUsed) * GasPrice` to the payer, but the swap has already extracted the full gas-limit-based `AmountRepay` from the user's swap proceeds — the user is charged for gas they never consumed, with no corresponding refund path in the gasless settlement flow. func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}

	// st.gasPrice = tx.gasPrice (before Magma) or effectiveGasPrice (since Magma)
	mgval := new(big.Int).Mul(new(big.Int).SetUint64(st.msg.Gas()), st.gasPrice)

	// GasFeeCap = tx.maxFeePerGas (if exists) or tx.gasPrice

			blobFeeCap := new(big.Int).SetUint64(blobGas)

	if validatedFeePayer == validatedSender {

		// 2. FeeDelegatedWithRatio with sender == feePayer
		// 3. FeeDelegated          with sender == feePayer

		// Therefore, all options are false.

// AdjustFeesByReceipts corrects the accountMap after mining by reconciling the estimated
// intrinsic gas fee (used in Update) against the actual gas used recorded in receipts.
// This is necessary because Update() uses IntrinsicGas as an approximation, which excludes
// execution overhead (e.g., constructor gas, code storage cost for contract deployments).
// txs must be b.Transactions() and receipts must be the corresponding block receipts.
func (a *AccountMap) AdjustFeesByReceipts(txs types.Transactions, receipts types.Receipts, blockNum uint64) error {
	if a.chainConfig == nil || len(a.txFeeCache) == 0 {
		return nil
	}

	blockNumBig := new(big.Int).SetUint64(blockNum)
	rules := a.chainConfig.Rules(blockNumBig)
	isNonDeferred := a.chainConfig.Governance == nil || !a.chainConfig.Governance.DeferredTxFee()

	for i, tx := range txs {
		cached, ok := a.txFeeCache[tx.Hash()]
		if !ok {
			continue // tx was skipped in Update (txHashesExpectedFail) or not tracked
		}

		actualFee := new(big.Int).Mul(tx.GasPrice(), new(big.Int).SetUint64(receipts[i].GasUsed))
		delta := new(big.Int).Sub(actualFee, cached.estimatedFee)
		if delta.Sign() == 0 {
			continue
		}

		// delta > 0: actual > estimated (e.g. constructor or execution gas not in IntrinsicGas)
		//   → deduct delta from payer, add delta/2 to rewardbase
		// delta < 0: actual < estimated (e.g. EIP-7702 authorization refund > execution gas)
		//   → refund |delta| to payer, subtract |delta|/2 from rewardbase
		// SubBalance with a negative value adds to balance; AddBalance with negative subtracts.
		if cached.hasFeeRatio {
			deltaByFeePayer, deltaBySender := types.CalcFeeWithRatio(cached.feeRatio, delta)
			a.SubBalance(cached.feePayer, deltaByFeePayer)
			a.SubBalance(cached.from, deltaBySender)
		} else {
			a.SubBalance(cached.feePayer, delta)
		}

		rewardDelta := new(big.Int).Set(delta)
		if rules.IsMagma && isNonDeferred {
			rewardDelta.Div(rewardDelta, big.NewInt(2))
		}
		a.AddBalance(a.rewardbase, rewardDelta)
	}
