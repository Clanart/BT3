Audit Report

## Title
Attacker-selectable `before`/`until` signature forces full historical block reconstruction on every `getSignaturesForAddress` call - (File: `ledger/src/blockstore.rs`)

## Summary
`Blockstore::get_confirmed_signatures_for_address2` resolves an attacker-supplied `before` (and separately `until`) signature to a slot and then calls the private helper `get_block_signatures_rev`, which calls `get_complete_block(slot, false)` to reconstruct the *entire* block's transactions merely to recover a reversed list of first signatures for ordering/truncation purposes. Since a client fully controls the `before`/`until` signature values passed to the public `getSignaturesForAddress` RPC method, they can repeatedly target the largest rooted block in ledger history, making per-call cost proportional to that block's size rather than to the requested `limit`.

## Finding Description
`get_confirmed_signatures_for_address2` looks up the slot for `before` via `get_transaction_status`, then calls `self.get_block_signatures_rev(slot)` purely to find the position of `before` within the block's signature ordering and truncate accordingly. [1](#0-0) 
The same full-block reconstruction happens again for `until`. [2](#0-1) 
`get_block_signatures_rev` performs the expensive work: it calls `get_complete_block(slot, false)`, which deshreds and reconstructs the full block (all entries/transactions), then discards everything except the first signature of each transaction. [3](#0-2) 
There is no size cap, cache, or cost accounting tied to the size of the block referenced by `before`/`until`; the cost is decoupled from the `limit` parameter that normally bounds RPC response cost. This method is reachable from the public, unprivileged `getSignaturesForAddress` RPC method in `rpc/src/rpc.rs`, which forwards the `before`/`until` parameters supplied by any RPC client. A rooted block's transaction signatures are public data (obtainable from any block explorer or by scanning blocks once), so an attacker can deterministically select a `before`/`until` signature belonging to the largest historical block and repeat the call to force disproportionate CPU/IO work on the validator's RPC-serving path, independent of the requested `limit` or any per-call rate limiting based on response size.

## Impact Explanation
This matches the "single-client low-rate RPC crash/degradation" category in scope: an unprivileged client sending a normal rate of `getSignaturesForAddress` requests can force repeated, disproportionately expensive full-block deshred/reconstruction work on the validator, degrading RPC-serving latency/CPU without needing a high request rate. The wrong/uncontrolled resource is the CPU/IO cost of the RPC call, which becomes bound to an attacker-chosen historical block size rather than the `limit` parameter that request-cost accounting is normally expected to scale with.

## Likelihood Explanation
Likelihood is moderate-to-high. Exploitation requires no privileges beyond ordinary RPC access, and only knowledge of a signature located in a large historical rooted block, which is trivially and publicly obtainable. The vulnerable code path is exercised on every call that supplies a `before` or `until` parameter, both being standard, documented parameters of `getSignaturesForAddress`, and the call can be repeated indefinitely since nothing invalidates or caches the result of a specific `before`/`until` lookup.

## Recommendation
Avoid full block reconstruction solely to resolve signature ordering for `before`/`until`. Use the existing per-slot ordering data already available via `address_signatures_cf` / `transaction_status_cf` (which encode per-slot transaction index) instead of `get_complete_block`, or introduce a lightweight per-slot signature-order cache/index. Additionally, apply resource accounting in the RPC layer that reflects the cost of resolving `before`/`until` (e.g., proportional to referenced block size) rather than accounting only for the response `limit`.

## Proof of Concept
1. Identify a transaction signature from one of the largest rooted blocks in ledger history (e.g., via a public block explorer).
2. Call `getSignaturesForAddress` with `before` set to that signature; the server-side call reaches `get_confirmed_signatures_for_address2` → `get_block_signatures_rev` → `get_complete_block`, fully deshredding/reconstructing that large block.
3. Repeat the call using a signature from a small block and compare observed latency/CPU.
4. The measured disparity demonstrates per-call cost is controlled by the attacker-chosen `before`/`until` block rather than by `limit`, confirming the RPC cost is unbounded relative to normal per-response cost accounting. [3](#0-2) [4](#0-3)

    fn get_block_signatures_rev(&self, slot: Slot) -> Result<Vec<Signature>> {
        let block = self.get_complete_block(slot, false).map_err(|err| {
            BlockstoreError::Io(IoError::other(format!("Unable to get block: {err}")))
        })?;

        Ok(block
            .transactions
            .into_iter()
            .rev()
            .filter_map(|transaction_with_meta| {
                transaction_with_meta
                    .transaction
                    .signatures
                    .into_iter()
                    .next()
            })
            .collect())
    }

    pub fn get_confirmed_signatures_for_address2(
        &self,
        address: Pubkey,
        highest_slot: Slot, // highest_super_majority_root or highest_confirmed_slot
        before: Option<Signature>,
        until: Option<Signature>,
        limit: usize,
    ) -> Result<SignatureInfosForAddress> {
        let max_root = self.max_root();
        let confirmed_unrooted_slots: HashSet<_> =
            AncestorIterator::new_inclusive(highest_slot, self)
                .take_while(|&slot| slot > max_root)
                .collect();

        // Figure the `slot` to start listing signatures at, based on the ledger location of the
        // `before` signature if present.  Also generate a HashSet of signatures that should
        // be excluded from the results.
        let mut get_before_slot_timer = Measure::start("get_before_slot_timer");
        let (slot, mut before_excluded_signatures) = match before {
            None => (highest_slot, None),
            Some(before) => {
                let transaction_status =
                    self.get_transaction_status(before, &confirmed_unrooted_slots)?;
                match transaction_status {
                    None => return Ok(SignatureInfosForAddress::default()),
                    Some((slot, _)) => {
                        let mut slot_signatures = self.get_block_signatures_rev(slot)?;
                        if let Some(pos) = slot_signatures.iter().position(|&x| x == before) {
                            slot_signatures.truncate(pos + 1);
                        }

                        (
                            slot,
                            Some(slot_signatures.into_iter().collect::<HashSet<_>>()),
                        )
                    }
                }
            }
        };
        get_before_slot_timer.stop();
