## Title
Unbounded pagination loop in `CW721ERC721Pointer.balanceOf()` can be forced to exceed the block gas limit, permanently DoS'ing any transaction that depends on it - (File: `contracts/src/CW721ERC721Pointer.sol`)

### Summary
`CW721ERC721Pointer.balanceOf()` counts a CW721 owner's tokens by repeatedly calling the `WasmdPrecompile.query` with `start_after` pagination (1000 tokens per page) inside a `while` loop that only terminates when the query returns an empty token list. There is no cap on the number of iterations, so the gas cost of `balanceOf()` grows linearly, without bound, with the number of NFTs an address owns on the underlying CosmWasm collection.

### Finding Description
The loop is: [1](#0-0) 

Each iteration performs a `WasmdPrecompile.query` (a synthetic CosmWasm smart-query call routed through the wasmd precompile), extracts the returned token list via `JsonPrecompile.extractAsBytesList`, and issues another query starting after the last token returned, until the CW721 contract returns `{"tokens":[]}`. Because a single owner can accumulate an arbitrary number of NFTs on the backing CW721 contract (e.g. by minting many low-cost/no-cost tokens to that address, which is possible for any CW721 contract with permissionless or cheap minting, or simply by acquiring/being sent many tokens), the number of pages — and therefore the number of expensive cross-VM `wasmd` precompile queries — is unbounded and fully attacker-controlled. This mirrors the reported bug class: an operation that must iterate an entire per-account collection in a single call, with no cap on that collection's size, so the call can be pushed past the block/transaction gas limit purely by growing the account's on-chain data.

### Impact Explanation
`balanceOf` is the standard ERC721 entry point that other on-chain contracts rely on for accounting, collateral checks, allow-list/holding checks, or batched operations. Once an address's underlying CW721 token count is large enough that a full pagination scan exceeds the available gas, `balanceOf()` for that address becomes permanently uncallable from within any state-changing transaction (and effectively unusable even for `eth_call`, since RPC nodes cap simulated gas). Any protocol logic composed on top of the pointer contract that calls `balanceOf` as part of an atomic operation (e.g., verifying NFT holdings before a transfer, mint, unlock, or liquidation-style action) will permanently revert for that address, matching the "permanent freezing"/DoS impact class from the reference report (there it froze liquidation of an account with too many pending quotes; here it freezes any composed operation that needs to know an address's balance on a pointer contract with too many tokens).

### Likelihood Explanation
Likelihood is moderate-to-high: any user or attacker can grow the number of tokens associated with a target address on the backing CW721 contract (their own address, to grief themselves-and-others' composability, or by sending/airdropping many NFTs to a victim address) without any special privilege, since pointer contracts are meant to be usable with arbitrary/attacker-deployed CW721 collections. No governance or validator collusion is required — a single CosmWasm mint transaction sequence from an unprivileged sender is sufficient to build the oversized collection before anyone calls `balanceOf` on the pointer.

### Recommendation
Cap the number of pages/tokens counted by `balanceOf()` (e.g., rely on the CW721 contract's own `num_tokens`/enumeration count if available, or track counts incrementally in the pointer contract's own storage on mint/transfer/burn instead of re-deriving them via unbounded pagination), and/or bound the maximum number of pagination iterations and revert with a clear "count too large, use alternate method" error rather than silently consuming unbounded gas.

### Proof of Concept
1. Deploy/reference a CW721 collection with cheap or permissionless minting.
2. Mint enough tokens to a single Sei address `X` (thousands+) so that the number of `tokens` pagination pages needed to enumerate `X`'s holdings, at 1000 tokens/page, exceeds what fits in a block's gas limit when executed through the `CW721ERC721Pointer`.
3. Call `CW721ERC721Pointer.balanceOf(X)` from any contract/transaction context that requires it to complete atomically with other logic (e.g., a marketplace or vault contract that checks `balanceOf` before proceeding).
4. Observe the call runs out of gas / exceeds the caller's gas limit and reverts every time, permanently blocking any composed operation that depends on `balanceOf(X)` succeeding. [1](#0-0)

    function balanceOf(address owner_) public view override returns (uint256) {
        if (owner_ == address(0)) {
            revert ERC721InvalidOwner(address(0));
        }
        uint256 numTokens = 0;
        string memory startAfter;
        string memory qb = string.concat(
            string.concat("\"limit\":1000,\"owner\":\"", AddrPrecompile.getSeiAddr(owner_)),
            "\""
        );
        bytes32 terminator = keccak256("{\"tokens\":[]}");

        bytes[] memory tokens;
        uint256 tokensLength;
        string memory req = string.concat(string.concat("{\"tokens\":{", qb), "}}");
        bytes memory response = WasmdPrecompile.query(Cw721Address, bytes(req));
        while (keccak256(response) != terminator) {
            tokens = JsonPrecompile.extractAsBytesList(response, "tokens");
            tokensLength = tokens.length;
            numTokens += tokensLength;
            startAfter = string.concat(",\"start_after\":", string(tokens[tokensLength-1]));
            req = string.concat(
                string.concat("{\"tokens\":{", string.concat(qb, startAfter)),
                "}}"
            );
            response = WasmdPrecompile.query(Cw721Address, bytes(req));
        }
        return numTokens;
    }
