### Title
Front-running one's own `queueMGP` harvest via `VLMGP.lockFor`/`lock` to reduce `forfeitAmount` and steal socialized forfeiture rewards - ([File: rewards/vlMGPBaseRewarder.sol])

### Summary
`vlMGPBaseRewarder._calExpireForfeit` computes the forfeiture on a pending MGP payout using a live, unsnapshotted call to `vlMGP.getRewardablePercentWAD(_account)` [1](#0-0) . Because this percentage is recomputed at the moment `queueMGP` executes rather than being fixed to the state that accrued the reward, a staker can top up their fully-locked MGP balance immediately before their harvest is processed to inflate the "rewardable" fraction and reduce the amount forfeited to the shared reward pool.

### Finding Description
`queueMGP` is called by `MasterMagpie._sendMGPForVlMGPPool` with an `_amount` equal to the account's already-accrued `unClaimedMgp` (unrelated to any fresh lock) [2](#0-1) . Inside `queueMGP`, `_calExpireForfeit(_account, _amount)` queries `vlMGP.getRewardablePercentWAD(_account)` live [3](#0-2) .

The analogous `getRewardablePercentWAD` implementation (mirrored in `wombat/mWomSV.sol`, same pattern used by `VLMGP.sol` per the shared interface `IVLMGP.getRewardablePercentWAD`) computes:
```
percent = fullyInLock * 1e18 / (fullyInLock + inCoolDown)
+ weighted contributions from amounts still in/  past cooldown
``` [4](#0-3) 

Since `fullyInLock` grows immediately when the user calls `lock`/`lockFor` with fresh MGP, and `inCoolDown` amounts (the diluting/penalized cooldown state) stay fixed, adding a fresh lock right before the harvest transaction raises `fullyInLock/(fullyInLock+inCoolDown)`, pushing `rewardablePercentWAD` toward 1e18. This directly reduces `forfeitAmount` computed in `_calExpireForfeit` for the pre-existing pending MGP reward, and correspondingly increases `rewardableAmount` sent to the receiver in `queueMGP` [5](#0-4) . No modifier, cooldown-lock, or snapshot mechanism prevents this: `onlyManager`/`nonReentrant` only gate who calls `queueMGP`, not the timing-sensitivity of the underlying percentage calculation used inside it.

### Impact Explanation
The forfeited portion is redistributed to all vlMGP stakers via `_queueNewRewardsWithoutTransfer` [6](#0-5) . By manipulating `rewardablePercentWAD` right before their own harvest is triggered, an attacker captures a larger share of their own pending MGP payout than their historical lock/cooldown state entitles them to, at the direct expense of the socialized forfeiture pool that other vlMGP holders would otherwise receive. This is a theft of unclaimed/socialized yield from other stakers (Immunefi: "theft of unclaimed yield").

### Likelihood Explanation
The attack requires only: (1) an existing vlMGP position with an active cooldown/unlock schedule diluting `rewardablePercentWAD`, (2) spare MGP to lock, and (3) the ability to sequence `lock`/`lockFor` immediately before the harvest transaction that triggers `queueMGP` (same block or back-to-back transactions, no special permissions needed). This is fully repeatable on every harvest cycle and requires no privileged role, making it a feasible, low-cost, and repeatable exploit for any unprivileged staker with an active cooldown position.

### Recommendation
Snapshot the `rewardablePercentWAD` (or the components `fullyInLock`/`inCoolDown`) at the time the reward accrues rather than recomputing it live at `queueMGP`/harvest time, or require a minimum holding period after any `lock`/`lockFor` action before it can affect the rewardable percentage used for pending forfeiture calculations.

### Proof of Concept
Foundry test plan:
1. Set up `VLMGP`, `vlMGPBaseRewarder`, and `MasterMagpie` with the attacker holding an existing vlMGP position that has triggered an early unlock/cooldown (so `getRewardablePercentWAD(attacker) < 1e18`).
2. Accrue a pending MGP reward for the attacker in `MasterMagpie` (e.g., via normal pool emissions) so `unClaimedMgp[stakingToken][attacker] > 0`.
3. Baseline: call `MasterMagpie.multiclaimFor` for the attacker without any extra lock; record `forfeitAmount` emitted in `MGPHarvested` from `queueMGP`.
4. Reset state (or use a fork/snapshot) and repeat, but call `VLMGP.lock(extraMGP)` from the attacker immediately before `multiclaimFor`.
5. Assert that `vlMGP.getRewardablePercentWAD(attacker)` after step 4 is strictly greater than in step 3, and that the resulting `forfeitAmount` in `MGPHarvested` is strictly lower (and `rewardableAmount` sent to attacker is strictly higher) than the baseline, for the exact same pre-existing `_amount` of pending MGP — demonstrating the attacker unlocked extra value purely by timing a self-lock around their own harvest.

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }
```

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalmWomSV = fullyInLock + inCoolDown;
        if (userTotalmWomSV == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalmWomSV;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalmWomSV / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalmWomSV;
                }

            }
        }

        return percent;
    }
