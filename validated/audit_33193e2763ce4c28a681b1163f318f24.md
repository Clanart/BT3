### Title
Forged `ReceivedOutput` deserialization can report nonexistent wallet funds as spendable - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput::read` accepts the claimed scalar offset, `TxOut`, and outpoint as three independent, unauthenticated fields without proving that the outpoint exists or contains that `TxOut` [1](#0-0) . An attacker who can submit bytes to this reader can therefore inject a stored output that appears wallet-controlled and carries an arbitrary value [2](#0-1) . The transaction builder trusts that injected value and outpoint when constructing inputs [3](#0-2) .

### Finding Description
`Scanner::scan_transaction` normally creates a `ReceivedOutput` only after finding a transaction output whose `script_pubkey` was registered for the wallet [4](#0-3) . The serialized form loses that provenance: `ReceivedOutput::read` merely parses `offset`, `output`, and `outpoint` and returns them as a valid object [5](#0-4) . `SignableTransaction::new` then sums the claimed `TxOut` value as available input, stores the claimed `TxOut` as a Taproot prevout, and inserts the attacker-chosen outpoint into the transaction [3](#0-2) [6](#0-5) . The later multisig check only verifies that `keys.offset(offset)` produces the declared script, which an attacker can satisfy by choosing both the scalar and script together [7](#0-6) .

### Impact Explanation
A forged record can report arbitrary funds as received even though no such UTXO exists, and the wallet can proceed through FROST signing for a transaction that Bitcoin consensus will reject [8](#0-7) . This can corrupt balance accounting, trigger a withdrawal or fee-spending workflow based on phantom inputs, or cause an otherwise valid batch to fail when broadcast [9](#0-8) . Because a scalar-offset output can be made script-compatible without knowing the wallet secret, the attacker does not need control of the wallet key or an existing wallet UTXO [10](#0-9) .

### Likelihood Explanation
The exploit only requires an untrusted byte stream to reach `ReceivedOutput::read`, such as forged persisted wallet data or another unauthenticated transport carrying serialized outputs [1](#0-0) . No Bitcoin transaction has to be accepted by the network because the parser never checks the claimed outpoint against the chain [11](#0-10) .

### Recommendation
Treat serialized `ReceivedOutput` values as authenticated internal state, not attacker-supplied evidence of payment: protect them with a keyed MAC bound to the wallet key, or revalidate the outpoint and full prevout against the Bitcoin UTXO set before crediting or signing [1](#0-0) . Store enough chain provenance to distinguish scanner-derived outputs from deserialized claims, and reject outputs whose `outpoint` does not resolve to the exact encoded `TxOut` [4](#0-3) .

### Proof of Concept
```rust
use bitcoin::{
  OutPoint, TxOut, Amount,
  consensus::serialize,
};
use bitcoin_serai::wallet::{p2tr_script_buf, ReceivedOutput, SignableTransaction};
use frost::{curve::Secp256k1, ThresholdKeys};
use k256::{ProjectivePoint, Scalar};
use rand_core::OsRng;

fn forged_received_output(
  wallet_key: ProjectivePoint,
) -> ReceivedOutput {
  // Choose an offset and derive a script which will pass the later offset/script check.
  let mut offset = Scalar::random(&mut OsRng);
  let script = loop {
    if let Some(script) =
      p2tr_script_buf(wallet_key + (ProjectivePoint::GENERATOR * offset))
    {
      break script;
    }
    offset += Scalar::ONE;
  };

  let fake_txout = TxOut {
    value: Amount::from_sat(100_000_000),
    script_pubkey: script,
  };

  // The claimed outpoint does not need to exist on-chain.
  let mut encoded = offset.to_bytes().to_vec();
  encoded.extend(serialize(&fake_txout));
  encoded.extend(serialize(&OutPoint::null()));

  ReceivedOutput::read(&mut encoded.as_slice()).unwrap()
}
```

`forged.value()` reports 100,000,000 satoshis despite the null outpoint because `read` returns the claimed `TxOut` unchanged [12](#0-11) . `SignableTransaction::new(vec![forged], &[], Some(change_script), None, fee_rate)` accepts it as an input and serializes `OutPoint::null()` as its `previous_output` [3](#0-2) . Calling `multisig(&keys)` also succeeds because the attacker deliberately generated `fake_txout.script_pubkey` from `wallet_key + G * offset` [7](#0-6) .
