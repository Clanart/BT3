### Title
Missing Proof-of-Possession in `associatePublicKey` Allows Unauthorized Forced Address Association - (File: `precompiles/addr/addr.go`)

### Summary
The Buildbot advisory (CVE-2019-12300) describes accepting a user-submitted credential (an OAuth token) and using it to authenticate as another user without proving the submitter actually controls it. The `addr` precompile's `Associate` method correctly requires a signature (proof of private-key possession) before linking an EVM address to a Sei address, but the sibling `AssociatePubKey` method accepts only a raw public key — with no signature, challenge, or possession check — and uses it to permanently bind the derived EVM/Sei address pair and migrate balances.

### Finding Description
`PrecompileExecutor.associate` derives `evmAddr`/`seiAddr` from an ECDSA signature (`v,r,s`) over a `customMessage`, which cryptographically proves the caller controls the corresponding private key: [1](#0-0) 

In contrast, `associatePublicKey` derives the same address pair directly from a caller-supplied public key with zero proof of possession: [2](#0-1) 

Both paths converge on `associateAddresses`, which only checks that the target `seiAddr` isn't already associated — it never verifies the caller is the pubkey's owner — before calling `AssociationHelper.AssociateAddresses`: [3](#0-2) 

`AssociateAddresses` sets the permanent address mapping, sets the account pubkey, and immediately triggers `MigrateBalance`, which moves all spendable coins and wei balance from the "cast" shadow address (`sdk.AccAddress(evmAddr[:])`) to the derived `seiAddr`, and can remove the cast account entirely: [4](#0-3) 

Because Cosmos SDK account public keys become publicly visible on-chain as soon as an account has broadcast a single transaction (retrievable via the `auth` module / any indexer), any unprivileged EVM caller can take a victim's already-public pubkey and call `associatePublicKey` on their behalf — without the victim ever signing anything for Sei — to force the association and balance migration to occur on the attacker's chosen timing, and to permanently block the victim's own future legitimate `associate()` call (which will revert with "already associated" once bound).

### Impact Explanation
This is a `CWE-287`-class authentication weakness analogous to the Buildbot flaw: identity/ownership is established purely from a submitted public credential (the public key) instead of proof of possession of the matching private key. The concrete effects are:
- Forced, attacker-timed migration of the victim's cast-address `usei`/wei balances into the Sei address, executed without the victim's authorization.
- Permanent lock-out of the victim's legitimate `Associate`/`AssociatePubKey` self-association, since the precompile only guards against double-association, not against association by a non-owner.

### Likelihood Explanation
The attack requires only knowledge of a target account's public key, which is inherently public for any Cosmos account that has previously transacted, and the call is reachable by any unprivileged EVM/precompile caller with no special privileges — matching the reachable-surface criteria (public RPC client / contract caller invoking a Cosmos precompile).

### Recommendation
Require proof of private-key possession for `associatePublicKey` just as `associate` does (e.g., require a signature over a nonce/challenge message that recovers to the supplied public key), or remove the pubkey-only association path and require callers to go through the signature-based flow exclusively.

### Proof of Concept
1. Observe any Sei account `V` that has broadcast at least one Cosmos transaction; retrieve its secp256k1 public key via the `auth` module query (public keys are stored on-chain once revealed).
2. From an unrelated EVM account, call the `addr` precompile at `0x0000000000000000000000000000000000001004` method `associatePubKey(pubKeyHex)` passing `V`'s public key hex, as exercised in the test harness: [5](#0-4) 
3. The call succeeds without any signature from `V`, forcing the association and balance migration in `AssociateAddresses`/`MigrateBalance` on `V`'s behalf, and any subsequent association attempt by `V` will fail with "already associated" as returned by `associateAddresses`: [6](#0-5)

func (p PrecompileExecutor) associatePublicKey(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}

	// Takes a single argument, a compressed pubkey in hex format, excluding the '0x'
	pubKeyHex := args[0].(string)

	pubKeyBytes, err := hex.DecodeString(pubKeyHex)
	if err != nil {
		return nil, 0, err
	}

	// Parse the compressed public key
	pubKey, err := btcec.ParsePubKey(pubKeyBytes)
	if err != nil {
		return nil, 0, err
	}

	// Convert to uncompressed public key
	uncompressedPubKey := pubKey.SerializeUncompressed()

	evmAddr, seiAddr, pubkey, err := helpers.GetAddressesFromPubkeyBytes(uncompressedPubKey)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p PrecompileExecutor) associateAddresses(ctx sdk.Context, method *abi.Method, evmAddr common.Address, seiAddr sdk.AccAddress, pubkey cryptotypes.PubKey) (ret []byte, remainingGas uint64, err error) {
	// Check that address is not already associated
	_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if found {
		return nil, 0, fmt.Errorf("address %s is already associated with evm address %s", seiAddr, evmAddr)
	}

	// Associate Addresses:
	associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.bankKeeper, p.accountKeeper)
	err = associationHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false)
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(seiAddr.String(), evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}
