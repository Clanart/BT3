### Title
Unauthenticated disclosure of the encrypted emergency-stop transaction via `InternalGetEmergencyStopTx` when `client_verification` is disabled - ([File: core/src/rpc/interceptors.rs], [File: core/src/servers.rs])

### Summary
The `only_aggregator_and_self` authorization check that gates all `Internal*` RPCs (including `internal_get_emergency_stop_tx`) is only installed as the connection interceptor when `config.client_verification == true`. When it is `false`, `create_grpc_server` wires in `Interceptors::Noop`, which passes every request through unchanged, so the `is_internal`/`leaf_cert == our_cert` binding is never evaluated for any caller.

### Finding Description
The binding the aggregator relies on is: `caller_identity == self` for any RPC whose gRPC method name starts with `Internal`, enforced by `is_internal(&req)` plus `leaf_cert == our_cert` inside `only_aggregator_and_self` [1](#0-0) . This function is only ever invoked from the `Interceptor::call` match arm `Interceptors::OnlyAggregatorAndSelf` [2](#0-1) .

`create_grpc_server` decides which interceptor variant to install strictly based on `config.client_verification`: if `true`, it builds `OnlyAggregatorAndSelf` with the loaded certs; if `false`, it installs `Interceptors::Noop`, which simply forwards the request with `Ok(req)` and performs no identity check at all [3](#0-2) . `create_aggregator_grpc_server` explicitly logs a warning when verification is enabled, implying the disabled state is a supported/expected deployment mode, not a defect path [4](#0-3) .

`AggregatorServer::verify_and_save_emergency_stop_sigs` computes the fully-signed emergency-stop transaction, encrypts it with `emergency_stop_encryption_public_key`, and stores it via `insert_signed_emergency_stop_tx_if_not_exists` keyed by `move_to_vault_txid` [5](#0-4) . The corresponding `InternalGetEmergencyStopTx` RPC (defined in `core/src/rpc/clementine.proto`/generated `clementine.rs`, implemented in `core/src/rpc/aggregator.rs`) reads this stored ciphertext and decrypts/returns it to the caller. Under `Noop`, any unauthenticated TCP client can invoke this `Internal*` method directly, since the `is_internal` gate that would normally require `leaf_cert == our_cert` is unreachable.

### Impact Explanation
An attacker who knows (or brute-forces/observes) a `move_to_vault_txid` can retrieve the plaintext emergency-stop transaction before the security council or aggregator intends to broadcast it. This is premature disclosure of a protocol commitment: the attacker can front-run or race the emergency-stop broadcast, potentially confirming a conflicting transaction first or otherwise undermining the emergency-stop mechanism's timing guarantees. This matches the "High – premature disclosure of a protocol commitment" impact category. It does not by itself move bridge value or forge signatures, but it degrades the emergency-stop safety mechanism across every deposit for which an emergency-stop signature has been aggregated.

### Likelihood Explanation
This requires the deployment to run the aggregator with `client_verification = false`, which is an explicit, supported configuration branch in `create_grpc_server`/`create_aggregator_grpc_server` (not a test-only code path) [3](#0-2) . Given that precondition, exploitation costs nothing beyond a plaintext gRPC connection and knowledge of a `move_to_vault_txid` (learnable from chain data), and it is repeatable for every deposit that has completed emergency-stop signature aggregation.

### Recommendation
Do not rely solely on `client_verification` to gate `Internal*` methods. Enforce the `is_internal` + self-identity check unconditionally (e.g., always run identity/self-origin verification for `Internal*` RPCs regardless of the `Noop`/`OnlyAggregatorAndSelf` selection), or refuse to serve `Internal*` methods over any listener that isn't provably loopback/self-originated when `client_verification` is disabled.

### Proof of Concept
1. Start an aggregator test instance with `client_verification = false` (forcing `Interceptors::Noop`).
2. Call `verify_and_save_emergency_stop_sigs` (or directly call `db.insert_signed_emergency_stop_tx_if_not_exists`) to store a signed, encrypted emergency-stop tx for a known `move_to_vault_txid`.
3. Open a raw `tonic` channel to the aggregator's TCP port with no client certificate (plaintext/unauthenticated), and issue `InternalGetEmergencyStopTx { move_to_vault_txid }`.
4. Assert the RPC succeeds (no `Status::unauthenticated`) and returns the decrypted emergency-stop transaction bytes matching what was stored — demonstrating that `is_internal`/`leaf_cert == our_cert` was never evaluated.
