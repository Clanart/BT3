### Title
Public-key based forced association permanently freezes payments to an unassociated EVM/Sei cast address without proof of private-key ownership - ([File: precompiles/addr/addr.go])

### Summary
The `addr` precompile's `associatePubKey` method (and the underlying `AssociationHelper.AssociateAddresses`) lets *any* caller permanently link an arbitrary EVM address to its derived Sei address by submitting only the target's raw public key — with no signature, no proof of private-key possession, and no consent from the address owner. Because secp256k1 public keys are routinely public (visible in every signed Cosmos/EVM transaction), an unrelated third party can force this identity-linking state change for a victim who never opted in, exactly analogous to CVE-2021-25323's class of bug: a sensitive credential/identity-linking change performed without requiring proof tied to the current owner.

### Finding Description
`associatePublicKey`/`associatePubKey` derives `evmAddr` and `seiAddr` directly from a caller-supplied public key and immediately calls `associateAddresses`, which only checks that the *target* Sei address isn't already associated — it performs no check that the caller is the key owner: [1](#0-0) 

The `associate` (signature-based) variant does require a valid ECDSA signature over a custom message, proving private-key possession: [2](#0-1) 

But `associatePubKey` requires no such proof — a bare public key is sufficient input, and public keys are not secret (they can be harvested from any prior signed transaction by the victim). The shared `AssociateAddresses` helper then unconditionally overwrites the address mapping and migrates the direct-cast address's balance to the pubkey-derived Sei address: [3](#0-2) [4](#0-3) 

Once this forced association exists, `CanAddressReceive` permanently blocks any subsequent bank transfer aimed at the un-associated "direct-cast" address representation of that EVM address, because the cast address no longer resolves to itself: [5](#0-4) 

### Impact Explanation
Any unprivileged actor can force-associate a victim's EVM address ahead of time using only a harvested public key. After this forced association, `CanAddressReceive` will reject bank sends to the victim's not-yet-associated direct-cast address (`sdk.AccAddress(evmAddr[:])`), permanently freezing/failing any transfer still in flight or expected to land at that cast address (e.g., an exchange withdrawal, bridge payout, or counterparty payment prepared before the victim associated). This satisfies the "permanent freezing of funds" impact bar without requiring any cooperation, private key, or prior authorization from the victim — mirroring the CVE's root cause of skipping verification of the current/previous credential holder before a sensitive account-state change.

### Likelihood Explanation
High reachability: `associatePubKey` is a public EVM precompile method at `0x0000000000000000000000000000000000001004`, callable by any transaction sender with an arbitrary target public key argument. Public keys of active accounts are trivially obtainable from public chain history (any signed tx reveals its signer's pubkey), so no privileged access or victim cooperation is needed to trigger the freeze.

### Recommendation
Require the caller to prove possession of the private key corresponding to the supplied public key before performing (or allowing a third party to trigger) an association — e.g., mandate a fresh signature check identical to the `associate` method's flow, or restrict `associatePubKey` to only be invocable by the EVM `tx.origin`/msg.sender whose derived address matches the supplied pubkey, so that no third party can force an association for an address they do not control.

### Proof of Concept
1. Observe any signed transaction from victim `V` on Sei (Cosmos tx or EVM tx); extract `V`'s compressed public key.
2. From any unrelated account, call `addr.associatePubKey(V_pubkey_hex)` on the `0x1004` precompile.
3. `associatePublicKey` → `associateAddresses` (`precompiles/addr/addr.go:239-255`) finds `V`'s Sei address not yet associated, and unconditionally calls `AssociateAddresses`, setting the EVM↔Sei mapping for `V` without any signature check.
4. Any subsequent bank transfer sent to `sdk.AccAddress(V_evmAddr[:])` (the direct-cast form) is rejected by `CanAddressReceive` (`x/evm/keeper/address.go:81-86`), permanently freezing that transfer path for `V`, who never requested or authorized the association.

func (p PrecompileExecutor) associate(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}

	// v, r and s are components of a signature over the customMessage sent.
	// We use the signature to construct the user's pubkey to obtain their addresses.
	v := args[0].(string)
	r := args[1].(string)
	s := args[2].(string)
	customMessage := args[3].(string)

	rBytes, err := decodeHexString(r)
	if err != nil {
		return nil, 0, err
	}
	sBytes, err := decodeHexString(s)
	if err != nil {
		return nil, 0, err
	}
	vBytes, err := decodeHexString(v)
	if err != nil {
		return nil, 0, err
	}

	vBig := new(big.Int).SetBytes(vBytes)
	rBig := new(big.Int).SetBytes(rBytes)
	sBig := new(big.Int).SetBytes(sBytes)

	// Derive addresses
	vBig = new(big.Int).Add(vBig, utils.Big27)

	customMessageHash := crypto.Keccak256Hash([]byte(customMessage))
	evmAddr, seiAddr, pubkey, err := helpers.GetAddresses(vBig, rBig, sBig, customMessageHash)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p PrecompileExecutor) associateAddresses(ctx sdk.Context, method *abi.Method, evmAddr common.Address, seiAddr sdk.AccAddress, pubkey cryptotypes.PubKey) (ret []byte, remainingGas uint64, err error) {
	// Check that address is not already associated
	_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if found {
		return nil, 0, fmt.Errorf("address %s is already associated with evm address %s", seiAddr, evmAddr)
	}

	// Associate Addresses:
	associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.bankKeeper, p.accountKeeper)
	err = associationHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false)
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(seiAddr.String(), evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}

// A sdk.AccAddress may not receive funds from bank if it's the result of direct-casting
// from an EVM address AND the originating EVM address has already been associated with
// a true (i.e. derived from the same pubkey) sdk.AccAddress.
func (k *Keeper) CanAddressReceive(ctx sdk.Context, addr sdk.AccAddress) bool {
	directCast := common.BytesToAddress(addr) // casting goes both directions since both address formats have 20 bytes
	associatedAddr, isAssociated := k.GetSeiAddress(ctx, directCast)
	// if the associated address is the cast address itself, allow the address to receive (e.g. EVM contract addresses)
	return associatedAddr.Equals(addr) || !isAssociated // this means it's either a cast address that's not associated yet, or not a cast address at all.
}
