### Title
Zero-threshold multisig spending condition allows funds to be spent with no valid signatures - (File: `stacks-codec/src/transaction.rs`)

### Summary
`MultisigSpendingCondition::verify` and `OrderIndependentMultisigSpendingCondition::verify` accept a spending condition as authenticated whenever the number of signatures counted equals (or, for order-independent, is at least) `signatures_required`. Neither the deserializer nor `TransactionSpendingCondition::new_multisig_p2sh`/`new_multisig_p2wsh`/`new_multisig_order_independent_p2sh`/`new_multisig_order_independent_p2wsh` nor `StacksAddress::from_public_keys` reject `signatures_required == 0`. When the threshold is 0, the verification loop over `fields` need not process a single `TransactionAuthField::Signature` entry — `num_sigs` stays `0`, which trivially equals (or exceeds) `signatures_required = 0`, so the "must recover N valid ECDSA signatures" check passes vacuously, exactly as the Rubicon `route.length - 1 == 0` loop vacuously satisfied `currentAmount >= buy_amt_min` when `buy_amt_min == 0`.

### Finding Description
`MultisigSpendingCondition::verify` at [1](#0-0)  iterates `self.fields`; if all fields are `PublicKey` entries (or the field vector is empty), `num_sigs` never increments, so `num_sigs != self.signatures_required` fails to trigger only when `signatures_required == 0`. The same vacuous-pass pattern exists in `OrderIndependentMultisigSpendingCondition::verify` at [2](#0-1) , where the check is `num_sigs < self.signatures_required`, again trivially satisfied at threshold 0.

Nothing in the codec deserializers enforces a nonzero threshold: [3](#0-2)  only checks that the number of `Signature` fields *equals* `signatures_required` (0 == 0 passes), and the order-independent variant at [4](#0-3)  only checks `num_sigs_given < signatures_required` (0 < 0 is false, so it passes too). The convenience constructors also accept `num_sigs = 0` unchecked: [5](#0-4) .

The final address-equality check calls `StacksAddress::from_public_keys` with `self.signatures_required as usize` as the threshold: [6](#0-5) . That function only rejects the case where `pubkeys.len() < num_sigs` [7](#0-6) ; `num_sigs == 0` is always "sufficient" regardless of key count, and `to_bits_p2sh`/`to_bits_p2sh_p2wsh` happily hash a `0`-of-N redeem script [8](#0-7) .

### Impact Explanation
If any account is (deliberately or mistakenly) created as a "0-of-N" P2SH/P2WSH multisig address — i.e. `signatures_required = 0` — then any party who knows that address's public-key set (or even none, since `fields` can be empty of `PublicKey` entries too, as long as the resulting hash still needs to match `signer`) can construct a spending condition that is accepted by `verify()` without ever presenting a valid ECDSA signature. This breaks the core equality that authorization requires recovering at least `signatures_required` valid signatures over the sighash, letting an asset move (STX transfer, contract call, etc.) with zero actual proof of key ownership — a forged authorization, matching the "Critical" impact bucket (asset moves without authorization).

### Likelihood Explanation
Exploitation requires that a `signatures_required = 0` spending condition exists and is funded — this is a self-inflicted precondition analogous to the Rubicon report's "2 user errors" scenario (single-entry route + zero slippage). Nothing in the wallet-facing constructors (`new_multisig_p2sh`, etc.) or the codec deserializer stops a caller/tool from producing such a condition, so it is reachable through ordinary transaction construction/signing code paths, not just crafted bytes. Given the explicit user-error precedent set by the original finding (downgraded to Medium for requiring user mistakes), the direct analog here likely warrants Medium/High rather than assuming attacker-only exploitation, since it depends on an address having been created with a zero threshold.

### Recommendation
Reject `signatures_required == 0` for `Multisig`/`OrderIndependentMultisig` spending conditions at every construction/deserialization boundary:
- Add an explicit `signatures_required >= 1` check in `MultisigSpendingCondition::consensus_deserialize` and `OrderIndependentMultisigSpendingCondition::consensus_deserialize` (`stacks-codec/src/transaction.rs`).
- Add the same check in `TransactionSpendingCondition::new_multisig_p2sh`, `new_multisig_p2wsh`, `new_multisig_order_independent_p2sh`, `new_multisig_order_independent_p2wsh`.
- Optionally harden `StacksAddress::from_public_keys` to return `None` when `num_sigs == 0` for `SerializeP2SH`/`SerializeP2WSH`, closing the gap at the lowest-level primitive as well.

### Proof of Concept
1. Construct (via `TransactionSpendingCondition::new_multisig_p2sh(0, pubkeys)`, or by hand-crafting bytes through `consensus_deserialize`) a `MultisigSpendingCondition` with `signatures_required = 0` and `fields = vec![]` (or only `PublicKey` fields, no `Signature` fields). The constructor and deserializer both accept this — see [3](#0-2)  and [9](#0-8) .
2. Fund the resulting P2SH address (`Hash160` derived from `to_bits_p2sh(0, pubkeys)`), e.g. as a testnet/mainnet multisig wallet mistakenly created with threshold 0.
3. Craft a `StacksTransaction` whose origin spending condition is this same `MultisigSpendingCondition` (signer/nonce/tx_fee copied, `fields` left with zero `Signature` entries).
4. Call `verify()`: the loop over `fields` produces `num_sigs = 0`; `0 != self.signatures_required (0)` is `false`, so the "incorrect number of signatures" branch at [10](#0-9)  is skipped, `StacksAddress::from_public_keys` reproduces the same signer hash, and `verify()` returns `Ok(..)` — the transaction is authenticated and can move the funded STX/asset with zero real signatures presented.

        &self,
        initial_sighash: &Txid,
        cond_code: &TransactionAuthFlags,
        mode: TransactionAuthVerificationMode,
    ) -> Result<Txid, AuthError> {
        let mut pubkeys = vec![];
        let mut cur_sighash = initial_sighash.clone();
        let mut num_sigs: u16 = 0;
        let mut have_uncompressed = false;
        for field in self.fields.iter() {
            let pubkey = match field {
                TransactionAuthField::PublicKey(ref pubkey) => {
                    if !pubkey.compressed() {
                        have_uncompressed = true;
                    }
                    pubkey.clone()
                }
                TransactionAuthField::Signature(ref pubkey_encoding, ref sigbuf) => {
                    if *pubkey_encoding == TransactionPublicKeyEncoding::Uncompressed {
                        have_uncompressed = true;
                    }

                    let (pubkey, next_sighash) = TransactionSpendingCondition::next_verification(
                        &cur_sighash,
                        cond_code,
                        self.tx_fee,
                        self.nonce,
                        pubkey_encoding,
                        sigbuf,
                        mode,
                    )?;

                    num_sigs = num_sigs
                        .checked_add(1)
                        .ok_or(AuthError::VerifyingError("Too many signatures".to_string()))?;

                }
            };

        }

            return Err(AuthError::VerifyingError(

    pub fn from_public_keys(
        version: u8,
        hash_mode: &AddressHashMode,
        num_sigs: usize,
        pubkeys: &Vec<StacksPublicKey>,
    ) -> Option<StacksAddress> {
        // must be sufficient public keys
        if pubkeys.len() < num_sigs {
            return None;
        }

        // address hash mode must be consistent with the number of keys
        match *hash_mode {
            AddressHashMode::SerializeP2PKH | AddressHashMode::SerializeP2WPKH
                // must be a single public key, and must require one signature
                if (num_sigs != 1 || pubkeys.len() != 1) => {
                    return None;
                }
            _ => {}
        }

        // if segwit, then keys must all be compressed
        match *hash_mode {
            AddressHashMode::SerializeP2WPKH | AddressHashMode::SerializeP2WSH => {
                for pubkey in pubkeys {
                    if !pubkey.compressed() {
                        return None;
                    }
                }
            }
            _ => {}
        }

        let hash_bits = public_keys_to_address_hash(hash_mode, num_sigs, pubkeys);
        StacksAddress::new(version, hash_bits).ok()
    }

/// Internally, the Stacks blockchain encodes address the same as Bitcoin
/// multi-sig address (p2sh)
fn to_bits_p2sh<K: PublicKey>(num_sigs: usize, pubkeys: &Vec<K>) -> Hash160 {
    let mut bldr = Builder::new();
    bldr = bldr.push_int(num_sigs as i64);
    for pubk in pubkeys {
        bldr = bldr.push_slice(&pubk.to_bytes());
    }
    bldr = bldr.push_int(pubkeys.len() as i64);
    bldr = bldr.push_opcode(btc_opcodes::OP_CHECKMULTISIG);

    let script = bldr.into_script();
    Hash160::from_data(script.as_bytes())
}

/// Internally, the Stacks blockchain encodes address the same as Bitcoin
/// single-sig address over p2sh (p2h-p2wpkh)
fn to_bits_p2sh_p2wpkh<K: PublicKey>(pubk: &K) -> Hash160 {
    let key_hash = Hash160::from_data(&pubk.to_bytes());

    let bldr = Builder::new().push_int(0).push_slice(key_hash.as_bytes());

    let script = bldr.into_script();
    Hash160::from_data(script.as_bytes())
}

/// Internally, the Stacks blockchain encodes address the same as Bitcoin
/// multisig address over p2sh (p2sh-p2wsh)
fn to_bits_p2sh_p2wsh<K: PublicKey>(num_sigs: usize, pubkeys: &Vec<K>) -> Hash160 {
    let mut bldr = Builder::new();
    bldr = bldr.push_int(num_sigs as i64);
    for pubk in pubkeys {
        bldr = bldr.push_slice(&pubk.to_bytes());
    }
    bldr = bldr.push_int(pubkeys.len() as i64);
    bldr = bldr.push_opcode(btc_opcodes::OP_CHECKMULTISIG);

    let mut digest = Sha256::new();
    let mut d = [0u8; 32];

    digest.update(bldr.into_script().as_bytes());
    d.copy_from_slice(&digest.finalize());

    let ws = Builder::new().push_int(0).push_slice(&d).into_script();
    Hash160::from_data(ws.as_bytes())
}
