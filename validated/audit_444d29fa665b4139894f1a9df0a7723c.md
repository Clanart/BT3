### Title
Deflationary/Fee-on-Transfer Token Breaks Gasless Balance/Allowance Admission Checks Leading to Wasted Gas-Lending and Denial of Gasless Service - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The Kaia `kaiax/gasless` module admits `SwapTx`/`ApproveTx` pairs into the tx pool and later lends KAIA to cover a user's gas by statically checking the ERC20 token's `balanceOf`/`allowance`/router-quoted `amountIn` at admission time. These checks assume the ERC20 token moves exactly the declared `amountIn` on `transferFrom`, an assumption that is false for fee-on-transfer/deflationary/rebasing tokens — the exact bug class described in the external report. Because `AllowedTokensFlag` defaults to `"all"` [1](#0-0)  any ERC20, including non-standard ones, can be registered as a gasless-swap token, making this reachable by an ordinary unprivileged gasless user.

### Finding Description
`checkBalanceForSwap` validates a swap transaction using only static ERC20 view calls before proposer lends KAIA gas to the sender: [2](#0-1) 

Specifically, it checks:
- `tx.token.allowance(sender, router) >= tx.amountIn`
- `tx.token.balanceOf(sender) >= tx.amountIn`
- `tx.amountIn >= gsr.getAmountIn(minAmountOut)` (a DEX quote) [3](#0-2) 

These checks compare the *declared* `amountIn` field decoded from the transaction calldata against a static balance/allowance snapshot: [4](#0-3) . Nowhere in this admission logic (nor in `VerifyExecutable`) is there a pre/post-balance delta check on the token contract itself: [5](#0-4) .

When `swapForGas` on the `GaslessSwapRouter` (KIP-247) system contract actually executes, it must (per the ABI/binding and the emitted `SwappedForGas(proposer, amountRepaid, user, finalUserAmount, commission)` event) pull `amountIn` tokens from the sender via `transferFrom`, swap them through the DEX for KAIA, repay the proposer `amountRepay`, and forward the remainder (`finalUserAmount`) to the user: [6](#0-5) , [7](#0-6) . The integration test explicitly encodes the assumption that the token behaves as a standard, non-fee ERC20: `currentBalanceOfTestAcc == preSwapBalanceOfTestAcc - swapAmount` [8](#0-7) , and the deadline/insufficient-balance/insufficient-approval reverts modeled in the test suite are all based on exact-amount ERC20 semantics [9](#0-8) .

If a fee-on-transfer or rebasing/deflationary token is used (allowed by default configuration, since `AllowedTokens: nil` means all tokens are allowed [10](#0-9) ), the router will receive less than `amountIn` tokens after `transferFrom`. The DEX swap step inside `swapForGas` then either:
1. Reverts because the router cannot swap the full `amountIn` it never actually received (insufficient balance inside the router), or
2. Produces output below `minAmountOut`, tripping the DEX's own slippage check and reverting.

Because the mempool-level `checkBalanceForSwap`/`VerifyExecutable` checks used static `balanceOf`/`allowance` (not the deflationary token's effective transferable amount), a swap that looks valid at admission time systematically fails at execution time for any token with balance-changing transfer semantics.

### Impact Explanation
This does not directly cause fund theft from the protocol treasury, but it creates a denial-of-service against the gasless/gas-lending mechanism for any campaign/token pairing that uses a deflationary/rebasing/fee-on-transfer ERC20: transactions that pass mempool admission deterministically revert on execution, wasting the block proposer's gas-lending flow and the gas budget allotted to bundle inclusion, and preventing legitimate gasless swaps from ever succeeding for such tokens. Because `swapForGas` is expected to be atomic (transferFrom + swap + repay proposer + pay user in one call), a revert means the proposer's lent KAIA/repayment step never completes within that call, and the entire lending bundle fails — repeatedly, for every attempt with that token — degrading the gasless service's reliability and potentially enabling a griefing vector where a user's `ApproveTx`+`SwapTx` bundle occupies pool nonce space/bundling slots (`MaxBundleTxsInPending`/`MaxBundleTxsInQueue`) with guaranteed-to-fail swaps.

### Likelihood Explanation
Likelihood is Medium: the `gasless.allowed-tokens` flag defaults to `"all"` [1](#0-0) , and there is no on-chain validation that a token registered for gasless usage is a standard, balance-preserving ERC20. Any unprivileged user can submit an `ApproveTx`/`SwapTx` pair referencing an arbitrary allowed token; if the node operator or governance registers (or defaults allow) a fee-on-transfer/rebasing token, every swap attempt using it is affected deterministically, not probabilistically.

### Recommendation
- In `checkBalanceForSwap`/`VerifyExecutable` (`kaiax/gasless/impl/tx_pool.go`, `kaiax/gasless/impl/getter.go`), validate that the token's effective transferable amount (e.g., simulate `transferFrom` and measure the router's actual balance delta, or explicitly reject tokens with fee-on-transfer/rebasing behavior) matches `amountIn` before admitting swaps.
- Restrict `AllowedTokensFlag`'s default from `"all"` to an explicit allow-list validated for standard ERC20 balance-preserving semantics, and reject tokens whose `balanceOf` can change outside of `transfer`/`transferFrom` (rebasing) or whose received amount is less than the sent amount (fee-on-transfer).
- Have the `GaslessSwapRouter.swapForGas` implementation measure its own actual token balance increase after `transferFrom` and use that measured value (not the caller-declared `amountIn`) for the subsequent DEX swap, so deflationary tokens fail safely rather than reverting the whole atomic lending flow.

### Proof of Concept
Conceptual PoC (contract source for `GaslessSwapRouter` is compiled-only in this repo, so exact line-level PoC against it cannot be constructed from the indexed sources; behavior inferred from ABI/bindings and the `tx_pool.go` checks):
1. Deploy a fee-on-transfer ERC20 `FeeToken` that burns/deducts 5% on every `transfer`/`transferFrom`, and register it via governance/`AllowedTokensFlag` for the gasless module.
2. User approves `GaslessSwapRouter` for `amountIn = 1000` `FeeToken`, and their static balance is `1000`.
3. `checkBalanceForSwap` passes: `allowance(sender, router) == 1000 >= amountIn`, `balanceOf(sender) == 1000 >= amountIn`, and `getAmountIn(minAmountOut)` quote also passes based on `amountIn = 1000`. See [11](#0-10) .
4. Transaction is bundled and lent gas by proposer.
5. On execution, `GaslessSwapRouter.swapForGas` calls `transferFrom(sender, router, 1000)`, but router only receives `950` due to the token's transfer fee. The subsequent DEX swap attempts to swap `1000` (the declared `amountIn`), which the router does not actually hold, causing the underlying UniswapV2 swap call to revert (or, if router uses its actual balance, the swap output falls below `minAmountOut`, tripping the DEX-side slippage check) — matching the `SwappedForGas`-less failure path exercised in [9](#0-8) .
6. Result: the gasless bundle fails deterministically for every user attempting this admitted-but-unexecutable swap, despite passing all mempool-level `checkBalanceForSwap` validations.

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {

		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// If SwapTx.nonce is the sender's next nonce, then there is no room for ApproveTx proceeding SwapTx.
		senderNonce := g.getCurrentStateNonce(swapArgs.Sender)
		noApproveTxPreceeds := swapNonce == senderNonce
		if noApproveTxPreceeds {
			// tx.token.allowance(sender, router) >= tx.amountIn
			approval, err := tokenContract.Allowance(nil, swapArgs.Sender, swapRouter)
			if err != nil {
				return err
			}
			if approval.Cmp(swapArgs.AmountIn) < 0 {
				return fmt.Errorf("insufficient approval: approval=%s, want=%s", approval.String(), swapArgs.AmountIn.String())
			}
		}

		// tx.token.balanceOf(sender) >= tx.amountIn
		balance, err := tokenContract.BalanceOf(nil, swapArgs.Sender)
		if err != nil {
			return err
		}
		if balance.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("insufficient balance: balance=%s, want=%s", balance.String(), swapArgs.AmountIn.String())
		}
	}

	// tx.deadline >= currentTimestamp
	deadline := swapArgs.Deadline
	if deadline.Cmp(g.Chain.CurrentBlock().Time()) < 0 {
		return fmt.Errorf("insufficient deadline: deadline=%s, want=%s", deadline.String(), g.Chain.CurrentBlock().Time().String())
	}

	return nil
}

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}
