## Analysis Result [1](#0-0) 

### Title
Divide-by-zero panic in `KIP71Config.NextMagmaBlockBaseFee` from unguarded zero `GasTarget` governance parameter - (File: params/kip71_config.go)

### Summary
`NextMagmaBlockBaseFee` divides by `kc.GasTarget` twice without ever checking it for zero, unlike its sibling parameter `BaseFeeDenominator`, which explicitly falls back to a safe default when zero. If the `kip71.gastarget` governance parameter is ever ratified to `0`, every node computing the next block's base fee (during block assembly and during header verification) hits a Go `big.Int` division by zero and panics, crashing the node — directly analogous to the AMD `calculate_mcache_setting` bug where a zero divisor derived from an unchecked parameter (viewport width/height) caused a kernel panic.

### Finding Description
`NextMagmaBlockBaseFee` reads the governance-controlled `GasTarget` value and uses it unguarded as a divisor in both the "gas used > target" and "gas used < target" branches: [2](#0-1) 

Note that `BaseFeeDenominator` — a peer governance parameter used in the very same function — is defensively checked and defaulted when zero: [3](#0-2) 

No equivalent guard exists for `GasTarget`. Checking the governance parameter registry confirms `Kip71GasTarget`'s `FormatChecker` is a no-op, accepting any `uint64` including `0`, whereas parameters like `BaseFeeDenominator` explicitly reject `0`: [4](#0-3) 

The header-governance consistency check (`checkConsistency`) also does not special-case `Kip71GasTarget` — it falls into the generic bucket that unconditionally returns `nil` (accepts any value already passed by `NewVoteData`'s format checker): [5](#0-4) 

If `GasTarget == 0`, then in `NextMagmaBlockBaseFee`, `parentGasUsed = min(parentHeaderGasUsed, upperGasLimit)` will always be `> gasTarget` (unless `parentHeaderGasUsed` is also 0, in which case the `else` branch is taken and divides by zero there instead), and the code executes `x.Div(x, new(big.Int).SetUint64(gasTarget))` with `gasTarget == 0`. Go's `math/big.Int.Div` panics on division by zero, crashing any node executing this code path.

This function is invoked from consensus-critical paths: header verification (`VerifyMagmaHeader`) and fee estimation (`processBlock` in `node/cn/gasprice/feehistory.go`), meaning the panic is reachable both during normal block processing/validation by every node, and via a public RPC call (`eth_feeHistory`). [6](#0-5) [7](#0-6) 

### Impact Explanation
If `kip71.gastarget` is ratified to `0` via governance, every full node in the network (validators and non-validators alike) that calls `NextMagmaBlockBaseFee` — during block header verification, block assembly, or answering `eth_feeHistory` RPC queries near a Magma-active fork boundary — will panic and crash. This is a network-wide denial-of-service: honest nodes halt/crash while attempting consensus-critical base-fee computation, which can also cause state divergence/chain halt since block validation cannot proceed past the point the parameter takes effect.

### Likelihood Explanation
Triggering this requires the governance parameter `kip71.gastarget` to be voted and ratified to `0`. In `single` governance mode (Mainnet/Kairos), only the governing node can cast an effective vote; the vote/ratification path (`governance_vote` API, header `Vote`/`Governance` fields) performs no zero-value validation for this specific parameter, either at the `FormatChecker` level or in `checkConsistency`. Once ratified, the zero value is applied automatically at the next epoch boundary and affects every node computing `NextMagmaBlockBaseFee`, with no way to skip or reject the resulting panic — unlike the fixed AMD bug pattern, there is no early-return/guard to gracefully reject the invalid configuration.

### Recommendation
Add an explicit zero-guard for `GasTarget` in `NextMagmaBlockBaseFee`, mirroring the existing `BaseFeeDenominator == 0` fallback (e.g., default to `DefaultGasTarget` or reject/skip the update), and add a `FormatChecker` for `Kip71GasTarget` in `kaiax/gov/param.go` that rejects `0` (consistent with `Kip71BaseFeeDenominator`'s `v != 0` check) so an invalid vote can never be ratified in the first place.

### Proof of Concept
1. As the governing node (single mode), cast `governance_vote("kip71.gastarget", 0)`.
2. Once ratified at the epoch boundary and effective at the next epoch, any node — proposer building the next block, or any node verifying that block's header — calls `KIP71Config.NextMagmaBlockBaseFee(parentNum, parentBaseFee, parentGasUsed)`.
3. With `GasTarget == 0` and `parentGasUsed != gasTarget` (true whenever `parentGasUsed != 0`), the code executes `x.Div(x, new(big.Int).SetUint64(0))` in the `parentGasUsed > gasTarget` branch (params/kip71_config.go:102), or in the `else` branch when `parentGasUsed == 0` too (line 120) — both panic with "division by zero", crashing the node process.
