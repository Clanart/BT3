The cleartext-transmission bug class maps to PedPoP's ECDH: if a participant registers an identity/zero encryption key, the shared secret becomes identity — publicly derivable. Check whether `read_G` rejects identity.### Title
PedPoP accepts an identity encryption key, making every ECDH shared secret publicly known — DKG secret shares are effectively transmitted in cleartext - ([File: crypto/dkg/pedpop/src/encryption.rs])

### Summary
The PedPoP DKG encrypts each participant's secret share with ChaCha20 keyed by `H(context || ECDH(per_message_key, recipient_enc_key))`. The recipient's `enc_key` is an untrusted group element read with `Ciphersuite::read_G`, which rejects only non-canonical encodings — not the identity point. A participant who registers `enc_key = identity` causes every sender's ECDH to collapse to the identity element, whose encoding is public. Any passive observer can recompute the cipher and decrypt all secret shares destined for that participant.

### Finding Description
- `EncryptionKeyMessage::read` parses `enc_key` via `C::read_G` (`crypto/dkg/pedpop/src/encryption.rs:57-59`).
- `Ciphersuite::read_G` checks only canonical encoding; identity is accepted (`crypto/ciphersuite/src/lib.rs:91-101`). The stricter identity-rejecting `read_G` exists only on `frost::Curve` (`crypto/frost/src/curve/mod.rs:125-131`), but PedPoP is generic over `Ciphersuite` and never uses it.
- `Decryption::register` stores the key without validation (`encryption.rs:351-362`); `verify_r1` calls it on every received commitment message (`lib.rs:315`).
- `encrypt` computes `ecdh(&key, to)` = `to * key` (`encryption.rs:95-97`, `153-154`). With `to = identity`, the shared point is identity for every sender and every message.
- `cipher` derives the ChaCha20 key solely from `context` (a public `[u8; 32]`) and the shared point encoding, with a fixed IV (`encryption.rs:101-133`). `H(context || identity_encoding)` is computable by anyone.
- Result: every `EncryptedMessage` sent to the malicious participant — containing their `SecretShare` from each other participant — is decryptable by any observer of the wire.

### Impact Explanation
Secret shares are the sole confidential input to `calculate_share`; the final private share is `sum_i share_i` (`lib.rs:476-484`). An observer who collects the t shares addressed to the rogue participant recovers that participant's threshold secret share. Combined with the rogue participant's own share, an adversary controlling one validator plus passive network observation (the coordinator relays shares in `processor/src/key_gen.rs:404-413`) reduces the security of the resulting `ThresholdKeys` / FROST group key. This is cleartext transmission of sensitive key material triggered entirely by attacker-supplied bytes in the commitment message.

### Likelihood Explanation
Requires only that the attacker be a DKG participant who submits a commitment message — an unprivileged, public input path (`EncryptionKeyMessage::read` → `verify_r1`). Identity is a canonical Ristretto/Secp256k1 encoding, so it passes all parsing. One malicious registration poisons all n−1 share transmissions to that participant simultaneously, in every attempt using the same context.

### Recommendation
Reject the identity point (and any non-prime-order point) in `EncryptionKeyMessage::read` / `Decryption::register`, e.g., `if bool::from(enc_key.is_identity()) { Err(...) }`. A proof-of-possession for `enc_key` (Schnorr signature over it) would additionally prevent claiming a key whose discrete log is unknown, though the identity check alone closes this specific leak.

### Proof of Concept
1. Attacker runs `KeyGenMachine::generate_coefficients` but replaces the `enc_key` field in the emitted `EncryptionKeyMessage` with `<C::G as GroupEncoding>::Repr` of the identity (all-zero bytes for Ristretto), keeping a valid `Commitments` PoK.
2. Every honest participant `j` calls `verify_r1`, which registers `enc_keys[attacker] = identity` without error.
3. `generate_secret_shares` calls `encrypt(rng, attacker, identity, share_bytes)`: `ecdh = identity * k_j = identity`; ciphertext = `share_j ⊕ ChaCha20(H(context || identity_bytes) || "DKG IV v0.2\0")`.
4. Observer computes the same keystream from public `context` and the identity encoding, XORs the observed ciphertext, and recovers `SecretShare` for each `j`. fn ecdh<C: Ciphersuite>(private: &Zeroizing<C::F>, public: C::G) -> Zeroizing<C::G> {
  Zeroizing::new(public * private.deref())
}

// Each ecdh must be distinct. Reuse of an ecdh for multiple ciphers will cause the messages to be
// leaked.
fn cipher<C: Ciphersuite>(context: [u8; 32], ecdh: &Zeroizing<C::G>) -> ChaCha20 {
  // Ideally, we'd box this transcript with ZAlloc, yet that's only possible on nightly
  // TODO: https://github.com/serai-dex/serai/issues/151
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"encryption_key");

  let mut ecdh = ecdh.to_bytes();
  transcript.append_message(b"shared_key", ecdh.as_ref());
  ecdh.as_mut().zeroize();

  let zeroize = |buf: &mut [u8]| buf.zeroize();

  let mut key = Cc20Key::default();
  let mut challenge = transcript.challenge(b"key");
  key.copy_from_slice(&challenge[.. 32]);
  zeroize(challenge.as_mut());

  // Since the key is single-use, it doesn't matter what we use for the IV
  // The issue is key + IV reuse. If we never reuse the key, we can't have the opportunity to
  // reuse a nonce
  // Use a static IV in acknowledgement of this
  let mut iv = Cc20Iv::default();
  // The \0 is to satisfy the length requirement (12), not to be null terminated
  iv.copy_from_slice(b"DKG IV v0.2\0");

  // ChaCha20 has the same commentary as the transcript regarding ZAlloc
  // TODO: https://github.com/serai-dex/serai/issues/151
  let res = ChaCha20::new(&key, &iv);
  zeroize(key.as_mut());
  res
}

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
  }
