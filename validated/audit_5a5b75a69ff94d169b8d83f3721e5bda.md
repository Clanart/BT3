## Analog Found: Uncontrolled Recursion in Custody `MofN` Memo Parsing

### Title
Uncontrolled Recursion in `PuzzleWithRestrictions.from_memo()` Enables Wallet-Client Stack-Exhaustion DoS via Malicious On-Chain Custody Memo - (File: `chia/wallet/puzzles/custody/custody_architecture.py`)

### Summary
`PuzzleWithRestrictions.from_memo()` recursively reconstructs nested `MofN` custody structures from an untrusted, on-chain CLVM `Program` memo with no depth or branching-factor limit. This is the same bug class as GHSA-pq2g-wx69-c263 (json-smart uncontrolled recursion / CWE-674): a crafted deeply-nested input drives unbounded native-language recursion until the interpreter's call stack is exhausted, producing a denial of service in the code path that parses it.

### Finding Description
`PuzzleWithRestrictions.from_memo()` is explicitly documented as "the on-chain/exported synchronization contract," used by wallet clients to reconstruct an unknown custody puzzle discovered on-chain (memo attached to a coin) so it can later be filled in with known puzzle implementations: [1](#0-0) 

When the memo indicates `further_branching`, the method parses a `MofNHint` and then calls itself once per member:
```python
puzzle: MIPSComponent = MofN(
    m=m_of_n_hint.m, members=[PuzzleWithRestrictions.from_memo(memo) for memo in m_of_n_hint.member_memos]
)
```
Each `PuzzleWithRestrictions.from_memo(memo)` call can itself contain another `MofN` node whose members again trigger `from_memo()`, with no cap on nesting depth. Since the memo `Program` is arbitrary CLVM data (constructed by whoever creates the coin/spend that hints at this puzzle), an adversary can build a memo that nests `MofN` structures thousands of levels deep. There is no `LIMIT_JSON_DEPTH`-equivalent guard here, unlike the Rust CLVM parser paths and the Data Layer merkle-tree loader, which do have an analogous recursion cap enforced via `chia_rs.datalayer.RecursionDepthExceededError`: [2](#0-1) 

That data-layer test demonstrates the project is aware of, and defends against, exactly this recursion-depth attack class elsewhere — but the custody-memo parser in `custody_architecture.py` has no equivalent protection. Similarly, `Program.sha256_treehash()` was deliberately rewritten as an iterative algorithm "to avoid Python recursion limits on deeply nested CLVM," confirming this is a recognized robustness property that `from_memo()` violates: [3](#0-2) 

`PuzzleWithRestrictions.unknown_puzzles` and `fill_in_unknown_puzzles()` mirror the same unbounded recursive traversal over `MofN.members`: [4](#0-3) 

### Impact Explanation
Any wallet client implementing the CHIP-0043 custody architecture that calls `PuzzleWithRestrictions.from_memo()` to sync an unrecognized custody puzzle discovered on-chain (per the code's own stated purpose, "necessary functionality to sync an unknown inner puzzle from on chain") will recurse into a Python `RecursionError` when handed a maliciously deep memo, crashing or hanging that processing path. This is a spend-triggered transaction-processing halt on the wallet side: an attacker only needs to get such a coin/memo observed by the victim's wallet (e.g., as a coin sent to a custody arrangement, or surfaced through an offer/trade interaction referencing the puzzle), not gain any privileged access.

### Likelihood Explanation
Likelihood is moderate: the attacker needs the victim's wallet to actually call `from_memo()` on attacker-supplied data. This happens as part of syncing/backfilling custody puzzle information for coins that hint at a `PuzzleWithRestrictions` puzzle hash, which is the documented purpose of `memo()`/`from_memo()`. No signature or special permission is required to construct an arbitrarily deep memo `Program`; only CLVM encoding effort is needed, and building the nesting is trivial to script.

### Recommendation
Add an explicit depth/size limit to `PuzzleWithRestrictions.from_memo()` (and the related `unknown_puzzles`/`fill_in_unknown_puzzles()` traversals), returning a clear parse error once a bounded nesting depth is exceeded, mirroring the guard already used for Data Layer merkle-tree loading (`chia_rs.datalayer.RecursionDepthExceededError`) or converting the traversal to an explicit iterative stack-based algorithm, as was already done for `sha256_treehash()`.

### Proof of Concept
1. Build a `MofNHint` where a member's memo is itself a `PuzzleWithRestrictions` memo containing another `MofN` with `further_branching=True`, and nest this construction N times (N in the thousands), each further-branching layer wrapping the previous as its sole member.
2. Encode the resulting memo as a CLVM `Program` matching the format produced by `PuzzleWithRestrictions.memo()`.
3. Attach/hint this memo to a coin that a victim wallet running the custody architecture will observe and attempt to sync via `PuzzleWithRestrictions.from_memo(memo)`.
4. Observe the victim wallet process raise `RecursionError` (or crash/hang depending on interpreter/thread stack size) while reconstructing the nested `MofN` structure, halting further transaction/wallet-sync processing on that call path.

@pytest.mark.anyio
@pytest.mark.parametrize("depth", [1000, 100_000])
async def test_insert_into_data_store_from_file_line_graph_depth(
    data_store: DataStore,
    store_id: bytes32,
    tmp_path: Path,
    depth: int,
) -> None:
    # Binary "line graph":
    #   1 -> leaf_1, 2
    #   2 -> leaf_2, 3
    #   ...
    #   depth -> leaf_depth, leaf_end
    #
    # This stresses depth/stack handling while staying strictly binary.
    #
    # Node IDs:
    # - internal nodes: 1..depth
    # - per-level leaf nodes: (depth+1)..(2*depth)
    # - final leaf: (2*depth+1)
    internal_first = 1
    internal_last = depth
    leaf_base = internal_last + 1
    leaf_end = (2 * depth) + 1

    edges: list[tuple[int, int]] = []
    for i in range(internal_first, internal_last):
        # Order matters: first edge is left child, second edge is right child.
        edges.append((i, leaf_base + (i - internal_first)))  # unique leaf for this internal node
        edges.append((i, i + 1))  # next internal node

    # last internal points to its leaf and a final leaf
    edges.append((internal_last, leaf_base + (internal_last - internal_first)))
    edges.append((internal_last, leaf_end))

    filename = tmp_path / f"line_graph_depth_{depth}.dat"
    root_hash = create_graph_util(filename, edges)

    with pytest.raises(chia_rs.datalayer.RecursionDepthExceededError):
        await data_store.insert_into_data_store_from_file(store_id, root_hash, filename)
