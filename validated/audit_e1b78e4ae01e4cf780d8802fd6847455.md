### Title
Scanner credits unspendable dust outputs as received funds - ([File: networks/bitcoin/src/wallet/mod.rs])

### Summary
`Scanner::scan_transaction` credits every output paying to a registered script as a `ReceivedOutput`, with no minimum-value check. An unprivileged party can send dust/uneconomic outputs to a published multisig script pubkey, inflating the tracked balance with outputs that can never be profitably spent — value permanently stranded in the wallet's accounting, analogous to reward tokens claimed by the staking contract but credited to no position.

### Finding Description
`Scanner` maps `ScriptBuf -> Scalar` offsets and reports any matching `tx.output` as a spendable `ReceivedOutput`:

- `scan_transaction` pushes a `ReceivedOutput` for any output whose `script_pubkey` is registered, without inspecting `output.value` (`networks/bitcoin/src/wallet/mod.rs:199-214`). [1](#0-0) 
- `scan_block` extends this to every transaction in a block (including coinbase, documented separately) (`networks/bitcoin/src/wallet/mod.rs:221-227`). [2](#0-1) 
- The only dust logic in the wallet is `DUST = 546`, applied solely to *outgoing* payments and change in `SignableTransaction::new` (`networks/bitcoin/src/wallet/send.rs:32`, `networks/bitcoin/src/wallet/send.rs:165-169`, `networks/bitcoin/src/wallet/send.rs:228-235`). There is no filter on incoming inputs. [3](#0-2) 

Spending a Taproot input costs ~57 vbytes (the code's own model uses a fixed 64-byte signature witness, `send.rs:71-83`). At any reasonable fee rate, an input worth at or below the dust threshold costs more in fee than it contributes. `SignableTransaction::new` does not check per-input economics: it sums `input_sat` (`send.rs:175`) and silently lets leftover become fee. `multisig` will happily produce FROST signing machines for such inputs (`send.rs:273-285`), burning value — or the outputs sit forever, counted in the balance but unspendable.

### Impact Explanation
The multisig's reported/tracked balance includes value that cannot be recovered. An attacker can permanently inflate the wallet's books with dust outputs at minimal cost (each costs them ~546 sats or less), causing the wallet/accounting layer to treat unattributable funds as available — the same failure mode as the reference bug: tokens sit in the contract, claimed, but owned by no spendable position. If automation aggregates these inputs, each one is a net-negative spend, leaking funds to miners.

### Likelihood Explanation
The target script pubkeys are public on-chain data; anyone can send Bitcoin transactions to them. No collusion, no key material, and no protocol privilege is required — just standard dust outputs, which the scanner will report on the next scanned block.

### Recommendation
Apply a minimum-value filter in `Scanner::scan_transaction`/`scan_block` (e.g., reject outputs below `DUST`, or below an economics-derived spendability bound accounting for the ~57-vbyte input weight), and/or have `SignableTransaction::new` drop or reject inputs whose value is less than the marginal fee required to spend them.

### Proof of Concept
```rust
// bitcoin-serai wallet
let mut scanner = Scanner::new(group_key).unwrap();

// Attacker (any third party) crafts a tx paying a dust output to the
// multisig's P2TR script_pubkey and broadcasts it.
let dust_tx = Transaction {
    version: Version(2),
    lock_time: LockTime::ZERO,
    input: vec![/* attacker's input */],
    output: vec![
        TxOut {
            value: Amount::from_sat(294), // below DUST = 546
            script_pubkey: p2tr_script_buf(group_key).unwrap(),
        },
    ],
};

// The wallet reports the dust output as received funds.
let received = scanner.scan_transaction(&dust_tx);
assert_eq!(received.len(), 1);
assert_eq!(received[0].value(), 294);      // counted as balance
assert_eq!(received[0].offset(), Scalar::ZERO);

// Spending it costs ~57 vb * fee_per_vbyte > 294 sats at any
// fee_per_vbyte >= ~5, i.e. it can never be spent profitably.
// It remains permanently attributed to the wallet yet unspendable.
```

```rust
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
```
