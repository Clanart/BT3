### Title
PedPoP accepts identity ECDH encryption keys, making encrypted secret shares publicly decryptable - ([File: crypto/dkg/pedpop/src/encryption.rs](crypto/dkg/pedpop/src/encryption.rs))

### Summary

`EncryptionKeyMessage::read` accepts any canonical prime-group point as a participant’s registered encryption public key, including the identity point. Senders subsequently derive the ChaCha20 key from `participant_key * ephemeral_scalar`; when the registered key is identity, this shared secret is always identity. The resulting keystream is therefore determined entirely by the public DKG context, allowing anyone with the ciphertext to recover the encrypted secret-share bytes.

### Finding Description

`EncryptionKeyMessage::read` parses `enc_key` through `C::read_G(reader)` without checking `is_identity` or otherwise proving that the key is usable for ECDH. [1](#0-0) 

`Ciphersuite::read_G` verifies only that the supplied encoding decodes and re-encodes canonically; it does not reject the identity point. [2](#0-1) 

Registration stores the supplied `enc_key` without further validation. [3](#0-2) 

When encrypting a share to that participant, `encrypt` computes `ecdh(key, to)` and uses the result to initialize ChaCha20. [4](#0-3) 

The ECDH operation is direct scalar multiplication of the peer-supplied public point. [5](#0-4) 

Therefore, if `to` is the identity point, `to * key` is identity regardless of the random nonzero ephemeral scalar. `cipher` then transcripts the public context and the canonical encoding of identity to derive the ChaCha20 key, with a fixed IV. [6](#0-5) 

The commitments proof-of-knowledge does not bind or validate `enc_key`; `Commitments::read` caches only the commitment-point bytes for the PoK challenge, while `enc_key` is read separately afterward by `EncryptionKeyMessage::read`. [7](#0-6) [1](#0-0) 

### Impact Explanation

A DKG participant can publish an otherwise valid commitments message whose trailing encryption-key encoding is identity. Every honest participant will accept it, register it, and encrypt that participant’s secret shares with a shared secret equal to identity. [8](#0-7) [9](#0-8) 

The DKG context is public protocol data, and the identity encoding is public. Consequently, an observer who obtains the encrypted share messages can recreate the same ChaCha20 keystream and recover every scalar share sent to the malformed-key participant. Those plaintext shares are summed into that participant’s threshold secret share during `calculate_share`. [10](#0-9) 

This is secret-share/key-share recovery caused by accepting an invalid ECDH public key. It is directly analogous to improper validation of an ephemeral or peer-supplied public key causing ECDH to produce a predictable shared secret.

### Likelihood Explanation

The attack requires only a DKG participant to modify the public-key bytes in its broadcast `EncryptionKeyMessage`; no discrete-logarithm calculation, collusion, malformed curve point, noncanonical encoding, or implementation-dependent behavior is required. [1](#0-0) 

The malformed registration remains compatible with the protocol because the Schnorr PoK covers the Pedersen commitments, not possession or non-identity of `enc_key`. [11](#0-10) [12](#0-11) 

Exploitation requires access to ciphertexts sent to the malicious participant. The protocol expects these shares to be sent over authenticated channels, but encryption is specifically intended to protect their confidentiality on those channels. [13](#0-12) 

### Recommendation

Reject the identity point for both registered ECDH keys and per-message ECDH keys:

- In `EncryptionKeyMessage::read`, call `is_identity` after `C::read_G` and return an error if set.
- In `EncryptedMessage::read`, apply the same check to `key`.
- Prefer using a dedicated PedPoP `read_nonzero_G` helper so this requirement remains explicit even if the underlying `Ciphersuite::read_G` semantics change.
- Optionally add a proof of possession for the registered encryption key, though rejecting identity is the minimum required fix for this predictable-shared-secret issue.
- Add regression tests for each supported ciphersuite asserting that an `EncryptionKeyMessage` ending in `C::G::identity().to_bytes()` fails to parse.

### Proof of Concept

Conceptually, using any in-scope `Ciphersuite`:

```rust
use ciphersuite::group::GroupEncoding;

// Generate an otherwise valid registration message.
let (machine, mut registration_bytes) =
    key_gen_machine.generate_coefficients(&mut rng);

// Replace the trailing `enc_key` encoding with the canonical identity encoding.
let point_len = <C::G as GroupEncoding>::Repr::default().as_ref().len();
let identity = C::G::identity().to_bytes();
registration_bytes[
    registration_bytes.len() - point_len ..
].copy_from_slice(identity.as_ref());

// This currently succeeds because `EncryptionKeyMessage::read`
// only requires a canonical group element.
let parsed = EncryptionKeyMessage::<C, Commitments<C>>::read(
    &mut registration_bytes.as_slice(),
    params,
).unwrap();
```

After other participants register this key, each outgoing share uses:

```rust
let shared = identity * ephemeral_scalar; // always identity
let cipher_key = transcript(context, shared.to_bytes());
```

An observer can reproduce `cipher_key` because both `context` and the identity encoding are public, then XOR the ciphertext with that keystream to recover the serialized `SecretShare`. The relevant operations are `ecdh`, `cipher`, and `encrypt` in `crypto/dkg/pedpop/src/encryption.rs`. [14](#0-13) [15](#0-14)

impl<C: Ciphersuite> ReadWrite for Commitments<C> {
  fn read<R: Read>(reader: &mut R, params: ThresholdParams) -> io::Result<Self> {
    let mut commitments = Vec::with_capacity(params.t().into());
    let mut cached_msg = vec![];

    #[allow(non_snake_case)]
    let mut read_G = || -> io::Result<C::G> {
      let mut buf = <C::G as GroupEncoding>::Repr::default();
      reader.read_exact(buf.as_mut())?;
      let point = C::read_G(&mut buf.as_ref())?;
      cached_msg.extend(buf.as_ref());
      Ok(point)
    };

    for _ in 0 .. params.t() {
      commitments.push(read_G()?);
    }

    Ok(Commitments { commitments, cached_msg, sig: SchnorrSignature::read(reader)? })
