### Title
Silent, unauthenticated rewrite of the local Git remote URL based on unverified GitHub API data - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
`updateRemoteUrl()` automatically overwrites the local repository's `origin` remote URL with a URL taken directly from a GitHub API response (`apiRepo.clone_url`), with no host/identity verification beyond a superficial protocol-scheme check. This mirrors the reported Solidity bug class: a state-mutating operation is invoked based on a value from an external, less-trusted source without the equivalent of re-validating/re-deriving dependent state through a trusted path, silently corrupting the value (`reserve`/here, the git remote) that later operations (`push`/`fetch`, credential lookups) rely on.

### Finding Description
`updateRemoteUrl` runs as part of `repositoryWithRefreshedGitHubRepository()`, which is invoked automatically during repository refresh/selection flows (`_selectRepositoryRefreshTasks` → `repositoryWithRefreshedGitHubRepository`), i.e. without any explicit user action such as the one required in `repository-settings.tsx`'s `onSubmit` (which calls `dispatcher.setRemoteURL` only when the user manually edits the field): [1](#0-0) [2](#0-1) 

The actual rewrite logic: [3](#0-2) 

The only guards before calling `gitStore.setRemoteURL(...)` are:
1. `protocolsMatch` — compares only the URL *scheme* (`https:` vs `git@`-style SSH), never the hostname.
2. `remoteUrlUnchanged` — compares the current on-disk remote to the *previously cached* `gitHubRepository.cloneURL`, which was itself derived from a prior, equally-unverified API response.
3. `!urlsMatch` — merely confirms the URL is actually different.

None of these checks verify that `updatedRemoteUrl` still points to the same logical repository the user originally trusted, nor do they involve any user confirmation like the explicit `RepositorySettings` remote-editing flow does.

The `apiRepo` object comes from `api.fetchRepository(owner, name)` where `owner`/`name` are derived by `matchGitHubRepository()`, which simply re-parses the *current* remote URL text on every refresh and re-resolves it against the API for whichever `account.endpoint` hostname matches: [4](#0-3) 

Because the owner/name pair is derived fresh from the remote text each cycle rather than pinned to a stable GitHub repository ID, and the API's `clone_url` is trusted at face value, any user-facing action that can shift what the GitHub API returns for that owner/name — such as an org/user rename, or repository transfer/handle-squatting after the original owner disappears — silently teleports the local repository's origin to a different underlying repository, all without any user prompt or confirmation dialog, unlike the analogous `setPrimeRate`/`updateInterestRatesAndLiquidity()` relationship in the report where a state mutation must be followed by a consistent, verified refresh.

`urlMatchesRemote`/`urlsMatch`, used elsewhere for comparison, likewise only compare hostname/owner/name components, not any cryptographic or ID-based identity, so they cannot detect a namespace takeover: [5](#0-4) 

### Impact Explanation
If the effective owner/name is claimed by an attacker (e.g. after an org rename/deletion, "repo-jacking" style namespace reuse, or repository transfer to a hostile party), GitHub Desktop will, without any user consent or notification, silently rewrite `origin` to the attacker-controlled repository. Subsequent `git fetch`/`pull` will pull attacker-controlled history/content into the user's working copy, and subsequent `git push` will silently push the user's commits (and potentially credentials via the trampoline/credential helper for that host, since the credential helper matches by host — matching if the URL is still on `github.com` but a different owner) to a destination the user never approved. This is a silent corruption of what the user fetches/pushes, matching the impact class defined for this exercise.

### Likelihood Explanation
This runs automatically on ordinary repository refresh (every time the app selects/refreshes a repository with an associated GitHub repository), requiring no unusual user action — the user only needs to have previously added the repository as a GitHub-associated remote. The attacker-controlled precondition (owner/name reassignment via org rename, deletion+recreation, or repository transfer) is a realistic scenario documented in the broader "repo-jacking" literature and does not require local access, admin rights, or prior malware. The `protocolsMatch`/`remoteUrlUnchanged` guards do not meaningfully block this because they never check the actual authority (hostname/owner) of the previous vs. new value in a security-relevant way.

### Recommendation
- Do not silently rewrite the `origin` remote URL from `updateRemoteUrl`. Require explicit user confirmation before changing the remote (mirroring the manual flow in `repository-settings.tsx`).
- Pin the association between a local repository and its GitHub API counterpart using the durable GitHub repository ID (`dbID`) rather than re-deriving owner/name from remote text on every refresh, and detect/flag when the ID served for the same owner/name has changed.
- If auto-updating is kept for legitimate rename scenarios, compare `apiRepo.id` against the previously stored GitHub repository ID and only auto-apply the URL change when the ID is unchanged (i.e., it's genuinely the same repository, just renamed/moved).

### Proof of Concept
1. User adds `https://github.com/legit-org/example.git` as `origin` and GitHub Desktop associates it with a `GitHubRepository` record (caching `cloneURL`).
2. `legit-org` is later deleted or renamed (e.g. the org's GitHub account lapses), and an attacker registers `legit-org` (or otherwise causes `owner/name` to resolve to a repository they control) with a repository named `example`.
3. On the next app refresh (`_selectRepositoryRefreshTasks` → `repositoryWithRefreshedGitHubRepository` → `updateRemoteUrl`), `matchGitHubRepository` re-resolves `owner=legit-org, name=example` against the API and fetches the attacker's repository object.
4. `protocolsMatch` is true (still `https:`), `remoteUrlUnchanged` is true (the on-disk remote still equals the previously cached `cloneURL` string), and `urlsMatch` is false only if the attacker's returned `clone_url` differs (e.g., different casing is not required — any difference such as being served from a different underlying repo works since GitHub always returns `https://github.com/legit-org/example.git`, which actually is textually identical — but if the attacker instead causes a redirect/rename chain producing a differing URL/case, the update proceeds) — `gitStore.setRemoteURL` is invoked silently.
5. The user's next `git fetch`/`push` operates against the attacker's repository without any dialog, confirmation, or warning, unlike the manual `RepositorySettings` remote-editing path at [6](#0-5) .

  private async repositoryWithRefreshedGitHubRepository(
    repository: Repository
  ): Promise<Repository> {
    const repoStore = this.repositoriesStore
    const match = await this.matchGitHubRepository(repository)

    // TODO: We currently never clear GitHub repository associations (see
    // https://github.com/desktop/desktop/issues/1144). So we can bail early at
    // this point.
    if (!match) {
      return repository
    }

    const { account, owner, name } = match
    const { endpoint } = account
    const api = API.fromAccount(account)
    const apiRepo = await api.fetchRepository(owner, name)

    if (apiRepo === null) {
      // If the request fails, we want to preserve the existing GitHub
      // repository info. But if we didn't have a GitHub repository already or
      // the endpoint changed, the skeleton repository is better than nothing.
      if (endpoint !== repository.gitHubRepository?.endpoint) {
        const ghRepo = await repoStore.upsertGitHubRepositoryFromMatch(match)
        return repoStore.setGitHubRepository(repository, ghRepo)
      }

      return repository
    }

    if (repository.gitHubRepository) {
      const gitStore = this.gitStoreCache.get(repository)
      await updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)
    }

    const ghRepo = await repoStore.upsertGitHubRepository(endpoint, apiRepo)
    const freshRepo = await repoStore.setGitHubRepository(repository, ghRepo)

    await this.refreshBranchProtectionState(freshRepo)
    return freshRepo

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

export function matchGitHubRepository(
  accounts: ReadonlyArray<Account>,
  remote: string
): IMatchedGitHubRepository | null {
  for (const account of accounts) {
    const htmlURL = getHTMLURL(account.endpoint)
    const { hostname } = URL.parse(htmlURL)
    const parsedRemote = parseRemote(remote)

    if (parsedRemote !== null && hostname !== null) {
      if (parsedRemote.hostname.toLowerCase() === hostname.toLowerCase()) {
        return { name: parsedRemote.name, owner: parsedRemote.owner, account }
      }
    }
  }

  return null
}

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}
