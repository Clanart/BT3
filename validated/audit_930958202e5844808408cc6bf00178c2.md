### Title
`get_outputs` applies the last transaction's origin/data to every output collected so far in the block - (File: processor/src/networks/bitcoin.rs)

### Summary
`Bitcoin::get_outputs` accumulates matching outputs from all transactions in a block into a single `outputs` Vec, then — still inside the per-transaction loop — assigns `presumed_origin` and `data` computed from the *current* transaction to **every** output accumulated so far, not just the outputs produced by that transaction. Worse, the `if outputs.is_empty() { continue }` guard checks the cumulative vector, so any transaction after the first matching one rewrites the metadata of all previously scanned outputs — even transactions that paid nothing to Serai.

### Finding Description [1](#0-0) 

```rust
async fn get_outputs(&self, block: &Self::Block, key: ProjectivePoint) -> Vec<Output> {
    let (scanner, _, kinds) = scanner(key);
    let mut outputs = vec![];
    for tx in &block.txdata[1 ..] {
      for output in scanner.scan_transaction(tx) { ...; outputs.push(output); }
      if outputs.is_empty() { continue; }        // cumulative, not per-tx
      let presumed_origin = { let input = &tx.input[0]; ... };  // this tx's input
      let data = Self::extract_serai_data(tx);                  // this tx's data
      for output in &mut outputs {               // ALL outputs so far
        if output.kind == OutputType::External {
          output.data.clone_from(&data);
        }
        output.presumed_origin.clone_from(&presumed_origin);
      }
    }
    outputs
}
```

The kernel bug class is iteration over a collection where the reader assumes each visited element belongs to the consistent snapshot being processed. Here, the inner `for output in &mut outputs` iterates the *cumulative* collection while holding per-transaction context (`tx`), silently stamping one transaction's input origin and embedded `InInstruction` data onto outputs belonging to other transactions.

Two distinct misbehaviors:

1. **Cross-transaction metadata overwrite.** If tx1 (block position k) contains a deposit to a Serai output and tx2 (position k+1) is *any* transaction, the tx2 iteration still runs the metadata block because `outputs` is non-empty. `tx2.input[0]`'s prevout script becomes `presumed_origin` and `Self::extract_serai_data(tx2)` becomes `data` for tx1's output.
2. **Wrong-tx data even among matching txs.** If two deposits occur in one block, the later tx's data overwrites the earlier output's `data` field.

`data` is not cosmetic: `Output::data()` feeds `instruction_from_output` / the scheduler's handling of externally received funds (see `processor/src/multisigs/mod.rs` lines 824-868, where `OutputType::External` outputs are retained and turned into `Plan`s using their data), and `presumed_origin` is used for refunds.

### Impact Explanation
An unprivileged Bitcoin user can place a transaction in the same block after a victim's deposit, overwriting the victim output's `data` (the `InInstruction`, e.g., refund address / memo) and `presumed_origin` with attacker-controlled values. Consequences include deposits being credited against the wrong instruction, refunds directed to an attacker-chosen origin, or deposit data being erased (attacker tx carries no Serai data → `data` becomes empty). This is funds being reported with corrupted attribution/metadata — the scanned output is real and spendable by Serai, but it is processed under the wrong instruction context.

### Likelihood Explanation
Requires only that an attacker's transaction appear in the same Bitcoin block after a Serai-bound transaction — trivially achievable by watching the mempool (Serai deposit addresses are predictable P2TR scripts derived from the known group key and fixed offsets). No validator collusion, no threshold compromise, no malformed encodings needed. Any tx with at least one input suffices; the attacker doesn't even need to send funds to Serai.

### Recommendation
Track the per-transaction slice: record `let start = outputs.len();` before scanning each `tx`, `continue` when no *new* outputs were added, and apply `presumed_origin`/`data` only to `outputs[start ..]`. Also consider skipping metadata assignment entirely for transactions whose `tx.input` is empty or whose scan produced nothing.

### Proof of Concept
Conceptual: a regtest block containing `[coinbase, tx_victim, tx_eve]`, where `tx_victim` pays `p2tr_script_buf(key + GENERATOR*ZERO)` (External) and embeds the victim's `InInstruction`, and `tx_eve` is any attacker transaction (e.g., paying themselves). `get_outputs` scans `tx_victim` → pushes one `Output`; on the `tx_eve` iteration `outputs` is non-empty, so `tx_eve.input[0]` and `extract_serai_data(tx_eve)` overwrite the victim output's `presumed_origin`/`data`. The resulting `Output` is then retained as `OutputType::External` and scheduled under the attacker's instruction data rather than the victim's.

```rust
  async fn get_outputs(&self, block: &Self::Block, key: ProjectivePoint) -> Vec<Output> {
    let (scanner, _, kinds) = scanner(key);

    let mut outputs = vec![];
    // Skip the coinbase transaction which is burdened by maturity
    for tx in &block.txdata[1 ..] {
      for output in scanner.scan_transaction(tx) {
        let offset_repr = output.offset().to_repr();
        let offset_repr_ref: &[u8] = offset_repr.as_ref();
        let kind = kinds[offset_repr_ref];

        let output = Output { kind, presumed_origin: None, output, data: vec![] };
        assert_eq!(output.tx_id(), tx.id());
        outputs.push(output);
      }

      if outputs.is_empty() {
        continue;
      }

      // populate the outputs with the origin and data
      let presumed_origin = {
        // This may identify the P2WSH output *embedding the InInstruction* as the origin, which
        // would be a bit trickier to spend that a traditional output...
        // There's no risk of the InInstruction going missing as it'd already be on-chain though
        // We *could* parse out the script *without the InInstruction prefix* and declare that the
        // origin
        // TODO
        let spent_output = {
          let input = &tx.input[0];
          let mut spent_tx = input.previous_output.txid.as_raw_hash().to_byte_array();
          spent_tx.reverse();
          let mut tx;
          while {
            tx = self.rpc.get_transaction(&spent_tx).await;
            tx.is_err()
          } {
            log::error!("couldn't get transaction from bitcoin node: {tx:?}");
            sleep(Duration::from_secs(5)).await;
          }
          tx.unwrap().output.swap_remove(usize::try_from(input.previous_output.vout).unwrap())
        };
        Address::new(spent_output.script_pubkey)
      };
      let data = Self::extract_serai_data(tx);
      for output in &mut outputs {
        if output.kind == OutputType::External {
          output.data.clone_from(&data);
        }
        output.presumed_origin.clone_from(&presumed_origin);
      }
    }

    outputs
  }
```
