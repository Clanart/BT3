### Title
`OpenWithDefaultProgramLabel` in Copilot conflicts dialog skips the `isSafeFileExtension` guard, allowing execution of attacker-named files - (File: `app/src/ui/multi-commit-operation/dialog/copilot-conflicts-dialog.tsx`)

### Summary
GitHub Desktop enforces a Windows-specific allowlist (`isSafeFileExtension`) that disables the "Open with Default Program" action for `.exe`, `.bat`, `.cmd`, and `.sh` files everywhere it is wired up in the Changes list, commit history, and PR file views. The Copilot merge-conflicts overflow menu implements the same "Open with Default Program" action but omits this check entirely, letting a conflicted file with a dangerous extension be launched via `shell.openExternal(file://...)` regardless of its extension.

### Finding Description
`isSafeFileExtension` is defined once and is meant to gate every "Open with Default Program" menu item on Windows: [1](#0-0) 

It is correctly applied at three call sites, each disabling the menu item when the extension is unsafe: [2](#0-1) [3](#0-2) [4](#0-3) 

However, the Copilot conflict-resolution overflow menu wires the identical `OpenWithDefaultProgramLabel` action directly to `openFile(absolutePath, dispatcher)` with no `isSafeFileExtension` check and no `enabled` gate at all: [5](#0-4) 

`openFile` itself performs no extension validation — it simply hands the path to `shell.openExternal` as a `file://` URI, which on Windows/macOS will invoke the OS default handler (i.e., execute `.exe`/`.bat`/`.cmd` files): [6](#0-5) 

`file.path` for entries shown in this dialog comes straight from the merge conflict state (attacker-controlled file names/paths from a cloned/fetched repository that produces a merge conflict), joined with the repository root: [7](#0-6) 

This is the same class of bug as the reported `RCNftHubL2.safeTransferFrom` finding: a safety check that the codebase's own contract requires (there, the `IERC721Receiver` check on `safeTransferFrom`; here, the `isSafeFileExtension` check on "Open with Default Program") is implemented in some code paths but silently dropped in another implementation of the same operation.

### Impact Explanation
An attacker who controls a cloned/fetched repository can craft a file (e.g. `payload.exe`, `run.bat`, `run.cmd`) that produces a merge/rebase conflict when the victim performs a Copilot-assisted conflict resolution. If the victim opens the overflow menu for that file and selects "Open with Default Program," GitHub Desktop invokes the OS default handler on the attacker-named executable/script, resulting in code execution on the victim's machine — bypassing the exact protection (`RestrictedFileExtensions = ['.cmd', '.exe', '.bat', '.sh']`) the rest of the app relies on for this action.

### Likelihood Explanation
Requires the user to be resolving a merge conflict via the Copilot conflicts dialog and to explicitly click "Open with Default Program" for the attacker's file — a single, plausible user action within a normal Desktop workflow (unlike the excluded self-XSS/social-engineering/local-access scenarios), and it needs no elevated privileges, no leaked credentials, and no pre-existing malware.

### Recommendation
Gate the `OpenWithDefaultProgramLabel` item in `copilot-conflicts-dialog.tsx`'s `onOverflowMenuClick` with the same `isSafeFileExtension(Path.extname(path))` check (and `enabled` flag) used in `filter-changes-list.tsx`, `selected-commits.tsx`, and `pull-request-files-changed.tsx`, so all "Open with Default Program" entry points enforce the identical extension allowlist consistently.

### Proof of Concept
1. Attacker prepares a repository/branch that, when merged/rebased against the victim's branch, produces a conflicting file named `update.exe` (or `.bat`/`.cmd`).
2. Victim fetches/pulls and triggers a Copilot-assisted conflict resolution; the conflicts dialog lists `update.exe`.
3. Victim opens the file's overflow menu and clicks "Open with Default Program" (`app/src/ui/multi-commit-operation/dialog/copilot-conflicts-dialog.tsx:225-229`).
4. `openFile()` (`app/src/ui/lib/open-file.ts:4-17`) calls `shell.openExternal('file://.../update.exe')` with no extension check, causing Windows to execute the attacker-controlled binary — unlike the identical action in the Changes list or commit history views, where `isSafeFileExtension` would have disabled the menu item.

import { shell } from '../../lib/app-shell'
import { Dispatcher } from '../dispatcher'

export async function openFile(
  fullPath: string,
  dispatcher: Dispatcher
): Promise<void> {
  const result = await shell.openExternal(`file://${fullPath}`)

  if (!result) {
    const error = {
      name: 'no-external-program',
      message: `Unable to open file ${fullPath} in an external program. Please check you have a program associated with this file extension`,
    }
    await dispatcher.postError(error)
  }
}
