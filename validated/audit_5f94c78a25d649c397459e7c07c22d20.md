### Title
Missing PoP verification before blame release in `KeyMachine::calculate_share` leaks the ECDH shared key, enabling secret-share recovery - (File: crypto/dkg/pedpop/src/lib.rs)

### Summary
The KubeView bug class is "a reachable endpoint returns authentication secrets without requiring authentication." The analog in Serai is `KeyMachine::calculate_share` in PedPoP: it returns a blame proof (which reveals the ECDH shared key `b·msg.key`) on the early `from_repr` error path **before the queued batch — which contains the proof-of-possession signature — is ever verified**. An unauthenticated sender can replay a victim's per-message encryption key `X` (without knowing its discrete log, i.e., without a valid PoP) inside a crafted `EncryptedMessage`, and whenever the decrypted bytes fail scalar decoding the victim emits the ECDH key `bX`, which decrypts the honest party's original message and recovers a secret share.

### Finding Description
`EncryptedMessage` carries a Schnorr PoP specifically to stop exactly this attack. The code comment states the threat model explicitly: if Eve could reuse Alice's key `X` toward Bob, Bob's blame would reveal `bX`, decrypting Alice's real message to Bob [1](#0-0) .

However, in `calculate_share`, decryption happens immediately, the PoP is only *queued* into a `BatchVerifier` (`batch_id` = `BatchId::Decryption(l)`), and then `C::F::from_repr(share_bytes.0)` is evaluated inline. If the decrypted bytes are a non-canonical scalar, the function returns `Err(PedPoPError::InvalidShare { blame: Some(blame) })` early — the `blame` is an `EncryptionKeyProof` containing `key = ecdh(self.enc_key, msg.key)` plus a DLEq proving correctness [2](#0-1) . `batch.verify_with_vartime_blame()` is only reached afterward, so on this path the PoP is never checked [3](#0-2) .

`Encryption::decrypt` computes `key = ecdh::<C>(&self.enc_key, msg.key)` — i.e., the shared secret between the victim's registered encryption key and the attacker-supplied `msg.key` — and packages it into the `EncryptionKeyProof` returned to the caller as blame [4](#0-3) . `decrypt_with_proof` confirms that anyone holding `proof.key` can run `cipher` and decrypt the message [5](#0-4) .

### Impact Explanation
**Key share material recovery.** For every honest `EncryptedMessage` Alice sent to Bob under per-message key `X = xG`, an attacker Eve can force Bob to publish the ECDH secret `bX` (as a blame proof inside `ProcessorMessage::InvalidShare`). With `bX`, Eve recomputes `cipher(context, bX)` and decrypts Alice's original ciphertext, recovering Alice's secret share contribution to Bob. Repeating this against each honest sender whose messages Eve observed lets Eve reconstruct Bob's full threshold secret share `s_B = Σ shares`, i.e., the equivalent of obtaining credential files usable for authentication/signing as in the KubeView report. The same leak applies to any blame-evaluating third party via `AdditionalBlameMachine`/`decrypt_with_proof`.

### Likelihood Explanation
Eve only needs to observe one honest `EncryptedMessage` on the wire (the wire format itself is unauthenticated, as the code notes the channel merely is "assumed-to-exist") and submit `EncryptedMessage { key: X, pop: <garbage>, msg: <random bytes> }` to Bob's `calculate_share`. The garbage `msg` decrypts under `bX` to effectively uniform bytes; for a ~256-bit field with a ~252-bit order (e.g., ed25519), a random 32-byte string is a non-canonical `Repr` with high probability (~7/8), triggering the early `from_repr` error and the blame release before PoP verification. If it happens to decode, the queued batch is verified and the PoP failure yields `blame: None`, so Eve simply retries with fresh `msg` bytes — each attempt is independent and cheap. No malicious-validator assumptions are required; Eve is an ordinary protocol participant (or anyone who can feed `shares` to `calculate_share` via the processor's `Shares` message path, which passes attacker bytes straight to `EncryptedMessage::read` then `calculate_share`).

### Recommendation
Verify the PoP *before* releasing the blame proof on the scalar-decoding path. Concretely: in `calculate_share`, do not return `blame: Some(...)` from the `from_repr` error arm until the batch (or at least that message's PoP statement) has been verified. Options: (a) defer the `from_repr` check until after `batch.verify_with_vartime_blame()`, storing a marker so a non-canonical share still blames `l` with the proof only once the PoP has passed; (b) verify the PoP individually for a message whose share fails to deserialize before attaching `blame`. This restores the invariant documented in `encryption.rs` that the PoP prevents replaying someone else's `msg.key` to extract ECDH keys.

### Proof of Concept
Setup: Alice (participant 1) and Eve (participant 2) run PedPoP toward Bob (participant 3) with `t = 2, n = 3`. Eve observes Alice's `EncryptedMessage<C, SecretShare>` `M_A` on the wire, which contains `key = X` (Alice's random per-message key, `x` unknown to Eve).

1. Eve runs her legitimate `SecretShareMachine`, obtains `enc_keys` for all parties, then for Bob constructs:
   - `msg.key = X` (copied verbatim from `M_A`),
   - `msg.pop = SchnorrSignature { R: <random>, s: <random> }` (no valid PoP — Eve doesn't know `x`),
   - `msg.msg = SecretShare([0x42; 32])` (arbitrary ciphertext bytes).
2. Bob's `calculate_share` calls `encryption.decrypt`, queuing the (invalid) PoP into `batch` under `BatchId::Decryption(2)`, and computes `key = b·X` — the exact ECDH secret protecting `M_A` — wrapping it into `EncryptionKeyProof { key, dleq }`.
3. `cipher(context, bX).apply_keystream([0x42;32])` produces ~uniform bytes. With probability ~7/8 over ed25519, `C::F::from_repr` returns `None`, and Bob hits the early return at `lib.rs:480-482`, emitting `InvalidShare { participant: 2, blame: Some(proof) }` — **without ever calling `batch.verify_with_vartime_blame()`**, so the invalid PoP is never detected.
4. The processor propagates this blame (`ProcessorMessage::InvalidShare { blame: Some(blame.serialize()) }`, `processor/src/key_gen.rs:419-425`). Anyone holding `proof.key = bX` runs `cipher(context, bX)` over `M_A.msg` to recover Alice's plaintext secret share for Bob. Repeating for each sender's observed message reconstructs Bob's entire secret share.

The fix-verification: after patching so the PoP is checked before blame release, step 3 must yield `blame: None` (or blame the sender) without disclosing `bX`.
