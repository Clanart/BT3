### Title
Failed post-insertion validation in `AddBid()` permanently occupies a bid slot without rollback, enabling `ErrBidPoolFull`/`ErrBidSenderExists` DoS by unprivileged bidders - ([File: kaiax/auction/impl/bid_pool.go])

### Summary
`BidPool.AddBid()` calls `insertBid()`, which commits the bid into `bidMap`, `bidTargetMap`, and `bidWinnerMap` before the function has fully validated the bid. Immediately afterward, `AddBid()` calls `getBidTxGasLimit(bid)`, and if that call errors, `AddBid()` returns the error directly without removing the bid it just inserted. The bid remains permanently resident in all three maps, consuming a slot in the bounded `bidMap` (`maxBidPoolSize`) and reserving the sender's single "winner" slot for that block (`bidWinnerMap[blockNumber][sender]`), exactly mirroring the kernel bug class: a resource is allocated/committed, an error occurs on a subsequent step, and the resource is never released on that error path.

### Finding Description
In `AddBid()`: [1](#0-0) 

`insertBid()` unconditionally commits the bid into the pool's tracking structures on success: [2](#0-1) 

After `insertBid()` succeeds, `AddBid()` calls `getBidTxGasLimit(bid)`, which can fail if `system.EncodeAuctionCallData` or `types.IntrinsicGas`/`FloorDataGas` return an error (e.g., unsupported auction entry point version, or gas computation error): [3](#0-2) 

When `getBidTxGasLimit` returns an error, `AddBid()` returns immediately with that error and never calls anything to undo `insertBid()`'s side effects: [4](#0-3) 

There is no corresponding "remove/rollback" call in `AddBid()`'s failure branch. The only paths that clear entries from `bidMap`/`bidTargetMap`/`bidWinnerMap` are `removeOldBids()` (triggered on block insertion, only removes bids at or below the finalized block number) and `clearBidPool()` (triggered on stop or auctioneer config change): [5](#0-4) [6](#0-5) 

Because the leaked bid's `BlockNumber` is validated to be in `[currentBlockNumber+1, currentBlockNumber+allowFutureBlock]` before insertion, and `allowFutureBlock` is small, this specific leaked bid will eventually be cleaned by `removeOldBids()` once that block number is reached/passed. However, within that window (until the block is finalized/pruned), the leaked bid:
1. Occupies a slot in the size-bounded `bidMap` (bounded by `maxBidPoolSize`), pushing the pool closer to `ErrBidPoolFull` and rejecting other legitimate bids for any target in the affected block: [7](#0-6) 
2. Occupies the *sender's* single per-block winner slot via `bidWinnerMap[blockNumber][sender]`, so if the same sender resubmits a corrected/different bid for a different target in the same block, it is rejected with `ErrBidSenderExists` because `senderHasDifferentWinner()` sees the stale winner entry still present: [8](#0-7) 

The `AddBid()` path is directly reachable by any unprivileged auction bidder via the public RPC `SubmitBid`: [9](#0-8) 

An attacker-controlled trigger for `getBidTxGasLimit` failure exists via `system.EncodeAuctionCallData(bid, bp.auctionEntryPointVersion)` — any bid data/version combination that this function rejects, or a transient/interface error from encoding, will cause a "commit-then-fail-without-rollback" leak for every such bid submitted.

### Impact Explanation
This causes state divergence between the bid pool's intended invariants and its actual contents — permanently-stuck (until block-expiry pruning) "ghost" bid entries occupy scarce bounded resources (`maxBidPoolSize` slots and per-sender per-block winner slots). A malicious or buggy searcher can repeatedly submit bids engineered to succeed `validateBid`/`insertBid` but fail `getBidTxGasLimit`, filling the bid pool and blocking legitimate bidders from participating in the auction for those blocks (denial of auction participation / bid-pool exhaustion), and can also self-grief or grief another sender's ability to correct/replace a bid in the same block due to the stale `bidWinnerMap` entry. This directly affects the auction/gasless settlement module reachable by any public-RPC auction bidder, satisfying "state divergence" and denial-of-service against a core value-flow module (auction settlement), consistent with a Medium/High-severity DoS analog of the original kernel resource-leak class.

### Likelihood Explanation
High likelihood of triggerability: `SubmitBid` is a public, unauthenticated RPC entry point reachable by any auction bidder; no special privilege is required. The attacker only needs to craft a bid that passes `validateBid` (signature/size/gas-limit/block-range checks) but is rejected by `getBidTxGasLimit`'s downstream call to `system.EncodeAuctionCallData` or gas computation — a condition well within the control of the bid's own fields.

### Recommendation
In `AddBid()`, roll back the `insertBid()` side effects (remove the bid from `bidMap`, `bidTargetMap`, and `bidWinnerMap`) if `getBidTxGasLimit()` fails, mirroring the pattern used in the kernel fix (free the resource before returning the error). Alternatively, reorder the logic to compute `getBidTxGasLimit()` and call `bid.SetGasLimit()` before calling `insertBid()`, so that `insertBid()` only commits fully-validated, fully-prepared bids.

### Proof of Concept
1. A searcher calls the public `auction_submitBid` RPC (`AuctionAPI.SubmitBid`) with a bid whose fields pass `validateBid()` (valid signature, size, gas limit, block range) but that will make `getBidTxGasLimit()` fail — e.g., a bid whose fields cause `system.EncodeAuctionCallData(bid, auctionEntryPointVersion)` to return an error (such as an unsupported/mismatched auction entry point version state at call time).
2. `AddBid()` calls `insertBid(bid)`, which succeeds and commits the bid into `bidMap`, `bidTargetMap[blockNumber][targetTxHash]`, and `bidWinnerMap[blockNumber][sender]`.
3. `AddBid()` then calls `getBidTxGasLimit(bid)`, which returns an error; `AddBid()` returns this error to the RPC caller without undoing step 2.
4. The bid remains in `bidMap`/`bidTargetMap`/`bidWinnerMap` for `blockNumber` until `removeOldBids()` eventually prunes it once the chain progresses past that block.
5. Repeating steps 1–4 for many distinct senders/targets within the `allowFutureBlock` window fills `bidMap` up to `maxBidPoolSize`, causing subsequent legitimate bids to be rejected with `auction.ErrBidPoolFull` in `insertBid()`; alternatively, the same sender resubmitting a corrected bid for a different target in the same block is rejected with `auction.ErrBidSenderExists` due to the stale `bidWinnerMap` entry.

// removeOldBids removes the old bids for the given block number.
func (bp *BidPool) removeOldBids(num uint64, txHashMap map[common.Hash]struct{}) {
	bp.bidMu.Lock()
	defer bp.bidMu.Unlock()

	// Remove the old bids.
	for bn := range bp.bidWinnerMap {
		if bn > num {
			continue
		}

		for _, bh := range bp.bidWinnerMap[bn] {
			delete(bp.bidMap, bh)
		}
		delete(bp.bidTargetMap, bn)
		delete(bp.bidWinnerMap, bn)
	}

	// Remove the bid which target tx is in the txHashMap.
	toBlock := num + allowFutureBlock
	for blockNum := num + 1; blockNum <= toBlock; blockNum++ {
		targetMap := bp.bidTargetMap[blockNum]
		if targetMap == nil {
			continue
		}

		// Collect bids to remove first to avoid modifying map during iteration
		var bidsToRemove []*auction.Bid
		for _, bid := range targetMap {
			if _, ok := txHashMap[bid.TargetTxHash]; ok {
				bidsToRemove = append(bidsToRemove, bid)
			}
		}

		// Remove collected bids
		for _, bid := range bidsToRemove {
			delete(targetMap, bid.TargetTxHash)
			delete(bp.bidWinnerMap[blockNum], bid.Sender)
			delete(bp.bidMap, bid.Hash())
		}
	}

	numBidsGauge.Update(int64(len(bp.bidMap)))
}

func (bp *BidPool) AddBid(bid *auction.Bid) (common.Hash, error) {
	if atomic.LoadUint32(&bp.running) == 0 {
		return common.Hash{}, auction.ErrAuctionPaused
	}

	if err := bp.validateBid(bid); err != nil {
		return common.Hash{}, err
	}

	if err := bp.insertBid(bid); err != nil {
		return common.Hash{}, err
	}

	gasLimit, err := bp.getBidTxGasLimit(bid)
	if err != nil {
		return common.Hash{}, err
	}
	bid.SetGasLimit(gasLimit)

	bp.newBidCh <- bid

	return bid.Hash(), nil
}

func (bp *BidPool) insertBid(bid *auction.Bid) error {
	bp.bidMu.Lock()
	defer bp.bidMu.Unlock()

	var (
		blockNumber  = bid.BlockNumber
		targetTxHash = bid.TargetTxHash
		sender       = bid.Sender
	)

	// Re-check bidWinnerMap here — two concurrent bids can pass validateBid together.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		return auction.ErrBidAlreadyExists
	}
	if bp.senderHasDifferentWinner(bid) {
		return auction.ErrBidSenderExists
	}

	// If same block number, same target tx hash exists, replace it if it's better
	if existingBid, ok := bp.bidTargetMap[blockNumber][targetTxHash]; ok {
		// FCFS if the bid is the same.
		if existingBid.Bid.Cmp(bid.Bid) >= 0 {
			return auction.ErrLowBid
		}

		logger.Trace("Replace bid", "old", existingBid.Hash(), "new", bid.Hash())
		delete(bp.bidMap, existingBid.Hash())
		delete(bp.bidWinnerMap[blockNumber], existingBid.Sender)
	} else {
		if int64(len(bp.bidMap)) >= bp.maxBidPoolSize {
			logger.Info("Bid pool is full", "maxBidPoolSize", bp.maxBidPoolSize, "bid", bid.Hash())
			return auction.ErrBidPoolFull
		}
	}

	hash := bid.Hash()

	bp.initializeBidMap(blockNumber)

	bp.bidMap[hash] = bid
	bp.bidTargetMap[blockNumber][targetTxHash] = bid
	bp.bidWinnerMap[blockNumber][sender] = hash

	numBidsGauge.Update(int64(len(bp.bidMap)))

	logger.Trace("Add bid", "bid", hash)

	return nil
}

// senderHasDifferentWinner reports whether a different bid from the same sender
// already exists in the winner list for this block. Caller must hold bidMu.
func (bp *BidPool) senderHasDifferentWinner(bid *auction.Bid) bool {
	hash, ok := bp.bidWinnerMap[bid.BlockNumber][bid.Sender]
	if !ok {
		return false
	}
	return !bid.Equals(bp.bidMap[hash])
}

func (bp *BidPool) getBidTxGasLimit(bid *auction.Bid) (uint64, error) {
	bp.auctionInfoMu.RLock()
	buffer := bp.bidTxGasBuffer
	bp.auctionInfoMu.RUnlock()

	data, err := system.EncodeAuctionCallData(bid, bp.auctionEntryPointVersion)
	if err != nil {
		return 0, err
	}

	rules := bp.ChainConfig.Rules(big.NewInt(int64(bid.BlockNumber)))
	intrinsicGas, err := types.IntrinsicGas(data, nil, nil, false, rules)
	if err != nil {
		return 0, err
	}
	floorDataGas := uint64(0)
	if rules.IsPrague {
		floorDataGas, err = blockchain.FloorDataGas(types.TxTypeEthereumDynamicFee, data, 0)
		if err != nil {
			return 0, err
		}
	}

	return max(intrinsicGas+bid.CallGasLimit+buffer, floorDataGas), nil

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)
