### Title
Malicious reference-denom vote can DoS oracle price updates for all whitelisted denoms - (File: x/oracle/abci.go)

### Summary
`MidBlocker` computes a single reference-denom exchange rate outside the per-denom loop and uses it to derive every other denom's price via cross-rate division. If the reference-denom ballot's weighted median computation panics or produces a pathological value, the failure propagates to (or blocks pricing for) all other whitelisted denoms in that vote period, mirroring the Perennial Vault bug where one broken market blocks settlement/update for the whole vault.

### Finding Description
`MidBlocker` in `x/oracle/abci.go` picks one "reference denom" (the denom with highest voting power) and computes its weighted median once: [1](#0-0) 
Every other denom's price is then derived as `exchangeRateRD.Quo(exchangeRate)` from that single reference value: [2](#0-1) 

The reference denom's weighted median is computed unconditionally via `ballotRD.WeightedMedianWithAssertion()`, without the same defensive `recover()` wrapping that is used for cross-rate division elsewhere in the codebase: [3](#0-2) 

Note that `ToCrossRate`/related helpers do wrap their `Quo` calls in `defer/recover` to survive overflow (as shown for `ToCrossRate`), and `pickReferenceDenom`/`ballotIsPassing` filter out ballots that don't meet the voting-power threshold. However, `ballotRD.WeightedMedianWithAssertion()` at line 66 executes directly on whatever denom was selected as reference — any validator/voter who is part of that ballot can submit an exchange-rate tuple for the reference denom designed to trigger an unhandled panic or extreme value in the median calculation. Since this call sits inside `MidBlocker` (not inside a per-denom guarded loop), if it panics, the panic is not scoped only to the reference denom: it aborts the entire `MidBlocker` execution for **all** denoms in that vote period, because the subsequent `for _, denom := range keys` loop (lines 76-100) that updates every denom's price never runs.

This is structurally analogous to `Vault::_settleUnderlying` in the Perennial report: a single "market" (here, the reference denom) being broken/malicious blocks the shared batch operation (price tally/update) for every other independent market (denom), even though those other denoms' votes were valid.

### Impact Explanation
If the reference-denom weighted-median calculation panics (e.g., via crafted `sdk.Dec` values causing overflow in decimal division/multiplication used inside `WeightedMedianWithAssertion`, unlike the explicitly-guarded `ToCrossRate`), `MidBlocker` aborts for the block, meaning:
- No exchange rates get updated for any whitelisted denom that vote period, not just the malicious one.
- Downstream modules and integrations that depend on fresh Sei oracle prices experience stale price freezing repeatedly (an attacker with voting power for the reference denom can repeat this every vote period), which can constitute prolonged denial of core oracle pricing functionality.
- Given `EndBlocker`/`MidBlocker` execute in the block-processing pipeline, an unrecovered panic here would also propagate up through `ABCI` block processing and could halt block production, which is a Medium-to-High severity chain-halt risk depending on whether the panic is caught upstream.

### Likelihood Explanation
Reachability requires being a bonded, active validator with a submitted `AggregateExchangeRateVote` (oracle vote admission) — an unprivileged transaction sender in the sense that any validator's aggregate-vote transaction is processed by this ABCI code without additional gatekeeping of the specific values submitted for the denom that ends up chosen as reference denom. Since `pickReferenceDenom` selects whichever denom currently has the largest ballot power, and denom selection can shift block-to-block based on participation, an attacker does not need to control which denom becomes the reference denom in every block — only needs to occasionally align with it, or influence ballot power for a denom to be selected as reference and then submit malformed values.

I could not fully verify from the indexed portion of `x/oracle/types/ballot.go` whether `WeightedMedianWithAssertion` itself has internal overflow protection (only `ToCrossRate`'s call site was visible with `defer/recover`), so likelihood is somewhat uncertain without seeing the full implementation of `WeightedMedianWithAssertion`.

### Recommendation
Wrap the reference-denom weighted-median computation (`ballotRD.WeightedMedianWithAssertion()` at `x/oracle/abci.go:66`) in the same `defer/recover` pattern already used in `ToCrossRate`, and treat a failure as "no reference denom this period" (skip price updates but do not panic the whole `MidBlocker`). Additionally, isolate the per-denom exchange-rate computation loop so that a panic while tallying one denom cannot prevent other denoms from being priced, e.g. by wrapping each iteration body in its own recoverable closure.

### Proof of Concept
Not independently reproducible from indexed code alone: reproducing requires exercising `WeightedMedianWithAssertion` with crafted `sdk.Dec` inputs for the reference-denom ballot to confirm whether it panics without recovery (analogous to the divide-by-zero/overflow cases already covered — and apparently guarded — for cross-rate conversion in `TestOverflowAndDivByZero`, `x/oracle/abci_test.go:692-750`). A Devin session with full repository access would be needed to inspect `WeightedMedianWithAssertion`'s implementation and construct a failing vote sequence to confirm the panic path is unguarded at the reference-denom call site.

func (pb ExchangeRateBallot) ToCrossRate(bases map[string]sdk.Dec) (cb ExchangeRateBallot) {
	for i := range pb {
		vote := pb[i]

		if exchangeRateRT, ok := bases[string(vote.Voter)]; ok && vote.ExchangeRate.IsPositive() {
			// Quo will panic on overflow, so we wrap it in a defer/recover
			func() {
				defer func() {
					if r := recover(); r != nil {
						// if overflow, set exchange rate to 0 and power to 0
						vote.ExchangeRate = sdk.ZeroDec()
						vote.Power = 0
					}
				}()
				vote.ExchangeRate = exchangeRateRT.Quo(vote.ExchangeRate)
			}()
