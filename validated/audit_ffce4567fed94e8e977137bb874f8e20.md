### Title
Scanner reports coinbase (immature) outputs as spendable, letting a depositor extract minted value while the underlying funds cannot move - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
`Scanner::scan_block` iterates over `block.txdata` in full, including `txdata[0]` (the coinbase transaction). Any output paying to a registered script in a coinbase is returned as a `ReceivedOutput` indistinguishable from a mature output. The code's own doc comment acknowledges the flaw ("bound by maturity… a post-processing pass is needed") but the function performs no filtering itself, and `scan_transaction` has no way to know its input was a coinbase.

### Finding Description
The mirrored bug class is "withdraw value after the liability-inducing event, escaping the obligation." Here, an unprivileged miner (or anyone influencing coinbase outputs) sends coins to the multisig's Taproot script inside a coinbase. `scan_block` reports it as a normal received output:

- `scan_block` loops `for tx in &block.txdata` with no exclusion of index 0 ( [1](#0-0) ).
- `scan_transaction` matches purely on `output.script_pubkey`, producing a `ReceivedOutput` with a valid offset and outpoint ( [2](#0-1) ).
- `SignableTransaction::new` / `TransactionSignMachine::sign` will happily consume it: the sighash commits to `Prevouts::All` with no maturity check ( [3](#0-2) ).

The depositor's output is credited (Serai tokens minted / instructions executed per the downstream pipeline), yet any `Batch`/`Burn` transaction spending it is consensus-invalid for 100 blocks. The depositor keeps the minted value while the multisig holds an output it cannot move — precisely the shape of collecting premium while escaping the pending liability.

### Impact Explanation
- Funds are reported received that are not spendable: the inventory of available outputs is inflated by outputs that cannot be spent for ~100 blocks.
- If the scheduling pipeline selects a coinbase output as a `Batch`/`Burn` input, the resulting signed transaction fails relay/consensus (`bad-txns-premature-spend`), stalling the batch and requiring re-signing — a repeatable DoS vector any miner can trigger at the cost of donating coinbase funds to the multisig address.
- In the rotation context, coinbase outputs attributed to a retiring key complicate the forwarding/handover accounting.

### Likelihood Explanation
Requires a miner (or a pool that lets miners set coinbase outputs) to pay the multisig script in a coinbase. This is cheap for any miner finding a block and needs no collusion; it is a fully external, unprivileged input. Whether it causes loss vs. stall depends on downstream maturity handling, which the in-scope code does not provide — the burden is entirely on callers heeding the doc comment.

### Recommendation
In `scan_block`, skip `block.txdata[0]` or thread a maturity flag through `ReceivedOutput`, so coinbase outputs are either not reported or reported as immature until they have `COINBASE_MATURITY` confirmations. Alternatively, have `scan_transaction` take an `is_coinbase`/height parameter and refuse to emit `ReceivedOutput`s that `SignableTransaction::new` would accept but consensus rejects.

### Proof of Concept
1. Register/scan for the multisig's P2TR script via `Scanner::new(key)` ( [4](#0-3) ).
2. A miner creates a block whose coinbase contains `TxOut { script_pubkey: <multisig p2tr script>, value: X }`.
3. `scanner.scan_block(&block)` returns a `ReceivedOutput` for the coinbase output ( [1](#0-0) ).
4. The output is fed to `SignableTransaction::new` and signed via `TransactionSignMachine::sign` using `Prevouts::All` ( [5](#0-4) ).
5. The fully valid-looking signed transaction is rejected by the network for 100 blocks (`bad-txns-premature-spend`), while the depositor's credit for the received funds has already been recorded.

```rust
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
```
