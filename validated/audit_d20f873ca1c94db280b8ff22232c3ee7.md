### Title
Same-epoch cross-field governance votes can enact `LowerBoundBaseFee > UpperBoundBaseFee`, breaking KIP-71 base fee invariants - (File: `kaiax/gov/headergov/impl/header.go`)

### Summary
`checkConsistency()` in `kaiax/gov/headergov/impl/header.go` validates a `Kip71LowerBoundBaseFee` vote against the *currently active* `UpperBoundBaseFee`, and a `Kip71UpperBoundBaseFee` vote against the *currently active* `LowerBoundBaseFee`. Each of the two per-field `FormatChecker`s in `kaiax/gov/param.go` is a `noopFormatChecker` — the "lower ≤ upper" invariant is enforced *only* pairwise, against stale state, exactly like `AMKTVault`'s `setFeeScaled()` checking `feeScaled <= SCALAR` on write but never re-validating the combined state that other code paths rely on. If two validators cast conflicting votes within the same epoch, each individually passes `checkConsistency()` against the pre-epoch `ParamSet`, but the *combined* ratified result can violate `Lower <= Upper` — a state that no code path re-validates when it is actually applied.

### Finding Description
`kaiax/gov/param.go` defines:
```go
Kip71LowerBoundBaseFee: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: noopFormatChecker,
    ...
},
...
Kip71UpperBoundBaseFee: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: noopFormatChecker,
    ...
},
``` [1](#0-0) 

The only invariant check (`lower <= upper`) lives in `checkConsistency()`:
```go
case gov.Kip71LowerBoundBaseFee:
    params := h.GetParamSet(blockNum)
    if vote.Value().(uint64) > params.UpperBoundBaseFee {
        return ErrLowerBoundBaseFee
    } else { return nil }
case gov.Kip71UpperBoundBaseFee:
    params := h.GetParamSet(blockNum)
    if vote.Value().(uint64) < params.LowerBoundBaseFee {
        return ErrUpperBoundBaseFee
    } else { return nil }
``` [2](#0-1) 

This is called both from the vote-casting API `Vote()` (`api.h.checkConsistency(nextBlock, vote)`) [3](#0-2)  and from `VerifyVote()` when validating a proposer's `header.Vote` [4](#0-3) .

Critically, `params := h.GetParamSet(blockNum)` in both branches reads the **currently ratified** `ParamSet`, not a value that accounts for *other pending votes in the same epoch*. Votes accumulate per-epoch and are only merged into the header's `Governance` field at the epoch boundary (see `PrepareHeader`, which builds `header.Governance` from `getExpectedGovernance` combining all votes seen in the previous epoch) [5](#0-4) . Multiple different block proposers in the same epoch can each cast one vote each (`Lower=X` and `Upper=Y`), and each vote is validated independently against the *same, unmodified* pre-epoch `ParamSet` — the check never considers that another vote in the same epoch might also change the opposing bound. If `X > Y` but `X <= old_Upper` and `Y >= old_Lower`, both votes pass `checkConsistency()` individually, yet the epoch's ratified `Governance` (verified later by `VerifyGov()`, which only checks that the aggregated `GovData` matches the deterministically-recomputed set of votes — not that the aggregated result satisfies `Lower <= Upper`) enacts an inconsistent pair.

Once `LowerBoundBaseFee > UpperBoundBaseFee` is active, `KIP71Config.NextMagmaBlockBaseFee()` in `params/kip71_config.go` no longer guarantees `baseFee` stays within `[Lower, Upper]`:
```go
parentBaseFee := parentHeaderBaseFee
if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
    parentBaseFee = upperBoundBaseFee
} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
    parentBaseFee = lowerBoundBaseFee
}
...
if parentGasUsed == gasTarget {
    return makeEvenByFloor(parentBaseFee)
}
``` [6](#0-5) 
When `Lower > Upper`, `parentBaseFee` gets clamped down to `upperBoundBaseFee` (which is now *below* `lowerBoundBaseFee`), and if gas usage equals `gasTarget`, this sub-lower-bound value is returned directly with **no re-clamp to `lowerBoundBaseFee`**, unlike the increase/decrease branches which do clamp against both bounds. This permanently breaks the intended fee floor for as long as the misconfigured governance state remains active, since all node code deterministically computes the same "wrong" base fee (no consensus divergence, but the base fee mechanism's floor guarantee is violated network-wide).

### Impact Explanation
This is a governance-parameter validation bypass analogous to the `AMKTVault` bug: a bound is enforced pairwise at vote/setter time using stale state, but the actually-enacted composite state is never re-validated. The result is a KIP-71 fee-market invariant violation (`baseFee` can be driven and pinned below the governance-intended `LowerBoundBaseFee`), which is a concrete fee-mechanism abuse: users can pay less than the protocol's intended minimum fee for an indefinite period, until governance manually corrects the misconfigured bounds through further votes (which is itself now easier to break again the same way). This falls within the explicitly permitted "governance parameters" analog category and constitutes fee-mechanism abuse impacting all network participants, not merely a resource/DoS issue.

### Likelihood Explanation
Requires two validators (council members with voting rights) to cast conflicting `Kip71LowerBoundBaseFee` / `Kip71UpperBoundBaseFee` votes within the same epoch — a scenario governance/validator council members can trigger deliberately or accidentally, since no single vote is rejected in isolation and no cross-check exists at ratification time (`VerifyGov`) or at the point the values are consumed (`NextMagmaBlockBaseFee`). Because it needs coordination among privileged validators rather than a single unprivileged transaction, likelihood is moderate, but it does not require any compromised key, node bug, or consensus-message manipulation — only ordinary governance actions already exposed via the `governance_vote` RPC.

### Recommendation
Re-validate the fully-merged `ParamSet` (not each vote individually against stale state) before ratifying `header.Governance` at epoch boundaries — i.e., add a consistency check in `getExpectedGovernance`/`VerifyGov` (or wherever the epoch's aggregate `GovData` is finalized) ensuring `LowerBoundBaseFee <= UpperBoundBaseFee` holds for the *combined* result, not just for each vote against the pre-epoch state. Additionally, harden `NextMagmaBlockBaseFee` in `params/kip71_config.go` to always clamp the returned base fee into `[lowerBoundBaseFee, upperBoundBaseFee]` in every branch (including the `parentGasUsed == gasTarget` case), rather than relying solely on caller-side invariants.

### Proof of Concept
1. Governance state: `LowerBoundBaseFee = 25e9`, `UpperBoundBaseFee = 750e9`.
2. In epoch N, validator A (block proposer of block `n1`) casts vote `Kip71LowerBoundBaseFee = 700e9`. `checkConsistency` compares `700e9 > params.UpperBoundBaseFee(750e9)` → false → vote accepted.
3. In the same epoch N, validator B (block proposer of block `n2`, `n2 != n1`) casts vote `Kip71UpperBoundBaseFee = 100e9`. `checkConsistency` compares `100e9 < params.LowerBoundBaseFee(25e9)` → false (using the *pre-epoch* Lower value, since A's vote hasn't been ratified yet) → vote accepted.
4. At the epoch boundary, `PrepareHeader`/`getExpectedGovernance` merges both votes into `header.Governance`, ratifying `Lower=700e9, Upper=100e9` with no cross-check in `VerifyGov`.
5. Subsequent blocks compute `NextMagmaBlockBaseFee` with `Lower=700e9 > Upper=100e9`, producing base fees inconsistent with (and potentially below) the governance-intended floor, per the clamping logic in `params/kip71_config.go` lines 80-91.

Note: I was unable to fully inspect `kaiax/gov/headergov/impl/execution.go` (where `HandleVote`/epoch aggregation logic lives) due to a tool error in the final iteration, so the exact mechanics of how same-epoch votes are merged into the ratified `GovData` could not be double-checked line-by-line; the analysis above is based on `PrepareHeader`/`checkConsistency`/`VerifyGov` in `header.go` and the `param.go` `FormatChecker` definitions, which were directly confirmed.

	// if this node has a vote waiting to be casted, put Vote field.
	if vote, ok := h.peekMyVote(); ok {
		voteBytes, err := vote.ToVoteBytes()
		if err != nil {
			return err
		}
		header.Vote = voteBytes
		logger.Debug("Prepare header with vote", "num", header.Number.Uint64(), "vote", hexutil.Encode(header.Vote))
	}

	// if epoch block & vote exists in the last epoch, put Governance field.
	if header.Number.Uint64()%h.epoch == 0 {
		gov := h.getExpectedGovernance(header.Number.Uint64())
		if len(gov.Items()) > 0 {
			govBytes, err := gov.ToGovBytes()
			if err != nil {
				return err
			}
			header.Governance = govBytes
			logger.Debug("Prepare header with governance", "num", header.Number.Uint64(), "governance", hexutil.Encode(header.Governance))
		}
	}

	return nil
}

func (h *headerGovModule) VerifyVote(header *types.Header) error {
	if len(header.Vote) == 0 {
		return nil
	}

	var (
		vb       headergov.VoteBytes = header.Vote
		blockNum                     = header.Number.Uint64()
	)

	vote, err := vb.ToVoteData()
	if err != nil {
		logger.Error("ToVoteData error", "num", blockNum, "vote", vb, "err", err)
		return err
	}

	if gov.DeprecatedAt(vote.Name(), h.ChainConfig.Rules(header.Number)) {
		logger.Error("Vote is deprecated", "num", blockNum, "name", vote.Name())
		return ErrDeprecatedVote
	}

	council, err := h.ValSet.GetCouncil(blockNum)
	if err != nil {
		return err
	}

	// check if the voter is in council
	if !slices.Contains(council, vote.Voter()) {
		return ErrInvalidKeyValue
	}

	// check if Voter is the block proposer.
	author, err := h.Chain.Sealer().Author(header)
	if err != nil {
		return err
	}
	if author != vote.Voter() {
		return ErrInvalidVoter
	}

	// In single mode, only the governing node can write header.Vote after Permissionless.
	params := h.GetParamSet(blockNum)
	if h.ChainConfig.IsPermissionlessForkEnabled(new(big.Int).SetUint64(blockNum)) &&
		params.GovernanceMode == "single" &&
		vote.Voter() != params.GoverningNode {
		return ErrVotePermissionDenied
	}

	return h.checkConsistency(blockNum, vote)
}
