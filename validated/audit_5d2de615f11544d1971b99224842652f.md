### Title
Division by zero in KIP-71 `NextMagmaBlockBaseFee` when `GasTarget` governance parameter is set to 0 - ([File: params/kip71_config.go])

### Summary
`KIP71Config.NextMagmaBlockBaseFee` divides by the `GasTarget` governance parameter without checking it for zero, unlike the analogous `BaseFeeDenominator` parameter which is explicitly guarded against a zero value. [1](#0-0)  If `GasTarget` is ever set to `0`, every node that computes the next block's base fee (for any block whose parent used any gas at all) will attempt a `big.Int` division by zero, which panics in Go's `math/big` package.

### Finding Description
`NextMagmaBlockBaseFee` computes the KIP-71 dynamic base fee. The `GasTarget` parameter is read directly from governance without a zero-value validity check, then used unconditionally as a divisor: [2](#0-1)  for the gas-used-above-target branch, and [3](#0-2)  for the gas-used-below-target branch. Both call `x.Div(x, new(big.Int).SetUint64(gasTarget))`, which panics if `gasTarget == 0`.

By contrast, the sibling parameter `BaseFeeDenominator` is explicitly protected: if it is zero, the code substitutes a safe default of `64` to "avoid panic" [1](#0-0) . No equivalent protection exists for `GasTarget`.

The governance-parameter definition for `Kip71GasTarget` uses `noopFormatChecker`, i.e., it performs no validation on the submitted value, whereas the neighboring `Kip71BaseFeeDenominator` parameter explicitly rejects zero via `FormatChecker: func(cv any) bool { v, ok := cv.(uint64); return ok && v != 0 }` [4](#0-3) . This asymmetry means a governance vote (or `GovParamContract` update under contract-based governance) can set `GasTarget = 0` and have it accepted as a valid parameter change.

Once `GasTarget = 0` is active, `parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)` will exceed the target (0) for essentially any block with non-zero gas usage, driving execution into the "gas used above target" branch that performs `x.Div(x, gasTarget)` with `gasTarget = 0`, causing an immediate panic.

`NextMagmaBlockBaseFee` (and the header check `VerifyMagmaHeader` that calls it) is invoked from consensus-critical code paths used by every node: `blockchain/block_validator.go` (header verification), `blockchain/tx_pool.go` (tx admission/pricing), `work/worker.go` (block assembly), and RPC-facing gas price estimation (`node/cn/gasprice/gasprice.go`, `node/cn/gasprice/feehistory.go`). A panic here on the block validation or block assembly path crashes the node process handling that block.

### Impact Explanation
This is a chain-wide denial-of-service / state-divergence risk: once the `GasTarget` governance value is set to `0` and the KIP-71/Magma fork is active, every full node, validator, and RPC node that attempts to validate the resulting header or build the next block will panic in `NextMagmaBlockBaseFee`. Because the panic occurs deterministically in code executed by all nodes on the same input, it results in a total, synchronized crash of the network (chain halt) rather than mere non-consensus between honest nodes — an availability-critical impact for a consensus/fee-calculation primitive reachable by manipulating a listed governance parameter.

### Likelihood Explanation
This requires a governance parameter change (`Kip71GasTarget` set to 0), which is only actionable by whoever controls governance voting/`GovParamContract` (single governance mode: the `GoverningNode`; or contract-governed mode: however param updates are authorized). This is not reachable by an arbitrary unprivileged transaction sender directly, but the report's rules explicitly list "governance parameters" as an in-scope reachable category, and the lack of any `FormatChecker` validation (unlike the sibling `BaseFeeDenominator` param, which is explicitly hardened) is a genuine, provable code defect — an accidental or malicious governance proposal (or a bug in a proposal-generation tool) setting `GasTarget=0` would not be rejected by any format/validity check before being accepted and applied network-wide.

### Recommendation
Add a `FormatChecker` for `Kip71GasTarget` in `kaiax/gov/param.go` that rejects `0`, mirroring the existing check on `Kip71BaseFeeDenominator`. Defensively, also guard `gasTarget` inside `NextMagmaBlockBaseFee` in `params/kip71_config.go` (e.g., substitute a safe non-zero default, matching the existing `baseFeeDenominator == 0` protection) so that even a misconfigured/legacy value cannot cause a panic in consensus-critical code.

### Proof of Concept
1. Via governance (single mode governing node, or contract-governance authorized proposer), submit a parameter update setting `kip71.gastarget = 0`. Because `Kip71GasTarget`'s `FormatChecker` is `noopFormatChecker` [5](#0-4) , this value is accepted without rejection.
2. Once the parameter becomes effective at the next epoch/governance-effective block (and the Magma fork is active), any block with `GasUsed > 0` is proposed.
3. All nodes evaluating the header (`VerifyMagmaHeader` → `NextMagmaBlockBaseFee`) or the block-producing node (`work/worker.go` calling `NextMagmaBlockBaseFee`) compute `parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)` which is `> gasTarget (0)`, entering the branch at [2](#0-1)  and executing `x.Div(x, new(big.Int).SetUint64(0))`, which panics, crashing every node processing that block/header.
