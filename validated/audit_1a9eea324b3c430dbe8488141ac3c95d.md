### Title
Server-controlled `WWW-Authenticate` realm header can force GitHub Desktop's credential helper to misclassify a non-GitHub host as GitHub Enterprise, enabling credential prompts/exfiltration for attacker-controlled remotes - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
`Harvester.getEstimates` used the wrong input value (`WETH` amount fed into a `YAXIS→WETH` path) to compute a security-relevant number (slippage bound), and nothing validated that the computed value actually corresponded to the trade being protected. The Desktop analog is `getEndpointKind` in `trampoline-credential-helper.ts`: it derives the *trust classification* of a remote endpoint (`github.com` / `enterprise` / `generic`) from data supplied by the remote server itself (the `wwwauth[...]` credential fields forwarded by Git), rather than from a value Desktop actually controls or verifies independently, and that classification then drives credential handling for the endpoint.

### Finding Description
When Git needs credentials for an HTTPS remote, it invokes Desktop's credential helper with fields captured from the server's HTTP response, including any `WWW-Authenticate` headers, exposed as `wwwauth[N]` entries in the credential map. [1](#0-0) 

`getEndpointKind` trusts the *content* of this attacker/server-controlled header to decide the endpoint is `enterprise` (i.e., a GitHub host) purely because the realm string contains `realm="GitHub"`, before ever calling `isGitHubHost` (which performs an actual verifying network probe): [2](#0-1) 

This "enterprise" classification then feeds directly into `getCredential`, which — for any endpoint classified as non-`generic` where no matching account exists — will prompt the user with `ui.promptForGitHubSignIn(endpoint)`, i.e., a GitHub-branded sign-in flow, for a URL that git resolved from the remote: [3](#0-2) 

If an account for that endpoint *does* already exist (e.g. because the attacker crafted a URL that happens to match a normalized form of a real GHE endpoint, or because of endpoint string ambiguities), the flow instead falls straight through to returning the stored GHE token from `credWithAccount`/`findGitHubTrampolineAccount`, without a second confirming check that the host is actually the enterprise server that account belongs to beyond origin string equality: [4](#0-3) 

The broken invariant: a value that should only ever be established by Desktop's own verification (`isGitHubHost`, an outbound network check) is instead short-circuited by a value read straight out of the credential map that Git populated from the remote server's response headers. Nothing here cross-checks the header claim against DNS, TLS certificate identity, or any Desktop-controlled allowlist — the string `realm="GitHub"` alone is sufficient to move the endpoint out of the safe `generic` bucket.

### Impact Explanation
This is analogous to the smart-contract bug in that a security-relevant computed value (`_fee`/`_estimatedYAXIS` there; `endpointKind`/trust decision here) is derived from the wrong/attacker-influenced source instead of the value that should actually govern the decision. Consequences:
- A malicious HTTP git server (a repo the user clones/fetches, or a MITM/rogue proxy sitting on a `git remote`) can spoof `WWW-Authenticate: realm="GitHub"` to make Desktop treat it as GitHub Enterprise.
- This can trigger `promptForGitHubSignIn`, presenting the user a GitHub-branded auth prompt for a non-GitHub host, a phishing/credential-capture vector that lends unwarranted legitimacy compared to the plain generic-credential prompt (`promptForGenericGitAuthentication`) that would otherwise be shown.
- In the "existing account" branch, if any string-level endpoint match occurs, the stored token for a real GHE account could be sent as a credential to a host that only *claims* to be that GHE server via headers it fully controls, risking token exfiltration to an attacker-controlled endpoint.

### Likelihood Explanation
The attacker primitive required is exactly within the allowed scope: control of a git remote/proxy response (the server can freely set arbitrary response headers, including `WWW-Authenticate`). No local access, admin rights, or pre-existing malware is needed — simply having the victim add/fetch from a URL pointing at the attacker's HTTP(S) endpoint is sufficient to reach this code path via normal Git credential-helper invocation. The existing guard (`isGitHubHost`, a real network probe) is present but is only reached in the fallback branch — the header-based shortcut executes first and bypasses it entirely for any response containing the crafted realm string.

### Recommendation
Do not trust the `wwwauth[...]` realm string as sufficient evidence to classify an endpoint as `enterprise`. At minimum, treat the header as a weak hint and always confirm with the existing `isGitHubHost` verifying check (or an equivalent authenticated probe / pinned allowlist) before elevating trust or presenting a GitHub-branded credential prompt, and ensure the "existing account" match in `findGitHubTrampolineAccount` compares more than string origin equality when deciding to release a stored token.

### Proof of Concept
1. Set up a plain HTTP(S) server that responds to Git's credential probe with `WWW-Authenticate: realm="GitHub"` on a 401.
2. In GitHub Desktop, clone or add this server's URL as a remote and perform a fetch/push that requires authentication.
3. Observe that `getEndpointKind` returns `'enterprise'` purely from the header match at [5](#0-4) 
without invoking `isGitHubHost`, causing `getCredential` to invoke `ui.promptForGitHubSignIn(endpoint)` (a GitHub-branded prompt) for the attacker's host instead of the generic credential prompt.

Note: I was not able to fully trace every call site of `findGitHubTrampolineAccount`/account-matching logic or confirm end-to-end whether a stored GHE token could definitively be released to a spoofed host in this codebase snapshot (the exact endpoint-string normalization used for account matching would need deeper tracing); this part of the impact should be verified with a live reproduction before treating it as fully confirmed.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'

export async function findGitHubTrampolineAccount(
  accountsStore: AccountsStore,
  remoteUrl: string
): Promise<Account | undefined> {
  const accounts = await accountsStore.getAll()
  const parsedUrl = new URL(remoteUrl)
  return accounts.find(
    a => new URL(getHTMLURL(a.endpoint)).origin === parsedUrl.origin
  )
}
