Found a genuine analog: the "trust this directory" flow in `addSafeDirectory` binds trust permanently to a filesystem *path string* in the global git config, not to any property of the repository content or ownership at the moment of trust. Once a path is trusted, Desktop never revokes or re-scopes that trust when the underlying object at that path changes — the same broken-invariant pattern as the MultiSig bug (a check validated once against state that can later change without re-validating the dependent guarantee).

### Title
Path-scoped `safe.directory` trust is never revoked, letting an attacker-controlled directory inherit stale trust - ([File: app/src/lib/git/config.ts])

### Summary
`addSafeDirectory()` permanently whitelists a path string in the user's global git config so that Git (and Desktop) will operate on a repository at that path even though it is owned by a different OS user. [1](#0-0) 
This whitelist is never narrowed or removed by Desktop, and `getRepositoryType()`'s "unsafe" detection is purely path-based, so any git repository later placed at that same path is automatically treated as trusted. [2](#0-1) 

### Finding Description
The invariant the "unsafe repository" prompt is supposed to protect is: *Desktop should only run git operations that assume a benign repository owner for directories the current user has consciously trusted, at the time of that specific repository's content.* This mirrors the MultiSig invariant `_numConfirmationsRequired <= _whiteWallet.length`, which was supposed to hold continuously, not just at the moment it was checked.

`addSafeDirectory(path)` writes the raw path string to `safe.directory` in the global gitconfig via `addGlobalConfigValueIfMissing`. [3](#0-2) 
This call site is reached from both `AddExistingRepository.onTrustDirectory` and `MissingRepository.onTrustDirectory`. [4](#0-3) [5](#0-4) 

The trust decision is scoped only to a path string, never to any identity of the repository (e.g., its initial commit, remote URL, or ownership at grant time). Once added, nothing in the codebase ever removes an entry from `safe.directory` — there is no analog to a "deregister" hook that shrinks the trusted set when circumstances change. `getRepositoryType()` re-checks ownership on every call by shelling out to `git rev-parse`, but that check only asks "does git consider the *path* unsafe", which is controlled entirely by the static `safe.directory` list, not by anything about the specific repository contents. [2](#0-1) 

Concretely, if a user ever trusted a path (e.g., a USB drive mount point, a network share such as `/media/usb0`, or a shared multi-user machine path like `/home/shared/project`) because they legitimately owned/trusted the repository there at the time, that trust is permanent and global. If that path is later reused — the original repository is deleted and an attacker (a different local user, or content dropped by removable/shared media) places a new, malicious repository at the identical path — Desktop's `getRepositoryType()` will report `kind: 'regular'` instead of `kind: 'unsafe'`, and Desktop will run git commands (and hooks, if enabled) against attacker-controlled repository content without ever re-prompting the user. [6](#0-5) 
This is exactly the MultiSig pattern: a guard (`_numConfirmationsRequired <= _whiteWallet.length` / "is this path still trustworthy") was valid when first established, but the underlying object it was meant to protect (`_whiteWallet` membership / the repository at that path) changed later, and the stale guard was never re-derived or revoked.

### Impact Explanation
An attacker who can get content placed at a previously-trusted path (shared machines, mounted/removable media reused by the same user, restored path from backup, or a path recycled by repository/relocate flows such as `_relocateRepository`) inherits the "trusted" designation without any additional user consent. [7](#0-6) 
Because trusting a directory is explicitly documented as bypassing protection against "automatically execute files in the repository," a stale trust grant on attacker-controlled content can lead to arbitrary code execution via git hooks or similar mechanisms without the user being warned again. [8](#0-7) 

### Likelihood Explanation
This requires a real-world sequence (path reuse after deletion, shared/removable media, or common working-directory names such as `~/repos/project` reassigned to a different owner) — not local malware or leaked credentials. It fits the stated valid-impact class because the trigger is attacker-controlled content later placed at a git working-directory path the user interacts with, and the resulting corruption is silent (no re-prompt, no visible indication that trust is stale).

### Recommendation
Scope trust to more than a bare path: bind the trust decision to filesystem identity (e.g., inode/device) as well as path, and/or re-validate meaningful repository identity (e.g., remote URL / initial commit) after trust is granted. At minimum, provide a mechanism (analogous to the recommended "internal function that decreases `_numConfirmationsRequired`" in the report) that automatically revokes a `safe.directory` entry when Desktop detects the repository at that path was removed and replaced (e.g., different `.git` directory identity, different initial commit, or a large gap since last opened), instead of leaving the trust grant permanent and content-agnostic.

### Proof of Concept
1. User opens a git repository at `/media/usb0/project` that they legitimately own; Git reports "dubious ownership," and the user clicks "Trust Repository," calling `addSafeDirectory('/media/usb0/project')`. [4](#0-3) 
2. This appends `/media/usb0/project` to `safe.directory` in the user's global `.gitconfig` permanently. [3](#0-2) 
3. The user unmounts and later reuses the drive, or an attacker with access to the same mount point replaces the directory contents with a malicious repository (including hooks) at the exact same path `/media/usb0/project`.
4. The user reopens Desktop and points it (or Desktop auto-opens a previously known repository) at that path. `getRepositoryType()` runs `git rev-parse`, which no longer errors with "dubious ownership" because the path is in `safe.directory`, returning `kind: 'regular'`. [2](#0-1) 
5. Desktop proceeds to operate on the attacker's repository as fully trusted, with no re-prompt, exactly reproducing the "stale invariant" bug class from the MultiSig report where a once-valid guarantee silently became false after the underlying state changed.

/**
 * Adds a path to the `safe.directories` configuration variable if it's not
 * already present. Adding a path to `safe.directory` will cause Git to ignore
 * if the path is owner by a different user than the current.
 */
export async function addSafeDirectory(path: string) {
  // UNC-paths on Windows need to be prefixed with `%(prefix)/`, see
  // https://github.com/git-for-windows/git/commit/e394a16023cbb62784e380f70ad8a833fb960d68
  if (__WIN32__ && path[0] === '/') {
    path = `%(prefix)/${path}`
  }

  await addGlobalConfigValueIfMissing('safe.directory', path)
}

/** Set the global config value by name. */
export async function addGlobalConfigValueIfMissing(
  name: string,
  value: string
): Promise<void> {
  const { stdout, exitCode } = await git(
    ['config', '--global', '-z', '--get-all', name, value],
    __dirname,
    'addGlobalConfigValue',
    { successExitCodes: new Set([0, 1]) }
  )

  if (exitCode === 1 || !stdout.split('\0').includes(value)) {
    await addGlobalConfigValue(name, value)
  }
}

export async function getRepositoryType(path: string): Promise<RepositoryType> {
  if (!(await directoryExists(path))) {
    return { kind: 'missing' }
  }

  try {
    const result = await git(
      ['rev-parse', '--is-bare-repository', '--show-cdup', '--git-dir'],
      path,
      'getRepositoryType',
      { successExitCodes: new Set([0, 128]) }
    )

    if (result.exitCode === 0) {
      // Bare repositories will not include gitdir so we handle that separately
      if (result.stdout.startsWith('true\n')) {
        return { kind: 'bare' }
      }

      // --is-bare-repository and --show-cdup each produce a single line but
      // --git-dir could theoretically contain newlines so we parse the known
      // fields first and treat the remainder as the git dir. We use [\s\S]*
      // instead of .* for the git dir capture group because .* doesn't match
      // newlines whereas [\s\S]* matches any character including newlines.
      const match = result.stdout.match(/^(true|false)\n(.*)\n([\s\S]*)\n$/)

      if (match) {
        const [, isBare, cdup, gitDir] = match

        return isBare === 'true'
          ? { kind: 'bare' }
          : {
              kind: 'regular',
              topLevelWorkingDirectory: resolve(path, cdup),
              gitDir: resolve(path, gitDir),
            }
      }
    }

    const unsafeMatch =
      /fatal: detected dubious ownership in repository at '(.+)'/.exec(
        result.stderr
      )
    if (unsafeMatch) {
      return { kind: 'unsafe', path: unsafeMatch[1] }
    }

  private async validatePath(path: string): Promise<boolean> {
    if (path.length === 0) {
      this.setState({
        isRepositoryBare: false,
        showNonGitRepositoryWarning: false,
      })
      return false
    }

    const type = await getRepositoryType(path)

    const isRepository = type.kind !== 'missing' && type.kind !== 'unsafe'
    const isRepositoryUnsafe = type.kind === 'unsafe'
    const isRepositoryBare = type.kind === 'bare'
    const showNonGitRepositoryWarning = !isRepository || isRepositoryBare
    const repositoryUnsafePath = type.kind === 'unsafe' ? type.path : undefined

    this.setState(state =>
      path === state.path
        ? {
            isRepositoryBare,
            isRepositoryUnsafe,
            showNonGitRepositoryWarning,
            repositoryUnsafePath,
          }
        : null
    )

    return path.length > 0 && isRepository && !isRepositoryBare
  }

  public async _relocateRepository(repository: Repository): Promise<void> {
    const path = await showOpenDialog({ properties: ['openDirectory'] })

    if (path === null) {
      return
    }

    const rt = await getRepositoryType(path)

    if (rt.kind === 'regular') {
      // The repository has moved, so any main worktree we recorded before now
      // points at where it used to be. Resolve it again from the new location.
      await this.repositoriesStore.updateRepositoryPath(
        repository,
        rt.topLevelWorkingDirectory,
        rt.gitDir,
        await this.findMainWorktreePath(rt.topLevelWorkingDirectory)
      )
    } else if (rt.kind === 'unsafe') {
      // Git refuses to run in a repository it considers unsafe, so there's no
      // resolving the main worktree here. Drop the recorded path rather than
      // keep one we know is stale.
      await this.repositoriesStore.updateRepositoryPath(
        repository,
        path,
        undefined,
        undefined,
        true
      )
    } else {
      this.emitError(new Error(this.getInvalidRepoPathsMessage([path])))
    }
