### Title
`IntentGatewayV2.instance()` falls back to `address(this)` for unregistered source chains, allowing cross-chain address-collision impersonation to drain escrow — ([File: evm/tron/contracts/apps/IntentGatewayV2.sol])

### Summary
The external report's core defect is: a value that gates fund movement (the fee) is attacker-influenced and never validated/bound before the user is asked to trust it. The local analog is `IntentGatewayV2.authenticate()`, which gates fund movement (escrow release/refund) on a "known module" check whose fallback silently trusts the *local contract's own address* as the accepted sender identity for any state machine that has no registered gateway instance. This turns an unconfigured-chain edge case into a spoofable authorization bypass.

### Finding Description
`instance()` is used to resolve which remote address is trusted as the counterpart `IntentGatewayV2` for a given source chain: [1](#0-0) 

```solidity
function instance(bytes calldata stateMachineId) public view returns (address) {
    address gateway = _instances[keccak256(stateMachineId)];
    return gateway == address(0) ? address(this) : gateway;
}

function authenticate(PostRequest calldata request) internal view {
    if (request.from.length != 20) revert InvalidInput();
    address module = address(bytes20(request.from));
    // IntentGateway only accepts incoming assets from itself or known instances
    if (instance(request.source) != module) revert Unauthorized();
}
```

`authenticate()` is the sole gate for `RedeemEscrow` and `RefundEscrow` messages, which trigger `withdraw()` — the function that transfers escrowed tokens and accumulated fee-token balances to an attacker-controlled `beneficiary`: [2](#0-1) 

When no `NewDeployment` message has ever registered a gateway for a given `stateMachineId` (`_instances[keccak256(stateMachineId)] == address(0)`), `instance()` returns `address(this)` — the destination gateway trusts *itself* as the legitimate remote sender for that chain. Since EVM/Tron contract addresses are derived deterministically (CREATE2, or identical nonce/deployer sequences), an attacker can deploy a malicious contract on **any Hyperbridge-connected but not-yet-onboarded source chain** at the exact same address as the destination `IntentGatewayV2` (`address(this)`), using well-known deterministic deployer factories that exist at the same address across many EVM-compatible chains. That malicious contract then dispatches an ISMP `PostRequest` whose `from` field (set to `msg.sender` by the source-chain host) equals the destination gateway's address, and whose `source` is the unregistered chain id. On delivery, `authenticate()` computes `instance(request.source) == address(this)` and compares it to `module == address(this)` — the check trivially passes, with no relayer, prover, or governance compromise required; only a valid consensus/state proof for the (legitimately Hyperbridge-connected) source chain is needed, which any permissionless relayer will produce.

The attacker's forged body can carry an arbitrary `WithdrawalRequest{commitment, tokens, beneficiary}` referencing any live order commitment with escrowed value, invoking `withdraw()` to redirect the full escrow (and stored transaction fees) to themselves. [3](#0-2) 

### Impact Explanation
This is a false module-identity acceptance that leads directly to unauthorized fund transfer: escrowed user assets (`order.inputs`) and accrued transaction fees for any order on the vulnerable gateway can be redirected to an attacker-chosen beneficiary, without needing a malicious relayer, prover, or governance actor — only a state machine that Hyperbridge can prove state for, but for which the IntentGateway has not (yet) registered a counterpart instance. This matches the bounty's core impact classes: "stealing or loss of funds," "unauthorized transaction or execution," and "false proof/state acceptance" (accepting a message as if it came from a known gateway when it did not).

### Likelihood Explanation
Exploitability depends on: (1) at least one Hyperbridge-supported state machine existing for which `_instances[...]` has not been populated (plausible during gradual multi-chain rollout, or any chain intentionally left un-onboarded for the Intent Gateway while still supported by the wider Hyperbridge network), and (2) the attacker being able to deploy a contract at the same address as the destination gateway on that chain — achievable via public CREATE2 deployer factories that are commonly pre-deployed at identical addresses across EVM-compatible chains. No relayer collusion, key compromise, or governance action is required, only a permissionless proof submission. This is a self-contained, unprivileged-attacker path with a concrete corrupted value: `instance(request.source)` silently resolving to `address(this)` instead of `address(0)`/revert for unconfigured chains.

### Recommendation
Change `instance()` to explicitly revert (or have `authenticate()` reject) when no instance is registered for `request.source`, rather than defaulting to `address(this)`:
```solidity
function instance(bytes calldata stateMachineId) public view returns (address) {
    address gateway = _instances[keccak256(stateMachineId)];
    if (gateway == address(0)) revert UnknownInstance();
    return gateway;
}
```
Audit all other call sites of `instance()`/`_instance()` (including dispatch-side `to: abi.encodePacked(instance(order.source))`) to ensure the same fallback isn't relied upon for outbound routing either, and verify whether the primary EVM implementation (`evm/src/apps/intentsv2/IntentsBase.sol` / `ExtrinsicIntents.sol`, which expose the analogous `_instance()`/`_authenticate()` functions) contains the identical fallback pattern — I was not able to confirm the exact body of `_instance()` in that file within this session and this should be verified directly, since if it mirrors the Tron contract it carries the same vulnerability.

### Proof of Concept
1. Identify a state machine `X` supported by Hyperbridge's consensus/state-proof infrastructure but for which `IntentGatewayV2._instances[keccak256(X)]` is still `address(0)` on the target destination chain (no `NewDeployment` processed for `X` yet).
2. Using a public deterministic deployer (e.g., a CREATE2 factory deployed at the same address on both chain `X` and the destination chain), deploy a minimal malicious `IsmpModule` contract on chain `X` at the exact same address as the destination `IntentGatewayV2` contract.
3. From that contract, dispatch a `PostRequest` to the destination `IntentGatewayV2` with:
   - `body = bytes1(RequestKind.RefundEscrow) || abi.encode(WithdrawalRequest({commitment: <victim order commitment>, tokens: <victim's full escrowed inputs>, beneficiary: attacker}))`
4. Wait for a permissionless relayer to submit the valid consensus/state proof for chain `X` (no relayer complicity needed — this is standard message delivery).
5. On `onAccept`, `authenticate()` computes `instance(X) == address(this)` (fallback) and compares to `module == address(this)` (the attacker's deployed address) — check passes.
6. `withdraw()` executes, transferring the victim's escrowed tokens and stored fees to the attacker's `beneficiary`.

    function withdraw(WithdrawalRequest memory body, bool isRefund) internal {
        address beneficiary = address(uint160(uint256(body.beneficiary)));
        _filled[body.commitment] = beneficiary;

        // redeem escrowed tokens
        uint256 len = body.tokens.length;
        for (uint256 i; i < len;) {
            address token = address(uint160(uint256(body.tokens[i].token)));
            uint256 amount = body.tokens[i].amount;
            if (_orders[body.commitment][token] == 0) revert UnknownOrder();

            if (token == address(0)) {
                (bool sent,) = beneficiary.call{value: amount}("");
                if (!sent) revert InsufficientNativeToken();
            } else {
                (bool success,) = token.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, amount));
                if (!success) revert TransferFailed();
            }

            _orders[body.commitment][token] -= amount;
            unchecked {
                ++i;
            }
        }

        // redeem tx fees
        uint256 fees = _orders[body.commitment][TRANSACTION_FEES];
        if (fees > 0) {
            address feeToken = IDispatcher(host()).feeToken();
            (bool success,) = feeToken.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, fees));
            if (!success) revert TransferFailed();
            delete _orders[body.commitment][TRANSACTION_FEES];
        }

        if (isRefund) {
            emit EscrowRefunded({commitment: body.commitment});
        } else {
            emit EscrowReleased({commitment: body.commitment});
        }
    }
