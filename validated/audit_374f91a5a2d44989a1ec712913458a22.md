### Title
Cross-shop session hijack via attacker-controlled `shop`/`embedded` params in `EnsureInstalled` skips all ownership verification - (File: app/controllers/concerns/shopify_app/ensure_installed.rb)

### Summary
`current_shopify_domain` and `installed_shop_session` derive the "current shop" purely from the unauthenticated `params[:shop]` query string, format-checked only by `ShopifyApp::Utils.sanitize_shop_domain`. `check_shop_known`/`validate_non_embedded_session` then load and use that shop's stored offline session, but the only "proof" step (`validate_non_embedded_session`) can be bypassed entirely by an attacker simply adding `embedded=1` to the request, which is itself just a raw, attacker-controlled param.

### Finding Description
`check_shop_domain` (before_action) calls `current_shopify_domain`, which does nothing more than sanitize the format of `params[:shop]`: [1](#0-0) . `sanitize_shop_domain` only validates that the string looks like a `*.myshopify.com` (or trusted-domain) hostname — it performs no authentication of the caller: [2](#0-1) .

`installed_shop_session` then blindly loads whatever offline session is stored for that shop domain from `SessionRepository`: [3](#0-2) .

In the legacy (non `use_new_embedded_auth_strategy?`) branch, the only extra check is `validate_non_embedded_session`: [4](#0-3) . This method's *entire* effect can be nullified because it early-returns when `loaded_directly_from_admin?` is true, and that predicate is fully attacker-controlled: [5](#0-4) . An attacker simply appends `embedded=1` to the request and `loaded_directly_from_admin?` returns `true`, so `validate_non_embedded_session` returns immediately without even attempting the Shopify API call that would have been the only (weak) sanity check.

Even in the non-`embedded=1` path, `validate_non_embedded_session` only proves the *stored token still works against Shopify* — it never proves that the *current HTTP request* legitimately originates from that shop (no HMAC over the query string, no ID token/JWT verification, no `host` param signature check). Nothing in this file ties `params[:shop]`/`params[:host]` to a cryptographic assertion from Shopify; they are raw, forgeable query parameters, and `shop_login`'s `URI.encode_www_form(shop: params[:shop], host: params[:host], return_to: request.fullpath)` further propagates these unauthenticated values downstream: [6](#0-5) .

Consequently, any unprivileged attacker who knows (or guesses/enumerates) another merchant's `*.myshopify.com` domain — which is not secret — can issue `GET <any EnsureInstalled-protected action>?shop=victim-shop.myshopify.com&embedded=1&host=<anything>` and have the controller load and act with `victim-shop`'s installed offline session for the entire request, violating the required invariant that the loaded session must correspond to a merchant proven to control the shop, for the whole class of inputs where `shop` names any previously-installed store and `embedded=1` is set (or, in the non-embedded case, whenever the victim shop's token still happens to be valid, which is the normal case).

### Impact Explanation
This is a cross-shop access primitive: the app will execute the developer's controller logic (data reads/writes, API calls to Shopify) using the victim shop's real offline access token and shop context, driven entirely by attacker-supplied `shop`/`embedded`/`host` params with no session-token, ID-token, or HMAC verification. This matches Shopify HackerOne's "cross-shop/session confusion — accessing or acting on another merchant's store data/token" impact class.

### Likelihood Explanation
High feasibility and fully repeatable: no secrets, no victim interaction, and no host misconfiguration are required. The attacker only needs (a) a target shop domain string (commonly discoverable/guessable `*.myshopify.com` names) and (b) to add `embedded=1` to bypass the one weak check present. This applies to the entire generated input class of `(shop, host, embedded)` where `shop` is any store with an existing session row — not a single crafted example — because `sanitize_shop_domain` accepts the whole class of valid `*.myshopify.com`-shaped strings and `loaded_directly_from_admin?` is a boolean the attacker fully controls for every such input.

### Recommendation
Do not derive shop identity for authorization purposes from raw `params[:shop]`/`params[:embedded]`. Require cryptographic proof of shop context before loading `installed_shop_session`: verify a signed Shopify session/ID token (as done in the `use_new_embedded_auth_strategy?`/`activate_shopify_session` path) or validate an HMAC over the full query string for the legacy flow, and never let `embedded` (an unsigned client-supplied flag) skip verification of session validity/ownership.

### Proof of Concept
Controller/integration test sketch (legacy, non-token-exchange configuration):
```ruby
test "attacker loads another shop's session via unauthenticated params" do
  victim_domain = "victim-shop.myshopify.com"
  ShopifyApp::SessionRepository.store_shop_session(
    ShopifyAPI::Auth::Session.new(shop: victim_domain, access_token: "victim-token")
  )

  get "/some_ensure_installed_action", params: {
    shop: victim_domain,
    host: Base64.strict_encode64("random-embedded-host"),
    embedded: "1", # attacker-controlled, bypasses validate_non_embedded_session entirely
  }

  assert_response :success
  # controller action now runs with @shop / installed_shop_session == victim's offline session,
  # despite the request never presenting any proof of controlling victim-shop.
end
```
Expected (buggy) result: request succeeds and `installed_shop_session`/`current_shopify_domain` resolve to `victim-shop.myshopify.com` purely from the query string, confirming the invariant "session must correspond to a proven shop owner" is violated for the whole class of `(shop=any installed domain, embedded="1")` inputs.

      def sanitize_shop_domain(shop_domain)
        uri = uri_from_shop_domain(shop_domain)
        return if uri.nil? || uri.host.nil?

        trusted_domains.each do |trusted_domain|
          no_shop_name_in_subdomain = uri.host == trusted_domain
          from_trusted_domain = trusted_domain == uri.domain

          return myshopify_domain_from_unified_admin(uri) if unified_admin?(uri) && from_trusted_domain
          return nil if no_shop_name_in_subdomain || uri.host&.empty?
          return uri.host if from_trusted_domain
        end
        nil
      end
