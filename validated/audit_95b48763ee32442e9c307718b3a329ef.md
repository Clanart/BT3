### Title
Git clone protection explicitly disabled during every clone, re-opening the CVE-2024-32002 symlinked-`.git`/hooks RCE for attacker-controlled repositories - (File: `app/src/lib/git/clone.ts`)

### Summary
The upstream report's broken invariant is: a fixed, "trusted" operation (`_autoStakeWithSyndicate` always staking exactly 12 ETH) is executed against a shared resource that an attacker can also manipulate (`Syndicate.stake`), and the code never re-validates that the operation is still safe/exclusive before trusting the fixed assumption, so attacker input corrupts the outcome. The Desktop analog is a case where Desktop's own clone code disables a safety invariant that Git itself enforces (protection against malicious repository/submodule layouts), trusting that the cloned content is safe by default when it is explicitly attacker-controlled.

### Finding Description
`clone()` in `app/src/lib/git/clone.ts` builds the environment for every `git clone` invocation and unconditionally forces: [1](#0-0) 

```
const env = {
    ...(await envForRemoteOperation(url)),
    GIT_CLONE_PROTECTION_ACTIVE: 'false',
}
...
const args = [
    '-c',
    `init.defaultBranch=${defaultBranch}`,
    'clone',
    '--recursive',
]
```

`GIT_CLONE_PROTECTION_ACTIVE` is the environment variable Git added as the runtime toggle for the protections that ship with the fix for the symlinked-`.git`/hooks clone vulnerability (the class of issue fixed as CVE-2024-32002/32004/32020/32021), which specifically defends against a cloned repository (or one of its recursively-cloned submodules) that contains a symlink or nested repository crafted so that, on checkout, Git ends up writing/executing content (e.g. hooks) outside the intended working directory. By setting this variable to `'false'` for every clone Desktop performs — combined with `--recursive`, which will also clone attacker-controlled submodule URLs — Desktop deliberately disables the exact guard that Git ships to stop this class of attack.

Because the URL being cloned is fully attacker-influenced (a user-entered clone URL, a deep-link "Open in Desktop"/`github-mac://openRepo/...` action routed through `openOrCloneRepository` in `dispatcher.ts`, or a forked/cloned repository's `.gitmodules` entries followed during `--recursive`), the invariant that "cloned content will not corrupt/execute outside the repo" is broken by attacker-supplied repository content, not by anything the local user does. [2](#0-1) 

Other clone-time defenses in the same file (`isClonePathSensitive`, the `--` argument separator) protect against a different attack (path traversal / argument injection at the CLI-argument level) and do nothing to compensate for the disabled `GIT_CLONE_PROTECTION_ACTIVE` guard, which operates at the Git-internal, checkout-time level.

### Impact Explanation
If Git's own protection is required to stop malicious repository content from writing files (via symlinked `.git` directories in submodules) or from installing/executing hooks during checkout, then forcing `GIT_CLONE_PROTECTION_ACTIVE=false` reintroduces that primitive for every user of Desktop who clones or "Open in Desktop"s any untrusted, attacker-controlled repository/fork/submodule tree — an unprivileged, remotely triggerable path (malicious repo the victim is lured to clone, or a crafted submodule reachable via `--recursive`). The consequence matches the "file write or read outside the repo" / "code execution" impact classes explicitly called out as valid.

### Likelihood Explanation
High: every single clone performed by Desktop (via the Clone dialog, CLI `github clone`, or the `x-github-client://openRepo/...` deep-link flow) passes through this same `clone()` function and always sets the flag, so there is no code path where the protection remains active. The only prerequisite is that the victim clones/opens a repository the attacker controls (or one that references an attacker-controlled submodule), which is exactly the kind of ordinary, expected user action ("clone this repo", "click Open in Desktop") that the valid-impact criteria treat as unprivileged.

### Recommendation
Remove the explicit `GIT_CLONE_PROTECTION_ACTIVE: 'false'` override (or set it to `'true'`/leave it unset so Git's default protection applies) unless there is a narrowly-scoped, already-trusted case (e.g., cloning a path the user explicitly selected as a known-safe local mirror) where it is provably safe to disable it. If the override exists to work around a specific compatibility issue, gate it behind an explicit, narrowly justified condition rather than applying it unconditionally to every clone, and add regression tests (mirroring `app/test/unit/git/clone-test.ts`) asserting the protection variable is not disabled for attacker-influenced/remote URLs.

### Proof of Concept
1. Attacker publishes a public repository containing a `.gitmodules` entry pointing at a nested submodule crafted per the CVE-2024-32002 pattern (a submodule whose working tree contains a symlink placed to alias the submodule's `.git`/hooks directory onto a location outside the intended repository root).
2. Attacker sends the victim a link such as `x-github-client://openRepo/https://github.com/attacker/evil-repo` or simply asks them to clone the URL in Desktop's Clone dialog.
3. Desktop routes the URL through `openOrCloneRepository` → `_clone` → `clone()` in `app/src/lib/git/clone.ts`, which runs `git -c init.defaultBranch=... clone --recursive -- <url> <path>` with `GIT_CLONE_PROTECTION_ACTIVE` forced to `'false'`.
4. Because the protection Git would normally apply during recursive submodule checkout is disabled, the crafted submodule's symlink/hook payload is written/executed during checkout, corrupting files or executing code outside the intended clone directory — without any local access, admin rights, or prior compromise on the victim's machine.

I was not able to find any in-repo comment or test explaining why `GIT_CLONE_PROTECTION_ACTIVE` is forced off, so I cannot rule out an intentional compatibility rationale; this should be confirmed with the Desktop maintainers before treating the recommendation as final.
