Based on my investigation, I found a genuine analog to the M-38 bug class in the `SmartWomConvert` contract, which handles automatic conversion of pooled WOM reward tokens (analogous to Derby's Compound/COMP reward selling).

### Title
Missing per-swap slippage protection and disabled deadline check in SmartWomConvert reward-token buyback swap - (File: wombat/SmartWomConvert.sol)

### Summary
`SmartWomConvert._convertFor` performs a Wombat router swap of pooled WOM (reward/deposit tokens) into mWOM with a hardcoded `minimumToAmount` of `0` and a `deadline` of `block.timestamp`, disabling both per-swap slippage protection and transaction-expiration protection, exactly the missing-deadline pattern described in M-38. [1](#0-0) 

### Finding Description
`_convertFor` splits an incoming WOM amount into `convertAmount` (deposited 1:1 into mWOM) and `buybackAmount` (swapped WOM→mWOM on the Wombat router). The router call passes `0` as the swap's own minimum-output parameter and `block.timestamp` as `deadline`, meaning the swap itself has no price protection and no expiration protection: [2](#0-1) 

The only protection is a post-swap aggregate check `convertAmount + amountRec < _minRec`, which reverts if the total across both legs is insufficient. [3](#0-2) 

This aggregate check does not protect the swap leg individually — when `convertRatio` routes a large share of funds to the 1:1 `convertAmount` deposit path (which always meets or exceeds its own value), the `amountRec` output of the sandwich-able swap can be driven down substantially by an attacker while the sum still clears `_minRec`. `smartConvert`, the entry point intended to be used automatically for pooled WOM rewards ("should mainly used by wombat staking upon sending wom"), is externally callable by any unprivileged wallet and computes `convertRatio` dynamically based on `currentRatio()` versus `buybackThreshold`. [4](#0-3) 

This mirrors the Derby M-38 root cause: a protocol-level function responsible for converting reward/pool tokens on Uniswap-style DEXs uses `block.timestamp` for `deadline`, which fully disables the expiration protection Uniswap/Wombat routers are meant to provide, and the swap's own slippage bound is set to `0`.

### Impact Explanation
Pooled WOM belonging to all depositors of a Wombat pool is converted through this vulnerable path when rewards accrue. A sandwich attacker (or a delayed-mining scenario during gas spikes) can extract value from the `buybackAmount` leg of the swap because the individual swap has no minimum-output enforcement and no real expiration bound, while the aggregate check can still pass. This results in depositors/gamers receiving less mWOM (yield) than the fair market price would provide — a theft of unclaimed/accrued yield shared across all pool depositors, not just the caller.

### Likelihood Explanation
`smartConvert` is externally callable without access control by any wallet, and is the documented mechanism for converting pooled WOM rewards, so the vulnerable code path executes routinely as part of normal reward processing, not merely under adversarial or privileged conditions. The precondition (mWOM trading below `buybackThreshold`) is a normal market state, not a rare edge case.

### Recommendation
Pass a real minimum-output value (not `0`) to the Wombat router's `swapExactTokensForTokens` call for the `buybackAmount` leg specifically, derived from an on-chain quote with an acceptable slippage tolerance, and set `deadline` to `block.timestamp + X` (a bounded window) rather than `block.timestamp`, so that the transaction cannot be executed at an arbitrarily degraded price and cannot linger indefinitely in the mempool without expiring.

### Proof of Concept
1. WOM accrues in `WombatStaking`/pool operations and is periodically routed through `SmartWomConvert.smartConvert`, which computes `convertRatio` such that a meaningful share of the WOM goes to the swap leg (`buybackAmount`).
2. An attacker observes the pending transaction (or mines-delay scenario) and sandwiches the Wombat router swap since `minimumToAmount = 0` provides no floor.
3. The attacker drives `amountRec` down while `convertAmount + amountRec` still clears `_minRec` (easier when `convertRatio` skews toward the safe `convertAmount` leg), extracting the difference as MEV profit.
4. Depositors collectively receive fewer mWOM tokens for their WOM rewards than fair-market conversion would yield. [5](#0-4)

    function smartConvert(uint256 _amountIn, uint256 _mode) external returns (uint256 obtainedmWomAmount) {
        if (_amountIn == 0) revert MustNoBeZero();

        uint256 convertRatio = DENOMINATOR;
        uint256 mWomToWom = currentRatio();

        if (mWomToWom < buybackThreshold) {
            uint256 maxSwap = maxSwapAmount();
            uint256 amountToSwap = _amountIn > maxSwap ? maxSwap : _amountIn;
            uint256 convertAmount = _amountIn - amountToSwap;
            convertRatio = convertAmount * DENOMINATOR / _amountIn;
        }

        return _convertFor(_amountIn, convertRatio, _amountIn, msg.sender, _mode);
    }

    function _convertFor(uint256 _amount, uint256 _convertRatio, uint256 _minRec, address _for, uint256 _mode)
        internal returns (uint256 obtainedmWomAmount) {

        if (_convertRatio > DENOMINATOR)
            revert IncorrectRatio();

        IERC20(wom).safeTransferFrom(msg.sender, address(this), _amount);
        uint256 buybackAmount = _amount - (_amount * _convertRatio / DENOMINATOR);
        uint256 convertAmount = _amount - buybackAmount;
        uint256 amountRec = 0;

        if (buybackAmount > 0) {
            address[] memory tokenPath = new address[](2);
            tokenPath[0] = wom;
            tokenPath[1] = mWom;
            address[] memory poolPath = new address[](1);
            poolPath[0] = womMWomPool;
        
            IERC20(wom).safeApprove(router, buybackAmount);
            amountRec = IWombatRouter(router).swapExactTokensForTokens(
                tokenPath, poolPath, buybackAmount, 0, address(this), block.timestamp
            );
        }

        if (convertAmount > 0) {
            IERC20(wom).safeApprove(mWom, convertAmount);
            IMWom(mWom).deposit(convertAmount);
        }

        if (convertAmount + amountRec < _minRec)
            revert MinRecNotMatch();

        obtainedmWomAmount = convertAmount + amountRec;

        if (_mode == 1) {
            IERC20(mWom).safeApprove(masterMagpie, obtainedmWomAmount);
            IMasterMagpie(masterMagpie).depositFor(mWom, obtainedmWomAmount, _for);
        } else if (_mode == 2) {
            IERC20(mWom).safeApprove(address(mWomSV), obtainedmWomAmount);
            mWomSV.lockFor(obtainedmWomAmount, _for);
        } else {
            IERC20(mWom).safeTransfer(_for, obtainedmWomAmount);
        }

        emit mWomConverted(_for, _amount, obtainedmWomAmount, _mode);
    }
