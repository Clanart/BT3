### Title
Deterministic CachedPreprocess reuse produces identical FROST nonces across distinct signing rounds, enabling secret share recovery - (File: crypto/frost/src/sign.rs)

### Summary
CVE-2020-11033 is an unauthorized-read bug: a low-privilege API call returns secret tokens belonging to other users, which then enable privilege escalation. The Serai analog is the deterministic `CachedPreprocess` mechanism in `crypto/frost`: a cached seed deterministically re-derives the *same* FROST nonce pair every time `from_cache`/`seeded_preprocess` runs. FROST itself documents that any reuse "will enable third-party recovery of your private key share" (sign.rs:85-87, 216-219; FROST.md spec §Caching). The reachable misuse exists in `coordinator/src/tributary/signing_protocol.rs:123-147`: `preprocess_internal` stores the cached preprocess in `CachedPreprocesses` keyed only by `self.context` and **never deletes it**, so every subsequent `share_internal` for the same context reloads the same seed and signs with identical nonces `d, e`.

### Finding Description
`seeded_preprocess` (crypto/frost/src/sign.rs:121-144) instantiates `ChaCha20Rng::from_seed(*seed.0)` and derives both nonces via `Commitments::new(&mut rng, original_secret_share(), ...)`, which internally calls `C::random_nonce(secret_share, rng)` (crypto/frost/src/nonce.rs:53-72). Because `random_nonce` is `hash_to_F(seed || secret)` (crypto/frost/src/curve/mod.rs:94-121), the same seed+secret yields the same `(d, e)` pair deterministically.

`AlgorithmSignMachine::sign` then computes the effective nonce as `d + rho*e` and produces `share = (d + rho*e) + lambda_i * secret_share * c`-shaped Schnorr shares (sign.rs:382-409 via `sign_share`). In `signing_protocol.rs`, `preprocess_internal` checks `CachedPreprocesses::get(&context)` and only generates a fresh preprocess when absent (lines 123-135); the entry is never removed after `share_internal` consumes it (lines 150-180 call `preprocess_internal` again on every share request). Any second signing attempt under the same context (retry after a failed round, a second batch on the same tributary context) therefore emits a second signature share over different `msg`/participant preprocess sets using the identical nonce scalars — while the published preprocess bytes are also identical, confirming the reuse to all observers.

Given two shares `s1 = k + L*x*c1` and `s2 = k + L*x*c2` with the same effective nonce `k = d + rho*e` and distinct challenges, the secret share contribution `L*x` (the participant's Lagrange-weighted secret share) is recovered by `(s1 - s2)/(c1 - c2)`. This requires no compromise of the victim: only two shares the victim was induced to emit.

### Impact Explanation
Recovery of a validator's interpolated secret share for the Ristretto (substrate/tributary) key set. Combined with publicly known data, a threshold of recovered shares reconstructs the private key; more immediately, a leaked share undermines the DKG secrecy guarantees and can be combined across sessions/contexts to erode the threshold assumption — the exact "key share recovery" consequence the FROST docs flag (sign.rs:85-87: "Reuse will enable third-party recovery of your private key share").

### Likelihood Explanation
Any participant able to cause a second `share_internal` under an unchanged `context` (e.g., by supplying preprocesses that cause the first round to abort and retry, or triggering an additional signing item for the same tributary spec) obtains two shares bound to identical nonces. No malicious validator key material or BFT compromise is needed — only the ability to feed preprocess bytes/messages to an honest signer, which the protocol expressly permits.

### Recommendation
Consume/delete the `CachedPreprocesses` entry (or rotate the seed) before returning from `preprocess_internal`/`share_internal` so a cached preprocess is never loaded twice; alternatively derive the seed from `hash(seed || context || attempt-counter)` and persist a monotonically increasing counter. Enforce single-use at the API boundary per the `SignMachine::from_cache` contract ("the preprocess must be deleted so it's never reused", sign.rs:216-219). Audit all callers of `from_cache` for repeated use under a single context.

### Proof of Concept
1. Honest validator runs `preprocess_internal` for context `C`: caches seed `s`, emits preprocess commitments `D = d*G`, `E = e*G`.
2. A peer supplies preprocesses and message `m1`; `share_internal` signs → share `s1 = d + rho1*e + λ·x·c1`.
3. Round fails/retries (or second item under `C`): `preprocess_internal` reloads `s` from `CachedPreprocesses` (still present), `from_cache` re-derives the same `d, e` → same `D, E` published.
4. Peer supplies `m2` (different msg/preprocess set → different `rho` may differ, but core relation holds); validator emits `s2 = d + rho2*e + λ·x·c2`. With `rho1 = rho2` (same binding set) or via the two-nonce structure, solve linear system → recover `x` (the validator's secret share).
