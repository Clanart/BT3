### Title
Consensus reward misattribution lets an attacker steal other relayers' `pallet-consensus-incentives` payouts by batching multiple consensus messages under one signer - ([File: modules/pallets/consensus-incentives/src/impls.rs])

### Summary
`FeeHandler::on_executed` in `pallet-consensus-incentives` determines the relayer to be rewarded solely from `messages.get(0)` and then pays that single account for *every* `StateMachineUpdated` event produced anywhere in the entire batch, even when the batch contains multiple, independently-signed `Consensus` messages for different state machines. [1](#0-0) 

### Finding Description
`pallet_ismp::Pallet::handle_unsigned` is a permissionless, unsigned extrinsic (`ensure_none`) that accepts an arbitrary `Vec<Message>` from anyone, executes every message, and passes the resulting `messages_with_weights` and `events` to `T::FeeHandler::on_executed` as one batch. [2](#0-1) [3](#0-2) 

Each `Consensus` message carries its own embedded relayer signature (`signer` field, verified against the keccak of `consensus_proof`), which is the mechanism that is supposed to attribute the reward to whoever actually produced/delivered that specific consensus update. [4](#0-3) 

However, `on_executed` only recovers a relayer identity from **the first message in the batch** (`messages.get(0)`), and then loops over *all* `StateMachineUpdated` events collapsed from the entire batch (across all state machines), crediting every one of them to that single recovered relayer:
```rust
let maybe_relayer_account = messages.get(0).and_then(|first_message| { ... });
...
for (state_machine_id, latest_height) in highest_per_state_machine {
    let _ = Self::process_message(state_machine_height, state_machine_id, relayer_account.clone().into());
}
``` [5](#0-4) 

Because `handle_unsigned` accepts a `Vec<Message>` from any submitter with no requirement that every message in the batch be signed by the same relayer, an attacker can:
1. Take a validly-signed `Consensus` message that a different, honest relayer already produced (consensus proofs and their embedded relayer signatures are public — they are broadcast in the mempool / observable on-chain — nothing about the signature binds it to the transaction submitter or prevents re-submission alongside other messages).
2. Prepend the attacker's own signed `Consensus` message (for a cheap/any state machine) as `messages[0]`.
3. Submit `vec![attacker_msg, victim_msg_1, victim_msg_2, ...]` via `handle_unsigned`.

Every `StateMachineUpdated` event generated by the victims' messages is credited to the attacker's account (position-0 signer), because `calculate_reward`/`process_message` never checks which message actually produced which event — it only tracks a `LastRewardedHeight` watermark per state machine and pays whoever `on_executed` decided is "the relayer" for the whole call. [6](#0-5) [7](#0-6) 

The `LastRewardedHeight` watermark logic itself is a genuinely fixed version of the RLQ-1-style pattern (it explicitly guards against double-paying the same height span more than once via `saturating_sub` from a monotonic watermark), but that fix does not address *who* gets paid — it only bounds the amount. The `messages.get(0)` shortcut for the relayer identity is the actual analog of "distributing rewards based on the wrong actor's state" from the report: exactly as `userB`'s frequent updates in RLQ-1 let them capture rewards that should have been split, here the batch-submitter captures a legitimate relayer's entire reward for a state machine they did not deliver the message for.

### Impact Explanation
This directly causes loss/misdirection of protocol treasury funds and reputation-asset mints: `T::Currency::transfer` moves real `BRIDGE`/native balance from the treasury account to the wrong beneficiary, and `T::ReputationAsset::mint_into` mints reputation to the wrong account. [8](#0-7) 
This is a "wrong beneficiary" fund-movement bug against the treasury, matching the bounty's in-scope class (unauthorized transaction/execution causing funds to move to the wrong party), and requires no relayer/prover/admin collusion — only an unprivileged party observing public mempool/chain data and resubmitting it in a crafted batch.

### Likelihood Explanation
`handle_unsigned` is explicitly documented as "an unsigned extrinsic that permits anyone execute ISMP messages for free," so front-running/repackaging another party's already-valid message is a normal, expected capability of the interface, not a privileged action. [9](#0-8) 
Any relayer competing for consensus-incentive rewards has direct financial incentive to grab a low position-0 slot and append other relayers' pending consensus messages once observed, so this is realistically exploitable whenever more than one relayer is delivering consensus updates for different state machines around the same time.

### Recommendation
In `on_executed`, recover the signer independently for each `Consensus` message in the batch and attribute each `StateMachineUpdated` event to the signer of the specific message that produced it (e.g., match consensus messages to the state machine/consensus_state_id they update, rather than defaulting to `messages.get(0)`), instead of using a single batch-wide relayer identity.

### Proof of Concept
1. Relayer A observes on the network (mempool or a recently included block) a valid `Message::Consensus` for `state_machine_id = X`, correctly signed by A, ready to be included via `handle_unsigned`.
2. Attacker B crafts their own trivial/cheap `Message::Consensus` for `state_machine_id = Y` (or reuses any minimal valid consensus proof they control), signs it themselves.
3. Attacker B submits `pallet_ismp::handle_unsigned(origin: None, messages: vec![B_message_for_Y, A_message_for_X])`.
4. `Pallet::execute` processes both messages successfully, producing two `StateMachineUpdated` events (for X and Y).
5. `on_executed` recovers the relayer only from `messages[0]` = B's signature, then iterates `highest_per_state_machine` covering both X and Y, calling `process_message` with `relayer_account = B` for both.
6. B is paid the treasury reward for advancing state machine X, a consensus update they did not produce/sign — the reward due to A is instead transferred to B's account and reputation is minted to B. [1](#0-0)

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}

	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

		let message_results = messages
			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		let messages_with_weights = message_results
			.iter()
			.zip(messages)
			.map(|(result, message)| MessageWithWeight { message, weight: result.weight() })
			.collect::<Vec<_>>();

		let events = message_results
			.into_iter()
			// check that requests will be successfully dispatched
			// so we can not be spammed with failing txs
			.map(|result| match result {
				MessageResult::Request { events, .. } |
				MessageResult::Response { events, .. } |
				MessageResult::Timeout { events, .. } => events,
				MessageResult::ConsensusMessage(events) => events.into_iter().map(Ok).collect(),
				MessageResult::FrozenClient(_) => vec![],
			})
			.flatten()
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		T::FeeHandler::on_executed(messages_with_weights, events.clone())
			.map_err(|_| Error::<T>::ErrorChargingFee)?;
