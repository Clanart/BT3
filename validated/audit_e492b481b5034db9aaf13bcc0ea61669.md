### Title
Aggregate Schnorr verifier derives weights without binding the nonce points `Rs` or keys, enabling universal forgery of `SchnorrAggregate` - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::verify` computes the aggregation weights `z_i` via `weight()` from a transcript that only absorbs the per-signature `challenge` scalars (aggregate.rs:132-136). The `Rs` supplied inside the attacker-controlled `SchnorrAggregate` and the public keys are never hashed into the weight transcript. In the ePrint 2021/350 half-aggregation scheme this implementation cites, the weights must be bound to the full statement (all `R_i`, keys, and challenges), otherwise the weights are predictable before `Rs` are chosen and the linear verification equation collapses to a single solvable constraint.

### Finding Description
The verification equation is:

```
sum_i ( z_i * R_i ) + sum_i ( z_i * c_i * A_i ) - s*G == 0
```

where `A_i` are public keys, `c_i` challenges, `z_i` weights from `weight(&mut digest)`, and `R_i`, `s` come from `SchnorrAggregate::read` / attacker construction. Since `digest` only contains `dst`, the `"signatures"` domain separator, and the challenges, an attacker who knows the `(key, challenge)` list can compute every `z_i` before choosing any `R_i` or `s`. The equation has `n+1` free attacker values (`R_1..R_n`, `s`) and only one constraint. The forger picks arbitrary `s` and `R_1..R_{n-1}`, then solves for `R_n`:

```
R_n = z_n^{-1} * ( s*G - sum_{i<n} z_i*R_i - sum_i z_i*c_i*A_i )
```

Scalar inversion modulo the group order makes this trivially computable. `SchnorrAggregator::complete` mirrors the same flaw — it appends only `challenge` to the digest (aggregate.rs:170) and never the signature's `R`, so honestly produced aggregates are computed under the same weak weight derivation. This is the same bug class as the Inverse Finance incident: a critical value (oracle price / aggregation weight) derived from inputs that omit the adversary-controllable terms it is supposed to bind.

### Impact Explanation
Any verifier accepting `SchnorrAggregate::verify` accepts a forged aggregate attesting to `n` Schnorr signatures under arbitrary public keys and challenges, with zero knowledge of any private key. This is a complete forgery of the aggregated signature primitive, reachable entirely from untrusted bytes via `SchnorrAggregate::read` (aggregate.rs:77-88).

### Likelihood Explanation
Exploitation requires only public inputs: the `(key, challenge)` pairs being verified. The attacker performs a handful of scalar multiplications and one scalar inversion — no threshold cooperation, no malicious validator, no key leakage. If any in-scope consumer verifies aggregates over attacker-supplied `Rs`, forgery is deterministic.

### Recommendation
Bind the full aggregate statement into the weight transcript: before deriving each `z_i`, append every `R_i` (and ideally each public key) to the digest, e.g. `digest.append_message(b"R", R.to_bytes())` and `digest.append_message(b"key", key.to_bytes())` in both `verify` and `SchnorrAggregator::aggregate`/`complete`, matching the Fiat–Shamir binding required by ePrint 2021/350.

### Proof of Concept
```rust
// For targets (A_i, c_i) known to the verifier:
let mut digest = DigestTranscript::<C::H>::new(dst);
digest.domain_separate(b"signatures");
for (_, c) in &keys_and_challenges { digest.append_message(b"challenge", c.to_repr()); }

// z_i are all known now, before choosing Rs
let zs: Vec<C::F> = (0..n).map(|_| weight(&mut digest)).collect();

// Pick arbitrary s and R_1..R_{n-1}; solve for R_n
let mut acc = C::generator() * s;
for i in 0..n-1 { acc -= Rs[i] * zs[i]; }
for (i, (A, c)) in keys_and_challenges.iter().enumerate() {
  acc -= *A * (zs[i] * c);
}
let R_n = acc * zs[n-1].invert().unwrap(); // scalar inverse mod group order

  pub fn verify(&self, dst: &'static [u8], keys_and_challenges: &[(C::G, C::F)]) -> bool {
    if self.Rs.len() != keys_and_challenges.len() {
      return false;
    }

    let mut digest = DigestTranscript::<C::H>::new(dst);
    digest.domain_separate(b"signatures");
    for (_, challenge) in keys_and_challenges {
      digest.append_message(b"challenge", challenge.to_repr());
    }

    let mut pairs = Vec::with_capacity((2 * keys_and_challenges.len()) + 1);
    for (i, (key, challenge)) in keys_and_challenges.iter().enumerate() {
      let z = weight(&mut digest);
      pairs.push((z, self.Rs[i]));
      pairs.push((z * challenge, *key));
    }
    pairs.push((-self.s, C::generator()));
    multiexp_vartime(&pairs).is_identity().into()
  }

  pub fn aggregate(&mut self, challenge: C::F, sig: SchnorrSignature<C>) {
    self.digest.append_message(b"challenge", challenge.to_repr());
    self.sigs.push(sig);
  }

  /// Complete aggregation, returning None if none were aggregated.
  pub fn complete(mut self) -> Option<SchnorrAggregate<C>> {
    if self.sigs.is_empty() {
      return None;
    }

    let mut aggregate = SchnorrAggregate { Rs: Vec::with_capacity(self.sigs.len()), s: C::F::ZERO };
    for i in 0 .. self.sigs.len() {
      aggregate.Rs.push(self.sigs[i].R);
      aggregate.s += self.sigs[i].s * weight::<_, C::F>(&mut self.digest);
    }
    Some(aggregate)
  }
