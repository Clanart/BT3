The reported bug class depends on an ERC20-style external token contract silently deducting a transfer tax on `transferFrom`, causing a lending protocol's internal accounting (amount lent vs. amount received) to diverge from actual token balance. Chia has no analogous mechanism reachable by an unprivileged submitter:

- CATs are not external contracts invoked via `transferFrom`; they are native coins whose supply conservation is enforced directly by the `CAT_MOD` consensus puzzle, which requires the sum of input amounts to equal the sum of output amounts (ring/subtotal structure) for the same asset ID, with any deviation requiring TAIL-authorized mint/melt via the `-113` condition and `extra_delta` [1](#0-0) .
- There is no "tax deduction" hook — a coin spend either satisfies the puzzle's exact accounting or the spend bundle is rejected at consensus/mempool validation, so there is no path where a contract "expects" one amount but "receives" a smaller one due to a third-party fee, as seen in `do_spend` test helper for CAT lifecycle [2](#0-1) .
- Royalty payments in NFT offers, which superficially resemble a "percentage taken on transfer," are computed and enforced puzzle-side via `compute_royalty_amount`/`royalty_calculation` and asserted via puzzle announcements — the payer's own transaction constructs and asserts these amounts up front, not an opaque third-party deduction post-transfer [3](#0-2) [4](#0-3) .

Since Chia's coin/CAT model enforces exact conservation at the consensus layer rather than relying on trusting an external contract's transfer return amount, there is no reachable analog to the "fee-on-transfer breaks accounting, funds get stuck" bug class within the allowed attack surface (spend bundle submission, offers, CAT/CR-CAT flow, NFT royalties).

def compute_royalty_amount(offered_amount: int, royalty_split: int, percentage: int) -> uint64:
    """Compute royalty using integer arithmetic, validating against overflow and excessive percentage."""
    if percentage > MAX_ROYALTY_BASIS_POINTS:
        raise ValueError(f"NFT royalty percentage {percentage} exceeds 100% ({MAX_ROYALTY_BASIS_POINTS} basis points)")
    amount = abs(offered_amount) // royalty_split * percentage // MAX_ROYALTY_BASIS_POINTS
    royalty = uint64(amount)
    if royalty >= abs(offered_amount):
        raise ValueError("Royalty amount meets or exceeds the offered amount")
    return royalty
