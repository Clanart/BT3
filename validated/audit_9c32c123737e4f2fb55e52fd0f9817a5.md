## Finding: SSRF Analog in Chia DataLayer Mirror/Subscription Mechanism

The Jenkins Git Plugin SSRF (CVE-2018-1000182) is a case where a user-supplied URL is used by server code to issue an outbound GET request without restriction. Chia's DataLayer mirror/subscription mechanism has a directly analogous, reachable SSRF primitive.

### Title
Arbitrary Mirror URLs Published for Any Store ID Drive Unrestricted Outbound HTTP GET Requests (SSRF) - (File: chia/data_layer/download_data.py)

### Summary
Any wallet user can create an on-chain "mirror" coin advertising arbitrary URLs for **any** DataLayer store id — not just stores they own — via `create_new_mirror()`. Other DataLayer nodes that subscribe to that store id will later read these URLs from wallet state and issue unauthenticated outbound HTTP GET requests to them via `http_download()`, with no scheme restriction, no private/loopback address filtering, and no ownership binding between the URL publisher and the store id.

### Finding Description
`DataLayerWallet.create_new_mirror()` builds and signs a standard coin spend embedding `launcher_id` and arbitrary `urls` as memos with no check that `launcher_id` is a store owned by the calling wallet: [1](#0-0) 

This is exposed directly over wallet RPC (`dl_new_mirror`), which passes the caller-supplied `launcher_id` and `urls` straight through without validating ownership or URL shape: [2](#0-1) 

On the consuming side, `DataLayer.get_mirrors()` / `update_subscriptions_from_wallet()` pull all mirror URLs registered for a store id — regardless of who published them — and persist them as subscription server candidates: [3](#0-2) 

`fetch_and_validate()` then iterates these server URLs and calls `insert_from_delta_file()` → `download_file()` → `http_download()`: [4](#0-3) 

`http_download()` performs an unrestricted `aiohttp` GET to `server_info.url + "/" + filename` with no scheme allow-list, no DNS/IP validation, and no protection against internal/loopback/link-local targets (e.g. cloud metadata endpoints, internal admin services): [5](#0-4) 

The project's own module notes acknowledge mirror URLs are untrusted external input, but the mitigation described is limited to validating *downloaded content* against the wallet root — not validating or restricting the *destination* of the outbound request itself: [6](#0-5) 

### Impact Explanation
Any wallet holder able to submit a spend bundle (minimal fee, minimal mirror amount, even `0`) can force every DataLayer node that later subscribes to the targeted store id — including nodes it does not control — to issue outbound HTTP requests to attacker-chosen destinations. This can be used to probe/attack internal network services reachable from the DataLayer host (e.g. cloud metadata services, internal RPC/admin endpoints, other localhost-bound services), or as a request-forgery/pivot primitive. Because the mirror is not bound to ownership of the store id, an attacker can target any store id in use by other participants, not just their own.

### Likelihood Explanation
The mirror-publish path only requires a standard signed coin spend (`create_mirror_puzzle()` output with memos) reaching mempool acceptance — well within reach of an ordinary wallet user with no special privilege. The victim path (subscribing to a store and running `periodically_manage_data()`) is standard DataLayer operation for anyone who subscribes to that store to replicate data, making exploitation practical whenever a targeted node subscribes to an attacker-poisoned store id.

### Recommendation
- Bind mirror creation to store ownership, or explicitly document/enforce that mirrors are informational-only and require URL/destination validation before use.
- In `http_download()`/`download_file()`, restrict outbound requests to `http`/`https` schemes and reject requests resolving to loopback, link-local, and other private/internal IP ranges (SSRF-safe HTTP client pattern), consistent with treatment of untrusted external endpoints.
- Consider requiring explicit local operator opt-in (e.g. an allow-list) before mirror URLs discovered via wallet state are used for automatic downloads, rather than trusting all on-chain-advertised mirrors implicitly.

### Proof of Concept
1. Attacker wallet calls `dl_new_mirror` RPC (or `chia data add_mirror`) with an arbitrary `store_id` belonging to a victim/target store and `urls=["http://169.254.169.254/latest/meta-data/"]` (or any internal address), paying a small fee/mirror amount.
2. Transaction confirms on chain, creating a `Mirror` coin for that `store_id`.
3. Any node subscribed to that `store_id` runs `periodically_manage_data()` → `update_subscription()` → `update_subscriptions_from_wallet()`, pulling the attacker's URL into its subscriptions table.
4. `fetch_and_validate()` → `insert_from_delta_file()` → `download_file()` → `http_download()` issues an outbound `GET` to the attacker-controlled/internal URL from the victim's DataLayer process, per `chia/data_layer/download_data.py:298-324`.

```python
                action_scope,
                fee=request.fee,
                extra_conditions=extra_conditions,
            )

        # tx_endpoint will take care of default values here
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
