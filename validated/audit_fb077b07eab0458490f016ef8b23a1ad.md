### Title
`Scanner` reports zero/dust-valued outputs as spendable `ReceivedOutput`s, causing net-loss fee burn when later spent - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
Analogous to Surge's `Pool.repay()` accepting an `amount` that converts to zero burned shares (tokens taken, no debt reduced), Serai's `Scanner::scan_transaction` matches outputs purely by `script_pubkey` and emits a `ReceivedOutput` for *any* value — including 0 and sub-dust values. Such outputs are then consumed by `SignableTransaction::new`, which never checks that an input's value covers the marginal fee cost of spending it. The result is the same shape: a transfer accepted and acted upon whose effective contribution is zero (or negative), while real satoshis are burned as extra fee.

### Finding Description
`Scanner::scan_transaction` pushes a `ReceivedOutput` whenever `self.scripts.get(&output.script_pubkey)` matches, with no check on `output.value` [1](#0-0) . `ReceivedOutput` faithfully stores the value, and `value()` exposes it, but nothing in the wallet crate enforces a minimum [2](#0-1) .

Downstream, `SignableTransaction::new` sums `input_sat` from every supplied `ReceivedOutput` and builds a `TxIn` per input [3](#0-2) . Each `TxIn` adds ~57.5 vbytes of weight to the transaction via `calculate_weight_vbytes` [4](#0-3) . There is a `DustPayment` check for *payments* [5](#0-4)  and a dust gate for *change* [6](#0-5) , but no check that an *input* is worth more than the fee paid to spend it. The processor-side DUST filter (`output.balance().amount.0 >= N::DUST`) exists only in `processor/src/multisigs/scanner.rs` [7](#0-6) ; consumers of `bitcoin-serai`'s `Scanner`/`scan_block` directly — including `scan_block`, which even surfaces coinbase outputs — receive unfiltered results [8](#0-7) .

### Impact Explanation
An unprivileged party who learns a registered script (any deposit/branch/change address derived from `key + offset·G`, all on-chain-visible P2TR scripts) can send outputs of value 0 or value below the marginal spend cost (~58 vbytes × fee rate) to that script. The scanner reports them as received funds. When the wallet later includes them as inputs, `needed_fee`/`fee()` increases by more than the input contributes, so the transaction's effective fee (`sum(inputs) - sum(outputs)`) silently inflates [9](#0-8) . Funds are reported received that are economically unspendable, and spending them burns real balance as fee — the direct analog of losing loan tokens while burning zero debt shares.

### Likelihood Explanation
Any third party can craft dust/zero outputs to a known P2TR script at negligible cost (one dust output per UTXO). It requires the wallet to auto-consume scanned outputs without an external dust filter — which is precisely the library's exposed behavior for `bitcoin-serai` consumers; only the Serai processor adds the missing `N::DUST` gate on top.

### Recommendation
- In `Scanner::scan_transaction`/`scan_block`, skip outputs with `output.value.to_sat() < DUST` (or a configurable minimum), so unscannable-value outputs are never reported as `ReceivedOutput`.
- In `SignableTransaction::new`, reject or skip inputs whose value is below the marginal fee cost of one Taproot input (`fee_per_vbyte * ~57.5` vbytes), analogous to requiring `_shares > 0` before taking the user's tokens.

### Proof of Concept
1. `Scanner::new(key)` then `register_offset(offset)` → attacker sends a tx with `TxOut { value: 0, script_pubkey: <offset script> }` (consensus-valid, though non-standard) or `value: 300` (< 546 dust and below marginal fee cost).
2. `scanner.scan_transaction(&tx)` returns a `ReceivedOutput` with `value() == 300`.
3. `SignableTransaction::new(vec![dust_output, real_output], &payments, change, None, fee)` succeeds; the dust input adds ~58·fee sats to the fee while contributing 300 — net loss of `58·fee − 300` burned to miners, invisible to `needed_fee()` accounting per input.
4. Worse, a `ReceivedOutput` with `value: 0` is accepted by `TxOut::consensus_decode` in `ReceivedOutput::read` and consumed identically. [10](#0-9)

```rust
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
```
