Based on my investigation, I found a strong analog to the reported PHP `php_jpg_get16` buffer over-read.

### Title
Unbounded buffer read in `is_atom_canonical`/`is_clvm_canonical` allows a crafted spend bundle to trigger an unhandled exception during mempool transaction admission - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_atom_canonical()` and `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` parse the raw CLVM byte serialization of a coin's `puzzle_reveal` and `solution` to decide whether the encoding is "canonical" (required for dedup-eligible mempool acceptance). Both functions index directly into the attacker-supplied `bytes` buffer using a length-prefix-derived offset without ever checking that the offset stays within the buffer bounds, mirroring the underlying flaw class in `php_jpg_get16` (reading past the end of a buffer based on an attacker-controlled length field with no bounds check). [1](#0-0) [2](#0-1) 

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads `clvm_buffer[offset]` to get a length-prefix byte, then loops `prefix_len` times (up to 5 extra bytes) doing `offset += 1; atom_len |= clvm_buffer[offset]` — with no check that `offset < len(clvm_buffer)` at any point in the loop: [3](#0-2) 

`is_clvm_canonical(clvm_buffer)` similarly walks the buffer in a `while True:` loop, unconditionally reading `clvm_buffer[offset]` and incrementing `offset` on every branch (pair `0xFF`, back-reference `0xFE`, small atom, or calling `is_atom_canonical`), without ever validating that `offset` remains inside the buffer before the next read: [4](#0-3) 

Both functions are invoked directly on attacker-controlled bytes from every coin spend in a submitted `SpendBundle`, inside `MempoolManager.validate_spend_bundle()`, which runs during ordinary mempool admission of any transaction (`push_tx` RPC, wallet `send_transaction`, or peer `respond_transaction`): [5](#0-4) 

A crafted `puzzle_reveal` or `solution` can end exactly at a byte that begins a multi-byte atom-length prefix (e.g., a trailing `0xFC` byte, which signals a 5-extra-byte length prefix) with no further bytes present. This causes `clvm_buffer[offset]` to run off the end of the buffer, raising an unhandled `IndexError` inside `is_atom_canonical`/`is_clvm_canonical`. Existing unit tests confirm the shape of these non-canonical/malformed encodings is a first-class test surface (`test_clvm_not_canonical`, `test_atom_not_canonical`), but none of the existing parametrized cases exercise a buffer that is *too short* for its own declared prefix length — only cases where the buffer is long enough but the encoding itself is non-canonical: [6](#0-5) 

### Impact Explanation
Tracing the call path, `validate_spend_bundle()` is called from `MempoolManager.add_spend_bundle()`, which is invoked directly (with no surrounding `try/except`) from `FullNode.add_transaction()`: [7](#0-6) 

`add_transaction()` only catches `ValueError` and `ValidationError` around the earlier `pre_validate_spendbundle()` call, but there is no exception handling wrapped around the later `add_spend_bundle()` call where `is_clvm_canonical` executes: [8](#0-7) 

However, callers further up the stack (`_handle_one_transaction`, `respond_transaction`) do catch generic `Exception`, so an unhandled `IndexError` from a crafted spend bundle would be caught, logged, and (per `_handle_one_transaction`) result in banning/closing the connection of the peer/caller that submitted it, rather than crashing the node: [9](#0-8) 

For the RPC path (`push_tx`), the exception would propagate as an unhandled 500-style error from `add_transaction`, since `full_node_rpc_api.py`'s `push_tx` has no local exception handling around `self.service.add_transaction(...)`: [10](#0-9) 

Because Python raises a normal `IndexError` (not a native memory-safety violation) when indexing past the end of a `bytes` object, this issue does **not** reproduce the "information disclosure" impact of the original CVE-2019-11040 (which read adjacent heap memory in C). The realistic impact here is limited to a single spend bundle failing to validate with an unhandled exception rather than a graceful `INVALID_COIN_SOLUTION` rejection — a localized processing fault for that one transaction, not consensus corruption, fund theft, or a broader mempool/node halt, since callers with broad exception handling exist at multiple levels in the transaction-processing pipeline.

### Likelihood Explanation
Any unprivileged party who can submit a spend bundle (via RPC `push_tx`, wallet `send_transaction`, or as a peer sending `respond_transaction`) can trivially construct a `puzzle_reveal` or `solution` whose final byte is a CLVM atom length-prefix byte (e.g., `0xC0`–`0xFF` family) with insufficient trailing bytes to satisfy the declared prefix length, triggering the out-of-bounds index during canonical-serialization checking. This requires no special access and is a pure single-spend-bundle-submission trigger.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before each `clvm_buffer[offset]` access (raising a `ValueError`/returning "not canonical" instead of indexing out of range), and similarly bound-check `offset` in `is_clvm_canonical()`'s main loop before dereferencing `clvm_buffer[offset]`, consistent with the defensive length checks already used elsewhere in this codebase (e.g., `chia/full_node/full_block_utils.py`'s `skip_bytes`/`skip_list`, which explicitly raise descriptive `ValueError`s when a declared length exceeds the remaining buffer). [11](#0-10) 

### Proof of Concept
Construct a `puzzle_reveal` (or `solution`) whose bytes are, e.g., `b"\xfc"` alone (a 6-byte-prefix atom marker with zero trailing bytes) or `b"\xff\xfc"` (a pair introducing a nested atom whose length-prefix marker has no trailing bytes). Submit a `SpendBundle` containing a coin spend using this puzzle/solution via `push_tx`. During `MempoolManager.validate_spend_bundle()`, `is_clvm_canonical(bytes(coin_spend.puzzle_reveal))` will invoke `is_atom_canonical(clvm_buffer, offset)`, which executes `atom_len |= clvm_buffer[offset]` past the end of the buffer, raising an unhandled `IndexError` instead of the expected `Err.INVALID_COIN_SOLUTION` rejection path that the existing `test_mempool_requires_canonical_clvm` test expects for other malformed-but-in-bounds encodings. [12](#0-11)

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
