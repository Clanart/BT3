### Title
Missing timestamp/freshness validation in App Proxy signature verification enables replay of valid signed requests - (File: `lib/shopify_app/controller_concerns/app_proxy_verification.rb`)

### Summary
`ShopifyApp::AppProxyVerification#query_string_valid?` validates only that the HMAC signature over the query-string parameters matches the app's shared secret. It never checks that the `timestamp` parameter (which Shopify includes in every app proxy request) is recent, so a previously valid, correctly-signed app proxy request can be captured and replayed indefinitely and will still be accepted as authentic.

### Finding Description
Shopify signs app proxy requests forwarded from a shop's storefront to the app, including a `timestamp` query parameter meant to bound the validity window of the signature. `query_string_valid?` in `lib/shopify_app/controller_concerns/app_proxy_verification.rb` only recomputes the HMAC over the sorted query parameters (including `timestamp` as just another signed field) and compares it to the supplied `signature`: [1](#0-0) [2](#0-1) 

There is no code anywhere in `verify_proxy_request` or `query_string_valid?` that reads `query_hash["timestamp"]` and rejects the request if it is older than some acceptable window. Because the signature is a deterministic function of the query parameters and the shared secret, any request that was ever validly signed by Shopify (e.g., one observed via browser history, server logs, a referrer header, a shared/bookmarked URL, or network capture) remains permanently "valid" and will pass verification no matter how much time has elapsed. This is directly analogous to the reported chain-id replay issue: a signed message lacking a scope/freshness binding can be replayed outside its intended context (there, across chains; here, across time) and still be accepted as authentic.

### Impact Explanation
An attacker who obtains a single previously-issued, validly-signed app proxy request URL (no special privileges required — it can be leaked via logs, referrers, or a shared link) can resend it to the app's app-proxy endpoint at any later time and have it accepted as a genuine, freshly-signed request from that shop's storefront. This constitutes acceptance of a forged/replayed signed request, undermining the integrity guarantee the app proxy signature is supposed to provide, and can lead to unauthorized state changes or data disclosure depending on what the app's proxy controller does with the (attacker-controlled, but signature-validated) parameters.

### Likelihood Explanation
Exploitation requires only that an attacker obtain one previously valid signed proxy query string — no secret key, no cross-shop trust violation, and no authentication bypass beyond replay is needed. Proxy URLs frequently appear in browser history, third-party analytics/referrer headers, and server access logs, making capture plausible in normal operation.

### Recommendation
Add an explicit freshness check on the `timestamp` parameter in `query_string_valid?` (e.g., reject if `Time.now.to_i - timestamp.to_i` exceeds a small tolerance, such as a few minutes), consistent with Shopify's documented app proxy verification guidance, before or in addition to the HMAC comparison.

### Proof of Concept
1. A legitimate app-proxy request is issued by Shopify to the app, e.g.:
   `GET /apps/my-app?shop=some-shop.myshopify.com&path_prefix=%2Fapps%2Fmy-app&timestamp=1466106083&signature=<valid_hmac>`
2. An attacker captures this exact URL (e.g., from a log file, browser history, or referrer header) at some point after the original request time.
3. At an arbitrary later time, the attacker replays the identical URL/query string to the app's endpoint protected by `ShopifyApp::AppProxyVerification`.
4. `query_string_valid?` recomputes the HMAC over the same (unchanged) query parameters and it still matches `signature`, per [1](#0-0) , so `verify_proxy_request` allows the request through with no `head(:forbidden)` — confirming the request is accepted as authentic despite being an old, replayed request.

```ruby
    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end
```

```ruby
    def calculated_signature(query_hash_without_signature)
      sorted_params = query_hash_without_signature.collect { |k, v| "#{k}=#{Array(v).join(",")}" }.sort.join

      OpenSSL::HMAC.hexdigest(
        OpenSSL::Digest.new("sha256"),
        ShopifyApp.configuration.secret,
        sorted_params,
      )
    end
```
