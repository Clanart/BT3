### Title
Forged `WWW-Authenticate` header from a malicious git remote spoofs Desktop's GitHub-host classification, triggering an unintended Enterprise sign-in against an attacker-controlled endpoint - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The reported Crestal bug is a "confused caller" issue: `payWithERC20` trusts caller-supplied identity data (`fromAddress`) instead of verifying that the invocation actually originates from the party it should, letting anyone pull funds from any account that has merely granted approval. The GitHub Desktop analog is a similarly misplaced trust decision in the Git credential-helper trampoline: `getEndpointKind` in [1](#0-0)  classifies a completely untrusted, attacker-supplied HTTP response header as authoritative proof that a remote is a "GitHub" host, which then causes Desktop to launch its GitHub sign-in flow against that attacker-controlled endpoint.

### Finding Description
When Git performs an HTTP(S) operation (clone/fetch/push, including for submodules or LFS remotes) against a server that returns `401` with a `WWW-Authenticate: Basic realm="GitHub"` header, Git forwards that header to Desktop's credential helper as a `wwwauth[]` credential field. `getEndpointKind` treats this attacker-controlled string as ground truth: [2](#0-1) 

If the realm contains `GitHub`, the host is classified `'enterprise'` even though it has no relationship to `isDotCom`/`isGHE`/`isGitHubHost` checks and no existing stored account. `getCredential` then acts on that classification: [3](#0-2) 

Because no account matches `apiEndpoint` (the attacker's own host), `ui.promptForGitHubSignIn(endpoint)` is invoked automatically, mid-Git-operation, with `endpoint` pointing at the attacker's server: [4](#0-3) 

Since the spoofed host is not literally `github.com`, this calls `dispatcher.beginEnterpriseSignIn(cb)` followed by `dispatcher.setSignInEndpoint(origin)` — bypassing the normal manual "enter your GHE server URL" step (`SignInStep.EndpointEntry`) entirely, jumping straight into `SignInStep.Authentication` with the endpoint preset to the attacker's origin: [5](#0-4) [6](#0-5) 

If the user proceeds with "sign in with browser," `authenticateWithBrowser` opens the system browser to `getOAuthAuthorizationURL(endpoint, csrfToken)` — an OAuth authorize URL built from the attacker's own host, not github.com: [7](#0-6) 

The corrupted value is the `endpoint` string passed through `getCredentialUrl(cred)` → `getEndpointKind` → `promptForGitHubSignIn` → `setSignInEndpoint`: it originates from data the remote server controls (its response headers), yet is treated with the same trust as a locally verified GitHub/GHE endpoint. Existing guards (`isDotCom`, `isGHE`, `isGist`, `isGitHubHost` via an actual API probe) are all bypassed by the `wwwauth[]` fast path, which exists purely as a heuristic to avoid an extra network round trip and does not authenticate the header's origin in any way.

### Impact Explanation
A hostile git remote (or a compromised/MITM'd proxy in front of one) can silently steer a victim into what looks like GitHub Desktop's native "Sign in to GitHub" flow for an Enterprise account, with the target host fully attacker-controlled. If the user completes the browser-based OAuth step, they land on a page served by the attacker at the attacker's domain, which can visually impersonate GitHub's login/authorize screen and harvest the victim's real GitHub.com credentials or PAT. This is triggered purely by ordinary repository interaction (clone/fetch/pull, including through submodules), matching the "attacker controls a git remote/proxy response" primitive and resulting in credential exfiltration / unauthorized account-binding as described in the valid-impact criteria.

### Likelihood Explanation
Exploitation only requires the victim to fetch from or clone a repository whose remote (or any submodule/LFS endpoint reachable during normal Git operations) is served by infrastructure the attacker controls, which is precisely the "malicious remote" precondition Desktop already treats as untrusted elsewhere (e.g. for generic-git-auth prompts). No local access, no leaked credentials, and no unnatural steps are required — the classification and sign-in-flow redirection happen automatically as part of the credential-helper's normal `get` handling, before any user judgment about the URL is invoked (the manual `EndpointEntry` step, which would otherwise let a user notice a suspicious host, is skipped).

### Recommendation
Do not use the client-supplied `wwwauth[]` header content as a basis for classifying a host as GitHub Enterprise. Either remove the `realm="GitHub"` heuristic entirely and rely solely on `isGitHubHost` (a real network probe against the candidate host) and known-account matching, or, if the heuristic is kept for latency reasons, require it to be corroborated by an actual `isGitHubHost` check before routing the user into a GitHub sign-in flow tied to that endpoint. Additionally, when routing into the sign-in flow from the credential helper, surface the concrete endpoint origin prominently in the sign-in UI (and consider forcing the `EndpointEntry` confirmation step) so users always have an opportunity to notice an unexpected host before authenticating.

### Proof of Concept
1. Attacker hosts an HTTP git server (e.g. `https://evil.example.com/repo.git`) that, for any credential-requiring request, responds `401 Unauthorized` with header `WWW-Authenticate: Basic realm="GitHub"`.
2. Victim adds this URL as a remote (or it appears as a `.gitmodules`/LFS endpoint in a cloned repository) and performs a fetch/pull in GitHub Desktop.
3. Git captures the header and passes `wwwauth[0]=Basic realm="GitHub"` to Desktop's credential helper via `createCredentialHelperTrampolineHandler` → `getCredential`.
4. `getEndpointKind` ( [2](#0-1) ) returns `'enterprise'`.
5. Since no account is registered for `evil.example.com`, `ui.promptForGitHubSignIn('https://evil.example.com/...')` fires, opening Desktop's "Sign in to GitHub" dialog bound to the attacker's origin.
6. Victim clicks "Sign in using your browser"; Desktop opens the system browser at an OAuth-authorize URL on `evil.example.com`, which the attacker can render as a convincing GitHub login clone to capture the victim's real credentials.

I was not able to fully inspect `app/src/ui/sign-in/sign-in.tsx` to confirm exactly how prominently the endpoint origin is displayed to the user during this flow, nor `app/src/lib/api.ts`'s `getOAuthAuthorizationURL`/`isGitHubHost` implementations in full, due to the final-iteration cutoff — a Devin session with full repo access would be needed to verify the exact rendered UI text and finalize a patch.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }

    const currentState = this.state

    if (
      currentState?.kind !== SignInStep.Authentication &&
      currentState?.kind !== SignInStep.ExistingAccountWarning
    ) {
      const stepText = currentState ? currentState.kind : 'null'
      return fatalError(
        `Sign in step '${stepText}' not compatible with browser authentication`
      )
    }

    this.setState({ ...currentState, loading: true })

    if (currentState.kind === SignInStep.ExistingAccountWarning) {
      const { existingAccount } = currentState
      // Try to avoid emitting an error out of AccountsStore if the account
      // is already gone.
      if (this.accounts.find(x => x.endpoint === existingAccount.endpoint)) {
        await this.accountStore.removeAccount(existingAccount)
      }
    }

    const csrfToken = crypto.randomUUID()

    new Promise<Account>((resolve, reject) => {
      const { endpoint, resultCallback } = currentState
      log.info('[SignInStore] initializing OAuth flow')
      this.setState({
        kind: SignInStep.Authentication,
        endpoint,
        resultCallback,
        error: null,
        loading: true,
        oauthState: {
          state: csrfToken,
          endpoint,
          onAuthCompleted: resolve,
          onAuthError: reject,
        },
      })
      shell.openExternal(getOAuthAuthorizationURL(endpoint, csrfToken))
    })

  public async setEndpoint(url: string): Promise<void> {
    const currentState = this.state

    if (
      currentState?.kind !== SignInStep.EndpointEntry &&
      currentState?.kind !== SignInStep.ExistingAccountWarning
    ) {
      const stepText = currentState ? currentState.kind : 'null'
      return fatalError(
        `Sign in step '${stepText}' not compatible with endpoint entry`
      )
    }

    /**
     * If the user enters a github.com url in the GitHub Enterprise sign-in
     * flow we'll redirect them to the GitHub.com sign-in flow.
     */
    if (/^(?:https:\/\/)?(?:api\.)?github\.com($|\/)/.test(url)) {
      this.beginDotComSignIn(currentState.resultCallback)
      return
    }

    this.setState({ ...currentState, loading: true })

    let validUrl: string
    try {
      validUrl = validateURL(url)
    } catch (e) {
      let error = e
      if (e.name === InvalidURLErrorName) {
        error = new Error(
          `The GitHub Enterprise instance address doesn't appear to be a valid URL. We're expecting something like https://example.ghe.com.`
        )
      } else if (e.name === InvalidProtocolErrorName) {
        error = new Error(
          'Unsupported protocol. Only https is supported when authenticating with GitHub Enterprise instances.'
        )
      }

      this.setState({ ...currentState, loading: false, error })
      return
    }

    const endpoint = getEnterpriseAPIURL(validUrl)

    const existingAccount = this.accounts.find(x => x.endpoint === endpoint)

    if (existingAccount) {
      this.setState({
        kind: SignInStep.ExistingAccountWarning,
        endpoint,
        existingAccount,
        error: null,
        loading: false,
        resultCallback: currentState.resultCallback,
      })
    } else {
      this.setState({
        kind: SignInStep.Authentication,
        endpoint,
        error: null,
        loading: false,
        resultCallback: currentState.resultCallback,
      })
    }
  }
