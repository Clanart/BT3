### Title
Stale `safe.directory` trust exception is never revoked, letting a later repository dropped at the same path bypass the untrusted-owner warning - (File: `app/src/lib/git/config.ts`)

### Summary
GitHub Desktop's `approvedCreditor`-style trust primitive is the `safe.directory` exception it adds to the user's **global** Git config whenever a user clicks "Trust Repository" for a path Git considers to have "dubious ownership" [3](#0-2) . This exception is keyed purely by filesystem **path**, not by the identity/fingerprint of the repository content or its origin. Once granted, the exception is permanent — Desktop never removes it, including when the user removes the tracked repository from Desktop.

### Finding Description
The trust flow works as follows:
- `getRepositoryType` shells out to `git rev-parse` and classifies a directory as `unsafe` when Git reports "dubious ownership", parsing the untrusted path straight out of `stderr` [4](#0-3) .
- The `MissingRepository` and `AddExistingRepository` UI components then let the user grant a permanent exception via `onTrustDirectory` → `addSafeDirectory(unsafePath)` [5](#0-4) [6](#0-5) .
- `addSafeDirectory` writes the path into the **global** `safe.directory` config value, which Git will honor for **any** repository subsequently found at that path, forever, with no expiry and no binding to repository identity (remote URL, commit history, or owner) [7](#0-6) .
- Removing a repository from Desktop (`_removeRepository` / `RepositoriesStore.removeRepository`) only deletes the local database row; it never calls any function to revoke the `safe.directory` entry [8](#0-7) [1](#0-0) . There is no `removeSafeDirectory`/"untrust" API anywhere in `app/src/lib/git/config.ts` or elsewhere in the codebase.

This is structurally identical to the reported `approvedCreditor` bug: an authorization ("this identifier is trustworthy") is granted while bound to one entity, but the invariant tying the authorization to that specific entity is never re-validated or reset when the entity behind the identifier changes. In the reported case the identifier is an account/contract address; in Desktop the identifier is a filesystem path. If the user later removes that repository (e.g., deletes it, or Desktop's tracked entry is dropped) and any different, attacker-influenced repository content ends up at the very same path — for example a path reused by a subsequent `git clone` of an attacker-supplied URL into the default clone directory, a restored/extracted archive, a symlink target from a fetched submodule, or a shared/synced folder — Git will silently skip the dubious-ownership check for that new content because the stale `safe.directory` entry still matches the path. Desktop's own explanatory copy states plainly why this check exists: *"Adding untrusted repositories may automatically execute files in the repository"* [9](#0-8) , i.e., the whole point of the check is to gate automatic execution of repository-controlled content (hooks, `.gitattributes` filters, etc.).

### Impact Explanation
If a previously-trusted path is repopulated with attacker-supplied repository content, Git will treat it as safe again without re-prompting the user, defeating the purpose of the ownership check and re-opening the path to automatic execution of repository-controlled hooks/config for content the user never explicitly reviewed a second time. The severity mirrors the original report: a trust decision granted for one entity silently carries over to a different entity that later occupies the same identifier.

### Likelihood Explanation
Medium: the reused-path scenario requires the same path to later host different repository content (e.g., delete+re-clone into the default directory, restoring from a compromised archive/dotfiles repo, or a shared network path scenario already anticipated by Desktop's own Windows UNC-path handling in `addSafeDirectory`) [7](#0-6) . It doesn't require the attacker to have prior host compromise or admin rights — just the ability to get their content placed at a path the user previously trusted, which is a realistic outcome of normal Desktop workflows (remove repository → clone a new one to the same folder).

### Recommendation
Do not persist trust solely by path. Either (a) remove the `safe.directory` exception when the tracked repository is removed from Desktop or when Desktop detects the directory's git history/remote has changed since the exception was granted, or (b) bind the trust decision to a fingerprint of the repository (e.g., initial commit hash / `.git` directory identity) in addition to the path, and re-prompt if that fingerprint changes.

### Proof of Concept
1. User adds a repository at `~/Projects/foo` that Git flags as `unsafe` (e.g., dubious ownership) and clicks "Trust Repository", triggering `addSafeDirectory('~/Projects/foo')` which adds a permanent global config entry [7](#0-6) .
2. User later removes this repository from Desktop via `_removeRepository`, which deletes only the DB record, leaving the global `safe.directory` entry intact [8](#0-7) .
3. An attacker gets the user to place different repository content at the identical path `~/Projects/foo` (e.g., a shared folder sync, or user re-clones what they believe is a legitimate repo into that same default path but it's actually attacker-controlled/malicious content, or a symlink swap).
4. Desktop calls `getRepositoryType('~/Projects/foo')`; because `safe.directory` already lists that path, Git no longer reports `dubious ownership`, so `type.kind` is `regular` instead of `unsafe` [4](#0-3) , and the user is never shown the "Trust Repository" warning again for this new, different repository content — despite the stated risk that "Adding untrusted repositories may automatically execute files in the repository" [9](#0-8) .

/**
 * Adds a path to the `safe.directories` configuration variable if it's not
 * already present. Adding a path to `safe.directory` will cause Git to ignore
 * if the path is owner by a different user than the current.
 */
export async function addSafeDirectory(path: string) {
  // UNC-paths on Windows need to be prefixed with `%(prefix)/`, see
  // https://github.com/git-for-windows/git/commit/e394a16023cbb62784e380f70ad8a833fb960d68
  if (__WIN32__ && path[0] === '/') {
    path = `%(prefix)/${path}`
  }

  await addGlobalConfigValueIfMissing('safe.directory', path)
}

/** Set the global config value by name. */
export async function addGlobalConfigValueIfMissing(
  name: string,
  value: string
): Promise<void> {
  const { stdout, exitCode } = await git(
    ['config', '--global', '-z', '--get-all', name, value],
    __dirname,
    'addGlobalConfigValue',
    { successExitCodes: new Set([0, 1]) }
  )

  if (exitCode === 1 || !stdout.split('\0').includes(value)) {
    await addGlobalConfigValue(name, value)
  }
}

export async function getRepositoryType(path: string): Promise<RepositoryType> {
  if (!(await directoryExists(path))) {
    return { kind: 'missing' }
  }

  try {
    const result = await git(
      ['rev-parse', '--is-bare-repository', '--show-cdup', '--git-dir'],
      path,
      'getRepositoryType',
      { successExitCodes: new Set([0, 128]) }
    )

    if (result.exitCode === 0) {
      // Bare repositories will not include gitdir so we handle that separately
      if (result.stdout.startsWith('true\n')) {
        return { kind: 'bare' }
      }

      // --is-bare-repository and --show-cdup each produce a single line but
      // --git-dir could theoretically contain newlines so we parse the known
      // fields first and treat the remainder as the git dir. We use [\s\S]*
      // instead of .* for the git dir capture group because .* doesn't match
      // newlines whereas [\s\S]* matches any character including newlines.
      const match = result.stdout.match(/^(true|false)\n(.*)\n([\s\S]*)\n$/)

      if (match) {
        const [, isBare, cdup, gitDir] = match

        return isBare === 'true'
          ? { kind: 'bare' }
          : {
              kind: 'regular',
              topLevelWorkingDirectory: resolve(path, cdup),
              gitDir: resolve(path, gitDir),
            }
      }
    }

    const unsafeMatch =
      /fatal: detected dubious ownership in repository at '(.+)'/.exec(
        result.stderr
      )
    if (unsafeMatch) {
      return { kind: 'unsafe', path: unsafeMatch[1] }
    }
