## Title
Automatic Remote-URL Rewrite Trusts Unverified GitHub API `clone_url`, Silently Redirecting Push/Pull Target — (`File: app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
Similar to the reported `BaseCustomAccounting` bug — where a hook's single-pool state (`poolKey`) is silently overwritten by an unrelated, unconsented registration event — GitHub Desktop's `updateRemoteUrl` function silently rewrites a repository's `origin` remote URL based on an untrusted signal: the `clone_url` field returned by the GitHub API for whatever repository the *locally stored* owner/name happens to resolve to at refresh time. There is no verification that the "new" target is the same trust-anchor as the one the user originally added; only shape-based heuristics (protocol match, previous non-drift) gate the rewrite.

### Finding Description
`repositoryWithRefreshedGitHubRepository` in `app-store.ts` re-derives the GitHub identity for a tracked repository purely from the current `origin` remote URL, via `matchGitHubRepository`, which does nothing more than parse hostname/owner/name out of the remote string: [1](#0-0) 

That match is then used to call `api.fetchRepository(owner, name)` and feed the result straight into `updateRemoteUrl`: [2](#0-1) 

`updateRemoteUrl` then overwrites the local `origin` URL with `apiRepo.clone_url` whenever the protocol matches and the current remote still resembles the last-known `gitHubRepository.cloneURL`: [3](#0-2) 

None of these guards verify that the "new" `clone_url` refers to a repository the user actually intended to keep pushing to — they only check URL *shape* (protocol, prior drift), not identity/ownership/authenticity. Because `api.fetchRepository(owner, name)` resolves whatever GitHub currently serves for that `owner/name` pair (which follows GitHub's rename/transfer redirect semantics), any change in what that endpoint returns — e.g., a repository rename or ownership transfer performed by someone with write access, or a name that gets vacated and re-claimed by a different account — causes Desktop to silently repoint every collaborator's local `origin` to the new location and re-bind the local `Repository`'s `gitHubRepository` association via `setGitHubRepository`, without any user confirmation. This mirrors the report's core issue: a piece of state meant to describe a single, deliberately-chosen trust relationship (pool ↔ hook, or here, local clone ↔ remote identity) gets silently reassigned by an event the state's owner did not explicitly approve.

### Impact Explanation
If exploited, the victim's local `origin` remote is silently changed to point at a different repository controlled by whoever triggered the rename/transfer/reclaim. Subsequent `git push` operations (performed through Desktop's push UI, which uses the stored remote) would send commits to that new destination instead of the one the user believes they're using, and subsequent fetch/pull would silently start pulling history from the new target — i.e., corruption of what the user commits/pushes and a plausible vector for injecting attacker content into what looks like the same "origin" in the Desktop UI. This matches the "silent corruption of what the user commits or pushes" impact class.

### Likelihood Explanation
This path only requires that the GitHub-hosted `owner/name` that Desktop is tracking at some point resolves (via GitHub's own redirect-following API behavior) to a different repository than the one originally cloned — something that can be triggered by any actor who can rename/transfer/rename-and-reclaim a repository name, not by the Desktop user. The rewrite is performed automatically during routine refresh flows (`repositoryWithRefreshedGitHubRepository`, invoked e.g. on account change), with no popup, confirmation, or diff shown to the user, and the built-in guard conditions do not check trust/ownership continuity, only URL shape.

### Recommendation
Do not silently rewrite the local remote URL from API-derived `clone_url` values. At minimum, require explicit user confirmation before changing `origin`/tracked remotes based on a detected rename, and additionally validate that the underlying repository/owner ID (not just owner/name string and protocol) is unchanged, so a name-reclaim or transfer cannot silently redirect an existing clone.

### Proof of Concept
1. Victim clones `https://github.com/alice/project` with Desktop; Desktop stores `gitHubRepository.cloneURL = https://github.com/alice/project`.
2. The `alice/project` name is later vacated (rename or transfer) and re-claimed, or renamed by a collaborator, such that GitHub's API now resolves `alice/project` (or the redirect chain Desktop still tracks) to a different repository with `clone_url = https://github.com/mallory/project-evil`.
3. On the next background refresh (`repositoryWithRefreshedGitHubRepository`), Desktop calls `api.fetchRepository('alice','project')`, gets back the new `clone_url`, and — because protocol matches and the previous remote still matched the last stored `cloneURL` — `updateRemoteUrl` rewrites the victim's `origin` to `https://github.com/mallory/project-evil` with no prompt.
4. The victim's next push/pull now silently targets the attacker-controlled repository. [4](#0-3)

export function matchGitHubRepository(
  accounts: ReadonlyArray<Account>,
  remote: string
): IMatchedGitHubRepository | null {
  for (const account of accounts) {
    const htmlURL = getHTMLURL(account.endpoint)
    const { hostname } = URL.parse(htmlURL)
    const parsedRemote = parseRemote(remote)

    if (parsedRemote !== null && hostname !== null) {
      if (parsedRemote.hostname.toLowerCase() === hostname.toLowerCase()) {
        return { name: parsedRemote.name, owner: parsedRemote.owner, account }
      }
    }
  }

  return null
}

  private async repositoryWithRefreshedGitHubRepository(
    repository: Repository
  ): Promise<Repository> {
    const repoStore = this.repositoriesStore
    const match = await this.matchGitHubRepository(repository)

    // TODO: We currently never clear GitHub repository associations (see
    // https://github.com/desktop/desktop/issues/1144). So we can bail early at
    // this point.
    if (!match) {
      return repository
    }

    const { account, owner, name } = match
    const { endpoint } = account
    const api = API.fromAccount(account)
    const apiRepo = await api.fetchRepository(owner, name)

    if (apiRepo === null) {
      // If the request fails, we want to preserve the existing GitHub
      // repository info. But if we didn't have a GitHub repository already or
      // the endpoint changed, the skeleton repository is better than nothing.
      if (endpoint !== repository.gitHubRepository?.endpoint) {
        const ghRepo = await repoStore.upsertGitHubRepositoryFromMatch(match)
        return repoStore.setGitHubRepository(repository, ghRepo)
      }

      return repository
    }

    if (repository.gitHubRepository) {
      const gitStore = this.gitStoreCache.get(repository)
      await updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)
    }

    const ghRepo = await repoStore.upsertGitHubRepository(endpoint, apiRepo)
    const freshRepo = await repoStore.setGitHubRepository(repository, ghRepo)

    await this.refreshBranchProtectionState(freshRepo)
    return freshRepo
  }

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}
