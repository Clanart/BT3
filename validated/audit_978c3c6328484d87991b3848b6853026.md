### Title
Dust-value outputs are reported as spendable `ReceivedOutput`s, making received funds economically unspendable - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
Analogous to the report's "withdrawal path exists but the transfer can never economically succeed, leaving funds stuck," `Scanner::scan_transaction` classifies a transaction output as a `ReceivedOutput` purely by `script_pubkey` match, with no minimum-value check. `SignableTransaction::new` then accepts such outputs as inputs unconditionally, even though spending a P2TR input costs more in fees than a dust output is worth. An unprivileged party can send dust (or even 1-sat / 0-value-adjacent) outputs to the scanned key, producing reported "received funds" that can never be spent without a net loss.

### Finding Description
`scan_transaction` pushes a `ReceivedOutput` for any output whose `script_pubkey` is in `self.scripts`, without inspecting `output.value`: [1](#0-0) 

The received value is only exposed via `ReceivedOutput::value()` and is never validated: [2](#0-1) 

On the spend side, `SignableTransaction::new` enforces `DUST = 546` only on outgoing *payments* (line 166), not on inputs. Every entry in `inputs` is summed into `input_sat` and consumed as a prevout regardless of value: [3](#0-2) 

Spending a Taproot input costs ~58 vbytes of witness/input weight (modeled in `calculate_weight_vbytes` with a 64-byte signature witness per input): [4](#0-3) 

At any non-trivial fee rate, an input worth less than ~hundreds of sats costs more to spend than it contributes. The wallet has no in-crate mechanism to reject or deprioritize such outputs at scan time; once reported, the only way to "withdraw" them is a net-negative spend.

### Impact Explanation
Funds sent to the scanner's key at dust values are reported as received yet are not economically spendable — the direct analog of yield that is credited but can never be withdrawn. Additionally, an attacker can force value burn: dust outputs included in `inputs` add weight and raise `needed_fee` while contributing ~nothing to `input_sat`, and any leftover below `DUST` is silently burned as fee rather than returned as change (the change output is only pushed `if value >= DUST`): [5](#0-4) 

### Likelihood Explanation
Low-to-medium likelihood: exploitation only requires an unprivileged party to send dust outputs to a publicly known P2TR address derived from the scanned key — cheap (≤546 sats each) and always possible since receive addresses are public. The impact per output is bounded by the dust threshold, keeping this at Medium rather than High.

### Recommendation
Enforce a minimum value on received outputs: have `scan_transaction`/`Scanner` skip outputs with `value < DUST` (or a configurable economic-spendability threshold accounting for current fee rates), and/or have `SignableTransaction::new` reject or refuse inputs whose value is below the marginal cost of spending them (`fee_per_vbyte * input_vbytes`).

### Proof of Concept
1. An attacker learns the P2TR script for the multisig key via `p2tr_script_buf(key)` (the address is public).
2. The attacker broadcasts a transaction paying 100 sats to that script.
3. `scanner.scan_transaction(&tx)` returns a `ReceivedOutput` with `value() == 100`; no error or filtering occurs (`networks/bitcoin/src/wallet/mod.rs:199-214`).
4. Any `SignableTransaction::new` including this output must pay ~58+ vbytes × `fee_per_vbyte` to spend it — at FEE = 20 sat/vB, ~1160 sats — an ~11x net loss. The 100 sats are permanently stranded: reported as received, never rationally spendable.

```rust
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
```
