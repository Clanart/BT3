### Title
`git commit --amend` after Claude edits causes the entire change to bypass Stop-hook security review - ([File: plugins/security-guidance/hooks/diffstate.py])

### Summary
`compute_v2_review_set` builds the reviewable file set as `dirty_now ∩ changed_since(baseline_sha)`, where `dirty_now` is populated only from `git status` (working-tree dirt) plus commits reachable when `head_at_capture` is a linear ancestor of the current `HEAD`. When a turn's edits are folded into the working tree via `git commit --amend`, the tree becomes clean (nothing in `git status`) and the amended commit is *not* a descendant of `head_at_capture` (amend replaces the tip rather than building on it), so `_is_ancestor(head_at_capture, current_head)` is false and the amend's changes never enter `dirty_now`. Since the review set is an intersection, an empty `dirty_now` yields an empty `review_set` regardless of what `changed_since` (diff vs `baseline_sha`) would show, so the Stop hook exits at the "empty review set" skip path and the dangerous, Claude-authored change is never sent to the LLM reviewer.

### Finding Description
`compute_v2_review_set` in `plugins/security-guidance/hooks/diffstate.py` computes: [1](#0-0) 
`dirty_now` is derived from `_git_status_porcelain` (working-tree vs index/HEAD) unioned with `_git_name_only(head_at_capture..HEAD)` only when `head_at_capture` is an ancestor of the current `HEAD` (i.e., normal fast-forward commits during the turn). `changed_since` is the diff of the current tree against `baseline_sha` (the `git stash create` snapshot taken at `UserPromptSubmit`) — see `capture_git_baseline`: [2](#0-1) 
The final review set is `dirty_now & changed_since` (line 426), an intersection, not a union: [3](#0-2) 

Exploit flow:
1. `UserPromptSubmit` (`handle_user_prompt_submit`) captures `baseline_sha` (stash-create SHA or `HEAD`) and `head_at_capture` = current `HEAD`: [4](#0-3) 
2. Claude (or a Bash tool call driven by attacker-controlled repo content/instructions) edits a file introducing a dangerous change, then runs `git commit --amend` to fold the edit into the existing tip commit instead of creating a new commit on top of `head_at_capture`.
3. After the amend, the working tree is clean (`git status` shows nothing), so `tracked_dirty` and `untracked` are both empty from `_git_status_porcelain`.
4. The new `HEAD` (amended commit) is not a git-ancestor-descendant of `head_at_capture` (amend replaces the commit rather than extending it), so `_is_ancestor(repo, head_at_capture, current_head)` is `False`, and the `head_at_capture..HEAD` name-only diff is never unioned into `dirty_now`.
5. `dirty_now` is therefore empty, so `review_set = dirty_now & changed_since = ∅` regardless of `changed_since` correctly showing the file as changed vs `baseline_sha`.
6. `handle_stop_hook` sees `review_paths == []` and skips entirely: [5](#0-4) 

The dangerous change committed via `--amend` is permanently invisible to the Stop-hook LLM review — no future turn re-flags it either, because the next `UserPromptSubmit` re-baselines to the new clean/committed state, and there is no `touched_paths`-independent fallback that unions committed-but-non-ancestor ranges into the review set.

### Impact Explanation
This breaks the stated invariant that "the review set must stay bound to the right repo, baseline, and touched paths." A single ordinary git operation (`git commit --amend`), fully reachable through a normal cloned-repo workflow (e.g., repo instructions/CLAUDE.md nudging Claude to "amend the last commit" instead of creating a new one, or Claude choosing to amend on its own), causes a security-relevant diff to be silently dropped from review with no error, no warning, and no telemetry indicating the skip was due to a stale/misaligned baseline rather than a genuinely empty diff. This is a wrong-target/skip-scope class bug: the Stop-hook's core security promise (LLM reviews every Claude-introduced change) is defeated by ordinary git history rewriting, not by any authentication or sandbox bypass.

### Likelihood Explanation
This requires no privilege beyond normal use of Claude Code against a git repository and no memory-corruption or injection primitives — only a commit workflow (`edit file` → `git commit --amend`) that is common and easily encouraged by a malicious/crafted repository's contribution instructions, CI hints, or agent nudges embedded in repo content. It is deterministic and repeatable every time the ancestor check fails.

### Recommendation
Change `dirty_now` to be a union across both the linear-ancestor case and the non-ancestor case: when `head_at_capture != current_head` and it is NOT an ancestor (history was rewritten via amend/rebase/reset), fall back to diffing `head_at_capture` against `current_head` directly (or diff `baseline_sha` against `current_head` unconditionally) rather than relying solely on `git status` porcelain output for `dirty_now`. At minimum, union `_git_name_only(repo, f"{head_at_capture}...{current_head}")` (or a direct two-dot diff when not an ancestor) into `dirty_now` so amended/rebased commits are not silently excluded from the intersection.

### Proof of Concept
Integration test in the plugin's git-baseline test suite:
1. Init a git repo, commit an initial file, capture `head_at_capture = HEAD_0` and `baseline_sha` via `capture_git_baseline` (clean tree ⇒ `baseline_sha == HEAD_0`).
2. Edit a tracked file to introduce a dangerous pattern (e.g., `eval(input())`), then run `git add -A && git commit -m "wip"` to get `HEAD_1`, then `git commit --amend -m "final"` to get `HEAD_2` (tree clean, `HEAD_2` is not an ancestor-descendant of `HEAD_0` in the fast-forward sense checked by `_is_ancestor` — assert this directly with `_is_ancestor(repo, HEAD_0, HEAD_2)` returning what `git merge-base --is-ancestor` reports for this specific history shape).
3. Call `compute_v2_review_set(repo, baseline_sha=HEAD_0, head_at_capture=HEAD_0)`.
4. Assert (current buggy behavior): `review_paths == []` even though `git diff HEAD_0 HEAD_2 --name-only` shows the dangerous file changed.
5. Expected (fixed) assertion: `review_paths` contains the absolute path to the dangerous file, proving the review set stayed bound to the actual set of Claude-touched/dangerous files across the amend.

def capture_git_baseline(cwd):
    """
    Capture a git ref representing the current working tree state.
    Uses `git stash create` which creates a commit object for the current state
    (HEAD + uncommitted changes) without modifying the stash list or working tree.
    Falls back to HEAD if the working tree is clean.
    Returns the SHA string, or None if not in a git repo or if the repo has no commits.

    NOTE: `git stash create` does NOT capture untracked files. UPS pairs this
    SHA with a `_list_untracked()` snapshot stored as `untracked_at_baseline`,
    and `compute_v2_review_set` subtracts that set so pre-existing untracked
    files are not reviewed as Claude-authored.
    """
    try:
        # Check if HEAD exists (i.e., repo has at least one commit)
        head_check = subprocess.run(
            [*GIT_CMD, "rev-parse", "HEAD"],
            cwd=cwd, capture_output=True, text=True, timeout=5
        )
        if head_check.returncode != 0:
            # No commits yet — skip review rather than creating commits in the user's repo
            debug_log("No commits in repo, skipping baseline capture")
            return None

        result = subprocess.run(
            [*GIT_CMD, "stash", "create"],
            cwd=cwd, capture_output=True, text=True, timeout=15
        )
        sha = result.stdout.strip()
        if sha:
            return sha

        # Working tree is clean — stash create returns empty. Use HEAD.
        result = subprocess.run(
            [*GIT_CMD, "rev-parse", "HEAD"],
            cwd=cwd, capture_output=True, text=True, timeout=5
        )
        sha = result.stdout.strip()
        return sha if sha else None

    # stash-create and ls-files both walk the worktree (~2-5s each in a very

    import concurrent.futures as _cf
    with _cf.ThreadPoolExecutor(max_workers=2) as _ex:
        _f_sha = _ex.submit(capture_git_baseline, cwd)
        _f_ut = _ex.submit(_list_untracked, cwd)
        sha = _f_sha.result()
        # Always capture the untracked snapshot. `git stash create` returns
        # empty when there are no TRACKED changes, but pre-existing untracked
        # files still need to be excluded from the next Stop's review_set —
        # otherwise an untracked-only working tree gets every untracked file
        # reviewed on every turn until something tracked is dirtied.
        untracked_now = _f_ut.result() or {}
    head = _git_rev_parse_head(cwd)

    # If the previous turn's Stop hook never ran (user interrupt, follow-up
    # during work, tool-reject, model crash, maxTurns, PostToolUse block…),
    # touched_paths is still populated because consume_stop_state is the only
    # consumer and it runs under the state lock. Overwriting baseline_sha now
    # would re-baseline *past* those unreviewed edits, making them permanently
    # invisible to the next Stop. Preserve the old baseline so the next Stop
    # diffs the aborted turn's edits plus the new turn's edits together.
    preserved = {"value": False}

    def _save(state):
        # Only preserve if there's actually an old baseline to preserve.
        # First UPS of a session can have touched_paths if PostToolUse
        # somehow ran first (print mode, odd harnesses) — in that case
        # we still need to capture a baseline.
        if state.get("touched_paths") and state.get("baseline_sha"):
            preserved["value"] = True
            return
        if sha:
            state["baseline_sha"] = sha
            state["head_at_capture"] = head
        # untracked_at_baseline is independent of whether the stash produced
        # a SHA — write it unconditionally so compute_v2_review_set's
        # preexisting-untracked exclusion works in untracked-only trees.
        state["untracked_at_baseline"] = untracked_now
