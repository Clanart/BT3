Based on the codebase investigation, I found a valid analog to the reported path-traversal arbitrary file deletion bug class, reachable through the harvester's local RPC `delete_plot` endpoint, which accepts an attacker-controlled path with no containment check against the configured plot directories.

### Title
Unauthenticated-scope Path Traversal Arbitrary File Deletion via Harvester RPC `delete_plot` - (File: `chia/harvester/harvester.py`)

### Summary
The harvester RPC endpoint `/delete_plot` takes a raw `filename` string from the RPC request and passes it straight to `remove_plot()`, which calls `Path(str_path).unlink()` with no validation that the path resides inside any of the harvester's configured plot directories (`get_plot_directories`). Any RPC caller able to reach the harvester's `/delete_plot` endpoint can delete an arbitrary file on the host filesystem that the harvester process has permission to remove, exactly mirroring the CVE-2026-72569 bug class (unsanitized path handed directly to a delete/unlink operation with a `--delete`-style feature).

### Finding Description
`HarvesterRpcApi.delete_plot()` extracts `filename` from the JSON request body and forwards it unmodified to `Harvester.delete_plot()`: [1](#0-0) 

`Harvester.delete_plot()` wraps the string in a `Path` and calls the shared `remove_plot()` helper without any check that the path is one of the actively tracked/known plot files or that it lives under a configured plot directory: [2](#0-1) 

`remove_plot()` itself performs no containment or ownership validation — it simply checks existence and unlinks: [3](#0-2) 

Contrast this with `add_plot_directory`/`remove_plot_directory`, which at least resolve and validate the path is a real directory before mutating config: [4](#0-3) 

No equivalent validation exists for `delete_plot` — it does not check that the resolved path is a `*.plot`/`*.plot2` file, that it is currently tracked in `PlotManager.plots`, or that it is contained within any directory listed in `get_plot_directories(root_path)`. This means a caller can supply any absolute or `../`-relative path (e.g. the node's `config.yaml`, wallet DB, keychain files, or any other file the harvester process user can write to) and have it deleted.

The internal `.cursor/context/harvester.md` documentation itself notes this gap explicitly: "`delete_plot()` unlinks the supplied path... There is no extra ownership model in this module; RPC authorization and local file permissions are the relevant gates." [5](#0-4) 

### Impact Explanation
Any principal with access to submit a `delete_plot` RPC call to the harvester (an RPC caller in-scope per the analysis rules) can delete arbitrary files reachable by the harvester process — not limited to actual plot files or plot directories. This can be used to destroy wallet databases, config files, keychain files, or other plot files belonging to other pools/paths outside the harvester's own configuration, producing a spend-triggered or availability-impacting halt of node/wallet operation (data loss requiring reconfiguration or resync), which matches the "spend-triggered transaction-processing halt" / high-impact criteria in scope.

### Likelihood Explanation
The endpoint is trivially reachable with a single RPC call (`{"filename": "<any path>"}`) — no complex chain of conditions, no consensus interaction, and no special privileges beyond ordinary RPC client access are required. There is no path canonicalization/containment check anywhere on this call path, so exploitation is deterministic once RPC access is available.

### Recommendation
In `Harvester.delete_plot()` (or in `remove_plot()`), resolve the supplied path and verify it is (a) contained within one of the configured plot directories returned by `get_plot_directories(self.root_path)`, and (b) currently present in `self.plot_manager.plots` (i.e., an actual known plot file), before unlinking. Reject the request otherwise.

### Proof of Concept
1. Obtain RPC access to a running harvester (e.g., via the harvester RPC port/cert as any RPC client).
2. Send: `POST /delete_plot` with body `{"filename": "/path/to/target/config.yaml"}` (or a relative `../../` path to escape the plot directories).
3. `HarvesterRpcApi.delete_plot` → `Harvester.delete_plot` → `remove_plot(Path(str_path))` unlinks the target file with no containment check, deleting it regardless of whether it is a plot file or inside a configured plot directory.

```python
def add_plot_directory(root_path: Path, str_path: str) -> dict[str, Any]:
    path: Path = Path(str_path).resolve()
    if not path.exists():
        raise ValueError(f"Path doesn't exist: {path}")
    if not path.is_dir():
        raise ValueError(f"Path is not a directory: {path}")
    log.debug(f"add_plot_directory {str_path}")
    with lock_and_load_config(root_path, "config.yaml") as config:
        if str(Path(str_path).resolve()) in get_plot_directories(root_path, config):
            raise ValueError(f"Path already added: {path}")
        if not config["harvester"]["plot_directories"]:
            config["harvester"]["plot_directories"] = []
        config["harvester"]["plot_directories"].append(str(Path(str_path).resolve()))
        save_config(root_path, "config.yaml", config)
    return config
```
