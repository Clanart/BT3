### Title

Unauthenticated `ReceivedOutput` deserialization permits fabricated collateral values and unspendable inputs - (File: `networks/bitcoin/src/wallet/mod.rs`)

### Summary

`ReceivedOutput::read` accepts an attacker-controlled scalar, `TxOut`, and `OutPoint` without proving that the referenced UTXO exists or that the claimed `TxOut` matches the UTXO committed by that outpoint [1](#0-0) . `SignableTransaction::new` then trusts `input.output.value` as spendable collateral when calculating available input value [2](#0-1) . This is analogous to collateral-price inflation: a fabricated input valuation can make an insufficiently funded or nonexistent input appear sufficient to fund payments.

### Finding Description

`ReceivedOutput::read` parses `offset`, `output`, and `outpoint` as independent serialized fields, but performs no UTXO lookup, Merkle proof validation, or consistency check between `outpoint` and the claimed `TxOut` [1](#0-0) . The transaction builder sums the untrusted `output.value` values into `input_sat` and uses that total to authorize the requested payments and fee [3](#0-2) . When constructing the signing machine, `SignableTransaction::multisig` checks only that the offset-derived Taproot script equals `prevouts[i].script_pubkey`; it does not validate that the prevout amount is the amount actually confirmed on-chain [4](#0-3) . The signing path then commits these attacker-influenced prevouts through `Prevouts::All` in the Taproot sighash [5](#0-4) .

### Impact Explanation

An attacker who can supply serialized `ReceivedOutput` bytes can report a low-value or nonexistent UTXO as a high-value spendable input, inflating the wallet’s apparent collateral [1](#0-0) . That fabricated value can satisfy the `input_sat < payment_sat + needed_fee` check even where the real UTXO cannot fund the outputs [6](#0-5) . If the object references a nonexistent outpoint or an incorrect amount, the resulting signatures commit to false prevout data and the transaction is not broadcastable, leaving funds reported as spendable when they are not [5](#0-4) . If an integrating service releases off-chain value or marks a balance as available after deserializing the object or constructing the transaction, this can cause incorrect accounting and loss of real assets outside the Bitcoin transaction.

### Likelihood Explanation

The attacker needs only control over serialized bytes passed to `ReceivedOutput::read`; no validator key, peer privilege, leaked secret, or malformed curve encoding is required [1](#0-0) . The attack is reachable where untrusted persisted or network-supplied outputs are restored into `ReceivedOutput` rather than obtained directly from `Scanner::scan_transaction`, which derives both `output` and `outpoint` from an observed transaction [7](#0-6) . Because `multisig` accepts the object after matching only the script, fabrication does not require finding a hash collision or controlling the threshold key [4](#0-3) . Severity is Medium: the library produces false spendability and potentially an invalid threshold-signed transaction, but Bitcoin consensus prevents the inflated amount itself from being spent.

### Recommendation

Treat `ReceivedOutput::read` as parsing an unauthenticated claim rather than a spendable output [1](#0-0) . Before crediting the value or constructing a `SignableTransaction`, resolve `outpoint` against a trusted Bitcoin node or verified block data and require byte-for-byte equality with the returned `TxOut` [8](#0-7) . Prefer making `ReceivedOutput` construction private or crate-visible so production callers must obtain it from `Scanner::scan_transaction`, while keeping a separate explicitly untrusted representation for deserialization [7](#0-6) . `SignableTransaction::multisig` should also be fed authenticated prevouts, because the Taproot sighash commits to all prevout amounts and scripts [5](#0-4) .

### Proof of Concept

The following conceptual Rust sequence demonstrates the forged collateral path from `networks/bitcoin/src/wallet/mod.rs` and `networks/bitcoin/src/wallet/send.rs`:

```rust
use bitcoin::{
  consensus::serialize,
  hashes::Hash,
  Amount, OutPoint, ScriptBuf, TxOut, Txid,
};
use k256::Scalar;
use serai_bitcoin::wallet::{p2tr_script_buf, ReceivedOutput, SignableTransaction};

// Use an even aggregate key controlled/known by the wallet.
let script: ScriptBuf = p2tr_script_buf(group_key).unwrap();

// Claim a 1 BTC prevout while referencing a nonexistent or low-value outpoint.
let forged_txout = TxOut {
  value: Amount::from_sat(100_000_000),
  script_pubkey: script,
};
let forged_outpoint = OutPoint {
  txid: Txid::all_zeros(),
  vout: 0,
};

// Wire format used by ReceivedOutput::read: scalar || TxOut || OutPoint.
let mut bytes = Vec::new();
bytes.extend(Scalar::ZERO.to_bytes());
bytes.extend(serialize(&forged_txout));
bytes.extend(serialize(&forged_outpoint));

let forged = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();
assert_eq!(forged.value(), 100_000_000);

// The builder now treats the fabricated satoshis as available collateral.
let tx = SignableTransaction::new(
  vec![forged],
  &[(destination_script, 90_000_000)],
  None,
  None,
  adequate_fee_per_vbyte,
).unwrap();

// multisig succeeds when the script matches, even though the prevout claim is false.
let machine = tx.multisig(&threshold_keys).unwrap();
```

The parsed object reports `100_000_000` satoshis because `value()` directly returns the embedded `TxOut` amount [9](#0-8) . `SignableTransaction::new` accepts the payment because that forged amount raises `input_sat` above the payment plus fee [3](#0-2) . The transaction cannot validly spend a missing or mismatched UTXO, proving that an attacker can cause the wallet to report and sign for collateral that is not actually spendable.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
