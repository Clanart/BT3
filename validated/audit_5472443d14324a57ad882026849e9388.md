### Title
`aptos move verify-package` never compares on-chain module bytecode, only source-derived metadata - ([File: aptos-move/cli/src/commands.rs])

### Summary
The Aptos CLI's `verify-package` command is documented to "verify the bytecode matches a local compilation of the Move code," but the implementation never fetches or compares actual on-chain compiled module bytes. It only compares `PackageMetadata` fields (name, deps, `ModuleMetadata.source`/`source_map` text, manifest, upgrade_policy, `source_digest` string) between a freshly built local package and the on-chain `PackageRegistry` entry.

### Finding Description
`VerifyPackage::execute` in [1](#0-0)  builds the package locally, extracts `compiled_metadata` via `pack.extract_metadata()`, fetches the on-chain package via `CachedPackageRegistry::create(client, self.account, false)`, and calls `package.verify(&compiled_metadata)`.

The `false` argument means bytecode download is skipped: `CachedPackageRegistry::create` only populates its internal `bytecode` map `if with_bytecode` [2](#0-1) . Since `with_bytecode=false` here, `self.bytecode` stays empty, and `get_bytecode` is never invoked anywhere in the `VerifyPackage` flow.

`CachedPackageMetadata::verify` in [3](#0-2)  then only compares `name`, `deps`, `modules` (which is `ModuleMetadata` containing gzipped `source` text and `source_map`, not bytecode), `manifest`, `upgrade_policy`, `extension`, and `source_digest` string — fields that are entirely author-supplied and attached to the `PackageMetadata` resource at publish time via `code::publish_package_txn`. The `PackageMetadata`/`ModuleMetadata` Move structs, as defined in [4](#0-3) , never contain the actual bytecode — bytecode is separately deployed as module resources, and Aptos's on-chain publish flow does not cross-check that `source_digest`/`source` in the metadata actually correspond to the deployed bytecode; that correspondence is only meant to be checked off-chain via tooling.

Because `verify-package` never downloads or diffs the real on-chain bytecode (the `DownloadPackage` command's `--bytecode` flag does that via `get_bytecode`, but `VerifyPackage` never uses this path), a package publisher can attach arbitrary `source`/`source_digest` metadata describing innocuous code while deploying different (e.g., backdoored) bytecode, and `aptos move verify-package` will still print `"Successfully verified source of package"` as long as the attacker crafts metadata whose `source`/`source_digest`/`manifest` happen to match what a victim would locally build (which is possible since these are independent, author-controlled fields with no on-chain linkage enforced between them and the compiled module bytes).

### Impact Explanation
Users, auditors, or integrators who rely on `aptos move verify-package` to confirm that on-chain deployed code corresponds to publicly reviewed source will get a false positive "verified" result, because the tool checks only self-consistency between locally computed and remotely stored *metadata*, never the deployed *bytecode*. This directly matches the required-impact bullet "Mismatch between verified bytes, package metadata, dependency declarations, and committed module bytes," enabling supply-chain-style trust deception for any package whose owner controls what metadata is attached at publish.

### Likelihood Explanation
This requires only publishing a package with metadata (source text, source digest, manifest) independent from the actual compiled bytecode bundle — both are already independently supplied as separate parameters to `code::publish_package_txn`/`object_code_deployment::publish`/`upgrade`, with no protocol-level check tying them together. No special privilege is needed beyond normal publish rights on one's own package/object; this is exploitable by any ordinary package deployer.

### Recommendation
Have `VerifyPackage::execute` create the `CachedPackageRegistry` with `with_bytecode = true`, and additionally verify that each locally-compiled module's serialized bytecode bytes match those returned by `get_bytecode` for the corresponding module — not just the metadata's `source`/`source_digest` fields. Consider hardening `verify()` in `stored_package.rs` to require this bytecode-level comparison before reporting success, and update the command name/output to make clear when only metadata (not bytecode) was checked, if bytecode verification is optional.

### Proof of Concept
1. Compile package `P` locally with legitimate source producing metadata `M_local` and bytecode `B_legit`.
2. Compile a malicious bytecode `B_evil` (e.g., different logic) but craft/attach metadata fields (`source`, `source_map`, `manifest`, `source_digest`) that are byte-identical to what would be generated from the legitimate source `M_local` (the attacker fully controls these fields when calling `code::publish_package_txn`).
3. Publish `B_evil` together with the crafted metadata under account/object `A`.
4. Run `aptos move verify-package --account A` using the legitimate source tree.
5. Because `CachedPackageRegistry::create(..., false)` skips bytecode retrieval and `verify()` only compares metadata fields, the command prints `"Successfully verified source of package"` despite the deployed bytecode (`B_evil`) never being checked against the local compilation output.         // First build the package locally to get the package metadata
        let build_options = BuildOptions {
            install_dir: self.move_options.output_dir.clone(),
            bytecode_version: fix_bytecode_version(
                self.move_options.bytecode_version,
                self.move_options.language_version,
            ),
            ..self.included_artifacts.build_options(&self.move_options)?
        };
        let w = self.env.writer();
        let pack = BuiltPackage::build_to(&w, self.move_options.get_package_path()?, build_options)
            .map_err(|e| CliError::MoveCompilationError(format!("{:#}", e)))?;
        let compiled_metadata = pack.extract_metadata()?;

        // Now pull the compiled package
        let client = self.rest_options.client(&self.profile_options)?;
        let registry = CachedPackageRegistry::create(client, self.account, false).await?;
        let package = registry
            .get_package(pack.name())
            .await
            .map_err(|s| CliError::CommandArgumentError(s.to_string()))?;

        // We can't check the arbitrary, because it could change on us
        if package.upgrade_policy() == UpgradePolicy::arbitrary() {
            return Err(CliError::CommandArgumentError(
                "A package with upgrade policy `arbitrary` cannot be downloaded \
                since it is not safe to depend on such packages."
                    .to_owned(),
            ));
        }

        // Verify that the source digest matches
        package.verify(&compiled_metadata)?;

        Ok("Successfully verified source of package")

    pub async fn create(
        client: Client,
        addr: AccountAddress,
        with_bytecode: bool,
    ) -> anyhow::Result<Self> {
        // Need to use a different type to deserialize JSON
        let inner = client
            .get_account_resource_bcs::<PackageRegistry>(addr, "0x1::code::PackageRegistry")
            .await?
            .into_inner();
        let mut bytecode = BTreeMap::new();
        if with_bytecode {
            for pack in &inner.packages {
                for module in &pack.modules {
                    let bytes = client
                        .get_account_module(addr, &module.name)
                        .await?
                        .into_inner()
                        .bytecode
                        .0;
                    bytecode.insert(module.name.clone(), bytes);
                }
            }
        }
        Ok(Self { inner, bytecode })
    }

    pub fn verify(&self, package_metadata: &PackageMetadata) -> anyhow::Result<()> {
        let self_metadata = self.metadata;

        if self_metadata.name != package_metadata.name {
            bail!(
                "Package name doesn't match {} : {}",
                package_metadata.name,
                self_metadata.name
            )
        } else if self_metadata.deps != package_metadata.deps {
            bail!(
                "Dependencies don't match {:?} : {:?}",
                package_metadata.deps,
                self_metadata.deps
            )
        } else if self_metadata.modules != package_metadata.modules {
            bail!(
                "Modules don't match {:?} : {:?}",
                package_metadata.modules,
                self_metadata.modules
            )
        } else if self_metadata.manifest != package_metadata.manifest {
            bail!(
                "Manifest doesn't match {:?} : {:?}",
                package_metadata.manifest,
                self_metadata.manifest
            )
        } else if self_metadata.upgrade_policy != package_metadata.upgrade_policy {
            bail!(
                "Upgrade policy doesn't match {:?} : {:?}",
                package_metadata.upgrade_policy,
                self_metadata.upgrade_policy
            )
        } else if self_metadata.extension != package_metadata.extension {
            bail!(
                "Extensions doesn't match {:?} : {:?}",
                package_metadata.extension,
                self_metadata.extension
            )
        } else if self_metadata.source_digest != package_metadata.source_digest {
            bail!(
                "Source digests doesn't match {:?} : {:?}",
                package_metadata.source_digest,
                self_metadata.source_digest
            )
        }

        Ok(())
    }
