### Title
Unauthenticated pre-association of victim accounts via `associatePublicKey` precompile lets any caller force a public-key-derived address migration without proof of key possession - (File: precompiles/addr/addr.go)

### Summary
The Sei EVM `addr` precompile (`0x0000000000000000000000000000000000001004`) exposes two ways to bind a Sei address to an EVM address: `associate` (requires an ECDSA signature over a caller-supplied message, proving the caller currently controls the private key) and `associatePublicKey` (accepts only a raw compressed public key, with no signature or challenge at all). Because a secp256k1 public key is not secret - it is recoverable from any prior transaction/signature the account has ever produced - any unrelated address can submit someone else's public key to `associatePublicKey` and force that account's Sei<->EVM address association and balance migration to occur, without the victim initiating or consenting to the call. [1](#0-0) 

### Finding Description
`associate()` derives `evmAddr`, `seiAddr`, and `pubkey` from an ECDSA signature (`v, r, s`) over a `customMessage`, so a caller must actually hold the private key at call time to produce a valid signature: [2](#0-1) 

`associatePublicKey()`, however, only decodes a hex-encoded compressed public key and parses it with `btcec.ParsePubKey` - there is no signature, challenge, or any proof that the caller possesses the corresponding private key: [3](#0-2) 

Both paths funnel into `associateAddresses`, whose only guard is that the target `seiAddr` is not already associated - it never checks that the transaction sender (`caller`) is related to the derived `seiAddr`/`evmAddr` at all: [4](#0-3) 

The actual state mutation happens in `AssociationHelper.AssociateAddresses`, which sets the address mapping, sets the account pubkey if unset, and unconditionally moves any spendable coins and wei balance from the direct-cast address (`sdk.AccAddress(evmAddr[:])`) to the derived `seiAddr`, and can remove the cast account entirely: [5](#0-4) 

Because compressed public keys are freely obtainable (any signed Cosmos or EVM transaction/broadcast reveals the account's pubkey, and Cosmos-SDK auth also stores/queries pubkeys once set), an attacker can enumerate victim accounts' public keys and call `associatePublicKey` on their behalf. This lets an attacker unilaterally trigger, for any victim address of their choosing, the state transitions that are supposed to require the victim's own signed intent: creation/overwrite of the `SeiAddressToEVMAddressKey`/`EVMAddressToSeiAddressKey` mapping, setting the account's on-chain pubkey, and an unsolicited `SendCoins`/`SendCoinsAndWei` migration from the victim's direct-cast address into their real address, plus potential removal of the cast account via `RemoveAccount` if it holds no locked coins. [6](#0-5) 

This mirrors the GLPI Kanban class of bug: a state-mutating "user-account" operation that is supposed to be gated on proof of identity/ownership is reachable through an alternate code path that skips the check, letting an unprivileged caller force a change to another user's account state.

### Impact Explanation
While the derived `seiAddr`/`evmAddr` pair is cryptographically bound to the supplied pubkey (an attacker cannot redirect the migrated funds to an address they control), the attacker can still force, at a time of their choosing and without the victim's consent:
- Premature/forced migration of any balance currently held at the victim's un-associated direct-cast EVM address into the victim's Sei address, and potential removal of that cast account.
- After this forced association, `CanAddressReceive` will begin rejecting bank transfers targeting the victim's cast address (`x/evm/keeper/address.go` lines 78-86), which can break counterparties/integrations (exchanges, bridges, EVM contracts) that still expect to send funds to that raw cast address, causing subsequent legitimate transfers to that address to revert.
- Front-running a victim's own intended `associate()` call, since once `associatePublicKey` succeeds for a `seiAddr`, subsequent association attempts fail with "address already associated."

This is a state-integrity/availability issue reachable by any unprivileged EVM caller against any account, but I could not confirm a path by which an attacker can redirect funds to an address they control (the derived addresses are fixed by the supplied pubkey), so it does not clearly meet the "unauthorized transfer to attacker" bar with full certainty - the concrete harm is forced, non-consensual account-state migration and downstream transfer failures/interference for the victim, not provable attacker profit.

### Likelihood Explanation
High reachability: `associatePublicKey` is a public, unauthenticated EVM precompile method (`IsTransaction` marks it as a state-changing transaction) callable by any address with any hex-encoded valid secp256k1 public key, which is trivial to obtain for any account that has ever broadcast a signed transaction on Sei or elsewhere with a reused key. [7](#0-6) 

### Recommendation
Require proof of key possession for `associatePublicKey` (e.g., a signature challenge like `associate`), or restrict it to be self-callable only (verify the recovered `evmAddr`/`seiAddr` corresponds to `msg.sender`/`caller`), before performing `SetAddressMapping` and the balance migration in `AssociateAddresses`.

### Proof of Concept
I could not construct a runnable PoC without executing code (index-only access), but the exploit path is:
1. Attacker observes a victim's compressed secp256k1 public key (obtainable from any past signed transaction of that account).
2. Attacker calls `associate` precompile method `associatePublicKey(pubKeyHex)` from any account (no relation to the victim required).
3. `associatePublicKey` -> `helpers.GetAddressesFromPubkeyBytes` derives the victim's real `evmAddr`/`seiAddr`, then `associateAddresses` -> `AssociationHelper.AssociateAddresses` runs `SetAddressMapping` and `MigrateBalance`, moving the victim's cast-address balance and mutating account state without any transaction signed by the victim. func (p PrecompileExecutor) associate(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}

	// v, r and s are components of a signature over the customMessage sent.
	// We use the signature to construct the user's pubkey to obtain their addresses.
	v := args[0].(string)
	r := args[1].(string)
	s := args[2].(string)
	customMessage := args[3].(string)

	rBytes, err := decodeHexString(r)
	if err != nil {
		return nil, 0, err
	}
	sBytes, err := decodeHexString(s)
	if err != nil {
		return nil, 0, err
	}
	vBytes, err := decodeHexString(v)
	if err != nil {
		return nil, 0, err
	}

	vBig := new(big.Int).SetBytes(vBytes)
	rBig := new(big.Int).SetBytes(rBytes)
	sBig := new(big.Int).SetBytes(sBytes)

	// Derive addresses
	vBig = new(big.Int).Add(vBig, utils.Big27)

	customMessageHash := crypto.Keccak256Hash([]byte(customMessage))
	evmAddr, seiAddr, pubkey, err := helpers.GetAddresses(vBig, rBig, sBig, customMessageHash)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p PrecompileExecutor) associatePublicKey(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}

	// Takes a single argument, a compressed pubkey in hex format, excluding the '0x'
	pubKeyHex := args[0].(string)

	pubKeyBytes, err := hex.DecodeString(pubKeyHex)
	if err != nil {
		return nil, 0, err
	}

	// Parse the compressed public key
	pubKey, err := btcec.ParsePubKey(pubKeyBytes)
	if err != nil {
		return nil, 0, err
	}

	// Convert to uncompressed public key
	uncompressedPubKey := pubKey.SerializeUncompressed()

	evmAddr, seiAddr, pubkey, err := helpers.GetAddressesFromPubkeyBytes(uncompressedPubKey)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p PrecompileExecutor) associateAddresses(ctx sdk.Context, method *abi.Method, evmAddr common.Address, seiAddr sdk.AccAddress, pubkey cryptotypes.PubKey) (ret []byte, remainingGas uint64, err error) {
	// Check that address is not already associated
	_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if found {
		return nil, 0, fmt.Errorf("address %s is already associated with evm address %s", seiAddr, evmAddr)
	}

	// Associate Addresses:
	associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.bankKeeper, p.accountKeeper)
	err = associationHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false)
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(seiAddr.String(), evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}

func (k *Keeper) SetAddressMapping(ctx sdk.Context, seiAddress sdk.AccAddress, evmAddress common.Address) {
	store := ctx.KVStore(k.storeKey)
	store.Set(types.EVMAddressToSeiAddressKey(evmAddress), seiAddress)
	store.Set(types.SeiAddressToEVMAddressKey(seiAddress), evmAddress[:])
	if !k.accountKeeper.HasAccount(ctx, seiAddress) {
		k.accountKeeper.SetAccount(ctx, k.accountKeeper.NewAccountWithAddress(ctx, seiAddress))
	}
	ctx.EventManager().EmitEvent(sdk.NewEvent(
		types.EventTypeAddressAssociated,
		sdk.NewAttribute(types.AttributeKeySeiAddress, seiAddress.String()),
		sdk.NewAttribute(types.AttributeKeyEvmAddress, evmAddress.Hex()),
	))
}
