### Title
ProtoJSON duplicate-field detection bypass via alternate field-name spelling silently overwrites values instead of rejecting - (`python/google/protobuf/json_format.py`)

### Summary
`json_format.Parse`/`ParseDict` is supposed to reject a JSON object that sets the same proto field twice (whether via its camelCase `json_name` or its original snake_case `name`), raising `ParseError: ... should not have multiple ... fields`. The duplicate-key guard only compares the literal JSON key strings collected in `_ConvertFieldValuePair`, not the resolved `FieldDescriptor` object. Because a single field can be legally addressed by two different strings (its `json_name` and its `name`, which the parser accepts as a fallback for compatibility), an attacker can send both spellings for one field in one JSON payload and the check never fires — the second value silently overwrites the first, and no rejection occurs.

### Finding Description
`_ConvertFieldValuePair` ( [4](#0-3) ) builds `fields_by_json_name` keyed on `field.json_name`, and for each key in the input `js` dict, resolves the field first via `fields_by_json_name.get(name)`, then falls back to `message_descriptor.fields_by_name.get(name)` (the proto field name) if the json_name lookup misses. The intended per-field-once invariant is enforced only by:
```
if name in names:
    raise ParseError(... should not have multiple ... fields ...)
names.append(name)
```
This checks the raw string `name`, not the `field` it resolved to. Feeding `{"int32Value": 1, "int32_value": 2}` produces two different strings ("int32Value", "int32_value") that both resolve to the same `FieldDescriptor` for `int32_value`. Since `"int32_value" not in names` (`names` only contains `"int32Value"`), the guard never triggers, and `setattr(message, field.name, value)` is called twice, with the second value winning. The identical class of bug affects map fields via `_ConvertMapFieldValue`, which is called again on the alternate name, re-entering and overwriting the map without any merge-conflict signal ( [5](#0-4) ).

The upstream JSON duplicate-key protection at the raw-JSON level (`_DuplicateChecker`) only catches identical string keys ( [6](#0-5) ) and does not help here since the two keys are lexically different.

### Impact Explanation
This breaks the "each field set at most once" invariant that ProtoJSON parsing is documented and tested to enforce (see the sibling `testDuplicateField` test which does raise for exact-string duplicates). An ordinary client can submit a single JSON payload that appears, on cursory validation by an application (e.g., one that checks `"int32Value" in json_obj` for presence/audit purposes, or logs/validates one spelling) to set a field once, while actually causing the parser to silently accept a second, different value for that same field under an alternate key the validator didn't inspect — a "TOCTOU"-style validation bypass at the object-mapping layer. Any consuming application relying on protobuf's documented duplicate-field rejection as an integrity guarantee (e.g. detecting tampered/ambiguous requests) can be silently subverted, since the last value present under either spelling wins with no error, warning, or exception distinguishing this from a normal single-field payload.

### Likelihood Explanation
High reachability: `json_format.Parse`/`ParseDict` is a supported public parsing API for arbitrary attacker-controlled ProtoJSON text; no privileged access, custom schema, or non-default option is required — the trigger is simply supplying both the field's `json_name` and its `name` in one object, which is legal input syntax. The behavior is deterministic and already demonstrated by the project's own test suite, which explicitly labels it "a non-spec... oversight bug" that has been left unfixed only due to backward-compatibility concerns.

### Recommendation
In `_ConvertFieldValuePair`, track already-seen fields by the resolved `FieldDescriptor` object (or its number) rather than by the raw JSON key string, matching how `oneof_name` collision detection already works via `field.containing_oneof`. Raise `ParseError` when the same `FieldDescriptor` is targeted twice within one JSON object, regardless of which name variant was used, for both scalar and map/repeated fields.

### Proof of Concept
Using the existing project test as a live reproduction ( [3](#0-2) ):
```python
from google.protobuf import json_format
from google.protobuf.internal import json_format_proto3_pb2 as pb2

msg = pb2.TestMessage()
json_format.Parse('{"int32Value": 1,"int32_value":2}', msg)
assert msg.int32_value == 2   # no ParseError raised; silent overwrite, not rejection

m = pb2.TestMap()
json_format.Parse('{"int32Map": {"1": 2}, "int32_map": {"3": 4}}', m)
assert dict(m.int32_map) == {3: 4}  # entire map silently replaced, not merged/rejected
```
Compare with the exact-duplicate-string case, which correctly raises:
```python
json_format.Parse('{"int32Value": 1,\n"int32Value":2}', pb2.TestMessage())
# ParseError: Failed to load JSON: duplicate key int32Value.
```

def _DuplicateChecker(js):
  result = {}
  for name, value in js:
    if name in result:
      raise ParseError('Failed to load JSON: duplicate key {0}.'.format(name))
    result[name] = value
  return result

  def _ConvertFieldValuePair(self, js, message, path):
    """Convert field value pairs into regular message.

    Args:
      js: A JSON object to convert the field value pairs.
      message: A regular protocol message to record the data.
      path: parent path to log parse error info.

    Raises:
      ParseError: In case of problems converting.
    """
    names = []
    message_descriptor = message.DESCRIPTOR
    fields_by_json_name = dict(
        (f.json_name, f) for f in message_descriptor.fields
    )

    def _ClearFieldOrExtension(message, field):
      if field.is_extension:
        message.ClearExtension(field)
      else:
        message.ClearField(field.name)

    def _GetFieldOrExtension(message, field):
      if field.is_extension:
        return message.Extensions[field]
      else:
        return getattr(message, field.name)

    def _SetFieldOrExtension(message, field, value):
      if field.is_extension:
        message.Extensions[field] = value
      else:
        setattr(message, field.name, value)

    for name in js:
      try:
        field = fields_by_json_name.get(name, None)
        if not field:
          field = message_descriptor.fields_by_name.get(name, None)
