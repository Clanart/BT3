### Title
Forfeiture avoidance on MGP yield via same-block `cancelUnlock` before `queueMGP` settlement - (File: `rewards/vlMGPBaseRewarder.sol`, `VLMGP.sol`)

### Summary
`vlMGPBaseRewarder.queueMGP` computes the forfeited portion of harvested MGP using `vlMGP.getRewardablePercentWAD(_account)` evaluated at the *time of settlement*, not at the time the MGP was actually emitted. Because `VLMGP.cancelUnlock` is the only unlock-state-mutating function that does **not** force a `multiclaimFor` settlement before changing `amountInCoolDown`, an attacker can reset an expired/aging cooldown slot back to "fully locked" status immediately before triggering a `MasterMagpie` harvest, inflating their rewardable percentage snapshot and evading the forfeiture that should apply to MGP that accrued while their cooldown was expired and decaying.

### Finding Description
`_calExpireForfeit` in `rewards/vlMGPBaseRewarder.sol` (lines 386-400) determines how much of a harvested MGP amount is forfeited by calling `vlMGP.getRewardablePercentWAD(_account)` at the moment `queueMGP` executes: [1](#0-0) 

`getRewardablePercentWAD` in `VLMGP.sol` (lines 193-218) computes the percent based on the account's *current* lock/cooldown composition: fully-locked balances count at 100%, cooldown slots that are still within their cooldown window count at full weight, and only slots whose `endTime` has already passed have their rewardable weight decay over time: [2](#0-1) 

`startUnlock` (lines 275-311) and `unlock` (lines 315-337) both call `IMasterMagpie(masterMagpie).multiclaimFor(...)` **before** mutating `userUnlockings` state, forcing any pending MGP to be settled (and forfeiture calculated) against the pre-mutation lock state: [3](#0-2) [4](#0-3) 

`cancelUnlock` (lines 339-349), however, mutates `slot.amountInCoolDown = 0` and `totalAmountInCoolDown` directly with **no** prior `multiclaimFor` call: [5](#0-4) 

This asymmetry means an attacker who has an expired cooldown slot (past `endTime`, where `getRewardablePercentWAD` is decaying that slot's weight due to elapsed time) can call `cancelUnlock` to instantly zero out that slot's `amountInCoolDown`. This removes the decayed slot from the `userTotalVlmgp` denominator and folds its value back into `fullyInLock` (100% weight) for the purposes of `getRewardablePercentWAD`, without any harvest occurring first. If the attacker immediately follows with a call that triggers `MasterMagpie._sendMGPForVlMGPPool` → `vlMGPBaseRewarder.queueMGP` (lines 274-289), the forfeiture calculation in `_calExpireForfeit` uses this artificially inflated, freshly-reset rewardable percentage instead of the lower percentage that applied throughout the actual MGP-emission period: [6](#0-5) [7](#0-6) 

No modifier, receipt-token accounting, or reward-index mechanism prevents this: `queueMGP` only has `onlyManager` and `nonReentrant`, neither of which addresses the state-timing issue, and `cancelUnlock` only has `whenNotPaused` (no `nonReentrant`, no forced settlement).

### Impact Explanation
This allows an unprivileged staker to reduce or entirely avoid the forfeiture that should apply to MGP emitted while their cooldown balance's rewardable weight was decayed, by resetting their cooldown state in the same transaction/block immediately preceding a harvest. The forfeited amount that the attacker avoids paying would otherwise be redistributed to other vlMGP stakers via `_queueNewRewardsWithoutTransfer`, so this is a direct theft of unclaimed yield from the pool of other stakers (Immunefi: "Theft of unclaimed yield").

### Likelihood Explanation
Preconditions are fully within reach of any unprivileged staker: hold vlMGP with MGP emissions routed through the vlMGP pool, have an unlock slot whose cooldown has expired but is not yet claimed (a normal occurrence if a user doesn't immediately call `unlock`), then call `cancelUnlock` followed by any action that triggers a harvest (e.g., `startUnlock` on another slot, `multiclaimFor`, or any deposit/withdraw path that harvests). No special capital or privileged role is required, and the exploit is repeatable every time the attacker lets a cooldown slot expire before harvesting.

### Recommendation
Make `cancelUnlock` settle pending rewards before mutating cooldown state, mirroring `startUnlock`/`unlock`, e.g. call `IMasterMagpie(masterMagpie).multiclaimFor(...)` for `address(this)`/vlMGP pool before zeroing `slot.amountInCoolDown`. More robustly, `_calExpireForfeit` should not rely purely on point-in-time `getRewardablePercentWAD`; forfeiture should be computed against the lock state that was in effect when the corresponding MGP accrued (e.g., by forcing settlement on every state-changing lock/unlock operation, or by tracking a time-weighted/checkpointed rewardable percent rather than an instantaneous one).

### Proof of Concept
Foundry test plan:
1. Deploy `VLMGP`, `vlMGPBaseRewarder`, `MasterMagpie`, `MGP` token with test configuration.
2. Attacker locks MGP, then calls `startUnlock` for a portion, advance time past `coolDownInSecs` (slot now expired/decaying), and advance further so `getRewardablePercentWAD` reflects meaningful decay for that slot.
3. Let MGP emissions accrue in `MasterMagpie` during this whole window (pending unclaimed MGP builds up for the vlMGP pool via `_calNewMGP`).
4. **Baseline run**: directly trigger the harvest path (`multiclaimFor` → `_sendMGPForVlMGPPool` → `queueMGP`) without calling `cancelUnlock`; record `forfeitAmount` emitted in `MGPHarvested`/`ForfeitRewardAdded`.
5. **Attack run** (fresh identical setup/emission history): call `cancelUnlock` on the expired slot in the same block immediately before triggering the same harvest path; record `forfeitAmount`.
6. Assert `forfeitAmount_attack < forfeitAmount_baseline` for the same accrued `_amount`, proving the attacker reduces/eliminates forfeiture purely by reordering `cancelUnlock` before harvest, with no additional MGP contributed.

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalVlmgp = fullyInLock + inCoolDown;
        if (userTotalVlmgp == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalVlmgp;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalVlmgp / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalVlmgp;
                }

            }
        }

        return percent;
    }
