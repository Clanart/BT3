## Title
Unauthenticated OP_RETURN operator attribution in payout transactions allows forged reimbursement credit and double-payout of bridge funds - (`core/src/builder/transaction/operator_reimburse.rs`)

### Summary
`create_payout_txhandler` only binds the withdrawer's `SinglePlusAnyoneCanPay` signature to input index 0 and output index 0; the OP_RETURN output carrying `operator_xonly_pk` (output index 2) and any additional funding inputs are completely unauthenticated. Anyone possessing the withdrawer's disclosed signature can therefore rebuild an equally valid payout transaction, self-fund the withdrawal output, name an arbitrary (real) operator's public xonly key in the OP_RETURN, and broadcast it first, causing that operator's fully automated `PayoutCheckerTask` to claim reimbursement from the move-to-vault UTXO for a payout it never funded.

### Finding Description
The claimed binding is: `withdrawals.payout_payer_operator_xonly_pk` (written by `update_payout_txs_and_payer_operator_xonly_pk`, [1](#0-0) ) == the identity of the party that actually supplied the BTC value paid out in the confirmed payout transaction.

`create_payout_txhandler` builds the payout tx with a single signed input (the withdrawal UTXO) and three outputs: user payout (idx 0), anchor (idx 1), and OP_RETURN with `operator_xonly_pk` (idx 2), then applies only the user's key-spend witness: [2](#0-1) . The operator's `withdraw()` flow verifies this signature against sighash of *txin 0 only* (`calculate_sighash_txin(0, ...)`), then calls bitcoind's `fund_raw_transaction` with `add_inputs: true` to append the operator's own funding inputs: [3](#0-2) [4](#0-3) . Because the signature type is `SinglePlusAnyoneCanPay`, it authenticates only input 0 and output 0 — additional inputs (funding) and outputs (anchor, OP_RETURN) are entirely unauthenticated by the user's key, by design, to let a party add its own funding UTXOs.

`update_finalized_payouts` derives the DB attribution purely by looking at whichever transaction confirms first spending the registered `withdrawal_utxo` (matched via `bitcoin_syncer_spent_utxos`, joined in `get_payout_txs_for_withdrawal_utxos`), then blindly parses the first OP_RETURN for an xonly pubkey with no cryptographic check that this pubkey belongs to whoever actually funded the tx: [5](#0-4) .

`PayoutCheckerTask::run_once` then automatically, without any additional verification (e.g., checking its own wallet/broadcast history), polls for payouts attributed to its own key and immediately proceeds to `handle_finalized_payout` (kickoff/reimbursement flow): [6](#0-5) . `is_kickoff_malicious` (run by verifiers) only checks that `operator_xonly_pk` in the OP_RETURN equals `kickoff_data.operator_xonly_pk` and that the committed payout blockhash matches — both of which the attacker can trivially satisfy since they choose the OP_RETURN content and the actual confirmed block: [7](#0-6) .

Exploit flow: attacker (the withdrawer, or anyone who observes the disclosed `WithdrawParamsWithSig` gRPC signature) constructs their own payout transaction reusing the signed input/output pair, adds their own funding input(s) sufficient to cover `output_amount` (paid right back to their own `output_script_pubkey`, so net attacker cost ≈ mining fees only), attaches an OP_RETURN naming a real, uninvolved operator's public xonly key, and races to get it mined before the honest operator's own funded payout tx. If it confirms first, the honest operator's competing tx (spending the same now-consumed withdrawal UTXO) is permanently invalidated, and the DB permanently records the attacker-chosen (possibly uninvolved) operator as payer. That named operator's automation later autonomously executes kickoff and reimbursement for a payout it never made, draining the move-to-vault deposit — while the withdrawer already received funds from the attacker's self-funded transaction, i.e. bridge value is paid out twice for a single L2 withdrawal, or the true funding operator is permanently locked out.

### Impact Explanation
This directly hits two Critical categories: (1) BTC leaves a move-to-vault UTXO without a matching fronted withdrawal from the credited operator (the named operator is reimbursed for funds it never provided), and (2) an honest operator who did front the real payout is permanently unable to be reimbursed once its payout tx's shared input is consumed by the attacker's decoy. The attack is repeatable across every withdrawal and every operator, since the only precondition is possession of a `SinglePlusAnyoneCanPay` signature that is routinely disclosed to operators (and observable once broadcast to the mempool) and knowledge of any operator's public xonly key (public information).

### Likelihood Explanation
The attacker only needs standard unprivileged capabilities already assumed in scope: ability to withdraw on Citrea, obtain/observe a withdrawal signature, fund a small self-paid Bitcoin transaction, and win a normal mempool/fee race — no verifier, operator, or aggregator privilege is required. Attacker cost is limited to Bitcoin mining fees (the payout amount itself returns to the attacker's own address since they are the withdrawer), making this a cheap, highly repeatable attack across withdrawals.

### Recommendation
Cryptographically bind the OP_RETURN `operator_xonly_pk` (and ideally the funding inputs) to the claimed operator, e.g., by requiring the operator to co-sign the payout transaction (adding an operator signature/commitment covering the OP_RETURN output), or by having verifiers validate that the party the DB names as payer can prove control of the funding inputs (e.g., via a MuSig2/co-signed structure) rather than trusting an arbitrary, unauthenticated OP_RETURN byte string. At minimum, `PayoutCheckerTask` should not blindly trust `payout_payer_operator_xonly_pk`; the operator should independently verify it actually broadcast/funded the specific payout txid before starting kickoff.

                payout_txid = c.payout_txid,

                payout_tx_blockhash = c.payout_tx_blockhash

                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
