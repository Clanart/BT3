### Title
Coinbase outputs reported as spendable by `Scanner::scan_block`, locking funds scheduled against them - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_block` iterates over `block.txdata` including `txdata[0]`, the coinbase transaction. Outputs paying Serai's P2TR script inside a coinbase are returned by `scan_transaction` as ordinary `ReceivedOutput`s, indistinguishable from immediately-spendable UTXOs, even though the coinbase subsidy/outputs are unspendable for `COINBASE_MATURITY` (100) blocks under Bitcoin consensus rules.

### Finding Description
`Scanner::scan_transaction` matches purely on `output.script_pubkey` membership in `self.scripts` and emits a `ReceivedOutput` with no maturity check [1](#0-0) . `scan_block` explicitly feeds the coinbase transaction through it, merely noting in a doc comment that "a post-processing pass is needed" if immediate spendability is required [2](#0-1) . The `ReceivedOutput` produced carries a real offset, script, and outpoint [3](#0-2) , so `SignableTransaction::new` will accept it as an input and `TransactionSignMachine::sign` will produce a fully signed transaction [4](#0-3) . That transaction is consensus-invalid until maturity: nodes will reject it from the mempool, and any batching logic that bundles the immature coinbase input together with legitimate inputs has the entire spend rejected, not just the coinbase leg.

### Impact Explanation
An immature coinbase output is counted in the wallet's spendable set. If it is selected as an input, the resulting transaction fails relay, and — worse — since `SignableTransaction` aggregates all inputs into one tx, a single immature input poisons every other input in the same transaction. Those co-spent inputs are effectively locked for the remainder of the maturity window (up to 100 blocks) or until the transaction is rebuilt without the bad input. This maps directly onto the source report's class: funds present and accounted for, yet unspendable due to a state condition the spending path does not guard against.

### Likelihood Explanation
Any miner is an unprivileged party capable of paying the Serai P2TR script from a coinbase transaction — either deliberately (the script is public) or incidentally (e.g., a pool paying a participant who supplied a Serai deposit address, or an attacker mining/regtest-style grinding to grief the set). No threshold compromise, collusion, or privileged access is required; the trigger is a transaction appearing on-chain, which is precisely the untrusted input surface `scan_block` consumes. Severity is bounded because the lock is temporary (self-resolving after 100 confirmations) and requires the scheduler to select the output, so this rates Medium rather than High.

### Recommendation
Filter coinbase transactions out of `scan_block` (skip `block.txdata[0]`, as the doc comment already suggests for `scan_transaction`), or tag `ReceivedOutput`s derived from coinbase transactions with a maturity height and exclude them from input selection until `block_height - coinbase_height >= 100`. If coinbase deposits must be supported, they should only enter the spendable set once mature.

### Proof of Concept
1. A miner constructs a block whose coinbase transaction contains an output paying `p2tr_script_buf(serai_key)` (or any registered offset script).
2. `Scanner::scan_block(&block)` returns a `ReceivedOutput` for that coinbase output — `scan_transaction` applies no coinbase discrimination [5](#0-4) .
3. The output is passed to `SignableTransaction::new(vec![coinbase_output, other_outputs], ...)`, which succeeds since nothing validates maturity [6](#0-5) .
4. `multisig`/`sign`/`complete` produce a validly signed transaction, but Bitcoin Core rejects it at mempool admission ("bad-txns-premature-spend-of-coinbase"), so neither the coinbase output nor the co-spent honest inputs move until the transaction is rebuilt or maturity elapses.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res

  /// Scan a block.
  ///
  /// This will also scan the coinbase transaction which is bound by maturity. If received outputs
  /// must be immediately spendable, a post-processing pass is needed to remove those outputs.
  /// Alternatively, scan_transaction can be called on `block.txdata[1 ..]`.
  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }

  pub fn new(
    mut inputs: Vec<ReceivedOutput>,
    payments: &[(ScriptBuf, u64)],
    change: Option<ScriptBuf>,
    data: Option<Vec<u8>>,
    fee_per_vbyte: u64,
  ) -> Result<SignableTransaction, TransactionError> {
    if inputs.is_empty() {
      Err(TransactionError::NoInputs)?;
    }

    if payments.is_empty() && change.is_none() && data.is_none() {
      Err(TransactionError::NoOutputs)?;
    }

    for (_, amount) in payments {
      if *amount < DUST {
        Err(TransactionError::DustPayment)?;
      }
    }

    if data.as_ref().map_or(0, Vec::len) > 80 {
      Err(TransactionError::TooMuchData)?;
    }

    let input_sat = inputs.iter().map(|input| input.output.value.to_sat()).sum::<u64>();
    let offsets = inputs.iter().map(|input| input.offset).collect();
    let tx_ins = inputs
      .iter()
      .map(|input| TxIn {
        previous_output: input.outpoint,
        script_sig: ScriptBuf::new(),
        sequence: Sequence::MAX,
        witness: Witness::new(),
      })
      .collect::<Vec<_>>();

    let payment_sat = payments.iter().map(|payment| payment.1).sum::<u64>();
    let mut tx_outs = payments
      .iter()
      .map(|payment| TxOut { value: Amount::from_sat(payment.1), script_pubkey: payment.0.clone() })
      .collect::<Vec<_>>();

    // Add the OP_RETURN output
    if let Some(data) = data {
      tx_outs.push(TxOut {
        value: Amount::ZERO,
        script_pubkey: ScriptBuf::new_op_return(
          PushBytesBuf::try_from(data)
            .expect("data didn't fit into PushBytes depsite being checked"),
        ),
      })
    }

    let (mut weight, vbytes) = Self::calculate_weight_vbytes(tx_ins.len(), payments, None);

    let mut needed_fee = fee_per_vbyte * vbytes;
    // Technically, if there isn't change, this TX may still pay enough of a fee to pass the
    // minimum fee. Such edge cases aren't worth programming when they go against intent, as the
    // specified fee rate is too low to be valid
    // bitcoin::policy::DEFAULT_MIN_RELAY_TX_FEE is in sats/kilo-vbyte
    if needed_fee < ((u64::from(bitcoin::policy::DEFAULT_MIN_RELAY_TX_FEE) * vbytes) / 1000) {
      Err(TransactionError::TooLowFee)?;
    }

    if input_sat < (payment_sat + needed_fee) {
      Err(TransactionError::NotEnoughFunds {
        inputs: input_sat,
        payments: payment_sat,
        fee: needed_fee,
      })?;
    }

    // If there's a change address, check if there's change to give it
    if let Some(change) = change {
      let (weight_with_change, vbytes_with_change) =
        Self::calculate_weight_vbytes(tx_ins.len(), payments, Some(&change));
      let fee_with_change = fee_per_vbyte * vbytes_with_change;
      if let Some(value) = input_sat.checked_sub(payment_sat + fee_with_change) {
        if value >= DUST {
          tx_outs.push(TxOut { value: Amount::from_sat(value), script_pubkey: change });
          weight = weight_with_change;
          needed_fee = fee_with_change;
        }
      }
    }

    if tx_outs.is_empty() {
      Err(TransactionError::NoOutputs)?;
    }

    if weight > u64::from(bitcoin::policy::MAX_STANDARD_TX_WEIGHT) {
      Err(TransactionError::TooLargeTransaction)?;
    }

    Ok(SignableTransaction {
      tx: Transaction {
        version: Version(2),
        lock_time: LockTime::ZERO,
        input: tx_ins,
        output: tx_outs,
      },
      offsets,
      prevouts: inputs.drain(..).map(|input| input.output).collect(),
      needed_fee,
    })
  }
