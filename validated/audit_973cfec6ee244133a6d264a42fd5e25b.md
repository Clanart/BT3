### Title
Out-of-bounds slice access in auction bid signature verification (`getSigner`) - ([File: kaiax/auction/bid.go])

### Summary
`getSigner()` in `kaiax/auction/bid.go` reads fixed offsets (`[0:32]`, `[32:64]`, index `64`) from an externally-supplied signature byte slice without first validating its length, mirroring the CVE-2019-20912 bug class (a fixed-size buffer read/parse routine invoked on attacker-controlled data without a preceding length check). An unprivileged auction bidder can submit a `Bid` whose `SearcherSig`/`AuctioneerSig` is shorter than 65 bytes to trigger an out-of-bounds slice access.

### Finding Description
`BidData.SearcherSig` and `BidData.AuctioneerSig` are plain `[]byte` fields populated directly from bid submissions (JSON/RLP decoded, no fixed-length struct tag or length validation) [1](#0-0) .

`ValidateSearcherSig` and `ValidateAuctioneerSig` pass these attacker-controlled slices straight into `getSigner` [2](#0-1) .

`getSigner` immediately indexes `copiedSig[crypto.RecoveryIDOffset]` (offset 64) and slices `copiedSig[0:32]` and `copiedSig[32:64]` before any length check is performed: [3](#0-2) 

If `sig` (i.e., `SearcherSig` or `AuctioneerSig`) has length less than 65 bytes (including empty/nil), `slices.Clone(sig)` preserves that short length, and the subsequent index/slice operations on `copiedSig` will panic with "index out of range" or "slice bounds out of range" — a Go runtime panic caused entirely by unchecked external input length, analogous to the unchecked fixed-size buffer read in LibreDWG's `bit_read_TF` that caused a stack overflow on crafted input.

No caller in the shown code path (`ValidateSearcherSig`/`ValidateAuctioneerSig`) validates `len(SearcherSig) == 65` or `len(AuctioneerSig) == 65` prior to calling `getSigner`, and no length assertion exists inside `getSigner` itself.

### Impact Explanation
The auction module is explicitly listed as an in-scope, externally reachable path (gasless/auction settlement). A crafted bid with a truncated signature reaching `ValidateSearcherSig`/`ValidateAuctioneerSig` causes an unrecovered panic in the goroutine processing the bid. Depending on whether the bid-processing call path recovers panics, this can crash or destabilize the node handling auction bid admission, denying auction service to legitimate bidders/auctioneers (denial of service in the auction settlement pipeline). This does not achieve memory corruption (Go slice panics are safe, unlike the C stack overflow in the original CVE), but it is a concrete, unauthenticated-input-triggered crash in a value-bearing settlement path.

### Likelihood Explanation
High likelihood: any unprivileged party able to submit an auction bid (searcher or auctioneer signature field) can supply a `SearcherSig`/`AuctioneerSig` shorter than 65 bytes with zero cost or special privilege. No prior authentication or signature validity is needed to reach the vulnerable code — the length/index issue occurs before signature validity is checked.

### Recommendation
Add an explicit length check (`len(sig) != 65`) at the start of `getSigner` (and/or in `ValidateSearcherSig`/`ValidateAuctioneerSig` before calling `getSigner`), returning `ErrInvalidSignature` for any signature not exactly `crypto.SignatureLength` (65) bytes, matching the pattern already used in `crypto.Ecrecover`/`crypto/secp256k1.checkSignature`.

### Proof of Concept
1. Construct a `BidData` with `SearcherSig` set to a byte slice shorter than 65 bytes (e.g., `[]byte{}` or a 10-byte slice) and submit it as a bid (`Bid.ValidateSearcherSig` is invoked during bid admission/validation).
2. `getSigner(b.SearcherSig, digest)` is called; `slices.Clone(sig)` yields a short slice.
3. `copiedSig[crypto.RecoveryIDOffset]` (index 64) panics with "index out of range" since `len(copiedSig) < 65`.
4. The panic propagates out of `getSigner` → `ValidateSearcherSig`, crashing/terminating the goroutine (or the node process, if unrecovered) that handles bid validation.

Note: I was unable to fully verify whether the calling code in `kaiax/auction/impl/bid_pool.go` wraps bid validation in a `recover()` (I found matches for signature-length-related checks there but could not inspect the full file contents due to tool-call limits reached before completing this trace). If `bid_pool.go` already enforces a 65-byte length check or wraps validation in a panic-recovery handler before calling `ValidateSearcherSig`/`ValidateAuctioneerSig`, the practical exploitability of this panic would be reduced to a recoverable per-bid rejection rather than a node crash — this should be confirmed by reviewing `kaiax/auction/impl/bid_pool.go` in full.

func (b *Bid) ValidateSearcherSig(chainId *big.Int, verifyingContract common.Address, version string) error {
	if chainId == nil {
		return ErrNilChainId
	}

	if common.EmptyAddress(verifyingContract) {
		return ErrNilVerifyingContract
	}

	digest := b.GetHashTypedData(chainId, verifyingContract, version)

	recoveredSender, err := getSigner(b.SearcherSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover searcher sig: %v", err)
	}

	if recoveredSender != b.Sender {
		return fmt.Errorf("invalid searcher sig: expected %v, calculated %v", b.Sender.String(), recoveredSender.String())
	}

	return nil
}

func (b *Bid) ValidateAuctioneerSig(auctioneer common.Address) error {
	digest := b.GetEthSignedMessageHash()

	recoveredAuctioneer, err := getSigner(b.AuctioneerSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover auctioneer sig: %v", err)
	}

	if recoveredAuctioneer != auctioneer {
		return fmt.Errorf("invalid auctioneer sig: expected %v, calculated %v", auctioneer.String(), recoveredAuctioneer.String())
	}

	return nil
}

func getSigner(sig, digest []byte) (common.Address, error) {
	// Manually convert V from 27/28 to 0/1
	copiedSig := slices.Clone(sig)
	if copiedSig[crypto.RecoveryIDOffset] == 27 || copiedSig[crypto.RecoveryIDOffset] == 28 {
		copiedSig[crypto.RecoveryIDOffset] -= 27
	}

	v := copiedSig[crypto.RecoveryIDOffset]
	r := new(big.Int).SetBytes(copiedSig[0:32])
	s := new(big.Int).SetBytes(copiedSig[32:64])
	if !crypto.ValidateSignatureValues(v, r, s, true) {
		return common.Address{}, ErrInvalidSignature
	}
