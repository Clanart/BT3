### Title
SchnorrAggregate::verify binds weights only to challenges, not to nonces/public keys, enabling trivial aggregate forgery - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate` implements Schnorr half-aggregation (eprint 2021/350). The per-signature weights `z_i` are drawn from a `DigestTranscript` that absorbs **only** the caller-supplied challenges — never the nonce commitments `Rs` nor the public keys. Because `Rs` inside the aggregate are attacker-controlled bytes parsed by `SchnorrAggregate::read` (`C::read_G`), an attacker can choose `Rs` *after* computing all weights and forge an aggregate signature that verifies under arbitrary public keys/challenges without knowing any private key. [1](#0-0) 

### Finding Description
`verify` builds the transcript as:

```
digest.domain_separate(b"signatures");
for (_, challenge) in keys_and_challenges {
  digest.append_message(b"challenge", challenge.to_repr());
}
```

then computes `z = weight(&mut digest)` per index and checks `Σ z_i·R_i + Σ z_i·c_i·A_i − s·G == 0` via `multiexp_vartime`. [2](#0-1) 

In the referenced scheme the weights must be bound to the full statement `(R_i, A_i, m_i)` so the prover commits to the nonces before learning `z_i`. Here `R_i` are deserialized from untrusted bytes by `SchnorrAggregate::read` with no binding into the transcript, so a forger knows every `z_i` before choosing any `R_i`. [3](#0-2) 

Analog to the report's bug class: an untrusted-input validation gap in a security component — inputs that should be cryptographically bound are not, letting unauthenticated public input produce a forged signature accepted by `verify`.

### Impact Explanation
Forgery is linear algebra, not discrete-log:

1. Pick arbitrary `(A_i, c_i)` pairs (any public keys, any messages' challenges).
2. Compute all `z_i` locally (they depend only on `dst` and `c_i`).
3. Pick random `r_i`, set `R_i = r_i·G − c_i·A_i`, set `s = Σ z_i·r_i`.
4. `Σ z_i·R_i + Σ z_i·c_i·A_i − s·G = Σ z_i·r_i·G − s·G = 0` — verifies.

The result is a forged aggregate signature valid for keys whose private keys the attacker does not know — a universal forgery against any consumer of `SchnorrAggregate::verify` reachable from untrusted bytes (`read` → `verify`).

### Likelihood Explanation
`SchnorrAggregate::read` accepts arbitrary canonical points for `Rs` and an arbitrary scalar `s`; both are fully attacker-controlled. Any in-scope caller that deserializes an aggregate from a peer/message and calls `verify` (e.g., coordinator aggregation of validator signatures) is exploitable with zero key knowledge and zero interaction. Likelihood is high wherever this API is exposed to untrusted input.

### Recommendation
Bind the full statement into the weight transcript: before drawing each weight, `append_message` the encoding of each `R_i` (and ideally each public key), i.e., transcript `R_1..R_n`, `A_1..A_n`, and the challenges, matching eprint 2021/350 where `z_i = H(AggInfo || R_i || A_i || m_i)`. Update `SchnorrAggregator::aggregate`/`complete` symmetrically — currently the signer side also only absorbs challenges (lines 169–184), so both sides must commit to `Rs` before deriving weights. [4](#0-3) 

### Proof of Concept
```rust
// Attacker-only code; produces a SchnorrAggregate accepted by verify()
// for public keys A_i it does not control.

fn forge<C: Ciphersuite>(dst: &'static [u8], kas: &[(C::G, C::F)]) -> SchnorrAggregate<C> {
  // Reproduce the weight schedule: depends only on dst + challenges
  let mut digest = DigestTranscript::<C::H>::new(dst);
  digest.domain_separate(b"signatures");
  for (_, c) in kas { digest.append_message(b"challenge", c.to_repr()); }

  let mut rng = OsRng;
  let mut Rs = vec![];
  let mut s = C::F::ZERO;
  for (A, c) in kas {
    let z = weight::<_, C::F>(&mut digest);          // same as verifier's z_i
    let r = C::F::random(&mut rng);
    Rs.push((C::generator() * r) - (*A * *c));        // R_i = r_i·G − c_i·A_i
    s += z * r;
  }
  SchnorrAggregate { Rs, s }  // passes verify(dst, kas)
}
```
Each `R_i` is canonical and parses cleanly via `SchnorrAggregate::read`; `verify` returns `true` despite no private key being known.
