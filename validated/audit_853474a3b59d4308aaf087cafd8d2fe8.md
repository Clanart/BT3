### Title
`WombatStaking.depositLP` mints receipt tokens based on nominal input amount instead of actual LP tokens received, breaking accounting for fee-on-transfer / deflationary LP tokens - (File: wombat/WombatStaking.sol)

### Summary
`WombatStaking.deposit()` correctly measures the actual amount of Wombat LP tokens received by taking a before/after balance snapshot before minting receipt tokens, but the sibling function `WombatStaking.depositLP()` mints receipt tokens equal to the raw `_lpAmount` parameter without verifying how many tokens were actually received by the contract via `safeTransferFrom`.

### Finding Description
In `deposit()`, the contract explicitly guards against transfer-amount mismatches: [1](#0-0) 

In contrast, `depositLP()` transfers the LP token directly from the caller and then mints receipt tokens and stakes into MasterWombat using the *nominal* `_lpAmount`, with no balance-diff check: [2](#0-1) 

`depositLP` is reachable by any ordinary wallet through the pool helper contracts, e.g. `WombatPoolHelper.depositLP` / `WombatPoolHelperV2.depositLP` / `AnkrBNBPoolHelper.depositLP`, all of which forward `_lpAmount` unchanged into `IWombatStaking.depositLP`: [3](#0-2) [4](#0-3) 

If the underlying Wombat LP/Asset token (`poolInfo.lpAddress`) were ever a fee-on-transfer or rebasing/deflationary token, `safeTransferFrom(_for, address(this), _lpAmount)` would deliver less than `_lpAmount` tokens to `WombatStaking`, yet the contract would still: (1) mint `_lpAmount` receipt tokens to the depositor via `IMintableERC20(poolInfo.receiptToken).mint(msg.sender, _lpAmount)`, and (2) attempt to stake `_lpAmount` (more than it actually holds) via `_toMasterWomAndSendReward(_lpAddress, _lpAmount, true)`. This creates a permanent mismatch between the receipt token supply (representing claims) and the actual LP tokens custodied/staked by the protocol.

### Impact Explanation
This directly threatens protocol solvency for the affected pool: receipt token holders collectively have claims exceeding the actual LP backing held by `WombatStaking`. When later depositors/withdrawers attempt to redeem via `withdraw()`, some legitimate receipt-token holders would be unable to fully withdraw their entitled LP/underlying tokens because the pool is under-collateralized — a form of permanent freezing/loss of user funds and protocol insolvency for that pool, matching the accepted-impact criteria (protocol insolvency / permanent freezing of funds).

### Likelihood Explanation
The likelihood is contingent on a pool being configured with a fee-on-transfer or deflationary Wombat LP/Asset token as `poolInfo.lpAddress`. Standard Wombat Asset tokens (as deployed by the Wombat protocol) are not fee-on-transfer today, so under current pool configurations this path is not actively exploitable. However, the code contains no defensive check, and the sibling `deposit()` function demonstrates the developers are aware of and already mitigate this exact bug class for the non-LP deposit path — but failed to apply the same mitigation consistently in `depositLP()`. Any future pool added with a nonstandard LP/wrapper token exhibiting a transfer fee would immediately trigger the mismatch with zero additional privilege required, purely from an ordinary user's `depositLP` call.

### Recommendation
In `WombatStaking.depositLP()`, use a before/after balance check on `poolInfo.lpAddress` (as already done in `deposit()`) to compute the actually-received LP amount, and use that value (not the raw `_lpAmount` parameter) both for `_toMasterWomAndSendReward` and for the receipt-token `mint` call:

```solidity
uint256 beforeBalance = IERC20(poolInfo.lpAddress).balanceOf(address(this));
IERC20(poolInfo.lpAddress).safeTransferFrom(_for, address(this), _lpAmount);
uint256 lpReceived = IERC20(poolInfo.lpAddress).balanceOf(address(this)) - beforeBalance;

_toMasterWomAndSendReward(_lpAddress, lpReceived, true);
IMintableERC20(poolInfo.receiptToken).mint(msg.sender, lpReceived);
```

### Proof of Concept
1. Governance/operator adds a pool where `poolInfo.lpAddress` is (or is later upgraded/replaced with) a fee-on-transfer token (e.g. a wrapped asset charging 1% transfer tax).
2. A user calls `WombatPoolHelper.depositLP(1000)`, which calls `IWombatStaking.depositLP(lpToken, 1000, user)`. [3](#0-2) 
3. Inside `WombatStaking.depositLP`, `safeTransferFrom(user, address(this), 1000)` actually delivers only 990 tokens to the contract due to the fee, but the function still mints 1000 receipt tokens to the user and attempts to stake 1000 units into MasterWombat. [5](#0-4) 
4. Over repeated deposits, the receipt token supply for that pool grows faster than the actual LP tokens custodied/staked, so later withdrawers cannot be fully repaid — resulting in permanent fund loss/insolvency for the pool.
