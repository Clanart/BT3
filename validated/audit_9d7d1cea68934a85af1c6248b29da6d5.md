### Title
Unauthenticated TxSender JSON-RPC Server Allows Any Network-Reachable Party to Submit Arbitrary Transactions and Drain Fee-Paying UTXOs — (`crates/clementine-tx-sender/src/jsonrpc/server.rs`)

### Summary

The standalone `clementine-tx-sender` JSON-RPC server exposes `send_tx` (and `send_citrea_tx`) with zero authentication. When the service is bound to `0.0.0.0` — an explicitly supported and validated configuration option — any network-reachable party can enqueue arbitrary Bitcoin transactions for broadcast, force the tx-sender to spend its own fee-paying UTXOs via CPFP, and supply `cancel_txids`/`cancel_outpoints` to mark legitimate pending bridge transactions as cancelled in the database. This is the direct Clementine analog of the L2LivepeerToken `MINTER_ROLE` issue: a privileged bridge action (transaction submission and queue management) is gated by no access control at all.

The JSON-RPC server has no equivalent protection at any configuration value.

**Attack flow:**

1. Operator deploys standalone `clementine-tx-sender` with `TX_SENDER_JSONRPC_BIND=0.0.0.0` and `TX_SENDER_JSONRPC_PORT=3030`.
2. Attacker discovers the open port (no firewall, or misconfigured network policy).
3. **CPFP drain**: Attacker submits many `send_tx` calls with `fee_paying_type: "CPFP"` and syntactically valid but unconfirmable transactions. The tx-sender creates child transactions spending its own fee-payer UTXOs for each, exhausting the operator's fee-paying balance.
4. **Queue cancellation**: Attacker submits a `send_tx` call with `cancel_txids` containing the txids of legitimate pending bridge transactions (kickoff, reimbursement, payout). Those entries are marked cancelled in the PostgreSQL queue and are no longer broadcast.
5. Legitimate bridge transactions (kickoff, reimbursement) are not confirmed before their timelocks expire.

### Impact Explanation

- **tx-sender-managed balances drained**: The tx-sender's fee-paying UTXOs are spent on attacker-controlled CPFP children. This is direct loss of tx-sender-managed balances, within the allowed impact gate.
- **Liveness failure / permanent lock**: If kickoff or reimbursement transactions are cancelled from the queue and their timelocks expire, the operator loses the ability to claim reimbursement for a payout it already made, resulting in permanent loss of operator collateral (the pre-funded collateral UTXO).
- **Slashable exposure**: An operator that cannot broadcast its `OperatorChallengeACK` or assert transactions in time due to a drained fee-payer or cancelled queue entries becomes slashable by any challenger.

### Likelihood Explanation

The default bind is `127.0.0.1`, which limits exposure to local processes. However:
- `0.0.0.0` is explicitly validated and documented as a supported value.
- Docker/container deployments commonly expose all interfaces.
- The `run.sh` smoke-test script demonstrates the `0.0.0.0` path.
- No firewall rule is enforced by the code itself.

An operator who deploys the standalone tx-sender in a container environment with `TX_SENDER_JSONRPC_BIND=0.0.0.0` (a natural choice for inter-container communication) is fully exposed.

### Recommendation

1. **Require authentication on the JSON-RPC server**: Add a shared-secret bearer token, IP allowlist middleware, or Unix-socket-only binding (removing `0.0.0.0` support).
2. **Validate `cancel_txids` ownership**: Before cancelling a pending transaction, verify that the cancellation request originates from the same session or entity that submitted the original transaction.
3. **Rate-limit CPFP submissions per source**: Even with auth, bound the number of CPFP-funded transactions per time window to prevent fee-payer exhaustion.

```rust
pub async fn start_jsonrpc_server(
    tx_sender_client: TxSenderClient,
    bind_addr: SocketAddr,
) -> Result<TxSenderJsonRpcServer, BridgeError> {
    let server: Server = ServerBuilder::default()
        .max_request_body_size(MAX_JSONRPC_REQUEST_BODY_SIZE)
        .build(bind_addr)
        .await
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    let local_addr = server
        .local_addr()
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    let mut module = RpcModule::new(tx_sender_client.clone());
    module
        .register_async_method("send_tx", |params, client, _| async move {
            let req: InsertTryToSendParams = params.one().map_err(jsonrpc_err)?;

            let raw_tx = hex::decode(&req.signed_tx_hex).map_err(jsonrpc_err)?;
            let signed_tx: Transaction = consensus::deserialize(&raw_tx).map_err(jsonrpc_err)?;

            let mut dbtx = client.db.begin_transaction().await.map_err(jsonrpc_err)?;

            let try_to_send_id = client
                .insert_try_to_send(
                    &mut dbtx,
                    req.tx_metadata,
                    &signed_tx,
                    req.fee_paying_type,
                    req.rbf_signing_info,
                    &req.cancel_outpoints,
                    &req.cancel_txids,
                    &req.activate_txids,
                    &req.activate_outpoints,
                )
                .await
                .map_err(jsonrpc_err)?;

            client
                .db
                .commit_transaction(dbtx)
                .await
                .map_err(jsonrpc_err)?;

            Ok::<u32, ErrorObjectOwned>(try_to_send_id)
        })
        .map_err(|e| BridgeError::Eyre(e.into()))?;
```
