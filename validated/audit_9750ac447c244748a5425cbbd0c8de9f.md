### Title
Uncaught `UnicodeDecodeError` from attacker-controlled NFT URI metadata crashes wallet RPC calls that render NFT info - (File: chia/wallet/nft_wallet/nft_puzzle_utils.py)

### Summary
`get_nft_info_from_puzzle()` decodes the `data_uris`, `meta_uris`, and `license_uris` fields taken directly from an NFT's on-chain metadata using `str(uri, "utf-8")` with no exception handling. These byte strings are fully attacker-controlled: any unprivileged user can mint or transfer an NFT (via `nft_add_uri`/`update_metadata` or bulk mint) whose `"u"`/`"mu"`/`"lu"` metadata fields contain invalid UTF‑8 byte sequences. When any wallet subsequently calls an RPC that renders that NFT's info (`nft_get_info`, `manual_nft_search`, related list/detail RPCs), the decode raises an unhandled `UnicodeDecodeError`, aborting that RPC call.

### Finding Description
`UncurriedNFT.uncurry()` extracts `data_uris`, `meta_uris`, and `license_uris` directly from the CLVM-curried metadata of the NFT puzzle without validating their content beyond being CLVM atoms [1](#0-0) . These fields are set by whoever mints or updates the NFT — through `NFTWallet.update_metadata()` (backing the `nft_add_uri` RPC) which lets the caller supply an arbitrary URI string that ends up in a `CREATE_COIN` condition of a spend the NFT wallet must process [2](#0-1) , and through `mint_nft`/`NFTMintNFTRequest` where `uris`, `meta_uris`, and `license_uris` are plain user-supplied strings sent as bytes with no UTF‑8 validation [3](#0-2) . Because a CLVM atom can hold arbitrary bytes (e.g. a lone `0xff` byte), it is trivial to construct a "URI" that is not valid UTF‑8.

`get_nft_info_from_puzzle()` later decodes these fields unconditionally: [4](#0-3) 

This function is invoked from `WalletStateManager.manual_nft_search()`, which is reached by the `nft_get_info` wallet RPC [5](#0-4) , and by other NFT-info-producing RPC paths in `wallet_rpc_api.py`. Any local RPC caller (including the standard GUI/CLI) who looks up such an NFT — whether their own or one received/offered by a counterparty — triggers the crash inside that RPC handler.

### Impact Explanation
This is a spend-triggered processing halt reachable by an unprivileged actor: mint or update an NFT with an invalid-UTF‑8 URI, then have any wallet (the minter's own wallet, or any counterparty who receives/queries that NFT, e.g. during an NFT offer inspection) call `nft_get_info`/`manual_nft_search`. The RPC call raises an unhandled exception and fails, denying the wallet the ability to inspect/display that NFT's info via the affected RPC. This matches the reported bug class (a specially crafted "filename"/string field causing a client-side crash when a coin/attachment is processed) mapped onto Chia's NFT metadata/RPC path.

### Likelihood Explanation
Likelihood is high for triggering the crash (trivial to include a non-UTF‑8 byte string in the `"u"`/`"mu"`/`"lu"` metadata via the standard mint/update-metadata RPCs, no special privileges required), but the impact is limited to a localized RPC-call failure (a caught-at-the-boundary crash of one RPC invocation) rather than a broader consensus/mempool/wallet-sync halt, since `NFTWallet.coin_added`/`puzzle_solution_received` (the automatic sync path) uses `get_metadata_and_phs`, not `get_nft_info_from_puzzle`, so normal coin-sync processing is not affected — only explicit info-lookup RPCs are.

### Recommendation
Wrap the `str(uri, "utf-8")` conversions in `get_nft_info_from_puzzle()` with error handling (e.g., `errors="replace"`/`errors="ignore"`, or catch `UnicodeDecodeError` and fall back to a hex/base64 representation) so that malformed metadata URIs cannot abort the RPC call. Consider validating URI fields at mint/update time as well.

### Proof of Concept
1. Mint an NFT (or call `nft_add_uri`) with a metadata URI list containing a raw non‑UTF‑8 byte atom, e.g. `meta_uris=["\udcff"]`/constructing a CLVM atom `0xff` directly via a custom spend bundle so `meta_uris.as_python()` yields `[b'\xff']`.
2. Confirm the mint/update transaction on chain.
3. Call the `nft_get_info` wallet RPC (or any RPC path reaching `manual_nft_search`) for that NFT's coin id.
4. Observe `get_nft_info_from_puzzle()` raise `UnicodeDecodeError` on `str(uri, "utf-8")` [6](#0-5) , causing the RPC call to fail with an unhandled exception.
