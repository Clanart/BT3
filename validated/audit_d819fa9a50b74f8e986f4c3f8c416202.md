### Title
Gasless `LendTx` is paid to the user unconditionally before the `SwapTx` executes, allowing the block proposer's lent KAIA to be drained if the swap later reverts — (File: `kaiax/gasless/impl/builder.go`, `kaiax/gasless/impl/getter.go`, `kaiax/gasless/impl/tx_pool.go`)

### Summary
The KIP-247 gasless flow lends KAIA to a fee-less sender via a `LendTx` that is unconditionally prepended to the sender's `[ApproveTx?, SwapTx]` bundle. The decision to lend, and the amount required to be repaid, is computed and validated once — at transaction-pool admission time, against a price-dependent view call (`GetAmountIn`) on an external swap-router/AMM. Because the `LendTx` is a plain value transfer with no dependency on the outcome of the later `SwapTx`, and the price/liquidity check is not re-verified atomically at actual block-execution time, an unprivileged transaction sender can cause the `SwapTx` to revert on-chain (e.g., by moving the underlying pool price with an ordinary prior transaction in the same block) after already receiving the lent KAIA, resulting in a fund loss to the block proposer with no repayment. This mirrors the Arrakis H-3 bug class: a trusted operation (executor `rebalance`/here, proposer-funded lending) performs an irreversible value transfer based on a pre-check that can be invalidated by intervening state changes before the compensating step (deposit/repay) actually executes.

### Finding Description
The gasless design intentionally skips the sender balance check for gasless transactions and instead relies on `GetCheckBalance()` invoking `checkBalanceForSwap`, which validates, at tx-pool admission time: [1](#0-0) 

This check queries the *current* on-chain state of the `GaslessSwapRouter`/pool via `GetAmountIn` to decide whether `swapArgs.AmountIn` is sufficient for `minAmountOut`: [2](#0-1) 

`VerifyExecutable` (used both by the tx-pool readiness logic and by the block-bundling logic) enforces that the declared `AmountRepay` equals a purely fee-derived value (`repayAmount`), not a value tied to the live swap execution result: [3](#0-2) [4](#0-3) 

When a valid `[Approve?, Swap]` pair is found, the block-bundling logic in `ExtractTxBundles` unconditionally prepends a `LendTx` generator ahead of the sender's own transactions: [5](#0-4) 

The generated `LendTx` is a plain native-KAIA value transfer, signed by the proposer's node key, sent to the sender's address for `lendAmount(approveTxOrNil, swapTx)` — a value computed purely from the transactions' declared gas fees, independent of whether the subsequent swap actually succeeds: [6](#0-5) [7](#0-6) 

The module's own documentation confirms the sequencing and the one-way nature of the lend/repay relationship: the proposer funds the gas via `LendTxGenerator`, and "user repays the lent amount during gasless swap" — i.e., repayment is a *side effect internal to the SwapTx's own execution*, not a precondition enforced atomically with the lend: [8](#0-7) 

Because `LendTx` and `SwapTx` are two separate transactions in the block (not a single atomic call), if the `SwapTx` reverts on-chain — for example because the underlying AMM's price/liquidity has moved between the moment `checkBalanceForSwap`/`GetAmountIn` was evaluated (tx-pool admission, against a prior block's state) and the moment the bundle is actually executed inside a new block (after other, ordinary transactions from any unprivileged sender have already altered the pool's reserves) — the `SwapForGas()` call inside `GaslessSwapRouter` reverts due to its own `minAmountOut`/slippage checks. The `LendTx`, however, already executed successfully and irreversibly transferred KAIA out of the proposer's balance to the sender. No on-chain mechanism claws back the lent amount when the paired `SwapTx` fails.

This is structurally analogous to the reported Arrakis issue: a trusted flow (there, `rebalance()`; here, the gasless bundling/lending flow) performs a value-affecting action based on a check performed at one point in time, but the compensating/verifying step is executed later, in a context whose state (there: pool reserves after `router_.call`; here: AMM price/liquidity at actual block-execution time) can be altered by an intervening, unprivileged actor before settlement completes, letting the actor keep the transferred value without providing consideration.

### Impact Explanation
Any block proposer running the gasless module can have its lent KAIA balance drained: for every failed/reverted gasless swap (which is achievable by an ordinary unprivileged transaction sender simply moving the referenced AMM pool's price or draining relevant liquidity/allowance shortly before block inclusion), the proposer irrecoverably pays out `lendAmount` in KAIA with zero repayment. Because this does not require validator/node-level privilege, collusion, or any cryptographic compromise — only ordinary transaction submission — it constitutes unauthorized value movement / fee-delegation ("gasless") settlement theft directly against the block proposer's funds. Repeated at scale, this can materially drain proposer balances that fund the KIP-247 lending pool.

### Likelihood Explanation
Likelihood is elevated because:
- The check that gatekeeps the lend decision (`checkBalanceForSwap` / `GetAmountIn`) executes against a snapshot of chain state at tx-pool admission time, not atomically with block inclusion.
- Any account (not necessarily the gasless sender) can submit an ordinary transaction that changes the referenced pool's price/reserves before the gasless bundle lands in a block, since gasless bundling only prevents intra-bundle conflicts, not price movement from unrelated transactions.
- The `LendTx` is generated and signed unconditionally once a candidate pair passes the (stale) checks, with no re-validation immediately preceding inclusion in the final block.

### Recommendation
- Make the lend and repay atomic: either move the lending logic into the same on-chain call as the swap/repay (so a revert of the swap also reverts the lend), or have the proposer verify solvency/success conditions using state as of the exact position the `LendTx`+`Swap` bundle will occupy in the block being built, immediately before inclusion, not at arbitrary earlier tx-pool admission time.
- Add a compensating mechanism so that if `SwapTx` reverts after `LendTx` has been included, the `LendTx` amount is force-reclaimed within the same block (e.g., structure the lend as a refundable escrow rather than a direct KAIA transfer), or reject block bundling for that gasless pair entirely if a live, execution-time simulation shows the swap would fail.
- Re-run `checkBalanceForSwap`/`GetAmountIn` against the state immediately preceding the bundle's actual insertion point during block building, not only at pool promotion time.

### Proof of Concept
Conceptual sequence (based on the reachable code paths above; no live testnet run was performed since this is a static/code-review analog derived from the referenced bug class):
1. Attacker (or any unprivileged sender) prepares a valid `[ApproveTx, SwapTx]` pair for `GaslessSwapRouter`, satisfying `checkBalanceForSwap` at the moment of submission (current pool price makes `AmountIn` sufficient for `MinAmountOut`) — see `kaiax/gasless/impl/tx_pool.go:107-142`.
2. The gasless tx-pool/bundling logic accepts the pair and, at block-building time, prepends a signed `LendTx` transferring `lendAmount()` KAIA from the proposer to the sender — `kaiax/gasless/impl/builder.go:28-72`, `kaiax/gasless/impl/getter.go:268-313`.
3. Before this bundle's `SwapTx` executes within the block, an ordinary transaction (submitted by the same or a colluding unprivileged account, included earlier in the same block due to gas price/ordering) trades heavily against the AMM pool that `GaslessSwapRouter.GetAmountIn`/`swapForGas` relies on, shifting the price unfavorably.
4. The block executes: `LendTx` succeeds unconditionally, transferring KAIA to the sender's address.
5. `SwapTx` then calls into `GaslessSwapRouter.swapForGas(...)`, which now reverts due to insufficient output relative to `minAmountOut`/`amountRepay` at the new, worse price.
6. Net result: the sender keeps the `LendTx` KAIA payout and their original tokens; the proposer has an unrepaid loss of `lendAmount`.

Note: full confirmation of this scenario (e.g., whether any additional on-chain repay-enforcement exists inside the actual `GaslessSwapRouter.sol` contract logic beyond the ABI signature seen in the Go bindings) would require inspecting the router's Solidity source directly, which was not fully available in the indexed context — only the compiled bytecode/ABI bindings (`contracts/bindings/kip247/GaslessSwapRouter.go`) were retrievable. This should be verified against the actual `GaslessSwapRouter.sol` implementation before treating this as fully confirmed.

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

// MakeLendTx creates a transaction with following properties:
// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)
// L2. LendTx.from = proposer
// L3. LendTx.to = SwapTx.from
// L4. LendTx.value = LendAmount(approveTxOrNil, swapTx)
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}

```markdown
Note that gasless transaction does not mean the gas prices of gasless transactions are zero, but it means that proposer will lend the user with gas fee and user will pay back during gasless swap.

The gas fee of gasless transaction's is funded by block proposer (i.e., lend transaction generated by `GetLendTxGenerator`), and user repays the lent amount during gasless swap.

### Transaction pool rules

#### Ready

This module is responsible for promoting gasless transactions.
Sender's nonce of GaslessSwapTx is checked to distinguish if GaslessApproveTx is expected. If `tx.nonce == GetNonce(sender) + 1`, GaslessApproveTx is expected. If `tx.nonce == GetNonce(sender)`, GaslessApproveTx is not expected.

If GaslessApproveTx is expected, GaslessApproveTx and GaslessSwapTx can be promoted when they are both ready for execution.
Otherwise, GaslessSwapTx can be promoted when it is ready for execution.

See ready condition [KIP-247](https://kips.kaia.io/KIPs/kip-247) and the implementation `IsExecutable(approveTxOrNil, swapTx *types.Transaction) bool`.

#### Balance check

Sender balance check is omitted for gasless transactions (see `GetCheckBalance()`).

### Block building rules

Upon detection of GaslessTxs, the following logics are executed:

- Per sender, if exists, GaslessApproveTx is relocated before GaslessSwapTx.
- LendTxGenerator is prepended before GaslessApproveTx.
- A new bundle is generated which contain either `[LendTxGenerator, GaslessApproveTx, GaslessSwapTx]` or `[LendTxGenerator, GaslessSwapTx]`
```
