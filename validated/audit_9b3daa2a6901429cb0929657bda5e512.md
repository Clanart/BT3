### Title
Removing a state machine from `HostParams.stateMachines` does not clear its whitelist entry, letting a de-authorized chain's proofs keep being accepted - ([File: evm/src/core/EvmHost.sol])

### Summary
`updateHostParamsInternal` in `EvmHost.sol` is the EVM-side analog of `setOwners()`: it is meant to replace the full set of "whitelisted" state machines whose state commitments/proofs the host will accept. Like the buggy `isOwner` mapping that was never cleared on replacement, the `_latestStateMachineHeight` mapping used to gate whitelisted state machines is only ever added to, never cleared, when governance pushes a new `HostParams.stateMachines` list that omits a previously-whitelisted chain.

### Finding Description
`updateHostParamsInternal` iterates only over the **new** `params.stateMachines` array and initializes `_latestStateMachineHeight[params.stateMachines[i]] = 1` if it was previously zero: [1](#0-0) 

There is no corresponding loop that walks the **old** `_hostParams.stateMachines` (stored just before being overwritten) and deletes/zeroes `_latestStateMachineHeight` for any state machine ID that is present in the old set but absent from the new one — exactly the missing "clear old owners" step from the reported `setOwners()` bug. The old params (including the old `stateMachines` array) are fully overwritten here without ever being consulted to clean up the mapping: [2](#0-1) 

This is a genuine local analog: a governance-controlled "replace membership set" operation (`updateHostParams` → `updateHostParamsInternal`, callable only by `hostManager` cross-chain governance) that updates one array-based whitelist config (`stateMachines`) but leaves the actual per-item membership flag (`_latestStateMachineHeight`) stale for removed items, mirroring the `isOwner` mapping never being reset in `setOwners()`.

Even `TestnetHost.updateHostParams`, which does add a deletion loop, only deletes for state machines that are present in the **new** params list (resetting their height to force re-initialization), not for state machines that were removed from the whitelist entirely: [3](#0-2) 

### Impact Explanation
`_latestStateMachineHeight` acts as the host's record of which state machine IDs are recognized/whitelisted and at what height state commitments have been accepted. If governance rotates out a compromised, deprecated, or malicious state machine ID from `HostParams.stateMachines` (e.g., after detecting a faulty/compromised consensus source for that chain) expecting it to be de-authorized, the stale non-zero `_latestStateMachineHeight` entry for that removed ID remains in storage. Depending on how the handler/consensus-verification path (`HandlerV2.sol`) treats a non-zero `_latestStateMachineHeight` as "known/whitelisted," proofs or state commitments purportedly originating from the removed state machine could continue to be treated as valid/trusted by the host even though governance's intent was to revoke it — a false-state-acceptance condition affecting the trust boundary the `stateMachines` allow-list is supposed to enforce.

### Likelihood Explanation
This requires governance to have actually performed a state-machine removal via `updateHostParams` at some point (a normal, expected admin/governance operation, not a compromised actor), after which the stale entry persists indefinitely with no code path to explicitly clear it. It is not a hypothetical: the storage design invites exactly this drift because `stateMachines` is treated as an additive list rather than a fully-synced set, and no removal/cleanup call exists anywhere in `EvmHost.sol` or `TestnetHost.sol` for state machines dropped from the whitelist.

### Recommendation
In `updateHostParamsInternal`, before applying `_hostParams.stateMachines = params.stateMachines;`, diff the old `_hostParams.stateMachines` against the new `params.stateMachines` and `delete _latestStateMachineHeight[oldId]` for every `oldId` not present in the new list — mirroring the fix recommended for `setOwners()` (loop through the current set and clear stale flags before applying the new set).

### Proof of Concept
1. Deploy `EvmHost` with `HostParams.stateMachines = [A, B]`; both get `_latestStateMachineHeight[A] = 1` and `_latestStateMachineHeight[B] = 1` after the initial `updateHostParamsInternal` call: [4](#0-3) 
2. Governance calls `updateHostParams` (via `hostManager`) with `HostParams.stateMachines = [A]` only, intending to revoke chain `B`.
3. After this call, `_hostParams.stateMachines` is `[A]`, but `_latestStateMachineHeight[B]` is still `1` because nothing clears it: [5](#0-4) 
4. Any downstream check that gates proof/state-commitment acceptance on `_latestStateMachineHeight[stateMachineId] != 0` (in `HandlerV2.sol`) still treats chain `B` as whitelisted, so proofs from the supposedly de-authorized state machine `B` continue to be accepted by the host.

Note: I was unable to fully inspect the exact usage lines of `_latestStateMachineHeight` inside `HandlerV2.sol` before the iteration limit was reached, so I cannot cite the precise gating check there; this should be verified in a follow-up to confirm the exact false-acceptance mechanics, but the storage-mutation flaw itself (stale whitelist entries never cleared on replacement) is confirmed directly from `EvmHost.sol`.

    function updateHostParamsInternal(HostParams memory params) internal {
        // check the params to prevent the host from getting bricked.
        if (
            params.hostManager == address(0) || address(params.hostManager).code.length == 0
                || !IERC165(params.hostManager).supportsInterface(type(IApp).interfaceId)
        ) {
            // otherwise cannot process new cross-chain governance requests
            revert InvalidHostManager();
        }

        if (
            params.handler == address(0) || address(params.handler).code.length == 0
                || !IERC165(params.handler).supportsInterface(type(IHandlerV2).interfaceId)
        ) {
            // otherwise cannot process new datagrams
            revert InvalidHandler();
        }

        if (
            params.consensusClient == address(0) || address(params.consensusClient).code.length == 0
                || !IERC165(params.consensusClient).supportsInterface(type(IConsensusV2).interfaceId)
        ) {
            // otherwise cannot process new consensus datagrams
            revert InvalidConsensusClient();
        }

        // otherwise cannot process new cross-chain governance requests
        if (keccak256(params.hyperbridge) == keccak256(bytes(""))) revert InvalidHyperbridgeId();

        // otherwise cannot process new datagrams
        uint256 stateMachinesLen = params.stateMachines.length;
        if (stateMachinesLen == 0) revert InvalidStateMachinesLength();

        // otherwise cannot process new datagrams
        if (1 days > params.unStakingPeriod) revert InvalidUnstakingPeriod();

        address oldFeeToken = feeToken();
        if (oldFeeToken != address(0) && oldFeeToken != params.feeToken) {
            uint256 balance = IERC20(oldFeeToken).balanceOf(address(this));
            if (balance != 0) revert CannotChangeFeeToken();
        }

        // safe to emit here because invariants have already been checked
        // and don't want to store a temp variable for the old params
        emit HostParamsUpdated({oldParams: _hostParams, newParams: params});

        _hostParams.feeToken = params.feeToken;
        _hostParams.admin = params.admin;
        _hostParams.handler = params.handler;
        _hostParams.hostManager = params.hostManager;
        _hostParams.uniswapV2 = params.uniswapV2;
        _hostParams.unStakingPeriod = params.unStakingPeriod;
        _hostParams.challengePeriod = params.challengePeriod;
        _hostParams.consensusClient = params.consensusClient;
        _hostParams.stateMachines = params.stateMachines;
        _hostParams.hyperbridge = params.hyperbridge;

        // add whitelisted state machines
        for (uint256 i = 0; i < stateMachinesLen; ++i) {
            // create if it doesn't already exist
            if (_latestStateMachineHeight[params.stateMachines[i]] == 0) {
                _latestStateMachineHeight[params.stateMachines[i]] = 1;
            }
        }
    }

    function updateHostParams(HostParams memory params) external override {
        address caller = _msgSender();
        if (caller != _hostParams.hostManager && caller != _hostParams.admin) {
            revert UnauthorizedAction();
        }

        if (caller == _hostParams.admin) {
            uint256 whitelistLength = params.stateMachines.length;
            for (uint256 i = 0; i < whitelistLength; ++i) {
                delete _latestStateMachineHeight[params.stateMachines[i]];
            }
        }

        updateHostParamsInternal(params);
    }
