## Analysis

The M‑04 pattern in the external report is: a value that legitimately belongs to (or is owed to) a party is not accounted for at the moment a state/eligibility decision is made, because the check reads stale or incomplete data, letting the same underlying value be paid out twice while the rightful party is shortchanged.

The closest verifiable analog in this repository is in the Intent Gateway's cross-chain cancel-from-source flow, which decides "was this order filled?" from a **GET proof of a caller-chosen historical height** rather than from the actual in-flight settlement message, creating a race that lets the same escrowed input be paid out to both the user (refund) and the solver (fill) — or, more precisely, lets the user drain the source escrow while a legitimately-filled solver's `RedeemEscrow` message is later rejected.

### Title
Stale-height GET proof in cross-chain order cancellation allows double-settlement of escrowed inputs - ([File: evm/src/apps/intentsv2/ExtrinsicIntents.sol])

### Summary
`_cancelFromSource` lets the order owner request a refund of source-chain escrow based on a Hyperbridge GET proof of the destination's `_filled[commitment]` slot at an attacker-chosen height greater than `order.deadline`. `_fillCrossChain` has no deadline check, so a solver can legitimately fill an order after its deadline. Because the owner can pick a post-deadline height that is still *before* the solver's fill, the GET proof will show `_filled` as empty even though a fill (and an outbound `RedeemEscrow` message) is already underway. The source contract accepts this proof and refunds escrow to the user via `_withdraw(..., true, true)`, zeroing `_orders[commitment][token]`. When the solver's `RedeemEscrow` message later lands, `_withdraw` reverts with `UnknownOrder` (escrow already zero), so the solver — who already paid the user's outputs on the destination chain — never gets reimbursed.

### Finding Description
- `_cancelFromSource` (evm/src/apps/intentsv2/ExtrinsicIntents.sol:188-223) only requires `options.height > order.deadline`; it does not require `height` to be the *latest* known destination height, and nothing ties it to whether a fill has since occurred. [1](#0-0) 
- `_fillCrossChain` (evm/src/apps/intentsv2/ExtrinsicIntents.sol:89-171) contains no deadline/expiry check at all, so a solver's fill dispatched after `order.deadline` is accepted and immediately sends real outputs to the beneficiary before the `RedeemEscrow` message even reaches the source chain. [2](#0-1) 
- `onGetResponse` trusts the GET proof result unconditionally and finalizes a refund the moment the (stale) slot reads empty: [3](#0-2) 
- `_withdraw`'s only defense against double-spend is that escrow reaches zero once one of the two withdrawal paths (refund or redeem) runs first; the second path simply reverts instead of being prevented up front by a receipt/commitment mechanism: [4](#0-3) 

The net effect: the "who is owed the escrow" decision is made from a proof of state that can be provably stale relative to a real fill in flight, exactly like M‑04's health check being computed from asset data that omits value already earned/committed. Here the omitted/ignored fact is "a fill dispatch is already underway," and the existing guard (`_filled` slot check via GET) doesn't bind to a specific up-to-date height or to the existence of the pending `RedeemEscrow` request.

### Impact Explanation
The order's user can receive the full destination-chain output from an honest solver's fill **and** reclaim the source-chain input escrow via a manipulated-timing cancellation, at the solver's expense. This is direct fund loss for the solver and effectively duplicate settlement of a single order's escrowed value — one of the explicitly in-scope impacts (double-claim/double-settlement, wrong beneficiary/amount).

### Likelihood Explanation
This requires only the order's own user (an ordinary, unprivileged party — not a malicious relayer, prover, or admin) picking a `height` argument for their own cancel call. It depends on: (a) a solver being willing to fill after `order.deadline` (permitted by the contract, since `_fillCrossChain` has no deadline gate), and (b) the user submitting `_cancelFromSource` with a `height` that is after `order.deadline` but strictly before the fill's block on the destination chain — something the user fully controls and can pick opportunistically once they observe mempool/pending fill activity. I could not fully verify from the indexed code whether the outer `fillOrder` entrypoint in `IntentGatewayV2.sol` (not fully retrieved in this session) imposes its own deadline check that would prevent post-deadline fills; if it does, the specific timing window analyzed here narrows to solvers filling in the same block range as the deadline rollover. This uncertainty should be resolved by reading the full `fillOrder`/`_fillCrossChain` call path in `evm/src/apps/IntentGatewayV2.sol` before treating this as conclusively exploitable.

### Recommendation
- Require `_cancelFromSource`'s GET proof height to be the chain's current/latest known height at execution time (or bound it to be within a small, recent window), not merely `> order.deadline`.
- Alternatively, have the source chain track "cancellation initiated" per commitment and reject/queue a competing `RedeemEscrow` delivery that arrives after a refund already executed, refunding the solver's dispatch fee and outputs via a dispute path rather than silently reverting and stranding the solver.
- Add an explicit deadline check inside `_fillCrossChain` so fills cannot occur after `order.deadline`, closing the race window entirely.

### Proof of Concept
1. User places a cross-chain order with `deadline = D`.
2. Solver fills the order on the destination chain at block `D+5` via `_fillCrossChain` (no deadline check blocks this), paying the user's beneficiary and dispatching `RedeemEscrow` back to source (in flight). [5](#0-4) 
3. Before `RedeemEscrow` lands on source, the user calls `_cancelFromSource` with `options.height = D+1` (satisfies `height > deadline`), requesting a GET proof of `_filled[commitment]` on the destination at height `D+1`, where the slot is still empty. [6](#0-5) 
4. `onGetResponse` sees an empty slot and refunds the full input escrow to `order.user` via `_withdraw(..., true, true)`, zeroing `_orders[commitment][token]`. [3](#0-2) 
5. The solver's `RedeemEscrow` message later arrives and calls `_withdraw(..., false, true)`; since `escrowed == 0`, it reverts with `UnknownOrder`, and the solver never recovers the input tokens despite having already paid the user's outputs. [7](#0-6)

    function _fillCrossChain(Order calldata order, FillOptions calldata options, bytes32 commitment) internal {
        uint256 outputsLen = order.output.assets.length;

        _filled[commitment] = msg.sender;

        uint256 msgValue = msg.value;
        address beneficiary = address(uint160(uint256(order.output.beneficiary)));
        TokenInfo[] memory outputFills = new TokenInfo[](outputsLen);

        for (uint256 i; i < outputsLen; i++) {
            bytes32 outputToken = order.output.assets[i].token;
            if (options.outputs[i].token != outputToken) revert InvalidInput();

            address token = address(uint160(uint256(outputToken)));
            uint256 totalRequired = order.output.assets[i].amount;
            uint256 solverAmount = options.outputs[i].amount;

            if (solverAmount < totalRequired) revert InvalidInput();

            uint256 dust = solverAmount - totalRequired;
            uint256 beneficiaryShare = 0;
            uint256 protocolShare = 0;

            if (dust > 0) {
                if (order.output.call.length > 0) {
                    protocolShare = dust;
                } else {
                    protocolShare = (dust * _params.surplusShareBps) / 10_000;
                    beneficiaryShare = dust - protocolShare;
                }
            }

            if (token == address(0)) {
                if (msgValue < solverAmount) revert InsufficientNativeToken();
                uint256 beneficiaryTotal = totalRequired + beneficiaryShare;
                (bool sent,) = beneficiary.call{value: beneficiaryTotal}("");
                if (!sent) revert InsufficientNativeToken();
                msgValue -= (beneficiaryTotal + protocolShare);
            } else {
                IERC20(token).safeTransferFrom(msg.sender, beneficiary, totalRequired + beneficiaryShare);
                if (protocolShare > 0) {
                    IERC20(token).safeTransferFrom(msg.sender, address(this), protocolShare);
                }
            }
            if (protocolShare > 0) emit DustCollected(token, protocolShare);
            outputFills[i] = TokenInfo({token: outputToken, amount: totalRequired});
        }

        _execute(order, outputsLen);

        address hostAddr = host();
        bytes memory body = bytes.concat(
            bytes1(uint8(RequestKind.RedeemEscrow)),
            abi.encode(
                WithdrawalRequest({
                    commitment: commitment, tokens: order.inputs, beneficiary: bytes32(uint256(uint160(msg.sender)))
                })
            )
        );
        DispatchPost memory request = DispatchPost({
            dest: order.source,
            to: abi.encodePacked(_instance(order.source)),
            body: body,
            timeout: 0,
            fee: options.relayerFee,
            payer: msg.sender
        });

        if (options.nativeDispatchFee > 0 && msgValue >= options.nativeDispatchFee) {
            IDispatcher(hostAddr).dispatch{value: options.nativeDispatchFee}(request);
            msgValue -= options.nativeDispatchFee;
        } else {
            dispatchWithFeeToken(request);
        }

        // Refund any unspent native tokens to the solver.
        if (msgValue > 0) {
            (bool sent,) = msg.sender.call{value: msgValue}("");
            if (!sent) revert InsufficientNativeToken();
        }

        emit OrderFilled({commitment: commitment, filler: msg.sender, outputs: outputFills, inputs: order.inputs});
    }

    function _cancelFromSource(Order calldata order, CancelOptions calldata options, bytes32 commitment) internal {
        if (order.user != bytes32(uint256(uint160(msg.sender)))) revert Unauthorized();

        if (options.height <= order.deadline) revert NotExpired();

        uint256 inputsLen = order.inputs.length;
        for (uint256 i; i < inputsLen;) {
            if (_orders[commitment][address(uint160(uint256(order.inputs[i].token)))] == 0) revert UnknownOrder();

            unchecked {
                ++i;
            }
        }

        bytes memory context =
            abi.encode(WithdrawalRequest({commitment: commitment, tokens: order.inputs, beneficiary: order.user}));

        bytes[] memory keys = new bytes[](1);
        keys[0] = bytes.concat(abi.encodePacked(_instance(order.destination)), _calculateCommitmentSlotHash(commitment));
        DispatchGet memory request = DispatchGet({
            dest: order.destination,
            keys: keys,
            timeout: 0,
            height: options.height,
            fee: options.relayerFee,
            context: context,
            payer: msg.sender
        });

        address hostAddr = host();
        if (msg.value > 0) {
            IDispatcher(hostAddr).dispatch{value: msg.value}(request);
        } else {
            dispatchWithFeeToken(request);
        }
    }

    function _withdraw(WithdrawalRequest memory body, bool isRefund, bool finalize) internal {
        address beneficiary = address(uint160(uint256(body.beneficiary)));
        if (finalize) _filled[body.commitment] = beneficiary;

        uint256 len = body.tokens.length;
        for (uint256 i; i < len; i++) {
            address token = address(uint160(uint256(body.tokens[i].token)));
            uint256 amount = body.tokens[i].amount;
            if (amount == 0) continue;

            uint256 escrowed = _orders[body.commitment][token];
            if (escrowed == 0) revert UnknownOrder();

            _orders[body.commitment][token] = escrowed - amount;
            if (token == address(0)) {
                (bool sent,) = beneficiary.call{value: amount}("");
                if (!sent) revert InsufficientNativeToken();
            } else {
                IERC20(token).safeTransfer(beneficiary, amount);
            }
        }

        if (finalize) {
            uint256 fees = _orders[body.commitment][TRANSACTION_FEES];
            if (fees > 0) {
                delete _orders[body.commitment][TRANSACTION_FEES];
                IERC20(IDispatcher(host()).feeToken()).safeTransfer(beneficiary, fees);
            }

            if (isRefund) {
                emit EscrowRefunded({commitment: body.commitment, tokens: body.tokens});
            } else {
                emit EscrowReleased({commitment: body.commitment, tokens: body.tokens});
            }
        }
    }
