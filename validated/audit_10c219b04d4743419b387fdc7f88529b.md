### Title
Malformed participant preprocess vector panics multi-input Bitcoin signing - ([File: networks/bitcoin/src/wallet/send.rs](networks/bitcoin/src/wallet/send.rs))

### Summary
`TransactionSignMachine::sign` trusts each participant-supplied `Vec<Preprocess<Secp256k1, ()>>` to contain one preprocess per transaction input, then indexes it without checking its length. [1](#0-0)  A signing participant can therefore submit a syntactically valid but empty or truncated preprocess vector and trigger an out-of-bounds panic. [2](#0-1) 

### Finding Description
`TransactionSignMachine` stores one `AlgorithmSignMachine` for every input in the transaction. [3](#0-2)  During signing, it iterates over `0 .. self.sigs.len()` and directly evaluates `commitments[c]` for each participant’s preprocess vector. [1](#0-0)  `commitments` is an untrusted `HashMap<Participant, Vec<Preprocess<Secp256k1, ()>>>`, and neither `sign` nor `validate_map` validates that every vector has the same length as `self.sigs`. [4](#0-3) [5](#0-4) 

The parser does parse the local expected number of per-input preprocesses, but the public signing API accepts the collection itself and does not reject peers that provide an undersized vector. [6](#0-5) [7](#0-6)  Consequently, a transaction with at least one input and a peer preprocess vector of length `0` reaches `commitments[0]` and panics. [1](#0-0) 

### Impact Explanation
This is a remotely triggerable denial of service against the signing task or process: one malformed preprocessing message can crash the state machine before any signature share is produced. [4](#0-3)  For multi-input transactions, a vector containing fewer than `tx.input.len()` preprocesses also crashes when the missing index is reached. [8](#0-7)  The impact is availability-only, but it is a concrete panic caused by attacker-controlled protocol input rather than an internal invariant violation. [1](#0-0) 

### Likelihood Explanation
A threshold participant controls the value mapped to its `Participant` in the `commitments` map passed to `sign`. [2](#0-1)  No cryptographic property or signature validation is needed to reach the panic, so any participant able to submit preprocessing material can trigger it by providing an undersized vector. [1](#0-0)  The likelihood depends on whether deployment plumbing can supply a `Vec` whose length differs from the parser-produced shape; the parser itself produces `self.sigs.len()` entries when parsing succeeds. [6](#0-5) 

### Recommendation
Before transposing the map, validate `commitments.len() == self.sigs.len()` for every participant and return `FrostError::InvalidPreprocess(participant)` when it does not. [1](#0-0) [9](#0-8)  The indexing expression should also use `get(c)` with an error conversion rather than `commitments[c]` so malformed peer input cannot panic. [1](#0-0)  Apply the same length validation to `Vec<SignatureShare<Secp256k1>>` in `TransactionSignatureMachine::complete`, which later removes index `0` without checking that the vector is non-empty. [10](#0-9) 

### Proof of Concept
```rust
use std::collections::HashMap;
use frost::{Participant, sign::SignMachine};

// `machine` is a TransactionSignMachine created from a SignableTransaction with at least
// one input. `peer` is another included signer.
fn poc(
  machine: impl SignMachine<
    Vec<u8>,
    Preprocess = Vec<frost::sign::Preprocess<
      frost::curve::Secp256k1,
      (),
    >>,
  >,
  peer: Participant,
) {
  let mut commitments = HashMap::new();

  // Malformed public preprocessing material: the peer provides no per-input preprocess,
  // while TransactionSignMachine assumes one exists for each transaction input.
  commitments.insert(peer, Vec::new());

  // Panics at `commitments[c]` when `c == 0`.
  let _ = machine.sign(commitments, b"");
}
```

The panic occurs because the transposition loop unconditionally indexes participant vectors by input number. [1](#0-0)  An equivalent failure occurs in completion when a participant supplies an empty `Vec<SignatureShare<Secp256k1>>`, because `complete` calls `shares.remove(0)` without checking vector length. [11](#0-10)
