### Title
`ReceivedOutput::read` accepts an arbitrary offset/output pair without validating the offset derives the output's `script_pubkey`, letting untrusted bytes register unspendable funds as received — (`networks/bitcoin/src/wallet/mod.rs`)

### Summary

The external report's bug class is a failed consistency check falling through to an unrestricted assignment: fields that were supposed to remain identical between an old and new object were never compared, letting an attacker substitute a more valuable parameter set. In `bitcoin-serai`, a `ReceivedOutput` pairs a scalar `offset` with a `TxOut`/`OutPoint`, and the security-critical invariant is that `key + offset*G` actually produces the output's `script_pubkey`. `ReceivedOutput::read` deserializes these three fields from attacker-controlled bytes with no such consistency check — the analog of the roll path assigning the new token ID without validating it matches the masked fields.

### Finding Description

`ReceivedOutput::read` reads `offset` via `Secp256k1::read_F`, then a `TxOut` and `OutPoint` via consensus decoding, and returns them unconditionally [1](#0-0) . At no point does it compute `p2tr_script_buf(self.key + offset*G)` and compare it to `output.script_pubkey` — the way `Scanner::register_offset`/`scan_transaction` establish the binding on the honest path [2](#0-1) .

The consistency check only exists downstream, and even there it fails silently: `SignableTransaction::multisig` returns `None` when `p2tr_script_buf(offset.group_key()) != prevouts[i].script_pubkey` [3](#0-2) . So a malformed `ReceivedOutput` is accepted as "received funds" by the reading path, but can never be turned into a signing machine — the exact shape of the original bug (validation skipped, mismatching value accepted, failure deferred and silent).

### Impact Explanation

Any consumer that ingests `ReceivedOutput`s from an untrusted source (a coordinator, another participant, or deserialized storage the attacker can influence) will treat the output as spendable balance. When spending is attempted, `multisig` yields `None`, so the wallet has funds it believes it owns but cannot sign for — funds reported received that are not spendable. Worse, an attacker can pair a *valid-looking* script with an offset that derives a key the victim does not control, corrupting accounting and selectable-input sets. This maps to the report's profit path: the object is accepted with mismatched parameters because the equality check that should bind `offset` to `script_pubkey` was never performed at the trust boundary.

### Likelihood Explanation

`ReceivedOutput::read` is a public deserialization entry point explicitly meant for reading external data, and nothing in it authenticates the offset-to-output relationship [1](#0-0) . Exploitation only requires an unprivileged party to supply crafted bytes; no validator collusion or key material is needed. Impact is bounded to Medium: it corrupts the set of spendable outputs (freeze/misattribution) rather than directly leaking key material.

### Recommendation

Validate the binding at construction/read time: compute `p2tr_script_buf(key + ProjectivePoint::GENERATOR * offset)` (or take the base key/expected script as a parameter to `read`) and reject if it does not equal `output.script_pubkey`. Alternatively, make `ReceivedOutput::read` return `Option`/`Result` on mismatch so malformed entries cannot propagate into the spendable-output set.

### Proof of Concept

```rust
// Attacker-controlled bytes: a real TxOut paying to an honest P2TR script,
// but paired with an offset that does not derive that script.
let mut buf = vec![];
// offset = 1 (arbitrary; does not map `key` to the output's script)
buf.extend(Scalar::ONE.to_bytes());
buf.extend(serialize(&victim_script_txout)); // TxOut { value, script_pubkey: honest_p2tr }
buf.extend(serialize(&fake_outpoint));

let received = ReceivedOutput::read(&mut &buf[..]).unwrap(); // accepted, no check

// Wallet now believes it can spend `output` with `offset`.
// Later, spending silently fails:
let keys = tweak_keys(victim_keys); // base keys for `key`
let tx = SignableTransaction { /* prevouts includes received.output, offsets[0] = received.offset */ };
assert!(tx.multisig(&keys).is_none()); // None: offset.group_key() != script_pubkey
// Result: funds counted as received are permanently unspendable.
```

  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
