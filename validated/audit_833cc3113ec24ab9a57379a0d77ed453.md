### Title
Gasless block-building bundle inclusion (`VerifyExecutable`) omits deadline validation present in mempool admission, enabling proposer fund loss via non-atomic Lend/Swap bundles - (File: `kaiax/gasless/impl/getter.go`)

### Summary
The gasless module (KIP-247) validates the swap transaction's `deadline` when admitting a transaction into the mempool (`checkBalanceForSwap` in `kaiax/gasless/impl/tx_pool.go`), but the equivalent check used at block-building time to decide whether to bundle a `LendTx + ApproveTx? + SwapTx` (`VerifyExecutable`/`IsExecutable` in `kaiax/gasless/impl/getter.go`, called from `ExtractTxBundles` in `kaiax/gasless/impl/builder.go`) never checks the deadline at all. This is a textbook instance of the reported bug class: input that is validated in one code path but not in the reachable consensus/block-building path.

### Finding Description
`checkBalanceForSwap` explicitly enforces `tx.deadline >= currentTimestamp` before a swap tx is accepted into the pool: [1](#0-0) 

However, the function that the block builder actually consults when deciding to include a gasless bundle, `VerifyExecutable`, performs a complete set of structural/consistency checks (S1–S3, A1–A4, AP1, SP1–SP4) but never re-validates `swapArgs.Deadline` against the current block time: [2](#0-1) 

`ExtractTxBundles`, the `kaiax.TxBundlingModule` entry point invoked by the block builder, calls `g.IsExecutable(approveTxs[addr], tx)` (which just wraps `VerifyExecutable`) as the sole gate for constructing a bundle consisting of `[LendTxGenerator, ApproveTx?, SwapTx]`: [3](#0-2) 

The bundle is created with the atomic flag explicitly set to `false`: [4](#0-3) 

`GetLendTxGenerator` creates and signs an unconditional value-transfer transaction from the block proposer's own key to the swap sender, sized to cover the swap tx's (and approve tx's) gas fee, with no dependency on the swap tx's success: [5](#0-4) 

Because the deadline is not re-checked at bundling time and the bundle is non-atomic, a `SwapTx` whose `deadline` has already elapsed (or is set to elapse between pool admission and inclusion, or was never checked because the sequencing paths differ from `checkBalanceForSwap`) can still be selected for bundling. If the on-chain `GaslessSwapRouter.swapForGas` reverts because the deadline check fails inside the contract (or for any other execution-time reason, e.g. slippage/liquidity change), the independent `LendTx` — which unconditionally moves proposer funds to the sender — still lands successfully in the same block, while the repayment logic embedded in the (reverted) `SwapTx` never executes.

### Impact Explanation
This allows a swap sender (an unprivileged transaction submitter) to receive a real, unconditional KAIA transfer from the block proposer (the `LendTx`) while never repaying it, because the paired `SwapTx` that is supposed to atomically repay the proposer can fail independently. This is concrete unauthorized value movement / fee-delegation-analog abuse: the proposer effectively lends gas value that is never recovered. Given `kaiax/gasless` is designed so "user repays the lent amount during gasless swap" as stated in the module's own documentation, breaking that repayment guarantee is a direct fund-loss vector for block proposers, and by extension a structural weakness in the KIP-247 gasless mechanism reachable by any public transaction sender.

### Likelihood Explanation
The precondition is straightforward: a user submits a `SwapTx` with a deadline that will have elapsed (or a swap that will otherwise revert on-chain for a benign reason such as price movement) but that still passes `VerifyExecutable`'s structural checks (since it never inspects `Deadline`). Because `ExtractTxBundles` runs at block-building time on every proposal, and the pool-admission-time deadline check in `checkBalanceForSwap` does not re-run when the tx is later pulled for bundling (timing gap between pool admission and inclusion, or reorgs/requeues), the expired condition is trivially reachable by any user crafting or waiting for their own swap transaction. No special privileges, node compromise, or consensus-message manipulation are required.

### Recommendation
Add the same deadline check performed in `checkBalanceForSwap` (`swapArgs.Deadline.Cmp(currentBlockTime) < 0` ⇒ reject) directly inside `VerifyExecutable` in `kaiax/gasless/impl/getter.go`, so both the mempool-admission path and the block-building/bundling path enforce identical validation. Additionally, review whether the `LendTx`/`SwapTx` bundle should be executed atomically (i.e., reverted together) rather than being marked non-atomic (`false` in `builder.NewBundle`), so that a reverting `SwapTx` cannot leave an unconditional `LendTx` transfer standing.

### Proof of Concept
Conceptual PoC (exact bundle/atomicity semantics of `work/builder/bundle.go` were not fully re-verified due to tool budget, so this should be confirmed by re-running the flow end-to-end):
1. Attacker (any account with sufficient token balance/allowance) crafts and signs a valid `SwapTx` calling `swapForGas(token, amountIn, minAmountOut, amountRepay, deadline)` with a `deadline` that is already in the past (or nearly expiring), targeting the whitelisted `swapRouter`/token so `isSwapTx` passes.
2. Attacker submits the `SwapTx` (optionally preceded by an `ApproveTx`) to a node's tx pool. Because `checkBalanceForSwap` (pool admission) may run before the deadline is reached, or because the tx sits in the pool until the deadline passes before being picked up by a proposer, the tx pool's per-tx deadline gate is bypassed at bundling time.
3. When a block proposer calls `ExtractTxBundles`, `IsExecutable`/`VerifyExecutable` returns `true` because it never inspects `swapArgs.Deadline` — see `kaiax/gasless/impl/getter.go` lines 211-266.
4. The proposer builds a non-atomic bundle `[LendTxGenerator, SwapTx]` (see `kaiax/gasless/impl/builder.go` lines 28-72) and includes it in the block.
5. `LendTx`, a plain signed value transfer from the proposer to the attacker, executes successfully and unconditionally, regardless of `SwapTx`'s outcome (see `kaiax/gasless/impl/getter.go` lines 268-313).
6. `SwapTx` reverts on-chain (e.g., due to the router's own deadline check, if present, or unrelated execution failure), so the repayment to the proposer never occurs, and the attacker keeps the lent KAIA.

Note: this PoC assumes `GaslessSwapRouter.swapForGas` enforces the deadline on-chain (typical for swap routers) and that the bundle's `atomic=false` flag means transactions execute/commit independently rather than being rolled back together; both assumptions should be validated against `contracts/bindings/kip247/GaslessSwapRouter.go` and `work/builder/bundle.go` before treating this as fully confirmed, since I was unable to inspect their full contents within the available tool budget.

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}

// MakeLendTx creates a transaction with following properties:
// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)
// L2. LendTx.from = proposer
// L3. LendTx.to = SwapTx.from
// L4. LendTx.value = LendAmount(approveTxOrNil, swapTx)
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}
