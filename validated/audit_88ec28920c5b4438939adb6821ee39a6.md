### Title
Unbounded-offset CLVM atom-length parsing in mempool dedup canonicalization check can crash spend-bundle processing - (File: chia/full_node/mempool_manager.py)

### Summary
`is_atom_canonical()` and `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` walk a CLVM-serialized buffer taken from a submitted spend bundle's solution/puzzle bytes to decide DEDUP eligibility, but they index into `clvm_buffer` using an `offset` that is never checked against `len(clvm_buffer)` before each byte access.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads `clvm_buffer[offset]` and then, based on the high bits of that byte, walks forward `prefix_len` additional bytes to build a multi-byte length prefix: [1](#0-0) 

Nowhere in this loop is `offset` checked against `len(clvm_buffer)`. `is_clvm_canonical()` calls this in its own byte-walking loop that also never bounds-checks `offset` before `clvm_buffer[offset]`: [2](#0-1) 

This is structurally the same bug class as the Ollama CVE: a parser trusts an internal, attacker-influenced length/format field to determine how many more bytes to consume, without validating that those bytes actually exist in the buffer — leading to an out-of-bounds access (an `IndexError` in Python, analogous to the segfault in the Go/C parser) instead of a controlled parse error. Per `.cursor/context/clvm-execution.md`, this canonical-form check is invoked specifically to validate whether a submitted spend's CLVM buffer is eligible for the mempool's DEDUP optimization: [3](#0-2) 

A submitter can craft a spend bundle whose CLVM buffer ends with a truncated multi-byte atom-length prefix (e.g., a lead byte indicating a 5-byte length prefix — `0b111111xx` pattern — placed at the very end of the buffer), causing `is_atom_canonical`'s inner loop to index past the end of `clvm_buffer` and raise an unhandled `IndexError` during mempool admission processing of that spend bundle.

### Impact Explanation
If this exception propagates uncaught out of the mempool-manager's spend-bundle admission path, it can abort processing of that spend bundle and, depending on how the calling task/loop handles the exception, disrupt the full node's mempool/transaction-processing pipeline — a spend-triggered transaction-processing halt, which is one of the explicitly in-scope high-impact outcomes for this analog search.

### Likelihood Explanation
Likelihood is High in terms of reachability: the trigger is a single spend bundle submitted through the ordinary mempool-admission path (no special privileges, no other party's participation, no malicious peer/node assumption required) — exactly the "unprivileged spend-bundle submitter" threat model in scope. The main open question (which I could not fully confirm from available context) is whether the caller wraps this canonicalization check in a broad `try/except` that would downgrade the crash to a handled rejection rather than an unhandled exception; I was not able to locate and inspect the exact call site of `is_clvm_canonical()` within the mempool add-to-pool flow before running out of investigation budget, so the severity should be validated by tracing that call site directly.

### Recommendation
Add explicit bounds checks (`offset < len(clvm_buffer)` and `offset + prefix_len < len(clvm_buffer)`) inside `is_atom_canonical()` before each `clvm_buffer[offset]` access, and inside `is_clvm_canonical()`'s main loop before dereferencing `clvm_buffer[offset]`, returning `False`/raising a well-defined, caught error instead of allowing an `IndexError` to propagate. Additionally, verify (and if necessary add) exception handling around the call site in the mempool manager's spend-bundle validation path so that any parsing failure is treated as spend-bundle rejection rather than an unhandled exception in the node's processing loop.

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

```python
def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
