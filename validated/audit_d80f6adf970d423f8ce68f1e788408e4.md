### Title
Unvalidated CLVM atom length prefix causes out-of-bounds read / crash in mempool spend-bundle canonical check - (File: chia/full_node/mempool_manager.py)

### Summary
`is_clvm_canonical()` and its helper `is_atom_canonical()` in `chia/full_node/mempool_manager.py` parse the raw CLVM serialization of a coin spend's `puzzle_reveal` and `solution` byte-by-byte, using a length prefix taken directly from attacker-controlled bytes, without ever checking that `offset` stays within `len(clvm_buffer)` before indexing into it. This mirrors the CVE-2023-39176 bug class: a length-prefixed field is trusted to determine how many bytes to consume/read without validating it against the actual remaining buffer size, allowing a read past the end of the buffer. [1](#0-0) [2](#0-1) 

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads `clvm_buffer[offset]` to determine the atom's length-prefix format, then loops `prefix_len` times reading additional bytes via `clvm_buffer[offset]` with no bound check against `len(clvm_buffer)`: [3](#0-2) 

`is_clvm_canonical()` similarly advances `offset` based on the returned `atom_len` (which itself is derived purely from attacker-supplied bytes) and loops back to read `clvm_buffer[offset]` again without checking whether `offset` is still within bounds: [4](#0-3) 

This function is called unconditionally on both `puzzle_reveal` and `solution` for every coin spend in `validate_spend_bundle()`, which is on the direct path of every spend bundle submitted to the mempool (including from unprivileged wallet/RPC clients and gossiped transactions): [5](#0-4) 

Because Python raises an `IndexError` on out-of-bounds `bytes` indexing (rather than silently reading adjacent memory as in the C ksmbd case), a crafted `puzzle_reveal` or `solution` with a truncated length-prefix atom near the end of the buffer (e.g., a multi-byte prefix declaring more prefix bytes than remain) causes `clvm_buffer[offset]` to raise `IndexError` instead of returning a `bool`. This exception is not caught anywhere in `validate_spend_bundle()`/`add_spend_bundle()`, so it propagates up out of the mempool-admission call chain.

### Impact Explanation
This is not a memory-disclosure primitive in Python the way the original ksmbd CVE is in C (Python's bounds-checked buffer indexing prevents reading adjacent heap memory), so the "read past end of allocated buffer" impact does not translate to information disclosure here. The closest applicable, in-scope impact category is a spend-triggered transaction-processing halt: an unprivileged spend bundle submitter can trigger an unhandled `IndexError` inside the mempool admission pipeline that every full node runs when receiving that spend bundle. Depending on how far up the call stack the exception propagates before being caught (e.g., by a generic exception handler in the RPC/network message-processing layer), this could manifest as a rejected/failed transaction, a logged traceback, or, in the worst case, interfere with mempool processing for that message if no catch-all exists at that layer. This is a lower-severity denial-of-service-flavored issue rather than the high-severity confidentiality impact of the original CVE.

### Likelihood Explanation
High: constructing a `puzzle_reveal` or `solution` with a truncated multi-byte length-prefix atom (e.g., byte `0xFC` indicating a 5-byte length suffix that isn't present in the remaining buffer) is trivial and requires no privileges — any spend bundle submitter or wallet RPC caller can build such CLVM bytes. Existing tests (`test_atom_canonical`, `test_mempool_requires_canonical_clvm`) already exercise adjacent code paths with crafted non-canonical CLVM byte strings, confirming this input path is reachable and exercised with attacker-controlled hex payloads. [6](#0-5) [7](#0-6) 

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before each `clvm_buffer[offset]` access (verify `offset < len(clvm_buffer)` prior to reading the initial byte and prior to/after each prefix-byte read), and in `is_clvm_canonical()` verify `offset < len(clvm_buffer)` at the top of the loop before dereferencing `clvm_buffer[offset]`. On any out-of-bounds condition, treat the buffer as non-canonical (return `False`) rather than raising an unhandled exception, consistent with the defensive bounds-checking style already used in `chia/full_node/full_block_utils.py`'s `skip_bytes`/`skip_list` helpers. [8](#0-7) 

### Proof of Concept
1. Construct a coin spend whose `solution` (or `puzzle_reveal`) CLVM bytes end with a truncated large-atom length prefix, e.g. bytes ending in `\xfc` (which signals a 5-byte length suffix per the encoding table in `is_atom_canonical`) followed by fewer than 5 remaining bytes, such as `b"\xff\xfc\x01"`.
2. Submit this as a `SpendBundle` via the wallet/RPC path (`push_tx`) so it reaches `MempoolManager.validate_spend_bundle()`.
3. `is_clvm_canonical(bytes(coin_spend.solution))` is invoked at line 724, which calls `is_atom_canonical()`; the prefix-byte loop at lines 178–181 attempts to read `clvm_buffer[offset]` beyond the buffer length, raising `IndexError` instead of returning a canonical/non-canonical verdict. def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
