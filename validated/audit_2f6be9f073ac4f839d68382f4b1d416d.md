## Finding: GitHub host detection accepts attacker-controlled domains via naive hostname pattern match

### Title
Weak `isGitHubHost` heuristic misclassifies attacker-controlled domains as trusted GitHub Enterprise hosts, triggering GitHub sign-in/credential flow against untrusted endpoints - (`app/src/lib/api.ts`)

### Summary
`Root.getAddress`'s SOA check was meant to validate the actual root TLD but instead checked a derived/prefixed name (`_ens.nic.<tld>`), silently weakening the intended trust check. GitHub Desktop has an equivalent pattern in `isGitHubHost()`: the function is meant to determine whether a remote endpoint genuinely belongs to a GitHub product (github.com/GHE/ghe.com), but before doing any real verification it short-circuits on a loose regex test of the hostname string, which any attacker can satisfy by choosing a subdomain label rather than the actual domain being GitHub-owned.

### Finding Description
`isGitHubHost()` in `app/src/lib/api.ts` is the authority used to decide, for an unknown git remote endpoint, whether Desktop should treat it as a trusted "enterprise" GitHub host: [1](#0-0) 

The intended, reliable check is the final network probe that verifies the `x-github-request-id` response header actually returned by a real GitHub(E) server: [2](#0-1) 

But before ever reaching that verification, the function returns `true` early for any hostname matching `/(^|\.)(github)\./`: [3](#0-2) 

This regex only requires that some dot-delimited label in the hostname literally be `github`, with nothing tying it to a domain actually operated by GitHub. An attacker who registers any domain can create a subdomain such as `github.attacker-domain.com`, and that hostname alone satisfies `(^|\.)(github)\.` (the label starts the string and is followed by a dot), causing `isGitHubHost()` to return `true` without ever issuing the meta-endpoint request that would have caught it. The existing `isKnownThirdPartyHost()` denylist (`gitlab.com`, `bitbucket.org`, etc.) does not help here since it is only consulted for hosts that don't match the github-label heuristic: [4](#0-3) 

`isGitHubHost()` feeds directly into `getEndpointKind()` in the git credential trampoline, which decides how Desktop's credential helper handles a `git` credential request for an unrecognized host: [5](#0-4) 

If classified `'enterprise'` and no existing account matches that endpoint, the `get` credential handler prompts the user to sign in to what Desktop presents as a GitHub/GHE host: [6](#0-5) 

The corrupted value is the boolean classification produced by `isGitHubHost`/`getEndpointKind` (`'enterprise'` vs `'generic'`), which downstream code trusts as proof the remote is an authentic GitHub product endpoint, when in fact it was derived from a superficial substring match on the hostname rather than verification of the domain's actual identity.

### Impact Explanation
Because credential-helper invocations originate from `git` itself (triggered by `fetch`/`clone`/`push`/submodule updates against whatever remote URL is configured), an attacker who controls a repository the victim clones/fetches (e.g., via a `.gitmodules` entry or configured remote pointing at `https://github.<attacker-domain>/...`) can cause Desktop to classify that attacker host as `'enterprise'`. This routes the user into the GitHub/GHE sign-in prompt (`ui.promptForGitHubSignIn(endpoint)`), i.e., Desktop's OAuth/account-binding flow, anchored at an attacker-chosen endpoint rather than a genuine GitHub product — satisfying the "unauthorized OAuth or account binding" impact category triggered purely by an attacker-controlled fetched/cloned repository content, no local access or pre-existing compromise required.

### Likelihood Explanation
The label-based regex is trivially satisfiable by anyone who can register a domain and add a `github.` subdomain label; no special privileges, DNS control over `github.com`, or certificate tricks are needed. The condition is reached automatically any time Desktop's bundled git invokes the credential helper for a host it doesn't already recognize (`isDotCom`/`isGHE`/`wwwauth` header checks all fail first), which is a normal path for any first-time interaction with a new remote/submodule URL.

### Recommendation
Remove the substring-based `/(^|\.)(github)\./` shortcut (and similarly reconsider the `bitbucket|gitlab` denylist shortcut) and rely solely on the network-verified check (`x-github-request-id` response header from an actual request to the candidate endpoint), or restrict the heuristic to an exact, anchored match against `github.com`/known enterprise suffixes rather than an arbitrary dot-delimited label appearing anywhere in the hostname.

### Proof of Concept
1. Attacker hosts a public git repository containing a `.gitmodules` (or is added directly as a remote) referencing `https://github.attacker-domain.com/foo/bar.git`, a domain fully controlled by the attacker.
2. Victim opens/clones this repository in GitHub Desktop and performs a fetch/submodule update, causing git to invoke Desktop's credential helper for `github.attacker-domain.com`.
3. `getEndpointKind()` calls `isGitHubHost('https://github.attacker-domain.com')`; `isGitHubHost` matches `/(^|\.)(github)\./` against hostname `github.attacker-domain.com` and returns `true` immediately, without the `x-github-request-id` network check ever running. [3](#0-2) 
4. `getEndpointKind` returns `'enterprise'`; since no account matches this new endpoint, Desktop's `getCredential` handler invokes `ui.promptForGitHubSignIn(endpoint)`, presenting the attacker-controlled host to the user as if it were a legitimate GitHub Enterprise sign-in target. [6](#0-5)

```typescript
/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }
```
