### Title
Unhandled `ValueError` from unchecked `ConditionOpcode` enum cast in clawback puzzle condition parsing crashes wallet coin processing - (File: chia/consensus/condition_tools.py)

### Summary
`parse_sexp_to_condition()` performs `ConditionOpcode(op)` on a single-byte atom taken directly from an inner puzzle's CLVM output, with no exception handling for the case where `op` doesn't match any defined `ConditionOpcode` member. `conditions_for_solution()`, the wrapper used by `match_clawback_puzzle()` in the wallet's clawback driver, only catches `Program.EvalError`, leaving the `ValueError` from the invalid enum cast unhandled.

### Finding Description
`ConditionOpcode` is a `bytes, enum.Enum` with a fixed, sparse set of valid single-byte values (1, 43-52, 60-67, 70-76, 80-90). `parse_sexp_to_condition()` extracts a 1-byte atom from a CLVM-produced condition and constructs `ConditionOpcode(op)` unconditionally:
```
op = first[0].atom
if op is None or len(op) != 1:
    raise ConsensusError(Err.INVALID_CONDITION, ["invalid op"])
...
return ConditionWithArgs(ConditionOpcode(op), vars)
```
Any single byte not in the enum's defined set (e.g. `0x02`, `0x0A`, `0x59`, etc.) raises an unhandled `ValueError: 2 is not a valid ConditionOpcode`, not a `ConsensusError`.

The wallet's clawback puzzle matcher, `match_clawback_puzzle()`, runs an arbitrary attacker-supplied `inner_puzzle`/`inner_solution` pair (taken from a coin being processed as a candidate clawback coin) through `conditions_for_solution()`, which itself only wraps `run_with_cost` failures in a try/except for `Program.EvalError`—it does not catch the `ValueError` raised by the enum cast. A malicious sender can construct a coin whose `inner_puzzle`, when run, outputs a condition list containing any single-byte atom not in `ConditionOpcode`'s value set as the first element of a top-level condition. When the recipient wallet later attempts to interpret this coin (e.g., while scanning received coins for clawback metadata during wallet sync/coin-added processing), `match_clawback_puzzle()`'s call into `conditions_for_solution()` raises the uncaught `ValueError`, which is not the deliberately-handled `Program.EvalError`/`ConsensusError` path the rest of the code expects.

This mirrors the CVE-2026-48140 bug class exactly: an "unchecked enum cast" fed by attacker-supplied input that lacks range validation before constructing the enum value, producing an exceptional/undefined program state instead of a clean rejection path.

### Impact Explanation
If this exception propagates out of the wallet's coin-processing/state-manager pipeline uncaught by any higher-level generic exception handler, it halts processing of new coin additions for the wallet, which is a denial-of-service against the victim wallet's ability to detect and process incoming coins (including legitimate clawback and non-clawback coins queued in the same processing batch). This matches the "spend-triggered transaction-processing halt" impact category. The severity is limited by whether an outer caller (wallet state manager) wraps this call in a broad `except Exception`, which could not be confirmed for the exact call site invoking `match_clawback_puzzle()` from the repository content available.

### Likelihood Explanation
Reachable by any unprivileged party who can send a coin to a victim's wallet with a custom puzzle (i.e., anyone can send XCH/coins to any address). No signature validation of the inner puzzle content is required to trigger parsing—the wallet processes puzzle-hash-matching coins during normal receive/sync detection to look for clawback structure regardless of whether the coin is actually spendable by the recipient.

### Recommendation
In `parse_sexp_to_condition()` (or in `conditions_for_solution()`/`match_clawback_puzzle()`), catch `ValueError` from the `ConditionOpcode(op)` construction and convert it into a `ConsensusError(Err.INVALID_CONDITION, ...)` or otherwise handle unknown opcodes gracefully (e.g., skip the condition) rather than letting `ValueError` escape. Audit other unguarded `ConditionOpcode(...)`/enum constructions fed by untrusted puzzle output for the same gap.

### Proof of Concept
1. Craft a puzzle `P` such that `P.run(solution)` returns a condition list where one condition's first element is a single byte not in `ConditionOpcode`'s defined values, e.g. `(q ((2 0xdead) (51 <ph> <amt>)))` where `2` (`0x02`) is not a valid `ConditionOpcode` member.
2. Create/send a coin with this puzzle to a victim wallet (does not need a valid signature to be *received*/processed by wallet coin-detection logic).
3. When the victim wallet processes the newly seen coin and calls `match_clawback_puzzle()` → `conditions_for_solution()` → `parse_sexp_to_conditions()` → `parse_sexp_to_condition()`, the line `ConditionOpcode(op)` raises `ValueError`, which is not caught anywhere in this call chain, propagating to the caller of `match_clawback_puzzle()`.

```python
def parse_sexp_to_condition(sexp: Program) -> ConditionWithArgs:
    """
    Takes a ChiaLisp sexp and returns a ConditionWithArgs.
    Raises an ConsensusError if it fails.
    """
    first = sexp.pair
    if first is None:
        raise ConsensusError(Err.INVALID_CONDITION, ["first is None"])
    op = first[0].atom
    if op is None or len(op) != 1:
        raise ConsensusError(Err.INVALID_CONDITION, ["invalid op"])

    # since the ConditionWithArgs only has atoms as the args, we can't parse
    # hints and memos with this function. We just exit the loop if we encounter
    # a pair instead of an atom
    vars: list[bytes] = []
    for arg in Program(first[1]).as_iter():
        a = arg.atom
        if a is None:
            break
        vars.append(a)
        # no condition (currently) has more than 3 arguments. Additional
        # arguments are allowed but ignored
        if len(vars) > 3:
            break

    return ConditionWithArgs(ConditionOpcode(op), vars)
```

```python
def conditions_for_solution(
    puzzle_reveal: Program | SerializedProgram, solution: Program | SerializedProgram, max_cost: int
```

```python
def match_clawback_puzzle(
    unknown_puzzle: UnknownPuzzle,
    inner_puzzle: Program | SerializedProgram,
    inner_solution: Program | SerializedProgram,
) -> ClawbackMetadata | None:
    # Check if the inner puzzle is a P2 puzzle
    if MOD != unknown_puzzle.mod:
        return None
    if not isinstance(inner_puzzle, SerializedProgram):
        inner_puzzle = inner_puzzle.to_serialized()
    if not isinstance(inner_solution, SerializedProgram):
        inner_solution = inner_solution.to_serialized()
    # Fetch Remark condition
    conditions = conditions_for_solution(
        inner_puzzle,
        inner_solution,
        DEFAULT_CONSTANTS.MAX_BLOCK_COST_CLVM // 8,
    )
```
