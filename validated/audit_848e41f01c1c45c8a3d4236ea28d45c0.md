### Title
`SignableTransaction::new` omits the OP_RETURN data output from fee/weight estimation, underpaying the requested fee rate - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
When the optional `data` field is provided, `SignableTransaction::new` appends an OP_RETURN `TxOut` to the transaction but computes `weight`, `vbytes`, `needed_fee`, the `NotEnoughFunds` check, and the change amount using `calculate_weight_vbytes(tx_ins.len(), payments, …)`, which is called only with `payments` and never includes the data output. The signed transaction is therefore larger than estimated, and the fee actually paid (`inputs - outputs`) corresponds to a lower effective sat/vbyte than the caller-specified `fee_per_vbyte`.

### Finding Description
In `SignableTransaction::new`, the zero-valued OP_RETURN output is pushed onto `tx_outs` before weight estimation, but both estimation calls exclude it:

```rust
// networks/bitcoin/src/wallet/send.rs
tx_outs.push(TxOut { value: Amount::ZERO, script_pubkey: ScriptBuf::new_op_return(...) });
let (mut weight, vbytes) = Self::calculate_weight_vbytes(tx_ins.len(), payments, None);
...
let (weight_with_change, vbytes_with_change) =
  Self::calculate_weight_vbytes(tx_ins.len(), payments, Some(&change));
```

`calculate_weight_vbytes` builds the template transaction solely from `payments` plus optional `change`, so the OP_RETURN output (up to 8-byte value + ~2-byte script header + 80-byte push ≈ 91 bytes ≈ 91 vbytes) is never counted. Consequences:

- `needed_fee = fee_per_vbyte * vbytes` under-reports the fee needed to hit the requested rate by up to `~91 * fee_per_vbyte` sats.
- When `change` is supplied, the change output value is computed as `input_sat - (payment_sat + fee_with_change)`, so the underestimated fee is locked in: the actual fee rate is strictly below `fee_per_vbyte`.
- The `TooLowFee` minimum-relay check uses the underestimated `vbytes`, and `NotEnoughFunds` can pass while the true required fee is higher than computed.
- `tx.weight()` of the produced transaction can also exceed `MAX_STANDARD_TX_WEIGHT` even though the check passes, since `weight` is the underestimated value.

This is reachable purely from public inputs: `data` is a caller/integrator-supplied byte vector fed into a `SignableTransaction` that the FROST threshold then signs.

### Impact Explanation
The multisig produces a fully-signed transaction that pays less than the intended fee rate. At low `fee_per_vbyte` (near `DEFAULT_MIN_RELAY_TX_FEE`) the missing ~91 vbytes can push the effective rate below the relay minimum, yielding a transaction that will not propagate or confirm — funds committed as inputs are effectively stuck until an RBF/new signing round is coordinated. It also misreports `needed_fee()` to any caller budgeting fees (the same class of "funds reserved/demanded incorrectly" as the extortion-payment bug class: value accounting diverges from what the protocol believes).

### Likelihood Explanation
Requires the `data` parameter to be used and a low fee rate to cause a non-relayable TX; otherwise the impact is a small, silent underpayment relative to the requested rate. Deterministic miscalculation whenever `data` is `Some`; exploitable by any party who can influence the data or timing to force a minimum-fee transaction.

### Recommendation
Include the OP_RETURN output in `calculate_weight_vbytes` — e.g., pass the fully formed `tx_outs` (or an equivalent `data: Option<&ScriptBuf>` parameter) to both weight-estimation calls so `weight`, `vbytes`, `needed_fee`, `fee_with_change`, and the change-amount/`NotEnoughFunds`/`TooLowFee` checks all account for the data output.

### Proof of Concept
```rust
// networks/bitcoin (regtest)
let data = vec![0u8; 80];
let tx = SignableTransaction::new(inputs, &payments, Some(change_addr), Some(data), FEE).unwrap();
// tx.needed_fee() == FEE * vbytes(tx_without_op_return)
// actual signed tx contains the ~91-byte OP_RETURN output, so
// tx.fee() < FEE * tx.vsize() — the paid rate is below the requested FEE.
// With FEE == min relay rate, the signed TX falls under the relay minimum.
```
