### Title
Payout attribution (`payout_payer_operator_xonly_pk`) is derived from an unsigned OP_RETURN output, letting an unrelated funder misattribute operator credit for a payout it never funded - (File: `core/src/verifier.rs`, `core/src/builder/transaction/operator_reimburse.rs`)

### Summary
Clementine binds "who gets reimbursed from the vault for a withdrawal" to whichever x-only pubkey appears in the payout transaction's OP_RETURN output, but nothing in the protocol signs or otherwise authenticates that OP_RETURN value against the actual source of funds in the transaction.

### Finding Description
The payout transaction is built by `create_payout_txhandler`, which embeds the operator's x-only pubkey in a plain `OP_RETURN` output (index 2) and only puts the user's signature on input 0 / output 0 via `set_p2tr_key_spend_witness`: [1](#0-0) 

The user's signature is `SinglePlusAnyoneCanPay` (documented on `WithdrawParams`), which under BIP341/BIP143 semantics only commits to input 0 and the output at the same index (the payout output); it does not commit to any other inputs or to the `OP_RETURN`/anchor outputs: [2](#0-1) 

The actual funding of the payout (covering `output_amount`, which is normally far larger than the dust input) is added later "using TxSender RBF option": [3](#0-2) 

On the verifier side, the operator attribution recorded in the database, `payout_payer_operator_xonly_pk`, is populated purely by parsing the OP_RETURN bytes of whatever payout transaction is found on-chain for the withdrawal UTXO - with no check that the funding inputs of that transaction belong to, or were authorized by, the named operator: [4](#0-3) 

This value is later trusted as ground truth to decide which operator is credited/reimbursed for that withdrawal, both when checking for malicious kickoffs and when an operator looks up its own unhandled payouts to claim reimbursement: [5](#0-4) [6](#0-5) 

Because (a) the OP_RETURN payer identity is not signature-protected and (b) `SinglePlusAnyoneCanPay` explicitly permits arbitrary third-party inputs/outputs to be attached around the user-signed input/output pair, any party who observes the user-signed input+output (e.g. once any operator's own unconfirmed payout tx reaches the public mempool) can construct a *different*, self-funded transaction that reuses that same signed input/output, but attaches its own funding input(s) and writes an arbitrary registered operator's x-only pubkey into the OP_RETURN. If this alternate transaction confirms (e.g. via fee-bumping/RBF race) instead of the real operator's broadcast, the database will record the named (but uninvolved) operator as `payout_payer_operator_xonly_pk`, even though that operator never funded the withdrawal - the attacker did.

### Impact Explanation
This breaks the core custody binding "the operator credited == the party that paid": the operator whose xonly pubkey ends up in the OP_RETURN is the one whose automation (`get_first_unhandled_payout_by_operator_xonly_pk`) will treat the withdrawal as its own unhandled payout and proceed to kickoff and claim reimbursement from the bridge/vault for a withdrawal it never actually funded. This matches the "operator reimbursed for a payout it never funded" Critical category, and can additionally be used to grief/sabotage an honest, uninvolved operator by causing its collateral/round funds to be drawn down for a payment it made no decision to make and did not benefit from, which can leave that operator without reimbursement capacity for withdrawals it genuinely does front later ("an honest operator's collateral burned" / "permanently unable to be reimbursed").

### Likelihood Explanation
Exploitation requires the attacker to fully self-fund the withdrawal output amount for the reused input/output pair and win a fee-bumping race (or otherwise get an alternate transaction confirmed) against the legitimate operator's broadcast, which raises the cost/complexity, but the underlying signature scope gap (`SinglePlusAnyoneCanPay` combined with an unsigned OP_RETURN payer field) is real and requires no special privilege, key compromise, or trusted role - only public mempool visibility and normal Bitcoin transaction construction/broadcast capability.

### Recommendation
Bind the payer identity cryptographically to the actual transaction rather than trusting an unsigned OP_RETURN: e.g., require the payout's funding input(s) to be provably owned/signed by the operator being credited, or extend the committed sighash (or add an operator signature covering the whole transaction, including the OP_RETURN and funding inputs) so a third party cannot rewrite payer attribution while reusing the user's `SinglePlusAnyoneCanPay` signature.

### Proof of Concept
1. A user obtains a withdrawal signature and outpoint for `output_amount`/`output_script_pubkey`, signed `SinglePlusAnyoneCanPay` over input 0 / output 0 only, per `WithdrawParams` / `create_payout_txhandler`.
2. A legitimate operator broadcasts its payout transaction (input 0 = user's dust UTXO + witness, funding input from the operator's own wallet, output 0 = payout, output 1 = anchor, output 2 = `OP_RETURN(<operator_xonly_pk>)`), which is now visible in the public mempool.
3. An attacker observes the transaction, extracts the signed input 0 and output 0 (which remain individually valid under `SinglePlusAnyoneCanPay`), and constructs a new transaction that reuses them but supplies its own funding input(s) to cover `output_amount`, and sets `OP_RETURN` to a different, uninvolved, currently-registered operator's x-only pubkey.
4. The attacker broadcasts this alternate transaction with a higher fee/RBF so it confirms instead of the original.
5. `update_finalized_payouts` in `core/src/verifier.rs` parses the confirmed transaction's OP_RETURN and records the uninvolved operator as `payout_payer_operator_xonly_pk` for that withdrawal.
6. The uninvolved operator's automation later finds this via `get_first_unhandled_payout_by_operator_xonly_pk`, proceeds to kickoff, and is reimbursed from the bridge/vault for a withdrawal it never funded.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
            ));
        }

        self.db
            .update_payout_txs_and_payer_operator_xonly_pk(
                Some(dbtx),
                payout_txs_and_payer_operator_idx,
            )
            .await?;

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }
