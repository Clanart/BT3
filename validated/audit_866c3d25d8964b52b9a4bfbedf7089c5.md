Audit Report

## Title
Missing socket-address de-duplication in `ClusterInfo::repair_peers` combined with equal-weight fallback in `ClusterSlots::compute_weights` allows sybil poisoning of the repair-peer selection pool - (`gossip/src/cluster_info.rs`, `core/src/cluster_slots_service/cluster_slots.rs`)

## Summary
`ClusterInfo::repair_peers(slot)` admits every CRDS `ContactInfo` with a valid TVU/serve-repair socket into the repair candidate pool without any stake requirement or de-duplication by IP/port, unlike the gossip pull/push paths which explicitly call `dedup_gossip_addresses` to collapse multiple pubkeys sharing one socket down to the highest-staked one. `ClusterSlots::compute_weights` then weights any pubkey absent from `validator_stakes` as `1` (identical to a genuine minimally-staked validator) and floors the combined weight at `1`, so cheap sybil `ContactInfo` entries pointed at a single attacker-controlled endpoint compete on equal footing with legitimate low-stake peers in the `WeightedIndex`-based sampling used by `ServeRepair::repair_peer_weights`/`RepairPeers::sample`.

## Finding Description
`ClusterInfo::repair_peers` filters candidates only by valid TVU/serve-repair sockets and an optional `LowestSlot` bound — no stake check, no socket dedup: [1](#0-0) . This contrasts with `dedup_gossip_addresses`, which collapses multiple pubkeys sharing a gossip socket to the highest-stake one, and which is used in `new_pull_request` and `refresh_push_active_set`: [2](#0-1) [3](#0-2) [4](#0-3) . That dedup is never applied to the repair path, so `ServeRepair::repair_peers` (called from `repair_peers_from_cache`) and `repair_request_ancestor_hashes_sample_peers` both consume the un-deduplicated pool directly: [5](#0-4) [6](#0-5) .

`ClusterSlots::compute_weights`, used as the default weight source (`RepairPeerWeightSource::ClusterSlots`) for standard shred repair, defaults any pubkey missing from `validator_stakes` to `1` and floors the final `(support/2 + stake/2)` combination at `1` as well: [7](#0-6) . This is confirmed by the repo's own unit tests, which explicitly assert that an unstaked/default `ContactInfo` gets weight `1`, same floor as a genuine but very low-stake peer: [8](#0-7) [9](#0-8) . These weights feed `WeightedIndex` in `RepairPeers::new`/`sample`, which is the actual peer-selection mechanism for standard shred repair requests: [10](#0-9) .

The number of sybil `ContactInfo` entries an attacker can sustain is bounded only by `CRDS_UNIQUE_PUBKEY_CAPACITY` (8192) and the CRDS table's stake-preferring eviction, which triggers only once the table exceeds `1.1 * cap` and removes just the overshoot amount per trim — it does not prevent an attacker from filling most of the headroom below the cap with zero-stake identities all pointing at one physical endpoint: [11](#0-10) . Note that `compute_weights_exclude_nonfrozen` (used only for ancestor-hash sampling) is stricter, requiring `stake > 0` in the recorded slot support, but this stricter path is not used for the default shred-repair `compute_weights` call: [12](#0-11) .

## Impact Explanation
Because sybil entries are admitted into the repair pool at parity weight with genuine low-stake peers, and because the pool is not deduplicated by socket address, an attacker who registers many cheap `ContactInfo` entries pointed at one malicious/unresponsive repair server can accumulate an outsized share of total sampling weight in `WeightedIndex` relative to genuine peers — including, in aggregate, relative to a single well-staked honest peer, since sybil weight sums linearly with count. This increases the probability that a querying validator directs shred/ancestor-hash repair requests to the attacker's endpoint, which can silently drop them, degrading that validator's block/shred repair throughput. This falls under the allowed "non-RPC remote exhaustion/degradation of syncing validators" impact category via the repair path.

## Likelihood Explanation
Generating keypairs and gossiping signed `ContactInfo` values is cheap and requires no stake; the only friction is the aggregate CRDS capacity (8192 unique pubkeys) and its stake-preferring eviction, which bounds but does not prevent large numbers of sybils, particularly on clusters where genuine unique validator identities are far below that cap. No privileged access, validator status, or trusted role is required — this is an unprivileged gossip-flooding attack using only public gossip protocol inputs.

## Recommendation
- Apply `dedup_gossip_addresses` (or an equivalent socket-address dedup keeping the highest-stake pubkey) to the candidate list built in `ClusterInfo::repair_peers` before it is returned to `ServeRepair`.
- Change `ClusterSlots::compute_weights`'s fallback for pubkeys absent from `validator_stakes` from `1` to `0`, or exclude such peers entirely, matching the stricter `stake > 0` requirement already used in `compute_weights_exclude_nonfrozen`.

## Proof of Concept
1. From a single host, generate N keypairs and gossip signed `ContactInfo` values for each, all with TVU/serve-repair sockets pointing at one attacker-controlled `SocketAddr` running a modified repair server that drops all requests.
2. Choose N large relative to the number of genuinely low-stake validators (bounded by `CRDS_UNIQUE_PUBKEY_CAPACITY` minus current unique pubkeys, per `gossip/src/crds.rs` L671-696).
3. Call `ClusterInfo::repair_peers(slot)` and observe the sybil entries included with no dedup filtering, matching `gossip/src/cluster_info.rs` L1158-1176.
4. Call `ClusterSlots::compute_weights(slot, &repair_peers)` and confirm each sybil peer receives `weight == 1`, identical to the `test_compute_weights_failsafes`/`test_best_peer_3` fixtures at `core/src/cluster_slots_service/cluster_slots.rs` L678-748.
5. Run repeated `WeightedIndex` sampling (as in `RepairPeers::sample`) across the full peer set and measure the fraction of draws landing on the attacker's endpoint versus genuine high-stake peers, demonstrating disproportionate selection probability as N grows.

impl RepairPeers {
    fn new(
        asof: Instant,
        weight_source: RepairPeerWeightSource,
        peers: &[ContactInfo],
        weights: &[u64],
    ) -> Result<Self> {
        if peers.len() != weights.len() {
            return Err(Error::from(WeightedError::InvalidWeight));
        }
        let (peers, weights): (Vec<_>, Vec<u64>) = peers
            .iter()
            .zip(weights)
            .filter_map(|(peer, &weight)| {
                let node = Node {
                    pubkey: *peer.pubkey(),
                    serve_repair: peer.serve_repair(Protocol::UDP)?,
                };
                Some((node, weight))
            })
            .unzip();
        if peers.is_empty() {
            return Err(Error::from(ClusterInfoError::NoPeers));
        }
        let weighted_index = WeightedIndex::new(weights)?;
        Ok(Self {
            asof,
            weight_source,
            peers,
            weighted_index,
        })
    }

    fn sample<R: Rng>(&self, rng: &mut R) -> &Node {
        let index = self.weighted_index.sample(rng);
        &self.peers[index]
    }

    pub(crate) fn compute_weights(&self, slot: Slot, repair_peers: &[ContactInfo]) -> Vec<u64> {
        if repair_peers.is_empty() {
            return vec![];
        }
        let stakes = {
            let failsafe = std::iter::repeat_n(1, repair_peers.len());
            let Some(epoch) = self.get_epoch_for_slot(slot) else {
                error!("No epoch info for slot {slot}");
                return Vec::from_iter(failsafe);
            };
            let epoch_metadata = self.epoch_metadata.read().unwrap();
            let Some(stakeinfo) = epoch_metadata.get(&epoch) else {
                error!("No epoch_metadata record for epoch {epoch}");
                return Vec::from_iter(failsafe);
            };
            let validator_stakes = stakeinfo.validator_stakes.as_ref();
            repair_peers
                .iter()
                .map(|peer| {
                    validator_stakes
                        .get(peer.pubkey())
                        .cloned()
                        .unwrap_or(1)
                        .max(1)
                })
                .collect()
        };
        let Some(slot_peers) = self.lookup(slot) else {
            return stakes;
        };

        repair_peers
            .iter()
            .map(|peer| slot_peers.get_support_by_pubkey(peer.pubkey()).unwrap_or(0))
            .zip(stakes)
            .map(|(a, b)| (a / 2 + b / 2).max(1u64))
            .collect()
    }

    pub(crate) fn compute_weights_exclude_nonfrozen(
        &self,
        slot: Slot,
        repair_peers: &[ContactInfo],
    ) -> (Vec<u64>, Vec<usize>) {
        let Some(slot_peers) = self.lookup(slot) else {
            return (vec![], vec![]);
        };
        let mut weights = Vec::with_capacity(repair_peers.len());
        let mut indices = Vec::with_capacity(repair_peers.len());

        for (index, peer) in repair_peers.iter().enumerate() {
            if let Some(stake) = slot_peers.get_support_by_pubkey(peer.pubkey())
                && stake > 0
            {
                weights.push(stake.max(1));
                indices.push(index);
            }
        }
        (weights, indices)
    }

    /// Returns true if the number of unique pubkeys in the table exceeds the
    /// given capacity (plus some margin).
    /// Allows skipping unnecessary calls to trim without obtaining a write
    /// lock on gossip.
    pub(crate) fn should_trim(&self, cap: usize) -> bool {
        // Allow 10% overshoot so that the computation cost is amortized down.
        10 * self.records.len() > 11 * cap
    }

    /// Trims the table so that the number of unique pubkeys are bounded.
    pub(crate) fn trim(
        &mut self,
        cap: usize, // Capacity hint for number of unique pubkeys.
        // Set of pubkeys to never drop.
        // e.g. known validators, self pubkey, entrypoints, ...
        keep: &HashSet<Pubkey>,
        stakes: &HashMap<Pubkey, u64>,
        now: u64,
    ) -> usize {
        if self.should_trim(cap) {
            let size = self.records.len().saturating_sub(cap);
            self.drop(size, keep, stakes, now)
        } else {
            0
        }
    }

    // Drops 'size' many pubkeys with the lowest stake if stakes are known
    // Otherwise select and drop a random sample of `size` many pubkeys
    fn drop(
        &mut self,
        size: usize,
        keep: &HashSet<Pubkey>,
        stakes: &HashMap<Pubkey, u64>,
        now: u64,
    ) -> usize {
        if stakes.values().all(|&stake| stake == 0) {
            // Stakes are unavailable, evict amount above cap
            return self.drop_random(size, keep, now);
        }
        let mut keys: Vec<_> = self
            .records
            .keys()
            .map(|k| (stakes.get(k).copied().unwrap_or_default(), *k))
            .collect();
        if size < keys.len() {
            keys.select_nth_unstable(size);
        }
        let keys: Vec<_> = keys
            .into_iter()
            .take(size)
            .map(|(_, k)| k)
            .filter(|k| !keep.contains(k))
            .flat_map(|k| &self.records[&k])
            .map(|k| self.table.get_index(*k).unwrap().0.clone())
            .collect();
        for key in &keys {
            self.remove(key, now);
        }
        keys.len()
    }
