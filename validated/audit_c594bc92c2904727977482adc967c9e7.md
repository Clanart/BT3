## Finding

The strongest reachable analog to ALPINE-CVE-2016-3191 (stack-based overflow from unbounded recursive parsing of nested constructs) is the **`json` precompile's use of unguarded, unbounded-depth `encoding/json` unmarshalling on raw attacker-supplied calldata**, reachable from any EVM transaction.

### Title
Unbounded recursive JSON depth in the `json` precompile causes an unrecoverable goroutine stack-overflow crash on every validator - (File: precompiles/json/json.go)

### Summary
`PrecompileExecutor.extractAsBytes`, `extractAsBytesList`, `ExtractAsUint256`, and `extractAsBytesFromArray` all call Go's standard `encoding/json` `Unmarshal` directly on `args[0].([]byte)`, which is fully attacker-controlled EVM calldata, with no nesting-depth limit imposed before or during decoding. [1](#0-0) [2](#0-1) 

### Finding Description
`encoding/json.Unmarshal` decodes arrays/objects via mutual recursion in the decoder (each `[` or `{` triggers another recursive call into the value decoder for its children), with no depth cap in the standard library. A payload consisting of many thousands to millions of nested `[` characters (e.g. `[[[[[...]]]]]`) drives that recursion arbitrarily deep. Unlike a normal Go panic, exceeding the runtime's maximum goroutine stack size is a **fatal, unrecoverable runtime error** ("goroutine stack exceeds … -byte limit") that terminates the entire process — it cannot be caught by `recover()`, unlike an ordinary EVM execution panic.

The codebase already recognizes this exact bug class and defends against it elsewhere:
- `evmrpc/tracers.go`'s `validateMuxTraceConfig` explicitly caps `depth` against `maxMuxTracerNestingDepth` before recursing into nested tracer JSON. [3](#0-2) 
- `sei-cosmos/codec/unknownproto/unknown_fields.go` caps protobuf `Any` nesting via `MaxProtobufNestingDepth`. [4](#0-3) 
- `app/antedecorators/authz_nested_message.go` caps nested `MsgExec` recursion at `maxNestedMsgs`. [5](#0-4) 

No equivalent guard exists on the `json` precompile's `gjson.Unmarshal` calls: only a byte-length-proportional gas charge is applied, which limits total payload size but not nesting depth relative to size (a highly compressible pattern like repeated `[` maximizes depth per byte). [6](#0-5) 

### Impact Explanation
Because the `json` precompile executes as part of ordinary EVM message execution, every full node/validator that processes the block containing such a transaction runs the same vulnerable `Unmarshal` call deterministically. A fatal stack-overflow runtime error crashes the whole node process (not just the transaction, not just a goroutine), producing a **network-wide validator halt** once the transaction is included in a block, or a crash of default-configuration RPC/full nodes that simulate/execute it via `eth_call`/`eth_sendRawTransaction` prior to inclusion.

### Likelihood Explanation
This is directly reachable by any unprivileged EVM transaction sender or contract deployer — no privileges, precompile allow-list, or governance action is required. Constructing a deeply nested JSON byte array is straightforward and inexpensive per byte; the `GasCostPerByte` charge is linear, not exponential, so an attacker can afford enough bytes within a block's gas limit to reach a fatal recursion depth. The bug fires unconditionally whenever `gjson.Unmarshal` is invoked on such a payload, i.e. deterministically, not probabilistically.

### Recommendation
Impose an explicit maximum nesting-depth check on the raw JSON payload before calling `encoding/json.Unmarshal` in all four `PrecompileExecutor` methods in `precompiles/json/json.go` (mirroring the depth-limiting pattern already used in `evmrpc/tracers.go`'s `validateMuxTraceConfig`), or switch to a streaming/iterative JSON parser (e.g. `json.Decoder` with `Token()`-based depth counting) that rejects payloads exceeding a safe depth before recursive struct construction occurs.

### Proof of Concept
1. Deploy/call any contract (or call the precompile directly at address `0x0000000000000000000000000000000000001003`) invoking `extractAsBytesFromArray(bytes,uint16)` or `extractAsBytes(bytes,string)`.
2. Set the `bytes` argument to a JSON payload of the form `strings.Repeat("[", N)` (optionally closed) where `N` is large enough (on the order of hundreds of thousands, size-permitting under the block gas limit) to exceed the Go runtime's maximum stack size during `encoding/json.Unmarshal`'s recursive descent.
3. Submit the transaction; every node executing it invokes `p.extractAsBytesFromArray` → `gjson.Unmarshal(bz, &decoded)` [7](#0-6) , triggering the Go runtime's fatal "goroutine stack exceeds maximum" error and crashing the process on every validator that processes the block.

const maxNestedMsgs = 5

type AuthzNestedMessageDecorator struct{}

func NewAuthzNestedMessageDecorator() AuthzNestedMessageDecorator {
	return AuthzNestedMessageDecorator{}
}

func (ad AuthzNestedMessageDecorator) AnteHandle(ctx sdk.Context, tx sdk.Tx, simulate bool, next sdk.AnteHandler) (newCtx sdk.Context, err error) {
	for _, msg := range tx.GetMsgs() {
		switch m := msg.(type) {
		case *authz.MsgExec:
			// find nested evm messages
			containsEvm, err := ad.CheckAuthzContainsEvm(ctx, m, 0)
			if err != nil {
				return ctx, err
			}
			if containsEvm {
				return ctx, errors.New("permission denied, authz tx contains evm message")
			}
		default:
			continue
		}
	}

	return next(ctx, tx, simulate)
}

func (ad AuthzNestedMessageDecorator) CheckAuthzContainsEvm(ctx sdk.Context, authzMsg *authz.MsgExec, nestedLvl int) (bool, error) {
	if nestedLvl >= maxNestedMsgs {
		return false, errors.New("permission denied, more nested msgs than permitted")
