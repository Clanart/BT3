## Title
Deep-link "Open Repository from URL" action silently fetches and checks out an attacker-controlled PR/branch into an already-cloned repository — ([File: app/src/ui/dispatcher/dispatcher.ts])

### Summary
The bug-class from the report is: an unprivileged actor supplies an identifier (a "receiver"/target) that the victim did not choose, and the application uses that identifier to silently mutate victim-controlled state (a lock timestamp) with no re-authorization check. The GitHub Desktop analog is the `x-github-client://openRepo/...` protocol handler: an attacker fully controls the `url`, `branch`, and `pr` parameters of the deep link, and if the victim already has the referenced repository cloned, Desktop will automatically add a remote, fetch it, and check out the attacker-chosen ref — with no confirmation dialog, exactly mirroring the "attacker-supplied target causes unauthorized state mutation with no re-check" pattern from the report.

### Finding Description
`parseAppURL` parses the `openRepo` deep-link action into an `IOpenRepositoryFromURLAction` with attacker-controlled `url`, `branch`, and `pr` fields validated only for character-set sanity, not authorization/trust: [1](#0-0) 

`dispatchURLAction` routes this straight into `openRepositoryFromUrl` with no user confirmation gate: [2](#0-1) 

If the target repository is already cloned locally (matched purely by comparing the `url` parameter to origin/upstream URLs via `doesRepositoryMatchUrl`), `openOrCloneRepository` skips the "Clone Repository" popup entirely and just calls `selectRepository`: [3](#0-2) 

For the PR case, `openPullRequestFromUrl` then calls `_checkoutPullRequest`, which — via `_findPullRequestBranch` — adds a brand-new remote pointing at the PR head's `clone_url` (an arbitrary fork URL taken from the GitHub API response for the attacker-chosen PR number), fetches it, and creates/checks out a local branch tracking that fork ref, all without prompting the user: [4](#0-3) [5](#0-4) [6](#0-5) 

For the branch case, `openBranchNameFromUrl` fetches and calls `checkoutLocalBranch` automatically as soon as the deep link is opened: [7](#0-6) 

No step in this chain asks the victim "are you sure you want to check out code from this fork?" — the only gating condition is whether the repo happens to already be open in Desktop, which an attacker can trivially arrange by targeting any public/popular repository the victim is known to have cloned (e.g., their employer's or a well-known OSS repo).

### Impact Explanation
Clicking a single crafted link (e.g. embedded in an email, issue comment, or malicious webpage, using the registered `x-github-client://` / `github-mac://` protocol) causes Desktop to silently:
1. Add a new git remote pointing at an attacker-controlled fork.
2. Fetch that fork's content into the victim's local `.git` object store.
3. Check out a new branch tracking the attacker's ref into the victim's working directory.

This corrupts "what the user commits or pushes" going forward: the victim's working tree now contains attacker-authored files (build scripts, CI workflow files, dependency manifests, editor/launch configs) without any indication that this content did not come from a source the victim trusted or reviewed. If the victim continues working, commits, or builds/runs the project, attacker-controlled content executes or gets propagated upstream — this matches the report's "impact category" of silent corruption of committed/pushed state via a link the victim clicked, without any local access, admin rights, or leaked credentials.

### Likelihood Explanation
The only prerequisite is that the victim has previously cloned the targeted repository in Desktop (common for any actively used or well-known repository) and clicks a link. No confirmation dialog exists between the click and the fetch/checkout for the "PR" and "branch" deep-link variants when the repo is already present — this is a straightforward, repeatable one-click trigger with no unusual victim behavior required.

### Recommendation
- Require an explicit user-facing confirmation dialog before adding a new remote / fetching / checking out any ref triggered via `openRepo` deep links, showing the source fork URL and PR author to the user for review.
- Do not silently skip the existing repository confirmation path (`openOrCloneRepository`'s "already cloned" branch) for the `pr=`/`branch=` variants — surface the same level of scrutiny as a first-time clone.
- Consider requiring that the `url` parameter's owner/repo match an already-associated `GitHubRepository` the user has explicitly interacted with (e.g., starred/has write access to) before allowing automatic remote creation from PR metadata.

### Proof of Concept
1. Attacker forks a public repository the victim already has cloned in Desktop and opens a pull request from the fork containing malicious changes (e.g., a modified `package.json`/`Makefile`/CI workflow).
2. Attacker sends the victim a link: `x-github-client://openRepo/https://github.com/<owner>/<repo>?pr=<attacker_pr_number>`.
3. Victim clicks the link (e.g., delivered via email or a webpage). Desktop invokes `handleAppURL` → `parseAppURL` → `dispatchURLAction` → `openRepositoryFromUrl` → `openPullRequestFromUrl` → `_checkoutPullRequest` [8](#0-7) .
4. Because the repository is already present locally, `openOrCloneRepository` bypasses the clone confirmation UI [9](#0-8) , and `_findPullRequestBranch` adds the attacker's fork as a new remote, fetches it, and checks out `pr/<number>` automatically [10](#0-9) .
5. The victim's working directory now contains attacker-controlled files with no confirmation ever shown.

      return null

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }
    if (!isRepositoryWithGitHubRepository(repository)) {
      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    if (pullRequest.head.repo === null) {
      return null
    }

    await this.appStore._checkoutPullRequest(
      repository,
      pullRequest.number,
      pullRequest.head.repo.owner.login,
      pullRequest.head.repo.clone_url,
      pullRequest.head.ref
    )

    return repository
  }

  private async openOrCloneRepository(url: string): Promise<Repository | null> {
    const state = this.appStore.getState()
    const repositories = state.repositories
    const existingRepository = repositories.find(r =>
      this.doesRepositoryMatchUrl(r, url)
    )

    if (existingRepository) {
      return await this.selectRepository(existingRepository)
    }

    return this.appStore._startOpenInDesktop(() => {
      this.changeCloneRepositoriesTab(CloneRepositoryTab.Generic)
      this.showPopup({
        type: PopupType.CloneRepository,
        initialURL: url,
      })
    })
  }
