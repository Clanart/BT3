### Title
Unbounded buffer over-read in CLVM canonical-encoding check on attacker-submitted spend bundles - (File: chia/full_node/mempool_manager.py)

### Summary
`is_atom_canonical()` in `chia/full_node/mempool_manager.py` parses a CLVM atom's length prefix directly from attacker-controlled bytes and reads `prefix_len` (up to 5) additional bytes past the leading byte without ever checking that `offset` stays inside the buffer, mirroring the class of bug in CVE-2019-11455 (Monit's `Util_urlDecode` reading past the end of a request buffer while decoding attacker-supplied encoded data).

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` inspects the top bits of `clvm_buffer[offset]` to decide how many additional length-prefix bytes (`prefix_len`, 0–5) to consume, then loops: [1](#0-0) 

The loop body does `offset += 1; atom_len |= clvm_buffer[offset]` for `prefix_len` iterations with no check that `offset < len(clvm_buffer)` before or during the loop. The caller, `is_clvm_canonical()`, walks the buffer token-by-token using `atom_len, canonical = is_atom_canonical(clvm_buffer, offset)` and advances `offset += atom_len`, again without validating that the reported `atom_len` or the next `offset` stay within the buffer before the next iteration reads `clvm_buffer[offset]`: [2](#0-1) 

Because `clvm_buffer` here is a Python `bytes` object, an out-of-bounds index does not literally leak adjacent heap memory the way the C `Util_urlDecode` bug did — instead it raises an uncaught `IndexError`. Functionally, this is the direct analog of the Monit bug class: a length-prefixed decoder that trusts an attacker-supplied length field and reads past the buffer boundary while decoding externally-supplied encoded data, with the same trigger vector of "manipulation of a submitted parameter" (here, the serialized CLVM solution/generator bytes of a submitted spend bundle instead of a GET/POST parameter).

### Impact Explanation
If a crafted spend bundle whose CLVM serialization is truncated right at an atom's multi-byte length-prefix boundary reaches this canonicality check without a surrounding broad exception handler, the resulting unhandled `IndexError` can abort the transaction-validation code path for the submitted spend bundle. Since this check sits in the mempool admission path (`chia/full_node/mempool_manager.py`), which is reachable by any unprivileged remote peer or wallet submitting a `SpendBundle`, a reliably-crafted bundle can be used to repeatedly trigger the exception, causing a spend-triggered denial-of-service against mempool/transaction processing — the impact class explicitly permitted by the validation rules ("a spend-triggered transaction-processing halt").

### Likelihood Explanation
Likelihood is moderate: constructing a byte sequence whose declared CLVM atom length-prefix bits claim more prefix bytes than remain in the buffer is straightforward (it only requires crafting the trailing bytes of a spend bundle's solution/generator so a length-prefix atom starts near the very end of the buffer). The main uncertainty — which could not be fully confirmed from the available index — is whether the call sites of `is_clvm_canonical`/`is_atom_canonical` are wrapped in a catch-all exception handler that gracefully rejects the bundle (in which case impact is limited to bundle rejection) or whether the exception can propagate further up an unguarded path.

### Recommendation
Add explicit bounds checks in `is_atom_canonical` before every `clvm_buffer[offset]` access (validate `offset < len(clvm_buffer)` prior to reading the length-prefix bytes, and validate the final computed `atom_len`/`offset` against `len(clvm_buffer)` in `is_clvm_canonical` before continuing the loop), returning a definite "not canonical"/error result instead of indexing out of range. Additionally, confirm and, if missing, add a defensive `try/except (IndexError, ValueError)` around the canonicality check at its call site(s) in the mempool admission pipeline so a malformed/truncated buffer results in bundle rejection rather than an unhandled exception.

### Proof of Concept
1. Construct a `clvm_buffer` whose last byte is a length-prefix discriminant byte requiring, e.g., `0b11100000` pattern (5+8+8 bits length prefix, `prefix_len = 2`), but provide zero or one trailing bytes after it (i.e., truncate the buffer so `offset + prefix_len` exceeds `len(clvm_buffer) - 1`).
2. Submit this buffer as (part of) the solution/generator bytes of a `SpendBundle` through the normal transaction submission path so it reaches `is_clvm_canonical(clvm_buffer)` during mempool pre-validation: [2](#0-1) 
3. Observe `clvm_buffer[offset]` raise `IndexError` inside `is_atom_canonical`, propagating up through `is_clvm_canonical` — if uncaught at the call site, this aborts validation of that spend bundle (and, if repeatable at scale, degrades mempool processing for the submitting session/worker).

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
