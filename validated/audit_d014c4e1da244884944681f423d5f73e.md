### Title
`ReceivedOutput::read` accepts a claimed key-offset without checking it actually unlocks the output's `script_pubkey`, letting crafted bytes report unspendable outputs as spendable funds - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
The Big Combo / Growth DeFi exploit was a "missing if-condition": the staking contract accepted a liquidity-pair token without validating that it was a real pair, so a worthless fake token was used to withdraw real assets. The analog in Serai's Bitcoin wallet code is the same class of bug — a deserialization routine accepts attacker-controlled fields without re-checking the invariant that ties them together. `ReceivedOutput::read` reads an `offset` scalar and a `TxOut`/`OutPoint` from untrusted bytes but never verifies that `key + offset*G` actually derives the output's `script_pubkey` — the very invariant `Scanner` maintains when it creates `ReceivedOutput`s legitimately.

### Finding Description
`Scanner` binds a spend-offset to a specific Taproot script: `register_offset` inserts `p2tr_script_buf(self.key + GENERATOR * offset) -> offset` and `scan_transaction` only emits a `ReceivedOutput` when `self.scripts.get(&output.script_pubkey)` matches, so a legitimately-produced `ReceivedOutput` always satisfies `output.script_pubkey == p2tr(key + offset*G)` [1](#0-0) [2](#0-1) .

`ReceivedOutput::read`, however, deserializes `offset`, `output`, and `outpoint` independently and returns them with no consistency check [3](#0-2) . The struct's invariants (`offset` is "the scalar offset to obtain the key usable to spend this output", per the field comment) are silently assumed rather than enforced [4](#0-3) . There is no `verify`/`check` method on `ReceivedOutput` at all, so nothing downstream re-establishes the binding either.

An unprivileged party who can cause these bytes to be fed to `read` (the type is `PartialEq`-comparable, serializable via `serialize`/`write`, and explicitly designed to cross trust boundaries) can claim any on-chain `TxOut` — e.g., someone else's output paying to an unrelated key — plus a junk `offset`, and the wallet will treat it as a received, spendable output. This mirrors the exploit exactly: a "fake" claim (wrong script/offset pairing, like the fake AXZ token) is accepted because the binding check is missing, and the "real" side (accounting crediting those sats as received/spendable) is then acted on.

### Impact Explanation
Funds are reported as received and spendable when they are not. Any `TxOut` on the network can be presented as a `ReceivedOutput` with a fabricated offset; the wallet's `value()`, `outpoint()`, and `output()` accessors will faithfully report the attacker's chosen amount and UTXO. Downstream coin-selection/signing would then either attempt to spend an output it cannot unlock (the offset yields a different key than the script commits to) or, worse, credit balances backed by outputs the multisig never controlled — the same end state as Growth DeFi crediting a fake LP position and releasing real liquidity. At minimum this produces incorrecr balance accounting and stuck/failed spends; where received outputs drive crediting logic, it enables claiming deposits that were never made.

### Likelihood Explanation
Reachability requires only untrusted bytes reaching `ReceivedOutput::read` — no key material, no validator privileges, no collusion. The type exists precisely to be serialized (`write`/`serialize`) and transmitted between components, and `read` performs no key-context validation by construction (it cannot — the function doesn't even take the scanner key, so the check is structurally impossible at this layer and must happen at a caller that isn't forced to do it). That is a Medium-severity pattern: conditional on an integrator round-tripping these objects through an untrusted channel/storage, but when it happens the fake output is accepted silently — exactly like the missing if-condition, which only fired when the attacker bothered to supply the fake token.

### Recommendation
Bind the offset to the output at deserialization or add a mandatory verification step:

- Change `ReceivedOutput::read` (or add `ReceivedOutput::read_and_verify(key, r)` / `fn verify(&self, key: &ProjectivePoint) -> bool`) to recompute `p2tr_script_buf(key + GENERATOR * offset)` and reject inputs where it doesn't equal `output.script_pubkey`.
- Alternatively make `ReceivedOutput` construction `pub(crate)`-only, so the only way to obtain one is through `Scanner::scan_transaction`, which enforces the invariant.
- Document and enforce that any caller deserializing a `ReceivedOutput` must re-derive the script from `(key, offset)` before crediting or spending it — mirroring the fix the exploit needed: check the token is the real pair before accepting the stake.

### Proof of Concept
Conceptual reproduction (Rust, `std` feature):

```rust
// networks/bitcoin/src/wallet/mod.rs behavior demo
let real_scanner_key: ProjectivePoint = /* multisig group key */;
let scanner = Scanner::new(real_scanner_key).unwrap();

// Attacker picks ANY output on the network, e.g. paying to their own key:
let victim_offset = Scalar::ONE; // junk: does NOT derive the output's script
let foreign_output = TxOut {
    value: Amount::from_sat(1_000_000),
    script_pubkey: /* attacker-controlled P2TR script */,
};

// Craft bytes: offset || TxOut || OutPoint
let mut buf = victim_offset.to_bytes().to_vec();
buf.extend(serialize(&foreign_output));
buf.extend(serialize(&OutPoint::new(attacker_txid, 0)));

// Accepted with no consistency check:
let ro = ReceivedOutput::read(&mut buf.as_slice()).unwrap();
assert_eq!(ro.value(), 1_000_000); // reported as received/spendable

// Yet spending it is impossible: real_scanner_key + victim_offset*G
// does not equal the key committed in `foreign_output.script_pubkey`,
// so no threshold signature over the tweaked key can satisfy the output.
```

The crafted object passes `read`, reports a 1,000,000-sat output as belonging to the wallet, and is unspendable — the direct analog of the fake-token LP position that was accepted and used to withdraw real funds.

  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }
