### Title
Unauthenticated operator attribution in payout OP_RETURN allows reimbursement misattribution - (File: `core/src/builder/transaction/operator_reimburse.rs`)

### Summary
The `payout_tx`'s OP_RETURN output, which encodes the `operator_xonly_pk` used later to decide which operator is credited/reimbursed for a withdrawal, is not covered by the withdrawing user's signature because that signature uses `SIGHASH_SINGLE|ANYONECANPAY`. Any party holding the raw signed input (from the user's off-chain-provided `in_signature`) could rebuild the payout transaction with a different `operator_xonly_pk` in the OP_RETURN before broadcasting, without invalidating the user's signature.

### Finding Description
`create_payout_txhandler` builds the payout transaction with three outputs: the user payout, an anchor, and an OP_RETURN containing `operator_xonly_pk.serialize()` [2](#0-1) . Only the first input (the withdrawal UTXO, spent by the user's key-path signature) is signed, and `operator.withdraw()` verifies that signature using `in_signature.sighash_type`, explicitly documenting that it must be `SinglePlusAnyoneCanPay` [3](#0-2) . Later, the verifier's block-processing logic (`update_finalized_payouts`) determines which operator is credited purely by parsing this OP_RETURN field from the payout transaction actually observed on-chain, with no cross-check against any operator signature or funding input [4](#0-3) . That attribution is then used by `get_first_unhandled_payout_by_operator_xonly_pk` and `handle_finalized_payout` to select which operator's kickoff/reimbursement flow gets driven [5](#0-4) [6](#0-5) . If `SIGHASH_SINGLE|ANYONECANPAY` indeed leaves outputs beyond index 0 unauthenticated (standard BIP-341/BIP-143 semantics), the OP_RETURN and even the anchor output can be freely rewritten by anyone who has the signed input, breaking the intended equality "OP_RETURN operator_xonly_pk == operator who actually fronted/broadcast the payout."

### Impact Explanation
If exploitable, this breaks the binding "the operator credited versus the party that paid": a party could redirect credit for a payout to an operator that never funded/broadcast it, or prevent the true payer from ever being matched to its own payout (since `validate_payer_is_operator` in `core/src/operator.rs:1686-1740` requires the DB-recorded payer key to equal the querying operator's own key). This could either cause an honest operator to be permanently unable to claim reimbursement for a payout it genuinely fronted, or cause reimbursement flow to be routed to an operator who did not pay — both are Critical-tier impacts per the rubric.

### Likelihood Explanation
Exploitability hinges entirely on the still-unverified detail of exactly which parts of the transaction `SIGHASH_SINGLE|ANYONECANPAY` commits to in this construction, and on whether an attacker can realistically obtain the user's raw signature before the legitimate operator broadcasts (the report calls this "given off-chain to operators", so it is not public by default, limiting realistic reachability to a race/interception scenario). Both of these left me at moderate-to-low confidence without further verification.

### Recommendation
Verify whether `SIGHASH_SINGLE|ANYONECANPAY` on this key-path spend leaves the OP_RETURN output (and anchor output) unauthenticated. If so, require the user's signature to use `SIGHASH_ALL` (or otherwise commit to all outputs, e.g., via a script path enforcing the OP_RETURN content), or have the payer operator additionally sign/commit to the OP_RETURN content in a way that can be independently verified, rather than relying solely on unauthenticated on-chain OP_RETURN parsing for reimbursement attribution.

### Proof of Concept
Not constructed — requires confirming BIP-341 sighash commitment rules for `SIGHASH_SINGLE|ANYONECANPAY` against `TxHandler::calculate_sighash_txin`, which I was unable to complete before running out of tool-call iterations. A background Devin session with repository access should verify this via `core/src/builder/transaction/txhandler.rs`'s sighash calculation and, if confirmed, write a unit/integration test that signs a payout tx, swaps the OP_RETURN operator key, and confirms `SECP.verify_schnorr` still passes in `operator.rs:632-637`.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
            ));
        }
