### Title
Full Go stack trace (including server file paths) is embedded in the public, queryable `TxResult.Log` field when the giga EVM executor panics - ([File: app/app.go])

### Summary
When the Giga (parallel) EVM transaction executor panics on an unexpected error while processing an EVM transaction submitted by any user, `makeGigaDeliverTx` recovers the panic and writes the entire `runtime/debug.Stack()` output directly into the `Log` field of the `abci.ResponseDeliverTx` / `ExecTxResult` that is committed for that transaction. This field is non-deterministic but is nonetheless persisted by the tx indexer and is publicly retrievable by anyone via the Tendermint `/tx` RPC endpoint, `GetTx` gRPC/REST endpoint, or block/tx search - exposing internal Go source file paths, function names, and goroutine stack layout to any unprivileged RPC client, analogous to the Xibo CMS stack-trace disclosure (CVE-2023-33181).

### Finding Description
In the giga (parallel) EVM tx execution path, `makeGigaDeliverTx` recovers from panics raised while executing an EVM transaction: [1](#0-0) 

For panics that are not classified as `OCCAbort`, `ErrorOutOfGas`, or `ErrIteratorUnsupported`, the handler builds the `Log` field of the returned `abci.ResponseDeliverTx` with:
```go
Log: fmt.Sprintf("recovered: %v\nstack:\n%v", r, string(debug.Stack())),
```
This is the *value returned to the caller* (the ABCI response used to finalize the transaction), not merely a server-side log line. It is functionally identical to the pattern that already exists (safely, server-side only) in `app/legacyabci/recovery.go`'s `newDefaultRecoveryMiddleware`, which wraps `sdkerrors.ErrPanic` with the same `"recovered: %v\nstack:\n%v"` message including `debug.Stack()`- but there that wrapped error also becomes part of `result.Log`/response `Log` via `sdkerrors.ResponseDeliverTxWithEvents` and `ABCIInfo`. [2](#0-1) 

The resulting `ExecTxResult.Log` (or `ResponseDeliverTx.Log`) is stored by the KV tx indexer and served back verbatim through:
- Tendermint RPC `Tx`/`TxSearch` (`sei-tendermint/internal/rpc/core/tx.go`), returning `ResultTx{TxResult: r.Result}` where `TxResult.Log` is the raw string: [3](#0-2) 
- The Cosmos SDK `GetTx` gRPC/REST service, which populates `TxResponse.RawLog` directly from `res.TxResult.Log`: [4](#0-3) 

Any unprivileged transaction sender can therefore submit an EVM transaction crafted to trigger an unexpected panic inside `executeEVMTxWithGigaExecutor` (e.g., malformed/edge-case input causing a nil-pointer dereference, out-of-bounds access, or type assertion failure not already covered by the special-cased recovery branches), then query the resulting `Log` via the public `/tx` endpoint or `GetTx` gRPC/REST call to read the full Go stack trace, which includes absolute or relative source file paths and internal package/function names of the running node binary.

### Impact Explanation
This discloses internal implementation details (file paths, function names, goroutine internals) of the validator/full node's binary to any public RPC client, aiding reconnaissance for further attacks (e.g., identifying code paths, build environment, or unpatched code versions) - the same class of impact as the Xibo CVE. It does not directly cause fund loss, but it is a genuine information-disclosure bug reachable by an unprivileged transaction sender through the standard transaction submission and query surface (submit tx -> query tx result), consistent with the "Sensitive Information Disclosure abusing Stack Trace" bug class.

### Likelihood Explanation
Reachability depends on finding an input that causes an *uncaught, non-special-cased* panic inside the giga executor path (the OOG, OCC-abort, and iterator-unsupported panic types are already handled without leaking a stack trace). Given the size and complexity of `executeEVMTxWithGigaExecutor` and its downstream EVM/precompile/state-access code, and the fact that a nearby comment ("For other panics (e.g., nil deref from malformed protobuf) ...") acknowledges this exact scenario is expected to occur in practice, it is plausible that such panics are triggerable by adversarial transaction inputs. Confirming a concrete panic-triggering payload would require deeper testing of `executeEVMTxWithGigaExecutor` and its callees, which was not fully explorable from the indexed code alone.

### Recommendation
- Do not include `debug.Stack()` (or any raw panic stack trace) in any field of `abci.ResponseDeliverTx` / `ExecTxResult` that is returned to callers (`Log`, `Info`, `Data`). Log the stack trace only server-side via the node's logger, as already done elsewhere (`logger.Error("panic in gigaDeliverTx", "panic", r, "stack", string(debug.Stack()))` right above the vulnerable line).
- Set the public `Log` field to a generic message (e.g., `"internal error"` or the wrapped `sdkerrors.ErrPanic` message without the stack), matching the safer pattern used for the OOG/OCC-abort branches in the same function.
- Apply the same fix to any other Log-population code path with a similar pattern, since `newDefaultRecoveryMiddleware` in `app/legacyabci/recovery.go` constructs an equivalent `"recovered: %v\nstack:\n%v"` message that also becomes part of the committed tx `Log`.

### Proof of Concept
1. Craft/submit an EVM transaction designed to trigger an unhandled panic inside the giga parallel executor (a path not covered by the `occ.Abort`, `sdk.ErrorOutOfGas`, or `gigastore.ErrIteratorUnsupported` special cases) via the public JSON-RPC `eth_sendRawTransaction` endpoint.
2. Once the transaction is included in a block, query its result via the public Tendermint RPC `tx` endpoint (`/tx?hash=0x...`) or the Cosmos `cosmos.tx.v1beta1.Service/GetTx` gRPC/REST call.
3. Observe that the returned `tx_result.log` / `raw_log` field contains the full string `"recovered: <panic value>\nstack:\n<full Go stack trace>"`, revealing internal source file paths and function names of the node binary, as produced by: [1](#0-0)

// newDefaultRecoveryMiddleware creates a default (last in chain) recovery middleware for app.runTx method.
func newDefaultRecoveryMiddleware() recoveryMiddleware {
	handler := func(recoveryObj interface{}) error {
		return sdkerrors.Wrap(
			sdkerrors.ErrPanic, fmt.Sprintf(
				"recovered: %v\nstack:\n%v", recoveryObj, string(debug.Stack()),
			),
		)
	}

	return newRecoveryMiddleware(handler, nil)
}

func (env *Environment) Tx(ctx context.Context, req *coretypes.RequestTx) (*coretypes.ResultTx, error) {
	// if index is disabled, return error
	if !indexer.KVSinkEnabled(env.EventSinks) {
		return nil, errors.New("transaction querying is disabled due to no kvEventSink")
	}

	for _, sink := range env.EventSinks {
		if sink.Type() == indexer.KV {
			r, err := sink.GetTxByHash(req.Hash)
			if r == nil {
				return nil, fmt.Errorf("tx (%X) not found, err: %w", req.Hash, err)
			}

			var proof types.TxProof
			if req.Prove {
				block := env.BlockStore.LoadBlock(r.Height)
				proof = block.Txs.Proof(int(r.Index))
			}

			return &coretypes.ResultTx{
				Hash:     req.Hash,
				Height:   r.Height,
				Index:    r.Index,
				TxResult: r.Result,
				Tx:       r.Tx,
				Proof:    proof,
			}, nil
		}

func NewResponseResultTx(res *ctypes.ResultTx, anyTx *codectypes.Any, timestamp string) *TxResponse {

		Height:    res.Height,

		Tx:        anyTx,
