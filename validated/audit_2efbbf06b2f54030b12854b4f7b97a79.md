### Title
`get-notional-evaluation` silently drops debt owed in a globally-disabled asset, letting `is-healthy` pass on understated debt during `borrow` - ([File: local-testing/contracts/market/market.clar])

### Summary
`borrow` (and `collateral-remove`) fetch the position with `get-position`, which is built from `.market-vault get-position account mask` using the **global enabled bitmap**, not the user's actual mask. `market-vault`'s `iter-lookup-debt`/`relevant` filters (`local-testing/contracts/market/market-vault.clar:175-235`) drop any debt-asset row whose enabled bit is not set from the returned `debt` list, so debt legitimately owed in a since-disabled asset never reaches `get-notional-evaluation`'s `debt-total`, while collateral for the same account is fully counted.

### Finding Description
The full chain: `borrow` calls `get-position` (`local-testing/contracts/market/market.clar:488-490`), which passes only the **global enabled bitmap** (`get-enabled-bitmap`) into `.market-vault get-position`. Inside `market-vault.clar`, `iter-lookup-debt` (`market-vault.clar:218-235`) asserts `relevant asset mask false` before appending a debt row (`market-vault.clar:175-178,226-228`); `relevant` checks the asset's debt bit is a *subset* of the passed-in enabled mask. If asset id 2's debt bit has been turned off in the global asset registry (assumed-correct DAO config per scope), the borrower's 50,000 USD debt-scaled entry for id 2 is never appended to the returned `debt` list — even though the underlying `debt` map in `market-vault.clar:83` still holds the real scaled balance and is never zeroed.

That truncated `debt` list flows straight into `get-notional-evaluation` (`market.clar:536-564`), whose fold in `calculate-asset-notional-value` (`market.clar:566-596`) only sums `debt-total` for rows present in `dlist` via `find-debt-scaled`. Because id 2's row is absent, `debt-total` reflects only the visible 79,000 USD, not the real 129,000 USD.

`borrow`'s health gates then operate on this understated figure: the pre-check `is-healthy collateral-value debt-value current-ltvb` (`market.clar:1295`) and the post-check `is-healthy-with-mask collateral-value debt-post-increased future-mask` (`market.clar:1310`) both use `debt-value`/`debt-post-increased` derived from the truncated total. `is-healthy` (`mainnet/contracts/market/v0-4-market.clar:656-659`) is a pure `(<= (* debt-usd BPS) (* collateral-usd ltv))` comparison with no mechanism to recover the missing 50,000 USD. Note that `get-assets`'s `user-safe-mask` (`market.clar:450-455`) explicitly does *not* mask the debt component by the enabled bitmap for pricing purposes — asymmetric with the vault-side debt-list filtering — confirming the exclusion happens specifically in the debt-list construction step, not by design elsewhere (collateral-remove's disabled-asset branch, `market.clar:1168-1176`, shows the protocol normally does special-case accounting to re-include disabled-asset value; no equivalent exists for debt in `borrow`).

Direction: debt is undervalued (real debt > visible debt); no gate re-adds the hidden amount before `is-healthy` is evaluated.

### Impact Explanation
This causes the health check to authorize new borrowing against real collateral that is already effectively pledged 130% against liabilities, letting the borrower extract additional funds from the protocol that cannot be recovered through liquidation (liquidation paths use `get-liquidation-position`/`get-full-position`, which are separate code paths and not verified here, but the extra borrowed principal has already left the protocol by the time any liquidation math runs). This is protocol insolvency / theft of protocol funds at rest, matching the Critical category.

### Likelihood Explanation
Requires (a) the borrower to hold debt in an asset before it is disabled (a normal lifecycle event under legitimate DAO control, out of attacker's control but foreseeable and awaitable) and (b) the borrower to then call `borrow` for a still-enabled asset. No special privilege is needed for step (b); the attacker only needs ordinary market access and to time the call after the disable event. Repeatable for any account holding debt in an asset that later becomes disabled.

### Recommendation
In `borrow` (and other health-check call sites), compute `debt-value` from the position's **full** debt list (unfiltered by the enabled bitmap, analogous to `get-full-position`), not from the enabled-filtered `get-position`. Alternatively, explicitly re-include the notional value of debt in disabled assets before evaluating `is-healthy`, mirroring the disabled-collateral re-inclusion logic already present in `collateral-remove`.

### Proof of Concept
Clarinet simnet test outline:
1. Configure oracle mocks so collateral asset returns price/decimals yielding exactly 100,000 USD notional for the borrower's held collateral amount.
2. Configure debt asset 1 price/decimals so 79,000 USD of debt-scaled balance is recorded (via `borrow`), and debt asset 2 price/decimals so 50,000 USD of debt-scaled balance is recorded (via `borrow` while asset 2 is enabled).
3. As the DAO signer (test-only setup, not attacker action), disable asset 2 in `.assets`/`.v0-assets` (turn off its debt-enabled bit) via the existing DAO-authorized registry call.
4. As the unprivileged borrower, call `borrow` for asset 1 to push visible debt from 79,000 to 80,000 USD; feed correct price-feeds. Assert the call succeeds (`is-healthy` returns true using only the 80,000/100,000 = 8000 bps check).
5. Independently sum the real debt (`market-vault` `debt` map entries for both asset 1 and asset 2) and assert real total is 130,000 USD against 100,000 USD collateral (13000 bps), contradicting the protocol's own reported 8000 bps health check from step 4. (define-private (relevant (asset uint) (enabled-mask uint) (c bool))
  (let ((position (mask-pos asset c))
        (mask (bit-or u0 (pow u2 position))))
    (subset mask enabled-mask)))

(define-private (iter-lookup-collateral
                (asset uint)
                (acc {
                    id: uint,
                    result: (list 64 { aid: uint, amount: uint}),
                    enabled-mask: uint
                }))
  (let ((mask (get enabled-mask acc))
        (relevant? (asserts! (relevant asset mask true) acc))
        (user-id (get id acc))
        (value (get-collateral user-id asset))
        (entry { aid: asset, amount: value }))
    {
      id: user-id,
      result: (unwrap-panic (as-max-len? (append (get result acc) entry) u64)),
      enabled-mask: mask
    }))

(define-private (iter-lookup-debt
                (asset uint)
                (acc {
                    id: uint,
                    result: (list 64 { aid: uint, scaled: uint}),

        (user-id (get id acc))
        (value (get-debt user-id asset)) ;; unreachable

(define-private (is-healthy (collateral-usd uint) (debt-usd uint) (ltv uint))
  (if (is-eq debt-usd u0)
      true
      (<= (* debt-usd BPS) (* collateral-usd ltv))))

;; Check health using a custom mask's egroup rules
;; Returns true if position is healthy under the specified mask's LTV requirements
(define-private (is-healthy-with-mask (collateral-usd uint) (debt-usd uint) (mask uint))
  (let ((group (try! (get-egroup mask)))
        (ltvb (buff-to-uint-be (get LTV-BORROW group))))
    (ok (is-healthy collateral-usd debt-usd ltvb))))
