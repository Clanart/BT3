### Title
Attacker-funded dust UTXOs are reported spendable and can force fee-wasting transaction signatures - ([File: `networks/bitcoin/src/wallet/mod.rs`])

### Summary
`Scanner::scan_transaction` returns every output whose `script_pubkey` belongs to the wallet, without checking that its value economically justifies spending it. `SignableTransaction::new` likewise accepts every supplied `ReceivedOutput` as an input while enforcing `DUST` only for created payments and change. An unprivileged party can therefore send low-value outputs to a watched address and cause wallet automation which spends all discovered outputs to sign transactions whose incremental input fee exceeds the donated value. [1](#0-0) [2](#0-1) 

### Finding Description
`Scanner` models every matched transaction output as a `ReceivedOutput`, explicitly described as “a spendable output,” and filters solely by `output.script_pubkey`. It does not reject zero-, dust-, or otherwise uneconomically valued UTXOs. [3](#0-2) [1](#0-0) 

Although `SignableTransaction` defines `DUST` as 546 satoshis, that bound is applied only to requested payment outputs and the optional change output, not to elements of the `inputs` vector. The constructor sums all supplied input values, converts all supplied outpoints into `TxIn`s, and computes weight from the resulting input count. [4](#0-3) [5](#0-4) [6](#0-5) 

Each additional Taproot input increases the transaction weight and therefore `needed_fee`, but the donated input contributes only its own low value. If a low-value scanned output is included together with sufficient legitimate inputs, the constructor succeeds and `multisig` creates a signing machine for every input because the scanner supplied the corresponding offset and the prevout script matches the offset group key. [7](#0-6) [8](#0-7) 

The resulting signing machine commits all prevouts with `Prevouts::All`, produces one Taproot signature per input, and installs those signatures as input witnesses. Consequently, the attacker’s unsolicited output is not merely displayed; it can reach production signing as part of a fee-paying transaction. [9](#0-8) [10](#0-9) 

### Impact Explanation
This is a wallet-level analogue of donating a negligible balance to keep an otherwise unnecessary action profitable to trigger. A transaction whose script matches the wallet is sufficient for the attacker to create a persistent `ReceivedOutput`; no validator, peer, key holder, or RPC compromise is required. [1](#0-0) 

For every forced input, the wallet pays the incremental transaction fee while receiving only the attacker-selected UTXO value. At any fee rate where that marginal fee exceeds the UTXO’s value, inclusion causes a net loss charged against legitimate inputs or change. Repeating the attack produces repeated fee-wasting signatures and can drain wallet funds over time. [7](#0-6) [11](#0-10) 

This can also cause the scanner API to report funds as `ReceivedOutput`/`value()` even when spending them would cost more than their face value at the wallet’s intended fee rate, making the reported balance economically non-spendable. [12](#0-11) [13](#0-12) 

### Likelihood Explanation
The attacker only needs the wallet’s public P2TR address or script and the ability to send an ordinary Bitcoin transaction. A standard output at or modestly above the 546-satoshi creation threshold is enough; below that threshold remains consensus-possible when mined, while the missing input-side bound means even nominally non-dust outputs can still be economically negative at the current spend fee rate. [4](#0-3) [1](#0-0) 

The exploit requires wallet logic that treats scanned outputs as candidates for consolidation or automatic spending. That is the natural consumer of an API which labels matches as spendable `ReceivedOutput`s and provides no warning or policy result distinguishing economically viable inputs from dust. [3](#0-2) [14](#0-13) 

### Recommendation
Introduce an explicit input-spendability policy rather than returning every script match indiscriminately. At minimum, `Scanner` should expose an amount-aware scan, such as `scan_transaction_with_min(tx, minimum_input_value)`, or return a classification allowing callers to distinguish economically spendable outputs from dust. [15](#0-14) 

The threshold should be based on the marginal cost of spending a Taproot input at the caller’s configured `fee_per_vbyte`, not solely on the static output-creation `DUST` constant. `SignableTransaction::new` should also reject or explicitly annotate an input whose value is below its incremental fee at the requested fee rate, unless the caller deliberately opts into negative-value consolidation. [16](#0-15) [2](#0-1) 

### Proof of Concept
The following sequence demonstrates the reachable path:

1. An attacker obtains the wallet’s P2TR script.
2. The attacker broadcasts a transaction containing an output to that script valued at `DUST` or another amount below the marginal fee required to spend it.
3. `Scanner::scan_transaction` returns that output as a `ReceivedOutput` because only the script is checked.
4. Wallet automation includes the returned output with a legitimate UTXO in `SignableTransaction::new`.
5. The constructor counts the added input in the weight/fee calculation and returns a signable transaction once the legitimate input covers the loss.
6. `multisig` and `TransactionSignMachine::sign` produce a signature for the dust input as well as the legitimate input.

Representative test-shaped code:

```rust
// Attacker-controlled funding transaction.
let attacker_tx = Transaction {
  version: Version(2),
  lock_time: LockTime::ZERO,
  input: vec![/* attacker's input */],
  output: vec![
    TxOut {
      // At a sufficiently high spend feerate, this is worth less than its
      // marginal input cost even though it is not below creation dust.
      value: Amount::from_sat(DUST),
      script_pubkey: wallet_script.clone(),
    },
  ],
};

// The wallet reports the uneconomic output as a ReceivedOutput.
let scanned = scanner.scan_transaction(&attacker_tx);
assert_eq!(scanned.len(), 1);
assert_eq!(scanned[0].value(), DUST);

// Automation combining all discovered outputs pays the marginal fee for it.
let tx = SignableTransaction::new(
  vec![legitimate_output, scanned[0].clone()],
  &[(payment_script, payment_amount)],
  Some(change_script),
  None,
  fee_per_vbyte,
)
.unwrap();

// Each input, including the attacker's uneconomic input, is signed.
let machine = tx.multisig(&threshold_keys).unwrap();
```

The key assertions are that scanning succeeds without an amount check, construction accepts the output as an input, and signing produces witnesses for every supplied input. [1](#0-0) [17](#0-16) [8](#0-7) [10](#0-9)

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
