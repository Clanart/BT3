### Title
Searcher bid nonce is included in the signed EIP-712 payload but never verified, preventing cancellation/invalidation of stale bids - (File: kaiax/auction/bid.go, kaiax/auction/impl/bid_pool.go)

### Summary
`auction.BidData` includes a `Nonce` field that is part of the EIP-712 struct hash signed by the searcher [1](#0-0) , and the corresponding on-chain entry point (mock) also defines a `nonce` field intended to be checked against a `nonces(sender)` counter [2](#0-1) . However, `BidPool.validateBid`/`validateBidSigs` in the kaiax auction module never reads or checks `bid.Nonce` against any current/expected nonce — it only validates sender/auctioneer signatures, block-number range, bid size, and data/gas limits [3](#0-2) .

### Finding Description
This is the same bug class as the Astaria "strategist nonce is not checked" issue: a signed off-chain payload contains a nonce field that is meant to let the signer invalidate/cancel a previously issued signature, but the field is never enforced by the validating component. In Astaria, `AstariaRouter.validateCommitment` never checked the strategist's nonce, so a signed commitment could be reused indefinitely and `increaseNonce` was dead code.

In this Kaia codebase, the searcher signs a `BidData` struct (via EIP-712, `GetHashTypedData`) that embeds `Nonce`, exactly mirroring the intent of a cancelable signed authorization [4](#0-3) . The Go-side `BidPool.validateBid` (called from `AddBid`, which backs the `auction_submitBid` RPC and the p2p bid-relay path via `HandleBid`) performs only:
1. duplicate/hash check,
2. sender-has-different-winner check,
3. block-number range check,
4. bid > 0 check,
5. data-size / gas-limit checks,
6. searcher and auctioneer ECDSA signature checks,

but at no point compares `bid.Nonce` to a stored/expected nonce for `bid.Sender` [3](#0-2) . There is no `IncreaseNonce`/nonce-consumption bookkeeping anywhere in `kaiax/auction` (confirmed by grep across the module — only test fixtures and the EIP-712 encoder reference `Nonce`). The on-chain mock even shows the intended check commented out: `// return auctionTx.nonce == nonces(auctionTx.sender);` [5](#0-4) .

Because the bid's uniqueness/anti-replay protection in the pool is only `bid.Hash()` (content hash) plus a per-block/target-tx overwrite rule (`bidTargetMap`, `senderHasDifferentWinner`) [6](#0-5) , a searcher has no mechanism to invalidate a bid they previously signed once it is in circulation (e.g., leaked to, or cached by, the `Auctioneer` or any relaying peer) before its target block is reached. The searcher's only actual protection is the `BlockNumber` field constraining the bid to a specific future block, but for any bid whose target block has not yet passed, the stale signature remains fully valid and acceptable to the pool — the nonce field that was clearly designed to support cancellation (mirrored in the commented-out on-chain check) is inert.

### Impact Explanation
A searcher who wants to withdraw/cancel a previously signed bid (e.g., because market conditions changed, the target transaction is no longer relevant, or the auctioneer/relaying party should no longer be able to use that authorization) cannot do so. Any entity holding that valid signed bid (the `Auctioneer`, or any peer that received it via `HandleBid`) can still get it accepted by `BidPool.AddBid` and have it executed as a winning bid in a future block within the allowed range, executing the searcher's `AuctionTx.data` call with the searcher-authorized `bid` value and `callGasLimit`. This can result in unauthorized/unwanted contract calls and fund/bid extraction on behalf of the searcher, i.e. concrete unauthorized value movement / auction settlement abuse, without any way for the affected party to invalidate the outstanding authorization.

### Likelihood Explanation
This requires no privileged access: it only requires that a validly-signed (searcher + auctioneer) bid remain circulating in the auction pipeline (submitted via `auction_submitBid` RPC or relayed via the auction p2p bid message) with a `BlockNumber` still in the acceptable future-block window. Since the nonce check is entirely absent from the validation path, exploitation is deterministic whenever a searcher's bid outlives their intent to keep it valid — no race condition or timing trick beyond normal bid-relay/latency is needed.

### Recommendation
Track and enforce a per-searcher nonce state (either on-chain via the `AuctionEntryPoint`/`nonces(sender)` mapping referenced but disabled in `AuctionEntryPointMock.sol`, or in `BidPool`'s in-memory/state read) and reject any bid whose `Nonce` does not match the currently expected value in `BidPool.validateBid`/`validateBidSigs`, mirroring the check that is already commented out in `_verifyInputIntegrity`. Additionally provide (or wire up) a mechanism for the searcher to increment their nonce (a cancellation transaction/call), analogous to the recommended `increaseNonce` fix in the original Astaria report, so that all previously signed bids with lower nonces are immediately invalidated.

### Proof of Concept
1. Searcher signs `BidData{Sender: S, Nonce: 0, BlockNumber: N+5, Bid: X, ...}` via `GetHashTypedData`/EIP-712 and sends it to the `Auctioneer`, who co-signs it with `AuctioneerSig` [7](#0-6) .
2. Before block `N+5` is reached, the searcher decides to withdraw the bid (e.g., no longer wants the trade executed) but has no on-chain or off-chain mechanism to bump their nonce, since none is checked/consumed anywhere in `bid_pool.go`.
3. The `Auctioneer` (or any peer holding the bid via `HandleBid`) submits the same bid again close to block `N+5`; `BidPool.validateBid` passes all checks (signatures valid, block-number in range, bid > 0, sizes OK) because `bid.Nonce` is never compared to anything [8](#0-7) .
4. The bid is accepted (`AddBid` succeeds), inserted into `bidTargetMap`/`bidWinnerMap`, and becomes eligible to be bundled and executed at block `N+5`, despite the searcher's intent to cancel it — demonstrating that the nonce provides no actual cancellation guarantee.

func (bp *BidPool) insertBid(bid *auction.Bid) error {
	bp.bidMu.Lock()
	defer bp.bidMu.Unlock()

	var (
		blockNumber  = bid.BlockNumber
		targetTxHash = bid.TargetTxHash
		sender       = bid.Sender
	)

	// Re-check bidWinnerMap here — two concurrent bids can pass validateBid together.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		return auction.ErrBidAlreadyExists
	}
	if bp.senderHasDifferentWinner(bid) {
		return auction.ErrBidSenderExists
	}

	// If same block number, same target tx hash exists, replace it if it's better
	if existingBid, ok := bp.bidTargetMap[blockNumber][targetTxHash]; ok {
		// FCFS if the bid is the same.
		if existingBid.Bid.Cmp(bid.Bid) >= 0 {
			return auction.ErrLowBid
		}

		logger.Trace("Replace bid", "old", existingBid.Hash(), "new", bid.Hash())
		delete(bp.bidMap, existingBid.Hash())
		delete(bp.bidWinnerMap[blockNumber], existingBid.Sender)
	} else {
		if int64(len(bp.bidMap)) >= bp.maxBidPoolSize {
			logger.Info("Bid pool is full", "maxBidPoolSize", bp.maxBidPoolSize, "bid", bid.Hash())
			return auction.ErrBidPoolFull
		}
	}

	hash := bid.Hash()

	bp.initializeBidMap(blockNumber)

	bp.bidMap[hash] = bid
	bp.bidTargetMap[blockNumber][targetTxHash] = bid
	bp.bidWinnerMap[blockNumber][sender] = hash

	numBidsGauge.Update(int64(len(bp.bidMap)))

	logger.Trace("Add bid", "bid", hash)

	return nil
}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}

func (b bidV3) EncodeData() []byte {
	maxGasPrice := b.MaxGasPrice
	if maxGasPrice == nil {
		maxGasPrice = new(big.Int)
	}
	encoded := make([]byte, 0, 10*32)
	encoded = append(encoded, b.TargetTxHash.Bytes()...)
	encoded = append(encoded, common.LeftPadBytes(common.Int64ToByteBigEndian(b.BlockNumber), 32)...)
	encoded = append(encoded, common.LeftPadBytes(b.Sender.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(b.To.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(common.Int64ToByteBigEndian(b.Nonce), 32)...)
	encoded = append(encoded, common.LeftPadBytes(b.BidData.Bid.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(maxGasPrice.Bytes(), 32)...)
	encoded = append(encoded, common.LeftPadBytes(common.Int64ToByteBigEndian(b.CallGasLimit), 32)...)
	encoded = append(encoded, crypto.Keccak256Hash(b.Data).Bytes()...)
	return encoded
}
