### Title
Reward accounting in `BaseRewardPool`/rewarders credits new depositors instantly instead of streaming, enabling flash-deposit dilution of `harvest()`-triggered WOM rewards - ([File: rewards/BaseRewardPool.sol])

### Summary
`BaseRewardPool._provisionReward()` (and its equivalents in `BaseRewardPoolV2.sol`, `mWOMSVBaseRewarder.sol`, `vlMGPBaseRewarder.sol`) credits an entire incoming reward amount to `rewardPerTokenStored` in a single lump sum, proportional to `totalStaked()` at that exact instant, with no streaming/vesting over time. Anyone can trigger a large reward injection into this accounting via the permissionless `harvest()` path (`WombatPoolHelper.harvest()` → `WombatStaking.harvest()` → `_toMasterWomAndSendReward()` → `_sendRewards()` → `IBaseRewardPool.queueNewRewards()`), and `MasterMagpie.deposit()`/`withdraw()` have no lockup or cooldown. This mirrors the reported `returnFunds()` frontrunning bug class: a bot can flash-deposit right before a (predictable, publicly observable, permissionlessly triggerable) reward injection, instantly receive a pro-rata share of `rewardPerTokenStored`, and withdraw immediately after, diluting the yield of stakers who were actually staked while the WOM rewards accrued.

### Finding Description

This immediately raises `rewardPerTokenStored` for the *current* `totalStaked()`, regardless of how long each staker has actually been staked. There is no time-weighted streaming (e.g., a `rewardRate` distributed over a duration) as in typical Synthetic-style staking rewards contracts.

`queueNewRewards()` is reachable from a fully permissionless call chain: `WombatPoolHelper.harvest()` is external with no access control, and simply forwards to `WombatStaking.harvest()`: [2](#0-1) [3](#0-2) 
which calls `_toMasterWomAndSendReward()` → `_sendRewards()`, ultimately calling `IBaseRewardPool(_rewarder).queueNewRewards(_amount, _rewardToken)`: [4](#0-3) 

Meanwhile `MasterMagpie.deposit()`/`withdraw()` are open to any wallet with no lockup: [5](#0-4) 
and `_deposit`/`_withdraw` immediately update `user.amount`/`user.available` and settle the base rewarder against current `rewardPerTokenStored`: [6](#0-5) 

Because accrued WOM rewards sitting in `MasterWombat` grow visibly over time (and `harvest()` is callable by anyone at any moment), an attacker can:
1. Monitor pending WOM rewards for a given Wombat pool.
2. Flash-deposit a large amount of the pool's receipt token into `MasterMagpie` for that `_stakingToken`.
3. Call (or piggyback on someone else calling) `harvest()`, which pushes the accumulated WOM reward into `BaseRewardPool` via `queueNewRewards()`, instantly inflating `rewardPerTokenStored` based on the now-inflated `totalStaked()` that includes the attacker's flash deposit.
4. Immediately claim/withdraw, capturing a share of rewards that accrued before the attacker ever staked — diluting genuine long-term stakers.

This is the same root cause pattern as the referenced `SafetyModule.returnFunds()` finding: a value-increasing event that is either predictable or permissionlessly triggerable, combined with unrestricted deposit/withdraw, allows risk-free extraction of value from other participants.

### Impact Explanation
Existing stakers of a Wombat pool's receipt token in `MasterMagpie` have part of their earned WOM yield diverted to the attacker's flash-staked capital, which is a theft of unclaimed yield from legitimate stakers. The size of the loss scales with the amount of WOM accrued since the last harvest and the ratio of the attacker's flash deposit to total staked supply — for pools with large accrued/harvestable rewards relative to TVL, this can be a substantial, repeatable value transfer.

### Likelihood Explanation
Likelihood is high relative to the original `returnFunds()` case, because here the "value-injection" event (`harvest()`) is *fully permissionless and can be triggered by the attacker themselves at will* rather than requiring governance action; no frontrunning race against another party's transaction is even necessary. There is no deposit fee, cooldown, or minimum staking duration to prevent immediate deposit-harvest-withdraw cycles.

### Recommendation
Stream rewards over time instead of crediting them to `rewardPerTokenStored` instantly (e.g., a `rewardRate` distributed over a fixed duration as in standard `StakingRewards`-style contracts), and/or introduce a minimum staking duration or a reward-eligibility snapshot (e.g., only stakers with a balance as of the last accrual period, or a deposit cooldown before rewards start accruing) so freshly deposited balances cannot immediately capture previously-accrued rewards.

### Proof of Concept
1. Attacker observes `MasterWombat` pending WOM rewards for pool `P` growing over several blocks.
2. Attacker calls `MasterMagpie.deposit(receiptToken_P, largeAmount)` (`rewards/MasterMagpie.sol:337`), instantly becoming a large share of `totalStaked()` in the corresponding `BaseRewardPool`.
3. Attacker (or anyone) calls `WombatPoolHelper.harvest()` (`wombat/WombatPoolHelper.sol:142`), which pushes accrued WOM into `BaseRewardPool.queueNewRewards()` (`wombat/WombatStaking.sol:769`), instantly raising `rewardPerTokenStored` per `_provisionReward` (`rewards/BaseRewardPool.sol:297-318`) based on the now-inflated `totalStaked()`.
4. Attacker immediately calls `MasterMagpie.withdraw(receiptToken_P, largeAmount)` (`rewards/MasterMagpie.sol:344`), which harvests/claims the base rewarder's reward for the account (`_harvestBaseRewarder`) before returning the principal — capturing a pro-rata share of the WOM reward that accrued before the deposit, at zero risk and with no capital exposure.

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (this.totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingDecimals()) /
                this.totalStaked();
        }

    function _sendRewards(
        address _lpToken,
        address _rewardToken,
        address _rewarder,
        uint256 _amount
    ) internal {
        if (_amount == 0) return;
        uint256 originalRewardAmount = _amount;

        if (!isPoolFeeFree[_lpToken]) {
            for (uint256 i = 0; i < feeInfos.length; i++) {
                Fees storage feeInfo = feeInfos[i];

                if (feeInfo.isActive) {
                    address rewardToken = _rewardToken;
                    uint256 feeAmount = (originalRewardAmount * feeInfo.value) / DENOMINATOR;
                    _amount -= feeAmount;
                    uint256 feeTosend = feeAmount;

                    if (feeInfo.isMWOM && rewardToken == wom) {
                        if (smartWomConverter != address(0)) {
                            IERC20(wom).safeApprove(smartWomConverter, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IConverter(smartWomConverter).smartConvert(feeAmount, 0);
                            rewardToken = mWom;
                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
                        } else {
                            IERC20(wom).safeApprove(mWom, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IMWom(mWom).deposit(feeAmount);
                            rewardToken = mWom;
                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
                        }
                    }

                    if (!feeInfo.isAddress) {
                        IERC20(rewardToken).safeApprove(feeInfo.to, 0);
                        IERC20(rewardToken).safeApprove(feeInfo.to, feeTosend);
                        IBaseRewardPool(feeInfo.to).queueNewRewards(feeTosend, rewardToken);
                    } else {
                        IERC20(rewardToken).safeTransfer(feeInfo.to, feeTosend);
                        emit RewardPaidTo(feeInfo.to, rewardToken, feeTosend);
                    }
                }
            }
        }

        IERC20(_rewardToken).safeApprove(_rewarder, 0);
        IERC20(_rewardToken).safeApprove(_rewarder, _amount);
        IBaseRewardPool(_rewarder).queueNewRewards(_amount, _rewardToken);
    }

    function _deposit(address _stakingToken, address _account, uint256 _amount, bool _isVlmgp) internal {
        updatePool(_stakingToken);

        PoolInfo storage pool = tokenToPoolInfo[_stakingToken];
        UserInfo storage user = userInfo[_stakingToken][_account];

        if (user.amount > 0) {
            _harvestMGP(_stakingToken, _account);
        }
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount + _amount;
        if (!_isVlmgp) {
            user.available = user.available + _amount;
            IERC20(pool.stakingToken).safeTransferFrom(address(msg.sender), address(this), _amount);
        }
        user.rewardDebt = (user.amount * pool.accMGPPerShare) / 1e12;

        if (_amount > 0)
            if (!_isVlmgp)
                emit Deposit(_account, _stakingToken, _amount);
            else
                emit DepositNotAvailable(_account, _stakingToken, _amount);
    }

    /// @notice internal function to deal with withdraw staking token
    function _withdraw(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        _harvestAndUnstake(_stakingToken, _account, _amount, _isVlMgp);

        if (!_isVlMgp)
            IERC20(tokenToPoolInfo[_stakingToken].stakingToken).safeTransfer(address(msg.sender), _amount);
        emit Withdraw(_account, _stakingToken, _amount);
    }

    function _harvestAndUnstake(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        updatePool(_stakingToken);

        UserInfo storage user = userInfo[_stakingToken][_account];

        if (!_isVlMgp && user.available < _amount)
            revert WithdrawAmountExceedsStaked();
        else if(user.amount < _amount && _isVlMgp)
            revert UnlockAmountExceedsLocked();
        
        _harvestMGP(_stakingToken, _account);
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount - _amount;
        
        if(!_isVlMgp)
            user.available = user.available - _amount;
        user.rewardDebt = (user.amount * tokenToPoolInfo[_stakingToken].accMGPPerShare) / 1e12;
    }
