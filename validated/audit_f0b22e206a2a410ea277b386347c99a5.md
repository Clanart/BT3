### Title
Payout OP_RETURN operator attribution is unauthenticated and can be hijacked by front-running the withdrawal UTXO spend - ([File: core/src/builder/transaction/operator_reimburse.rs -> fn create_payout_txhandler])

### Summary
The user's withdrawal authorization signature is required to use `TapSighashType::SinglePlusAnyoneCanPay` (enforced in `core/src/rpc/parser/operator.rs:174-187` and verified in `Operator::withdraw` at `core/src/operator.rs:630-637`). Under BIP-341, this sighash flag commits only to input 0 and to the single output at the same index (output 0); it never commits to output 1 (anchor) or output 2 (the `OP_RETURN` carrying `operator_xonly_pk`, added in `create_payout_txhandler` at `core/src/builder/transaction/operator_reimburse.rs:407-436`). Any party who observes the operator's payout transaction on the P2P network before confirmation can reuse the exact same valid witness for input 0 to construct a conflicting, higher-fee transaction that keeps output 0 identical but swaps output 2's `OP_RETURN` payload (or removes it), and get that transaction mined instead.

### Finding Description
The binding the protocol relies on is:
`operator_xonly_pk_recorded(withdrawal_idx) == party_that_actually_authored/funded the confirmed transaction's output 0`

`Verifier::update_finalized_payouts` (`core/src/verifier.rs:2283-2353`) determines this recorded value purely from whichever transaction is found on-chain spending the registered `withdrawal_utxo` outpoint — the lookup (`get_payout_txs_for_withdrawal_utxos`, `core/src/database/verifier.rs:170-196`) joins on `bitcoin_syncer_spent_utxos.txid/vout`, i.e. on *any* transaction that spends that specific outpoint, not on a pre-registered/committed txid. It then reads `operator_xonly_pk` straight from `get_first_op_return_output` + `parse_op_return_data` on whatever transaction won the race for that outpoint (`core/src/verifier.rs:2312-2321`).

Because the user's `SinglePlusAnyoneCanPay` signature only commits to input 0 and output 0, nothing in the signed message constrains output 2's `OP_RETURN`. An operator building the real payout via `create_payout_txhandler` funds the tx with `fund_raw_transaction`/`sign_raw_transaction_with_wallet` (`core/src/operator.rs:652-689`) and broadcasts it. Before it confirms, an attacker who has observed it in the mempool can:
1. Extract input 0's witness (a valid Schnorr signature over input0+output0 only).
2. Build a new transaction spending the same withdrawal outpoint with identical output 0, but arbitrary output 2 `OP_RETURN` bytes (a different xonly pk, garbage, or omit `OP_RETURN` entirely), funding any additional required value themselves.
3. Broadcast with a higher fee so it confirms first, evicting the original operator's transaction as a double-spend.

`update_finalized_payouts` then records the attacker-chosen (or absent) `operator_xonly_pk` for that withdrawal index, not the honest operator's key. `Verifier::is_kickoff_malicious` (`core/src/verifier.rs:1857-1915`) compares `kickoff_data.operator_xonly_pk` against this DB-recorded value; a mismatch is treated as malicious.

Existing guards do not prevent this: `Operator::withdraw`'s `SECP.verify_schnorr` only checks the sighash-scoped message (input0+output0), `is_kickoff_malicious` only detects the *symptom* (mismatch) after the fact, and `get_payout_txs_for_withdrawal_utxos` has no notion of "the transaction the operator originally signed/broadcast" — it accepts whatever confirms first for that outpoint.

### Impact Explanation
The practical consequences differ from the exact chain hypothesized in the question and must be stated precisely:
- If the attacker nulls/garbles the `OP_RETURN`, the withdrawal gets permanently recorded with no operator credit. The honest operator's own broadcast transaction never confirms (it is double-spent), so the honest operator's `PayoutCheckerTask` (`core/src/task/payout_checker.rs`, driven by `get_first_unhandled_payout_by_operator_xonly_pk`) will never find this withdrawal as its own and will not automatically send a Kickoff for it — automatic collateral burn via `is_kickoff_malicious` is therefore not triggered by the automated flow. The direct, confirmed harm here is that the withdrawal becomes an orphaned/unattributed payout that no operator can claim: an "honest operator permanently unable to be reimbursed" for the deposit it prepared to service.
- If instead the attacker funds output 0 from their own capital and sets the `OP_RETURN` to an arbitrary third-party operator's real xonly pk, that named operator's automation (`get_first_unhandled_payout_by_operator_xonly_pk` matching its own key) will treat it as its own completed payout and proceed to `handle_finalized_payout`/Kickoff, ultimately being reimbursed for a payout it never funded — matching the "operator reimbursed for a payout it never funded" Critical category.
- The scenario where the honest operator's own collateral gets burned via Challenge/Disprove requires that operator to still submit a Kickoff for a withdrawal the DB does not credit to it; the automated task path does not do this, so that specific final step is not proven reachable purely from this bug without an additional (non-automated) operator misstep.

This is repeatable across any withdrawal for which an operator's payout transaction can be observed unconfirmed in the mempool, and across any operator/deposit, since the root cause (unauthenticated `OP_RETURN` under `SinglePlusAnyoneCanPay`) is structural, not deposit-specific.

### Likelihood Explanation
Any unprivileged network participant who can observe the Bitcoin mempool (trivial) and outbid the operator's fee rate can perform this attack; no privileged role, key material, or majority hashrate is required. The attacker must fund output 0 fully from their own capital if they want a "credit theft" outcome (real BTC cost equal to the withdrawal amount), which limits pure griefing profitability but not feasibility for a targeted attack against a specific operator (either to deny it reimbursement or to gift reimbursement to a rival/colluding operator). Detecting and front-running an unconfirmed payout transaction with a higher-fee replacement is standard, low-cost Bitcoin mempool behavior.

### Recommendation
Bind the `OP_RETURN` operator-attribution output (and ideally all outputs) to the user's authorization signature, e.g. by requiring `SIGHASH_ALL` (or `SIGHASH_ALL|ANYONECANPAY`) for the withdrawal input so all outputs — including the `operator_xonly_pk` `OP_RETURN` — are committed to by the same signature the user produced, or by having verifiers additionally validate that the confirmed payout transaction is byte-identical/structurally consistent with what the specific claiming operator originally constructed and broadcast (e.g., via a committed txid rather than accepting any spender of the outpoint).

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

#[allow(clippy::result_large_err)]
pub fn parse_withdrawal_sig_params(
    params: WithdrawParams,
) -> Result<(u32, taproot::Signature, OutPoint, ScriptBuf, Amount), Status> {
    let mut input_signature =
        taproot::Signature::from_slice(&params.input_signature).map_err(|e| {
            Status::invalid_argument(format!("Can't convert input to taproot Signature - {e}"))
        })?;

    // If the Taproot sighash type is Default (no explicit type attached; i.e. a 64-byte
    // signature without a sighash flag), normalize it to SinglePlusAnyoneCanPay.
    // Prior to v0.5 this was Clementine's implicit behavior; we retain it here for
    // backwards compatibility when a 64-byte signature is provided.
    if input_signature.sighash_type == TapSighashType::Default {
        tracing::warn!(
            "Input signature for withdrawal {} has sighash type default, setting to SinglePlusAnyoneCanPay", params.withdrawal_id,
        );
        input_signature.sighash_type = TapSighashType::SinglePlusAnyoneCanPay;
    }

    // enforce sighash type here
    if input_signature.sighash_type != TapSighashType::SinglePlusAnyoneCanPay {
        return Err(Status::invalid_argument(format!(
            "Input signature has wrong sighash type, SinglePlusAnyoneCanPay expected, got {}",
            input_signature.sighash_type
        )));
    }

    /// Checks if the operator who sent the kickoff matches the payout data saved in our db
    /// Payout data in db is updated during citrea sync.
    async fn is_kickoff_malicious(
        &self,
        kickoff_witness: Witness,
        deposit_data: &mut DepositData,
        kickoff_data: KickoffData,
        dbtx: DatabaseTransaction<'_>,
    ) -> Result<bool, BridgeError> {
        let move_txid =
            create_move_to_vault_txhandler(deposit_data, self.config.protocol_paramset())?
                .get_cached_tx()
                .compute_txid();

        let payout_info = self
            .db
            .get_payout_info_from_move_txid(Some(dbtx), move_txid)
            .await?;
        let Some((operator_xonly_pk_opt, payout_blockhash, _, _)) = payout_info else {
            tracing::warn!(
                "No payout info found in db for move txid {move_txid}, assuming malicious"
            );
            return Ok(true);
        };

        let Some(operator_xonly_pk) = operator_xonly_pk_opt else {
            tracing::warn!("No operator xonly pk found in payout tx OP_RETURN, assuming malicious");
            return Ok(true);
        };

        if operator_xonly_pk != kickoff_data.operator_xonly_pk {
            tracing::warn!("Operator xonly pk for the payout does not match with the kickoff_data");
            return Ok(true);
        }

        let wt_derive_path = WinternitzDerivationPath::Kickoff(
            kickoff_data.round_idx,
            kickoff_data.kickoff_idx,
            self.config.protocol_paramset(),
        );
        let commits = extract_winternitz_commits(
            kickoff_witness,
            &[wt_derive_path],
            self.config.protocol_paramset(),
        )?;
        let blockhash_data = commits.first();
        // only last 20 bytes of the blockhash is committed
        let truncated_blockhash = &payout_blockhash[12..];
        if let Some(committed_blockhash) = blockhash_data {
            if committed_blockhash != truncated_blockhash {
                tracing::warn!("Payout blockhash does not match committed hash: committed: {:?}, truncated payout blockhash: {:?}",
                        blockhash_data, truncated_blockhash);
                return Ok(true);
            }
        } else {
            return Err(eyre::eyre!("Couldn't retrieve committed data from witness").into());
        }
        Ok(false)
    }

    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
            ));
        }

        self.db
            .update_payout_txs_and_payer_operator_xonly_pk(
                Some(dbtx),
                payout_txs_and_payer_operator_idx,
            )
            .await?;

        Ok(())
    }

    /// Returns the withdrawal indexes and their spending txid for the given
    /// block id.
    pub async fn get_payout_txs_for_withdrawal_utxos(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        block_id: u32,
    ) -> Result<Vec<(u32, Txid)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, TxidDB)>(
            "SELECT w.idx, bsu.spending_txid
             FROM withdrawals w
             JOIN bitcoin_syncer_spent_utxos bsu
                ON bsu.txid = w.withdrawal_utxo_txid
                AND bsu.vout = w.withdrawal_utxo_vout
             WHERE bsu.block_id = $1",
        )
        .bind(i32::try_from(block_id).wrap_err("Failed to convert block id to i32")?);

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_all)?;

        results
            .into_iter()
            .map(|(idx, txid)| {
                Ok((
                    u32::try_from(idx).wrap_err("Failed to convert withdrawal index to u32")?,
                    txid.0,
                ))
            })
            .collect()
    }
