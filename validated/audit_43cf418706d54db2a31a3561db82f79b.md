### Title
Payout attribution derived from unauthenticated `OP_RETURN` data lets any party reassign reimbursement credit for a withdrawal - (File: core/src/verifier.rs)

### Summary
The bridge determines *which operator gets reimbursed* for a Bitcoin withdrawal by reading an `OP_RETURN` output on the confirmed payout transaction and extracting an x-only public key from it, with no check that this key belongs to a real operator, no check that this key's owner actually signed or funded the transaction, and no cryptographic binding between the withdrawal's user-signed input and that `OP_RETURN` output. This mirrors the referenced `witch.sol` "second grab" class of bug: a critical custody-attribution mapping (`vaultOwners[vaultId]` there, `withdrawals.payout_payer_operator_xonly_pk` here) can be set/overwritten by an operation that does not verify the party being recorded is actually entitled to that record, breaking the equality "operator credited == operator who actually fronted the withdrawal."

### Finding Description
The payout attribution flow works as follows:

1. When a verifier processes a finalized block, `update_finalized_payouts` locates the transaction that spends a tracked withdrawal UTXO, looks for the first `OP_RETURN` output in it, and parses an x-only public key straight out of the script data — with no membership check against the deposit's registered operator set: [1](#0-0) 

2. That unauthenticated key is persisted as `payout_payer_operator_xonly_pk` for the withdrawal via an unconditional `UPDATE ... SET ... WHERE w.idx = c.idx` (no ownership or prior-value check, no idempotency guard tying the value to the actual signer of the transaction): [2](#0-1) 

3. The user's authorization for the withdrawal only covers the withdrawal input and its designated output — the operator confirms this by verifying a Schnorr signature and constructing the payout transaction, which is then funded with *additional* wallet inputs via RBF, i.e. the committed signature does not bind the whole transaction (its other inputs/outputs, including whichever `OP_RETURN` ends up in the final broadcast tx) to a specific operator: [3](#0-2) 

4. This attributed value is later trusted unconditionally when an operator tries to claim reimbursement — `validate_payer_is_operator` simply compares the stored key to its own key and proceeds if they match, with no additional proof that this operator's funds paid for the withdrawal: [4](#0-3) 

5. The automated `PayoutCheckerTask` polls for "first unhandled payout" rows keyed purely by this stored `payout_payer_operator_xonly_pk` and, once found, automatically drives the full reimbursement machinery (`handle_finalized_payout`, ending the round, and eventually spending the `Reimburse`/`ReimburseInKickoff` connector) for whichever operator key happens to be recorded — regardless of who actually paid: [5](#0-4) 

Because the identity used for the custody-binding "who paid this withdrawal" comes from an unauthenticated `OP_RETURN` byte string rather than from a signature or on-chain proof of funding, any party who can observe (or race to replace) the payout transaction before it confirms can stamp an arbitrary registered operator's x-only public key into the `OP_RETURN`, causing that operator to be credited/reimbursed for a withdrawal it never funded — or causing the operator who actually did fund it to never be credited at all (their `OP_RETURN` gets replaced, or no valid key is present).

### Impact Explanation
This breaks the equality "the operator credited versus the party that paid," one of the explicitly protected bindings. Concretely:
- An operator can be automatically driven through `handle_finalized_payout` and the full reimbursement/collateral-release flow for a payout it never funded ("an operator reimbursed for a payout it never funded" — Critical).
- The operator that genuinely fronted the withdrawal, if their `OP_RETURN` gets front-run/replaced or is malformed by a third party, can become permanently unable to claim reimbursement for that payout ("an honest operator permanently unable to be reimbursed" — Critical).

### Likelihood Explanation
The withdrawal input is signed with a sighash mode (`SinglePlusAnyoneCanPay`) that only commits to the withdrawal input and its output, not to the rest of the transaction; the funding inputs and `OP_RETURN` byte string are added afterward via RBF/`fund_raw_transaction`. Any party observing the payout transaction in the mempool (or the user's signature, which is passed over the wire pre-broadcast) can construct a rival transaction spending the same signed input with a different `OP_RETURN` payload, without needing any privileged role, key compromise, or verifier/operator collusion — this is reachable by an ordinary unprivileged actor with a Bitcoin node.

### Recommendation
Do not derive payout attribution from unauthenticated transaction data. Instead:
- Require the operator's identity to be cryptographically bound to the payout transaction (e.g., have the operator sign a commitment that is verified against the actual broadcasting/funding key, or check that a registered operator's watched wallet actually supplied the funding UTXOs).
- Validate that the extracted `OP_RETURN` public key belongs to a currently registered operator before persisting `payout_payer_operator_xonly_pk`.
- Consider making the attribution immutable/idempotent once set (analogous to the recommended fix for the `witch.sol` bug of preserving the original owner instead of blindly overwriting), and reject updates that would change an already-recorded payer for a given withdrawal idx.

### Proof of Concept
1. Operator A observes a pending Citrea withdrawal, builds and signs a valid payout transaction (`create_payout_txhandler`) using the user's `SinglePlusAnyoneCanPay` signature over the withdrawal input/output, funds it with its own wallet UTXOs, and broadcasts it, embedding its own x-only public key in the `OP_RETURN` output as in [3](#0-2) .
2. Before Operator A's transaction confirms, an unprivileged attacker (or a competing Operator B) observes it in the mempool, extracts the same user-signed input (its signature only commits to that input/output), and constructs a replacement transaction that funds the identical withdrawal output but swaps the `OP_RETURN` to embed Operator B's x-only public key, then relays it with a higher fee.
3. Operator B's replacement confirms first. `update_finalized_payouts` parses Operator B's key from the `OP_RETURN` with no ownership check [1](#0-0)  and unconditionally records it via `update_payout_txs_and_payer_operator_xonly_pk` [2](#0-1) .
4. `PayoutCheckerTask` for Operator B sees an "unhandled payout" attributed to itself [5](#0-4)  and automatically drives `handle_finalized_payout`, eventually letting Operator B claim the `Reimburse`/`ReimburseInKickoff` connector — even though Operator A actually funded the withdrawal payment and never gets credited.

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

    pub async fn withdraw(
        &self,
        withdrawal_index: u32,
        in_signature: taproot::Signature,
        in_outpoint: OutPoint,
        out_script_pubkey: ScriptBuf,
        out_amount: Amount,

        tracing::info!(
            "Withdrawing with index: {}, in_signature: {:?}, in_outpoint: {:?}, out_script_pubkey: {}, out_amount: {}",
            withdrawal_index,
            in_signature,
            in_outpoint,
            out_script_pubkey,
            out_amount
        );

        // Prepare input and output of the payout transaction.
        let input_prevout = self.rpc.get_txout_from_outpoint(&in_outpoint).await?;
        let input_utxo = UTXO {
            outpoint: in_outpoint,
            txout: input_prevout,
        };
        let output_txout = TxOut {
            value: out_amount,
            script_pubkey: out_script_pubkey,
        };

        // Check Citrea for the withdrawal state.
        let withdrawal_utxo = self
            .db
            .get_withdrawal_utxo_from_citrea_withdrawal(None, withdrawal_index)
            .await?;

        if withdrawal_utxo != input_utxo.outpoint {
            return Err(eyre::eyre!("Input UTXO does not match withdrawal UTXO from Citrea: Input Outpoint: {0}, Withdrawal Outpoint (from Citrea): {1}", input_utxo.outpoint, withdrawal_utxo).into());
        }

        let operator_withdrawal_fee_sats =
            self.config
                .operator_withdrawal_fee_sats
                .ok_or(BridgeError::ConfigError(
                    "Operator withdrawal fee sats is not specified in configuration file"
                        .to_string(),
                ))?;
        if !Self::is_profitable(
            input_utxo.txout.value,
            output_txout.value,
            self.config.protocol_paramset().bridge_amount,
            operator_withdrawal_fee_sats,
        ) {
            return Err(eyre::eyre!("Not enough fee for operator").into());
        }

        let user_xonly_pk = &input_utxo
            .txout
            .script_pubkey
            .try_get_taproot_pk()
            .wrap_err("Input utxo script pubkey is not a valid taproot script")?;

        let payout_txhandler = builder::transaction::create_payout_txhandler(
            input_utxo,
            output_txout,
            self.signer.xonly_public_key,
            in_signature,
            self.config.protocol_paramset().network,
        )?;

        // tracing::info!("Payout txhandler: {:?}", hex::encode(bitcoin::consensus::serialize(&payout_txhandler.get_cached_tx())));

        let sighash = payout_txhandler.calculate_sighash_txin(0, in_signature.sighash_type)?;

        SECP.verify_schnorr(
            &in_signature.signature,
            &Message::from_digest(*sighash.as_byte_array()),
            user_xonly_pk,
        )
        .wrap_err("Failed to verify signature received from user for payout txin. Ensure the signature uses SinglePlusAnyoneCanPay sighash type.")?;

    /// For a deposit_id checks that the payer for that deposit is the operator, and the payout blockhash and kickoff txid are set.
    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

    async fn run_once(&mut self) -> Result<Self::Output, BridgeError> {
        let mut dbtx = self.db.begin_transaction().await?;
        let unhandled_payout = self
            .db
            .get_first_unhandled_payout_by_operator_xonly_pk(
                Some(&mut dbtx),
                self.operator.signer.xonly_public_key,
            )
            .await?;

        if unhandled_payout.is_none() {
            return Ok(false);
        }

        let (citrea_idx, move_to_vault_txid, payout_tx_blockhash) =
            unhandled_payout.expect("Must be Some");

        tracing::info!(
            "Unhandled payout found for withdrawal {}, move_txid: {}",
            citrea_idx,
            move_to_vault_txid
        );

        let deposit_data = self
            .db
            .get_deposit_data_with_move_tx(Some(&mut dbtx), move_to_vault_txid)
            .await?;
        if deposit_data.is_none() {
            return Err(eyre::eyre!("Fronted withdrawal for move tx {move_to_vault_txid} found, but the signatures for the deposit are not found in the db.").into());
        }

        let deposit_data = deposit_data.expect("Must be Some");

        let kickoff_txid = self
            .operator
            .handle_finalized_payout(
                &mut dbtx,
                deposit_data.get_deposit_outpoint(),
                payout_tx_blockhash,
            )
            .await?;

        // fetch and save the LCP for if we get challenged and need to provide proof of payout later
        let (_, payout_block_height) = self
            .operator
            .db
            .get_block_info_from_hash(Some(&mut dbtx), payout_tx_blockhash)
            .await?
            .ok_or_eyre("Couldn't find payout blockhash in bitcoin sync")?;

        let _ = self
            .operator
            .citrea_client
            .fetch_validate_and_store_lcp(
                payout_block_height as u64,
                citrea_idx,
                &self.operator.db,
                Some(&mut dbtx),
                self.operator.config.protocol_paramset(),
            )
            .await?;

        #[cfg(feature = "automation")]
        self.operator.end_round(&mut dbtx).await?;

        self.db
            .mark_payout_handled(Some(&mut dbtx), citrea_idx, kickoff_txid)
            .await?;
