## Title
Subdomain-suffix confusion bypass in `githubAssetVideoRegex` allows attacker-controlled URLs to be embedded as `<video>` sources - (File: `app/src/lib/markdown-filters/video-url-regex.ts`)

### Summary
The regex used to validate that a link is a genuine GitHub user-asset CDN video URL fails to anchor the match after the domain name, so any string that merely *starts with* the literal `https://user-images.githubusercontent.com` prefix passes validation — even if a hostname suffix like `.attacker.io` is appended immediately after `.com`.

### Finding Description
`githubAssetVideoRegex` is built as: [1](#0-0) 

which compiles to `^https://user\-images\.githubusercontent\.com.+(mp4|webm|...)$` (case-insensitive). There is no boundary assertion (e.g. `/` or `$`) immediately after the escaped `.com` literal, so the `.+` wildcard is free to consume additional host-label characters such as `.attacker.io` before the path. Consequently a URL such as:

```
https://user-images.githubusercontent.com.attacker.io/1.mp4
```

satisfies `^https://user-images\.githubusercontent\.com` (as a literal prefix) followed by `.+` matching `.attacker.io/1` and the trailing `mp4` extension — so `githubAssetVideoRegex.test()` returns `true`.

This value is used directly as the trust gate in `VideoLinkFilter.getGithubVideoLink()`: [2](#0-1) 

and once accepted, the anchor's `href` is used verbatim as the `src` of a newly created `<video>` element with no further validation: [3](#0-2) 

This filter runs inside `SandboxedMarkdown.applyFilters()`, on markdown rendered from PR bodies/comments, commit descriptions, etc.: [4](#0-3) 

### Impact Explanation
The intended invariant — "only links whose host is exactly `user-images.githubusercontent.com` become `<video src>` elements" — is broken. An attacker who controls markdown content (a PR description, PR comment, commit message, review body, etc. rendered via `SandboxedMarkdown`) can craft a link like `https://user-images.githubusercontent.com.attacker.io/1.mp4` that is auto-linked by `marked`/GFM autolinking and then converted into a real `<video>` element pointing at attacker-controlled infrastructure. The sandboxed iframe is rendered with `sandbox="allow-same-origin"` only (no `allow-scripts`) so this is not an XSS/script-execution primitive, but it does allow:
- Network beaconing / IP and client fingerprinting when the victim's iframe fetches the attacker-hosted media resource.
- Display of arbitrary attacker-controlled video content presented within GitHub Desktop's UI as if it were a legitimate GitHub asset, which could be used for social engineering (e.g., misleading/deceptive video content) within an otherwise trusted-looking rendering surface. [5](#0-4) 

### Likelihood Explanation
Likelihood is high in terms of exploitability of the regex itself (trivial to construct such a URL and it is entirely attacker-controlled content, e.g. a PR/commit description), but the resulting impact is bounded because the iframe sandbox lacks `allow-scripts`, and the primitive is limited to loading arbitrary passive/media content plus a leaked network request — not code execution or credential exfiltration.

### Recommendation
Anchor the regex so the domain must be followed by a path separator or end-of-string, e.g.:
```ts
new RegExp('^' + escapeRegExp(user_images_cdn_url) + '(/|$).+' + videoExtensionRegex.source, 'i')
```
or, more robustly, parse the URL with the `URL` API and strictly compare `url.hostname === 'user-images.githubusercontent.com'` (and `url.protocol === 'https:'`) instead of relying on prefix-matching regex against the full href string.

### Proof of Concept
```js
const { githubAssetVideoRegex } = require('./video-url-regex')
console.log(githubAssetVideoRegex.test('https://user-images.githubusercontent.com.attacker.io/1.mp4'))
// -> true (should be false)
```
Embedding this as a markdown autolink in a PR/commit description (`https://user-images.githubusercontent.com.attacker.io/1.mp4`) causes `VideoLinkFilter` to rewrite the paragraph into `<video src="https://user-images.githubusercontent.com.attacker.io/1.mp4">` inside the sandboxed markdown iframe.

  private getGithubVideoLink(node: Node): string | null {
    if (
      isElement(node, 'p') &&
      node.childElementCount === 1 &&
      node.firstChild &&
      isElement(node.firstChild, 'a') &&
      githubAssetVideoRegex.test(node.firstChild.href)
    ) {
      return node.firstChild.href
    }

    return null
  }

  private async applyFilters(doc: Document) {
    const { emoji, repository, markdownContext } = this.props
    const filters = buildCustomMarkDownNodeFilterPipe({
      emoji,
      repository,
      markdownContext,
    })

    for (const nodeFilter of filters) {
      let docMutated = false
      const walker = nodeFilter.createFilterTreeWalker(doc)

      let node = walker.nextNode()
      while (node !== null) {
        const replacementNodes = await nodeFilter.filter(node)

        if (this.currentDocument !== doc) {
          // Abort, the document has changed
          return
        }

        const currentNode = node
        node = walker.nextNode()

        if (replacementNodes === null) {
          continue
        }

        docMutated = true

        for (const replacementNode of replacementNodes) {
          currentNode.parentNode?.insertBefore(replacementNode, currentNode)
        }
        currentNode.parentNode?.removeChild(currentNode)
      }

      if (docMutated) {
        this.refreshHeight()
      }
    }
  }
