### Title
Deserialized `ReceivedOutput` accepts an offset inconsistent with its script_pubkey, crediting funds no key can spend - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput::read` deserializes a spendable-output record — a scalar `offset`, a `TxOut`, and an `OutPoint` — from untrusted bytes without checking that the claimed `offset` actually derives the output's `script_pubkey` from the vault key. This is the same class as the reference bug: the vault credits a declared amount/position that does not correspond to assets actually receivable/spendable under its key.

### Finding Description
`Scanner::scan_transaction` produces `ReceivedOutput`s where `offset` is guaranteed consistent with `output.script_pubkey` because it is looked up in `self.scripts`, a map keyed by `p2tr_script_buf(key + offset*G)` [1](#0-0) . However, `ReceivedOutput::read` reconstructs the struct directly from a byte stream — `Secp256k1::read_F` for the offset, then `TxOut` and `OutPoint` via `consensus_decode` — with no such consistency check [2](#0-1) .

The accounting that consumes this record trusts the pair. `Output::key()` recovers the credited key as `read_G(script_key) - offset*G` [3](#0-2) , and `balance()` reports `self.output.value()` [4](#0-3) . With a forged/attacker-influenced `ReceivedOutput`, either (a) the `offset` does not correspond to the `script_pubkey`, so `key()` returns a point that is not the real controlling key — the output is credited to the wrong/no key and is unspendable despite being counted — or (b) the `outpoint` references an on-chain output that does not pay to the claimed script, so a `SignableTransaction` built over it signs an input the network will reject.

### Impact Explanation
Analogous to fee-on-transfer crediting: the system books a balance (`balance()` = claimed `TxOut.value`) that is not backed by spendable coins. A `ReceivedOutput` whose offset/script are inconsistent is reported as received funds under a key that cannot spend it, or an outpoint is credited that the vault never actually received. The result is stuck funds, failed spends, and misattributed balances — the same "vault balance < recorded balance" loss-of-assets shape as the reference finding. Severity Medium: integrity of received-funds accounting is broken, but only where untrusted `ReceivedOutput` bytes are accepted.

### Likelihood Explanation
`ReceivedOutput::read` is an explicit untrusted-bytes sink, reachable whenever serialized outputs cross a trust boundary (DB reloads, inter-process/network messages). No secret material or validator collusion is needed — only control over the byte stream. The defect is deterministic: the constructor performs zero binding between `offset` and `script_pubkey`.

### Recommendation
After decoding in `ReceivedOutput::read` (or at the point of use), recompute `p2tr_script_buf(group_key + GENERATOR * offset)` and require equality with `output.script_pubkey`, analogous to measuring `balanceAfter - balanceBefore` rather than trusting a declared amount. Alternatively, store only the `offset` and re-derive/verify the script via `Scanner` on deserialization.

### Proof of Concept
1. Take any valid serialized `ReceivedOutput` for key `K` (offset `o`, P2TR script `S = p2tr(K + oG)`).
2. Mutate the `TxOut.script_pubkey` bytes to an attacker-chosen P2TR script `S'`, keep `o` and `outpoint` unchanged.
3. `ReceivedOutput::read` succeeds (line 122–134 performs no consistency check).
4. `Output::key()` now returns `read_G(S'_key) - oG ≠ K`; `balance()` still reports the full value. The output is counted as received while no registered offset/key can spend it — funds reported received that are not spendable.

  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
