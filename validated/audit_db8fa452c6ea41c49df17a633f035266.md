## Title
Owner of `GaslessSwapRouter` can front-run pending gasless swaps by raising `commissionRate`, siphoning value from gasless users - (File: `contracts/bindings/kip247/GaslessSwapRouter.go`)

### Summary
`GaslessSwapRouter` (KIP-247 gasless swap contract) exposes an owner-only `updateCommissionRate` function that changes the commission taken out of every `swapForGas` execution with immediate effect and no timelock. Because gasless swap transactions are validated against the *current* commission rate only at tx-pool admission time, and the actual commission deduction happens later at block-inclusion time, the router owner can submit an `updateCommissionRate` transaction ahead of a pending user's `swapForGas`/lend bundle to increase the cut taken from the user's swap output, exactly analogous to the TITLES `EDITION_MANAGER_ROLE` royalty front-running issue.

### Finding Description
The gasless flow works as follows: a user submits `GaslessApproveTx`/`GaslessSwapTx`; the block proposer prepends a `LendTx` that fronts the user's gas fee, and the bundle `[LendTx, ApproveTx, SwapTx]` is executed atomically [1](#0-0) . Before admission, the tx-pool validates the swap using `checkBalanceForSwap`, which only checks `tx.minAmountOut >= tx.amountRepay` and `tx.amountIn >= gsr.getAmountIn(minAmountOut)` against the router's *current* on-chain state [2](#0-1) . `VerifyExecutable`'s only check tying the repay amount to anything is `SP4`, which validates `amountRepay` purely against gas-fee math (`repayAmount`), independent of the commission rate [3](#0-2) [4](#0-3) .

The actual commission deduction happens inside `GaslessSwapRouter.swapForGas` on-chain, at whatever `commissionRate` is set at execution time, and is emitted as `SwappedForGas(proposer, amountRepaid, user, finalUserAmount, commission)` — i.e., `finalUserAmount` is the amount returned to the user *after* subtracting `commission` [5](#0-4) . The `commissionRate` itself is mutated via the owner-only, immediate-effect `updateCommissionRate` function [6](#0-5) , with no delay or epoch-based activation (unlike Kaia's header-governance parameters, which only take effect at the next epoch boundary) [7](#0-6) .

Because nothing in the tx-pool admission logic (`checkBalanceForSwap`) or on-chain execution re-validates the commission rate that was assumed when the user's `minAmountOut`/`amountIn` were chosen, the owner can submit a plain `updateCommissionRate` transaction that gets included in the same or an earlier block than the victim's gasless swap bundle, unilaterally increasing the cut taken from `finalUserAmount` without the swap ever failing the `minAmountOut` DEX-level check (that check targets the raw swap output from the DEX, not the user's post-commission proceeds).

### Impact Explanation
An unprivileged gasless-swap user (a normal RPC caller relying on KIP-247 gasless transactions) can have more of their swapped-token proceeds redirected to the router owner than they agreed to when signing/broadcasting their transaction, without any on-chain protection catching this discrepancy. This is a direct value-extraction/fee-abuse vector reachable purely by a public transaction (`updateCommissionRate`) racing an ordinary user's public transaction (`swapForGas`), matching the accepted Sherlock M-12 pattern where a role empowered to change a fee-like parameter can front-run victims for profit.

### Likelihood Explanation
The `updateCommissionRate` call is a simple, cheap transaction that can be broadcast at any time and takes effect immediately upon inclusion, with no queued/epoch-delayed activation like Kaia's governance parameters. Any party controlling the router's owner key (which, per the KIP-247 gasless design, need not be as trusted/decentralized as core validator governance) can opportunistically front-run high-value pending gasless swaps observed in the mempool.

### Recommendation
- Require gasless swap validation (`checkBalanceForSwap`/`VerifyExecutable`) to pin the commission rate used to compute `minAmountOut`, and have `swapForGas` revert if the on-chain commission rate at execution differs from what the caller expected (e.g., pass an expected `commissionRate`/`maxCommission` parameter and enforce it on-chain).
- Alternatively, apply a timelock/epoch-delay to `updateCommissionRate` changes, mirroring the delayed-activation pattern already used for Kaia governance parameters, so pending transactions cannot be retroactively affected by a same-block rate change.

### Proof of Concept
1. Alice broadcasts a `GaslessApproveTx` + `GaslessSwapTx` bundle to swap Token X for KAIA to repay her lent gas, computing `minAmountOut`/`amountIn` off the router's current `commissionRate` (e.g., 1%).
2. Before Alice's bundle is included, the router owner broadcasts `updateCommissionRate(newRate)` raising the rate to, e.g., 50%. This transaction is ordinary, unprivileged-reachable, and takes effect immediately once mined [8](#0-7) .
3. The proposer includes `[LendTx, ApproveTx, SwapTx]` after the rate change (or in the same block via bundle ordering). `swapForGas` executes, and pays out `finalUserAmount = swapOutput - commission` at the new, higher commission — the DEX-level `minAmountOut` check still passes because it doesn't account for `commission`, so the transaction does not revert [5](#0-4) .
4. Alice receives materially less than she expected when she signed and broadcast her swap, with no recourse, matching the front-run/fee-abuse pattern of the referenced report.

	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

		// tx.amountIn >= gsr.getAmountIn(minAmountOut)

			return err
		}

		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
