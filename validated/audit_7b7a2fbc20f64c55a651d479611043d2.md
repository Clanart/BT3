### Title
Persistent Pyth confidence-interval gate can indefinitely block liquidations during volatility, risking protocol insolvency - (File: mainnet/contracts/market/v0-4-market.clar)

### Summary
`liquidate` resolves prices for every collateral/debt asset in a user's position via `get-assets` → `price-multi-resolve` → `price-resolve` → `resolve-pyth` → `check-confidence`. If the Pyth confidence interval for any single relevant asset exceeds `max-confidence-ratio` (default 10% of price), `check-confidence` reverts with `ERR-PRICE-CONFIDENCE-LOW`, and because it is `unwrap!`'d/`try!`'d, the failure aborts the entire `liquidate` call — not just for that asset, but for the whole transaction.

### Finding Description
`check-confidence` is a hard on-chain gate:
```
(define-private (check-confidence (price int) (confidence uint))
  (ok (asserts! (<= confidence (/ (* (to-uint price) (var-get max-confidence-ratio)) BPS)) ERR-PRICE-CONFIDENCE-LOW)))
``` [5](#0-4) 

It is invoked unconditionally inside `resolve-pyth`, used for every price lookup: [6](#0-5) 

`price-resolve` propagates any failure via `try!`, and `iter-price-multi`/`price-multi-resolve` propagate it further, so a single asset's confidence failure aborts the batch resolution used by `get-assets`: [7](#0-6) 

`liquidate` calls `get-assets` (via `price-multi-resolve`) unconditionally before it can compute `current-ltv` or perform the health check, so this failure blocks the liquidation entirely rather than only excluding the problematic asset or falling back to a stale-but-valid last-known price: [4](#0-3) 

This mirrors the OpenLeverage M-05 pattern: a flash-loan/manipulation-avoidance price sanity check (max confidence ratio, analogous to `maxLiquidationPriceDiffientRatio`) hard-reverts the liquidation path rather than gracefully falling back to determining position health, so as long as the condition triggers (Pyth confidence widening in fast/volatile markets, which routinely happens during sharp drawdowns), liquidation of an under-collateralized position cannot proceed.

### Impact Explanation
During a rapid market crash, Pyth's published confidence interval for the affected asset(s) widens (this is normal exchange/oracle behavior in volatile conditions, not third-party bad data — the vulnerability is that the protocol's own code turns this into an unconditional liquidation-blocking revert rather than a softer fallback). While `check-confidence` is triggered, `liquidate` cannot execute for any position holding that asset as collateral or debt. If the price continues moving against under-collateralized positions while confidence remains elevated, bad debt accrues and the protocol can become insolvent — this is Critical: protocol insolvency, the same root cause class the external report flags for OpenLeverage.

### Likelihood Explanation
`max-confidence-ratio` defaults to 10% (`u1000` of `BPS`) and is DAO-adjustable but not designed to auto-relax during stress. Sharp, fast-moving markets commonly cause Pyth publishers' confidence intervals to widen beyond typical single-digit-percent bands, so this condition is plausible during exactly the high-volatility events that make timely liquidation most critical. Unlike the same-block borrow/liquidate check (a single-block guard that resolves itself the next block), the confidence gate can persist across many blocks for as long as market volatility elevates the reported confidence, so it is not a bounded, self-resolving guard.

### Recommendation
Do not let a high-confidence-interval reading on one asset hard-revert the entire liquidation transaction. Options: (1) use the confidence-adjusted (e.g., lower-bound/upper-bound) price to conservatively determine health/liquidatability instead of reverting; (2) fall back to the last valid cached price (subject to its own staleness bound) when confidence is temporarily elevated, rather than blocking liquidation outright; (3) exclude only the specific asset whose confidence check fails from valuation (treating it conservatively, e.g., valuing debt at the higher bound / collateral at the lower bound) instead of aborting the whole call.

### Proof of Concept
1. Attacker or organic market conditions cause the Pyth price feed for a collateral or debt asset used by an under-collateralized borrower to report a confidence interval `conf` such that `conf > price * max-confidence-ratio / BPS`.
2. Any liquidator calls `liquidate(...)` on the under-collateralized position; `write-feeds` updates the feed with the current (high-confidence) publish.
3. `get-assets` → `price-multi-resolve` → `price-resolve` → `resolve-pyth` → `check-confidence` triggers `asserts!` failure, returning `ERR-PRICE-CONFIDENCE-LOW`, aborting the whole `liquidate` transaction. [1](#0-0) 
4. As long as the confidence interval remains elevated (which can persist through an entire volatile market move), no liquidator can close the position, and if the underlying price keeps deteriorating, the position's debt may exceed its collateral value, leaving bad debt for the protocol to absorb.
