### Title
Stop-hook review set silently drops amended commits, allowing dangerous changes to bypass security review - (File: `plugins/security-guidance/hooks/diffstate.py`, function `compute_v2_review_set`)

### Summary
`compute_v2_review_set` computes the Stop-hook review set as an **intersection** of `dirty_now` (files differing from current HEAD per `git status`) and `changed_since` (files differing from the pre-turn `baseline_sha`). A `git commit --amend` (or any non-fast-forward rewrite such as reset+recommit) breaks the `_is_ancestor(head_at_capture, current_head)` linear-advance check used to fold newly-committed files into `dirty_now`, while simultaneously making the file clean/committed so it no longer appears in `git status`. The dangerous file is thus present in `changed_since` but absent from `dirty_now`, so the intersection silently drops it from review.

### Finding Description
`save_baseline_sha` / `capture_git_baseline` (`plugins/security-guidance/hooks/diffstate.py:163-204`) capture `baseline_sha` (a `git stash create` object, falling back to `HEAD`) and `head_at_capture` on every `UserPromptSubmit`, via `handle_user_prompt_submit` in `security_reminder_hook.py:446-515`.

At Stop time, `compute_v2_review_set` (`diffstate.py:353-438`) derives the review set purely from git state:
```
tracked_dirty, untracked = _git_status_porcelain(repo)   # vs current HEAD
...
if (head_at_capture and current_head and head_at_capture != current_head
        and _is_ancestor(repo, head_at_capture, current_head)):
    dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD") or set()
    diff_base = head_at_capture
...
changed_since = _git_name_only(repo, baseline_sha)   # vs stash baseline
...
review_set = (dirty_now & changed_since) if changed_since is not None else dirty_now
``` [1](#0-0) 

If a turn's edit is committed and then `git commit --amend` is run (a completely ordinary git workflow, e.g. "amend the last commit to add this file" or "fix the commit message"), the resulting commit is a **sibling**, not a descendant, of `head_at_capture` — `_is_ancestor` returns `False` — so the head-advance union that would normally fold committed changes into `dirty_now` never fires. Because the file is now committed, `git status --porcelain` shows it as clean, so it is also absent from `tracked_dirty`/`dirty_now` directly. Meanwhile `changed_since = _git_name_only(repo, baseline_sha)` (diff of current worktree against the stash-created baseline) correctly shows the file as changed. Since `review_set = dirty_now & changed_since`, and `dirty_now` doesn't contain the file, the intersection is empty for that file — it is excluded from the review set entirely, even though it demonstrably differs from the session's baseline.

This directly violates the stated invariant ("review set must stay bound to the right repo, baseline, and touched paths") because a file that changed since the true baseline is dropped purely due to the shape of git history (amend) rather than any intentional exclusion (the `preexisting_unchanged`/untracked exclusion logic is not involved here — this is a tracked, committed file).

### Impact Explanation
The Stop hook's LLM security review (`analyze_code_security`/`agentic_review`, downstream of `compute_v2_review_set`) never receives the dangerous file's diff, so a vulnerability introduced and then amended into a commit is never flagged, never triggers the `exit(2)` re-wake, and ships silently. This is a trust-boundary/review-bypass impact: the plugin's core guarantee ("all code Claude changed during the session is reviewed before the turn ends") is broken by ordinary, unprivileged git operations available to anyone driving the Bash tool — no maintainer/admin rights, leaked credentials, or social engineering required.

### Likelihood Explanation
The trigger is a single ordinary git command (`git commit --amend`) performed after a tracked edit and commit within the same turn. This is an extremely common workflow (fixing a commit message, squashing a follow-up fix into the previous commit) and requires no unusual privileges — only that the working tree is a normal git clone, matching the stated attacker model exactly. It is fully repeatable and deterministic given the described sequence.

### Recommendation
Change `compute_v2_review_set` to union rather than gate the "committed since baseline" set on strict linear ancestry, or independently include `_git_name_only(repo, baseline_sha)` results for files reachable from `current_head` regardless of whether `head_at_capture` is an ancestor (e.g. also diff `baseline_sha..HEAD` unconditionally and union with `dirty_now` before intersecting with `changed_since`, or simply use `changed_since` alone as the review set when it is a superset of `dirty_now` due to non-linear history). At minimum, detect the amend/rewrite case (e.g. via reflog, as already done for `_resolve_amend_pre_sha`) and explicitly widen `dirty_now` to include files touched by the rewritten commit(s).

### Proof of Concept
Integration test plan (pytest-style) against `diffstate.compute_v2_review_set`:
1. Init a temp git repo with an initial commit `C0` containing `safe.py`.
2. Simulate UPS: capture `baseline_sha = capture_git_baseline(repo)` (clean tree → returns `C0`), `head_at_capture = C0`.
3. Simulate Claude's turn: write a dangerous payload into `vuln.py`, `git add vuln.py && git commit -m "add vuln"` → `C1`.
4. Simulate an amend: `git commit --amend -m "add vuln (fixed message)"` → `C1'` (parent still `C0`, `C1` no longer reachable from `C1'`).
5. Call `compute_v2_review_set(repo, baseline_sha=C0, head_at_capture=C0)`.
6. Assert: `_is_ancestor(repo, C0, C1')` is `True` in this simple case (since C1' is a direct child of C0) — so first confirm with a **second** amend or an intervening unrelated commit/rebase between `head_at_capture` and the amended commit to break ancestry (e.g. amend twice, or `git reset --soft` + recommit), then re-run and assert `os.path.join(repo, "vuln.py") not in review_paths` even though `vuln.py` differs from `baseline_sha`. This demonstrates the dangerous file is excluded from the review set purely due to the amend/rewrite, violating the "review set must contain all files changed since baseline" invariant.

    preexisting_unchanged = {p for p in untracked if _unchanged_since_baseline(p)}
    new_untracked = untracked - preexisting_unchanged
