### Title
Potential unbounded computation in permissionless validator/staking-info aggregation via `AddressBookV2.createNode` growth - (File: `kaiax/staking/impl/getter.go`, `kaiax/reward/impl/getter.go`, `kaiax/valset/impl/getter_demote.go`)

### Summary
`kaiax/staking/impl/getter.go`'s `getFromState` reads validator profiles via `MultiCallStakingInfoPermissionless`/`MultiCallStakingInfo`, and this list is subsequently iterated repeatedly by consensus-critical code: `parsePermissionlessCallResult` [1](#0-0) , `assignStakingRewards`/`assignStakingRewardsFlex` (looping over `si.ConsolidatedNodes()`) [2](#0-1) [3](#0-2) , and `collectStakingAmounts` in the valset demotion logic [4](#0-3) . These loops all run once per block on every node during `FinalizeState`/header verification, analogous to the audit finding's per-call loop over `vault.getUsers(...)`.

### Finding Description
Under the Permissionless fork, new validator nodes are created via `AddressBookV2.createNode(...)`, a state-changing entry point discoverable in the bindings [5](#0-4) . If this function (or the `CnStakingV4Factory.deployCnStaking` path used to obtain a valid staking contract [6](#0-5) ) can be invoked by an arbitrary, unprivileged account (subject only to gas/stake economics, not admin allow-listing), then the number of profiles returned by `getAllProfiles`/`MultiCallStakingInfoPermissionless` is attacker-influenced and can grow without an enforced hard cap that is checked at every consensus-critical read site. The reward and valset modules then loop over this array once per block for every full/consensus node (`assignStakingRewards`, `collectStakingAmounts`, `ConsolidatedNodes()`), which is the same structural pattern as the reported `LiquidationBot.fetchUnhealthyAccounts` looping over unbounded user-provided accounts.

### Impact Explanation
If reachable, this could cause per-block computation cost to grow linearly (or worse) with the number of registered validator nodes, potentially causing block processing/verification to exceed acceptable time budgets across all nodes simultaneously (unlike the original bot-only DoS, this would affect consensus-critical `FinalizeState`/header verification paths), which could manifest as degraded finality or divergence if some nodes time out while others do not.

### Likelihood Explanation
**Low-to-uncertain.** I could not confirm within the available search budget whether `createNode`/`deployCnStaking` registration is truly permissionless (open to any unprivileged EOA with sufficient stake) or gated by `MaxNodeCount`/`MaxCandReadyCount`/suspender-configurator permissions — I did find `MaxNodeCount`, `MaxCandReadyCount`, and `MaxValActivePausedCount` parameters in the genesis config (`abv2data.IABv2DataContractInitData`) [7](#0-6) , which strongly suggests the protocol already enforces caps on the validator set size specifically to prevent this class of issue. Given these caps likely exist and are checked in `AddressBookV2.sol` (not indexed/found in my search), the practical exploitability is probably already mitigated by design, unlike the original unbounded liquidation-bot loop.

### Recommendation
Verify that `AddressBookV2.createNode` enforces `MaxNodeCount`/`MaxCandReadyCount` limits on-chain (not just as advisory config) before any node reaches `ValActive`/`CandReady` state that gets included in `getAllProfiles()`. Confirm that `kaiax/staking/impl/getter.go`, `kaiax/reward/impl/getter.go`, and `kaiax/valset/impl/getter_demote.go` loops are bounded by this same cap, and add explicit bounds checks or gas-metering safeguards in these hot paths if the cap can be bypassed (e.g., via race conditions between suspend/exit and creation, or multiple manager addresses).

### Proof of Concept
Not constructed — I was unable to confirm within the tool budget whether `AddressBookV2.createNode`'s permission model allows an unprivileged actor to exceed configured node-count caps, which is the crux of exploitability. A background Devin session with full repository/contract access (specifically `kaia-system-contracts/contracts-v3.0/src/AddressBookV2.sol`, which was not returned by the index) would be needed to verify the exact access-control and cap-enforcement logic in `createNode` before this can be confirmed as a genuine, reachable analog rather than an already-mitigated design.

func assignStakingRewardsFlex(config *reward.RewardConfig, budget *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		minStake  = config.MinimumStake.Uint64()
		threshold = config.StakingRewardThreshold.Uint64()
		isPrague  = config.Rules.IsPrague

		cns            = si.ConsolidatedNodes()
		excessInt      = make(map[common.Address]uint64)
		totalExcessInt = uint64(0)
	)

	// Calculate the excess stakes (the amount over the threshold) for each CN.
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it. Even if (CNStaking + CLStaking) could be more than minStake,
		// the CNStaking alone must be at least minStake to be eligible.
		if cn.StakingAmount < minStake {
			continue
		}

		amount := cn.StakingAmount
		if isPrague && cn.CLStakingInfo != nil {
			amount += cn.CLStakingInfo.CLStakingAmount
		}

		// Excess is the amount over the threshold (not over minStake).
		if amount > threshold {
			excessInt[cn.RewardAddr] = amount - threshold
			totalExcessInt += excessInt[cn.RewardAddr]
		}
	}

	// Distribute the budget to the CNs based on the excess stakes.
	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(budget)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		if excessInt[cn.RewardAddr] <= 0 {
			continue
		}
		excess := new(big.Int).SetUint64(excessInt[cn.RewardAddr])

		// The KAIA unit will cancel out:
		// reward (kei) = excess (KAIA) * budget (kei) / totalExcess (KAIA)
		reward := new(big.Int).Div(new(big.Int).Mul(excess, budget), totalExcess)
		if reward.Sign() <= 0 {
			continue
		}

		// If Prague and CL is configured for this CN, split the reward between CN and CL.
		if isPrague && cn.CLStakingInfo != nil {
			cnAmount, clAmount := cn.Split(reward)
			alloc[cn.RewardAddr] = cnAmount
			alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
		} else {
			alloc[cn.RewardAddr] = reward
		}
		remaining.Sub(remaining, reward)
	}
	return alloc, remaining

// assignStakingRewards assigns staking rewards to stakers according to their staking amounts.
// Returns the allocation and the remainder.
func assignStakingRewards(config *reward.RewardConfig, stakersReward *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		cns               = si.ConsolidatedNodes()
		minStake          = config.MinimumStake.Uint64()
		totalExcessInt    = uint64(0) // sum of excess stakes (the amount over minStake) over all stakers
		cnTotalStakingMap = make(map[common.Address]uint64)
		isPrague          = config.Rules.IsPrague
	)
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it.
		if cn.StakingAmount >= minStake {
			// Calculate total staking amount once
			cnTotalStakingAmount := cn.StakingAmount
			if isPrague && cn.CLStakingInfo != nil {
				cnTotalStakingAmount += cn.CLStakingInfo.CLStakingAmount
			}
			totalExcessInt += cnTotalStakingAmount - minStake
			cnTotalStakingMap[cn.RewardAddr] = cnTotalStakingAmount
		}
	}

	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(stakersReward)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		cnTotalStakingAmount := cnTotalStakingMap[cn.RewardAddr]
		if cnTotalStakingAmount > minStake {
			// The KAIA unit will cancel out:
			// reward (kei) = excess (KAIA) * stakersReward (kei) / totalExcess (KAIA)
			excess := new(big.Int).SetUint64(cnTotalStakingAmount - minStake)
			if reward := new(big.Int).Div(new(big.Int).Mul(excess, stakersReward), totalExcess); reward.Sign() > 0 {
				if isPrague && cn.CLStakingInfo != nil {
					// The remaining amount will be added to the cnAmount.
					cnAmount, clAmount := cn.Split(reward)
					alloc[cn.RewardAddr] = cnAmount
					alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
				} else {
					alloc[cn.RewardAddr] = reward
				}
				remaining.Sub(remaining, reward)
			}
		}
	}
	return alloc, remaining
}

// collectStakingAmounts returns the staking amounts for the given nodes(i.e., the registered validator set).
// The staking amount for each node is determined based on the consolidated nodes,
// which aggregate stakes across multiple staking contracts that share the same reward address.
// Under a single RewardAddr, only one representative NodeId is included in the validator set,
// and that NodeId will be assigned the total aggregated stake.
//
// for example, consolidated nodes:
//
//	CN1 = {[N1,N2], [S1,S2], R1, A1+A2}
//	CN3 = {[N3],    [S3],    R3, A3}
//
// Given nodes = [N2, N3], the resulting stakingAmounts will be:
//
//	{N2: A1 + A2, N3: A3}
//
// Note: This function assumes that validator registration is controlled,
// and that only one NodeId per reward address can be part of the validator set.
// If this assumption changes, this logic may need to be revisited.
func collectStakingAmounts(nodes []common.Address, si *staking.StakingInfo) map[common.Address]float64 {
	cns := si.ConsolidatedNodes()
	stakingAmounts := make(map[common.Address]float64, len(nodes))
	for _, node := range nodes {
		stakingAmounts[node] = 0
	}
	for _, cn := range cns {
		for _, node := range cn.NodeIds {
			if _, ok := stakingAmounts[node]; ok {
				stakingAmounts[node] = float64(cn.StakingAmount)
			}
		}
	}
	return stakingAmounts
}
