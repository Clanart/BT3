### Title
Unbounded aggregate-signature deserialization enables attacker-controlled memory exhaustion - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::read` accepts a 32-bit signature count and then reads and retains that many group elements without imposing any protocol or memory bound. An attacker who supplies serialized aggregate-signature bytes can force the victim to allocate memory proportional to the supplied count/input until allocation failure or process termination.

### Finding Description
The decoder reads a little-endian `u32` length and pushes one decoded point per declared element into `Rs`. There is no cap based on the expected number of signatures, the verifier's configured signer set, or the bytes actually available before allocation begins [1](#0-0) . `C::read_G` validates each encoding, but a valid repeated point encoding remains attacker-controlled input and is retained indefinitely [2](#0-1) . Verification additionally allocates a pair vector proportional to the decoded count, compounding memory usage after a sufficiently large encoded aggregate is accepted [3](#0-2) .

### Impact Explanation
An unprivileged party able to submit an aggregate signature or bytes passed to `SchnorrAggregate::read` can cause sustained memory consumption and eventual allocator panic/process termination by providing a large valid sequence. The affected component is availability, matching the externally reported class: a locally supplied object causes a repeatable denial of service without requiring key access or cryptographic invalidity.

### Likelihood Explanation
The length field permits up to `u32::MAX` entries. Although the reader stops on premature EOF, no early bound rejects impossible aggregate sizes. A reader backed by a large file, stream, or generated source can provide enough valid encodings to exhaust memory. Verification also creates approximately twice as many entries as the number of supplied signatures.

### Recommendation
Pass an explicit expected/maximum signature count into `SchnorrAggregate::read`, or deserialize only within a bounded type owned by the calling protocol. Reject counts exceeding the configured signer/signature set before accumulating `Rs`, and preferably return an error once remaining input cannot satisfy the declared count rather than retaining decoded elements one by one.
