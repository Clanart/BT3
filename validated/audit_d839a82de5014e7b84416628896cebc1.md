### Title
Recursive/Nested Precompile Calls Cause Balance Desync Between EVM StateDB and x/bank via Stale `BalanceHandler.prevEventsLen` Window - (File: precompiles/common/balance_handler.go, precompiles/common/precompile.go)

### Summary
The Arcadia report is a reentrancy bug where a flash-action callback lets an attacker trigger a nested state-changing call (liquidation + bid) *before* the outer call's invariant check runs, corrupting collateral/debt accounting. The Cosmos EVM analog is in the stateful-precompile execution path: `Precompile.runNativeAction` computes an event-window (`prevEventsLen`) to translate bank/precisebank events into `StateDB.AddBalance`/`SubBalance` calls, but this window is derived from a shared, mutable event log that persists across **nested/recursive precompile invocations** within the same EVM call. A contract that triggers a precompile call recursively (directly analogous to the "actionTarget re-enters mid-flow" pattern in the report) causes bank events emitted by an inner precompile call to be replayed and re-applied to the StateDB by an outer call's `AfterBalanceChange`, corrupting the 1:1 mapping between real `x/bank` balances and EVM-visible balances.

### Finding Description
`Precompile.runNativeAction` (precompiles/common/precompile.go:57-126) is the shared entrypoint used by every stateful precompile (bank, staking, distribution, gov, ics20, erc20, slashing, werc20 — see the `BalanceHandlerFactory` usages found in each of those files). For every precompile call it:
1. Takes a `stateDB.GetCacheContext()` and a multistore snapshot [1](#0-0) 
2. Creates a **new** `BalanceHandler` and calls `BeforeBalanceChange(ctx)`, which snapshots `prevEventsLen = len(ctx.EventManager().Events())` [2](#0-1) [3](#0-2) 
3. Runs the precompile's native action, which may itself call back into the EVM (e.g. `evmKeeper.CallEVMWithData`) triggering **another, nested** precompile call before returning [4](#0-3) 
4. After the action returns, `AfterBalanceChange(ctx, stateDB)` replays every `EventTypeCoinSpent`/`EventTypeCoinReceived`/`EventTypeFractionalBalanceChange` event in `events[bh.prevEventsLen:]` and applies matching `stateDB.AddBalance`/`SubBalance` calls [5](#0-4) 

Because the outer call's `ctx` and its underlying `EventManager` are shared with the nested/recursive precompile call (the cache context is a StateDB-level construct, not freshly isolated per nesting level), events emitted during the *inner* precompile call are visible to, and replayed by, the *outer* call's `AfterBalanceChange` window as well as by the inner call's own `AfterBalanceChange`. This causes bank-triggered balance deltas to be counted more than once (or windows to be miscomputed) against the EVM `StateDB`, desynchronizing EVM-visible balances from the actual `x/bank` ledger.

This exact defect is already reproduced by a dedicated regression test shipped in the repository, whose own comment confirms the root cause and impact: [6](#0-5) 
The accompanying PoC contract performs nested/recursive calls into the same precompile address exactly as an attacker-controlled contract would: [7](#0-6) 

While the shipped test uses a debug-only precompile to demonstrate the mechanism, the vulnerable code path (`Precompile.runNativeAction` + `BalanceHandler`) is shared infrastructure used by every production stateful precompile that moves real bank funds (bank, staking, distribution, gov deposits, ics20 transfer, erc20, werc20). Any contract that can cause one of these precompiles to be invoked recursively/nested within a single EVM transaction (e.g., via a fallback/receive hook triggered by a precompile-initiated transfer, or via `try/catch` wrapped precompile calls as already demonstrated in `precompiles/testutil/contracts/StakingReverter.sol` and `tests/solidity/suites/revert_cases/contracts/RevertTestContract.sol`) can trigger the same event-window overlap.

### Impact Explanation
This breaks the invariant that EVM-visible native balances (`StateDB.AddBalance`/`SubBalance`, used for `value` transfers, `SELFBALANCE`, `BALANCE` opcodes, and ERC20/precompile balance views) must equal the real `x/bank` coin ledger. Depending on call ordering, the bug can cause:
- Double-crediting of `AddBalance` for a single real bank transfer, letting the EVM-visible balance of an account exceed its true backing in `x/bank` — a form of unauthorized duplication/minting of spendable value that can then be moved out via ordinary `CALL{value:}` from the EVM, corrupting the escrow ledger for real users.
- Double-debiting of `SubBalance`, artificially freezing/destroying spendable EVM balance for a victim account without a matching real balance change.

Both outcomes fall squarely under the allowed Critical impact class of "unauthorized minting, burning, duplication, or irreversible accounting corruption of spendable user value across native balances, EVM balances… or precompile-mediated assets," matching the accounting-corruption theme of the Arcadia H-2 report.

### Likelihood Explanation
The regression test in this exact repository already reproduces the desync using an ordinary (non-privileged) EVM transaction from a user-deployed contract, with no special permissions required — only the ability to call a stateful precompile recursively from Solidity, a pattern already present multiple times in the repo's own test fixtures (`StakingReverter.sol`, `RevertTestContract.sol`, `DebugPrecompileCaller.sol`). This indicates the trigger is reachable through ordinary transaction/contract flow by any unprivileged user, satisfying the "unprivileged trigger" requirement.

### Recommendation
Scope the `BalanceHandler`'s event window and/or the underlying `EventManager` per precompile-call *nesting level*, not just per top-level call: e.g., have `stateDB.GetCacheContext()` return an isolated event manager for each nested invocation (mirroring how `MultiStoreSnapshot`/`RevertMultiStore` isolate store state per snapshot), and have each `AfterBalanceChange` consume only the events emitted strictly within its own nesting level, marking them consumed so an outer level cannot re-process events already applied by an inner level. Add an explicit "already applied" marker or slice-truncation step at each level boundary, and extend the existing `evmd/tests/integration/balance_handler` regression tests to exercise every production precompile that mutates bank balances (bank, staking, distribution, gov, ics20, erc20, werc20) under nested/recursive call scenarios, verifying `x/bank` balance equals `StateDB` balance after execution.

### Proof of Concept
The repository already contains a working PoC: `contracts/solidity/DebugPrecompileCaller.sol` recursively invokes the debug precompile, and `evmd/tests/integration/balance_handler/balance_handler_test.go::TestRecursivePrecompileCallsWithDebugPrecompile` drives it end-to-end, asserting the exact event/desync symptom described above. I was not able to fully trace the internal implementations of `StateDB.GetCacheContext()` / `CommitWithCacheCtx()` (only signatures/usages were visible in the indexed context), so the precise mechanism by which the event manager is shared across nesting levels should be re-verified against the full `x/vm/statedb/statedb.go` source before remediation; a Devin session with full repository access would be needed to confirm line-level details and validate the fix against all production precompiles listed above.

```go
func (bh *BalanceHandler) AfterBalanceChange(ctx sdk.Context, stateDB *statedb.StateDB) error {
	events := ctx.EventManager().Events()

	for _, event := range events[bh.prevEventsLen:] {
		switch event.Type {
		case banktypes.EventTypeCoinSpent:
			spenderAddr, err := ParseAddress(event, banktypes.AttributeKeySpender)
			if err != nil {
				return fmt.Errorf("failed to parse spender address from event %q: %w", banktypes.EventTypeCoinSpent, err)
			}
			if bh.bankKeeper.BlockedAddr(spenderAddr) {
				// Bypass blocked addresses
				continue
			}

			amount, err := ParseAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", banktypes.EventTypeCoinSpent, err)
			}

			stateDB.SubBalance(common.BytesToAddress(spenderAddr.Bytes()), amount, tracing.BalanceChangeUnspecified)

		case banktypes.EventTypeCoinReceived:
			receiverAddr, err := ParseAddress(event, banktypes.AttributeKeyReceiver)
			if err != nil {
				return fmt.Errorf("failed to parse receiver address from event %q: %w", banktypes.EventTypeCoinReceived, err)
			}
			if bh.bankKeeper.BlockedAddr(receiverAddr) {
				// Bypass blocked addresses
				continue
			}

			amount, err := ParseAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", banktypes.EventTypeCoinReceived, err)
			}

			stateDB.AddBalance(common.BytesToAddress(receiverAddr.Bytes()), amount, tracing.BalanceChangeUnspecified)

		case precisebanktypes.EventTypeFractionalBalanceChange:
			addr, err := ParseAddress(event, precisebanktypes.AttributeKeyAddress)
			if err != nil {
				return fmt.Errorf("failed to parse address from event %q: %w", precisebanktypes.EventTypeFractionalBalanceChange, err)
			}
			if bh.bankKeeper.BlockedAddr(addr) {
				// Bypass blocked addresses
				continue
			}

			delta, err := ParseFractionalAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", precisebanktypes.EventTypeFractionalBalanceChange, err)
			}

			deltaAbs, err := utils.Uint256FromBigInt(new(big.Int).Abs(delta))
			if err != nil {
				return fmt.Errorf("failed to convert delta to Uint256: %w", err)
			}

			if delta.Sign() == 1 {
				stateDB.AddBalance(common.BytesToAddress(addr.Bytes()), deltaAbs, tracing.BalanceChangeUnspecified)
			} else if delta.Sign() == -1 {
				stateDB.SubBalance(common.BytesToAddress(addr.Bytes()), deltaAbs, tracing.BalanceChangeUnspecified)
			}

		default:
			continue
		}
	}
```

```text
contract DebugPrecompileCaller {
    address constant debugPrecompile = 0x0000000000000000000000000000000000000799;
    error CallFailed(bytes data);
    function callback(uint256 counter) public {
        bool result;
        bytes memory data;

        // emit events
        for (uint i = 0; i < counter; i++) {
            (result, data) = debugPrecompile.call(abi.encodePacked(uint8(1)));
            if (!result) {
                revert CallFailed(data);
            }
        }

        if (counter > 3) {
            // stop the recursion
            return;
        }

        // recursive call
        (result, data) = debugPrecompile.call(abi.encodePacked(uint8(0), counter));
        if (!result) {
            revert CallFailed(data);
        }
    }
```
