### Title
Unbounded-depth JSON parsing in the JSON precompile causes an unrecoverable stack-overflow crash of every validator/RPC node - ([File: precompiles/json/json.go])

### Summary
The `json` precompile (address `0x0000000000000000000000000000000000001003`) decodes attacker-supplied byte payloads with Go's standard `encoding/json.Unmarshal` (aliased `gjson` in this package) directly into `map[string]json.RawMessage` / `[]json.RawMessage`. [1](#0-0)  Go's `encoding/json` decoder recurses through real Go function calls (`decodeState.value` → `array`/`object` → `value` → …) for every level of JSON nesting, with no depth limit. A single EVM transaction that calls this precompile with a deeply-nested JSON array/object (e.g. thousands of nested `[`) drives the decoder into a Go-runtime stack overflow, which is a `fatal error: stack overflow` — unrecoverable by `defer/recover` — and crashes the whole process. Because every validator (and RPC/full node) executes this same transaction deterministically, this crashes the entire network simultaneously.

### Finding Description
Every entry point of the precompile — `extractAsBytes`, `extractAsBytesList`, `ExtractAsUint256`, and `extractAsBytesFromArray` — unmarshals `args[0]` (the caller-controlled JSON payload) with `gjson.Unmarshal` before any structural/depth validation is performed: [2](#0-1) [3](#0-2) 

The only guard present is a per-byte gas charge (`GasCostPerByte = 100`) applied to the raw payload length before dispatch: [4](#0-3) 

This charges gas proportional to payload *size*, not to nesting *depth*. A payload consisting almost entirely of open brackets (e.g. `"[[[[[[...]]]]]]"`) has one byte per nesting level, so an attacker can reach tens or hundreds of thousands of nesting levels for a gas cost of only ~100 gas per level — well within a single transaction's gas limit. Unlike other JSON-handling code paths in this codebase that explicitly defend against this exact bug class — e.g. `sei-cosmos/codec/unknownproto/unknown_fields.go`'s `MaxProtobufNestingDepth = 100` [5](#0-4)  and `sei-cosmos/codec/types/interface_registry.go`'s `MaxUnpackAnyRecursionDepth` [6](#0-5)  — the JSON precompile has no analogous depth check. The same unguarded pattern is repeated across every legacy precompile version still shipped in the binary (v552, v555, v562, v603, v605, v606, v610, v614, v620, v630, v640, v65, v66, v67), e.g. [7](#0-6)  and [8](#0-7) .

This is the direct structural analog of CVE-2026-60194: a JSON-parsing feature that a network-reachable caller can drive into a hang/crash of the server process. Here the "server" is every sei-chain validator and RPC node, and the caller is any unprivileged EVM transaction sender or contract that invokes the precompile.

### Impact Explanation
A stack overflow in Go triggers `fatal error: stack overflow`, which is a runtime-level fatal condition, not a normal panic — it cannot be intercepted by the EVM's or the Cosmos SDK's panic-recovery/ante-handler wrappers. The process terminates immediately. Since transaction execution (including EVM calls to precompiles) is part of consensus-critical, deterministic state transition, every validator and full node that processes the offending transaction (in a block, in `CheckTx`, or via `eth_call`) crashes identically. This causes a network-wide validator halt / chain stall — the transaction can be repeatedly rebroadcast to prevent recovery until the precompile is patched, satisfying the "validator halt" / "block delay beyond 2.5 seconds" / "crash of default-configuration RPC nodes" criteria.

### Likelihood Explanation
Exploitation requires nothing more than an EOA or contract calling the JSON precompile at `0x1003` with a crafted `bytes` argument containing deep bracket nesting — no special privileges, no state setup, and gas cost scales linearly (not exponentially) with the depth needed to exhaust the goroutine stack. This is trivially and repeatably exploitable by any transaction sender, making likelihood high.

### Recommendation
Add an explicit maximum nesting-depth check before/while unmarshaling attacker-supplied JSON in the `json` precompile (and its legacy variants), consistent with the existing `MaxProtobufNestingDepth`/`MaxUnpackAnyRecursionDepth` pattern used elsewhere in the codebase. Practically, replace the direct `encoding/json.Unmarshal` calls with a depth-bounded decoder (e.g., use `json.NewDecoder` with `Token()`-based streaming and an explicit depth counter that errors out past a small fixed limit, such as 32–64) before falling back to structural unmarshaling into `RawMessage` maps/slices.

### Proof of Concept
1. Craft an EVM transaction calling the JSON precompile (`0x0000000000000000000000000000000000001003`) method `extractAsBytesFromArray(bytes,uint16)` (selector `p.ExtractAsBytesFromArrayID`).
2. Set the `bytes` argument to a JSON payload consisting of N repeated `[` characters followed by N repeated `]` characters (e.g., N = 200,000), which is valid but deeply-nested JSON and costs only `GasCostPerByte * len(payload)` gas (linear, not depth-scaled).
3. Submit the transaction to any full node/validator; `gjson.Unmarshal(bz, &decoded)` in `extractAsBytesFromArray` [9](#0-8)  recurses once per nesting level via Go function calls, exhausting the goroutine stack and triggering `fatal error: stack overflow`, crashing the node process irrecoverably.

		return nil, err
