### Title
Gasless swap price check uses manipulable single-block AMM spot price, allowing bundle desync between lend and repay - ([File: kaiax/gasless/impl/tx_pool.go])

### Summary
The KIP-247 gasless module lends KAIA to a user (via `GetLendTxGenerator`) *before* the user's swap transaction actually executes, trusting that the swap will yield enough output to repay the loan. The only pre-execution guarantee that the swap can repay the loan is `checkBalanceForSwap`, which queries `GaslessSwapRouter.GetAmountIn(token, minAmountOut)` — a live, single-call AMM quote based on the pool's current reserves at tx-pool admission time. This is structurally the same bug class as the PLVGLP `previewRedeem` issue: a critical financial precondition (sufficiency of collateral/output to satisfy the lender) is derived from an instantaneously readable, single-transaction-manipulable AMM state rather than a guarantee enforced atomically at the point of loan disbursement and repayment.

### Finding Description
`checkBalanceForSwap` in [1](#0-0)  validates a `GaslessSwapTx` by:
1. Requiring `minAmountOut >= amountRepay` (a value fixed purely from gas price × gas limits, computed in [2](#0-1) ).
2. Requiring `amountIn >= gsr.GetAmountIn(token, minAmountOut)`, where `GetAmountIn` is a live on-chain call to the `GaslessSwapRouter` contract [3](#0-2) , which for a Uniswap-V2-style pool derives its answer purely from the pool's *current* reserves (a manipulable spot price, no TWAP, no execution-time guarantee).

This check is executed once, against the chain-head state, when the transaction is admitted/promoted in the tx pool [4](#0-3) . The block-building flow then prepends an unconditional `LendTxGenerator` transaction that pays the user KAIA up-front, followed by the (optional) approve and swap transactions, bundled together per [5](#0-4)  and [6](#0-5) . The `LendTx` transfers value from the proposer to the user regardless of whether the subsequent swap actually succeeds in delivering `AmountRepay` worth of KAIA back — the repayment relies entirely on the swap transaction's own on-chain execution against the reserves *at the moment the bundle is actually included*, which can differ from the reserves seen during the earlier `checkBalanceForSwap` admission check (e.g., due to intervening trades by other block participants, or a searcher who trades against the pool between admission and inclusion, or across the gap between mempool re-validation cycles).

Because the admission-time `GetAmountIn` quote is a spot-price read of a manipulable AMM state rather than an atomically-enforced guarantee tied to the loan disbursement itself, an adversary can influence the pool's reserves between the time `checkBalanceForSwap` approves the transaction and the time the bundle is actually executed on-chain, causing the real swap output to diverge from what was validated at admission — the same "verify against instantaneous manipulable value" pattern identified in the PLVGLP report.

### Impact Explanation
If the swap's actual (post-manipulation) output undercuts what was represented by the stale `GetAmountIn` check, the swap can fail to repay the amount the proposer already fronted via `LendTx`, since the `LendTx` is a separate, already-committed transaction in the block that is not automatically reversed if the paired `SwapTx` reverts or under-delivers. This results in the proposer (block builder) losing the lent KAIA — an unauthorized/uncompensated value transfer out of the fee-delegation/gasless mechanism, matching the "concrete unauthorized value movement" bar required for Medium/High severity.

### Likelihood Explanation
This requires an attacker capable of moving the relevant token/WKAIA AMM pool's reserves within the narrow window between a gasless bundle's admission-time price check and its actual on-chain inclusion — feasible for any unprivileged pool participant or the gasless user's own colluding account trading against thinly-liquid gasless-whitelisted tokens, without requiring any protocol-level privilege. The likelihood is bounded by liquidity depth of the specific pools registered for gasless swaps and by how quickly re-validation/promotion re-checks balances, which I was not able to fully confirm from the available bindings (the Solidity source of `GaslessSwapRouter.sol` implementing `swapForGas`/`getAmountIn` was not present in the indexed codebase, only its Go bindings), so I cannot state with certainty whether on-chain slippage protection inside `swapForGas` fully closes this gap or only partially mitigates it.

### Recommendation
- Ensure `LendTx` and `SwapTx` execution and repayment are enforced atomically at the EVM level (e.g., have the lend/repay accounting occur within the same contract call/transaction as the swap, or make the bundle abort the `LendTx` value transfer if the paired swap fails to fully repay).
- Avoid relying on a single spot-price `GetAmountIn` call read at tx-pool admission time as the sole solvency guarantee; instead require the on-chain `swapForGas` execution itself to enforce `output >= AmountRepay` with the funds movement to the proposer happening strictly within that same atomic call.
- Consider re-validating `checkBalanceForSwap` (or a stronger price bound) immediately before block inclusion using the exact state the bundle will execute against, rather than only at initial admission.

### Proof of Concept
Not independently reproducible from the indexed code alone: the Solidity implementation of `GaslessSwapRouter.swapForGas()`/`getAmountIn()` (which would show whether on-chain slippage enforcement is atomic with the lend/repay accounting) was not found in the indexed repository content — only its compiled Go bindings were available [7](#0-6) . Due to index size limits, some file contents (notably the `.sol` source for `GaslessSwapRouter`) may not be available; a full Devin session with filesystem access would be needed to confirm the exact atomicity guarantees of `swapForGas` and construct a concrete end-to-end PoC.

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

### Block building rules

Upon detection of GaslessTxs, the following logics are executed:

- Per sender, if exists, GaslessApproveTx is relocated before GaslessSwapTx.
- LendTxGenerator is prepended before GaslessApproveTx.
- A new bundle is generated which contain either `[LendTxGenerator, GaslessApproveTx, GaslessSwapTx]` or `[LendTxGenerator, GaslessSwapTx]`
- If the bundle has conflict with any previous bundles, it is excluded from the returned bundle list.

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}
