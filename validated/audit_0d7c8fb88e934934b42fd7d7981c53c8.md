### Title
Transaction pool caches a stale `UnitPrice`/`gasPrice` that diverges from the governance value enforced during block execution, pre-Magma - ([File: blockchain/tx_pool.go])

### Summary
`TxPool` snapshots `governance.unitprice` into `pool.gasPrice` once at construction and, in `reset()`, only refreshes it from the governance module (`pool.govModule.GetParamSet(...)`) when `pool.rules.IsMagma` is true. Before Magma, the only other way `pool.gasPrice` changes is through the explicit `SetGasPrice()` call. This mirrors the reported `minRentalDayDivisor` bug class exactly: a governance-controlled parameter is copied into a component's local state at one point in time, and that local copy is not kept synchronized with the authoritative governance parameter that the rest of the protocol (block validation / state transition) actually enforces per block via `GetParamSet(blockNum)`.

### Finding Description
`NewTxPool` initializes the pool's minimum acceptance price directly from the governance parameter set at construction time: [1](#0-0) 

In `reset()`, which runs on every new head, the cached `pool.gasPrice` is only recomputed from the live governance parameter set when the Magma fork rules are active: [2](#0-1) 

Outside of the Magma branch, `pool.gasPrice` is a static value that was captured once (at pool construction) and is subsequently only mutated by an explicit external call to `SetGasPrice()`: [3](#0-2) 

`validateTx()` (the function reached by every unprivileged transaction sender submitting a tx through `AddLocal`/`AddRemote`/RPC `eth_sendRawTransaction`) enforces this cached, possibly-stale `pool.gasPrice` against the exact `unitprice` policy — before Magma it requires an *exact match* between `tx.GasPrice()` and `pool.gasPrice`: [4](#0-3) 

Meanwhile, the authoritative source of truth for `unitprice` is the governance module, which computes the parameter per block number by merging header-governance votes and (post-Kore) contract-governance values: [5](#0-4) 

`governance.unitprice` is an explicitly mutable governance parameter that can change via governance vote at any epoch boundary, as documented: [6](#0-5) 

Because the mempool's admission rule (`pool.gasPrice`, static pre-Magma) and the block-execution/consensus rule (`GetParamSet(blockNum).UnitPrice`, computed fresh per block) draw from the same governance source but the pool's copy is not refreshed on every head update pre-Magma, a governance vote that changes `governance.unitprice` mid-chain creates a window where the txpool's admission price and the price that block proposers/validators will actually require for inclusion diverge — exactly the "value copied at one point, not synced to the live governance source" pattern described in the report for `minRentalDayDivisor`.

### Impact Explanation
If `governance.unitprice` is voted to a new value and the txpool does not refresh `pool.gasPrice` for existing/queued transactions (or new submitters compute their tx's exact-match `gasPrice` from a stale RPC-reported pool value), transactions can be:
- Rejected by the pool (`ErrInvalidUnitPrice`) even though they would be valid under the newly voted price, causing denial of service to legitimate senders, or
- Accepted into the pool as "valid" under the stale cached price yet fail block inclusion under the new governance-enforced price, wasting user-submitted transactions and causing state divergence in mempool behavior between nodes that reset at different times relative to the vote.

This is a protocol-consistency/availability issue reachable by any unprivileged transaction sender or public-RPC caller submitting ordinary transactions, matching the Medium-severity classification of the underlying bug class (unexpected results / DoS-adjacent behavior from a stale copied governance parameter, not an outright fund-theft primitive) as accepted in the original report.

### Likelihood Explanation
Likelihood is limited to networks that (a) are still pre-Magma (since post-Magma the code explicitly refreshes `pool.gasPrice` every reset) and (b) actively vote to change `governance.unitprice`. Given Kaia mainnet has passed Magma, this specific instance is largely legacy-path risk; however, the same architectural pattern (component caching a governance-derived value that other components recompute fresh per block) is a recurring theme in the codebase (e.g., `gasless` module's `swapRouter`/`allowedTokens`, which are explicitly refreshed at every block per its README, showing the team is aware of and mitigates this class elsewhere, in contrast to the pre-Magma unit-price path in `tx_pool.go`).

### Recommendation
Refresh `pool.gasPrice` (and `pool.blobBaseFee`) from `pool.govModule.GetParamSet(newHead.Number.Uint64()+1)` unconditionally in `reset()`, not only when `pool.rules.IsMagma`, so that the txpool's admission price always tracks the current governance `unitprice`/`basefee` regardless of fork status. Alternatively, explicitly document (as Reality Cards did) that `governance.unitprice` changes pre-Magma require operators to call `SetGasPrice()` to avoid pool/consensus divergence.

### Proof of Concept
1. Deploy a pre-Magma Kaia chain configuration (`MagmaCompatibleBlock` unset or in the future).
2. Start a node; `NewTxPool` captures `pool.gasPrice = pset.UnitPrice` (e.g., 25 Gkei) at construction — see `blockchain/tx_pool.go` lines 281-305.
3. Submit a `governance.unitprice` vote (header governance) to change `unitprice` to a new value (e.g., 30 Gkei) and let it ratify at the epoch boundary — this changes what `GetParamSet(blockNum)` returns for subsequent blocks, per `kaiax/gov/impl/getter.go`.
4. Observe `reset()` is invoked on the new head (`blockchain/tx_pool.go` lines 570-580); because `pool.rules.IsMagma` is false, `pool.gasPrice` is **not** updated to 30 Gkei and remains 25 Gkei.
5. Submit a transaction with `GasPrice = 30 Gkei` (the new governance-correct value): `validateTx()` compares `pool.gasPrice.Cmp(tx.GasPrice()) != 0` (line 877) and rejects it with `ErrInvalidUnitPrice`, even though 30 Gkei is the value that will actually be required for block inclusion under the updated governance parameter — demonstrating concrete divergence between the pool's stale cached governance value and the live value enforced elsewhere in the protocol.

// SetGasPrice updates the gas price of the transaction pool for new transactions, and drops all old transactions.
func (pool *TxPool) SetGasPrice(price *big.Int) {
	if pool.rules.IsMagma {
		logger.Info("Ignoring SetGasPrice after Magma fork")
		return
	}
	if pool.gasPrice.Cmp(price) != 0 {
		pool.mu.Lock()

		logger.Info("TxPool.SetGasPrice", "before", pool.gasPrice, "after", price)

		pool.gasPrice = price
		pool.pending = make(map[common.Address]*txList)
		pool.queue = make(map[common.Address]*txList)
		pool.pendingCount = 0
		pool.queuedCount = 0
		pool.beats = make(map[common.Address]time.Time)
		pool.all = newTxLookup()
		pool.pendingNonce = make(map[common.Address]uint64)
		pool.locals = newAccountSet(pool.signer)
		pool.priced = newTxPricedList(pool.all)

		pool.mu.Unlock()
	}
}

package impl

import (
	"github.com/kaiachain/kaia/kaiax/gov"
)

func (m *GovModule) GetParamSet(blockNum uint64) gov.ParamSet {
	ret := gov.GetDefaultGovernanceParamSet()

	p0 := m.Fallback
	for k, v := range p0 {
		err := ret.Set(k, v)
		if err != nil {
			logger.CritWithStack("Failed to add param from Fallback", "name", k, "value", v, "error", err)
		}
	}

	p1 := m.Hgm.GetPartialParamSet(blockNum)
	for k, v := range p1 {
		err := ret.Set(k, v)
		if err != nil {
			logger.CritWithStack("Failed to add param from HeaderGov", "name", k, "value", v, "error", err)
		}
	}

	if m.isKoreHF(blockNum) {
		p2 := m.Cgm.GetPartialParamSet(blockNum)
		for k, v := range p2 {
			err := ret.Set(k, v)
			if err != nil {
				logger.CritWithStack("Failed to add param from ContractGov", "name", k, "value", v, "error", err)
			}
		}
	}

	return *ret
}
