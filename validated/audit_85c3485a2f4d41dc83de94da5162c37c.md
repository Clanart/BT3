## Finding

### Title
Optimism dispute-game "not challenged" check is vacuously true at game creation, allowing acceptance of a false L2 state root before any real challenge window exists - ([File: modules/ismp/clients/optimism/src/lib.rs])

### Summary
The M-05 report's core broken invariant is: a validity gate that is supposed to represent "this claim survived scrutiny" can be satisfied by an attacker without the claim ever actually being scrutinized, because the check only tests a structural side-effect of disputing (a VM state transition / a move on the bisection tree) rather than the passage of the actual challenge/finality window. Hyperbridge's OP Stack `FaultDisputeGame` consensus verifier has the same defect: it treats `claimData.length == 1` as proof that a root claim is "unchallenged" and therefore trustworthy, but that condition is trivially true for every dispute game the instant it is created, regardless of how long it has existed or whether it will ever resolve correctly.

### Finding Description
`verify_not_challenged` in [1](#0-0)  reads the `claimData` array length at a fixed storage slot and accepts the claim as valid if the length is exactly `1`: [2](#0-1) 

This slot holds only the root claim appended in `initialize()`; every `move()` (attack/defense) appends another entry. Consequently `claimData.length == 1` is true from the very block the dispute game is created until the first challenger move — there is no check of `resolvedAt`, `status()` (`GameStatus`), or elapsed game-clock duration anywhere in `verify_optimism_dispute_game_proof`: [3](#0-2) 

The `OptimismDisputeGameProof` struct carries `timestamp` ("L1 Timestamp at game creation") but this value is only used to derive/compare the game ID, never to enforce that a minimum dispute period has elapsed: [4](#0-3) 

Real OP Stack fault-proof security requires a `FaultDisputeGame` to survive its full challenge clock (`MAX_CLOCK_DURATION`) and resolve as `DEFENDER_WINS` before its root claim is treated as final — exactly the invariant the `[M-05]` report shows can be broken when a "no counter-claim yet" heuristic substitutes for "the dispute actually concluded correctly." Hyperbridge's verifier uses the same kind of proxy signal (structural absence of a move) instead of the real finality criterion (resolved status after the clock elapses), so it provides no security by itself — it is satisfiable by construction at creation time.

Dispute-game creation on OP Stack is explicitly permissionless per Hyperbridge's own documentation: "Any bonded party can submit an L2 output root as a fault dispute game at any time" [5](#0-4) . Submitting the resulting consensus proof to Hyperbridge is equally permissionless: `handle_unsigned` is dispatched with `ensure_none(origin)` and "permits anyone execute ISMP messages for free, provided they have valid proofs" [6](#0-5) , and `update_client`/`create_client` only requires a valid `ConsensusClient::verify_consensus` pass [7](#0-6) .

### Impact Explanation
An unprivileged attacker can create a `FaultDisputeGame` on L1 with a false L2 output root, then — in the same or the very next block, before any fisherman or challenger has had a chance to act — construct an `OptimismDisputeGameProof` referencing that fresh game (where `claimData.length` is provably `1` because nothing has happened yet) and submit it as a `ConsensusMessage` to Hyperbridge. `verify_optimism_dispute_game_proof` will accept it and store the false state as a `StateCommitment` for the OP state machine [8](#0-7) . This directly matches the ISMP consensus documentation's warning that a naive "no fraud proof yet" signal is not the same as "safe": the challenge window, not the absence of a move, is what is supposed to establish canonicality [9](#0-8) . Once stored, the false commitment starts its own (separate, Hyperbridge-side) `challenge_period` clock before it can be used for request/response/timeout processing, so the fisherman/blacklist mechanism is the only remaining backstop — but the on-chain "not challenged" check that the protocol documentation presents as part of the security argument for accepting the claim contributes nothing, since it can never fail for a claim that is only seconds old.

### Likelihood Explanation
High feasibility: creating a `FaultDisputeGame` requires only the bond, no privileged role; submitting the ISMP consensus message requires no signer permissions (`ensure_none`); and the exploit window (immediately post-creation) is guaranteed to satisfy `claimData.length == 1` by construction, not by chance or race condition.

### Recommendation
Do not accept a `FaultDisputeGame`/`AggregateVerifier` claim based solely on the "no move yet" storage signal. Require proof that the OP Stack finality criteria have actually been met — e.g. prove `status() == DEFENDER_WINS` and that `resolvedAt` plus the chain's `proofMaturityDelaySeconds` (or equivalent finalization delay) has elapsed relative to the L1 height being proven against, in addition to (or instead of) the `claimData.length` check. At minimum, enforce a minimum elapsed time since `createdAt` no shorter than the dispute game's configured `maxClockDuration` before `verify_not_challenged` can pass.

### Proof of Concept
1. Attacker calls `DisputeGameFactory.create()` on L1 (bond-only permissionless entrypoint) with a fabricated `rootClaim` for a nonexistent/incorrect L2 state.
2. In the same transaction context, attacker constructs `OptimismDisputeGameProof` with `dispute_game_proof`/`challenge_proof` demonstrating `claimData.length == 1` (trivially true — the game was just created).
3. Attacker submits `Message::Consensus(ConsensusMessage { consensus_proof: OptimismUpdate{ proof: OpFaultProofGames(payload) }.encode(), .. })` via the public `handle_unsigned` extrinsic.
4. `verify_optimism_dispute_game_proof` → `verify_not_challenged` returns `Ok(())` because no `move()` has occurred, and `update_client` persists the attacker's fabricated `StateCommitment` at [10](#0-9) , before any real dispute-resolution or off-chain fisherman quorum check has had time to occur.

pub fn verify_optimism_dispute_game_proof<H: Keccak256 + Send + Sync>(
	payload: OptimismDisputeGameProof,
	root: H256,
	dispute_factory_address: H160,
	game_type_configs: Vec<GameTypeConfig>,
	consensus_state_id: ConsensusStateId,
) -> Result<IntermediateState, Error> {
	// Find the per-game-type configuration for this proof's game type.
	let game_config = game_type_configs
		.iter()
		.find(|c| c.game_type == payload.game_type)
		.ok_or(Error::UnsupportedGameType(payload.game_type))?
		.clone();

	let factory_storage_root =
		get_contract_account::<H>(payload.dispute_factory_proof, &dispute_factory_address.0, root)?
			.storage_root
			.0
			.into();
	let l2_block_hash = Header::from(&payload.header).hash::<H>();

	let root_claim = calculate_output_root::<H>(
		payload.version,
		payload.header.state_root,
		payload.withdrawal_storage_root,
		l2_block_hash,
	);

	let game_uuid = get_game_uuid::<H>(payload.game_type, root_claim, payload.extra_data);

	let dispute_game_key = derive_map_key::<H>(game_uuid.0.to_vec(), DISPUTE_GAMES_SLOT);

	// Does the dispute game's unique identifier exist in the _disputeGames map?
	let proof_value = match get_value_from_proof::<H>(
		dispute_game_key.0.to_vec(),
		factory_storage_root,
		payload.dispute_game_proof,
	)? {
		Some(value) => value.clone(),
		_ => Err(Error::DisputeGameIdMissing)?,
	};

	let mut encoded_game_id = <alloy_primitives::Bytes as Decodable>::decode(&mut &*proof_value)
		.map_err(|_| Error::DecodeDisputeGameId(format!("{:?}", &proof_value)))?
		.0
		.to_vec();

	let game_id = get_game_id(payload.game_type, payload.timestamp, payload.proxy);
	let game_id_bytes = game_id.to_big_endian();

	// Pad the encoded game id gotten from proof with zeros so it becomes 32 bytes long
	(0..game_id_bytes.len().saturating_sub(encoded_game_id.len()))
		.for_each(|_| encoded_game_id.insert(0, 0));

	// Derived game id must be equal to encoded game id
	if encoded_game_id != game_id_bytes {
		Err(Error::DisputeGameIdMismatch)?
	}

	// Bind the proxy's storage layout to the expected implementation by proving
	// `gameImpls[game_type]` in the factory matches the configured address. This is what makes
	// the per-kind "not challenged" check below meaningful: a factory upgrade that swaps
	// `gameImpls` to an implementation with a different layout would fail this check.
	let game_type_key = {
		let mut key = vec![0u8; 32];
		key[28..].copy_from_slice(&payload.game_type.to_be_bytes());
		derive_map_key::<H>(key, GAME_IMPLS_SLOT)
	};
	let impl_value = get_value_from_proof::<H>(
		game_type_key.0.to_vec(),
		factory_storage_root,
		payload.game_impl_proof,
	)?
	.ok_or(Error::GameImplsMissing)?;
	let impl_address = decode_address_from_storage_value(&impl_value)?;
	if impl_address != game_config.expected_impl {
		Err(Error::GameImplMismatch {
			game_type: payload.game_type,
			actual: impl_address,
			expected: game_config.expected_impl,
		})?
	}

	// Prove the proxy account, then verify "not challenged" against its storage root.
	verify_not_challenged::<H>(
		&game_config.kind,
		root,
		payload.proxy,
		payload.proxy_account_proof,
		payload.challenge_proof,
	)?;

fn verify_not_challenged<H: Keccak256 + Send + Sync>(
	kind: &DisputeGameImpl,
	root: H256,
	proxy_address: H160,
	proxy_account_proof: Vec<Vec<u8>>,
	challenge_proof: Vec<Vec<u8>>,
) -> Result<(), Error> {
	if matches!(kind, DisputeGameImpl::OPSuccinct) {
		// OPSuccinctDisputeGame has no challenge mechanism by construction, so any game we
		// accepted as registered in the factory is unchallenged.
		return Ok(());
	}

	let proxy_storage_root =
		get_contract_account::<H>(proxy_account_proof, &proxy_address.0, root)?
			.storage_root
			.0
			.into();

	match kind {
		DisputeGameImpl::FaultDisputeGame => {
			// `claimData` is a dynamic `ClaimData[]` at `FAULT_DISPUTE_CLAIM_DATA_SLOT`. Solidity
			// stores a dynamic array's element count in the slot itself (the elements live at
			// `keccak256(slot)`). A freshly created, unchallenged game holds exactly one entry —
			// the root claim appended in `initialize()` — and every `move()` (attack or defense)
			// appends another. So `claimData.length == 1` iff the game has not been challenged.
			// Any other length (including absence, i.e. length 0 for a game that never registered
			// its root claim) is rejected.
			//
			// The MPT trie path for a direct storage slot is `keccak256(slot)`.
			let storage_key = U256::from(FAULT_DISPUTE_CLAIM_DATA_SLOT).to_big_endian();
			let trie_path = H::keccak256(&storage_key);
			let value = get_value_from_proof::<H>(
				trie_path.0.to_vec(),
				proxy_storage_root,
				challenge_proof,
			)?
			.ok_or(Error::ClaimDataSlotMissing)?;
			let raw = <alloy_primitives::Bytes as Decodable>::decode(&mut &*value)
				.map_err(|_| Error::DecodeClaimData(format!("{:?}", value)))?
				.0
				.to_vec();
			if raw.len() > 32 {
				Err(Error::ClaimDataTooLong)?
			}
			// RLP strips leading zeros from the stored length; reconstruct the uint256 and require
			// it to be exactly one.
			if U256::from_big_endian(&raw) != U256::one() {
				Err(Error::FaultDisputeGameChallenged)?
			}
			Ok(())
		},

# Fault Dispute Games

The OpStack system finalizes L2 state commitments using fraud proofs in a permissionless manner. Any bonded party can submit an L2 output root as a fault dispute game at any time.
Invalid outputs can be challenged by anyone in a permissionless manner. The challenge process involves both the proposer (who submitted the output root) and the challenger playing a fault dispute game on-chain.
If the challenger wins, the malicious output root is discarded, and the proposer's bond acts as a reward.
Different types of dispute games, defined within the dispute factory contract, can be used for validation, with the specific game determined by the initial submission and respected game types.
Unchallenged outputs are accepted as final after a designated challenge period.

pub fn update_client<H>(host: &H, msg: ConsensusMessage) -> Result<MessageResult, anyhow::Error>
where
	H: IsmpHost,

	let consensus_client_id = host.consensus_client_id(msg.consensus_state_id).ok_or(

	let trusted_state = host.consensus_state(msg.consensus_state_id)?;

		host,
		msg.consensus_state_id,
