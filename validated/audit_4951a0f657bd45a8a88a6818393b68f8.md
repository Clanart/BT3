### Title
Naive hostname regex in `isGitHubHost` lets an attacker-controlled git remote impersonate a GitHub Enterprise host and hijack the OAuth sign-in flow - (File: `app/src/lib/api.ts`)

### Summary
`isGitHubHost()` classifies a remote host as a genuine GitHub server using a substring/regex heuristic (`/(^|\.)(github)\./.test(hostname)`) *before* performing any network verification. Any hostname with a label matching `github.` (e.g. `github.attacker.com`) is trusted as GitHub without contacting it. This flaw is exercised automatically by the Git credential-helper trampoline whenever Desktop needs credentials for a remote host it doesn't already recognize, causing Desktop to launch a full "Sign in to GitHub Enterprise" OAuth flow — including opening the system browser to an attacker-chosen `login/oauth/authorize` URL — for a host the user never asked to trust.

### Finding Description
The credential path is:
1. Git needs credentials for a remote → `createCredentialHelperTrampolineHandler` → `getCredential` → `getEndpointKind` runs in `app/src/lib/trampoline/trampoline-credential-helper.ts`. [1](#0-0) 
2. When the endpoint is not dotcom/GHE/gist and no `WWW-Authenticate: realm="GitHub"` header or existing account is found, `getEndpointKind` falls through to `isGitHubHost(endpoint)`.
3. Inside `isGitHubHost`, after checking dotcom/GHE hostnames and a small hard-coded `knownThirdPartyHosts` set (`dev.azure.com`, `gitlab.com`, `bitbucket.org`, `amazonaws.com`, `visualstudio.com`), the function returns `true` for *any* hostname matching `/(^|\.)(github)\./` — with **no network request performed**: [2](#0-1) 
The real verification (a `HEAD` request checking for `x-github-request-id`) only happens later, and is skipped entirely once this regex matches. [3](#0-2) 
4. Since `isKnownThirdPartyHost` only rejects a small fixed allowlist, an attacker fully controls the rest of the domain namespace, e.g. `github.attacker.com`, `attacker-github.example` won't match but `github.example.com`, `sub.github.io`-style hosts will. [4](#0-3) 
5. With `isGitHubHost` returning `true`, `getEndpointKind` returns `'enterprise'`, and since no account exists yet for that fabricated endpoint, `getCredential` calls `ui.promptForGitHubSignIn(endpoint)`. [5](#0-4) 
6. `promptForGitHubSignIn` sees the hostname isn't `github.com`, so it calls `beginEnterpriseSignIn` + `setSignInEndpoint(origin)`, pre-filling the attacker's host and jumping straight to the Authentication step: [6](#0-5) 
7. The Authentication step's browser sign-in opens `getOAuthAuthorizationURL(endpoint, csrfToken)` — built directly from the attacker's endpoint — via `shell.openExternal`, sending the user's system browser to an attacker-controlled OAuth authorize URL that visually mimics a normal "GitHub Enterprise" sign-in Desktop itself initiated: [7](#0-6) [8](#0-7) 

The corrupted value is the boolean classification produced by `isGitHubHost`/`getEndpointKind`: it should represent "this host is a real GitHub server," but it is derived from a naive string pattern rather than an authenticated identity check, letting attacker-chosen domain labels flip it to `true`.

### Impact Explanation
This lets an attacker who merely controls a git remote/clone URL (public repo, submodule URL, or a MITM'd insecure clone) trigger, as a side effect of a routine `fetch`/`pull`/`push`, an unprompted, Desktop-initiated OAuth sign-in flow pointed at the attacker's own server. Because the flow is presented as Desktop's own trusted "Sign in to GitHub Enterprise" dialog (not a link the user clicked), users are primed to trust it and enter credentials or complete 2FA on the attacker's page, or the attacker can proxy the flow to real github.com to harvest a valid OAuth `code`/session. This matches "unauthorized OAuth ... binding" / credential exfiltration triggered purely by an attacker-controlled remote.

### Likelihood Explanation
Moderate-to-high: exploitation requires no privileged access — only that the victim clone/fetch/push against a repository whose remote hostname contains a `github.`-labeled subdomain (trivial for an attacker to register), and that Desktop doesn't already have an account/credential cached for that endpoint (the common case for a brand-new host). No certificate, TLS, or `x-github-request-id` validation is needed to reach the vulnerable branch.

### Recommendation
Remove the unauthenticated regex short-circuit in `isGitHubHost` (or move it after, and gate it behind, the actual network-based `x-github-request-id` check), and require real verification (successful GitHub-specific response header) before ever classifying an unknown third-party host as `enterprise`. At minimum, `promptForGitHubSignIn`/`beginEnterpriseSignIn` triggered via the credential-helper path should never auto-launch browser OAuth without an explicit, visible user confirmation naming the exact host being trusted.

### Proof of Concept
1. Attacker publishes/serves a git repository reachable at `https://github.attacker.com/owner/repo.git` (any HTTPS host works, no valid TLS cert from a CA required beyond what the OS trusts for outbound `git`/`fetch` — or MITM an `http://` clone during a transparent proxy).
2. Victim adds/clones this repo in GitHub Desktop and performs a `fetch`/`push` requiring auth; Git invokes the credential helper trampoline.
3. `getEndpointKind` calls `isGitHubHost('https://github.attacker.com')`; hostname matches `/(^|\.)(github)\./` and the function returns `true` without any request to the attacker's server. [2](#0-1) 
4. `getCredential` finds no existing account for the fabricated enterprise endpoint and calls `ui.promptForGitHubSignIn('https://github.attacker.com')`. [9](#0-8) 
5. Desktop shows "Sign in to your GitHub Enterprise" and, on browser sign-in, opens `https://github.attacker.com/login/oauth/authorize?client_id=...` in the system browser via `shell.openExternal`. [10](#0-9) 
6. The attacker's server serves a phishing page (or proxies to real GitHub) at that URL, harvesting credentials/OAuth code from the unsuspecting user who believes this was initiated by trusted Desktop UI, not a link they clicked.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'

const knownThirdPartyHosts = new Set([
  'dev.azure.com',
  'gitlab.com',
  'bitbucket.org',
  'amazonaws.com',
  'visualstudio.com',
])

const isKnownThirdPartyHost = (hostname: string) => {
  if (knownThirdPartyHosts.has(hostname)) {
    return true
  }

  for (const knownHost of knownThirdPartyHosts) {
    if (hostname.endsWith(`.${knownHost}`)) {
      return true
    }
  }

  return false
}
