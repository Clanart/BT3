### Title
Data race on `BidPool.auctionEntryPointVersion` allows a bidder's `AddBid` call to read a torn/stale value concurrently written by block processing - ([File: kaiax/auction/impl/bid_pool.go])

### Summary
This is the same bug class as the referenced Celo fix: a field that is normally protected by a dedicated mutex (`announceRunning`/`auctionInfoMu`) is written under lock from one goroutine (block-processing) but read without holding that lock from a different, concurrently-running goroutine (a per-transaction/per-bid hot path reachable by any auction bidder).

### Finding Description
`BidPool` protects its auction-info fields (`auctioneer`, `auctionEntryPoint`, `auctionEntryPointVersion`, `bidTxGasBuffer`) with `auctionInfoMu`. Writes go through `updateAuctionInfo`, which takes the write lock: [1](#0-0) 

Reads are supposed to go through the same lock, as done correctly in `GetAuctionEntryPointVersion` and `validateBidSigs`: [2](#0-1) [3](#0-2) 

However, `getBidTxGasLimit` takes the `RLock` only to read `bidTxGasBuffer`, releases it, and then reads `bp.auctionEntryPointVersion` directly, **without holding `auctionInfoMu`**: [4](#0-3) 

`getBidTxGasLimit` is invoked from `AddBid`, which is the entry point both for the public RPC `auction_submitBid` call (`AuctionAPI.SubmitBid`) and for the `handleBidMsg` goroutine that processes bids received from peers: [5](#0-4) [6](#0-5) [7](#0-6) 

Meanwhile, `AuctionModule.PostInsertBlock` calls `updateAuctionInfo` on every new block (writing `auctionEntryPointVersion` under `auctionInfoMu.Lock()`), running on the blockchain insertion goroutine concurrently with bidder-triggered `AddBid` calls: [8](#0-7) 

Because Go string values are two-word headers (pointer + length), an unsynchronized concurrent read/write is a data race that can yield a torn string (mismatched pointer/length) or an observably stale/inconsistent value under the memory model, exactly analogous to the `announceRunning` bool race in the referenced Celo commit — a flag/field updated under lock in one goroutine but read unlocked in a periodic/per-event handler in another.

### Impact Explanation
`auctionEntryPointVersion` selects the EIP-712 typehash/ABI encoding used by `system.EncodeAuctionCallData` to compute the intrinsic gas for a bid transaction, which is then used to set the bid's gas limit (`bid.SetGasLimit(gasLimit)`) before the bid is queued for building into the block. A torn/incorrect version value read during a race window (e.g., right when the entry point contract is upgraded/version changes at an epoch/registry-update boundary) can cause `EncodeAuctionCallData` to encode the bid data with the wrong version/ABI, producing either an error path or a corrupted/incorrect gas limit for the winning bid's settlement transaction. Under `-race`, this is flagged as an unsynchronized concurrent access on shared memory; functionally it risks state divergence between nodes if version selection differs from what the auctioneer/consensus expects, or malformed settlement of the auction bid.

### Likelihood Explanation
The race window is narrow (opens only when `updateAuctionInfo` actually changes the auction entry point version, which happens on registry/upgrade events, not every block), but the read side is on the hot path of every `AddBid` call, which is directly reachable by any external caller via `auction_submitBid` RPC or via a received p2p bid message — no privileged access required. This matches the same shape as the original bug: rare-trigger but easily reachable, and would reproduce reliably under `go test -race` with concurrent bid submission during an auction-info update.

### Recommendation
In `getBidTxGasLimit`, read `bp.auctionEntryPointVersion` (and any other auction-info fields it uses) while holding `bp.auctionInfoMu.RLock()`, consistent with `GetAuctionEntryPointVersion`/`validateBidSigs`, e.g.:
```go
bp.auctionInfoMu.RLock()
buffer := bp.bidTxGasBuffer
version := bp.auctionEntryPointVersion
bp.auctionInfoMu.RUnlock()
data, err := system.EncodeAuctionCallData(bid, version)
```

### Proof of Concept
Not independently reproducible without running `go test -race` against `kaiax/auction/impl`; however, the race is structurally provable by inspecting the code: `updateAuctionInfo` writes `bp.auctionEntryPointVersion` under `auctionInfoMu.Lock()` from the block-insertion goroutine (`PostInsertBlock`), while `getBidTxGasLimit` (called synchronously from `AddBid`, reachable from `AuctionAPI.SubmitBid` and `handleBidMsg`) reads the same field without acquiring `auctionInfoMu` at all. A concurrent test that repeatedly calls `bidPool.AddBid` from one goroutine while calling `updateAuctionInfo`/`PostInsertBlock` with a changing version string from another would trigger a `-race` detector failure on `bp.auctionEntryPointVersion`.

func (bp *BidPool) updateAuctionInfo(auctioneer common.Address, auctionEntryPoint common.Address, auctionEntryPointVersion string, bidTxGasBuffer uint64) {
	bp.auctionInfoMu.Lock()
	defer bp.auctionInfoMu.Unlock()

	if bp.auctioneer == auctioneer && bp.auctionEntryPoint == auctionEntryPoint && bp.auctionEntryPointVersion == auctionEntryPointVersion && bp.bidTxGasBuffer == bidTxGasBuffer {
		return
	}

	// Clear the existing auction pool since the auctioneer or auction entry point address is changed.
	bp.clearBidPool()

	bp.auctioneer = auctioneer
	bp.auctionEntryPoint = auctionEntryPoint
	bp.auctionEntryPointVersion = auctionEntryPointVersion
	bp.bidTxGasBuffer = bidTxGasBuffer

	logger.Info("Update auction info", "auctioneer", auctioneer, "auctionEntryPoint", auctionEntryPoint, "auctionEntryPointVersion", auctionEntryPointVersion, "bidTxGasBuffer", bidTxGasBuffer)
}

// Required mutex is locked in each function.
func (bp *BidPool) AddBid(bid *auction.Bid) (common.Hash, error) {
	if atomic.LoadUint32(&bp.running) == 0 {
		return common.Hash{}, auction.ErrAuctionPaused
	}

	if err := bp.validateBid(bid); err != nil {
		return common.Hash{}, err
	}

	if err := bp.insertBid(bid); err != nil {
		return common.Hash{}, err
	}

	gasLimit, err := bp.getBidTxGasLimit(bid)
	if err != nil {
		return common.Hash{}, err
	}
	bid.SetGasLimit(gasLimit)

	bp.newBidCh <- bid

	return bid.Hash(), nil
}

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)
}

func (a *AuctionModule) PostInsertBlock(block *types.Block) error {
	if a.Downloader.Synchronising() || !a.ChainConfig.IsRandaoForkEnabled(block.Number()) {
		atomic.CompareAndSwapUint32(&a.bidPool.running, 1, 0)
		return nil
	}

	if !a.updateAuctionInfo(block.Number()) {
		logger.Debug("stop auction since auctioneer or auction entry point is not set")
		atomic.CompareAndSwapUint32(&a.bidPool.running, 1, 0)
		return nil
	}

	atomic.CompareAndSwapUint32(&a.bidPool.running, 0, 1)

	txHashMap := make(map[common.Hash]struct{})
	for _, tx := range block.Transactions() {
		txHashMap[tx.Hash()] = struct{}{}
	}
	a.bidPool.removeOldBids(block.Number().Uint64(), txHashMap)

	return nil
}

// updateAuctionInfo updates the auctioneer address and auction entry point address for the given block number.
// It expects the `num` is after Randao fork.
// It returns true if the non-zero auctioneer address and auction entry point address are set, otherwise false.
