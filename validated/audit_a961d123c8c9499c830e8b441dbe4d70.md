### Title
Aggregate Schnorr signature forgery: `weight()` transcript omits `Rs` and public keys, letting an attacker algebraically cancel the verification equation - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::verify` derives the per-signature scalar weights `z_i` from a transcript that binds only the callers' challenges — not the nonce points `Rs` or the public keys. Because the weights are fully predictable before `Rs` are chosen, a forger can choose one `R` to algebraically cancel the entire multiexp, producing an aggregate signature that verifies for arbitrary keys/messages without knowing any private key.

### Finding Description
Half-aggregation (ePrint 2021/350) requires the aggregation weights `z_i` to bind the full statement being aggregated — i.e., `z_i = H(L, i)` where `L` commits to `(pk_i, m_i, R_i)` for every signature. In `SchnorrAggregate::verify`, the digest only receives `domain_separate(b"signatures")` plus the challenges from `keys_and_challenges`:

- `SchnorrAggregator::aggregate` appends only `challenge` (aggregate.rs:169-172); `self.sigs[i].R` is never transcribed.
- `SchnorrAggregate::verify` rebuilds the same digest: only `challenge.to_repr()` is appended (aggregate.rs:134-136); `self.Rs[i]` and `key` appear only in the multiexp `pairs`, not in the transcript.

The verification equation is `Σ_i z_i·R_i + Σ_i z_i·c_i·A_i − s·G = 0` (aggregate.rs:138-145). Since every `z_i` is computable by the prover in advance (it depends only on `dst` and the challenges), the forger fixes `Rs[1..]`, `s`, and solves for `Rs[0]`:

```
R_0 = −z_0^{-1} · ( Σ_{i≥1} z_i·R_i + Σ_i z_i·c_i·A_i − s·G )
```

Setting `s = 0`, `R_0 = −z_0^{-1}·(Σ_{i≥1} z_i·R_i + Σ_i z_i·c_i·A_i)` makes the multiexp evaluate to identity and `verify` return `true`. `Rs` are arbitrary attacker-controlled bytes via `SchnorrAggregate::read` (aggregate.rs:77-88), and `ciphersuite`'s `read_G` accepts any canonical non-torsion point — `R_0` above is a valid group element the forger can encode.

Additionally, `weight()` uses `debug_assert!` (aggregate.rs:24, 26) for its byte-length assumptions, so the <2^128 bias guarantee is unchecked in release builds — a secondary robustness gap, though not the primary flaw.

### Impact Explanation
Any consumer calling `SchnorrAggregate::verify(dst, keys_and_challenges)` accepts a forged aggregate attesting to Schnorr signatures over arbitrary messages under arbitrary victim public keys. The analog to the CVE is precise: a gate intended to restrict access (here, cryptographic authorization of "these keys signed these challenges") fails open because a required input is missing from the gating computation — exactly the missing-binding/missing-authorization class, reachable by an unprivileged party supplying untrusted bytes to `SchnorrAggregate::read`/`verify`.

### Likelihood Explanation
Exploitation requires only public inputs: the verifier's `keys_and_challenges` and a crafted `SchnorrAggregate` encoding. The forger computes `z_i` locally (deterministic transcript), performs one multiexp to solve for `R_0`, and serializes. No private key material, threshold collusion, or validator control is needed. Exploitable wherever aggregate Schnorr verification is exposed to untrusted signatures.

### Recommendation
Bind every aggregated statement into the weight transcript: in both `SchnorrAggregator::aggregate` and `SchnorrAggregate::verify`, append each `R_i` and each public key alongside the challenge before calling `weight()` (e.g., `digest.append_message(b"R", R.to_bytes()); digest.append_message(b"key", key.to_bytes());`), matching the `H(L, i)` construction of ePrint 2021/350. Replace the `debug_assert!`s in `weight()` with real assertions.

### Proof of Concept
```rust
// Given victim keys A_i and challenges c_i (i = 0..n):
let mut digest = DigestTranscript::<C::H>::new(dst);
digest.domain_separate(b"signatures");
for (_, c) in keys_and_challenges { digest.append_message(b"challenge", c.to_repr()); }

// weights are predictable: Rs/keys never enter the transcript
let zs: Vec<C::F> = (0..n).map(|_| weight::<_, C::F>(&mut digest.clone())).collect();

// choose R_1..R_{n-1} arbitrarily (e.g., generator), s = 0, solve for R_0:
//   z_0*R_0 = -( sum_{i>=1} z_i*R_i + sum_i z_i*c_i*A_i )
let mut acc = C::G::identity();
for i in 1..n { acc += zs[i] * Rs[i]; }
for i in 0..n { acc += zs[i] * cs[i] * A[i]; }
let R_0 = -acc * zs[0].invert().unwrap();

// SchnorrAggregate { Rs: [R_0, R_1, ...], s: 0 } passes verify()
// because sum z_i(R_i + c_i A_i) - 0*G == identity
```
