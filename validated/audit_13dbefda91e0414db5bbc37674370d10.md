### Title
mWOMSVBaseRewarder never forfeits rewards for users in cooldown, permanently leaking yield meant to be redistributed - (File: rewards/mWOMSVBaseRewarder.sol)

### Summary
`_calExpireForfeit` in `mWOMSVBaseRewarder.sol` is supposed to mirror `vlMGPBaseRewarder.sol`'s logic of reducing a user's claimable reward based on how much of their `mWomSV` balance is actively locked vs. in cooldown/unlocking (using `getRewardablePercentWAD`), forfeiting the unearned portion back into the reward pool for remaining stakers. Instead it hardcodes `rewardableAmount = _amount`, so `forfeitAmount` is always zero regardless of the user's cooldown state.

### Finding Description
In `vlMGPBaseRewarder.sol`, `_calExpireForfeit` computes the user's forfeitable share by querying `vlMGP.getRewardablePercentWAD(_account)`, which discounts reward eligibility for locked-token amounts that are in the process of unlocking (cooldown) [2](#0-1) . The `mWomSV` locker contract exposes the exact analogous function, `getRewardablePercentWAD`, computing a WAD percent based on `fullyInLock`, `inCoolDown`, and time-weighted cooldown progress [1](#0-0) . This function exists specifically to support forfeiture-based reward calculations for `mWomSV` holders, mirroring the `VLMGP.sol` design (`VLMGP.sol` has its own equivalent `getRewardablePercentWAD`) [4](#0-3) .

However, in `mWOMSVBaseRewarder.sol`, the counterpart `_calExpireForfeit` never calls `mWOMSV.getRewardablePercentWAD`, and instead sets `rewardableAmount = _amount` unconditionally, so `forfeitAmount = _amount - rewardableAmount` is always `0` [3](#0-2) . This is called from `_sendReward`, which is invoked whenever a user calls `getReward`/`getRewards` through `MasterMagpie` [5](#0-4) .

The net effect: every `mWomSV` reward-token holder, including those with tokens sitting in the unlock cooldown queue (who should have a reduced rewardable percentage and forfeit part of their yield back to the pool via `_queueNewRewardsWithoutTransfer`), instead receives 100% of their accrued rewards with zero forfeiture, every single time.

### Impact Explanation
This is a direct, permanent misallocation of yield among unprivileged wallets: users who initiate `startUnlock` on `mWomSV` (i.e., move tokens into cooldown) are supposed to forfeit a proportional share of rewards back into the pool for the benefit of users who remain fully locked, per the `getRewardablePercentWAD` design intent shown in the sibling `vlMGP`/`vlMGPBaseRewarder` implementation. Because the forfeit calculation is broken, that yield is never clawed back and is instead paid out in full to users who should have partially forfeited it. This constitutes theft of yield that should have accrued to other unprivileged stakers who keep their tokens fully locked, and it is a permanent, systemic accounting defect reachable by any ordinary wallet interacting with `startUnlock`/`getReward` — no privileged role is required to trigger or benefit from it.

### Likelihood Explanation
High likelihood: this triggers on the default reward-claim path (`getReward`/`getRewards` → `_sendReward` → `_calExpireForfeit`) for every `mWomSV` staker with cooldown activity, requiring no special conditions beyond normal use of `startUnlock` followed by a reward claim.

### Recommendation
Update `_calExpireForfeit` in `mWOMSVBaseRewarder.sol` to mirror `vlMGPBaseRewarder.sol`: compute `rewardableAmount = _amount * mWOMSV.getRewardablePercentWAD(_account) / 1e18` instead of hardcoding `rewardableAmount = _amount`.

### Proof of Concept
1. User A locks `mWomSV` and calls `startUnlock` to move part of their balance into cooldown (`mWomSV.startUnlock`) [6](#0-5) . Per `getRewardablePercentWAD`, their rewardable percent should now be less than 100% [1](#0-0) .
2. Reward tokens accrue to User A in `mWOMSVBaseRewarder` via `_earned`/`_updateFor` based on their full `balanceOf` (locked + cooldown) [7](#0-6) .
3. User A claims rewards through `MasterMagpie` → `getReward`/`getRewards` → `_sendReward` → `_calExpireForfeit(_account, userRewards[...])` [5](#0-4) .
4. Because `_calExpireForfeit` never reads `getRewardablePercentWAD`, `forfeitAmount` is `0` regardless of the user's cooldown fraction, and User A receives 100% of `userRewards`, instead of the reduced amount that `vlMGPBaseRewarder.sol`'s equivalent logic would have enforced [2](#0-1) .

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalmWomSV = fullyInLock + inCoolDown;
        if (userTotalmWomSV == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalmWomSV;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalmWomSV / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalmWomSV;
                }

            }
        }

        return percent;
    }

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }
