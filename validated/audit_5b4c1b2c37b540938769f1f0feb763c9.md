## Analysis

The external report's core broken invariant is: **a user has already paid an irreversible cost (entropy fee / burned tokens) for an action, but the completion or refund callback that finalizes or reverses that cost is gated by a `whenNotPaused` modifier — so a pause window between the initial payment and the callback either burns funds permanently or leaves them stuck with no automatic recovery.**

## Local Analog Found

`HyperFungibleToken.sol` (and its upgradeable/wrapped variants) reproduce exactly this pattern in the ISMP request lifecycle.

### Title
Refund path `onPostRequestTimeout` gated by `whenNotPaused` locks already-burned tokens when the contract is paused - (File: `sdk/packages/core/contracts/apps/HyperFungibleToken.sol`)

### Summary
`send()` burns the caller's tokens immediately and dispatches a cross-chain POST request [1](#0-0) . The only two paths that can ever restore value to the user — successful delivery via `onAccept` on the destination, or a timeout refund via `onPostRequestTimeout` on the source — are both gated by `whenNotPaused` [2](#0-1) [3](#0-2) . If the contract is paused at any point between the burn and delivery/timeout resolution, the funds are unrecoverable until an admin unpauses — exactly the "already paid, callback blocked" defect described in the report.

### Finding Description
The mint side (`onAccept`) and the refund side (`onPostRequestTimeout`) are both marked `whenNotPaused`: [4](#0-3) 

The ISMP host's `dispatchTimeOut` for `PostRequestTimeout` calls the app's `onPostRequestTimeout` via a low-level `.call`, and only clears the request commitment (releasing relayer-fee refund) if that call succeeds; otherwise it restores the commitment for retry [5](#0-4) . Because `HyperFungibleToken.onPostRequestTimeout` reverts while paused (via `whenNotPaused`), any relayer/permissionless retry of the timeout submission during the pause window fails, and the user's already-burned tokens cannot be re-minted back to them.

Simultaneously, `onAccept` on the destination is also `whenNotPaused` [2](#0-1) , so if the destination token contract is paused, the mint side also reverts and the message is only retryable until the timeout expires (per the documented retry/timeout semantics) [6](#0-5) . If the pause on the source chain persists past that timeout window, neither the mint nor the refund path can execute: the tokens are burned, never minted on the destination, and the timeout refund also reverts — leaving the user's value stuck in limbo with no path to resolution besides waiting for an unpause, unlike the entropy report's manual `refundGame` there is not even an admin-triggered recovery function here.

### Impact Explanation
This is a direct fund-lock / loss-of-funds class issue matching the bounty's accepted categories ("stealing or loss of funds", "logic attacks"). A user's tokens are burned on `send()` [7](#0-6)  and become unrecoverable for the duration of any pause overlapping the delivery/timeout window, with no permissionless or admin recovery function present in the contract to compensate the user in the interim.

### Likelihood Explanation
Pausing is a normal operational action (emergency response, migrations) documented as pausing "all cross-chain `send()` and `onAccept()`" [8](#0-7) . Any user whose `send()` is in flight (already burned, not yet delivered or timed out) when the admin pauses the contract is affected — no attacker action, malicious relayer, or governance compromise is required; it triggers purely from the intersection of normal pause operations and normal in-flight transfers.

### Recommendation
Do not gate `onAccept`/`onPostRequestTimeout` refund/mint completion paths with `whenNotPaused` when the corresponding debit (`_burn`) already occurred unconditionally. Either: (1) remove `whenNotPaused` from `onPostRequestTimeout` so refunds always succeed regardless of pause state (pausing should stop new burns via `send()`, not already-committed refunds), or (2) add an explicit recovery mechanism allowing users to claim their refund once unpaused, independent of relayer retry.

### Proof of Concept
1. User calls `send()`, burning `SEND_AMOUNT` tokens and dispatching a POST request [7](#0-6) .
2. Admin calls `pause()` before the request is delivered or times out.
3. The destination `onAccept` call reverts while paused, per the existing test `testOnAcceptRevertsWhenPaused` [9](#0-8) , so no mint occurs, and retries continue failing until either unpause or timeout.
4. If the timeout elapses while the source contract remains paused, a relayer submits the timeout proof; `EvmHost.dispatchTimeOut` invokes `onPostRequestTimeout`, which reverts due to `whenNotPaused` [3](#0-2) ; the commitment is restored for retry per `EvmHost.sol` lines 895-899 [10](#0-9) .
5. Until the admin unpauses, the user has burned tokens with zero balance on either chain and no way to recover them.

```text
    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost whenNotPaused {
        PostRequest calldata request = incoming.request;

        bytes memory expectedSource = _supportedChains[request.source];
        if (expectedSource.length == 0) revert UnsupportedChain();
        if (keccak256(request.from) != keccak256(expectedSource)) revert UnauthorizedSource();

        Message memory message = abi.decode(request.body, (Message));
        address beneficiary = _toAddr(message.to);
        _mint(beneficiary, message.amount);

        if (message.data.length > 0) {
            ICallDispatcher(_dispatcher).dispatch(message.data);
        }

        emit Received({
            from: message.from,
            to: beneficiary,
            source: string(request.source),
            amount: message.amount
        });
    }

    /**
     * @notice Handles timeout of a previously dispatched cross-chain transfer
     * @dev Called by the ISMP host when a sent message times out without being delivered.
     * Re-mints the burned tokens back to the original sender as a refund.
     * @param incoming The timed-out POST request and the relayer that submitted the timeout proof
     */
    function onPostRequestTimeout(PostRequestTimeout memory incoming) external override onlyHost whenNotPaused {
        Message memory message = abi.decode(incoming.request.body, (Message));
        address refundee = _toAddr(message.from);
        _mint(refundee, message.amount);
        emit Refunded({to: refundee, amount: message.amount});
    }
```

```text
    function dispatchTimeOut(
        PostRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onPostRequestTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit PostRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }
```
