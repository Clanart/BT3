Let me look at the transaction construction and fee/change math in the in-scope bitcoin wallet code.### Title
Per-block output accumulation lets a later transaction's `InInstruction` data overwrite an earlier depositor's external output - (File: processor/src/networks/bitcoin.rs)

### Summary
The original finding's class is an accounting formula that misses an injected contribution, letting a deposit be double-counted/stolen. The Serai analog lives in `Bitcoin::get_outputs`: the `outputs` vector is declared once per *block* and accumulates across transactions, but the code that stamps `presumed_origin` and attaches `data` (the parsed `InInstruction`) iterates over **all** accumulated outputs each time a later transaction produces any output. An attacker's transaction placed after a victim's deposit in the same block rewrites the victim output's instruction/origin — Serai's accounting applies the wrong contribution metadata to a deposit it already counted.

### Finding Description
`get_outputs` builds `outputs` once per block, then loops `for tx in &block.txdata[1 ..]` pushing scanned outputs into that shared vec (line 689-699). After each tx, if `outputs` is non-empty (which it remains once any earlier tx contributed an output — the check is `outputs.is_empty()`, not "this tx produced outputs"), it computes `presumed_origin` from `tx.input[0]` and `data` from `Self::extract_serai_data(tx)`, then does `for output in &mut outputs { if kind == External { output.data = data } output.presumed_origin = presumed_origin }` (lines 702-736). Because `outputs` still contains earlier transactions' outputs, every subsequent tx that yields at least one scanned output overwrites all prior External outputs' `data` and every output's `presumed_origin`. These outputs feed `ScannerEvent::Block` → `scanner_event_to_multisig_event` → `instruction_from_output`, which mints/routes funds per the (now attacker-controlled) `InInstruction`. ### Impact Explanation
An attacker who gets a transaction paying any Serai-scanned script (external, branch, change, or forward addresses are all publicly derivable via `scanner(key)`/`hash_to_F` offsets, lines 314-346) into the same block as, and after, a victim's deposit can overwrite the victim's `External` output `data` with the attacker's own `InInstruction` (e.g., crediting sriXYZ to the attacker's account or refunding to an attacker address). The victim's real deposit is still counted/spendable, but its credited instruction belongs to the attacker — the contribution is effectively stolen, mirroring H-08's "vault steals the prize token contribution". Impact is a direct fund misappropriation — High. [4](#0-3) 

### Likelihood Explanation
The attacker only needs their transaction to appear later in the same block as a victim deposit. They can observe the mempool and submit their tx; while ordering is miner-chosen, the attacker can attempt this repeatedly at the cost of a normal transaction fee — no privileged position, no collusion required. Deposits are frequent events, so the race is winnable probabilistically.

### Recommendation
Move the `outputs` vector inside the per-transaction loop (or collect `(tx, output)` pairs), so `presumed_origin` and `data` are only applied to outputs actually produced by that transaction. Alternatively index origin/data assignment by the tx that produced the output.

### Proof of Concept
1. Victim broadcasts tx V paying Serai's external address with an `InInstruction` crediting the victim.
2. Attacker sees V in mempool and broadcasts tx A paying Serai's external (or any registered-offset) address, with attacker's `InInstruction`, arranged to land in the same block after V.
3. `get_outputs`: V pushes the victim External output; A pushes the attacker output. On A's iteration, `for output in &mut outputs` sets the victim output's `data` to attacker's instruction and `presumed_origin` to A's input-0 address.
4. `scanner_event_to_multisig_event` processes the victim output under the attacker's instruction; the victim's BTC is received but credited/routed to the attacker. [5](#0-4)
