### Title
App Proxy request signatures accept indefinite replay due to missing timestamp/freshness check - ([File: lib/shopify_app/controller_concerns/app_proxy_verification.rb])

### Summary
`ShopifyApp::AppProxyVerification` verifies that an inbound App Proxy request's `signature` query parameter matches an HMAC computed over the remaining query parameters (which include a Shopify-supplied `timestamp`), but it never checks that the `timestamp` is recent. Because App Proxy URLs are delivered to a storefront visitor's browser as ordinary, unauthenticated navigation (they are not secret to the requester), any anonymous actor who has ever seen a valid, signed App Proxy request can replay that exact query string indefinitely, and the verification will always accept it as genuine.

### Finding Description
`AppProxyVerification#verify_proxy_request` calls `query_string_valid?`, which strips out the `signature` param, recomputes an HMAC-SHA256 over the sorted remaining params (which Shopify populates with `shop`, `path_prefix`, `timestamp`, etc.) using the app's shared secret, and compares it to the supplied `signature`: [1](#0-0) 

There is no check anywhere in this concern (or elsewhere in the gem) that the `timestamp` query parameter is within an acceptable freshness window. This mirrors the reported bug class exactly: a value that legitimately exists in the signed payload for anti-replay purposes (`timestamp`) is never validated for recency, so once a valid `(query_string, signature)` pair exists it remains valid forever. The test suite confirms only signature correctness is checked, never staleness of the `timestamp=1466106083` fixture value (a date years in the past) which passes validation: [2](#0-1) 

Unlike webhook HMAC verification (`PayloadVerification#hmac_valid?`), which is scoped to server-to-server delivery, App Proxy requests are proxied through the storefront and rendered/fetched in the context of an end-user's browser session — the full signed URL (including `signature` and `timestamp`) is visible to that browser (e.g., via network inspection, browser history, referrer headers, shared/cached links, corporate proxies, etc.) and can therefore be captured and replayed by any unrelated, unauthenticated party, not just the app or Shopify. [3](#0-2) 

### Impact Explanation
Any app that relies on the App Proxy signature verification alone to authorize an action considers a replayed request as if it were sent live by Shopify on behalf of the shop/storefront visitor "right now." If application logic behind the App Proxy performs stateful or session/time-sensitive operations (e.g., "one-time" discount redemption, form submissions, cart mutations, review submissions as shown in the generator's sample `ReviewsController`), an attacker can resubmit an old, captured, but still cryptographically "valid" request at will, at any point in the future, producing an accepted forged/stale signed request. This is analogous to the reported class of bug where a signed object lacking a nonce/timestamp/cycle check can be replayed to force unwanted, persistent state changes. [4](#0-3) 

### Likelihood Explanation
Exploitation requires only that the attacker previously observe one valid, signed App Proxy request URL — trivial for any storefront visitor, since these requests are unauthenticated and visible in the browser. No secret or credential leak is required; the shared secret itself is never exposed. This makes exploitation straightforward for any unrelated, anonymous party who has interacted with a shop's storefront app proxy endpoint at least once.

### Recommendation
Add a required freshness check for the `timestamp` parameter in `query_string_valid?`/`verify_proxy_request` (e.g., reject if `Time.now.to_i - timestamp.to_i` exceeds a small tolerance window, such as a few minutes), and document that App Proxy Controllers must be idempotent-safe or use additional nonce tracking if they perform state-changing actions.

### Proof of Concept
1. Attacker observes any legitimate App Proxy request made by a storefront visitor's browser to `https://example.com/app_proxy/basic?shop=some-shop.myshopify.com&path_prefix=%2Fapps%2Fmy-app&timestamp=1466106083&signature=f5cd7233...` (visible via browser devtools/network history/shared link/proxy logs).
2. At any later time, attacker replays the exact same URL/query string.
3. `query_string_valid?` recomputes the same HMAC over the same params and it matches, so `verify_proxy_request` allows the request through, exactly as demonstrated by the passing test case using a fixed, non-expiring `timestamp`: [5](#0-4)

    def verify_proxy_request
      head(:forbidden) unless query_string_valid?(request.query_string)
    end

    private

    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end

    def calculated_signature(query_hash_without_signature)
      sorted_params = query_hash_without_signature.collect { |k, v| "#{k}=#{Array(v).join(",")}" }.sort.join

      OpenSSL::HMAC.hexdigest(
        OpenSSL::Digest.new("sha256"),
        ShopifyApp.configuration.secret,
        sorted_params,
      )
    end
```

## Verify HTTP requests sent via an app proxy

See [`ShopifyApp::AppProxyVerification`](/lib/shopify_app/controller_concerns/app_proxy_verification.rb).

The engine provides a mixin for verifying incoming HTTP requests sent via an App Proxy. Any controller that `include`s `ShopifyApp::AppProxyVerification` will verify that each request has a valid `signature` query parameter that is calculated using the other query parameters and the app's shared secret.

### Recommended usage of `ShopifyApp::AppProxyVerification`

The App Proxy Controller Generator automatically adds the mixin to the generated app_proxy_controller.rb
Additional controllers for resources within the App_Proxy namespace, will need to include the mixin like so:

```ruby
# app/controllers/app_proxy/reviews_controller.rb
class ReviewsController < ApplicationController
  include ShopifyApp::AppProxyVerification
  # ...
end
```
