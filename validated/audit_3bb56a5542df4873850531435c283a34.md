**Analysis:**

`BribeRewardPool` overrides both `balanceOf` and `totalStaked` together, consistently pointing to the same private ledger (`_balances`/`totalSupply`) rather than the MasterMagpie-backed ledger used in the base `BaseRewardPoolV2` implementation. [1](#0-0)  Because Solidity resolves `virtual` function calls dynamically, when the inherited `_provisionReward` (called from `donateRewards`) invokes `totalStaked()`, it correctly dispatches to `BribeRewardPool`'s override, not the base implementation. [2](#0-1)  Likewise `earned` calls `balanceOf(_account)`, which also dispatches to the overridden version. [3](#0-2)  So there is no divergence between the balance source used for distribution accounting and the one used for reward-earning accounting within `BribeRewardPool` — both consistently use `_balances`/`totalSupply`.

When `totalStaked() == 0` (all voters unvoted), `_provisionReward` takes the branch that adds `_amountReward` into `rewardInfo.queuedRewards` without touching `rewardPerTokenStored`. [4](#0-3)  This is the designed safe-guard against division by zero / reward loss, not a bug — queued rewards get folded into the next `_provisionReward` call once `totalStaked() > 0` again. [5](#0-4)  No user's `userRewards[_rewardToken][account]` state is altered by `donateRewards`, since that function only calls `_provisionReward`, which transfers tokens from `msg.sender` into the pool and updates only pool-level `Reward` struct fields, not any per-account mapping. [6](#0-5)  An attacker calling `donateRewards` can only give away tokens they own into the contract; there is no path by which this call extracts funds, corrupts another account's `earned()` value, or causes insolvency.

The premise of the question — that `balanceOf`/`totalStaked` overrides diverge from "inherited" MasterMagpie semantics causing an exploitable mismatch — does not hold, because the override pair is applied consistently and Solidity's virtual dispatch ensures all inherited code paths use the overridden ledger uniformly.

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;

        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingTokenDecimals) /
                totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
