### Title
Unauthenticated shop-domain param drives real Admin API calls using another shop's stored access token in `EnsureInstalled` - (File: app/controllers/concerns/shopify_app/ensure_installed.rb)

### Summary
`ShopifyApp::EnsureInstalled` derives the acting shop entirely from the unauthenticated `shop` query-string parameter and, when the legacy (non-token-exchange) auth strategy is active and the request isn't flagged as loaded directly from Shopify Admin, automatically loads that shop's stored offline session and uses it to make a live Shopify Admin API call. This is structurally the same bug class as the reported "payer not tied to msg.sender" issue: the identity used to authorize/attribute an action (`shop`) is a caller-supplied value that is never tied to who is actually making the request.

### Finding Description
`EnsureInstalled#current_shopify_domain` resolves the shop purely from `params[:shop]`: [1](#0-0) 

`installed_shop_session` then loads the *stored* session (containing the real offline access token) for that attacker-chosen shop domain: [2](#0-1) 

When the app is not using the newer token-exchange strategy, the concern registers `check_shop_known` and `validate_non_embedded_session` as `before_action`s automatically: [3](#0-2) 

`validate_non_embedded_session` builds a real `ShopifyAPI::Clients::Rest::Admin` client using `installed_shop_session` (i.e., the *victim* shop's own access token) and calls the Admin API, unless the request is detected as `loaded_directly_from_admin?`: [4](#0-3) 

`loaded_directly_from_admin?` only returns true if the app is configured as embedded **and** the request explicitly carries `embedded=1`: [5](#0-4) 

Any anonymous caller can simply omit `embedded=1` from the query string to skip that guard, causing `validate_non_embedded_session` to run and to make a live Admin API call using a store's real, previously-stored token — purely because the caller supplied that store's domain in the `shop` param. The docs explicitly acknowledge this concern "does not authenticate the request" and that the shop parameter is "user-controllable," warning developers not to use it for API calls — but the built-in `validate_non_embedded_session` before_action inside the concern itself does exactly that, unconditionally for any controller that includes `EnsureInstalled` (e.g. the generated, publicly-reachable `HomeController`): [6](#0-5) [7](#0-6) 

I was not able to fully confirm (index does not expose it) what the default value of `use_new_embedded_auth_strategy?`/`embedded_app?` is for a freshly generated app, so it is uncertain whether this legacy code path is on by default versus only reachable for apps still using the older (pre-token-exchange) OAuth strategy — this would need to be verified against `lib/shopify_app/configuration.rb` directly (index truncation prevented a full view of that file's defaults).

### Impact Explanation
An anonymous request to any endpoint using `EnsureInstalled` (typically the app's home/index route, which is public by design) with `?shop=<any-installed-shop>.myshopify.com` and no `embedded=1` causes the app server to:
- Load and use a third party's real stored offline access token to call the Shopify Admin API on the attacker's behalf, without that shop's knowledge or consent.
- Consume that shop's Admin API rate-limit budget.
- Act as a shop/domain oracle: response behavior (200 vs redirect-to-login on 401) leaks whether a given `myshopify.com` domain has the app installed and whether its stored token is still valid, enabling enumeration of the app's install base.
This mirrors the reported bug's core harm: a caller-supplied identity field, not verified against the actual requester, is trusted to select whose "account"/credentials are used for an action — leading to third-party resource consumption/spam triggered by an unrelated, unauthenticated party.

### Likelihood Explanation
High reachability: the vulnerable before_action chain is wired in automatically by including `EnsureInstalled` (no opt-in required beyond using the documented, recommended "installation check" concern), and the guard that would skip it (`embedded=1`) is trivial for an anonymous caller to simply not send. The only precondition is the app using the legacy (non-token-exchange) auth strategy, which the gem still supports and documents as the default flow in several code paths.

### Recommendation
- Do not perform any Admin API call (`validate_non_embedded_session`) based solely on an unauthenticated `shop` query parameter. Either remove this behavior from `EnsureInstalled` (matching its documented "installation check only, no API calls" contract) or gate it behind actual authentication of the requester (session token / cookie), analogous to requiring `request.payer == msg.sender`.
- If a lightweight "is this shop currently valid" check is required, it should be performed only within `EnsureHasSession`-protected, authenticated flows, not as a default before_action on an unauthenticated concern.

### Proof of Concept
1. Configure an app with `embedded_app? == true` and the legacy (non-token-exchange) OAuth strategy, using the generated `HomeController` which includes `ShopifyApp::EnsureInstalled` (see `lib/generators/shopify_app/home_controller/templates/unauthenticated_home_controller.rb`).
2. As an anonymous, unrelated user, send `GET /?shop=victim-shop.myshopify.com` (no `embedded=1`, no session cookie, no Authorization header).
3. `check_shop_domain` and `check_shop_known` resolve `victim-shop.myshopify.com` purely from the query string and load its stored offline session via `installed_shop_session`.
4. `loaded_directly_from_admin?` is false (no `embedded=1` sent), so `validate_non_embedded_session` executes `ShopifyAPI::Clients::Rest::Admin.new(session: installed_shop_session).get(path: "shop")`, making a real Admin API call using `victim-shop`'s stored access token, triggered entirely by the attacker's unauthenticated request.

```markdown
##### `EnsureInstalled` — Installation Check Only
Use [EnsureInstalled](https://github.com/Shopify/shopify_app/blob/main/app/controllers/concerns/shopify_app/ensure_installed.rb) only for unauthenticated entry points, such as serving your embedded app's frontend shell. This concern checks whether the app is installed on the shop provided in the `shop` query string parameter. If the app is not installed, the request is redirected to login or the `embedded_redirect_url`.

> ⚠️ **This concern does not authenticate the request.** The `installed_shop_session` helper resolves the session from the user-controllable `shop` query parameter — it does not verify who is making the request. Do not use `EnsureInstalled` or `installed_shop_session` for any action that accesses shop data or makes Shopify API calls. Use `EnsureHasSession` instead.
```

```ruby
class HomeController < ApplicationController
  include ShopifyApp::EmbeddedApp
  include ShopifyApp::EnsureInstalled
  include ShopifyApp::ShopAccessScopesVerification

  def index
    if ShopifyAPI::Context.embedded? && (!params[:embedded].present? || params[:embedded] != "1")
      embedded_app_url = safe_embedded_app_url(params[:host])
      redirect_url = embedded_app_url ? embedded_app_url + request.path : ShopifyApp.configuration.root_url
      redirect_to(redirect_url, allow_other_host: true)
    else
      @shop_origin = current_shopify_domain
      @host = params[:host]
    end
  end
end
```
