### Title
PedPoP encrypted-share PoP does not bind the recipient, allowing replay of an honest sender's `EncryptedMessage` to a different recipient and framing the honest sender as faulty - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
`pop_challenge` binds the DKG context, the per-message key, the sender index, and the ciphertext — but not the intended recipient or the recipient's encryption key. The ChaCha20 key is derived solely from `ecdh(recipient_enc_priv, msg.key)` with a static IV (`cipher`), so an `EncryptedMessage` that was honestly produced for recipient Bob can be replayed by any observer to recipient Dave. Dave's `calculate_share` decrypts it to garbage, produces a *valid* `EncryptionKeyProof`, and `blame_internal` then attributes fault to the honest sender Alice. This is the unprivileged-input analog of the reported information/attribution disclosure class: attacker-controlled bytes fed to `EncryptedMessage::read` → `calculate_share`/`blame` cause an incorrect, security-relevant verdict against a party that behaved correctly.

### Finding Description
In `encrypt`, the sender signs a PoP over `pop_challenge(context, pub_nonce, pub_key, from, msg)` — `from` is the sender only (crypto/dkg/pedpop/src/encryption.rs:302-324, 161-165). The decryption path `Encryption::decrypt` computes `key = ecdh(self.enc_key, msg.key)` and immediately stream-decrypts before any identity/recipient check (lines 469-501). Because neither the transcript context nor the PoP commits to the recipient's `enc_key`, a copied message `(key, pop, msg)` is entirely well-formed under a different recipient: the PoP verifies (sender bound correctly), the ECDH just yields the wrong key.

Then in `KeyMachine::calculate_share` (crypto/dkg/pedpop/src/lib.rs:476-499):
1. Decrypted bytes fail `C::F::from_repr` → `PedPoPError::InvalidShare { participant: l = Alice, blame: Some(proof) }` where `proof` is a legitimately valid `EncryptionKeyProof` under *Dave's* decryption key.
2. `BlameMachine::blame_internal` (lib.rs:575-609) re-decrypts with `decrypt_with_proof` — the DLEq verifies (it binds `enc_keys[recipient]` = Dave's key, which is genuinely the key used), the plaintext is non-canonical → returns `sender` = Alice.
3. Every participant running `AdditionalBlameMachine::blame` reaches the same conclusion: honest Alice is slashed.

The code comments acknowledge the sender-side variant of this attack (lines 84-90: Eve claiming Alice's key) but the recipient binding that would prevent the complementary replay is absent — the transcript has no `append_message(b"recipient", ...)` and no recipient `enc_key` in `pop_challenge` or `cipher`.

### Impact Explanation
An unprivileged observer of the (authenticated but broadcast) DKG transcript can take any honest participant's encrypted share intended for one recipient and deliver it to another participant (or to an `AdditionalBlameMachine` evaluator). The honest sender is deterministically blamed for "sending" a non-canonical share they never sent, since blame resolution cryptographically "confirms" the message decrypts to garbage under the stated recipient. In Serai's deployment this maps to fatal slashing of an honest validator's bond and abort of key generation — attribution of fault to the wrong party via attacker-supplied message bytes.

### Likelihood Explanation
Reachable with only public protocol data: the `EncryptedMessage` is transmitted over the external authenticated channel exactly as documented, and replay requires no key knowledge, no threshold, and no compromised participant — any party able to inject a message to a DKG participant (or submit a `VerifyBlame`) suffices. Deterministic, not probabilistic.

### Recommendation
Bind the recipient in both layers: add `transcript.append_message(b"recipient", recipient_enc_key.to_bytes())` (and/or recipient index) to `pop_challenge` and to the `cipher` context, so a message valid for Bob cannot be presented as a message to Dave; and/or have `blame_internal` reject messages whose PoP recipient differs from the accusing recipient.

### Proof of Concept
1. Alice encrypts share s_i to Bob: `EncryptedMessage { key: K, pop: sign(k, challenge(ctx, R, K, Alice, c)), msg: c = share ⊕ stream(ecdh(k, B)) }`.
2. Attacker relays the identical byte blob to Dave as "Alice's share to Dave". `EncryptedMessage::read` succeeds; PoP verifies (challenge binds only sender/ciphertext).
3. Dave decrypts with `ecdh(d, K) ≠ ecdh(k, B)`-derived key → non-canonical scalar → `InvalidShare { participant: Alice, blame: Some(valid proof for Dave's key) }`.
4. `blame(Alice, Dave, msg, proof)` → `decrypt_with_proof` succeeds (DLEq valid for Dave) → `from_repr` fails → returns `Alice`. All evaluators slash honest Alice.
