### Title
Missing identity-element rejection on FROST nonce commitments lets a participant force a binding-factor-independent aggregate nonce - (File: crypto/frost/src/nonce.rs)

### Summary
The external report concerns an input-filtering blacklist that misses entries, letting dangerous inputs pass validation. The structural analog in Serai is FROST preprocess validation: `Commitments::read` / `GeneratorCommitments::read` accept the group identity element for nonce commitments `D_i` and `E_i`, because `C::read_G` only enforces canonicality, not non-identity. FROST (RFC 9591 §7.2, and the checks the Zcash/SEC frost implementations added after their audits) requires aborting on identity nonce commitments; Serai's validation "list" is missing that entry, so the hostile bytes flow unimpeded into `BindingFactor::bound`/`nonces`.

### Finding Description
`GeneratorCommitments::read` reads two points via `Curve::read_G` with no additional validation [1](#0-0) . `Ciphersuite::read_G` rejects only non-canonical encodings; the identity element is a canonical encoding and is accepted [2](#0-1) . `Commitments::read` performs no semantic validation either [3](#0-2) . `SignMachine::read_preprocess` feeds attacker-controlled bytes straight into this path [4](#0-3) .

An unprivileged cosigner who sends a preprocess with `E_i = identity` makes their bound nonce commitment `D_i + rho_i * E_i = D_i` — completely independent of the binding factor `rho_i` [5](#0-4) . With `D_i = identity` as well, the participant contributes nothing to the aggregate nonce `R` while still being counted as a signer [6](#0-5) . Neither `sign` nor `complete` ever inspect the commitments for identity [7](#0-6) .

### Impact Explanation
The binding factor is the mechanism that ties each participant's effective nonce to the (message, participant-set, commitments) transcript, defeating rogue-contribution/ROS-style nonce manipulation. A commitment pair `(identity, E_i)` or `(D_i, identity)` collapses a participant's contribution to a value either fixed before `rho` exists or fully attacker-chosen (`rho * E_i` alone). In concurrent signing sessions this restores precisely the freedom the binding factor exists to remove: the attacker can align their contribution to a target aggregate `R` after observing other preprocesses within the same epoch, undermining the one-more-unforgeability argument of FROST and enabling signature forgery in the parallel-session (ROS) setting that `hash_msg`-bound `rho` was designed to prevent. At minimum it silently produces invalid or attacker-biased signatures on messages the honest set intended to sign. It is classified High rather than Critical because weaponizing a full forgery requires controlling scheduling across parallel sessions, not just a single preprocess.

### Likelihood Explanation
The attack surface is fully reachable by an unprivileged party: any cosigner in a signing set serializes arbitrary commitment bytes into its preprocess, which is decoded by the identity-tolerant `read_preprocess` → `Commitments::read` → `read_G` path. No honest-party misconfiguration is needed; the check that RFC 9591 marks mandatory is simply absent from the code.

### Recommendation
Reject identity (and, for full alignment with hardened implementations, small-order) elements in `Commitments::read` / `GeneratorCommitments::read`, e.g. `if bool::from(point.is_identity()) { Err(io::Error::other("identity nonce commitment")) }`, or have `Curve::read_G` take a `must_be_non_identity` flag used by all commitment/key deserialization paths. Alternatively validate in `AlgorithmSignMachine::sign` when building `B`, before `B.nonces` is computed.

### Proof of Concept
```rust
// Attacker participant l crafts a preprocess whose commitments are identity:
// For each nonce and generator, write two encodings of C::G::identity()
// (e.g., 32 zero bytes for Ristretto/secq "01..00" identity encodings
// that round-trip through GroupEncoding).
let mut buf = vec![];
for _ in 0 .. (2 * num_nonces * num_generators) {
    buf.extend_from_slice(C::G::identity().to_bytes().as_ref());
}
// Prepend/append the addendum bytes as expected by read_preprocess.
// Honest signer j calls:
machine.read_preprocess(&mut &buf[..])?; // succeeds: no identity check
// Then sign() inserts it into B; the bound contribution
//   D_l + rho_l * E_l = identity + rho_l * identity = identity
// is independent of the binding factor and of everything rho commits to.
```

Honest verification of the accept path: `read_G` errors only on `from_bytes` failure or non-canonical round-trip [8](#0-7) , and the identity encoding round-trips canonically, so the crafted preprocess is accepted and used in `sign` [9](#0-8) .

Caveat: I verified the missing check and reachability within the available search scope; I could not enumerate every `Curve` implementation to confirm none overrides `read_G` to add an identity rejection, but the default trait implementation used by the in-scope ciphersuites does not.

    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
