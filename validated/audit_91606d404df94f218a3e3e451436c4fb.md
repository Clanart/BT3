### Title
Attacker-controlled `WWW-Authenticate` header spoofs GitHub host classification, triggering Desktop's trusted sign-in UI for an untrusted remote - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
The original report's broken invariant is: a piece of attacker-influenced input (the credential query) is used to make a trust/consent decision, and the resulting confirmation/consent UI does not make clear to the user what is actually being granted, letting a malicious actor obtain broader access than the user believes they're allowing. The closest verified analog in GitHub Desktop is in the Git credential-helper trampoline, where the *classification* of a remote host as a trusted "GitHub" endpoint is derived from a header value that is fully controlled by the remote server (or a MITM proxy on that connection), not from any Desktop-owned trust store.

### Finding Description
When Git needs credentials for a host, it invokes Desktop's credential helper trampoline, which parses the credential request in `getEndpointKind`: [1](#0-0) 

Specifically, if the credential request contains a `wwwauth[...]` entry (populated by Git directly from the `WWW-Authenticate` response header sent by the remote server during an HTTP 401 challenge) containing the substring `realm="GitHub"`, Desktop classifies the endpoint as `'enterprise'` regardless of the actual hostname: [2](#0-1) 

This classification feeds directly into `getCredential`, which — when no stored account matches that host — invokes `ui.promptForGitHubSignIn(endpoint)` using the attacker-supplied `endpoint`: [3](#0-2) 

`promptForGitHubSignIn` starts Desktop's native, trusted GitHub/GitHub-Enterprise sign-in flow against that same attacker-controlled origin: [4](#0-3) 

The invariant that should hold — "Desktop only offers its native GitHub sign-in UI for hosts it has independently verified as GitHub(.com)/GHE (e.g., via `isGitHubHost`'s API probe)" — is bypassed by the `wwwauth[]` fast path, which trusts a value that originates entirely from the remote/attacker's HTTP response rather than from any Desktop-side verification.

### Impact Explanation
An attacker who controls a git remote, or sits as a proxy/MITM on a plain HTTP(S) connection the user fetches/clones from, can return a crafted `WWW-Authenticate: Basic realm="GitHub"` header. This causes Desktop to short-circuit its normal host-verification path and immediately surface its own trusted "sign in to GitHub Enterprise" chrome for an arbitrary attacker-chosen host, during what looks like an ordinary `git fetch`/`clone` operation the user initiated. This matches the explicitly allowed "unauthorized OAuth or account binding" impact category: the user is led, through Desktop's own trusted UI rather than an external browser popup they'd be suspicious of, into an authentication flow for a host they never chose to trust.

### Likelihood Explanation
The trigger requires only that the user perform a normal fetch/clone/push against a repository whose remote (or an intermediary) the attacker controls — no local access, malware, or unusual user action is required beyond routine Desktop usage. However, I was not able to fully trace the subsequent `beginEnterpriseSignIn`/`beginDotComSignIn` implementation in `app-store.ts`/`sign-in-store.ts` within the available review budget, so I cannot confirm with certainty whether that downstream flow performs its own host-authenticity checks (e.g., requiring a valid GitHub Enterprise `/meta` API response) that might mitigate the ultimate impact, or whether any real credential/token would end up being sent to the attacker's host as a result.

### Recommendation
Do not use the attacker-supplied `wwwauth[]` header value alone to classify a host as GitHub/Enterprise for purposes of triggering Desktop's native sign-in UI. Require the same authenticated verification (`isGitHubHost`, i.e., an actual API probe) before offering the "enterprise" sign-in path, or otherwise clearly and separately warn the user that the host in question is unverified before initiating an authentication flow.

### Proof of Concept
1. Attacker hosts a git-over-HTTPS server at `https://evil.example.com/repo.git` (or a MITM proxy for any HTTP remote the victim uses).
2. On any authenticated request, the server responds with `HTTP/1.1 401` and header `WWW-Authenticate: Basic realm="GitHub"`.
3. Victim runs `git fetch`/`clone` for that remote inside GitHub Desktop.
4. Git forwards this header to Desktop's credential trampoline as a `wwwauth[]` field; `getEndpointKind` (trampoline-credential-helper.ts:157-165) misclassifies `evil.example.com` as `'enterprise'`.
5. `getCredential` finds no matching stored account for `evil.example.com` and calls `ui.promptForGitHubSignIn('https://evil.example.com')`, presenting Desktop's own trusted sign-in UI for that attacker-controlled host. [2](#0-1) [4](#0-3)

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
