### Title
Lazy-field deferred parsing lets a corrupted/duplicated submessage silently desynchronize the exposed value from the cached serialized bytes - ([File: java/core/src/main/java/com/google/protobuf/LazyFieldLite.java])

### Summary
The BendDAO report describes a state-desynchronization bug: an attacker-influenced boundary value (`redeemThreshold = 10000`) drives one piece of state (`scaledAmount`) to zero while a second, logically-dependent piece of state (`loanStatus` / `LockerAddr`) is never updated to match, and a downstream check (`ValidateLogic`) trusts the stale flag, locking the user out of a valid state transition. The transferable invariant is: **two representations of the same logical fact (a "real" value and a cached/derived flag) can be driven out of sync by adversarial input, and a security-relevant check consults the wrong one.**

In the Protobuf Java runtime, `LazyFieldLite`/`InternalLazyField` maintain exactly this kind of dual state for `[lazy=true]` message fields: raw, unvalidated `delayedBytes` (as received from an untrusted `ParseFrom` call) versus a `value`/`memoizedBytes` that is only materialized when first accessed. `CachedFieldSizeTest`/`LazilyParsedMessageSetTest` in this checkout show the runtime explicitly guarding against divergence between the cached serialized size and the lazily-parsed value, and `mergeValueAndBytes()` shows that when a merge of raw bytes fails validation, the corruption is **silently swallowed** and the pre-existing `value` is kept, with no signal to the caller that data was dropped: [1](#0-0) .

### Finding Description
`LazyFieldLite` stores an untrusted, attacker-supplied byte range (`delayedBytes`) for a `lazy` message field without validating it at parse time, deferring both wire-format validation and required-field checks to first access (`ensureInitialized()`/`getValue()`). Two mutually-dependent state representations exist: the deferred bytes (`delayedBytes`) and the resolved value (`value`), plus a `memoizedBytes` cache used to keep serialized-size accounting consistent, as documented at [2](#0-1) .

When two `LazyFieldLite`/`InternalLazyField` instances are merged (as happens on every repeated call to a public parse/merge API such as `Message.Builder.mergeFrom` for a message that itself embeds another lazily-parsed message, or via `FieldSet.mergeFromField` for extensions marked lazy), the merge logic takes different code paths depending on which side has `value` vs `delayedBytes` populated: [3](#0-2) . If bytes need to be merged into an already-resolved `value` and that merge throws `InvalidProtocolBufferException` (i.e., the attacker supplied a malformed inner submessage), `mergeValueAndBytes()` catches the exception and returns the **old, unmodified `value`** — the corruption is not surfaced to the caller in any way: [1](#0-0) .

This is the direct analog of the BendDAO bug's failed invariant: the "real" content of the field (what an eager parser or a downstream consumer that re-serializes and re-parses would see) diverges from what the in-memory `value`/cached size claims to be, and no status flag records that the divergence occurred. Exactly as the isolate-lending contract kept `loanStatus == ACTIVE` after `scaledAmount` silently hit zero, `LazyFieldLite` keeps a "valid" `value` in place after a byte-level merge silently fails, with the `getSerializedSize()`/`toByteString()` accounting (`memoizedBytes`) still keyed to whatever was last materialized — as the code's own comment warns: "the serialized size changed after LazyField parsed. Be careful when using this method," at [2](#0-1) .

`InternalLazyField.mergeFrom(InternalLazyField, CodedInputStream, ExtensionRegistryLite)` shows the same asymmetry for the MessageSet/extension code path: when extension registries differ, the code eagerly triggers `ensureInitialized()`, but if that throws it re-wraps as `InvalidProtobufRuntimeException` rather than leaving the field in a defined "cleared"/"invalid" state that downstream `Has*`/serialization logic could check: [4](#0-3) .

### Impact Explanation
The consuming-application exposure is any Java service that (a) accepts untrusted binary protobuf via a public `parseFrom`/`mergeFrom` entry point, (b) has a lazily-parsed nested/extension message field, and (c) merges two independently-received payloads addressing the same field (a legitimate and common pattern, e.g. streaming/chunked merges, MessageSet-style extension aggregation, or repeated `mergeFrom` calls building up a request). An attacker who controls one of the two merged payloads can make a subsequent access of that field silently retain stale/pre-corruption content instead of surfacing an error, which is a data-integrity failure: application logic that relies on the merged value (e.g. authorization data embedded in an extension, or a security-relevant nested message) can end up trusting content the attacker never actually supplied validly, while other, differently-implemented consumers (e.g. a re-serialize-then-parse path, or a non-lazy decode of the same bytes) would see the byte-corruption failure and reject the message — a parser/application state divergence directly analogous to BendDAO's "one path sees debt=0, the other still sees status=ACTIVE."

This is Medium severity: it is not a crash or memory-safety bug, and the impact requires the specific merge pattern (lazy field + two-source merge) to be present in application code, but it is a genuine internal-invariant violation reachable purely through the public parsing/merging API with attacker-controlled, bounded binary input.

### Likelihood Explanation
Reaching this requires: (1) a schema field marked `[lazy=true]` (or MessageSet-style extension), which is a supported, documented feature, not a hostile schema; (2) an application path that merges two protobuf payloads targeting the same lazy field (e.g. via repeated `mergeFrom` or extension aggregation) — a realistic, supported usage pattern; (3) one of the payloads containing a malformed/undecodable inner submessage. All three conditions are attacker-reachable through the standard, documented public API without any privileged access, and the code paths (`mergeValueAndBytes`, `InternalLazyField.mergeFrom`) are exercised by the project's own tests (`LazyFieldLiteTest`, `InternalLazyFieldTest`), confirming the scenario is a real, intended-but-imperfect code path rather than a purely theoretical one.

### Recommendation
- In `LazyFieldLite.mergeValueAndBytes()` (and the analogous `InternalLazyField.mergeFrom` path), do not silently swallow `InvalidProtocolBufferException` when merging raw bytes into an already-resolved `value`. Either propagate the failure to the caller of `mergeFrom`/`build()` (consistent with how a non-lazy field would fail `ParseFrom`), or record an explicit "corrupted" state on the lazy field that all downstream accessors (`getValue()`, `getSerializedSize()`, `toByteString()`, `writeTo()`) consistently observe, mirroring the `is_cleared`/`is_lazy` bookkeeping already used elsewhere in the codebase (`extension_set.h`'s `Extension::is_cleared`) so there is a single source of truth for "was this field successfully merged."
- Add a regression test that merges a valid `LazyFieldLite` value with a deliberately corrupted byte payload and asserts that either the merge fails loudly or that `getValue()`, `getSerializedSize()`, and `toByteString()` all agree on the resulting (degraded) state — closing the gap the current `testInvalidMergeFromOtherBecomesValid`-style tests leave unchecked for the "value already resolved + corrupt incoming bytes" branch.

### Proof of Concept
Conceptual, derived from the existing test scaffolding in this checkout (`LazyFieldLiteTest`, `InternalLazyFieldTest`):
1. Build `LazyFieldLite field1` from a valid message and force it to resolve (`field1.getValue(default)`), so `field1.value != null`.
2. Build `LazyFieldLite field2` via `LazyFieldLite.setByteString(bytes, registry)` where `bytes` is a syntactically-valid-length but semantically corrupt encoding for the message type (e.g., a field tag with an invalid wire type for that field, forcing `MessageLite.Builder.mergeFrom` to throw `InvalidProtocolBufferException` when materialized) — same shape as `createLazyFieldWithBytesFromMessage` in `InternalLazyFieldTest.java` but with corrupted bytes instead of a validly serialized message.
3. Call `field1.merge(field2)`. Because `field1.value != null` and `field2.value == null`, this hits `mergeValueAndBytes(this.value, other.delayedBytes, other.extensionRegistry)` at [1](#0-0) . The `InvalidProtocolBufferException` is caught and `value` (the pre-merge, "clean" content) is returned unchanged.
4. Assert that `field1.getValue(default)` still equals the pre-merge value with **no exception raised and no flag set**, while separately serializing `field2`'s raw bytes and attempting a strict `parseFrom` on them independently would throw `InvalidProtocolBufferException` — demonstrating the divergence between what the lazy-merged object reports as "successfully merged" state and what an eager/strict decode of the same attacker-supplied bytes would report.

I was not able to execute this scenario in a live JVM within this session (tool access is read-only/index-based), so this PoC is derived directly from the existing test helpers (`createLazyFieldWithBytesFromMessage`, `testInvalidMergeFromOtherBecomesValid` in `InternalLazyFieldTest.java`) and the documented `mergeValueAndBytes` catch-and-swallow behavior rather than from an observed run; a background Devin session with build/test access would be needed to confirm the exact exception path and byte pattern that triggers `InvalidProtocolBufferException` inside `mergeValueAndBytes` for a concrete message type.

  // Do "this.mergeFrom(other)", and then whichever contains null value will be parsed using the
  // other's default instance.
  private void mergeValue(LazyFieldLite other) {
    if (this.value == null && other.value != null) {
      setValue(
          getValue(other.value.getDefaultInstanceForType()).toBuilder()
              .mergeFrom(other.value)
              .build());
      return;
    }

    if (this.value != null && other.value == null) {
      setValue(mergeValueAndBytes(this.value, other.delayedBytes, other.extensionRegistry));
      return;
    }

    // At this point we have two fully parsed messages.
    setValue(this.value.toBuilder().mergeFrom(other.value).build());
  }

  /**
   * Merges another instance's contents. In some cases may drop some extensions if both fields
   * contain data. If the other field has an {@code ExtensionRegistry} but this does not, then this
   * field will copy over that {@code ExtensionRegistry}.
   *
   * <p>LazyField is not thread-safe for write access. Synchronizations are needed under read/write
   * situations.
   */
  public void merge(LazyFieldLite other) {
    if (other.containsDefaultInstance()) {
      return;
    }
    if (this.containsDefaultInstance()) {
      set(other);
      return;
    }

    // If the other field has an extension registry but this does not, copy over the other extension
    // registry.
    if (this.extensionRegistry == null) {
      this.extensionRegistry = other.extensionRegistry;
    }

    // The above checks guarantee that both `other` and `this` have `value` and/or `delayedBytes`
    // set. When both are unset it is considered a containsDefaultInstance==true case.

    // If both sides have delayed bytes we simply concatenate the bytes to save time, but we can
    // only safely do this if the extension registries are the same.
    if (this.delayedBytes != null
        && other.delayedBytes != null
        && this.extensionRegistry == other.extensionRegistry) {
      this.delayedBytes = this.delayedBytes.concat(other.delayedBytes);
      return;
    }

    // If either side is parsed, we merge on parsed instances.
    if (this.value != null || other.value != null) {
      mergeValue(other);
      return;
    }

    // If we have reached this far, both sides have `delayedBytes` set and neither have `value` set.

    // If `this.defaultInstance` is not known, we can't trigger a parse of `this` and so the
    // best we can do is concat the bytes. Since other side's extension registry is different
    // this may result in some extensions being lost that shouldn't have been, but its the
    // best that we can do if we reach this point and is not expected to occur in real use.
    if (defaultInstance == null) {
      // TODO: b/467739361 - Consider throwing an exception here.
      this.delayedBytes = this.delayedBytes.concat(other.delayedBytes);
      return;
    }

    setValue(mergeValueAndBytes(getValue(), other.delayedBytes, other.extensionRegistry));
  }

  private static MessageLite mergeValueAndBytes(
      MessageLite value, ByteString otherBytes, ExtensionRegistryLite extensionRegistry) {
    try {
      return value.toBuilder().mergeFrom(otherBytes, extensionRegistry).build();
    } catch (InvalidProtocolBufferException e) {
      // Nothing is logged and no exceptions are thrown. Clients will be unaware that a proto
      // was invalid.
      return value;
    }
  }

  static InternalLazyField mergeFrom(
      InternalLazyField lazyField, CodedInputStream input, ExtensionRegistryLite extensionRegistry)
      throws IOException {
    if (lazyField.isEmpty()) {
      return new InternalLazyField(lazyField.defaultInstance, extensionRegistry, input.readBytes());
    }

    if (lazyField.hasBytes()) {
      if (lazyField.extensionRegistry == extensionRegistry) {
        ByteString inputBytes = input.readBytes();
        if (inputBytes.isEmpty()) {
          return lazyField;
        }
        return new InternalLazyField(
            lazyField.defaultInstance, extensionRegistry, lazyField.bytes.concat(inputBytes));
      }
      // The extension registries are different, so we need to parse the bytes first to "consume"
      // the extension registry of this lazy field.
      try {
        lazyField.ensureInitialized();
      } catch (InvalidProtocolBufferException e) {
        throw new InvalidProtobufRuntimeException(
            "Cannot merge invalid lazy field from bytes that is absent or with a different"
                + " extension registry.",
            e);
      }
    }

    try {
      MessageLite.Builder builder = lazyField.value.toBuilder();
      input.readMessage(builder, extensionRegistry);
      return new InternalLazyField(builder.build());
    } catch (InvalidProtocolBufferException e) {
      // If the input bytes is corrupted, we should concat bytes. However, we should only do so if
      // the extension registries are the same AND self.bytes is present. This should have been
      // handled in the mergeFrom function, so we just throw an exception here.
      throw new InvalidProtobufRuntimeException(
          "Cannot merge lazy field from invalid bytes with a different extension registry.", e);
    }
  }
