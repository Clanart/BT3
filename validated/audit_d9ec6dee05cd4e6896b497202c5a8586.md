### Title
DataLayer subscription/mirror sync is vulnerable to Server-Side Request Forgery via attacker-controlled mirror URLs - (File: `chia/data_layer/data_layer.py`, `chia/data_layer/download_data.py`)

### Summary
Chia DataLayer nodes resolve "mirror" server URLs for a store from on-chain mirror coins and then make outbound HTTP requests (or hand the URL to a downloader/uploader plugin) to those URLs without any restriction on target host/scheme. Because mirror coins are created by spending a fixed, ownerless puzzle (`create_mirror_puzzle()` = `P2_PARENT.curry(1)`), **any** wallet user can create a mirror coin for **any** `store_id` (launcher id) carrying arbitrary attacker-controlled URLs, including internal/loopback/link-local addresses. A DataLayer node that subscribes to (or owns) that store will fetch the URL, resulting in classic SSRF reachable purely by submitting a normal spend bundle / wallet transaction.

### Finding Description
Mirror coins are created via `DataLayerWallet.create_new_mirror()`, which sends coins to `create_mirror_puzzle().get_tree_hash()` with the target `launcher_id` and arbitrary `urls` embedded as coin memos: [1](#0-0) 

`create_mirror_puzzle()` curries `P2_PARENT` with `Program.to(1)`, i.e. an anyone-can-spend/anyone-can-create puzzle used purely as a tag, and `get_mirror_info()` extracts `launcher_id` and the URL list directly from `CREATE_COIN` memos without validating that the creator is the actual store owner: [2](#0-1) 

The RPC path `dl_new_mirror` lets any local wallet user (or, more importantly for the SSRF class, anyone who can get a coin with the mirror puzzle hash mined) register a URL for an arbitrary `launcher_id`: [3](#0-2) [4](#0-3) 

DataLayer then pulls these URLs into its subscription table without validation: [5](#0-4) 

and `fetch_and_validate()` iterates over `servers_info` (built from those URLs) and issues outbound requests via `insert_from_delta_file` → `download_file` → `http_download`, using `aiohttp.ClientSession().get(server_info.url + "/" + filename, ...)` with no host/IP allow-listing: [6](#0-5) [7](#0-6) 

If a downloader plugin is configured, the raw attacker-supplied URL is also forwarded verbatim to the plugin's `/download` endpoint as a JSON field, and separately, `get_downloader()`/`get_uploaders()` themselves make direct outbound POSTs to plugin URLs (also externally configured, though those are operator-controlled rather than attacker-controlled): [8](#0-7) [9](#0-8) 

No component in this chain (mirror puzzle spend, `get_mirror_info`, `add_mirror`/`dl_new_mirror`, `update_subscriptions_from_wallet`, `fetch_and_validate`, `http_download`) validates that the URL resolves to a non-internal, non-loopback, non-link-local address, or restricts scheme/port. This mirrors the Galaxy `uris.py` SSRF class referenced in the report: attacker-supplied "import" URLs are dereferenced by the server without validation.

### Impact Explanation
An attacker who is not a peer, node operator, or store owner — merely a wallet user able to broadcast a standard coin-creation spend bundle to the mirror puzzle hash with a chosen `launcher_id` and URL memos — can cause any DataLayer node that later subscribes to (or already owns) that `store_id` to issue outbound HTTP GET requests to attacker-chosen hosts (e.g., `http://127.0.0.1:<port>/...`, cloud metadata endpoints, internal services). This can be used to probe/interact with internal network services reachable from the DataLayer host, potentially leaking response data indirectly (e.g., via error/log differences or timing) since the DataLayer error handling logs failures with `self.log.warning(...)` and treats non-conforming responses as download failures, or via the downloader-plugin JSON `res_json["downloaded"]` boolean leak of reachability. This satisfies the "reachable by unprivileged spend-bundle submitter" bar and is a genuine internal-network access vector rather than a no-impact bug.

### Likelihood Explanation
Likelihood is moderate: the request requires (1) getting a mirror-puzzle coin creation mined on chain (any user can create such a coin for any `store_id`/launcher id — no signature tying it to the store's owner is required by `get_mirror_info`), and (2) a DataLayer node choosing to subscribe to that particular store id (subscriptions are typically opt-in by store id, but any store id including attacker-created ones can be subscribed to by any DataLayer operator wanting to mirror/replicate data, and owned stores are auto-mirrored). Given DataLayer is designed for open store sharing/subscription across untrusted networks, encountering attacker-controlled mirror URLs during normal use is a realistic and expected occurrence, not a contrived edge case.

### Recommendation
- Validate/allow-list mirror and downloader/uploader URLs before dereferencing them: reject loopback, link-local, private (RFC1918), and other non-routable/internal address ranges unless explicitly configured by the operator.
- Perform DNS resolution and IP-range checks at request time (not just string checks) to prevent DNS-rebinding bypasses, and pin the resolved IP for the actual `aiohttp` request.
- Consider requiring explicit operator opt-in (config allow-list) per subscribed store/mirror URL rather than trusting whatever URL appears in on-chain mirror memos.
- Apply the same validation to plugin `PluginRemote.url` values reachable indirectly through attacker-influenced fields (e.g., `server_info.url` forwarded into `/download` requests).

### Proof of Concept
1. As any wallet user, call `dl_new_mirror` (or otherwise get a coin spent to `create_mirror_puzzle().get_tree_hash()`) targeting a `launcher_id` of a store that a target DataLayer node subscribes to (or owns), with `urls=["http://127.0.0.1:6789/some-internal-path"]` (or a cloud metadata IP). [4](#0-3) 
2. Once mined, the coin's memos are parsed by `get_mirror_info()` and surfaced via `dl_get_mirrors`. [10](#0-9) 
3. The target DataLayer node's periodic sync calls `update_subscriptions_from_wallet()`, storing the attacker URL, then `fetch_and_validate()` triggers `http_download()` to issue an HTTP GET to `http://127.0.0.1:6789/<delta-filename>`. [11](#0-10) [12](#0-11) 
4. Observe via logs/timing whether the internal service responded (e.g., a 200 vs. connection-refused/timeout distinguishes open vs. closed internal ports), confirming SSRF against the DataLayer host's internal network.

def create_mirror_puzzle() -> Program:
    return P2_PARENT.curry(Program.to(1))


MIRROR_PUZZLE_HASH = create_mirror_puzzle().get_tree_hash()


def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")

    async def get_downloader(self, store_id: bytes32, url: str) -> PluginRemote | None:
        request_json = {"store_id": store_id.hex(), "url": url}
        for d in self.downloaders:
            async with aiohttp.ClientSession() as session:
                try:
                    async with session.post(

                        json=request_json,
                        headers=d.headers,
                        timeout=self.client_timeout,
                    ) as response:

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
