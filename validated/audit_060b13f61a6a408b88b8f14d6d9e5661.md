### Title
`ReceivedOutput::read` accepts outputs whose offset cannot spend them, bypassing the `Scanner` matching invariant - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The M-06 bug class is a handler that covers only one error form while a reachable, equally-invalid case slips through (`catch Error(string)` missing `EnforcedPause`). The Serai analog is `ReceivedOutput::read` in `networks/bitcoin/src/wallet/mod.rs`. The honest constructor path — `Scanner::scan_transaction` — only produces a `ReceivedOutput` when the output's `script_pubkey` is bound to a registered offset (`self.scripts.get(&output.script_pubkey)` at `wallet/mod.rs:205`). The deserialization path checks only canonicality: `Secp256k1::read_F` enforces a canonical scalar (`ciphersuite/src/lib.rs:74-83`) and `TxOut`/`OutPoint` are consensus-decoded (`wallet/mod.rs:127-132`), but no check verifies that `key + offset·G` actually yields the claimed `script_pubkey`, nor that the tweaked point is even-Y / spendable. An unprivileged party feeding crafted bytes to `ReceivedOutput::read` gets a structurally valid object claiming receipt of an output the key cannot spend.

### Finding Description
`ReceivedOutput` couples a scalar `offset`, a `TxOut`, and an `OutPoint` into "a spendable output" (`wallet/mod.rs:88-97`). The invariant that makes it spendable is established only in `Scanner`:

- `register_offset` increments the offset until `p2tr_script_buf(key + offset·G)` returns an even-Y P2TR script and rejects collisions (`wallet/mod.rs:180-195`).
- `scan_transaction` emits a `ReceivedOutput` only if the output's `script_pubkey` exists in `self.scripts` (`wallet/mod.rs:199-213`).

`ReceivedOutput::read` (`wallet/mod.rs:122-134`) performs none of this. It accepts:
1. An `offset` that does not correspond to the output's `script_pubkey` under any key — the reader never sees the scanner key, and no binding is encoded.
2. An `offset` of `Scalar::ZERO` for a script that was registered under a nonzero offset, or vice versa.
3. An `OutPoint` referencing a nonexistent or already-spent output — `read` only checks the wire encoding.

This is the same shape as the report: the encoding-level checks (analogous to `catch Error(string)`) pass, while the semantic failure (offset↔script binding, analogous to the uncaught `EnforcedPause`) is not handled, so the caller proceeds as if the output were spendable.

### Impact Explanation
A deserialized `ReceivedOutput` can report funds as received that are not spendable by the threshold key: the stored `offset` will not produce a valid tweaked key/signature for the claimed `script_pubkey`. Downstream code that aggregates `value()` (`wallet/mod.rs:115-118`) over read outputs miscounts balance, and any spend attempt built on the false binding wastes transaction fees or produces an invalid input — mirroring the report's "unnecessary fee expenditure" consequence. Impact is medium: it corrupts the received-funds ledger and wastes fees, but does not directly move funds.

### Likelihood Explanation
The read API takes raw bytes with no authentication and the failure is deterministic — any attacker-controlled or corrupted `ReceivedOutput` blob deserializes successfully. Likelihood is bounded by how deployments source these bytes (local DB writes are benign; any network/hostile source triggers it), so medium.

### Recommendation
Bind deserialization to the scanning key, or defer trust: have `ReceivedOutput::read` take the scanner `key` (or have `Scanner` expose a `read`/`verify` method) and re-derive `p2tr_script_buf(key + offset·G)`, rejecting the object if it does not equal `output.script_pubkey`. Additionally reject `offset == Scalar::ZERO` unless the zero offset was actually registered, and document that `OutPoint` existence/maturity must be verified against chain state before the output is counted as spendable.

### Proof of Concept
```rust
// Construct bytes for an output whose script_pubkey belongs to a DIFFERENT
// offset than the one encoded — or to no registered offset at all.
let mut buf = vec![];
// arbitrary canonical scalar, e.g. 42, which was never registered
buf.extend(Scalar::from(42u64).to_bytes());
// any TxOut (e.g. paying to an unrelated P2TR script)
buf.extend(serialize(&attacker_chosen_txout));
// any OutPoint, including a fabricated txid
buf.extend(serialize(&OutPoint::new(Txid::from_byte_array([0u8; 32]), 0)));

// Succeeds: read only checks scalar canonicality and consensus encoding.
let output = ReceivedOutput::read(&mut &buf[..]).unwrap();
// output.offset() (42) does not derive the script in attacker_chosen_txout
// under the scanner key -> reported as received, unspendable in practice.
```
The analogous negative control: `Scanner::scan_transaction` would never emit this `ReceivedOutput` because `self.scripts.get(&output.script_pubkey)` fails; the deserialization path lacks that guard entirely (`wallet/mod.rs:122-134` vs `wallet/mod.rs:199-213`).
