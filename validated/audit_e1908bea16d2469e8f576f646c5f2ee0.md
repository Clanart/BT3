### Title
Bandwidth Subscription FIFO Cap Allows Unprivileged Eviction of a Victim App's Prepaid Bandwidth - (File: `modules/pallets/bandwidth/src/lib.rs`)

### Summary
The OtterSec report describes a bounded list (max delegators) that an attacker can fill with dust entries to lock out legitimate participants, with no lifetime-minimum stake to make the attack costly. The local analog is `pallet-bandwidth`'s per-`(chain, app)` subscription list, capped at `MAX_SUBSCRIPTIONS = 1024` [1](#0-0) . `BandwidthManager.purchase()` on any EVM source chain lets an *arbitrary, unprivileged caller* choose both the credited `app` and the credited `chain` with no relationship to `msg.sender` — this is the intentional "sponsorship" feature [2](#0-1) . Every purchase unconditionally appends a new `Subscription` row; once the list is at cap, the *oldest* entry — which could be a large, recently-purchased, mostly-unused legitimate subscription — is evicted and its `remaining_bytes` are permanently lost [3](#0-2) .

### Finding Description
`push_subscription` in `modules/pallets/bandwidth/src/lib.rs` implements the FIFO-with-eviction logic:
```
let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
    let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
        Some(list.remove(0))
    } else {
        None
    };
    let _ = list.try_push(new_sub);
    evicted
});
``` [4](#0-3) 

There is no check binding who may credit a given `(chain, app)` pair to the app owner, and no per-purchase minimum relative to what's already queued. `BandwidthManager.purchase(bytes app, uint256 tier, uint256 months, bytes chain)` accepts caller-supplied `app` and `chain` values, pulls the tier price from `msg.sender`, and dispatches the credit — the docs explicitly describe this as intended "sponsorship" behavior ("A buyer on Ethereum credits an app on Base by passing the credit chain id in `chain`") [5](#0-4) .

Because tier prices can be set arbitrarily low by governance (the docs even flag "a hypothetical sub-penny SKU") [6](#0-5) , and `months` can be `1` (minimum), an attacker can repeatedly call `purchase()` with the victim's known `(chain, app)` pair and the cheapest configured tier. After `MAX_SUBSCRIPTIONS` (1024) such purchases, every subsequent purchase evicts one more real entry from the head of the list — draining out the victim's legitimately prepaid, larger/higher-tier subscriptions before they are ever consumed by the gate. This mirrors the OtterSec pattern exactly: a bounded list with a fixed capacity, fillable by cheap adversary-controlled entries, that displaces legitimate participants' stake/allocation — here, prepaid non-refundable bandwidth funds.

### Impact Explanation
This is a direct "loss of funds" vector under the bounty's impact gate: bytes a legitimate app already paid for (`amountPaid` debited at purchase time, non-refundable — the tokens are held by the manager/treasury) are evicted from the FIFO queue and permanently lost (`SubscriptionEvicted { lost_bytes }`) before the app can use them [7](#0-6) . An attacker who knows a victim's `(chain, app)` — public information, since `app` is just an address and `chain` a public chain id — can grief that specific app's bandwidth continuously and cheaply if a low-priced tier is configured, or at moderate but bounded cost otherwise, causing asymmetric loss (attacker spends `1024 × cheap_tier_price`, victim loses however much higher-value bandwidth they'd queued). No relayer, prover, admin, or governance compromise is required — this is reachable from an ordinary unprivileged EVM account via the public `purchase()` entrypoint.

### Likelihood Explanation
The attack requires no special access: `purchase()` is a public, unauthenticated function with no relationship check between `msg.sender` and the `app`/`chain` being credited, by design (the sponsorship feature). The only friction is the aggregate gas + tier-price cost of issuing enough purchases to reach and exceed the 1024-entry cap for the targeted `(chain, app)`, which is bounded and can be made arbitrarily cheap depending on which tier governance has priced lowest. Any app with meaningful queued bandwidth (multiple months/tiers pending) is a viable target.

### Recommendation
Enforce that credits toward an app's own bandwidth cannot be evicted below a meaningful floor by unrelated dust purchases: either (a) require the credited `app` to authorize/opt-in to being credited by a third party (or restrict same-tx sponsorship to allowlisted payers), (b) impose a minimum bytes/duration-value floor per purchase so an attacker cannot cheaply fill the queue with negligible entries, and/or (c) evict based on remaining-value/expiry priority rather than strict insertion-order FIFO so large, unexpired legitimate subscriptions are not the first candidates displaced by spam entries. At minimum, emit alerting/rate-limit the number of subscriptions a single external payer can push to a given `(chain, app)` within a short window.

### Proof of Concept
1. Governance configures at least one low-priced tier, e.g. `TierOne` with `tierPrice[1] = 10**12` (18-decimal, sub-penny per the docs) [6](#0-5) .
2. Victim app `V` on chain `C` legitimately purchases a large, expensive tier for many months, landing a high-value `Subscription` at the tail of `Allowance::<T>::get(C, V)`.
3. Attacker repeatedly calls `BandwidthManager.purchase(app = V, tier = TierOne, months = 1, chain = C)` from any EVM account, paying the (potentially near-zero) tier price each time [5](#0-4) .
4. Each purchase dispatches a `BandwidthPurchaseMsg` to `pallet-bandwidth`, which calls `push_subscription(C, V, ...)` [3](#0-2) .
5. Once `Allowance::<T>::get(C, V).len() == 1024`, every additional attacker purchase evicts the oldest entry in the list — eventually reaching and evicting the victim's expensive, unused subscription, emitting `SubscriptionEvicted { lost_bytes }` and permanently destroying the prepaid bandwidth the victim paid real fee-tokens for.

    /// @dev Pulls the scaled tier price from `msg.sender` in the host's
    /// fee token, then dispatches a `BandwidthPurchaseMsg` to
    /// `pallet-bandwidth` on hyperbridge. The pallet credits an
    /// `(chain, app)` bucket bounded by tier `bytes` × `months`.
    /// @param app Recipient app address (usually 20-byte EVM, packed as bytes).
    /// @param tier Tier discriminant; must be configured via `SetTiers`.
    /// @param months Number of tier-windows to credit; must be > 0.
    /// @param chain UTF-8 chain id (e.g. `"EVM-8453"`) of the credit chain.
    /// @return commitment Hyperbridge dispatch commitment for tracking.
    function purchase(bytes calldata app, uint256 tier, uint256 months, bytes calldata chain)
        external
        returns (bytes32 commitment)
    {
        if (app.length == 0 || chain.length == 0 || months == 0) revert InvalidPurchase();
        uint256 price18d = tierPrice[tier];
        if (price18d == 0) revert UnknownTier();

        uint256 total18d = price18d * months;
        address feeToken = IDispatcher(_host).feeToken();
        uint8 dec = IERC20Metadata(feeToken).decimals();
        uint256 scale = 10 ** (18 - dec);
        if (total18d % scale != 0) revert PriceNotRepresentable();
        uint256 amount = total18d / scale;

        IERC20(feeToken).safeTransferFrom(msg.sender, address(this), amount);

		/// Append a fresh subscription with a fixed expiry. If the list
		/// is already at `MaxSubscriptions`, evict the oldest entry and
		/// emit [`Event::SubscriptionEvicted`] so the lost bytes are
		/// auditable. Returns the new subscription's `expires_at`.
		fn push_subscription(
			app_chain: &StateMachine,
			app: &AppKey,
			tier: TierIndex,
			bytes: BandwidthBytes,
			duration_secs: u64,
		) -> u64 {
			let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();
			let expires_at = now.saturating_add(duration_secs);
			let new_sub =
				Subscription { tier, remaining_bytes: bytes, expires_at, purchased_at: now };

			let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
				let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
					Some(list.remove(0))
				} else {
					None
				};
				// Capacity is now guaranteed; try_push can't fail.
				let _ = list.try_push(new_sub);
				evicted
			});

			if let Some(old) = evicted {
				Self::deposit_event(Event::SubscriptionEvicted {
					app_chain: *app_chain,
					app: app.clone(),
					tier: old.tier,
					lost_bytes: old.remaining_bytes,
				});
			}

			expires_at
		}
