## Title
Hard-coded UTF-8 decoding of diff output silently corrupts non-UTF-8 file content when staging/discarding changes - (File: `app/src/lib/git/diff.ts`)

### Summary
`diffFromRawDiffOutput()` unconditionally decodes the raw buffer returned by `git diff --patch-with-raw` as UTF-8, even though the comment itself acknowledges this is an assumption that doesn't always hold: [1](#0-0) 

This is structurally the same bug class as the reported `getRate()` issue: a fixed, hard-coded interpretation parameter (`USDC_SPOT_DECIMALS` there, `'utf-8'` here) is applied uniformly to a value whose real format varies per-instance (`szDecimals` per asset there, actual file encoding per file here). When the assumption doesn't hold, the decoded value is silently wrong, and that wrong value is later used as ground truth for a consequential action (scaling a price there, reconstructing and applying a patch here).

### Finding Description
`getWorkingDirectoryDiff()` reads the diff with `encoding: 'buffer'` specifically to avoid premature decoding, but the very next step, `diffFromRawDiffOutput()`, throws that care away and force-decodes with `output.toString('utf-8')`: [2](#0-1) [1](#0-0) 

If a file in the working tree/repository is encoded in anything other than valid UTF-8 (e.g. UTF-16, Shift-JIS, Latin-1, or simply contains a byte sequence that isn't valid UTF-8), `Buffer.toString('utf-8')` replaces the invalid byte sequences with U+FFFD replacement characters. This is a lossy, one-way transformation — the original bytes are gone from that point forward.

This corrupted text then flows straight into `DiffParser.parse()`, producing `DiffLine.text` values that no longer match the bytes on disk. Those lines are exactly what `formatPatch()` and `formatPatchToDiscardChanges()` use, verbatim, to build a brand-new unified diff that is fed to `git apply`: [3](#0-2) [4](#0-3) [5](#0-4) 

`applyPatchToIndex` (used by partial staging via `stageFiles`) and `discardChangesFromSelection` (used by "Discard changes") both apply this reconstructed, UTF-8-re-encoded patch back against the index or the working directory. Since context lines are also re-emitted verbatim, corruption is not limited to the specific hunk/line the user selected — any file containing non-UTF-8 bytes anywhere in the diff will have those bytes silently replaced the moment the user stages part of the file or discards any change in it.

Existing UI mitigations don't cover this: `hasHiddenBidiChars` only detects a narrow set of bidi override characters and `lineEndingsChange` only reports CRLF/LF conversions reported by Git on stderr — neither detects or warns about invalid/non-UTF-8 byte sequences being irreversibly replaced during decode. [6](#0-5) 

### Impact Explanation
This causes silent corruption of what the user commits, stages, or leaves in their working directory — one of the explicitly in-scope impacts. A file cloned/fetched from an attacker-controlled or simply non-UTF-8-authored repository can have its content permanently mangled (replacement characters substituted for original bytes) the moment a Desktop user performs a completely ordinary action: partially staging a hunk/line, or discarding a change. There is no warning shown to the user that this destructive, lossy transformation is happening.

### Likelihood Explanation
Likelihood is Medium: non-UTF-8 encoded text files are common in real-world repositories (legacy Windows-1252/Shift-JIS files, files with binary-like content misdetected as text, etc.), and the corrupting code path is hit on the default "stage selected lines"/"discard changes" workflows — no special user action beyond normal use of Desktop's partial-staging feature is required.

### Recommendation
Do not blindly force UTF-8 decoding of arbitrary repository content. Detect the actual encoding (e.g. via a BOM check, `.gitattributes` `working-tree-encoding`, or a charset-detection library) before decoding, and/or preserve the raw buffer for round-tripping when reconstructing patches so `formatPatch`/`formatPatchToDiscardChanges` never re-encode data lossily. At minimum, detect invalid UTF-8 sequences during decode and warn the user (similar to the existing `hasHiddenBidiChars`/`lineEndingsChange` warnings) before allowing partial-stage or discard operations on such files.

### Proof of Concept
1. Create a repository containing a file with content encoded as, e.g., Shift-JIS or Latin-1 containing a byte sequence that is invalid UTF-8 (or simply not equivalent to any valid UTF-8 codepoint).
2. Modify the file and open it in GitHub Desktop; the diff view will show replacement characters (`�`) instead of the true characters because `diffFromRawDiffOutput` decoded the raw buffer as UTF-8.
3. Select and stage (or discard) any single line/hunk in that file.
4. `formatPatch`/`formatPatchToDiscardChanges` reconstruct the patch using the already-corrupted `DiffLine.text` values (including untouched context lines) and pipe it to `git apply --cached` / `git apply`.
5. Inspect the resulting index entry or working file on disk: the original byte sequence has been permanently replaced with UTF-8 replacement-character bytes, even for content the user never intended to change.

/**
 * Render the diff for a file within the repository working directory. The file will be
 * compared against HEAD if it's tracked, if not it'll be compared to an empty file meaning
 * that all content in the file will be treated as additions.
 */
export async function getWorkingDirectoryDiff(
  repository: Repository,
  file: WorkingDirectoryFileChange,
  hideWhitespaceInDiff: boolean = false
): Promise<IDiff> {
  // `--no-ext-diff` should be provided wherever we invoke `git diff` so that any
  // diff.external program configured by the user is ignored
  const args = [
    'diff',
    ...(hideWhitespaceInDiff ? ['-w'] : []),
    '--no-ext-diff',
    '--patch-with-raw',
    '-z',
    '--no-color',
  ]
  const successExitCodes = new Set([0])
  const isSubmodule = file.status.submoduleStatus !== undefined

  // For added submodules, we'll use the "default" parameters, which are able
  // to output the submodule commit.
  if (
    !isSubmodule &&
    (file.status.kind === AppFileStatusKind.New ||
      file.status.kind === AppFileStatusKind.Untracked)
  ) {
    // `git diff --no-index` seems to emulate the exit codes from `diff` irrespective of
    // whether you set --exit-code
    //
    // this is the behavior:
    // - 0 if no changes found
    // - 1 if changes found
    // -   and error otherwise
    //
    // citation in source:
    // https://github.com/git/git/blob/1f66975deb8402131fbf7c14330d0c7cdebaeaa2/diff-no-index.c#L300
    successExitCodes.add(1)
    args.push('--no-index', '--', '/dev/null', file.path)
  } else if (file.status.kind === AppFileStatusKind.Renamed) {
    // NB: Technically this is incorrect, the best kind of incorrect.
    // In order to show exactly what will end up in the commit we should
    // perform a diff between the new file and the old file as it appears
    // in HEAD. By diffing against the index we won't show any changes
    // already staged to the renamed file which differs from our other diffs.
    // The closest I got to that was running hash-object and then using
    // git diff <blob> <blob> but that seems a bit excessive.
    args.push('--', ensureRelativePath(file.path))
  } else {
    args.push('HEAD', '--', ensureRelativePath(file.path))
  }

  const { stdout, stderr } = await git(
    args,
    repository.path,
    'getWorkingDirectoryDiff',
    { successExitCodes, encoding: 'buffer' }
  )
  const lineEndingsChange = parseLineEndingsWarning(stderr)

  return buildDiff(stdout, repository, file, 'HEAD', 'HEAD', lineEndingsChange)

function diffFromRawDiffOutput(output: Buffer): IRawDiff {
  // for now we just assume the diff is UTF-8, but given we have the raw buffer
  // we can try and convert this into other encodings in the future
  const result = output.toString('utf-8')

  const pieces = result.split('\0')
  const parser = new DiffParser()
  return parser.parse(forceUnwrap(`Invalid diff output`, pieces.at(-1)))
}

export async function discardChangesFromSelection(
  repository: Repository,
  filePath: string,
  diff: ITextDiff,
  selection: DiffSelection
) {
  const patch = formatPatchToDiscardChanges(filePath, diff, selection)

  if (patch === null) {
    // When the patch is null we don't need to apply it since it will be a noop.
    return
  }

  const args = ['apply', '--unidiff-zero', '--whitespace=nowarn', '-']

  await git(args, repository.path, 'discardChangesFromSelection', {
    stdin: patch,
  })
}
