### Title
Ed448 point decoding accepts non-prime-order torsion points, enabling forged Schnorr signatures - (File: crypto/ed448/src/point.rs)

### Summary
`minimal_ed448::Point::is_torsion_free` never rejects any point because it computes `-P + P` and tests whether the result is identity. Consequently, `GroupEncoding::from_bytes` and `Ed448::read_G` accept Ed448 torsion components that are outside the prime-order subgroup.

### Finding Description
`Point::from_bytes` decodes an Ed448 point and gates acceptance on `not_negative_zero & point.is_torsion_free()`. The subgroup test is implemented as:

```rust
((*self * (Scalar::ZERO - Scalar::ONE)) + self).is_identity()
```

`Scalar::ZERO - Scalar::ONE` is `-1`, so this always evaluates `(P - P) == 0`, including for nontrivial torsion points. [1](#0-0) 

The generic `Ciphersuite::read_G` rejects non-canonical encodings, but otherwise relies on `G::from_bytes` to enforce the `PrimeGroup` contract. [2](#0-1)  FROST's `Curve::read_G` additionally rejects only the identity, not other torsion points. [3](#0-2) 

`SchnorrSignature::read` accepts attacker-controlled `R` through `C::read_G`, while verification accepts an attacker-controlled public key and evaluates `R + cA - sG == 0`. [4](#0-3) [5](#0-4) 

### Impact Explanation
An unprivileged party can submit the canonical encoding of the order-2 Ed448 point `T = (0, -1)` as a public key. Because the decoder accepts it as a `PrimeGroup` element, the party can create a Schnorr signature that verifies under that accepted public key without knowing a prime-subgroup discrete logarithm.

For example, use `R = identity` and `s = 0`. Verification succeeds whenever the challenge is even because `cT = identity` for even `c`. When the challenge is hash-derived from attacker-influenced message bytes, the attacker can vary the message until its scalar challenge is even.

This is a forged accepted signature under a malformed public key and breaks the `PrimeGroup` assumption used by Schnorr, FROST, PedPoP, and related parsing paths.

### Likelihood Explanation
The attack requires only public bytes: a 57-byte Ed448 point encoding and a signature/message. The order-2 point is public and deterministic, `R` and `s` are fixed, and an attacker-controlled message only needs to produce an even challenge.

The bug is deterministic: every decodable torsion point passes `is_torsion_free`. Exploiting the Schnorr verification path requires a protocol that accepts an attacker-selected Ed448 public-key encoding or exposes an equivalent verification input.

### Recommendation
Replace `Point::is_torsion_free` with a real prime-order subgroup check, such as testing whether multiplication by the Ed448 prime subgroup order yields identity, or equivalently rejecting points that remain nonzero after multiplication by that order according to the intended representation invariant.

Add regression tests asserting that:

- the order-2 encoding `y = -1, sign = 0` is rejected;
- all nontrivial order-4 encodings are rejected;
- identity handling remains consistent between `Ciphersuite::read_G` and `Curve::read_G`;
- decoded `Point` values satisfy `l * P == identity`.

### Proof of Concept
The following Rust-style proof demonstrates acceptance of the order-2 point and construction of a signature satisfying the verifier equation for an even challenge:

```rust
use ff::PrimeField;
use group::{Group, GroupEncoding};
use ciphersuite::Ciphersuite;
use minimal_ed448::{Ed448, FieldElement, Scalar};
use schnorr::SchnorrSignature;

// Canonical encoding of T = (0, -1), the order-2 Ed448 point.
// GroupEncoding::Repr is FieldElement::Repr.
let mut torsion_encoding = (-FieldElement::ONE).to_repr();
torsion_encoding.as_mut()[56] &= 0x7f; // sign = 0; x = 0 and must not encode -0

let torsion_key =
  Ed448::read_G::<&[u8]>(&mut torsion_encoding.as_ref()).unwrap();

// This should fail for a real prime-order group element, but succeeds.
assert!(!bool::from(torsion_key.is_identity()));

// Canonical encoding of the identity: y = 1, x = 0, sign = 0.
let identity_encoding = FieldElement::ONE.to_repr();
let identity_r =
  Ed448::read_G::<&[u8]>(&mut identity_encoding.as_ref()).unwrap();

let forgery = SchnorrSignature::<Ed448> {
  R: identity_r,
  s: Scalar::ZERO,
};

// Even challenge: R + cA - sG = 0 + 2T - 0G = identity.
let even_challenge = Scalar::ONE + Scalar::ONE;
assert!(forgery.verify(torsion_key, even_challenge));
```

For a hash-derived challenge, iterate over attacker-controlled message bytes until the derived scalar is even. The forged tuple is then `(torsion_key_encoding, identity_R, s = 0, selected_message)`.
