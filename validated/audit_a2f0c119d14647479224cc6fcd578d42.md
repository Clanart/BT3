### Title
Scanner accepts zero-value / below-dust outputs as spendable `ReceivedOutput`s - (File: `networks/bitcoin/src/wallet/mod.rs`)

### Summary
The Bitcoin `Scanner` registers any output whose `script_pubkey` matches a registered offset as a spendable `ReceivedOutput`, with no check on the output's value. A zero-value (or economically unspendable, sub-dust) output is therefore reported as received funds even though it can never contribute net value to a spend and actively harms fee/input accounting. This is the Serai analog of "0 value transfer for fees should not be allowed": a zero value is accepted where a positive minimum is required, and downstream logic that consumes it breaks.

### Finding Description
`Scanner::scan_transaction` filters outputs solely on `output.script_pubkey` membership in `self.scripts` and unconditionally pushes a `ReceivedOutput` carrying whatever `TxOut.value` the transaction contains:

```rust
if let Some(offset) = self.scripts.get(&output.script_pubkey) {
  res.push(ReceivedOutput {
    offset: *offset,
    output: output.clone(),
    outpoint: OutPoint::new(tx.compute_txid(), vout),
  });
}
``` [1](#0-0) 

Bitcoin consensus permits outputs with `value == 0` (and any value below the 546-sat dust relay policy); they are merely non-standard to relay, not invalid. `ReceivedOutput` preserves the value verbatim (`value()` returns `self.output.value.to_sat()`), so the scanner surfaces worthless outputs as real, spendable inputs.

Downstream, `SignableTransaction::new` sums input values into `input_sat` and derives `needed_fee` from the number of inputs:

```rust
let input_sat = inputs.iter().map(|input| input.output.value.to_sat()).sum::<u64>();
...
let (mut weight, vbytes) = Self::calculate_weight_vbytes(tx_ins.len(), payments, None);
let mut needed_fee = fee_per_vbyte * vbytes;
...
if input_sat < (payment_sat + needed_fee) { Err(TransactionError::NotEnoughFunds { ... })?; }
``` [2](#0-1) 

A zero/sub-dust `ReceivedOutput` contributes ~0 sats to `input_sat` while adding a full input's weight to `needed_fee`. While `SignableTransaction::new` carefully enforces a minimum on *payments* (`if *amount < DUST { Err(TransactionError::DustPayment) }`) and on the *change* output (`if value >= DUST`), no equivalent minimum exists on *inputs* at either the scanning or signing layer — exactly the missing `fee > 0`-style guard from the original report.

### Impact Explanation
An unprivileged party can craft a Bitcoin transaction paying 0 sats (or 1 sat, or any amount below the fee cost of spending it) to the Serai vault's `p2tr` script_pubkey or to any registered offset address. Such a transaction is consensus-valid and can be included by any miner (or on regtest/non-standard-accepting paths). The scanner then reports `ReceivedOutput`s that are not economically spendable:

- They are tracked as received value yet spending them is always net-negative (each input adds ~57.5 vbytes of weight while contributing ~0 sats), so the "funds" can never be realized.
- If the processor ever includes such outputs in a `SignableTransaction`, they inflate `needed_fee` while adding nothing to `input_sat`, which can push a constructible transaction into `NotEnoughFunds` and cause a spurious signing/transaction failure — the same "functions that require the value revert" DoS shape as the reference finding (`lend()`/`withdrawLend()` reverting on a 0-value `safeTransfer`).

### Likelihood Explanation
Creating the triggering output requires only a valid Bitcoin transaction an attacker fully controls; zero/sub-dust outputs violate relay *policy*, not consensus, so a miner relationship or non-standard-accepting path suffices. Once the output is confirmed, the scanner accepts it deterministically — there is no randomness or threshold cooperation needed. The value check is absent in a single, unconditional code path.

### Recommendation
Enforce a minimum-value guard on received outputs, mirroring the existing `DUST` guard already applied to payments and change:

```rust
// Scanner::scan_transaction
if let Some(offset) = self.scripts.get(&output.script_pubkey) {
  if output.value.to_sat() >= DUST {
    res.push(ReceivedOutput { offset: *offset, output: output.clone(),
      outpoint: OutPoint::new(tx.compute_txid(), vout) });
  }
}
```

Equivalently, reject zero/sub-dust `ReceivedOutput`s in `SignableTransaction::new` alongside the existing `DustPayment` check, so worthless inputs can never be counted as spendable funds or silently drag `needed_fee` above `input_sat`.

### Proof of Concept
```rust
// regtest / unit context
let keys = /* vault ThresholdKeys<Secp256k1>, tweaked via tweak_keys() */;
let mut scanner = Scanner::new(keys.group_key()).unwrap();

// Attacker crafts a consensus-valid tx paying 0 sats to the vault script
let attacker_tx = Transaction {
  version: Version(2),
  lock_time: LockTime::ZERO,
  input: vec![/* any spendable input of attacker's own */],
  output: vec![TxOut {
    value: Amount::ZERO,                       // consensus-valid, non-standard to relay
    script_pubkey: p2tr_script_buf(keys.group_key()).unwrap(),
  }],
};

let received = scanner.scan_transaction(&attacker_tx);
assert_eq!(received.len(), 1);                 // 0-value output accepted as received
assert_eq!(received[0].value(), 0);            // no minimum enforced

// Downstream: the worthless input inflates needed_fee but adds nothing
let payments = vec![(dest_script, 10_000u64)];
let res = SignableTransaction::new(vec![received[0].clone()], &payments, None, None, 10);
assert!(matches!(res, Err(TransactionError::NotEnoughFunds { .. })));
```

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
