## Analysis

The `[M-08]` report's core broken invariant is: **an admin/governance parameter change silently invalidates an already-accruing (but not-yet-settled) reward calculation**, because the reward formula reads the *current* rate to price a span of unclaimed activity rather than pricing each sub-span at the rate that was actually in effect.

Hyperbridge's `pallet-consensus-incentives` reproduces this exact pattern for relayer consensus-delivery rewards.

`modules/pallets/consensus-incentives/src/impls.rs` computes rewards as `blocks_since_watermark × current_block_cost`: [1](#0-0) 

The watermark (`LastRewardedHeight`) is only advanced **inside** the `if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(...)` branch: [2](#0-1) 

Governance can remove a chain's incentive rate entirely via `remove_incentives`, which deletes the `StateMachinesCostPerBlock` entry: [3](#0-2) 

and later re-enable it at a new rate via `update_cost_per_block`: [4](#0-3) 

### Title
Stale reward watermark lets relayers collect treasury payouts for blocks delivered while incentives were disabled, priced at the wrong rate - (`modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`process_message` only advances `LastRewardedHeight` when `StateMachinesCostPerBlock` is `Some`. While incentives are disabled for a state machine (`remove_incentives`), consensus messages continue to be delivered and `latest_commitment_height` keeps advancing, but the watermark freezes at its last value because the whole reward branch is skipped. When governance later re-enables incentives with `update_cost_per_block`, the very next processed message prices the **entire frozen span** — including all the blocks delivered during the disabled period — at the newly-set rate, and pays it out from the treasury in one shot.

### Finding Description
`calculate_reward` treats the accrual span as a single homogeneous rate window:
```
blocks = latest_height - baseline (LastRewardedHeight or previous_height)
reward = blocks * block_cost   // block_cost is whatever is currently stored
```
There is no per-block or per-epoch rate history; the single scalar `block_cost` is applied uniformly to the whole `[baseline, latest_height]` range. This mirrors the reported `rewardPerToken`/boost-period bug: a rate change does not just affect blocks going forward, it retroactively re-prices unclaimed history.

Because the watermark update is gated behind `if let Some(block_cost) = ...`, any period during which incentives are turned off is **not skipped from the reward span** — it's simply deferred and later folded into whatever rate is active when incentives resume. This differs from the original report's direction (loss) but is the same broken invariant (accrual span priced by the wrong, currently-active rate rather than the rate(s) actually in force during that span), and here it manifests as an unbounded, unintended treasury payout rather than a user loss.

### Impact Explanation
This is a direct loss-of-funds path for the protocol treasury: a normal relayer, performing only the ordinary act of delivering the next consensus proof after a rate change, triggers a reward transfer sized by a span that was never supposed to be paid at all (the disabled window) or supposed to be paid at the old, possibly much lower, rate. `T::Currency::transfer` moves treasury funds unconditionally once `calculate_reward` returns non-zero: [5](#0-4) 

No proof, admin action, or malicious relayer input is required beyond normal message delivery — the corrupted state is the stale `LastRewardedHeight` watermark itself.

### Likelihood Explanation
`remove_incentives` / `update_cost_per_block` are ordinary, expected governance operations (pausing incentives for a misbehaving or paused chain, adjusting economics), not one-off edge cases. Any relayer that continues delivering consensus proofs during a disabled window, then delivers again after re-enable, automatically triggers the mispriced payout — this requires no coordination or malicious behavior, just the pallet's designed operational lifecycle.

### Recommendation
Do not gate the watermark update on `block_cost` being `Some`. On `remove_incentives`, either (a) advance `LastRewardedHeight` to the current `latest_commitment_height` so the disabled span is excluded from any future reward calculation, or (b) record the historical `(height_range, rate)` segments so `calculate_reward` can price each segment at the rate that was actually active during it, analogous to snapshotting `rewardPerTokenStored` before a boost-period change in the original report's recommendation.

### Proof of Concept
1. Governance calls `update_cost_per_block(sm, 100)` for state machine `sm`.
2. Relayer delivers consensus proofs advancing `sm` from height 0 → 1000; a message is processed and paid, `LastRewardedHeight[sm] = 1000`.
3. Governance calls `remove_incentives(sm)`, deleting the rate entry.
4. Relayer keeps delivering proofs; `sm`'s commitment height advances 1000 → 5000. Each `process_message` call hits the `if let Some(block_cost)` branch as `None` and returns early — `LastRewardedHeight` stays at `1000`.
5. Governance calls `update_cost_per_block(sm, 100)` again (re-enable, same or different rate).
6. Relayer delivers the next proof (height 5000 → 5001). `calculate_reward` computes `baseline = 1000`, `blocks = 4001`, `reward = 4001 * 100` — the treasury pays out for the entire disabled 1000→5000 window it was never supposed to reward, in a single transfer. [6](#0-5)

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	/// Calculate the reward for a message based on the state machine id
	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)

	impl<T: Config> Pallet<T> {
		/// Update cost per block for a state machine
		#[pallet::call_index(0)]
		#[pallet::weight(T::WeightInfo::update_cost_per_block())]
		pub fn update_cost_per_block(
			origin: OriginFor<T>,
			state_machine_id: StateMachineId,
			cost_per_block: <T as pallet_ismp::Config>::Balance,
		) -> DispatchResult {
			T::IncentivesOrigin::ensure_origin(origin)?;

			StateMachinesCostPerBlock::<T>::mutate(state_machine_id.clone(), |maybe_cost| {
				*maybe_cost = Some(cost_per_block);
			});

			Self::deposit_event(Event::<T>::StateMachineCostPerBlockUpdated {
				state_machine_id,
				cost_per_block,
			});

			Ok(())
		}
