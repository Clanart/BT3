### Title
Enabling the non-default `UseConsoleLog` debug option permanently mutates the shared global precompile maps, corrupting precompile dispatch for all subsequent EVM executions - (File: blockchain/vm/precompiles.go)

### Summary
`EVM.GetPrecompiledContractMap` is intended to return a per-call, per-caller precompile lookup map, optionally augmented with the debug-only `console.log` precompile when the node operator sets `UseConsoleLog` in `vm.Config`. However, the underlying map it augments is a direct reference to a package-level global variable (e.g. `PrecompiledContractsIstanbul`, `PrecompiledContractsCancun`, etc.), not a fresh copy. Writing `precompiles[consoleLogContractAddress] = &consoleLog{}` into that returned map permanently inserts the entry into the shared global, affecting every future EVM instance and every future transaction/call processed by that node process — even ones that do not have `UseConsoleLog` enabled.

### Finding Description
`getPrecompiledContractForVersion` selects and returns one of several package-level `var` maps based on `VmVersion`/fork rules: [1](#0-0) 

These are the same global maps used everywhere precompile membership/dispatch is decided, including `run()` (`precompiles := evm.GetPrecompiledContractMap(contract.CallerAddress); if p := precompiles[*contract.CodeAddr]; p != nil { ... }`) and `isProgramAccount()`: [3](#0-2) 

`GetPrecompiledContractMap` receives that same shared reference and, whenever `evm.Config.UseConsoleLog` is true, mutates it directly:
```go
func (evm *EVM) GetPrecompiledContractMap(addr common.Address) map[common.Address]PrecompiledContract {
    precompiles := evm.getPrecompiledContractForVersion(addr)
    if evm.Config.UseConsoleLog {
        precompiles[consoleLogContractAddress] = &consoleLog{}
    }
    return precompiles
}
``` [2](#0-1) 

Once this line executes a single time on a node process (e.g. via any EVM call that is configured with `UseConsoleLog=true`, such as a debug/trace RPC call or a node started with the console-log debug flag), the address `0x000000000000000000636F6E736F6C652E6C6F67` becomes a permanent member of the relevant global fork map for the remaining lifetime of the process — including for ordinary block/transaction execution paths whose `vm.Config.UseConsoleLog` is false, because they still read the same mutated global map via `getPrecompiledContractForVersion`.

This mirrors the reported bug class exactly: a configuration flag that looks like an isolated, "safe," opt-in debug feature (`sort` added to a safelist / `UseConsoleLog` enabled for tracing) silently and permanently widens what is treated as a legitimate/allowlisted target (`--compress-program` escape hatch / permanently-injected `consoleLog` precompile entry in the shared table), independent of the per-call intent, defeating the allowlist's isolation guarantee (CWE-15/CWE-78 class: privileged/allowlist bypass via configuration side-channel).

### Impact Explanation
Because `common.IsPrecompiledContractAddress` is a fast static range check (0x0001–0x03FF) used for `evm.Call()`'s special precompiled-address handling, while the actual dispatch table used by `run()`/`isProgramAccount()` is exactly this globally shared, mutable map, once `consoleLogContractAddress` is injected into a global fork map, any code path calling that specific address on any node process sharing that map would treat it as a program account and route to `consoleLog.Run`, regardless of whether the current transaction/call intended `UseConsoleLog` to be enabled. If different validators/full nodes have inconsistent lifetime history of enabling `UseConsoleLog` (e.g., one operator runs `debug_traceCall` with console-log tracing enabled while others never do), the shared global precompile tables can diverge in content across nodes' process lifetimes, which is a direct state-divergence risk between honest nodes for any contract that (deliberately or not) targets/probes that address. This satisfies the "state divergence between honest nodes" acceptance criterion.

### Likelihood Explanation
`UseConsoleLog` is exposed as an operator-configurable node flag (`cmd/utils/flags.go`, `node/cn/config.go`, `cmd/utils/config.go`) and is also referenced in RPC-adjacent code (`api/api_eth.go`, `api/api_kaia_blockchain.go`, `node/cn/api_backend.go`), meaning it can plausibly be toggled per-call for `eth_call`/`debug_traceCall`-style flows without a full node restart. Any single execution with this flag set (even a read-only unprivileged simulate/call/trace RPC request) is sufficient to trigger the permanent global mutation, making the trigger trivially reachable by anyone able to invoke that call/trace endpoint — no special privilege beyond RPC access is required for the mutation to occur, matching the "public-RPC caller" reachable actor in scope.

### Recommendation
Do not mutate the shared package-level precompile maps in `GetPrecompiledContractMap`. Instead, build a fresh, per-call `map[common.Address]PrecompiledContract` (cloning the selected base map) before optionally adding `consoleLog`, so the debug-only entry is scoped strictly to EVM instances/calls that actually opted into `UseConsoleLog`, leaving the shared global fork maps immutable read-only tables as originally intended.

### Proof of Concept
1. Configure/execute a single EVM call (e.g., via a debug trace or local call path) with `vm.Config.UseConsoleLog = true`. This calls `evm.GetPrecompiledContractMap(...)`, which executes `precompiles[consoleLogContractAddress] = &consoleLog{}` on the shared global map returned by `getPrecompiledContractForVersion` (e.g. `PrecompiledContractsCancun`). [2](#0-1) 
2. In any subsequent, unrelated transaction/call processed by the same node process with `UseConsoleLog = false`, invoke `evm.Call` targeting `0x000000000000000000636F6E736F6C652E6C6F67`. Because `evm.chainRules` maps to the same global (e.g. Cancun) table, `isProgramAccount`/`run()` will find the now-permanently-inserted `consoleLog` entry and dispatch to it, even though this call never requested console-log behavior. [3](#0-2) 
3. Compare behavior across two node processes where one has ever executed step 1 and the other has not — they will diverge in whether that address is treated as a program account, demonstrating state/behavior divergence rooted purely in incidental, non-consensus configuration history rather than deterministic chain state. (Full confirmation that this creates on-chain consensus-visible state divergence, versus only affecting local `eth_call`/trace results, would require exercising the exact code paths that set `vm.Config.UseConsoleLog` end-to-end, which was not fully traced in this review — noted as a residual uncertainty.)

func (evm *EVM) getPrecompiledContractForVersion(addr common.Address) map[common.Address]PrecompiledContract {
	// VmVersion means that the contract uses the precompiled contract map at the deployment time.
	// Also, it follows old map's gas price & computation cost.

	// Get vmVersion from addr only if the addr is a contract address.
	// If new "VmVersion" is added, add new if clause below
	if vmVersion, ok := evm.StateDB.GetVmVersion(addr); ok && vmVersion == params.VmVersion0 {
		// Without VmVersion0, precompiled contract address 0x09-0x0b won't work properly
		// with the contracts deployed before istanbulHF
		return PrecompiledContractsByzantium
	}

	switch {
	case evm.chainRules.IsOsaka:
		return PrecompiledContractsOsaka
	case evm.chainRules.IsPrague:
		return PrecompiledContractsPrague
	case evm.chainRules.IsCancun:
		return PrecompiledContractsCancun
	case evm.chainRules.IsKore:
		return PrecompiledContractsKore
	case evm.chainRules.IsIstanbul:
		return PrecompiledContractsIstanbul
	default:
		return PrecompiledContractsByzantium
	}
