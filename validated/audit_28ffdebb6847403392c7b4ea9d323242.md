### Title
Half-aggregation `weight()` does not bind Rs or keys, enabling universal aggregate signature forgery - ([File: crypto/schnorr/src/aggregate.rs](crypto/schnorr/src/aggregate.rs))

### Summary
`SchnorrAggregate::verify` in `crypto/schnorr/src/aggregate.rs` implements the half-aggregation scheme of eprint 2021/350, but the per-signature weight `z_i` is derived from a transcript that commits **only to the challenges** — not to the nonce commitments `R_i` or the public keys. The referenced scheme requires the weight to bind the full signature list. Because the weights are fully predictable before any `R` is chosen, an unprivileged attacker can compute a point `R_n` that makes the verification equation hold for arbitrary keys/messages they never signed.

### Finding Description
`weight()` (aggregate.rs:22-65) draws bytes from `digest`, which in `verify` is initialized as `DigestTranscript::<C::H>::new(dst)`, domain-separated with `b"signatures"`, and then fed only `append_message(b"challenge", ...)` for each challenge (lines 132-136). `Rs` and `keys` are never appended.

Verification checks:

```
sum_i z_i·R_i  +  sum_i z_i·c_i·A_i  −  s·G  ==  0
```

All `z_i`, `c_i`, and `A_i` are known to an attacker who sees the claimed `(key, message)` list. The attacker therefore:

1. Picks arbitrary `s` (e.g., zero) and arbitrary `R_1..R_{n-1}`.
2. Computes `R_n = (1/z_n)·( s·G − Σ_i z_i·c_i·A_i − Σ_{i<n} z_i·R_i )`, a pure public multiexp.
3. Serializes `SchnorrAggregate { Rs, s }`; `read` accepts it since `read_G` enforces canonicality but not non-identity.

The batch equation then holds by construction, and `verify` returns `true` — a forged aggregate signature over keys the attacker does not control. In eprint 2021/350, `z_i = H(L, i)` where `L` binds every `(pk, R, m)` triple, which is exactly what prevents this solving-for-`R_n` attack; Serai's comment at line 27 invokes that paper but the implementation omits the binding.

### Impact Explanation
Any verifier relying on `SchnorrAggregate::verify` accepts an aggregate "signature" attesting that a set of public keys signed messages they never signed — a forged signature, reachable purely from public inputs (`SchnorrAggregate::read` + `verify`).

### Likelihood Explanation
The attacker needs only the public keys and the challenges (deterministic functions of key/nonce/message per the caller's challenge construction, all public or attacker-influenced). No secret material, collusion, or malicious-validator assumption is required.

### Recommendation
Bind all `R_i` and public keys (and ideally each challenge in order) into the digest before deriving weights — e.g., `append_message(b"R", R.to_bytes())` and `append_message(b"key", key.to_bytes())` per entry — matching the `L` commitment in eprint 2021/350, and update `SchnorrAggregator` symmetrically. Optionally reject identity `R` values in `SchnorrAggregate::read`.

### Proof of Concept
For `keys_and_challenges = [(A_1, c_1), …, (A_n, c_n)]`:

```rust
// Reproduce the digest locally
let mut digest = DigestTranscript::<C::H>::new(dst);
digest.domain_separate(b"signatures");
for (_, c) in &entries { digest.append_message(b"challenge", c.to_repr()); }
let z: Vec<C::F> = entries.iter().map(|_| weight(&mut digest)).collect();

// Forge
let s = C::F::ZERO;
let mut Rs: Vec<C::G> = (0..n-1).map(|_| C::generator() * C::random_nonzero_F(rng)).collect();
let mut acc = s * C::generator();          // s·G
for i in 0..n { acc -= z[i] * entries[i].0 * entries[i].1; } // − Σ z_i c_i A_i
for i in 0..n-1 { acc -= z[i] * Rs[i]; }                     // − Σ z_i R_i
Rs.push(acc * z[n-1].invert().unwrap());
SchnorrAggregate { Rs, s }.verify(dst, &entries) // → true
```
