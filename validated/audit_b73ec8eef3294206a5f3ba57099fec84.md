### Title
`SignableTransaction` computes weight and fee without the OP_RETURN output, underpaying the requested fee rate - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
`SignableTransaction::new` pushes the `data` OP_RETURN output into `tx_outs` (the actual transaction outputs), but computes `weight`, `vbytes`, `needed_fee`, the change amount, and the `MAX_STANDARD_TX_WEIGHT` check using only `payments` and `change` — never including the OP_RETURN output. Analogous to the Teller bug where the gross principal is used instead of the net remaining amount, the fee accounting here is performed against a transaction that is not the one actually built: the signed transaction is larger than the one the fee was priced for.

### Finding Description
In `networks/bitcoin/src/wallet/send.rs`, `SignableTransaction::new` constructs `tx_outs` including a zero-valued OP_RETURN output when `data` is supplied (lines 193–202). However, `calculate_weight_vbytes(tx_ins.len(), payments, None)` (line 204) and the change-path call with `Some(&change)` (lines 225–226) are invoked with `payments`, which does not contain the OP_RETURN entry. Consequently:

- `needed_fee = fee_per_vbyte * vbytes` (line 206) is priced for a smaller transaction than the one signed.
- The change value `input_sat - (payment_sat + fee_with_change)` (line 228) uses that underpriced fee, so the change output is inflated relative to the intended rate and the real fee rate is lower than `fee_per_vbyte`.
- `fee()` (lines 138–141) still returns `sum(inputs) - sum(outputs)`, so the reported fee is internally consistent while being below the caller-requested rate.
- The `MAX_STANDARD_TX_WEIGHT` bound (line 241) is checked against `weight` that excludes the OP_RETURN output, so a transaction can be constructed that exceeds standard weight policy by up to the size of the data payload.
- The `TooLowFee` check (line 211) compares `needed_fee` against the minimum relay fee for the underestimated `vbytes`; the actual transaction's vsize is larger, so it can fall below the true minimum relay fee and be rejected by the network even though the check passed.

The caller-facing contract in `needed_fee` is "the fee necessary for this transaction to achieve the fee rate specified" (lines 129–135) — that guarantee does not hold whenever `data.is_some()`.

### Impact Explanation
Any unprivileged party able to cause a transaction carrying `data` to be built through this API obtains a transaction paying strictly less than the requested fee rate. With an 80-byte payload (the maximum allowed, checked at line 171), the shortfall is roughly `fee_per_vbyte * (data_len + ~11)` vbytes. At the boundary, the transaction can pay under the minimum relay fee for its actual size and be dropped by the mempool, leaving the inputs unspent/unspendable until recreated — "funds reported as handled that are not actually spendable at the intended rate." Additionally, the standardness weight check can be bypassed, producing transactions nodes refuse to relay.

### Likelihood Explanation
Reachable whenever `SignableTransaction::new` is called with `Some(data)`. The underestimation is deterministic — it occurs on every such call, requiring no race or adversary-controlled chain state, only a supplied `data` payload. Severity is bounded because the transaction still internally balances (change absorbs the difference), so funds are not directly stolen; the concrete harm is a silently degraded fee rate and potential relay failure.

### Recommendation
Include the OP_RETURN output in the weight/vbytes calculation — e.g., build the full `payments + data + change` output list before calling `calculate_weight_vbytes`, or pass `tx_outs`-equivalent script/length data into it, so `needed_fee`, the change amount, the `TooLowFee` check, and the `MAX_STANDARD_TX_WEIGHT` check all reflect the final transaction.

### Proof of Concept

```rust
// With data = Some(vec![0u8; 80]):
let tx = SignableTransaction::new(inputs, &payments, change, Some(vec![0u8; 80]), fee_per_vbyte).unwrap();
// tx.needed_fee() == fee_per_vbyte * vbytes(without OP_RETURN)
// actual tx.vsize() > vbytes used, so tx.fee() < fee_per_vbyte * tx.vsize()
// i.e., the effective fee rate is strictly below the requested rate.
```
