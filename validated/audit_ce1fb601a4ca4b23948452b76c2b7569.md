### Title
Missing minimum-value validation on `kip71.gastarget` governance parameter allows division-by-zero panic in Magma base fee calculation - (File: kaiax/gov/param.go)

### Summary
The KIP-71 (Magma) base-fee governance parameter `kip71.gastarget` is registered with a `noopFormatChecker`, meaning any `uint64` value — including `0` — passes validation when set via header-governance vote or contract governance (`GovParam` contract). By contrast, the sibling parameter `kip71.basefeedenominator` explicitly rejects `0` in its `FormatChecker`. `GasTarget` is later used as a divisor in `NextMagmaBlockBaseFee`, so setting it to `0` causes every node to panic (division by zero) while computing/verifying the base fee of every subsequent block, halting the chain.

### Finding Description
`Kip71GasTarget`'s parameter definition uses `noopFormatChecker`, which always returns `true`, so no minimum/non-zero constraint is enforced: [1](#0-0) 

This is inconsistent with the neighboring `Kip71BaseFeeDenominator` parameter, which explicitly guards against `0`: [2](#0-1) 

Format checking is the only guard applied both for header-governance votes (`NewVoteData`) and for `PartialParamSet.Add` used by contract governance parsing: [3](#0-2) [4](#0-3) 

`checkConsistency` in header governance additionally validates several KIP-71 parameters (e.g., lower/upper bound base fee ordering), but `Kip71GasTarget` falls into the "no additional checks" bucket and is accepted as long as it passes the (trivial) format check: [5](#0-4) 

The resulting `ParamSet.GasTarget` value is converted directly into `KIP71Config.GasTarget` via `ToKip71Config()`: [6](#0-5) 

`KIP71Config.GasTarget` is then used as a divisor in `NextMagmaBlockBaseFee`, which every node calls to compute/verify the next block's base fee: [7](#0-6) 

If `GasTarget == 0`, then for any block with `parentGasUsed > 0` (i.e., virtually every real block, since `parentGasUsed > gasTarget` becomes true), the code executes `x.Div(x, new(big.Int).SetUint64(gasTarget))`, which is a division by zero and panics in Go's `math/big` package (unlike EVM division, `big.Int.Div` panics on zero divisor rather than returning 0).

### Impact Explanation
A single governance vote (cast by the governing node in `single` mode, or via the on-chain `GovParam` contract per KIP-81) that sets `kip71.gastarget` to `0` becomes ratified and effective at the next epoch boundary. From that point, all full nodes computing or validating any post-Magma block panic deterministically inside `NextMagmaBlockBaseFee`/`VerifyMagmaHeader`, since block header validation and block building both invoke this function. This causes a synchronized, deterministic crash across the entire honest network — a full chain halt / denial of service — rather than a localized fraud-protection bypass as in the referenced report. This is more severe than the original "delayBlocks" issue because it does not merely weaken a security mechanism; it can stop block production/verification entirely across the network.

### Likelihood Explanation
The only prerequisite is a single ratified governance vote for `kip71.gastarget = 0`. There is no lower bound, no consistency check against `gastarget` (unlike `LowerBoundBaseFee`/`UpperBoundBaseFee`, which are cross-validated against each other), and the format checker unconditionally accepts the value. This mirrors exactly the class of bug in the report (owner/governing party can set a critical governance parameter to an unsafe low value without any minimum enforcement), but here the blast radius is a hard node panic instead of degraded fraud-window protection, making it reachable by design through the existing governance parameter-setting path.

### Recommendation
Add a non-zero (and preferably a sane minimum) `FormatChecker` for `Kip71GasTarget`, consistent with `Kip71BaseFeeDenominator`'s `v != 0` check, e.g.:
```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0
    },
    ...
},
```
Additionally, consider adding a defensive guard in `NextMagmaBlockBaseFee` (similar to the existing `BaseFeeDenominator == 0` fallback) so that a `GasTarget == 0` value already present in historical/legacy configuration cannot crash the node.

### Proof of Concept
1. In `single` governance mode, the governing node (or via `GovParam` contract `setParamIn`) casts a vote: `governance_vote("kip71.gastarget", 0)`.
2. The vote passes `NewVoteData`'s format check (`noopFormatChecker` always true) and `checkConsistency` (no dedicated case), so it is accepted and ratified at the next epoch boundary.
3. Starting from the block after ratification takes effect, `GetParamSet(blockNum).GasTarget == 0`, and `ToKip71Config()` propagates this into `KIP71Config.GasTarget`.
4. When building/verifying the next Magma block with `parentGasUsed > 0` (virtually guaranteed), `NextMagmaBlockBaseFee` executes `x.Div(x, new(big.Int).SetUint64(0))`, which panics in `math/big`, crashing every node processing that block.
