### Title
Unverified prevout `TxOut` in `ReceivedOutput` is committed into the Taproot sighash, letting untrusted serialized outputs cause signatures for an unbroadcastable transaction / permanently stalled spend - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
`SignableTransaction::multisig` builds per-input signing machines from `self.prevouts`, and `TransactionSignMachine::sign` commits `Prevouts::All(&self.tx.prevouts)` into `taproot_key_spend_signature_hash`. `prevouts` are the `TxOut`s deserialized by `ReceivedOutput::read`, which accepts attacker-controlled `value` and `outpoint` fields. `multisig` only verifies `p2tr_script_buf(offset.group_key()) == self.prevouts[i].script_pubkey` — it never checks that the outpoint exists, or that the prevout `value` matches the actual on-chain UTXO amount. Because BIP-341 key-path sighashes commit to every input's prevout amount, a single byte difference in the claimed value produces valid-looking FROST signature shares that combine into signatures which are invalid on-chain. This is the same bug class as the external report: an internal accounting value (the claimed prevout amount) diverges from the real spendable amount, and the mismatch surfaces only at the point of use, where the operation fails.

### Impact Explanation
An unprivileged party that feeds malicious bytes to `ReceivedOutput::read` (which performs `TxOut::consensus_decode` / `OutPoint::consensus_decode` with no chain validation) can inject a `prevouts` entry whose `value` exceeds the real UTXO's value, or reference a non-existent outpoint. Consequences:

- The multisig signs a sighash committing to false prevout amounts; the completed transaction fails consensus/policy validation, so the spend is unspendable as signed — the analog of `unstake`/`unstakePrincipal` reverting because `reward - paidOutReward` underflows: the accounted value doesn't match reality at the moment of finalization.
- Because each FROST signing session consumes preprocesses (`TransactionMachine::preprocess` / `sign`), each poisoned `ReceivedOutput` wastes a full threshold signing round and can permanently stall withdrawals for the affected outpoint until the discrepancy is manually detected — the scheduler cannot "wait" its way out, matching the reported bug where a second unstake request can't fix the first.

There is no recovery path in `send.rs` equivalent to "recompute the reward": the signed bytes are bound to the forged prevout set.

### Likelihood Explanation
Reachable wherever serialized `ReceivedOutput`s cross a trust boundary (e.g., outputs relayed between processes/participants via `serialize`/`read` rather than freshly produced by `scan_transaction`/`scan_block`, which take `value` from authenticated chain data). `ReceivedOutput::read` explicitly exposes this untrusted-bytes surface. Medium likelihood: it requires the integration to accept peer-supplied output lists, but the failure is deterministic once fed.

### Recommendation
In `SignableTransaction::multisig` (or `SignableTransaction::new`), verify each `ReceivedOutput` against the chain before signing: confirm `outpoint` resolves to a real UTXO whose `value` and `script_pubkey` equal `prevouts[i]`. Alternatively, authenticate the serialization boundary so `prevouts` can only originate from `Scanner` results. Do not treat deserialized `TxOut` values as authoritative accounting of spendable funds — derive them from chain state, analogous to recomputing `rewardToSend` via `getRewardForStakingStore` instead of trusting `currentStore.reward - currentStore.paidOutReward`.

### Proof of Concept
```rust
use bitcoin::{OutPoint, TxOut, Amount, ScriptBuf, consensus::encode::serialize};
use frost::curve::Secp256k1;
use bitcoin_serai::wallet::ReceivedOutput;

// Take an honestly scanned output `honest: ReceivedOutput`.
// Rewrite its TxOut with an inflated amount while keeping the same script_pubkey.
let mut evil_buf = Vec::new();
honest.offset().serialize(/* .. */); // write offset bytes
let forged = TxOut {
  value: Amount::from_sat(honest.value() + 1), // claimed amount != real UTXO amount
  script_pubkey: honest.output().script_pubkey.clone(),
};
// serialize(forged) + serialize(honest.outpoint()) -> bytes fed to ReceivedOutput::read
let evil = ReceivedOutput::read(&mut &evil_bytes[..]).unwrap();

// SignableTransaction::new(vec![evil], &payments, change, None, fee)
//   -> multisig(&keys) succeeds: p2tr_script_buf check only covers script_pubkey
//   -> sign() commits Prevouts::All(&prevouts) with value+1 into the sighash
//   -> complete() returns a Transaction whose witness sigs are invalid on-chain.
// Result: threshold signers burned a signing session; the real UTXO is unspendable
// under the produced transaction, permanently DoS-ing this spend until corrected.
```
