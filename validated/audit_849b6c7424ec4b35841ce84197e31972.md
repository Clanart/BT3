## Finding: valid, but the injection point is not `getEffectiveBranchName` itself — it's the downstream `addWorktree()` call that lacks an `--` end-of-options guard

### Summary

`getEffectiveBranchName` in `app/src/ui/worktrees/add-worktree-dialog.tsx` is a pure string accessor — it returns either the raw, user-typed `branchName` state or `sanitizedRefName(worktreeName)`, and does not itself build any argv or spawn anything [1](#0-0) . The real sink is `addWorktree()` in `app/src/lib/git/worktree.ts`, which consumes this value (or a `Branch` object's `name`/`ref`/`nameWithoutRemote` derived from it) and constructs the `git worktree add` argv without inserting a `--` separator before the positional `path`/`commitish` arguments: [2](#0-1) 

### Finding Description

- `onSubmit` calls `getEffectiveBranchName()` and then looks the result up against `this.props.allBranches` (branches enumerated from the actual, possibly attacker-controlled/cloned repository) [3](#0-2) .
- Three call shapes feed `addWorktree`:
  - Remote branch match: `createBranch: branch.nameWithoutRemote`, `commitish: branch.ref` — both derived from ref names actually present in the repository (attacker can name a branch/tag arbitrarily within `git-check-ref-format` limits).
  - Local branch match: `commitish: branch.name`.
  - No match ("new branch"): `createBranch: effectiveBranchName` — the raw, **unsanitized** user-typed `branchName` (only the worktree-name fallback path goes through `sanitizedRefName`, which strips leading `-`/`+`) [1](#0-0) [4](#0-3) .
- `addWorktree` builds `args = ['worktree', 'add']`, optionally pushes `-b`, `createBranch`, then pushes `path`, then optionally `commitish` — with no `--` inserted before `path`/`commitish` [5](#0-4) .

The `-b <value>` pair is not exploitable via flag injection because the value is always consumed positionally as `-b`'s argument regardless of its content. The unguarded arguments are `path` and `commitish`: if either begins with `-`, `git worktree add` will attempt to parse it as an option rather than a positional operand, since there is no `--` boundary.

### Impact / Likelihood Explanation

Exploitability is limited compared to the theoretical "Critical" template because:
- `commitish` values sourced from `Branch.ref`/`Branch.name` are always well-formed git ref strings (e.g., `refs/remotes/origin/...` for remote branches), and `git-check-ref-format` already rejects many dangerous constructs upstream when the ref was created/fetched.
- `path` originates from the local `RepositoryPath` file-picker component, not directly from repository/remote text.
- `git()` invocations in this codebase use array-based argv (not a shell), so shell-metacharacter injection is not applicable here — only git-flag injection via a leading `-`/`--` token is theoretically in scope.
- I could not fully verify (index limits) whether git actually permits creating a branch/ref whose short name begins with `-` in a way that would survive into `Branch.name`/`Branch.ref` as parsed by this app, which is required for this to be practically triggerable from a malicious remote/cloned repository.

### Recommendation

Insert git's end-of-options marker before positional operands in `addWorktree()`:
```ts
const args = ['worktree', 'add']
if (options.createBranch) {
  args.push('-b', options.createBranch)
}
args.push('--', path, ...(options.commitish ? [options.commitish] : []))
```
This ensures `path` and `commitish` are always treated as inert operands even if they begin with `-`/`--`, regardless of their origin (typed input or repository-provided ref names).

### Proof of Concept

Not independently validated end-to-end (would require confirming git accepts a `-`-leading ref name that survives into `Branch.name`), but the structural gap is directly visible: [5](#0-4)  lacks a `--` separator that other worktree functions in the same file also omit, e.g. `moveWorktree`/`removeWorktree` similarly push `oldPath`/`newPath`/`worktreePath` without a `--` guard [6](#0-5) .

```typescript
export async function addWorktree(
  repository: Repository,
  path: string,
  options: {
    /** Branch name used with -b (create new branch) */
    readonly createBranch?: string
    /** Commit-ish to check out (branch name, ref, or SHA) */
    readonly commitish?: string
  } = {}
): Promise<void> {
  const args = ['worktree', 'add']

  if (options.createBranch) {
    args.push('-b', options.createBranch)
  }

  args.push(path)

  if (options.commitish) {
    args.push(options.commitish)
  }

  await git(args, repository.path, 'addWorktree')
}
```

```typescript
export async function removeWorktree(
  repositoryPath: string,
  worktreePath: string,
  force: boolean = false
): Promise<void> {
  const args = ['worktree', 'remove']
  if (force) {
    args.push('--force')
  }
  args.push(worktreePath)

  await git(args, repositoryPath, 'removeWorktree')
}

export async function moveWorktree(
  repository: Repository,
  oldPath: string,
  newPath: string
): Promise<void> {
  await git(
    ['worktree', 'move', oldPath, newPath],
    repository.path,
    'moveWorktree'
  )
}
```
