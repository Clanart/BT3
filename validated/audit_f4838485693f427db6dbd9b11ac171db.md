**Rationale:** `create_optimistic_payout_txhandler` builds a transaction that spends two specific UTXOs: the user's registered withdrawal outpoint (`input_utxo.outpoint`) and the `UtxoVout::DepositInMove` output of the deposit's `move_to_vault` transaction [1](#0-0) . That same `DepositInMove` output is also the one spent by `create_reimburse_txhandler` in the kickoff/BitVM reimbursement path [2](#0-1) . Because both settlement paths (optimistic payout vs. kickoff+reimburse) target the identical Bitcoin outpoint, Bitcoin consensus itself — not this function — enforces that only one of the two competing spends can ever be confirmed; the loser is rejected as a double-spend. This makes "two vaults for one payout" structurally impossible regardless of connector reuse, round-racing, or payout-record visibility, since there is only one spendable output to race for, not two.

Supporting guards also close the specific sub-attacks implied by the question:
- Both the aggregator's `optimistic_payout` RPC and `Verifier::sign_optimistic_payout` reject signing if the withdrawal outpoint is already spent, and cross-check the DB-recorded `withdrawal_utxo`/`move_to_vault_txid` mapping (keyed 1:1 by Citrea `idx`) against attacker-supplied values before ever calling `create_optimistic_payout_txhandler` [3](#0-2) [4](#0-3) .
- The DB mapping from Citrea deposit/withdrawal index to `move_to_vault_txid`/`withdrawal_utxo` is a single upserted row per `idx`, so one withdrawal cannot be made to resolve to two different deposits/vaults [5](#0-4) .
- `insert_deposit_data_if_not_exists` uses an `ON CONFLICT DO NOTHING` unique constraint on `deposit_outpoint`, preventing divergent deposit records for the same deposit [6](#0-5) .

Since the equality "settled withdrawals == vaults spent, one-to-one" is preserved by the underlying single-spendable-UTXO model plus these existing DB/RPC checks, no attacker-controlled input (withdrawal registration timing, self-crafted UTXO, signature/sighash choice) can cause two vaults to be drained for one settled withdrawal.

    pub async fn insert_deposit_data_if_not_exists(
        &self,
        mut tx: Option<DatabaseTransaction<'_>>,
        deposit_data: &mut DepositData,
        paramset: &'static ProtocolParamset,
    ) -> Result<u32, BridgeError> {
        // compute move to vault txid
        let move_to_vault_txid = create_move_to_vault_txhandler(deposit_data, paramset)?
            .get_cached_tx()
            .compute_txid();

        let query = sqlx::query_as::<_, (i32,)>(
            "INSERT INTO deposits (deposit_outpoint, deposit_params, move_to_vault_txid)
                VALUES ($1, $2, $3)
                ON CONFLICT (deposit_outpoint) DO NOTHING
                RETURNING deposit_id",
        )
        .bind(OutPointDB(deposit_data.get_deposit_outpoint()))
        .bind(DepositParamsDB(deposit_data.clone().into()))
        .bind(TxidDB(move_to_vault_txid));

        let result =
            execute_query_with_tx!(self.connection, tx.as_deref_mut(), query, fetch_optional)?;

        // If we got a deposit_id back, that means we successfully inserted new data
        if let Some((deposit_id,)) = result {
            return Ok(u32::try_from(deposit_id).wrap_err("Failed to convert deposit id to u32")?);
        }

        // If no rows were returned, data already exists - check if it matches
        let existing_query = sqlx::query_as::<_, (i32, DepositParamsDB, TxidDB)>(
            "SELECT deposit_id, deposit_params, move_to_vault_txid FROM deposits WHERE deposit_outpoint = $1"
        )
        .bind(OutPointDB(deposit_data.get_deposit_outpoint()));

        let (existing_deposit_id, existing_deposit_params, existing_move_txid): (
            i32,
            DepositParamsDB,
            TxidDB,
        ) = execute_query_with_tx!(self.connection, tx, existing_query, fetch_one)?;

        let existing_deposit_data: DepositData = existing_deposit_params
            .0
            .try_into()
            .map_err(|e| eyre::eyre!("Invalid deposit params {e}"))?;

        if existing_deposit_data != *deposit_data {
            tracing::error!(
                "Deposit data mismatch: Existing {:?}, New {:?}",
                existing_deposit_data,
                deposit_data
            );
            return Err(BridgeError::DepositDataMismatch(
                deposit_data.get_deposit_outpoint(),
            ));
        }

        if existing_move_txid.0 != move_to_vault_txid {
            // This should never happen, only a sanity check
            tracing::error!(
                "Move to vault txid mismatch in set_deposit_data: Existing {:?}, New {:?}",
                existing_move_txid.0,
                move_to_vault_txid
            );
            return Err(BridgeError::DepositDataMismatch(
                deposit_data.get_deposit_outpoint(),
            ));
        }

        // If data matches, return the existing deposit_id
        Ok(u32::try_from(existing_deposit_id).wrap_err("Failed to convert deposit id to u32")?)
