### Title
DataLayer mirror coins let any unprivileged spend-bundle submitter force victim nodes into SSRF against attacker-controlled URLs - (File: `chia/data_layer/download_data.py`)

### Summary
Any user who can submit a spend bundle can create a `MIRROR_PUZZLE_HASH` coin whose memos encode an arbitrary DataLayer `launcher_id` and an arbitrary list of URLs, without proving ownership of that DataLayer store. Nodes that later sync/subscribe to that store id read these attacker-supplied URLs from chain and the `DataLayer` service automatically issues outbound HTTP requests (`http_download`/`aiohttp` calls) to them during routine subscription sync. This mirrors the Emlog SSRF pattern: attacker-controlled, unauthenticated input (URLs) is later fetched server-side without validation.

### Finding Description
The mirror puzzle is a fixed, ownerless puzzle: `create_mirror_puzzle()` curries `P2_PARENT` with `1`, producing a constant `MIRROR_PUZZLE_HASH` [1](#0-0) . `get_mirror_info()` extracts the `launcher_id` and URL list purely from a `CREATE_COIN` condition's memos, with no check that the spender is the owner of that `launcher_id`/DataLayer singleton [2](#0-1) . Because the mirror puzzle hash is fixed and public, any wallet holding funds can construct a coin spend that creates such a coin referencing someone else's store id and attacker-chosen URLs (e.g. `http://169.254.169.254/...` or an internal RPC port), independent of DataLayer ownership.

On the consuming side, `DataLayer.update_subscriptions_from_wallet()` pulls all mirror URLs for a store id from wallet RPC (`dl_get_mirrors`) and feeds them straight into `data_store.update_subscriptions_from_wallet()` as sync servers [3](#0-2) . The periodic `fetch_and_validate()` loop then iterates these `servers_info` entries and, for each, calls `insert_from_delta_file()`/`download_file()` against the URL [4](#0-3) . `download_file()` performs an actual outbound HTTP GET (`http_download`) or POST to a downloader plugin using the attacker-supplied `server_info.url` with no allowlist or private-IP filtering [5](#0-4) .

The module's own design notes acknowledge this boundary is untrusted but do not indicate any host-based restriction is enforced: "Plugin and mirror URLs are external trust inputs. Downloaded data must continue to be verified against wallet-advertised roots" — verification covers the downloaded *data*, not the destination host of the outbound request.

### Impact Explanation
Any node that subscribes to (or owns and mirrors) a DataLayer store id can be induced to send outbound HTTP requests to attacker-chosen hosts/ports, entirely triggered by an unprivileged, unauthenticated on-chain spend that anyone can broadcast. This enables internal network probing/port scanning from the victim's host, and potential SSRF against internal services or cloud metadata endpoints reachable from the node's network, with no signature or ownership requirement over the targeted DataLayer store.

### Likelihood Explanation
Likelihood is high: constructing the mirror coin requires only a standard coin spend with `CREATE_COIN` to the well-known `MIRROR_PUZZLE_HASH` and memos containing any `launcher_id` plus attacker URLs — no special privilege, no cooperation from the store owner, and no protocol validation prevents targeting a store id you don't own. Any node actively subscribing to or syncing that store will periodically fetch from the malicious URL as part of normal `fetch_and_validate()`/subscription-management cycles.

### Recommendation
- Restrict mirror coin acceptance/consumption to mirrors created by or attributable to a store's actual owner, or otherwise require an authenticated/allowlisted relationship between `launcher_id` and mirror URL submitter.
- Validate/sanitize mirror and plugin URLs before use (reject private/loopback/link-local addresses, restrict schemes/ports) in `download_data.py`'s `http_download`/`download_file` and in `DataLayer.update_subscriptions_from_wallet()`.
- Consider rate-limiting or requiring explicit user opt-in per store/URL before the service will issue outbound requests to newly observed mirror URLs.

### Proof of Concept
1. Attacker crafts and broadcasts a spend bundle that creates a coin with puzzle hash `MIRROR_PUZZLE_HASH` (from `create_mirror_puzzle()`), with `CREATE_COIN` memos `[victim_launcher_id, "http://169.254.169.254/latest/meta-data/"]`.
2. The coin confirms on chain; any full node observes it as a mirror for `victim_launcher_id` via `get_mirror_info()`.
3. A victim node that owns or subscribes to `victim_launcher_id`'s DataLayer store calls `update_subscriptions_from_wallet()`, pulling this URL into its subscription table [3](#0-2) .
4. On the next `periodically_manage_data()` cycle, `fetch_and_validate()` selects this server and calls `download_file()`, which issues an HTTP request to the attacker-controlled/internal URL [6](#0-5) , completing the SSRF.

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True
```
