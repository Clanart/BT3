### Title
Permanent, unrevoked `safe.directory` trust exception allows silent execution of an attacker-controlled repository reusing a previously trusted path - ([File: app/src/lib/git/config.ts])

### Summary
GitHub Desktop lets a user "trust" a Git working directory that Git flags as having "dubious ownership" (a directory owned by a different user than the current process). This trust decision is implemented by permanently appending the path to the global `safe.directory` Git config value via `addSafeDirectory`. There is no corresponding `removeSafeDirectory`/revocation call anywhere in the codebase — not when the repository is removed from Desktop (`_removeRepository`), not when it becomes missing, and not on any other lifecycle event. Once a path is marked safe, Git will never again warn about ownership mismatches for that exact path, for as long as the user's global gitconfig exists.

### Finding Description
The trust flow is triggered from `AddExistingRepository.onTrustDirectory` and `MissingRepository.onTrustDirectory`, both of which call `addSafeDirectory(path)`: [1](#0-0) 

`addSafeDirectory` writes the path into the user's **global** `safe.directory` list, which is a machine-wide, permanent trust exception, not scoped to a particular clone/session: [2](#0-1) 

The ownership check itself, `getRepositoryType`, only looks at whether `git rev-parse` returns the "dubious ownership" fatal error for the given `path`; if the path is already present in `safe.directory`, Git suppresses that error entirely and Desktop treats the directory as a normal, safe repository: [3](#0-2) 

Nowhere in `RepositoriesStore.removeRepository`, `AppStore._removeRepository`, or elsewhere is the corresponding `safe.directory` entry ever removed when a repository is deleted from Desktop: [4](#0-3) [5](#0-4) 

This is the same broken-invariant pattern as the referenced smart-contract bug: a security-relevant boolean/state ("trusted"/"liquidityAdded") is set to grant a privileged action, but the code path that undoes the precondition (removing liquidity / removing a repository) never resets that state, so the flag persists beyond the lifetime of the object it was meant to gate.

The corrupted/stale value is the entry for `path` in the global `safe.directory` config — it is bound only to a filesystem path string, with no binding to directory ownership identity, repository content hash, or Desktop's in-memory repository record. Once written, it silently authorizes *any* future directory that happens to occupy that path, regardless of who owns it or what it contains at that later point in time.

### Impact Explanation
`safe.directory` exists specifically to stop Git/Desktop from automatically operating on (and thus potentially executing hooks/config from) a directory that isn't owned by the current user — a mitigation against local privilege-escalation and directory-hijacking attacks (e.g., another user recreating a directory at a shared/predictable path, a symlink swap, or a directory reused after deletion on a multi-user machine or CI-adjacent environment). Because Desktop's trust decision is permanent and keyed only on the path string, an attacker who can cause a *different, untrusted* directory to later occupy a path the user previously trusted (e.g. after the user removes the original repository from Desktop and deletes the folder, or on a shared workstation) inherits that trust silently — no warning is shown, and Desktop proceeds to run Git operations (which can trigger hooks, filters, or other untrusted repo config execution) against attacker-controlled content. This bypasses the exact protection the unsafe-repository warning was designed to provide.

### Likelihood Explanation
The likelihood is Medium: it requires a plausible but not universal precondition — a path that was once trusted becoming re-populated by different, untrusted content (shared machines, restored/reused directories, external drives reused between users, or directory recreation races). The application-level guard (the `isRepositoryUnsafe` check in `AddExistingRepository`/`MissingRepository`) offers no protection here because it consults live ownership state through `getRepositoryType`, and that check is defeated once the path is in `safe.directory` — the guard simply never fires again for that path, with no user-visible indication the exception still exists or an option in Desktop to revoke it.

### Recommendation
- When a repository is removed from Desktop (`RepositoriesStore.removeRepository` / `AppStore._removeRepository`), remove the corresponding entry from the global `safe.directory` list (mirroring `addGlobalConfigValueIfMissing` with a `removeGlobalConfigValue`/`--unset-all` call for that specific path), so trust does not outlive the repository record Desktop knows about.
- Consider re-validating ownership at the moment `safe.directory` would suppress the warning (e.g., record the owner SID/UID at trust time and compare on each open) rather than trusting by path alone.
- Surface trusted directories in Desktop's settings UI so users can review and revoke them manually.

### Proof of Concept
1. User adds a repository at `C:\Users\alice\repos\foo` on a shared/multi-user Windows machine or one where the directory can later be owned by someone else; Git reports "dubious ownership," Desktop shows the "potentially unsafe" warning via `MissingRepository`/`AddExistingRepository`.
2. User clicks "Trust Repository" → `onTrustDirectory` → `addSafeDirectory(path)` writes `C:\Users\alice\repos\foo` into the global `safe.directory` list permanently.
3. User later removes this repository from Desktop (`_removeRepository`) and deletes the folder from disk — no code path unsets `safe.directory` for that path.
4. An attacker (another local account, a different process, or a later restore/sync operation) recreates a directory at the exact same path `C:\Users\alice\repos\foo`, this time owned by a different user and containing a malicious repository (e.g., with hooks or a malicious `.git/config` core.fsmonitor/hooksPath entry).
5. User re-adds the repository at that path in Desktop (e.g., via "Clone Again" from `MissingRepository`, or `Add Existing Repository`). `getRepositoryType` runs `git rev-parse`, finds the path already whitelisted in `safe.directory`, and returns `regular` — no unsafe warning is shown.
6. Desktop performs normal Git operations against the directory, executing whatever untrusted content/hooks the attacker planted, with no user awareness that the ownership-safety exception from step 2 is what silently permitted it.

Note: exploiting this requires the attacker to gain control of the same filesystem path after the user's original trust decision (e.g., shared-account reuse, directory recreation race, or reused removable media) — no malware pre-installed by the attacker on the *victim's* running session is assumed; the attacker only needs write access to that path at a later point, consistent with the "attacker controls a cloned/fetched repository" impact criteria.

```typescript
/**
 * Adds a path to the `safe.directories` configuration variable if it's not
 * already present. Adding a path to `safe.directory` will cause Git to ignore
 * if the path is owner by a different user than the current.
 */
export async function addSafeDirectory(path: string) {
  // UNC-paths on Windows need to be prefixed with `%(prefix)/`, see
  // https://github.com/git-for-windows/git/commit/e394a16023cbb62784e380f70ad8a833fb960d68
  if (__WIN32__ && path[0] === '/') {
    path = `%(prefix)/${path}`
  }

  await addGlobalConfigValueIfMissing('safe.directory', path)
}
```

```typescript
export async function getRepositoryType(path: string): Promise<RepositoryType> {
  if (!(await directoryExists(path))) {
    return { kind: 'missing' }
  }

  try {
    const result = await git(
      ['rev-parse', '--is-bare-repository', '--show-cdup', '--git-dir'],
      path,
      'getRepositoryType',
      { successExitCodes: new Set([0, 128]) }
    )

    if (result.exitCode === 0) {
      // Bare repositories will not include gitdir so we handle that separately
      if (result.stdout.startsWith('true\n')) {
        return { kind: 'bare' }
      }

      // --is-bare-repository and --show-cdup each produce a single line but
      // --git-dir could theoretically contain newlines so we parse the known
      // fields first and treat the remainder as the git dir. We use [\s\S]*
      // instead of .* for the git dir capture group because .* doesn't match
      // newlines whereas [\s\S]* matches any character including newlines.
      const match = result.stdout.match(/^(true|false)\n(.*)\n([\s\S]*)\n$/)

      if (match) {
        const [, isBare, cdup, gitDir] = match

        return isBare === 'true'
          ? { kind: 'bare' }
          : {
              kind: 'regular',
              topLevelWorkingDirectory: resolve(path, cdup),
              gitDir: resolve(path, gitDir),
            }
      }
    }

    const unsafeMatch =
      /fatal: detected dubious ownership in repository at '(.+)'/.exec(
        result.stderr
      )
    if (unsafeMatch) {
      return { kind: 'unsafe', path: unsafeMatch[1] }
    }

    return { kind: 'missing' }
```

```typescript
  public async _removeRepository(
    repository: Repository | CloningRepository,
    moveToTrash: boolean
  ): Promise<void> {
    try {
      if (moveToTrash) {
        try {
          await shell.moveItemToTrash(repository.path)
        } catch (error) {
          log.error('Failed moving repository to trash', error)

          this.emitError(
            new Error(
              `Failed to move the repository directory to ${TrashNameLabel}.\n\nA common reason for this is that the directory or one of its files is open in another program.`
            )
          )
          return
        }
      }

      if (repository instanceof CloningRepository) {
        this._removeCloningRepository(repository)
      } else {
        await this.repositoriesStore.removeRepository(repository)
      }
    } catch (err) {
      this.emitError(err)
      return
    }

    const allRepositories = await this.repositoriesStore.getAll()
    if (allRepositories.length === 0) {
      this._closeFoldout(FoldoutType.Repository)
    } else {
      this._showFoldout({ type: FoldoutType.Repository })
    }
```
