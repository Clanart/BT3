## Finding

The strongest available analog to the Wireshark SoulSeek "unbounded loop" bug class in this codebase is `is_clvm_canonical()` / `is_atom_canonical()` in [1](#0-0) . Like the CVE's dissector, this function walks an attacker-supplied byte buffer with a `while True:` loop and an implicit termination assumption (`tokens_left == 0` reached exactly at `offset == len(clvm_buffer)`), never checking `offset` against the buffer length before indexing `clvm_buffer[offset]`.

### Title
Unbounded offset-walking loop in `is_clvm_canonical`/`is_atom_canonical` lacks explicit bounds checks - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_clvm_canonical()` is called on the raw bytes of every submitted coin spend's `puzzle_reveal` and `solution` during mempool admission [2](#0-1) . It advances a manually tracked `offset` while decrementing/incrementing a `tokens_left` counter, relying on the buffer's internal structure to make `offset` land exactly at `len(clvm_buffer)` when the traversal completes. There is no `if offset >= len(clvm_buffer): raise/break` guard anywhere in the loop or in `is_atom_canonical()`'s length-prefix decoding at [3](#0-2) .

### Finding Description
Both functions index into `clvm_buffer` purely based on counters derived from the buffer's own claimed structure (pair markers `0xFF`, atom length-prefix bit patterns), never validating that the computed `atom_len`/`offset` stays within the buffer's actual size before the next `clvm_buffer[offset]` access. This mirrors exactly the class of bug fixed for CVE-2017-9346: "making loop bounds more explicit" — i.e., a parser that trusts internal length/structure fields to bound its own iteration instead of explicitly bounding against the real buffer size.

### Impact Explanation
The call site at [4](#0-3)  is inside `validate_spend_bundle()`, invoked from `add_spend_bundle()` [5](#0-4) , which in turn is called directly from `FullNode.add_transaction()` at [6](#0-5)  — with no `try/except` wrapping this specific call (unlike the `pre_validate_spendbundle` call a few lines above, which is guarded for `ValueError`/`ValidationError`). An unhandled `IndexError` here would propagate up uncaught through the transaction-processing path, potentially halting/crashing the handling task for every submitted spend bundle that triggers it — a spend-triggered transaction-processing halt.

### Likelihood Explanation
This path is reached unconditionally for every coin spend in every submitted `SpendBundle`, making it reachable by any unprivileged wallet/mempool submitter. However, exploitability depends on constructing a `puzzle_reveal`/`solution` byte sequence that (a) is valid enough to pass the earlier Rust-based CLVM execution/hash checks in `pre_validate_spendbundle`, yet (b) causes this hand-rolled Python offset walker to compute an `atom_len`/`offset` that overruns the buffer before `tokens_left` reaches zero. Whether such a discrepancy between the Rust parser's accepted encodings and this Python re-implementation's bit-pattern decoding actually exists could not be conclusively proven from static reading alone — it would need dedicated fuzzing/differential testing against the Rust CLVM deserializer to confirm.

### Recommendation
Add an explicit bound check (`offset < len(clvm_buffer)` and `offset + prefix_len < len(clvm_buffer)`) before each buffer access in both `is_clvm_canonical()` and `is_atom_canonical()`, raising a caught/expected error (not an unguarded `IndexError`) on overrun. Additionally, wrap the `add_spend_bundle()` call in `FullNode.add_transaction()` in the same defensive `try/except` used for `pre_validate_spendbundle`, so any unexpected exception from spend-bundle validation degrades to a rejected transaction rather than an unhandled crash.

### Proof of Concept
Not conclusively constructible from static analysis alone — a concrete PoC byte sequence would require confirming a discrepancy between the Rust CLVM parser's accepted/consumed length and this Python re-implementation's length-prefix decoding (`chia/full_node/mempool_manager.py:144-183`), which needs dynamic testing (e.g. differential fuzzing feeding crafted `puzzle_reveal`/`solution` bytes through both `pre_validate_spendbundle` and directly through `is_clvm_canonical`) to produce an offset overrun.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value


def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
