### Title
Excess input value is silently burned as miner fee instead of being returned as change - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
The external report describes funds sent in excess of `amount + baseFee` being permanently absorbed by the Allo contract rather than refunded. The same bug class exists in `SignableTransaction::new` in `bitcoin-serai`: when a change address *is* provided, any leftover input value that falls below the `DUST` threshold is silently folded into the transaction fee and burned to miners, with no error, no warning, and `needed_fee()` continuing to report the lower, pre-decision fee.

### Finding Description
In `networks/bitcoin/src/wallet/send.rs`, `SignableTransaction::new` computes `needed_fee = fee_per_vbyte * vbytes` and verifies `input_sat >= payment_sat + needed_fee` (lines 204-221). It then attempts to add a change output:

```rust
if let Some(change) = change {
  let (weight_with_change, vbytes_with_change) =
    Self::calculate_weight_vbytes(tx_ins.len(), payments, Some(&change));
  let fee_with_change = fee_per_vbyte * vbytes_with_change;
  if let Some(value) = input_sat.checked_sub(payment_sat + fee_with_change) {
    if value >= DUST {
      tx_outs.push(TxOut { value: Amount::from_sat(value), script_pubkey: change });
      ...
    }
  }
}
``` [1](#0-0) 

If `input_sat - payment_sat - fee_with_change` is positive but `< DUST` (546 sats), the `if value >= DUST` check fails, no change output is created, and the entire leftover becomes fee. The doc comment only documents this swallow behavior for the `change.is_none()` case ("If a change address isn't specified, all leftover funds will become part of the paid fee", lines 145-147); the dust-leftover case for a specified change address is undocumented. Additionally, `needed_fee` retains the *no-change* `vbytes` value rather than reflecting the actual `inputs - outputs` fee, so `tx.fee()` returns a value larger than `tx.needed_fee()` — contradicting the comment that `needed_fee` is "the fee necessary for this transaction to achieve the fee rate specified at construction" (lines 129-135). The upstream consumer (`processor/src/networks/bitcoin.rs::make_signable_transaction`) and `prepare_send` in `processor/src/networks/mod.rs` treat dust change as an "operating cost" accounting matter but still ship the transaction with the excess burned — the funds are never returned to the pool key.

### Impact Explanation
Caller-supplied input value above `payments + fee` is irrevocably destroyed as miner fee even though the caller explicitly requested change. This is a direct analog of "excess funds may not be withdrawn": the sats are permanently unrecoverable (not merely unspendable). `fee()` vs `needed_fee()` diverging also breaks fee accounting invariants for any consumer reconciling expected vs. actual fee.

### Likelihood Explanation
Reachable entirely through public inputs to `SignableTransaction::new` (`inputs`, `payments`, `change`, `fee_per_vbyte`) — the caller selects the UTXOs and amounts. Any input set whose remainder after `payments + fee_with_change` lands in `(0, 546)` triggers silent burn. In the processor flow this occurs naturally whenever a UTXO's balance minus amortized payments and fee produces a sub-dust remainder, which the code path explicitly tolerates.

### Recommendation
When `change` is `Some` and the leftover is non-zero but below `DUST`, either return an explicit error (e.g., `ChangeBelowDust`) so the caller can decide to add another input or absorb the cost knowingly, or redistribute the dust amount into the fee while updating `needed_fee` to `input_sat - payment_sat` so `fee() == needed_fee()`. Document the behavior in `SignableTransaction::new`'s doc comment.

### Proof of Concept
```rust
// One input of 10_000 sats, one payment of 9_000 sats, change address provided.
// Suppose fee_with_change = 500 sats -> leftover = 10_000 - 9_000 - 500 = 500 < DUST (546).
let tx = SignableTransaction::new(
  vec![input_10k],                       // ReceivedOutput worth 10_000 sats
  &[(change_addr_script, 9_000)],        // payment
  Some(change_script.clone()),           // change explicitly requested
  None,
  fee_per_vbyte,                         // chosen so fee_with_change = 500
).unwrap();

// No change output was pushed: tx has 1 output of 9_000 sats.
assert_eq!(tx.clone().sign(...).output.len(), 1);
// Actual fee is 1_000 sats (500 expected + 500 dust burned).
assert_eq!(tx.fee(), 1_000);
// needed_fee still reports only the no-change computation.
assert!(tx.needed_fee() < tx.fee());
// The 500 sats are permanently lost to miners despite a change address being given.
```
