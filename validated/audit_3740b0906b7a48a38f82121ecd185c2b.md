### Title
External sender controls `OutputType` classification by choosing which derived Taproot address to pay - ([File: processor/src/networks/bitcoin.rs](processor/src/networks/bitcoin.rs))

### Summary

Analogous to CVE-2019-12383 (a hidden attribute — UI locale — being exposed/determined by an externally measurable property — button width), Serai's Bitcoin processor lets an unprivileged on-chain sender determine the internal semantic classification (`OutputType`) of their deposit purely by which observable `script_pubkey` they pay to. The scanner matches `script_pubkey` alone, and all four Serai address types (External, Branch, Change, Forwarded) are just the group key plus publicly-computable scalar offsets. A sender can therefore force Serai to report their payment as `Change`, `Branch`, or `Forwarded` rather than `External`, bypassing the deposit-handling path and causing funds to be registered under an intent the sender fabricated.

### Finding Description

`Scanner::register_offset` inserts `p2tr_script_buf(key + G*offset) -> offset` into `self.scripts`, and `Scanner::scan_transaction` classifies an output solely by `self.scripts.get(&output.script_pubkey)` [1](#0-0) [2](#0-1) .

The processor builds this scanner with offsets derived from fixed public constants: `Secp256k1::hash_to_F(b"Serai Bitcoin Output Offset", b"branch"/"change"/"forward")` [3](#0-2) . Since the multisig `group_key` is public, any third party can compute every derived address: `key + G*branch_offset`, `key + G*change_offset`, `key + G*forward_offset`.

In `get_outputs`, the scanned offset is reverse-mapped to an `OutputType` via `kinds[offset_repr]`, and only `OutputType::External` outputs receive the transaction's embedded Serai `data` (the `InInstruction`/credit metadata) [4](#0-3) . Nothing on-chain authenticates that a payment to the `Change`/`Forwarded` script actually originated from an internal spend or forward — the sender simply chose the script.

### Impact Explanation

A depositor who pays directly to the multisig's `Forwarded`/`Change`/`Branch` addresses produces outputs that are scannable and spendable by the multisig key (they are valid P2TR outputs to `key + G*offset`), but are classified as internal bookkeeping types rather than external deposits. Because `data` is only attached for `OutputType::External`, the deposit carries no instruction, so it will not be credited/routed as a normal deposit — the funds are received by the multisig yet not spendable through the intended deposit flow, and may be misinterpreted by downstream code that assumes `Forwarded`/`Change` outputs were self-generated with known provenance. This inverts the Tor locale bug's shape: instead of the victim's hidden setting leaking, the attacker silently overrides a classification Serai assumes is trustworthy (intent provenance), yielding miscredited or stranded funds.

### Likelihood Explanation

Reachable by any unprivileged Bitcoin sender: compute the three offset scalars (fixed hash outputs), add `offset*G` to the public group key, build the P2TR script (requires the parity iteration already implemented in `register_offset`), and send to it. No collusion, key material, or protocol participation required — just a standard Bitcoin transaction.

### Recommendation

Do not infer `OutputType` from `script_pubkey` alone. Internal outputs (Change, Forwarded, Branch) should be recognized only when produced by Serai's own transactions — e.g., track expected outpoints/scripts created by `SignableTransaction`/forward flows and match on `(txid, vout)` provenance, or embed a distinguishing marker only Serai-produced transactions can contain. At minimum, `get_outputs` should treat unexpected payments to non-External offset addresses as external deposits (or flag them for operator review) rather than silently assigning an internal kind.

### Proof of Concept

// Given the public multisig group key:
let key: ProjectivePoint = group_key; // known publicly

// Recompute Serai's internal offsets (all constants public):
let forward = Secp256k1::hash_to_F(b"Serai Bitcoin Output Offset", b"forward");

// Iterate parity exactly like Scanner::register_offset to get the usable offset,
// then build the Forwarded address without ever registering it:
let mut offset = forward;
let script = loop {
  if let Some(s) = p2tr_script_buf(key + (ProjectivePoint::GENERATOR * offset)) { break s }
  offset += Scalar::ONE;
};

// Attacker sends a normal Bitcoin payment to `script`.
// processor get_outputs: Scanner::scan_transaction matches script_pubkey,
// kinds[offset] == OutputType::Forwarded, so the deposit is reported as a
// forward output with empty `data` (data only set for OutputType::External),
// never credited as an external deposit despite being an attacker payment.

  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

    let mut res = Vec::new();

      // If the vout index exceeds 2**32, stop scanning outputs

          output: output.clone(),

static BRANCH_OFFSET: OnceLock<Scalar> = OnceLock::new();
static CHANGE_OFFSET: OnceLock<Scalar> = OnceLock::new();
static FORWARD_OFFSET: OnceLock<Scalar> = OnceLock::new();

// Always construct the full scanner in order to ensure there's no collisions
fn scanner(
  key: ProjectivePoint,
) -> (Scanner, HashMap<OutputType, Scalar>, HashMap<Vec<u8>, OutputType>) {
  let mut scanner = Scanner::new(key).unwrap();
  let mut offsets = HashMap::from([(OutputType::External, Scalar::ZERO)]);

  let zero = Scalar::ZERO.to_repr();
  let zero_ref: &[u8] = zero.as_ref();
  let mut kinds = HashMap::from([(zero_ref.to_vec(), OutputType::External)]);

  let mut register = |kind, offset| {
    let offset = scanner.register_offset(offset).expect("offset collision");
    offsets.insert(kind, offset);

    let offset = offset.to_repr();
    let offset_ref: &[u8] = offset.as_ref();
    kinds.insert(offset_ref.to_vec(), kind);
  };

  register(
    OutputType::Branch,
    *BRANCH_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"branch")),
  );

    OutputType::Change,
    *CHANGE_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"change")),
  );

    OutputType::Forwarded,
