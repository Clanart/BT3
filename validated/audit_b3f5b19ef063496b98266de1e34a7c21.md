## Finding [1](#0-0) 

### Title
Purely oracle-derived `amountOutMin` in `SimplexPaymaster.swapAndDeposit` enables sandwich-attack fund loss - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster.swapAndDeposit` computes the Uniswap V2 swap's minimum output solely from Chainlink oracle prices minus a fixed `swapSlippageBps` tolerance, exactly the pattern flagged in the seed report for `AaveLeverageStrategyExtension._calculateMinRepayUnits`. Because the oracle price can lag the true market price (Chainlink's ~2% deviation threshold before a round update) and `swapSlippageBps` can be configured up to 10%, an unprivileged MEV actor watching the public mempool can sandwich the treasury's `swapAndDeposit` transaction and extract the gap between the stale oracle-bounded floor and the manipulated execution price, draining paymaster reserves that should have funded the EntryPoint deposit.

### Finding Description
`swapAndDeposit` derives `amountOutMin` exclusively from two Chainlink feeds: [2](#0-1) 

```solidity
uint256 nativeUsd = _getOraclePrice(nativeOracle, nativeOracleDecimals);
uint256 tokenUsd = _getOraclePrice(cfg.tokenOracle, cfg.tokenOracleDecimals);
uint256 expectedWei = (amountIn * tokenUsd * 1e18) / (nativeUsd * (10 ** cfg.tokenDecimals));
uint256 amountOutMin = (expectedWei * (10_000 - swapSlippageBps)) / 10_000;
```

This is then passed straight to `swapExactTokensForETH` on the host-configured Uniswap V2 router with no independent, real-time market check: [3](#0-2) 

The contract's own comment acknowledges the guard is oracle-only ("the caller cannot influence the execution price") and only defends against **mid-bundle** manipulation by a malicious UserOp, not against an ordinary public-mempool sandwich of the treasury's own transaction: [4](#0-3) 

`swapSlippageBps` is governance-configurable up to `MAX_SWAP_SLIPPAGE_BPS = 1_000` (10%) and `maxOracleAge` up to `MAX_ORACLE_AGE = 7 days`: [5](#0-4) 

Combined with Chainlink's deviation-threshold behavior (price only updates once a several-percent move accumulates), the effective floor enforced by `amountOutMin` can sit meaningfully below the true market price. Nothing in `_setParams` validates that `swapSlippageBps` and `maxOracleAge` together bound worst-case price staleness to a safe level — it only checks `p.swapSlippageBps > MAX_SWAP_SLIPPAGE_BPS` and `p.maxOracleAge > MAX_ORACLE_AGE`: [6](#0-5) 

Because `swapAndDeposit` is an ordinary, non-atomic (multi-block-visible-in-mempool) transaction gated only by `msg.sender == treasury` — not protected from front/back-running — any unprivileged party observing the pending transaction can:
1. Front-run: buy the token being swapped (or sell the native asset) on the same pool to push the price to the exact edge the oracle-derived `amountOutMin` still permits.
2. Let the treasury's swap execute at that manipulated price, extracting only the oracle-bound worst-case output.
3. Back-run: reverse the position, pocketing the difference between the manipulated execution price and the true pre-attack price — funds that come out of the paymaster's ERC-20 stablecoin reserves.

This requires no malicious relayer, prover, admin, or governance actor — the treasury's call is entirely legitimate; the attacker is a generic, unprivileged MEV participant, matching the exact primitive the external report describes for `AaveLeverageStrategyExtension`.

### Impact Explanation
Every `swapAndDeposit` invocation recycles the paymaster's accumulated ERC-20 fee revenue into native gas for the EntryPoint deposit. A sandwich attack against this call directly siphons a portion of those stablecoin reserves to the attacker, reducing funds available for the EntryPoint deposit and constituting a loss of protocol/paymaster funds — the exact "stealing or loss of funds" class explicitly in-scope for this bounty.

### Likelihood Explanation
The call is periodic/predictable (invoked by treasury whenever surplus stablecoins accumulate), publicly visible in the mempool before inclusion, and the loss margin scales directly with the configured `swapSlippageBps` (up to 10%) and oracle staleness bound (up to 7 days) — parameters within the deployed contract's own accepted governance ranges, not requiring any edge-case misconfiguration.

### Recommendation
Do not rely solely on the Chainlink oracle bound for `amountOutMin`. Either: (a) query a live on-chain TWAP/quoter for the target pool immediately before computing `amountOutMin` and take the tighter of the two bounds, or (b) split `swapAndDeposit` execution across a private/MEV-protected relay path, or (c) let the treasury pass a caller-supplied `amountOutMin` that is validated to be within a safe margin of the oracle price (the exact fix suggested — and ultimately not adopted — in the seed report), rather than trusting the oracle-derived floor alone.

### Proof of Concept
1. Governance sets `swapSlippageBps` near its cap (e.g., 500–1000 bps) via `UpdateParams`.
2. Paymaster accrues stablecoins from paymaster fee collection over time.
3. Treasury submits `swapAndDeposit(token, amountIn)`; `amountOutMin` is computed purely from `nativeOracle`/`tokenOracle` prices (see lines 309–312 above) as shown validated in `testSwapAndDepositEnforcesOracleSlippageBound`: [7](#0-6) 
which confirms the router only reverts below the oracle-derived floor, and accepts anything at or above it — i.e., any execution price within the full `swapSlippageBps` band is accepted regardless of real market conditions.
4. A watching bot detects the pending tx, front-runs by trading the pool toward the oracle-permitted floor, lets the treasury tx fill at that price, then back-runs to close the position, capturing the spread between the manipulated price and the true price — funds drained from the paymaster's swap output that would otherwise have funded the EntryPoint deposit.

    /// @notice Swaps accrued stablecoins to the native asset through the host's
    ///         V2-style router and deposits the contract's entire native balance
    ///         into the EntryPoint, so collected fees keep the paymaster funded
    ///         without a governance round-trip.
    /// @param token    A registered token; deactivated tokens remain recyclable.
    /// @param amountIn Token amount to swap; 0 (or more than the balance)
    ///                 swaps the full balance.
    /// @dev The minimum output is derived onchain from the Chainlink oracles
    ///      (markup-free price minus `swapSlippageBps`), so the caller cannot
    ///      influence the execution price. Still treasury-gated: were this
    ///      permissionless, a UserOp's calldata could invoke it mid-bundle and
    ///      swap away other ops' pending prefunds, breaking their postOp
    ///      refunds. The treasury sends ordinary transactions, which can never
    ///      execute mid-bundle.
    function swapAndDeposit(address token, uint256 amountIn) external {
        if (msg.sender != treasury) revert UnauthorizedCall();
        address router = IDispatcher(host()).uniswapV2Router();
        if (router == address(0)) revert InvalidRouter(router);
        TokenConfig memory cfg = tokenConfigs[token];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(token);

        uint256 balance = IERC20(token).balanceOf(address(this));
        if (amountIn == 0 || amountIn > balance) amountIn = balance;

        uint256 nativeUsd = _getOraclePrice(nativeOracle, nativeOracleDecimals);
        uint256 tokenUsd = _getOraclePrice(cfg.tokenOracle, cfg.tokenOracleDecimals);
        uint256 expectedWei = (amountIn * tokenUsd * 1e18) / (nativeUsd * (10 ** cfg.tokenDecimals));
        uint256 amountOutMin = (expectedWei * (10_000 - swapSlippageBps)) / 10_000;

        address[] memory path = new address[](2);
        path[0] = token;
        path[1] = IUniswapV2Router02(router).WETH();

        IERC20(token).forceApprove(router, amountIn);
        uint256[] memory amounts = IUniswapV2Router02(router).swapExactTokensForETH(
            amountIn,
            amountOutMin,
            path,
            address(this),
            block.timestamp
        );

        uint256 deposited = address(this).balance;
        entryPoint().depositTo{value: deposited}(address(this));
        emit FeesRecycled(token, amountIn, amounts[1], deposited);
    }
