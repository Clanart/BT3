### Title
Partial liquidation with bonus can worsen LTV instead of improving it once collateral value drops below debt × (1 + penalty) - ([File: mainnet/contracts/market/v0-4-market.clar])

### Summary
`liquidate()` in `mainnet/contracts/market/v0-4-market.clar` lets a liquidator choose an arbitrary `debt-amount` up to a graduated cap, and seizes collateral equal to `debt-repay × (1 + liq-penalty)`. When a position's collateral value has fallen below `debt × (1 + liq-penalty)` (i.e. current LTV is already above roughly `1/(1+liq-penalty)`, which includes every LTV ≥ 100%), any partial liquidation of that kind mathematically *increases* the remaining LTV rather than decreasing it, because the bonus removes proportionally more collateral value than debt value. This mirrors the StakeWise finding: liquidation is supposed to make an unhealthy position healthier, but for sufficiently underwater positions the accounting used (debt reduced by `X`, collateral reduced by `X(1+bonus)`) fails to do so, and instead accelerates collateral drain while barely reducing debt, deepening the deficit that ultimately gets socialized onto lenders.

### Finding Description
The liquidation percentage is computed and capped in `calc-liq-factor`: [1](#0-0) 

Once `current-ltv >= ltv-liq-full`, this factor saturates at `BPS` (100%) and stays there no matter how far LTV rises above 100% — `max-debt-usd` becomes `total-debt-usd`, i.e. the *maximum* liquidatable amount is capped at "the whole debt," but the actual `debt-amount` executed is whatever the liquidator supplies as a parameter to `liquidate`: [2](#0-1) 

Collateral seized for a chosen debt repayment always includes the liquidator bonus: [3](#0-2) 

For a position with collateral USD value `C` and debt USD value `D`, repaying debt `X` and seizing `X(1+b)` of collateral value changes the LTV from `D/C` to `(D-X)/(C-X(1+b))`. Algebraically, this new ratio is *strictly lower* than the old one only when `C > D(1+b)`. Once `C <= D(1+b)` — which is guaranteed whenever `D/C >= 1`, i.e. LTV ≥ 100% (and even somewhat below, depending on `b`) — every partial liquidation of this form makes `(D-X)/(C-X(1+b))` *larger* than `D/C`: the position becomes less healthy, not more, contrary to the intent of liquidation.

There is no check anywhere in `liquidate` that verifies the resulting position's LTV actually improved; the only checks are amount-nonzero and slippage checks: [4](#0-3) 

The "remaining-debt-to-repay" / dust-cleanup logic only forces full seizure of the *processed* collateral asset when the *leftover* USD value of that same collateral, after applying `liq-penalty-max`, would round to zero debt — it is a rounding/dust safeguard, not a health-improvement guarantee, and it does nothing to prevent a liquidator from deliberately choosing a small `debt-amount` far below `max-debt-usd` while LTV is already ≥100%: [5](#0-4) 

If the collateral is eventually fully exhausted, the shortfall is written off onto the lending pool via `socialize-debt-asset`, which calls `vault-socialize-debt` to reduce the vault's index (i.e., all depositors absorb the loss): [6](#0-5) 

Because each bonus-inclusive partial liquidation removes collateral value disproportionately faster than it removes debt once LTV ≥ ~100%, a liquidator can repeatedly submit small `liquidate()` calls against the same severely underwater position, extracting the liquidation bonus multiple times while barely reducing outstanding debt, and increasing the total collateral shortfall that must ultimately be socialized onto depositors in `.v0-market-vault`.

### Impact Explanation
This lands on the in-scope **Critical** class of "protocol insolvency" / theft of lender funds: repeated bonus extraction on positions whose LTV is already ≥100% increases the amount of bad debt that is later socialized across the debt vault's depositors, effectively transferring value from depositors to the liquidator beyond what a correctly designed liquidation (which should shrink, not grow, the deficit per unit of debt cleared) would allow.

### Likelihood Explanation
Any liquidator can trigger this by choosing to call `liquidate` with a small `debt-amount` (well below the `max-debt-usd` cap returned by `calc-liquidation-params`) against a position whose `current-ltv` has already crossed 100% (e.g., after a sharp price drop on the collateral asset, or after being ignored/under-liquidated for one block due to the same-block frontrunning guard). No special privileges are required — it is available to any external liquidator, and is economically favorable to repeat since each call yields the fixed liquidation bonus in collateral value.

### Recommendation
Add an explicit post-liquidation health check in `liquidate` (`mainnet/contracts/market/v0-4-market.clar`) that recomputes the borrower's LTV (or a proxy of collateral-vs-debt-with-bonus ratio) after applying `coll-final`/`debt-to-repay`, and either: (a) reject/adjust the liquidation if it would leave a non-zero-collateral position with a worse or unchanged LTV than before, or (b) force full liquidation of all remaining collateral for that borrower/debt pair whenever `total-collateral-usd <= total-debt-usd × (1 + liq-penalty)`, instead of allowing an unconstrained small `debt-amount` in that regime.

### Proof of Concept
1. Borrower has collateral `C = $100` and debt `D = $105` (LTV = 105%, above `ltv-liq-full`), with `liq-penalty = 10%` (`b = 0.10`), so `1+b = 1.10`. Note `D(1+b) = 115.5 > C = 100`, so any positive liquidation `X` strictly increases LTV.
2. Liquidator calls `liquidate` with a small `debt-amount` corresponding to `X = $1` of debt (well under `max-debt-usd`, which is capped at `D = $105` since `calc-liq-factor` saturates at `BPS`).
3. Collateral seized = `X(1+b) = $1.10`. New position: `D' = $104`, `C' = $98.90`. New LTV = `104/98.90 ≈ 105.16%`, which is worse than the starting `105%`.
4. Liquidator repeats this process across many small calls (or via `liquidate-multi`), extracting the 10% bonus each time while the borrower's LTV keeps climbing, until collateral is exhausted and the remaining debt is written off via `socialize-debt-asset` — at which point the aggregate collateral extracted by the liquidator exceeds what a single correctly-executed full liquidation would have taken, with the excess loss borne by the debt vault's depositors.
