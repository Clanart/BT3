### Title
Missing `from` (module-identity) check in `BandwidthManager.onAccept` allows unauthenticated selection and execution of privileged `Withdraw`/`SetTiers` actions - (evm/src/apps/BandwidthManager.sol)

### Summary
`BandwidthManager.onAccept` authenticates only the *source chain* of an inbound ISMP message, not the *sender module* on that chain, before using `request.body[0]` to select between `SetTiers` and `Withdraw`.

### Finding Description
`onAccept` performs: [1](#0-0) 

The only authentication check is `request.source.equals(IDispatcher(_host).hyperbridge())`, verifying the message originated from the Hyperbridge chain. There is no check that `request.from` equals `PALLET_BANDWIDTH_MODULE_ID` (the pallet's identity), even though the contract itself documents that the pallet's `PalletId` is what should be enforced: [2](#0-1) 

Contrast this with the corresponding Substrate-side handler, `pallet_bandwidth::Pallet::on_accept`, which explicitly binds the sender identity before trusting the message body: [3](#0-2) 

The pallet-side comment even states the invariant that should hold symmetrically on the EVM side: "A purchase whose `request.from` doesn't match [the registered manager] is rejected." [4](#0-3) 

Because `onAccept` never checks `request.from`, any inbound PostRequest routed to this contract (i.e. any message whose `to` equals `PALLET_BANDWIDTH_MODULE_ID` and whose `source` is the Hyperbridge chain) is accepted regardless of which pallet/module on Hyperbridge actually dispatched it. `request.body[0]` is decoded straight into `OnAcceptActions` with no correlation to a pallet-issued nonce or a verified sender module id — the enum-cast bounds check (reverting on values other than `0`/`1`) is the *only* validation performed on the discriminant, and it says nothing about who was authorized to choose it.

As the question's proof idea outlines: an attacker able to get an arbitrary-`from` PostRequest dispatched from the Hyperbridge chain to `to = PALLET_BANDWIDTH_MODULE_ID` can set `body[0] = 1` with an ABI-encoded `Withdrawal{token, beneficiary, amount}` payload and drain the contract's token/native balance to any address, or set `body[0] = 0` to overwrite `tierPrice` arbitrarily (e.g. to manipulate future `purchase()` economics).

### Impact Explanation
If reachable, this breaks the invariant that "cross-chain admin or host-management effects must not be reachable through ... wrong module bindings, or unauthenticated message flow." Successful exploitation is direct unauthorized fund withdrawal from `BandwidthManager` (theft of accumulated purchase fees / native balance) and/or unauthorized rewriting of tier pricing, both privileged operations that should only be reachable from `pallet-bandwidth`'s sovereign module id.

### Likelihood Explanation
Exploitability hinges on whether an unprivileged actor can cause an ISMP PostRequest with attacker-chosen `from` bytes and `to = PALLET_BANDWIDTH_MODULE_ID` to be dispatched from the Hyperbridge state machine and successfully proven/relayed to the destination `EvmHost`. I was not able to fully verify, within the available index, whether the generic ISMP dispatch path (`pallet_ismp` / `IsmpDispatcher::dispatch_request`) constrains the `from` field to the calling pallet's own identity or allows arbitrary caller-supplied `from` bytes for any permissionless extrinsic. This is the deciding factor for real-world likelihood and could not be confirmed with the tools available here — a Devin session with full repo access (including `modules/pallets/ismp/src/impls.rs` and the dispatcher implementation) would be needed to confirm whether `from` is pallet-derived (lower likelihood, defense-in-depth issue) or attacker-controllable (high likelihood, directly exploitable). Regardless of that determination, the missing check itself is a genuine structural asymmetry versus the pallet-side implementation and violates the stated discriminant-to-intent binding invariant.

### Recommendation
Add an explicit check in `BandwidthManager.onAccept` that `request.from` equals `PALLET_BANDWIDTH_MODULE_ID` (mirroring the pallet-side `request.from != manager` check), in addition to the existing `request.source` check, before decoding `request.body[0]` into `OnAcceptActions`.

### Proof of Concept
1. Determine whether any Hyperbridge-side caller can invoke ISMP dispatch with `to = PALLET_BANDWIDTH_MODULE_ID` (`"BWMARKET"`) and a `from` value different from `PALLET_BANDWIDTH.0` (`b"BWMARKET"` PalletId).
2. If so, dispatch a PostRequest with body `abi.encodePacked(uint8(1), abi.encode(Withdrawal({token: address(0), beneficiary: attacker, amount: contractBalance})))`.
3. Relay/prove the message to `EvmHost`, which routes to `BandwidthManager.onAccept`; since only `request.source` is checked, the `Withdraw` branch executes and transfers `contractBalance` to `attacker`.
4. Repeat with `uint8(0)` and an attacker-chosen `Tier[]` to show `SetTiers` is equally forgeable, confirming the attacker — not the pallet — chooses which privileged branch executes. [1](#0-0) [3](#0-2)

    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost {
        PostRequest calldata request = incoming.request;

        if (!request.source.equals(IDispatcher(_host).hyperbridge())) revert UnauthorizedAction();

        OnAcceptActions action = OnAcceptActions(uint8(request.body[0]));
        if (action == OnAcceptActions.SetTiers) {
            Tier[] memory updates = abi.decode(request.body[1:], (Tier[]));
            for (uint256 i = 0; i < updates.length; i++) {
                tierPrice[updates[i].tier] = updates[i].price;
                emit TierSet(updates[i].tier, updates[i].price);
            }
        } else if (action == OnAcceptActions.Withdraw) {
            Withdrawal memory w = abi.decode(request.body[1:], (Withdrawal));
            if (w.token != address(0)) {
                IERC20(w.token).safeTransfer(w.beneficiary, w.amount);
            } else {
                (bool sent,) = w.beneficiary.call{value: w.amount}("");
                if (!sent) revert InsufficientNativeToken();
            }
            emit Withdrawn(w.token, w.beneficiary, w.amount);
        } else {
            revert UnauthorizedAction();
        }
    }
