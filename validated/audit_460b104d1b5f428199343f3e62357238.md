## Analysis

The seed report (Notional's `wstETHChainlinkOracle`) flags a Chainlink integration that checks `answer > 0` but omits `roundId`/`answeredInRound` validation, allowing a stale round to be accepted as fresh. Hyperbridge's own `SimplexPaymaster` contract has the identical Chainlink integration pattern, reproducing exactly the same gap.

### Title
Chainlink price oracle in `SimplexPaymaster` accepts stale/carried-over round data due to missing `roundId`/`answeredInRound` validation - (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster._getOraclePrice()` fetches `latestRoundData()` from the configured Chainlink `AggregatorV3Interface` and only validates `answer > 0` and `block.timestamp - updatedAt <= maxOracleAge`. It never checks `roundId`/`answeredInRound`, so it cannot detect a round whose answer was carried over from a previous, stale round (a known Chainlink failure mode during phase transitions/aggregator misbehavior, where `updatedAt` can still look "fresh" while `answeredInRound < roundId`).

### Finding Description
`_getOraclePrice` is: [1](#0-0) 

It destructures `latestRoundData()` and discards `roundId` and `answeredInRound` entirely (`(, int256 answer, , uint256 updatedAt, )`), checking only `answer <= 0` and a timestamp-based staleness bound. This is the exact gap the seed report calls out: without comparing `answeredInRound >= roundId`, the contract cannot distinguish a genuinely fresh answer from one that was mechanically re-stamped/carried forward by the aggregator.

This price feed is consumed by two reachable, unprivileged/attacker-adjacent paths:

1. `_tokenPrice` → `_fetchDetails`, invoked on every ERC-4337 `UserOperation` that pays gas via the paymaster: [2](#0-1) 
Any account can submit a `PackedUserOperation` with attacker-chosen timing, picking the block/moment where the oracle round is stale-but-timestamp-fresh to get a mispriced `tokenPrice`.

2. `swapAndDeposit`, which derives `amountOutMin` (slippage floor) directly from the same unchecked oracle price: [3](#0-2) 
Although gated to `treasury`, the floor itself is computed from a value that can be silently wrong, defeating the slippage protection's purpose.

### Impact Explanation
Because `tokenPrice` directly sets how much ERC-20 stablecoin a UserOp sender pays for a given amount of gas (`PaymasterERC20._erc20Cost`), a stale-but-fresh-looking round can make the effective price diverge from the true market rate. An unprivileged UserOp sender can time submission to exploit a stale round and underpay relative to the true native-asset cost, draining value from the paymaster/treasury on every such operation — this is a direct loss-of-funds path reachable through the public paymaster validation flow, not through any malicious relayer, prover, or admin.

### Likelihood Explanation
Requires only normal Chainlink aggregator behavior (phase rollover / partially-answered round) coinciding with a permissionless UserOp submission — no compromised keys, peers, or governance actions are needed. `maxOracleAge` is configurable (up to `MAX_ORACLE_AGE = 7 days`), and stablecoin feeds documented in the deploy script use 24h heartbeats, so the staleness window that could mask a bad round is non-trivial: [4](#0-3) 

### Recommendation
In `_getOraclePrice`, capture `roundId` and `answeredInRound` and revert unless `answeredInRound >= roundId` (and optionally `updatedAt > 0`), mirroring the seed report's recommended check:
```solidity
(uint80 roundId, int256 answer, , uint256 updatedAt, uint80 answeredInRound) = oracle.latestRoundData();
if (updatedAt == 0) revert InvalidOraclePrice(address(oracle), answer);
if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
if (answeredInRound < roundId) revert StaleOraclePrice(address(oracle), updatedAt);
if (block.timestamp - updatedAt > maxOracleAge) revert StaleOraclePrice(address(oracle), updatedAt);
```

### Proof of Concept
1. Governance registers a token whose Chainlink aggregator is mid phase-transition (or otherwise produces `answeredInRound < roundId` while `updatedAt` remains within `maxOracleAge`).
2. An attacker submits a `PackedUserOperation` with `paymasterData` targeting that token during this window.
3. `_fetchDetails` → `_tokenPrice` → `_getOraclePrice` returns the stale (mispriced) `tokenPrice` because only `answer > 0` and the timestamp bound are checked; `roundId`/`answeredInRound` are never inspected.
4. `PaymasterERC20._erc20Cost` charges the attacker's UserOp based on this stale price, resulting in the paymaster receiving less value than the true gas cost — a direct fund loss on the paymaster/treasury side, reachable by any unprivileged UserOp sender.

```text
    /// @dev Returns the token to charge and its price relative to native gas.
    ///
    ///      PaymasterERC20 computes `erc20Cost = weiCost * tokenPrice / 1e18`,
    ///      so tokenPrice must be token base units per wei, scaled by 1e18:
    ///        tokenPrice = (nativeUsd * 10^tokenDecimals) / tokenUsd
    ///      e.g. BNB at $600, USDC at $1 with 6 decimals: 0.001 BNB (1e15 wei)
    ///      should cost 0.60 USDC (600000 units), giving tokenPrice = 6e8, which
    ///      is exactly (600e8 * 1e6) / 1e8. Markup is applied on top.
    function _fetchDetails(
        PackedUserOperation calldata userOp,
        bytes32 /* userOpHash */
    ) internal view override returns (uint256 validationData, IERC20 token, uint256 tokenPrice) {
        bytes calldata data = userOp.paymasterData();
        if (data.length < 21) revert InvalidPaymasterData(data.length);

        uint8 mode = uint8(data[0]);
        if (mode > 0x01) revert InvalidMode(mode);

        address tokenAddr = address(bytes20(data[1:21]));

        TokenConfig memory cfg = tokenConfigs[tokenAddr];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(tokenAddr);
        if (!cfg.active) revert TokenNotActive(tokenAddr);

        tokenPrice = _tokenPrice(cfg);
        token = IERC20(tokenAddr);
        validationData = 0; // no time-range restriction
    }
```

```text
    /// @dev Fetch a Chainlink price normalized to 8 decimals.
    ///      Reverts on stale or non-positive answers.
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer, , uint256 updatedAt, ) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
```
