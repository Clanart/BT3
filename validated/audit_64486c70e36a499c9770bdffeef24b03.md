### Title
JIT front-running of `queueMGP`/`queueNewRewards` forfeiture events lets an attacker capture pro-rata share of forfeited MGP with zero holding period - (File: `rewards/vlMGPBaseRewarder.sol`)

### Summary
`vlMGPBaseRewarder` books forfeited/queued rewards instantly into `rewardPerTokenStored` using the current `totalStaked()` snapshot, with no time-weighting or streaming mechanism. Because `VLMGP.lock()` credits a user's staked balance immediately (no vesting delay) and `_updateFor` only snapshots the caller's own reward checkpoint at the moment of staking, an attacker who locks MGP in the same block just before a large forfeiture-triggering `queueMGP`/`getReward` call can capture a pro-rata share of that forfeiture with effectively zero holding duration.

### Finding Description
`totalStaked()` returns `IERC20(vlMGP).totalSupply()` live [1](#0-0) , and `balanceOf(_account)` reads the user's current staked amount from `MasterMagpie.stakingInfo` [2](#0-1) , both without any vesting/cooldown before counting toward reward eligibility.

When `VLMGP.lock()` is called, `MasterMagpie._deposit` first calls `_harvestBaseRewarder` -> `rewarder.updateFor(_account)`, which snapshots `userRewardPerTokenPaid[token][account] = rewardPerToken(token)` at the *pre-deposit* state, and only afterward increases `user.amount` (i.e., the staked balance and `totalSupply()`) [3](#0-2) [4](#0-3) . This means the newly locked balance is already included in `totalStaked()` before any subsequent `rewardPerTokenStored` update in the same block.

If a victim's forfeiture-triggering transaction (e.g., `queueMGP` from `MasterMagpie._sendMGPForVlMGPPool`, or a self-forfeit path in `_sendReward`) executes later in the same block, `_calExpireForfeit` computes `forfeitAmount` and pushes it into `rewardPerTokenStored` via `_queueNewRewardsWithoutTransfer`, dividing by the now-inflated `totalStaked()` that already includes the attacker's fresh stake [5](#0-4) [6](#0-5) .

Because the attacker's `userRewardPerTokenPaid` was captured *before* this update, `earned()` correctly computes a non-zero share for the attacker proportional to `attackerBalance / totalStaked()` at that instant [7](#0-6) . The attacker can then call `getReward`, which routes through `_sendReward`, applying `_calExpireForfeit` to the attacker's *own* forfeiture eligibility — since the attacker has not started any unlock, `getRewardablePercentWAD` returns 100% (fully locked, no cooldown) [8](#0-7) , so the attacker receives the full harvested MGP reward with zero forfeiture [9](#0-8) .

No modifier, cooldown, or minimum-holding-period check exists to prevent a same-block staker from being counted in the reward distribution snapshot; `nonReentrant` and `onlyManager`/`onlyMasterMagpie` guards only prevent reentrancy/unauthorized calls, not this timing issue.

### Impact Explanation
This allows an unprivileged, capital-holding attacker to dilute long-term stakers' entitlement to forfeited MGP by capturing a pro-rata share of yield they did not economically earn, transferring value from genuine long-duration lockers to a just-in-time attacker. This is a theft of unclaimed yield from existing stakers, matching the "theft or permanent freezing of unclaimed yield" Immunefi impact class.

### Likelihood Explanation
The attacker needs: (1) visibility of a pending large `queueMGP`/forfeiture transaction in the mempool (publicly observable), (2) sufficient MGP capital to lock in the same block ahead of it via higher gas price, and (3) no special privileges — `lock()`, `getReward` (via `MasterMagpie` harvest paths), and `startUnlock` are all public/permissionless. This is repeatable for any sufficiently large, predictable forfeiture event (e.g., scheduled harvests or large whale unlock/claim actions), though profitability scales with the size of the forfeiture relative to the attacker's stake and existing `totalStaked()`.

### Recommendation
Introduce a time-weighted reward mechanism (e.g., stream forfeited rewards over a duration similar to Synthetix's `rewardsDuration`, or checkpoint a user's eligible stake based on balance held since the last reward distribution) so that freshly staked balances in the same block/transaction as a forfeiture event cannot immediately share in that specific forfeiture payout. Alternatively, require a minimum lock duration before a balance counts toward `totalStaked()`/reward eligibility.

### Proof of Concept
Foundry test plan:
1. Deploy `VLMGP`, `MasterMagpie`, `vlMGPBaseRewarder`, mock MGP token.
2. Set up an existing long-term staker (Victim A) with locked MGP for N blocks, and a large pending forfeiture (simulate via a user starting/cancelling unlock such that `queueMGP` will produce a sizeable `forfeitAmount`).
3. In a single block: (a) Attacker calls `MGP.approve` + `VLMGP.lock(N)` with freshly acquired MGP; (b) immediately execute the pending `queueMGP`/harvest call that triggers `_calExpireForfeit` and `_queueNewRewardsWithoutTransfer`.
4. Assert `vlMGPBaseRewarder.earned(attacker, mgpToken) > 0` despite `block.timestamp` unchanged since attacker's lock.
5. Call `getReward`/`MasterMagpie` harvest for attacker and assert MGP balance increases by the expected pro-rata share (`N / totalStaked() * forfeitAmount`).
6. Call `startUnlock(N)` for attacker to confirm principal can begin exiting immediately after harvesting, and compute net profit (harvested reward minus any unlock penalty on principal, which is separate from the already-liquid reward tokens received).

    function queueMGP(uint256 _amount, address _account, address _receiver) override external onlyManager nonReentrant returns (bool) {
        IERC20(vlMGP.MGP()).safeTransferFrom(msg.sender, address(this), _amount);
        
        uint256 forfeitAmount = _calExpireForfeit(_account, _amount);
        uint256 rewardableAmount = _amount - forfeitAmount;
        
        if (forfeitAmount > 0)
            _queueNewRewardsWithoutTransfer(forfeitAmount, address(vlMGP.MGP()));

        if (rewardableAmount > 0) {
            IERC20(vlMGP.MGP()).safeTransfer(_receiver, rewardableAmount);
            emit MGPHarvested(_account, rewardableAmount, forfeitAmount);
        }

        return true;
    }

    function _queueNewRewardsWithoutTransfer(uint256 _amountReward, address _rewardToken) internal
    {
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards = rewardInfo.historicalRewards + _amountReward;
        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;

            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**vlMGPDecimal) / totalStaked();
        }
        emit ForfeitRewardAdded(_amountReward, _rewardToken);
    }

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalVlmgp = fullyInLock + inCoolDown;
        if (userTotalVlmgp == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalVlmgp;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalVlmgp / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalVlmgp;
                }

            }
        }

        return percent;
    }
