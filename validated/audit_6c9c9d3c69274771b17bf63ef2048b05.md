### Title
Empty Schnorr aggregate verifies as valid - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::verify` accepts an aggregate containing zero signatures when called with an empty `keys_and_challenges` list and `s == 0`, because the verification equation degenerates to the identity. [1](#0-0) 

### Finding Description
`SchnorrAggregate::read` permits the serialized nonce list length to be zero and then reads `s` without requiring any nonce or nonzero aggregate component. [2](#0-1)  During verification, an empty input passes the length check, produces no weighted `R` or public-key terms, and leaves only `-s * G` in the multiexponentiation. [1](#0-0)  With `s = 0`, that term is the identity, so `multiexp_vartime(...).is_identity()` returns true despite there being no signature to verify. [3](#0-2) 

### Impact Explanation
An unprivileged caller can submit serialized bytes for an empty aggregate and cause the verifier formula to report success for an empty statement. [2](#0-1)  If an API treats `SchnorrAggregate::verify(dst, &keys_and_challenges)` as proof that every supplied signature exists and verifies, the empty case is an incorrect verifier result rather than a rejected malformed aggregate. [1](#0-0) 

### Likelihood Explanation
The serialized input is fully attacker-controlled and requires only a four-byte zero length followed by a canonical zero scalar. [2](#0-1)  The issue requires the surrounding verifier invocation to use an empty `keys_and_challenges` list; it cannot bypass verification for a nonempty key list because the length check fails. [4](#0-3) 

### Recommendation
Reject empty aggregates both after deserialization and at the start of `verify`, or require `keys_and_challenges` to be a nonempty slice through the type system. [2](#0-1)  `SchnorrAggregator::complete` already returns `None` for an empty aggregate, so verification should enforce the same invariant instead of accepting the mathematically vacuous identity equation. [5](#0-4) 

### Proof of Concept
```rust
// crypto/schnorr/src/aggregate.rs
let mut encoded = Vec::new();
encoded.extend_from_slice(&0u32.to_le_bytes()); // zero Rs
encoded.extend_from_slice(C::F::ZERO.to_repr().as_ref()); // s = 0

let aggregate = SchnorrAggregate::<C>::read(&mut encoded.as_slice()).unwrap();
assert!(aggregate.verify(dst, &[]));
```

The resulting `pairs` vector contains only `(0, generator)`, making the final identity check pass. [3](#0-2)
