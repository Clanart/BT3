### Title
Unbounded RPC filter creation causes memory exhaustion (DoS) via `eth_newFilter`/`eth_newBlockFilter`/`eth_newPendingTransactionFilter` - (File: node/cn/filters/api_kaia_filter.go)

### Summary
The Jetty advisory (CVE-2024-9823) roots in `DosFilter` tracking client state (e.g., sessions) in an internal map with no bound other than a passivation/timeout policy, allowing an attacker to grow that map unboundedly and trigger an `OutOfMemory` condition. Kaia's JSON-RPC `FilterAPI`/`KaiaFilterAPI` exhibits the same structural pattern: every filter created by any RPC caller is stored in an in-memory map (`api.filters`) that is bounded only by a 5-minute inactivity timer, not by a maximum count, so a caller can create filters faster than they expire and grow the map (and its associated goroutines/subscriptions/buffers) without limit.

### Finding Description
`FilterAPI.filters` is a `map[rpc.ID]*filter` guarded by `filtersMu`, and the only eviction mechanism is `timeoutLoop`, which runs every `defaultFilterDeadline` (5 minutes) and removes filters whose per-filter `deadline` timer has fired since the filter was last polled: [1](#0-0) [2](#0-1) 

None of the filter-creation entry points — `NewFilter` (logs), `NewBlockFilter`, and `NewPendingTransactionFilter` — enforce any cap on the total number of filters (per-connection or global) before inserting into `api.filters`: [3](#0-2) [4](#0-3) [5](#0-4) 

Each created filter also spawns a dedicated goroutine and a subscription registered in the `EventSystem`'s `filterIndex` (via `install`), and its buffer (`f.logs`, `f.hashes`, or `f.txs`) is only cleared on `GetFilterChanges`, so an unpolled filter's buffer also grows unboundedly while active: [6](#0-5) [7](#0-6) 

These filter-creation RPC methods (`eth_newFilter`, `eth_newBlockFilter`, `eth_newPendingTransactionFilter`, and their `kaia_`/auction-namespace equivalents) are standard public JSON-RPC calls reachable by any unauthenticated public-RPC caller — there is no authentication or per-IP/per-connection throttling visible in this code path.

### Impact Explanation
An unauthenticated RPC caller can repeatedly invoke `eth_newFilter`/`eth_newBlockFilter`/`eth_newPendingTransactionFilter` faster than the 5-minute expiry window, each call allocating a new map entry, a new goroutine, a new `subscription` struct with multiple channels registered in the event loop's `filterIndex`, and (if matching events occur) growing log/hash/tx slices. This can exhaust node memory or goroutine/file-descriptor resources, causing a denial of service on the RPC node — directly analogous to the Jetty `DosFilter` OOM condition where per-client tracking state was unbounded except by a timeout.

### Likelihood Explanation
High, in principle: the RPC methods are unauthenticated and unrate-limited at this layer; the only mitigating factor is that a client would need many concurrent connections/requests to outpace the 5-minute cleanup, and typical `geth`-style RPC servers often rely on operator-configured connection limits or reverse-proxy rate limiting rather than in-process caps. I could not find any additional cap (e.g., max filters per connection) elsewhere in the module during this investigation; this should be verified against the RPC server's connection-level limits (e.g., `networks/rpc` batch/connection limits) to determine whether an outer layer already mitigates it.

### Recommendation
Add a maximum number of concurrently active filters (global and/or per-connection) enforced in `NewFilter`, `NewBlockFilter`, and `NewPendingTransactionFilter`, rejecting new filter creation once the limit is reached, similar to the Jetty patch's approach of removing unbounded tracking. Additionally consider shortening `defaultFilterDeadline` for unauthenticated public RPC access or supporting per-IP filter-creation rate limiting.

### Proof of Concept
1. Connect to the node's public JSON-RPC endpoint (HTTP or WS) without authentication.
2. In a loop, repeatedly call `eth_newFilter` with a low-cost filter body (e.g., `{"fromBlock":"latest"}`) or `eth_newBlockFilter`/`eth_newPendingTransactionFilter`, at a rate exceeding one every few milliseconds.
3. Because each call unconditionally inserts an entry into `api.filters` (see `NewFilter`/`NewBlockFilter`/`NewPendingTransactionFilter` above) without any count-based rejection, the map, associated goroutines, and subscriptions grow continuously; sustained flooding faster than the 5-minute timeout accumulates state and drives up server memory/goroutine usage, eventually degrading or crashing the RPC node.

// timeoutLoop runs every 5 minutes and deletes filters that have not been recently used.
// It is started when the api is created.
func (api *FilterAPI) timeoutLoop() {
	var toUninstall []*Subscription
	ticker := time.NewTicker(api.timeout)
	defer ticker.Stop()
	for {
		<-ticker.C
		api.filtersMu.Lock()
		for id, f := range api.filters {
			select {
			case <-f.deadline.C:
				toUninstall = append(toUninstall, f.s)
				delete(api.filters, id)
			default:
				continue
			}
		}
		api.filtersMu.Unlock()

		// Unsubscribes are processed outside the lock to avoid the following scenario:
		// event loop attempts broadcasting events to still active filters while
		// Unsubscribe is waiting for it to process the uninstall request.
		for _, s := range toUninstall {
			s.Unsubscribe()
		}
		toUninstall = nil
	}

func (api *KaiaFilterAPI) NewPendingTransactionFilter() rpc.ID {
	var (
		pendingTxs   = make(chan []*types.Transaction)
		pendingTxSub = api.events.SubscribePendingTxs(pendingTxs)
	)

	api.filtersMu.Lock()
	api.filters[pendingTxSub.ID] = &filter{typ: PendingTransactionsSubscription, deadline: time.NewTimer(api.timeout), txs: make([]*types.Transaction, 0), s: pendingTxSub}
	api.filtersMu.Unlock()

	go func() {
		defer pendingTxSub.Unsubscribe()
		for {
			select {
			case pTx := <-pendingTxs:
				api.filtersMu.Lock()
				if f, found := api.filters[pendingTxSub.ID]; found {
					f.txs = append(f.txs, pTx...)
				}
				api.filtersMu.Unlock()
			case <-pendingTxSub.Err():
				api.filtersMu.Lock()
				delete(api.filters, pendingTxSub.ID)
				api.filtersMu.Unlock()
				return
			}
		}
	}()

	return pendingTxSub.ID

// GetFilterChanges returns the logs for the filter with the given id since
// last time it was called. This can be used for polling.
//
// For pending transaction and block filters the result is []common.Hash.
// (pending)Log filters return []Log.
func (api *KaiaFilterAPI) GetFilterChanges(id rpc.ID) (interface{}, error) {
	api.filtersMu.Lock()
	defer api.filtersMu.Unlock()

	if f, found := api.filters[id]; found {
		if !f.deadline.Stop() {
			// timer expired but filter is not yet removed in timeout loop
			// receive timer value and reset timer
			<-f.deadline.C
		}
		f.deadline.Reset(api.timeout)

		switch f.typ {
		case BlocksSubscription:
			hashes := f.hashes
			f.hashes = nil
			return returnHashes(hashes), nil
		case PendingTransactionsSubscription:
			if f.fullTx {
				txs := make([]map[string]interface{}, 0, len(f.txs))
				for _, tx := range f.txs {
					txs = append(txs, tx.MakeRPCOutput())
				}
				f.txs = nil
				return txs, nil
			} else {
				hashes := make([]common.Hash, 0, len(f.txs))
				for _, tx := range f.txs {
					hashes = append(hashes, tx.Hash())
				}
				f.txs = nil
				return hashes, nil
			}
		case LogsSubscription:
			logs := f.logs
			f.logs = nil
			return returnLogs(logs), nil
		}
	}

	return []interface{}{}, fmt.Errorf("filter not found")
}

type filterIndex map[Type]map[rpc.ID]*subscription

// broadcast event to filters that match criteria.
func (es *EventSystem) broadcast(filters filterIndex, ev interface{}) {
	if ev == nil {
		return
	}

	switch e := ev.(type) {
	case []*types.Log:
		if len(e) > 0 {
			for _, f := range filters[LogsSubscription] {
				if matchedLogs := filterLogs(e, f.logsCrit.FromBlock, f.logsCrit.ToBlock, f.logsCrit.Addresses, f.logsCrit.Topics); len(matchedLogs) > 0 {
					f.logs <- matchedLogs
				}
			}
		}
	case blockchain.RemovedLogsEvent:
		for _, f := range filters[LogsSubscription] {
			if matchedLogs := filterLogs(e.Logs, f.logsCrit.FromBlock, f.logsCrit.ToBlock, f.logsCrit.Addresses, f.logsCrit.Topics); len(matchedLogs) > 0 {
				f.logs <- matchedLogs
			}
		}
	case blockchain.NewTxsEvent:
		for _, f := range filters[PendingTransactionsSubscription] {
			f.txs <- e.Txs
		}
	case blockchain.ChainEvent:
		for _, f := range filters[BlocksSubscription] {
			f.headers <- e.Block.Header()
		}
	}
}

// eventLoop (un)installs filters and processes mux events.
func (es *EventSystem) eventLoop() {
	// Ensure all subscriptions get cleaned up
	defer func() {
		es.txsSub.Unsubscribe()
		es.logsSub.Unsubscribe()
		es.rmLogsSub.Unsubscribe()
		es.chainSub.Unsubscribe()
	}()

	index := make(filterIndex)
	for i := range LastIndexSubscription {
		index[i] = make(map[rpc.ID]*subscription)
	}

	for {
		select {
		// Handle subscribed events
		case ev := <-es.txsCh:
			es.broadcast(index, ev)
		case ev := <-es.logsCh:
			es.broadcast(index, ev)
		case ev := <-es.rmLogsCh:
			es.broadcast(index, ev)
		case ev := <-es.chainCh:
			es.broadcast(index, ev)

		case f := <-es.install:
			index[f.typ][f.id] = f
			close(f.installed)

		case f := <-es.uninstall:
			delete(index[f.typ], f.id)
