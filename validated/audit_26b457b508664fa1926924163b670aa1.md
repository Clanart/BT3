### Title
Panic via Unchecked Type Assertion on Missing/Non-String `name`/`symbol` Field in Pointer Precompile (`AddCW20`/`AddCW721`/`AddCW1155`) - ([File: precompiles/pointer/pointer.go])

### Summary
The `pointer` precompile's `AddCW20`, `AddCW721`, and `AddCW1155` handlers query an attacker-supplied CosmWasm contract for `token_info`/`contract_info`, JSON-decode the response into `map[string]interface{}`, and immediately type-assert `formattedRes["name"].(string)` and `formattedRes["symbol"].(string)` without checking whether the keys exist or hold string values. This mirrors the CVE-2026-28390 bug class: an optional/attacker-controlled field is consumed without a presence/type check, producing a panic before any further validation or authentication occurs.

### Finding Description
`AddCW20`, `AddCW721` and `AddCW1155` in `precompiles/pointer/pointer.go` do: [1](#0-0) [2](#0-1) [3](#0-2) 

`cwAddr` in each case is an attacker-chosen address supplied directly as an EVM call argument, and the query response `res` comes from `p.wasmdKeeper.QuerySmartSafe(ctx, cwAddress, ...)` against whatever CosmWasm contract lives at that address — including a contract deployed by the caller in the same or a prior transaction. If that contract's `token_info`/`contract_info` query response JSON omits the `"name"` or `"symbol"` key, or encodes them as `null`/non-string JSON values, `formattedRes["name"]` yields a `nil` (or non-string) `interface{}`, and the unchecked type assertion `.(string)` panics with `interface conversion: interface {} is nil, not string` (or a type mismatch panic). This is functionally the same defect class as the CVE: an "optional" field is examined/consumed without checking for its presence, causing an unrecovered panic during processing of attacker-crafted input.

Unlike the sibling `json` precompile, which explicitly comments that its type assertions are safe because arguments were already ABI-validated in `Prepare`, the `pointer` precompile's assertions operate on **externally supplied, unvalidated CosmWasm query response data**, not on ABI-decoded arguments — so the "always succeeds" invariant does not hold here.

Critically, the dynamic-gas precompile wrapper only recovers and converts **gas-meter** panics into EVM reverts; all other panics (including this type-assertion panic) are explicitly re-panicked and propagate out of `RunAndCalculateGas`: [4](#0-3) 

### Impact Explanation
Any account can deploy a trivial CosmWasm contract whose `token_info`/`contract_info` query handler returns JSON without a `name` or `symbol` field (or with a non-string value), then call `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` on the `pointer` precompile (address `0x...100b`) pointing at that contract. Because the panic is not caught inside the precompile or the dynamic-gas wrapper, it propagates up through EVM execution. When triggered through `eth_call`/`eth_estimateGas` or any EVM execution path that lacks a defensive recover boundary, this can crash the executing node process (denial of service), matching the "crash of default-configuration RPC nodes" impact criterion. Even where a `recover()` exists further up the call stack (e.g., in `baseapp.runTx`), the bug still represents an unauthenticated, unprivileged-reachable panic path triggerable by any CosmWasm/pointer-precompile user with zero cost beyond gas for a trivial CW20/CW721/CW1155 contract.

### Likelihood Explanation
High. No special privileges are required: an unprivileged user can (1) deploy or point to a minimal CosmWasm contract that returns a `token_info`/`contract_info` response missing or misencoding `name`/`symbol`, and (2) call the `pointer` precompile's `AddCW20`/`AddCW721`/`AddCW1155` methods against that contract address from an ordinary EVM transaction or JSON-RPC call. No signatures, governance, or validator cooperation is needed.

### Recommendation
Replace the unchecked type assertions with safe, checked extraction, e.g.:
```go
name, ok := formattedRes["name"].(string)
if !ok {
    return nil, 0, fmt.Errorf("cw contract response missing or invalid \"name\" field")
}
symbol, ok := formattedRes["symbol"].(string)
if !ok {
    return nil, 0, fmt.Errorf("cw contract response missing or invalid \"symbol\" field")
}
```
Apply this in `AddCW20`, `AddCW721`, and `AddCW1155` in `precompiles/pointer/pointer.go` (and all legacy-versioned copies under `precompiles/pointer/legacy/*`), and consider adding a defensive `recover()` in the pointer precompile's execute path (or at RPC-simulation entry points) to guarantee a malformed CosmWasm response degrades to a reverted transaction rather than a process panic.

### Proof of Concept
1. Deploy a CosmWasm contract whose `QueryMsg::TokenInfo {}` (or `ContractInfo {}`) handler returns `{}` (or `{"name": null}`) instead of the expected `{"name": "...", "symbol": "...", ...}`.
2. From any EVM account, call the `pointer` precompile at `0x000000000000000000000000000000000000100b`, method `addCW20Pointer(string)` (or `addCW721Pointer`/`addCW1155Pointer`), passing the bech32 address of the contract from step 1.
3. Observe `formattedRes["name"].(string)` in `precompiles/pointer/pointer.go` panics with an `interface conversion` error; the panic re-propagates through `RunAndCalculateGas` (confirmed by the non-gas repanic behavior in `precompiles/common/precompiles_test.go`) rather than being converted to a revert.
