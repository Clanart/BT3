### Title
PedPoP encrypted-share proof of possession does not bind the recipient, allowing cross-recipient replay and false blame of honest DKG participants - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
The rusqlite advisory is a bug class where a bound that should have been restrictive was too relaxed, letting a registered artifact be legitimately invoked outside the scope it was created for. The Serai analog is in PedPoP's per-message proof of possession: `pop_challenge` binds the DKG `context`, the ephemeral `key`, the `nonce`, the `sender`, and the ciphertext `msg` — but not the intended recipient. An `EncryptedMessage` created by an honest sender for participant A is therefore a fully valid, authentic `EncryptedMessage` "from" that sender to *any* participant, and the library's own validation accepts it wherever it is submitted.

### Finding Description
`encrypt` ECDH-encrypts the secret share to a specific participant's registered encryption key (`self.decryption.enc_keys[&participant]`) and signs a PoP over `pop_challenge(context, R, key, from, msg)`: [1](#0-0) [2](#0-1) 

The challenge transcript appends `context`, `nonce`, `key`, `sender`, and `message` — there is no `to`/`recipient` field, even though the function already treats "the important part is its owner" as the security property and goes out of its way to bind `sender` "to prevent the attack this is meant to stop". The decryption side verifies the PoP with exactly the same fields, again with no recipient: [3](#0-2) [4](#0-3) 

On the receive path (`KeyMachine::calculate_share`), the `shares` map is only checked for *sender* correctness via `validate_map` — the encrypted message itself carries no authenticated indication of whom it was encrypted for. The binding is therefore "too relaxed" in exactly the advisory's sense: a ciphertext+PoP minted for scope (sender→A) is accepted as valid in scope (sender→B).

### Impact Explanation
Any party able to route, reorder, or resubmit DKG round-2 messages — i.e., whoever feeds untrusted bytes to `EncryptedMessage::read` / `calculate_share`, which the rules explicitly allow as the reachable surface — can take the authentic `EncryptedMessage<C, SecretShare>` an honest sender `l` produced for participant A and deliver it to participant B (or simply duplicate a real broadcast into B's inbox as `l`'s share).

- The PoP verifies at B, because it never committed to B vs. A. 
- `ecdh::<C>(&enc_key_B, msg.key)` then yields a wrong keystream, so the share decrypts to garbage.
- `C::F::from_repr` fails or `share_verification_statements` fails, producing `PedPoPError::InvalidShare { participant: l, blame: Some(..) }` — i.e., the *honest sender `l`* is cryptographically blamed, and B publishes a blame proof (`EncryptionKeyProof` revealing an ECDH shared key derived under B's static encryption key with a message never addressed to B).

Consequences: an honest DKG participant is deterministically identified as faulty by `BlameMachine`/`AdditionalBlameMachine` (which exists precisely so even non-participants can adjudicate blame), causing wrongful exclusion/slashing and aborted key-generation sessions — a per-message, per-victim repeatable attack with only message-relay capability.

### Likelihood Explanation
The DKG explicitly delegates message transport to an external authenticated-but-not-necessarily-private channel ("this still doesn't mean the DKG offers an authenticated channel" for content). Routing messages between recipients is a normal capability of that layer, and the attack requires no key knowledge, no collusion, and no malicious DKG participant — only delivering a genuine message to a genuine-but-wrong recipient. The fix of the "missing" field is trivially absent by inspection of the transcript labels.

### Recommendation
Bind the intended recipient into the PoP: extend `pop_challenge` to take the `to: Participant` (or the recipient's registered encryption public key) and `transcript.append_message(b"recipient", ...)` in both `encrypt`/`SchnorrSignature::sign` and the two verification sites (`Encryption::decrypt`, `Decryption::decrypt_with_proof`). This makes an `EncryptedMessage` valid only within the (sender → recipient) scope it was created for, restoring the tight bound. Note the analogous gap exists for `encryption_key_transcript` used in blame DLEq proofs, which binds only `context` and should additionally bind the message/sender so blame proofs cannot be transplanted between messages.

### Proof of Concept
1. Honest sender `l` runs `generate_secret_shares`, producing `Enc_l→A = encrypt(rng, ctx, l, enc_pub_A, share_A)` and `Enc_l→B = encrypt(.., enc_pub_B, share_B)`.
2. Attacker on the channel forwards `Enc_l→A` to B in place of (or in addition to) `Enc_l→B`.
3. B calls `calculate_share` with `shares = {l: Enc_l→A}`. `msg.pop.batch_verify(... pop_challenge(ctx, R, key, l, msg))` passes — no recipient field exists to fail.
4. `ecdh(enc_key_B, key_A)` applies a wrong keystream → `from_repr` fails or the share-verification batch fails with `BatchId::Share(l)`.
5. B emits `PedPoPError::InvalidShare { participant: l, blame: Some(EncryptionKeyProof) }`; `BlameMachine`/`AdditionalBlameMachine::blame` confirms `l` — not the relay — as faulty. Honest `l` is blamed and the DKG aborts, purely from replaying a valid message outside its intended scope.

fn pop_challenge<C: Ciphersuite>(
  context: [u8; 32],
  nonce: C::G,
  key: C::G,
  sender: Participant,
  msg: &[u8],
) -> C::F {
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption Key Proof of Possession v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"proof_of_possession");

  transcript.append_message(b"nonce", nonce.to_bytes());
  transcript.append_message(b"key", key.to_bytes());
  // This is sufficient to prevent the attack this is meant to stop
  transcript.append_message(b"sender", sender.to_bytes());
  // This, as written above, doesn't hurt
  transcript.append_message(b"message", msg);
  // While this is a PoK and a PoP, it's called a PoP here since the important part is its owner
  // Elsewhere, where we use the term PoK, the important part is that it isn't some inverse, with
  // an unknown to anyone discrete log, breaking the system
  C::hash_to_F(b"DKG-encryption-proof_of_possession", &transcript.challenge(b"schnorr"))
}

    &self,
    rng: &mut R,

    // Uses a distinct batch ID so if this batch verifier is reused, we know its the PoP aspect
    // which failed, and therefore to use None for the blame
    batch_id: I,
    from: Participant,
    mut msg: EncryptedMessage<C, E>,
  ) -> (Zeroizing<E>, EncryptionKeyProof<C>) {

      rng,
      batch,
      batch_id,
      msg.key,

    );

    cipher::<C>(self.context, &key).apply_keystream(msg.msg.as_mut().as_mut());

      msg.msg,
      EncryptionKeyProof {
        key,
        dleq: DLEqProof::prove(
          rng,
          &mut encryption_key_transcript(self.context),
          &[C::generator(), msg.key],
          &self.enc_key,
        ),
      },
    )

  pub fn calculate_share<R: RngCore + CryptoRng>(
    mut self,
    rng: &mut R,
    mut shares: HashMap<Participant, EncryptedMessage<C, SecretShare<C::F>>>,
  ) -> Result<BlameMachine<C>, PedPoPError<C>> {
    validate_map(
      &shares,
      &self.params.all_participant_indexes().collect::<Vec<_>>(),
      self.params.i(),
    )?;

    let mut batch = BatchVerifier::new(shares.len());
    let mut blames = HashMap::new();
    for (l, share_bytes) in shares.drain() {
      let (mut share_bytes, blame) =
        self.encryption.decrypt(rng, &mut batch, BatchId::Decryption(l), l, share_bytes);
      let share =
        Zeroizing::new(Option::<C::F>::from(C::F::from_repr(share_bytes.0)).ok_or_else(|| {
          PedPoPError::InvalidShare { participant: l, blame: Some(blame.clone()) }
        })?);
      share_bytes.zeroize();
      *self.secret += share.deref();

      blames.insert(l, blame);
      batch.queue(
        rng,
        BatchId::Share(l),
        share_verification_statements::<C>(self.params.i(), &self.commitments[&l], share),
      );
    }
    batch.verify_with_vartime_blame().map_err(|id| {
      let (l, blame) = match id {
        BatchId::Decryption(l) => (l, None),
        BatchId::Share(l) => (l, Some(blames.remove(&l).unwrap())),
      };
      PedPoPError::InvalidShare { participant: l, blame }
    })?;
