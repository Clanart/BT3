## Analysis

This is a valid analog. The NocoDB bug class is **SSRF via a URL that an unprivileged actor fully controls, which the server later fetches without destination filtering**. Chia's DataLayer has the same shape: any wallet holder can publish an on-chain "mirror" record for *any* store (not just their own), and DataLayer nodes that subscribe to (or auto-track) that store id will later issue outbound HTTP `GET` requests to the attacker-supplied URL with no scheme/host/IP restriction.

### Root cause

`DataLayerWallet.create_new_mirror()` builds a standard coin spend whose memo is `[launcher_id, *urls]`, but it never verifies that the caller owns or controls `launcher_id`: [1](#0-0) 

Any wallet user can therefore spend their own coin (a fully unprivileged, self-funded transaction) to register a mirror URL for a store id belonging to someone else. When that coin confirms, `coin_added()` decodes the memo and inserts the mirror into the local mirror table for any launcher id that is tracked, without checking whether the transaction submitter owns that launcher/store: [2](#0-1) 

`DataLayer.update_subscriptions_from_wallet()` and `periodically_manage_data()` pull mirror URLs for tracked/owned/subscribed stores straight from the wallet (`dl_get_mirrors`) and feed them into the local server list used for downloads, with no filtering of scheme or destination: [3](#0-2) [4](#0-3) 

The actual outbound request is a plain `aiohttp` GET to the attacker-chosen URL with no IP/host allow-list, unlike the NocoDB fix which added `request-filtering-agent`'s `useAgent(url)` socket-layer filtering: [5](#0-4) 

The manual `subscribe` RPC/CLI path (`chia/cmds/data.py`, `data_layer.subscribe`) also accepts arbitrary URLs directly, but that requires the operator's own action; the mirror-coin path is the concerning one because it lets a third party inject URLs into another operator's node purely by broadcasting a spend.

### Why this matches the required impact bar

This is reachable by an unprivileged actor via a single self-funded coin spend (a `create_mirror_puzzle()` coin with attacker-chosen memo), and results in another party's DataLayer node making unauthenticated outbound HTTP requests to attacker-controlled destinations — including internal/private network addresses reachable from that node — satisfying the CWE-918/441 SSRF pattern and the "Data Layer roots and proofs" in-scope category.

### Title
Unauthenticated SSRF via DataLayer mirror-coin URLs with no destination filtering - (File: chia/data_layer/data_layer_wallet.py)

### Summary
`DataLayerWallet.create_new_mirror()` lets any wallet user attach an arbitrary URL to *any* store's launcher id via a normal, self-funded coin spend. `coin_added()` accepts and stores this mirror for any locally tracked launcher id without verifying the submitter's relationship to that store. DataLayer's periodic sync (`update_subscriptions_from_wallet`, `fetch_and_validate`/`http_download`) later issues plain HTTP requests to these attacker-supplied URLs with no scheme or destination restriction, letting a remote unprivileged party coerce a victim's DataLayer node into making requests to internal or otherwise unintended hosts.

### Finding Description
`create_new_mirror()` ( [1](#0-0) ) constructs a standard XCH spend where the memo encodes `[launcher_id, *urls]`. There is no check that `launcher_id` is a store owned by the spending wallet. On confirmation, `coin_added()` inserts a `Mirror` record for `launcher_id` as long as that launcher is "tracked" locally ( [6](#0-5) ) — which includes stores the victim merely subscribes to or watches, not just stores they own.

`update_subscriptions_from_wallet()` then unconditionally folds all mirror URLs for a store into the local server list used for downloads ( [7](#0-6) ), and `fetch_and_validate()`/`insert_from_delta_file()`/`http_download()` perform a raw `aiohttp` GET against `server_info.url` ( [8](#0-7) ) with no host/IP allow-listing analogous to `request-filtering-agent` in the NocoDB fix.

### Impact Explanation
Any user who can fund a small on-chain transaction can force victim DataLayer nodes (anyone subscribed to, or auto-tracking, the targeted store) to issue outbound HTTP requests to attacker-chosen destinations, including internal/private addresses reachable from the victim's host. This can be used to probe or interact with internal services, cloud metadata endpoints, or other hosts not intended to be reachable externally — a classic SSRF impact.

### Likelihood Explanation
Likelihood is high for any operator running DataLayer with active subscriptions: creating a mirror coin costs only a small amount of XCH/fee and requires no special privilege, and the periodic sync loop (`periodically_manage_data`) automatically ingests and dials mirror URLs without operator interaction.

### Recommendation
Restrict mirror ingestion so `coin_added()`/`update_subscriptions_from_wallet()` only trust mirror URLs for stores the local wallet actually owns (or require explicit operator opt-in per store), and add destination filtering (block RFC1918/loopback/link-local ranges and enforce an http/https scheme allow-list) around `http_download()` and `get_downloader()`'s outbound requests, similar to `request-filtering-agent`'s socket-layer protection in the referenced NocoDB fix.

### Proof of Concept
1. Attacker (any funded wallet) calls `dl_new_mirror`/`add_mirror` with `launcher_id` = victim's tracked/subscribed store id and `urls = ["http://169.254.169.254/latest/meta-data/", ...]` or an internal service URL, per `chia/data_layer/data_layer_rpc_api.py:468-475` and `chia/data_layer/data_layer_wallet.py:687-703`.
2. Once the transaction confirms, the victim's `DataLayerWallet.coin_added()` records the mirror for that launcher id (no ownership check), per `chia/data_layer/data_layer_wallet.py:775-799`.
3. Victim's periodic loop calls `update_subscriptions_from_wallet()` and `fetch_and_validate()`, which route the malicious URL into `http_download()`, causing the victim node to issue an HTTP GET to the attacker-chosen internal/private address, per `chia/data_layer/data_layer.py:979-985,642-694` and `chia/data_layer/download_data.py:298-324`.

```python
    async def add_mirror(self, store_id: bytes32, urls: list[str], amount: uint64, fee: uint64) -> None:

        )

    async def delete_mirror(self, coin_id: bytes32, fee: uint64) -> None:
        await self.wallet_rpc.dl_delete_mirror(DLDeleteMirror(coin_id=coin_id, fee=fee, push=True), DEFAULT_TX_CONFIG)

    async def get_mirrors(self, store_id: bytes32) -> list[Mirror]:
        mirrors: list[Mirror] = (await self.wallet_rpc.dl_get_mirrors(DLGetMirrors(launcher_id=store_id))).mirrors
        return [mirror for mirror in mirrors if mirror.urls]

    async def update_subscriptions_from_wallet(self, store_id: bytes32) -> None:
        mirrors: list[Mirror] = (await self.wallet_rpc.dl_get_mirrors(DLGetMirrors(launcher_id=store_id))).mirrors
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
