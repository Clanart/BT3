### Title
Arbitrary directory write via unvalidated `foldername` in DataLayer `add_missing_files` RPC - (File: chia/data_layer/data_layer_rpc_api.py)

### Summary
The `add_missing_files` DataLayer RPC endpoint accepts a `foldername` string directly from the request body and converts it to a `Path` with no validation, canonicalization, or restriction to `server_files_location`. That path is then used as the destination directory into which DataLayer writes `.dat` (full-tree/delta) files derived from local store data. This mirrors the OpenRGB bug class: a network/RPC-reachable parameter is used to control a filesystem write destination without sanitization, allowing a write outside the intended directory.

### Finding Description
`DataLayerRpcApi.add_missing_files` reads `foldername` straight from the JSON request and wraps it in `Path()` without any check that it stays under the configured `server_files_location` or any other allow-listed directory: [1](#0-0) 

This value is passed through to `DataLayer.add_missing_files(store_id, overwrite, foldername)`, which flows into `write_files_for_root()` in `chia/data_layer/download_data.py`. That function joins the caller-supplied folder with a filename computed from the store id/root hash/generation and opens it for writing (`"wb"`/`"xb"` mode), creating parent directories along the way: [2](#0-1) 

The equivalent client-side wrapper confirms the folder name is taken verbatim as a string and forwarded unmodified in the RPC payload: [3](#0-2) 

Unlike the delta/full-tree filename generators (`get_full_tree_filename_path`/`get_delta_filename_path`), which are always anchored to a caller-chosen `foldername` root, there is no server-side restriction forcing that root to remain inside the DataLayer's own file-serving directory: [4](#0-3) 

Because the directory (`filename_full_tree.parent`) is created with `mkdir(parents=True, exist_ok=True)` before any writes, an RPC caller can point `foldername` at an arbitrary path on disk that the daemon process has permission to write to (e.g. `/home/user/.config/autostart/`, a cron directory, or any writable location), and the daemon will create that directory tree and write files into it — the OpenRGB-analog "write into attacker-controlled arbitrary file system path."

### Impact Explanation
While the file *content* is local Merkle-tree/data-store bytes rather than fully attacker-chosen content, the *destination* is fully attacker-controlled, and the daemon will create missing parent directories and write files there. On a host where the DataLayer RPC is reachable (local RPC caller, or a caller with an RPC keyring/session), this can be abused to plant files into unexpected filesystem locations owned by the daemon process's user, which is the essence of an arbitrary file write primitive. Given the same daemon typically also holds wallet/keychain material, an attacker who can reach this RPC could potentially write into other service-consumed paths, escalating from a data-layer bug into local system compromise, consistent with the severity class described in the OpenRGB CVE analog.

### Likelihood Explanation
Reaching this endpoint requires access to the DataLayer JSON-RPC (normally gated by daemon-issued SSL certs / local RPC authorization), which limits exposure to authorized local RPC callers rather than fully unauthenticated remote attackers. However, per the defined threat model this class of caller ("local RPC caller") is in scope, and no additional path validation exists once the RPC call is authorized — the `foldername` parameter is trusted implicitly.

### Recommendation
Validate that any client-supplied `foldername` resolves (after `Path.resolve()`) to a location inside an explicit allow-listed base directory (e.g. the configured `server_files_location` or a dedicated "reconstruction output" root), rejecting absolute paths or `..` traversal that escape it. Reuse the same filename-validation discipline already applied to downloaded filenames (`download_data.is_filename_valid()`) for the destination directory, and apply this validation uniformly in `DataLayerRpcApi.add_missing_files`, `DataLayer.add_missing_files`, and `write_files_for_root`.

### Proof of Concept
1. Start `chia data` service with DataLayer RPC enabled and obtain valid RPC credentials (local caller).
2. Call the `add_missing_files` RPC with a store id owned/known locally and `foldername` set to an arbitrary writable path outside the DataLayer server-files directory, e.g.:
```json
{
  "ids": ["<store_id_hex>"],
  "overwrite": true,
  "foldername": "/home/victim/.config/some-autostart-dir"
}
``` [1](#0-0) 
3. Observe that `DataLayer.add_missing_files` → `write_files_for_root` creates the target directory (if missing) and writes `<store_id>-<node_hash>-full-<gen>-v1.0.dat` / `-delta-...` files into it, confirming a write outside the intended `server_files_location` sandbox. [5](#0-4)

    async def add_missing_files(self, request: dict[str, Any]) -> EndpointResult:
        """
        complete the data server files.
        """
        if "ids" in request:
            store_ids = request["ids"]
            ids_bytes = [bytes32.from_hexstr(id) for id in store_ids]
        else:
            subscriptions: list[Subscription] = await self.service.get_subscriptions()
            ids_bytes = [subscription.store_id for subscription in subscriptions]
        overwrite = request.get("overwrite", False)
        foldername: Path | None = None
        if "foldername" in request:
            foldername = Path(request["foldername"])
        for store_id in ids_bytes:
            await self.service.add_missing_files(store_id, overwrite, foldername)
        return {}

async def write_files_for_root(
    data_store: DataStore,
    store_id: bytes32,
    root: Root,
    foldername: Path,
    full_tree_first_publish_generation: int,
    overwrite: bool = False,
    group_by_store: bool = False,
) -> WriteFilesResult:
    if root.node_hash is not None:
        node_hash = root.node_hash
    else:
        node_hash = bytes32.zeros  # todo change

    filename_full_tree = get_full_tree_filename_path(foldername, store_id, node_hash, root.generation, group_by_store)
    filename_diff_tree = get_delta_filename_path(foldername, store_id, node_hash, root.generation, group_by_store)
    filename_full_tree.parent.mkdir(parents=True, exist_ok=True)

    written = False
    mode: Literal["wb", "xb"] = "wb" if overwrite else "xb"

    written_full_file = False
    if root.generation >= full_tree_first_publish_generation:
        try:
            with open(filename_full_tree, mode) as writer:
                await data_store.write_tree_to_file(root, node_hash, store_id, False, writer)
            written = True
            written_full_file = True
        except FileExistsError:
            pass

    try:
        with open(filename_diff_tree, mode) as writer:
            await data_store.write_tree_to_file(root, node_hash, store_id, True, writer)
        written = True
    except FileExistsError:
        pass

    return WriteFilesResult(written, filename_full_tree if written_full_file else None, filename_diff_tree)

    async def add_missing_files(
        self, store_ids: list[bytes32] | None, overwrite: bool | None, foldername: Path | None
    ) -> dict[str, Any]:
        request: dict[str, Any] = {}
        if store_ids is not None:
            request["ids"] = [store_id.hex() for store_id in store_ids]
        if overwrite is not None:
            request["overwrite"] = overwrite
        if foldername is not None:
            request["foldername"] = str(foldername)
        response = await self.fetch("add_missing_files", request)
        return response

def get_full_tree_filename_path(
    foldername: Path,
    store_id: bytes32,
    node_hash: bytes32,
    generation: int,
    group_by_store: bool = False,
) -> Path:
    if group_by_store:
        path = foldername.joinpath(f"{store_id}")
        return path.joinpath(f"{node_hash}-full-{generation}-v1.0.dat")
    return foldername.joinpath(f"{store_id}-{node_hash}-full-{generation}-v1.0.dat")


def get_delta_filename_path(
    foldername: Path,
    store_id: bytes32,
    node_hash: bytes32,
    generation: int,
    group_by_store: bool = False,
) -> Path:
    if group_by_store:
        path = foldername.joinpath(f"{store_id}")
        return path.joinpath(f"{node_hash}-delta-{generation}-v1.0.dat")
    return foldername.joinpath(f"{store_id}-{node_hash}-delta-{generation}-v1.0.dat")
