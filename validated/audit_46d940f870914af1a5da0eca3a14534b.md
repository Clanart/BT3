## Binding (stated before tracing)

`withdrawals.payout_payer_operator_xonly_pk` (the value that `PayoutCheckerTask::run_once` / `get_first_unhandled_payout_by_operator_xonly_pk` use to decide "operator X handled withdrawal i, therefore operator X may claim Reimburse for it") **should equal** the identity of the party whose Bitcoin funds actually paid out withdrawal i (i.e., who supplied the value in `payout_tx`'s non-dust inputs beyond the user's own pre-signed withdrawal UTXO).

## Trace

- `Verifier::update_finalized_payouts` derives the credited operator **solely** from the OP_RETURN of whichever tx spends the registered `withdrawal_utxo`, with no check on who supplied the tx's other inputs: [1](#0-0) 
- This is written to `withdrawals.payout_payer_operator_xonly_pk` verbatim: [2](#0-1) 
- `PayoutCheckerTask::run_once` reads this column by the operator's own public key and, without any funding/profitability check, immediately calls `handle_finalized_payout`, `end_round`, and `mark_payout_handled`: [3](#0-2) 
- `create_payout_txhandler` builds the payout tx with the *withdrawal UTXO* input (key-spend, `SinglePlusAnyoneCanPay`), a user-output, an anchor, and an **arbitrary caller-supplied `operator_xonly_pk`** written into OP_RETURN — nothing binds this key to whoever actually funds the tx: [4](#0-3) 
- The `SinglePlusAnyoneCanPay` sighash flag on the withdrawal UTXO's signature is exactly what allows *anyone* to complete the transaction by adding their own funding inputs (as `Operator::withdraw` itself does via `fund_raw_transaction`): [5](#0-4) 
- Once a kickoff is sent, the only cross-check performed is that the OP_RETURN key equals `kickoff_data.operator_xonly_pk` — never that the credited operator actually funded the payout: [6](#0-5) [7](#0-6) 
- `Reimburse` always pays the **fixed, full deposit/bridge amount** from the `MoveToVault` UTXO, independent of how much was actually paid to the user in `payout_tx`: [8](#0-7) 

No existing guard (`is_kickoff_malicious`, `send_asserts`, `is_profitable`) checks that the *payer* of the payout tx's funding inputs matches the xonly_pk embedded in OP_RETURN; `is_profitable` is only invoked inside the operator's own `withdraw()` RPC path, not in the passive `PayoutCheckerTask`/`update_finalized_payouts` path that picks up transactions broadcast directly to Bitcoin by anyone.

### Title
Payout attribution trusts an unauthenticated OP_RETURN pubkey, letting anyone credit (and enable Reimburse for) an operator who never funded the withdrawal - ([File: core/src/verifier.rs])

### Summary
`Verifier::update_finalized_payouts` attributes a completed withdrawal to whichever x-only public key appears in the payout transaction's OP_RETURN output, without verifying that key's owner supplied any of the transaction's funding. Because the withdrawal UTXO's signature uses `SIGHASH_SINGLE|ANYONECANPAY`, any unprivileged party can complete the payout transaction, fund it with their own (arbitrarily small, Citrea-withdrawal-amount-bounded) BTC, and embed a real operator's public xonly_pk, causing that operator's automated `PayoutCheckerTask` to mark the withdrawal handled and proceed through kickoff/Reimburse for a payout it never funded.

### Finding Description
The broken binding: `payout_payer_operator_xonly_pk == the party who funded payout_tx`. In `update_finalized_payouts` (core/src/verifier.rs:2312-2342) this value is derived purely via `parse_op_return_data`/`XOnlyPublicKey::from_slice` on the confirmed payout transaction's OP_RETURN, with zero cryptographic link between the embedded key and the transaction's actual funding inputs. `create_payout_txhandler` (core/src/builder/transaction/operator_reimburse.rs:407-436) lets whoever assembles the transaction choose `operator_xonly_pk` freely, and the withdrawal UTXO input is signed with `SinglePlusAnyoneCanPay`, explicitly enabling any third party to append their own paying inputs. `PayoutCheckerTask::run_once` (core/src/task/payout_checker.rs:39-111) reads this DB column keyed by the operator's own signer key, and — without any funding/profitability verification — automatically calls `handle_finalized_payout`, `end_round`, and `mark_payout_handled`. Downstream, `is_kickoff_malicious`/`send_asserts` only check that the OP_RETURN key equals the kickoff's operator key, not that the credited operator funded the payout. Finally, `create_reimburse_txhandler` (core/src/builder/transaction/operator_reimburse.rs:341-384) always disburses the *fixed full bridge/deposit amount* from the `MoveToVault` output, independent of how little the attacker actually spent completing the payout. An attacker (acting as the withdrawer on Citrea, choosing their own dust withdrawal UTXO, signature, sighash, output amount and OP_RETURN) can therefore spend a small amount of real BTC to complete a withdrawal while attributing it to a chosen honest operator's public (previously seen) xonly_pk, triggering that operator's fully automated software to claim a full bridge-amount Reimburse it never funded.

### Impact Explanation
The bridge's `MoveToVault` deposit escrow (fixed bridge_amount, e.g. 10 BTC-equivalent) is disbursed via Reimburse to an operator whose automation was tricked into believing it fronted a withdrawal it did not fund; the attacker (not the credited operator) supplied the actual payout funds, and can size the registered Citrea withdrawal amount arbitrarily small relative to the full reimbursement. This is repeatable per deposit/withdrawal and against any operator whose xonly_pk is publicly known (visible in prior kickoffs/rounds), so the blast radius spans the whole operator set and every future withdrawal. This matches the Critical category "an operator reimbursed for a payout it never funded."

### Likelihood Explanation
Requires only unprivileged capabilities already granted to the attacker: calling Citrea's `withdraw`, choosing/controlling a withdrawal UTXO and its `SinglePlusAnyoneCanPay` signature, constructing the on-chain payout transaction with an arbitrary OP_RETURN, and broadcasting it — no verifier/operator/aggregator privilege, key compromise, or majority hashrate needed. The honest operator's participation is fully automated (`PayoutCheckerTask`, round/kickoff state machines), so no operator cooperation or awareness is required. Attacker cost is bounded by the (attacker-chosen, small) registered withdrawal amount plus Bitcoin fees, versus the fixed full bridge-amount reimbursement obtained by the credited operator — a large asymmetry that makes the attack cheap and repeatable.

### Recommendation
Bind payer attribution cryptographically: require the payout transaction's OP_RETURN-embedded operator key (or a separate signature) to be authenticated by that operator (e.g., an operator signature over the payout tx or its funding inputs) before `update_finalized_payouts`/`PayoutCheckerTask` treats it as "handled by operator X." Additionally, `PayoutCheckerTask`/`handle_finalized_payout` should re-verify profitability/funding provenance (mirroring the `is_profitable` check already done in `Operator::withdraw`) before auto-progressing round state and enabling Reimburse.

### Proof of Concept
`cargo test` plan (regtest, mocked Citrea, no mainnet):
1. Set up one operator O with known `xonly_pk` (public via existing test helpers, e.g. `generate_random_xonly_pk`/actor setup).
2. As "attacker," register a withdrawal on the mock Citrea client for a small `output_amount`, sign the dust withdrawal UTXO with `SinglePlusAnyoneCanPay` using attacker's own key (mirroring `sign_withdrawal_output` in `core/src/test/common/setup_utils.rs`).
3. Construct `payout_tx` via `create_payout_txhandler`, but fund the extra required input entirely from an attacker-controlled wallet UTXO, and set `operator_xonly_pk = O`'s xonly_pk in the OP_RETURN.
4. Broadcast and confirm to finality depth; let the block sync path invoke `update_finalized_payouts`; assert `get_payout_info_from_move_txid` returns `Some(O_pk)` while asserting O signed nothing and funded none of `payout_tx`'s inputs (compare O's wallet UTXO set before/after — unchanged).
5. Let O's `PayoutCheckerTask::run_once` run; assert it returns `Ok(true)` and `mark_payout_handled`/`is_payout_handled = TRUE` is set for O's key, with no funds having left O's wallet.
6. Drive O's normal automated kickoff → `Reimburse` flow to completion; assert the `Reimburse` tx confirms and pays O's `reimburse_addr` the full `bridge_amount`, while asserting the sum of BTC spent from O's own wallet across the whole flow (excluding fixed protocol fees/anchors) is zero — i.e., O is reimbursed for a payout it never funded.

        )>,

        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),

        .finalize())

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
