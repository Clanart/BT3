### Title
PedPoP accepts identity/malformed encryption keys, making encrypted secret shares decryptable by any observer - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
The bug class is "incorrect access control exposing sensitive information via a crafted payload." The analog in Serai is the PedPoP DKG encryption layer: `EncryptionKeyMessage::read` accepts any canonical point as a participant's `enc_key`, and `Decryption::register` stores it without validating it is non-identity or proving possession. A participant registering the identity point causes every secret share ciphertext addressed to them to be encrypted under a publicly known ECDH shared secret, so any unprivileged observer of the wire bytes can decrypt the `SecretShare` plaintext.

### Finding Description
`EncryptionKeyMessage::read` reads `enc_key` with `C::read_G`, which only enforces canonical encoding — identity points are canonical and pass through. [1](#0-0) [2](#0-1) 

`Decryption::register` stores `msg.enc_key` keyed by participant with no non-identity check and no proof of possession over the encryption key itself (the Schnorr PoK in `Commitments` covers only `commitments[0]`, i.e. the secret polynomial, not `enc_key`). [3](#0-2) [4](#0-3) 

When a share is encrypted for that participant, `encrypt` computes `ecdh(key, to) = to * key`. If `to` is the identity point, the shared secret is the identity point — a fixed public constant. `cipher` then derives the ChaCha20 key solely from `transcript(context || shared_key)` with a static IV, so the keystream is fully computable by anyone who knows `context` (which is public protocol data). [5](#0-4) [6](#0-5) 

The crafted payload is an `EncryptionKeyMessage<Commitments>` with a valid commitments PoK but `enc_key` set to the canonical identity encoding — fully reachable by an unprivileged DKG participant through the standard `Commitments::read`/`EncryptionKeyMessage::read` path in `generate_secret_shares`/`verify_r1`.

### Impact Explanation
The encryption layer exists specifically to keep `SecretShare` values confidential in transit ("protect the secret shares during communication", per the DKG spec). With an identity `enc_key`, all shares sent to the malicious registrant are world-decryptable: any passive observer who sees the `EncryptedMessage<C, SecretShare>` ciphertexts recovers the plaintext scalars `f_j(l)` for every sender `j`. This is an unauthorized disclosure of protocol secret material — the exact class of "sensitive information disclosure via crafted payload" as the reference CVE. It also silently degrades the blame system: blame proofs assume messages were confidential to the recipient, but here the recipient's share transcript was never private.

### Likelihood Explanation
Any single participant in a DKG session can submit the crafted commitment message; it requires no collusion, no valid encryption key, and no special privileges. `verify_r1` and `register` perform no check that would reject it, and the protocol proceeds normally — honest senders will happily encrypt to the identity point. The attack is deterministic and leaves no on-protocol evidence other than the malformed `enc_key` itself, which nothing inspects.

### Recommendation
In `Decryption::register` (or `EncryptionKeyMessage::read`), reject `enc_key` values that are the identity point (and ideally require a proof of possession for `enc_key`, binding it to the participant and `context`, mirroring the per-message PoP already used for `EncryptedMessage`). At minimum: `if bool::from(msg.enc_key.is_identity()) { return error }`. Additionally, on the encryption side, `ecdh`/`cipher` could defensively reject an identity shared secret before keystream derivation.

### Proof of Concept
1. Attacker (participant `l`) runs `KeyGenMachine::generate_coefficients` normally to obtain valid `Commitments` and PoK, but constructs the broadcast message as `EncryptionKeyMessage { msg: commitments, enc_key: C::G::identity() }` and serializes it.
2. Each honest participant `j` parses it via `EncryptionKeyMessage::read` (succeeds — identity is canonical), calls `verify_r1` → `encryption.register(l, msg)` (succeeds — no identity check), then `generate_secret_shares` calls `encryption.encrypt(rng, l, share_bytes)`.
3. Inside `encrypt`, `ecdh(&key, to)` returns `identity * key = identity`; `cipher(context, &identity)` produces a ChaCha20 keystream keyed by `H(context || identity_bytes)` with IV `"DKG IV v0.2\0"` — both public constants.
4. Any observer who captures the resulting `EncryptedMessage` (e.g., via `EncryptedMessage::read` on relayed bytes) reconstructs the identical `cipher(context, &Zeroizing::new(C::G::identity()))` and applies the keystream to `msg.msg`, recovering `SecretShare` `f_j(l)` for every sender `j` — decryption of protocol secret material without any authorization or key knowledge, since the "shared secret" is a hardcoded public value.

fn ecdh<C: Ciphersuite>(private: &Zeroizing<C::F>, public: C::G) -> Zeroizing<C::G> {
  Zeroizing::new(public * private.deref())
}

// Each ecdh must be distinct. Reuse of an ecdh for multiple ciphers will cause the messages to be
// leaked.
fn cipher<C: Ciphersuite>(context: [u8; 32], ecdh: &Zeroizing<C::G>) -> ChaCha20 {
  // Ideally, we'd box this transcript with ZAlloc, yet that's only possible on nightly
  // TODO: https://github.com/serai-dex/serai/issues/151
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"encryption_key");

  let mut ecdh = ecdh.to_bytes();
  transcript.append_message(b"shared_key", ecdh.as_ref());
  ecdh.as_mut().zeroize();

  let zeroize = |buf: &mut [u8]| buf.zeroize();

  let mut key = Cc20Key::default();
  let mut challenge = transcript.challenge(b"key");
  key.copy_from_slice(&challenge[.. 32]);
  zeroize(challenge.as_mut());

  // Since the key is single-use, it doesn't matter what we use for the IV
  // The issue is key + IV reuse. If we never reuse the key, we can't have the opportunity to
  // reuse a nonce
  // Use a static IV in acknowledgement of this
  let mut iv = Cc20Iv::default();
  // The \0 is to satisfy the length requirement (12), not to be null terminated
  iv.copy_from_slice(b"DKG IV v0.2\0");

  // ChaCha20 has the same commentary as the transcript regarding ZAlloc
  // TODO: https://github.com/serai-dex/serai/issues/151
  let res = ChaCha20::new(&key, &iv);
  zeroize(key.as_mut());
  res
}

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
  }
