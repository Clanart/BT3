### Title
`clone()` explicitly disables Git's clone-time symlink/hook protection via `GIT_CLONE_PROTECTION_ACTIVE=false` on attacker-controlled `git clone --recursive` targets - (File: `app/src/lib/git/clone.ts`)

### Summary
Git introduced `GIT_CLONE_PROTECTION_ACTIVE` as a safety mechanism (related to the class of clone-time submodule/hook-injection issues, e.g. CVE-2024-32004/CVE-2024-32021) that prevents a malicious repository from smuggling executable hooks or symlink-based path tricks into the working tree via `git clone --recursive`. GitHub Desktop's `clone()` function explicitly overrides this protection by setting the environment variable to `'false'` for every clone, unconditionally. [1](#0-0) 

### Finding Description
`clone()` builds the git invocation with `--recursive` and forces the protection flag off in the child process environment:

```
const env = {
  ...(await envForRemoteOperation(url)),
  GIT_CLONE_PROTECTION_ACTIVE: 'false',
}
...
const args = [
  '-c',
  `init.defaultBranch=${defaultBranch}`,
  'clone',
  '--recursive',
]
``` [1](#0-0) 

The `url` and thus the entire remote-controlled repository content (including `.gitmodules`, submodule URLs, and any embedded hooks that git's protections are designed to catch during recursive clone) is fully attacker-controlled input, whether reached through the "Clone repository" dialog, the CLI (`github clone owner/repo`, see `app/src/cli/main.ts`), or the `x-github-client://openRepo/...` deep link handled by `openOrCloneRepository`/`openRepositoryFromUrl` in the dispatcher. [2](#0-1) [3](#0-2) 

The only other guard present in `clone.ts` is `isClonePathSensitive()`, which only checks the *destination* path against a fixed list of sensitive directories (home dir, `.ssh`, `.gnupg`, etc.) — it does nothing to validate or constrain what the *cloned content itself* can do once `--recursive` submodule initialization/hook execution occurs with the upstream protection disabled. [4](#0-3) 

This is the analog of the report's broken-invariant pattern: a protective value/flag (there: `baseRate`; here: git's built-in clone protection) is unconditionally forced into the unsafe state for every operation, with no compensating check elsewhere in the call path, allowing attacker-supplied content (a malicious remote repo, reachable simply by the victim cloning a link or running `github clone <owner>/<repo>`) to reach a code path that the upstream tool otherwise guards against.

### Impact Explanation
If the disabled protection is what stands between a "clone --recursive" of a crafted repository and unwanted code execution or file writes outside the intended clone directory (which is exactly the class of issue `GIT_CLONE_PROTECTION_ACTIVE` exists to stop), then any user cloning an attacker-supplied URL — via the UI, the `github clone` CLI, or a `x-github-client://openRepo/...` deep link that a victim merely clicks — inherits that risk. That satisfies the "attacker controls a cloned/fetched repository ... link a user clicks ... resulting in code execution / file write outside the repo" impact bar described in the task.

### Likelihood Explanation
Likelihood is high for exposure (this code path executes unconditionally on every clone, including from the deep-link/CLI entry points, requiring no unusual user action beyond the normal "clone this repo" action), but I could not fully verify from the indexed code alone which specific upstream git protection is bypassed by this exact env var in the installed git/dugite version, nor find a code comment in this repo explaining the rationale for forcing it to `'false'`. This should be confirmed by checking the bundled git/dugite version's release notes for `GIT_CLONE_PROTECTION_ACTIVE` before treating this as confirmed-exploitable.

### Recommendation
- Do not unconditionally disable `GIT_CLONE_PROTECTION_ACTIVE`. If there was a legitimate reason (e.g. compatibility with a specific clone flow), scope the override narrowly and document why it's safe, or better, leave the protection enabled and handle any resulting failures explicitly.
- Add a code comment/citation explaining what this flag guards against so future changes don't silently regress it.
- Apply the same "least trust" model used in `isClonePathSensitive()` to the cloned content itself (e.g., validate submodule URLs against `protocol.file.allow`/`protocol.allow` defaults rather than disabling protections outright).

### Proof of Concept
1. Attacker publishes a Git repository whose content is designed to trigger the class of issue `GIT_CLONE_PROTECTION_ACTIVE` protects against during `git clone --recursive` (e.g., via crafted submodule configuration/hooks).
2. Attacker distributes a link: `x-github-client://openRepo/<attacker-repo-url>` or simply the repo's GitHub URL with "Open in Desktop".
3. Victim clicks the link (or runs `github clone <owner>/<repo>` from the CLI), which flows through `openOrCloneRepository` → `_clone` → `clone()` in `app/src/lib/git/clone.ts`.
4. `clone()` invokes `git ... clone --recursive -- <url> <path>` with `GIT_CLONE_PROTECTION_ACTIVE: 'false'` forced in the environment, bypassing the built-in protection for the entire recursive clone/submodule-init sequence. [5](#0-4)

function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}

  private async openOrCloneRepository(url: string): Promise<Repository | null> {
    const state = this.appStore.getState()
    const repositories = state.repositories
    const existingRepository = repositories.find(r =>
      this.doesRepositoryMatchUrl(r, url)
    )

    if (existingRepository) {
      return await this.selectRepository(existingRepository)
    }

    return this.appStore._startOpenInDesktop(() => {
      this.changeCloneRepositoriesTab(CloneRepositoryTab.Generic)
      this.showPopup({
        type: PopupType.CloneRepository,
        initialURL: url,
      })
    })
  }
