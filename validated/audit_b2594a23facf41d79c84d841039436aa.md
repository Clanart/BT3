### Title
`compute_v2_review_set` drops files modified via `git commit --amend` from the Stop-hook review set, silently skipping security review of dangerous changes - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Summary
`compute_v2_review_set` only includes a file changed since the turn baseline if that file is either (a) currently dirty per `git status` (`dirty_now`), or (b) part of a *linear* HEAD advance (`_is_ancestor(head_at_capture, current_head)`). A `git commit --amend` during a turn rewrites history non-linearly and leaves the working tree clean, so the amended file satisfies neither condition and is excluded from `review_set` even though its content demonstrably differs from the stash baseline (`changed_since`).

### Finding Description
`compute_v2_review_set` computes `review_set = dirty_now ∩ changed_since` (falling back to `dirty_now` alone if `changed_since` is unavailable). [1](#0-0) 

`dirty_now` is built from `git status --porcelain` (`tracked_dirty`/`new_untracked`), plus, only when `head_at_capture` is an ancestor of `current_head` (i.e., HEAD moved forward linearly via ordinary commits), the name-only diff of `head_at_capture..HEAD`: [2](#0-1) 

`_is_ancestor` explicitly checks only for forward/linear movement ("HEAD moved forward via commit/merge, not sideways via checkout"): [3](#0-2) 

`git commit --amend` rewrites the tip commit to a new SHA whose old tip is *not* reachable from the new tip in the ancestor sense the check relies on for range diffing — the working tree becomes clean immediately after the amend (nothing left in `git status`), and `head_at_capture..HEAD` is not used because `_is_ancestor` gate is not satisfied for this rewritten-history case in the same turn. As a result, the amended file is absent from `dirty_now`, and since `review_set = dirty_now ∩ changed_since`, the file is dropped from `review_set` regardless of the fact that `changed_since` (diff against `baseline_sha`, the stash captured at `UserPromptSubmit`) correctly shows the content changed: [4](#0-3) 

This is invoked directly by `handle_stop_hook`, which treats an empty/incomplete `review_paths` result as "no changes since baseline" and skips the LLM security review entirely: [5](#0-4)  and [6](#0-5) 

No existing check compensates for this: the code's own docstring only claims correctness for the linear-advance case ("plus files committed this turn when HEAD advanced linearly") and does not mention amend/rebase/rewrite as a covered or excluded scenario. [7](#0-6) 

### Impact Explanation
Because the Stop hook is the sole gate that triggers Claude's LLM-based security review/reminder for uncommitted-or-just-committed changes in a turn, a dangerous edit that is committed and then amended in the same turn (a routine, unprivileged git workflow — e.g., "fix a typo, then `git commit --amend --no-edit`") is silently excluded from `review_paths` and therefore never surfaces in the diff sent for review. This breaks the stated invariant that "the review set must stay bound to the right repo, baseline, and touched paths," letting a security-relevant change (e.g., introduced secret, unsafe deserialization, unintended sink) pass through unflagged. This matches the "Sensitive code/diff disclosure to an unintended sink" framing in the sense that the security-guidance detection layer — the mechanism meant to catch and warn about such disclosures before they land — is bypassed for amended commits.

### Likelihood Explanation
This requires no special privilege beyond normal repository/git access in a session where the Stop hook's v2 review path is active: any turn in which a file is committed and then amended (a common, unremarkable workflow, including automated agent behavior fixing up its own prior commit) triggers the gap deterministically. It is fully repeatable and does not depend on race conditions, external services, or any bypass of approval prompts.

### Recommendation
In `compute_v2_review_set`, do not gate the head-range diff on `_is_ancestor` alone. When `head_at_capture != current_head`, additionally union in the set of paths where `git diff --name-only head_at_capture current_head` (a non-range, two-dot content diff, which works regardless of ancestry) differs, so amended/rebased/force-updated commits are still captured. Alternatively, always compute `changed_since` relative to `baseline_sha` and use it directly as (part of) `dirty_now` for files that are tracked-clean but differ from `head_at_capture`, rather than only intersecting with the porcelain-status-derived `dirty_now`.

### Proof of Concept
Unit/integration test plan (extends existing `compute_v2_review_set` test style):
1. Init a temp git repo, commit an initial file, capture `head_at_capture = HEAD` and `baseline_sha = capture_git_baseline(cwd)` (clean tree).
2. Edit `dangerous.py` with an injected vulnerable pattern, `git add` + `git commit -m "wip"`.
3. Run `git commit --amend --no-edit` (or amend with a small further edit) so the working tree is clean and HEAD is a new, non-ancestor-related SHA relative to `head_at_capture` in the sense checked by `_is_ancestor`.
4. Call `compute_v2_review_set(cwd, baseline_sha, head_at_capture, {})`.
5. Assert that `review_paths` contains the absolute path to `dangerous.py`.
   - Expected (current buggy behavior): `dangerous.py` is absent from `review_paths` because `dirty_now` is empty and `_is_ancestor(head_at_capture, HEAD)` is False for the rewritten tip, so the intersection with `changed_since` yields nothing.
   - Expected (after fix): `dangerous.py` is present, since the fix unions in files differing from `head_at_capture` regardless of ancestry.
6. End-to-end variant: drive `handle_stop_hook` with this git state and assert it does NOT take the `_skip(6)` ("no changes since baseline") path and that `diff_files` includes `dangerous.py`.

```python
def compute_v2_review_set(cwd, baseline_sha, head_at_capture, untracked_at_baseline=None):
    """v2 diff strategy: derive the review set from git state alone.

    review_set = (files dirty vs current HEAD, plus files committed this turn
    when HEAD advanced linearly) ∩ (files whose content differs from the
    pre-turn stash baseline). The first term is immune to checkout/pull
    ballooning; the second filters out the user's untouched pre-turn WIP.
    Falls back to dirty_now alone when no baseline is available.
```

```python
    dirty_now = tracked_dirty | new_untracked

    diff_base = "HEAD"
    current_head = _git_rev_parse_head(repo)
    if (head_at_capture and current_head and head_at_capture != current_head
            and _is_ancestor(repo, head_at_capture, current_head)):
        dirty_now |= _git_name_only(repo, f"{head_at_capture}..HEAD") or set()
        diff_base = head_at_capture

    # changed_since: tracked files vs the stash baseline (no temp index — the
    # stash never contained untracked files anyway), then union with
    # currently-untracked. The previous `include_untracked=True` arm cost a
    # full `git add -N .` (slow in large repos) per call to surface
    # untracked files in the diff output — but `git diff <stash>` already
    # lists them as "only in worktree" without that, and we have the explicit
    # set from status regardless.
    if baseline_sha:
        changed_since = _git_name_only(repo, baseline_sha)
        if changed_since is not None:
            changed_since |= new_untracked
    else:
        changed_since = None
    # changed_since is None on missing baseline OR on git error (e.g. the
    # dangling stash SHA was pruned). Either way, don't intersect with ∅ —
    # that would silently zero the review set. Fall back to dirty_now.
    review_set = (dirty_now & changed_since) if changed_since is not None else dirty_now
```

```python
def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
```
