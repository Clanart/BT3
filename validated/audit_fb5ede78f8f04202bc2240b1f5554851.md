## Analog Found

### Title
Full-node RPC and mempool-admission paths dereference `MempoolManager` before initialization, causing a startup-window crash on spend/RPC calls - (File: chia/full_node/full_node_rpc_api.py, chia/full_node/full_node.py)

### Summary
The erigon report fixes a nil-pointer panic where `GetEthV1ValidatorAttestationData` and related beacon accessors dereferenced shared state (`headState`, `committeeIndex`) before the node had synced, while sibling accessors in the same file already carried the lock/nil-check convention. Chia's `FullNode` has the same missing-guard asymmetry around `self.mempool_manager`: it is `None` during node startup, `get_blockchain_state()` explicitly guards every mempool field access with `if self.service.mempool_manager is not None`, but several sibling RPC handlers and the transaction-admission entry point do not follow that same guard.

### Finding Description
`FullNodeRpcApi.get_blockchain_state()` treats `self.service.mempool_manager` as possibly `None` and branches accordingly before touching `.mempool`: [1](#0-0) 

But the mempool-facing RPC endpoints registered in the same `get_routes()` table dereference `self.service.mempool_manager.mempool` (or `.get_mempool_item`) unconditionally, with no equivalent `is not None` check: [2](#0-1) 

`create_block_generator()`, also in the same RPC table, likewise calls `self.service.mempool_manager.create_block_generator2(...)` inside the priority-mutex block without checking `mempool_manager is not None`: [3](#0-2) 

On the transaction-admission side, `FullNode.add_transaction()` — the function backing `/push_tx` and the peer `send_transaction` path — immediately calls `self.mempool_manager.get_spendbundle(spend_name)`, `self.mempool_manager.seen(...)`, and `self.mempool_manager.in_flight(...)` before any check that `self.mempool_manager` itself is non-`None`; the only mempool-related guard present is `self.mempool_manager.peak is None`, which itself would already crash if `self.mempool_manager` were `None`: [4](#0-3) 

This is functionally the same bug class as the erigon commit: a shared, lazily-initialized piece of state (`headState` in erigon, `mempool_manager` in chia) is nil/`None` during a startup/pre-sync window, one accessor in the file demonstrates the correct nil-guard convention, and sibling accessors that are equally reachable from an external request omit it.

### Impact Explanation
If `self.service.mempool_manager` is `None` during the window between full-node process start and mempool initialization completing, any local RPC caller hitting `/get_all_mempool_tx_ids`, `/get_all_mempool_items`, `/get_mempool_item_by_tx_id`, `/get_mempool_items_by_coin_name`, or `/create_block_generator`, or any wallet/spend-bundle submitter hitting `/push_tx` (via `add_transaction`), triggers an unhandled `AttributeError` on `NoneType`. Depending on how the RPC/message-handling layer treats unexpected exceptions from these code paths versus `RpcError`, this can present as a transaction-processing halt for that request path rather than the graceful `Err.NO_TRANSACTIONS_WHILE_SYNCING` / `MEMPOOL_NOT_INITIALIZED` responses the rest of the code base clearly intends (as shown by the extensive, deliberate "no peak" guards elsewhere in `add_transaction`, e.g. lines 3036–3050). This matches the "spend-triggered transaction-processing halt" impact category.

### Likelihood Explanation
Reachability requires only that the RPC/P2P surface be reachable during the narrow window before `mempool_manager` is assigned — this is a normal startup sequence on every node restart, not a rare or attacker-controlled race, and `/push_tx` is a first-class externally-reachable endpoint for a "spend-bundle submitter." The likelihood of the exact window being hit depends on startup timing and how quickly RPC/P2P listeners come up relative to mempool initialization, which I could not fully confirm from the indexed code (the exact ordering of `self.mempool_manager = None` vs. `self._start()` completion in `full_node.py` was only partially visible in the available grep results, so the precise duration/reachability of this window is not fully verified).

### Recommendation
Add an explicit `if self.service.mempool_manager is None: raise RpcError(...)` (or equivalent early return) at the top of `get_all_mempool_tx_ids`, `get_all_mempool_items`, `get_mempool_item_by_tx_id`, `get_mempool_items_by_coin_name`, and `create_block_generator` in `chia/full_node/full_node_rpc_api.py`, mirroring the guard already used in `get_blockchain_state`. Add the same `self.mempool_manager is None` check at the very top of `FullNode.add_transaction()` in `chia/full_node/full_node.py`, before any attribute access, returning `MempoolInclusionStatus.FAILED, Err.NO_TRANSACTIONS_WHILE_SYNCING` (consistent with the existing not-synced/no-peak handling).

### Proof of Concept
Not independently reproduced in this session (no execution environment available). Conceptually: start `FullNode`/`FullNodeRpcApi` such that `self.mempool_manager` is still `None` (immediately after process construction, before mempool initialization completes), then issue an RPC call to `/get_all_mempool_items` or `/push_tx`; the handler will raise `AttributeError: 'NoneType' object has no attribute 'mempool'` (or `'get_spendbundle'`) instead of returning a structured RPC error, because these handlers, unlike `get_blockchain_state`, lack the `mempool_manager is not None` guard verified at [1](#0-0) .

    async def get_all_mempool_items(self, _: dict[str, Any]) -> EndpointResult:
        spends = {}
        for item in self.service.mempool_manager.mempool.all_items():
            spends[item.name.hex()] = item.to_json_dict()
        return {"mempool_items": spends}

    async def get_mempool_item_by_tx_id(self, request: dict[str, Any]) -> EndpointResult:
        if "tx_id" not in request:
            raise RpcError.simple(RpcErrorCodes.NO_TX_ID_IN_REQUEST, "No tx_id in request")
        include_pending: bool = request.get("include_pending", False)
        tx_id: bytes32 = bytes32.from_hexstr(request["tx_id"])

        item = self.service.mempool_manager.get_mempool_item(tx_id, include_pending)
        if item is None:
            raise RpcError(
                RpcErrorCodes.TX_NOT_IN_MEMPOOL,
                f"Tx id 0x{tx_id.hex()} not in the mempool",
                data={"tx_id": tx_id.hex()},
                structured_message="Tx id not in the mempool",
            )

        return {"mempool_item": item.to_json_dict()}

    async def get_mempool_items_by_coin_name(self, request: dict[str, Any]) -> EndpointResult:
        if "coin_name" not in request:
            raise RpcError.simple(RpcErrorCodes.NO_COIN_NAME_IN_REQUEST, "No coin_name in request")

        coin_name: bytes32 = bytes32.from_hexstr(request["coin_name"])
        items = self.service.mempool_manager.mempool.get_items_by_coin_id(coin_name)

        return {"mempool_items": [item.to_json_dict() for item in items]}
