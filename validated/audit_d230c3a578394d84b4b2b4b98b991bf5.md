### Title
Deposits attributed to the wrong transaction's origin/instruction — outputs from earlier transactions in a block are overwritten by later transactions' data (networks/bitcoin/src — `Bitcoin::get_outputs` in processor/src/networks/bitcoin.rs)

### Summary
Analogous to the Omnipool assuming `1 rETH = 1 ETH`, `Bitcoin::get_outputs` assumes a 1:1 relationship between a scanned transaction and the outputs accumulated for the block. The `outputs` vector is declared once before the `for tx in &block.txdata[1 ..]` loop, but the `presumed_origin` and Serai `data` population pass iterates `&mut outputs` — every output collected so far, including ones pushed by earlier transactions. A later transaction in the same block therefore overwrites the `data` (the `InInstruction`) and `presumed_origin` of deposits made in earlier transactions. [1](#0-0) 

### Finding Description
In `impl Network for Bitcoin`, `get_outputs` does:

```rust
let mut outputs = vec![];
for tx in &block.txdata[1 ..] {
  for output in scanner.scan_transaction(tx) {
    ...
    outputs.push(output);
  }
  if outputs.is_empty() { continue; }
  let presumed_origin = { ... tx.input[0] ... };
  let data = Self::extract_serai_data(tx);
  for output in &mut outputs {
    if output.kind == OutputType::External {
      output.data.clone_from(&data);
    }
    output.presumed_origin.clone_from(&presumed_origin);
  }
}
``` [2](#0-1) 

The intent is clearly to annotate *the outputs of `tx`*, but `outputs` is cumulative across the whole block. Two consequences:

1. **Clobbering:** if `tx1` produces an External output with `InInstruction` data `D1`, and `tx2` (any later tx in the same block, including one carrying zero Serai outputs but at least one scanned output — attacker dust to the multisig address suffices to enter the population block) has data `D2`, then `tx1`'s output ends up with `data = D2` and `presumed_origin = tx2.input[0]`'s source address. If `tx2` carries no Serai data, the victim's instruction is erased entirely.
2. **Misattribution:** `presumed_origin` is taken from `tx.input[0]` only, already assuming all inputs/outputs of a tx share one origin; combined with the accumulation bug, every output in the block ends up stamped with the *last* scanned tx's first input.

These annotated outputs feed `scanner_event_to_multisig_event` → `instruction_from_output` in `processor/src/multisigs/mod.rs`, which derives refund/forwarding instructions from the output's data and balance. [3](#0-2) 

### Impact Explanation
An unprivileged attacker who can get a transaction into the same block as a victim's deposit (normal on Bitcoin — blocks are public, and the attacker only needs to send ≥ `DUST` = 10,000 sats to a known multisig script) can replace or erase the victim deposit's embedded `InInstruction`. Depending on how `instruction_from_output` treats data-less or attacker-controlled instructions, the deposit can be refunded to the attacker's `presumed_origin`, credited under the attacker's instruction payload, or stranded. This satisfies "funds reported received that are not spendable / incorrectly attributed." [4](#0-3) 

### Likelihood Explanation
Requires only that the attacker's tx land in a block after any tx containing a Serai-bound output — trivially achievable with fee bidding or by mining/ordering luck, and repeatable every block. No validator compromise needed; the inputs are ordinary public Bitcoin transactions.

### Recommendation
Scope the population loop to the outputs of the current `tx` — e.g., track `let start = outputs.len()` before scanning `tx` and iterate `&mut outputs[start ..]`, or annotate each `ReceivedOutput` inside the inner scan loop directly. Also derive `presumed_origin` per-output/per-tx rather than assuming `tx.input[0]` represents the origin of all outputs.

### Proof of Concept
1. Victim broadcasts `tx_v` paying ≥10,000 sats to the multisig `p2tr` script with embedded Serai `InInstruction` `I_v`.
2. Attacker broadcasts `tx_a` paying ≥10,000 sats to the same script, with `input[0]` spending an attacker-controlled output and either no Serai data or attacker-chosen data `I_a`, ordered after `tx_v` in the block (higher fee / miner arrangement).
3. `get_outputs(block)` scans `tx_v`, stores `I_v`/origin `O_v`; then scans `tx_a` and rewrites the victim's `ReceivedOutput` to `data = I_a` (or empty), `presumed_origin = O_a`.
4. `scanner_event_to_multisig_event` processes the victim's real deposit under the attacker's instruction/origin — the victim's funds are mis-instructed or refunded to the attacker.

  async fn get_outputs(&self, block: &Self::Block, key: ProjectivePoint) -> Vec<Output> {
    let (scanner, _, kinds) = scanner(key);

    let mut outputs = vec![];
    // Skip the coinbase transaction which is burdened by maturity
    for tx in &block.txdata[1 ..] {
      for output in scanner.scan_transaction(tx) {
        let offset_repr = output.offset().to_repr();
        let offset_repr_ref: &[u8] = offset_repr.as_ref();
        let kind = kinds[offset_repr_ref];

        let output = Output { kind, presumed_origin: None, output, data: vec![] };
        assert_eq!(output.tx_id(), tx.id());
        outputs.push(output);
      }

      if outputs.is_empty() {
        continue;
      }

      // populate the outputs with the origin and data
      let presumed_origin = {
        // This may identify the P2WSH output *embedding the InInstruction* as the origin, which
        // would be a bit trickier to spend that a traditional output...
        // There's no risk of the InInstruction going missing as it'd already be on-chain though
        // We *could* parse out the script *without the InInstruction prefix* and declare that the
        // origin
        // TODO
        let spent_output = {
          let input = &tx.input[0];
          let mut spent_tx = input.previous_output.txid.as_raw_hash().to_byte_array();
          spent_tx.reverse();
          let mut tx;
          while {
            tx = self.rpc.get_transaction(&spent_tx).await;
            tx.is_err()
          } {
            log::error!("couldn't get transaction from bitcoin node: {tx:?}");
            sleep(Duration::from_secs(5)).await;
          }
          tx.unwrap().output.swap_remove(usize::try_from(input.previous_output.vout).unwrap())
        };
        Address::new(spent_output.script_pubkey)
      };
      let data = Self::extract_serai_data(tx);
      for output in &mut outputs {
        if output.kind == OutputType::External {
          output.data.clone_from(&data);
        }
        output.presumed_origin.clone_from(&presumed_origin);
      }
    }

    outputs
  }
