### Title
Operator reimbursement attribution trusts an unauthenticated OP_RETURN field, allowing a withdrawing user to self-front a payout and frame an operator into claiming reimbursement it never funded — ([File: core/src/verifier.rs])

### Summary
The bridge decides *which operator gets reimbursed* for a Bitcoin `payout_tx` purely from an unauthenticated OP_RETURN output inside that transaction. Nothing ties the OP_RETURN's `operator_xonly_pk` to the entity that actually funded/broadcast the transaction. Because the withdrawal input is spent with a `SinglePlusAnyoneCanPay` signature, the withdrawing user (an unprivileged party, not an operator/verifier/aggregator) already possesses everything needed to construct and broadcast their own `payout_tx` directly to the Bitcoin network — bypassing Clementine's gRPC entirely — while stamping an arbitrary victim operator's x-only public key into the OP_RETURN. The verifiers' chain-scan then blindly records that victim operator as the payer, and the victim operator's own automation (`PayoutCheckerTask`) will subsequently claim reimbursement from the shared vault for a withdrawal it never funded.

### Finding Description
`create_payout_txhandler` embeds an `operator_xonly_pk` into an OP_RETURN output with no signature or commitment binding it to the funding inputs of the transaction: [1](#0-0) 

Only the withdrawal input (index 0) is signed by the user's `SinglePlusAnyoneCanPay` signature; any other inputs (funding) and all outputs (including the OP_RETURN) are unconstrained and can be freely chosen by whoever assembles the final transaction: [2](#0-1) 

Because `SinglePlusAnyoneCanPay` only commits input 0 and its matching output, **anyone possessing the withdrawal input's signature can build and broadcast this transaction, adding their own funding input and paying the user themselves — no operator or Clementine RPC involvement is required.** The withdrawing user always legitimately possesses this signature for their own withdrawal (it's their signature over their own `WithdrawParams`), so the user qualifies as an unprivileged attacker who is not a verifier/operator/watchtower/aggregator/security council/sequencer.

Once such a transaction confirms and finalizes on Bitcoin, the verifier's block scanner parses the OP_RETURN and stores its content as the "payer" with no check that the named operator actually funded any input: [3](#0-2) 

This is persisted via `update_payout_txs_and_payer_operator_xonly_pk`: [4](#0-3) 

The victim operator's own background task polls for payouts attributed to its own key and, upon finding one, automatically proceeds to build the kickoff/reimbursement flow — trusting the DB-recorded attribution completely: [5](#0-4) [6](#0-5) 

`handle_finalized_payout` then locates an unused kickoff connector and drives the operator toward sending `kickoff_tx`/`reimburse_tx`: [7](#0-6) 

The only cross-check performed elsewhere (`is_kickoff_malicious`) compares the OP_RETURN-recorded pubkey against the pubkey of whoever sends the kickoff — which is trivially satisfied here because the victim operator (the one framed in the OP_RETURN) is the one whose automation sends the kickoff: [8](#0-7) 

There is no check anywhere in this path that verifies the claimed operator's wallet actually funded any input of the `payout_tx`, i.e., that `payout_payer_operator_xonly_pk` equals the party that actually paid. This breaks the binding: **`payout_payer_operator_xonly_pk` (operator credited) == the entity that funded the payout_tx's non-withdrawal inputs (party that paid)**. Before the attack this equality naturally holds because only operators build and broadcast payout transactions through the RPC flow in `operator.rs::withdraw`, which always inserts `self.signer.xonly_public_key`: [9](#0-8) 
After the attack, the equality is broken: the recorded payer is the framed victim operator, while the true funder is the withdrawing user.

### Impact Explanation
This matches the Critical impact category "an operator reimbursed for a payout it never funded" / "an honest operator's collateral burned" (the victim operator spends its own kickoff connector, collateral round progression, and on-chain fees pursuing a reimbursement for money it never paid, and ultimately receives BTC from the shared vault for a withdrawal event it did not fund). It directly parallels the reported bug class: a derived attribution/accounting field (`euRetailInvestorsCount` there; `payout_payer_operator_xonly_pk` here) is updated from an event (a transfer there; a chain-observed OP_RETURN here) without validating that the recorded party is actually who caused the underlying state change, letting the two diverge and causing the system to act on the wrong attribution.

### Likelihood Explanation
Any user who has legitimately requested a withdrawal already holds the exact `SinglePlusAnyoneCanPay` signature needed. No compromise of verifier/operator/aggregator keys, no majority hashrate, no TLS interception, and no reliance on a misconfigured deployment are required — the user simply constructs and broadcasts a standard Bitcoin transaction outside of Clementine's gRPC surface. The described attack path uses only publicly documented protocol mechanics (sighash flags, OP_RETURN parsing) with no dependence on ignoring documented configuration.

### Recommendation
Do not treat the OP_RETURN pubkey in a `payout_tx` as proof that the named operator funded the transaction. Require the operator to co-sign or otherwise cryptographically commit to fronting the payout (e.g., require an operator signature over the payout transaction itself, or require that the additional funding input(s) are provably spent from that operator's registered collateral/wallet key) before `update_finalized_payouts` records `payout_payer_operator_xonly_pk`, and before `PayoutCheckerTask`/`handle_finalized_payout` proceed to kickoff/reimbursement.

### Proof of Concept
1. User requests a withdrawal on Citrea and obtains their `WithdrawParams` (`input_signature`, `input_outpoint`, `output_script_pubkey`, `output_amount`) as normal — this signature is theirs by construction, requiring no operator or verifier cooperation.
2. Instead of sending `WithdrawParams` to any Clementine operator RPC, the user independently constructs a transaction spending `input_outpoint` with `input_signature` at index 0 (matching `create_payout_txhandler`'s structure: user output + anchor + OP_RETURN), adds their own extra input(s) to cover fees/output funding, and sets the OP_RETURN payload to the x-only public key of a victim operator (obtained from `GetXOnlyPublicKey`/`GetParams`, which is public).
3. User broadcasts this transaction directly to the Bitcoin network (bypassing all Clementine gRPC services).
4. Once the transaction is mined and finalized, verifiers' `update_finalized_payouts` (`core/src/verifier.rs:2283-2353`) parses the OP_RETURN and calls `update_payout_txs_and_payer_operator_xonly_pk`, recording the victim operator as payer.
5. The victim operator's `PayoutCheckerTask` (`core/src/task/payout_checker.rs`) finds this "unhandled payout" via `get_first_unhandled_payout_by_operator_xonly_pk` and automatically drives `handle_finalized_payout` → kickoff → reimbursement, claiming BTC from the shared vault for a withdrawal it never funded.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

        }
        Ok(false)

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }

            .operator
            .handle_finalized_payout(

            .operator

            .await?;

            .mark_payout_handled(Some(&mut dbtx), citrea_idx, kickoff_txid)
            .await?;

        dbtx.commit().await?;
