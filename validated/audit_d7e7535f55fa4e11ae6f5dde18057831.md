### Title
Unhandled `IndexError` in canonical-CLVM length-prefix parser causes spend-triggered mempool validation crash - ([File: chia/full_node/mempool_manager.py])

### Summary
The CVE bug class (ASN.1 CHOICE-type parser mishandling causing an unbounded/uncontrolled parsing loop over attacker-controlled bytes, leading to DoS) maps to `is_clvm_canonical()` / `is_atom_canonical()` in [1](#0-0) . These functions parse the raw, attacker-controlled `puzzle_reveal` and `solution` bytes of every coin spend in a submitted `SpendBundle` with a hand-rolled byte-offset state machine that never validates `offset` against the buffer length before indexing into it.

### Finding Description
`is_clvm_canonical()` is invoked directly on unsanitized, submitter-controlled bytes inside `MempoolManager.validate_spend_bundle()`: [2](#0-1) 

Both `is_clvm_canonical()`'s `while True` loop and the length-prefix decoding loop in `is_atom_canonical()` index into `clvm_buffer[offset]` without ever checking `offset < len(clvm_buffer)`: [3](#0-2) [4](#0-3) 

A crafted `puzzle_reveal` or `solution` can end with a multi-byte length-prefix marker (e.g. `0xFC`/`0xFD`/... a 6-byte-prefix atom marker) with too few trailing bytes, or with a `tokens_left` counter kept artificially positive (via `0xFF` "pair" bytes) so that `offset` runs past `len(clvm_buffer)` before `tokens_left` reaches zero. In either case, `clvm_buffer[offset]` raises an uncaught `IndexError` rather than gracefully returning `False`.

This is structurally analogous to CVE-2017-9023: a hand-written parser over untrusted, attacker-supplied bytes that fails to bound its position/state machine correctly, so malformed/crafted input drives the parser into an unintended failure mode instead of a controlled rejection.

### Impact Explanation
`validate_spend_bundle()` is called for every spend bundle admitted to (or evaluated against) the mempool, from `add_spend_bundle()`, which itself is reachable by any unprivileged peer submitting a `SpendBundle`/transaction (wallet RPC `push_tx`, or a peer relaying a transaction). Neither `add_spend_bundle()` nor `validate_spend_bundle()` wraps the `is_clvm_canonical()` calls in a `try/except`: [5](#0-4) 

An uncaught `IndexError` propagating out of `validate_spend_bundle()` (called from `add_spend_bundle()`, which is awaited directly by the full-node's per-connection message handler) is not a `ValidationError`/`ValueError`/`Err` result the caller is prepared to handle — it will raise instead of returning a `SpendBundleAddInfo`. Depending on how the calling coroutine/task is supervised, this can abort the transaction-processing task for that peer, or bubble up uncaught in the event loop, halting processing of that spend bundle path. This matches the "spend-triggered transaction-processing halt" impact category: a single crafted spend bundle can turn a routine admission check into an unhandled exception rather than a normal `INVALID_COIN_SOLUTION` rejection.

### Likelihood Explanation
Likelihood is high for triggering the crash condition: any unprivileged party who can submit a `CoinSpend` (puzzle_reveal/solution) — e.g., a wallet RPC `push_tx` caller or a mempool peer — fully controls the raw bytes fed into `is_clvm_canonical()`. Constructing a buffer whose final bytes are a truncated multi-byte atom-length prefix, or one that keeps `tokens_left > 0` via `0xFF` pair markers until the buffer is exhausted, is trivial and requires no signature, no fee, and no prior chain state — the canonical-form check runs before cost/fee/coin-record checks in `validate_spend_bundle()`.

### Recommendation
- Add explicit bounds checks in `is_atom_canonical()` before each `clvm_buffer[offset]` access in the prefix-reading loop, returning a "not canonical"/error result instead of indexing out of range.
- Add the same bound check in `is_clvm_canonical()`'s main loop (`if offset >= len(clvm_buffer): return False`) before dereferencing `clvm_buffer[offset]`.
- Wrap the `is_clvm_canonical()` calls (or the whole canonical-check block) in `validate_spend_bundle()` with a `try/except (IndexError, ValueError)` that maps any parsing failure to `Err.INVALID_COIN_SOLUTION`, so malformed input always yields a normal rejection instead of an unhandled exception.
- Add regression tests with truncated/short buffers ending mid length-prefix and with unterminated pair sequences, verifying `is_clvm_canonical` returns `False` rather than raising.

### Proof of Concept
```python
from chia.full_node.mempool_manager import is_clvm_canonical

# Buffer ends immediately after a 6-byte-length-prefix atom marker (0xFC),
# with zero trailing length/payload bytes -> is_atom_canonical() reads
# clvm_buffer[offset] past the end of the buffer.
malformed = b"\xfc"
is_clvm_canonical(malformed)  # raises IndexError instead of returning False

# Alternative: an unterminated sequence of "pair" markers (0xFF) that keeps
# tokens_left positive until the buffer is exhausted.
malformed2 = b"\xff" * 8
is_clvm_canonical(malformed2)  # tokens_left never reaches 0 before offset
                                # runs past len(clvm_buffer) -> IndexError
```
Submitting a `CoinSpend` whose `puzzle_reveal`/`solution` bytes are shaped this way, wrapped in a `SpendBundle` and pushed via the normal transaction-submission path, drives execution into `MempoolManager.validate_spend_bundle()` at [6](#0-5)  where the uncaught `IndexError` is raised instead of a clean `Err.INVALID_COIN_SOLUTION` rejection.

**Note on confidence**: I was not able to fully trace, within the available indexed context, exactly how the top-level RPC/peer message-handling task supervises exceptions raised out of `add_spend_bundle()` (i.e., whether some higher-level generic exception handler in the full-node message dispatcher ultimately swallows this `IndexError` and only logs it, versus it terminating the request/task). That caller-side exception-handling behavior could not be verified from the retrieved code and would need direct confirmation in a full session before treating the "processing halt" impact as fully confirmed rather than a likely-but-unverified consequence.

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value


def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

```python
    async def add_spend_bundle(
        self,
        new_spend: SpendBundle,
        conds: SpendBundleConditions,
        spend_name: bytes32,
        first_added_height: uint32,
        get_coin_records: Callable[[Collection[bytes32]], Awaitable[list[CoinRecord]]] | None = None,
        get_unspent_lineage_info_for_puzzle_hash: Callable[[bytes32], Awaitable[UnspentLineageInfo | None]]
        | None = None,
    ) -> SpendBundleAddInfo:
        """
        Validates and adds to mempool a new_spend with the given
        SpendBundleConditions, and spend_name, and the current mempool. The mempool
        should be locked during this call (blockchain lock). If there are mempool
        conflicts, the conflicting spends might be removed (if the new spend is
        a superset of the previous). Otherwise, the new spend might be
        added to the potential pool.

        Args:
            new_spend: spend bundle to validate and add
            conds: SpendBundleConditions resulting from running the clvm in the spend bundle's coin spends
            spend_name: hash of the spend bundle data, passed in as an optimization

        Returns:
            Optional[uint64]: cost of the entire transaction, None iff status is FAILED
            MempoolInclusionStatus:  SUCCESS (should add to pool), FAILED (cannot add), and PENDING (can add later)
            list[MempoolRemoveInfo]: conflicting mempool items which were removed, if no Err
            Optional[Err]: Err is set iff status is FAILED
        """

        # Skip if already added
        existing_item = self.mempool.get_item_by_id(spend_name)
        if existing_item is not None:
            return SpendBundleAddInfo(existing_item.cost, MempoolInclusionStatus.SUCCESS, [], None)

        if get_coin_records is None:
            get_coin_records = self.get_coin_records

        if get_unspent_lineage_info_for_puzzle_hash is None:
            get_unspent_lineage_info_for_puzzle_hash = self.get_unspent_lineage_info_for_puzzle_hash

        err, item, remove_items = await self.validate_spend_bundle(
            new_spend,
            conds,
            spend_name,
            first_added_height,
            get_coin_records,
            get_unspent_lineage_info_for_puzzle_hash,
        )
        if err is None:
            # No error, immediately add to mempool, after removing conflicting TXs.
            assert item is not None
            conflict = self.mempool.remove_from_pool(remove_items, MempoolRemoveReason.CONFLICT)
            info = self.mempool.add_to_pool(item)
            if info.error is not None:
                return SpendBundleAddInfo(item.cost, MempoolInclusionStatus.FAILED, [], info.error)
            return SpendBundleAddInfo(item.cost, MempoolInclusionStatus.SUCCESS, [*info.removals, conflict], None)
```
