### Title
Missing validation on governance parameter `kip71.gastarget` allows a single validator vote to set `GasTarget = 0`, causing a division-by-zero panic in the KIP-71 base fee calculation and halting all nodes - (File: kaiax/gov/param.go, params/kip71_config.go)

### Summary
The `Kip71GasTarget` governance parameter uses `noopFormatChecker`, meaning any `uint64` value — including `0` — is accepted as valid without range checking, unlike other KIP-71 parameters (`Kip71BaseFeeDenominator` explicitly rejects `0`). The KIP-71 base fee formula in `NextMagmaBlockBaseFee` divides by `gasTarget` without a zero-check, unlike `baseFeeDenominator`, which is defensively substituted with `64` when `0`. Setting `gasTarget` to `0` therefore causes a division-by-zero panic in every node computing the next block's base fee, which is invoked deterministically during header preparation and verification by all nodes.

### Finding Description
`Kip71GasTarget`'s parameter definition in `kaiax/gov/param.go` has `FormatChecker: noopFormatChecker`, which always returns `true` regardless of the value: [1](#0-0) 

By contrast, `Kip71BaseFeeDenominator` explicitly rejects zero: [2](#0-1) 

Consistency checks in `checkConsistency` do not add any additional validation for `Kip71GasTarget` either — it falls into the catch-all "no more checks" case: [3](#0-2) 

`NextMagmaBlockBaseFee` in `params/kip71_config.go` defensively guards against `BaseFeeDenominator == 0` but performs no such guard for `GasTarget`, dividing by it directly: [4](#0-3) 

Specifically, at line 102 (`y := x.Div(x, new(big.Int).SetUint64(gasTarget))`), if `gasTarget == 0` and `parentGasUsed > 0` (the common case, since `parentGasUsed > gasTarget` triggers this branch when `gasTarget == 0`), `big.Int.Div` will panic with a division-by-zero runtime error.

Regarding reachability, governance votes are cast via `header.Vote`, requiring the voter to be a council member and the current block's proposer: [5](#0-4) 

Critically, ratification into `header.Governance` at the next epoch boundary does not require a supermajority of votes — `getExpectedGovernance` simply aggregates the last vote seen per parameter name across the previous epoch, meaning **a single validator acting as proposer for one block** can inject a `kip71.gastarget = 0` vote that becomes the canonical governance value for all subsequent blocks, with no per-parameter bound enforced.

### Impact Explanation
Once `GasTarget = 0` is ratified, every full node (validators and endpoint nodes alike) that computes `NextMagmaBlockBaseFee` for a block with nonzero gas usage will panic deterministically, since this computation happens both during header preparation (block production) and header verification (`VerifyMagmaHeader`) on all nodes. This causes a network-wide, unrecoverable chain halt — the highest-impact consequence explicitly called out in the report ("halted operations"). This is a concrete state-machine crash reachable via the standard, permissionless (non-privileged in the p2p/consensus sense) governance-vote mechanism available to any validator with proposer turn, not a p2p/consensus-message-level attack.

### Likelihood Explanation
Likelihood is elevated because: (1) no majority/quorum is required to ratify the vote — a single vote from one validator during an epoch suffices; (2) the value `0` passes both the `Canonicalizer` and `FormatChecker` without any error; (3) the resulting panic occurs deterministically on every node the moment a block with non-target-matching gas usage is processed after ratification, which is virtually certain to occur immediately given genesis/default gas usage patterns.

### Recommendation
Add a `FormatChecker` for `Kip71GasTarget` (and `Kip71MaxBlockGasUsedForBaseFee`) that rejects `0`, consistent with the treatment already applied to `Kip71BaseFeeDenominator`:
```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0
    },
    ...
}
```
Additionally, as defense-in-depth, `NextMagmaBlockBaseFee` in `params/kip71_config.go` should guard against `gasTarget == 0` the same way it already guards against `baseFeeDenominator == 0`, to prevent a panic even if an invalid value slips through via chain config or future code paths.

### Proof of Concept
1. A validator that is due to propose a block within the current epoch casts a governance vote `{name: "kip71.gastarget", value: uint64(0)}` via `governance_vote`, embedded into `header.Vote` per `PrepareHeader`.
2. `VerifyVote` accepts the vote since the voter is a council member and the block's proposer, and `checkConsistency` performs no bound check for this parameter name (falls into the no-op case).
3. At the next epoch boundary, `getExpectedGovernance` aggregates this vote (last-writer-wins, no quorum needed) into `header.Governance`, ratifying `GasTarget = 0` chain-wide.
4. On the next block where `parentHeaderGasUsed != 0`, every node calling `NextMagmaBlockBaseFee` (during block production and header verification) executes `y := x.Div(x, new(big.Int).SetUint64(0))`, which panics, crashing all nodes computing the base fee — halting the chain.

func (h *headerGovModule) VerifyVote(header *types.Header) error {
	if len(header.Vote) == 0 {
		return nil
	}

	var (
		vb       headergov.VoteBytes = header.Vote
		blockNum                     = header.Number.Uint64()
	)

	vote, err := vb.ToVoteData()
	if err != nil {
		logger.Error("ToVoteData error", "num", blockNum, "vote", vb, "err", err)
		return err
	}

	if gov.DeprecatedAt(vote.Name(), h.ChainConfig.Rules(header.Number)) {
		logger.Error("Vote is deprecated", "num", blockNum, "name", vote.Name())
		return ErrDeprecatedVote
	}

	council, err := h.ValSet.GetCouncil(blockNum)
	if err != nil {
		return err
	}

	// check if the voter is in council
	if !slices.Contains(council, vote.Voter()) {
		return ErrInvalidKeyValue
	}

	// check if Voter is the block proposer.
	author, err := h.Chain.Sealer().Author(header)
	if err != nil {
		return err
	}
	if author != vote.Voter() {
		return ErrInvalidVoter
	}

	// In single mode, only the governing node can write header.Vote after Permissionless.
	params := h.GetParamSet(blockNum)
	if h.ChainConfig.IsPermissionlessForkEnabled(new(big.Int).SetUint64(blockNum)) &&
		params.GovernanceMode == "single" &&
		vote.Voter() != params.GoverningNode {
		return ErrVotePermissionDenied
	}

	return h.checkConsistency(blockNum, vote)
