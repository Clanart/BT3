### Title
Identity public key enables universal Schnorr signature forgery - (File: crypto/schnorr/src/lib.rs)

### Summary
`SchnorrSignature::verify` does not reject the identity public key or identity nonce commitment, allowing `(A = identity, R = identity, s = 0)` to satisfy the verification equation for every challenge and message. [1](#0-0) 

### Finding Description
`SchnorrSignature::read` deserializes `R` through `C::read_G` and `s` through `C::read_F`, without enforcing that either decoded value is non-identity. [2](#0-1)  Verification checks `R + cA - sG = 0`; substituting `R = 0`, `A = 0`, and `s = 0` makes every term identity regardless of `c`. [1](#0-0)  Serai recognizes this distinction in the FROST-specific `Curve::read_G`, which explicitly rejects an identity returned by generic `C::read_G`, but the standalone Schnorr API does not apply that additional check. [3](#0-2) 

### Impact Explanation
An attacker who can supply an untrusted public key and signature can authenticate as the identity key without knowing a private key. [1](#0-0)  The forged signature is independent of the challenge, so normal Fiat–Shamir challenge binding cannot prevent the bypass. [4](#0-3) 

### Likelihood Explanation
The attack is reachable wherever attacker-controlled bytes are decoded into a public key with `C::read_G`, a signature with `SchnorrSignature::read`, and then passed to `verify`. [2](#0-1)  FROST is not affected through its own parsing path because `Curve::read_G` explicitly rejects identity after the generic ciphersuite decode. [3](#0-2) 

### Recommendation
Reject the identity point for Schnorr public keys before calling `verify`, or enforce non-identity inside `verify`. [4](#0-3)  Also reject identity `R` values during signature verification unless a specific protocol intentionally permits zero nonces. [5](#0-4) 

### Proof of Concept
```rust
// crypto/schnorr/src/lib.rs
let public_key = C::G::identity();
let forged = SchnorrSignature::<C> {
    R: C::G::identity(),
    s: C::F::ZERO,
};

assert!(forged.verify(public_key, arbitrary_challenge));
```

The verification terms become `identity + c·identity - 0·G = identity` for every `arbitrary_challenge`. [1](#0-0)

  /// Return the series of pairs whose products sum to zero for a valid signature.
  /// This is intended to be used with a multiexp.
  pub fn batch_statements(&self, public_key: C::G, challenge: C::F) -> [(C::F, C::G); 3] {
    // s = r + ca
    // sG == R + cA
    // R + cA - sG == 0
    [
      // R
      (C::F::ONE, self.R),
      // cA
      (challenge, public_key),
      // -sG
      (-self.s, C::generator()),
    ]
  }

  /// Verify a Schnorr signature for the given key with the specified challenge.
  ///
  /// This challenge must be properly crafted, which means being binding to the public key, nonce,
  /// and any message. Failure to do so will let a malicious adversary to forge signatures for
  /// different keys/messages.
  #[must_use]
  pub fn verify(&self, public_key: C::G, challenge: C::F) -> bool {
    multiexp_vartime(&self.batch_statements(public_key, challenge)).is_identity().into()
  }
