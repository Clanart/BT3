### Title
Coinbase outputs are reported as immediately spendable - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_block` scans every transaction in `block.txdata`, including the coinbase transaction at index `0`. Any coinbase output paying to a registered Taproot script is returned as a `ReceivedOutput`, even though Bitcoin consensus makes coinbase outputs unspendable for 100 confirmations.

### Finding Description
`ReceivedOutput` is documented as "A spendable output" in `networks/bitcoin/src/wallet/mod.rs`. However, `scan_block` iterates over `&block.txdata` without excluding `txdata[0]`, and `scan_transaction` creates a `ReceivedOutput` solely from the transaction ID, output index, output value, and registered key offset.

The resulting value contains no block height or maturity metadata, so downstream wallet code cannot distinguish an immature coinbase output from a normally spendable output. `SignableTransaction::new` in `networks/bitcoin/src/wallet/send.rs` accepts `ReceivedOutput` values directly and builds a transaction spending their outpoints. A transaction spending an immature coinbase output will be rejected by Bitcoin consensus.

### Impact Explanation
An attacker-controlled or otherwise malformed block can cause the wallet to report funds as spendable when they are not. Wallet accounting can then select the immature output as an input and produce a transaction that cannot be accepted by the network. This can interrupt wallet operation and cause unavailable funds to be treated as usable balance.

### Likelihood Explanation
The condition is deterministic whenever a scanned block's coinbase transaction pays to a tracked script. Exploitation requires a coinbase transaction paying to the wallet's script, which generally requires the sender to produce a valid block or cause the wallet to scan an untrusted block containing one. Once present, no additional race or cryptographic condition is required.

### Recommendation
Exclude `block.txdata[0]` from `Scanner::scan_block`, or track block height/maturity in `ReceivedOutput` and prevent immature coinbase outputs from being passed to transaction construction. At minimum, `scan_block` should return maturity information so callers can enforce the 100-block coinbase maturity rule before treating the output as spendable.

### Proof of Concept
Conceptually:

```rust
let mut scanner = Scanner::new(wallet_key).unwrap();

let block = Block {
    header,
    txdata: vec![
        coinbase_transaction_paying_to_scanner_script,
    ],
};

let received = scanner.scan_block(&block);
assert_eq!(received.len(), 1);

let signable = SignableTransaction::new(
    received,
    &[(payment_script, payment_amount)],
    None,
    None,
    fee_per_vbyte,
).unwrap();
```

The coinbase output is returned by `scan_block`, but any transaction spending it before maturity violates Bitcoin consensus rules and will be rejected.
