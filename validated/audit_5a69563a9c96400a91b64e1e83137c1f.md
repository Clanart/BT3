### Title
ReceivedOutput deserialization trusts an attacker-supplied offset without binding it to the output's script_pubkey, allowing arbitrary UTXOs to be recorded as spendable funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary

The rendertron LFI bug class — using untrusted input to select which resource is read and treated as legitimate — maps onto `ReceivedOutput::read`, which parses a `Scalar` offset, a `TxOut`, and an `OutPoint` entirely from attacker bytes and returns them as a spendable output with no consistency check between the offset and the output.

### Finding Description

`Scanner::scan_transaction` constructs `ReceivedOutput` values where the `offset` field is cryptographically bound to `output.script_pubkey`: the script is looked up in `self.scripts`, a map built by `register_offset`/`Scanner::new` that only contains Taproot scripts derived as `key + offset*G` (plus the BIP-341 unspendable-script tweak) [1](#0-0) [2](#0-1) . That binding is what makes the output later spendable: spending code re-keys the threshold keys by `offset`, which only produces the correct key if the script genuinely commits to `key + offset*G`.

`ReceivedOutput::read` discards this invariant entirely. It accepts any canonical scalar for `offset`, any `TxOut`, and any `OutPoint`, and constructs a `ReceivedOutput` that downstream code treats identically to a scanner-produced one [3](#0-2) . There is no check that `p2tr_script_buf(key + offset*G) == output.script_pubkey`, and no check that the referenced outpoint exists or pays to the multisig.

This is the LFI pattern: the attacker controls the "path" (offset + outpoint + TxOut bytes) and causes the system to "include" a resource (a received output) that was never legitimately derived, bypassing the derivation check that `Scanner` performs.

### Impact Explanation

An unprivileged party feeding crafted bytes to `ReceivedOutput::read` can register phantom deposits: a `ReceivedOutput` naming any on-chain outpoint (including outputs paying to the attacker's own keys, or nonexistent outpoints) together with any offset is accepted as a spendable received output. Consequences:

- Funds reported received that are not spendable: the recorded `offset` does not derive the key for the output's script_pubkey, so when the output is selected as a plan input and signed for (per-input commitment re-keying in `send.rs`), the resulting transaction is invalid — the input's script requires a key the multisig cannot produce with that offset.
- Denial of service / fund freezing: a plan incorporating such an input will produce a transaction that fails Bitcoin consensus/script validation, stalling the signing pipeline and potentially pinning honest inputs in an unbroadcastable plan.
- Balance inflation: arbitrarily large `TxOut.value` amounts can be claimed, since the deserialized `TxOut` is never checked against the real chain output.

### Likelihood Explanation

Reachability requires the deployment path where `ReceivedOutput` values are deserialized from data influenced by an untrusted party (the prompt's reachability model includes untrusted bytes fed to `ReceivedOutput::read`). The cryptographic check itself is trivially defeated — no hash grinding or key knowledge is needed; the attacker simply serializes any `Scalar`, any `TxOut`, and any `OutPoint`. Impact on consensus-validity of downstream signing is deterministic once the phantom output is used. Rated Medium: it corrupts wallet state and can freeze spending flows, but does not directly leak key material or forge signatures.

### Recommendation

Bind the offset to the output during deserialization or before the output is admitted into the spendable set: recompute `p2tr_script_buf(scanner_key + G * offset)` and reject the `ReceivedOutput` if it does not equal `output.script_pubkey`. Additionally, verify the claimed `outpoint` resolves on-chain to a matching `TxOut` before crediting the output, rather than trusting the serialized `TxOut`/`OutPoint` pair.

### Proof of Concept

```rust
use bitcoin::{OutPoint, TxOut, ScriptBuf, Amount, Txid, hashes::Hash};
use k256::Scalar;
use bitcoin_serai::wallet::ReceivedOutput;
use frost::curve::{Ciphersuite, Secp256k1};

// Attacker bytes: arbitrary offset + an output paying to THEIR OWN key
// (or any script), with an arbitrary outpoint and inflated value.
let mut buf = vec![];
buf.extend(Scalar::ONE.to_bytes()); // offset = 1, not derived for the script

let attacker_output = TxOut {
  value: Amount::from_sat(21_000_000_0000_0000), // inflated claim
  script_pubkey: ScriptBuf::new_p2tr_tweaked(
    // some script the attacker controls / unrelated to key + 1*G
    bitcoin::key::TweakedPublicKey::dangerous_assume_tweaked(
      bitcoin::key::XOnlyPublicKey::from_slice(&[2u8; 32]).unwrap()
    )
  ),
};
buf.extend(bitcoin::consensus::encode::serialize(&attacker_output));
buf.extend(bitcoin::consensus::encode::serialize(
  &OutPoint::new(Txid::all_zeros(), 0)
));

// Accepted unconditionally: no check that offset derives the script_pubkey
let output = ReceivedOutput::read(&mut buf.as_slice()).unwrap();
assert_eq!(output.value(), attacker_output.value.to_sat());
// Downstream, this is treated as a spendable multisig input, yet
// re-keying by `offset` cannot produce the key the script requires.
```

  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
