### Title
Withdrawal of healthy, unrelated collateral is blocked by an unrelated asset's price-feed failure due to fold-abort in `price-multi-resolve` - (File: mainnet/contracts/market/v0-4-market.clar)

### Summary
`price-multi-resolve`/`iter-price-multi` (lines 397-418) fold over every asset id present in a position's collateral (and debt) mask and, on any single `price-resolve` failure (line 413, via `unwrap!`), sets `valid: false` for the whole batch, causing `price-multi-resolve` to abort the entire call with `ERR-ORACLE-MULTI` (line 402). Any market action that needs a fresh health computation — including withdrawing an unrelated, fully healthy asset — invokes this batched pricer over the full position mask, so a single stale/failing feed (e.g. stSTX ratio callcode) blocks withdrawal of unrelated collateral (e.g. USDC) that never needed that feed to prove its own health.

### Finding Description
`price-resolve` (lines 373-395) resolves a single asset's price, applies `resolve-callcode` (lines 349-358) for wrapped/ratio assets like stSTX, and asserts freshness/legality; any failure at any of these micro-steps (`resolve-price-feed`, `resolve-callcode`, staleness check) returns an error rather than a price. `iter-price-multi` (lines 405-418) `unwrap!`s that per-asset result: on failure it flips the shared accumulator's `valid` flag to `false` for the *entire fold*, and `price-multi-resolve` (lines 397-403) turns that into a global `asserts! (get valid response) ERR-ORACLE-MULTI`. There is no per-asset partial success path and no mechanism to exclude the failing asset from the computation and still process the assets that do have valid prices. Because the mask passed into this pricer is derived from the position's full collateral bitmap (all assets the user holds, not just the one being withdrawn), a user holding stSTX + USDC + sBTC who wants to withdraw only USDC still causes the pricer to attempt resolving stSTX's price/ratio as part of computing/validating the position mask, and a failure there aborts the whole call, blocking the USDC withdrawal even though the USDC portion is independently healthy and uninvolved with the failing feed.

### Impact Explanation
Direction: no assets are mispriced; the effect is a denial-of-service on withdrawal action for otherwise-healthy, uninvolved collateral, caused solely by this contract's all-or-nothing fold-abort design over the fetched price list. The affected user cannot access unrelated, healthy funds until the failing feed (stSTX ratio callcode / staleness) recovers, which fits "temporary freezing of funds" (High) rather than a mispricing/theft scenario.

### Likelihood Explanation
Likelihood depends only on an ordinary oracle feed transiently failing or going stale for one collateral type (e.g., stSTX ratio source unavailable, DIA/Pyth staleness threshold exceeded) while the user simultaneously holds that asset alongside other, healthy collateral. This requires no attacker action, capital, or privileged access — it is a naturally occurring operational condition (any oracle hiccup) that any regular user holding a diversified collateral position can be affected by, and it is fully repeatable every time any single feed used in the position's mask fails or goes stale.

### Recommendation
Change `price-multi-resolve`/`iter-price-multi` to compute health using only the prices needed for the specific action (e.g., only the asset(s) involved in the withdrawal, or only assets with non-zero debt) rather than pricing the entire mask; alternatively, allow partial success by excluding a failing asset's contribution to the health computation when computing whether the remaining collateral/debt is unaffected, or expose a per-asset withdraw path that does not require repricing the whole position mask when there is no debt or when the withdrawn asset's price is independently sufficient to prove health.

### Proof of Concept
Clarinet simnet test: 1) fund a test principal, deposit a small stSTX collateral amount and a large USDC collateral amount, no borrow/debt. 2) Mock/force the stSTX ratio callcode read (`call-ststx-ratio` / `resolve-ststx`) to fail or return a stale timestamp so `oracle-timestamp-fresh` fails. 3) Call the market's withdraw entrypoint for the USDC amount. 4) Assert the call reverts with `ERR-ORACLE-MULTI` even though the USDC-only sub-position, when priced in isolation, is fully healthy (no debt, ample collateral) — demonstrating the fold-abort in `price-multi-resolve`/`iter-price-multi` (lines 397-418) freezes access to unrelated healthy funds.
