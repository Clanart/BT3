### Title
Tokenfactory admin can arbitrarily change a denom's decimals/exponent via `MsgSetDenomMetadata` after ERC20/CW20 pointer creation, causing frozen-decimals mismatch and value mispricing - (File: `x/tokenfactory/keeper/msg_server.go`)

### Summary
The tokenfactory denom's own admin (any permissionless account, since denom creators are auto-admin) can call `MsgSetDenomMetadata` at any time to rewrite the denom's `Metadata`, including its `DenomUnits`/exponent (i.e., effective "decimals"), with no check against the previously stored metadata. Meanwhile, the EVM native ERC20 pointer for that denom bakes the decimals value it read *at pointer-creation time* into an immutable contract field, and the raw balance amounts stored in the bank module never change. This is the same bug class as the ERC20Rewards `setRewards` finding: a value/decimals-defining parameter can be changed for an already-circulating asset while dependents (holders, pointer contracts, and any protocol reading token decimals) continue to interpret existing raw balances under the old assumption, producing value distortions of many orders of magnitude.

### Finding Description
`MsgSetDenomMetadata` is handled by `SetDenomMetadata` in `x/tokenfactory/keeper/msg_server.go`: [1](#0-0) 

The only checks performed are:
1. `msg.Metadata.Validate()` — internal self-consistency of the *new* metadata (name/symbol not blank, base/display denoms valid, sorted denom units, etc.) via `sei-cosmos/x/bank/types/metadata.go`: [2](#0-1) 
2. `authorityMetadata, err := server.GetAuthorityMetadata(ctx, msg.Metadata.Base)` and a comparison of `msg.Sender` to the stored admin for that base denom, via `GetAuthorityMetadata`, which is keyed solely by the denom string: [3](#0-2) 

Neither check compares the new `DenomUnits`/exponent (decimals) against the metadata that was set when the denom was created (`createDenomAfterValidation`, which starts every tokenfactory denom with a single base unit at exponent 0): [4](#0-3) 

`ValidateBasic` on the message likewise only calls `Metadata.Validate()` and `DeconstructDenom`, with no cross-check against the currently-stored metadata: [5](#0-4) 

This metadata is exactly what the EVM native pointer precompile reads **once**, at pointer-creation time, to fix the pointer contract's `decimals()`: [6](#0-5) 

The deployed Solidity pointer (`NativeSeiTokensERC20`) stores this value in an immutable field set only in the constructor and never re-synced with bank metadata: [7](#0-6) 

Balances are always the raw base-denom amount fetched live via the bank precompile (`BankPrecompile.balance`/`send`), so no rescaling of stored amounts ever occurs when metadata changes: [8](#0-7) 

Because the same raw amount is reinterpreted under a different `decimals()` by anything that treats decimals as immutable (the already-deployed ERC20 pointer, EVM contracts that cached it, or third-party integrations that read decimals once and assume it is fixed), the numeric "human" value of `1 unit` silently changes — precisely analogous to the reported bug where `ERC20Rewards.setRewards` let a new token with different decimals be substituted while stale reward accounting persisted.

### Impact Explanation
Any EVM contract that reads `decimals()` from the native-token ERC20 pointer once (e.g., to normalize amounts for pricing, AMM reserves, or collateral valuation) and later has the underlying tokenfactory denom's metadata changed by its admin will misinterpret the same raw balance by up to `10^|Δdecimals|`. This can be leveraged to manipulate AMM pool pricing, over/under-collateralize lending positions, or otherwise extract value from any protocol built on top of the assumption that a tokenfactory denom's decimals are fixed once a pointer/integration is created — a direct analog of the "1e18 DAI redeemed as 1e18 USDC" fund-loss scenario in the original report. Because the tokenfactory admin is a normal, permissionless, self-appointed role (the denom creator), this is reachable without any privileged/validator/governance action.

### Likelihood Explanation
High reachability: any account can call `tokenfactory create-denom`, become admin of that denom, get a native pointer created against it (permissionlessly, via the `AddNative`/`RegisterPointer` precompile path), have other users/contracts integrate against the pointer, and then call `MsgSetDenomMetadata` to change the `DenomUnits` exponent. No governance, validator, or operator privilege is required — only being the denom's own admin, which is attainable by any transaction sender.

### Recommendation
- In `SetDenomMetadata` (`x/tokenfactory/keeper/msg_server.go`), reject metadata updates that change the base denomination's decimal exponent (or more conservatively, disallow any change to `DenomUnits`/exponents entirely) once a denom has been created; only allow updates to display-only fields (name, symbol, aliases) that do not affect value interpretation.
- Alternatively, if decimal changes must be supported, require that any dependent ERC20/CW20 pointer be force re-derived (or invalidated) atomically with the metadata change, and document/enforce that all downstream integrations must not cache `decimals()`.

### Proof of Concept
1. Attacker calls `MsgCreateDenom` to create `factory/{attacker}/foo` with default metadata (exponent 0 base unit) — attacker becomes admin (`x/tokenfactory/keeper/createdenom.go`).
2. Attacker sets a normal-looking `MsgSetDenomMetadata` with `denom_units` giving `foo` an effective decimals of 6 and mints/distributes tokens.
3. Attacker (or a third party) registers a native EVM pointer for the denom via the pointer/registration precompile; `AddNative` reads current metadata and bakes `decimals = 6` into the deployed `NativeSeiTokensERC20` contract (`precompiles/pointer/legacy/v605/pointer.go:106-127`).
4. Third-party DeFi contracts integrate with the pointer, caching or reading `decimals() == 6` to compute prices/collateral ratios, and users deposit/trade based on that assumption.
5. Attacker (still the denom admin) calls `MsgSetDenomMetadata` again, changing `denom_units` to represent `foo` with 0 decimals (or 18) — `SetDenomMetadata` accepts this since it only validates internal consistency and admin identity, not consistency with prior metadata (`x/tokenfactory/keeper/msg_server.go:188-206`).
6. Raw balances in the bank module are unchanged, but any new reader of bank metadata (or a redeployed pointer) now interprets the same raw amount as 10^12 (or 10^-12) times more/less valuable than the already-deployed pointer contract used by integrated dApps, enabling mispriced trades/collateral extraction against those dApps.

func (m Metadata) Validate() error {
	if strings.TrimSpace(m.Name) == "" {
		return errors.New("name field cannot be blank")
	}

	if strings.TrimSpace(m.Symbol) == "" {
		return errors.New("symbol field cannot be blank")
	}

	if err := sdk.ValidateDenom(m.Base); err != nil {
		return fmt.Errorf("invalid metadata base denom: %w", err)
	}

	if err := sdk.ValidateDenom(m.Display); err != nil {
		return fmt.Errorf("invalid metadata display denom: %w", err)
	}

	var (
		hasDisplay      bool
		currentExponent uint32 // check that the exponents are increasing
	)

	seenUnits := make(map[string]bool)

	for i, denomUnit := range m.DenomUnits {
		// The first denomination unit MUST be the base
		if i == 0 {
			// validate denomination and exponent
			if denomUnit.Denom != m.Base {
				return fmt.Errorf("metadata's first denomination unit must be the one with base denom '%s'", m.Base)
			}
			if denomUnit.Exponent != 0 {
				return fmt.Errorf("the exponent for base denomination unit %s must be 0", m.Base)
			}
		} else if currentExponent >= denomUnit.Exponent {
			return errors.New("denom units should be sorted asc by exponent")
		}

		currentExponent = denomUnit.Exponent

		if seenUnits[denomUnit.Denom] {
			return fmt.Errorf("duplicate denomination unit %s", denomUnit.Denom)
		}

		if denomUnit.Denom == m.Display {
			hasDisplay = true
		}

		if err := denomUnit.Validate(); err != nil {
			return err
		}

		seenUnits[denomUnit.Denom] = true
	}

	if !hasDisplay {
		return fmt.Errorf("metadata must contain a denomination unit with display denom '%s'", m.Display)
	}

	return nil

func (k Keeper) GetAuthorityMetadata(ctx sdk.Context, denom string) (types.DenomAuthorityMetadata, error) {
	bz := k.GetDenomPrefixStore(ctx, denom).Get([]byte(types.DenomAuthorityMetadataKey))

	metadata := types.DenomAuthorityMetadata{}

	if err != nil {
		return types.DenomAuthorityMetadata{}, err
	}
	return metadata, nil

    constructor(string memory denom_, string memory name_, string memory symbol_, uint8 decimals_) ERC20("", "") {

    }

        return ddecimals;
    }

    function totalSupply() public view override returns (uint256) {
        return BankPrecompile.supply(denom);
