### Title
Unbounded `io.ReadAll(r.Body)` in NewRelic/Datadog RPC HTTP wrappers bypasses `MaxRequestContentLength` and allows memory-exhaustion DoS of the public JSON-RPC endpoint - ([File: networks/rpc/http_newrelic.go])

### Summary
`StartHTTPEndpoint` starts the public JSON-RPC HTTP server via `NewHTTPServer`, which optionally wraps the handler chain with `newNewRelicHTTPHandler` and `newDatadogHTTPHandler` when the corresponding APM env vars are configured (a common production setup, e.g. for KAS-integrated nodes given the `parseKASHeader`/`x-chain-id` handling in the same file) [1](#0-0) [2](#0-1) . These outer wrappers call `getRPCRequests(r)`, which reads the entire HTTP request body into memory with `io.ReadAll(r.Body)` before the inner `Server.ServeHTTP`/`validateRequest` content-length/size check ever runs [3](#0-2) .

### Finding Description
In the normal (non-instrumented) code path, `Server.ServeHTTP` enforces `MaxRequestContentLength` via `validateRequest` and further limits the body reader with `io.LimitReader` in `newHTTPServerConn` [4](#0-3) [5](#0-4) .

However, when NewRelic (`NEWRELIC_APP_NAME`/`NEWRELIC_LICENSE`) or Datadog tracing is enabled, `NewHTTPServer` wraps the handler chain so that `newNewRelicHTTPHandler`/`newDatadogHTTPHandler` execute *before* the inner `Server.ServeHTTP` and its size checks:
```
handler := newCorsHandler(srv, cors)
handler = newVHostHandler(vhosts, handler)
handler = http.TimeoutHandler(handler, timeouts.ExecutionTimeout, "timeout")
if nrApp != nil { handler = newNewRelicHTTPHandler(nrApp, handler) }
if ddTracer != nil { handler = newDatadogHTTPHandler(ddTracer, handler) }
``` [2](#0-1) 

Both `newNewRelicHTTPHandler` and `newDatadogHTTPHandler` call `getRPCRequests(r)` at the very start of the request, purely to extract the RPC method name for tracing/logging purposes:
```go
func getRPCRequests(r *http.Request) ([]*jsonrpcMessage, bool, error) {
	reqBody, err := io.ReadAll(r.Body)
	...
}
``` [6](#0-5) 

This `io.ReadAll` has no size cap, and it runs on the outermost layer of the handler chain — *before* the `http.Server` created by `NewHTTPServer` reaches the inner `Server.ServeHTTP`'s `validateRequest`/`io.LimitReader` protections [4](#0-3) . The underlying `http.Server` itself sets no `MaxHeaderBytes`/body-size limit for this listener [7](#0-6) , so an attacker can stream an arbitrarily large POST body (e.g., via chunked transfer-encoding with no `Content-Length` header, or any oversized body) directly to the public JSON-RPC port, causing the process to buffer the entire payload in memory. This is precisely the bug class described in the reported advisory (deprecated/unbounded `ReadAll` usage on public HTTP handlers causing OOM DoS), reproduced here in Kaia's RPC HTTP tracing wrappers.

### Impact Explanation
Any unauthenticated public RPC caller reaching the JSON-RPC HTTP endpoint of a Kaia node that has NewRelic or Datadog tracing enabled (a realistic production configuration, given the KAS-specific header parsing present in the same file) can send a single, arbitrarily large HTTP POST request and force the node to allocate memory proportional to the attacker-controlled body size, with no cap. Repeated or large-enough requests can exhaust available memory and crash the node process, denying service to all RPC clients — matching CWE-400/CWE-787 resource exhaustion impact (Availability: High) as in the referenced advisory.

### Likelihood Explanation
The vulnerable code path is reached only when a node operator enables NewRelic or Datadog tracing via environment variables (`NEWRELIC_APP_NAME`/`NEWRELIC_LICENSE`, or Datadog equivalents) — this is a common production/observability setup rather than a default, but once enabled, the vulnerable path is unconditionally triggered on every incoming HTTP RPC request without any authentication or special privilege, so exploitation is trivial for any external caller.

### Recommendation
Wrap `r.Body` with `http.MaxBytesReader(w, r.Body, common.MaxRequestContentLength)` (or apply the same `io.LimitReader`/content-length validation used in `validateRequest`) before calling `io.ReadAll` inside `getRPCRequests` in `networks/rpc/http_newrelic.go`, or move the content-length/size validation to the outermost handler in the chain so it executes before the NewRelic/Datadog wrappers read the body. Restore the original (unconsumed) body via `io.NopCloser` only after enforcing the size bound.

### Proof of Concept
1. Start a Kaia node with `NEWRELIC_APP_NAME`/`NEWRELIC_LICENSE` (or Datadog tracer) environment variables set, exposing the HTTP JSON-RPC endpoint via `StartHTTPEndpoint`.
2. Send an HTTP POST request to the RPC endpoint with a body far larger than `common.MaxRequestContentLength` (or using `Transfer-Encoding: chunked` with an extremely large streamed body and no `Content-Length`).
3. Observe that `getRPCRequests` in `networks/rpc/http_newrelic.go` calls `io.ReadAll(r.Body)` unconditionally, buffering the full payload in memory before the inner `Server.ServeHTTP`'s `validateRequest` size check ever executes, leading to excessive memory consumption and potential OOM crash of the node.

func NewHTTPServer(cors []string, vhosts []string, timeouts HTTPTimeouts, srv http.Handler) *http.Server {
	timeouts = sanitizeTimeouts(timeouts)
	// Wrap the CORS-handler within a host-handler
	handler := newCorsHandler(srv, cors)
	handler = newVHostHandler(vhosts, handler)
	handler = http.TimeoutHandler(handler, timeouts.ExecutionTimeout, "timeout")

	// If os environment variables for NewRelic exist, register the NewRelicHTTPHandler
	nrApp := newNewRelicApp()
	if nrApp != nil {
		handler = newNewRelicHTTPHandler(nrApp, handler)
	}

	// If os environment variables for Datadog exist, register the NewDatadogHTTPHandler
	ddTracer := newDatadogTracer()
	if ddTracer != nil {
		handler = newDatadogHTTPHandler(ddTracer, handler)
	}

	return &http.Server{
		Handler:      handler,
		ReadTimeout:  timeouts.ReadTimeout,
		WriteTimeout: timeouts.WriteTimeout,
		IdleTimeout:  timeouts.IdleTimeout,
	}
}

```go
func getRPCRequests(r *http.Request) ([]*jsonrpcMessage, bool, error) {
	reqBody, err := io.ReadAll(r.Body)
	if err != nil {
		logger.Error("cannot read a request body", "err", err)
		return nil, false, err
	}

	r.Body = io.NopCloser(bytes.NewReader(reqBody))
	conn := &httpServerConn{Reader: io.NopCloser(bytes.NewReader(reqBody)), Writer: bytes.NewBufferString(""), r: r}

	codec := NewCodec(conn)

	defer codec.close()

	return codec.readBatch()
}
