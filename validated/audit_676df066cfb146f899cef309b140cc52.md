### Title
Unbounded recursive RLP decoding of nested `AccountKeyRoleBased` causes stack-consumption DoS on raw transaction submission - ([File: blockchain/types/accountkey/account_key_role_based.go])

### Summary
`AccountKeyRoleBased.DecodeRLP` recursively invokes `rlp.DecodeBytes` on each sub-key entry, and that recursion is fully attacker-controlled by RLP nesting depth, with no depth limit enforced during decoding. An unprivileged sender can submit a crafted `TxTypeAccountUpdate` transaction (or the equivalent `AccountKeySerializer` payload) via the public `SendRawTransaction`/`SendRawTransactions` RPC, causing the node to recurse thousands of levels deep while merely parsing the transaction, before any semantic "nested composite type" validation ever runs. This mirrors the CVE-2017-11626 bug class: a recursive parser function (`QPDFTokenizer::resolveLiteral` / `QPDFObjectHandle::parseInternal`) consuming the call stack on crafted nested input, causing denial of service.

### Finding Description
`AccountKeyRoleBased` is RLP-encoded as a `[][]byte`, where each inner byte slice is itself a fully independent RLP-encoded `AccountKeySerializer` blob: [1](#0-0) 

Decoding proceeds by calling `rlp.DecodeBytes` on each inner blob, which invokes `AccountKeySerializer.DecodeRLP`: [2](#0-1) 

If the decoded `keyType` for that inner blob is again `AccountKeyTypeRoleBased`, `NewAccountKey` constructs another `AccountKeyRoleBased`, and `s.Decode(serializer.key)` re-enters `AccountKeyRoleBased.DecodeRLP`, repeating the cycle. Nothing in this call chain — nor in the underlying `rlp` package's stream/struct decoder — tracks or limits nesting depth: [3](#0-2) 

The intended guard against nested role-based keys, `ErrNestedCompositeType`, is enforced only *after* decoding, at transaction-pool admission and block-validation time — not inside `DecodeRLP` itself: [4](#0-3) 

This means the recursive decode of an attacker-crafted, deeply nested `AccountKeyRoleBased` payload fully executes (consuming one or more Go stack frames per nesting level across `AccountKeySerializer.DecodeRLP` → `AccountKeyRoleBased.DecodeRLP` → `rlp.DecodeBytes` → …) before the node has any chance to reject it as invalid.

The reachable entry point is the standard raw-transaction submission path used by any unprivileged sender: [5](#0-4) [6](#0-5) 
which for a `TxTypeAccountUpdate` transaction dispatches into `TxInternalDataAccountUpdate.DecodeRLP`, decoding an embedded `AccountKeySerializer`/`AccountKeyRoleBased` field: [7](#0-6) 

### Impact Explanation
A crafted transaction with a sufficiently deep chain of nested `AccountKeyRoleBased` keys can drive the decoding call stack far beyond normal bounds, crashing the goroutine (and, depending on Go runtime behavior for stack-overflow panics in the RPC/tx-pool goroutine, potentially the whole node process) purely from parsing untrusted, unsigned-at-parse-time input. Because this is triggered at the RLP-decode stage — before signature verification or semantic validation — every node that receives and decodes the raw transaction (via RPC submission, transaction propagation, or block re-execution) is affected, giving an unprivileged actor a low-cost, repeatable denial-of-service primitive against public RPC endpoints and, if the transaction propagates, against the broader network's honest nodes.

### Likelihood Explanation
Likelihood is high: constructing nested `AccountKeyRoleBased` structures is programmatically trivial (just wrap `AccountKeySerializer` blobs recursively), requires no special privileges, and the `SendRawTransaction`/`SendRawTransactions` RPC methods are exposed to any public caller. No signature validity is required to trigger the parsing path, since `DecodeRLP` runs before signature checks in `Transaction.DecodeRLP`/`SanityCheckSignatures`.

### Recommendation
Enforce a maximum recursion/nesting depth check inside `AccountKeyRoleBased.DecodeRLP` (and generally in `AccountKeySerializer.DecodeRLP`) before recursing into nested key material, rejecting any `AccountKeyTypeRoleBased` found nested inside another role-based key at decode time rather than deferring the `ErrNestedCompositeType` check to post-decode validation. Additionally, consider adding a general recursion-depth guard to `rlp.Stream` decoding paths that can recurse based on attacker-supplied type tags (e.g., a `Decoder`-implementing type instantiating another instance of itself), so a single malformed value cannot cause unbounded stack growth regardless of which composite type is involved.

### Proof of Concept
1. Construct an `AccountKeySerializer`-encoded blob of `AccountKeyTypeFail` (or `AccountKeyTypeNil`) as the innermost leaf key.
2. Wrap it in an `AccountKeyRoleBased` (`[][]byte{leafBlob}`), RLP-encode via `AccountKeySerializer.EncodeRLP`.
3. Repeat step 2, wrapping the previous encoded blob as the sole entry of a new `AccountKeyRoleBased`, for N iterations (e.g., N = 100,000+), producing a deeply nested serialized key.
4. Embed the resulting key bytes as the `Key` field of a `TxTypeAccountUpdate` transaction (`values[types.TxValueKeyAccountKey]`), sign it with an arbitrary valid key, and RLP-encode the full transaction.
5. Submit the encoded transaction via `eth_sendRawTransaction` / `klay_sendRawTransaction` (`KaiaTransactionAPI.SendRawTransaction`).
6. Observe that `Transaction.DecodeRLP` recurses through `AccountKeyRoleBased.DecodeRLP` N times before any `ErrNestedCompositeType` check occurs, exhausting the goroutine stack and crashing/panicking the RPC-handling process, denying service to other users of that node.

func (a *AccountKeyRoleBased) DecodeRLP(s *rlp.Stream) error {
	enc := [][]byte{}
	if err := s.Decode(&enc); err != nil {
		return err
	}

	keys := make([]AccountKey, len(enc))
	for i, b := range enc {
		serializer := NewAccountKeySerializer()
		if err := rlp.DecodeBytes(b, &serializer); err != nil {
			return err
		}
		keys[i] = serializer.key
	}

	*a = (AccountKeyRoleBased)(keys)

	return nil
}

func (s *Stream) readKind() (kind Kind, size uint64, err error) {
	b, err := s.readByte()
	if err != nil {
		if len(s.stack) == 0 {
			// At toplevel, Adjust the error to actual EOF. io.EOF is
			// used by callers to determine when to stop decoding.
			switch err {
			case io.ErrUnexpectedEOF:
				err = io.EOF
			case ErrValueTooLarge:
				err = io.EOF
			}
		}
		return 0, 0, err
	}
	s.byteval = 0
	switch {
	case b < 0x80:
		// For a single byte whose value is in the [0x00, 0x7F] range, that byte
		// is its own RLP encoding.
		s.byteval = b
		return Byte, 0, nil
	case b < 0xB8:
		// Otherwise, if a string is 0-55 bytes long, the RLP encoding consists
		// of a single byte with value 0x80 plus the length of the string
		// followed by the string. The range of the first byte is thus [0x80, 0xB7].
		return String, uint64(b - 0x80), nil
	case b < 0xC0:
		// If a string is more than 55 bytes long, the RLP encoding consists of a
		// single byte with value 0xB7 plus the length of the length of the
		// string in binary form, followed by the length of the string, followed
		// by the string. For example, a length-1024 string would be encoded as
		// 0xB90400 followed by the string. The range of the first byte is thus
		// [0xB8, 0xBF].
		size, err = s.readUint(b - 0xB7)
		if err == nil && size < 56 {
			err = ErrCanonSize
		}
		return String, size, err
	case b < 0xF8:
		// If the total payload of a list (i.e. the combined length of all its
		// items) is 0-55 bytes long, the RLP encoding consists of a single byte
		// with value 0xC0 plus the length of the list followed by the
		// concatenation of the RLP encodings of the items. The range of the
		// first byte is thus [0xC0, 0xF7].
		return List, uint64(b - 0xC0), nil
	default:
		// If the total payload of a list is more than 55 bytes long, the RLP
		// encoding consists of a single byte with value 0xF7 plus the length of
		// the length of the payload in binary form, followed by the length of
		// the payload, followed by the concatenation of the RLP encodings of
		// the items. The range of the first byte is thus [0xF8, 0xFF].
		size, err = s.readUint(b - 0xF7)
		if err == nil && size < 56 {
			err = ErrCanonSize
		}
		return List, size, err
	}
