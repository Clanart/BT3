### Title
FieldMask path injection via unescaped comma when re-serializing attacker-controlled binary `FieldMask.paths` to ProtoJSON - (`upb/json/encode.c`, `src/google/protobuf/util/field_mask_util.cc`, `java/util/src/main/java/com/google/protobuf/util/FieldMaskUtil.java`, `python/google/protobuf/internal/field_mask.py`)

### Summary
Protobuf's ProtoJSON encoders for `google.protobuf.FieldMask` join the repeated `paths` strings with a literal `,` separator to build the single JSON string value, but none of the checked implementations reject or escape a `,` that is itself embedded inside one path. Because a binary-wire `FieldMask.paths` entry is an ordinary `string` field with no character restrictions, an attacker who controls a bounded binary Protobuf payload can set a single path value containing an embedded comma (e.g. `"a,b"`). When that message is later reflected to ProtoJSON by Protobuf's own public serialize API, the single attacker-controlled path is indistinguishable from two legitimate, comma-separated paths — exactly the “separator smuggled inside a value that is supposed to be one token” defect in the CSP report, just for the FieldMask JSON contract instead of the CSP header contract.

### Finding Description
`google.protobuf.FieldMask`'s documented JSON encoding is: “a single string where paths are separated by a comma” (`src/google/protobuf/field_mask.proto:178-206`) [1](#0-0) . Every encoder that implements this contract simply concatenates paths with `,` and never checks whether an individual path already contains a `,`:

- upb's C JSON encoder (used by the Ruby, PHP-upb and other upb-based bindings) builds the field mask by looping over `paths` and calling `jsonenc_putsep(e, ",", &first)` before each `jsonenc_fieldpath`, and `jsonenc_fieldpath`/`jsonenc_put_escaped_char` only escape control characters, quotes and backslashes — commas pass through untouched: [2](#0-1) , escape table at [3](#0-2) . The identical code exists in the Ruby and PHP upb copies: [4](#0-3) , [5](#0-4) .
- The C++ `util::FieldMaskUtil::ToJsonString` / `SnakeCaseToCamelCase` helper copies every character that isn't `_` or uppercase verbatim into the output, including `,`, before joining paths with `,`: [6](#0-5) .
- Java's `FieldMaskUtil.toJsonString`/`lowerUnderscoreToLowerCamel` has the same gap — it joins with `FIELD_PATH_SEPARATOR` (`,`) with no rejection of an embedded comma: [7](#0-6) .
- Python's `FieldMask.ToJsonString` does the same unconditional `','.join(...)`: [8](#0-7) .

On the decode side, every implementation (C++ `ParseFieldMask`, upb `jsondec_fieldmask`, PHP `GPBUtil::parseFieldMask`) unconditionally treats every `,` as a path separator: [9](#0-8) , [10](#0-9) , [11](#0-10) .

The missing invariant is exactly analogous to the CSP report: a value that downstream logic treats as **one opaque unit** (one CSP directive value / one FieldMask path) is joined into a delimited composite string using the same delimiter character (`;` / `,`) that appears in the composite grammar, and the value is never scrubbed of that delimiter before the join. Just as `build_sandbox_list_directive` lets an attacker's `;` become a new CSP directive that a later parser (the browser) splits out, `jsonenc_fieldpath`/`ToJsonString`/`toJsonString` let an attacker's `,` become what a later parser (Protobuf's own `ParseFieldMask`/`jsondec_fieldmask`, or any RFC-compliant AIP-134 FieldMask consumer) will split into an extra path.

### Impact Explanation
`FieldMask` is the standard mechanism (per AIP-134/AIP-157) for scoping partial-update/get requests to specific fields — many gRPC/REST services trust the parsed `paths` list directly as an authorization/whitelist boundary for which fields a caller may read or write. If a service:
1. accepts a bounded, attacker-controlled binary Protobuf message containing a `FieldMask` (or embedding one), and
2. re-serializes that message to ProtoJSON via Protobuf's own public `MessageToJson`/`serializeToJsonString`/`to_json` API to hand off to another component (a different service, a UI, an audit log, another language binding) that re-parses the FieldMask per the standard comma-separated ProtoJSON contract,

then a single attacker-supplied path value containing an embedded `,` will silently turn into two (or more) distinct paths at the consumer. This lets an attacker-controlled string smuggle an unintended field path into a field mask that a downstream trust boundary interprets structurally, mirroring the CSP bug's "one appended directive becomes two directives, one of which the app never approved."  This is Improper Neutralization of a structurally significant element (CWE-113 class), reachable purely through a bounded, well-formed binary Protobuf payload via the standard `FieldMask.paths` repeated-string field — no huge/unbounded input, no schema/plugin trust violation, no privileged access required.

### Likelihood Explanation
Exploitation requires no special access: any client of a public `ParseFrom*`/binary-parse API can set an arbitrary byte sequence (including `,`) into a `string` field, since binary wire format places no character restrictions on `string` fields, and the bug is triggered purely by then calling Protobuf's own supported JSON-serialize entry point on that message. All checked encoder implementations (upb/C, C++ util, Java, Python) have the same unescaped-join defect, indicating this is a systemic gap rather than a single-language oversight, raising confidence that it is a genuine, reachable, cross-implementation defect rather than an isolated bug.

### Recommendation
Apply the same fix pattern the CSP advisory prescribes for its three uncovered directive builders: before joining `FieldMask` paths with `,` in every JSON encoder (`upb/json/encode.c:jsonenc_fieldpath`, `field_mask_util.cc:SnakeCaseToCamelCase`/`ToJsonString`, `FieldMaskUtil.java:toJsonString`, `field_mask.py:ToJsonString`, and any other language binding's equivalent), either (a) reject the operation with an explicit error if a path contains a literal `,` (consistent with the existing rejection of uppercase/invalid underscore sequences already present in `jsonenc_fieldpath`), or (b) escape/percent-encode the `,` so it cannot be confused with the path separator on decode. Add regression/conformance tests (mirroring `conformance/binary_json_conformance_suite.cc`) asserting that a `FieldMask` path containing a comma either round-trips losslessly or is rejected at encode time, across all first-party JSON encoders.

### Proof of Concept
Conceptual reproduction (not executed, derived from source read):
1. Build a raw binary Protobuf payload for a message containing a `google.protobuf.FieldMask mask` field, with `mask.paths = ["a,b"]` (field 1, wire type 2, encoding the 3-byte string `a,b`).
2. Parse it with any supported binary parse API (e.g., `Message::ParseFromArray` in C++, `Message.parseFrom` in Java, or upb's `upb_Decode`). The resulting in-memory `FieldMask` correctly has a single path element `"a,b"`.
3. Serialize the same message to ProtoJSON using the standard public API (`util::MessageToJsonString`, `JsonFormat.printer().print(...)`, `FieldMaskUtil.toJsonString(mask)`, `message.to_json` on upb-based Ruby/PHP, or `FieldMask.ToJsonString()` in Python).
4. Inspect the produced JSON `FieldMask` value: it is the single string `"a,b"`, with no escaping of the embedded comma — see the join sites at [12](#0-11)  and [13](#0-12) .
5. Any standards-compliant FieldMask JSON consumer (including Protobuf's own `ParseFieldMask`/`jsondec_fieldmask`/`GPBUtil::parseFieldMask`, shown at [14](#0-13) ) parses this string as **two** paths, `"a"` and `"b"`, not the single original path `"a,b"` — confirming the injected splitting.

Because I could not execute code in this environment, this is a source-level trace rather than an executed test; the actual splitting behavior on decode (`memchr(ptr, ',', ...)` in `jsondec_fieldmask` and `absl::StrSplit(paths, ',')` in `ParseFieldMask`) is directly visible in the cited decode code and is unconditional, so the trace is deterministic from the source alone.

static void jsonenc_fieldpath(jsonenc* e, upb_StringView path) {
  const char* ptr = path.data;
  const char* end = ptr + path.size;

  while (ptr < end) {
    char ch = *ptr;

    if (ch >= 'A' && ch <= 'Z') {
      jsonenc_err(e,
                  "Field mask path containing an uppercase letter cannot be "
                  "successfully round tripped through JSON format. See "
                  "https://github.com/protocolbuffers/protobuf/issues/25786");
    } else if (ch == '_') {
      if (ptr == end - 1 || *(ptr + 1) < 'a' || *(ptr + 1) > 'z') {
        jsonenc_err(e,
                    "Underscore in FieldMask path must be followed by a "
                    "lowercase letter to successfully round trip through JSON "
                    "format. See "
                    "https://github.com/protocolbuffers/protobuf/issues/25786");
      }
      ch = *++ptr - 32;
    }

    jsonenc_put_escaped_char(e, ch);
    ptr++;
  }
}

static void jsonenc_fieldmask(jsonenc* e, const upb_Message* msg,
                              const upb_MessageDef* m) {
  const upb_FieldDef* paths_f = upb_MessageDef_FindFieldByNumber(m, 1);
  const upb_Array* paths = upb_Message_GetFieldByDef(msg, paths_f).array_val;
  bool first = true;
  size_t i, n = 0;

  if (paths) n = upb_Array_Size(paths);

  jsonenc_putstr(e, "\"");

  for (i = 0; i < n; i++) {
    jsonenc_putsep(e, ",", &first);
    jsonenc_fieldpath(e, upb_Array_Get(paths, i).str_val);
  }

  jsonenc_putstr(e, "\"");
}

  /* repeated string paths = 1; */
  const upb_FieldDef* paths_f = upb_MessageDef_FindFieldByNumber(m, 1);

bool FieldMaskUtil::SnakeCaseToCamelCase(absl::string_view input,
                                         std::string* output) {
  output->clear();
  bool after_underscore = false;
  for (char input_char : input) {
    if (input_char >= 'A' && input_char <= 'Z') {
      // The field name must not contain uppercase letters.
      return false;
    }
    if (after_underscore) {
      if (input_char >= 'a' && input_char <= 'z') {
        output->push_back(input_char + 'A' - 'a');
        after_underscore = false;
      } else {
        // The character after a "_" must be a lowercase letter.
        return false;
      }
    } else if (input_char == '_') {
      after_underscore = true;
    } else {
      output->push_back(input_char);
    }
  }
  if (after_underscore) {
    // Trailing "_".
    return false;
  }
  return true;
}

bool FieldMaskUtil::CamelCaseToSnakeCase(absl::string_view input,
                                         std::string* output) {
  output->clear();
  for (const char c : input) {
    if (c == '_') {
      // The field name must not contain "_"s.
      return false;
    }
    if (c >= 'A' && c <= 'Z') {
      output->push_back('_');
      output->push_back(c + 'a' - 'A');
    } else {
      output->push_back(c);
    }
  }
  return true;
}

bool FieldMaskUtil::ToJsonString(const FieldMask& mask, std::string* out) {
  out->clear();
  for (int i = 0; i < mask.paths_size(); ++i) {
    absl::string_view path = mask.paths(i);
    std::string camelcase_path;
    if (!SnakeCaseToCamelCase(path, &camelcase_path)) {
      return false;
    }
    if (i > 0) {
      out->push_back(',');
    }
    out->append(camelcase_path);
  }
  return true;
}

  /**
   * Converts a field mask to a ProtoJSON string, that is converting from snake case to camel case
   * and joining all paths into one string with commas.
   */
  public static String toJsonString(FieldMask fieldMask) {
    List<String> paths = new ArrayList<String>(fieldMask.getPathsCount());
    for (String path : fieldMask.getPathsList()) {
      if (path.isEmpty()) {
        continue;
      }
      paths.add(lowerUnderscoreToLowerCamel(path));
    }
    return String.join(FIELD_PATH_SEPARATOR, paths);
  }

   * converting from camel case to snake case.

    String[] paths = value.split(FIELD_PATH_SEPARATOR);

        continue;

template <typename Traits>
absl::Status ParseFieldMask(JsonLexer& lex, const Desc<Traits>& desc,
                            Msg<Traits>& msg) {
  absl::StatusOr<LocationWith<MaybeOwnedString>> str = lex.ParseUtf8();
  RETURN_IF_ERROR(str.status());
  auto paths = str->value.AsView();

  // The special case of the empty string is not handled correctly below,
  // because StrSplit("", ',') is [""], not [].
  if (paths.empty()) {
    return absl::OkStatus();
  }

  // google.protobuf.FieldMask has a single field with number 1.
  auto paths_field = Traits::MustHaveField(desc, 1);
  for (absl::string_view path : absl::StrSplit(paths, ',')) {
    std::string snake_path;
    // Assume approximately six-letter words, so add one extra space for an
    // underscore for every six bytes.
    snake_path.reserve(path.size() * 7 / 6);
    for (char c : path) {
      if (absl::ascii_isdigit(c) || absl::ascii_islower(c) || c == '.') {
        snake_path.push_back(c);
      } else if (absl::ascii_isupper(c)) {
        snake_path.push_back('_');
        snake_path.push_back(absl::ascii_tolower(c));
      } else if (lex.options().allow_legacy_nonconformant_behavior) {
        snake_path.push_back(c);
      } else {
        return str->loc.Invalid("unexpected character in FieldMask");
      }
    }
    Traits::SetString(paths_field, msg, snake_path);
  }

  return absl::OkStatus();
}
