### Title
Gasless module cannot promptly de-whitelist a compromised/fee-charging ERC20, allowing fee-delegation (gas-repayment) shortfall - (File: kaiax/gasless/impl/tx_pool.go, kaiax/gasless/impl/getter.go)

### Summary
The Kaia `kaiax/gasless` module whitelists a fixed set of ERC20 tokens (`allowedTokens`) that unprivileged users may swap for gas via `swapForGas`. Both mempool admission (`checkBalanceForSwap`) and bundle validation (`VerifyExecutable`) validate the transaction using the token's nominal `balanceOf`/`allowance`/`amountIn` values, implicitly assuming the `GaslessSwapRouter` will actually receive the full declared `amountIn` when it calls `transferFrom`. This is the same root-cause class as the reported finding: once a whitelisted token's transfer semantics change (e.g. a fee-on-transfer or rebasing upgrade), the protocol has no fast, transaction-triggered way to remove it from the whitelist — the whitelist is refreshed once per block from a delayed Registry-style mechanism, not something a single transaction/RPC caller can immediately correct.

### Finding Description
`GaslessModule.isApproveTx` and `isSwapTx` only check membership in the `allowedTokens` map populated by `updateAddresses`, which is invoked once per block in `PostInsertBlock` [1](#0-0) . The admission checks performed before executing/bundling a gasless swap validate declared amounts against on-chain `balanceOf`/`allowance` of the sender, and require `swapArgs.AmountIn` to be at least the router's `GetAmountIn(minAmountOut)`, but never verify what the router actually *receives* after the ERC20 transfer: [2](#0-1) 

The gasless swap/approve pattern is validated purely by nominal values (`SP2`: `approveArgs.Amount >= swapArgs.AmountIn`, and the repay-amount equality check) with no accounting for tokens that deduct a fee on `transferFrom`: [3](#0-2) 

Token whitelisting itself is a governance-controlled, delayed mechanism (registered via the KIP-149 `Registry` contract with a future `targetBlockNum` before it takes effect), as exercised in the test setup: [4](#0-3) 

No expedited/administrative "remove-now" path independent of this delayed registry update was found for `allowedTokens`, mirroring the report's "no way to remove a whitelisted collateral" problem: once a listed token's transfer behavior changes (fee-on-transfer, rebase, blacklist logic, etc.), affected transactions continue to pass pool/bundle admission checks that assume full-value transfers.

### Impact Explanation
If a whitelisted gasless token begins charging a transfer fee (or otherwise delivers less than the nominal amount on `transferFrom`), the `GaslessSwapRouter` receives less than `swapArgs.AmountIn` while the transaction has already passed all off-chain/mempool validity checks in `checkBalanceForSwap`/`VerifyExecutable`, which are based on the sender's balance/allowance rather than the router's actual receipt. This can cause the swap to produce less output than required to satisfy `minAmountOut`/`amountRepay`, i.e., a shortfall in the amount repaid to the fee-delegating consensus node (CN) that already incurred the gas cost of accepting/executing the bundled transaction, or unpredictable reverts at execution time for transactions the pool considered valid — a divergence between admission-time and execution-time state that can be exploited by a gasless user against the fee-delegation counterparty (the CN/lender).

### Likelihood Explanation
Exploitation requires only that a currently-whitelisted token later change its transfer semantics (fee-on-transfer, rebase, or similar), which is entirely plausible for third-party ERC20s admitted to `allowedTokens` via governance/registry. Once that happens, any unprivileged user submitting an ordinary `approve`+`swapForGas` pair (or standalone swap) can trigger the shortfall — no privileged access is needed to exploit the condition, only to have originally listed the affected token, which is a normal governance action, not an attack precondition.

### Recommendation
- Verify the router's actual token balance delta (pre/post `transferFrom`) matches the declared `amountIn` before proceeding with the swap, rather than trusting the nominal amount.
- Provide an expedited/emergency de-whitelisting path for `allowedTokens` that does not depend on the standard delayed Registry update cycle, so a misbehaving or fee-charging token can be pulled from gasless eligibility immediately.
- Consider re-validating amounts at execution time (not just at pool-admission time) to reject bundles where actual and declared token amounts diverge.

### Proof of Concept
1. Governance whitelists token X in the gasless `Registry`/`allowedTokens` set (as in `tests/gasless_test.go`, `registry.Register(..., gsrAddr, targetBlockNum)`).
2. Token X's owner (or an upgradeable proxy) later enables a transfer fee, so `transferFrom` delivers `amountIn - fee` to `GaslessSwapRouter`.
3. `checkBalanceForSwap` in `kaiax/gasless/impl/tx_pool.go` still passes because it only checks the sender's `balanceOf`/`allowance` against the declared `amountIn`, not what the router will actually receive.
4. `GaslessModule.VerifyExecutable` (`kaiax/gasless/impl/getter.go`) likewise only compares `approveArgs.Amount` to `swapArgs.AmountIn` and validates the computed `repayAmount`, without accounting for the fee.
5. The transaction is accepted into the pool/bundle, but the router receives less than `amountIn`, producing a smaller swap output than assumed — potentially causing the CN to be repaid less than `amountRepay` for gas it already advanced, and there is no fast mechanism to remove token X from `allowedTokens` outside the normal governance/registry delay.

Note: The `GaslessSwapRouter.sol` source was not present in the indexed codebase (only its Go bindings were found), so the exact on-chain handling of the received-vs-declared amount inside `swapForGas` could not be directly verified; a Devin session with full repository access would be needed to confirm whether the router uses balance-diff accounting that would mitigate this, or a fixed `amountIn` value as in the vulnerable Polynomial pattern.

// IsGaslessPattern checks following conditions:
// Ax. IsApproveTx conditions (if ApproveTx != nil)
// Sx. IsSwapTx conditions
// AP1. ApproveTx.from == SwapTx.from
// SP1. ApproveTx.to == SwapTx.token
// SP2. ApproveTx.amount >= SwapTx.amountIn
// SP3. ApproveTx.nonce+1 == SwapTx.nonce and Gasless transactions are head for nonce
// SP4. SwapTx.amountRepay = RepayAmount(ApproveTx, SwapTx)
func (g *GaslessModule) IsExecutable(approveTxOrNil, swapTx *types.Transaction) bool {
	err := g.VerifyExecutable(approveTxOrNil, swapTx)
	if err != nil {
		return false
	}
	return true
}

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}
