## Title
Deprecated-TokenGateway on_timeout rejection permanently blocks refund path for legitimate in-flight escrowed transfers - ([File: parachain/runtimes/nexus/src/ismp.rs])

### Summary
Nexus's `ProxyModule::on_timeout` unconditionally rejects any `Post` request timeout whose `from` field matches one of the hardcoded `DEPRECATED_TOKEN_GATEWAY_ADDRESSES`, before any other processing runs. Because Nexus acts as a routing hub for cross-chain messages whose `dest != HostStateMachine` (forwarded via `Ismp::dispatch_request` in `on_accept`), a legitimate TokenGateway transfer that was already in flight when the deprecation list was added — with real user assets locked/burned in escrow on the origin EVM `TokenGateway` contract — can never have its timeout delivered back through Nexus. This mirrors the M-09 pattern: a lifecycle transition (sunset/deprecation) permanently disables the only recovery mechanism (timeout-driven refund) for funds already escrowed under the old regime, leaving them stuck with no path to reclaim them.

### Finding Description
`ProxyModule::on_accept` forwards any request whose `dest != HostStateMachine::get()` via `Ismp::dispatch_request`, making Nexus a relay hop between EVM chains for `TokenGateway` cross-chain transfers: [1](#0-0) 

The corresponding `on_timeout` handler adds an unconditional, permanent rejection for any timed-out `Post` request whose `from` matches a deprecated `TokenGateway` address, before the normal source/pallet routing logic executes: [2](#0-1) 

The list of blocked addresses is hardcoded and applied unconditionally to both `on_accept` and `on_timeout`: [3](#0-2) 

`pallet-token-gateway`'s own docs confirm the recovery invariant this breaks: "Funds from undelivered requests can be recovered by submitting a timeout message for the request through `pallet-ismp`." [4](#0-3) 

Because a `TokenGateway` transfer locks or burns the user's assets in escrow at dispatch time and only unlocks/refunds them via `on_timeout` (or successful delivery), any transfer that was dispatched from a now-deprecated `TokenGateway` address and fails to be delivered before its timeout has no recovery path once the deprecation filter is live: Nexus will reject processing the timeout unconditionally, regardless of whether the underlying assets are real, legitimately escrowed user funds. This is exactly analogous to the `PositionManager` bug in the external report — a lifecycle/deprecation action (sunset) closes off the only mechanism (cooldown-triggered dequeue / timeout-triggered refund) that lets a legitimate user recover funds already committed under the pre-deprecation state.

### Impact Explanation
This is a High impact, fund-lock class issue: it can permanently strand real user assets (locked native tokens or burned ERC-6160/ERC-20 balances) in the deprecated EVM `TokenGateway` contract's escrow with no governance override or alternate recovery call visible in this handler — the rejection is unconditional and independent of admin/governance action once the address list is deployed. Unlike a malicious-relayer or malicious-peer scenario, this triggers for ordinary users who dispatched a transfer before deprecation and simply experienced ordinary delivery latency or destination unavailability past the timeout window.

### Likelihood Explanation
Likelihood is Low-to-Medium: it requires a transfer to be in flight (dispatched, not yet delivered) at the exact moment the deprecation list takes effect, and for that transfer to subsequently time out rather than deliver successfully. This is a narrow window, but is entirely plausible given real relayer/finality latency, and requires no attacker — it's an inherent race in the deprecation rollout design.

### Recommendation
Before enabling the `DEPRECATED_TOKEN_GATEWAY_ADDRESSES` rejection (or as part of the same runtime upgrade), ensure the deprecation is scoped only to *new* incoming requests and does not block the `on_timeout` refund path for previously-dispatched (in-flight) requests. Options: (1) only reject in `on_accept` (block new/incoming asset transfers) while still allowing `on_timeout` for these addresses to proceed to the pallet's refund logic, since a timeout only ever *returns* previously-escrowed funds and never delivers new state; (2) add a grace/drain period that processes all commitments dispatched from deprecated addresses before the reject-list is activated; (3) add a governance-gated escape hatch that lets Nexus (or the origin `TokenGateway` contract) manually settle/refund commitments tied to deprecated addresses.

### Proof of Concept
1. A user calls `teleport` (or the EVM `TokenGateway.teleport`) from a `TokenGateway` contract address that is later added to `DEPRECATED_TOKEN_GATEWAY_ADDRESSES`, locking/burning their asset in escrow and dispatching a Post request with `timeout > 0` routed through Nexus (`dest != HostStateMachine`).
2. Before the request is delivered to its destination, the relevant `DEPRECATED_TOKEN_GATEWAY_ADDRESSES` entry is added to the Nexus runtime (deprecation goes live) — see `evm/src/apps/IntentGatewayV2.sol`/token-gateway docs confirming legacy TokenGateway addresses were deprecated in favor of `pallet-hyper-fungible-token`.
3. The request times out (destination liveness failure, no delivery within `timeoutTimestamp`).
4. A relayer submits the timeout message to Nexus; `ProxyModule::on_timeout` matches `is_deprecated_token_gateway(&post.from)` and returns `Err(...)` unconditionally, per [5](#0-4) .
5. The timeout is never processed, so the refund/unlock logic on the origin `TokenGateway` contract is never triggered — the user's escrowed assets remain locked indefinitely with no available recovery call.

Note: I was not able to fully trace the exact wire-level semantics of how a rejected `on_timeout` on the Nexus intermediary hop propagates (or fails to propagate) back to the origin EVM `TokenGateway` contract's own timeout-triggered refund call (`onPostRequestTimeout` in `EvmHost.sol`), since that depends on `pallet-ismp`'s handler-level behavior on `IsmpModule::on_timeout` returning `Err`, which I could not fully inspect within the available context. If, in practice, `pallet-ismp` still records the timeout receipt (or independently relays the timeout proof back to the origin chain) even when the module rejects processing, then the origin chain's own `dispatchTimeOut` refund path could still succeed independently of the Nexus module's rejection, which would substantially reduce or eliminate this finding's impact. Confirming this requires reading `modules/pallets/ismp/src/handlers/timeout.rs` (or equivalent) to see whether `Err` from `IsmpModule::on_timeout` blocks receipt/commitment cleanup or request-status propagation to the origin state machine.

/// Deprecated TokenGateway contract addresses whose incoming ISMP Post requests
/// must be rejected unconditionally by the nexus runtime.
/// Any [`PostRequest`] whose `from` field matches any of these 20-byte addresses
/// is rejected in [`ProxyModule::on_accept`] before any other processing — the
/// message is neither dispatched locally nor forwarded onwards.
pub const DEPRECATED_TOKEN_GATEWAY_ADDRESSES: &[[u8; 20]] = &[
	// Ethereum / Arbitrum / Optimism / Base / BSC / Gnosis TokenGateway
	hex_literal::hex!("Fd413e3AFe560182C4471F4d143A96d3e259B6dE"),
	// Polygon / Unichain TokenGateway
	hex_literal::hex!("8b536105b6Fae2aE9199f5146D3C57Dfe53b614E"),
	// Soneium TokenGateway
	hex_literal::hex!("Ce304770236f39F9911BfCC51afBdfF3b8635718"),
];

/// Returns `true` if `from` is exactly one of the deprecated TokenGateway
/// contract addresses in [`DEPRECATED_TOKEN_GATEWAY_ADDRESSES`].
fn is_deprecated_token_gateway(from: &[u8]) -> bool {
	DEPRECATED_TOKEN_GATEWAY_ADDRESSES.iter().any(|deprecated| deprecated == from)
}

	fn on_timeout(&self, timeout: Request) -> Result<Weight, anyhow::Error> {
		// Permanently reject Post-request timeouts whose originating module is a
		// deprecated TokenGateway deployment, before any other handling runs. Only
		// Post requests are subject to this — Get requests and Response timeouts
		// are untouched.
		if let Request::Post(post) = &timeout {
			if is_deprecated_token_gateway(&post.from) {
				return Err(anyhow!(
					"rejecting Post-request timeout from deprecated TokenGateway address {:?}",
					post.from,
				));
			}
		}
