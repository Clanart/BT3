### Title
`ReceivedOutput::read` accepts any offset/output pair without verifying the offset actually derives the output's `script_pubkey`, letting an untrusted party fabricate "received" funds that are not spendable - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner` maintains a `scripts: HashMap<ScriptBuf, Scalar>` binding each watched `script_pubkey` to the scalar offset needed to spend it. `scan_transaction` only produces a `ReceivedOutput` after looking the output's `script_pubkey` up in that map, so a scanned output is guaranteed spendable under `key + offset*G`. `ReceivedOutput::read`, however, deserializes `offset`, `output`, and `outpoint` straight from the byte stream with no check that `p2tr_script_buf(self.key + GENERATOR * offset) == output.script_pubkey`. A `ReceivedOutput` is explicitly documented as "a spendable output," yet nothing in the deserialization path enforces that invariant.

### Finding Description
The external report's bug class is a privileged path (`executeOperation`, intended to run only for self-initiated flash loans) that can be triggered by any external party because the gate verifies the immediate caller, not the true initiator — and the attacker-controlled `params` then drive a privileged action.

In `networks/bitcoin/src/wallet/mod.rs`, the spendability invariant is established inside `Scanner` at scan time (`scan_transaction` at lines 199–214 only emits outputs whose `script_pubkey` was registered via `register_offset`/`Scanner::new`). `ReceivedOutput::read` (lines 122–134) reconstructs the same type from untrusted bytes while skipping that check entirely. Just as `executeOperation` assumed "the lending pool called me, therefore I initiated the loan," `ReceivedOutput::read` assumes "these bytes came from a Scanner, therefore `offset` spends `output`." Any unprivileged party who can feed bytes into `ReceivedOutput::read` (the rules explicitly designate it an untrusted-bytes surface) can inject a `ReceivedOutput` claiming funds were received under an offset that does not correspond to the output's `script_pubkey` — e.g., an arbitrary `TxOut` paying someone else's script paired with an arbitrary scalar, or an offset that maps to a different (even script-path-controlled) key.

### Impact Explanation
Any downstream consumer that treats `ReceivedOutput`s as spendable balance (the struct's own documentation promises this) will account for BTC that cannot actually be spent. An attacker can inflate reported received balances or inject outputs that later fail at signing/spend time — "funds reported received that are not spendable," an accepted impact class. A crafted `TxOut`/`OutPoint` also lets the attacker point the wallet at arbitrary outpoints.

### Likelihood Explanation
Reachable by any unprivileged party able to supply bytes to `ReceivedOutput::read` — no key share, validator status, or collusion required. The only prerequisite is an integration that round-trips or accepts serialized `ReceivedOutput`s from a peer/remote source rather than solely from its own `Scanner`. Likelihood is moderate: integrations that only ever deserialize their own scans are unaffected, but nothing in the type or API communicates that requirement.

### Recommendation
Bind the deserialized components the same way `scan_transaction` does: have `ReceivedOutput::read` take the scanning `key` (or a `&Scanner`) and verify `p2tr_script_buf(key + GENERATOR * offset) == Some(output.script_pubkey)`, rejecting otherwise. Alternatively, rename/document the read API as trusted-only and provide a separate `verify(&Scanner)` method — but an explicit cryptographic check is preferable since the type carries a "spendable" guarantee.

### Proof of Concept

```rust
// Attacker crafts bytes for a ReceivedOutput whose offset does NOT
// derive the output's script_pubkey.
let victim_key = scanner.key; // e.g. a known group key
let honest_offset = Scalar::ONE;

// An output paying an unrelated P2TR script (or an attacker's key).
let fake_output = TxOut {
    value: Amount::from_sat(100_000),
    script_pubkey: ScriptBuf::new_p2tr_tweaked(TweakedPublicKey::dangerous_assume_tweaked(
        attacker_xonly,
    )),
};
let fake_outpoint = OutPoint::new(some_txid, 0);

let mut buf = vec![];
buf.extend(honest_offset.to_bytes());       // valid scalar
buf.extend(serialize(&fake_output));        // arbitrary TxOut
buf.extend(serialize(&fake_outpoint));      // arbitrary OutPoint

// ReceivedOutput::read succeeds; the wallet now believes it owns a
// spendable output under key + offset*G, when the script_pubkey is
// keyed by something else entirely.
let ro = ReceivedOutput::read(&mut &buf[..]).unwrap();
// ro.value() == 100_000 reported as received, yet unspendable.
```

```rust
  /// Read a ReceivedOutput from a generic satisfying Read.
  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }
```

```rust
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {

          offset: *offset,
          output: output.clone(),

    }
```
