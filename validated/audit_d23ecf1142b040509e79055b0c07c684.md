### Title
Unbounded EIP-7702 Authorization List Causes Unmetered CPU/State-Write Work in the EVM Ante Pipeline - (File: x/evm/ante/preprocess.go)

### Summary
`EVMPreprocessDecorator.AnteHandle` runs `associateAuthorizationAuthorities`, which loops over every entry of a `SetCodeTx`'s EIP-7702 authorization list and performs ECDSA recovery plus a Sei/EVM address association write for each one [1](#0-0) . This loop executes while the context is set to an **infinite gas meter**, and it runs *before* the decorator that validates intrinsic gas (`BasicDecorator`) and *before* the decorator that sets the real, bounded EVM gas meter (`GasDecorator`) in the ante chain ordering [2](#0-1) . The authorization list itself has no length cap — `validateAuthList` only rejects an empty list, never bounds its size [3](#0-2) .

### Finding Description
`EVMPreprocessDecorator.AnteHandle` first switches the context to `sdk.NewInfiniteGasMeterWithMultiplier` "because EVM handles gas checking from within" [4](#0-3) , then calls `p.associateAuthorizationAuthorities(ctx, msg, associateHelper)` unconditionally for every EVM transaction [5](#0-4) . That function unpacks the tx data, and if it is a `SetCodeTx` (EIP-7702), iterates `ethTx.SetCodeAuthorizations()` calling `helpers.AuthorityToPreAssociate` (ECDSA signature recovery) and `associateHelper.AssociateAddresses` (a Cosmos KV write under `ctx.CacheContext()`) for each authorization tuple [6](#0-5) .

The authorization list length is only validated for non-emptiness — there is no upper bound enforced anywhere in `validateAuthList` [3](#0-2) , nor in `AuthList`/`NewAuthList` construction [7](#0-6) .

Critically, the ante-decorator ordering places `EVMPreprocessDecorator` (which runs this unbounded loop) *before* `BasicDecorator` (which performs the `core.IntrinsicGas` check that would normally reject a tx whose declared `Gas()` is too low for the number of authorizations/access-list entries it carries) and before `GasDecorator` (which installs the bounded gas meter derived from the tx's own gas limit) [2](#0-1) . Consequently, an attacker can craft a `SetCodeTx` with a very large `AuthList` (bounded only by the node's max tx-size/mempool config, not by gas), and every node that receives and processes the transaction (in `CheckTx` and again in `DeliverTx`) will perform the entire per-authorization ECDSA-recovery/association loop under an infinite gas meter, with no gas charged for this work and no fee guaranteed to be collected (fee deduction/`BuyGas` happens later, in `EVMFeeCheckDecorator`, and the tx can still ultimately be rejected for insufficient intrinsic gas after the expensive loop has already run) [8](#0-7) .

This is structurally the same bug class as the reported `MarginTradingFactory.multicall` DoS: an externally reachable entry point iterates an attacker-controlled, unbounded array performing non-trivial work (there, `delegatecall`; here, ECDSA recovery + KV writes) with no cap on iteration count, and the cost-accounting mechanism that should bound the work (gas metering / intrinsic-gas rejection) is bypassed or deferred until after the expensive work has already executed.

### Impact Explanation
Every validator/full node that receives such a transaction (via gossip/mempool `CheckTx`, and again on `DeliverTx` if it makes it into a block) must perform this unbounded, effectively-free-to-submit loop of ECDSA recoveries and state association writes. A sufficiently large authorization list submitted repeatedly (mempool spam, since `CheckTx` never charges fees and the tx can still be rejected afterward) can degrade `CheckTx`/`DeliverTx` throughput network-wide, risking block-production delay beyond the 2.5-second target on a chain-wide basis rather than being scoped to a single misbehaving contract.

### Likelihood Explanation
Likelihood is high in terms of reachability — any unprivileged EVM transaction sender can submit a `SetCodeTx` (EIP-7702, supported per `AllowedTxTypes` for the `Prague` signer version) [9](#0-8)  with a crafted authorization list, and it is processed by the ante pipeline before any gas-based rejection or fee charge occurs. The actual severity depends on how large an authorization list a max transaction/mempool size permits and on the per-authorization CPU/state-write cost, which was not fully quantifiable from the indexed code alone (no explicit max-tx-bytes or mempool size constant was located in this pass).

### Recommendation
Move (or duplicate) the intrinsic-gas / authorization-count validation ahead of `EVMPreprocessDecorator`'s authorization-association loop, or cap the number of `SetCodeAuthorizations` processed in `associateAuthorizationAuthorities` (e.g., reject or truncate at the same limit go-ethereum's mempool imposes on authorization lists) before doing any ECDSA recovery/state work under the infinite gas meter. Alternatively, meter this loop against a bounded gas allowance (proportional to `etx.Gas()`) instead of running it under `sdk.NewInfiniteGasMeterWithMultiplier`.

### Proof of Concept
1. Construct a signed `SetCodeTx` (EIP-7702) whose `AuthList` contains the maximum number of distinct, validly-signed `SetCodeAuthorization` tuples that fit under the node's transaction-size limit (each tuple only needs to pass `validateAuthList`'s per-field length checks — there is no cap on list length).
2. Broadcast the transaction (or many copies with bumped nonces/different signers) to a full node's mempool.
3. Observe that `EVMPreprocessDecorator.AnteHandle` → `associateAuthorizationAuthorities` performs one ECDSA recovery (`AuthorityToPreAssociate`) and one association write attempt per authorization entry, under an infinite gas meter, prior to the `BasicDecorator` intrinsic-gas check that could otherwise reject the tx for insufficient declared gas — i.e., the expensive work occurs regardless of whether the tx is ultimately admitted.
4. Repeated submission of such transactions (which cost nothing until/unless they are actually included and pay fees) can be used to load `CheckTx` CPU time network-wide.

	// sender association above does not cover them. Associate each authority to its true
	// (pubkey-derived) Sei address before EVM execution installs delegation code for it.
	// Otherwise SetCode creates a mutable direct-cast EVM->Sei mapping that a later
	// associatePubKey call can remap, orphaning any staking/distribution state created

	// validator-removal hook).
	p.associateAuthorizationAuthorities(ctx, msg, associateHelper)

// associateAuthorizationAuthorities associates every EIP-7702 authorization authority in
// the transaction with its true (pubkey-derived) Sei address, so that a subsequent
// SetCode for the authority does not create a mutable direct-cast mapping. It is
// best-effort: authorities with invalid signatures (which EVM execution would also skip)
// or that are already associated are left untouched, and an association failure skips
// only that authority rather than rejecting the transaction, which go-ethereum would
// still accept.
func (p *EVMPreprocessDecorator) associateAuthorizationAuthorities(ctx sdk.Context, msg *evmtypes.MsgEVMTransaction, associateHelper *helpers.AssociationHelper) {
	txData, err := evmtypes.UnpackTxData(msg.Data)
	if err != nil {
		return
	}
	setCodeTx, ok := txData.(*ethtx.SetCodeTx)
	if !ok {
		// Only SetCode (EIP-7702) transactions carry authorizations.
		return
	}
	ethTx := ethtypes.NewTx(setCodeTx.AsEthereumData())
	for _, auth := range ethTx.SetCodeAuthorizations() {
		// Only pre-associate authorities whose authorization the EVM will actually apply
		// (matching chain id, nonce, and account state). This prevents replaying a
		// publicly-visible authorization a user signed for another chain to force-associate
		// them, which the EVM would skip but which still recovers a valid authority.
		evmAddr, seiAddr, pubkey, ok := helpers.AuthorityToPreAssociate(ctx, p.evmKeeper, auth)
		if !ok {
			continue
		}
		cacheCtx, write := ctx.CacheContext()
		if err := associateHelper.AssociateAddresses(cacheCtx, seiAddr, evmAddr, pubkey, false); err == nil {
			write()
		}
	}
}

func validateAuthList(authList AuthList) error {
	if len(authList) == 0 {
		return fmt.Errorf("auth list cannot be empty")
	}
	for _, auth := range authList {
		if auth.ChainID == nil {
			return fmt.Errorf("auth list chain id cannot be nil")
		}
		if err := validateHexAddress("auth list address", auth.Address); err != nil {
			return err
		}
		if err := validateSignatureValue("auth list v", auth.V, 1); err != nil {
			return err
		}
		if err := validateSignatureValue("auth list r", auth.R, 32); err != nil {
			return err
		}
		if err := validateSignatureValue("auth list s", auth.S, 32); err != nil {
			return err
		}
	}
	return nil
}

func NewAuthList(ethAuthList *[]ethtypes.SetCodeAuthorization) AuthList {
	if ethAuthList == nil {
		return nil
	}

	al := AuthList{}
	for _, auth := range *ethAuthList {
		chainId := sdk.NewIntFromBigInt(auth.ChainID.ToBig())
		al = append(al, SetCodeAuthorization{
			ChainID: &chainId,
			Address: auth.Address.String(),
			Nonce:   auth.Nonce,
			V:       []byte{auth.V},
			R:       (auth.R).Bytes(),
			S:       (auth.S).Bytes(),
		})
	}

	return al
}

func (fc EVMFeeCheckDecorator) AnteHandle(ctx sdk.Context, tx sdk.Tx, simulate bool, next sdk.AnteHandler) (sdk.Context, error) {
	if simulate {
		return next(ctx, tx, simulate)
	}

	msg := evmtypes.MustGetEVMTransactionMessage(tx)
	txData, err := evmtypes.UnpackTxData(msg.Data)
	if err != nil {
		return ctx, err
	}

	ver := msg.Derived.Version

	if txData.GetGasFeeCap().Cmp(fc.getBaseFee(ctx)) < 0 {
		return ctx, sdkerrors.ErrInsufficientFee
	}
	if txData.GetGasFeeCap().Cmp(fc.getMinimumFee(ctx)) < 0 {
		return ctx, sdkerrors.ErrInsufficientFee
	}
	if txData.GetGasTipCap().Sign() < 0 {
		return ctx, sdkerrors.Wrapf(sdkerrors.ErrInvalidRequest, "gas fee cap cannot be negative")
	}
	ethCfg := evmtypes.DefaultChainConfig().EthereumConfig(fc.evmKeeper.ChainID(ctx))

	// if EVM version is Cancun or later, and the transaction contains at least one blob, we need to
	// make sure the transaction carries a non-zero blob fee cap.
	if ver >= derived.Cancun && len(txData.GetBlobHashes()) > 0 {
		// For now we are simply assuming excessive blob gas is 0. In the future we might change it to be
		// dynamic based on prior block usage.
		if txData.GetBlobFeeCap().Cmp(eip4844.CalcBlobFee(ethCfg, &ethtypes.Header{Time: uint64(ctx.BlockTime().Unix())})) < 0 { // nolint:gosec
			return ctx, sdkerrors.ErrInsufficientFee
		}
	}

	// check if the sender has enough balance to cover fees
	etx, _ := msg.AsTransaction()
	emsg := fc.evmKeeper.GetEVMMessage(ctx, etx, msg.Derived.SenderEVMAddr)
	stateDB := state.NewDBImpl(ctx, fc.evmKeeper, false)
	gp := fc.evmKeeper.GetGasPool()
	blockCtx, err := fc.evmKeeper.GetVMBlockContext(ctx, gp)
	if err != nil {
		return ctx, err
	}
	txCtx := core.NewEVMTxContext(emsg)
	evmInstance := vm.NewEVM(*blockCtx, stateDB, ethCfg, vm.Config{}, fc.evmKeeper.CustomPrecompiles(ctx))
	evmInstance.SetTxContext(txCtx)
	st := core.NewStateTransition(evmInstance, emsg, &gp, true, false)
	// run stateless checks before charging gas (mimicking Geth behavior)
	if !ctx.IsCheckTx() && !ctx.IsReCheckTx() {
		// we don't want to run nonce check here for CheckTx because we have special
		// logic for pending nonce during CheckTx in sig.go
		if err := st.StatelessChecks(); err != nil {
			return ctx, sdkerrors.Wrap(sdkerrors.ErrWrongSequence, err.Error())
		}
	}
	if err := st.BuyGas(); err != nil {
		return ctx, sdkerrors.Wrap(sdkerrors.ErrInsufficientFunds, err.Error())
	}
