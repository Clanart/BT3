### Title
Lazily-parsed extension permanently "corrupted" after one malformed record poisons all future reads on that field - ([File: java/core/src/main/java/com/google/protobuf/InternalLazyField.java])

### Summary
CoreWCF's Kafka pump fails a single "poison" input (a null-value tombstone record) in a way that permanently disables all subsequent processing on that consumer — the missing check is "handle/skip the bad record and keep the pump alive"; instead the unhandled edge case wedges the loop forever, producing a persistent availability loss triggered by one attacker-controlled record. The nearest analog in this checkout is Java's lazily-parsed extension field implementation, `InternalLazyField` (and its lite counterpart `LazyFieldLite`), where a single malformed extension payload permanently marks the field `corrupted`, and — unlike a normal parse failure that is scoped to the one failed call — every subsequent access to that field object (`getValue()`, `hashCode()`, `equals()`, `toString()`, further `mergeFrom` calls) deterministically re-fails, by design, for the remaining lifetime of the object, with no recovery path.

### Finding Description
`InternalLazyField` defers parsing of an extension's bytes until first access [1](#0-0) . The class documents the invariant "If corrupted is true, value must be null" [2](#0-1) .

The failure path is in `ensureInitialized()`: on first access, if the lazily-stored bytes fail to parse, the field is marked `corrupted = true` and the exception is re-thrown; on any subsequent access, instead of retrying, the code short-circuits and unconditionally throws again ("Repeat access to corrupted lazy field") without ever attempting to recover or re-inspect the underlying bytes: [3](#0-2) 

`getValue()` — the primary read accessor used by `hashCode()`, `equals()`, `toString()`, and by `FieldSet.mergeFromField`/`getAllFields()` when resolving lazy fields for reflection — converts this into either a `RuntimeException` (when `lazyExtensionEnabled()`) or silently returns the default instance (legacy mode): [4](#0-3) 

Once `lazyExtensionEnabled()` is true (the new, hardened behavior this class was built for), a single malformed extension byte-payload converts every future, otherwise-legitimate call that touches this field (`equals`, `hashCode`, `toString`, `getAllFields()`, further `mergeFrom`) into an uncaught `InvalidProtobufRuntimeException` — a `RuntimeException`, not the checked `InvalidProtocolBufferException` callers normally guard against on parse. This is directly analogous to the CoreWCF bug's failed invariant: "one malformed unit of input should only fail that one unit's processing, and must not permanently disable future processing of the same, otherwise healthy, object/stream." Here the object (the extension field) is wedged permanently rather than merely failing the one access that triggered the corruption, and the failure mode (an unexpected `RuntimeException` from what looks like a read-only accessor such as `equals()`/`hashCode()`/`toString()`) is exactly the kind of unhandled exception category that, per the CoreWCF advisory, kills the surrounding processing loop when the caller isn't expecting a runtime exception from what should be side-effect-free accessor methods.

`FieldSet.mergeFromField` and `MessageReflection.mergeMessage` further compound this: they route repeated `mergeFrom()` calls for the same extension through `InternalLazyField.mergeFrom(lazyField, input, extensionRegistry)` whenever the field already exists [5](#0-4) , and `InternalLazyField.mergeFrom` calls `ensureInitialized()` whenever registries differ or the fast-path bytes-concatenation is unavailable [6](#0-5) . So a message object that has accumulated one corrupted extension will throw on every future merge targeting that extension too, not just on reads.

### Impact Explanation
A server that keeps a parsed message (or a builder accumulating merges, e.g. via repeated `mergeFrom`/streaming concatenation of extension data across multiple wire fragments) will have that specific extension field permanently unusable once one malformed byte sequence for it is received. Any code path that calls `equals()`, `hashCode()`, `toString()`, reflective `getAllFields()`, or additional `mergeFrom()` targeting that field will throw an uncaught `RuntimeException` from then on for that object, denying legitimate future operations on an otherwise valid message — an availability impact scoped to the affected message/field object, matching CWE-248 (uncaught exception)/CWE-754/755 (improper handling of exceptional/erroneous input) in the referenced advisory. This is narrower than the CoreWCF case (which wedges an entire topic-wide consumer pump) since the poisoning is scoped to a single message/field instance rather than a shared, long-lived service loop; whether it rises to a full persistent-DoS depends on whether application code caches/reuses that specific message instance across many subsequent requests (e.g., a long-lived cached prototype or memoized object), which is consuming-application-specific and not verifiable from the protobuf source alone.

### Likelihood Explanation
Reachable via the standard public binary-parse API for messages containing extensions, using `ExtensionRegistry` with `lazyExtensionEnabled()` set — an ordinary client sending a bounded, malformed extension payload for a message field can trigger this with no special privileges beyond being able to submit a message to the parsing API. The precondition (`lazyExtensionEnabled()`, a `MessageSet` or lazily-loaded extension path) narrows applicability to codepaths already opted into this class's newer, hardened lazy-parsing mode [7](#0-6) , and the persistence of the impact requires the application to retain and reuse the poisoned object across multiple later operations — this reuse pattern cannot be confirmed generically from the library alone.

### Recommendation
In `InternalLazyField.ensureInitialized()`/`getValue()`, avoid converting a single malformed-bytes failure into a permanently sticky `corrupted` state that turns unrelated accessor calls (`equals`, `hashCode`, `toString`, `getAllFields`) into uncaught `RuntimeException`s; either scope the failure to the specific operation that attempted the parse (throwing a checked exception only from parse-triggering call sites) or ensure `RuntimeException` propagation is clearly documented and defensively caught at all call sites (`FieldSet`, `MessageReflection`) that invoke `getValue()`/`mergeFrom()` on a potentially corrupted lazy field, so a single bad record cannot silently convert benign accessor use into an unhandled-exception denial-of-service for the remainder of that object's lifetime.

### Proof of Concept
Not independently executed in this environment (read-only index access); logical reproduction based on code inspection:
1. Enable lazy extension parsing (`ExtensionRegistryLite.lazyExtensionEnabled()` returns true for the registry used).
2. Parse a message containing a `MessageSet`/extension field whose serialized bytes for that field are intentionally malformed (e.g., truncated length-delimited submessage), using `InternalLazyField(defaultInstance, extensionRegistry, corruptBytes)` via the normal `parseFrom` path (`MessageReflection.mergeMessage` at [8](#0-7) ).
3. Call `message.getExtension(...)`, `message.equals(other)`, `message.hashCode()`, or `message.toString()` — first call parses lazily, fails, sets `corrupted = true`, and throws `InvalidProtobufRuntimeException` (per `ensureInitialized`/`getValue()` at [9](#0-8) ).
4. Repeat any of the above accessor calls on the same message object — each call re-throws deterministically ("Repeat access to corrupted lazy field") with no possibility of recovery, confirming the permanent, object-scoped denial rather than a one-shot parse failure.

  private void ensureInitialized() throws InvalidProtocolBufferException {
    if (value != null) {
      return;
    }

    synchronized (this) {
      if (corrupted) {
        throw new InvalidProtocolBufferException("Repeat access to corrupted lazy field");
      }
      try {
        // `bytes` is guaranteed to be non-null since `value` was null.
        CodedInputStream input = bytes.newCodedInput();
        input.enableAliasing(/* enabled= */ true);
        // When lazyExtensionEnabled() returns true, it means all extensions including MessageSet's
        // will be fully parsed. When it returns false, it basically implies this can only be a
        // MessageSet extension, and we should fall back to the old behavior of silently returning
        // the default instance on corrupted extensions i.e. a full parse.
        value =
            extensionRegistry.lazyExtensionEnabled()
                ? defaultInstance.getParserForType().parsePartialFrom(input, extensionRegistry)
                : defaultInstance.getParserForType().parseFrom(input, extensionRegistry);
        input.checkLastTagWas(0);
      } catch (InvalidProtocolBufferException e) {
        corrupted = true;
        throw e;
      }
    }
  }

  /**
   * Returns the parsed message value.
   *
   * <p>If the lazy field is corrupted, it will throw a runtime exception if {@link
   * ExtensionRegistryLite#lazyExtensionEnabled()} is true, otherwise it will return the default
   * instance.
   */
  MessageLite getValue() {
    try {
      ensureInitialized();
      return value;
    } catch (InvalidProtocolBufferException e) {
      if (extensionRegistry.lazyExtensionEnabled()) {
        // New behavior: runtime exception on corrupted extensions.
        throw new InvalidProtobufRuntimeException(e);
      } else {
        // Old behavior: silently return the default instance.
        return defaultInstance;
      }
    }
  }
