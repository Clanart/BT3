Confirmed: `is_deposit_valid` (`core/src/verifier.rs:541-732`) checks the security council, watchtower/operator/verifier count and uniqueness, that the deposit tx exists on chain with the correct amount/script pubkey, and that it's confirmed at or after `start_height` — it never checks whether the deposit output is still unspent. [1](#0-0) [2](#0-1) 

This confirms the premise: an attacker can deposit into the bridge address and then spend that same UTXO before/while the aggregator drives a `new_deposit` round, and verifiers will still produce N-of-N partial signatures over the `MoveToVault` transaction's sighash via `deposit_sign`/`deposit_finalize`, since nothing in the code checks `is_utxo_spent` for the deposit outpoint (unlike `sign_optimistic_payout`, which explicitly calls `self.rpc.is_utxo_spent(&input_outpoint)` for withdrawal UTXOs).
