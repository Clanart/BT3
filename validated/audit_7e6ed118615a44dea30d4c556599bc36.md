### Title
Deserialized `ReceivedOutput` binds an arbitrary offset to an arbitrary `TxOut`, so funds can be reported received yet be provably unspendable (and crash signing) — ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
The analog of "record in phase 1, re-derive and compare in phase 2" exists in `bitcoin-serai`'s output pipeline. A `ReceivedOutput` pairs a scalar `offset` with a `TxOut`. `Scanner::scan_transaction` produces pairs that are self-consistent (script ↔ offset), but `ReceivedOutput::read` deserializes both fields from untrusted bytes with no consistency check. Later, `SignableTransaction::new` stores the recorded `offsets` verbatim, and `SignableTransaction::multisig` re-derives `p2tr_script_buf(key + G*offset)` and requires it to equal `prevouts[i].script_pubkey` — the phase-2 recomputation of the phase-1 implicit invariant. A mismatch returns `None`, which `attempt_sign` turns into a panic (`"used the wrong keys"`), freezing spends and halting the processor.

### Finding Description
`ReceivedOutput::read` accepts any `(offset, output, outpoint)` triple from a byte stream, with no relation enforced between `offset` and `output.script_pubkey` — it decodes `offset = Secp256k1::read_F(r)` and the `TxOut`/`OutPoint` independently. In contrast, the honest producer `Scanner::scan_transaction` only emits outputs where `scripts.get(&output.script_pubkey)` yields the exact registered offset, so the invariant `p2tr_script_buf(key + G*offset) == output.script_pubkey` holds by construction. At spend time, `SignableTransaction::new` collects `inputs.iter().map(|input| input.offset)` into `self.offsets`, and `multisig` recomputes the expected script per input: `if p2tr_script_buf(offset.group_key())? != self.prevouts[i].script_pubkey { None? }`. Like the vault's `require(userWithdraw.shares >= _shares)` comparing values from two epochs, this check compares a recomputed value against a stale recorded one — except here the divergence is attacker-injected rather than price-driven. The `None` propagates to `Bitcoin::attempt_sign`, which calls `.expect("used the wrong keys")` and panics.

### Impact Explanation
An unprivileged party who can feed bytes into `ReceivedOutput::read` (the deserialization path used to load persisted/transported outputs) can cause an output to be recorded as wallet funds — carrying a real-looking `TxOut` and `OutPoint` — that no signature can ever be produced for, since the offset doesn't derive the output's script. Beyond "funds reported received that are not spendable," including such an output in a `SignableTransaction` makes `multisig()` return `None`, causing `attempt_sign` to panic, which aborts signing for the entire batch (all honest inputs in the transaction are blocked too).

### Likelihood Explanation
The trigger requires only malformed input bytes on the `ReceivedOutput::read` path — no key material, collusion, or validator misbehavior. Any untrusted source that can inject into output persistence/transport (e.g., a forged serialized output) can plant the inconsistent pair once; the failure then deterministically fires every time a transaction tries to spend it, making it a persistent freeze rather than a transient error.

### Recommendation
Bind the offset to the output at the boundary where the pair is created/read, mirroring the report's fix ("store and use the recorded value directly" → here, "validate the recorded pair once, at ingress"):
- In `ReceivedOutput::read` (or a checked constructor), require `p2tr_script_buf(key + G*offset) == Some(output.script_pubkey)` — this needs the scanner key, so alternatively store/derive the expected script or the full tweaked point inside `ReceivedOutput` and verify internally.
- Have `SignableTransaction::new` reject mismatched inputs early with a `TransactionError` instead of letting `multisig` return `None` into a panicking `.expect` in `attempt_sign`, so a bad input yields an error rather than a crash.

### Proof of Concept
1. Deserialize: `let forged = ReceivedOutput::read(&mut bytes)` where `bytes` encodes a random scalar `o` plus a `TxOut` whose `script_pubkey` is `p2tr_script_buf(key + G*o')` for some `o' != o` (or any valid P2TR script not derived from `o`) and any `OutPoint`. `read` succeeds — no check links `o` to the script.
   - `read` body: `offset = Secp256k1::read_F(r)?;` then independent `TxOut`/`OutPoint` decode.
2. Spend attempt: `SignableTransaction::new(vec![forged, honest_output], &payments, change, None, fee)` succeeds — it only checks `NoInputs`, `DustPayment`, `NotEnoughFunds`, weight; `offsets` is copied from `input.offset` without validation.
3. `tx.multisig(&keys)` computes `keys.clone().offset(o)` → `p2tr_script_buf(group_key) != prevout.script_pubkey` → returns `None`.
4. `Bitcoin::attempt_sign` executes `transaction.actual.clone().multisig(&keys).expect("used the wrong keys")` → panic, aborting the signing attempt for all inputs.
