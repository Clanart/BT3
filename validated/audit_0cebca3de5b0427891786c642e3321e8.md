### Title
Attacker-flooded received outputs inflate input count, forcing one FROST signature machine per input with quadratic share handling — (File: networks/bitcoin/src/wallet/send.rs)

### Summary
Analogous to the Y2K `rolloverQueue` issue — where dead queue items permanently inflate the cost of every rollover — `SignableTransaction`/`TransactionMachine` in the bitcoin-serai wallet scale linearly (and in `complete`, quadratically) with the number of inputs, and the set of candidate inputs is driven by outputs anyone can send to the multisig's addresses. There is no mechanism to prune or consolidate "dead" low-value outputs before they are fed into `SignableTransaction::new`, so an attacker can persistently raise the CPU/memory cost of every spend the multisig performs.

### Finding Description
`SignableTransaction::new` accepts an arbitrary `Vec<ReceivedOutput>` and turns every entry into a `TxIn` plus a stored prevout, with no per-input economic check (each input is admitted as long as total `input_sat >= payment_sat + needed_fee`). [1](#0-0) 

`multisig` then instantiates a separate FROST `AlgorithmMachine` per input — each input is an independent Schnorr signing ceremony over the same participant set. [2](#0-1) 

During completion, `TransactionSignatureMachine::complete` calls `shares.remove(0)` on each participant's share vector for every input, making share assembly O(inputs × participants × shares-per-participant) — quadratic in attacker-influenced input count. [3](#0-2) 

The only bound is the standardness weight check at the end of `new`, which permits on the order of ~1600 inputs per transaction — roughly 1600 concurrent FROST sign/verify pipelines per attempt. [4](#0-3) 

On the intake side, `get_outputs`/`Scanner::scan_transaction` admit every output ≥ `DUST` (546 sat) paying to the external, branch, change, or forward addresses — all of which are publicly derivable (`external_address`/`forward_address`). An unprivileged party can keep sending cheap ≥546-sat outputs that permanently enlarge the input set Serai must process. [5](#0-4) [6](#0-5) 

### Impact Explanation
Every spend attempt by the multisig must preprocess, sign, and complete one FROST signature per input. Attacker-injected dust-value inputs accumulate like the "dead" rollover items: they carry almost no economic value but each adds a full signature pipeline plus an O(n) `Vec::remove(0)` shift per participant in `complete`. Signing cost grows superlinearly while the marginal value recovered is near zero, degrading coordinator/processor throughput for all users' withdrawals batched in the same transaction, or forcing transactions to be abandoned and re-planned.

### Likelihood Explanation
Reachability is high: deposit/forward/change addresses are deterministic functions of the (public) group key via `register_offset`/`p2tr_script_buf`, so anyone can create outputs the scanner will report. Cost to the attacker is ~546 sat plus fees per injected input — small relative to forcing n participants through an extra threshold-signature round each. Persisting "dead" inputs require no further attacker action once on-chain; consolidation requires the multisig itself to spend them, paying the same inflated cost.

### Recommendation
- Bound the input count in `SignableTransaction::new` (well below `MAX_STANDARD_TX_WEIGHT`) and/or impose a minimum per-input value relative to the marginal signature/fee cost, so inputs whose value doesn't cover their marginal cost are excluded ("removed" rather than carried).
- In `TransactionSignatureMachine::complete`, pop shares in O(1) — e.g. iterate `shares` by mutable iterator/`VecDeque` or `swap_remove` with order restoration — instead of `remove(0)` per input.

### Proof of Concept
1. Derive the multisig's external/forward address from the public group key (`external_address`, `forward_address`, `p2tr_script_buf(key + G*offset)`).
2. Broadcast N transactions each creating a 546-sat output to those addresses. Each is emitted by `Scanner::scan_transaction` since `output.balance().amount.0 >= N::DUST` and is under no per-input economic viability check.
3. When the processor builds a spend, it passes the accumulated `Vec<ReceivedOutput>` to `SignableTransaction::new`, which unconditionally converts all of them to inputs (send.rs:175-185).
4. `multisig` constructs N `AlgorithmMachine`s (send.rs:281) and `complete` performs N×(participants) `shares.remove(0)` operations (send.rs:417-419), so each subsequent spend bears O(N²) share-handling work and N full Schnorr ceremonies triggered by outputs worth ~546 sat each — the same disincentivization dynamic as dead `rolloverQueue` entries.

  pub fn multisig(self, keys: &ThresholdKeys<Secp256k1>) -> Option<TransactionMachine> {
    let mut sigs = vec![];
    for i in 0 .. self.tx.input.len() {
      let offset = keys.clone().offset(self.offsets[i]);
      if p2tr_script_buf(offset.group_key())? != self.prevouts[i].script_pubkey {
        None?;
      }

      sigs.push(AlgorithmMachine::new(Schnorr::new(), keys.clone().offset(self.offsets[i])));
    }

    Some(TransactionMachine { tx: self, sigs })
  }

  fn complete(
    mut self,
    mut shares: HashMap<Participant, Self::SignatureShare>,
  ) -> Result<Transaction, FrostError> {
    for (input, schnorr) in self.tx.input.iter_mut().zip(self.sigs.drain(..)) {
      let sig = schnorr.complete(
        shares.iter_mut().map(|(l, shares)| (*l, shares.remove(0))).collect::<HashMap<_, _>>(),

      let mut witness = Witness::new();
      witness.push(sig);
      input.witness = witness;
    }

    Ok(self.tx)
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
