### Title
`ReceivedOutput::read` skips the key/script binding enforced during scanning, allowing forged unspendable outputs - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
Analogous to AnteHandlers that validate in `CheckTx` but skip checks in `DeliverTx`, `Scanner::scan_transaction`/`register_offset` enforce that a `ReceivedOutput`'s `script_pubkey` equals `p2tr(key + offset·G)` with even parity, while `ReceivedOutput::read` — which accepts arbitrary bytes — performs no such validation. A deserialized `ReceivedOutput` is trusted as a wallet output despite carrying an attacker-chosen `offset`, `TxOut`, and `OutPoint`.

### Finding Description
`ReceivedOutput::read` (networks/bitcoin/src/wallet/mod.rs:122-134) reads `offset` via `Secp256k1::read_F`, then consensus-decodes `TxOut` and `OutPoint`, and returns the struct directly:

```rust
pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
  let offset = Secp256k1::read_F(r)?;
  ...
  Ok(ReceivedOutput { offset, output, outpoint })
}
```

By contrast, the legitimate production path binds all three fields cryptographically: `Scanner::register_offset` (mod.rs:180-196) only records an offset if `p2tr_script_buf(key + offset·G)` yields an even-parity key and the script is unclaimed, and `scan_transaction` (mod.rs:199-214) only emits a `ReceivedOutput` when `output.script_pubkey` is present in that map. The "check exists in one mode but not the other" defect mirrors the report's `if !ctx.IsCheckTx() { return next(...) }` — the integrity invariant (`output.script_pubkey == p2tr(key + offset·G)`, parity even, outpoint unique to this output) is enforced on the scan path and silently dropped on the deserialize path.

Downstream, `OutputTrait::key()` (processor/src/networks/bitcoin.rs:112-122) derives the claimed ownership key as `read_G(x_only(script)) - offset·G` and only asserts `script.is_p2tr()`. Since `offset` is attacker-chosen, any P2TR `TxOut` deserializes into an apparently valid `ReceivedOutput` for some derived key. `Output::read` (processor/src/networks/bitcoin.rs:145-166) feeds untrusted bytes straight into `ReceivedOutput::read`, and the result is consumed by the multisig scanner's output accounting (processor/src/multisigs/scanner.rs:562-567, which pushes outputs whose `balance() >= N::DUST`).

### Impact Explanation
An attacker who can feed crafted bytes to `ReceivedOutput::read`/`Output::read` can fabricate a `ReceivedOutput` claiming an arbitrary `TxOut` value at an arbitrary outpoint, reported as belonging to a derived key. This produces "funds reported received that are not spendable": the value field and outpoint are never checked against a real chain output, and the implied tweak (`key() + offset·G == script key`) holds trivially for any input because `key()` is defined by subtraction. It can also synthesize outputs under odd-parity keys or offsets that `register_offset` would have rejected, and collide/forge outpoints that the scan path could never produce.

### Likelihood Explanation
Exploitation requires an attacker to deliver untrusted bytes to a `read` path (e.g., exchanged/exported output records, DB-restored data manipulated before write, or any peer-supplied serialized `Output`). The crypto layer itself supplies no defense because the check was centralized in `Scanner` rather than the type invariant. Where the bytes are attacker-influenced, no witness, signature, or honest cooperation is needed — the forgery is pure deserialization.

### Recommendation
Make the invariant a property of the type rather than the scan path:
- Have `ReceivedOutput::read` (or a checked constructor) take the scanner key and re-verify `self.scripts.get(&output.script_pubkey) == Some(offset)`, or store/verify `p2tr_script_buf(key + offset·G) == output.script_pubkey` with even-parity enforcement.
- Alternatively, reject deserialization entirely (`ReceivedOutput` only constructible via `Scanner`), and have `Output::read` re-derive/validate the binding using the registered offsets (`kinds` map) instead of trusting the serialized offset.

  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
