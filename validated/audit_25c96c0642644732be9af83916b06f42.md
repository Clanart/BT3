### Title
NFT royalty amount truncates to zero for small-value trades, allowing on-chain royalty bypass via trade splitting - (File: chia/wallet/nft_wallet/nft_wallet.py)

### Summary
`compute_royalty_amount` and `NFTWallet.royalty_calculation` compute NFT creator royalties using integer (floor) division against `MAX_ROYALTY_BASIS_POINTS` (10000). For sufficiently small trade amounts relative to the royalty percentage, the computed royalty rounds down to zero, exactly mirroring the `Vault.open_position` fee-bypass pattern in the external report: a percentage-based charge computed via integer division can be driven to zero by using small enough amounts, and a large trade can be split into many small trades to avoid ever paying the fee/royalty.

### Finding Description
The wallet-side royalty computation is: [1](#0-0) 

and the offer-summary royalty calculation used for multiple royalty assets: [2](#0-1) 

Both divide `amount * percentage` by `MAX_ROYALTY_BASIS_POINTS` (10000) using integer division with no minimum-amount guard, so `royalty = 0` whenever `amount * percentage < 10000`. This is explicitly acknowledged as expected behavior in the test suite: [3](#0-2) 

Critically, this is not merely a wallet-convenience quirk — the royalty amount is enforced on-chain by the NFT ownership layer's transfer program via puzzle-announcement assertions (`-10` condition and `ASSERT_PUZZLE_ANNOUNCEMENT`), computed proportionally from the trade price and royalty percentage the same way: [4](#0-3) 

Because the on-chain enforcement is also proportional (percentage × trade price), a buyer/seller pair can structure an NFT sale as many small notarized payments (e.g., splitting a large fungible-asset trade price across several small `trade_prices_list` entries or across many royalty-enabled NFT legs in one offer) such that each individual computed royalty rounds down to zero: [5](#0-4) [6](#0-5) 

The code even explicitly filters out trade prices whose computed royalty is zero when building `trade_prices_list`, and skips creating royalty payout coins entirely when the summed royalty is zero: [7](#0-6) 

There is no lower bound imposed anywhere on the trade price, offered/requested fungible amount, or on `royalty_split`, so this path is fully reachable by any unprivileged offer maker/taker constructing their own `offer_dict` amounts via the wallet RPC (`create_offer_for_ids` / `respond_to_offer` / `take_offer`).

### Impact Explanation
An NFT creator's royalty is a value the on-chain ownership-layer puzzle is designed to enforce whenever an NFT with a non-zero royalty percentage changes hands for a fungible asset. By splitting a sale into small enough increments (or offering NFTs against a large number of tiny fungible-asset legs), a counterparty can complete NFT trades while paying zero royalty, defeating the intended on-chain royalty-enforcement mechanism. This is a direct value-extraction/economic-bypass issue analogous to the reported fee bypass: the creator loses expected royalty income with no consensus-level minimum-amount safeguard preventing it.

### Likelihood Explanation
Any wallet user or offer counterparty can freely choose the amounts in an offer (`offer_dict`) they construct via `create_offer_for_ids`/`respond_to_offer`, including splitting large trades into many sub-trade-price legs. No special privileges, signatures, or trusted roles are required — this is purely a matter of choosing offer amounts, making the likelihood high for any economically motivated buyer/seller wishing to avoid royalties.

### Recommendation
Introduce a minimum trade-price/royalty-amount enforcement: either round up (ceiling division) instead of floor division when computing royalty amounts, or reject/require a minimum trade amount such that `amount * percentage // MAX_ROYALTY_BASIS_POINTS` cannot be zero for any non-zero `percentage`, both in `compute_royalty_amount`/`royalty_calculation` and in the on-chain transfer-program royalty computation the ownership layer enforces, so it cannot be trivially bypassed by amount-splitting.

### Proof of Concept
1. NFT is minted with a non-zero `royalty_percentage` (e.g., 100 basis points = 1%) via `create_ownership_layer_puzzle`.
2. A buyer structures an offer/take-offer such that the fungible trade-price leg attributed to that NFT is small (e.g., `amount = 50`), or splits a large purchase (e.g. amount 5000) into 100 separate offers of amount 50 each.
3. `compute_royalty_amount(offered_amount=-50, royalty_split=1, percentage=100)` (or the equivalent on-chain transfer-program computation) returns `0`, as verified by `test_small_amount_truncates_to_zero` in `chia/_tests/wallet/nft_wallet/test_nft_royalty.py`.
4. Because `royalty_payments`/`trade_prices_list` filter out zero-value royalty entries (`chia/wallet/nft_wallet/nft_wallet.py:1027-1046`), no royalty coin is created or announced, and the on-chain ownership-layer puzzle assertion is satisfied without any royalty payment.
5. Repeating this across many small trades lets the buyer accumulate the full NFT purchase amount while paying zero cumulative royalty to the creator, versus paying the full royalty if done in one large trade.

```python
def compute_royalty_amount(offered_amount: int, royalty_split: int, percentage: int) -> uint64:
    """Compute royalty using integer arithmetic, validating against overflow and excessive percentage."""
    if percentage > MAX_ROYALTY_BASIS_POINTS:
        raise ValueError(f"NFT royalty percentage {percentage} exceeds 100% ({MAX_ROYALTY_BASIS_POINTS} basis points)")
    amount = abs(offered_amount) // royalty_split * percentage // MAX_ROYALTY_BASIS_POINTS
    royalty = uint64(amount)
    if royalty >= abs(offered_amount):
        raise ValueError("Royalty amount meets or exceeds the offered amount")
    return royalty
```

```python
    def royalty_calculation(
        royalty_assets_dict: dict[Any, tuple[Any, uint16]],
        fungible_asset_dict: dict[Any, uint64],
    ) -> dict[Any, list[dict[str, Any]]]:
        summary_dict: dict[Any, list[dict[str, Any]]] = {}
        for id, royalty_info in royalty_assets_dict.items():
            address, percentage = royalty_info
            summary_dict[id] = []
            for name, amount in fungible_asset_dict.items():

                    {
                        "asset": name,
                        "address": address,
                        "amount": abs(amount) // len(royalty_assets_dict) * percentage // MAX_ROYALTY_BASIS_POINTS,
                    }
                )

        return summary_dict
```
