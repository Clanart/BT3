`Scanner::scan_block` credits immature coinbase outputs as spendable funds — (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The external report describes an operation classified as "read" that actually performs a state-changing write, letting a low-privilege caller trigger effects reserved for higher privilege. The analog in Serai's in-scope code is a "read" API (`Scanner::scan_block`) that produces a state-affecting result — crediting a received output — for funds the protocol cannot actually move: outputs of the block's coinbase transaction, which Bitcoin consensus forbids spending until 100 confirmations deep. An unprivileged miner (a fully public-input party — they merely publish a block) can pay the multisig's script inside the coinbase and cause Serai to record funds that are not spendable.

### Finding Description
`Scanner::scan_transaction` at `networks/bitcoin/src/wallet/mod.rs:199-214` matches outputs solely on `output.script_pubkey` against its registered `scripts` map, emitting a `ReceivedOutput` for every match. `Scanner::scan_block` at `networks/bitcoin/src/wallet/mod.rs:221-227` iterates `block.txdata` **including index 0**, the coinbase transaction:

```rust
for tx in &block.txdata {
  res.extend(self.scan_transaction(tx));
}
```

Bitcoin consensus rules make coinbase outputs unspendable for `COINBASE_MATURITY = 100` blocks. The scanner performs no check that a matched outpoint is mature, nor that the containing transaction is a coinbase. The doc comment acknowledges this ("This will also scan the coinbase transaction which is bound by maturity. If received outputs must be immediately spendable, a post-processing pass is needed"), but the responsibility is pushed to every caller, and the processor-side scan path (`processor/src/multisigs/scanner.rs`) consumes `get_outputs` results as credited outputs without visible maturity filtering at the `Scanner` level.

The bug-class mapping: a nominally read-only operation (`scan_block`, `&self`, returns data) performs the effective "write" of crediting a balance — exactly the read-disguised-as-write misclassification from the report, where the write (minting a runner token / crediting an unspendable deposit) is reachable by a party holding only read-level capability.

### Impact Explanation
Any miner (or anyone whose coinbase lands in a scanned block) can send funds to the multisig's P2TR script via the coinbase transaction. The output is reported as received. If downstream code builds a `SignableTransaction` spending that `ReceivedOutput`, `Prevouts::All` commits to it and the resulting transaction is consensus-invalid (`bad-txns-premature-spend-of-coinbase`), or worse, accounting treats unmovable funds as available balance. This yields "funds reported received that are not spendable" — a concrete acceptance criterion — and can stall signing batches built over the immature input.

### Likelihood Explanation
A miner need only include a P2TR output paying the (publicly known) group key's script in their coinbase — no keys, collusion, or privileged access required; it is a normal, consensus-valid block. Reachability is high whenever the scanner processes blocks containing such a payment. Impact is bounded (the funds do become spendable after maturity, and honest payers rarely use coinbase outputs for deposits), justifying Medium.

### Recommendation
In `Scanner::scan_block` (`networks/bitcoin/src/wallet/mod.rs`), skip `block.txdata[0]` — i.e., iterate `block.txdata[1 ..]` — or have the scanner return coinbase outputs tagged as immature so callers cannot treat them as spendable, rather than relying on an out-of-band documented post-processing pass. Alternatively, thread the block height through `ReceivedOutput` so maturity can be enforced at the spend-construction site.

let script = p2tr_script_buf(key).unwrap();
let coinbase = Transaction {
  input: vec![TxIn {
    previous_output: OutPoint::null(),
    ..Default::default()
  }],
  output: vec![TxOut {

    value: Amount::from_sat(100_000),
  }],
  ..Default::default()

let scanner = Scanner::new(key).unwrap();

assert_eq!(outputs.len(), 1);
