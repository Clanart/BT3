### Title
Deserialized `SchnorrAggregate` with zero `Rs` verifies as a valid signature - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::read` accepts a serialized aggregate whose length field is `0`, producing `SchnorrAggregate { Rs: [], s }`, and `SchnorrAggregate::verify` does not reject this degenerate case. When `keys_and_challenges` is empty, the multiexponentiation reduces to the single pair `(-s, G)`, so an attacker-supplied aggregate with `Rs: []` and `s: 0` returns `true` from `verify` — a forged aggregate signature that validates even though `SchnorrAggregator::complete` explicitly refuses to produce empty aggregates.

### Finding Description
This is the direct analog of the kernel bug class: a code path applies its full verification setup to an absent/empty input without special-casing it (the kernel set up an `iov_iter` for `data = NULL` silencing; here `verify` runs the aggregation-weight/multiexp machinery for a zero-signer aggregate).

`SchnorrAggregate::read` reads a `u32` count and pushes that many points with no lower-bound check: [1](#0-0) 

`verify` only checks `self.Rs.len() != keys_and_challenges.len()`; for an empty expected set the loop body never executes and only `(-self.s, C::generator())` is pushed to `pairs`: [2](#0-1) 

`multiexp_vartime` with one pair returns `pairs[0].1 * pairs[0].0`, which is the identity iff `s == 0`: [3](#0-2) 

Crucially, the honest producer side treats the empty case as an error — `SchnorrAggregator::complete` returns `None` when `self.sigs.is_empty()`: [4](#0-3) 

So an empty aggregate is a value that can never be honestly produced, yet is accepted by the deserializer and verifier. Additionally, because the first queued/iterated statement in this scheme uses a fixed path (`weight` is derived from the transcript regardless), the degenerate case gives the attacker a trivially satisfiable equation `s·G == 0` with no signer-bound terms at all.

### Impact Explanation
An unprivileged party who can feed attacker-controlled bytes into `SchnorrAggregate::read` and have the result passed to `verify` obtains a forged "aggregate signature" for any `dst` whenever the caller's expected `keys_and_challenges` list is empty (e.g., a membership/attestation check where the signer set is itself derived from untrusted data, or a code path that treats `verify == true` as "all listed signers signed"). The verifier formula is therefore incorrect at the boundary: it proves `0·G == 0`, asserting nothing about any key, yet reports success.

### Likelihood Explanation
Reachable entirely through public input: `SchnorrAggregate::read` is a `pub` deserialization entry point over raw bytes, and `verify` takes only public data (`dst`, keys, challenges). No malicious-validator, collusion, or leaked-key assumptions are needed — just a caller that deserializes an aggregate from untrusted input and verifies it against a list that can be empty.

### Recommendation
Reject empty aggregates at the trust boundary: in `SchnorrAggregate::read`, error when `u32::from_le_bytes(len) == 0` (mirroring `SchnorrAggregator::complete`'s `None` on empty), and/or return `false` early in `verify` when `keys_and_challenges.is_empty()`. Optionally also cap `len` before allocation to bound the `vec` growth for large declared counts.

  pub fn verify(&self, dst: &'static [u8], keys_and_challenges: &[(C::G, C::F)]) -> bool {
    if self.Rs.len() != keys_and_challenges.len() {
      return false;
    }

    let mut digest = DigestTranscript::<C::H>::new(dst);
    digest.domain_separate(b"signatures");
    for (_, challenge) in keys_and_challenges {
      digest.append_message(b"challenge", challenge.to_repr());
    }

    let mut pairs = Vec::with_capacity((2 * keys_and_challenges.len()) + 1);
    for (i, (key, challenge)) in keys_and_challenges.iter().enumerate() {
      let z = weight(&mut digest);
      pairs.push((z, self.Rs[i]));
      pairs.push((z * challenge, *key));
    }
    pairs.push((-self.s, C::generator()));
    multiexp_vartime(&pairs).is_identity().into()
  }

pub fn multiexp_vartime<G: Group<Scalar: PrimeFieldBits>>(pairs: &[(G::Scalar, G)]) -> G {
  match algorithm(pairs.len()) {
    Algorithm::Null => Group::identity(),
    Algorithm::Single => pairs[0].1 * pairs[0].0,
    Algorithm::Straus(window) => straus_vartime(pairs, window),
    Algorithm::Pippenger(window) => pippenger_vartime(pairs, window),
  }
