### Title
Forged `ReceivedOutput` deserializes into a signed transaction spending a nonexistent UTXO - ([File: networks/bitcoin/src/wallet/mod.rs])

### Summary
High. `ReceivedOutput::read` accepts the spending offset, `TxOut`, and `OutPoint` as three independent attacker-controlled fields without proving that the outpoint exists, contains the supplied output, or was discovered by `Scanner`. A crafted serialized `ReceivedOutput` can therefore inject a fake UTXO into transaction construction and cause the threshold wallet to sign a transaction spending bytes that do not correspond to any spendable chain output.

### Finding Description
`ReceivedOutput::read` deserializes `offset` with `Secp256k1::read_F`, then independently consensus-decodes `output` and `outpoint`, and returns all three without checking their relationship to an actual transaction or to the scanner key [1](#0-0) . Legitimate construction through `Scanner::scan_transaction` establishes this missing invariant by only creating an `OutPoint` from the transaction ID and index of an output whose `script_pubkey` is registered to the scanner [2](#0-1) . `SignableTransaction::new` trusts the embedded `outpoint` as the transaction input and the embedded `TxOut` as the prevout data [3](#0-2) . During signing, `multisig` only checks that the serialized prevout’s `script_pubkey` matches the offset group key; it does not verify that the referenced outpoint exists or contained that script [4](#0-3) . The resulting input is signed with `Prevouts::All`, and completion installs the produced Schnorr signature into the input witness [5](#0-4) [6](#0-5) .

### Impact Explanation
An attacker who can feed serialized bytes to `ReceivedOutput::read` can make the wallet report or consume a `ReceivedOutput` for funds that are not spendable. By selecting an offset that makes the group key even and setting the fake `TxOut` to the corresponding P2TR script, the forged object passes `multisig`’s script check and induces a valid threshold signature over a transaction referencing a nonexistent or unrelated outpoint. Any accounting or automation that treats the parsed output as wallet-controlled value can credit nonexistent funds; any signing pipeline will emit a transaction that consensus rejects only after the signing ceremony has occurred.

### Likelihood Explanation
Exploitation requires an application boundary where attacker-controlled serialized `ReceivedOutput` values are accepted rather than outputs produced directly by `Scanner`. No private key, malformed curve encoding, malicious validator set, or protocol collusion is needed. The attacker only needs the target group key, which is public, and can choose an offset such that `p2tr_script_buf(key + offset * G)` succeeds.

### Recommendation
Do not deserialize `ReceivedOutput` as an authorization-bearing wallet object across trust boundaries. Either authenticate serialized outputs as trusted scanner state, or revalidate them against the chain before use: fetch the transaction identified by `outpoint.txid`, confirm `vout` is in bounds, compare the actual `TxOut` byte-for-byte with the stored `TxOut`, and verify the script corresponds to `key + offset * G`. Store the scanner-derived provenance or a commitment to the confirmed transaction in the object so parsing cannot combine an arbitrary offset, output, and outpoint.

### Proof of Concept
Conceptual bytes supplied to `ReceivedOutput::read`:

```rust
use bitcoin::{absolute::LockTime, transaction::Version, OutPoint, TxOut, Amount, Txid};
use bitcoin::hashes::Hash;
use k256::{ProjectivePoint, Scalar};
use bitcoin_serai::wallet::{p2tr_script_buf, ReceivedOutput};

// Public victim group key.
let group_key: ProjectivePoint = victim_group_key();

// Find a public offset producing an even Taproot key.
let mut offset = Scalar::ZERO;
let script = loop {
  if let Some(script) =
    p2tr_script_buf(group_key + (ProjectivePoint::GENERATOR * offset))
  {
    break script;
  }
  offset += Scalar::ONE;
};

let fake_txout = TxOut {
  value: Amount::from_sat(1_000_000),
  script_pubkey: script,
};

let fake_outpoint = OutPoint {
  txid: Txid::all_zeros(), // Or any other nonexistent TXID.
  vout: 0,
};

// Serialize offset || consensus TxOut || consensus OutPoint and feed it to:
let forged = ReceivedOutput::read(&mut forged_bytes.as_slice()).unwrap();
```

`SignableTransaction::new(vec![forged], payments, change, None, fee_rate)` uses `fake_outpoint` as an input and `fake_txout` as its prevout. `multisig` then passes because the supplied script was deliberately constructed from the victim’s public offset key, and `complete` produces a fully witnessed transaction spending `TXID:0`. That output was never created, so the reported funds are not spendable despite the wallet producing a signature for the spend.
