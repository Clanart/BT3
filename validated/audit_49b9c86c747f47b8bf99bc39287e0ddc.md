### Title
Out-of-bounds atom length-prefix read in CLVM canonical-encoding check causes mempool spend-bundle processing to crash - (File: chia/full_node/mempool_manager.py)

### Summary
`is_atom_canonical()` and its caller `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` parse a serialized CLVM atom's variable-length size prefix (1–6 bytes) directly out of `clvm_buffer` without ever checking that the prefix bytes it reads, or the atom length it computes, actually fit inside the buffer that was captured/received. This mirrors the Wireshark AirPDcapPacketProcess flaw: a length field is trusted and used to advance/copy without validating it against the true remaining buffer size.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads `clvm_buffer[offset]` to get the atom tag, decides a `prefix_len` (0–5 additional bytes) based on the top bits of that tag, and then loops `prefix_len` times indexing further into the buffer to accumulate `atom_len`: [1](#0-0) 

None of this code checks `offset + prefix_len` against `len(clvm_buffer)` before indexing, nor does it check that the resulting `atom_len` fits within the remaining bytes of the buffer. The caller, `is_clvm_canonical()`, walks the same buffer token-by-token and calls `is_atom_canonical()` at each atom boundary, then advances `offset += atom_len` and continues the loop assuming the returned `atom_len` is trustworthy relative to buffer bounds: [2](#0-1) 

Per `.cursor/context/clvm-execution.md`, this canonical-encoding check is invoked on solution bytes to gate DEDUP eligibility for a submitted spend bundle:


Because a crafted, truncated, or malformed atom length prefix (e.g., a `0xFC`/`0xFB`-class prefix claiming a 5-byte length field near the end of the buffer, or an `atom_len` that exceeds the remaining bytes) causes `clvm_buffer[offset]` indexing to read past the end of `bytes`, Python raises an `IndexError`. In C, the analogous unchecked length-vs-capture mismatch produced a stack buffer overflow/crash (CVE-2015-8723); in this Python code the same missing bounds validation produces an unhandled exception during untrusted-input parsing, which is the type-safe equivalent failure mode.

### Impact Explanation
If the `IndexError` raised out of `is_clvm_canonical()`/`is_atom_canonical()` is not caught somewhere up the call stack of the mempool's spend-bundle admission pipeline, a single unprivileged spend-bundle submitter can trigger an unhandled exception during transaction processing, halting or crashing the code path that evaluates that mempool item (a spend-triggered transaction-processing halt). This is reachable purely from mempool admission of an attacker-crafted spend bundle solution, with no special privileges required.

### Likelihood Explanation
The precondition is straightforward for an attacker to construct: any spend bundle solution whose CLVM serialization contains an atom near the end of the buffer with a multi-byte length prefix, where the encoded length or the prefix itself overruns the buffer, will drive the unchecked indexing past the buffer end. Because the DEDUP-eligibility canonical check runs on attacker-supplied solution bytes during standard mempool processing, likelihood of the malformed input reaching this code is high; the remaining variable is whether an enclosing exception handler in the mempool pipeline suppresses the `IndexError` before it can cause a processing halt, which could not be confirmed from the inspected code and would require tracing every caller of `is_clvm_canonical()`.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before indexing `clvm_buffer` for the prefix bytes (verify `offset + 1 + prefix_len <= len(clvm_buffer)`) and validate that `atom_len` does not exceed the remaining buffer length before returning it to `is_clvm_canonical()`, raising a well-defined, caught error (e.g., treat as non-canonical / reject the spend) rather than allowing an `IndexError` to propagate. Ensure `is_clvm_canonical()` and any callers processing untrusted solution bytes wrap this parsing in a try/except that converts out-of-bounds conditions into a mempool rejection rather than crashing the caller.

### Proof of Concept
Construct a CLVM solution buffer ending in a truncated multi-byte atom length prefix, for example a single trailing byte `0xF8` (which signals a 5-byte length prefix per the `0b11111000` case) with no following bytes, and submit a spend bundle whose solution serializes to this buffer. When `is_clvm_canonical()` is invoked on this buffer (as part of DEDUP-eligibility evaluation), `is_atom_canonical()` will attempt to index `clvm_buffer[offset+1]` through `clvm_buffer[offset+5]`, which are past the end of the buffer, raising an uncaught `IndexError` during processing of the submitted spend bundle.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
