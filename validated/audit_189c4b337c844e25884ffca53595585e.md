### Title
Malicious/MITM git remote can spoof `WWW-Authenticate: realm="GitHub"` to trigger GitHub Enterprise sign-in flow for an attacker-controlled endpoint, exfiltrating the user's GitHub credential/token to that endpoint - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
The credential-helper trampoline decides whether a remote host "is GitHub" partly by trusting a `WWW-Authenticate` header value forwarded by Git from the remote server itself. A malicious or MITM'd git remote can set `realm="GitHub"` in its 401 response to make Desktop classify an arbitrary, attacker-controlled endpoint as an "enterprise" GitHub host, causing Desktop to launch its real GitHub Enterprise sign-in UI against that attacker endpoint. Any credential/PAT/OAuth token the user completes that sign-in with is then handed back to `git` as the credential for that remote and sent to the attacker's server.

### Finding Description
`getEndpointKind` in [1](#0-0)  classifies a remote endpoint by inspecting `wwwauth[]` entries taken directly from the credential input, which originates from Git's parsing of the actual HTTP response headers sent by the remote server: [2](#0-1) 

If the value contains `realm="GitHub"`, the endpoint is trusted and returned as `'enterprise'` with no further verification (no TLS/cert check, no call to the real GitHub API, no comparison against known GitHub Enterprise endpoints). This value is fully attacker-controlled: any git server (a repo the user added as a remote, a MITM proxy, or a compromised mirror) can return this header on an authentication challenge.

In `getCredential`, once `endpointKind !== 'generic'` and no existing account matches that endpoint, the trampoline calls `ui.promptForGitHubSignIn(endpoint)`: [3](#0-2) 

`promptForGitHubSignIn` then launches the real "Enterprise sign-in" flow, setting the sign-in endpoint to the attacker's origin and showing the credential-helper sign-in dialog: [4](#0-3) 

The resulting `Account` (containing `login`/`token`) is merged back into the git credential via `credWithAccount` and returned to Git as `formatCredential(cred)`: [5](#0-4) [6](#0-5) 

Because Git then uses that credential to authenticate to the same remote/endpoint that produced the spoofed header, the token ends up being sent straight to the attacker-controlled server.

The only competing check, `isGitHubHost(endpoint)` (an actual network validation against the real GitHub API), is only reached as a fallback **after** the `wwwauth` heuristic — the spoofed header short-circuits it entirely, so the "guard" that would normally catch this never runs.

### Impact Explanation
This satisfies the "unauthorized OAuth or account binding" / "credential exfiltration" categories: the attacker is the remote/server the user is interacting with (a cloned/fetched repo's origin, or a MITM proxy sitting on a legitimate-looking HTTPS remote), they never need local access or existing credentials, and the outcome is that Desktop performs a full "Sign in to GitHub Enterprise" ceremony bound to the attacker's endpoint and then forwards the resulting token/credential to that same attacker endpoint via the git credential protocol. A user who has never configured that URL as an actual GitHub Enterprise instance can be tricked into typing/authorizing credentials that get sent to the attacker.

### Likelihood Explanation
Likelihood is moderate: it requires the victim to perform a git operation (fetch/push/clone) against a remote controlled or intercepted by the attacker that challenges with HTTP 401 and a spoofed `WWW-Authenticate` header, and the victim must not already have an account registered for that exact endpoint (a common case for a "new"/unknown remote). No special git server compromise is needed beyond the attacker's own repo host returning a crafted header, which is trivial to configure.

### Recommendation
Do not trust the `wwwauth[]` realm string alone to classify a host as GitHub. Require an authoritative check (e.g., always fall through to the real `isGitHubHost()` API-based verification, or check that the header's origin matches a known/pinned GitHub Enterprise endpoint) before offering the GitHub Enterprise sign-in flow, and surface the true destination host prominently in the sign-in dialog so users can detect endpoint spoofing.

### Proof of Concept
1. Attacker hosts a git server (or MITM proxy) at `https://evil.example.com/foo.git` and adds it as a remote the victim clones/fetches from.
2. On the HTTP Basic auth challenge, the server responds with `WWW-Authenticate: Basic realm="GitHub"`.
3. Git forwards this as a `wwwauth[]=...realm="GitHub"...` line to Desktop's credential helper (`get` command) via [7](#0-6) .
4. `getEndpointKind` matches the regex on line 161 and returns `'enterprise'` without any further validation.
5. Since the victim has no account bound to `evil.example.com`, `getCredential` calls `ui.promptForGitHubSignIn('https://evil.example.com')`, which opens Desktop's genuine "Sign in to GitHub Enterprise" dialog targeting that origin.
6. Victim completes sign-in (PAT entry or OAuth) believing it's a legitimate enterprise prompt tied to their fetch/clone action.
7. The resulting token is merged into the credential and returned to Git, which sends it directly to `evil.example.com` to complete authentication — exfiltrating the token to the attacker.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

export const createCredentialHelperTrampolineHandler: (

) => TrampolineCommandHandler = (store: Store) => async command => {
  const firstParameter = command.parameters.at(0)
  if (!firstParameter) {
    return undefined
  }

  const { trampolineToken: token } = command
  const input = parseCredential(command.stdin)

  if (__DEV__) {
    debug(
      `${firstParameter}\n${command.stdin
        .replaceAll(/^password=.*$/gm, 'password=***')
        .replaceAll(/^(.*)$/gm, '  $1')
        .trimEnd()}`
    )
  }

  try {
    if (firstParameter === 'get') {
      const cred = await getCredential(input, store, token)
      if (!cred) {
        const endpoint = `${getCredentialUrl(input)}`
        info(`could not find credential for ${endpoint}`)
        setHasRejectedCredentialsForEndpoint(token, endpoint)
      }
      return cred ? formatCredential(cred) : undefined

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
