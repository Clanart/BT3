### Title
Flash-loan stake capture of instantly-distributed BaseRewardPool yield via permissionless `harvest()` - ([File: rewards/BaseRewardPool.sol], [File: wombat/WombatPoolHelper.sol], [File: wombat/WombatStaking.sol])

### Summary
`BaseRewardPool` distributes newly harvested WOM/bonus rewards by immediately bumping `rewardPerTokenStored` in proportion to the *current* `totalStaked()`, with no time-weighting, streaming, or lock. Because `WombatPoolHelper.harvest()` → `WombatStaking.harvest()` is fully permissionless and unstaking is possible in the very next call, any unprivileged wallet can flash-stake immediately before triggering a harvest, capture a large share of the freshly queued rewards, and withdraw again — the same "flash loan stake" bug class described in the RUSH1-7 report, applied here to reward yield instead of an LP fee.

### Finding Description
`_provisionReward` in `BaseRewardPool` updates the global accumulator in a single shot based on the staked amount at the moment the reward is queued: [1](#0-0) 

`rewardPerToken()` simply returns this stored accumulator (no time-based streaming/vesting): [2](#0-1) 

and `earned()` computes a user's share purely from their current `balanceOf()` multiplied by the accumulator delta since their last checkpoint: [3](#0-2) 

Any wallet can trigger a harvest of pending WOM rewards for a pool without any privilege check: [4](#0-3) [5](#0-4) 

which flows into `_toMasterWomAndSendReward` → `_sendRewards` → `queueNewRewards`, instantly crediting `rewardPerTokenStored` based on whatever `totalStaked()` is at that exact block: [6](#0-5) [7](#0-6) 

`totalStaked()` is read live from the operator's staking-token balance, and `balanceOf()` is read live from `MasterMagpie`'s stored user amount — both are instantaneous, unlocked values: [8](#0-7) 

`MasterMagpie._deposit`/`_withdraw` have no minimum holding period, cooldown, or same-block restriction, so a user can stake, trigger the harvest, and withdraw in the same transaction (each call is a separate, non-nested external call, so the `nonReentrant` guard on each of `deposit`/`withdraw` does not prevent this sequence): [9](#0-8) [10](#0-9) 

This is the exact bug-class analog of the RUSH1-7 report: the LiquidityPool fee/reward is delivered as an immediate, unlocked balance-based accrual (there, WETH transferred directly to an ERC4626 vault; here, an instant `rewardPerTokenStored` bump), letting a large, momentary depositor free-ride on yield meant for long-term stakers.

### Impact Explanation
An attacker can:
1. Flash-loan or otherwise acquire a large amount of the pool's `depositToken`/LP token.
2. Call `WombatPoolHelper.deposit()`/`depositLP()` to become the overwhelming majority of `totalStaked()` for that pool's receipt token in `MasterMagpie`.
3. Call the permissionless `WombatPoolHelper.harvest()`, which harvests pending WOM (and bonus tokens) from `MasterWombat` and immediately distributes them via `queueNewRewards`, spiking `rewardPerTokenStored` proportional to the attacker's now-dominant share.
4. Immediately call `WombatPoolHelper.withdraw()`, which internally calls `MasterMagpie.withdrawFor` → `_harvestAndUnstake` → `_harvestBaseRewarder`, realizing (crediting to `userRewards`) the attacker's inflated share of the just-queued reward before unstaking.
5. Repay the flash loan, having captured yield that legitimate long-term liquidity providers/stakers would otherwise have earned.

This is a direct theft of unclaimed yield from honest stakers, diluting their expected rewards without contributing any real time-weighted stake — matching the "concrete direct theft of... unclaimed yield" acceptance criterion.

### Likelihood Explanation
High. `harvest()` requires no privilege beyond the pool being active, deposit/withdraw functions have no lock or cooldown, and pending WOM rewards accrue continuously in `MasterWombat`, so there is regularly a non-trivial pending-reward balance available to "steal" at any time an attacker chooses to time their flash stake. The attack is executable atomically within a single transaction by any unprivileged wallet with access to a flash-loanable form of the relevant deposit/LP token.

### Recommendation
Do not allow instantaneous stake-then-harvest-then-withdraw to capture rewards. Options: (a) stream newly queued rewards over a duration (rewardRate/rewardsDuration model) rather than crediting them to `rewardPerTokenStored` in one shot; (b) enforce a minimum holding period / disallow deposit-then-withdraw within the same block for `MasterMagpie`/`WombatPoolHelper`; or (c) checkpoint stakers' weighted average balance over time rather than using the instantaneous `balanceOf()`/`totalStaked()` snapshot when crediting rewards.

### Proof of Concept
Conceptual sequence (single attacker transaction/contract):
1. `flashLoan(depositToken, hugeAmount)`
2. `WombatPoolHelper(pool).deposit(hugeAmount, minLiquidity)` → attacker's stake dominates `totalStaked()` in `MasterMagpie` for that pool.
3. `WombatPoolHelper(pool).harvest()` → `WombatStaking.harvest(lpToken)` → `_toMasterWomAndSendReward` withdraws 0 lpAmount but triggers `MasterWombat` harvest, realizing pending WOM, then `_sendRewards` calls `IBaseRewardPool(rewarder).queueNewRewards(womAmount, wom)`, which runs `_provisionReward`, bumping `rewardPerTokenStored` by `(womAmount * 10**stakingDecimals) / totalStaked()` where `totalStaked()` is now dominated by the attacker's flash stake.
4. `WombatPoolHelper(pool).withdraw(hugeAmount, minAmount)` → `MasterMagpie.withdrawFor` → `_harvestBaseRewarder` calls `getReward`, transferring the attacker's `earned()` share (majority of the just-queued WOM) to the attacker, then unstakes.
5. Repay flash loan; net profit = captured WOM reward minus flash-loan fee, at the expense of long-term stakers who now see a lower `rewardPerTokenStored` delta going forward relative to what they should have earned from that harvest.

Note: I was not able to execute this against a live fork/test environment (no filesystem/terminal access in this mode) to empirically confirm gas/slippage economics or exact numeric magnitude of extractable reward per harvest cycle; the mechanism itself, however, is directly verifiable from the cited contract logic.

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (this.totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingDecimals()) /
                this.totalStaked();
        }

    /// @notice Send rewards to the rewarders
    /// @param _rewardToken the address of the reward token to send
    /// @param _rewarder the rewarder that will get the rewards
    /// @param _amount the initial amount of rewards after harvest

    function _sendRewards(
        address _lpToken,
        address _rewardToken,
        address _rewarder,
        uint256 _amount
    ) internal {
        if (_amount == 0) return;
        uint256 originalRewardAmount = _amount;

        if (!isPoolFeeFree[_lpToken]) {
            for (uint256 i = 0; i < feeInfos.length; i++) {
                Fees storage feeInfo = feeInfos[i];

                if (feeInfo.isActive) {
                    address rewardToken = _rewardToken;
                    uint256 feeAmount = (originalRewardAmount * feeInfo.value) / DENOMINATOR;
                    _amount -= feeAmount;
                    uint256 feeTosend = feeAmount;

                    if (feeInfo.isMWOM && rewardToken == wom) {
                        if (smartWomConverter != address(0)) {
                            IERC20(wom).safeApprove(smartWomConverter, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IConverter(smartWomConverter).smartConvert(feeAmount, 0);
                            rewardToken = mWom;
                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
                        } else {
                            IERC20(wom).safeApprove(mWom, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IMWom(mWom).deposit(feeAmount);
                            rewardToken = mWom;
                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
                        }
                    }

                    if (!feeInfo.isAddress) {
                        IERC20(rewardToken).safeApprove(feeInfo.to, 0);
                        IERC20(rewardToken).safeApprove(feeInfo.to, feeTosend);
                        IBaseRewardPool(feeInfo.to).queueNewRewards(feeTosend, rewardToken);
                    } else {
                        IERC20(rewardToken).safeTransfer(feeInfo.to, feeTosend);
                        emit RewardPaidTo(feeInfo.to, rewardToken, feeTosend);
                    }
                }
            }
        }

        IERC20(_rewardToken).safeApprove(_rewarder, 0);
        IERC20(_rewardToken).safeApprove(_rewarder, _amount);
        IBaseRewardPool(_rewarder).queueNewRewards(_amount, _rewardToken);

    function _deposit(address _stakingToken, address _account, uint256 _amount, bool _isVlmgp) internal {
        updatePool(_stakingToken);

        PoolInfo storage pool = tokenToPoolInfo[_stakingToken];
        UserInfo storage user = userInfo[_stakingToken][_account];

        if (user.amount > 0) {
            _harvestMGP(_stakingToken, _account);
        }
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount + _amount;
        if (!_isVlmgp) {
            user.available = user.available + _amount;
            IERC20(pool.stakingToken).safeTransferFrom(address(msg.sender), address(this), _amount);
        }
        user.rewardDebt = (user.amount * pool.accMGPPerShare) / 1e12;

        if (_amount > 0)
            if (!_isVlmgp)
                emit Deposit(_account, _stakingToken, _amount);
            else
                emit DepositNotAvailable(_account, _stakingToken, _amount);
    }

    /// @notice internal function to deal with withdraw staking token
    function _withdraw(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
