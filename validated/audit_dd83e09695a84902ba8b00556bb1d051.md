### Title
Quadratic Lagrange interpolation in `ThresholdKeys::new` via attacker-controlled participant count enables CPU-exhaustion DoS — (File: crypto/dkg/src/lib.rs)

### Summary
`ThresholdKeys::read` deserializes an attacker-controlled `n` (u16) and `t`, then calls `ThresholdKeys::new`, which computes the group key by evaluating `interpolation_factor` for every participant `1..=t`. Under `Interpolation::Lagrange`, each `interpolation_factor` call iterates over all `t` included participants and performs a field inversion, making group-key derivation `O(t²)` field operations plus `t` inversions and `n` scalar-point multiplications — for an input whose size is only `O(n)` bytes. This is the same amplification shape as GraphQL field duplication: a small attacker-declared count multiplies redundant work across every element.

### Finding Description
In `ThresholdKeys::read` (`crypto/dkg/src/lib.rs:591-632`), `t` and `n` are read as raw u16s from the byte stream and `n` verification shares are read — so a ~4 MB input can declare `n = t = 65535`. `ThresholdKeys::new` (`crypto/dkg/src/lib.rs:376-378`) then builds `t = 1..=params.t()` and computes `group_key` as a sum of `verification_shares[i] * interpolation.interpolation_factor(*i, &t)`. With `Interpolation::Lagrange`, `interpolation_factor` (`crypto/dkg/src/lib.rs:229-247`) loops over every participant in `included`, performing field multiplications and a `denom.invert().unwrap()` per call. Total cost is `t²` field multiplications, `t` field inversions, and `t` point-scalar multiplications — roughly 4.3×10⁹ field ops plus 65k inversions and 65k point muls for a single ~4 MB malicious blob. Because the check `verification_shares.len() == n` requires the attacker to actually supply the points, the read itself is linear, but the post-deserialization computation is quadratic — exactly the "duplicate fields to multiply work" primitive from the Directus report.

### Impact Explanation
An unprivileged party who can feed serialized `ThresholdKeys` bytes to `ThresholdKeys::read` (or equivalently cause `ThresholdKeys::new` to run over an attacker-shaped `ThresholdParams`/`verification_shares` map, e.g. via untrusted key material in a re-share/promotion flow) can burn seconds-to-minutes of CPU per request while the node remains synchronously occupied in `group_key` derivation. Repeating the request sustains the denial of service, matching the availability impact class of GHSA-7hmh-pfrp-vcx4. No secret material is required; the payload is entirely public scalars and points.

### Likelihood Explanation
Reachability depends on a caller passing untrusted bytes to `ThresholdKeys::read`; the format is self-describing (curve ID + t/n/i + coefficients + shares), so any endpoint, message, or stored-object reload path that ingests peer-supplied key blobs is exposed. `n` is bounded only by `u16::MAX` — there is no `MAX_KEY_SHARES_PER_SET`-style cap in the in-scope reader (contrast `coordinator/src/tributary/transaction.rs:431`), and `ThresholdParams::new`/`ThresholdKeys::new` only validate `t <= n`, not magnitude. Work grows quadratically while attacker bandwidth grows linearly, so amplification is real and unbounded within the u16 domain.

### Recommendation
Cap `t`/`n` in `ThresholdKeys::read`/`ThresholdParams::new` to the maximum set size actually supported (e.g. `MAX_KEY_SHARES_PER_SET`), and/or compute the group key with a single multiexponentiation rather than per-participant interpolation. Computing all Lagrange denominators with one batched inversion (Montgomery trick) and sharing prefix products reduces the `O(t²)` factor computations to `O(t)`.

### Proof of Concept
```rust
// Craft a ThresholdKeys<Ristretto> blob: ID, t = n = 0xFFFF, i = 1,
// Interpolation::Lagrange (byte 1), one secret scalar, then n valid points.
let n: u16 = u16::MAX;
let mut buf = vec![];
buf.extend((Ristretto::ID.len() as u32).to_le_bytes());
buf.extend(Ristretto::ID);
buf.extend(n.to_le_bytes());            // t
buf.extend(n.to_le_bytes());            // n
buf.extend(1u16.to_le_bytes());         // i
buf.push(1);                            // Interpolation::Lagrange
buf.extend(<Ristretto as Ciphersuite>::F::ONE.to_repr().as_ref()); // secret_share
for _ in 0 .. n {
    buf.extend(<Ristretto as Ciphersuite>::generator().to_bytes().as_ref());
}
// ~4.2 MB input -> ~4.3e9 field muls + 65535 inversions + 65535 point muls
let _ = ThresholdKeys::<Ristretto>::read(&mut buf.as_slice());
```
