### Title
Review set skips security-relevant content changes made via `git commit --amend` due to intersection logic in `compute_v2_review_set` - (File: `plugins/security-guidance/hooks/diffstate.py`)

### Finding Description
`load_baseline_sha`/`save_baseline_sha` (`plugins/security-guidance/hooks/diffstate.py:43-54`) persist `baseline_sha` and `head_at_capture` per session via `with_locked_state`. These values feed `compute_v2_review_set` (`diffstate.py:353-438`), which is the sole gate deciding which files the Stop-hook LLM review actually inspects [1](#0-0) .

The review set is computed as an **intersection**: `review_set = dirty_now & changed_since` when `changed_since` is available [2](#0-1) . `dirty_now` is derived from `git status` (uncommitted changes) plus, only when `head_at_capture` is a linear ancestor of the current HEAD, the commit range `head_at_capture..HEAD` [3](#0-2) . `changed_since` is a separate diff of the working tree against `baseline_sha` (the pre-turn stash SHA) [4](#0-3) .

The exploit sequence, reachable through ordinary git operations available to any user/agent working in the repo, with no elevated privileges:

1. At `UserPromptSubmit`, the baseline is captured: `baseline_sha` = stash-create SHA (or HEAD if clean), `head_at_capture` = current HEAD (call it `H1`), since the working tree is clean [5](#0-4) .
2. During the turn, the tip commit is rewritten with `git commit --amend` (e.g., injecting/altering a dangerous change in the amended content). This produces a new commit `H2` whose parent is the same as `H1`'s parent — `H1` itself becomes unreachable and is **not** an ancestor of `H2`.
3. At Stop, `current_head = H2`. `_is_ancestor(head_at_capture=H1, H2)` returns `False` (`H1` is not an ancestor of its sibling `H2`) [6](#0-5) , so the linear-advance branch is skipped and `diff_base` stays `"HEAD"`. Since the working tree is clean after the amend, `git status` reports nothing dirty, so `dirty_now` is empty.
4. `changed_since = git diff --name-only baseline_sha` (i.e., `H1` vs current tree) correctly reports the amended/dangerous file as changed [4](#0-3) .
5. `review_set = dirty_now (∅) & changed_since ({dangerous_file})` = `∅`. The Stop hook then reports "no changes since baseline" / empty review set and exits without ever generating a diff or invoking the LLM review [7](#0-6) .

The intersection design assumes `dirty_now` (git-status/linear-commit derived) and `changed_since` (content-diff derived) always agree on which files changed, but `git commit --amend` (and similarly, interactive rebase of the tip, or any history rewrite that breaks linear ancestry from `head_at_capture`) decouples them: the file is truly changed relative to the reviewed baseline, yet excluded from `dirty_now` because it's neither "dirty" in the working tree nor part of a linear commit range from `head_at_capture`. No existing check (recursion guard, kill switches, `ensure_anthropic_reachable`, file-count caps) catches this — the review set is empty before any of those are relevant, and the code proceeds straight to `_skip(9)`.

### Impact Explanation
This causes the mandatory Stop-hook LLM security review to be silently skipped for content that legitimately changed since the last reviewed baseline. A dangerous/vulnerable code change introduced via `git commit --amend` is treated as "no changes to review" and bypasses the guard entirely — this is exactly the "Logic-level service disruption caused by bypassing a required guard or misbinding security state" impact: the review-set invariant (bound to the correct baseline/touched content) is broken, and a required security control (the diff-review gate) is defeated using nothing but ordinary git commands.

### Likelihood Explanation
Fully reachable by any user/agent with normal git access in the cloned repo — no admin/maintainer privilege, no leaked credentials, no social engineering required. `git commit --amend` on the most recent commit made in the turn is a completely ordinary operation. The condition only requires: (a) a commit made and then amended within the same turn (or a scenario where `head_at_capture` predates a commit that later gets amended), and (b) the working tree being clean after the amend (the common case for `--amend`). This makes the bypass easily and repeatably triggerable.

### Recommendation
Change the review-set computation in `compute_v2_review_set` (`diffstate.py`) to not rely on intersecting `dirty_now` and `changed_since` when history has been rewritten non-linearly. Specifically:
- When `_is_ancestor(head_at_capture, current_head)` is `False` (history rewrite / amend / rebase detected), do not restrict to the old linear-advance semantics — instead trust `changed_since` (diff vs `baseline_sha`) directly as the review set (union, not intersection), since `baseline_sha` already represents the pre-turn content snapshot and is unaffected by which commits exist.
- Alternatively, detect divergence explicitly (`head_at_capture` not reachable from `current_head`) and always fall back to `changed_since` alone in that case, since the "dirty_now" ancestry-based restriction is only valid for genuinely linear, non-rewritten history.

### Proof of Concept
Integration test plan for `compute_v2_review_set`:
1. Init a git repo with an initial commit (`H0`).
2. Simulate UPS: capture `baseline_sha = capture_git_baseline(repo)` (clean tree), `head_at_capture = H0`.
3. Write `dangerous_file.py` with a vulnerable pattern (e.g., `eval(user_input)`), `git add` and `git commit` → `H1`.
4. `git commit --amend --no-edit` (or amend with further content change) → `H2`. Ensure working tree is clean.
5. Call `compute_v2_review_set(repo, baseline_sha, head_at_capture=H0, untracked_at_baseline={})`.
6. Assert: `review_paths` includes `dangerous_file.py` (or its final amended path/content).
   - Expected current (buggy) behavior: `_is_ancestor(H0, H2)` is `True` here since `H0` is still parent of `H2` (careful: use a scenario where the amend happens on a commit that is NOT `head_at_capture`'s direct child from that turn but a prior turn's HEAD, i.e., set `head_at_capture = H1` after a first Stop hook update, then amend `H1` → `H2` in the next turn) so that `H1` becomes non-ancestor of `H2`.
   - Assert the review set is non-empty and contains `dangerous_file.py`; a failing/red test demonstrates `review_set == set()` despite `changed_since` containing the file, confirming the bug.

def compute_v2_review_set(cwd, baseline_sha, head_at_capture, untracked_at_baseline=None):
    """v2 diff strategy: derive the review set from git state alone.

    review_set = (files dirty vs current HEAD, plus files committed this turn
    when HEAD advanced linearly) ∩ (files whose content differs from the
    pre-turn stash baseline). The first term is immune to checkout/pull
    ballooning; the second filters out the user's untouched pre-turn WIP.
    Falls back to dirty_now alone when no baseline is available.

    untracked_at_baseline: {repo-root-relative path: mtime_ns} captured at
    UPS. `git stash create` doesn't include untracked files, so without this
    snapshot a pre-existing untracked file looks "new since baseline" forever.
    A file is excluded only if it was untracked at baseline AND its mtime is
    unchanged — an in-place edit during the turn is still reviewed.

    Known limitation: a Bash-only turn that's interrupted before Stop fires
    leaves touched_paths empty, so the next UPS re-baselines past those edits.
    v1 never reviews Bash-only turns at all, so v2 is no worse there.

    Returns (absolute paths sorted, diff_base, repo_root, metrics).
    diff_base is "HEAD" unless HEAD advanced linearly this turn (commits),
    in which case it's head_at_capture so committed files produce a diff.
    repo_root is the git toplevel — `git diff --name-only` outputs paths
    relative to it (not to cwd), so the caller's get_git_diff must run
    from there too or pathspecs won't match.

    Also returns the untracked subset of review_set so get_git_diff can do
    a targeted `add -N -- <files>` instead of a whole-tree scan.
    """
    repo = _git_toplevel(cwd) or cwd

def _is_ancestor(cwd, maybe_ancestor, descendant):
    """True if `maybe_ancestor` is reachable from `descendant` (i.e. HEAD
    moved forward via commit/merge, not sideways via checkout)."""
    try:
        result = subprocess.run(
            [*GIT_CMD, "merge-base", "--is-ancestor", maybe_ancestor, descendant],
            cwd=cwd, capture_output=True, text=True, timeout=5,
        )
        return result.returncode == 0
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return False
