Confirmed: `Kip71GasTarget` uses `noopFormatChecker` (no validation, including no non-zero check), unlike `Kip71BaseFeeDenominator` which explicitly requires `v != 0`. [1](#0-0) 

### Title
Unvalidated `kip71.gastarget` governance parameter can be set to zero, causing a division-by-zero panic in KIP-71 base fee computation - ([File: params/kip71_config.go])

### Summary
The `Kip71GasTarget` governance parameter is registered with `noopFormatChecker`, meaning no format/range validation is applied when the parameter is set (unlike the sibling `Kip71BaseFeeDenominator`, which explicitly rejects zero). If `GasTarget` is set to `0` via governance, `NextMagmaBlockBaseFee` divides by `gasTarget` and panics, causing consensus-critical block processing to fail for every node computing the next base fee — a chain-wide, unpriviledged-transaction-reachable temporary DoS, directly analogous to the referenced report's "unbounded setter → downstream arithmetic panic" pattern.

### Finding Description
`Kip71GasTarget` is defined with no format checker (`noopFormatChecker`), so any `uint64` value including `0` passes validation when it flows through `ParamSet.Set`/`SetFromMap` from header governance votes or contract governance. [2](#0-1) 

Compare this to `Kip71BaseFeeDenominator`, which is defined right above it and explicitly guards against a zero value with `v != 0`, showing the project is aware that these KIP-71 divisor/target values need range enforcement — but the guard was omitted for `GasTarget`. [3](#0-2) 

The resulting parameter is consumed unguarded in `NextMagmaBlockBaseFee`, which computes the next block's base fee (used by every state transition/transaction in the chain, per KIP-71/Magma). When the parent block's gas used differs from `gasTarget`, the code performs `x.Div(x, new(big.Int).SetUint64(gasTarget))`. If `gasTarget == 0`, and `parentGasUsed` is anything other than 0 (i.e., the block used gas — the near-universal case), this branch executes and `big.Int.Div` by zero panics. [4](#0-3) 

Only the case `parentGasUsed == gasTarget == 0` short-circuits safely; any block with `gasUsed > 0` (which is essentially guaranteed given normal transaction processing) hits the `parentGasUsed > gasTarget` or `parentGasUsed < gasTarget` branches, both of which divide by `gasTarget`. [5](#0-4) 

### Impact Explanation
`NextMagmaBlockBaseFee` computes the base fee for every subsequent block after Magma hardfork activation and is invoked as part of header validation/block assembly on every node (`VerifyMagmaHeader`) as well as fee computation for every transaction in the mempool and state transition. [6](#0-5)  A panic here halts block processing network-wide until governance corrects the parameter — a consensus-critical, chain-halting temporary DoS that any subsequent transaction inclusion (by an ordinary, unprivileged sender) would trigger, matching the "temporary DoS" impact class of the referenced report (which similarly stemmed from an unvalidated setter feeding into unguarded arithmetic).

### Likelihood Explanation
This requires the governance mechanism (governing node vote or contract governance) to set `kip71.gastarget = 0`; this is a privileged action, but exactly parallels the "Guardian" role in the original report, which was also a privileged-but-lower-trust actor whose input lacked bounds validation. Once set, the DoS is triggered automatically and unconditionally by ordinary chain activity (any transaction causing nonzero gas usage in a block) — no additional malicious transaction crafting is needed, making the downstream trigger trivially reachable by an unprivileged user submitting any normal transaction to a node.

### Recommendation
Add a `FormatChecker` for `Kip71GasTarget` analogous to `Kip71BaseFeeDenominator`'s, rejecting `0`:

```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0
    },
    ...
}
```

Additionally, add a defensive guard in `NextMagmaBlockBaseFee` (mirroring the existing `BaseFeeDenominator == 0` fallback) so that `gasTarget == 0` cannot reach the `Div` call even if an invalid value slips through some other path. [7](#0-6) 

### Proof of Concept
1. Governance sets `kip71.gastarget` to `0` (via header-vote governance, which applies no format check for this parameter as shown above). [2](#0-1) 
2. On the following block, `NextMagmaBlockBaseFee` is called with `parentHeaderGasUsed > 0` (true for any block containing a normal transaction).
3. `gasTarget := kc.GasTarget` is `0`; `parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)` is `> 0`, so it doesn't equal `gasTarget` and the "increase" branch executes `y := x.Div(x, new(big.Int).SetUint64(gasTarget))`, dividing by zero. [8](#0-7) 
4. `big.Int.Div` panics on divide-by-zero, crashing/halting block verification and base-fee computation across all nodes until the governance parameter is fixed.

func (kc *KIP71Config) VerifyMagmaHeader(headerBaseFee *big.Int, parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) error {
	if headerBaseFee == nil {
		return fmt.Errorf("header is missing baseFee")
	}
	// Verify the baseFee is correct based on the parent header.
	expectedBaseFee := kc.NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)
	if headerBaseFee.Cmp(expectedBaseFee) != 0 {
		return fmt.Errorf("invalid baseFee: have %s, want %s, parentBaseFee %s, parentGasUsed %d",
			headerBaseFee, expectedBaseFee, parentHeaderBaseFee, parentHeaderGasUsed)
	}
	return nil
}
