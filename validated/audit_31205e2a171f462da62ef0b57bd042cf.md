### Title
Unauthenticated tx-sender JSON-RPC server allows anyone reachable on the bound port to insert/cancel broadcast-queue entries - (File: crates/clementine-tx-sender/src/jsonrpc/server.rs)

### Summary
The tx-sender's JSON-RPC server registers `send_tx` (and, under the `citrea` feature, `send_citrea_tx`) with no authentication, no TLS, and no caller-identity check, while every other Clementine gRPC entrypoint (verifier/operator/aggregator) enforces mTLS client certificate verification. The server's bind address is explicitly permitted to be `0.0.0.0` by the config validator itself (not merely a deployment default being ignored), so this is a genuine gap in the code's own authorization model rather than a documented-config-ignoring deployment mistake.

### Finding Description
`start_jsonrpc_server` in `crates/clementine-tx-sender/src/jsonrpc/server.rs` builds a `jsonrpsee` `Server` bound to `bind_addr` and registers the `send_tx` method with zero authentication middleware: [1](#0-0) 

Contrast this with the gRPC entrypoints (`create_verifier_grpc_server`, `create_operator_grpc_server`, `create_aggregator_grpc_server`), which all route through `create_grpc_server` and rely on mTLS client-certificate verification (`server_cert_path`, `client_cert_path`, `client_verification`) and an auth interceptor validated in `core/src/test/rpc_auth.rs`: [2](#0-1) [3](#0-2) 

The tx-sender's own config loader explicitly treats `0.0.0.0` as a valid, first-class bind value (not a default users must override), meaning the maintainers anticipated public exposure without adding any corresponding auth layer: [4](#0-3) 

`send_tx` is state-changing and ultimately broadcasting: it begins a DB transaction, calls `TxSenderClient::insert_try_to_send` with `cancel_outpoints`, `cancel_txids`, `activate_txids`, and `activate_outpoints` parameters, and commits — feeding the tx-sender's fee-bumping/broadcast loop: [5](#0-4) 

Because on-chain outpoints/txids referenced by `cancel_outpoints`/`cancel_txids` are public information, any unauthenticated caller reaching the port can submit a `send_tx` request identifying a legitimate operator/verifier's pending broadcast entry (e.g., for a deadline-bound disprove/challenge/timeout transaction) and instruct the queue to cancel or reprioritize it, without needing the operator's private key.

### Impact Explanation
This falls under the "unauthenticated state-changing or broadcasting call" and "deadline-bound challenge/disprove/timeout transaction made unconfirmable" High-severity categories: the boundary crossed is "a caller reaching a signing or state-changing method versus the party it is meant for" — `send_tx` is meant only for the operator's own tx-sender pipeline, but the code enforces no caller identity at all.

### Likelihood Explanation
I was not able to fully trace `insert_try_to_send`'s exact cancellation semantics in `crates/clementine-tx-sender/src/client.rs` (i.e., whether a bare `cancel_txids`/`cancel_outpoints` call without a matching valid `signed_tx` actually mutates existing queue rows for transactions belonging to a different operator/verifier instance, or whether cancellation is scoped/guarded elsewhere) before running out of investigation budget — this should be verified before treating the exploitability of the cancellation path as certain. The lack of any authentication on the endpoint itself, however, is confirmed directly from the code.

### Recommendation
Add authentication (e.g., a shared secret/API key, or reuse of the mTLS pattern already used for the gRPC servers) to the tx-sender JSON-RPC server before allowing binds other than `127.0.0.1`, and audit `insert_try_to_send`'s cancel/activate code paths to ensure they cannot be used to affect another party's pending broadcast entries.

### Proof of Concept
1. Operate (or compromise network access to) a tx-sender instance configured with `TX_SENDER_JSONRPC_BIND=0.0.0.0` (an explicitly supported value per `crates/clementine-tx-sender/src/config.rs`).
2. From any remote host, send a JSON-RPC POST to `send_tx` with `cancel_txids`/`cancel_outpoints` referencing a known on-chain outpoint/txid belonging to the operator's pending deadline-bound transaction.
3. Observe that the request is processed and committed without any authentication check, per `crates/clementine-tx-sender/src/jsonrpc/server.rs` lines 42-89.

pub async fn start_jsonrpc_server(
    tx_sender_client: TxSenderClient,
    bind_addr: SocketAddr,
) -> Result<TxSenderJsonRpcServer, BridgeError> {
    let server: Server = ServerBuilder::default()
        .max_request_body_size(MAX_JSONRPC_REQUEST_BODY_SIZE)
        .build(bind_addr)
        .await
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    let local_addr = server
        .local_addr()
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    let mut module = RpcModule::new(tx_sender_client.clone());
    module
        .register_async_method("send_tx", |params, client, _| async move {
            let req: InsertTryToSendParams = params.one().map_err(jsonrpc_err)?;

            let raw_tx = hex::decode(&req.signed_tx_hex).map_err(jsonrpc_err)?;
            let signed_tx: Transaction = consensus::deserialize(&raw_tx).map_err(jsonrpc_err)?;

            let mut dbtx = client.db.begin_transaction().await.map_err(jsonrpc_err)?;

            let try_to_send_id = client
                .insert_try_to_send(
                    &mut dbtx,
                    req.tx_metadata,
                    &signed_tx,
                    req.fee_paying_type,
                    req.rbf_signing_info,
                    &req.cancel_outpoints,
                    &req.cancel_txids,
                    &req.activate_txids,
                    &req.activate_outpoints,
                )
                .await
                .map_err(jsonrpc_err)?;

            client
                .db
                .commit_transaction(dbtx)
                .await
                .map_err(jsonrpc_err)?;

            Ok::<u32, ErrorObjectOwned>(try_to_send_id)
        })
        .map_err(|e| BridgeError::Eyre(e.into()))?;

pub async fn create_verifier_grpc_server<C: CitreaClientT>(
    config: BridgeConfig,
) -> Result<(std::net::SocketAddr, oneshot::Sender<()>), BridgeError> {
    let _rpc = ExtendedBitcoinRpc::connect(
        config.bitcoin_rpc_url.clone(),
        config.bitcoin_rpc_user.clone(),
        config.bitcoin_rpc_password.clone(),
        None,
    )
    .await
    .wrap_err("Failed to connect to Bitcoin RPC")?;

    let addr: std::net::SocketAddr = format!("{}:{}", config.host, config.port)
        .parse()
        .wrap_err("Failed to parse address")?;
    let verifier = VerifierServer::<C>::new(config.clone()).await?;
    verifier.start_background_tasks().await?;

    let svc = ClementineVerifierServer::new(verifier)
        .max_encoding_message_size(config.grpc.max_message_size)
        .max_decoding_message_size(config.grpc.max_message_size);

    let (server_addr, shutdown_tx) =
        create_grpc_server(addr.into(), svc, "Verifier", &config).await?;

    match server_addr {
        ServerAddr::Tcp(socket_addr) => Ok((socket_addr, shutdown_tx)),
        _ => Err(BridgeError::ConfigError("Expected TCP address".into())),
    }
}

pub async fn create_operator_grpc_server<C: CitreaClientT>(
    config: BridgeConfig,
) -> Result<(std::net::SocketAddr, oneshot::Sender<()>), BridgeError> {
    tracing::info!(
        "config host and port are: {} and {}",
        config.host,
        config.port
    );
    let addr: std::net::SocketAddr = format!("{}:{}", config.host, config.port)
        .parse()
        .wrap_err("Failed to parse address")?;

    tracing::info!("Creating operator server");
    let operator = OperatorServer::<C>::new(config.clone()).await?;
    operator.start_background_tasks().await?;

    tracing::info!("Creating ClementineOperatorServer");
    let svc = ClementineOperatorServer::new(operator)
        .max_encoding_message_size(config.grpc.max_message_size)
        .max_decoding_message_size(config.grpc.max_message_size);
    let (server_addr, shutdown_tx) =
        create_grpc_server(addr.into(), svc, "Operator", &config).await?;
    tracing::info!("Operator gRPC server created");

    match server_addr {
        ServerAddr::Tcp(socket_addr) => Ok((socket_addr, shutdown_tx)),
        _ => Err(BridgeError::ConfigError("Expected TCP address".into())),
    }
}

        #[cfg(feature = "json-rpc")]
        let jsonrpc = {
            let port = env_parse_optional::<u16>("TX_SENDER_JSONRPC_PORT")?;
            port.map(|port| {
                let bind = env_optional("TX_SENDER_JSONRPC_BIND")
                    .unwrap_or_else(|| "127.0.0.1".to_string());
                if bind != "127.0.0.1" && bind != "0.0.0.0" {
                    return Err(BridgeError::EnvVarMalformed(
                        "TX_SENDER_JSONRPC_BIND",
                        "bind must be either 127.0.0.1 or 0.0.0.0".to_string(),
                    ));
                }
                Ok(TxSenderJsonRpcConfig { bind, port })
            })
            .transpose()?
        };
