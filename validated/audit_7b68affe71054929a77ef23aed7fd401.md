### Title
`aptos move verify-package` (`VerifyPackage`) never compares on-chain bytecode to local compilation — it only diffs self-reported metadata — ([File: aptos-move/cli/src/commands.rs], [File: aptos-move/cli/src/stored_package.rs])

### Summary
The `aptos move verify-package` CLI command is documented as verifying that "the on-chain copy matches" the local source/compilation, and its own doc-comment states it "verifies the bytecode matches a local compilation of the Move code." In reality, `VerifyPackage::execute` fetches the on-chain `PackageRegistry` with `with_bytecode = false` and only calls `CachedPackageMetadata::verify()`, which compares self-reported `PackageMetadata` fields (name, deps, `ModuleMetadata` source/source_map, manifest, upgrade_policy, extension, `source_digest`). It never fetches or diffs the actual deployed `.mv` module bytecode against the freshly compiled bytecode.

### Finding Description
`VerifyPackage::execute` in [1](#0-0)  does the following:
1. Builds the package locally and extracts `compiled_metadata` from the fresh build.
2. Creates a `CachedPackageRegistry` with `with_bytecode = false`: [2](#0-1) .
3. Calls `package.verify(&compiled_metadata)` and, if it passes, prints "Successfully verified source of package".

`CachedPackageRegistry::create` only populates the `bytecode` map when `with_bytecode` is `true` [3](#0-2) , so with `false` no on-chain `.mv` bytes are ever downloaded during verification.

`CachedPackageMetadata::verify` then only compares metadata fields already present in the `PackageRegistry` resource read from chain: package name, `deps`, `modules` (i.e., `ModuleMetadata { name, source, source_map, extension }` — never actual bytecode), `manifest`, `upgrade_policy`, `extension`, and `source_digest` [4](#0-3) .

Crucially, `source_digest` is a value chosen by the *publisher* and embedded in the `PackageMetadata` argument passed to `code::publish_package_txn` at publish time — it is uninterpreted, arbitrary metadata as far as the Move VM and `aptos_framework::code` module are concerned. `code::publish_package` in [5](#0-4)  never checks that `source_digest`, `manifest`, or `ModuleMetadata.source` actually correspond to the compiled module bytes in `code: vector<vector<u8>>`. There is no on-chain (or off-chain, in this CLI path) cryptographic binding enforced between the declared source/metadata and the bytecode that is actually loaded via `request_publish`/`request_publish_with_allowed_deps`.

As a result, a publisher can submit honest-looking `PackageMetadata` (correct `source`, correct `source_digest` computed from that honest source, correct `manifest`) while publishing a completely different, malicious `code` bundle. `aptos move verify-package` will recompute the same `source_digest` from the honest local source, compare it against the honest-looking on-chain metadata, find a match, and report "Successfully verified source of package" — even though the bytecode actually running on-chain differs entirely from the verified source.

### Impact Explanation
This breaks the code-safety invariant that "verified bytes, package metadata, dependency declarations, and committed module bytes" must agree — explicitly called out as an in-scope impact category. Any downstream tooling, auditor, or user relying on `aptos move verify-package` to confirm that a deployed package's logic matches its published/audited source is given a false assurance. This is a supply-chain-style integrity failure: it does not directly let an attacker mutate protected state without authorization (the attacker still needs to be the legitimate publisher/owner of the target account or object), but it defeats the one code-safety mechanism whose entire purpose is to catch exactly this kind of mismatch (metadata/source claims vs. committed module bytes), which is high impact for anyone who publishes or verifies packages and trusts this tool as a trust-verification gate (e.g., before interacting with, depending on, or auditing a contract).

### Likelihood Explanation
High likelihood of being triggered, intentionally or not: any account/object owner publishing a package fully controls both the `code` bytes and the `PackageMetadata` (including `source_digest`, `manifest`, per-module `source`) sent to `publish_package_txn`/`publish`/`upgrade`; nothing on-chain enforces they correspond. A malicious or compromised publisher (or a benign publisher whose tooling has a bug computing `source_digest`) can trivially cause this mismatch, and `verify-package`'s only defense (metadata self-consistency, not bytecode comparison) will not detect it.

### Recommendation
Change `VerifyPackage::execute` to fetch bytecode with `with_bytecode = true` (as `CachedPackageRegistry` already supports via `get_bytecode`) and extend `CachedPackageMetadata::verify` (or a new check in the command) to serialize the locally compiled `CompiledModule`s and byte-for-byte compare them against the downloaded on-chain module bytecode for every module in the package, in addition to the existing metadata field checks. Treat any bytecode mismatch as a hard verification failure, independent of whether the metadata fields (including `source_digest`) happen to agree.

### Proof of Concept
Conceptual PoC (no execution environment available to run this, but derivable directly from the code paths cited above):
1. Publisher writes an honest module `M` and computes `PackageMetadata` (source, `source_digest`, manifest) from `M`'s real source, as the CLI normally would.
2. Publisher swaps the `code: vector<vector<u8>>` argument passed to `code::publish_package_txn` for a different, malicious compiled module `M'` (e.g., changing a fee calculation or moving funds to an attacker address), while keeping the exact same `PackageMetadata` (still describing honest `M`). Nothing in `code::publish_package` ( [5](#0-4) ) checks `code` bytes against `pack.modules[i].source`/`source_digest`.
3. A third party runs `aptos move verify-package --account <publisher>` against the honest source tree for `M`.
4. `VerifyPackage::execute` ( [1](#0-0) ) fetches only metadata (`with_bytecode=false`), recomputes `source_digest` from the honest local source, finds it matches the on-chain metadata's `source_digest`, and prints "Successfully verified source of package" — despite `M'` being what is actually deployed and executed on-chain.

Note: I was not able to execute this end-to-end in this environment (no filesystem/CLI access), so this PoC is based on static tracing of the exact code paths shown above rather than an observed runtime result; a background Devin session with CLI/network access would be needed to produce a concrete transaction-level demonstration.

    async fn execute(self) -> CliTypedResult<&'static str> {
        // First build the package locally to get the package metadata
        let build_options = BuildOptions {
            install_dir: self.move_options.output_dir.clone(),
            bytecode_version: fix_bytecode_version(
                self.move_options.bytecode_version,
                self.move_options.language_version,
            ),
            ..self.included_artifacts.build_options(&self.move_options)?
        };
        let w = self.env.writer();
        let pack = BuiltPackage::build_to(&w, self.move_options.get_package_path()?, build_options)
            .map_err(|e| CliError::MoveCompilationError(format!("{:#}", e)))?;
        let compiled_metadata = pack.extract_metadata()?;

        // Now pull the compiled package
        let client = self.rest_options.client(&self.profile_options)?;
        let registry = CachedPackageRegistry::create(client, self.account, false).await?;
        let package = registry
            .get_package(pack.name())
            .await
            .map_err(|s| CliError::CommandArgumentError(s.to_string()))?;

        // We can't check the arbitrary, because it could change on us
        if package.upgrade_policy() == UpgradePolicy::arbitrary() {
            return Err(CliError::CommandArgumentError(
                "A package with upgrade policy `arbitrary` cannot be downloaded \
                since it is not safe to depend on such packages."
                    .to_owned(),
            ));
        }

        // Verify that the source digest matches
        package.verify(&compiled_metadata)?;

        Ok("Successfully verified source of package")
    }

    pub async fn create(
        client: Client,
        addr: AccountAddress,
        with_bytecode: bool,
    ) -> anyhow::Result<Self> {
        // Need to use a different type to deserialize JSON
        let inner = client
            .get_account_resource_bcs::<PackageRegistry>(addr, "0x1::code::PackageRegistry")
            .await?
            .into_inner();
        let mut bytecode = BTreeMap::new();
        if with_bytecode {
            for pack in &inner.packages {
                for module in &pack.modules {
                    let bytes = client
                        .get_account_module(addr, &module.name)
                        .await?
                        .into_inner()
                        .bytecode
                        .0;
                    bytecode.insert(module.name.clone(), bytes);
                }
            }
        }
        Ok(Self { inner, bytecode })
    }

    pub fn verify(&self, package_metadata: &PackageMetadata) -> anyhow::Result<()> {
        let self_metadata = self.metadata;

        if self_metadata.name != package_metadata.name {
            bail!(
                "Package name doesn't match {} : {}",
                package_metadata.name,
                self_metadata.name
            )
        } else if self_metadata.deps != package_metadata.deps {
            bail!(
                "Dependencies don't match {:?} : {:?}",
                package_metadata.deps,
                self_metadata.deps
            )
        } else if self_metadata.modules != package_metadata.modules {
            bail!(
                "Modules don't match {:?} : {:?}",
                package_metadata.modules,
                self_metadata.modules
            )
        } else if self_metadata.manifest != package_metadata.manifest {
            bail!(
                "Manifest doesn't match {:?} : {:?}",
                package_metadata.manifest,
                self_metadata.manifest
            )
        } else if self_metadata.upgrade_policy != package_metadata.upgrade_policy {
            bail!(
                "Upgrade policy doesn't match {:?} : {:?}",
                package_metadata.upgrade_policy,
                self_metadata.upgrade_policy
            )
        } else if self_metadata.extension != package_metadata.extension {
            bail!(
                "Extensions doesn't match {:?} : {:?}",
                package_metadata.extension,
                self_metadata.extension
            )
        } else if self_metadata.source_digest != package_metadata.source_digest {
            bail!(
                "Source digests doesn't match {:?} : {:?}",
                package_metadata.source_digest,
                self_metadata.source_digest
            )
        }

        Ok(())
    }

    public fun publish_package(owner: &signer, pack: PackageMetadata, code: vector<vector<u8>>) acquires PackageRegistry {
        // Disallow incompatible upgrade mode. Governance can decide later if this should be reconsidered.
        assert!(
            pack.upgrade_policy.policy > upgrade_policy_arbitrary().policy,
            error::invalid_argument(EINCOMPATIBLE_POLICY_DISABLED),
        );

        let addr = signer::address_of(owner);
        if (!exists<PackageRegistry>(addr)) {
            move_to(owner, PackageRegistry { packages: vector::empty() })
        };

        // Checks for valid dependencies to other packages
        let allowed_deps = check_dependencies(addr, &pack);

        // Check package against conflicts
        // To avoid prover compiler error on spec
        // the package need to be an immutable variable
        let module_names = get_module_names(&pack);

        // Record, per module in this package, the object's transitive root owner at (re)publish, so
        // lazy self-init can detect a later transfer of the object or an ancestor since that module
        // was published (see `init::internal_maybe_initialize`). Objects only; feature-gated.
        if (features::is_lazy_module_initialization_enabled() && object::is_object(addr)) {
            let owner = object::address_to_object<object::ObjectCore>(addr).root_owner();
            module_names.for_each_ref(|name| {
                init::record_deploy_owner(addr, *name.bytes(), owner);
            });
        };
        let package_immutable = &borrow_global<PackageRegistry>(addr).packages;
        let len = package_immutable.length();
        let index = len;
        let upgrade_number = 0;
        package_immutable.enumerate_ref(|i, old| {
            let old: &PackageMetadata = old;
            if (old.name == pack.name) {
                upgrade_number = old.upgrade_number + 1;
                check_upgradability(old, &pack, &module_names);
                index = i;
            } else {
                check_coexistence(old, &module_names)
            };
        });

        // Assign the upgrade counter.
        pack.upgrade_number = upgrade_number;

        let packages = &mut borrow_global_mut<PackageRegistry>(addr).packages;
        // Update registry
        let policy = pack.upgrade_policy;
        if (index < len) {
            pack.modules.for_each_ref(|m| {
                let m: &ModuleMetadata = m;
                init::reset_initialized(addr, *m.name.bytes());
            });
            *packages.borrow_mut(index) = pack
        } else {
            packages.push_back(pack)
        };

        event::emit(PublishPackage {
            code_address: addr,
            is_upgrade: upgrade_number > 0
        });

        // Request publish
        if (features::code_dependency_check_enabled())
            request_publish_with_allowed_deps(addr, module_names, allowed_deps, code, policy.policy)
        else
        // The new `request_publish_with_allowed_deps` has not yet rolled out, so call downwards
        // compatible code.
            request_publish(addr, module_names, code, policy.policy)
    }
