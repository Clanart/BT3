### Title
Repository name from an attacker-controlled clone URL is not shell-escaped and breaks out of the quoted argument in `launch()`, enabling command injection when "Open in Shell/Terminal" is used - ([File: app/src/lib/shells/win32.ts])

### Summary
GitHub Desktop derives the local directory name for a cloned repository from the last path segment of the *remote URL* the user (or a “Clone with Desktop” deep link) provides, via `sanitizeCloneName`. This function only strips path separators (`/`, `\`, `:`) and rejects `..`/`.`/empty segments — it does **not** strip shell metacharacters such as `"`, `&`, `^`, `|`, `` ` ``. That unsanitized name becomes part of the on-disk repository path, which is later interpolated, unescaped, directly into a `shell: true` `spawn()` call in `launch()` (used by the "Open in Git Bash/Cygwin/Warp/Hyper/Alacritty" shell-integration feature). A crafted remote URL (or GitHub Desktop `x-github-client://` clone deep link) whose owner/name segment contains a double quote followed by shell metacharacters therefore results in arbitrary command execution the next time the victim opens a shell/terminal for that repository — a very common, expected user action, not an "unnatural" step.

### Finding Description
- `sanitizeCloneName` in [1](#0-0)  only guards against path traversal (splitting on `/`, `\`, `:` and rejecting `..`); it allows any other character, including `"`, `&`, `^`, `%`, `|`, back-ticks, etc.
- `parseRepositoryIdentifier`/`parseRemote` extract the `name` segment from the URL with a permissive regex (`[^/]+?`), so a URL such as `https://evil.example.com/owner/name"^&calc.exe^&".git` yields a `name` containing shell metacharacters, as shown by `parseRemote`'s capture groups in [2](#0-1) .
- This sanitized-but-not-escaped name is joined into the destination path in the Clone dialog: [3](#0-2) .
- That path becomes `Repository.path` and, when the user later invokes "Open in Git Bash" / Cygwin / Warp / Hyper / Alacritty, is interpolated **without escaping** into a template string that is passed to `spawn(..., { shell: true, ... })`: [4](#0-3) 
- Note that the codebase already contains a proper shell-escaping helper, `app/src/lib/hooks/shell-escape.ts` (`cmdEscape`, `bashEscape`, `powershellEscape`, `quoteCommand`) [5](#0-4) , but `launch()` in `win32.ts` does not use it for the `path` argument — it manually wraps the path in literal `"..."` instead, which is exactly the pattern `shell-escape.ts` was built to replace.
- Because `shell: true` on Windows results in the joined argv being handed to `cmd.exe /d /s /c` with no further escaping performed by Node beyond what the caller supplies, an embedded `"` in `path` closes the quoted string early, and any subsequent `&`, `|`, `^` etc. are interpreted by `cmd.exe` as command separators/operators.

### Impact Explanation
This is a full command-execution primitive triggered purely by cloning a repository from an attacker-supplied URL — no admin rights, no pre-existing malware, no leaked credentials, and no unnatural steps: opening a shell for a freshly cloned repo ("Open in Git Bash", a first-class Desktop feature) is normal workflow. It maps directly to the seed report's class (unescaped, attacker-controlled string interpolated into a shell-executed command line), just relocated from ImageMagick’s `identify()` filename argument to Desktop’s repository-path argument used by its shell-integration `launch()` function.

### Likelihood Explanation
Requires only that the victim clone from a URL the attacker controls (or click a "Clone with GitHub Desktop" deep link with such a URL/owner-name) and later use the built-in "Open in Shell" menu item on that repository — both are ordinary, expected user actions. `sanitizeCloneName`'s regression tests (`app/test/unit/clone-path-safety-test.ts`) only assert against path-traversal payloads, confirming that shell-metacharacter injection was never considered as part of the existing hardening.

### Recommendation
- Extend `sanitizeCloneName` (or add a follow-up sanitation step) to strip/replace shell-significant characters (`"`, `` ` ``, `$`, `&`, `|`, `^`, `%`, `<`, `>`, `;`) from the derived directory name, in addition to path separators.
- In `app/src/lib/shells/win32.ts`'s `launch()`, stop manually wrapping `path` in literal quotes; use the existing `cmd`/`quoteCommand` escaping helpers from `app/src/lib/hooks/shell-escape.ts` (already used elsewhere) for every shell branch that sets `shell: true`.
- More generally, prefer `spawn` without `shell: true` (passing the path as a discrete argv element) wherever the target executable supports it, eliminating the need for manual quoting entirely.

### Proof of Concept
1. Attacker hosts a git remote reachable at a URL whose path segment is `owner/name"^&calc.exe^&".git` (any harmless-looking git repo content).
2. Victim clones this URL via the Clone dialog (`CloneGenericRepository`) or a `x-github-client://openRepo` deep link with that URL.
3. `parseRepositoryIdentifier` → `sanitizeCloneName` yields a folder name like `name"^&calc.exe^&"`, and `Path.join(dirPath, safeName)` becomes the repository's on-disk path.
4. Victim right-clicks the repository in Desktop and selects "Open in Git Bash" (or Cygwin/Warp/etc.).
5. `launch()` executes `spawn(gitBashPath, ['--cd="C:\...\name"^&calc.exe^&""'], { shell: true, cwd: path })`; `cmd.exe` interprets the embedded `"` as closing the quoted segment and `&calc.exe&` as a separate command, executing `calc.exe` (or any attacker payload) with the victim's privileges.

  for (const { protocol, regex } of remoteRegexes) {
    const match = regex.exec(url)
    if (match !== null && match.length >= 4) {
      return { protocol, hostname: match[1], owner: match[2], name: match[3] }
    }
  }

  return null
}

export function sanitizeCloneName(name: string): string | null {
  const components = name.split(/[/\\:]/)

  let lastComponent = ''
  for (let i = components.length - 1; i >= 0; i--) {
    if (components[i].length > 0) {
      lastComponent = components[i]
      break
    }
  }

  if (lastComponent.length === 0) {
    return null
  }

  if (lastComponent.endsWith('.git')) {
    lastComponent = lastComponent.slice(0, -4)
  }

  if (
    lastComponent === '..' ||
    lastComponent === '.' ||
    lastComponent.length === 0
  ) {
    return null
  }

  return lastComponent
}

// https://github.com/ericcornelissen/shescape/blob/89072ba7de233f81f5553b52098671c94eb9bd0c/src/internal/unix/bash.js#L39
const bashEscape = (arg: string) =>
  arg
    .replace(/[\0\u0008\u001B\u009B]/gu, '')
    .replace(/\r(?!\n)/gu, '')
    .replace(/'/gu, "'\\''")

const shQuoteCommand = (
  escapeFn: (arg: string) => string,
  cmd: string,
  ...args: string[]
) => [cmd, ...args].map(a => `'${escapeFn(a)}'`).join(' ')

export const bash: Shell = {
  args: ['-ilc'],
  quoteCommand: shQuoteCommand.bind(null, bashEscape),
}

const cmdEscape = (arg: string) =>
  arg
    .replace(/[\0\u0008\r\u001B\u009B]/gu, '')
    .replace(/\n/gu, ' ')
    .replace(/"/gu, '""')
    .replace(/([%&<>^|])/gu, '"^$1"')
    .replace(/(?<!\\)(\\*)(?="|$)/gu, '$1$1')

export const cmd: Shell = {
  args: ['/d', '/s', '/c'],
  quoteCommand: (cmd, ...args) =>
    `"${[cmd, ...args].map(a => `"${cmdEscape(a)}"`).join(' ')}"`,
}
