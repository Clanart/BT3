### Title
Tokenfactory denom allowlist bypass via EVM bank precompile `send` calling `bankKeeper.SendCoins` directly - ([File: precompiles/bank/legacy/v552/bank.go])

### Summary
The `IsInDenomAllowList` check for tokenfactory denoms is enforced only inside the Cosmos `bank` module's `MsgServer.Send` / `MsgServer.MultiSend` handlers, not inside `BaseSendKeeper.SendCoins` itself. Several legacy versions of the EVM `bank` precompile's `send` method call `p.bankKeeper.SendCoins(...)` directly instead of routing through `p.bankMsgServer.Send(...)`, which skips the allowlist check entirely — analogous to the reported "session keys bypass allowlist" bug where an alternate execution path skipped the allowlist gate.

### Finding Description
`sdk.bank`'s `msgServer.Send` explicitly calls `k.IsInDenomAllowList` for both sender and receiver before invoking `k.SendCoins`: [1](#0-0) 

The allowlist check is not embedded in `SendCoins`/`BaseSendKeeper` itself — it lives in the message-server layer, as the `SendKeeper` interface separately exposes `IsInDenomAllowList` as its own method that callers are expected to invoke: [2](#0-1) 

The EVM `bank` precompile (multiple legacy versions, e.g. v552/v555/v562/v580/v600) implements `send` by calling `p.bankKeeper.SendCoins` directly, bypassing the msg-server-level allowlist gate: [3](#0-2) [4](#0-3) [5](#0-4) [6](#0-5) 

Newer precompile versions (v610/v614/v630/v640/v66/v67) were changed to route through `p.bankMsgServer.Send(sdk.WrapSDKContext(ctx), msg)` instead, which does perform the allowlist check: [7](#0-6) [8](#0-7) 

This means for the affected legacy precompile versions, an EVM caller who is not on a tokenfactory denom's allowlist can still transfer that restricted denom by calling the precompile's `send` — an unprivileged transaction sender bypassing an authority-configured allowlist, directly analogous to the aa-sdk allowlist-bypass advisory where session keys reached a code path that skipped the allowlist gate.

### Impact Explanation
Tokenfactory denom allowlists (`AllowList`) are used by denom admins to restrict which addresses may hold/transfer a given token — e.g. for compliance-gated or permissioned assets. Bypassing this check allows unauthorized transfer of a restricted asset via the EVM bank precompile, which is an unauthorized-transfer-via-precompile impact directly covered by the validation criteria (unauthorized transfer via precompile). It does not create/destroy supply, but it can move restricted assets to/from addresses the denom admin explicitly disallowed, undermining the security guarantee the allowlist is meant to provide.

### Likelihood Explanation
Reachability requires only that: (1) a tokenfactory denom's admin has configured a `DenomAllowList` via `MsgCreateDenom`/`MsgUpdateDenom`, (2) an ERC20 native pointer exists for that denom (`GetERC20NativePointer`), and (3) an EVM account (the pointer contract itself, since `send` requires `pointer.Cmp(caller) != 0` check) calls the bank precompile's `send` function. Given pointer contracts wrap tokenfactory denoms for EVM interop and are commonly deployed for any tokenfactory asset, this is reachable by any EVM user interacting with a pointer-wrapped allowlisted tokenfactory denom, with no special privilege needed.

### Recommendation
Ensure all EVM bank-precompile `send` implementations route through the same allowlist-enforcing path as the Cosmos `MsgServer.Send` (i.e., call `p.bankMsgServer.Send` or explicitly call `IsInDenomAllowList` before `SendCoins`), consistent with the already-fixed newer precompile versions. Ideally, move the allowlist check into `BaseSendKeeper.SendCoins` itself so every caller (precompiles, IBC transfer hooks, wasm bindings, future msg types) is protected by construction rather than relying on each caller to remember to check it.

### Proof of Concept
1. Denom admin creates tokenfactory denom `factory/{admin}/RESTRICTED` with `AllowList{Addresses: [addrA]}` via `MsgCreateDenom`.
2. A native pointer contract is registered for `factory/{admin}/RESTRICTED` (`AddNativePointer` in the pointer precompile), yielding pointer address `P`.
3. Denom admin funds `addrA` (allowed) with the restricted denom via `Mint`.
4. From EVM, `addrA`'s associated EVM address calls, through the pointer contract `P` (satisfying `pointer.Cmp(caller) == 0`), `BANK_CONTRACT.send(addrA_evm, addrB_evm, "factory/{admin}/RESTRICTED", amount)` where `addrB` is NOT in the allow list.
5. On the affected legacy precompile version, this succeeds because `send` calls `bankKeeper.SendCoins` directly, never invoking `IsInDenomAllowList`, resulting in disallowed address `addrB` receiving the restricted-list token — whereas the equivalent Cosmos `MsgSend` to `addrB` would be rejected with `ErrUnauthorized`.

func (k msgServer) Send(goCtx context.Context, msg *types.MsgSend) (*types.MsgSendResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	if err := k.IsSendEnabledCoins(ctx, msg.Amount...); err != nil {
		return nil, err
	}

	from, err := sdk.AccAddressFromBech32(msg.FromAddress)
	if err != nil {
		return nil, err
	}
	to, err := sdk.AccAddressFromBech32(msg.ToAddress)
	if err != nil {
		return nil, err
	}

	allowListCache := make(map[string]AllowedAddresses)
	if !k.IsInDenomAllowList(ctx, from, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to send funds", msg.FromAddress)
	}

	if k.BlockedAddr(to) || !k.IsInDenomAllowList(ctx, to, msg.Amount, allowListCache) {
		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", msg.ToAddress)
	}

	err = k.SendCoins(ctx, from, to, msg.Amount)
	if err != nil {
		return nil, err
	}

func (p Precompile) send(ctx sdk.Context, caller common.Address, method *abi.Method, args []interface{}, value *big.Int, readOnly bool) ([]byte, error) {
	if readOnly {
		return nil, errors.New("cannot call send from staticcall")
	}
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, err
	}
	denom := args[2].(string)
	if denom == "" {
		return nil, errors.New("invalid denom")
	}
	pointer, _, exists := p.evmKeeper.GetERC20NativePointer(ctx, denom)
	if !exists || pointer.Cmp(caller) != 0 {
		return nil, fmt.Errorf("only pointer %s can send %s but got %s", pointer.Hex(), denom, caller.Hex())
	}
	amount := args[3].(*big.Int)
	if amount.Cmp(utils.Big0) == 0 {
		// short circuit
		return method.Outputs.Pack(true)
	}
	// TODO: it's possible to extend evm module's balance to handle non-usei tokens as well
	senderSeiAddr, err := p.accAddressFromArg(ctx, args[0])
	if err != nil {
		return nil, err
	}
	receiverSeiAddr, err := p.accAddressFromArg(ctx, args[1])
	if err != nil {
		return nil, err
	}

	if err := p.bankKeeper.SendCoins(ctx, senderSeiAddr, receiverSeiAddr, sdk.NewCoins(sdk.NewCoin(denom, sdk.NewIntFromBigInt(amount)))); err != nil {
		return nil, err
	}

	return method.Outputs.Pack(true)
}

func (p PrecompileExecutor) send(ctx sdk.Context, caller common.Address, method *abi.Method, args []interface{}, value *big.Int, readOnly bool) ([]byte, uint64, error) {
	if readOnly {
		return nil, 0, errors.New("cannot call send from staticcall")
	}
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}
	denom := args[2].(string)
	if denom == "" {
		return nil, 0, errors.New("invalid denom")
	}
	pointer, _, exists := p.evmKeeper.GetERC20NativePointer(ctx, denom)
	if !exists || pointer.Cmp(caller) != 0 {
		return nil, 0, fmt.Errorf("only pointer %s can send %s but got %s", pointer.Hex(), denom, caller.Hex())
	}
	amount := args[3].(*big.Int)
	if amount.Cmp(utils.Big0) == 0 {
		// short circuit
		bz, err := method.Outputs.Pack(true)
		return bz, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
	}
	senderSeiAddr, err := p.accAddressFromArg(ctx, args[0])
	if err != nil {
		return nil, 0, err
	}
	receiverSeiAddr, err := p.accAddressFromArg(ctx, args[1])
	if err != nil {
		return nil, 0, err
	}

	msg := &banktypes.MsgSend{
		FromAddress: senderSeiAddr.String(),
		ToAddress:   receiverSeiAddr.String(),
		Amount:      sdk.NewCoins(sdk.NewCoin(denom, sdk.NewIntFromBigInt(amount))),
	}

	err = msg.ValidateBasic()
	if err != nil {
		return nil, 0, err
	}

	if _, err = p.bankMsgServer.Send(sdk.WrapSDKContext(ctx), msg); err != nil {
		return nil, 0, err
	}

	bz, err := method.Outputs.Pack(true)
	return bz, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}
