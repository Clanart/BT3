### Title
Unbounded raw-byte indexing in CLVM "canonical" check on attacker-supplied `puzzle_reveal`/`solution` can raise an unhandled `IndexError` during mempool admission - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_clvm_canonical()` / `is_atom_canonical()` in `chia/full_node/mempool_manager.py` walk an attacker-controlled `bytes` buffer (`coin_spend.puzzle_reveal` / `coin_spend.solution`) by hand, decoding CLVM atom length prefixes, but never verify that the buffer actually contains enough remaining bytes before indexing into it, either for the length-prefix continuation bytes or for the atom body that `offset` is advanced past. This is directly analogous to CVE‑2018‑11436's `buffer_addraw`: a hand-rolled length-prefixed parser trusts an attacker-supplied length field and indexes/copies without a bounds check.

### Finding Description
`is_atom_canonical()` reads the header byte and, depending on its high bits, expects `prefix_len` (0–5) additional continuation bytes to build `atom_len`: [1](#0-0) 

Inside the `for i in range(prefix_len)` loop it does `offset += 1; atom_len |= clvm_buffer[offset]` with no check that `offset < len(clvm_buffer)`. It also never checks that the buffer actually holds `atom_len` bytes of atom content after the header; it just returns the `atom_len` it computed.

The caller, `is_clvm_canonical()`, reads `b = clvm_buffer[offset]` on every loop iteration with no bounds check either, and after handling an atom does `offset += atom_len` unconditionally, without verifying `offset <= len(clvm_buffer)`: [2](#0-1) 

If `tokens_left` is still nonzero after such an out-of-range advance (i.e., more sibling/parent nodes are expected in the s-expression), the very next loop iteration indexes `clvm_buffer[offset]` past the end of the buffer, raising an uncaught `IndexError` (Python's own bounds check triggers here, but the *logic* is written as if it never can go out of range — no `try/except`, no length re-validation before indexing).

This function is invoked unconditionally on every submitted spend bundle's puzzle reveal and solution, not just DEDUP-eligible ones: [3](#0-2) 

`validate_spend_bundle()` is called from `add_spend_bundle()` with no surrounding `try/except`: [4](#0-3) 

so an `IndexError` raised deep inside `is_clvm_canonical`/`is_atom_canonical` propagates unhandled out of `add_spend_bundle`, which is the core mempool-admission entry point called for every spend bundle received from full-node peers, wallets, or RPC callers.

### Impact Explanation
An unhandled exception raised while processing a single submitted spend bundle inside the mempool's core admission path (`add_spend_bundle` → `validate_spend_bundle` → `is_clvm_canonical`) is a spend-triggered transaction-processing halt: the task/coroutine handling that spend bundle crashes with an unexpected exception instead of returning a normal `MempoolInclusionStatus.FAILED`/`Err`, which can disrupt mempool processing for the node handling the crafted bundle. This maps to the explicitly allowed "spend-triggered transaction-processing halt" impact category.

### Likelihood Explanation
Reaching this code path only requires submitting one spend bundle whose `puzzle_reveal` or `solution` bytes decode successfully through the real CLVM engine (so `conds` gets computed) but whose byte-level atom-length-prefix structure, when independently re-walked by this hand-rolled Python canonical scanner, causes the scanner's `offset` bookkeeping to diverge from the buffer's actual bounds (e.g., a length-prefix header at/near the end of the buffer, or an atom-length computation that outruns the real atom boundary while more sibling tokens are still expected). Because `is_clvm_canonical` is a bespoke re-implementation of the CLVM atom-length encoding rather than the authoritative Rust parser, constructing a byte sequence where the two parsers disagree just enough to walk `offset` out of bounds is a pure crafting problem, reachable by any unprivileged spend-bundle submitter — no privileged position or network manipulation needed. I was not able to fully construct and trace a concrete byte sequence that both (a) passes real CLVM execution to produce valid `conds`, and (b) drives the Python scanner's `offset` strictly out of bounds while `tokens_left != 0`; this requires exhaustively cross-checking the six bit-pattern branches in `is_atom_canonical` against the real CLVM serialization spec, which I could not fully verify against the Rust deserializer implementation from the indexed code alone.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before indexing continuation bytes (`if offset + prefix_len >= len(clvm_buffer): return ..., False` or raise a caught error), and validate in `is_clvm_canonical()` that `offset + atom_len <= len(clvm_buffer)` before treating the atom as consumed. Wrap the whole canonical check (or the call sites in `validate_spend_bundle`) so any unexpected exception is converted into `Err.INVALID_COIN_SOLUTION` rather than propagating as an unhandled exception out of mempool admission.

### Proof of Concept
Not fully constructed/verified — see Likelihood Explanation. The mechanism is: craft `coin_spend.puzzle_reveal` (or `.solution`) bytes that (1) are valid, executable CLVM so `pre_validate_spendbundle` succeeds and produces `conds`, and (2) contain an atom whose header byte falls into one of the multi-byte-prefix branches of `is_atom_canonical` positioned such that either the length-prefix continuation bytes or the computed `atom_len` extend at/beyond the true end of the buffer while `tokens_left` in `is_clvm_canonical` is still nonzero, causing `clvm_buffer[offset]` to be indexed out of range on the next loop iteration and raise an unhandled `IndexError` from inside `MempoolManager.add_spend_bundle`.

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

```python
def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
