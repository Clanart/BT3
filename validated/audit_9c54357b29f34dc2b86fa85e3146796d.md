### Title
Payout OP_RETURN operator attribution is unauthenticated, allowing reimbursement credit theft between operators - ([File: core/src/verifier.rs])

### Summary
`Verifier::update_finalized_payouts` attributes a confirmed payout tx to whichever operator xonly pubkey appears in its OP_RETURN output, but that field is never covered by any signature. Because the user's `SinglePlusAnyoneCanPay` signature on the payout tx's input 0 only commits to input 0 and output 0, anyone possessing that signature (including the withdrawing user, an allowed unprivileged attacker) can build and broadcast an alternate payout tx that keeps input 0/output 0 unchanged but swaps the OP_RETURN operator pubkey for a different, uninvolved operator, making that operator falsely eligible for reimbursement.

### Finding Description
The claimed invariant is: `withdrawals.payout_payer_operator_xonly_pk == xonly_pk(operator whose funds actually financed output 0 of the mined payout tx)`.

`create_payout_txhandler` builds the payout tx with input 0 = withdrawal UTXO (key-spend, signed by the user with `SinglePlusAnyoneCanPay`), output 0 = user payout, output 1 = anchor, output 2 = OP_RETURN with `operator_xonly_pk.serialize()`: [1](#0-0) 

`SinglePlusAnyoneCanPay` only commits to input 0's prevout/amount/scriptPubkey/sequence and to output 0 (SIGHASH_SINGLE binds only the output at the signer's own input index); it explicitly does not cover other inputs or outputs, as shown by the manual sighash construction used elsewhere in the codebase: [2](#0-1) 

`Operator::withdraw` verifies exactly this: it recomputes the sighash for input 0 only and checks the Schnorr signature against it, then funds the rest of the tx (including output 2's OP_RETURN with its own xonly pubkey) via `fund_raw_transaction`: [3](#0-2) 

Later, when the Bitcoin syncer scans a confirmed block, `update_finalized_payouts` finds "the payout tx" purely by matching the recorded withdrawal outpoint against spent UTXOs on-chain (`get_payout_txs_for_withdrawal_utxos`, joined via `bitcoin_syncer_spent_utxos`), with no check on who authored/funded that tx: [4](#0-3) 

It then parses whatever OP_RETURN bytes are present in that on-chain tx and treats the parsed 32 bytes as an authoritative xonly pubkey identifying "the paying operator," with no signature check tying that pubkey to the funding inputs: [5](#0-4) 

This value is persisted as `payout_payer_operator_xonly_pk`: [6](#0-5) 

**Exploit flow:** The withdrawing user (an unprivileged attacker under the stated threat model — they legitimately hold their own `SinglePlusAnyoneCanPay` signature over the withdrawal input/output, since they generated it to submit to `withdraw`) constructs their own clone of the payout transaction:
- Input 0: the exact withdrawal UTXO and witness (unchanged — the signature stays valid because it only commits to input 0/output 0).
- Output 0: unchanged (must match exactly, per SIGHASH_SINGLE).
- Any additional funding input(s): supplied and signed by the attacker themselves to cover fees/value (since they cannot reuse Operator A's funding-input signatures, which are signed under a sighash type that *does* commit to the full output set including OP_RETURN, and would break if OP_RETURN changes).
- Output 2 (OP_RETURN): replaced with Operator B's real, registered xonly pubkey instead of Operator A's.

The attacker broadcasts and mines this variant directly on Bitcoin (attacker capability explicitly includes broadcasting BTC transactions and choosing OP_RETURN/script/signature bytes), bypassing any operator RPC (`withdraw`, `is_profitable`, verification-signature checks) entirely, since `update_finalized_payouts` only looks at what actually confirmed on-chain for the recorded withdrawal outpoint.

**Why existing guards fail:**
- `Operator::is_profitable` / verification-signature checks in `withdraw()` (`core/src/rpc/operator.rs`) only apply to the RPC path; a directly broadcast transaction never goes through them.
- `Verifier::is_kickoff_malicious` only compares the kickoff's `operator_xonly_pk` against the DB's `payout_payer_operator_xonly_pk` — since Operator B's own kickoff naturally carries B's own key, this matches the (poisoned) DB value and passes: [7](#0-6) 
- Nothing in `update_finalized_payouts` verifies that the OP_RETURN pubkey corresponds to the entity that supplied the additional funding inputs of the payout tx.

### Impact Explanation
`PayoutCheckerTask::run_once` looks up unhandled payouts scoped to `self.operator.signer.xonly_public_key` and, once matched, drives the operator through `handle_finalized_payout` → kickoff → the reimbursement/round-end flow: [8](#0-7) 

If Operator B's key is planted in the payout's OP_RETURN, `get_first_unhandled_payout_by_operator_xonly_pk(B)` returns the withdrawal index, and B proceeds to be reimbursed for a payout it never made — matching the Critical category "an operator reimbursed for a payout it never funded." Simultaneously, the honest operator that actually fronted the withdrawal (if any) is locked out: `validate_payer_is_operator` strictly compares the DB's payer pubkey to the caller's own key and errors out otherwise, and since Citrea withdrawal indices are one-shot, the honest funder has no path to recover credit for that index — matching "an honest operator permanently unable to be reimbursed." The attack is repeatable across every withdrawal index and requires no operator collusion, only possession of the payout tx's input-0 signature, which the withdrawing user always has.

### Likelihood Explanation
Preconditions are minimal and match the stated threat model exactly: the attacker only needs to be the withdrawing user (or otherwise obtain the `SinglePlusAnyoneCanPay` signature/outpoint, both of which the user generates and submits), and Operator B must be a currently-registered operator (checked via `fetch_operator_keys`, satisfied trivially). The attacker pays only normal Bitcoin transaction fees plus (if they are not simply reusing an operator-funded tx) the cost of funding output 0 themselves, which they recoup since output 0 pays their own chosen address. No majority hashrate, no key compromise, no TLS interception is required — this is a straightforward standard-signature/tx-construction issue reachable by anyone who can broadcast Bitcoin transactions.

### Recommendation
Do not trust the OP_RETURN operator pubkey as unauthenticated metadata. Either (a) require the additional funding input(s) of the payout tx to provably belong to/be spendable only by the operator claimed in OP_RETURN (e.g., by checking that the operator's known collateral/reimbursement wallet address funded the tx), or (b) have the operator co-sign the OP_RETURN output (e.g., extend the signed message set/commit the OP_RETURN payload under a covenant the user's signature also binds to), or (c) cross-check on-chain, at `update_finalized_payouts` time, that the funding input(s) of the mined payout tx are controlled by the xonly pubkey found in OP_RETURN before writing `payout_payer_operator_xonly_pk`.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

    async fn run_once(&mut self) -> Result<Self::Output, BridgeError> {
        let mut dbtx = self.db.begin_transaction().await?;
        let unhandled_payout = self
            .db
            .get_first_unhandled_payout_by_operator_xonly_pk(
                Some(&mut dbtx),
                self.operator.signer.xonly_public_key,
            )
            .await?;

        if unhandled_payout.is_none() {
            return Ok(false);
        }

        let (citrea_idx, move_to_vault_txid, payout_tx_blockhash) =
            unhandled_payout.expect("Must be Some");

        tracing::info!(
            "Unhandled payout found for withdrawal {}, move_txid: {}",
            citrea_idx,
            move_to_vault_txid
        );

        let deposit_data = self
            .db
            .get_deposit_data_with_move_tx(Some(&mut dbtx), move_to_vault_txid)
            .await?;
        if deposit_data.is_none() {
            return Err(eyre::eyre!("Fronted withdrawal for move tx {move_to_vault_txid} found, but the signatures for the deposit are not found in the db.").into());
        }

        let deposit_data = deposit_data.expect("Must be Some");

        let kickoff_txid = self
            .operator
            .handle_finalized_payout(
                &mut dbtx,
                deposit_data.get_deposit_outpoint(),
                payout_tx_blockhash,
            )
            .await?;

        // fetch and save the LCP for if we get challenged and need to provide proof of payout later
        let (_, payout_block_height) = self
            .operator
            .db
            .get_block_info_from_hash(Some(&mut dbtx), payout_tx_blockhash)
            .await?
            .ok_or_eyre("Couldn't find payout blockhash in bitcoin sync")?;

        let _ = self
            .operator
            .citrea_client
            .fetch_validate_and_store_lcp(
                payout_block_height as u64,
                citrea_idx,
                &self.operator.db,
                Some(&mut dbtx),
                self.operator.config.protocol_paramset(),
            )
            .await?;

        #[cfg(feature = "automation")]
        self.operator.end_round(&mut dbtx).await?;

        self.db
            .mark_payout_handled(Some(&mut dbtx), citrea_idx, kickoff_txid)
            .await?;

        dbtx.commit().await?;

        Ok(true)
    }
