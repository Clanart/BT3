### Title
Permanent loss of solver's escrowed payment via unwhitelisted, attacker-controlled input token that blocks `withdraw()` on `onAccept` - (File: `evm/src/apps/intentsv2/IntentsBase.sol` / `evm/src/apps/intentsv2/ExtrinsicIntents.sol`)

### Summary
`IntentGatewayV2` places no restriction on which ERC-20 addresses a user can escrow as `order.inputs` — any user-supplied token contract is accepted at `placeOrder`. When a solver fills a cross-chain order, `_fillCrossChain` (`evm/src/apps/intentsv2/ExtrinsicIntents.sol:89-171`) delivers real output value to the beneficiary and then dispatches a `RedeemEscrow` message back to the source chain, hard-coding the beneficiary of the escrowed input as `msg.sender` (the solver) with no ability to choose an alternate receiving address. On the source chain, `onAccept()` calls `_withdraw()` (`evm/src/apps/intentsv2/IntentsBase.sol:390-425`), which loops over `body.tokens` and uses `safeTransfer` to pay the solver; a single reverting/blacklisting token in that list reverts the entire `withdraw()` call.

### Finding Description
This mirrors the CrabNetting bug class: a loop that must fully succeed to release funds, where any single failing transfer element (attacker-controlled) blocks the whole release. In `_withdraw`:

```solidity
// evm/src/apps/intentsv2/IntentsBase.sol:394-409
for (uint256 i; i < len; i++) {
    address token = address(uint160(uint256(body.tokens[i].token)));
    uint256 amount = body.tokens[i].amount;
    if (amount == 0) continue;
    uint256 escrowed = _orders[body.commitment][token];
    if (escrowed == 0) revert UnknownOrder();
    _orders[body.commitment][token] = escrowed - amount;
    if (token == address(0)) {
        (bool sent,) = beneficiary.call{value: amount}("");
        if (!sent) revert InsufficientNativeToken();
    } else {
        IERC20(token).safeTransfer(beneficiary, amount);
    }
}
```

Because the escrow input token is chosen entirely by the order's creator (attacker) at `placeOrder` time with no whitelist check, the attacker can escrow a malicious ERC-20 whose `transfer` reverts (unconditionally, or conditionally once a solver has been locked in as beneficiary). The solver has no way to know this in advance from a standard-looking order, and the beneficiary of the redeem message is forced to be `msg.sender` (`ExtrinsicIntents.sol:144`) — the solver cannot redirect payout to a different, unaffected address.

`EvmHost.dispatchIncoming` (the POST-request delivery path) treats a failing `onAccept` call as "retry later" by deleting the request receipt (`evm/src/core/EvmHost.sol:811-816`), exactly like the `HandlerV2`/timeout retry model — but here retrying does not help because the same malicious token transfer will fail every time. There is no rescue path, no per-token skip-and-continue, and no owner override to force-release escrow to the rightful beneficiary once one token in the list is permanently non-transferable — the same missing "rescue function" gap the H-2 report calls out.

### Impact Explanation
The solver has already paid real value on the destination chain (delivering output tokens to the order's beneficiary) before the source-chain settlement message is even dispatched. If the escrowed input token on the source chain is malicious/blacklist-capable, the solver's reward becomes permanently unclaimable — the escrow is frozen forever in the `IntentGatewayV2` contract, with no owner or retry mechanism able to release it to the rightful (or any alternate) beneficiary. This is a direct, permanent loss of funds for an unprivileged, honest counterparty (the solver), triggered purely by an unprivileged attacker (the order creator) choosing the input token.

### Likelihood Explanation
Likelihood is high: placing an order with an arbitrary, attacker-deployed token as one of the `inputs` requires no special privilege, no relayer/prover/governance collusion, and no front-running — it is a standard `placeOrder` call. The only precondition is that a solver decides to fill the order without recognizing the token as malicious, which is realistic since solvers are incentivized to fill profitable-looking orders quickly and the escrow-side token contract is not vetted by the protocol.

### Recommendation
- Do not let a single token transfer failure in `_withdraw`'s loop revert the whole payout; attempt each transfer with try/catch (or low-level call) and skip failed entries, tracking them for later manual resolution — mirroring the report's `try/catch`-and-skip recommendation.
- Provide a governance/owner rescue path (via a Hyperbridge-authenticated admin request, consistent with the existing `onAccept` governance pattern already used for `UpdateParams`/`SweepDust`) to force-resolve a stuck escrow entry to the correct beneficiary or an alternate address.
- Consider allowing the beneficiary of a `RedeemEscrow`/`RefundEscrow` withdrawal to be re-specified (e.g., solver-signed redirection) so a solver whose primary address becomes unable to receive a specific token is not permanently locked out.

### Proof of Concept
1. Attacker deploys `EvilToken`, an ERC-20 whose `transfer` reverts whenever the recipient equals a specific "solver" address (or reverts unconditionally, to hit *any* solver).
2. Attacker calls `placeOrder` on the source chain with `order.inputs` including `EvilToken` as one of the escrowed tokens, offering an attractive output on the destination chain.
3. An honest solver calls `fillOrder` on the destination chain (`ExtrinsicIntents.sol:_fillCrossChain`), delivering the required output tokens to the order's beneficiary and dispatching `RedeemEscrow{commitment, tokens: order.inputs, beneficiary: solver}` back to the source chain.
4. On the source chain, `onAccept` invokes `withdraw`/`_withdraw`; the loop reaches `EvilToken.safeTransfer(solver, amount)`, which reverts, causing the whole `onAccept` call — and thus the whole message delivery — to fail.
5. `EvmHost.dispatchIncoming` deletes the request receipt so delivery can be retried (`EvmHost.sol:811-816`), but every retry hits the same revert. The solver's escrowed reward, and the attacker's escrowed non-EvilToken inputs, remain permanently locked in `IntentGatewayV2` with no recovery path. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3)

    function _fillCrossChain(Order calldata order, FillOptions calldata options, bytes32 commitment) internal {
        uint256 outputsLen = order.output.assets.length;

        _filled[commitment] = msg.sender;

        uint256 msgValue = msg.value;
        address beneficiary = address(uint160(uint256(order.output.beneficiary)));
        TokenInfo[] memory outputFills = new TokenInfo[](outputsLen);

        for (uint256 i; i < outputsLen; i++) {
            bytes32 outputToken = order.output.assets[i].token;
            if (options.outputs[i].token != outputToken) revert InvalidInput();

            address token = address(uint160(uint256(outputToken)));
            uint256 totalRequired = order.output.assets[i].amount;
            uint256 solverAmount = options.outputs[i].amount;

            if (solverAmount < totalRequired) revert InvalidInput();

            uint256 dust = solverAmount - totalRequired;
            uint256 beneficiaryShare = 0;
            uint256 protocolShare = 0;

            if (dust > 0) {
                if (order.output.call.length > 0) {
                    protocolShare = dust;
                } else {
                    protocolShare = (dust * _params.surplusShareBps) / 10_000;
                    beneficiaryShare = dust - protocolShare;
                }
            }

            if (token == address(0)) {
                if (msgValue < solverAmount) revert InsufficientNativeToken();
                uint256 beneficiaryTotal = totalRequired + beneficiaryShare;
                (bool sent,) = beneficiary.call{value: beneficiaryTotal}("");
                if (!sent) revert InsufficientNativeToken();
                msgValue -= (beneficiaryTotal + protocolShare);
            } else {
                IERC20(token).safeTransferFrom(msg.sender, beneficiary, totalRequired + beneficiaryShare);
                if (protocolShare > 0) {
                    IERC20(token).safeTransferFrom(msg.sender, address(this), protocolShare);
                }
            }
            if (protocolShare > 0) emit DustCollected(token, protocolShare);
            outputFills[i] = TokenInfo({token: outputToken, amount: totalRequired});
        }

        _execute(order, outputsLen);

        address hostAddr = host();
        bytes memory body = bytes.concat(
            bytes1(uint8(RequestKind.RedeemEscrow)),
            abi.encode(
                WithdrawalRequest({
                    commitment: commitment, tokens: order.inputs, beneficiary: bytes32(uint256(uint160(msg.sender)))
                })
            )
        );
        DispatchPost memory request = DispatchPost({
            dest: order.source,
            to: abi.encodePacked(_instance(order.source)),
            body: body,
            timeout: 0,
            fee: options.relayerFee,
            payer: msg.sender
        });

        if (options.nativeDispatchFee > 0 && msgValue >= options.nativeDispatchFee) {
            IDispatcher(hostAddr).dispatch{value: options.nativeDispatchFee}(request);
            msgValue -= options.nativeDispatchFee;
        } else {
            dispatchWithFeeToken(request);
        }

        // Refund any unspent native tokens to the solver.
        if (msgValue > 0) {
            (bool sent,) = msg.sender.call{value: msgValue}("");
            if (!sent) revert InsufficientNativeToken();
        }

        emit OrderFilled({commitment: commitment, filler: msg.sender, outputs: outputFills, inputs: order.inputs});
    }

    function withdraw(WithdrawalRequest memory body, bool isRefund) internal {
        address beneficiary = address(uint160(uint256(body.beneficiary)));
        _filled[body.commitment] = beneficiary;

        // redeem escrowed tokens
        uint256 len = body.tokens.length;
        for (uint256 i; i < len;) {
            address token = address(uint160(uint256(body.tokens[i].token)));
            uint256 amount = body.tokens[i].amount;
            if (_orders[body.commitment][token] == 0) revert UnknownOrder();

            if (token == address(0)) {
                (bool sent,) = beneficiary.call{value: amount}("");
                if (!sent) revert InsufficientNativeToken();
            } else {
                (bool success,) = token.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, amount));
                if (!success) revert TransferFailed();
            }

            _orders[body.commitment][token] -= amount;
            unchecked {
                ++i;
            }
        }

        // redeem tx fees
        uint256 fees = _orders[body.commitment][TRANSACTION_FEES];
        if (fees > 0) {
            address feeToken = IDispatcher(host()).feeToken();
            (bool success,) = feeToken.call(abi.encodeWithSelector(IERC20.transfer.selector, beneficiary, fees));
            if (!success) revert TransferFailed();
            delete _orders[body.commitment][TRANSACTION_FEES];
        }

        if (isRefund) {
            emit EscrowRefunded({commitment: body.commitment});
        } else {
            emit EscrowReleased({commitment: body.commitment});
        }
    }
