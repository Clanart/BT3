### Title
Unauthenticated OP_RETURN operator-attribution in the Payout transaction lets any withdrawal-UTXO owner redirect bridge reimbursement credit to an operator who never funded the payout - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
`create_payout_txhandler` embeds the "fronting operator" `xonly_pk` in an OP_RETURN output that is not covered by the user's `SinglePlusAnyoneCanPay` signature, so whoever assembles/broadcasts the final Payout transaction can write any `xonly_pk` there, independent of who actually paid the top-up. Downstream code (`update_finalized_payouts`, `get_first_unhandled_payout_by_operator_xonly_pk`, `is_kickoff_malicious`) trusts this unauthenticated field as the sole record of "who fronted the withdrawal," breaking the attribution binding that is supposed to equal the real funder.

### Finding Description
Binding claimed: `payout_payer_operator_xonly_pk` recorded for withdrawal `i` == the entity whose Bitcoin funds actually paid the payout output for withdrawal `i`.

- `create_payout_txhandler` builds a single-input Payout tx: input = withdrawal UTXO (KeySpend), output0 = user payout, output1 = anchor, output2 = OP_RETURN containing `operator_xonly_pk.serialize()` [3](#0-2) . Only `input0`/`output0` is signed by the user (`set_p2tr_key_spend_witness`), and the wrap_err message explicitly documents the sighash type as `SinglePlusAnyoneCanPay` [2](#0-1) . Under BIP341/BIP143 semantics, `SIGHASH_SINGLE` commits only to the output at the signed input's index (output0); `ANYONECANPAY` additionally allows arbitrary other inputs. Outputs 1 and 2 (anchor, OP_RETURN) are **not** covered by the signature.
- Because the `operator_xonly_pk` argument is a bare, unsigned parameter chosen by whoever calls `create_payout_txhandler`/assembles the final tx, anyone holding a valid user signature over the withdrawal UTXO (the withdrawing user themselves, who is explicitly granted this capability by the attacker model — "choose the bytes of a withdrawal UTXO, a Schnorr signature and its sighash flag") can build and broadcast their own competing Payout tx for the same registered `withdrawal_utxo`, self-funding any extra inputs needed (allowed by ANYONECANPAY), and writing an arbitrary `xonly_pk` — belonging to an operator who did nothing — into the OP_RETURN.

```rust
pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}
```
