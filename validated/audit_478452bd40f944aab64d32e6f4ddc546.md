## Title
Governance rate change in `update_cost_per_block()` retroactively re-prices already-accrued relayer rewards, draining the treasury — (`modules/pallets/consensus-incentives/src/lib.rs`, `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet-consensus-incentives::update_cost_per_block()` directly mutates `StateMachinesCostPerBlock` without first settling ("checkpointing") the reward owed for the block span that has already accrued under the old rate. The next `on_executed` call then computes `reward = (latest_height - baseline) * new_cost_per_block`, applying the **new** rate to the **entire unpaid span**, including all blocks that accrued before the rate change. This is the same class of bug as the external report's `setProtocolFeeRate()` — a rate parameter is updated in isolation without invoking the equivalent of `updateInterestRatesAndLiquidity()` to settle/checkpoint the state that depends on the old rate first.

### Finding Description
The reward formula and its state are defined in `modules/pallets/consensus-incentives/src/impls.rs`: [1](#0-0) 

`calculate_reward` takes the `baseline` (the `LastRewardedHeight` watermark, or `previous_commitment_height` if none was ever paid) and the `latest_height`, and multiplies the entire `blocks = latest_height - baseline` span by whatever `block_cost` is passed in — which is always the value currently stored in `StateMachinesCostPerBlock`: [2](#0-1) 

Governance updates that rate with `update_cost_per_block`, which performs a bare `mutate` with no side effect on `LastRewardedHeight` and no reward flush for the span accrued so far: [3](#0-2) 

Contrast this with the correct pattern used elsewhere in the report's RAAC analog (`ReserveLibrary.setPrimeRate()`), which immediately calls `updateInterestRatesAndLiquidity()` to settle state under the old parameter before the new one takes effect. `update_cost_per_block` has no equivalent settlement step — it never calls `process_message`/`calculate_reward` to pay out the pending span at the *old* rate before switching to the new one. `LastRewardedHeight` is only advanced inside `process_message`, which only runs on the next `on_executed` (i.e., the next relayer-submitted consensus message), by which point the rate has already changed.

Because `blocks = latest_height - baseline` spans across the entire unpaid history (which can be arbitrarily large — e.g., a chain that hasn't been rewarded in a while, or one where governance has just enabled incentives after some blocks already advanced), a rate change is applied uniformly to that whole span rather than only to blocks going forward.

### Impact Explanation
Any permissionless relayer submitting a consensus proof is who gets paid the reward (identified via signature recovery, not privilege-gated): [4](#0-3) 

If governance raises `cost_per_block` for a state machine, whoever submits the *next* consensus update collects `(latest_height - baseline) * new_cost` from the treasury — paying the new, higher rate for a potentially large backlog of blocks that should have been priced at the old (lower) rate. This is a direct, unauthorized over-transfer of treasury funds to an ordinary, permissionless relayer, not requiring any node compromise, admin collusion, or malicious peer behavior — only observing a public governance extrinsic and timing an already-permitted action (submitting the consensus proof) after it lands. The treasury transfer is executed unconditionally once the reward is nonzero: [5](#0-4) 

### Likelihood Explanation
`update_cost_per_block` is a normal, expected governance operation (rates are meant to be tunable), so the precondition (a rate change happening while a backlog of unrewarded blocks exists) is common rather than contrived — it happens on every rate adjustment unless a relayer happens to have delivered a proof in the exact same block. Any relayer can simply wait for a publicly-visible `StateMachineCostPerBlockUpdated` event and then submit (or delay submitting) its next consensus proof to capture the mispriced backlog, with no special access required.

### Recommendation
Before writing the new `cost_per_block`, checkpoint the pending reward for the affected state machine at the *current* rate: fetch `latest_commitment_height` and `LastRewardedHeight`, pay/accrue the outstanding span at the old rate (or at minimum advance `LastRewardedHeight` to `latest_commitment_height` without paying, if a lossless split isn't desired), and only then apply the new `cost_per_block`. This mirrors adding the missing `updateInterestRatesAndLiquidity()` call in the original report — settle dependent state under the old parameter before switching to the new one.

### Proof of Concept
1. Chain `X` advances from height 1000 to height 2000 with `cost_per_block = 1` and no relayer submits a consensus update in between (so `LastRewardedHeight` stays at 1000 / unset).
2. Governance calls `update_cost_per_block(X, 1000)` — a 1000x increase — intending it to apply only to future blocks.
3. A relayer (any address, no special privilege) now submits a consensus proof advancing to height 2000.
4. `on_executed` → `process_message` → `calculate_reward` computes `blocks = 2000 - 1000 = 1000`, `reward = 1000 * 1000 = 1,000,000`, transferred from `TreasuryAccount` to the relayer — 1000x more than the protocol intended for that already-accrued backlog, confirmed by the test harness pattern in `modules/pallets/testsuite/src/tests/pallet_consensus_incentives.rs` (`test_incentivize_relayer`, `reward_covers_only_unpaid_heights_after_rollback`), which shows the reward is always `(latest - baseline) * current_cost_per_block` with no rate-checkpointing step. 	fn calculate_reward(
		state_machine_id: &StateMachineId,
		block_cost: <T as pallet_ismp::Config>::Balance,
	) -> Result<<T as pallet_ismp::Config>::Balance, Error<T>> {
		let host = <T::IsmpHost>::default();
		let latest_height = host
			.latest_commitment_height(state_machine_id.clone())
			.map_err(|_| Error::<T>::CouldNotGetStateMachineHeight)?;
		let previous_height =
			host.previous_commitment_height(state_machine_id.clone()).unwrap_or_default();

		// Use the rewarded watermark as the baseline and fall back to the previous height until
		// the first reward is recorded for this chain. The watermark only moves forward, so a
		// height that is rolled back and later resubmitted is not paid for a second time.
		let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);

		let blocks = latest_height.saturating_sub(baseline);

		let blocks_as_balance: <T as pallet_ismp::Config>::Balance = blocks.saturated_into();
		let reward = blocks_as_balance.saturating_mul(block_cost);

		Ok(reward)
	}

	#[pallet::call]
	impl<T: Config> Pallet<T> {
		/// Update cost per block for a state machine
		#[pallet::call_index(0)]
		#[pallet::weight(T::WeightInfo::update_cost_per_block())]
		pub fn update_cost_per_block(
			origin: OriginFor<T>,
			state_machine_id: StateMachineId,
			cost_per_block: <T as pallet_ismp::Config>::Balance,
		) -> DispatchResult {
			T::IncentivesOrigin::ensure_origin(origin)?;

			StateMachinesCostPerBlock::<T>::mutate(state_machine_id.clone(), |maybe_cost| {
				*maybe_cost = Some(cost_per_block);
			});

			Self::deposit_event(Event::<T>::StateMachineCostPerBlockUpdated {
				state_machine_id,
				cost_per_block,
			});

			Ok(())
		}
