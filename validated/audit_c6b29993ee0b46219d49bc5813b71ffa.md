### Title
`ReceivedOutput::read` accepts an arbitrary offset/outpoint pair with no consistency check, letting crafted bytes report funds the wallet cannot spend - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
The jqueryFileTree advisory is a directory traversal: an attacker-supplied `dir` parameter escapes the intended root because the server resolves it without validating that the result stays in-bounds. The analog in Serai is `ReceivedOutput::read`, which deserializes a `(offset, TxOut, OutPoint)` triple from untrusted bytes and accepts it as a "received output" without ever validating the one invariant that makes the record meaningful: that `output.script_pubkey == p2tr_script_buf(group_key + G * offset)`. Like the traversal, attacker-controlled input is accepted as identifying a resource (a spendable output) without checking it resolves to the intended location.

### Finding Description
`ReceivedOutput` couples a scalar `offset` with a Bitcoin `TxOut`/`OutPoint`. The only producer that establishes correctness is `Scanner::scan_transaction`, which only constructs a `ReceivedOutput` after matching `output.script_pubkey` against the `scripts` map built from `key + G * offset` via `register_offset`/`Scanner::new` ( [1](#0-0) ). `p2tr_script_buf` requires the tweaked key to be even-Y ( [2](#0-1) ), which is why `register_offset` increments odd offsets ( [3](#0-2) ).

`ReceivedOutput::read`, however, performs no such check — it reads any canonical scalar as `offset` and any consensus-valid `TxOut`/`OutPoint` ( [4](#0-3) ). Downstream, the processor trusts the pairing: `Output::key()` reconstructs the spending key as `script_key - G * offset` ( [5](#0-4) ), and signing applies `output.offset()` to the FROST key. If `offset` does not actually map to `script_pubkey`, the derived key is wrong, the threshold signature is produced for a key that does not control the UTXO, and the output is unspendable despite being reported as received.

### Impact Explanation
An attacker who can feed crafted bytes to `ReceivedOutput::read` causes a mismatch between the reported output and the key material needed to spend it: funds are reported received (balance credited via `output.value()` / `ExternalBalance`) yet are not spendable, and any spend attempt produces an invalid transaction. This satisfies the "funds reported received that are not spendable" impact class.

### Likelihood Explanation
Reachable wherever serialized `ReceivedOutput`s cross a trust boundary (e.g., data restored or relayed rather than produced by the local `Scanner`). It requires no key knowledge — only canonical scalar and consensus encodings — but does require an attacker to reach the deserialization path, so it is less likely than a purely remote attack. Medium.

### Recommendation
Have `ReceivedOutput::read` take the group `key` (or a `Scanner`) and reject any record where `p2tr_script_buf(key + G * offset) != output.script_pubkey`, mirroring the check `Scanner::scan_transaction` performs. Alternatively, store/derive the offset from the script rather than trusting it from the byte stream.

### Proof of Concept
```rust
// Craft a ReceivedOutput whose offset does not correspond to script_pubkey.
let real_offset = scanner.register_offset(Scalar::random(&mut OsRng)).unwrap();
let mut crafted = received_output.clone();           // scanned legitimately
// Re-serialize with a different offset for the same TxOut:
let mut buf = vec![];
buf.extend((real_offset + Scalar::ONE).to_bytes());  // wrong offset
buf.extend(&serialize(received_output.output()));    // unchanged TxOut
buf.extend(&serialize(received_output.outpoint()));
let forged = ReceivedOutput::read(&mut buf.as_slice()).unwrap(); // accepted
// forged.key() = script_key - G*(real_offset+1) != group key -> unspendable
```

  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
