### Title
Unbounded Offset/Length Parsing in CLVM Canonical-Serialization Check Enables Spend-Triggered Mempool Processing Halt - (File: chia/full_node/mempool_manager.py)

### Summary
`is_atom_canonical()` and `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` walk an attacker-supplied CLVM buffer (from a submitted spend bundle's puzzle reveal/solution) computing atom lengths and advancing an `offset` index, but never validate that `offset` (or `offset + prefix_len`, or the final `atom_len`) stays within the bounds of `clvm_buffer` before indexing into it. [1](#0-0) 

### Finding Description
`is_atom_canonical` reads `clvm_buffer[offset]` and then, based on the top bits of that byte, loops `prefix_len` times incrementing `offset` and indexing `clvm_buffer[offset]` again to build up `atom_len`, with no bounds check that `offset` is still `< len(clvm_buffer)`: [1](#0-0) 

`is_clvm_canonical` drives this in a loop, advancing `offset` by the returned `atom_len` and continuing to index `clvm_buffer[offset]` on the next iteration, again without checking that the computed length keeps `offset` inside the buffer before the next read: [2](#0-1) 

This is structurally the same bug class as the reported GStreamer AV1 issue: a length value taken from untrusted, attacker-controlled input is used to advance a cursor/copy operation without first validating it against the size of the buffer being read. In this codebase's hardened parsers (e.g. `skip_bytes`, `skip_list`, and the generator-buffer parsing in `chia/full_node/full_block_utils.py`) every length read from the wire is explicitly checked against the remaining buffer size (`if n > len(buf): raise ValueError(...)`) before it is used to slice or advance. `is_atom_canonical`/`is_clvm_canonical` lack this check entirely, allowing a crafted, malformed atom-length encoding embedded in a CLVM program (reachable via a submitted spend bundle's puzzle reveal or solution) to walk `offset` past the end of `clvm_buffer`, raising an unhandled `IndexError` inside CLVM canonical-form checking during spend-bundle processing.

### Impact Explanation
If this uncaught `IndexError` propagates out of the mempool/spend-bundle validation pipeline that invokes `is_clvm_canonical`, an unprivileged spend-bundle submitter can trigger an exception during transaction processing simply by submitting a spend bundle containing a puzzle/solution with a malformed atom-length prefix. Depending on where exceptions are caught in the calling path, this maps to a spend-triggered transaction-processing halt/DoS rather than memory corruption (Python has no true heap overflow), which is the closest in-scope, reachable analog to the reported "unvalidated length prior to copy" bug class.

### Likelihood Explanation
Likelihood depends on whether the caller(s) of `is_clvm_canonical` wrap the call in a broad exception handler that converts any exception into a benign rejection (e.g., `Err.INVALID_SPEND_BUNDLE`) versus letting an `IndexError` propagate and crash/stall the processing coroutine. I was not able to fully trace and confirm the exact call sites and their exception handling before running out of tool budget — the grep only located the two definitions and their references in `chia/full_node/mempool_manager.py` and test files, not the enclosing try/except structure of the caller. This introduces material uncertainty about actual exploitability versus a caught-and-handled edge case.

### Recommendation
Add explicit bounds checks in `is_atom_canonical` (verify `offset + prefix_len < len(clvm_buffer)` before each index, and that `offset + 1 + prefix_len + atom_len <= len(clvm_buffer)`) and in `is_clvm_canonical`'s loop (verify `offset < len(clvm_buffer)` before indexing), raising a well-defined `ValueError`/`Err` instead of allowing an `IndexError` to propagate, mirroring the defensive length checks already used in `chia/full_node/full_block_utils.py`.

### Proof of Concept
Construct a CLVM-serialized buffer whose final byte is a multi-byte atom length prefix (e.g. `0b11111100` class, `prefix_len = 5`) placed near the end of the buffer such that the prefix-length loop in `is_atom_canonical` needs to read bytes beyond `len(clvm_buffer)`. Embed this buffer as (or within) a puzzle reveal/solution of a coin spend in a submitted `SpendBundle`, and submit it through the normal spend-bundle-add path that invokes `is_clvm_canonical`; without a caller-side length check, the parser indexes past the buffer end and raises `IndexError`. def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value


def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
