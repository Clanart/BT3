## Title
DataLayer file-publishing pipeline leaves orphaned/truncated `.dat` files on aborted writes, permanently halting store publication and sync - (File: `chia/data_layer/download_data.py`)

### Summary
`write_files_for_root()` creates delta/full-tree `.dat` files with exclusive-create (`"xb"`) semantics and streams serialized Merkle-tree nodes into them via `DataStore.write_tree_to_file()`. If that streaming write is interrupted by any exception partway through, the partially-written file is left on disk with no cleanup, and the exclusive-create mode then permanently blocks any future correction of that file. This is the same bug class as the Multer advisory: an aborted "upload" (here, a streamed disk write of tree data) is not cleaned up, leaving orphaned/corrupt state that accumulates and disrupts service availability.

### Finding Description
`write_files_for_root()` opens the full-tree and delta files exclusively and writes into them incrementally: [1](#0-0) 

`write_tree_to_file()` performs the actual byte-by-byte writes while pulling key/value blobs from disk (`get_blob_from_file()`, which does a `zstd.decompress()` on a `read_bytes()` result) and from the DB (`get_table_blobs()`), any of which can raise partway through the loop after some `writer.write()` calls have already succeeded: [2](#0-1) [3](#0-2) 

There is no `try/except`/`finally` around the `open(...)`/`write_tree_to_file(...)` calls inside `write_files_for_root()` to delete a partially-written file on failure. The exception propagates out of `write_files_for_root()` unguarded.

The caller, `DataLayer.upload_files()`, only wraps the *uploader HTTP call* section in a try/except that cleans up files — the `write_files_for_root()` call itself sits outside that guard: [4](#0-3) 

So if the write raises, the exception escapes `upload_files()` entirely and is only caught generically (and logged, not remediated) by `update_subscription()`: [5](#0-4) 

Because the file was opened with `"xb"` (exclusive create), the partially-written file now exists on disk. On every subsequent periodic management cycle, `write_files_for_root()` will try to reopen the same path in `"xb"` mode, receive `FileExistsError`, and silently treat it as "already written" (`except FileExistsError: pass`), returning `written=False`/`written_full_file=False` if both files hit that path — this causes `upload_files()`'s loop to `break` on `not write_file_result.result`, permanently and silently stopping traversal of all older generations for that store, not just the corrupted one: [6](#0-5) [7](#0-6) 

The truncated file is never cleaned up or repaired automatically. `DataLayerServer`'s static file handler serves whatever exists under `server_files_location` without validating content, so any peer/Data Layer client fetching that generation will receive a truncated file and fail with `"Incomplete read of length."`/`"Incomplete read of blob."` in `DataStore.read_from_file()`, and the surrounding `insert_from_delta_file()` cleanup only removes locally-downloaded copies, not the source of truth on the serving node: [8](#0-7) 

### Impact Explanation
A single interrupted write (triggerable by a concurrency/locking race the module's own docs flag as unresolved — "File-system writes for Merkle blobs, key/value blobs, and `.dat` files have TODOs around locking... Concurrent service/plugin/server access should be treated as a real consistency concern" — or by a transient I/O error, missing/corrupted key-value blob file, or `MerkleBlobNotFoundError`) leaves an unrecoverable, permanently truncated `.dat` file. This:
- Halts publication of all older generations for the affected store on every future management cycle (early `break`), a persistent, spend-triggered/store-triggered transaction-processing-adjacent halt of the Data Layer sync/publish pipeline for that store.
- Causes any Data Layer client fetching that generation to repeatedly fail sync with parse errors, since the served file is truncated and cannot self-heal.
- Requires manual operator intervention (deleting the corrupt file) to recover — matching CWE-459 (Incomplete Cleanup) and the DoS impact class of the referenced Multer advisory (orphaned partial artifacts from aborted writes degrading availability).

### Likelihood Explanation
The write path runs on every periodic `update_subscription()` cycle for every owned/subscribed store (`upload_files()`/`add_missing_files()`), so any condition that raises mid-write during `write_tree_to_file()` (disk contention, concurrent Merkle-blob/kv-blob access acknowledged as an open TODO in the module, or malformed data reaching local store state via offer processing/delta-file ingestion) reliably reproduces the stuck state due to the deterministic `"xb"`+swallowed-`FileExistsError` combination.

### Recommendation
- Wrap the file-writing section of `write_files_for_root()` in a `try/except`/`finally` that deletes the target file(s) on any exception before re-raising, mirroring the cleanup already done in `insert_from_delta_file()`.
- Avoid using bare exclusive-create semantics as an implicit "already correctly written" signal; instead verify file completeness (e.g., re-derive/verify against the expected root hash) before treating an existing file as valid, or write to a temp path and atomically rename on success.
- Ensure `upload_files()`/`add_missing_files()` treat a write failure differently from "file already exists and is correct" so older generations are still attempted.

### Proof of Concept
1. Configure a store with `maximum_full_file_count` such that a full-tree file is due for generation.
2. During a management cycle's call to `write_files_for_root()`, force `get_blob_from_file()` (or `get_table_blobs()`) to raise partway through iterating a tree with multiple nodes (e.g., by deleting/corrupting a key-value blob file referenced mid-tree, simulating the concurrency race the code's own TODO acknowledges).
3. Observe: a truncated `.dat` file is left at `filename_full_tree`/`filename_diff_tree`; `upload_files()` raises and is only caught/logged by `update_subscription()`.
4. On the next cycle, observe `write_files_for_root()` hits `FileExistsError` on the same path and returns `written=False`, causing `upload_files()` to `break` immediately — no older generations get published, and the corrupted file is never repaired or removed.

    async def write_tree_to_file(
        self,
        root: Root,
        node_hash: bytes32,
        store_id: bytes32,
        deltas_only: bool,
        writer: BinaryIO,
    ) -> None:
        if node_hash == bytes32.zeros:
            return

        with log_exceptions(log=log, message="Error while getting merkle blob"):
            root_path = self.get_merkle_path(store_id=store_id, root_hash=root.node_hash)
        delta_file_cache = DeltaFileCache(root_path)

        if root.generation > 0:
            previous_root = await self.get_tree_root(store_id=store_id, generation=root.generation - 1)
            if previous_root.node_hash is not None:
                with log_exceptions(log=log, message="Error while getting previous merkle blob"):
                    previous_root_path = self.get_merkle_path(store_id=store_id, root_hash=previous_root.node_hash)
                delta_file_cache.load_previous_hashes(previous_root_path)

        tree_nodes: list[SerializedNode] = []

        await self.get_nodes_for_file(root, node_hash, store_id, deltas_only, delta_file_cache, tree_nodes)
        kv_ids = (
            KeyOrValueId.from_bytes(raw_id)
            for node in tree_nodes
            if node.is_terminal
            for raw_id in (node.value1, node.value2)
        )
        table_blobs = await self.get_table_blobs(kv_ids, store_id)

        for node in tree_nodes:
            if node.is_terminal:
                blobs = []
                for raw_id in (node.value1, node.value2):
                    id = KeyOrValueId.from_bytes(raw_id)
                    blob_hash, blob = table_blobs[id]
                    if blob is None:
                        blob = self.get_blob_from_file(blob_hash, store_id)
                    blobs.append(blob)
                to_write = bytes(SerializedNode(True, blobs[0], blobs[1]))
            else:
                to_write = bytes(node)
            writer.write(len(to_write).to_bytes(4, byteorder="big"))
            writer.write(to_write)
