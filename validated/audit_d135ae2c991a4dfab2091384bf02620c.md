### Title
Missing owner/approval check in the ERC721→CW721 pointer's `transfer_nft` allows unauthorized NFT transfer - (File: example/cosmwasm/cw721/src/contract.rs)

### Summary
The CosmWasm-side CW721 pointer contract that wraps a real EVM ERC721 token (used for the "ERC721 exposed as CW721" pointer flow) builds and dispatches an EVM `transferFrom(owner, recipient, tokenId)` call using the *actual on-chain owner* of the token, but never checks that the CW message sender (`info.sender`) is that owner or is approved by that owner. Any Sei account can invoke `transfer_nft`/`send_nft` for any token ID owned by anyone and redirect it to an arbitrary recipient, as long as the real owner has ever granted the pointer contract's EVM address operator rights on the underlying ERC721 (which is the normal, expected setup for using this pointer at all).

### Finding Description
`transfer_nft` in `example/cosmwasm/cw721/src/contract.rs` resolves the real token owner via a query and then constructs a `transferFrom` payload using that owner as `from`, completely independent of who called the CW message: [1](#0-0) 

`execute_transfer_nft` / `execute_send_nft` pass `info` straight into `transfer_nft` but the function never compares `info.sender` to the resolved `owner`, nor checks any approval relationship between `info.sender` and `owner`: [2](#0-1) 

The owner lookup itself, `HandleERC721Owner`, performs a plain `ownerOf` static call and returns the true owner regardless of who issued the query - it is not an authorization check, it's just data retrieval: [3](#0-2) 

The resulting transfer payload is built purely from the queried owner and the caller-supplied recipient, with no linkage back to `info.sender`: [4](#0-3) 

The message is finally dispatched as `EvmMsg::DelegateCallEvm { to: erc_addr, ... }`, i.e. executed as if the pointer's own EVM identity called `transferFrom` on the real ERC721 contract. Because the actual authorization check in the underlying ERC721 (`_isApprovedOrOwner`) only verifies that the pointer contract's own address is approved/operator for `from`, once an owner grants the pointer's EVM address `setApprovalForAll` (a normal step required to make the CW pointer usable at all), the pointer's own privilege is sufficient for the transfer to succeed - `info.sender`'s identity is irrelevant to the check. Contrast this with the parallel `approve`/`approve_all` handlers, which also never validate `info.sender` against ownership, compounding the issue by letting an attacker even set approvals on someone else's token via the pointer: [5](#0-4) 

This is the sei-chain analog of the reported bug class: rather than a *missing approval causing reverts/stuck NFTs*, the missing-authorization-check pattern here inverts the risk into *unauthorized transfers*, which is an even higher-impact variant of the same root cause (a pointer/bridge contract mismanaging ERC721 ownership/approval semantics when relaying a transfer).

### Impact Explanation
Once a legitimate NFT owner sets `setApprovalForAll` for the pointer's EVM address on the real ERC721 contract (the documented/expected pattern to make the CW-side pointer functional for that owner), any other unprivileged Sei account can call `transfer_nft` (or `send_nft`) on the pointer contract specifying that owner's token ID and any recipient, stealing the NFT without any signature or authorization from the true owner. This is a direct unauthorized-transfer / fund-loss condition via a CW↔EVM pointer, matching the "unauthorized transfer via precompile or pointer" impact criterion.

### Likelihood Explanation
Likelihood is high for any user of this pointer type: granting the pointer contract operator rights over one's ERC721 tokens is the normal, expected step to interact with the CW-side wrapper (mint/transfer via CW messages), so any owner using the pointer as intended is immediately exposed. No special conditions beyond "user has approved the pointer once" are required, and exploitation is a single permissionless `MsgExecuteContract` call specifying an arbitrary `token_id`/`recipient`.

### Recommendation
In `transfer_nft` (and `execute_approve`/`execute_approve_all`), require that `info.sender` equals the resolved `owner`, or is explicitly approved for that specific token / operator-approved by that owner (mirroring standard CW721/ERC721 semantics), before constructing and dispatching the EVM payload. Concretely, add a check comparable to:
```rust
let owner = querier.erc721_owner(info.sender.to_string(), erc_addr.to_string(), token_id.to_string())?.owner;
if info.sender.to_string() != owner {
    // also check erc721_is_approved_for_all / per-token approval for info.sender
    return Err(ContractError::Unauthorized {});
}
```
before building `erc721_transfer_payload`.

### Proof of Concept
1. Owner `A` deploys/uses the ERC721→CW721 pointer for their real ERC721 token `T` (token ID `N`) and, as required for pointer functionality, calls `setApprovalForAll(pointerEvmAddress, true)` on the real ERC721 contract.
2. Attacker `B` (an unrelated, unprivileged Sei account with no approval from `A`) sends `MsgExecuteContract` to the pointer contract with `ExecuteMsg::TransferNft { recipient: B, token_id: N }`.
3. `transfer_nft` queries `erc721_owner` and finds `owner = A` (irrelevant to `info.sender = B`), builds `transferFrom(A, B, N)`, and dispatches it via `DelegateCallEvm`.
4. Because the pointer's EVM address is approved-for-all on `A`'s tokens, the underlying ERC721 `transferFrom` succeeds, transferring token `N` from `A` to `B` with no signature or consent from `A`. [1](#0-0)

pub fn execute_approve(
    deps: DepsMut<EvmQueryWrapper>,
    info: MessageInfo,
    spender: String,
    token_id: String,
    approved: bool,
) -> Result<Response<EvmMsg>, ContractError> {
    let erc_addr = ERC721_ADDRESS.load(deps.storage)?;

    let querier = EvmQuerier::new(&deps.querier);
    let mut payload_spender = spender.clone();
    let mut action = "approve";
    if !approved {
        payload_spender = "".to_string();
        action = "revoke";
    }
    let payload = querier.erc721_approve_payload(payload_spender, token_id.clone())?;
    let msg = EvmMsg::DelegateCallEvm { to: erc_addr, data: payload.encoded_payload };
    let res = Response::new()
        .add_attribute("action", action)
        .add_attribute("token_id", token_id)
        .add_attribute("sender", info.sender)
        .add_attribute("spender", spender.clone())
        .add_message(msg);

    Ok(res)
}

pub fn execute_approve_all(
    deps: DepsMut<EvmQueryWrapper>,
    info: MessageInfo,
    to: String,
    approved: bool,
) -> Result<Response<EvmMsg>, ContractError> {
    let erc_addr = ERC721_ADDRESS.load(deps.storage)?;

    let querier = EvmQuerier::new(&deps.querier);
    let payload = querier.erc721_set_approval_all_payload(to.clone(), approved)?;
    let msg = EvmMsg::DelegateCallEvm { to: erc_addr, data: payload.encoded_payload };
    let mut action = "approve_all";
    if !approved {
        action = "revoke_all";
    }
    let res = Response::new()
        .add_attribute("action", action)
        .add_attribute("operator", to)
        .add_attribute("sender", info.sender)
        .add_attribute("approved", format!("{}", approved))
        .add_message(msg);

    Ok(res)
}

fn transfer_nft(
    deps: DepsMut<EvmQueryWrapper>,
    info: &MessageInfo,
    recipient: &str,
    token_id: &str,
) -> Result<Response<EvmMsg>, ContractError> {
    deps.api.addr_validate(recipient)?;

    let erc_addr = ERC721_ADDRESS.load(deps.storage)?;

    let querier = EvmQuerier::new(&deps.querier);
    let owner = querier.erc721_owner(info.sender.to_string(), erc_addr.to_string(), token_id.to_string())?.owner;
    let payload = querier.erc721_transfer_payload(owner, recipient.to_string(), token_id.to_string())?;
    let msg = EvmMsg::DelegateCallEvm { to: erc_addr, data: payload.encoded_payload };
    let res = Response::new().add_message(msg);

    Ok(res)
}

func (h *EVMQueryHandler) HandleERC721Owner(ctx sdk.Context, caller string, contractAddress string, tokenId string) ([]byte, error) {
	callerAddr, err := sdk.AccAddressFromBech32(caller)
	if err != nil {
		return nil, err
	}
	contract := common.HexToAddress(contractAddress)
	abi, err := cw721.Cw721MetaData.GetAbi()
	if err != nil {
		return nil, err
	}
	t, ok := sdk.NewIntFromString(tokenId)
	if !ok {
		return nil, errors.New("invalid token ID for ERC721, must be a big Int")
	}
	bz, err := abi.Pack("ownerOf", t.BigInt())
	if err != nil {
		return nil, err
	}
	res, err := h.k.StaticCallEVM(ctx, callerAddr, &contract, bz)
	if err != nil {
		return nil, err
	}
	typed, err := abi.Unpack("ownerOf", res)
	if err != nil {
		return nil, err
	}
	typedOwner := typed[0].(common.Address)
	owner := ""
	if (typedOwner != common.Address{}) {
		owner = h.k.GetSeiAddressOrDefault(ctx, typedOwner).String()
	}
	response := bindings.ERC721OwnerResponse{Owner: owner}
	return json.Marshal(response)
}

func (h *EVMQueryHandler) HandleERC721TransferPayload(ctx sdk.Context, from string, recipient string, tokenId string) ([]byte, error) {
	abi, err := cw721.Cw721MetaData.GetAbi()
	if err != nil {
		return nil, err
	}
	fromEvmAddr, found := h.k.GetEVMAddress(ctx, sdk.MustAccAddressFromBech32(from))
	if !found {
		return nil, types.NewAssociationMissingErr(from)
	}
	toEvmAddr, found := h.k.GetEVMAddress(ctx, sdk.MustAccAddressFromBech32(recipient))
	if !found {
		return nil, types.NewAssociationMissingErr(recipient)
	}
	t, ok := sdk.NewIntFromString(tokenId)
	if !ok {
		return nil, errors.New("invalid token ID for ERC721, must be a big Int")
	}
	bz, err := abi.Pack("transferFrom", fromEvmAddr, toEvmAddr, t.BigInt())
	if err != nil {
		return nil, err
	}
	res := bindings.ERCPayloadResponse{EncodedPayload: base64.StdEncoding.EncodeToString(bz)}
	return json.Marshal(res)
}
