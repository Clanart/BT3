## Analog Found: Unconditional Local Commit of `HostParams` Before Cross-Chain Delivery Confirmation

### Title
Hyperbridge-side `HostParams` storage is committed unconditionally before the destination EVM host confirms the update, permanently desynchronizing fee-token/host-manager bookkeeping across chains - (File: `modules/pallets/host-executive/src/lib.rs`)

### Summary
The external report's core broken invariant is: *a privileged registration/config action on one side of a bridge is persisted locally without any guarantee that the paired side (the other layer) actually applied the matching state, and there is no mechanism to detect or repair the resulting mismatch.* The local Hyperbridge analog is `pallet_ismp_host_executive::update_host_params`, which updates the relay-chain's own `HostParams` storage for a given `StateMachine` immediately after dispatching a cross-chain message, without waiting for — or ever verifying — that the destination `EvmHost` actually accepted the new params.

### Finding Description
`update_host_params` builds the new `EvmHostParam`, ABI-encodes it, dispatches it as a `PostRequest` to the destination chain's `host_manager`, and then unconditionally writes the resulting value into local storage: [1](#0-0) 

`dispatch_request` returning `Ok` only means the message was queued for relaying — it says nothing about whether a relayer ever delivers it, or whether the destination `EvmHost` accepts it. On the EVM side, the message flows through `HostManager.onAccept` → `IHostManager(_params.host).updateHostParams(params)` → `updateHostParamsInternal`, which enforces multiple strict `require`-style reverts: [2](#0-1) 

Any of these reverts (`InvalidHostManager`, `InvalidHandler`, `InvalidConsensusClient`, `InvalidHyperbridgeId`, `InvalidStateMachinesLength`, `InvalidUnstakingPeriod`, `CannotChangeFeeToken`), a relayer failing to deliver the message before `timeout: 0` in the dispatched `DispatchPost`, or `dispatchIncoming`'s silent early-return on a bad `to` address: [3](#0-2) 

will cause the destination `EvmHost._hostParams` to remain at the OLD values while the Hyperbridge relay chain's `HostParams::<T>` storage already reflects the NEW values. There is no `IsmpModule::on_response`/`on_timeout` wired into `pallet-ismp-host-executive` to detect this divergence and roll back the local write — the pallet has no response/timeout handler at all for this dispatch.

This exactly parallels the report's second concern: registration/config functions are updated independently on each layer with no atomic sync guarantee, and once diverged there is no way to reconcile because the write already happened unconditionally.

### Impact Explanation
Downstream consumers treat the pallet's local `HostParams` as ground truth for that state machine:
- `fee_token_decimals` in the relayer messaging provider reads `params.fee_token` straight from this storage to compute relayer fee decimals used in gas/fee economics: [4](#0-3) 
- `withdraw` (protocol fee withdrawal) reads `params.host_manager` from the same possibly-stale storage to route the withdrawal `PostRequest`'s destination module address: [5](#0-4) 

If the on-chain `HostParams` diverge from the pallet's belief (e.g., `feeToken` or `hostManager` updated locally but rejected/undelivered on the EVM side), fee computations can be built against the wrong token/decimals, and governance withdrawal messages can be dispatched to an address that no longer corresponds to the live `hostManager` on that chain — causing protocol revenue to be undeliverable/locked, or relayer fee accounting to be computed against the wrong token. Because there is no reconciliation path, this mismatch is permanent until manually corrected by another privileged `set_host_params`/`update_host_params` call, mirroring the report's "cannot be updated/fixed" severity escalation.

### Likelihood Explanation
Triggering this does not require a malicious relayer or governance actor behaving maliciously — it only requires a normal, honest, but not-yet-confirmed governance update flow: `HostExecutiveOrigin` submits an `update_host_params` extrinsic with new params, and the corresponding cross-chain message either times out (dispatched with `timeout: 0`, i.e., no protocol-level timeout enforcement window preventing indefinite non-delivery), reverts on the EVM side due to one of `updateHostParamsInternal`'s validation checks, or is simply never relayed. Because the local storage write happens synchronously and unconditionally in the same extrinsic that dispatches the request, the desync window opens on every single call, with no additional attacker action needed beyond normal operational conditions (delivery delay, relayer downtime, or a parameter combination that reverts on the destination but was not pre-validated on the source pallet).

### Recommendation
Do not commit `HostParams::<T>::insert(state_machine, updated)` until the destination `EvmHost` has confirmed acceptance. Concretely:
1. Mirror `updateHostParamsInternal`'s validation checks (`hostManager`/`handler`/`consensusClient` code-existence and interface checks, `unStakingPeriod` minimum, non-empty `hyperbridge`/`stateMachines`, fee-token-balance guard) on the pallet side *before* dispatching, so obviously-invalid updates never leave the source chain.
2. Implement `IsmpModule::on_response`/`on_timeout` for the host-executive pallet's dispatched request so that the local `HostParams` write is applied only upon a confirmed successful response from the destination `HostManager`, and rolled back (or flagged) on timeout/failure, rather than optimistically applied at dispatch time.

### Proof of Concept
1. `HostExecutiveOrigin` calls `update_host_params(StateMachine::Evm(1), HostParamUpdate::EvmHostParam { fee_token: Some(new_token), .. })`.
2. The pallet immediately executes `HostParams::<T>::insert(StateMachine::Evm(1), HostParam::EvmHostParam(new_params))` (line 219 of `modules/pallets/host-executive/src/lib.rs`) and dispatches the ISMP `PostRequest` to the EVM `HostManager`.
3. On the destination chain, the relayed message reaches `HostManager.onAccept` → `updateHostParams` → `updateHostParamsInternal`, which reverts with `CannotChangeFeeToken` because the old fee token still holds a nonzero balance on that `EvmHost` (per the check at `evm/src/core/EvmHost.sol` lines 617-621).
4. The EVM `EvmHost._hostParams.feeToken` remains the OLD token; the Hyperbridge relay chain's `HostParams` storage now reports the NEW token for `StateMachine::Evm(1)`.
5. Any relayer computing fee decimals via `fee_token_decimals` (`tesseract/messaging/evm/src/provider.rs`) or any subsequent `withdraw` call routing on `params.host_manager`/token fields now operates on a state that no longer matches the live EVM contract, with no automatic detection or repair path in the pallet.

		/// Update the host params for the provided state machine
		#[pallet::weight(T::DbWeight::get().writes(1))]
		#[pallet::call_index(1)]
		pub fn update_host_params(
			origin: OriginFor<T>,
			state_machine: StateMachine,
			update: HostParamUpdate,
		) -> DispatchResult {
			T::HostExecutiveOrigin::ensure_origin(origin)?;

			let params = HostParams::<T>::get(&state_machine)
				.ok_or_else(|| Error::<T>::UnknownStateMachine)?;

			let (HostParam::EvmHostParam(mut inner), HostParamUpdate::EvmHostParam(update)) =
				(params.clone(), update);
			inner.update(update);

			let body = inner.abi_encode_with_variant().map_err(|_| Error::<T>::DispatchFailed)?;

			let post = DispatchPost {
				dest: state_machine,
				from: PALLET_ID.to_bytes(),
				to: inner.host_manager.0.to_vec(),
				timeout: 0,
				body,
			};

			let updated = HostParam::EvmHostParam(inner);

			let dispatcher = <T as Config>::IsmpHost::default();
			dispatcher
				.dispatch_request(
					DispatchRequest::Post(post),
					FeeMetadata { payer: [0u8; 32].into(), fee: Default::default() },
				)
				.map_err(|_| Error::<T>::DispatchFailed)?;

			HostParams::<T>::insert(state_machine, updated.clone());

			Self::deposit_event(Event::<T>::HostParamsUpdated {
				state_machine,
				old: params,
				new: updated,
			});

			Ok(())
		}

    function updateHostParamsInternal(HostParams memory params) internal {
        // check the params to prevent the host from getting bricked.
        if (
            params.hostManager == address(0) || address(params.hostManager).code.length == 0
                || !IERC165(params.hostManager).supportsInterface(type(IApp).interfaceId)
        ) {
            // otherwise cannot process new cross-chain governance requests
            revert InvalidHostManager();
        }

        if (
            params.handler == address(0) || address(params.handler).code.length == 0
                || !IERC165(params.handler).supportsInterface(type(IHandlerV2).interfaceId)
        ) {
            // otherwise cannot process new datagrams
            revert InvalidHandler();
        }

        if (
            params.consensusClient == address(0) || address(params.consensusClient).code.length == 0
                || !IERC165(params.consensusClient).supportsInterface(type(IConsensusV2).interfaceId)
        ) {
            // otherwise cannot process new consensus datagrams
            revert InvalidConsensusClient();
        }

        // otherwise cannot process new cross-chain governance requests
        if (keccak256(params.hyperbridge) == keccak256(bytes(""))) revert InvalidHyperbridgeId();

    function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
        address destination = _bytesToAddress(request.to);
        uint256 size;
        assembly {
            size := extcodesize(destination)
        }
        if (size == 0) {
            // instead of reverting the entire batch, early return here.
            return;
        }

        // replay protection
        bytes32 commitment = request.hash();
        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)
            .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));

        if (!success) {
            // so that it can be retried
            delete _requestReceipts[commitment];
            return;
        }
        emit PostRequestHandled({commitment: commitment, relayer: relayer});

	async fn fee_token_decimals(&self) -> Result<u8, anyhow::Error> {

			HostParam::EvmHostParam(params) => params.fee_token,

	}
