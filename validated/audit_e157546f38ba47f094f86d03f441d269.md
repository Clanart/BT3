### Title
Missing bounds check in CLVM atom length-prefix parsing during mempool canonical-form validation - (File: chia/full_node/mempool_manager.py)

### Summary
`is_atom_canonical()` and its caller `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` parse a length-prefixed CLVM atom encoding directly out of an attacker-supplied buffer (a spend's puzzle/solution bytes), advancing an `offset` index based on a length value read from the buffer itself, without ever checking that `offset` stays within `len(clvm_buffer)` before indexing. This mirrors the CVE-2020-25687 bug class: `rfc1035.c:extract_name()` computed a length from untrusted DNS data and indexed/copied past the buffer because there was no check that the derived length stayed inside the received message.

### Finding Description
`is_atom_canonical()` reads a length prefix from `clvm_buffer[offset]`, determines `prefix_len` (0–5 additional bytes) and a `mask`, then loops `prefix_len` times incrementing `offset` and reading `clvm_buffer[offset]` to build `atom_len` — with no check anywhere in the loop that `offset` remains less than `len(clvm_buffer)`: [1](#0-0) 

The caller `is_clvm_canonical()` walks a CLVM-serialized buffer token-by-token, calling `is_atom_canonical(clvm_buffer, offset)` whenever it encounters an atom byte greater than `0x80`, and then advances `offset += atom_len` based on the (unvalidated) return value: [2](#0-1) 

Per the project's own context notes, this canonical-form check is applied to spend solutions to determine dedup eligibility for mempool items: [3](#0-2) 
(see also `.cursor/context/clvm-execution.md` describing `is_clvm_canonical()` as being "Required for DEDUP-eligible spends").

If a crafted spend bundle supplies a truncated or malformed CLVM buffer where a length-prefix byte near the end of the buffer claims more continuation bytes than actually remain, the loop at line 181 (`atom_len |= clvm_buffer[offset]`) or the initial `clvm_buffer[offset]` read at line 199 will index past the end of the `bytes` object.

### Impact Explanation
Unlike the C implementation in dnsmasq, Python `bytes` objects are bounds-checked, so this would raise an `IndexError` rather than causing heap memory corruption. The practical impact is therefore constrained to a denial-of-service if the exception is not caught somewhere in the call chain that invokes `is_clvm_canonical()`/`is_atom_canonical()` during spend-bundle processing — potentially halting or crashing the mempool-manager task handling a submitted spend bundle. I was unable to confirm, within the available iterations, the exact call site that invokes `is_clvm_canonical()` on attacker-controlled solution bytes, nor whether that call site wraps it in a try/except. This is a material gap that would need to be closed before treating this as a confirmed, exploitable finding.

### Likelihood Explanation
The parsing functions clearly operate on attacker-influenced bytes (a spend bundle's puzzle/solution reveal), and the missing bounds check is present in the reachable, non-test code path. However, likelihood of actual impact depends on unverified details: whether the dedup-eligibility check path is reached before other CLVM/cost validation would already reject a malformed program, and whether an `IndexError` here is caught or propagates to crash a task.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before each indexing operation (initial `clvm_buffer[offset]` and each `clvm_buffer[offset]` inside the `prefix_len` loop), returning "not canonical" (or raising a well-defined, caught exception) instead of indexing unconditionally. Apply the same guard to the `clvm_buffer[offset]` read in `is_clvm_canonical()`'s main loop. Confirm the call site(s) that invoke this on untrusted spend-bundle data wrap it in exception handling that safely rejects the spend bundle rather than propagating an unhandled exception.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
