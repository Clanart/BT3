### Title
Unpermissioned `multiclaimFor` lets anyone force a vlMGP staker to realize their MGP-reward forfeiture at an unfavorable time - (File: `rewards/MasterMagpie.sol`, `rewards/vlMGPBaseRewarder.sol`)

### Summary
`MasterMagpie.multiclaimFor` allows **any caller** to trigger a reward claim on behalf of an arbitrary `_account`, with the harvested reward sent straight to that same account. When the staking token is `vlmgp`, this claim path routes through `vlMGPBaseRewarder.getReward`/`getRewards`, which apply an early-forfeit penalty (`_calExpireForfeit`) computed from the target account's *current* on-chain lock/cooldown state via `vlMGP.getRewardablePercentWAD(_account)`. Because the forfeit percentage is a function of the account's state at the moment of the call rather than of the caller's intent, a third party can force a claim while the victim is in an unfavorable lock/cooldown state, permanently diverting part of their earned MGP reward to the rest of the pool.

### Finding Description
`multiclaimFor` has no `msg.sender == _account` restriction: [1](#0-0) 

It funnels into `_multiClaim`, which for the vlMGP pool eventually calls the rewarder's `getReward`/`getRewards`, restricted only to `onlyMasterMagpie` (i.e., callable by MasterMagpie regardless of who triggered the outer transaction): [2](#0-1) 

The actual payout is computed in `_sendReward`, which subtracts a forfeit amount from the user's accrued reward and permanently redirects that forfeited portion back into the pool for other stakers via `_queueNewRewardsWithoutTransfer` — the original account can never reclaim it: [3](#0-2) 

The forfeit percentage itself is derived from the account's *current* rewardable percentage, not the caller's: [4](#0-3) 

This mirrors the reported bug class exactly: a pro-rata/penalty computation that depends on the state of the target account at claim time, combined with an unpermissioned "claim for" entry point, lets any user force another account to realize value at a worse rate than the account owner would have chosen by claiming at a different time.

### Impact Explanation
An attacker can call `multiclaimFor` for any vlMGP staker while that staker's `getRewardablePercentWAD` is depressed (e.g., before they have fully vested/unlocked), forcing them to forfeit a larger share of their pending MGP rewards than they would if they had chosen to claim later once their rewardable percentage improved. The forfeited amount is not returned to the victim — it is permanently redistributed to other stakers in the pool via `_queueNewRewardsWithoutTransfer`. This is a permanent, involuntary loss of unclaimed yield for the victim and a value transfer to whichever stakers subsequently harvest.

### Likelihood Explanation
`multiclaimFor` is a plain external function with no access control beyond `whenNotPaused`, callable by any unprivileged wallet for any target address, and the forfeit math is unconditionally executed inside the rewarder's claim path. No special conditions or privileged roles are required — only that the victim currently holds a pending vlMGP MGP reward and a sub-100% rewardable percentage.

### Recommendation
Restrict `multiclaimFor` (and any other public "claim for" entry points that route to reward payouts with a time/state-dependent penalty, such as the vlMGP forfeit logic) so that only the account owner, or an explicitly authorized/opted-in operator (e.g., the compounder via `multiclaimOnBehalf`), can trigger the claim. Alternatively, decouple the forfeit calculation so it cannot be manipulated by a third party choosing an unfavorable time to force the claim, or require an explicit opt-in signature/allowance from the account before rewards can be claimed to it by a third party.

### Proof of Concept
1. Alice locks MGP into vlMGP and accrues rewards in `vlMGPBaseRewarder`; her `getRewardablePercentWAD` is currently low because she is mid-cooldown.
2. Bob (any unprivileged wallet) calls `MasterMagpie.multiclaimFor([vlmgpAddress], [[rewardToken]], aliceAddress)`.
3. This reaches `vlMGPBaseRewarder.getReward(alice, alice)` → `_sendReward`, which computes `forfeitAmount = _calExpireForfeit(alice, userRewards[...])` based on Alice's current low rewardable percentage.
4. Alice receives only the reduced `toSend` amount; the forfeited portion is queued into the pool for other stakers via `_queueNewRewardsWithoutTransfer`, permanently lost to Alice, even though she would have preferred to wait until her rewardable percentage recovered. [1](#0-0) [5](#0-4)

    function _sendReward(address _rewardToken, address _account, address _receiver) internal {
        uint256 forfeitAmount = _calExpireForfeit(_account, userRewards[_rewardToken][_account]);
        uint256 toSend = userRewards[_rewardToken][_account] - forfeitAmount;


        userRewards[_rewardToken][_account] = 0;
            
        if (toSend > 0) {
            IERC20(_rewardToken).safeTransfer(_receiver, toSend);
            emit RewardPaid(_account, _receiver, toSend, _rewardToken);
        }

        if(forfeitAmount > 0)
            _queueNewRewardsWithoutTransfer(forfeitAmount, _rewardToken);
    }

    function _earned(address _account, address _rewardToken, uint256 _userVlmgpShare) internal view returns (uint256) {
        return ((_userVlmgpShare *
                (rewardPerToken(_rewardToken) -
                    userRewardPerTokenPaid[_rewardToken][_account])) /
                10**vlMGPDecimal) + userRewards[_rewardToken][_account];
    }

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }
