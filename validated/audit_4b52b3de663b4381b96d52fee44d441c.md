### Title
Front-runnable bribe reward theft via last-block vote() before castVotes() reward distribution - ([File: rewards/BribeRewardPool.sol], [File: wombat/WombatBribeManager.sol], [File: wombat/WombatStaking.sol])

### Summary
`WombatBribeManager.vote()` calls `IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, delta)` immediately, crediting the caller's balance in the pool's `BribeRewardPool` before any bribe reward for that voting epoch has been queued. When `castVotes()` is later executed (by anyone, including the front-runner), `WombatStaking.vote()` harvests the bribe and calls `queueNewRewards`, which increases `rewardPerTokenStored` based on `totalStaked()` at that exact moment. An attacker can front-run the pending `castVotes()`/`claimBribe()` transaction with their own `vote()` call to inflate `totalStaked()`/`pool.totalVoteInVlmgp` right before the reward index bump, and immediately capture a pro-rata share of rewards that accrued from other users' votes over the prior epoch.

### Finding Description
`BribeRewardPool.stakeFor` (extends `BaseRewardPoolV2`) is guarded by `updateRewards(_for, rewardTokens)`, which snapshots `userRewardPerTokenPaid[token][_for] = rewardPerToken(token)` using the account's balance **before** `totalSupply`/`_balances[_for]` are incremented: [1](#0-0) 

`rewardPerToken()` simply returns a stored accumulator `rewardPerTokenStored`, which is only bumped discretely inside `queueNewRewards`, proportional to `totalStaked()` at the time the bribe is harvested and forwarded — not a continuous per-second accrual: [2](#0-1) 

The trigger for this bump is `WombatStaking.vote()`, invoked from `WombatBribeManager.castVotes()`, which harvests the external Wombat bribe and calls `IBaseRewardPool(_rewarders[i]).queueNewRewards(...)`: [3](#0-2) 

`WombatBribeManager.vote()` lets any vlMGP holder immediately increase `pool.totalVoteInVlmgp` and call `stakeFor` on the rewarder in the same block as a pending `castVotes()`/`claimBribe()` transaction: [4](#0-3) 

Exploit flow:
1. Attacker observes a pending `castVotes()` (or `voteAndCast`/`castVotesAndClaimBribes`) transaction in the mempool for a pool with a large amount of unharvested bribe reward accrued from other voters' stake over the prior epoch.
2. Attacker front-runs with `vote([lp], [+X])`. This calls `stakeFor(attacker, X)`, which snapshots `userRewardPerTokenPaid = rewardPerTokenStored` (pre-harvest value, since attacker's prior balance was 0/small) and increases `totalStaked()`/`pool.totalVoteInVlmgp` by `X`.
3. The victim's `castVotes()` executes next, harvesting the bribe and calling `queueNewRewards`, which bumps `rewardPerTokenStored += (amountReward * 1e18) / totalStaked()` — using `totalStaked()` that now includes the attacker's freshly added `X`.
4. Attacker calls `claimBribe([lp])` → `getReward` → `earned()` = `balance * (rewardPerToken - userRewardPerTokenPaid)`, which credits the attacker a full pro-rata share of the just-added reward despite having staked zero time before the reward was earned in the external Wombat bribe contract.

Existing protections do not stop this: there is no time-weighting, checkpointing, or minimum holding period between `stakeFor` and reward eligibility, and `updateRewards` only prevents double-counting of the same reward index, not late-entrant free-riding.

### Impact Explanation
This is theft of unclaimed yield: honest voters who held their position throughout the reward-accrual epoch have their bribe rewards diluted by an attacker who enters and exits (via `unvote`/`vote` reversal) within the same block, extracting value proportional to `X / totalStaked()` of every newly queued reward across all pools they target. This matches the "theft of unclaimed yield" impact class. Because attacker capital (vlMGP votes) can be sized arbitrarily relative to `totalStaked()`, the extractable fraction scales directly with capital deployed, and can be repeated every epoch/harvest.

### Likelihood Explanation
Preconditions are minimal and fully within the "unprivileged attacker" scope: hold/acquire vlMGP (or borrow/flash-source vote-weight if transferable — otherwise just normal vlMGP holdings), monitor the mempool for pending `castVotes()`/`claimBribe()`/`voteAndCast()` calls (these are public, frequently called, gas-incentivized functions), and submit a higher-gas `vote()` transaction ahead of it. No special role or governance access is required. This is straightforward front-running feasible on any public mempool chain (BNB Chain), and repeatable every time a bribe harvest occurs.

### Recommendation
Decouple reward eligibility from instantaneous stake changes: track a time-weighted or per-epoch-locked vote balance instead of the live `balanceOf`, or introduce a minimum staking duration / snapshot at the start of a voting period, so `stakeFor` calls occurring after a reward period starts do not retroactively participate in that period's already-harvested rewards. Alternatively, change `queueNewRewards` distribution to weight by balances at the time votes were last cast (snapshot at `castVotes` execution) rather than `totalStaked()` at the arbitrary block of harvest, or require a cooldown between `vote()` and reward accrual eligibility equal to at least one voting epoch.

### Proof of Concept
Foundry test plan:
1. Deploy `WombatBribeManager`, `WombatStaking`, `BribeRewardPool` (or `vlMGPBaseRewarder`), mock `Voter`/`Bribe` contracts returning a fixed bribe reward amount on `voter.vote()`.
2. Set up two users: Victim (votes `Y` vlMGP for pool `lp` well before the harvest, e.g., several blocks/epochs earlier) and Attacker (holds vlMGP but has not voted for `lp`).
3. Simulate mempool ordering in the same block/transaction sequence:
   - Attacker calls `bribeManager.vote([lp], [int256(X)])` (front-run).
   - Then call `bribeManager.castVotes(false)` (simulating the victim's or a keeper's pending tx), which triggers `wombatStaking.vote` → `queueNewRewards` on `lp`'s rewarder with the mocked bribe amount `R`.
4. Assert `IBribeRewardPool(rewarder).earned(attacker, rewardToken) > 0` immediately after step 3, despite attacker having staked for zero blocks prior to `R` being queued.
5. Assert attacker's share equals `R * X / (X + Y)` (or `X / totalStaked()`), and that calling `claimBribe([lp])` transfers this amount to the attacker, while the victim's fair share is correspondingly reduced by the same delta versus a baseline run where the attacker does not front-run.
6. Optionally show attacker can `unvote(lp)` immediately after claiming to withdraw `X` again in the same or next block, completing a capital-neutral extraction.

    function vote(address[] calldata _lps, int256[] calldata _deltas) override public {
        if (_lps.length != _deltas.length)
            revert LengthMismatch();

        uint256 length = _lps.length;
        int256 totalUserVote;

        for (uint256 i; i < length; i++) {
            Pool storage pool = poolInfos[_lps[i]];
            if (!pool.isActive)
                revert PoolNotActive();
            int256 delta = _deltas[i];
            totalUserVote += delta;
            if (delta != 0) {
                if (delta > 0) {
                    pool.totalVoteInVlmgp += uint256(delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] += uint256(delta);
                    IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, uint256(delta));
                } else {
                    pool.totalVoteInVlmgp -= uint256(-delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] -= uint256(-delta);
                    IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(-delta), false);
                }
            }
        }

        if (msg.sender != delegatedPool) {
            if (totalUserVote > 0) {
                userTotalVotedInVlmgp[msg.sender] += uint256(totalUserVote);
                totalVlMgpInVote += uint256(totalUserVote);
            } else {
                userTotalVotedInVlmgp[msg.sender] -= uint256(-totalUserVote);
                totalVlMgpInVote -= uint256(-totalUserVote);
            }
        }

        if (userTotalVotedInVlmgp[msg.sender] > getUserVotable(msg.sender))
            revert NotEnoughVote();
    }
