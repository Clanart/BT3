## Title
Client-controlled `kc_user`/`kc_service` identity fields allow any local daemon RPC caller to access or delete another keychain namespace's keys - (File: `chia/daemon/keychain_server.py`)

### Summary
The Mealie CVE-2024-55073 is a broken object-level authorization (BOLA) bug: the server trusts a client-supplied identifier on `/api/users/{user-id}` instead of binding the mutated object to the caller's actual authenticated identity, letting a user escalate privilege by editing fields on "their own" (but attacker-chosen) record. `KeychainServer.get_keychain_for_request()` in `chia/daemon/keychain_server.py` has the same shape of bug: it selects which `Keychain` namespace to operate on purely from client-supplied `kc_user`/`kc_service` fields in the request body, with no verification that those values correspond to the identity of the connection issuing the command.

### Finding Description
`KeychainServer.get_keychain_for_request()` resolves the keychain instance to operate on strictly from attacker-controlled JSON fields: [1](#0-0) 

`user`/`service` come directly from `request.get("kc_user", ...)`/`request.get("kc_service", ...)` — values the caller places in the WS request payload — and are used as a cache key to either fetch or lazily create a distinct `Keychain(user=user, service=service)` instance. There is no check anywhere in `KeychainServer.handle_command()` (`chia/daemon/keychain_server.py` lines 174-209) or in `WebSocketServer.handle_message()` (`chia/daemon/server.py` lines 408-449) that ties the `kc_user`/`kc_service` fields to the identity of the connected websocket. Any local process that can reach the daemon's TLS websocket (any service registered against the daemon, e.g. farmer, harvester, or a compromised/lower-trust component) can set `kc_user`/`kc_service` to a different namespace and call privileged keychain commands such as `get_all_private_keys`, `get_key_for_fingerprint`, `delete_all_keys`, or `delete_key_by_fingerprint` against that other namespace: [2](#0-1) [3](#0-2) 

`KeychainProxy.format_request()` normally injects the legitimate `kc_user`/`kc_service` for the calling service, but this is a client-side convention only — nothing on the server side re-derives or validates these fields from the authenticated connection: [4](#0-3) 

This is structurally the same bug class as the Mealie CVE: the server-side handler trusts a caller-supplied "whose object is this" identifier rather than deriving ownership from the authenticated session, enabling one actor to read or mutate another actor's private data/state.

### Impact Explanation
`get_all_private_keys`/`get_first_private_key`/`get_key_for_fingerprint` return raw private-key material (`sk`/entropy) for the targeted namespace, so a lower-privileged local caller that can only reach the daemon socket (not necessarily the operator) can exfiltrate another namespace's master private keys and derive wallet/farmer/pool keys, enabling unauthorized coin movement (spend-bundle signing with someone else's keys). `delete_all_keys`/`delete_key_by_fingerprint` let that same caller destroy another namespace's keys, causing denial of custody/service. This satisfies the "concrete unsigned or unauthorized coin movement" bar via private-key disclosure.

### Likelihood Explanation
Exploitation requires only a valid local daemon websocket connection (mTLS cert for the daemon), which is the trust level already granted to every registered local service (farmer, harvester, wallet, etc.) and is explicitly called out in-scope as a "local RPC caller." No operator/admin-only capability is required beyond what any registered local client already has; the missing check is a straightforward oversight rather than a complex chain.

### Recommendation
Bind the keychain namespace to the authenticated connection/service identity rather than to attacker-controlled JSON fields — e.g., derive `kc_user`/`kc_service` from the daemon's own registration/session state for the calling websocket, or explicitly document and enforce that `kc_user`/`kc_service` are only trusted for callers with elevated/administrative daemon privilege, rejecting cross-namespace requests from ordinary registered services.

### Proof of Concept
1. Start the daemon with an existing default keychain holding keys, and set up a second logical keychain namespace (e.g. by any component that constructs a `Keychain(user=..., service=...)` pair, as supported by `Keychain.__init__`).
2. From any local process holding a daemon client certificate (any already-registered service, e.g. farmer), open a websocket to the daemon and send a `get_all_private_keys` command with `data = {"kc_user": "<other-namespace-user>", "kc_service": "<other-namespace-service>"}`.
3. Observe `KeychainServer.get_keychain_for_request()` resolves to the other namespace's `Keychain` and `handle_command()` returns that namespace's private keys/entropy in the response, despite the caller never having been granted access to that namespace.

```python
    def get_keychain_for_request(self, request: dict[str, Any]) -> Keychain:
        """
        Keychain instances can have user and service strings associated with them.
        The keychain backends ultimately point to the same data stores, but the user
        and service strings are used to partition those data stores. We attempt to
        maintain a mapping of user/service pairs to their corresponding Keychain.
        """
        user = request.get("kc_user", self._default_keychain.user)
        service = request.get("kc_service", self._default_keychain.service)
        if user == self._default_keychain.user and service == self._default_keychain.service:
            keychain = self._default_keychain
        else:
            key = (user or "unnamed") + (service or "")
            if key in self._alt_keychains:
                keychain = self._alt_keychains[key]
            else:
                keychain = Keychain(user=user, service=service)
                self._alt_keychains[key] = keychain
        return keychain
```

```python
    async def delete_all_keys(self, request: dict[str, Any]) -> dict[str, Any]:
        if self.get_keychain_for_request(request).is_keyring_locked():
            return {"success": False, "error": KEYCHAIN_ERR_LOCKED}

        self.get_keychain_for_request(request).delete_all_keys()

        return {"success": True}

    async def delete_key_by_fingerprint(self, request: dict[str, Any]) -> dict[str, Any]:
        if self.get_keychain_for_request(request).is_keyring_locked():
            return {"success": False, "error": KEYCHAIN_ERR_LOCKED}

        fingerprint = request.get("fingerprint", None)
        if fingerprint is None:
            return {
                "success": False,
                "error": KEYCHAIN_ERR_MALFORMED_REQUEST,
                "error_details": {"message": "missing fingerprint"},
            }

        self.get_keychain_for_request(request).delete_key_by_fingerprint(fingerprint)

        return {"success": True}
```

```python
    async def get_all_private_keys(self, request: dict[str, Any]) -> dict[str, Any]:
        all_keys: list[dict[str, Any]] = []
        if self.get_keychain_for_request(request).is_keyring_locked():
            return {"success": False, "error": KEYCHAIN_ERR_LOCKED}

        private_keys = self.get_keychain_for_request(request).get_all_private_keys()
        for sk, entropy in private_keys:
            all_keys.append({"pk": bytes(sk.get_g1()).hex(), "entropy": entropy.hex()})

        return {"success": True, "private_keys": all_keys}

    async def get_first_private_key(self, request: dict[str, Any]) -> dict[str, Any]:
        key: dict[str, Any] = {}
        if self.get_keychain_for_request(request).is_keyring_locked():
            return {"success": False, "error": KEYCHAIN_ERR_LOCKED}

        sk_ent = self.get_keychain_for_request(request).get_first_private_key()
        if sk_ent is None:
            return {"success": False, "error": KEYCHAIN_ERR_NO_KEYS}

        pk_str = bytes(sk_ent[0].get_g1()).hex()
        ent_str = sk_ent[1].hex()
        key = {"pk": pk_str, "entropy": ent_str}

        return {"success": True, "private_key": key}
```

```python
    def format_request(self, command: str, data: dict[str, Any]) -> WsRpcMessage:
        """
        Overrides DaemonProxy.format_request() to add keychain-specific RPC params
        """
        if data is None:
            data = {}

        if self.keychain_user or self.keychain_service:
            data["kc_user"] = self.keychain_user
            data["kc_service"] = self.keychain_service
```
