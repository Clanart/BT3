### Title
Unbounded EIP-7702 authorization-list loop performs ECDSA recovery on an infinite gas meter before intrinsic-gas/fee checks - ([File: x/evm/ante/preprocess.go])

### Summary
`EVMPreprocessDecorator.AnteHandle` runs `associateAuthorizationAuthorities`, which iterates over every entry of an EIP-7702 `SetCodeTx.AuthList` and performs a full `ecrecover` (`RecoverAddressesFromAuthorization`) plus cross-checks for each one, before the transaction's intrinsic gas and fee/balance are ever validated. This is analogous to the JOJO `openPositions[]` finding: an attacker-controlled, effectively unbounded array (`AuthList`) is looped over in a way that can consume large amounts of CPU/compute before the normal gas/fee gates that are supposed to bound per-tx work take effect.

### Finding Description
In the ante pipeline (`app/ante.go`), the EVM decorator order is:
1. `evmante.NewEVMNoCosmosFieldsDecorator()`
2. `evmante.NewEVMPreprocessDecorator(...)`
3. `evmante.NewBasicDecorator(...)` — this is where `core.IntrinsicGas(...)` is computed and checked against `etx.Gas()`
4. `evmante.NewEVMFeeCheckDecorator(...)` — this is where the fee payer's balance/fee sufficiency is checked
5. `evmante.NewEVMSigVerifyDecorator(...)`
6. `evmante.NewGasDecorator(...)` [1](#0-0) 

`EVMPreprocessDecorator.AnteHandle` explicitly switches the context to an **infinite gas meter** immediately at the start (`ctx = ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx))`), and then calls `p.associateAuthorizationAuthorities(ctx, msg, associateHelper)` before returning to `next(ctx, tx, simulate)` (which eventually reaches `BasicDecorator`'s intrinsic-gas check and `EVMFeeCheckDecorator`'s fee check). [2](#0-1) 

`associateAuthorizationAuthorities` loops over `ethTx.SetCodeAuthorizations()` — i.e., every element of the `AuthList` field of a `SetCodeTx` — calling `helpers.AuthorityToPreAssociate` for each entry: [3](#0-2) 

`AuthorityToPreAssociate` itself calls `RecoverAddressesFromAuthorization`, which performs an RLP encode, a Keccak256 hash, and a full secp256k1 `ecrecover` for every authorization tuple, plus additional keeper reads (`GetCode`, `GetNonce`, `GetEVMAddress`) per entry: [4](#0-3) 

The only structural bound on `AuthList` length prior to this point is `validateAuthList`, which only enforces that the list is non-empty and that each entry's fields are correctly sized — it does **not** cap the number of entries: [5](#0-4) 

The actual per-entry cost accounting (`core.IntrinsicGas(etx.Data(), etx.AccessList(), etx.SetCodeAuthorizations(), ...)` compared against `etx.Gas()`) happens only in `BasicDecorator`, which runs *after* `EVMPreprocessDecorator` has already performed the ecrecover loop: [6](#0-5) 

Because the intrinsic-gas and fee-sufficiency checks are ordered after the authorization-association loop, and because that loop runs under an infinite gas meter, a transaction can be crafted with a very large `AuthList` (bounded only by node/mempool max-tx-bytes, not by any authorization-count-specific limit) and an arbitrary `Gas()`/fee value that will ultimately be rejected by `BasicDecorator` or `EVMFeeCheckDecorator` — but only *after* every authorization has already been ecrecover'd, RLP-encoded/hashed, and checked against on-chain nonce/code state. The submitter pays no fee for this work if the tx is ultimately rejected in `CheckTx`/`ReCheckTx` (mempool admission) since fee deduction happens later in the ante chain (`DeductFeeDecorator`/`EVMFeeCheckDecorator`) than this loop.

### Impact Explanation
This lets an unprivileged EVM transaction submitter (via public RPC `eth_sendRawTransaction`, or gRPC broadcast of a `MsgEVMTransaction`) force full nodes/validators, during `CheckTx` and `ReCheckTx` re-execution on every mempool re-validation cycle, to perform potentially thousands of expensive `ecrecover` calls and keeper store reads per submitted transaction, before the intrinsic-gas or fee checks that are meant to price and bound this work take effect. Repeated submission of such transactions (which can be cheaply resubmitted since they may never need to pay a fee if rejected downstream, or can be crafted to pass fee checks with a high declared gas limit) can degrade validator/full-node CheckTx throughput and block-proposal timing, risking a block-delay/liveness impact across the network rather than affecting only the submitter's own node.

### Likelihood Explanation
Reachable by any transaction sender with no special privileges: constructing an EIP-7702 `SetCodeTx` with a large `AuthList` requires only valid-looking authorization tuples (fields need to satisfy `validateAuthList`'s length checks, but the signature/authority does not need to be a *real* valid recovery — `RecoverAddressesFromAuthorization` will still attempt full recovery work and only fail cross-checks afterward, so garbage authorizations with correctly-sized R/S/V bytes are sufficient to trigger the expensive path repeatedly). The number of entries is bounded only by tx-size limits (mempool `max_tx_bytes`), not by an authorization-count cap, so a large but still-mempool-admissible tx can carry many thousands of authorization tuples.

### Recommendation
- Move or duplicate the intrinsic-gas check (or an authorization-count-specific cap) so it runs *before* `EVMPreprocessDecorator`'s authorization-association loop, ensuring the number of authorizations processed is bounded by the fee actually being validated for the transaction.
- Add an explicit maximum `AuthList` length enforced in `validateAuthList` (or earlier, at decode time) independent of gas accounting, so mempool admission itself cannot be used to force unbounded per-tx cryptographic work.
- Consider running `associateAuthorizationAuthorities` under a real (non-infinite) gas meter charged per authorization, consistent with go-ethereum's `PerEmptyAccountCost`/`PerAuthBaseCost` accounting, rather than deferring all cost accounting to the later `BasicDecorator` check.

### Proof of Concept
1. Craft a `SetCodeTx` (`ethtypes.SetCodeTx`) with a very large `AuthList` (e.g., several thousand `SetCodeAuthorization` entries), each with syntactically valid-length `ChainID`/`Address`/`Nonce`/`V`/`R`/`S` fields (they do not need to recover to real accounts, only to be well-formed enough to pass `validateAuthList`).
2. Set an arbitrary `Gas`/`GasFeeCap` on the outer transaction and submit it via `eth_sendRawTransaction` or as a `MsgEVMTransaction`.
3. Observe that `EVMPreprocessDecorator.AnteHandle` → `associateAuthorizationAuthorities` (`x/evm/ante/preprocess.go` lines 122-147) executes an `ecrecover` plus keeper lookups for every one of the thousands of authorizations under an infinite gas meter, before `BasicDecorator`'s `core.IntrinsicGas` check (`x/evm/ante/basic.go` line 51) or `EVMFeeCheckDecorator`'s fee/balance check ever runs — regardless of whether the transaction is ultimately accepted or rejected.
4. Repeating this submission (including via `CheckTx`/`ReCheckTx` re-validation on mempool refresh) demonstrates CPU cost incurred by full nodes/validators disproportionate to, and prior to, any fee-based rate limiting.

//nolint:revive
func (p *EVMPreprocessDecorator) AnteHandle(ctx sdk.Context, tx sdk.Tx, simulate bool, next sdk.AnteHandler) (sdk.Context, error) {
	msg := evmtypes.MustGetEVMTransactionMessage(tx)
	if err := Preprocess(ctx, msg, p.evmKeeper.ChainID(ctx), p.evmKeeper.EthBlockTestConfig.Enabled); err != nil {
		return ctx, err
	}

	// use infinite gas meter for EVM transaction because EVM handles gas checking from within
	ctx = ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx))

	derived := msg.Derived
	seiAddr := derived.SenderSeiAddr
	evmAddr := derived.SenderEVMAddr
	ctx.EventManager().EmitEvent(sdk.NewEvent(evmtypes.EventTypeSigner,
		sdk.NewAttribute(evmtypes.AttributeKeyEvmAddress, evmAddr.Hex()),
		sdk.NewAttribute(evmtypes.AttributeKeySeiAddress, seiAddr.String())))
	pubkey := derived.PubKey
	isAssociateTx := derived.IsAssociate
	associateHelper := helpers.NewAssociationHelper(p.evmKeeper, p.evmKeeper.BankKeeper(), p.accountKeeper)
	_, isAssociated := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if isAssociateTx && isAssociated {
		return ctx, sdkerrors.Wrap(sdkerrors.ErrInvalidRequest, "account already has association set")
	} else if isAssociateTx {
		// check if the account has enough balance (without charging)
		if !p.IsAccountBalancePositive(ctx, seiAddr, evmAddr) {
			assocErr := evmtypes.NewAssociationMissingErr(seiAddr.String())
			evmAnteMetrics.associationError.Add(ctx.Context(), 1, otelmetric.WithAttributes(attribute.String("scenario", "associate_tx_insufficient_funds"), attribute.String("type", assocErr.AddressType())))
			return ctx, sdkerrors.Wrap(sdkerrors.ErrInsufficientFunds, "account needs to have at least 1 wei to force association")
		}
		if err := associateHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false); err != nil {
			return ctx, err
		}

		return ctx.WithPriority(antedecorators.EVMAssociatePriority), nil // short-circuit without calling next
	} else if isAssociated {
		// noop; for readability
	} else {
		// not associatedTx and not already associated
		if err := associateHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false); err != nil {
			return ctx, err
		}
		if p.evmKeeper.EthReplayConfig.Enabled {
			p.evmKeeper.PrepareReplayedAddr(ctx, evmAddr)
		}
	}

	// EIP-7702 authorization authorities are distinct accounts from the tx sender, so the
	// sender association above does not cover them. Associate each authority to its true
	// (pubkey-derived) Sei address before EVM execution installs delegation code for it.
	// Otherwise SetCode creates a mutable direct-cast EVM->Sei mapping that a later
	// associatePubKey call can remap, orphaning any staking/distribution state created
	// under the direct-cast identity (which can then halt the chain via the distribution
	// validator-removal hook).
	p.associateAuthorizationAuthorities(ctx, msg, associateHelper)

	return next(ctx, tx, simulate)
}

func (p *EVMPreprocessDecorator) associateAuthorizationAuthorities(ctx sdk.Context, msg *evmtypes.MsgEVMTransaction, associateHelper *helpers.AssociationHelper) {
	txData, err := evmtypes.UnpackTxData(msg.Data)
	if err != nil {
		return
	}
	setCodeTx, ok := txData.(*ethtx.SetCodeTx)
	if !ok {
		// Only SetCode (EIP-7702) transactions carry authorizations.
		return
	}
	ethTx := ethtypes.NewTx(setCodeTx.AsEthereumData())
	for _, auth := range ethTx.SetCodeAuthorizations() {
		// Only pre-associate authorities whose authorization the EVM will actually apply
		// (matching chain id, nonce, and account state). This prevents replaying a
		// publicly-visible authorization a user signed for another chain to force-associate
		// them, which the EVM would skip but which still recovers a valid authority.
		evmAddr, seiAddr, pubkey, ok := helpers.AuthorityToPreAssociate(ctx, p.evmKeeper, auth)
		if !ok {
			continue
		}
		cacheCtx, write := ctx.CacheContext()
		if err := associateHelper.AssociateAddresses(cacheCtx, seiAddr, evmAddr, pubkey, false); err == nil {
			write()
		}
	}
}

// RecoverAddressesFromAuthorization recovers the EVM address, Sei address, and public
// key of the account that signed an EIP-7702 SetCode authorization (the "authority").
// The authorization sig hash is keccak256(0x05 || rlp([chainId, address, nonce])) and
// the recovery id is carried directly in auth.V (yParity, 0 or 1), which GetAddresses
// expects bumped by 27. This mirrors go-ethereum's SetCodeAuthorization.Authority(), but
// additionally returns the recovered public key so the authority can be associated with
// its true Sei address.
func RecoverAddressesFromAuthorization(auth ethtypes.SetCodeAuthorization) (common.Address, sdk.AccAddress, cryptotypes.PubKey, error) {
	var buf bytes.Buffer
	buf.WriteByte(eip7702MagicPrefix)
	if err := rlp.Encode(&buf, []any{auth.ChainID, auth.Address, auth.Nonce}); err != nil {
		return common.Address{}, sdk.AccAddress{}, nil, err
	}
	sigHash := crypto.Keccak256Hash(buf.Bytes())
	v := new(big.Int).SetUint64(uint64(auth.V) + 27)
	return GetAddresses(v, auth.R.ToBig(), auth.S.ToBig(), sigHash)
}

// AuthorizationStateReader exposes the EVM state lookups needed to decide whether an
// EIP-7702 authorization would be applied. Both the standard and giga EVM keepers satisfy it.
type AuthorizationStateReader interface {
	ChainID(ctx sdk.Context) *big.Int
	GetCode(ctx sdk.Context, addr common.Address) []byte
	GetNonce(ctx sdk.Context, addr common.Address) uint64
	GetEVMAddress(ctx sdk.Context, seiAddr sdk.AccAddress) (common.Address, bool)
}

// AuthorityToPreAssociate returns the authority of an EIP-7702 authorization that should be
// associated with its true (pubkey-derived) Sei address before execution, or ok=false.
//
// It mirrors go-ethereum's StateTransition.validateAuthorization (chain id, nonce overflow,
// authority code, and account-nonce checks) so that pre-association happens only for
// authorizations the EVM will actually apply, and additionally skips authorities that are
// already associated. Mirroring validateAuthorization is essential to security: the
// authorization sig hash is computed from the auth's own ChainID, so recovery and
// auth.Authority() succeed for an authorization signed for ANY chain. Without these checks a
// publicly-visible authorization a user signed for another chain (e.g. Ethereum mainnet)
// could be replayed in a sponsored Sei SetCode tx to force-associate them — migrating their
// direct-cast balance and orphaning staking/distribution state — even though the EVM skips
// the wrong-chain authorization and installs no delegation.
func AuthorityToPreAssociate(ctx sdk.Context, k AuthorizationStateReader, auth ethtypes.SetCodeAuthorization) (common.Address, sdk.AccAddress, cryptotypes.PubKey, bool) {
	// Chain ID must be null or match the local chain.
	if !auth.ChainID.IsZero() && auth.ChainID.CmpBig(k.ChainID(ctx)) != 0 {
		return common.Address{}, nil, nil, false
	}
	// Nonce must not overflow (EIP-2681).
	if auth.Nonce+1 < auth.Nonce {
		return common.Address{}, nil, nil, false
	}
	evmAddr, seiAddr, pubkey, err := RecoverAddressesFromAuthorization(auth)
	if err != nil {
		return common.Address{}, nil, nil, false
	}
	// Cross-check against go-ethereum's authoritative recovery so we only ever act on the
	// exact address SetCode would target during execution.
	if authAddr, aerr := auth.Authority(); aerr != nil || authAddr != evmAddr {
		return common.Address{}, nil, nil, false
	}
	// Authority must have no code, or only an existing delegation designator.
	if code := k.GetCode(ctx, evmAddr); len(code) != 0 {
		if _, ok := ethtypes.ParseDelegation(code); !ok {
			return common.Address{}, nil, nil, false
		}
	}
	// Authority account nonce must match the authorization nonce.
	if k.GetNonce(ctx, evmAddr) != auth.Nonce {
		return common.Address{}, nil, nil, false
	}
	// Already-associated authorities need no pre-association (and cannot be re-mapped).
	if _, associated := k.GetEVMAddress(ctx, seiAddr); associated {
		return common.Address{}, nil, nil, false
	}
	return evmAddr, seiAddr, pubkey, true

func validateAuthList(authList AuthList) error {
	if len(authList) == 0 {
		return fmt.Errorf("auth list cannot be empty")
	}
	for _, auth := range authList {
		if auth.ChainID == nil {
			return fmt.Errorf("auth list chain id cannot be nil")
		}
		if err := validateHexAddress("auth list address", auth.Address); err != nil {
			return err
		}
		if err := validateSignatureValue("auth list v", auth.V, 1); err != nil {
			return err
		}
		if err := validateSignatureValue("auth list r", auth.R, 32); err != nil {
			return err
		}
		if err := validateSignatureValue("auth list s", auth.S, 32); err != nil {
			return err
		}
	}
	return nil
}
