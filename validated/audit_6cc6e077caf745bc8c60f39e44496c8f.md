### Title
Unauthenticated `send_tx` JSON-RPC endpoint allows any network-reachable party to enqueue arbitrary transactions and drain bridge fee-payer UTXOs via CPFP — (`crates/clementine-tx-sender/src/jsonrpc/server.rs`)

### Summary
The standalone tx-sender's JSON-RPC server exposes a `send_tx` method with no authentication or authorization. Any party that can reach the socket — trivially true when `TX_SENDER_JSONRPC_BIND=0.0.0.0`, and reachable from co-located processes even at `127.0.0.1` — can enqueue arbitrary transactions with any `FeePayingType`. Choosing `FeePayingType::CPFP` causes the bridge's fee-bumping loop to spend bridge-controlled fee-payer UTXOs on behalf of the attacker's transaction.

### Finding Description
`start_jsonrpc_server` builds a `jsonrpsee` server with `ServerBuilder::default()` and registers `send_tx` with no middleware, no bearer token, no mTLS, and no caller identity check. The handler deserializes the caller-supplied `InsertTryToSendParams` and passes it directly to `TxSenderClient::insert_try_to_send`, which persists the transaction and its fee-paying strategy into the DB queue. The tx-sender loop subsequently picks up every queued entry and attempts to broadcast it, creating CPFP children that spend bridge fee-payer UTXOs when `FeePayingType::CPFP` is specified.

The config struct `TxSenderJsonRpcConfig` explicitly supports `bind = "0.0.0.0"`, and the `from_env` parser accepts it without requiring any additional authentication configuration. [7](#0-6) 

### Impact Explanation
- **Direct fund loss:** Bridge fee-payer UTXOs are spent to pay fees for attacker-chosen transactions via CPFP. The attacker pays nothing; the bridge pays the miner fees.
- **Liveness disruption:** Queue flooding blocks legitimate bridge transactions (kickoff, payout, challenge, reimbursement) from being processed, breaking bridge safety/liveness with material fund impact.
- **Unauthorized privileged action:** An unprivileged party gains the ability to enqueue transactions for broadcast under the bridge's fee-bumping identity, which is an authentication bypass granting privileged bridge actions to the wrong party.

### Likelihood Explanation
High when `TX_SENDER_JSONRPC_BIND=0.0.0.0` (explicitly supported and documented). Medium even at `127.0.0.1` if any co-located service is compromised or has SSRF. The existing test and `run.sh` smoke-test script both demonstrate the endpoint works with zero credentials.

### Recommendation
Add an authentication layer to the JSON-RPC server before registering any methods. Options include:
1. A shared-secret bearer token checked in a `tower` middleware layer on the `jsonrpsee` server.
2. Restricting the bind address to `127.0.0.1` only (removing `0.0.0.0` support) and documenting that the endpoint is trust-local.
3. mTLS client certificate validation consistent with the rest of the Clementine actor RPC surface.

At minimum, the server must reject requests that do not present a valid credential before calling `insert_try_to_send`.

        let (config, db, rpc) = create_test_environment(true, true).await;
        let rpc = rpc.unwrap();
        let db = db.unwrap();
        rpc.rpc().mine_blocks(1).await.unwrap();

        // Start txsender with JSON-RPC enabled on a free port.
        let tx_sender_cfg = config.clone();

        let url = format!("http://{addr}");
        let client =
            JsonRpcTxSenderClient::new(&url).map_err(|e| BridgeError::Eyre(eyre::eyre!(e)))?;

        // A minimal syntactically-valid transaction (doesn't need to be mineable for enqueueing).
        let tx = Transaction {
            version: Version::TWO,
            lock_time: absolute::LockTime::ZERO,
            input: vec![TxIn {
                previous_output: OutPoint {
                    txid: Txid::all_zeros(),
                    vout: 0,
                },
                script_sig: ScriptBuf::new(),
                sequence: Sequence::ENABLE_LOCKTIME_NO_RBF,
                witness: Witness::default(),
            }],
            output: vec![TxOut {
                value: bitcoin::Amount::from_sat(0),
                script_pubkey: ScriptBuf::new(),
            }],
        };

        // Wait for server to come up (spawn loop initializes asynchronously).
        let start = Instant::now();
        let try_to_send_id = loop {
            match client
                .insert_try_to_send(None, &tx, FeePayingType::CPFP, None, &[], &[], &[], &[])
                .await
            {
                Ok(id) => break id,
                Err(e) => {
                    if start.elapsed() > Duration::from_secs(10) {
                        return Err(BridgeError::Eyre(eyre::eyre!(
                            "Timed out waiting for txsender JSON-RPC to start: {e:?}"
                        )));
                    }
                    tokio::time::sleep(Duration::from_millis(100)).await;
                }
            }
        };

        // Verify persisted in DB.
        let tx_sender_db = TxSenderDb::from_pool(db.pool().clone());
        let (_meta, stored_tx, fee_paying_type, _seen_at_height, _rbf) = tx_sender_db
            .get_try_to_send_tx(None, try_to_send_id)
            .await?;
        assert_eq!(fee_paying_type, FeePayingType::CPFP);
        assert_eq!(stored_tx.compute_txid(), tx.compute_txid());

        // Stop background loop.
        handle.abort();
        let _ = handle.await;

        Ok(())
    }

    pub async fn insert_try_to_send(
        &self,
        tx_metadata: Option<TxMetadata>,
        signed_tx: &Transaction,
        fee_paying_type: FeePayingType,
        rbf_signing_info: Option<RbfSigningInfo>,
        cancel_outpoints: &[OutPoint],
        cancel_txids: &[Txid],
        activate_txids: &[ActivatedWithTxid],
        activate_outpoints: &[ActivatedWithOutpoint],
    ) -> Result<u32, JsonRpcError> {
        let signed_tx_hex = consensus::encode::serialize_hex(signed_tx);

        let req = InsertTryToSendParams {
            tx_metadata,
            signed_tx_hex,
            fee_paying_type,
            rbf_signing_info,
            cancel_outpoints: cancel_outpoints.to_vec(),
            cancel_txids: cancel_txids.to_vec(),
            activate_txids: activate_txids.to_vec(),
            activate_outpoints: activate_outpoints.to_vec(),
        };

        self.inner
            .request::<u32, _>("send_tx", rpc_params![req])
            .await
    }
