### Title
FROST nonce reuse via never-cleared `CachedPreprocesses` seed allows secret share recovery - (File: coordinator/src/tributary/signing_protocol.rs)

### Summary
The kernel bug frees a resource on one path but leaves the pointer in place so later cleanup frees it again. The Serai analog is a *consumed* secret that is never cleared: `SigningProtocol::preprocess_internal` derives FROST nonces deterministically from a cached seed stored in the `CachedPreprocesses` DB table, and that seed is never deleted or rotated after use. Every subsequent `share_internal` call under the same context re-derives the identical nonce pair `(d, e)`, so two signature shares over different messages share the same nonces, enabling private key share recovery.

### Finding Description
`preprocess_internal` stores a random seed on first use and, on every later call, reloads the same seed and passes it to `AlgorithmSignMachine::from_cache` (`coordinator/src/tributary/signing_protocol.rs:123-145`). There is no `CachedPreprocesses::del`/delete anywhere — the entry persists for the lifetime of the context. `seeded_preprocess` then derives `nonces` and `commitments` purely from `ChaCha20Rng::from_seed(*seed.0)` (`crypto/frost/src/sign.rs:127-141`), so the same seed always produces the same `d, e` and the same preprocess commitments. The FROST docs and code comments explicitly warn a cached preprocess "MUST only be used once. Reuse will enable third-party recovery of your private key share" and "the preprocess must be deleted so it's never reused" (`crypto/frost/src/sign.rs:85-87,218-219`), yet the caller never deletes it.

The context for `DkgConfirmer` is `(b"DkgConfirmer", self.attempt)` (`signing_protocol.rs:275`), which is constant for all confirmations within one DKG attempt. `share()`/`complete()` are invoked per generated `KeyPair`, and the signed message `set_keys_message(set, removed, key_pair)` differs per key pair (`signing_protocol.rs:296-301`). Therefore each `share_internal` call signs a *different* message with the *same* nonces.

### Impact Explanation
A FROST share is `z = d + e·rho + lambda·s·c`. With identical `d, e` and identical `rho` (the binding factor depends on the preprocess set, which is the same across calls since our commitments are the same), two shares over messages producing different challenges `c1 ≠ c2` yield `z1 - z2 = lambda·s·(c1 - c2)`, recovering the validator's MuSig/FROST secret share `s`. Combined with threshold-many compromised or observed shares, this breaks the confidentiality of the tributary signing key — equivalent to the double-free's impact class (a stale reference to an already-consumed secret being reused), reachable purely through untrusted `preprocesses`/triggered confirmations supplied via public coordinator messages.

### Likelihood Explanation
The seed is deterministic and persistent; reuse requires only that `share_internal` run more than once under the same `(b"DkgConfirmer", attempt)` context, which occurs whenever a DKG attempt confirms more than one `KeyPair` or when `share`/`complete` are retried after an error (e.g., `FrostError::InvalidPreprocess` from a malformed participant preprocess — note the error path in `share_internal` leaves the cached seed intact for the next call, exactly paralleling the kernel's error path leaving the stale pointer). No attacker needs special privileges — only to feed preprocess messages or trigger multiple confirmations.

### Recommendation
Delete the `CachedPreprocesses` entry immediately after `from_cache` in `preprocess_internal` (single-use semantics), or mix a per-message/per-key-pair counter into the context so each signing operation derives a distinct seed. Additionally, clear the entry on any `share_internal` error path so a failed attempt cannot reuse the same nonces.

### Proof of Concept
Within one DKG attempt (same `attempt` value), `DkgConfirmer::share` is invoked for two distinct `KeyPair`s, `kp1` and `kp2`:
1. First call: `preprocess_internal` reads seed `S` from `CachedPreprocesses[(b"DkgConfirmer", attempt)]` → nonces `(d,e)`, commitments `(D,E)`, share `z1 = d + e·rho + λ·s·c1` over `set_keys_message(.., kp1)`.
2. Second call: same seed `S` (never deleted) → identical `(d,e)`, identical `(D,E)` and `rho`, share `z2 = d + e·rho + λ·s·c2` over `set_keys_message(.., kp2)`, with `c1 ≠ c2` because the transcript commits to the differing message.
3. Observer computes `s = (z1 - z2) / (λ·(c1 - c2))`, recovering the secret key share — matching the "A preprocess MUST only be used once" warning in `crypto/frost/src/sign.rs:85`.
