### Title
Gasless module trusts on-chain `GaslessSwapRouter` token/DEX routing that its owner can silently rewire after users grant infinite approvals, enabling settlement theft - ([File: kaiax/gasless/impl/getter.go])

### Summary
The `kaiax/gasless` module (KIP-247) allows a user to sign a `GaslessApproveTx` granting an **unlimited (`MaxUint256`) allowance** to the `GaslessSwapRouter` contract, and a `GaslessSwapTx` that gets bundled by the block builder with a `LendTxGenerator`. Whether a transaction qualifies as an approve/swap tx, and therefore whether it gets a fee-lending bundle built for it, depends on the *live, mutable* `allowedTokens`/`swapRouter`/DEX-routing state read from the `GaslessSwapRouter` system contract on every block via `updateAddresses()`. That routing state (`addToken`/`removeToken`, which set the `factory`/`router` pair used internally for a token) is owner-controlled with no restriction tied to whether users have already committed (approved) funds to it, unlike the SoundEditionV1_2 pattern in the external report where mutation of "ultimate" parameters is explicitly blocked once irreversible user commitments (mints) exist.

### Finding Description
`GaslessModule.updateAddresses` re-reads the router address and the full token allow-list from the `GaslessSwapRouter` contract every block: [1](#0-0) 

This is used to gate whether a submitted transaction is treated as a gasless `ApproveTx`/`SwapTx` (`isApproveTx`/`isSwapTx`), which in turn determines whether the block builder prepends a `LendTxGenerator` (which funds gas fees on the user's behalf) and bundles `[Lend, Approve, Swap]`: [2](#0-1) [3](#0-2) 

Critically, `isApproveTx` only checks that `spender == g.swapRouter` — a fixed contract address — but the per-token `factory`/`router` DEX mapping used internally by `GaslessSwapRouter` to actually execute the swap is fully mutable by the router's `owner` via `addToken`/`removeToken`, with **no check on whether users have already approved or have pending unrepaid gasless swaps for that token**: [4](#0-3) 

This mirrors the root cause of the external report precisely: in SoundEditionV1_2, `setEditionMaxMintableRange()` explicitly freezes the ultimate supply once `currentTotalMinted != 0` to protect committed users, but the parallel `setSAM()`/`create()` mutation path lacked the equivalent freeze, letting the owner change the "rules" after users had already committed value. Here, the invariant an unprivileged gasless user relies on — "the router will swap my approved token through the DEX pool it was paired with when I approved it" — is never enforced on-chain or by the module: `GaslessSwapRouter`'s owner can call `RemoveToken`/`AddToken` to repoint the `factory`/`router` used for that token to an attacker-controlled pair **after** a user has broadcast (or even after execution begins in the same block, since the router mapping is a single storage read at call time) a `GaslessApproveTx` granting `MaxUint256` allowance, and before/while the corresponding `GaslessSwapTx` executes.

### Impact Explanation
Because the approve transaction grants an unlimited allowance to the fixed `swapRouter` address, and the router's internal notion of "which pool to swap through" for a given token is owner-mutable with no timelock or check against outstanding approvals, a malicious or compromised `GaslessSwapRouter` owner can redirect the swap execution path to a pool they control. Combined with the fact that user repayment amount (`AmountRepay`) is fixed by the user's signed tx while the actual swap output is determined by whatever pool is currently mapped, this allows unauthorized value movement / gasless-settlement theft against unprivileged public users who believed the router was bound to the DEX pool that existed at approval time. This directly matches the "gasless ... settlement theft" impact category.

### Likelihood Explanation
Exploitation requires the router owner (or an attacker who compromises that key) to act, and to time the `addToken`/`removeToken` call around a victim's pending approve/swap pair — this is a privileged action, similar in nature to how the SoundEditionV1_2 issue required the "edition owner" (a privileged but semi-trusted party) to act maliciously. Given `GaslessSwapRouter`'s `addToken`/`removeToken` have no on-chain restriction analogous to `_totalMinted() == 0`/`onlyBeforeMintConcluded`, and the gasless module re-derives its trust state every single block with no staleness or consistency check across the approve/swap pair boundary, the precondition for abuse is trivially reachable at any time — it only requires ordinary owner-key access, not a chain bug.

### Recommendation
- Bind approval validity to the specific `factory`/`router` pairing that existed at approval time (e.g., include a DEX-routing commitment hash in `ApproveTx`/`SwapTx` validation, or snapshot/pin it for the pending pair), similar to how the audit's fix pinned the SAM configurability to `_totalMinted() == 0`.
- Add a cool-down/timelock on `addToken`/`removeToken` for tokens with outstanding user approvals to `swapRouter`, or require zero outstanding allowances before remapping a token's DEX pool.
- Have `kaiax/gasless` verify, at swap-execution/bundling time, that the `factory`/`router` for the swap's token has not changed since the paired `ApproveTx` was accepted into the pool.

### Proof of Concept
1. User Alice signs `GaslessApproveTx` granting `MaxUint256` allowance of Token X to `GaslessSwapRouter` (fixed address `R`), and a following `GaslessSwapTx` swapping Token X via `R`, per `IsApproveTx`/`IsSwapTx` checks in `kaiax/gasless/impl/getter.go` (lines 79-103).
2. Both txs are visible in the mempool; `GaslessModule.ExtractTxBundles` (`kaiax/gasless/impl/builder.go` lines 28-72) will bundle `[LendTxGenerator, ApproveTx, SwapTx]` once ready.
3. Before/at inclusion, the owner of `GaslessSwapRouter` calls `RemoveToken(X)` then `AddToken(X, maliciousFactory, maliciousRouterPool)` (`contracts/bindings/kip247/GaslessSwapRouter.go` lines 470-531) — `g.swapRouter` in the gasless module (checked in `isApproveTx`/`isSwapTx`) is unchanged, so the bundle is still built and accepted.
4. `ApproveTx` executes, granting infinite allowance to `R`. `SwapTx` executes against `R`, which now internally routes Token X through the attacker-controlled `maliciousFactory`/`maliciousRouterPool`, extracting value from Alice's approved balance while she still owes the fixed `AmountRepay` to the lender per `repayAmount` logic in `kaiax/gasless/impl/getter.go`.

*Note: the exact Solidity implementation of `GaslessSwapRouter.swapForGas` (how the `factory`/`router` mapping is consumed during a swap) was not available in the indexed codebase context (only Go ABI bindings were found, not the `.sol` source), so the precise on-chain fund-flow mechanics of the redirected swap could not be fully verified from the index. A Devin session with full repository access should confirm the exact `swapForGas` logic in `GaslessSwapRouter.sol` to finalize the exploit mechanics.*

func (g *GaslessModule) isApproveTx(args *ApproveArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.allowedTokens[args.Token] && // A1
		g.swapRouter == args.Spender && // A3
		args.Amount.Cmp(abi.MaxUint256) == 0 // A4
}

// IsSwapTx checks following conditions:
// S1. tx.to is a whitelisted SwapRouter contract.
// S2. tx.data is `swapForGas(token, amountIn, minAmountOut, amountRepay)`.
// S3. token is a whitelisted ERC20 token.
func (g *GaslessModule) IsSwapTx(tx *types.Transaction) bool {
	args, ok := decodeSwapTx(tx, g.signer)
	return ok && g.isSwapTx(args)
}

func (g *GaslessModule) isSwapTx(args *SwapArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.swapRouter == args.Router && // S1
		g.allowedTokens[args.Token] // S3
}

func (g *GaslessModule) updateAddresses(header *types.Header) error {
	g.gaslessInfoMu.Lock()
	defer g.gaslessInfoMu.Unlock()

	swapRouter, tokens, err := getGaslessInfo(g.Chain, header)
	// proceed even if there is something wrong with multicall contract
	if err != nil {
		g.swapRouter = common.Address{}
		g.allowedTokens = map[common.Address]bool{}
		logger.Warn("there is something wrong with multicall contract", "err", err.Error())
		return nil
	}

	g.swapRouter = swapRouter

	g.allowedTokens = map[common.Address]bool{}
	for _, addr := range tokens {
		// all tokens are allowed if nil
		if g.GaslessConfig.AllowedTokens == nil {
			g.allowedTokens[addr] = true
		}
		for _, allowed := range g.GaslessConfig.AllowedTokens {
			if addr == allowed {
				g.allowedTokens[addr] = true
			}
		}
	}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}
