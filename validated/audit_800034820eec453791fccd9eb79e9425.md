## #Vulnerability found for this question.

### Title
DataLayer mirror coins let any unprivileged spender inject arbitrary URLs that peers auto-fetch without host validation (SSRF) - ([File: chia/data_layer/download_data.py])

### Summary
Chia's DataLayer mirror mechanism lets anyone create a `CREATE_COIN` spend with the mirror puzzle and arbitrary `(launcher_id, url...)` memos for *any* store id, with no proof of ownership of that singleton. Peers that subscribe to (or own) the referenced store automatically pull these attacker-supplied URLs into their local server list and issue outbound HTTP GET requests to them via `http_download()`, with no host allow-listing, scheme restriction, private-IP/SSRF guard, or binding of the fetch target to a trusted host. This mirrors the OpenClaw CWE-918 bug class: an untrusted "node payload" URL is trusted and fetched by the local host without host-binding checks.

### Finding Description
Mirror creation is a plain XCH spend, not a singleton-authorized action: [1](#0-0) 

`create_new_mirror()` calls `standard_wallet.generate_signed_transaction()` with `puzzle_hashes=[create_mirror_puzzle().get_tree_hash()]` and `memos=[[launcher_id, *urls]]`. `create_mirror_puzzle()` is just `P2_PARENT.curry(Program.to(1))` — an anyone-can-create-coin puzzle, not gated by the DL singleton's inner puzzle or ownership: [2](#0-1) 

Any wallet with sufficient XCH can therefore submit a spend bundle creating a mirror coin whose memo names a `launcher_id` that belongs to a store it doesn't own, paired with arbitrary attacker-chosen `url` strings — there is no CWE-918-relevant validation of the URL's scheme/host, and no check that the submitter controls the referenced singleton.

`get_mirror_info()` extracts `launcher_id`/`urls` purely from the `CREATE_COIN` condition memos with no further validation: [3](#0-2) 

Wallets store these as `Mirror` records and expose them via `dl_get_mirrors`: [4](#0-3) 

The DataLayer service periodically merges these attacker-controlled URLs into local subscription state for the referenced store id, unconditionally: [5](#0-4) 

`periodically_manage_data()` runs this for every subscription and every owned store on a timer: [6](#0-5) 

`fetch_and_validate()` then picks a server URL from that list and calls `insert_from_delta_file()` → `download_file()` → `http_download()`: [7](#0-6) 

`http_download()` issues a raw `aiohttp` GET straight to `server_info.url + "/" + filename` with no host/scheme allow-listing, no SSRF guard, and no verification that the URL belongs to a trusted mirror operator: [8](#0-7) 

The only content-level protection is `is_filename_valid()`, which validates the *filename* format, not the *URL host* being fetched: [9](#0-8) 

So the fetch destination itself (`server_info.url`) is fully attacker-controlled and unvalidated — directly analogous to the OpenClaw flaw where `camera.snap`/`camera.clip` `url` payloads were fetched without binding to the resolved node host.

### Impact Explanation
Any unprivileged actor who can submit a spend bundle (i.e., anyone who can pay a small XCH amount + fee) can force the DataLayer host of *every node that subscribes to, or owns, a targeted store* to make outbound HTTP requests to attacker-chosen URLs/hosts — including internal/private network addresses, cloud metadata endpoints, or other services reachable from the node's network. This is a spend-triggered SSRF pivot from the local gateway/DataLayer process, reachable purely from a submitted transaction (no wallet-owner interaction, no operator/node compromise required), matching the "Data Layer roots and proofs" reachable surface in scope. It does not require compromising a peer — the mirror-URL propagation mechanism is itself the on-chain vector.

### Likelihood Explanation
Likelihood is high for any deployment where DataLayer subscription/auto-management is enabled: mirror coins are cheap to create (fee + small XCH amount), can target arbitrary `launcher_id`s without any ownership check, and `periodically_manage_data()` runs continuously by default, automatically pulling in and fetching from any newly observed mirror URL for tracked stores.

### Recommendation
- Require mirrors to be created/authorized only by the actual owner of the referenced DL singleton (e.g., bind mirror-coin creation to a spend of the singleton itself, or require a signature/lineage proof tying the mirror to the launcher's current owner) rather than accepting any `CREATE_COIN` with matching puzzle hash and arbitrary memo content.
- Add SSRF-hardening to `http_download()`/`get_downloader()` in `chia/data_layer/download_data.py` and `chia/data_layer/data_layer.py`: validate URL scheme (https/http only), resolve and reject private/loopback/link-local/metadata IP ranges, and re-validate on redirect.
- Consider making mirror URL usage opt-in/allow-listed per store rather than automatically merged from any on-chain mirror record in `update_subscriptions_from_wallet()`.

### Proof of Concept
1. Attacker (any wallet with a small amount of XCH) calls `dl_new_mirror` (or `data_rpc_api.add_mirror`) with `launcher_id` set to a *victim* DataLayer store id they don't own, and `urls=["http://169.254.169.254/latest/meta-data/"]` (or any internal RFC1918 address), per `chia/wallet/wallet_rpc_api.py` `dl_new_mirror()` → `DataLayerWallet.create_new_mirror()`.
2. The resulting spend bundle is accepted into the mempool/block since it's just a valid `CREATE_COIN` from the attacker's own coin to the mirror puzzle hash with memos — no singleton ownership check occurs (`chia/wallet/db_wallet/db_wallet_puzzles.py` `create_mirror_puzzle()`/`get_mirror_info()`).
3. Any node subscribed to (or owning) the victim store id runs `periodically_manage_data()` → `update_subscriptions_from_wallet()` (`chia/data_layer/data_layer.py:979-985`), which pulls the attacker's URL into its subscription list.
4. `fetch_and_validate()` → `insert_from_delta_file()` → `download_file()` → `http_download()` (`chia/data_layer/download_data.py:298-324`) issues an outbound HTTP GET from the node's own network context to the attacker-chosen host/URL, completing the SSRF fetch pivot.

```python
def create_mirror_puzzle() -> Program:
    return P2_PARENT.curry(Program.to(1))


MIRROR_PUZZLE_HASH = create_mirror_puzzle().get_tree_hash()


def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
def is_filename_valid(filename: str, group_by_store: bool = False) -> bool:
    if group_by_store:
        if filename.count("/") != 1:
            return False
        filename = filename.replace("/", "-")

    split = filename.split("-")

    try:
        raw_store_id, raw_node_hash, file_type, raw_generation, raw_version, *rest = split
        store_id = bytes32(bytes.fromhex(raw_store_id))
        node_hash = bytes32(bytes.fromhex(raw_node_hash))
        generation = int(raw_generation)
    except ValueError:
        return False

    if len(rest) > 0:
        return False

    # TODO: versions should probably be centrally defined
    if raw_version != "v1.0.dat":
        return False

    if file_type not in {"delta", "full"}:
        return False

    generate_file_func = get_delta_filename if file_type == "delta" else get_full_tree_filename
    reformatted = generate_file_func(
        store_id=store_id, node_hash=node_hash, generation=generation, group_by_store=False
    )

    return reformatted == filename
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
```
