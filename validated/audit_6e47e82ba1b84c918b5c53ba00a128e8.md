### Title
Deterministic cached FROST nonces reused across multiple `share`/`complete` invocations enable validator key recovery - (File: coordinator/src/tributary/signing_protocol.rs)

### Summary
The kernel bug class is *state that remains usable after a failed/repeated initialization*: `nf_nat_init()` fails yet the hook path still dereferences `nat_net`. The Serai analog lives in `SigningProtocol::preprocess_internal`/`share_internal`: the preprocess seed is cached in `CachedPreprocesses` keyed only by `context` and is **never consumed or invalidated**, so every call to `share_internal` regenerates the identical FROST nonces `(d, e)` from `ChaCha20Rng::from_seed(*seed.0)` [1](#0-0) [2](#0-1) . A participant who feeds different preprocess sets/messages into repeated `share`/`complete` calls obtains multiple shares built on the same `(d, e)`, enabling algebraic recovery of the coordinator's MuSig secret key.

### Finding Description
`preprocess_internal` stores an XOR-encrypted 32-byte seed under `CachedPreprocesses::set(txn, &context, ...)` only when absent, then unconditionally reloads that same seed on every invocation [1](#0-0) . `share_internal` calls `preprocess_internal` and then `machine.sign(preprocesses, msg)` with attacker-influenced `serialized_preprocesses` [3](#0-2) . `DkgConfirmer::share` and `DkgConfirmer::complete` both funnel into `share_internal` for the same `(b"DkgConfirmer", attempt)` context [4](#0-3) . In `AlgorithmSignMachine::sign`, the effective nonce is `actual = base + rho * actual` where `base = d`, `actual = e` come from the reused seed, while `rho` is bound to the signer's index, the group key, `hash_msg(msg)`, and the *other participants'* commitments [5](#0-4) . Because `rho` and the challenge `c` vary with the adversary-supplied commitment set and message while `d, e` stay fixed, each produced share is `s_i = d + rho_i·e + c_i·x`.

### Impact Explanation
Three observed shares with distinct `(rho_i, c_i)` yield a 3×3 linear system over `d, e, x`, directly recovering `x` — the coordinator's Ristretto validator secret key used in the MuSig DKG-confirmation protocol. With the key, an attacker can forge `Signed` tributary transactions and sign future confirmations, i.e., full key-share recovery and signing of unintended messages. The file's own safety argument acknowledges nonce reuse is catastrophic and rests entirely on BFT ordering guaranteeing identical inputs [6](#0-5) , yet nothing cryptographically enforces single-use: `share()` and `complete()` are independent entry points, and `complete` re-signs even after `share` succeeded [7](#0-6) .

### Likelihood Explanation
Reachability requires the adversary to cause `share_internal` to run multiple times for one context with differing preprocess maps or messages — e.g., `share()` invoked on one finalized preprocess set and `complete()` invoked on a different set, or repeated calls after a sign failure returns `Err` (the error path does not delete the cached seed) [8](#0-7) . Whether BFT ordering actually prevents divergent inputs in `handle.rs` could not be fully verified within the tool-iteration budget; the finding is that the code relies purely on that assumption while the dangerous primitive — a persistent, replayable nonce seed — is unconditionally wired in.

### Recommendation
Consume/delete the `CachedPreprocesses` entry (or record a "share-issued" flag keyed by the exact commitment-set digest and msg) before returning a share, and make `complete` reuse the share produced by `share` rather than re-signing via `share_internal`. Bind the cache key to the full signing context (participant set + message) so any divergent input derives fresh nonces.

### Proof of Concept
1. Validator set where attacker controls ≥1 participant in a `DkgConfirmer` attempt with context `C = (b"DkgConfirmer", attempt)`.
2. Trigger `confirmer.share(P1, kp)` with preprocess set P1 → coordinator emits `s1 = d + rho1·e + c1·x` (seed loaded/created under `C`).
3. Trigger `confirmer.complete(P2, kp, shares)` with a different preprocess set P2 → `share_internal` reloads the same seed, emitting `s2 = d + rho2·e + c2·x` with `rho2 ≠ rho1`, `c2 ≠ c1` (computed locally since all inputs are public).
4. Obtain a third share from any further `share`/`complete` invocation; solve the linear system for `x`, the coordinator's private key.

    &mut self,
    participants: &[<Ristretto as Ciphersuite>::G],
    mut serialized_preprocesses: HashMap<Participant, Vec<u8>>,
    msg: &[u8],
  ) -> Result<(AlgorithmSignatureMachine<Ristretto, Schnorrkel>, [u8; 32]), Participant> {
    let machine = self.preprocess_internal(participants).0;

    let mut participants = serialized_preprocesses.keys().copied().collect::<Vec<_>>();
    participants.sort();
    let mut preprocesses = HashMap::new();
    for participant in participants {
      preprocesses.insert(
        participant,
        machine
          .read_preprocess(&mut serialized_preprocesses.remove(&participant).unwrap().as_slice())
          .map_err(|_| participant)?,
      );
    }

    let (machine, share) = machine.sign(preprocesses, msg).map_err(|e| match e {
      FrostError::InternalError(e) => unreachable!("FrostError::InternalError {e}"),

      FrostError::InvalidSigningSet(_) |
      FrostError::InvalidParticipantQuantity(_, _) |
      FrostError::DuplicatedParticipant(_) |
      FrostError::MissingParticipant(_) => unreachable!("{e:?}"),
      FrostError::InvalidPreprocess(p) | FrostError::InvalidShare(p) => p,
    })?;

    Ok((machine, share.serialize().try_into().unwrap()))

  fn seeded_preprocess(
    self,
    seed: CachedPreprocess,
  ) -> (AlgorithmSignMachine<C, A>, Preprocess<C, A::Addendum>) {
    let mut params = self.params;

    let mut rng = ChaCha20Rng::from_seed(*seed.0);
    let (nonces, commitments) = Commitments::new::<_>(
      &mut rng,
      params.keys.original_secret_share(),
      &params.algorithm.nonces(),
    );
    let addendum = params.algorithm.preprocess_addendum(&mut rng, &params.keys);

    let preprocess = Preprocess { commitments, addendum };

    // Also obtain entropy to randomly sort the included participants if we need to identify blame
    let mut blame_entropy = [0; 32];
    rng.fill_bytes(&mut blame_entropy);
    (
      AlgorithmSignMachine { params, seed, nonces, preprocess: preprocess.clone(), blame_entropy },
      preprocess,
    )
  }
