### Title
Stale `gitHubRepository` association is never invalidated after a remote is changed or removed, causing continued authenticated account binding on out-of-date ownership - (File: `app/src/lib/stores/app-store.ts`)

### Summary
The external report's bug class is a **removal that doesn't actually clear the trust state**: `removeLiquidityPool` deletes an entry from a set, but `isLiquidityPool` still returns `true` via an independent fast-path check that was never reset, so downstream logic keeps applying "trusted pool" behavior. The Desktop analog is `AppStore.repositoryWithRefreshedGitHubRepository`, which explicitly and intentionally never clears a `Repository`'s cached `gitHubRepository` association once the underlying remote stops matching a known GitHub account/host — the code comment even references this as a known-open issue. All downstream authorization/permission logic keeps trusting the stale association.

### Finding Description
When Desktop re-syncs a repository's GitHub metadata it tries to re-derive the match from the current remote: [1](#0-0) 

```
private async repositoryWithRefreshedGitHubRepository(
  repository: Repository
): Promise<Repository> {
  const repoStore = this.repositoriesStore
  const match = await this.matchGitHubRepository(repository)

  // TODO: We currently never clear GitHub repository associations (see
  // https://github.com/desktop/desktop/issues/1144). So we can bail early at
  // this point.
  if (!match) {
    return repository
  }
```

`matchGitHubRepository` derives the match purely from the **current default remote URL's hostname** matching a signed-in account's endpoint: [2](#0-1) 

If a user (or an attacker who can rewrite `.git/config`/remotes, e.g. via a malicious script bundled in a cloned repo, a compromised build tool, or a `git remote set-url` executed by tooling) changes the origin remote to a non-GitHub host or removes it, `match` becomes `null` and the function returns the **unmodified `repository`** object — the old `gitHubRepository` (owner, name, `endpoint`, `parent`, `isPrivate`, permissions) is preserved forever, by explicit design (`desktop/desktop#1144`).

Every consumer that gates authenticated behavior on `isRepositoryWithGitHubRepository(repository)` (a pure null-check on the stale field, not a remote-recheck) continues to operate as if nothing changed:

- `getAccountForRepository` picks the signed-in account/token to use for API calls purely from `repository.gitHubRepository.endpoint`, with no re-validation against the live remote: [3](#0-2) 
- That account is then used to fetch branch protections, PR checks, mentionables, and to decide Copilot/commit-message eligibility for the repository, all keyed off the stale association: [4](#0-3) [5](#0-4) 
- The LFS proxy fallback URL is resolved from the stale `gitHubRepository.endpoint` rather than the actual current remote: [6](#0-5) 
- Repo-rules enablement and fork-contribution-target permission checks (`isRepositoryWithForkedGitHubRepository`) also key off this never-invalidated field: [7](#0-6) [8](#0-7) 

The corrupted value is `Repository.gitHubRepository` (owner/name/endpoint/permissions/parent): it should be cleared or re-validated whenever the tracked remote no longer resolves to it, but the guard (`isRepositoryWithGitHubRepository`) only checks "is this field non-null", exactly mirroring `isLiquidityPool`'s "is this address still in the fast-path check" — neither guard is invalidated on removal.

### Impact Explanation
This does not itself leak the OAuth token to an attacker-controlled server (the trampoline credential helper independently host-scopes credential lookups via `getCredentialUrl`, so it isn't affected). The concrete impact is **unauthorized account/permission binding survives a remote change/removal**: Desktop keeps treating a local working copy as bound to the original GitHub owner/repo (and its permissions, fork/parent relationship, and repo-rules eligibility) even after the remote no longer corresponds to it, which can cause the app to keep making authenticated API calls, apply stale branch-protection/PR/notification behavior, or misroute LFS proxy resolution based on an association that should have been dropped once the remote diverged.

### Likelihood Explanation
Reaching this path only requires a user-visible action that changes the remote of a repository Desktop is already tracking (e.g. opening a repository whose `.git/config` was altered by a script in the cloned tree, or the remote pointing to a decommissioned/renamed repo) — no admin rights, local exploit, or leaked credentials are required, and the maintainers themselves have flagged this as an outstanding, intentional gap (`desktop/desktop#1144`), confirming it is a real, currently-unaddressed invariant violation rather than a hypothetical.

### Recommendation
When `matchGitHubRepository` returns `null` (the current remote no longer resolves to a known account/host), clear `repository.gitHubRepository` (set to `null`) instead of returning the repository unmodified, and re-derive downstream permission/authentication decisions from the cleared state — mirroring the AgentToken fix of resetting `uniswapV2Pair` to a neutral value on removal rather than leaving stale trust data in place.

### Proof of Concept
1. Sign in to a GitHub.com account in Desktop and add/clone a repository so `Repository.gitHubRepository` is populated (owner/name/endpoint/permissions).
2. Change the repository's remote to a URL/host unrelated to any signed-in account, e.g. `git remote set-url origin https://example.com/foo/bar.git` (or remove the remote), simulating what a build script or malicious repo content could do.
3. Trigger `repositoryWithRefreshedGitHubRepository` (occurs on account-change refresh, adding the repo again, etc.) — observe in `app/src/lib/stores/app-store.ts:4880-4885` that `match` is `null` and the function returns the original `repository` object unchanged.
4. Confirm `isRepositoryWithGitHubRepository(repository)` still returns `true` and `getAccountForRepository` (`app/src/lib/get-account-for-repository.ts:11-21`) still resolves the original account/endpoint, and that branch-protection/PR/notification logic keyed on `repository.gitHubRepository` continues to execute using the stale owner/name — exactly analogous to `isLiquidityPool` still returning `true` for a pair removed via `removeLiquidityPool`.

/** Try to use the list of users and a remote URL to guess a GitHub repository. */
export function matchGitHubRepository(
  accounts: ReadonlyArray<Account>,
  remote: string
): IMatchedGitHubRepository | null {
  for (const account of accounts) {
    const htmlURL = getHTMLURL(account.endpoint)
    const { hostname } = URL.parse(htmlURL)
    const parsedRemote = parseRemote(remote)

    if (parsedRemote !== null && hostname !== null) {
      if (parsedRemote.hostname.toLowerCase() === hostname.toLowerCase()) {
        return { name: parsedRemote.name, owner: parsedRemote.owner, account }
      }
    }
  }

  return null
}

export function getAccountForRepository(
  accounts: ReadonlyArray<Account>,
  repository: Repository
): Account | null {
  const gitHubRepository = repository.gitHubRepository
  if (!gitHubRepository) {
    return null
  }

  return getAccountForEndpoint(accounts, gitHubRepository.endpoint)
}

export function isRepositoryWithGitHubRepository(
  repository: Repository
): repository is RepositoryWithGitHubRepository {
  return repository.gitHubRepository instanceof GitHubRepository
}

/**
 * Asserts that the passed repository is a GitHub repository.
 */
export function assertIsRepositoryWithGitHubRepository(
  repository: Repository
): asserts repository is RepositoryWithGitHubRepository {
  if (!isRepositoryWithGitHubRepository(repository)) {
    return fatalError(`Repository must be GitHub repository`)
  }
}

/**
 * Returns whether the passed repository is a GitHub fork.
 *
 * This function narrows down the type of the passed repository to
 * RepositoryWithForkedGitHubRepository if it returns true.
 */
export function isRepositoryWithForkedGitHubRepository(
  repository: Repository
): repository is RepositoryWithForkedGitHubRepository {
  return (
    isRepositoryWithGitHubRepository(repository) &&
    repository.gitHubRepository.parent !== null
  )
}
