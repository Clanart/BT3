### Title
`ReceivedOutput::read` accepts untrusted output/offset pairs without re-deriving the script binding, enabling forged deposits and signing under attacker-chosen offsets - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The GitLab report describes an authorization-restriction bypass: an alternate path (GraphQL) exposed data that the primary path restricted. The analog in bitcoin-serai is that `Scanner` carefully binds each `ReceivedOutput` to a `(script_pubkey, offset)` pair it derived, but `ReceivedOutput::read` deserializes the same structure from untrusted bytes with no such binding — the `offset` scalar, `TxOut` (script and value), and `outpoint` are all attacker-controlled and mutually inconsistent fields are accepted. Downstream, `SignableTransaction::new` trusts `output.value` for fee/change math and `multisig` re-derives `p2tr_script_buf(key + offset·G)` — a check the attacker can satisfy with a chosen offset — causing threshold signature shares to be produced under an attacker-selected key tweak for an attacker-crafted sighash.

### Finding Description
`Scanner::register_offset`/`scan_transaction` guarantee `scripts[script_pubkey] == offset` where `script_pubkey == p2tr(key + offset·G)` [1](#0-0) [2](#0-1) . `ReceivedOutput::read` performs no equivalent check: it reads an arbitrary scalar via `Secp256k1::read_F`, then arbitrary `TxOut`/`OutPoint` consensus bytes [3](#0-2) . There is no stored group key to validate against, so any deserialized `ReceivedOutput` is trusted as a genuine scan result.

In `SignableTransaction::new`, the attacker-controlled `output.value` is summed as `input_sat` for the funds/fee/change computation [4](#0-3) , and `prevouts` (which commit into the BIP-341 `Prevouts::All` sighash) are taken verbatim [5](#0-4) [6](#0-5) .

`multisig` only verifies `p2tr_script_buf(offset.group_key()) == prevouts[i].script_pubkey` [7](#0-6) . An attacker satisfies this by choosing offset `x` and `script_pubkey = p2tr(key + x·G)`, which they can compute from the public group key. The outpoint and value remain entirely fictitious. The result: every participant's `AlgorithmMachine` signs a BIP-341 sighash committing to attacker-chosen prevout values under the tweaked key `k + x` — a signing key relation the attacker selected [8](#0-7) .

### Impact Explanation
Two accepted-impact consequences:

1. Funds reported received that are not spendable: a forged `ReceivedOutput` with a fabricated `outpoint`/`value` is indistinguishable from a real scanned deposit to any consumer that deserializes rather than re-scans, inflating apparent balance and causing transactions that can never confirm.
2. Unintended-message signing: by choosing `x` freely, the attacker obtains FROST signature shares under `k + x` over sighashes committing to fabricated prevouts — a related-key signing oracle the honest `Scanner` path never exposes, since `register_offset` only accepts offsets it derives [9](#0-8) .

### Likelihood Explanation
Requires an unprivileged party to supply `ReceivedOutput` bytes to a wallet consumer that accepts serialized outputs (the crate explicitly exposes `read`/`serialize` for transport/storage). No validator collusion, key leakage, or chain manipulation is needed — only forged bytes. Severity is Medium: the fabricated input cannot steal existing funds directly, but it corrupts balance reporting and yields signing shares under attacker-chosen key tweaks over attacker-chosen sighashes.

### Recommendation
Bind the deserialized structure to the scanner invariant. Either store the group key in/with `ReceivedOutput` and have `read` (or a `verify`/`new_checked` constructor) assert `output.script_pubkey == p2tr_script_buf(key + offset·G)` and that the script is a v1 P2TR output, or authenticate serialized `ReceivedOutput`s so deserialization cannot introduce attacker-invented `(offset, script, outpoint, value)` tuples. `SignableTransaction::new`/`multisig` should treat `ReceivedOutput` as untrusted and re-verify the full invariant, not just the script equality.

### Proof of Concept

let fake = ReceivedOutput::read(&mut serialize_fake(
    x,                                                    // arbitrary offset
    TxOut { value: Amount::from_sat(100_000_000),         // fictitious 1 BTC
            script_pubkey: script },                      // satisfies multisig() check
    OutPoint { txid: Txid::all_zeros(), vout: 0 },        // nonexistent outpoint
).as_slice()).unwrap();

// Consumer deserializes and builds a spend:
let tx = SignableTransaction::new(vec![fake], &payments, Some(change), None, fee).unwrap();
// multisig() succeeds: p2tr(key + x*G) == prevout.script_pubkey
let machine = tx.multisig(&keys).unwrap();
// Participants produce signature shares under key k + x over a sighash committing to
// the fabricated 1 BTC prevout — an unintended message under an attacker-chosen tweak.

  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }
