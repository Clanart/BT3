## Finding: `object::root_owner` lacks the nesting/cycle bound enforced everywhere else in the ownership-traversal code, and it gates the publish-path self-init owner check

### Title
Unbounded cyclic traversal in `object::root_owner` breaks the object-ownership invariant relied on by the code-publish self-init guard - (File: `aptos-move/framework/aptos-framework/sources/object.move`)

### Summary
`aptos_framework::object::root_owner` walks the object ownership chain with an unbounded `while` loop, unlike every other ownership-chain walker in the same module (`owns`, `verify_ungated_and_descendant`), which explicitly enforce `MAXIMUM_OBJECT_NESTING` (8) to guard against cycles. `root_owner` is the exact function used by the new publish-safety mechanism in `code::publish_package` (to record the deploy-time owner for lazy module initialization) and in `init::assert_may_self_initialize` (to gate minting a self-init signer for object-hosted modules). Because ownership cycles are constructible with ordinary, legitimate `object::transfer` calls (verification only checks reachability back to the *transferring signer*, not global acyclicity), a cyclic object graph causes `root_owner` to loop without termination wherever it is invoked in the publish/self-init path.

### Finding Description
In `aptos-move/framework/aptos-framework/sources/object.move`: [1](#0-0) 

`root_owner` has no depth bound, while its siblings do: [2](#0-1) [3](#0-2) 

Critically, `verify_ungated_and_descendant` (used by `transfer`/`transfer_to_object`) only checks that the *signer* performing a transfer can reach the destination object within 8 hops — it does not check the graph is acyclic overall. Two ordinary transfers by the *same* owner are enough to create a genuine ownership cycle between two objects `A` and `B`:
1. Owner transfers `A` into `B` (`A.owner = B`) — passes, since `B` is directly owned by the same signer.
2. Owner transfers `B` into `A` (`B.owner = A`) — passes, since `A`'s owner chain (`A -> B -> owner`) reaches the signer within the bound.

After step 2, `A.owner == B` and `B.owner == A`: a fully valid, on-chain, 2-cycle, reachable purely through public entry functions, with no aborts. (The existing single-object self-loop test even demonstrates the 1-cycle case is legal for one transfer: `test_cyclic_ownership_transfer_should_fail` only fails on the *second* self-transfer because `verify_ungated_and_descendant`'s bound triggers — it is not a cycle-detection abort.) [4](#0-3) 

Once such a cycle exists at an address that hosts (or will host) published code, `root_owner` is invoked from two publish/self-init sites: [5](#0-4) [6](#0-5) 

Both call sites feed a cyclic-owner object address into `root_owner`'s unbounded loop, which never converges (`obj_owner` keeps flip-flopping between the cycle members and `is_object(obj_owner)` is always true).

### Impact Explanation
This breaks a documented, audited code-safety invariant of the publish path: `code.move`'s spec comments explicitly state the ownership-recording flow is meant to prevent "the caller [minting] a signer for an object it no longer controls," and `init.move`'s design doc states the guard should "fail-closed" cleanly with `EOWNER_CHANGED_SINCE_DEPLOY`. Instead of a clean, well-defined abort, a cyclic owner graph turns the check into resource exhaustion (loop runs until gas is exhausted), which:
- Silently breaks the invariant enforcement path (`assert_may_self_initialize`) with a nondeterministic/expensive failure mode instead of the intended, cheap, explicit permission-denied abort.
- Can permanently and unrecoverably DoS the `LAZY_MODULE_INITIALIZATION`-gated self-init and the object-owner recording step of `code::publish_package`/`object_code_deployment::publish`/`upgrade` for any code object whose ownership graph is cyclic, since every future publish/self-init call to that address burns gas until it aborts, with no way to "undo" a cycle already recorded on chain (transfers into/out of the cycle members can themselves need `root_owner`/`owns`-style traversal that is bounded, but nothing un-cycles an already-cyclic pair short of another transfer breaking it).
- Is directly reachable via ordinary public entry points (`object::transfer`, `object::transfer_to_object`, `code::publish_package_txn`, `object_code_deployment::publish/upgrade`) — no privileged access required.

### Likelihood Explanation
Constructing the cycle requires only two ordinary, permissionless `transfer` calls by a single object owner over two objects they control — no admin or governance rights needed. Triggering the bug requires the `LAZY_MODULE_INITIALIZATION` feature flag to be active (it is currently marked "transient" in `features.move`), which limits *current* mainnet exposure but does not require any other precondition once that flag is live; it is a straightforward, deterministic reproduction with any test harness that enables the flag.

### Recommendation
Bound `root_owner`'s traversal the same way `owns` and `verify_ungated_and_descendant` are bounded — e.g., loop at most `MAXIMUM_OBJECT_NESTING` times and either return the address reached at that depth or abort with `EMAXIMUM_NESTING`/a dedicated error, so that `code::publish_package` and `init::assert_may_self_initialize` see a deterministic, cheap abort instead of unbounded traversal. Additionally, consider rejecting `transfer`/`transfer_to_object` calls that would create any cycle (not just ones exceeding the depth bound relative to the signer), since a legal 2+-object cycle is a broader invariant violation than just this one call site.

### Proof of Concept
1. Enable `FeatureFlag::LAZY_MODULE_INITIALIZATION`.
2. As `attacker`, create two objects `A` and `B` (e.g., via `object::create_object`).
3. Call `object::transfer_to_object(attacker, A, B)` → succeeds (`A.owner = B`).
4. Call `object::transfer_to_object(attacker, B, A)` → succeeds (`B.owner = A`), forming the cycle `A <-> B`.
5. Publish (or attempt to lazily self-init) a module at address `A` (or `B`) while `LAZY_MODULE_INITIALIZATION` is enabled — `code::publish_package` (or `init::internal_maybe_initialize` → `assert_may_self_initialize`) calls `object::address_to_object::<ObjectCore>(addr).root_owner()`, which loops indefinitely between `A` and `B` until the transaction runs out of gas, instead of returning a deterministic owner or a clean, cheap abort.

    /// object between the two allows for ungated transfers. Note, this is limited to a depth of 8

    fun verify_ungated_and_descendant(owner: address, destination: address) {
        let current_address = destination;
        assert!(
            exists<ObjectCore>(current_address),
            error::not_found(EOBJECT_DOES_NOT_EXIST),
        );

        let object = borrow_global<ObjectCore>(current_address);
        assert!(
            object.allow_ungated_transfer,
            error::permission_denied(ENO_UNGATED_TRANSFERS),
        );

        let current_address = object.owner;
        let count = 0;
        while (owner != current_address) {
            count += 1;
            assert!(count < MAXIMUM_OBJECT_NESTING, error::out_of_range(EMAXIMUM_NESTING));
            // At this point, the first object exists and so the more likely case is that the
            // object's owner is not an object. So we return a more sensible error.

            assert!(

                error::permission_denied(ENO_UNGATED_TRANSFERS),

        };

    /// Note: intentionally not using `self` as first argument, as a.owns(b) syntax would be ambiguous.
    public fun owns<T: key>(object: Object<T>, owner: address): bool {
        let current_address = object.object_address();

        assert!(
            exists<ObjectCore>(current_address),
            error::not_found(EOBJECT_DOES_NOT_EXIST),
        );

        if (current_address == owner) {
            return true
        };

        let object = borrow_global<ObjectCore>(current_address);
        let current_address = object.owner;

        let count = 0;
        while (owner != current_address) {
            count += 1;
            assert!(count < MAXIMUM_OBJECT_NESTING, error::out_of_range(EMAXIMUM_NESTING));
            if (!exists<ObjectCore>(current_address)) {
                return false
            };

            let object = borrow_global<ObjectCore>(current_address);
            current_address = object.owner;
        };
        true
    }
