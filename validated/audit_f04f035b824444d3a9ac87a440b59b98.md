### Title
Path-traversal/symlink-escape read of arbitrary files during Copilot conflict-resolution diff preview - (File: `app/src/lib/git/diff.ts`, function `getResolutionDiff`)

### Summary
The write path that applies Copilot-generated merge-conflict resolutions (`app-store.ts`, `_applyCopilotConflictResolutions`) and the context-gathering path that reads conflicted files before sending them to Copilot (`copilot-conflict-context.ts`, `buildConflictContext`) both resolve the attacker-influenced, repository-relative conflict file path through `resolveWithin()` before touching the filesystem, explicitly to guard against "path traversal and symlink escapes." The diff-preview path used to render the same resolution in the UI, `getResolutionDiff` in `app/src/lib/git/diff.ts`, reads the same kind of path with a bare `Path.join(repository.path, filePath)` and no `resolveWithin` check. ### Finding Description
This mirrors the report's broken invariant exactly: a security-relevant primitive (`safeTransferFrom`'s `src == msg.sender` handling / here, "conflict file path always resolves inside the repo root") is enforced in most call sites, but one sibling code path that consumes the *same untrusted input* (a repository-relative path taken from the git conflict state, which is attacker-influenced content in a cloned/merged repository) skips the guard.

`getResolutionDiff` is invoked by the Copilot-conflicts UI (`copilot-conflicts-changes.tsx`) to build the "before/after" diff shown to the user for each conflicted file, for all three resolution choices (Copilot, ours, theirs). It reads what it calls the "working-tree file" via:

```
const baseContent = await readFile(Path.join(repository.path, filePath), 'utf8')
```

`filePath` is the repository-relative conflict path, sourced from the merge/rebase/cherry-pick conflict state (same `resolution.path` / conflicted-file path used elsewhere). If a malicious remote/branch that the victim merges, rebases onto, or cherry-picks from introduces a *path component that is itself, or resolves through, a symlink* — e.g. a tracked symlink named `evil` pointing to `../../../../etc/passwd` or to a sensitive file outside the working directory, checked into the malicious branch as a conflicting entry — then `Path.join(repository.path, filePath)` followed by a plain `readFile` will happily follow the symlink and read content **outside the repository root**, exactly the class of attack `resolveWithin` (used in `buildConflictContext` and `_applyCopilotConflictResolutions`) is designed to stop: [4](#0-3) 

The corrupted value here is `baseContent`: instead of being guaranteed to be the contents of a file inside the user's repository, it can be the contents of an arbitrary file reachable via a symlink placed by the attacker's branch/commit. This value is then written into a temp file and diffed, and displayed to the user in the "old contents" side of the resolution diff (and used as `oldContents` for syntax highlighting per the `IResolutionDiff` return shape).

Unlike the write path (`_applyCopilotConflictResolutions`) and the Copilot-context builder (`buildConflictContext`), which both explicitly call `resolveWithin(repository.path, path)` and skip/`log.warn` on `null`, `getResolutionDiff` has no equivalent check, so the guard that stops this exact primitive elsewhere in the same feature does not apply here.

### Impact Explanation
Impact is a read of arbitrary files outside the repository root (e.g., other private repos on disk, SSH keys, config files) triggered purely by the user merging/rebasing/cherry-picking a hostile branch and opening the Copilot conflict-resolution dialog — no local access, admin rights, or unnatural user steps are required beyond the normal Desktop workflow of resolving conflicts. The exposed content is displayed directly in the diff view (and feeds into syntax highlighting), meaning secret material outside the repo can be leaked into the UI the user is looking at, and potentially into anything derived from that diff (e.g., copy/screenshot, or if the file happens to also match a resolution path that later gets staged). This satisfies the report's valid-impact bar: the attacker controls a cloned/fetched repository (the conflicting branch/commit with the symlink), and the result is a file read outside the repo through a broken invariant that other, sibling code paths in the same feature explicitly guard against.

### Likelihood Explanation
Likelihood is moderate-to-high for anyone using the Copilot conflict-resolution feature on non-Windows platforms (symlinks are followed on POSIX by default, as demonstrated by the project's own `resolveWithin` tests). The victim's ordinary workflow — merge/rebase/cherry-pick from an untrusted branch, hit a conflict, open the Copilot dialog — reaches this code without any special user action, since `getResolutionDiff` is called to preview every conflicted file's resolution.

### Recommendation
Route `filePath` in `getResolutionDiff` through the same `resolveWithin(repository.path, filePath)` guard used in `buildConflictContext` and `_applyCopilotConflictResolutions`, and refuse to read/diff the file (surfacing an error/skip state) when the resolved path is `null` or outside the repository root.

### Proof of Concept
Conceptual PoC (cannot be executed here, but follows directly from the code and the project's own symlink test):
1. Attacker prepares a branch where a file at some path (e.g., `notes.txt`) is committed as a **symlink** pointing to a sensitive absolute path outside the repo (e.g., `/home/victim/.ssh/id_rsa`), and modifies it so that merging it against the victim's branch produces a conflict on `notes.txt`.
2. Victim clones/fetches this branch and performs a merge/rebase/cherry-pick, hitting the conflict, and opens "Resolve with Copilot" (or the manual conflicts dialog that renders `getResolutionDiff`).
3. `getResolutionDiff(repository, 'notes.txt', ...)` executes `readFile(Path.join(repository.path, 'notes.txt'), 'utf8')`; because `notes.txt` is a symlink checked out into the working tree, this follows the symlink and reads `/home/victim/.ssh/id_rsa` instead of a repo-contained file.
4. The contents are shown to the user as the "old" side of the resolution diff — confirming out-of-repo file content was disclosed through a path that lacks the `resolveWithin` guard present in the analogous `buildConflictContext`/`_applyCopilotConflictResolutions` code paths (see `app/test/unit/path-test.ts:65-78` for the project's own demonstration that `resolveWithin` — but not a bare `Path.join`+`readFile` — blocks this exact symlink-traversal pattern).
