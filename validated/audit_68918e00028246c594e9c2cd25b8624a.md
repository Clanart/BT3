### Title
Empty aggregate signature bypasses verification after deserialization - ([File: crypto/schnorr/src/aggregate.rs](crypto/schnorr/src/aggregate.rs))

### Summary
`SchnorrAggregate::read` accepts a zero-length nonce list without enforcing the non-empty invariant enforced by `SchnorrAggregator::complete`. [1](#0-0) [2](#0-1) 

`SchnorrAggregate::verify` then accepts that deserialized object when supplied with an empty `keys_and_challenges` list and `s = 0`, because the only remaining verification term is `-0G`, which is the identity. [3](#0-2) 

### Finding Description
`SchnorrAggregator::complete` refuses to produce an aggregate when no signatures were aggregated, so a valid in-memory `SchnorrAggregate` must contain at least one nonce. [2](#0-1) 

The deserializer bypasses that state-transition validation: it trusts the encoded `u32` length, permits `0`, reads no `R` values, and then reads `s`. [1](#0-0) 

During verification, equality between `self.Rs.len()` and `keys_and_challenges.len()` succeeds for two empty lists. [4](#0-3) 

No per-signature equations are queued, and the verifier queues only `(-self.s, generator)`; with canonically encoded `s = 0`, the multiexp result is the identity and verification returns `true`. [5](#0-4) 

### Impact Explanation
An unprivileged party can provide public bytes that deserialize into a signature object which the normal aggregator cannot create and which verifies successfully for an empty statement set. [1](#0-0) [2](#0-1) 

This creates a forged aggregate Schnorr signature accepted by the verification API for zero public keys/challenges. [3](#0-2) 

The impact is bounded by whether a caller treats an empty aggregate authorization as meaningful, but the cryptographic invariant that a serialized aggregate represents at least one verified signature is broken. [6](#0-5) 

### Likelihood Explanation
The payload is constant-sized and does not require solving a discrete logarithm, predicting a challenge, or controlling private key material. [1](#0-0) 

Any public path that feeds attacker-controlled bytes to `SchnorrAggregate::read` and then calls `verify` with an empty `keys_and_challenges` list reaches the bypass deterministically. [3](#0-2) 

### Recommendation
Reject zero-length aggregates in `SchnorrAggregate::read`, matching `SchnorrAggregator::complete`. [1](#0-0) [7](#0-6) 

Defense in depth should also make `SchnorrAggregate::verify` return `false` when `self.Rs` or `keys_and_challenges` is empty, rather than relying on every constructor to enforce that invariant. [4](#0-3) 

### Proof of Concept
```rust
use ciphersuite::Ciphersuite;
use schnorr::SchnorrAggregate;

fn forged_empty_aggregate<C: Ciphersuite>() -> Vec<u8> {
    let mut bytes = Vec::new();

    // R count: zero.
    bytes.extend(0u32.to_le_bytes());

    // s = 0, canonically encoded.
    bytes.extend(C::F::ZERO.to_repr().as_ref());

    bytes
}

fn accepts_forged_aggregate<C: Ciphersuite>() {
    let encoded = forged_empty_aggregate::<C>();
    let aggregate = SchnorrAggregate::<C>::read(&mut encoded.as_slice()).unwrap();

    // Returns true even though no public key, nonce, message challenge, or
    // signature was supplied.
    assert!(aggregate.verify(b"example dst", &[]));
}
```

`SchnorrAggregate::read` consumes this object successfully because it only enforces scalar canonicity and does not reject `len = 0`. [1](#0-0) 

`verify` accepts it because the single queued statement is `(-0)G = identity`. [5](#0-4)

  /// Perform signature verification.
  ///
  /// Challenges must be properly crafted, which means being binding to the public key, nonce, and
  /// any message. Failure to do so will let a malicious adversary to forge signatures for
  /// different keys/messages.
  ///
  /// The DST used here must prevent a collision with whatever hash function produced the
  /// challenges.
  #[must_use]
  pub fn verify(&self, dst: &'static [u8], keys_and_challenges: &[(C::G, C::F)]) -> bool {
    if self.Rs.len() != keys_and_challenges.len() {
      return false;
    }

    let mut digest = DigestTranscript::<C::H>::new(dst);
    digest.domain_separate(b"signatures");
    for (_, challenge) in keys_and_challenges {
      digest.append_message(b"challenge", challenge.to_repr());
    }

    let mut pairs = Vec::with_capacity((2 * keys_and_challenges.len()) + 1);
    for (i, (key, challenge)) in keys_and_challenges.iter().enumerate() {
      let z = weight(&mut digest);
      pairs.push((z, self.Rs[i]));
      pairs.push((z * challenge, *key));
    }
    pairs.push((-self.s, C::generator()));
    multiexp_vartime(&pairs).is_identity().into()
  }
