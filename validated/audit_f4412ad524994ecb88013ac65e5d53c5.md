### Title
Gasless bundle block-building check (`VerifyExecutable`) never re-validates token balance/allowance, diverging from the stricter tx-pool admission check (`GetCheckBalance`) - (File: `kaiax/gasless/impl/tx_pool.go`, `kaiax/gasless/impl/getter.go`, `kaiax/gasless/impl/builder.go`)

### Summary
The gasless module enforces sender token-balance/allowance/swap-amount sufficiency only in `checkBalanceForApprove`/`checkBalanceForSwap` (invoked through `GetCheckBalance`) when a GaslessApproveTx/GaslessSwapTx is admitted or promoted in the tx pool [1](#0-0) . When a bundle is actually assembled for block building, `ExtractTxBundles` decides inclusion purely via `IsExecutable`/`VerifyExecutable`, which validates only structural conditions (sender match, token match, approve-amount ≥ swap amountIn, nonce sequencing, and repay-amount arithmetic) and performs **no** on-chain balance, allowance, or swap-amount re-check [2](#0-1) [3](#0-2) .

### Finding Description
This mirrors the Wise Lending bug class: two logically-equivalent "is this operation valid to proceed" checks compute sufficiency differently, and the weaker one is the one that actually gates the consequential state transition. In Wise Lending, `checksWithdraw` used the bare (unweighted) collateral value while `checksLiquidation` used the weighted value, letting withdrawals through that would fail the liquidation-equivalent check.

In the gasless module:
- The **admission/promotion-time** check (`GetCheckBalance` → `checkBalanceForApprove`/`checkBalanceForSwap`) is the strict one: it verifies `tokenBalance > 0`, `allowance >= amountIn`, `balance >= amountIn`, and `amountIn >= requiredAmountIn` from the DEX, gated behind `GaslessConfig.BalanceCheckLevel` (`ShouldCheckToken`, `ShouldCheckSwapAmount`) [4](#0-3) .
- The **block-building** check (`ExtractTxBundles` → `IsExecutable` → `VerifyExecutable`) is the one that actually decides whether the `[LendTxGenerator, ApproveTx, SwapTx]` bundle is placed into the block, and it only checks nonce/amount static relationships, never re-querying the sender's live token balance or allowance [5](#0-4) .

Because state can change between the time a GaslessSwapTx is admitted to the pool (when the strict balance check ran) and the time it is later selected and bundled for inclusion in a block, the sender's real token balance/allowance can have dropped below what is required for the swap to actually succeed (e.g., the user spent or revoked the token via an unrelated transaction, or is simply included from queued/re-broadcast state where the check is stale). The block-building path has no mechanism to catch this since `VerifyExecutable` deliberately omits the balance/allowance/DEX-amount checks that live in `checkBalanceForApprove`/`checkBalanceForSwap`.

### Impact Explanation
The `LendTxGenerator` transaction unconditionally fronts the gas fee for the user before the swap executes [6](#0-5) . If the accompanying GaslessSwapTx reverts on-chain because the sender's actual token balance/allowance is insufficient (a condition the block-assembly-time `VerifyExecutable` never checks), the proposer's lent gas fee is not repaid by the swap, since the repayment happens inside `swapForGas`, which the router would revert given insufficient balance/allowance. This is a direct fee-delegation abuse / gasless settlement theft vector against the block proposer: the proposer (or the protocol) unconditionally pays gas on the user's behalf based on a "readiness" check that no longer reflects the user's real token state at inclusion time. It also creates a path for accepting a fundamentally invalid gasless bundle into a block, since the invariant that "the block-building admission decision reflects actual executability" is broken, similarly to how Wise Lending's withdraw check allowed a fundamentally invalid withdrawal by using a weaker check than the corresponding liquidation check.

### Likelihood Explanation
This is reachable by any ordinary unprivileged public-RPC caller: a user can submit a valid GaslessApproveTx+GaslessSwapTx pair that passes the strict pool-admission balance check, then submit a second, unrelated transaction (or interact with the token contract off-band, e.g. another approve/transfer) that drains their balance or revokes the allowance before the swap is actually selected for a block. Since `ExtractTxBundles`/`VerifyExecutable` is the sole gate at block-assembly time and performs no live balance/allowance re-check, the bundle can still be selected and placed after the pool's earlier balance snapshot has gone stale, especially under `BalanceCheckLevelStatic` config or simply due to normal TOCTOU timing between pool checks and block building.

### Recommendation
Align the block-building admission check with the tx-pool admission check: either (a) have `ExtractTxBundles`/`IsExecutable`/`VerifyExecutable` re-verify current on-chain token balance, allowance, and DEX-derived amountIn sufficiency immediately before bundling (mirroring `checkBalanceForApprove`/`checkBalanceForSwap`), or (b) re-run `GetCheckBalance` against the state at the block-building point for every candidate gasless bundle before finalizing inclusion, so that the same sufficiency criteria gate both promotion and actual inclusion.

### Proof of Concept
1. Attacker (unprivileged EOA) submits `GaslessApproveTx` (nonce N) and `GaslessSwapTx` (nonce N+1) for token T, with balance/allowance of T currently sufficient; both pass `checkBalanceForApprove`/`checkBalanceForSwap` in `kaiax/gasless/impl/tx_pool.go` and are promoted to pending.
2. Before a block proposer picks these up, attacker sends another transaction (e.g., `transfer` of T to another address, or `approve(router, 0)`), draining balance/allowance below `amountIn` — this transaction is unrelated to the gasless flow and is processed normally.
3. When the proposer builds the next block, `GaslessModule.ExtractTxBundles` (`kaiax/gasless/impl/builder.go`) calls `IsExecutable`/`VerifyExecutable` (`kaiax/gasless/impl/getter.go:203-266`), which only checks nonce ordering, approve-amount vs. amountIn, and repay-amount arithmetic — none of which detect the drained balance/allowance.
4. The bundle `[LendTxGenerator, ApproveTx, SwapTx]` is included; `LendTxGenerator` pays gas on behalf of the sender, but `SwapTx`'s on-chain `swapForGas` call reverts due to insufficient balance/allowance, so the router never repays the lent amount to the proposer.

Note: I could not fully verify from the indexed code whether `builder.Bundle`'s atomicity flag (the `false` argument passed to `builder.NewBundle` in `ExtractTxBundles`) would cause the whole bundle (including the `LendTxGenerator` tx) to be rolled back together with the failed swap, which would mitigate or eliminate the proposer's loss. This detail lives in `work/builder/bundle.go`, whose full semantics I was unable to inspect within the available tool calls. If bundle atomicity does force all-or-nothing inclusion of the three transactions in the same block execution such that a revert in the swap prevents the lend transaction's effect from persisting, the fee-loss impact described above would not materialize, though the underlying design inconsistency (two divergent sufficiency checks for the same gasless-executability question) would still stand as a code-quality/defense-in-depth gap. A Devin session with full repository access could confirm this by reading `work/builder/bundle.go` and the block execution/finalization logic that consumes bundles.

func (g *GaslessModule) GetCheckBalance() func(tx *types.Transaction) error {
	return func(tx *types.Transaction) error {
		if approveArgs, ok := decodeApproveTx(tx, g.signer); ok {
			return g.checkBalanceForApprove(approveArgs)
		}
		if swapArgs, ok := decodeSwapTx(tx, g.signer); ok {
			return g.checkBalanceForSwap(swapArgs, tx.Nonce())
		}
		return errors.New("not a gasless transaction") // should not happen because IsModuleTx is called before GetCheckBalance
	}
}

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {

		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// If SwapTx.nonce is the sender's next nonce, then there is no room for ApproveTx proceeding SwapTx.
		senderNonce := g.getCurrentStateNonce(swapArgs.Sender)
		noApproveTxPreceeds := swapNonce == senderNonce
		if noApproveTxPreceeds {
			// tx.token.allowance(sender, router) >= tx.amountIn
			approval, err := tokenContract.Allowance(nil, swapArgs.Sender, swapRouter)
			if err != nil {
				return err
			}
			if approval.Cmp(swapArgs.AmountIn) < 0 {
				return fmt.Errorf("insufficient approval: approval=%s, want=%s", approval.String(), swapArgs.AmountIn.String())
			}
		}

		// tx.token.balanceOf(sender) >= tx.amountIn
		balance, err := tokenContract.BalanceOf(nil, swapArgs.Sender)
		if err != nil {
			return err
		}
		if balance.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("insufficient balance: balance=%s, want=%s", balance.String(), swapArgs.AmountIn.String())
		}
	}

	// tx.deadline >= currentTimestamp
	deadline := swapArgs.Deadline
	if deadline.Cmp(g.Chain.CurrentBlock().Time()) < 0 {
		return fmt.Errorf("insufficient deadline: deadline=%s, want=%s", deadline.String(), g.Chain.CurrentBlock().Time().String())
	}

	return nil
}

func (g *GaslessModule) IsExecutable(approveTxOrNil, swapTx *types.Transaction) bool {
	err := g.VerifyExecutable(approveTxOrNil, swapTx)
	if err != nil {
		return false
	}
	return true
}

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}
