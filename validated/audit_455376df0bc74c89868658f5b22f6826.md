### Title
Out-of-bounds read in `is_atom_canonical()` via unterminated CLVM atom length prefix in mempool canonical-serialization check - (File: chia/full_node/mempool_manager.py)

### Summary
`is_clvm_canonical()` and its helper `is_atom_canonical()` in `chia/full_node/mempool_manager.py` parse the atom length-prefix of a submitted spend bundle's puzzle reveal and solution without validating that enough bytes remain in the buffer to hold the declared prefix. This mirrors the `fast-string-search` bug class: an incorrect/unchecked length calculation drives a read past the end of the caller-controlled buffer.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` [1](#0-0)  decodes a variable-length (0–5 extra byte) prefix from `clvm_buffer[offset]` and then loops `prefix_len` times indexing `clvm_buffer[offset]` again without ever checking `offset < len(clvm_buffer)`:

```
atom_len = b & mask
for i in range(prefix_len):
    atom_len <<= 8
    offset += 1
    atom_len |= clvm_buffer[offset]
```

This function is called from `is_clvm_canonical()` [2](#0-1) , which itself is invoked directly on attacker-supplied bytes during mempool admission in `MempoolManager.validate_spend_bundle()`:

```
if not is_clvm_canonical(bytes(coin_spend.puzzle_reveal)) or not is_clvm_canonical(
    bytes(coin_spend.solution)
):
    return Err.INVALID_COIN_SOLUTION, None, []
``` [3](#0-2) 

Any unprivileged party can submit a spend bundle whose puzzle reveal or solution ends with a byte such as `0xFC` (declaring a 5-byte extra length prefix, i.e. `prefix_len = 5`) but supplies fewer than 5 trailing bytes. `is_atom_canonical()` then indexes past the end of the `bytes` object.

### Impact Explanation
In CPython, indexing a `bytes` object past its end raises `IndexError` rather than returning stale heap memory, so this does not directly leak process memory the way the C `fast-string-search` bug does (the underlying language is memory-safe here). The closest concretely provable consequence is a spend-triggered exception: if this `IndexError` is not caught anywhere along `validate_spend_bundle()`'s call chain, an unprivileged submitter could trigger an unhandled exception during mempool admission processing, which is the "spend-triggered transaction-processing halt" impact category. I was not able to fully trace, within available context, whether `add_spend_bundle()`/`validate_spend_bundle()`'s caller wraps this specific code path in a broad `try/except`, so I cannot confirm whether the exception actually escapes uncaught and crashes/hangs mempool processing, or is silently absorbed and merely returns a spurious rejection.

### Likelihood Explanation
Reaching this code only requires submitting a normal spend bundle whose puzzle reveal or solution atom uses a non-canonical/oversized length-prefix byte with a truncated trailing length field — trivial to construct and requires no signature validation success, no special coin, and no privileged access.

### Recommendation
Add an explicit bounds check in `is_atom_canonical()` before entering the prefix-reading loop (verify `offset + prefix_len < len(clvm_buffer)`), returning/raising a controlled validation error instead of relying on implicit `IndexError` propagation. Confirm (and add regression tests for) that any exception raised here is caught and mapped to `Err.INVALID_COIN_SOLUTION` rather than propagating as an unhandled exception through the mempool admission pipeline.

### Proof of Concept
Submit a `CoinSpend` whose `solution` (or `puzzle_reveal`) SerializedProgram bytes end with a truncated atom header, e.g. bytes `b"\xfc"` alone (declares `prefix_len = 5`, needs 5 more bytes, buffer supplies zero) as the tail of an otherwise well-formed CLVM list so that `is_clvm_canonical()` reaches `is_atom_canonical(buffer, offset)` at that trailing byte:
```
clvm_buffer = b"\xff\x80\xfc"   # e.g. (nil . <truncated-atom>)
is_clvm_canonical(clvm_buffer)  # -> IndexError inside is_atom_canonical
```
This is called from `validate_spend_bundle()` on every submitted coin spend's puzzle reveal/solution [3](#0-2) , making it reachable by any unprivileged spend-bundle submitter to the mempool.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
