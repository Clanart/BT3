### Title
Governing node can vote `reward.proposerupdateinterval` (and `reward.stakingupdateinterval`) to `0`, causing a modulo-by-zero panic in proposer/staking interval calculations - (File: `kaiax/valset/impl/getter_proposers.go`, `kaiax/gov/param.go`, `kaiax/gov/headergov/impl/header.go`)

### Summary
The `reward.proposerupdateinterval` and `reward.stakingupdateinterval` governance parameters are registered with a `noopFormatChecker`, meaning any `uint64` value, including `0`, is accepted as a valid vote value. The consistency check performed on votes before ratification (`checkConsistency`) does not add any special-case validation for these two parameters, so a vote of `0` will be ratified like any other value. These intervals are later used as the divisor/modulus in `roundDown`, which computes `n - (n % p)`. A `0` divisor causes an integer division/modulo-by-zero panic in Go.

### Finding Description
`RewardProposerUpdateInterval` and `RewardStakingUpdateInterval` are defined in `kaiax/gov/param.go` with `FormatChecker: noopFormatChecker`, unlike other numeric params such as `IstanbulCommitteeSize` which explicitly require `v > 0`. [1](#0-0) [2](#0-1) 

`noopFormatChecker` unconditionally returns `true` for any candidate value: [3](#0-2) 

Governance votes are validated through `checkConsistency`, which only special-cases `GovernanceGoverningNode`, `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee`, and `AddValidator`/`RemoveValidator`. Both `RewardProposerUpdateInterval` and `RewardStakingUpdateInterval` fall into the catch-all case that simply returns `nil` (accepted) with no bound checking: [4](#0-3) 

Once ratified (a single vote from the governing node in `single` mode is sufficient, per `VerifyVote`), the value becomes part of the effective `ParamSet` from the next epoch onward: [5](#0-4) 

The proposer-list computation directly uses `ProposerUpdateInterval` as a modulus via `roundDown`: [6](#0-5) 

Per the module's own documentation, `roundDown(n, p) = n - (n % p)`, so `p = 0` triggers a runtime panic (integer division/modulo by zero) in Go: [7](#0-6) 

Note: `kaiax/staking/impl/init.go` guards against a zero `StakingUpdateInterval` only at genesis/Init time (`ErrZeroStakingInterval`), reading from `ChainConfig`, not from the live, governance-updatable `ParamSet`: [8](#0-7) 
This means the genesis-time safety check does not protect against a subsequent governance vote setting the parameter to `0` at runtime.

### Impact Explanation
If the interval parameter is ratified to `0`, every node computing `getProposerList` (called during block processing/consensus for proposer selection) will hit a modulo-by-zero panic in `roundDown`. Because this code path runs identically on every full node/validator during block execution, this is not a single-node fault but a chain-wide liveness failure: all nodes processing blocks past the effective epoch would panic/crash simultaneously, halting the chain. This matches the "state divergence between honest nodes / acceptance of invalid transaction or block" class of impact expected by the validation rules, manifesting instead as a total consensus/liveness failure triggered by an on-chain governance vote.

### Likelihood Explanation
Requires the governing node (in `single` governance mode, which Mainnet/Kairos use) to cast one vote for `reward.proposerupdateinterval` (or `reward.stakingupdateinterval`) with value `0`. The vote passes `NewVoteData` format checks (since `noopFormatChecker` accepts any `uint64`) and passes `checkConsistency` (since these parameters aren't specifically validated). Only a single ratified vote is needed, and no other consistency layer (e.g., `ParamSet.Set`) rejects zero values.

### Recommendation
Add an explicit `FormatChecker` (analogous to the one used for `IstanbulCommitteeSize`) for `RewardProposerUpdateInterval` and `RewardStakingUpdateInterval` requiring `v > 0`, and/or add explicit zero-value rejection cases in `checkConsistency` in `kaiax/gov/headergov/impl/header.go`, mirroring the pattern already used for `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee`.

### Proof of Concept
1. Governing node calls the `governance_vote` API with `{name: "reward.proposerupdateinterval", value: 0}`.
2. The vote passes `NewVoteData` (format checker is a no-op) and `checkConsistency` (falls into the default-accept case).
3. At the next epoch boundary the vote is ratified into `header.Governance`, becoming effective the following epoch (`kaiax/gov/headergov/README.md` describes the ratification/effect timeline).
4. Starting from the effective block, any node processing a block calls `getProposerList`, which executes `roundDown(c.num-1, uint64(c.pset.ProposerUpdateInterval))` with `ProposerUpdateInterval == 0`, causing a modulo-by-zero panic on every node, halting block production/verification chain-wide.

func (h *headerGovModule) VerifyVote(header *types.Header) error {
	if len(header.Vote) == 0 {
		return nil
	}

	var (
		vb       headergov.VoteBytes = header.Vote
		blockNum                     = header.Number.Uint64()
	)

	vote, err := vb.ToVoteData()
	if err != nil {
		logger.Error("ToVoteData error", "num", blockNum, "vote", vb, "err", err)
		return err
	}

	if gov.DeprecatedAt(vote.Name(), h.ChainConfig.Rules(header.Number)) {
		logger.Error("Vote is deprecated", "num", blockNum, "name", vote.Name())
		return ErrDeprecatedVote
	}

	council, err := h.ValSet.GetCouncil(blockNum)
	if err != nil {
		return err
	}

	// check if the voter is in council
	if !slices.Contains(council, vote.Voter()) {
		return ErrInvalidKeyValue
	}

	// check if Voter is the block proposer.
	author, err := h.Chain.Sealer().Author(header)
	if err != nil {
		return err
	}
	if author != vote.Voter() {
		return ErrInvalidVoter
	}

	// In single mode, only the governing node can write header.Vote after Permissionless.
	params := h.GetParamSet(blockNum)
	if h.ChainConfig.IsPermissionlessForkEnabled(new(big.Int).SetUint64(blockNum)) &&
		params.GovernanceMode == "single" &&
		vote.Voter() != params.GoverningNode {
		return ErrVotePermissionDenied
	}

	return h.checkConsistency(blockNum, vote)
}

func (s *StakingModule) Init(opts *InitOpts) error {
	if opts == nil || opts.ChainConfig == nil || opts.Chain == nil || opts.ChainKv == nil {
		return staking.ErrInitUnexpectedNil
	}
	s.InitOpts = *opts

	if s.ChainConfig.Governance == nil || s.ChainConfig.Governance.Reward == nil {
		return staking.ErrInitUnexpectedNil
	}
	if s.ChainConfig.Governance.Reward.StakingUpdateInterval == 0 {
		return staking.ErrZeroStakingInterval
	}
	s.stakingInterval = s.ChainConfig.Governance.Reward.StakingUpdateInterval
	s.useGiniCoeff = s.ChainConfig.Governance.Reward.UseGiniCoeff
	s.minimumStake = s.ChainConfig.Governance.Reward.MinimumStake

	return nil
}
