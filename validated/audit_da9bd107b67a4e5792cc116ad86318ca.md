### Title
Instant bribe reward sniping via permissionless vote→castVotes→claimBribe sequence with no staking-duration checkpoint - ([File: wombat/WombatBribeManager.sol], [File: rewards/BribeRewardPool.sol])

### Summary
`WombatBribeManager.vote`, `castVotes`, and `claimBribe` (and the atomic helper `voteAndCast`) have no cooldown or minimum holding-period requirement, and the underlying `BribeRewardPool` uses a lump-sum `rewardPerTokenStored` accumulator that is updated once per `queueNewRewards` call based on the pool's *current* `totalStaked()`. An attacker who already holds locked vlMGP can free up capacity with `unvote(oldPool)` and redirect it with `vote(newPool, +delta)` in the same transaction/block as `castVotes()`, then immediately `claimBribe()`, capturing a share of a just-harvested Wombat bribe proportional to their newly added stake despite zero elapsed voting time. This dilutes the share that would otherwise accrue to voters who held their position for the full accrual period.

### Finding Description
`unvote` itself performs no invalid check-skip — it correctly zeroes `userVotedForPoolInVlmgp` and decrements `totalVoteInVlmgp`/`userTotalVotedInVlmgp` [1](#0-0) . The real issue is that none of `vote`, `unvote`, `castVotes`, or `claimBribe` impose any per-block/epoch cooldown or minimum stake duration [2](#0-1) [3](#0-2) .

`castVotes()` is fully permissionless and, via `wombatStaking.vote(...)`, harvests real pending Wombat bribes and pushes them into `IBaseRewardPool(_rewarder).queueNewRewards(...)` [4](#0-3) . `queueNewRewards` immediately bumps `rewardPerTokenStored` using the pool's `totalStaked()` **at that instant**: `rewardPerTokenStored += _amountReward * 10**decimals / totalStaked()` [5](#0-4) . Because `_earned` computes reward as `userShare * (rewardPerToken - userRewardPerTokenPaid)` with no time-weighting of the user's balance [6](#0-5) , any stake added to `totalStaked()` immediately before this bump earns a full proportional share of the harvested reward, regardless of how briefly it was held.

Exploit flow: an attacker holding locked vlMGP calls `unvote(oldPool)` to free their allocation [1](#0-0) , then `vote(newPool, +delta)` to redirect the freed (or newly available) vlMGP into a pool with a large pending, not-yet-harvested Wombat bribe — this calls `IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, delta)`, increasing `totalStaked()` for that rewarder immediately [7](#0-6) . The attacker (or anyone) then calls `castVotes()` (or does it atomically via `voteAndCast`) [8](#0-7) , which harvests the accumulated real bribe and stamps `rewardPerTokenStored` using the now-inflated `totalStaked()` that includes the attacker's fresh stake. Finally `claimBribe(newPool)` pays out the attacker's proportional share instantly [9](#0-8) [10](#0-9) .

No existing modifier, `nonReentrant`, or checkpoint prevents this: `stakeFor`/`withdrawFor` only gate on `onlyOperator` (i.e., must be called via the bribe manager) and update rewards *before* changing balances, so the newly added balance is fully counted in the very next reward-queueing event [11](#0-10) .

### Impact Explanation
This dilutes and effectively redirects a portion of previously-accrued-but-unclaimed bribe rewards from long-standing voters of a pool to a last-second entrant, matching the Immunefi "theft of unclaimed yield" impact class. The magnitude is bounded by the size of the pending bribe at harvest time and the fraction of `totalStaked()` the attacker can command relative to genuine long-term voters — for a pool with a large pending bribe and modest existing vote share, the diverted amount can be substantial.

### Likelihood Explanation
Preconditions are low: the attacker only needs vlMGP already locked (no flash-loan of the lock itself is required or claimed) and must correctly identify a pool with a large unharvested Wombat bribe relative to its current `totalVoteInVlmgp`. Since `vote`, `unvote`, `castVotes`, `voteAndCast`, and `claimBribe` are all public/external with no cooldown, the full sequence is trivially repeatable every time a sizeable bribe accumulates, and callable atomically in one transaction via `voteAndCast` followed by `claimBribe`.

### Recommendation
Introduce a minimum holding/checkpoint period before newly added stake becomes eligible for a currently pending (not-yet-queued) reward distribution — e.g., checkpoint `rewardPerToken` for a user's *pre-existing* balance only, or require that `stakeFor` additions do not participate in reward shares until after the next `queueNewRewards` call following their deposit (a common "snapshot before top-up" or explicit vesting/cooldown pattern). Alternatively, restrict `castVotes()`/harvesting cadence to fixed epochs and require `vote` changes to be locked-in before the epoch's harvest, similar to a voting-then-harvest checkpoint pattern.

### Proof of Concept
Foundry test plan:
1. Deploy `WombatBribeManager`, `WombatStaking`, and `BribeRewardPool` (or forked mainnet/BSC state) with two active pools A (attacker's target, large pending real Wombat bribe accrued over time via honest voter B) and B (attacker's initial vote).
2. Voter B locks vlMGP and calls `vote([A], [+1000e18])` long before the test's main block, then time-warps forward to accrue a large pending Wombat bribe on pool A (do not call `castVotes` yet).
3. Attacker locks vlMGP and calls `vote([B], [+1000e18])` in an earlier block (establishing a baseline stake elsewhere), asserting no reward is owed yet.
4. In a single block/transaction: attacker calls `unvote(B)`, then `vote([A], [+1000e18])`, then `castVotes(false)`.
5. Attacker calls `claimBribe([A])` and asserts `earned`/received reward > 0 and is proportional to `attackerVote / (attackerVote + voterBVote)` of the harvested bribe amount, despite attacker's stake existing for 0 elapsed time versus voter B's long holding period.
6. Assert voter B's `claimBribe([A])` yields less than the full harvested bribe amount they would have received absent the attacker's last-second entry, quantifying the diverted/stolen yield.

    function vote(address[] calldata _lps, int256[] calldata _deltas) override public {
        if (_lps.length != _deltas.length)
            revert LengthMismatch();

        uint256 length = _lps.length;
        int256 totalUserVote;

        for (uint256 i; i < length; i++) {
            Pool storage pool = poolInfos[_lps[i]];
            if (!pool.isActive)
                revert PoolNotActive();
            int256 delta = _deltas[i];
            totalUserVote += delta;
            if (delta != 0) {
                if (delta > 0) {
                    pool.totalVoteInVlmgp += uint256(delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] += uint256(delta);
                    IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, uint256(delta));
                } else {
                    pool.totalVoteInVlmgp -= uint256(-delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] -= uint256(-delta);
                    IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(-delta), false);
                }
            }
        }

        if (msg.sender != delegatedPool) {
            if (totalUserVote > 0) {
                userTotalVotedInVlmgp[msg.sender] += uint256(totalUserVote);
                totalVlMgpInVote += uint256(totalUserVote);
            } else {
                userTotalVotedInVlmgp[msg.sender] -= uint256(-totalUserVote);
                totalVlMgpInVote -= uint256(-totalUserVote);
            }
        }

        if (userTotalVotedInVlmgp[msg.sender] > getUserVotable(msg.sender))
            revert NotEnoughVote();
    }

    function unvote(address _lp) public {
