### Title
Malicious user can craft a syntactically-valid but execution-reverting GaslessApprove/GaslessSwap pair, forcing the block proposer to lose the lent gas fee - (File: kaiax/gasless/impl/getter.go)

### Summary
`GaslessModule.VerifyExecutable` (called from `IsExecutable`) only performs **static/syntactic** validation of a `GaslessApproveTx`/`GaslessSwapTx` pair before the block proposer commits to lending KAIA to the sender. It never simulates whether the underlying ERC20 transfer/swap will actually succeed on-chain. Because the `LendTx` (which unconditionally transfers `lendAmount()` KAIA to the sender) is prepended and executed *before* the swap logic runs, a malicious sender can guarantee the swap reverts (e.g. insufficient token balance, price/slippage condition, or an already-consumed allowance) while still passing all of `VerifyExecutable`'s checks, causing the proposer's lent KAIA (and the associated gas cost) not to be repaid. [1](#0-0) 

### Finding Description
`ExtractTxBundles` builds the gasless bundle `[LendTx, ApproveTx?, SwapTx]` whenever `IsExecutable(approveTxOrNil, swapTx)` returns true: [2](#0-1) 

`IsExecutable`/`VerifyExecutable` only checks: correct function selectors/whitelisted token & router, sender consistency between approve/swap, approve amount ≥ swap amountIn, sequential nonces matching current state nonce, and that `amountRepay` matches the formula `repayAmount()`. It never calls into the EVM to check the sender's actual ERC20 balance, pool liquidity/slippage feasibility, or deadline validity: [3](#0-2) 

`GetLendTxGenerator` unconditionally creates and signs a `LendTx` from the node's/proposer's key that sends `lendAmount(approveTxOrNil, swapTx)` (== R2+R3, the approve+swap gas fees) directly to the swap sender's address, with no dependency on whether the subsequent swap actually succeeds: [4](#0-3) 

The repayment mechanism (transferring `amountRepay` = R1+R2+R3 back to the proposer, per the `SwappedForGas` event `AmountRepaid`) is implemented **inside** the `swapForGas` contract call itself: [5](#0-4) 

If that call reverts — for reasons the pre-block-building `VerifyExecutable` check does not verify (e.g. "insufficient balance", "insufficient approval: approval=0", "insufficient minAmountOut", "insufficient amountIn" — all conditions the test suite shows are enforced only at execution time inside the router, not by `VerifyExecutable`) — the on-chain repayment logic never executes, yet the `LendTx` that already paid out the KAIA to the sender is a separate, already-included transaction and is not reverted: [6](#0-5) [7](#0-6) 

This is directly analogous to the referenced GMX finding: a malicious/unprivileged user (the gasless tx sender) can construct an "order"/tx that is superficially well-formed and accepted by the pre-check (`VerifyExecutable`, analogous to `_handleOrderError`'s dispatch), but which is guaranteed or likely to fail at actual execution time (analogous to `UnsupportedOrderType`), and the party fronting resources — here the block proposer lending the gas fee, rather than a keeper paying gas — bears the loss because the pre-check does not simulate real execution outcomes.

### Impact Explanation
Every time a malicious user submits such a doomed approve+swap pair, the proposer's `LendTx` still executes and transfers real KAIA (R2+R3, potentially hundreds of thousands of gas-equivalent value) to the attacker's account before the swap fails and forfeits repayment. Since `VerifyExecutable`'s checks are all static and can be satisfied deterministically by the attacker (e.g., start with 0 token balance/approval, or manipulate their own balance to fall below `amountIn` right before block inclusion), the attack is repeatable across blocks, draining the proposer's `NodeKey`-controlled funds used for `LendTxGenerator`. This is a direct, repeatable unauthorized value transfer from the block proposer to an attacker-controlled account — a concrete instance of "fee-delegation/gasless settlement theft," within the "Medium/High" severity band required.

### Likelihood Explanation
Likelihood is high: the conditions that make the swap fail (insufficient token balance, insufficient allowance timing, slippage/minAmountOut manipulation, or deadline just past) are entirely within the attacker's control and are not checked by `VerifyExecutable` prior to bundling. No special privilege, node access, or consensus-level control is required — a normal gasless-tx sender using the public RPC/tx pool can trigger it as long as the tx pool's own `Ready`/`IsExecutable` promotion logic and block-building `ExtractTxBundles` accept the pair, which per the code only checks the same static conditions.

### Recommendation
Before generating and including the `LendTxGenerator` transaction, the `GaslessModule` should simulate (e.g. via `eth_call`/state simulation) the full `[ApproveTx, SwapTx]` execution against the current pending state to confirm it would actually succeed (sufficient token balance, deadline not expired, minAmountOut/amountIn feasible against current pool reserves) rather than relying solely on the static checks in `VerifyExecutable`. Alternatively, restructure the flow so that the lend and repay happen atomically within a single transaction/bundle that reverts together (e.g., have the `LendTx` and repayment enforced by the same top-level call, or refund/claw back the lend if the swap tx reverts), so the proposer cannot lose the lent principal to a guaranteed-to-fail swap.

### Proof of Concept
1. Attacker account has 0 test-token balance and 0 approval to `GaslessSwapRouter`.
2. Attacker crafts and submits an `ApproveTx` (approve MaxUint256 to router) and a `SwapTx` (`swapForGas(token, amountIn, minAmountOut, amountRepay=repayAmount(...), deadline)`), both satisfying every static check in `VerifyExecutable` (correct selectors, whitelisted token/router, matching nonces, correct `amountRepay` formula).
3. The txpool/`ExtractTxBundles` accepts the pair as gasless (`IsExecutable` returns true) and the block proposer prepends a `LendTx` sending `lendAmount()` KAIA to the attacker's address, as shown in `GetLendTxGenerator`.
4. Block is built: `LendTx` succeeds, funding the attacker's account. `ApproveTx` succeeds. `SwapTx` reverts on-chain with e.g. `"insufficient balance"` (as reproduced in `tests/gasless_test.go` lines 255-258), so the router's internal repay-to-proposer logic never runs.
5. The attacker keeps the difference between what the `LendTx` paid out and what was actually consumed by their own txs' gas, while the proposer never receives the `amountRepay` that was supposed to reimburse the lent principal — repeatable every block the attacker can get such a pair bundled.

	err := g.VerifyExecutable(approveTxOrNil, swapTx)
	if err != nil {
		return false
	}
	return true

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}

// MakeLendTx creates a transaction with following properties:
// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)
// L2. LendTx.from = proposer
// L3. LendTx.to = SwapTx.from
// L4. LendTx.value = LendAmount(approveTxOrNil, swapTx)
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}
