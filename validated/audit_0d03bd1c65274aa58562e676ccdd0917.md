### Title
Validator voting-power concentration cap (`MaxVotingPowerRatio`) is enforced only on `Delegate`, not on `Undelegate`/`Unbond`, `RemoveValidatorTokensAndShares`, or slashing, allowing the cap to be silently bypassed - ([File: sei-cosmos/x/staking/keeper/delegation.go])

### Summary
`Keeper.Delegate` enforces a hard cap (`MaxVotingPowerRatio`) on the fraction of total voting power any single validator may hold, but this check exists only in the "add power" path. Any operation that reduces `lastTotalPower` (e.g., a different delegator calling `Undelegate`/`MsgBeginRedelegate` away from other validators, or a slash reducing another validator's tokens) can push an already near-cap validator's *ratio* of total power above `MaxVotingPowerRatio` with no invariant check on that path, exactly mirroring the reported float-liquidity bug pattern (limit enforced on `addFloat` but not on `remove`).

### Finding Description
`Keeper.Delegate` computes `newVotingPowerRatio = validatorNewTotalPower / newTotalPower` and rejects the delegation with `ErrExceedMaxVotingPowerRatio` if it exceeds `MaxVotingPowerRatio`: [1](#0-0) 

This is the only place in the staking keeper where `MaxVotingPowerRatio`/`ErrExceedMaxVotingPowerRatio` is referenced, confirmed by the fact that `ErrExceedMaxVotingPowerRatio` occurs only in `delegation.go` and its test file, with no matches in `Unbond`, `Undelegate`, `RemoveValidatorTokensAndShares`, or the slashing keeper.

`Keeper.Unbond` (invoked by `Undelegate` and by the redelegation flow) reduces a validator's `DelegatorShares`/`Tokens` and, transitively, `lastTotalPower` in the next `EndBlocker` power update, but performs no ratio re-check at all: [2](#0-1) 

`RemoveValidatorTokensAndShares`, called from `Unbond`, likewise has no invariant enforcement: [3](#0-2) 

Because `lastTotalPower` is the denominator of the ratio check and it only decreases when *other* validators lose stake (via `MsgUndelegate`, `MsgBeginRedelegate` away from them, or slashing), any unprivileged delegator can, at any time, submit `MsgUndelegate`/`MsgBeginRedelegate` against validators other than the one already sitting at/near the `MaxVotingPowerRatio` cap. This reduces `lastTotalPower` and can push the already-capped validator's share of total power above `MaxVotingPowerRatio`, without triggering any check — since the check only runs inside `Delegate`.

### Impact Explanation
`MaxVotingPowerRatio` exists specifically to bound the fraction of consensus voting power any single validator can hold, which is a chain-safety control against excessive stake concentration in one validator (censorship risk, outsized influence on block production/liveness if that validator misbehaves or goes offline). Because the invariant is only checked on the increase path and never re-validated or corrected when total power shrinks due to unrelated, unprivileged `MsgUndelegate`/`MsgBeginRedelegate` transactions from other delegators, the protocol-level power-concentration guarantee can silently be violated by ordinary user transactions, without any of the affected validator's own actions. This undermines a security invariant the chain explicitly enforces elsewhere, and if operators/tooling rely on `MaxVotingPowerRatio` never being exceeded (e.g., for network resilience assumptions), the guarantee can be broken as a side effect of routine, permissionless staking operations.

### Likelihood Explanation
Likelihood is moderate-to-high: any account holding delegations, or willing to delegate then undelegate, can trigger the condition once a validator's power is already near the enforcement threshold (`MaxVotingPowerEnforcementThreshold`) and cap. No special privilege, precompile access, or validator collusion is required — a plain `MsgUndelegate`/`MsgBeginRedelegate` from any account against any validator (not necessarily the one near the cap) is sufficient to shrink `lastTotalPower` and push another validator over the ratio limit.

### Recommendation
Apply the same `MaxVotingPowerRatio` check (or an equivalent invariant re-validation) inside `Unbond`/`Undelegate`/`RemoveValidatorTokensAndShares` and in the slashing path whenever `lastTotalPower` or a validator's token balance changes, similar to how the report's "Version 2" fix introduced a centralized `checkUtilization()` invariant check on every state-changing operation (add, remove, pay) rather than only on the "add" path. At minimum, recompute and log/alert on ratio violations at `EndBlock` power-update time so the invariant cannot silently be violated by unrelated delegator actions.

### Proof of Concept
1. Configure `MaxVotingPowerEnforcementThreshold` low enough to be active, and `MaxVotingPowerRatio` at some limit (e.g., 33%).
2. Validator A accumulates delegations up to just under the ratio cap relative to `lastTotalPower` via normal `MsgDelegate` calls, each individually passing the check in `Delegate`. [1](#0-0) 
3. Any other delegator (unrelated to Validator A) submits `MsgUndelegate` (or `MsgBeginRedelegate`) reducing stake on Validator B/C, which lowers `lastTotalPower` on the next power update. [4](#0-3) 
4. Validator A's tokens are unchanged, but `validatorNewTotalPower / newTotalPower` now exceeds `MaxVotingPowerRatio` — yet no error is raised anywhere in the `Unbond`/`RemoveValidatorTokensAndShares` path. [2](#0-1) [3](#0-2) 
5. Validator A now holds voting power above the configured safety cap, with the invariant only re-checked (and only blocking further increases) the next time someone tries to `Delegate` to Validator A.

func (k Keeper) Unbond(
	ctx sdk.Context, delAddr sdk.AccAddress, valAddr sdk.ValAddress, shares sdk.Dec,
) (amount sdk.Int, err error) {
	// check if a delegation object exists in the store
	delegation, found := k.GetDelegation(ctx, delAddr, valAddr)
	if !found {
		return amount, types.ErrNoDelegatorForAddress
	}

	// call the before-delegation-modified hook
	k.BeforeDelegationSharesModified(ctx, delAddr, valAddr)

	// ensure that we have enough shares to remove
	if delegation.Shares.LT(shares) {
		return amount, sdkerrors.Wrap(types.ErrNotEnoughDelegationShares, delegation.Shares.String())
	}

	// get validator
	validator, found := k.GetValidator(ctx, valAddr)
	if !found {
		return amount, types.ErrNoValidatorFound
	}

	// subtract shares from delegation
	delegation.Shares = delegation.Shares.Sub(shares)

	delegatorAddress, err := sdk.AccAddressFromBech32(delegation.DelegatorAddress)
	if err != nil {
		return amount, err
	}

	isValidatorOperator := delegatorAddress.Equals(validator.GetOperator())

	// If the delegation is the operator of the validator and undelegating will decrease the validator's
	// self-delegation below their minimum, we jail the validator.
	if isValidatorOperator && !validator.Jailed &&
		validator.TokensFromShares(delegation.Shares).TruncateInt().LT(validator.MinSelfDelegation) {
		k.jailValidator(ctx, validator)
		validator = k.mustGetValidator(ctx, validator.GetOperator())
	}

	// remove the delegation
	if delegation.Shares.IsZero() {
		k.RemoveDelegation(ctx, delegation)
	} else {
		k.SetDelegation(ctx, delegation)
		// call the after delegation modification hook
		k.AfterDelegationModified(ctx, delegatorAddress, delegation.GetValidatorAddr())
	}

	// remove the shares and coins from the validator
	// NOTE that the amount is later (in keeper.Delegation) moved between staking module pools
	validator, amount = k.RemoveValidatorTokensAndShares(ctx, validator, shares)

	if validator.DelegatorShares.IsZero() && validator.IsUnbonded() {
		// if not unbonded, we must instead remove validator in EndBlocker once it finishes its unbonding period
		k.RemoveValidator(ctx, validator.GetOperator())
	}

	return amount, nil
}

// Undelegate unbonds an amount of delegator shares from a given validator. It
// will verify that the unbonding entries between the delegator and validator
// are not exceeded and unbond the staked tokens (based on shares) by creating
// an unbonding object and inserting it into the unbonding queue which will be
// processed during the staking EndBlocker.
func (k Keeper) Undelegate(
	ctx sdk.Context, delAddr sdk.AccAddress, valAddr sdk.ValAddress, sharesAmount sdk.Dec,
) (time.Time, error) {
	validator, found := k.GetValidator(ctx, valAddr)
	if !found {
		return time.Time{}, types.ErrNoDelegatorForAddress
	}

	if k.HasMaxUnbondingDelegationEntries(ctx, delAddr, valAddr) {
		return time.Time{}, types.ErrMaxUnbondingDelegationEntries
	}

	returnAmount, err := k.Unbond(ctx, delAddr, valAddr, sharesAmount)
	if err != nil {
		return time.Time{}, err
	}

	// transfer the validator tokens to the not bonded pool
	if validator.IsBonded() {
		k.bondedTokensToNotBonded(ctx, returnAmount)
	}

	completionTime := ctx.BlockHeader().Time.Add(k.UnbondingTime(ctx))
	ubd := k.SetUnbondingDelegationEntry(ctx, delAddr, valAddr, ctx.BlockHeight(), completionTime, returnAmount)
	k.InsertUBDQueue(ctx, ubd, completionTime)

	return completionTime, nil

// Update the tokens of an existing validator, update the validators power index key
func (k Keeper) RemoveValidatorTokensAndShares(ctx sdk.Context, validator types.Validator,
	sharesToRemove sdk.Dec) (valOut types.Validator, removedTokens sdk.Int) {
	k.DeleteValidatorByPowerIndex(ctx, validator)
	validator, removedTokens = validator.RemoveDelShares(sharesToRemove)
	k.SetValidator(ctx, validator)
	k.SetValidatorByPowerIndex(ctx, validator)

	return validator, removedTokens
}
