### Title
Gasless swap admission relies on manipulable Uniswap V2 spot price via `getAmountIn`, enabling proposer/lender fund-drain from a single bundled transaction sequence - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The Kaia gasless-transaction module (KIP-247) admits a `GaslessSwapTx` into the pending pool by checking that the declared `amountIn` covers the router's quoted `getAmountIn(token, minAmountOut)`. That quote is a live, single-block Uniswap V2 (`getReserves`-based) spot price computed by the `GaslessSwapRouter`/`UniswapV2Router02` contracts bound in this repo, with no TWAP or other manipulation-resistant pricing. Because the check is a view call evaluated at the moment of admission/promotion (and the actual on-chain swap in `swapForGas` uses the same manipulable reserves at execution time in the same block), an attacker who also controls or fronts a large swap against the same pool in the same block can force `getAmountIn` to return an artificially low value, get the gasless tx admitted/executed with an `amountIn` far below the "fair" pre-manipulation price, and extract more token value out of the pool than a fairly priced swap would allow — at the expense of the pool's other users, and ultimately at the expense of the block proposer/lender who fronts KAIA for gas and expects `amountRepay` to be reliably covered by the swap's real economic value.

### Finding Description
`checkBalanceForSwap` in [4](#0-3)  performs:
```
requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
...
if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 { return error }
```
`GetAmountIn` is a view call on the `GaslessSwapRouter` contract, whose ABI is bound at [5](#0-4) . The gasless integration test confirms this router wraps a standard Uniswap V2 factory/router pair (`UniswapV2Factory`/`UniswapV2Router02`) whose pricing is derived from `getReserves()` spot balances, with bytecode pinned in [2](#0-1) , and the exchange-rate quote is used directly to size `amountsOut`/`minAmountOut` for the swap in [6](#0-5) .

This is architecturally the same bug class as the reported stNXM issue: a spot AMM reserve ratio, readable and moveable within a single transaction/block, is used as the sole input to a critical financial computation (`getAmountIn`, i.e., "how much token must the user provide to guarantee `minAmountOut`"). Just as `dexBalances()` in the stNXM report used `slot0()` (an instantaneous price) to size a payout, `swapForGas`'s router uses instantaneous reserves to size `amountIn`, and both the tx-pool admission check and the final on-chain execution read the same live, unprotected value in the same block. The `BalanceCheckLevelSwapAmount` config flag in [3](#0-2)  exists specifically to police this value, but it inherits the router's underlying spot-price weakness — it cannot detect that the "current" price was manipulated moments earlier by a bundled or front-run swap.

### Impact Explanation
An attacker (an ordinary, unprivileged gasless-swap sender, optionally colluding with or acting as the block proposer given Kaia's block-building rules that place `[LendTxGenerator, GaslessApproveTx, GaslessSwapTx]` deterministically in a bundle) can:
1. Execute a large swap against the same Uniswap V2 pool referenced by `dexAddress(token)` in the same block, skewing reserves.
2. Immediately submit/have bundled a `swapForGas` call whose `minAmountOut`/`amountIn` were computed off the skewed price, extracting more wKAIA/KAIA value from the pool (and ultimately from the proposer who lent gas and expects timely, correctly priced `amountRepay`) than the pre-manipulation price would allow.
3. Reverse the initial swap in the same or an adjacent transaction to restore the pool and realize a profit, mirroring the stNXM flash-loan/flash-swap pattern exactly.

This constitutes unauthorized value extraction from a Kaia system-adjacent module (KIP-247 gasless swaps) reachable purely by submitting ordinary transactions/bundles, satisfying the "concrete unauthorized value movement" bar.

### Likelihood Explanation
Likelihood is high for any deployment where the gasless module's designated `GaslessSwapRouter`/underlying DEX pool has shallow liquidity, since the attack requires only capital for one round-trip swap within a single block — no special privileges, no cryptographic material, and no consensus-level access are needed. The `IsReady`/bundling logic in [7](#0-6)  guarantees the approve/swap sequence (and by extension, an attacker-controlled preceding manipulation transaction from the same or a colluding sender) lands atomically within a single block, which is exactly the precondition needed for spot-price manipulation to be effective and irreversible-detection-free.

### Recommendation
Do not rely on instantaneous `getReserves()`/spot-price quotes from the `GaslessSwapRouter`/Uniswap V2 pair for sizing `amountIn`/`minAmountOut` validation. Use a manipulation-resistant price source (e.g., a TWAP oracle over multiple blocks, or a router that reads a checked/cumulative price accumulator) both in the `checkBalanceForSwap` admission check and inside the `GaslessSwapRouter.swapForGas` on-chain logic itself, and/or bound the maximum single-block price deviation allowed for gasless swap execution.

### Proof of Concept
Not directly executable from this read-only review since the `GaslessSwapRouter.sol` source itself is not present in this repository (only its compiled bytecode/bindings). The reachable path is demonstrated structurally via the existing test scaffold: the same Uniswap V2 factory/router deployed in [8](#0-7)  could be extended by inserting a large `swapExactTokensForTokens` call from a manipulator immediately before the gasless `swapForGas` call (mirroring `sendSwapTx` at [9](#0-8) ) and observing that `routerContract.GetAmountIn`/`GetAmountsOut` return a skewed quote that `checkBalanceForSwap` accepts, exactly as the stNXM PoC manipulated `slot0()` before calling `withdrawFinalize()`.

// Check promotion condition and enforce pending pool flow control.
func (g *GaslessModule) IsReady(txs map[uint64]*types.Transaction, next uint64, ready types.Transactions) bool {
	g.knownTxsMu.Lock()
	defer g.knownTxsMu.Unlock()

	tx, ok := txs[next]
	if !ok {
		return false
	}

	if !g.isReady(txs, next, ready) {
		return false
	}

	if g.IsBundleTx(tx) {
		// If prev tx is bundle tx, there's no need to check the knownTxs limit because it has been checked in the previous `IsReady()` execution.
		isPrevTxBundleTx := len(ready) != 0 && g.IsBundleTx(ready[len(ready)-1])
		if isPrevTxBundleTx {
			g.knownTxs.add(tx, TxStatusPending)
			return true
		}

		maxBundleTxsInPending := g.GetMaxBundleTxsInPending()
		if maxBundleTxsInPending != math.MaxUint64 {
			numExecutable := uint(g.knownTxs.numExecutable())

			numSeqTxs := uint(1)
			for i := next + 1; i < next+uint64(len(txs)); i++ {
				if tx, ok := txs[i]; ok && g.IsBundleTx(tx) {
					numSeqTxs++
				} else {
					break
				}
			}

			// false if there is possibility of exceeding max bundle tx num
			if numExecutable+numSeqTxs > maxBundleTxsInPending {
				logger.Trace("Not promoting a tx because of exceeding max bundle tx num", "tx", tx.Hash().String(), "numExecutable", numExecutable, "maxBundleTxsInPending", maxBundleTxsInPending)
				return false
			}
		}

		g.knownTxs.add(tx, TxStatusPending)
	}

	return true
}

func (_GaslessSwapRouter *GaslessSwapRouterCaller) GetAmountIn(opts *bind.CallOpts, token common.Address, amountOut *big.Int) (*big.Int, error) {
	var out []interface{}
	err := _GaslessSwapRouter.contract.Call(opts, &out, "getAmountIn", token, amountOut)

	if err != nil {
		return *new(*big.Int), err
	}

	out0 := *abi.ConvertType(out[0], new(*big.Int)).(**big.Int)

	return out0, err

}
