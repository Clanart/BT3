### Title
`ReceivedOutput::read` accepts untrusted `TxOut`/`OutPoint` bytes without re-verifying the `offset` ↔ `script_pubkey` binding enforced by `Scanner::scan_transaction` — ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
The Serai Bitcoin wallet binds a registered HDKD `offset` to a Taproot `script_pubkey` at detection time: `Scanner` maintains `scripts: HashMap<ScriptBuf, Scalar>` and `scan_transaction` only produces a `ReceivedOutput` when `output.script_pubkey` is a key in that map, i.e. when the output provably pays to `key + G*offset` (wallet/mod.rs:185, 205). `ReceivedOutput::read` — the deserialization path for the same object — performs no such consistency check. It reads `offset` via `Secp256k1::read_F`, then `consensus_decode`s an arbitrary `TxOut` and `OutPoint` and returns them as a spendable `ReceivedOutput` (wallet/mod.rs:122–133). Analogous to the Portainer advisory — where `HostConfig.Binds` was inspected but the equivalent `HostConfig.Mounts` was not — here the check exists on the scan path but not on the read path, and the two produce the same object.

### Finding Description
`Scanner::scan_transaction` (wallet/mod.rs:199–214) guarantees every `ReceivedOutput` satisfies `output.script_pubkey == p2tr_tweaked(key + G*offset)` for a registered `offset`. `ReceivedOutput::read` (wallet/mod.rs:122–134) reconstructs a `ReceivedOutput` from raw bytes and validates only that `offset` is a canonical scalar and that `TxOut`/`OutPoint` are consensus-decodable. No check ties `offset` to `output.script_pubkey`, and no check ties `output` to the on-chain UTXO at `outpoint`. Any party able to feed bytes into `ReceivedOutput::read` can therefore inject a `ReceivedOutput` claiming ownership of an arbitrary `TxOut` — e.g. a high-value output paying to an attacker-controlled script — paired with a valid registered offset.

### Impact Explanation
Downstream spend code (`wallet/send.rs`) trusts `ReceivedOutput::offset`, `output`, and `outpoint` to build and sign transactions. A forged `ReceivedOutput` causes funds to be reported as received that are not spendable by the threshold key: the wallet can record an attacker-script output as owned, construct a transaction spending a nonexistent or foreign UTXO, or compute fee/change/dust math on a `value` that was never received. Since the read path bypasses the `scripts` map, the injected output need not correspond to any registered offset at all — only the scalar must be canonical.

### Likelihood Explanation
Exploitation requires an attacker to supply bytes to `ReceivedOutput::read` — plausible wherever serialized outputs cross a trust boundary (relayed scans, stored/transported wallet state, processor inputs). It requires no key material and no collusion; `read_F` accepts any canonical scalar. Impact is bounded to reporting/spendability corruption rather than key recovery, consistent with a Medium-to-High rating.

### Recommendation
After deserialization, re-derive the expected script: compute `p2tr_script_buf(scanner.key + GENERATOR * offset)` and reject the `ReceivedOutput` unless it equals `output.script_pubkey`, or re-run `scripts.get(&output.script_pubkey)` and require it to match the decoded `offset`. Alternatively, store only `offset` + `outpoint` and re-resolve the `TxOut` from chain data at use time.

### Proof of Concept
```
// Attacker-controlled bytes fed to ReceivedOutput::read:
//   offset    = Scalar::ONE (any canonical scalar)
//   output    = TxOut { value: 1_000_000, script_pubkey: <attacker P2TR key> }
//   outpoint  = OutPoint::new(<any txid>, 0)
let forged = ReceivedOutput::read(&mut attacker_bytes).unwrap();
// forged.output().script_pubkey != p2tr_script_buf(key + G*offset)
// yet forged is accepted as a wallet-owned, spendable output.
// Scanner::scan_transaction would never have produced this object
// because scripts.get(&output.script_pubkey) returns None.
```

Key supporting code: the check that exists — `if let Some(offset) = self.scripts.get(&output.script_pubkey)` at wallet/mod.rs:205 — and the unchecked equivalent path — `ReceivedOutput::read` at wallet/mod.rs:122–133.
