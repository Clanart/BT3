## Finding

### Title
Stale `_requestCommitments` entry after a GET response payout enables double payment of the same escrowed relayer fee via `dispatchTimeOut(GetRequestTimeout)` - (`File: evm/src/core/EvmHost.sol`)

### Summary
When an `IApp.onGetResponse` delivery succeeds, `EvmHost.dispatchIncoming(GetResponse,...)` pays the escrowed relayer fee out of `_requestCommitments[commitment]` but never clears that storage slot. Because `handleGetRequestTimeouts`/`dispatchTimeOut(GetRequestTimeout)` re-reads the very same, still-populated `_requestCommitments[commitment]` to determine the refund amount and payer, and the guard against a duplicate timeout is a non-membership proof checked against a *destination-chain* storage slot that a delivered GET response never touches, the same fee can be paid out twice: once to the relayer at delivery time, and again to the original payer via a later, permissionless timeout submission.

### Finding Description
`EvmHost.dispatch(DispatchGet)` escrows the relayer fee in `_requestCommitments[commitment] = FeeMetadata({sender: payer, fee: get.fee})`.

On successful delivery, `dispatchIncoming(GetResponse memory response, address relayer)` does: [1](#0-0) 

It sets `_responseReceipts[commitment]`, calls `onGetResponse`, and — on success — pays the relayer straight from `_requestCommitments[commitment].fee`, but it **never deletes or zeroes `_requestCommitments[commitment]`**.

Separately, the timeout path reads the exact same, uncleared metadata: [2](#0-1) 

and forwards it to: [3](#0-2) 

`dispatchTimeOut(GetRequestTimeout,...)` deletes `_requestCommitments[commitment]` for replay protection *at that point*, calls `onGetTimeout`, and on success refunds `meta.fee` to `meta.sender`. Because `meta` was fetched from `host.requestCommitments(commitment)` before this call, and that slot was never cleared by the earlier successful `dispatchIncoming(GetResponse)`, `meta.fee` and `meta.sender` are still the original values.

The only guard in `handleGetRequestTimeouts` against timing out an already-delivered response is a state-trie **non-membership proof of `RESPONSE_RECEIPTS_STORAGE_PREFIX + commitment`** verified against the *destination* chain's finalized state at `message.height` — i.e., the chain that was originally read by the GET request. But `_responseReceipts[commitment]` is a mapping on the **source** host (the same `EvmHost` instance that ran `dispatchIncoming(GetResponse)`), not on the destination chain. The destination chain's storage trie was never going to contain that key regardless of whether the response was delivered on the source chain, so this non-membership proof is trivially satisfiable even after the response has already been delivered and the fee already paid out.

### Impact Explanation
An unprivileged caller (both `handlePostRequests`-style handlers and `handleGetRequestTimeouts` are documented as "Access: Permissionless") can, after a legitimate GET response has been delivered and the relayer paid, submit a valid `GetRequestTimeout` (backed by a genuine but irrelevant non-membership proof from the destination chain) to trigger a second payout of the identical fee to the original payer. This drains `feeToken()` balance held by `EvmHost` — funded by the pooled fees of all users of the bridge — beyond what was ever escrowed for that specific request, i.e., an unauthorized double-settlement/double-claim of a single fee.

### Likelihood Explanation
The path requires only: (1) a GET request whose response was already delivered and paid, (2) the destination chain's genuine state proof at some height (which naturally never contains the source-host's `_responseReceipts` key), and (3) that `onGetTimeout` on the source module returns success (many modules implement idempotent/no-op timeout handlers). No relayer collusion, no admin/governance action, and no proof forgery are needed — every proof involved is a real proof of real (irrelevant) chain state. This is reachable by any address willing to submit the timeout message.

### Recommendation
Clear `_requestCommitments[commitment]` (or otherwise mark the request as settled) inside `dispatchIncoming(GetResponse,...)` immediately after a successful `onGetResponse` and fee payout, mirroring the replay-protection pattern already used in `dispatchTimeOut`. Additionally, `handleGetRequestTimeouts`/`dispatchTimeOut(GetRequestTimeout)` should check the source host's own `_responseReceipts[commitment]` (or an equivalent settled flag) rather than relying solely on a non-membership proof against an unrelated destination-chain storage slot.

### Proof of Concept
1. Application dispatches a `DispatchGet` with `fee = F`, `payer = P`; `_requestCommitments[commitment] = {sender: P, fee: F}` (`EvmHost.sol` dispatch(DispatchGet)).
2. A relayer submits `handleGetResponses` → `EvmHost.dispatchIncoming(GetResponse, relayer)`. `onGetResponse` succeeds; `_responseReceipts[commitment]` is set; `feeToken().safeTransfer(relayer, F)` executes. `_requestCommitments[commitment]` is left untouched, still `{sender: P, fee: F}` (`EvmHost.sol:824-847`).
3. After the GET request's timeout timestamp passes, any address submits `handleGetRequestTimeouts` with the real `GetRequest`, a valid consensus/state proof for the destination chain at some height, and a (trivially true) non-membership proof that `RESPONSE_RECEIPTS_STORAGE_PREFIX+commitment` is absent from that destination chain's trie (`HandlerV2.sol:293-321`).
4. `host.requestCommitments(commitment)` still returns `{sender: P, fee: F}` since it was never cleared, so `dispatchTimeOut(GetRequestTimeout, meta, commitment)` runs, `onGetTimeout` succeeds (or is a no-op), and `feeToken().safeTransfer(P, F)` fires a second time (`EvmHost.sol:849-877`).
5. Net result: `F` was paid out twice from the shared fee-token pool for a single escrowed request fee.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    /**
     * @dev Dispatch an incoming GET timeout to the source module.
     * @notice Does not refund any protocol fees.
     * @param timeout - timed-out get request bundled with the relayer that submitted the timeout proof
     * @param meta - fee metadata for the original request
     * @param commitment - request commitment
     */
    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
