### Title
`WSEI.withdraw()` uses `transfer()` with a 2300-gas stipend, permanently freezing wrapped SEI held by contract accounts - ([File: contracts/src/WSEI.sol])

### Summary
The canonical Wrapped SEI (`WSEI`) contract, which is compiled into the chain's system artifacts and deployed as a core protocol contract, implements `withdraw()` using Solidity's `transfer()` to return native SEI to the caller. `transfer()` forwards only a fixed 2300-gas stipend to the recipient. Any smart-contract holder of WSEI whose fallback/receive function needs more than 2300 gas (or is invoked through a proxy that adds overhead) can never successfully call `withdraw()`, permanently freezing the native SEI backing its WSEI balance.

### Finding Description
`withdraw()` debits the caller's `balanceOf` mapping and then attempts to pay out native SEI via `payable(msg.sender).transfer(wad)`: [1](#0-0) 

`transfer()` is hard-capped at 2300 gas for the receiving call, per Solidity semantics — the same limitation flagged in the referenced Opyn `PayableProxyController` report. If `msg.sender` is a contract that:
- has no payable fallback/`receive`,
- has a payable fallback/`receive` that consumes more than 2300 gas, or
- is reached through a proxy/delegatecall wrapper that pushes total gas usage above 2300,

then the internal call inside `transfer()` always reverts, causing every `withdraw()` call from that contract to revert unconditionally.

The `WSEI` contract is not merely a test fixture — it is compiled into the chain's EVM system-contract artifacts, confirming it is deployed and used as Sei's canonical wrapped-native-token contract: [2](#0-1) 

Any unprivileged contract deployer can deposit native SEI into `WSEI` (via `deposit()`/`receive()`/`fallback()`), receive WSEI ERC-20 balance, and then be permanently unable to call `withdraw()` to reclaim native SEI if their contract's fallback logic exceeds the 2300-gas stipend — this is fully reachable from ordinary EVM transactions/contract calls with no privileged access required.

### Impact Explanation
Native SEI wrapped through this system contract can become permanently unrecoverable for any smart-contract holder whose receive/fallback path exceeds 2300 gas (a very common case for contracts that update storage, emit events, or forward calls in their fallback, or that are accessed through a proxy). While the WSEI ERC-20 token itself remains transferable, the affected contract can never unwrap it back into native SEI itself, and if the contract has no external mechanism to move the WSEI token elsewhere (e.g., it is not upgradeable, has no admin/rescue function, or is a simple vault/pool contract), the underlying native SEI is permanently locked with no path to recovery — a fund-freezing condition.

### Likelihood Explanation
High likelihood of accidental triggering: smart-contract wallets, multisigs, vaults, DeFi routers, and proxies frequently implement fallback logic that consumes more than 2300 gas (e.g., writing to storage, emitting events, forwarding to a `delegatecall` proxy target) or lack a payable fallback entirely. Any such contract that legitimately deposits into `WSEI` and later tries to withdraw will hit this permanently, with no workaround inside the contract itself.

### Recommendation
Replace `payable(msg.sender).transfer(wad)` in `withdraw()` with a low-level `call{value: wad}("")` (checking the boolean return value), following checks-effects-interactions (balance is already decremented before the external call, so reentrancy risk is limited) and optionally guarding with a reentrancy lock for defense in depth, consistent with the fix pattern (`sendValue`-style calls) referenced in the external report.

### Proof of Concept
1. Deploy a contract `C` with no `receive()`/`fallback()` function (or one that consumes > 2300 gas, e.g., writes to a storage slot).
2. From `C`, call `WSEI.deposit{value: 1 ether}()` — `C` now holds 1 ether worth of WSEI balance.
3. From `C`, call `WSEI.withdraw(1 ether)`.
4. The internal `payable(msg.sender).transfer(wad)` call reverts because the forwarded 2300 gas stipend is insufficient (or no payable fallback exists), causing the entire `withdraw()` transaction to revert.
5. `C` retains its WSEI ERC-20 balance forever but can never redeem it for native SEI directly, demonstrating permanent freezing of the wrapped funds via the deployed `WSEI` system contract.
