### Title
Payout OP_RETURN operator attribution is unsigned by the withdrawer, letting anyone self-fund a payout and frame an uninvolved operator for reimbursement - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
The withdrawer's presigned signature over the payout transaction only uses `SIGHASH_SINGLE|ANYONECANPAY`, which commits solely to the withdrawal input and the matching output (index 0). The OP_RETURN output carrying `operator_xonly_pk` (index 2) and any additional funding inputs are never covered by that signature, so whoever assembles and broadcasts the final transaction can freely choose which operator's key is embedded there — completely independent of who actually supplies the BTC that funds the payout.

### Finding Description
Binding claimed: `operator_xonlypk` committed in `deposit_constant` (and stored as `payout_payer_operator_xonly_pk`) == the operator whose Bitcoin funds paid the withdrawer's output value.

- `create_payout_txhandler` builds the payout tx with input 0 = the Citrea-registered withdrawal UTXO (owned/controlled by the withdrawer), output 0 = withdrawal payment, output 1 = anchor, output 2 = OP_RETURN(`operator_xonly_pk`) [1](#0-0) .
- The withdrawer's signature is generated and verified with `TapSighashType::SinglePlusAnyoneCanPay`, which per BIP341/BIP143 only commits input 0 and output 0; outputs 1 and 2 (anchor, OP_RETURN) and any additional inputs are unsigned [2](#0-1) , confirmed by `Operator::withdraw`'s `SECP.verify_schnorr` call over `calculate_sighash_txin(0, in_signature.sighash_type)` [3](#0-2) .
- The withdrawal input the withdrawer registers via Citrea's `withdraw()` is a dust UTXO (e.g. 550 sats) they fully control the key for, while the output value is the full bridge amount [4](#0-3) ; the real payout amount is funded by whoever adds inputs/fees when broadcasting (normally the operator via `fund_raw_transaction`) [5](#0-4) .
- Because ANYONECANPAY/SINGLE leaves output 2 (OP_RETURN) and any extra funding inputs unsigned, an attacker holding their own dust UTXO's private key can independently construct and broadcast a payout transaction: pay the destination in full from their own separate Bitcoin funds, and put ANY registered operator's `xonly_pk` (public knowledge) in the OP_RETURN — no operator participation required.
- `Verifier::update_finalized_payouts` blindly trusts this OP_RETURN content: it parses `get_first_op_return_output`/`parse_op_return_data` from the on-chain payout tx and stores the resulting key as `payout_payer_operator_xonly_pk`, with no check that the named operator's wallet actually funded the transaction [6](#0-5) .
- The named operator's own automation (`PayoutCheckerTask::run_once`) then queries `get_first_unhandled_payout_by_operator_xonly_pk` for their own key, finds this attacker-fabricated payout, and calls `handle_finalized_payout`, which builds and signs the full kickoff/reimbursement transaction chain [7](#0-6) [8](#0-7) .
- `Verifier::is_kickoff_malicious` and the bridge-circuit `deposit_constant` binding only check that `operator_xonly_pk` (from OP_RETURN) matches `kickoff_data.operator_xonly_pk` (i.e., internal consistency of the DB-derived attribution) — neither checks that the named operator's Bitcoin wallet actually supplied the paid value [9](#0-8) . The circuit's `deposit_constant` computation itself only ever consumes `operator_xonlypk` taken from `get_first_op_return_output`, never the payer/funding source [10](#0-9) .

Thus the equality the protocol depends on (OP_RETURN key == actual funder) never had a signature or funding-source check backing it; it is purely advisory metadata that the withdrawer never signs and an attacker fully controls.

### Impact Explanation
An unprivileged attacker can force a targeted (or arbitrary) operator's automation to spend their round's kickoff connector and reimbursement flow for a withdrawal the operator never funded, releasing bridge move-to-vault collateral to that operator without them ever having fronted BTC. This is exactly "an operator reimbursed for a payout it never funded" (Critical). It is repeatable per withdrawal/deposit and can target any operator whose xonly public key is known (operator keys are public), consuming their kickoff connectors and round state without their consent, and causing collateral to leave the bridge under a false attribution.

### Likelihood Explanation
The attacker only needs: (1) to register a withdrawal via Citrea's `withdraw()` under their own control (standard user action), (2) a Bitcoin UTXO and key they own to sign the SinglePlusAnyoneCanPay withdrawal input, (3) enough BTC to actually front the payout amount themselves, and (4) knowledge of any registered operator's x-only public key (public data). No verifier, operator, or aggregator collusion is required — everything is done by broadcasting attacker-authored Bitcoin transactions and calling public/registered gRPC endpoints. Cost is the payout amount itself (which the attacker pays anyway to receive their own withdrawal) plus fees; the attack is fully repeatable across withdrawals/operators.

### Recommendation
Bind the OP_RETURN operator attribution cryptographically to the actual funding source, e.g., require the withdrawer's payout signature to cover (or separately require an operator-signed acknowledgment of) the OP_RETURN output and all inputs (use `SIGHASH_ALL` semantics for attribution-relevant fields, or have the operator co-sign a commitment binding their key to this specific payout before it is treated as "their" payout). Alternatively, require `update_finalized_payouts`/`PayoutCheckerTask` to verify that the named operator's own wallet/output actually supplied the funding input(s) of the payout transaction (e.g., check that a specific pre-registered operator-funding UTXO was spent) before accepting the OP_RETURN attribution as authoritative.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    pub async fn handle_finalized_payout<'a>(
        &'a self,
        dbtx: DatabaseTransaction<'a>,
        deposit_outpoint: OutPoint,
        payout_tx_blockhash: BlockHash,
    ) -> Result<bitcoin::Txid, BridgeError> {
        let (deposit_id, deposit_data) = self
            .db
            .get_deposit_data(Some(dbtx), deposit_outpoint)
            .await?
            .ok_or(BridgeError::DatabaseError(sqlx::Error::RowNotFound))?;

        // get unused kickoff connector
        let (round_idx, kickoff_idx) = self
            .db
            .get_unused_and_signed_kickoff_connector(
                Some(dbtx),
                deposit_id,
                self.signer.xonly_public_key,
            )
            .await?
            .ok_or(BridgeError::DatabaseError(sqlx::Error::RowNotFound))?;

        let current_round_index = self.db.get_current_round_index(Some(dbtx)).await?;
        tracing::info!(
            "Operator: Current round index: {}, round idx for kickoff: {}",
            current_round_index,
            round_idx
        );
        #[cfg(feature = "automation")]
        if current_round_index != round_idx {
            // we currently have no free kickoff connectors in the current round, so we need to end round first
            // if current_round_index should only be smaller than round_idx, and should not be smaller by more than 1
            // so sanity check:
            if current_round_index.next_round() != round_idx {
                return Err(eyre::eyre!(
                    "Internal error: Expected the current round ({:?}) to be equal to or 1 less than the round of the first available kickoff for deposit reimbursement ({:?}) for deposit {:?}. If the round is less than the current round, there is an issue with the logic of the fn that gets the first available kickoff. If the round is greater, that means the next round do not have any kickoff connectors available for reimbursement, which should not be possible.",
                    current_round_index, round_idx, deposit_outpoint
                ).into());
            }
            tracing::info!(
                "Operator: Starting next round to be able to get reimbursement for the payout"
            );
            // start the next round to be able to get reimbursement for the payout
            self.end_round(dbtx).await?;
        }

        // get signed txs,
        let kickoff_data = KickoffData {
            operator_xonly_pk: self.signer.xonly_public_key,
            round_idx,
            kickoff_idx,
        };

    async fn run_once(&mut self) -> Result<Self::Output, BridgeError> {
        let mut dbtx = self.db.begin_transaction().await?;
        let unhandled_payout = self
            .db
            .get_first_unhandled_payout_by_operator_xonly_pk(
                Some(&mut dbtx),
                self.operator.signer.xonly_public_key,
            )
            .await?;

        if unhandled_payout.is_none() {
            return Ok(false);
        }

        let (citrea_idx, move_to_vault_txid, payout_tx_blockhash) =
            unhandled_payout.expect("Must be Some");

        tracing::info!(
            "Unhandled payout found for withdrawal {}, move_txid: {}",
            citrea_idx,
            move_to_vault_txid
        );

        let deposit_data = self
            .db
            .get_deposit_data_with_move_tx(Some(&mut dbtx), move_to_vault_txid)

            return Err(eyre::eyre!("Fronted withdrawal for move tx {move_to_vault_txid} found, but the signatures for the deposit are not found in the db.").into());

            .operator
            .handle_finalized_payout(

                deposit_data.get_deposit_outpoint(),
