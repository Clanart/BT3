### Title
Malicious FROST preprocess forces an identity nonce sum, panicking `Hram::hram`/`x` and DoS-ing every honest Bitcoin signer - (File: networks/bitcoin/src/crypto.rs)

### Summary
`x()` in `networks/bitcoin/src/crypto.rs` calls `key.to_encoded_point(true).x().expect("point at infinity")`, and the BIP-340 `Hram::hram` unconditionally invokes it on the aggregated nonce `R`. In FROST signing, `R` is the sum of attacker-influenceable nonce commitments (`D + rho * E`) from every participant's preprocess. A malicious participant who sends their preprocess last can grind their `D` commitment so that `D_adv + rho_adv * E_adv` exactly cancels all other contributions, making `R` the point at infinity. Every honest signer then panics inside `sign` → `sign_share` → `hram` — a deterministic, remotely triggered denial of service, mirroring the Squid bug class where a value that can plausibly occur in benign traffic crashes the victim.

### Finding Description
- `crypto/frost/src/nonce.rs` (`GeneratorCommitments::read`, lines 34-36; `Commitments::read`, lines 133-139) deserializes each participant's nonce commitments via `C::read_G` with no non-identity or non-trivial-sum check on the resulting bound nonce `D_l + rho_l * E_l` (`BindingFactor::nonces`, lines 194-212: `D += commitments.nonces[n].generators[g].0[0]` plus `multiexp_vartime` of `rho * E` terms).
- `crypto/frost/src/sign.rs` (`AlgorithmSignMachine::sign`, lines 283-398) computes the per-signer binding factors `rho` from a transcript over *all* preprocesses (`rho_transcript`, lines 361-379) and the aggregate `Rs = B.nonces(&nonces)` (line 383), then calls `algorithm.sign_share(&view, &Rs, nonces, msg)` (line 398).
- For the Bitcoin Schnorr algorithm, `sign_share`/`verify` compute the BIP-340 challenge via `Hram::hram(R, A, m)` at `networks/bitcoin/src/crypto.rs` lines 59-73, which calls `x(R)` at line 65. `x` panics on the point at infinity (lines 13-16): `(*encoded.x().expect("point at infinity")).into()`.
- Because `rho` is a public deterministic hash over the full preprocess set, an adversary who broadcasts their preprocess last can precompute `rho_adv` for a chosen `E_adv`, then set `D_adv = -(sum of other contributions) - rho_adv * E_adv`. The resulting aggregate `R` is identity. There is no `is_identity` check anywhere on the summed nonce before it reaches `hram` (confirmed: the only identity handling in `crypto/frost` is `C::G::identity()` as the accumulator seed in `nonce.rs` line 200).
- The panic aborts the honest signer's `sign` call rather than returning a `FrostError`, so the documented blame path (`FrostError::InvalidShare` / `InvalidParticipant`) is bypassed entirely — the attacker cannot even be identified by the protocol.

### Impact Explanation
An unprivileged counterparty in a Bitcoin threshold-signing session can deterministically crash every honest signer that consumes their preprocess bytes via `read_preprocess` + `sign`. For a Serai validator node this is a process-level panic during signing of Bitcoin transactions — repeatedly triggerable at negligible cost, halting all signing progress (liveness failure of the threshold network) with no attributable blame. The panic also occurs in `verify`/completion paths (`AlgorithmSignatureMachine::complete`, `crypto/frost/src/sign.rs` lines 447-495) whenever the crafted `R` is evaluated.

### Likelihood Explanation
The attack is fully deterministic and needs no bruteforce: the adversary waits for other preprocesses (a standard rushing-adversary capability in broadcast-round protocols), solves for `D_adv` in one step, and publishes a well-formed preprocess that passes `Commitments::read` and `validate_map`. Identity points are only excluded if `read_G` rejects them, and even a non-identity `D_adv`/`E_adv` suffices — only the *sum* must be identity, which requires no special encodings. Documentation for `Schnorr` explicitly acknowledges the panic ("may panic if called with nonces... which are the point at infinity"), and incorrectly assesses it as "a negligible probability... even with malicious participants present" (`networks/bitcoin/src/crypto.rs` lines 78-80) — it is not probabilistic; it is adversarially constructible.

### Recommendation
Check `R` (each element of `Rs`) for the point at infinity in `AlgorithmSignMachine::sign` / `SignatureMachine::complete` before invoking the algorithm's `hram`, returning `FrostError` instead of panicking; or make `Hram::hram`/`x` return an `Option`/`Result`. Additionally, rejecting identity `D`/`E` commitments at `read_G`/preprocess-validation time removes a class of degenerate nonces.

      const TAG_HASH: Sha256 = Sha256::const_hash(b"BIP0340/challenge");

      let mut data = Sha256::engine();
      data.input(TAG_HASH.as_ref());
      data.input(TAG_HASH.as_ref());
      data.input(&x(R));
      data.input(&x(A));
      data.input(m);

      let c = Scalar::reduce(U256::from_be_slice(Sha256::from_engine(data).as_ref()));
      // If the nonce was odd, sign `r - cx` instead of `r + cx`, allowing us to negate `s` at the
      // end to sign as `-r + cx`
      <_>::conditional_select(&c, &-c, needs_negation(R))
    }

  pub(crate) fn nonces(&self, planned_nonces: &[Vec<C::G>]) -> Vec<Vec<C::G>> {
    let mut nonces = Vec::with_capacity(planned_nonces.len());
    for n in 0 .. planned_nonces.len() {
      nonces.push(Vec::with_capacity(planned_nonces[n].len()));
      for g in 0 .. planned_nonces[n].len() {
        #[allow(non_snake_case)]
        let mut D = C::G::identity();
        let mut statements = Vec::with_capacity(self.0.len());
        #[allow(non_snake_case)]
        for IndividualBinding { commitments, binding_factors } in self.0.values() {
          D += commitments.nonces[n].generators[g].0[0];
          statements
            .push((binding_factors.as_ref().unwrap()[n], commitments.nonces[n].generators[g].0[1]));
        }
        nonces[n].push(D + multiexp_vartime(&statements));
      }
    }
    nonces
  }
