### Title
Missing path/traversal validation of the `filepath` deep-link parameter in `parseAppURL` allows attacker-controlled file targeting after clone - (File: `app/src/lib/parse-app-url.ts`)

### Summary
`parseAppURL()` builds an `IOpenRepositoryFromURLAction` from an untrusted `x-github-client://openrepo?...` deep link that any web page or email can trigger via `app.setAsDefaultProtocolClient` [1](#0-0) . Of the four query parameters (`url`, `branch`, `pr`, `filepath`), `branch` is checked with `testForInvalidChars` and `pr` is checked against a strict `^\d+$`/`^pr\/\d+$` regex, but `filepath` is passed through completely unvalidated. [2](#0-1) 

### Finding Description
`parseAppURL()` is the trust boundary between an external, attacker-influenced deep link and Desktop's internal clone/open logic. The function explicitly validates two of the three optional fields (`branch`, `pr`) to reject malformed or dangerous values, showing the developers were aware this data needs sanitization before use: [3](#0-2)  yet the `filepath` value taken from `getQueryStringValue(query, 'filepath')` is returned as-is with no length, character, or path-traversal check: [4](#0-3) 

This is structurally the same bug class as the report: a validation routine that checks some combinations/fields but omits a check for one specific field/combination that is later consumed by downstream logic which assumes the value has already been sanitized (analogous to `_validateConfig` checking `withSlasher`/`isBurnerHook` combinations but missing the `burner == address(0)` case). Here, the omitted check is on `filepath`, which downstream code (in `dispatcher.ts`, main process `handleAppURL`/`open-url` handler) uses to decide which file to open after the clone/open-repository action completes. [1](#0-0) 

### Impact Explanation
If the downstream consumer joins `filepath` with the cloned repository's local path without normalizing/verifying containment (e.g., rejecting `..` segments or absolute paths), a malicious "Open in Desktop" link could cause Desktop to open a file outside of the cloned repository directory once the user clicks the link and completes the clone/open flow — matching the "file read/write outside repo" and "link the user clicks" attacker primitive in the valid-impact criteria.

### Likelihood Explanation
I could not, within the available tool budget, confirm with certainty how `filepath` is consumed at the sink (I identified references in `app/src/ui/dispatcher/dispatcher.ts` but did not get to read that code before the iteration limit). This is a meaningful gap: if the consumer already normalizes/validates the path against the repository root before opening it, this finding would not be exploitable. I am flagging this explicitly rather than asserting confirmed exploitability.

### Recommendation
Regardless of what the current sink does, `parseAppURL()` should validate `filepath` the same way `branch` is validated — reject values containing `..`, backslash/traversal sequences, or absolute path prefixes — before constructing the `IOpenRepositoryFromURLAction`, so the validation happens at the trust boundary rather than relying on every consumer to re-validate correctly.

### Proof of Concept
```
x-github-client://openrepo?url=https://github.com/attacker/repo&filepath=../../../../.ssh/id_rsa
```
`parseAppURL` will return `{ name: 'open-repository-from-url', url: '.../repo', branch: null, pr: null, filepath: '../../../../.ssh/id_rsa' }` unmodified, since only `branch`/`pr` are checked. [2](#0-1) 

**Caveat:** Because I was unable to verify the exact behavior of the consumer of `filepath` in `dispatcher.ts` before running out of tool calls, this should be treated as a preliminary finding requiring confirmation of the downstream sink (does it join with `Path.join`/normalize and check containment, or open the value directly?) before being considered a confirmed, exploitable vulnerability.

  if (actionName === 'openrepo') {
    const pr = getQueryStringValue(query, 'pr')
    const branch = getQueryStringValue(query, 'branch')
    const filepath = getQueryStringValue(query, 'filepath')

    if (pr != null) {
      if (!/^\d+$/.test(pr)) {
        return unknown
      }

      // we also expect the branch for a forked PR to be a given ref format
      if (branch != null && !/^pr\/\d+$/.test(branch)) {
        return unknown
      }
    }

    if (branch != null && testForInvalidChars(branch)) {
      return unknown
    }

    return {
      name: 'open-repository-from-url',
      url: parsedPath,
      branch,
      pr,
      filepath,
    }
