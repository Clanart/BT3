### Title
Unfair/stealable reward distribution via just-in-time (JIT) stake/vote sniping around lump-sum reward injection - (File: rewards/BaseRewardPoolV2.sol, rewards/BaseRewardPool.sol, wombat/WombatBribeManager.sol)

### Summary
Magpie's reward accounting (`MasterMagpie`, `BaseRewardPool`/`BaseRewardPoolV2`, `vlMGPBaseRewarder`, `mWOMSVBaseRewarder`, and the vote-based `WombatBribeManager`/`IBribeRewardPool`) attributes externally-accrued rewards (trading fees, bribes) to whichever stake/vote balance is present at the exact instant a lump-sum reward is injected via `_provisionReward`, rather than to the balances that actually existed throughout the period the reward accrued. Because deposits/withdrawals (and votes) have no cooldown or time-weighting, an ordinary wallet can front-run a predictable/permissionless reward-injection transaction with a large deposit or vote, and immediately withdraw afterward, capturing a share of rewards that accrued before the attacker ever held a position — stealing from honest long-term stakers/voters.

### Finding Description
Reward injection is a discrete, instantaneous event: `_provisionReward` divides the entire incoming reward amount by `totalStaked()` measured at that single block and adds it to `rewardPerTokenStored`: [1](#0-0) 

The same pattern exists in `BaseRewardPool.sol`, `vlMGPBaseRewarder.sol`, and `mWOMSVBaseRewarder.sol`, all of which compute `rewardPerTokenStored += amountReward * 10**decimals / totalStaked()` at the moment `queueNewRewards`/`donateRewards` (or the internal forfeit re-queue) is called: [2](#0-1) 

A user's claimable amount for a reward token is `_earned = userShare * (rewardPerToken - userRewardPerTokenPaid) + userRewards`, i.e. it only depends on the balance held *at the checkpoint boundaries*, not on how long that balance was actually held while the underlying reward was accruing externally: [3](#0-2) 

`MasterMagpie.deposit`/`withdraw` (and the `depositFor`/`withdrawFor` pool-helper equivalents) have no lock-up, cooldown, or minimum holding period, so stake can be added and removed within the same block/transaction bundle around a reward-injection call: [4](#0-3) 

The same instantaneous-snapshot pattern governs bribe voting rewards: `WombatBribeManager.vote()`/`unvote()` let a user add/remove voting stake (`stakeFor`/`withdrawFor` into the `IBribeRewardPool`) at any time with no lock, while `castVotes()` triggers `wombatStaking.vote(...)` which harvests and forwards accumulated bribe rewards (accrued since the last cast) into the bribe reward pools in one lump sum: [5](#0-4) [6](#0-5) 

This mirrors the reported bug class exactly: rewards that accrued over a prior period (trading fees / bribes) are distributed based on the position/tick (here: stake or vote balance) that exists at the moment the distribution is *triggered*, not based on who actually provided value during the accrual window. `castVotes()` and the various `harvest*` entry points on `WombatStaking`/pool helpers are externally callable and visible in the mempool ahead of execution, giving an unprivileged attacker the same front-run/back-run window described in the source report (attacker moves into position immediately before the triggering call, captures disproportionate rewards, then exits).

### Impact Explanation
An ordinary wallet can flash-deposit (or flash-vote) capital immediately before a predictable reward-queuing transaction, receive a share of `rewardPerTokenStored` proportional to its instantaneous balance rather than time held, then withdraw immediately after. This directly steals accrued-but-undistributed yield from honest long-term stakers/voters — a direct theft of unclaimed yield, matching the accepted impact category.

### Likelihood Explanation
Deposits/withdrawals and votes are permissionless and have no cooldown, minimum stake duration, or vesting; reward-injection functions (`queueNewRewards`, `castVotes`, staking-pool harvests) are also permissionless/predictable and visible pre-confirmation in the mempool. No special privileges, oracle manipulation, or governance access are required — only capital and correct transaction ordering (achievable via same-block bundling or simple front-running), making this practically exploitable by any user.

### Recommendation
Replace instantaneous lump-sum `rewardPerTokenStored` updates with time-weighted accrual (e.g., stream the reward linearly over the period it represents, similar to `MasterMagpie.updatePool`'s per-second emission model) or require a minimum stake/vote holding duration (epoch-based locking) before a position becomes eligible for a given reward injection, so that only balances present throughout the accrual period participate in that reward's distribution — analogous to the Super DCA team's proposed fixed-epoch mitigation.

### Proof of Concept
1. Rewards (trading fees / bribes) accumulate off-chain-visible in `WombatStaking`/Wombat gauges over time without being pushed into `BaseRewardPoolV2`/bribe `IBribeRewardPool` yet.
2. Attacker observes a pending `castVotes()` or pool-helper `harvest()` transaction in the mempool that will call `queueNewRewards`/`donateRewards`, injecting the accumulated reward.
3. Attacker front-runs with `MasterMagpie.deposit()` (or `WombatBribeManager.vote()`) for a large amount into the target pool.
4. The harvest transaction executes; `_provisionReward` computes `rewardPerTokenStored += reward * 10**decimals / totalStaked()`, where `totalStaked()` now includes the attacker's fresh stake, giving the attacker a proportional share of rewards that accrued entirely before their deposit.
5. Attacker back-runs with `withdraw()` (or `unvote()`) and calls `getReward`/`getRewards` to claim the sniped share, exiting with profit taken from honest long-term participants.

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;

        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingTokenDecimals) /
                totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
    }

    /// @param _deltas delta amount in vlMGP
    function vote(address[] calldata _lps, int256[] calldata _deltas) override public {
        if (_lps.length != _deltas.length)
            revert LengthMismatch();

        uint256 length = _lps.length;
        int256 totalUserVote;

        for (uint256 i; i < length; i++) {
            Pool storage pool = poolInfos[_lps[i]];
            if (!pool.isActive)
                revert PoolNotActive();
            int256 delta = _deltas[i];
            totalUserVote += delta;
            if (delta != 0) {
                if (delta > 0) {
                    pool.totalVoteInVlmgp += uint256(delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] += uint256(delta);
                    IBribeRewardPool(pool.rewarder).stakeFor(msg.sender, uint256(delta));
                } else {
                    pool.totalVoteInVlmgp -= uint256(-delta);
                    userVotedForPoolInVlmgp[msg.sender][pool.poolAddress] -= uint256(-delta);
                    IBribeRewardPool(pool.rewarder).withdrawFor(msg.sender, uint256(-delta), false);
                }
            }
        }

        if (msg.sender != delegatedPool) {
            if (totalUserVote > 0) {
                userTotalVotedInVlmgp[msg.sender] += uint256(totalUserVote);
                totalVlMgpInVote += uint256(totalUserVote);
            } else {
                userTotalVotedInVlmgp[msg.sender] -= uint256(-totalUserVote);
                totalVlMgpInVote -= uint256(-totalUserVote);
            }
        }

        if (userTotalVotedInVlmgp[msg.sender] > getUserVotable(msg.sender))
            revert NotEnoughVote();
    }
