### Title
Untracked-file pathspec injection via colon-prefixed filenames silently disables security-diff review scope in `_temp_index`/`_diff_pathspec` - (File: `plugins/security-guidance/hooks/gitutil.py`)

### Summary
`_temp_index` and `_diff_pathspec` build `git add`/`git diff` pathspecs directly from repo-controlled filenames without disabling git's pathspec "magic" parsing (`:(...)`, `:!`, `:^`, etc.) or checking the `git add` exit code. An attacker who can create an untracked file whose name starts with `:` can make the `git add --intent-to-add` call fail atomically or match unintended paths, silently dropping the entire batch of untracked files — including genuinely malicious new source files — from the security-review diff.

### Finding Description
`_temp_index` in `plugins/security-guidance/hooks/gitutil.py` stages untracked files for review with: [1](#0-0) 

`surviving` is built purely from repo-relative filenames reported by `git status --porcelain`/`ls-files` (see `_git_status_porcelain` and `_list_untracked` in `diffstate.py`), with no sanitization for git's pathspec magic syntax. Git parses a leading `:` on any pathspec argument as a magic signature (e.g. `:(exclude)`, `:(glob)`, `:!`, `:^`) regardless of the preceding `--` separator — `--` only ends option parsing for the subcommand, it does not disable pathspec magic. If the untracked-file list contains a name like `:(bogus)evil.py` (an invalid/unsupported magic keyword), `git add --intent-to-add -- <surviving>` exits non-zero and, per the code's own comment about the atomic nonexistent-path case, "adds NOTHING" — but the `subprocess.run` return code here is **never checked**: [2](#0-1) 

Because the failure is silently swallowed and `env` (pointing at the incompletely-populated temp index) is yielded regardless, every other untracked file batched into the same `git add` call — including unrelated, legitimately malicious new files created in the same turn — never gets an intent-to-add entry. Files with no intent-to-add entry are invisible to the subsequent `git diff <baseline>` in `get_git_diff`, so they never reach the LLM security reviewer.

The sibling function `_diff_pathspec` (used to restrict `get_git_diff`'s `paths` argument) has the identical gap: repo-relative paths are spliced after `--` with no magic-pathspec neutralization, so a colon-prefixed path here can also perturb the intended diff scope rather than being treated as a literal filename: [3](#0-2) 

Neither `GIT_CMD` nor any caller sets `core.literalPathspecs=true` / `GIT_LITERAL_PATHSPECS=1`, which is git's documented mechanism to force literal (non-magic) pathspec interpretation: [4](#0-3) 

### Impact Explanation
This breaks the stated invariant that git path scoping must never escape the intended repo target: attacker-controlled filenames change how git resolves pathspecs, causing intended files to silently drop out of (or the wrong files to be pulled into) the diff that feeds the LLM security review. Concretely, an untracked file with a crafted colon-prefixed name can cause the entire untracked-file batch for that Stop-hook/commit-review cycle to be excluded from `git diff`, meaning newly introduced malicious code is never sent to `analyze_code_security`/`agentic_review`. This is a silent Security-control bypass — the review pipeline reports success/normal operation while never actually inspecting the attacker's payload files.

### Likelihood Explanation
No special privilege is required: any actor able to place files into the working tree that Claude Code will later treat as "untracked" (e.g. content committed into the repo, files dropped by an earlier automated step, or a file that Claude itself is instructed/tricked into creating with an attacker-chosen name) can trigger this. The trigger filename is a normal, valid filesystem name (`:(bogus)payload.py` or similar) requiring no elevated permissions, symlink tricks, or timing races — just a specific character at the start of a filename. It is fully repeatable: the same crafted filename always reproduces the `git add` failure.

### Recommendation
- Set `GIT_LITERAL_PATHSPECS=1` in the environment used for all `git add`/`git diff` invocations in `gitutil.py` (or add `core.literalPathspecs=true` to `GIT_CMD`), so filenames are never interpreted as pathspec magic.
- Check the return code of the `git add --intent-to-add` call in `_temp_index`; on failure, fall back to per-file `add --intent-to-add` calls (or log/skip only the offending file) instead of silently proceeding with an incomplete temp index.
- Apply the same literal-pathspec hardening to `_diff_pathspec`'s output before it is spliced into `get_git_diff`'s `git diff -- ...` command.

### Proof of Concept
Integration test plan for `plugins/security-guidance/hooks/gitutil.py`:
1. Init a temp git repo with one commit (baseline).
2. Create two untracked files: `legit_malicious.py` (containing an obvious vuln pattern, e.g. `eval(input())`) and `:(bogus)trigger.py`.
3. Call `compute_v2_review_set`/`get_git_diff(cwd, baseline_sha, untracked_paths=["legit_malicious.py", ":(bogus)trigger.py"])`.
4. Assert: with the current code, `get_git_diff` returns a diff that does **not** contain `legit_malicious.py`'s content (because the batched `git add --intent-to-add` failed silently), and `_temp_index`'s internal `subprocess.run` for `git add` has `returncode != 0` that is currently discarded.
5. Expected fix behavior: after applying `GIT_LITERAL_PATHSPECS=1` and return-code checking, either (a) both files are literally added and both appear in the diff, or (b) only the malformed name is skipped while `legit_malicious.py` still appears in the diff — i.e., one bad filename must never suppress review of unrelated files.

```python
def _diff_pathspec(cwd, paths):
    """Convert absolute touched-paths to repo-relative pathspec args for
    git diff. Paths outside cwd (e.g. ~/.claude/…) are dropped. Returns the
    list to splice after `--`, or [] for an unrestricted diff. realpath both
    sides so the macOS /var ↔ /private/var symlink doesn't make in-repo
    paths look external."""
    if not paths:
        return []
    cwd_abs = os.path.realpath(cwd)
    rel = []
    for p in paths:
        try:
            r = os.path.relpath(os.path.realpath(p), cwd_abs)
        except ValueError:
            continue
        if r.startswith(".."):
            continue
        rel.append(r)
    return ["--"] + rel if rel else []
```
