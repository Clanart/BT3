### Title
Unvalidated attacker-controlled offset can read past the end of a mempool-submitted spend's serialized CLVM buffer - ([File: chia/full_node/mempool_manager.py])

### Summary
`is_atom_canonical()` / `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` walk an attacker-supplied byte buffer (`coin_spend.puzzle_reveal` / `coin_spend.solution`) using an `offset` index derived entirely from length-prefix bits taken from the buffer itself, with no bound check against `len(clvm_buffer)` before each indexed read. [1](#0-0)  This is analogous to CVE-2022-42261's root cause: "an input index is not validated," causing reads to be made beyond the intended structure using attacker-controlled offsets.

### Finding Description
`is_atom_canonical` reads `clvm_buffer[offset]` and, for atoms with multi-byte length prefixes, loops `prefix_len` times (up to 5) incrementing `offset` and reading `clvm_buffer[offset]` again — `prefix_len` itself is derived from bit patterns in the just-read byte, which is fully attacker controlled. [1](#0-0)  `is_clvm_canonical` calls this in a loop that advances `offset` by `atom_len` (also attacker-controlled, since `atom_len` is computed from the buffer's own bytes) each iteration, with the only bound check occurring *after* the loop completes (`return offset == len(clvm_buffer)`), not before each indexed access. [2](#0-1) 

This function is invoked directly on every coin spend's `puzzle_reveal` and `solution` bytes during mempool admission of an untrusted, single submitted spend bundle: `validate_spend_bundle()` calls `is_clvm_canonical(bytes(coin_spend.puzzle_reveal))` and `is_clvm_canonical(bytes(coin_spend.solution))` for each `coin_spend` in `new_spend.coin_spends`. [3](#0-2)  This is a directly reachable path for any unprivileged spend-bundle submitter (mempool admission).

If `offset` walks past `len(clvm_buffer) - 1` inside `is_atom_canonical`'s prefix-consuming loop or inside `is_clvm_canonical`'s dispatch (`b = clvm_buffer[offset]`), Python raises `IndexError` on the out-of-range index because Python `bytes` indexing is bounds-checked at the interpreter level (unlike a native/unmanaged buffer, where an unvalidated index would cause a real out-of-bounds memory read as in the NVIDIA vGPU CVE). There is no `try/except` around this call in `validate_spend_bundle`, so an `IndexError` here is not caught and would propagate up, crashing/erroring out of the coin-spend processing loop rather than returning a clean `Err.INVALID_COIN_SOLUTION`.

### Impact Explanation
Because this code runs inside Python (a memory-safe managed runtime), the analog to the NVIDIA buffer-overrun (out-of-bounds read leading to information disclosure or crash) manifests here as an unhandled `IndexError` rather than actual memory corruption. Since the exception is not caught in the calling path (`validate_spend_bundle`), a maliciously crafted `coin_spend.puzzle_reveal`/`solution` byte sequence — where a length-prefix byte's trailing continuation bytes point past the end of the buffer — could raise an unhandled exception during mempool admission of a single, otherwise well-formed spend bundle. Depending on how the caller of `validate_spend_bundle`/`add_spend_bundle` handles exceptions (not shown in the excerpts reviewed), this could interrupt normal spend-bundle processing for that request. I was unable to fully verify whether an outer `try/except` around the full mempool admission pipeline (e.g., in the RPC/peer message handler) would catch and gracefully convert this exception, which limits certainty about whether this rises to a transaction-processing halt versus a per-request error.

### Likelihood Explanation
Reachability is high: this code path is exercised for every coin spend in every submitted spend bundle. The trigger only requires constructing a `puzzle_reveal` or `solution` byte string with a crafted multi-byte atom length-prefix (e.g., a byte matching the `0b11111100`/`0b11111110` patterns) placed near the end of the buffer so that the subsequent prefix-continuation reads exceed the buffer length. Test coverage in the repo (`test_mempool_requires_canonical_clvm`) only exercises non-canonical-but-in-bounds cases, not out-of-bounds offsets, so I could not confirm from the index whether this exact edge case is tested or already guarded elsewhere (e.g., a length check I may not have located).

### Recommendation
Add explicit bounds checks before every indexed read in `is_atom_canonical` and `is_clvm_canonical` (e.g., verify `offset < len(clvm_buffer)` before each `clvm_buffer[offset]` access, and verify `offset + prefix_len < len(clvm_buffer)` before the prefix-consuming loop), returning "not canonical" or raising a well-defined `ConsensusError`/`Err.INVALID_COIN_SOLUTION` instead of allowing a raw `IndexError` to propagate. Additionally, wrap the `is_clvm_canonical` calls in `validate_spend_bundle` in a `try/except` (or ensure equivalent handling upstream) so any parsing exception maps cleanly to `Err.INVALID_COIN_SOLUTION` rather than potentially propagating unexpectedly.

### Proof of Concept
Construct a `coin_spend` whose `puzzle_reveal` (or `solution`) bytes end with a byte matching a multi-byte atom length-prefix pattern (e.g., `0b11110000` mask, indicating a 3-byte continuation) but with fewer than 3 bytes remaining in the buffer, for example a 2-byte buffer `b"\xf0\x01"`:
1. Submit a `SpendBundle` containing this `coin_spend` to `MempoolManager.add_spend_bundle()`.
2. `validate_spend_bundle()` calls `is_clvm_canonical(bytes(coin_spend.puzzle_reveal))`. [4](#0-3) 
3. Inside `is_clvm_canonical`, `b = clvm_buffer[0]` matches the `0xf0` prefix branch dispatching to `is_atom_canonical(clvm_buffer, 0)`. [5](#0-4) 
4. `is_atom_canonical` computes `prefix_len = 3` from the byte pattern and then loops 3 times reading `clvm_buffer[offset]`, but the buffer only has 1 more byte — on the second/third iteration `offset` exceeds `len(clvm_buffer) - 1`, raising an unhandled `IndexError`. [6](#0-5) 

I was not able to execute this PoC in the sandbox to confirm the exact exception propagation behavior upstream of `validate_spend_bundle`; a Devin session with full repo/test access would be needed to confirm whether an outer handler already catches this or whether it results in an actual unhandled crash during mempool processing.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
