### Title
Operator's `payout_tx` fee/output malleability via `SIGHASH_SINGLE|ANYONECANPAY` user signature causes attribution loss and permanent reimbursement block - ([File: crates/clementine-tx-sender/src/db/citrea.rs], [core/src/builder/transaction/operator_reimburse.rs], [core/src/database/verifier.rs])

### Summary
`create_payout_txhandler` builds a taproot key-spend transaction whose only witness is the user's signature over input 0, and that signature only commits to input 0 and output 0 when using `SIGHASH_SINGLE|ANYONECANPAY`, leaving outputs 1 (anchor) and 2 (OP_RETURN carrying `operator_xonly_pk`) unauthenticated. Any unprivileged party who observes the broadcast `payout_tx` can extract the signature+input, rebuild a transaction with identical input and output 0 but a corrupted OP_RETURN, and get it mined first.

### Finding Description
The broken binding is: `withdrawals.payout_payer_operator_xonly_pk` for withdrawal idx *i* should equal the xonly pubkey of the operator O whose funds paid `payout_tx.output[0]` (the user payout). Because `create_payout_txhandler` (`core/src/builder/transaction/operator_reimburse.rs`, lines 407-436) constructs the payout as a single `SpendPath::KeySpend` input signed once via `set_p2tr_key_spend_witness(&user_sig, 0)`, and the user signature is a `SinglePlusAnyoneCanPay` type sighash (as referenced across `core/src/actor.rs` and `core/src/rpc/parser/operator.rs`), BIP341 semantics for `SIGHASH_SINGLE|ANYONECANPAY` mean the sighash commits only to: (a) the single input being spent (its outpoint/amount/scriptPubKey), and (b) the output at the same index as the input (output 0). Outputs 1 (anchor) and 2 (OP_RETURN with `operator_xonly_pk.serialize()`) are entirely outside the signed message.

Consequently, an attacker who sees the broadcast `payout_tx` can construct `tx2` reusing the exact signed input (with its valid signature, still verifying against the unchanged sighash) and output 0 verbatim, while replacing output 2 with an unparsable/malformed script (and optionally output 1). Because the signature never covered output 2's content, `tx2` is a fully valid, independently broadcastable transaction that conflicts with O's `payout_tx` (same input) and can win via RBF/fee bump.

When `tx2` confirms first, `Verifier::update_finalized_payouts` (`core/src/verifier.rs`) calls `Database::get_payout_txs_for_withdrawal_utxos` (`core/src/database/verifier.rs`, lines 170-196) to find the withdrawal idx spent, then attempts to extract the payer's operator xonly pk from the OP_RETURN. Since `tx2`'s output 2 is malformed, `get_first_op_return_output`/`parse_op_return_data` fails to parse a valid pubkey and `None` is written via `update_payout_txs_and_payer_operator_xonly_pk` (lines 199-251) — the DB test at lines 496-513 explicitly documents this "None operator xonly pk (optimistic payout or incorrect payout)" code path as an accepted outcome, showing no guard rejects a payout row with `payout_payer_operator_xonly_pk = NULL` when it's actually a real (non-optimistic) payout with corrupted attribution data.

No existing guard checks that the winning spending transaction's OP_RETURN format/content matches what O actually broadcast, nor does the protocol require output 2 to be covered by the withdrawal signature. `Verifier::is_deposit_valid`, `SECP.verify_schnorr`, and other listed guards operate on deposit/kickoff data, not on payout OP_RETURN integrity against malleation of unsigned outputs.

### Impact Explanation
Operator O funded the user's withdrawal (output 0 of the true `payout_tx`), but because `withdrawals.payout_payer_operator_xonly_pk` is stored as `NULL` for idx i, `get_first_unhandled_payout_by_operator_xonly_pk(O.xonly_pk)` (`core/src/database/verifier.rs`, lines 282-313) will never return idx i for O, since the query filters on `payout_payer_operator_xonly_pk = $1`. This means `PayoutCheckerTask::run_once` never reaches `mark_payout_handled`/kickoff attribution for this withdrawal on O's behalf, permanently blocking O's `Reimburse` path for BTC it fronted. This matches the Critical category "an honest operator permanently unable to be reimbursed." The attack is repeatable per withdrawal that any operator fronts, and costs the attacker only the fee needed to win the mempool/RBF race and confirm `tx2` before `payout_tx`.

### Likelihood Explanation
Preconditions are realistic: a deposit exists, a withdrawal is requested on Citrea, and an operator has already broadcast a valid `payout_tx` (unconfirmed, within default `finality_depth`). The attacker needs no protocol role — only the ability to observe the mempool/broadcast transaction, extract input+signature+output 0, and rebroadcast with a higher fee/RBF to win the race before O's transaction confirms. This is a standard transaction-malleation/pinning race achievable by any Bitcoin network participant with modest fee budget, entirely within the stated attacker capability of "anyone who can broadcast Bitcoin transactions and pay fees."

### Recommendation
Change the payout signature scheme so the user's signature commits to all outputs of `payout_tx`, e.g. use `SIGHASH_ALL` (or `SIGHASH_SINGLE` without `ANYONECANPAY` combined with a fixed/committed input set) instead of `SinglePlusAnyoneCanPay`, ensuring the OP_RETURN carrying `operator_xonly_pk` cannot be altered without invalidating the signature. Alternatively, commit the operator's xonly pubkey via a script-path condition tied to the same signature that authorizes output 0, so any malleation of the OP_RETURN also invalidates the spend.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,

    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
