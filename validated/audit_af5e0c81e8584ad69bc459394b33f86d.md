### Title
Missing caller authorization check in `CW721ERC721Pointer.transferFrom` allows anyone to steal NFTs - (File: contracts/src/CW721ERC721Pointer.sol)

### Summary
`CW721ERC721Pointer.transferFrom()` only validates that the `from` argument matches the on-chain owner returned by `ownerOf(tokenId)`, but never checks that `msg.sender` is that owner or an approved spender/operator. Any unauthorized address can invoke `transferFrom(realOwner, attacker, tokenId)` for any token it does not own or control, and the pointer will faithfully forward a `transfer_nft` message to the underlying CW721 contract, moving the NFT to the attacker.

### Finding Description
The vulnerable function is: [1](#0-0) 

```solidity
function transferFrom(address from, address to, uint256 tokenId) public override {
    if (to == address(0)) {
        revert ERC721InvalidReceiver(address(0));
    }
    require(from == ownerOf(tokenId), "`from` must be the owner");
    string memory recipient = _formatPayload("recipient", _doubleQuotes(AddrPrecompile.getSeiAddr(to)));
    string memory tId = _formatPayload("token_id", _doubleQuotes(Strings.toString(tokenId)));
    string memory req = _curlyBrace(_formatPayload("transfer_nft", _curlyBrace(_join(recipient, tId, ","))));
    _execute(bytes(req));
}
```

This mirrors the report's bug class: a function trusts data fetched from an authoritative source (`ownerOf(tokenId)`, analogous to `tellerV2.getLoanBorrower`) but never validates that the transaction sender (`msg.sender`) is authorized to act on behalf of that owner. Since `from` is caller-supplied and only checked for equality against the real owner (not against `msg.sender`), any account can pass in the true owner's address as `from` and its own address as `to`.

Compare this to the correct pattern used in the sibling pointer contract `CW1155ERC1155Pointer.safeTransferFrom`, which does gate transfers by caller identity: [2](#0-1) 

and to the reference `ERC721.sol` implementation bundled in the same repo, which requires `_isApprovedOrOwner(from, msg.sender, id)`: [3](#0-2) 

`CW721ERC721Pointer.transferFrom` omits this `msg.sender` check entirely, and neither `approve()` nor `getApproved()`/`isApprovedForAll()` are consulted before executing the transfer: [4](#0-3) 

Once the ownership check passes, `_execute` delegatecalls into the wasmd precompile to submit a `transfer_nft` execute message directly to the CW721 contract using the pointer's own authority, with no `msg.sender`-based ACL applied: [5](#0-4) 

### Impact Explanation
Any unprivileged EVM account can call `CW721ERC721Pointer.transferFrom(victimOwner, attacker, tokenId)` for arbitrary tokens on any deployed CW721↔ERC721 pointer, stealing NFTs (and any escrowed/represented value) from their rightful owners without ever obtaining approval. This is a direct, unauthorized transfer of user assets via a Cosmos↔EVM pointer contract, meeting the "unauthorized transfer via precompile or pointer" impact bar with concrete fund/asset loss.

### Likelihood Explanation
The vulnerability is trivially and deterministically reachable by any public RPC client/contract deployer: it requires only knowledge of an existing pointer address and a valid `tokenId` with a known owner (`ownerOf` is a public view function on the same contract), and a single `transferFrom` transaction completes the theft. No special privileges, races, or validator cooperation are required.

### Recommendation
Add the standard ERC721 authorization check before executing the transfer, requiring `msg.sender == from || msg.sender == getApproved(tokenId) || isApprovedForAll(from, msg.sender)`, matching the pattern already implemented in `CW1155ERC1155Pointer.safeTransferFrom` and the local reference `ERC721.sol`.

### Proof of Concept
1. Owner `O` owns `tokenId = 1` on the CW721 contract behind pointer `P` (`P.ownerOf(1) == O`), and has never approved anyone.
2. Attacker `A` (unrelated account, no approval) calls `P.transferFrom(O, A, 1)` directly.
3. `require(from == ownerOf(tokenId), ...)` passes because `from == O` is the true owner — the check never inspects `msg.sender`.
4. `_execute` submits `{"transfer_nft":{"recipient": A_sei_addr, "token_id": "1"}}` to the underlying CW721 contract via the wasmd precompile using the pointer contract's execution authority.
5. The CW721 contract moves token `1` from `O` to `A`; `A` now owns the NFT despite never being authorized by `O`.
