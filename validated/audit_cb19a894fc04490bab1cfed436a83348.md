### Title
Out-of-bounds atom-length decoding in CLVM canonical-form check causes unhandled exception on spend bundle submission - ([File: chia/full_node/mempool_manager.py])

### Summary
`is_atom_canonical()` and its caller `is_clvm_canonical()` in `chia/full_node/mempool_manager.py` decode CLVM atom length-prefixes directly from an attacker-supplied byte buffer without ever validating that the computed offsets stay within the buffer bounds, mirroring the bug class in CVE-2024-29164 (HDF5 `H5R__decode_heap` reading a length-prefixed heap object without validating the decoded length against the buffer size).

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads `clvm_buffer[offset]` to determine a length-prefix format, then loops `prefix_len` times incrementing `offset` and indexing `clvm_buffer[offset]` again to build up `atom_len`: [1](#0-0) 

None of these branches check `offset` (or `offset + prefix_len`) against `len(clvm_buffer)` before indexing. The value `atom_len`, which is fully attacker-controlled (up to `0x01FFFFFFFFFF` for the 5-byte prefix branch), is then returned and used by the caller `is_clvm_canonical()` to advance the read cursor: [2](#0-1) 

Specifically, in `is_clvm_canonical()`, the returned `atom_len` is added to `offset` (`offset += atom_len`) with no check that the new offset stays within `clvm_buffer`. On the next loop iteration, `clvm_buffer[offset]` is indexed again — an offset that can be pushed arbitrarily far past the end of the buffer by crafting a single oversized/malformed atom length prefix. In Python this raises an unhandled `IndexError` rather than corrupting memory (since `bytes.__getitem__` is bounds-checked), but the effect is the same class of defect as the HDF5 CVE: a decode routine that trusts an attacker-supplied length field to walk a buffer without a bounds check.

### Impact Explanation
This function operates on CLVM byte buffers taken directly from spend bundles submitted to the mempool (used to detect non-canonical/back-reference serialization during spend bundle processing). If the resulting `IndexError` is not caught somewhere up the call chain during spend bundle validation, a single malformed spend bundle submitted by any unprivileged peer/wallet could raise an uncaught exception inside the mempool manager's validation path, halting or crashing transaction processing for the node — a spend-triggered transaction-processing halt, which is explicitly in-scope impact for this analog scan.

### Likelihood Explanation
Likelihood is high for triggering the exception: constructing a CLVM buffer whose final atom's length-prefix byte(s) claim a length or prefix count that overruns the buffer is trivial and requires no privileges — it's just crafted bytes in a submitted spend bundle. What is not confirmed from the available code is whether the immediate caller of `is_clvm_canonical` in the mempool add/pre-validation pipeline wraps this check in a broad exception handler; if it does, the practical impact is reduced to a benign rejection rather than a processing halt. This caller context could not be fully verified because the specific call site invoking `is_clvm_canonical` (only its test-imports and definition were located within the available tool budget) was not reachable in the remaining iterations.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before each `clvm_buffer[offset]` access (raise a clean, catchable error such as `ValueError`/`Err.INVALID_SPEND_BUNDLE` rather than allowing `IndexError` to propagate), and ensure `is_clvm_canonical()` validates that `offset` never exceeds `len(clvm_buffer)` on each iteration. Confirm the mempool spend-bundle validation call site wraps this canonical-check call in the same structured error handling used for other malformed-spend-bundle conditions so a crafted buffer is rejected with a normal validation error instead of raising an unhandled exception.

### Proof of Concept
Constructing a minimal CLVM buffer with a single atom whose 5-byte length prefix (`0b111110xx` lead byte, e.g. `0xFD`) is followed by fewer than 5 trailing bytes causes `is_atom_canonical`/`is_clvm_canonical` to index past the end of `clvm_buffer`, e.g.:
```python
from chia.full_node.mempool_manager import is_clvm_canonical
buf = bytes([0xFD, 0x00, 0x00])  # 5-byte-prefix atom, but buffer ends after 2 prefix bytes
is_clvm_canonical(buf)  # raises IndexError instead of a handled validation error
```
This mirrors the analog bug class of CVE-2024-29164: a length-prefixed decode routine that trusts an attacker-controlled length field without validating it against the actual buffer bounds.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
