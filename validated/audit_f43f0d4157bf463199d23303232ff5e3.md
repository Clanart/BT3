### Title
Unregistered-participant HashMap indexing panics during PedPoP blame decryption, crashing the node on attacker-influenced input - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
`Decryption::decrypt_with_proof` indexes `self.enc_keys[&decryptor]` directly. If the `decryptor` participant index was never registered via `Decryption::register` — which only happens when that participant previously submitted an `EncryptionKeyMessage` — the `HashMap` index panics, aborting the calling process. This is the Rust analog of CVE-2017-7507's NULL pointer dereference: attacker-reachable message data drives a lookup into a missing entry and crashes the host application instead of returning an error.

### Finding Description
In PedPoP's blame/accusation flow, a party that claims it received a bad share must reveal the encrypted message so others can verify the accusation. `decrypt_with_proof` is invoked with `from` (the accused) and `decryptor` (the accuser), both supplied through the accusation message path: [1](#0-0) 

The two lookups `self.enc_keys[&decryptor]` (line 388) and `self.decryption.enc_keys[&participant]` in `Encryption::encrypt` (line 466) use `HashMap`'s `Index` impl, which panics on missing keys. `enc_keys` is populated only by `register`, which is driven by each participant voluntarily broadcasting an `EncryptionKeyMessage`: [2](#0-1) 

A participant that never sends its `EncryptionKeyMessage` (or whose message is dropped/malformed) leaves no entry in the map. Any subsequent call to `encrypt`/`decrypt_with_proof` naming that participant then panics. `Participant` is a plain `u16` wrapper (`Participant::new`), so any syntactically valid index ≤ 65535 is accepted at deserialization; nothing validates that the index has a registered encryption key before indexing.

### Impact Explanation
An unprivileged protocol participant can crash the DKG/host process by triggering an encryption or blame-decryption path against a participant index that has no registered key — e.g., by withholding their own `EncryptionKeyMessage` and then being named as an accuser, or by inducing the caller to process an accusation referencing an unregistered index. This mirrors the CVE-2017-7507 class exactly: well-formed-but-unexpected input reaches a dereference of a nonexistent object, producing an availability failure (CVSS-class A:H) across every node executing the code path.

### Likelihood Explanation
Reachability is high: the crash requires only that a participant abstains from (or fails at) the encryption-key registration round and is later referenced — both conditions are creatable by a single faulty participant with public inputs, no collusion, leaked keys, or broken BFT assumptions needed. The panic is unconditional once reached (`HashMap::index` on absent key → `panic!`).

### Recommendation
Replace panicking indexing with checked lookups in `crypto/dkg/pedpop/src/encryption.rs`:
- In `Decryption::decrypt_with_proof` (line 388), use `self.enc_keys.get(&decryptor).ok_or(DecryptionError::InvalidProof)?` (or a dedicated `UnregisteredParticipant` error variant).
- In `Encryption::encrypt` (line 466), return a `Result` and surface missing registration as an error instead of indexing.
- Optionally validate in `Decryption::register`'s caller that all `1..=n` participants registered before proceeding to the share-distribution/blame phases.

  pub(crate) fn decrypt_with_proof<E: Encryptable>(
    &self,
    from: Participant,
    decryptor: Participant,
    mut msg: EncryptedMessage<C, E>,
    // There's no encryption key proof if the accusation is of an invalid signature
    proof: Option<EncryptionKeyProof<C>>,
  ) -> Result<Zeroizing<E>, DecryptionError> {
    if !msg.pop.verify(
      msg.key,
      pop_challenge::<C>(self.context, msg.pop.R, msg.key, from, msg.msg.deref().as_ref()),
    ) {
      Err(DecryptionError::InvalidSignature)?;
    }

    if let Some(proof) = proof {
      // Verify this is the decryption key for this message
      proof
        .dleq
        .verify(
          &mut encryption_key_transcript(self.context),
          &[C::generator(), msg.key],
          &[self.enc_keys[&decryptor], *proof.key],
        )
        .map_err(|_| DecryptionError::InvalidProof)?;

      cipher::<C>(self.context, &proof.key).apply_keystream(msg.msg.as_mut().as_mut());
      Ok(msg.msg)
    } else {
      Err(DecryptionError::InvalidProof)
    }
  }
