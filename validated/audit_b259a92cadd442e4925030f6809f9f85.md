### Title
Gasless module `Disable` config flag is not enforced in tx-pool promotion or block-bundling paths, preventing runtime pause of proposer fund-lending during an active exploit - (File: `kaiax/gasless/impl/tx_pool.go`, `kaiax/gasless/impl/builder.go`, `kaiax/gasless/impl/init.go`)

### Summary
The external report flags `MarketRouter.sol` for lacking a `whenNotPaused` kill-switch on fund-moving functions, leaving operators unable to quickly halt exploitable functionality. The closest reachable analog in this Kaia codebase is the `kaiax/gasless` module's `GaslessConfig.Disable` flag: it is treated as a pause switch (`IsDisabled()`), but it is only consulted in `Init()` (one-time, startup balance check) and in the read-only `debug_isGaslessTx` RPC handler. It is **never checked** in the actual consensus-relevant paths — `PreAddTx`, `IsModuleTx`, `IsReady`, or `ExtractTxBundles` — which are what actually admit `GaslessApproveTx`/`GaslessSwapTx` into the pool and bundle them together with a proposer-funded `LendTxGenerator` transaction that transfers KAIA from the block proposer to the sender.

### Finding Description
`GaslessModule.IsDisabled()` reads `g.GaslessConfig.Disable`: [1](#0-0) 

This flag is set once during `Init()` (only auto-disabled if the CN's balance is below `GaslessLenderMinBal`), or via the CLI/config flag `gasless.disable`: [2](#0-1) [3](#0-2) 

The only other place `IsDisabled()`/`Disable` is consulted is the read-only debug API `IsGaslessTx`, not any transaction-admission or block-building path: [4](#0-3) 

However, the functions that actually control whether a `GaslessApproveTx`/`GaslessSwapTx` is accepted into the tx pool, promoted to pending, and bundled with a proposer-funded lending transaction (`LendTxGenerator`) never check `IsDisabled()`:
- `PreAddTx` (tx-pool admission) — no disable check: [5](#0-4) 
- `IsModuleTx` — no disable check: [6](#0-5) 
- `IsReady` (pending promotion) — no disable check: [7](#0-6) 
- `ExtractTxBundles` (block-building, generates the `LendTxGenerator` that transfers the proposer's KAIA balance to the sender) — no disable check: [8](#0-7) 

The same pattern exists in `kaiax/auction`: `AuctionModule.IsDisabled()` is only checked at `Init()` (auto-disable on low balance) and in `SubmitBid` RPC, but the auction module's `PostInsertBlock` state-sync path continues operating regardless: [9](#0-8) [10](#0-9) 

Because `Disable` is only read at construction time and in an out-of-band RPC, there is no functional "pause" for the actual value-transferring mechanics: if a node operator discovers a bug in `IsExecutable`/`VerifyExecutable`/`repayAmount` logic (e.g., an underpriced repay amount or spoofable executability check) that lets an attacker drain the proposer's `LendTxGenerator` funds, flipping `gasless.disable` at runtime has no effect on tx pool admission or block bundling — only a full node restart with the flag set at `Init()` would stop it, and even that only works if the balance-based auto-disable or explicit flag is evaluated before the exploit tx is already in-flight.

### Impact Explanation
This is functionally the same bug class as the report: a feature that moves funds (proposer KAIA to a transaction sender via `LendTxGenerator`) lacks an effective runtime pause. In a live incident, operators would rely on the `Disable`/`IsDisabled()` semantics believing they can halt gasless processing, but the tx-pool and block-building code paths ignore it, so the vulnerable/exploitable flow (proposer fund lending per malicious `GaslessSwapTx`) continues to execute against every subsequent block until the node is fully restarted with the correct flag baked into `Init()`. This directly risks continued unauthorized value movement (proposer KAIA drained repeatedly) during exactly the window when a fix should be taking effect.

### Likelihood Explanation
Medium-High. It requires (a) a bug in the gasless swap/repay verification logic being separately discovered/exploited, and (b) the operator relying on the `Disable` flag as an emergency stop, which does not immediately halt bundling. Given `Disable` is explicitly modeled as a pause mechanism (config flag `gasless.disable`, auto-disable on low balance) but not wired into the consensus-critical paths, this is a design/implementation gap rather than a purely theoretical one, matching the report's core complaint about insufficient pausability of fund-moving logic.

### Recommendation
Wire `g.IsDisabled()`/`g.GaslessConfig.Disable` (and the analogous `AuctionConfig.Disable`) into all consensus/tx-pool critical entry points — `PreAddTx`, `IsModuleTx`, `IsReady`, `ExtractTxBundles` (and `FilterTxs`) for gasless, and the equivalent bid-admission/bundle paths for auction — so that toggling the disable flag (or an on-chain/admin-triggered runtime reload of `GaslessConfig`) immediately stops new `GaslessTx`/bid promotion and bundle generation without requiring a node restart. Consider exposing an admin RPC to toggle `Disable` at runtime and re-check it on every `PreAddTx`/`ExtractTxBundles` call rather than only at `Init()`.

### Proof of Concept
1. Start a CN with `gasless.disable=false` (or with sufficient balance so auto-disable does not trigger).
2. Discover/exploit an issue in `VerifyExecutable`/`repayAmount` (`kaiax/gasless/impl/getter.go`) that lets `swapArgs.AmountRepay` be set below the fair lend amount, letting an attacker profit from `LendTxGenerator`'s KAIA transfer.
3. Operator sets `gasless.disable=true` at runtime (e.g., via config reload) attempting to stop the drain.
4. Because `PreAddTx`, `IsModuleTx`, `IsReady`, and `ExtractTxBundles` never call `g.IsDisabled()`, the attacker's `GaslessApproveTx`/`GaslessSwapTx` pair is still accepted into the pool, promoted, and bundled with `LendTxGenerator`, continuing to drain the CN's KAIA balance despite the "pause."

func (g *GaslessModule) PreAddTx(tx *types.Transaction, local bool) error {
	g.knownTxsMu.RLock()
	defer g.knownTxsMu.RUnlock()

	if knownTx, ok := g.knownTxs.get(tx.Hash()); ok && knownTx.elapsedPromotedOrAddedTime() < KnownTxTimeout {
		return ErrUnableToAddKnownBundleTx
	}

	if g.IsBundleTx(tx) {
		if uint(g.knownTxs.numQueue()) >= g.GetMaxBundleTxsInQueue() {
			return ErrBundleTxQueueFull
		}
		g.knownTxs.add(tx, TxStatusQueue)
	}
	return nil
}

func (g *GaslessModule) IsReady(txs map[uint64]*types.Transaction, next uint64, ready types.Transactions) bool {
	g.knownTxsMu.Lock()
	defer g.knownTxsMu.Unlock()

	tx, ok := txs[next]
	if !ok {
		return false
	}

	if !g.isReady(txs, next, ready) {
		return false
	}

	if g.IsBundleTx(tx) {
		// If prev tx is bundle tx, there's no need to check the knownTxs limit because it has been checked in the previous `IsReady()` execution.
		isPrevTxBundleTx := len(ready) != 0 && g.IsBundleTx(ready[len(ready)-1])
		if isPrevTxBundleTx {
			g.knownTxs.add(tx, TxStatusPending)
			return true
		}

		maxBundleTxsInPending := g.GetMaxBundleTxsInPending()
		if maxBundleTxsInPending != math.MaxUint64 {
			numExecutable := uint(g.knownTxs.numExecutable())

			numSeqTxs := uint(1)
			for i := next + 1; i < next+uint64(len(txs)); i++ {
				if tx, ok := txs[i]; ok && g.IsBundleTx(tx) {
					numSeqTxs++
				} else {
					break
				}
			}

			// false if there is possibility of exceeding max bundle tx num
			if numExecutable+numSeqTxs > maxBundleTxsInPending {
				logger.Trace("Not promoting a tx because of exceeding max bundle tx num", "tx", tx.Hash().String(), "numExecutable", numExecutable, "maxBundleTxsInPending", maxBundleTxsInPending)
				return false
			}
		}

		g.knownTxs.add(tx, TxStatusPending)
	}

	return true
}

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}

func (a *AuctionModule) Init(opts *InitOpts) error {
	if opts == nil || opts.ChainConfig == nil || opts.AuctionConfig == nil || opts.Chain == nil || opts.Backend == nil || opts.Downloader == nil || opts.NodeKey == nil {
		return auction.ErrInitUnexpectedNil
	}

	a.InitOpts = *opts

	// Note that the auction module is always disabled except CN.
	// Disable the auction module if the CN has insufficient balance.
	if !opts.AuctionConfig.Disable {
		state, err := opts.Chain.State()
		if err != nil {
			return fmt.Errorf("failed to get state: %v", err)
		}
		nodeAddr := crypto.PubkeyToAddress(opts.NodeKey.PublicKey)
		balance := state.GetBalance(nodeAddr)
		if balance.Cmp(AuctionLenderMinBal) < 0 {
			a.AuctionConfig.Disable = true
			logger.Warn("disabling auction module due to insufficient balance", "node", nodeAddr.Hex(), "balance", balance.String())
		}
	}

	a.bidPool = NewBidPool(opts.ChainConfig, opts.Chain, opts.AuctionConfig)
	if a.bidPool == nil {
		return auction.ErrInitUnexpectedNil
	}

	return nil
}

func (a *AuctionModule) RegisterGaslessModule(module gasless.GaslessModule) {
	a.gaslessModule = module

func (a *AuctionModule) IsDisabled() bool {
	return a.AuctionConfig.Disable
}
