### Title
Anonymous/unauthenticated HTTP access to DataLayer Merkle store files - (File: chia/data_layer/data_layer_server.py)

### Summary
The DataLayer HTTP static file server (`DataLayerServer`) exposes full/delta `.dat` Merkle tree files over plain, unauthenticated HTTP to any network client that can reach `host_ip:host_port` (default `0.0.0.0:8575`), mirroring the Apache Ozone S3 bug where buckets/keys were reachable via anonymous curl/HTTP requests.

### Finding Description
`DataLayerServer.start()` stands up a `WebServer` bound to `host_ip`/`host_port` with two GET routes, `file_handler` and `folder_handler`, and no SSL context, authentication middleware, or session/API-key check is installed on this server (unlike the TLS-protected `RpcServer`). [1](#0-0) 
Both handlers only validate that the requested filename conforms to the expected `store_id-node_hash-file_type-generation-version.dat` naming shape via `is_filename_valid()`, then directly open and stream the underlying file with no ownership, subscription, or access-control check tying the requester to the store. [2](#0-1) 
The default config binds this listener to `0.0.0.0` on port `8575`, i.e., all interfaces, and the module documentation explicitly notes this server "does not validate store state beyond filename shape." [3](#0-2) [4](#0-3) 
Any client that knows or brute-forces a valid `store_id`/`node_hash`/generation triple (all of which are publicly derivable from on-chain singleton launcher IDs and root hashes) can retrieve the full key/value Merkle tree contents for that DataLayer store without any credentials — functionally identical to the Ozone bug where bucket/key contents were reachable by unauthenticated HTTP/curl requests.

### Impact Explanation
DataLayer stores are used to hold structured key/value application data (e.g. NFT metadata, DID documents, or any off-chain data anchored by a DataLayer singleton), and this data is meant to be gated by subscription/mirror-plugin logic and singleton lineage — not openly downloadable to arbitrary anonymous HTTP clients. Anonymous, unauthenticated bulk retrieval of `.dat` files exposes potentially private or access-controlled key/value contents to any network party able to reach the DataLayer HTTP port, which is a data confidentiality issue matching the CVE's "unauthorized access to buckets/keys" impact.

### Likelihood Explanation
Likelihood is high for any operator running a DataLayer server with the default `host_ip: 0.0.0.0` configuration and no firewall restricting inbound access, since the vulnerability requires no credentials, no chain interaction, and no privileged access — a single unauthenticated HTTP GET to a guessed/discovered filename is sufficient.

### Recommendation
Add an authentication/authorization gate (e.g., mutual TLS matching the RPC boundary, an API key, or a store-ownership/subscription check) to `DataLayerServer.file_handler`/`folder_handler` before serving file contents, and consider defaulting `host_ip` to `127.0.0.1` rather than `0.0.0.0` unless the operator explicitly opts into public serving with the plugin/mirror trust model in mind.

### Proof of Concept
1. Start a DataLayer HTTP server with default config (`host_ip: 0.0.0.0`, `host_port: 8575`).
2. From any unauthenticated network location, run `curl http://<host>:8575/<store_id>-<node_hash>-full-<generation>-v1.0.dat` (or the `/{tree_id}/{filename}` folder route) using a filename matching the format enforced by `is_filename_valid()`.
3. The server returns the full file contents with no authentication challenge, as seen in `file_handler`/`folder_handler`, which perform only filename-shape validation before reading and returning the file. [5](#0-4)

```python
    async def file_handler(self, request: web.Request) -> web.Response:
        filename = request.match_info["filename"]
        if not is_filename_valid(filename):
            raise Exception("Invalid file format requested.")
        file_path = self.server_dir.joinpath(filename)
        with open(file_path, "rb") as reader:
            content = reader.read()
        response = web.Response(
            content_type="application/octet-stream",
            headers={"Content-Disposition": f"attachment;filename={filename}"},
            body=content,
        )
        return response

    async def folder_handler(self, request: web.Request) -> web.Response:
        tree_id = request.match_info["tree_id"]
        filename = request.match_info["filename"]
        if not is_filename_valid(tree_id + "-" + filename):
            raise Exception("Invalid file format requested.")
        file_path = self.server_dir.joinpath(tree_id).joinpath(filename)
        with open(file_path, "rb") as reader:
            content = reader.read()
        response = web.Response(
            content_type="application/octet-stream",
            headers={"Content-Disposition": f"attachment;filename={filename}"},
            body=content,
        )
        return response
```
