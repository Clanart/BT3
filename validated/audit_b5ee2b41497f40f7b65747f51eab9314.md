### Title
Ungoverned `kip71.gastarget` value of `0` causes divide-by-zero panic in Magma base-fee calculation - ([File: params/kip71_config.go])

### Summary
`kip71.gastarget` is a governance parameter with no consistency/range validation, unlike `kip71.lowerboundbasefee`/`kip71.upperboundbasefee`. A `GasTarget` of `0` is accepted by `NewVoteData`, the header-vote `checkConsistency` switch, and the format checker, exactly mirroring the external report's root cause: an out-of-range/unsupported parameter value is silently admitted because of a missing input-validation check on that specific field. When `GasTarget == 0` and any positive gas is used in a block, `KIP71Config.NextMagmaBlockBaseFee` divides by a `big.Int` set to `0`, which panics in Go's `math/big`, crashing every node that computes/verifies the next base fee (both during header verification and block assembly).

### Finding Description
`checkConsistency` in `kaiax/gov/headergov/impl/header.go` explicitly checks `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee` against each other, but for `Kip71GasTarget` (along with `Kip71BaseFeeDenominator` and `Kip71MaxBlockGasUsedForBaseFee`) it takes the fallthrough branch that returns `nil` unconditionally: [1](#0-0) 

The parameter's `FormatChecker` is a no-op and its canonicalizer only enforces the `uint64` type, not a nonzero/minimum value: [2](#0-1) 

`TestNewVoteData` confirms `Kip71GasTarget` accepts any `uint64`, and there is no bad-vote case rejecting `0`, unlike other fields: [3](#0-2) 

Once `GasTarget = 0` is committed through a governance vote (the vote-tx path exercised by `TestVerifyVote`/`checkConsistency`), it propagates into `KIP71Config.GasTarget` via `ToKip71Config`: [4](#0-3) 

The consuming function `NextMagmaBlockBaseFee` unconditionally divides by `gasTarget` in both the "used > target" and "used < target" branches, with no zero-check (unlike `BaseFeeDenominator`, which explicitly special-cases `0`): [5](#0-4) 

Specifically: `y := x.Div(x, new(big.Int).SetUint64(gasTarget))` executes `big.Int.Div` with a zero divisor, which panics in Go's `math/big` package. This function is invoked from consensus-critical paths (header verification via `VerifyMagmaHeader` and block assembly when computing the next block's base fee), so once a block with `parentGasUsed > 0` is processed after the misconfiguration, every node evaluating that header/block crashes.

### Impact Explanation
This is the direct analog of the reported bug class: an admin-set parameter that bypasses input validation (missing range/nonzero check) silently corrupts a downstream computation. Instead of causing a mispriced oracle draining a vault, here it causes a hard, network-wide node crash (denial of service / potential chain halt) on every honest node computing or verifying the KIP-71 base fee — a critical consensus/liveness impact reachable from a single governance vote due to the absent input-validation guard that exists for the sibling `LowerBoundBaseFee`/`UpperBoundBaseFee` parameters but not for `GasTarget`.

### Likelihood Explanation
Likelihood is Medium: it requires a single successful governance vote (by the governing node in single mode, or via `contractgov`) setting `kip71.gastarget` to `0`. This is a realistic misconfiguration/fat-finger scenario analogous to the external report's "admin registered an unsupported value in January that sat undetected for ~3 months" — the code path performs zero sanity checking on this specific field even though adjacent fields (`LowerBoundBaseFee`/`UpperBoundBaseFee`) are checked, indicating an inconsistent validation policy rather than a deliberate design choice.

### Recommendation
Add a `checkConsistency` (or `FormatChecker`) rule rejecting `Kip71GasTarget == 0` (and consider bounding it below `Kip71MaxBlockGasUsedForBaseFee`), matching the pattern already used for `LowerBoundBaseFee`/`UpperBoundBaseFee` in `kaiax/gov/headergov/impl/header.go`. Defensively, `NextMagmaBlockBaseFee` in `params/kip71_config.go` should guard against `gasTarget == 0` the same way it already guards against `BaseFeeDenominator == 0`, falling back to a safe default instead of dividing by zero.

### Proof of Concept
1. Governing node casts `governance.Vote("kip71.gastarget", uint64(0))`; `NewVoteData` and `checkConsistency` both accept it (no validation), and the vote is finalized at the next epoch, updating `ParamSet.GasTarget = 0`.
2. `ParamSet.ToKip71Config()` propagates `GasTarget: 0` into the active `KIP71Config`.
3. Any subsequent block with `parentHeaderGasUsed > 0` (virtually every real block) triggers `NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)`; since `parentGasUsed (>0) > gasTarget (0)`, the code executes `y := x.Div(x, new(big.Int).SetUint64(0))`, causing an immediate panic in every node that verifies the header (`VerifyMagmaHeader`) or assembles the next block, halting the chain.
