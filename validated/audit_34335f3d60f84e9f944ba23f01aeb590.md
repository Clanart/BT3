### Title
Silent, unauthenticated rewrite of a repository's git remote URL based on GitHub API data, with no user notification or confirmation - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
This is reduced from the report's broken invariant: a trust-critical parameter (there, the fee %; here, the git remote URL that determines where the user's code is pushed/fetched) can be silently changed by an external, semi-trusted party with no event emitted and no user confirmation/timelock. In GitHub Desktop, `updateRemoteUrl` rewrites the repository's `origin` remote automatically whenever the app refreshes GitHub repository metadata, based solely on the `clone_url` field returned by the GitHub API, without ever notifying the user that their remote has changed.

### Finding Description
`updateRemoteUrl` compares the local git remote URL, the previously cached `GitHubRepository.cloneURL`, and the freshly fetched `apiRepo.clone_url`, and silently calls `gitStore.setRemoteURL(...)` (which runs `git remote set-url origin <url>`) when the protocol matches and the current remote still equals the previously-cached API URL: [1](#0-0) 

This function is invoked from `repositoryWithRefreshedGitHubRepository`, which is called automatically in the background — when a repository is selected, when the active account changes, when a repository is added, and after fetch/push flows that refresh GitHub metadata — with no user interaction required: [2](#0-1) [3](#0-2) [4](#0-3) 

`GitStore.setRemoteURL` performs the git operation and only calls the generic `emitUpdate()` — a UI re-render signal, not a distinguishable "your remote just changed" notification, popup, or log entry the user is meant to notice: [5](#0-4) 

The matching logic (`urlMatchesRemote`) only compares hostname/owner/name, not full origin authority, and the guard rails (`protocolsMatch`, `remoteUrlUnchanged`) are trust decisions based entirely on data returned by the GitHub API `fetchRepository` call — an external, network-reachable data source: [6](#0-5) [7](#0-6) 

By design, the same-name-repo scenario (repository transferred/renamed, or a user's repo slot reused by another party after rename/deletion) or a compromised/spoofed GitHub Enterprise Server endpoint can cause `apiRepo.clone_url` to point at an attacker-controlled URL while `protocolsMatch` and `remoteUrlUnchanged` still hold for any user who has not manually customized their remote (the common case for anyone who cloned via Desktop). There is no explicit code path here that authenticates that the "new" clone_url actually still refers to the same underlying repository object (e.g., no ID comparison — the code only re-parses and string-compares hostname/owner/name).

### Impact Explanation
If exploited, the local `origin` remote silently changes to an attacker-controlled URL. Subsequent `git push` operations from the user will exfiltrate their commits/code to the attacker's endpoint; subsequent `git fetch`/`git pull` and merges will pull attacker-provided history and content into the user's working tree and future commits — a silent corruption of what the user pushes/fetches, exactly the "valid impact" category called out (silent corruption of what the user commits/pushes, without needing local access, malware, or leaked credentials). There is no popup like `UpstreamAlreadyExists` (which does ask before changing the `upstream` remote) guarding this `origin`/default-remote change path — that dialog only exists for the upstream-fork-remote flow, not for this default-remote sync flow: [8](#0-7) 

### Likelihood Explanation
The refresh path runs automatically and frequently (on every repository selection, account-change refresh, and add-repository flow), requiring zero user interaction beyond normal app usage. The trigger condition (remote URL still matches the last known API clone_url, and protocol unchanged) holds for the overwhelming majority of users, since Desktop itself is what set up the remote originally from the API's clone_url. The main constraint is obtaining a scenario where the GitHub API returns a differing `clone_url` for what the app still associates as "the same" `GitHubRepository` record (e.g., repository rename/ownership-transfer interactions, or a compromised/MITM'd GHES endpoint) — a real but not certain condition, so likelihood is Medium rather than High.

### Recommendation
- Emit a distinct, user-visible event/notification whenever `setRemoteURL` is invoked as a side effect of an automatic background refresh (as opposed to the user manually editing the remote in Repository Settings), analogous to the report's recommendation to `Emit` an event for fee changes.
- Require explicit user confirmation before silently rewriting `origin`, mirroring the existing `UpstreamAlreadyExists` dialog pattern used for the `upstream` remote.
- Strengthen the trust check beyond hostname/owner/name string matching (e.g., verify the GitHub repository's stable numeric ID from the API response matches the previously stored `GitHubRepository` ID) before treating a `clone_url` change as legitimate.
- Consider a cooldown/timelock before applying an automatically-detected remote URL change, giving the user a chance to notice and react, consistent with the report's core recommendation.

### Proof of Concept
1. User adds/clones a repository through Desktop; `origin` is set to `https://github.com/owner/repo` and `GitHubRepository.cloneURL` is cached as the same value.
2. Through a scenario where the API's `clone_url` for the same locally-tracked GitHub repository record subsequently differs (e.g., repository renamed and the name later reused by a different/malicious repository, or a GHES/network-level response spoof), the next background refresh calls `repositoryWithRefreshedGitHubRepository` → `updateRemoteUrl`.
3. `remoteUrlUnchanged` is true (user's remote still matches the previously cached `cloneURL`), `protocolsMatch` is true (both `https`), and `urlsMatch` is false (new URL differs) — `gitStore.setRemoteURL(...)` fires silently: [9](#0-8) 
4. The user's next `git push`/`git fetch` transparently targets the new (potentially attacker-controlled) remote with no dialog, event, or log entry surfaced to the user.

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}

  public async fetchRepository(
    owner: string,
    name: string
  ): Promise<IAPIFullRepository | null> {
    try {
      const response = await this.ghRequest('GET', `repos/${owner}/${name}`)
      if (response.status === HttpStatusCode.NotFound) {
        log.warn(`fetchRepository: '${owner}/${name}' returned a 404`)
        return null
      }
      return await parsedResponse<IAPIFullRepository>(response)
    } catch (e) {
      log.warn(`fetchRepository: an error occurred for '${owner}/${name}'`, e)
      return null
    }
  }
