### Title
Empty aggregate signature verifies successfully for an empty signer set - (File: crypto/schnorr/src/aggregate.rs)

### Summary
`SchnorrAggregate::verify` accepts an aggregate with zero nonce points when the supplied signer/challenge list is also empty. A serialized proof consisting only of a zero `Rs` length and a canonical zero scalar therefore verifies as a valid aggregate signature.

### Finding Description
`SchnorrAggregate::read` parses an attacker-controlled 32-bit count, allows that count to be zero, and then reads `s` as a canonical scalar without rejecting zero. [1](#0-0) 

During verification, zero `Rs` values match an empty `keys_and_challenges` slice. The loop queues no signature terms, leaving only `(-s)G`; with `s = 0`, that term is the identity and the multiexponentiation succeeds. [2](#0-1) 

The signing-side API explicitly treats empty aggregation as invalid by returning `None` from `SchnorrAggregator::complete`, but the deserializer and verifier do not enforce the same invariant. [3](#0-2) 

### Impact Explanation
If a caller accepts `SchnorrAggregate` bytes and passes an empty signer set to `verify`, an unprivileged party can forge acceptance without any private key, nonce, signature share, or challenge interaction. This is a forged aggregate signature for an unintended empty authorization set.

### Likelihood Explanation
The attack requires an application to authorize an operation with an empty expected-signer list. The library does not itself reject that case, and the asymmetric behavior between `complete`, `read`, and `verify` makes the invalid object easy to construct from public input bytes.

### Recommendation
Reject empty aggregates in `SchnorrAggregate::read` and defensively reject an empty `keys_and_challenges` slice in `SchnorrAggregate::verify`. Verification should fail before evaluating the multiexponentiation when either side is empty.

### Proof of Concept
Conceptually, for a ciphersuite whose scalar encoding is 32 zero bytes:

```rust
let mut encoded = Vec::new();
encoded.extend([0; 4]); // Rs length = 0
encoded.extend([0; 32]); // canonical scalar s = 0

let aggregate =
  SchnorrAggregate::<C>::read(&mut encoded.as_slice()).unwrap();

assert!(aggregate.verify(dst, &[]));
```

The assertion follows because `Rs.len() == keys_and_challenges.len() == 0`, no weighted signature statements are queued, and `-0 * G` is the identity.
