Based on my research, I found a concrete analog to the reported bug class in the `kaiax/gasless` module and the `GaslessSwapRouter` (KIP-247) contract, where an owner-controlled address-mapping update can be used to front-run pending gasless swap transactions from unprivileged users.

Caveat: the Solidity source of `GaslessSwapRouter` itself is not indexed in this repo snapshot (only the compiled bytecode/Go bindings at `contracts/bindings/kip247/GaslessSwapRouter.go` and the runtime bytecode constant are available) [1](#0-0) . I was unable to inspect the exact internal logic of `swapForGas` to confirm whether the newly set `router`/`factory` are invoked with custody of user funds inside the same transaction. If the user needs to confirm this reasoning, a Devin session with full repo access should be used to pull the actual Solidity source.

### Title
Gasless swap router owner can front-run pending gasless swap bundles via `addToken` - ([File: kaiax/gasless/impl/getter.go])

### Summary
The `GaslessSwapRouter` contract exposes an owner-only `addToken(token, factory, router)` function that rebinds the DEX `factory`/`router` used to execute gasless swaps for a given ERC20 token [1](#0-0) . The `kaiax/gasless` module reads this live on-chain state every block via `getGaslessInfo`/`MultiCallGaslessInfo` to determine the trusted `swapRouter` and `allowedTokens` used to validate and execute users' gasless `ApproveTx`+`SwapTx` bundles [2](#0-1) .

### Finding Description
Gasless users submit a bundle consisting of an `ApproveTx` (max-approval to the `GaslessSwapRouter`) followed by a `SwapTx` calling `swapForGas(token, amountIn, minAmountOut, amountRepay, deadline)` [3](#0-2) [4](#0-3) . The router validation only checks that `tx.to` matches the currently registered `swapRouter` and that the token is in `allowedTokens`, both of which are pulled from live contract state at each block [5](#0-4) .

Because these bundles are visible in the mempool before inclusion (analogous to the `Multicall` front-running scenario in the referenced report), the contract `owner` of `GaslessSwapRouter` can observe a pending `ApproveTx`/`SwapTx` bundle and submit an `addToken(token, maliciousFactory, maliciousRouter)` transaction ahead of it. This is the same owner-only, unbounded-address-update primitive flagged in the external report (`setNewAddresses` in `Swap`/`Aave`), applied here to the token→(factory, router) mapping consumed by every subsequent `swapForGas` call for that token.

### Impact Explanation
If the owner rebinds a token to a malicious `factory`/`router` pair immediately before a user's `swapForGas` executes, the swap logic will route through attacker-controlled contracts while the user has already granted max-allowance to the `GaslessSwapRouter` [6](#0-5)  (see `addToken` usage in the test setup, mirroring production usage). This can result in the user's tokens being pulled and the returned "for-gas" KAIA/WKAIA being diverted or reduced, directly harming an unprivileged gasless-tx sender who has no way to prevent the owner's front-run.

### Likelihood Explanation
Low-to-Medium: it requires the `GaslessSwapRouter` owner (or a compromised owner key) to actively front-run, similar to the original report's likelihood assessment for `Swap`/`Aave`. This is only reachable in the context of the gasless module's own registered router (per KIP-247), which is an in-scope Kaia system contract path reachable by any public gasless-tx submitter.

### Recommendation
Restrict or remove the ability to arbitrarily rebind an already-listed token's `factory`/`router` without a timelock or without invalidating in-flight approvals, e.g., require existing allowances/pending bundles to complete before an `addToken` update take effect, or require that `addToken` for an existing token can only be called through a delayed governance/registry-activation mechanism such as the block-delayed `Registry.register` pattern already used elsewhere in the system (`system.RegistryAddr`/`Register(..., targetBlockNum)`) [7](#0-6) , so the update is not immediately effective in the same block as pending user transactions.

### Proof of Concept
1. User submits `ApproveTx` granting max allowance of `TokenX` to `GaslessSwapRouter`, followed by `SwapTx` calling `swapForGas(TokenX, amountIn, minAmountOut, amountRepay, deadline)`.
2. Both transactions are visible in the mempool/bundle before block inclusion.
3. `GaslessSwapRouter` owner submits `addToken(TokenX, maliciousFactory, maliciousRouter)` with higher priority to be included before the user's bundle, as demonstrated by the same call pattern used in test setup [6](#0-5) .
4. When the user's `swapForGas` executes, it operates against the newly-set malicious `factory`/`router`, potentially resulting in the user losing `TokenX` value while receiving little or no KAIA/WKAIA in return.

// IsApproveTx checks following conditions:
// A1. tx.to is a whitelisted ERC20 token.
// A2. tx.data is `approve(spender, amount)`.
// A3. spender is a whitelisted SwapRouter contract.
// A4. amount is MaxUint.
func (g *GaslessModule) IsApproveTx(tx *types.Transaction) bool {
	args, ok := decodeApproveTx(tx, g.signer)
	return ok && g.isApproveTx(args)
}

func (g *GaslessModule) isApproveTx(args *ApproveArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.allowedTokens[args.Token] && // A1
		g.swapRouter == args.Spender && // A3
		args.Amount.Cmp(abi.MaxUint256) == 0 // A4
}

func decodeSwapTx(tx *types.Transaction, signer types.Signer) (args *SwapArgs, ok bool) {
	to, inputs, ok := decodeFunctionCall(tx, routerSwapFunc)
	if !ok {
		return nil, false
	}
	token, ok := inputs["token"].(common.Address)
	if !ok {
		return nil, false
	}
	amountIn, ok := inputs["amountIn"].(*big.Int)
	if !ok {
		return nil, false
	}
	minAmountOut, ok := inputs["minAmountOut"].(*big.Int)
	if !ok {
		return nil, false
	}
	amountRepay, ok := inputs["amountRepay"].(*big.Int)
	if !ok {
		return nil, false
	}
	deadline, ok := inputs["deadline"].(*big.Int)
	if !ok {
		return nil, false
	}
	from, err := types.Sender(signer, tx)
	if err != nil {
		return nil, false
	}
	return &SwapArgs{
		Sender:       from,
		Router:       to,
		Token:        token,
		AmountIn:     amountIn,
		MinAmountOut: minAmountOut,
		AmountRepay:  amountRepay,
		Deadline:     deadline,
	}, true
}

func (g *GaslessModule) updateAddresses(header *types.Header) error {
	g.gaslessInfoMu.Lock()
	defer g.gaslessInfoMu.Unlock()

	swapRouter, tokens, err := getGaslessInfo(g.Chain, header)
	// proceed even if there is something wrong with multicall contract
	if err != nil {
		g.swapRouter = common.Address{}
		g.allowedTokens = map[common.Address]bool{}
		logger.Warn("there is something wrong with multicall contract", "err", err.Error())
		return nil
	}

	g.swapRouter = swapRouter

	g.allowedTokens = map[common.Address]bool{}
	for _, addr := range tokens {
		// all tokens are allowed if nil
		if g.GaslessConfig.AllowedTokens == nil {
			g.allowedTokens[addr] = true
		}
		for _, allowed := range g.GaslessConfig.AllowedTokens {
			if addr == allowed {
				g.allowedTokens[addr] = true
			}
		}
	}

	return nil
}
