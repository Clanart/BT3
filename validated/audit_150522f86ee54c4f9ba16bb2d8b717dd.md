### Title
Payout OP_RETURN operator attribution is not covered by the user's withdrawal signature, allowing a third party to mint fraudulent reimbursement credit for an operator that never funded the payout - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
`create_payout_txhandler` signs only the withdrawal input with the user's `SinglePlusAnyoneCanPay` (SIGHASH_SINGLE|ANYONECANPAY) signature, which by definition only commits to input #0 and the output at the same index (#0, the user payout). The OP_RETURN output (#2) that records `operator_xonly_pk` — the value the whole reimbursement pipeline (`update_finalized_payouts`, `is_kickoff_malicious`, `validate_payer_is_operator`, `get_first_unhandled_payout_by_operator_xonly_pk`) trusts as "who fronted this payout" — is not covered by that signature.

### Finding Description [1](#0-0)  constructs the `Payout` transaction with a single signed input (the dust withdrawal UTXO, spent via `SpendPath::KeySpend` using `user_sig`) and three outputs: the user payout, an anchor, and an `op_return_txout` carrying `operator_xonly_pk.serialize()`. The comment even documents the sighash requirement ("Ensure the signature uses SinglePlusAnyoneCanPay sighash type") in `operator.rs`: [2](#0-1) 

Because SIGHASH_SINGLE only binds the output whose index matches the spent input's index (index 0 here), and ANYONECANPAY only binds the single signed input, none of the signature covers output #2 (OP_RETURN). Consequently, whoever actually broadcasts/funds the transaction (via `fund_raw_transaction` / RBF, see `core/src/operator.rs:652-674` and `crates/clementine-tx-sender/src/rbf.rs`) can freely choose the operator_xonly_pk placed in the OP_RETURN, independent of who owns `user_sig`.

Downstream, this OP_RETURN value is the sole source of truth for crediting an operator with having fronted a withdrawal:
- `update_finalized_payouts` parses OP_RETURN straight from the confirmed block and writes it as `payout_payer_operator_xonly_pk` in the DB: [3](#0-2) 
- `get_first_unhandled_payout_by_operator_xonly_pk` later selects payouts to reimburse by matching against this stored value: [4](#0-3) 
- `validate_payer_is_operator` in the reimbursement-tx-fetch path checks only that the stored payer key equals the local operator key, with no independent proof that this operator's wallet actually funded the payout: [5](#0-4) 
- `is_kickoff_malicious` treats a matching OP_RETURN key as proof of legitimacy: [6](#0-5) 

The binding that should hold is: `party whose Bitcoin wallet funded the payout output == operator_xonly_pk recorded in OP_RETURN == operator credited/reimbursed via kickoff/Reimburse tx`. Because the OP_RETURN is unauthenticated, an unprivileged party who obtains the user's registered withdrawal signature (which is registered on the Citrea bridge contract and handed to operators off-chain per the RPC docs, `core/src/rpc/clementine.proto:391-405`) can construct and broadcast their own variant of the payout transaction — with the identical signed input/output pair required by the sighash — but stamping an arbitrary `operator_xonly_pk` into the OP_RETURN, and fund the tx from their own wallet. Whoever's wallet actually front-loads the BTC via `fund_raw_transaction`/RBF controls which operator receives protocol credit, but nothing in the txhandler or in `update_finalized_payouts` verifies that the credited operator is the entity whose UTXOs paid the additional funding inputs.

### Impact Explanation
This breaks the "operator credited versus the party that paid" binding: an operator whose xonly pubkey ends up in the OP_RETURN of someone else's broadcast payout tx is now the target of `get_first_unhandled_payout_by_operator_xonly_pk` and will attempt reimbursement (kickoff/asserts/Reimburse tx) for BTC it never actually spent, or — if it never intends to claim — the withdrawal is permanently marked with an attribution that is unfalsifiable on-chain, since the "proof" the whole reimbursement/dispute machinery relies on (`is_kickoff_malicious`, `send_asserts`'s `payout_op_xonly_pk` check) is exactly this spoofable OP_RETURN. In the confirmed BakerFi bug class terms, this is the "operator credited versus the party that paid" binding broken by an unauthenticated write to state that downstream custody logic (`Reimburse`/`Kickoff`) trusts.

### Likelihood Explanation
Exploitation requires only knowledge of the user's off-chain `SinglePlusAnyoneCanPay` withdrawal signature (already disseminated to "operators" per design, and also embedded in the aggregator's `WithdrawParams` flow for optimistic payouts) plus the ability to broadcast a standard Bitcoin transaction with wallet funding — no verifier, operator, or aggregator privileged role is needed to construct or sign the malicious OP_RETURN itself, since sighash coverage simply doesn't extend to that output. However, I was not able to fully verify in the available index whether some additional protocol-level gate (e.g., a mempool-acceptance policy, a whitelist on who is allowed to fund/broadcast payout txs, or a requirement that the withdrawal UTXO's funding path is restricted to operator-controlled wallets by construction elsewhere) closes this gap; the dust withdrawal UTXO's origin/ownership model and exactly how "any wallet" vs. "only registered operator wallets" could reach `fund_raw_transaction` for a given payout tx were not conclusively confirmed from the code paths I could inspect within the given iterations.

### Recommendation
Bind `operator_xonly_pk` (and any other payout metadata used for reimbursement attribution) to the same signature domain that authorizes spending of the withdrawal UTXO, e.g. by using SIGHASH_ALL (or SIGHASH_SINGLE covering an output that itself commits to a hash of all outputs) for the funding operator's own contribution, or by requiring an additional operator-signed attestation (covering OP_RETURN content) that is independently verified in `update_finalized_payouts`/`validate_payer_is_operator` before crediting reimbursement.

### Proof of Concept
Not independently reproducible from the static index alone (would require a running regtest harness). Conceptually:
1. Obtain the user's registered `SinglePlusAnyoneCanPay` signature for withdrawal index `N` (available via Citrea bridge contract / off-chain to operators).
2. Build a `Payout` tx per `create_payout_txhandler`, using the correct input/output (matching the sighash) but insert an arbitrary `operator_xonly_pk_target` (an operator that did not fund it) into the OP_RETURN output.
3. Fund/broadcast this tx from any Bitcoin wallet (not `operator_xonly_pk_target`'s).
4. Observe `update_finalized_payouts` (`core/src/verifier.rs:2283-2353`) recording `operator_xonly_pk_target` as `payout_payer_operator_xonly_pk` for withdrawal `N`, and `get_first_unhandled_payout_by_operator_xonly_pk` subsequently surfacing this withdrawal for `operator_xonly_pk_target`'s `PayoutCheckerTask` to process as if it had fronted the payout.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

        tracing::info!(
            "Payer xonly pk, payout blockhash and kickoff txid found and valid for own operator for the requested deposit id: {}, payer xonly pk: {:?}, payout blockhash: {:?}, kickoff txid: {:?}",
            deposit_id,
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid
        );

        Ok((payout_blockhash, kickoff_txid))
    }

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }
