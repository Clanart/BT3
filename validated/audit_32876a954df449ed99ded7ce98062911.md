### Title
Forged discovery response makes an untrusted git remote pass as "GitHub Enterprise", steering the user's sign-in credentials to an attacker-controlled endpoint - (File: `app/src/lib/api.ts`, `app/src/lib/endpoint-capabilities.ts`, `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
`isGitHubHost()` classifies an unknown git host as a trusted GitHub Enterprise instance based on response headers it fully controls (`x-github-request-id`, `x-github-enterprise-version`), and the version it reads is cached to `localStorage` forever with no expiry or re-validation, just like the Venus `setDirectPrice()` override that is "given priority... and never becomes stale." A malicious git remote can trip this check once and get permanently classified as an enterprise host, after which GitHub Desktop's credential helper routes the user into a "GitHub sign-in" flow that navigates to the attacker's own server for OAuth authorization.

### Finding Description
`isGitHubHost()` performs a best-effort discovery request and short-circuits trust in two attacker-reachable ways: [1](#0-0) 

1. If a version was previously cached for the endpoint, it returns `true` immediately without any live check: `if (getEndpointVersion(endpoint) !== null) return true`.
2. Otherwise it issues a `HEAD /meta` request and trusts it as a GitHub host purely because the response has an `x-github-request-id` header — a header the remote server (attacker) can freely set: `return response.headers.has('x-github-request-id')`.

The version used for the cache short-circuit comes straight from a response header, with no authenticity check, and is persisted indefinitely: [2](#0-1) [3](#0-2) 

This is the exact bug class from the report: a value supplied by an untrusted/unverified source (`setDirectPrice` ⇄ attacker-controlled `x-github-enterprise-version`/`x-github-request-id` headers) is given priority over — or entirely substitutes for — a proper trust decision, and it never expires (`versionCache`/`localStorage` have no TTL, mirroring "the price never becomes stale").

This classification directly drives credential/authentication routing in the trampoline credential helper, which decides whether an unknown host is `'enterprise'`, `'github.com'`, or `'generic'`: [4](#0-3) 

When `endpointKind !== 'generic'` and no existing account matches that endpoint, Desktop prompts the user to sign in to "GitHub"/"GitHub Enterprise" for that exact endpoint: [5](#0-4) 

`promptForGitHubSignIn` then opens the real Desktop sign-in UI pointed at the attacker's `endpoint` (since `hostname !== 'github.com'`, it calls `beginEnterpriseSignIn` and `setSignInEndpoint(origin)`): [6](#0-5) 

The subsequent OAuth authorize URL and token exchange are built directly from that attacker-controlled `endpoint`: [7](#0-6) 

Because `getOAuthAuthorizationURL`/`requestOAuthToken` use `getHTMLURL(endpoint)` as the base, both the authorization page the user is sent to and the token-exchange POST (containing `client_id`/`client_secret`/authorization `code`) go to the attacker's server, not to real GitHub infrastructure.

### Impact Explanation
An attacker who merely operates a git remote/proxy that the user clones, fetches, or pushes to can:
- Forge a single HTTP header (`x-github-request-id`, trivial to add) on the `/meta` discovery probe, or a `WWW-Authenticate` header advertising `realm="GitHub"` in the git auth challenge, to be classified as an "enterprise" GitHub host — permanently, since successful `x-github-enterprise-version` values are cached with no expiry (`updateEndpointVersion`/`localStorage`).
- Get Desktop's own trusted "Sign in to GitHub Enterprise" dialog to load and interact with the attacker's server as if it were the user's real Enterprise instance, phishing username/password or hosted-SSO credentials, and receiving the OAuth `client_id`/`client_secret`/authorization `code` directly in the token-exchange request.

This matches the valid impact class: attacker controls a git remote/proxy response, and the result is unauthorized OAuth flow direction / credential exfiltration for an unprivileged user simply interacting with a hostile repository — no local access, malware, or leaked credentials required.

### Likelihood Explanation
Any git clone/fetch/push against a repository hosted by the attacker triggers the trampoline credential helper's `getEndpointKind`/`isGitHubHost` path when no existing account matches that endpoint, which is the common case for a brand-new/unknown remote. Setting a response header is trivial for anyone who controls the server. The main uncertainty (not fully verifiable from the index) is the exact UX friction in the resulting `SignIn` popup (e.g., whether the displayed host name gives the user a chance to notice it isn't real GitHub) — this affects how convincing the phishing is but does not change that the app itself, not the user, chose to trust and route to the attacker endpoint based on a forged header.

### Recommendation
- Never let a single unauthenticated header (`x-github-request-id`) or a persisted-without-expiry version cache be sufficient to classify a host as a trusted GitHub/Enterprise endpoint for the purposes of *initiating an authentication/OAuth flow*. Require re-validation (e.g., TLS-pinned/allow-listed enterprise endpoints, or explicit user confirmation) before routing to a "Sign in" dialog for a previously-unknown host.
- Apply a staleness window to `updateEndpointVersion`/`versionCache` similar to other TTL caches in the codebase (e.g., `ExpiringOperationCache`), rather than storing it in `localStorage` indefinitely.
- Surface the concrete endpoint URL prominently in the `SignIn`/OAuth dialogs triggered from the credential helper so users can detect a mismatch before entering credentials.

### Proof of Concept
1. Attacker hosts a git-over-HTTPS repository at `https://evil.example.com/foo.git` and configures the server to respond to Desktop's discovery `HEAD /meta?ghd=...` request with header `x-github-request-id: 1`.
2. Victim adds/clones this remote in GitHub Desktop and performs any git operation requiring auth (private repo, push, etc.), which invokes the credential helper's `get` command.
3. `getEndpointKind` finds no `wwwauth` GitHub realm, no existing account, falls through to `isGitHubHost('https://evil.example.com')`, which returns `true` because of the forged header (`app/src/lib/api.ts:2483`).
4. `getCredential` sees `endpointKind !== 'generic'` and no matching account, so it calls `ui.promptForGitHubSignIn('https://evil.example.com/foo.git')`.
5. `promptForGitHubSignIn` calls `beginEnterpriseSignIn` + `setSignInEndpoint('https://evil.example.com')`, and the `SignIn` popup navigates the user through OAuth authorize/token-exchange requests built from `getHTMLURL('https://evil.example.com')` — i.e., entirely served/controlled by the attacker (`app/src/lib/api.ts:2357-2395`).
6. The attacker's server receives whatever the user submits during that flow (credentials, or the `client_id`/`client_secret`/`code` sent to its fake `/login/oauth/access_token` endpoint).

/** Stores raw x-github-enterprise-version headers keyed on endpoint */
const rawVersionCache = new Map<string, string>()

/** Stores parsed x-github-enterprise-version headers keyed on endpoint */
const versionCache = new Map<string, semver.SemVer | null>()

/** Get the cache key for a given endpoint address */
const endpointVersionKey = (ep: string) => `endpoint-version:${ep}`

/**
 * Whether or not the given endpoint belongs to GitHub.com
 */
export const isDotCom = (ep: string) => {
  if (ep === getDotComAPIEndpoint()) {
    return true
  }

  const { hostname } = new URL(ep)
  return hostname === 'api.github.com' || hostname === 'github.com'
}

export const isGist = (ep: string) => {
  const { hostname } = new URL(ep)
  return hostname === 'gist.github.com' || hostname === 'gist.ghe.io'
}

/** Whether or not the given endpoint URI is under the ghe.com domain */
export const isGHE = (ep: string) => new URL(ep).hostname.endsWith('.ghe.com')

/**
 * Whether or not the given endpoint URI appears to point to a GitHub Enterprise
 * Server instance
 */
export const isGHES = (ep: string) => !isDotCom(ep) && !isGHE(ep)

export function getEndpointVersion(endpoint: string) {
  const key = endpointVersionKey(endpoint)
  const cached = versionCache.get(key)

  if (cached !== undefined) {
    return cached
  }

  const raw = localStorage.getItem(key)
  const parsed = raw === null ? null : semver.parse(raw)

  if (parsed !== null) {
    versionCache.set(key, parsed)
  }

  return parsed
}

/**
 * Update the known version number for a given endpoint
 */
export function updateEndpointVersion(endpoint: string, version: string) {
  const key = endpointVersionKey(endpoint)

  if (rawVersionCache.get(key) !== version) {
    const parsed = semver.parse(version)
    localStorage.setItem(key, version)
    rawVersionCache.set(key, version)
    versionCache.set(key, parsed)
  }
}

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)

    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
