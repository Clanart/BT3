### Title
Shared `CallDispatcher` lets an attacker's `placeOrder` predispatch sweep credit itself with any un-swept residual token balance left by another app's `dispatch()` call - (File: `evm/src/apps/IntentGatewayV2.sol`)

### Summary
`IntentGatewayV2.placeOrder`'s predispatch flow measures how much of an input token to escrow by reading `IERC20(token).balanceOf(dispatcher)` on the shared `CallDispatcher` and treating anything at or above `order.inputs[i].amount` as "received," exactly the same pattern as the LiFi `swap()` bug where `LibAsset.getOwnBalance(fromAssetId) < fromAmount` let a caller skip the actual funding transfer whenever the shared contract already held a sufficient balance.

### Finding Description
In `placeOrder`, when `order.predispatch.call.length > 0 && order.predispatch.assets.length > 0`, the gateway:
1. Transfers the caller's declared `predispatch.assets` into the shared `_params.dispatcher` (`CallDispatcher`).
2. Executes attacker-supplied `order.predispatch.call` via `ICallDispatcher(dispatcher).dispatch(...)`.
3. For each `order.inputs[i]`, reads `balance = IERC20(token).balanceOf(dispatcher)` and only checks `balance < requiredAmount` before sweeping `balance` back to the gateway and crediting escrow up to `order.inputs[i].amount`. [1](#0-0) 

The check is identical in spirit to the LiFi bug: it never verifies that the swept amount was actually contributed by `msg.sender` in this call — it only verifies that the dispatcher's *total current balance* for that token is large enough. `CallDispatcher` is a generic, stateless, permissionless executor with no access control and a payable `receive()`, and is reused as `_dispatcher`/`_params.dispatcher` across multiple apps (e.g. `HyperFungibleTokenUpgradeable.onAccept` also invokes `ICallDispatcher(_dispatcher).dispatch(message.data)` with attacker/relayer-influenced `message.data`, and never sweeps residual balances left on the dispatcher afterward). [2](#0-1) [3](#0-2) 

Because `CallDispatcher` never tracks per-caller balances and any ERC20 `transfer()` to it — whether from a mis-sent user transaction, dust left by another app's `dispatch()` call, or tokens that land there as the byproduct of an unrelated `message.data` execution that is never swept by that other flow — simply increases `balanceOf(dispatcher)`, any subsequent `placeOrder` predispatch sweep from *any* caller will happily count that balance toward the caller's own `order.inputs[i].amount`, exactly the "unaccounted ERC20 balance could be freely taken" condition from the LiFi report.

### Impact Explanation
An unprivileged attacker can escrow an order input "for free" whenever the shared `CallDispatcher` holds a latent token balance it should not (dust from another app's non-sweeping `dispatch()` call, e.g. `HyperFungibleTokenUpgradeable.onAccept`, or simple misdirected transfers). The attacker's `order.inputs[i].amount` is then backed by funds that never came from them, letting them claim a solver's/protocol's output tokens once the (now-inflated) input escrow is honored — a false state/loss-of-funds outcome matching the bounty's "stealing or loss of funds" and "transaction manipulation" categories. The same-chain `_execute()` sweep path in `IntentsBase.sol` has the same full-balance-sweep shape. [4](#0-3) 

### Likelihood Explanation
The attacker primitive is fully public and requires no privileged actor: calling `placeOrder` with `predispatch.call`/`predispatch.assets` set is a normal, unprivileged entrypoint, and `CallDispatcher` accepts arbitrary inbound token transfers with no owner check. The only prerequisite is that a nonzero residual balance exists on the dispatcher for the targeted token at the time of the attacker's call — a condition that can arise from ordinary operational dust (the shared dispatcher is used by multiple flows across the protocol, and at least one of them, `HyperFungibleTokenUpgradeable.onAccept`, never sweeps after `dispatch()`), not from a compromised relayer/prover/admin.

### Recommendation
Do not use `balanceOf(dispatcher)` as the trust signal for "amount received." Instead:
- Snapshot the dispatcher's per-token balance immediately before transferring `predispatch.assets`/dispatching calls, and compute `received = balanceAfter - balanceBefore` (the same delta pattern already used a few lines later in the same function for crediting `order.inputs[i].amount`, but currently only applied *after* the sweep, not to gate the sweep amount itself).
- Ensure every app that routes tokens through the shared `CallDispatcher` (including `HyperFungibleTokenUpgradeable.onAccept`) sweeps 100% of any residual balance back to a safe, attributable destination (or reverts if nonzero) immediately after `dispatch()`, so no cross-app dust can accumulate on the shared executor.

### Proof of Concept
1. Some other flow using the same `CallDispatcher` instance (e.g. a cross-chain `HyperFungibleTokenUpgradeable.onAccept` message whose `message.data` results in the dispatcher itself ending up holding `Y` units of token `T`, since `onAccept` never sweeps after `dispatch(message.data)`) leaves `IERC20(T).balanceOf(dispatcher) == Y > 0`.
2. Attacker calls `IntentGatewayV2.placeOrder(order, ...)` with:
   - `order.predispatch.assets = [{token: someThrowawayToken, amount: 1}]` (minimal real transfer, only to satisfy `predispatch.assets.length > 0`).
   - `order.predispatch.call` = a harmless no-op call to a benign contract (only to satisfy `predispatch.call.length > 0`).
   - `order.inputs = [{token: T, amount: Y}]`.
3. In the predispatch sweep loop, `balance = IERC20(T).balanceOf(dispatcher) == Y >= requiredAmount (Y)`, so the check passes without the attacker ever contributing `T` to the dispatcher. [5](#0-4) 
4. `transferCalls` sweeps the full `Y` of `T` from dispatcher to the gateway, and `order.inputs[0].amount` is credited as `Y` received, escrowing `Y` of `T` under the attacker's order for free. [6](#0-5)

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {
            Call[] memory finalCalls = new Call[](sweepCount);
            for (uint256 i; i < sweepCount;) {
                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
    }
