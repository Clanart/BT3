### Title
Regex-based GitHub host detection in the credential-helper trusts attacker-controlled hostnames as "GitHub Enterprise" - (`app/src/lib/api.ts`, `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The seed report's broken invariant is a hardcoded constant (`BLOCK_PERIOD = 13 seconds`) that stands in for a real, protocol-defined value and is silently wrong, causing a security-relevant calculation (`PRIORITY_EXPIRATION`) to be off by a meaningful margin. The Desktop analog is a hardcoded *heuristic* standing in for real host verification: `isGitHubHost()` classifies any hostname that merely matches the regex `/(^|\.)(github)\./` as a legitimate GitHub host, even though this is not the actual GitHub domain.

### Finding Description
`isGitHubHost()` in [1](#0-0)  determines whether a URL "belongs to a GitHub host" using string/regex heuristics rather than strict origin comparison against known GitHub endpoints:

```
// github.example.com,
if (/(^|\.)(github)\./.test(hostname)) {
  return true
}
```

This matches any hostname where a label equal to `github` appears, including fully attacker-registered domains such as `github.attacker.com` or `sub.github.attacker.com`. The only prior checks are exact matches for `github.com`/`api.github.com` and a small hardcoded `knownThirdPartyHosts` denylist (`dev.azure.com`, `gitlab.com`, `bitbucket.org`, `amazonaws.com`, `visualstudio.com`) — see [2](#0-1) . Anything not on that short denylist and matching the `github.` regex is treated as trustworthy.

This heuristic feeds directly into the git credential helper's trust decision in `getEndpointKind()`: [3](#0-2) . When none of the earlier exact checks (`isGist`, `isDotCom`, `isGHE`, `WWW-Authenticate` header, existing exact-origin account match) apply, the code falls back to:

```js
return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
```

Once an endpoint is classified as `'enterprise'` (i.e., not `'generic'`), `getCredential()` treats it as a first-party GitHub endpoint: [4](#0-3) . If Desktop has no account for that literal endpoint, it actively prompts the user with the "Sign in to GitHub" dialog (`ui.promptForGitHubSignIn(endpoint)`), and suppresses use of the generic/external credential helper for that host (`if (endpointKind !== 'generic') return undefined`).

### Impact Explanation
Just as the incorrect `BLOCK_PERIOD` constant caused a security parameter (expiration) to be computed against the wrong reference value, this heuristic causes Desktop's "is this GitHub" trust decision to be computed against an attacker-influenceable string pattern instead of the actual authoritative signal (verified TLS/DNS identity or exact known endpoints). A remote a user clones/fetches from (which the attacker fully controls, satisfying the "attacker controls a git remote" impact criterion) can be hosted at a domain that matches the regex (e.g. `github.<attacker-domain>`), causing Desktop's own git credential helper to:
- Present the "Sign in to GitHub" dialog for what is actually not GitHub, lending false legitimacy to an attacker's host during an OAuth/browser-based sign-in flow, and
- Refuse to route the host through Desktop's generic credential storage path, changing credential handling behavior in a way the user does not expect.

This aligns with the "unauthorized OAuth or account binding" and "credential exfiltration" categories in the given valid-impact list, since a misclassified attacker host can trigger Desktop's own GitHub sign-in UI against a non-GitHub server.

### Likelihood Explanation
Exploitation requires the attacker to register/host a domain whose hostname contains a `github` label (e.g., `github.example-attacker.tld`) and get a user to clone/add that remote in Desktop, then have git attempt authentication against it. Existing guards (`isDotCom`, `isGHE`, exact-origin matching in `findGitHubTrampolineAccount`, and the small `knownThirdPartyHosts` denylist) do not stop this path because none of them validate that the `github.` substring match in `isGitHubHost` actually corresponds to a real, trusted GitHub deployment — the check is purely lexical on the hostname, not tied to TLS identity, DNS ownership, or an allowlist of enterprise endpoints the user has configured. Because it still requires the user to interact with a malicious remote and, in the worse case, to complete a sign-in dialog, likelihood is Low-to-Medium rather than High.

### Recommendation
Do not use substring/regex hostname matching as a proxy for "this is a GitHub server." `isGitHubHost` should rely solely on: (1) exact match to configured/known endpoints (`isDotCom`, `isGHE`), (2) verified `x-github-request-id` / enterprise version response from an actual network probe (which the function already does as a fallback), and (3) explicit user-configured GHE endpoints — never a bare hostname-contains-"github" heuristic. At minimum, the regex-based branches in `isGitHubHost` (`app/src/lib/api.ts:2451-2459`) should be removed or restricted to only fire after the network probe corroborates the `x-github-request-id`/enterprise-version signal.

### Proof of Concept
1. Register/host a server at a domain matching the regex, e.g. `github.attacker-example.com`.
2. In GitHub Desktop, clone or add a remote pointing at `https://github.attacker-example.com/foo/bar.git`.
3. Trigger a git operation that requires credentials (e.g. `git fetch`/`git push`) so the trampoline credential helper's `get` command runs.
4. Observe in `getEndpointKind()` that none of the exact checks match, but `isGitHubHost('https://github.attacker-example.com')` returns `true` due to the `/(^|\.)(github)\./` regex, classifying the endpoint as `'enterprise'`.
5. Because no account exists for that literal endpoint, Desktop shows the "Sign in to GitHub" dialog (`ui.promptForGitHubSignIn`) for a host that is not actually GitHub, and simultaneously refuses to fall back to the generic credential helper for it.

Note: I was unable to fully trace every downstream consumer of `getEndpointKind`'s `'enterprise'` classification (e.g., whether any code path also auto-attaches an *existing* GHE account's token to such a mismatched endpoint), so the exact worst-case token-leak scenario could not be conclusively confirmed from the indexed code alone; a full review of `app/src/lib/trampoline/` and the OAuth device-flow completion handlers in a live session would be needed to rule out a stronger, direct token-exfiltration variant.

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }
```

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
```
