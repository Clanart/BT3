Audit Report

## Title
Feature-flag-dependent stake recomputation can desynchronize `delegated_stakes` bookkeeping and panic on subtraction underflow - (File: runtime/src/stakes.rs)

## Summary
`Stakes::delegated_stakes` is a per-vote-account running total updated incrementally by `upsert_stake_delegation`/`remove_stake_delegation`, which recompute the delta to add/remove via `delegation_effective_stake(...)` using the *current* `use_fixed_point_stake_math` flag rather than reusing the value originally added to the accumulator. Because `use_fixed_point_stake_math` is read fresh from the feature set on every call to `Bank::update_stakes_cache` and — unlike `new_warmup_cooldown_rate_epoch` — has no epoch-boundary alignment mechanism, it can flip between the slot that added a delegation's stake to the accumulator and a later slot in the same epoch that modifies it, causing `sub_delegated_stake`'s hard `.expect()` to panic on a legitimate transaction.

## Finding Description
`Bank::use_fixed_point_stake_math` is a direct, unguarded read of the feature set snapshot: `self.feature_set.snapshot().upgrade_bpf_stake_program_to_v5_1` [1](#0-0)  — contrasted with `new_warmup_cooldown_rate_epoch`, which is explicitly epoch-aligned via `feature_set.new_warmup_cooldown_rate_epoch(&self.epoch_schedule)` [2](#0-1) . Both values are captured once per call to `update_stakes_cache` and passed straight through to `StakesCache::check_and_store` for every account touched by a transaction batch [3](#0-2) .

`upsert_stake_delegation` recomputes `old_stake` for the previous delegation state using the caller's current `use_fixed_point_stake_math`, then calls `sub_delegated_stake(&old_voter_pubkey, old_stake)` [4](#0-3) . `sub_delegated_stake` has no tolerance for a mismatch — it panics via `.expect("subtraction value exceeds delegated stake")` if the recomputed value exceeds what is actually stored [5](#0-4) . `delegation_effective_stake` dispatches between the float-based `stake()` and fixed-point `stake_v2()` implementations depending on the boolean [6](#0-5)  — two distinct arithmetic paths not guaranteed to produce bit-identical `u64` outputs for the same delegation/epoch/history.

Existing guards do not close this gap: `sub_delegated_stake` has no saturating fallback, and nothing in `upsert_stake_delegation` verifies that the same math mode was used for the value being added versus removed.

## Impact Explanation
A successful trigger causes an unrecoverable Rust panic inside `Bank::update_stakes_cache`, which every honest validator executes deterministically for the same block, aborting the bank-processing thread across the entire validator set that replays the transaction — matching the "consensus halt" / "non-RPC remote crash" impact categories.

## Likelihood Explanation
This is a narrow, low-likelihood, time-window-dependent condition: it requires (a) a stake-math feature flag such as `upgrade_bpf_stake_program_to_v5_1` to activate strictly mid-epoch rather than at an epoch boundary, (b) the float vs. fixed-point calculations to diverge (even by 1 lamport) for the specific delegation in question, and (c) an ordinary stake-modifying transaction to touch that delegation on both sides of the activation boundary. Feature-activation timing is a network governance event rather than something an unprivileged attacker fully controls, though activation slots are public and could in principle be raced with an ordinary transaction. This substantially limits repeatability compared to a general-purpose, attacker-triggerable bug.

## Recommendation
- Align `use_fixed_point_stake_math` transitions to epoch boundaries the same way `new_warmup_cooldown_rate_epoch` is handled, so all `delegated_stakes` accumulator operations within an epoch use a consistent math mode.
- Replace the hard `.expect()` panics in `sub_delegated_stake` with a recoverable path (saturating subtraction plus a full recomputation/refresh of `delegated_stakes`, or a logged clamp) so a bookkeeping mismatch degrades gracefully instead of crashing the process.
- Audit `remove_stake_delegation` and the analogous vote-account stake bookkeeping (`do_sub_node_stake`) for the same pattern.

## Proof of Concept
1. Construct a stake delegation for voter `V` in a state (partially activating/deactivating) where `Delegation::stake()` and `Delegation::stake_v2()` diverge for identical `(delegation, epoch, stake_history)` inputs.
2. In slot N, before the `upgrade_bpf_stake_program_to_v5_1` feature activates, submit a transaction that stores the account, causing `upsert_stake_delegation` to add `stake_v1` into `delegated_stakes[V]` via `add_delegated_stake` [7](#0-6) .
3. Activate the feature at slot N+1 within the same epoch, flipping `use_fixed_point_stake_math` to `true`.
4. In slot N+1, submit another ordinary transaction touching the same stake account; `upsert_stake_delegation` recomputes `old_stake` using `stake_v2`, and `sub_delegated_stake` panics if `old_stake_v2 > current_stake` [8](#0-7) .

    fn update_stakes_cache(
        &self,
        txs: &[impl SVMMessage],
        processing_results: &[TransactionProcessingResult],
    ) {
        debug_assert_eq!(txs.len(), processing_results.len());
        let new_warmup_cooldown_rate_epoch = self.new_warmup_cooldown_rate_epoch();
        let use_fixed_point_stake_math = self.use_fixed_point_stake_math();
        txs.iter()
            .zip(processing_results)
            .filter_map(|(tx, processing_result)| {
                processing_result
                    .processed_transaction()
                    .map(|processed_tx| (tx, processed_tx))
            })
            .filter_map(|(tx, processed_tx)| {
                processed_tx
                    .executed_transaction()
                    .map(|executed_tx| (tx, executed_tx))
            })
            .filter(|(_, executed_tx)| executed_tx.was_successful())
            .flat_map(|(tx, executed_tx)| {
                let num_account_keys = tx.account_keys().len();
                let loaded_tx = &executed_tx.loaded_transaction;
                loaded_tx.accounts.iter().take(num_account_keys)
            })
            .for_each(|(pubkey, account)| {
                // note that this could get timed to: self.rc.accounts.accounts_db.stats.stakes_cache_check_and_store_us,

                    pubkey,
                    account,
                    new_warmup_cooldown_rate_epoch,
                    use_fixed_point_stake_math,
                );
            });

    fn sub_delegated_stake(&mut self, voter_pubkey: &Pubkey, stake: u64) {
        if stake == 0 {
            return;
        }
        let current_stake = self
            .delegated_stakes
            .get_mut(voter_pubkey)
            .expect("subtraction from missing delegated stake");
        *current_stake = current_stake
            .checked_sub(stake)
            .expect("subtraction value exceeds delegated stake");
        if *current_stake == 0 {
            self.delegated_stakes.remove(voter_pubkey);
        }
    }

    fn upsert_stake_delegation(
        &mut self,
        stake_pubkey: Pubkey,
        stake_account: StakeAccount,
        new_rate_activation_epoch: Option<Epoch>,
        use_fixed_point_stake_math: bool,
    ) {
        debug_assert_ne!(stake_account.lamports(), 0u64);
        let delegation = stake_account.delegation();
        let voter_pubkey = delegation.voter_pubkey;
        let stake = delegation_effective_stake(
            delegation,
            self.epoch,
            &self.stake_history,
            new_rate_activation_epoch,
            use_fixed_point_stake_math,
        );
        match self.stake_delegations.insert(stake_pubkey, stake_account) {
            None => {
                self.add_delegated_stake(voter_pubkey, stake);
                self.vote_accounts.add_stake(&voter_pubkey, stake);
            }
            Some(old_stake_account) => {
                let old_delegation = old_stake_account.delegation();
                let old_voter_pubkey = old_delegation.voter_pubkey;
                let old_stake = delegation_effective_stake(
                    old_delegation,
                    self.epoch,
                    &self.stake_history,
                    new_rate_activation_epoch,
                    use_fixed_point_stake_math,
                );
                if voter_pubkey != old_voter_pubkey || stake != old_stake {
                    self.sub_delegated_stake(&old_voter_pubkey, old_stake);
                    self.add_delegated_stake(voter_pubkey, stake);
                    self.vote_accounts.sub_stake(&old_voter_pubkey, old_stake);
                    self.vote_accounts.add_stake(&voter_pubkey, stake);
                }
            }
        }
    }

#[inline]
pub(crate) fn delegation_effective_stake<T: StakeHistoryGetEntry>(
    delegation: &Delegation,
    epoch: Epoch,
    history: &T,
    new_rate_activation_epoch: Option<Epoch>,
    use_fixed_point_stake_math: bool,
) -> u64 {
    if use_fixed_point_stake_math {
        delegation.stake_v2(epoch, history, new_rate_activation_epoch)
    } else {
        #[allow(deprecated)]
        delegation.stake(epoch, history, new_rate_activation_epoch)
    }
}
