### Title
Unfiltered mapping of attacker-controlled CosmWasm event attributes into synthetic EVM receipt logs allows forged ERC20/ERC721/ERC1155 events - (File: app/receipt.go)

### Summary
`app.AddCosmosEventsToEVMReceiptIfApplicable` and its helpers (`translateCW20Event`, `translateCW721Event`, `translateCW1155Event`, `GetActionsFromWasmEvent`) synthesize Ethereum-style `Transfer`/`Approval`/`TransferSingle`/`TransferBatch`/`ApprovalForAll` logs for CW20/CW721/CW1155 pointer contracts directly from the free-form string attributes (`action`, `amount`, `from`, `to`, `sender`, `recipient`, `owner`, `spender`, `operator`, `token_id`) that a CosmWasm contract itself puts in its `wasm` event, with no schema/authenticity validation of those values beyond wasmd's generic `_`-prefix reservation check.

### Finding Description
When a CW20 (or CW721/CW1155) contract executes, sei-wasmd's `contractSDKEventAttributes` copies every custom attribute the contract supplies verbatim into the `wasm` event, only rejecting keys with the reserved `_` prefix [2](#0-1) . Nothing constrains a contract's own `action`, `amount`, `from`, `to`, etc. values to reflect real state changes.

`app.GetActionsFromWasmEvent` parses these attacker-defined attribute strings into an `Action` struct purely by key name, with no correlation to actual bank/CW20 balance changes [3](#0-2) . `translateCW20Event` then unconditionally turns `mint`/`burn`/`transfer`/`transfer_from` actions into ERC20 `Transfer` logs, and `increase_allowance`/`decrease_allowance` into `Approval` logs, keyed on `pointerAddr` [4](#0-3) . The only gate is that the wasm event's `_contract_address` attribute (which is chain-set, not attacker-set) must equal a CosmWasm address that has a registered ERC20/ERC721/ERC1155 pointer, via `GetERC20CW20Pointer`/`GetERC721CW721Pointer`/`GetERC1155CW1155Pointer` [5](#0-4) .

Critically, pointer registration (`AddCW20`) does not verify that the target CosmWasm contract is a canonical, trusted CW20 implementation — it only requires that a `{"token_info":{}}` smart query succeed and returns `name`/`symbol` [1](#0-0) . Any user can deploy their own CosmWasm contract that implements a `token_info` query (satisfying pointer registration) and includes an `execute` entry point (or any message) that emits a fabricated `wasm` event with contract-controlled `action="mint"`, `to="<attacker-controlled address>"`, and an arbitrary `amount`, without altering any real token supply or balance. Because the mapping from wasm-event attribute to synthetic Ethereum log has no cross-check against the contract's actual state transition (e.g., verifying the mint/transfer really occurred via bank/CW20 balance deltas), the transaction's `eth_getTransactionReceipt`/`eth_getLogs` output will contain a completely fabricated ERC20 `Transfer`/`Approval` log for the registered pointer address.

This is directly analogous to the Camel-NATS defect: untrusted, externally/contract-controlled data (`wasmEvent.Attributes`) is mapped without any filtering/allow-list strategy into a downstream "control" structure (the synthesized EVM log/receipt) that other systems (bridges, exchanges, indexers, wallets) treat as authoritative proof of an on-chain ERC20/NFT transfer.

### Impact Explanation
Any downstream consumer that trusts `eth_getLogs`/`eth_getTransactionReceipt` output for a registered CW20/CW721/CW1155 pointer address (custodians, bridges, CEX deposit detectors, other smart contracts reading logs off-chain) can be deceived into crediting deposits, releasing funds, or minting wrapped assets based on log events that were never backed by an actual CosmWasm balance change. This is a direct fund-loss / unauthorized-transfer vector via a CW<->EVM pointer, reachable by any unprivileged user who deploys and calls their own CosmWasm contract.

### Likelihood Explanation
Reachable by any address that can (1) deploy an arbitrary CosmWasm contract implementing a minimal `token_info` query, (2) call the public `AddCW20`/`AddCW721`/`AddCW1155` precompile method to register a pointer (no special permission required), and (3) execute the contract to emit crafted `wasm` event attributes. No validator collusion, governance, or privileged access is required — this is entirely reachable from a single submitted EVM/CosmWasm transaction.

### Recommendation
Do not derive synthetic EVM Transfer/Approval/mint logs purely from free-form contract-emitted attribute strings. Instead, cross-validate the claimed action against actual state transitions (e.g., query CW20/CW721/CW1155 balance/ownership before and after execution, or restrict `GetActionsFromWasmEvent`/`translateCW*Event` to only trust attributes emitted by contracts whose code hash matches an allow-listed, audited CW20/CW721/CW1155 implementation at pointer-registration time). At minimum, apply a strict allow-list of attribute keys with confirmed semantics tied to verified state diffs, similar to how the Camel fix introduced a dedicated filtering strategy instead of accepting all inbound fields verbatim.

### Proof of Concept
1. Deploy a minimal CosmWasm contract exposing `{"token_info":{}}` returning arbitrary `name`/`symbol`, and an `execute` handler that emits a `wasm` event with attributes `action=mint`, `to=<attacker sei address>`, `amount=1000000000000` — without performing any real CW20 mint/transfer logic.
2. Call the `pointer` precompile's `AddCW20Pointer` method with this contract's address to register an ERC20 pointer [1](#0-0) .
3. From an EVM transaction (or via `MsgExecuteContract`), call `execute` on the CosmWasm contract to trigger the fabricated `mint` event.
4. Query `eth_getTransactionReceipt`/`eth_getLogs` for the transaction — observe a fabricated `Transfer(0x0, attacker, 1000000000000)` ERC20 log for the pointer address, with no corresponding real CW20 balance increase, because `translateCW20Event`/`GetActionsFromWasmEvent` blindly trust the contract's self-reported `action`/`amount`/`to` attributes [6](#0-5) .

		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(contractAddr)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return

func (app *App) translateCW20Event(ctx sdk.Context, wasmEvent abci.Event, pointerAddr common.Address, contractAddr string) (res []*ethtypes.Log) {
	defer func() {
		if r := recover(); r != nil {
			fmt.Printf("[Error] Panic caught during translateCW20Event: type=%T, value=%+v\n", r, r)
		}
	}()

	for _, action := range app.GetActionsFromWasmEvent(ctx, wasmEvent) {
		switch action.Type {
		case "mint", "burn", "send", "transfer", "transfer_from", "send_from", "burn_from":
			if action.Amount == nil {
				continue
			}
			res = append(res, &ethtypes.Log{
				Address: pointerAddr,
				Topics: []common.Hash{
					ERC20TransferTopic,
					action.From,
					action.To,
				},
				Data: common.BigToHash(action.Amount).Bytes(),
			})
		case "increase_allowance", "decrease_allowance":
			topics := []common.Hash{
				ERC20ApprovalTopic,
				action.Owner,
				action.Spender,
			}
			ret, err := app.WasmKeeper.QuerySmart(
				ctx,
				sdk.MustAccAddressFromBech32(contractAddr),
				[]byte(fmt.Sprintf(
					"{\"allowance\":{\"owner\":\"%s\",\"spender\":\"%s\"}}",
					app.EvmKeeper.GetSeiAddressOrDefault(ctx, common.BytesToAddress(action.Owner[:])).String(),
					app.EvmKeeper.GetSeiAddressOrDefault(ctx, common.BytesToAddress(action.Spender[:])).String())),
			)
			if err != nil {
				continue
			}
			allowanceResponse := &AllowanceResponse{}
			if err := json.Unmarshal(ret, allowanceResponse); err != nil {
				continue
			}
			res = append(res, &ethtypes.Log{
				Address: pointerAddr,
				Topics:  topics,
				Data:    common.BigToHash(allowanceResponse.Allowance.BigInt()).Bytes(),
			})
		}
	}
	return
}

func (app *App) GetActionsFromWasmEvent(ctx sdk.Context, event abci.Event) (actions []*Action) {
	for _, attr := range event.Attributes {
		key := string(attr.Key)
		value := string(attr.Value)
		if key == "action" {
			actions = append(actions, &Action{Type: value})
			continue
		}
		if len(actions) == 0 {
			continue
		}
		curAction := actions[len(actions)-1]
		switch key {
		case "amount":
			curAction.Amount = safeBigIntFromString(value)
		case "amounts":
			curAction.Amounts = utils.Map(strings.Split(value, ","), safeBigIntFromString)
		case "token_id":
			curAction.TokenId = safeBigIntFromString(value)
		case "token_ids":
			curAction.TokenIds = utils.Map(strings.Split(value, ","), safeBigIntFromString)
		case "sender":
			curAction.Sender = app.GetEvmAddressHash(ctx, value)
		case "recipient":
			curAction.Recipient = app.GetEvmAddressHash(ctx, value)
		case "spender":
			curAction.Spender = app.GetEvmAddressHash(ctx, value)
		case "operator":
			curAction.Operator = app.GetEvmAddressHash(ctx, value)
		case "owner":
			curAction.Owner = app.GetEvmAddressHash(ctx, value)
		case "from":
			curAction.From = app.GetEvmAddressHash(ctx, value)
		case "to":
			curAction.To = app.GetEvmAddressHash(ctx, value)
		}
	}
	return
}
