### Title
`distribution` precompile's `rewards()` method accepts native value with no payment handling, permanently stranding funds sent to it - (File: `precompiles/distribution/distribution.go`)

### Summary
The `distribution` precompile at `0x...1007` dispatches transaction/query methods in `PrecompileExecutor.Execute` [1](#0-0) . Every payable method that is designed to accept `usei`/`wei` value explicitly refunds/redirects the payment via `pcommon.HandlePaymentUseiWei` (e.g. `sendNative` in the bank precompile) [2](#0-1) , and every non-payable method is guarded with `pcommon.ValidateNonPayable(value)` (e.g. `WithdrawValidatorCommissionMethod`) [3](#0-2) . The `RewardsMethod` case, however, is dispatched with neither guard nor payment handling: `case RewardsMethod: return p.rewards(ctx, method, args)` [4](#0-3) . This gap is explicitly documented by the integration test suite as a known quirk: "`rewards()` is the one phase-2 view WITHOUT a non-payable check (a value-bearing call would succeed and strand the funds)" [5](#0-4) .

### Finding Description
When an EVM `CALL` targets a precompile address with non-zero `value`, the EVM value-transfer mechanism credits that value to the precompile's associated account balance in the StateDB before the precompile logic runs. Every other value-accepting precompile method in this codebase (bank's `sendNative`, staking's `delegate`, distribution's `setWithdrawAddress`, etc.) immediately calls `pcommon.HandlePaymentUseiWei`, which explicitly moves the just-transferred `usei`/`wei` back out of the precompile module account to the actual payer/recipient via `bankKeeper.SendCoinsAndWei` [6](#0-5) . Non-payable query/view methods are protected from ever receiving value at all via `pcommon.ValidateNonPayable`, which reverts if `value.Sign() != 0` [7](#0-6) .

The `rewards()` handler, `p.rewards(ctx, method, args)`, does neither: it has no `value` parameter at all in its signature (`func (p PrecompileExecutor) rewards(ctx sdk.Context, method *abi.Method, args []interface{})`) and performs only a read-only `DelegationTotalRewards` query [8](#0-7) . Because the dispatch switch never calls `ValidateNonPayable` for `RewardsMethod`, any caller can attach `msg.value` to a call/transaction invoking `rewards(address)`; the EVM will still transfer that value into the precompile's account balance as part of normal `CALL` semantics, but no code path exists to route it back to the sender or credit it to the intended recipient, unlike every other payable precompile method.

### Impact Explanation
Any usei/wei sent alongside a `rewards()` call is transferred to the precompile module account by the EVM's value-transfer step but is never returned, refunded, or otherwise accounted for by application logic, since `rewards()` performs no `HandlePaymentUseiWei`/`bankKeeper` interaction. This constitutes a permanent, unrecoverable loss of user funds for anyone (or any contract, e.g. via `callerContract` relaying value) that submits a value-bearing call to `rewards()` — reachable by any ordinary EVM transaction sender, satisfying the "concrete fund loss / permanent freezing" bar for this analog.

### Likelihood Explanation
Likelihood is low-to-moderate: exploitation requires a caller to deliberately (or mistakenly, e.g. via a generic multicall/router forwarding `msg.value`) attach value to a call whose ABI signature (`rewards(address)`) gives no indication it is payable. However, unlike most Solidity `view`-style calls, nothing in the interpreter dispatch or the ABI prevents this — `distribution.rewards` is documented in-repo as "accepts value (no non-payable check)" [9](#0-8) , confirming it is a real, currently-unguarded gap rather than a purely theoretical one.

### Recommendation
Add a `pcommon.ValidateNonPayable(value)` check for `RewardsMethod` in every `Execute` dispatcher of the distribution precompile (current and all legacy versions still reachable on-chain), consistent with the guard already applied to `WithdrawValidatorCommissionMethod` and other non-payable methods, e.g.:
```go
case RewardsMethod:
    if err = pcommon.ValidateNonPayable(value); err != nil {
        return nil, 0, err
    }
    return p.rewards(ctx, method, args)
```

### Proof of Concept
1. Deploy/use the `callerContract` (or any contract) capable of forwarding `msg.value` on a `CALL`.
2. Invoke `distribution.rewards(delegatorAddress)` on precompile `0x...1007`, attaching non-zero `msg.value` (e.g. `1 usei` worth of wei).
3. Observe the call succeeds and returns reward data as normal (per the documented behavior in `distribution.spec.ts`), while the attached value is transferred to the precompile's account and is not returned to the caller nor credited to any Sei bank account, since `rewards()` never calls `HandlePaymentUseiWei` or any bank keeper method.
4. The sent value is now permanently unrecoverable through any precompile-exposed function.

func HandlePaymentUseiWei(ctx sdk.Context, precompileAddr sdk.AccAddress, payer sdk.AccAddress, value *big.Int, bankKeeper putils.BankKeeper, evmKeeper putils.EVMKeeper, hooks *tracing.Hooks, depth int) (sdk.Int, sdk.Int, error) {
	usei, wei := state.SplitUseiWeiAmount(value)
	// refund payer because the following precompile logic will debit the payments from payer's account
	// this creates a new event manager to avoid surfacing these as cosmos events
	if err := bankKeeper.SendCoinsAndWei(ctx.WithEventManager(sdk.NewEventManager()), precompileAddr, payer, usei, wei); err != nil {
		return sdk.Int{}, sdk.Int{}, err
	}
	if hooks != nil {
		newCtx := ctx.WithGasMeter(sdk.NewInfiniteGasMeterWithMultiplier(ctx))
		if hooks.OnEnter != nil {
			hooks.OnEnter(depth+1, byte(vm.CALL), evmKeeper.GetEVMAddressOrDefault(newCtx, precompileAddr), evmKeeper.GetEVMAddressOrDefault(newCtx, payer), []byte{}, GetRemainingGas(newCtx, evmKeeper), value)
		}
		if hooks.OnExit != nil {
			hooks.OnExit(depth+1, []byte{}, 0, nil, false)
		}
	}
	return usei, wei, nil
}

func (p PrecompileExecutor) rewards(ctx sdk.Context, method *abi.Method, args []interface{}) (ret []byte, remainingGas uint64, rerr error) {
	defer func() {
		if err := recover(); err != nil {
			ret = nil
			remainingGas = 0
			rerr = fmt.Errorf("%s", err)
			return
		}
	}()

	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		rerr = err
		return
	}

	seiDelegatorAddress, err := p.accAddressFromArg(ctx, args[0])
	if err != nil {
		rerr = err
		return
	}

	req := &distrtypes.QueryDelegationTotalRewardsRequest{
		DelegatorAddress: seiDelegatorAddress.String(),
	}

	wrappedC := sdk.WrapSDKContext(ctx)
	response, err := p.distrKeeper.DelegationTotalRewards(wrappedC, req)
	if err != nil {
		rerr = err
		return
	}

	rewardsOutput := getResponseOutput(response)
	ret, rerr = method.Outputs.Pack(rewardsOutput)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}
