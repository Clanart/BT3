## Analysis: FieldMaskTree recursion is unbounded, directly analogous to jq's CVE-2026-33947

**External invariant that failed in jq:** `jv_setpath`/`jv_getpath`/`delpaths_sorted` recurse once per element of an attacker-supplied path array, with no depth cap independent of the JSON parser's `MAX_PARSING_DEPTH`. The fix added an explicit depth check.

**Protobuf analog:** `google.protobuf.FieldMask`'s path-driven tree walkers (`FieldMaskUtil::MergeMessageTo`/`TrimMessage` in C++, and the equivalent `FieldMaskTree.mergeMessage`/`_MergeMessage` in Java/Python/C#) recurse once per dot-separated segment of a `FieldMask` path string, with **no recursion-depth limit at all** — unlike every wire/JSON parser in the same codebase, which all enforce an explicit `recursion_limit`/`SetRecursionLimit`/`max_recursion_depth` (typically 100) as shown throughout `CodedInputStream`, `ParseContext`, `json/internal/lexer.h`, `json_format.py`, `JsonFormat.java`, and `JsonParser.cs`. [1](#0-0) 

That `MergeMessage` recurses unconditionally whenever the tree node has children and the matching field is a singular message field — it does **not** check `HasField` first, so the recursion depth is controlled purely by the number of `.`-separated segments in the client-supplied `FieldMask` path, exactly as jq's bug is controlled purely by path-array length rather than actual document nesting: [2](#0-1) 

`AddPath`/tree construction is iterative (uses a loop, not recursion) so building the tree itself is safe, but the walker functions `MergeMessage`/`TrimMessage` are genuinely recursive C++ functions: [3](#0-2) 

The same unbounded-recursion pattern exists in the Java, Python, and C# ports (`FieldMaskTree.java` `mergeMessage`, `field_mask.py` `_MergeMessage`, `FieldMaskTree.cs` `Merge`), none of which impose a path-depth limit: [4](#0-3) [5](#0-4) 

I traced the message/JSON binary parsers extensively and confirmed they all enforce depth limits (`CodedInputStream::SetRecursionLimit`, `ParseContext::depth_`, upb's `LimitDepth`, `json_internal::lexer.h`'s `recursion_depth`), so the "parsing depth is bounded" invariant holds for wire/JSON decoding — it just doesn't transfer to `FieldMask`-driven reflection walks, which is a distinct, unguarded code path reachable from a fully trusted, bounded `FieldMask` message.

### Title
Unbounded recursion in `FieldMaskTree::MergeMessage`/`TrimMessage` via attacker-controlled `FieldMask` path depth - (File: `src/google/protobuf/util/field_mask_util.cc`)

### Summary
`google.protobuf.FieldMask.paths` entries are dot-separated field-path strings that are split into tree nodes and then walked by `FieldMaskTree::MergeMessage`/`TrimMessage` (and their Java/Python/C# equivalents) with one level of C-stack recursion per path segment. No recursion-depth limit is enforced on this walk, unlike every binary/JSON parser in the codebase, which caps nested-message recursion (default 100). A client that controls the `FieldMask` (e.g., an `update_mask` field in an AIP-134-style API, a routine and widely-used protobuf pattern) can submit one `FieldMask` path with tens of thousands of `.`-separated segments that match a self-referential singular message field in the trusted schema (e.g., `message Node { Node child = 1; }`), producing tens of thousands of recursive stack frames in `MergeMessage`/`TrimMessage` and crashing the process with SIGSEGV — the same "path-length-driven unbounded recursion" bug class as jq's `jv_setpath`/`jv_getpath`.

### Finding Description
`FieldMaskUtil::MergeMessageTo`/`TrimMessage` build a `FieldMaskTree` from the `FieldMask.paths` list (`AddPath`, which is iterative and therefore safe) and then invoke the recursive `MergeMessage`/`TrimMessage` walker over that tree. Each tree level corresponds to one `.`-separated path segment; `MergeMessage` recurses into `MergeMessage(child, source_reflection->GetMessage(source, field), ..., destination_reflection->MutableMessage(destination, field))` for every level where the matching field is a singular message type, with **no check on recursion depth**. This mirrors jq's failed invariant exactly: the recursion depth is controlled by the length of a caller/attacker-supplied "path," not by any independent, enforced structural limit — and the existing protobuf recursion guards (`CodedInputStream::SetRecursionLimit`, `ParseContext::depth_`, upb `LimitDepth`, JSON lexer `recursion_depth`) only protect wire/JSON *parsing*, not this post-parse reflection-based `FieldMask` walk, just as jq's `MAX_PARSING_DEPTH` only protected the JSON parser and not `jv_setpath`/`jv_getpath`.

### Impact Explanation
A crash (SIGSEGV via C-stack exhaustion) in any process that parses a client-supplied `FieldMask` (bounded-size, valid ProtoJSON/binary) and passes it to `FieldMaskUtil::MergeMessageTo`/`TrimMessage` against a message type containing a self-referential singular message field — a common schema shape for tree/graph-like data. This is a denial-of-service impacting availability (CVSS `AV:L/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H`, matching the referenced CVE's rating), consistent across the C++, Java, Python, and C# implementations.

### Likelihood Explanation
Moderate-to-high for applications using the extremely common `FieldMask`/`update_mask` API pattern (AIP-134) where the mask is populated from client input and applied via `FieldMaskUtil`, combined with a trusted schema containing a recursive singular-message field. No malicious schema, plugin, or privileged access is needed — only an ordinary bounded `FieldMask` payload through a supported public API (`FieldMaskUtil::MergeMessageTo`/`TrimMessage`, or the Java/Python/C# equivalents), which many services expose indirectly via update RPCs.

### Recommendation
Add an explicit recursion/path-depth limit to `FieldMaskTree::MergeMessage`, `TrimMessage`, `AddRequiredFieldPath`, and their Java/Python/C# equivalents, consistent with the depth limits already enforced by `CodedInputStream`/`ParseContext`/JSON parsers (e.g., cap at 100 by default), returning an error rather than recursing unboundedly when a `FieldMask` path exceeds the limit.

### Proof of Concept
Given a trusted schema with a self-referential singular message field, e.g.:
```proto
message Node {
  Node child = 1;
  int32 value = 2;
}
```
An attacker sends a bounded `google.protobuf.FieldMask` (e.g., via a public update-RPC's `update_mask` field) with a single path of the form `child.child.child. ... .child` (tens of thousands of repetitions, well under typical message-size limits), then the application calls:
```cpp
FieldMaskUtil::MergeMessageTo(source, mask, options, &destination);
```
`FieldMaskTree::MergeMessage` recurses once per `.`-separated segment with no depth check, exhausting the C stack and crashing with SIGSEGV — directly analogous to constructing a ~65,000-element flat JSON array as the `jq` `setpath`/`getpath` path argument in CVE-2026-33947.

bool FieldMaskTree::TrimMessage(const Node* node, Message* message) {
  ABSL_DCHECK(!node->children.empty());
  const Reflection* reflection = message->GetReflection();
  const Descriptor* descriptor = message->GetDescriptor();
  const int32_t field_count = descriptor->field_count();
  bool modified = false;
  for (int index = 0; index < field_count; ++index) {
    const FieldDescriptor* field = descriptor->field(index);
    auto it = node->children.find(field->name());
    if (it == node->children.end()) {
      if (field->is_repeated()) {
        if (reflection->FieldSize(*message, field) != 0) {
          modified = true;
        }
      } else {
        if (reflection->HasField(*message, field)) {
          modified = true;
        }
      }
      reflection->ClearField(message, field);
    } else {
      if (field->cpp_type() == FieldDescriptor::CPPTYPE_MESSAGE) {
        Node* child = it->second.get();
        if (!child->children.empty() && reflection->HasField(*message, field)) {
          if (field->is_repeated()) {
            for (int i = 0; i < reflection->FieldSize(*message, field); ++i) {
              bool nestedMessageChanged = TrimMessage(
                  child, reflection->MutableRepeatedMessage(message, field, i));
              modified = nestedMessageChanged || modified;
            }
          } else {
            bool nestedMessageChanged =
                TrimMessage(child, reflection->MutableMessage(message, field));
            modified = nestedMessageChanged || modified;
          }
        }
      }
    }
  }
  return modified;
}

        private void Merge(
            Node node,
            string path,
            IMessage source,
            IMessage destination,
            FieldMask.MergeOptions options)
        {
            if (source.Descriptor != destination.Descriptor)
            {
                throw new InvalidProtocolBufferException($"source ({source.Descriptor}) and destination ({destination.Descriptor}) descriptor must be equal");
            }

            var descriptor = source.Descriptor;
            foreach (var entry in node.Children)
            {
                var field = descriptor.FindFieldByName(entry.Key);
                if (field == null)
                {
                    Debug.WriteLine($"Cannot find field \"{entry.Key}\" in message type \"{descriptor.FullName}\"");
                    continue;
                }

                if (entry.Value.Children.Count != 0)
                {
                    if (field.IsRepeated
                        || field.FieldType != FieldType.Message)
                    {
                        Debug.WriteLine($"Field \"{field.FullName}\" is not a singular message field and cannot have sub-fields.");
                        continue;
                    }

                    var sourceField = field.Accessor.GetValue(source);
                    var destinationField = field.Accessor.GetValue(destination);
                    if (sourceField == null
                        && destinationField == null)
                    {
                        // If the message field is not present in both source and destination, skip recursing
                        // so we don't create unnecessary empty messages.
                        continue;
                    }

                    if (destinationField == null)
                    {
                        // If we have to merge but the destination does not contain the field, create it.
                        destinationField = field.MessageType.Parser.CreateTemplate();
                        field.Accessor.SetValue(destination, destinationField);
                    }

                    if (sourceField == null)
                    {
                        // If the message field is not present in the source but is in the destination, create an empty one
                        // so we can properly handle child entries
                        sourceField = field.MessageType.Parser.CreateTemplate();
                    }

                    var childPath = path.Length == 0 ? entry.Key : path + "." + entry.Key;
                    Merge(entry.Value, childPath, (IMessage)sourceField, (IMessage)destinationField, options);
                    continue;
                }
