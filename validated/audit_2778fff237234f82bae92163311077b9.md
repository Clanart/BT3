## Title
Fractional (extended-coin) value is silently dropped when transferring to/from the `x/precisebank` reserve module account - ([File: x/precisebank/keeper/send.go])

## Summary
`x/precisebank` tracks a hidden reserve invariant analogous to PoolTogether's `SPONSORSHIP_ADDRESS` special-case: the reserve module account is deliberately excluded from fractional-balance bookkeeping, and code paths special-case it. In `sendExtendedCoins`, when either `from` or `to` equals the precisebank module (reserve) address, the function truncates the extended-coin amount to its integer component (`amt.Quo(ConversionFactor())`) and transfers only that, discarding the fractional remainder (`amt.Mod(ConversionFactor())`) entirely — it is never added to the recipient's fractional balance, never added to the `remainder` accounting bucket, and never backed/unbacked in the reserve.

Contrast this with the normal path (non-reserve transfers), which correctly separates `integerAmt` and `fractionalAmt = amt.Mod(ConversionFactor())`, and carefully carries/borrows integer units to keep the sum of fractional balances + remainder consistent with reserve integer backing [2](#0-1) . The reserve special-case path has no equivalent handling for `fractionalAmt`: if `amt` is not an exact multiple of `ConversionFactor()`, the fractional remainder is silently lost — it is subtracted from the sender's logical extended-coin balance (the caller believes the full `amt` was sent) but is never credited to the recipient, never added to `k.GetRemainderAmount`, and the reserve's integer backing is not adjusted to match. This breaks the core `x/precisebank` invariant documented in the module's own README, where the reserve integer balance must always fully back the sum of fractional balances and the remainder [3](#0-2) .

This exactly matches the analog bug class from the external report: a "special address" (there, `SPONSORSHIP_ADDRESS`; here, the precisebank reserve module account) is deliberately excluded from normal balance/invariant bookkeeping, and a transfer code path that special-cases it fails to correctly propagate value, breaking the sum-of-parts vs. total invariant.

## Impact Explanation
Any accounting path that routes an extended-coin (`GetEVMCoinExtendedDenom()`, i.e. the fractional/wei-precision denom) `SendCoins` call where `from` or `to` is the precisebank module address, with a non-multiple-of-`ConversionFactor()` amount, causes value to be irrecoverably destroyed (from the recipient's perspective) or created as an accounting inconsistency (the sender's tracked send amount no longer matches what was actually delivered). Since `x/precisebank` backs the EVM's wei-precision native balance used throughout `x/vm` (`SetBalance` mints/burns via this keeper) [4](#0-3) , any bug that de-syncs the reserve backing from tracked fractional balances is a direct, irreversible corruption of spendable user value / native-balance accounting — matching the "Critical unauthorized... irreversible accounting corruption of spendable user value across native balances" impact class.

## Likelihood Explanation
This is uncertain and could not be fully confirmed within the available context. The three public wrapper methods (`SendCoinsFromAccountToModule`, `SendCoinsFromModuleToAccount`, `SendCoinsFromModuleToModule`) all explicitly reject the precisebank module name as sender/recipient [5](#0-4) [6](#0-5) , which closes off the most obvious module-to-module trigger paths. The remaining trigger surface is the forked `Send()` method (used for direct `MsgSend`/EVM-driven transfers), which only checks `k.BlockedAddr(to)` [7](#0-6) ; I was unable to confirm from the available index whether `evmd/app.go`'s blocked-address configuration actually flags the precisebank reserve account address as blocked for receiving funds. If it is not blocked, a normal user could construct a `MsgSend` (or an EVM-level native transfer routed through this keeper) with `to` set to the deterministic precisebank module address and a non-`ConversionFactor()`-aligned amount, triggering the fractional-drop directly and unprivileged.

## Recommendation
In the reserve special-case branch of `sendExtendedCoins`, apply the same `Quo`/`Mod` decomposition and integer carry/borrow logic used in the general path, or explicitly reject non-multiple-of-`ConversionFactor()` transfers to/from the reserve address with an error, rather than silently truncating. Additionally, confirm (and if necessary add) a `BlockedAddr` entry for the precisebank module account so it cannot be targeted as a `Send()` recipient at all, consistent with the module's explicit blocking of it as a `SendCoinsFromModuleToAccount`/`SendCoinsFromAccountToModule` counterparty.

## Proof of Concept
Could not fully construct/verify an end-to-end PoC within the available tooling (no execution environment) because confirming reachability requires checking `evmd/app.go`'s bank blocklist configuration and the address blocking behavior of `k.bk.BlockedAddr`, which I could not fully resolve from the indexed code. Conceptually:
1. Compute the precisebank module address: `authtypes.NewModuleAddress(precisebanktypes.ModuleName)`.
2. Fund an ordinary account with extended-denom balance.
3. Call `k.SendCoins(ctx, ordinaryAccount, precisebankModuleAddr, extendedAmt)` where `extendedAmt` is not a multiple of `types.ConversionFactor()` (e.g., `ConversionFactor()+1`).
4. Observe: only `1` integer unit is transferred via `k.bk.SendCoins`; the fractional remainder is never recorded anywhere (`GetRemainderAmount` unchanged, reserve's fractional backing unchanged), so total extended-coin value drops by the fractional remainder amount versus what was debited from the sender.

func (k Keeper) SendCoinsFromModuleToAccount(
	goCtx context.Context,
	senderModule string,
	recipientAddr sdk.AccAddress,
	amt sdk.Coins,
) error {
	ctx := sdk.UnwrapSDKContext(goCtx)

	// Identical panics to x/bank
	senderAddr := k.ak.GetModuleAddress(senderModule)
	if senderAddr == nil {
		panic(errorsmod.Wrapf(sdkerrors.ErrUnknownAddress, "module account %s does not exist", senderModule))
	}

	// Custom error to prevent external modules from modifying x/precisebank
	// balances. x/precisebank module account balance is for internal reserve
	// use only.
	if senderModule == types.ModuleName {
		return errorsmod.Wrapf(sdkerrors.ErrUnauthorized, "module account %s is not allowed to send funds", types.ModuleName)
	}

	// Uses x/bank BlockedAddr, no need to modify. x/precisebank should be
	// blocked.
	if k.bk.BlockedAddr(recipientAddr) {
		return errorsmod.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", recipientAddr)
	}

	return k.SendCoins(ctx, senderAddr, recipientAddr, amt)
}

func (k Keeper) Send(goCtx context.Context, msg *banktypes.MsgSend) (*banktypes.MsgSendResponse, error) {
	var (
		from, to []byte
		err      error
	)

	from, err = k.ak.AddressCodec().StringToBytes(msg.FromAddress)
	if err != nil {
		return nil, sdkerrors.ErrInvalidAddress.Wrapf("invalid from address: %s", err)
	}

	to, err = k.ak.AddressCodec().StringToBytes(msg.ToAddress)
	if err != nil {
		return nil, sdkerrors.ErrInvalidAddress.Wrapf("invalid to address: %s", err)
	}

	if !msg.Amount.IsValid() {
		return nil, errorsmod.Wrap(sdkerrors.ErrInvalidCoins, msg.Amount.String())
	}

	if !msg.Amount.IsAllPositive() {
		return nil, errorsmod.Wrap(sdkerrors.ErrInvalidCoins, msg.Amount.String())
	}

	ctx := sdk.UnwrapSDKContext(goCtx)
	if err := k.IsSendEnabledCoins(ctx, msg.Amount...); err != nil {
		return nil, err
	}

	if k.BlockedAddr(to) {
		return nil, errorsmod.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", msg.ToAddress)
	}

	err = k.SendCoins(ctx, from, to, msg.Amount)
	if err != nil {
		return nil, err
	}

// SetBalance update account's balance, compare with current balance first, then decide to mint or burn.
func (k *Keeper) SetBalance(ctx sdk.Context, addr common.Address, amount *uint256.Int) error {
	if amount == nil {
		return nil
	}
	cosmosAddr := sdk.AccAddress(addr.Bytes())
	coin := k.bankWrapper.SpendableCoin(ctx, cosmosAddr, types.GetEVMCoinDenom())

	balance := coin.Amount.BigInt()
	delta := new(big.Int).Sub(amount.ToBig(), balance)
	switch delta.Sign() {
	case 1:
		// mint
		if err := k.bankWrapper.MintAmountToAccount(ctx, cosmosAddr, delta); err != nil {
			return err
		}
	case -1:
		// burn
		if err := k.bankWrapper.BurnAmountFromAccount(ctx, cosmosAddr, new(big.Int).Neg(delta)); err != nil {
			return err
		}
	default:
		// not changed
	}
	return nil
}
