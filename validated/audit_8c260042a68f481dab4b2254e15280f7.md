## Analysis

The reported bug class — reliance on a manipulable on-chain **spot price** to determine token amounts issued/exchanged, with no slippage/TWAP protection — has a concrete analog in `SmartWomConvert.sol`, reachable by any unprivileged wallet through `WombatStaking`.

### Title
Spot-price-dependent buyback swap with zero slippage protection allows sandwich theft of protocol WOM fees during mWOM conversion - (File: wombat/SmartWomConvert.sol)

### Summary
`SmartWomConvert.smartConvert()` reads the instantaneous Wombat AMM pool ratio via `currentRatio()` to decide how much of an incoming WOM amount should be "bought back" into mWOM through a live swap. That swap is executed with a hardcoded `amountOutMin = 0`, meaning the actual conversion price is fully exposed to manipulation of the same `womMWomPool` used to price it.

### Finding Description
`currentRatio()` fetches a spot quote from the Wombat pool via `IWombatRouter.getAmountOut(...)` [1](#0-0) . This spot value drives `smartConvert()`'s decision of `convertRatio`, i.e., how much of the incoming WOM is routed through an actual AMM swap for buyback versus minted 1:1 via `IMWom(mWom).deposit()` [2](#0-1) .

The buyback swap itself is executed in `_convertFor()` with **no minimum-output protection at the swap call**: [3](#0-2) 

The only downstream safety check is `convertAmount + amountRec < _minRec`, but for the `smartConvert` path `_minRec` is set to the full input amount (`_amountIn`) [4](#0-3) , which does not bound the *price* used inside the swap itself — it only guards the aggregate total, not the AMM execution price for the swapped portion.

Crucially, `smartConvert()` is not a privileged/admin-only entry point. It is invoked automatically inside `WombatStaking._sendRewards()` — reachable by **any unprivileged wallet** simply by calling `deposit`/`depositLP`/`withdraw` on `WombatStaking`, which triggers reward harvesting and fee routing: [5](#0-4) 

This fee-routing logic runs on every harvest of WOM rewards from Wombat's MasterWombat, which is triggered by ordinary user deposit/withdraw calls [6](#0-5) .

### Impact Explanation
An attacker can manipulate the `womMWomPool` spot price immediately before triggering a harvest (e.g., via a large swap or flash loan), pushing `currentRatio()` below `buybackThreshold` and depressing the mWom price. When the unprivileged-triggered `_sendRewards` → `smartConvert` → `_convertFor` path executes its buyback `swapExactTokensForTokens(..., 0, ...)`, the protocol's accumulated WOM fee amount is swapped into mWom at the attacker-manipulated, unprotected price. The attacker (who is on the other side of the AMM trade, or reverses the price manipulation afterward within the same transaction) captures the value that should have gone toward mWom buyback for reward-pool distribution via `IBaseRewardPool(feeInfo.to).queueNewRewards(...)` [7](#0-6) . This constitutes theft of protocol fee/yield value that would otherwise accrue to stakers.

### Likelihood Explanation
The path is triggered by any ordinary deposit/withdraw call on `WombatStaking` (fully unprivileged) and is combined with a public AMM pool that any wallet can trade against in the same transaction/block, making the manipulation self-contained and repeatable on every harvest event where `isMWOM` fee routing applies.

### Recommendation
Do not use a live spot quote (`currentRatio()`/`getAmountOut`) both to decide the buyback ratio and as the acceptable execution price for the same swap. Enforce a real minimum-output bound (derived from a TWAP or a bounded deviation from a trusted reference price) on the `swapExactTokensForTokens` call instead of hardcoded `0`, and/or cap the per-harvest buyback amount to limit price-impact-driven losses, consistent with the cited report's fix approach of avoiding spot-price-driven amounts and bounding exposure.

### Proof of Concept
1. Attacker observes pending WOM fees accumulating in `WombatStaking` destined for `_sendRewards` fee routing (`isMWOM` fee active).
2. Attacker swaps a large amount of mWom into the `womMWomPool` (or flash-loans to do so), depressing `currentRatio()` below `buybackThreshold`.
3. In the same transaction, attacker calls a trivial `WombatStaking.deposit`/`withdraw` to trigger `_toMasterWomAndSendReward` → `_sendRewards`, which calls `smartConvert(feeAmount, 0)`.
4. `smartConvert` computes a large `amountToSwap` (buyback) based on the manipulated `currentRatio()`/`maxSwapAmount()`, then executes `swapExactTokensForTokens(..., 0, ...)` at the manipulated pool price, yielding far fewer mWom than fair value.
5. Attacker reverses their initial swap, restoring the pool price and pocketing the value siphoned from the protocol's buyback swap, since the swap had zero output-amount protection.

    function smartConvert(uint256 _amountIn, uint256 _mode) external returns (uint256 obtainedmWomAmount) {
        if (_amountIn == 0) revert MustNoBeZero();

        uint256 convertRatio = DENOMINATOR;
        uint256 mWomToWom = currentRatio();

        if (mWomToWom < buybackThreshold) {
            uint256 maxSwap = maxSwapAmount();
            uint256 amountToSwap = _amountIn > maxSwap ? maxSwap : _amountIn;
            uint256 convertAmount = _amountIn - amountToSwap;
            convertRatio = convertAmount * DENOMINATOR / _amountIn;
        }

        return _convertFor(_amountIn, convertRatio, _amountIn, msg.sender, _mode);
    }
