## Title
Operator credited for a payout it never funded via UTXO-keyed join in `get_payout_txs_for_withdrawal_utxos` / `update_finalized_payouts` - (File: `core/src/verifier.rs`, `core/src/database/verifier.rs`)

## Summary
The `withdrawals` table has no uniqueness constraint on `(withdrawal_utxo_txid, withdrawal_utxo_vout)`, and `Database::get_payout_txs_for_withdrawal_utxos` joins spent-UTXO records to withdrawal rows purely by outpoint bytes, not by `idx`/`deposit_id`. If an attacker registers the same withdrawal outpoint for two different Citrea withdrawal indices, spending that outpoint once (to pay withdrawal D1) causes `update_finalized_payouts` to also mark the unrelated withdrawal D2 as paid by the same operator/txid, letting that operator claim `Reimburse` for D2's vault without ever funding D2's payout.

## Finding Description
The broken binding is: **one finalized payout record for withdrawal UTXO X == exactly one `deposit_id`'s vault spend.** The code enforces this only through the raw outpoint bytes, not through `idx`.

- `withdraw()` on the Citrea contract only takes `(txId, outputId)` bytes with no signature or uniqueness check, per [1](#0-0) . An attacker fully controls these bytes (per the problem statement's threat model) and can register the identical outpoint bytes `X` for two different withdrawal indices D1 and D2.
- `update_citrea_deposit_and_withdrawals` blindly copies whatever Citrea reports into the `withdrawals` table keyed by `idx`, with no dedup/uniqueness check across rows: [2](#0-1) .
- The `withdrawals` table schema has no `UNIQUE` constraint on `(withdrawal_utxo_txid, withdrawal_utxo_vout)`: [3](#0-2) .
- `get_payout_txs_for_withdrawal_utxos` joins `withdrawals` to `bitcoin_syncer_spent_utxos` **by outpoint value alone**: [4](#0-3) . If two `idx` rows (D1, D2) share the same `withdrawal_utxo_txid`/`vout`, and that outpoint is spent once (by the tx that funds D1's payout), this query returns **two** rows — `(D1, payout_txid)` and `(D2, payout_txid)` — for the same single spend.
- `update_finalized_payouts` then writes the same `payout_txid`, `operator_xonly_pk` (parsed from the payout tx's OP_RETURN), and block hash into **both** withdrawal rows: [5](#0-4) .
- `get_first_unhandled_payout_by_operator_xonly_pk` and `PayoutCheckerTask` will then surface D2 as an "unhandled payout" fronted by the operator who only actually paid D1, and drive `handle_finalized_payout`/kickoff/reimburse for D2's real, distinct move-to-vault UTXO: [6](#0-5) [7](#0-6) [8](#0-7) .

D1 and D2 have genuinely distinct, unrelated `move_to_vault_txid`s (real Bitcoin deposits), so the operator ends up reimbursed from D2's vault while never having paid D2's withdrawal beneficiary a single satoshi — the actual UTXO `X` was spent only once, to pay D1's recipient. Existing guards do not catch this: `sign_optimistic_payout`'s `is_utxo_spent` check and `withdraw()`'s `get_txout_from_outpoint` check [9](#0-8)  only prevent an operator from *fronting* the same UTXO twice on Bitcoin — they do nothing to stop the DB-level join from crediting a second, unrelated `idx` once the first payout is observed on-chain.

## Impact Explanation
An operator can be reimbursed (via the Reimburse transaction path) from a deposit's move-to-vault UTXO (D2) that it never actually fronted a payout for, because `update_finalized_payouts`/`get_payout_txs_for_withdrawal_utxos` conflates two distinct `deposit_id`s under one withdrawal-UTXO key. This directly matches the Critical category "an operator reimbursed for a payout it never funded." It is repeatable across any pair (or larger set) of withdrawals whose registered outpoint bytes collide, and the amount extracted per occurrence is up to one full `bridge_amount` per colliding extra `deposit_id`.

## Likelihood Explanation
The only precondition is that Citrea's `withdraw()` contract call accepts attacker-chosen `(txId, outputId)` bytes without checking they form a genuinely-unspent, unique Bitcoin UTXO or without deduplicating against previously registered withdrawal indices — consistent with the test harness's usage of `contract.withdraw(txId_bytes, vout_bytes)` taking raw bytes with no signature. Given that, the attacker needs only to submit two ordinary `withdraw()` calls with identical outpoint bytes; no verifier/operator/aggregator privilege, key material, or majority hashrate is required, and cost is limited to L2 gas plus one funded withdrawal input. Once an (any) operator legitimately pays out D1 by spending `X`, the bug fires automatically in `update_finalized_payouts` on the next processed block with no further attacker action needed.

## Recommendation
Key payout finalization strictly by withdrawal `idx`/`deposit_id`, not by outpoint bytes:
- Add a database-level `UNIQUE` constraint on `(withdrawal_utxo_txid, withdrawal_utxo_vout)` in the `withdrawals` table (or reject/flag a new withdrawal registration whose outpoint bytes already exist for another `idx`).
- In `get_payout_txs_for_withdrawal_utxos`, additionally verify that the payout transaction's inputs match the specific `idx`'s expected user signature/output, or at minimum ensure at most one `idx` is ever matched per spent outpoint (e.g., pick the row with the matching `move_to_vault_txid`/expected payout structure, not "all rows with same bytes").
- Reject duplicate withdrawal-UTXO registrations from Citrea entirely in `update_citrea_deposit_and_withdrawals`.

    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
            ));
        }

        self.db
            .update_payout_txs_and_payer_operator_xonly_pk(
                Some(dbtx),
                payout_txs_and_payer_operator_idx,
            )
            .await?;

        Ok(())
    }

    /// Returns the withdrawal indexes and their spending txid for the given
    /// block id.
    pub async fn get_payout_txs_for_withdrawal_utxos(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        block_id: u32,
    ) -> Result<Vec<(u32, Txid)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, TxidDB)>(
            "SELECT w.idx, bsu.spending_txid
             FROM withdrawals w
             JOIN bitcoin_syncer_spent_utxos bsu
                ON bsu.txid = w.withdrawal_utxo_txid
                AND bsu.vout = w.withdrawal_utxo_vout
             WHERE bsu.block_id = $1",
        )
        .bind(i32::try_from(block_id).wrap_err("Failed to convert block id to i32")?);

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_all)?;

        results
            .into_iter()
            .map(|(idx, txid)| {
                Ok((
                    u32::try_from(idx).wrap_err("Failed to convert withdrawal index to u32")?,
                    txid.0,
                ))
            })
            .collect()
    }

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }
