### Title
Missing validation of `kip71.gastarget` governance parameter allows a division-by-zero panic in `NextMagmaBlockBaseFee`, halting block processing network-wide - (File: `params/kip71_config.go`, `kaiax/gov/param.go`)

### Summary
The `kaiax/gov` module lets a governance parameter be set to any `uint64` value—including `0`—for `kip71.gastarget`, because its `FormatChecker` is the permissive `noopFormatChecker`. Unlike `kip71.basefeedenominator`, which is explicitly checked to be non-zero, `GasTarget` has no such guard either at the format-check layer or in the consumer code (`NextMagmaBlockBaseFee`), which uses it as a divisor. If `GasTarget` is ratified as `0`, every subsequent non-empty block causes a division-by-zero panic when the base fee is recalculated, crashing block validation across all nodes.

### Finding Description
The governance parameter table defines `Kip71GasTarget` with a no-op format checker that accepts any canonicalized `uint64`: [1](#0-0) 

Compare this to `Kip71BaseFeeDenominator`, which explicitly rejects `0`: [2](#0-1) 

Both header-governance votes and contract-governance (KIP-81) updates run values through the same canonicalizer/format-checker pipeline before acceptance: [3](#0-2) [4](#0-3) 

Since the format checker for `GasTarget` is a no-op, a value of `0` passes validation and can be ratified into the effective `ParamSet`/`ChainConfig.Governance.KIP71.GasTarget`.

The consensus-critical base-fee calculation then divides by `gasTarget` without checking for zero (unlike `baseFeeDenominator`, which has an explicit zero-fallback a few lines above): [5](#0-4) 

When `gasTarget == 0` and a block's used gas is non-zero (`parentGasUsed > gasTarget`), the code executes `x.Div(x, new(big.Int).SetUint64(gasTarget))` at the line computing `y`, dividing by zero, which panics in Go's `math/big`.

### Impact Explanation
`NextMagmaBlockBaseFee` is invoked from `VerifyMagmaHeader`, part of consensus block-header verification, meaning this panic would be triggered on every node validating any subsequent non-empty block once the poisoned `GasTarget=0` value takes effect: [6](#0-5) 

This is a chain-halting denial of service reachable purely by ratifying an unvalidated governance parameter — no code deployment, no smart-contract exploit, just a single vote value that the format checker fails to reject. This directly parallels the reported bug class (`updateUtilizationCurve` accepting an unchecked parameter struct that can make dependent computations revert), except here the missing validation leads to a hard panic across the entire network instead of a single contract revert.

### Likelihood Explanation
The governance parameter update path (single-mode governing node vote, or KIP-81 contract governance) is the intended, in-scope path for changing `kip71.gastarget`, exactly as `onlyOwnerOrParamAdmin` was the intended path in the original report. The bug requires no exceptional conditions: any ratified vote of `kip71.gastarget = 0` (a value that trivially passes `uint64Canonicalizer` and the no-op `FormatChecker`) is sufficient, and it will affect the very next non-empty block.

### Recommendation
Add a non-zero check to `Kip71GasTarget`'s `FormatChecker` (as already done for `Kip71BaseFeeDenominator`), e.g.:
```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0
    },
    ...
```
Additionally, add a defensive zero-check/fallback for `gasTarget` inside `NextMagmaBlockBaseFee`, mirroring the existing `BaseFeeDenominator == 0` fallback, so that even a value that slips through validation cannot crash consensus.

### Proof of Concept
1. As the governing node (single governance mode) or via KIP-81 contract governance, submit a vote/parameter update setting `kip71.gastarget = 0`.
2. The vote passes `NewVoteData`'s canonicalizer/format-checker pipeline unmodified, since `Kip71GasTarget`'s checker is `noopFormatChecker`.
3. Once ratified (at the next epoch boundary for header governance, or immediately visible for contract governance), `ChainConfig.Governance.KIP71.GasTarget` becomes `0`.
4. On the next block where `gasUsed > 0`, every node's call to `NextMagmaBlockBaseFee` (via `VerifyMagmaHeader`) executes `x.Div(x, new(big.Int).SetUint64(0))`, panicking and halting block processing network-wide.

	param, ok := gov.Params[gov.ParamName(name)]
	if !ok {
		param, ok = gov.ValidatorParams[gov.ParamName(name)]
		if !ok {
			logger.Error("Invalid vote name", "name", name)
			return nil
		}
	}

	cv, err := param.Canonicalizer(value)
	if err != nil {
		logger.Error("Canonicalize error", "name", name, "value", value, "err", err)
		return nil
	}

	if !param.FormatChecker(cv) {
		logger.Error("Format check error", "name", name, "value", value)
		return nil
	}

	return &voteData{
		voter: voter,
		name:  gov.ParamName(name),
		value: cv,
	}
}

func (kc *KIP71Config) VerifyMagmaHeader(headerBaseFee *big.Int, parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) error {
	if headerBaseFee == nil {
		return fmt.Errorf("header is missing baseFee")
	}
	// Verify the baseFee is correct based on the parent header.
	expectedBaseFee := kc.NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)
	if headerBaseFee.Cmp(expectedBaseFee) != 0 {
		return fmt.Errorf("invalid baseFee: have %s, want %s, parentBaseFee %s, parentGasUsed %d",
			headerBaseFee, expectedBaseFee, parentHeaderBaseFee, parentHeaderGasUsed)
	}
	return nil
}
