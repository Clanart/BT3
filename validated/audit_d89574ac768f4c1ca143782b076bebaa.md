### Title
Stale non-membership proof lets `handleGetRequestTimeouts` double-pay GET request fees and fire duplicate `onGetResponse`/`onGetTimeout` callbacks - (File: `evm/src/core/HandlerV2.sol`, `evm/src/core/EvmHost.sol`)

### Summary
The external report's core broken invariant is: a cross-chain executor fails to record that a call was already attempted/settled, so the same logical action can be replayed through a second path, causing duplicated effects. The Hyperbridge EVM analog is in the GET-request response/timeout pair: `EvmHost.dispatchIncoming(GetResponse,...)` never clears `_requestCommitments[commitment]` (or its `.fee`) after successfully delivering a response and paying the relayer, and `HandlerV2.handleGetRequestTimeouts` never checks the local `_responseReceipts` mapping before accepting a timeout — unlike the Substrate implementation which explicitly guards against this with `GetResponseAlreadyReceived`.

### Finding Description
On the EVM side, GET-request lifecycle state lives in two independent maps on `EvmHost.sol`:
- `_requestCommitments[commitment]` — set when the request is dispatched, holding `FeeMetadata{sender, fee}` [1](#0-0) 
- `_responseReceipts[commitment]` — set only when a response is successfully delivered locally [2](#0-1) 

When a response is delivered via `dispatchIncoming(GetResponse,...)`, on success the relayer is paid `_requestCommitments[commitment].fee`, but `_requestCommitments[commitment]` itself is never deleted: [3](#0-2) 

Compare this with the POST-timeout and GET-timeout dispatch functions, which explicitly delete `_requestCommitments[commitment]` for replay protection and restore it only on module callback failure: [4](#0-3) 

`HandlerV2.handleGetRequestTimeouts` gates a timeout purely on: challenge-period elapsed, `request.timeout() > state.timestamp` at the *proof height*, `meta.sender != 0`, and a non-membership proof (against Hyperbridge's state root at `message.height`) that no `RESPONSE_RECEIPTS_STORAGE_PREFIX+commitment` entry exists there: [5](#0-4) 

Critically, it never checks the *local* `_responseReceipts` mapping on the source host — the only place that reflects whether the response has already been delivered and settled on this chain. `EvmHost` retains state commitments for every previously certified height (`_stateCommitments[stateMachineId][height]`), so an attacker can submit a `GetTimeoutMessage` anchored at an **older, already-accepted** Hyperbridge height whose timestamp is past the request's `timeoutTimestamp` and at which Hyperbridge had not yet generated the response (hence a truthful, verifiable non-membership proof), even though a newer Hyperbridge height already produced the response and it was already delivered and paid out on the source chain via `dispatchIncoming(GetResponse,...)`.

This mirrors the exact confirmed semantics from the Substrate implementation, where Hyperbridge itself records `response_receipt` when it produces a GET response and rejects duplicate production: [6](#0-5) , and where the Substrate timeout handler explicitly checks `host.response_receipt(&response).is_some()` before allowing a timeout: [7](#0-6) . The EVM `HandlerV2.handleGetRequestTimeouts` has no equivalent local guard.

### Impact Explanation
Since `_requestCommitments[commitment].fee` survives a successful response delivery, submitting a stale-but-validly-provable timeout after the response was already paid causes `dispatchTimeOut(GetRequestTimeout,...)` to refund `meta.fee` to `meta.sender` a second time: [4](#0-3) 
This drains the fee token held by `EvmHost` (double payment of the same fee: once to the relayer via `dispatchIncoming(GetResponse)`, once refunded to the payer via `dispatchTimeOut(GetRequestTimeout)`), a direct loss of protocol/user funds. It also invokes `onGetTimeout()` on the application module after `onGetResponse()` already fired for the same request — a duplicate, contradictory settlement callback that application modules are not required to guard against, enabling double-settlement bugs in downstream apps (e.g., an app that reverses or re-credits state on timeout after having already committed effects on response).

### Likelihood Explanation
The path is fully permissionless — any relayer or unprivileged actor can call `handleGetRequestTimeouts` with a previously-accepted, valid consensus-proven Hyperbridge state height and a truthful non-membership proof for that height. No malicious relayer collusion, prover compromise, or admin action is required; only patience to acquire an older still-retrievable state commitment and construct a request whose `timeoutTimestamp` falls before that older height's timestamp but after the request was already answered at a later height — a realistic scenario for short-timeout GET requests answered near their expiry.

### Recommendation
- In `EvmHost.dispatchIncoming(GetResponse,...)`, delete (or zero the `.fee` field of) `_requestCommitments[commitment]` once the response has been successfully delivered, mirroring the replay-protection pattern already used for POST/GET timeout dispatch.
- In `HandlerV2.handleGetRequestTimeouts`, add an explicit local check `if (host.responseReceipts(commitment).relayer != address(0)) revert DuplicateMessage();` before accepting the non-membership proof, matching the Substrate handler's `GetResponseAlreadyReceived` guard.

### Proof of Concept
1. Dispatch `DispatchGet` on chain A with a short `timeout` (e.g., 60s), paying `fee` in `feeToken`; `_requestCommitments[commitment] = {sender, fee}` is written (`evm/src/core/EvmHost.sol:921-948`).
2. Hyperbridge processes the query and, near the request's timeout window, produces the `GetResponse`, recording its own `response_receipt` at Hyperbridge height H2.
3. A relayer delivers the response to chain A via `HandlerV2.handleGetResponses` → `EvmHost.dispatchIncoming(GetResponse,...)`; `_responseReceipts[commitment]` is set and the relayer is paid `meta.fee`, but `_requestCommitments[commitment]` (with `fee` still populated) is left untouched (`evm/src/core/EvmHost.sol:824-847`).
4. An attacker, holding an earlier already-consensus-certified Hyperbridge height H1 (< H2, before the response existed) whose `state.timestamp` is already past the GET request's `timeoutTimestamp`, constructs a truthful non-membership proof for `RESPONSE_RECEIPTS_STORAGE_PREFIX+commitment` at H1 and calls `HandlerV2.handleGetRequestTimeouts(host, message)` with `message.height = H1` (`evm/src/core/HandlerV2.sol:293-321`).
5. All checks pass (`meta.sender != 0` still true, proof at H1 truthfully shows no receipt yet, `request.timeout() > state.timestamp` at H1 passes since H1's timestamp already exceeds `timeoutTimestamp`); `EvmHost.dispatchTimeOut(GetRequestTimeout,...)` executes, refunding `meta.fee` to the original payer a second time and firing `onGetTimeout()` on the app module after it already received `onGetResponse()`.

        bytes32 commitment

        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)

            // so that it can be retried

            return;

            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
