### Title
Data Layer mirror URLs are fetched via outbound HTTP with no host/address-class validation, enabling SSRF against DataLayer subscribers - (File: `chia/data_layer/download_data.py`)

### Summary
Chia's DataLayer lets any wallet owner publish arbitrary mirror URLs on-chain for their store via `DataLayer.add_mirror()`, which forwards user-supplied `urls` straight to the wallet RPC with only a "non-empty" check [1](#0-0) . Every other node that subscribes to that store id will later pull these URLs into its local `update_subscription()`/`fetch_and_validate()` loop and issue outbound HTTP GET requests to them via `http_download()`, with no host/IP-class validation whatsoever [2](#0-1) . This is the same bug class as the Appsmith SSRF advisory (outbound requests to attacker-influenced hosts reaching loopback/internal services), except here there isn't even a flawed denylist — there is no filtering at all.

### Finding Description
`add_mirror` accepts a list of URLs and only rejects an empty list before publishing them on-chain through `dl_new_mirror` [1](#0-0) . These URLs are later retrieved by any node subscribing to the store via `update_subscriptions_from_wallet()` [3](#0-2)  and used as candidate `ServerInfo.url` values in `fetch_and_validate()`, which randomly selects a server and calls `insert_from_delta_file()` with that URL [4](#0-3) . `insert_from_delta_file()` calls `download_file()`, which — when no downloader plugin is configured — calls `http_download()` directly against `server_info.url + "/" + filename` using `aiohttp.ClientSession` with no scheme/host/IP validation [5](#0-4) . There is no check anywhere in this path (add_mirror → wallet RPC → subscription sync → fetch_and_validate → download_file → http_download) that rejects loopback (`127.0.0.1`), link-local, `0.0.0.0`, or other internal/private addresses — unlike the SMTP-only address-class check referenced in the Appsmith advisory, DataLayer's HTTP fetch path has no equivalent check at all.

### Impact Explanation
Any DataLayer store owner can publish mirror URLs pointing at loopback-bound services or internal network addresses on the machines of every peer that subscribes to their store (`add_mirror` -> `dl_new_mirror`, confirmed via `test_mirrors` even uses `http://127.0.0.1/8000` style URLs in the test suite itself as a valid-looking URL [6](#0-5) ). Subscribing nodes will automatically issue outbound HTTP GET requests to attacker-chosen hosts/ports as part of routine periodic sync (`periodically_manage_data()` / `update_subscription()`), which is a classic SSRF primitive that can be used to probe or interact with services bound to localhost or internal networks on those subscribers' hosts.

### Likelihood Explanation
Any wallet user who can create/own a DataLayer store and call the `add_mirror` RPC can trigger this; no special privilege beyond normal DataLayer usage is required, and any other Data Layer client that subscribes to the store will automatically perform the outbound fetch during its normal background sync loop.

### Recommendation
Validate mirror URLs at publish time (`DataLayer.add_mirror`) and/or at fetch time (`http_download`/`download_file`) by resolving the host and rejecting loopback, link-local, unspecified, and other non-public/internal address ranges, mirroring the address-class checks that exist elsewhere in the codebase (e.g., the SMTP-equivalent check referenced in the Appsmith fix) before allowing the URL to be stored or dereferenced.

### Proof of Concept
1. Node A creates a DataLayer store and calls `add_mirror(store_id, urls=["http://127.0.0.1:<internal-port>/"], amount=1, fee=1)` [1](#0-0) .
2. Node B subscribes to Node A's store id; its periodic sync calls `update_subscriptions_from_wallet()` and picks up the malicious URL [3](#0-2) .
3. Node B's `fetch_and_validate()` selects the malicious server and calls `insert_from_delta_file()` → `download_file()` → `http_download()`, which performs `session.get("http://127.0.0.1:<internal-port>/" + filename, ...)` from Node B's own process [2](#0-1) , demonstrating outbound requests to attacker-chosen internal/loopback endpoints with no filtering.

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
