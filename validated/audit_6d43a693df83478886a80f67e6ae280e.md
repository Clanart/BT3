### Title
Naive substring-matching in `isGitHubHost()` lets an attacker-controlled git remote spoof a "GitHub Enterprise" identity and trigger a native credential/sign-in prompt for a malicious host - (File: `app/src/lib/api.ts`)

### Summary
`LibUsdOracle`'s bug was a hardcoded, network-specific assumption (`chainlinkRegistry` address) baked into a security-relevant lookup, which silently returns wrong/broken data whenever the assumption doesn't hold for the actual deployment target. The Desktop analog is the heuristic hostname classifier `isGitHubHost()` (and its caller `getEndpointKind()` in the git-credential trampoline), which uses a naive regex/substring check to decide whether an arbitrary remote host is a trusted GitHub Enterprise instance. Just like the oracle assumed "this address is always the right registry," this code assumes "any hostname containing `github.` as a label is a real GitHub host" — an assumption that is trivially false and attacker-controlled.

### Finding Description
`isGitHubHost()` is a best-effort classifier used to decide whether a git remote endpoint should be treated as GitHub Enterprise: [1](#0-0) 

After ruling out real GitHub.com/`ghe.com` endpoints and a short allow-list of known third-party hosts (`dev.azure.com`, `gitlab.com`, `bitbucket.org`, `amazonaws.com`, `visualstudio.com`), it falls back to a bare regex:

```js
// github.example.com,
if (/(^|\.)(github)\./.test(hostname)) {
  return true
}
``` [2](#0-1) 

This matches ANY hostname that starts with, or has a label equal to, `github.` — including attacker-registered domains like `github.attacker.com`, `github.com.attacker.io`, or `github-enterprise.attacker.net` are not caught (only the strict `github.` prefix/label matches, but that's exactly what an attacker can register). There is no relation to the real `github.com`/`*.ghe.com` domains that `isDotCom`/`isGHE` check with exact hostname comparisons: [3](#0-2) 

This classifier feeds directly into the git credential trampoline's decision logic, `getEndpointKind()`, which is invoked every time Git needs credentials for a remote (clone/fetch/push): [4](#0-3) 

Note also that this function has a second broken shortcut: a `WWW-Authenticate` header with `realm="GitHub"` returned by ANY server is trusted outright to classify the host as `'enterprise'`, with no domain check at all: [5](#0-4) 

When `getEndpointKind()` returns `'enterprise'` for an attacker's host and no existing account matches that endpoint, `getCredential()` calls `ui.promptForGitHubSignIn(endpoint)`: [6](#0-5) 

`promptForGitHubSignIn()` then drives the dispatcher into the real "Sign in to GitHub Enterprise" UI flow, pointed at the attacker's `origin`: [7](#0-6) [8](#0-7) 

The broken invariant: the app decides "is this a trustworthy GitHub host that deserves my native sign-in/credential UI" using a substring match on the hostname instead of validating it against the real GitHub.com/`ghe.com` domain suffixes (the same class of mistake as hardcoding a mainnet-only registry address and using it unconditionally regardless of the real deployment target). Existing guards (`isDotCom`, `isGHE`, `isKnownThirdPartyHost`) are all exact-suffix/exact-hostname checks and do not protect against this fallback regex, because the fallback is specifically designed to catch cases those checks miss — it just does so far too permissively.

### Impact Explanation
A user who adds/clones from (or is redirected to) a repository whose remote hostname contains the label `github.` (fully attacker-controlled domain, e.g. `github.attacker-corp.com`) will have GitHub Desktop's own trampoline present a native "Sign in to GitHub Enterprise" dialog scoped to that attacker's origin. Because this is the app's own trusted-looking sign-in UI (not a webpage the user has to judge), it meaningfully increases the chance the user enters a Personal Access Token or completes an OAuth device/browser flow against attacker infrastructure, exfiltrating credentials. This satisfies the "unauthorized OAuth or credential/token exfiltration triggered by attacker-controlled remote" category explicitly listed as valid impact.

### Likelihood Explanation
The attacker only needs to control a git remote/host with a hostname containing the `github.` label (cheap, no privileged access required) and have the victim add/clone/fetch that remote in Desktop, or return a spoofable `WWW-Authenticate: realm="GitHub"` header on any HTTPS git server. Both are entirely within a normal, unprivileged "malicious remote" attacker model — no local access, no leaked credentials, and no unnatural extra steps beyond what Desktop already does automatically when authenticating to a new remote (the git credential trampoline flow is triggered automatically during clone/fetch/push).

### Recommendation
Replace the loose regex fallback in `isGitHubHost()` with a check that only trusts explicit, exact-suffix domain matching (mirroring `isDotCom`/`isGHE`), and remove/harden the `WWW-Authenticate: realm="GitHub"` shortcut in `getEndpointKind()` so it cannot be spoofed by an arbitrary server response. At minimum, any host that doesn't match an exact GitHub.com/`*.ghe.com` suffix should require the network-based `/meta` header verification (`x-github-request-id`) currently used later in the function, rather than being short-circuited to `true` by a substring test on the hostname.

### Proof of Concept
1. Attacker stands up an HTTPS git server at `https://github.attacker-corp.com/evil/repo.git` (no relation to real GitHub).
2. Victim, using GitHub Desktop, clones or adds this repository (e.g., via a link/deep-link or by adding an existing repo with this remote).
3. Git invokes the Desktop credential trampoline for the `get` operation; `getEndpointKind()` runs:
   - `isDotCom`/`isGHE`/`isKnownThirdPartyHost` all return `false`.
   - No `WWW-Authenticate` header present yet on first pass, no existing account for this host.
   - `isGitHubHost('https://github.attacker-corp.com')` is called → hostname `github.attacker-corp.com` matches `/(^|\.)(github)\./` → returns `true` → `getEndpointKind` returns `'enterprise'`.
4. `getCredential()` sees `endpointKind !== 'generic'` and no matching account, so it calls `ui.promptForGitHubSignIn('https://github.attacker-corp.com/...')`.
5. Desktop shows its native "Sign in to GitHub Enterprise" popup, pre-scoped to the attacker's origin; if the victim enters a PAT or completes OAuth, the credential is sent to attacker infrastructure. [2](#0-1) [6](#0-5)

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

export const isDotCom = (ep: string) => {
  if (ep === getDotComAPIEndpoint()) {
    return true
  }

  const { hostname } = new URL(ep)
  return hostname === 'api.github.com' || hostname === 'github.com'
}

export const isGist = (ep: string) => {
  const { hostname } = new URL(ep)
  return hostname === 'gist.github.com' || hostname === 'gist.ghe.io'
}

/** Whether or not the given endpoint URI is under the ghe.com domain */

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
