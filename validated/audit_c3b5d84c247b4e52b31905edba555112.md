### Title
Unbounded Python recursion in wallet puzzle-driver matching allows a malicious offer/coin spend to crash the wallet process (`chia/wallet/outer_puzzles.py`, `chia/wallet/puzzles/puzzle_drivers.py`)

### Summary
The axios advisory describes an attacker-controlled key structure (`FormData` bracket segments) driving an unbounded recursive parser (`buildPath`) with no depth guard, causing `RangeError: Maximum call stack size exceeded` and process crash. Chia's wallet-side puzzle-driver dispatch (`match_puzzle()` in `chia/wallet/outer_puzzles.py`) has the same shape: it recursively descends into nested "outer puzzle" layers (CAT, singleton, ownership, metadata, credential-restricted, revocation) with no maximum-depth check, and the recursion depth is entirely controlled by an untrusted puzzle reveal that an unprivileged counterparty can hand to a wallet via an offer file or an observed coin spend.

### Finding Description
`match_puzzle()` iterates the registered outer-puzzle drivers and calls `driver.match(puzzle)`: [1](#0-0) 

Each driver's `match()` implementation recurses into the puzzle's inner layer via `self._match(...)`, which is bound back to `match_puzzle` itself: [2](#0-1) 

For example, `CATOuterPuzzle.match()`: [3](#0-2) 

and `CROuterPuzzle.match()`, `OwnershipOuterPuzzle.match()`, `MetadataOuterPuzzle.match()`, `SingletonOuterPuzzle.match()` all follow the identical pattern of unconditionally recursing one level per curried "also" layer with no depth counter or recursion limit: [4](#0-3) [5](#0-4) 

Each recursion step also triggers `UnknownPuzzle` uncurrying (`chia/wallet/puzzles/puzzle_drivers.py:67-83`), which performs a full `uncurry_puzzle()` at every layer. None of this path has any bound on nesting depth analogous to `formToJSON`'s missing `maxDepth`; it is pure Python-level recursion, not CLVM cost-metered execution, so the CLVM "max cost" mempool defenses do not apply to it.

This dispatcher is reached from wallet code that inspects untrusted puzzle reveals supplied by a counterparty or a peer, most directly:
- `Offer._get_offered_coins()` calls `match_puzzle(parent_puzzle)` on every `parent_spend.puzzle_reveal` taken directly from an externally supplied offer/spend bundle: [6](#0-5) 
- `Offer.from_spend_bundle()` (used by `Offer.from_bytes()` / `Offer.from_bech32()`, i.e. parsing an offer string handed to the wallet by any counterparty) also calls `match_puzzle` on every coin spend's puzzle reveal before any CLVM execution or cost accounting occurs: [7](#0-6) 

Because `curry()`/`uncurry()` construction is a pure Python-level CLVM tree operation with no depth limit and effectively free of "cost", an attacker can build a puzzle reveal that curries thousands of nested outer-layer wrappers (e.g., repeatedly wrapping a CAT puzzle inside another CAT puzzle, or stacking ownership/metadata/CR layers) around a trivial inner puzzle. Constructing such a puzzle client-side costs the attacker nothing meaningful, and delivering it as an offer file (`.offer`) or exposing it as a coin's puzzle reveal that the victim wallet later fetches costs no fee at all since `Offer.from_bech32()` parses the offer purely locally before any spend is broadcast or validated by consensus.

### Impact Explanation
When a wallet user (or the trade manager / wallet RPC / `chia offers` CLI) loads a maliciously crafted offer, or a wallet observes a coin whose parent puzzle reveal contains thousands of nested outer-puzzle layers, `match_puzzle()`'s recursion exceeds Python's default recursion limit and raises `RecursionError`. This is a spend/offer-triggered transaction-processing halt: it can crash the wallet RPC service handling `get_offer_summary`, `check_offer_validity`, or offer acceptance, denying wallet service to the user with a single attacker-crafted offer file — directly analogous to the axios `formToJSON` DoS, where a crafted structured input with unbounded nesting exhausts the call stack in a code path lacking a depth guard. This matches the required "spend-triggered transaction-processing halt" impact category (Medium severity), reachable by any offer counterparty without needing a valid signature or fee since offer parsing/summarization occurs before broadcast or full consensus validation.

### Likelihood Explanation
Likelihood is high for any wallet user who opens/inspects an untrusted `.offer` file or accepts offers from arbitrary counterparties (a routine wallet action), since building the malicious puzzle reveal requires no special access, no fee payment, and no interaction with consensus — it is a pure local Python object construction performed by the victim's own wallet when it parses the offer.

### Recommendation
Add an explicit maximum recursion/nesting-depth guard to `match_puzzle()` and to each outer-puzzle driver's `.match()`/`.get_inner_puzzle()`/`.get_inner_solution()`/`.solve()` recursive chain (e.g., a `depth` parameter passed through `_match`/`_get_inner_puzzle`/etc. with a hard cap, similar to how `toFormData` in the axios fix enforces `maxDepth`), or convert the "also" chain traversal to an iterative loop instead of mutual Python recursion. Reject offers/puzzle reveals whose outer-layer nesting exceeds the cap before dispatching to `match_puzzle`.

### Proof of Concept
```python
from chia.types.blockchain_format.program import Program
from chia.wallet.cat_wallet.cat_utils import CAT_MOD
from chia.wallet.outer_puzzles import match_puzzle
from chia.wallet.puzzles.puzzle_drivers import UnknownPuzzle

# Build a puzzle with thousands of nested CAT outer-layers around a trivial inner puzzle.
inner = Program.to(1)
puzzle = inner
tail_hash = b"\x00" * 32
for _ in range(5000):
    puzzle = CAT_MOD.curry(CAT_MOD.get_tree_hash(), tail_hash, puzzle)

unknown = UnknownPuzzle(known_program=puzzle)
match_puzzle(unknown)  # raises RecursionError: maximum recursion depth exceeded
```
Delivering `puzzle` as the `puzzle_reveal` of a coin spend inside an `Offer` (via `Offer.from_bech32`) causes the same `RecursionError` when the victim wallet calls `Offer._get_offered_coins()` / `get_offer_summary`, crashing the wallet RPC request handling that offer.
