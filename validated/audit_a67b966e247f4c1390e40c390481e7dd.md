Confirmed: `harvest(address _lpToken)` on `WombatStaking` is permissionless (only `whenNotPaused` + `_onlyActivePool`, no caller restriction), and it triggers `_toMasterWomAndSendReward` → `queueNewRewards` on `BaseRewardPoolV2`, which immediately folds the harvested reward into `rewardPerTokenStored` based on `totalStaked()` *at that instant* [1](#0-0) [2](#0-1) . Deposits into `MasterMagpie`/pool helpers are un-gated and instantly increase the depositor's `balanceOf`/share used in the reward-per-token math [3](#0-2) .

### Title
Front-runnable reward harvest lets any wallet snipe already-accrued yield via flash deposit/withdraw - (File: wombat/WombatStaking.sol, rewards/BaseRewardPoolV2.sol)

### Summary
`WombatStaking.harvest()` is callable by any address with no cooldown or access restriction beyond the pool being active [1](#0-0) . It pulls the WOM reward that has accrued in Wombat's `MasterWombat` over time and immediately calls `queueNewRewards` on the pool's `BaseRewardPoolV2`, which folds the entire reward amount into `rewardPerTokenStored` in a single step, proportional to `totalStaked()` at that exact block [2](#0-1) . There is no time-vesting/streaming of rewards and no minimum staking duration enforced in `MasterMagpie._deposit`/`_withdraw` [4](#0-3) .

### Finding Description
Because `rewardPerTokenStored` jumps instantly and rewards are shared strictly by current stake ratio (`_earned` uses `rewardPerToken(_rewardToken) - userRewardPerTokenPaid`) [5](#0-4) , an attacker who deposits into the pool immediately before calling (or being included in the same block as) `harvest()`/`castVotes()` captures a proportional share of yield that accrued entirely before their deposit, diluting the rewards legitimately earned by long-term stakers. This mirrors the reported bug class: a permissionless state transition (there: emergency-status grant; here: harvest/reward injection) creates an atomic window in which an opportunistic party can insert a large, short-lived position to intercept value that was never meant to accrue to them, then immediately reverse the position (`withdraw`) once the payout is locked in.

### Impact Explanation
This is a direct theft of already-accrued, unclaimed yield from existing LPs/stakers, redistributing it to a flash depositor who contributed no time-weighted stake to earning it. It satisfies "theft or permanent freezing of unclaimed yield" for the affected reward pool, since diluted stakers permanently lose their proportional share of that specific reward tranche.

### Likelihood Explanation
`harvest()` is unauthenticated and can be called by anyone (or bundled by the depositor themselves) [6](#0-5) , and `MasterMagpie.deposit`/`withdraw` have no lock-up, cooldown, or fee that would prevent same-block deposit-harvest-withdraw sequences [7](#0-6) . This is trivially executable in a single transaction (flash-loan-funded stake, if the staking token is a liquid LP/receipt token) or across adjacent blocks by any ordinary wallet, requiring no special privilege.

### Recommendation
Introduce a minimum holding period or linear reward-streaming (vesting the queued reward over a duration, as accumulator-based `BaseRewardPool` implementations often do) instead of instantaneously crediting `rewardPerTokenStored` for the full amount. Alternatively, snapshot eligible balances prior to the block in which `queueNewRewards` executes, or require deposits to "settle" for at least one full reward-harvest cycle before being eligible for that cycle's rewards.

### Proof of Concept
1. Wombat's `MasterWombat` accrues WOM rewards for an LP pool over time; nobody has called `harvest()` for a while, so a large reward is pending.
2. Attacker deposits a large amount of the pool's staking/receipt token into `MasterMagpie` (or via `WombatPoolHelperV2.deposit`) immediately before the harvest call: `_deposit` increases `user.amount`/`user.available` and sets `rewardDebt`, with no lock time [3](#0-2) .
3. Attacker (or anyone) calls `WombatStaking.harvest(_lpToken)`, which routes the full pending WOM reward into `BaseRewardPoolV2.queueNewRewards`, instantly increasing `rewardPerTokenStored` based on current `totalStaked()`, which now includes the attacker's fresh deposit [1](#0-0) [2](#0-1) .
4. Attacker immediately calls `withdraw`/`getReward` to claim their proportional share of the just-added reward and withdraw their principal, having held the position for at most one transaction/block while collecting a slice of yield accrued over the entire prior harvest interval.

        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;

        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingTokenDecimals) /
                totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);

    function _deposit(address _stakingToken, address _account, uint256 _amount, bool _isVlmgp) internal {
        updatePool(_stakingToken);

        PoolInfo storage pool = tokenToPoolInfo[_stakingToken];
        UserInfo storage user = userInfo[_stakingToken][_account];

        if (user.amount > 0) {
            _harvestMGP(_stakingToken, _account);
        }
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount + _amount;
        if (!_isVlmgp) {
            user.available = user.available + _amount;
            IERC20(pool.stakingToken).safeTransferFrom(address(msg.sender), address(this), _amount);
        }
        user.rewardDebt = (user.amount * pool.accMGPPerShare) / 1e12;

        if (_amount > 0)
            if (!_isVlmgp)
                emit Deposit(_account, _stakingToken, _amount);
            else
                emit DepositNotAvailable(_account, _stakingToken, _amount);
    }
