Based on the investigation, I found a plausible analog in the Chia pooling code, but with lower confidence than a typical high-severity finding because the exact end-to-end attacker-controlled input path could not be fully confirmed within available context.

### Title
Missing zero-puzzle-hash validation on pool `target_puzzle_hash` allows claimed pool rewards to be sent to a burn address - (File: `chia/pools/pool_wallet.py`)

### Summary
`PoolWallet._verify_pool_state()` and its helpers `_verify_self_pooled()` / `_verify_pooling_state()` validate several `PoolState` fields (protocol version, `pool_url`, `relative_lock_height`) but only check `target_puzzle_hash is None`, never that it is not the all-zero puzzle hash. `target_puzzle_hash` is the address that `PoolWallet.claim_pool_rewards()` later pays the entire absorbed reward amount to. This mirrors the reported `SdtBuffer.pullRewards` bug class: an unchecked destination address for a reward/payout flow that can end up equal to the zero address, permanently burning value instead of erroring out.

### Finding Description
`PoolState.target_puzzle_hash` is documented as "the final destination" for pool rewards [1](#0-0) . It is set/updated by `PoolWallet.update_pool_config()` and is what gets used directly as the transaction's output puzzle hash in `claim_pool_rewards()`: [2](#0-1) 

The only gate on `target_puzzle_hash` before a `PoolState` is accepted is in `_verify_pool_state`: [3](#0-2) 

This only rejects `None`; it does not reject `bytes32(32 * b"\x00")` (the all-zero puzzle hash) or other unspendable/degenerate hashes. `_verify_self_pooled` and `_verify_pooling_state` add checks for `pool_url` and `relative_lock_height` but nothing about the puzzle-hash value itself: [4](#0-3) 

Separately, the farmer-side/CLI mirror (`PoolingShareState`) also allows `target_puzzle_hash`/`payout_instructions` to be set to the zero address without validation, as shown by the existing test that explicitly sets `pool_config.target_puzzle_hash = bytes32(32 * b"0")` and a zero-address `payout_instructions` and the flow succeeding: [5](#0-4) . The CLI helper `change_payout_instructions` also writes whatever address the caller supplies with no zero-hash check: [6](#0-5) .

### Impact Explanation
If a `target_puzzle_hash` of all zeros (or another provably unspendable/burn hash) is ever accepted into `PoolState` — whether via a malicious/misbehaving pool server's protocol response driving `FARMING_TO_POOL` state, an operator/CLI mistake, or a bug elsewhere that fails to populate this field — `claim_pool_rewards()` will construct a valid, correctly-signed transaction that pays the entire absorbed pool-reward balance to that puzzle hash, permanently destroying the funds with no on-chain error, matching the reported bug's impact of "rewards sent to 0 address."

### Likelihood Explanation
This is lower likelihood than the original finding because reaching this state normally requires either the pool operator or the local user/CLI to supply a bad `target_puzzle_hash`, and I could not fully trace whether an external, less-trusted pool server response can set this field without any local wallet-side confirmation (the exact code path from `PutFarmerPayload`/`/pool_info` into `PoolState.target_puzzle_hash` was not fully verified in the time available). The CLI path (`change_payout_instructions`) is directly reachable by the local wallet operator with no validation.

### Recommendation
Add an explicit check in `PoolWallet._verify_pool_state()` (and in `change_payout_instructions`/`PoolWallet.update_pool_config()`) rejecting `target_puzzle_hash == bytes32(32 * b"\x00")` (and ideally any known burn addresses), similar to the recommended `require(processor != address(0))` fix in the original report.

### Proof of Concept
1. Create a plot NFT / pool wallet and drive it into `FARMING_TO_POOL` (or self-pooling) state.
2. Cause `PoolState.target_puzzle_hash` (or the mirrored `PoolingShareState.target_puzzle_hash`) to be set to `bytes32(32 * b"\x00")`, as already exercised in the existing test fixture `test_plotnft_cli_change_payout` [5](#0-4) .
3. Call `PoolWallet.claim_pool_rewards()`; the resulting `TransactionRecord`/`WalletSpendBundle` pays `total_amount` to the zero puzzle hash, per [2](#0-1) , with no validation rejecting the zero address.

    def _verify_self_pooled(cls, state: PoolState) -> str | None:
        err = ""
        if state.pool_url not in {None, ""}:
            err += " Unneeded pool_url for self-pooling"

        if state.relative_lock_height != 0:
            err += " Incorrect relative_lock_height for self-pooling"

        return None if err == "" else err

    @classmethod
    def _verify_pooling_state(cls, state: PoolState) -> str | None:
        err = ""
        if state.relative_lock_height < cls.MINIMUM_RELATIVE_LOCK_HEIGHT:
            err += (
                f" Pool relative_lock_height ({state.relative_lock_height})"
                f"is less than recommended minimum ({cls.MINIMUM_RELATIVE_LOCK_HEIGHT})"
            )
        elif state.relative_lock_height > cls.MAXIMUM_RELATIVE_LOCK_HEIGHT:
            err += (
                f" Pool relative_lock_height ({state.relative_lock_height})"
                f"is greater than recommended maximum ({cls.MAXIMUM_RELATIVE_LOCK_HEIGHT})"
            )

        if state.pool_url in {None, ""}:
            err += " Empty pool url in pooling state"
        return err

    @classmethod
    def _verify_pool_state(cls, state: PoolState) -> str | None:
        if state.target_puzzle_hash is None:
            return "Invalid puzzle_hash"

        if state.version > POOL_PROTOCOL_VERSION:
            return (
                f"Detected pool protocol version {state.version}, which is "
                f"newer than this wallet's version ({POOL_PROTOCOL_VERSION}). Please upgrade "
                f"to use this pooling wallet"
            )

        if state.state == PoolSingletonState.SELF_POOLING.value:
            return cls._verify_self_pooled(state)
        elif state.state in {PoolSingletonState.FARMING_TO_POOL.value, PoolSingletonState.LEAVING_POOL.value}:
            return cls._verify_pooling_state(state)
        else:
            return "Internal Error"
