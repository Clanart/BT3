### Title
Race condition between `BidPool.stop()` channel closure and `BidPool.AddBid()` causes panic on closed channel - ([File: kaiax/auction/impl/bid_pool.go])

### Summary
`BidPool.AddBid()` guards its execution with a single atomic check (`atomic.LoadUint32(&bp.running) == 0`) and, if the pool is "running", proceeds to validate the bid, insert it into internal maps, and finally send it on the unbuffered-except-for-2048-slot `bp.newBidCh` channel. Concurrently, `BidPool.stop()` flips `running` to 0 and then closes `bp.bidMsgCh`/`bp.newBidCh`. Because the "is running" check in `AddBid` and the later `bp.newBidCh <- bid` send are not covered by the same lock/synchronization as `stop()`'s channel-closing logic, a goroutine that passed the `running` check can still be executing when `stop()` closes the channel, causing a "send on closed channel" panic — the same class of defect as the referenced Linux `n_gsm` bug, where a cleanup routine (`gsm_cleanup_mux`) frees/tears down resources while another code path (`gsm_modem_update`) still assumes the resource is live and touches it, causing a kernel panic.

### Finding Description
`AddBid` is reachable directly from the public `auction_submitBid` RPC (`AuctionAPI.SubmitBid` → `bp.AddBid(bid)`), so any unprivileged auction bidder can trigger it. [1](#0-0) 

`AddBid` checks `bp.running` once at the top, then does validation and insertion work, and finally unconditionally sends on `bp.newBidCh`: [2](#0-1) 

`stop()` is not synchronized with `AddBid`'s check-then-act sequence: it flips `running` to 0, clears the pool, and then closes both channels that `AddBid`/`handleBidMsg` write to: [3](#0-2) 

`stop()` is invoked from `AuctionModule.Stop()`, which in turn is invoked as part of the kaiax module lifecycle (e.g., on auction disablement/module lifecycle transitions triggered by block processing or node shutdown paths): [4](#0-3) 

There is no lock or WaitGroup preventing a bidder's in-flight `AddBid` call (which already passed the `running==1` check) from executing `bp.newBidCh <- bid` after `stop()` has closed `newBidCh`. Sending on a closed channel in Go always panics, and since this pool is used by the CN's auction subsystem in block-production critical path, the panic crashes the node process.

### Impact Explanation
This is a remotely triggerable denial-of-service: a public-RPC auction bidder submitting a bid concurrently with a legitimate stop/restart of the auction module (e.g. triggered by governance disabling auction, insufficient-balance auto-disable, or module reinitialization on reorg/shutdown sequences) can cause the node to panic ("send on closed channel"), crashing the CN. This matches the "Medium/High, crash/DoS-reachable-from-one-transaction-or-RPC-call" bar because a single attacker-controlled `SubmitBid` RPC call racing with pool lifecycle transitions on the node side is sufficient to trigger a panic that halts block production on that node.

### Likelihood Explanation
Exploitation requires winning a narrow race window between the atomic `running` check in `AddBid` and the `close()` calls in `stop()`. This window is small under normal conditions but is systematically reachable: an attacker can flood `auction_submitBid` calls to maximize the probability of overlapping with any legitimate `stop()`/`start()` cycle (module toggling, node restart, or the balance-triggered auto-disable path). No special privilege is required — only the ability to call the public auction RPC.

### Recommendation
Synchronize the "is running" check with the channel send under the same lock used for `bidMu`, or replace the plain channel close with a `sync.Once`-guarded shutdown combined with holding a `sync.RWMutex`/reference count across the entire `AddBid` critical section (from the running check through the channel send), so that `stop()` cannot close the channels while an `AddBid` call is in flight. Alternatively, avoid closing `newBidCh`/`bidMsgCh` altogether and instead use a `done`/context-cancellation signal that `AddBid` selects on when sending, e.g. `select { case bp.newBidCh <- bid: case <-bp.done: return ...}`, eliminating the send-on-closed-channel panic path entirely.

### Proof of Concept
1. Start a CN with the auction module enabled and `bidPool.running=1`.
2. Concurrently:
   - Goroutine A: repeatedly call `auction_submitBid` (`AuctionAPI.SubmitBid` → `BidPool.AddBid`) with valid bids.
   - Goroutine B: trigger `AuctionModule.Stop()` (e.g., via balance dropping below `AuctionLenderMinBal` causing auto-disable logic, or a module-lifecycle stop/restart cycle) which calls `bidPool.stop()`.
3. When Goroutine A's call to `AddBid` passes the `atomic.LoadUint32(&bp.running) == 0` check just before Goroutine B executes `close(bp.newBidCh)` in `stop()`, Goroutine A's subsequent `bp.newBidCh <- bid` will panic with "send on closed channel", crashing the node process.

func (api *AuctionAPI) SubmitBid(ctx context.Context, bidInput BidInput) RPCOutput {
	numBidRequestCounter.Inc(1)
	if api.a.IsDisabled() {
		return makeRPCOutput(EMPTY_HASH, auction.ErrAuctionDisabled)
	}

	//  1. directly send target transaction
	targetTx, errTxDecode := toTx(bidInput.TargetTxRaw)
	if errTxDecode != nil {
		return makeRPCOutput(EMPTY_HASH, errTxDecode)
	}
	if targetTx.Hash() != bidInput.TargetTxHash {
		return makeRPCOutput(EMPTY_HASH, auction.ErrInvalidTargetTxHash)
	}
	errTargetTxSend := api.a.Backend.SendTx(ctx, targetTx)
	// ignore known transaction related errors against target tx validation
	if errTargetTxSend != nil && !(strings.HasPrefix(errTargetTxSend.Error(), "known transaction:") || errors.Is(errTargetTxSend, gasless_impl.ErrUnableToAddKnownBundleTx)) {
		return makeRPCOutput(EMPTY_HASH, errTargetTxSend)
	}

	// 2. add bid
	bid := ToBid(bidInput)
	bidHash, errValidateBid := api.a.bidPool.AddBid(bid)
	return makeRPCOutput(bidHash, errValidateBid)

func (bp *BidPool) stop() {
	// Stop the bid pool.
	atomic.CompareAndSwapUint32(&bp.running, 1, 0)
	bp.clearBidPool()

	// Only close channels if they haven't been closed before
	if atomic.CompareAndSwapUint32(&bp.stopped, 0, 1) {
		close(bp.bidMsgCh)
		close(bp.newBidCh)
	}
	bp.wg.Wait()
}

func (bp *BidPool) AddBid(bid *auction.Bid) (common.Hash, error) {
	if atomic.LoadUint32(&bp.running) == 0 {
		return common.Hash{}, auction.ErrAuctionPaused
	}

	if err := bp.validateBid(bid); err != nil {
		return common.Hash{}, err
	}

	if err := bp.insertBid(bid); err != nil {
		return common.Hash{}, err
	}

	gasLimit, err := bp.getBidTxGasLimit(bid)
	if err != nil {
		return common.Hash{}, err
	}
	bid.SetGasLimit(gasLimit)

	bp.newBidCh <- bid

	return bid.Hash(), nil
}
