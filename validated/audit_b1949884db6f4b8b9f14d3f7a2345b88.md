### Title
PlotNFT owners lose already-accrued self-farmed rewards when joining a pool - (File: `chia/wallet/plotnft_wallet/plotnft_wallet.py`, `chia/pools/plotnft_drivers.py`)

### Summary
`PlotNFT2Wallet.join_pool()` transitions a self-pooling PlotNFT singleton into `FARMING_TO_POOL` state without first settling or protecting reward coins that were already farmed to the plot's p2-singleton address while self-pooling. Once the transition lands on-chain, the singleton's `pool_config` is set and `pooling` becomes `True`, which permanently disables the user's ability to claim those pre-existing reward coins for themselves — the only remaining spend path forwards them to the pool's `pool_puzzle_hash` instead of the user.

### Finding Description
`PlotNFT.claim_pool_rewards()` unconditionally rejects any attempt to sweep p2-singleton reward coins to the owner once the singleton is pooling: [1](#0-0) 

The only spend path available for reward coins on a pooling singleton is `forward_pool_reward()`, which routes the coin's value to `self.guaranteed_pool_config.pool_puzzle_hash` (the pool's address), not the plot owner's `rewards_claim_puzhash`: [2](#0-1) 

`PlotNFT2Wallet.join_pool()` performs the state transition to pooling with no check for, or settlement of, any outstanding/unclaimed reward coins recorded in `PlotNFTStore.get_pool_rewards()` before committing the join spend: [3](#0-2) 

This is structurally the same bug class as the reported Vault.vy issue: a state-changing action (`liquidate()` in the report, `join_pool()` here) flips a mode flag (`is_liquidated` / `pool_config is not None`) that permanently forecloses the normal claim path for value that had already legitimately accrued to the owner, without first settling that claimable balance.

The codebase itself documents this as known, unmitigated behavior — the wallet test suite contains a scenario explicitly named "LOSE REWARDS (while pooling)" that farms self-pooling rewards, joins a pool, and then shows those pre-existing reward coins get swept away (forwarded to the pool puzzle hash) rather than paid to the owner: [4](#0-3) 

The same pattern repeats for the `LEAVING_POOL` state, where `claim_rewards()` also unconditionally rejects with "Cannot claim rewards while pooling" and rewards are again lost to a forward spend: [5](#0-4) 

Additionally, because new pool-reward coins keep arriving at the p2-singleton address at each block farmed to it, there is an inherent race: even a careful user who calls `claim_rewards()` immediately before `join_pool()` can still farm one or more additional reward coins in blocks between the claim confirming and the join spend confirming, and those coins become unclaimable the moment the join lands on-chain.

### Impact Explanation
Any self-pooling PlotNFT owner who transitions to `FARMING_TO_POOL` (or triggers the second-stage transition while `LEAVING_POOL` back into `FARMING_TO_POOL`) with outstanding, unswept self-farmed reward coins permanently loses those funds — they get redirected to the target pool's puzzle hash instead of the user's own wallet. This is a concrete, unauthorized transfer of value away from its rightful owner triggered purely by a normal wallet-level user action (`join_pool`/`pw_join_pool` RPC), with no attacker or malicious peer required. Given block rewards for self-pooling plots can be substantial (`POOL_REWARD_AMOUNT` per block), this can mean irreversible loss of one or more full block rewards per join.

### Likelihood Explanation
This triggers under completely normal usage: a solo/self-pooling farmer who decides to join a pool. It does not require any adversarial behavior, malicious peer, or privileged access — only a standard wallet action (`join_pool` via `PlotNFT2Wallet.join_pool()` or the `pw_join_pool` RPC). The race-condition variant (new rewards farmed between claim and join confirmation) makes the loss possible even for careful users who attempt to claim beforehand.

### Recommendation
`join_pool()` (and the second-stage `_finish_leaving_pool()` → `join_pool()` path) should refuse to proceed, or should automatically claim/sweep, any outstanding unclaimed self-farmed reward coins (`PlotNFTStore.get_pool_rewards()`) before or atomically with the pool-join spend, so that pre-existing accrued rewards are paid to the owner's `rewards_claim_puzhash` rather than becoming reachable only through `forward_pool_reward()`, which pays the pool. Consider bundling a `claim_pool_rewards` spend for all pending reward coins into the same transaction as the `join_pool` singleton spend, and re-checking for newly-farmed rewards immediately prior to broadcasting the join transaction to close the race window.

### Proof of Concept
The existing test suite already reproduces the loss end-to-end:
1. Farm 2 blocks of self-pooling rewards to the PlotNFT's p2-singleton address (`REWARDS_GAINED`), confirmed unclaimed. [6](#0-5) 
2. Call `plotnft_wallet.join_pool(...)` to transition to `FARMING_TO_POOL`. [7](#0-6) 
3. Attempting `claim_rewards()` now raises `"Cannot claim rewards while pooling..."`. [8](#0-7) 
4. The pre-existing reward coins are swept via `forward_pool_reward()` (test even labels this "LOSE REWARDS (while pooling)"), and the wallet balance decreases by the forwarded amount instead of being paid to the owner. [4](#0-3)

    def forward_pool_reward(self, reward: PoolReward) -> list[CoinSpend]:
        if not self.pooling:
            raise ValueError("Cannot forward pool reward while self pooling. Try `claim_pool_rewards`")
        return [
            self.singleton_action_spend(inner_solution=self.forward_pool_reward_inner_solution(reward)),
            make_spend(

                puzzle_reveal=reward.puzzle(),

                        puzzle=self.forward_pool_reward_dpuz(),
                        solution=Program.to([reward.coin.amount]),
                    ),
                ),
            ),
        ]

    async def join_pool(
        self,
        *,
        pool_config: PoolConfig,
        action_scope: WalletActionScope,
        fee: uint64 = uint64(0),
        finish_leaving_fee: uint64 = uint64(0),
        pool_url: str,
        extra_conditions: tuple[Condition, ...] = tuple(),
        plotnft_override: PlotNFT | None = None,
    ) -> None:
        if plotnft_override is None:
            plotnft = await self.get_current_plotnft()
        else:
            plotnft = plotnft_override
        if plotnft.pool_config is not None:
            await self.leave_pool(
                action_scope=action_scope,
                fee=fee,
                finish_leaving_fee=finish_leaving_fee,
                extra_conditions=extra_conditions,
                new_pool_url=pool_url,
                new_pool_config=pool_config,
            )
            return
        elif finish_leaving_fee != uint64(0):
            raise ValueError("A fee to finish leaving was specified but PlotNFT does not need to leave")
        fee_hook = CreateCoinAnnouncement(msg=b"", coin_id=plotnft.coin.name())
        url_remark = Remark(rest=Program.to(pool_url))
        coin_spends = plotnft.join_pool(
            user_config=plotnft.user_config,
            pool_config=pool_config,
            extra_conditions=(*extra_conditions, fee_hook, url_remark),
        )
        if fee > 0:
            await self.xch_wallet.create_tandem_xch_tx(
                fee=fee,
                action_scope=action_scope,
                extra_conditions=(fee_hook.corresponding_assertion(),),
            )
