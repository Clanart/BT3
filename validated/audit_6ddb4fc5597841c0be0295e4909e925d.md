### Title
PlotNFT `transfer_plotnft` changes singleton ownership without claiming pending unclaimed pool-reward coins first, causing the previous owner to permanently lose access to those funds - ([File: chia/wallet/plotnft_wallet/plotnft_wallet.py])

### Summary
`PlotNFT2Wallet.transfer_plotnft()` re-curries the PlotNFT singleton with a brand-new `UserConfig` (new owner synthetic pubkey / spend authority) but never checks for, or sweeps, `PoolReward` coins that are sitting unclaimed at the PlotNFT's `p2_singleton_puzzle_hash`. This mirrors the Cooler.sol `transferOwnership()`/`claimRepaid()` bug class: an ownership-transfer path exists side-by-side with a separate "claim accrued funds" path, and the transfer does not force/require the claim first, so whoever controls the singleton's spend authority *after* the transfer is the only one who can ever sweep those coins.

### Finding Description
`PlotNFT2Wallet.claim_rewards()` sweeps `PoolReward` coins recorded for a `plotnft_id` (keyed only by the singleton's `launcher_id`, not by owner) and requires spending the current PlotNFT singleton coin together with the reward coins: [1](#0-0) 

That spend is authorized by whichever key currently controls the singleton's inner puzzle (`UserConfig.synthetic_pubkey`), because `plotnft.claim_pool_rewards(...)` is built from the *current* `plotnft` state fetched via `get_current_plotnft()`.

Separately, `transfer_plotnft()` builds a `new_user_config` from a different fingerprint's root key and spends the PlotNFT singleton to re-curry it with that new owner key - without first checking `plotnft2_store.get_pool_rewards()` for any pending, unclaimed reward coins tied to this `plotnft_id`, and without calling `claim_rewards()` beforehand: [2](#0-1) 

Once this spend confirms, the singleton's authorized key is now the new owner's key. Because `PoolReward` coin claims (`claim_pool_rewards`) require a signature/spend authorized by the *current* singleton owner key, only the new owner can subsequently claim any `PoolReward` coins that were pending at transfer time - even though those rewards were earned by the plots/farming activity associated with the previous owner's control period. The previous owner has no mechanism to claim rewards that accrued before the transfer once the transfer has gone through, exactly as in the reported Cooler.sol issue where `claimRepaid()` is not invoked before `transferOwnership()` finalizes and the old lender loses access to `loan.unclaimed`.

Unlike `leave_pool()`/`join_pool()`, which are guarded against overlapping unconfirmed transactions, `transfer_plotnft()` performs no equivalent check against outstanding unclaimed `PoolReward` coins before re-currying ownership.

### Impact Explanation
This is a genuine loss-of-funds path for the previous PlotNFT owner: pending self-pool farming rewards recorded at the PlotNFT's `p2_singleton_puzzle_hash` become permanently unreachable by the party who earned them once ownership is transferred, since only the new owner's key can authorize the sweep afterward. This qualifies as unauthorized/asymmetric control over coin movement resulting from a state-transition ordering flaw reachable by a normal wallet user performing a supported RPC action (`plotnft_transfer` / `PlotNFTTransfer`), matching the Medium severity class of the analog report (loss of funds due to missing "claim before transfer" ordering).

### Likelihood Explanation
Likelihood is moderate: it requires (a) the PlotNFT to have unclaimed `PoolReward` coins (a normal, common state while self-pooling before a `claim_rewards`/absorb call), and (b) the owner calling `transfer_plotnft` (a supported, user-triggered CLI/RPC action: `plotnft transfer` / `DidTransferDidCMD`-style command) without first claiming rewards. There is no built-in warning or automatic claim, so any user unaware of pending rewards, or any transfer executed programmatically/rapidly, will trigger this loss without any malicious actor being required.

### Recommendation
In `PlotNFT2Wallet.transfer_plotnft()`, before building the new-user-config spend, query `self.wallet_state_manager.plotnft2_store.get_pool_rewards(plotnft_id=self.plotnft_id)`; if any unclaimed `PoolReward` coins exist, either automatically claim them first (mirroring the suggested Cooler.sol fix of calling `claimRepaid` before `transferOwnership` completes) or reject the transfer with a clear error instructing the user to call `claim_rewards()` first.

### Proof of Concept
1. User creates a self-pooling PlotNFT2 wallet via `PlotNFT2Wallet.create_new` and farms blocks, so that one or more `PoolReward` coins accumulate at `p2_singleton_puzzle_hash` and are recorded via `plotnft2_store.add_pool_reward` in `coin_added` (`chia/wallet/plotnft_wallet/plotnft_wallet.py` lines 651-657).
2. Without calling `claim_rewards()`, the user calls `transfer_plotnft(target_wallet_fingerprint=<other fingerprint>)` (`chia/wallet/plotnft_wallet/plotnft_wallet.py` lines 421-481), which spends the PlotNFT singleton with a new `UserConfig` bound to the new fingerprint's key.
3. After this transaction confirms, the original owner's key is no longer the singleton's authorized owner key.
4. The original owner attempts `claim_rewards()` for the still-unclaimed `PoolReward` coins recorded under the same `plotnft_id`; the required singleton spend can only be authorized by the new owner's key, so the original owner cannot construct a valid claim spend and permanently loses access to those reward coins.

    async def transfer_plotnft(
        self,
        *,
        action_scope: WalletActionScope,
        target_wallet_fingerprint: int,
        fee: uint64 = uint64(0),
        extra_conditions: tuple[Condition, ...] = tuple(),
    ) -> None:
        """
        Because the wallet doesn't have broad support for MIPS-style custody, transferring using addresses is
        a bit complicated because transferring to the wrong kind of address could leave the wallet unable to
        sync/spend the PlotNFT. As a guard, we implement this endpoint as a transfer between local keys to make
        sure that we generate the correct kind of inner puzzle.

        This is not necessarily a permanent restriction, but solves the primary use case of transferring between
        a user's own wallets and keeps the implementation relatively simple for now.
        """
        plotnft = await self.get_current_plotnft()
        fee_hook = CreateCoinAnnouncement(msg=b"", coin_id=plotnft.coin.name())
        root_pubkey = await self.wallet_state_manager.wallet_node.keychain_proxy.get_key_for_fingerprint(
            fingerprint=target_wallet_fingerprint, private=False
        )
        if root_pubkey is None:
            raise RuntimeError(f"Error retrieving key for fingerprint {target_wallet_fingerprint}")
        wallet_pubkey = master_pk_to_wallet_pk_unhardened(root_pubkey, index=uint32(0))
        synthetic_pubkey = self.xch_wallet.convert_public_key_to_synthetic(wallet_pubkey)
        hint = self.xch_wallet.puzzle_hash_for_pk(wallet_pubkey)
        new_user_config = UserConfig(synthetic_pubkey=synthetic_pubkey)
        coin_spends = plotnft.new_user_config(
            user_config=new_user_config,
            hint=hint,
            extra_conditions=(fee_hook, *extra_conditions),
        )
        if fee > 0:
            await self.xch_wallet.create_tandem_xch_tx(
                fee=fee,
                action_scope=action_scope,
                extra_conditions=(fee_hook.corresponding_assertion(),),
            )

        spend_bundle = WalletSpendBundle(coin_spends, G2Element())
        async with action_scope.use() as interface:
            interface.side_effects.transactions.append(
                self.wallet_state_manager.new_outgoing_transaction(
                    wallet_id=self.id(),
                    puzzle_hash=hint,
                    amount=uint64(1),
                    fee=fee,
                    spend_bundle=spend_bundle,
                    additions=[
                        Coin(
                            parent_coin_info=plotnft.coin.name(),
                            puzzle_hash=dataclasses.replace(plotnft, user_config=new_user_config).puzzle_hash(nonce=0),
                            amount=uint64(1),
                        )
                    ],
                    removals=[plotnft.coin],
                    name=spend_bundle.name(),
                    extra_conditions=extra_conditions,
                )
