### Title
Undelegation/unbonding funds are permanently frozen when the delegator address cannot receive funds at maturity, because the failed `CompleteUnbonding` withdrawal is dequeued but never retried - (File: sei-cosmos/x/staking/keeper/delegation.go, sei-cosmos/x/staking/keeper/val_state_change.go)

### Summary
`Undelegate` guarantees a delegator will get their tokens back once the unbonding period matures. This is analogous to Rocket Pool's invariant that "if a node operator is allowed to withdraw funds, the withdrawal should always succeed." However, `CompleteUnbonding` calls `bankKeeper.UndelegateCoinsFromModuleToAccount`, which fails whenever the delegator address currently cannot receive funds (`CanSendTo` returns false — e.g. because the delegator is a direct-cast EVM address that has since been re-associated to a different Sei address via the `associate`/`associatePubKey` precompile). `BlockValidatorUpdates` in `val_state_change.go` already removed the queue entry from the `UnbondingDelegationQueue` via `DequeueAllMatureUBDQueue` *before* calling `CompleteUnbonding`; on error it simply `continue`s. Since `CompleteUnbonding` returns before persisting any store mutation on error, the `UnbondingDelegation` entry itself is retained in the store, but it is never re-inserted into the maturity queue. As a result the entry can never mature again, and the underlying funds — already debited out of the bonded/not-bonded pool accounting and earmarked for the delegator — become permanently unretrievable through the normal path.

### Finding Description
`CompleteUnbonding` iterates over mature `UnbondingDelegation` entries and, for each, calls: [1](#0-0) 

If `k.bankKeeper.UndelegateCoinsFromModuleToAccount` fails (which happens whenever `CanSendTo(ctx, delegatorAddress)` is false, per `UndelegateCoins`'s own `CanSendTo` guard), the function returns the error immediately, **without calling `k.SetUnbondingDelegation` or `k.RemoveUnbondingDelegation`**: [2](#0-1) 

The caller, `BlockValidatorUpdates` (invoked every `EndBlock` for all staking-module chains), had already dequeued the maturity-queue entry via `DequeueAllMatureUBDQueue` before calling `CompleteUnbonding`, and on error it does nothing but `continue`: [3](#0-2) 

Because the queue entry (`UnbondingQueueKey` timeslice) was already deleted, but the `UnbondingDelegation` object itself was left untouched (still containing the mature entry), there is **no remaining trigger** in the codebase that will re-attempt `CompleteUnbonding` for that entry. The team's own regression test confirms this exact end state — after a failed `EndBlocker` pass, the delegation entry is retained, but the maturity-queue iterator is empty: [4](#0-3) 

`CanSendTo` can become false for a legitimate delegator through normal, permissionless user action: the EVM `addr` precompile lets anyone call `associate`/`associatePubKey`, which re-associates a Sei address's EVM mapping via `AssociateAddresses`/`SetAddressMapping`: [5](#0-4) [6](#0-5) 

If a delegator's account is the *direct-cast* Sei address of an EVM address (i.e., it never went through `associatePubKey` itself) and a third party later associates that same EVM address to a *different* true Sei address, `CanSendTo`/`GetEVMAddress` resolution makes the original cast address unreceivable — exactly the scenario the codebase's own test (`TestEndBlockRetainsUnbondingForInvalidRecipient`) constructs, and the same class of scenario the `x/evm/ante/preprocess.go` comment explicitly warns about for distribution's validator-removal hook: [7](#0-6) 

Note that the codebase has clearly already hardened several sibling withdrawal paths against this exact bug class — `x/distribution`'s `AfterValidatorRemoved` hook (routes to community pool instead of panicking), `x/gov`'s `RefundDeposits` (retains the deposit record), and `x/distribution`'s `SetWithdrawAddr` (rejects unpayable addresses up front). `x/staking`'s `CompleteUnbonding`/`BlockValidatorUpdates` pair is the one path in this family that was not given an equivalent safety net: it dequeues before the transfer succeeds and never re-enqueues on failure, so the fix pattern applied everywhere else (retain the record *and* keep it reachable for a future retry, or fall back to a receivable address) was not applied here in a way that preserves future re-processing.

### Impact Explanation
This results in **permanent freezing of user funds**: once an `UnbondingDelegation` entry matures while its delegator address is temporarily unreceivable, the tokens remain locked in the `NotBondedPool` module account forever, with no code path capable of retrying or manually re-triggering `CompleteUnbonding` for that specific entry (it is absent from every `UnbondingDelegationQueue` timeslice, and no message handler re-inserts it). This meets the "permanent freezing" bar for a valid finding, and it is reachable by an ordinary transaction sender through the permissionless `associate`/`associatePubKey` EVM precompile combined with a plain `MsgUndelegate`/staking-precompile `undelegate` call — no governance, validator, or node compromise required.

### Likelihood Explanation
Likelihood is moderate: the delegator must be delegating from a Sei account that is the *direct cast* of an EVM address (i.e., an address seen on-chain before it went through `associatePubKey`), and that same EVM address's mapping must be re-associated (by the delegator itself accidentally, or by an attacker who controls the EVM private key and wants to grief/self-lock funds, or simply through normal usage patterns where a user's EVM key later gets formally associated to a distinct HD-derived Sei address) before the unbonding entry matures. This is a realistic and easily triggerable condition given how common the cast-address pattern is for new EVM users on Sei prior to explicit association.

### Recommendation
Apply the same defensive pattern already used in `x/distribution` (`canReceiveWithdrawAddr`) and `x/gov` (`RefundDeposits`) to `CompleteUnbonding`/`BlockValidatorUpdates`:
- Before dequeuing, or upon `UndelegateCoinsFromModuleToAccount` failure, check `CanSendTo` (or catch the resulting error) and, if the recipient cannot currently receive funds, **re-insert the entry into the `UnbondingDelegationQueue`** (e.g., at a short retry delay) instead of silently dropping it, so it will be retried in a subsequent block once the address becomes receivable again; or persist the unresolved entry in a dedicated "stuck withdrawals" store that a permissionless message can later replay once the address is fixed. Ensure `BlockValidatorUpdates` never dequeues a maturity entry without a guaranteed follow-up path to either complete or re-queue it.

### Proof of Concept
1. Create a Sei account `D` whose address is the direct byte-cast of EVM address `E` (i.e., `D` has never called `associatePubKey`).
2. From `D`, delegate to a validator and then submit `MsgUndelegate` (or the EVM staking precompile's `undelegate`), creating an `UnbondingDelegation` entry maturing at time `T`.
3. Before time `T`, from any account holding the private key for `E` (or a party who can produce a valid signature for `E`), call the `addr` precompile's `associatePubKey`/`associate` for a *different* Sei address using EVM address `E`. This calls `AssociateAddresses`/`SetAddressMapping(ctx, newSeiAddr, E)`, which makes `GetEVMAddress`/`CanSendTo` resolution reject sends to `D` going forward — mirrored by the existing test `TestEndBlockRetainsUnbondingForInvalidRecipient` in `sei-cosmos/x/staking/keeper/delegation_test.go:281-326`, which reproduces exactly this precondition using `SetAddressMapping`.
4. Advance the chain past time `T`. In `EndBlock`, `BlockValidatorUpdates` dequeues `D`'s entry from `UnbondingDelegationQueue` and calls `CompleteUnbonding`, which fails at `UndelegateCoinsFromModuleToAccount` due to `CanSendTo(D) == false`, and the error is swallowed via `continue`.
5. Observe: `GetUnbondingDelegation(D, validator)` still returns the (unmodified) entry, but `UBDQueueIterator` no longer contains it at any future timestamp — the entry can never mature again, and the corresponding tokens remain stuck in the `NotBondedPool` module account indefinitely.

// CompleteUnbonding completes the unbonding of all mature entries in the
// retrieved unbonding delegation object and returns the total unbonding balance
// or an error upon failure.
func (k Keeper) CompleteUnbonding(ctx sdk.Context, delAddr sdk.AccAddress, valAddr sdk.ValAddress) (sdk.Coins, error) {
	ubd, found := k.GetUnbondingDelegation(ctx, delAddr, valAddr)
	if !found {
		return nil, types.ErrNoUnbondingDelegation
	}

	bondDenom := k.GetParams(ctx).BondDenom
	balances := sdk.NewCoins()
	ctxTime := ctx.BlockHeader().Time

	delegatorAddress, err := sdk.AccAddressFromBech32(ubd.DelegatorAddress)
	if err != nil {
		return nil, err
	}

	// loop through all the entries and complete unbonding mature entries
	for i := 0; i < len(ubd.Entries); i++ {
		entry := ubd.Entries[i]
		if entry.IsMature(ctxTime) {
			ubd.RemoveEntry(int64(i))
			i--

			// track undelegation only when remaining or truncated shares are non-zero
			if !entry.Balance.IsZero() {
				amt := sdk.NewCoin(bondDenom, entry.Balance)
				if err := k.bankKeeper.UndelegateCoinsFromModuleToAccount(
					ctx, types.NotBondedPoolName, delegatorAddress, sdk.NewCoins(amt),
				); err != nil {
					return nil, err
				}

				balances = balances.Add(amt)
			}
		}
	}

	// set the unbonding delegation or remove it if there are no more entries
	if len(ubd.Entries) == 0 {
		k.RemoveUnbondingDelegation(ctx, ubd)
	} else {
		k.SetUnbondingDelegation(ctx, ubd)
	}

	return balances, nil
}

func TestEndBlockRetainsUnbondingForInvalidRecipient(t *testing.T) {
	_, app, ctx := createTestInput(t)
	maturity := time.Unix(1, 0).UTC()
	ctx = ctx.WithBlockTime(maturity)
	evmAddr := common.HexToAddress("0x3333333333333333333333333333333333333333")
	delegator := sdk.AccAddress(evmAddr[:])
	app.EvmKeeper.SetAddressMapping(ctx, delegator, evmAddr)
	app.EvmKeeper.SetAddressMapping(
		ctx,
		sdk.AccAddress(common.HexToAddress("0x4444444444444444444444444444444444444444").Bytes()),
		evmAddr,
	)
	validator := sdk.ValAddress(seiapp.AddTestAddrsIncremental(app, ctx, 1, sdk.NewInt(10000))[0])
	amount := sdk.NewInt(40)
	bondDenom := app.StakingKeeper.BondDenom(ctx)
	notBondedPool := app.StakingKeeper.GetNotBondedPool(ctx)
	coins := sdk.NewCoins(sdk.NewCoin(bondDenom, amount))

	require.NoError(t, apptesting.FundModuleAccount(
		app.BankKeeper,
		ctx,
		notBondedPool.GetName(),
		coins,
	))

	unbonding := types.NewUnbondingDelegation(delegator, validator, 0, maturity, amount)
	app.StakingKeeper.SetUnbondingDelegation(ctx, unbonding)
	app.StakingKeeper.InsertUBDQueue(ctx, unbonding, maturity)
	require.False(t, app.BankKeeper.CanSendTo(ctx, delegator))

	poolBalanceBefore := app.BankKeeper.GetBalance(ctx, notBondedPool.GetAddress(), bondDenom)
	require.NotPanics(t, func() {
		staking.EndBlocker(ctx, app.StakingKeeper)
	})

	poolBalanceAfter := app.BankKeeper.GetBalance(ctx, notBondedPool.GetAddress(), bondDenom)
	require.Equal(t, poolBalanceBefore, poolBalanceAfter)
	require.True(t, app.BankKeeper.GetBalance(ctx, delegator, bondDenom).IsZero())
	retained, found := app.StakingKeeper.GetUnbondingDelegation(ctx, delegator, validator)
	require.True(t, found)
	require.Equal(t, unbonding, retained)

	iterator := app.StakingKeeper.UBDQueueIterator(ctx, maturity)
	require.False(t, iterator.Valid())
	require.NoError(t, iterator.Close())
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}
