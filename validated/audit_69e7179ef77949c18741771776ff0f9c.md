### Title
`SignableTransaction`/`multisig` trusts attacker-supplied `ReceivedOutput` prevout values, enabling signing of transactions that burn funds as fees — ([File: networks/bitcoin/src/wallet/send.rs])

### Summary
CVE-2021-21685 is a missing agent-to-controller authorization check: Jenkins let an agent invoke `FilePath#mkdirs` to create directories on the controller without validating that the agent was allowed to touch that path — a trusted-side resource created from unvalidated, unprivileged input. The Serai analog is `SignableTransaction::new`/`TransactionSignMachine::sign` in `networks/bitcoin/src/wallet/send.rs`, which consumes `ReceivedOutput` values (deserializable from arbitrary bytes via `ReceivedOutput::read`) and signs a sighash committing to the attacker-claimed prevout amounts, without ever checking those prevouts against the chain.

### Finding Description
`SignableTransaction::new` takes `Vec<ReceivedOutput>` and uses each `input.output.value` and `input.outpoint` verbatim to compute `input_sat`, the change amount, and the prevout list committed by `Prevouts::All` (`send.rs:175`, `send.rs:253`, `send.rs:375`). `ReceivedOutput::read` (`wallet/mod.rs:122-133`) will happily deserialize any `Scalar` offset, `TxOut`, and `OutPoint` — nothing ties it to a real UTXO.

The only validation before signing is in `multisig` (`send.rs:277`):

```rust
if p2tr_script_buf(offset.group_key())? != self.prevouts[i].script_pubkey {
  None?;
}
```

This checks the prevout's *script* matches the offset key, but not that the outpoint exists, is unspent, or has the claimed value. Because the sighash (`taproot_key_spend_signature_hash` with `Prevouts::All`, `send.rs:375-389`) commits to the *claimed* `TxOut` amounts, a signer will produce a valid BIP-340 signature for a transaction built on false prevout data — the exact "sign an unintended message" primitive the access-check analog implies.

Concretely, an attacker who supplies a `ReceivedOutput` referencing a real multisig-controlled outpoint but with a *lower* `value` causes `input_sat` to be understated while the actual UTXO spends its true amount: the difference is paid to miners as excess fee (or, if `change` is set, the change output is computed from the wrong number and the TX remains consensus-valid with an inflated fee). Supplying a fake/higher-valued outpoint produces a fully-signed but invalid transaction.

### Impact Explanation
Every threshold signer that consumes attacker-controlled `ReceivedOutput` bytes will emit valid signature shares over a sighash committing to fabricated prevout amounts. The completed transaction is consensus-valid and broadcasts: funds equal to `actual_value - claimed_value` per forged input are irrecoverably burned as miner fees, or change is misdirected relative to intent. This is a signing of an attacker-chosen financial statement — not merely a DoS — when the claimed value understates a real UTXO.

### Likelihood Explanation
`ReceivedOutput` is an untrusted-by-construction type: it has a public `read`/`serialize` pair intended for transport, and the scan prompt's reachability rules explicitly treat bytes fed to `ReceivedOutput::read` as attacker-controlled. Any architecture where the transaction coordinator (or an untrusted scheduler/plan input) rather than the local `Scanner` supplies the inputs reaches this path. The defense is one line (`p2tr_script_buf` equality) covering only the script, so no secondary check catches a manipulated `value`/`outpoint`. Exploitation requires no collusion — each signer independently signs the malicious sighash.

### Recommendation
Before signing, verify each `ReceivedOutput` against consensus: in `SignableTransaction::new` or `multisig`, confirm `outpoint` resolves to an existing, unspent `TxOut` whose `script_pubkey` and `value` exactly match the supplied `output` (e.g., via `gettxout`/the node's view of the UTXO set), or restrict `SignableTransaction` inputs to values produced directly by a trusted `Scanner` rather than `ReceivedOutput::read` output. Documenting "inputs must be scanner-produced" is insufficient — the check is cheap relative to threshold signing and must be enforced in code.

### Proof of Concept
```rust
// Attacker constructs bytes describing the multisig's real UTXO but with
// a deflated value (real: 100_000 sats, claimed: 10_000 sats).
let mut buf = vec![];
buf.extend(Scalar::ZERO.to_bytes());                    // offset = 0 (external output)
let fake_txout = TxOut {
    value: Amount::from_sat(10_000),                    // claimed, not actual
    script_pubkey: p2tr_script_buf(group_key).unwrap(), // matches offset key
};
buf.extend(serialize(&fake_txout));
buf.extend(serialize(&real_outpoint));                  // real, unspent multisig outpoint

let forged = ReceivedOutput::read(&mut buf.as_ref()).unwrap();

// Coordinator/signers build the tx. `multisig` passes: script_pubkey matches.
let tx = SignableTransaction::new(
    vec![forged],
    &[(dest_script, 9_000)],
    Some(change_script),
    None,
    fee_rate,
).unwrap();

// Each signer signs sighash committing to the fake 10_000-sat prevout.
// Resulting TX spends the real 100_000-sat UTXO: ~91_000 sats - outputs
// are silently burned as excess fee. The signature is consensus-valid.
```
