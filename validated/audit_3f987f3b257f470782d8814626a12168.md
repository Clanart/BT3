### Title
Unbounded numeric-string CPU/memory exhaustion in legacy JSON precompile `ExtractAsUint256` reachable via EVM tracing RPCs - (File: precompiles/json/legacy/{v562,v603,v605,v610,v614,v620,v630,v640,v65}/json.go)

### Summary
Several archived ("legacy") versions of the `x/evm` JSON precompile's `ExtractAsUint256` method convert an attacker-controlled JSON value into a `big.Int` via `new(big.Int).SetString(strValue, 10)` without any bound on the length of `strValue`. The only currently-shipped version that has the guard is the latest one (`precompiles/json/json.go`) and `v66`/`v67`, which added `if len(strValue) > 100 { ... }` before the conversion. All the other archived versions (`v562`, `v603`, `v605`, `v606`, `v610`, `v614`, `v620`, `v630`, `v640`, `v65`) lack this check entirely.

### Finding Description
`math/big.Int.SetString` with base 10 has cost that grows worse than linearly with input length (the decimal-to-binary conversion is effectively quadratic for very large digit strings). CVE‑2023‑30082 is the same bug class: an unbounded-length numeric/password string fed into an expensive parsing routine causes CPU/memory exhaustion.

In sei-chain, live/current EVM calls always execute against the *latest* precompile implementation, selected via `k.latestCustomPrecompiles` when `!ctx.IsTracing()`: [1](#0-0) 
That latest implementation does bound the string length before calling `big.Int.SetString`: [2](#0-1) 

However, when `ctx.IsTracing()` is true (the path used by `debug_traceCall`/`debug_traceTransaction` and similar tracing RPCs), the keeper resolves the precompile version that was active at the *historical* block height being traced, via `GetCustomPrecompilesVersions`, and can dispatch into any of the archived legacy implementations: [3](#0-2) 

Every legacy version registered in `precompiles/json/setup.go` prior to the fix (`v562`, `v603`, `v605`, `v610`, `v614`, `v620`, `v630`, `v640`, `v65`) implements `ExtractAsUint256` without the length guard: [4](#0-3) 
compared to the fixed versions: [5](#0-4) [6](#0-5) 

The precompile registry that wires these versions in by upgrade name is: [7](#0-6) 

### Impact Explanation
A public-facing RPC node with `debug`/tracing APIs enabled can be asked (via `debug_traceCall` at a historical block number, or `debug_traceTransaction` for a historical tx that invoked the JSON precompile) to execute `ExtractAsUint256` under one of the vulnerable legacy implementations. Supplying a JSON payload whose target key's value is an extremely long numeric string (megabytes of digits) forces `big.Int.SetString` to perform a very expensive base-10 parse on every such call, consuming disproportionate CPU and memory relative to the gas/resources charged, and can be used to degrade or crash a default-configuration RPC node that serves tracing endpoints — matching the CVE-2023-30082 bug class (unbounded-length input driving disproportionate computation) and the report's "crash of default-configuration RPC nodes" impact bar.

### Likelihood Explanation
There is measurable mitigation already in place: the tracing subsystem enforces a per-call timeout and a concurrency semaphore (`traceCallSemaphore`, `traceTimeout`) that reject/cancel long-running trace calls: [8](#0-7) 
This reduces — but does not eliminate — the impact, since the semaphore only limits concurrency of trace requests, not the CPU/memory a single request can burn before the timeout fires, and repeated/parallel requests up to the semaphore limit can still each pin a CPU core for the duration of the timeout window. Whether `debug`/tracing namespaces are enabled by default in a production `seid` deployment (vs. being an operator-opt-in RPC namespace) could not be conclusively confirmed from the available index; this affects the realistic likelihood and should be verified directly against the RPC server default namespace configuration.

### Recommendation
Backport the `len(strValue) > 100` (or an equivalently small bound) guard into all legacy `ExtractAsUint256` implementations that are still reachable through the tracing/historical-replay path (`v562`, `v603`, `v605`, `v610`, `v614`, `v620`, `v630`, `v640`, `v65`), or alternatively make the tracing dispatcher always route non-critical/util precompiles like JSON through the current hardened implementation regardless of historical version, since faithful byte-for-byte historical replay is not required for a length-validation bug fix that only rejects previously-un-representable extreme inputs.

### Proof of Concept
1. Identify a block height (or craft a `debug_traceCall` with a historical block number) at which `GetCustomPrecompilesVersions` resolves the JSON precompile address to one of the vulnerable versions (e.g. `v640`).
2. Send `debug_traceCall`/`debug_traceTransaction` targeting the JSON precompile address with calldata for `extractAsUint256(bytes,string)` where the JSON bytes contain `{"k":"<10,000,000-digit number>"}` and key `"k"`.
3. Observe the RPC node's CPU/memory spike disproportionately during `big.Int.SetString(strValue, 10)` processing of the huge digit string, consistent with the CVE-2023-30082 resource-exhaustion pattern; repeat concurrently up to the trace semaphore limit to amplify load on the node.

func (k *Keeper) CustomPrecompiles(ctx sdk.Context) map[common.Address]vm.PrecompiledContract {
	if !ctx.IsTracing() {
		return k.latestCustomPrecompiles
	}
	versions := k.GetCustomPrecompilesVersions(ctx)
	cp := make(map[common.Address]vm.PrecompiledContract, len(k.customPrecompiles))
	for addr, versioned := range k.customPrecompiles {
		cp[addr] = versioned[versions[addr]]
	}
	return cp
}

func (k *Keeper) GetCustomPrecompilesVersions(ctx sdk.Context) map[common.Address]string {
	height := ctx.BlockHeight()
	cp := make(map[common.Address]string, len(k.customPrecompiles))
	for addr, versioned := range k.customPrecompiles {
		mostRecentUpgradeHeight := int64(0)
		noForkHistory := true
		for upgrade := range versioned {
			upgradeHeight := k.upgradeKeeper.GetDoneHeight(ctx, upgrade)
			if upgradeHeight != 0 {
				noForkHistory = false
			}
			if height < upgradeHeight {
				// requested height hasn't seen this upgrade version yet.
				continue
			}
			if upgradeHeight > mostRecentUpgradeHeight {
				mostRecentUpgradeHeight = upgradeHeight
				cp[addr] = upgrade
			}
		}
		if noForkHistory {
			cp[addr] = k.latestUpgrade
		}
	}
	return cp
}

		return nil, err
	}
	key := args[1].(string)
	result, ok := decoded[key]
	if !ok {
		return nil, fmt.Errorf("input does not contain key %s", key)
	}

	// Convert byte slice to string and trim quotation marks

	// Convert the string to big.Int
	value, success := new(big.Int).SetString(strValue, 10)
	if !success {
		return nil, fmt.Errorf("failed to convert %s to big.Int", strValue)
	}

	return value, nil
