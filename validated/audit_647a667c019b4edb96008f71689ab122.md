### Title
Missing timestamp/freshness bound check in App Proxy signature verification allows unlimited replay of leaked signed requests - (File: lib/shopify_app/controller_concerns/app_proxy_verification.rb)

### Summary
`ShopifyApp::AppProxyVerification#query_string_valid?` re-derives the HMAC signature from the query parameters (including the `timestamp` param that Shopify includes on every app-proxy request) and compares it to the supplied `signature`, but it never inspects the value of `timestamp` itself to enforce that the request is recent.

### Finding Description
The verification logic is: [1](#0-0) 

`calculated_signature` simply concatenates the sorted `key=value` pairs (including `timestamp`) and HMACs them with the app secret: [2](#0-1) 

`timestamp` is treated purely as signed *data* — it is folded into the HMAC input, but its value is never compared against `Time.now` or any allowed drift window. This is structurally the same root cause as the Chainlink report: a value that is supposed to bound the validity of externally supplied data (the oracle's `updatedAt` in the C4 report, the proxy request's `timestamp` here) is present but simply not range/staleness-checked before the request/response is trusted. As in the oracle case, a signature that was valid at time T remains "valid" forever, because nothing in `verify_proxy_request` rejects it once too much time has passed: [3](#0-2) 

The same pattern (correct HMAC over the payload, but no timestamp/staleness bound) also exists in the shared webhook/extension verifier, which never even includes a timestamp in the checked material: [4](#0-3) [5](#0-4) 

### Impact Explanation
Any app-proxy URL that is ever captured (browser history, server/proxy access logs, `Referer` headers, shared links, caching layers, browser extensions, etc.) remains a permanently valid, "correctly signed" request as far as `ShopifyApp::AppProxyVerification` is concerned. An unrelated, unauthenticated party who obtains such a URL can replay it indefinitely to whatever `AppProxyController`/`AppProxy::*` actions the host app has built, exactly mirroring the oracle report's core lesson: trusting a bounded-but-unchecked value lets stale/attacker-controlled state be treated as fresh, correct data, with consequences dependent on what the app does with proxy requests (e.g., triggering shop-scoped side effects, reading `shop`/`logged_in_customer_id` params as if freshly issued by Shopify).

### Likelihood Explanation
Any host app that follows the documented `ShopifyApp::AppProxyVerification` pattern is affected out of the box — this is default gem behavior, not opt-in misconfiguration. All that's required is for a valid, previously-issued signed proxy URL to leak or be observable by a third party (a very common occurrence for URLs), and it can be replayed with no time limit.

### Recommendation
Add an explicit bound check on `timestamp` in `query_string_valid?`/`verify_proxy_request`, e.g., reject the request if `Time.now.to_i - query_hash["timestamp"].to_i` exceeds a small allowed window (mirroring the recommended Chainlink fix of enforcing `MIN`/`MAX` bounds on trusted external values), in addition to the existing signature check.

### Proof of Concept
1. Configure an app with `ShopifyApp::AppProxyVerification` on `AppProxyController` (default generator setup): [6](#0-5) 
2. Observe/capture any legitimately issued app-proxy request URL, e.g. `.../app_proxy?shop=store.myshopify.com&path_prefix=%2Fapps%2Fmy-app&timestamp=1466106083&signature=...` (test fixture format shown in the suite): [7](#0-6) 
3. Replay that exact same URL (all params unchanged) at any point in the future — arbitrarily long after `timestamp` — and `query_string_valid?` will still return `true` because it only recomputes/compares the HMAC and never checks whether `timestamp` is stale, so `verify_proxy_request` never blocks it.

  module AppProxyVerification
    extend ActiveSupport::Concern
    included do
      skip_before_action :verify_authenticity_token, raise: false
      before_action :verify_proxy_request
    end

    def verify_proxy_request
      head(:forbidden) unless query_string_valid?(request.query_string)
    end

    private

    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end

    def calculated_signature(query_hash_without_signature)
      sorted_params = query_hash_without_signature.collect { |k, v| "#{k}=#{Array(v).join(",")}" }.sort.join

      OpenSSL::HMAC.hexdigest(
        OpenSSL::Digest.new("sha256"),
        ShopifyApp.configuration.secret,
        sorted_params,
      )
    end

    def shopify_hmac
      request.headers["HTTP_X_SHOPIFY_HMAC_SHA256"]
    end

    def hmac_valid?(data)
      secrets = [ShopifyApp.configuration.secret, ShopifyApp.configuration.old_secret].reject(&:blank?)

      secrets.any? do |secret|
        digest = OpenSSL::Digest.new("sha256")
        ActiveSupport::SecurityUtils.secure_compare(
          shopify_hmac,
          Base64.strict_encode64(OpenSSL::HMAC.digest(digest, secret, data)),
        )
      end
    end
