## Finding

### Title
Symlink/path-traversal file read outside the repository in conflict-resolution diff generation - (File: `app/src/lib/git/diff.ts`)

### Summary
`getResolutionDiff()` reads a conflicted file's on-disk content by joining the repository root with an attacker-influenced relative path and calling `readFile` directly, with no containment check. This is inconsistent with the rest of the codebase, which uses the hardened `resolveWithin()` helper (which additionally resolves symlinks via `realpath` and rejects any result that escapes the root) before touching the filesystem for similarly-sourced paths.

### Finding Description
`getResolutionDiff` builds the path for the "base" content used for AI/Copilot-assisted conflict resolution: [1](#0-0) 

```
export async function getResolutionDiff(
  repository: Repository,
  filePath: string,
  ...
  const baseContent = await readFile(
    Path.join(repository.path, filePath),
    'utf8'
  )
```

`filePath` is a repository-relative path that originates from the list of conflicted files during a merge/rebase/cherry-pick — content that is directly influenced by whatever tree state resulted from merging in an attacker-controlled branch/commit (i.e., a cloned/fetched, attacker-crafted repository). `Path.join` performs no bounds checking, and `readFile` on the resulting path follows symlinks on disk.

Compare this to `buildConflictContext`, which handles the *same class* of input (a list of conflicted file paths from the working directory) and explicitly guards against exactly this attack: [2](#0-1) 

```
// Guard against path traversal and symlink escapes (cross-platform)
let absolutePath: string | null
try {
  absolutePath = await resolveWithin(workingDirectory, file.path)
} catch { ... }
if (absolutePath === null) {
  return { path: file.path, hunks: [], skippedReason: 'File path is outside the repository' }
}
```

And `resolveWithin` is specifically designed and tested to reject paths that escape the root via directory traversal *or* via a symlink planted inside the working tree that points outside it: [3](#0-2) [4](#0-3) 

`getResolutionDiff` skips this guard entirely, so a malicious repository could commit a symlink (e.g. `victim-file -> /Users/victim/.ssh/id_rsa` or a Windows junction) inside the working directory. If a merge conflict is ever reported for that path (e.g. the attacker's branch modifies the symlink entry while the victim's branch also modifies it, forcing it into the conflicted-files list), `getResolutionDiff` will happily `readFile` through the symlink and return the *target file's* contents as the "base" diff content.

### Impact Explanation
The broken invariant is: "a path derived from repository content must never resolve to a location outside the repository." Here, unlike the sibling code path (`buildConflictContext`), no such check exists. Depending on how the resolution diff's `oldContents`/`baseContent` is consumed (rendered in the UI, and per the surrounding code, also potentially fed to the Copilot conflict-resolution flow that sends conflict content to a model/API), this can exfiltrate arbitrary file contents from outside the repository to the UI and/or to a remote AI service — matching the "credential/token exfiltration" and "file read outside the repo" categories for an unprivileged attacker who only controls a cloned/fetched repository.

### Likelihood Explanation
Requires the victim to open a repository containing an attacker-crafted symlink and hit a merge/rebase/cherry-pick conflict on that path — a realistic scenario for any repo the user clones or pulls from an untrusted remote, with no unusual manual steps beyond the normal "resolve conflicts" workflow. The existing, tested guard (`resolveWithin`) already anticipates and blocks this exact symlink-escape technique elsewhere in the codebase, confirming it is a recognized and reachable threat model that this call site simply failed to apply.

### Recommendation
In `getResolutionDiff` (and any other direct `readFile(Path.join(repository.path, filePath), ...)` call operating on conflict/diff file paths), replace the raw `Path.join` + `readFile` with `resolveWithin(repository.path, filePath)` (as already done in `copilot-conflict-context.ts`), and refuse to read/return content when it returns `null`.

### Proof of Concept
1. Attacker prepares a branch where a tracked path (e.g. `notes.txt`) is a symlink pointing to a sensitive host file (e.g. `../../../../.ssh/id_rsa` or an absolute path), and modifies it so a merge with the victim's branch produces a conflict on that path.
2. Victim clones/fetches the attacker's branch and merges/rebases, hitting a conflict on `notes.txt`.
3. When the conflict-resolution UI calls `getResolutionDiff(repository, 'notes.txt', ...)`, `Path.join(repository.path, 'notes.txt')` resolves to the symlink, and `readFile` follows it, returning the contents of the victim's SSH key (or other targeted file) as `baseContent`, which is then surfaced in the diff/resolution UI (and potentially forwarded to the Copilot resolution pipeline).

**Note:** I could not fully trace every downstream consumer of `getResolutionDiff`'s output (e.g., whether it's always sent to the Copilot API or only rendered locally) within the available index; a Devin session with full repository access would be needed to confirm the exact data flow to the Copilot SDK for a complete exfiltration proof.
