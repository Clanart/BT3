### Title
Cross-transaction data/origin overwrite in `Bitcoin::get_outputs` corrupts scanned outputs - (File: processor/src/networks/bitcoin.rs)

### Summary
`Bitcoin::get_outputs` accumulates scanned `Output`s in a block-scoped `outputs` vector, then applies the *current* transaction's `presumed_origin` and Serai `data` to **every** output collected so far — not just the outputs from the transaction being processed. When a block contains two or more transactions paying a Serai key, the later transaction's origin/data overwrite the earlier transaction's outputs. An unprivileged Bitcoin sender controls both fields via their own transaction, giving attacker-controlled modification of deposit metadata — an integrity-only, network-reachable analog of CVE-2023-22043 (JavaFX, `I:H`).

### Finding Description
In `get_outputs`, `outputs` is declared once before iterating all non-coinbase transactions (`block.txdata[1 ..]`, `processor/src/networks/bitcoin.rs:686-699`). The `if outputs.is_empty() { continue; }` check at line 702 only skips the origin/data population when *no* outputs have been found yet; it does not scope the mutation to the current `tx`. Lines 731-736 then do:

```rust
for output in &mut outputs {
  if output.kind == OutputType::External {
    output.data.clone_from(&data);
  }
  output.presumed_origin.clone_from(&presumed_origin);
}
```

where `data` is `Self::extract_serai_data(tx)` and `presumed_origin` is derived from `tx.input[0]` of the *current* transaction (`processor/src/networks/bitcoin.rs:714-730`). Both loops run over the cumulative `outputs` vec, so any transaction later in the same block that also pays a scanned script rewrites `data`/`presumed_origin` on outputs produced by earlier transactions.

### Impact Explanation
- `data` on `OutputType::External` outputs carries the Serai InInstruction payload (e.g., destination/refund instructions for a bridge deposit). Overwriting it with a different transaction's `data` causes a deposit to be credited against attacker-chosen instruction bytes — unauthorized modification of critical data, matching the CVE's integrity-only impact profile.
- `presumed_origin` is similarly corrupted, misattributing which address funded the output.
- The attacker needs only to broadcast an ordinary Bitcoin transaction paying the same (publicly known) Serai key in the same block as the victim deposit — no special access, no key material.

### Likelihood Explanation
Requires two relevant payments to one Serai key in a single confirmed block (`N::CONFIRMATIONS` gates scanning, but blocks routinely contain many transactions). The attacker can observe a pending deposit transaction in the mempool and race it into the same block with a dust payment to the same script — a realistic, unprivileged action. Difficulty is comparable to the CVE's `AC:H`.

### Recommendation
Scope the origin/data assignment to only the outputs scanned from the current transaction, e.g.:

```rust
let start = outputs.len();
for output in scanner.scan_transaction(tx) { ...; outputs.push(output); }
if outputs.len() == start { continue; }
// populate origin and data
for output in &mut outputs[start ..] { ... }
```

Alternatively, collect per-transaction results and populate metadata before extending the block-level vector.

### Proof of Concept
1. Register a Scanner for a Serai group key; obtain its `p2tr` script (External offset `Scalar::ZERO`).
2. Victim broadcasts `txA` paying the script with InInstruction data `D_A`.
3. Attacker broadcasts `txB` paying a dust amount to the same script, with input[0] spending an attacker-controlled output and embedding InInstruction data `D_B`.
4. Both confirm in one block, `txA` before `txB` in `block.txdata`.
5. `get_outputs` scans `txA` → pushes output with correct data; then scans `txB` → pushes its output and rewrites `outputs[0].data` to `D_B` and `presumed_origin` to the attacker's address.
6. The processor emits the victim's deposit carrying the attacker's instruction data — misdirected credit, per `Output::data()`/`presumed_origin()` consumers (`processor/src/networks/bitcoin.rs:124-134`). [1](#0-0) [2](#0-1)

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
