### Title
Unsigned OP_RETURN operator-attribution output in `payout_tx` lets any third party rewrite which operator gets reimbursed - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
`create_payout_txhandler` embeds the fronting operator's `x_only_public_key` in an `OP_RETURN` output (output index 2) that is used later by verifiers as the sole, authoritative source of "who fronted this withdrawal and is owed reimbursement." The only signature present on the transaction is the user's signature over the withdrawal input, and it is required to use `SIGHASH_SINGLE | ANYONECANPAY`. Under BIP-341 taproot sighash rules, that sighash type commits only to input 0 and the output at the same index (output 0, the user's payout). It does **not** commit to output 1 (anchor) or output 2 (`OP_RETURN` operator attribution), and `ANYONECANPAY` means no other inputs are committed either. Consequently, anyone who observes an unconfirmed `payout_tx` (e.g. in the mempool, or via the `Withdraw`/`InternalWithdraw` RPC response) can rebuild a transaction that reuses the same signed input/output-0 pair but substitutes an arbitrary `OP_RETURN` payload (a different operator's xonly-pk, a bogus key, or none) and adds their own funding inputs/fee, then get that transaction mined instead of the original.

### Finding Description
- `create_payout_txhandler` (core/src/builder/transaction/operator_reimburse.rs:407-436) builds the payout tx with output 0 = user payout, output 1 = anchor, output 2 = `op_return_txout(operator_xonly_pk)`, and signs only input 0 with the user-supplied `taproot::Signature` via `set_p2tr_key_spend_witness`.
- `Operator::withdraw` (core/src/operator.rs:560-692) explicitly requires and verifies the sighash type to be `SinglePlusAnyoneCanPay` (`.wrap_err("...Ensure the signature uses SinglePlusAnyoneCanPay sighash type.")`, line 637), then calls `fund_raw_transaction`/`sign_raw_transaction_with_wallet`/`send_raw_transaction` to broadcast it. Nothing in this flow binds the `OP_RETURN` operator-identity output to the signature.
- On the verifier side, `update_finalized_payouts` (core/src/verifier.rs:2283-2353) determines which operator gets credited purely by parsing the `OP_RETURN` bytes out of whichever `payout_tx` actually confirms on-chain (`get_first_op_return_output` / `parse_op_return_data`), storing the result as `payout_payer_operator_xonly_pk` with no cryptographic proof that the named operator actually funded/broadcast that specific transaction.
- Downstream, `PayoutCheckerTask::run_once` (core/src/task/payout_checker.rs:31-112) and `Operator::handle_finalized_payout` (core/src/operator.rs:839+) use exactly that unauthenticated DB field to allocate a kickoff connector and drive the reimbursement (`Reimburse`) transaction for the credited operator, and `validate_payer_is_operator` (core/src/operator.rs:1686-1740) simply trusts `payout_payer_operator_xonly_pk` as the ground truth for "who is entitled to reimbursement."

Because the sighash leaves outputs 1 and 2 and all inputs beyond input 0 unauthenticated, the binding "operator credited == party that actually paid" is not enforced by cryptography anywhere in the pipeline; it is enforced only by hoping nobody rewrites the transaction before it confirms.

### Impact Explanation
This breaks the exact custody binding called out in the rules: "the operator credited versus the party that paid." Concretely:
- Any unprivileged actor who sees an unconfirmed `payout_tx` (from mempool relay, or from calling the operator's own `Withdraw`/`InternalWithdraw` RPC and observing the returned `RawSignedTx`) can reuse the signed input/output-0 pair, replace the `OP_RETURN` with an arbitrary operator's xonly-pk, add their own fee-paying inputs, and get their version mined in place of the original.
- If it confirms, `update_finalized_payouts` attributes the payout to the attacker-chosen operator. That operator's automation (`PayoutCheckerTask`) will then proceed through the normal reimbursement path and receive the `Reimburse` output from the vault — even though that operator never funded the user's payout.
- This matches the stated Critical impact category verbatim: "an operator reimbursed for a payout it never funded." It can also manifest as the correlated Critical case "an honest operator permanently unable to be reimbursed" for the operator whose original `payout_tx` was displaced before confirmation.

### Likelihood Explanation
The attack requires no privileged role (no verifier/operator/watchtower key, no majority hashrate) — only: (1) visibility into an unconfirmed `payout_tx` (readily available via mempool or the RPC response itself), and (2) the ability to construct/fund/broadcast a competing Bitcoin transaction that wins the race to confirmation (e.g., via a higher fee or full-RBF-accepting relays/miners). This is a standard low-cost mempool front-running/replacement scenario, not a theoretical edge case, and is directly analogous to the reported bug class (an unsigned, mutable field being read post-hoc to determine entitlement instead of being cryptographically bound at commitment time).

### Recommendation
Bind the operator-attribution data to the same signature that authorizes the spend, e.g.:
- Cover the `OP_RETURN` output (and ideally the anchor output) under the committed sighash by using `SIGHASH_ALL` (or `SIGHASH_SINGLE` is insufficient here) instead of the currently mandated `SinglePlusAnyoneCanPay`, or otherwise cryptographically commit to the operator's xonly-pk as part of what the withdrawal signature protects.
- Alternatively, require a signature from the claiming operator over the specific `payout_tx` (or its `OP_RETURN` payload) before crediting `payout_payer_operator_xonly_pk`, rather than trusting unauthenticated on-chain `OP_RETURN` bytes.
- At minimum, require the withdrawal-registration/Citrea commitment to pre-bind an expected operator (or a signature proving operator identity) so `update_finalized_payouts` can reject/ignore attribution data that isn't provably tied to the party that actually funded the confirmed transaction.

### Proof of Concept
1. Operator A calls `withdraw` (core/src/operator.rs:560-692) for withdrawal `idx`, producing `payout_tx_A`: input 0 = registered withdrawal UTXO with witness `user_sig` (sighash `SinglePlusAnyoneCanPay`), output 0 = user payout, output 1 = anchor, output 2 = `OP_RETURN(A_xonly_pk)`. A broadcasts it (unconfirmed).
2. Attacker observes `payout_tx_A` in the mempool (or obtains the equivalent raw tx via the `Withdraw`/`InternalWithdraw` RPC response, which returns the fully signed tx to the caller per `core/src/rpc/operator.rs:168-258`).
3. Attacker builds `payout_tx_X`: same input 0 (same outpoint, same witness — the signature is valid regardless of the rest of the transaction because `SIGHASH_SINGLE|ANYONECANPAY` only commits input 0/output 0), same output 0, but output 2 = `OP_RETURN(B_xonly_pk)` where B is an arbitrary/unrelated operator, plus attacker's own additional funding input(s)/change to cover fees (added exactly as `fund_raw_transaction` would for a legitimate operator).
4. Attacker broadcasts `payout_tx_X` with a higher fee (or via a full-RBF-friendly relay/miner) so it displaces `payout_tx_A` and confirms instead.
5. `update_finalized_payouts` (core/src/verifier.rs:2283-2353) parses the confirmed tx's `OP_RETURN`, sets `payout_payer_operator_xonly_pk = B`.
6. Operator B's `PayoutCheckerTask` (core/src/task/payout_checker.rs:31-112) picks up the "unhandled payout" and drives `handle_finalized_payout`/reimbursement to completion, causing the vault to reimburse B for a withdrawal B never funded. [1](#0-0) [2](#0-1) [3](#0-2) [4](#0-3) [5](#0-4)

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };
