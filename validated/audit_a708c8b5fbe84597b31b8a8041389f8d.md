### Title
No Verification That a CW Contract Actually Implements CW721/CW1155 Before Registering an ERC721/ERC1155 Pointer, Allowing Type-Confused Pointers That Permanently Break NFT/Multi-Token Interop - (File: precompiles/pointer/pointer.go)

### Summary
The `pointer` precompile's `AddCW721Pointer` and `AddCW1155Pointer` methods create an EVM-side ERC721/ERC1155 pointer contract for an arbitrary CosmWasm contract address supplied by the caller. The only check performed is a generic `{"contract_info":{}}` smart query used to extract a `name` and `symbol` string; there is no verification that the target contract actually implements the CW721 or CW1155 standard (e.g., by attempting a standard-specific query such as `num_tokens`, `all_tokens`, or `balance` with a `token_id`). Since `AddCW721` and `AddCW1155` use the exact same generic query, any CW20, CW1155, or arbitrary CosmWasm contract exposing a `contract_info` query with `name`/`symbol` fields can be registered as either an ERC721 or ERC1155 pointer.

### Finding Description
`AddCW721` at [1](#0-0)  and `AddCW1155` at [2](#0-1)  both issue the identical `wasmdKeeper.QuerySmartSafe(ctx, cwAddress, []byte("{\"contract_info\":{}}"))` call and simply extract `name`/`symbol` strings from the JSON response, without any interface-specific query proving the contract is actually CW721 or CW1155.

The extracted metadata is then passed straight to `UpsertERCCW721Pointer` / `UpsertERCCW1155Pointer` in [3](#0-2) , which deploys the corresponding pointer bytecode (`erc721`/`erc1155` artifact) bound to the supplied `cwAddr` — with no on-chain check that `cwAddr` actually supports the expected NFT/multi-token execute or query messages. The only anti-pointer-loop guard present is `evmAddressIsPointer`/`cwAddressIsPointer` in `x/evm/keeper/pointer.go`, which prevents pointer-to-pointer chains but does not validate token-standard conformance.

Once deployed, `CW721ERC721Pointer.sol` blindly issues cw721-style messages such as `transfer_nft`, `approve`, and `mint` against the registered CW address, as seen in [4](#0-3) . If the underlying contract is actually a CW20 or CW1155 contract (different message/query schema, different ownership/balance semantics), these calls will either revert unpredictably or, worse, silently succeed against unrelated CW20/CW1155 execute handlers that happen to share message names, corrupting pointer state and effectively locking any tokens interacted with through the mismatched pointer.

### Impact Explanation
Registering a pointer with a mismatched underlying token standard can permanently break interoperability for that token: `ownerOf`/`balanceOf`/`transferFrom` calls on the resulting ERC721/ERC1155 pointer will not correspond to real ownership/balances of the underlying contract, since the pointer assumes CW721/CW1155 semantics that the underlying contract doesn't implement. Any user who deposits/interacts with the mismatched pointer contract risks tokens becoming permanently stuck or transfers behaving inconsistently with actual on-chain ownership, matching the "permanent freezing"/fund-loss impact bar. Additionally, because pointer registration is a normal, permissionless EVM precompile call (`addCW721Pointer`/`addCW1155Pointer`) reachable by any address, this can be triggered by any unprivileged EVM caller.

### Likelihood Explanation
Any EVM account can call `addCW721Pointer(cwAddr)` or `addCW1155Pointer(cwAddr)` on the pointer precompile at `0x000000000000000000000000000000000000100b` for any CosmWasm contract address that responds to `{"contract_info":{}}` with `name`/`symbol` fields — this includes legitimate CW1155 contracts being registered as ERC721 pointers (or vice versa), and potentially other contracts that happen to expose a compatible `contract_info` query. No special privileges, front-running, or complex setup is required, only a single permissionless transaction.

### Recommendation
Add a standard-conformance check before registering CW721/CW1155 pointers, e.g., attempt a CW721-specific query (`num_tokens`, `all_nft_info`, or `owner_of` on a canary token) for `AddCW721`, and a CW1155-specific query (e.g., `balance` with `owner`+`token_id`, or `all_tokens`) for `AddCW1155`, rejecting registration if the standard-specific query fails or the response doesn't match the expected schema. Alternatively, maintain separate, non-overlapping query strings per pointer type so a contract implementing only one of CW20/CW721/CW1155 cannot satisfy the query used to register a pointer of the wrong type.

### Proof of Concept
1. Deploy or use an existing CW1155 contract implementing `contract_info` returning `{"name": "...", "symbol": "..."}` (per `example/cosmwasm/cw1155/src/contract.rs`).
2. From any EVM account, call `pointer.addCW721Pointer(cw1155ContractAddress)` on the pointer precompile at `0x...100b`.
3. Observe that `AddCW721` succeeds because the generic `contract_info` query matches, and `UpsertERCCW721Pointer` deploys an ERC721 pointer bound to the CW1155 address.
4. Interact with the resulting ERC721 pointer (`transferFrom`, `ownerOf`, `mint`) — because the underlying contract is CW1155 (batch/amount-based ownership) not CW721 (single-owner-per-token), these calls will diverge from actual token state, permanently breaking correct NFT semantics for that contract's pointer, analogous to the reported ERC20-as-NFT deposit issue.

func (p PrecompileExecutor) AddCW721(ctx sdk.Context, method *ethabi.Method, caller common.Address, args []interface{}, value *big.Int, evm *vm.EVM, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	cwAddr := args[0].(string)
	cwAddress, err := sdk.AccAddressFromBech32(cwAddr)
	if err != nil {
		return nil, 0, err
	}
	res, err := p.wasmdKeeper.QuerySmartSafe(ctx, cwAddress, []byte("{\"contract_info\":{}}"))
	if err != nil {
		return nil, 0, err
	}
	formattedRes := map[string]interface{}{}
	if err := json.Unmarshal(res, &formattedRes); err != nil {
		return nil, 0, err
	}
	name := formattedRes["name"].(string)
	symbol := formattedRes["symbol"].(string)
	contractAddr, err := p.evmKeeper.UpsertERCCW721Pointer(ctx, evm, cwAddr, utils.ERCMetadata{Name: name, Symbol: symbol})
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(contractAddr)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}
