### Title
Unauthenticated `InternalSendTx` RPC lets any network peer force the aggregator to broadcast an attacker-chosen Bitcoin transaction - (File: core/src/rpc/aggregator.rs)

### Summary
When `client_verification` is `false`, `create_grpc_server` wires the aggregator's gRPC service with `Interceptors::Noop`, which admits every request without any certificate or identity check [1](#0-0) . `AggregatorServiceImpl::internal_send_tx` deserializes the caller-supplied `raw_tx` and hands it straight to `tx_sender.insert_try_to_send` with no check that the transaction belongs to this aggregator's presigned transaction graph [2](#0-1) .

### Finding Description
The intended binding is: `transaction accepted by tx_sender.insert_try_to_send()` == `transaction previously presigned/authorized by the N-of-N or this aggregator's own signer`. In `internal_send_tx`, this binding is never checked — the function only validates that `raw_tx` deserializes into a syntactically valid `bitcoin::Transaction` and that `fee_type` converts, then immediately calls `self.tx_sender.insert_try_to_send(&mut dbtx, None, &signed_tx, fee_type.try_into()?, None, &[], &[], &[], &[])` [3](#0-2) . `insert_try_to_send` itself performs no ownership/authorization check either — it only deduplicates by txid and persists the transaction for the background sender loop [4](#0-3) .

Whether an attacker can reach this unauthenticated depends entirely on `config.client_verification`. When `true`, `create_grpc_server` installs `Interceptors::OnlyAggregatorAndSelf`; when `false`, it installs `Interceptors::Noop`, which simply returns `Ok(req)` for every request with no certificate inspection at all [5](#0-4) . This applies uniformly to every RPC exposed by `ClementineAggregatorServer`, including `InternalSendTx`.

Once queued, the background `TxSenderTaskInternal::run_once` loop picks the entry up via `try_to_send_unconfirmed_txs` and dispatches it to `send_cpfp_tx`, `send_rbf_tx`, or `send_no_funding_tx` based on the attacker-chosen `fee_type` [6](#0-5) . For `CPFP`, the sender will create and fund a fee-payer UTXO from its own wallet and pay to have the attacker's transaction confirmed [7](#0-6) ; for `NoFunding`/`RBF`, it directly calls `send_raw_transaction` [8](#0-7) . None of these paths re-verify that the transaction originates from Clementine's own presigned protocol graph.

No other guard intercepts this: `is_deposit_valid`, `only_aggregator_and_self`, `SECP.verify_schnorr`, and the presigned transaction graph are never consulted on this path, because the request never reaches any bridge-protocol validation logic — it is a raw pass-through to the generic tx broadcaster.

### Impact Explanation
With `client_verification == false`, any unprivileged party who can reach the aggregator's gRPC port can force it to broadcast an arbitrary, attacker-supplied Bitcoin transaction and, depending on `fee_type=Cpfp`, cause the aggregator/tx-sender wallet to spend its own BTC funding fees for that unrelated transaction. This is squarely the "unauthenticated state-changing or broadcasting call" category defined as High severity. It is repeatable per call (subject to the tx-sender's own dedup-by-txid, which an attacker trivially bypasses by varying the transaction). It does not, by itself, let the attacker move bridge value out of a vault UTXO (it cannot forge N-of-N signatures for bridge-owned UTXOs), so the blast radius is bounded to the aggregator's operational tx-sender resources rather than the vaulted funds — but it is a genuine unauthenticated-broadcast primitive against protocol infrastructure.

### Likelihood Explanation
Requires the operational precondition `config.client_verification == false` and the `automation` feature enabled, plus network reachability to the aggregator's gRPC port — both are supported, non-default configuration states in this codebase (default/test/production configs all set `client_verification = true`) [9](#0-8) . Given that precondition, exploitation cost is a single unauthenticated gRPC call plus, for CPFP fee_type, no attacker cost at all (the aggregator pays fees from its own wallet). Feasibility is high and trivially repeatable whenever the misconfiguration is present.

### Recommendation
Never wire `Interceptors::Noop` for the aggregator's automation-only/internal RPCs regardless of `client_verification`; at minimum, `internal_send_tx` (and other `Internal*` RPCs) should always require the entity's own client certificate (mirroring `only_aggregator_and_self`'s internal-method branch used for verifier/operator) independent of the `client_verification` toggle. Additionally, `internal_send_tx` should validate that `signed_tx` matches a transaction already known to/derivable from the aggregator's own presigned transaction graph (e.g., checked against stored round/kickoff/move-to-vault transactions) before calling `insert_try_to_send`.

// cargo test -p clementine-core --features automation internal_send_tx_unauthenticated_broadcast
#[tokio::test]
async fn internal_send_tx_unauthenticated_broadcast() {
    let mut config = create_test_config_with_thread_name().await;
    config.client_verification = false; // precondition
    let regtest = create_regtest_rpc(&mut config).await;

    let (addr, _shutdown) = create_aggregator_grpc_server(config.clone()).await.unwrap();

    // Certificate-less client (no mTLS identity) connecting to the aggregator port.
    let mut client = ClementineAggregatorClient::connect(format!("http://{addr}"))
        .await
        .unwrap();

    // Attacker crafts an arbitrary, valid, but bridge-unrelated signed tx.
    let attacker_tx: bitcoin::Transaction = build_self_funded_valid_tx(&regtest).await;

    let resp = client
        .internal_send_tx(SendTxRequest {
            raw_tx: Some(RawSignedTx { raw_tx: bitcoin::consensus::serialize(&attacker_tx) }),
            fee_type: FeeType::Cpfp as i32,
        })
        .await;

    // Assert LHS == RHS binding is broken: the call succeeds despite no proof
    // this tx belongs to the aggregator's presigned tree.
    assert!(resp.is_ok(), "unauthenticated call should have been rejected but succeeded");

    // Assert the attacker's tx entered tx_sender's queue / eventually the mempool,
    // i.e. tx_sender broadcast something never authorized by N-of-N or self-signer.
    poll_until_condition(
        async || Ok(regtest.rpc().get_mempool_entry(&attacker_tx.compute_txid()).await.is_ok()),
        Some(Duration::from_secs(15)),
        Some(Duration::from_millis(200)),
    )
    .await
    .expect("attacker tx never reached mempool");
}

    #[tracing::instrument(skip_all, fields(try_to_send_id, tx_meta=?tx_metadata))]
    pub async fn send_no_funding_tx(
        &self,
        try_to_send_id: u32,
        tx: Transaction,
        tx_metadata: Option<TxMetadata>,
    ) -> Result<()> {
        match self.rpc.send_raw_transaction(&tx).await {
            Ok(sent_txid) => {
                tracing::debug!(
                    try_to_send_id,
                    "Successfully sent no funding tx with txid {}",
                    sent_txid
                );
                let _ = self
                    .db
                    .update_tx_debug_sending_state(try_to_send_id, "no_funding_send_success", true)
                    .await;
            }
            Err(e) => {
                let err_str = e.to_string();
                if rpc_errors::is_rejecting_replacement_error(&err_str) {
                    tracing::debug!(
                        try_to_send_id,
                        "No funding tx rejected (tx already in mempool): {err_str}"
                    );
                    return Ok(());
                } else {
                    tracing::error!(
                        "Failed to send no funding tx with try_to_send_id: {try_to_send_id:?} and metadata: {tx_metadata:?}"
                    );
                    log_error_for_tx!(
                        self.db,
                        try_to_send_id,
                        format!("send_raw_transaction error for no funding tx: {err_str}")
                    );
                }
                let _ = self
                    .db
                    .update_tx_debug_sending_state(try_to_send_id, "no_funding_send_failed", true)
                    .await;
                return Err(SendTxError::Other(eyre::eyre!(e)));
            }
        };

        Ok(())
    }

    /// Creates and broadcasts a new "fee payer" UTXO to be used for CPFP
    /// transactions.
    ///
    /// This function is called when a CPFP attempt fails due to insufficient funds
    /// in the existing confirmed fee payer UTXOs associated with a transaction (`bumped_id`).
    /// It calculates the required fee based on the parent transaction (`tx`) and the current
    /// `fee_rate`, adding a buffer (2x required fee + dust limit) to handle potential fee spikes.
    /// It then sends funds to the `TxSender`'s own signer address using the RPC's
    /// `send_to_address` and saves the resulting UTXO information (`outpoint`, `amount`)
    /// to the database, linking it to the `bumped_id`.
    ///
    /// # Arguments
    /// * `bumped_id` - The database ID of the parent transaction requiring the fee bump.
    /// * `tx` - The parent transaction itself.
    /// * `fee_rate` - The target fee rate for the CPFP package.
    /// * `total_fee_payer_amount` - The sum of amounts in currently available confirmed fee payer UTXOs.
    /// * `fee_payer_utxos_len` - The number of currently available confirmed fee payer UTXOs.
    async fn create_fee_payer_utxo(
        &self,
        bumped_id: u32,
        dbtx: Option<&mut TxSenderTransaction>,
        tx: &Transaction,
        fee_rate: FeeRateKvb,
        total_fee_payer_amount: Amount,
        fee_payer_utxos_len: usize,
    ) -> Result<()> {
        tracing::debug!(
            "Creating fee payer UTXO for txid {} with bump id {}",
            &tx.compute_txid().to_string(),
            bumped_id
        );
        let required_fee = Self::calculate_required_fee(
            tx.weight(),
            fee_payer_utxos_len + 1,
            fee_rate,
            FeePayingType::CPFP,
        )?;

        // Aggressively add 2x required fee to the total amount to account for sudden spikes
        // We won't actually use 2x fees, but the fee payer utxo will hold that much amount so that while fee payer utxo gets mined
        // if fees increase the utxo should still be sufficient to fund the tx with high probability
        // leftover fees will get sent back to wallet with a change output in fn create_child_tx
        let new_total_fee_needed = required_fee
            .checked_mul(2)
            .and_then(|fee| fee.checked_add(MIN_TAPROOT_AMOUNT));
        if new_total_fee_needed.is_none() {
            return Err(eyre!("Total fee needed is too large, required fee: {}, total fee payer amount: {}, fee rate: {}", required_fee, total_fee_payer_amount, fee_rate).into());
        }
        let new_fee_payer_amount =
            new_total_fee_needed.and_then(|fee| fee.checked_sub(total_fee_payer_amount));

        let new_fee_payer_amount = match new_fee_payer_amount {
            Some(fee) => fee,
            // if underflow, no new fee payer utxo is needed, log it anyway in case its a bug
            None => {
                tracing::debug!("create_fee_payer_utxo was called but no new fee payer utxo is needed for tx: {:?}, required fee: {}, total fee payer amount: {}, current fee rate: {}", tx, required_fee, total_fee_payer_amount, fee_rate);
                return Ok(());
            }
        };

        tracing::debug!(
            "Creating fee payer UTXO with amount {} ({} sat/kvB)",
            new_fee_payer_amount,
            fee_rate
        );

        let fee_payer_tx = Transaction {
            version: Version::TWO,
            lock_time: LockTime::ZERO,
            input: vec![],
            output: vec![TxOut {
                value: new_fee_payer_amount,
                script_pubkey: self.signer.address().script_pubkey(),
            }],
        };

        let fee_payer_bytes = crate::serialize_tx_for_fund_raw(&fee_payer_tx);

        let funded_fee_payer_tx = self
            .rpc
            .fund_raw_transaction(
                &fee_payer_bytes,
                Some(&FundRawTransactionOptions {
                    add_inputs: Some(true),
                    // for cpfp txs, the speed of tx inclusion is not that important, so we can not use unsafe utxos and wait for them to become safe. Also all cpfp fee payer tx's are safe (all wallet owned inputs), so wallet can already chain them
                    include_unsafe: Some(self.include_unsafe),
                    change_address: None,
                    change_position: None,
                    change_type: None,
                    include_watching: None,
                    lock_unspents: None,
                    fee_rate: Some(Amount::from_sat(fee_rate.to_sat_per_kvb())),
                    subtract_fee_from_outputs: None,
                    replaceable: Some(true),
                    conf_target: None,
                    estimate_mode: None,
                }),
                None,
            )
            .await
            .wrap_err("Failed to fund cpfp fee payer tx")?
            .hex;

        let signed_fee_payer_tx: Transaction = bitcoin::consensus::deserialize(
            &self
                .rpc
                .sign_raw_transaction_with_wallet(&funded_fee_payer_tx, None, None)
                .await
                .wrap_err("Failed to sign funded tx through bitcoin RPC")?
                .hex,
        )
        .wrap_err("Failed to deserialize signed tx")?;

        let outpoint_vout = signed_fee_payer_tx
            .output
            .iter()
            .position(|o| {
                o.value == new_fee_payer_amount
                    && o.script_pubkey == self.signer.address().script_pubkey()
            })
            .ok_or(eyre!("Failed to find outpoint vout"))?;

        self.rpc
            .send_raw_transaction(&signed_fee_payer_tx)
            .await
            .wrap_err("Failed to send signed fee payer tx")?;
