## Title
Argument Injection via Unsanitized `commitish` in `git worktree add` — ([File: app/src/lib/git/worktree.ts])

### Summary
`addWorktree()` builds the `git worktree add` argv by appending the raw, attacker-influenceable `commitish` string as the last positional argument with **no `--` end-of-options terminator**, unlike every sibling git-wrapper function in this codebase that accepts ref/path input. A local branch whose name begins with `-` (created, for example, by checking out an attacker-controlled remote branch) reaches this unguarded sink when the user later creates a worktree from that branch, letting the value be parsed by `git` as an option rather than a ref.

### Finding Description
`addWorktree` constructs its argv like this: [1](#0-0) 

There is no `--` separator before `options.commitish`, and no call to `sanitizedRefName` on it.

In `AddWorktreeDialog.onSubmit`, when the user selects an existing **local** branch, the raw `branch.name` is passed straight through as `commitish`: [2](#0-1) 

(Note the remote-branch path uses `branch.ref`, the fully-qualified `refs/remotes/<remote>/<name>` string, which cannot start with `-`, so that specific path is not exploitable — only the pre-existing **local** branch path is.)

This codebase already recognizes this exact class of bug and defends against it elsewhere: `checkoutBranch` explicitly appends a trailing `--` after the branch name specifically to stop a ref name from being reinterpreted as an option: [3](#0-2) 

The same `--`-terminator pattern is used consistently across the git wrapper layer (`checkout.ts`, `reset.ts`, `rm.ts`, `add.ts`, `clone.ts`, `apply.ts`, `log.ts`, `reflog.ts`, `stash.ts`, `submodule.ts`, `rev-list.ts`, `diff-index.ts`), but `worktree.ts`'s `addWorktree` was never given this protection. Git's own `check-ref-format` rules (no leading `.`, no `..`, no control/`~^: ?*[` chars, no leading/trailing `/`, no trailing `.`, no `@{`, not literal `@`, no `\`) do **not** forbid a ref/branch name beginning with `-`, so such a branch name is a syntactically legal git ref and can persist as a local branch (e.g., created via "Checkout branch" from a malicious remote, which itself is protected by the `--` terminator in `checkout.ts`, but that protection does not extend to the later worktree-creation step).

### Impact Explanation
If exploited, `git worktree add <path> <injected-flag>` is parsed by git as an option rather than a commit-ish. Depending on which flag string the attacker chooses, this can corrupt or redirect what gets checked out into the new worktree (e.g., silently checking out an unexpected ref/orphan state), and — because `git worktree add` accepts option-like arguments that take file/string parameters (e.g., `--reason=<string>` combined with `--lock`, or interaction with `-b`) — can be leveraged for argument-injection-driven corruption of repository state. This matches the "silent corruption of what the user commits/checks out" impact category.

### Likelihood Explanation
Exploitation requires: (1) the victim fetches from an attacker-controlled/malicious remote containing a branch whose name begins with `-`; (2) the victim checks that branch out locally (a normal, expected workflow, and itself already hardened against argument injection in `checkout.ts`); (3) the victim later opens "Add Worktree" and selects that now-local branch. This is a multi-step but entirely natural user workflow requiring no unusual actions, matching the fact pattern the codebase's own `checkout.ts` fix was designed to prevent — just one hop later in the pipeline.

### Recommendation
Add a `--` terminator (and/or route `commitish`/`createBranch` through the same ref-sanitization/verification used elsewhere) in `addWorktree`:
```ts
args.push(path)
args.push('--')
if (options.commitish) {
  args.push(options.commitish)
}
```
Apply the same fix pattern already established in `checkout.ts` (`getBranchCheckoutArgs`) to keep this git-wrapper consistent with the rest of the codebase's argument-injection defenses.

### Proof of Concept
1. Create/control a remote with a branch literally named `--upload-pack=/tmp/evil.sh` (a syntactically valid git ref name).
2. Victim fetches this remote and uses "Checkout branch" to create a local branch of the same name (protected checkout succeeds due to `--` terminator in `checkout.ts`).
3. Victim opens "Add Worktree", selects this local branch.
4. `AddWorktreeDialog.onSubmit` calls `addWorktree(repository, fullPath, { commitish: branch.name })` with `branch.name === '--upload-pack=/tmp/evil.sh'`.
5. `addWorktree` invokes `git worktree add <fullPath> --upload-pack=/tmp/evil.sh` with no `--` separator — git parses the last token as an option rather than a commit-ish argument, confirming argument injection into `commitish`.
