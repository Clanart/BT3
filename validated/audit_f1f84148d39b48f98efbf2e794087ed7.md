### Title
Auction bid EIP-712 signature silently omits `MaxGasPrice` when the on-chain `AUCTION_VERSION` string doesn't exact-match "0.0.2", allowing tamper of a searcher's bid price ceiling - (File: kaiax/auction/eip712.go, blockchain/system/auction.go, kaiax/auction/impl/execution.go)

### Summary
The Fairswap report's root cause is that multiple conceptually-identical interfaces (`orderEThToToken`/`OrderBaseToSettlement`/`orderBaseToSettlement`) were implemented independently instead of being unified behind a single, type-safe interface, so callers must guess/string-match which one applies. The kaia auction module (KIP-249) has the same structural pattern: two structurally different `AuctionTx` interfaces (v2.1 without `maxGasPrice`, v3.0 with `maxGasPrice`) are selected at runtime by comparing an on-chain `AUCTION_VERSION` string against two hard-coded literals, with an un-validated "else" branch that silently falls back to the older (v2.1) interface instead of failing closed.

### Finding Description
`ReadAuctionVersion` reads the deployed entry point's `AUCTION_VERSION` view and returns it as a free-form string [1](#0-0) . This string is then compared against the constants `AuctionVersionV2 = "0.0.1"` / `AuctionVersionV3 = "0.0.2"` [2](#0-1)  in two independent places that must stay consistent with each other and with the deployed contract:

1. `EncodeAuctionCallData`, which builds the `call()` calldata: any value other than the exact literal `AuctionVersionV3` "defaults to the v2.1 ABI" [3](#0-2) .
2. `Bid.GetHashTypedData`, which builds the EIP-712 struct hash that the searcher signs: "Unknown version: default to v2.1 typehash" [4](#0-3) .

The v2.1 struct (`auctionType`) omits `maxGasPrice` entirely from the signed data, while the v3.0 struct (`auctionTypeV3`) includes it [5](#0-4) . The bid pool's signature check calls exactly this function with the version string it cached from the last successful `ReadAuctionVersion()` call: `bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion)` [6](#0-5) , and `auctionEntryPointVersion` is populated purely by string equality logic in `updateAuctionInfo`/`ReadAuctionVersion`, with no validation that it is one of the two known literals before use [7](#0-6) .

Consequently, whenever `auctionEntryPointVersion` is anything other than the exact string `"0.0.2"` (empty on startup before the first successful `updateAuctionInfo`, a future `v3.x`/`v4` deployment whose `AUCTION_VERSION` string doesn't hit the hard-coded literal, or any deployment returning a differently formatted version string) while the deployed entry point is actually running the v3.0 ABI (which carries `maxGasPrice` in `AuctionTx`), the node validates incoming bids using the v2.1 EIP-712 typehash that does not commit to `maxGasPrice`. `ValidateSearcherSig` only checks that the recovered signer over that (v2) digest matches `bid.Sender` [8](#0-7) ; it never fails just because `bid.MaxGasPrice != nil`. This is structurally identical to the Fairswap issue: consumers pick between multiple interface variants using unenforced name/string matching instead of a single canonical, versioned type, and the mismatch silently degrades to a weaker interface rather than rejecting the input.

### Impact Explanation
Bids are gossiped over the wire via `BidMsg`/`handleBidMsg` and independently via the `auction_submitBid` RPC, both of which route to `HandleBid` → `bidPool.insertBid` → `validateBidSigs` [9](#0-8) , [10](#0-9) . Any relaying peer or the RPC path itself sits between the searcher who signs the bid and the CN that validates it. If version detection is in the fallback state described above, that intermediary can mutate `bid.MaxGasPrice` after the searcher signed it, and `ValidateSearcherSig` will still pass because the field was never part of the signed digest. A modified `MaxGasPrice` changes the price ceiling the searcher committed to for inclusion of their auction transaction, which is a fee/auction-settlement parameter directly affecting how much the searcher pays — i.e., unauthorized tampering with an auction-settlement value that the searcher never actually authorized.

### Likelihood Explanation
This requires the client's cached `auctionEntryPointVersion` to differ from the exact literal `"0.0.2"` while the live entry point contract is the v3.0 ABI (with `maxGasPrice`). This is plausible in normal operational conditions: at node startup/resync before `updateAuctionInfo` has run once, during a live migration from v2.1 to v3.0 (or any future version bump), or if the deployed `AUCTION_VERSION` string ever diverges even slightly from the hard-coded literal. Because the fallback is silent (no error, no rejection) rather than fail-closed, the condition is not self-evident from logs/behavior, increasing the chance it goes unnoticed in production.

### Recommendation
Do not use free-form string equality with a silent "else = v2.1" default for both wire-encoding and EIP-712 signing decisions. Instead:
- Make `ReadAuctionVersion`/`EncodeAuctionCallData`/`GetHashTypedData` fail closed (return an explicit error) whenever the version string is not one of the exactly-recognized, enumerated versions, rather than silently defaulting to v2.1.
- Represent the auction version as a strongly-typed enum resolved once at the source (`ReadAuctionVersion`) and propagated as that type everywhere, instead of re-comparing raw strings against literals in multiple independent call sites (`blockchain/system/auction.go` and `kaiax/auction/eip712.go`).
- Add a unit/integration test asserting that an unrecognized/garbled `AUCTION_VERSION` value causes bid processing to halt (module treated as "not set", mirroring the existing `auctioneer == common.Address{}` fail path) rather than falling back to v2.1 semantics.

### Proof of Concept
1. Deploy (or upgrade the registry to point to) a v3.0 `AuctionEntryPoint` whose `AUCTION_VERSION()` returns a value that isn't the exact literal `"0.0.2"` (e.g., due to a future minor version bump, or simply observe the startup window before the module's first `updateAuctionInfo` call, where `auctionEntryPointVersion` is `""`).
2. A searcher signs a v3-style bid including a non-zero `MaxGasPrice`, calling `Bid.GetHashTypedData(chainId, verifyingContract, "0.0.2")` client-side to get the correct v3 digest and sign it with `SearcherSig`.
3. A malicious relaying peer (or a compromised/misbehaving hop on the `auction_submitBid` path) intercepts the bid and changes `bid.MaxGasPrice` to an arbitrary value, leaving `SearcherSig` untouched.
4. The receiving CN node's `bidPool.validateBidSigs` calls `bid.ValidateSearcherSig(chainId, entryPoint, bp.auctionEntryPointVersion)` with the non-`"0.0.2"` cached version, which internally calls `GetHashTypedData(..., version)` and — per the "Unknown version: default to v2.1 typehash" branch — computes the digest over the v2.1 struct (`auctionType`), which never includes `MaxGasPrice`. The recovered signer still equals `bid.Sender`, so `ValidateSearcherSig` returns `nil`, and the tampered bid (with attacker-controlled `MaxGasPrice`) is accepted into the bid pool as genuinely signed by the searcher [8](#0-7) , [4](#0-3) .

Note: I was not able to fully verify from the index whether any additional cross-check exists elsewhere in the codebase (e.g., inside the on-chain Solidity `AuctionEntryPoint.sol` contracts, which live outside this repo's indexed sources as a git submodule under `kaia-system-contracts`) that would independently re-validate `maxGasPrice` against the signature on-chain and thus mitigate this at settlement time. If such on-chain re-validation exists and is strict, the practical impact would be reduced to bid-pool-level admission inconsistency rather than final settlement theft; confirming this would require inspecting the actual deployed `IAuctionEntryPoint`/`AuctionEntryPoint` Solidity source, which is not part of this indexed repository content.

// ReadAuctionVersion reads the AUCTION_VERSION view from the given entry-point
// contract. The result distinguishes v2.1 ("0.0.1") from v3.0 ("0.0.2") so
// callers can pick the appropriate EIP-712 typehash and ABI.
//
// The v3.0 binding is used for the call: AUCTION_VERSION() is a public-constant
// getter with the same selector on both v2.1 and v3.0 contracts, so the same
// typed binding works against either deployment.
func ReadAuctionVersion(backend bind.ContractCaller, contractAddr common.Address, num *big.Int) (string, error) {
	caller, err := contractsv3.NewIAuctionEntryPointCaller(contractAddr, backend)
	if err != nil {
		return "", err
	}
	return caller.AUCTIONVERSION(&bind.CallOpts{BlockNumber: num})
}

// GetHashTypedData returns the EIP-712 digest for the bid.
// version must match the on-chain AUCTION_VERSION of the entry-point contract
// the bid targets; "0.0.2" selects the v3.0 struct typehash (with maxGasPrice),
// any other value falls back to the v2.1 typehash.
func (b *Bid) GetHashTypedData(chainId *big.Int, verifyingContract common.Address, version string) []byte {
	if chainId == nil {
		return nil
	}

	domain := EIP712Domain{
		EIP712DomainTypeHash: eip712TypeHash,
		NameHash:             auctionNameHash,
		VersionHash:          crypto.Keccak256Hash([]byte(version)),
		ChainId:              chainId,
		VerifyingContract:    verifyingContract,
	}

	domainSeparator := EncodeEIP712(domain)

	var structHash []byte
	if version == AuctionVersionV3 {
		structHash = EncodeEIP712(bidV3{b})
	} else if version == AuctionVersionV2 {
		structHash = EncodeEIP712(b)
	} else {
		// Unknown version: default to v2.1 typehash.
		structHash = EncodeEIP712(b)
	}

	return crypto.Keccak256([]byte{0x19, 0x01}, domainSeparator, structHash)
}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}

// updateAuctionInfo updates the auctioneer address and auction entry point address for the given block number.
// It expects the `num` is after Randao fork.
// It returns true if the non-zero auctioneer address and auction entry point address are set, otherwise false.
func (a *AuctionModule) updateAuctionInfo(num *big.Int) bool {
	auctioneer := common.Address{}
	auctionEntryPointAddr := common.Address{}
	auctionEntryPointVersion := ""
	bidTxGasBuffer := uint64(0)

	defer func() {
		a.bidPool.updateAuctionInfo(auctioneer, auctionEntryPointAddr, auctionEntryPointVersion, bidTxGasBuffer)
	}()

	header := a.Chain.GetHeaderByNumber(num.Uint64())
	if header == nil {
		return false
	}
	_, err := a.Chain.StateAt(header.Root)
	if err != nil {
		return false
	}

	backend := backends.NewBlockchainContractBackend(a.Chain, nil, nil)

	// 1. Read auction entry point address
	auctionEntryPointAddr, err = system.ReadActiveAddressFromRegistry(backend, system.AuctionEntryPointName, num)
	if err != nil {
		return false
	}

	if auctionEntryPointAddr == (common.Address{}) {
		return false
	}

	// 2. Read auctioneer address
	auctioneer, err = system.ReadAuctioneer(backend, auctionEntryPointAddr, num)
	if err != nil {
		return false
	}

	if auctioneer == (common.Address{}) {
		return false
	}

	// 3. Read gas buffer estimate
	bidTxGasBuffer, err = system.ReadGasBufferEstimate(backend, auctionEntryPointAddr, num)
	if err != nil {
		return false
	}

	// 4. Read AUCTION_VERSION to pick the right EIP-712 typehash and ABI for bids targeting this entry point.
	auctionEntryPointVersion, err = system.ReadAuctionVersion(backend, auctionEntryPointAddr, num)
	if err != nil {
		return false
	}

	return true
}

func (b *Bid) ValidateSearcherSig(chainId *big.Int, verifyingContract common.Address, version string) error {
	if chainId == nil {
		return ErrNilChainId
	}

	if common.EmptyAddress(verifyingContract) {
		return ErrNilVerifyingContract
	}

	digest := b.GetHashTypedData(chainId, verifyingContract, version)

	recoveredSender, err := getSigner(b.SearcherSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover searcher sig: %v", err)
	}

	if recoveredSender != b.Sender {
		return fmt.Errorf("invalid searcher sig: expected %v, calculated %v", b.Sender.String(), recoveredSender.String())
	}

	return nil
}

// maxBidMsgSize bounds an encoded BidMsg: the Data cap plus slack for the other fields.
const maxBidMsgSize = auction_impl.BidTxMaxDataSize + 2048

// handleBidMsg handles bid message.
func handleBidMsg(pm *ProtocolManager, p Peer, msg p2p.Msg) error {
	if pm.IsAuctionModuleDisabled() {
		return nil
	}
	if p.ConnType() != common.CONSENSUSNODE {
		return errResp(ErrInvalidMsgCode, "bid message from a non-CN peer: conntype %d", p.ConnType())
	}

	if uint64(msg.Size) > maxBidMsgSize {
		return errResp(ErrMsgTooLarge, "msg %v: %v > %v", msg, msg.Size, maxBidMsgSize)
	}

	var data *auction.Bid
	if err := msg.Decode(&data); err != nil {
		return errResp(ErrDecode, "msg %v: %v", msg, err)
	}

	pm.auctionModule.HandleBid(p.GetID(), data)

	return nil
}
