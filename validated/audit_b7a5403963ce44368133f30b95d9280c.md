### Title
Missing null check on parsed inner-puzzle output causes unhandled `AssertionError` when processing an attacker-crafted NFT transfer solution - (File: chia/wallet/nft_wallet/nft_puzzle_utils.py)

### Summary
`get_metadata_and_phs()` in [1](#0-0)  derives the recipient puzzle hash of an NFT transfer by running the p2 inner puzzle against the attacker-supplied `CoinSpend.solution` and scanning the resulting conditions for a `CREATE_COIN` with a memo/hint atom of `1`. If no such condition is produced by the inner solution, `puzhash_for_derivation` stays `None` and the function does `assert puzhash_for_derivation`, an ordinary Python `assert` with no null check/graceful error path. This is exactly the same bug class as the ImageMagick issue: a value derived from untrusted, attacker-controlled input is used without validating it is non-null before being dereferenced, resulting in a crash rather than a handled error.

### Finding Description
`get_metadata_and_phs` is invoked directly on data coming from the network/counterparty, without any surrounding validation of the puzzle-reveal/solution pair beyond curry-structure matching done in `UncurriedNFT.uncurry` (which is wrapped in `try/except`, unlike this function):
- `NFTWallet.identify()` calls it while routing every newly observed NFT coin during wallet sync: [2](#0-1) 
- `NFTWallet.puzzle_solution_received()` calls it when adding an NFT coin to the wallet: [3](#0-2) 
- `WalletStateManager.manual_nft_search()` calls it for RPC-driven NFT lookups: [4](#0-3) 

The function itself:

An attacker who sends (or offers) an NFT coin whose inner p2 puzzle/solution produces conditions with no `CREATE_COIN ... hint==1` (e.g. only a `CREATE_COIN` with a different/absent hint, or none at all — perfectly legal from CLVM's perspective since the inner puzzle is attacker-chosen for coins not yet claimed by the victim) causes `puzhash_for_derivation` to remain `None`, triggering an unhandled `AssertionError`. Because `UncurriedNFT.uncurry` already succeeds (it only validates the singleton/NFT/ownership-layer curry structure, not the *solution*), this exception surfaces deep inside wallet-sync processing (`determine_coin_type` → `NFTWallet.identify`) for every NFT-shaped coin the wallet observes on-chain, including ones the wallet does not even own yet.

### Impact Explanation
An unhandled `AssertionError` raised while iterating incoming coin states in `WalletStateManager` can abort the coin-state processing task for that peer/sync batch. Since NFT coin identification happens unconditionally for any coin whose puzzle uncurries to the NFT singleton pattern (regardless of ownership), a single malicious NFT mint/transfer broadcast on-chain (or delivered via an offer/trade prior to acceptance) can repeatedly throw during every wallet's sync pass that observes it, disrupting normal transaction/coin-state processing for the wallet (a spend-triggered transaction-processing halt in the wallet sync path). This matches the "spend-triggered transaction-processing halt" acceptance criterion.

### Likelihood Explanation
Reachable by any unprivileged actor: minting or transferring an NFT with a custom p2 inner puzzle (fully attacker-controlled, since the p2 layer is standard/arbitrary CLVM) that yields no `CREATE_COIN ... 1` hinted condition is trivial to construct and can be pushed to the mempool/chain like any other spend bundle. No special privileges, and no cooperation from the victim wallet's owner is required — the crash occurs purely from observing the coin during normal chain sync.

### Recommendation
Replace the bare `assert puzhash_for_derivation` in `get_metadata_and_phs` with an explicit `None` check that raises a well-defined, caught exception type (e.g. `ValueError`), and ensure all call sites (`NFTWallet.identify`, `NFTWallet.puzzle_solution_received`, `WalletStateManager.manual_nft_search`) treat this as "not a valid/ownable NFT transfer" (skip/ignore) rather than letting the exception propagate uncaught through the wallet-sync call stack, consistent with how `UncurriedNFT.uncurry` already tolerates malformed curry data.

### Proof of Concept
1. Mint or acquire an NFT-shaped coin whose inner p2 puzzle is a custom CLVM program (not the standard puzzle) that runs to produce conditions with a `CREATE_COIN` whose memo/hint list is empty or has an atom other than `1` (or no `CREATE_COIN` at all).
2. Spend it (or have it appear on chain) with that solution.
3. Any wallet that syncs this coin invokes `WalletStateManager.determine_coin_type` → `NFTWallet.identify` → `get_metadata_and_phs`, hits `assert puzhash_for_derivation` with `puzhash_for_derivation is None`, and raises an unhandled `AssertionError`, per [5](#0-4)  and [2](#0-1) .

Note: I was unable to fully confirm within the available tool budget whether `determine_coin_type`'s caller in `wallet_state_manager.py` wraps this specific call in a broad `try/except` that would downgrade the crash to a logged/skipped error rather than aborting the sync task — this is a limitation of the index/time available and should be verified directly in a full checkout of `chia/wallet/wallet_state_manager.py` (`_add_coin_state`/`determine_coin_type` call chain) before relying on the severity assessment above.

def get_metadata_and_phs(unft: UncurriedNFT, solution: SerializedProgram) -> tuple[Program, bytes32]:
    conditions = unft.p2_puzzle.run(unft.get_innermost_solution(Program.from_serialized(solution)))
    metadata = unft.metadata
    puzhash_for_derivation: bytes32 | None = None
    for condition in conditions.as_iter():
        if condition.list_len() < 2:
            # invalid condition
            continue
        condition_code = condition.first().as_int()
        log.debug("Checking condition code: %r", condition_code)
        if condition_code == -24:
            # metadata update
            metadata = update_metadata(metadata, condition)
            metadata = Program.to(metadata)
        elif condition_code == 51:
            atom = condition.rest().rest().first().as_int()

            if atom == 1:
                # destination puzhash
                if puzhash_for_derivation is not None:
                    # ignore duplicated create coin conditions
                    continue
                memo = bytes32(condition.at("rrrff").as_atom())
                puzhash_for_derivation = memo
                log.debug("Got back puzhash from solution: %s", puzhash_for_derivation)
    assert puzhash_for_derivation
    return metadata, puzhash_for_derivation
