### Title
Deep-link `openrepo` action can be triggered to fetch/clone/checkout attacker-chosen remotes and open PRs without an explicit user-initiated "clone/open" confirmation gate on the URL's authenticity - (File: `app/src/lib/parse-app-url.ts`, `app/src/ui/dispatcher/dispatcher.ts`)

### Summary
GitHub Desktop registers OS-level protocol handlers (`x-github-client://`, `x-github-desktop-auth://`, and legacy `github-mac://`/`github-windows://`) that any link, webpage, or email a user clicks can invoke. `parseAppURL` in `app/src/lib/parse-app-url.ts` parses the `openrepo` action and extracts an attacker-controlled `url`, `branch`, `pr`, and `filepath` directly from the link with only superficial validation (regex checks on `pr` and `branch`, and `isAbsolute`/`resolveWithin` checks on `filepath`). This is analogous to the C4 report's broken invariant: a "trusted" internal capability (opening/fetching/checking out a repository, or writing into a path derived from user-controlled input) is invoked using attacker-supplied parameters rather than data the user directly reviewed and approved, similar to how `BribeVault` let a privileged role redirect funds using attacker-chosen `briber`/`amount` parameters.

### Finding Description
`parseAppURL` accepts a `url` field for the `openrepo` action taken verbatim from the clicked link [1](#0-0) . This flows into `Dispatcher.openRepositoryFromUrl`, which will either match an existing local repo by URL or otherwise clone/open the remote, fetch it, and check out a branch or PR head with no additional confirmation step beyond what `openOrCloneRepository` does [2](#0-1) . For the `pr` case, it fetches PR data from the API and checks out `pullRequest.head.repo.clone_url` — a remote URL that is entirely attacker-controlled content coming from the PR object itself (an "attacker controls a GitHub API object" scenario) [3](#0-2) . The `filepath` parameter is passed through `resolveWithin(repository.path, filepath)` before calling `shell.showItemInFolder` [4](#0-3) ; I was not able to verify the internals of `resolveWithin` (in `app/src/lib/path.ts`) in this session due to a tool failure, so I cannot confirm whether it correctly canonicalizes symlinks/`..`/absolute-after-join sequences before comparison — this is the key unverified guard.

### Impact Explanation
If `resolveWithin` has any traversal bypass (e.g., not resolving symlinks created by the cloned/checked-out repository content before the containment check, or mishandling drive-relative paths on Windows), a link-triggered deep link combined with a malicious repository/PR could cause Desktop to open/reveal a file path outside the intended repository directory, which matches the accepted impact category "file write or read outside the repo" triggered via "a link or deep link the user clicks" plus "a GitHub API object" (the PR's `head.repo.clone_url` and checked-out contents). Even absent a `resolveWithin` bypass, the ability to silently drive Desktop to fetch and check out attacker-chosen remotes/branches/PR heads via an unauthenticated OS-level URI scheme is a meaningful trust boundary weakening, since the only gating is regex validation of `branch`/`pr` format, not verification that the destination matches any account the user trusts.

### Likelihood Explanation
Medium — requires the user to click a link (a natural, low-friction action, consistent with allowed "link or deep link the user clicks" vector), and does not require local/physical access, admin rights, or pre-existing malware. However, actual file-system escape depends on the unverified behavior of `resolveWithin`, which I could not confirm in this session.

### Recommendation
Verify `resolveWithin` in `app/src/lib/path.ts` fully canonicalizes (realpath) both the base repository path and the joined target path — including symlink resolution — before performing the containment check, and add regression tests using symlinked directories/files inside a fixture repo. Additionally, consider surfacing a confirmation dialog showing the exact clone/fetch URL and destination before acting on `openrepo` deep-link actions, rather than silently proceeding through `openOrCloneRepository`.

### Proof of Concept
Conceptual PoC (not fully verified against `resolveWithin` internals):
1. Attacker crafts `x-github-client://openrepo/https://github.com/attacker/repo?branch=pr/1&pr=1&filepath=<crafted-path>` and gets the victim to click it (e.g., embedded in a webpage or email).
2. Desktop's OS-level protocol handler invokes `handleAppURL` → `parseAppURL`, producing an `open-repository-from-url` action with attacker-supplied `url`/`pr`/`filepath` [1](#0-0) .
3. `Dispatcher.openRepositoryFromUrl` calls `openPullRequestFromUrl`, which fetches the PR from the API and may clone/checkout `pullRequest.head.repo.clone_url` (attacker-controlled) [3](#0-2) , then resolves `filepath` against the repository root and calls `shell.showItemInFolder` [4](#0-3) .
4. If a crafted `filepath` (potentially combined with a symlink checked into the attacker's repository) can defeat the `resolveWithin` containment check, this reveals/operates on a path outside the repository — needs confirmation against the actual `resolveWithin`/`path.ts` implementation, which could not be retrieved in this session.

  private async openRepositoryFromUrl(action: IOpenRepositoryFromURLAction) {
    const { url, pr, branch, filepath } = action

    let repository: Repository | null

    if (pr !== null) {
      repository = await this.openPullRequestFromUrl(url, pr)
    } else if (branch !== null) {
      repository = await this.openBranchNameFromUrl(url, branch)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      return
    }

    if (filepath !== null) {
      if (isAbsolute(filepath)) {
        log.error(`Refusing to open absolute path: ${filepath}`)
        return
      }

      const resolved = await resolveWithin(repository.path, filepath)

      if (resolved !== null) {
        shell.showItemInFolder(resolved)
      } else {
        log.error(
          `Prevented attempt to open path outside of the repository root: ${filepath}`
        )
      }
    }
  }

  private async openBranchNameFromUrl(
    url: string,
    branchName: string
  ): Promise<Repository | null> {
    const repository = await this.openOrCloneRepository(url)

    if (repository === null) {
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    // if the repo has a remote, fetch before switching branches to ensure
    // the checkout will be successful. This operation could be a no-op.
    await this.appStore._fetch(repository, FetchType.UserInitiatedTask)

    await this.checkoutLocalBranch(repository, branchName)

    return repository
  }

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }
    if (!isRepositoryWithGitHubRepository(repository)) {
      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    if (pullRequest.head.repo === null) {
      return null
    }

    await this.appStore._checkoutPullRequest(
      repository,
      pullRequest.number,
      pullRequest.head.repo.owner.login,
      pullRequest.head.repo.clone_url,
      pullRequest.head.ref
    )

    return repository
