## Analysis

The external report's broken invariant: a cross-context destination identifier (`msg.sender` on the source chain, hard-coded as the receiver on the destination chain) is trusted without letting the actual controller of the destination context confirm or specify it, so an attacker who can influence which context the funds/action land in can hijack the outcome.

The closest verifiable analog in this codebase is in `app/src/ui/dispatcher/dispatcher.ts`, where a `x-github-client://openRepo/...?pr=<n>` deep link (fully attacker-craftable and clickable by the victim) drives `openPullRequestFromUrl` → `getRepositoryFromPullRequest` → `_checkoutPullRequest`. The "destination" here is an *existing local repository* selected purely by comparing GitHub API-supplied clone/html URLs against the user's already-open repositories (`doesRepositoryMatchUrl`/`urlsMatch`), with no confirmation step, before fetching and checking out an attacker-controlled fork branch into it.

### Title
Unconfirmed PR checkout via `x-github-client://openRepo` deep link silently switches an existing repository to attacker-controlled fork branch - (File: app/src/ui/dispatcher/dispatcher.ts)

### Summary
The `open-repository-from-url` URL action, when it carries a `pr` query parameter, resolves the destination repository purely by matching the PR's `head`/`base` clone URLs against repositories the user already has open, then silently adds the PR author's fork as a remote and checks out its branch into that repository — with no user prompt confirming the destination or warning that a fork's code is about to overwrite the working tree.

### Finding Description
`parseAppURL` (`app/src/lib/parse-app-url.ts:66-125`) accepts `openrepo` deep links with `pr`, `branch`, and `filepath` query parameters, validated only for format (`^\d+$` for `pr`, `^pr\/\d+$` for `branch`), not for whether the PR/branch actually corresponds to a repo the user trusts. [1](#0-0) 

`dispatchURLAction` routes this to `openRepositoryFromUrl` → `openPullRequestFromUrl`, which fetches the PR object from the GitHub API (`this.appStore.fetchPullRequest(url, pr)`) — data an attacker fully controls simply by opening a PR (even from a throwaway fork) against any public repository. [2](#0-1) 

The destination repository is then chosen by `getRepositoryFromPullRequest`, which loops over the user's *already-opened* local repositories and matches by comparing the PR's `head.repo.clone_url` (attacker's fork) or `base.repo.clone_url` against each repository's `htmlURL`/parent `htmlURL` via `urlsMatch` (hostname+owner+name string comparison only, no ownership or ACL check): [3](#0-2) 

Once a match is found, Desktop proceeds directly to `_checkoutPullRequest`, which adds the fork as a remote (`addRemote`) and checks out `pr/<number>` — no dialog, no diff preview, no explicit user confirmation of "you are about to fetch and check out code from `<attacker/fork>` into `<your repo>`": [4](#0-3) [5](#0-4) 

This mirrors the external report's broken invariant: the "destination" (here, the local working repository into which foreign code lands) is selected via a hard-coded matching rule tied to a value the attacker also controls (the PR's repo URLs), rather than being explicitly confirmed by the party who actually owns/controls that destination (the user, at the keyboard, looking at their own repo list).

### Impact Explanation
If the victim has a repository open in Desktop whose origin/upstream matches a public repo the attacker can open PRs against, clicking the crafted link causes Desktop to fetch the attacker's fork as a remote and check out the attacker's branch into that existing repository's working directory — replacing the user's current working tree contents without an explicit "are you sure" step tied to the specific fork/branch being introduced. If the user then continues working (stages/commits/pushes) without carefully noticing the branch/remote change, they can unknowingly commit or push attacker-authored code, satisfying the "silent corruption of what the user commits or pushes" impact category. This does not steal funds/credentials directly, but it is a genuine analog of the underlying flaw class: an externally-influenceable value (PR clone URL) drives an action (checkout target) that the local system trusts as if it reflected the user's actual intent/destination.

### Likelihood Explanation
Medium. It requires: (1) the victim to already have the targeted repository open in Desktop, (2) the victim to click a maliciously crafted `x-github-client://openRepo/...?pr=<n>` link (a normal, low-friction user action — e.g., embedded in a webpage, README, or the "Open in Desktop" button GitHub itself surfaces for PRs), and (3) the attacker to have an open PR (trivial for public repos) against the repo. No admin rights, local access, or leaked credentials are needed — only the two named attacker primitives (a link the user clicks, and a GitHub API object the attacker controls).

### Recommendation
Before checking out a PR reached via a deep link, show an explicit confirmation dialog identifying the target repository, the PR author/fork, and the branch that will be fetched and checked out, requiring the user to confirm before `_checkoutPullRequest` runs — rather than silently matching to an already-open repository and proceeding.

### Proof of Concept
1. Attacker forks a public repository the victim has cloned and opened in Desktop, adds a distinctive change, and opens a PR (e.g., PR #42) against the upstream repo.
2. Attacker sends the victim a link: `x-github-client://openRepo/https://github.com/victim-org/target-repo?pr=42&branch=pr%2F42`.
3. Victim clicks the link. `parseAppURL` accepts it (`pr` matches `^\d+$`, `branch` matches `^pr\/\d+$`).
4. `openPullRequestFromUrl` fetches PR #42 from the API, `getRepositoryFromPullRequest` matches it to the victim's already-open `target-repo` via `urlsMatch` on `base.repo.clone_url`.
5. `_checkoutPullRequest` adds the attacker's fork as a remote and checks out `pr/42` into the victim's existing local `target-repo` working directory — with no confirmation dialog shown to the victim beforehand. [6](#0-5)

```typescript
  private getRepositoryFromPullRequest(
    pullRequest: IAPIPullRequest
  ): RepositoryWithGitHubRepository | null {
    const state = this.appStore.getState()
    const repositories = state.repositories
    const headUrl = pullRequest.head.repo?.clone_url
    const baseUrl = pullRequest.base.repo?.clone_url

    // This likely means that the base repository has been deleted
    // and we don't support checking out from refs/pulls/NNN/head
    // yet so we'll bail for now.
    if (headUrl === undefined || baseUrl === undefined) {
      return null
    }

    for (const repository of repositories) {
      if (this.doesRepositoryMatchUrl(repository, headUrl)) {
        return repository
      }
    }

    for (const repository of repositories) {
      if (this.doesRepositoryMatchUrl(repository, baseUrl)) {
        return repository
      }
    }

    return null
  }

  private doesRepositoryMatchUrl(
    repo: Repository | CloningRepository,
    url: string
  ): repo is RepositoryWithGitHubRepository {
    if (repo instanceof Repository && isRepositoryWithGitHubRepository(repo)) {
      const originRepoUrl = repo.gitHubRepository.htmlURL
      const upstreamRepoUrl = repo.gitHubRepository.parent?.htmlURL ?? null

      if (originRepoUrl !== null && urlsMatch(originRepoUrl, url)) {
        return true
      }

      if (upstreamRepoUrl !== null && urlsMatch(upstreamRepoUrl, url)) {
        return true
      }
    }

    return false
  }
```

```typescript
  public async _findPullRequestBranch(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,
    headRefName: string
  ): Promise<Branch | undefined> {
    const gitStore = this.gitStoreCache.get(repository)
    const remotes = await getRemotes(repository)

    // Find an existing remote (regardless if set up by us or outside of
    // Desktop).
    let remote = remotes.find(r => urlMatchesRemote(headCloneUrl, r))

    // If we can't find one we'll create a Desktop fork remote.
    if (remote === undefined) {
      try {
        const forkRemoteName = forkPullRequestRemoteName(headRepoOwner)
        remote = await addRemote(repository, forkRemoteName, headCloneUrl)
      } catch (e) {
        this.emitError(
          new Error(
            `Couldn't find PR branch, adding remote failed: ${e.message}`
          )
        )
        return
      }
    }

    const remoteRef = `${remote.name}/${headRefName}`

    // Start by trying to find a local branch that is tracking the remote ref.
    let existingBranch = gitStore.allBranches.find(
      x => x.type === BranchType.Local && x.upstream === remoteRef
    )

    // If we found one, let's check it out and get out of here, quick
    if (existingBranch !== undefined) {
      return existingBranch
    }

    const findRemoteBranch = (name: string) =>
      gitStore.allBranches.find(
        x => x.type === BranchType.Remote && x.name === name
      )

    // No such luck, let's see if we can at least find the remote branch then
    existingBranch = findRemoteBranch(remoteRef)

    // It's quite possible that the PR was created after our last fetch of the
    // remote so let's fetch it and then try again.
    if (existingBranch === undefined) {
      try {
        await this._fetchRemote(repository, remote, FetchType.UserInitiatedTask)
        existingBranch = findRemoteBranch(remoteRef)
      } catch (e) {
        log.error(`Failed fetching remote ${remote?.name}`, e)
      }
    }

    if (existingBranch === undefined) {
      this.emitError(
        new Error(
          `Couldn't find branch '${headRefName}' in remote '${remote.name}'. ` +
            `A common reason for this is that the PR author has deleted their ` +
            `branch or their forked repository.`
        )
      )
      return
    }

    // For fork remotes we checkout the ref as pr/[123] instead of using the
    // head ref name since many PRs from forks are created from their default
    // branch so we'll have a very high likelihood of a conflicting local branch
    const isForkRemote =
      remote.name !== gitStore.defaultRemote?.name &&
      remote.name !== gitStore.upstreamRemote?.name

    if (isForkRemote) {
      return await this._createBranch(
        repository,
        `pr/${prNumber}`,
        remoteRef,
        false
      )
    }

    return existingBranch
  }
```
