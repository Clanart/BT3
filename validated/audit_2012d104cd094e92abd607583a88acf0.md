## Analysis

The Move bug's broken invariant is: **two components (`bank.move` and `pancake_dex_worker.move`) disagree about how many "types" a shared struct can validly represent, and the code path that trusts attacker-adjacent input (arbitrary generic type parameters) never re-validates that the type matches the state actually stored.** The result is that a value is accepted/classified as belonging to one category (single coin pair) while the underlying storage semantics assume another (map of many), letting attacker-influenced input corrupt an unrelated position/health-check.

Searching the GitHub Desktop codebase for the closest analog of "attacker-controlled input silently reclassifies a security-relevant category without re-validation" leads to `getEndpointKind` in `app/src/lib/trampoline/trampoline-credential-helper.ts`.

### Title
Attacker-Controlled `WWW-Authenticate` Header Spoofs GitHub Host Classification, Triggering Credential Sign-In Flow Against Untrusted Endpoint - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
`getEndpointKind()` classifies a Git remote host as `'github.com'`, `'ghe.com'`, `'enterprise'`, or `'generic'` before deciding whether to invoke GitHub's internal credential/sign-in machinery. One of its checks trusts a `wwwauth[...]` credential field — which is populated directly from the `WWW-Authenticate` HTTP header returned by the remote server during a Git HTTP auth challenge — and classifies the host as `'enterprise'` purely because the header string contains `realm="GitHub"`, with no verification that the host is actually a GitHub Enterprise instance.

### Finding Description [1](#0-0) 

The relevant logic:
```
for (const [k, v] of cred.entries()) {
  if (k.startsWith('wwwauth[')) {
    if (v.includes('realm="GitHub"')) {
      return 'enterprise'
    } ...
  }
}
```

`cred` is the credential-helper input, populated by Git itself from the server's HTTP response headers when a remote requires authentication. This value is **entirely attacker-controlled**: any Git server (including a malicious remote the user clones/fetches, or an MITM/malicious proxy) can respond to the auth challenge with `WWW-Authenticate: Basic realm="GitHub"` regardless of the actual hostname. This is exactly analogous to the Move bug: `bank.move` inferred a coin's "identity/category" from caller-supplied generics without checking it against the actual stored type; here Desktop infers a remote's "GitHub-ness" from a caller/server-supplied string without checking it against the actual, verified hostname (`isDotCom`/`isGHE` checks already exist right above and are bypassed by this fallback).

This misclassification feeds into `getCredential()`: [2](#0-1) 
```

...
if (endpointKind !== 'generic' && !accounts.some(a => a.endpoint === apiEndpoint)) {
  ...
  const account = await ui.promptForGitHubSignIn(endpoint)
  ...
}
```

Because the endpoint is misclassified as `'enterprise'` and no account exists yet for the attacker's arbitrary host, Desktop shows a **GitHub sign-in dialog** and calls `promptForGitHubSignIn(endpoint)`: [3](#0-2) 
```
const { hostname, origin } = new URL(endpoint)
if (hostname === 'github.com') {
  this.dispatcher.beginDotComSignIn(cb)
} else {
  this.dispatcher.beginEnterpriseSignIn(cb)
  await this.dispatcher.setSignInEndpoint(origin)
}
```

Since `hostname !== 'github.com'`, this unconditionally starts the **Enterprise sign-in flow bound to the attacker's `origin`**. The user is presented with what looks like a normal "Desktop needs to authenticate to this repository" prompt, but the underlying sign-in endpoint is the attacker's server — not a validated GitHub Enterprise instance (no `x-github-request-id` / `/meta` check like `isGitHubHost()` performs elsewhere is applied here).

### Impact Explanation
If the user completes the Enterprise sign-in flow (e.g., supplies a Personal Access Token, or completes OAuth against what they believe is their company's GHE server), that credential material is bound to/sent toward the attacker-controlled `origin`, resulting in credential/token exfiltration and an account record (`Account`) associated with a host the attacker fully controls — matching "unauthorized OAuth or account binding" and "credential/token exfiltration" from the impact criteria. Unlike `isGitHubHost()` (used elsewhere in `app/src/lib/api.ts:2435-2491`), which performs an actual network probe (`/meta` + `x-github-request-id` check) before trusting a host as GitHub, `getEndpointKind`'s `wwwauth[` branch performs **no such verification** — it trusts a single attacker-suppliable string.

### Likelihood Explanation
The attacker only needs to control (or MITM/proxy) a Git HTTP remote that the victim clones, fetches, or pulls from — squarely within the "attacker controls...a git remote/proxy response" valid-impact category. No local access, malware, or leaked credentials are required; the victim's own normal Git workflow (adding/cloning a malicious HTTPS remote requiring auth) triggers Git to invoke Desktop's credential helper trampoline with the forged header, and Desktop autonomously decides to show a GitHub-branded sign-in prompt.

### Recommendation
Do not classify a host as `'enterprise'`/GitHub based solely on the `WWW-Authenticate` realm string. Either remove this heuristic entirely, or use it only as a low-confidence *hint* that still requires the existing network-based verification (`isGitHubHost()`) before trusting the endpoint and before invoking `promptForGitHubSignIn`. At minimum, surface the actual hostname prominently in the sign-in dialog and require it to pass the same `/meta` + `x-github-request-id` verification used in `isGitHubHost`.

### Proof of Concept
1. Attacker sets up an HTTPS Git server at `https://evil.example.com/foo.git` that responds to unauthenticated Git HTTP requests with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
2. Victim adds this as a remote in Desktop (or clones it) and performs a fetch/pull requiring auth.
3. Git invokes the Desktop credential-helper trampoline (`GIT_CONFIG_PARAMETERS` → `credential.helper=desktop`, set in `withTrampolineEnv`, `app/src/lib/trampoline/trampoline-environment.ts:143`), passing the `wwwauth[]` header value from step 1.
4. `getEndpointKind()` returns `'enterprise'` for `evil.example.com` due to the `realm="GitHub"` match.
5. `getCredential()` finds no existing account for `evil.example.com` and calls `ui.promptForGitHubSignIn('https://evil.example.com')`.
6. Desktop displays a GitHub-style sign-in dialog with `beginEnterpriseSignIn` bound to `origin = https://evil.example.com`; if the victim completes sign-in, their credentials are sent to the attacker's host.

Note: I could not fully trace the downstream Enterprise sign-in store logic (`beginEnterpriseSignIn`/`setSignInEndpoint`) to confirm whether it performs any additional endpoint validation before proceeding with OAuth/PAT submission; that would need to be checked in a full Devin session against `app/src/lib/stores/sign-in-store.ts` to confirm the complete exploit chain end-to-end.

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
