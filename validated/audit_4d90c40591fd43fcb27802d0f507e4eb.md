### Title
Broken forfeit mechanism in `mWOMSVBaseRewarder` lets early unlockers keep 100% of rewards, permanently freezing/misappropriating yield owed to remaining stakers - (File: `rewards/mWOMSVBaseRewarder.sol`)

### Summary
`mWOMSVBaseRewarder._calExpireForfeit` is a no-op: it never queries the actual "rewardable percent" of the account from the locker contract, so it always returns a forfeit amount of `0`, regardless of whether the caller is unlocking `mWomSV` early. The sibling implementation, `vlMGPBaseRewarder`, correctly computes the forfeit by calling `vlMGP.getRewardablePercentWAD(_account)` [1](#0-0)  — but `mWOMSVBaseRewarder` instead sets `rewardableAmount = _amount` and checks `rewardableAmount > _amount`, a condition that can never be true, guaranteeing `forfeitAmount = _amount - rewardableAmount = 0` for every account and every call [2](#0-1) .

### Finding Description
`mWomSV` (the mWOM staked/locked position) implements the same lock/cooldown/forfeit design as `VLMGP`, exposing `getRewardablePercentWAD(_user)` to compute what fraction of accrued rewards a user is entitled to based on how much of their position is still locked versus mid-cooldown [3](#0-2) . `vlMGPBaseRewarder` correctly uses this function to calculate the forfeited portion when a user claims rewards for VLMGP: `uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account); uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;` [4](#0-3) .

`mWOMSVBaseRewarder._calExpireForfeit`, which should perform the analogous calculation for `mWomSV` holders, never calls `mWOMSV.getRewardablePercentWAD(...)` at all. Instead it sets `rewardableAmount = _amount`, making `forfeitAmount = _amount - rewardableAmount` always equal `0` [2](#0-1) . This function is invoked from `_sendReward`, which is reachable by any unprivileged holder claiming rewards through `getReward`/`getRewards` (called via `MasterMagpie`), so the missing validation is on the direct, unprivileged reward-claim path [5](#0-4) .

The forfeited amount that should be withheld is meant to be redistributed to the remaining pool via `_queueNewRewardsWithoutTransfer`, which increases `rewardPerTokenStored` for all other stakers [6](#0-5) . Because forfeiture never triggers, that redistribution never happens: any user who withdraws or unlocks `mWomSV` early keeps their full share of rewards, permanently denying the loyal/remaining stakers the forfeited yield they are entitled to under the protocol's design.

### Impact Explanation
This causes a permanent, protocol-level loss of yield redistribution for `mWomSV` stakers who remain locked: value that the reward-accounting design intends to be clawed back from early-unlocking users and redistributed to remaining stakers is instead retained by the leaving user in full, every time, with no way to ever recover or redistribute it after the reward is transferred out (`userRewards[...] = 0` at line 367). This is a concrete, permanent misallocation/freezing of yield due to a completely broken validation check, directly analogous to the reported bug class (an assertion/validation that is trivially neutralized, here effectively hard-coded to a no-op).

### Likelihood Explanation
High likelihood: the flawed code path executes on every single `getReward`/`getRewards` call for `mWomSV` stakers, with no special preconditions, permissions, or edge cases required — any ordinary wallet holding `mWomSV` and unlocking early (or even without unlocking, since the check is unconditionally bypassed for all reward claims) benefits, and any co-staker relying on forfeited-reward redistribution is impacted every time this executes.

### Recommendation
Fix `_calExpireForfeit` in `rewards/mWOMSVBaseRewarder.sol` to mirror `vlMGPBaseRewarder`'s logic, calling `mWOMSV.getRewardablePercentWAD(_account)` and computing `rewardableAmount = _amount * rewardablePercentWAD / 1e18` before deriving `forfeitAmount`, so that early-unlock forfeits are actually applied and redistributed via `_queueNewRewardsWithoutTransfer`.

### Proof of Concept
1. User A locks `mWom` into `mWomSV`.
2. Rewards accrue in `mWOMSVBaseRewarder` for the pool.
3. User A calls `startUnlock`/`unlock` on `mWomSV` before their lock naturally matures (early exit), then claims rewards via `MasterMagpie` → `mWOMSVBaseRewarder.getReward`.
4. `_sendReward` calls `_calExpireForfeit(_account, userRewards[...])`, which returns `0` regardless of the early-unlock status (per lines 385-398).
5. User A receives 100% of `userRewards[...]` with no forfeit, whereas the intended design (as implemented for VLMGP) would have forfeited a portion back to remaining stakers via `_queueNewRewardsWithoutTransfer`.
6. Repeating this for every early-exiting user permanently denies remaining `mWomSV` stakers the forfeited-yield redistribution they are entitled to.

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalmWomSV = fullyInLock + inCoolDown;
        if (userTotalmWomSV == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalmWomSV;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalmWomSV / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalmWomSV;
                }

            }
        }

        return percent;
    }
