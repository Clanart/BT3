## Finding

### Title
`CW721ERC721Pointer.transferFrom()` lacks a receiver-safety check, permanently freezing bridged CW721 NFTs sent to non-ERC721-aware contracts - (File: `contracts/src/CW721ERC721Pointer.sol`)

### Summary
The `CW721ERC721Pointer` contract, which exposes a CosmWasm CW721 NFT collection as an ERC721 token on the EVM side, implements `transferFrom()` by directly calling the CW721 contract's `transfer_nft` execute message via the wasmd precompile, with no check that the recipient can handle an ERC721 asset. This is the exact bug class described in the external report: use of unchecked `transferFrom` instead of a safe-transfer pattern with `onERC721Received` verification.

### Finding Description
`transferFrom` in the pointer is overridden to bypass the OpenZeppelin `ERC721` internal state entirely and instead push a `transfer_nft` CosmWasm message to the underlying CW721 contract: [1](#0-0) 

Unlike the inherited/standard `safeTransferFrom`, this override performs no `to.code.length` / `IERC721Receiver.onERC721Received` check before moving ownership. Because `transferFrom` is completely overridden and never calls the base contract's internal `_update`/`_mint` logic, the base `ERC721` storage (`_ownerOf`, etc.) is never populated for these tokens — meaning the inherited `safeTransferFrom` (which the contract does not override) operates against a base-storage `_ownerOf` mapping that never reflects the token's real owner (the true state lives only in the CosmWasm contract, queried live via `ownerOf()`), so calling the inherited `safeTransferFrom` on a pointer-tracked token id is effectively broken/unusable. As a result, `transferFrom()` is the only realistic movement path for a user holding a pointer-wrapped NFT, and it provides no protection: any EVM contract that receives such an NFT via `transferFrom` and does not implement arbitrary outbound calls (or was never designed to hold or move ERC721/CW721 NFTs) can never move the NFT back out, permanently locking it.

This mirrors the reported Isomorph bug class ("`transferFrom()` … may cause NFT to be frozen in a contract that does not support ERC721") applied to Sei's CW721↔ERC721 pointer bridge, which is reachable by any public EVM RPC client / contract that owns a bridged NFT.

### Impact Explanation
An NFT bridged from CosmWasm to EVM through `CW721ERC721Pointer` can become permanently frozen if `transferFrom` sends it to a contract (e.g., a DeFi vault, marketplace escrow, or any generic smart contract) that has no code path to call `transferFrom`/`approve` back out on the pointer. Since the underlying asset is a CW721 NFT with real (often non-fungible/unique) value, this constitutes permanent freezing of user funds/assets, satisfying the "permanent freezing" impact bar.

### Likelihood Explanation
Likelihood is moderate: it requires a user or integrating contract to send a pointer NFT to a contract lacking `onERC721Received` support, which is a common integration mistake (e.g., older or minimal contracts, misconfigured integrations, or contracts that were never audited for NFT receipt). No malicious actor or privileged role is required — any normal EVM transaction sender interacting with the CW721→ERC721 pointer can trigger this.

### Recommendation
Change `CW721ERC721Pointer.transferFrom` to perform the standard EIP-721 receiver check (i.e., implement/override `safeTransferFrom` to route through the CW721 `transfer_nft` execution path used by `transferFrom`, and add the `to.code.length > 0` + `IERC721Receiver(to).onERC721Received(...)` check), or alternatively have `transferFrom` itself enforce this check consistent with the guidance in EIP-721 for wallets/contracts accepting NFTs. Also ensure `safeTransferFrom` is properly overridden to use the live CW721 ownership state (via `ownerOf`) rather than relying on the disconnected base `ERC721` storage.

### Proof of Concept
1. A CW721 collection is registered via the wasmd precompile/`AddCW721`, creating a `CW721ERC721Pointer` at some EVM address, per [2](#0-1) .
2. A user (`from`) who owns CW721 token `id` calls `pointer.transferFrom(from, contractC, id)` where `contractC` is a plain contract with no `onERC721Received` implementation and no ability to call `approve`/`transferFrom` on the pointer on its own.
3. `transferFrom` executes unconditionally: `require(from == ownerOf(tokenId), ...)` passes, then it fires `transfer_nft` to the CW721 contract via `_execute`, per [1](#0-0) .
4. Ownership of the underlying CW721 token is now `contractC`; since `contractC` has no logic to call back into the pointer, the NFT is permanently stuck — there is no recovery path since the inherited `safeTransferFrom`/base-storage path is disconnected from the real CW721 ownership state maintained via `ownerOf()`, per [3](#0-2) .

```text
    function transferFrom(address from, address to, uint256 tokenId) public override {
        if (to == address(0)) {
            revert ERC721InvalidReceiver(address(0));
        }
        require(from == ownerOf(tokenId), "`from` must be the owner");
        string memory recipient = _formatPayload("recipient", _doubleQuotes(AddrPrecompile.getSeiAddr(to)));
        string memory tId = _formatPayload("token_id", _doubleQuotes(Strings.toString(tokenId)));
        string memory req = _curlyBrace(_formatPayload("transfer_nft", _curlyBrace(_join(recipient, tId, ","))));
        _execute(bytes(req));
    }
```

```go
func (p PrecompileExecutor) AddCW721(ctx sdk.Context, method *ethabi.Method, caller common.Address, args []interface{}, value *big.Int, evm *vm.EVM, hooks *tracing.Hooks) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}
	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}
	cwAddr := args[0].(string)
	cwAddress, err := sdk.AccAddressFromBech32(cwAddr)
	if err != nil {
		return nil, 0, err
	}
	res, err := p.wasmdKeeper.QuerySmartSafe(ctx, cwAddress, []byte("{\"contract_info\":{}}"))
	if err != nil {
		return nil, 0, err
	}
	formattedRes := map[string]interface{}{}
	if err := json.Unmarshal(res, &formattedRes); err != nil {
		return nil, 0, err
	}
	name := formattedRes["name"].(string)
	symbol := formattedRes["symbol"].(string)
	contractAddr, err := p.evmKeeper.UpsertERCCW721Pointer(ctx, evm, cwAddr, utils.ERCMetadata{Name: name, Symbol: symbol})
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(contractAddr)
	remainingGas = pcommon.GetRemainingGas(ctx, p.evmKeeper)
	return
}
```
