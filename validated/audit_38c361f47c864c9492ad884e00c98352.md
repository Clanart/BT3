## Analysis

The TensorFlow report describes a classic **CWE-369 (division by zero)**: an attacker-controlled tensor value (`updates`) is used directly as the divisor in `ResourceScatterDiv` with no zero-check, causing a crash. The failed invariant is "never divide by a value taken directly from untrusted input without validating it is non-zero."

Searching the Protobuf codebase for the same failed invariant — attacker-controlled parsed data flowing unchecked into a division — surfaces a direct analog in the well-known-types time utility, not in the wire-format parser itself (which has no arithmetic division on field values).

`google::protobuf::util::TimeUtil` provides overloaded arithmetic operators for `Duration` messages, intended for application code to manipulate `Duration`/`Timestamp` values obtained by parsing binary or JSON protobuf input (both are ordinary parseable well-known types, reachable from any public `ParseFromString`/`MergeFrom`/JSON-parse API). Two of these operators divide by a second `Duration` operand: [1](#0-0) [2](#0-1) 

Both `operator/(const Duration&, const Duration&)` and `operator%=(Duration&, const Duration&)` convert both operands to `absl::uint128` via `ToUint128` and then perform `value1 / value2` / `value1 % value2` with **no check that `value2` (derived from the divisor `Duration`) is non-zero**: [3](#0-2) 

If the divisor `Duration` is a message parsed straight from attacker-controlled binary/JSON (e.g., `seconds=0, nanos=0` — the default, zero-initialized `Duration`, which is a perfectly valid wire encoding), `ToUint128` produces `value2 = 0`, and the subsequent integer division/modulo triggers a division-by-zero trap (SIGFPE on x86/ARM), crashing the process — the exact same class of failure as `ResourceScatterDiv`'s unchecked `updates` divisor.

This does not qualify as a full public-API "parse" bug per se (the crash requires application code to call `operator/`/`operator%` on the parsed `Duration`), but it is protobuf's *own* shipped utility code (not user application logic) operating on values immediately obtained from parsing supported well-known types, with no validity/zero check — `IsDurationValid` exists in the same class but is never invoked here.

### Title
Division by zero in `google::protobuf::util::operator/`/`operator%` for `Duration` — (`src/google/protobuf/util/time_util.cc`)

### Summary
`TimeUtil`'s `Duration` division/modulo operators divide by a `Duration` value converted via `ToUint128` without checking it is non-zero. A `Duration` message parsed from attacker-controlled binary or JSON input (e.g. the all-zero default value, `{seconds:0, nanos:0}`) used as the divisor operand causes an integer division-by-zero crash (SIGFPE).

### Finding Description
`operator/(const Duration& d1, const Duration& d2)` and `operator%=(Duration& d1, const Duration& d2)` in [1](#0-0)  and [2](#0-1)  call `ToUint128(d2, &value2, &negative2)` and then compute `value1 / value2` or `value1 % value2` unconditionally. `ToUint128` simply encodes `seconds*1e9 + nanos` [4](#0-3) ; it performs no validation and does not reject a zero-valued `Duration`. Since a `Duration` protobuf message with `seconds=0, nanos=0` is a completely valid, default-initialized message reachable by parsing any attacker-supplied (empty or explicit-zero) binary/JSON payload, the divisor can be attacker-controlled zero with no upstream guard.

### Impact Explanation
Triggers an unhandled machine-level SIGFPE / trap on integer division by zero, crashing the host process. This is a denial-of-service against any application that calls `TimeUtil`'s `Duration / Duration` or `Duration % Duration` operators on a value obtained from parsing untrusted `Duration` messages — a legitimate and documented use case for the well-known types utility.

### Likelihood Explanation
Medium: it requires the consuming application to invoke `operator/(Duration, Duration)` or `operator%` (not automatically triggered merely by `ParseFromString`), but this is a normal, documented usage pattern for `TimeUtil`, and the trigger value (an all-zero `Duration`) is trivially producible by any client (default/empty message).

### Recommendation
Add an explicit zero-check (or `IsDurationValid`-style guard rejecting a zero divisor) inside `ToUint128`-consuming division/modulo paths in `time_util.cc`, returning a defined error/exception instead of performing the raw integer division when the divisor `Duration` equals zero.

### Proof of Concept
```cpp
#include "google/protobuf/duration.pb.h"
#include "google/protobuf/util/time_util.h"

int main() {
  google::protobuf::Duration d1, d2;
  // d2 parsed from attacker-controlled bytes (e.g. empty message = all zero fields)
  d2.ParseFromString("");   // seconds=0, nanos=0 -- valid wire encoding
  d1.set_seconds(10);

  int64_t result = d1 / d2;  // SIGFPE: division by zero
}

void ToUint128(const Duration& value, absl::uint128* result, bool* negative) {
  if (value.seconds() < 0 || value.nanos() < 0) {
    *negative = true;
    *result = static_cast<uint64_t>(-value.seconds());
    *result = *result * kNanosPerSecond + static_cast<uint32_t>(-value.nanos());
  } else {
    *negative = false;
    *result = static_cast<uint64_t>(value.seconds());
    *result = *result * kNanosPerSecond + static_cast<uint32_t>(value.nanos());
  }
}

Duration& operator%=(Duration& d1, const Duration& d2) {  // NOLINT
  bool negative1, negative2;
  absl::uint128 value1, value2;
  ToUint128(d1, &value1, &negative1);
  ToUint128(d2, &value2, &negative2);
  absl::uint128 result = value1 % value2;
  // When negative values are involved in division, we round the division
  // result towards zero. With this semantics, sign of the remainder is the
  // same as the dividend. For example:
  //     -5 / 10    = 0, -5 % 10    = -5
  //     -5 / (-10) = 0, -5 % (-10) = -5
  //      5 / (-10) = 0,  5 % (-10) = 5
  ToDuration(result, negative1, &d1);
  return d1;
}
