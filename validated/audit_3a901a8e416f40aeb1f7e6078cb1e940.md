### Title
Unbounded transaction decoding in `debug_isGaslessTx` RPC allows single-request resource-exhaustion DoS - (File: kaiax/gasless/impl/api.go)

### Summary
The `GaslessAPI.IsGaslessTx` handler, exposed as the `debug_isGaslessTx` JSON-RPC method, accepts an arbitrary-length list of raw hex-encoded transactions from an untrusted caller and unconditionally RLP-decodes every element in the list *before* checking whether the number of supplied transactions is within the module's supported bound (1 or 2). This mirrors the CVE-2026-57819 bug class: an externally-controlled collection (form parameters in CXF; `rawTxs` items here) is fully parsed with no default upper bound, so the cost of processing scales with attacker-supplied input size rather than being capped up front.

### Finding Description
`IsGaslessTx` iterates over the full `rawTxs []hexutil.Bytes` slice supplied by the caller and calls `rlp.DecodeBytes` on every item, appending to a `txs` slice, with no cap on `len(rawTxs)`: [1](#0-0) 

Only *after* this unconditional decode loop does the function check the total count of decoded transactions and reject anything other than 1 or 2: [2](#0-1) 

Because the length check happens after the decode work, a caller can submit a single JSON-RPC request containing thousands of `rawTxs` entries (each individually valid or invalid RLP), forcing the node to perform unbounded RLP decoding work per request before any rejection occurs. There is no `maxRawTxsCount`-style guard analogous to the `MaxTxDataSize` cap enforced in the transaction pool (`blockchain/tx_pool.go`) or the `MaxNumKeysForMultiSig` bound enforced for multisig key counts (`blockchain/types/accountkey/account_key_weighted_multi_sig.go`), both of which demonstrate that Kaia normally enforces default limits on attacker-controlled collection sizes before expensive processing — this API path is the exception.

This is directly analogous to the reported Apache CXF issue: "no default restriction on the amount of form parameters per message" — here, no default restriction exists on the amount of raw-transaction items per `debug_isGaslessTx` call.

### Impact Explanation
An unprivileged public-RPC caller can send a single request with an oversized `rawTxs` array to force the node to perform unbounded RLP-decoding work (allocation and parsing) synchronously within the RPC handler goroutine, consuming CPU and memory disproportionate to the request size limits otherwise enforced elsewhere (e.g., `MaxTxDataSize`, `RPCBatchRequestLimit`). Repeated or concurrent such calls can degrade node responsiveness, potentially affecting availability of the RPC service (a Medium/High-severity resource-exhaustion DoS), though it does not by itself cause fund loss, consensus divergence, or invalid block acceptance.

### Likelihood Explanation
The method is reachable by any caller with access to the JSON-RPC endpoint exposing the gasless module's API (documented publicly with a `curl` example in the module's README), requires no special privileges, and the vulnerable code path (decode-before-limit-check) is unconditionally executed on every call. This makes exploitation straightforward for any external caller who can reach the RPC endpoint.

### Recommendation
Enforce a maximum `len(rawTxs)` bound (e.g., reject requests with more than 2 items, matching the module's only supported cases) **before** entering the decode loop in `IsGaslessTx`, mirroring the pattern already used elsewhere in the codebase (`MaxTxDataSize` check in `blockchain/tx_pool.go`, `MaxNumKeysForMultiSig` check in `accountkey`). This ensures decode cost is bounded regardless of attacker-supplied array size.

### Proof of Concept
1. Construct a JSON-RPC request to `debug_isGaslessTx` with a `rawTxs` array containing, e.g., 100,000 hex-encoded byte strings (valid or garbage RLP of moderate size each).
2. Submit the request to a node's RPC endpoint.
3. Observe that the node performs `rlp.DecodeBytes` for every one of the 100,000 entries in the loop at [3](#0-2)  before the `len(txs)` bound check at line 125 rejects the request — demonstrating unbounded per-request decode cost with no default limit on item count.

func (s *GaslessAPI) IsGaslessTx(ctx context.Context, rawTxs []hexutil.Bytes) *GaslessTxResponse {
	if len(rawTxs) == 0 {
		return ToResponse(errors.New("no transactions provided"))
	}

	// Decode the raw transactions
	txs := make([]*types.Transaction, 0, len(rawTxs))
	for i, rawTx := range rawTxs {
		if len(rawTx) == 0 {
			return ToResponse(fmt.Errorf("empty transaction at index %d", i))
		}

		// Handle Ethereum transaction envelope
		if 0 < rawTx[0] && rawTx[0] < 0x7f {
			rawTx = append([]byte{byte(types.EthereumTxTypeEnvelope)}, rawTx...)
		}

		tx := new(types.Transaction)
		if err := rlp.DecodeBytes(rawTx, tx); err != nil {
			return ToResponse(fmt.Errorf("failed to decode transaction at index %d: %v", i, err))
		}

		txs = append(txs, tx)
	}
