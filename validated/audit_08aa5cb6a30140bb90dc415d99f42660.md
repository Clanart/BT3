### Title
Unauthenticated tx-sender JSON-RPC `send_tx` allows any network-reachable caller to cancel bridge transactions and drain the fee wallet — (`File: crates/clementine-tx-sender/src/jsonrpc/server.rs`)

### Summary

The tx-sender JSON-RPC server exposes a `send_tx` method with no authentication layer. Any caller who can reach the bound socket can queue arbitrary transactions for broadcast and, critically, supply `cancel_txids` / `cancel_outpoints` that mark existing bridge transactions (challenge, payout, reimbursement) as cancelled in the database once the attacker's own transaction confirms. This is the direct Clementine analog of the `VestedZeroNFT.split()` missing-ownership check: both allow an unprivileged caller to act on an object they do not own and corrupt its state.

### Finding Description

`start_jsonrpc_server` in `crates/clementine-tx-sender/src/jsonrpc/server.rs` builds a plain `jsonrpsee` HTTP server with no TLS, no API key, and no IP-allowlist enforcement in the code:

The `cancel_txids` parameter is documented as "Txids that should be marked invalid if this tx confirms." An attacker submits a cheap self-transfer (spending their own UTXOs) with `cancel_txids = [challenge_tx_id]`. Once that self-transfer confirms on Bitcoin, the tx-sender marks the challenge transaction as cancelled in its database and stops retrying it. [2](#0-1) 

The gRPC layer (verifier/operator) is correctly protected by the `OnlyAggregatorAndSelf` mTLS interceptor, but the tx-sender JSON-RPC is a completely separate HTTP server with no equivalent guard: [3](#0-2) 

The `run.sh` helper script confirms the JSON-RPC is intended to be reachable over the network (it calls `curl` against a configurable URL with no credentials): [4](#0-3) 

### Impact Explanation

**Liveness / safety break (bridge fund theft):** A watchtower or verifier queues a `Challenge` transaction to contest a malicious operator kickoff. The attacker submits a cheap self-transfer to the unauthenticated JSON-RPC with `cancel_txids = [challenge_txid]`. Once the self-transfer confirms, the tx-sender marks the challenge as cancelled and stops broadcasting it. The challenge timeout expires, the operator's fraudulent kickoff goes unchallenged, and the operator claims the bridged BTC.

**Fee-wallet drain:** The attacker submits many transactions with `fee_paying_type = CPFP`. The tx-sender creates child transactions spending its own wallet UTXOs to fee-bump them, draining the operator's fee reserve and halting all future bridge transaction broadcasts.

Both outcomes satisfy the allowed-impact gate: the first is an unauthorized state transition in the challenge flow that breaks bridge safety with material fund impact; the second is direct theft of operator-controlled balances managed by the tx-sender.

### Likelihood Explanation

The tx-sender JSON-RPC is a separate process that the operator binary connects to. In any containerised or multi-host deployment where the JSON-RPC port is not strictly firewalled to `127.0.0.1`, any network peer can reach it. The `run.sh` script and the `JsonRpcTxSenderClient` both accept arbitrary URLs, providing no localhost-only enforcement at the code level. The attack cost is a single Bitcoin transaction fee. [5](#0-4) 

### Recommendation

1. **Add authentication to the JSON-RPC server.** At minimum, require a shared secret (bearer token or HMAC) on every request, or bind exclusively to a Unix-domain socket and enforce filesystem permissions.
2. **Restrict `cancel_txids` / `cancel_outpoints` to internally-generated calls only.** The JSON-RPC surface exposed to external callers should not accept cancellation parameters; those should only be set by the operator/verifier process that owns the tx-sender.
3. **Bind to `127.0.0.1` by default** and document that any other binding requires explicit operator acknowledgement.

pub async fn start_jsonrpc_server(
    tx_sender_client: TxSenderClient,
    bind_addr: SocketAddr,
) -> Result<TxSenderJsonRpcServer, BridgeError> {
    let server: Server = ServerBuilder::default()
        .max_request_body_size(MAX_JSONRPC_REQUEST_BODY_SIZE)
        .build(bind_addr)
        .await
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    let local_addr = server
        .local_addr()
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    let mut module = RpcModule::new(tx_sender_client.clone());
    module
        .register_async_method("send_tx", |params, client, _| async move {
            let req: InsertTryToSendParams = params.one().map_err(jsonrpc_err)?;

            let raw_tx = hex::decode(&req.signed_tx_hex).map_err(jsonrpc_err)?;
            let signed_tx: Transaction = consensus::deserialize(&raw_tx).map_err(jsonrpc_err)?;

            let mut dbtx = client.db.begin_transaction().await.map_err(jsonrpc_err)?;

            let try_to_send_id = client
                .insert_try_to_send(
                    &mut dbtx,
                    req.tx_metadata,
                    &signed_tx,
                    req.fee_paying_type,
                    req.rbf_signing_info,
                    &req.cancel_outpoints,
                    &req.cancel_txids,
                    &req.activate_txids,
                    &req.activate_outpoints,
                )
                .await
                .map_err(jsonrpc_err)?;

            client
                .db
                .commit_transaction(dbtx)
                .await
                .map_err(jsonrpc_err)?;

            Ok::<u32, ErrorObjectOwned>(try_to_send_id)
        })
        .map_err(|e| BridgeError::Eyre(e.into()))?;

impl JsonRpcTxSenderClient {
    pub fn new(url: &str) -> Result<Self, JsonRpcError> {
        let inner = HttpClientBuilder::default().build(url)?;
        Ok(Self { inner })
    }

    #[cfg(feature = "clementine")]
    #[allow(clippy::too_many_arguments)]
    pub async fn insert_try_to_send(
        &self,
        tx_metadata: Option<TxMetadata>,
        signed_tx: &Transaction,
        fee_paying_type: FeePayingType,
        rbf_signing_info: Option<RbfSigningInfo>,
        cancel_outpoints: &[OutPoint],
        cancel_txids: &[Txid],
        activate_txids: &[ActivatedWithTxid],
        activate_outpoints: &[ActivatedWithOutpoint],
    ) -> Result<u32, JsonRpcError> {
        let signed_tx_hex = consensus::encode::serialize_hex(signed_tx);

        let req = InsertTryToSendParams {
            tx_metadata,
            signed_tx_hex,
            fee_paying_type,
            rbf_signing_info,
            cancel_outpoints: cancel_outpoints.to_vec(),
            cancel_txids: cancel_txids.to_vec(),
            activate_txids: activate_txids.to_vec(),
            activate_outpoints: activate_outpoints.to_vec(),
        };

        self.inner
            .request::<u32, _>("send_tx", rpc_params![req])
            .await
    }
