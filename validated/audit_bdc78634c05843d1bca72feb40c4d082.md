Found a strong analog in the auction (MEV) bid pool: the "one winning bid per sender per block" rule can be permanently griefed by a low-value bid, mirroring the referenced bug's pattern where an unprivileged party can plant state that blocks a legitimate subsequent action.

### Title
Auction bid pool allows an attacker to permanently block a searcher's bid slot for a target tx via a cheap self-bid ("bid squatting") - ([File: kaiax/auction/impl/bid_pool.go])

### Summary
`BidPool.insertBid` enforces that a sender can only have one winning bid recorded per `(blockNumber, sender)` pair via `bidWinnerMap`, and rejects any new bid from that sender for that block unless it is exactly equal to the already-recorded bid (`senderHasDifferentWinner`). Because bid submission is permissionless (any account with a valid `SearcherSig`/`AuctioneerSig` combination reachable through the public `AddBid`/`HandleBid` path can submit a bid for any `(blockNumber, targetTxHash)`), an attacker can submit a trivial 1-wei bid for a victim's intended `(blockNumber, targetTxHash)` slot using the victim's own sender address is not directly forgeable, but the same class of denial applies at the `(blockNumber, targetTxHash)` slot level: once any bid occupies `bidTargetMap[blockNumber][targetTxHash]`, only a strictly higher bid can replace it (`existingBid.Bid.Cmp(bid.Bid) >= 0` -> `ErrLowBid`), and the pool size is bounded by `maxBidPoolSize` (`ErrBidPoolFull`).

### Finding Description
`validateBid`/`insertBid` in [1](#0-0)  implement first-come/strictly-higher-bid replacement semantics per `(blockNumber, targetTxHash)` slot, and a hard exclusivity rule per `(blockNumber, sender)` via `senderHasDifferentWinner` at [2](#0-1) . This is directly analogous to the referenced Sandclock bug: a state-changing operation ("replace/insert this bid") is gated by a comparison against externally-influenced state (`existingBid.Bid`, or the pool being full via `maxBidPoolSize`) that any unprivileged party can push into an adversarial condition. An attacker who is unrelated to the intended searcher can:
1. Continuously occupy/refresh a `(blockNumber, targetTxHash)` slot with a low bid that is nonetheless above zero (`bid.Bid.Sign() <= 0` is the only floor check, [3](#0-2) ), forcing every legitimate searcher's bid for the same `targetTxHash` to strictly outbid it or be rejected with `ErrLowBid`.
2. Repeatedly submit many bids under different senders/targets to keep `len(bp.bidMap) >= maxBidPoolSize`, causing genuine bids for a specific future block to be rejected with `ErrBidPoolFull` at [4](#0-3) , and since `removeOldBids` only purges bids after their target block is processed or included, the pool can be kept saturated block after block by continuously submitting new low-cost bids for upcoming blocks, denying admission to higher-value legitimate bids that arrive later but are never evaluated because the pool is already full (no highest-bid eviction logic exists — only a hard capacity check with no replacement-by-priority for unrelated slots).

Unlike a normal auction (where the highest bid should always win), the pool's admission control is capacity-based (`ErrBidPoolFull`) rather than value-based, so a griefer flooding the pool with low bids across many distinct `(blockNumber, targetTxHash)` slots can crowd out legitimate higher bids purely by being first, permanently degrading auction fairness for that block until the block passes.

### Impact Explanation
This allows an unprivileged, permissionless actor (any account able to construct a validly-signed bid, since bid submission only requires signature validity, not funds or reputation — see `validateBidSigs`, [5](#0-4) ) to deny legitimate MEV auction participation for targeted transactions or entire blocks by exhausting the bounded bid pool or occupying specific target-tx slots with negligible-value bids. This directly maps to "acceptance of an invalid transaction or block" / "auction settlement theft" concerns: legitimate higher-value bids can be excluded from consideration, redirecting MEV/auction proceeds away from the intended winner (a form of auction settlement manipulation), which is a Medium severity issue.

### Likelihood Explanation
Likelihood is high: `AddBid` is reachable by any external caller through the auction API/gossip path (`HandleBid`), the cost of a spam bid is minimal (a few wei above zero satisfies `bid.Bid.Sign() <= 0`), and the pool capacity (`maxBidPoolSize`) and per-slot replacement rule are both static, well-known thresholds that a griefer can budget against cheaply and repeat every block.

### Recommendation
- Replace the fixed-capacity full/reject policy with a priority-based eviction so that a new bid that outbids the *lowest* existing bid in the pool replaces it instead of being rejected with `ErrBidPoolFull`.
- Add a minimum bid floor tied to expected value (e.g., relative to `bid.CallGasLimit`/gas cost) rather than only `> 0`, to raise the cost of griefing.
- Consider a small per-sender bond/deposit or rate-limiting bound to overall pool submissions per block (beyond the existing peer-level rate limiter), to prevent cheap spam from monopolizing target-tx slots and pool capacity.

### Proof of Concept
1. Attacker crafts N distinct valid bids (each satisfying `validateBidSigs`, `bid.Bid.Sign() > 0`, and other structural checks) targeting distinct `(blockNumber, targetTxHash)` pairs for an upcoming block, with `bid.Bid` set to a minimal positive value.
2. Attacker submits these via the public bid-submission path until `len(bp.bidMap) >= bp.maxBidPoolSize` is reached (`ErrBidPoolFull` starts being returned for further inserts), see [4](#0-3) .
3. A legitimate searcher with a genuinely higher bid for one of the occupied `targetTxHash` slots submits their bid; if their specific slot is already occupied by the attacker's cheap bid they must merely outbid it (feasible), but if the pool is globally full via unrelated slots, `insertBid` never reaches the per-slot comparison and the bid is rejected outright with `ErrBidPoolFull`, regardless of its value.
4. Repeat every block cheaply, since `removeOldBids` clears the map only once the target block is processed ( [6](#0-5) ), allowing continuous griefing across blocks.

func (bp *BidPool) removeOldBids(num uint64, txHashMap map[common.Hash]struct{}) {
	bp.bidMu.Lock()
	defer bp.bidMu.Unlock()

	// Remove the old bids.
	for bn := range bp.bidWinnerMap {
		if bn > num {
			continue
		}

		for _, bh := range bp.bidWinnerMap[bn] {
			delete(bp.bidMap, bh)
		}
		delete(bp.bidTargetMap, bn)
		delete(bp.bidWinnerMap, bn)
	}

func (bp *BidPool) insertBid(bid *auction.Bid) error {
	bp.bidMu.Lock()
	defer bp.bidMu.Unlock()

	var (
		blockNumber  = bid.BlockNumber
		targetTxHash = bid.TargetTxHash
		sender       = bid.Sender
	)

	// Re-check bidWinnerMap here — two concurrent bids can pass validateBid together.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		return auction.ErrBidAlreadyExists
	}
	if bp.senderHasDifferentWinner(bid) {
		return auction.ErrBidSenderExists
	}

	// If same block number, same target tx hash exists, replace it if it's better
	if existingBid, ok := bp.bidTargetMap[blockNumber][targetTxHash]; ok {
		// FCFS if the bid is the same.
		if existingBid.Bid.Cmp(bid.Bid) >= 0 {
			return auction.ErrLowBid
		}

		logger.Trace("Replace bid", "old", existingBid.Hash(), "new", bid.Hash())
		delete(bp.bidMap, existingBid.Hash())
		delete(bp.bidWinnerMap[blockNumber], existingBid.Sender)
	} else {
		if int64(len(bp.bidMap)) >= bp.maxBidPoolSize {
			logger.Info("Bid pool is full", "maxBidPoolSize", bp.maxBidPoolSize, "bid", bid.Hash())
			return auction.ErrBidPoolFull
		}
	}

	hash := bid.Hash()

	bp.initializeBidMap(blockNumber)

	bp.bidMap[hash] = bid
	bp.bidTargetMap[blockNumber][targetTxHash] = bid
	bp.bidWinnerMap[blockNumber][sender] = hash

	numBidsGauge.Update(int64(len(bp.bidMap)))

	logger.Trace("Add bid", "bid", hash)

	return nil
}

// senderHasDifferentWinner reports whether a different bid from the same sender
// already exists in the winner list for this block. Caller must hold bidMu.
func (bp *BidPool) senderHasDifferentWinner(bid *auction.Bid) bool {
	hash, ok := bp.bidWinnerMap[bid.BlockNumber][bid.Sender]
	if !ok {
		return false
	}
	return !bid.Equals(bp.bidMap[hash])
}

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}
