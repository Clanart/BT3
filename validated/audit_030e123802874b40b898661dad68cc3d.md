### Title
Unbounded recursion in `FieldMaskTree.GetFieldPaths`/`Merge` (C#) allows uncatchable `StackOverflowException` via a crafted deep FieldMask path - ([File: csharp/src/Google.Protobuf/FieldMaskTree.cs])

### Summary
Java's `FieldMaskTree` (`java/util/src/main/java/com/google/protobuf/util/FieldMaskTree.java`) was explicitly hardened to use an iterative stack-based traversal for `getFieldPaths` (lines 185–224) — confirmed by a dedicated regression test with a 250,000-segment path (`FieldMaskTreeTest.java:138-159`). C++'s equivalent (`field_mask_util.cc:315-338`) also uses an explicit `std::vector`-based stack. Python's `_FieldMaskTree.AddLeafNodes` (`field_mask.py:251-264`) is likewise iterative, verified by `field_mask_test.py:476-492` with a 1500-segment path noted as deliberately exceeding "Python's default recursion limit of 1000." The C# `FieldMaskTree`, however, was never given this treatment: `GetFieldPaths` (`FieldMaskTree.cs:146-159`) and its sibling `Merge` (`FieldMaskTree.cs:225-355`) are still classic self-recursive tree walks with no depth cap, one stack frame per FieldMask path segment. ### Finding Description
`google.protobuf.FieldMask` is a normal message with a `repeated string paths` field — it is parsed through the standard, supported binary/ProtoJSON parse APIs with no length or segment-count limit applied to each path string (only the usual total-message-size limits apply). This is the attacker-controlled input, directly analogous to the crafted GNU-`L` long-path header in the node-tar report: a single string field whose internal structure (here, `.`-separated segments) determines recursion depth in a downstream helper.

Once a consuming application uses that parsed `FieldMask` with the standard `FieldMaskTree`/`FieldMaskUtil` utilities — a documented, common pattern for API field-selection/merge/trim, exactly analogous to `tar.t`/`tar.x` member selection — the C# implementation walks the tree recursively:

- `GetFieldPaths` (`FieldMaskTree.cs:146-159`) recurses once per tree level (i.e., once per `.`-separated path segment) with **no depth counter or limit**, and is reached from `ToFieldMask()` (`FieldMaskTree.cs:130-141`, used by `FieldMask.ToString()`/normalization) and from `IntersectFieldPath` (`FieldMaskTree.cs:164-202`, used by `FieldMask.Intersect`).
- `Merge` (`FieldMaskTree.cs:225-355`) recurses once per nested-message segment in the mask, reached from the public `FieldMaskTree.Merge(source, destination, options)` entry point (`FieldMaskTree.cs:207-220`), itself invoked from field-mask-based merge operations.

Both are triggered purely by the number of `.`-delimited segments in an attacker-supplied `FieldMask.Paths` string — no schema depth, application logic, or byte-length cap bounds this count. A `FieldMask` path like `"a.a.a....a"` with tens of thousands of segments (well within normal message-size limits) produces a correspondingly deep call stack.

I attempted to verify whether other language runtimes share this weakness, and found they do not: Java's `getFieldPaths`/`merge` were already converted to explicit-stack iteration (verified via the 250k-segment regression test that specifically guards against this bug class), Python's tree traversal is iterative with an explicit `stack` list, and C++ uses an explicit `std::vector<StackElement>` stack. Only the C# implementation retains the naive recursive form.

### Impact Explanation
This transfers node-tar's `mapHas` bug class directly: an attacker-controlled, wire-format string field drives unbounded native-call-stack recursion in a helper routine reached through common application usage (field-mask merge/intersect/normalize), analogous to node-tar's "member selection" trigger. A `StackOverflowException` in .NET is not catchable by ordinary `try/catch` and terminates the process — an unauthenticated, remotely triggerable denial of service for any C# service that accepts a `FieldMask` from a client and applies it via `FieldMaskTree`/the C# `FieldMaskUtil`-equivalent operations (`Union`, `Intersect`, `ToString`/normalize, or a field-mask-based merge).

### Likelihood Explanation
High. The trigger requires only a plain string field inside a normal, valid FieldMask message — no malformed wire data, no schema tricks, no privileged access. Any C# server that parses a client-supplied `FieldMask` (e.g., for partial-update or field-selection APIs, a very common gRPC/REST pattern) and calls into `FieldMaskTree` is exposed. This is a lower bar than triggering the analogous but-already-fixed bug classes in Java/Python/C++.

### Recommendation
Rewrite `FieldMaskTree.GetFieldPaths` and `FieldMaskTree.Merge` in `csharp/src/Google.Protobuf/FieldMaskTree.cs` to use an explicit iterative stack, mirroring the fix already applied in `java/util/src/main/java/com/google/protobuf/util/FieldMaskTree.java` (`getFieldPaths`, lines 185-224) and the `std::vector`-based approach in `src/google/protobuf/util/field_mask_util.cc` (lines 315-338). Add a C# regression test analogous to `FieldMaskTreeTest.testGetFieldPaths_excessivelyDeepTree` (Java) using a path with tens/hundreds of thousands of `.`-separated segments to confirm no `StackOverflowException`.

  private static void getFieldPaths(Node node, String path, List<String> paths) {
    class PathStackElement {
      final Node node;
      final String segment;
      final int prefixLength;

      PathStackElement(Node node, String segment, int prefixLength) {
        this.node = node;
        this.segment = segment;
        this.prefixLength = prefixLength;
      }
    }

    StringBuilder currentPath = new StringBuilder(path);
    Deque<PathStackElement> stack = new ArrayDeque<>();
    stack.push(new PathStackElement(node, null, currentPath.length()));

    while (!stack.isEmpty()) {
      PathStackElement element = stack.pop();
      if (element.segment != null) {
        // Backtrack to the parent path length and append this segment.
        currentPath.setLength(element.prefixLength);
        if (element.prefixLength > 0) {
          currentPath.append('.');
        }
        currentPath.append(element.segment);
      }
      if (element.node.children.isEmpty()) {
        paths.add(currentPath.toString());
        continue;
      }
      // Pushing the children in reverse order so that they are processed in ascending order
      // will maintain the behavior that the paths are alphabetically sorted in the final
      // FieldMask.
      int currentLength = currentPath.length();
      for (Entry<String, Node> entry : element.node.children.descendingMap().entrySet()) {
        stack.push(new PathStackElement(entry.getValue(), entry.getKey(), currentLength));
      }
    }
  }
