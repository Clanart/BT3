### Title
Uncharged PDA derivation cost in CPI signer translation (`translate_signers`) allows cheap repeated `create_program_address` hashing per invocation - (File: program-runtime/src/cpi.rs)

### Summary
`cpi_common` charges a flat `invoke_units` cost once per CPI call at `program-runtime/src/cpi.rs:785-786`, and separately charges per-byte costs (`cpi_bytes_per_unit`) for account-info arrays and account data throughout `translate_account_infos`/`translate_accounts_common`/`translate_instruction_*`. However, `translate_signers` (`program-runtime/src/cpi.rs:631-674`), which is called from `cpi_common` for every CPI, performs up to `MAX_SIGNERS` PDA derivations via `Pubkey::create_program_address` — each of which does SHA256 hashing over up to `MAX_SEEDS` seed slices — without consuming any compute units for that work.

### Finding Description
`cpi_common` (`program-runtime/src/cpi.rs:773-891`) charges compute in several well-scoped places:
- A flat `invoke_units` charge for the CPI call itself [1](#0-0) .
- Byte-based charges for translated instruction data/account metas in `translate_instruction_rust`/`translate_instruction_c` [2](#0-1) .
- Byte-based charges for the `account_infos` array size in `translate_account_infos` [3](#0-2) .
- Byte-based charges for each account's serialized length in `translate_accounts_common` [4](#0-3)  and for executable account data [5](#0-4) .

So the premise that "all real cost is charged once at cpi.rs:785-786" does not hold — account/data copy costs are metered elsewhere. However, `translate_signers`, called unconditionally from `cpi_common` at `program-runtime/src/cpi.rs:801-806`, only enforces bound checks (`MAX_SIGNERS`, `MAX_SEEDS`) and then calls `Pubkey::create_program_address(&seeds_bytes, program_id)` for every signer-seed set with **no `compute_meter.consume_checked` call anywhere in the function** [6](#0-5) . `create_program_address` performs SHA256 hashing internally, which is real, non-trivial CPU work that the runtime does price elsewhere (the direct `sol_create_program_address` syscall charges `create_program_address_units` per call, per `execution_budget.rs`'s `SVMTransactionExecutionCost::create_program_address_units` field, which is a distinct code path from `translate_signers`).

This means a CPI call with `MAX_SIGNERS` signer-seed sets, each with up to `MAX_SEEDS` seeds, performs up to `MAX_SIGNERS` hash-based PDA derivations paid only by the flat `invoke_units` charge, not scaled to the actual hashing work performed.

### Impact Explanation
This falls under "materially underpriced compute" (Agave bounty category: compute-unit/DoS-adjacent under-metering). An attacker can construct a program that loops CPI calls, each supplying the maximum permitted signer/seed combinations, to perform far more SHA256 hashing work per compute unit charged than the runtime's expected `SVMTransactionExecutionCost` model assumes. This does not grant privilege escalation or memory corruption by itself — it is limited to compute-metering inaccuracy causing excess wall-clock work per CU, consistent with the DoS-adjacent invariant described in the question.

### Likelihood Explanation
Fully reachable by any unprivileged program: it only requires deploying a program that repeatedly calls `sol_invoke_signed` (Rust `invoke_signed`/C equivalent) with the maximum allowed signer/seed arrays within a single instruction's compute budget. No special privileges, validator control, or crafted snapshots are needed — just ordinary CPI usage at the parameter limits.

### Recommendation
Add an explicit compute charge in `translate_signers` proportional to the PDA derivation cost (using `execution_budget.rs`'s `create_program_address_units`, mirroring what the direct `sol_create_program_address` syscall charges) for each signer-seed set processed, before or after calling `Pubkey::create_program_address`, so the flat `invoke_units` charge is not the only cost paid for cryptographic seed-derivation work performed during CPI signer translation.

### Proof of Concept
Add a unit test in `program-runtime/src/cpi.rs`'s test module that:
1. Constructs a mock `InvokeContext` with a compute budget just above `invoke_units` plus byte-costs for a minimal `account_infos`/instruction payload.
2. Calls `translate_signers` with `MAX_SIGNERS` signer-seed sets, each containing `MAX_SEEDS` seeds of near-maximum seed length, verifying it succeeds without any additional `compute_meter.consume_checked` being invoked (e.g., by wrapping/mocking the compute meter to count invocations or track total consumed units before/after the call).
3. Assert that `compute_meter`'s consumed amount before and after `translate_signers` is unchanged (proving no charge for the `create_program_address` work), then separately benchmark wall-clock time of `MAX_SIGNERS * MAX_SEEDS` `create_program_address` calls to show it is non-negligible relative to the flat `invoke_units` cost, demonstrating disproportionate free work per CPI call.
