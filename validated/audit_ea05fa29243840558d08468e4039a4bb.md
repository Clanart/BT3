### Title
Attacker-controlled `WWW-Authenticate` header from a Git remote spoofs GitHub Enterprise classification, triggering a phishing-style sign-in prompt against an untrusted host - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
When Git needs credentials for an HTTP(S) remote, the trampoline credential helper's `getCredential` flow calls `getEndpointKind` to classify the target host before deciding how to obtain credentials. `getEndpointKind` includes a "happy path" that trusts the `WWW-Authenticate` header Git forwards from the remote server's HTTP response, without any network-side verification: if the header contains `realm="GitHub"`, the host is immediately classified as `'enterprise'`. Since this header is fully attacker-controlled (it comes straight from the HTTP response of whatever remote Desktop is cloning/fetching/pushing to), a malicious or compromised git server can force Desktop to treat an arbitrary domain as a trusted GitHub Enterprise endpoint and pop the "sign in to GitHub" dialog scoped to that attacker domain.

The broken invariant mirrors the Sentiment bug's core lesson: an attacker-controlled external input (there: an ERC777 callback; here: an HTTP response header from the remote being cloned/fetched/pushed to) is consumed by a trust decision *before* the equivalent "real" validation (there: the health check; here: `isGitHubHost`'s actual network verification) runs, and that unverified state is then acted upon by a privileged flow (there: borrow/withdraw; here: initiating an authenticated sign-in against the attacker's origin).

### Impact Explanation
This is a credential/account-binding integrity issue: a purely network-observed value (`WWW-Authenticate` from a git remote) can cause Desktop to autonomously present its own "Sign in to GitHub" UI pointed at an attacker-chosen domain during a routine `fetch`/`clone`/`push`, without the user ever typing a URL or clicking a suspicious link — the classic UI-trust cue ("Desktop initiated this, it must be legitimate") is subverted. Because the endpoint origin the user is guided to authenticate against is attacker-controlled, this enables convincing credential/OAuth phishing against GitHub Enterprise users, and falls under "unauthorized OAuth or account binding" in the accepted impact categories. It does not directly leak already-stored tokens (the exact-endpoint match check in `getCredential` prevents that), but it does misuse Desktop's own trusted-looking sign-in surface as a phishing vector triggered purely by remote response content.

### Likelihood Explanation
Likelihood is moderate-to-high for any workflow where Desktop performs credential-helper-mediated HTTP(S) git operations against a server not already known to the user (adding an unknown remote, cloning a URL from an untrusted source, or a compromised/MITM'd proxy in between). No local access, admin rights, or social engineering beyond "user has a repo pointing at an attacker's git server" is required — the trigger is automatic as part of the git credential negotiation, matching the report's "unprivileged, attacker controls a git remote/proxy response" threat model.

### Recommendation
Do not classify a host as `'enterprise'` based solely on the `WWW-Authenticate` realm string. Either remove this fast path entirely and always fall back to the network-verified `isGitHubHost(endpoint)` check, or treat the header as only a weak hint that still requires the real verification step before it can upgrade trust level / trigger the sign-in UI.

### Proof of Concept
1. Set up an HTTP git server at `https://evil.example.com/repo.git` that, on any request requiring auth, responds with `WWW-Authenticate: Basic realm="GitHub"`.
2. In GitHub Desktop, add `https://evil.example.com/repo.git` as a remote (or clone it) and no account exists for `evil.example.com`.
3. Trigger a `fetch`/`push`/`pull`; Git invokes the credential helper trampoline with the captured `wwwauth[...]` header included in the credential command's stdin.
4. `getEndpointKind` (`app/src/lib/trampoline/trampoline-credential-helper.ts:152-165`) matches `realm="GitHub"` and returns `'enterprise'` without ever calling `isGitHubHost`.
5. `getCredential` finds no existing account for `evil.example.com` and calls `ui.promptForGitHubSignIn('https://evil.example.com')`, which opens Desktop's native "Sign in to GitHub Enterprise" dialog pre-scoped to the attacker's domain (`app/src/lib/trampoline/trampoline-ui-helper.ts:80-104`, `app/src/lib/stores/sign-in-store.ts:394-416`).
6. A user who proceeds believes they are authenticating a legitimate GitHub Enterprise account through Desktop's own trusted UI, but the browser session and any OAuth code are directed at the attacker's origin.

Note: I was not able to fully trace the exact wording/format Git uses when populating `wwwauth[...]` fields for HTTP credential-helper input beyond what's referenced in `app/test/unit/git/credential-test.ts`; a Devin session with full repo/test access would be needed to confirm the precise header-forwarding mechanics end-to-end if a full exploit chain reproduction is required.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
