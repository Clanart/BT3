### Title
OP_RETURN `data` output excluded from fee/weight estimation causes under-priced, potentially unrelayable transactions - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
`SignableTransaction::new` pushes the user-supplied OP_RETURN `data` output into `tx_outs` *before* calling `calculate_weight_vbytes`, but the weight/vbyte estimator only models `payments` (and optionally `change`). The up-to-80-byte data output's weight is never priced, so `needed_fee` is systematically too low whenever `data` is provided and a change output exists. The transaction is then signed paying `input - outputs == needed_fee` while being larger than estimated, i.e., the signer subsidizes the attacker's arbitrary bytes — the same "protocol subsidizes user-controlled resource consumption" pattern as the feeMultiplier/GAS_OVERHEAD_NATIVE report.

### Finding Description
In `SignableTransaction::new`, the OP_RETURN output is appended to `tx_outs` first, and then the fee is computed from a mock transaction built only from `payments`: [1](#0-0) 

```rust
if let Some(data) = data {
  tx_outs.push(TxOut { value: Amount::ZERO, script_pubkey: ScriptBuf::new_op_return(...) })
}
let (mut weight, vbytes) = Self::calculate_weight_vbytes(tx_ins.len(), payments, None);
let mut needed_fee = fee_per_vbyte * vbytes;
```

`calculate_weight_vbytes` builds outputs from `payments` only — the data output is never represented: [2](#0-1) 

The change path repeats the omission: `fee_with_change = fee_per_vbyte * vbytes_with_change` where `vbytes_with_change` again excludes the data output. [3](#0-2) 

An 80-byte OP_RETURN output adds ~91 non-witness bytes (~91 vbytes) to the real transaction that were never priced. The minimum-relay check `needed_fee < DEFAULT_MIN_RELAY_TX_FEE * vbytes / 1000` is evaluated against the *understated* `vbytes`, so a transaction built at exactly the relay minimum is signed paying less than the minimum fee for its actual size.

### Impact Explanation
Whoever supplies the inputs (Serai's multisig wallet) produces a signed transaction whose real fee rate is lower than `fee_per_vbyte` by roughly `data_len + overhead` vbytes worth of fee. At boundary fee rates this falls below `DEFAULT_MIN_RELAY_TX_FEE`, making the signed transaction unrelayable — Serai's change (the bulk of the funds) is locked in a transaction no node will propagate, recoverable only via CPFP/RBF or resigning. An unprivileged caller who can get the wallet to sign a transaction embedding their bytes gains ~91 vbytes of fee-free transaction space per transaction at the signer's expense (the missing sats are effectively absorbed into the change/output math, distorting the intended fee accounting). The maximum amplification is bounded (~80 bytes of data, 80-byte cap enforced at line 171), keeping this Medium rather than High.

### Likelihood Explanation
The `data` parameter is a public, caller-controlled argument of `SignableTransaction::new` (used on Bitcoin to carry `Shorthand` instructions such as transfer/refund metadata). Any call site that forwards attacker-influenced bytes — e.g., a refund address or memo derived from a user's burn/mint instruction — reaches this path with only public inputs. The underpricing is deterministic on every call with `data.is_some()` and `change.is_some()`; it only bites when `fee_per_vbyte` is near the relay minimum or when the caller relies on `needed_fee()`/`fee()` being accurate.

### Recommendation
Include the OP_RETURN output in the weight calculation. Either pass the constructed `tx_outs` (or a size-hint for the data output) into `calculate_weight_vbytes`, or construct the mock `Transaction` from the final output list:

```rust
fn calculate_weight_vbytes(
  inputs: usize,
  outputs: &[(ScriptBuf, u64)],
) -> (u64, u64)
```

with `data` mapped to `(op_return_script, 0)` before both the no-change and with-change calls. Also re-check `needed_fee` against `DEFAULT_MIN_RELAY_TX_FEE` using the corrected vbytes.

### Proof of Concept
```rust
// Pseudocode against networks/bitcoin/src/wallet/send.rs
let inputs = vec![received_output];            // any spendable ReceivedOutput
let payments = vec![(p2tr_script, 10_000)];
let change = Some(p2tr_script.clone());
let data = Some(vec![0xAA; 80]);               // max allowed

// Fee rate at exactly the relay minimum: 1000 sat/kvB = 1 sat/vB
let tx = SignableTransaction::new(inputs, &payments, change, data, 1).unwrap();

// Real transaction now contains the extra ~91-byte OP_RETURN output,
// but needed_fee was computed without it:
//   signed_fee == tx.fee() == needed_fee (computed for vbytes_without_data)
//   actual_vsize ≈ estimated_vsize + ~91
//   effective_feerate = needed_fee / actual_vsize < 1 sat/vB
// -> below DEFAULT_MIN_RELAY_TX_FEE: not relayed by default policy,
//    change output (Serai's funds) is stuck until republished/CPFP'd.
```
Contrast with the `data: None` path where `fee() == needed_fee == fee_per_vbyte * actual_vsize` holds exactly, as asserted by the existing test `assert_eq!(input_value - output_value, needed_fee)` in `networks/bitcoin/tests/wallet.rs:269-272`.
