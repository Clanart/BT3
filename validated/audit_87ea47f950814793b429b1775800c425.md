## Analysis Result: Vulnerability Confirmed

### Title
Attribution of `payout_payer_operator_xonly_pk` relies solely on an unauthenticated OP_RETURN in the transaction spending `withdrawal_utxo`, letting a withdrawer credit an arbitrary victim operator for a payout it never funded - ([File: core/src/verifier.rs])

### Summary
`update_finalized_payouts` derives `payout_payer_operator_xonly_pk` purely from parsing the OP_RETURN of whatever transaction spends the tracked `withdrawal_utxo` on Bitcoin [1](#0-0) , with no check that the named operator actually funded the output. Because the withdrawal UTXO is a P2TR output whose key is the withdrawer's own (`user_xonly_pk` derived directly from the input's own script pubkey) [2](#0-1) , the withdrawer can self-spend it in a transaction they fully craft — bypassing the operator's RPC entirely — and stamp any operator's x-only pubkey in the OP_RETURN.

### Finding Description
**Broken binding:** `payout_payer_operator_xonly_pk[idx] == operator whose own BTC funded withdrawal[idx]'s payout output` is assumed but never enforced.

**Trace:**
1. The attacker calls Citrea's withdraw, registering a `withdrawal_utxo` outpoint — a UTXO they fully control the private key for (`try_get_taproot_pk()`/`user_xonly_pk`) [3](#0-2) .
2. Instead of using an honest operator's `Withdraw`/`InternalWithdraw` gRPC flow (which sets OP_RETURN to `self.signer.xonly_public_key`, the operator's own key, via `create_payout_txhandler`) [4](#0-3) , the attacker crafts and broadcasts their own transaction spending `withdrawal_utxo` (which they own), with an arbitrary OP_RETURN naming a **victim operator's** xonly public key.
3. `bitcoin_syncer` records the spend; `update_finalized_payouts` parses the first OP_RETURN output and unconditionally records it as `payout_payer_operator_xonly_pk`, without verifying the payer actually is that operator or that the output matches any real fronted amount/address [5](#0-4) .
4. `get_first_unhandled_payout_by_operator_xonly_pk` (queried by the victim operator's `PayoutCheckerTask`) returns this entry keyed only on `payout_payer_operator_xonly_pk` [6](#0-5) .
5. The victim operator's `PayoutCheckerTask::run_once` calls `handle_finalized_payout`, builds/queues a Kickoff, and marks the payout handled [7](#0-6) .
6. `Verifier::is_kickoff_malicious` compares the OP_RETURN-derived xonly pk against `kickoff_data.operator_xonly_pk` — this matches trivially since both come from the same attacker-controlled OP_RETURN [8](#0-7) ; it does not verify who actually funded the payout output.
7. Critically, in the bridge circuit, `verify_storage_proofs`/`bridge_circuit` only check that the payout tx's **input** (`previous_output.txid`/`vout`) matches the storage-proven withdrawal outpoint [9](#0-8) . Neither the storage-proof check nor `verify_storage_proofs` (`circuits-lib/src/bridge_circuit/storage_proof.rs`) validate the payout transaction's **output** script/amount against the Citrea-committed withdrawal parameters (`output_script_pubkey`/`output_amount`). The OP_RETURN is read purely to compute `deposit_constant` (binding it to the *claimed* operator identity for the disprove circuit's own commitments), not to verify actual funding attribution [10](#0-9) .

Because nothing anywhere in this path checks that the operator named in the OP_RETURN is the one whose funds actually paid the withdrawer, and because the withdrawer, not any operator, holds the sole signing key over the UTXO being spent, the attacker can self-fund their own withdrawal (paying themselves) while gratuitously tagging a victim operator, who then legitimately clears all downstream checks (`is_kickoff_malicious`, SPV, storage proofs) and gets reimbursed via the kickoff/Disprove flow for a payout it never sent.

### Impact Explanation
A named operator is fraudulently credited with, and can claim reimbursement for, a payout it never funded — this is the Critical impact category "an operator reimbursed for a payout it never funded." The attack is repeatable per withdrawal the attacker initiates, and works against any operator whose xonly pubkey is public knowledge (all operator pubkeys are public/discoverable via gRPC). No operator collateral or key compromise is required from the attacker's side — only their own withdrawal and their own signature over their own UTXO.

### Likelihood Explanation
Preconditions: attacker must be able to perform a real Citrea `withdraw()` call (unprivileged, standard user action) and register a `withdrawal_utxo` they control, then broadcast a Bitcoin transaction spending it with an OP_RETURN tag of their choosing. Cost is essentially just the attacker's own withdrawal amount plus fees (which they receive back to themselves, i.e. no net loss beyond fees) — this is a low-cost, fully repeatable attack requiring no privileged access.

### Recommendation
Never derive operator attribution purely from an OP_RETURN of the payout-spending transaction. Attribution must be cryptographically bound to the specific operator, e.g. by requiring the payout transaction to be signed/authorized via a MuSig2/N-of-N mechanism that includes the claiming operator's key, or by requiring `verify_storage_proofs`/`bridge_circuit` to additionally verify that a specific output of the payout transaction actually transfers `output_amount` to `output_script_pubkey` as committed on Citrea, sourced from an input controlled by the operator identified in the OP_RETURN (e.g. the operator's own change/reimbursement path), not merely trusting attacker-supplied OP_RETURN bytes.

// 8. Assert: Verifier::is_kickoff_malicious returns false for this kickoff (since OP_RETURN matches kickoff_data.operator_xonly_pk).
// 9. (Optional deeper check) Run through to Disprove/bridge_circuit path and assert verify_storage_proofs succeeds because it only checks input outpoint/vout match, not output content/funder — confirming reimbursement would be paid to OP_A's `wallet_reimburse_address` for a payout OP_A never made.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }

    async fn run_once(&mut self) -> Result<Self::Output, BridgeError> {
        let mut dbtx = self.db.begin_transaction().await?;
        let unhandled_payout = self
            .db
            .get_first_unhandled_payout_by_operator_xonly_pk(
                Some(&mut dbtx),
                self.operator.signer.xonly_public_key,
            )
            .await?;

        if unhandled_payout.is_none() {
            return Ok(false);
        }

        let (citrea_idx, move_to_vault_txid, payout_tx_blockhash) =
            unhandled_payout.expect("Must be Some");

        tracing::info!(
            "Unhandled payout found for withdrawal {}, move_txid: {}",
            citrea_idx,
            move_to_vault_txid
        );

        let deposit_data = self
            .db
            .get_deposit_data_with_move_tx(Some(&mut dbtx), move_to_vault_txid)
            .await?;
        if deposit_data.is_none() {
            return Err(eyre::eyre!("Fronted withdrawal for move tx {move_to_vault_txid} found, but the signatures for the deposit are not found in the db.").into());
        }

        let deposit_data = deposit_data.expect("Must be Some");

        let kickoff_txid = self
            .operator
            .handle_finalized_payout(
                &mut dbtx,
                deposit_data.get_deposit_outpoint(),
                payout_tx_blockhash,
            )
            .await?;

        // fetch and save the LCP for if we get challenged and need to provide proof of payout later
        let (_, payout_block_height) = self
            .operator
            .db
            .get_block_info_from_hash(Some(&mut dbtx), payout_tx_blockhash)
            .await?
            .ok_or_eyre("Couldn't find payout blockhash in bitcoin sync")?;

        let _ = self
            .operator
            .citrea_client
            .fetch_validate_and_store_lcp(
                payout_block_height as u64,
                citrea_idx,
                &self.operator.db,
                Some(&mut dbtx),
                self.operator.config.protocol_paramset(),
            )
            .await?;

        #[cfg(feature = "automation")]
        self.operator.end_round(&mut dbtx).await?;

        self.db
            .mark_payout_handled(Some(&mut dbtx), citrea_idx, kickoff_txid)
            .await?;

        dbtx.commit().await?;

        Ok(true)
