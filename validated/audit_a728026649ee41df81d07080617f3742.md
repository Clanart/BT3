### Title
Attacker-controlled `WWW-Authenticate` realm spoofing bypasses GitHub-host verification and triggers an unvalidated "Sign in to GitHub Enterprise" OAuth flow bound to an arbitrary attacker host - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
`getEndpointKind()` in the trampoline credential helper classifies a remote host as a "GitHub" host (`enterprise`) by trusting the `wwwauth[]` credential attribute that Git forwards from the server's HTTP `WWW-Authenticate` response header, before ever performing the network-verified `isGitHubHost()` check. [1](#0-0) 
Because that header value is fully attacker-controlled (it comes from whatever server Git is talking to), any git remote/proxy can spoof `realm="GitHub"` to make Desktop treat an arbitrary domain as a trusted GitHub Enterprise endpoint. This causes Desktop to automatically pop up the real "Sign in to GitHub Enterprise" flow scoped to the attacker's domain and open an OAuth authorize URL on that domain in the user's browser, without any actual confirmation that the host is a genuine GitHub Enterprise/dotcom instance.

### Finding Description
When Git needs credentials for an HTTPS remote, it invokes Desktop's credential helper via the trampoline (`createCredentialHelperTrampolineHandler` → `getCredential`). `getCredential` calls `getEndpointKind()` to decide whether the target host should be treated as GitHub/GHE (in which case only internally-stored account tokens are used, or the user is prompted to sign in) or as `generic` (basic username/password credential). [2](#0-1) 

Inside `getEndpointKind`, before falling back to the network-verified `isGitHubHost()` check (which does a `/meta` HEAD request and checks for an `x-github-request-id` header), the function scans the credential map for `wwwauth[...]` keys — Git's forwarded copy of the server's `WWW-Authenticate` response header — and immediately classifies the host as `'enterprise'` if the value merely contains `realm="GitHub"`: [1](#0-0) 

This value is attacker-controlled: it is set by whatever HTTP server responds to Git's unauthenticated request for the remote (this could be a malicious git host added as a remote, a repository fetched via a crafted `x-github-client://openRepo/...` deep link handled by `parseAppURL`/`dispatcher.openOrCloneRepository`, or a MITM/malicious proxy). There is no TLS-certificate, hostname-suffix, or content check to confirm the server is a real GitHub Enterprise instance — unlike the legitimate fallback path `isGitHubHost()`, which is skipped entirely once the spoofed header is seen. [3](#0-2) 

Once `getEndpointKind` returns `'enterprise'` and no existing account matches that host's derived API endpoint, `getCredential` calls `ui.promptForGitHubSignIn(endpoint)`: [4](#0-3) 

`promptForGitHubSignIn` binds the sign-in flow's endpoint to the attacker's own origin (`this.dispatcher.setSignInEndpoint(origin)`), and shows the real Desktop "Sign in" popup: [5](#0-4) 

If the user proceeds with "sign in with browser", `authenticateWithBrowser()` opens `getOAuthAuthorizationURL(endpoint, csrfToken)` externally, which constructs `${getHTMLURL(attacker-controlled-endpoint)}/login/oauth/authorize?...`, i.e., a URL on the attacker's own domain: [6](#0-5) [7](#0-6) 

This is the "confirmed with parent" gap analogous to the report: the endpoint-kind decision (analogous to "which pool the fee belongs to") is derived from unverified, attacker-supplied data instead of being confirmed by the trusted verification path (`isGitHubHost`), so a value that should only be trusted after confirmation (host identity) is instead trusted directly from attacker input.

### Impact Explanation
An attacker who controls a git remote/proxy the victim fetches from (e.g., a repository added via clone, or opened through an `x-github-client://openRepo/...`/`github-mac://openRepo/...` deep link routed through `dispatcher.openOrCloneRepository`) can spoof the `WWW-Authenticate` header to make GitHub Desktop believe the attacker's arbitrary domain is a legitimate GitHub Enterprise server. This automatically drives the victim into Desktop's genuine "Sign in to GitHub Enterprise" UI scoped to the attacker's domain, and, if the user proceeds, opens an OAuth authorize page hosted entirely by the attacker in the system browser. Because the UI and prompts are Desktop's own trusted "Sign in" dialog, the phishing surface is highly convincing (it is not an ad-hoc external browser tab the user was told to distrust, but a flow the app itself initiated in response to a normal git operation like a fetch/clone). This can lead to credential/token exfiltration for the victim's actual GitHub Enterprise or GitHub.com account if they complete authentication believing it is legitimate.

### Likelihood Explanation
Triggering the code path only requires the victim to add/clone/fetch from an attacker-controlled HTTPS git remote or open an "Open in Desktop" deep link pointing at an attacker's server — both are unprivileged, common actions a user might perform without suspicion (e.g., cloning a repo shared by a link). Spoofing an HTTP response header is trivial for anyone running the target server. The only extra step required is for the user to click through the sign-in prompt, but the prompt itself is triggered automatically by Desktop, not something the attacker has to social-engineer the user into opening manually.

### Recommendation
Do not classify a host as `'enterprise'`/GitHub based solely on the attacker-suppliable `wwwauth[]` realm string. Either remove this heuristic entirely and always fall back to the network-verified `isGitHubHost()` check (which validates via TLS-protected `/meta` response headers), or require that the `wwwauth[]`-based heuristic be corroborated by `isGitHubHost()`/hostname-suffix checks before it is allowed to trigger the sign-in flow. At minimum, before opening any external OAuth URL or presenting the "Sign in to GitHub Enterprise" flow for a host discovered via this heuristic, perform (and require success of) the existing `isGitHubHost()` verification.

### Proof of Concept
1. Stand up an HTTPS server (`https://evil.example.com`) that responds to unauthenticated Git HTTP requests (e.g. `GET /info/refs?service=git-upload-pack`) with `401 Unauthorized` and header `WWW-Authenticate: Basic realm="GitHub"`.
2. Get the victim to add/clone this URL as a remote in GitHub Desktop, or send them a link such as `x-github-client://openRepo/https://evil.example.com/foo/bar`, which Desktop's `parseAppURL`/`dispatcher.openOrCloneRepository` will handle and attempt to fetch. [8](#0-7) 
3. When Git contacts `evil.example.com` and receives the spoofed 401/`WWW-Authenticate` header, Desktop's trampoline credential helper invokes `getCredential` → `getEndpointKind`, which returns `'enterprise'` purely because of the `realm="GitHub"` string, bypassing `isGitHubHost()`. [9](#0-8) 
4. Since no account exists for `evil.example.com`, Desktop shows the "Sign in to GitHub Enterprise" popup scoped to that domain (`ui.promptForGitHubSignIn`), and if the user chooses "Sign in using your browser," Desktop opens `https://evil.example.com/login/oauth/authorize?...` in the system browser — a page fully controlled by the attacker, who can render a convincing fake GitHub Enterprise login page to harvest credentials. [5](#0-4) [6](#0-5)

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}

    })
  }

export function parseAppURL(url: string): URLActionType {
  const parsedURL = URL.parse(url, true)
  const hostname = parsedURL.hostname
  const unknown: IUnknownAction = { name: 'unknown', url }
  if (!hostname) {
    return unknown
  }

  const query = parsedURL.query

  const actionName = hostname.toLowerCase()
  if (actionName === 'oauth') {
    const code = getQueryStringValue(query, 'code')
    const state = getQueryStringValue(query, 'state')
    if (code != null && state != null) {
      return { name: 'oauth', code, state }
    } else {
      return unknown
    }
  }

  // we require something resembling a URL first
  // - bail out if it's not defined
  // - bail out if you only have `/`
  const pathName = parsedURL.pathname
  if (!pathName || pathName.length <= 1) {
    return unknown
  }

  // Trim the trailing / from the URL
  const parsedPath = pathName.substring(1)

  if (actionName === 'openrepo') {
    const pr = getQueryStringValue(query, 'pr')
    const branch = getQueryStringValue(query, 'branch')
    const filepath = getQueryStringValue(query, 'filepath')

    if (pr != null) {
      if (!/^\d+$/.test(pr)) {
        return unknown
      }

      // we also expect the branch for a forked PR to be a given ref format
      if (branch != null && !/^pr\/\d+$/.test(branch)) {
        return unknown
      }
    }

    if (branch != null && testForInvalidChars(branch)) {
      return unknown
    }

    return {
      name: 'open-repository-from-url',
      url: parsedPath,
      branch,
      pr,
      filepath,
    }
  }

  return unknown
}
