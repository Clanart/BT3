### Title
Python `str()`/`repr()`/`MessageToString()` do not honor `debug_redact` field option, leaking sensitive fields into logs - ([File: python/google/protobuf/pyext/message.cc], [File: python/google/protobuf/text_format.py])

### Summary
The C++ `Message::DebugString()`/`ShortDebugString()`/`Utf8DebugString()` implementations explicitly enable `SetRedactDebugString(true)` before rendering a message to text [1](#0-0) , and the field-level redaction is enforced in `TextFormat::Printer::TryRedactFieldValue` based on the `debug_redact` FieldOptions annotation [2](#0-1) . Java mirrors this via `DebugFormat`/`TextFormat.debugFormatPrinter()`, which also drives `shouldRedact()` off the same annotation [3](#0-2) [4](#0-3) .

The Python C-extension binding's `str(message)`/`repr(message)` path (`ToStr`) builds a bare `TextFormat::Printer` and never calls `SetRedactDebugString(true)`, so redaction is off by construction [5](#0-4) . `python_message.py`'s `__str__`/`__repr__`/`__unicode__` implementations call `text_format.MessageToString(self)` directly with no redaction argument either [6](#0-5) . A grep of the entire `python/` tree for `redact`/`debug_redact` returns zero matches, confirming the pure-Python `text_format.py` implementation of `MessageToString`/printer classes has no redaction logic at all.

### Finding Description
The `debug_redact` FieldOptions annotation is protobuf's built-in mechanism for schema owners to mark a field as sensitive so that debug/log rendering (`DebugString()`, `%s` logging, etc.) never prints its value — directly analogous to how a SessionID should never surface in an audit log. In C++ and Java, this invariant is enforced centrally: any code path reaching `Message::DebugString()`/`ShortDebugString()`/`Utf8DebugString()` or `DebugFormat` unconditionally turns on redaction. In Python, the exact same "print protobuf message for a human/log" surface — `str(msg)`, `repr(msg)`, `text_format.MessageToString(msg)` — does not consult `debug_redact` at all, in either the C-extension (`ToStr`) or pure-Python backends. An ordinary client-controlled bounded message parsed through any public parse API (`ParseFromString`, JSON parse, etc.) that happens to populate a field the schema author marked `debug_redact=true` will have that field's plaintext value printed verbatim by Python application code that does what every other language implementation does safely (logs the message with `%s`/`str()`).

### Impact Explanation
Application code written against the Python protobuf API and relying on `debug_redact` for defense-in-depth (the same class of protection the UAA advisory says was missing for SessionIDs) silently fails: sensitive field values (tokens, credentials, PII marked via `[debug_redact = true]`) are written to logs whenever a message is stringified. This is an information-disclosure issue with the same root cause as CVE-2018-1192 — a security-relevant value ends up in logs due to a missing redaction check in the logging/rendering code path — but confined to the Python binding's debug-string surface rather than a network audit log.

### Likelihood Explanation
High likelihood of occurrence in real applications: `str(message)`/`repr(message)`/`%s` formatting of protobuf messages is an extremely common logging idiom in Python codebases (e.g., `logging.info("request=%s", msg)`), and no attacker action beyond normal bounded parsing is required — the field is populated through a supported public parse API and then unintentionally logged by trusted application code that reasonably assumes `debug_redact` is honored uniformly across languages, as documented and enforced in C++/Java.

### Recommendation
Wire `debug_redact` support into the Python bindings' debug-string surfaces: have `pyext/message.cc`'s `ToStr` construct its `TextFormat::Printer` with `SetRedactDebugString(true)` (matching `internal::StringifyMessage` in C++), and add equivalent field-option-aware redaction to the pure-Python `text_format.py` printer/`MessageToString` implementation so `str()`/`repr()` and `MessageToString()` redact fields per `FieldOptions.debug_redact`, consistent with C++ and Java behavior.

### Proof of Concept
Conceptual reproduction (not executed, described from source inspection):
1. Define a `.proto` message with a field annotated `string token = 1 [debug_redact = true];`.
2. In Python, parse an attacker-supplied bounded serialized message setting that field via `Message.ParseFromString(data)` (a supported public parse API).
3. Application code logs it: `logging.info("msg=%s", parsed_msg)`, which invokes `__str__` → `text_format.MessageToString(self)` (pure Python) or `ToStr` (C extension).
4. Because neither path sets `SetRedactDebugString(true)` nor has any `debug_redact` handling (confirmed by the zero-match grep across `python/` for `redact`), the token's plaintext value appears in the output/log line, whereas the equivalent C++ (`msg.DebugString()`) or Java (`DebugFormat.toString(msg)`) call on the same message would print `[REDACTED]`.

std::string StringifyMessage(const Message& message, Option option,
                             FieldReporterLevel reporter_level) {
  // Indicate all scoped reflection calls are from DebugString function.
  ScopedReflectionMode scope(ReflectionMode::kDebugString);

  TextFormat::Printer printer;
  internal::FieldReporterLevel reporter = reporter_level;
  switch (option) {
    case Option::kShort:
      printer.SetSingleLineMode(true);
      break;
    case Option::kUTF8:
      printer.SetUseUtf8StringEscaping(true);
      break;
    case Option::kNone:
      break;
  }
  printer.SetExpandAny(true);
  printer.SetRedactDebugString(true);
  printer.SetRandomizeDebugString(true);
  printer.SetReportSensitiveFields(reporter);
  std::string result;
  // TODO: Remove this suppression.
  (void)printer.PrintToString(message, &result);

  if (option == Option::kShort) {
    TrimTrailingSpace(result);
  }

  return result;
}

PROTOBUF_EXPORT std::string StringifyMessage(const Message& message) {
  return StringifyMessage(message, Option::kNone,
                          FieldReporterLevel::kAbslStringify);
}
}  // namespace internal

std::string Message::DebugString() const {
  return internal::StringifyMessage(*this, internal::Option::kNone,
                                    FieldReporterLevel::kDebugString);
}

bool TextFormat::Printer::TryRedactFieldValue(
    const Message& message, const FieldDescriptor* field,
    BaseTextGenerator* generator, bool insert_value_separator) const {
  TextFormat::RedactionState redaction_state =
      DescriptorPool::MemoizeProjection(
          field, [](const FieldDescriptor* field) {
            return TextFormat::GetRedactionState(field);
          });
  if (redaction_state.redact) {
    if (redact_debug_string_) {
      IncrementRedactedFieldCounter();
      if (insert_value_separator) {
        generator->PrintMaybeWithMarker(MarkerToken(), ": ");
      }
      generator->PrintString(kFieldValueReplacement);
      if (insert_value_separator) {
        if (single_line_mode_) {
          generator->PrintLiteral(" ");
        } else {
          generator->PrintLiteral("\n");
        }
      }
      return true;
    }
  }
  return false;
}

static PyObject* ToStr(CMessage* self) {
  TextFormat::Printer printer;
  // Passes ownership
  printer.SetDefaultFieldValuePrinter(new PythonFieldValuePrinter());
  printer.SetHideUnknownFields(true);
  std::string output;
  if (!printer.PrintToString(*self->message, &output)) {
    PyErr_SetString(PyExc_ValueError, "Unable to convert message to str");
    return nullptr;
  }
  return PyUnicode_FromString(output.c_str());
}
