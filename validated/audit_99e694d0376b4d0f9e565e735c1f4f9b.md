### Title
`Scanner::scan_block` reports immature coinbase outputs as spendable `ReceivedOutput`s - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
`Scanner::scan_transaction` is safe to call on any attacker-influenced transaction: it only emits outputs whose `script_pubkey` matches a registered Taproot script. `Scanner::scan_block`, the convenience wrapper, iterates `block.txdata` starting at index 0, so it also scans the coinbase transaction. Any miner (an unprivileged party who fully controls coinbase outputs) can pay to the multisig's registered P2TR script inside a coinbase transaction, causing `scan_block` to return a `ReceivedOutput` that is consensus-unspendable for 100 blocks. Analogous to `LMPVaultRouter.depositMax` not handling the native-payment case that the sibling deposit functions handle, `scan_block` does not handle the coinbase-maturity case that downstream consumers (e.g., the processor's `get_outputs`, which explicitly skips `block.txdata[0]`) must handle.

### Finding Description
`scan_block` calls `scan_transaction` on every transaction in the block, including `block.txdata[0]` (the coinbase) (mod.rs:221-227). The returned `ReceivedOutput` is indistinguishable from a mature output: it carries only `offset`, `output`, and `outpoint` (mod.rs:89-97), and `ReceivedOutput::read`/`write` serialize no maturity flag (mod.rs:122-141). When such an output is passed to `SignableTransaction::new`, the prevout is committed via `Prevouts::All` and a signature is produced over a transaction that spends an immature coinbase output (send.rs:373-391). That transaction is invalid under consensus rule `OP_COINBASE`/maturity (BIP-113 style 100-block rule) and will be rejected by the network. Notably, Serai's own processor avoids this by scanning only `block.txdata[1 ..]` in `Bitcoin::get_outputs` (processor/src/networks/bitcoin.rs:690-691), confirming the correct behavior is known but not enforced in the wallet-level `scan_block` API.

### Impact Explanation
An unprivileged miner can cause the scanner to report funds "received" that are not actually spendable. Any consumer that trusts `scan_block` output will attempt to spend an immature coinbase output, producing a threshold-signed transaction the Bitcoin network rejects — burning a FROST signing session and misreporting balance until maturity. Because `ReceivedOutput` has no maturity marker, there is no way to detect the bad output from the type itself; the only defense is the doc comment on `scan_block`.

### Likelihood Explanation
Requires a miner to include the multisig's script in a coinbase output — cheap and fully within miner control, though it donates the funds and only causes temporary unspendability plus a wasted signing round. Reachable purely through public on-chain inputs (a Bitcoin transaction an attacker causes to be mined). Medium likelihood, medium-low but concrete impact.

### Recommendation
Skip `block.txdata[0]` inside `scan_block`, or return a structured result distinguishing coinbase outputs (e.g., add an `immature`/`coinbase` flag to `ReceivedOutput` and its `read`/`write` encoding), matching the behavior already implemented in `processor/src/networks/bitcoin.rs`'s `get_outputs`.

### Proof of Concept
```rust
// A miner constructs a block whose coinbase tx pays to the multisig's script:
let key = keys.group_key(); // even-Y tweaked key
let script = p2tr_script_buf(key).unwrap();
let coinbase = Transaction {
  version: Version(2),
  lock_time: LockTime::ZERO,
  input: vec![TxIn { /* coinbase input */ .. }],
  output: vec![TxOut { value: Amount::from_sat(100_000), script_pubkey: script }],
};
let block = Block { header: .., txdata: vec![coinbase /* , ... */] };

let scanner = Scanner::new(key).unwrap();
let outputs = scanner.scan_block(&block);
assert_eq!(outputs.len(), 1); // reported as received

// Consumer builds a spend; the resulting TX is invalid for 100 blocks:
let tx = SignableTransaction::new(
  outputs, &payments, Some(change), None, fee_per_vbyte
).unwrap();
// signing succeeds, broadcast fails: "bad-txns-premature-spend-of-coinbase"
```
