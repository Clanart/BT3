## Title
Attacker-controlled `WWW-Authenticate` realm header spoofs GitHub host classification, triggering GitHub Enterprise sign-in flow pointed at an untrusted server - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

## Summary
GitHub Desktop's credential-helper trampoline decides how to authenticate a Git HTTP(S) remote by classifying the target host as `github.com`, `enterprise`, `ghe.com`, `gist`, or `generic`. Part of that classification trusts a string literal (`realm="GitHub"`) taken directly from the HTTP response of the remote Git server/proxy, with no verification that the host is actually a GitHub endpoint. This is structurally the same bug class as the PRBProxy report: a value fully controlled by an untrusted party (there: a colliding 4-byte selector; here: a colliding realm string) silently overrides the trusted classification/dispatch logic and hijacks control flow that the user assumes is safe.

## Finding Description
When Git needs credentials for an HTTPS remote, it invokes Desktop's credential helper and forwards any `WWW-Authenticate` response headers as `wwwauth[n]=...` parameters. `getEndpointKind` in `app/src/lib/trampoline/trampoline-credential-helper.ts` uses these attacker/server-supplied values as a "happy path" to decide the endpoint kind before doing any authoritative check: [1](#0-0) 

```
// When Git attempts to authenticate with a host it captures any
// WWW-Authenticate headers and forwards them to the credential helper. We
// use them as a happy-path to determine if the host is a GitHub host without
// having to resort to making a request ourselves.
for (const [k, v] of cred.entries()) {
  if (k.startsWith('wwwauth[')) {
    if (v.includes('realm="GitHub"')) {
      return 'enterprise'
    } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
      return 'generic'
    }
  }
}
```

Any HTTP(S) Git server the user clones/fetches from (or a MITM/misconfigured proxy on the network path to such a server) fully controls its own response headers, so it can trivially return `WWW-Authenticate: Basic realm="GitHub"` regardless of whether it is actually GitHub or GitHub Enterprise. This string match takes precedence over any real host validation (`isDotCom`, `isGHE`) and is checked before the fallback `isGitHubHost(endpoint)` network probe.

Once `getEndpointKind` returns `'enterprise'` for an arbitrary attacker-controlled host, `getCredential` treats it as a first-party GitHub endpoint: [2](#0-1) 

If no existing account matches that exact endpoint, Desktop calls `ui.promptForGitHubSignIn(endpoint)`, which — because the hostname isn't `github.com` — starts the **GitHub Enterprise sign-in flow pointed at the attacker's origin**: [3](#0-2) 

```
const { hostname, origin } = new URL(endpoint)
if (hostname === 'github.com') {
  this.dispatcher.beginDotComSignIn(cb)
} else {
  this.dispatcher.beginEnterpriseSignIn(cb)
  await this.dispatcher.setSignInEndpoint(origin)
}
```

This is exactly the "colliding signature silently overrides trusted dispatch" pattern from the report: the `installPlugin` mapping trusted a caller-supplied selector to decide which code handles a hook; here, `getEndpointKind` trusts a server-supplied string to decide which trust tier (and therefore which authentication UI/flow) handles a host. In both cases, the guard exists (selector uniqueness / endpoint identity) but is bypassable by an attacker who controls the input that feeds the lookup.

## Impact Explanation
- The victim only needs to add/clone/fetch from a Git remote that the attacker controls (or is positioned to intercept, e.g., a plain-HTTP remote or a compromised/malicious proxy) — squarely in the "attacker controls a git remote/proxy response" impact category.
- The spoof causes Desktop to open its GitHub Enterprise sign-in dialog against `origin` (the attacker's own domain) via `setSignInEndpoint`. This begins an OAuth/device-style enterprise authentication sequence the user believes is a legitimate "sign in to GitHub" prompt triggered by Desktop, when it is actually directed at an untrusted server — a credential-phishing/unauthorized-account-binding primitive fully driven by server response content rather than local/physical access or leaked secrets.
- The `SignIn` dialog does display the endpoint (`credentialHelperUrl`) and the existing-account-warning step shows the host, so a careful user could notice the domain is wrong; this reduces exploitability, but a user cloning an unfamiliar/attacker-provided repository URL (e.g. an internal-looking corporate name) has no ground truth to compare against. This is the key nuance limiting severity relative to a full silent takeover.

## Likelihood Explanation
Triggering it only requires the attacker's Git server to add one HTTP header on a 401 response — no local access, no prior malware, no leaked credentials, and no unnatural user action beyond the ordinary "clone/fetch from a repository URL," which is squarely within the accepted attack surface. The check is a plain substring match on a value that originates entirely from the remote server, with no authoritative validation (e.g., checking the actual response against `isDotCom`/`isGHE`/a real GitHub-only response signature) before branching into `enterprise` classification.

## Recommendation
Do not let the `wwwauth[*]` realm string alone elevate an endpoint to `'enterprise'`. Either:
- Restrict the “happy path” shortcut to also require that the URL's hostname independently pass `isGHES`/`isGHE`-style checks, or
- Treat the realm hint only as a soft signal that triggers the authoritative `isGitHubHost(endpoint)` network probe (which does a real capability check against the server) rather than returning `'enterprise'` directly, or
- If the shortcut is kept for performance, gate it behind verifying a genuine GitHub-only response marker (e.g., a real `X-GitHub-Request-Id`/`x-github-enterprise-version` header) instead of a client-supplied realm string that any server can emit.

## Proof of Concept
1. Stand up a plain HTTP(S) git-server (e.g., `git http-backend` behind nginx, or any custom server implementing the smart-HTTP protocol) at `https://internal-tools.example`.
2. Configure it to respond to unauthenticated requests with:
   `WWW-Authenticate: Basic realm="GitHub"`
3. In GitHub Desktop, clone or add an existing repository whose remote is `https://internal-tools.example/foo/bar.git`.
4. Git invokes Desktop's credential helper (`createCredentialHelperTrampolineHandler`), which calls `getCredential` → `getEndpointKind`, which matches the spoofed `realm="GitHub"` and returns `'enterprise'`.
5. Because no account exists for `https://internal-tools.example`, `getCredential` calls `ui.promptForGitHubSignIn('https://internal-tools.example/...')`, which calls `dispatcher.beginEnterpriseSignIn(cb)` and `dispatcher.setSignInEndpoint('https://internal-tools.example')`, opening the enterprise sign-in flow against the attacker's own server instead of failing over to the plain "Authentication Failed" generic credentials dialog (`GenericGitAuthentication`) that would normally be shown for a non-GitHub host. /** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
