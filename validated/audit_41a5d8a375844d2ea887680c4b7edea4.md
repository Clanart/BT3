### Title
Missing deletion of `_requestCommitments` after GET-response fee payout allows duplicate relayer fee claim via a later timeout replay - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatchIncoming(GetResponse, ...)` pays the relayer fee out of `_requestCommitments[commitment].fee` on success, but — unlike the symmetric timeout handlers — never deletes the `_requestCommitments[commitment]` entry afterwards.

### Finding Description
This is a structural analog of the Lido bug: two code paths perform the "same" bookkeeping action (clearing `_requestCommitments[commitment]` as replay/consumption protection for a GET request's fee metadata), but only one of them actually does it.

- `dispatchTimeOut(GetRequestTimeout ...)` explicitly clears the entry before invoking the callback: [1](#0-0) 

- `dispatchTimeOut(PostRequestTimeout ...)` does the same for POST requests: [2](#0-1) 

- But `dispatchIncoming(GetResponse, ...)`, which reads `_requestCommitments[commitment].fee` to pay the relayer, never deletes the entry once the fee has been paid out: [3](#0-2) 

Compare this to `dispatchIncoming(PostRequest, ...)`, whose replay protection is `_requestReceipts[commitment]`, set unconditionally before the external call and only rolled back on failure — a self-consistent single-location update pattern: [4](#0-3) 

The GET-response path is the odd one out: it reads and spends `_requestCommitments[commitment].fee` but leaves the fee metadata (`sender`, `fee`) dangling in storage afterward, exactly like the Lido report's "one function updates the tracked variable, the other doesn't."

`handleGetRequestTimeouts` in `HandlerV2.sol` uses exactly this dangling entry as its authorization check for paying out a timeout refund: [5](#0-4) 

Because `meta.sender` is still non-zero after a successful `GetResponse` delivery, `UnknownMessage()` does not trigger, and the flow proceeds to a non-membership proof check on the `RESPONSE_RECEIPTS_STORAGE_PREFIX` key at the *destination* chain's state root for the specified `message.height`.

### Impact Explanation
If this non-membership proof can be satisfied for a height that predates when the response was actually delivered on the destination (or for any height that legitimately shows no response receipt yet recorded at the destination, e.g. due to state pruning/height selection or destination-chain-specific storage layout mismatches), a relayer/attacker can drive `dispatchTimeOut(GetRequestTimeout, meta, commitment)` and receive `meta.fee` a second time, in addition to the fee already paid via the successful `dispatchIncoming(GetResponse, ...)` call. This is a duplicate/double payment out of the relayer-fee-token balance held by the host — a direct loss-of-funds condition matching the bounty's "double-claim/double-settlement" and "unauthorized transaction" categories.

### Likelihood Explanation
I was not able to fully verify, within the available context, whether the non-membership proof at a chosen `message.height` can actually be constructed/passed for a commitment whose response was already delivered at a later height (this depends on exact trie-key semantics and height-selection validation elsewhere in the handler, which I could not fully trace in the remaining budget). What is concretely and locally provable is the storage-hygiene discrepancy itself: `_requestCommitments[commitment]` is deleted by both timeout paths as a replay guard but is never deleted by the GET-response fee-payout path, leaving `meta.sender != address(0)` as a permanently-true precondition for `handleGetRequestTimeouts` even after the request has already been fully serviced and paid. This is a clear violation of the "one-time receipt handling" invariant Hyperbridge requires for request/response/timeout paths, independent of whatever height-proof strength ultimately gates full exploitability.

### Recommendation
In `EvmHost.dispatchIncoming(GetResponse memory response, address relayer)`, after the fee is successfully transferred to the relayer, delete `_requestCommitments[commitment]` (mirroring the pattern already used in both `dispatchTimeOut` overloads), so that a completed GET response can never again pass the `meta.sender == address(0)` liveness check in `handleGetRequestTimeouts`.

### Proof of Concept
Not independently reproducible from the indexed code alone — full exploitation requires confirming that `handleGetRequestTimeouts`'s non-membership proof against `message.height` can be satisfied at some valid state-machine height after a `GetResponse` has already been delivered for the same commitment (e.g., a height captured before response inclusion, or a chain/height where the response-receipt key is genuinely absent). The concretely demonstrable defect is:
1. Dispatch a `GetRequest` with `fee > 0`, populating `_requestCommitments[commitment]`.
2. Relayer delivers `GetResponse` via `HandlerV2.handleGetResponses` → `EvmHost.dispatchIncoming(GetResponse, relayer)` succeeds, `_responseReceipts[commitment]` is set, fee is paid, but `_requestCommitments[commitment]` remains populated (verifiable directly via `host.requestCommitments(commitment)` returning non-zero `sender`/`fee` post-delivery — this part is fully verifiable from the code shown above).
3. If a relayer can subsequently supply a `PostRequestTimeoutMessage`/`GetTimeoutMessage`-style non-membership proof for `message.height` under `handleGetRequestTimeouts`'s current height-selection rules, `host.dispatchTimeOut(GetRequestTimeout, meta, commitment)` executes and pays `meta.fee` again, since nothing in that path checks `_responseReceipts` before paying the timeout refund.

        address destination = _bytesToAddress(request.to);

        // replay protection

        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)

        if (!success) {
            // so that it can be retried
            delete _requestReceipts[commitment];
            return;
        }
        emit PostRequestHandled({commitment: commitment, relayer: relayer});

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

            // so that it can be retried
            delete _responseReceipts[commitment];
            return;

        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
