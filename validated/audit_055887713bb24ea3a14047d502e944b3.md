### Title
`SchnorrAggregate::read` accepts an empty `Rs` vector, letting a forged `(Rs = [], s = 0)` aggregate verify as valid — (File: crypto/schnorr/src/aggregate.rs)

### Summary
The analog of the Flatcoins issue — a missing empty-array check letting an attacker bypass work the protocol assumed was performed — exists in `crypto/schnorr/src/aggregate.rs`. `SchnorrAggregate::read` accepts a serialized aggregate with `len = 0`, and `SchnorrAggregate::verify` then checks `sum_i z_i*R_i + z_i*c_i*A_i - s*G == 0` over zero statements. With `s = 0` the single remaining term is `0 * G = identity`, so `verify` returns `true`. The honest producer side, `SchnorrAggregator::complete`, explicitly returns `None` when no signatures were aggregated (`crypto/schnorr/src/aggregate.rs:175-178`), so no legitimate empty aggregate can ever be produced — yet the deserializer accepts one and the verifier accepts it. This is a deserialization-produced forgery: an aggregate signature bytes string (`u32(0) || 0-scalar`) that verifies successfully while representing zero real signatures.

### Finding Description
`SchnorrAggregate::read` reads a `u32` count and pushes that many points into `Rs`, with no `len == 0` rejection (`crypto/schnorr/src/aggregate.rs:77-88`). `verify` checks `self.Rs.len() != keys_and_challenges.len()` and otherwise builds the weighted multiexp ending in `(-self.s, C::generator())` (`crypto/schnorr/src/aggregate.rs:127-146`). When both are empty, `multiexp_vartime(&[(0, G)])` is identity and verification succeeds — confirmed by `BatchVerifier`/multiexp semantics where an empty statement is trivially identity (`crypto/multiexp/src/batch.rs:93-95`). Unlike the FROST `sign` path, which rejects undersized/empty signing sets (`crypto/frost/src/sign.rs:297-300`), and unlike `Transaction::read` for `DkgCommitments`/`SignData`, which explicitly reject zero-length collections (`coordinator/src/tributary/transaction.rs:279-281`, `transaction.rs:85-87`), `SchnorrAggregate::read` performs no such check.

### Impact Explanation
An attacker can hand a verifier a byte string that deserializes to an "aggregate signature" nobody ever produced and have `verify` return `true`, provided the caller's `keys_and_challenges` list is empty (i.e., the statement set is derived from or matched against the supplied aggregate — precisely the shape where this class bites: "zero items claimed, zero checks performed"). This is a forged signature at the verification layer and mirrors the Flatcoins bug: the empty-input case silently vacuous-satisfies a check that was assumed to cost real work.

### Likelihood Explanation
Requires an integrator that calls `SchnorrAggregate::verify` with a `keys_and_challenges` slice that can be empty when the attacker controls it (e.g., a batch whose entries are all filtered/rejected upstream but verification still runs). Within this repository the aggregate is only exercised in tests, so in-tree reachability is low; as a published `verify`/`read` API in `crypto/schnorr` the flaw is concrete and matches the "untrusted bytes fed to a verify API" criterion.

### Recommendation
Mirror the fix applied in `coordinator/src/tributary/transaction.rs` and `complete`: reject `len == 0` in `SchnorrAggregate::read` (`aggregate.rs:78-85`), and/or return `false` early in `verify` when `Rs` is empty, so the verifier can never accept an aggregate that `SchnorrAggregator::complete` refuses to emit.

```rust
// In SchnorrAggregate::read, after reading `len`:
if u32::from_le_bytes(len) == 0 {
  Err(io::Error::other("SchnorrAggregate with zero signatures"))?;
}
```

### Proof of Concept
```rust
// 4-byte little-endian 0 (zero Rs) followed by a zero scalar encoding
let mut bytes = vec![0, 0, 0, 0];
bytes.extend(C::F::ZERO.to_repr());
let agg = SchnorrAggregate::<C>::read(&mut bytes.as_slice()).unwrap();
// Vacuously verifies despite no signature ever being aggregated
assert!(agg.verify(b"some_dst", &[]));
```
Root cause: `read` (`aggregate.rs:77-88`) lacks the empty-check that `complete` (`aggregate.rs:175-178`) enforces on the production side, and `verify` (`aggregate.rs:138-145`) reduces to `-0 * G == identity` for the empty case.
