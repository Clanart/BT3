### Title
`Encryption::decrypt` emits the ECDH decryption key (blame proof) before the message's proof-of-possession is verified, letting a DKG sender recover the shared key for another participant's encrypted share — (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary

The FreeRDP bug class — *output written / side effect committed before the bounds/validity check* — maps directly onto `KeyMachine::calculate_share` in PedPoP. The per-message proof of possession (`pop`) is only **queued** into a `BatchVerifier`, but the ECDH key that decrypts the message is computed, returned inside an `EncryptionKeyProof`, and exposed in the `PedPoPError::InvalidShare` blame value **before** `batch.verify_with_vartime_blame()` ever runs — and in the `from_repr` failure path, *never* runs at all for that message. A sender can therefore replay another participant's encryption key to extract the shared ECDH key, exactly the attack the in-code comment says the PoP exists to prevent.

### Finding Description

In `Encryption::decrypt` the Schnorr PoP over `(context, R, msg.key, sender, msg)` is scheduled for batch verification, yet the function unconditionally performs ECDH and returns `EncryptionKeyProof { key: ecdh(enc_key, msg.key), dleq }`: [1](#0-0) 

In `KeyMachine::calculate_share`, if the decrypted bytes fail `C::F::from_repr`, the function returns early with `blame: Some(blame)` — the ECDH key — while the PoP verification remains an unexecuted queue entry: [2](#0-1) 

The file itself documents why this ordering is unsafe: [3](#0-2) 

`msg.key` is attacker-controlled bytes read via `EncryptedMessage::read` → `C::read_G` (`encryption.rs:171-177`). An attacker who observes victim Alice's `EncryptedMessage` to Bob can send Bob a message with `key` copied from Alice's message and garbage ciphertext. Bob's `decrypt` derives `key = enc_key_bob * msg.key` — identical to the shared key protecting Alice's real secret share — and hands it out inside the `InvalidShare` error's blame proof. Since the PoP was never verified (early `?` return at `lib.rs:481`), the key-reuse defense is bypassed.

### Impact Explanation

Whoever observes the blame proof (which is designed to be published for attribution, and is verified publicly by `Decryption::decrypt_with_proof` / `BlameMachine::blame`) obtains `proof.key`, reconstructs the ChaCha20 keystream via `cipher(context, &proof.key)`, and decrypts Alice's legitimate secret share to Bob. That is recovery of another participant's threshold key share — secret leakage reducing the effective security of the generated `ThresholdKeys`. This matches the "key share recovery" acceptance criterion.

### Likelihood Explanation

Requires the attacker to be a DKG participant sending one malformed `EncryptedMessage` to a victim who runs `calculate_share`, plus visibility of the resulting blame proof — the standard blame-propagation path this protocol is built around. Note the mitigating factor: this requires a malicious DKG participant and an authenticated channel for share delivery, which the threat model partially assumes. If malicious participants are out of scope per the engagement rules, this analog does not qualify; it is presented because `calculate_share`/`EncryptedMessage::read` are explicitly listed as reachable surfaces and the side effect genuinely occurs before validation.

### Recommendation

Do not construct or return `EncryptionKeyProof` until the PoP has actually verified. Either verify `msg.pop` synchronously inside `decrypt` before deriving/returning `key`, or split `decrypt` into a phase that queues the PoP and a phase that yields the proof only after `batch.verify_with_vartime_blame()` succeeds for `BatchId::Decryption(l)`.

### Proof of Concept

```rust
// Alice sends Bob a valid EncryptedMessage (key = A_key, ciphertext over share).
// Attacker Mallory (also a DKG participant) builds:
//   msg.key   = A_key                  // copied, replayed key
//   msg.pop   = any SchnorrSignature   // will fail — but is only batch-queued
//   msg.msg   = SecretShare with repr bytes that fail C::F::from_repr
// Bob runs calculate_share({Mallory: forged_msg, ...}):
//   - decrypt() queues pop verification, computes key = enc_key_bob * A_key,
//     returns EncryptionKeyProof { key, dleq }
//   - C::F::from_repr fails -> Err(InvalidShare { blame: Some(proof) })
//   - batch.verify_with_vartime_blame() is never reached for this message
// proof.key == shared key for Alice's ciphertext -> decrypt Alice's share to Bob.
```
