### Title
Native tokens sent as `msg.value` to non-payable staking/distribution/gov precompile methods are permanently locked at the precompile address - (File: precompiles/staking/staking.go, precompiles/common/precompile.go)

### Summary
This is the Cosmos EVM analog of the Tapioca `_payNative()` bug: a function that is supposed to fully account for/return `msg.value` instead only processes a separately-specified `amount` parameter, leaving any native value attached to the call unaccounted for and trapped. In Cosmos EVM, the stateful precompiles (`staking`, `distribution`, `gov`, `slashing`, etc.) expose Solidity interfaces such as `StakingI.delegate(address, string, uint256 amount)` that are declared **non-payable** at the Solidity interface level [1](#0-0) . The actual value moved is driven entirely by the `amount` argument, which is converted into a `MsgDelegate`/`MsgFundCommunityPool`/etc. and settled through the bank keeper [2](#0-1) [3](#0-2) .

### Finding Description
The Solidity-level `payable`/non-payable modifier is a compile-time convenience only; it is not enforced by the EVM itself. A caller can bypass the high-level interface and issue a raw low-level `call{value: X}(abi.encodeWithSignature("delegate(...)"))` directly to the precompile address (`0x...800`), or construct an EVM transaction with non-zero `value` targeting the precompile. Go-ethereum's call semantics move `value` from the caller to the callee's account balance (via `StateDB.SubBalance`/`AddBalance`) **before** the precompiled contract's `Run()` is invoked, exactly as with any regular contract call.

Once inside `Run()`, execution goes through `RunNativeAction`/`runNativeAction` in the common precompile helper [4](#0-3) , and then to method dispatch, e.g. `Precompile.Execute` for staking [5](#0-4) . None of the transaction handlers (`Delegate`, `Undelegate`, `Redelegate`, `EditValidator`, `CancelUnbondingDelegation`, distribution methods, etc.) read or validate `contract.Value()`/`msg.value` — they only use the caller-supplied `amount` argument to build the underlying `Msg*` and execute it via the module's `MsgServer`. The `BalanceHandler.AfterBalanceChange` mechanism that reconciles StateDB balances after a precompile call only replays `bank` module `EventTypeCoinSpent`/`EventTypeCoinReceived` events emitted by the keeper-level operations actually performed by the precompile logic [6](#0-5) ; it does not know about, or reverse, the EVM-level value transfer to the precompile's own address that occurred prior to `Run()`, because that transfer never touched the bank keeper and therefore never emitted a bank event.

Consequently, any native `aatom`/base-denom tokens attached as `msg.value` to a call targeting a stateful precompile address end up permanently credited to that fixed precompile address in the unified EVM/bank balance store, with no code path in any precompile (`staking`, `distribution`, `gov`, `slashing`) that spends from, or refunds, its own address balance. Since precompile addresses are not EOAs and have no owning private key, and no precompile handler performs a `SendCoins` from itself, the funds become irrecoverably locked — mirroring the exact "additional `msg.value` beyond the accounted fee gets trapped in the contract" pattern in the Tapioca finding.

### Impact Explanation
This matches the Critical Impact Gate for "permanent freezing, locking, theft, or unauthorized extraction of user funds" — an unprivileged user (or a user tricked by a malicious frontend/dApp) who sends value directly to a precompile call loses those funds permanently with no recovery mechanism. Because it's the native staking/gov/distribution denomination (the chain's base coin), this is not an isolated corner case but a systemic risk touching multiple precompiles that share the same `RunNativeAction`/`BalanceHandler` pattern.

### Likelihood Explanation
Likelihood is constrained by the fact that ordinary Solidity contracts using the official `StakingI`/`DistributionI` interfaces cannot attach value to these non-payable functions (the Solidity compiler will reject `{value: x}()` on a non-payable declared function at the interface-call level). Triggering the bug requires either (a) hand-crafted raw EVM calldata/value transactions bypassing the Solidity type system, or (b) a malicious/buggy integrating contract using low-level `call`. This makes exploitation plausible for sophisticated or malicious actors and for accidental user error (e.g., a wallet incorrectly populating `value` alongside calldata), but it is not triggerable purely through the "intended" high-level Solidity interface.

### Recommendation
Add an explicit `contract.Value()`/`msg.value` guard at the top of `RunNativeAction`/each precompile's `Execute` (or centrally in `precompile.go`) that reverts any transaction carrying non-zero value for methods that do not explicitly declare a use for it, similar to how the ERC20 precompile documents "Prevents receiving funds directly to the precompile address" as a security control [7](#0-6) . Where value-taking behavior is intended, funds should be fully applied to the operation and any excess above the intended `amount` refunded to the caller within the same call, or the check should require `msg.value == 0` for non-payable precompile methods.

### Proof of Concept
Conceptual PoC (not executed — I could not run a live chain in this environment):
1. Deploy or use an account capable of issuing a raw low-level call, e.g. a helper contract:
   ```solidity
   (bool ok, ) = STAKING_PRECOMPILE.call{value: 1 ether}(
       abi.encodeWithSignature(
           "delegate(address,string,uint256)",
           msg.sender, validatorAddr, 1 ether
       )
   );
   ```
2. Observe that the `MsgDelegate` executes for `1 ether` worth of the bond denom debited from `msg.sender`'s bank balance via `stakingMsgServer.Delegate` [8](#0-7) , while **separately** the EVM call also transferred `1 ether` of native value from `msg.sender` to the staking precompile address `0x...800` as part of the CALL opcode's value-transfer semantics.
3. Query the bank balance of `0x0000000000000000000000000000000000000800` after the call — it will show a nonzero, ever-growing balance that is never spent by any staking/distribution/gov/slashing precompile handler, since none of them consume `contract.Value()`.

I was not able to directly execute/verify this end-to-end (e.g., confirm the exact EVM value-transfer wiring in `x/vm` for precompile calls, or find an explicit non-payable enforcement check in `SetupABI`) within the available indexed code; the `SetupABI` function body itself was not returned by search. I recommend a background Devin session with full repository/build access to (a) inspect `precompiles/common/precompile.go`'s `SetupABI` and the `x/vm` `Call`/`vm.EVM` value-transfer path to confirm whether any check already rejects value sent to non-payable precompile methods, and (b) write an integration test sending non-zero `value` directly to the staking precompile to confirm whether funds become stranded, before treating this as a confirmed, unmitigated Critical finding.

func NewMsgDelegate(args []interface{}, denom string, addrCdc address.Codec) (*stakingtypes.MsgDelegate, common.Address, error) {
	delegatorAddr, validatorAddress, amount, err := checkDelegationUndelegationArgs(args)

		return nil, common.Address{}, err
	}

		return nil, common.Address{}, fmt.Errorf("failed to decode delegator address: %w", err)
	}
	msg := &stakingtypes.MsgDelegate{
		DelegatorAddress: delegatorAddrStr,
		ValidatorAddress: validatorAddress,
		Amount: sdk.Coin{
			Denom:  denom,
			Amount: math.NewIntFromBigInt(amount),
		},
	}

	return msg, delegatorAddr, nil
}

// Delegate performs a delegation of coins from a delegator to a validator.
func (p *Precompile) Delegate(
	ctx sdk.Context,
	contract *vm.Contract,
	stateDB vm.StateDB,
	method *abi.Method,
	args []interface{},
) ([]byte, error) {
	bondDenom, err := p.stakingKeeper.BondDenom(ctx)
	if err != nil {
		return nil, err
	}
	msg, delegatorHexAddr, err := NewMsgDelegate(args, bondDenom, p.addrCdc)
	if err != nil {
		return nil, err
	}

	p.Logger(ctx).Debug(
		"tx called",
		"method", method.Name,
		"args", fmt.Sprintf(
			"{ delegator_address: %s, validator_address: %s, amount: %s }",
			delegatorHexAddr,
			msg.ValidatorAddress,
			msg.Amount.Amount,
		),
	)

	msgSender := contract.Caller()
	if msgSender != delegatorHexAddr {
		return nil, fmt.Errorf(cmn.ErrRequesterIsNotMsgSender, msgSender.String(), delegatorHexAddr.String())
	}

	// Execute the transaction using the message server
	if _, err = p.stakingMsgServer.Delegate(ctx, msg); err != nil {
		return nil, err
	}

	// Emit the event for the delegate transaction
	if err = p.EmitDelegateEvent(ctx, stateDB, msg, delegatorHexAddr); err != nil {
		return nil, err
	}

	return method.Outputs.Pack(true)
}

// Run prepare the native context to execute native action for stateful precompile,
// it manages the snapshot and revert of the multi-store.
func (p Precompile) RunNativeAction(evm *vm.EVM, contract *vm.Contract, action NativeAction) ([]byte, error) {
	bz, err := p.runNativeAction(evm, contract, action)
	if err != nil {
		return ReturnRevertError(evm, err)
	}

	return bz, nil
}

func (p Precompile) runNativeAction(evm *vm.EVM, contract *vm.Contract, action NativeAction) (bz []byte, err error) {
	stateDB, ok := evm.StateDB.(*statedb.StateDB)
	if !ok {
		return nil, errors.New(ErrNotRunInEvm)
	}

	// get the stateDB cache ctx
	ctx, err := stateDB.GetCacheContext()
	if err != nil {
		return nil, err
	}

	// take a snapshot of the current state before any changes
	// to be able to revert the changes
	snapshot := stateDB.MultiStoreSnapshot()
	events := ctx.EventManager().Events()

	// add precompileCall entry on the stateDB journal
	// this allows to revert the changes within an evm tx
	if err := stateDB.AddPrecompileFn(snapshot, events); err != nil {
		return nil, err
	}

	// commit the current changes in the cache ctx
	// to get the updated state for the precompile call
	if err := stateDB.CommitWithCacheCtx(); err != nil {
		return nil, err
	}

	initialGas := ctx.GasMeter().GasConsumed()

	defer HandleGasError(ctx, contract, initialGas, &err)()

	// set the default SDK gas configuration to track gas usage
	// we are changing the gas meter type, so it panics gracefully when out of gas
	ctx = ctx.WithGasMeter(storetypes.NewGasMeter(contract.Gas)).
		WithKVGasConfig(p.KvGasConfig).
		WithTransientKVGasConfig(p.TransientKVGasConfig)

	// we need to consume the gas that was already used by the EVM
	ctx.GasMeter().ConsumeGas(initialGas, "creating a new gas meter")

	var balanceHandler *BalanceHandler
	if p.BalanceHandlerFactory != nil {
		balanceHandler = p.BalanceHandlerFactory.NewBalanceHandler()
	}

	if balanceHandler != nil {
		balanceHandler.BeforeBalanceChange(ctx)
	}

	bz, err = action(ctx)
	if err != nil {
		return bz, err
	}

	cost := ctx.GasMeter().GasConsumed() - initialGas

	if !contract.UseGas(cost, nil, tracing.GasChangeCallPrecompiledContract) {
		return nil, vm.ErrOutOfGas
	}

	if balanceHandler != nil {
		if err := balanceHandler.AfterBalanceChange(ctx, stateDB); err != nil {
			return nil, err
		}
	}

	return bz, nil
}

func (p Precompile) Execute(ctx sdk.Context, stateDB vm.StateDB, contract *vm.Contract, readOnly bool) ([]byte, error) {
	method, args, err := cmn.SetupABI(p.ABI, contract, readOnly, p.IsTransaction)
	if err != nil {
		return nil, err
	}

	var bz []byte

	switch method.Name {
	// Staking transactions
	case CreateValidatorMethod:
		bz, err = p.CreateValidator(ctx, contract, stateDB, method, args)
	case EditValidatorMethod:
		bz, err = p.EditValidator(ctx, contract, stateDB, method, args)
	case DelegateMethod:
		bz, err = p.Delegate(ctx, contract, stateDB, method, args)
	case UndelegateMethod:
		bz, err = p.Undelegate(ctx, contract, stateDB, method, args)
	case RedelegateMethod:
		bz, err = p.Redelegate(ctx, contract, stateDB, method, args)
	case CancelUnbondingDelegationMethod:
		bz, err = p.CancelUnbondingDelegation(ctx, contract, stateDB, method, args)
	// Staking queries
	case DelegationMethod:
		bz, err = p.Delegation(ctx, contract, method, args)
	case UnbondingDelegationMethod:
		bz, err = p.UnbondingDelegation(ctx, contract, method, args)
	case ValidatorMethod:
		bz, err = p.Validator(ctx, method, contract, args)
	case ValidatorsMethod:
		bz, err = p.Validators(ctx, method, contract, args)
	case RedelegationMethod:
		bz, err = p.Redelegation(ctx, method, contract, args)
	case RedelegationsMethod:
		bz, err = p.Redelegations(ctx, method, contract, args)
	default:
		return nil, fmt.Errorf(cmn.ErrUnknownMethod, method.Name)
	}

	return bz, err
}

// AfterBalanceChange processes the recorded events and updates the stateDB accordingly.
// It handles the bank events for coin spent and coin received, updating the balances
// of the spender and receiver addresses respectively.
//
// NOTES: Balance change events involving BlockedAddresses are bypassed.
// Native balances are handled separately to prevent cases where a bank coin transfer
// initiated by a precompile is unintentionally overwritten by balance changes from within a contract.

// Typically, accounts registered as BlockedAddresses in app.go—such as module accounts—are not expected to receive coins.
// However, in modules like precisebank, it is common to borrow and repay integer balances
// from the module account to support fractional balance handling.
//
// As a result, even if a module account is marked as a BlockedAddress, a keeper-level SendCoins operation
// can emit an x/bank event in which the module account appears as a spender or receiver.
// If such events are parsed and used to invoke StateDB.AddBalance or StateDB.SubBalance, authorization errors can occur.
//
// To prevent this, balance changes from events involving blocked addresses are not applied to the StateDB.
// Instead, the state changes resulting from the precompile call are applied directly via the MultiStore.
func (bh *BalanceHandler) AfterBalanceChange(ctx sdk.Context, stateDB *statedb.StateDB) error {
	events := ctx.EventManager().Events()

	for _, event := range events[bh.prevEventsLen:] {
		switch event.Type {
		case banktypes.EventTypeCoinSpent:
			spenderAddr, err := ParseAddress(event, banktypes.AttributeKeySpender)
			if err != nil {
				return fmt.Errorf("failed to parse spender address from event %q: %w", banktypes.EventTypeCoinSpent, err)
			}
			if bh.bankKeeper.BlockedAddr(spenderAddr) {
				// Bypass blocked addresses
				continue
			}

			amount, err := ParseAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", banktypes.EventTypeCoinSpent, err)
			}

			stateDB.SubBalance(common.BytesToAddress(spenderAddr.Bytes()), amount, tracing.BalanceChangeUnspecified)

		case banktypes.EventTypeCoinReceived:
			receiverAddr, err := ParseAddress(event, banktypes.AttributeKeyReceiver)
			if err != nil {
				return fmt.Errorf("failed to parse receiver address from event %q: %w", banktypes.EventTypeCoinReceived, err)
			}
			if bh.bankKeeper.BlockedAddr(receiverAddr) {
				// Bypass blocked addresses
				continue
			}

			amount, err := ParseAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", banktypes.EventTypeCoinReceived, err)
			}

			stateDB.AddBalance(common.BytesToAddress(receiverAddr.Bytes()), amount, tracing.BalanceChangeUnspecified)
