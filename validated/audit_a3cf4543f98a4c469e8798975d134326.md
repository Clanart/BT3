### Title
Unchecked Bitcoin value arithmetic panics on untrusted transaction inputs - ([File: networks/bitcoin/src/wallet/send.rs](networks/bitcoin/src/wallet/send.rs))

### Summary

`SignableTransaction::new` performs unchecked `u64` summation, multiplication, and addition while preparing a transaction. The workspace enables `overflow-checks` even in release builds, so overflowing values panic instead of wrapping. [1](#0-0) 

### Finding Description

The constructor accepts caller-controlled `ReceivedOutput` values, payment amounts, and a fee rate. [2](#0-1)  `ReceivedOutput::read` accepts serialized outputs containing arbitrary consensus-encoded `TxOut` values without validating them against actual UTXOs. [3](#0-2) 

It then directly sums input values and payment values into `u64`. [4](#0-3)  The fee calculation also multiplies `fee_per_vbyte` by `vbytes` without checked arithmetic, and later adds the resulting fee to the payment sum. [5](#0-4)  The change path repeats the unchecked addition inside `checked_sub`, meaning the addition itself can panic before the checked subtraction runs. [6](#0-5) 

### Impact Explanation

An attacker who can provide serialized `ReceivedOutput` data, payment instructions, or an attacker-influenced fee rate can panic transaction construction. This prevents the wallet/FROST signing flow from preparing or signing the transaction, analogous to the original report’s rebalance denial of service.

### Likelihood Explanation

The vulnerable values are public API inputs, and `ReceivedOutput::read` explicitly accepts externally serialized transaction data. [3](#0-2)  Two serialized outputs whose values sum beyond `u64::MAX`, payment amounts whose sum exceeds `u64::MAX`, or a sufficiently large `fee_per_vbyte` all reach the unchecked arithmetic directly.

### Recommendation

Use checked arithmetic for every amount calculation. `input_sat`, `payment_sat`, `needed_fee`, `payment_sat + needed_fee`, and `payment_sat + fee_with_change` should use `checked_add`, `checked_mul`, or widened integer arithmetic and return a `TransactionError` instead of panicking.

### Proof of Concept

```rust
// Conceptually construct two untrusted ReceivedOutput values whose TxOut values
// are both u64::MAX using ReceivedOutput::read.

let mut encoded = Vec::new();
encoded.extend(Scalar::ZERO.to_bytes());
encoded.extend(bitcoin::consensus::encode::serialize(&TxOut {
  value: Amount::from_sat(u64::MAX),
  script_pubkey: ScriptBuf::new(),
}));
encoded.extend(bitcoin::consensus::encode::serialize(&OutPoint::default()));

let input1 = ReceivedOutput::read(&mut encoded.as_slice()).unwrap();
let input2 = ReceivedOutput::read(&mut encoded.as_slice()).unwrap();

let payments = [(ScriptBuf::new(), 546)];

// Panics while summing input values: u64::MAX + u64::MAX.
let _ = SignableTransaction::new(
  vec![input1, input2],
  &payments,
  None,
  None,
  1,
);
```

The panic occurs at the unchecked input summation before transaction construction reaches the insufficient-funds or transaction-size checks. [7](#0-6)
