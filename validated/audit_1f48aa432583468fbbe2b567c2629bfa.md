### Title
Undelegate lacks a `CanSendTo`/`BlockedAddr` recipient check, permanently orphaning matured unbonding funds if the delegator address later becomes unpayable - (File: `sei-cosmos/x/staking/keeper/delegation.go`)

### Summary
`x/staking/keeper.Undelegate` queues an unbonding entry for whatever `delAddr` initiated the undelegation, with no check that this address will still be able to receive a bank transfer when the entry matures. `CompleteUnbonding`, run from `BlockValidatorUpdates` in `EndBlock`, silently `continue`s past a failed payout, but the maturity timeslice has already been dequeued and deleted by `DequeueAllMatureUBDQueue` before `CompleteUnbonding` runs, so a failed payout is never retried. This is the same class of bug as the reported "insufficient checks during request settlement": checks are only performed when the request is *created*, not when it is *settled*.

### Finding Description
`Undelegate` (`sei-cosmos/x/staking/keeper/delegation.go:831-858`) validates the validator exists and that max-entries limits aren't exceeded, then unconditionally inserts the unbonding delegation and its queue entry: [1](#0-0) 

It never calls `BankKeeper.CanSendTo` or `BankKeeper.BlockedAddr` on `delAddr`, unlike the analogous distribution-module fix that explicitly gates `SetWithdrawAddr` with both checks specifically to avoid a later panic/失败 in `EndBlock`: [2](#0-1) 

At maturity, `BlockValidatorUpdates` first dequeues the mature `(delegator, validator)` pairs from the time-indexed queue (deleting the queue entries), and only afterward calls `CompleteUnbonding`, which performs the actual bank transfer. If that transfer errors, the loop simply `continue`s: [3](#0-2) 

`CompleteUnbonding` itself removes the matured `Entries` from the `UnbondingDelegation` object and only performs the bank send inside that loop; if `UndelegateCoinsFromModuleToAccount` fails, it returns an error without persisting/removing the entry, but since the enclosing `BlockValidatorUpdates` loop already deleted the corresponding queue timeslice key before calling `CompleteUnbonding`, the entry is never re-scheduled: [4](#0-3) 

This exact behavior — queue entry retained in `UnbondingDelegation` store but removed from the time-queue, funds never returned, no panic — is directly confirmed by the existing regression test: [5](#0-4) 

The trigger condition is `BankKeeper.CanSendTo` returning `false` for the delegator address. This check fails for a "cast address" (an `sdk.AccAddress` literally built from an EVM address's 20 bytes with no corresponding association) once that Sei/EVM pair becomes associated via `SetAddressMapping` — an operation any user can invoke themselves through a standard Associate transaction in the EVM ante pipeline. This is demonstrated directly: [6](#0-5) 

An unprivileged user can (1) delegate/undelegate using their unassociated cast address as `delAddr`, receiving a valid pending `UnbondingDelegation` entry and queue insertion, and then (2) submit a self-service Associate transaction for that same address before the unbonding matures. From that point on, native transfers to the cast address are rejected, `CompleteUnbonding` fails on `EndBlock`, and — because the time-queue entry was already deleted before the failing call — the funds are permanently stuck: the `UnbondingDelegation` record remains in state, referencing tokens locked in the `NotBondedPool`, with no remaining queue reference and no user-facing retry/claim path in the reachable staking module.

### Impact Explanation
This results in permanent freezing of user funds reachable purely through normal, unprivileged user transactions (staking `Undelegate` + EVM `Associate`), matching the "permanent freezing" impact bar. The funds are not lost from the supply (they remain in the `NotBondedPool` module account), but they become permanently unclaimable by the delegator through any standard staking flow, since the maturity-queue bookkeeping that would trigger a retry has already been destroyed by the time the failure is detected.

### Likelihood Explanation
Likelihood is high for any user who delegates from a not-yet-associated EVM-derived (cast) address and later associates that address — a common and encouraged workflow on Sei (associating addresses to unlock full EVM functionality). No validator or admin collusion is required; only the delegator's own two ordinary transactions (`Undelegate`, then `Associate`) are needed, executed in either order relative to each other as long as association happens before the unbonding period elapses.

### Recommendation
- **Short-term:** Add a `CanSendTo`/`BlockedAddr` check on `delAddr` in `Undelegate` (and equivalently in `BeginRedelegation`/wherever a payout address is captured) mirroring the guard added in `x/distribution/keeper.SetWithdrawAddr`, to reject undelegation requests whose payout target cannot currently receive funds. Additionally, harden `BlockValidatorUpdates`/`CompleteUnbonding` so that a failed payout re-inserts the queue entry (or otherwise keeps it retryable) instead of silently dropping the time-slice reference, and/or expose an explicit user-triggered "claim/retry unbonding" endpoint for stranded entries.
- **Long-term:** Audit all settlement paths that consume a time-indexed queue (unbonding delegations, redelegations, any deferred payout) for the same create-time-check/settle-time-no-recheck asymmetry, and add unit tests (in addition to the existing `TestEndBlockRetainsUnbondingForInvalidRecipient`, which only proves no-panic, not recoverability) asserting that funds can eventually be recovered after a recipient becomes payable again.

### Proof of Concept
1. Attacker/user controls Sei address `A = castAddr(evmAddr)` where `evmAddr` has no association yet (`CanSendTo(A) == true`).
2. User delegates tokens to a validator from `A`, then calls `Undelegate(A, validator, shares)`. This succeeds and inserts an `UnbondingDelegation` entry plus a UBD queue entry with completion time `T`.
3. Before `T`, the user submits a self-service `Associate` EVM transaction binding `A`'s underlying EVM address to a real Sei signer key (`SetAddressMapping`). After this, `BankKeeper.CanSendTo(A) == false` (as shown by `TestSendingToCastAddress`).
4. At block time ≥ `T`, `EndBlock` → `BlockValidatorUpdates` dequeues the mature `(A, validator)` pair (deleting the queue timeslice) and calls `CompleteUnbonding(A, validator)`, which fails at `UndelegateCoinsFromModuleToAccount` and returns an error; the outer loop `continue`s.
5. Result (confirmed by `TestEndBlockRetainsUnbondingForInvalidRecipient`): the `UnbondingDelegation` record for `A` still exists in state, the queue no longer references it, and the tokens remain stuck in the `NotBondedPool`, unreachable by any subsequent standard staking action.

func (k Keeper) Undelegate(
	ctx sdk.Context, delAddr sdk.AccAddress, valAddr sdk.ValAddress, sharesAmount sdk.Dec,
) (time.Time, error) {
	validator, found := k.GetValidator(ctx, valAddr)
	if !found {
		return time.Time{}, types.ErrNoDelegatorForAddress
	}

	if k.HasMaxUnbondingDelegationEntries(ctx, delAddr, valAddr) {
		return time.Time{}, types.ErrMaxUnbondingDelegationEntries
	}

	returnAmount, err := k.Unbond(ctx, delAddr, valAddr, sharesAmount)
	if err != nil {
		return time.Time{}, err
	}

	// transfer the validator tokens to the not bonded pool
	if validator.IsBonded() {
		k.bondedTokensToNotBonded(ctx, returnAmount)
	}

	completionTime := ctx.BlockHeader().Time.Add(k.UnbondingTime(ctx))
	ubd := k.SetUnbondingDelegationEntry(ctx, delAddr, valAddr, ctx.BlockHeight(), completionTime, returnAmount)
	k.InsertUBDQueue(ctx, ubd, completionTime)

	return completionTime, nil
}

// CompleteUnbonding completes the unbonding of all mature entries in the
// retrieved unbonding delegation object and returns the total unbonding balance
// or an error upon failure.
func (k Keeper) CompleteUnbonding(ctx sdk.Context, delAddr sdk.AccAddress, valAddr sdk.ValAddress) (sdk.Coins, error) {
	ubd, found := k.GetUnbondingDelegation(ctx, delAddr, valAddr)
	if !found {
		return nil, types.ErrNoUnbondingDelegation
	}

	bondDenom := k.GetParams(ctx).BondDenom
	balances := sdk.NewCoins()
	ctxTime := ctx.BlockHeader().Time

	delegatorAddress, err := sdk.AccAddressFromBech32(ubd.DelegatorAddress)
	if err != nil {
		return nil, err
	}

	// loop through all the entries and complete unbonding mature entries
	for i := 0; i < len(ubd.Entries); i++ {
		entry := ubd.Entries[i]
		if entry.IsMature(ctxTime) {
			ubd.RemoveEntry(int64(i))
			i--

			// track undelegation only when remaining or truncated shares are non-zero
			if !entry.Balance.IsZero() {
				amt := sdk.NewCoin(bondDenom, entry.Balance)
				if err := k.bankKeeper.UndelegateCoinsFromModuleToAccount(
					ctx, types.NotBondedPoolName, delegatorAddress, sdk.NewCoins(amt),
				); err != nil {
					return nil, err
				}

				balances = balances.Add(amt)
			}
		}
	}

	// set the unbonding delegation or remove it if there are no more entries
	if len(ubd.Entries) == 0 {
		k.RemoveUnbondingDelegation(ctx, ubd)
	} else {
		k.SetUnbondingDelegation(ctx, ubd)
	}

	return balances, nil
}

// SetWithdrawAddr sets a new address that will receive the rewards upon withdrawal
func (k Keeper) SetWithdrawAddr(ctx sdk.Context, delegatorAddr sdk.AccAddress, withdrawAddr sdk.AccAddress) error {
	// Reject any address the bank keeper would block from receiving funds, not just
	// the module-account blocklist: BlockedAddr also covers dynamically-derived
	// addresses such as the EVM coinbase addresses. Rejecting them here prevents a
	// delegator from parking an unpayable withdraw address that would later make the
	// force-withdraw in AfterValidatorRemoved panic during EndBlock.
	if k.blockedAddrs[withdrawAddr.String()] || k.bankKeeper.BlockedAddr(withdrawAddr) {
		return sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive external funds", withdrawAddr)
	}

	if !k.GetWithdrawAddrEnabled(ctx) {
		return types.ErrSetWithdrawAddrDisabled
	}

	if !k.bankKeeper.CanSendTo(ctx, withdrawAddr) {
		return sdkerrors.Wrapf(sdkerrors.ErrInvalidRecipient, "%s is not allowed to receive external funds", withdrawAddr)
	}

	ctx.EventManager().EmitEvent(
		sdk.NewEvent(
			types.EventTypeSetWithdrawAddress,
			sdk.NewAttribute(types.AttributeKeyWithdrawAddress, withdrawAddr.String()),
		),
	)

	k.SetDelegatorWithdrawAddr(ctx, delegatorAddr, withdrawAddr)
	return nil
}

func (k Keeper) canReceiveWithdrawAddr(ctx sdk.Context, withdrawAddr sdk.AccAddress) bool {
	// BlockedAddr mirrors the gate SendCoinsFromModuleToAccount actually enforces:
	// beyond the module-account blocklist it also rejects dynamically-derived
	// addresses such as the EVM coinbase addresses (an "evm_coinbase"-prefixed
	// address), which CanSendTo does not catch. Consulting it here keeps this
	// predicate in lockstep with the send, so AfterValidatorRemoved never concludes
	// an address is receivable and then panics on the resulting bank error.
	return !k.blockedAddrs[withdrawAddr.String()] &&
		!k.bankKeeper.BlockedAddr(withdrawAddr) &&
		k.bankKeeper.CanSendTo(ctx, withdrawAddr)
}

func TestEndBlockRetainsUnbondingForInvalidRecipient(t *testing.T) {
	_, app, ctx := createTestInput(t)
	maturity := time.Unix(1, 0).UTC()
	ctx = ctx.WithBlockTime(maturity)
	evmAddr := common.HexToAddress("0x3333333333333333333333333333333333333333")
	delegator := sdk.AccAddress(evmAddr[:])
	app.EvmKeeper.SetAddressMapping(ctx, delegator, evmAddr)
	app.EvmKeeper.SetAddressMapping(
		ctx,
		sdk.AccAddress(common.HexToAddress("0x4444444444444444444444444444444444444444").Bytes()),
		evmAddr,
	)
	validator := sdk.ValAddress(seiapp.AddTestAddrsIncremental(app, ctx, 1, sdk.NewInt(10000))[0])
	amount := sdk.NewInt(40)
	bondDenom := app.StakingKeeper.BondDenom(ctx)
	notBondedPool := app.StakingKeeper.GetNotBondedPool(ctx)
	coins := sdk.NewCoins(sdk.NewCoin(bondDenom, amount))

	require.NoError(t, apptesting.FundModuleAccount(
		app.BankKeeper,
		ctx,
		notBondedPool.GetName(),
		coins,
	))

	unbonding := types.NewUnbondingDelegation(delegator, validator, 0, maturity, amount)
	app.StakingKeeper.SetUnbondingDelegation(ctx, unbonding)
	app.StakingKeeper.InsertUBDQueue(ctx, unbonding, maturity)
	require.False(t, app.BankKeeper.CanSendTo(ctx, delegator))

	poolBalanceBefore := app.BankKeeper.GetBalance(ctx, notBondedPool.GetAddress(), bondDenom)
	require.NotPanics(t, func() {
		staking.EndBlocker(ctx, app.StakingKeeper)
	})

	poolBalanceAfter := app.BankKeeper.GetBalance(ctx, notBondedPool.GetAddress(), bondDenom)
	require.Equal(t, poolBalanceBefore, poolBalanceAfter)
	require.True(t, app.BankKeeper.GetBalance(ctx, delegator, bondDenom).IsZero())
	retained, found := app.StakingKeeper.GetUnbondingDelegation(ctx, delegator, validator)
	require.True(t, found)
	require.Equal(t, unbonding, retained)

	iterator := app.StakingKeeper.UBDQueueIterator(ctx, maturity)
	require.False(t, iterator.Valid())
	require.NoError(t, iterator.Close())
}

func TestSendingToCastAddress(t *testing.T) {
	a, ctx := keeper.MockApp(t)
	seiAddr, evmAddr := keeper.MockAddressPair()
	castAddr := sdk.AccAddress(evmAddr[:])
	sourceAddr, _ := keeper.MockAddressPair()
