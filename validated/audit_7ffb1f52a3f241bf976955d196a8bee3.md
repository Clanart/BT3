This confirms the vulnerability: `onAccept` in `BandwidthManager.sol` only validates `request.source` (the source **chain**) against `IDispatcher(_host).hyperbridge()`, but never validates `request.from` (the source **module**) against `PALLET_BANDWIDTH_MODULE_ID`. [1](#0-0) 

## Finding

`onAccept` decodes `PostRequest` and checks only:
```solidity
if (!request.source.equals(IDispatcher(_host).hyperbridge())) revert UnauthorizedAction();
``` [2](#0-1) 

This confirms the message came from the hyperbridge parachain, but it does not check `request.from` — the identity of the pallet/module that dispatched the message on that source chain — against `PALLET_BANDWIDTH_MODULE_ID` (`"BWMARKET"`). [3](#0-2) 

The `PostRequest` struct explicitly carries a `from` field distinguishing the source module, as seen in the test helper `_governanceRequestFor`, which sets `from: bytes("hyperbridge-governance")` — a value that is never actually checked against `PALLET_BANDWIDTH_MODULE_ID` anywhere in `onAccept`. [4](#0-3) 

Because `HandlerV2` routes any authenticated post request whose `dest`/`to` targets `BandwidthManager` regardless of which module on the hyperbridge parachain originated it, **any pallet/module on the hyperbridge chain** — not just `pallet-bandwidth` — could craft (or be tricked/compromised into producing, or simply be a different legitimate pallet with a different governance origin) a message with a first body byte of `0` (`SetTiers`) or `1` (`Withdraw`) and have it accepted by `BandwidthManager.onAccept`, since only the chain-level `source` is authenticated, not the module-level `from`.

This directly matches the target invariant in the question: *cross-chain bandwidth actions must authenticate both source chain and source module before changing credit or withdrawing assets* — here only the source chain is authenticated, not the source module, so `onAccept` will execute `SetTiers` (arbitrary tier-price rewrite) or `Withdraw` (arbitrary token/native transfer to any beneficiary) from any module dispatching on the hyperbridge parachain, not exclusively `pallet-bandwidth`.

### Impact
- `Withdraw` action directly transfers ERC20 or native tokens held by `BandwidthManager` to an attacker-chosen `beneficiary` for an attacker-chosen `amount`. [5](#0-4) 
- `SetTiers` lets an unauthenticated-module source rewrite `tierPrice` mapping, corrupting the pricing model used by `purchase()`. [6](#0-5) 

This matches "Critical: unauthenticated cross-chain governance or host-management execution" since asset withdrawal and governance state mutation are reachable without validating the specific source module identity.

### Recommendation
Add an explicit check binding `request.from` to `PALLET_BANDWIDTH_MODULE_ID` in `onAccept`, e.g.:
```solidity
if (!request.from.equals(PALLET_BANDWIDTH_MODULE_ID)) revert UnauthorizedAction();
```
alongside the existing `request.source` check, so both source chain and source module are authenticated before applying `SetTiers` or `Withdraw`.

### Proof of Concept
Using the existing test harness's `_governanceRequestFor` helper as a template: construct a `PostRequest` with `source == hyperbridge` (passes the only existing check) but `from` set to an arbitrary/different module identifier (e.g. `bytes("some-other-pallet")` instead of `"BWMARKET"`), with body `bytes.concat(bytes1(uint8(OnAcceptActions.Withdraw)), abi.encode(Withdrawal({token: feeToken, beneficiary: attacker, amount: manager.balance})))`. Call `manager.onAccept(req)` as `address(host)` (satisfying `onlyHost`). Because `from` is never validated, the withdrawal succeeds and drains the manager's fee-token balance to `attacker`, despite the message never originating from `pallet-bandwidth`.

    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost {
        PostRequest calldata request = incoming.request;

        if (!request.source.equals(IDispatcher(_host).hyperbridge())) revert UnauthorizedAction();

        OnAcceptActions action = OnAcceptActions(uint8(request.body[0]));
        if (action == OnAcceptActions.SetTiers) {
            Tier[] memory updates = abi.decode(request.body[1:], (Tier[]));
            for (uint256 i = 0; i < updates.length; i++) {
                tierPrice[updates[i].tier] = updates[i].price;
                emit TierSet(updates[i].tier, updates[i].price);
            }
        } else if (action == OnAcceptActions.Withdraw) {
            Withdrawal memory w = abi.decode(request.body[1:], (Withdrawal));
            if (w.token != address(0)) {
                IERC20(w.token).safeTransfer(w.beneficiary, w.amount);
            } else {
                (bool sent,) = w.beneficiary.call{value: w.amount}("");
                if (!sent) revert InsufficientNativeToken();
            }
            emit Withdrawn(w.token, w.beneficiary, w.amount);
        } else {
            revert UnauthorizedAction();
        }
    }
