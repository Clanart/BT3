## Strongest analog: unbounded recursion in `FieldMaskTree::MergeMessage`/`merge`/`Merge` driven by attacker-controlled `FieldMask.paths` dot-segment count

### Title
Unbounded Recursion in FieldMask Tree Merge/Trim via Attacker-Controlled Path Depth — (`src/google/protobuf/util/field_mask_util.cc`)

### Summary
The jq CVE's failed invariant is: a runtime-constructed array (the `setpath`/`getpath` path) drives recursion depth in `jv_setpath()`/`jv_getpath()`/`delpaths_sorted()` with no depth check, even though the JSON *parser* itself enforces `MAX_PARSING_DEPTH`. The check that limits nesting exists on one axis (parser depth) but not on the axis actually used for recursion (path-array length).

Protobuf has the same structural gap in its `FieldMask` utility. `FieldMask.paths` is a `repeated string` field; a single path string like `"a.a.a...a"` is a *flat* scalar, so parsing/deserializing it costs zero wire-format nesting and is **not** subject to protobuf's extensively-tested message recursion limits (`CodedInputStream::SetRecursionLimit`, `ParseContext::depth_`, JSON `recursion_depth`, etc. — all verified in `src/google/protobuf/io/coded_stream.h:387-421`, `src/google/protobuf/parse_context.h:800-846`, and dozens of `RecursionLimit`/`MaliciousRecursion` tests across languages). Once that string is split on `.` to build a `FieldMaskTree`, however, `FieldMaskTree::MergeMessage` (C++), `FieldMaskTree.merge` (Java), `FieldMaskTree.Merge` (C#), and `_MergeMessage` (Python) recurse **one stack frame per path segment with zero depth check**, exactly mirroring jq's bypass.

### Finding Description
`FieldMaskTree::AddPath` in `src/google/protobuf/util/field_mask_util.cc:353-377` iteratively builds a tree node per dot-separated segment of an attacker-supplied path string — this part is stack-safe (explicitly noted for `Node::ClearChildren`, `field_mask_util.cc:246-273`).

But the actual traversal that uses this tree to merge or trim data is recursive and unbounded: [1](#0-0) 

Each tree level with children recurses via `MergeMessage(child, ..., destination_reflection->MutableMessage(destination, field))` — one native stack frame per FieldMask path segment, with **no depth counter, no limit, no bail-out**. The only thing gating recursion is that `field` (looked up purely from the *descriptor*, not from actual message contents) must exist and be a singular message field — it does **not** require the field to actually be populated in the data. `MutableMessage`/`GetMessage` will happily materialize an empty default submessage at each level.

The same unguarded pattern is repeated in every language binding:
- Java: [2](#0-1) 
- C#: [3](#0-2) 
- Python (via `_MergeMessage`, driven by `FieldMaskTree.MergeMessage`): [4](#0-3) 

`FieldMaskTree::TrimMessage` and `AddRequiredFieldPath` follow the identical unguarded recursive shape: [5](#0-4) 

Compare this to every other recursive-descent entry point in the codebase, all of which are hardened and regression-tested against exactly this class of bug: [6](#0-5) [7](#0-6) [8](#0-7) 

`FieldMaskUtil::MergeMessageTo` and `TrimMessage` are the public entry points that application code calls, directly analogous to the "trusted filter" in the jq report — the schema/message type is trusted, but the `FieldMask` value passed to it is untrusted, client-supplied data (e.g., a gRPC `UpdateFooRequest.field_mask` used for partial updates): [9](#0-8) 

### Impact Explanation
This is the transferred external invariant: **the depth-limiting mechanism (protobuf's parse-time recursion limit) does not cover this code path**, because `FieldMask.paths` is a flat scalar array whose "logical nesting" only materializes after parsing, during reflection-based tree traversal — exactly like jq's path array bypassing `MAX_PARSING_DEPTH`.

For an application whose protobuf schema contains any self-referential (or mutually-recursive) message field — a very common pattern (trees, linked comment threads, org charts, nested folders, `NestedTestAllTypes.child` in this very repo's own test protos) — an attacker can submit a `FieldMask` such as `{"paths": ["child.child.child...(N times)...child"]}` to any endpoint that calls `FieldMaskUtil::MergeMessageTo`/`TrimMessage` (C++), `FieldMaskTree.merge`/`trim` (Java), `FieldMaskTree.Merge`/`Trim` (C#), or `FieldMask.MergeMessage` (Python). This drives N native stack frames of recursion with no limit check, exhausting the call stack and crashing the process (SIGSEGV / `StackOverflowError`) — the same unrecoverable denial-of-service impact as CVE-2026-33947.

### Likelihood Explanation
- `FieldMask` is a first-class, widely-used well-known type (`google.protobuf.FieldMask`), commonly accepted directly from clients in partial-update RPCs (e.g., Google Cloud/AIP-compliant APIs).
- Building the malicious path string requires no special tooling — it is a single string field, and the ~200KB-scale payload matches the size class in the original jq PoC (a path with tens of thousands of `.`-separated segments is well within normal message size limits, e.g. default 2GB / typical 64MB app limits).
- The vulnerable code paths (`MergeMessage`, `TrimMessage`, `merge`, `Merge`) are all reachable through documented, public `FieldMaskUtil` APIs, not internal/test-only code.
- The one precondition — a self-referential message field somewhere in the target schema — is common but not universal, which is why this is Medium rather than Critical/High: it requires an application-specific schema shape, unlike the jq bug which is triggerable against jq itself with no schema dependency.

### Recommendation
Add an explicit recursion/depth guard to `FieldMaskTree::MergeMessage`, `TrimMessage`, and `AddRequiredFieldPath` (and their Java/C#/Python equivalents), either by:
1. Capping the number of dot-separated segments accepted per path in `AddPath`/`FieldMaskUtil::FromString` (reject or truncate paths beyond a fixed depth, mirroring `CodedInputStream`'s default recursion limit of 100), or
2. Converting the recursive tree merge/trim into an explicit iterative worklist traversal (the codebase already has this pattern available in `ForEachLeaf`, `field_mask_util.cc:308-338`, and `Node::ClearChildren`, `field_mask_util.cc:246-273` — the same technique should be applied to `MergeMessage`/`TrimMessage`/`AddRequiredFieldPath`).

### Proof of Concept
Given a message type with a self-referential message field (e.g. `NestedTestAllTypes` with field `child` of type `NestedTestAllTypes`, already present in this repo's test protos, `src/google/protobuf/util/field_mask_util_test.cc:484-513`):

```cpp
// Attacker-controlled FieldMask, e.g. received over an update RPC.
std::string path = absl::StrJoin(std::vector<std::string>(65000, "child"), ".");
FieldMask mask;
FieldMaskUtil::FromString(path, &mask);   // just splits on ',' — flat, cheap

NestedTestAllTypes src, dst;
FieldMaskUtil::MergeOptions options;
// This call recurses ~65000 levels deep in FieldMaskTree::MergeMessage
// (field_mask_util.cc:476-504) with no depth check, exhausting the stack.
FieldMaskUtil::MergeMessageTo(src, mask, options, &dst);
```

No sanitizer run was performed in this analysis; the claim of stack exhaustion is based on the reachable, unbounded per-segment recursion demonstrated in the cited code and the absence of any recursion-limit check comparable to the one enforced for wire/JSON message parsing elsewhere in the same codebase.

                                 Message* destination) {

  const Reflection* source_reflection = source.GetReflection();
  const Reflection* destination_reflection = destination->GetReflection();
  const Descriptor* descriptor = source.GetDescriptor();
  for (const auto& kv : node->children) {
    absl::string_view field_name = kv.first;
    const Node* child = kv.second.get();
    const FieldDescriptor* field = descriptor->FindFieldByName(field_name);

                                   const MergeOptions& options,

  // Build a FieldMaskTree and walk through the tree to merge all specified

            }

            foreach (var entry in node.Children)
            {
                var field = descriptor.FindFieldByName(entry.Key);
                if (field == null)
                {
                    Debug.WriteLine($"Cannot find field \"{entry.Key}\" in message type \"{descriptor.FullName}\"");
                    continue;
                }

                if (entry.Value.Children.Count != 0)
                {
                    if (field.IsRepeated
                        || field.FieldType != FieldType.Message)
                    {
                        Debug.WriteLine($"Field \"{field.FullName}\" is not a singular message field and cannot have sub-fields.");
                        continue;

                    var destinationField = field.Accessor.GetValue(destination);
