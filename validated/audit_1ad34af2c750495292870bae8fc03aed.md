## Title
BEEFY supermajority threshold is checked on raw signature/vote count, not on unique authority indices — duplicate votes can be padded to fake quorum - (File: `evm/src/consensus/EcdsaBeefy.sol`, `modules/consensus/beefy/verifier/src/lib.rs`)

### Summary
Both the Solidity (`EcdsaBeefy.sol`) and Rust (`modules/consensus/beefy/verifier/src/lib.rs`) BEEFY consensus verifiers compute the 2/3+1 supermajority threshold from the raw length of the submitted `votes`/`signatures` array, without first requiring that every entry come from a distinct `authorityIndex`. This mirrors exactly the SwingTraderManager bug class: a collection that is supposed to represent unique entities (there, `traderContract`s; here, BEEFY authorities) is never de-duplicated before its size is used to drive downstream accounting — there `buyMalt()`/`sellMalt()` ratio math, here the supermajority quorum check that gates state-commitment acceptance.

### Finding Description
In `EcdsaBeefy.sol::verifyMmrUpdateProof`:
```solidity
uint256 sigLen = relayProof.signedCommitment.votes.length;
...
if (!checkParticipationThreshold(sigLen, authoritySet.len)) revert SuperMajorityRequired();
...
for (uint256 i = 0; i < sigLen; i++) {
    Vote memory vote = relayProof.signedCommitment.votes[i];
    address authority = ECDSA.recover(commitmentHash, vote.signature);
    authorities[i] = MerkleMultiProof.Leaf({index: vote.authorityIndex, hash: keccak256(abi.encodePacked(authority))});
}
bool valid = MerkleMultiProof.VerifyProof(authoritySet.root, relayProof.proof, authorities, authoritySet.len);
``` [1](#0-0) 

`checkParticipationThreshold` only compares array length to `authoritySet.len`:
```solidity
function checkParticipationThreshold(uint256 len, uint256 total) internal pure returns (bool) {
    return len >= ((2 * total) / 3) + 1;
}
``` [2](#0-1) 

The identical pattern exists in the Rust light-client verifier used for Substrate-side BEEFY verification:
```rust

...
if !check_participation_threshold(signatures_length as u32, authority_set.len) {
    return Err(Error::SuperMajorityRequired);
}
...
for sig in mmr.signed_commitment.signatures.iter() {
    ...
    authority_leaves.push(authority_address_hash.into());
    authority_indices.push(sig.index as usize);
}
let valid = merkle_proof.verify(authority_set.keyset_commitment.into(), &authority_indices, &authority_leaves, authority_set.len as usize);
``` [3](#0-2) [4](#0-3) 

Nowhere in either code path is there a check that `vote.authorityIndex` / `sig.index` values are unique across the submitted list. Contrast this with the two other verifiers in the same codebase that consciously guard against exactly this class of bug:
- The GRANDPA justification verifier explicitly rejects `num_duplicated_precommits() > 0` from `finality_grandpa::validate_commit`. [5](#0-4) 
- The Pharos verifier explicitly dedupes participant keys before counting stake: `if deduped.len() != participants.len() { return Err(Error::DuplicateParticipant); }`. [6](#0-5) 

The BEEFY ECDSA path (both the on-chain Solidity client and the off-chain/Substrate Rust verifier) lacks this guard. An attacker with access to only a minority of honestly-produced BEEFY authority signatures for a commitment (fewer than 2/3+1 of the authority set, e.g. leaked/observed signatures from relayers gossiping votes, which are not secret) can pad the `votes`/`signatures` array with repeated copies of the *same* `(authorityIndex, signature)` pairs to inflate `sigLen`/`signatures_length` past the supermajority threshold, while `MerkleMultiProof.VerifyProof` / `merkle_proof.verify` is asked to prove membership for the same leaf index multiple times. Whether the underlying multi-proof library rejects duplicate indices as malformed input is the only thing standing between this construction and consensus acceptance — but the threshold check itself, which is supposed to be the substantive "supermajority" security property, is fully satisfied by duplication regardless of what the multi-proof library does, since `checkParticipationThreshold`/`check_participation_threshold` never inspects uniqueness.

### Impact Explanation
This directly targets the "false proof/state acceptance" impact category. The supermajority check is the core security assumption behind BEEFY consensus finality on Hyperbridge — if it can be satisfied without a genuine 2/3+1 of authorities agreeing, an attacker can drive acceptance of a forged/less-supported MMR root and downstream parachain state commitments (`storeStateMachineCommitment`), which are then trusted for proof verification of requests, responses, relayer fee claims, and bridged asset movement throughout the protocol. This is a root-of-trust break, not a peripheral bug.

### Likelihood Explanation
The severity of exploitation depends on how the underlying `MerkleMultiProof.VerifyProof` (Solidity, from `@polytope-labs/solidity-merkle-trees`) and the Rust `MerkleProof::verify` handle duplicate leaf indices in their `indices`/`leaves` inputs — I was not able to fully inspect that library's source in this pass to determine definitively whether it silently accepts duplicate indices as valid proof inputs or reverts. If the multi-proof implementation does reject duplicate indices, this specific padding vector is closed at that layer even though the threshold-check function itself remains logically unsound (checking count instead of uniqueness) and unsafe as a standalone building block. This uncertainty should be resolved by inspecting `MerkleMultiProof.VerifyProof`'s handling of repeated `index` values in a Devin session with full repo access, since the index-size and index limits are not visible from the indexed snippets available here.

### Recommendation
- In both `EcdsaBeefy.sol::verifyMmrUpdateProof` and `modules/consensus/beefy/verifier/src/lib.rs::verify_mmr_update_proof`, deduplicate `vote.authorityIndex` / `sig.index` before counting `sigLen`/`signatures_length` toward the supermajority threshold, mirroring the pattern already used in the Pharos verifier (`DuplicateParticipant` check) and enforced by `finality_grandpa::validate_commit`'s duplicate-precommit rejection in the GRANDPA path.
- Confirm and, if necessary, harden `MerkleMultiProof.VerifyProof` / the Rust merkle multi-proof verifier to explicitly reject duplicate indices in the proof input, rather than relying on it as an implicit (and unverified) defense.

### Proof of Concept
Conceptual (requires confirming library-level duplicate-index handling, hence not a full exploit script):
1. Attacker observes/collects `k` valid BEEFY vote signatures for a commitment, where `k < (2/3)*total_authorities + 1` (i.e., insufficient for legitimate quorum).
2. Attacker constructs `relayProof.signedCommitment.votes` (or `mmr.signed_commitment.signatures`) by repeating some of these `k` `(authorityIndex, signature)` pairs multiple times until `sigLen`/`signatures_length` reaches `>= (2/3)*total_authorities + 1`.
3. Calls `EcdsaBeefy.verify(...)` (or the Rust `verify_consensus`/`verify_mmr_update_proof`) with this padded proof.
4. `checkParticipationThreshold(sigLen, authoritySet.len)` passes purely on array length.
5. If the merkle multi-proof verification (`MerkleMultiProof.VerifyProof` / `merkle_proof.verify`) does not itself reject duplicate `index` entries, the proof is accepted, and a state commitment/MMR root not actually finalized by the real BEEFY supermajority is stored via `storeStateMachineCommitment`, corrupting the trusted `_stateCommitments` used by all downstream ISMP proof verification.

pub fn verify_mmr_update_proof<H: Keccak256 + EcdsaRecover + Send + Sync>(
	mut trusted_state: ConsensusState,
	mmr: MmrProof,
) -> Result<(ConsensusState, H256), Error> {
	let signatures_length = mmr.signed_commitment.signatures.len();
	let latest_height = mmr.signed_commitment.commitment.block_number;

	if trusted_state.latest_beefy_height >= latest_height {
		return Err(Error::StaleHeight {
			trusted_height: trusted_state.latest_beefy_height,
			current_height: latest_height,
		});
	}

	let commitment = mmr.signed_commitment.commitment.clone();

	// Pick the authority set the commitment claims to be signed under, then judge
	// participation against that set alone.
	let authority_set = if commitment.validator_set_id == trusted_state.current_authorities.id {
		&trusted_state.current_authorities
	} else if commitment.validator_set_id == trusted_state.next_authorities.id {
		&trusted_state.next_authorities
	} else {
		return Err(Error::UnknownAuthoritySet { id: commitment.validator_set_id });
	};

	if !check_participation_threshold(signatures_length as u32, authority_set.len) {
		return Err(Error::SuperMajorityRequired);
	}

	let mmr_root_data = commitment
		.payload
		.get_raw(&MMR_ROOT_PAYLOAD_ID)
		.ok_or(Error::MmrRootHashMissing)?;

	if mmr_root_data.len() != 32 {
		return Err(Error::InvalidMmrRootHashLength { len: mmr_root_data.len() });
	}
	let mmr_root = H256::from_slice(mmr_root_data);

	let commitment_hash = H::keccak256(&commitment.encode());
	let mut authority_leaves: Vec<[u8; 32]> = Vec::new();
	let mut authority_indices = Vec::new();

	for sig in mmr.signed_commitment.signatures.iter() {
		let uncompressed = H::secp256k1_recover(&commitment_hash.0, &sig.signature)
			.map_err(|_| Error::FailedToRecoverPublicKey)?;

		let hashed_uncompressed = H::keccak256(&uncompressed);

		let mut eth_address = [0u8; 20];
		eth_address.copy_from_slice(&hashed_uncompressed.as_ref()[12..]);

		let authority_address_hash = H::keccak256(&eth_address);

		authority_leaves.push(authority_address_hash.into());
		authority_indices.push(sig.index as usize);
	}

	let merkle_proof = MerkleProof::<MerkleHasher<H>>::new(mmr.authority_proof.clone());

	let valid = merkle_proof.verify(
		authority_set.keyset_commitment.into(),
		&authority_indices,
		&authority_leaves,
		authority_set.len as usize,
	);

	if !valid {
		Err(Error::InvalidAuthoritiesProof)?;
	}

/// Verify that all participating validators are members of the trusted validator set.
fn verify_validator_membership(
	validator_set: &ValidatorSet,
	participants: &[BlsPublicKey],
) -> Result<(), Error> {
	let deduped: alloc::collections::BTreeSet<&[u8]> =
		participants.iter().map(|k| k.as_ref()).collect();
	if deduped.len() != participants.len() {
		return Err(Error::DuplicateParticipant);
	}
	if let Some(key) = participants.iter().find(|key| !validator_set.contains(key)) {
		return Err(Error::UnknownValidator { key: key.clone() });
	}
	Ok(())
}
