### Title
Explicit disabling of Git's clone symlink/hook-injection protection during recursive clones - (File: `app/src/lib/git/clone.ts`)

### Summary
Reducing the Sablier report to its core primitive: an operation hands control flow to attacker-influenced logic *before* the code path's protective invariant has been enforced, and an existing safety mechanism is bypassed as a side effect of the surrounding orchestration code. The Desktop analog is in `clone()` (`app/src/lib/git/clone.ts`), which performs `git clone --recursive` on an arbitrary, fully attacker-controlled URL while explicitly forcing the environment variable `GIT_CLONE_PROTECTION_ACTIVE` to `'false'`. This variable is Git's own internal guard against the class of vulnerability fixed for CVE-2024-32002 (arbitrary hook/file write via crafted, case-colliding, or symlinked `.git`/submodule paths during recursive clone/checkout). By unconditionally forcing this flag to `false` for a clone of a remote, untrusted repository, Desktop's clone helper removes a Git-provided defense exactly in the scenario (recursive clone of a URL the user does not control) where it matters most.

`GIT_CLONE_PROTECTION_ACTIVE` is used by upstream Git to track whether the recursive-clone protection logic (introduced to remediate CVE-2024-32002, where a maliciously crafted repository/submodule tree could get a hook file written into `.git/hooks` on case-insensitive or symlink-tolerant filesystems and have it auto-executed during checkout) is currently engaged for the operation. This flag is meant to be set/managed internally by Git as it recurses into submodule clones — not force-disabled by a calling application for the *entire* top-level clone. Desktop pins it to `'false'` unconditionally for every clone, including the very first, outermost invocation against a URL that is fully attacker-controlled (the user is cloning someone else's repository).

The clone path does add its own mitigations — `isClonePathSensitive()` rejects clone destinations that resolve to sensitive directories like `~/.ssh`, `~/.gnupg`, or the home directory itself: [2](#0-1) 

but that check only validates the *top-level* destination path chosen by the user/UI. It does nothing to prevent a malicious repository from using `--recursive` submodule expansion to place a crafted `.git`/hooks entry that collides with the real `.git` directory via case-folding or symlink tricks on the *submodule* paths — which is precisely the attack `GIT_CLONE_PROTECTION_ACTIVE` exists to stop. Forcing it to `'false'` removes this check for the whole operation.

### Impact Explanation
If Git's own recursive-clone protection is the only thing standing between "clone this crafted repository" and "execute an attacker-supplied file as a Git hook," disabling it converts an ordinary, unprivileged action — cloning a repository the user was given a link to (matching the "Valid Impact" criteria: attacker controls a cloned/fetched repository or a link the user clicks) — into a potential arbitrary code execution primitive on the user's machine, entirely outside the intended repository sandbox, with no additional user interaction beyond "Clone" or "Open in Desktop."

### Likelihood Explanation
Every clone performed through Desktop's `clone()` helper (the primary UI clone flow and "Open in Desktop"/clone-URL protocol handler flows that route through it) passes `--recursive` with this flag disabled, so the exposure is not conditional on a rare setting — it applies to the default, everyday clone operation whenever the source repository contains (or is crafted to contain) submodules designed to exploit the case-insensitive/symlink collision. The main open question, which I could not verify further given the tool limitations in this pass, is the exact semantics `GIT_CLONE_PROTECTION_ACTIVE=false` has in the specific bundled Git/dugite version Desktop ships — i.e., whether it fully disables the CVE-2024-32002 mitigation or only skips a redundant re-check during submodule recursion. That distinction should be confirmed against the bundled Git source/changelog before treating this as fully proven exploitable, but the code's intent (explicitly overriding a security-named environment variable to `false` for a fully untrusted clone) is itself a red flag warranting a fix regardless of the precise mechanics.

### Recommendation
- Do not force `GIT_CLONE_PROTECTION_ACTIVE` to `'false'` from application code. Let Git manage this flag internally as designed, so the top-level clone of an untrusted URL remains protected.
- If the flag was added to work around an unrelated compatibility issue (e.g., noisy warnings on recursive submodule clones), scope the override to only the inner/nested submodule clone invocations that Git itself spawns, not the outer, user-initiated clone of an untrusted remote.
- Add a regression test that attempts to clone a crafted repository (or a local fixture simulating the CVE-2024-32002 payload — a submodule whose `.git` entry collides case-insensitively with the parent's `.git` directory) and asserts that Desktop refuses/aborts the clone rather than checking out attacker-controlled files into `.git/hooks`.

### Proof of Concept
1. Construct a malicious repository containing a submodule configured so that, on a case-insensitive or symlink-tolerant filesystem, the submodule's `.git` path collides with the parent repository's real `.git` directory (the general shape of the CVE-2024-32002 payload).
2. Host it and have a victim clone it via GitHub Desktop's normal "Clone repository" flow, which calls `clone()` in `app/src/lib/git/clone.ts` with `--recursive` and `GIT_CLONE_PROTECTION_ACTIVE: 'false'`.
3. If the bundled Git's protection is bypassed by this flag (to be confirmed against the exact bundled Git version), the crafted hook file lands in `.git/hooks` and executes during the recursive checkout step, achieving code execution outside the intended repository content — without the user running any command beyond "Clone." function isClonePathSensitive(unresolvedClonePath: string): boolean {
```typescript
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}
```

```typescript
export async function clone(
  url: string,
  path: string,
  options: CloneOptions,
  progressCallback?: (progress: ICloneProgress) => void
): Promise<void> {
  if (isClonePathSensitive(path)) {
    throw new Error(
      `The clone destination "${path}" targets a sensitive system location. ` +
        'Cloning into this directory is not allowed.'
    )
  }

  const env = {
    ...(await envForRemoteOperation(url)),
    GIT_CLONE_PROTECTION_ACTIVE: 'false',
  }

  const defaultBranch = options.defaultBranch ?? (await getDefaultBranch())

  const args = [
    '-c',
    `init.defaultBranch=${defaultBranch}`,
    'clone',
    '--recursive',
  ]

  let opts: IGitStringExecutionOptions = { env }

  if (progressCallback) {
    args.push('--progress')

    const title = `Cloning into ${path}`
    const kind = 'clone'

    opts = await executionOptionsWithProgress(
      { ...opts, trackLFSProgress: true },
      new CloneProgressParser(),
      progress => {
        const description =
          progress.kind === 'progress' ? progress.details.text : progress.text
        const value = progress.percent

        progressCallback({ kind, title, description, value })
      }
    )

    // Initial progress
    progressCallback({ kind, title, value: 0 })
  }

  if (options.branch) {
    args.push('-b', options.branch)
  }

  args.push('--', url, path)

  await git(args, __dirname, 'clone', opts)
}
```
