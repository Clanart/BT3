### Title
Unbounded memory allocation via unauthenticated JSON-RPC HTTP request body read in APM tracing handlers - ([File: networks/rpc/http_newrelic.go])

### Summary
When Kaia's JSON-RPC HTTP server is run with NewRelic or Datadog APM tracing enabled, every inbound HTTP request (including from unauthenticated, public JSON-RPC callers) is first passed through `getRPCRequests(r)`, which reads the entire request body into memory with `io.ReadAll(r.Body)` and **no size limit**, before the framework's own `Content-Length`/body-size enforcement (`validateRequest` + `io.LimitReader(r.Body, MaxRequestContentLength)`) is ever reached. [1](#0-0) 

### Finding Description
The default hardened path for the JSON-RPC HTTP server enforces `common.MaxRequestContentLength` in two ways: `validateRequest` rejects requests whose `Content-Length` exceeds the limit, and `newHTTPServerConn` wraps `r.Body` in `io.LimitReader(r.Body, int64(common.MaxRequestContentLength))` so that even chunked/unknown-length bodies cannot be read past the cap. [2](#0-1) [3](#0-2) 

However, when APM integration is enabled (`NEWRELIC_APP_NAME`/`NEWRELIC_LICENSE`, or `DD_TRACE_ENABLED`), `NewHTTPServer` wraps the handler chain with `newNewRelicHTTPHandler`/`newDatadogHTTPHandler` as the **outermost** handler, executed before the CORS/vhost/timeout-wrapped `srv` (which contains the size-limited `ServeHTTP`/`validateRequest` logic). [4](#0-3) 

Both APM wrappers call `getRPCRequests(r)` purely to extract the RPC method name for tracing/logging purposes: [5](#0-4) [6](#0-5) 

`getRPCRequests` performs `io.ReadAll(r.Body)` with no length check or limit reader, buffering the full request body in memory regardless of its size: [7](#0-6) 

Because this occurs before `validateRequest`'s `Content-Length` check and before `newHTTPServerConn`'s `io.LimitReader`, an attacker who sends a POST request with an arbitrarily large body (with or without a matching `Content-Length` header, e.g. using chunked transfer-encoding to bypass any client-side length pre-check) will have that entire body read into a Go byte slice in `getRPCRequests` before any size validation runs. Sending many such requests concurrently allows unauthenticated exhaustion of node memory — the same bug class as the reported Grafana public-dashboard-query DoS: a pre-authentication endpoint that "does not limit request body size before processing."

### Impact Explanation
Any public Kaia RPC node operator who enables NewRelic or Datadog APM tracing (a supported, documented operational feature, not an unusual configuration) exposes their public JSON-RPC HTTP endpoint to unauthenticated, pre-validation memory-exhaustion DoS. This affects node availability for all `eth_*`/`klay_*`/`debug_*` public RPC consumers (transaction senders, contract deployers, gasless/auction callers, etc.) that depend on the node, and could be used to degrade or crash a public RPC endpoint with no authentication or valid request required.

### Likelihood Explanation
Likelihood is High for any deployment with APM tracing enabled: no authentication, no special headers, and no valid JSON-RPC payload are required — any POST to the RPC HTTP listener is unconditionally passed to `getRPCRequests` before the framework rejects it. `MaxRequestContentLength` is otherwise the project's own documented mitigation against exactly this class of attack (confirmed by test `TestHTTPErrorResponseWithMaxContentLength`), but the APM instrumentation paths bypass it entirely. [8](#0-7) 

### Recommendation
Wrap `r.Body` with `io.LimitReader(r.Body, int64(common.MaxRequestContentLength))` (or reuse `newHTTPServerConn`'s limiting logic) inside `getRPCRequests` before calling `io.ReadAll`, and/or move the `validateRequest`/Content-Length check to execute before the NewRelic/Datadog wrapper in `NewHTTPServer`'s handler chain, so that oversized requests are rejected prior to any full-body buffering.

### Proof of Concept
1. Start a Kaia node's JSON-RPC HTTP server with `NEWRELIC_APP_NAME` and `NEWRELIC_LICENSE` (or `DD_TRACE_ENABLED=true`) set, exposing the public RPC HTTP port.
2. From an unauthenticated client, send repeated POST requests to the RPC endpoint with a very large body (e.g. several hundred MB of arbitrary JSON-like bytes), optionally using `Transfer-Encoding: chunked` to avoid needing to declare `Content-Length` up front:
   ```
   curl -X POST http://<rpc-host>:<port> \
     -H "Content-Type: application/json" \
     -H "Transfer-Encoding: chunked" \
     --data-binary @huge_payload.json
   ```
3. Each such request causes `newNewRelicHTTPHandler`/`newDatadogHTTPHandler` to invoke `getRPCRequests`, which calls `io.ReadAll(r.Body)` and buffers the entire payload in memory before `validateRequest`'s size check is ever reached.
4. Repeating this concurrently drives up node memory usage without any authentication, valid JSON-RPC method, or content-length declaration, leading to memory exhaustion / OOM and denial of service for the public RPC endpoint.

// getRPCRequests copies a http request body data and parses RPC requests from the data.
// It returns a slice of RPC request, an indication if these requests are in batch, and an error.
// Ethereum returns []*jsonrpcMessage, which replaces []rpcRequest
func getRPCRequests(r *http.Request) ([]*jsonrpcMessage, bool, error) {
	reqBody, err := io.ReadAll(r.Body)
	if err != nil {
		logger.Error("cannot read a request body", "err", err)
		return nil, false, err
	}

	r.Body = io.NopCloser(bytes.NewReader(reqBody))
	conn := &httpServerConn{Reader: io.NopCloser(bytes.NewReader(reqBody)), Writer: bytes.NewBufferString(""), r: r}

	codec := NewCodec(conn)

	defer codec.close()

	return codec.readBatch()
}

func NewHTTPServer(cors []string, vhosts []string, timeouts HTTPTimeouts, srv http.Handler) *http.Server {
	timeouts = sanitizeTimeouts(timeouts)
	// Wrap the CORS-handler within a host-handler
	handler := newCorsHandler(srv, cors)
	handler = newVHostHandler(vhosts, handler)
	handler = http.TimeoutHandler(handler, timeouts.ExecutionTimeout, "timeout")

	// If os environment variables for NewRelic exist, register the NewRelicHTTPHandler
	nrApp := newNewRelicApp()
	if nrApp != nil {
		handler = newNewRelicHTTPHandler(nrApp, handler)
	}

	// If os environment variables for Datadog exist, register the NewDatadogHTTPHandler
	ddTracer := newDatadogTracer()
	if ddTracer != nil {
		handler = newDatadogHTTPHandler(ddTracer, handler)
	}

	return &http.Server{
		Handler:      handler,
		ReadTimeout:  timeouts.ReadTimeout,
		WriteTimeout: timeouts.WriteTimeout,
		IdleTimeout:  timeouts.IdleTimeout,
	}
}

func validateRequest(r *http.Request) (int, error) {
	if r.Method == http.MethodPut || r.Method == http.MethodDelete {
		return http.StatusMethodNotAllowed, errors.New("method not allowed")
	}
	if r.ContentLength > int64(common.MaxRequestContentLength) {
		err := fmt.Errorf("content length too large (%d>%d)", r.ContentLength, int64(common.MaxRequestContentLength))
		return http.StatusRequestEntityTooLarge, err
	}
