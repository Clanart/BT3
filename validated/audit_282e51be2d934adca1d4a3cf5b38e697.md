### Title
Batch-position reward misattribution lets caller redirect relayer rewards to an attacker-controlled account - (File: `modules/pallets/consensus-incentives/src/impls.rs`)

### Summary
`pallet-ismp`'s `handle_unsigned` extrinsic lets any unprivileged, unsigned caller submit an arbitrary `Vec<Message>` batch for execution [3](#0-2) . The `consensus-incentives::FeeHandler::on_executed` implementation picks the reward beneficiary by decoding **only `messages[0]`**'s embedded signer, then pays that single recovered account for **every** `StateMachineUpdated` event that resulted from processing the entire batch [4](#0-3) . Because batch composition and ordering are entirely attacker-controlled (the submitter of `handle_unsigned` chooses which messages to include and in what order), the on-chain treasury payout for consensus proofs that other relayers actually delivered can be diverted to whichever account crafted `messages[0]`.

### Finding Description
The reward computation flow is:

1. `execute()` processes the whole `messages: Vec<Message>` array and collects all resulting ISMP `events` (including `StateMachineUpdated` for every state machine advanced by any message in the batch), then calls `T::FeeHandler::on_executed(messages_with_weights, events)` once for the entire batch [5](#0-4) .
2. `consensus-incentives::on_executed` derives `maybe_relayer_account` **exclusively from `messages.get(0)`**: if the first message is `Message::Consensus`, it recovers a public key from the signature embedded in that single message's `signer` field over `keccak256(consensus_proof)` [6](#0-5) .
3. It then iterates **all** `StateMachineUpdated` events in the batch (which can originate from consensus messages other than `messages[0]`, e.g. a second `Message::Consensus` for a different chain later in the same call), collapses them to `highest_per_state_machine`, and pays the treasury-funded reward for **every one of those state machines** to the single account recovered in step 2 [7](#0-6) , transferring funds via `T::Currency::transfer` from the treasury account [8](#0-7) .

The corrupted value is `relayer_account` in `on_executed`: it is bound only to `messages[0].signer`, but is then used as the beneficiary for reward computed over `events` generated by the *entire* batch, not just the events caused by `messages[0]`. Because `handle_unsigned` is `ensure_none(origin)` (permissionless, unsigned) and takes the raw `messages` vector directly from the caller with no ordering or composition constraint [9](#0-8) , an unprivileged submitter fully controls which `Message::Consensus` item lands at index 0.

Existing guards do not stop this path:
- The per-message consensus proof itself is cryptographically verified by `handle_incoming_message` (so an attacker cannot forge a *consensus* proof), but that verification is independent of, and does not bind, which account collects the *reward* for it.
- There is no per-message-to-per-event linkage in the reward pallet — attribution is batch-wide via index 0 only, and nothing checks that the `state_machine_id` rewarded actually corresponds to the consensus message whose signature was recovered.
- `on_executed` never validates that `messages[0]`'s `consensus_msg.consensus_proof` is the proof that produced the `StateMachineUpdated` event(s) being paid out.

### Impact Explanation
This directly breaks the "relayer rewards must move exactly once and only to the rightful beneficiary" invariant. A submitter can bundle a genuine, real consensus proof for a valuable/high-`block_cost` state machine (crafted or copied from public network traffic — consensus proofs and their signer fields are not secret, they are published on the source chain and gossiped through the relayer network) *behind* their own cheap/self-authored `Message::Consensus` at index 0, causing the treasury to pay the attacker for state-machine advances they did not relay. This is a direct loss-of-funds / wrong-beneficiary bug against the Hyperbridge treasury (`T::TreasuryAccount`), matching the required "stealing or loss of funds" / "logic attacks" impact categories. It does not require a malicious relayer, prover, or admin — any address able to submit the permissionless `handle_unsigned` extrinsic can trigger it.

### Likelihood Explanation
`handle_unsigned` is explicitly documented as callable by "anyone" with valid proofs [10](#0-9) , and consensus proof messages containing another relayer's signer bytes are inherently public data flowing through the network before being included on-chain (the pallet only checks proof/signature validity, not exclusivity of submission). The only requirement is assembling a batch with the attacker's own valid, cheap consensus message first and a legitimately-signed (by someone else, or even attacker-authored for a second high-value chain) consensus message afterward in the same call — well within reach of any unprivileged actor monitoring the mempool/network for pending consensus submissions.

### Recommendation
Attribute rewards per-message rather than per-batch: recover a relayer account independently for each `Message::Consensus` item and only credit `StateMachineUpdated` events that are provably produced by that specific message (e.g., by threading the message index/consensus_state_id or proof hash through `MessageResult` into the events, or by processing `on_executed` per-message instead of batching all events against `messages[0]`). At minimum, reject batches containing more than one `Message::Consensus` when using index-0 attribution, or bind each `StateMachineUpdated` event to the specific message whose proof produced it before awarding a reward.

### Proof of Concept
1. Attacker generates (or captures publicly-broadcast) `Message::Consensus` proof `A` that will legitimately advance `state_machine_id = X` (high `block_cost`), signed by relayer key `R_honest`.
2. Attacker crafts a trivial/self-signed `Message::Consensus` proof `B` for a low-cost or otherwise-cheap state machine, signing it with their own key `R_attacker`.
3. Attacker submits `handle_unsigned(messages = [B, A])` via the unsigned, permissionless extrinsic.
4. `execute()` processes both messages, verifying each proof independently and emitting `StateMachineUpdated` events for both state machines advanced (including the high-value chain `X` from proof `A`).
5. `consensus-incentives::on_executed` decodes `messages[0] == B`, recovering `R_attacker` as `relayer_account`.
6. The loop over `highest_per_state_machine` includes the state machine advanced by `A`, and `Self::process_message` transfers the treasury reward for `X` to `R_attacker` instead of `R_honest`, who actually possessed/authored proof `A`.

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}

	pub fn execute(messages: Vec<Message>) -> Result<Vec<events::Event>, Error<T>> {
		let host = Pallet::<T>::default();

		let message_results = messages
			.iter()
			.map(|msg| handle_incoming_message(&host, msg.clone()))
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		let messages_with_weights = message_results
			.iter()
			.zip(messages)
			.map(|(result, message)| MessageWithWeight { message, weight: result.weight() })
			.collect::<Vec<_>>();

		let events = message_results
			.into_iter()
			// check that requests will be successfully dispatched
			// so we can not be spammed with failing txs
			.map(|result| match result {
				MessageResult::Request { events, .. } |
				MessageResult::Response { events, .. } |
				MessageResult::Timeout { events, .. } => events,
				MessageResult::ConsensusMessage(events) => events.into_iter().map(Ok).collect(),
				MessageResult::FrozenClient(_) => vec![],
			})
			.flatten()
			.collect::<Result<Vec<_>, _>>()
			.map_err(|err| {
				log::debug!(target: "ismp", "Handling Error {:#?}", err);
				Pallet::<T>::deposit_event(Event::<T>::Errors { errors: vec![err.into()] });
				Error::<T>::InvalidMessage
			})?;

		T::FeeHandler::on_executed(messages_with_weights, events.clone())
			.map_err(|_| Error::<T>::ErrorChargingFee)?;

		for event in events.clone() {
			// deposit any relevant events
			Pallet::<T>::deposit_event(event.into());
		}

		Ok(events)
	}
