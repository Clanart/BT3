### Title
Recursive clone explicitly disables Git's built-in clone-time protection against malicious repository content, enabling code execution on clone/fetch of an untrusted repo - (File: `app/src/lib/git/clone.ts`)

### Summary
`clone()` in `app/src/lib/git/clone.ts` runs every user-initiated "Clone repository" / "Clone again" operation with `--recursive` while explicitly forcing the environment variable `GIT_CLONE_PROTECTION_ACTIVE` to `'false'`. This variable is used internally by upstream Git as part of the hardening added for the class of clone-time vulnerabilities where a maliciously crafted repository (typically via symlinked `.git` paths or nested submodule hooks) can get arbitrary hook code executed during a recursive clone/checkout. By forcing this flag off, Desktop deliberately turns off a safety check that Git itself relies on, re-opening the door for a repository the user does not yet control or trust (the exact thing being cloned) to run code on the victim's machine the moment the clone/recursive-submodule step completes.

### Finding Description [1](#0-0) 

The clone flow is:
1. `isClonePathSensitive()` only validates the destination directory path (home dir, `.ssh`, `.gnupg`, `.config`, `.gitconfig`) — it says nothing about the contents of the remote repository being cloned.
2. `envForRemoteOperation(url)` builds the base environment, and the code then unconditionally merges in `GIT_CLONE_PROTECTION_ACTIVE: 'false'`.
3. `git clone --recursive -- url path` is executed with that environment, meaning submodules are fetched and checked out automatically as part of the same operation, without any additional user confirmation step.

`GIT_CLONE_PROTECTION_ACTIVE` is not a Desktop-invented feature flag — it's the guard Git itself introduced to prevent hostile repository content (e.g. a symlinked `.git` directory or crafted submodule/hooks layout inside a nested repo) from being able to run hook scripts or escape the intended clone target during `--recursive` clones. That fix specifically targets the scenario where the attacker fully controls the thing being cloned (the repository/submodule tree), which is exactly the untrusted input Desktop is handling here: the user has only clicked "Clone", they have not yet reviewed or trusted the repository's content.

By hardcoding this to `'false'` for every clone, Desktop unconditionally disables Git's own mitigation instead of only doing so in a context where it's provably safe (e.g., a known-good, already-vetted URL). None of Desktop's other guards address this: `isClonePathSensitive` only checks the destination path, not repository content; there is no repository-trust prompt equivalent to the "unsafe directory ownership" check (`getRepositoryType`/`addSafeDirectory` in `app/src/ui/add-repository/add-existing-repository.tsx` and `app/src/ui/missing-repository.tsx`) applied before or during the clone step — that trust dialog only fires for pre-existing local directories, not for content freshly pulled down from `git clone --recursive`.

This mirrors the report's core invariant break: a multi-step, externally-influenced operation ("clone → checkout → recurse into submodules") hands control to attacker-supplied content mid-flight, after a protective check has been deliberately bypassed, before the operation is safely completed.

### Impact Explanation
An attacker who controls (or can get a victim to clone) a malicious Git repository — including as a submodule pulled in transitively via `--recursive` — can craft the repository to exploit the class of clone-time issues that `GIT_CLONE_PROTECTION_ACTIVE` exists to stop, resulting in arbitrary code execution on the victim's machine using only the standard "Clone repository" action in Desktop. This satisfies the impact bar for unprivileged, repository-controlled attacker primitives leading to code execution.

### Likelihood Explanation
Every clone performed via Desktop's UI (`app/src/ui/clone-repository/clone-repository.tsx` → `Dispatcher.clone` → `AppStore._clone` → `CloningRepositoriesStore.clone` → `clone()`) and "Clone Again" (`MissingRepository.cloneAgain`) goes through this exact code path with `--recursive` and the protection forcibly disabled, and cloning a repository someone points you to (a link, a GitHub search result, a fork) is one of Desktop's most common, ordinary user actions — no special/local access or social engineering beyond "clone this repo" is required.

### Recommendation
Do not force `GIT_CLONE_PROTECTION_ACTIVE` to `'false'`. Let Git's default protection remain active for `git clone --recursive`, and if there's a legitimate reason it was disabled (e.g. compatibility with some internal flow), scope that exception narrowly and document why it's safe in that specific context, rather than disabling it globally for every user-initiated clone of arbitrary, potentially untrusted URLs.

### Proof of Concept
1. Attacker publishes a public repository containing a submodule (or nested repository referenced via `.gitmodules`) engineered using the symlink/hooks-path technique that Git's clone-time protection (`GIT_CLONE_PROTECTION_ACTIVE`) is designed to block during recursive clone/checkout.
2. Victim opens GitHub Desktop, chooses "Clone repository…", and pastes the attacker's URL (or clicks a "Clone with Desktop" style link).
3. `clone()` in `app/src/lib/git/clone.ts` runs `git -c init.defaultBranch=... clone --recursive -- <url> <path>` with `GIT_CLONE_PROTECTION_ACTIVE` forced to `'false'`.
4. Because the protection is disabled, the malicious submodule/hook payload executes as part of the recursive clone/checkout, achieving code execution on the victim's machine without any further confirmation from Desktop.

```typescript
export async function clone(
  url: string,
  path: string,
  options: CloneOptions,
  progressCallback?: (progress: ICloneProgress) => void
): Promise<void> {
  if (isClonePathSensitive(path)) {
    throw new Error(
      `The clone destination "${path}" targets a sensitive system location. ` +
        'Cloning into this directory is not allowed.'
    )
  }

  const env = {
    ...(await envForRemoteOperation(url)),
    GIT_CLONE_PROTECTION_ACTIVE: 'false',
  }

  const defaultBranch = options.defaultBranch ?? (await getDefaultBranch())

  const args = [
    '-c',
    `init.defaultBranch=${defaultBranch}`,
    'clone',
    '--recursive',
  ]
```
