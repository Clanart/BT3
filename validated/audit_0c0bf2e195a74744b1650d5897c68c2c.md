### Title
Unbounded atom-length advance in `is_clvm_canonical`/`is_atom_canonical` causes unhandled out-of-bounds read and mempool-validation crash from a submitted spend bundle - (File: chia/full_node/mempool_manager.py)

### Summary
The reported PrusaSlicer CVE is a classic "attacker-controlled length field advances a cursor without validating it against the remaining buffer size" bug. `chia/full_node/mempool_manager.py` contains the same bug-class pattern in `is_atom_canonical()`/`is_clvm_canonical()`: the atom length is read from a length-prefix in an attacker-supplied CLVM buffer and used to advance a cursor with no check that the resulting offset stays inside the buffer. Every other CLVM/streamable buffer parser in this codebase (`chia/full_node/full_block_utils.py`) explicitly validates lengths against "remaining buffer" size before slicing; this function does not.

### Finding Description
`is_atom_canonical()` reads a 0–5 byte length prefix out of `clvm_buffer` and returns `1 + prefix_len + atom_len` as the number of bytes the atom occupies: [1](#0-0) 

`is_clvm_canonical()` calls this in a loop and blindly advances `offset` by the returned `atom_len` without ever checking that `offset` (or `offset + atom_len`) stays within `len(clvm_buffer)`: [2](#0-1) 

Contrast this with the hardened cheap-parsers in `full_block_utils.py`, which explicitly reject a length that "exceeds remaining buffer": [3](#0-2) 

`is_clvm_canonical()` is invoked unconditionally on every coin spend's `puzzle_reveal` and `solution` bytes inside `MempoolManager.validate_spend_bundle()`, which is the core admission path for any spend bundle a peer/wallet/RPC caller submits to the mempool: [4](#0-3) 

Because `atom_len` is attacker-controlled (it comes straight from the submitted `puzzle_reveal`/`solution` bytes) and is never bounds-checked against the remaining buffer length, a crafted atom whose declared length exceeds the actual remaining bytes causes `offset` to run past the end of `clvm_buffer`. The next loop iteration's `b = clvm_buffer[offset]` then raises an unhandled `IndexError` instead of returning `False` or a `ValidationError`. This is the direct analog of the OBJ parser's out-of-bounds access driven by an attacker-supplied size field: a size taken from untrusted input is used to advance a pointer/offset with no bounds validation.

### Impact Explanation
`validate_spend_bundle()` is called from the mempool admission path (`add_spend_bundle` → `validate_spend_bundle`) while holding the blockchain/mempool lock, for every spend bundle a wallet, RPC caller, or peer submits. Because `is_clvm_canonical` can raise an uncaught `IndexError` (rather than returning `False`, which is the only outcome the caller handles via `Err.INVALID_COIN_SOLUTION`), a single malicious spend bundle can throw an unexpected exception out of the mempool's core validation routine. Unlike the codebase's own test coverage for unexpected exceptions from `pre_validate_spendbundle` (which is explicitly handled and re-raised while cleaning up the "seen" cache), an exception raised from deep inside `validate_spend_bundle` at this specific point is not a `ValidationError`/`Err` the mempool code paths are designed to expect, and it can propagate up through `add_spend_bundle`, disrupting mempool bookkeeping for that call and constituting a spend-triggered transaction-processing halt/DoS for the affected full node. This is a Medium/High-severity denial-of-service analog to the reported bug class (bounds-check-free length-driven cursor advance on untrusted input), reachable by any unprivileged spend-bundle submitter — no special privileges, peer status, or node operator access required.

### Likelihood Explanation
Likelihood is high: constructing a CLVM buffer with a 2–6 byte atom-length prefix that declares a length larger than the remaining bytes in `puzzle_reveal` or `solution` is trivial and does not require the buffer to pass CLVM execution validity first — `is_clvm_canonical` runs directly on the raw bytes before/independent of full CLVM semantic checks in this specific call site. The test suite even exercises non-canonical atom-length prefixes but only in the "safe" case where they still fit inside the buffer (`test_atom_not_canonical`, `test_mempool_requires_canonical_clvm`), not the case where the declared length overruns the buffer, so this specific bounds-check gap is untested. [5](#0-4) 

### Recommendation
In `is_atom_canonical()`/`is_clvm_canonical()`, validate every prefix-byte read and the final atom length against the remaining buffer length before advancing `offset`, mirroring the "exceeds remaining buffer" checks already used in `chia/full_node/full_block_utils.py` (`skip_bytes`, `skip_list`). Raise a well-defined error (or return non-canonical / `False`) instead of allowing `offset` to exceed `len(clvm_buffer)`, and ensure `validate_spend_bundle()` treats any parsing failure here as `Err.INVALID_COIN_SOLUTION` rather than letting an `IndexError` escape.

### Proof of Concept
Construct a `CoinSpend` whose `solution` (or `puzzle_reveal`) bytes are a single "large-prefix" atom header whose declared length exceeds the remaining buffer, e.g. bytes `0xC0 0x3F` (a 2-byte-prefix atom claiming length `0x3F` = 63) followed by fewer than 63 payload bytes — or more directly, an atom header claiming a length larger than what is actually present, followed immediately by end-of-buffer. Submitting a `SpendBundle` containing such a `CoinSpend` (as done via `make_spend`/`SpendBundle` and `mempool_manager.add_spend_bundle`, exactly as in `test_mempool_requires_canonical_clvm`) drives execution into `validate_spend_bundle()` → `is_clvm_canonical(bytes(coin_spend.solution))` → `is_atom_canonical()`, where `offset` is advanced past the end of the buffer and the subsequent `clvm_buffer[offset]` access raises an unhandled `IndexError` instead of the expected `Err.INVALID_COIN_SOLUTION` result.

Note: I was unable to fully trace, within the remaining tool budget, every intermediate caller (`add_transaction` in `full_node.py`, RPC/peer message handlers) to confirm exactly how far the unhandled `IndexError` propagates in production (e.g., whether it is caught generically at a higher layer and only logged, or whether it disrupts the mempool lock/seen-cache state as seen in the analogous `pre_validate_spendbundle` exception-handling test). This should be verified with a live PoC before treating the DoS severity as certain.

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

```python
def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

```python
def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
```
