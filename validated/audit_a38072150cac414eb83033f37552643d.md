### No vulnerability found for this question.

**Analysis supporting this conclusion:**

The question's premise conflates two unrelated mechanisms. The `sighash` function at [1](#0-0)  is a BIP-341 Taproot sighash computation used exclusively for watchtower-challenge signature verification in `verify_watchtower_challenges` — it has no involvement with state roots, storage proofs, or the light-client journal at all.

The actual binding the question describes — "the state root used for storage verification == the root in the verified light-client journal for the payout's block" — is enforced correctly in `bridge_circuit`:

1. The root is never taken from unverified attacker input. `lc_proof_verifier` calls `env::verify(LC_IMAGE_ID, &light_client_proof.lc_journal)` before deserializing anything, and `light_client_circuit_output.l2_state_root` is extracted only from that verified journal: [2](#0-1) .

2. This verified root is the sole value passed into `verify_storage_proofs`: [3](#0-2) . There is no code path where a caller-supplied raw root bypasses `lc_proof_verifier`.

3. The circuit additionally binds the verified light-client DA state to the exact block the payout is proved in, by asserting `lc_l1_block_hash == spv_l1_block_hash`: [4](#0-3) . This prevents an attacker from supplying a light-client proof for a different (e.g., wrong-height) DA state while claiming SPV inclusion in another block — the two must match.

Since the root is always sourced from a `guest.verify`-checked journal (or in `is_regtest()` a locally-computed deserialization used only in test builds, out of scope per the audit rules) and is cross-checked against the payout's actual block hash, an attacker cannot substitute an arbitrary or wrong-height root into `verify_storage_proofs`. The invariant holds before and after tracing the code, so there is no divergence to exploit.

pub fn lc_proof_verifier(light_client_proof: LightClientProof) -> LightClientCircuitOutput {
    if !is_regtest() {
        env::verify(LC_IMAGE_ID, &light_client_proof.lc_journal)
            .expect("Failed to verify light client proof");
    }

    let light_client_circuit_output = deserialize_circuit_output(&light_client_proof.lc_journal);

    if !is_regtest() {
        assert!(
            check_method_id(&light_client_circuit_output, LC_IMAGE_ID),
            "Light client proof method ID does not match the expected LC image ID"
        );
    }

    light_client_circuit_output
}
