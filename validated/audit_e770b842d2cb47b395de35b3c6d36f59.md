## Title
Malicious HTTP remote can trick Desktop's credential-helper trampoline into binding the user's real GitHub OAuth token to an attacker-controlled endpoint - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
Desktop's Git credential-helper trampoline (`createCredentialHelperTrampolineHandler`) decides whether a remote host is a "GitHub" endpoint using the `WWW-Authenticate` header value Git forwards from the remote server itself, via `getEndpointKind`. Because this classification is derived entirely from attacker-controlled server response content rather than a validated identity, a hostile or compromised HTTP git remote can cause Desktop to treat itself as talking to a GitHub Enterprise host, triggering `trampolineUIHelper.promptForGitHubSignIn(endpoint)` bound to the attacker's own origin. The resulting real GitHub `Account`/token is then stored keyed to the attacker's endpoint and will subsequently be handed back to Git as HTTP Basic Auth credentials for that same attacker-controlled remote — exfiltrating the user's real GitHub token to the attacker's server.

### Finding Description
`getEndpointKind` is used to classify the remote endpoint associated with a git credential request: [1](#0-0) 

The key branch:
```js
for (const [k, v] of cred.entries()) {
  if (k.startsWith('wwwauth[')) {
    if (v.includes('realm="GitHub"')) {
      return 'enterprise'
    } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
      return 'generic'
    }
  }
}
```
`wwwauth[...]` credential fields are populated by Git from the `WWW-Authenticate` HTTP response header returned by the remote server during an authentication challenge — i.e., content fully controlled by whoever operates the remote/proxy the user is talking to. There is no host validation (e.g., checking the domain looks like a GitHub Enterprise install, or matching against `isGitHubHost`'s network-based heuristic) before trusting this header to mean "this is a GitHub host."

Once `getEndpointKind` returns `'enterprise'` for an arbitrary attacker-controlled origin, `getCredential` runs: [2](#0-1) 

Since the attacker's endpoint won't match any existing stored account, `!accounts.some(a => a.endpoint === apiEndpoint)` is true, and (outside of a background task) the code calls `ui.promptForGitHubSignIn(endpoint)`: [3](#0-2) 

This opens a legitimate GitHub sign-in flow (`beginEnterpriseSignIn` / `setSignInEndpoint(origin)`) using the attacker's origin as the target "enterprise" endpoint. If the user completes what looks like a normal Desktop sign-in prompt (which they would reasonably do, believing Desktop is asking them to authenticate to a repository they're cloning/pushing to), a real, valid `Account` with a genuine OAuth/PAT token is created and stored — but keyed to the attacker's endpoint/origin, not to any real GitHub instance.

On subsequent credential lookups for that same remote, `findGitHubTrampolineAccount` will match this stored account by origin and hand the token straight back to Git: [4](#0-3) [5](#0-4) 

Git then sends this token as the HTTP Basic Auth password to the attacker-controlled server, and the attacker's server captures a real, live GitHub credential.

The existing network-based heuristic `isGitHubHost()` (which performs a `HEAD` request to `/meta` and checks for `x-github-request-id`) is never consulted in this trampoline path — only the trusted-looking-but-attacker-supplied `WWW-Authenticate` header is used, so that safeguard does not stop this path: [6](#0-5) 

### Impact Explanation
This results in exfiltration of the user's real GitHub OAuth/PAT credential to an attacker who merely operates (or has compromised/MITM'd) an HTTP git remote or proxy that the user adds/clones/pushes to. Because the credential store then associates the token with that attacker endpoint, the token is repeatedly sent to the attacker on every subsequent git operation against that remote for as long as the account persists in Desktop.

### Likelihood Explanation
No local access, prior malware, or leaked credentials are required. The only attacker action needed is to run/host a Git-over-HTTP endpoint (or a MITM proxy for a plaintext/self-signed HTTP remote) that returns a crafted `WWW-Authenticate: ... realm="GitHub" ...` header during Git's HTTP authentication challenge — something entirely within an attacker's control when they supply a remote/clone URL that the victim adds to Desktop. The main friction is that the victim must interact with the resulting sign-in popup, but this is a normal, expected UI flow in Desktop (no unusual or "unnatural" steps), and users have no way to tell from the popup that they're not signing into a legitimate GitHub Enterprise install because the popup is shown using an endpoint the app itself already (incorrectly) trusts as GitHub.

### Recommendation
Do not trust the `wwwauth[...]` `realm="GitHub"` heuristic on its own to classify a remote as a genuine GitHub/Enterprise host. Require this heuristic to be corroborated by the same authoritative check used elsewhere (`isGitHubHost`, which validates via `/meta` + `x-github-request-id`) before invoking `promptForGitHubSignIn`, or otherwise clearly warn the user (with the literal hostname) that they're about to authenticate a full GitHub account against a specific, arbitrary host, and require explicit confirmation of that hostname rather than treating it as an implicit, low-friction "enterprise sign-in."

### Proof of Concept
1. Attacker stands up an HTTP git server (or transparent proxy) at `https://evil.example.com/attacker/repo.git`.
2. Attacker configures the server so that any authentication challenge response includes a header such as `WWW-Authenticate: Basic realm="GitHub"`.
3. Victim adds this URL as a remote in GitHub Desktop and performs a fetch/push, triggering Git's credential-helper protocol; Git forwards the `WWW-Authenticate` value as a `wwwauth[...]` field in the `get` credential request sent to Desktop's trampoline.
4. `getEndpointKind` in `trampoline-credential-helper.ts` matches `realm="GitHub"` and returns `'enterprise'` for `evil.example.com`.
5. Since no account exists for that endpoint, Desktop calls `promptForGitHubSignIn('https://evil.example.com')`, opening a sign-in dialog scoped to that origin.
6. Victim completes sign-in (believing it's a normal enterprise auth prompt); a genuine `Account` with a real token is stored keyed to `evil.example.com`.
7. On the next credential request for that same remote, `findGitHubTrampolineAccount` matches by origin and returns the real token, which Git sends as Basic Auth to `evil.example.com`, giving the attacker the victim's live GitHub credential.

Confirming the exact runtime behavior (e.g., whether the sign-in dialog's endpoint display would tip off some users) would benefit from running the app in a full dev/test environment.*

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }

export async function findGitHubTrampolineAccount(
  accountsStore: AccountsStore,
  remoteUrl: string
): Promise<Account | undefined> {
  const accounts = await accountsStore.getAll()
  const parsedUrl = new URL(remoteUrl)
  return accounts.find(
    a => new URL(getHTMLURL(a.endpoint)).origin === parsedUrl.origin
  )
}

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}
