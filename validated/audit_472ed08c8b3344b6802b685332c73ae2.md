### Title
Unauthenticated on-chain mirror coins let any spend-bundle submitter inject arbitrary URLs into a victim's DataLayer, triggering unverified outbound HTTP fetches (SSRF) - (File: chia/data_layer/data_layer_wallet.py)

### Summary
`DataLayerWallet.coin_added()` accepts and persists mirror URLs for *any* DataLayer store the local node tracks, based solely on the spent coin's puzzle hash matching the fixed, public mirror puzzle (`create_mirror_puzzle()`), with no check that the spender owns, controls, or is otherwise authorized for that store's singleton/launcher_id. This mirrors the Cryptomator bug class of "unverified/unauthenticated data used before its integrity or provenance is validated" — here, the untrusted `launcher_id`/`urls` memo pair drives later automatic outbound network fetches instead of a filesystem `Files.exists()` check.

### Finding Description
The DataLayer mirror puzzle (`create_mirror_puzzle()` in `chia/wallet/db_wallet/db_wallet_puzzles.py:90-91`) is a fixed, globally spendable puzzle. Any wallet user can create a coin with this puzzle hash and CREATE_COIN memos of the form `[launcher_id, url1, url2, ...]` by submitting an ordinary spend bundle — no relationship to `launcher_id`'s actual DataLayer singleton owner is required.

On the receiving side, `DataLayerWallet.coin_added()` processes every coin created to this puzzle hash: [1](#0-0) 

The only gating check is `is_launcher_tracked(launcher_id)` — i.e., whether the local node happens to track that store (which happens automatically for any store a user has subscribed to or owns). There is no verification that the coin's spender is the store's owner, holds any authority over the singleton, or that the URL points to a server that actually serves data for that store. The parsed `urls` are decoded directly from attacker-controlled memo bytes (`get_mirror_info()` in `chia/wallet/db_wallet/db_wallet_puzzles.py:97-109`) and stored via `DataLayerStore.add_mirror()`: [2](#0-1) 

These attacker-supplied URLs are later read by the DataLayer service and used to sync/fetch files: [3](#0-2) 

and consumed in the periodic background sync loop, `fetch_and_validate()`, which iterates `servers_info` (built from these mirror URLs) and issues outbound requests via `insert_from_delta_file()` → `download_file()` → `http_download()`: [4](#0-3) 

`http_download()` performs an unrestricted `aiohttp` GET to `server_info.url + "/" + filename` with no scheme allow-list or destination restriction (e.g., no blocking of internal/link-local addresses), so the request fires automatically and periodically as long as the store is tracked — before any content validation occurs. Content validation (root-hash reconstruction) only happens *after* the network request already succeeded, so the outbound request itself is unconditionally triggered by unauthenticated on-chain data, analogous to Cryptomator's `Files.exists()` firing on an unverified `keyId` before passphrase entry/integrity check.

### Impact Explanation
Any user who can submit a spend bundle (no special privilege required) can force a victim's DataLayer service to make outbound HTTP requests to attacker-chosen hosts/ports for any store the victim tracks, purely by publishing a low-value coin to the public mirror puzzle with a `launcher_id`/`url` memo pointing at the victim's tracked store. This is a classic SSRF primitive against the victim's DataLayer daemon: it can be used to probe internal network services, hit cloud metadata endpoints, or otherwise abuse the victim's node as an unwitting outbound-request originator, all without the victim's consent or any ownership check on the mirror registration.

### Likelihood Explanation
Likelihood is high for any node operator running DataLayer with tracked/subscribed stores: the attack requires only the ability to submit a standard spend bundle creating a coin to the well-known mirror puzzle hash with the target `launcher_id` in the memo — something any wallet holder can do without coordination with the store owner. The periodic sync loop (`periodically_manage_data()`/`update_subscription()`) will pick up and act on the injected mirror automatically.

### Recommendation
Before accepting and persisting a mirror record in `coin_added()`, verify that the spender is authorized for the target `launcher_id` (e.g., require the mirror-creating coin to be provably linked to the singleton's current owner, or require an explicit local user opt-in/allow-list per store rather than trusting any on-chain mirror coin). Additionally, validate mirror URL schemes/hosts before use in `http_download()`/`fetch_and_validate()` (restrict to `http`/`https`, and consider blocking loopback/link-local/private-network targets) so unauthenticated on-chain data cannot drive arbitrary outbound requests.

### Proof of Concept
1. Attacker learns or targets a `launcher_id` that a victim's node tracks (e.g., a public DataLayer store).
2. Attacker submits a standard spend bundle creating a coin with `puzzle_hash == create_mirror_puzzle().get_tree_hash()` and memos `[launcher_id, b"http://attacker-controlled-host:1234"]`, funding it with minimal XCH.
3. Once confirmed, the victim's `DataLayerWallet.coin_added()` sees the coin, calls `get_mirror_info()`, finds `is_launcher_tracked(launcher_id)` true, and stores the attacker URL via `dl_store.add_mirror()` — [5](#0-4) .
4. On the next `periodically_manage_data()` cycle, `update_subscriptions_from_wallet()` pulls this URL into `data_store` subscriptions — [3](#0-2) .
5. `fetch_and_validate()` selects the attacker server and calls `insert_from_delta_file()` → `download_file()` → `http_download()`, causing the victim's node to issue an outbound HTTP GET to `http://attacker-controlled-host:1234/...` — [4](#0-3) , confirming the SSRF trigger from unauthenticated on-chain memo data.

```python
        self, coin: Coin, height: uint32, peer: WSChiaConnection, coin_data: object | None, sync_scope: WalletSyncScope

            )[0]
            parent_spend = await fetch_coin_spend(height, parent_state.coin, peer)
            assert parent_spend is not None
            launcher_id, urls = get_mirror_info(parent_spend.puzzle_reveal, parent_spend.solution)
            # Don't track mirrors with empty url list.
            if not urls:
                return
            if await self.wallet_state_manager.dl_store.is_launcher_tracked(launcher_id):
                ours: bool = await self.wallet_state_manager.get_wallet_for_coin(coin.parent_coin_info) is not None
                await self.wallet_state_manager.dl_store.add_mirror(
                    Mirror(
                        coin.name(),
                        launcher_id,
                        uint64(coin.amount),
                        Mirror.decode_urls(urls),
                        ours,
                        height,
                    )
                )
                await self.wallet_state_manager.add_interested_coin_ids([coin.name()])
```

```python
    async def add_mirror(self, mirror: Mirror) -> None:
        """
        Add a mirror coin to the DB
        """

        async with self.db_wrapper.writer_maybe_transaction() as conn:
            await conn.execute_insert(
                "INSERT OR REPLACE INTO mirrors VALUES (?, ?, ?, ?, ?)",
                (
                    mirror.coin_id,
                    mirror.launcher_id,
                    mirror.amount.stream_to_bytes(),
                    b"".join(
                        [uint16(len(url)).stream_to_bytes() + url for url in Mirror.encode_urls(mirror.urls)]
                    ),  # prefix each item with a length
                    1 if mirror.ours else 0,
                ),
            )
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
```
