## Title
Spoofable "GitHub host" detection in the trampoline credential helper allows attacker-controlled remotes to trigger a GitHub/Enterprise sign-in flow pointed at the attacker's domain - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The Clave `isValidSignature()` bug is a case where a security decision (is this signature valid *for this specific context*?) is made using an under-scoped check that an attacker can satisfy from an unrelated context. The closest analog found in GitHub Desktop is `getEndpointKind()` in `app/src/lib/trampoline/trampoline-credential-helper.ts:137-179`, which decides whether a credential request "is a GitHub host" using signals that are fully controlled by the remote server/repository being cloned or fetched, rather than a value tied to a specific known account/endpoint. A malicious repository or man-in-the-middle proxy can cause Desktop to misclassify an arbitrary host as a legitimate GitHub/Enterprise endpoint and drive the user into a sign-in flow bound to the attacker's origin.

### Finding Description
When Git needs credentials for an HTTPS remote, it invokes Desktop's credential helper trampoline (`app/src/lib/trampoline/trampoline-credential-helper.ts`). `getCredential()` first tries `getGitHubCredential()`, which safely matches an existing account by exact origin via `findGitHubTrampolineAccount` [1](#0-0) . If no exact match exists, it falls through to `getEndpointKind()` to classify the endpoint [2](#0-1) .

`getEndpointKind()` trusts two attacker-controllable signals to conclude a host is GitHub-owned:
1. Any `WWW-Authenticate` header returned by the remote server whose value contains `realm="GitHub"` is treated as sufficient proof the host is an "enterprise" GitHub host [3](#0-2) . This header is emitted by the remote HTTP server that Git is talking to — i.e., by the attacker's own git server/proxy — and is not otherwise validated.
2. Separately, `isGitHubHost()` in `app/src/lib/api.ts` uses a hostname regex `/(^|\.)(github)\./.test(hostname)` that matches any hostname containing a `github.` label, e.g. `github.attacker.com`, in addition to a live HTTP probe for a GitHub-identifying response header [4](#0-3) .

Once `getEndpointKind()` classifies the endpoint as `'enterprise'` and no existing account matches that endpoint, `getCredential()` calls `ui.promptForGitHubSignIn(endpoint)` [5](#0-4) . `promptForGitHubSignIn` then derives `origin` from the credential-request URL itself (which is fully attacker-controlled, since it comes from the git remote/host Git is authenticating against) and starts an Enterprise sign-in flow bound to that origin: `dispatcher.beginEnterpriseSignIn(cb); await dispatcher.setSignInEndpoint(origin)` [6](#0-5) . `setSignInEndpoint`/`SignInStore.setEndpoint` only validates that the URL is syntactically a valid HTTPS URL — it does not verify that the host is actually a trusted/known GitHub Enterprise instance [7](#0-6) .

The broken invariant mirrors the Clave bug: a validation function (`getEndpointKind`/`isGitHubHost`) that is supposed to gate a security-sensitive action (surfacing a "sign in to GitHub" prompt and initiating an OAuth/credential flow) is satisfied using a signal supplied entirely by the untrusted party being validated (the remote server's own HTTP headers/hostname), instead of being bound to something the attacker cannot control (a previously trusted account/endpoint). Existing guards — the exact-origin match in `findGitHubTrampolineAccount`, and endpoint capability checks in `endpoint-capabilities.ts` — only protect the case where credentials for an *already known* account would be sent to the wrong host; they do nothing to stop a *new* GitHub sign-in prompt from being spuriously triggered against an attacker-chosen origin.

### Impact Explanation
This is a phishing-enabling primitive fully triggerable from an unprivileged, attacker-controlled git remote/proxy: simply cloning, fetching, or pushing to a repository hosted at `https://github.<anything>.attacker.tld` (or any host whose HTTP response includes a spoofed `WWW-Authenticate: ... realm="GitHub"` header) is enough to make Desktop present a "Sign in to GitHub Enterprise" dialog whose target endpoint is the attacker's own domain. A user who is used to seeing Desktop's legitimate sign-in dialogs may enter their GitHub Enterprise credentials, or complete an OAuth authorization flow, believing they are authenticating to their real GHES instance, when the endpoint being contacted (`setSignInEndpoint(origin)`) is entirely attacker-supplied. This can lead to credential/token capture for GitHub Enterprise instances that use basic-style sign-in, or to confusing OAuth authorization prompts directed at an untrusted host — both outside the class of "self-XSS" or "requires local access," and squarely within "attacker controls a git remote/proxy response" → "unauthorized OAuth or credential exfiltration."

### Likelihood Explanation
Likelihood is moderate: it requires (a) the user to attempt a git operation (clone/fetch/push) against a malicious or compromised HTTPS remote, and (b) the user to proceed through a sign-in prompt without noticing the endpoint. No prior credentials, local access, or social engineering beyond "clone/interact with an attacker's repository" (already in-scope per the task's valid-impact criteria) are required. The `WWW-Authenticate` header spoofing path in particular requires zero cleverness — the attacker's own server can emit whatever header value it wants.

### Recommendation
- Do not let an unauthenticated `WWW-Authenticate` header value (`realm="GitHub"`) or a loose hostname regex be sufficient, on their own, to classify an arbitrary remote as a trusted "enterprise" GitHub host in `getEndpointKind()`/`isGitHubHost()`.
- Before invoking `ui.promptForGitHubSignIn(endpoint)` for a host with no existing matching account, surface the actual target hostname clearly to the user and/or require an explicit user confirmation step that makes clear a new, unrecognized host is requesting GitHub credentials.
- Tighten the `isGitHubHost` regex so it cannot match attacker-chosen subdomains/labels like `github.attacker.com`, and prefer the network probe (`x-github-request-id` check) as the primary signal rather than a fallback.
- Consider binding the sign-in flow's target endpoint to a value the user has previously configured/approved rather than one derived solely from the credential-request context.

### Proof of Concept
1. Attacker sets up an HTTPS git server at `https://github.malicious-corp.com/evil/repo.git` (or any host under attacker control), configured so that unauthenticated requests return `WWW-Authenticate: Basic realm="GitHub"`.
2. Victim, using GitHub Desktop, clones or adds this repository and performs a fetch/push, causing Git to invoke the trampoline credential helper for that host.
3. In `trampoline-credential-helper.ts`, `getGitHubCredential()` finds no matching stored account for this new origin; `getEndpointKind()` inspects the `WWW-Authenticate` header, sees `realm="GitHub"`, and returns `'enterprise'` [3](#0-2) .
4. `getCredential()` sees no existing account for `apiEndpoint` and calls `ui.promptForGitHubSignIn('https://github.malicious-corp.com')` [5](#0-4) .
5. `promptForGitHubSignIn` calls `dispatcher.beginEnterpriseSignIn(cb)` and `dispatcher.setSignInEndpoint('https://github.malicious-corp.com')`, and shows the sign-in popup [6](#0-5) .
6. The victim, believing this is a legitimate Desktop-initiated sign-in for a corporate GHES instance, enters credentials or completes an OAuth grant that is actually directed at the attacker's endpoint.

Note: I was not able to fully trace whether the current Enterprise sign-in UI supports a legacy basic-auth username/password path (versus OAuth-only) within the indexed code, since no `authenticateWithBasicAuth`/`setCredentials` implementation was found in the search index; if Enterprise sign-in is OAuth-only in the current codebase, the concrete credential-exfiltration impact is reduced to OAuth-authorization-directed-at-a-spoofed-origin rather than raw password capture. Confirming this would require inspecting the full `sign-in.tsx` component and any Enterprise-specific authentication step components, which were not fully retrievable from the index. If you need the complete picture of the Enterprise sign-in step implementation, a Devin session with full repository access would be needed to verify this last detail.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }
