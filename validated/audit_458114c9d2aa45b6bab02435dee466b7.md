### Title
Flashloaned stake can be used to front-run reward distribution and siphon a disproportionate share of `BaseRewardPool` yield in a single transaction - (File: `rewards/BaseRewardPool.sol`, `rewards/MasterMagpie.sol`)

### Summary
`BaseRewardPool` (and its variants `BaseRewardPoolV2`, `BribeRewardPool`, `vlMGPBaseRewarder`, `mWOMSVBaseRewarder`) distribute reward tokens using an instantaneous `rewardPerTokenStored` accumulator that is bumped the moment new rewards are provisioned, using whatever `totalStaked()` happens to be at that exact block. Because `balanceOf()` reads a live, un-checkpointed mapping in `MasterMagpie` that can be inflated and deflated within the same block via ordinary `deposit`/`withdraw` calls, an attacker can flashloan a large stake immediately before a reward injection and withdraw immediately after, capturing a share of rewards proportional to a balance they held for zero economic time. This is the same bug class as the Telcoin `Checkpoints#getAtBlock()` flashloan issue: a temporary, same-block stake is used to fake a large "share" and extract value that should accrue only to genuine long-term stakers.

### Finding Description
`BaseRewardPool.balanceOf()` simply forwards to `MasterMagpie.stakingInfo()`, which returns the user's live `UserInfo.amount`/`available`, updated instantly on `deposit`/`withdraw` with no vesting, cooldown, or historical checkpointing: [1](#0-0) [2](#0-1) 

`earned()` computes reward purely from the current `balanceOf()` multiplied by the delta between the current `rewardPerToken()` and the user's last-paid checkpoint: [3](#0-2) 

`rewardPerTokenStored` is not time-weighted at all — it jumps instantly whenever `_provisionReward` is invoked (via `queueNewRewards` or the fully permissionless `donateRewards`), dividing the newly added reward amount by `totalStaked()` at that single instant: [4](#0-3) [5](#0-4) 

Staking and withdrawing via `MasterMagpie._deposit`/`_withdraw` (which in turn call `rewarder.updateFor`/`getReward`) happen synchronously and can both occur in the same block/transaction, with no minimum holding period: [6](#0-5) [7](#0-6) 

Because `_updateFor` sets `userRewardPerTokenPaid` to the *current* `rewardPerToken()` at the moment of staking, and `earned()` only measures the delta from that point forward, a flashloaned stake placed immediately before a reward injection captures a full share of that injection proportional to its (temporarily huge) balance, exactly mirroring the "two checkpoints in the same block" exploit pattern in the referenced report — except here it's an un-checkpointed live balance rather than an OpenZeppelin `Checkpoints` structure.

### Impact Explanation
An attacker with access to a flashloan of the relevant `stakingToken` (e.g., a Wombat LP token or `mWOM`) can:
1. Flashloan-deposit a large amount into `MasterMagpie` for a pool with an active `BaseRewardPool`/`BaseRewardPoolV2`/`BribeRewardPool`.
2. Trigger (or front-run) a reward injection into that pool (`queueNewRewards`, or directly call the permissionless `donateRewards`/wait for a scheduled harvest that calls `queueNewRewards`).
3. Immediately call `withdraw`, which internally calls `getReward`, crediting the attacker with `earned()` computed against their inflated balance.
4. Repay the flashloan in the same transaction.

This directly transfers reward tokens that should accrue to genuine long-term stakers into the attacker's pocket, i.e., theft of unclaimed yield from other stakers with minimal capital cost (only flashloan fees). This satisfies the "theft of unclaimed yield" impact bar.

### Likelihood Explanation
Likelihood is high wherever: (a) the pool's underlying staking token is flashloan-borrowable (LP tokens, `mWOM`, etc. are typically composable ERC20s), and (b) reward injections are predictable or visible in the mempool before execution (e.g., `donateRewards` is fully permissionless and can even be called by the attacker themselves to trigger the rebase against their own inflated balance in combination with any pre-existing `queuedRewards` balance, and legitimate `queueNewRewards` calls from harvesting flows are typically public/keeper-incentivized). No privileged role is required by the attacker — any wallet with flashloan access can execute this end-to-end in a single transaction.

### Recommendation
- Replace the instantaneous `rewardPerTokenStored` bump with a time-weighted / streaming distribution model (Synthetix-style `rewardRate` over a `rewardsDuration`), so that reward accrual is proportional to time-weighted stake rather than balance sampled at a single instant.
- Alternatively, require a minimum holding period (e.g., stake must have existed for at least N blocks/seconds) before it counts toward `balanceOf()` for reward-earning purposes, or snapshot `totalStaked()`/user balances prior to the block in which the reward is provisioned.
- Restrict/rate-limit `donateRewards` or require it to average over a longer window rather than instantly repricing `rewardPerTokenStored`.

### Proof of Concept
```text
Pre-conditions: MasterMagpie pool P has staking token S (flashloanable, e.g. an LP token),
with a BaseRewardPool R distributing reward token T. R currently has totalStaked() = X (from
genuine long-term stakers) and rewardPerTokenStored = P0.

1. Attacker flashloans a large amount L of S (L >> X).
2. Attacker calls MasterMagpie.deposit(S, L):
   - _deposit() -> rewarder.updateFor(attacker) sets userRewardPerTokenPaid[T][attacker] = P0
   - user.amount[attacker] = L
3. Attacker (or a bot they front-run) triggers a reward injection of amount `r` reward tokens T
   into R, e.g. via BaseRewardPool.donateRewards(r, T) or by front-running a scheduled
   queueNewRewards(r, T) call:
   - _provisionReward computes:
       rewardPerTokenStored_new = P0 + r * 10**decimals / (X + L)
   Because L >> X, almost all of `r` is now allocated to the attacker's massive temporary balance.
4. Attacker calls MasterMagpie.withdraw(S, L):
   - _harvestAndUnstake -> _harvestBaseRewarder -> rewarder.getReward(attacker, attacker)
   - earned(attacker, T) = L * (rewardPerTokenStored_new - P0) / 10**decimals
     ≈ r  (attacker captures almost the entire newly injected reward `r`)
   - Attacker receives token T, withdraws S, repays the flashloan.

Net effect: the attacker extracts nearly all of reward `r` — which should have been distributed
to the pre-existing stakers holding X — for the cost of a flashloan fee only.
```

    function _provisionReward(uint256 _amountReward, address _rewardToken) internal {
        IERC20(_rewardToken).safeTransferFrom(
            msg.sender,
            address(this),
            _amountReward
        );
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (this.totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**stakingDecimals()) /
                this.totalStaked();
        }
        emit RewardAdded(_amountReward, _rewardToken);
    }

        updatePool(_stakingToken);

        PoolInfo storage pool = tokenToPoolInfo[_stakingToken];
        UserInfo storage user = userInfo[_stakingToken][_account];

        if (user.amount > 0) {
            _harvestMGP(_stakingToken, _account);
        }
        _harvestBaseRewarder(_stakingToken, _account);

        user.amount = user.amount + _amount;
        if (!_isVlmgp) {
            user.available = user.available + _amount;
            IERC20(pool.stakingToken).safeTransferFrom(address(msg.sender), address(this), _amount);
        }
        user.rewardDebt = (user.amount * pool.accMGPPerShare) / 1e12;

        if (_amount > 0)
            if (!_isVlmgp)
                emit Deposit(_account, _stakingToken, _amount);
            else
                emit DepositNotAvailable(_account, _stakingToken, _amount);
    }

    /// @notice internal function to deal with withdraw staking token
    function _withdraw(address _stakingToken, address _account, uint256 _amount, bool _isVlMgp) internal {
        _harvestAndUnstake(_stakingToken, _account, _amount, _isVlMgp);

        if (!_isVlMgp)
            IERC20(tokenToPoolInfo[_stakingToken].stakingToken).safeTransfer(address(msg.sender), _amount);
