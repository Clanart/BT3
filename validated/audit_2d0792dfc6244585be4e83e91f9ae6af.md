### Title
`ReceivedOutput::read` deserializes `(offset, output, outpoint)` without verifying the offset derives the output's `script_pubkey`, allowing unspendable funds to be reported as received - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
The referenced CVE class is deserialization of untrusted data leading to tampering. In bitcoin-serai, `ReceivedOutput::read` accepts three independent fields — a scalar `offset`, a `TxOut`, and an `OutPoint` — from raw bytes, with no consistency check that `offset` actually derives the Taproot key committed in `output.script_pubkey`. The only path that produces `ReceivedOutput` values correctly, `Scanner::scan_transaction`, guarantees this relationship by construction; the deserialization path discards that guarantee entirely. Any downstream consumer which deserializes attacker-influenced `ReceivedOutput` bytes will treat arbitrary UTXOs as spendable by the group key.

### Finding Description
`Scanner` maintains `scripts: HashMap<ScriptBuf, Scalar>` mapping each registered even-Y Taproot script to the offset that produces it (`self.key + offset * G`), so a scanned output is always backed by a known spend path (`networks/bitcoin/src/wallet/mod.rs:180-214`).

`ReceivedOutput::read` instead reads `Secp256k1::read_F` for the offset and consensus-decodes the `TxOut`/`OutPoint`, returning the tuple verbatim (`networks/bitcoin/src/wallet/mod.rs:122-134`). There is no recomputation of `p2tr_script_buf(key + offset*G)` and no comparison against `output.script_pubkey`. The `Scanner` key isn't even available to the reader, so the check cannot be enforced by the format. A crafted byte stream therefore yields a `ReceivedOutput` claiming ownership of any outpoint with any offset — including outpoints paying to third-party scripts or to tweaked keys whose discrete log the signer does not know.

Note also the `BufReader::with_capacity(0, r)` wrapper relies on zero-capacity buffering to avoid over-read; that is fragile but not the primary issue.

### Impact Explanation
An unprivileged party who can cause serialized `ReceivedOutput` bytes to be ingested (e.g., a peer supplying output data to a processor/wallet component) can cause the wallet to report funds as received which are not spendable: the signer will attempt to spend an outpoint whose script does not correspond to `group_key + offset·G`, producing either an invalid, unspendable input or accounting of phantom funds. This maps directly to the CVE's "data tampering / information disclosure" consequence and to the accepted analog class of funds reported received that are not spendable.

### Likelihood Explanation
Reachability requires an attacker to supply the serialized bytes to a component calling `ReceivedOutput::read`. Within the Serai architecture, output metadata is exchanged between scanners/processors and signing components; wherever that boundary is not trusted-local, the unchecked fields are attacker-controlled. The cryptographic checks elsewhere (`read_F` canonicality via `Ciphersuite::read_F`, `crypto/ciphersuite/src/lib.rs:74-83`) only guarantee the offset is a valid scalar — they say nothing about its semantic correctness, so exploitation needs no malformed encoding, just inconsistent fields.

### Recommendation
Either make `ReceivedOutput` unforgeable by construction (require the `Scanner` — or at least the group key — at read time and verify `output.script_pubkey == p2tr_script_buf(key + offset·G)`), or re-derive the offset at read time by scanning: pass the bytes through `Scanner::scan_transaction`-equivalent logic so only outputs whose script is in `self.scripts` yield `ReceivedOutput`s. If the format must stay self-contained, store and verify the expected script commitment alongside the offset and reject mismatches with `io::Error`.

### Proof of Concept
```rust
// Attacker-controlled bytes for ReceivedOutput::read:
//   offset  = 0x01... (scalar ONE, canonical)
//   output  = TxOut { value: 1_000_000, script_pubkey: <victim's own P2TR script or an
//             arbitrary script_pubkey not equal to p2tr(key + offset*G)> }
//   outpoint = any real, unspent outpoint the attacker does not control
let forged = ReceivedOutput::read(&mut bytes).unwrap();
// forged.value() reports 1_000_000 sats "received";
// key.offset(forged.offset()).group_key() != the key in forged.output().script_pubkey,
// so any spend attempt produces a signature invalid for that script —
// the reported funds are unspendable.
```

The fix-verifying test is: serialize a `ReceivedOutput` whose `output.script_pubkey` does not equal `p2tr_script_buf(scanner_key + offset*G)`; `read` must return `Err`.
