## Title
Unauthenticated `InternalSendTx` (and other `Internal*`) RPCs reachable on the Aggregator due to disabled client-certificate enforcement - (File: `core/src/servers.rs`, `core/src/rpc/interceptors.rs`, `core/src/rpc/aggregator.rs`)

### Summary
Clementine's access-control model marks certain gRPC methods with an `Internal` prefix (e.g. `InternalSendTx`, `InternalGetEmergencyStopTx`) that are meant to be callable only by the hosting entity itself, enforced via mTLS client-certificate checks in `core/src/rpc/interceptors.rs`. For the Verifier and Operator servers this restriction is real, but the Aggregator's gRPC server is documented and configured to skip client-certificate verification entirely, which removes the ACL check for every RPC including the `Internal*` ones. Any network peer that can reach the aggregator's TLS port can therefore call `internal_send_tx` and force the aggregator to queue and broadcast an arbitrary Bitcoin transaction using its own fee-bumping wallet.

### Finding Description
The interceptor logic that is supposed to gate "Internal" methods to the entity's own certificate is: [1](#0-0) 

This is only wired in when `config.client_verification` is `true`; otherwise `Interceptors::Noop` is used and no certificate check happens at all: [2](#0-1) 

The Aggregator server is built through the same generic `create_grpc_server` used by Verifier/Operator, but it only *warns* if `client_verification` is enabled — it does not require it, and the documented/intended deployment explicitly disables it for the Aggregator ("The aggregator does not enforce client certificates but does use TLS for encryption."): [3](#0-2) 

Because the `is_internal()` gate in `interceptors.rs` is the *only* mechanism restricting `Internal*` RPCs to the entity's own certificate, and this gate is bypassed entirely for the Aggregator (Noop interceptor), the `InternalSendTx` and `InternalGetEmergencyStopTx` endpoints declared in the proto are reachable by anyone who can open a TLS connection to the aggregator, with no certificate-based authorization: [4](#0-3) 

`internal_send_tx`'s implementation takes an arbitrary caller-supplied `raw_tx` and inserts it into the aggregator's `tx_sender` for broadcast (with CPFP/RBF fee-bumping funded from the aggregator's wallet), with no authentication or ownership check beyond basic tx parsing: [5](#0-4) 

This is the same bug class as the SimpleShares report: a function whose caller is *intended* to be restricted (there, "not during pause"; here, "only the entity itself, via the `Internal` naming convention and cert-check pattern established for Verifier/Operator") executes successfully for a party it was never meant to serve, because the enforcement mechanism was omitted for one specific caller context (the Aggregator).

### Impact Explanation
This matches the rules' High-impact category "an unauthenticated state-changing or broadcasting call." An unprivileged attacker can invoke `InternalSendTx` on the aggregator to make it broadcast attacker-chosen transactions using the aggregator's own fee-bumping funds/UTXOs, and can invoke `InternalGetEmergencyStopTx` to retrieve encrypted emergency-stop transactions for arbitrary move-txids without any authorization check — both actions that should be restricted to the aggregator's own internal automation loop per the codebase's established `Internal*` ACL convention.

### Likelihood Explanation
Likelihood is high for any deployment following the documented/recommended aggregator configuration (`client_verification` disabled for the Aggregator, as explicitly recommended), since no credential, key, or special role is required — only network reachability to the aggregator's gRPC/TLS endpoint, which by protocol design must be reachable by the "clementine-backend" client for legitimate non-internal RPCs like `NewDeposit`/`Withdraw`.

### Recommendation
Enforce a certificate check for `Internal*` methods on the Aggregator server regardless of the `client_verification` toggle (e.g., always apply the `is_internal()` gate against the aggregator's own client certificate for methods whose gRPC path starts with `Internal`), so that disabling `client_verification` only relaxes checks for the intentionally-public RPCs (`NewDeposit`, `Withdraw`, `SendMoveToVaultTx`, etc.) and not for `InternalSendTx` / `InternalGetEmergencyStopTx`.

### Proof of Concept
1. Deploy the Aggregator per the documented configuration (`client_verification = false`, as recommended in the operator docs).
2. From any machine with network access to the aggregator's TLS port, open a TLS connection with no client certificate (the server does not request `client_ca_root` when `client_verification` is false, per `core/src/servers.rs:106-112`).
3. Call `ClementineAggregator/InternalSendTx` with a crafted `SendTxRequest{raw_tx, fee_type}`.
4. Observe that `internal_send_tx` (`core/src/rpc/aggregator.rs:1269-1312`) accepts the call, inserts the transaction into `tx_sender`, and the aggregator proceeds to fee-bump/broadcast it — without ever checking the caller's identity.

fn is_internal(req: &Request<()>) -> bool {
    // This normally doesn't exist but we add it in the AddMethodMiddleware
    let Some(path) = req.metadata().get("grpc-method") else {
        // No grpc method? this should not happen
        tracing::error!("Missing grpc-method header in request");
        return false;
    };
    path.as_bytes().starts_with(b"Internal")
}

impl Interceptor for Interceptors {
    #[allow(clippy::result_large_err)]

        match self {
            Interceptors::OnlyAggregatorAndSelf {
                our_cert,
                aggregator_cert,
            } => only_aggregator_and_self(req, our_cert, aggregator_cert),
            Interceptors::Noop => Ok(req),
        }
    }
}

pub async fn create_aggregator_grpc_server(
    config: BridgeConfig,
) -> Result<(std::net::SocketAddr, oneshot::Sender<()>), BridgeError> {
    let addr: std::net::SocketAddr = format!("{}:{}", config.host, config.port)
        .parse()
        .wrap_err("Failed to parse address")?;
    let aggregator_server = AggregatorServer::new(config.clone()).await?;
    aggregator_server.start_background_tasks().await?;

    let svc = ClementineAggregatorServer::new(aggregator_server)
        .max_encoding_message_size(config.grpc.max_message_size)
        .max_decoding_message_size(config.grpc.max_message_size);

    if config.client_verification {
        tracing::warn!("Client verification is enabled on aggregator gRPC server",);
    }

    let (server_addr, shutdown_tx) =
        create_grpc_server(addr.into(), svc, "Aggregator", &config).await?;

    match server_addr {
        ServerAddr::Tcp(socket_addr) => Ok((socket_addr, shutdown_tx)),
        _ => Err(BridgeError::ConfigError("Expected TCP address".into())),
    }
}

            self.tx_sender

                    None,

                    None,

        }
