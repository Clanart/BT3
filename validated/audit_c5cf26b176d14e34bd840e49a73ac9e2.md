### Title
Unauthenticated senders can inject outputs classified under Serai's internal/offset addresses, bypassing the external-deposit source check - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner` classifies every transaction output purely by whether its `script_pubkey` appears in the registered script map (`self.scripts.get(&output.script_pubkey)`). The registered scripts include Serai's internally-derived offset addresses — including the `Branch`, `Change`, and `Forwarded` offsets used by downstream consumers — all of which are deterministic functions of the public group key (`key + G * offset`). Because the check only proves "this output pays to a script we know," not "this output came through the expected deposit path," any unprivileged third party can craft a Bitcoin transaction paying to an internal offset address and have it reported by `scan_transaction`/`scan_block` as a `ReceivedOutput` carrying that offset — exactly the same analog shape as CVE-2026-4893, where attacker-controlled packet fields (client-subnet data) cause a source/attribution check to be bypassed.

### Finding Description
`Scanner::new` seeds the map with the plain P2TR script for the group key, and `register_offset` inserts additional scripts keyed by `p2tr_script_buf(key + G * offset)`. [1](#0-0)  The scan logic then performs no provenance or context check whatsoever:

- `scan_transaction` iterates `tx.output`, looks up `script_pubkey` in `self.scripts`, and emits a `ReceivedOutput { offset, output, outpoint }`. [2](#0-1) 
- `scan_block` additionally scans the coinbase transaction, deferring maturity handling to callers. [3](#0-2) 

The offsets consumed downstream are not secret: `processor` derives them as `Secp256k1::hash_to_F(b"Serai Bitcoin Output Offset", b"branch"/"change"/"forward")`, and maps scanned outputs back to `OutputType` by the offset's scalar representation. [4](#0-3) [5](#0-4)  Since the group key is public and `register_offset` deterministically increments to the next even-Y point, an external observer can recompute every internal address. A crafted transaction paying to, e.g., the `Change` or `Forwarded` script is therefore indistinguishable to the scanner from an internally generated output — the "source check" (this output kind implies it was produced by the protocol's own spend path) is silently bypassed.

### Impact Explanation
Outputs are reported as received under an attacker-chosen internal offset, so the processor will treat externally injected funds as `Branch`, `Change`, or `Forwarded` `OutputType`s rather than `External` deposits. Only `External` outputs receive the `InInstruction`-derived `data` payload and origin attribution (`presumed_origin` is populated for all kinds, but `data` only for `External`), so injected outputs skip the deposit-data path entirely and enter flows reserved for protocol-generated outputs. [6](#0-5)  This permits misattribution of funds and injection of outputs into internal handling (branch/rotation, change, forwarded-funds accounting) at attacker-chosen amounts — including dust-level outputs used to trigger internal handling paths — constituting funds reported received under a false classification. Note: the `DUST` filter in `processor` mitigates sub-dust injection but not injection at/above dust. [7](#0-6) 

### Likelihood Explanation
The attack requires only a standard, permissionless Bitcoin transaction — the same reachability class as the dnsmasq packet in the external report. All inputs are public: the group key is the multisig's published address key, and `KEY_DST`/offset labels are protocol constants, so the internal addresses are computable by anyone. No key material, collusion, or trusted-position access is needed. The main caveat is that the concrete downstream consequence depends on how `processor` treats injected `Branch`/`Forwarded`-kind outputs (out of the strictly in-scope crates); the in-scope defect — unconditional crediting of any output matching a registered script — is confirmed in `networks/bitcoin/src/wallet/mod.rs`.

### Recommendation
Bind received outputs to their expected provenance rather than to script identity alone. Concretely: have `Scanner` expose the registered `OutputType`/purpose alongside the offset, and have `get_outputs` (or `scan_transaction` callers) reject or separately quarantine outputs claiming internal offsets that did not originate from a transaction the multisig itself produced (e.g., verify that `Change`/`Forwarded`-kind outputs appear only in transactions spending known multisig inputs, and `Branch` outputs carry the required structure). Alternatively, use per-deposit or per-purpose non-public offsets for internal addresses so external parties cannot precompute them.

### Proof of Concept
1. Observe the multisig group key `K` (public — it is the key behind the deposit address).
2. Recompute the internal offsets: `branch = Secp256k1::hash_to_F(b"Serai Bitcoin Output Offset", b"branch")` (incremented per `register_offset`'s even-Y rule), similarly `change`, `forward`. [8](#0-7) 
3. Construct `script = p2tr_script_buf(K + G * change)` and broadcast a transaction with an output `TxOut { script_pubkey: script, value: X }` with `X >= DUST`.
4. Once confirmed, `Scanner::scan_transaction` returns `ReceivedOutput { offset: change, output, outpoint }`, and `get_outputs` maps it to `OutputType::Change` — an externally created output is now classified and processed as protocol-internal change, with no External-deposit `data` requirement ever applied.     Some(Scanner { key, scripts })

  /// Register an offset to scan for.
  ///
  /// Due to Bitcoin's requirement that points are even, not every offset may be used.
  /// If an offset isn't usable, it will be incremented until it is. If this offset is already
  /// present, None is returned. Else, Some(offset) will be, with the used offset.
  ///
  /// This means offsets are surjective, not bijective, and the order offsets are registered in
  /// may determine the validity of future offsets.
  ///
  /// The offsets registered must be securely generated. Arbitrary offsets may introduce a script
  /// path into the output, allowing the output to be spent by satisfaction of an arbitrary script
  /// (not by the signature of the key).
  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

// Always construct the full scanner in order to ensure there's no collisions
fn scanner(
  key: ProjectivePoint,
) -> (Scanner, HashMap<OutputType, Scalar>, HashMap<Vec<u8>, OutputType>) {
  let mut scanner = Scanner::new(key).unwrap();
  let mut offsets = HashMap::from([(OutputType::External, Scalar::ZERO)]);

  let zero = Scalar::ZERO.to_repr();
  let zero_ref: &[u8] = zero.as_ref();
  let mut kinds = HashMap::from([(zero_ref.to_vec(), OutputType::External)]);

  let mut register = |kind, offset| {
    let offset = scanner.register_offset(offset).expect("offset collision");
    offsets.insert(kind, offset);

    let offset = offset.to_repr();
    let offset_ref: &[u8] = offset.as_ref();
    kinds.insert(offset_ref.to_vec(), kind);
  };

  register(
    OutputType::Branch,
    *BRANCH_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"branch")),
  );
  register(
    OutputType::Change,
    *CHANGE_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"change")),
  );

    OutputType::Forwarded,
    *FORWARD_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"forward")),
