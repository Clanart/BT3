## Title
Recursive `git clone` explicitly disables Git's CVE-2024-32002 clone-protection, re-enabling hook-based RCE from attacker-controlled repositories - (File: `app/src/lib/git/clone.ts`)

### Summary
`app/src/lib/git/clone.ts`'s `clone()` function always runs `git clone --recursive` while unconditionally forcing the environment variable `GIT_CLONE_PROTECTION_ACTIVE` to `'false'` [1](#0-0) . This variable is the guard that upstream Git added to close CVE-2024-32002 — a vulnerability where a maliciously crafted repository with an embedded/case-confusable submodule `.git` directory could get its hooks written into the parent working tree's real `.git/hooks` during a recursive clone, leading to hook execution (arbitrary code execution) on the victim's machine. By forcing this protection off for every clone, Desktop reintroduces exactly the condition Git's own mitigation was built to prevent, for any repository URL the app clones.

### Finding Description
The `clone()` function builds the environment for the underlying `git clone` invocation like this:

```ts
const env = {
  ...(await envForRemoteOperation(url)),
  GIT_CLONE_PROTECTION_ACTIVE: 'false',
}
...
const args = [
  '-c',
  `init.defaultBranch=${defaultBranch}`,
  'clone',
  '--recursive',
]
``` [1](#0-0) 

`--recursive` causes Git to immediately clone every submodule referenced by the (attacker-supplied) repository, and disabling the clone-protection env var removes Git's own runtime check against unsafe/embedded git directories and case-insensitive/normalizing filesystem collisions during that recursive submodule clone — the exact primitive behind CVE-2024-32002. The only other safeguard in this file, `isClonePathSensitive()`, only validates the destination directory against a fixed list of sensitive paths (home, `.ssh`, `.gnupg`, etc.) [2](#0-1)  — it does nothing to validate the *content* of the remote repository or its submodules, so it provides no protection against a malicious submodule structure.

The attacker fully controls the input to this function: `url` and the repository content come from a user-clicked "Open in Desktop" deep link (`x-github-client://openRepo/...` parsed in `parseAppURL`) [3](#0-2) , from `dispatcher.openOrCloneRepository` / `openBranchNameFromUrl` [4](#0-3) , or from the normal "Clone repository" UI flow via `AppStore._clone` → `CloningRepositoriesStore.clone` [5](#0-4) . In every case, the eventual call reaches `clone()` in `app/src/lib/git/clone.ts` with the attacker-chosen URL and the hard-coded, unconditional protection bypass.

### Impact Explanation
If Git's clone protection would have blocked or warned about a malicious repository layout (e.g., a submodule whose `.git` resolves — via symlink, case-folding, or Unicode normalization on the local filesystem — into the parent repository's real hooks directory), that protection is disabled by Desktop for every single clone. A victim who clones an attacker-hosted repository (through a normal clone, a GitHub "Open with Desktop" deep link, or a CLI `--cli-clone` invocation) can have arbitrary hook scripts placed into their local `.git/hooks`, which Git/Desktop will subsequently execute on ordinary operations (checkout, commit, merge, etc.), resulting in code execution on the victim's machine — i.e., an RCE outside of what the user explicitly authorized, achieved purely by the victim cloning a repository the attacker controls.

### Likelihood Explanation
This does not require local/physical access, admin rights, prior malware, or leaked credentials — only that the victim clones (or opens via deep link) a repository hosted by the attacker, which is a standard, expected Desktop workflow. Since the bypass is unconditional and hard-coded (not behind any feature flag or fallback path), every clone performed by Desktop is affected, and the only prerequisite for exploitation is the filesystem-specific condition (case-insensitive/normalizing filesystem, e.g. default macOS/Windows) that the underlying CVE targets.

### Recommendation
Remove the unconditional `GIT_CLONE_PROTECTION_ACTIVE: 'false'` override in `clone()` so Git's built-in clone-time protections remain active. If protection needs to be relaxed for specific, already-trusted local operations, do so narrowly and only after equivalent validation of submodule paths/hook directories is performed by Desktop itself, rather than disabling the guard for all attacker-supplied clone URLs.

### Proof of Concept
1. Attacker hosts a git repository containing a submodule crafted so that, once recursively cloned on a case-insensitive or Unicode-normalizing filesystem (default on macOS/Windows), the submodule's `.git` resolves into the parent repository's `.git/hooks` directory, planting a malicious hook (e.g. `post-checkout`).
2. Attacker distributes a normal clone URL or an `x-github-client://openRepo/<url>` deep link.
3. Victim clicks "Open in Desktop" / pastes the URL into the Clone dialog. Desktop calls `AppStore._clone` → `cloningRepositoriesStore.clone` → `clone()` in `app/src/lib/git/clone.ts`, which runs `git clone --recursive` with `GIT_CLONE_PROTECTION_ACTIVE=false`.
4. Because Git's clone protection is disabled, the malicious hook is written into the real `.git/hooks` of the cloned repository instead of being rejected/quarantined by Git.
5. On the next ordinary Desktop-triggered git operation that invokes that hook, the attacker's code executes on the victim's machine.

function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}

  /** This shouldn't be called directly. See `Dispatcher`. */
  public _clone(
    url: string,
    path: string,
    options: { branch?: string; defaultBranch?: string } = {}
  ): {
    promise: Promise<boolean>
    repository: CloningRepository
  } {
    const promise = this.cloningRepositoriesStore.clone(url, path, options)
    const repository = this.cloningRepositoriesStore.repositories.find(
      r => r.url === url && r.path === path
    )!

    promise.then(success => {
      if (success) {
        this.statsStore.recordCloneRepository()
      }
    })

    return { promise, repository }
  }
