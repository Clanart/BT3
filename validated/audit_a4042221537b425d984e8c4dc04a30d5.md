### Title
SSRF via attacker-controlled DataLayer mirror URLs consumed by peer subscribers - ([File: chia/data_layer/data_layer.py])

### Summary
Any unprivileged DataLayer client can publish arbitrary URLs on-chain via `add_mirror`, which the DataLayer service later dereferences with unauthenticated outbound HTTP(S) requests when other nodes sync that store, without any URL/host validation.

### Finding Description
`DataLayerRpcApi.add_mirror` accepts a raw list of `urls` from the RPC caller and forwards them unchanged to `DataLayer.add_mirror`, which publishes them on-chain in a mirror coin via `dl_new_mirror`/`create_new_mirror` (memos containing `launcher_id` and each url). [1](#0-0) [2](#0-1) 

Any DataLayer node that subscribes to that store (or discovers the store via chain state) later runs `fetch_and_validate()`, which reads `server_info.url` for each mirror registered for the store, and unconditionally issues outbound requests to it — either directly via `http_download()` or, if a downloader plugin is configured, via an `aiohttp` `POST` to `downloader.url + "/download"` carrying the mirror URL in the JSON payload. [3](#0-2) [4](#0-3) 

There is no validation restricting the mirror URL to `http(s)` schemes pointed at legitimate hosts, no denylist for private/link-local/metadata IP ranges (e.g. `127.0.0.1`, `169.254.169.254`, internal service ports), and the URL is fully attacker-chosen by whichever wallet owns the DataLayer singleton that calls `add_mirror`. The project's own internal documentation explicitly calls out mirror URLs as an external trust boundary: "Mirror URLs, plugins, or static file names" must never be treated as trusted data sources, and "Plugin and mirror URLs are external trust inputs." [5](#0-4) [6](#0-5) 

This mirrors the iTop CVE-2024-51740 pattern: a low-privileged actor supplies unvalidated input (there, a PHP class name to instantiate; here, a URL to register) that a privileged component (there, the form-manager instantiation logic; here, every peer's `DataLayer` sync loop) later uses to perform a server-initiated network request without validating the target.

### Impact Explanation
Any node running the DataLayer service and subscribed to a store — or simply owning/tracking that singleton — will make an outbound network request to a URL fully controlled by whoever added the mirror, on a recurring background schedule (`periodically_manage_data()` → `update_subscription()` → `fetch_and_validate()`). This allows an unprivileged DataLayer participant to force victim nodes to issue HTTP requests to internal-only endpoints (cloud metadata services, internal admin panels, other local ports), potentially exfiltrating internal responses, probing internal network topology, or triggering side effects on internal HTTP services reachable from the victim's network. The impact is bounded to whatever an outbound GET/POST can achieve against the reachable internal targets and does not directly redirect funds, but it is a genuine server-side request forgery against arbitrary chia-blockchain nodes running DataLayer.

### Likelihood Explanation
Likelihood is moderate: exploitation only requires operating a DataLayer wallet/singleton (something any user can create) and calling the standard `add_mirror` RPC/CLI with an attacker-chosen URL; no special privileges, signatures beyond the owner's own coin spend, or race conditions are needed. The victim side, however, requires that node to run the DataLayer service and actively subscribe to (or track) the malicious store, which is an opt-in action by the victim operator, moderating overall likelihood.

### Recommendation
Validate and restrict mirror URLs before persisting/using them: enforce an allow-list of schemes (`http`/`https` only), and before issuing any outbound request in `fetch_and_validate()`/`http_download()`, resolve and reject requests to private, loopback, link-local, and cloud-metadata address ranges (unless explicitly configured otherwise by the operator). Consider requiring explicit per-node opt-in/allow-listing of mirror hosts, and apply the same validation to plugin-provided URLs (`PluginRemote.url`) used in `download_file()`.

### Proof of Concept
1. Attacker creates/owns a DataLayer store (`create_data_store`) and calls `add_mirror` with `urls=["http://169.254.169.254/latest/meta-data/", "http://internal-admin.local:8080/"]`, publishing the mirror coin on-chain. [1](#0-0) 
2. A victim node subscribes to (or otherwise tracks) the attacker's store id.
3. The victim's `periodically_manage_data()` loop eventually calls `fetch_and_validate()` for that store, which iterates `servers_info` (populated from the attacker's mirror URLs) and calls `insert_from_delta_file(... server_info=server_info ...)`. [3](#0-2) 
4. `insert_from_delta_file`/`download_file` issues an outbound HTTP(S) request to the attacker-controlled URL from the victim node's network context, with no host/IP restriction. [4](#0-3)

async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True

    log.info(f"Using downloader {downloader} for store {store_id.hex()}.")
    request_json = {
        "url": server_info.url,
        "client_folder": str(client_foldername),
        "filename": filename,
        "group_files_by_store": group_downloaded_files_by_store,
        "max_delta_file_size": max_delta_file_size,
    }
    try:
        async with aiohttp.ClientSession() as session:
            async with session.post(
                downloader.url + "/download",
                json=request_json,
                headers=downloader.headers,
                timeout=timeout,
            ) as response:
                res_json = await response.json()
                assert isinstance(res_json["downloaded"], bool)
                return res_json["downloaded"]
    except (asyncio.TimeoutError, aiohttp.ClientError) as e:
        log.error(f"download_file could not get response from plugin {downloader}: {type(e).__name__}: {e}")
        return False
