### Title
Forged `ReceivedOutput` bytes overstate spendable Bitcoin inputs - (File: `networks/bitcoin/src/wallet/mod.rs`)

### Summary
`ReceivedOutput::read` accepts an attacker-supplied `OutPoint` and `TxOut` without proving that the referenced UTXO exists or that it has the claimed value. `SignableTransaction::new` then trusts the serialized value when calculating available funds and commits that value into the Taproot sighash. A forged input can therefore be reported and scheduled as spendable even though consensus will reject its spend.

### Finding Description
`ReceivedOutput::read` deserializes only the offset, `TxOut`, and `OutPoint`; it performs no lookup of the outpoint and no comparison against the UTXO's consensus amount or script. [1](#0-0) 

The transaction builder sums `input.output.value`, uses `input.outpoint` as the transaction input, and stores the attacker-controlled `TxOut` in `prevouts`. [2](#0-1) [3](#0-2) 

Signing commits to `Prevouts::All(&self.tx.prevouts)`, including the forged amount. [4](#0-3)  Although `multisig` verifies that the supplied script equals the expected offset-key script, it cannot verify that the claimed outpoint or amount exists on chain. [5](#0-4) 

This is analogous to crediting the requested transfer amount rather than the amount actually received: the decoded object represents a claimed deposit, while nothing establishes that the claimed UTXO and value were actually created.

### Impact Explanation
An attacker who can supply serialized `ReceivedOutput` data can cause phantom Bitcoin funds to be treated as available. The resulting transaction either references a nonexistent outpoint or commits to an incorrect prevout amount, so Bitcoin consensus rejects it despite the input having been counted toward payments, fees, and change.

If a real UTXO is referenced with an altered amount, the threshold signature is still produced over the false amount and remains invalid. If an arbitrary outpoint is referenced, the transaction is invalid regardless of the signature. This can lock scheduling/accounting state around funds that cannot actually be spent.

### Likelihood Explanation
Exploitation requires an attacker-controlled serialized `ReceivedOutput` to reach `ReceivedOutput::read`; legitimately scanner-produced outputs use the consensus transaction's actual `TxOut` and outpoint. [6](#0-5)  The issue is therefore conditional on that untrusted read path being exposed, but no private key, validator compromise, malformed curve point, or Bitcoin protocol violation is required to construct the bytes.

### Recommendation
Treat `ReceivedOutput` as an untrusted claim after deserialization. Before scheduling or signing, retrieve the referenced outpoint from the chain and verify that it exists, is unspent, has exactly the decoded `TxOut`'s value and script, and is spendable under the expected offset key. Prefer storing a canonical scanner-derived identifier and re-fetching the consensus output rather than accepting a serialized `TxOut` as authoritative.

### Proof of Concept
The following constructs syntactically valid bytes for a nonexistent outpoint claiming one million sats. The output script matches the threshold key, so it passes the offset/script check, while the outpoint and amount are fabricated:

```rust
use bitcoin::{
  consensus::encode::serialize,
  hashes::Hash,
  Amount, OutPoint, TxOut, Txid,
};
use bitcoin_serai::wallet::{p2tr_script_buf, ReceivedOutput, SignableTransaction};
use frost::curve::Secp256k1;
use k256::Scalar;

fn forged_input(
  keys: &frost::ThresholdKeys<Secp256k1>,
) -> ReceivedOutput {
  // The correct script causes SignableTransaction::multisig's script check to pass.
  let script = p2tr_script_buf(keys.group_key()).unwrap();

  // This UTXO does not need to exist; ReceivedOutput::read only checks encoding.
  let forged_txout = TxOut {
    value: Amount::from_sat(1_000_000),
    script_pubkey: script,
  };
  let forged_outpoint = OutPoint {
    txid: Txid::from_raw_hash(bitcoin::hashes::sha256d::Hash::from_byte_array([0x42; 32])),
    vout: 0,
  };

  let mut encoded = Scalar::ZERO.to_bytes().to_vec();
  encoded.extend(serialize(&forged_txout));
  encoded.extend(serialize(&forged_outpoint));

  let input = ReceivedOutput::read(&mut encoded.as_slice()).unwrap();
  assert_eq!(input.value(), 1_000_000);
  input
}
```

Passing the result to `SignableTransaction::new` makes the phantom million sats count toward `input_sat`, and signing commits the fabricated prevout through `Prevouts::All`. The resulting transaction cannot be confirmed because its claimed input is absent from the UTXO set. [7](#0-6) [4](#0-3)
