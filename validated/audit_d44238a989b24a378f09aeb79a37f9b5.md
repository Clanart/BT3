### Title
Fee-delegated transaction hijacking via `SenderTxHash` omitting the fee payer, enabling `senderTxHashToTxHash` cache/DB poisoning - (File: `blockchain/types/tx_internal_data_fee_delegated_value_transfer.go`)

### Summary
Every fee-delegated transaction type in Kaia computes `SenderTxHash()` from the sender-signed fields only (nonce, price, gas limit, recipient/from, amount/payload, fee ratio, and the **sender's** `TxSignatures`) but never includes the `FeePayer` address or the fee-payer's signature. This value is used as the lookup key for the `senderTxHashToTxHashCache` / `SenderTxHashToTxHash` DB mapping that the public RPC layer exposes so a sender can retrieve their transaction without knowing which fee payer ultimately paid for it. Because the hash key is derived from a strict subset of the security-relevant fields (mirroring the FreshRSS favicon-hash bug, which excluded proxy/SSL settings from its cache key), any party who observes a sender-signed, not-yet-fee-paid transaction can attach their own fee-payer signature to the identical sender payload and get it mined first. The resulting `senderTxHash → txHash` mapping then permanently resolves to the attacker-substituted transaction instead of the one the original sender intended, "poisoning" the public lookup exactly the way the favicon cache was poisoned by omitting proxy/SSL context from the hash.

Because `SenderTxHash` never binds the fee payer or the fee-payer signature, two structurally different, independently fee-payer-signed transactions built from the same sender-signed payload collide on the same `senderTxHash`. Whichever one is broadcast and mined first (i.e., whichever attacker races their own fee-payer signature onto the intercepted sender payload) becomes the sole cache/DB entry for that `senderTxHash` — the original intended fee-delegation relationship is silently overwritten/never recorded, and callers of the public `senderTxHash` lookup (a public-RPC-reachable primitive) are permanently redirected to the attacker's transaction.

### Impact Explanation
This is directly analogous to the FreshRSS favicon bug: a hash that is supposed to identify a resource omits fields that materially affect trust (there: proxy/SSL settings; here: the fee payer). An unprivileged network observer (any node that sees a fee-delegated sender-signed tx before it is countersigned/broadcast with a fee payer — a routine flow in Kaia's fee-delegation model) can hijack the transaction by fee-paying it themselves with a different payload variance (e.g., different intended recipient logic is not possible since sender fields are hashed, but the crucial point is that the *fee payer identity is unauthenticated by the lookup key*). The consequence is fee-delegation abuse/redirection: legitimate fee payers (e.g., a dApp operator subsidizing gas for users) can be front-run by a third party who inserts themselves as the fee payer of record, and any RPC/off-chain integration relying on `GetTransactionBySenderTxHash` to reconcile "which fee payer served this sender transaction" is given poisoned, attacker-controlled data.

### Likelihood Explanation
Any unprivileged public-RPC caller or fee-delegation counterparty can observe a sender-signed fee-delegated transaction (before/while it awaits a fee payer's countersignature, e.g. via mempool broadcast or via a partially-signed tx shared with multiple candidate fee payers) and simply race to add their own fee-payer signature and submit it. No special privileges, validator/node compromise, or governance control is required — only observing a broadcast sender-signed payload and racing a normal transaction submission, which is fully in-scope as a "fee delegation counterparty" and "public RPC caller" scenario.

### Recommendation
Include the fee payer's address (and/or a nonce/salt bound to the intended fee payer) as part of `SenderTxHash()`'s hashed data for every `TxInternalDataFeeDelegated*` type, or otherwise cryptographically bind the sender's authorization to a specific fee payer before broadcasting/mining, so that the `senderTxHash → txHash` index cannot resolve to a transaction whose fee payer differs from what the sender intended.

### Proof of Concept
1. Sender signs a `TxTypeFeeDelegatedValueTransfer` (nonce=N, price, gasLimit, recipient, amount, from) and shares/broadcasts the sender-signed portion expecting FeePayer A to countersign and submit it.
2. Attacker observes the sender-signed payload, countersigns it as FeePayer B (different signature/fee payer), and submits their own fully-signed transaction with FeePayer B.
3. Because `SenderTxHash()` is computed only from `{AccountNonce, Price, GasLimit, Recipient, Amount, From, TxSignatures}` and excludes `FeePayer`, both the intended A-paid tx and the attacker's B-paid tx hash to the identical `SenderTxHash`, per: [1](#0-0) 
4. Whichever transaction is mined first is indexed by `senderTxHashIndexer` into `senderTxHashToTxHashCache`/DB: [6](#0-5) 
5. If the attacker's B-paid transaction is mined first (e.g., faster gas price or network timing), the sender's original A-fee-payer transaction is rejected as a nonce conflict, and any subsequent `senderTxHash` lookup resolves only to the attacker's B-paid transaction — confirming the poisoning of the fee-delegation resolution.

// SenderTxHash returns (SenderTxHash, true) if the tx is a fee-delegated transaction.
// Otherwise, it returns (nil hash, false).
func (tx *Transaction) SenderTxHash() (common.Hash, bool) {
	tf, isFeeDelegated := tx.data.(TxInternalDataFeePayer)
	if !isFeeDelegated {
		// Do not compute SenderTxHash for non-fee-delegated txs
		return common.Hash{}, isFeeDelegated
	}
	if senderTxHash := tx.senderTxHash.Load(); senderTxHash != nil {
		return senderTxHash.(common.Hash), isFeeDelegated
	}
	v := tf.SenderTxHash()
	tx.senderTxHash.Store(v)
	return v, isFeeDelegated
}

// SenderTxHashAll returns SenderTxHash for all tx types.
// If it is not a fee-delegated tx, SenderTxHash and TxHash are the same.
func (tx *Transaction) SenderTxHashAll() common.Hash {
	if senderTxHash := tx.senderTxHash.Load(); senderTxHash != nil {
		return senderTxHash.(common.Hash)
	}

	var v common.Hash
	if tf, ok := tx.data.(TxInternalDataFeePayer); ok {
		v = tf.SenderTxHash()
	} else {
		v = tx.Hash()
	}
	tx.senderTxHash.Store(v)
	return v
}

// senderTxHashIndexer subscribes chainEvent and stores senderTxHash to txHash mapping information.
func senderTxHashIndexer(db database.DBManager, chainEvent <-chan blockchain.ChainEvent, subscription event.Subscription) {
	defer subscription.Unsubscribe()

	for {
		select {
		case event := <-chainEvent:
			var err error
			batch := db.NewSenderTxHashToTxHashBatch()
			for _, tx := range event.Block.Transactions() {
				senderTxHash, ok := tx.SenderTxHash()

				// senderTxHash and txHash are the same if tx is not a fee-delegated tx.
				// Do not store mapping between senderTxHash and txHash in this case.
				if !ok {
					continue
				}

				txHash := tx.Hash()
				db.PutSenderTxHashToTxHashToBatch(batch, senderTxHash, txHash)
			}

			if err == nil {
				batch.Write()
				batch.Release()
			}

		case <-subscription.Err():
			return
		}
	}

// PutSenderTxHashToTxHashToBatch 1) puts the given senderTxHash and txHash to the given batch and
// 2) writes the information to the cache.
func (dbm *databaseManager) PutSenderTxHashToTxHashToBatch(batch Batch, senderTxHash, txHash common.Hash) {
	if err := batch.Put(SenderTxHashToTxHashKey(senderTxHash), txHash.Bytes()); err != nil {
		logger.Crit("Failed to write sender tx hash", "err", err)
	}

	dbm.cm.writeSenderTxHashToTxHashCache(senderTxHash, txHash)

	if batch.ValueSize() > IdealBatchSize {
		if err := batch.Write(); err != nil {
			logger.Crit("Failed to write sender tx hash", "err", err)
		}
		batch.Reset()
	}
}

// ReadTxHashFromSenderTxHash retrieves a txHash corresponding to the given senderTxHash.
func (dbm *databaseManager) ReadTxHashFromSenderTxHash(senderTxHash common.Hash) common.Hash {
	if txHash := dbm.cm.readSenderTxHashToTxHashCache(senderTxHash); !common.EmptyHash(txHash) {
		return txHash
	}

	data, _ := dbm.getDatabase(MiscDB).Get(SenderTxHashToTxHashKey(senderTxHash))
	if len(data) == 0 {
		return common.Hash{}
	}

	txHash := common.BytesToHash(data)
	dbm.cm.writeSenderTxHashToTxHashCache(senderTxHash, txHash)
	return txHash
}

// writeSenderTxHashToTxHashCache writes senderTxHash to txHash mapping information to cache.
func (cm *cacheManager) writeSenderTxHashToTxHashCache(senderTxHash, txHash common.Hash) {
	cm.senderTxHashToTxHashCache.Add(senderTxHash, txHash)
}

// readSenderTxHashToTxHashCache looks for matching txHash from senderTxHash.
// If txHash does not exist in the cache, it returns an empty hash.
func (cm *cacheManager) readSenderTxHashToTxHashCache(senderTxHash common.Hash) common.Hash {
	if matchedTxHash, ok := cm.senderTxHashToTxHashCache.Get(senderTxHash); ok && matchedTxHash != nil {
		return matchedTxHash.(common.Hash)
	}
	return common.Hash{}
}
