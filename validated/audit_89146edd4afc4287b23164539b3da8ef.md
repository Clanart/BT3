### Title
AuctioneerSig lacks chain-ID / domain binding and is replayable across forked chains and across bids - (File: kaiax/auction/bid.go)

### Summary
`Bid.ValidateAuctioneerSig` verifies the auctioneer's approval of a bid using a bare `\x19Ethereum Signed Message:\n` hash over only the `SearcherSig` bytes, with no chain ID, verifying contract, or bid-content binding, unlike the searcher signature which is EIP-712 domain-separated by `chainId` and `verifyingContract`.

### Finding Description
The searcher signature is validated with a proper EIP-712 domain separator that includes `chainId` and `verifyingContract`: [1](#0-0) [2](#0-1) 

In contrast, the auctioneer signature is computed only over the searcher's signature bytes with a plain personal-sign style prefix, with no chain ID or domain separator at all: [3](#0-2) [4](#0-3) 

Because `GetEthSignedMessageHash()` hashes only `b.SearcherSig` (not `chainId`, not `Sender`, `To`, `Bid`, `BlockNumber`, `TargetTxHash`, etc.), the auctioneer's approval signature is bound only to the searcher signature bytes and to nothing chain-specific. This means:
1. On a chain fork/split, an `AuctioneerSig` produced on chain A remains valid and replayable verbatim on the forked chain B for the same `SearcherSig`, since no `chainId` is encoded in the signed payload (this directly mirrors the reported bug class: signed backend/operator approvals lacking `block.chainid` binding).
2. The bid pool's admission check (`bid.SearcherSig` and `bid.AuctioneerSig` must be valid, per README rule 6) relies on this weak binding as the sole authorization gate that a bid actually came from the auctioneer, before it is placed into the bid pool and later turned into an on-chain bundle transaction via `EncodeAuctionCallData`. [5](#0-4) 

### Impact Explanation
`AuctioneerSig` is the mechanism the client-side bid pool uses to trust that a bid was approved by the legitimate, on-chain-registered `Auctioneer` address before admitting it and building it into a block via the auction entry-point contract call. Because the signed digest carries no chain identifier, in the event of a Kaia network chain split (fork), any `AuctioneerSig` accepted as valid on one branch is also valid on the other branch for the same `SearcherSig` bytes. An attacker (any searcher/bid submitter reachable via the public `auction_submitBid` RPC) could capture an auctioneer-approved bid observed on one chain and resubmit the same `AuctioneerSig`+`SearcherSig` pair to the bid pool of the forked chain, potentially getting an unauthorized/duplicate auction settlement admitted and executed against different chain state, without a fresh approval from the actual auctioneer on that fork. This is a fee/auction-settlement integrity issue: it undermines the guarantee that the bid pool only executes bids the auctioneer approved specifically for that chain.

### Likelihood Explanation
Exploitation requires an actual chain split/fork event, which is not routinely occurring but is an explicit "eventual chain fork" scenario acknowledged as in-scope by the referenced bug class. Given that the signature is trivially replayable (no chain binding at all, not even implicit binding through EIP-155-style transaction signing), any occurrence of a fork immediately enables replay with no additional computation by the attacker — the attacker only needs to resubmit a previously observed bid (`targetTxRaw`, bid fields, `searcherSig`, `auctioneerSig`) via the public `auction_submitBid` RPC endpoint on the forked chain.

### Recommendation
Bind the auctioneer signature to chain-specific and bid-specific context, analogous to the searcher's EIP-712 domain separator:
- Include `chainId` (and ideally the `AuctionEntryPoint` address as `verifyingContract`) in the digest signed by the auctioneer, e.g., by hashing `(chainId, verifyingContract, SearcherSig)` or, better, migrate `ValidateAuctioneerSig`/`GetEthSignedMessageHash` to use the same EIP-712 typed-data scheme used for `ValidateSearcherSig`, so the auctioneer signature also carries the domain separator and cannot be replayed across forked or differently-configured chains.

### Proof of Concept
1. On chain A (chainId=X), a searcher submits a valid bid; the auctioneer computes `AuctioneerSig = sign(keccak256("\x19Ethereum Signed Message:\n" + len(SearcherSig) + SearcherSig))` per `Bid.GetEthSignedMessageHash`/`ValidateAuctioneerSig` [3](#0-2) .
2. A network split occurs, producing chain B with chainId=Y but the same `Auctioneer` address/key registered in the `AuctionEntryPoint` system contract state (inherited from the pre-fork state) as read via `ReadAuctioneer` [6](#0-5) .
3. An attacker resubmits the identical `(targetTxRaw, bid fields, SearcherSig, AuctioneerSig)` payload to chain B's `auction_submitBid` RPC endpoint.
4. Since `ValidateAuctioneerSig` recomputes the identical hash (no chain ID input) and recovers the same auctioneer address, the bid passes bid-pool admission on chain B despite the auctioneer never approving it there, allowing unauthorized bundle execution/settlement on the forked chain.

func (b *Bid) ValidateSearcherSig(chainId *big.Int, verifyingContract common.Address, version string) error {
	if chainId == nil {
		return ErrNilChainId
	}

	if common.EmptyAddress(verifyingContract) {
		return ErrNilVerifyingContract
	}

	digest := b.GetHashTypedData(chainId, verifyingContract, version)

	recoveredSender, err := getSigner(b.SearcherSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover searcher sig: %v", err)
	}

	if recoveredSender != b.Sender {
		return fmt.Errorf("invalid searcher sig: expected %v, calculated %v", b.Sender.String(), recoveredSender.String())
	}

	return nil
}

func (b *Bid) GetHashTypedData(chainId *big.Int, verifyingContract common.Address, version string) []byte {
	if chainId == nil {
		return nil
	}

	domain := EIP712Domain{
		EIP712DomainTypeHash: eip712TypeHash,
		NameHash:             auctionNameHash,
		VersionHash:          crypto.Keccak256Hash([]byte(version)),
		ChainId:              chainId,
		VerifyingContract:    verifyingContract,
	}

	domainSeparator := EncodeEIP712(domain)

	var structHash []byte
	if version == AuctionVersionV3 {
		structHash = EncodeEIP712(bidV3{b})
	} else if version == AuctionVersionV2 {
		structHash = EncodeEIP712(b)
	} else {
		// Unknown version: default to v2.1 typehash.
		structHash = EncodeEIP712(b)
	}

	return crypto.Keccak256([]byte{0x19, 0x01}, domainSeparator, structHash)
}

	if version == auction.AuctionVersionV3 {
		maxGasPrice := bid.MaxGasPrice
		if maxGasPrice == nil {
			maxGasPrice = new(big.Int)
		}
		input := contractsv3.IAuctionEntryPointAuctionTx{
			TargetTxHash:  bid.TargetTxHash,
			BlockNumber:   new(big.Int).SetUint64(bid.BlockNumber),
			Sender:        bid.Sender,
			To:            bid.To,
			Nonce:         new(big.Int).SetUint64(bid.Nonce),
			Bid:           bid.Bid,
			MaxGasPrice:   maxGasPrice,
			CallGasLimit:  new(big.Int).SetUint64(bid.CallGasLimit),
			Data:          bid.Data,
			SearcherSig:   bid.SearcherSig,
			AuctioneerSig: bid.AuctioneerSig,
		}
		return abiV3.Pack("call", input)
	}

	// auction.AuctionVersionV2 or unknown version: default to v2.1 ABI.
	input := contracts.IAuctionEntryPointAuctionTx{
