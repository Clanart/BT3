### Title
Synthetic ERC20/ERC721/ERC1155 Transfer logs are forged from raw wasm event attributes without verifying an actual state change occurred - ([File: app/receipt.go])

### Summary
`AddCosmosEventsToEVMReceiptIfApplicable` translates raw CosmWasm module events emitted by a CW20/CW721/CW1155 contract into synthetic Ethereum `Transfer`/`Approval` logs attached to the EVM transaction receipt, which is exposed via `eth_getLogs`/`eth_getTransactionReceipt`. The translation trusts the `action`, `from`, `to`, and `amount` fields parsed out of the wasm event attributes verbatim, rather than cross-checking them against an actual bank/CW20 balance mutation that occurred in the same execution.

### Finding Description
`app.translateCW20Event` [1](#0-0)  iterates over `app.GetActionsFromWasmEvent(ctx, wasmEvent)` and, for any action typed `mint`, `burn`, `send`, `transfer`, `transfer_from`, `send_from`, or `burn_from` with a non-nil `Amount`, unconditionally appends an `ERC20TransferTopic` log using the `From`/`To`/`Amount` values taken directly from the wasm event's attributes: [2](#0-1) . `translateCW721Event` performs the analogous construction for `transfer_nft`, `mint`, `approve`, etc., again driven purely by attribute values reported in the wasm event [3](#0-2) .

This is analogous to CVE-2018-12020: GnuPG trusted an attacker-controlled "filename" field embedded in OpenPGP data and echoed it verbatim on `--status-fd 2`, allowing an attacker to inject fabricated `GOODSIG`/`VALIDSIG` status lines that downstream consumers (e.g., mail clients) treated as authoritative signature-verification results. Here, the pipeline treats attacker-controlled wasm event attribute strings (emitted by the CW20/CW721 contract itself, under contract logic control) as authoritative proof of a token transfer, then republishes them as canonical EVM `Transfer` logs on the public JSON-RPC surface — a surface many wallets, exchanges, and bridging/indexing tools trust to represent real balance-affecting events, exactly as GnuPG's downstream consumers trusted the spoofed status codes.

### Impact Explanation
If a CW20 (or CW721/CW1155) contract that has a registered ERC20/ERC721/ERC1155 pointer emits a wasm event with `action=transfer` (or `mint`) and arbitrary `from`/`to`/`amount` attributes without a corresponding real balance change (e.g., via a custom, non-standard execute message that only emits the event but performs no actual token movement, or emits an event with inflated amount relative to the real transfer), the receipt/log surface would report a synthetic ERC20 `Transfer` event that does not correspond to reality. Off-chain consumers (exchanges crediting deposits based on `eth_getLogs`/`eth_getTransactionReceipt`, bridges, wallets) that rely on the EVM log stream as the source of truth for pointer-token balance changes could be deceived into crediting funds that never moved — a fund-loss/spoofing vector via precompile/pointer log forgery.

### Likelihood Explanation
Exploitability hinges on whether an untrusted, attacker-authored CW20/CW721/CW1155 contract can obtain (or already possess) a registered pointer and control the exact attribute contents of its emitted `wasm` event on an arbitrary execute call. I was **not able to confirm within available tool calls** whether pointer registration (`RegisterPointer`, `x/evm/keeper/pointer.go`) enforces that the underlying wasm contract conforms strictly to the standard CW20/721/1155 reference implementation (which would only emit truthful events) versus accepting any contract address supplied by a caller. If pointer registration is permissionless for arbitrary contract code, likelihood is high since any deployer can craft a contract that emits a `wasm` event with a `transfer`/`mint` action and forged `amount`/`from`/`to` fields. If registration is restricted to canonical, audited CW20/721/1155 code (or if `GetActionsFromWasmEvent` also validates the event against actual bank-module coin_spent/coin_received events), the bug class does not materialize and the report should be treated as **unconfirmed**.

### Recommendation
Cross-validate the parsed CW20/721/1155 action attributes against actual, keeper-emitted `coin_spent`/`coin_received` (for tokenfactory/bank-backed CW20) or the contract's on-chain balance/ownership state before emitting a synthetic ERC20/ERC721 log, rather than trusting `wasm` event attributes verbatim. Alternatively, restrict pointer registration in `x/evm/keeper/pointer.go` to contracts whose code hash matches a known, audited reference implementation, and add fuzz/adversarial tests where a malicious CW20 contract emits fabricated `wasm` events to confirm no spurious `Transfer` log is produced without a matching real balance mutation.

### Proof of Concept
1. Deploy a custom "CW20-like" contract that implements the minimal interface required to register an ERC20 pointer via `x/evm/keeper/pointer.go` (registration path unverified — needs confirmation it accepts arbitrary contract code).
2. Register the contract as a CW20 pointer so `GetERC20CW20Pointer(contractAddr)` resolves to `pointerAddr` [4](#0-3) .
3. Invoke an execute message on the contract that emits a `wasm` event with attributes `{action: "transfer", from: <victim>, to: <attacker>, amount: <large amount>}` without performing any real balance change.
4. Observe via `eth_getTransactionReceipt`/`eth_getLogs` that a synthetic `Transfer(from, to, amount)` log is emitted at `pointerAddr` [5](#0-4) , indistinguishable from a genuine ERC20 transfer to any off-chain consumer trusting the receipt/log stream.

**Caveat:** This finding could not be fully validated end-to-end (pointer registration access-control semantics and whether `GetActionsFromWasmEvent` performs any cross-checking were not confirmed) within the available investigation. If registration is gated to verified/canonical CW20 bytecode, this analog does not hold and should be disregarded.

func (app *App) translateCW20Event(ctx sdk.Context, wasmEvent abci.Event, pointerAddr common.Address, contractAddr string) (res []*ethtypes.Log) {
	defer func() {
		if r := recover(); r != nil {
			fmt.Printf("[Error] Panic caught during translateCW20Event: type=%T, value=%+v\n", r, r)
		}
	}()

	for _, action := range app.GetActionsFromWasmEvent(ctx, wasmEvent) {
		switch action.Type {
		case "mint", "burn", "send", "transfer", "transfer_from", "send_from", "burn_from":
			if action.Amount == nil {
				continue
			}
			res = append(res, &ethtypes.Log{
				Address: pointerAddr,
				Topics: []common.Hash{
					ERC20TransferTopic,
					action.From,
					action.To,
				},
				Data: common.BigToHash(action.Amount).Bytes(),
			})
		case "increase_allowance", "decrease_allowance":
			topics := []common.Hash{
				ERC20ApprovalTopic,
				action.Owner,
				action.Spender,
			}
			ret, err := app.WasmKeeper.QuerySmart(
				ctx,
				sdk.MustAccAddressFromBech32(contractAddr),
				[]byte(fmt.Sprintf(
					"{\"allowance\":{\"owner\":\"%s\",\"spender\":\"%s\"}}",
					app.EvmKeeper.GetSeiAddressOrDefault(ctx, common.BytesToAddress(action.Owner[:])).String(),
					app.EvmKeeper.GetSeiAddressOrDefault(ctx, common.BytesToAddress(action.Spender[:])).String())),
			)
			if err != nil {
				continue
			}
			allowanceResponse := &AllowanceResponse{}
			if err := json.Unmarshal(ret, allowanceResponse); err != nil {
				continue
			}
			res = append(res, &ethtypes.Log{
				Address: pointerAddr,
				Topics:  topics,
				Data:    common.BigToHash(allowanceResponse.Allowance.BigInt()).Bytes(),
			})
		}
	}
	return
}

func (app *App) translateCW721Event(ctx sdk.Context, wasmEvent abci.Event, pointerAddr common.Address, contractAddr string,
	ownerEventsMap map[string][]abci.Event, cw721TransferCounterMap map[string]int) (res []*ethtypes.Log) {
	for _, action := range app.GetActionsFromWasmEvent(ctx, wasmEvent) {
		switch action.Type {
		case "transfer_nft", "send_nft", "burn":
			if action.TokenId == nil {
				continue
			}
			sender := action.Sender
			ownerEventKey := getOwnerEventKey(contractAddr, action.TokenId.String())
			var currentCounter int
			if c, ok := cw721TransferCounterMap[ownerEventKey]; ok {
				currentCounter = c
			}
			cw721TransferCounterMap[ownerEventKey] = currentCounter + 1
			if ownerEvents, ok := ownerEventsMap[ownerEventKey]; ok {
				if len(ownerEvents) > currentCounter {
					ownerSeiAddrStr := string(ownerEvents[currentCounter].Attributes[2].Value)
					if ownerSeiAddr, err := sdk.AccAddressFromBech32(ownerSeiAddrStr); err == nil {
						ownerEvmAddr := app.EvmKeeper.GetEVMAddressOrDefault(ctx, ownerSeiAddr)
						sender = common.BytesToHash(ownerEvmAddr[:])
					} else {
						logger.Error("Translate CW721 error: invalid bech32 owner", "address", ownerSeiAddrStr, "err", err)
					}
				} else {
					logger.Error("Translate CW721 error: insufficient owner events", "key", ownerEventKey, "counter", currentCounter, "events", len(ownerEvents))
				}
			} else {
				logger.Error("Translate CW721 error: owner event not found", "key", ownerEventKey)
			}
			res = append(res, &ethtypes.Log{
				Address: pointerAddr,
				Topics: []common.Hash{
					ERC721TransferTopic,
					sender,
					action.Recipient,
					common.BigToHash(action.TokenId),
				},
				Data: EmptyHash.Bytes(),
			})
		case "mint":
			if action.TokenId == nil {
				continue
			}
			res = append(res, &ethtypes.Log{
				Address: pointerAddr,
				Topics: []common.Hash{
					ERC721TransferTopic,
					EmptyHash,
					action.Owner,
					common.BigToHash(action.TokenId),
				},
				Data: EmptyHash.Bytes(),
			})
