[1](#0-0) ### Title
Invalid DKG share PoPs can leak reusable ECDH blame keys before verification - ([File: crypto/dkg/pedpop/src/lib.rs])

### Summary
`KeyMachine::calculate_share` can return an `EncryptionKeyProof` before verifying the ciphertext’s proof-of-possession, allowing an attacker to force disclosure of the ECDH output for a previously observed encryption key. [1](#0-0) [2](#0-1) 

### Finding Description
`EncryptedMessage` explicitly includes a PoP because copying another message’s ephemeral key could otherwise cause a blame proof to reveal the ECDH output and decrypt the copied message. [3](#0-2) 

`EncryptedMessage::read` accepts attacker-controlled `key`, `pop`, and ciphertext fields without validating the PoP. [4](#0-3) 

During `calculate_share`, `Encryption::decrypt` queues the PoP signature for batch verification, but immediately computes `ecdh(self.enc_key, msg.key)`, decrypts the ciphertext, and constructs an `EncryptionKeyProof` containing that ECDH point. [5](#0-4) [2](#0-1) 

If the decrypted bytes are not a canonical scalar, `calculate_share` immediately returns `PedPoPError::InvalidShare` with `blame: Some(blame)`, before the queued PoP signature is ever batch-verified. [1](#0-0) [6](#0-5) 

The serialized `EncryptionKeyProof` exposes the ECDH point and a DLEq proof linking it to the victim’s registered encryption key and the attacker-selected message key. [7](#0-6) [8](#0-7) 

### Impact Explanation
An attacker can copy the ephemeral `key` from an observed honest `EncryptedMessage`, attach an invalid PoP and random ciphertext, and submit it as a DKG share to the same victim. [9](#0-8) [4](#0-3) 

When the forged ciphertext decrypts to non-canonical scalar bytes, the victim returns a blame proof even though the PoP is invalid. [1](#0-0) 

`decrypt_with_proof` demonstrates that `proof.key` is the usable shared ECDH point: it verifies the DLEq and then feeds `proof.key` into the message cipher to decrypt the supplied message. [10](#0-9) [11](#0-10) 

Because the copied `msg.key` is the same key used by the honest ciphertext, publication of the blame proof lets the attacker derive the same ChaCha20 stream and recover the honest sender’s encrypted secret share. [12](#0-11) [11](#0-10) 

Repeated against enough DKG share messages and recipients, this compromises confidential secret shares and can progress to threshold key-share recovery, matching the protocol’s own warning that revealing such ECDH keys exposes messages. [13](#0-12) [3](#0-2) 

### Likelihood Explanation
The attacker only needs to observe a prior encrypted share message and cause the victim to process a malformed share through the public `calculate_share` path. [9](#0-8) 

The probability that random decrypted bytes fail canonical scalar decoding depends on the field; for Ristretto’s roughly `2^252` scalar order, random 32-byte plaintext is non-canonical with probability approximately `15/16`. [1](#0-0) 

If the forged plaintext is canonical, the batch verifier later rejects the invalid PoP as a decryption failure and returns no blame proof, but the attacker can retry with another ciphertext on a subsequent DKG attempt. [14](#0-13) 

### Recommendation
Do not generate or expose an `EncryptionKeyProof` until the message PoP has been verified. [5](#0-4) 

Split verification into two phases: first batch-verify every `EncryptedMessage` PoP, then decrypt and queue share-statement verification only for messages whose PoPs passed. [15](#0-14) 

Alternatively, retain pending blame proofs internally and attach one only after confirming that the PoP succeeded and the decrypted share or scalar serialization failed. [14](#0-13) 

### Proof of Concept
1. Observe an honest `EncryptedMessage<C, SecretShare<C::F>>` addressed to the victim and extract its serialized `key` bytes.
2. Construct a serialized malicious message using the same `key`, a canonically encoded but invalid `SchnorrSignature` such as identity/zero values, and fresh random ciphertext bytes of the secret-share length.
3. Submit the bytes to the victim’s `KeyMachine::calculate_share` input map; `read` accepts the fields, and `decrypt` derives the ECDH proof before PoP verification. [4](#0-3) [2](#0-1) 
4. If decryption produces non-canonical scalar bytes, `calculate_share` returns `InvalidShare { blame: Some(proof) }` without first rejecting the forged PoP. [1](#0-0) 
5. Serialize the returned `EncryptionKeyProof`; its `key` is the ECDH output that decrypts any ciphertext using the copied message key, including the original honest share ciphertext. [8](#0-7) [11](#0-10)
