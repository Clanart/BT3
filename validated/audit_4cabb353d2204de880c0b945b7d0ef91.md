### Title
EIP-712 bid signature does not bind `MaxGasPrice`, letting an unprivileged submitter alter a signed auction bid without invalidating either signature - ([File: kaiax/auction/eip712.go], [File: kaiax/auction/bid.go], [File: kaiax/auction/impl/bid_pool.go])

### Summary
The reported JOJO bug is a class of "signer intent not fully bound by the signature" — the signer signs an order without being able to express a constraint (maker-only), and the execution layer is free to reinterpret an unsigned/underspecified attribute of the order (its role), silently changing settlement (fee) outcomes. The same bug class exists in Kaia's `kaiax/auction` module: the searcher's EIP-712 signature over a `Bid` (v2.1 typehash) omits the `MaxGasPrice` field entirely, and the auctioneer's signature only covers the raw `SearcherSig` bytes rather than the bid content. As a result, `MaxGasPrice` is a value that is transmitted and stored in `BidData` but is not cryptographically bound by either signature for v2.1 bids, so any public caller of `auction_submitBid` can take a previously-observed valid `(BidData, SearcherSig, AuctioneerSig)` tuple, splice in an arbitrary `MaxGasPrice`, and have it accepted by the bid pool as a fully signature-valid bid.

### Finding Description
`Bid.EncodeData()` (v2.1 typehash) explicitly excludes `MaxGasPrice` from the EIP-712 struct hash: [1](#0-0) 
Only the v3.0 branch (`bidV3.EncodeData`) folds `MaxGasPrice` into the signed digest: [2](#0-1) 

`GetHashTypedData` selects the typehash purely based on the pool's currently observed on-chain `AuctionVersion` string, defaulting to the v2.1 (no-`MaxGasPrice`) hash for any unrecognized/legacy version: [3](#0-2) 

Signature verification for a bid consists of two independent checks:
1. `ValidateSearcherSig` recomputes the EIP-712 digest from the *current* bid fields (excluding `MaxGasPrice` in v2.1) and checks it recovers to `bid.Sender`: [4](#0-3) 
2. `ValidateAuctioneerSig` verifies a signature over `GetEthSignedMessageHash()`, which hashes **only the `SearcherSig` bytes**, not any bid content: [5](#0-4) [6](#0-5) 

Both checks are invoked together in `validateBidSigs`, which is the sole cryptographic gate applied by the bid pool before a bid is admitted: [7](#0-6) 

Because neither check depends on `MaxGasPrice` when the pool is operating in v2.1 mode, an attacker who has observed any legitimately signed `(BidData, SearcherSig, AuctioneerSig)` — e.g. via the `auction_submitBid` RPC being public-facing input, P2P bid gossip (`HandleBid`), or simply re-submitting their own past bid with a modified field — can construct a new `BidInput` with an arbitrary `MaxGasPrice` value while reusing the original `SearcherSig`/`AuctioneerSig` untouched. `ToBid` happily carries this attacker-chosen value into the `BidData`: [8](#0-7) 
`validateBid` computes `bid.Hash()` over the full `BidData` (including `MaxGasPrice`) via RLP, so the tampered bid is treated as a brand-new, distinct bid and is not rejected as a duplicate: [9](#0-8) [10](#0-9) 

This is the direct analog of the JOJO issue: the signer (searcher) has no way to bind a materially significant execution parameter (`MaxGasPrice`) into their authorization, and the party that submits/executes the order (any RPC caller, analogous to the "taker" in JOJO who unilaterally decides how a maker-only order gets executed) can freely choose that parameter's value while the signature checks still pass.

### Impact Explanation
`MaxGasPrice` is precisely the searcher's expressed cap on gas price exposure for the bid execution (as evidenced by its inclusion in the v3.0 typehash and its propagation into the on-chain `call` payload via `EncodeAuctionCallData`): [11](#0-10) 
Since the field is unauthenticated under v2.1, an unprivileged actor can inject or strip a `MaxGasPrice` value the searcher never agreed to while producing a bid the node treats as fully valid (passing both `ValidateSearcherSig` and `ValidateAuctioneerSig`). This is analogous to the JOJO issue's impact: a signed authorization is executed under different economic terms than the signer intended, because the signature does not cover a field that changes settlement behavior. Concretely this can be leveraged to submit forged bids into the bid pool bypassing the intended cryptographic guarantee that both the searcher and auctioneer approved *all* the material terms of the bid, corrupting the pool's admission integrity and enabling downstream fee/gas-related abuse once processed by the `AuctionEntryPoint` contract logic that consumes `MaxGasPrice`.

### Likelihood Explanation
The bid pool and `auction_submitBid` RPC (`kaiax/auction/impl/api.go` `APIs()`) are reachable via a public-facing endpoint reachable by any unprivileged caller, and bids are also broadcast/handled over P2P (`HandleBid`), so an attacker only needs to observe one valid bid (their own, or one seen in the pool/gossip) to reuse its signatures with a modified `MaxGasPrice`. No validator, node-operator, or cryptographic-key compromise is required — only knowledge of a previously valid signed bid, which is by design publicly transmittable.

### Recommendation
Always include `MaxGasPrice` in the EIP-712 struct hash regardless of contract version (or reject/zero it out and re-verify consistently when the version doesn't support it), and change `ValidateAuctioneerSig` to sign over the full bid content (or at minimum a hash that includes all fields, not just `SearcherSig` bytes), so that no field of `BidData` can be altered post-signature without invalidating either signature.

### Proof of Concept
1. Attacker observes (or is themselves) a searcher who legitimately submits a v2.1 bid via `auction_submitBid`, obtaining a valid `(BidData, SearcherSig, AuctioneerSig)` tuple where `MaxGasPrice` is unset/zero.
2. Attacker crafts a new `BidInput` identical in all EIP-712-covered fields (`TargetTxHash, BlockNumber, Sender, To, Nonce, Bid, CallGasLimit, Data`) but sets `MaxGasPrice` to an arbitrary nonzero value, keeping the same `SearcherSig`/`AuctioneerSig` bytes (`kaiax/auction/impl/api.go` `ToBid`).
3. Submit this bid via `auction_submitBid`. `validateBidSigs` (`kaiax/auction/impl/bid_pool.go:397-419`) calls `ValidateSearcherSig`, which recomputes the v2.1 digest — unaffected by `MaxGasPrice` (`kaiax/auction/eip712.go:75-86`) — and succeeds; then `ValidateAuctioneerSig`, which only hashes `SearcherSig` bytes (`kaiax/auction/bid.go:52-55,117-130`) and also succeeds.
4. The tampered bid, with attacker-controlled `MaxGasPrice`, is accepted into the pool as a new, distinct bid (different `Hash()` due to RLP over full `BidData`), despite the searcher never having authorized that value.

func (b *Bid) ValidateSearcherSig(chainId *big.Int, verifyingContract common.Address, version string) error {
	if chainId == nil {
		return ErrNilChainId
	}

	if common.EmptyAddress(verifyingContract) {
		return ErrNilVerifyingContract
	}

	digest := b.GetHashTypedData(chainId, verifyingContract, version)

	recoveredSender, err := getSigner(b.SearcherSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover searcher sig: %v", err)
	}

	if recoveredSender != b.Sender {
		return fmt.Errorf("invalid searcher sig: expected %v, calculated %v", b.Sender.String(), recoveredSender.String())
	}

	return nil
}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}

		BlockNumber:   bidInput.BlockNumber,
		Sender:        bidInput.Sender,
		To:            bidInput.To,
		Nonce:         bidInput.Nonce,
		Bid:           bidInput.Bid.ToInt(),
		CallGasLimit:  bidInput.CallGasLimit,
		Data:          bidInput.Data,
		SearcherSig:   bidInput.SearcherSig,
		AuctioneerSig: bidInput.AuctioneerSig,
	}
	if bidInput.MaxGasPrice != nil {
		bidData.MaxGasPrice = bidInput.MaxGasPrice.ToInt()
	}
	return &auction.Bid{BidData: bidData}
}
