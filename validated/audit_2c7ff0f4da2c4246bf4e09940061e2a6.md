### Title
Encrypted share oracle reveals an ECDH key before proof-of-possession verification - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
`Encryption::decrypt` decrypts an attacker-supplied `EncryptedMessage` and returns an `EncryptionKeyProof` before the queued Schnorr proof-of-possession has actually been verified. `KeyMachine::calculate_share` can therefore return that blame proof early when the decrypted share is not a canonical scalar, before batch verification rejects the forged message. A participant can reuse the per-message key from someone else's encrypted share, submit malformed ciphertexts until decryption yields a non-canonical scalar, obtain the shared ECDH key through the emitted blame proof, and decrypt the copied honest share.

### Finding Description
`EncryptedMessage::read` accepts the message key, Schnorr PoP, and ciphertext from serialized protocol input without performing authentication during parsing. [1](#0-0)  During share calculation, `Encryption::decrypt` queues `msg.pop` for later batch verification, but immediately computes `key = ecdh(self.enc_key, msg.key)`, decrypts the ciphertext, and returns an `EncryptionKeyProof` containing that shared key. [2](#0-1)  `KeyMachine::calculate_share` then attempts `C::F::from_repr` on the decrypted bytes and returns `PedPoPError::InvalidShare` with `blame: Some(blame)` before `batch.verify_with_vartime_blame` has established that the PoP is valid. [3](#0-2) 

The PoP binds the sender and ciphertext through `pop_challenge`, so an attacker cannot validly sign a copied victim ciphertext as a different sender. [4](#0-3)  However, that check happens too late to protect the ECDH result: malformed ciphertext that decrypts to a non-canonical scalar exits through the scalar-decoding branch before the queued PoP failure is evaluated. [5](#0-4) 

### Impact Explanation
A malicious DKG participant can recover another participant's encrypted secret share. They copy the victim message's `key` and ciphertext into their own serialized `EncryptedMessage`, then vary the ciphertext. For most random 32-byte field representations, the decrypted bytes will be non-canonical for a roughly 252-bit scalar field, causing the victim's node to emit an `EncryptionKeyProof` for the copied message key. That proof reveals the ECDH point used as the ChaCha20 key source, after which the attacker can decrypt the original copied ciphertext and recover the victim's contributed secret share. This is unauthorized disclosure of DKG share material and can compromise the generated threshold key when combined with other protocol shares.

### Likelihood Explanation
The attack only requires network messages under the attacker's participant identity: serialized `EncryptedMessage` values supplied to `calculate_share`. No private key, validator privilege, or protocol collusion is needed beyond being a DKG participant able to send a share. A random ciphertext has a substantial chance of decrypting to a non-canonical scalar, so the oracle generally does not require an impractical number of attempts. Once one non-canonical decryption occurs, the blame proof exposes the ECDH key needed to decrypt the copied victim ciphertext.

### Recommendation
Do not decrypt or create `EncryptionKeyProof`s until the message PoP has passed verification. Split `Encryption::decrypt` into an authentication step that verifies `msg.pop` for `from`, followed by decryption only after successful verification. Alternatively, perform PoP verification synchronously before computing `ecdh`, rather than queueing it behind scalar decoding. Also ensure `calculate_share` cannot attach a blame proof to a message whose PoP has not already been accepted.

### Proof of Concept
1. Victim `A` sends recipient `B` an `EncryptedMessage` containing ephemeral public key `K_A`, valid PoP, and ciphertext `C_A`.
2. Attacker `E` observes that serialized message and constructs `EncryptedMessage { key: K_A, pop: invalid_signature, msg: C_E }`, choosing arbitrary `C_E` while reusing `K_A`.
3. `E` submits this message to `B` as participant `E`.
4. `B` calls `EncryptedMessage::read`, then `KeyMachine::calculate_share`.
5. `Encryption::decrypt` computes `shared = ecdh(B_enc_secret, K_A)`, decrypts `C_E`, and prepares `EncryptionKeyProof { key: shared, dleq: ... }` before the invalid PoP is checked.
6. If `C_E` decrypts to a non-canonical scalar, `C::F::from_repr` fails and `calculate_share` returns `InvalidShare { participant: E, blame: Some(proof) }` before batch verification.
7. `E` retries candidate `C_E` values until that early error exposes `shared`.
8. `E` derives the ChaCha20 cipher with the DKG context and `shared`, applies it to the copied victim ciphertext `C_A`, and recovers `A`'s `SecretShare` bytes.
