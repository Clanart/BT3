## Title
Reentrant fee-refund during `GetResponse` delivery lets the query payer steal the relayer's fee - ([File: evm/src/core/EvmHost.sol])

### Summary
`EvmHost.dispatchIncoming(GetResponse, address relayer)` pays the relayer's fee **after** it makes an untrusted external call into the destination app (`onGetResponse`), and it reads that fee from `_requestCommitments[commitment]` — a mapping that is never cleared on the success path of this function. Because the fee metadata is left "live" across the external call, a malicious app that both dispatched the original `GetRequest` and receives the `onGetResponse` callback can re-enter through the permissionless `HandlerV2.handleGetRequestTimeouts` during that callback, cause `EvmHost.dispatchTimeOut(GetRequestTimeout, ...)` to refund the escrowed fee back to itself (`meta.sender`), and then let the outer call continue — at which point the relayer's fee read (`_requestCommitments[commitment].fee`) is now zero. The relayer executes the delivery, but is paid nothing, while the fee has already been paid out to the querying app.

### Finding Description
`dispatchIncoming(GetResponse, ...)` ( [1](#0-0) ):
```solidity
function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
    bytes32 commitment = response.request.hash();
    _responseReceipts[commitment] = ResponseReceipt({relayer: relayer, responseCommitment: response.hash()});

    (bool success,) = _bytesToAddress(response.request.from)
        .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

    if (!success) {
        delete _responseReceipts[commitment];
        return;
    }

    uint256 fee = _requestCommitments[commitment].fee;
    if (fee != 0) {
        IERC20(feeToken()).safeTransfer(relayer, fee);
    }
    emit GetRequestHandled({commitment: commitment, relayer: relayer});
}
```
The relayer's payment is computed from `_requestCommitments[commitment].fee` *after* the untrusted call to the requester's contract (`response.request.from`), not before. This mirrors exactly the bug class of the external report: registered per-entity data (`_requestCommitments`, analogous to the NFT trait fields) is not finalized/cleared when the entity's lifecycle event completes (here, "fulfilling" the `GetRequest` with a response), leaving it readable/mutable during the same operation.

Meanwhile `HandlerV2.handleGetRequestTimeouts` ( [2](#0-1) ) is fully permissionless and only requires:
- `request.timeout() <= state.timestamp` for some already-verified `StateMachineHeight` (the EVM host retains arbitrarily many historical `_stateCommitments` entries; there is no requirement to use the *latest* height — see `EvmHost.stateMachineCommitment`/`_stateCommitments` at [3](#0-2) ),
- a valid non-membership proof of `ResponseReceipts` at that (older) height,
- `host.requestCommitments(commitment).sender != address(0)`.

Because `_requestCommitments[commitment]` is untouched by a successful `dispatchIncoming(GetResponse, ...)`, all three conditions can still be satisfied for a request whose response is in the process of being delivered, as long as the attacker supplies a **stale but genuinely valid** Hyperbridge state height/proof from before Hyperbridge itself recorded the response — which will always exist for any request that took at least one Hyperbridge block to answer.

`EvmHost.dispatchTimeOut(GetRequestTimeout, ...)` ( [4](#0-3) ) deletes `_requestCommitments[commitment]` and refunds the fee to `meta.sender` **before** invoking `onGetTimeout` on the same requester contract — and it can be invoked from inside the requester's own `onGetResponse` callback because `dispatchIncoming`/`dispatchTimeOut` are only `restrict`ed to be called by `_hostParams.handler` (the permissionless `HandlerV2` contract), not protected by any host-level reentrancy guard.

Attack sequence (single transaction, single relayer submission of the response):
1. Attacker deploys an app that implements both `IApp.onGetResponse` and `onGetTimeout`, and dispatches a `GetRequest` paying a fee, with `payer == self` and `timeout` set low.
2. A relayer submits the legitimate response via `HandlerV2.handleGetResponses` → `EvmHost.dispatchIncoming(GetResponse, relayer)`.
3. Inside the attacker's `onGetResponse` callback, before returning, it calls `HandlerV2.handleGetRequestTimeouts` with an old, already-verified `StateMachineHeight`/non-membership proof (recorded before Hyperbridge processed the response) whose timestamp already exceeds `request.timeout()`.
4. This reaches `EvmHost.dispatchTimeOut(GetRequestTimeout,...)`, which deletes `_requestCommitments[commitment]` and refunds the escrowed fee to the attacker (`meta.sender`), then successfully calls the attacker's own `onGetTimeout`.
5. Control returns to the outer `dispatchIncoming(GetResponse,...)` call, which had already succeeded getting the query data delivered to the attacker; it now reads `_requestCommitments[commitment].fee == 0` and pays the relayer nothing.

Net effect: the attacker gets both the query result delivered and their escrowed fee refunded, while the relayer who did the work and paid gas is paid zero — the fee ends up at the wrong beneficiary (the payer instead of the relayer), a logic/fund-diversion bug rooted in stale, un-cleared registered data (`_requestCommitments`) surviving across an untrusted external call.

### Impact Explanation
This is a direct fund-diversion bug: an unprivileged attacker (controlling only their own app contract and its own `GetRequest`) redirects a fee escrowed for a relayer's service back to themselves, causing loss of expected reward for the relayer and incorrect settlement of the request's lifecycle (the request is simultaneously "answered" and "refunded"). This matches the bounty's "wrong beneficiary or amount" / "logic attack" / stealing-of-funds categories, since it requires no malicious relayer, prover, or admin — only a malicious application contract that is a normal, permissionless participant in the protocol.

### Likelihood Explanation
Likelihood is medium: it requires the attacker to control the destination application (easy, since anyone can deploy an `IApp`), craft a request with a short timeout, and possess/derive a stale-but-valid consensus/state proof for an earlier Hyperbridge height whose timestamp already exceeds the request timeout — plausible whenever response delivery is not instantaneous relative to `timeout`, which is common. No relayer collusion, admin action, or governance is needed.

### Recommendation
- In `dispatchIncoming(GetResponse, ...)`, snapshot/clear `_requestCommitments[commitment]` (or at least cache the fee and delete the entry) **before** making the external call to `response.request.from`, exactly as `dispatchTimeOut` already does for its own commitment deletion, and pay the relayer from the cached value.
- Add a reentrancy guard on `EvmHost` covering `dispatchIncoming`/`dispatchTimeOut` so that a request cannot be simultaneously "responded to" and "timed out" within the same call stack.
- Ensure the non-membership proof check for `GetRequestTimeout` also rejects proofs from heights that predate any receipt/commitment change made against this same request within the current or a more advanced height, or require use of the most recent known height to avoid an "old but valid" proof being replayable during response delivery.

### Proof of Concept
Not independently executed; the path is derived from static analysis of `EvmHost.dispatchIncoming(GetResponse, ...)` and `EvmHost.dispatchTimeOut(GetRequestTimeout, ...)` combined with the permissionless `HandlerV2.handleGetRequestTimeouts` entrypoint, as cited above. Concretely reproducing it requires: (1) a malicious `IApp` implementing `onGetResponse`/`onGetTimeout`, (2) a genuine relayer response submission, and (3) a genuinely valid but stale Hyperbridge state-commitment/non-membership proof pair usable at the time of the reentrant call — this last piece depends on live Hyperbridge state history and was not simulated end-to-end.

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
