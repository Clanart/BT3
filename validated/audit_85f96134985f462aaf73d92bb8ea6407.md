### Title
Duplicate withdrawal-UTXO registration lets one Bitcoin payout be attributed to multiple Citrea withdrawal indices, enabling double reimbursement - ([File: core/src/database/verifier.rs])

### Summary
`withdrawals.withdrawal_utxo_txid/vout` has no uniqueness constraint, and `get_payout_txs_for_withdrawal_utxos` joins purely on `(txid, vout)` values rather than on a value that is guaranteed unique per index. Since the withdrawal outpoint bytes are freely chosen by whoever calls `withdraw()` on the Citrea Bridge contract, an attacker can register the identical outpoint for two distinct withdrawal indices, causing a single Bitcoin spend of that outpoint to be attributed to both indices and both to be marked "paid" by the same operator.

### Finding Description
The invariant the code implicitly assumes is: for withdrawal index `i`, `withdrawals.withdrawal_utxo_txid/vout WHERE idx = i` uniquely and exclusively identifies the one Bitcoin outpoint Citrea recorded at `withdrawalUTXOs[i]`, and no other index `j` may share that same outpoint. This binding is never enforced anywhere in the schema or the update path.

- `update_withdrawal_utxo_from_citrea_withdrawal` blindly writes `withdrawal_utxo_txid`/`vout` for a given `idx` with no check that the outpoint is not already used by a different `idx`: [1](#0-0) 
- The `withdrawals` table declares `withdrawal_utxo_txid bytea` / `withdrawal_utxo_vout int` with no `UNIQUE` constraint on the pair: [2](#0-1) 
- `get_payout_txs_for_withdrawal_utxos` joins `withdrawals` to `bitcoin_syncer_spent_utxos` solely on `(txid, vout)` equality, so a single recorded spend can match every `withdrawals` row that happens to carry the same `(withdrawal_utxo_txid, withdrawal_utxo_vout)`: [3](#0-2) 
- `update_finalized_payouts` iterates every row returned by that join and unconditionally writes `payout_txid`/`payout_payer_operator_xonly_pk` for each matched `idx`: [4](#0-3) 

The Citrea `withdraw()` call takes attacker-supplied raw txid/vout bytes with no on-chain uniqueness check across the caller's own indices (as seen in the test invocation): [5](#0-4) ; `collect_withdrawal_utxos` copies whatever is registered, per index, verbatim into Clementine's sync loop: [6](#0-5) , which then calls `update_withdrawal_utxo_from_citrea_withdrawal` once per new index: [7](#0-6) .

Exploit flow: attacker makes two real deposits (idx `i` and idx `j`, distinct `move_to_vault_txid`s), then calls the Citrea Bridge's `withdraw()` twice with the identical outpoint bytes `X:0` (a single dust UTXO the attacker controls), once against each deposit's withdrawal slot. Clementine's sync writes `withdrawal_utxo_txid=X, vout=0` into both `withdrawals` rows `idx=i` and `idx=j`. The attacker (or a cooperating/oblivious operator) fronts exactly one payout transaction `Y` spending `X:0` for one of the withdrawals. Once `Y` confirms, `bitcoin_syncer_spent_utxos` records a single spend of `X:0`; the join in `get_payout_txs_for_withdrawal_utxos` now matches BOTH `idx=i` and `idx=j` to `Y`, and `update_finalized_payouts` marks both indices' `payout_txid=Y` and `payout_payer_operator_xonly_pk=<operator>`. Downstream, `PayoutCheckerTask`/`send_asserts`/`is_kickoff_malicious` all trust this DB state per-index and never cross-check that the same physical payout was already claimed by another index — `is_kickoff_malicious` only verifies operator pk and blockhash consistency against the (already-conflated) DB row: [8](#0-7) . The bridge circuit's `verify_storage_proofs` genuinely proves `withdrawalUTXOs[i]==X:0` and `withdrawalUTXOs[j]==X:0` independently from Citrea state (both true, since Citrea itself stored the duplicate), so a ZK proof for reimbursing BOTH `i` and `j` against the SAME payout `Y` is constructible and valid: [9](#0-8) . Nothing in the reachable path re-derives or enforces per-outpoint exclusivity across indices.

### Impact Explanation
The operator that fronted exactly one payout ends up eligible to run two independent kickoff/reimbursement flows (one per conflated index), each entitled to draw from the round's reimbursement UTXOs. This is a reimbursement credited for a payout that was never separately fronted for the second index — directly matching the Critical category "an operator reimbursed for a payout it never funded." It drains collateral/reimbursement capacity that should back other, legitimate withdrawals, which can in turn make an honest operator unable to be reimbursed for a real payout later. The attack is repeatable per pair of deposits the attacker controls and is not specific to one operator — any operator servicing the conflated indices is affected identically.

### Likelihood Explanation
Preconditions are minimal and entirely within the unprivileged attacker's capability: make two ordinary deposits, then call the public `withdraw()` function on the Citrea Bridge contract twice with identical outpoint bytes (no special preconditions, TLS, keys, or privileged roles needed). Cost is the price of two deposits' worth of bridge_amount into Citrea and one small dust UTXO/fee on Bitcoin — no majority hashrate, no key compromise, no verifier/operator collusion required for the DB conflation itself. The only extra step for the double-reimbursement payout is that an operator processes both withdrawal requests normally (a routine, automated action), which the protocol does not treat with any suspicion since both requests independently pass the `withdrawal_utxo == input_outpoint` check.

### Recommendation
Enforce the intended one-to-one binding at the source: add a `UNIQUE(withdrawal_utxo_txid, withdrawal_utxo_vout)` constraint (partial, `WHERE withdrawal_utxo_txid IS NOT NULL`) on the `withdrawals` table, and make `update_withdrawal_utxo_from_citrea_withdrawal` reject (or flag as invalid/malicious) an update that would introduce a duplicate outpoint already used by a different `idx`. Additionally, harden `get_payout_txs_for_withdrawal_utxos`/`update_finalized_payouts` to detect and refuse to attribute a payout to more than one `idx`, and have `is_kickoff_malicious` treat a withdrawal whose outpoint collides with another index's outpoint as malicious/invalid rather than trusting the DB blindly.

### Proof of Concept
Extend `core/src/database/verifier.rs`'s test module (pattern of `update_get_payout_txs_from_citrea_withdrawal`):
1. Create two `withdrawals` rows, `idx=i` and `idx=j`, each with a distinct `move_to_vault_txid` via `upsert_move_to_vault_txid_from_citrea_deposit`.
2. Call `update_withdrawal_utxo_from_citrea_withdrawal(idx=i, utxo=X:0, block_id)` and `update_withdrawal_utxo_from_citrea_withdrawal(idx=j, utxo=X:0, block_id)` — same `X:0` for both.
3. Insert exactly one spend record via `insert_spent_utxo(block_id, spending_txid=Y, X, 0)`.
4. Call `get_payout_txs_for_withdrawal_utxos(block_id)` and assert the result contains BOTH `(i, Y)` and `(j, Y)` — i.e. `assert_eq!(result.len(), 2)` and both `idx` values map to the same `Y`, proving one physical spend is attributed to two independent withdrawal indices, violating the exclusivity binding `withdrawals[idx].withdrawal_utxo == Citrea.withdrawalUTXOs[idx]` (unique per idx).

    pub async fn get_payout_txs_for_withdrawal_utxos(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        block_id: u32,
    ) -> Result<Vec<(u32, Txid)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, TxidDB)>(
            "SELECT w.idx, bsu.spending_txid
             FROM withdrawals w
             JOIN bitcoin_syncer_spent_utxos bsu
                ON bsu.txid = w.withdrawal_utxo_txid
                AND bsu.vout = w.withdrawal_utxo_vout
             WHERE bsu.block_id = $1",
        )
        .bind(i32::try_from(block_id).wrap_err("Failed to convert block id to i32")?);

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_all)?;

        results
            .into_iter()
            .map(|(idx, txid)| {
                Ok((
                    u32::try_from(idx).wrap_err("Failed to convert withdrawal index to u32")?,
                    txid.0,
                ))
            })
            .collect()
    }

            kickoff_witness,
            &[wt_derive_path],
            self.config.protocol_paramset(),
        )?;
        let blockhash_data = commits.first();
        // only last 20 bytes of the blockhash is committed
        let truncated_blockhash = &payout_blockhash[12..];
        if let Some(committed_blockhash) = blockhash_data {
            if committed_blockhash != truncated_blockhash {
                tracing::warn!("Payout blockhash does not match committed hash: committed: {:?}, truncated payout blockhash: {:?}",
                        blockhash_data, truncated_blockhash);
                return Ok(true);
            }
        } else {
            return Err(eyre::eyre!("Couldn't retrieve committed data from witness").into());
        }
        Ok(false)
    }

    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
            ));
        }

        self.db
            .update_payout_txs_and_payer_operator_xonly_pk(
                Some(dbtx),
                payout_txs_and_payer_operator_idx,
            )
            .await?;

        Ok(())
    }

    async fn collect_withdrawal_utxos(
        &self,
        last_withdrawal_idx: Option<u32>,
        to_height: u64,
    ) -> Result<Vec<(u64, OutPoint)>, BridgeError> {
        let mut utxos = vec![];

        let mut start_idx = match last_withdrawal_idx {
            Some(idx) => idx + 1,
            None => 0,
        };

        loop {
            let withdrawal_utxo = self
                .contract
                .withdrawalUTXOs(U256::from(start_idx))
                .block(BlockId::Number(BlockNumberOrTag::Number(to_height)))
                .call()
                .await;
            match withdrawal_utxo {
                Err(e) if e.to_string().contains("execution reverted") => {
                    tracing::trace!("Withdrawal utxo not found for index, error: {:?}", e);
                    break;
                }
                Err(e) => return Err(e.into()),
                Ok(_) => {}
            }
            let withdrawal_utxo = withdrawal_utxo.expect("Failed to get withdrawal UTXO");
            let txid = withdrawal_utxo.txId.0;
            let txid =
                Txid::from_slice(txid.as_ref()).wrap_err("Failed to convert txid to Txid")?;
            let vout = withdrawal_utxo.outputId.0;
            let vout = u32::from_le_bytes(vout);
            let utxo = OutPoint { txid, vout };
            utxos.push((start_idx as u64, utxo));
            start_idx += 1;
        }
        Ok(utxos)
    }
