## Analog Vulnerability Found

### Title
Shared `BalanceHandler` instance across recursive/nested precompile calls causes native-balance/EVM-StateDB desync, enabling incorrect debit/credit accounting - ([File: precompiles/common/precompile.go], [File: testutil/testdata/debug/debug.go])

### Summary
The audited bug pattern is a "combined withdraw+deposit" operation where a critical per-operation accounting hook (`beforeKeroseneWithdrawn`) is skipped/overwritten by a generic hook (`updateXP`), so state that should be updated per-leg of the operation is instead clobbered/lost. The Cosmos EVM analog is the `BalanceHandler` used by stateful precompiles to reconcile native `x/bank`/`x/precisebank` balance-change events with the EVM `StateDB`. `BeforeBalanceChange` records `prevEventsLen := len(ctx.EventManager().Events())` and `AfterBalanceChange` only replays events from that recorded index onward [1](#0-0) . If a precompile call recursively/nestedly triggers another precompile call (or another balance-changing native action) that reuses the *same* `BalanceHandler` instance, the second call's `BeforeBalanceChange` overwrites `prevEventsLen`, discarding the marker for the outer call's already-elapsed events. This is functionally identical to the reported bug class: a shared/overwritten "before-state" marker causes one leg of a multi-leg balance-affecting operation to be silently skipped when translating native accounting changes into EVM `StateDB` balance changes.

### Finding Description
`Precompile.runNativeAction` (the generic per-precompile entrypoint) correctly creates a **fresh** `BalanceHandler` on each invocation via `p.BalanceHandlerFactory.NewBalanceHandler()` [2](#0-1) . However, the test/debug precompile implementation (`testutil/testdata/debug/debug.go`) calls `p.GetBalanceHandler()` to obtain the handler used for `BeforeBalanceChange`/`AfterBalanceChange` around `p.Execute(...)` [3](#0-2) . The repository ships an integration test explicitly documenting this defect:

> "BalanceHandlerTestSuite tests the balance handler bug where recursive precompile calls share the same BalanceHandler instance, causing prevEventsLen to be overwritten. This leads to balance desync between native bank keeper and EVM stateDB." [4](#0-3) 

The underlying `AfterBalanceChange` logic walks `events[bh.prevEventsLen:]` and, for each `CoinSpent`/`CoinReceived`/`FractionalBalanceChange` bank event, calls `stateDB.SubBalance`/`stateDB.AddBalance` to sync the EVM-visible balance with the native balance change [5](#0-4) . If `prevEventsLen` is overwritten mid-flight by a nested/recursive call sharing the same handler instance, the outer call's `AfterBalanceChange` will either (a) replay events that were already replayed by the inner call (double-counting a balance delta into `StateDB`), or (b) skip a range of events that occurred before the inner call reset the marker (losing a balance delta entirely) — directly mirroring the report's core defect: a shared/incorrectly-scoped "before/after" hook state causing per-leg accounting to be silently dropped or duplicated during a multi-step balance-affecting operation.

### Impact Explanation
Because `AfterBalanceChange` directly drives `stateDB.AddBalance`/`stateDB.SubBalance` (which back the EVM-visible account balances used for subsequent transfers, gas accounting, and `balanceOf` reads), a desync here can cause the EVM `StateDB` balance to diverge from the true `x/bank`/`x/precisebank` balance for accounts touched by a precompile that triggers reentrant/nested precompile-style balance changes. Depending on the direction of the miscount, this can manifest as unauthorized minting of EVM-visible balance (an account appears to have received funds it never got, allowing it to spend/transfer more than backed by real coins) or loss of credited balance (funds effectively vanish from the EVM view while remaining escrowed at the bank level), both of which are irreversible accounting-corruption / spendable-value-duplication conditions within the meaning of the Critical impact gate.

### Likelihood Explanation
The trigger requires a caller contract to invoke a stateful precompile in a way that produces nested/recursive precompile-style balance-changing calls sharing one `BalanceHandler` instance — the repository's own test (`TestRecursivePrecompileCallsWithDebugPrecompile`) demonstrates this is reachable via an ordinary, unprivileged EVM contract call (`callback(0)`) with no special permissions required [6](#0-5) . The generic `Precompile.runNativeAction` path already avoids the flaw by allocating a new handler per call, so the concretely demonstrated defect is scoped to precompile implementations (such as the debug precompile, and potentially any precompile pattern that stores/reuses a handler across nested `Run` invocations rather than obtaining one from a per-call factory) that call `GetBalanceHandler()`/reuse a shared instance. I could not fully verify from the available index whether any **production** (non-test) precompile (ERC20, WERC20, staking, distribution, ICS-20, bank precompile) shares a `BalanceHandler` instance across nested calls the way the debug precompile does — the `GetBalanceHandler` pattern only appears in the test/debug precompile per the grep results. This is a limitation of the available index; a full audit of all `precompiles/*` implementations (and any codepath that stores a `BalanceHandler` as a struct field rather than creating one per `runNativeAction` call) is needed to confirm whether a production-reachable Critical instance exists, or whether the test merely documents a fixed/isolated debug-only artifact.

### Recommendation
Ensure every precompile obtains a fresh `BalanceHandler` per top-level native-action invocation (as `runNativeAction` already does via `p.BalanceHandlerFactory.NewBalanceHandler()`), and audit/remove any pattern where a `BalanceHandler` is stored as shared mutable state (e.g., `GetBalanceHandler()` returning a cached instance) that could be reused across nested/recursive precompile calls within the same EVM call frame. Guard `BeforeBalanceChange` from being invoked reentrantly on an already-active handler (e.g., panic or stack the `prevEventsLen` markers instead of overwriting a single field), and add an invariant check that the sum of `AddBalance`/`SubBalance` deltas applied by `AfterBalanceChange` across a full transaction equals the net native bank balance delta for every touched account.

### Proof of Concept
The repository's own `TestRecursivePrecompileCallsWithDebugPrecompile` test is a working PoC: it deploys a caller contract that invokes the debug precompile recursively (`callback(0)`), funds the contract via ordinary `SendCoins`, and executes the transaction as a normal, unprivileged EVM transaction [7](#0-6) . Reproducing this against a production precompile that shares a `BalanceHandler` instance across nested native-action calls (rather than allocating one per call via the factory) would demonstrate the `StateDB` balance diverging from the true bank-module balance for the accounts involved.

```go
func (bh *BalanceHandler) AfterBalanceChange(ctx sdk.Context, stateDB *statedb.StateDB) error {
	events := ctx.EventManager().Events()

	for _, event := range events[bh.prevEventsLen:] {
		switch event.Type {
		case banktypes.EventTypeCoinSpent:
			spenderAddr, err := ParseAddress(event, banktypes.AttributeKeySpender)
			if err != nil {
				return fmt.Errorf("failed to parse spender address from event %q: %w", banktypes.EventTypeCoinSpent, err)
			}
			if bh.bankKeeper.BlockedAddr(spenderAddr) {
				// Bypass blocked addresses
				continue
			}

			amount, err := ParseAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", banktypes.EventTypeCoinSpent, err)
			}

			stateDB.SubBalance(common.BytesToAddress(spenderAddr.Bytes()), amount, tracing.BalanceChangeUnspecified)

		case banktypes.EventTypeCoinReceived:
			receiverAddr, err := ParseAddress(event, banktypes.AttributeKeyReceiver)
			if err != nil {
				return fmt.Errorf("failed to parse receiver address from event %q: %w", banktypes.EventTypeCoinReceived, err)
			}
			if bh.bankKeeper.BlockedAddr(receiverAddr) {
				// Bypass blocked addresses
				continue
			}

			amount, err := ParseAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", banktypes.EventTypeCoinReceived, err)
			}

			stateDB.AddBalance(common.BytesToAddress(receiverAddr.Bytes()), amount, tracing.BalanceChangeUnspecified)

		case precisebanktypes.EventTypeFractionalBalanceChange:
			addr, err := ParseAddress(event, precisebanktypes.AttributeKeyAddress)
			if err != nil {
				return fmt.Errorf("failed to parse address from event %q: %w", precisebanktypes.EventTypeFractionalBalanceChange, err)
			}
			if bh.bankKeeper.BlockedAddr(addr) {
				// Bypass blocked addresses
				continue
			}

			delta, err := ParseFractionalAmount(event)
			if err != nil {
				return fmt.Errorf("failed to parse amount from event %q: %w", precisebanktypes.EventTypeFractionalBalanceChange, err)
			}

			deltaAbs, err := utils.Uint256FromBigInt(new(big.Int).Abs(delta))
			if err != nil {
				return fmt.Errorf("failed to convert delta to Uint256: %w", err)
			}

			if delta.Sign() == 1 {
				stateDB.AddBalance(common.BytesToAddress(addr.Bytes()), deltaAbs, tracing.BalanceChangeUnspecified)
			} else if delta.Sign() == -1 {
				stateDB.SubBalance(common.BytesToAddress(addr.Bytes()), deltaAbs, tracing.BalanceChangeUnspecified)
			}
```

```go
func (s *BalanceHandlerTestSuite) TestRecursivePrecompileCallsWithDebugPrecompile() {
	evmApp := s.chain.App.(evm.EvmApp)
	ctx := s.chain.GetContext()

	// Create and register debug precompile
	debugPrec := debugprecompile.NewPrecompile(evmApp.GetBankKeeper(), evmApp.GetEVMKeeper())
	// Set the precompile directly in the EVM keeper's precompile map
	evmApp.GetEVMKeeper().RegisterStaticPrecompile(debugPrec.Address(), debugPrec)
	err := evmApp.GetEVMKeeper().EnableStaticPrecompiles(ctx, debugPrec.Address())
	s.Require().NoError(err)

	a, b, c := evmApp.GetEVMKeeper().GetPrecompileInstance(ctx, debugPrec.Address())
	fmt.Println(a, b, c)

	// Deploy caller contract
	callerContract, err := contracts.LoadDebugPrecompileCaller()
	s.Require().NoError(err)

	deploymentData := testutiltypes.ContractDeploymentData{
		Contract:        callerContract,
		ConstructorArgs: []interface{}{},
	}

	// Use local helper function
	callerAddr, err := DeployContract(s.T(), s.chain, deploymentData)
	s.Require().NoError(err)
	s.chain.NextBlock()

	s.T().Logf("Deployed caller contract at %s", callerAddr.Hex())
	s.T().Logf("Debug precompile at %s", debugPrec.Address().Hex())

	// Pack the input for callback(0)
	input, err := callerContract.ABI.Pack("callback", big.NewInt(0))
	s.Require().NoError(err)

	// Fund Contract
	err = evmApp.GetBankKeeper().SendCoins(ctx, s.chain.SenderAccounts[0].SenderAccount.GetAddress(), callerAddr.Bytes(), types.NewCoins(types.NewCoin("aatom", sdkmath.NewInt(10000000))))
	s.Require().NoError(err)

	res, _, _, err := s.chain.SendEvmTx(
		s.chain.SenderAccounts[0],
		0,             // sender index
		callerAddr,    // to address
		big.NewInt(0), // value
		input,         // data
		0,             // gas price multiplier
	)
	s.Require().NoError(err, "callback transaction should succeed")
	s.Require().False(res.IsErr(), "callback should not fail: %s", res.Events)

	s.Require().Equal(len(res.Events), 15, "callback should have 15 events")
	debug_count := 0
	for _, event := range res.Events {
		if event.Type == "debug_precompile" {
			debug_count++
		}
	}
	s.Require().Equal(10, debug_count, "callback should have 1 debug precompile")

	// Advance to next block to finalize state
	s.chain.NextBlock()
```
