## Title
Server-Side Request Forgery (SSRF) via unauthenticated DataLayer mirror URLs in `http_download` — (File: `chia/data_layer/download_data.py`)

### Summary
The vLLM report describes an SSRF where a fully attacker-controlled URL from untrusted batch input flows unvalidated into `aiohttp.ClientSession().get(url)`. Chia's DataLayer subsystem has a structurally identical flaw: on-chain "mirror" coins let any unprivileged spend-bundle submitter attach arbitrary URLs to *any* DataLayer store id, and any node/service tracking that store id will later fetch from that URL via unrestricted `aiohttp` requests with no host/scheme/domain validation.

### Finding Description
Mirror coins use a fixed, public puzzle hash `MIRROR_PUZZLE_HASH = create_mirror_puzzle().get_tree_hash()` [1](#0-0) . Any wallet holder can construct a standard spend bundle that creates a coin with this puzzle hash and a memo of the form `[launcher_id, url, ...]` for *any* `launcher_id`, not necessarily one they own — nothing in the consensus rules or in `get_mirror_info` checks ownership of the referenced store: [2](#0-1) 

When any node/wallet is tracking that `launcher_id` (`is_launcher_tracked`), `DataLayerWallet.coin_added` blindly parses the memo and stores the URLs with no validation of scheme, host, or target: [3](#0-2) 

These attacker-supplied URLs are then pulled into the local `DataStore` subscription list: [4](#0-3) 

and later selected as a download server in `fetch_and_validate`, which invokes `insert_from_delta_file` → `download_file` with `server_info.url` taken directly from the mirror record: [5](#0-4) [6](#0-5) 

Finally, `http_download` issues an unrestricted `aiohttp` `GET` request to that URL with no allowlist, no private/loopback IP filtering, and no scheme restriction beyond whatever the attacker supplied: [7](#0-6) 

This is the same class of bug as the vLLM `download_bytes_from_url` finding: attacker-controlled input (there, a batch JSON `file_url`; here, an on-chain mirror memo URL) reaches an outbound HTTP client (`aiohttp.ClientSession`) with zero domain/host validation, unlike the codebase's own multimodal connector analog in vLLM which enforces an allowlist.

### Impact Explanation
A node/service running DataLayer and tracking any store (including public stores it merely subscribes to, e.g. to browse public data) can be coerced into issuing outbound HTTP requests to arbitrary attacker-chosen hosts and ports — including internal-only services, cloud metadata endpoints, or other local ports on the host — purely by an unprivileged actor spending a small amount of XCH to create a mirror coin referencing that store's `launcher_id`. This matches CWE-918 (SSRF) and can be used for internal network reconnaissance/pivoting from the DataLayer host. Severity aligns with the Medium classification of the analogous vLLM advisory.

### Likelihood Explanation
Likelihood is high for any DataLayer operator subscribing to third-party/public stores: creating a mirror coin only requires a standard coin spend (no special permission, no requirement to own the launcher/store id), and `get_mirror_info`/`coin_added` accept the memo URLs unconditionally once the coin confirms on chain and the store id is tracked locally.

### Recommendation
Validate and constrain mirror URLs before they are used as download targets: enforce an allowed scheme (http/https only), resolve and reject requests targeting private/loopback/link-local ranges (e.g. block RFC1918, 169.254.0.0/16, etc.), and/or require an explicit operator-configured domain allowlist analogous to the `_assert_url_in_allowed_media_domains` pattern, applied inside `http_download` (and ideally also at mirror ingestion time in `DataLayerWallet.coin_added`) in `chia/data_layer/download_data.py` and `chia/data_layer/data_layer_wallet.py`.

### Proof of Concept
1. Attacker constructs and submits a standard spend bundle creating a coin with puzzle hash `MIRROR_PUZZLE_HASH` and `CREATE_COIN` memo `[victim_launcher_id, b"http://169.254.169.254/latest/meta-data/"]` (`chia/wallet/db_wallet/db_wallet_puzzles.py:90-94,97-110`).
2. Once confirmed, any DataLayer node tracking `victim_launcher_id` ingests the mirror via `DataLayerWallet.coin_added` with no URL validation (`chia/data_layer/data_layer_wallet.py:775-799`).
3. The URL is merged into that store's subscription server list (`chia/data_layer/data_layer.py:979-985`).
4. On the next sync attempt, `fetch_and_validate`/`insert_from_delta_file`/`download_file` selects the malicious server and `http_download` issues an unrestricted `aiohttp` GET to the attacker-chosen internal URL (`chia/data_layer/data_layer.py:642-694`, `chia/data_layer/download_data.py:110-145,298-323`).

```python
def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")
```

```python
async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True
```

```python
async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
```
