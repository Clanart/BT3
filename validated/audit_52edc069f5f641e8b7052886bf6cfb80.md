### Title
`Scanner::scan_block` reports immature coinbase outputs as spendable received funds — (`networks/bitcoin/src/wallet/mod.rs`)

### Summary
The fee-on-transfer bug class is "credited amount/state does not match what can actually be used": the pool trusts a transfer's nominal value instead of verifying what is actually available. In `bitcoin-serai`, `Scanner::scan_block` iterates over `block.txdata` including `block.txdata[0]` (the coinbase) and returns any matching outputs as `ReceivedOutput`s via `scan_transaction`. Coinbase outputs are unspendable for 100 blocks, yet they are returned indistinguishable from confirmed, spendable outputs. [1](#0-0) 

### Finding Description
`Scanner::scan_block` calls `self.scan_transaction(tx)` for every transaction in the block, including the coinbase at index 0. `scan_transaction` matches `output.script_pubkey` against registered scripts and builds a `ReceivedOutput` containing the `TxOut` (with its full `value`) and `outpoint`. [2](#0-1)  Downstream, `SignableTransaction::new` sums `input.output.value.to_sat()` across the provided `ReceivedOutput`s to decide `input_sat` and build a fully-formed, signable transaction. [3](#0-2)  `TransactionSignMachine::sign` then produces FROST signature shares committing to the sighash of that transaction with `Prevouts::All`, and `complete` yields the final signed `Transaction`. [4](#0-3)  A transaction spending an immature coinbase output is consensus-invalid: the signature ceremony burns preprocesses (FROST nonces) and produces an unbroadcastable transaction, while the scanner had already "credited" the funds as received.

### Impact Explanation
An unprivileged miner (or anyone relaying a block) can cause funds to be reported as received that are not spendable: a coinbase paying the Serai address is returned by `scan_block` and counted as a `ReceivedOutput` of full value, but any spend built from it within 100 blocks is invalid at consensus. Analogously to the fee-on-transfer pool crediting the nominal deposit, the scanner credits the nominal output value with no maturity check, leading to signed-but-unusable transactions and threshold ceremony exhaustion. The code itself acknowledges the gap in a comment — "If received outputs must be immediately spendable, a post-processing pass is needed to remove those outputs" — but `scan_block` still returns them as ordinary `ReceivedOutput`s, so any consumer that does not perform this undocumented external filtering is affected. [5](#0-4) 

### Likelihood Explanation
Any miner can craft a coinbase paying a registered Serai script; every `scan_block` caller then receives it as a spendable `ReceivedOutput`. No cooperation from validators or integrators beyond using the public `scan_block` API is required, and the misuse path is the natural one (the function is the primary way to scan blocks).

### Recommendation
Skip `block.txdata[0]` inside `scan_block` (or tag `ReceivedOutput`s with a maturity height/coinbase flag) so that immature coinbase outputs are never surfaced as spendable; enforce maturity before constructing `SignableTransaction` inputs. Alternatively, remove `scan_block`'s coinbase coverage entirely and document that coinbase outputs must be handled separately.

### Proof of Concept
1. A miner mines a block whose coinbase includes an output paying `p2tr_script_buf(scanner.key)` (or a registered offset script).
2. `Scanner::scan_block(&block)` returns a `ReceivedOutput { offset, output, outpoint }` for the coinbase output with full `value`. [6](#0-5) 
3. The consumer passes it to `SignableTransaction::new`, which counts its value in `input_sat` and produces a valid-looking `SignableTransaction`. [7](#0-6) 
4. The threshold signature ceremony runs (`preprocess` → `sign` → `complete`), consuming FROST preprocesses and producing a signed transaction that Bitcoin Core rejects as consensus-invalid (`bad-txns-premature-spend-of-coinbase`) — funds were reported received but are not spendable.

```rust
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
```

```rust
  /// Scan a block.
  ///
  /// This will also scan the coinbase transaction which is bound by maturity. If received outputs
  /// must be immediately spendable, a post-processing pass is needed to remove those outputs.
  /// Alternatively, scan_transaction can be called on `block.txdata[1 ..]`.
  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }
```
