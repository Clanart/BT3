### Title
KIP-247 Gasless Protocol Forces Unlimited ERC20 Approval to Externally-Registered SwapRouter, Enabling Full Token Drain If Router Is Compromised - (File: kaiax/gasless/impl/getter.go)

### Summary
The KIP-247 gasless transaction protocol mandates that a `GaslessApproveTx` grant `type(uint256).max` allowance to the `GaslessSwapRouter` contract before a `GaslessSwapTx` can execute. This mirrors the Balancer/Aura pattern of granting unlimited, indefinite allowance to a pluggable third-party contract: if the `GaslessSwapRouter` (whose address is fetched from the on-chain `SystemRegistry` and can change) is ever compromised — via owner-key compromise, a bug in the router, or a malicious registry update — it can call `transferFrom` on every gasless user's approved token at any time in the future, well beyond the amount needed for any single swap, draining their full token balance.

### Finding Description
The node-side validation logic in `kaiax/gasless/impl/getter.go` enforces condition A4 that a `GaslessApproveTx` must approve the *maximum* uint256 value to the swap router, not the exact amount required for the swap: [1](#0-0) 

This is the sole gate that promotes a `GaslessApproveTx`/`GaslessSwapTx` pair into a block — the transaction pool and bundling logic (`isReady`, `VerifyExecutable`) accept any approve amount as long as it equals `MaxUint256`: [2](#0-1) 

The `swapRouter` address itself is not hardcoded — it is read from the `SystemRegistry` contract every block and can be updated by governance/registry owner: [3](#0-2) 

Once a user submits a single `GaslessApproveTx` (reachable by any unprivileged gasless-transaction sender), an unlimited, standing allowance to the `GaslessSwapRouter` contract is created on-chain and persists indefinitely — the protocol never revokes or bounds this allowance to the amount actually consumed by the paired `swapForGas` call: [4](#0-3) 

This is structurally identical to the reported Balancer/Aura issue: a contract designated to perform a bounded operation (a single swap) is instead given unbounded, permanent pull rights over the user's token balance.

### Impact Explanation
If the registered `GaslessSwapRouter` address is later pointed to a malicious/compromised contract (e.g., compromised owner key performing an upgrade-like redeploy-and-registry-update, or a bug discovered in the router's `swapForGas`/other functions), every account that has ever completed a `GaslessApproveTx` has an outstanding `MaxUint256` allowance that can be pulled in full via `transferFrom`, independent of any subsequent user action. This is unauthorized value movement / theft of user funds at scale (all historical gasless users), not bounded to the swap amount, matching the Medium-severity impact class of the source report.

### Likelihood Explanation
Every use of the standard, documented KIP-247 gasless flow forces this unlimited-approval pattern (it's a mandatory validation condition, not an option), so the attack surface (accumulated unlimited allowances) grows with every gasless swap performed on the network. Exploitation requires the router to become compromised or maliciously swapped via the registry, but the underlying design (unbounded approval left outstanding rather than a limited/instant approval consumed then revoked) is what turns a router compromise into a full-balance drain instead of a bounded loss.

### Recommendation
Do not require/validate `MaxUint256` as the approve amount (condition A4). Instead, require the `GaslessApproveTx` amount to be exactly (or minimally) `AmountIn` of the paired `GaslessSwapTx` (condition SP2 already checks `approveArgs.Amount >= swapArgs.AmountIn`, so exact-amount approval is already compatible with existing checks), so that any outstanding allowance is bounded to what is strictly necessary for that specific swap, and does not persist as a standing unlimited allowance after execution. This eliminates the systemic all-user-funds-drain risk if the swap router is ever compromised or maliciously re-registered.

### Proof of Concept
1. Alice (a gasless user) submits a `GaslessApproveTx` for `TokenX` to the current `GaslessSwapRouter` address, which the module accepts only if amount == `MaxUint256` (`kaiax/gasless/impl/getter.go:79-86`).
2. Alice's paired `GaslessSwapTx` executes; `TokenX.allowance(Alice, GaslessSwapRouter)` remains `MaxUint256` after the swap (no revoke step exists in this flow, unlike the recommended pattern in the source report).
3. At a later block, `SystemRegistry` is updated (via governance/owner action, or the router owner key is compromised) so that `GaslessSwapRouterName` now resolves to a malicious contract, or the existing router's owner (`Owner()`/`TransferOwnership` exist per `contracts/bindings/kip247/GaslessSwapRouter.go:538-594`) is compromised and adds arbitrary-transfer logic.
4. The attacker calls `TokenX.transferFrom(Alice, attacker, Alice.balance)` using the standing unlimited allowance — no further action or consent from Alice is needed, and the amount pulled is unbounded by the original swap size.

// A1. tx.to is a whitelisted ERC20 token.

// A4. amount is MaxUint.
func (g *GaslessModule) IsApproveTx(tx *types.Transaction) bool {
	args, ok := decodeApproveTx(tx, g.signer)
	return ok && g.isApproveTx(args)
}

func (g *GaslessModule) isApproveTx(args *ApproveArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.allowedTokens[args.Token] && // A1
		g.swapRouter == args.Spender && // A3
		args.Amount.Cmp(abi.MaxUint256) == 0 // A4
}

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}

func (g *GaslessModule) updateAddresses(header *types.Header) error {
	g.gaslessInfoMu.Lock()
	defer g.gaslessInfoMu.Unlock()

	swapRouter, tokens, err := getGaslessInfo(g.Chain, header)
	// proceed even if there is something wrong with multicall contract
	if err != nil {
		g.swapRouter = common.Address{}
		g.allowedTokens = map[common.Address]bool{}
		logger.Warn("there is something wrong with multicall contract", "err", err.Error())
		return nil
	}

	g.swapRouter = swapRouter

	g.allowedTokens = map[common.Address]bool{}
	for _, addr := range tokens {
		// all tokens are allowed if nil
		if g.GaslessConfig.AllowedTokens == nil {
			g.allowedTokens[addr] = true
		}
		for _, allowed := range g.GaslessConfig.AllowedTokens {
			if addr == allowed {
				g.allowedTokens[addr] = true
			}
		}
	}
