### Title
No maximum bound on `reward.stakingrewardthreshold` governance parameter allows the governing node to zero out all staker rewards - (File: kaiax/gov/param.go)

### Summary
The governance parameter `RewardStakingRewardThreshold` ("reward.stakingrewardthreshold") only validates that the value is non-negative, with no upper bound check, mirroring the `dustThreshold` bug pattern where a privileged, single-authority role can set a threshold to an unbounded value and effectively deny value to the legitimate recipients.

### Finding Description
The `RewardStakingRewardThreshold` parameter's `FormatChecker` only asserts `v.Sign() >= 0`, with no cap: [1](#0-0) 

This value is subtracted from each staker's stake before computing their share of the staking reward pool in `assignStakingRewardsFlex`: [2](#0-1) 

If a validator's `StakingAmount` is at or below the threshold, its "excess" contribution is zero, and it becomes ineligible for any staking-reward share. Because there is no cap on how high `reward.stakingrewardthreshold` can be set, a governing node (in `governance.governancemode == "single"`, where a single privileged address controls governance votes, analogous to `onlyManagement` in the reported bug) can set this threshold to an arbitrarily large value (e.g. larger than any validator's actual stake), causing `totalExcessInt` to be zero for every validator and thus the entire staker reward budget (`stakers`/`budget`) to go unassigned to any staker; unlike `dustThreshold`, the unassigned remainder is redirected to `proposer` rather than truly "locked" in the contract, so the funds are not stuck but are redirected away from stakers who are otherwise entitled to them.

### Impact Explanation
An unbounded governing-node-controlled parameter can strip all stakers of their earned staking rewards for as long as the malicious value is in effect, redirecting those rewards to the block proposer instead. This is a reward-redirection issue similar in spirit to the referenced report (privileged party abusing an unbounded threshold to deny users their due funds), but differs materially: the diverted value is not "locked" — it is paid to the proposer, and the mechanism requires control of governance (single-governance mode), which is a higher-privilege actor than an ordinary unprivileged transaction sender.

### Likelihood Explanation
Requires the network to be operating in `governance.governancemode = "single"` with a malicious or compromised governing node — this is a privileged, not permissionless, precondition, and would need further confirmation of how governance mode is actually enforced/reachable in this codebase's current fork state (not verified here due to remaining iteration budget).

### Recommendation
Add an explicit upper bound to the `RewardStakingRewardThreshold` `FormatChecker` in `kaiax/gov/param.go` (e.g., relative to `RewardMinimumStake` or a sane absolute cap), and confirm equivalent bound checks are unnecessary/present for the un-capped `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee` parameters which use `noopFormatChecker`.

### Proof of Concept

// assignStakingRewardsFlex assigns staking rewards to stakers according to their staking amounts.
// Returns the allocation and the remainder.
func assignStakingRewardsFlex(config *reward.RewardConfig, budget *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		minStake  = config.MinimumStake.Uint64()
		threshold = config.StakingRewardThreshold.Uint64()
		isPrague  = config.Rules.IsPrague

		cns            = si.ConsolidatedNodes()
		excessInt      = make(map[common.Address]uint64)
		totalExcessInt = uint64(0)
	)

	// Calculate the excess stakes (the amount over the threshold) for each CN.
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it. Even if (CNStaking + CLStaking) could be more than minStake,
		// the CNStaking alone must be at least minStake to be eligible.
		if cn.StakingAmount < minStake {
			continue
		}

		amount := cn.StakingAmount
		if isPrague && cn.CLStakingInfo != nil {
			amount += cn.CLStakingInfo.CLStakingAmount
		}

		// Excess is the amount over the threshold (not over minStake).
		if amount > threshold {
			excessInt[cn.RewardAddr] = amount - threshold
			totalExcessInt += excessInt[cn.RewardAddr]
		}
	}
