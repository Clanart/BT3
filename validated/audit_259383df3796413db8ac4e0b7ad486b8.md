Confirmed: `DefaultParams()` sets `PermissionlessRegistration: true` [1](#0-0) , and `RegisterERC20` permits any signer to register an arbitrary external ERC20 contract as a `native ERC20` token pair when this param is true [2](#0-1) . This confirms the analog is reachable by an unprivileged user.

### Title
Rebasing/elastic-supply ERC20 tokens permanently break the 1:1 backing invariant between escrowed tokens and minted native coins - (File: `x/erc20/keeper/msg_server.go`)

### Summary
The Cally finding describes rewards from rebasing tokens accruing to a vault and becoming permanently unclaimable because the vault only tracks a fixed deposited amount, not the token's live `balanceOf`. The Cosmos EVM `x/erc20` module has the same structural flaw: when a "native ERC20" token pair is created, `ConvertERC20` escrows a fixed amount of the external ERC20 contract on the module account and mints an equal amount of Cosmos-native coin 1:1 [3](#0-2) . The reverse flow, `ConvertCoinNativeERC20`, burns the same fixed coin amount and unescrows the corresponding token amount [4](#0-3) . Neither function tracks or reconciles the *actual* live balance of the module's ERC20 holdings against the *total outstanding* minted native-coin supply for that denom over time — only the balance delta within a single transaction is checked via `ErrBalanceInvariance` [5](#0-4) .

### Finding Description
`RegisterERC20` is permissionless by default (`PermissionlessRegistration: true`) [1](#0-0) , so any unprivileged account can register any externally-owned ERC20 contract — including malicious or exotic rebasing/elastic-supply tokens — as a `TokenPair` with `OWNER_EXTERNAL` (`IsNativeERC20() == true`) [6](#0-5) [7](#0-6) .

Once registered, users call `ConvertERC20` to lock tokens on the module address and mint the mapped Cosmos coin 1:1, and `ConvertCoin` to redeem coins for tokens 1:1 [8](#0-7) [9](#0-8) . Both directions validate only that the *immediate* pre/post-call balance delta matches the exact amount transferred in that specific EVM call (`expToken := balanceToken + tokens`) [5](#0-4) [10](#0-9) . This defends against fee-on-transfer tokens within a single tx, but there is no invariant anywhere in the module that continuously reconciles: `sum(bank coin supply for pair.Denom)` vs. `ERC20.balanceOf(ModuleAddress)`.

If the registered token is a negative-rebasing/deflationary token (balance auto-decreases over time independent of transfers, e.g. certain elastic-supply or slashing-style tokens), the module's escrowed balance can silently fall below the total minted coin liability between transactions. Since coin minting/burning is always 1:1 against the *original* converted amount rather than the live balance, later `ConvertCoin` redemptions by legitimate holders will fail once escrowed inventory is exhausted — value that was represented as spendable Cosmos-coin becomes permanently unredeemable/frozen, and whichever holders redeem first drain the shared pool at the expense of the rest (an accounting shortfall the invariant checks cannot detect because they only compare against the balance snapshotted moments earlier in the same call, not against total outstanding liabilities).

Conversely, if the token is positive-rebasing (balance auto-increases, e.g. aToken-style), the surplus permanently accrues to the module account and is unrecoverable by anyone (owner, gov, or original depositors) — this is the direct structural analog of the original Cally bug: `Vaults steal rebasing tokens' rewards`.

### Impact Explanation
This breaks the core 1:1 accounting invariant between the native-coin representation and the underlying ERC20 collateral for a `token-pair-backed balance`, which is explicitly in the Critical allowed-impact set ("irreversible accounting corruption ... across ... ERC20 representations ... token-pair-backed balances" and "permanent freezing, locking ... of user funds ... escrowed assets ... token-pair-backed balances"). In the deflationary case, some fraction of coin-holders can never redeem their minted coin for the promised ERC20 — a permanent, irreversible loss of spendable value backed by an accounting shortfall the module cannot detect or prevent.

### Likelihood Explanation
Reachable by any unprivileged account because `PermissionlessRegistration` defaults to `true` and needs no governance action [1](#0-0) ; an attacker (or an unaware user) simply registers a rebasing/elastic-supply ERC20 and other users interacting with the resulting token pair via `ConvertERC20`/`ConvertCoin` are exposed. No privileged role or malicious validator/relayer assumption is required — only ordinary `MsgRegisterERC20`, `MsgConvertERC20`, and `MsgConvertCoin` transactions.

### Recommendation
- Track the module's own internal ledger of "amount owed" per token pair (total minted coin supply for `pair.Denom`) separately from the ERC20 contract's live `balanceOf`, and reject `ConvertCoin` redemptions (or `RegisterERC20` for known-rebasing tokens) if the live escrowed balance is insufficient to cover the redemption plus all other outstanding liabilities.
- Consider disallowing permissionless registration of `OWNER_EXTERNAL` token pairs by default, or require a rebase/fee-on-transfer compatibility check (e.g. simulate mint+immediate balance re-check after a time delay, or a governance allow-list) before enabling conversions for arbitrary externally-owned ERC20 contracts.
- Alternatively, mint/burn coins strictly pro-rata against the live `balanceOf(ModuleAddress)` at the time of each conversion rather than against the fixed nominal amount, so that both positive and negative rebases are reflected proportionally in the outstanding coin supply.

### Proof of Concept
1. Deploy a malicious/exotic ERC20 contract whose `balanceOf` decreases for all holders over time (e.g., implements an internal "slashing" or negative-rebase mechanism unrelated to `transfer` calls), or which is a legitimate deflationary/rebasing token.
2. Call `MsgRegisterERC20` (permissionless by default) to register it as a native ERC20 token pair — `RegisterERC20` succeeds without any allow-list check [2](#0-1) .
3. Multiple users call `MsgConvertERC20` to escrow tokens on `types.ModuleAddress` and mint the mapped Cosmos coin 1:1 [11](#0-10) .
4. Wait for the token's negative rebase to reduce `ERC20.balanceOf(types.ModuleAddress)` below the total minted coin supply for `pair.Denom` (this happens independent of any module transaction, so no invariant check is triggered).
5. A subset of coin holders call `MsgConvertCoin`; each redemption's per-call invariant check (`balanceTokenAfter == balanceToken + amount`, checked against the receiver's balance, not the module's total liability) passes as long as the module still holds *some* tokens [10](#0-9) , silently depleting the shared pool.
6. Once the module's ERC20 balance is exhausted, remaining coin holders' `MsgConvertCoin` calls fail permanently (the underlying `transfer` from `types.ModuleAddress` cannot succeed for insufficient balance) — their coin balance is stranded with no way to redeem the promised ERC20, and no on-chain owner/mechanism exists to correct the shortfall.

func (k Keeper) convertERC20IntoCoinsForNativeToken(
	ctx sdk.Context,
	pair types.TokenPair,
	msg *types.MsgConvertERC20,
	receiver sdk.AccAddress,
	sender common.Address,
) (*types.MsgConvertERC20Response, error) {
	erc20 := contracts.ERC20MinterBurnerDecimalsContract.ABI
	contract := pair.GetERC20Contract()
	balanceCoin := k.bankKeeper.GetBalance(ctx, receiver, pair.Denom)
	balanceToken := k.BalanceOf(ctx, erc20, contract, types.ModuleAddress)
	if balanceToken == nil {
		return nil, sdkerrors.Wrap(types.ErrEVMCall, "failed to retrieve balance")
	}

	// Escrow tokens on module account
	transferData, err := erc20.Pack("transfer", types.ModuleAddress, msg.Amount.BigInt())
	if err != nil {
		return nil, err
	}

	res, err := k.evmKeeper.CallEVMWithData(ctx, sender, &contract, transferData, true, nil)
	if err != nil {
		return nil, err
	}

	// Check evm call response
	var unpackedRet types.ERC20BoolResponse
	if len(res.Ret) == 0 {
		// if the token does not return a value, check for the transfer event in logs
		if err := validateTransferEventExists(res.Logs, contract); err != nil {
			return nil, err
		}
	} else {
		if err := erc20.UnpackIntoInterface(&unpackedRet, "transfer", res.Ret); err != nil {
			return nil, err
		}
		if !unpackedRet.Value {
			return nil, sdkerrors.Wrap(errortypes.ErrLogic, "failed to execute transfer")
		}
	}

	// Check expected escrow balance after transfer execution
	// NOTE: coin fields already validated in the ValidateBasic() of the message
	coins := sdk.Coins{sdk.Coin{Denom: pair.Denom, Amount: msg.Amount}}
	tokens := coins[0].Amount.BigInt()
	balanceTokenAfter := k.BalanceOf(ctx, erc20, contract, types.ModuleAddress)
	if balanceTokenAfter == nil {
		return nil, sdkerrors.Wrap(types.ErrEVMCall, "failed to retrieve balance")
	}

	expToken := big.NewInt(0).Add(balanceToken, tokens)

	if r := balanceTokenAfter.Cmp(expToken); r != 0 {
		return nil, sdkerrors.Wrapf(
			types.ErrBalanceInvariance,
			"invalid token balance - expected: %v, actual: %v",
			expToken, balanceTokenAfter,
		)
	}

	// Mint coins
	if err := k.bankKeeper.MintCoins(ctx, types.ModuleName, coins); err != nil {
		return nil, err
	}

	// Send minted coins to the receiver
	if err := k.bankKeeper.SendCoinsFromModuleToAccount(ctx, types.ModuleName, receiver, coins); err != nil {
		return nil, err
	}

func (k Keeper) ConvertCoinNativeERC20(
	ctx sdk.Context,
	pair types.TokenPair,
	amount math.Int,
	receiver common.Address,
	sender sdk.AccAddress,
) error {
	if !amount.IsPositive() {
		return sdkerrors.Wrap(types.ErrNegativeToken, "converted coin amount must be positive")
	}

	erc20 := contracts.ERC20MinterBurnerDecimalsContract.ABI
	contract := pair.GetERC20Contract()

	balanceToken := k.BalanceOf(ctx, erc20, contract, receiver)
	if balanceToken == nil {
		return sdkerrors.Wrap(types.ErrEVMCall, "failed to retrieve balance")
	}

	// Escrow Coins on module account
	coins := sdk.Coins{{Denom: pair.Denom, Amount: amount}}
	if err := k.bankKeeper.SendCoinsFromAccountToModule(ctx, sender, types.ModuleName, coins); err != nil {
		return sdkerrors.Wrap(err, "failed to escrow coins")
	}

	// Unescrow Tokens and send to receiver
	res, err := k.evmKeeper.CallEVM(ctx, erc20, types.ModuleAddress, contract, true, nil, "transfer", receiver, amount.BigInt())
	if err != nil {
		return err
	}

	// Check unpackedRet execution
	var unpackedRet types.ERC20BoolResponse
	if len(res.Ret) == 0 {
		// if the token does not return a value, check for the transfer event in logs
		if err := validateTransferEventExists(res.Logs, contract); err != nil {
			return err
		}
	} else {
		if err := erc20.UnpackIntoInterface(&unpackedRet, "transfer", res.Ret); err != nil {
			return err
		}
		if !unpackedRet.Value {
			return sdkerrors.Wrap(errortypes.ErrLogic, "failed to execute unescrow tokens from user")
		}
	}

	// Check expected Receiver balance after transfer execution
	balanceTokenAfter := k.BalanceOf(ctx, erc20, contract, receiver)
	if balanceTokenAfter == nil {
		return sdkerrors.Wrap(types.ErrEVMCall, "failed to retrieve balance")
	}

	exp := big.NewInt(0).Add(balanceToken, amount.BigInt())

	if r := balanceTokenAfter.Cmp(exp); r != 0 {
		return sdkerrors.Wrapf(
			types.ErrBalanceInvariance,
			"invalid token balance - expected: %v, actual: %v", exp, balanceTokenAfter,
		)
	}

	// Burn escrowed Coins
	err = k.bankKeeper.BurnCoins(ctx, types.ModuleName, coins)
	if err != nil {
		return sdkerrors.Wrap(err, "failed to burn coins")
	}

	return nil
}

// RegisterERC20 implements the gRPC MsgServer interface. Any account can permissionlessly
// register a native ERC20 contract to map to a Cosmos Coin.
func (k *Keeper) RegisterERC20(goCtx context.Context, req *types.MsgRegisterERC20) (*types.MsgRegisterERC20Response, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	params := k.GetParams(ctx)

	if !params.PermissionlessRegistration {
		if err := k.validateAuthority(req.Signer); err != nil {
			return nil, err
		}
	}

	// Check if the conversion is globally enabled
	if !k.IsERC20Enabled(ctx) {
		return nil, types.ErrERC20Disabled.Wrap("registration is currently disabled by governance")
	}

	for _, addr := range req.Erc20Addresses {
		if !common.IsHexAddress(addr) {
			return nil, errortypes.ErrInvalidAddress.Wrapf("invalid ERC20 contract address: %s", addr)
		}

		pair, err := k.registerERC20(ctx, common.HexToAddress(addr))
		if err != nil {
			return nil, err
		}
