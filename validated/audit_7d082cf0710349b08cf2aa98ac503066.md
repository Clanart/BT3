## Analysis



### Title
Unbounded atom-length indexing in `is_atom_canonical()`/`is_clvm_canonical()` causes an uncaught `IndexError` on malformed spend-bundle CLVM buffers - ([File: chia/full_node/mempool_manager.py])

### Summary
`is_atom_canonical()` reads an attacker-controlled length prefix from a CLVM-encoded buffer and then indexes further into that same buffer without ever checking that the buffer is long enough to contain the declared atom, mirroring the CUPS `cupsUTF32ToUTF8()` bug class of trusting an internal length field to read past the end of a caller-supplied buffer. `is_clvm_canonical()` calls this on `coin_spend.puzzle_reveal` and `coin_spend.solution` taken straight from a submitted, unvalidated `SpendBundle`.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads `b = clvm_buffer[offset]` to determine a length-prefix class, then loops `prefix_len` times reading additional prefix bytes (`clvm_buffer[offset]` again, incrementing `offset`) to compute `atom_len`, and finally returns `1 + prefix_len + atom_len` as the new offset for the caller — all without ever validating that `offset + prefix_len` or the resulting new offset stay within `len(clvm_buffer)`: [1](#0-0) 

`is_clvm_canonical()` drives this loop directly over attacker-supplied bytes and calls `is_atom_canonical()` whenever a large-atom marker byte (`b > 0x80`) is seen, then advances `offset` by the returned `atom_len` and re-indexes `clvm_buffer[offset]` on the next loop iteration — again with no bound check before the read: [2](#0-1) 

This is invoked in `MempoolManager.validate_spend_bundle()` directly on `coin_spend.puzzle_reveal` and `coin_spend.solution` bytes from an incoming, attacker-crafted `SpendBundle`: [3](#0-2) 

Crucially, `validate_spend_bundle()` is called from `add_spend_bundle()` *after* `pre_validate_spendbundle()`, and the call site in `FullNode.add_transaction()` only wraps the earlier `pre_validate_spendbundle()` call in `try/except ValueError / ValidationError`: [4](#0-3) 

The subsequent `add_spend_bundle()` call (which triggers `is_clvm_canonical`) is invoked outside that exception scope: [5](#0-4) 

Because Python raises `IndexError` (not `ValueError`) when a bytes index is out of range, a crafted puzzle_reveal/solution containing a large-atom marker byte whose declared prefix length or atom length exceeds the actual remaining buffer will raise an uncaught `IndexError` from `is_atom_canonical`/`is_clvm_canonical`, propagating out of `validate_spend_bundle` → `add_spend_bundle` → `add_transaction` with no handler for it.

### Impact Explanation
An unprivileged party can submit a spend bundle whose `puzzle_reveal` or `solution` ends with a truncated large-atom length prefix (e.g. a byte matching the `0xf8`/`0xfc` masks in `is_atom_canonical` followed by fewer trailing bytes than the prefix class requires). This crafts a condition where `clvm_buffer[offset]` is accessed past the end of the bytes object. Since this exception is not caught by the `add_transaction` error-handling logic (which only expects `ValueError`/`ValidationError`), it escapes as an unhandled exception in the transaction-processing coroutine, held under `self.blockchain.priority_mutex`. This can halt/crash processing of that transaction path, denying spend-bundle admission — a spend-triggered transaction-processing halt, matching the "Accept only... spend-triggered transaction-processing halt" validation criterion.

### Likelihood Explanation
Any unprivileged wallet user or RPC caller who can submit a spend bundle (e.g. via `push_tx`) can trigger this: the malformed puzzle_reveal/solution encoding does not require any special privileges, valid signature, or coin existence — the offending code path (`is_clvm_canonical`) runs during general mempool admission for every submitted spend, before the item is confirmed valid or discarded gracefully.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before each buffer read: verify `offset + 1 + prefix_len <= len(clvm_buffer)` before reading prefix bytes, and verify the computed `1 + prefix_len + atom_len` does not exceed `len(clvm_buffer)` before returning, raising a controlled `False`/rejection (or a caught `ValueError`) rather than letting `IndexError` propagate. Additionally, wrap the `is_clvm_canonical` calls in `validate_spend_bundle()` (or the whole `add_spend_bundle` call in `full_node.py`) with defensive exception handling so any parsing anomaly degrades to `MempoolInclusionStatus.FAILED` rather than an unhandled exception.

### Proof of Concept
1. Construct a `CoinSpend` whose `solution` (or `puzzle_reveal`) bytes are exactly `b"\xfc"` (matching the `0b11111100` mask, `prefix_len = 4`) with zero or one trailing bytes — far fewer than the 4 length-prefix bytes required.
2. Wrap it in a `SpendBundle` and submit via the standard transaction path (`FullNode.add_transaction` / `push_tx` RPC).
3. `validate_spend_bundle()` calls `is_clvm_canonical(bytes(coin_spend.solution))`, which sees `b > 0x80` and calls `is_atom_canonical(clvm_buffer, 0)`.
4. Inside `is_atom_canonical`, the loop `for i in range(prefix_len): ... atom_len |= clvm_buffer[offset]` attempts to read `clvm_buffer[1]`, `[2]`, `[3]`, `[4]` — indices that don't exist in the truncated buffer — raising `IndexError: index out of range`, uncaught anywhere in the `add_transaction`/`add_spend_bundle` call chain.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
