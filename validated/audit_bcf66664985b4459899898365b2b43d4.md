### Title
Pure-Python `MergeFromString`/`ParseFromString` can raise undocumented `UnicodeDecodeError` instead of `message.DecodeError` on malformed string-field bytes - ([File: python/google/protobuf/internal/decoder.py])

### Summary
The ecdsa advisory's failed invariant is that a public "verify" API is documented to raise exactly one exception type (`BadSignatureError`) on malformed attacker-controlled input, but the real implementation can propagate other, undocumented exception types, so application code that only catches the documented type experiences an uncaught exception (DoS). The protobuf analog is the pure-Python (`api_implementation.Type() == 'python'`) binary-wire decoder: parsing a `string` field whose bytes are not valid UTF-8 raises a bare `UnicodeDecodeError` from deep inside `StringDecoder`, instead of being converted into the single documented parse-failure exception `google.protobuf.message.DecodeError`.

### Finding Description
`decoder.py`'s module docstring establishes the exception contract for this file: decoders may internally raise `IndexError` or `struct.error`, and "something up the call stack is expected to catch [those] and convert them to `message.DecodeError`" [1](#0-0) . `message.py` likewise only defines `Error`/`DecodeError`/`EncodeError` as the module's public exception surface [2](#0-1) .

However, `StringDecoder._ConvertToUnicode` decodes attacker-controlled length-delimited bytes directly with `str(byte_str, 'utf-8')`, and when this fails it only annotates and **re-raises** the raw `UnicodeDecodeError`, rather than raising `message.DecodeError`: [3](#0-2) 
This exception is not caught anywhere in the surrounding `DecodeField`/`DecodeRepeatedField` closures [4](#0-3) , so it propagates unmodified out of `MergeFromString`/`ParseFromString`/`FromString` — public, documented parse entry points reachable directly on a bounded, attacker-supplied byte string against a trusted schema.

The project's own tests confirm this divergence is real and implementation-specific: `testBadUtf8String` explicitly expects `UnicodeDecodeError` (not `DecodeError`) for the pure-Python implementation and is skipped for the C++/upb backends [5](#0-4) , and `testStringUTF8Serialization` documents the same asymmetry between implementations ("The pure Python API throws an exception on `MergeFromString()`... The C++ implementation... has no way to throw the exception") [6](#0-5) . By contrast, `testParseErrors` shows the intended/expected contract is that malformed wire data on parse produces `message.DecodeError` [7](#0-6) , confirming `UnicodeDecodeError` is outside that documented contract.

This mirrors the ecdsa bug class precisely: the invariant "malformed/attacker-controlled input to the public parse/verify API yields only the one documented exception type" is violated because a lower-level, format-specific exception (`UnicodeDecodeError`, analogous to `UnexpectedDER`/`AssertionError` in ecdsa) escapes uncaught-and-unconverted.

### Impact Explanation
Any Python application using the pure-Python protobuf implementation (`PROTOCOL_BUFFERS_PYTHON_IMPLEMENTATION=python`, or PyPy where C++ is unavailable per `api_implementation.py` [8](#0-7) ) that calls `ParseFromString`/`MergeFromString`/`FromString` on untrusted, bounded bytes and only catches `google.protobuf.message.DecodeError` (the documented contract) will receive an uncaught `UnicodeDecodeError` on a crafted string field, causing worker/process crashes — a Denial of Service consistent in kind (not degree) with the ecdsa advisory. Impact is limited to consuming applications using the pure-Python backend and relying on catching only `DecodeError`; it does not affect the C++ or upb backends, which silently substitute raw bytes instead of throwing (as shown in `pyext/message.cc` `ToStringObject` and `convert.c`) [9](#0-8) [10](#0-9) .

### Likelihood Explanation
High for deployments still on the pure-Python implementation: no special conditions are needed beyond sending a bounded protobuf message with a `string`-typed field whose bytes are invalid UTF-8 to any code path that calls `ParseFromString`/`MergeFromString`. The behavior is deterministic and already reproduced by the project's own unit test (`testBadUtf8String`), confirming it is reachable through the fully-supported public API.

### Recommendation
In `python/google/protobuf/internal/decoder.py`, wrap the `str(byte_str, 'utf-8')` conversion in `StringDecoder._ConvertToUnicode` so that `UnicodeDecodeError` is caught and re-raised as `message.DecodeError` (chaining the original exception for diagnostics), aligning the pure-Python decoder with the documented exception contract already stated in the module docstring and with the behavior expected by callers that catch only `DecodeError`. Update `message.py`/API docs to explicitly state whichever behavior is chosen as the guaranteed contract across implementations (python/cpp/upb) so callers can rely on a single exception type.

### Proof of Concept
Using the pure-Python implementation (`PROTOCOL_BUFFERS_PYTHON_IMPLEMENTATION=python`):
```python
from google.protobuf.internal import api_implementation
assert api_implementation.Type() == 'python'

from google.protobuf.internal import encoder
import unittest_pb2  # any generated message with a `string` field, e.g. optional_string, field #14

msg = unittest_pb2.TestAllTypes()
# Field 14 (optional_string), wiretype 2 (length-delimited), length 1, invalid UTF-8 byte 0xFF
bad_utf8_data = encoder.TagBytes(14, 2) + b'\x01\xff'

try:
    msg.MergeFromString(bad_utf8_data)
except Exception as e:
    print(type(e), e)  # -> <class 'UnicodeDecodeError'>, NOT google.protobuf.message.DecodeError
```
This reproduces the project's own `testBadUtf8String` [5](#0-4)  and demonstrates that catching only `message.DecodeError` around `MergeFromString`/`ParseFromString` fails to catch this attacker-triggerable exception on bounded, schema-valid input.

  def _ConvertToUnicode(memview):
    """Convert byte to unicode."""
    byte_str = memview.tobytes()
    try:
      value = str(byte_str, 'utf-8')
    except UnicodeDecodeError as e:
      # add more information to the error message and re-raise it.
      e.reason = '%s in field: %s' % (e, key.full_name)
      raise

    return value

PyObject* ToStringObject(const FieldDescriptor* descriptor,
                         const absl::string_view value) {
  if (descriptor->type() != FieldDescriptor::TYPE_STRING) {
    return PyBytes_FromStringAndSize(value.data(), value.length());
  }

  PyObject* result =
      PyUnicode_DecodeUTF8(value.data(), value.length(), nullptr);
  // If the string can't be decoded in UTF-8, just return a string object that
  // contains the raw bytes. This can't happen if the value was assigned using
  // the members of the Python message object, but can happen if the values were
  // parsed from the wire (binary).
  if (result == nullptr) {
    PyErr_Clear();
    result = PyBytes_FromStringAndSize(value.data(), value.length());
  }
  return result;
}
