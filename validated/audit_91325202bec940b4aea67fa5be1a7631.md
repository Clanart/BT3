## Analysis: CEI/Reentrancy-Class Bug Analog Found

The Axelar report's core issue is a violation of Checks-Effects-Interactions where external calls execute before internal accounting state is finalized, letting reentrant execution "double count" the same value transfer. The Cosmos EVM analog exists in the precompile **BalanceHandler** mechanism, which is designed to reconcile native x/bank balance-change events into the EVM `StateDB` around every precompile call.

Each precompile invocation wraps its native action with `BeforeBalanceChange`/`AfterBalanceChange`, which records `len(events)` before the call and replays `events[prevEventsLen:]` afterward to apply `AddBalance`/`SubBalance` to the StateDB [1](#0-0) . The window is closed over the *global* event log for the entire block/tx execution, not a call-local scope [2](#0-1) .

When a precompile action itself triggers execution that reaches another (or the same) precompile — e.g. an ERC20 token with a `_beforeTokenTransfer` hook that calls the staking/distribution precompile, as reproduced in the repo's own test contracts [3](#0-2)  and `StakingCallerTwo.sol` [4](#0-3)  — the inner precompile call's `AfterBalanceChange` consumes and applies events `[innerStart:innerEnd]` to the StateDB. When control returns to the outer precompile, its own `AfterBalanceChange` replays events `[outerStart:currentLen]`, a window that **still includes the inner call's already-applied events**, re-crediting/re-debiting the same bank balance change into the StateDB a second time.

This exact defect is already captured by the repository's own regression tests, which explicitly document it as a known bug class:
- `evmd/tests/integration/balance_handler/balance_handler_test.go` — "tests the balance handler bug where recursive precompile calls share the same BalanceHandler instance... This leads to balance desync between native bank keeper and EVM stateDB." [5](#0-4) 
- `evmd/tests/ibc/ics20_recursive_precompile_calls_test.go` — "Tests the native balance handler bug where reverted distribution calls leave persistent bank events that are incorrectly aggregated" [6](#0-5) 

Production precompiles (`erc20`, `staking`, `ics20`) all wire this same `BalanceHandlerFactory` through `precompiles/common/precompile.go`'s `runNativeAction`, so any user-deployed contract that triggers nested/recursive precompile calls (a common, unprivileged, EVM-native pattern — token hooks, callback contracts, ICS20 callback contracts) can reach this event-double-processing path [7](#0-6) [8](#0-7) .

### Impact
The result is that the EVM-visible balance (`StateDB`) for an account can diverge from its true x/bank balance — balances can be inflated (over-credited) or deflated (over-debited) relative to actual escrowed/spendable value, which is a direct "unauthorized duplication / accounting corruption of spendable user value" per the impact gate. Since this arises from ordinary unprivileged EVM transaction flow (any contract making nested precompile calls), it meets the "reachable by unprivileged user" bar.

### Recommendation direction
Scope `BalanceHandler`'s event window to be properly nestable — e.g., have each precompile invocation snapshot/consume only the events it directly produced and exclude any sub-range already consumed by a nested `AfterBalanceChange`, or make outer-call windows start from the position left off by the most recently completed inner call rather than from the outer call's own entry point.

Given the specificity of this needed fix (bounding the precompile-nesting event window), I don't have enough certainty from static review alone to produce a fully verified, exploit-confirmed PoC without running the existing tests — I'd recommend starting a Devin session to execute the two existing tests above (`TestRecursivePrecompileCallsWithDebugPrecompile` and `TestHandleMsgTransfer`'s recursive-call case) against current `main` to confirm whether the double-accounting still reproduces in production precompiles (not just the debug/test-only precompile), and if so, quantify the exact StateDB-vs-bank-keeper balance delta achievable.
