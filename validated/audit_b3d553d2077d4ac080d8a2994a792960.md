### Title
Gasless swap module admits fee-on-transfer/rebasing tokens for `swapForGas`, causing the fee-delegating proposer to lose lent gas funds - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The Kaia gasless (KIP-247) module lets a block proposer pre-lend gas KAIA to a user via `LendTxGenerator`, expecting to be repaid `amountRepay` inside the bundled `GaslessSwapTx` execution of `GaslessSwapRouter.swapForGas`. The admission-time balance check performed by `checkBalanceForSwap` only compares the sender's nominal ERC20 `balanceOf`/`allowance` against the declared `amountIn`; it never verifies that the router actually *receives* `amountIn` of the token. If a whitelisted token later becomes a fee-on-transfer/deflationary/rebasing token (the same "weird-erc20" class referenced in the original report), the amount actually received by the router on `transferFrom` will be less than `amountIn`, causing the swap output to fall short of `amountRepay` and the whole `swapForGas` call to revert — while the proposer's `LendTxGenerator` KAIA transfer to the user has already been included and finalized in the block as a separate, unconditional transaction.

### Finding Description
`GaslessModule.checkBalanceForSwap` in [1](#0-0)  validates:
- `tx.minAmountOut >= tx.amountRepay`
- `token.allowance(sender, router) >= amountIn`
- `token.balanceOf(sender) >= amountIn`

None of these checks account for a token that deducts a transfer fee, meaning the router can receive strictly less than `amountIn` when `transferFrom` executes inside `swapForGas`. `repayAmount`/`lendAmount` are computed purely from gas parameters, independent of the actual swap outcome [2](#0-1) .

Per the module's own design (README), block assembly unconditionally prepends `LendTxGenerator` ahead of `GaslessApproveTx`/`GaslessSwapTx` in a bundle [3](#0-2) . The lend transaction is a plain KAIA transfer from the proposer to the user and, once included, is not reverted or reclaimed if the subsequent `GaslessSwapTx` reverts. If `swapForGas` reverts because the actually-received input amount (net of the token's transfer fee) yields swap output below `minAmountOut`/`amountRepay`, the repayment logic inside the router never executes, so the proposer never recovers the KAIA it fronted via `LendTxGenerator`.

This mirrors the original report's root cause exactly: a whitelisted asset that can (or does) implement fee-on-transfer behavior is never revalidated for "amount actually received" before value is irreversibly disbursed on the promise of repayment.

### Impact Explanation
A single malicious or newly-fee-enabled whitelisted token can cause the block proposer to lose the KAIA lent for gas (`R1+R2+R3` per gasless transaction) whenever the sender submits a swap for that token, since:
1. `LendTxGenerator`'s transfer is unconditional and irreversible once the block is finalized.
2. `GaslessSwapTx`'s repayment to the proposer only occurs if the swap succeeds with output ≥ `amountRepay`.

This is a direct fee/value-loss vector against the fee-delegation counterparty (block proposer), reachable purely by any gasless-eligible user submitting a swap transaction for a token that changes to fee-on-transfer behavior after being whitelisted — no privileged access required.

### Likelihood Explanation
Requires: (1) a token being whitelisted for gasless swaps, and (2) that token becoming fee-on-transfer (e.g., via upgradeable proxy or governance-controlled fee parameter) after whitelisting, or being a token whose fee-on-transfer nature was not caught during whitelisting review. Given `allowedTokens` is populated from an on-chain, upgradable `GaslessSwapRouter`/Registry configuration [4](#0-3) , whitelisting changes are administrative but the underlying token contract's behavior is not re-verified per-transaction at the protocol level, so likelihood depends on governance/whitelisting hygiene rather than a validator/consensus safeguard — the module itself performs no defense-in-depth check.

### Recommendation
In `checkBalanceForSwap`, and ideally within the on-chain `GaslessSwapRouter.swapForGas`, verify the router's actual received token balance delta after `transferFrom` matches (or at least covers) the declared `amountIn` before proceeding with the swap/repay accounting, rejecting or aborting the module-tx path otherwise. Additionally, consider tracking realized (post-fee) input amounts rather than nominal `amountIn` when computing whether `amountRepay` can be honored, so shortfalls are detected before the `LendTxGenerator` value is committed on-chain.

### Proof of Concept
1. Token `T` is whitelisted for `GaslessSwapRouter` via Registry update, initially a standard ERC20.
2. Token `T`'s owner/upgrade path later enables a transfer fee (fee-on-transfer), while `T` remains whitelisted.
3. User submits `GaslessSwapTx` for `T` with `amountIn = X`, `minAmountOut = amountRepay = Y`; admission passes `checkBalanceForSwap` because `balanceOf(sender) >= X` and `allowance >= X` [5](#0-4) .
4. Block builder prepends `LendTxGenerator`, transferring `Y`-equivalent KAIA to the user; this transaction is included and finalized.
5. `swapForGas` executes `transferFrom(sender, router, X)`, but due to the transfer fee the router only receives `X' < X`; the resulting swap output falls short of `minAmountOut`/`amountRepay`, and `swapForGas` reverts.
6. The `LendTxGenerator` transfer from step 4 is not rolled back (separate, already-included transaction), so the proposer permanently loses the lent KAIA while the user keeps both the lent KAIA and their (fee-reduced) token balance.

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {

		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// If SwapTx.nonce is the sender's next nonce, then there is no room for ApproveTx proceeding SwapTx.
		senderNonce := g.getCurrentStateNonce(swapArgs.Sender)
		noApproveTxPreceeds := swapNonce == senderNonce
		if noApproveTxPreceeds {
			// tx.token.allowance(sender, router) >= tx.amountIn
			approval, err := tokenContract.Allowance(nil, swapArgs.Sender, swapRouter)
			if err != nil {
				return err
			}
			if approval.Cmp(swapArgs.AmountIn) < 0 {
				return fmt.Errorf("insufficient approval: approval=%s, want=%s", approval.String(), swapArgs.AmountIn.String())
			}
		}

		// tx.token.balanceOf(sender) >= tx.amountIn
		balance, err := tokenContract.BalanceOf(nil, swapArgs.Sender)
		if err != nil {
			return err
		}
		if balance.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("insufficient balance: balance=%s, want=%s", balance.String(), swapArgs.AmountIn.String())

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func repayAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	// R1 = LendTx.Fee() = SwapTx.GasPrice() * TxGas
	r1 := new(big.Int).Mul(swapTx.GasPrice(), new(big.Int).SetUint64(params.TxGas))

	// RepayAmount = R1 + R2 + R3
	return new(big.Int).Add(r1, lendAmount(approveTxOrNil, swapTx))
}

func getGaslessInfo(bc backends.BlockChainForCaller, header *types.Header) (common.Address, []common.Address, error) {
	statedb, err := bc.StateAt(header.Root)
	if err != nil {
		return common.Address{}, nil, err
	}

	// If Registry is not installed, do not query GaslessSwapRouter contract.
	if statedb.GetCode(system.RegistryAddr) == nil || bc.Config().IsRandaoForkBlockParent(header.Number) {
		return common.Address{}, nil, nil
	}

	caller, err := system.NewMultiCallContractCaller(statedb, bc, header)
	if err != nil {
		return common.Address{}, nil, err
	}

	opts := &bind.CallOpts{BlockNumber: header.Number}
	info, err := caller.MultiCallGaslessInfo(opts)

	return info.Gsr, info.Tokens, err
}

### Block building rules

Upon detection of GaslessTxs, the following logics are executed:

- Per sender, if exists, GaslessApproveTx is relocated before GaslessSwapTx.
- LendTxGenerator is prepended before GaslessApproveTx.
- A new bundle is generated which contain either `[LendTxGenerator, GaslessApproveTx, GaslessSwapTx]` or `[LendTxGenerator, GaslessSwapTx]`
- If the bundle has conflict with any previous bundles, it is excluded from the returned bundle list.
