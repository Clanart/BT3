### Title
Later transaction in a block overwrites earlier deposits' `data`/`presumed_origin`, letting an attacker hijack a victim's InInstruction - (File: processor/src/networks/bitcoin.rs)

### Summary
In `Bitcoin::get_outputs`, the `outputs` accumulator is declared **outside** the per-transaction loop, but the code that attaches `presumed_origin` and the Serai `data` (`InInstruction`) iterates over *all* accumulated `outputs` — including outputs found in earlier transactions of the same block. Any unprivileged party who gets a transaction paying to a scanned Serai address mined later in the same block can overwrite the instruction data and origin attribution of a victim's deposit from an earlier transaction, redirecting the credited action (e.g., a `transfer`) to themselves.

### Finding Description [1](#0-0) 

- `let mut outputs = vec![];` at line 689 is created once per `get_outputs(block, key)` call, not per transaction.
- The loop `for tx in &block.txdata[1 ..]` pushes matched outputs into that shared vector (lines 691–700).
- For each tx with at least one matched output, the code computes `presumed_origin` from `tx.input[0]` (lines 707–729) and `data = Self::extract_serai_data(tx)` (line 730), then runs `for output in &mut outputs` (line 731) — mutating every output collected so far, not just the ones from the current `tx`.

This mirrors the reported bug class: a permissionless external action (the attacker simply broadcasting a transaction to a scanned address — the branch/change/external addresses are derivable from the public group key via `address_from_key`/`scanner(key)`) mutates state that is being accounted as part of another user's operation in the same atomic unit (here, the same block scan). The attacker's tx doesn't even need to carry a valid instruction for `presumed_origin` to be clobbered; if it carries an `InInstruction` (e.g., via an OP_RETURN/P2WSH-embedded Serai shorthand as used in `processor/src/tests/literal/mod.rs`), it also overwrites `data` on the victim's `OutputType::External` outputs.

Concretely: victim's tx1 deposits BTC to the external address with `data = transfer(alice)`. Attacker's tx2 in the same block sends dust-above-`DUST` (≥10,000 sats) to the same external address with `data = transfer(attacker)`. After the loop, tx1's output is returned with `data = transfer(attacker)` and `presumed_origin` taken from tx2's first input.

### Impact Explanation
The processor credits deposits and executes the attached Serai instruction (`InInstruction`) based on `Output::data()` produced by `get_outputs`. An attacker can rewrite the instruction bound to *any* earlier scanned output in the same block — redirecting minted funds/transfer destinations to themselves — and falsify `presumed_origin` (used to attribute who sent funds), enabling theft of the economic value of the victim's deposit at the cost of one ≥10,000 sat output. This is "funds accounted under attacker-chosen instructions," the analog of "deposit amount inflated by permissionlessly claimed rewards."

### Likelihood Explanation
Fully reachable by an unprivileged party: the external deposit address is public (derived from the group key), and inclusion in the same block is achievable by watching the mempool and submitting with a competitive fee. No validator collusion, key material, or RPC compromise is required. The only mitigating factor is that the attacker's tx must land in the same block *after* the victim's tx, and it costs a dust-threshold output; the overwrite is unconditional once both are in the block.

### Recommendation
Reset or scope the attribution loop to the current transaction. E.g., track `let start = outputs.len();` before scanning `tx`, and iterate `for output in &mut outputs[start ..]` when applying `presumed_origin` and `data`. Additionally consider skipping mutation when `data` is empty so a tx without an InInstruction cannot clobber a prior tx's instruction.

### Proof of Concept
1. Victim broadcasts tx1 paying X sats to `external_address(group_key)` and embedding an `InInstruction` encoding `Shorthand::transfer(None, alice)`.
2. Attacker observes tx1 in the mempool and broadcasts tx2 paying ≥ `DUST` (10,000 sats) to the same address, embedding `Shorthand::transfer(None, attacker)`, ordered later in the same block.
3. The processor calls `Bitcoin::get_outputs(block, key)`. tx1's output is pushed with `data` initially unset; when tx2 is processed, `data = extract_serai_data(tx2)` and `for output in &mut outputs` writes `transfer(attacker)` onto tx1's output as well.
4. `ScannerEvent::Block` reports the victim's X-sat output carrying the attacker's instruction; the victim's deposit is credited/executed to the attacker's Serai account.

Code path: `get_outputs` shared accumulator (`processor/src/networks/bitcoin.rs:689`), per-tx push (`:691–700`), block-wide mutation (`:730–736`).

  async fn get_outputs(&self, block: &Self::Block, key: ProjectivePoint) -> Vec<Output> {
    let (scanner, _, kinds) = scanner(key);

    let mut outputs = vec![];
    // Skip the coinbase transaction which is burdened by maturity
    for tx in &block.txdata[1 ..] {
      for output in scanner.scan_transaction(tx) {
        let offset_repr = output.offset().to_repr();
        let offset_repr_ref: &[u8] = offset_repr.as_ref();
        let kind = kinds[offset_repr_ref];

        let output = Output { kind, presumed_origin: None, output, data: vec![] };
        assert_eq!(output.tx_id(), tx.id());
        outputs.push(output);
      }

      if outputs.is_empty() {
        continue;
      }

      // populate the outputs with the origin and data
      let presumed_origin = {
        // This may identify the P2WSH output *embedding the InInstruction* as the origin, which
        // would be a bit trickier to spend that a traditional output...
        // There's no risk of the InInstruction going missing as it'd already be on-chain though
        // We *could* parse out the script *without the InInstruction prefix* and declare that the
        // origin
        // TODO
        let spent_output = {
          let input = &tx.input[0];
          let mut spent_tx = input.previous_output.txid.as_raw_hash().to_byte_array();
          spent_tx.reverse();
          let mut tx;
          while {
            tx = self.rpc.get_transaction(&spent_tx).await;
            tx.is_err()
          } {
            log::error!("couldn't get transaction from bitcoin node: {tx:?}");
            sleep(Duration::from_secs(5)).await;
          }
          tx.unwrap().output.swap_remove(usize::try_from(input.previous_output.vout).unwrap())
        };
        Address::new(spent_output.script_pubkey)
      };
      let data = Self::extract_serai_data(tx);
      for output in &mut outputs {
        if output.kind == OutputType::External {
          output.data.clone_from(&data);
        }
        output.presumed_origin.clone_from(&presumed_origin);
      }
    }
