### Title
Newline injection in `.gitignore` via unescaped attacker-controlled file names in `escapeGitSpecialCharacters` - (File: `app/src/lib/git/gitignore.ts`)

### Summary
`escapeGitSpecialCharacters` is meant to make a single file path safe to use as one literal pattern line in `.gitignore`, but its escape regex only covers `[ ] ! * # ?` and does not escape `\n` or `\r`. Because POSIX filesystems allow newline/carriage-return bytes in file names, and a git repository can be cloned/checked out with such names, a crafted repository can cause `appendIgnoreFile` to write more than one `.gitignore` rule when the user asks Desktop to "ignore" a single file.

### Finding Description
`escapeGitSpecialCharacters` escapes only bracket/glob/comment/wildcard characters: [1](#0-0) 

`appendIgnoreFile` passes the raw file path straight through this escaper and then hands the (supposedly single-line, fully-escaped) result to `appendIgnoreRule`, which simply concatenates it into the `.gitignore` text: [2](#0-1) [3](#0-2) 

Because `\n`/`\r` are not in the escape set, a file name that itself contains a newline (e.g. `evil\n*.env`) is written to the `.gitignore` file verbatim, so the single call to `appendIgnoreFile` ends up producing two separate pattern lines instead of one escaped literal — breaking the function's own documented invariant ("The file path will be escaped before adding").

The unit tests in the repo only exercise the documented special characters (`[ ] ! * # ?`) and never test embedded newlines/CRs, so this gap is untested: [4](#0-3) [5](#0-4) 

### Impact Explanation
If a user clones/checks out a repository containing a file whose name embeds a newline followed by an attacker-chosen glob pattern (e.g. `src/evil\n*.env`), and the user right-clicks that file in the Changes list and chooses "Ignore file", GitHub Desktop will append not just an escaped literal for that odd filename, but also a second, attacker-controlled `.gitignore` rule line (`*.env` in the example). This can cause git to silently start ignoring additional files the user did not intend to ignore — e.g., secrets files, build artifacts, or specific source files — leading to silent corruption of what gets committed/pushed, without the user noticing since the UI only shows "ignore this one file" as the action taken.

### Likelihood Explanation
Exploitation requires the victim to clone or fetch a repository that contains a file whose name embeds a raw `\n`/`\r` byte (permitted on POSIX filesystems, and git itself will happily track such paths) and then use the specific "ignore file" UI action on that exact file. This is a plausible but not trivial attacker setup (requires the user to interact with that specific unusual file through the ignore-file feature), so likelihood is moderate rather than high.

### Recommendation
Extend the escaping in `escapeGitSpecialCharacters` (or reject/sanitize such inputs earlier) to also handle `\n` and `\r` — either by escaping them in a way that keeps the pattern on one physical line, or by rejecting/normalizing file paths that contain raw newline/carriage-return characters before they reach `appendIgnoreRule`, so a single call to `appendIgnoreFile` can never introduce more than one `.gitignore` line.

```typescript
/** Add the given pattern or patterns to the root gitignore file */
export async function appendIgnoreRule(
  repository: Repository,
  patterns: string | string[]
): Promise<void> {
  const text = (await readGitIgnoreAtRoot(repository)) || ''

  const currentContents = await formatGitIgnoreContents(text, repository)

  const newPatternText =
    patterns instanceof Array ? patterns.join('\n') : patterns
  const newText = await formatGitIgnoreContents(
    `${currentContents}${newPatternText}`,
    repository
  )

  await saveGitIgnore(repository, newText)
}
```

```typescript
export async function appendIgnoreFile(
  repository: Repository,
  filePath: string | string[]
): Promise<void> {
  if (filePath instanceof Array) {
    const escapedFilePaths = filePath.map(path =>
      escapeGitSpecialCharacters(path)
    )

    return appendIgnoreRule(repository, escapedFilePaths)
  }

  const escapedFilePath = escapeGitSpecialCharacters(filePath)
  return appendIgnoreRule(repository, escapedFilePath)
}
```

```typescript
/** Escapes a string from special characters used in a gitignore file */
export function escapeGitSpecialCharacters(pattern: string): string {
  const specialCharacters = /[\[\]!\*\#\?]/g

  return pattern.replaceAll(specialCharacters, match => {
    return '\\' + match
  })
}
```
