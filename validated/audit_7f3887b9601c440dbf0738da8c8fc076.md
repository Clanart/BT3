## Analog Finding

### Title
DataLayer mirror URLs are attacker-controlled on-chain data that trigger unauthenticated server-side HTTP fetches (SSRF) - ([File: chia/data_layer/data_layer.py])

### Summary
The HyperChat SSRF report shows a `fetch()` primitive taking an attacker-influenced `baseurl` and issuing an outbound request without validating the destination. Chia's DataLayer has an analogous pattern: a store's "mirror" URL list is untrusted on-chain data that any wallet can publish for *any* store id, and other DataLayer nodes that subscribe to that store id will later issue outbound HTTP requests to those attacker-chosen URLs.

### Finding Description
`DataLayerWallet.create_new_mirror()` creates a standard coin spend to the fixed mirror puzzle (`create_mirror_puzzle()`), embedding the caller-supplied `launcher_id` and `urls` directly as coin memos: [1](#0-0) 

Nothing in `create_new_mirror()` / `dl_new_mirror` verifies that `launcher_id` corresponds to a store owned or created by the caller — a caller can name *any* DataLayer store's launcher id as the mirror target: [2](#0-1) 

The mirror coin's puzzle/memo layout is later parsed generically from any coin matching the mirror puzzle hash, extracting `launcher_id` and the URL list with no allowlist or scheme/host restriction: [3](#0-2) 

Any node syncing a given store pulls all such mirror URLs via `dl_get_mirrors`/`update_subscriptions_from_wallet` and inserts them as subscription servers: [4](#0-3) 

The periodic sync loop then uses these attacker-supplied URLs to perform outbound HTTP downloads in `fetch_and_validate()` → `insert_from_delta_file()` → `download_file()` → `http_download()`, with no restriction on scheme, host, or destination (e.g., internal/private IPs, cloud metadata endpoints, localhost services): [5](#0-4) [6](#0-5) 

Additionally, if a downloader plugin is configured, the same attacker-controlled `server_info.url` is placed into a JSON POST body sent to the plugin, and `get_downloader()` similarly issues outbound POSTs keyed off mirror data: [7](#0-6) [8](#0-7) 

The only mitigations present are content-length/size caps (`max_delta_file_size`) and filename validation on the *content* of what's downloaded — none of that constrains *where* the request is sent. Mirror URLs are explicitly called out in the module's own documentation as "external trust inputs" that must not be trusted for data integrity, but no code path restricts the network destination itself: [9](#0-8) 

### Impact Explanation
This is a spend-triggered SSRF: any wallet holder can spend a small amount of XCH to create a mirror coin naming an arbitrary (even someone else's) DataLayer store and pointing to an arbitrary URL (internal service, cloud metadata endpoint, or a target used for port-scanning/DoS amplification). Any operator running a DataLayer node that subscribes to or auto-subscribes to that store — including via `auto_subscribe_to_local_stores` or owned-store pseudo-subscription — will have their node issue outbound HTTP GET/POST requests to attacker-chosen destinations on a periodic loop (`periodically_manage_data`). This can be used to probe/attack internal infrastructure reachable from the DataLayer host, exfiltrate data via crafted URLs, or pivot into an internal network — a CWE-918 SSRF impact matching the reported bug class, reachable purely through a Data Layer client's normal subscription flow with no privileged access required.

### Likelihood Explanation
Likelihood is moderate-to-high for any operator running DataLayer with subscriptions to third-party stores (a core supported use case of DataLayer/mirrors). The attack requires only: (1) creating a mirror coin for a chosen `launcher_id` (any wallet operation, low cost), and (2) a victim node subscribing to that store id (a normal, expected DataLayer usage pattern — subscribing to other people's stores is the entire purpose of DataLayer replication). No special privileges, malicious peer, or protocol-level attack is needed.

### Recommendation
- Validate/sanitize mirror URLs before they are used for outbound requests: enforce an allowlist of schemes (e.g., `https`), reject loopback/link-local/private-range and cloud-metadata addresses unless explicitly configured, and consider requiring operator opt-in per mirror or per store before automatically fetching from newly discovered URLs.
- Add a configurable network egress policy (e.g., resolve-and-check destination IP against a deny list) at the point where `http_download()` and `get_downloader()`/plugin POST calls are made.
- Consider requiring explicit administrator approval for newly observed mirror URLs rather than always auto-trusting on-chain-discovered mirrors during `update_subscriptions_from_wallet()`.

### Proof of Concept
1. Attacker runs a wallet with DataLayer enabled and calls `dl_new_mirror` (or CLI `chia data add_mirror`) specifying an arbitrary victim `store_id` (any known DataLayer launcher id, not necessarily one they own) and `urls=["http://169.254.169.254/latest/meta-data/"]` or `["http://internal-service.local:8080/admin"]`. [10](#0-9) 
2. The mirror coin confirms on-chain with memo `[launcher_id, url...]`.
3. Any DataLayer node subscribed to `store_id` (or one that has `auto_subscribe_to_local_stores` enabled, or that owns the store and periodically syncs) picks up the new mirror URL via `update_subscriptions_from_wallet()`. [4](#0-3) 
4. On the next `periodically_manage_data()` cycle, `fetch_and_validate()` selects this server and calls `http_download()`, issuing a GET request from the victim's DataLayer host to the attacker-chosen URL. [5](#0-4) [6](#0-5)

def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]

    async def get_downloader(self, store_id: bytes32, url: str) -> PluginRemote | None:
        request_json = {"store_id": store_id.hex(), "url": url}
        for d in self.downloaders:
            async with aiohttp.ClientSession() as session:
                try:
                    async with session.post(
                        d.url + "/handle_download",
                        json=request_json,
                        headers=d.headers,
                        timeout=self.client_timeout,
                    ) as response:
                        res_json = await response.json()
                        if res_json["handle_download"]:
                            return d
                except Exception as e:
                    self.log.error(f"get_downloader could not get response: {type(e).__name__}: {e}")
        return None

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
