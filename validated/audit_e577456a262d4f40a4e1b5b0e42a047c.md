### Title
Unauthenticated on-chain "mirror" coins let any spend-bundle submitter inject attacker-controlled URLs into a victim wallet's DataLayer mirror list, causing SSRF/arbitrary outbound HTTP fetches - ([File: chia/data_layer/data_layer_wallet.py])

### Summary
`DataLayerWallet.coin_added()` recognizes any coin sent to the well-known, unkeyed `create_mirror_puzzle()` puzzle hash as a "DataLayer mirror" and copies the memo-supplied `launcher_id`/URLs straight into the local `Mirror` store, gated only by whether the *launcher_id* (the DataLayer store id) happens to be tracked — not by any proof that the sender owns or is authorized to publish mirrors for that store. This is structurally the same bug class as the Camel-Iggy advisory: externally supplied, unauthenticated "header"/metadata fields (here, mirror server URLs) are mapped into an internal trust namespace without a filter/ownership check, and that data later drives an outbound HTTP request whose destination is fully attacker-controlled (SSRF).

### Finding Description
`create_mirror_puzzle()` returns a fixed, parameter-less puzzle (`P2_PARENT.curry(Program.to(1))`), so its puzzle hash (`MIRROR_PUZZLE_HASH`) is public and stable across the network. [1](#0-0) 

`get_mirror_info()` extracts the mirror's `launcher_id` and URL list purely from the `CREATE_COIN` condition's memo field of *any* spend that creates a coin at that puzzle hash — there is no signature check, no verification that the spender owns the DataLayer singleton referenced by `launcher_id`, and no validation of the URL contents: [2](#0-1) 

Any unprivileged spend-bundle submitter can construct a normal coin spend (from a coin they own) that creates a child coin with `puzzle_hash == MIRROR_PUZZLE_HASH` and a memo of `[victim_launcher_id, malicious_url, ...]`. When a wallet observes this coin via normal SPV sync, `DataLayerWallet.coin_added()` fires: [3](#0-2) 

The only gate is `wallet_state_manager.dl_store.is_launcher_tracked(launcher_id)` — true whenever the wallet is subscribed to or owns that DataLayer store, which is the normal state for any DataLayer client following a store. There is no requirement that the mirror-creating coin have any relationship to the store's owner/singleton lineage; the attacker's `launcher_id` memo value is trusted at face value. The resulting `Mirror` record (containing attacker-chosen URLs) is persisted and surfaced through `dl_get_mirrors`/`get_mirrors()`.

These attacker-controlled URLs then feed the DataLayer service's subscription/fetch pipeline: [4](#0-3) 

`fetch_and_validate()` randomly selects one of these server URLs (indistinguishable from legitimate mirrors) and issues outbound requests against it: [5](#0-4) 

The actual network call goes through `download_file()`/`http_download()`, which performs `session.get(server_info.url + "/" + filename, ...)` (or POSTs to a configured downloader plugin using the attacker-controlled `url`), with the destination host fully determined by the attacker-supplied memo string: [6](#0-5) [7](#0-6) 

This mirrors the Camel-Iggy root cause precisely: an externally supplied, unauthenticated field (Camel header / here, mirror URL memo) is copied into an internal-trust data structure without a filtering/authorization boundary, and that data structure is later used to determine the target of an outbound HTTP request that the local process makes on the victim's behalf.

### Impact Explanation
Any party who can submit a standard, unrelated spend bundle (no special permission, no relationship to the targeted DataLayer store) can force any node/wallet that is subscribed to (or owns) that store to make outbound HTTP GET/POST requests to an attacker-chosen URL, on a recurring basis via `periodically_manage_data()`. This is a classic SSRF primitive against the local DataLayer service process: it can be used to probe/pivot into internal-only services, hit cloud metadata endpoints (e.g., `169.254.169.254`) reachable from the host, or exhaust local resources by pointing at very large "delta files" (bounded by `max_delta_file_size`, but still an amplification/probe vector). Because `MIRROR_PUZZLE_HASH` is public and requires no special wallet type or DID/NFT ownership, the attack surface is any coin owner able to spend into that puzzle hash — i.e., an unprivileged spend-bundle submitter. This matches the CWE-918 (SSRF) / CWE-20 (Improper Input Validation) classification of the analog advisory and is reachable purely from mempool-admitted transactions plus normal DataLayer subscription behavior, no malicious peer/node control required.

### Likelihood Explanation
Likelihood is high: constructing the malicious spend requires only a coin the attacker controls, knowledge of the fixed `MIRROR_PUZZLE_HASH`, and the `launcher_id` of the target store (which is public — it's the DataLayer store id anyone can subscribe to or discover via offers). No cooperation from the store owner and no privileged RPC access are needed. The only precondition is that a victim node be actively tracking (subscribed to or owning) the targeted `launcher_id`, which is the normal operating condition for any DataLayer client.

### Recommendation
Do not treat "coin sends to `MIRROR_PUZZLE_HASH` with a matching tracked `launcher_id`" as sufficient authorization to add a mirror. At minimum:
- Require that the mirror-creating spend be provably linked to the DataLayer singleton's owner (e.g., verify the parent/ancestor lineage ties back to the actual singleton launcher coin or an announcement signed by the singleton's current owner), not merely that the memo claims a tracked `launcher_id`.
- Treat mirror URLs as untrusted network destinations even after acceptance: apply an allow/deny policy (e.g., block link-local/metadata/private IP ranges) before `http_download()`/`get_downloader()` issue requests, and rate-limit/backoff per-URL more aggressively for unauthenticated mirrors.
- Consider requiring an explicit user action (not automatic background `update_subscriptions_from_wallet()`/`periodically_manage_data()` fetch) before contacting a newly observed, unauthenticated mirror URL for the first time.

### Proof of Concept
1. Attacker learns/observes the public `launcher_id` of a DataLayer store that a victim node subscribes to or owns (this id is inherently public — it is shared to allow offers/subscriptions).
2. Attacker spends any coin they own with solution producing:
   `CREATE_COIN(puzzle_hash=MIRROR_PUZZLE_HASH, amount=<any>, memos=[victim_launcher_id, b"http://169.254.169.254/latest/meta-data/"])`
   (mirroring the shape asserted by `create_mirror_puzzle()`/`get_mirror_info()` in [8](#0-7) , and consistent with how a legitimate mirror is built in [9](#0-8) ).
3. This spend bundle is submitted to the mempool and confirmed like any ordinary transaction — no special signature over `launcher_id` is checked.
4. The victim's wallet, syncing normally, executes `DataLayerWallet.coin_added()`, sees `is_launcher_tracked(victim_launcher_id) == True`, and stores the attacker's URL as a legitimate `Mirror` [3](#0-2) .
5. On the victim's next `periodically_manage_data()`/`update_subscription()` cycle, `update_subscriptions_from_wallet()` pulls this URL into the subscription's server list [4](#0-3) , and `fetch_and_validate()` may select it and call `http_download()`, causing the victim's DataLayer service process to issue an outbound GET to the attacker-chosen target [5](#0-4) , [6](#0-5) .

Note: I was not able to independently execute this against a running node to confirm end-to-end request delivery (no execution environment available in this session); the analysis is based on tracing the exact code paths above from puzzle-hash recognition through to the outbound `aiohttp` call. A Devin session with a runnable simulator/testnet environment would be needed to fully confirm request execution and any additional guardrails (e.g., timeouts, `max_delta_file_size`) that could limit real-world impact.

def create_mirror_puzzle() -> Program:
    return P2_PARENT.curry(Program.to(1))


MIRROR_PUZZLE_HASH = create_mirror_puzzle().get_tree_hash()


def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")

    async def coin_added(
        self, coin: Coin, height: uint32, peer: WSChiaConnection, coin_data: object | None, sync_scope: WalletSyncScope
    ) -> None:
        if coin.puzzle_hash == create_mirror_puzzle().get_tree_hash():
            parent_state: CoinState = (
                await self.wallet_state_manager.wallet_node.get_coin_state([coin.parent_coin_info], peer=peer)
            )[0]
            parent_spend = await fetch_coin_spend(height, parent_state.coin, peer)
            assert parent_spend is not None
            launcher_id, urls = get_mirror_info(parent_spend.puzzle_reveal, parent_spend.solution)
            # Don't track mirrors with empty url list.
            if not urls:
                return
            if await self.wallet_state_manager.dl_store.is_launcher_tracked(launcher_id):
                ours: bool = await self.wallet_state_manager.get_wallet_for_coin(coin.parent_coin_info) is not None
                await self.wallet_state_manager.dl_store.add_mirror(
                    Mirror(
                        coin.name(),
                        launcher_id,
                        uint64(coin.amount),
                        Mirror.decode_urls(urls),
                        ours,
                        height,
                    )
                )
                await self.wallet_state_manager.add_interested_coin_ids([coin.name()])

async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True

    log.info(f"Using downloader {downloader} for store {store_id.hex()}.")
    request_json = {
        "url": server_info.url,
        "client_folder": str(client_foldername),
        "filename": filename,
        "group_files_by_store": group_downloaded_files_by_store,
        "max_delta_file_size": max_delta_file_size,
    }
    try:
        async with aiohttp.ClientSession() as session:
            async with session.post(
                downloader.url + "/download",
                json=request_json,
                headers=downloader.headers,
                timeout=timeout,
            ) as response:
                res_json = await response.json()
                assert isinstance(res_json["downloaded"], bool)
                return res_json["downloaded"]
    except (asyncio.TimeoutError, aiohttp.ClientError) as e:
        log.error(f"download_file could not get response from plugin {downloader}: {type(e).__name__}: {e}")
        return False

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
