### Title
Cached FROST preprocess is reused to sign different messages under one context, enabling private key share recovery - ([File: coordinator/src/tributary/signing_protocol.rs](coordinator/src/tributary/signing_protocol.rs))

### Summary
The kernel bug class is a stale binding: an object moved into a new context (`dst_addr`) while retaining metadata indexed by the old context, so a later lookup finds the object but its embedded index doesn't match — the copy was not re-keyed for the destination. `SigningProtocol::preprocess_internal` has exactly this shape: a deterministic FROST preprocess seed is cached under `context` (e.g. `(b"DkgConfirmer", attempt)`), yet the *message being signed* is not part of that context. Any second signing under the same context regenerates identical nonces — a stale nonce bound to a new message.

### Finding Description
`preprocess_internal` encrypts a random seed and stores it in `CachedPreprocesses` keyed only by `self.context`, then rebuilds the sign machine via `AlgorithmSignMachine::from_cache` on every call [1](#0-0) . `seeded_preprocess` derives `nonces` deterministically from `ChaCha20Rng::from_seed(*seed.0)`, so the same `(context, participants)` pair always yields identical `d, e` nonces and identical `Commitments` [2](#0-1) . The cache is never deleted after use, and the FROST spec itself warns reuse enables private key share recovery [3](#0-2) .

`DkgConfirmer::share` and `DkgConfirmer::complete` each call `share_internal` → `preprocess_internal` with the fixed context `(b"DkgConfirmer", self.attempt)`, while the signed message `set_keys_message(&self.spec.set(), &removed, key_pair)` includes the attacker-influenced `key_pair` parameter [4](#0-3) . Two calls with different `key_pair` values under the same `attempt` produce two signature shares `s₁ = d + b·ρ + c₁·λ·xᵢ` and `s₂ = d + b·ρ + c₂·λ·xᵢ` with identical nonce terms and different challenges — the FROST nonce-reuse equation that linearly recovers the secret share `xᵢ`.

This is the precise analog of the kernel bug: the cached seed is "the folio still in swapcache" — it is re-instantiated under a new message ("destination VMA") while its index (the context key) was never updated to bind the new message, and nothing detects the mismatch before the share is emitted.

### Impact Explanation
Recovery of a validator's MuSig/FROST secret share compromises the tributary's validator-set signing key (Schnorrkel/Ristretto), letting an attacker forge validator signatures — equivalent to the kernel's BUG-level integrity failure, but worse: instead of a crash, the stale binding silently produces valid-looking shares that leak the key.

### Likelihood Explanation
`share`/`complete` take `key_pair` and `preprocesses` maps supplied from tributary protocol messages; whether an unprivileged peer can force two distinct `key_pair` confirmations within one `attempt` depends on the DKG-confirmation flow in `handle.rs`, which I could not fully trace in the available iterations. Even without an active trigger, crash/retry paths re-execute `share_internal` under the same context, and any divergence in `key_pair` (or in the signer set derived via `threshold_i_map_to_keys_and_musig_i_map`) across retries yields nonce reuse. Partially verified; the deterministic-reuse mechanism itself is fully confirmed by the code above.

### Recommendation
Include the message digest (or `key_pair` hash) in the `CachedPreprocesses` context key, or delete the cached seed after the first `sign`/`from_cache` consumption and regenerate when the bound message differs. At minimum, assert that a cached seed is only ever reused for a bitwise-identical `(participants, msg)` pair.

### Proof of Concept
1. Under `attempt = N`, call `DkgConfirmer::share(preprocesses, key_pair_A)` — this stores and uses seed `S` under context `(b"DkgConfirmer", N)`, producing share `s_A` over `msg_A`.
2. Call `DkgConfirmer::share(preprocesses', key_pair_B)` with `key_pair_B ≠ key_pair_A` — `preprocess_internal` hits the cache, `from_cache` regenerates identical nonces, and emits `s_B` over `msg_B`.
3. With identical commitments, the binding factors `ρ` and group nonce `R` are identical; solving `s_A − s_B = (c_A − c_B)·λ·xᵢ` (or the two-equation system for `d + b·ρ` and `λ·xᵢ`) recovers the signer's secret share.

  fn seeded_preprocess(
    self,
    seed: CachedPreprocess,
  ) -> (AlgorithmSignMachine<C, A>, Preprocess<C, A::Addendum>) {
    let mut params = self.params;

    let mut rng = ChaCha20Rng::from_seed(*seed.0);
    let (nonces, commitments) = Commitments::new::<_>(
      &mut rng,
      params.keys.original_secret_share(),
      &params.algorithm.nonces(),
    );
    let addendum = params.algorithm.preprocess_addendum(&mut rng, &params.keys);

    let preprocess = Preprocess { commitments, addendum };

    // Also obtain entropy to randomly sort the included participants if we need to identify blame
    let mut blame_entropy = [0; 32];
    rng.fill_bytes(&mut blame_entropy);
    (
      AlgorithmSignMachine { params, seed, nonces, preprocess: preprocess.clone(), blame_entropy },
      preprocess,
    )
  }
