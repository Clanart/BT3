### Title
DOS via Fee‑Payer Hijacking of Signed Fee‑Delegated Transactions - (File: `blockchain/types/tx_internal_data_fee_delegated_value_transfer.go`, `api/api_kaia_transaction.go`)

### Summary
A Kaia fee‑delegated transaction's sender signature never commits to the fee payer that will pay for it. Any party who obtains the sender‑signed (but not yet fee‑payer‑signed) transaction can attach themselves as the `FeePayer`, produce a valid fee‑payer signature, and broadcast the resulting transaction through the public `kaia_sendTransactionAsFeePayer` RPC. This lets an unrelated third party consume the sender's nonce and front‑run the fee payer/relayer who was actually supposed to complete and pay for that transaction, causing the original relayer's completed transaction to be rejected ("nonce too low"/already known) — the same class of "copy a signature that doesn't bind the counterparty, and DOS the intended transaction" bug reported for `AjnaToken.transferFromWithPermit`.

### Finding Description
For all `TxTypeFeeDelegated*` transaction types, the sender's signature hash (`SigHash`) is computed over the transaction body **excluding** the `FeePayer` field: [1](#0-0) 

Only the fee payer's own signature hash includes the fee payer's address: [2](#0-1) 

This means a sender's signature over `(type, nonce, gasPrice, gas, to, value, from, ...)` is valid for **any** `FeePayer` address — the field is mutable and unauthenticated from the sender's point of view. The interface used across all fee-delegated tx types explicitly separates the fee-payer commitment from the sender commitment: [3](#0-2) 

The node exposes an RPC that lets a caller submit a fully‑formed but sender‑only‑signed transaction and have the *local* account sign it as the fee payer and broadcast it: [4](#0-3) 

`SendTransactionAsFeePayer` only requires `args.TxSignatures` (the sender's signature values) plus standard fields (`TypeInt`, nonce, gas, price); it does not validate that the caller is the intended/expected fee payer for that sender signature — it derives the fee payer purely from `tx.FeePayer()` (i.e., the `From`/fee-payer address supplied in the same RPC call): [5](#0-4) 

Because a signed-by-sender transaction (type, nonce, gasPrice, gas, to, value, from, signatures) is unambiguously identified by `SenderTxHash`/`SigRLP` and does not encode who the fee payer must be, **anyone who can see that sender‑signed payload** (e.g. a public relay/gas‑station service that broadcasts sender‑only‑signed transactions for fee payers to pick up, or any observer of the pending mempool) can:
1. Take the sender's `TxSignatures` and other fields,
2. Call `kaia_sendTransactionAsFeePayer` with their own controlled account as `From` (fee payer),
3. Get a fully valid transaction (their own valid fee‑payer signature over their own address) with the same sender, same nonce, same intended action,
4. Submit it with a higher gas price to front‑run the intended fee payer's submission of the exact same sender-signed payload with the legitimate `FeePayer`.

### Impact Explanation
Once the attacker's copy is mined, the sender's nonce is consumed. The originally intended relayer/fee‑payer's transaction (which carries a different `FeePayer` address and thus a different tx hash) becomes invalid due to nonce reuse and is rejected by the pool/state ("nonce too low" or replaced). This breaks any fee‑delegation-based relayer/gas‑station business flow that relies on being able to claim and pay for a specific sender-signed transaction: the intended fee payer never gets to complete/settle it, while an unrelated party could hijack the gas‑payment role for a transaction they had no business relationship with. This is a concrete instance of "fee-delegation abuse" — an unprivileged public RPC caller can redirect who pays for and completes any observed sender-signed fee-delegated transaction, denying service to the intended fee-payer/relayer.

### Likelihood Explanation
Exploitation only requires that the sender-signed (fee‑payer‑unsigned) transaction payload become visible to an attacker before the intended fee payer submits the complete transaction — this is the normal workflow for fee delegation (a sender signs and hands the payload to a gas station / relayer to add the fee-payer signature), so leakage via a shared relay API, log, or public channel is realistic. The RPC call itself (`kaia_sendTransactionAsFeePayer`) is a standard, publicly documented method requiring no special privilege beyond having an unlocked/keystore account to act as fee payer, which any user can create.

### Recommendation
Bind the fee payer identity into the sender's signed payload (e.g., require the sender to specify an expected `FeePayer` and include it in `SigHash`, or require a nonce/commitment scheme that ties a specific sender signature to a specific, pre-agreed fee payer) so that a copied sender signature cannot be repurposed by an arbitrary third party to hijack the fee-payer role. Alternatively, restrict `SendTransactionAsFeePayer` to only accept transactions where the caller's account matches a fee payer address that the sender explicitly authorized as part of the signed data.

### Proof of Concept
1. Alice signs a `TxTypeFeeDelegatedValueTransfer` as sender only (`tx.SignWithKeys`), producing `TxSignatures` over a hash that excludes `FeePayer` — as shown by `SigHash`/`SenderTxHash` construction in [6](#0-5)  (same "no FeePayer in payload" pattern used across all fee-delegated types) and confirmed by the test-vector split of `SenderSigs` vs `FeePayerSigs` at [7](#0-6) .
2. Alice sends this sender‑signed transaction (nonce N, `TxSignatures`) to RelayerA expecting RelayerA to call `kaia_sendTransactionAsFeePayer` with `From=RelayerA`.
3. Kane observes the sender-signed payload (e.g., via the relay's API/mempool) and calls `kaia_sendTransactionAsFeePayer` himself with `From=Kane` and the same `TypeInt`, `AccountNonce`, `GasLimit`, `Price`, and `TxSignatures`, per [4](#0-3) .
4. Kane submits with higher gas price, gets mined first, consuming nonce N for Alice's account.
5. RelayerA's later submission of the same sender-signed payload (with `FeePayer=RelayerA`) is rejected due to nonce collision, denying RelayerA the ability to fulfill its intended fee-delegation service.

// SendTransactionAsFeePayer creates a transaction for the given argument, sign it as a fee payer
// and submit it to the transaction pool.
func (s *KaiaTransactionAPI) SendTransactionAsFeePayer(ctx context.Context, args SendTxArgs) (common.Hash, error) {
	// Don't allow dynamic assign of values from the setDefaults function since the sender already signed on specific values.
	if args.TypeInt == nil {
		return common.Hash{}, errTxArgNilTxType
	}
	if args.AccountNonce == nil {
		return common.Hash{}, errTxArgNilNonce
	}
	if args.GasLimit == nil {
		return common.Hash{}, errTxArgNilGas
	}
	if args.Price == nil {
		return common.Hash{}, errTxArgNilGasPrice
	}

	if args.TxSignatures == nil {
		return common.Hash{}, errTxArgNilSenderSig
	}

	feePayerSignedTx, err := s.SignTransactionAsFeePayer(ctx, args)
	if err != nil {
		return common.Hash{}, err
	}

	return submitTransaction(ctx, s.b, feePayerSignedTx.Tx)
}

// SignTransactionAsFeePayer will sign the given transaction as a fee payer
// with the from account. The node needs to have the private key of the account
// corresponding with the given from address and it needs to be unlocked.
func (s *KaiaTransactionAPI) SignTransactionAsFeePayer(ctx context.Context, args SendTxArgs) (*SignTransactionResult, error) {
	// Allows setting a default nonce value of the sender just for the case the fee payer tries to sign a tx earlier than the sender.
	if err := args.setDefaults(ctx, s.b); err != nil {
		return nil, err
	}
	tx, err := args.toTransaction()
	if err != nil {
		return nil, err
	}
	// Don't return errors for nil signature allowing the fee payer to sign a tx earlier than the sender.
	if args.TxSignatures != nil {
		tx.SetSignature(args.TxSignatures.ToTxSignatures())
	}
	feePayer, err := tx.FeePayer()
	if err != nil {
		return nil, errTxArgInvalidFeePayer
	}
	feePayerSignedTx, err := s.signAsFeePayer(feePayer, tx)
	if err != nil {
		return nil, err
	}
	data, err := rlp.EncodeToBytes(feePayerSignedTx)
	if err != nil {
		return nil, err
	}
	return &SignTransactionResult{data, feePayerSignedTx}, nil
}

func (t *TxInternalDataFeeDelegatedCancel) SenderTxHash() common.Hash {
	hw := sha3.NewKeccak256()
	rlp.Encode(hw, t.Type())
	rlp.Encode(hw, []interface{}{
		t.AccountNonce,
		t.Price,
		t.GasLimit,
		t.From,
		t.TxSignatures,
	})

	h := common.Hash{}

	hw.Sum(h[:0])

	return h
}
