### Title
Unescaped git pathspec magic characters in `_diff_pathspec`/`get_git_diff` let crafted filenames desync the diff from the intended review set - (File: `plugins/security-guidance/hooks/gitutil.py`)

### Summary
`get_git_diff` builds its `git diff -- <pathspec>` argument list from real repo-relative filenames returned by `_diff_pathspec` without neutralizing git's pathspec "glob" magic characters (`*`, `?`, `[...]`, `\`). A tracked/untracked file whose real name contains one of these characters is a legal POSIX filename, and when it appears in `compute_v2_review_set`'s output it is passed straight to `git diff` as a bare pathspec, so git interprets the name as a wildcard/class expression instead of a literal path.

### Finding Description
`get_git_diff(cwd, baseline_sha, ..., paths=review_paths, ...)` calls `_diff_pathspec(cwd, paths)` to turn the caller's absolute paths into repo-relative pathspec arguments: [1](#0-0) 

The realpath/`relpath` logic in `_diff_pathspec` correctly guards against symlink/worktree escape (the stated invariant of "never escape the intended repo target" via `..`-relative paths), but it performs no escaping of git's pathspec magic characters before splicing the relative name after `--`: [2](#0-1) 

`review_paths` (and therefore the `paths` argument) is sourced from `compute_v2_review_set`, which in turn is populated from real repo file names returned by `_git_status_porcelain`/`_git_name_only` — both correctly use `-z` and `core.quotePath=false` to avoid quoting/unicode corruption: [3](#0-2) 

However, none of this pipeline adds `--literal-pathspecs`, `git -c core.pathspecMagic=none`, or an explicit `:(literal)` prefix to the paths before they reach `git diff -- <pathspec>` (also true of the `git add --intent-to-add -- <files>` call in `_temp_index`). Because git's default pathspec grammar treats `*`, `?`, `[...]`, and `\` as magic, a legitimately-named repo file such as `app[i].py` or `client*.ts` is not matched literally: `[i]` is parsed as a character class and `*` as a wildcard. Since these filenames are attacker/repo-controlled (any tool call, commit, or checked-out branch content can introduce such a name), this breaks the invariant that "git path scoping must never escape the intended repo target" in the diff-restriction sense — the pathspec silently diverges from the specific file the caller intended to scope the diff to.

### Impact Explanation
When the crafted-name file is the one actually changed this turn, `git diff -- <pathspec>` can return **no match** for that pathspec element even though the file is genuinely dirty, making `diff_output` empty for that file. `handle_stop_hook` treats an empty/blank diff as "no changes since baseline" and skips security review entirely (`_skip(6)`): [4](#0-3) 

This is a required-guard bypass: a maliciously-modified file whose name happens to contain pathspec magic characters can escape the Stop-hook / commit-review security scan even though `compute_v2_review_set` correctly identified it as part of the review set. Conversely, the same magic characters can cause the pathspec to match *additional* unintended files, expanding what is diffed beyond the intended scope. Both directions are a logic-level disruption of the intended repo-diff scoping guarantee.

### Likelihood Explanation
No special privilege is needed — any workflow that creates or edits a file with a name containing `*`, `?`, `[`, or `]` (all valid on Linux/macOS filesystems) during a Claude Code turn will trigger this. It is fully attacker/repo-content-controlled (a commit, branch, or agent-driven file write can introduce such a name) and is deterministic/repeatable given the same filename.

### Recommendation
Force literal pathspec matching everywhere a filename-derived pathspec is passed to git in `gitutil.py`:
- Add `-c core.pathspecMagic=none` (or pass `--literal-pathspecs`) to `GIT_CMD`-based invocations that consume caller-supplied file paths (`get_git_diff`'s `git diff` call and `_temp_index`'s `git add --intent-to-add`), or
- Prefix each relative path in `_diff_pathspec` with `:(literal)` before appending it after `--`.

### Proof of Concept
Integration test plan (pytest, mirroring existing `gitutil`/`security_reminder_hook` test style):
1. Init a temp git repo, commit an initial file, capture baseline SHA (stash-equivalent).
2. Create/modify a tracked file literally named `app[x].py` (or `weird*.py`) with a clearly injected vulnerable pattern (e.g. `eval(user_input)`).
3. Run `compute_v2_review_set` to confirm the file is included in `review_set`/`review_paths`.
4. Call `get_git_diff(repo_root, baseline_sha, paths=review_paths, untracked_paths=untracked)` and assert the returned diff text contains the file's actual changed content.
5. **Expected failure today**: the diff is empty/does not contain the file's hunk (because `git diff -- app[x].py` treats `[x]` as a character class rather than literal brackets), demonstrating that `handle_stop_hook` would take the `_skip(6)` "no changes since baseline" path and never run the LLM review — i.e., the intended source file is silently dropped out of scope.
6. After applying the recommended `:(literal)`/`--literal-pathspecs` fix, re-run and assert the diff now correctly contains the file's changes, closing the gap.

def _diff_pathspec(cwd, paths):
    """Convert absolute touched-paths to repo-relative pathspec args for
    git diff. Paths outside cwd (e.g. ~/.claude/…) are dropped. Returns the
    list to splice after `--`, or [] for an unrestricted diff. realpath both
    sides so the macOS /var ↔ /private/var symlink doesn't make in-repo
    paths look external."""
    if not paths:
        return []
    cwd_abs = os.path.realpath(cwd)
    rel = []
    for p in paths:
        try:
            r = os.path.relpath(os.path.realpath(p), cwd_abs)
        except ValueError:
            continue
        if r.startswith(".."):
            continue
        rel.append(r)
    return ["--"] + rel if rel else []
```

def _git_status_porcelain(cwd):
    """One `git status --porcelain=v1 -z` → (tracked_dirty, untracked) sets of
    repo-root-relative paths, or (None, None) on error. Replaces the
    `_temp_index + git diff HEAD --name-only` pair for the v2 dirty_now
    computation: faster in large repos, and yields the
    untracked set separately so the later get_git_diff can do a targeted
    `add -N -- <files>` instead of a whole-tree `add -N .`.

    -uall: list individual files inside untracked directories (default
    collapses to `dir/`). Required so the untracked set subtracts cleanly
    against the UPS-time `_list_untracked` snapshot, which uses ls-files and
    therefore always lists individual files."""
    try:
        r = subprocess.run(
            [*GIT_CMD, "-c", "core.quotePath=false", "status",
             "--porcelain=v1", "-uall", "-z"],
            cwd=cwd, capture_output=True, text=True, timeout=30,
        )
        if r.returncode != 0:
            debug_log(f"_git_status_porcelain rc={r.returncode}: {r.stderr[:200]}")
            return None, None
        tracked, untracked = set(), set()
        entries = r.stdout.split("\0")
        i = 0
        while i < len(entries):
            e = entries[i]
            if not e:
                i += 1
                continue
            xy, path = e[:2], e[3:]
            if xy == "??":
                untracked.add(path)
            else:
                tracked.add(path)
                # Rename/copy entries are XY old\0new\0 — second NUL field is
                # the origin path; consume it so it isn't misparsed as a new
                # 2-char-status entry.
                if "R" in xy or "C" in xy:
                    i += 1
            i += 1
        return tracked, untracked
```

def get_git_diff(cwd, baseline_sha, full_context=False, paths=None, untracked_paths=None):
    """
    Get the git diff between the baseline SHA and the current working tree,
    including untracked (new) files.

    Uses a temporary copy of the git index (GIT_INDEX_FILE) so the user's
    real index is never modified. The temp index gets intent-to-add entries
    for untracked files, making them visible in the diff output. Cleanup
    is just deleting the temp file in a finally block.

    If `paths` is given, the diff is restricted to those paths (relative to
    cwd; absolute paths are converted, paths outside cwd are dropped).
    `untracked_paths` (repo-root-relative) is forwarded to _temp_index so it
    can add only those files instead of scanning the whole worktree.
    """
    pathspec = _diff_pathspec(cwd, paths)
    if paths and not pathspec:
        # Caller restricted to specific paths but none are inside this repo
        # (e.g. only ~/.claude/... edits). Returning "" flows to skip(6); an
        # empty pathspec would mean an UNRESTRICTED diff — the bug this whole
        # change exists to fix.
        return ""

    cmd = [*GIT_CMD, "diff", "--no-color", "--no-ext-diff", baseline_sha] + (["--unified=99999"] if full_context else []) + pathspec
