### Title
Unbounded Python recursion through nested outer-puzzle "also" drivers when parsing an attacker-supplied offer/spend bundle causes a wallet-crashing `RecursionError` - ([File: chia/wallet/outer_puzzles.py])

### Summary
`Offer.from_bytes()`/`from_bech32()` and `Offer._get_offered_coins()` call `match_puzzle()` on every `puzzle_reveal` contained in an untrusted `SpendBundle` supplied by an offer counterparty. `match_puzzle()` and the per-asset `OuterPuzzle` drivers (`CATOuterPuzzle`, `MetadataOuterPuzzle`, `SingletonOuterPuzzle`, `CROuterPuzzle`, `OwnershipOuterPuzzle`) recurse through the puzzle's nested `also` chain with no depth limit, mirroring the unbounded-recursion class described in the HAPI FHIR `XhtmlParser` advisory (deep untrusted nesting → unbounded parser recursion → `StackOverflowError`/crash). A puzzle constructed by wrapping `CAT_MOD`/`NFT_STATE_LAYER_MOD`/`SINGLETON_TOP_LAYER_MOD` inside itself hundreds of times drives Python's call stack past its recursion limit, raising an unhandled `RecursionError` while a wallet user merely inspects or takes a maliciously crafted offer.

### Finding Description
`chia/wallet/outer_puzzles.py` defines:
```python
def match_puzzle(puzzle: UnknownPuzzle) -> PuzzleInfo | None:
    for driver in driver_lookup.values():
        potential_info: PuzzleInfo | None = driver.match(puzzle)
        if potential_info is not None:
            return potential_info
    return None
``` [1](#0-0) 

Each driver's `match()` (e.g. `CATOuterPuzzle.match()`) unwraps one curried layer and recurses into `self._match(UnknownPuzzle(known_program=inner_puzzle))`, which is `match_puzzle` again:
```python
def match(self, puzzle: UnknownPuzzle) -> PuzzleInfo | None:
    args = match_cat_puzzle(puzzle)
    if args is None:
        return None
    _, tail_hash, inner_puzzle = args
    ...
    next_constructor = self._match(UnknownPuzzle(known_program=inner_puzzle))
``` [2](#0-1) 

The same "also"-chain recursion pattern exists in `MetadataOuterPuzzle`, `SingletonOuterPuzzle`, and `CROuterPuzzle` for `match`, `construct`, `get_inner_puzzle`, and `get_inner_solution`: [3](#0-2) [4](#0-3) [5](#0-4) 

The test suite itself demonstrates that a CAT puzzle can be nested inside another CAT puzzle (`double_cat_puzzle`) and successfully matched via this recursive chain, confirming the mechanism is a supported/expected pattern with no depth ceiling: [6](#0-5) 

This recursive matching is reached directly from untrusted, attacker-controlled offer bytes. `Offer.from_bytes()`/`from_spend_bundle()` calls `match_puzzle(UnknownPuzzle(known_program=coin_spend.puzzle_reveal))` for every coin spend in the parsed `WalletSpendBundle`, with `puzzle_reveal` taken verbatim from the offer file/bech32 string supplied by the offer counterparty: [7](#0-6) 

`Offer._get_offered_coins()` (invoked by `get_offer_summary`/`get_offered_coins` when a wallet inspects an offer before accepting it) performs the same `match_puzzle(parent_puzzle)` call on every spend in the bundle: [8](#0-7) 

Because `Offer.from_bytes()`/`from_bech32()` merely deserializes a `WalletSpendBundle`, there is no CLVM-cost or mempool byte-size gate at this stage (unlike mempool admission of a real spend); the only cost to the attacker is constructing a puzzle with N nested `CAT_MOD`/`NFT_STATE_LAYER_MOD`/`SINGLETON_TOP_LAYER_MOD` layers, each adding a small, roughly constant number of bytes via `curry()`. Reaching Python's default recursion limit (~1000) requires only a few hundred nested layers, which is trivial to construct and well under any block/transaction size limit — and in fact no such limit applies to a locally-parsed offer file at all.

### Impact Explanation
An offer counterparty (an unprivileged actor who can hand a wallet user an offer file or bech32 string) can cause the victim's wallet process to raise an unhandled `RecursionError` the moment the wallet inspects the offer (e.g., via `get_offer_summary`/`take_offer` RPC or CLI, which call into `Offer.from_bytes()`/`_get_offered_coins()`). This is a spend/offer-triggered processing halt: the wallet daemon/RPC call crashes or the containing async task fails, denying wallet functionality to the victim without requiring any signature, key compromise, or on-chain broadcast. This matches the "spend-triggered transaction-processing halt" impact category.

### Likelihood Explanation
Likelihood is high for any wallet user who accepts offer files from arbitrary/untrusted counterparties (a normal, expected wallet workflow in Chia's offer/trade system). No special privileges, valid signatures, or successful mempool admission are required — only that the victim's wallet parse/inspect the crafted offer bytes, which happens automatically as part of showing an offer summary before a user decides whether to accept it.

### Recommendation
Impose an explicit maximum recursion/nesting depth (or convert to an iterative work-list algorithm) in `match_puzzle()` and in the `also`-chain traversal of `CATOuterPuzzle`, `MetadataOuterPuzzle`, `SingletonOuterPuzzle`, `OwnershipOuterPuzzle`, and `CROuterPuzzle` (`match`, `construct`, `get_inner_puzzle`, `get_inner_solution`, `solve`). Reject or gracefully error on puzzles whose curried nesting depth exceeds a small, sane bound before recursing, and add tests asserting that deeply nested (e.g., 2,000+ layer) CAT/NFT/singleton puzzles fail cleanly with a handled exception rather than a `RecursionError`.

### Proof of Concept
1. Build a deeply nested CAT puzzle programmatically:
```python
inner = Program.to(1)  # ACS
for _ in range(2000):
    inner = construct_cat_puzzle(CAT_MOD, bytes32.zeros, inner)
```
2. Wrap it in a dummy `CoinSpend`/`WalletSpendBundle` with `coin.parent_coin_info == bytes32.zeros` so it parses as a `requested_payments` entry, matching the shape consumed by `Offer.from_spend_bundle()`.
3. Serialize as an `Offer` (`bytes(offer)` / `to_bech32()`) and send it to a victim wallet.
4. Victim calls `Offer.from_bech32(...)` (or the wallet RPC `get_offer_summary`/`take_offer`, which internally calls `Offer.from_bytes()` and `_get_offered_coins()`), triggering `match_puzzle()` → `CATOuterPuzzle.match()` → `self._match()` recursion ~2000 levels deep, raising `RecursionError` and aborting the wallet's processing of the offer.

Note: I was not able to execute this PoC in a live environment; the recursion depth and reachability are established from the source in `chia/wallet/outer_puzzles.py`, `chia/wallet/cat_wallet/cat_outer_puzzle.py`, and `chia/wallet/trading/offer.py`, but the exact default `sys.setrecursionlimit()` configuration used by the packaged wallet process (which could raise or lower the practical threshold) was not directly verified in this codebase.

    @classmethod
    def from_spend_bundle(cls, bundle: WalletSpendBundle) -> Offer:
        # Because of the `to_spend_bundle` method, we need to parse the dummy CoinSpends as `requested_payments`
        requested_payments: dict[bytes32 | None, list[NotarizedPayment]] = {}
        driver_dict: dict[bytes32, PuzzleInfo] = {}
        leftover_coin_spends: list[CoinSpend] = []
        for coin_spend in bundle.coin_spends:
            driver = match_puzzle(UnknownPuzzle(known_program=coin_spend.puzzle_reveal))
            if driver is not None:
                asset_id = create_asset_id(driver)
                assert asset_id is not None
                driver_dict[asset_id] = driver
            else:
                asset_id = None
            if coin_spend.coin.parent_coin_info == bytes32.zeros:
                notarized_payments: list[NotarizedPayment] = []
                for payment_group in Program.from_serialized(coin_spend.solution).as_iter():
                    nonce = bytes32(payment_group.first().as_atom())
                    payment_args_list = payment_group.rest().as_iter()
                    notarized_payments.extend(
                        [NotarizedPayment.from_condition_and_nonce(condition, nonce) for condition in payment_args_list]
                    )

                requested_payments[asset_id] = notarized_payments
            else:
                leftover_coin_spends.append(coin_spend)

        return cls(
            requested_payments, WalletSpendBundle(leftover_coin_spends, bundle.aggregated_signature), driver_dict
        )
