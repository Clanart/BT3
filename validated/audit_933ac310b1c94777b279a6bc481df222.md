### Title
Missing recipient binding in DKG blame decryption lets an attacker replay an honest party's encrypted share to falsely convict them - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
Analogous to CVE-2021-41256 (untrusted data reflected/re-dispatched under someone else's authority to reach restricted functionality), an unprivileged DKG participant can take an `EncryptedMessage` that an honest sender legitimately produced for a *different* recipient, present it via the blame mechanism while naming themselves as recipient, and cause the honest sender to be judged faulty. `EncryptedMessage`/the per-message PoP binds only the sender and ciphertext, never the intended recipient, and `blame_internal` accepts whatever `(sender, recipient)` pair the accuser claims.

### Finding Description
`EncryptedMessage` consists of `{ key, pop, msg }`; the proof-of-possession challenge `pop_challenge` binds `context`, the Schnorr nonce, the ephemeral key, `sender` (`from`), and the ciphertext — but not the recipient's encryption key (`crypto/dkg/pedpop/src/encryption.rs:302-324`). In `blame_internal` (`crypto/dkg/pedpop/src/lib.rs:575-609`), the accuser supplies `sender`, `recipient` (themselves), the `EncryptedMessage`, and an `EncryptionKeyProof`. `decrypt_with_proof` verifies the PoP (valid — it is a genuine message from `accused`), then verifies a DLEq proving `proof.key == enc_priv(recipient) * msg.key` (`encryption.rs:381-390`). The accuser knows `enc_priv(accuser)`, so they can always produce this proof for *any* `msg.key`, even though the ciphertext was encrypted under the real recipient's key. Decrypting the honest ciphertext under the accuser's key yields garbage: `from_repr` fails or `share_verification_statements(recipient=accuser, ...)` fails, and `blame_internal` returns `sender` — blaming the innocent `accused`. This is consumed by `CoordinatorMessage::VerifyBlame` in `processor/src/key_gen.rs:504-563`, where `Blame { participant: accused }` results in a fatal slash, and DKG shares are disseminated via the public `Transaction::DkgShares` path (`coordinator/src/tributary/handle.rs:320`), so the required ciphertext is observable.

### Impact Explanation
An unprivileged participant can frame any honest DKG participant, causing them to be blamed and fatally slashed for a correctly-formed share they actually delivered to someone else. This is a forged-blame / incorrect-attribution primitive that corrupts the key-generation accountability layer and enables targeted removal of honest validators.

### Likelihood Explanation
The attack requires only (a) observing a victim's `EncryptedMessage` (public on the tributary chain), (b) knowing their own DKG encryption private key, and (c) producing a standard DLEq proof. No collusion, key leakage, or protocol deviation by the victim is needed; every piece of cryptography verifies because nothing binds the claimed recipient.

### Recommendation
Bind the intended recipient into the per-message proof-of-possession and/or the DLEq transcript — e.g., include `enc_keys[&decryptor]` (the recipient's registered encryption public key) in `pop_challenge`, or include `msg.key`/recipient identity in `encryption_key_transcript`, so a message provable to one recipient cannot be re-presented under another.

### Proof of Concept
1. Participants 1..n run PedPoP; honest participant H sends `EncryptedMessage msg_H→V` to victim V (ciphertext = `cipher(context, enc_priv_V * K) ⊕ share`, `key = K`, valid PoP bound to `from = H`).
2. Attacker A observes `msg_H→V` (published DkgShares). A calls `blame(sender=H, recipient=A, msg=msg_H→V, proof)` with `proof = EncryptionKeyProof { key: enc_priv_A * K, dleq: DLEqProof::prove(..., [G, K], enc_priv_A) }`.
3. `decrypt_with_proof`: PoP verifies (genuine message from H); DLEq verifies (`proof.key = enc_priv_A * K`); decryption under `cipher(context, proof.key)` yields garbage.
4. Garbage either fails `from_repr` or fails `share_verification_statements(A, commitments[H], share)` → `blame_internal` returns `H`.
5. `AdditionalBlameMachine::new(...).blame(A, H, ...)` in `VerifyBlame` returns `H == accused` → `ProcessorMessage::Blame { participant: H }` → honest H is fatally slashed.
