### Title
Malformed participant set crashes generator promotion - (File: crypto/dkg/promote/src/lib.rs)

### Summary
`GeneratorPromotion::complete` panics when the supplied proof map has the expected length but omits any required participant, including when a proof is incorrectly keyed by the local participant. [1](#0-0) 

### Finding Description
`complete` validates only that `proofs.len() == n - 1` and that every map key is less than or equal to `n`. [2](#0-1) 

It does not reject `params.i()`, the local participant whose proof is already supplied by `self.proof`. [3](#0-2) 

After skipping `params.i()`, it unconditionally unwraps the proof for every other participant index, so a malformed map that substitutes the local participant for another participant reaches `proofs.get(&i).unwrap()` with `None`. [4](#0-3) 

The required proofs are independently deserializable public messages through `GeneratorProof::read`, which parses a group element and DLEq proof. [5](#0-4) 

### Impact Explanation
An unprivileged participant can cause a repeatable panic in the promotion state machine by supplying an incorrectly keyed proof map. [6](#0-5) 

If the host runs promotion on a critical task or does not isolate panic handling, this produces denial of service and prevents key-generator promotion from completing. [7](#0-6) 

### Likelihood Explanation
The attacker only needs to control the `Participant` key associated with a supplied `GeneratorProof`; the proof itself does not need to be valid because the missing-participant unwrap occurs before verification. [8](#0-7) 

For a two-participant promotion, submitting `n - 1 == 1` proof under the local participant ID is sufficient to satisfy both existing checks and then panic while looking for the other participant. [9](#0-8) 

### Recommendation
Validate that `proofs` contains exactly `all_participant_indexes().filter(|i| *i != params.i())`, rejecting both the local participant and any missing participant with `PromotionError` before indexing the map. [9](#0-8) 

Replace the unconditional lookup with an error-returning lookup such as `proofs.get(&i).ok_or(PromotionError::InvalidParticipant { n: params.n(), participant: i })?`. [10](#0-9) 

### Proof of Concept
```rust
use std::collections::HashMap;
use rand_core::OsRng;

use dkg::Participant;
use dkg_dealer::key_gen;
use dkg_promote::GeneratorPromotion;
use ciphersuite::Ciphersuite;

// Any in-scope ciphersuite works. C1 and C2 must have the same F and G.
fn poc<C1: Ciphersuite, C2: Ciphersuite<F = C1::F, G = C1::G>>() {
  // n = 2 means complete() expects one external proof.
  let keys = key_gen::<_, C1>(&mut OsRng, 2, 2).unwrap();
  let local_i = Participant::new(1).unwrap();
  let base = keys[&local_i].clone();

  let (promotion, _our_proof) =
    GeneratorPromotion::<C1, C2>::promote(&mut OsRng, base);

  // Satisfy proofs.len() == n - 1 and every key <= n, while omitting
  // Participant 2 by incorrectly keying the supplied proof as ourselves.
  let mut proofs = HashMap::new();
  let mut encoded = _our_proof.serialize();
  proofs.insert(
    local_i,
    dkg_promote::GeneratorProof::<C1>::read(&mut encoded.as_slice()).unwrap(),
  );

  // Panics at `proofs.get(&Participant(2)).unwrap()`.
  let _ = promotion.complete(&proofs);
}
```

The map passes the quantity check because it contains `n - 1` entries and passes the range check because the local participant ID is not greater than `n`. [11](#0-10) 

The local ID is then skipped, and lookup of required participant `2` returns `None`, causing the unwrap panic. [4](#0-3)

  /// Complete promotion by taking in the proofs from all other participants.
  pub fn complete(
    self,
    proofs: &HashMap<Participant, GeneratorProof<C1>>,
  ) -> Result<ThresholdKeys<C2>, PromotionError> {
    let params = self.base.params();
    if proofs.len() != (usize::from(params.n()) - 1) {
      Err(PromotionError::IncorrectAmountOfParticipants {
        t: params.n(),
        n: params.n(),
        amount: proofs.len() + 1,
      })?;
    }
    for i in proofs.keys().copied() {
      if u16::from(i) > params.n() {
        Err(PromotionError::InvalidParticipant { n: params.n(), participant: i })?;
      }
    }

    let mut verification_shares = HashMap::new();
    verification_shares.insert(params.i(), self.proof.share);
    for i in 1 ..= params.n() {
      let i = Participant::new(i).unwrap();
      if i == params.i() {
        continue;
      }

      let proof = proofs.get(&i).unwrap();
      proof
        .proof
        .verify(
          &mut transcript(&self.base.original_group_key(), i),
          &[C1::generator(), C2::generator()],
          &[self.base.original_verification_share(i), proof.share],
        )
        .map_err(|_| PromotionError::InvalidProof(i))?;
