## Title
Uncharged compute for repeated `Pubkey::create_program_address` (SHA256) invocations inside `translate_signers` during CPI, priced only via flat `invoke_units` - (File: program-runtime/src/cpi.rs)

## Summary
`translate_signers` in `program-runtime/src/cpi.rs` calls `Pubkey::create_program_address` once per signer-seed set supplied by the caller in a CPI, but this loop contains no `compute_meter.consume_checked` call anywhere in its body. The only compute charge levied for the whole `cpi_common` CPI entry path is the fixed `invoke_units` fee, meaning the SHA256-based PDA-derivation cost inside `translate_signers` is not metered proportionally to the number or size of seeds supplied.

## Finding Description
`cpi_common` charges a single flat fee before doing any signer work: `let amount = invoke_context.get_execution_cost().invoke_units; invoke_context.compute_meter.consume_checked(amount)?;` [1](#0-0) . It then calls `translate_signers(caller_program_id, signers_seeds_addr, signers_seeds_len, invoke_context)` [2](#0-1) .

Inside `translate_signers`, the function iterates over up to `MAX_SIGNERS` signer-seed sets, each with up to `MAX_SEEDS` seeds, and for every signer-seed set calls `Pubkey::create_program_address(&seeds_bytes, program_id)` [3](#0-2) . There is no `compute_meter.consume_checked` call anywhere in this function body — contrast this with the standalone `SyscallCreateProgramAddress` and `SyscallTryFindProgramAddress` syscalls, which explicitly charge `create_program_address_units` via `invoke_context.compute_meter.consume_checked(cost)?` before/for each PDA derivation attempt [4](#0-3) [5](#0-4) .

Thus a program invoking a CPI (`invoke_signed`) with the maximum number of signer-seed sets and maximum seeds each is charged the exact same flat `invoke_units` fee as a CPI with zero signer seeds, even though the former forces the runtime to perform `MAX_SIGNERS * MAX_SEEDS`-bounded SHA256 hashing work that a bare invoke does not incur.

## Impact Explanation
This falls under materially underpriced compute for CPI/PDA derivation, matching Agave's compute-cost mismatch bounty category (as flagged in the audit metadata "File: 'File Name: svm/src/transaction_commit_result.rs -> Scope: High. ... compute-cost mismatch'"). Because the loop bound is fixed by `MAX_SIGNERS` and `MAX_SEEDS` (enforced by `if signers_seeds.len() > MAX_SIGNERS { return Err(...) }` and `if untranslated_seeds.len() > MAX_SEEDS { return Err(...) }` at [6](#0-5) ), the extra unmetered work per CPI call is bounded rather than unbounded, so this is a per-call cost-underpricing/amplification issue (attacker can extract extra unmetered SHA256 work per compute unit spent) rather than an unbounded DoS.

## Likelihood Explanation
Fully attacker-controlled and trivially reachable: any unprivileged program can invoke `invoke_signed` via CPI supplying `signers_seeds_addr`/`signers_seeds_len` pointing to the maximum `MAX_SIGNERS` signer-seed arrays, each containing `MAX_SEEDS` seeds of near-maximum length. No special privileges, staked node, or non-standard preconditions are required — this is reachable through a single ordinary CPI call from a deployed sBPF program with the attacker's own lamports.

## Recommendation
Add an explicit `compute_meter.consume_checked` charge inside `translate_signers` (or in `cpi_common` immediately around the `translate_signers` call) that scales with the actual number of `Pubkey::create_program_address` calls performed and the seed byte volume — e.g., charge `create_program_address_units` (as used by `SyscallCreateProgramAddress`) per signer-seed set, plus SHA256 byte cost proportional to total seed bytes, mirroring the metering already done in the standalone `SyscallCreateProgramAddress`/`SyscallTryFindProgramAddress` syscalls.

## Proof of Concept
Rust unit test plan (to be added alongside `test_translate_signers` in `program-runtime/src/cpi.rs`):
1. Build a mock `invoke_context` with `compute_meter` starting at a fixed budget `B` (e.g., equal to `invoke_units + small_margin`, deliberately excluding any headroom for PDA derivation cost).
2. Case A ("minimal"): call `translate_signers` with `signers_seeds_len == 0`.
3. Case B ("maximal"): construct `MAX_SIGNERS` signer-seed sets, each with `MAX_SEEDS` seeds of length `MAX_SEED_LEN`, mapped into VM memory via `mock_signers`, and call `translate_signers` with `signers_seeds_len == MAX_SIGNERS`.
4. Assert that `invoke_context.compute_meter.get_remaining()` is identical (modulo only the flat `invoke_units` deduction already applied in `cpi_common`) after Case A and Case B — i.e., no additional compute was consumed for the extra `MAX_SIGNERS * MAX_SEEDS` SHA256-based `create_program_address` invocations performed in Case B, despite the measurable extra CPU work.
5. Additionally use `std::time::Instant` to measure wall-clock time of `translate_signers` for both cases and assert the maximal case takes materially longer while consuming zero additional compute units — demonstrating the CPU/compute-unit cost mismatch described in the audit question.

pub fn translate_signers(
    program_id: &Pubkey,
    signers_seeds_addr: u64,
    signers_seeds_len: u64,
    invoke_context: &InvokeContext,
) -> Result<Vec<Pubkey>, Error> {
    let check_aligned = invoke_context.get_check_aligned();
    let memory_mapping = invoke_context.memory_contexts.memory_mapping()?;
    if signers_seeds_len > 0 {
        let signers_seeds = translate_slice::<VmSlice<VmSlice<u8>>>(
            memory_mapping,
            signers_seeds_addr,
            signers_seeds_len,
            check_aligned,
        )?;
        if signers_seeds.len() > MAX_SIGNERS {
            return Err(Box::new(CpiError::TooManySigners));
        }
        Ok(signers_seeds
            .iter()
            .map(|signer_seeds| {
                let untranslated_seeds = translate_slice::<VmSlice<u8>>(
                    memory_mapping,
                    signer_seeds.ptr(),
                    signer_seeds.len(),
                    check_aligned,
                )?;
                if untranslated_seeds.len() > MAX_SEEDS {
                    return Err(Box::new(InstructionError::MaxSeedLengthExceeded) as Error);
                }
                let seeds_bytes = untranslated_seeds
                    .iter()
                    .map(|untranslated_seed| {
                        translate_vm_slice(untranslated_seed, memory_mapping, check_aligned)
                    })
                    .collect::<Result<Vec<_>, Error>>()?;
                Pubkey::create_program_address(&seeds_bytes, program_id)
                    .map_err(|err| Box::new(CpiError::BadSeeds(err)) as Error)
            })
            .collect::<Result<Vec<_>, Error>>()?)
    } else {
        Ok(vec![])
    }
}

        let mut bump_seed = [u8::MAX];
