### Title
SSRF via unauthenticated on-chain DataLayer mirror URLs fetched by `http_download` - (File: chia/data_layer/download_data.py)

### Summary
Chia's DataLayer subscription/mirror system lets **any** wallet on the network publish an on-chain "mirror" coin containing an arbitrary list of URL strings tied to any DataLayer store's `launcher_id`. Peer nodes that track that store ingest these URLs unconditionally into their local mirror/subscription tables and later have their DataLayer service issue outbound HTTP requests to them via `http_download()`, with no validation of scheme or destination host. This is the direct structural analog of CVE-2018-19047 (mPDF `getImage()` fetching attacker-supplied URLs without SSRF filtering).

### Finding Description
A `Mirror` coin is created by spending any coin to `create_mirror_puzzle()`'s puzzle hash with memos `[launcher_id, *urls]` via `DataLayerWallet.create_new_mirror()` [1](#0-0) . This requires only a standard XCH spend — anyone can create such a coin for **any** `launcher_id`, including stores they do not own, since the puzzle/solution only encodes an arbitrary memo payload, not an ownership proof.

When any wallet observes this coin type on chain, `DataLayerWallet.coin_added()` decodes the memo via `get_mirror_info()` and, as long as the `launcher_id` is one this wallet already tracks (i.e., any store the victim node subscribes to or owns), unconditionally records the attacker-chosen URLs into `dl_store.add_mirror()` — with no host/scheme validation: [2](#0-1) .

The DataLayer service periodically pulls these mirror URLs via `update_subscriptions_from_wallet()` and stores them as subscription server URLs: [3](#0-2) . During sync, `fetch_and_validate()` selects one of these attacker-controlled URLs and passes it into `insert_from_delta_file()` → `download_file()` → `http_download()`: [4](#0-3) .

`http_download()` performs a raw outbound `aiohttp` GET against the attacker-supplied URL with no allow-list, scheme restriction, or private/loopback-address filtering: [5](#0-4) . The existing test suite even demonstrates mirror URLs of `http://127.0.0.1/8000` being accepted without complaint [6](#0-5) , confirming no loopback/internal-address filtering exists.

### Impact Explanation
Any unprivileged chain participant can force a victim's DataLayer node process to issue authenticated-context, server-side HTTP GET requests to arbitrary attacker-chosen endpoints — including the node's own loopback RPC ports, other internal services (e.g. `chia_full_node`, `chia_wallet`, `chia_farmer` RPC ports, or Docker/K8s-internal hosts), or cloud metadata endpoints (`169.254.169.254`). Because these requests originate from the operator's own network position, this is a classic SSRF that can be used to probe internal network topology, hit internal management interfaces, or in constrained environments exfiltrate metadata/credentials, depending on deployment. This directly matches the mPDF SSRF bug class: attacker-controlled input reaching an unrestricted server-side fetch.

### Likelihood Explanation
Likelihood is high for any node operator running the DataLayer service and subscribing to (or owning) any public store: the attacker only needs to know a `launcher_id` (public, on-chain) and spend a small amount of XCH to create a mirror coin with malicious memo URLs — no special permission, DL ownership, or privileged RPC access is required. The periodic sync loop (`periodically_manage_data()`) automatically pulls these mirrors and triggers the fetch without operator interaction.

### Recommendation
- Validate and sanitize mirror URLs before storing/using them: enforce an allow-list of schemes (`http`/`https` only), reject loopback/link-local/private IP ranges (RFC1918, 127.0.0.0/8, 169.254.0.0/16, etc.) unless explicitly opted in, and consider DNS-rebinding protections at fetch time (re-resolve and re-check before connecting).
- Add this validation both when persisting mirrors from `coin_added()`/`dl_store.add_mirror()` and defensively again in `http_download()`/`download_file()` immediately before the outbound request.
- Consider requiring operator opt-in/allow-listing of trusted mirror hosts, since mirror URLs are fully attacker-controlled on-chain data.

### Proof of Concept
1. Attacker learns the `launcher_id` of any DataLayer store the victim node tracks or owns (public on-chain identifier).
2. Attacker spends any coin they control, creating an output to `create_mirror_puzzle().get_tree_hash()` with memos `[launcher_id, b"http://127.0.0.1:8562/get_routes"]` (or any internal/loopback URL) using the same mechanism as `DataLayerWallet.create_new_mirror()`.
3. Once confirmed, the victim's `DataLayerWallet.coin_added()` picks up the coin, decodes the memo, and stores the malicious URL via `dl_store.add_mirror()` since the `launcher_id` is tracked.
4. The victim's `DataLayer.periodically_manage_data()` loop calls `update_subscriptions_from_wallet()`, adding the malicious URL to `servers_info` for that store.
5. On the next `fetch_and_validate()` cycle, `download_file()`/`http_download()` issues an outbound GET to the attacker-chosen URL from the victim's own process/network context — completing the SSRF.

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
