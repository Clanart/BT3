### Title
Ed448 `is_torsion_free` is vacuously true, admitting small-subgroup (torsion) points wherever a prime-order point is assumed - (File: crypto/ed448/src/point.rs)

### Summary
Analogous to the kernel bug where `pmd_special()`/`pud_special()` were assumed implemented but silently no-oped (so special pages were misclassified as normal), `Point::is_torsion_free` in `crypto/ed448` is assumed to reject non-prime-order points but is implemented as `((*self * (Scalar::ZERO - Scalar::ONE)) + self).is_identity()`, i.e. `(-P) + P == identity`. This holds for *every* point on the curve, so the predicate never rejects anything. `GroupEncoding::from_bytes` gates acceptance on `point.is_torsion_free()`, meaning any attacker-supplied Ed448 encoding that decompresses and is canonical is accepted as a prime-group element even if it carries a low-order (4-torsion) component.

### Finding Description [1](#0-0) [2](#0-1) 

The correct cofactor check for a prime-order subgroup of order `q` is `P * q == identity`. Instead, the code multiplies the point by `Scalar::ZERO - Scalar::ONE` (i.e. `-1 mod q`) and adds `self`, computing `-P + P`, which is the identity for all inputs. Since `Ed448::read_G` (via `Ciphersuite::read_G` → `GroupEncoding::from_bytes` → the round-trip canonicality check in `crypto/ciphersuite/src/lib.rs:91-101`) treats this as proof of prime-subgroup membership, torsioned points flow into every protocol using the `Ed448` ciphersuite: `SchnorrSignature::<Ed448>::read`/`verify`, FROST preprocess/share/group-key parsing for Ed448, PedPoP `Commitments::read`, and `ThresholdKeys::<Ed448>::read` verification shares.

This breaks the `PrimeGroup` contract that all of these protocols assume (the type is even declared `impl PrimeGroup for Point` elsewhere in the crate), so downstream equations `sG == R + cA`, interpolation over verification shares, and binding-factor commitments operate on elements outside the prime-order subgroup.

### Impact Explanation
- **Incorrect verification predicate**: a public input (raw 57-byte Ed448 point encoding) carrying a non-trivial torsion component is accepted wherever a prime-order point is required. Because the byte encodings differ, two points equal in the prime subgroup but differing in their torsion component are accepted as *distinct* group elements — defeating duplicate-commitment/duplicate-encoding checks in DKG/PedPoP and FROST preprocessing, where distinct encodings map to distinct `Participant`/commitment entries while being subgroup-equivalent.
- **Signature/statement malleability and equivocation**: an unprivileged participant can register a verification share or nonce commitment of the form `P + T` (`T` a 4-torsion point). Its prime-subgroup behavior is `P`, but its serialization and any full-group equation differ, allowing the same effective key/share to appear under multiple identities and enabling inconsistent views of verification shares across parties that accept the encoding.
- Severity: Medium — no direct discrete-log recovery is demonstrated, but a security-critical validation predicate is dead code, violating the prime-group invariant relied on by Schnorr/FROST/DKG verification over Ed448, reachable purely from attacker-controlled bytes passed to `read_G`/`Commitments::read`/`SchnorrSignature::read`.

### Likelihood Explanation
Fully deterministic: the predicate is mathematically always true, so every torsioned-but-canonical encoding is accepted on every path that decodes an Ed448 point. No timing, race, or probabilistic element is involved. Exploitation requires only that the attacker supplies an Ed448 point encoding to a deserialization or verification endpoint (e.g., a PedPoP `Commitments` message or a FROST preprocess over Ed448) — public input per the engagement rules. Crafting such a point is trivial: decompress a valid `y`, add a known 4-torsion point, re-encode canonically.

### Recommendation
Replace the vacuous check with a real subgroup-membership test: `is_torsion_free` should compute `(*self * Scalar::MODULUS-equivalent prime-order q).is_identity()`, i.e. multiply by the order of the prime subgroup (the scalar field modulus `q`), not by `-1`. Add a regression test asserting that a known low-order Ed448 point encoding is rejected by `Ed448::read_G` / `Point::from_bytes`.
