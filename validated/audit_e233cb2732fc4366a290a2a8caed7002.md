## Analysis

The core broken invariant in H-2 is: a security check computed using a **stale/wrong accounting variable** (`isoUSDLoaned`, principal-only) instead of the variable that reflects the true, current outstanding position (`isoUSDLoanAndInterest`), letting the attacker bypass a solvency check.

The Hyperbridge codebase has a structurally identical pattern in the Tron deployment of the Intent Gateway: `evm/tron/contracts/apps/IntentGatewayV2.sol`'s `cancelOrder()`/`withdraw()` same-chain path uses `order.inputs[i].amount` (the amount recorded **at order placement**) as the refund amount instead of `_orders[commitment][token]` (the actual remaining escrow, which is drained proportionally by any solver partial fills). The current, fixed EVM contract (`evm/src/apps/intentsv2/IntrinsicIntents.sol`, `_cancelSameChain`) explicitly reads `_orders[commitment][token]` for this exact reason.

### Title
Same-chain order cancellation on the Tron IntentGateway refunds the original escrowed amount instead of the actual remaining balance, enabling over-refund/fund drain via native-token reentrancy - (File: evm/tron/contracts/apps/IntentGatewayV2.sol)

### Summary
`cancelOrder()`'s same-chain branch and the shared `withdraw()` helper in `evm/tron/contracts/apps/IntentGatewayV2.sol` build the refund `WithdrawalRequest` from `order.inputs` (the order's original escrow amount, fixed at placement) rather than from `_orders[commitment][token]` (the live, per-token escrow balance that is decremented on every partial fill). [1](#0-0)  The token-safe fixed version of the contract instead re-reads the live escrow balance before refunding. [2](#0-1) 

### Finding Description
Same-chain orders on this Intent Gateway support partial fills: `fillOrder` decrements `_orders[commitment][token]` by the proportion filled and pays the solver out of escrow, leaving `_orders[commitment][token]` strictly less than `order.inputs[i].amount` for a partially-filled order. [3](#0-2) 

In `evm/tron/contracts/apps/IntentGatewayV2.sol`, `cancelOrder`'s same-chain branch builds the refund request directly from `order.inputs` (the amount escrowed at placement — the wrong/stale variable) instead of the live per-token balance: [1](#0-0) 

That request flows into the shared `withdraw()` function, which:
1. only checks `_orders[commitment][token] == 0` (existence, not sufficiency),
2. transfers the (possibly inflated) `amount` from `body.tokens[i]` to the beneficiary via a raw low-level `.call` — including a raw native-ETH `.call{value: amount}("")` for the native-token branch, which hands control to the beneficiary before any state update,
3. only afterwards does `_orders[body.commitment][token] -= amount`. [4](#0-3) 

Because the transfer of the inflated `amount` (original escrow, not remaining escrow) happens before the balance is decremented, and `cancelOrder`/`withdraw` in this contract carry no `nonReentrant` guard (unlike the corresponding functions in the fixed `evm/src/apps/IntentGatewayV2.sol`, which is `nonReentrant`) [5](#0-4) , a native-token beneficiary contract can re-enter `cancelOrder` (or another path touching the same commitment) during the `.call{value:}` before `_orders[commitment][token]` is decremented, repeatedly draining the contract's pooled escrow beyond what was ever escrowed for that specific order. Even without reentrancy, the wrong-variable bug alone causes the refund to attempt paying out more than is actually escrowed for a partially-filled order, corrupting the invariant that `_orders[commitment][token]` tracks true liability.

### Impact Explanation
This directly matches the bounty's fund-custody impact class: escrowed bridge assets can move to the wrong amount/beneficiary (over-refund) and, via the reentrancy compounding effect from the raw native-token `.call`, an unprivileged attacker (the order's own user, who legitimately controls `cancelOrder` for their own commitment) can drain other orders' pooled escrow held by the same gateway contract — a direct loss-of-funds / unauthorized-transaction-manipulation scenario, not merely a griefing or DoS.

### Likelihood Explanation
Likelihood is high for any deployment of this Tron contract variant: no special relayer, prover, or governance role is required — only an ordinary user who (a) places a same-chain order, (b) gets it partially filled by any solver, and (c) calls `cancelOrder` themselves (as required by the `Unauthorized()` check, which the legitimate order owner naturally satisfies), optionally as/behind a smart-contract wallet to add the reentrant callback for the native-token case. This is a public entry point reachable by any unprivileged token holder.

### Recommendation
Mirror the fix already applied in `evm/src/apps/intentsv2/IntrinsicIntents.sol::_cancelSameChain`: read `_orders[commitment][token]` for each input token to build the refund's `tokens` array instead of `order.inputs`, and add a `nonReentrant` guard to `cancelOrder`/`withdraw` in the Tron contract, matching `evm/src/apps/IntentGatewayV2.sol`.

### Proof of Concept
1. User places a same-chain order via `placeOrder`, escrowing `order.inputs[0].amount = 1000` USDC for `_orders[commitment][USDC] = 1000`.
2. A solver partially fills 400 USDC worth via `fillOrder`, so `_orders[commitment][USDC]` is decremented to `600` and 400 USDC-equivalent escrow is already paid out (mirrors "attacker repays principal but leaves interest owed" in H-2 — the accounting variable diverges from the placement-time amount).
3. User calls `cancelOrder(order, options)` on the same chain. `cancelOrder` builds `WithdrawalRequest{tokens: order.inputs}` using the **original** `1000` USDC figure rather than the live `600` remaining. [1](#0-0) 
4. `withdraw()` only checks `_orders[commitment][USDC] != 0` (true, it's 600), then transfers `1000` USDC to the user — 400 more than is actually still escrowed for this order, before decrementing `_orders[commitment][USDC] -= 1000` — for a native-token order this pays out via `.call{value: amount}` before the decrement, allowing the user (as a smart-contract beneficiary) to re-enter and repeat the drain against the shared escrow pool. [4](#0-3)

    function _fillSameChain(Order calldata order, FillOptions calldata options, bytes32 commitment) internal {
        uint256 outputsLen = order.output.assets.length;

        _filled[commitment] = msg.sender;

        uint256 msgValue = msg.value;
        address beneficiary = address(uint160(uint256(order.output.beneficiary)));
        bool isFullyFilled = true;

        TokenInfo[] memory escrowedInputs = new TokenInfo[](outputsLen);
        TokenInfo[] memory outputFills = new TokenInfo[](outputsLen);

        for (uint256 i; i < outputsLen; i++) {
            bytes32 outputToken = order.output.assets[i].token;
            if (options.outputs[i].token != outputToken) revert InvalidInput();

            address token = address(uint160(uint256(outputToken)));
            uint256 totalRequired = order.output.assets[i].amount;
            uint256 solverAmount = options.outputs[i].amount;

            uint256 alreadyFilled = _partialFills[commitment][outputToken];
            uint256 remaining = totalRequired - alreadyFilled;
            if (remaining == 0 || solverAmount == 0) {
                if (solverAmount == 0 && remaining > 0) isFullyFilled = false;
                continue;
            }
            uint256 fillAmount;

            uint256 beneficiaryShare = 0;
            uint256 protocolShare = 0;
            if (alreadyFilled == 0 && solverAmount > totalRequired) {
                fillAmount = totalRequired;
                uint256 dust = solverAmount - totalRequired;
                if (order.output.call.length > 0) {
                    protocolShare = dust;
                } else {
                    protocolShare = (dust * _params.surplusShareBps) / 10_000;
                    beneficiaryShare = dust - protocolShare;
                }
            } else {
                fillAmount = solverAmount > remaining ? remaining : solverAmount;
            }

            uint256 amountFilled = alreadyFilled + fillAmount;
            _partialFills[commitment][outputToken] = amountFilled;
            uint256 beneficiaryTotal = fillAmount + beneficiaryShare;

            if (token == address(0)) {
                if (msgValue < beneficiaryTotal + protocolShare) revert InsufficientNativeToken();
                msgValue -= (beneficiaryTotal + protocolShare);
                (bool sent,) = beneficiary.call{value: beneficiaryTotal}("");
                if (!sent) revert InsufficientNativeToken();
            } else {
                IERC20(token).safeTransferFrom(msg.sender, beneficiary, beneficiaryTotal);
                if (protocolShare > 0) {
                    IERC20(token).safeTransferFrom(msg.sender, address(this), protocolShare);
                }
            }

            if (totalRequired > amountFilled) isFullyFilled = false;
            if (protocolShare > 0) emit DustCollected(token, protocolShare);

            uint256 escrowedAmount;
            if (amountFilled == totalRequired) {
                escrowedAmount = _orders[commitment][address(uint160(uint256(order.inputs[i].token)))];
            } else {
                escrowedAmount = (order.inputs[i].amount * fillAmount) / totalRequired;
            }
            escrowedInputs[i] = TokenInfo({token: order.inputs[i].token, amount: escrowedAmount});

    function _cancelSameChain(Order calldata order, bytes32 commitment) internal {
        if (order.user != bytes32(uint256(uint160(msg.sender)))) revert Unauthorized();

        address hostAddr = host();
        bytes32 currentChain = keccak256(IDispatcher(hostAddr).host());
        bytes32 orderSource = keccak256(order.source);
        if (orderSource != currentChain) revert WrongChain();

        uint256 inputsLen = order.inputs.length;
        TokenInfo[] memory remainingTokens = new TokenInfo[](inputsLen);
        bool hasEscrow = false;
        for (uint256 i; i < inputsLen;) {
            address token = address(uint160(uint256(order.inputs[i].token)));
            uint256 escrowed = _orders[commitment][token];
            if (escrowed > 0) hasEscrow = true;
            remainingTokens[i] = TokenInfo({token: order.inputs[i].token, amount: escrowed});
            unchecked {
                ++i;
            }
        }
        if (!hasEscrow) revert UnknownOrder();

        WithdrawalRequest memory body =
            WithdrawalRequest({commitment: commitment, tokens: remainingTokens, beneficiary: order.user});

        _withdraw(body, true, true);
    }

    function cancelOrder(Order calldata order, CancelOptions calldata options) public payable nonReentrant {
        bytes32 commitment = keccak256(abi.encode(order));

        if (_filled[commitment] != address(0)) revert Filled();

        address hostAddr = host();
        bytes32 currentChain = keccak256(IDispatcher(hostAddr).host());
        bytes32 orderSource = keccak256(order.source);
        bytes32 orderDest = keccak256(order.destination);
        bool isSameChain = orderSource == orderDest;

        if (isSameChain) {
            _cancelSameChain(order, commitment);
        } else if (currentChain == orderSource) {
            _cancelFromSource(order, options, commitment);
        } else if (currentChain == orderDest) {
            _cancelFromDest(order, options, commitment);
        } else {
            revert WrongChain();
        }
    }
