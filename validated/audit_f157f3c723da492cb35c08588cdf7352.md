### Title
Data race on `TxPool.gasPrice` / `TxPool.rules` due to unsynchronized write in `reset()` - (File: `blockchain/tx_pool.go`)

### Summary
`TxPool.gasPrice` is documented and consumed as a lock-protected field (`GasPrice()` takes `pool.mu.RLock()`, `SetGasPrice()` takes `pool.mu.Lock()`), but `TxPool.reset()` mutates both `pool.rules` and `pool.gasPrice` without holding `pool.mu` at all, creating a data race analogous to the missing `READ_ONCE()`/lock discipline described in the Linux CVE (a value that must be read/written under a consistent synchronization discipline is instead accessed unguarded on the write side).

### Finding Description
`TxPool.GasPrice()` and `TxPool.SetGasPrice()` both treat `pool.gasPrice` as protected by `pool.mu`: [1](#0-0) 

However, `reset()` — which runs on every new chain head / reorg via the pool's block-processing path — updates `pool.rules` and then `pool.gasPrice` with no lock held. Notably, the lock acquisition that should guard this section is explicitly commented out: [2](#0-1) [3](#0-2) 

`lockedReset()` (used only in tests, per its own comment "This method is only ever used in the tester!") wraps `reset()` with `pool.mu.Lock()`, implying the production caller of `reset()` is expected to already hold the lock, but the write to `pool.gasPrice`/`pool.rules` happens outside any lock scope inside `reset()` itself, while concurrent readers such as `GasPrice()` (called by fee estimation/`SuggestPrice`, `AccountUpdateTxArgs.setDefaults`, and by tx admission logic that gates the KIP-71 Magma minimum price) take `pool.mu.RLock()`. A write happening concurrently with these reads without a shared lock is a Go data race — this can manifest as the CPU/compiler observing a torn or stale `*big.Int` pointer for `pool.gasPrice`, or worse, `go test -race` / production race detector fatal exits, and functionally an admission check using either the pre- or partially-updated base fee.

### Impact Explanation
Because `pool.gasPrice` (the enforced minimum acceptable gas price under Magma/KIP-71 pricing) can be read while being concurrently overwritten without synchronization, a submitted transaction's admission check can observe an inconsistent/stale value of the network's dynamic base fee. This can lead to acceptance of underpriced transactions (fee-abuse / bypass of KIP-71 pricing floor) or to divergent admission behavior between nodes processing the same head concurrently with pool activity, which is a state-divergence-class impact reachable purely from ordinary transaction submission timed around a block transition — no privileged or node-internal actor required.

### Likelihood Explanation
`reset()` is invoked on every chain head update (very frequent, once per block, more often during reorgs), and `GasPrice()`/`SuggestPrice` are invoked on essentially every RPC gas-price query and every default-filling of a transaction's gas price (`AccountUpdateTxArgs.setDefaults` and similar callers). The race window is therefore hit continuously in normal network operation, requiring no special conditions beyond ordinary concurrent transaction submission around block boundaries.

### Recommendation
Guard the writes to `pool.gasPrice` and `pool.rules` inside `reset()` with `pool.mu.Lock()`/`Unlock()` (restoring the currently commented-out lock, or acquiring it specifically around the `pool.rules`/`pool.gasPrice` assignment block), ensuring all readers and writers of these fields consistently synchronize via `pool.mu`, mirroring the fix pattern of adding the missing synchronization primitive (as `READ_ONCE()` did for the kernel's `sysctl_tcp_thin_linear_timeouts`).

### Proof of Concept
1. Run the node with active transaction submission (calling `eth_gasPrice`/`SuggestPrice`, which internally calls `TxPool.GasPrice()` under `pool.mu.RLock()`) concurrently with normal block production, which triggers `TxPool.reset()` on each new head.
2. Observe with Go's race detector (`-race`) that `reset()`'s unlocked assignment to `pool.gasPrice` at [4](#0-3)  races against `GasPrice()`'s locked read at [5](#0-4) , confirming the unsynchronized concurrent access.

// GasPrice returns the current gas price enforced by the transaction pool.
func (pool *TxPool) GasPrice() *big.Int {
	pool.mu.RLock()
	defer pool.mu.RUnlock()

	return new(big.Int).Set(pool.gasPrice)
}

// SetGasPrice updates the gas price of the transaction pool for new transactions, and drops all old transactions.
func (pool *TxPool) SetGasPrice(price *big.Int) {
	if pool.rules.IsMagma {
		logger.Info("Ignoring SetGasPrice after Magma fork")
		return
	}
	if pool.gasPrice.Cmp(price) != 0 {
		pool.mu.Lock()

		logger.Info("TxPool.SetGasPrice", "before", pool.gasPrice, "after", price)

		pool.gasPrice = price
		pool.pending = make(map[common.Address]*txList)
		pool.queue = make(map[common.Address]*txList)
		pool.pendingCount = 0
		pool.queuedCount = 0
		pool.beats = make(map[common.Address]time.Time)
		pool.all = newTxLookup()
		pool.pendingNonce = make(map[common.Address]uint64)
		pool.locals = newAccountSet(pool.signer)
		pool.priced = newTxPricedList(pool.all)

		pool.mu.Unlock()
	}
}
