### Title
`Duration` unary negation operator throws unchecked `OverflowException` on attacker-controlled `Seconds == long.MinValue` - ([File: csharp/src/Google.Protobuf/WellKnownTypes/DurationPartial.cs])

### Summary
The GMX report shows `Calc.boundedSub` failing to guard against negating `type(int256).min`, causing an unexpected revert. The direct Protobuf analog is in the C# well-known-types helper for `Duration`: `Duration.operator -(Duration value)` unconditionally negates the attacker-controlled `Seconds` field inside a `checked` arithmetic block. A `Duration.Seconds` value of `long.MinValue` (a fully valid `int64` value on the wire, no wire-format restriction to the documented `[-315576000000, 315576000000]` range) causes `-value.Seconds` to overflow, throwing an unhandled `System.OverflowException`.

### Finding Description
`Duration.Seconds` is declared as a plain `int64` field in `duration.proto` and is parsed by the standard `CodedInputStream`/`ParsingPrimitives` varint path with no range restriction to the documented Duration bounds — any 64-bit value, including `long.MinValue`, is accepted as valid wire data. [1](#0-0) 

The only bound checking for Duration values (`IsNormalized`) is performed in specific helper paths like `ToJson`/`ToTimeSpan`, but is *not* enforced before the negation operator runs: [2](#0-1) 

The vulnerable operator negates `value.Seconds` directly, inside a `checked` block, with no special case for `long.MinValue`:
```csharp
public static Duration operator -(Duration value)
{
    ProtoPreconditions.CheckNotNull(value, "value");
    checked
    {
        return Normalize(-value.Seconds, -value.Nanos);
    }
}
``` [3](#0-2) 

This mirrors the failed invariant in `Calc.boundedSub`: the code assumes negation of an attacker-supplied signed integer is always safe, but for the minimum representable value (`type(int256).min` in Solidity / `long.MinValue` in C#), negation cannot be represented in the same signed type and overflows. `Normalize` (called after the negation) never gets a chance to run because the `checked` negation throws first: [4](#0-3) 

The related binary subtraction operator has an analogous exposure: `lhs.Seconds - rhs.Seconds` inside `checked` will overflow whenever `rhs.Seconds == long.MinValue` and `lhs.Seconds >= 0`, since subtracting `long.MinValue` is equivalent to adding `2^63`: [5](#0-4) 

### Impact Explanation
An attacker who controls the bytes of a bounded, well-formed binary Protobuf (or ProtoJSON) message containing a `Duration` field can set `seconds = -9223372036854775808`. If the trusted consuming C# application later calls the standard, publicly documented negation (`-duration`) or subtraction (`durationA - durationB`) operators on that value — a natural operation for any app doing duration/timestamp arithmetic with attacker-influenced data — the operator throws an unhandled `OverflowException`. This is a denial-of-service / unexpected-failure condition in application logic that trusted the message as "just data," directly analogous to the GMX report's "transactions that would have been expected to pass would fail" impact, but manifesting as a thrown exception rather than a blockchain revert.

### Likelihood Explanation
Likelihood is Medium: this requires (a) the parser to accept an out-of-documented-range `Duration.seconds` (true — the binary/JSON parser applies no range restriction on the raw `int64`), and (b) the consuming application to invoke `Duration`'s negation/subtraction operator on the attacker-influenced value without first validating via `IsNormalized`. Applications performing generic Duration math on externally sourced protobuf messages (a common pattern, e.g. computing elapsed/remaining time) are directly exposed.

### Recommendation
Special-case `long.MinValue` before negating in `Duration.operator -(Duration value)` (and consider validating `IsNormalized` before performing arithmetic), for example:
```csharp
public static Duration operator -(Duration value)
{
    ProtoPreconditions.CheckNotNull(value, "value");
    if (value.Seconds == long.MinValue)
    {
        throw new InvalidOperationException("Duration seconds value cannot be negated (long.MinValue)");
    }
    checked
    {
        return Normalize(-value.Seconds, -value.Nanos);
    }
}
```
Similarly guard `operator -(Duration lhs, Duration rhs)` and `operator +` against unnormalized inputs (e.g. by requiring `IsNormalized` on both operands, matching the documented Duration contract) instead of relying solely on `checked` to surface overflow as an uncaught exception.

### Proof of Concept
1. Construct (or receive from an attacker) a binary Protobuf message for `Duration` with field 1 (`seconds`) varint-encoded to `-9223372036854775808` (`long.MinValue`). This is a syntactically valid, bounded wire payload; `CodedInputStream`/`ParsingPrimitives` parses it without any range check against the `[-315576000000, 315576000000]` Duration contract.
2. In application code: `Duration d = Duration.Parser.ParseFrom(attackerBytes);`
3. Call `var negated = -d;` (or `var diff = otherDuration - d;` where `otherDuration.Seconds >= 0`).
4. `checked { -value.Seconds }` with `value.Seconds == long.MinValue` throws `System.OverflowException`, crashing the calling code path unless the caller has defensively wrapped the call in a try/catch — which is not indicated anywhere in the documented API contract for these operators.

        internal static Duration Normalize(long seconds, int nanoseconds)
        {
            // Ensure that nanoseconds is in the range (-1,000,000,000, +1,000,000,000)
            int extraSeconds = nanoseconds / NanosecondsPerSecond;
            seconds += extraSeconds;
            nanoseconds -= extraSeconds * NanosecondsPerSecond;

            // Now make sure that Sign(seconds) == Sign(nanoseconds) if Sign(seconds) != 0.
            if (seconds < 0 && nanoseconds > 0)
            {
                seconds += 1;
                nanoseconds -= NanosecondsPerSecond;
            }
            else if (seconds > 0 && nanoseconds < 0)
            {
                seconds -= 1;
                nanoseconds += NanosecondsPerSecond;
            }
            return new Duration { Seconds = seconds, Nanos = nanoseconds };
        }
