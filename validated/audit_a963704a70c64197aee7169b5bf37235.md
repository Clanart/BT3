### Title
Attacker-controlled `WWW-Authenticate` realm spoofs GitHub Enterprise sign-in, redirecting credentials to a malicious endpoint - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
Git forwards `WWW-Authenticate` response headers received from a remote server to credential helpers as `wwwauth[]` fields in the credential protocol. GitHub Desktop's `getEndpointKind` trusts an attacker-supplied `realm="GitHub"` value in that header to classify an arbitrary host as an `'enterprise'` GitHub endpoint, which then triggers `promptForGitHubSignIn` and points the sign-in flow at the attacker's own origin.

### Finding Description
`getEndpointKind` in `app/src/lib/trampoline/trampoline-credential-helper.ts` inspects the credential map's `wwwauth[...]` entries (populated straight from the HTTP response the remote returns) and classifies the host as `'enterprise'` purely because the header string contains `realm="GitHub"`: [1](#0-0) 

This value is fully attacker-controlled: any git server (or a MITM/malicious proxy responding to a `git fetch`/`git clone`/`git push` over HTTPS) can return a `401` response with `WWW-Authenticate: Basic realm="GitHub"` and Desktop will treat the endpoint as GitHub Enterprise, with no verification that the host is an actual GHE instance (no TLS cert check, no `/api/v3` probe, no `.ghe.com` suffix check — that path is only reached later via `isGitHubHost` for hosts that don't send a spoofed header).

Because the endpoint is classified as non-`'generic'`, `getCredential` checks whether an existing account matches the endpoint; if not, it calls `promptForGitHubSignIn(endpoint)`: [2](#0-1) 

`promptForGitHubSignIn` then routes the user into the Enterprise sign-in UI and explicitly binds the sign-in flow's endpoint to the attacker-controlled `origin`: [3](#0-2) 

Since `dispatcher.setSignInEndpoint(origin)` is called with the origin taken directly from the spoofed credential URL, the entire GitHub Enterprise OAuth/basic-auth sign-in flow is pointed at the attacker's server.

### Impact Explanation
A user cloning/fetching from, or being redirected to, a malicious git remote can be shown Desktop's native "Sign in to GitHub Enterprise" dialog while the underlying endpoint used to actually perform the sign-in exchange is the attacker's server. If the user proceeds (a very natural action — the prompt is Desktop's own trusted, expected credential dialog triggered mid-`fetch`/`clone`/`push`), any credentials/OAuth token submitted would be sent to the attacker-controlled endpoint, constituting credential/token exfiltration and unauthorized account binding — the corrupted value is the sign-in `endpoint`/`origin` bound in `sign-in-store.ts` via `setSignInEndpoint`, which should only ever be a value the user explicitly typed in, not one derived from an untrusted server response.

### Likelihood Explanation
Likelihood is moderate-to-high for a targeted attack: the attacker only needs to control (or MITM) an HTTPS git remote that the victim adds/fetches, and return a crafted `401 WWW-Authenticate` header — no local access, no prior malware, and no unusual user steps beyond the normal "enter your credentials in the sign-in popup Desktop showed" flow that users already expect during authentication failures.

### Recommendation
Do not trust the `wwwauth[]` realm string alone to classify a host as GitHub/GHE. Require an independent verification step (e.g., probing a well-known GHE API endpoint over HTTPS with certificate validation, or matching against a previously-registered/pinned enterprise endpoint) before routing into `promptForGitHubSignIn`, and never derive `setSignInEndpoint`'s origin from unauthenticated header content supplied by the remote/proxy.

### Proof of Concept
1. Host a git-over-HTTPS server (e.g. `evil.example.com`) that, on any authenticated request (`git-upload-pack`/`git-receive-pack`), responds `401` with header `WWW-Authenticate: Basic realm="GitHub"`.
2. In GitHub Desktop, add `https://evil.example.com/foo.git` as a remote (or clone it) and trigger a fetch/push.
3. Git invokes Desktop's credential helper (`createCredentialHelperTrampolineHandler`) with `wwwauth[0]=Basic realm="GitHub"` in the `get` request.
4. `getEndpointKind` returns `'enterprise'` purely from the header string; since no account matches `evil.example.com`, `getCredential` calls `ui.promptForGitHubSignIn('https://evil.example.com')`.
5. `promptForGitHubSignIn` calls `dispatcher.beginEnterpriseSignIn(cb)` and `dispatcher.setSignInEndpoint('https://evil.example.com')`, showing the native GitHub Enterprise sign-in popup bound to the attacker's origin.
6. If the user completes sign-in, their credentials/token exchange occurs against `evil.example.com`. [4](#0-3) [1](#0-0) [3](#0-2)

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
