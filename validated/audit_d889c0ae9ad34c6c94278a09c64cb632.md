### Title
Schnorr verification accepts signatures for the identity public key - (File: crypto/schnorr/src/lib.rs)

### Summary
`SchnorrSignature::verify` treats the identity point as an ordinary public key and accepts the identity nonce with `s = 0` for any challenge. Because both `Ciphersuite::read_G` and `SchnorrSignature::read` preserve the identity encoding, an attacker can submit a canonical forged signature whenever an identity public key reaches verification. [1](#0-0) [2](#0-1) 

### Finding Description
`Ciphersuite::read_G` checks only point validity and canonical encoding; it does not reject `G::identity()`. [1](#0-0)  `SchnorrSignature::read` uses that permissive decoder for `R`, while `verify` accepts the caller-supplied `public_key` without checking whether either point is the identity. [2](#0-1) [3](#0-2)  The verification equation is `R + cA - sG == 0`; substituting `R = 0`, `A = 0`, and `s = 0` satisfies it unconditionally. [4](#0-3) 

### Impact Explanation
An attacker can produce a universally valid Schnorr signature for the identity public key without knowing a private key. [4](#0-3)  Any protocol path that accepts an attacker-selected public key or allows the identity key to be registered can therefore authenticate an arbitrary challenge or message using a forged signature. [3](#0-2) 

### Likelihood Explanation
This requires the verifier to accept an identity public key, which is possible because canonical point decoding does not reject it. [1](#0-0)  The forged signature is deterministic and requires no nonce reuse, private-key material, privileged access, or repeated attempts. [2](#0-1) [4](#0-3) 

### Recommendation
Reject identity points in `SchnorrSignature::read`, reject identity `public_key` values in `verify`, or do both. [2](#0-1) [3](#0-2)  If identity is valid in some lower-level use case, callers that use signatures for authentication should explicitly enforce `!R.is_identity()` and `!public_key.is_identity()` before verification. [4](#0-3) 

### Proof of Concept
```rust
use ciphersuite::{group::Group, group::ff::Field, Ciphersuite};
use schnorr::SchnorrSignature;

fn forged_signature<C: Ciphersuite>() {
  // Canonical encodings for the identity point and zero scalar decode successfully.
  let identity = C::G::identity();
  let forged = SchnorrSignature::<C> { R: identity, s: C::F::ZERO };
  let encoded = forged.serialize();

  let parsed = SchnorrSignature::<C>::read(&mut encoded.as_slice()).unwrap();
  let arbitrary_challenge = C::F::ONE;

  // R + cA - sG = 0 + c*0 - 0*G = 0.
  assert!(parsed.verify(identity, arbitrary_challenge));
}
```

The parsed `R` can be the canonical identity encoding because `SchnorrSignature::read` delegates to `C::read_G` without an identity check. [5](#0-4) [1](#0-0)  The resulting `(R, s) = (identity, 0)` passes `verify` for `public_key = identity` under every challenge. [6](#0-5)

  pub fn batch_statements(&self, public_key: C::G, challenge: C::F) -> [(C::F, C::G); 3] {
    // s = r + ca
    // sG == R + cA
    // R + cA - sG == 0
    [
      // R
      (C::F::ONE, self.R),
      // cA
      (challenge, public_key),
      // -sG
      (-self.s, C::generator()),
    ]
  }
