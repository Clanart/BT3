### Title
Unvalidated `None` `aggregator_verification_address` Silently Bypasses ECDSA Withdrawal Authorization — (`File: core/src/verifier.rs`, `core/src/rpc/operator.rs`)

### Summary

`aggregator_verification_address` in `BridgeConfig` is `Option<alloy::primitives::Address>`. When it is `None` (unset), both `Verifier::sign_optimistic_payout()` and `OperatorRpc::withdraw()` skip the ECDSA signature check entirely and proceed to authorize the withdrawal. The startup mainnet-safety check (`check_mainnet_requirements()`) does not flag a missing `aggregator_verification_address`, so a deployment without `AGGREGATOR_VERIFICATION_ADDRESS` set silently removes the ECDSA authentication layer with no error or warning.

### Finding Description

`BridgeConfig.aggregator_verification_address` is declared as `Option<alloy::primitives::Address>`: [1](#0-0) 

Both enforcement sites gate the entire ECDSA check on `Some(...)`:

```rust
// Verifier::sign_optimistic_payout
if let Some(address_in_config) = self.config.aggregator_verification_address {
    // verify ECDSA sig ...
}
// if None → falls through, no check performed
``` [2](#0-1) 

The same pattern appears in the operator's `withdraw` RPC handler: [3](#0-2) 

The env-var parser treats the variable as optional with `.ok()`: [4](#0-3) 

The mainnet safety check `check_mainnet_requirements()` enforces `client_verification` but does **not** enforce that `aggregator_verification_address` is set: [5](#0-4) 

The mTLS interceptor is only active when `client_verification = true`; when `false`, `Interceptors::Noop` is used, passing all requests: [6](#0-5) [7](#0-6) 

### Impact Explanation

When `AGGREGATOR_VERIFICATION_ADDRESS` is not set:

- `aggregator_verification_address = None`
- Both `sign_optimistic_payout` and `withdraw` skip ECDSA verification entirely
- The only remaining guard is mTLS (`client_verification`)

If `client_verification = false` (which is flagged by `check_mainnet_requirements()` but only for mainnet Bitcoin network), any unauthenticated caller can invoke `withdraw()` with arbitrary withdrawal parameters and trigger a payout transaction spending bridge-controlled UTXOs. Even with `client_verification = true`, the ECDSA layer — which is the mechanism that binds withdrawal authorization to the aggregator's identity beyond the TLS certificate — is silently absent, meaning a compromised or misconfigured aggregator cert is the only remaining barrier.

The `internal_withdraw` RPC endpoint has no ECDSA check at all by design, relying solely on the self-only mTLS restriction: [8](#0-7) 

### Likelihood Explanation

The `AGGREGATOR_VERIFICATION_ADDRESS` env var is optional and absent from the minimum required configuration. A new operator/verifier deployment that omits it will silently operate without ECDSA withdrawal authorization. The `check_mainnet_requirements()` function does not catch this. The `.env.example` includes the variable, but it is not enforced at startup. [9](#0-8) 

### Recommendation

1. Add `aggregator_verification_address` to `check_mainnet_requirements()` — if it is `None` on mainnet, push a misconfiguration error.
2. In `sign_optimistic_payout` and `withdraw`, if `aggregator_verification_address` is `None`, either reject the request with an explicit error or log a prominent warning rather than silently skipping the check.
3. Consider making `aggregator_verification_address` a required field (non-`Option`) for production actor types, with a separate opt-out flag if the feature is intentionally disabled.

### Proof of Concept

1. Deploy an operator/verifier with `AGGREGATOR_VERIFICATION_ADDRESS` unset (omit the env var).
2. `BridgeConfig::aggregator_verification_address` is `None`.
3. `check_mainnet_requirements()` passes without error.
4. Call `withdraw(WithdrawParamsWithSig { withdrawal: Some(params), verification_signature: None })` — the `if let Some(address_in_config)` branch is not entered, no ECDSA check runs.
5. The operator proceeds to `self.operator.withdraw(...)`, constructing and broadcasting a payout transaction for the supplied withdrawal parameters without any aggregator ECDSA authorization. [2](#0-1) [10](#0-9)

    pub fn check_mainnet_requirements(&self, actor_type: cli::Actor) -> Result<(), BridgeError> {
        if self.protocol_paramset().network != Network::Bitcoin {
            return Ok(());
        }

        let mut misconfigs = Vec::new();

        if matches!(actor_type, cli::Actor::Verifier | cli::Actor::Operator)
            && !self.client_verification
        {
            misconfigs.push("CLIENT_VERIFICATION=false".to_string());
        }

        /// Checks if an env var is set to a non 0 value.
        fn check_env_var(env_var: &str, misconfigs: &mut Vec<String>) {
            if let Ok(var) = std::env::var(env_var) {
                if var == "0" || var.eq_ignore_ascii_case("false") {
                    return;
                }

                misconfigs.push(format!("{env_var}={var}"));
            }
        }

        check_env_var("DISABLE_NOFN_CHECK", &mut misconfigs);

        if is_dev_mode() {
            misconfigs.push("Risc0 dev mode is enabled (RISC0_DEV_MODE=1)".to_string());
        }

        if is_test_vk() {
            misconfigs.push("use-test-vk feature is enabled".to_string());
        }

        if !misconfigs.is_empty() {
            return Err(BridgeError::ConfigError(format!(
                "Following configs can't be used on Mainnet: {misconfigs:?}",
            )));
        }

        Ok(())
    }
