### Title
Unauthenticated tx-sender JSON-RPC server drains operator fee-paying wallet via CPFP when bound to `0.0.0.0` — (`File: crates/clementine-tx-sender/src/jsonrpc/server.rs`)

---

### Summary

The standalone tx-sender's JSON-RPC server (`start_jsonrpc_server`) starts with `ServerBuilder::default()` — no TLS, no token, no IP allowlist. The configuration explicitly permits binding to `0.0.0.0`. Any network-reachable host can call `send_tx` to enqueue arbitrary transactions with `FeePayingType::CPFP`, causing the tx-sender to repeatedly call `fund_raw_transaction` on the operator's Bitcoin Core wallet to create fee-payer UTXOs, draining the operator's on-chain funds.

---

### Finding Description

`start_jsonrpc_server` builds the HTTP server with no authentication layer: [1](#0-0) 

The `send_tx` handler accepts a caller-supplied `InsertTryToSendParams` — including `fee_paying_type` — and enqueues it unconditionally: [2](#0-1) 

The configuration struct documents `0.0.0.0` as a valid bind address: [3](#0-2) 

And the env-var parser explicitly accepts it: [4](#0-3) 

When the tx-sender loop processes a queued CPFP entry and finds no confirmed fee-payer UTXOs, it calls `create_fee_payer_utxo`, which issues a real `fund_raw_transaction` against the operator's Bitcoin Core wallet: [5](#0-4) 

Each attacker-submitted CPFP entry triggers a new wallet spend. The attacker's transaction does not need to be valid on-chain — it only needs to be accepted into the DB queue.

---

### Impact Explanation

The operator's Bitcoin Core wallet is the sole source of fee-paying UTXOs for all bridge operations: kickoff, payout, watchtower challenge, reimbursement, and move-tx CPFP. Draining it causes the tx-sender to fail to fund any of these transactions. Missed challenge or reimbursement deadlines result in slashable collateral exposure or permanent loss of bridged BTC. This is a direct, material fund impact on bridge-controlled UTXOs and operator collateral. [6](#0-5) 

---

### Likelihood Explanation

The `0.0.0.0` bind is an explicitly supported, documented configuration option (not a misconfiguration). Any host with network access to the tx-sender port — including other containers in the same Docker network, or any external host if the port is exposed — can exploit this with a single unauthenticated HTTP POST. No credentials, certificates, or prior knowledge of bridge state are required. [7](#0-6) 

---

### Recommendation

1. **Add authentication**: Require a shared secret token (e.g., `Authorization: Bearer <token>`) on every JSON-RPC request, validated in a `tower` middleware layer before the handler is reached.
2. **Default to localhost-only**: The current default of `127.0.0.1` is correct; add a startup warning or hard error if `0.0.0.0` is configured without an explicit acknowledgment flag.
3. **Add TLS**: Use `ServerBuilder` with TLS so that even if the port is reachable, connections cannot be intercepted or spoofed.

---

### Proof of Concept

With `TX_SENDER_JSONRPC_BIND=0.0.0.0` and `TX_SENDER_JSONRPC_PORT=3030`:

```bash
# Attacker submits a syntactically valid but economically worthless CPFP transaction
# (any hex-encoded Bitcoin transaction with a P2A anchor output)
curl -s -X POST http://<operator-ip>:3030 \
  -H 'Content-Type: application/json' \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "send_tx",
    "params": [{
      "tx_metadata": null,
      "signed_tx_hex": "<hex of attacker tx with P2A anchor>",
      "fee_paying_type": "cpfp",
      "rbf_signing_info": null,
      "cancel_outpoints": [],
      "cancel_txids": [],
      "activate_txids": [],
      "activate_outpoints": []
    }]
  }'
```

The tx-sender loop picks up the entry, finds no fee-payer UTXOs, calls `fund_raw_transaction` on the operator's Bitcoin Core wallet, and broadcasts a real on-chain transaction spending operator funds. Repeating this in a loop exhausts the wallet. [8](#0-7) [9](#0-8)

pub async fn start_jsonrpc_server(
    tx_sender_client: TxSenderClient,
    bind_addr: SocketAddr,
) -> Result<TxSenderJsonRpcServer, BridgeError> {
    let server: Server = ServerBuilder::default()
        .max_request_body_size(MAX_JSONRPC_REQUEST_BODY_SIZE)
        .build(bind_addr)
        .await
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    let local_addr = server
        .local_addr()
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    let mut module = RpcModule::new(tx_sender_client.clone());
    module
        .register_async_method("send_tx", |params, client, _| async move {
            let req: InsertTryToSendParams = params.one().map_err(jsonrpc_err)?;

            let raw_tx = hex::decode(&req.signed_tx_hex).map_err(jsonrpc_err)?;
            let signed_tx: Transaction = consensus::deserialize(&raw_tx).map_err(jsonrpc_err)?;

            let mut dbtx = client.db.begin_transaction().await.map_err(jsonrpc_err)?;

            let try_to_send_id = client
                .insert_try_to_send(
                    &mut dbtx,
                    req.tx_metadata,
                    &signed_tx,
                    req.fee_paying_type,
                    req.rbf_signing_info,
                    &req.cancel_outpoints,
                    &req.cancel_txids,
                    &req.activate_txids,
                    &req.activate_outpoints,
                )
                .await
                .map_err(jsonrpc_err)?;

            client
                .db
                .commit_transaction(dbtx)
                .await
                .map_err(jsonrpc_err)?;

            Ok::<u32, ErrorObjectOwned>(try_to_send_id)
        })
        .map_err(|e| BridgeError::Eyre(e.into()))?;

    // Citrea-specific RPCs.
    #[cfg(feature = "citrea")]
    {
        module
            .register_async_method("send_citrea_tx", |params, client, _| async move {
                let req: InsertCitreaRawTxParams = params.one().map_err(jsonrpc_err)?;

                let insertion_id = client
                    .send_citrea_tx(req.citrea_tx_request)
                    .await
                    .map_err(jsonrpc_err)?;

                Ok::<i64, ErrorObjectOwned>(insertion_id)
            })
            .map_err(|e| BridgeError::Eyre(e.into()))?;
    }

    let handle = server.start(module);

    Ok(TxSenderJsonRpcServer { handle, local_addr })
}
