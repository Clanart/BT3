## Title
Attacker-controlled `WWW-Authenticate` realm on any git remote forces Desktop to auto-launch a "GitHub Enterprise" sign-in flow against an untrusted host - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

## Summary
The `LeverageActions.sol` bug is really about a privileged action (unlimited `approve`) being granted to an address whose trustworthiness was never verified — the contract never checks that `creditManager` is actually part of the trusted system before extending trust to it. The closest reachable analog in GitHub Desktop is `getEndpointKind()` in `app/src/lib/trampoline/trampoline-credential-helper.ts`, which classifies an arbitrary git remote as a trusted **GitHub** host based solely on an attacker-controlled `WWW-Authenticate` header value forwarded by Git, without any cryptographic or allow-list verification that the host is actually GitHub or GitHub Enterprise.

## Finding Description
When Git performs HTTP(S) authentication against a remote, it captures any `WWW-Authenticate` response headers and forwards them to the configured credential helper as `wwwauth[N]=...` fields. Desktop's credential helper reads these fields to decide whether a remote "looks like" a GitHub host: [1](#0-0) 

If the response contains `realm="GitHub"`, the endpoint is unconditionally classified `'enterprise'` — i.e., treated as a trusted GitHub Enterprise instance — with no verification that the host actually is GitHub-branded infrastructure (no TLS/cert pinning, no allow-list, no call to the existing `isGitHubHost()` discovery check that is used later as the real fallback): [2](#0-1) 

This classification directly controls `getCredential()`'s branch selection. If the resulting `endpoint` doesn't correspond to any already-signed-in account, Desktop calls `ui.promptForGitHubSignIn(endpoint)`: [3](#0-2) 

`promptForGitHubSignIn` takes the attacker-supplied `endpoint` string verbatim and uses it to drive the Enterprise sign-in flow, calling `setSignInEndpoint(origin)` with the attacker's own host and showing a "Sign in" popup branded as a GitHub credential request: [4](#0-3) 

`setEndpoint()` in `sign-in-store.ts` then does perform basic URL validation and connectivity checks, but it does not verify GitHub identity/branding beyond parsing the URL — it trusts the caller-provided endpoint as a legitimate Enterprise host to authenticate against: [5](#0-4) 

So the broken invariant is: **"host classified/trusted as GitHub" is derived from an unauthenticated, attacker-controlled protocol field (`WWW-Authenticate: realm="GitHub"`), not from an actual verification of GitHub identity.** This mirrors the `LeverageActions.sol` flaw of extending privileged trust to an address without checking it is a genuine system component.

## Impact Explanation
An attacker who controls (or MITMs) a git HTTP remote can make their server respond to Git's credential probe with `WWW-Authenticate: Basic realm="GitHub"`. Any Desktop user who clones/fetches/pushes to that remote will have Desktop misclassify the attacker's host as an "enterprise" GitHub endpoint and pop a native "Sign in to GitHub Enterprise" dialog scoped to the attacker's own domain. This is a credible phishing surface: the sign-in UI (native Desktop chrome, GitHub-branded copy) increases user trust in providing GitHub/GHE credentials for a domain the user did not knowingly choose to authenticate against, since the endpoint was silently derived from the git remote rather than user input. It falls under "unauthorized OAuth or account binding" style risk from an "attacker-controlled ... git remote/proxy response."

## Likelihood Explanation
Likelihood is moderate: it only requires the attacker to control the git server's HTTP auth challenge (trivially done for any self-hosted remote, or a MITM proxy on an unauthenticated `http://` remote), and it fires automatically the first time Git needs to authenticate against that remote without Desktop having a stored credential for it — no unusual user interaction beyond a normal clone/fetch is required. However, the real damage requires the user to then complete a GHE sign-in against the attacker's host, which is a social-engineering-adjacent final step and mitigates full automatic exploitation.

## Recommendation
Do not use the caller/attacker-supplied `WWW-Authenticate` realm value as sufficient evidence to classify a host as GitHub/Enterprise. Either drop this heuristic entirely and always fall back to the existing `isGitHubHost()` network-based check (which validates via TLS + `x-github-request-id` and known-endpoint version headers) or, at minimum, require both the `wwwauth` hint and a passing `isGitHubHost()`/certificate check before elevating an endpoint to `'enterprise'` and before invoking `promptForGitHubSignIn`.

## Proof of Concept
1. Stand up an HTTP git remote (e.g. via a small proxy/CGI in front of `git http-backend`) that, on the initial unauthenticated request, responds `401` with header `WWW-Authenticate: Basic realm="GitHub"`.
2. Have a victim `git clone`/`fetch` this remote in GitHub Desktop (no account previously configured for this host).
3. Git forwards the header to Desktop's credential helper as `wwwauth[0]=Basic realm="GitHub"`; `getEndpointKind()` returns `'enterprise'` per [6](#0-5) .
4. Since no account matches, `getCredential()` calls `ui.promptForGitHubSignIn(endpoint)` with `endpoint` equal to the attacker's remote URL, triggering `beginEnterpriseSignIn` + `setSignInEndpoint(origin)` against the attacker's domain [7](#0-6) , presenting the user a "Sign in to GitHub Enterprise" dialog for the attacker's host.

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}
