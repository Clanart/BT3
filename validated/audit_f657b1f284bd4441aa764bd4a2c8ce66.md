### Title
Out-of-Bounds Slice Access in Auction Bid Signature Recovery via Unvalidated Signature Length - (File: kaiax/auction/bid.go)

### Summary
`getSigner` in `kaiax/auction/bid.go` performs unchecked, fixed-offset slicing (`copiedSig[crypto.RecoveryIDOffset]`, `copiedSig[0:32]`, `copiedSig[32:64]`) on `SearcherSig`/`AuctioneerSig` byte slices that originate directly from an unprivileged, network-submitted `auction.Bid`. This mirrors the CryptoLib bug class: parsing/consuming attacker-controlled variable-length data with hard-coded offset arithmetic and no length/bounds validation before indexing.

### Finding Description
`auction.BidData.SearcherSig` and `AuctioneerSig` are plain `[]byte` fields decoded via RLP directly from a `Bid` message submitted by an external bidder (see `kaiax/auction/bid.go` `DecodeRLP`, and the p2p `handleBidMsg` path in `node/cn/handler_msg_test.go` referencing `BidMsg`). When the bid pool validates a bid, `validateBidSigs` calls `Bid.ValidateSearcherSig` / `Bid.ValidateAuctioneerSig`, both of which call the shared helper `getSigner(sig, digest)`: [1](#0-0) 

`getSigner` clones the caller-supplied `sig` slice and immediately indexes it at `crypto.RecoveryIDOffset` (64) and slices `[0:32]` and `[32:64]` without first checking `len(sig) >= 65`. A `SearcherSig`/`AuctioneerSig` shorter than 65 bytes (e.g. empty, 1 byte, or any length < 65) causes a Go slice-bounds-out-of-range runtime panic when indexing/slicing past the actual backing array length — the direct analog of the CryptoLib flaw where `ptr + strlen(ptr) + 1` read past the allocated buffer because the parser assumed a fixed structure without checking the actual buffer size.

Reviewing `validateBid` in `kaiax/auction/impl/bid_pool.go`, the pre-checks performed before `validateBidSigs` is invoked are: bid-already-exists, sender-winner conflict, block-number range, bid > 0, data size limit, and gas limit — **none of these validate the length of `SearcherSig` or `AuctioneerSig`**: [2](#0-1) 

Thus a malformed, short signature reaches `getSigner` unchecked.

### Impact Explanation
This is reachable by any unprivileged auction bidder/searcher submitting a bid directly to the bid pool (via RPC/API or p2p `BidMsg`) with a truncated `searcherSig` or `auctioneerSig` field. Because Go slice out-of-bounds accesses panic rather than silently reading adjacent heap memory (unlike C), the practical effect is a runtime panic in the node process handling bid validation — a crash/DoS of the bid-processing goroutine/node when processing a single attacker-crafted bid, rather than the leaked-heap-memory outcome of the original CVE. This still constitutes an availability impact on the auction module reachable from a single external bid, consistent with rejecting/crashing on malformed input that should have been gracefully rejected.

### Likelihood Explanation
High likelihood of triggering: the bid fields are plain byte slices with no length assertion anywhere before `getSigner` is called, and an attacker fully controls the RLP-encoded bid content (any length signatures). No privileged access, special timing, or state is required — a single malformed bid submission is sufficient.

### Recommendation
Add an explicit length check (`len(sig) != 65`) at the start of `getSigner` in `kaiax/auction/bid.go`, returning `ErrInvalidSignature` (or a new descriptive error) before any indexing/slicing occurs. Additionally, validate `len(SearcherSig) == 65` and `len(AuctioneerSig) == 65` earlier in `validateBid` (`kaiax/auction/impl/bid_pool.go`) alongside the other structural checks (data size, gas limit) so malformed bids are rejected deterministically rather than causing a panic deep in signature-recovery code.

### Proof of Concept
1. Craft an `auction.Bid` (or `BidData`) with a valid-looking `TargetTxHash`, `BlockNumber`, `Sender`, etc., but set `SearcherSig = []byte{}` (or any slice shorter than 65 bytes) and/or `AuctioneerSig` similarly truncated.
2. RLP-encode the bid and submit it via the p2p `BidMsg` handler (`handleBidMsg`) or the bid-pool ingestion API, reaching `BidPool.validateBid` → `validateBidSigs` → `Bid.ValidateSearcherSig`/`ValidateAuctioneerSig` → `getSigner`.
3. In `getSigner`, `copiedSig[crypto.RecoveryIDOffset]` (index 64) and `copiedSig[32:64]` panic with "slice bounds out of range" because `len(copiedSig) < 65`, since no prior code path validates signature length.

func getSigner(sig, digest []byte) (common.Address, error) {
	// Manually convert V from 27/28 to 0/1
	copiedSig := slices.Clone(sig)
	if copiedSig[crypto.RecoveryIDOffset] == 27 || copiedSig[crypto.RecoveryIDOffset] == 28 {
		copiedSig[crypto.RecoveryIDOffset] -= 27
	}

	v := copiedSig[crypto.RecoveryIDOffset]
	r := new(big.Int).SetBytes(copiedSig[0:32])
	s := new(big.Int).SetBytes(copiedSig[32:64])
	if !crypto.ValidateSignatureValues(v, r, s, true) {
		return common.Address{}, ErrInvalidSignature
	}

	pub, err := crypto.SigToPub(digest, copiedSig)
	if err != nil {
		return common.Address{}, err
	}
	return crypto.PubkeyToAddress(*pub), nil
}

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}
