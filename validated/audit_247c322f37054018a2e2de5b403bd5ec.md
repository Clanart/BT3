### Title
Forwarded InInstructions replayed and dropped due to balance-keyed queue writing back the unconsumed buffer - (File: processor/src/multisigs/db.rs)

### Summary
During multisig rotation, outputs received by the retiring multisig are forwarded to the new multisig's `Forwarded` offset address. The `InInstruction` belonging to each forwarded output is persisted in `ForwardedOutputDb`, keyed solely by `ExternalBalance` (coin + amount), and later replayed when a `Forwarded`-kind output is scanned. Two defects combine here:

1. `take_forwarded_output` decodes the first queued instruction but writes back the **entire original buffer** (`&outputs`) instead of the remainder (`outputs_ref`), so the consumed instruction is never removed. Only when the buffer decodes to empty is the key deleted.
2. Because the key is just the balance, any output of equal value sent to the forward address — including one sent by an unrelated third party directly to that deterministic address — pops the queue in FIFO order.

The result: a pending instruction can be emitted multiple times and other users' queued instructions under the same balance key are never emitted at all. This mirrors the report's bug class — assets present at an address are attributed/executed by amount alone, not by the transaction that actually carried them.

### Finding Description
`ForwardedOutputDb::save_forwarded_output` appends SCALE-encoded `InInstructionWithBalance` records under the key `instruction.balance`. `take_forwarded_output` is called from `scanner_event_to_multisig_event` for every scanned output of `OutputType::Forwarded`:

```rust
// processor/src/multisigs/db.rs
let outputs = Self::get(txn, balance)?;
let mut outputs_ref = outputs.as_slice();
let res = InInstructionWithBalance::decode(&mut outputs_ref).unwrap();
assert!(outputs_ref.len() < outputs.len());
if outputs_ref.is_empty() {
  txn.del(Self::key(balance));
} else {
  Self::set(txn, balance, &outputs); // BUG: writes back `outputs`, not `outputs_ref`
}
``` [1](#0-0) 

When two or more instructions are queued under one balance, the first `take` returns instruction[0] yet re-stores `[instruction[0], instruction[1], ...]` unchanged. The next `Forwarded` output of that value returns instruction[0] *again* — instruction[1] can never be reached because every pop decodes from the head of the same unmodified buffer.

The `Forwarded` address is publicly derivable (`forward_address` = `key + FORWARD_OFFSET*G`, where `FORWARD_OFFSET = hash_to_F(KEY_DST, b"forward")`), and the scanner classifies outputs purely by `script_pubkey` (`scan_transaction`/`get_outputs` match on script only). Any Bitcoin user can therefore create a `Forwarded`-kind output of a chosen amount to the new multisig and pop the queue.

### Impact Explanation
- **Theft / mis-crediting of deposits**: an attacker who deposits to the retiring multisig during `RotationStep::ForwardFromExisting` such that their instruction is saved *first* under balance `B` will have their instruction emitted once per `Forwarded` output of value `B`. A victim's instruction queued under the same balance is shadowed forever; the victim's forwarded coins arrive but their `InInstruction` (mint/refund/swap) is never emitted — funds are received by the multisig but never credited, while the attacker's instruction is credited multiple times.
- **Queue exhaustion DoS**: `decode(&mut outputs_ref).unwrap()` and the `assert!`/`panic!` paths crash the processor if the stored data is corrupted, but more importantly the shadowed-instruction state persists indefinitely.
- Like the FEI bug, value that merely sits at an address (matching amount) is treated as proof a specific protocol event occurred.

### Likelihood Explanation
- The trigger requires two pending forwarded instructions sharing a post-fee balance `B`. Since the forwarded amount equals `deposit − tx.fee()` and the fee is set by the protocol's own fixed fee rate on a small fixed-vsize forwarding transaction, an attacker can deliberately size their deposit so their instruction lands under the same key as a concurrently-forwarded victim deposit, ordering theirs first (same-block ordering is attacker-influenceable).
- Even absent an attacker, any two equal-amount forwards — common for round deposit amounts — deterministically corrupt the queue on normal operation.
- Requires a multisig rotation (occurs each key-rotation period) and a network requiring forwarding (`shim_forward_plan` returning `Some`).

### Recommendation
- Write back the remainder, not the original buffer: `Self::set(txn, balance, outputs_ref)` (i.e., store the bytes after the consumed prefix).
- Key forwarded instructions by something the output itself commits to — e.g., the expected `OutPoint` of the forwarding transaction, or the forwarding `Eventuality` ID — rather than by amount alone, so an outsider cannot pop the queue with an unrelated payment and equal-amount forwards cannot collide.
- Return an explicit error instead of `unwrap()`/`assert!` on malformed stored data.

### Proof of Concept
1. Rotation begins (`RotationStep::ForwardFromExisting`); the new multisig's forward address `A_f = p2tr(key_new + FORWARD_OFFSET·G)` is publicly computable.
2. Victim deposits `D_v` to the old multisig; processor plans a forward, saving `I_v` under key `B = D_v − fee`. Attacker deposits `D_a` chosen so `D_a − fee = B`, ensuring `I_a` is appended *before* `I_v` in the same balance slot (earlier position in the scan order/block).
3. Forwarding transactions confirm. First `Forwarded` output of value `B` scans → `take_forwarded_output(B)` returns `I_a` and re-stores `[I_a, I_v]` due to the write-back bug.
4. Second `Forwarded` output of value `B` (the victim's real forward) scans → returns `I_a` again. `I_a` executes twice; `I_v` never executes; the victim's coins sit in the new multisig uncredited. Alternatively, the attacker pre-pops with their own `B`-valued output to `A_f`, shifting all attributions by one.

    balance: ExternalBalance,

    let mut outputs_ref = outputs.as_slice();

    assert!(outputs_ref.len() < outputs.len());

    }
    Some(res)
  }

      // If the vout index exceeds 2**32, stop scanning outputs
