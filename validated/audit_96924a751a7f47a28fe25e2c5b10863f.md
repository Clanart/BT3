### Title
Governance can set `kip71.gastarget` to zero, causing a division-by-zero panic in base fee calculation that halts the chain - ([File: params/kip71_config.go])

### Summary
The `kip71.gastarget` governance parameter has no format validation preventing a zero value, and `checkConsistency` in header governance performs no additional bounds-checking for it. A governing node can therefore ratify `GasTarget = 0`, which is then used as a divisor in `KIP71Config.NextMagmaBlockBaseFee`, causing a `division by zero` panic on every node that verifies or produces the following block.

### Finding Description
The governance parameter table defines `Kip71GasTarget` with `FormatChecker: noopFormatChecker`, i.e. any `uint64` value including `0` is accepted: [1](#0-0) 

Unlike `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee`, which get an explicit cross-check in `checkConsistency` (lower must not exceed upper), `Kip71GasTarget` falls into the default branch that performs no additional checks beyond format validation: [2](#0-1) 

Once `GasTarget = 0` is ratified into the effective parameter set (via `governance_vote` in `single` governance mode, which only requires the designated governing node), it flows into `KIP71Config.GasTarget` and is used to compute the next block's base fee: [3](#0-2) 

When `parentGasUsed > gasTarget` (true for essentially any block using gas once `gasTarget` is `0`), the code divides by `gasTarget`: [4](#0-3) 

`big.Int.Div` panics with `"division by zero"` when the divisor is zero. This function, `NextMagmaBlockBaseFee`, is invoked from consensus-critical paths (header verification, block assembly), so once the parameter takes effect, every node processing a block with nonzero gas usage will panic.

### Impact Explanation
This is a direct analog of the reported "compromised/malicious admin sets an unbounded capacity-like parameter to break protocol logic" bug class, except the blast radius is far larger: instead of a single Vault DOS, this causes every full node (validators and RPC nodes alike) to crash while verifying or producing the next block, i.e., a full network liveness halt / consensus-critical DOS. This satisfies the "state divergence between honest nodes" / "acceptance-of-invalid-block-halting" bar for a valid analog since a bad governance value can never be recovered from without a hard fork/patch, unlike the bounded issues explicitly protected for `LowerBoundBaseFee`/`UpperBoundBaseFee`.

### Likelihood Explanation
Reaching this requires only a single `governance_vote` RPC call/transaction by the governing node (the same kind of "admin" role referenced by the original report), followed by ratification at the epoch boundary — no unusual conditions or race required. Given that `LowerBoundBaseFee`/`UpperBoundBaseFee` already received defensive consistency checks in this codebase, the omission of a `> 0` check for `GasTarget` appears to be an oversight rather than an intentional design decision.

### Recommendation
Add a `FormatChecker` for `Kip71GasTarget` (and ideally `Kip71MaxBlockGasUsedForBaseFee`) that rejects `0`, mirroring the `v != 0` check already used for `Kip71BaseFeeDenominator`: [5](#0-4) 
Additionally, `NextMagmaBlockBaseFee` should defensively guard against `gasTarget == 0` (similar to the existing `baseFeeDenominator == 0` fallback) so that a bad on-chain configuration cannot crash node software.

### Proof of Concept
1. Governing node (single-mode governance) calls `governance_vote("kip71.gastarget", 0)`.
2. Since `Kip71GasTarget`'s `FormatChecker` is `noopFormatChecker` and `checkConsistency` has no special case for it, `VerifyVote`/ratification succeeds and `GasTarget = 0` becomes effective from the next epoch.
3. Once effective, any subsequent block with `header.GasUsed > 0` triggers `NextMagmaBlockBaseFee(parentNumber, parentBaseFee, parentGasUsed)` with `kc.GasTarget == 0`.
4. Because `parentGasUsed (>0) > gasTarget (0)`, execution enters the branch computing `y := x.Div(x, new(big.Int).SetUint64(gasTarget))` with divisor `0`, panicking every node that verifies/produces that header (`params/kip71_config.go` lines 92-109), halting the chain.
