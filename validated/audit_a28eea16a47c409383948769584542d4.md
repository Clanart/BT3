## Analysis

The `Vault._to_usd_oracle_price()` bug pattern — a single global freshness threshold applied uniformly to price feeds with materially different actual heartbeats — reappears in `SimplexPaymaster.sol`'s `_getOraclePrice()`.

### Title
Single global `maxOracleAge` applied to all token/native price feeds allows stale-price gas underpayment — (File: `evm/src/utils/SimplexPaymaster.sol`)

### Summary
`SimplexPaymaster` prices ERC-4337 gas in ERC-20 stablecoins using two Chainlink feeds (native/USD and token/USD), validated only by a single global `maxOracleAge` parameter checked identically for every oracle, regardless of each feed's actual on-chain heartbeat.

### Finding Description
`_getOraclePrice()` reverts only if `block.timestamp - updatedAt > maxOracleAge`: [1](#0-0) 

`maxOracleAge` is a single governance-set value shared by `nativeOracle` and *every* registered `TokenConfig.tokenOracle`, set via `_setParams()` and only bounded by `MAX_ORACLE_AGE = 7 days`: [2](#0-1) [3](#0-2) 

`_registerToken()` accepts any Chainlink `AggregatorV3Interface` for a new token without recording or checking that oracle's actual heartbeat against `maxOracleAge`: [4](#0-3) 

The contract's own comment acknowledges heartbeats vary drastically per chain/token ("BSC stablecoins ~27s, Base/Ethereum stablecoins up to 24h"), yet only one `maxOracleAge` value is stored and applied uniformly to *all* registered tokens plus the native oracle: [5](#0-4) [6](#0-5) 

`_fetchDetails()` (the ERC-4337 pricing hook invoked from any unprivileged UserOperation) calls `_tokenPrice()` → `_getOraclePrice()` for both feeds using this one shared threshold to compute the exact token amount charged for gas: [7](#0-6) [8](#0-7) 

If governance registers a token whose Chainlink feed has a short real heartbeat (e.g., a fast-updating, more volatile asset) while `maxOracleAge` remains tuned loosely for a slow-heartbeat stablecoin feed (up to the 7-day ceiling), that token's feed can go stale well past its intended heartbeat — and past a real, significant price move — without ever tripping `StaleOraclePrice`. The same class of "one-size-fits-all" freshness check flagged in the Unstoppable-DeFi Sherlock finding (`ORACLE_FRESHNESS_THRESHOLD` reused across LINK/USD, CRV/USD, etc. with 3600s heartbeats but a 24h check) is reproduced here verbatim: no per-oracle heartbeat is ever consulted.

### Impact Explanation
Any unprivileged UserOperation sender paying with a registered token whose real feed price has moved (crashed/spiked) after its true heartbeat but within the shared `maxOracleAge` window can have `_tokenPrice()` compute gas cost from the stale, no-longer-accurate rate. This directly mispriced the ERC-20 amount `PaymasterERC20._erc20Cost` collects from the sender, draining value from the paymaster's treasury/surplus relative to actual gas cost — a direct loss of funds for the protocol, reachable by any ordinary UserOp sender with no privileged or colluding actor required.

### Likelihood Explanation
Likelihood depends on governance choosing `maxOracleAge` loosely enough (up to 7 days) to accommodate one feed's heartbeat while registering another token whose feed's real heartbeat/deviation trigger is far tighter — a realistic operational scenario given the contract explicitly registers heterogeneous tokens/feeds under one shared parameter. No attacker action is needed to create the staleness window; the attacker merely needs to observe a stale-but-accepted price and time a UserOperation, which is a normal, permissionless interaction with the paymaster.

### Recommendation
Store a per-token (and per-native) maximum oracle age alongside each `TokenConfig`/native oracle entry, validated at registration/update time against that feed's documented heartbeat, and check staleness in `_getOraclePrice()` against the oracle-specific threshold rather than a single global `maxOracleAge`.

### Proof of Concept
1. Governance calls `UpdateParams` with `maxOracleAge` set to e.g. 24 hours (within `MAX_ORACLE_AGE`), sized for a slow-heartbeat stablecoin native oracle.
2. Governance calls `RegisterToken` to add `tokenX` whose Chainlink feed has a genuine ~1-hour heartbeat/deviation trigger.
3. `tokenX`'s feed's underlying market price drops sharply, but the feed stops updating for several hours (oracle outage, low liquidity, or simply between heartbeats) — still within the 24h `maxOracleAge` window, so `_getOraclePrice()` in `SimplexPaymaster.sol` lines 428-442 does not revert.
4. An attacker submits a UserOperation paying gas with `tokenX`; `_fetchDetails()` → `_tokenPrice()` prices gas using the stale, now-overvalued `tokenX/USD` reading, letting the attacker pay far less `tokenX` than the token's real market value for the sponsored gas, draining the treasury's economic value over repeated UserOps.

```text
        tokenConfigs[token] = TokenConfig({

            tokenOracleDecimals: oracle.decimals(),
            tokenDecimals: IERC20Metadata(token).decimals(),
            active: true
        });

        if (isNew) {
            registeredTokens.push(token);
        }

        emit TokenRegistered(token, address(oracle));
    }
```

```text
    function _fetchDetails(
        PackedUserOperation calldata userOp,
        bytes32 /* userOpHash */
    ) internal view override returns (uint256 validationData, IERC20 token, uint256 tokenPrice) {
        bytes calldata data = userOp.paymasterData();
        if (data.length < 21) revert InvalidPaymasterData(data.length);

        uint8 mode = uint8(data[0]);
        if (mode > 0x01) revert InvalidMode(mode);

        address tokenAddr = address(bytes20(data[1:21]));

        TokenConfig memory cfg = tokenConfigs[tokenAddr];
        if (address(cfg.tokenOracle) == address(0)) revert TokenNotRegistered(tokenAddr);
        if (!cfg.active) revert TokenNotActive(tokenAddr);

        tokenPrice = _tokenPrice(cfg);
        token = IERC20(tokenAddr);
        validationData = 0; // no time-range restriction
    }
```

```text
        uint256 nativeUsd = _getOraclePrice(nativeOracle, nativeOracleDecimals);
        uint256 tokenUsd = _getOraclePrice(cfg.tokenOracle, cfg.tokenOracleDecimals);

        return (nativeUsd * (10 ** cfg.tokenDecimals) * (10_000 + markupBps)) / (tokenUsd * 10_000);
    }
```

```text
    function _getOraclePrice(AggregatorV3Interface oracle, uint8 oracleDecimals) internal view returns (uint256) {
        (, int256 answer, , uint256 updatedAt, ) = oracle.latestRoundData();

        if (answer <= 0) revert InvalidOraclePrice(address(oracle), answer);
        if (block.timestamp - updatedAt > maxOracleAge) {
            revert StaleOraclePrice(address(oracle), updatedAt);
        }

        if (oracleDecimals < 8) {
            return uint256(answer) * (10 ** (8 - oracleDecimals));
        } else if (oracleDecimals > 8) {
            return uint256(answer) / (10 ** (oracleDecimals - 8));
        }
        return uint256(answer);
    }
```
