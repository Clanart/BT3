### Title
Missing on-chain spend-linkage check for `ReplacementDeposit` allows fabricating a "replacement" deposit for any `old_move_txid` - (`core/src/verifier.rs`)

### Summary
`Verifier::is_deposit_valid` validates a `ReplacementDeposit` purely by re-deriving the expected script pubkey from `(nofn_xonly_pk, old_move_txid, security_council)` and comparing it to the on-chain UTXO at `deposit_outpoint`; it never checks that this UTXO was actually produced by spending `old_move_txid`'s `UtxoVout::DepositInMove` output through the security-council/nofn script. Any unprivileged actor can therefore fund `generate_replacement_deposit_address(old_move_txid, real_nofn_xonly_pk, network, real_security_council)` directly with their own BTC, using any `old_move_txid` value (including a victim's real move-to-vault txid), and `new_deposit`/`deposit_finalize` will accept it as a legitimate replacement.

### Finding Description
The binding that should hold is:
`deposit_outpoint's funding transaction.input[].previous_output == (old_move_txid, UtxoVout::DepositInMove)` AND that spend is authorized by `CheckSig(old_nofn_xonly_pk) OR Multisig(security_council)` (as built by `create_replacement_deposit_txhandler`, [1](#0-0) ).

`Verifier::is_deposit_valid` never checks this. It only recomputes the expected script pubkey for a `ReplacementDeposit` from `get_deposit_scripts` (which embeds `nofn_xonly_pk` and the caller-supplied `old_move_txid` into `ReplacementDepositScript`, plus the `Multisig` script) and compares it against whatever is actually confirmed on chain at `deposit_outpoint`: [2](#0-1) 

Because a Taproot address (`generate_replacement_deposit_address`) can be funded by *any* transaction, not only the security-council-authorized replacement transaction, an attacker can:
1. Call `get_nofn_aggregated_xonly_pk`/use the public `nofn_xonly_pk` and `security_council` (both public protocol values).
2. Pick any `old_move_txid` (e.g. a real victim's existing move-to-vault txid, or a completely made-up one) and derive the address via `generate_replacement_deposit_address` [3](#0-2) .
3. Send `bridge_amount` BTC to that address in an ordinary transaction that never touches `old_move_txid`'s UTXO.
4. Call `new_deposit` with `DepositData::ReplacementDeposit(ReplacementDeposit{old_move_txid})` [4](#0-3) .
5. Verifiers run `is_deposit_valid`/`deposit_finalize`, which only checks amount + script pubkey + confirmation height, and never checks the *origin* of the deposit UTXO's funding transaction [5](#0-4) .
6. The aggregator proceeds to collect N-of-N partial signatures and finalize a `move_to_vault_tx` for this fabricated deposit, exactly as it would for a genuine replacement.

`get_replacement_deposit_move_txids`/`update_replacement_deposit_move_txid` show that the on-chain `deposit_id` linkage used by verifiers afterward is driven by whatever `deposit_id` the caller passes to the Citrea `replaceDeposit(replace_tx, tx_proof, deposit_id, sha_script_pubkeys)` call [6](#0-5)  and by `Verifier::update_citrea_deposit_and_withdrawals`, which blindly maps whatever `(idx, new_move_txid)` Citrea emits into the DB [7](#0-6) . Since Clementine's own bridge signing path never verified that `replace_tx`'s input actually spent the deposit at `idx`, an attacker who can also drive the Citrea call (out of scope for this Rust repo to verify further) can point any `deposit_id` at an attacker-funded, attacker-controlled vault whose script merely *claims* to replace it.

Existing guards do not catch this: `Verifier::is_deposit_valid` checks council membership match, watchtower/operator counts, uniqueness, script pubkey, amount, and start height — none of which verify the provenance of the deposit-funding transaction [8](#0-7) .

### Impact Explanation
Within Clementine's own signing path, the immediate, code-confirmed consequence is that `deposit_finalize` treats a self-funded, fabricated `ReplacementDeposit` (never linked to any real security-council spend) exactly like a legitimate replacement, and produces N-of-N signatures for its `move_to_vault_tx`. Because the script embeds an attacker-chosen `old_move_txid`, this can be a real victim's move-to-vault txid, which downstream Citrea bookkeeping (`update_replacement_deposit_move_txid`) associates by `idx`, i.e. `deposit_id`. If the on-chain `replaceDeposit` acceptance criteria used by Citrea (not visible in this Rust repository/index) rely on the embedded `old_move_txid` value rather than an actual spend proof of that UTXO, this allows hijacking a `deposit_id`'s vault mapping to an attacker-controlled vault, orphaning/freezing the honest depositor's real BTC (still locked under the old script, no longer tracked as active) while the attacker's new vault impersonates that deposit for withdrawal purposes. This matches "a move-to-vault UTXO permanently frozen" / potential wrong-party reimbursement categories. I could not confirm the exact Citrea-side `replaceDeposit` contract logic in this index, so the full chain to fund-loss is not fully verifiable here — the confirmed, in-scope defect is strictly the missing spend-linkage check in `Verifier::is_deposit_valid`.

### Likelihood Explanation
No privileged role is required. `nofn_xonly_pk` and `security_council` are public protocol parameters obtainable via `GetNofnAggregatedKey`/config. `old_move_txid` can be any historical move-to-vault txid, visible on-chain. Funding the derived Taproot address costs only `bridge_amount` (self-funded) plus fees, and the attacker retains the funds inside their own new vault. The RPC calls `new_deposit`/`deposit_finalize` are reachable by any client of the aggregator's gRPC port. This is repeatable per victim deposit txid.

### Recommendation
In `Verifier::is_deposit_valid` (or `get_deposit_scripts`), when `deposit.deposit_type == DepositType::ReplacementDeposit`, additionally fetch the transaction that funds `deposit_outpoint`, confirm its single relevant input is `OutPoint{ txid: old_move_txid, vout: UtxoVout::DepositInMove }`, and confirm the witness spent that input via the `Multisig(security_council)` script path (i.e., verify the actual on-chain spend, not just the resulting script pubkey). Reject the deposit otherwise.

    async fn is_deposit_valid(&self, deposit_data: &mut DepositData) -> Result<(), BridgeError> {
        // check if security council is the same as in our config
        if deposit_data.security_council != self.config.security_council {
            let reason = format!(
                "Security council in deposit is not the same as in the config, expected {:?}, got {:?}",
                self.config.security_council,
                deposit_data.security_council
            );
            tracing::error!("{reason}");
            return Err(BridgeError::InvalidDeposit(reason));
        }
        // check if extra watchtowers (non verifier watchtowers) are not greater than the maximum allowed
        if deposit_data.actors.watchtowers.len() > MAX_EXTRA_WATCHTOWERS {
            let reason = format!(
                "Number of extra watchtowers in deposit is greater than the maximum allowed, expected at most {}, got {}",
                MAX_EXTRA_WATCHTOWERS,
                deposit_data.actors.watchtowers.len()
            );
            tracing::error!("{reason}");
            return Err(BridgeError::InvalidDeposit(reason));
        }
        // check if total watchtowers are not greater than the maximum allowed
        if deposit_data.get_num_watchtowers() > MAX_NUMBER_OF_WATCHTOWERS {
            let reason = format!(
                "Number of watchtowers in deposit is greater than the maximum allowed, expected at most {}, got {}",
                MAX_NUMBER_OF_WATCHTOWERS,
                deposit_data.get_num_watchtowers()
            );
            tracing::error!("{reason}");
            return Err(BridgeError::InvalidDeposit(reason));
        }

        // check if all verifiers are unique
        if !deposit_data.are_all_verifiers_unique() {
            let reason = format!(
                "Verifiers in deposit are not unique: {:?}",
                deposit_data.actors.verifiers
            );
            tracing::error!("{reason}");
            return Err(BridgeError::InvalidDeposit(reason));
        }

        // check if all watchtowers are unique
        if !deposit_data.are_all_watchtowers_unique() {
            let reason = format!(
                "Watchtowers in deposit are not unique: {:?}",
                deposit_data.actors.watchtowers
            );
            tracing::error!("{reason}");
            return Err(BridgeError::InvalidDeposit(reason));
        }

        // check if all operators are unique
        if !deposit_data.are_all_operators_unique() {
            let reason = format!(
                "Operators in deposit are not unique: {:?}",
                deposit_data.actors.operators
            );
            tracing::error!("{reason}");
            return Err(BridgeError::InvalidDeposit(reason));
        }

        let operators_in_deposit_data = deposit_data.get_operators();
        // check if all operators that still have collateral are in the deposit
        let operators_in_db = self.db.get_operators(None).await?;
        for (xonly_pk, reimburse_addr, collateral_funding_outpoint) in operators_in_db.iter() {
            let operator_data = OperatorData {
                xonly_pk: *xonly_pk,
                collateral_funding_outpoint: *collateral_funding_outpoint,
                reimburse_addr: reimburse_addr.clone(),
            };
            let kickoff_winternitz_pks = self
                .db
                .get_operator_kickoff_winternitz_public_keys(None, *xonly_pk)
                .await?;
            let kickoff_wpks = KickoffWinternitzKeys::new(
                kickoff_winternitz_pks,
                self.config.protocol_paramset().num_kickoffs_per_round,
                self.config.protocol_paramset().num_round_txs,
            )?;
            let is_collateral_usable = self
                .rpc
                .collateral_check(
                    &operator_data,
                    &kickoff_wpks,
                    self.config.protocol_paramset(),
                )
                .await?;
            // if operator is not in deposit but its collateral is still on chain, return false
            if !operators_in_deposit_data.contains(xonly_pk) && is_collateral_usable {
                let reason = format!(
                    "Operator {xonly_pk:?} is is still in protocol but not in the deposit data from aggregator",
                );
                tracing::error!("{reason}");
                return Err(BridgeError::InvalidDeposit(reason));
            }
            // if operator is in deposit, but the collateral is not usable, return false
            if operators_in_deposit_data.contains(xonly_pk) && !is_collateral_usable {
                let reason = format!(
                    "Operator {xonly_pk:?} is in the deposit data from aggregator but its collateral is spent, operator cannot fulfill withdrawals anymore",
                );
                tracing::error!("{reason}");
                return Err(BridgeError::InvalidDeposit(reason));
            }
        }
        // check if there are any operators in the deposit that are not in the DB.
        for operator_xonly_pk in operators_in_deposit_data {
            if !operators_in_db
                .iter()
                .any(|(xonly_pk, _, _)| xonly_pk == &operator_xonly_pk)
            {
                let reason = format!(
                    "Operator {operator_xonly_pk:?} is in the deposit data from aggregator but not in the verifier's DB, cannot sign deposit"
                );
                tracing::error!("{reason}");
                return Err(BridgeError::InvalidDeposit(reason));
            }
        }
        // check if deposit script in deposit_outpoint is valid
        let deposit_scripts: Vec<ScriptBuf> = deposit_data
            .get_deposit_scripts(self.config.protocol_paramset())?
            .into_iter()
            .map(|s| s.to_script_buf())
            .collect();
        // what the deposit scriptpubkey is in the deposit_outpoint should be according to the deposit data
        let expected_scriptpubkey = create_taproot_address(
            &deposit_scripts,
            None,
            self.config.protocol_paramset().network,
        )
        .0
        .script_pubkey();
        let deposit_outpoint = deposit_data.get_deposit_outpoint();
        let deposit_txid = deposit_outpoint.txid;
        let deposit_tx = self
            .rpc
            .get_tx_of_txid(&deposit_txid)
            .await
            .wrap_err("Deposit tx could not be found on chain")?;
        let deposit_txout_in_chain = deposit_tx
            .output
            .get(deposit_outpoint.vout as usize)
            .ok_or(eyre::eyre!(
                "Deposit vout not found in tx {}, vout: {}",
                deposit_txid,
                deposit_outpoint.vout
            ))?;
        if deposit_txout_in_chain.value != self.config.protocol_paramset().bridge_amount {
            let reason = format!(
                "Deposit amount is not correct, expected {}, got {}",
                self.config.protocol_paramset().bridge_amount,
                deposit_txout_in_chain.value
            );
            tracing::error!("{reason}");
            return Err(BridgeError::InvalidDeposit(reason));
        }
        if deposit_txout_in_chain.script_pubkey != expected_scriptpubkey {
            let reason = format!(
                "Deposit script pubkey in deposit outpoint does not match the deposit data, expected {:?}, got {:?}",
                expected_scriptpubkey,
                deposit_txout_in_chain.script_pubkey
            );
            tracing::error!("{reason}");
            return Err(BridgeError::InvalidDeposit(reason));
        }

pub fn generate_replacement_deposit_address(
    old_move_txid: bitcoin::Txid,
    nofn_xonly_pk: XOnlyPublicKey,
    network: bitcoin::Network,
    security_council: SecurityCouncil,
) -> Result<(Address, TaprootSpendInfo), BridgeError> {
    let deposit_script =
        ReplacementDepositScript::new(nofn_xonly_pk, old_move_txid).to_script_buf();

    let security_council_script = Multisig::from_security_council(security_council).to_script_buf();

    let (addr, spend) =
        create_taproot_address(&[deposit_script, security_council_script], None, network);
    Ok((addr, spend))
}
