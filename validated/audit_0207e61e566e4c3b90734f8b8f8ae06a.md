## Summary

The Timeswap bug is: a pool's `lastTimestamp` defaults to `0`, so the first duration-weight calculation computes elapsed time from the Unix epoch instead of from pool creation, over-crediting the first liquidity provider at the expense of everyone else. The local analog is in `pallet-consensus-incentives`: the reward baseline for a state machine's first-ever payout defaults to `0` (via `previous_height`/`LastRewardedHeight` defaults) instead of the height at which tracking began, so the very first relayer reward for a state machine is computed over the entire historical height span instead of the actual incremental block span delivered.

## Finding Description

`pallet_consensus_incentives::calculate_reward` computes the reward as: [1](#0-0) 

```
let previous_height = host.previous_commitment_height(state_machine_id).unwrap_or_default();
let baseline = LastRewardedHeight::<T>::get(state_machine_id).unwrap_or(previous_height);
let blocks = latest_height.saturating_sub(baseline);
let reward = blocks_as_balance.saturating_mul(block_cost);
```

`previous_commitment_height` reads `PreviousStateMachineHeight`, which is populated by `store_latest_commitment_height`: [2](#0-1) 

```rust
fn store_latest_commitment_height(&self, height: StateMachineHeight) -> Result<(), Error> {
    let previous_height = LatestStateMachineHeight::<T>::get(height.id).unwrap_or_default();
    PreviousStateMachineHeight::<T>::insert(height.id, previous_height);
    LatestStateMachineHeight::<T>::insert(height.id, height.height);
    Ok(())
}
```

For a state machine that has never had a commitment stored before, `LatestStateMachineHeight::get(id)` is `None`, so `previous_height` defaults to `0` — the analog of `pool.lastTimestamp == 0`. When the first `ConsensusMessage` for that state machine is processed (and `LastRewardedHeight` is also `None` the first time), `baseline` resolves to `0`, so:

```
blocks = latest_height - 0 = latest_height
```

If the state machine's initial commitment height is not `0` (e.g., a light client bootstrapped at a real-world height, such as height 5,000,000 on an established chain, or any state machine onboarded after governance sets `StateMachinesCostPerBlock` well after the remote chain has already produced many blocks), the first relayer to deliver a valid consensus update is paid `latest_height × cost_per_block` — a reward computed as if every block since genesis had to be individually rewarded — instead of the actual incremental span the relayer proved. This is the direct structural analog of the 53-years-of-shorts bug: an unset/zero baseline value is used as the start of an accrual window whose "true" start should be the point the pallet began tracking the state machine.

The pallet's own regression test only exercises the *rollback* scenario (`reward_covers_only_unpaid_heights_after_rollback`), where `previous_height` is non-zero and stale, not the true first-ever-update case where both `LastRewardedHeight` and `PreviousStateMachineHeight` are `None`/default `0`: [3](#0-2) 

There is no guard anywhere that special-cases "this is the first commitment ever stored for this `state_machine_id`" and pins the baseline to that first height rather than `0`.

## Impact Explanation

This directly causes loss of treasury funds to an unprivileged party (the first relayer to submit a valid consensus message for a given state machine), funded from `T::TreasuryAccount`: [4](#0-3) 

Because `blocks_as_balance.saturating_mul(block_cost)` scales linearly with `latest_height`, a state machine with a large initial/current height (which is normal — most chains onboarded to Hyperbridge already have millions of blocks) results in a reward payout many orders of magnitude larger than intended for a single relayed message, potentially draining or significantly depleting the treasury in one extrinsic. This matches the bounty's "stealing or loss of funds" / "logic attacks" categories and requires no malicious relayer, prover, or governance action — any relayer submitting a legitimate first proof triggers it.

## Likelihood Explanation

This triggers on ordinary, expected usage: whenever governance configures `StateMachinesCostPerBlock` for a state machine (a normal admin action, not itself malicious) and the first honest consensus update is subsequently delivered by any relayer, the bug fires automatically. No adversarial proof, race condition, or privileged action is needed beyond the routine chain-onboarding sequence, making this highly likely to occur in production rather than a contrived edge case.

## Recommendation

Initialize the reward baseline explicitly when a state machine is first tracked (i.e., when `PreviousStateMachineHeight`/`LatestStateMachineHeight` are first written, or when `update_cost_per_block` first configures a state machine), rather than relying on `unwrap_or_default()`/`unwrap_or(0)` semantics. Concretely, `calculate_reward` should special-case the "no prior watermark and no prior commitment" state by seeding `LastRewardedHeight` to the *current* `latest_height` on first observation (paying zero for the initial sync) rather than computing `latest_height - 0`, mirroring the Timeswap fix of setting `lastTimestamp = block.timestamp` on first mint instead of leaving it at its zero default.

## Proof of Concept

1. Governance calls `update_cost_per_block(state_machine_id, cost_per_block)` for a new state machine, e.g. `cost_per_block = 100`.
2. A relayer submits the first valid `ConsensusMessage` for that state machine, whose remote chain is already at height `H = 5_000_000` (typical for onboarding an established chain). `pallet_ismp::Pallet::handle_unsigned` processes it, calling `store_latest_commitment_height` with `height.height = 5_000_000`. Since `LatestStateMachineHeight` was `None`, `previous_height` is set to `0` and `PreviousStateMachineHeight = 0`.
3. `FeeHandler::on_executed` fires with a `StateMachineUpdated { latest_height: 5_000_000 }` event; `calculate_reward` computes `baseline = LastRewardedHeight::get(id).unwrap_or(previous_height) = 0`, then `blocks = 5_000_000 - 0 = 5_000_000`.
4. Reward paid = `5_000_000 × 100 = 500_000_000` units transferred from `TreasuryAccount` to the relayer for a single message — the reward-covers-only-unpaid-heights invariant (verified only for the rollback case in `reward_covers_only_unpaid_heights_after_rollback`) is violated for the "first update ever" case, matching the existing test file's `LastRewardedHeight` mechanism but showing the uncovered gap at initialization. #[test]
fn reward_covers_only_unpaid_heights_after_rollback() {
	let mut ext = new_test_ext();
	ext.execute_with(|| {
		const BLOCK_COST: u128 = 100;
		let host = Ismp::default();
		let state_machine_id = setup_state_machine();
		let treasury_account: AccountId32 = PalletId(*b"treasury").into_account_truncating();

		pallet_consensus_incentives::Pallet::<Test>::update_cost_per_block(
			RuntimeOrigin::root(),
			state_machine_id,
			BLOCK_COST,
		)
		.unwrap();

		let (consensus_message, relayer_account) = setup_host_and_message(&host);
		let message = MessageWithWeight { message: consensus_message, weight: Weight::zero() };
		let updated = |height: u64| {
			vec![IsmpEvent::StateMachineUpdated(StateMachineUpdated {
				state_machine_id,
				latest_height: height,
			})]
		};

		// The chain has already advanced to 1025 and every block up to it has been rewarded once.
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1024 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1024,
		})
		.unwrap();
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1025 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1025,
		})
		.unwrap();

		let treasury_before_first = Balances::balance(&treasury_account);
		<pallet_consensus_incentives::Pallet<Test> as FeeHandler>::on_executed(
			vec![message.clone()],
			updated(1025),
		)
		.unwrap();

		assert_eq!(Balances::balance(&treasury_account), treasury_before_first - BLOCK_COST);
		assert_eq!(
			pallet_consensus_incentives::LastRewardedHeight::<Test>::get(state_machine_id),
			Some(1025)
		);

		// The previous-height pointer references an older height whose commitment is no longer
		// retained in the bounded map.
		pallet_ismp::PreviousStateMachineHeight::<Test>::insert(state_machine_id, 1);

		// Deleting the latest commitment rolls the latest height back to that previous pointer.
		host.delete_state_commitment(StateMachineHeight { id: state_machine_id, height: 1025 })
			.unwrap();
		assert_eq!(host.latest_commitment_height(state_machine_id).unwrap(), 1);

		// The next honest consensus update advances to 1030, carrying the stale pointer forward as
		// the new previous height.
		host.store_state_machine_commitment(
			StateMachineHeight { id: state_machine_id, height: 1030 },
			commitment(),
		)
		.unwrap();
		host.store_latest_commitment_height(StateMachineHeight {
			id: state_machine_id,
			height: 1030,
		})
		.unwrap();
		assert_eq!(host.previous_commitment_height(state_machine_id), Some(1));

		let treasury_before_second = Balances::balance(&treasury_account);
		<pallet_consensus_incentives::Pallet<Test> as FeeHandler>::on_executed(
			vec![message],
			updated(1030),
		)
		.unwrap();

		// The real advance is 1025 -> 1030, so only the 5 new blocks are paid rather than the full
		// span back to the previous pointer.
		assert_eq!(Balances::balance(&treasury_account), treasury_before_second - 5 * BLOCK_COST);
		assert_eq!(
			pallet_consensus_incentives::LastRewardedHeight::<Test>::get(state_machine_id),
			Some(1030)
		);
	})
}
