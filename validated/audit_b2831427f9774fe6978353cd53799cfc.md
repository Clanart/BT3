### Title
Unhandled TypeError in `CommitMentionLinkFilter.getRefFromComparePath` on attacker-crafted compare link crashes markdown rendering pipeline - (File: `app/src/lib/markdown-filters/commit-mention-link-filter.ts`)

### Summary
`CommitMentionLinkFilter` rewrites autolinked GitHub commit/compare/pull-commit URLs found in rendered markdown (issue/PR/commit descriptions and comments fetched from the GitHub API) into shortened `<tt>sha</tt>` references. The `getRefFromComparePath` method assumes a compare URL always contains a `...` separator producing two SHA segments, but never validates that assumption before indexing into the split result, so a malformed compare link throws an uncaught `TypeError`.

### Finding Description
`getRefFromComparePath` matches paths against `this.comparePath = /^compare\/(?<range>.+)$/`, which only requires at least one character after `compare/` — it does not require a `...` delimiter: [1](#0-0) 

It then does: [2](#0-1) 

`range.split('...')` returns an array of length 1 when the captured `range` string does not contain `...` (e.g., `compare/abc1234` or `compare/abc1234.diff` is excluded, but something like `compare/abc1234` with no dots is not). The code only guards `shas.length > 2` — it never checks for `shas.length < 2`. When `shas.length === 1`, `shas[1]` is `undefined`, and `shas[1].indexOf('/')` throws `TypeError: Cannot read properties of undefined (reading 'indexOf')`.

This is invoked from `filter()`, which is called for every accepted anchor node in `SandboxedMarkdown.applyFilters`: [3](#0-2) 

The tree-walker `acceptNode` predicate in `createFilterTreeWalker` only checks that the anchor's `href` equals its `innerText` and matches `commitMentionUrl` (a regex requiring `.../compare/<hex sha>` pattern with `\b` word boundary, not requiring `...`): [4](#0-3) 

Because the `commitMentionUrl` regex uses `([0-9a-f]{7,40})` for the final segment and doesn't require a second SHA/`...`, a URL like `https://github.com/<owner>/<repo>/compare/6fd7945` (single 7+ hex-char token, no `...`) is accepted by the tree walker, routed to `getRefFromComparePath` via the `commitPath` (fails, since it requires `commit/`) then falls to `getRefFromComparePath`, and crashes on `shas[1].indexOf`.

### Impact Explanation
`applyFilters` in `SandboxedMarkdown.applyFilters` (`app/src/ui/lib/sandboxed-markdown.tsx:342-364`) calls `await nodeFilter.filter(node)` inside a `for`/`while` loop with no `try`/`catch`. An uncaught exception here aborts the entire filter pipeline for that render pass, meaning all subsequent node filters (issue mentions, mentions, emoji, video tags, etc.) for the remaining nodes are skipped, and downstream calls such as `this.props.onMarkdownParsed?.()` never fire. This is a rendering-pipeline crash bounded within the renderer/sandboxed-iframe context (denial of correct rendering / broken UI state for that comment or PR body), not remote code execution, since content is DOMPurify-sanitized before injection and the iframe is sandboxed (`sandbox="allow-same-origin"`).

### Likelihood Explanation
Any attacker who can post content that gets rendered through `SandboxedMarkdown` with a `repository` context — e.g., a PR description, PR/issue comment, or commit message on a public repo the victim opens in Desktop — can include an autolinked URL of the form `https://github.com/<owner>/<repo>/compare/<7-40 hex chars>` (GitHub auto-links raw URLs matching this pattern in rendered markdown, and Desktop's own `commitMentionUrl` regex accepts it since it doesn't require `...`). This requires no special permissions beyond commenting/opening a PR against a repo the victim views in Desktop.

### Recommendation
In `getRefFromComparePath`, validate `shas.length === 2` (not just `> 2`) before accessing `shas[1]`, returning `null` otherwise:
```ts
const shas = range.split('...')
if (shas.length !== 2) {
  return null
}
```
Additionally, wrap the `await nodeFilter.filter(node)` call in `SandboxedMarkdown.applyFilters` in a `try`/`catch` so a single malformed node cannot abort the remaining filter pipeline.

### Proof of Concept
1. Render markdown content (e.g., a PR description or comment body) containing the autolinked text:
   `https://github.com/owner/repo/compare/6fd7945`
   as the sole content of an anchor tag where `href === innerText` (this is how GitHub/marked auto-linking normally produces such tags).
2. This is displayed via `SandboxedMarkdown` with a `repository` prop set, triggering `buildCustomMarkDownNodeFilterPipe` to include `CommitMentionLinkFilter`.
3. The tree walker in `createFilterTreeWalker` accepts the node because `commitMentionUrl.test(href)` matches (`compare/` + single hex token).
4. `filter()` calls `getRefFromComparePath` (after `getRefFromCommitPath` returns `null` since path doesn't start with `commit/`), which executes `range.split('...')` → `['6fd7945']`, then `shas[1].indexOf('/')` throws `TypeError`.
5. The exception propagates up through `filter()` → `applyFilters`'s uncaught `await`, terminating the filter loop for that document render pass. [5](#0-4) [6](#0-5)

  private getRefFromComparePath(path: string) {
    const match = path.match(this.comparePath)
    if (match === null || match.groups === undefined) {
      return null
    }

    const { range } = match.groups

    if (/\.(diff|path)$/.test(range)) {
      return null
    }

    const shas = range.split('...')
    if (shas.length > 2) {
      return null
    }

    const slashIndex = shas[1].indexOf('/')
    const secondSha = slashIndex >= 0 ? shas[1].slice(0, slashIndex) : shas[1]

    return {
      ref: `${this.trimCommitSha(shas[0])}...${this.trimCommitSha(secondSha)}`,
      filepathToAppend: slashIndex >= 0 ? shas[1].slice(slashIndex) : undefined,
    }
  }
