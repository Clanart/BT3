### Title
Missing `pool.mu` lock in `TxPool.reset()` causes concurrent unsynchronized mutation of transaction pool data structures - ([File: blockchain/tx_pool.go])

### Summary
`TxPool.reset()`, which runs on every new canonical block, has its `pool.mu.Lock()`/`Unlock()` calls commented out while it still invokes `pool.addTxsLocked(reinject, false)`, a function explicitly documented to require the caller to already hold `pool.mu`. Meanwhile, any transaction sender's RPC call path (`AddLocal`/`AddRemotes` → `addTx`/`addTxs`) *does* take `pool.mu.Lock()` before mutating the same pool-internal maps/lists. This mirrors the btrfs bug class exactly: one code path assumes a lock is held (like `btrfs_delete_unused_bgs()` relying on `space_info->groups_sem`), while another mutation path (`btrfs_reclaim_bgs_work`) does not actually hold the equivalent lock, letting two goroutines mutate the same shared list/map concurrently and corrupt it.

### Finding Description
In `reset()`, the lock acquisition is disabled: [1](#0-0) 

But `addTxsLocked` is documented and written to run "whilst assuming the transaction pool lock is already held": [2](#0-1) 

Every ordinary transaction submission path takes the same lock before performing equivalent mutations: [3](#0-2) 

Because `reset()` runs on a separate goroutine each time the chain head changes (block import), and does not hold `pool.mu` while calling `pool.addTxsLocked()` → `pool.add()`, this path executes concurrently with any external caller's `addTx()`/`addTxs()`, both mutating the same underlying pending/queue maps and per-module hooks (e.g. the gasless `knownTxs` map, itself mutated by `PreAddTx` under only an `RLock`, not a write-exclusive lock, at [4](#0-3) , backed by an unsynchronized map write in [5](#0-4) ).

The result is the Go-runtime analog of the btrfs list corruption: concurrent, unsynchronized writes to shared maps/lists (`pool.pending`, `pool.queue`, `pool.all`, and the gasless `knownTxs` map) from two different call paths that each assume they alone hold the lock.

### Impact Explanation
Concurrent unsynchronized map/list mutation in Go typically triggers `fatal error: concurrent map writes`, which is an unrecoverable node crash (denial of service), or, in rarer cases, silently corrupts pool state (e.g., duplicate/lost transactions, incorrect promotion state), leading to state divergence between nodes on which transactions are considered valid/pending — directly reachable by any unprivileged sender submitting a transaction at the moment a new block triggers `reset()`, which happens on every block, making the race window frequent and reliably reachable without any special privilege.

### Likelihood Explanation
`reset()` is invoked on essentially every new head/canonical block, and any RPC transaction submission (`sendRawTransaction` → `AddLocal`/`AddRemotes`) can race with it. Given normal network transaction throughput and steady block production, the racing window recurs continuously, making this a highly likely, easily triggerable condition rather than a rare edge case.

### Recommendation
Restore the `pool.mu.Lock()`/`defer pool.mu.Unlock()` pair in `TxPool.reset()` (or explicitly document/enforce that the caller of `reset()` already holds `pool.mu`, and audit all call sites to confirm this invariant). Additionally, change `GaslessModule.PreAddTx` to take `knownTxsMu.Lock()` (write lock) instead of `RLock()`, since it performs a mutating `knownTxs.add()` call.

### Proof of Concept
1. Node imports a new block, triggering `blockchain.go`'s call into `TxPool.reset(oldHead, newHead)`. Because `pool.mu.Lock()` is commented out, `reset()` proceeds to call `pool.addTxsLocked(reinject, false)` → `pool.add()` without holding `pool.mu`.
2. Concurrently, an unprivileged user submits a transaction via RPC (`eth_sendRawTransaction`), which routes to `TxPool.addTx()`/`addTxs()`, which correctly takes `pool.mu.Lock()` and calls `pool.add()`.
3. Both goroutines now execute `pool.add()` (and downstream kaiax hooks like gasless `PreAddTx`/`IsReady`) concurrently, mutating the same underlying maps (`pool.pending`, `pool.queue`, `gaslessModule.knownTxs`) without mutual exclusion.
4. Under Go's race detector or in production under load, this manifests as `fatal error: concurrent map writes` (crash) or corrupted pool state — analogous to the btrfs `list_del corruption` crash caused by the missing `unused_bgs_lock`.

// addTx enqueues a single transaction into the pool if it is valid.
func (pool *TxPool) addTx(tx *types.Transaction, local bool) error {
	senderCacher.recover(pool.signer, []*types.Transaction{tx})

	pool.mu.Lock()
	defer pool.mu.Unlock()

	// Try to inject the transaction and update any state
	replace, err := pool.add(tx, local)
	if err != nil {
		return err
	}
	// If we added a new transaction, run promotion checks and return
	if !replace {
		from, _ := types.Sender(pool.signer, tx) // already validated
		pool.promoteExecutables([]common.Address{from})
	}
	return nil
}

	defer pool.mu.Unlock()

// addTxsLocked attempts to queue a batch of transactions if they are valid,
// whilst assuming the transaction pool lock is already held.
func (pool *TxPool) addTxsLocked(txs []*types.Transaction, local bool) []error {
	// Add the batch of transaction, tracking the accepted ones
	dirty := make(map[common.Address]struct{})
	errs := make([]error, len(txs))

	for i, tx := range txs {
		var replace bool
		if replace, errs[i] = pool.add(tx, local); errs[i] == nil {
			if !replace {
				from, _ := types.Sender(pool.signer, tx) // already validated
				dirty[from] = struct{}{}
			}
		}
	}

	// Only reprocess the internal state if something was actually added
	if len(dirty) > 0 {
		addrs := make([]common.Address, 0, len(dirty))
		for addr := range dirty {
			addrs = append(addrs, addr)
		}
		pool.promoteExecutables(addrs)
	}
	return errs
}

func (g *GaslessModule) PreAddTx(tx *types.Transaction, local bool) error {
	g.knownTxsMu.RLock()
	defer g.knownTxsMu.RUnlock()

	if knownTx, ok := g.knownTxs.get(tx.Hash()); ok && knownTx.elapsedPromotedOrAddedTime() < KnownTxTimeout {
		return ErrUnableToAddKnownBundleTx
	}

	if g.IsBundleTx(tx) {
		if uint(g.knownTxs.numQueue()) >= g.GetMaxBundleTxsInQueue() {
			return ErrBundleTxQueueFull
		}
		g.knownTxs.add(tx, TxStatusQueue)
	}
	return nil
}

func (k knownTxs) add(tx *types.Transaction, status int) {
	if tx == nil {
		return
	}

	if ktx, ok := k.get(tx.Hash()); ok {
		ktx.status = status
	} else {
		k[tx.Hash()] = &knownTx{
			tx:           tx,
			addedTime:    time.Time{},
			promotedTime: time.Time{},
			status:       status,
		}
	}

	if status == TxStatusQueue {
		k[tx.Hash()].startAddedTimeIfZero()
	} else if status == TxStatusPending {
		k[tx.Hash()].startPromotedTimeIfZero()
	}

	updateMetrics(&k)
}
