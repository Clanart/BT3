### Title
Missing cross-validation between KIP-71 `LowerBoundBaseFee` and `UpperBoundBaseFee` governance parameters allows inversion of the Magma fee-market mechanism - ([File: kaiax/gov/param.go], [File: params/kip71_config.go])

### Summary
The KIP-71 dynamic base fee parameters `LowerBoundBaseFee` and `UpperBoundBaseFee` are each validated independently by their own `FormatChecker` when set via governance vote, but no check ensures `LowerBoundBaseFee < UpperBoundBaseFee`. This is directly analogous to the reported `setExecutabilityAge` issue, where two related bound parameters are set without validating their relative order.

### Finding Description
Governance parameters are defined in a per-parameter table where each entry independently specifies a `Canonicalizer` and `FormatChecker`. For `Kip71LowerBoundBaseFee` and `Kip71UpperBoundBaseFee`, the `FormatChecker` is `noopFormatChecker` for both, meaning any `uint64` value is accepted for either parameter with no bound-relationship check: [1](#0-0) 

Governance votes for individual parameters are added and applied one at a time via `AddVote`/`HandleVote`/`ParamSet.Set`, with no cross-field validation step that inspects the resulting `ParamSet` as a whole: [2](#0-1) [3](#0-2) 

The bound values are consumed in `KIP71Config.NextMagmaBlockBaseFee`, which computes the next block's base fee by clamping the parent base fee against `lowerBoundBaseFee` and `upperBoundBaseFee`: [4](#0-3) 

If governance sets `LowerBoundBaseFee > UpperBoundBaseFee` (e.g., Lower=100, Upper=50), the clamping logic inverts the intended elastic fee mechanism:
- When `parentBaseFee >= upperBoundBaseFee`, it is clamped down to the (smaller) `upperBoundBaseFee`.
- When `parentBaseFee <= lowerBoundBaseFee`, it is clamped up to the (larger) `lowerBoundBaseFee`.
- Any computed `nextBaseFee` above target usage is clipped back down to `upperBoundBaseFee`, and any computed value below target usage is clipped back up to `lowerBoundBaseFee`.

The net effect is that the base fee snaps to `upperBoundBaseFee` whenever block gas usage exceeds `gasTarget`, and snaps to `lowerBoundBaseFee` whenever usage is below `gasTarget` — the opposite of the intended congestion-pricing behavior (fees should rise when usage is high, not fall).

### Impact Explanation
Because base fee computation directly determines the price every ordinary transaction sender pays (and how much is burned per KIP-71/Magma), an inverted bound configuration allows any block proposer or heavy transaction submitter to force the network's effective base fee to a fixed, artificially low value simply by keeping block gas usage above `gasTarget`. This subverts the intended fee market: honest fee-based congestion pricing is defeated, transaction senders systematically underpay for scarce block space, and the burn/fee economics computed from the base fee become manipulable/gameable by any unprivileged party who can submit enough transactions to push usage above the target. This is a concrete fee-abuse condition reachable purely through normal transaction submission once such a misconfigured `ParamSet` is active.

### Likelihood Explanation
The vulnerability requires a governance vote to set `LowerBoundBaseFee >= UpperBoundBaseFee`, which is a configuration mistake rather than something an ordinary unprivileged actor can trigger directly. However, once the misconfiguration exists (accidentally or via a malicious/compromised governing node), any unprivileged transaction sender can trivially trigger and exploit the resulting fee inversion by submitting transactions that push block gas usage above or below `gasTarget`— no special privilege is needed to exploit the state once it exists. The root cause — absence of a sanity check preventing this invalid parameter combination from ever being accepted — is present in the code today, matching the pattern in the reported issue.

### Recommendation
Add a cross-parameter validation step when applying governance parameter changes for KIP-71 (e.g., in `ParamSet.Set`/`PartialParamSet.Add` or before finalizing a `ParamSet`) that rejects any configuration where `LowerBoundBaseFee >= UpperBoundBaseFee`. This should be enforced both when validating an individual vote for either parameter (by checking against the currently effective value of the other) and when computing/finalizing the merged `ParamSet`, consistent with the check suggested in the reported `setExecutabilityAge` issue (`if lower >= upper { revert }` equivalent, e.g., returning `gov.ErrInvalidParamValue` and rejecting the vote/param application).

### Proof of Concept
1. Governance vote sets `Kip71LowerBoundBaseFee = 100000000000` (100 gwei-equivalent) and `Kip71UpperBoundBaseFee = 50000000000` (50 gwei-equivalent) — both individually pass their `noopFormatChecker` and are accepted independently (`kaiax/gov/param.go` lines 335-367; `kaiax/gov/paramset.go` `Set`).
2. Once active, `NextMagmaBlockBaseFee` (`params/kip71_config.go`) is called for each new block:
   - If `parentGasUsed > gasTarget`: `nextBaseFee` is computed above `parentBaseFee` but immediately clipped down to `upperBoundBaseFee` (50 gwei) since it exceeds it.
   - If `parentGasUsed < gasTarget`: `nextBaseFee` is computed below `parentBaseFee` but immediately clipped up to `lowerBoundBaseFee` (100 gwei) since it falls below it.
3. Any transaction sender can therefore force the network base fee to permanently settle at 50 gwei by ensuring blocks stay above `gasTarget` (e.g., by submitting enough transactions), defeating the intended fee-increase-under-congestion mechanism and paying artificially suppressed fees despite full block utilization.

func (kc *KIP71Config) NextMagmaBlockBaseFee(parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) *big.Int {
	// governance parameters
	lowerBoundBaseFee := new(big.Int).SetUint64(kc.LowerBoundBaseFee)
	upperBoundBaseFee := new(big.Int).SetUint64(kc.UpperBoundBaseFee)
	makeEvenByCeil(lowerBoundBaseFee)
	makeEvenByFloor(upperBoundBaseFee)

	// If the parent is the magma disabled block or genesis, then return the lowerBoundBaseFee (default 25ston)
	if parentHeaderNumber.Cmp(new(big.Int).SetUint64(0)) == 0 || parentHeaderBaseFee == nil {
		return makeEvenByFloor(lowerBoundBaseFee)
	}

	var baseFeeDenominator *big.Int
	if kc.BaseFeeDenominator == 0 {
		// To avoid panic, set the fluctuation range small
		baseFeeDenominator = new(big.Int).SetUint64(64)
	} else {
		baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
	}
	gasTarget := kc.GasTarget
	upperGasLimit := kc.MaxBlockGasUsedForBaseFee

	// check the case of upper/lowerBoundBaseFee is updated by governance mechanism
	parentBaseFee := parentHeaderBaseFee
	if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
		parentBaseFee = upperBoundBaseFee
	} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
		parentBaseFee = lowerBoundBaseFee
	}

	// upper gas limit cut off the impulse of used gas to upper bound
	parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
	if parentGasUsed == gasTarget {
		return makeEvenByFloor(parentBaseFee)
	} else if parentGasUsed > gasTarget {
		// shortcut. If parentBaseFee is already reached upperbound, do not calculate.
		if parentBaseFee.Cmp(upperBoundBaseFee) == 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		// If the parent block used more gas than its target,
		// the baseFee of the next block should increase.
		// baseFeeDelta = max(1, parentBaseFee * (parentGasUsed - gasTarget) / gasTarget / baseFeeDenominator)
		gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := math.BigMax(x.Div(y, baseFeeDenominator), common.Big1)

		nextBaseFee := x.Add(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(upperBoundBaseFee) > 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	} else {
		// shortcut. If parentBaseFee is already reached lower bound, do not calculate.
		if parentBaseFee.Cmp(lowerBoundBaseFee) == 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		// Otherwise if the parent block used less gas than its target,
		// the baseFee of the next block should decrease.
		// baseFeeDelta = parentBaseFee * (gasTarget - parentGasUsed) / gasTarget / baseFeeDenominator
		gasUsedDelta := new(big.Int).SetUint64(gasTarget - parentGasUsed)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := x.Div(y, baseFeeDenominator)

		nextBaseFee := x.Sub(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(lowerBoundBaseFee) < 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	}
}
