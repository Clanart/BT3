Based on my research, the strongest analog is the **FieldMask <-> ProtoJSON string conversion**, which has the same class of flaw as the CVE: converting a list of attacker-controlled structured values into a single delimiter-joined string without rejecting/escaping the delimiter character within an individual value, then re-parsing that string by naive splitting — creating ambiguity between "one entry containing the delimiter" and "multiple entries separated by the delimiter."

### Title
FieldMask path/JSON-string conversion allows comma-delimiter smuggling, letting one raw path masquerade as multiple paths (or vice versa) - ([File: src/google/protobuf/util/field_mask_util.cc])

### Summary
The Node.js CVE's failed invariant was: a structured, attacker-influenced value (a SAN entry) was serialized into a single delimited string without escaping characters that collide with the delimiter, so downstream string-based matching logic could not tell "one entry with an embedded delimiter" apart from "multiple entries," letting an attacker's single crafted value be reinterpreted as multiple, unintended values and bypass a security check performed on the pre-conversion representation. Protobuf's `FieldMask` implements the exact same pattern: `paths` is an unrestricted `repeated string` (any bytes are legal, since binary/ProtoJSON parsing performs no field-mask-specific validation), and `FieldMaskUtil::ToJsonString`/`ToString` join `paths()` with a literal `,` while `FromJsonString`/`FromString` split on `,` — with no check that an individual path doesn't itself contain a `,`.

### Finding Description
`FieldMaskUtil::ToJsonString` in C++ walks each path, camel-cases it via `SnakeCaseToCamelCase`, and joins them with `,`: [1](#0-0)  `SnakeCaseToCamelCase` only rejects uppercase ASCII letters; it passes every other byte (including `,` and any control character) through unchanged: [2](#0-1)  Symmetrically, `FromString`/`FromJsonString` split purely on `,` with no re-validation that the resulting segments correspond to the original path boundaries: [3](#0-2) 

The same unescaped-join/naive-split pattern is duplicated in the Java (`FieldMaskUtil.toJsonString`/`fromJsonString`, using plain `String.join`/`split(",")` with `lowerUnderscoreToLowerCamel`/`lowerCamelToLowerUnderscore` that never reject `,`): [4](#0-3)  the C# `MergeFieldMask`/`ToSnakeCase` path (splits on `FieldMaskPathSeparators`, and the encode side similarly joins with `,`, with `ToSnakeCase` only rejecting underscores, not commas): [5](#0-4)  and the Python `FieldMask.ToJsonString`/`FromJsonString` (`','.join(...)` / `value.split(',')`, with `_SnakeCaseToCamelCase`/`_CamelCaseToSnakeCase` not rejecting commas): [6](#0-5) 

Because `paths` is populated straight from a binary-parsed `FieldMask` message (or from raw ProtoJSON via `FromJsonString`, which is the mirror direction), a client can send a bounded, otherwise-valid `FieldMask` whose single path element is the literal string `"a,b"`. Any application logic that treats `fieldMask.paths()` as the security-relevant unit (e.g., checking each path string against an allow/deny-list of updatable fields) will see one opaque token `"a,b"` that does not match either `"a"` or `"b"` in its list. If that same `FieldMask` is subsequently serialized with `ToJsonString`/`toJsonString` and handed to another component (a different service, language binding, or a later `FromJsonString` call in the same process) that re-parses the comma-joined string, it silently becomes two independent paths, `"a"` and `"b"` — exactly the SAN-string injection pattern, where one structured unit is smuggled through a validation boundary as multiple.

### Impact Explanation
Protobuf itself performs no validation of `FieldMask.paths` content during binary or ProtoJSON parsing (validation via `FieldMaskUtil::IsValidPath`/`isValid` is opt-in and applied to the pre-split path list, not to the round-tripped JSON string). Any consuming application that (a) validates/authorizes field-mask paths at one layer, then (b) reserializes/deserializes the mask through `ToJsonString`/`FromJsonString` before applying it at another layer (a common pattern for cross-service field-level update authorization, e.g. AIP-134 "updatable fields" checks) is exposed to path smuggling: a single allowed-looking path string can expand into multiple, unauthorized field paths after a JSON round-trip, or conversely two individually-disallowed short paths could be assembled into one path string that evades a substring/exact-match check. This is an integrity failure in a security-relevant matching/authorization primitive Protobuf ships for consuming applications (`google.protobuf.FieldMask` + `FieldMaskUtil`), analogous to how the Node.js SAN-to-string conversion undermined the security decision made on the reconstructed string.

### Likelihood Explanation
Reaching this requires only a supported public API path: constructing a `FieldMask` (via binary parse, since `paths` is an unrestricted `repeated string`) with a path containing a `,`, then calling the standard, documented `ToJsonString`/`toJsonString`/`ToJsonString()` conversion routines that ship in every major language binding (C++, Java, Python, C#) — no privileged access or malformed schema is needed. The likelihood of exploitation depends entirely on whether a consuming application performs authorization decisions on `FieldMask.paths` before a JSON round-trip and trusts the round-tripped result afterward, which is a plausible but not universal integration pattern (hence Medium, matching the source CVE's severity, rather than Critical/High).

### Recommendation
Reject (or percent-/backslash-escape) the path separator character (`,`) inside individual `FieldMask` path segments during `ToJsonString`/`toJsonString`/`ToJsonString()` conversion in all bindings (C++ `field_mask_util.cc`, Java `FieldMaskUtil.java`, Python `field_mask.py`, C# `JsonParser.cs`/`FieldMask.pb.cs`), returning an error rather than silently emitting an ambiguous comma-joined string. Additionally, document that `FieldMaskUtil::IsValidPath`/`isValid` (which already rejects invalid path syntax against a descriptor) should be invoked before any authorization decision that will later be re-expressed via `ToJsonString`, and consider making `FromString`/`FromJsonString` reject empty-looking splits distinctly from legitimately empty paths to avoid similar ambiguity in the reverse direction.

### Proof of Concept
Conceptual reproduction (mirrors the CVE's "single value with embedded delimiter becomes multiple values after string conversion"):
```cpp
google::protobuf::FieldMask mask;
mask.add_paths("a,b");   // single, syntactically-unusual but wire-legal path (repeated string has no charset restriction)

std::string json;
FieldMaskUtil::ToJsonString(mask, &json);
// json == "a,b"  -- indistinguishable from a two-path mask {"a","b"}

FieldMask reparsed;
FieldMaskUtil::FromJsonString(json, &reparsed);
// reparsed.paths() == ["a", "b"]  -- ONE original path became TWO
```
A hypothetical caller that authorizes `mask.paths()` (seeing only the single token `"a,b"`, which matches no entry in a deny-list containing `"b"`) and later applies `reparsed` (now containing `"b"`) after a `ToJsonString`/`FromJsonString` round trip through another service boundary would apply an update to `"b"` that the original authorization check never actually evaluated. I have not executed this against a live consuming application; the trace above is a direct reading of the cited `field_mask_util.cc`/`FieldMaskUtil.java`/`field_mask.py`/`JsonParser.cs` conversion routines, which is where a Devin session with full repo/build access could compile and run the exact C++ snippet above to confirm the round-trip behavior.

bool FieldMaskUtil::SnakeCaseToCamelCase(absl::string_view input,
                                         std::string* output) {
  output->clear();
  bool after_underscore = false;
  for (char input_char : input) {
    if (input_char >= 'A' && input_char <= 'Z') {
      // The field name must not contain uppercase letters.
      return false;
    }
    if (after_underscore) {
      if (input_char >= 'a' && input_char <= 'z') {
        output->push_back(input_char + 'A' - 'a');
        after_underscore = false;
      } else {
        // The character after a "_" must be a lowercase letter.
        return false;
      }
    } else if (input_char == '_') {
      after_underscore = true;
    } else {
      output->push_back(input_char);
    }
  }
  if (after_underscore) {
    // Trailing "_".
    return false;
  }
  return true;
}

bool FieldMaskUtil::ToJsonString(const FieldMask& mask, std::string* out) {
  out->clear();
  for (int i = 0; i < mask.paths_size(); ++i) {
    absl::string_view path = mask.paths(i);
    std::string camelcase_path;
    if (!SnakeCaseToCamelCase(path, &camelcase_path)) {
      return false;
    }
    if (i > 0) {
      out->push_back(',');
    }
    out->append(camelcase_path);
  }
  return true;
}

  /** Converts a lowerCamelCase string to lower_underscore style. */
  private static String lowerCamelToLowerUnderscore(String str) {
    StringBuilder sb = new StringBuilder();
    for (int i = 0; i < str.length(); i++) {
      char c = str.charAt(i);
      if (c >= 'A' && c <= 'Z') {
        sb.append('_');
      }
      sb.append(Character.toLowerCase(c));
    }
    return sb.toString();
  }

  /**
   * Converts a field mask to a ProtoJSON string, that is converting from snake case to camel case
   * and joining all paths into one string with commas.
   */
  public static String toJsonString(FieldMask fieldMask) {
    List<String> paths = new ArrayList<String>(fieldMask.getPathsCount());
    for (String path : fieldMask.getPathsList()) {
      if (path.isEmpty()) {
        continue;
      }
      paths.add(lowerUnderscoreToLowerCamel(path));
    }
    return String.join(FIELD_PATH_SEPARATOR, paths);
  }

  /**
   * Converts a field mask from a ProtoJSON string, that is splitting the paths along commas and
   * converting from camel case to snake case.
   */
  @SuppressWarnings("StringSplitter")
  public static FieldMask fromJsonString(String value) {
    String[] paths = value.split(FIELD_PATH_SEPARATOR);
    FieldMask.Builder builder = FieldMask.newBuilder();
    for (String path : paths) {
      if (path.isEmpty()) {
        continue;
      }
      builder.addPaths(lowerCamelToLowerUnderscore(path));
    }
    return builder.build();
  }

        private static string ToSnakeCase(string text)
        {
            var builder = new StringBuilder(text.Length * 2);
            // Note: this is probably unnecessary now, but currently retained to be as close as possible to the
            // C++, whilst still throwing an exception on underscores.
            bool wasNotUnderscore = false;  // Initialize to false for case 1 (below)
            bool wasNotCap = false;

            for (int i = 0; i < text.Length; i++)
            {
                char c = text[i];
                if (c >= 'A' && c <= 'Z') // ascii_isupper
                {
                    // Consider when the current character B is capitalized:
                    // 1) At beginning of input:   "B..." => "b..."
                    //    (e.g. "Biscuit" => "biscuit")
                    // 2) Following a lowercase:   "...aB..." => "...a_b..."
                    //    (e.g. "gBike" => "g_bike")
                    // 3) At the end of input:     "...AB" => "...ab"
                    //    (e.g. "GoogleLAB" => "google_lab")
                    // 4) Followed by a lowercase: "...ABc..." => "...a_bc..."
                    //    (e.g. "GBike" => "g_bike")
                    if (wasNotUnderscore &&               //            case 1 out
                        (wasNotCap ||                     // case 2 in, case 3 out
                         (i + 1 < text.Length &&         //            case 3 out
                          (text[i + 1] >= 'a' && text[i + 1] <= 'z')))) // ascii_islower(text[i + 1])
                    {  // case 4 in
                       // We add an underscore for case 2 and case 4.
                        builder.Append('_');
                    }
                    // ascii_tolower, but we already know that c *is* an upper case ASCII character...
                    builder.Append((char) (c + 'a' - 'A'));
                    wasNotUnderscore = true;
                    wasNotCap = false;
                }
                else
                {
                    builder.Append(c);
                    if (c == '_')
                    {
                        throw new InvalidProtocolBufferException($"Invalid field mask: {text}");
                    }
                    wasNotUnderscore = true;
                    wasNotCap = true;
                }
            }
            return builder.ToString();
        }

  def ToJsonString(self):
    """Converts FieldMask to string according to ProtoJSON spec."""
    camelcase_paths = []
    for path in self.paths:
      camelcase_paths.append(_SnakeCaseToCamelCase(path))
    return ','.join(camelcase_paths)

  def FromJsonString(self, value):
    """Converts string to FieldMask according to ProtoJSON spec."""
    if not isinstance(value, str):
      raise ValueError('FieldMask JSON value not a string: {!r}'.format(value))
    self.Clear()
    if value:
      for path in value.split(','):
        self.paths.append(_CamelCaseToSnakeCase(path))
