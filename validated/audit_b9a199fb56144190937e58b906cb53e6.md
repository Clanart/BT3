### Title
Auction bid pool accepts arbitrarily low bids while committing the proposer to pay uncapped, attacker-controlled gas cost, allowing gas-griefing deficit against the CN's `AuctionLenderMinBal` reserve - ([File: kaiax/auction/impl/bid_pool.go])

### Summary
`BidPool.validateBid` only rejects a bid when `bid.Bid.Sign() <= 0`, i.e. any bid ≥ 1 wei is accepted, while the proposer's `BidTx` gas limit is derived from the attacker-controlled `CallGasLimit` (up to `BidTxMaxCallGasLimit = 10_000_000`) and its gas price is copied from the searcher's own target transaction. Because the `BidTx` is generated and signed by the CN's own `NodeKey`, the CN itself fronts the KAIA to pay for gas on every accepted bid, expecting the bid amount to be adequate compensation. There is no check tying the bid amount to the actual gas cost the CN is about to incur, mirroring the original report's core defect: no floor relating the claimed value to the real cost of servicing the request.

### Finding Description
`validateBid` enforces only:
1. sender/winner uniqueness,
2. block-number range,
3. `bid.Bid.Sign() > 0` (i.e., bid ≥ 1 wei),
4. data size ≤ `BidTxMaxDataSize`,
5. `CallGasLimit` ≤ `BidTxMaxCallGasLimit` (10,000,000),
6. valid searcher/auctioneer signatures. [1](#0-0) 

None of these checks relate the bid amount to the gas the CN will actually spend. `getBidTxGasLimit` computes `intrinsicGas + bid.CallGasLimit + bidTxGasBuffer`, i.e., the searcher fully controls the gas limit up to the 10M cap: [2](#0-1) 

`GetBidTxGenerator` builds and signs the `BidTx` with the CN's own `NodeKey`, using the target tx's `GasFeeCap`/`GasTipCap` (fully attacker-controlled, since the attacker crafts their own target transaction) as the gas price for the CN-funded transaction: [3](#0-2) 

The module only requires the CN to hold `AuctionLenderMinBal` (10 KAIA) once, at Init time, and disables itself only if the balance is already insufficient at startup — it never re-checks or replenishes as bids drain the balance during runtime: [4](#0-3) 

This is structurally identical to the original SolverVaults issue: a value-extraction primitive (withdrawal / bid) is gated only by "is the requested amount nonzero/positive," not by "does the requester's payment cover the fixed processing cost the privileged party (balancer / CN proposer) must front." Because bids are per-target-transaction and the target transaction itself is fully attacker-supplied, an attacker (as "auction bidder") can manufacture arbitrarily many cheap target transactions, each paired with a `CallGasLimit` near the 10M ceiling and a bid of 1 wei, forcing the CN to spend real KAIA gas on each accepted `BidTx` while receiving negligible compensation back.

### Impact Explanation
Repeatedly winning bids at 1 wei with maximal `CallGasLimit` forces the CN's `NodeKey` account to pay substantial gas fees per block while receiving virtually nothing in return, progressively draining the CN's on-chain balance. Once the balance falls below `AuctionLenderMinBal`, the auction module disables itself on subsequent restarts/checks, denying auction service availability and constituting a fee-drain/value-extraction impact on the CN operator that goes beyond a mere resource/DoS concern — it is a concrete asset-loss vector for the block proposer, analogous to the balancer being drained of funds in the original report.

### Likelihood Explanation
The path requires the `Auctioneer`'s co-signature on the bid (`ValidateAuctioneerSig`), which gates arbitrary unauthenticated spam, but the CN-side code performs no independent economic sanity check — it fully trusts that a signed bid ≥ 1 wei is acceptable regardless of the gas cost it is about to incur. Any auctioneer implementation that verifies eligibility/signatures but not "bid amount covers proposer's execution cost" (a reasonable oversight given KIP-249 does not mandate this on the CN side) permits this drain to occur repeatedly, block after block, with attacker fully controlling `CallGasLimit` and the target-tx gas price up to the enforced maxima.

### Recommendation
Add a minimum-bid check in `BidPool.validateBid` (or `insertBid`) that compares `bid.Bid` against the estimated gas cost of the resulting `BidTx` (e.g., `intrinsicGas + CallGasLimit + bidTxGasBuffer` times a current or bid-implied gas price), rejecting bids whose value does not at least cover the CN's expected outlay. Additionally, consider re-checking the CN's live balance against `AuctionLenderMinBal` before including each `BidTx` in a block, and pausing bid acceptance mid-operation (not just at Init) if the balance falls under a safety threshold.

### Proof of Concept
1. Attacker crafts a throwaway target transaction with `To`/`Data` that is cheap/no-op, sets its `GasFeeCap`/`GasTipCap` to some nonzero value the attacker is fine paying (or a minimal legitimate value).
2. Attacker (as searcher) constructs a `Bid` referencing this target tx, with `Bid = 1` (wei) and `CallGasLimit = BidTxMaxCallGasLimit (10_000_000)`.
3. Attacker obtains the (potentially non-adversarial) `Auctioneer`'s co-signature for this bid — nothing in `validateBid`/`validateBidSigs` requires the auctioneer to verify bid-to-cost ratio — and submits via `auction_submitBid` RPC.
4. `AddBid` → `validateBid` accepts (bid.Bid.Sign() > 0), `getBidTxGasLimit` computes a gas limit near 10M using intrinsic gas + `CallGasLimit` + buffer.
5. `ExtractTxBundles`/`GetBidTxGenerator` produces a `BidTx` signed by the CN's `NodeKey`, paid at the target tx's gas price, for up to ~10M gas, included in the next block after the target tx.
6. Repeating this across many blocks with new throwaway target transactions systematically drains the CN's KAIA balance for negligible (1 wei) compensation until the balance is exhausted, at which point auction functionality becomes unavailable per the `AuctionLenderMinBal` check.

func (bp *BidPool) validateBid(bid *auction.Bid) error {
	blockNumber := bid.BlockNumber

	bp.bidMu.RLock()

	// Check if the auction tx is already in the pool.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		bp.bidMu.RUnlock()
		return auction.ErrBidAlreadyExists
	}

	// 1. The `bid.Sender` must not be in the winner list of the same block number if the new bid isn't equal to the previous bid.
	if bp.senderHasDifferentWinner(bid) {
		bp.bidMu.RUnlock()
		return auction.ErrBidSenderExists
	}
	bp.bidMu.RUnlock()

	curBlock := bp.Chain.CurrentBlock()
	if curBlock == nil {
		return auction.ErrBlockNotFound
	}

	// 2. The `bid.BlockNumber` must be in range of `[currentBlockNumber + 1, currentBlockNumber + allowFutureBlock]`.
	curNum := curBlock.NumberU64()
	if blockNumber <= curNum || blockNumber > curNum+allowFutureBlock {
		return auction.ErrInvalidBlockNumber
	}

	// 3. The `bid.Bid` must be greater than 0.
	if bid.Bid.Sign() <= 0 {
		return auction.ErrZeroBid
	}

	// 4. The data size must be less than the maximum limit.
	if uint64(len(bid.Data)) > BidTxMaxDataSize {
		return auction.ErrExceedMaxDataSize
	}

	// 5. The gas limit must be less than the maximum limit.
	if bid.CallGasLimit > BidTxMaxCallGasLimit {
		return auction.ErrExceedMaxCallGasLimit
	}

	// 6. The `bid.SearcherSig` and `bid.AuctioneerSig` must be valid.
	if err := bp.validateBidSigs(bid); err != nil {
		return err
	}

	return nil
}

func (bp *BidPool) getBidTxGasLimit(bid *auction.Bid) (uint64, error) {
	bp.auctionInfoMu.RLock()
	buffer := bp.bidTxGasBuffer
	bp.auctionInfoMu.RUnlock()

	data, err := system.EncodeAuctionCallData(bid, bp.auctionEntryPointVersion)
	if err != nil {
		return 0, err
	}

	rules := bp.ChainConfig.Rules(big.NewInt(int64(bid.BlockNumber)))
	intrinsicGas, err := types.IntrinsicGas(data, nil, nil, false, rules)
	if err != nil {
		return 0, err
	}
	floorDataGas := uint64(0)
	if rules.IsPrague {
		floorDataGas, err = blockchain.FloorDataGas(types.TxTypeEthereumDynamicFee, data, 0)
		if err != nil {
			return 0, err
		}
	}

	return max(intrinsicGas+bid.CallGasLimit+buffer, floorDataGas), nil
}

func (a *AuctionModule) GetBidTxGenerator(tx *types.Transaction, bid *auction.Bid) *builder.TxOrGen {
	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId           = a.InitOpts.ChainConfig.ChainID
			signer            = types.LatestSignerForChainID(chainId)
			auctionEntryPoint = a.bidPool.GetAuctionEntryPoint()
			key               = a.InitOpts.NodeKey
		)

		data, err := system.EncodeAuctionCallData(bid, a.bidPool.GetAuctionEntryPointVersion())
		if err != nil {
			return nil, err
		}

		if bid.GetGasLimit() == 0 {
			gasLimit, err := a.bidPool.getBidTxGasLimit(bid)
			if err != nil {
				return nil, err
			}
			bid.SetGasLimit(gasLimit)
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &auctionEntryPoint,
			types.TxValueKeyAmount:     common.Big0,
			types.TxValueKeyData:       data,
			types.TxValueKeyGasLimit:   bid.GetGasLimit(),
			types.TxValueKeyGasFeeCap:  tx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  tx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)

		return tx, err
	}

var AuctionLenderMinBal = new(big.Int).Mul(big.NewInt(10), new(big.Int).SetUint64(params.KAIA))

func NewAuctionModule() *AuctionModule {
	return &AuctionModule{}
}

func (a *AuctionModule) Init(opts *InitOpts) error {
	if opts == nil || opts.ChainConfig == nil || opts.AuctionConfig == nil || opts.Chain == nil || opts.Backend == nil || opts.Downloader == nil || opts.NodeKey == nil {
		return auction.ErrInitUnexpectedNil
	}

	a.InitOpts = *opts

	// Note that the auction module is always disabled except CN.
	// Disable the auction module if the CN has insufficient balance.
	if !opts.AuctionConfig.Disable {
		state, err := opts.Chain.State()
		if err != nil {
			return fmt.Errorf("failed to get state: %v", err)
		}
		nodeAddr := crypto.PubkeyToAddress(opts.NodeKey.PublicKey)
		balance := state.GetBalance(nodeAddr)
		if balance.Cmp(AuctionLenderMinBal) < 0 {
			a.AuctionConfig.Disable = true
			logger.Warn("disabling auction module due to insufficient balance", "node", nodeAddr.Hex(), "balance", balance.String())
		}
	}
