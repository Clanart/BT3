### Title
MultiEdit content extraction joins `new_string` fragments with a space, letting a split payload evade substring/regex pattern checks - ([File: plugins/security-guidance/hooks/security_reminder_hook.py])

### Summary
`extract_content_from_input()` builds the text checked by `check_patterns()` for a `MultiEdit` call by joining each edit's `new_string` with `" ".join(...)`, not by simulating the actual sequential string replacements applied to the file. An attacker can split a dangerous substring (e.g. `os.system(`) across two `new_string` entries such that the joined check string never contains the substring contiguously, while the real post-edit file content does contain it unbroken (MultiEdit performs literal string replacement, it does not insert any space between edits' replacement text).

### Finding Description
`extract_content_from_input` at [1](#0-0)  handles `MultiEdit` by extracting only the `new_string` values and joining them with a literal space: `" ".join(edit.get("new_string", "") for edit in edits)`. This string is what gets passed into `check_patterns(file_path, content)`, defined at [2](#0-1) , which performs substring matching (`if substring in content`) and regex matching (`re.search(pattern["regex"], content)`) against `SECURITY_PATTERNS`.

Because `MultiEdit` applies each `old_string -> new_string` replacement directly against the file's existing text (concatenating whatever surrounding characters already exist in the file, not a space), the actual on-disk result of two edits whose `new_string` values are e.g. `"os.syst"` and `"em("` — inserted adjacent to each other in the file (through appropriate `old_string` targets or sequential appends) — produces the contiguous substring `os.system(` in the real file, while the check-time joined string becomes `"os.syst em("`, which does not contain `os.system(` and does not match the substring rule. The same reasoning applies to `child_process.exec` or any other substring/regex-based rule whose match spans what would be the join boundary.

This is a real parser-completeness gap: the hook's detection input diverges from the true resulting file content it is meant to protect.

### Impact Explanation
This allows dangerous code patterns (e.g., command-injection primitives like `os.system(`, `child_process.exec`) to land on disk via the `MultiEdit` tool without triggering the PostToolUse pattern-based warning that the security-guidance plugin is designed to surface for every edit, per the plugin's own stated architecture (fast regex checks that run "on every file write" to detect command injection, per the module docstring around [3](#0-2) ). The pattern-based layer is silently bypassed for split payloads, undermining the "deny means deny" detection invariant for this specific enforcement layer.

### Likelihood Explanation
Exploitability requires only using the `MultiEdit` tool with an `edits` list crafted so a monitored substring/regex straddles a `new_string` boundary — no privilege beyond normal tool use is required, and it is fully deterministic/reproducible given `extract_content_from_input`'s fixed join logic.

### Recommendation
Instead of joining `new_string` values with a separator, `extract_content_from_input` should reconstruct or approximate the actual resulting content for `MultiEdit` — e.g., by reading the current file content and applying the sequence of `old_string -> new_string` replacements in order (mirroring what the `MultiEdit` tool itself does) before passing the result to `check_patterns`, or at minimum joining with an empty string plus checking each adjacent-fragment concatenation rather than a space-delimited join, so pattern rules cannot be defeated by fragment splitting at edit boundaries.

### Proof of Concept
Unit test plan:
1. Construct `tool_input = {"edits": [{"old_string": "A", "new_string": "os.syst"}, {"old_string": "B", "new_string": "em("}]}`.
2. Call `extract_content_from_input("MultiEdit", tool_input)` and assert the result is `"os.syst em("`.
3. Call `check_patterns(file_path, "os.syst em(")` and assert no match is returned for the `os.system(` substring rule.
4. Separately, apply the two edits to a sample file's content in sequence (simulating the real `MultiEdit` semantics, i.e., `content.replace("A","os.syst").replace("B","em(")` where `A` and `B` are placed adjacently in the source), producing actual file content containing the contiguous substring `os.system(`.
5. Call `check_patterns(file_path, actual_file_content)` and assert it DOES match the `os.system(` rule — demonstrating the divergence between what the hook checks and the true resulting file content.

```python
def check_patterns(file_path, content):
    """Check if file path or content matches any security patterns. Returns ALL matches."""
    normalized_path = file_path.lstrip("/")
    matches = []

    for pattern in list(SECURITY_PATTERNS) + extensibility.user_patterns():
        # path_filter is a gate: when present, the rule only applies to
        # matching paths. Distinct from path_check, which is itself a
        # positive match condition (e.g. .github/workflows/).
        if "path_filter" in pattern:
            try:
                if not pattern["path_filter"](normalized_path):
                    continue
            except Exception:
                continue

        matched = False

        if "path_check" in pattern:
            try:
                if pattern["path_check"](normalized_path):
                    matched = True
            except Exception:
                pass

        if not matched and "substrings" in pattern and content:
            for substring in pattern["substrings"]:
                if substring in content:
                    matched = True
                    break

        if not matched and "regex" in pattern and content:
            try:
                if re.search(pattern["regex"], content):
                    matched = True
            except Exception:
                pass

        if matched:
            matches.append((pattern["ruleName"], pattern["reminder"]))

    return matches
```

```python
def extract_content_from_input(tool_name, tool_input):
    """Extract content to check from tool input based on tool type."""
    if tool_name == "Write":
        return tool_input.get("content", "")
    elif tool_name == "Edit":
        return tool_input.get("new_string", "")
    elif tool_name == "MultiEdit":
        edits = tool_input.get("edits", [])
        if edits:
            return " ".join(edit.get("new_string", "") for edit in edits)
        return ""
    return ""
```
