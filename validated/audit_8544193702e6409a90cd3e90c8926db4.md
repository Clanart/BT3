### Title
Missing consistency validation on KIP-71 base fee bounds set via contract governance (`GovParam`) allows near-instant, unbounded base-fee parameter changes with no timelock - (File: kaiax/gov/contractgov/impl/getter.go)

### Summary
`GovParam` contract governance (`setParam`/`setParamIn`) can change `kip71.lowerboundbasefee` and `kip71.upperboundbasefee` with an activation as low as a few blocks, and unlike header governance, contract governance never validates that `lowerBoundBaseFee <= upperBoundBaseFee` before the value is merged into the effective `ParamSet`. This mirrors the reported bug class: a privileged "key variable" setter with no timelock/consistency guard that can instantly break an invariant users depend on.

### Finding Description
Header governance enforces a consistency check on any vote that changes `kip71.lowerboundbasefee`/`kip71.upperboundbasefee`, rejecting a lower bound greater than the upper bound (or vice versa): [1](#0-0) 

This check exists only inside `headerGovModule.checkConsistency`, which runs during header vote verification. Header-governance changes are also naturally delayed: a ratified vote at epoch `k` only takes effect at epoch `k+1` (an epoch is 604800 blocks on Mainnet), giving an implicit timelock.

Contract governance (`GovParam` contract, reachable post-Kore) has no equivalent check. `contractGovModule.GetParamSet`/`GetPartialParamSet` reads whatever values are stored in the contract and applies them directly via `ParamSet.Set`, with no cross-field validation: [2](#0-1) 

The top-level `GovModule.GetParamSet` merges Fallback → HeaderGov → ContractGov (post-Kore), so a contract-governance value simply overwrites the consistent header-governance value with no re-validation: [3](#0-2) 

`GovParam.setParamIn` allows the owner to schedule a parameter change to activate after an arbitrary relative number of blocks (as small as 1), i.e., far below the epoch-scale delay used by header governance: [4](#0-3) 

The KIP-71 base-fee calculation (`NextMagmaBlockBaseFee`) assumes `lowerBoundBaseFee <= upperBoundBaseFee` is always true; this invariant is explicitly asserted in tests: [5](#0-4) [6](#0-5) 

If contract governance sets `lowerBoundBaseFee > upperBoundBaseFee` (which the code never rejects), `parentBaseFee` gets clamped to `lowerBoundBaseFee` when it is below the (now-lower) `upperBoundBaseFee`, and subsequent delta calculations can push the returned "next base fee" below `upperBoundBaseFee` while `lowerBoundBaseFee` remains higher — i.e., the computed base fee can end up **outside** its own configured lower bound, silently violating the invariant the fee-market design relies on.

### Impact Explanation
The resulting base fee feeds directly into transaction-pool admission logic that unprivileged transaction senders depend on (`ErrGasPriceBelowBaseFee`, `ErrFeeCapBelowBaseFee`) and into `LowerBoundGasPrice`/`UpperBoundGasPrice` RPC responses used for fee estimation: [7](#0-6) 

An inconsistent bound pair can cause the base fee to behave unpredictably (e.g., a legitimate transaction with a fee cap computed against the advertised lower/upper bound getting rejected, or the fee market failing to stabilize as designed), directly harming ordinary public transaction senders and RPC callers with no advance warning — the same class of harm ("a position/tx could become invalid from one block to the next") described in the referenced report, but for KIP-71 pricing instead of margin-trading leverage/liquidation thresholds.

### Likelihood Explanation
This requires control of the `GovParam` contract owner key (a privileged actor, analogous to the `MarginSwap` owner in the original report), so it is not exploitable by a fully unprivileged party. However, given the report's own pattern (privileged setter, unprivileged victims, no timelock/consistency check), and that Kaia's own header-governance path already implements the missing consistency check, the absence of the same guard on the contract-governance path is a real, concretely reachable gap once contract governance is enabled (post-Kore, `GovParamContract` set).

### Recommendation
Apply the same `checkConsistency`-style validation (`lowerBoundBaseFee <= upperBoundBaseFee`) inside `contractGovModule.GetParamSet`/`GetPartialParamSet` (or in `ParamSet.SetFromMap`) before accepting contract-governance values, and/or enforce a minimum `relativeActivation` in `GovParam.setParamIn` comparable to the epoch-scale delay used by header governance, so KIP-71 bound changes cannot take effect faster than the network can safely adapt.

### Proof of Concept
1. Enable contract governance (Kore fork active, `governance.govparamcontract` set to a deployed `GovParam` contract), as exercised in the existing test harness: [8](#0-7) 
2. As the `GovParam` owner, call `setParamIn("kip71.lowerboundbasefee", true, <value greater than current upperboundbasefee>, 1)` so it activates within 1 block — no equivalent of `checkConsistency` blocks this, unlike the header-governance `governance_vote` path.
3. Once active, `GovModule.GetParamSet` returns a `ParamSet` with `LowerBoundBaseFee > UpperBoundBaseFee`.
4. `NextMagmaBlockBaseFee` (params/kip71_config.go) computes a base fee using these inconsistent bounds, and downstream consumers (`blockchain/tx_pool.go` fee-cap checks, `CNAPIBackend.LowerBoundGasPrice/UpperBoundGasPrice`) operate on values that violate the documented/tested invariant (`params/kip71_config_test.go` `TestEvenBaseFee`), which never occurs on the header-governance path due to its `checkConsistency` guard.

func (c *contractGovModule) GetParamSet(blockNum uint64) gov.ParamSet {
	m, err := c.contractGetAllParamsAt(blockNum)
	if err != nil {
		return *gov.GetDefaultGovernanceParamSet()
	}

	ret := *gov.GetDefaultGovernanceParamSet()
	for k, v := range m {
		err = ret.Set(k, v)
		if err != nil {
			return *gov.GetDefaultGovernanceParamSet()
		}
	}

	return ret
}

func (kc *KIP71Config) NextMagmaBlockBaseFee(parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) *big.Int {
	// governance parameters
	lowerBoundBaseFee := new(big.Int).SetUint64(kc.LowerBoundBaseFee)
	upperBoundBaseFee := new(big.Int).SetUint64(kc.UpperBoundBaseFee)
	makeEvenByCeil(lowerBoundBaseFee)
	makeEvenByFloor(upperBoundBaseFee)

	// If the parent is the magma disabled block or genesis, then return the lowerBoundBaseFee (default 25ston)
	if parentHeaderNumber.Cmp(new(big.Int).SetUint64(0)) == 0 || parentHeaderBaseFee == nil {
		return makeEvenByFloor(lowerBoundBaseFee)
	}

	var baseFeeDenominator *big.Int
	if kc.BaseFeeDenominator == 0 {
		// To avoid panic, set the fluctuation range small
		baseFeeDenominator = new(big.Int).SetUint64(64)
	} else {
		baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
	}
	gasTarget := kc.GasTarget
	upperGasLimit := kc.MaxBlockGasUsedForBaseFee

	// check the case of upper/lowerBoundBaseFee is updated by governance mechanism
	parentBaseFee := parentHeaderBaseFee
	if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
		parentBaseFee = upperBoundBaseFee
	} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
		parentBaseFee = lowerBoundBaseFee
	}

	// upper gas limit cut off the impulse of used gas to upper bound
	parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
	if parentGasUsed == gasTarget {
		return makeEvenByFloor(parentBaseFee)
	} else if parentGasUsed > gasTarget {
		// shortcut. If parentBaseFee is already reached upperbound, do not calculate.
		if parentBaseFee.Cmp(upperBoundBaseFee) == 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		// If the parent block used more gas than its target,
		// the baseFee of the next block should increase.
		// baseFeeDelta = max(1, parentBaseFee * (parentGasUsed - gasTarget) / gasTarget / baseFeeDenominator)
		gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := math.BigMax(x.Div(y, baseFeeDenominator), common.Big1)

		nextBaseFee := x.Add(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(upperBoundBaseFee) > 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	} else {
		// shortcut. If parentBaseFee is already reached lower bound, do not calculate.
		if parentBaseFee.Cmp(lowerBoundBaseFee) == 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		// Otherwise if the parent block used less gas than its target,
		// the baseFee of the next block should decrease.
		// baseFeeDelta = parentBaseFee * (gasTarget - parentGasUsed) / gasTarget / baseFeeDenominator
		gasUsedDelta := new(big.Int).SetUint64(gasTarget - parentGasUsed)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := x.Div(y, baseFeeDenominator)

		nextBaseFee := x.Sub(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(lowerBoundBaseFee) < 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	}
}

func (b *CNAPIBackend) UpperBoundGasPrice(ctx context.Context) *big.Int {
	bignum := b.CurrentBlock().Number()
	pset := b.cn.govModule.GetParamSet(bignum.Uint64() + 1)
	if b.cn.chainConfig.IsMagmaForkEnabled(bignum) {
		return new(big.Int).SetUint64(pset.UpperBoundBaseFee)
	} else {
		return new(big.Int).SetUint64(pset.UnitPrice)
	}
}
