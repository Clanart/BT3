### Title
Temp git-index copy silently widens exposure via `shutil.copy2`'s permission-preserving `copystat` - ([File: plugins/security-guidance/hooks/gitutil.py])

### Summary
`_temp_index` creates a temp file with `tempfile.mkstemp` (owner-only `0600` by default) but then calls `shutil.copy2(real_index, tmp_index)`, which invokes `copystat` and overwrites the destination's mode bits to match the source index file's mode. If the real `.git/index` has typical non-owner-only permissions (e.g. `0644`, the common result of `umask 022`), the temp copy ends up with the same `0644` mode inside the world-listable, shared `/tmp` directory, whereas the original index's real exposure was mitigated by parent-directory traversal restrictions (home/project/`.git` dirs not world-executable).

### Finding Description
In `_temp_index` (`plugins/security-guidance/hooks/gitutil.py`, lines 112-141):
```python
tmp_fd, tmp_index = tempfile.mkstemp(prefix="security_hook_idx_")
os.close(tmp_fd)
try:
    shutil.copy2(real_index, tmp_index)
    env = {**os.environ, "GIT_INDEX_FILE": tmp_index}
    ...
finally:
    os.unlink(tmp_index)
``` [1](#0-0) 

`tempfile.mkstemp` does create the file with `0600` permissions initially, contrary to the premise that it is "world-readable by default." However, `shutil.copy2` = `copy()` + `copystat()`, and `copystat()` copies the source file's mode bits onto the destination, **overwriting** the secure `0600` mode mkstemp set. If `real_index` (found via `_find_git_index`, `plugins/security-guidance/hooks/gitutil.py` lines 48-67) has the ordinary git-created mode (commonly `0644` under a standard `022` umask), `tmp_index` ends up `0644` too — group/other readable.

The file is placed in the shared system temp directory (typically `/tmp`, mode `1777`, world-listable), with a predictable, grep-able prefix (`security_hook_idx_`). An unprivileged local attacker with only read/list access to `/tmp` (per the stated precondition) can enumerate matching filenames and, if the copied mode is `0644`, read the file directly during the window between `copy2` and `os.unlink` — which spans at least one `git add --intent-to-add`/`git diff` subprocess call (up to the function's `timeout=10`/`30`).

The real risk is not "readable vs owner-only" per se, but **directory-based access control bypass**: the original index sits behind whatever traversal restrictions protect the user's home/project/`.git` directories (e.g. `700`/`750` home dirs common on multi-user or hardened systems). Copying it into globally-traversable `/tmp` strips that protection layer even though the file's own mode is merely "as loose as the source," not stricter than the source. On any host where the index file mode itself is non-owner-only (the common case), this is a real widening of practical exposure.

The staged-content risk is indirect: the index itself contains only staged file paths, modes, and blob SHAs (not raw content), but combined with existing repo-object read access it can reveal precisely which objects/paths are staged, and on shared-project setups (shared group ownership, CI runners, shared build boxes) that alone is disclosure of what's about to be committed.

No chmod/umask hardening is applied anywhere in this file or in `llm.py`'s temp-file handling, so nothing corrects the mode after `copy2`.

### Impact Explanation
Local information disclosure: an unprivileged co-resident user/process on the same host can, during the (bounded but non-trivial, up to ~10-30s per invocation, and re-occurring on essentially every diff/status call) window that `_temp_index` holds the temp copy open, read the copied index and learn the set of staged paths/blob-SHA metadata for a repo they otherwise could not traverse into. This is a real, if narrow, cross-user information-disclosure primitive scoped to metadata (paths, modes, blob hashes) rather than raw file bytes — the invariant "secrets stay secret" can be partially violated when combined with any other access the attacker has to the same object store (e.g. shared filesystem quirks, backup snapshots, or a later-committed identical blob).

### Likelihood Explanation
- Requires local unprivileged read/list access to `/tmp` — commonly available to any local user on multi-user systems.
- Requires the real `.git/index` to have non-owner-only permissions, which is the git/OS default under a typical `022` umask; only hardened `077`-umask environments avoid this.
- The predictable prefix (`security_hook_idx_`) makes enumeration trivial; no randomness is needed to *find* the file, only to read it, and read is gated by the (often non-restrictive) copied mode.
- Exploitation is repeatable on every `get_git_diff`/`_git_name_only(..., include_untracked=True)` call, i.e. very frequently during normal plugin operation (every UserPromptSubmit/Stop-hook diff), so the exposure window recurs continuously rather than being a one-off race.

### Recommendation
After `tempfile.mkstemp` (or immediately after `shutil.copy2`), explicitly re-assert a restrictive mode with `os.chmod(tmp_index, 0o600)` so the copy's permissions never depend on the source index's mode. Do this right after `shutil.copy2` and before the file is used/`GIT_INDEX_FILE` is set, closing the gap where `copystat` could loosen permissions.

### Proof of Concept
Integration test (pytest) plan:
1. Create a temp "repo" dir; write a fake `.git/index` file with mode `0o644` (`os.chmod(index_path, 0o644)`).
2. Monkeypatch `_find_git_index` to return that path (or run inside a real minimal git repo and `chmod 644 .git/index` explicitly to normalize across CI umasks).
3. Call `_temp_index(cwd)` as a context manager; inside the `with` block, `os.stat(tmp_index).st_mode & 0o777` and assert it is `<= 0o600` (i.e., strictly owner-only), matching or stricter than a secure baseline — this assertion should **fail** against the current implementation when the source index is `0o644`, demonstrating the divergence.
4. Additionally assert `tmp_index`'s directory is the platform temp dir (`tempfile.gettempdir()`) and that its basename matches the `security_hook_idx_*` glob, confirming enumerability.
5. As a fix verification, add `os.chmod(tmp_index, 0o600)` right after `shutil.copy2` in `_temp_index` and re-run the same test to confirm it now passes regardless of the source index's mode.

    tmp_fd, tmp_index = tempfile.mkstemp(prefix="security_hook_idx_")
    os.close(tmp_fd)
    try:
        shutil.copy2(real_index, tmp_index)
        env = {**os.environ, "GIT_INDEX_FILE": tmp_index}
        if untracked_paths is None:
            add_args = ["."]
        elif untracked_paths:
            # `git add -N -- a b nonexistent` is atomic — one missing path
            # makes it exit 128 and add NOTHING, so a file removed between
            # `git status` and here would silently drop ALL untracked files
            # from the diff. --ignore-missing only works with --dry-run, so
            # filter to surviving paths (lexists so dangling symlinks count).
            surviving = [p for p in untracked_paths
                         if os.path.lexists(os.path.join(cwd, p))]
            add_args = ["--"] + surviving if surviving else None
        else:
            add_args = None
        if add_args:
            subprocess.run(
                [*GIT_CMD, "add", "--intent-to-add"] + add_args,
                cwd=cwd, capture_output=True, text=True, timeout=10,
                env=env,
            )
        yield env
    finally:
        try:
            os.unlink(tmp_index)
        except OSError:
            pass
