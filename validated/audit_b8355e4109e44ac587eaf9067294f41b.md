### Title
FROST nonce reuse via never-invalidated CachedPreprocess enables secret share recovery - (File: coordinator/src/tributary/signing_protocol.rs)

### Summary
`SigningProtocol::preprocess_internal` stores a deterministic preprocess seed in `CachedPreprocesses` keyed only by `context`, and `share_internal` rebuilds a fresh `AlgorithmSignMachine` from that same cached seed on every invocation. The cache entry is written if absent and then read back, but it is never cleared after use. Any second call to `share_internal`/`preprocess_internal` for the same `context` regenerates identical FROST nonces, so signing two distinct messages (or two distinct signing sets, which changes the binding factors) reuses `d`/`e` — the classic FROST nonce-reuse failure that leaks the signer's secret share.

### Finding Description
In `preprocess_internal`, the flow is: if `CachedPreprocesses::get(txn, context)` is `None`, generate a preprocess via `AlgorithmMachine::preprocess(&mut OsRng)`, XOR-encrypt `machine.cache()` and store it; then unconditionally load the cached seed and construct the sign machine with `AlgorithmSignMachine::from_cache(algorithm, keys, CachedPreprocess(cached))` [1](#0-0) . There is no `CachedPreprocesses::del`/overwrite after the machine is consumed. `from_cache` deterministically regenerates the same `Vec<Nonce<C>>` from the seed [2](#0-1) , and `share_internal` calls `preprocess_internal` then `machine.sign(preprocesses, msg)` each time it is invoked [3](#0-2) . The library itself documents that cached preprocess reuse "will presumably cause the signer to leak their secret share" [4](#0-3) , and signing computes the nonce as `base + rho * actual` with `actual` derived from the reused seed [5](#0-4) .

### Impact Explanation
If `share_internal` is ever driven twice for the same `context` — e.g., a reboot/retry path, an RPC retry of the signing request, or two signing attempts that share the tributary context — the same `Nonce` pair is used in two signatures. With two shares `s1 = d + rho1*e + z1` and `s2 = d + rho2*e + z2` (binding factors `rho` differ whenever the message or participant set/commitments differ), the observer solves the 2x2 linear system for `d` and `e`, then recovers the secret share `x` from `s_i`. This is full threshold key-share compromise reachable purely by causing public messages to be signed.

### Likelihood Explanation
It requires the coordinator/processor to re-drive `share_internal` under the same context. The persistence layer explicitly supports recovery-after-reboot patterns (`self.signing.remove`, `warn!("not preprocessing ... if we didn't reboot")` in the sibling signer code), so a crash between `preprocess_internal` calls — or any duplicate delivery of the shares request — reuses the seed. The code takes care to encrypt the cache precisely because disclosure is fatal, but does nothing about the equally fatal reuse it documents as a MUST NOT [6](#0-5) .

### Recommendation
Delete (or rotate) the `CachedPreprocesses` entry as soon as it is consumed in `preprocess_internal` — e.g., overwrite with a tombstone or remove the key after decryption — so any repeated call for the same `context` generates a fresh seed via `preprocess(&mut OsRng)` rather than silently reusing nonces. Alternatively, bind the context to a monotonically increasing attempt counter and refuse to build a machine from an already-consumed cache entry.

### Proof of Concept
1. Drive `SigningProtocol::share_internal(participants, preprocesses_A, msg_A)` for context `C`. This stores `cache` under `C` and produces share `s_A` using nonces `(d, e)` regenerated from the stored seed.
2. Trigger a second `share_internal` (or any path calling `preprocess_internal` then `sign`) for the same `C` with `msg_B != msg_A` or a different signing set. `CachedPreprocesses::get` returns the same seed; `from_cache` yields identical `d, e` [7](#0-6) .
3. Collect the two broadcast `SignatureShare` values. Since `s_i = share_i(view)` embeds `d + rho_i * e` with publicly computable `rho_i` (rho transcript commits group_key, message, preprocesses) [8](#0-7) , solve for `d`, `e`, then the participant's interpolated secret share — compromising the threshold key.

  fn share_internal(
    &mut self,
    participants: &[<Ristretto as Ciphersuite>::G],
    mut serialized_preprocesses: HashMap<Participant, Vec<u8>>,
    msg: &[u8],
  ) -> Result<(AlgorithmSignatureMachine<Ristretto, Schnorrkel>, [u8; 32]), Participant> {
    let machine = self.preprocess_internal(participants).0;

    let mut participants = serialized_preprocesses.keys().copied().collect::<Vec<_>>();
    participants.sort();
    let mut preprocesses = HashMap::new();
    for participant in participants {
      preprocesses.insert(
        participant,
        machine
          .read_preprocess(&mut serialized_preprocesses.remove(&participant).unwrap().as_slice())
          .map_err(|_| participant)?,
      );
    }

    let (machine, share) = machine.sign(preprocesses, msg).map_err(|e| match e {
      FrostError::InternalError(e) => unreachable!("FrostError::InternalError {e}"),
      FrostError::InvalidParticipant(_, _) |
      FrostError::InvalidSigningSet(_) |
      FrostError::InvalidParticipantQuantity(_, _) |
      FrostError::DuplicatedParticipant(_) |
      FrostError::MissingParticipant(_) => unreachable!("{e:?}"),
      FrostError::InvalidPreprocess(p) | FrostError::InvalidShare(p) => p,
    })?;

    Ok((machine, share.serialize().try_into().unwrap()))
