### Title
Unchecked payment arithmetic permits signing a consensus-invalid Bitcoin transaction - ([File: networks/bitcoin/src/wallet/send.rs](networks/bitcoin/src/wallet/send.rs))

### Summary
`SignableTransaction::new` performs unchecked `u64` addition when comparing total inputs with `payment_sat + needed_fee` [1](#0-0) . A payment amount of `u64::MAX` wraps that sum to `needed_fee - 1` in release builds, allowing the insufficient-funds check to pass even though the transaction output is impossible under Bitcoin consensus.

### Finding Description
The constructor sums input and payment amounts with `sum::<u64>()`, then performs `payment_sat + needed_fee` without `checked_add` or `checked_sub` [2](#0-1) . It accepts the attacker-controlled payment amount into the output vector unchanged [3](#0-2) . The resulting transaction is subsequently sighashed and passed to each FROST input-signing machine [4](#0-3) .

### Impact Explanation
An attacker can cause a threshold signing round to produce signatures for a transaction that Bitcoin nodes will reject, consuming the signing attempt and any associated nonce material while yielding an unspendable result. In debug builds, the overflowing addition can instead panic, directly denying service.

### Likelihood Explanation
The attacker only needs to supply a payment amount of `u64::MAX` and a scanner-recognized input large enough to satisfy the wrapped comparison. The vulnerable path is `SignableTransaction::new` followed by `TransactionSignMachine::sign`, both reachable from transaction-construction data.

### Recommendation
Use checked arithmetic for `payment_sat`, `input_sat`, `payment_sat + needed_fee`, `payment_sat + fee_with_change`, `fee_per_vbyte * vbytes`, and `fee()`. Reject payment or output amounts that exceed Bitcoin’s monetary range and return `TransactionError` rather than panicking or wrapping.

### Proof of Concept
```rust
use bitcoin_serai::wallet::{Scanner, SignableTransaction};

let scanner = Scanner::new(group_key).unwrap();
let input = scanner.scan_transaction(&funding_tx).remove(0);
let script = input.output().script_pubkey.clone();

let signable = SignableTransaction::new(
  vec![input],
  &[(script, u64::MAX)],
  None,
  None,
  20,
)
.unwrap();
```

In a release build, `payment_sat + needed_fee` wraps below `input_sat`, so construction succeeds despite creating a `u64::MAX` output [5](#0-4) .
