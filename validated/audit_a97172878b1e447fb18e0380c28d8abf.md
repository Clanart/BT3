## Analysis

The GLP report's root bug class is: **a boundary/order mistake in a guard computation silently produces an incorrect (and exploitable) result instead of throwing or failing safe.** Searching Desktop's codebase for an analogous class of "boundary check computed incorrectly, guard silently passes when it shouldn't" turns up the repo-containment check used to gate which files Desktop will read from disk and forward to the Copilot API for conflict resolution. [1](#0-0) 

### Title
Repository-boundary check in `resolveWithin` uses a bare `startsWith` prefix comparison without a path-separator boundary, allowing conflicted-file paths to escape the repository - (File: `app/src/lib/path.ts`)

### Summary
`_resolveWithin` is the sole guard used by `buildConflictContext` (the Copilot-assisted merge-conflict resolver) to ensure a conflicted file's path stays inside the repository before its contents are read from disk and sent to the Copilot API. The containment check is `realResolved.startsWith(realRoot)`, which is a classic string-prefix bug: it does not verify that a path separator immediately follows `realRoot`. A sibling directory or path segment that merely starts with the same characters as the repository root (e.g. root `/Users/bob/repo` vs. resolved `/Users/bob/repo-secrets/config`) will incorrectly satisfy the guard.

### Finding Description
`resolveWithin`/`_resolveWithin` normalizes and `realpath`s both the repository root and the candidate path, then determines containment purely via `realResolved.startsWith(realRoot)`: [2](#0-1) 

This is called from `buildConflictContext` for every conflicted file path reported by git before the file is `stat`'d and `readFile`'d and its contents (conflict hunks) are sent to the Copilot backend: [3](#0-2) 

Because git tracks symbolic links as blobs (mode `120000`) whose target text is attacker-controlled content committed to the repository, a malicious/compromised repository can ship a conflicted file that is (or is nested inside) a symlink pointing outside the working directory, e.g. `../repo-secrets/id_rsa`. When Desktop's user resolves that conflict with the "Resolve with Copilot" feature, `resolveWithin` will `realpath` the symlink target to something like `/Users/bob/repo-secrets/id_rsa`. If `realRoot` is `/Users/bob/repo`, the check `'/Users/bob/repo-secrets/id_rsa'.startsWith('/Users/bob/repo')` evaluates to `true` even though `repo-secrets` is a sibling directory, not a subdirectory - the missing separator check (`realRoot + path.sep`) means the guard silently passes instead of rejecting the path, exactly mirroring the misplaced-divisor bug where a boundary/scaling term is applied in the wrong spot and the check no longer protects the invariant it was designed for.

### Impact Explanation
If the prefix bypass is triggered, Desktop will read a file that is outside the intended repository boundary and transmit its content to an external API (Copilot) as conflict-resolution context — this is unauthorized file read/exfiltration of data outside the repo, driven entirely by content in an attacker-supplied repository (a symlink target string), matching the "attacker controls a cloned/fetched repository ... result is ... file read outside the repo, credential/token exfiltration" impact class.

### Likelihood Explanation
Exploitation requires: (1) the attacker's repo contains a symlink-typed blob whose target string traverses to a sibling path that happens to share the root's string prefix, (2) that conflicting file participates in a merge/rebase/cherry-pick conflict, and (3) the victim uses the Copilot conflict-resolution feature on that conflict. Because directory-naming collisions (e.g., `repo` and `repo-backup`, `repo` and `repository`) are common on real filesystems, and the guard is purely textual rather than filesystem-boundary-aware, this is a realistic-not-hypothetical bypass path, though it does depend on victim-side directory layout rather than being universally exploitable.

### Recommendation
Change the containment check in `app/src/lib/path.ts` to require a trailing separator or exact equality, e.g.:
```ts
return realResolved === realRoot || realResolved.startsWith(realRoot + Path.sep)
  ? resolved
  : null
```
This mirrors the report's fix pattern of relocating the boundary term to where it actually enforces the intended invariant.

### Proof of Concept
1. Attacker creates a repo where a tracked file `link` is a symlink (git mode `120000`) with target `../victim-sibling/secret.txt`.
2. Attacker crafts two branches so `link` is edited differently on both sides, producing a merge conflict when the victim merges/rebases.
3. Victim, whose checkout path happens to share a prefix with an existing sibling directory (e.g. clones into `/Users/victim/project` while `/Users/victim/project-data` exists on disk), opens the conflict and invokes Copilot-assisted conflict resolution.
4. `buildConflictContext` calls `resolveWithin(workingDirectory, 'link')` at [4](#0-3) ; `_resolveWithin`'s `realpath` resolves the symlink to `/Users/victim/project-data/secret.txt`, and the `startsWith` check incorrectly passes.
5. Desktop reads `secret.txt` and includes its content in the payload sent to the Copilot API.
