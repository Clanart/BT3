### Title
Division-by-zero panic in `NextMagmaBlockBaseFee` when `kip71.gastarget` governance parameter is set to 0 - (File: params/kip71_config.go)

### Summary
`Kip71GasTarget` is registered with a `noopFormatChecker` in `kaiax/gov/param.go`, unlike its sibling `Kip71BaseFeeDenominator` which explicitly rejects zero (`v != 0`). This allows the governance system (header-vote/ratification or the on-chain `GovParam` contract) to set `GasTarget = 0`. `NextMagmaBlockBaseFee` in `params/kip71_config.go` then divides by `gasTarget` via `big.Int.Div`, which panics on division by zero, without any pre-check analogous to the existing `BaseFeeDenominator == 0` guard.

### Finding Description
`kaiax/gov/param.go` defines the governance parameter table. `Kip71BaseFeeDenominator` has a `FormatChecker` that requires `v != 0` [1](#0-0) , but `Kip71GasTarget` uses `noopFormatChecker`, accepting any `uint64` including `0` [2](#0-1) .

`NextMagmaBlockBaseFee` in `params/kip71_config.go` explicitly defends against `BaseFeeDenominator == 0` by substituting a fallback value [3](#0-2) , but performs no equivalent check for `gasTarget`. When `parentGasUsed != gasTarget`, the code computes `x.Div(x, new(big.Int).SetUint64(gasTarget))` in both the "above target" and "below target" branches [4](#0-3) [5](#0-4) . If `gasTarget == 0`, `big.Int.Div` panics (Go's `math/big` division by zero raises a runtime panic), just as ImageMagick's `ThumbnailImage()` divides by a zero dimension originating from unchecked geometry parsing.

This function is called on every block during base-fee verification/computation (`VerifyMagmaHeader` → `NextMagmaBlockBaseFee`, and in `feehistory.go`'s `processBlock`) [6](#0-5) [7](#0-6) , meaning once the parameter is ratified with value 0, every node computing/verifying the next block's base fee (which happens for effectively every block with `IsMagmaForkEnabled`) will panic, unless `parentGasUsed` happens to equal `0` exactly (which returns early and avoids the crash) [8](#0-7) .

### Impact Explanation
Once `GasTarget=0` is ratified (via header governance vote by the governing node, or via the `GovParam` contract's `setParam`/`setParamIn`, both of which are network-wide governance mechanisms explicitly in scope), any block whose parent used non-zero gas causes a deterministic panic in `NextMagmaBlockBaseFee` on every full node computing the base fee — a chain-halting Denial of Service, not merely a single-node crash. This is a severe, chain-wide safety/liveness issue.

### Likelihood Explanation
Exploitation requires a governance parameter to be set through the normal governance-vote or `GovParam`-contract path. This is not directly reachable by an arbitrary unprivileged transaction sender, but the parameter itself is validated with an insufficiently strict `FormatChecker` (`noopFormatChecker`) that fails to mirror the zero-check already applied to the sibling `BaseFeeDenominator` parameter — indicating a genuine validation gap rather than a hypothetical. Any governing node (single mode) or GC member (none mode), or the `GovParam` contract owner, could trigger it, intentionally or by misconfiguration/fat-finger.

### Recommendation
Add a `FormatChecker` for `Kip71GasTarget` rejecting `0`, mirroring `Kip71BaseFeeDenominator`'s check (`v != 0`) in `kaiax/gov/param.go`. Additionally, add a defensive `gasTarget == 0` fallback inside `NextMagmaBlockBaseFee` in `params/kip71_config.go`, symmetric to the existing `BaseFeeDenominator == 0` handling, so that malformed/legacy chain configs cannot trigger a panic.

### Proof of Concept
1. Governing node casts a vote (or `GovParam` contract owner calls `setParam`) setting `kip71.gastarget = 0`; this passes validation because `Kip71GasTarget`'s `FormatChecker` is `noopFormatChecker` [2](#0-1) .
2. Once ratified/activated, `ParamSet.GasTarget` becomes `0` for subsequent blocks.
3. On the next block after a Magma-enabled parent block with `GasUsed > 0`, `NextMagmaBlockBaseFee(parentNumber, parentBaseFee, parentGasUsed)` is invoked; since `parentGasUsed (>0) != gasTarget (0)`, it enters the `parentGasUsed > gasTarget` branch and executes `y := x.Div(x, new(big.Int).SetUint64(0))` [4](#0-3) , causing a runtime panic in every node that verifies or builds this block, halting the chain.
