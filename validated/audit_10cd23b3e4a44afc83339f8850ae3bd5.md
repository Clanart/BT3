## Finding

### Title
Attacker-controlled `WWW-Authenticate` header from a Git remote triggers unwarranted GitHub/Enterprise trust classification and OAuth sign-in flow - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
When Git needs credentials for an HTTP(S) remote, it forwards any `WWW-Authenticate` response headers it received from the *server* into the credential-helper protocol as `wwwauth[]` fields. GitHub Desktop's trampoline credential helper uses the content of these attacker-controlled headers as a "happy path" to decide whether an arbitrary remote host should be treated as a GitHub Enterprise endpoint, without any origin/hostname verification against a known GitHub domain.

### Finding Description
`getEndpointKind` in [1](#0-0)  classifies a credential request as `'enterprise'` purely because a `wwwauth[...]` value contains `realm="GitHub"`:

```
for (const [k, v] of cred.entries()) {
  if (k.startsWith('wwwauth[')) {
    if (v.includes('realm="GitHub"')) {
      return 'enterprise'
```

This header is not something Desktop generates — it comes straight from the HTTP response of whatever remote the user cloned or fetched from (`user@evil.example.com/repo.git`, a malicious proxy, a compromised self-hosted Git server, etc.), and is only "sanity-checked" via a substring match on a string the attacker fully controls.

Once classified as `'enterprise'`, `getCredential` in the same file [2](#0-1)  checks whether an existing `Account` already matches that endpoint; if not (the common case for a brand-new malicious host), it calls `ui.promptForGitHubSignIn(endpoint)`. That in turn invokes `TrampolineUIHelper.promptForGitHubSignIn` [3](#0-2) , which starts the full **Enterprise sign-in flow** (`dispatcher.beginEnterpriseSignIn` + `setSignInEndpoint(origin)`) against the attacker's own `origin`. The sign-in store then drives an OAuth authorization request via `getOAuthAuthorizationURL`/`requestOAuthToken` [4](#0-3)  targeted at that attacker-controlled endpoint, and on success persists a new `Account` bound to it via the account store/keychain.

The broken invariant is: **the trust decision "this host is a legitimate GitHub/Enterprise endpoint" is derived from unauthenticated, attacker-suppliable protocol data (a Git `WWW-Authenticate` header) rather than from a verified relationship to a known GitHub domain.** No existing guard revalidates this — `isDotCom`/`isGHE` checks happen only *before* the `wwwauth[]` branch and are false for an arbitrary attacker host, so the header is the deciding factor.

### Impact Explanation
An attacker who merely controls the HTTP responses of a Git remote (a repo the victim was told to clone, a malicious mirror/proxy, or a MITM'd HTTP git server) can cause GitHub Desktop to:
- Present the victim with what looks like a legitimate "Sign in to GitHub Enterprise" dialog for an arbitrary host, when in a normal generic-git-auth scenario the app would only show a lightweight, non-account-creating username/password prompt.
- Drive Desktop's OAuth machinery against that attacker-controlled endpoint and, on completion, silently create and store a persistent `Account` bound to that host.
- Once bound, `findGitHubTrampolineAccount` will subsequently treat any origin-matching remote as a trusted GitHub/Enterprise endpoint and auto-supply the stored token on future git operations without prompting, and other GitHub-only UI surfaces keyed on `Account` (PR/issue integrations, avatar/API calls) may begin trusting the attacker's endpoint as a first-party GitHub Enterprise install.

This matches the "unauthorized OAuth or account binding" impact category: a remote the attacker controls forces an elevated trust/account-binding flow that the user never consciously opted into for that host.

### Likelihood Explanation
Likelihood is realistic but requires the attacker to control (or proxy) the HTTP responses for a repository the victim clones/fetches — no local access, no prior malware, and no unnatural user steps beyond the ordinary "clone this repo" action are needed. Setting a spoofed `WWW-Authenticate: realm="GitHub"` header is trivial for any HTTP server the attacker operates, and Git will forward it verbatim to the credential helper on any authentication challenge.

### Recommendation
Do not use the `wwwauth[]` header content to elevate trust for a host. At minimum, cross-check the header hint against the actual `isGitHubHost(endpoint)` network-based detection (already implemented in `app/src/lib/api.ts`) before classifying an endpoint as `'enterprise'`, and require it to only shortcut the *positive* HEAD-request check, not replace it, and never allow header-derived classification alone to trigger the persistent OAuth sign-in/account-creation flow.

### Proof of Concept
1. Attacker stands up an HTTP git server at `https://evil.example/repo.git` and configures it to respond to unauthenticated requests with `WWW-Authenticate: realm="GitHub"`.
2. Victim clones/fetches `https://evil.example/repo.git` in GitHub Desktop.
3. Git invokes Desktop's credential helper trampoline; the `cred` map passed to `getCredential` contains `wwwauth[0]=Basic realm="GitHub"`.
4. `getEndpointKind` returns `'enterprise'` purely from that header match [5](#0-4) .
5. Since no `Account` exists for `evil.example`, `getCredential` calls `ui.promptForGitHubSignIn('https://evil.example')`, which starts the Enterprise OAuth sign-in flow and, on completion, persists an `Account` bound to `evil.example` in the accounts store/keychain [6](#0-5) .

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
