### Title
Empty aggregate signature (zero Rs, s = 0) verifies as valid for an empty signer set - ([File: crypto/schnorr/src/aggregate.rs](crypto/schnorr/src/aggregate.rs))

### Summary
Analogous to the scp client treating an empty/`.` filename as "the existing directory" and acting on it without validation, `SchnorrAggregate::verify` treats an empty signer set as a vacuously valid case: an aggregate signature with `Rs = []` and `s = 0` satisfies the verification equation over an empty `keys_and_challenges` slice. There is no rejection of the empty case, so a forged "signature by nobody" is accepted by any caller that reaches `verify` with an empty signer list.

### Finding Description
`SchnorrAggregate::read` accepts a length prefix of 0, producing `Rs = []` and then reads `s` freely, so `s = 0` is fully attacker-controlled serialized input. In `verify`, the loop over `keys_and_challenges` produces no `(z, R)` / `(z*c, key)` pairs when the slice is empty, leaving only the single pair `(-self.s, C::generator())`. The check `multiexp_vartime(&pairs).is_identity()` then reduces to `s·G == identity`, which holds for `s = 0`. The `Rs.len() != keys_and_challenges.len()` length check passes because both are zero. Result: `SchnorrAggregate { Rs: [], s: 0 }.verify(dst, &[])` returns `true` — a signature produced by no key is accepted for an empty key set, with the digest transcript never binding any challenge (the transcript contributes nothing when `keys_and_challenges` is empty). ### Impact Explanation
Any consumer that derives its signer set from attacker-influenced data (e.g., a validator/committee set resolved from the message or from empty participation) and calls `verify` will accept a completely forged aggregate signature. This is an incorrect verifier formula: the existential statement "for every signer i, s·G = Σ zᵢ·(Rᵢ + cᵢ·Aᵢ)" degenerates to `0·G == 0` with no signers bound, analogous to scp chmod'ing the current directory because the attacker-supplied empty filename resolved to `.`.

### Likelihood Explanation
Severity is bounded by callers that can pass an empty `keys_and_challenges` — e.g., a validator set lookup that returns an empty list for an unknown/removed set, or an aggregator layer that filters signers before verification. In-tree, `Validators::verify_aggregate` in `coordinator/tributary/src/tendermint/mod.rs` passes `signers` straight through after only an `Rs.len()` equality check, so any caller that reaches it with `signers = []` accepts `{Rs: [], s: 0}` unconditionally. [3](#0-2) 

### Recommendation
Reject `self.Rs.is_empty()` (or `keys_and_challenges.is_empty()`) at the top of `SchnorrAggregate::verify`, mirroring how `Curve::read_G` rejects identity points and `ThresholdParams::new` rejects zero parameters — an aggregate signature over zero signers is meaningless and should never verify. Optionally also reject `Rs.len() == 0` in `SchnorrAggregate::read`.

### Proof of Concept
```rust
use ciphersuite::Ciphersuite;
use schnorr::SchnorrAggregate;
use dalek_ff_group::Ristretto;

// Attacker-serialized bytes: u32 length = 0, then s = 0 (32 zero bytes for Ristretto scalar)
let mut bytes = vec![0u8; 4 + 32];
let agg = SchnorrAggregate::<Ristretto>::read(&mut bytes.as_slice()).unwrap();
// No signers, yet verification succeeds
assert!(agg.verify(b"any dst", &[]));
```

  pub fn verify(&self, dst: &'static [u8], keys_and_challenges: &[(C::G, C::F)]) -> bool {
    if self.Rs.len() != keys_and_challenges.len() {
      return false;
    }

    let mut digest = DigestTranscript::<C::H>::new(dst);
    digest.domain_separate(b"signatures");
    for (_, challenge) in keys_and_challenges {
      digest.append_message(b"challenge", challenge.to_repr());
    }

    let mut pairs = Vec::with_capacity((2 * keys_and_challenges.len()) + 1);
    for (i, (key, challenge)) in keys_and_challenges.iter().enumerate() {
      let z = weight(&mut digest);
      pairs.push((z, self.Rs[i]));
      pairs.push((z * challenge, *key));
    }
    pairs.push((-self.s, C::generator()));
    multiexp_vartime(&pairs).is_identity().into()
  }
