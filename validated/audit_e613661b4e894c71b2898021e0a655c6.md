### Title
Out-of-bounds buffer read in CLVM canonical-encoding scanner reachable from submitted spend-bundle solutions - (File: chia/full_node/mempool_manager.py)

### Summary
`is_clvm_canonical()` and its helper `is_atom_canonical()` scan a caller-supplied CLVM byte buffer (the serialized solution of a coin spend inside a submitted `SpendBundle`) to decide whether the buffer is eligible for mempool deduplication/fast-forward optimizations. [1](#0-0)  Neither function validates that the scan offset stays within the buffer bounds before indexing into it, mirroring the CVE-2017-16358 bug class (`string_scan_range()` reading past the end of an attacker-influenced buffer during a byte-by-byte scan).

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads `clvm_buffer[offset]` to determine the atom's length-prefix format, then loops `prefix_len` times incrementing `offset` and reading `clvm_buffer[offset]` again to build `atom_len`, with no check that `offset < len(clvm_buffer)` at any point in the loop: [2](#0-1) 

The caller, `is_clvm_canonical(clvm_buffer)`, walks the buffer token-by-token (`b = clvm_buffer[offset]`), and after determining an atom's declared length via `is_atom_canonical()`, advances `offset += atom_len` with no bound on `atom_len` relative to the remaining buffer size before continuing to loop and index again: [3](#0-2) 

Both functions trust the declared prefix/length encoding embedded in the buffer itself rather than validating it against the actual buffer length before each read — the same root-cause pattern as `string_scan_range()` in the referenced radare2 CVE, where a length/marker byte read from untrusted input drove further reads without confirming the buffer was long enough. Because `clvm_buffer` here originates from a spend's on-chain solution bytes, which are fully attacker-controlled at submission time, a malformed/truncated buffer (e.g., a length-prefix byte claiming several trailing bytes that don't exist, or an atom `offset` that lands exactly at the end of the buffer) drives `clvm_buffer[offset]` past the end of the buffer.

### Impact Explanation
In this Python codebase, indexing `bytes` past its length raises an `IndexError` rather than a memory-safety violation as in the original C target, so the direct-memory-disclosure impact of the original CVE does not translate. The reachable consequence here is an unhandled exception thrown from mempool eligibility processing while evaluating a submitted spend bundle's solution for dedup/fast-forward eligibility — a spend-triggered exception during mempool item construction, which can disrupt processing of the offending spend bundle (and potentially other pending items sharing the same processing pass) rather than being cleanly rejected as an ordinary invalid-spend error.

### Likelihood Explanation
Any unprivileged party that can submit a spend bundle to the mempool controls the solution bytes of their coin spends and can therefore craft a truncated or malformed canonical-encoding sequence to hit this code path, assuming it is exercised during normal dedup/fast-forward eligibility checks on submission. I was not able to fully confirm, within the available search budget, the exact call site that invokes `is_clvm_canonical()` on spend-bundle solution data or whether an enclosing `try/except` already converts this into a handled validation error before it can affect mempool availability — this should be verified directly in `chia/full_node/mempool_manager.py`'s eligibility-check code path before treating this as high-confidence exploitable DoS.

### Recommendation
Add explicit bounds checks in both `is_atom_canonical()` and `is_clvm_canonical()` before every buffer index/slice: verify `offset < len(clvm_buffer)` prior to reading the marker byte, verify enough bytes remain for the declared `prefix_len`, and verify `atom_len` does not extend past the end of the buffer before advancing `offset`. Raise a well-defined validation error (not an implicit `IndexError`) so any call site can treat malformed input as an ordinary invalid-spend/ineligibility condition rather than an unexpected exception.

### Proof of Concept
Construct a coin spend whose solution buffer ends immediately after a multi-byte atom length-prefix marker, e.g. a single byte `0xC0` (indicating a 5+8 bit length prefix, `prefix_len = 1`) with no following byte. Submitting a `SpendBundle` containing this coin spend and having it reach the mempool's canonical-encoding eligibility check causes `is_atom_canonical()` to execute `clvm_buffer[offset]` at an `offset` equal to `len(clvm_buffer)`, raising `IndexError`. def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value

def is_clvm_canonical(clvm_buffer: bytes) -> bool:

    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
