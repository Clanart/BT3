### Title
Unbounded `tier`/`months` in `BandwidthManager.purchase()` allows irrecoverable loss of the buyer's fee-token payment - ([File: evm/src/apps/BandwidthManager.sol])

### Summary
`BandwidthManager.purchase()` on EVM only checks `months == 0` / empty `app`/`chain` before pulling the fee token and dispatching a non-timeout (`timeout: 0`) ISMP POST to `pallet-bandwidth`. Both `tier` and `months` are `uint256` on the Solidity side but are decoded as `u32` on the Hyperbridge pallet side (`modules/pallets/bandwidth/src/abi.rs`). A caller who supplies a `tier` or `months` value greater than `u32::MAX` passes every Solidity-side check, has the fee token pulled, and dispatches the message — but the pallet's `PurchaseMessage::try_from` decode fails, `on_accept` returns an `Err`, no subscription is ever credited, and because the message was dispatched with `timeout: 0` there is no timeout/refund path (`on_timeout` in `pallet-bandwidth` unconditionally errors with "purchases are non-timeouting"). The already-pulled fee tokens remain stuck in the `BandwidthManager` contract with no user-facing recovery mechanism.

### Finding Description
`purchase()` validates only:
```solidity
if (app.length == 0 || chain.length == 0 || months == 0) revert InvalidPurchase();
``` [1](#0-0) 

Neither `tier` nor `months` is bounded to the value range the destination pallet can actually decode. On the pallet side, both fields are narrowed to `u32`, and any overflow becomes a hard error, not a saturating clamp:
```rust
let tier: u32 = abi.tier.try_into().map_err(|_| anyhow::anyhow!("tier exceeds u32"))?;
let months: u32 = abi.months.try_into().map_err(|_| anyhow::anyhow!("months exceeds u32"))?;
``` [2](#0-1) 

Once decode fails, `Pallet::on_accept` never runs the credit logic — it returns before touching `Allowance` storage: [3](#0-2) 

Crucially, the purchase message is dispatched with `timeout: 0`, and `pallet-bandwidth`'s `on_timeout` implementation makes clear this path is deliberately unsupported/fatal, not a refund mechanism:
```rust
/// Purchases dispatch with `timeout = 0`. If `on_timeout` ever
/// fires it's an invariant violation, not a noop.
fn on_timeout(&self, _timeout: Request) -> Result<Weight, anyhow::Error> {
    Err(anyhow::anyhow!("pallet-bandwidth purchases are non-timeouting"))
}
``` [4](#0-3) 

Meanwhile, on the Solidity side, `IERC20(feeToken).safeTransferFrom(msg.sender, address(this), amount)` already executed unconditionally before the dispatch, and the only path that ever moves tokens back out of `BandwidthManager` is the admin/governance-triggered `Withdraw` action decoded in `onAccept`, which sends funds to whatever `beneficiary` governance specifies — not automatically back to the original payer: [5](#0-4) 

This is the same broken-invariant class as the seed report: an externally-controlled numeric input (`_newScanPeriod`/`cliff`/`vestingPeriod` in the report; `tier`/`months` here) is accepted by an entry point without validating it against the bound actually enforced later in the pipeline, so an out-of-range value causes an irrevocable action (fee pull + non-timeout dispatch) to silently fail and strand funds.

### Impact Explanation
The impact is direct loss/lock of the fee token pulled from the caller — the amount is transferred out of the caller's wallet and into `BandwidthManager`, but the credit that was supposed to be minted on Hyperbridge never lands, and the non-timeout design (`timeout: 0`, `on_timeout` fatal) removes the only self-service recovery path that other ISMP flows rely on. Recovery is possible only if governance later notices and issues a `dispatch_withdraw`/`Withdraw` message — and even then, funds land wherever governance points them, not necessarily back to the original buyer. This matches the bounty's "loss of funds" and "false state acceptance"-adjacent class (the destination silently drops a paid-for state transition with no compensating control), reachable directly by any unprivileged caller of `purchase()`.

### Likelihood Explanation
Likelihood is low-to-moderate: it requires a caller (attacker against themselves, or against a third party who is tricked into calling `purchase` with an oversized `months`/`tier` via a malicious frontend/integration) to pass a value above `u32::MAX` (4,294,967,295) for `tier` or `months`. Since these are plain `uint256` function parameters with no UI-level bound, and the only Solidity guard is `months == 0`, nothing stops an integrator's bug, a malicious dApp front-end, or user error from producing such a value — this does not require a compromised relayer, prover, or governance actor, only a normal unprivileged transaction to the public `purchase()` entry point.

### Recommendation
Bound `tier` and `months` in `purchase()` to values guaranteed to decode on the destination pallet, e.g.:
```solidity
if (tier > type(uint32).max || months > type(uint32).max) revert InvalidPurchase();
```
Alternatively/additionally, mirror the pallet's `u32` domain explicitly by typing `tier`/`months` as `uint32` in the Solidity function signature and the `BandwidthPurchaseMsg` struct, so the ABI itself enforces the bound and a malformed call reverts before any token transfer occurs. Independently, consider giving `pallet-bandwidth` a supported refund/timeout path (or an explicit `RefundOnDecodeFailure` governance action) so payer funds are not solely recoverable at governance's discretion when a message is otherwise well-formed but semantically out of range.

### Proof of Concept
1. Governance configures a tier, e.g. `TierIndex::TierOne` with `bytes = 10_000_000`, `duration_secs = 2_592_000`, and sets its EVM-side price via `dispatch_set_tiers`.
2. An attacker (or a naive integrator) calls:
```solidity
manager.purchase(
    abi.encodePacked(appAddr),
    1,                       // valid tier, or an out-of-range one
    4294967296,              // months = u32::MAX + 1
    bytes("EVM-8453")
);
```
3. `purchase()` passes `months == 0` check (false), computes `total18d = price18d * 4294967296` (no Solidity overflow for typical small tier prices), pulls that amount of fee token from `msg.sender` into `BandwidthManager`, and dispatches the ISMP POST with `timeout: 0, fee: 0`. [6](#0-5) 
4. On Hyperbridge, `Pallet::on_accept` calls `PurchaseMessage::try_from(request.body)`, which fails at `abi.months.try_into::<u32>()` with `"months exceeds u32"`, so the function returns `Err` before any `Allowance` storage is touched. [7](#0-6) 
5. No subscription is credited on Hyperbridge; because `timeout: 0` was used and `on_timeout` is fatal by design, no timeout-refund flow ever fires. [8](#0-7) 
6. The fee tokens pulled in step 3 remain in `BandwidthManager`'s balance indefinitely, recoverable only via a governance-initiated `dispatch_withdraw` to a `beneficiary` chosen by governance — not automatically returned to the caller.

Note: I was unable to fully trace the generic ISMP request-processing dispatcher's handling of a failed `on_accept` (whether the request commitment is marked processed/finalized or left pending) since that code path in `modules/ismp/state-machines/substrate/src/lib.rs` was not retrievable within the available context; this does not change the core finding that no refund path exists on the EVM side regardless of how the failure is recorded on Hyperbridge.

        external
        returns (bytes32 commitment)

        if (app.length == 0 || chain.length == 0 || months == 0) revert InvalidPurchase();
        uint256 price18d = tierPrice[tier];
        if (price18d == 0) revert UnknownTier();

        uint256 total18d = price18d * months;
        address feeToken = IDispatcher(_host).feeToken();
        uint8 dec = IERC20Metadata(feeToken).decimals();
        uint256 scale = 10 ** (18 - dec);
        if (total18d % scale != 0) revert PriceNotRepresentable();
        uint256 amount = total18d / scale;

        IERC20(feeToken).safeTransferFrom(msg.sender, address(this), amount);

        BandwidthPurchaseMsg memory body = BandwidthPurchaseMsg({
            app: app,
            tier: tier,
            months: months,
            chain: chain
        });

            DispatchPost({

                to: PALLET_BANDWIDTH_MODULE_ID,
                body: abi.encode(body),
                timeout: 0,
                fee: 0,

            })

    /// @notice Inbound governance from `pallet-bandwidth`. The first
    /// body byte selects `OnAcceptActions`; the remainder is the
    /// action's ABI-encoded payload.
    /// @dev Only the configured host may invoke (`onlyHost`); the
    /// request's `source` must additionally equal hyperbridge.
    function onAccept(IncomingPostRequest calldata incoming) external override onlyHost {
        PostRequest calldata request = incoming.request;

        if (!request.source.equals(IDispatcher(_host).hyperbridge())) revert UnauthorizedAction();

        OnAcceptActions action = OnAcceptActions(uint8(request.body[0]));
        if (action == OnAcceptActions.SetTiers) {
            Tier[] memory updates = abi.decode(request.body[1:], (Tier[]));
            for (uint256 i = 0; i < updates.length; i++) {
                tierPrice[updates[i].tier] = updates[i].price;
                emit TierSet(updates[i].tier, updates[i].price);
            }
        } else if (action == OnAcceptActions.Withdraw) {
            Withdrawal memory w = abi.decode(request.body[1:], (Withdrawal));
            if (w.token != address(0)) {
                IERC20(w.token).safeTransfer(w.beneficiary, w.amount);
            } else {
                (bool sent,) = w.beneficiary.call{value: w.amount}("");
                if (!sent) revert InsufficientNativeToken();
            }
            emit Withdrawn(w.token, w.beneficiary, w.amount);
        } else {
            revert UnauthorizedAction();
        }
    }

impl TryFrom<&[u8]> for PurchaseMessage {
	type Error = anyhow::Error;

	fn try_from(body: &[u8]) -> Result<Self, Self::Error> {
		let abi = BandwidthPurchaseMsg::abi_decode(body)
			.map_err(|err| anyhow::anyhow!(format!("invalid bandwidth purchase ABI: {err:?}")))?;

		let tier: u32 = abi.tier.try_into().map_err(|_| anyhow::anyhow!("tier exceeds u32"))?;
		let months: u32 =
			abi.months.try_into().map_err(|_| anyhow::anyhow!("months exceeds u32"))?;
		if months == 0 {
			return Err(anyhow::anyhow!("months must be >= 1"));
		}
		let chain_str = str::from_utf8(&abi.chain)
			.map_err(|err| anyhow::anyhow!(format!("chain is not utf-8: {err}")))?;
		let chain = StateMachine::from_str(chain_str)
			.map_err(|err| anyhow::anyhow!(format!("invalid chain {chain_str:?}: {err}")))?;

		Ok(PurchaseMessage { app: abi.app.into(), tier, months, chain })
	}

		fn on_accept(&self, request: PostRequest) -> Result<Weight, anyhow::Error> {
			let manager = BandwidthManager::<T>::get(&request.source).ok_or_else(|| {
				anyhow::anyhow!(format!("no bandwidth manager registered for {:?}", request.source))
			})?;

			if request.from != manager.0.to_vec() {
				return Err(anyhow::anyhow!(format!(
					"purchase from unauthorised sender on {:?}: expected {:x?}, got {:x?}",
					request.source, manager.0, request.from
				)));
			}

			let msg = PurchaseMessage::try_from(request.body.as_slice())?;
			let tier = TierIndex::try_from(msg.tier)
				.map_err(|_| anyhow::anyhow!(format!("unknown tier discriminant {}", msg.tier)))?;
			let cfg = Tiers::<T>::get(tier)
				.ok_or_else(|| anyhow::anyhow!(format!("tier {:?} is not configured", tier)))?;

			let bytes = cfg.bytes.saturating_mul(msg.months as u128);
			let duration = cfg.duration_secs.saturating_mul(msg.months as u64);

			let key = AppKey::truncate_from(msg.app);
			let expires_at = Self::push_subscription(&msg.chain, &key, tier, bytes, duration);

			Self::deposit_event(Event::BandwidthCredited {
				app_chain: msg.chain,
				app: key,
				paid_from: request.source,
				tier,
				bytes,
				expires_at,
			});

			Ok(Weight::zero())
		}
