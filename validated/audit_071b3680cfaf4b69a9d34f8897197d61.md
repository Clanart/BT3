## Title
Concurrent index mutation race between commit-message generation and manual staging can silently corrupt what the user commits - ([File: app/src/lib/git/diff.ts])

### Summary
`getFilesDiffText` (used by `_generateCommitMessage` to build the diff sent to Copilot) directly mutates the shared Git index — `unstageAll()`, `stageFiles(files)`, run `git diff --staged`, then `unstageAll()` again — with no locking against other index-mutating operations in the same repository. [1](#0-0) 

### Finding Description
`_generateCommitMessage` is guarded only by `withIsGeneratingCommitMessage`, which just prevents two *generation* calls from overlapping; it does not go through `gitStore.performFailableOperation`, which is the mechanism used to serialize git-mutating operations (commit, push, pull, rebase, etc.) per repository. [2](#0-1) [3](#0-2) 

Meanwhile `_commitIncludedChanges` snapshots the currently selected working-directory files synchronously, then invokes `createCommit`, which internally calls `stageFiles` again to build the index right before committing. [4](#0-3) [5](#0-4) 

Because both `getFilesDiffText` and `stageFiles`/`createCommit` operate on the *same on-disk index* for the *same repository* and are not mutually exclusive (`performFailableOperation` only serializes calls that go through it; `_generateCommitMessage` bypasses it), a commit-message-generation request that races with a commit (or with `_finishConflictedMerge`, `continueRebase`, `continueCherryPick`, `getResolutionDiff`, all of which also call `stageFiles`/`unstageAll` outside of a single funnel) can interleave: e.g. `unstageAll()` from the diff-generation path clears the index right as `createCommit`'s own `stageFiles` call is populating it, or vice versa, resulting in the wrong set of files (or a partially staged state) being what actually gets committed via `git commit`. The invariant broken is: "the index used to build the diff shown to Copilot/the user must not be the same index concurrently mutated by an actual commit operation" — this mirrors the erigon peerstore bug where two independent code paths mutated the same underlying shared state without a common serialization primitive.

### Impact Explanation
If the interleaving lands such that `createCommit`'s internal `stageFiles` call is undone by a concurrent `unstageAll()` from `getFilesDiffText`, the commit can capture an unintended/incomplete file set (silent corruption of what the user commits), matching the "silent corruption of what the user commits or pushes" impact category. This is triggerable purely through normal UI interaction sequencing (clicking "Generate Commit Message with Copilot" and "Commit" close together), no elevated privileges or local/physical access required.

### Likelihood Explanation
Likelihood is speculative/unconfirmed rather than demonstrated: the JS/TS single-threaded event loop means the two async operations are never running literal machine instructions simultaneously, but git subprocess invocations (`git update-index`, `git diff`) are asynchronous and can interleave at the process level once control yields on `await`. I was not able to trace a synchronous reproduction path that proves the race actually manifests (e.g. confirming there is no other implicit lock I missed, or that `performFailableOperation` doesn't also wrap `_generateCommitMessage` indirectly). This would need to be validated by running the two flows concurrently against a real repository and observing actual index corruption, which requires execution the available tools/index search cannot perform.

### Recommendation
Route `getFilesDiffText` (and other ad-hoc `stageFiles`/`unstageAll` callers like `getResolutionDiff`, rebase/cherry-pick continuation) through the same `gitStore.performFailableOperation` queue used for commit/push/pull so that all index-mutating operations for a given repository are strictly serialized, eliminating the possibility of interleaved `stageFiles`/`unstageAll` calls from unrelated features.

### Proof of Concept
Not executable from static analysis alone — this would require: (1) opening a repo with pending changes, (2) triggering "Generate Commit Message with Copilot" (kicks off `getFilesDiffText`'s `unstageAll`→`stageFiles`→`git diff`→`unstageAll` sequence), and, while that's in flight, (3) triggering a commit, and observing whether the resulting commit's file set diverges from what the UI displayed as selected. I could not verify actual reproduction; this is a structural/code-level concern based on the absence of shared locking between the two code paths.

export async function getFilesDiffText(
  repository: Repository,
  files: ReadonlyArray<WorkingDirectoryFileChange>,
  commitish?: string
): Promise<string> {
  // Clear the staging area, our diffs reflect the difference between the
  // working directory and the last commit (if any) so our commits should
  // do the same thing.
  await unstageAll(repository)

  await stageFiles(repository, files)

  // `--no-ext-diff` should be provided wherever we invoke `git diff` so that any
  // diff.external program configured by the user is ignored
  const args = [
    'diff',
    '--no-ext-diff',
    '--patch-with-raw',
    '--no-color',
    '--staged',
    ...(commitish ? [commitish] : []),
  ]
  const successExitCodes = new Set([0])

  const { stdout } = await git(args, repository.path, 'getFilesDiffText', {
    successExitCodes,
    encoding: 'buffer',
  })

  await unstageAll(repository)

  private async withIsGeneratingCommitMessage(
    repository: Repository,
    fn: (signal: AbortSignal) => Promise<boolean>
  ): Promise<boolean> {
    const state = this.repositoryStateCache.get(repository)
    // ensure the user doesn't try and commit again
    if (state.isGeneratingCommitMessage) {
      return false
    }

    const abortController = new AbortController()

    this.repositoryStateCache.update(repository, () => ({
      isGeneratingCommitMessage: true,
      commitMessageGenerationAbortController: abortController,
    }))
    this.emitUpdate()

    try {
      return await fn(abortController.signal)
    } finally {
      const currentState = this.repositoryStateCache.get(repository)
      if (
        currentState.commitMessageGenerationAbortController === abortController
      ) {
        this.repositoryStateCache.update(repository, () => ({
          isGeneratingCommitMessage: false,
          commitMessageGenerationAbortController: null,
        }))
        this.emitUpdate()
      }
    }
  }

export async function stageFiles(
  repository: Repository,
  files: ReadonlyArray<WorkingDirectoryFileChange>
): Promise<void> {
  const normal = []
  const oldRenamed = []
  const partial = []
  const deletedFiles = []

  for (const file of files) {
    if (file.selection.getSelectionType() === DiffSelectionType.All) {
      normal.push(file.path)
      if (file.status.kind === AppFileStatusKind.Renamed) {
        oldRenamed.push(file.status.oldPath)
      } else if (file.status.kind === AppFileStatusKind.Deleted) {
        deletedFiles.push(file.path)
      }
    } else {
      partial.push(file)
    }
  }
