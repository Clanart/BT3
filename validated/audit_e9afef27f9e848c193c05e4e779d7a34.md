### Title
Self-payments to the vault's own scanned scripts are accepted and re-reported as fresh deposits, letting a withdrawal "pay" the vault itself — ([File: networks/bitcoin/src/wallet/send.rs])

### Summary
The reported bug class is a missing "payer != payee" check: the wAlgo vault required the burn fee/principal to be paid to the minter, but accepted a transfer *from the minter to itself*, making the payment check vacuous. The analog in Serai's Bitcoin wallet code is that `SignableTransaction::new` performs no check that a payment's `script_pubkey` is distinct from the multisig's own scanner-registered scripts, and `Scanner::scan_transaction` reports *any* output paying a registered script as a `ReceivedOutput` — with no notion of direction or of the output belonging to a spend the multisig itself constructed. A withdrawal that pays the vault's own external (or branch/forward) address therefore simultaneously (a) satisfies the payment side of the transaction and (b) produces an output that the scanner will re-report as a new inbound deposit once confirmed.

### Finding Description
`SignableTransaction::new` validates only dust, data length, fee, and solvency. It never compares `payments[i].0` against the scripts the `Scanner` watches, so a payment whose `script_pubkey` equals `p2tr_script_buf(group_key)` (offset 0) or any registered `hash_to_F(KEY_DST, b"branch"|"change"|"forward")`-offset script is accepted and signed [1](#0-0) .

On the receive side, `Scanner::scan_transaction` matches purely on `output.script_pubkey` membership in `self.scripts` and unconditionally emits a `ReceivedOutput` credited with that script's offset [2](#0-1) . There is no check that the spending transaction wasn't authored by the multisig, nor that the output isn't simply the multisig paying itself. The deterministic offset derivation (`Secp256k1::hash_to_F(KEY_DST, b"...")`) means every registered script — external, branch, change, forward — is publicly computable by any unprivileged party from the group key alone [3](#0-2) .

This mirrors the minter self-transfer exactly: the "payment" leg of an operation is vacuously satisfied because the payer and payee are the same entity, and the accounting layer (the scanner) cannot tell the difference, crediting the self-sent output as a fresh receipt.

### Impact Explanation
If a withdrawal (or any scheduler-built `SignableTransaction`) directs funds to one of the multisig's own scanned scripts, the multisig is debited on the orchestration layer while the Bitcoin never leaves its control, and the resulting output is later scanned and reported as a brand-new inbound output. Depending on how the out-of-scope processor layer consumes `get_outputs`, this yields either a double-credit (withdrawal honored *and* the same value re-deposited, enabling repeated draining) or at minimum funds counted as received without any corresponding external inflow. Note: whether the processor layer credits an `External`-kind output with empty `data` could not be verified — `processor/` is outside the indexed scope of this review — so the credit-theft leg is partially unverified; the wallet-layer absence of the check itself is confirmed.

### Likelihood Explanation
An unprivileged user who can request a withdrawal to an arbitrary Bitcoin address can supply the vault's own external address (derivable from the public group key) or any of the deterministic branch/change/forward addresses. No cryptographic break, collusion, or validator misbehavior is required — only a destination address the wallet layer fails to reject. Likelihood therefore hinges solely on whether upstream code filters self-addressed payments; the wallet crate itself offers no such defense.

### Recommendation
- In `SignableTransaction::new`, reject payments whose `script_pubkey` equals the change script or any script the owning `Scanner` would match (or require callers to pass the scanner/registered script set for this check).
- In `Scanner::scan_transaction` / `get_outputs`, classify outputs of transactions that spend already-tracked `ReceivedOutput`s, or otherwise mark self-spend outputs so they are not re-emitted as new deposits.

### Proof of Concept
1. Compute the vault's external script: `p2tr_script_buf(group_key)` (offset `Scalar::ZERO`, pre-registered in `Scanner::new` at `networks/bitcoin/src/wallet/mod.rs:164`).
2. Request/construct `SignableTransaction::new(inputs, &[(own_external_script, amount)], change, None, fee)` — it returns `Ok`, since no self-payment check exists (`send.rs:150-256`).
3. Threshold-sign and broadcast. When the transaction confirms, `scan_transaction` matches the payment output's script against `self.scripts` and emits a `ReceivedOutput { offset: Scalar::ZERO, ... }` (`mod.rs:205-210`), which `get_outputs` classifies as `OutputType::External` — indistinguishable from a genuine new deposit (`processor/src/networks/bitcoin.rs:686-700`). The vault has been "paid" by itself, exactly as the minter was "paid" by itself in the original report.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

const KEY_DST: &[u8] = b"Serai Bitcoin Output Offset";
static BRANCH_OFFSET: OnceLock<Scalar> = OnceLock::new();
static CHANGE_OFFSET: OnceLock<Scalar> = OnceLock::new();
static FORWARD_OFFSET: OnceLock<Scalar> = OnceLock::new();

// Always construct the full scanner in order to ensure there's no collisions
fn scanner(
  key: ProjectivePoint,
) -> (Scanner, HashMap<OutputType, Scalar>, HashMap<Vec<u8>, OutputType>) {
  let mut scanner = Scanner::new(key).unwrap();
  let mut offsets = HashMap::from([(OutputType::External, Scalar::ZERO)]);

  let zero = Scalar::ZERO.to_repr();
  let zero_ref: &[u8] = zero.as_ref();
  let mut kinds = HashMap::from([(zero_ref.to_vec(), OutputType::External)]);

  let mut register = |kind, offset| {
    let offset = scanner.register_offset(offset).expect("offset collision");
    offsets.insert(kind, offset);

    let offset = offset.to_repr();
    let offset_ref: &[u8] = offset.as_ref();
    kinds.insert(offset_ref.to_vec(), kind);
  };

  register(
    OutputType::Branch,
    *BRANCH_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"branch")),
  );
  register(
    OutputType::Change,
    *CHANGE_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"change")),
  );
  register(
    OutputType::Forwarded,
    *FORWARD_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"forward")),
  );
