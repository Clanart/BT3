### Title
Global (not per-sender) gasless bundle-tx queue cap can be exhausted by cheap fake gasless transactions, blocking legitimate gasless users - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The `gasless` kaiax module admits `GaslessApproveTx`/`GaslessSwapTx` into a shared, module-wide counter (`knownTxs`) with a single global cap (`MaxBundleTxsInQueue`, default 200), enforced in `PreAddTx` before the transaction's actual balance/allowance is validated. Because the format check for `IsApproveTx`/`IsSwapTx` only requires calling the correct whitelisted token/router address with the right selector/argument shape — not real balances — any unprivileged sender can cheaply craft transactions that pass the format check and consume the shared queue capacity, exhausting it and reverting legitimate users' `GaslessApproveTx`/`GaslessSwapTx` submissions with `ErrBundleTxQueueFull`. This mirrors the reported OpenQ bug class: a fixed-size, unauthenticated shared resource ("token address list" there, "gasless bundle-tx queue slots" here) that can be pre-filled by any calling party to block legitimate use of the feature.

### Finding Description
`PreAddTx` is the txpool admission hook for gasless bundle transactions: [1](#0-0) 

It checks `g.IsBundleTx(tx)` (i.e., `IsApproveTx(tx) || IsSwapTx(tx)`) and, if the *global* `knownTxs.numQueue()` count is below `MaxBundleTxsInQueue`, immediately adds the tx to the shared `knownTxs` map with `TxStatusQueue`, incrementing the count for **all senders combined** — there is no per-account limiting analogous to the txpool's own `NonExecSlotsAccount`/`ExecSlotsAccount` fairness mechanism used for ordinary transactions.

`IsApproveTx`/`IsSwapTx` only require: `tx.to` is a whitelisted ERC20 token / the whitelisted swap router, correct 4-byte selector and ABI-decodable arguments, and (for approve) `amount == MaxUint256`: [2](#0-1) 

Critically, this classification is purely syntactic/whitelist-based and does not check the sender's real token balance, allowance, or ability to actually execute the swap — those checks (`checkBalanceForApprove`/`checkBalanceForSwap`, exposed via `GetCheckBalance`) are performed later, and `PreAddTx` runs *before* `validateTx` in the pool's `add()` flow: [3](#0-2) 

So an attacker only needs: (a) minimal gas to submit legacy-type transactions targeting the whitelisted token address with `approve(router, MaxUint256)`, or targeting the whitelisted router with `swapForGas(...)` args that decode correctly — no real token holdings are required to pass `IsBundleTx`/`IsApproveTx`/`IsSwapTx` and thus reserve a queue slot. Filling `numQueue()` up to `MaxBundleTxsInQueue` (default 200, configurable via `MaxBundleTxsInQueueFlag`) causes subsequent legitimate `PreAddTx` calls to return `ErrBundleTxQueueFull`: [4](#0-3) [5](#0-4) 

This is analogous to the reported bug: a shared, size-limited admission list (bounty's fixed token-address array in the original report; here the gasless bundle-tx queue slot count) can be filled by an unprivileged party with cheap, non-genuine entries, causing legitimate participants' transactions to be rejected once the cap is reached.

### Impact Explanation
This blocks the KIP-247 gasless transaction feature network-wide (or at least at the affected node/proposer) for as long as the attacker keeps refilling the queue with cheap fake approve/swap-shaped transactions, denying real users the ability to get gas lent by the proposer and preventing gasless swap settlement. Since gasless swap involves proposer-funded `LendTxGenerator` transactions and repayment flows, blocking admission also indirectly affects fee-delegation-like value flow for legitimate users who can no longer transact gaslessly. This is a availability/DoS style impact on a specific value-flow feature (gasless settlement), reachable by any unprivileged transaction sender.

### Likelihood Explanation
Likelihood is high given the low cost to the attacker: transactions only need to be well-formed, targeting the whitelisted token/router addresses with valid ABI-encoded arguments and pass basic tx-pool validation (nonce, gas), but do not need real token balances since the `IsBundleTx`/`PreAddTx` gate is checked and slot-reserved before the balance-based `GetCheckBalance` validation runs. An attacker with many funded EOAs (or one EOA with sequential nonces) can cheaply generate up to `MaxBundleTxsInQueue` such transactions to saturate the counter continuously.

### Recommendation
Enforce per-sender limits on gasless bundle-tx queue admission (in addition to, or instead of, a purely global counter), similar to how the core txpool enforces `NonExecSlotsAccount` alongside `NonExecSlotsAll`. Alternatively, perform (at least a cheap subset of) balance/allowance validation before incrementing the shared `knownTxs` queue counter in `PreAddTx`, so that non-genuine gasless-shaped transactions cannot reserve scarce global slots.

### Proof of Concept
1. Attacker observes (or independently determines) the whitelisted `swapRouter` and `allowedTokens` addresses used by the gasless module (queryable via the `GaslessInfo` RPC, see `kaiax/gasless/impl/api.go`).
2. Attacker submits up to `MaxBundleTxsInQueue` (default 200) legacy-type transactions from throwaway/funded-only-for-gas EOAs, each calling `approve(swapRouter, type(uint256).max)` on a whitelisted token address (satisfying `IsApproveTx`'s A1/A3/A4 checks) or `swapForGas(token, amountIn, minAmountOut, amountRepay, deadline)` on the whitelisted router with a whitelisted `token` (satisfying `IsSwapTx`'s S1/S3 checks) — with no real token balance/allowance needed.
3. Each such tx passes `g.IsBundleTx(tx)` in `PreAddTx` and is added to `knownTxs` as `TxStatusQueue`, incrementing `knownTxs.numQueue()`, before `validateTx`/balance checks reject it for other reasons (or even if it's eventually evicted, the attacker can continuously resubmit to keep the counter saturated).
4. Once `numQueue() >= MaxBundleTxsInQueue`, a legitimate user's `GaslessApproveTx`/`GaslessSwapTx` submission hits the same `PreAddTx` check and is rejected with `ErrBundleTxQueueFull`, denying them the gasless feature.

func (g *GaslessModule) PreAddTx(tx *types.Transaction, local bool) error {
	g.knownTxsMu.RLock()
	defer g.knownTxsMu.RUnlock()

	if knownTx, ok := g.knownTxs.get(tx.Hash()); ok && knownTx.elapsedPromotedOrAddedTime() < KnownTxTimeout {
		return ErrUnableToAddKnownBundleTx
	}

	if g.IsBundleTx(tx) {
		if uint(g.knownTxs.numQueue()) >= g.GetMaxBundleTxsInQueue() {
			return ErrBundleTxQueueFull
		}
		g.knownTxs.add(tx, TxStatusQueue)
	}
	return nil
}

// A1. tx.to is a whitelisted ERC20 token.
// A2. tx.data is `approve(spender, amount)`.
// A3. spender is a whitelisted SwapRouter contract.
// A4. amount is MaxUint.
func (g *GaslessModule) IsApproveTx(tx *types.Transaction) bool {
	args, ok := decodeApproveTx(tx, g.signer)
	return ok && g.isApproveTx(args)
}

func (g *GaslessModule) isApproveTx(args *ApproveArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.allowedTokens[args.Token] && // A1
		g.swapRouter == args.Spender && // A3
		args.Amount.Cmp(abi.MaxUint256) == 0 // A4
}

// IsSwapTx checks following conditions:
// S1. tx.to is a whitelisted SwapRouter contract.
// S2. tx.data is `swapForGas(token, amountIn, minAmountOut, amountRepay)`.
// S3. token is a whitelisted ERC20 token.
func (g *GaslessModule) IsSwapTx(tx *types.Transaction) bool {
	args, ok := decodeSwapTx(tx, g.signer)
	return ok && g.isSwapTx(args)
}

func (g *GaslessModule) isSwapTx(args *SwapArgs) bool {
	g.gaslessInfoMu.RLock()
	defer g.gaslessInfoMu.RUnlock()

	return g.swapRouter == args.Router && // S1

}

func (pool *TxPool) add(tx *types.Transaction, local bool) (bool, error) {
	for _, module := range pool.modules {
		if module.IsModuleTx(tx) {
			err := module.PreAddTx(tx, local)
			if err != nil {
				return false, err
			}
			break
		}
	}

	// If the transaction is already known, discard it
	hash := tx.Hash()
	if pool.all.Get(hash) != nil {
		logger.Trace("Discarding already known transaction", "hash", hash)
		return false, fmt.Errorf("known transaction: %x", hash)
	}
	// If the transaction fails basic validation, discard it
	if err := pool.validateTx(tx); err != nil {
		logger.Trace("Discarding invalid transaction", "hash", hash, "err", err)
		invalidTxCounter.Inc(1)
		return false, err
	}

func (k knownTxs) numQueue() int {
	num := 0
	for _, knownTx := range k {
		if knownTx.status == TxStatusQueue {
			num++
		}
	}
	return num
}
