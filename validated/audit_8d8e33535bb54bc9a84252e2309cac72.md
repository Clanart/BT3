### Title
Unbounded buffer read in CLVM canonical-encoding check causes unhandled exception during mempool spend-bundle validation - (File: `chia/full_node/mempool_manager.py`)

### Summary
`MempoolManager.validate_spend_bundle()` calls `is_clvm_canonical()` on every attacker-controlled `puzzle_reveal` and `solution` byte buffer contained in any submitted `SpendBundle`, before signature or cost validation completes. `is_clvm_canonical()` delegates multi-byte atom headers to `is_atom_canonical()`, which indexes into `clvm_buffer` using a length-prefix `for` loop without ever checking that `offset` stays within `len(clvm_buffer)`. A specially crafted, truncated CLVM buffer (an atom byte-header indicating a multi-byte length prefix, with the buffer ending before all prefix bytes are present) makes this loop read past the end of the buffer, raising an unhandled `IndexError`. This is the same bug class as CVE-2024-31030: insufficient bounds checking while parsing a variable-length-prefixed message field from an untrusted, attacker-supplied buffer, causing a crash/DoS during message processing.

### Finding Description
`is_atom_canonical()` reads the length-prefix bytes for an atom purely based on the encoded prefix length, with no bound against the buffer size: [1](#0-0) 

Note that `offset` is incremented and `clvm_buffer[offset]` is dereferenced inside the `for i in range(prefix_len)` loop with no check that `offset < len(clvm_buffer)`. If `clvm_buffer` ends immediately after (or within) a multi-byte length-prefix marker — e.g. a trailing `0xFC` byte (5-byte length prefix) with fewer than 5 subsequent bytes — this loop indexes beyond the end of the buffer and Python raises `IndexError`.

`is_clvm_canonical()` also does not validate that a computed `atom_len`/offset advance stays within the buffer before continuing the loop, it only checks equality at the very end: [2](#0-1) 

This function is invoked directly and unconditionally on every coin spend's `puzzle_reveal` and `solution` in `MempoolManager.validate_spend_bundle()`, with no surrounding exception handling: [3](#0-2) 

`validate_spend_bundle()` is reached from any unprivileged wallet/peer submitting a spend bundle through the standard mempool admission path (`add_spend_bundle` → `pre_validate_spendbundle`/`validate_spend_bundle`), i.e., before any signature check gates malicious input, so an attacker can craft a `puzzle_reveal`/`solution` byte string without needing a valid signature to reach this parser (only the SpendBundleConditions produced by `chia_rs` need to correspond, which the attacker fully controls since they construct the whole bundle).

Existing tests exercise well-formed complete headers or full valid/invalid buffers (e.g. `test_atom_canonical`, `test_clvm_not_canonical`) but none exercise a header whose declared multi-byte length prefix is truncated by the end of the buffer: [4](#0-3) [5](#0-4) 

None of these hex fixtures test a buffer that ends mid-prefix (fewer trailing bytes than the prefix length implies), which is exactly the gap that leads to an out-of-bounds index in `is_atom_canonical`.

### Impact Explanation
Any unprivileged spend-bundle submitter can trigger an unhandled `IndexError` inside core mempool admission logic (`validate_spend_bundle`) simply by including a truncated multi-byte CLVM atom-length header as the `puzzle_reveal` or `solution` bytes of a coin spend in a spend bundle — no valid signature, coin ownership, or special privilege is required to reach the vulnerable parsing code, since this check runs before/alongside coin/signature validation for every coin spend in the bundle. This matches the accepted impact category of "a spend-triggered transaction-processing halt": an uncaught exception during mempool processing of a single submitted spend bundle can abort the enclosing validation task/coroutine, degrading or halting transaction admission and potentially crashing the invoking task in the full node, similar to how the CoAP parser DoS in CVE-2024-31030 is triggered by a single crafted packet parsed with insufficient bounds checking.

### Likelihood Explanation
Likelihood is high: the attacker needs no special access, no valid key, and no already-existing coin state beyond what's needed to construct a syntactically-plausible `SpendBundle`/`CoinSpend` object with an arbitrary byte string for `puzzle_reveal` or `solution`. Constructing a truncated multi-byte CLVM length header is trivial (a handful of specific bytes), and the check is unconditionally invoked for every coin spend regardless of other bundle validity.

### Recommendation
Add explicit bounds checks in `is_atom_canonical()` before reading `clvm_buffer[offset]` for each prefix byte (raise/return non-canonical, not an unhandled exception, if `offset >= len(clvm_buffer)`), and in `is_clvm_canonical()` verify that the atom's declared length plus the computed offset never exceeds `len(clvm_buffer)` before continuing to index it in the next loop iteration. Alternatively, wrap the calls to `is_clvm_canonical()` in `validate_spend_bundle()` with narrow exception handling that maps any parsing failure (including `IndexError`) to `Err.INVALID_COIN_SOLUTION` rather than letting it propagate uncaught.

### Proof of Concept
Construct a `puzzle_reveal` (or `solution`) byte buffer whose final atom uses the 5-byte length-prefix marker but omits the trailing length bytes, e.g.:
```python
from chia.full_node.mempool_manager import is_clvm_canonical

# 0xFC marks a 6-byte total header (1 marker + 5 length bytes); buffer
# is truncated after the marker byte, so is_atom_canonical() indexes
# past the end of the 1-byte buffer while reading the length prefix.
truncated_buf = bytes([0xFC])
is_clvm_canonical(truncated_buf)  # raises IndexError: index out of range
```
Embedding `truncated_buf` as `coin_spend.solution` (or `puzzle_reveal`) of a `CoinSpend` in a submitted `SpendBundle` and pushing it through normal mempool admission drives execution into `MempoolManager.validate_spend_bundle()` line 723-726, which calls `is_clvm_canonical(bytes(coin_spend.solution))` and raises the same unhandled `IndexError` during processing of that spend bundle.

```python
def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

```python
def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```
