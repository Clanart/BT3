### Title
Malicious git remote can spoof `WWW-Authenticate` header to trigger a native "Sign in to GitHub Enterprise" prompt pointed at the attacker's own server, exfiltrating credentials/tokens - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
GitHub Desktop's git credential helper trusts a `WWW-Authenticate` response header returned by the remote git server (forwarded by git as a `wwwauth[]` credential field) as a "happy path" signal that the remote is a GitHub/GitHub Enterprise host, with no independent verification. A fully attacker-controlled git remote can set `WWW-Authenticate: Basic realm="GitHub"` on a 401 response during any fetch/clone/push, causing Desktop to classify the attacker's arbitrary host as an "enterprise" endpoint and open its native Enterprise sign-in UI/OAuth flow pointed directly at the attacker's server, leading to credential or OAuth-code exfiltration.

### Finding Description
When git needs credentials for a remote it invokes Desktop's credential helper (`GIT_ASKPASS`/`credential.helper=desktop`) via the trampoline server. Git forwards any `WWW-Authenticate` headers it received from the remote as `wwwauth[]` fields in the credential payload passed to the helper.

`getEndpointKind` in [1](#0-0)  classifies the remote purely from the *content of this attacker-supplied header*, with a comment explicitly stating this is done "without having to resort to making a request ourselves" — i.e., no server-side verification that the host is actually GitHub/GHE:
```
for (const [k, v] of cred.entries()) {
  if (k.startsWith('wwwauth[')) {
    if (v.includes('realm="GitHub"')) {
      return 'enterprise'
    } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
      return 'generic'
    }
  }
}
```

In `getCredential`, once `endpointKind !== 'generic'` and no existing account matches the (attacker) host, Desktop calls `ui.promptForGitHubSignIn(endpoint)`: [2](#0-1) 

`promptForGitHubSignIn` then launches the real Enterprise sign-in flow, using the attacker-controlled `origin` (derived directly from the credential URL, i.e., the remote's actual host) as the sign-in target: [3](#0-2) 

Because `endpoint`/`origin` is simply the attacker's remote URL, `dispatcher.setSignInEndpoint(origin)` and the subsequent `SignInStore` flow (`setEndpoint` → `Authentication` step → username/password or OAuth via `shell.openExternal(getOAuthAuthorizationURL(endpoint, csrfToken))`) will submit the user's GitHub Enterprise credentials, or redirect the OAuth authorize request, to the attacker's own server: [4](#0-3) [5](#0-4) 

This mirrors the structure of the reported bug: an attacker-controlled external input (there, an ERC20 transfer hook; here, an HTTP response header from a git remote) is trusted to drive a security-relevant decision (there, releasing funds/state before the invariant "ticket owner == new lender" holds; here, classifying an arbitrary host as "GitHub" before any actual verification that it is), and the consuming code proceeds to perform a privileged, trust-sensitive action (transferring funds / opening a real sign-in flow against the untrusted target) based on that unverified signal.

### Impact Explanation
A successful exploitation causes Desktop to present its native, trusted "Sign in to GitHub Enterprise" dialog while actually targeting the attacker's server. If the user completes basic-auth sign-in, their GitHub Enterprise username/password (or PAT) is sent straight to the attacker. If they proceed through the browser OAuth path, the OAuth authorize request is directed at the attacker-controlled `endpoint`, letting the attacker capture the authorization code/state or otherwise manipulate the flow. This is credential/token exfiltration via a trusted-looking OAuth/sign-in surface, which is explicitly listed as a valid impact category.

### Likelihood Explanation
The trigger requires only that the victim clone/fetch/push to a repository whose remote is controlled by the attacker (or a proxy/MITM position on any git remote) — no local access, no prior credential leak, and no unusual user action beyond a normal git operation and responding to a sign-in prompt that will look like a legitimate GitHub Desktop authentication request. The `wwwauth[]` header is fully attacker-controlled server response content already documented in the code as the trust anchor, so likelihood is moderate-to-high for any user who adds/uses an untrusted remote.

### Recommendation
Do not use the `WWW-Authenticate` header alone to classify a remote as GitHub/Enterprise. Require positive verification (e.g., matching against `isGitHubHost`/an actual API probe, or requiring the header AND a successful `isGitHubHost` check) before elevating to the `'enterprise'` classification, and always surface the real target host prominently in the sign-in UI so users can detect a mismatch before entering credentials.

### Proof of Concept
1. Attacker stands up a git-over-HTTP(S) server at `https://evil.example.com/repo.git` that, on any authentication-required request, responds with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
2. Victim adds this as a remote (or clones it) in GitHub Desktop and performs a fetch/push.
3. Git forwards the header to Desktop's credential helper as `wwwauth[0]=Basic realm="GitHub"`.
4. `getEndpointKind` in `trampoline-credential-helper.ts` returns `'enterprise'` for `evil.example.com` purely from this header.
5. Since no existing account matches `evil.example.com`, `getCredential` calls `ui.promptForGitHubSignIn('https://evil.example.com/...')`.
6. `promptForGitHubSignIn` opens the Enterprise sign-in flow with `origin = https://evil.example.com`, and the victim's subsequent credential entry / OAuth authorize redirect is sent to the attacker's server. [6](#0-5)

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })

  public async setEndpoint(url: string): Promise<void> {
    const currentState = this.state

    if (
      currentState?.kind !== SignInStep.EndpointEntry &&
      currentState?.kind !== SignInStep.ExistingAccountWarning
    ) {
      const stepText = currentState ? currentState.kind : 'null'
      return fatalError(
        `Sign in step '${stepText}' not compatible with endpoint entry`
      )
    }

    /**
     * If the user enters a github.com url in the GitHub Enterprise sign-in
     * flow we'll redirect them to the GitHub.com sign-in flow.
     */
    if (/^(?:https:\/\/)?(?:api\.)?github\.com($|\/)/.test(url)) {
      this.beginDotComSignIn(currentState.resultCallback)
      return
    }

    this.setState({ ...currentState, loading: true })

    let validUrl: string
    try {
      validUrl = validateURL(url)
    } catch (e) {
      let error = e
      if (e.name === InvalidURLErrorName) {
        error = new Error(
          `The GitHub Enterprise instance address doesn't appear to be a valid URL. We're expecting something like https://example.ghe.com.`
        )
      } else if (e.name === InvalidProtocolErrorName) {
        error = new Error(
          'Unsupported protocol. Only https is supported when authenticating with GitHub Enterprise instances.'
        )
      }

      this.setState({ ...currentState, loading: false, error })
      return
    }

    const endpoint = getEnterpriseAPIURL(validUrl)

    const existingAccount = this.accounts.find(x => x.endpoint === endpoint)

    if (existingAccount) {
      this.setState({
        kind: SignInStep.ExistingAccountWarning,
        endpoint,
        existingAccount,
        error: null,
        loading: false,
        resultCallback: currentState.resultCallback,
      })
    } else {
      this.setState({
        kind: SignInStep.Authentication,
        endpoint,
        error: null,
        loading: false,
        resultCallback: currentState.resultCallback,
      })
    }
  }
