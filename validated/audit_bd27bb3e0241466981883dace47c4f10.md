### Title
`claimAllBribes` under-reports multi-token bribe pools, causing yield to be permanently stranded in `DelegateVoteRewardPool` - (File: `wombat/WombatBribeManager.sol`)

### Summary
`WombatBribeManager.claimAllBribes(address _for)` records only `IWombatBribe(bribesContract).rewardTokens()[0]` per pool in its return arrays, yet it triggers `IBribeRewardPool(pool.rewarder).getReward(_for, _for)`, which actually loops over and transfers **every** registered reward token of that rewarder. When `_for` is the `delegatedPool` (`DelegateVoteRewardPool`), the extra tokens land in that contract's balance but are never registered or queued for its stakers, permanently stranding that yield.

### Finding Description
In `claimAllBribes`: [1](#0-0) 
`rewardTokens[i]` is hard-set to index `[0]` of the bribe's reward token list, and `earnedRewards[i]` is computed only for that single token via `earned(_for, rewardTokens[i])`. But the actual token movement is performed by `IBribeRewardPool(pool.rewarder).getReward(_for, _for)`, whose implementation in `BribeRewardPool._getReward` iterates the rewarder's *entire* `rewardTokens` array and transfers each one directly to `_for`: [2](#0-1) 

For a normal EOA calling `claimAllBribes(msg.sender)`, this mismatch is cosmetic — all tokens land in the caller's own wallet regardless of what the return array says, so there is no fund loss there.

The real damage occurs through the `delegatedPool` integration. `DelegateVoteRewardPool.harvestAll()` calls `claimAllBribes(address(this))` and feeds the (incomplete) return arrays into `_manageRewards`: [3](#0-2) 
`_manageRewards` only registers/queues the single token per pool that was reported, via `_queueNewRewardsWithoutTransfer`: [4](#0-3) 
Meanwhile, the actual `getReward(_for, _for)` call inside `claimAllBribes` already transferred *all* of that pool's reward tokens (including index 1+) into the `DelegateVoteRewardPool` contract's balance, since `_for == address(this)`. Because only the first token is ever pushed into `isRewardToken`/`rewardTokens`/`rewards[...]` accounting, tokens beyond index 0 sit in the contract with no reward-per-share tracking and no code path (no sweep/rescue function present in `DelegateVoteRewardPool.sol`) to ever distribute or recover them to stakers of that pool. This is unprivileged-reachable: `claimAllBribes` is `public`, and any unprivileged caller (or the routine `harvestAll()` flow triggered as part of `castVotes`) can pass `_for = delegatedPool` and trigger this whenever a bribe contract for a voted pool registers more than one reward token — a normal, non-malicious configuration.

Existing checks (`userVotedForPoolInVlmgp[_for][lp] > 0` gate, `updateReward` modifiers in the rewarder) do not prevent this because they only gate *whether* a claim happens, not the completeness of what is reported/reinvested afterward.

### Impact Explanation
Bribe/reward tokens beyond index 0 for any multi-token bribe pool that `delegatedPool` has voted for become permanently frozen inside the `DelegateVoteRewardPool` contract: they are transferred there by `BribeRewardPool._getReward` but never registered as a distributable reward token, so stakers of the delegated pool can never claim them. This matches the "Permanent freezing of unclaimed yield" (High) impact class.

### Likelihood Explanation
No special privileges are required — `claimAllBribes` is a public function callable by anyone with any `_for` address, and it is also invoked automatically via `castVotes`/`voteAndCast` (`IDelegateVoteRewardPool(delegatedPool).harvestAll()`). The only precondition is that a bribe contract for a pool the `delegatedPool` has voted in registers more than one reward token, which is a routine/expected bribe configuration, not an admin misconfiguration. The bug is deterministic and repeatable on every harvest of such a pool.

### Recommendation
In `claimAllBribes`, collect and report the full reward-token list and amounts returned by the bribe/rewarder (e.g., call `pool.rewarder.allEarned`/enumerate `rewardTokens()` fully, sized per-pool rather than a fixed 1-slot-per-pool array), so the reported arrays passed to `_manageRewards` cover every token actually moved by `getReward`.

### Proof of Concept
Hardhat test plan:
1. Deploy `WombatBribeManager`, a mock `IWombatBribe` with 2 reward tokens (e.g. WOM and USDC) registered on its rewarder, and `DelegateVoteRewardPool` as `delegatedPool`.
2. Have `delegatedPool` vote for that pool (`userVotedForPoolInVlmgp[delegatedPool][lp] > 0`), and accrue nonzero `earned` amounts for both reward tokens.
3. Call `DelegateVoteRewardPool.harvestAll()`.
4. Assert: `USDC.balanceOf(delegatedPool)` increased by the full earned USDC amount (proving the transfer happened), but `delegatedPool.isRewardToken(USDC)` is `false` and `delegatedPool.rewards(USDC).historicalRewards == 0` (proving it was never queued for stakers).
5. Assert no function on `DelegateVoteRewardPool` allows recovering/distributing that stranded USDC balance to stakers, confirming permanent freezing.

    function _manageRewards(
        address[] memory rewardTokensList,
        uint256[] memory earnedRewards
    ) internal {
        uint256 length = rewardTokensList.length;
        for (uint256 index = 0; index < length; ++index) {
            uint256 fees = (protocolFee * earnedRewards[index]) / DENOMINATOR;
            if (fees > 0 && feeCollector != address(0)) {
                earnedRewards[index] = earnedRewards[index] - fees;
                IERC20(rewardTokensList[index]).safeTransfer(
                    feeCollector,
                    fees
                );
            }
            if (earnedRewards[index] > 0) {
                _queueNewRewardsWithoutTransfer(
                    earnedRewards[index],
                    rewardTokensList[index]
                );
            }
        }
    }

    /// @notice Sends new rewards to be distributed to the users staking.
    /// @param _amountReward Amount of reward token to be distributed
    /// @param _rewardToken Address reward token
    function _queueNewRewardsWithoutTransfer(
        uint256 _amountReward,
        address _rewardToken
    ) internal {
        if (!isRewardToken[_rewardToken]) {
            rewardTokens.push(_rewardToken);
            isRewardToken[_rewardToken] = true;
        }
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (totalSupply == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10 ** this.stakingDecimals()) /
                totalSupply;

    }
