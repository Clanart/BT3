### Title
TextFormat Any Printer Injects Unescaped/Unquoted `type_url` Into Debug Output Structure - ([File: src/google/protobuf/text_format.cc])

### Summary
The AWS advisory describes a defense-in-depth gap where the CloudFront `Signer` builds a policy-document string by concatenating attacker-influenced values without escaping quotes/backslashes, so the resulting JSON structure can be altered by special characters in the input. The transferable invariant is: *"a value taken from untrusted/attacker-reachable input is embedded into a structured serialized document by raw concatenation instead of through the document's normal escaping/quoting routine, so special structural characters in that value can break out of their intended slot."*

Protobuf's `TextFormat::Printer::PrintAny` (and its Java/C#/upb analogs) has the same pattern: when expanding a `google.protobuf.Any` field for debug/text output, it writes the raw `type_url` string between `[` and `]` using `PrintLiteral`/`PrintString` calls that do **not** go through the normal string-escaping path (`HardenedPrintString`/`CEscape`) that every other string field uses.

### Finding Description
Every ordinary `string` field printed by TextFormat is quoted and escaped via `FastFieldValuePrinter::PrintString` / `HardenedPrintString`, which explicitly escapes `"`, `\`, control characters, etc. (`src/google/protobuf/text_format.cc:2214-2243`, `1877-1900`). This is the "proper JSON/text encoder" analog to AWS's `json_encode`.

`PrintAny`, however, is special-cased: [1](#0-0) 

```
std::string serialized_value = reflection->GetString(message, value_field);
if (!value_message->ParseFromString(serialized_value)) { ... return false; }
generator->PrintLiteral("[");
generator->PrintString(type_url);
generator->PrintLiteral("]");
```

`type_url` is the raw `Any.type_url` field value, and it is written directly with no quoting and no escaping of `[`, `]`, `{`, `}`, newlines, or other TextFormat-structural characters. The Java implementation has the identical pattern: [2](#0-1) 

The only validation applied before printing comes from `internal::ParseAnyTypeUrl` (`any_lite.cc:72-84`), which merely does `type_url.find_last_of('/')` and splits the string into `url_prefix` (everything up to and including the last `/`) and `full_type_name` (everything after). It performs **no character-set validation whatsoever** on either half: [3](#0-2) 

Compare this to the **parser**-side helper `ConsumeAnyTypeUrlOrFullTypeName`, which does validate the prefix (rejects `/` at position 0, validates `%XX` escapes) and validates that `full_type_name` consists of legal dotted identifiers: [4](#0-3) 

That validation exists only in the *TextFormat parser's* consumption routine — it is never applied to `Any.type_url` when the field is populated via **binary wire format or ProtoJSON**, because `type_url` is an ordinary `string` field with no such constraint at the wire level. `full_type_name` (the suffix after the last `/`) is implicitly constrained because it must exactly equal a registered `Descriptor::full_name()` for `DefaultFinderFindAnyType` to resolve it (full names only contain `[A-Za-z0-9_.]`), but the **prefix** (`url_prefix`, i.e., everything up to and including the last `/`) is completely unconstrained and is included verbatim as part of `type_url` when printed.

### Impact Explanation
An attacker who controls a bounded binary-Protobuf or ProtoJSON payload that a trusted application parses into a message containing a `google.protobuf.Any` field can set `type_url` to something like:

```
evil]\n  injected_field: "pwned"\n[fake/google.protobuf.Empty
```

as long as the payload's `Any.value` bytes parse successfully as the resolved message type (`google.protobuf.Empty` trivially parses from zero bytes). When the application later calls `TextFormat::PrintToString` / `DebugString()` (a very common logging/debugging operation) with `SetExpandAny(true)` (the default in many contexts, including `DebugString()`), the resulting text-format output will contain injected `]`, `{`, `}`, or newline characters that do not correspond to the real structure of the message. This can:
- Corrupt structured logs that downstream tooling parses assuming well-formed TextFormat.
- Allow the printed debug string to be re-parsed (via `TextFormat::Parse`) into a *different* message shape than the one that was originally serialized, i.e., an integrity break of the round-trip invariant TextFormat otherwise guarantees (as explicitly tested elsewhere, e.g. `testMergeAngleBrackets`/roundtrip tests for Any).
- In injection-sensitive downstream consumers (e.g., systems that render or re-parse debug strings, similar to CloudFront's policy document use case), attacker-controlled data can escape its intended slot in the structured output.

This is a defense-in-depth-class issue, analogous in class and severity posture to the AWS advisory: no memory corruption, but a missing escaping/quoting invariant on an attacker-reachable string value embedded in a structured serialization output.

### Likelihood Explanation
Reaching this requires: (1) a schema with an `Any` field (extremely common, e.g., any gRPC status/error detail pattern), (2) attacker-controlled binary/ProtoJSON input decoded into that field (well within the stated threat model — "ordinary client sending bounded binary or ProtoJSON through a public parse API"), (3) the attacker choosing a `type_url` whose suffix resolves to *some* registered, trivially-parseable type (e.g. `google.protobuf.Empty`, or any type where the attacker also controls `value` bytes) and a prefix containing structural characters, and (4) the application later emitting `TextFormat`/`DebugString()` output with Any-expansion enabled (a default/common developer/debugging behavior, not something the attacker controls but something they can rely on being present in most Protobuf-based services). Likelihood is Medium: the exploitation setup is straightforward and requires no privileged access, but real impact depends on a downstream consumer of the debug/log text.

### Recommendation
Apply the same URL-prefix character validation used in `ConsumeAnyTypeUrlOrFullTypeName` (or, more simply, route the printed `type_url` through the same escaping/quoting logic used for ordinary string fields, or at minimum escape/percent-encode any `[`, `]`, `{`, `}`, and control characters) before writing it into the `[...]` bracket in `PrintAny`, in both `src/google/protobuf/text_format.cc` and the equivalent `java/core/src/main/java/com/google/protobuf/TextFormat.java` (`printAny`), C#, and upb text encoders. Alternatively, fall back to unexpanded `type_url:"..." value:"..."` printing (which *does* quote/escape) whenever `type_url` contains characters outside a safe URL character set, mirroring the parser's stricter validation.

### Proof of Concept
Conceptual reproduction (not executed — requires building the C++ library):
1. Construct, via raw binary wire-format bytes (no TextFormat/API validation applied), an `Any` message with:
   - `type_url` = `"x]\n  extra: 1\n[y/google.protobuf.Empty"`
   - `value` = `""` (valid empty serialization of `google.protobuf.Empty`)
2. Embed this `Any` in a container message field, and parse it via `Message::ParseFromString` (ordinary public binary parse API) into a trusted, generated message type.
3. Call `TextFormat::Printer` with `SetExpandAny(true)` (or use `DebugString()`, which enables it by default) on the parsed message.
4. Observe that the emitted text contains the raw injected `]`, newline, and `extra: 1` token sequence unescaped and unquoted inside the container's serialized text, breaking the well-formedness of the surrounding TextFormat structure — confirmed by code inspection of `PrintAny` (`text_format.cc:2564-2566`) showing `PrintLiteral`/`PrintString` used without any escaping call, contrasted with `FastFieldValuePrinter::PrintString` (`text_format.cc:2227-2238`), which always escapes and quotes ordinary string field values.

Note: I was not able to actually execute this PoC (no code-execution/build tooling available in this session); the finding is based on static code inspection of the cited functions. If independent confirmation is needed, a Devin session with the ability to build and run the C++ (or Java) protobuf library should be used to serialize the crafted `Any` bytes and confirm the exact injected text-format output.

bool ParseAnyTypeUrl(absl::string_view type_url,
                     std::string* PROTOBUF_NULLABLE url_prefix,
                     std::string* PROTOBUF_NONNULL full_type_name) {
  size_t pos = type_url.find_last_of('/');
  if (pos == std::string::npos || pos + 1 == type_url.size()) {
    return false;
  }
  if (url_prefix) {
    *url_prefix = std::string(type_url.substr(0, pos + 1));
  }
  *full_type_name = std::string(type_url.substr(pos + 1));
  return true;
}
