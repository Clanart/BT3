## Analog Found

### Title
Gasless swap admission and settlement price rely on manipulable Uniswap V2 pool reserves - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
Kaia's gasless-transaction module (KIP-247) determines whether a user-submitted `SwapForGas` transaction is admissible, and the `GaslessSwapRouter` contract itself executes the token→gas swap, using the spot reserves of a Uniswap-V2-style AMM pool as the sole price source. Exactly like the `MagicLpAggregator` finding, this "price oracle" is just `getReserves()`/constant-product math on a pool that any unprivileged account can move with an ordinary (flash-loan-free) trade in the same or an adjacent block, since Kaia has no sanity check against an independent reference price.

### Finding Description
`GaslessModule.checkBalanceForSwap` decodes a `swapForGas` transaction and validates it purely against the DEX-quoted price: [1](#0-0) 

`routerContract.GetAmountIn(nil, token, minAmountOut)` is a view call on `GaslessSwapRouter`, whose ABI signature is bound as a free/view call returning `amountIn` for a desired `amountOut`: [2](#0-1) 

This mirrors the Uniswap V2 `getAmountIn`/`getAmountOut` primitives that are computed directly from a pair's live reserves (`getReserves()`), as seen throughout the vendored Uniswap V2 bindings used elsewhere in the same test/gasless flow: [3](#0-2) 

The gasless end-to-end test explicitly wires the `GaslessSwapRouter` to a Uniswap V2 factory/router/pair whose price is entirely reserve-based: [4](#0-3) 

Because both the tx-pool admission check (`GetAmountIn`) and the actual on-chain execution of `swapForGas` (which internally performs the AMM swap and only enforces the caller-supplied `minAmountOut`, not any external price bound) key off the same manipulable spot reserves, an attacker who moves the pool's reserves with an ordinary swap can distort the price used to (a) gate whether their `SwapForGas`/`ApproveTx` pair is treated as a valid gasless transaction and admitted/sponsored by the network's gas-delegation flow, and (b) determine how much of the sponsoring token is actually extracted from the pool during settlement. There is no reference/TWAP/oracle cross-check anywhere in this path, unlike in a properly hardened price feed.

### Impact Explanation
An attacker can:
1. Execute an ordinary swap against the pool used by `GaslessSwapRouter` to skew the reserve ratio in their favor (classic spot-price manipulation, no flash loan required for a low-liquidity pool).
2. Immediately submit `ApproveTx` + `SwapForGas` referencing the distorted reserves, so `checkBalanceForSwap`'s `GetAmountIn` requirement is satisfied with a much smaller/undervalued `amountIn` than the pool's fair price would require.
3. Have the same distorted reserves used at actual settlement time (since Kaia does not re-price against any external oracle), extracting outsized `amountOut` (WKAIA) for a token amount well below fair market value — value that is drained from the pool's liquidity and effectively subsidized through the gasless/fee-delegation mechanism.

This is a concrete value-extraction vector reachable by any unprivileged transaction sender through Kaia's public gasless transaction pathway (KIP-247), not merely a resource/DoS issue, because it results in unauthorized value movement out of the swap pool underpinning the sponsored gas-payment mechanism.

### Likelihood Explanation
Likelihood is moderate-to-high in practice: pools used for `GaslessSwapRouter` are expected to be shallow relative to major DEX pools (they exist specifically to let a token holder swap into gas), making spot-price manipulation cheap, and the attack requires only standard, permissionless transactions from the attacker's own account — no privileged access, validator collusion, or protocol bug beyond the missing price-sanity check.

### Recommendation
Do not rely solely on instantaneous AMM reserves (`getAmountIn`/`getAmountOut`) for gasless-swap admission or settlement pricing. Introduce a TWAP-based price check, a maximum allowed deviation between spot price and a trusted reference/oracle price, or bound the price impact allowed per gasless swap (e.g., cap `amountIn`/pool-depth ratio), analogous to the H-04 remediation of cross-checking with an independent price feed before trusting pool-reserve-derived prices.

### Proof of Concept
Conceptual reproduction based on the existing `TestGasless` fixture (`tests/gasless_test.go`):
1. Deploy the same Uniswap V2 factory/router/pair and `GaslessSwapRouter` as in `tests/gasless_test.go` (`deployUniswapV2Factory`, `deployUniswapV2Router02`, `deployGaslessSwapRouter`) with realistic (shallow) liquidity.
2. As an unprivileged account, submit a large one-sided swap through the standard `UniswapV2Router02` to skew `testToken`/`WKAIA` reserves.
3. Immediately submit `ApproveTx` (`sendApproveTx`) then `SwapForGas` (`sendSwapTx`) with `amountIn` computed against the now-skewed `GetAmountIn` quote from `GaslessSwapRouter`.
4. Observe that `checkBalanceForSwap` (`kaiax/gasless/impl/tx_pool.go`) admits the transaction and that settlement extracts `minAmountOut` worth of WKAIA from the pool for an `amountIn` far below the pre-manipulation fair-market requirement, at the pool's/relayer's expense. [5](#0-4)
