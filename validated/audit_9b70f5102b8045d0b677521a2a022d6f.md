### Title
`update_finalized_payouts`/`get_payout_txs_for_withdrawal_utxos` keys payouts by `(withdrawal_utxo_txid, withdrawal_utxo_vout)` alone, letting one payout tx mark multiple `deposit_id`s "paid" and enabling double reimbursement - ([File: core/src/database/verifier.rs])

### Summary
`get_payout_txs_for_withdrawal_utxos` joins `withdrawals` to `bitcoin_syncer_spent_utxos` solely on `(withdrawal_utxo_txid, withdrawal_utxo_vout)`, with no `deposit_id`/`idx` disambiguation and no DB uniqueness constraint preventing two different `withdrawals.idx` rows from sharing the same withdrawal UTXO. If an attacker registers two Citrea withdrawals (different `deposit_id`s) that reference byte-identical withdrawal UTXOs, a single real Bitcoin payout transaction spending that UTXO will match both rows in the join, and `update_payout_txs_and_payer_operator_xonly_pk` will mark **both** `deposit_id`s as paid by the same operator/txid. The honest operator's own `PayoutCheckerTask` (via `get_first_unhandled_payout_by_operator_xonly_pk`) will then pick up the second, never-actually-funded row and automatically run `handle_finalized_payout`, producing a second kickoff/reimbursement cycle for funds it never fronted.

### Finding Description
Binding claimed to hold: for each withdrawal row `w.idx` (= `deposit_id`), `w.payout_txid` should be set if and only if a payout transaction whose input specifically satisfies **that** deposit's registered withdrawal UTXO was mined, i.e. `paid(deposit_id) == fronted(deposit_id)` for exactly one operator, exactly once.

Code path:
1. Attacker calls Citrea Bridge `withdraw()` twice with different `index` values (→ different `deposit_id`s in this repo) but chooses the identical `withdrawal_utxo` bytes both times. Nothing in `verify_storage_proofs` (circuits-lib/src/bridge_circuit/storage_proof.rs:44-133) or in `update_withdrawal_utxo_from_citrea_withdrawal` (core/src/database/verifier.rs:108-135) enforces uniqueness of the withdrawal UTXO across `idx` values — each is written independently, keyed only by `idx`.
2. The `withdrawals` table has no `UNIQUE` constraint on `(withdrawal_utxo_txid, withdrawal_utxo_vout)` (core/src/database/schema.sql:269-281).
3. When one of these deposits' payout tx is broadcast and confirmed (via operator payout or `Verifier::sign_optimistic_payout`, core/src/verifier.rs:1570-1660, which only checks `is_utxo_spent` against the live chain — a check that is per-outpoint and cannot know about the duplicate registration), the finalized-block handler runs `update_finalized_payouts` → `get_payout_txs_for_withdrawal_utxos` (core/src/database/verifier.rs:170-196):
   ```
   SELECT w.idx, bsu.spending_txid
   FROM withdrawals w
   JOIN bitcoin_syncer_spent_utxos bsu
      ON bsu.txid = w.withdrawal_utxo_txid AND bsu.vout = w.withdrawal_utxo_vout
   WHERE bsu.block_id = $1
   ```
   Because two `withdrawals` rows (`idx1`, `idx2`) share the same `(txid, vout)`, this join returns **both** rows mapped to the single real `spending_txid`.
4. `update_payout_txs_and_payer_operator_xonly_pk` (core/src/database/verifier.rs:199-251) then blindly sets `payout_txid`, `payout_payer_operator_xonly_pk`, `payout_tx_blockhash` for **every** `idx` returned, i.e. for both `idx1` and `idx2`, using the operator xonly pk parsed from the single payout tx's OP_RETURN (or `None` for an optimistic payout).
5. `PayoutCheckerTask::run_once` (core/src/task/payout_checker.rs:39-111) calls `get_first_unhandled_payout_by_operator_xonly_pk` (core/src/database/verifier.rs:282-313), which only filters on `payout_txid IS NOT NULL AND is_payout_handled = FALSE AND payout_payer_operator_xonly_pk = $1` — it has no way to distinguish that `idx2` was never actually separately funded. The task then calls `Operator::handle_finalized_payout` (core/src/operator.rs:839-970) for `idx2`'s `deposit_outpoint`, which allocates a fresh kickoff connector and queues a full `Kickoff`/`Reimburse` transaction chain, crediting the operator a second `bridge_amount` reimbursement for a withdrawal it fronted zero times.

Existing guards do not catch this: `sign_optimistic_payout`'s `is_utxo_spent` check only prevents re-signing a second payout transaction for the *same* Bitcoin outpoint (a physical impossibility to spend twice), but it does nothing to stop the same already-spent UTXO from being recorded as "paid" for a second, distinct `deposit_id` in the database. `Verifier::is_deposit_valid`, `SPV::verify`, and the storage-proof verification only check that a claimed withdrawal UTXO for a given index matches Citrea state — they never check cross-index uniqueness.

### Impact Explanation
This lets an operator be reimbursed twice (once per matched `withdrawals.idx`) for one real, single Bitcoin payout, i.e. "an operator reimbursed for a payout it never funded" (Critical category). It also means the second deposit's honest depositor/withdrawer is permanently marked as "paid" while never actually receiving the second withdrawal payout — the withdrawal is falsely closed with `is_payout_handled = TRUE` and a `kickoff_txid` pointing at unrelated funds, so the true withdrawal for `deposit_id2` never gets a real payout, an ambiguous but real financial/functional break. The condition is repeatable: attacker can register N withdrawal indices sharing the same UTXO, causing an operator's automation to attempt N reimbursement cycles off one funded payment, scaling the drain across the round's collateral/reimbursement connectors.

### Likelihood Explanation
The attacker only needs the capabilities explicitly granted: ability to call `withdraw()` on the Citrea Bridge contract multiple times and freely choose the withdrawal UTXO bytes each time — no verifier/operator/aggregator privilege, no key compromise, no majority hashrate. No BTC cost beyond whatever collateral Citrea requires per withdrawal registration (out of scope of this repo). The bug fires automatically through the honest operator's own `PayoutCheckerTask` automation, with no operator cooperation needed once the duplicate UTXO registration and one real payout have occurred.

### Recommendation
Change `get_payout_txs_for_withdrawal_utxos` (and the underlying data model) to disambiguate strictly by `deposit_id`/`idx`, not merely by `(withdrawal_utxo_txid, withdrawal_utxo_vout)`. Concretely: reject/ignore withdrawal registrations whose UTXO is already registered for a different, still-open `idx` (enforce a partial `UNIQUE` DB constraint on `(withdrawal_utxo_txid, withdrawal_utxo_vout)` where `payout_txid IS NULL`, or at withdrawal-registration time), and/or change the join/update logic so that once a UTXO is consumed by a payout tx, only the first matching, still-unpaid `idx` is marked paid and any other rows sharing that UTXO are flagged as invalid/conflicting rather than silently marked paid.

                    .push_bind(txid)

                    .push_bind(block_hash);
            },
        );

    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
            ));
        }

        self.db
            .update_payout_txs_and_payer_operator_xonly_pk(
                Some(dbtx),
                payout_txs_and_payer_operator_idx,
            )
            .await?;

        Ok(())
    }

    pub async fn handle_finalized_payout<'a>(
        &'a self,
        dbtx: DatabaseTransaction<'a>,
        deposit_outpoint: OutPoint,
        payout_tx_blockhash: BlockHash,
    ) -> Result<bitcoin::Txid, BridgeError> {
        let (deposit_id, deposit_data) = self
            .db
            .get_deposit_data(Some(dbtx), deposit_outpoint)
            .await?
            .ok_or(BridgeError::DatabaseError(sqlx::Error::RowNotFound))?;

        // get unused kickoff connector
        let (round_idx, kickoff_idx) = self
            .db
            .get_unused_and_signed_kickoff_connector(
                Some(dbtx),
                deposit_id,
                self.signer.xonly_public_key,
            )
            .await?
            .ok_or(BridgeError::DatabaseError(sqlx::Error::RowNotFound))?;

        let current_round_index = self.db.get_current_round_index(Some(dbtx)).await?;
        tracing::info!(
            "Operator: Current round index: {}, round idx for kickoff: {}",
            current_round_index,
            round_idx
        );
        #[cfg(feature = "automation")]
        if current_round_index != round_idx {
            // we currently have no free kickoff connectors in the current round, so we need to end round first
            // if current_round_index should only be smaller than round_idx, and should not be smaller by more than 1
            // so sanity check:
            if current_round_index.next_round() != round_idx {
                return Err(eyre::eyre!(
                    "Internal error: Expected the current round ({:?}) to be equal to or 1 less than the round of the first available kickoff for deposit reimbursement ({:?}) for deposit {:?}. If the round is less than the current round, there is an issue with the logic of the fn that gets the first available kickoff. If the round is greater, that means the next round do not have any kickoff connectors available for reimbursement, which should not be possible.",
                    current_round_index, round_idx, deposit_outpoint
                ).into());
            }
            tracing::info!(
                "Operator: Starting next round to be able to get reimbursement for the payout"
            );
            // start the next round to be able to get reimbursement for the payout
            self.end_round(dbtx).await?;
        }

        // get signed txs,
        let kickoff_data = KickoffData {
            operator_xonly_pk: self.signer.xonly_public_key,
            round_idx,
            kickoff_idx,
        };

        let payout_tx_blockhash = payout_tx_blockhash.as_byte_array().last_20_bytes();

        #[cfg(test)]
        let payout_tx_blockhash = self
            .config
            .test_params
            .maybe_disrupt_payout_tx_block_hash_commit(payout_tx_blockhash);

        let context = ContractContext::new_context_for_kickoff(
            kickoff_data,
            deposit_data,
            self.config.protocol_paramset(),
        );

        let signed_txs = create_and_sign_txs(
            self.db.clone(),
            &self.signer,
            self.config.clone(),
            context,
            Some(payout_tx_blockhash),
            Some(dbtx),
        )
        .await?;

        let tx_metadata = Some(TxMetadata {
            tx_type: TransactionType::Dummy, // will be replaced in add_tx_to_queue
            operator_xonly_pk: Some(self.signer.xonly_public_key),
            round_idx: Some(round_idx),
            kickoff_idx: Some(kickoff_idx),
            deposit_outpoint: Some(deposit_outpoint),
        });

        // try to send them
        for (tx_type, signed_tx) in &signed_txs {
            match *tx_type {
                TransactionType::Kickoff
                | TransactionType::OperatorChallengeAck(_)
                | TransactionType::WatchtowerChallengeTimeout(_)
                | TransactionType::ChallengeTimeout
                | TransactionType::DisproveTimeout
                | TransactionType::Reimburse => {
                    #[cfg(feature = "automation")]
                    self.tx_sender
                        .add_tx_to_queue(
                            dbtx,
                            *tx_type,
                            signed_tx,
                            &signed_txs,
                            tx_metadata,
                            self.config.protocol_paramset(),
                            None,
                        )
                        .await?;
                }
                _ => {}
            }
        }

        let kickoff_txid = signed_txs
            .iter()
            .find_map(|(tx_type, tx)| {
                if let TransactionType::Kickoff = tx_type {
                    Some(tx.compute_txid())
                } else {
                    None
                }
            })
            .ok_or(eyre::eyre!(
                "Couldn't find kickoff tx in signed_txs".to_string(),
            ))?;

        // mark the kickoff connector as used
        self.db
            .mark_kickoff_connector_as_used(Some(dbtx), round_idx, kickoff_idx, Some(kickoff_txid))
            .await?;

        Ok(kickoff_txid)
    }
