### Title
Baseline suppression in PostToolUse Write handler is keyed only on rule name, not the matched construct, allowing a pre-seeded benign occurrence to permanently suppress warnings for a genuinely more dangerous rewrite - (File: plugins/security-guidance/hooks/security_reminder_hook.py)

### Summary
`check_patterns()` returns matches as `(ruleName, reminder)` tuples with no record of which specific substring, line, or occurrence triggered the match. [1](#0-0)  Because the baseline-suppression logic in the Write-tool path (which calls `check_patterns()` on the baseline content obtained via `get_baseline_file_content()` and diffs against the new content's matches) operates on this rule-name-only representation, once a rule such as `pickle_deserialization` has any hit in the pre-session baseline for a file, it is excluded from all future reminders for that file regardless of what the new, attacker-influenced content actually contains.

### Finding Description
`check_patterns(file_path, content)` iterates `SECURITY_PATTERNS` and appends `(pattern["ruleName"], pattern["reminder"])` to `matches` whenever any substring/regex/path check matches — it does not capture the specific matched text, offset, or line number. [1](#0-0)  `get_baseline_file_content()` fetches the file's content at the session's captured `git stash create` baseline SHA via `git show <baseline_sha>:<rel_path>` for use by this dedup logic. [2](#0-1) 

For the Write tool path, the hook computes `check_patterns()` over the new `content` and separately over the baseline content, then removes from the reminder set any `ruleName` that was already present in the baseline set (per the described `main()` logic: "For Write tool, filter out patterns that existed in the baseline version"). Since `check_patterns()` only returns rule identity and not match specifics, this filter cannot distinguish "the same benign occurrence still present" from "a different, more dangerous occurrence of the same rule." An attacker who controls repository content prior to the session baseline (e.g., commits a file containing one innocuous `pickle.loads(fixed_bytes)` call) causes `pickle_deserialization` to land in `baseline_matches` for that file. If Claude subsequently uses the Write tool to rewrite that file — replacing the benign call with `pickle.loads(attacker_controlled_source)` on network/file-derived data — the new content still trips the `pickle_deserialization` rule, but because the rule name is already in `baseline_matches`, the reminder is suppressed entirely, even though the actual exploitable line is new and unrelated to the original occurrence.

No existing check (approval prompt, allowlist, workspace guard, or content-diff at the match level) mitigates this: the suppression only ever compares rule names, never the underlying matched code fragment.

### Impact Explanation
This is a security-control bypass: the plugin's PostToolUse pattern-warning feature is a defense-in-depth signal meant to flag every reintroduction of a dangerous construct. An attacker with only ordinary repo-content control (no elevated privileges) can neutralize this specific warning for a targeted file/rule pair for the rest of the session by pre-seeding a trivial occurrence before the baseline snapshot is taken. This silently reintroduces or expands unsafe deserialization (or any other pattern-based rule) without any PostToolUse warning being surfaced to Claude or the user, undermining the tool's "must warn on dangerous constructs" invariant.

### Likelihood Explanation
Feasible and repeatable: the attacker only needs write access to repository content that will exist in the working tree at the time `UserPromptSubmit` captures the baseline (i.e., ordinary contribution to the checked-out repo, no privileged access, no session/key compromise). The precondition (Claude using `Write` rather than `Edit` on that file at least once per session) is common in normal coding workflows (e.g., "rewrite this file to add X"). Once satisfied, the bypass is deterministic on every subsequent Write to that file within the session, since `baseline_matches` is computed once from the fixed baseline SHA.

### Recommendation
Track dedup state at the level of the actual matched fragment (e.g., the specific substring/line or a hash of the matched span) rather than by `ruleName` alone. `check_patterns()` should be extended to return match spans/snippets, and the Write-path baseline filter should only suppress a reminder when the identical matched snippet (not merely the rule) is present in both baseline and new content. Alternatively, always warn on Write for security-sensitive rules and only suppress when the new content's matched region is byte-identical to a baseline match.

### Proof of Concept
Integration test plan:
1. Set up a fake git repo/session state where `load_baseline_sha()` returns a SHA whose checked-out version of `target.py` contains a single benign line, e.g. `pickle.loads(b"\x80\x04.")`.
2. Mock/patch `get_baseline_file_content()` to return that baseline content for `target.py`.
3. Invoke the Write-tool PostToolUse handler (`main()`'s Write-path logic) with `tool_input = {"file_path": "target.py", "content": "<other code>\npickle.loads(attacker_controlled_bytes)\n"}` — a distinct, genuinely dangerous line differing from the baseline occurrence.
4. Call `check_patterns()` on both baseline and new content to obtain `baseline_matches` (containing `pickle_deserialization`) and `pattern_matches` for the new content (also containing `pickle_deserialization`).
5. Assert that, under the existing dedup (`r not in baseline_matches`), the `pickle_deserialization` reminder is dropped from the emitted PostToolUse `additionalContext`/reminder output — demonstrating the reminder is incorrectly suppressed for a materially different, more dangerous line.
6. Expected (fixed) behavior: the reminder should still fire because the matched pickle-deserialization line in the new content differs from the one recorded in the baseline snapshot.

```python
def check_patterns(file_path, content):
    """Check if file path or content matches any security patterns. Returns ALL matches."""
    normalized_path = file_path.lstrip("/")
    matches = []

    for pattern in list(SECURITY_PATTERNS) + extensibility.user_patterns():
        # path_filter is a gate: when present, the rule only applies to
        # matching paths. Distinct from path_check, which is itself a
        # positive match condition (e.g. .github/workflows/).
        if "path_filter" in pattern:
            try:
                if not pattern["path_filter"](normalized_path):
                    continue
            except Exception:
                continue

        matched = False

        if "path_check" in pattern:
            try:
                if pattern["path_check"](normalized_path):
                    matched = True
            except Exception:
                pass

        if not matched and "substrings" in pattern and content:
            for substring in pattern["substrings"]:
                if substring in content:
                    matched = True
                    break

        if not matched and "regex" in pattern and content:
            try:
                if re.search(pattern["regex"], content):
                    matched = True
            except Exception:
                pass

        if matched:
            matches.append((pattern["ruleName"], pattern["reminder"]))

    return matches
```

```python
def get_baseline_file_content(session_id, file_path, cwd):
    """Get the content of a file at the baseline SHA. Returns None if unavailable."""
    baseline_sha = load_baseline_sha(session_id)
    if not baseline_sha:
        return None
    try:
        abs_path = os.path.abspath(file_path)
        cwd_abs = os.path.abspath(cwd) if cwd else os.getcwd()
        try:
            rel_path = os.path.relpath(abs_path, cwd_abs)
        except ValueError:
            return None
        result = subprocess.run(
            [*GIT_CMD, "show", f"{baseline_sha}:{rel_path}"],
            cwd=cwd, capture_output=True, text=True, timeout=5
        )
        if result.returncode == 0:
            return result.stdout
        return None
    except (subprocess.TimeoutExpired, FileNotFoundError, OSError):
        return None
```
