### Title
Unauthorized permanent loss of native funds via WERC20 precompile nonpayable methods lacking `msg.value` check - (File: `precompiles/werc20/werc20.go`)

### Summary
The WERC20 precompile embeds `erc20.Precompile` but overrides `Execute` with its own implementation that dispatches directly to `p.HandleMethod` for all non-`deposit`/`withdraw` ERC-20 methods (`transfer`, `transferFrom`, `approve`, view methods), skipping the parent `erc20.Precompile.Execute` value check [1](#0-0) . Any native value attached to a call routed to `transfer`/`transferFrom`/`approve` on the WERC20 precompile is transferred by the EVM to the precompile's account but never returned, refunded, or accounted for, permanently stranding the caller's native funds.

### Finding Description
`erc20.Precompile.Execute` explicitly guards against receiving funds because the precompile "is not managed by an EOA and will not be possible to recover funds sent to an instance of them" [1](#0-0) . WERC20 is meant to add payable `deposit`/`withdraw` semantics on top of the ERC-20 precompile, and its own `Execute` implementation shadows (overrides) the parent's `Execute`, entirely omitting that value check: [2](#0-1) 

Only the `Deposit` handler consumes `contract.Value()` and sends it back to the caller via `BankKeeper.SendCoins` from the precompile's derived account address to the caller [3](#0-2) . `Withdraw` is a documented no-op that only validates balance and emits an event, without moving any funds [4](#0-3) ; this is safe by itself because `withdraw` is `nonpayable` in the ABI, so no value should reach it under normal EVM ABI-encoding conventions. However, `transfer`, `transferFrom`, and `approve` are also nonpayable per the IWERC20/ERC20 ABI, yet since a caller controls raw calldata and value independently at the EVM `CALL` level (not enforced by the ABI at the protocol level), a caller (or an intermediate contract) can attach `value > 0` to a call whose calldata selects `transfer`/`approve`/`transferFrom`. The EVM's standard value-transfer semantics move that native balance into the precompile's account (`sdk.AccAddress(p.Address().Bytes())`) as part of invoking `Run`/`Execute`, exactly as documented for `deposit` [5](#0-4) . Because `HandleMethod` (inherited unmodified from `erc20.Precompile`) never inspects or refunds `contract.Value()` [6](#0-5) , and WERC20's own `Execute` skips the parent's value check entirely, those native tokens are absorbed into the precompile's account balance with no code path to reclaim them: `Deposit` only forwards the value of the *current* call's `contract.Value()`, not the precompile's total accumulated balance, so a later `deposit()` call with `value: 0` returns nothing.

### Impact Explanation
This matches the "Critical permanent freezing, locking, theft, or unauthorized extraction of user funds" impact category. Any EOA or contract that attaches native value to a `transfer`, `transferFrom`, or `approve` call on the WERC20 precompile (e.g., due to a wallet/dApp bug, a naive DeFi integration pattern like `wrappedNative.transfer{value: x}(...)`, or a malicious frontrunning/mis-encoded transaction) irreversibly loses those funds, with no recovery mechanism in the contract.

### Likelihood Explanation
Reachable by any unprivileged EVM account with no special permissions—simply calling the WERC20 precompile address with a `transfer`/`approve`/`transferFrom` selector and non-zero `value`. This is a natural mistake for integrators who mentally treat WERC20 like WETH (where sending value to non-payable methods normally just reverts due to Solidity's default nonpayable guard, but here that guard doesn't exist at the precompile layer since Go execution is not enforcing Solidity's implicit `msg.value == 0` check for nonpayable functions).

### Recommendation
Add the same guard from `erc20.Precompile.Execute` into `werc20.Precompile.Execute` for any method that isn't `Deposit`/fallback/receive — i.e., reject the call (or route the value into `Deposit` handling) whenever `contract.Value().Sign() == 1` and the resolved method is not the deposit path:
```go
if method.Name != DepositMethod && method.Type != abi.Fallback && method.Type != abi.Receive {
    if contract.Value().Sign() == 1 {
        return nil, fmt.Errorf(cmn.ErrCannotReceiveFunds, contract.Value().String())
    }
}
```

### Proof of Concept
1. Deploy/point at a WERC20 token pair precompile address `P`.
2. From an EOA, craft a raw transaction/`eth_call` targeting `P` with `data` = ABI-encoded `transfer(recipient, amount)` selector, and `value` = 1 native token unit.
3. The EVM transfers 1 unit of native balance from the caller to `P`'s underlying account as part of standard `CALL` value semantics.
4. `werc20.Precompile.Execute` resolves `method.Name == "transfer"`, hits the `default` branch, and calls `p.HandleMethod`, which performs the ERC-20 `transfer` logic but never inspects `contract.Value()`.
5. The 1 unit of native balance now sits at `P`'s account permanently; no `deposit`, `withdraw`, or ERC-20 method can move it back to any user, since `Deposit` only forwards the value from its own call context and `Withdraw` performs no transfer.

```go
func (p *Precompile) HandleMethod(
	ctx sdk.Context,
	contract *vm.Contract,
	stateDB vm.StateDB,
	method *abi.Method,
	args []interface{},
) (bz []byte, err error) {
	switch method.Name {
	// ERC-20 transactions
	case TransferMethod:
		bz, err = p.Transfer(ctx, contract, stateDB, method, args)
	case TransferFromMethod:
		bz, err = p.TransferFrom(ctx, contract, stateDB, method, args)
	case ApproveMethod:
		bz, err = p.Approve(ctx, contract, stateDB, method, args)

	case NameMethod:
		bz, err = p.Name(ctx, contract, stateDB, method, args)
	case SymbolMethod:
		bz, err = p.Symbol(ctx, contract, stateDB, method, args)
	case DecimalsMethod:
		bz, err = p.Decimals(ctx, contract, stateDB, method, args)

		bz, err = p.TotalSupply(ctx, contract, stateDB, method, args)
```

```go
func (p Precompile) Execute(ctx sdk.Context, stateDB vm.StateDB, contract *vm.Contract, readOnly bool) ([]byte, error) {
	method, args, err := cmn.SetupABI(p.ABI, contract, readOnly, p.IsTransaction)
	if err != nil {
		return nil, err
	}

	var bz []byte

	switch {
	case method.Type == abi.Fallback,
		method.Type == abi.Receive,
		method.Name == DepositMethod:
		bz, err = p.Deposit(ctx, contract, stateDB)
	case method.Name == WithdrawMethod:
		bz, err = p.Withdraw(ctx, contract, stateDB, args)
	default:
		// ERC20 transactions and queries
		bz, err = p.HandleMethod(ctx, contract, stateDB, method, args)
	}

	return bz, err
}
```

```go
// Deposit handles the payable deposit function. It retrieves the deposited amount
// and sends it back to the sender using the bank keeper.
func (p Precompile) Deposit(
	ctx sdk.Context,
	contract *vm.Contract,
	stateDB vm.StateDB,
) ([]byte, error) {
	caller := contract.Caller()
	depositedAmount := contract.Value()

	callerAccAddress := sdk.AccAddress(caller.Bytes())
	precompileAccAddr := sdk.AccAddress(p.Address().Bytes())

	// Send the coins back to the sender
	if err := p.BankKeeper.SendCoins(
		ctx,
		precompileAccAddr,
		callerAccAddress,
		sdk.NewCoins(sdk.Coin{
			Denom:  evmtypes.GetEVMCoinExtendedDenom(),
			Amount: math.NewIntFromBigInt(depositedAmount.ToBig()),
		}),
	); err != nil {
		return nil, err
	}

	if err := p.EmitDepositEvent(ctx, stateDB, caller, depositedAmount.ToBig()); err != nil {
		return nil, err
	}

	return nil, nil
}
```

```go
// Withdraw is a no-op and mock function that provides the same interface as the
// WETH contract to support equality between the native coin and its wrapped
// ERC-20 (e.g. ATOM and WEVMOS).
func (p Precompile) Withdraw(ctx sdk.Context, contract *vm.Contract, stateDB vm.StateDB, args []interface{}) ([]byte, error) {
	amount, ok := args[0].(*big.Int)
	if !ok {
		return nil, fmt.Errorf("invalid argument type: %T", args[0])
	}
	amountInt := math.NewIntFromBigInt(amount)

	caller := contract.Caller()
	callerAccAddress := sdk.AccAddress(caller.Bytes())
	nativeBalance := p.BankKeeper.SpendableCoin(ctx, callerAccAddress, evmtypes.GetEVMCoinDenom())
	if nativeBalance.Amount.Mul(types.ConversionFactor()).LT(amountInt) {
		return nil, fmt.Errorf("account balance %v is lower than withdraw balance %v", nativeBalance.Amount, amountInt)
	}

	if err := p.EmitWithdrawalEvent(ctx, stateDB, caller, amount); err != nil {
		return nil, err
	}
	return nil, nil
```
