### Title
Partial line-selection is preserved across a working-directory status refresh keyed only on `kind+path`, allowing silent corruption of what a user commits - ([File: app/src/lib/stores/updates/changes-state.ts])

### Summary
`updateChangedFiles` re-attaches a file's *previous* `DiffSelection` (which tracks selected/deselected lines by numeric index) to the *new* `WorkingDirectoryFileChange` purely by matching `FileChange.id`, and `id` is derived only from `${status.kind}+${path}` (or with `oldPath` for renames), never from file content. [1](#0-0) [2](#0-1)  If the on-disk content of the tracked file changes between two `git status` refreshes (same path, same status kind, e.g. still `Modified`), the old line-index-based selection is blindly reused for the new diff.

### Finding Description
`WorkingDirectoryFileChange` selection state (`DiffSelection`) stores selected/deselected lines as a set of numeric line indices, not as content hashes or line contents. [3](#0-2) 

When the app refreshes status (`_loadStatus` → `updateChangedFiles`), it maps the new `status.workingDirectory.files` against the previous `state.workingDirectory.files` using `file.id` as the lookup key and reuses `existingFile.selection` verbatim if the id matches: [1](#0-0) 

The subsequent diff reload (`updateChangesWorkingDirectoryDiff`) only recomputes the *set of selectable line indices* from the newly loaded diff and calls `withSelectableLines`, which merely intersects the old diverging-line index set with the new selectable set - it does not check whether those indices still correspond to the same textual content: [4](#0-3) 

Because `id = status.kind + path`, two completely different diffs for the same path/kind (e.g., `Modified+file.txt`) are treated as "the same file" for selection-preservation purposes. If the content of a tracked file is rewritten on disk between the moment the user makes a partial line selection and the moment Desktop reloads status/diff for that file (e.g., triggered by a `post-checkout`/`post-merge` git hook shipped in a cloned/fetched attacker-controlled repository, which Desktop executes as part of normal pull/checkout/merge operations - see `app/src/lib/hooks/hooks-proxy.ts`, `app/src/lib/git/merge.ts`, `app/src/lib/git/pull.ts`), the same numeric line indices the user previously reviewed and selected get silently reapplied to entirely different line content.

### Impact Explanation
This breaks the invariant that "the lines the user visually selected in the diff viewer are the exact lines that get committed." An attacker-controlled repository containing a malicious `post-merge`/`post-checkout` hook (executed automatically by git during normal `pull`/`checkout`/`merge` operations the user performs through Desktop, not via any unnatural extra step) can rewrite a tracked file's content while the user has an in-flight partial selection on that same path/status-kind. When Desktop's next status/diff refresh completes, the stale line-index selection is reapplied to the attacker-modified content, so the user can end up committing and pushing lines they never reviewed - a silent corruption of what is committed, matching the explicitly allowed impact class ("silent corruption of what the user commits or pushes").

### Likelihood Explanation
Requires: (1) an attacker-controlled repository the victim clones/pulls/merges from, containing a git hook that modifies a tracked file when triggered by a normal Desktop-initiated git operation, and (2) the user having an active partial line selection on that file at the time of the refresh (a plausible, common workflow - reviewing/partially staging a file, then pulling/merging while the Changes tab stays open). No admin rights, local access, or leaked credentials are needed; the only precondition is a race between a background/foreground git operation and the existing selection state, which is realistic in normal Desktop usage (auto/background fetch + status refresh loops exist, e.g. `refreshIndicatorForRepository`).

### Recommendation
Bind selection preservation to more than `kind+path` - e.g., compare a content fingerprint (blob OID or diff hash) of the file at the time of selection versus the time of reload, and clear (or re-validate against actual line content, not just index) the partial selection whenever the underlying content differs, not just when the selectable-line-count changes.

### Proof of Concept
1. Clone/add an attacker-controlled repository that includes a `post-merge` hook which appends/rewrites lines in `tracked.txt` whenever a merge/pull completes.
2. In Desktop, modify `tracked.txt` locally and partially select a subset of lines (e.g., lines 1–3) for commit, leaving the diff view open.
3. Pull/merge from the remote (a normal action) - the hook fires and rewrites `tracked.txt` with different content but keeps the file's status as `Modified` (same `id`).
4. Desktop's background status refresh calls `updateChangedFiles`, matching the file by `id` and carrying over the old `DiffSelection` (line indices 1–3).
5. The diff viewer reloads the new diff and recomputes `selectableLines`; if indices 1–3 remain selectable in the new diff (common for typical edits), the previously-selected indices remain selected against the new content.
6. The user commits, believing they are committing the content they originally reviewed, but the actual committed content differs - silent corruption of the commit.

/**
 * An immutable, efficient, storage object for tracking selections of indexable
 * lines. While general purpose by design this is currently used exclusively for
 * tracking selected lines in modified files in the working directory.
 *
 * This class starts out with an initial (or default) selection state, ie
 * either all lines are selected by default or no lines are selected by default.
 *
 * The selection can then be transformed by marking a line or a range of lines
 * as selected or not selected. Internally the class maintains a list of lines
 * whose selection state has diverged from the default selection state.
 */
export class DiffSelection {
  /**
   * Initialize a new selection instance where either all lines are selected by default
   * or not lines are selected by default.
   */
  public static fromInitialSelection(
    initialSelection: DiffSelectionType.All | DiffSelectionType.None
  ): DiffSelection {
    if (
      initialSelection !== DiffSelectionType.All &&
      initialSelection !== DiffSelectionType.None
    ) {
      return assertNever(
        initialSelection,
        'Can only instantiate a DiffSelection with All or None as the initial selection'
      )
    }

    return new DiffSelection(initialSelection, null, null)
  }

  /**
   * @param divergingLines Any line numbers where the selection differs from the default state.
   * @param selectableLines Optional set of line numbers which can be selected.
   */
  private constructor(
    private readonly defaultSelectionType:
      | DiffSelectionType.All
      | DiffSelectionType.None,
    private readonly divergingLines: Set<number> | null = null,
    private readonly selectableLines: Set<number> | null = null
  ) {}
