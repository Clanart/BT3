### Title
Scanner accepts and transaction builder spends dust outputs whose spend cost exceeds their value — ([File: networks/bitcoin/src/wallet/mod.rs])

### Summary
The referenced bug class is "no minimum-size threshold lets unprivileged actors create economically dead positions that accumulate and are never worth servicing." Serai's Bitcoin wallet exhibits the same class: `Scanner::scan_transaction` registers any output paying to a tracked script with no minimum-value check, and `SignableTransaction::new` includes caller-supplied inputs without checking that each input's value exceeds the marginal fee cost of spending it. An unprivileged party can send dust outputs to Serai's publicly known P2TR script, creating inputs that are unspendable at a profit — spending one costs more in added transaction weight than the input contributes.

### Finding Description
`Scanner::scan_transaction` matches solely on `script_pubkey` and returns a `ReceivedOutput` for any value, including 1 sat:

```rust
// networks/bitcoin/src/wallet/mod.rs
if let Some(offset) = self.scripts.get(&output.script_pubkey) {
  res.push(ReceivedOutput { offset: *offset, output: output.clone(), ... });
}
``` [1](#0-0) 

Likewise `ReceivedOutput::read` accepts any `TxOut` value from untrusted bytes [2](#0-1) .

The only minimum-value enforcement in the wallet crate is `DUST = 546`, and it is applied to *payments* (outputs Serai creates), never to *inputs* (outputs Serai received):

```rust
// networks/bitcoin/src/wallet/send.rs
for (_, amount) in payments {
  if *amount < DUST {
    Err(TransactionError::DustPayment)?;
  }
}
``` [3](#0-2) 

Inputs are summed and used with no per-input economic check [4](#0-3) . Each Taproot input adds ~230 weight units (~58 vbytes) to the transaction; at a fee rate above ~9 sat/vbyte, spending a 546-sat input is net-negative, and below-dust inputs (creatable by miners or non-standard relay) are unspendable entirely. The scheduler logic that would filter these at the processor layer (`output.balance().amount.0 >= N::DUST`, `DUST = 10_000`) lives outside the wallet crate; the wallet itself reports and accepts the dust unconditionally.

### Impact Explanation
- Funds reported received that are not spendable: `Scanner` emits `ReceivedOutput`s for dust that can never be spent profitably, skewing accounting of available funds.
- Fee drain: when such outputs are passed to `SignableTransaction::new`, they are included as inputs whose marginal fee cost exceeds their value, burning the pool's funds — the analog of "liquidations that cost more than they recover."
- Accumulation: an attacker can mint arbitrary numbers of these dust outputs at near-zero cost, mirroring the unliquidatable-dust accumulation in the source report.

### Likelihood Explanation
The attack requires only sending standard Bitcoin transactions to a publicly derivable P2TR script — fully unprivileged, no collusion or validator misbehavior needed. Whether the dust is actually consumed depends on the caller's input selection (out of scope here), but the wallet layer provides no defense and reports the dust as spendable funds.

### Recommendation
- Enforce a minimum output value in `Scanner`/`ReceivedOutput` acceptance (e.g., the `DUST` constant or a spend-cost-based floor) so sub-economical outputs are never reported.
- In `SignableTransaction::new`, reject or skip inputs whose value is below the marginal fee cost of adding one input (`fee_per_vbyte * per-input vbytes`).

### Proof of Concept
1. Obtain the multisig's tweaked group key and compute its P2TR script via `p2tr_script_buf`.
2. Broadcast a transaction with an output of 546 sats (or less, via a miner) to that script.
3. `Scanner::scan_transaction` returns a `ReceivedOutput` for it.
4. Pass it as an input to `SignableTransaction::new` with `fee_per_vbyte = 10`: the input contributes 546 sats but adds ~58 vbytes ≈ 580 sats of required fee — a net loss that `SignableTransaction::new` accepts without error.

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
```
