### Title
Gasless lending value-movement bypasses the "sender has code" restriction because it is only checked at tx-pool admission, not at bundle/block-building execution - ([File: kaiax/gasless/impl/getter.go])

### Summary
The Dinari bug shows a pattern where an access-control restriction (blacklist) is enforced on ordinary `transfer` but is skipped on the actual value-movement operations (`mint`/`burn`), letting a restricted actor still receive/realize value through the unguarded path. The Kaia `kaiax/gasless` module reproduces the same pattern: the "sender must not have code" restriction is enforced only when a gasless approve/swap transaction is admitted to the tx pool, but the actual value-movement action — the proposer-funded `LendTx` created at block-building time — is generated and inserted without re-checking that restriction against the state at build time.

### Finding Description
`ShouldCheckSenderCode()` gates a check meant to prevent contract accounts from using the gasless-lending mechanism: [1](#0-0) 

That check is performed inside `checkBalanceForApprove` / `checkBalanceForSwap`, which are only invoked through `GetCheckBalance()` at tx-pool admission time (`pool.add` → `pool.validateTx` → `module.GetCheckBalance()`): [2](#0-1) [3](#0-2) [4](#0-3) 

However, the actual value-movement step — minting/lending real KAIA to the sender via `GetLendTxGenerator`, which is the "mint"-analog operation that pays out real value from the block proposer to the sender before the swap repays it — is produced during block assembly by `ExtractTxBundles`, which only calls `IsExecutable`/`VerifyExecutable`: [5](#0-4) [6](#0-5) [7](#0-6) 

`VerifyExecutable` validates decode-ability, sender consistency, token consistency, approval amount, nonce ordering, and repay-amount correctness — but it contains **no** call to `checkBalanceForApprove`/`checkBalanceForSwap`, and therefore never re-evaluates `ShouldCheckSenderCode()` against the state at the time the `LendTx` (the actual value-transferring transaction) is generated: [8](#0-7) 

Because the sender-code check is enforced only once, at the moment the approve/swap tx entered the pool, and the `LendTx` that performs the real KAIA transfer is synthesized later at block-building time from current chain state (`g.Chain.CurrentBlock()`), any state transition between admission and block-building (e.g., the sender's EOA becomes a contract account in an earlier transaction of the very same block, via account abstraction/AccountKey update or another mechanism that installs code) is not re-validated. The restriction that is supposed to gate the money-moving step is checked on the wrong step, exactly as in the reported bug where the blacklist check on `transfer` never propagated to `mint`/`burn`.

### Impact Explanation
`ShouldCheckSenderCode` exists specifically to keep the gasless-lending/repay mechanism restricted to EOA-like senders (`BalanceCheckLevelAll`), presumably to prevent contract accounts from gaming or exploiting the lend/repay settlement (e.g., reentrancy during repayment, or arbitrary logic execution while holding proposer-lent KAIA). Because this restriction is validated only at admission and not at the point where the value (`LendTx`) is actually generated and included in the block, an attacker who can cause their sender address to acquire code between tx-pool admission and block assembly can bypass the restriction and receive proposer-funded KAIA through the gasless flow that was supposed to be reserved for EOAs. This is a fee/settlement-abuse vector directly analogous to bypassing the blacklist via the unguarded mint/burn path.

### Likelihood Explanation
Exploitability depends on the attacker's ability to change their account's code status (become a contract account) between the time their gasless approve/swap transaction is queued and the time the block containing it is built — both of which are reachable from a single submitted bundle/transaction sequence by an unprivileged sender, without requiring any privileged, network, or off-chain actor. Given Kaia's account model changes (AccountKey / EOA delegation features) can alter account code state within the same block, this is plausible, though the exact mechanics of forcing "hasCode" to flip between admission and build for one's own sender in a single block were not independently verified within the scope of this review.

### Recommendation
Re-validate `ShouldCheckSenderCode()` (and ideally the other balance/allowance/deadline checks currently confined to `checkBalanceForApprove`/`checkBalanceForSwap`) inside `VerifyExecutable`/`IsExecutable`, i.e., at the moment `GetLendTxGenerator`'s bundle is actually assembled for block building, using the state as of that point — not only at tx-pool admission time. This closes the gap between the "transfer-like" admission check and the "mint-like" value-movement step, consistent with the recommendation in the referenced report to check restrictions at every point where value moves, not just at one entry point.

### Proof of Concept
1. Attacker submits a valid `GaslessApproveTx` + `GaslessSwapTx` pair from an EOA address `A` that currently has no code; `checkBalanceForApprove`/`checkBalanceForSwap` pass the `ShouldCheckSenderCode` check and the pair is admitted to the pool (`kaiax/gasless/impl/tx_pool.go:74-126`).
2. Before/within the same block being built, the attacker causes address `A` to acquire code (e.g., via an account-code-setting transaction executed earlier in block construction).
3. During block assembly, `ExtractTxBundles` (`kaiax/gasless/impl/builder.go:28-72`) calls `IsExecutable`/`VerifyExecutable` (`kaiax/gasless/impl/getter.go:203-266`), which does not re-check `hasCode(A)`, and proceeds to call `GetLendTxGenerator` (`kaiax/gasless/impl/getter.go:268-313`) to synthesize a real value-transferring `LendTx` paying KAIA from the proposer to `A`.
4. The bundle `[LendTx, ApproveTx, SwapTx]` is included in the block; `A`, now a contract account, has received proposer-funded KAIA through a channel that was supposed to be restricted to code-less senders — the restriction was bypassed exactly as blacklist checks were bypassed via mint/burn in the referenced report.

func (g *GaslessModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	// there are only at most two gasless transactions in pending for a sender
	bundles := []*builder.Bundle{}
	approveTxs := map[common.Address]*types.Transaction{}
	targetTxHash := common.Hash{}
	for _, tx := range txs {
		addr, err := types.Sender(g.signer, tx)
		if err != nil {
			continue
		}
		if g.IsApproveTx(tx) {
			approveTxs[addr] = tx
		} else if g.IsSwapTx(tx) && g.IsExecutable(approveTxs[addr], tx) {
			bundleTxs := builder.NewTxOrGenList(g.GetLendTxGenerator(approveTxs[addr], tx))
			if approveTxs[addr] != nil {
				bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(approveTxs[addr]))
			}
			bundleTxs = append(bundleTxs, builder.NewTxOrGenFromTx(tx))

			b := builder.NewBundle(
				bundleTxs,
				targetTxHash,
				false,
			)

			targetTxHash = tx.Hash()

			isConflict := false
			for _, prev := range append(prevBundles, bundles...) {
				if prev.IsConflict(b) {
					isConflict = true
					break
				}
			}
			if isConflict {
				// Gasless transactions will just fail even if they aren't bundled.
				continue
			}
			bundles = append(bundles, b)
		} else {
			targetTxHash = tx.Hash()
		}
	}
	return bundles
}

// VerifyExecutable checks if the given transactions form a valid gasless transaction
// It returns an error explaining why the transaction is not executable if it's not,
// and a boolean indicating whether the transaction is executable
func (g *GaslessModule) VerifyExecutable(approveTxOrNil, swapTx *types.Transaction) error {
	// Sx.
	swapArgs, ok := decodeSwapTx(swapTx, g.signer)
	if !ok {
		return ErrDecodeSwapTx
	}
	if !g.isSwapTx(swapArgs) {
		return ErrSwapTxInvalid
	}

	// Conditions involving ApproveTx
	if approveTxOrNil != nil {
		// Ax.
		approveArgs, ok := decodeApproveTx(approveTxOrNil, g.signer)
		if !ok {
			return ErrDecodeApproveTx
		}
		if !g.isApproveTx(approveArgs) {
			return ErrApproveTxInvalid
		}
		// AP1.
		if approveArgs.Sender != swapArgs.Sender {
			return ErrDifferentSenders
		}
		// SP1.
		if approveArgs.Token != swapArgs.Token {
			return fmt.Errorf("%w: approve token %s, swap token %s", ErrDifferentTokens, approveArgs.Token.Hex(), swapArgs.Token.Hex())
		}
		// SP2.
		if approveArgs.Amount.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("%w: approve amount %s, required amount %s", ErrInsufficientApproveAmount, approveArgs.Amount.String(), swapArgs.AmountIn.String())
		}
		// SP3.
		if approveTxOrNil.Nonce()+1 != swapTx.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, swap nonce %d (expected %d)", ErrNonSequentialNonce, approveTxOrNil.Nonce(), swapTx.Nonce(), approveTxOrNil.Nonce()+1)
		}
		if nonce := g.getCurrentStateNonce(approveArgs.Sender); nonce != approveTxOrNil.Nonce() {
			return fmt.Errorf("%w: approve nonce %d, current nonce %d", ErrApproveNonceNotCurrent, approveTxOrNil.Nonce(), nonce)
		}
	} else {
		// SP3.
		if nonce := g.getCurrentStateNonce(swapArgs.Sender); nonce != swapTx.Nonce() {
			return fmt.Errorf("%w: swap nonce %d, current nonce %d", ErrSwapNonceNotCurrent, swapTx.Nonce(), nonce)
		}
	}

	// SP4.
	if swapArgs.AmountRepay.Cmp(repayAmount(approveTxOrNil, swapTx)) != 0 {
		return fmt.Errorf("%w: got %s, expected %s", ErrIncorrectRepayAmount, swapArgs.AmountRepay.String(), repayAmount(approveTxOrNil, swapTx).String())
	}

	return nil
}

// MakeLendTx creates a transaction with following properties:
// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)
// L2. LendTx.from = proposer
// L3. LendTx.to = SwapTx.from
// L4. LendTx.value = LendAmount(approveTxOrNil, swapTx)
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}
