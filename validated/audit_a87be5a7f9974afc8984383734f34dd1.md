### Title
Improper output neutralization of terminal escape sequences in Kaia's structured logger allows RPC-supplied strings to tamper with/hide log output - (File: `log/format.go`)

### Summary
Kaia's shared log formatting code path (`log.TerminalFormat` / `log.LogfmtFormat`, both backed by `formatLogfmtValue`/`escapeString`) only escapes a narrow set of characters (`\`, `"`, `\n`, `\r`, `\t`) and otherwise writes arbitrary control bytes — including the ANSI escape character `ESC` (`0x1b`) — verbatim into the emitted log line. [1](#0-0)  Any string value that is attacker-influenced and gets logged through this path (for example the JSON-RPC `method` field of a request, which is echoed back into logs on error) can therefore carry raw terminal control sequences into the node's log stream, whether that stream is an interactive terminal or a plain log file. This is the same bug class as CVE-2025-54389 (AIDE): attacker-controlled strings are not neutralized before being written to a report/log, letting an attacker hide or spoof log content.

### Finding Description
The formatter used for both the human-oriented terminal format and the machine-parseable `logfmt` format routes string values through `formatLogfmtValue`, which for the `string` case calls `escapeString(v)`. [2](#0-1)  `escapeString` decides whether quoting/escaping is needed based only on space, `=`, and `"` characters, and only *escapes* backslash, quote, newline, carriage return, and tab — every other rune, including `ESC` (0x1b) and other C0/C1 control codes, is written through unchanged via `e.WriteRune(r)`. [3](#0-2)  This applies uniformly to `TerminalFormat` (colorized stdout/stderr) and `LogfmtFormat` (used for file-based logs), both of which call the shared `logfmt` helper. [4](#0-3) 

A concrete attacker-reachable sink is the public JSON-RPC error logger. `newNewRelicHTTPHandler` parses every incoming JSON-RPC request via `getRPCRequests`, which returns the caller-supplied `Method` field with no sanitization, and stores it in `reqMethod`. [5](#0-4) [6](#0-5)  If the response body contains an RPC error, `printRPCErrorLog` logs that raw method string directly as a `logger.Error(... "method", method)` field. [7](#0-6)  Since the node's default log handler is `TerminalFormat`/`LogfmtFormat` (configured in `api/debug/flags.go`'s `Setup`), the unescaped `ESC` bytes in the attacker-chosen `method` value pass straight into the operator-facing log stream. [8](#0-7) 

Any public RPC caller can trigger this simply by sending a JSON-RPC request whose `"method"` field is any string that causes an error response (e.g., an unknown/invalid method name) while embedding ANSI/VT100 control sequences in that same string (Kaia does not validate the syntax of `method` before this code path runs).

### Impact Explanation
An attacker (any unauthenticated public-RPC caller) can inject terminal control sequences into the node operator's logs. Depending on payload, this can:
- Clear or overwrite the display of preceding log lines when viewed live in a terminal, hiding evidence of malicious/probing RPC traffic.
- Forge fake log lines (cursor repositioning + overwrite) that could mislead operators or automated terminal-based monitoring.
- Corrupt or desynchronize terminal state of any operator who tails logs interactively.

This mirrors the AIDE CVE's core impact: a detection/monitoring pipeline can be blinded or spoofed by attacker-controlled, improperly neutralized strings, undermining incident response and auditability of a Kaia node without requiring any privileged access — only the ability to send a public RPC request.

### Likelihood Explanation
Likelihood is high for occurrence but the practical severity depends on operational log consumption (interactive terminal viewing vs. structured ingestion). Any unauthenticated user with network access to a node's JSON-RPC endpoint can trigger this with a single crafted request containing an invalid/error-inducing method name embedding escape bytes — no special permissions, gas payment, or on-chain state are required. JSON-formatted logs (`log.JsonFormat`) are not affected because Go's `encoding/json` marshaling escapes control characters, but the default and commonly used `terminal`/`logfmt` formats are affected.

### Recommendation
Update `escapeString` in `log/format.go` to treat all C0 control characters (0x00–0x1F) and DEL (0x7F), not just `\n`, `\r`, `\t`, `\\`, `"`, as requiring escaping (e.g., emit `\xNN` or drop/replace them), matching the fix approach used upstream for the analogous AIDE issue. Apply the same neutralization to any value implementing `TerminalStringer` before it's written out, and audit sinks like `printRPCErrorLog` to ensure request-derived strings (`method`, headers) are sanitized independent of the logger's own escaping.

### Proof of Concept
1. Start a Kaia node with default logging (`--log.format terminal` or the default `logfmt`).
2. Send a JSON-RPC POST request to the node's public HTTP RPC endpoint with a `method` field crafted to (a) be invalid/erroring and (b) contain an ANSI escape sequence, e.g.:
```json
{"jsonrpc":"2.0","id":1,"method":"eth_bogus\u001b[2K\u001b[1G[FAKE] node healthy","params":[]}
```
3. The request fails RPC method resolution, producing an RPC error response; `newNewRelicHTTPHandler` → `printRPCErrorLog` logs the field `method=<raw string>` through `logger.Error`, which is rendered by `TerminalFormat`/`LogfmtFormat` without stripping the embedded `\x1b[2K\x1b[1G` sequence. [7](#0-6) [3](#0-2) 
4. When viewed on an operator's terminal (or replayed through a terminal-emulating tool), the escape sequence clears/overwrites the preceding line and injects the attacker's spoofed "[FAKE] node healthy" text, demonstrating log tampering equivalent to the AIDE report-hiding technique.

func LogfmtFormat() Format {
	return FormatFunc(func(r *Record) []byte {
		common := []interface{}{r.KeyNames.Time, r.Time, r.KeyNames.Lvl, r.Lvl, r.KeyNames.Msg, r.Msg}
		buf := &bytes.Buffer{}
		logfmt(buf, append(common, r.Ctx...), 0, false)
		return buf.Bytes()
	})
}

func escapeString(s string) string {
	needsQuotes := false
	needsEscape := false
	for _, r := range s {
		if r <= ' ' || r == '=' || r == '"' {
			needsQuotes = true
		}
		if r == '\\' || r == '"' || r == '\n' || r == '\r' || r == '\t' {
			needsEscape = true
		}
	}
	if !needsEscape && !needsQuotes {
		return s
	}
	e := stringBufPool.Get().(*bytes.Buffer)
	e.WriteByte('"')
	for _, r := range s {
		switch r {
		case '\\', '"':
			e.WriteByte('\\')
			e.WriteByte(byte(r))
		case '\n':
			e.WriteString("\\n")
		case '\r':
			e.WriteString("\\r")
		case '\t':
			e.WriteString("\\t")
		default:
			e.WriteRune(r)
		}
	}
	e.WriteByte('"')
	var ret string
	if needsQuotes {
		ret = e.String()
	} else {
		ret = string(e.Bytes()[1 : e.Len()-1])
	}
	e.Reset()
	stringBufPool.Put(e)
	return ret
}

// getRPCRequests copies a http request body data and parses RPC requests from the data.
// It returns a slice of RPC request, an indication if these requests are in batch, and an error.
// Ethereum returns []*jsonrpcMessage, which replaces []rpcRequest
func getRPCRequests(r *http.Request) ([]*jsonrpcMessage, bool, error) {
	reqBody, err := io.ReadAll(r.Body)
	if err != nil {
		logger.Error("cannot read a request body", "err", err)
		return nil, false, err
	}

	r.Body = io.NopCloser(bytes.NewReader(reqBody))
	conn := &httpServerConn{Reader: io.NopCloser(bytes.NewReader(reqBody)), Writer: bytes.NewBufferString(""), r: r}

	codec := NewCodec(conn)

	defer codec.close()

	return codec.readBatch()
}

// printRPCErrorLog prints an error log if responseBody contains RPC error message.
// It does nothing if responseBody doesn't contain RPC error message.
func printRPCErrorLog(responseBody []byte, method string, r *http.Request) {
	// check whether the responseBody contains json error
	var rpcError jsonErrResponse
	if err := json.Unmarshal(responseBody, &rpcError); err != nil || rpcError.Error.Code == 0 {
		// do nothing if the responseBody didn't contain json error data
		return
	}

	// parse KAS HTTP header
	kasHeader := parseKASHeader(r)
	kasHeaderJson, err := json.Marshal(kasHeader)
	if err != nil {
		logger.Error("failed to marshal a KAS HTTP header", "err", err, "kasHeader", kasHeader)
	}

	// print RPC error log
	logger.Error("RPC error response", "rpcErr", rpcError.Error.Message, "kasHeader", string(kasHeaderJson),
		"method", method)
}
