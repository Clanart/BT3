### Title
Just-in-time reward sniping in `DelegateVoteRewardPool` via `castVotes()`-triggered `harvestAll()` allows theft of unclaimed delegate-pool yield - (File: `wombat/WombatBribeManager.sol`, `rewards/DelegateVoteRewardPool.sol`)

### Summary
`castVotes()` in `WombatBribeManager` is a fully public, unrestricted function that unconditionally calls `IDelegateVoteRewardPool(delegatedPool).harvestAll()` whenever `delegatedPool` is set. `harvestAll()` harvests bribe rewards and instantly credits them into `rewardPerTokenStored`, pro-rata to whatever `totalSupply`/`_balances` exist at that exact block — with no vesting period, cooldown, or time-weighting. Since `vote()`/`unvote()` let any voter with sufficient locked-MGP voting power instantly stake into and withdraw from the `delegatedPool` entry, an attacker can vote a large amount into `delegatedPool` immediately before a `castVotes()` call, capture a share of the harvested rewards proportional to their balance at that instant, then immediately `unvote()` — diluting and stealing yield that should have accrued to long-term delegate-pool voters.

### Finding Description
`castVotes()` [1](#0-0)  is callable by anyone with no access modifier, and at line 293 it triggers `IDelegateVoteRewardPool(delegatedPool).harvestAll()` [2](#0-1)  whenever a `delegatedPool` is configured.

`harvestAll()` in `DelegateVoteRewardPool` pulls bribe rewards via `claimAllBribes(address(this))` and immediately queues them into the reward index through `_manageRewards` → `_queueNewRewardsWithoutTransfer` [3](#0-2) . Critically, `_queueNewRewardsWithoutTransfer` directly bumps `rewardPerTokenStored` by `amountReward * scale / totalSupply` [4](#0-3)  — an instantaneous, non-vested credit based on whatever `totalSupply` happens to be at that moment, not on how long any staker has held their balance.

`WombatBribeManager.vote()` lets any user (with sufficient `getUserVotable`) increase `userVotedForPoolInVlmgp[msg.sender][delegatedPool]` and calls `stakeFor(msg.sender, delta)` on the `delegatedPool` rewarder [5](#0-4) , which increases `_balances[user]` and `totalSupply` in `DelegateVoteRewardPool`/`BribeRewardPool` with no lock-up [6](#0-5) . `unvote()` symmetrically calls `withdrawFor` immediately, with no cooldown [7](#0-6) , [8](#0-7) .

Because `stakeFor`/`withdrawFor` use the `updateRewards` modifier (standard Synthetix-style: `earned = balance * (rewardPerToken - userRewardPerTokenPaid)`), an attacker who stakes a large balance right before `harvestAll()`'s reward bump, and withdraws (claiming) right after, captures `balance_attacker / totalSupply_at_harvest` of the entire harvested reward — completely disproportionate to time held. Existing checks (`onlyOperator`, `updateRewards`) only gate *who* can call `stakeFor`/`withdrawFor` (only the `WombatBribeManager` operator) and correctly update accounting, but they do nothing to prevent instantaneous stake-then-withdraw sniping around a reward-crediting event. There is no minimum holding period, vesting schedule, or snapshot mechanism protecting long-term voters.

### Impact Explanation
This is a theft of unclaimed yield: long-term delegate-pool voters lose part of their pro-rata share of harvested delegate rewards to an attacker who briefly enters and exits around the `castVotes()`/`harvestAll()` call. This matches the Immunefi impact class "theft of unclaimed yield." The magnitude scales with the size of the attacker's temporary stake relative to existing `totalSupply` and the size of the harvested reward batch.

### Likelihood Explanation
The attacker needs existing locked-MGP voting power (`getUserVotable`) to satisfy the `NotEnoughVote` check in `vote()` [9](#0-8) ; this is not flash-loanable in general (voting power derives from `vlMGP.getUserTotalLocked`), but any real MGP locker can redirect their existing lock's voting weight into `delegatedPool` for a single block and back. `castVotes()` has no access restriction, so the attacker does not even need to front-run someone else — they can call `vote()` then `castVotes()` (or coordinate with the next expected `castVotes()` call, which happens routinely since it is incentivized with a caller fee) in immediate succession, then `unvote()`/`getReward()`. This is fully repeatable every time `castVotes()` is invoked and requires no privileged role, only capital (locked MGP) the attacker already controls.

### Recommendation
Introduce time-weighting or a minimum holding period for `DelegateVoteRewardPool` reward eligibility — e.g., snapshot-based reward accounting, a cooldown between `stakeFor` and `withdrawFor`/reward claim, or accruing rewards continuously over a vesting duration (`rewardRate` over `rewardsDuration`) instead of crediting the entire harvested amount into `rewardPerTokenStored` in a single instantaneous step tied to `totalSupply` at harvest time.

### Proof of Concept
Foundry test outline:
1. Deploy `WombatBribeManager`, `DelegateVoteRewardPool` (as `delegatedPool` rewarder), and a mock Wombat voter/bribe system that yields a fixed bribe reward per `castVotes()` call.
2. Set up two locked-MGP holders: `longTermVoter` who calls `vote()` into `delegatedPool` early and never withdraws, and `flashVoter` who has an equally large (or larger) amount of locked MGP available but idle.
3. Advance several blocks/epochs so `longTermVoter`'s stake has been present through multiple reward-accrual periods.
4. Immediately before calling `castVotes()`, have `flashVoter` call `vote()` to stake a large delta into `delegatedPool`.
5. Call `castVotes(false)`, which triggers `harvestAll()` and credits the harvested reward into `rewardPerTokenStored` based on the new (inflated) `totalSupply`.
6. Immediately after, have `flashVoter` call `unvote(delegatedPool)` (with `claim=true` path) or `getReward` to withdraw and claim.
7. Assert: `flashVoter`'s claimed reward / stake-duration is far larger per unit time than `longTermVoter`'s share, and that `longTermVoter`'s expected `earned()` (computed via time-weighted contribution) is strictly less than it would have been absent `flashVoter`'s deposit — demonstrating dilution/theft of yield proportional to `flashVoter`'s temporary balance at the harvest snapshot.

    function _queueNewRewardsWithoutTransfer(
        uint256 _amountReward,
        address _rewardToken
    ) internal {
        if (!isRewardToken[_rewardToken]) {
            rewardTokens.push(_rewardToken);
            isRewardToken[_rewardToken] = true;
        }
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards =
            rewardInfo.historicalRewards +
            _amountReward;
        if (totalSupply == 0) {
            rewardInfo.queuedRewards += _amountReward;
        } else {
            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;
            }
            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10 ** this.stakingDecimals()) /
                totalSupply;
        }
        emit RewardAdded(_amountReward, _rewardToken);
    }
