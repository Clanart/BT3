### Title
Unbounded Python recursion in wallet outer-puzzle driver matching allows an offer/spend-triggered stack exhaustion - ([File: chia/wallet/outer_puzzles.py], [File: chia/wallet/cat_wallet/cat_outer_puzzle.py], [File: chia/wallet/nft_wallet/ownership_outer_puzzle.py], [File: chia/wallet/trading/offer.py])

### Summary
The `ldap3_proto` bug class is "unbounded recursive-descent parsing of attacker-controlled input causes Python/native stack exhaustion." The closest reachable analog in this codebase is the wallet's outer-puzzle "layer" recognition system (`match_puzzle`), which recursively unwraps nested CAT/singleton/ownership/metadata/CR puzzle layers based on the *attacker-supplied* `puzzle_reveal` of an offer or coin spend, with no depth limit.

### Finding Description
`chia.wallet.outer_puzzles.match_puzzle()` iterates known drivers and calls `driver.match(puzzle)` [1](#0-0) . Each driver's `match()` (e.g. `CATOuterPuzzle.match`, `OwnershipOuterPuzzle.match`, `SingletonOuterPuzzle.match`, `CROuterPuzzle.match`, `MetadataOuterPuzzle.match`) recurses into its own `_match` callback on the puzzle's inner puzzle whenever a layer is recognized, building an `also` chain, e.g.: [2](#0-1) [3](#0-2) 

This recursion depth is driven entirely by how many times a coin's `puzzle_reveal` curries a recognized layer (CAT, singleton, ownership, credential-restricted, metadata) inside another recognized layer — a value fully controlled by whoever constructs the puzzle reveal, i.e., an offer counterparty or a spend-bundle submitter whose coin the wallet processes. There is no maximum-layer-depth check anywhere in `outer_puzzles.py` or the individual driver `match()`/`construct()`/`get_inner_puzzle()`/`get_inner_solution()`/`solve()` methods, all of which mirror the same unbounded recursive-descent pattern through the `also()` chain in `PuzzleInfo` [4](#0-3) .

This is reachable from `Offer.from_spend_bundle()` (parsing an incoming/untrusted offer file) and `Offer._get_offered_coins()`, both of which call `match_puzzle()` directly on `coin_spend.puzzle_reveal` taken from spend bundles a wallet did not construct itself [5](#0-4) [6](#0-5) . A wallet user who accepts or even just inspects/parses a maliciously crafted offer (or a coin spend seen on chain with a deeply nested but validly curried puzzle structure) will trigger deep Python recursion.

By contrast, the codebase shows clear awareness of this exact bug class elsewhere and has hardened against it: `chia.types.blockchain_format.tree_hash.sha256_treehash()` is explicitly implemented iteratively "so we don't have to worry about blowing out the python stack" [7](#0-6) , and DataLayer's Rust-backed Merkle tree insertion raises `chia_rs.datalayer.RecursionDepthExceededError` for deep untrusted trees [8](#0-7) . No equivalent guard exists for the wallet outer-puzzle driver recursion.

### Impact Explanation
A sufficiently deep chain of nested recognized outer-puzzle layers (CAT-in-CAT, CAT-in-singleton-in-ownership-in-CR, etc.) in an offer file or observed coin spend can exhaust the Python call stack in the wallet process, causing a `RecursionError` / crash (denial of service) when the wallet attempts to parse, display, or take the offer, or when it processes incoming coin state that matches such a puzzle. This affects the local wallet process a user is running, not consensus-critical full-node validation, but it is directly triggerable by an untrusted offer counterparty or by anyone able to get a matching coin observed by the wallet.

### Likelihood Explanation
Likelihood is real but bounded by practical constraints: each additional nesting layer requires a real, validly curried Chialisp puzzle structure (increasing spend/build cost and complexity, though CLVM curry/cost is cheap relative to Python recursion frames), and the wallet must actually call `match_puzzle`/`Offer.from_spend_bundle` on the crafted data (which does happen automatically for offers users are asked to inspect/take). No cost-based or explicit depth limit blocks this before Python recursion occurs, unlike the consensus-critical CLVM execution path which is cost-metered in Rust.

### Recommendation
Add an explicit maximum recursion/layer-depth guard in `match_puzzle()` (and the corresponding `construct_puzzle`, `get_inner_puzzle`, `get_inner_solution`, `solve_puzzle` traversals) in `chia/wallet/outer_puzzles.py`, raising a clear error once a configurable maximum layer count is exceeded, mirroring the pattern already used for `sha256_treehash` and DataLayer's `RecursionDepthExceededError`. Apply the same bound to `PuzzleInfo.check_type()`'s recursion in `chia/wallet/puzzle_drivers.py`.

### Proof of Concept
Construct a `WalletSpendBundle` whose single `CoinSpend.puzzle_reveal` is built by repeatedly nesting `construct_cat_puzzle(CAT_MOD, tail, construct_cat_puzzle(CAT_MOD, tail, ...))` (as already demonstrated safely at 2 levels in the test `test_cat_outer_puzzle`, which nests one CAT inside another [9](#0-8) ) to thousands of levels, wrap it in an `Offer`, and call `Offer.from_spend_bundle()` or `match_puzzle(UnknownPuzzle(known_program=deeply_nested_puzzle))`; the recursive `match()`/`_match` chain in `CATOuterPuzzle.match` will recurse once per nesting level with no bound, exhausting the Python stack.

@pytest.mark.anyio
@pytest.mark.parametrize("depth", [1000, 100_000])
async def test_insert_into_data_store_from_file_line_graph_depth(
    data_store: DataStore,
    store_id: bytes32,
    tmp_path: Path,
    depth: int,
) -> None:
    # Binary "line graph":
    #   1 -> leaf_1, 2
    #   2 -> leaf_2, 3
    #   ...
    #   depth -> leaf_depth, leaf_end
    #
    # This stresses depth/stack handling while staying strictly binary.
    #
    # Node IDs:
    # - internal nodes: 1..depth
    # - per-level leaf nodes: (depth+1)..(2*depth)
    # - final leaf: (2*depth+1)
    internal_first = 1
    internal_last = depth
    leaf_base = internal_last + 1
    leaf_end = (2 * depth) + 1

    edges: list[tuple[int, int]] = []
    for i in range(internal_first, internal_last):
        # Order matters: first edge is left child, second edge is right child.
        edges.append((i, leaf_base + (i - internal_first)))  # unique leaf for this internal node
        edges.append((i, i + 1))  # next internal node

    # last internal points to its leaf and a final leaf
    edges.append((internal_last, leaf_base + (internal_last - internal_first)))
    edges.append((internal_last, leaf_end))

    filename = tmp_path / f"line_graph_depth_{depth}.dat"
    root_hash = create_graph_util(filename, edges)

    with pytest.raises(chia_rs.datalayer.RecursionDepthExceededError):
        await data_store.insert_into_data_store_from_file(store_id, root_hash, filename)
