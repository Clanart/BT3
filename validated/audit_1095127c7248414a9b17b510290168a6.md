### Title
Tokenfactory denom AllowList (compliance restriction) is bypassed by CosmWasm contract `BankMsg::Send`, allowing transfers to/from non-allow-listed addresses - (File: sei-wasmd/x/wasm/keeper/keeper.go)

### Summary
`x/tokenfactory` lets a denom admin configure `AllowList.Addresses` via `MsgCreateDenom`/`MsgUpdateDenom`, which the bank module stores per-denom and is meant to restrict which accounts may send or receive that denom. This restriction is enforced only in the bank module's message-server handlers `Send` and `MultiSend`, via explicit `IsInDenomAllowList` calls. It is **not** enforced inside `BaseSendKeeper.SendCoins`/`SendCoinsWithoutAccCreation` themselves. CosmWasm contract execution reaches `SendCoins` through a different path — `BankCoinTransferrer.TransferCoins`, used to dispatch a contract's `BankMsg::Send` response message — which checks only `IsSendEnabledCoins` and `BlockedAddr`, then calls `k.keeper.SendCoins` directly, skipping the allow-list check entirely.

### Finding Description
- The allow-list check is defined in `IsInDenomAllowList` [1](#0-0)  and is only invoked from the bank `msgServer.Send`/`MultiSend` handlers: [2](#0-1) [3](#0-2) .
- `BaseSendKeeper.SendCoins` itself performs no allow-list check: [4](#0-3) .
- CosmWasm contract `Response` messages containing `BankMsg::Send` are encoded to a `banktypes.MsgSend` [5](#0-4) , but the actual coin movement for a contract-originated transfer is executed through `BankCoinTransferrer.TransferCoins`, which calls `SendCoins` directly and only checks `IsSendEnabledCoins`/`BlockedAddr` — never `IsInDenomAllowList`: [6](#0-5) .
- This is functionally identical to the Portainer bug class: a security restriction (there, `EndpointSecuritySettings`; here, tokenfactory `AllowList`) is fully enforced on one API surface (`MsgSend`/`MsgMultiSend`) but silently absent on another surface reaching the same mutating primitive (`SendCoins`), reachable by any CosmWasm contract execution.

### Impact Explanation
Any account holding a restricted tokenfactory denom that is escrowed in, or transferable through, a CosmWasm contract can move that denom to or from an address that the denom admin explicitly excluded via `AllowList`. This defeats the compliance/whitelisting guarantee the tokenfactory module is designed to provide (e.g., KYC-gated or permissioned RWA-style tokens), enabling unauthorized transfer of a restricted-distribution asset to arbitrary addresses. Because any user can deploy or interact with a contract that issues a `BankMsg::Send` submessage (e.g., an escrow, wrapper, or "sweep" contract) holding the restricted denom, this is reachable from a single wasm `MsgExecuteContract` by an unprivileged account.

### Likelihood Explanation
High reachability: any address can instantiate/execute a CosmWasm contract and trigger a `BankMsg::Send` response message; no special privilege, precompile access, or governance action is required. The only precondition is that the target denom has a tokenfactory `AllowList` configured (a supported, documented feature) and that some balance of it sits in, or passes through, a contract-controlled account (which is a very common pattern — escrow, AMM, vault, wrapper contracts, etc.).

### Recommendation
Enforce `IsInDenomAllowList` (and mirror the `BlockedAddr`/allow-list symmetry used in `msgServer.Send`/`MultiSend`) inside the shared, lower-level transfer primitives — either directly in `BaseSendKeeper.SendCoins`/`SendCoinsWithoutAccCreation`, or explicitly in `BankCoinTransferrer.TransferCoins` before calling `SendCoins`, so that every caller of the underlying transfer capability (contract-originated sends, `InputOutputCoins`, and any future callers) is subject to the same compliance restriction as `MsgSend`/`MsgMultiSend`.

### Proof of Concept
1. As the tokenfactory denom admin, create a denom `factory/<admin>/restricted` and call `SetDenomAllowList` (via `MsgUpdateDenom`/genesis) with `Addresses: [adminAddr, allowedUser]`.
2. Fund a CosmWasm contract (e.g., a generic "reflect"/escrow contract) with balance of `factory/<admin>/restricted`.
3. As any unprivileged user (not in `AllowList`), call `MsgExecuteContract` on that contract with a payload that causes it to return a `Response` containing `CosmosMsg::Bank(BankMsg::Send { to_address: <notAllowedUser>, amount: [...] })`.
4. Observe that `wasmkeeper.NewSDKMessageHandler` dispatches this through `BankCoinTransferrer.TransferCoins` → `SendCoins`, completing the transfer to `<notAllowedUser>` even though neither the contract nor `<notAllowedUser>` is in the denom's `AllowList` — whereas an equivalent `MsgSend`/`MsgMultiSend` from the same account would be rejected with `sdkerrors.ErrUnauthorized` ("... is not allowed to receive/send funds").

// IsInDenomAllowList checks if the given address is allowed to send the given coins.
// The check is performed only fot token factory denoms. For each token factory denom,
// it checks if there is allow list for the given denom. If there is no allow list,
// the address is allowed to send the coins. If there is an allow list, the address is
// allowed to send the coins only if it is in the allow list.
func (k BaseSendKeeper) IsInDenomAllowList(ctx sdk.Context, addr sdk.AccAddress, coins sdk.Coins, cache map[string]AllowedAddresses) bool {
	for _, coin := range coins {
		// Skip if denom does not contain the token factory prefix
		if !strings.HasPrefix(coin.Denom, TokenFactoryPrefix) {
			continue
		}

		allowedAddresses := k.getAllowedAddresses(ctx, cache, coin.Denom)
		// skip if there is no allow list for the denom
		if len(allowedAddresses.set) == 0 {
			continue
		}

		if !allowedAddresses.contains(addr) {
			return false
		}
	}
	return true
}

func (k msgServer) Send(goCtx context.Context, msg *types.MsgSend) (*types.MsgSendResponse, error) {

	if err != nil {
		return nil, err
	}
	to, err := sdk.AccAddressFromBech32(msg.ToAddress)
	if err != nil {
		return nil, err
	}

		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to send funds", msg.FromAddress)

		return nil, sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", msg.ToAddress)

// TransferCoins transfers coins from source to destination account when coin send was enabled for them and the recipient
// is not in the blocked address list.
func (c BankCoinTransferrer) TransferCoins(parentCtx sdk.Context, fromAddr sdk.AccAddress, toAddr sdk.AccAddress, amount sdk.Coins) error {
	em := sdk.NewEventManager()
	ctx := parentCtx.WithEventManager(em)
	if err := c.keeper.IsSendEnabledCoins(ctx, amount...); err != nil {
		return err
	}
	if c.keeper.BlockedAddr(toAddr) {
		return sdkerrors.Wrapf(sdkerrors.ErrUnauthorized, "%s is not allowed to receive funds", toAddr.String())
	}

	sdkerr := c.keeper.SendCoins(ctx, fromAddr, toAddr, amount)
	if sdkerr != nil {
		return sdkerr
	}
	for _, e := range em.Events() {
		if e.Type == sdk.EventTypeMessage { // skip messages as we talk to the keeper directly
			continue
		}
		parentCtx.EventManager().EmitEvent(e)
	}
	return nil
}
