## Finding

### Title
Reward-timing arbitrage in `WombatStaking`/`BaseRewardPoolV2` allows depositors to steal accrued WOM yield from existing stakers via atomic deposit→harvest→withdraw - (File: `wombat/WombatStaking.sol`, `rewards/BaseRewardPoolV2.sol`, `wombat/WombatPoolHelper.sol`)

### Summary
`BaseRewardPoolV2` distributes reward tokens using a lump-sum "drop" model: whenever `queueNewRewards` is called, the entire incoming reward amount is divided by whatever `totalStaked()` happens to be **at that exact moment**, and added to `rewardPerTokenStored`. Reward drops are triggered by the permissionless `WombatStaking.harvest()` / `WombatPoolHelper.harvest()` functions, and are also triggered as a side effect of `WombatPoolHelper.withdraw()`. Because there is no time-weighting, cooldown, or vesting on the base WOM rewarder, any wallet can deposit right before a harvest is triggered (or trigger the harvest itself) and immediately withdraw, capturing a disproportionate share of yield that accrued to long-term stakers, and can also exit before losses/fees are realized.

### Finding Description
`BaseRewardPoolV2._provisionReward` (called from `queueNewRewards`) computes: [1](#0-0) 
```
if (totalStaked() == 0) {
    rewardInfo.queuedRewards += _amountReward;
} else {
    ...
    rewardInfo.rewardPerTokenStored =
        rewardInfo.rewardPerTokenStored +
        (_amountReward * 10**stakingTokenDecimals) / totalStaked();
}
```
This spreads the newly harvested reward proportionally to `totalStaked()` measured at the instant of the call — not by how long each staker held their position while the reward accrued.

`queueNewRewards` is invoked from `WombatStaking._sendRewards`, which is reached from the **permissionless** `harvest()` entrypoint: [2](#0-1) 
```
function harvest(
    address _lpToken
) whenNotPaused _onlyActivePool(_lpToken) external {
    _toMasterWomAndSendReward(_lpToken, 0, true); // triggers harvest from wombat exchange
}
```
and exposed to users via `WombatPoolHelper.harvest()`: [3](#0-2) 

Critically, `WombatPoolHelper.withdraw()` itself triggers the harvest/reward-queueing path *before* unstaking the caller from `MasterMagpie`: [4](#0-3) 
```
function withdraw(uint256 _liquidity, uint256 _minAmount) external override {
    // we have to withdraw from wombat exchange to harvest reward to base rewarder
    IWombatStaking(wombatStaking).withdraw(lpToken, _liquidity, _minAmount, msg.sender);
    // then we unstake from master wombat to trigger reward distribution from basereward
    _unstake(_liquidity, msg.sender);
    IWombatStaking(wombatStaking).burnReceiptToken(lpToken, _liquidity);
    ...
}
```
An attacker can therefore:
1. Call `WombatPoolHelper.deposit()` with a large amount of the deposit token, minting receipt tokens and staking them into `MasterMagpie` via `depositFor` (no lock, no cooldown).
2. Immediately (same block / next tx) call `harvest()` (or their own `withdraw()`, which internally harvests) — this pulls all WOM rewards accrued by `WombatStaking`'s position in the underlying `MasterWombat` pool over time and dumps them into `BaseRewardPoolV2` in one shot, computing `rewardPerTokenStored` using the pool's `totalStaked()` that now includes the attacker's freshly added stake.
3. Call `withdraw()`/`multiClaim` to harvest their share of `rewardPerTokenStored` (via `MasterMagpie._harvestAndUnstake` → `_harvestBaseRewarder` → `BaseRewardPool.getReward`) and pull principal back out.

None of these steps require privileged access — `harvest`, `deposit`, and `withdraw` are all ordinary user-facing entrypoints reachable in `PoolHelper` contracts by any wallet with capital, and MGP's own MasterMagpie MGP-emission (`accMGPPerShare`) is time-based/per-second so it isn't affected the same way, but the WOM lump-sum rewarder (`BaseRewardPoolV2`/`BaseRewardPool`) is.

### Impact Explanation
This lets any depositor capture yield generated by other stakers' time-weighted participation without having contributed proportionally, diluting/stealing rewards genuinely earned by long-term stakers — a direct theft of unclaimed yield reachable from an ordinary wallet with no privileged role, oracle, or governance action required.

### Likelihood Explanation
`harvest()` is fully permissionless and callable by anyone at any time, and `deposit`/`withdraw` in `WombatPoolHelper`/`WombatPoolHelperV2` have no cooldown or minimum holding period, so the attack requires only capital (temporarily) and gas — no special conditions or races against other actors are strictly needed since the attacker can self-trigger the harvest.

### Recommendation
Move to a time-weighted/streamed reward accrual (e.g., stream rewards linearly over the interval since the last harvest, as `MasterMagpie`'s own `accMGPPerShare` does per-second) instead of instantly crediting `rewardPerTokenStored` based on `totalStaked()` at the harvest instant. Alternatively, add a minimum staking duration or decouple `harvest()` from `withdraw()` so newly deposited stake cannot immediately claim rewards accrued before the deposit.

### Proof of Concept
1. Attacker calls `WombatPoolHelper.deposit(amount, minLiquidity)`, staking a large LP position via `MasterMagpie.depositFor` (`wombat/WombatPoolHelper.sol` lines 148-155).
2. Attacker calls `WombatPoolHelper.harvest()` → `WombatStaking.harvest(lpToken)` → `_toMasterWomAndSendReward` → `_sendRewards` → `IBaseRewardPool(_rewarder).queueNewRewards(amount, wom)`, which updates `rewardPerTokenStored` using `totalStaked()` that now includes the attacker's stake (`rewards/BaseRewardPoolV2.sol` lines 290-314).
3. Attacker calls `WombatPoolHelper.withdraw()`/`MasterMagpie.multiClaim`, which internally calls `_harvestBaseRewarder`/`getReward`, paying out the attacker's inflated share of `rewardPerTokenStored`, then withdraws principal — netting yield that accrued to prior long-term stakers. [5](#0-4)

                if (feeInfo.isActive) {
                    address rewardToken = _rewardToken;
                    uint256 feeAmount = (originalRewardAmount * feeInfo.value) / DENOMINATOR;
                    _amount -= feeAmount;
                    uint256 feeTosend = feeAmount;

                    if (feeInfo.isMWOM && rewardToken == wom) {
                        if (smartWomConverter != address(0)) {
                            IERC20(wom).safeApprove(smartWomConverter, feeAmount);
                            uint256 beforeBalnce = IMWom(mWom).balanceOf(address(this));
                            IConverter(smartWomConverter).smartConvert(feeAmount, 0);

                            feeTosend = IMWom(mWom).balanceOf(address(this)) - beforeBalnce;
