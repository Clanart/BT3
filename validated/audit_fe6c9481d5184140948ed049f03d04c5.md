## Analog Found: Missing `_requestCommitments` cleanup lets a GET request's relayer fee be paid twice

### Title
GET request fee double-payment via missing `_requestCommitments` deletion in `dispatchIncoming(GetResponse)` - (File: `evm/src/core/EvmHost.sol`)

### Summary
The reported bug class is "a computed/authoritative value that should gate or finalize state is never written, so the caller's downstream branch either never fires or fires incorrectly." The Hyperbridge analog is the mirror image: `EvmHost.dispatchIncoming(GetResponse, ...)` pays out the GET request's escrowed relayer fee but never clears the request's bookkeeping entry (`_requestCommitments[commitment]`) the way every other terminal path for a GET request does. That omission leaves the fee metadata live for a second, independent payout via the timeout path.

### Finding Description
`EvmHost.sol` maintains `_requestCommitments[commitment]` as the single source of truth for a dispatched request's `FeeMetadata` (`payer`, `fee`). Every terminal handler for a GET request is expected to consume and clear this entry exactly once — that is the replay-protection contract used throughout the file:

- `dispatchTimeOut(GetRequestTimeout, ...)` explicitly deletes it for replay protection before refunding the fee to the original payer: [1](#0-0) 

- `dispatchTimeOut(PostRequestTimeout, ...)` follows the identical pattern.

But `dispatchIncoming(GetResponse, address relayer)` — the success path invoked when a `GetResponseMessage` is delivered — reads `_requestCommitments[commitment].fee`, pays it to the relayer, and **never deletes the entry**: [2](#0-1) 

Because `_requestCommitments[commitment]` is left intact after a successful response, the same commitment can later be submitted through `HandlerV2.handleGetRequestTimeouts`, which independently re-reads the (still-populated) `FeeMetadata`, checks only that the request is "known" (`meta.sender == address(0)` would revert, but the meta is still non-zero) and that a non-membership proof against a `StateCommitment` height shows no response receipt at that height: [3](#0-2) 

`host.stateMachineCommitment(message.height)` is looked up from a bounded, FIFO-retained history (`BoundedStateCommitments`/`StateCommitmentQueue` on the pallet side), not necessarily the latest height: [4](#0-3) 

There is no check in `handleGetRequestTimeouts` that `message.height` is the *latest* known commitment, nor any check that a `GetResponseMessage` for this same commitment has already been delivered on this chain. As long as an older, still-retained state commitment predates the moment the response-side receipt was recorded, its non-membership proof against `RESPONSE_RECEIPTS_STORAGE_PREFIX` for this commitment will still verify, and `dispatchTimeOut(GetRequestTimeout, meta, commitment)` will refund `meta.fee` a second time to `meta.sender` — on top of the fee already paid to the relayer in `dispatchIncoming(GetResponse, ...)`.

### Impact Explanation
This is a direct double-payment / double-settlement of the same escrowed relayer fee from `EvmHost`'s fee-token balance: once to the relayer (on response delivery) and again to the payer (on a stale-height timeout). This is a loss-of-funds / logic-attack condition drawn from the protocol's own fee-token reserve, matching the bounty's "double-claim/double-settlement" and "stealing or loss of funds" categories. Both `handleGetResponses` and `handleGetRequestTimeouts` are explicitly permissionless entry points, so no relayer, prover, or admin compromise is required — only submission of two independently-valid messages (a genuine response and a genuine, but stale-height, timeout) for the same GET request.

### Likelihood Explanation
Exploitability depends on the state-commitment retention window: the attacker (who can simply be the original `payer`, i.e., the module/user that dispatched the GET and is entitled to `meta.sender` on timeout) needs a still-queryable, older `StateMachineHeight` whose commitment predates the response's non-membership window, and the GET request itself must still satisfy `request.timeout() > state.timestamp` for that older commitment's `state.timestamp`. Both `BoundedStateCommitments`'s per-chain cap and each GET request's own `timeout` parameter bound this window, but neither eliminates it — it only requires the payer to act before the relevant retained heights are evicted, well within normal operational timeframes for slower-finality or infrequently-updated destination chains.

### Recommendation
Delete `_requestCommitments[commitment]` inside `dispatchIncoming(GetResponse, ...)` immediately after (or as part of) the fee payout, mirroring the cleanup already done in both `dispatchTimeOut` overloads. This makes "responded" and "timed out" mutually exclusive terminal states for the same commitment, exactly as the request-receipt/commitment lifecycle already enforces for POST requests, and closes the replay window regardless of which stale state-commitment heights remain retained.

### Proof of Concept
1. Source module dispatches a GET request via `IDispatcher.dispatch`; `_requestCommitments[commitment]` is populated with `{payer, fee}`.
2. A relayer delivers a valid `GetResponseMessage` via `HandlerV2.handleGetResponses` → `EvmHost.dispatchIncoming(GetResponse, relayer)`. The relayer is paid `fee` from `_requestCommitments[commitment].fee`; the entry is **not** cleared.
3. Before the state commitment that predates the response's Hyperbridge-side receipt is evicted from `BoundedStateCommitments`, the payer (or anyone acting on the payer's behalf) submits a `GetTimeoutMessage` referencing that older height via `HandlerV2.handleGetRequestTimeouts`.
4. The non-membership proof against the stale height succeeds (no receipt existed yet at that height); `EvmHost.dispatchTimeOut(GetRequestTimeout, meta, commitment)` refunds the same `fee` to `meta.sender`.
5. Net result: the protocol/fee-token reserve pays out the same GET-request fee twice for a single dispatched request.

Note: I was not able to fully trace the pallet-side GET-response receipt write path (which pallet/child-trie exactly populates the value proven non-existent at `RESPONSE_RECEIPTS_STORAGE_PREFIX` and how quickly older heights are evicted from `BoundedStateCommitments` in production configurations), so the precise exploitation window size is not independently confirmed from the indexed code alone — a Devin session with full repository access would be needed to pin down the exact retention parameters and confirm the receipt-write timing end-to-end.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }

	/// Per-chain FIFO queue of heights retained in [`BoundedStateCommitments`]
	/// and [`BoundedStateMachineUpdateTime`], keyed by a monotonically
	/// increasing insertion index. Insertion order matches height order because
	/// consensus updates only ever advance a state machine, so evicting at the
	/// head removes the oldest height. Entries whose height was vetoed via
	/// `delete_state_commitment` are left in place and become harmless no-ops
	/// when their index is evicted.
	///
	/// Each insertion touches O(1) small storage items, so the per-chain cap
	/// can grow without adding I/O or PoV weight to the insert path.
	#[pallet::storage]
	pub type StateCommitmentQueue<T: Config> = StorageDoubleMap<
		_,
		Blake2_128Concat,
		StateMachineId,
		Twox64Concat,
		u64,
		u64,
		OptionQuery,
	>;

	/// Head/tail indices for [`StateCommitmentQueue`], per chain.
	#[pallet::storage]
	pub type CommitmentQueueStates<T: Config> =
		StorageMap<_, Blake2_128Concat, StateMachineId, CommitmentQueueState, ValueQuery>;
