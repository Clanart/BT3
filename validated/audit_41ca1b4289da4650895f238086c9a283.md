### Title
`ReceivedOutput::read` bypasses the `Scanner`-enforced offset↔script binding, allowing fabricated unspendable outputs to be reported as received funds - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The blacklist-bypass class from the external report maps onto Serai as *inconsistent enforcement across two construction paths for the same invariant*. `Scanner` is the sole honest constructor of `ReceivedOutput` and guarantees that `offset` corresponds to `output.script_pubkey` via its `scripts: HashMap<ScriptBuf, Scalar>` map (`scan_transaction` only emits an output when `self.scripts.get(&output.script_pubkey)` hits). However, the public deserializer `ReceivedOutput::read` reconstructs the exact same type from raw bytes — an offset scalar, a `TxOut`, and an `OutPoint` — with no check that `output.script_pubkey == p2tr_script_buf(key + G * offset)`. Like `PHAR://` bypassing the lowercase `phar://` prefix check, the byte-level path bypasses the binding enforced on the scan path.

### Finding Description
`Scanner::scan_transaction` ties every `ReceivedOutput` it produces to a registered `(script_pubkey -> offset)` entry:

- `scripts.insert(p2tr_script_buf(key)?, Scalar::ZERO)` in `Scanner::new` and `scripts.insert(script, offset)` in `register_offset` — offset is only accepted alongside its derived script.
- `scan_transaction` looks up `output.script_pubkey` in that map, so `offset` always actually spends `output`.

`ReceivedOutput::read` accepts three independent fields (`Secp256k1::read_F`, `TxOut::consensus_decode`, `OutPoint::consensus_decode`) and returns `ReceivedOutput { offset, output, outpoint }` directly. `consensus_decode` validates Bitcoin serialization, not the cryptographic binding: an attacker can supply any offset and any `script_pubkey` — including an offset that derives to a completely different Taproot output — or pair a valid registered offset with an outpoint whose actual on-chain `TxOut` is not `output`. The type's private fields provide encapsulation only against honest Rust callers; the deserializer re-enters the invariant without re-checking it, the same way the case-sensitive `strpos` guarded only one spelling of `phar://`.

### Impact Explanation
Untrusted bytes reaching `ReceivedOutput::read` (an explicitly in-scope attack surface) let an unprivileged party fabricate an output the wallet treats as received and spendable:

- **Unspendable "received" funds**: `offset` that doesn't match `output.script_pubkey` produces a `ReceivedOutput` that `send` will attempt to spend; the resulting input signature is made under a key unrelated to the prevout script, so the transaction is consensus-invalid / the funds do not exist. This is "funds reported received that are not spendable," an accepted impact class.
- **Wrong-value accounting**: `output` is a claimed `TxOut`; nothing ties it to the `outpoint`'s actual on-chain output, so `value()` reports an arbitrary amount, corrupting fee/change/dust math in `send.rs`.

### Likelihood Explanation
Likelihood depends on how `ReceivedOutput` bytes are sourced: if the serialized form only ever round-trips locally produced `Scanner` output, the window is narrow (Medium). Any path where the bytes cross a trust boundary (relayed between components, persisted state an attacker can influence, or fed from an untrusted scan source) makes injection of a mismatched `(offset, output, outpoint)` trivial — no cryptographic work is required, just well-formed consensus encodings.

### Recommendation
Either remove `pub` deserialization of `ReceivedOutput` or bind it to the scanner: make `read` take the `Scanner`/`key` and verify `self.scripts.get(&output.script_pubkey) == Some(&offset)` (equivalently `p2tr_script_buf(key + G*offset) == output.script_pubkey`) before constructing — and have callers verify `outpoint` against a looked-up prevout rather than trusting the embedded `TxOut`. This converts the implicit path-dependent invariant into a scheme-level allow-list, mirroring the upstream fix.

### Proof of Concept
```rust
use bitcoin::{consensus::encode::serialize, OutPoint, ScriptBuf, TxOut, Txid, Amount};
use bitcoin::hashes::Hash;
use k256::Scalar;
use serai_bitcoin::wallet::ReceivedOutput;

// Attacker crafts bytes: offset = 0 (claims base-key script) but an unrelated script_pubkey
let offset = Scalar::ZERO;
let fake_output = TxOut {
  value: Amount::from_sat(1_000_000),
  script_pubkey: ScriptBuf::new_op_return(&[0u8; 4]), // attacker-chosen, not the base P2TR
};
let fake_outpoint = OutPoint::new(Txid::all_zeros(), 0);

let mut bytes = offset.to_bytes().to_vec();
bytes.extend(serialize(&fake_output));
bytes.extend(serialize(&fake_outpoint));

// Accepted without checking script_pubkey == p2tr_script_buf(key + G*offset)
let received = ReceivedOutput::read(&mut bytes.as_slice()).unwrap();
assert_eq!(received.value(), 1_000_000); // reported as a 1M-sat received output, unspendable
```

Relevant code: `ReceivedOutput::read` at `networks/bitcoin/src/wallet/mod.rs` (no binding check), versus the enforced binding in `Scanner::new`/`register_offset`/`scan_transaction` in the same file.
