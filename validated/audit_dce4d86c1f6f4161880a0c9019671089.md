### Title
DataLayer mirror URLs from an untrusted wallet action trigger unvalidated outbound HTTP requests (SSRF) - (File: chia/data_layer/download_data.py)

### Summary
A wallet user can register an arbitrary, attacker-chosen URL as a DataLayer mirror server via the `dl_new_mirror` wallet RPC / `create_new_mirror` puzzle path, which is stored on-chain and later read by any peer's DataLayer node that subscribes to that store. When another node's `DataLayer` service processes that mirror record (`update_subscriptions_from_wallet` → `get_available_servers_for_store` → `fetch_and_validate`), it calls `download_file`/`http_download` in `chia/data_layer/download_data.py` with the attacker-supplied URL, with no validation of scheme, host, or destination (no blocking of internal/loopback/link-local addresses). This mirrors the Liferay SSRF pattern: a low-privilege actor supplies a URL in a data-object field, and the server later fetches it without validating the destination.

### Finding Description
- Mirror URLs are attacker-controlled input added through the wallet-level `dl_new_mirror`/`create_new_mirror` flow and stored as coin data associated with the `MIRROR_PUZZLE_HASH` singleton mechanism [1](#0-0) .
- Any peer that subscribes to the same DataLayer store id will pull these mirror URLs from wallet state via `update_subscriptions_from_wallet`, which just concatenates all `mirror.urls` values with no filtering: [2](#0-1) 
- `fetch_and_validate` then iterates the resulting `servers_info` and calls `insert_from_delta_file` with the raw mirror URL as `server_info.url`: [3](#0-2) 
- `download_file` performs an outbound request to that URL with `http_download` (or POSTs it to a downloader plugin) with no scheme/host allow-list, no check against private/loopback/link-local ranges, and no restriction preventing the URL from pointing to internal services (e.g., cloud metadata endpoints, localhost RPC ports, or internal network hosts): [4](#0-3) 
- The only validation performed is on the downloaded **filename** shape (`is_filename_valid`), never on the destination **URL** itself: [5](#0-4) 
- The project's own internal documentation for this module explicitly flags mirror/plugin URLs as untrusted external inputs that must not be treated as trust anchors, but does not describe any host/IP validation being performed before dispatching requests: [6](#0-5) [7](#0-6) 

This is directly analogous to the Liferay CVE: an unprivileged actor (any wallet user able to submit a `dl_new_mirror` spend) supplies a URL in an object field (mirror record) that a separate service (the victim's DataLayer node) later fetches unconditionally, allowing requests to be redirected to internal/otherwise-unreachable network endpoints from the victim's own node.

### Impact Explanation
An attacker who is merely a normal wallet/DataLayer user (able to submit a `dl_new_mirror` transaction, requiring only spendable XCH for fees) can force any other node that subscribes to their store to issue arbitrary outbound HTTP GET/POST requests. This can be used to:
- Probe/attack internal services reachable only from the victim's host or LAN (e.g., cloud metadata service `169.254.169.254`, other local RPC ports).
- Cause the victim's DataLayer node to leak information via response timing/side channels, or cause resource exhaustion pointing at large/slow endpoints.
- Combined with the plugin download path (`get_downloader`/`download_file` plugin branch), a malicious URL is also POSTed to configured downloader plugins, further widening the blast radius to any configured plugin infrastructure.

This does not directly forge coins, steal funds, or corrupt consensus state, so it's scoped as Medium severity — matching the CVSS "Medium" and network-reachable, low-privilege, low-impact profile of the original Liferay advisory.

### Likelihood Explanation
Likelihood is moderate-to-high: creating a DL mirror with a crafted URL is a normal, low-cost, unprivileged wallet operation (just a spend bundle) requiring no elevated permissions, and any node that subscribes to (or auto-discovers, per the "pseudo-subscribes owned stores" logic) that store id will process the URL. The main precondition is that a target node must be actively subscribing to / syncing the attacker's DataLayer store — a normal usage pattern for shared/public DataLayer stores.

### Recommendation
- Validate mirror URLs before they are ever fetched: enforce an allow-list of schemes (`http`/`https`/`s3` as already partially done for the plugin path) and reject URLs resolving to loopback, link-local, private, or otherwise disallowed address ranges before calling `http_download`/`aiohttp.ClientSession`.
- Apply this validation both when accepting mirror URLs into `dl_new_mirror`/`update_subscriptions_from_wallet` and defensively again immediately before any outbound request in `download_file`/`http_download`.
- Consider resolving DNS and re-validating the resolved IP (to prevent DNS-rebinding bypasses of a naive string-based host check) before connecting.
- Document and enforce this as a required invariant given the project's own notes already flag mirror URLs as untrusted external trust boundaries.

### Proof of Concept
1. Attacker (unprivileged wallet user) creates a DataLayer store and calls `dl_new_mirror` with `urls=["http://169.254.169.254/latest/meta-data/"]` (or `http://127.0.0.1:<victim-internal-port>/...`), paying only normal transaction fees.
2. This mirror record becomes visible on-chain and readable by wallet RPC (`dl_get_mirrors`) to any node.
3. A victim node subscribes to the attacker's `store_id` (a normal DataLayer usage flow, e.g. via `subscribe`/pseudo-subscription for owned stores or explicit subscription for public stores).
4. During the victim's next `periodically_manage_data()` cycle, `update_subscriptions_from_wallet` pulls the attacker's URL [2](#0-1) , and `fetch_and_validate`/`download_file` issue an HTTP request from the victim node directly to the attacker-chosen URL [8](#0-7) [9](#0-8) , with no validation preventing the request from reaching internal or restricted network endpoints.

def is_filename_valid(filename: str, group_by_store: bool = False) -> bool:
    if group_by_store:
        if filename.count("/") != 1:
            return False
        filename = filename.replace("/", "-")

    split = filename.split("-")

    try:
        raw_store_id, raw_node_hash, file_type, raw_generation, raw_version, *rest = split
        store_id = bytes32(bytes.fromhex(raw_store_id))
        node_hash = bytes32(bytes.fromhex(raw_node_hash))
        generation = int(raw_generation)
    except ValueError:
        return False

    if len(rest) > 0:
        return False

    # TODO: versions should probably be centrally defined
    if raw_version != "v1.0.dat":
        return False

    if file_type not in {"delta", "full"}:
        return False

    generate_file_func = get_delta_filename if file_type == "delta" else get_full_tree_filename
    reformatted = generate_file_func(
        store_id=store_id, node_hash=node_hash, generation=generation, group_by_store=False
    )

    return reformatted == filename
```

async def download_file(
    data_store: DataStore,
    target_filename_path: Path,
    store_id: bytes32,
    root_hash: bytes32,
    generation: int,
    server_info: ServerInfo,
    proxy_url: str | None,
    downloader: PluginRemote | None,
    timeout: aiohttp.ClientTimeout,
    client_foldername: Path,
    timestamp: int,
    log: logging.Logger,
    grouped_by_store: bool,
    group_downloaded_files_by_store: bool,
    max_delta_file_size: int,
) -> bool:
    if target_filename_path.exists():
        return True
    filename = get_delta_filename(store_id, root_hash, generation, grouped_by_store)

    if downloader is None:
        # use http downloader - this raises on any error
        try:
            await http_download(
                target_filename_path, filename, proxy_url, server_info, timeout, log, max_delta_file_size
            )
        except (asyncio.TimeoutError, aiohttp.ClientError, MaxDeltaFileSizeExceededError):
            new_server_info = await data_store.server_misses_file(store_id, server_info, timestamp)
            log.info(
                f"Failed to download {filename} from {new_server_info.url}."
                f"Miss {new_server_info.num_consecutive_failures}."
            )
            log.info(f"Next attempt from {new_server_info.url} in {new_server_info.ignore_till - timestamp}s.")
            return False
        return True
```
