### Title
Gasless swap-amount validation relies on spot AMM reserves via `GetAmountIn`, allowing flash-loan price manipulation to bypass repayment checks - ([File: kaiax/gasless/impl/tx_pool.go])

### Summary
`GaslessModule.checkBalanceForSwap` validates a gasless `SwapTx` by calling the `GaslessSwapRouter` contract's `GetAmountIn(token, minAmountOut)` view function and comparing it against the sender-declared `amountIn`. This value is derived from the live, spot reserves of the underlying DEX pool backing the gasless token (as exposed through `dexAddress`/`GetAmountIn` on `GaslessSwapRouter`, which mirrors the UniswapV2 `getAmountIn`/`getReserves` pattern seen throughout the repo's Uniswap bindings). This is the same class of vulnerability as the reported `IchiLpOracle` issue: pricing that is read directly from an AMM's current reserves without any TWAP/fair-pricing protection is manipulable within a single block via a flash-loan sandwich.

### Finding Description
`checkBalanceForSwap` in [1](#0-0)  fetches the "current exchange rate" straight from the `GaslessSwapRouter` contract:

```
requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
...
if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 { ... "insufficient amountIn" }
```

`GetAmountIn` on `GaslessSwapRouter` is bound at [2](#0-1) , and the DEX/factory/router bindings throughout the repo (e.g. [3](#0-2) , [4](#0-3) ) confirm the underlying pricing primitive is the classic UniswapV2 `getReserves()`/`getAmountIn` formula — i.e., an un-averaged, single-block spot price, exactly the "naive" pricing formula flagged as vulnerable in the reference `IchiLpOracle` report.

This spot price is used at two critical, unprivileged-reachable points:
1. Mempool admission (`GetCheckBalance` → `checkBalanceForSwap`), which gates whether the `GaslessApproveTx`/`GaslessSwapTx` pair is promoted for inclusion.
2. Block-building, where — per the module's documented flow — the proposer unconditionally prepends a `LendTxGenerator` transaction that funds the user's gas fee in real KAIA *before* the `GaslessApproveTx`/`GaslessSwapTx` executes: "The gas fee of gasless transaction's is funded by block proposer ... and user repays the lent amount during gasless swap" [5](#0-4) .

Because the reserves used to price `minAmountOut`/`amountRepay` sufficiency can be pushed away from equilibrium and back within the same block (flash loan sandwich: pump the pool pre-swap, let the check/execution consume the skewed price, then dump back), an attacker (the gasless-tx sender or a colluding searcher) can submit a `SwapTx` whose `amountIn`/`minAmountOut` pair only satisfies `GetAmountIn`'s naive spot-based requirement under the manipulated reserves, not the pool's true price.

### Impact Explanation
The block proposer's `LendTxGenerator` transfers real KAIA to the gasless-tx sender irrespective of whether the subsequent swap ultimately repays a fair amount, since the value comparison that gates admission (`checkBalanceForSwap`) is based on a manipulable spot price rather than a manipulation-resistant valuation (unlike KIP-71's `NextMagmaBlockBaseFee`, which is intentionally derived from parent-block gas usage rather than an in-block spot signal — see [6](#0-5) ). This can result in the proposer/protocol under-recovering the lent gas fee (`amountRepay`) relative to the true value of tokens swapped, i.e., fee-delegation/gasless-settlement value being extracted at the protocol's expense — a direct funds-loss / fee-abuse impact matching the "gasless or auction settlement theft" acceptance criteria.

### Likelihood Explanation
Any unprivileged gasless-transaction sender can trigger this by submitting a crafted `SwapTx` (with `IsSwapTx` recognized by `decodeSwapTx`, [7](#0-6) ) timed against reserve manipulation of the small/thin gasless-whitelisted token pool used by `GaslessSwapRouter`. Because gasless swap tokens/pools are typically low-liquidity (they exist specifically to let users swap into KAIA for gas), they are cheaper to manipulate with a flash loan than a deep, primary trading pair, increasing practical likelihood.

### Recommendation
Do not price `minAmountOut`/`amountRepay` sufficiency (`GetAmountIn`) from single-block/spot AMM reserves. Use a manipulation-resistant valuation such as a TWAP oracle, or require the actual repayment check to be re-verified strictly at swap-execution time using the "fair" reserve-based formula (geometric-mean / Alpha Venture style adjustment, as recommended for `IchiLpOracle`), and additionally make the `LendTxGenerator` transfer conditional/atomic with a successful, sufficiently-repaying `SwapTx` execution within the same bundle rather than unconditionally preceding it.

### Proof of Concept
1. Attacker identifies the DEX pool backing a token registered with `GaslessSwapRouter` (`dexAddress(token)`).
2. Within a single block/bundle, attacker (or colluding proposer/searcher) flash-loans the pool's quote asset and swaps to skew reserves so that `GetAmountIn(token, minAmountOut)` returns an artificially low `requiredAmountIn`.
3. Attacker submits a `GaslessApproveTx` + `GaslessSwapTx` pair (per `decodeSwapTx`/`checkBalanceForSwap`, [8](#0-7) ) with `amountIn` just above the manipulated `requiredAmountIn`, which passes mempool admission.
4. The proposer's `LendTxGenerator` unconditionally sends real KAIA gas funding to the attacker (per documented block-building order in [9](#0-8) ).
5. Attacker reverts the flash loan/unwinds the price skew; the actual on-chain swap in `swapForGas` ( [10](#0-9) ) executes against the restored, true price, yielding less value than the true fair cost of the lent gas, so the proposer is under-repaid relative to the real market rate.

Note: The `GaslessSwapRouter.sol` source was not present in this repository's index (only Go bindings/ABI were available), so the exact internal pricing/repay-check logic executed inside `swapForGas` at settlement time could not be fully verified; this affects confidence in step 5's precise mechanics and should be confirmed by reviewing the actual contract source before remediation.

```markdown
Note that gasless transaction does not mean the gas prices of gasless transactions are zero, but it means that proposer will lend the user with gas fee and user will pay back during gasless swap.

The gas fee of gasless transaction's is funded by block proposer (i.e., lend transaction generated by `GetLendTxGenerator`), and user repays the lent amount during gasless swap.

### Transaction pool rules

#### Ready

This module is responsible for promoting gasless transactions.
Sender's nonce of GaslessSwapTx is checked to distinguish if GaslessApproveTx is expected. If `tx.nonce == GetNonce(sender) + 1`, GaslessApproveTx is expected. If `tx.nonce == GetNonce(sender)`, GaslessApproveTx is not expected.

If GaslessApproveTx is expected, GaslessApproveTx and GaslessSwapTx can be promoted when they are both ready for execution.
Otherwise, GaslessSwapTx can be promoted when it is ready for execution.

See ready condition [KIP-247](https://kips.kaia.io/KIPs/kip-247) and the implementation `IsExecutable(approveTxOrNil, swapTx *types.Transaction) bool`.

#### Balance check

Sender balance check is omitted for gasless transactions (see `GetCheckBalance()`).

### Block building rules

Upon detection of GaslessTxs, the following logics are executed:

- Per sender, if exists, GaslessApproveTx is relocated before GaslessSwapTx.
- LendTxGenerator is prepended before GaslessApproveTx.
- A new bundle is generated which contain either `[LendTxGenerator, GaslessApproveTx, GaslessSwapTx]` or `[LendTxGenerator, GaslessSwapTx]`
- If the bundle has conflict with any previous bundles, it is excluded from the returned bundle list.
```

```go
func decodeSwapTx(tx *types.Transaction, signer types.Signer) (args *SwapArgs, ok bool) {
	to, inputs, ok := decodeFunctionCall(tx, routerSwapFunc)
	if !ok {
		return nil, false
	}
	token, ok := inputs["token"].(common.Address)
	if !ok {
		return nil, false
	}
	amountIn, ok := inputs["amountIn"].(*big.Int)
	if !ok {
		return nil, false
	}
	minAmountOut, ok := inputs["minAmountOut"].(*big.Int)
	if !ok {
		return nil, false
	}
	amountRepay, ok := inputs["amountRepay"].(*big.Int)
	if !ok {
		return nil, false
	}
	deadline, ok := inputs["deadline"].(*big.Int)
	if !ok {
		return nil, false
	}
	from, err := types.Sender(signer, tx)
	if err != nil {
		return nil, false
	}
	return &SwapArgs{
		Sender:       from,
		Router:       to,
		Token:        token,
		AmountIn:     amountIn,
		MinAmountOut: minAmountOut,
		AmountRepay:  amountRepay,
		Deadline:     deadline,
	}, true
}
```
