## Title
Attacker-controlled `WWW-Authenticate` header from a malicious git remote forces GitHub Desktop into an unauthorized GitHub Enterprise sign-in flow bound to the attacker's host — (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The External Report's broken invariant is: a value that should reflect ground truth (total conviction score) is instead derived from data an unprivileged party can manipulate before the "distribution" decision is made, letting the attacker skew the outcome. The Desktop analog is `getEndpointKind()` in the credential-helper trampoline: it classifies a remote endpoint as `github.com` / `enterprise` / `generic` partly by trusting the `WWW-Authenticate` header that the *remote git server itself* returns during an HTTP auth challenge, without any independent verification. A malicious git remote/proxy can forge this header to make Desktop treat an arbitrary attacker-controlled host as a "GitHub Enterprise" endpoint, which changes the credential-handling path and triggers `promptForGitHubSignIn()` bound to the attacker's origin.

### Finding Description
Git captures any `WWW-Authenticate` header from the server it's talking to and forwards it verbatim to the configured credential helper — this is documented directly in the code: [1](#0-0) 

`getEndpointKind()` uses this attacker-supplied header as a "happy path" signal, treating a `realm="GitHub"` value as proof the host is a GitHub Enterprise server — before ever verifying the host via an actual account match or a real capability probe: [2](#0-1) 

Because `Credential` is just a `Map<string,string>` built by parsing the git credential-protocol stdin (`parseCredential`), any key (including `wwwauth[]`) originates entirely from data the remote git server returned: [3](#0-2) 

Once `getEndpointKind()` returns `'enterprise'` for a host with no existing matching account, `getCredential()` does not fall back to the safe "generic" credential path (used for arbitrary git hosts); instead it calls `ui.promptForGitHubSignIn(endpoint)`: [4](#0-3) 

`promptForGitHubSignIn()` then unconditionally starts the GitHub Enterprise sign-in flow and binds the sign-in session to the attacker's origin via `dispatcher.setSignInEndpoint(origin)`: [5](#0-4) 

The corrupted value here is the **endpoint classification (`endpointKind`)**, which should only ever be `'enterprise'`/`'github.com'` for a host Desktop can independently verify as a real GitHub host, but is instead derivable from attacker-controlled response headers.

### Impact Explanation
This lets an attacker who controls a git remote (or a MITM/HTTP proxy sitting in front of any HTTPS git remote the user adds/fetches from) force GitHub Desktop to present a "Sign in to GitHub Enterprise" dialog scoped to the attacker's chosen origin, instead of routing the request through the safe generic-credential/external-helper path used for unknown hosts. This is precisely the "unauthorized OAuth or account binding" impact class: Desktop's sign-in session (`dispatcher.beginEnterpriseSignIn` / `setSignInEndpoint`) is bound to a host the user never explicitly chose to authenticate against — the binding decision was hijacked by the remote server's own response, not by user intent or Desktop-side host validation.

### Likelihood Explanation
No local access, no leaked credentials, and no unusual user action are required beyond the normal git workflow already covered by "Valid Impact" (cloning/fetching from an attacker-controlled remote, or an MITM/proxy in the path of any git host). The header-forwarding behavior ("Git attempts to authenticate ... forwards them to the credential helper") is intentional and always active whenever HTTPS auth is challenged, so any repository the user adds pointing at a server the attacker controls can trigger this path on the very first fetch/clone/push. The only mitigating factor is that `getEndpointKind()` performs the `wwwauth` check before falling through to independent checks like `isGitHubHost()`, so the forged header takes precedence over legitimate verification when a matching account doesn't already exist for that endpoint.

### Recommendation
Do not trust the `wwwauth[]` realm value as a positive classification signal on its own. Treat it, at most, as a hint to *additionally* perform the existing independent verification (`isGitHubHost(endpoint)`, matching against known/previously-verified GitHub Enterprise origins) before routing to `promptForGitHubSignIn()`. Never bind a sign-in/OAuth session to an origin whose "GitHub-ness" was established solely from data returned by that same origin.

### Proof of Concept
1. Attacker stands up an HTTPS git server (or MITM proxy) at `https://evil.example.com/repo.git`.
2. Victim adds this URL as a remote in GitHub Desktop and performs `fetch`/`clone`/`push`.
3. Git issues an HTTP request; the attacker's server responds with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
4. Git forwards this via the credential-helper protocol; `parseCredential()` stores it under a `wwwauth[...]` key [6](#0-5) .
5. `getEndpointKind()` matches the `realm="GitHub"` pattern and returns `'enterprise'` [7](#0-6) , without ever calling `isGitHubHost(endpoint)`.
6. `getCredential()` finds no existing account for `evil.example.com` and, since `endpointKind !== 'generic'`, calls `ui.promptForGitHubSignIn('https://evil.example.com')` [8](#0-7) .
7. Desktop opens a GitHub Enterprise sign-in dialog bound to `evil.example.com` via `setSignInEndpoint(origin)` [9](#0-8) , an outcome the user never requested and which Desktop never independently validated as a real GitHub Enterprise instance.

Note: I was not able to fully trace the downstream Enterprise sign-in/OAuth implementation (`dispatcher.beginEnterpriseSignIn`, `sign-in-store.ts`) within the remaining investigation budget to confirm exactly what secret material (if any) is transmitted to the attacker's endpoint during that flow — this would need further verification, ideally via a Devin session with full repo access, to determine whether this escalates beyond unauthorized account/session binding to actual token exfiltration.

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

import { exec as git } from 'dugite'

export const parseCredential = (value: string) => {
  const cred = new Map<string, string>()

  // The credential helper protocol is a simple key=value format but some of its
  // keys are actually arrays which are represented as multiple key[] entries.
  // Since we're currently storing credentials as a Map we need to handle this
  // and expand multiple key[] entries into a key[0], key[1]... key[n] sequence.
  // We then remove the number from the key when we're formatting the credential
  for (const line of value.split(/\r?\n/)) {
    const eqIx = line.indexOf('=')
    if (eqIx === -1) {
      continue
    }

    const k = line.slice(0, eqIx)
    const v = line.slice(eqIx + 1)

    if (k.endsWith('[]')) {
      let i = 0
      let newKey

      do {
        newKey = `${k.slice(0, -2)}[${i}]`
        i++
      } while (cred.has(newKey))

      cred.set(newKey, v)
    } else {
      cred.set(k, v)
    }
  }

  return cred
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }
