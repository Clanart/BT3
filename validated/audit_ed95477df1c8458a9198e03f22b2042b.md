### Title
Stale on-chain price quote in gasless swap admission check enables griefing of `swapForGas` fee-delegation settlement - (File: `kaiax/gasless/impl/tx_pool.go`)

### Summary
The Kaia gasless module admits `SwapTx` transactions into the tx pool by validating `tx.amountIn >= gsr.getAmountIn(minAmountOut)` using a single point-in-time call to the `GaslessSwapRouter` contract's live AMM-based exchange rate. This mirrors the audited Malt `UniswapHandler.addLiquidity` pattern: a slippage/amount check computed from "whatever the current on-chain balance/reserve state happens to be" at validation time, with no guarantee that the same ratio holds at actual execution time.

### Finding Description
`checkBalanceForSwap` in [1](#0-0)  performs the following checks when a `SwapTx` is added or re-validated in the tx pool:
- `minAmountOut >= amountRepay`
- `amountIn >= gsr.getAmountIn(token, minAmountOut)` — computed via a live call into `GaslessSwapRouter.GetAmountIn`, i.e., based on the AMM pool's current reserves [2](#0-1) 
- token allowance/balance sufficiency

This check is invoked from `blockchain/tx_pool.go`'s `validateTx` at the moment a transaction is submitted, and again from `blockchain/tx_list.go`'s `Filter` each time the pool re-evaluates pending/queued transactions against the *current* state: [3](#0-2) [4](#0-3) . Because `GetCheckBalance` is only re-run opportunistically (on pool re-validation events), and the actual `swapForGas` execution happens later during block building, an unprivileged actor can shift the underlying AMM reserves (e.g., by submitting ordinary swaps against the same pool that the `GaslessSwapRouter` uses) between the time a legitimate gasless `SwapTx` passes this admission check and the time the block proposer actually executes it. Since `minAmountOut` is enforced strictly at execution time inside `swapForGas` (per the ABI signature bound in [5](#0-4) ), such reserve manipulation makes the previously-admitted transaction revert on execution, even though it satisfied the pool's own quote-based admission rule.

This is the same root-cause pattern as the Malt report: a min-amount / slippage guard is derived from a **live, manipulable exchange-rate snapshot** rather than being enforced consistently between check-time and execution-time, so an attacker can force reverts of otherwise-valid transactions.

### Impact Explanation
The gasless flow relies on the swap succeeding to deliver `amountRepay` KAIA to the fee-delegating proposer (see `SwappedForGas` event structure with `AmountRepaid`/`Commission` fields [6](#0-5) ). If the swap execution reverts because the on-chain exchange rate has moved between admission-time validation and execution, the block proposer who included the `ApproveTx`+`SwapTx` bundle expends real gas resources building/attempting the bundle without receiving the promised repayment, and the `IsExecutable`/`IsReady` bundle-promotion logic in [7](#0-6)  does not re-verify the swap quote immediately before inclusion. This constitutes a griefing vector against the gasless fee-delegation settlement mechanism, reachable purely by any public-RPC caller/unprivileged transaction sender manipulating the shared AMM pool that the whitelisted `GaslessSwapRouter` reads from — no privileged access needed.

### Likelihood Explanation
Reachability is straightforward: any account can submit ordinary swap transactions against the underlying liquidity pool used by `GaslessSwapRouter.GetAmountIn`, and any account (including the attacker) can also be the `SwapTx` sender or simply target another user's pending gasless swap. The gap between admission-time quote check and execution-time enforcement is inherent to the tx-pool design (mempool dwell time, block-building reordering), making this practically triggerable rather than theoretical, matching the "confirmed, medium severity" disposition of the original Malt finding for the analogous root cause.

### Recommendation
- Re-validate `checkBalanceForSwap`'s quote-derived fields (`GetAmountIn`) immediately before block inclusion, not only at pool admission/periodic re-validation, or
- Have `swapForGas` compute/verify amounts using a reference tied to values the proposer/user explicitly agreed at signing time (already partially done via `minAmountOut`/`amountRepay`), and treat pool-admission quote checks purely as a fast-fail heuristic, not a guarantee, so failures at execution are anticipated and do not waste proposer resources (e.g., by excluding/dropping the bundle instead of letting it revert on-chain).
- Consider bundling atomicity guarantees so that a reverting `SwapTx` cannot be included without compensating the proposer, or add a final on-chain check that re-derives `GetAmountIn` at the very start of `swapForGas` and fails cheaply before performing state-changing operations.

### Proof of Concept
1. Attacker observes a pending `ApproveTx`+`SwapTx` gasless bundle in the mempool (or targets their own bundle).
2. Attacker submits a swap transaction directly against the underlying AMM pool used by `GaslessSwapRouter`, shifting reserves so that the previously-computed `GetAmountIn(token, minAmountOut)` at admission time is now insufficient for the declared `AmountIn` in the pending `SwapTx` ( [2](#0-1) ).
3. The block proposer, having already promoted the bundle via `IsReady`/`IsExecutable` ( [7](#0-6) ) based on the stale quote, includes the bundle in a block.
4. `swapForGas` executes with its own strict `minAmountOut` check and reverts, so the proposer's `amountRepay` is not received despite the gas already spent processing/including the transactions — a proposer-facing griefing loss with no compensating value transfer.

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut

		if g.getCurrentHasCode(swapArgs.Sender) {

		}

		// tx.amountIn >= gsr.getAmountIn(minAmountOut)

			return err

			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

// Check promotion condition and enforce pending pool flow control.
func (g *GaslessModule) IsReady(txs map[uint64]*types.Transaction, next uint64, ready types.Transactions) bool {
	g.knownTxsMu.Lock()
	defer g.knownTxsMu.Unlock()

	tx, ok := txs[next]
	if !ok {
		return false
	}

	if !g.isReady(txs, next, ready) {
		return false
	}

	if g.IsBundleTx(tx) {
		// If prev tx is bundle tx, there's no need to check the knownTxs limit because it has been checked in the previous `IsReady()` execution.
		isPrevTxBundleTx := len(ready) != 0 && g.IsBundleTx(ready[len(ready)-1])
		if isPrevTxBundleTx {
			g.knownTxs.add(tx, TxStatusPending)
			return true
		}

		maxBundleTxsInPending := g.GetMaxBundleTxsInPending()
		if maxBundleTxsInPending != math.MaxUint64 {
			numExecutable := uint(g.knownTxs.numExecutable())

			numSeqTxs := uint(1)
			for i := next + 1; i < next+uint64(len(txs)); i++ {
				if tx, ok := txs[i]; ok && g.IsBundleTx(tx) {
					numSeqTxs++
				} else {
					break
				}
			}

			// false if there is possibility of exceeding max bundle tx num
			if numExecutable+numSeqTxs > maxBundleTxsInPending {
				logger.Trace("Not promoting a tx because of exceeding max bundle tx num", "tx", tx.Hash().String(), "numExecutable", numExecutable, "maxBundleTxsInPending", maxBundleTxsInPending)
				return false
			}
		}

		g.knownTxs.add(tx, TxStatusPending)
	}

	return true
}

// Check promotion condition.
func (g *GaslessModule) isReady(txs map[uint64]*types.Transaction, i uint64, ready types.Transactions) bool {
	tx := txs[i]

	if g.IsApproveTx(tx) && i < uint64(math.MaxUint64) {
		return g.isApproveTxReady(tx, txs[i+1])
	}

	if g.IsSwapTx(tx) {
		var prevTx *types.Transaction
		if len(ready) > 0 {
			prevTx = ready[len(ready)-1]
		}
		return g.isSwapTxReady(tx, prevTx)
	}

	return false
}

// isApproveTxReady assumes that the caller checked `g.IsApproveTx(approveTx)`
func (g *GaslessModule) isApproveTxReady(approveTx, nextTx *types.Transaction) bool {
	addr, err := types.Sender(g.signer, approveTx)
	if err != nil {
		return false
	}
	nonce := g.getCurrentStateNonce(addr)

	if approveTx.Nonce() != nonce {
		return false
	}
	if nextTx == nil || !g.IsSwapTx(nextTx) {
		return false
	}

	return g.IsExecutable(approveTx, nextTx)
}

// isSwapTxReady assumes that the caller checked `g.IsSwapTx(swapTx)`
func (g *GaslessModule) isSwapTxReady(swapTx, prevTx *types.Transaction) bool {
	addr, err := types.Sender(g.signer, swapTx)
	if err != nil {
		return false
	}
	nonce := g.getCurrentStateNonce(addr)

	var approveTx *types.Transaction
	if swapTx.Nonce() == nonce {
		approveTx = nil
	} else if swapTx.Nonce() == nonce+1 {
		if prevTx == nil || !g.IsApproveTx(prevTx) {
			return false
		}
		approveTx = prevTx
	} else {
		return false
	}

	return g.IsExecutable(approveTx, swapTx)
}
