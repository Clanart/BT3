Based on my investigation, I found a concrete asymmetry in the ISMP response-delivery path on EVM hosts that is a direct structural analog to the reported "missing input validation" class of bug (here: missing address/code validation before treating a destination call as a successful callback).

### Title
Missing destination code-size check in `dispatchIncoming(GetResponse)` allows a response to be silently finalized without executing the destination module - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.dispatchIncoming` for `PostRequest` explicitly checks that the destination address has code before dispatching and writing any receipt, but the sibling function for `GetResponse` does not perform the same check before calling the destination and marking the response as permanently handled.

### Finding Description
For incoming POST requests, `EvmHost.dispatchIncoming(PostRequest, address)` first resolves the destination address and checks its `extcodesize`; if it is zero, the function returns immediately, before writing `_requestReceipts[commitment]`, so the request is not marked as delivered and can be retried/timed out normally: [1](#0-0) 

For incoming GET responses, `EvmHost.dispatchIncoming(GetResponse, address)` performs no such check. It writes the one-time `_responseReceipts[commitment]` receipt, then makes a low-level `.call()` to `_bytesToAddress(response.request.from)`: [2](#0-1) 

In the EVM, a low-level `.call()` to an address with no deployed code always returns `success == true` (there is nothing to revert). Consequently, if `response.request.from` decodes to an address that has no code — because the request originator was an EOA, or because the original calling contract has since been destroyed via `SELFDESTRUCT` between request dispatch and response delivery — the call trivially "succeeds" even though no module logic ever executes `onGetResponse`. The code then proceeds to pay the relayer fee and emit `GetRequestHandled`, and (crucially) `_responseReceipts[commitment]` is now permanently set, which the batching handler in `HandlerV2.handleGetResponses` uses as the sole duplicate-protection gate: [3](#0-2) 

Because the receipt is written unconditionally before the external call (mirroring the POST path's replay-protection pattern but without the accompanying code-size guard), the response commitment can never be redelivered, and any application logic gated behind `onGetResponse` — for example, `IntentGatewayV2`/`IntentsBase`'s cross-chain cancellation flow, whose `onGetResponse` handler is what actually triggers `withdraw()` to refund escrowed user funds — will never run if `from` resolves to a non-contract address at delivery time: [4](#0-3) 

### Impact Explanation
This breaks the "request/response paths must bind... one-time receipt handling" invariant: the receipt is finalized and the relayer is paid for a "delivery" that never reaches the destination module. Where a GET response drives fund-moving logic (e.g., intent-gateway cancellation refunds via `onGetResponse` → `withdraw()`), this can permanently strand escrowed user funds, since the commitment is marked delivered and cannot be retried through the normal handler path.

### Likelihood Explanation
Exploitability depends on the ability to make `response.request.from` resolve to a non-contract address at the time the response is delivered. This is plausible if (a) the ISMP dispatch entrypoint for GET requests does not require the caller to be a contract (permitting EOA-originated requests), or (b) an attacker-controlled contract self-destructs after dispatching a GET request but before the response is relayed back — both are actions available to an ordinary unprivileged user, not requiring a malicious relayer, prover, or admin. I was not able to fully confirm within the available context whether the `dispatch(DispatchGet)` entrypoint restricts callers to contract addresses, so likelihood should be treated as moderate/unconfirmed pending that check.

### Recommendation
Add the same `extcodesize` guard used in `dispatchIncoming(PostRequest)` to `dispatchIncoming(GetResponse)` (and to the `dispatchTimeOut` variants that share this pattern), returning early — without writing `_responseReceipts` or paying the relayer — when the destination has no code, so the response remains retryable instead of being silently and permanently finalized.

### Proof of Concept
1. Deploy a minimal contract `C` whose only purpose is to call the ISMP host's GET-dispatch entrypoint (recording `from = address(C)`), then `SELFDESTRUCT` in the same transaction or shortly after.
2. Wait for a relayer to submit the `GetResponseMessage` proof; `HandlerV2.handleGetResponses` passes the standard duplicate/proof checks (there is no on-chain requirement that `from` still contains code) and calls `host.dispatchIncoming(response, relayer)`.
3. Inside `dispatchIncoming(GetResponse)`, `_bytesToAddress(response.request.from)` now points to an address with zero code; the low-level `.call()` returns `success = true` trivially.
4. `_responseReceipts[commitment]` is already set (before the call) and remains set; the relayer fee is paid and `GetRequestHandled` is emitted — even though `C`'s intended `onGetResponse` logic (e.g., a fund refund) never executed and can never be retried. [5](#0-4)

    function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
        address destination = _bytesToAddress(request.to);
        uint256 size;
        assembly {
            size := extcodesize(destination)
        }
        if (size == 0) {
            // instead of reverting the entire batch, early return here.
            return;
        }

        // replay protection
        bytes32 commitment = request.hash();
        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)
            .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));

        if (!success) {
            // so that it can be retried
            delete _requestReceipts[commitment];
            return;
        }
        emit PostRequestHandled({commitment: commitment, relayer: relayer});
    }

    /**
     * @dev Dispatch an incoming GET response to source module
     * @param response - get response
     */
    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }
