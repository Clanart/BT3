### Title
Unbounded, timelock-free `updateCommissionRate()` on GaslessSwapRouter lets the owner instantly change fees charged to gasless swap users - ([File: contracts/bindings/kip247/GaslessSwapRouter.go])

### Summary
`GaslessSwapRouter` (KIP-247), the on-chain router used by Kaia's gasless module to let fee-less users swap ERC-20 tokens to repay gas sponsors, exposes `updateCommissionRate(uint256 _commissionRate)` [1](#0-0)  as an owner-only mutator with no timelock, no visible upper bound enforcement in the reachable interface, and no delayed activation before being applied to in-flight `swapForGas` calls.

### Finding Description
`swapForGas` is the function reachable by an ordinary, fee-delegation/gasless user submitting a swap+approve transaction pair processed by the node's `kaiax/gasless` module [2](#0-1) . The gasless tx-pool validation (`checkBalanceForSwap`/`VerifyExecutable`) only checks `minAmountOut >= amountRepay`, required `amountIn`, allowance, balance, and deadline; it does not read or pin the router's `commissionRate` at submission time [3](#0-2) . The final settlement, including `Commission` and `FinalUserAmount`, is computed inside the router contract at execution time and only surfaced afterward via the `SwappedForGas` event [4](#0-3) . Because `commissionRate` can be changed by the owner at any time via `updateCommissionRate`, with no delay/timelock and no cap enforced in the ABI-visible interface, a rate change can land between a user's signed swap transaction being broadcast and it being mined, altering the commission deducted from the swap output without the user's consent or advance notice.

### Impact Explanation
This directly affects unprivileged gasless-swap users: an increase in `commissionRate` reduces `finalUserAmount` (and could push the effective repay economics against the user or the sponsoring proposer) with no time window for a signed pending transaction to be withdrawn, and no protocol-level cap preventing an extreme rate. This is a fee/fee-delegation abuse and gasless-settlement risk pattern, matching the report's underlying bug class ("fee setter with no timelock/notice period harms unprivileged counterparties") applied to Kaia's gasless module's on-chain fee point.

### Likelihood Explanation
Requires the router owner to act, but no compromise or governance vote is needed — a single `updateCommissionRate` transaction is immediately effective for the very next `swapForGas` executed by any user, and gasless swap users have no mechanism in the node's `kaiax/gasless` validation path to detect or reject an unexpected commission change before submission.

### Recommendation
Add a timelock (e.g., minimum delay between proposing and activating a new `commissionRate`) and/or a maximum bound plus an event-driven grace period, and consider having the gasless module read/pin the effective `commissionRate` at validation time and re-validate it has not changed unfavorably before the swap is executed.
