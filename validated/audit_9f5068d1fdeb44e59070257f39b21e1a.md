## Title
Host-agnostic regex in `githubAssetVideoRegex` allows video/link filters to trust lookalike domains as GitHub asset CDN URLs - ([File: app/src/lib/markdown-filters/video-url-regex.ts])

## Summary
`githubAssetVideoRegex`, used by both `VideoLinkFilter.getGithubVideoLink` and `VideoTagFilter`, is built as a plain string-prefix regex rather than a proper origin/host check. Because the regex only requires the string to *start with* the literal `https://user-images.githubusercontent.com` and then match `.+` before an (effectively optional) extension, any attacker-controlled URL whose string begins with that exact substring — even if the real host is a completely different, attacker-owned domain such as `user-images.githubusercontent.com.evil.com` — passes validation and is treated as a trusted GitHub CDN asset.

## Finding Description
The regex is constructed here: [1](#0-0) 

`escapeRegExp(user_images_cdn_url)` only escapes regex metacharacters in `https://user-images.githubusercontent.com` — it does not anchor the match to the URL's authority/host component. The pattern is `^` + literal-escaped-prefix + `.+` + `videoExtensionRegex`. Since `videoExtensionRegex` is `/(mp4|webm|ogg|mov|qt|avi|wmv|3gp|mpg|mpeg|)$/`, note the trailing empty alternative (`|)$`) — the extension check itself is optional, so effectively *any* string beginning with the literal prefix matches, regardless of what follows.

`VideoLinkFilter.getGithubVideoLink` uses this regex directly on `node.firstChild.href` with no host parsing (e.g., no `new URL(href).hostname === 'user-images.githubusercontent.com'` check): [2](#0-1) 

`VideoTagFilter` uses the same regex to decide whether to keep or strip a `<video>` tag's `src`: [3](#0-2) 

Because `.+` can match any character including `.` and `/`, a URL like `https://user-images.githubusercontent.com.evil.com/payload.mp4` (where the actual DNS host is `user-images.githubusercontent.com.evil.com`, entirely attacker-controlled) satisfies:
- `^https://user-images.githubusercontent.com` — matches the literal prefix exactly
- `.+` — matches `.evil.com/payload`
- extension group — matches `mp4`

So `getGithubVideoLink` returns this attacker URL as a "trusted" video source, and a `<video>` element is created with `src` pointing at the attacker's server.

This node is then inserted into the sandboxed iframe's document by `SandboxedMarkdown.applyFilters`, and the iframe (`sandbox="allow-same-origin"`, no `allow-scripts`) will load the `<video>` resource from the attacker-controlled origin: [4](#0-3) [5](#0-4) 

## Impact Explanation
Because the iframe sandbox does not include `allow-scripts`, this does not directly yield JavaScript execution or sandbox escape from the video load itself. The concrete, reachable impact is:
- Loading of arbitrary attacker-hosted content disguised as a "verified" GitHub CDN asset inside the app's rendered markdown (PR bodies, issue/PR comments, commit messages, Copilot conflict summaries, etc., all of which route through `SandboxedMarkdown`).
- This defeats the explicit security intent of the filter (per its own comment: "If not, the link is left unmodified" / "we remove the video tag" if not a genuine GitHub asset) which exists specifically to prevent embedding of untrusted external media/network requests in rendered markdown.
- It enables silent network beaconing to an attacker server merely by the victim viewing a PR/issue/commit containing such a link — leaking IP address, user-agent, and confirming the content was rendered by a specific Desktop user, without any click.

This does not meet the higher-severity outcomes required in the "Valid Impact" list (code execution, IPC/sandbox escape, credential exfiltration, file read/write outside repo, commit corruption); it is a validation-logic weakness whose practical impact here is limited to loading external, non-CDN media resulting in a tracking/beacon leak and content-spoofing inside a trusted-looking video element.

## Likelihood Explanation
Any attacker who can post a PR description, issue comment, PR comment, or commit message (i.e., a repository/API-object attacker) can trivially craft a URL of the form `https://user-images.githubusercontent.com.<attacker-domain>/x.mp4` (a valid, registrable subdomain) and have it auto-linked by the markdown parser, satisfying the regex.

## Recommendation
Replace the substring-prefix regex with a proper URL/host check, e.g., parse the href with `new URL()` and verify `url.protocol === 'https:'` and `url.hostname === 'user-images.githubusercontent.com'` (exact match, not `startsWith`/regex-prefix), for both `VideoLinkFilter` and `VideoTagFilter`. Also remove the empty alternative in `videoExtensionRegex` so a valid video extension is mandatory.

## Proof of Concept
1. Attacker registers `user-images.githubusercontent.com.evil.com` (a distinct, attacker-owned DNS name) and hosts an `.mp4` file at `https://user-images.githubusercontent.com.evil.com/x.mp4`.
2. Attacker posts a PR/issue comment body containing only the link, e.g.:
   ```
   https://user-images.githubusercontent.com.evil.com/x.mp4
   ```
3. Marked auto-links this into `<p><a href="https://user-images.githubusercontent.com.evil.com/x.mp4">...</a></p>`.
4. `VideoLinkFilter.getGithubVideoLink` runs `githubAssetVideoRegex.test(href)`, which returns `true` because the string starts with the literal CDN prefix and ends in `mp4`.
5. A `<video src="https://user-images.githubusercontent.com.evil.com/x.mp4">` element is inserted into the sandboxed markdown iframe's DOM and loaded when the victim views the PR/issue in Desktop.

  private getGithubVideoLink(node: Node): string | null {
    if (
      isElement(node, 'p') &&
      node.childElementCount === 1 &&
      node.firstChild &&
      isElement(node.firstChild, 'a') &&
      githubAssetVideoRegex.test(node.firstChild.href)
    ) {
      return node.firstChild.href
    }

    return null
  }

  private async applyFilters(doc: Document) {
    const { emoji, repository, markdownContext } = this.props
    const filters = buildCustomMarkDownNodeFilterPipe({
      emoji,
      repository,
      markdownContext,
    })

    for (const nodeFilter of filters) {
      let docMutated = false
      const walker = nodeFilter.createFilterTreeWalker(doc)

      let node = walker.nextNode()
      while (node !== null) {
        const replacementNodes = await nodeFilter.filter(node)

        if (this.currentDocument !== doc) {
          // Abort, the document has changed
          return
        }

        const currentNode = node
        node = walker.nextNode()

        if (replacementNodes === null) {
          continue
        }

        docMutated = true

        for (const replacementNode of replacementNodes) {
          currentNode.parentNode?.insertBefore(replacementNode, currentNode)
        }
        currentNode.parentNode?.removeChild(currentNode)
      }

      if (docMutated) {
        this.refreshHeight()
      }
    }
  }
