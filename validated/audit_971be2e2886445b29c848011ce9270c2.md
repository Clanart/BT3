### Title
Untrusted `ReceivedOutput::read` accepts an attacker-chosen outpoint, value, and script as a legitimately received output (`..`-style pointer outside the scanned set) - ([File: networks/bitcoin/src/wallet/mod.rs])

### Summary
CVE-2016-7569 is a traversal bug: attacker-controlled bytes embedded in a payload (the `..` in layer data) act as a pointer causing an action (file write) at a location outside the intended set. The direct analog in Serai is `ReceivedOutput::read` in `networks/bitcoin/src/wallet/mod.rs` (lines 122-134), which deserializes a fully attacker-controlled triple of `(offset: Scalar, output: TxOut, outpoint: OutPoint)` and returns it as a "spendable output the wallet received". The `outpoint` is an arbitrary pointer — the equivalent of `../` — that can name any `(txid, vout)` on or off the chain, the `value`/`script_pubkey` inside `output` are arbitrary, and nothing ties the three fields together or to an actual scanned transaction. Downstream, `SignableTransaction::new`/`multisig` in `networks/bitcoin/src/wallet/send.rs` consume these fields verbatim for balance accounting, change/fee math, and the sighash's `Prevouts::All` commitment.

### Finding Description
`Scanner::scan_transaction`/`scan_block` (mod.rs:199-227) produce genuine `ReceivedOutput`s whose `outpoint` is `tx.compute_txid()` + real `vout` and whose `output` is the real `TxOut`. `ReceivedOutput::read` (mod.rs:122-134) bypasses all of that: it reads `offset` via `Secp256k1::read_F`, then consensus-decodes a `TxOut` and an `OutPoint` straight from the reader, with no check that:

- the `outpoint` names an output that exists or was ever received,
- `output.script_pubkey` equals `p2tr_script_buf(key + GENERATOR * offset)` (the only consistency check lives later, in `SignableTransaction::multisig` at send.rs:277, and it only covers the script — never the outpoint's authenticity or the claimed `value` against the chain).

`TxOut::consensus_decode` does not range-check `value`, so a forged output can claim up to `u64::MAX` sats. `SignableTransaction::new` (send.rs:150-256) then uses `input.output.value.to_sat()` for `input_sat` (line 175), `input.outpoint` for the `TxIn` (line 180), and stores `input.output` into `prevouts` (line 253), which `TransactionSignMachine::sign` commits to via `Prevouts::All(&self.tx.prevouts)` (send.rs:375-386).

### Impact Explanation
Integrity impact, matching the CVE's `I:H`:

1. **Funds reported received that are not spendable.** A forged `ReceivedOutput` deserialized from untrusted bytes reports ownership of an arbitrary UTXO at an arbitrary value — e.g., a fabricated `(txid, vout)` pointing outside the legitimately scanned set (the traversal analog). The wallet's balance accounting (`input_sat`, send.rs:175) and any consumer of `value()`/`outpoint()` treat it as real, yet no such spendable output exists.
2. **Signature produced over an unintended message.** Because `multisig` (send.rs:275-285) only verifies `p2tr_script_buf(offset.group_key()) == prevouts[i].script_pubkey`, a forged `ReceivedOutput` carrying a copied group P2TR script passes the check and the threshold group produces a valid Schnorr signature over a sighash committing to a fabricated prevout set/amounts — a signature for a transaction spending outputs the group never received, which is unspendable/invalid on-chain while consuming a real signing session and its preprocesses.

### Likelihood Explanation
`ReceivedOutput::read` is a public deserialization API intended for persisted/transported output data (its `serialize`/`read` round-trip exists precisely for that). Any channel that lets an unprivileged party influence the bytes later read — e.g., stored plans/outputs relayed between components — reaches it. It requires no key material, no collusion, and only public data (a valid group P2TR script is public information). It does not allow recovering the group key or validly spending others' coins, bounding this at Medium rather than High.

### Recommendation
- In `ReceivedOutput::read` (or a validating constructor), require proof of consistency: at minimum, have callers pass the expected `key`/`Scanner` and assert `output.script_pubkey == p2tr_script_buf(key + GENERATOR * offset)`, failing deserialization otherwise rather than deferring a partial check to `multisig`.
- Treat deserialized `ReceivedOutput`s as claims to be re-verified against the chain (confirm the outpoint exists with the claimed value/script) before balance accounting or signing, mirroring how `scan_transaction` grounds the struct in a real transaction.
- Bound `value` on read to `Amount::MAX_MONEY` and reject `outpoint`s with sentinel/implausible fields.

### Proof of Concept
```rust
// networks/bitcoin/src/wallet/mod.rs behavior, conceptually:
use bitcoin_serai::wallet::{ReceivedOutput, p2tr_script_buf};
use bitcoin::{OutPoint, TxOut, Amount, Txid, hashes::Hash};
use k256::{Scalar, ProjectivePoint};
use frost::curve::Secp256k1;
use ciphersuite::{group::GroupEncoding, Ciphersuite};

let group_key: ProjectivePoint = /* the threshold group's even P2TR key */;
let script = p2tr_script_buf(group_key).unwrap();

// Forged bytes: offset 0, fabricated TxOut + fabricated outpoint (the ".." pointer)
let mut forged = Vec::new();
forged.extend(Scalar::ZERO.to_bytes());                                   // offset
// TxOut consensus encoding: u64 value + compact-size script
forged.extend(1_000_000_000u64.to_le_bytes());                            // claims 10 BTC
forged.extend(bitcoin::consensus::serialize(&script));
forged.extend(bitcoin::consensus::serialize(&OutPoint {
    txid: Txid::from_raw_hash(/* victim/arbitrary txid */),
    vout: 0,
}));
let ro = ReceivedOutput::read(&mut forged.as_slice()).unwrap();           // accepted
assert_eq!(ro.value(), 1_000_000_000);   // reported as received, unspendable

// Then: SignableTransaction::new(vec![ro], &payments, change, None, fee)
// -> input_sat credited 10 BTC, tx spends a fabricated outpoint;
// multisig() passes because script matches, and FROST signs a sighash
// committing to the fabricated prevouts via Prevouts::All (send.rs:375).
```
