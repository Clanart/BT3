### Title
Branch pruner races with checkout/delete on the same working directory, corrupting HEAD/branch state - ([File: app/src/lib/stores/helpers/branch-pruner.ts])

### Summary
The erigon bug is a classic "background maintenance task races the next foreground operation because the shared gate is released before cleanup finishes" issue. GitHub Desktop has a structurally identical background maintenance task — `BranchPruner` — which runs unattended on a `window.setInterval` timer [1](#0-0)  and performs multiple `await`-separated git reads followed by branch deletions against the exact same working directory that user-triggered operations (checkout, delete branch, commit) also mutate, with no mutex/semaphore serializing the two.

### Finding Description
`BranchPruner.pruneLocalBranches` takes a snapshot of `branchesState` from the `RepositoryStateCache` at the start [2](#0-1) , then performs a sequence of separately-awaited git subprocess calls — `getMergedBranches`, `getSymbolicRef`, `getBranchCheckouts`, `getBranches`, `listWorktrees` — before finally looping and calling `deleteLocalBranch` through `gitStore.performFailableOperation` [3](#0-2) . This entire pipeline spans many event-loop turns.

None of this is gated by anything analogous to the FCU semaphore in the erigon report. The only concurrency guards that exist in `AppStore` are narrow, single-purpose flags — `withIsCommitting` (`isCommitting`), `withPushPullFetch` (`isPushPullFetchInProgress`), `withIsGeneratingCommitMessage` — each of which only prevents concurrent invocations of *that specific* action [4](#0-3) . There is no flag preventing `_checkoutBranch`, `_createBranch`, or `_deleteBranch` from running concurrently with `BranchPruner`. `GitStore.performFailableOperation` (used both by the pruner and by every other git-store operation such as `merge`, `createBranch`, `revertCommit`) is purely an error/retry wrapper — it does not serialize concurrent calls against the same repository [5](#0-4) [6](#0-5) .

Because the pruner reads `recentlyCheckedOutCanonicalRefs`/`allBranches` from a stale snapshot and only checks "is this the currently checked out branch" via `getSymbolicRef('HEAD')` once at the very start (`findBranchesMergedIntoDefaultBranch`, line 121) [7](#0-6) , a user who checks out a merged branch (or creates/checks out a new branch tracking one of the candidate refs) *after* that snapshot but *before* `deleteLocalBranch` executes will not be excluded from pruning. `git branch -D <name>` run on the branch the user has just switched to (or is about to switch to) while a concurrent `_checkoutBranch` is also touching `HEAD`/refs in the same `.git` directory is the corrupted-value analog to erigon's un-gated `Sync` object: two independent async flows mutate the same `.git/refs` and index state without a shared lock, and the invariant "the branch shown as checked out is never deleted out from under the user" is not re-verified at the point of deletion.

### Impact Explanation
This is a silent-corruption-of-repository-state bug class matching the report's "silent corruption of what the user commits or pushes" impact bucket. If the user's active branch (or a branch mid-checkout) is deleted by the pruner racing a checkout, the local ref can be removed while Desktop's UI still shows it as current, leaving the repository in a state where the next commit/push targets a detached HEAD or an unexpected branch, and local work can become orphaned/unreachable. This does not require any special privileges from an attacker beyond controlling the remote's branch/merge topology (a forked or malicious upstream can shape which branches appear "merged into default"), which fits the allowed threat model of an attacker-controlled fetched repository.

### Likelihood Explanation
The prune-eligibility window is real but narrow: the multi-step async pipeline (several sequential git subprocess spawns) creates a window of tens to low hundreds of milliseconds per prune run, and `deleteLocalBranch` is only invoked for branches whose upstream is fully merged and not recently checked out. Triggering it reliably (as opposed to intermittently, mirroring the hive test's own intermittent failure) requires timing a checkout to land inside that window, once every `BackgroundPruneMinimumInterval` (4h enforced by `PruneRuntimeOptions`/`BackgroundPruneMinimumInterval`) [8](#0-7) . This makes it a genuine race rather than a deterministic bug, consistent with the "intermittent" nature described in the erigon source report.

### Recommendation
Serialize `BranchPruner` execution against other repository-mutating operations on the same `Repository`/`GitStore`, e.g. by having `AppStore` acquire the same per-repository operation lock used for checkout/commit/push-pull before invoking `pruneLocalBranches`, and by re-validating (immediately before each `deleteLocalBranch` call) that the branch is neither the current `HEAD` nor mid-checkout, rather than relying solely on a stale snapshot taken at the start of the prune run.

### Proof of Concept
1. Configure a repository so that a non-default local branch `B` has already been merged into the default branch upstream (satisfies `mergedBranches` filter in `findBranchesMergedIntoDefaultBranch`).
2. Wait until `BranchPruner`'s 4-hour interval elapses so `pruneLocalBranches` begins running (or, for local reproduction, call `BranchPruner.testPrune()`/`runOnce()` directly, which skips only the time threshold, not the concurrency gap) [9](#0-8) .
3. Immediately after `getBranchCheckouts`/`getSymbolicRef` are evaluated but before the deletion loop reaches `B`, trigger `Dispatcher._checkoutBranch(repository, B)` from the UI (or via the app-store `_checkoutBranch` public API) [10](#0-9) .
4. Because there is no shared lock between `BranchPruner` and `_checkoutBranch`, the pruner's `deleteLocalBranch(this.repository, 'B')` call can execute after the checkout has switched `HEAD` to `B`, deleting the branch the user is currently on and leaving the working directory/HEAD in an inconsistent state relative to what the UI reports.

  /** @returns a map of canonical refs to their shas */
  private async findBranchesMergedIntoDefaultBranch(
    repository: Repository,
    defaultBranch: Branch
  ): Promise<ReadonlyMap<string, string>> {
    const gitStore = this.gitStoreCache.get(repository)
    const mergedBranches = await gitStore.performFailableOperation(() =>
      getMergedBranches(repository, defaultBranch.name)
    )

    if (mergedBranches === undefined) {
      return new Map<string, string>()
    }

    const currentBranchCanonicalRef = await getSymbolicRef(repository, 'HEAD')

    // remove the current branch
    if (currentBranchCanonicalRef) {
      mergedBranches.delete(currentBranchCanonicalRef)
    }

    return mergedBranches
  }

  public async _checkoutBranch(
    repository: Repository,
    branch: Branch,
    explicitStrategy?: UncommittedChangesStrategy
  ): Promise<Repository> {
    const repositoryState = this.repositoryStateCache.get(repository)
    const { changesState, branchesState } = repositoryState
    const { currentBranchProtected, stashEntry } = changesState
    const { tip } = branchesState
    const hasChanges = changesState.workingDirectory.files.length > 0

    // No point in checking out the currently checked out branch.
    if (tip.kind === TipState.Valid && tip.branch.name === branch.name) {
      return repository
    }

    // If the branch is checked out in another worktree, switch to that worktree
    // instead of checking out the branch in the current worktree.
    const wt = repositoryState.worktrees.find(wt => wt.branch === branch.ref)

    if (wt) {
      return this._switchWorktree(repository, wt)
    }

    let strategy = explicitStrategy ?? this.uncommittedChangesStrategy

    // The user hasn't been presented with an explicit choice
    if (explicitStrategy === undefined) {
      // Even if the user has chosen to "always stash on current branch" in
      // preferences we still want to let them know changes might be lost
      if (strategy === UncommittedChangesStrategy.StashOnCurrentBranch) {
        if (hasChanges && stashEntry !== null) {
          const type = PopupType.ConfirmOverwriteStash
          this._showPopup({ type, repository, branchToCheckout: branch })
          return repository
        }
      }
    }

    // Always move changes to new branch if we're on a detached head, unborn
    // branch, or a protected branch.
    if (tip.kind !== TipState.Valid || currentBranchProtected) {
      strategy = UncommittedChangesStrategy.MoveToNewBranch
    }

    if (strategy === UncommittedChangesStrategy.AskForConfirmation) {
      if (hasChanges) {
        const type = PopupType.StashAndSwitchBranch
        this._showPopup({ type, branchToCheckout: branch, repository })
        return repository
      }
    }

    return this.withRefreshedGitHubRepository(repository, repository => {
      // We always want to end with refreshing the repository regardless of
      // whether the checkout succeeded or not in order to present the most
      // up-to-date information to the user.
      return this.checkoutImplementation(repository, branch, strategy)
        .then(() => this.onSuccessfulCheckout(repository, branch))
        .catch(async e => {
          this.emitError(new CheckoutError(e, repository, branch))
        })
        .then(() => this.refreshAfterCheckout(repository, branch.name))
        .finally(() => this.updateCheckoutProgress(repository, null))
    })
  }

  private async withIsCommitting(
    repository: Repository,
    fn: () => Promise<boolean>
  ): Promise<boolean> {
    const state = this.repositoryStateCache.get(repository)
    // ensure the user doesn't try and commit again
    if (state.isCommitting) {
      return false
    }

    this.repositoryStateCache.update(repository, () => ({
      isCommitting: true,
      hookProgress: null,
      subscribeToCommitOutput: null,
    }))
    this.emitUpdate()

    try {
      return await fn()
    } finally {
      this.repositoryStateCache.update(repository, () => ({
        isCommitting: false,
        hookProgress: null,
        subscribeToCommitOutput: null,
      }))
      this.emitUpdate()
    }
  }

  private async withIsGeneratingCommitMessage(
    repository: Repository,
    fn: (signal: AbortSignal) => Promise<boolean>
  ): Promise<boolean> {
    const state = this.repositoryStateCache.get(repository)
    // ensure the user doesn't try and commit again
    if (state.isGeneratingCommitMessage) {
      return false
    }

    const abortController = new AbortController()

    this.repositoryStateCache.update(repository, () => ({
      isGeneratingCommitMessage: true,
      commitMessageGenerationAbortController: abortController,
    }))
    this.emitUpdate()

    try {
      return await fn(abortController.signal)
    } finally {
      const currentState = this.repositoryStateCache.get(repository)
      if (
        currentState.commitMessageGenerationAbortController === abortController
      ) {
        this.repositoryStateCache.update(repository, () => ({
          isGeneratingCommitMessage: false,
          commitMessageGenerationAbortController: null,
        }))
        this.emitUpdate()
      }
    }
  }

  private async withPushPullFetch(
    repository: Repository,
    fn: () => Promise<void>
  ): Promise<void> {
    const state = this.repositoryStateCache.get(repository)
    // Don't allow concurrent network operations.
    if (state.isPushPullFetchInProgress) {
      return
    }

    this.repositoryStateCache.update(repository, () => ({
      isPushPullFetchInProgress: true,
    }))
    this.emitUpdate()

      await fn()
    } finally {

        isPushPullFetchInProgress: false,

  /** Merge the named branch into the current branch. */
  public merge(
    branch: Branch,
    options?: MergeOptions
  ): Promise<MergeResult | undefined> {
    if (this.tip.kind !== TipState.Valid) {
      throw new Error(
        `unable to merge as tip state is '${this.tip.kind}' and the application expects the repository to be on a branch currently`
      )
    }

    const currentBranch = this.tip.branch.name
    let aborted = false
    const onHookFailure = options?.onHookFailure

    return this.performFailableOperation(
      () =>
        merge(this.repository, branch.name, {
          ...options,
          onHookFailure:
            onHookFailure === undefined
              ? undefined
              : (hookName, terminalOutput) =>
                  onHookFailure(hookName, terminalOutput).then(result => {
                    aborted = result === 'abort'
                    return result
                  }),
        }).catch(e => (aborted ? MergeResult.Failed : Promise.reject(e))),
      {
        gitContext: {
          kind: 'merge',
          currentBranch,
          theirBranch: branch.name,
        },
        retryAction: {
          type: RetryActionType.Merge,
          currentBranch,
          theirBranch: branch,
          repository: this.repository,
        },
      }
    )
  }
