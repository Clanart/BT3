This is a NULL-pointer-dereference bug class ("crash on message with a missing required field") that maps to a reachable panic in Sei's EVM `SetCodeTx` (EIP‑7702) handling, mirroring the irssi DCC-message crash pattern: code assumes a field is present and dereferences a pointer that can be `nil` when a field is legitimately absent.

### Title
Nil-pointer dereference in `SetCodeTx.AsEthereumData` via `To == ""` crashes any node executing/simulating the transaction - (File: `x/evm/types/ethtx/set_code_tx.go`)

### Summary
`SetCodeTx.GetTo()` returns `nil` when the transaction's `To` field is an empty string [1](#0-0) , but `SetCodeTx.AsEthereumData()` unconditionally dereferences that pointer with `To: *tx.GetTo()` [2](#0-1) . `SetCodeTx.Validate()` never rejects an empty `To`; it only validates `To` when non-empty (`if tx.To != "" { ValidateAddress(tx.To) }`) and otherwise returns `nil` [3](#0-2) . The identical pattern exists in the `giga/deps/xevm` copy of the same file [4](#0-3) .

### Finding Description
A `SetCodeTx` (EIP-7702) is one of the Ethereum tx types accepted end-to-end through `MsgEVMTransaction` — a message any unprivileged sender can submit via `evmtypes.UnpackTxData` and the EVM ante pipeline [5](#0-4) . `ValidateBasic()` calls `txData.Validate()` [6](#0-5) , which for `SetCodeTx` does not reject a missing/empty `To` field — it is only checked "if tx.To != """ [3](#0-2) . This means a raw protobuf-encoded `MsgEVMTransaction` whose inner `SetCodeTx.To` is the empty string passes `ValidateBasic` cleanly.

Later, whenever the transaction data is converted back to a go-ethereum transaction object via `AsEthereumData()` — which happens in `EvmCheckTxAnte`/`EvmDeliverTxAnte` (`ethtypes.NewTx(txData.AsEthereumData())`) [7](#0-6) , in `EvmStatelessChecks` [8](#0-7) , and in `PreprocessUnpacked` [9](#0-8)  — the code executes `To: *tx.GetTo()`, dereferencing a `nil` `*common.Address`. This is a Go runtime panic (nil pointer dereference), directly analogous to the irssi bug class: a message lacking an "expected" field (source nick/host in irssi; `To` in `SetCodeTx`) is dereferenced without a nil check, crashing the process handling it.

Note that `LegacyTx`, `AccessListTx`, and `DynamicFeeTx` correctly avoid this by keeping `To` as `*common.Address` (nullable) in their `AsEthereumData()` output, since contract-creation transactions are legitimately allowed to have no `To`. `SetCodeTx` (and `BlobTx`, which returns `&common.Address{}` as a workaround instead of a proper validation rejection) special-case this incorrectly — EIP-7702 forbids contract creation, so `To` must always be present, but the codebase fails to enforce that in `Validate()`, leaving a crash-reachable gap.

### Impact Explanation
Any node that processes this transaction (`CheckTx`, `DeliverTx`/execution, mempool re-validation, block replay, or JSON-RPC simulation/estimateGas paths that build `ethtypes.Transaction` from stored/submitted `SetCodeTx` data) will panic. Because `AsEthereumData()` is called deep inside ante-handling and preprocessing that run on every validator processing the transaction, an attacker submitting a single crafted `MsgEVMTransaction` carrying a `SetCodeTx` with an empty `To` can trigger a synchronized panic across all validators that receive/process the tx (mempool gossip + `CheckTx`/`DeliverTx`), which can crash or halt block production — a validator/node halt, satisfying the "crash of default-configuration node" / "validator halt" impact bar.

### Likelihood Explanation
High: this requires no privileged access, no valid signature checks beyond what a normal EIP-7702 transaction otherwise needs, and no special network position — an attacker just needs to submit an `EVMTransaction` (or gossip it as a mempool tx) whose inner protobuf `ethtx.SetCodeTx.To` field is left as the empty string / zero value. Since `Validate()` treats empty `To` as valid (skips validation), and since Go's protobuf unmarshaling naturally leaves an unset `string` field as `""`, an attacker can trivially construct such a message without needing a valid signature dereference to succeed first — the panic in `AsEthereumData()` happens during ante-handling (`EvmStatelessChecks`/`EvmCheckTxAnte`), which runs before/around signature verification depending on order of checks, and definitely happens in `PreprocessUnpacked`.

### Recommendation
Enforce that `SetCodeTx.To` (and equivalently `BlobTx.To`) is a valid, non-empty address in `Validate()` (per EIP-7702/EIP-4844 semantics, which forbid contract creation for these tx types), rejecting the message with an error instead of allowing it to reach `AsEthereumData()`. Additionally, harden `AsEthereumData()` itself to check `GetTo() == nil` and return an error/skip rather than blindly dereferencing, mirroring the safe nullable-pointer pattern used by `LegacyTx`/`AccessListTx`/`DynamicFeeTx`. Apply the same fix in both `x/evm/types/ethtx/set_code_tx.go` and `giga/deps/xevm/types/ethtx/set_code_tx.go` (and audit `blob_tx.go` similarly, since it silently substitutes `&common.Address{}` instead of validating).

### Proof of Concept
1. Construct a Go-ethereum `SetCodeTx`-typed transaction data through the `ethtx.SetCodeTx` protobuf message directly (bypassing `NewSetCodeTx`, which is only used when converting from a real signed `ethtypes.Transaction`), setting all required fields (`GasTipCap`, `GasFeeCap`, valid `V/R/S` signature bytes, valid `ChainID`) but leaving `To` as the empty string (i.e., omit the field entirely in the protobuf encoding).
2. Pack it via `PackTxData`/`codectypes.NewAnyWithValue` into a `MsgEVMTransaction.Data` field and submit as a normal Cosmos SDK transaction to a node's RPC (`broadcast_tx_sync`) or the EVM JSON-RPC pathway that constructs such a message.
3. `ValidateBasic()` succeeds because `SetCodeTx.Validate()` does not reject empty `To`.
4. When the ante pipeline calls `AsEthereumData()` (through `EvmStatelessChecks` in `app/ante/evm_checktx.go` or `PreprocessUnpacked` in `x/evm/ante/preprocess.go`), `*tx.GetTo()` dereferences `nil`, causing a Go runtime panic in the transaction-processing goroutine.

		ltx := ethtx.LegacyTx{}

			// value is a legacy tx
			return &ltx, nil

			// value is a accesslist tx
			return &atx, nil

			// value is a dynamic fee tx
