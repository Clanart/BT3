### Title
Unbounded Recursive RLP Decoding of Nested `AccountKeyRoleBased` Leads to Unrecoverable Goroutine Stack Overflow (Node Crash) - ([File: blockchain/types/accountkey/account_key_role_based.go])

### Summary
`AccountKeyRoleBased.DecodeRLP` recursively invokes `AccountKeySerializer.DecodeRLP`, which in turn calls `NewAccountKey` and `s.Decode(serializer.key)`. If the decoded key type is again `AccountKeyTypeRoleBased`, this chain recurses into `AccountKeyRoleBased.DecodeRLP` again, with no depth limit or cycle/nesting check performed *during decoding*. The only protections against nested composite keys (`IsCompositeType` checks in `CheckInstallable`/`CheckUpdatable`, and `isNested` in `checkAccountKeyZeroValues`) are applied *after* the full structure has already been decoded — too late to prevent the recursive decode itself from exhausting the goroutine stack.

### Finding Description
- `AccountKeySerializer.DecodeRLP` decodes a key type tag, constructs the key via `NewAccountKey`, then decodes the key body with `s.Decode(serializer.key)`, with no depth tracking: [1](#0-0) 

- `AccountKeyRoleBased.DecodeRLP` decodes each role slot as a nested `AccountKeySerializer`, again with no depth limiting, allowing arbitrary self-nesting of `AccountKeyRoleBased` inside itself: [2](#0-1) 

- The only defenses against nested/composite account keys are enforced *after* decoding completes, at validation time (`IsCompositeType`/`CheckInstallable`/`CheckUpdatable`), not during the RLP decode itself: [3](#0-2) [4](#0-3) 

- Two concrete reachable entry points for an unprivileged caller:
  1. `KaiaAPI.DecodeAccountKey`, a public JSON-RPC method that directly RLP-decodes attacker-controlled bytes into an `AccountKeySerializer` with **no prior validation at all**: [5](#0-4) 
  2. A `TxTypeAccountUpdate` transaction submitted to the mempool, whose account key field is decoded via the same `AccountKeySerializer`/`AccountKeyRoleBased` machinery before any composite-type validation occurs, since tx pool/consensus code must first fully RLP-decode the transaction (including the account key) before it can call `CheckInstallable`/`CheckUpdatable`.

Because Go's `rlp` decoder here recurses via native Go function calls for each nesting level (`DecodeRLP` → `NewAccountKeySerializer`/`rlp.DecodeBytes` → `AccountKeyRoleBased.DecodeRLP` → …), a payload with many thousands of levels of self-nested `AccountKeyRoleBased` can exhaust the goroutine's stack.

### Impact Explanation
Unlike Java's `StackOverflowError` (which the docx4j report describes and which is normally catchable and can be isolated per-thread), a Go goroutine stack overflow (`runtime: goroutine stack exceeds ... - fatal error: stack overflow`) is **not recoverable** with `recover()` — it is a fatal runtime error that terminates the *entire process*. This means a single crafted RLP-encoded `AccountKeyRoleBased` blob, submitted either as a raw RPC parameter (`kaia_decodeAccountKey`) or embedded in a `TxTypeAccountUpdate` transaction, can crash the entire node process, not merely one request or one worker. This is more severe than the referenced docx4j analog and directly threatens availability of public RPC endpoints and network transaction propagation/processing paths.

### Likelihood Explanation
The RLP overhead per nesting level is small (a short list wrapping a byte-string element), so a payload of only a few megabytes could encode enough recursive depth to exhaust a goroutine's stack. No signature, authorization, or special privilege is required to call the public `kaia_decodeAccountKey` RPC method, and any unprivileged sender can submit a `TxTypeAccountUpdate` transaction carrying the malicious account key bytes to be relayed and decoded by full nodes. The attack requires no state manipulation and passes ordinary RLP structural well-formedness checks.

### Recommendation
Introduce and enforce a maximum recursion/nesting depth for `AccountKeySerializer`/`AccountKeyRoleBased` decoding (both `DecodeRLP` and `UnmarshalJSON` paths), rejecting the decode as soon as the depth limit (e.g., 1, since nested `RoleBased` keys are never valid) is exceeded — rather than only checking `IsCompositeType`/`isNested` after the entire structure has been fully decoded. This should be applied uniformly to the public API decode path (`KaiaAPI.DecodeAccountKey`) and the transaction/account-key decoding path used for `TxTypeAccountUpdate`.

### Proof of Concept
Conceptual PoC (cannot be executed in this environment, but the code path is directly traceable):
1. Construct account key bytes `K0` representing a normal `AccountKeyPublic`.
2. Wrap `K0` as `AccountKeyRoleBased` with RLP: `enc = [rlp(AccountKeySerializer{keyType: RoleBased, key: K0})]`.
3. Repeat wrapping N times (e.g., N = 500,000), each time producing `Kn = AccountKeySerializer{keyType: RoleBased, key: Kn-1}`.
4. Submit the final RLP bytes to the public `kaia_decodeAccountKey` JSON-RPC method (`api/api_kaia.go:167`), or embed it as the `AccountKey` field of a `TxTypeAccountUpdate` transaction and broadcast it.
5. `AccountKeyRoleBased.DecodeRLP` recurses N times through `AccountKeySerializer.DecodeRLP` → `NewAccountKey` → `s.Decode` → back into `AccountKeyRoleBased.DecodeRLP`, exhausting the goroutine stack and crashing the node process with a fatal, unrecoverable `stack overflow` error.

func (a *AccountKeyRoleBased) DecodeRLP(s *rlp.Stream) error {
	enc := [][]byte{}
	if err := s.Decode(&enc); err != nil {
		return err
	}

	keys := make([]AccountKey, len(enc))
	for i, b := range enc {
		serializer := NewAccountKeySerializer()
		if err := rlp.DecodeBytes(b, &serializer); err != nil {
			return err
		}
		keys[i] = serializer.key
	}

	*a = (AccountKeyRoleBased)(keys)

	return nil
}

func (a *AccountKeyRoleBased) CheckInstallable(currentBlockNumber uint64) error {
	// A zero-role key is not allowed.
	if len(*a) == 0 {
		return kerrors.ErrZeroLength
	}
	// Do not allow undefined roles.
	if len(*a) > (int)(RoleLast) {
		return kerrors.ErrLengthTooLong
	}
	for i := 0; i < len(*a); i++ {
		// A composite key is not allowed.
		if (*a)[i].IsCompositeType() {
			return kerrors.ErrNestedCompositeType
		}
		// If any key in the role cannot be initialized, return an error.
		if err := (*a)[i].CheckInstallable(currentBlockNumber); err != nil {
			return err
		}
	}
	return nil
}

func checkAccountKeyZeroValues(key accountkey.AccountKey, isNested bool) error {

				return errors.New("invalid weight of the multiSigKey")
			}
		}

		if isNested {
			return errors.New("roleBasedKey cannot contains a roleBasedKey as a role key")

		for _, roleKey := range *roleBasedKey {
			if err := checkAccountKeyZeroValues(roleKey, true); err != nil {
				return err
