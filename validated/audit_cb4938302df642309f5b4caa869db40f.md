### Title
App Proxy signed requests never expire, permitting indefinite replay of captured proxy URLs - ([File: lib/shopify_app/controller_concerns/app_proxy_verification.rb])

### Summary
`ShopifyApp::AppProxyVerification#query_string_valid?` validates only that the HMAC `signature` query parameter matches the other query parameters (which include a `timestamp` field), but it never checks that the `timestamp` is recent. Consequently, a signed app-proxy request captured at any point in time (e.g. from server access logs, browser history, a shared link, or a caching proxy) remains a valid, accepted forged request indefinitely, because the signature never expires.

### Finding Description
`query_string_valid?` recomputes the HMAC over all query parameters except `signature` and compares it to the supplied `signature`: [1](#0-0) 

The `timestamp` parameter is treated as just another signed field used in signature computation — it is never compared to the current server time to reject stale requests. This is confirmed by the test suite, where a signature computed against a fixed historical `timestamp=1466106083` (year 2016) is asserted to be valid at any later point in time the test suite runs: [2](#0-1) 

This mirrors the root-cause pattern in the referenced report: a time-boundary field (`cashbackClaim.startTime` there, `timestamp` here) exists in the data model/signed payload but is never validated against the current time, so requests/claims that should only be valid within an intended window remain valid indefinitely (retroactively or perpetually).

The same absence of freshness validation exists in `ShopifyApp::PayloadVerification#hmac_valid?` (shared by `WebhookVerification` and `ExtensionVerificationController`), which only performs a constant-time comparison of the HMAC digest with no timestamp/nonce freshness check at all: [3](#0-2) 

### Impact Explanation
App-proxy requests are GET requests forwarded by Shopify to the app, with the signed query string appended to the URL. Such URLs are commonly exposed in server access logs, browser history, Referer headers, CDN/proxy caches, and can be shared or leaked. Because `AppProxyVerification` never validates request freshness, any party who obtains a previously valid signed proxy URL (through logs, history, or interception, without needing the app secret) can replay it as an authenticated app-proxy request at any future time, resulting in an accepted forged request. Depending on what the app-proxy endpoint does (e.g. mutate shop data, issue rewards, perform actions on behalf of the shop/customer), this can lead to unauthorized state changes being accepted long after the original request's intended validity window — the "accepted forged signed request" category called out in the validation rules.

### Likelihood Explanation
Exploitation requires an attacker to have observed or obtained a legitimately-signed app-proxy query string once (a realistic scenario given browser history, logs, or referrer leakage), after which replay costs nothing (no secret knowledge needed) and works indefinitely since there is no expiry enforcement.

### Recommendation
In `query_string_valid?`, after validating the signature, additionally parse and validate the `timestamp` query parameter against `Time.now`, rejecting requests whose timestamp is older than a small tolerance window (e.g. a few minutes), similar to how Shopify recommends validating webhook/app-proxy timestamps to prevent replay attacks.

### Proof of Concept
1. Capture (or otherwise obtain, e.g. via server logs) a legitimately Shopify-signed app-proxy request URL, such as:
   `GET /app_proxy/basic?shop=some-store.myshopify.com&path_prefix=%2Fapps%2Fmy-app&timestamp=1466106083&signature=<valid-hmac>`
2. Wait an arbitrary amount of time (days, months, years) after the original request.
3. Replay the exact same URL to the app.
4. `query_string_valid?` recomputes the same HMAC over the same query params and returns `true` because `timestamp` is never checked against the current time, as demonstrated by the passing test `"request with a valid signature should pass"` using a fixed historical timestamp: [2](#0-1) . The request is processed as if it were fresh.

    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end

    def shopify_hmac
      request.headers["HTTP_X_SHOPIFY_HMAC_SHA256"]
    end

    def hmac_valid?(data)
      secrets = [ShopifyApp.configuration.secret, ShopifyApp.configuration.old_secret].reject(&:blank?)

      secrets.any? do |secret|
        digest = OpenSSL::Digest.new("sha256")
        ActiveSupport::SecurityUtils.secure_compare(
          shopify_hmac,
          Base64.strict_encode64(OpenSSL::HMAC.digest(digest, secret, data)),
        )
      end
    end
