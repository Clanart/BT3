### Cached preprocesses are reused across potentially different participant sets - (File: `coordinator/src/tributary/signing_protocol.rs`)

### Summary

`SigningProtocol::preprocess_internal` caches a deterministic FROST preprocess seed solely under `self.context`, then derives the signing machine using the participant set passed to the current call. If the same context is invoked with different `participants`, the same nonce material is reused for signing under different Lagrange coefficients/messages, enabling recovery of the validator's private key share from two public signature shares.

### Finding Description

`preprocess_internal` builds `ThresholdKeys` from the caller-provided `participants`, but stores and retrieves `CachedPreprocesses` only by `self.context`. [1](#0-0)  The cached seed deterministically regenerates the same FROST nonces and commitments via `ChaCha20Rng::from_seed`, `Commitments::new`, and `AlgorithmSignMachine::from_cache`. [2](#0-1) 

During signing, each included participant set produces a different `ThresholdView`; for Lagrange interpolation, the participant's effective secret share is multiplied by the participant set's interpolation factor. [3](#0-2)  The signature share then commits to the reused bound nonce and the differently interpolated secret share. [4](#0-3) 

### Impact Explanation

An attacker who can cause the same signing context to be used with two different participant lists obtains two public shares using the same nonce:

```text
s1 = r + c1 * λ1 * x
s2 = r + c2 * λ2 * x
```

Because `λ1`, `λ2`, `c1`, and `c2` are public, the attacker can solve for the validator's private share `x` and nonce `r`. This converts nonce reuse into key-share recovery, not merely signature malleability.

### Likelihood Explanation

The vulnerable path is reachable whenever an external protocol caller can influence or vary the participant list while reusing the same `context` cache key. The code explicitly accepts `participants` separately from the cached context and does not include the participant list in the cache key. [5](#0-4)  The preprocess is then loaded unconditionally if one already exists for the context. [6](#0-5) 

### Recommendation

Bind the cache entry to the complete signing configuration, not only `context`. At minimum, include the canonical ordered participant list—and preferably the algorithm/key identity—in `CachedPreprocesses` lookup. A cached preprocess must never be restored with `ThresholdKeys` corresponding to a different participant set. Alternatively, remove reuse entirely and generate a fresh preprocess for each signing session.

### Proof of Concept

1. Initialize a validator's `SigningProtocol` with context `C`.
2. Call `preprocess_internal` with participant list `P1`; this stores seed `K` under `C`.
3. Call `share_internal` for `C` using participant set `P1` and message `m1`, producing share `s1`.
4. Call `share_internal` again for `C`, but with a different valid participant set `P2`, and message `m2`, producing share `s2`.
5. `from_cache` regenerates the same nonce `r` from `K`, while `view(P1)` and `view(P2)` apply different Lagrange factors.
6. Solve the two share equations for `x`, recovering the validator's private threshold share. [2](#0-1)

  fn preprocess_internal(
    &mut self,
    participants: &[<Ristretto as Ciphersuite>::G],
  ) -> (AlgorithmSignMachine<Ristretto, Schnorrkel>, [u8; 64]) {
    // Encrypt the cached preprocess as recovery of it will enable recovering the private key
    // While the DB isn't expected to be arbitrarily readable, it isn't a proper secret store and
    // shouldn't be trusted as one
    let mut encryption_key = {
      let mut encryption_key_preimage =
        Zeroizing::new(b"Cached Preprocess Encryption Key".to_vec());
      encryption_key_preimage.extend(self.context.encode());
      let repr = Zeroizing::new(self.key.to_repr());
      encryption_key_preimage.extend(repr.deref());
      Blake2s256::digest(&encryption_key_preimage)
    };
    let encryption_key_slice: &mut [u8] = encryption_key.as_mut();

    let algorithm = Schnorrkel::new(b"substrate");
    let keys: ThresholdKeys<Ristretto> =
      musig(musig_context(self.spec.set().into()), self.key.clone(), participants)
        .expect("signing for a set we aren't in/validator present multiple times")
        .into();

    if CachedPreprocesses::get(self.txn, &self.context).is_none() {
      let (machine, _) =
        AlgorithmMachine::new(algorithm.clone(), keys.clone()).preprocess(&mut OsRng);

      let mut cache = machine.cache();
      assert_eq!(cache.0.len(), 32);
      #[allow(clippy::needless_range_loop)]
      for b in 0 .. 32 {
        cache.0[b] ^= encryption_key_slice[b];
      }

      CachedPreprocesses::set(self.txn, &self.context, &cache.0);
    }

    let cached = CachedPreprocesses::get(self.txn, &self.context).unwrap();
    let mut cached: Zeroizing<[u8; 32]> = Zeroizing::new(cached);
    #[allow(clippy::needless_range_loop)]
    for b in 0 .. 32 {
      cached[b] ^= encryption_key_slice[b];
    }
    encryption_key_slice.zeroize();
    let (machine, preprocess) =
      AlgorithmSignMachine::from_cache(algorithm, keys, CachedPreprocess(cached));

  fn seeded_preprocess(
    self,
    seed: CachedPreprocess,
  ) -> (AlgorithmSignMachine<C, A>, Preprocess<C, A::Addendum>) {
    let mut params = self.params;

    let mut rng = ChaCha20Rng::from_seed(*seed.0);
    let (nonces, commitments) = Commitments::new::<_>(
      &mut rng,
      params.keys.original_secret_share(),
      &params.algorithm.nonces(),
    );
    let addendum = params.algorithm.preprocess_addendum(&mut rng, &params.keys);

    let preprocess = Preprocess { commitments, addendum };

    // Also obtain entropy to randomly sort the included participants if we need to identify blame
    let mut blame_entropy = [0; 32];
    rng.fill_bytes(&mut blame_entropy);
    (
      AlgorithmSignMachine { params, seed, nonces, preprocess: preprocess.clone(), blame_entropy },
      preprocess,
    )
  }
