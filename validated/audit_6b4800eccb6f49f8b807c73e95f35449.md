## Title
`PoolWallet.join_pool` / `self_pool` change `target_puzzle_hash` before pending p2-singleton rewards are absorbed, redirecting previously-earned pool rewards to the new recipient - (File: `chia/pools/pool_wallet.py`)

### Summary
`PoolWallet.join_pool()` and `PoolWallet.self_pool()` immediately travel the pool singleton to a new `target_state` (new pool / new payout puzzle hash) without first requiring that any outstanding, already-farmed `p2_singleton` reward coins be absorbed to the *current* (about-to-be-replaced) `target_puzzle_hash`. When `claim_pool_rewards()` is later called, it pays out the entire absorbed amount to whatever `target_puzzle_hash` is *current at the time of the claim*, not the pool that was active when each reward coin was actually farmed. This is the same bug class as the reported `SdtFeeCollector.setUpFeesRepartition` issue: a "change recipient" operation runs before pending funds tied to the old recipient are swept out, so the wrong party ends up receiving them.

### Finding Description
`PoolState.target_puzzle_hash` is the destination address that all currently-unclaimed p2-singleton coinbase rewards will be paid to when absorbed [1](#0-0) . `PoolWallet.join_pool()` sets `self.target_state` and immediately calls `generate_travel_transactions()`, which spends the singleton and moves it to a new pool state on-chain [2](#0-1) . There is no check for, or forced absorption of, any outstanding `p2_singleton` reward coins that were farmed while the *old* target/pool was active before this transition is submitted.

Later, `PoolWallet.claim_pool_rewards()` gathers *all* unspent p2-singleton reward coins regardless of which pool state was active when they were farmed, and pays the summed `total_amount` to `current_state.current.target_puzzle_hash` — i.e. whatever the pool state is *at claim time*, not at farm time: [3](#0-2) [4](#0-3) 

Because `join_pool`/`self_pool` never force a claim of pre-existing rewards before switching `target_puzzle_hash` [2](#0-1) [5](#0-4) , any p2-singleton reward coins farmed under Pool A that remain unabsorbed when the owner switches to Pool B (or self-pools) will, on the next `pw_absorb_rewards` call, be paid entirely to Pool B's (or the owner's new) `target_puzzle_hash` instead of Pool A's. This mirrors the reported Convergence bug exactly: `setUpFeesRepartition` changes the recipient mapping before sweeping pending funds to the prior recipients, so the prior recipients lose their rightful share.

### Impact Explanation
Pool A (the prior recipient) never receives rewards that its plots legitimately earned while the singleton was farming to it; those funds are redirected to whoever the wallet owner sets as the new `target_puzzle_hash`. This is a reward-redirection bug causing loss of funds to the previously-entitled recipient (the pool operator/service that served the farmer during that period), and it is triggerable purely by the plot-NFT owner performing a normal, unprivileged `pw_join_pool`/`pw_self_pool` RPC call followed by `pw_absorb_rewards` — no malicious peer or privileged access required.

### Likelihood Explanation
This requires no adversarial network conditions: it happens whenever a farmer switches pools (or exits to self-pooling) while unclaimed `p2_singleton` reward coins exist from the previous pool assignment — a routine, expected pattern in normal wallet usage (e.g., a user pools with A, earns rewards, then decides to move to B before absorbing). The RPC/CLI flow (`pw_join_pool`, `pw_self_pool`, `pw_absorb_rewards`) provides no guard rail or automatic pre-absorb step, so the misdirection can occur unintentionally in ordinary operation, not just via a crafted attack.

### Recommendation
Before submitting the travel transaction in `join_pool()`/`self_pool()`, check for and, if found, require absorbing all outstanding `p2_singleton` reward coins tied to the *current* `target_puzzle_hash`/pool state (or reject the join/self-pool request until they are claimed), analogous to the audit's recommendation to call `withdrawSdt` before changing recipients. Alternatively, `claim_pool_rewards()` should track and pay out rewards according to the pool state that was active at each reward coin's farmed height rather than the state active at claim time.

### Proof of Concept
1. Farmer creates a Plot NFT and joins Pool A (`pw_join_pool` with `target_puzzle_hash = pool_A_ph`); plots begin farming to Pool A's p2-singleton address.
2. Several blocks are farmed, producing unspent `p2_singleton` reward coins destined (by pool contract convention) for Pool A.
3. Before calling `pw_absorb_rewards`, the farmer calls `pw_join_pool` again with `target_puzzle_hash = pool_B_ph` (switch to Pool B) — per `join_pool()` at [2](#0-1) , this immediately submits the travel transaction with no check for unclaimed p2-singleton rewards.
4. Once the travel transaction confirms, `current_state.current.target_puzzle_hash` is now `pool_B_ph`.
5. Farmer (or anyone permitted) calls `pw_absorb_rewards` → `claim_pool_rewards()` sweeps all the still-unspent reward coins (originally earned while assigned to Pool A) and pays the full `total_amount` to `current_state.current.target_puzzle_hash`, which is now Pool B's address [4](#0-3) .
6. Result: rewards earned under Pool A are paid entirely to Pool B, matching the reported bug's impact where previous recipients receive an incorrect (zero) share of funds owed to them.

    async def join_pool(self, target_state: PoolState, fee: uint64, action_scope: WalletActionScope) -> uint64:
        if target_state.state != FARMING_TO_POOL.value:
            raise ValueError(f"join_pool must be called with target_state={FARMING_TO_POOL} (FARMING_TO_POOL)")
        if self.target_state is not None:
            raise ValueError(f"Cannot join a pool while waiting for target state: {self.target_state}")
        if await self.have_unconfirmed_transaction():
            raise ValueError(
                "Cannot join pool due to unconfirmed transaction. If this is stuck, delete the unconfirmed transaction."
            )

        current_state: PoolWalletInfo = await self.get_current_state()

        total_fee = fee
        if current_state.current == target_state:
            self.target_state = None
            msg = f"Asked to change to current state. Target = {target_state}"
            self.log.info(msg)
            raise ValueError(msg)
        elif current_state.current.state in {SELF_POOLING.value, LEAVING_POOL.value}:
            total_fee = fee
        elif current_state.current.state == FARMING_TO_POOL.value:
            total_fee = uint64(fee * 2)

        if self.target_state is not None:
            raise ValueError(
                f"Cannot change to state {target_state} when already having target state: {self.target_state}"
            )
        PoolWallet._verify_initial_target_state(target_state)
        if current_state.current.state == LEAVING_POOL.value:
            history: list[tuple[uint32, CoinSpend]] = await self.get_spend_history()
            last_height: uint32 = history[-1][0]
            if (
                await self.wallet_state_manager.blockchain.get_finished_sync_up_to()
                <= last_height + current_state.current.relative_lock_height
            ):
                raise ValueError(
                    f"Cannot join a pool until height {last_height + current_state.current.relative_lock_height}"
                )

        self.target_state = target_state
        self.next_transaction_fee = fee
        self.next_tx_config = action_scope.config.tx_config
        await self.generate_travel_transactions(fee, action_scope)
        return total_fee

    async def self_pool(self, fee: uint64, action_scope: WalletActionScope) -> uint64:
        if await self.have_unconfirmed_transaction():
            raise ValueError(
                "Cannot self pool due to unconfirmed transaction. If this is stuck, delete the unconfirmed transaction."
            )
        pool_wallet_info: PoolWalletInfo = await self.get_current_state()
        if pool_wallet_info.current.state == SELF_POOLING.value:
            raise ValueError("Attempted to self pool when already self pooling")

        if self.target_state is not None:
            raise ValueError(f"Cannot self pool when already having target state: {self.target_state}")

        # Note the implications of getting owner_puzzlehash from our local wallet right now
        # vs. having pre-arranged the target self-pooling address
        owner_puzzlehash = await action_scope.get_puzzle_hash(self.wallet_state_manager)
        owner_pubkey = pool_wallet_info.current.owner_pubkey
        current_state: PoolWalletInfo = await self.get_current_state()
        total_fee = uint64(fee * 2)

        if current_state.current.state == LEAVING_POOL.value:
            total_fee = fee
            history: list[tuple[uint32, CoinSpend]] = await self.get_spend_history()
            last_height: uint32 = history[-1][0]
            if (
                await self.wallet_state_manager.blockchain.get_finished_sync_up_to()
                <= last_height + current_state.current.relative_lock_height
            ):
                raise ValueError(
                    f"Cannot self pool until height {last_height + current_state.current.relative_lock_height}"
                )
        self.target_state = create_pool_state(
            SELF_POOLING, owner_puzzlehash, owner_pubkey, pool_url=None, relative_lock_height=uint32(0)
        )
        self.next_transaction_fee = fee
        self.next_tx_config = action_scope.config.tx_config
        await self.generate_travel_transactions(fee, action_scope)
        return total_fee
