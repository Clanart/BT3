## Title
Unbounded `CREATE_COIN` Memo Size Enables Persistent Wallet-Side DoS via Oversized On-Chain Memo Blobs - (File: `chia/wallet/util/compute_memos.py`)

### Summary
Chia's `CREATE_COIN` condition allows an arbitrarily large `memos` list with no server-side (wallet or mempool) length/size validation beyond generic CLVM execution cost accounting. A spender can craft a single coin creation with an oversized memo payload that gets permanently embedded in the puzzle solution reveal on-chain. Any wallet that later becomes aware of this coin (e.g., the recipient wallet, an offer counterparty, or anyone syncing this puzzle hash) is forced to repeatedly parse, store, and re-serialize this oversized memo blob every time transaction history is synced or queried, degrading or effectively DoS-ing wallet operations for that coin/transaction indefinitely — closely mirroring the MantisBT bug class where unbounded user-supplied content permanently corrupts a persistent record and breaks future rendering/processing.

### Finding Description
`CreateCoin` conditions carry an optional `memos: list[bytes] | None` field with no size cap enforced anywhere in its construction or parsing: [1](#0-0) [2](#0-1) 

The wallet's memo-computation pipeline (used on every synced coin/spend, in production wallet paths, not just tests) extracts and copies whatever bytes are present in the CREATE_COIN condition's memo argument without any length bound: [3](#0-2) 

These memos are then persisted directly into the wallet's `TransactionRecord`/`TransactionRecordOld` and written to the wallet SQLite database as a raw streamable blob, with no size validation at write time: [4](#0-3) [5](#0-4) 

Finally, every call to `get_transactions`/`get_transaction` (or any RPC surface that serializes `TransactionRecord`) re-serializes this same oversized memo blob to JSON for the caller, unconditionally: [6](#0-5) 

Unlike announcement conditions (`CREATE_COIN_ANNOUNCEMENT`/`CREATE_PUZZLE_ANNOUNCEMENT`/`ASSERT_*`), which are explicitly rate/size-limited via `TOO_MANY_ANNOUNCEMENTS` and per-spend caps, no equivalent cap exists for `CREATE_COIN` memo payload size — the only throttle is the generic CLVM execution/byte cost, which is large enough (`max_tx_clvm_cost = MAX_BLOCK_COST_CLVM // 2`) to admit multi-megabyte memo blobs in a single paid transaction. Once confirmed on-chain, this data is permanent and must be re-processed by every wallet that ever encounters the coin.

### Impact Explanation
A single, fee-paying, otherwise fully valid spend bundle can pin an oversized memo blob (effectively bounded only by fee/cost budget, not by any explicit sanity limit) permanently into the puzzle solution of a confirmed coin. Every wallet that receives, or is a counterparty to, a transaction referencing that coin (standard sends, CAT sends, offers, notifications) will:
- repeatedly parse the oversized memo on every resync/`compute_memos` call,
- store it verbatim in its local SQLite `transaction_record` table forever,
- re-serialize it on every `get_transactions`/`get_transaction` RPC call.

This causes disproportionate CPU/memory/I/O consumption on the recipient side and can degrade or freeze the wallet's transaction-history views/RPC responses for that wallet from then on — a spend-triggered, persistent processing burden closely analogous to the MantisBT "excessive note length" DoS, where a single unbounded field write corrupts/overloads all future reads of that record.

### Likelihood Explanation
This is trivially reachable by any unprivileged wallet user or spend-bundle submitter: crafting a `CREATE_COIN` condition with a very large `memos` list requires no special privileges, only paying the corresponding CLVM cost/fee. No mempool, consensus, or wallet-side validation currently rejects or truncates oversized memo content before it is admitted, confirmed, and subsequently processed and stored by counterparties' wallets.

### Recommendation
- Introduce an explicit maximum total byte size (and/or count) for `CREATE_COIN` memos, enforced consistently in wallet condition construction (`chia/wallet/conditions.py`) and ideally at consensus/mempool admission, similar to the existing `TOO_MANY_ANNOUNCEMENTS` cap for announcement conditions.
- Cap the amount of memo data stored per `TransactionRecord` in `chia/wallet/wallet_transaction_store.py`/`wallet_state_manager.py`, truncating or flagging oversized memos rather than persisting them verbatim.
- Bound the memo payload returned by RPC endpoints (`get_transactions`, `get_transaction`, `get_transaction_memo`) to avoid repeated expensive serialization of arbitrarily large blobs.

### Proof of Concept
1. Construct a `CoinSpend` whose solution contains a `CREATE_COIN` condition of the form `(51 <puzzle_hash> <amount> (<memo_1> <memo_2> ... ))` where the memo list totals many megabytes of arbitrary bytes (fee sized appropriately to cover the CLVM byte/execution cost, well within `max_tx_clvm_cost`).
2. Submit and confirm the transaction; there is no size validation rejecting it (see `chia/wallet/conditions.py` `CreateCoin`/`from_program`, and mempool's absence of an equivalent to `TOO_MANY_ANNOUNCEMENTS` for `CREATE_COIN` memos).
3. Have a second wallet (recipient or any wallet tracking the destination puzzle hash) sync this coin: `compute_memos_for_spend`/`compute_memos` (`chia/wallet/util/compute_memos.py`) will extract and persist the full oversized memo list via `WalletTransactionStore.add_transaction_record` (`chia/wallet/wallet_transaction_store.py`).
4. Any subsequent call to `get_transactions`/`get_transaction` on that wallet (`chia/wallet/wallet_rpc_api.py`) re-serializes the full oversized memo blob, demonstrating the repeated, persistent processing burden triggered by the single original spend.

@streamable
@dataclass(frozen=True)
class CreateCoin(Condition):
    puzzle_hash: bytes32
    amount: uint64
    memos: list[bytes] | None = None
    memo_blob: Program | None = None

    def __post_init__(self) -> None:
        if self.memos is not None and self.memo_blob is not None:
            raise ValueError("Cannot have both memos and memo_blob")
        return super().__post_init__()

    def to_program(self) -> Program:
        condition_args = [ConditionOpcode.CREATE_COIN, self.puzzle_hash, self.amount]
        if self.memos is not None:
            condition_args.append(self.memos)
        elif self.memo_blob is not None:
            condition_args.append(self.memo_blob)
        condition: Program = Program.to(condition_args)
        return condition

        try:
            return cls(
                bytes32(program.at("rf").as_atom()),
                uint64(program.at("rrf").as_int()),

                    if potential_memos == Program.NIL
                    else [memo.as_atom() for memo in potential_memos.at("f").as_iter()]

                uint64(program.at("rrf").as_int()),
                memo_blob=potential_memos.at("f"),
            )

def compute_memos_for_spend(coin_spend: CoinSpend) -> dict[bytes32, list[bytes]]:
    _, result = run_with_cost(coin_spend.puzzle_reveal, INFINITE_COST, coin_spend.solution)
    memos: dict[bytes32, list[bytes]] = {}
    for condition in result.as_python():
        if condition[0] == ConditionOpcode.CREATE_COIN and len(condition) >= 4:
            # If only 3 elements (opcode + 2 args), there is no memo, this is ph, amount
            coin_added = Coin(coin_spend.coin.name(), bytes32(condition[1]), uint64(int_from_bytes(condition[2])))
            if type(condition[3]) is not list:
                # If it's not a list, it's not the correct format
                continue
            memos[coin_added.name()] = [mem for mem in condition[3] if isinstance(mem, bytes)]
    return memos


def compute_memos(bundle: WalletSpendBundle) -> dict[bytes32, list[bytes]]:
    """
    Retrieves the memos for additions in this spend_bundle, which are formatted as a list in the 3rd parameter of
    CREATE_COIN. If there are no memos, the addition coin_id is not included. If they are not formatted as a list
    of bytes, they are not included. This is expensive to call, it should not be used in full node code.
    """
    memos: dict[bytes32, list[bytes]] = {}
    for coin_spend in bundle.coin_spends:
        spend_memos = compute_memos_for_spend(coin_spend)
        for coin_name, coin_memos in spend_memos.items():
            existing_memos = memos.get(coin_name)
            if existing_memos is None:
                memos[coin_name] = coin_memos
            else:
                memos[coin_name] = existing_memos + coin_memos
    return memos

    async def get_transactions(self, request: GetTransactions) -> GetTransactionsResponse:
        to_puzzle_hash: bytes32 | None = None
        if request.to_address is not None:
            to_puzzle_hash = decode_puzzle_hash(request.to_address)

        transactions = await self.service.wallet_state_manager.tx_store.get_transactions_between(
            wallet_id=request.wallet_id,
            start=uint32(0) if request.start is None else request.start,
            end=uint32(50) if request.end is None else request.end,
            sort_key=request.sort_key,
            reverse=request.reverse,
            to_puzzle_hash=to_puzzle_hash,
            type_filter=request.type_filter,
            confirmed=request.confirmed,
        )
        tx_list = []
        # Format for clawback transactions
        for tr in transactions:
            tx = (await self._convert_tx_puzzle_hash(tr)).to_json_dict()
            tx_list.append(tx)
            if tx["type"] not in CLAWBACK_INCOMING_TRANSACTION_TYPES:
                continue
            coin: Coin = tr.additions[0]
            record: WalletCoinRecord | None = await self.service.wallet_state_manager.coin_store.get_coin_record(
                coin.name()
            )
            if record is None:
                log.error(f"Cannot find coin record for type {tx['type']} transaction {tx['name']}")
                continue
            try:
                tx["metadata"] = record.parsed_metadata().to_json_dict()
            except ValueError as e:
                log.error(f"Could not parse coin record metadata: {type(e).__name__} {e}")
                continue
            tx["metadata"]["coin_id"] = coin.name().hex()
            tx["metadata"]["spent"] = record.spent
        return GetTransactionsResponse(
            transactions=[TransactionRecordWithMetadata.from_json_dict(tx) for tx in tx_list],
            wallet_id=request.wallet_id,
        )
