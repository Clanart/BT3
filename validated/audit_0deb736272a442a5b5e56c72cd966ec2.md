## Confirmed: `Pallet::<T>::on_executed` credits ALL batch state-machine rewards to the signer of `messages[0]` only [1](#0-0) 

### Title
Single-signer extraction from `messages[0]` lets an attacker steal another state machine's consensus relayer reward via `on_executed` - (File: modules/pallets/consensus-incentives/src/impls.rs)

### Summary
`FeeHandler::on_executed` for the consensus-incentives pallet identifies **one** relayer account by decoding the signature carried in `messages[0]` only, but then iterates over **all** `StateMachineUpdated` events in the batch and pays the reward for every distinct `state_machine_id` found there to that single recovered account.

### Finding Description
The relevant logic:
```rust
let maybe_relayer_account = messages.get(0).and_then(|first_message| {
    if let Message::Consensus(consensus_msg) = &first_message.message {
        ... recover pub_key from consensus_msg.signer ...
    } else { None }
});

if let Some(relayer_account) = maybe_relayer_account {
    let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
    for event in events {
        if let IsmpEvent::StateMachineUpdated(update) = event {
            highest_per_state_machine.entry(update.state_machine_id)...
        }
    }
    for (state_machine_id, latest_height) in highest_per_state_machine {
        let _ = Self::process_message(state_machine_height, state_machine_id, relayer_account.clone().into());
    }
}
``` [2](#0-1) 

`events` here is the full set of `IsmpEvent`s produced by processing the *entire* `messages` batch handled in one call (multiple `Message::Consensus` entries can be submitted together, e.g. via `handle_unsigned`/`handle_messages`, each targeting a different state machine's consensus client and each independently producing a `StateMachineUpdated` event). The code, however, associates the whole batch's events with only the signer of `messages[0]`, without checking that each `StateMachineUpdated.state_machine_id` actually corresponds to the consensus message this signer submitted.

An attacker can:
1. Craft a valid, self-signed, minimal-cost `Message::Consensus` for a state machine `X` with `cost_per_block = 0` (or very low), placed as `messages[0]`.
2. Bundle it in the same extrinsic call together with a genuine, unrelated consensus update for state machine `Y` (a high-value/high-`cost_per_block` chain), submitted by anyone (it just needs to be included in the same `handle_unsigned`/`handle_messages` batch — it does not need to be authored by the attacker; any pending consensus update for `Y` in the mempool can be combined).
3. When `on_executed` runs, `events` contains `StateMachineUpdated{X, ...}` and `StateMachineUpdated{Y, ...}`. The attacker's account (signer of `messages[0]`) is credited for both `X`'s and `Y`'s reward, even though the attacker did not author `Y`'s consensus update.

This breaks the invariant "a state machine's reward must go to whoever produced that specific update," letting an attacker redirect another relayer's (or another, more valuable state machine's) reward to themselves by piggy-backing a cheap self-authored message.

### Impact Explanation
This directly enables unauthorized transfer of treasury funds (`T::TreasuryAccount` → attacker) intended for the legitimate relayer of state machine `Y`, plus minting of `ReputationAsset` to the attacker instead of the rightful party — a wrongful-beneficiary/stealing-funds impact matching the bounty's "wrong beneficiary or amount" and "stealing or loss of funds" categories.

### Likelihood Explanation
High. The attack only requires the ability to submit an unsigned/permissionless ISMP message batch (`handle_unsigned` or equivalent) containing multiple `Message::Consensus` entries, with the attacker's own cheap consensus message placed first in `messages`. No privileged access, no colluding relayer, and no proof-forgery is needed — the attacker's own message just needs to be first in the batch ordering, which the attacker fully controls when constructing the extrinsic.

### Recommendation
`process_message` must bind each `StateMachineUpdated` event to the specific `Message::Consensus` entry (and its recovered signer) that produced it, rather than applying one globally-extracted signer to the entire event list. Concretely, iterate over `messages`, match each `Message::Consensus` to its own `state_machine_id` (derivable from `consensus_state_id`/consensus client mapping) and recover that message's own event(s) before rewarding, or otherwise correlate messages to events 1:1 instead of assuming `messages[0]`'s signer covers the whole batch.

### Proof of Concept
1. Attacker generates a valid `Message::Consensus` for cheap/zero-cost state machine `X`, self-signed, and places it as `messages[0]`.
2. Attacker also includes (or waits to be batched with) a genuine consensus update message for high-value state machine `Y` in the same `handle_messages`/`handle_unsigned` call, as `messages[1]`.
3. `pallet-ismp` processes the batch, producing `events = [StateMachineUpdated{X, span}, StateMachineUpdated{Y, large_span}]`, and invokes:
```rust
<pallet_consensus_incentives::Pallet<Test> as FeeHandler>::on_executed(
    vec![attacker_msg_x, genuine_msg_y],
    vec![
        IsmpEvent::StateMachineUpdated(StateMachineUpdated{ state_machine_id: X, latest_height: h_x }),
        IsmpEvent::StateMachineUpdated(StateMachineUpdated{ state_machine_id: Y, latest_height: h_y }),
    ],
)
```
4. Assert: attacker's account balance increases by `reward(X) + reward(Y)`, even though it never authored `Y`'s update — confirming the wrong-beneficiary theft of `Y`'s relayer reward. [3](#0-2)

	fn process_message(
		state_machine_height: StateMachineHeight,
		state_machine_id: StateMachineId,
		relayer_account: T::AccountId,
	) -> Result<(), Error<T>> {
		if let Some(block_cost) = StateMachinesCostPerBlock::<T>::get(state_machine_id) {
			let reward = Self::calculate_reward(&state_machine_id, block_cost)?;

			if reward.is_zero() {
				return Ok(());
			}

			T::Currency::transfer(
				&T::TreasuryAccount::get().into_account_truncating(),
				&relayer_account,
				reward,
				Preservation::Expendable,
			)
			.map_err(|_| Error::<T>::RewardTransferFailed)?;

			Self::deposit_event(Event::<T>::RelayerRewarded {
				relayer: relayer_account.clone(),
				amount: reward,
				state_machine_height,
			});

			T::ReputationAsset::mint_into(&relayer_account, reward.saturated_into())
				.map_err(|_| Error::<T>::ReputationMintFailed)?;

			LastRewardedHeight::<T>::mutate(state_machine_id, |watermark| {
				*watermark = Some(watermark.unwrap_or_default().max(state_machine_height.height));
			});
		}
		Ok(())
	}

	fn on_executed(
		messages: Vec<MessageWithWeight>,
		events: Vec<IsmpEvent>,
	) -> DispatchResultWithPostInfo {
		let maybe_relayer_account = messages.get(0).and_then(|first_message| {
			if let Message::Consensus(consensus_msg) = &first_message.message {
				let data = sp_io::hashing::keccak_256(&consensus_msg.consensus_proof);
				Signature::decode(&mut &consensus_msg.signer[..])
					.ok()
					.and_then(|sig| sig.verify_and_get_sr25519_pubkey(&data, None).ok())
					.map(|pub_key| pub_key.into())
			} else {
				None::<[u8; 32]>
			}
		});

		if let Some(relayer_account) = maybe_relayer_account {
			// When a batch contains multiple `StateMachineUpdated` events for the
			// same `state_machine_id` (sequential consensus updates for the same
			// chain), `calculate_reward` reads the same persisted
			// `(latest_commitment_height, previous_commitment_height)` pair on
			// every iteration and pays the same block-span reward N times.
			// Collapse the per-state-machine event stream to the single highest
			// `latest_height` so each state machine receives one reward per
			// batch, sized by the actual span of its commitment advance.
			let mut highest_per_state_machine: BTreeMap<StateMachineId, u64> = BTreeMap::new();
			for event in events {
				if let IsmpEvent::StateMachineUpdated(update) = event {
					highest_per_state_machine
						.entry(update.state_machine_id)
						.and_modify(|h| {
							if update.latest_height > *h {
								*h = update.latest_height;
							}
						})
						.or_insert(update.latest_height);
				}
			}

			for (state_machine_id, latest_height) in highest_per_state_machine {
				let state_machine_height =
					StateMachineHeight { id: state_machine_id.clone(), height: latest_height };

				let _ = Self::process_message(
					state_machine_height,
					state_machine_id,
					relayer_account.clone().into(),
				);
			}
		}
