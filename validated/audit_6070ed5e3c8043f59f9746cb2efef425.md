### Title
App Proxy signature verification lacks a timestamp/deadline check, making valid signatures replayable indefinitely - (File: lib/shopify_app/controller_concerns/app_proxy_verification.rb)

### Summary
`ShopifyApp::AppProxyVerification#query_string_valid?` only checks that the HMAC `signature` query parameter matches the recomputed HMAC over the remaining query parameters. It never validates that the `timestamp` parameter included in that query string is recent, so a previously-observed valid, signed App Proxy request can be replayed against the app at any point in the future and will always pass verification.

### Finding Description
`query_string_valid?` extracts the `signature` parameter, recomputes the HMAC over the sorted remaining query parameters (which include `shop`, `path_prefix`, and `timestamp`), and does a constant-time comparison against the provided signature: [1](#0-0) 

`timestamp` is treated as just another signed parameter, not as a freshness/expiry check — there is no code anywhere in this file (or `verify_proxy_request`) that compares `timestamp` to `Time.now` or rejects stale requests: [2](#0-1) 

This is the same bug class as the referenced report: a signed request is accepted purely because the signature matches, with no deadline/expiry enforcement, so the exact same signed query string remains valid forever and can be resubmitted repeatedly.

### Impact Explanation
Any App Proxy controller in an app built on this gem (via `include ShopifyApp::AppProxyVerification`, e.g. the generated `AppProxyController`) inherits this weakness: [3](#0-2) 

If an attacker captures one legitimately-signed App Proxy request URL (e.g., via browser history, shared links, server/CDN access logs, a leaked Referer header, or network capture on non-HTTPS legacy setups), they can replay that exact URL/query string indefinitely. Since App Proxy endpoints commonly perform state-changing or shop/customer-context actions (submitting a review, redeeming a code, recording an action attributed to a shop), an unrelated party who obtains one signed URL gains the ability to repeat that action an unlimited number of times, with no way for the app to detect or reject the replay.

### Likelihood Explanation
Exploitation requires the attacker to obtain one previously valid signed App Proxy request (URL + signature). This is a realistic precondition for App Proxy links, which are often embedded in storefront pages and can leak through browser history, shared links, logs, or Referer headers. No credentials or privileged access are needed to perform the replay itself — the same signature works forever because there is no timestamp/deadline check in `query_string_valid?`.

### Recommendation
Add an explicit freshness check on the `timestamp` query parameter in `verify_proxy_request`/`query_string_valid?` — e.g., reject the request if `Time.now.to_i - timestamp.to_i` exceeds a small tolerance window (a few minutes) — in addition to the existing HMAC comparison in: [1](#0-0) 

### Proof of Concept
1. Observe/capture one legitimately signed App Proxy request, e.g.:
`GET /app_proxy/basic?shop=some-store.myshopify.com&path_prefix=%2Fapps%2Fmy-app&timestamp=1466106083&signature=f5cd7233558b1c50102a6f33c0b63ad1e1072a2fc126cb58d4500f75223cefcd`
(this is the exact fixture already used in the test suite, confirming the signature check has no time dependency): [4](#0-3) 
2. Replay the identical URL any time later (days, months, years after `timestamp=1466106083`).
3. `query_string_valid?` recomputes the same HMAC over the same parameters and returns `true`, so `verify_proxy_request` allows the action to proceed, because no code path checks whether `timestamp` is stale.

# frozen_string_literal: true

module ShopifyApp
  module AppProxyVerification
    extend ActiveSupport::Concern
    included do
      skip_before_action :verify_authenticity_token, raise: false
      before_action :verify_proxy_request
    end

    def verify_proxy_request
      head(:forbidden) unless query_string_valid?(request.query_string)
    end

    private

    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end

    def calculated_signature(query_hash_without_signature)
      sorted_params = query_hash_without_signature.collect { |k, v| "#{k}=#{Array(v).join(",")}" }.sort.join

      OpenSSL::HMAC.hexdigest(
        OpenSSL::Digest.new("sha256"),
        ShopifyApp.configuration.secret,
        sorted_params,
      )
    end
  end
end
