### Title
`SignableTransaction` / `TransactionSignMachine` trust the `value` inside untrusted `ReceivedOutput`s and commit to it in the BIP-341 sighash - ([File: networks/bitcoin/src/wallet/send.rs](networks/bitcoin/src/wallet/send.rs))

### Summary
The analog of "assuming a property of an external token instead of querying it" is `bitcoin-serai` assuming a property of an external UTXO (its satoshi value) instead of verifying it. `ReceivedOutput::read` deserializes a full `TxOut` — including `value` — from untrusted bytes, and `TransactionSignMachine::sign` feeds those `TxOut`s into `Prevouts::All`, so every BIP-341 key-spend sighash commits to whatever value the attacker serialized. The code checks the prevout `script_pubkey` against the offset key in `multisig`, but never checks the `value` against the actual on-chain output.

### Finding Description
`ReceivedOutput` is produced either by `Scanner::scan_transaction` (where `output` is taken verbatim from the chain) or by `ReceivedOutput::read`, which consensus-decodes an attacker-controlled `TxOut` — `offset`, `output`, and `outpoint` are all read from the byte stream with no validation that they correspond to a real UTXO [1](#0-0) .

When a `SignableTransaction` is built, the claimed prevout values drive all economic checks: `input_sat` is summed from `input.output.value`, the fee check `input_sat < payment_sat + needed_fee` uses it, and the change output value is `input_sat - payment_sat - fee_with_change` [2](#0-1) .

In `multisig`, the only integrity check on each prevout is that `p2tr_script_buf(offset.group_key()) == self.prevouts[i].script_pubkey`; `prevouts[i].value` is never compared to anything [3](#0-2) . Then `sign` computes each input's sighash with `Prevouts::All(&self.tx.prevouts)`, committing to the attacker-supplied amounts [4](#0-3) . Under BIP-341, the `Prevouts::All` commitment includes each prevout's value, so the resulting signature is only valid if the real UTXO carries exactly the claimed value.

### Impact Explanation
An attacker who controls the serialized `ReceivedOutput` bytes (e.g., a peer feeding inputs to a signer via `ReceivedOutput::read`) can inflate a prevout's `value`. The builder then believes it has more input funds than exist, produces a change output and/or implied fee that exceed the real input amount, and the FROST quorum produces a valid-looking threshold signature that commits to the false amount. The signed transaction is consensus-invalid (Taproot sighash verification fails at the input-amount binding), so the signing round is burned and the funds it was meant to move cannot be spent with the produced signature — an unintended message was signed, and a reported/spendable balance was fabricated.

### Likelihood Explanation
Any path where a signer or coordinator accepts `ReceivedOutput`s it did not itself scan from a verified block is exposed — `ReceivedOutput::read` is precisely the deserialization API for transmitting spendable inputs between parties. A single corrupted value poisons the sighash for every input (via `Prevouts::All`), so the attacker needs to alter only one byte-range of one input. Medium severity: it requires the attacker to supply the serialized input rather than the scanner-derived one, and the outcome is invalid/unspendable signatures and fabricated accounting rather than direct theft.

### Recommendation
Verify each `ReceivedOutput` against the actual UTXO set (fetch the prevout by `outpoint` and compare `value` and `script_pubkey`) before constructing the `SignableTransaction`, or at minimum extend the check in `SignableTransaction::multisig` to confirm `prevouts[i]` was obtained from `Scanner`/`scan_block` rather than deserialized. Alternatively, carry only the `outpoint` + `offset` through untrusted channels and resolve the `TxOut` locally.

### Proof of Concept
1. Attacker serializes a `ReceivedOutput` with `read`'s expected layout: a valid scalar `offset` (e.g., `Scalar::ZERO` for the base key), a `TxOut` whose `script_pubkey` is the real P2TR script but whose `value` is inflated from 100,000 sats to 1,000,000 sats, and a real `OutPoint`.
2. Victim calls `ReceivedOutput::read` on these bytes; decoding succeeds since consensus decoding does not validate the value [5](#0-4) .
3. `SignableTransaction::new` computes `input_sat = 1_000_000`, passes the `NotEnoughFunds` check for a 900,000-sat payment, and emits a ~100,000-sat change output [6](#0-5) .
4. `multisig` accepts the input because only `script_pubkey` is checked [7](#0-6) .
5. `TransactionSignMachine::sign` produces shares over a sighash committing to the 1,000,000-sat prevout [8](#0-7) ; `complete` assembles the signed transaction [9](#0-8) .
6. Broadcast fails: the real UTXO holds 100,000 sats, so every node's BIP-341 sighash recomputation disagrees with the signature — the quorum signed an unintended message and the outputs (including the fabricated change) are unspendable.

    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =

      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }
