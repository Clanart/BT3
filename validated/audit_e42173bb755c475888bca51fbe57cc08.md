## Finding [1](#0-0) 

### Title
Spoofable `WWW-Authenticate` realm header lets an attacker-controlled remote force GitHub Desktop into the GitHub Enterprise sign-in/OAuth flow, bypassing host verification - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
The bug-class in the report is "inconsistent implementations of the same contract, one of which is trusted uncritically, causing the wrong branch of security-relevant logic to run." In GitHub Desktop's git-credential-helper trampoline, `getEndpointKind()` has two ways of deciding whether a remote host is a trusted "GitHub"/"enterprise" endpoint: (1) a network-verified check via `isGitHubHost()` that actually contacts the host and validates a GitHub-specific response header, and (2) an unverified "happy path" that simply trusts the `wwwauth[]` credential field forwarded by git, which is populated verbatim from the remote server's own `WWW-Authenticate` HTTP header. These two paths are not held to the same contract/interface, and the unverified one is checked first and short-circuits the verified one.

### Finding Description
`getCredential()` in [2](#0-1)  calls `getEndpointKind(cred, store)` to classify a remote as `'generic'`, `'github.com'`, `'ghe.com'`, or `'enterprise'`. Inside `getEndpointKind`: [3](#0-2) 

the function iterates `cred.entries()` looking for keys starting with `wwwauth[` and, if the value contains `realm="GitHub"`, immediately returns `'enterprise'` — before ever calling the properly verified `isGitHubHost()` (which performs a real HTTPS request with certificate handling and checks for the `x-github-request-id` response header, see [4](#0-3) ). The comment in the code even acknowledges this is a "happy-path" shortcut to avoid a network round trip.

The `wwwauth[]` field is not derived from anything Desktop verifies — it's the literal `WWW-Authenticate` header echoed back by the remote HTTP server during Git's credential negotiation (this is standard Git credential-helper protocol behavior: Git captures `WWW-Authenticate` from a 401 response and forwards it as `wwwauth[]`/`wwwauth[N]` to the credential helper). Any git remote — a malicious server, a compromised mirror, or a MITM/proxy on an untrusted network — fully controls this string and can trivially cause it to contain `realm="GitHub"`.

Because `getGitHubCredential()` (exact-origin match against already-signed-in accounts) is checked first and only returns a value when the account origin exactly matches, this spoof does not directly exfiltrate an already-stored GitHub token. However, when it fails to match (no account known for that host), the spoofed `'enterprise'` classification causes Desktop to treat an arbitrary attacker-controlled HTTPS remote as if it were a verified GitHub Enterprise host and to automatically invoke `ui.promptForGitHubSignIn(endpoint)` [5](#0-4) , which in turn calls `dispatcher.beginEnterpriseSignIn(cb)` and `dispatcher.setSignInEndpoint(origin)` bound to the attacker's origin [6](#0-5) . This initiates a real GitHub Enterprise-style OAuth/sign-in flow scoped to an untrusted, attacker-chosen origin — without the network-based host verification that is supposed to gate that decision.

### Impact Explanation
This breaks the invariant that "only hosts Desktop has actually verified as GitHub-compatible (`isGitHubHost`) are treated as GitHub Enterprise endpoints eligible for the GitHub sign-in/OAuth flow." An attacker who controls (or MITMs) a git remote that the victim clones/fetches from can force Desktop to silently classify that remote as a trusted GitHub Enterprise host and kick off an enterprise sign-in/OAuth binding flow against the attacker's origin — this is precisely the "unauthorized OAuth or account binding" impact category, achieved purely by controlling server response headers during a normal git operation, with no local access, no malware, and no unusual user action beyond a routine `fetch`/`clone`/`push`.

### Likelihood Explanation
The trigger requires nothing more than operating (or intercepting) a git HTTPS remote that the victim adds to Desktop — an ordinary and expected attacker capability under the threat model (malicious/compromised repo host or network MITM). Setting a custom `WWW-Authenticate: Basic realm="GitHub"` header on a 401 response is trivial for any HTTP server operator. The existing guard, `isGitHubHost()`, is bypassed entirely because the `wwwauth[]` shortcut check runs first and returns before the network-verified path is ever reached.

### Recommendation
Do not trust the `wwwauth[]` realm value as sufficient proof of GitHub identity. Either remove the shortcut entirely and always fall back to the network-verified `isGitHubHost()` check, or treat a `realm="GitHub"` hint only as a signal to *prioritize* running `isGitHubHost()` (not to substitute for it) before classifying an endpoint as `'enterprise'` and before invoking any sign-in/OAuth UI flow bound to that origin.

### Proof of Concept
1. Stand up an HTTPS git server at `https://evil.example.com/attacker-repo.git` that, on the initial unauthenticated request, responds with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
2. In GitHub Desktop, add this remote (e.g. via clone or as a remote on an existing repo) and perform a fetch/push, causing Git to invoke the `desktop` credential helper.
3. Git forwards the captured header to the trampoline as `wwwauth[0]=Basic realm="GitHub"` in the credential `get` request's stdin.
4. `getEndpointKind()` matches `realm="GitHub"` and returns `'enterprise'` without ever calling `isGitHubHost()` [7](#0-6) .
5. Since no account matches `evil.example.com`, `getCredential()` calls `ui.promptForGitHubSignIn('https://evil.example.com')`, which starts the GitHub Enterprise sign-in flow bound to the attacker's origin [8](#0-7)  — a flow the user never explicitly requested and that a genuinely-verified non-GitHub host would not trigger.

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {

        resolve(result.kind === 'success' ? result.account : undefined)

        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)

    })
  }
