### Title
Missing sender-authorization check in `CW721ERC721Pointer.transferFrom` allows anyone to steal any pointer-wrapped CW721 NFT - (File: contracts/src/CW721ERC721Pointer.sol)

### Summary
`CW721ERC721Pointer` is the EVM-side ERC721 wrapper contract that lets an EVM caller interact with a native CosmWasm CW721 NFT collection through the wasmd precompile. Its overridden `transferFrom` function only checks that the `from` argument equals the token's actual owner, but never checks that `msg.sender` is that owner or an approved operator/spender. Any address can therefore call `transferFrom(realOwner, attacker, tokenId)` and have the underlying CW721 `transfer_nft` executed on the owner's behalf, exactly mirroring the reported bug class where an intended-looking but ineffective authorization check allows anyone to move/burn a token they do not own or control.

### Finding Description
The base OpenZeppelin `ERC721.transferFrom` enforces `_isAuthorized(owner, _msgSender(), tokenId)` before moving a token, but `CW721ERC721Pointer` overrides `transferFrom` and replaces that authorization logic with only an ownership check on the `from` parameter: [1](#0-0) 

There is no verification anywhere in this function (or in `approve`/`setApprovalForAll`, which are also unauthenticated pass-throughs to the wasmd precompile) that `msg.sender` is the `from` owner, is `getApproved` for the token, or `isApprovedForAll`. `require(from == ownerOf(tokenId), ...)` merely re-derives who the true owner is — it says nothing about who is calling. This is structurally identical to the reported `HoneyJarPortal._debitFrom` bug: a check that "looks like" access control (`if (_from != _msgSender())`) but is either redundant or, as here, entirely omits validating the caller's identity/authorization, letting a completely unrelated caller trigger a state-changing, asset-moving action on someone else's token.

Because `transferFrom` is `public override` and virtual dispatch in Solidity resolves to the overridden version, the inherited `safeTransferFrom(address,address,uint256)` / `safeTransferFrom(address,address,uint256,bytes)` from OpenZeppelin's `ERC721`, which internally call `transferFrom`, also inherit this missing-authorization flaw.

Contrast this with the sibling `CW1155ERC1155Pointer.burn`/`burnBatch`, which correctly gate the operation with `require(msg.sender == account || isApprovedForAll(account, msg.sender), ...)`: [2](#0-1) 

No equivalent check exists in `CW721ERC721Pointer.transferFrom`.

### Impact Explanation
This allows unauthorized transfer of any CW721 NFT wrapped by the pointer contract — any EVM account can move an arbitrary token out of its rightful owner's control to any address of the attacker's choosing, without holding approval, without the owner's signature, and without any precondition. This satisfies the "unauthorized transfer via pointer" acceptance criterion and represents concrete, permanent fund/asset loss for the NFT holder (equivalent to theft), just as the original report's unauthorized-burn bug results in permanent asset loss.

### Likelihood Explanation
High. Exploitation requires no special privileges, no preconditions, and no cooperation from the victim — a single EVM transaction calling `transferFrom(victim, attacker, tokenId)` on the pointer contract is sufficient, reachable by any public-RPC client / EVM transaction sender.

### Recommendation
Add proper authorization enforcement in `CW721ERC721Pointer.transferFrom` (and ensure `approve`/`setApprovalForAll` flows are consistent), e.g.:
```solidity
require(
    _msgSender() == from ||
    _msgSender() == getApproved(tokenId) ||
    isApprovedForAll(from, _msgSender()),
    "ERC721: caller is not token owner or approved"
);
```
before issuing the `transfer_nft` CosmWasm execute call, mirroring the pattern already used in `CW1155ERC1155Pointer`.

### Proof of Concept
1. Owner `O` holds `tokenId = 1` in the underlying CW721 contract, wrapped through `CW721ERC721Pointer`.
2. Attacker `A` (any unrelated EVM address, no approval) calls:
   ```solidity
   pointer.transferFrom(O, A, 1);
   ```
3. Inside `transferFrom`, `require(from == ownerOf(tokenId), ...)` passes because `from` (`O`) is indeed the current owner — this check validates *who owns the token*, not *who is calling*.
4. The function proceeds to build and `_execute` the CosmWasm `transfer_nft` message with `recipient = A`, which the wasmd precompile executes with the pointer contract's authority, transferring the NFT to `A` with no owner signature or approval involved. [1](#0-0)

```text
    function transferFrom(address from, address to, uint256 tokenId) public override {
        if (to == address(0)) {
            revert ERC721InvalidReceiver(address(0));
        }
        require(from == ownerOf(tokenId), "`from` must be the owner");
        string memory recipient = _formatPayload("recipient", _doubleQuotes(AddrPrecompile.getSeiAddr(to)));
        string memory tId = _formatPayload("token_id", _doubleQuotes(Strings.toString(tokenId)));
        string memory req = _curlyBrace(_formatPayload("transfer_nft", _curlyBrace(_join(recipient, tId, ","))));
        _execute(bytes(req));
    }
```
