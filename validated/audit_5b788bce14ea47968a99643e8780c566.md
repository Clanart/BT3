## Title
Unverified `git stash push` success heuristic in `createDesktopStashEntry` causes silent working-directory data loss during branch checkout - (File: `app/src/lib/git/stash.ts`)

### Summary
Analogous to the ERC20 `transfer`/`transferFrom` bug class — where a call's success is assumed without properly validating its return value, and the caller then updates state as if the operation had succeeded — GitHub Desktop's `createDesktopStashEntry` infers stash-creation success from an exit-code/stderr heuristic rather than verifying that a stash object actually exists. Callers (`createStashAndDropPreviousEntry`, `checkoutAndLeaveChanges`) trust this unverified "success" signal, drop the user's previous real stash, and then destructively check out the target branch — permanently discarding uncommitted changes that were never actually stashed.

### Finding Description
`createDesktopStashEntry` treats a `git stash push` exit code of `1` as success as long as stderr does not contain a line starting with `error: `: [1](#0-0) 

The code's own inline comment documents that this heuristic is known to be unsound: running `git stash push` on an **unborn branch** (a branch with no commits yet — e.g., right after cloning an empty repository or an orphan default branch) returns exit code `1` with the message `"You do not have the initial commit yet"` and **no stash is created**, yet the function still returns `true`: [2](#0-1) 

That unverified `true` return value is trusted by `createStashAndDropPreviousEntry`, which unconditionally drops the branch's existing (real) stash entry whenever `createdStash === true`: [3](#0-2) 

This function backs the "Leave my changes on current branch" checkout path, `checkoutAndLeaveChanges`, which after "stashing" proceeds to call `checkoutIgnoringChanges` — a destructive checkout that overwrites/discards the working directory on the assumption that a safety-net stash now exists: [4](#0-3) 

No guard re-verifies that a stash object was actually created before the previous stash is dropped and the destructive checkout is performed — exactly the ERC20 pattern of "operation return value not checked to be true, caller proceeds and updates authoritative state anyway."

### Impact Explanation
The corrupted value is the user's uncommitted working-directory changes and their previously saved Desktop stash entry for the branch. When the heuristic misfires:
1. The user's genuine, previously existing stash for the branch is deleted (`dropDesktopStashEntry`), even though no replacement stash was created.
2. `checkoutIgnoringChanges` then switches branches while discarding the working directory contents, believing they were safely stashed.

The net effect is silent, unrecoverable loss of both the old stash and the new uncommitted changes — with no error surfaced to the user, since the git call returned "success" by Desktop's own logic. This matches the requested impact category of "silent corruption of what the user commits."

### Likelihood Explanation
The exact documented trigger — an unborn/no-commit branch — is trivially attacker-controllable: a malicious or degenerate remote repository can simply be empty or have an orphan default branch with zero commits. A victim who clones such a repository, makes local edits, and then switches branches while GitHub Desktop is configured to "stash on current branch" (the default in some flows and an explicit option in others) will hit this exact code path. The developer's own 2024 comment ("That didn't hold up to a quick read of the stash code... I'm not going to mess with this now") indicates the unborn-repo case is only the confirmed instance and that other exit-code-1/no-`error:`-prefix scenarios may exist and behave the same way, broadening the trigger surface further.

### Recommendation
Do not infer stash success from exit code and stderr pattern-matching. After `git stash push` returns with a non-zero/ambiguous result, explicitly verify success by checking whether a new stash entry (e.g., via `git rev-parse -q --verify refs/stash` or comparing `getStashes()` before/after) was actually created before treating the operation as successful, dropping any prior stash entry, or proceeding with a destructive checkout.

### Proof of Concept
1. Clone (or create) a repository whose current branch is unborn (no commits yet) but already has an existing Desktop stash entry (created earlier while on a valid commit, then reset to unborn state — or more realistically, simulate by cloning an empty remote and having a prior stash from a previous session).
2. In GitHub Desktop, make local changes on this branch.
3. Trigger "Leave my changes on current branch" while switching branches, which calls `createStashAndDropPreviousEntry` → `createDesktopStashEntry`.
4. `git stash push -m ...` exits with code `1` and stderr `"You do not have the initial commit yet"` (no `error:` prefix) per [5](#0-4) .
5. `createDesktopStashEntry` returns `true` despite no stash existing; `createStashAndDropPreviousEntry` drops the pre-existing stash entry at [6](#0-5) .
6. `checkoutIgnoringChanges` then runs, discarding the working directory — the user's changes and the old stash are both gone.

   * Checkout the given branch and leave any local changes on the current branch
   *
   * Note that this will ovewrite any existing stash enty on the current branch.

  private async checkoutAndLeaveChanges(
    repository: Repository,
    branch: Branch,
    currentRemote: IRemote | null
  ) {
    const repositoryState = this.repositoryStateCache.get(repository)
    const { workingDirectory } = repositoryState.changesState
    const { tip } = repositoryState.branchesState

    if (tip.kind === TipState.Valid && workingDirectory.files.length > 0) {
      await this.createStashAndDropPreviousEntry(repository, tip.branch)
      this.statsStore.increment('stashCreatedOnCurrentBranchCount')
    }

    return this.checkoutIgnoringChanges(repository, branch, currentRemote)
  }

  private async createStashAndDropPreviousEntry(
    repository: Repository,
    branch: Branch
  ) {
    const entry = await getLastDesktopStashEntryForBranch(repository, branch)
    const gitStore = this.gitStoreCache.get(repository)

    const createdStash = await gitStore.performFailableOperation(() =>
      this.createStashEntry(repository, branch)
    )

    if (createdStash === true && entry !== null) {
      const { stashSha, branchName } = entry
      await gitStore.performFailableOperation(async () => {
        await dropDesktopStashEntry(repository, stashSha)
        log.info(`Dropped stash '${stashSha}' associated with ${branchName}`)
      })
    }

    return createdStash === true
  }
