### Title
`ThresholdKeys::read` accepts attacker-crafted key material with no consistency check, yielding a "threshold" key fully controlled by the attacker - (File: crypto/dkg/src/lib.rs)

### Summary
Analogous to CVE-2026-15976 — where untrusted bytes are deserialized into a trusted object without integrity verification (`torch.load(..., weights_only=False)`) — `ThresholdKeys::read` reconstructs a threshold signing key entirely from a byte stream, and neither `read` nor `ThresholdKeys::new` verifies that the deserialized fields are mutually consistent or correspond to any key the node actually agreed to. The group key is derived *solely* from attacker-supplied `verification_shares`, and the deserialized `secret_share` is never checked against `verification_shares[i]`. A crafted blob therefore instantiates a `ThresholdKeys` object whose group key is a solo key known to the attacker, which the victim's signer then treats as the output of its DKG.

### Finding Description
`ThresholdKeys::read` (`crypto/dkg/src/lib.rs:574-632`) parses `t`, `n`, `i`, an `Interpolation` method, a `secret_share` scalar, and `n` verification shares directly from a reader, then calls `ThresholdKeys::new` (`crypto/dkg/src/lib.rs:349-390`). `ThresholdKeys::new` validates only:

- the number of verification shares equals `n` (`lib.rs:355`),
- participant indexes are `<= n` (`lib.rs:361`),
- `Interpolation::Constant` requires `t == n` (`lib.rs:368`).

It then computes the group key as the interpolation of `verification_shares[1..=t]` (`lib.rs:376-378`) and stores everything unconditionally. Critically absent:

- **No check that `C::generator() * secret_share == verification_shares[i]`** — the deserialized secret share is never bound to the public key set.
- **No binding of `group_key` to any externally committed value** — the group key is whatever the input bytes imply.

Every `read_F`/`read_G` call accepts any canonically-encoded scalar/point, so the attacker has full freedom over the reconstructed state.

### Impact Explanation
A `ThresholdKeys` blob can be constructed where:

- `verification_shares[k] = G * s_k` for scalars `s_k` the attacker knows,
- `secret_share` is any attacker-known scalar (or simply inconsistent),

so `group_key()` interpolates to a key `K* = G * s*` whose discrete log `s*` is known to the attacker. Downstream, `ThresholdView` (`lib.rs:463-533`) and FROST signing will faithfully produce signature shares and view `K*` as the multisig's key. Any funds or trust anchored to `K*` (e.g., a Bitcoin address derived from it) are spendable by the attacker *alone*, without any threshold — the node believes it holds a `t`-of-`n` share of `K*` when in fact `K*` is a single-sig key. Alternatively, an inconsistent `secret_share` yields shares that fail `share_verification_statements`, silently poisoning every signing session. Either way, the deserialized object is trusted as a legitimate DKG product with no integrity proof — the same trust-boundary violation as the unpickled model weights in the CVE.

### Likelihood Explanation
The scan rules explicitly designate `ThresholdKeys::read` as reachable with untrusted bytes. Any deployment where serialized keys cross a trust boundary — fetched from storage, restored from backup, replicated, or delivered by another party — exposes this path. Crafting the blob requires only choosing scalars and writing their encodings; no crypto primitive needs to be broken. Severity is bounded by the requirement that the attacker control the serialized input, hence Medium rather than Critical.

### Recommendation
In `ThresholdKeys::new` (or `read`), verify `C::generator() * secret_share == verification_shares[&params.i()]` so the secret share is provably consistent with the committed verification shares. Where an externally committed group key exists, `read` should accept an expected `group_key`/`context` commitment and reject mismatches rather than deriving trust entirely from the blob. Document that `ThresholdKeys::read` must only consume authenticated input.

### Proof of Concept

// Attacker knows s* and builds a blob where K* = G * s*
let t = 1u16; let n = 1u16;
let s_star = <C as Ciphersuite>::F::random(&mut OsRng);
let mut blob = vec![];
blob.extend(u32::try_from(C::ID.len()).unwrap().to_le_bytes());
blob.extend(C::ID);
blob.extend(t.to_le_bytes());
blob.extend(n.to_le_bytes());
blob.extend(1u16.to_le_bytes());        // participant i = 1
blob.push(1);                            // Interpolation::Lagrange
blob.extend(s_star.to_repr().as_ref());  // "secret_share" = s* (attacker-known)
blob.extend((C::generator() * s_star).to_bytes().as_ref()); // verification_shares[1]

let keys = ThresholdKeys::<C>::read(&mut blob.as_ref()).unwrap();
// keys.group_key() == G * s_star — a solo key the attacker fully controls,
// yet presented as a 1-of-1 (or any t-of-n) threshold key.

  pub fn new(
    params: ThresholdParams,
    interpolation: Interpolation<C::F>,
    secret_share: Zeroizing<C::F>,
    verification_shares: HashMap<Participant, C::G>,
  ) -> Result<ThresholdKeys<C>, DkgError> {
    if verification_shares.len() != usize::from(params.n()) {
      Err(DkgError::IncorrectAmountOfVerificationShares {
        n: params.n(),
        shares: verification_shares.len(),
      })?;
    }
    for participant in verification_shares.keys().copied() {
      if u16::from(participant) > params.n() {
        Err(DkgError::InvalidParticipant { n: params.n(), participant })?;
      }
    }

    match &interpolation {
      Interpolation::Constant(_) => {
        if params.t() != params.n() {
          Err(DkgError::InapplicableInterpolation("constant interpolation for keys where t != n"))?;
        }
      }
      Interpolation::Lagrange => {}
    }

    let t = (1 ..= params.t()).map(Participant).collect::<Vec<_>>();
    let group_key =
      t.iter().map(|i| verification_shares[i] * interpolation.interpolation_factor(*i, &t)).sum();

    Ok(ThresholdKeys {
      core: Arc::new(Zeroizing::new(ThresholdCore {
        params,
        interpolation,
        secret_share,
        group_key,
        verification_shares,
      })),
      scalar: C::F::ONE,
      offset: C::F::ZERO,
    })

  pub fn read<R: io::Read>(reader: &mut R) -> io::Result<ThresholdKeys<C>> {
    {
      let different = || io::Error::other("deserializing ThresholdKeys for another curve");

      let mut id_len = [0; 4];
      reader.read_exact(&mut id_len)?;
      if u32::try_from(C::ID.len()).unwrap().to_le_bytes() != id_len {
        Err(different())?;
      }

      let mut id = vec![0; C::ID.len()];
      reader.read_exact(&mut id)?;
      if id != C::ID {
        Err(different())?;
      }
    }

    let (t, n, i) = {
      let mut read_u16 = || -> io::Result<u16> {
        let mut value = [0; 2];
        reader.read_exact(&mut value)?;
        Ok(u16::from_le_bytes(value))
      };
      (
        read_u16()?,
        read_u16()?,
        Participant::new(read_u16()?).ok_or(io::Error::other("invalid participant index"))?,
      )
    };

    let mut interpolation = [0];
    reader.read_exact(&mut interpolation)?;
    let interpolation = match interpolation[0] {
      0 => Interpolation::Constant({
        let mut res = Vec::with_capacity(usize::from(n));
        for _ in 0 .. n {
          res.push(C::read_F(reader)?);
        }
        res
      }),
      1 => Interpolation::Lagrange,
      _ => Err(io::Error::other("invalid interpolation method"))?,
    };

    let secret_share = Zeroizing::new(C::read_F(reader)?);

    let mut verification_shares = HashMap::new();
    for l in (1 ..= n).map(Participant) {
      verification_shares.insert(l, <C as Ciphersuite>::read_G(reader)?);
    }

    ThresholdKeys::new(
      ThresholdParams::new(t, n, i).map_err(io::Error::other)?,
      interpolation,
      secret_share,
      verification_shares,
    )
    .map_err(io::Error::other)
  }
