### Title
Gasless module's "sender with code" check uses a stale, once-per-block state snapshot, allowing an EIP-7702-delegated EOA to bypass the anti-abuse check within the same block - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The Kaia gasless module enforces that an approve/swap transaction's sender must be a plain EOA (no code), to prevent contract-controlled or delegated accounts from abusing gasless fee-sponsorship. This check is performed via `getCurrentHasCode`, which reads `g.currentState.GetCodeHash(addr)` [2](#0-1) . However `g.currentState` is only refreshed once per block, inside `PostInsertBlock` after a block is fully inserted [1](#0-0) . This mirrors the classic `isContract`/`extcodesize` TOCTOU bug from the report: the check reflects a snapshot of state that does not include changes made by transactions earlier in the very same in-flight block/bundle, so an entity can install "code" (via an EIP-7702 `SetCodeAuthorization` delegation) on their own EOA and still pass the "no code" gasless check for other transactions submitted in the same block cycle, exactly as attackers bypassed `isContract` during constructor execution.

### Finding Description
`checkBalanceForApprove` and `checkBalanceForSwap` both gate on `ShouldCheckSenderCode()` and call `g.getCurrentHasCode(sender)` to reject "sender with code" [3](#0-2) [4](#0-3) . Kaia supports EIP-7702-style `TxTypeEthereumSetCode` transactions, where an EOA authorizes installation of delegated "code" onto its own account via `SetCodeAuthorization`, applied by `applyAuthorization`/`SetCodeToEOA` during transaction execution [5](#0-4) . The existing repository test explicitly demonstrates the check is intended to catch exactly this case: after `sendSetCodeTx`, a subsequent swap from that account is rejected with "sender with code is not allowed" [6](#0-5) .

The vulnerability is that `getCurrentHasCode` does not consult the live/pending state as transactions execute within a block; it only reflects `g.currentState`, which is set exactly once per block boundary, after the block has already been fully inserted [1](#0-0) . `GetCheckBalance()` is invoked as a tx-pool level gate (`decodeApproveTx`/`decodeSwapTx` plus balance/code checks) prior to a block being built/inserted [7](#0-6) , meaning any code-installation that would occur during the current, not-yet-inserted block is invisible to this check — the check is validated against the previous block's final state, not the state as-of the point in the block sequence where the gasless tx would actually execute. This directly parallels the report's bug class: the security check ("isContract"/"has code") is evaluated at a point in the lifecycle (before code exists / before the check's snapshot is refreshed) that differs from the point where the protected value transfer actually occurs, permitting an account that will have code by execution time to pass the check as if it were a plain EOA.

### Impact Explanation
The "no code" restriction exists specifically to prevent contract-controlled or delegation-abused accounts from exploiting the gasless fee-sponsorship / swap-repay flow (e.g., an attacker using programmable/delegated logic to manipulate approvals, reentrancy, or repayment sequencing in ways a plain EOA transaction cannot). Bypassing it allows an account with code (via 7702 delegation) to participate in the gasless subsidized flow that the lender (fee-paying node) sponsors, undermining the anti-abuse safeguard and potentially enabling theft/drain of the gasless lender's sponsored funds through logic that would be executed via the delegated code path rather than a plain EOA transfer, which is the scenario `ShouldCheckSenderCode` was added to prevent.

### Likelihood Explanation
Exploitation only requires a single actor to submit a `TxTypeEthereumSetCode` transaction (self-authorizing delegation) and a gasless approve/swap transaction from the same address such that both land in the same block cycle relative to `PostInsertBlock`'s once-per-block refresh of `g.currentState`. This is a straightforward, low-cost, single-account, single-block sequencing action reachable by any ordinary transaction sender — no privileged access, validator collusion, or complex setup is required.

### Recommendation
Re-validate the sender's code status against the state as of immediately before the gasless transaction actually executes (e.g., re-check at execution time within `ExecutionModule` hooks, or refresh/derive `currentState` per-transaction within a block rather than only in `PostInsertBlock`), or explicitly reject any sender that has a pending/in-block `SetCodeAuthorization` targeting itself earlier in the same block/bundle. Additionally, consider validating code-status directly at the point-of-execution (inside `checkBalanceForApprove`/`checkBalanceForSwap` execution, not just pool admission) so that TOCTOU windows between tx-pool checking and actual block execution cannot be exploited.

### Proof of Concept
1. Attacker controls EOA `A` with zero code (`GetCodeHash(A) == EmptyCodeHash`).
2. Node's gasless module currently holds `g.currentState` set at the end of block N (`PostInsertBlock`) [1](#0-0) .
3. Attacker crafts a `TxTypeEthereumSetCode` transaction from `A` containing a `SetCodeAuthorization` delegating to an arbitrary contract, per the pattern in `TestEIP7702` [8](#0-7) , intending it to be included in block N+1.
4. In the same submission window (before block N+1 is inserted and `PostInsertBlock` refreshes `g.currentState`), the attacker also submits a gasless approve/swap transaction from `A`.
5. `GetCheckBalance()` calls `getCurrentHasCode(A)`, which still reads the stale `g.currentState` from block N where `A` has no code, so the check passes [9](#0-8) .
6. Both transactions land in block N+1; by the time the gasless transaction executes, `A` in fact has delegated code installed by the earlier SetCode transaction, defeating the intended "sender with code is not allowed" restriction that the existing test suite validates only for the simple sequential (already-committed) case [6](#0-5) .

```go
func (g *GaslessModule) PostInsertBlock(block *types.Block) error {
	currentState, err := g.Chain.StateAt(block.Header().Root)
	if err != nil {
		return err
	}
	g.setCurrentState(currentState)
	return g.updateAddresses(block.Header())
}
```

```go
func (g *GaslessModule) getCurrentHasCode(addr common.Address) bool {
	g.currentStateMu.Lock()
	defer g.currentStateMu.Unlock()

	return g.currentState.GetCodeHash(addr) != types.EmptyCodeHash
}
```

```go
func (g *GaslessModule) GetCheckBalance() func(tx *types.Transaction) error {
	return func(tx *types.Transaction) error {
		if approveArgs, ok := decodeApproveTx(tx, g.signer); ok {
			return g.checkBalanceForApprove(approveArgs)
		}
		if swapArgs, ok := decodeSwapTx(tx, g.signer); ok {
			return g.checkBalanceForSwap(swapArgs, tx.Nonce())
		}
		return errors.New("not a gasless transaction") // should not happen because IsModuleTx is called before GetCheckBalance
	}
}
```

```go
func (st *StateTransition) applyAuthorization(auth *types.SetCodeAuthorization, rules params.Rules) (err error) {
	authority, err := st.validateAuthorization(auth)
	if err != nil {
		return err
	}

	// If the account already exists in state, refund the new account cost
	// charged in the initrinsic calculation.
	if st.state.Exist(authority) {
		// If the account is not AccountKeyTypeLegacy, setcode is not allowed.
		accountKeyType := st.state.GetKey(authority).Type()
		if !accountKeyType.IsLegacyAccountKey() {
			return fmt.Errorf("%w: %v", ErrAuthorizationNotAllowAccountKeyType, accountKeyType)
		}
		st.state.AddRefund(params.CallNewAccountGas - params.TxAuthTupleGas)
	}

	// Update nonce and account code.
	st.state.IncNonce(authority)
	delegation := types.AddressToDelegation(auth.Address)
	if common.EmptyAddress(auth.Address) {
		// Delegation to zero address means clear.
		st.state.SetCodeToEOA(authority, []byte{}, rules)
		return nil
	}

	// Otherwise install delegation to auth.Address.
	// We treat EOA and SCA as separate objects and therefore need to use
	// distinct methods.
	st.state.SetCodeToEOA(authority, delegation, rules)

	return nil
```
