Based on my investigation, I found a concrete analog of the division-rounding hazard from the SecondSwap report: `Kip71GasTarget` uses `noopFormatChecker` (no lower-bound validation), and `NextMagmaBlockBaseFee` divides by `gasTarget` without a zero-guard (unlike `BaseFeeDenominator`, which explicitly falls back to 64 when zero).

### Title
KIP-71 base fee calculation panics on division-by-zero when `reward.kip71.gastarget` governance parameter is zero - (File: params/kip71_config.go)

### Summary
`KIP71Config.NextMagmaBlockBaseFee` divides by `gasTarget` in both the "gas used > target" and "gas used < target" branches without checking `gasTarget != 0`, unlike the `BaseFeeDenominator` field which is explicitly defended (`if kc.BaseFeeDenominator == 0 { baseFeeDenominator = 64 }`). The governance parameter `Kip71GasTarget` uses `noopFormatChecker`, meaning no validation prevents it from being set to `0`.

### Finding Description
`NextMagmaBlockBaseFee` computes the next block's base fee as: [1](#0-0) 

```go
parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
...
} else if parentGasUsed > gasTarget {
    ...
    gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
    x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
    y := x.Div(x, new(big.Int).SetUint64(gasTarget))   // <-- division by gasTarget
    baseFeeDelta := math.BigMax(x.Div(y, baseFeeDenominator), common.Big1)
    ...
} else {
    ...
    gasUsedDelta := new(big.Int).SetUint64(gasTarget - parentGasUsed)
    x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
    y := x.Div(x, new(big.Int).SetUint64(gasTarget))   // <-- division by gasTarget
    ...
}
``` [2](#0-1) 

Note that `BaseFeeDenominator` has an explicit zero-guard: [3](#0-2) 

But `GasTarget` has no equivalent protection. In `kaiax/gov/param.go`, the format checker registered for `Kip71GasTarget` is `noopFormatChecker`, in contrast to `Kip71BaseFeeDenominator` which explicitly checks `v != 0`: [4](#0-3) 

If `parentGasUsed != gasTarget` (i.e., `gasTarget == 0` and any nonzero gas was used, or vice versa), the code enters one of the two `big.Int.Div(x, 0)` branches, which in Go's `math/big` package panics with a runtime "division by zero" error rather than returning an error value.

### Impact Explanation
`NextMagmaBlockBaseFee` is invoked during header verification (`VerifyMagmaHeader`) and fee-history/oracle computations, both of which run on every full node as part of ordinary consensus block processing (State transition / gas price computation), and via the public `eth_feeHistory`/`kaia_...` JSON-RPC path (`node/cn/gasprice/feehistory.go`, calling `kip71Config.NextMagmaBlockBaseFee`) that a public RPC caller can trigger. A panic here (rather than a graceful error) crashes the node process or at minimum halts block processing/serving for any node that reaches this code path once `GasTarget=0` is active — a chain-wide denial-of-service that causes an "acceptance of an invalid transaction or block" state (nodes crash instead of consistently rejecting/handling the malformed governance state), and can cause divergence between nodes if some nodes have cached/old parameter values and others panic.

### Likelihood Explanation
Reaching this requires the governance parameter `reward.kip71.gastarget` to be set to `0` via a governance vote. This is not directly triggerable by an ordinary unprivileged transaction sender in one transaction; it requires governance-level control (an allowed analog category per the rules, but with lower likelihood since it needs a successful governance proposal/vote, not just a single call). However, once such a value is (even inadvertently, e.g., a typo/misconfiguration in a governance vote or a malicious governance council member) active, every node that computes the next base fee — including public RPC servers responding to unauthenticated `eth_feeHistory`/`kaia_getRewards` calls — will panic deterministically on the very next Magma-enabled block whose `parentGasUsed != 0`. This is a real, low-effort, single-point-of-failure since there is no validation anywhere in the governance parameter pipeline (`FormatChecker`) preventing `GasTarget = 0`, unlike the sibling `BaseFeeDenominator` parameter, which is explicitly hardened.

### Recommendation
Add a `FormatChecker` for `Kip71GasTarget` in `kaiax/gov/param.go` that rejects `0` (mirroring `Kip71BaseFeeDenominator`'s `v != 0` check), and additionally add a defensive zero-guard inside `NextMagmaBlockBaseFee` (analogous to the existing `baseFeeDenominator == 0` fallback) so that a zero `GasTarget` cannot cause a `big.Int` division-by-zero panic regardless of how the governance value was set.

### Proof of Concept
1. Governance sets `reward.kip71.gastarget = 0` (via a governance vote using the existing, unvalidated `Kip71GasTarget` parameter, since its `FormatChecker` is `noopFormatChecker`). [5](#0-4) 
2. Once this governance value becomes active at a Magma-enabled block, any node (or public RPC server) that computes `NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)` with `parentHeaderGasUsed != 0` executes:
```go
gasTarget := kc.GasTarget          // 0
parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)  // != 0
// parentGasUsed > gasTarget branch taken
gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
y := x.Div(x, new(big.Int).SetUint64(gasTarget))   // Div(x, 0) -> panic: division by zero
``` [6](#0-5) 
3. This panics inside header verification (`VerifyMagmaHeader`) for every full node processing the block, and inside `node/cn/gasprice/feehistory.go`'s `processBlock` for any node serving `eth_feeHistory` to public RPC callers, crashing the process — a chain-wide denial of service triggered by a single corrupted/malicious governance parameter with no validation layer to stop it.

func (kc *KIP71Config) NextMagmaBlockBaseFee(parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) *big.Int {
	// governance parameters
	lowerBoundBaseFee := new(big.Int).SetUint64(kc.LowerBoundBaseFee)
	upperBoundBaseFee := new(big.Int).SetUint64(kc.UpperBoundBaseFee)
	makeEvenByCeil(lowerBoundBaseFee)
	makeEvenByFloor(upperBoundBaseFee)

	// If the parent is the magma disabled block or genesis, then return the lowerBoundBaseFee (default 25ston)
	if parentHeaderNumber.Cmp(new(big.Int).SetUint64(0)) == 0 || parentHeaderBaseFee == nil {
		return makeEvenByFloor(lowerBoundBaseFee)
	}

	var baseFeeDenominator *big.Int
	if kc.BaseFeeDenominator == 0 {
		// To avoid panic, set the fluctuation range small
		baseFeeDenominator = new(big.Int).SetUint64(64)
	} else {
		baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
	}
	gasTarget := kc.GasTarget
	upperGasLimit := kc.MaxBlockGasUsedForBaseFee

	// check the case of upper/lowerBoundBaseFee is updated by governance mechanism
	parentBaseFee := parentHeaderBaseFee
	if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
		parentBaseFee = upperBoundBaseFee
	} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
		parentBaseFee = lowerBoundBaseFee
	}

	// upper gas limit cut off the impulse of used gas to upper bound
	parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
	if parentGasUsed == gasTarget {
		return makeEvenByFloor(parentBaseFee)
	} else if parentGasUsed > gasTarget {
		// shortcut. If parentBaseFee is already reached upperbound, do not calculate.
		if parentBaseFee.Cmp(upperBoundBaseFee) == 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		// If the parent block used more gas than its target,
		// the baseFee of the next block should increase.
		// baseFeeDelta = max(1, parentBaseFee * (parentGasUsed - gasTarget) / gasTarget / baseFeeDenominator)
		gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := math.BigMax(x.Div(y, baseFeeDenominator), common.Big1)

		nextBaseFee := x.Add(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(upperBoundBaseFee) > 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	} else {
		// shortcut. If parentBaseFee is already reached lower bound, do not calculate.
		if parentBaseFee.Cmp(lowerBoundBaseFee) == 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		// Otherwise if the parent block used less gas than its target,
		// the baseFee of the next block should decrease.
		// baseFeeDelta = parentBaseFee * (gasTarget - parentGasUsed) / gasTarget / baseFeeDenominator
		gasUsedDelta := new(big.Int).SetUint64(gasTarget - parentGasUsed)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := x.Div(y, baseFeeDenominator)

		nextBaseFee := x.Sub(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(lowerBoundBaseFee) < 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	}
}
