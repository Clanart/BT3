### Title
Denial of Service via Unbounded Pagination Loop in `CW721ERC721Pointer.balanceOf()` - (File: `contracts/src/CW721ERC721Pointer.sol`)

### Summary
`CW721ERC721Pointer.balanceOf()` computes an owner's NFT balance by repeatedly querying the underlying CosmWasm CW721 contract in pages of 1000 tokens via a `while` loop that only terminates when an empty `{"tokens":[]}` response is returned. The number of loop iterations (and thus the number of cross-VM `WasmdPrecompile.query()` calls) grows linearly with however many tokens the queried address owns in that collection. Since minting/holding a large number of tokens under one address is entirely within reach of an unprivileged CosmWasm/EVM user (self-mint or accumulate via transfers), an attacker can inflate an address's token count until any call to `balanceOf()` for that address exceeds the caller's available gas, mirroring the "unbounded array iteration causes DoS" bug class from the HAL-07 report (there, the growable structure was a Solidity `users` array; here it is the number of wasm-query pages needed to enumerate an owner's CW721 tokens).

### Finding Description
`balanceOf()` builds a CW721 `tokens` query with `limit:1000` and loops: [1](#0-0) 

Each iteration issues a new `WasmdPrecompile.query()` call (a Cosmos SDK/wasmd smart-query executed synchronously from the EVM precompile), extracts the returned token page via the JSON precompile, and continues until the wasmd query returns an empty list. There is no cap on the number of pages processed, so the total gas consumed by `balanceOf()` scales linearly with `floor(ownerTokenCount / 1000)` cross-VM query round-trips, each of which is itself non-trivial (wasm contract execution, JSON parsing precompile call, address-translation precompile call).

Because `balanceOf()` is a standard, externally-callable part of the ERC721 interface that the pointer explicitly implements (`override` of `IERC721.balanceOf`), any external contract or off-chain caller that needs to read a balance for a given address is forced to pay for the full pagination sweep. An address that accumulates enough CW721 tokens (via minting if the CW721 contract allows public mint, or simply by receiving many token transfers) makes `balanceOf()` for that address exceed practical EVM gas limits, causing the call to revert with an out-of-gas condition inside a transaction that invokes it.

### Impact Explanation
Unlike the original HAL-07 report where `mint()`/`burn()`/`transfer()` themselves became unusable, in this Sei analog the pointer's core transfer path (`transferFrom`) relies on `ownerOf()`, not `balanceOf()`, so token movement is not directly blocked. However, `balanceOf()` is the canonical ERC721 balance-check function that third-party EVM contracts (marketplaces, lending/staking integrations, portfolio/indexer contracts) are expected to call. Once an address's CW721 token count grows large enough, any transaction that calls `balanceOf(that address)` on the pointer will run out of gas and revert, permanently breaking composability/integration functionality for that holder as long as the token count remains large — a denial-of-service on a core, standardized entry point of the pointer contract that any unprivileged CosmWasm/EVM user can trigger by growing their own (or a target's) token holdings.

### Likelihood Explanation
Likelihood is high for triggering the condition (any user can mint/acquire large numbers of NFTs in a CW721 collection they control or that has open minting, at the cost of ordinary transaction fees), though the severity is bounded by the fact that the pointer's transfer/approve paths do not depend on `balanceOf()`. The bug is directly reachable by an unprivileged CW721 minter/holder with no special permissions, matching the "contract deployer / CosmWasm user / pointer user" reachable-actor requirement.

### Recommendation
Avoid unbounded iteration in `balanceOf()`. Either:
- Cap the number of pages iterated (e.g., document/limit `balanceOf()` to a bounded number of query rounds and revert or return early rather than looping indefinitely), or
- Rely on maintaining an explicit counter via events/side storage rather than re-enumerating tokens with pagination on every call, or
- Charge/require the caller to pass an expected upper bound and fail fast, avoiding always paying for a full sweep.

### Proof of Concept
1. Deploy/point a `CW721ERC721Pointer` at a CW721 contract with public or attacker-controlled minting.
2. As an unprivileged attacker, mint (or otherwise acquire) tens of thousands of CW721 tokens to a single address.
3. Call `CW721ERC721Pointer.balanceOf(attackerAddress)` from another contract with a normal gas budget (as would happen in any integrating protocol).
4. Observe that the call requires as many `WasmdPrecompile.query()` round trips as `ceil(tokenCount / 1000)`, each with real wasm execution + JSON/Addr precompile overhead; past a certain token count the call runs out of gas and reverts, exactly as the existing Foundry test `testBalanceOf()` demonstrates the paging mechanics on a much smaller scale: [2](#0-1)

    function balanceOf(address owner_) public view override returns (uint256) {
        if (owner_ == address(0)) {
            revert ERC721InvalidOwner(address(0));
        }
        uint256 numTokens = 0;
        string memory startAfter;
        string memory qb = string.concat(
            string.concat("\"limit\":1000,\"owner\":\"", AddrPrecompile.getSeiAddr(owner_)),
            "\""
        );
        bytes32 terminator = keccak256("{\"tokens\":[]}");

        bytes[] memory tokens;
        uint256 tokensLength;
        string memory req = string.concat(string.concat("{\"tokens\":{", qb), "}}");
        bytes memory response = WasmdPrecompile.query(Cw721Address, bytes(req));
        while (keccak256(response) != terminator) {
            tokens = JsonPrecompile.extractAsBytesList(response, "tokens");
            tokensLength = tokens.length;
            numTokens += tokensLength;
            startAfter = string.concat(",\"start_after\":", string(tokens[tokensLength-1]));
            req = string.concat(
                string.concat("{\"tokens\":{", string.concat(qb, startAfter)),
                "}}"
            );
            response = WasmdPrecompile.query(Cw721Address, bytes(req));
        }
        return numTokens;
    }
