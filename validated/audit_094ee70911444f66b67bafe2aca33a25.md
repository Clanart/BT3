### Title
OP_RETURN data output excluded from fee/vsize estimation causes underpriced transactions - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
`SignableTransaction::new` appends the caller-supplied `data` OP_RETURN output to `tx_outs` (lines 194–202) *before* calling `calculate_weight_vbytes`, but passes only `payments` to the estimator (lines 204, 225–226). The OP_RETURN output's weight (up to ~80 bytes of data plus output overhead) is never counted, so `needed_fee` is systematically under-estimated for any transaction carrying a `data` payload. The signed transaction then pays a lower effective fee rate than the caller requested — an analog of the "misleading security UI" class: the value displayed/committed as the fee does not reflect the real transaction's requirements.

### Finding Description
In `networks/bitcoin/src/wallet/send.rs`, the flow is:

1. `tx_outs` is built from `payments`, then the OP_RETURN `data` output is pushed (lines 194–202).
2. `calculate_weight_vbytes(tx_ins.len(), payments, None)` is called (line 204) — it reconstructs a mock transaction from `payments` only; the already-appended data output is ignored.
3. `needed_fee = fee_per_vbyte * vbytes` uses this underestimated `vbytes` (line 206).
4. The change-output path (lines 224–235) repeats the same call with `Some(&change)`, still omitting `data`, and sets `needed_fee = fee_with_change`.
5. `sign`/`complete` then produce valid BIP-340 signatures over the real (larger) transaction via `taproot_key_spend_signature_hash` (lines 385–390), so the underpriced transaction is broadcastable as-is.

The minimum-fee check at line 211 uses the same underestimated `vbytes`, so a transaction that is actually below `DEFAULT_MIN_RELAY_TX_FEE` per-vbyte can pass the check.

### Impact Explanation
Any `data`-bearing transaction produced through this API has an effective fee rate strictly below the `fee_per_vbyte` requested — including below the network's minimum relay fee — while `needed_fee()` reports the intended amount was budgeted. Such transactions are dropped from mempools or linger unconfirmed, leaving the multisig's funds temporarily unspendable (the inputs remain locked to an unconfirming tx) and requiring fee-bumping/re-signing intervention. In Serai's usage, `data` carries protocol payloads (e.g., instruction data embedded as OP_RETURN), so attacker-controlled or protocol-driven `data` directly inflates the missing weight — up to ~95+ bytes (~24 vbytes) of uncounted output per transaction. Integrity impact on fund availability with a reachable path matches the Medium class of the source advisory.

### Likelihood Explanation
Deterministic whenever `data: Some(_)` is passed — no adversarial precondition beyond a payload-bearing transaction. The error is bounded (~24 vbytes), so transactions with comfortable fee margins still confirm; impact materializes when the requested rate is near the relay/confirmation floor, which is precisely when accurate accounting matters.

### Recommendation
Include the OP_RETURN output in `calculate_weight_vbytes`, e.g., by passing a combined outputs slice (`payments` + optional data output) or building the mock `tx.output` from `tx_outs` after it is fully assembled. Recompute `needed_fee` after the data output is known, and perform the `TooLowFee` and `NotEnoughFunds` checks against the corrected vbytes.

### Proof of Concept
```rust
// Construct two transactions differing only in `data`:
let tx_no_data = SignableTransaction::new(inputs.clone(), &payments, change.clone(), None, FEE).unwrap();
let tx_data    = SignableTransaction::new(inputs, &payments, change, Some(vec![0u8; 80]), FEE).unwrap();

// The data-carrying tx is strictly larger, yet needed_fee only scales with payments:
assert!(tx_data.transaction().vsize() > tx_no_data.transaction().vsize());
// tx_data.needed_fee() - tx_no_data.needed_fee() == 0,
// i.e. the ~80-byte OP_RETURN output was never priced in.
// If FEE is at the minimum relay threshold, the check at send.rs:211 passes
// while the real transaction relays below the minimum fee rate.
```
