### Title
Attacker-constructed payout tx with arbitrary OP_RETURN causes unfunded operator reimbursement - ([File: core/src/database/verifier.rs -> get_payout_info_from_move_txid])

### Summary
The `withdrawals.payout_payer_operator_xonly_pk` value returned by `get_payout_info_from_move_txid` is populated purely from the OP_RETURN of whatever transaction is observed on-chain spending the withdrawal UTXO, with no check that the operator named in that OP_RETURN actually supplied the funds paid to the withdrawer. Because the user's payout signature uses `SIGHASH_SINGLE|ANYONECANPAY` on input 0/output 0 only, an unprivileged attacker can build and broadcast their own payout transaction (adding their own funding inputs and change, and any OP_RETURN xonly-pubkey of their choosing) that reuses that signature, causing an arbitrary operator to be credited as the payer for a withdrawal it never funded.

### Finding Description
Claimed binding: `get_payout_info_from_move_txid(move_txid).0 (operator_xonly_pk) == the operator whose BTC actually paid the withdrawer's output0`.

Trace:
- `withdraw`/`internal_withdraw` RPC (`core/src/rpc/operator.rs`) accepts `input_signature`, `input_outpoint`, `output_script_pubkey`, `output_amount` from an unauthenticated (or address-verified but still externally-supplied) caller, and `parser::operator::parse_withdrawal_sig_params` only enforces that the sighash type is `SinglePlusAnyoneCanPay` [1](#0-0) .
- `create_payout_txhandler` builds input 0 as a key-spend using this signature, output 0 as the user payout, and appends an OP_RETURN with an `operator_xonly_pk` chosen by whoever constructs the transaction [2](#0-1) . `SIGHASH_SINGLE|ANYONECANPAY` only commits to input 0 and output 0 (`bitcoin::sighash::Prevouts::One`) [3](#0-2) , so the user's signature remains valid in **any** transaction that keeps input 0 and output 0 unchanged, regardless of what other inputs/outputs (including the OP_RETURN operator pubkey) are added.
- Any funding inputs added to cover output 0 (e.g., via `fund_raw_transaction`/`create_funded_psbt`) are signed independently by whoever supplies them [4](#0-3) ; nothing forces the party signing those funding inputs to be the operator named in the OP_RETURN.
- On confirmation, `update_finalized_payouts` finds the spending tx of the withdrawal UTXO purely via `get_payout_txs_for_withdrawal_utxos` (a join on the spent-UTXO index, matching *any* transaction that spends the recorded `withdrawal_utxo_txid`/`vout`), then blindly parses the OP_RETURN of that transaction to obtain `operator_xonly_pk`, with no verification that the OP_RETURN owner supplied the transaction's funding inputs [5](#0-4) [6](#0-5) .
- `get_payout_info_from_move_txid` then surfaces this unverified `payout_payer_operator_xonly_pk` value as ground truth to `Verifier::is_kickoff_malicious` (which only checks that the OP_RETURN pk equals the kickoff sender's own declared pk — a tautology if the attacker names that same operator) [7](#0-6) , and to `Operator::send_asserts`/`PayoutCheckerTask`, which trusts it to trigger the reimbursement flow for whichever operator's key is in the OP_RETURN [8](#0-7) [9](#0-8) .

Because none of these code paths cross-check "who paid" against "who is named in OP_RETURN," an attacker who is the withdrawing user (and thus holds the reusable `SinglePlusAnyoneCanPay` signature over input 0/output 0) can independently construct a full payout transaction — funding output 0 with their own BTC via additional inputs they control and sign — and write ANY operator's x-only pubkey into the OP_RETURN. Once mined, `get_payout_info_from_move_txid` will report that fabricated operator as the payer, even though that operator never signed, broadcast, or funded anything.

### Impact Explanation
This directly matches the Critical category "an operator reimbursed for a payout it never funded." Once `update_finalized_payouts` records the fabricated operator's xonly pk, that operator's own automation (`PayoutCheckerTask` → `handle_finalized_payout` → kickoff/reimbursement transaction graph) will autonomously believe it fronted the withdrawal and proceed to claim reimbursement from the bridge's move-to-vault funds for a payout it never made. This is repeatable for every withdrawal the attacker (as a Citrea `withdraw` caller) initiates, and can be aimed at any operator whose x-only pubkey is public. It results in BTC/collateral value being paid out of the vault/reimbursement flow to a party that performed no service, which either directly harms that operator's collateral accounting or improperly credits it — both explicitly listed Critical impacts.

### Likelihood Explanation
Preconditions: an attacker must be the withdrawing party on Citrea (fully within the described unprivileged capabilities — the attacker can call `withdraw` on the Citrea Bridge contract and choose the withdrawal UTXO bytes, signature, and sighash flag), and must fund output 0 with their own BTC (cost ≈ withdrawal amount + fees, largely recoverable since output 0 pays the attacker's own chosen destination). No collusion, key compromise, or majority hashrate is required — only standard Bitcoin transaction construction and broadcast, which is explicitly within the attacker's granted capabilities. This is straightforward and repeatable across all withdrawals/operators.

### Recommendation
`update_finalized_payouts` (and by extension `get_payout_info_from_move_txid`) should not trust the OP_RETURN operator pubkey as sufficient proof of who funded the payout. Instead, bind the OP_RETURN claim to an authenticated signature from the named operator over the payout transaction (e.g., require the operator to sign the additional funding inputs and include a check that at least one of those inputs is controlled by the OP_RETURN-named operator's registered key), or require the operator's xonly pubkey commitment to be authenticated as part of the presigned protocol flow rather than being freely writable by whoever broadcasts the spending transaction.

#[allow(clippy::result_large_err)]
pub fn parse_withdrawal_sig_params(
    params: WithdrawParams,
) -> Result<(u32, taproot::Signature, OutPoint, ScriptBuf, Amount), Status> {
    let mut input_signature =
        taproot::Signature::from_slice(&params.input_signature).map_err(|e| {
            Status::invalid_argument(format!("Can't convert input to taproot Signature - {e}"))
        })?;

    // If the Taproot sighash type is Default (no explicit type attached; i.e. a 64-byte
    // signature without a sighash flag), normalize it to SinglePlusAnyoneCanPay.
    // Prior to v0.5 this was Clementine's implicit behavior; we retain it here for
    // backwards compatibility when a 64-byte signature is provided.
    if input_signature.sighash_type == TapSighashType::Default {
        tracing::warn!(
            "Input signature for withdrawal {} has sighash type default, setting to SinglePlusAnyoneCanPay", params.withdrawal_id,
        );
        input_signature.sighash_type = TapSighashType::SinglePlusAnyoneCanPay;
    }

    // enforce sighash type here
    if input_signature.sighash_type != TapSighashType::SinglePlusAnyoneCanPay {
        return Err(Status::invalid_argument(format!(
            "Input signature has wrong sighash type, SinglePlusAnyoneCanPay expected, got {}",
            input_signature.sighash_type
        )));
    }

    let input_outpoint: OutPoint = params
        .input_outpoint
        .ok_or_else(error::input_ended_prematurely)?
        .try_into()?;

    let users_intent_script_pubkey = ScriptBuf::from_bytes(params.output_script_pubkey);

    Ok((
        params.withdrawal_id,
        input_signature,
        input_outpoint,
        users_intent_script_pubkey,
        Amount::from_sat(params.output_amount),
    ))
}

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

                            "Failed to get address from script for output of tx with txid {} for script: {}",

                        None
                    }
                }
            })
            .collect::<Vec<_>>();

                            None
                        } else {
                            Some(inp.segwit_weight().to_wu())
                        },
                    })
                    .collect::<Vec<_>>(),
                outputs,
                None,
                Some(create_psbt_opts),
                None,
            )
            .await
            .map_err(|e| eyre!(e).into())

                ON bsu.txid = w.withdrawal_utxo_txid
                AND bsu.vout = w.withdrawal_utxo_vout

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_all)?;

        results
            .into_iter()
            .map(|(idx, txid)| {
                Ok((
                    u32::try_from(idx).wrap_err("Failed to convert withdrawal index to u32")?,
                    txid.0,
                ))
            })
            .collect()

        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
            ));
