## Title
Unauthenticated `(chain, app)` bandwidth key lets any purchaser evict and destroy another app's paid-for bandwidth allowance - (File: `modules/pallets/bandwidth/src/lib.rs`, `evm/src/apps/BandwidthManager.sol`)

### Summary
`BandwidthManager.purchase()` on EVM lets **any** caller credit bandwidth to an arbitrary `(chain, app)` pair by simply naming it in the call arguments, with no check that the caller owns or controls that app. [1](#0-0)  On Hyperbridge, `pallet-bandwidth` stores each app's allowance as a bounded FIFO list capped at 1024 entries; when the cap is hit, a new purchase unconditionally evicts the **oldest** entry regardless of its remaining value. [2](#0-1) [3](#0-2)  Because the "name" that gates this shared FIFO resource — `(app_chain, app)` — is fully attacker-suppliable and never validated against the actual payer/owner, an attacker can flood a victim's bucket with cheap purchases to force-evict the victim's real, higher-value subscription, permanently destroying bandwidth the victim already paid for. This mirrors the Salty bug class: a shared resource is keyed by attacker-controllable identifying data that excludes any ownership/ordering-by-value binding, letting an unprivileged party squat/exhaust the slot and destroy a legitimate holder's entry.

### Finding Description
`purchase()` takes `app` and `chain` as raw calldata parameters chosen entirely by `msg.sender`, with no restriction tying them to the caller's own identity: [4](#0-3) 

On the pallet side, `on_accept` only checks that the *message* came from the registered `BandwidthManager` contract for `request.source` (`is_purchase_message` / `BandwidthManager::<T>::get(&request.source)`), not that the app named in the payload belongs to whoever paid: [5](#0-4) 

Every successful purchase appends to `Allowance<T>` keyed by `(app_chain, AppKey)`: [6](#0-5) 

`push_subscription` enforces a hard cap of `MAX_SUBSCRIPTIONS = 1024` and, once full, evicts strictly by FIFO position (`list.remove(0)`) irrespective of the evicted entry's `remaining_bytes`, `expires_at`, or how much was paid for it: [7](#0-6) 

This is the direct analog of the Salty finding: the "ballot name" there was under-specified (missing key parameters), letting an attacker squat a shared slot to block/replace legitimate entries. Here, the shared slot identifier `(app_chain, app)` is fully public and un-owned — anyone can write into someone else's bucket — and the eviction policy has no value-awareness, so an attacker can cheaply overwrite/evict a victim's expensive, long-lived subscription with worthless throwaway ones.

### Impact Explanation
This is a fund-loss / logic-attack finding, not a generic DoS: an app that has already paid (potentially the $1000/8MB tier) for bandwidth can have that paid allowance permanently destroyed by a third party who never interacted with the victim, without the victim's consent and without any compensation. This falls squarely under "stealing or loss of funds" / "logic attacks" in the bounty's impact gate — it needs no malicious relayer, prover, admin, or governance actor: the entrypoint (`BandwidthManager.purchase()`) is public and unprivileged, and the pallet's acceptance path treats the message as fully authorized once it validates only that it arrived from the registered manager contract.

### Likelihood Explanation
The precondition is simply knowing the victim's `(chain, app)` pair, which is public (emitted in `BandwidthPurchased` events and readable via `allowances()`/`remaining()`). [8](#0-7)  The attack cost scales with `1024 × cheapest tier price` to fully evict from an empty state, which can be substantial, but if a victim's bucket already holds only a handful of entries (the common case for a newly-onboarded app), the attacker only needs to fill the remaining slack plus one more purchase to evict the targeted entry — a bounded, attacker-controlled cost against an arbitrarily large victim loss (e.g., destroying an 8MB/$1000 subscription with a stream of $50 purchases). The attack is fully repeatable and requires no privileged role.

### Recommendation
- Bind the FIFO/eviction ordering to remaining value (e.g., evict the subscription with the least remaining `remaining_bytes × time-to-expiry`, or refuse eviction of `Subscription`s whose value exceeds the incoming purchase) instead of naive insertion order.
- Require `BandwidthManager.purchase()` (or the pallet) to authenticate that the caller is authorized for `app` (e.g., only `app`'s own EVM address, or an explicit sponsor allowlist) before it can mutate that app's `Allowance` bucket, especially for third-chain "sponsorship" purchases.
- Consider separating "self bucket" writes from "sponsor for another chain/app" writes, with stricter caps/permissions on the latter, and/or refunding/pro-rating evicted subscriptions rather than silently discarding remaining bytes.

### Proof of Concept
1. Victim buys `TierFour` (8MB) bandwidth for their app via `BandwidthManager.purchase(appVictim, TierFour, 12, "EVM-8453")`, creating one `Subscription` entry in `Allowance[EVM-8453][appVictim]`.
2. Attacker (arbitrary account, no relationship to victim) reads the `BandwidthPurchased` event or calls `allowances(app_chain, app)` to learn `appVictim`/`chain` and confirm the bucket currently holds `N < 1024` entries.
3. Attacker calls `BandwidthManager.purchase(appVictim, TierOne, 1, "EVM-8453")` exactly `1024 - N` times, filling `Allowance[EVM-8453][appVictim]` to the 1024 cap — each call is accepted because `on_accept` only checks `request.from == registered manager`, never that the caller owns `appVictim`. [5](#0-4) 
4. Attacker sends one more cheap `TierOne` purchase. `push_subscription` sees the list at `MAX_SUBSCRIPTIONS`, calls `list.remove(0)` and emits `SubscriptionEvicted`, permanently discarding the victim's original 8MB `TierFour` subscription and its `remaining_bytes`, regardless of value. [9](#0-8) 
5. Victim's paid-for bandwidth is gone; they must re-purchase, while the attacker only spent cheap `TierOne` fees — a griefing/fund-loss primitive reachable from an unprivileged public entrypoint.

    function purchase(bytes calldata app, uint256 tier, uint256 months, bytes calldata chain)
        external
        returns (bytes32 commitment)
    {
        if (app.length == 0 || chain.length == 0 || months == 0) revert InvalidPurchase();
        uint256 price18d = tierPrice[tier];
        if (price18d == 0) revert UnknownTier();

        uint256 total18d = price18d * months;
        address feeToken = IDispatcher(_host).feeToken();
        uint8 dec = IERC20Metadata(feeToken).decimals();
        uint256 scale = 10 ** (18 - dec);
        if (total18d % scale != 0) revert PriceNotRepresentable();
        uint256 amount = total18d / scale;

        IERC20(feeToken).safeTransferFrom(msg.sender, address(this), amount);

        BandwidthPurchaseMsg memory body = BandwidthPurchaseMsg({
            app: app,
            tier: tier,
            months: months,
            chain: chain
        });

        commitment = IDispatcher(_host).dispatch(
            DispatchPost({
                dest: IDispatcher(_host).hyperbridge(),
                to: PALLET_BANDWIDTH_MODULE_ID,
                body: abi.encode(body),
                timeout: 0,
                fee: 0,
                payer: address(this)
            })
        );

		/// (= FIFO drain) order. Read-only snapshot.
		pub fn allowances(app_chain: &StateMachine, app: &[u8]) -> Vec<Subscription> {
			let key = AppKey::truncate_from(app.to_vec());
			let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();
			Allowance::<T>::get(app_chain, &key)
				.into_iter()
				.filter(|s| s.expires_at > now)
				.collect()
		}

		/// Append a fresh subscription with a fixed expiry. If the list
		/// is already at `MaxSubscriptions`, evict the oldest entry and
		/// emit [`Event::SubscriptionEvicted`] so the lost bytes are
		/// auditable. Returns the new subscription's `expires_at`.
		fn push_subscription(
			app_chain: &StateMachine,
			app: &AppKey,
			tier: TierIndex,
			bytes: BandwidthBytes,
			duration_secs: u64,
		) -> u64 {
			let now = <T as pallet_ismp::Config>::TimestampProvider::now().as_secs();
			let expires_at = now.saturating_add(duration_secs);
			let new_sub =
				Subscription { tier, remaining_bytes: bytes, expires_at, purchased_at: now };

			let evicted = Allowance::<T>::mutate(app_chain, app, |list| {
				let evicted = if list.len() == MAX_SUBSCRIPTIONS as usize {
					Some(list.remove(0))
				} else {
					None
				};
				// Capacity is now guaranteed; try_push can't fail.
				let _ = list.try_push(new_sub);
				evicted
			});

			if let Some(old) = evicted {
				Self::deposit_event(Event::SubscriptionEvicted {
					app_chain: *app_chain,
					app: app.clone(),
					tier: old.tier,
					lost_bytes: old.remaining_bytes,
				});
			}

			expires_at
		}
