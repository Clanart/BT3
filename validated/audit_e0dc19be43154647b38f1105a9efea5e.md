### Title
Global gasless bundle-tx queue admission has no per-value floor, enabling a single unprivileged sender to exhaust `MaxBundleTxsInQueue` and DoS legitimate gasless users - (File: kaiax/gasless/impl/tx_pool.go)

### Summary
The `delegation_service` report describes a hard, global cap on a resource (`MAX_NUMBER_OF_DELEGATIONS`) that any unprivileged actor can fill with low-value/dust entries because there is no lifetime minimum contribution requirement, thereby starving legitimate participants. The Kaia gasless module has an analogous structure: `GaslessModule.PreAddTx` admits "bundle" (approve/swap) transactions into a single, chain-wide `knownTxs` queue guarded only by a global counter `numQueue()` compared against `MaxBundleTxsInQueue` [1](#0-0) . There is no floor on the swap/approve amount, no per-sender share of the queue, and no meaningful-value requirement checked at admission time — value/balance checks (`checkBalanceForApprove`/`checkBalanceForSwap`) are only reachable after a tx is already recognized as a bundle tx and are not gates on whether the global slot is consumed [2](#0-1) .

### Finding Description
`PreAddTx` is invoked for every transaction entering the pool. If the incoming transaction is recognized as a gasless bundle transaction (`IsBundleTx`, i.e. matches the approve/swap selectors for the configured router/tokens), it is unconditionally counted against the single global `MaxBundleTxsInQueue` limit and rejected only once that global cap is reached: [3](#0-2) 

The default value of this global cap is small and fixed (200), independent of the number of distinct senders: [4](#0-3) [5](#0-4) 

Unlike the auction module's `bid_pool`, which requires a co-signature from the trusted `Auctioneer` before any bid occupies a slot (making it unreachable by an unprivileged actor alone) [6](#0-5) , the gasless bundle queue has no analogous gatekeeper: any account that can produce a syntactically valid approve/swap call targeting the configured token/router can occupy a queue slot, since the admission check in `PreAddTx` does not enforce a minimum swap amount, minimum token balance, or per-sender quota — those checks (`checkBalanceForApprove`, `checkBalanceForSwap`) are separate, deferred code paths, not conditions of the slot-consuming admission itself [7](#0-6) .

This mirrors the reported bug class precisely: a hard cap on a shared list (`MAX_NUMBER_OF_DELEGATIONS` ↔ `MaxBundleTxsInQueue`) that can be filled by an unprivileged party with minimal/dust-value entries because no lifetime-meaningful-value floor is enforced at admission.

### Impact Explanation
An attacker who repeatedly submits dust-value approve/swap "bundle" transactions (from freely creatable accounts, requiring only minimal token balance/allowance for the target token, since amounts as low as `1` satisfy the router-facing checks that are deferred anyway) can occupy all `MaxBundleTxsInQueue` slots. Once full, `PreAddTx` returns `ErrBundleTxQueueFull` for every subsequent bundle transaction [8](#0-7) , denying legitimate users the ability to use the gasless swap feature — a availability/service-denial impact on a public-RPC-reachable protocol feature (gasless transactions), consistent with the "Medium/High" severity bracket for this class of finding (no supply inflation or fund theft, but concrete denial of legitimate protocol functionality to an unprivileged, valid actor class).

### Likelihood Explanation
Reachable purely via public RPC (`eth_sendRawTransaction`/`kaia_sendRawTransaction`) by any unprivileged sender who can construct a transaction that decodes as an approve/swap call against the configured gasless router/token. No special role, node, or signature (unlike the auction module's mandatory `Auctioneer` co-signature) is required to occupy a slot. The attack is cheap to repeat (dust amounts) and does not require the swap to ever execute — it only needs to pass the txpool's own generic validation (nonce/signature/gas) to be queued and counted in `numQueue()`. This makes exploitation practical for any funded, unprivileged account, similar to the original delegator-list-filling scenario.

### Recommendation
Apply the same remediation principle recommended in the report: impose a meaningful floor on what is admitted to a shared, capacity-limited structure. Concretely:
- Enforce a minimum swap/approve amount (or minimum resulting economic value) as a precondition for a transaction to be counted toward `MaxBundleTxsInQueue`, mirroring the suggested "minimum delegation amount for the lifetime of the funds."
- Alternatively/additionally, enforce a per-sender share or rate limit within the global bundle-tx queue (analogous to `NonExecSlotsAccount` used elsewhere in the classic tx pool) so no single set of addresses can exhaust the entire global capacity [9](#0-8) .
- Move balance/amount validation (`checkBalanceForApprove`/`checkBalanceForSwap`) earlier, into `PreAddTx`, so dust or unfunded bundle transactions cannot consume a global queue slot in the first place.

### Proof of Concept
1. Configure/observe default `gasless.max-bundle-txs-in-queue = 200` [10](#0-9) .
2. From N ≤ 200 distinct funded accounts, craft and submit valid `approve`/`swap` calldata against the configured gasless router/token with minimal (dust) `amountIn`/`amountOut` values, each as ordinary transactions via public RPC.
3. Each transaction is accepted by `PreAddTx` and added to `g.knownTxs` with `TxStatusQueue` as long as `numQueue() < MaxBundleTxsInQueue` [3](#0-2) , with no check on the meaningfulness of the swap amount at this stage.
4. Once 200 slots are filled, any legitimate user's genuine gasless bundle transaction is rejected with `ErrBundleTxQueueFull`, denying them the gasless feature until the attacker's transactions time out (`QueueTimeout`) — which the attacker can perpetually renew by resubmitting new dust transactions from a rotating set of addresses.

Note: I was not able to fully trace, within the available iterations, the exact point at which `checkBalanceForApprove`/`checkBalanceForSwap` are invoked relative to pool admission versus promotion (e.g., whether `GetCheckBalance` is called synchronously during `add()`/`validateTx` for all txs or only during promotion of already-queued bundle txs). This affects whether the attacker needs any real token balance/allowance to occupy a queue slot at all, or only to eventually be promoted. This should be verified in the full source before finalizing severity/exploit cost estimates.

func (g *GaslessModule) PreAddTx(tx *types.Transaction, local bool) error {
	g.knownTxsMu.RLock()
	defer g.knownTxsMu.RUnlock()

	if knownTx, ok := g.knownTxs.get(tx.Hash()); ok && knownTx.elapsedPromotedOrAddedTime() < KnownTxTimeout {
		return ErrUnableToAddKnownBundleTx
	}

	if g.IsBundleTx(tx) {
		if uint(g.knownTxs.numQueue()) >= g.GetMaxBundleTxsInQueue() {
			return ErrBundleTxQueueFull
		}
		g.knownTxs.add(tx, TxStatusQueue)
	}
	return nil
}

func (g *GaslessModule) GetCheckBalance() func(tx *types.Transaction) error {
	return func(tx *types.Transaction) error {
		if approveArgs, ok := decodeApproveTx(tx, g.signer); ok {
			return g.checkBalanceForApprove(approveArgs)
		}
		if swapArgs, ok := decodeSwapTx(tx, g.signer); ok {
			return g.checkBalanceForSwap(swapArgs, tx.Nonce())
		}
		return errors.New("not a gasless transaction") // should not happen because IsModuleTx is called before GetCheckBalance
	}
}

func (g *GaslessModule) checkBalanceForApprove(approveArgs *ApproveArgs) error {
	token := approveArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(approveArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {
		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// tx.token.balanceOf(sender) > 0
		tokenBalance, err := tokenContract.BalanceOf(nil, approveArgs.Sender)
		if err != nil {
			return err
		}
		if tokenBalance.Sign() <= 0 {
			return fmt.Errorf("insufficient sender token balance: token=%s, have=%s, want=nonzero", token.Hex(), tokenBalance.String())
		}
	}
	return nil
}

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {

		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// If SwapTx.nonce is the sender's next nonce, then there is no room for ApproveTx proceeding SwapTx.
		senderNonce := g.getCurrentStateNonce(swapArgs.Sender)
		noApproveTxPreceeds := swapNonce == senderNonce
		if noApproveTxPreceeds {
			// tx.token.allowance(sender, router) >= tx.amountIn
			approval, err := tokenContract.Allowance(nil, swapArgs.Sender, swapRouter)
			if err != nil {
				return err
			}
			if approval.Cmp(swapArgs.AmountIn) < 0 {
				return fmt.Errorf("insufficient approval: approval=%s, want=%s", approval.String(), swapArgs.AmountIn.String())
			}
		}

		// tx.token.balanceOf(sender) >= tx.amountIn
		balance, err := tokenContract.BalanceOf(nil, swapArgs.Sender)
		if err != nil {
			return err
		}
		if balance.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("insufficient balance: balance=%s, want=%s", balance.String(), swapArgs.AmountIn.String())
		}
	}

	// tx.deadline >= currentTimestamp
	deadline := swapArgs.Deadline
	if deadline.Cmp(g.Chain.CurrentBlock().Time()) < 0 {
		return fmt.Errorf("insufficient deadline: deadline=%s, want=%s", deadline.String(), g.Chain.CurrentBlock().Time().String())
	}

	return nil
}

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}
