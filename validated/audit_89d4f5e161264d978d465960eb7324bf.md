## Analysis Result

### Title
Missing timestamp expiration check in App Proxy signature verification allows indefinite replay of signed proxy requests - (File: `lib/shopify_app/controller_concerns/app_proxy_verification.rb`)

### Summary
`ShopifyApp::AppProxyVerification#query_string_valid?` verifies only that the HMAC signature over the query string matches, but never validates the `timestamp` parameter that Shopify includes in every proxied request against the current time. This mirrors the reported bug class: a signed structure/request is accepted forever because no deadline/expiration is enforced on it, so anyone who captures a validly-signed app-proxy request URL can replay it indefinitely.

### Finding Description
The `verify_proxy_request` before_action calls `query_string_valid?`, which recomputes the HMAC over all query parameters (including `timestamp`) and compares it to the supplied `signature` using `ActiveSupport::SecurityUtils.secure_compare`. [1](#0-0) 

The `timestamp` value is only used as one of the signed inputs (to make the signature deterministic) but its value is never compared against `Time.now` or any expiry window: [2](#0-1) 

As a result, once a legitimately signed app-proxy query string is generated by Shopify (e.g. observed in a browser network tab, server log, referrer header, or any place a signed proxy URL leaks), that exact query string+signature pair remains valid forever — there is no mechanism analogous to a "deadline" on the signed payload, just like the credit structure in the referenced report which lacked an expiration timestamp despite carrying signed, security-relevant data.

This is directly confirmed by the test suite, which shows that requests signed with an old, arbitrary `timestamp=1466106083` (year 2016) are still accepted as valid years later: [3](#0-2) 

### Impact Explanation
Any captured or leaked app-proxy signed URL (containing `shop`, `path_prefix`, `timestamp`, `signature`, etc.) can be replayed by an unrelated, unprivileged party at any point in the future to hit app-proxy endpoints as if it were a legitimate, freshly-proxied Shopify storefront request. Because `AppProxyVerification` also skips CSRF protection (`skip_before_action :verify_authenticity_token`), this replay is not blocked by any other layer. [4](#0-3) 

Depending on what the app-proxy controller does with the trusted `shop` parameter from that query string (e.g., look up shop-specific data, perform shop-scoped actions), this enables cross-shop/forged-request access using stale signed parameters, since the app trusts any request that passes `query_string_valid?` regardless of age.

### Likelihood Explanation
Exploitation requires an attacker to obtain one previously valid signed app-proxy query string (via logs, browser history, referrer leakage, caching proxies, or shared links), which is a realistic scenario for storefront-facing app-proxy endpoints. No cryptographic secret needs to be compromised — only a single historical valid request needs to be observed.

### Recommendation
Add a bounded time-window check on the `timestamp` query parameter (e.g., reject requests where `Time.now.to_i - timestamp.to_i` exceeds a small threshold such as 60–300 seconds) inside `query_string_valid?`, in addition to the existing signature verification, before permitting the request through.

### Proof of Concept
1. Capture a legitimately-issued app-proxy request URL, e.g.
   `GET /app_proxy/basic?shop=some-random-store.myshopify.com&path_prefix=/apps/my-app&timestamp=1466106083&signature=f5cd7233558b1c50102a6f33c0b63ad1e1072a2fc126cb58d4500f75223cefcd`
2. Replay this exact URL at any arbitrary later time (days, months, years later).
3. `query_string_valid?` recomputes the same HMAC over the same parameters and returns `true` because `timestamp` is never checked against the current time, so `verify_proxy_request` allows the request through unconditionally. [3](#0-2)

```ruby
    def verify_proxy_request
      head(:forbidden) unless query_string_valid?(request.query_string)

    private

    def query_string_valid?(query_string)
      query_hash = Rack::Utils.parse_query(query_string)

      signature = query_hash.delete("signature")
      return false if signature.nil?

      ActiveSupport::SecurityUtils.secure_compare(
        calculated_signature(query_hash),
        signature,
      )
    end
```
