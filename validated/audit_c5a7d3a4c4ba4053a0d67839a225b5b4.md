### Title
Attacker-Controlled `WWW-Authenticate` Header Misclassifies a Malicious Git Host as "GitHub Enterprise", Triggering a Trusted Sign-In Prompt for an Untrusted Server - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
`getEndpointKind` classifies a git remote's credential request into `'github.com' | 'ghe.com' | 'enterprise' | 'generic'` and that classification decides which credential path Desktop takes (internal GitHub account lookup/sign-in vs. generic username/password storage). For hosts that aren't `github.com`/`*.ghe.com`, the classifier falls back to trusting a `realm="GitHub"` substring inside the `WWW-Authenticate` header that the remote git server itself returned and that git forwards verbatim to the credential helper as `wwwauth[...]` fields. This is the same bug class as the reported "incorrect namespace" issue: a value (the credential request) is routed into the wrong classification/namespace because the classifier trusts attacker-supplied input instead of verifying the actual identity of the resource.

### Finding Description
In `getEndpointKind`, after the hostname-based checks for `github.com`/`ghe.com` fail, the code inspects `wwwauth[...]` header values that were included in the credential map by git (sourced directly from the HTTP response of whatever server the user is talking to): [1](#0-0) 

If the value contains `realm="GitHub"`, the function returns `'enterprise'` — meaning any attacker-controlled HTTPS git server can force this classification simply by sending that header string, regardless of the real hostname. Since this classification input is attacker-controlled (it is literally an HTTP response header from the remote the user is fetching/cloning/pushing to), the "correct namespace" (generic vs. GitHub) is trivially forgeable.

This misclassification feeds into `getCredential`: [2](#0-1) 

When `endpointKind !== 'generic'` and no existing account matches the attacker's `apiEndpoint`, Desktop calls `ui.promptForGitHubSignIn(endpoint)` — a first-party, trusted-looking "Sign in to GitHub" flow — but pointed at the attacker-controlled `endpoint` URL, not a validated GitHub/GHE server.

### Impact Explanation
A user who simply clones, fetches, or pushes to a malicious/compromised git remote (or is MITM'd on a proxy) can be shown Desktop's own trusted "Sign in to GitHub Enterprise" UI for a server that is not GitHub at all. Whatever credential/PAT/OAuth flow the user completes there is validated against and/or sent to the attacker's endpoint, exfiltrating the user's real GitHub credential/token. This satisfies the "unauthorized OAuth/account binding" and "credential/token exfiltration" impact classes: the attacker fully controls the trigger (an HTTP header on their own server) and the target (their own endpoint URL), and the user takes no unnatural steps beyond a normal git operation against the attacker's repository.

### Likelihood Explanation
Likelihood is high for any workflow where Desktop performs the underlying git operation against attacker-influenced infrastructure (malicious remote URL, compromised/MITM proxy, or an untrusted host added as a "generic" remote). No existing guard validates that the host actually is GitHub-branded before honoring the `realm="GitHub"` self-declaration; the comment in the code explicitly documents this as an intentional "happy-path" shortcut rather than a verified identity check.

### Recommendation
Do not let a self-reported `WWW-Authenticate` realm string alone elevate an arbitrary host into the `enterprise`/GitHub credential path. At minimum, corroborate the `wwwauth` hint with an actual API probe (the existing `isGitHubHost(endpoint)` call already performed later in the function) before triggering `promptForGitHubSignIn`, or require confirmation from the user showing the real hostname before proceeding with a GitHub sign-in flow for an unknown endpoint.

### Proof of Concept
1. Host a git-over-HTTPS server (or MITM proxy) at `https://evil.example.com/repo.git`.
2. Configure it to answer unauthenticated requests with `WWW-Authenticate: Basic realm="GitHub"`.
3. In GitHub Desktop, add `https://evil.example.com/repo.git` as a remote and perform a `fetch`.
4. Git invokes Desktop's credential helper (`createCredentialHelperTrampolineHandler`) with the `wwwauth[...]` field containing the forged realm.
5. `getEndpointKind` returns `'enterprise'`; since no account exists for `evil.example.com`, `getCredential` calls `ui.promptForGitHubSignIn('https://evil.example.com/repo.git')`, presenting a trusted-looking GitHub sign-in dialog for the attacker's host. [3](#0-2)

/** Implementation of the 'get' git credential helper command */
async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
