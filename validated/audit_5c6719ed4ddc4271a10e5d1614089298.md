## Title
Spoofable `WWW-Authenticate` realm from a malicious git remote forces Desktop's credential helper to trust an attacker host as "GitHub Enterprise" and launch an OAuth/enterprise sign-in flow against it - (`app/src/lib/trampoline/trampoline-credential-helper.ts`)

### Summary
This mirrors the Quill bug class: a single, easily-spoofed "proxy signal" is used in place of authoritative verification, and the resulting *classification* (not a price, here an "is this host GitHub?" decision) drives a security-sensitive action — initiating GitHub sign-in / OAuth against a host that was never actually verified to be GitHub.

### Finding Description
`getEndpointKind()` decides whether a git credential request's host should be treated as `'github.com'`, `'enterprise'`, or `'generic'`. Aside from static allow-lists (`isDotCom`, `isGHE`) and a genuine network probe (`isGitHubHost`), it contains a "happy path" shortcut that trusts data supplied by the remote server itself: [1](#0-0) 

Any git server (or a MITM/malicious proxy sitting on the path to a configured remote) can respond to Git's auth challenge with a header such as `WWW-Authenticate: Basic realm="GitHub"`. Git forwards this header verbatim to Desktop's credential helper as a `wwwauth[...]` credential field, and Desktop unconditionally classifies that host as `'enterprise'` — a fully trusted category — without ever contacting the real endpoint or checking a certificate/hostname allow-list, unlike the `isGitHubHost()` fallback path a few lines below which does perform a real `fetch` and checks for the `x-github-request-id` response header.

That classification then drives `getCredential()`: [2](#0-1) 

Because the host has no matching account, and `endpointKind !== 'generic'`, Desktop calls `ui.promptForGitHubSignIn(endpoint)` instead of the generic-credential flow. That helper treats any non-`github.com` hostname as an Enterprise endpoint and drives the real sign-in store with the attacker's origin: [3](#0-2) 

`setEndpoint()` in the sign-in store then proceeds to build a GitHub Enterprise API URL from the attacker's host and offers the OAuth-in-browser flow (`shell.openExternal(getOAuthAuthorizationURL(endpoint, csrfToken))`), all under a Sign-In dialog UI that presents this as an ordinary "GitHub Enterprise" authentication: [4](#0-3) [5](#0-4) 

The corrupted value is the trust level (`endpointKind`) assigned to an arbitrary, attacker-controlled remote host: a value that should only ever be derived from an authoritative check (DNS/cert-pinned allow-list or the network probe `isGitHubHost`) is instead derived from unauthenticated response metadata the remote itself supplies.

### Impact Explanation
This routes a non-GitHub, attacker-controlled host into Desktop's "trusted GitHub/Enterprise" account-binding machinery. Because the sign-in flow shown to the user is presented identically to a real GitHub Enterprise sign-in (using the attacker's chosen host as the "enterprise instance"), a user who completes it believes they are authenticating to GitHub. This falls squarely into "unauthorized OAuth or account binding" against an attacker-controlled remote, one of the explicitly valid impact categories: the attacker only needs to control the git server/proxy for a remote the victim already has configured (e.g., a compromised self-hosted mirror, or a MITM on an `http://` remote), not any local access, malware, or leaked credentials.

### Likelihood Explanation
The trigger requires only that Desktop performs a git network operation (fetch/push/clone) against a remote controlled or intercepted by the attacker and that remote issue a 401 response with a crafted `WWW-Authenticate: ...realm="GitHub"...` header — something entirely within a malicious server operator's control and requiring no cooperation from the real GitHub. The existing guard, the actual network probe `isGitHubHost()`, is bypassed entirely because the `wwwauth[...]` check happens earlier and returns before that probe is ever reached.

### Recommendation
Do not let the `wwwauth[...]` realm value alone elevate an endpoint to `'enterprise'` trust. At minimum, corroborate it with the real `isGitHubHost()` network probe (checking `x-github-request-id` and/or a pinned `/meta` response) before granting the enterprise classification, or restrict the WWW-Authenticate fast path so it can only ever be used to *downgrade* to `'generic'` faster, never to promote an unverified host into the trusted category that triggers `promptForGitHubSignIn`.

### Proof of Concept
1. Victim has (or is tricked into adding) a remote pointing at `https://evil.example.com/foo/bar.git`, reachable either directly or via a MITM proxy the attacker controls.
2. Desktop performs a git operation against that remote; the attacker's server responds `401` with header `WWW-Authenticate: Basic realm="GitHub"`.
3. Git forwards this as a `wwwauth[0]=Basic realm="GitHub"` field to Desktop's credential helper via `createCredentialHelperTrampolineHandler`.
4. `getEndpointKind()` matches the regex at `trampoline-credential-helper.ts:159` and returns `'enterprise'` without ever probing `evil.example.com`.
5. `getCredential()` finds no existing account for `evil.example.com` and calls `ui.promptForGitHubSignIn('https://evil.example.com')`.
6. `promptForGitHubSignIn` starts `dispatcher.beginEnterpriseSignIn` + `setSignInEndpoint('https://evil.example.com')`, and shows the Sign In dialog offering "Continue in browser," which opens `shell.openExternal` to an OAuth-authorize URL built from the attacker's host — a flow indistinguishable in the UI from legitimate GitHub Enterprise sign-in.

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)
      }

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
