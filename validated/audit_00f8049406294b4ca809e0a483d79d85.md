### Title
Unsanitized `IMentionableUser.name` allows bidi/zero-width Unicode spoofing in the mention/co-author dropdown and is written verbatim into the `Co-Authored-By` git trailer - (File: `app/src/ui/autocompletion/user-autocompletion-provider.tsx`)

### Summary
`renderItem()` interpolates the attacker-controlled GitHub profile `name` field into a `<span className="name">` with only React's default string-escaping, which neutralizes `<`/`>`/`&` but does not strip or normalize Unicode bidi-control or zero-width characters. The same unsanitized `name` value is subsequently used to build the actual `Co-Authored-By` trailer that gets written into the git commit.

### Finding Description
`userToHit()` copies `user.name` (sourced from `fetchMentionables`/`getMentionableUsersMatching`, i.e., attacker-controlled GitHub profile data) into `KnownUserHit.name` unmodified: [1](#0-0) 

`renderItem()` then renders it directly: [2](#0-1) 

React's escaping only encodes HTML-significant characters; it performs no Unicode normalization or stripping of bidi override characters (`U+202E`, `U+2066`-`U+2069`) or zero-width characters (`U+200B`, `U+FEFF`), so a crafted `name` can visually reorder/obscure the rendered text and make it appear as a different, trusted username in the dropdown.

For plain `@mention` insertion, `getCompletionText()` only inserts `item.username`, not `name`: [3](#0-2) 
so mention text itself is not corrupted - the spoofing there is purely visual (a user could be tricked into picking the wrong entry from a dropdown that looks like the intended trusted user).

However, for the co-author flow the `name` value has a second, more consequential sink. `AuthorInput.authorFromUserHit()` builds a `KnownAuthor` using `user.name || user.username`: [4](#0-3) 
and `CommitMessage.getCoAuthorTrailers()` embeds that same unsanitized `name` directly into the `Co-Authored-By` trailer value that is merged into the actual commit message via `git interpret-trailers`: [5](#0-4) [6](#0-5) 

So a crafted profile `name` containing bidi-override or zero-width characters is not just a UI-rendering quirk - it is committed verbatim into the repository's permanent git history as part of the `Co-Authored-By:` trailer, without any normalization/stripping check anywhere in this path.

### Impact Explanation
This is a low/moderate-severity issue. It is not RCE, file exfiltration, or credential theft. The concrete effects are:
1. Visual spoofing in the mention/co-author suggestion dropdown, which could mislead a user into selecting a different account than intended (username, not name, is what actually gets inserted for `@mentions`, limiting damage there).
2. Silent corruption of committed metadata: the spoofed/obscured `name` is written into the `Co-Authored-By` trailer of the user's commit and pushed to the remote, meaning the resulting commit history contains attacker-controlled, visually-deceptive text as part of what the user believes they are committing/pushing without their awareness.

This aligns with the "silent corruption of what the user commits or pushes" impact category, but the practical damage is limited to a cosmetic/metadata corruption of a git trailer string - it does not affect diff content, staged files, or file scope, and does not disclose any local data.

### Likelihood Explanation
Moderate. Any GitHub user whose profile appears in a repository's mentionable-users list (collaborators, commenters, PR participants, etc., depending on `fetchMentionables` scope) can set an arbitrary `name` on their public profile, including bidi/zero-width control characters, with no special privileges required. The victim must voluntarily use the co-author/mention autocomplete UI and pick the spoofed entry, but no other unusual user interaction is required.

### Recommendation
- Sanitize/normalize `IMentionableUser.name` (and any other free-text profile fields rendered or embedded in git metadata) by stripping bidi control characters (`U+202A`-`U+202E`, `U+2066`-`U+2069`) and zero-width characters (`U+200B`, `U+200C`, `U+200D`, `U+FEFF`) before rendering in `renderItem()` and before use in `authorFromUserHit()`/`getCoAuthorTrailers()`.
- Consider visually isolating/escaping such Unicode categories (e.g., wrapping rendered names using CSS `unicode-bidi: isolate` in addition to text sanitization) so future similar fields are protected by default.

### Proof of Concept
1. On a GitHub account that will appear as a mentionable user for a target repository (e.g., a collaborator or PR commenter), set the profile display name to include an RTL override sequence, e.g. `"trusted\u202Eresu"` (renders visually reversed) or interleave zero-width characters to mimic a known username, e.g. `"octoc\u200Bat"`.
2. In GitHub Desktop, open the commit box for that repository and open the co-author (`@`) autocomplete or PR mention autocomplete.
3. Observe that `renderItem()` at `app/src/ui/autocompletion/user-autocompletion-provider.tsx:147/155` renders the crafted `name` unmodified, visually resembling a different trusted identity.
4. Select the attacker's entry as a co-author; observe that `authorFromUserHit()` (`app/src/ui/lib/author-input/author-input.tsx:86-93`) stores the same unmodified name, and upon commit, `getCoAuthorTrailers()` (`app/src/ui/changes/commit-message.tsx:577-585`) writes it verbatim into the `Co-Authored-By:` trailer of the resulting commit, which is then pushed to the remote unmodified.

export async function formatCommitMessage(
  repository: Repository,
  context: ICommitContext
) {
  const { summary, description, trailers } = context

  // Git always trim whitespace at the end of commit messages
  // so we concatenate the summary with the description, ensuring
  // that they're separated by two newlines. If we don't have a
  // description or if it consists solely of whitespace that'll
  // all get trimmed away and replaced with a single newline (since
  // all commit messages needs to end with a newline for git
  // interpret-trailers to work)
  const message = `${summary}\n\n${description || ''}\n`.replace(/\s+$/, '\n')

  return trailers !== undefined && trailers.length > 0
    ? mergeTrailers(repository, message, trailers)
    : message
