### Title
`associatePubKey` Precompile Accepts Public Keys Without Proof-of-Possession, Enabling Unauthorized Re-Association of EVM Addresses - ([File: precompiles/addr/addr.go])

### Summary
The `addr` precompile's `associatePubKey` method (`associatePublicKey` in Go) links a Sei address and EVM address to a caller-supplied compressed secp256k1 public key **without requiring any signature proving possession of the corresponding private key**. This is the same bug class as the Pion/DTLS advisory: a "certificate"/key is accepted and used to establish an authenticated identity binding without verifying the presenter actually controls the private key. Because Sei's own ante-handler code explicitly documents that such unauthorized re-association can "orphan any staking/distribution state" and "halt the chain via the distribution validator-removal hook," this is a directly reachable, high-impact analog.

### Finding Description
`PrecompileExecutor.associate` (signature-based) requires the caller to produce a valid ECDSA signature (`v/r/s`) over a message, which cryptographically proves possession of the private key before an address association is created: [1](#0-0) 

In contrast, `associatePublicKey` accepts a raw compressed public key directly from `args[0]`, parses it, and immediately derives and binds addresses from it — with **no signature check of any kind**: [2](#0-1) 

Both paths converge on `associateAddresses`, which only checks that the *target Sei address* isn't already associated — it does not verify that the caller is the legitimate owner of the EVM address being (re-)bound: [3](#0-2) 

The underlying `AssociateAddresses` helper performs state-mutating, fund-moving operations as a side effect of this unauthenticated call: it can reuse/rename the "cast" account (`sdk.AccAddress(evmAddr[:])`), migrate all of its spendable coins and wei balance to the new Sei address, and remove the old cast account: [4](#0-3) 

Because a compressed public key is *public information* — recoverable from any signature the address has ever produced (e.g., any prior EVM transaction, or an EIP-7702 authorization) — an attacker does not need the private key at all to trigger this precompile for a victim's address. The developers themselves acknowledge the resulting hazard in `x/evm/ante/preprocess.go`, where a dedicated pre-association routine (`associateAuthorizationAuthorities`) was added specifically to stop EIP-7702 `SetCode` authorities from later being remapped by `associatePubKey`, because doing so would "orphan any staking/distribution state created under the direct-cast identity (which can then halt the chain via the distribution validator-removal hook)": [5](#0-4) 

This comment confirms that `associatePubKey`'s lack of proof-of-possession is a known-dangerous re-association primitive; the mitigation only covers the EIP-7702 authority case reached via `SetCodeTx`, not the general case of any address that has acquired a "direct-cast" identity (e.g., via receiving funds/staking/delegating under its byte-reinterpreted Cosmos address before ever formally associating).

### Impact Explanation
An unauthenticated re-association primitive that anyone can invoke for any address whose public key has ever been exposed (which is essentially every actively-used EVM/Sei account) allows:
- Forced, non-consensual account migration/renaming (`NewBaseAccount` reusing account number/sequence) and forced fund transfers out of the "cast" account into the newly bound Sei address.
- Orphaning of staking/distribution state tied to the previous direct-cast identity for that EVM address, which — per the code's own comment — can trigger the distribution module's validator-removal hook and **halt the chain**.
- Griefing/DoS of legitimate users who intended to associate through the normal signed flow (`err = "address ... is already associated"`), since an attacker can front-run association using only a recoverable public key.

This satisfies the "validator halt" / "permanent chain split" impact bar called out in the validation rules, and is directly reachable by any public-RPC/EVM-transaction sender calling the `addr` precompile at `0x0000000000000000000000000000000000001004`.

### Likelihood Explanation
Medium-High. Exploitation requires:
1. Obtaining a target's compressed public key — trivially recoverable via ECDSA public-key recovery from any past signed EVM transaction or EIP-7702 authorization from that address (no cooperation from the victim required).
2. Calling `associatePubKey` on the `addr` precompile, which any account can do with a normal EVM transaction and moderate gas (50,000 required gas as configured).
3. The chain-halting outcome specifically requires the target address to have accrued staking/distribution state under its direct-cast identity prior to being remapped — a scenario the codebase's own comments indicate is realistic enough to warrant an explicit (but only partial) mitigation for the EIP-7702 case.

### Recommendation
Require the same proof-of-possession for `associatePubKey` as for `associate`: either remove `associatePubKey` entirely, or require a signature (e.g., over a nonce/challenge) verifiable against the submitted public key before performing any address binding or balance migration. Additionally, extend the existing authority pre-association safeguard (`associateAuthorizationAuthorities`) to cover all addresses that have acquired protocol state (staking, distribution, delegations) under a direct-cast identity, not just EIP-7702 `SetCode` authorities, and make `associateAddresses` reject re-association attempts when the target EVM address already has a distinct, protocol-state-bearing direct-cast mapping.

### Proof of Concept
1. Victim `V` sends a normal EVM transaction (or an EIP-7702 authorization) from EOA `evmAddrV`; this reveals `V`'s compressed secp256k1 public key `pubV` via standard ECDSA recovery (public knowledge, no private key required).
2. Prior to any formal association, `V`'s cast Cosmos address `castAddr = sdk.AccAddress(evmAddrV[:])` accrues balance/staking/distribution state (e.g., someone sends native `usei` to `castAddr`, or `V` delegates using the cast identity).
3. Attacker `A` (unrelated account) calls `addr.associatePubKey(pubV)` on precompile `0x1004`.
4. `associatePublicKey` → `helpers.GetAddressesFromPubkeyBytes` derives `seiAddrV`/`evmAddrV` from `pubV` with no signature check, and `associateAddresses` proceeds because `seiAddrV` was not yet associated.
5. `AssociateAddresses`/`MigrateBalance` migrates `castAddr`'s spendable coins and wei balance into `seiAddrV`, removes `castAddr`'s account, and rebinds `evmAddrV → seiAddrV` — all triggered by `A`, without `V`'s consent or private key, potentially orphaning any staking/distribution records still referencing the old `castAddr` identity.

func (p PrecompileExecutor) associate(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}

	// v, r and s are components of a signature over the customMessage sent.
	// We use the signature to construct the user's pubkey to obtain their addresses.
	v := args[0].(string)
	r := args[1].(string)
	s := args[2].(string)
	customMessage := args[3].(string)

	rBytes, err := decodeHexString(r)
	if err != nil {
		return nil, 0, err
	}
	sBytes, err := decodeHexString(s)
	if err != nil {
		return nil, 0, err
	}
	vBytes, err := decodeHexString(v)
	if err != nil {
		return nil, 0, err
	}

	vBig := new(big.Int).SetBytes(vBytes)
	rBig := new(big.Int).SetBytes(rBytes)
	sBig := new(big.Int).SetBytes(sBytes)

	// Derive addresses
	vBig = new(big.Int).Add(vBig, utils.Big27)

	customMessageHash := crypto.Keccak256Hash([]byte(customMessage))
	evmAddr, seiAddr, pubkey, err := helpers.GetAddresses(vBig, rBig, sBig, customMessageHash)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)

func (p PrecompileExecutor) associatePublicKey(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}

	// Takes a single argument, a compressed pubkey in hex format, excluding the '0x'
	pubKeyHex := args[0].(string)

	pubKeyBytes, err := hex.DecodeString(pubKeyHex)
	if err != nil {
		return nil, 0, err
	}

	// Parse the compressed public key
	pubKey, err := btcec.ParsePubKey(pubKeyBytes)
	if err != nil {
		return nil, 0, err
	}

	// Convert to uncompressed public key
	uncompressedPubKey := pubKey.SerializeUncompressed()

	evmAddr, seiAddr, pubkey, err := helpers.GetAddressesFromPubkeyBytes(uncompressedPubKey)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p PrecompileExecutor) associateAddresses(ctx sdk.Context, method *abi.Method, evmAddr common.Address, seiAddr sdk.AccAddress, pubkey cryptotypes.PubKey) (ret []byte, remainingGas uint64, err error) {
	// Check that address is not already associated
	_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if found {
		return nil, 0, fmt.Errorf("address %s is already associated with evm address %s", seiAddr, evmAddr)
	}

	// Associate Addresses:
	associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.bankKeeper, p.accountKeeper)
	err = associationHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false)
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(seiAddr.String(), evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}

// associateAuthorizationAuthorities associates every EIP-7702 authorization authority in
// the transaction with its true (pubkey-derived) Sei address, so that a subsequent
// SetCode for the authority does not create a mutable direct-cast mapping. It is
// best-effort: authorities with invalid signatures (which EVM execution would also skip)
// or that are already associated are left untouched, and an association failure skips
// only that authority rather than rejecting the transaction, which go-ethereum would
// still accept.
func (p *EVMPreprocessDecorator) associateAuthorizationAuthorities(ctx sdk.Context, msg *evmtypes.MsgEVMTransaction, associateHelper *helpers.AssociationHelper) {
	txData, err := evmtypes.UnpackTxData(msg.Data)
	if err != nil {
		return
	}
	setCodeTx, ok := txData.(*ethtx.SetCodeTx)
	if !ok {
		// Only SetCode (EIP-7702) transactions carry authorizations.
		return
	}
	ethTx := ethtypes.NewTx(setCodeTx.AsEthereumData())
	for _, auth := range ethTx.SetCodeAuthorizations() {
		// Only pre-associate authorities whose authorization the EVM will actually apply
		// (matching chain id, nonce, and account state). This prevents replaying a
		// publicly-visible authorization a user signed for another chain to force-associate
		// them, which the EVM would skip but which still recovers a valid authority.
		evmAddr, seiAddr, pubkey, ok := helpers.AuthorityToPreAssociate(ctx, p.evmKeeper, auth)
		if !ok {
			continue
		}
		cacheCtx, write := ctx.CacheContext()
		if err := associateHelper.AssociateAddresses(cacheCtx, seiAddr, evmAddr, pubkey, false); err == nil {
			write()
		}
	}
}
