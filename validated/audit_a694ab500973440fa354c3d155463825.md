### Title
Untrusted participant indexes in blame evaluation cause out-of-bounds HashMap indexing panic (DoS) - (File: crypto/dkg/pedpop/src/lib.rs)

### Summary
`BlameMachine::blame` / `AdditionalBlameMachine::blame` accept attacker-chosen `sender` and `recipient` `Participant` values and index `self.commitments[&sender]` and `self.enc_keys[&decryptor]` without checking the indexes are within `1 ..= n`. A crafted blame/accusation (e.g., a tributary `InvalidDkgShare` transaction, whose `accuser`/`faulty` fields are only validated as non-zero `u16`) with an index `> n` panics the evaluating party — the analog of the CVE-2017-8363 heap over-read/crash: an out-of-bounds access on attacker-controlled data causing denial of service.

### Finding Description
- `Transaction::InvalidDkgShare` deserialization reads `accuser` and `faulty` via `Participant::new(u16)`, which only rejects `0`, not values `> n` [1](#0-0) 
- `blame_internal` calls `self.encryption.decrypt_with_proof(sender, recipient, msg, proof)`, which does `self.enc_keys[&decryptor]` — a panic on a missing key [2](#0-1) 
- `blame_internal` then does `&self.commitments[&sender]` — likewise an unchecked index [3](#0-2) 
- `enc_keys`/`commitments` only contain entries for `1 ..= n` (registered in `AdditionalBlameMachine::new` and `verify_r1`) [4](#0-3) 

### Impact Explanation
Any participant (or anyone able to get a blame transaction/message evaluated) can crash every honest party evaluating the blame by supplying `sender` or `recipient` indexes in `(n, u16::MAX]`. The panic aborts the DKG/signing flow — a remote denial of service analogous to the libsndfile crash, but via a missing-key panic instead of a heap over-read.

### Likelihood Explanation
Reachable whenever blame evaluation runs on externally supplied sender/recipient indexes (tributary `InvalidDkgShare` transactions are the natural carrier). It requires no key material or threshold collusion — just a malformed index.

### Recommendation
Validate `sender`/`recipient` against `params.n()` (or check `enc_keys.get(&decryptor)` / `commitments.get(&sender)` and return a defined result/error) inside `blame_internal` and `decrypt_with_proof`, and bound `accuser`/`faulty` to `<= n` when parsing `InvalidDkgShare` transactions.

### Proof of Concept
```rust
// n = 3 DKG; attacker submits a blame statement with an out-of-range recipient
let attacker_controlled = Participant::new(0xFFFF).unwrap();
// AdditionalBlameMachine::new registered enc_keys only for Participants 1..=3
machine.blame(
  Participant::new(1).unwrap(),      // sender
  attacker_controlled,               // recipient -> enc_keys has no entry
  msg,                               // any EncryptedMessage<SecretShare>
  Some(proof),                       // any EncryptionKeyProof
);
// decrypt_with_proof evaluates `&[self.enc_keys[&decryptor], *proof.key]`
// -> HashMap index panic: process crashes
```
