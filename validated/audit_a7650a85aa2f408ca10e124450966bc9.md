### Title
`Scanner::scan_block` reports immature coinbase outputs as spendable `ReceivedOutput`s, indistinguishable from confirmed spendable funds — ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
Analogous to the reference bug (an event/log reporting a transfer that misrepresents the real on-chain fact), `Scanner::scan_block` iterates over `block.txdata` in full — including `txdata[0]`, the coinbase — and emits `ReceivedOutput`s for outputs paying to a registered script. A `ReceivedOutput` carries only `offset`, `output`, and `outpoint`; there is no maturity flag, so an output reported from the coinbase is byte-for-byte indistinguishable from a normally spendable output. Downstream consumers calling `scan_block` (rather than scanning `block.txdata[1..]` per the doc comment) will treat immature coinbase outputs as received, spendable funds.

### Finding Description
`scan_transaction` pushes a `ReceivedOutput` for every output whose `script_pubkey` matches a registered script [1](#0-0) . `scan_block` calls it for every transaction in the block, including the coinbase [2](#0-1) . The `ReceivedOutput` struct has no field recording that the outpoint is immature [3](#0-2) . The only mitigation is a doc comment stating "If received outputs must be immediately spendable, a post-processing pass is needed" — the type/API itself does not prevent or mark the misreport [4](#0-3) .

### Impact Explanation
Any consumer (e.g., a multisig scanner feeding an inbound-funds pipeline) that reports scanned outputs as received value will report a coinbase payment as spendable. Coinbase outputs are unspendable for 100 blocks and reside in a block that is more likely than average to be orphaned precisely during that window. Reporting them as normal receipts can cause crediting/minting against funds that cannot actually be spent and may vanish in a reorg before maturity — i.e., funds reported received that are not (yet, and possibly never) spendable.

### Likelihood Explanation
Reachable by an unprivileged party sending Bitcoin transactions: anyone who mines a block (permissionless) can set the coinbase output's `script_pubkey` to a scanned P2TR script. No key knowledge is needed — `scan_transaction` matches on `script_pubkey` alone [5](#0-4) . Exploitation additionally requires the consumer to call `scan_block` without the documented post-processing pass; since the API silently produces the misreport, this is a realistic integration hazard rather than a guaranteed break.

### Recommendation
Have `scan_block` skip `block.txdata[0]` (or return outputs tagged with a `coinbase`/`immature` flag on `ReceivedOutput`), so that a reported `ReceivedOutput` is always spendable-by-construction and the misreport cannot occur. At minimum, make the immature case a distinct type so consumers cannot conflate it with mature receipts.

### Proof of Concept
```rust
// Conceptual: key is the scanned even-y aggregate key.
let scanner = Scanner::new(key).unwrap();
// A miner crafts a block whose coinbase tx pays to p2tr_script_buf(key).
let block: Block = /* block where txdata[0].output[0].script_pubkey == p2tr(key) */;
let outputs = scanner.scan_block(&block);
// outputs[0] is a ReceivedOutput { offset: ZERO, outpoint: coinbase_txid:0, ... }
// indistinguishable from a spendable receipt, yet unspendable for 100 blocks
// and lost entirely if the block is orphaned.
```

Caveat: verification of whether the production caller (`processor`/`get_outputs`) performs the documented maturity filtering could not be completed in this scan; the finding stands on `scan_block` reporting immature outputs as ordinary `ReceivedOutput`s with no marker, which the API's own documentation acknowledges requires an external pass to correct [6](#0-5) .

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res

  /// Scan a block.
  ///
  /// This will also scan the coinbase transaction which is bound by maturity. If received outputs
  /// must be immediately spendable, a post-processing pass is needed to remove those outputs.
  /// Alternatively, scan_transaction can be called on `block.txdata[1 ..]`.
  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }
