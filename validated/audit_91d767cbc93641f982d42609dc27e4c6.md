### Title
Recursive `git clone` disables Git's built-in clone-time protection (`GIT_CLONE_PROTECTION_ACTIVE=false`), enabling RCE from a malicious repository - ([File: app/src/lib/git/clone.ts])

### Summary
Desktop's `clone()` helper unconditionally sets the environment variable `GIT_CLONE_PROTECTION_ACTIVE` to `'false'` on every invocation of `git clone --recursive`. This is the exact mechanism Git added upstream (as part of the fix for CVE‑2024‑32002, a critical RCE via crafted recursive clones with symlinked/case‑confusable `.git` directories in submodules) to prevent hostile repositories from writing hook files outside the intended working tree during clone. By forcing this protection off for every clone, Desktop reintroduces the vulnerability the flag exists to prevent.

### Finding Description
`clone()` builds its git invocation with: [1](#0-0) 
Every call sets `GIT_CLONE_PROTECTION_ACTIVE: 'false'` alongside `--recursive`, regardless of the source of the URL — including URLs sourced from `x-github-client://openRepo/...` deep links parsed by `parseAppURL` and dispatched via `openRepositoryFromUrl` in the app's dispatcher. [2](#0-1) [3](#0-2) 

Git's real `GIT_CLONE_PROTECTION_ACTIVE` (and the related NTFS/symlink protections it gates) exists to stop a malicious repository from using recursive submodule clones to place a `.git/hooks` file (e.g., `post-checkout`) outside the intended working directory on case-insensitive or symlink-supporting filesystems, which then executes arbitrary code the moment the clone/checkout completes. By explicitly disabling this protection on every clone, the only remaining guard in this file is `isClonePathSensitive()`: [4](#0-3) 
This function only validates the **destination path** the user chose (blocking `~/.ssh`, `~/.gnupg`, etc.) — it does nothing to validate the **contents of the remote repository itself**. It cannot stop a malicious submodule/symlink structure inside the cloned repo from writing files to arbitrary locations once Git's own upstream protection has been switched off.

### Impact Explanation
An attacker who controls a repository — reachable via a normal clone URL, a crafted "Open in Desktop" deep link (`x-github-client://openRepo/<attacker-url>`), or any git remote a user is lured into cloning — can craft a recursive-submodule repository that, when cloned by Desktop with protections disabled, writes a git hook (or other file) outside the intended repository directory and achieves arbitrary code execution on the victim's machine. This satisfies the "attacker controls a cloned/fetched repository ... result is code execution / file write outside the repo" criterion directly, and is High severity because it leads to full local code execution, not just data corruption.

### Likelihood Explanation
Likelihood is high: the vulnerable environment variable is set unconditionally for *every* clone operation performed by Desktop (manual "Clone repository" flow and deep-link "Open in Desktop" flow both funnel through this same `clone()` function), and `--recursive` is always passed, meaning any attacker-supplied malicious repository with recursive submodules is processed with the relevant Git safety check turned off. No special user action beyond clicking a clone/deep link or entering a malicious URL is required, and no other guard in the codebase compensates for the disabled protection.

### Recommendation
Remove the `GIT_CLONE_PROTECTION_ACTIVE: 'false'` override entirely (or explicitly set it to `'true'`/leave unset so Git's default protection applies) in `app/src/lib/git/clone.ts`. If the override was added to work around a specific legitimate clone scenario, that scenario should be handled without globally disabling the anti-RCE protection Git introduced for CVE‑2024‑32002; at minimum the protection should never be disabled for clones originating from untrusted URLs (deep links, arbitrary user-entered clone URLs).

### Proof of Concept
1. Attacker hosts a git repository containing a submodule configured with a crafted case-confusable/symlinked path (the same technique used for CVE‑2024‑32002) designed to escape the submodule directory and drop a hook file (e.g., `.git/hooks/post-checkout`) into the parent working tree.
2. Attacker sends the victim a link such as `x-github-client://openRepo/https://attacker.example/evil-repo` or simply shares the clone URL.
3. Victim clicks the link / clones the repo in GitHub Desktop, which calls `clone()` in `app/src/lib/git/clone.ts` with `--recursive` and `GIT_CLONE_PROTECTION_ACTIVE=false`. [1](#0-0) 
4. Because Git's clone-time protection is disabled, the malicious submodule structure is able to write the hook file outside the submodule directory during the recursive clone/checkout.
5. The hook executes automatically as part of the git checkout process, achieving code execution on the victim's machine — `isClonePathSensitive()` never inspects the resulting file writes because it only checks the top-level destination path chosen by the user. [4](#0-3)

function isClonePathSensitive(unresolvedClonePath: string): boolean {
  const clonePath = Path.resolve(unresolvedClonePath).toLowerCase()
  const home = Path.resolve(homedir()).toLowerCase()

  if (clonePath === home) {
    return true
  }

  const sensitiveLocations = [
    Path.join(home, '.ssh'),
    Path.join(home, '.gnupg'),
    Path.join(home, '.config'),
    Path.join(home, '.config', 'git'),
    Path.join(home, '.gitconfig'),
  ]

  if (__WIN32__) {
    const appData = process.env.APPDATA
    if (appData) {
      sensitiveLocations.push(appData.toLowerCase())
      sensitiveLocations.push(Path.join(appData, 'gnupg').toLowerCase())
    }
  }

  for (const sensitive of sensitiveLocations) {
    if (clonePath === sensitive || clonePath.startsWith(sensitive + Path.sep)) {
      return true
    }
  }

  return false
}

export function parseAppURL(url: string): URLActionType {
  const parsedURL = URL.parse(url, true)
  const hostname = parsedURL.hostname
  const unknown: IUnknownAction = { name: 'unknown', url }
  if (!hostname) {
    return unknown
  }

  const query = parsedURL.query

  const actionName = hostname.toLowerCase()
  if (actionName === 'oauth') {
    const code = getQueryStringValue(query, 'code')
    const state = getQueryStringValue(query, 'state')
    if (code != null && state != null) {
      return { name: 'oauth', code, state }
    } else {
      return unknown
    }
  }

  // we require something resembling a URL first
  // - bail out if it's not defined
  // - bail out if you only have `/`
  const pathName = parsedURL.pathname
  if (!pathName || pathName.length <= 1) {
    return unknown
  }

  // Trim the trailing / from the URL
  const parsedPath = pathName.substring(1)

  if (actionName === 'openrepo') {
    const pr = getQueryStringValue(query, 'pr')
    const branch = getQueryStringValue(query, 'branch')
    const filepath = getQueryStringValue(query, 'filepath')

    if (pr != null) {
      if (!/^\d+$/.test(pr)) {
        return unknown
      }

      // we also expect the branch for a forked PR to be a given ref format
      if (branch != null && !/^pr\/\d+$/.test(branch)) {
        return unknown
      }
    }

    if (branch != null && testForInvalidChars(branch)) {
      return unknown
    }

    return {
      name: 'open-repository-from-url',
      url: parsedPath,
      branch,
      pr,
      filepath,
    }
