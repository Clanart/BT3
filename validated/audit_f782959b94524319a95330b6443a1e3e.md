### Title
Gasless swap deadline check relies on manipulable proposer-set block timestamp - ([File: kaiax/gasless/impl/tx_pool.go])

### Summary
The gasless module validates a `GaslessSwapTx`'s `deadline` against `g.Chain.CurrentBlock().Time()`, treating the current block's proposer-supplied timestamp as a trusted "current time" oracle. Because the block proposer freely chooses this timestamp (subject only to a loose min/future bound), the deadline protection meant to prevent stale-price execution of the gasless swap can be bypassed by the very party assembling the block.

### Finding Description
`checkBalanceForSwap` enforces `tx.deadline >= currentTimestamp` using the local chain head's block time as the proxy for "now": [1](#0-0) 

This mirrors the classic block.timestamp deadline pattern (as in the original Teller report) used to protect users from having their swap executed at a stale, unfavorable price after too much time has elapsed. In Kaia, `header.Time` is set by the block proposer and is only constrained by:
- not being earlier than `parent.Time + BlockGenerationInterval`, and
- not being further in the future than `time.Now() + BlockGenerationInterval` as measured by the *validating* node's local wall clock: [2](#0-1) 

There is no strict binding of `header.Time` to true wall-clock time beyond this loose future-block check, and the proposer is the entity that both (a) sets the timestamp and (b) decides whether to include the gasless bundle (`LendTxGenerator` + `GaslessSwapTx`) via the auction/gasless bundling logic: [3](#0-2) 

A proposer can therefore advance `header.Time` toward the edge of the permitted drift window when building a block, causing `g.Chain.CurrentBlock().Time()` (the timestamp of the *previous* block, used as "currentTimestamp" for the *next* block's tx pool checks) to diverge from the swap's intended deadline semantics, or conversely include a swap whose real-world deadline has already passed but which still satisfies the check against the manipulated (or simply loosely-bounded) block time.

### Impact Explanation
The gasless swap deadline exists to protect the sender from stale-price execution: `tx.minAmountOut >= tx.amountRepay` is fixed at submission time, but the actual swap output depends on live AMM price via `GetAmountIn`, which is only checked at admission time, not necessarily re-verified against a trustworthy "now" when the swap is ultimately executed by the proposer's bundle. A proposer/searcher can manipulate the effective timestamp check to admit/execute an otherwise-expired swap, extracting value (unfavorable execution price for the gasless user, or replay of a stale swap advantageous to the proposer/searcher) — a form of gasless settlement abuse, matching the "gasless or auction settlement theft" acceptance criterion.

### Likelihood Explanation
Exploitation requires being the block proposer for the target block (or colluding with one), which is a role rotated among the validator set and reachable without needing to compromise the network — a proposer acting within its normal transaction-inclusion/ordering privileges (already explicitly permitted per the allowed analog surface: block assembly, gasless module, auction module) can perform this. The drift window is bounded by `BlockGenerationInterval` per block, but a proposer influences their own block's timestamp deterministically each time they are selected, making the manipulation straightforward and repeatable, not probabilistic.

### Recommendation
Do not rely solely on the local chain head's `Time()` as a trusted clock for user-facing deadline enforcement of value-sensitive operations. Options:
- Re-validate the deadline and expected output amount at actual execution/inclusion time (immediately before the swap call executes in the block), rather than only at tx-pool admission using `CurrentBlock().Time()`.
- Bound the acceptable timestamp more tightly relative to independently observed time across the block-time validation path, or require the deadline check to use `header.Time` of the block that will actually contain the tx (once known), consistent with proposer constraints, and reject bundling of swaps whose deadline is not comfortably ahead of the worst-case timestamp drift.
- Consider re-checking `minAmountOut` against a fresh on-chain quote at bundle-build/execution time regardless of the deadline check, closing the timestamp-based bypass entirely.

### Proof of Concept
1. A user submits `GaslessSwapTx` with `deadline = T`, where `T` is meant to bound execution to near-`T` real time.
2. As `T` approaches, the swap should be rejected from further pool admission per: [1](#0-0) 
3. A block proposer building the block containing this pending swap can set `header.Time` for their block within the permitted range (`parent.Time + BlockGenerationInterval` up to `now + BlockGenerationInterval`), which determines the `CurrentBlock().Time()` seen by the *next* admission check, and controls whether/when the already-known-executable bundle (lend + swap) is included via `ExtractTxBundles`: [4](#0-3) 
4. By choosing favorable inclusion timing/timestamp, the proposer can force execution of the swap at a price disadvantageous to the gasless user (or advantageous to a colluding searcher/bundle), effectively bypassing the deadline protection that block.timestamp-based checks are supposed to provide.

func (v *BlockValidator) validateHeader(header *types.Header, parent *types.Header) error {
	// Don't waste time checking blocks from the future
	if header.Time.Cmp(big.NewInt(time.Now().Add(time.Duration(params.DefaultBlockGenerationInterval)*time.Second).Unix())) > 0 {
		return consensus.ErrFutureBlock
	}

	// Ensure that the block's blockscore is meaningful (may not be correct at this point)
	if header.BlockScore == nil || header.BlockScore.Cmp(params.DefaultBlockScore) != 0 {
		return ErrInvalidBlockScore
	}

	// Reject out-of-uint64 numbers before Uint64() aliases them to a lower height.
	if header.Number == nil || !header.Number.IsUint64() {
		return ErrInvalidBlockNumber
	}

	// The genesis block is the always valid dead-end
	number := header.Number.Uint64()
	if number == 0 {
		return nil
	}

	// Ensure that the block's timestamp isn't too close to it's parent
	if parent == nil {
		parent = v.hc.GetHeader(header.ParentHash, number-1)
	}
	if parent == nil || parent.Number.Uint64() != number-1 || parent.Hash() != header.ParentHash {
		return consensus.ErrUnknownAncestor
	}
	if parent.Time.Uint64()+uint64(params.BlockGenerationInterval) > header.Time.Uint64() {
		return ErrInvalidTimestamp
	}

func (a *AuctionModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	bundles := []*builder.Bundle{}
	curBlock := a.Chain.CurrentBlock()
	if curBlock == nil || atomic.LoadUint32(&a.bidPool.running) == 0 {
		return bundles
	}

	miningBlock := curBlock.NumberU64() + 1
	bidTargetMap := a.bidPool.GetTargetTxMap(miningBlock)
	if len(bidTargetMap) == 0 {
		return bundles
	}

	for _, tx := range txs {
		txHash := tx.Hash()
		bid, ok := bidTargetMap[txHash]
		if !ok {
			continue
		}
		b := builder.NewBundle(
			builder.NewTxOrGenList(a.GetBidTxGenerator(tx, bid)),
			txHash,
			true,
		)

		isConflict := false
		for _, prev := range append(prevBundles, bundles...) {
			if prev.IsConflict(b) {
				isConflict = true
				break
			}
		}
		if isConflict {
			continue
		}
		bundles = append(bundles, b)
	}

	return bundles
}
