The only write function in this module that touches `block_hash` keys is `save_unproven_finalized_block`, which uses `INSERT ... ON CONFLICT (block_hash) DO NOTHING` — explicitly append-only/idempotent and never overwrites an existing row for a given hash. [2](#0-1) 

The claimed binding ("an established mapping gets overwritten by `get_block_info_from_hash_hcp`") does not correspond to any code in this function — there is no write path to trace, no equality to violate, and no attacker-controlled input reaches a mutation here.     pub async fn get_block_info_from_hash_hcp(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        block_hash: BlockHash,
    ) -> Result<Option<(BlockHash, Header, u32)>, BridgeError> {
        let query = sqlx::query_as(
            "SELECT prev_block_hash, block_header, height FROM header_chain_proofs WHERE block_hash = $1",
        )
        .bind(BlockHashDB(block_hash));
        let result: Option<(BlockHashDB, BlockHeaderDB, i64)> =
            execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;
        result
            .map(|result| -> Result<(BlockHash, Header, u32), BridgeError> {
                let height = result.2.try_into().wrap_err("Can't convert i64 to u32")?;
                Ok((result.0 .0, result.1 .0, height))
            })
            .transpose()
    }
