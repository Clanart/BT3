## Finding

The reported vulnerability is real. The `payout_payer_operator_xonly_pk` binding is broken because the payout transaction's OP_RETURN (and any inputs beyond index 0) are **not covered** by the user's withdrawal signature.

### Title
Unauthenticated OP_RETURN operator pubkey in payout tx lets any withdrawer frame an arbitrary operator for reimbursement it never funded - ([File: core/src/builder/transaction/operator_reimburse.rs])

### Summary
`create_payout_txhandler` builds a payout tx whose only signed input (index 0, the withdrawal UTXO) is authorized with a `SinglePlusAnyoneCanPay` signature, which under BIP-341/342 semantics only commits to input 0 and the output at the *same index* (output 0). The OP_RETURN output carrying `operator_xonly_pk` sits at output index 2 and any additional funding inputs sit at index ≥1 — none of these are covered by the withdrawer's signature. Consequently, an unprivileged withdrawer can self-fund and broadcast their own payout transaction (paying themselves, using their own extra inputs to cover the anchor/fee), while stamping *any* chosen operator's x-only pubkey into the OP_RETURN.

### Finding Description
Binding claimed to hold: `reimbursed_operator_pk (= withdrawals.payout_payer_operator_xonly_pk, read back by handle_finalized_payout via get_first_unhandled_payout_by_operator_xonly_pk)` == `actual_operator_who_supplied_non-input-0_funds_of_the_mined_payout_tx`.

Tracing the code shows this equality is never checked anywhere:

- `create_payout_txhandler` [1](#0-0)  builds input 0 as the withdrawal UTXO (`SpendPath::KeySpend`, user's `in_signature`) and places `operator_xonly_pk` in a separate OP_RETURN output at index 2.
- `Operator::withdraw` computes the sighash and verifies the schnorr signature strictly using **whatever `in_signature.sighash_type` the caller supplied** (`in_signature.sighash_type`, attacker-controlled), never enforcing that it must be `SinglePlusAnyoneCanPay`: [2](#0-1) . With `SinglePlusAnyoneCanPay`, the signature over input 0 commits only to input 0 and output 0 — not to the OP_RETURN output, not to any extra funding inputs, and not to the total input count.
- Anyone who broadcasts the raw payout tx (not necessarily a Clementine operator) can therefore add their own funding input(s) at index ≥1 and set the OP_RETURN's operator xonly pubkey to any value.
- `Verifier::update_finalized_payouts` blindly trusts this OP_RETURN when it scans the mined block: it just extracts and parses whatever bytes are there with `parse_op_return_data`/`XOnlyPublicKey::from_slice`, with no verification of who actually supplied the additional inputs: [3](#0-2) .
- This value is persisted as `payout_payer_operator_xonly_pk` [4](#0-3) .
- `PayoutCheckerTask::run_once` looks up unhandled payouts strictly by matching `self.operator.signer.xonly_public_key` against this DB column [5](#0-4)  and then calls `Operator::handle_finalized_payout`, which proceeds to allocate a kickoff connector and drive the reimbursement flow purely from `deposit_outpoint`/`payout_tx_blockhash`, with no independent check of who funded the mined payout tx's non-input-0 inputs [6](#0-5) .
- The only place that cross-checks `operator_xonly_pk` against anything is `Verifier::is_kickoff_malicious`, but it only compares the OP_RETURN value to the kickoff's declared `operator_xonly_pk` — it never checks who actually funded the payout tx [7](#0-6) .

Because `SinglePlusAnyoneCanPay` is exactly the sighash type the whole payout-fronting design relies on (to let *any* operator add funding inputs), this is not a corner case but the intended operating mode — yet no mechanism binds "whoever added the funding inputs" to "whoever's pubkey appears in OP_RETURN."

### Impact Explanation
A withdrawer (attacker) who calls Citrea's `withdraw` with their own `withdrawal_utxo`/output/`SinglePlusAnyoneCanPay` signature can independently construct and broadcast the completed payout transaction themselves — funding the extra inputs (fees/anchor) from their own wallet — while writing an arbitrary honest operator's x-only pubkey into the OP_RETURN. That operator's `PayoutCheckerTask` will then automatically walk into `handle_finalized_payout`, consume one of its own kickoff connectors/collateral cycle, and initiate the on-chain reimbursement claim for a payout it never actually funded — matching the listed Critical impact category "an operator reimbursed for a payout it never funded." This is repeatable per deposit/withdrawal and can target any specific honest operator (denial-of-collateral/round-slot abuse is a secondary consequence, though DoS itself is out of scope).

### Likelihood Explanation
No privileged role is required: the attacker only needs to be the withdrawer (which any unprivileged user can be by calling Citrea's `withdraw`), control the sighash flag of their own signature (explicitly listed as attacker-controlled in the threat model), and be able to broadcast a raw Bitcoin transaction. No key compromise, no majority hashrate, and no cooperation from any operator/verifier is needed. Cost is limited to a small dust/fee amount for the extra funding input.

### Recommendation
Do not derive the reimbursed operator's identity solely from OP_RETURN bytes. Either (a) require the OP_RETURN commitment (and the identity/ownership of any additional funding inputs) to be covered by a signature tied to the claiming operator (e.g., have the operator itself co-sign the full payout tx, or use `SIGHASH_ALL`/covenant enforcement that binds all outputs and inputs), or (b) have `handle_finalized_payout`/`update_finalized_payouts` independently verify that the additional (non-input-0) inputs of the mined payout tx are provably owned/spent by the operator whose pubkey is recorded in OP_RETURN (e.g., verify a signature from that operator's key over the specific txid before treating it as their payout).

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

        &self,

        deposit_data: &mut DepositData,
        kickoff_data: KickoffData,

    ) -> Result<bool, BridgeError> {

                .get_cached_tx()
                .compute_txid();

        let payout_info = self
            .db
            .get_payout_info_from_move_txid(Some(dbtx), move_txid)
            .await?;
        let Some((operator_xonly_pk_opt, payout_blockhash, _, _)) = payout_info else {
            tracing::warn!(
                "No payout info found in db for move txid {move_txid}, assuming malicious"
            );
            return Ok(true);
        };

        let Some(operator_xonly_pk) = operator_xonly_pk_opt else {
            tracing::warn!("No operator xonly pk found in payout tx OP_RETURN, assuming malicious");
            return Ok(true);
        };

        if operator_xonly_pk != kickoff_data.operator_xonly_pk {
            tracing::warn!("Operator xonly pk for the payout does not match with the kickoff_data");
            return Ok(true);

            kickoff_data.round_idx,
            kickoff_data.kickoff_idx,
            self.config.protocol_paramset(),

        let commits = extract_winternitz_commits(
            kickoff_witness,
            &[wt_derive_path],
            self.config.protocol_paramset(),
        )?;
        let blockhash_data = commits.first();
        // only last 20 bytes of the blockhash is committed
        let truncated_blockhash = &payout_blockhash[12..];
        if let Some(committed_blockhash) = blockhash_data {
            if committed_blockhash != truncated_blockhash {
                tracing::warn!("Payout blockhash does not match committed hash: committed: {:?}, truncated payout blockhash: {:?}",
                        blockhash_data, truncated_blockhash);
                return Ok(true);
            }
        } else {
            return Err(eyre::eyre!("Couldn't retrieve committed data from witness").into());
        }
        Ok(false)
    }

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
