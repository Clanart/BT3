### Title
Scanner reports immature coinbase outputs as spendable ReceivedOutputs - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`Scanner::scan_block` iterates over `block.txdata` in full, including `block.txdata[0]` (the coinbase transaction). Bitcoin consensus rules forbid spending coinbase outputs for 100 blocks. An output scanned from a coinbase is returned as an ordinary `ReceivedOutput`, indistinguishable from a mature output, and will be accepted as an input to `SignableTransaction` / multisig signing. The analog to the report's "improper authorization / missing check on transaction parameters" is a missing validity gate: the scanner treats a consensus-restricted output as authorized for spending when it is not.

### Finding Description
`scan_block` scans every transaction in the block:

```rust
// networks/bitcoin/src/wallet/mod.rs
pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
  let mut res = Vec::new();
  for tx in &block.txdata {
    res.extend(self.scan_transaction(tx));
  }
  res
}
```

The only acknowledgement is a doc comment stating "If received outputs must be immediately spendable, a post-processing pass is needed to remove those outputs." There is no marker on `ReceivedOutput` indicating coinbase provenance or maturity height, and `scan_transaction` does not check `tx.is_coinbase()`. Downstream consumers receive a `ReceivedOutput` carrying a valid offset, TxOut, and outpoint, and can feed it into transaction construction, which will produce a transaction the network rejects (BIP-30/BIP-34-era maturity rule, `Consensus::verify` / `bad-cb-height`/`bad-txns-premature-spend-of-coinbase`).

### Impact Explanation
A `ReceivedOutput` is the value-bearing input type used to construct and threshold-sign spends. Reporting a coinbase output as spendable means funds are reported received that are not spendable. A caller that aggregates scanned outputs for a spend will build a transaction that is consensus-invalid until maturity, stalling the spend/signing round; if used for accounting (crediting deposits), value is credited before it can actually be moved. This is a Medium-severity availability/accounting defect reachable purely from on-chain data.

### Likelihood Explanation
Any block whose coinbase pays to a scanned script (the base key, or a registered branch/change/forward offset script, which is deterministic and publicly derivable) produces this condition. A miner — or a mining pool paying a pooled reward address matching a registered script — triggers it with no interaction with Serai's off-chain APIs. It does not require key material or validator collusion; only a Bitcoin block.

### Recommendation
In `Scanner::scan_block`, either skip `block.txdata[0]` (equivalently `tx.is_coinbase()`) or tag `ReceivedOutput` with coinbase/maturity metadata so consumers can exclude immature outputs. Documenting that callers "may" post-process is insufficient since `ReceivedOutput` carries no field exposing coinbase status.

### Proof of Concept
Conceptual: construct a regtest block whose coinbase contains a `TxOut` with `script_pubkey = p2tr_script_buf(key)` for a key registered in `Scanner::new(key)`. `scan_block(&block)` returns a `ReceivedOutput` with `offset == Scalar::ZERO` and the coinbase outpoint. Passing that `ReceivedOutput` to `SignableTransaction::new(vec![output], ...)` and signing produces a transaction rejected by the node with a premature coinbase spend error, whereas `scan_transaction(&block.txdata[0])` vs `scan_transaction` on `block.txdata[1..]` demonstrates the missing gate: the code itself notes the workaround exists only in a comment.   pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
