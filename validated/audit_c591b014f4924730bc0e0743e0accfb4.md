### Title
`updateHostParamsInternal` accepts an unvalidated `admin` address, permanently bricking freeze/unfreeze and initial consensus bootstrap controls - (File: `evm/src/core/EvmHost.sol`)

### Summary
`EvmHost.updateHostParamsInternal` validates `hostManager`, `handler`, and `consensusClient` for non-zero address, deployed code, and correct interface support before committing the new `HostParams`, but performs **no validation whatsoever** on the `admin` field, which is copied directly into storage. [1](#0-0) 

### Finding Description
`HostParams.admin` is documented as the account that "only has the rights to freeze, or unfreeze the bridge" [2](#0-1) 
and is also the sole caller (with no fallback) permitted to perform the one-shot `setConsensusState` bootstrap: [3](#0-2) 

`updateHostParams`/`updateHostParamsInternal` is reachable only via the `hostManager` cross-chain governance path (or `TestnetHost`'s admin override), and unconditionally overwrites `_hostParams.admin = params.admin;` with no guard: [4](#0-3) [5](#0-4) 

Compare this to the strict checks applied to `hostManager`, `handler`, and `consensusClient` in the same function — each requires non-zero address, deployed bytecode, and matching `IERC165` interface — none of which are applied to `admin`. [6](#0-5) 

The governance message that ultimately triggers this update flows through `HostManager.onAccept`, which decodes an arbitrary `HostParams` struct from the incoming cross-chain request body and forwards it verbatim to `updateHostParams`: [7](#0-6) 

This is the exact `uberOwner`/single-step privileged-address-change pattern from the external report: a single transaction sets a new highest-privilege address (`admin`) with only a source-chain check (not a zero-address or reachability check), and there is no two-step accept/claim mechanism to catch an incorrect value before it is committed.

### Impact Explanation
If `params.admin` is set to an incorrect or unreachable address (zero address, a contract without the corresponding interface, or simply a typo'd address the intended admin does not control):
- `setFrozenState` can still be called by `handler` as a fallback, so freeze/unfreeze is not fully bricked.
- `setConsensusState`, however, is `admin`-only with **no fallback caller** and is a one-shot function gated by `_consensusState` being empty. If a host has not yet had its consensus state bootstrapped, and `admin` is bricked in that window, the host can never be initialized — the bridge for that state machine is permanently unusable and must be redeployed, matching the "system locked, redeploy required" impact described in the original report. [8](#0-7) 

### Likelihood Explanation
This path requires the cross-chain governance actor (via `hostManager`) to submit a `HostParams` update with a bad `admin` value — the same low-probability, high-impact profile as the original `changeUberOwner()` finding (accidental misconfiguration, not a malicious third party). The lack of any address validation on this specific field, in a function that otherwise carefully validates the other three privileged addresses, indicates this is an overlooked case rather than an intentional design choice.

### Recommendation
Add the same validation applied to `hostManager`/`handler`/`consensusClient` to `admin` at minimum (reject `address(0)`), and consider converting `admin` rotation into a two-step accept/claim pattern (`pendingAdmin` set by governance, claimed by the new admin) so an incorrect value can be corrected before being finalized, consistent with the recommendation in the original report.

### Proof of Concept
1. Deploy `EvmHost` and complete `initialize()` normally so `hostManager` is set to a valid `HostManager` contract.
2. As the legitimate `hostManager` governance flow (via `HostManager.onAccept` → `SetHostParam` action), submit a `HostParams` struct identical to current params except `admin = address(0)` (or any address for which no private key/contract logic exists).
3. `updateHostParamsInternal` passes all checks (`hostManager`, `handler`, `consensusClient`, `hyperbridge`, `stateMachines`, `unStakingPeriod`, fee-token sweep) since none of them touch `admin`, and commits `_hostParams.admin = address(0)`. [9](#0-8) 
4. If `_consensusState` was still empty at this point (host not yet bootstrapped), calling `setConsensusState(...)` now reverts with `UnauthorizedAction` for every caller, since `restrict(_hostParams.admin)` can never match `msg.sender`, and there is no alternate caller for this function. [10](#0-9) 
5. The host state machine can never complete initial consensus bootstrap and must be redeployed.

    /**
     * @dev Updates the HostParams. Will reset all fishermen accounts and initialize any new state machines.
     * @param params, the new host params.
     */
    function updateHostParamsInternal(HostParams memory params) internal {
        // check the params to prevent the host from getting bricked.
        if (
            params.hostManager == address(0) || address(params.hostManager).code.length == 0
                || !IERC165(params.hostManager).supportsInterface(type(IApp).interfaceId)
        ) {
            // otherwise cannot process new cross-chain governance requests
            revert InvalidHostManager();
        }

        if (
            params.handler == address(0) || address(params.handler).code.length == 0
                || !IERC165(params.handler).supportsInterface(type(IHandlerV2).interfaceId)
        ) {
            // otherwise cannot process new datagrams
            revert InvalidHandler();
        }

        if (
            params.consensusClient == address(0) || address(params.consensusClient).code.length == 0
                || !IERC165(params.consensusClient).supportsInterface(type(IConsensusV2).interfaceId)
        ) {
            // otherwise cannot process new consensus datagrams
            revert InvalidConsensusClient();
        }

        // otherwise cannot process new cross-chain governance requests
        if (keccak256(params.hyperbridge) == keccak256(bytes(""))) revert InvalidHyperbridgeId();

        // otherwise cannot process new datagrams
        uint256 stateMachinesLen = params.stateMachines.length;
        if (stateMachinesLen == 0) revert InvalidStateMachinesLength();

        // otherwise cannot process new datagrams
        if (1 days > params.unStakingPeriod) revert InvalidUnstakingPeriod();

        address oldFeeToken = feeToken();
        if (oldFeeToken != address(0) && oldFeeToken != params.feeToken) {
            uint256 balance = IERC20(oldFeeToken).balanceOf(address(this));
            if (balance != 0) revert CannotChangeFeeToken();
        }

        // safe to emit here because invariants have already been checked
        // and don't want to store a temp variable for the old params
        emit HostParamsUpdated({oldParams: _hostParams, newParams: params});

        _hostParams.feeToken = params.feeToken;
        _hostParams.admin = params.admin;
        _hostParams.handler = params.handler;
        _hostParams.hostManager = params.hostManager;
        _hostParams.uniswapV2 = params.uniswapV2;
        _hostParams.unStakingPeriod = params.unStakingPeriod;
        _hostParams.challengePeriod = params.challengePeriod;
        _hostParams.consensusClient = params.consensusClient;
        _hostParams.stateMachines = params.stateMachines;
        _hostParams.hyperbridge = params.hyperbridge;
