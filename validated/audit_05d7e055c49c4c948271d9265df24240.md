### Title
`debug_redact` annotation is silently bypassed by `MessageDifferencer`'s diff/report output, leaking sensitive field values - (File: `src/google/protobuf/util/message_differencer.cc`)

### Summary
XWiki's advisory describes a class of bug where a "diff" feature exposes sensitive field values (password hashes) because the diff-rendering code path does not go through the same sensitive-data check that protects the normal display path. Protobuf has a directly analogous, code-confirmed gap: fields annotated `debug_redact = true` are hidden from `Message::DebugString()`/`ShortDebugString()`/`AbslStringify`, but `util::MessageDifferencer`'s human-readable diff reporter (`StreamReporter`) prints the raw, unredacted field value regardless of the annotation.

### Finding Description
Protobuf's redaction feature lets schema owners mark a field `[debug_redact = true]` so that "the field value should not be printed out when using debug formats" [1](#0-0) . The intended enforcement point is `TextFormat::Printer::TryRedactFieldValue`, which is only effective when the printer has `redact_debug_string_` enabled [2](#0-1) . That flag is turned on specifically by the internal `StringifyMessage` helper that backs `DebugString()`/`ShortDebugString()`/Abseil stringify: `printer.SetRedactDebugString(true);` [3](#0-2) . The printer's default constructor otherwise leaves `redact_debug_string_` false [4](#0-3) , meaning `TryRedactFieldValue` becomes a no-op unless a caller explicitly opts in.

`util::MessageDifferencer::StreamReporter` — the standard, publicly documented human-readable reporter used by `ReportDifferencesToString`/`ReportDifferencesTo` to describe added/deleted/modified fields between two messages — builds its per-field text via two helper paths that both bypass the redaction gate:
- `PrintShortTextFormat()` constructs a brand-new, default `TextFormat::Printer` (redaction disabled) and calls `PrintToString` on it [5](#0-4) .
- `StreamReporter::PrintValue()` calls the *static* `TextFormat::PrintFieldValueToString(message, field, index, &output)` directly for scalar/message leaf values and map values [6](#0-5) .

That static helper simply constructs an anonymous default `Printer()` and forwards to `PrintFieldValue` [7](#0-6) [8](#0-7) . Because this default `Printer` never calls `SetRedactDebugString(true)`, `TryRedactFieldValue`'s internal check `if (redaction_state.redact) { if (redact_debug_string_) { ... return true; } } return false;` always falls through to `false` — the redaction annotation is checked and then unconditionally ignored, and the raw value is printed into `added:`/`deleted:`/`modified:` diff lines [9](#0-8) .

This mirrors the XWiki failure mode precisely: a security control (hide-on-display for sensitive fields) is enforced on the primary/expected rendering path (`DebugString`) but a secondary feature that renders essentially the same content for a different purpose (diff/history view in XWiki; diff/comparison reporting in protobuf) reaches the same underlying storage through a code path that was never wired up to the check.

### Impact Explanation
Any application that marks credential-like fields (passwords, tokens, hashes, API keys) with `debug_redact = true` — trusting that this is protobuf's supported mechanism for keeping such values out of "debug formats" — and then also uses `util::MessageDifferencer` (e.g. to compute/log audit diffs between message versions, unit-test failure messages, config change history, RPC request/response comparison tooling) will have the sensitive raw value written into logs, test output, or any consumer of the diff report string, even though the exact same field is correctly redacted when the message is logged via `DebugString()`. This is an information-disclosure issue (CWE-200/CWE-916 analog) with impact scoped to whatever data flow consumes the diff string (logs, test failure captures, audit trails) — the same "hash disclosure via unexpected feature" pattern as the CVE.

### Likelihood Explanation
`MessageDifferencer` and `ReportDifferencesToString`/`StreamReporter` are public, commonly used APIs (heavily exercised in the project's own unit tests, e.g. `message_differencer_unittest.cc`), and `debug_redact` is a documented, supported annotation intended for exactly this "don't leak in debug/diagnostic output" use case. Any trusted application combining both features (redacted schema field + diff reporting/logging) triggers the leak automatically, with no attacker input manipulation required beyond normal use of the differencer on a message instance that legitimately contains the sensitive value. There is no existing check anywhere in `message_differencer.cc` referencing `debug_redact`/`RedactionState`/`GetRedactionState` (confirmed via search — zero matches), so there is no partial mitigation to bypass; the gap is total.

### Recommendation
Wire `MessageDifferencer::StreamReporter::PrintValue`/`PrintShortTextFormat` through a `TextFormat::Printer` configured with `SetRedactDebugString(true)` (mirroring `internal::StringifyMessage`), or explicitly check `field->options().debug_redact()` (recursively, matching `TextFormat::GetRedactionState`) before emitting a diff line's value, replacing it with the same `[REDACTED]` marker used by `TextFormat`. Add a `unittest_redaction.proto`-based regression test analogous to `DebugFormatTest` that asserts `MessageDifferencer::StreamReporter` output redacts `debug_redact` fields.

### Proof of Concept
Conceptual reproduction (consistent with existing test patterns in `message_differencer_unittest.cc` and `DebugFormatTest.java`/`text_format.cc`):
1. Define a proto message with a field `string secret = 1 [debug_redact = true];` (pattern used by `RedactedFields`/`unittest_redaction.proto`) [10](#0-9) .
2. Construct `msg1` with `secret = "hash_v1"` and `msg2` with `secret = "hash_v2"`.
3. Call `DebugFormat::multiline().toString(msg1)` (or C++ `message.DebugString()`) — output shows `secret: [REDACTED]`, matching `DebugFormatTest.messageFormat_debugRedactFieldIsRedacted` [11](#0-10) .
4. Call:
```cpp
std::string diff_report;
util::MessageDifferencer differencer;
differencer.ReportDifferencesToString(&diff_report);
differencer.Compare(msg1, msg2);
```
5. `diff_report` contains `modified: secret: "hash_v1" -> "hash_v2"` — the raw values, not `[REDACTED]` — because `StreamReporter::ReportModified` → `PrintValue` → `TextFormat::PrintFieldValueToString` never checks `redact_debug_string_`/`debug_redact` [12](#0-11) .

Note: I was not able to execute this PoC in a sandbox (no build/test execution available in this environment); the trace is based on static code-path analysis of the cited functions, which shows no `debug_redact`/`RedactionState` reference anywhere in `message_differencer.cc`/`.h`.

bool TextFormat::Printer::TryRedactFieldValue(
    const Message& message, const FieldDescriptor* field,
    BaseTextGenerator* generator, bool insert_value_separator) const {
  TextFormat::RedactionState redaction_state =
      DescriptorPool::MemoizeProjection(
          field, [](const FieldDescriptor* field) {
            return TextFormat::GetRedactionState(field);
          });
  if (redaction_state.redact) {
    if (redact_debug_string_) {
      IncrementRedactedFieldCounter();
      if (insert_value_separator) {
        generator->PrintMaybeWithMarker(MarkerToken(), ": ");
      }
      generator->PrintString(kFieldValueReplacement);
      if (insert_value_separator) {
        if (single_line_mode_) {
          generator->PrintLiteral(" ");
        } else {
          generator->PrintLiteral("\n");
        }
      }
      return true;
    }
  }
  return false;
}

void MessageDifferencer::StreamReporter::ReportModified(
    const Message& message1, const Message& message2,
    const std::vector<SpecificField>& field_path) {
  if (!report_modified_aggregates_ && field_path.back().field == nullptr) {
    if (field_path.back().unknown_field_type == UnknownField::TYPE_GROUP) {
      // Any changes to the subfields have already been printed.
      return;
    }
  } else if (!report_modified_aggregates_) {
    if (field_path.back().field->cpp_type() ==
        FieldDescriptor::CPPTYPE_MESSAGE) {
      // Any changes to the subfields have already been printed.
      return;
    }
  }

  printer_->Print("modified: ");
  PrintPath(field_path, true);
  if (CheckPathChanged(field_path)) {
    printer_->Print(" -> ");
    PrintPath(field_path, false);
  }
  printer_->Print(": ");
  PrintValue(message1, field_path, true);
  printer_->Print(" -> ");
  PrintValue(message2, field_path, false);
  printer_->Print("\n");  // Print for newlines.
}
