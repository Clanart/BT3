### Title
stSTXbtc / zstSTXbtc collateral and debt mispriced using STX feed instead of BTC feed - (File: mainnet/contracts/utility/v0-1-data.clar)

### Summary
In `get-asset-price` inside `mainnet/contracts/utility/v0-1-data.clar`, the `stSTXbtc` and `zstSTXbtc` asset branches resolve their USD value from the `PYTH-STX` feed instead of the `PYTH-BTC` feed, even though the accompanying comments explicitly state they should use the BTC price. This is a "price attached to the wrong asset" defect: a BTC-denominated yield-bearing asset is priced as if it were STX, producing a USD value that is off by orders of magnitude (BTC ≈ tens of thousands of dollars vs. STX ≈ low single digits).

### Finding Description
`get-asset-price` is the pricing helper for this utility/data contract, used to build USD notional values for collateral and debt via `sum-collateral-usd` and `sum-debt-usd`: [1](#0-0) [2](#0-1) 

The pricing dispatcher correctly assigns `PYTH-BTC` to `sBTC` and `zsBTC`, but for `stSTXbtc` and `zstSTXbtc` it calls `get-pyth-price PYTH-STX` — the STX feed — despite the inline comment reading "BTC price (liquid staked STX with BTC yield)": [3](#0-2) 

This is a straightforward feed-selection bug: the wrong Pyth price identifier constant (`PYTH-STX` at ~$1-2 instead of `PYTH-BTC` at ~$60,000) is wired to the `stSTXbtc`/`zstSTXbtc` asset IDs, causing every USD notional computed for these two assets through this helper to be understated by roughly the STX/BTC price ratio.

Note on scope of impact: I was only able to confirm that `get-asset-price` is consumed internally by `sum-collateral-usd` / `sum-debt-usd` inside this same `v0-1-data.clar` utility contract; I could not find any other in-scope contract (including `market/v0-4-market.clar`, which implements the actual borrow/collateral/liquidation health checks via its own oracle-registry-driven `resolve-price-feed`/`calculate-asset-notional-value` path) calling into this specific helper. The core lending health-check path in `v0-4-market.clar` resolves prices per-asset from the on-chain asset/oracle registry (`ident`, `type`, `callcode` fields set at asset registration), not from this hardcoded dispatcher, so I cannot conclusively prove this bug reaches the funds-moving borrow/withdraw/liquidation path — it is confirmed to corrupt whatever position summary / USD valuation endpoints this utility contract exposes (e.g., to front-ends, off-chain risk/liquidation bots, or DAO/reporting tooling that rely on it for a "wrong health verdict").

### Impact Explanation
If any consumer (frontend health-factor display, off-chain liquidation bot, or governance tooling) relies on this utility contract's `sum-collateral-usd`/`sum-debt-usd`/`get-asset-price` output to gauge account health for `stSTXbtc`/`zstSTXbtc` positions, it will see collateral value grossly understated (BTC price replaced by STX price) and would either (a) fail to recognize sufficient collateral backing debt, triggering unwarranted liquidations against the position holder (theft via liquidation penalty), or (b) if used on the debt side of a stSTXbtc-denominated loan, understate debt and misjudge accounts as healthy when they are not, delaying deserved liquidations and risking bad debt / protocol insolvency. This lands on the Critical impact class (protocol insolvency / theft via incorrect liquidation) if the data is consumed by any liquidation-triggering logic, though the exact consuming component could not be verified in the available index.

### Likelihood Explanation
The bug is deterministic and always triggers whenever `stSTXbtc` or `zstSTXbtc` valuation is queried through this helper — no attacker action or oracle manipulation is required, only that the affected code path be invoked by any client of this contract.

### Recommendation
In `mainnet/contracts/utility/v0-1-data.clar`, change the `stSTXbtc` and `zstSTXbtc` branches of `get-asset-price` to call `(get-pyth-price PYTH-BTC)` instead of `(get-pyth-price PYTH-STX)`, matching the existing `sBTC`/`zsBTC` branches and the inline comments' stated intent.

### Proof of Concept
1. Observe `get-asset-price` dispatch for `sBTC`: `(get-pyth-price PYTH-BTC)` — correct. [4](#0-3) 
2. Observe `get-asset-price` dispatch for `stSTXbtc`: `(get-pyth-price PYTH-STX)` — wrong feed for a BTC-yield asset. [5](#0-4) 
3. With `PYTH-STX` at, e.g., $1.20 and `PYTH-BTC` at $60,000, any `stSTXbtc`/`zstSTXbtc` position valued through `sum-collateral-usd`/`sum-debt-usd` will report a USD value ~50,000x lower than the true BTC-denominated value, producing a wrong health verdict for that asset wherever this helper's output is consumed.
