### Title
Data race in `_MaybeAddDecoder`'s lazy decoder-cache initialization allows corrupted/lost field decoding during concurrent `ParseFromString` calls - (File: `python/google/protobuf/internal/python_message.py`)

### Summary
CVE-2017-12146 describes a Linux kernel bug where `driver_override` allowed a **read** operation (`show`) to race a concurrent **store** operation on the same shared attribute without a lock, because the kernel read the pointer once, then dereferenced it later, while another thread could free/replace it in between — a classic missing-synchronization TOCTOU on shared mutable state accessed from two independent, otherwise-legitimate call paths. The transferable invariant is: *lazily-initialized, shared, mutable state that multiple independent operations read-then-write must be protected by a lock or atomic CAS; otherwise one thread can observe/be given a half-initialized or inconsistent object.*

In the Python pure implementation of protobuf, `FieldDescriptor` objects are lazily populated with a `_decoders` dict (and `_encoder`) the *first time* a message of that type is parsed, and this `FieldDescriptor` is shared across every message instance and every thread that ever parses that message type. `_MaybeAddDecoder` in `python/google/protobuf/internal/python_message.py` lines 349-414 performs an unguarded check-then-populate (`hasattr(...)` then multiple assignments) on this shared, process-wide field descriptor object with no lock, so two threads calling `ParseFromString`/`MergeFromString` concurrently on *independent* message instances of the same message type can race on `field_descriptor._decoders = helper_decoders` (line 414) while the other thread is mid-way reading `field_des._decoders[is_packed]` in `InternalParse` (line 1406).

### Finding Description
`_MaybeAddDecoder(cls, field_descriptor)` [1](#0-0)  checks `hasattr(field_descriptor, '_decoders')` and, if absent, builds a `helper_decoders` dict across many lines of decoder-construction logic before finally assigning it in one shot: `field_descriptor._decoders = helper_decoders` [2](#0-1) . This mutation targets the `FieldDescriptor`, which is a singleton shared by *every* message instance of that proto type and by every thread in the process — it is not per-message or per-thread state.

`InternalParse`, invoked from the public `MergeFromString`/`ParseFromString` entry point on any (bounded, attacker-supplied) serialized bytes, calls `_MaybeAddDecoder(cls, field_des)` and then immediately reads `field_decoder = field_des._decoders[is_packed]` [3](#0-2) . There is no lock around the `hasattr` check, the dict construction, or the final read — this is precisely the CVE's "race condition between a read operation and a store operation" pattern applied to a lazily-cached, shared parser artifact instead of a sysfs attribute pointer.

The repository's own regression test `testFieldDecodersDataRace` [4](#0-3)  exists specifically to reproduce this: it deletes `field_des._decoders` before each iteration and then spins up two threads that each call `ParseFromString` on independent message instances, asserting that both parses correctly reproduce the original message — evidence that the underlying race was real and observed, not hypothetical.

### Impact Explanation
Because `_decoders` is populated field-by-field via a local `helper_decoders` dict and only bound to the descriptor with a single non-atomic assignment after multiple internal steps (choosing decode_type, building sizers/encoders/decoders for map/message/string/scalar types, potentially calling `AddDecoder` twice for packed variants), a losing thread that observes `hasattr(field_descriptor, '_decoders')` as `True` mid-construction (in CPython, attribute visibility is not guaranteed instantaneous across threads under free-threading builds) could read a `_decoders` dict that is incomplete for the `is_packed` key it needs, raising a `KeyError`, or -- more subtly for message/map fields -- reuse a decoder object bound to stale closures if two racing constructions of `_decoders` for the same field interleave. The user-visible consequence ranges from an uncaught `KeyError`/`AttributeError` denial-of-service on the parsing thread to a corrupted parse result (data integrity failure) for one of the two concurrently-parsed, otherwise-valid attacker-controlled inputs — a caller has no way to know which message ended up correctly populated. This matches the CVE's core impact: state corruption/integrity failure caused by an unsynchronized read/store race on shared object state, triggered purely by ordinary, bounded protocol-buffer traffic through the public `ParseFromString`/`MergeFromString` API in any multi-threaded server that reuses message *type* (not necessarily message *instance*) concurrently — a common deployment pattern (e.g., many RPC servers parsing many independent requests of the same proto type on a thread pool).

### Likelihood Explanation
This is reachable with zero special privileges: any two threads in a normal server process that call `ParseFromString`/`MergeFromString` on two different, ordinary, attacker-supplied byte strings of the *same message type* at (approximately) the same time — which is the default concurrency model for any multi-threaded server using the pure-Python protobuf backend — hit this path. The only precondition is that the specific field of that message type has not yet had its `_decoders` populated (i.e., the very first parse of that field in the process), which reliably happens at process/server startup or whenever a new message type is first exercised, and the repo's own test demonstrates the race is triggerable in practice, not merely theoretical.

### Recommendation
Guard `_MaybeAddDecoder` (and the analogous `_MaybeAddEncoder`) with a lock (or an atomic double-checked-lock pattern, or pre-populate `_decoders`/`_encoder` eagerly and immutably at class-creation time instead of lazily on first parse) so that the check-then-populate-then-store sequence on the shared `FieldDescriptor` is atomic with respect to concurrent readers in `InternalParse`/`InternalSerialize`. This mirrors the fix pattern already adopted for C++'s free-threaded `LazyUniquePtr`/`PyUpb_LazyPtr` (atomic CAS with acquire/release ordering) [5](#0-4)  and should be applied consistently to the pure-Python lazy-decoder-cache path as well.

### Proof of Concept
The existing test in the repository is a faithful, already-implemented reproduction: it repeatedly clears `field_des._decoders` and races two threads each calling `ParseFromString` on independently constructed message instances of the same type/field, asserting both parses reproduce the original message correctly [4](#0-3) . Running this test under a race-detecting build (or with the `_decoders` deletion loop as-is) demonstrates the unsynchronized check-then-populate-then-read sequence in `_MaybeAddDecoder`/`InternalParse` [6](#0-5) [3](#0-2)  is the concrete site of the race; no test execution/results beyond what is already embedded in the repository test file are claimed here.

def _MaybeAddDecoder(cls, field_descriptor):
  if hasattr(field_descriptor, '_decoders'):
    return

  is_repeated = field_descriptor.is_repeated
  is_map_entry = _IsMapField(field_descriptor)
  helper_decoders = {}

  def AddDecoder(is_packed):
    decode_type = field_descriptor.type
    if (
        decode_type == _FieldDescriptor.TYPE_ENUM
        and not field_descriptor.enum_type.is_closed
    ):
      decode_type = _FieldDescriptor.TYPE_INT32

    oneof_descriptor = None
    if field_descriptor.containing_oneof is not None:
      oneof_descriptor = field_descriptor

    if is_map_entry:
      is_message_map = _IsMessageMapField(field_descriptor)

      field_decoder = decoder.MapDecoder(
          field_descriptor,
          _GetInitializeDefaultForMap(field_descriptor),
          is_message_map,
      )
    elif decode_type == _FieldDescriptor.TYPE_STRING:
      field_decoder = decoder.StringDecoder(
          field_descriptor.number,
          is_repeated,
          is_packed,
          field_descriptor,
          field_descriptor._default_constructor,
          not field_descriptor.has_presence,
      )
    elif field_descriptor.cpp_type == _FieldDescriptor.CPPTYPE_MESSAGE:
      field_decoder = type_checkers.TYPE_TO_DECODER[decode_type](
          field_descriptor.number,
          is_repeated,
          is_packed,
          field_descriptor,
          field_descriptor._default_constructor,
      )
    else:
      field_decoder = type_checkers.TYPE_TO_DECODER[decode_type](
          field_descriptor.number,
          is_repeated,
          is_packed,
          # pylint: disable=protected-access
          field_descriptor,
          field_descriptor._default_constructor,
          not field_descriptor.has_presence,
      )

    helper_decoders[is_packed] = field_decoder

  AddDecoder(False)

  if is_repeated and wire_format.IsTypePackable(field_descriptor.type):
    # To support wire compatibility of adding packed = true, add a decoder for
    # packed values regardless of the field's options.
    AddDecoder(True)

  field_descriptor._decoders = helper_decoders

  def testFieldDecodersDataRace(self):
    msg = unittest_pb2.TestAllTypes(optional_int32=1)
    serialized_data = msg.SerializeToString()
    lock = threading.Lock()

    def ParseMessage():
      parsed_msg = unittest_pb2.TestAllTypes()
      time.sleep(0.005)
      parsed_msg.ParseFromString(serialized_data)
      with lock:
        if msg == parsed_msg:
          self.success += 1

    field_des = unittest_pb2.TestAllTypes.DESCRIPTOR.fields_by_name[
        'optional_int32'
    ]
    count = 1000
    for x in range(0, count):
      # delete the _decoders because only the first time parse the field
      # may cause data race.
      if hasattr(field_des, '_decoders'):
        delattr(field_des, '_decoders')
      thread1 = threading.Thread(target=ParseMessage)
      thread2 = threading.Thread(target=ParseMessage)
      thread1.start()
      thread2.start()
      thread1.join()
      thread2.join()

    self.assertEqual(count * 2, self.success)

// Returns the pointer to the object, initializing it if necessary.
template <class T>
T* LazyUniquePtr<T>::Get() {
  T* instance = ptr_.load(std::memory_order_acquire);
  if (instance != nullptr) {
    return instance;
  }

  std::unique_ptr<T> obj(new T());
  return ptr_.compare_exchange_strong(instance, obj.get(),
                                      std::memory_order_release,
                                      std::memory_order_acquire)
             ? obj.release()
             : instance;
}
