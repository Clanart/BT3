## Analysis

This maps to the reported bug class well: like the BAT crowdsale contract overloading the semantics of the `Transfer` event (an unauthenticated log field trusted by external consumers to mean "who minted/owns tokens"), Clementine's payout-attribution logic trusts an **unsigned `OP_RETURN` data field** inside the `payout_tx` to mean "which operator fronted this withdrawal" — without any cryptographic binding tying that field to the party that actually funded the transaction.

### Title
Payout attribution relies on an unauthenticated OP_RETURN field not covered by the user's signature - (File: core/src/verifier.rs)

### Summary
The bridge determines which operator is credited (and later reimbursed from the vault) for a withdrawal payout purely by parsing an `OP_RETURN` output embedded in the confirmed `payout_tx`. This field is not covered by the user's authorizing signature and is not otherwise validated against whoever actually funded/broadcast the transaction, breaking the binding `credited_operator == party_that_paid`.

### Finding Description
The user's withdrawal-authorizing signature is required to use `TapSighashType::SinglePlusAnyoneCanPay`, which only commits to the signed input and the output at the same index (index 0, the user payout output): [1](#0-0) [2](#0-1) 

`create_payout_txhandler` appends a third output — an `OP_RETURN` embedding `operator_xonly_pk` — which is *not* covered by this signature and is not signed by anyone at all: [3](#0-2) 

Because `SinglePlusAnyoneCanPay` also permits arbitrary additional inputs (`AnyoneCanPay`), any party possessing the user's authorizing signature (shared "off-chain to operators" per the protocol's own documentation, and ultimately derived from data visible on the public Citrea rollup) can construct their own version of the payout transaction — funding it with their own money, keeping the required signed input and output[0] intact — while writing an arbitrary value into the `OP_RETURN` field.

Verifiers later scan confirmed payout transactions and blindly trust this field as authoritative for "who paid": [4](#0-3) 

This attribution is written into the `withdrawals` table and is the *sole* mechanism used to route reimbursement: [5](#0-4) [6](#0-5) [7](#0-6) 

`PayoutCheckerTask` for a given operator only proceeds if its own key matches `payout_payer_operator_xonly_pk`: [8](#0-7) 

### Impact Explanation
Before the attacker's transaction: `payout_payer_operator_xonly_pk == funder_of_payout_tx` should hold, i.e. whichever party actually spent BTC to satisfy the user's withdrawal is the one entitled to later reimbursement from the deposit's move-to-vault UTXO.

After the attacker crafts and gets mined a payout transaction with the required signed input/output[0] but an arbitrary/mismatched `OP_RETURN` value:
- If the embedded key matches a real, unrelated registered operator, that operator's `PayoutCheckerTask` will pick up the payout as its own, allocate a kickoff connector, and eventually receive the bridge-amount `Reimburse` output — **an operator reimbursed for a payout it never funded** — even though a third party actually paid the user.
- If the embedded key is invalid or matches no operator, `payout_payer_operator_xonly_pk`/`operator_xonly_pk` resolves to `None`/unmatched, and no operator's `get_first_unhandled_payout_by_operator_xonly_pk` query ever picks up the payout, so `handle_finalized_payout` is never invoked by anyone — **the party that genuinely fronted the withdrawal can never be reimbursed**, and the deposit's vault UTXO's reimbursement path is never triggered by any operator's tracked round-state despite the withdrawal already being satisfied on L1.

Both outcomes are Critical-severity per the custody-binding rules: a reimbursement is created for an entity that did not fund the corresponding payout, or an honest funder is permanently denied the reimbursement it is entitled to.

### Likelihood Explanation
The attack requires only: (1) knowledge of the user's `SinglePlusAnyoneCanPay` signature for a pending withdrawal (obtainable from the public Citrea withdrawal request or from observing any operator's broadcast attempt in the mempool), (2) enough BTC to front the withdrawal output and fee via additional inputs (permitted by `AnyoneCanPay`), and (3) the ability to broadcast a standard Bitcoin transaction. No verifier, operator, watchtower, aggregator, or security-council role, and no key compromise, is required — the `OP_RETURN` field is architecturally unauthenticated by design.

### Recommendation
Cryptographically bind the operator attribution to the actual signer/funder of the payout transaction rather than trusting free-form `OP_RETURN` data. For example, require the embedded operator identity to be proven via a signature over the full transaction (or at least over all its outputs, e.g. `SIGHASH_ALL` for the operator's own funding inputs) so that the credited operator is provably the party who supplied the funding inputs, and reject/ignore payout transactions where the `OP_RETURN` operator key cannot be attributed to whoever actually signed the additional funding inputs.

### Proof of Concept
1. Observe/obtain the user's `SinglePlusAnyoneCanPay` withdrawal signature and associated `input_outpoint`/`output_script_pubkey`/`output_amount` for withdrawal `W` (public via Citrea, or visible once any operator broadcasts an attempt).
2. Build a transaction: input[0] = the withdrawal UTXO with the harvested signature; output[0] = the exact required user payout (satisfies the `SinglePlusAnyoneCanPay` sighash check in `withdraw`/`create_payout_txhandler`); add attacker-funded extra input(s) to cover fee/amount (`AnyoneCanPay` permits this); output[2] = `OP_RETURN` containing an arbitrary or victim operator's `xonly_pk`.
3. Broadcast with sufficient fee/priority to get mined ahead of/instead of the legitimate operator's version.
4. `update_finalized_payouts` (core/src/verifier.rs) parses the attacker-chosen `OP_RETURN` and stores it as `payout_payer_operator_xonly_pk`, causing either misattributed reimbursement to the embedded operator or a permanently unattributed payout, per the Impact section above.

#[allow(clippy::result_large_err)]
pub fn parse_withdrawal_sig_params(
    params: WithdrawParams,
) -> Result<(u32, taproot::Signature, OutPoint, ScriptBuf, Amount), Status> {
    let mut input_signature =
        taproot::Signature::from_slice(&params.input_signature).map_err(|e| {
            Status::invalid_argument(format!("Can't convert input to taproot Signature - {e}"))
        })?;

    // If the Taproot sighash type is Default (no explicit type attached; i.e. a 64-byte
    // signature without a sighash flag), normalize it to SinglePlusAnyoneCanPay.
    // Prior to v0.5 this was Clementine's implicit behavior; we retain it here for
    // backwards compatibility when a 64-byte signature is provided.
    if input_signature.sighash_type == TapSighashType::Default {
        tracing::warn!(
            "Input signature for withdrawal {} has sighash type default, setting to SinglePlusAnyoneCanPay", params.withdrawal_id,
        );
        input_signature.sighash_type = TapSighashType::SinglePlusAnyoneCanPay;
    }

    // enforce sighash type here
    if input_signature.sighash_type != TapSighashType::SinglePlusAnyoneCanPay {
        return Err(Status::invalid_argument(format!(
            "Input signature has wrong sighash type, SinglePlusAnyoneCanPay expected, got {}",
            input_signature.sighash_type
        )));
    }

    let input_outpoint: OutPoint = params
        .input_outpoint
        .ok_or_else(error::input_ended_prematurely)?
        .try_into()?;

    let users_intent_script_pubkey = ScriptBuf::from_bytes(params.output_script_pubkey);

    Ok((
        params.withdrawal_id,
        input_signature,
        input_outpoint,
        users_intent_script_pubkey,
        Amount::from_sat(params.output_amount),
    ))
}

        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self

            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

        tracing::info!(
            "Payer xonly pk, payout blockhash and kickoff txid found and valid for own operator for the requested deposit id: {}, payer xonly pk: {:?}, payout blockhash: {:?}, kickoff txid: {:?}",
            deposit_id,
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid
        );

        Ok((payout_blockhash, kickoff_txid))
    }

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    pub async fn get_first_unhandled_payout_by_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        operator_xonly_pk: XOnlyPublicKey,
    ) -> Result<Option<(u32, Txid, BlockHash)>, BridgeError> {
        let query = sqlx::query_as::<_, (i32, Option<TxidDB>, Option<BlockHashDB>)>(
            "SELECT w.idx, w.move_to_vault_txid, w.payout_tx_blockhash
             FROM withdrawals w
             WHERE w.payout_txid IS NOT NULL
                AND w.is_payout_handled = FALSE
                AND w.payout_payer_operator_xonly_pk = $1
                ORDER BY w.idx ASC
             LIMIT 1",
        )
        .bind(XOnlyPublicKeyDB(operator_xonly_pk));

        let results = execute_query_with_tx!(self.connection, tx, query, fetch_optional)?;

        results
            .map(|(citrea_idx, move_to_vault_txid, payout_tx_blockhash)| {
                Ok((
                    u32::try_from(citrea_idx).wrap_err("Failed to convert citrea index to u32")?,
                    move_to_vault_txid
                        .expect("move_to_vault_txid Must be Some")
                        .0,
                    payout_tx_blockhash
                        .expect("payout_tx_blockhash Must be Some")
                        .0,
                ))
            })
            .transpose()
    }
