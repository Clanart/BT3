### Title
Git credential helper classifies arbitrary HTTP remotes as "GitHub Enterprise" based on an attacker-controlled `WWW-Authenticate` header, bypassing real host verification - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
GitHub Desktop's credential trampoline decides whether a Git remote is a trusted GitHub/GitHub Enterprise host using `getEndpointKind`. For non-`github.com`/`ghe.com` hosts, it inspects the `WWW-Authenticate` response header that the *remote server itself* returns during Git's HTTP auth negotiation. If the header value contains `realm="GitHub"`, the endpoint is immediately trusted as `'enterprise'` — short-circuiting the independent `isGitHubHost()` verification that is otherwise performed for unrecognized hosts. This mirrors the reported bug class: a security-relevant classification ("is this a legitimate GitHub endpoint", analogous to "is this stablecoin still pegged") is taken from a self-reported, attacker-controlled signal instead of being independently verified, and the app proceeds to act (prompting a trusted "Sign in to GitHub" flow) as if that classification were ground truth.

### Finding Description
`getEndpointKind` in [1](#0-0)  determines how Desktop treats a Git remote for credential purposes:

- It first checks well-known first-party hosts (`isGist`, `isDotCom`, `isGHE`) — these are safe, hardcoded checks.
- For any other host, it inspects the credential map for keys starting with `wwwauth[` (populated from HTTP `WWW-Authenticate` headers forwarded by Git) and, if any value contains `realm="GitHub"`, returns `'enterprise'` **without further verification**.
- Only if none of the `wwwauth[` entries match does it fall through to `isGitHubHost(endpoint)`, a presumably stronger, independent check.

Because `WWW-Authenticate` is a header emitted by the remote server (or any network intermediary/proxy responding to the Git HTTP request), an attacker fully controls its content. Setting `WWW-Authenticate: Basic realm="GitHub"` on any HTTP(S) git server is trivial and causes `getEndpointKind` to classify that arbitrary host as `'enterprise'`, bypassing the `isGitHubHost` check that exists specifically to validate this class of host.

This classification then drives `getCredential` in [2](#0-1) : if the endpoint kind is not `'generic'` and no existing account matches that endpoint, Desktop calls `ui.promptForGitHubSignIn(endpoint)` (line 118), i.e., the *trusted* GitHub sign-in UI is invoked and bound to the attacker's endpoint, and any resulting account is fused into the outgoing credential via `credWithAccount`.

### Impact Explanation
A user who clones or fetches from a Git remote (URL the user pasted, a link they clicked, or a URL embedded in a repository's configured remotes/submodules) that is served or proxied by an attacker gets shown Desktop's native "Sign in to GitHub" dialog for a host that is not actually GitHub. Because the dialog is Desktop's own trusted UI, this can be used to:
- Bind a legitimate GitHub OAuth/account session to an attacker-designated "enterprise" endpoint (unauthorized account binding), and/or
- Have the resulting token subsequently sent back to the attacker's Git server as an HTTP Basic credential when Desktop performs the Git operation, exfiltrating the OAuth/PAT token to the attacker.

This satisfies the reported "unprivileged, remote/proxy-response-controlled data used for a security decision" class, and maps to "unauthorized OAuth or account binding" / "credential exfiltration" in the accepted impact list.

### Likelihood Explanation
Likelihood is moderate: it requires the user to add/clone/fetch from an HTTP(S) remote controlled by (or proxied through) an attacker — a normal, unprivileged workflow (no local access, no malware, no leaked credentials). The trigger (setting a response header) is trivial for any server operator or on-path proxy to add. The main mitigating factor is that the user still has to interact with a sign-in prompt, but the prompt is presented as Desktop's standard, trusted GitHub sign-in flow, making it a highly convincing pretext (the endpoint URL show is the only user-visible cue).

### Recommendation
- **Short term:** Remove reliance on the self-reported `WWW-Authenticate` realm string as sufficient evidence of a GitHub/Enterprise host. Always require the independent `isGitHubHost(endpoint)` API-based check before classifying an unknown host as `'enterprise'`, or at minimum require both signals to agree.
- **Long term:** When prompting for GitHub sign-in for a non-hardcoded endpoint, make the risk explicit to the user (e.g., clearly indicate that the host is not `github.com`/known GHE domain and that Desktop cannot verify its authenticity), and avoid auto-classifying arbitrary remotes as trusted GitHub Enterprise instances purely from response metadata that the remote fully controls.

### Proof of Concept
1. Stand up an HTTP git server (or MITM proxy) at `https://attacker.example/repo.git` that, on Git's credential probe request, responds with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
2. In GitHub Desktop, clone `https://attacker.example/repo.git` (an ordinary, unprivileged clone action).
3. Git invokes the trampoline credential helper; `getCredential` → `getEndpointKind` ( [3](#0-2) ) matches the `wwwauth[...]` header and returns `'enterprise'` without calling `isGitHubHost`.
4. Since no account exists for `apiEndpoint` derived from `attacker.example`, Desktop shows `ui.promptForGitHubSignIn(endpoint)` — the standard trusted GitHub sign-in dialog — bound to the attacker's endpoint.
5. If the user completes sign-in, the resulting account/token is merged into the credential (`credWithAccount`) and can be delivered to `attacker.example` on the Git request, and/or persisted as an account entry bound to that endpoint.

Note: I was not able to fully inspect the implementation of `isGitHubHost()` in `app/src/lib/api.ts` within the available tool budget, so the exact strength of the bypassed fallback check (e.g., whether it performs a genuine `/meta` API call) is inferred from naming and usage context rather than directly confirmed.

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

  // GitHub.com/GHE creds are only stored internally
  if (endpointKind !== 'generic') {
    return undefined
  }

  return useExternalCredentialHelper()
    ? getExternalCredential(cred, token)
    : getGenericCredential(cred, token)
}

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
