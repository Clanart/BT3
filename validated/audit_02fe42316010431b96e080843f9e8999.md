## Title
Auction bid signatures bypass Kaia's AccountKey revocation system, allowing forged bids after a searcher rotates/revokes their key - (File: kaiax/auction/bid.go)

### Summary
The advisory describes Casdoor's `GetTokenExchangeToken()` validating a JWT's signature/claims but never checking whether the underlying credential (the token) has been revoked. The closest reachable analog in this Kaia codebase is the KIP-249 auction bid pool: `Bid.ValidateSearcherSig()` verifies a raw ECDSA signature against `bid.Sender` using plain `crypto.SigToPub`/`crypto.PubkeyToAddress` recovery, completely bypassing Kaia's `accountkey` authorization framework that governs whether a given private key is still an authorized signer for that address.

### Finding Description
Every ordinary Kaia transaction type is validated through `accountkey.ValidateAccountKey`, which checks the account's current `AccountKey` (e.g., after a `TxTypeAccountUpdate`/`TxTypeFeeDelegatedAccountUpdate` "role rotation", or a role-based/multisig key configuration) to determine whether a signing key is still authorized for a given role: [1](#0-0) 

The tx pool actively enforces this: once an account's key is rotated via `TxTypeAccountUpdate`, transactions signed with the old key are rejected and pending transactions signed with the old key are dropped from the pool on reset: [2](#0-1) [3](#0-2) 

In contrast, the auction module's bid-signature verification is a self-contained ECDSA recovery routine that never consults `AccountKeyPicker`/`accountkey.ValidateAccountKey` or any statedb-backed authorization check at all: [4](#0-3) [5](#0-4) 

This check is invoked from `validateBidSigs`, which is the only authorization gate applied before a bid is admitted into the bid pool: [6](#0-5) 

Because `getSigner` performs raw secp256k1 recovery and compares the recovered address to `bid.Sender` directly — with no lookup of `bid.Sender`'s current `AccountKey` in state — any private key that was ever associated with `bid.Sender` (e.g., the original EOA key before the account switched to a role-based or multisig `AccountKey` via `TxTypeAccountUpdate`) remains permanently capable of producing a "valid" bid for that address, indefinitely, even though the address's authorization policy has been intentionally revoked/rotated at the protocol level.

### Impact Explanation
A bid accepted by the pool is turned into a real `TxTypeEthereumDynamicFee` call to `AuctionEntryPoint` and injected as a bundle right after the target transaction, executed with the searcher's `bid.Sender` context: [7](#0-6) [8](#0-7) 

Since the `AuctionEntryPoint` contract call is expected to withdraw/settle the bid amount from the searcher's account and execute the searcher's calldata (per KIP-249's design, as reflected in the mock in `AuctionEntryPointMock.sol`), an attacker who once held a private key for an address — before that address's owner rotated to a role-based/multisig `AccountKey` specifically to invalidate the old key — can still forge bids and cause fund movement out of that address's session/allowance in the entry point, or otherwise force execution of attacker-chosen calldata attributed to a supposedly-revoked signer. This is a fee/settlement and unauthorized-value-movement impact directly reachable by any auction bidder/searcher-facing caller through the public `auction_submitBid` RPC, matching the "acceptance of a transaction from a revoked credential" bug class in the report.

### Likelihood Explanation
Likelihood is moderate: it requires that (a) a searcher's EOA key was compromised or intentionally retired, and (b) the account owner relied on Kaia's `TxTypeAccountUpdate` mechanism (the documented, first-class way to invalidate a compromised/retired key in this codebase) to revoke it, believing this fully deauthorizes the old key across the protocol. Because the auction subsystem's bid verification never re-derives authorization from the account's current `AccountKey`, this reasonable assumption is violated specifically within the auction/bid-settlement path, while it holds for every other transaction type in the system.

### Recommendation
In `validateBidSigs` (and `ValidateSearcherSig`), after recovering the signer's public key, additionally look up `bid.Sender`'s current `AccountKey` from state (via the same `AccountKeyPicker`/`accountkey.ValidateAccountKey` used elsewhere in the codebase) and reject the bid if the recovered public key is not an authorized signer under the account's *current* key configuration, mirroring the enforcement already done for ordinary Kaia transactions in `Transaction.ValidateSender`.

### Proof of Concept
1. Address `S` initially has a legacy `AccountKeyPublic` derived from private key `k1`.
2. `S` submits `TxTypeAccountUpdate` to rotate to `AccountKeyRoleBased` (revoking `k1`, authorizing only new keys) — this is enforced for normal txs per `TestAccountUpdateRoleBasedTransition`.
3. An attacker who retains `k1` (e.g., it leaked before rotation) crafts a `Bid{Sender: S, ...}`, computes `GetHashTypedData(...)`, and signs it with `k1` to produce `SearcherSig`, then obtains/forges a valid `AuctioneerSig` (or colludes with a malicious/compromised auctioneer) and calls `auction_submitBid`.
4. `bp.validateBidSigs` → `bid.ValidateSearcherSig` recovers `k1`'s address, which equals `S`, and passes — despite `S`'s `AccountKey` no longer authorizing `k1`.
5. The bid is admitted, bundled via `ExtractTxBundles`/`GetBidTxGenerator`, and executed on-chain as `S`, causing settlement/value movement attributed to `S` using a key that was supposed to be revoked.

func (tx *Transaction) ValidateSender(signer Signer, p AccountKeyPicker, currentBlockNumber uint64) (uint64, error) {
	if tx.IsEthereumTransaction() {
		addr, err := Sender(signer, tx)
		// Legacy transaction cannot be executed unless the account has a legacy key.
		if p.GetKey(addr).Type().IsLegacyAccountKey() == false {
			return 0, kerrors.ErrLegacyTransactionMustBeWithLegacyKey
		}
		tx.mu.Lock()
		if tx.validatedSender == (common.Address{}) {
			tx.validatedSender = addr
			tx.validatedFeePayer = addr
		}
		tx.mu.Unlock()
		return 0, err
	}

	pubkey, err := SenderPubkey(signer, tx)
	if err != nil {
		return 0, err
	}
	txfrom, ok := tx.data.(TxInternalDataFrom)
	if !ok {
		return 0, errNotTxInternalDataFrom
	}
	from := txfrom.GetFrom()
	accKey := p.GetKey(from)

	gasKey, err := accKey.SigValidationGas(currentBlockNumber, GetRoleTypeForValidation(tx.Type()), len(pubkey))
	if err != nil {
		return 0, err
	}

	if err := accountkey.ValidateAccountKey(currentBlockNumber, from, accKey, pubkey, GetRoleTypeForValidation(tx.Type())); err != nil {
		return 0, ErrInvalidAccountKey
	}

func (b *Bid) ValidateSearcherSig(chainId *big.Int, verifyingContract common.Address, version string) error {
	if chainId == nil {
		return ErrNilChainId
	}

	if common.EmptyAddress(verifyingContract) {
		return ErrNilVerifyingContract
	}

	digest := b.GetHashTypedData(chainId, verifyingContract, version)

	recoveredSender, err := getSigner(b.SearcherSig, digest)
	if err != nil {
		return fmt.Errorf("failed to recover searcher sig: %v", err)
	}

	if recoveredSender != b.Sender {
		return fmt.Errorf("invalid searcher sig: expected %v, calculated %v", b.Sender.String(), recoveredSender.String())
	}

	return nil
}

func getSigner(sig, digest []byte) (common.Address, error) {
	// Manually convert V from 27/28 to 0/1
	copiedSig := slices.Clone(sig)
	if copiedSig[crypto.RecoveryIDOffset] == 27 || copiedSig[crypto.RecoveryIDOffset] == 28 {
		copiedSig[crypto.RecoveryIDOffset] -= 27
	}

	v := copiedSig[crypto.RecoveryIDOffset]
	r := new(big.Int).SetBytes(copiedSig[0:32])
	s := new(big.Int).SetBytes(copiedSig[32:64])
	if !crypto.ValidateSignatureValues(v, r, s, true) {
		return common.Address{}, ErrInvalidSignature
	}

	pub, err := crypto.SigToPub(digest, copiedSig)
	if err != nil {
		return common.Address{}, err
	}
	return crypto.PubkeyToAddress(*pub), nil
}

func (bp *BidPool) validateBidSigs(bid *auction.Bid) error {
	bp.auctionInfoMu.RLock()
	defer bp.auctionInfoMu.RUnlock()

	if bid.SearcherSig == nil || len(bid.SearcherSig) != crypto.SignatureLength {
		return auction.ErrInvalidSearcherSig
	}
	if bid.AuctioneerSig == nil || len(bid.AuctioneerSig) != crypto.SignatureLength {
		return auction.ErrInvalidAuctioneerSig
	}

	// Verify the EIP712 signature.
	if err := bid.ValidateSearcherSig(bp.ChainConfig.ChainID, bp.auctionEntryPoint, bp.auctionEntryPointVersion); err != nil {
		return err
	}

	// Verify the auctioneer signature.
	if err := bid.ValidateAuctioneerSig(bp.auctioneer); err != nil {
		return err
	}

	return nil
}

func (a *AuctionModule) GetBidTxGenerator(tx *types.Transaction, bid *auction.Bid) *builder.TxOrGen {
	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId           = a.InitOpts.ChainConfig.ChainID
			signer            = types.LatestSignerForChainID(chainId)
			auctionEntryPoint = a.bidPool.GetAuctionEntryPoint()
			key               = a.InitOpts.NodeKey
		)

		data, err := system.EncodeAuctionCallData(bid, a.bidPool.GetAuctionEntryPointVersion())
		if err != nil {
			return nil, err
		}

		if bid.GetGasLimit() == 0 {
			gasLimit, err := a.bidPool.getBidTxGasLimit(bid)
			if err != nil {
				return nil, err
			}
			bid.SetGasLimit(gasLimit)
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &auctionEntryPoint,
			types.TxValueKeyAmount:     common.Big0,
			types.TxValueKeyData:       data,
			types.TxValueKeyGasLimit:   bid.GetGasLimit(),
			types.TxValueKeyGasFeeCap:  tx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  tx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)

		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bid.Hash())

func (a *AuctionModule) ExtractTxBundles(txs []*types.Transaction, prevBundles []*builder.Bundle) []*builder.Bundle {
	bundles := []*builder.Bundle{}
	curBlock := a.Chain.CurrentBlock()
	if curBlock == nil || atomic.LoadUint32(&a.bidPool.running) == 0 {
		return bundles
	}

	miningBlock := curBlock.NumberU64() + 1
	bidTargetMap := a.bidPool.GetTargetTxMap(miningBlock)
	if len(bidTargetMap) == 0 {
		return bundles
	}

	for _, tx := range txs {
		txHash := tx.Hash()
		bid, ok := bidTargetMap[txHash]
		if !ok {
			continue
		}
		b := builder.NewBundle(
			builder.NewTxOrGenList(a.GetBidTxGenerator(tx, bid)),
			txHash,
			true,
		)

		isConflict := false
		for _, prev := range append(prevBundles, bundles...) {
			if prev.IsConflict(b) {
				isConflict = true
				break
			}
		}
		if isConflict {
			continue
		}
		bundles = append(bundles, b)
	}

	return bundles
}
