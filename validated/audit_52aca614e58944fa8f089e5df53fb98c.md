## Finding

Coolify's bug class — server/project IDs looked up without checking they belong to the caller's team — has a direct analog in Chia's daemon keychain RPC: keychain lookups are scoped by an attacker-supplied `kc_user`/`kc_service` pair taken straight from the request body, with no check that it matches the identity of the connecting client.

### Title
Keychain RPC lookups are scoped by client-supplied `kc_user`/`kc_service` instead of caller identity, allowing cross-keychain private key disclosure - (File: `chia/daemon/keychain_server.py`)

### Summary
`KeychainServer.get_keychain_for_request()` selects which `Keychain` instance (and therefore whose private keys/mnemonics) to operate on purely from the `kc_user`/`kc_service` fields embedded in the incoming JSON request, never from any property of the authenticated websocket connection. Any local process that can open a websocket to the daemon can therefore request key material for an arbitrary `kc_user`/`kc_service` namespace it does not own, exactly mirroring the Coolify pattern of trusting a client-supplied identifier instead of the caller's actual scope.

### Finding Description
`KeychainServer.get_keychain_for_request()` builds the target `Keychain` from `request.get("kc_user", ...)` and `request.get("kc_service", ...)` with no cross-check against the requester's own session/service identity: [1](#0-0) 

`WebSocketServer.handle_message()` routes any command in `keychain_commands` straight to `KeychainServer.handle_command()` without attaching or verifying any caller-identity context — the daemon-level gate is only the shared mutual-TLS certificate used by every local service (wallet, farmer, harvester, timelord, CLI, GUI) connecting to the same daemon: [2](#0-1) 

`KeychainProxy.format_request()` normally sets `kc_user`/`kc_service` from the proxy's own configuration when a legitimate client makes a request: [3](#0-2) 

but nothing in `handle_command`/`run_request`/`get_key_for_fingerprint`/`get_all_private_keys` enforces that the value actually matches the caller who is entitled to it — a raw request dict sent over the same daemon websocket can set `kc_user`/`kc_service` to any value: [4](#0-3) [5](#0-4) 

`GetKeyRequest.run()` with `include_secrets=True` returns the full `KeyData` (including the private key/mnemonic entropy) for the resolved keychain, and `run_request()` dispatches this without any additional authorization check beyond `is_keyring_locked()`: [6](#0-5) [7](#0-6) 

This is the same root-cause shape as the Coolify CVE: a resource lookup (`Keychain` instance / private-key material) is selected by a client-supplied identifier (`kc_user`/`kc_service`) instead of being scoped to the identity that the shared authentication mechanism (mTLS cert here, team login there) actually establishes.

### Impact Explanation
The daemon keeps multiple keychain namespaces (`kc_user`/`kc_service` pairs) alive simultaneously in `_alt_keychains`, intended for multiple local chia app instances/users sharing one daemon. Any local RPC caller that can reach the daemon websocket (holding the daemon's shared client certificate, which every co-located chia service already possesses) can request `get_key`/`get_keys` with `include_secrets=True` for a different `kc_user`/`kc_service` than its own, exfiltrating mnemonics/private keys belonging to another local user or app instance. Possession of the private key is equivalent to full custody of that wallet's coins, enabling unauthorized coin movement — directly analogous to Coolify's SSH key exposure through unscoped IDs.

### Likelihood Explanation
Exploitation requires only the ability to open a websocket connection to the local daemon with a valid daemon client certificate — something every co-located chia service (wallet, farmer, harvester, timelord, or any third-party plugin/process using the shared certs) already has by design in a multi-service/multi-user local deployment. No additional privilege beyond normal local-service connectivity is required, and the vulnerable code path (`get_keychain_for_request`) is on every keychain command.

### Recommendation
Bind the acceptable `kc_user`/`kc_service` values to the identity established at connection/registration time (e.g., the service name the websocket registered under) rather than trusting values embedded in each individual JSON request, and reject keychain requests whose `kc_user`/`kc_service` does not match the connection's established identity.

### Proof of Concept
1. Start the chia daemon normally with two keychain namespaces in use (e.g. `chia` and `chia-testnet10`, each with keys added via `add_key`).
2. From a process that already holds the daemon's shared client certificate (any local chia service or CLI), open a websocket to the daemon and send a raw `get_key` command with `kc_user`/`kc_service` set to the *other* namespace and `include_secrets: true`:
```json
{
  "command": "get_key",
  "data": {"fingerprint": <victim_fingerprint>, "include_secrets": true, "kc_user": "user-of-other-namespace", "kc_service": "chia-testnet10"},
  "request_id": "...", "destination": "daemon", "origin": "attacker_service", "ack": false
}
```
3. `KeychainServer.get_keychain_for_request()` resolves the "other" `Keychain` instance and `GetKeyRequest.run()` returns the full `KeyData`, including private key/mnemonic material for a keychain namespace the caller does not own. [8](#0-7)

```python
    def get_keychain_for_request(self, request: dict[str, Any]) -> Keychain:
        """
        Keychain instances can have user and service strings associated with them.
        The keychain backends ultimately point to the same data stores, but the user
        and service strings are used to partition those data stores. We attempt to
        maintain a mapping of user/service pairs to their corresponding Keychain.
        """
        user = request.get("kc_user", self._default_keychain.user)
        service = request.get("kc_service", self._default_keychain.service)
        if user == self._default_keychain.user and service == self._default_keychain.service:
            keychain = self._default_keychain
        else:
            key = (user or "unnamed") + (service or "")
            if key in self._alt_keychains:
                keychain = self._alt_keychains[key]
            else:
                keychain = Keychain(user=user, service=service)
                self._alt_keychains[key] = keychain
        return keychain
```

```python
    async def run_request(self, request_dict: dict[str, Any], request_type: type[Any]) -> dict[str, Any]:
        keychain = self.get_keychain_for_request(request_dict)
        if keychain.is_keyring_locked():
            return {"success": False, "error": KEYCHAIN_ERR_LOCKED}

        try:
            request = request_type.from_json_dict(request_dict)
        except Exception as e:
            return {
                "success": False,
                "error": KEYCHAIN_ERR_MALFORMED_REQUEST,
                "error_details": {"message": str(e)},
            }

        try:
            return {"success": True, **request.run(keychain).to_json_dict()}
        except KeychainFingerprintNotFound as e:
            return {
                "success": False,
                "error": KEYCHAIN_ERR_KEY_NOT_FOUND,
                "error_details": {"fingerprint": e.fingerprint},
            }
        except KeychainException as e:
            return {
                "success": False,
                "error": KEYCHAIN_ERR_MALFORMED_REQUEST,
                "error_details": {"message": str(e)},
            }
```

```python
    async def get_all_private_keys(self, request: dict[str, Any]) -> dict[str, Any]:
        all_keys: list[dict[str, Any]] = []
        if self.get_keychain_for_request(request).is_keyring_locked():
            return {"success": False, "error": KEYCHAIN_ERR_LOCKED}

        private_keys = self.get_keychain_for_request(request).get_all_private_keys()
        for sk, entropy in private_keys:
            all_keys.append({"pk": bytes(sk.get_g1()).hex(), "entropy": entropy.hex()})

        return {"success": True, "private_keys": all_keys}

    async def get_first_private_key(self, request: dict[str, Any]) -> dict[str, Any]:
        key: dict[str, Any] = {}
        if self.get_keychain_for_request(request).is_keyring_locked():
            return {"success": False, "error": KEYCHAIN_ERR_LOCKED}

        sk_ent = self.get_keychain_for_request(request).get_first_private_key()
        if sk_ent is None:
            return {"success": False, "error": KEYCHAIN_ERR_NO_KEYS}

        pk_str = bytes(sk_ent[0].get_g1()).hex()
        ent_str = sk_ent[1].hex()
        key = {"pk": pk_str, "entropy": ent_str}

        return {"success": True, "private_key": key}
```

```python
    def format_request(self, command: str, data: dict[str, Any]) -> WsRpcMessage:
        """
        Overrides DaemonProxy.format_request() to add keychain-specific RPC params
        """
        if data is None:
            data = {}

        if self.keychain_user or self.keychain_service:
            data["kc_user"] = self.keychain_user
            data["kc_service"] = self.keychain_service

        return super().format_request(command, data)
```
