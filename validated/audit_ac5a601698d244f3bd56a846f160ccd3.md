### Title
`instance()` fail-open fallback in Tron `IntentGatewayV2` lets unregistered chains spoof authenticated cross-chain messages - (File: evm/tron/contracts/apps/IntentGatewayV2.sol)

### Summary
The Tron variant of `IntentGatewayV2` implements `instance()` with a fail-open default instead of the fail-closed revert used everywhere else in the codebase, breaking the cross-chain sender-authentication invariant that `authenticate()` depends on.

### Finding Description
The canonical implementation of instance lookup, in `evm/src/apps/intentsv2/IntentsBase.sol`, is fail-closed:
```solidity
function _instance(bytes calldata stateMachineId) internal view returns (address) {
    address gateway = _instances[keccak256(stateMachineId)];
    if (gateway == address(0)) revert UnknownInstance();
    return gateway;
}
``` [1](#0-0) 

The Tron port in `evm/tron/contracts/apps/IntentGatewayV2.sol` silently substitutes the contract's own address as the "registered" peer for any state machine that has never been registered:
```solidity
function instance(bytes calldata stateMachineId) public view returns (address) {
    address gateway = _instances[keccak256(stateMachineId)];
    return gateway == address(0) ? address(this) : gateway;
}

function authenticate(PostRequest calldata request) internal view {
    if (request.from.length != 20) revert InvalidInput();
    address module = address(bytes20(request.from));
    // IntentGateway only accepts incoming assets from itself or known instances
    if (instance(request.source) != module) revert Unauthorized();
}
``` [2](#0-1) 

Because `IntentGatewayV2` instances are deployed deterministically via CREATE2 at the same address across chains (as documented in the sibling implementation: "identical across chains under deterministic CREATE2, so no peer address is carried in the proxy's init data" [3](#0-2) ), `address(this)` is a fixed, publicly known value. Any state machine for which `_instances[keccak256(stateMachineId)]` has not yet been set (a brand-new chain Hyperbridge supports state proofs for, a chain whose deployment/registration governance call hasn't landed, or any chain id the operator never intended to whitelist) will cause `instance()` to return `address(this)` instead of reverting. `authenticate()` then accepts any incoming `PostRequest` whose `from` field equals `bytes20(address(this))` as coming from a legitimate peer gateway — even though no peer relationship was ever configured for that source chain.

### Impact Explanation
`authenticate()` gates every privileged `onAccept` request kind processed by this contract: `RedeemEscrow` (releases escrowed input tokens to a solver), `SweepDust`, `RefundEscrow`, `UpdateParams`, and `NewDeployment` (writes to `_instances` itself). A false-positive authentication on an unregistered/attacker-reachable source chain lets an unauthorized party trigger these state-changing operations — draining escrowed funds via a forged `RedeemEscrow`/`SweepDust` message, rewriting `_instances`/`_params` via forged `NewDeployment`/`UpdateParams` messages, or refunding orders to arbitrary beneficiaries. This is direct unauthorized execution / fund loss on a bridge-custody contract, matching the bounty's "unauthorized transaction or execution" and "stealing or loss of funds" categories.

### Likelihood Explanation
The trigger condition — a source `StateMachine` id with no `_instances` entry — is the default state for every chain until an admin explicitly calls the `NewDeployment` registration flow, and can persist for any chain Hyperbridge adds ISMP/consensus support for before this specific gateway's governance catches up. No relayer, prover, or admin compromise is required: any unprivileged actor able to get a genuine ISMP-verified `PostRequest` delivered from an unregistered source chain (with `from` crafted/deployed to equal this fixed, public `address(this)`) satisfies `authenticate()` on the Tron gateway. This is a straightforward divergence from the fail-closed pattern proven correct and tested elsewhere in the repo (`testInstance` in `evm/tests/foundry/IntentGatewayV2Test.sol` explicitly asserts `UnknownInstance` reverts for the non-Tron implementation) [4](#0-3) , but the Tron contract has no equivalent revert and no equivalent test coverage.

### Recommendation
Make `instance()`/`authenticate()` in `evm/tron/contracts/apps/IntentGatewayV2.sol` fail-closed like the canonical implementation: revert with an `UnknownInstance`-style error when `_instances[keccak256(stateMachineId)] == address(0)`, instead of falling back to `address(this)`.

### Proof of Concept
1. Deploy `IntentGatewayV2` (Tron variant) at address `G` via the deterministic CREATE2 factory; never call the `NewDeployment` registration flow for state machine `X` (a chain Hyperbridge has state-proof support for but this gateway has not peered with).
2. An attacker arranges for a genuine, ISMP-verifiable `PostRequest` to be delivered from state machine `X` with `request.from = abi.encodePacked(G)` (trivial if the attacker deploys any contract to the same address `G` on chain `X` via the same public CREATE2 deployer/salt, or otherwise controls the `from` bytes emitted by the dispatching module on `X`) and `request.body` encoding a `RequestKind.SweepDust` (or `RedeemEscrow`/`UpdateParams`) payload targeting the attacker's own beneficiary address.
3. On delivery, `authenticate(request)` computes `instance(X)`; since `_instances[keccak256(X)] == address(0)`, it returns `address(this) == G`, which equals `bytes20(request.from)` — authentication passes.
4. `onAccept` executes the privileged request kind, transferring escrowed protocol funds to the attacker-controlled beneficiary despite no legitimate peer relationship ever having been established with chain `X`. [2](#0-1)
