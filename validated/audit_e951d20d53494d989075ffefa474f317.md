### Title
Coinbase outputs are reported as spendable without enforcing maturity - ([File: networks/bitcoin/src/wallet/mod.rs](networks/bitcoin/src/wallet/mod.rs))

### Summary
`Scanner::scan_block` scans every transaction in a block, including `txdata[0]` coinbase transaction, and `Scanner::scan_transaction` returns a `ReceivedOutput` based only on `script_pubkey` matching. The resulting `ReceivedOutput` can be passed directly to `SignableTransaction::new`, which treats it as spendable input without checking whether it came from an immature coinbase. [1](#0-0) [2](#0-1) [3](#0-2) 

### Finding Description
Bitcoin coinbase outputs are subject to a maturity requirement before they can be spent. `scan_block` explicitly iterates over `block.txdata` without excluding or delaying the coinbase transaction. For each matching output, `scan_transaction` creates a `ReceivedOutput` containing only the registered scalar offset, output data, and outpoint. It records no transaction type, block height, confirmation count, or maturity status.

The downstream transaction builder accepts each `ReceivedOutput` solely as an input `OutPoint` and `TxOut`; it has no field or validation path capable of determining that the output was produced by an immature coinbase. [4](#0-3) [3](#0-2) 

This is analogous to the hardcoded `sqrtPriceLimitX96` issue because a protocol-level safety constraint is effectively fixed to the permissive value instead of being enforced or exposed to the caller.

### Impact Explanation
An unprivileged block producer can create a coinbase output paying a scanned script. The wallet will report that output as received and may immediately consume it in `SignableTransaction::new`, but the resulting spend is invalid until the coinbase matures. This causes funds to be reported as spendable when they are not, potentially locking wallet accounting or producing transactions rejected by Bitcoin nodes. [5](#0-4) [6](#0-5) 

### Likelihood Explanation
Exploitation requires an attacker to produce a block containing a coinbase output to a script watched by the victim scanner. Once such a block is supplied to `scan_block`, no additional attacker action or malformed cryptographic input is needed because the code unconditionally scans the coinbase and emits the resulting `ReceivedOutput`. [7](#0-6) 

### Recommendation
Do not return coinbase outputs from `scan_block` as immediately spendable `ReceivedOutput` values. At minimum, skip `block.txdata[0]` or tag returned outputs with their source transaction and require sufficient confirmations before accepting them in `SignableTransaction::new`. A stronger API would carry the producing transaction/block metadata through scanning and enforce coinbase maturity at transaction construction rather than relying on callers to perform the documented post-processing. [8](#0-7) 

### Proof of Concept
```rust
// A block whose txdata[0] is a coinbase containing an output to
// scanner's registered P2TR script.
let outputs = scanner.scan_block(&block);

// This returns a ReceivedOutput even though the coinbase output is immature.
assert_eq!(outputs.len(), 1);
let immature = outputs[0].clone();

// The wallet then accepts it as an ordinary spendable input.
let signable = SignableTransaction::new(
  vec![immature],
  &[(payment_script, payment_amount)],
  None,
  None,
  fee_per_vbyte,
).unwrap();
```

The successful construction of `signable` demonstrates that the wallet treats a consensus-immature coinbase output as spendable; broadcasting the eventual transaction would fail until maturity. [7](#0-6) [9](#0-8)

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  /// Scan a block.
  ///
  /// This will also scan the coinbase transaction which is bound by maturity. If received outputs
  /// must be immediately spendable, a post-processing pass is needed to remove those outputs.
  /// Alternatively, scan_transaction can be called on `block.txdata[1 ..]`.
  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for tx in &block.txdata {
      res.extend(self.scan_transaction(tx));
    }
    res
  }
