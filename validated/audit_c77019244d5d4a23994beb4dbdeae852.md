## Title
Gasless module lends gas fee unconditionally before swap execution, allowing an attacker to keep the proposer's lent funds by causing the paired `GaslessSwapTx` to revert on-chain - (File: kaiax/gasless/impl/getter.go)

### Summary
KIP-247 gasless transactions are executed as a bundle `[LendTxGenerator, GaslessApproveTx(optional), GaslessSwapTx]` built by the block proposer. The `LendTx` unconditionally transfers native KAIA from the proposer to the user *before* the user's swap transaction runs, and repayment to the proposer only happens as a side effect deep inside the `swapForGas` execution. All the correctness checks that are supposed to guarantee repayment (`checkBalanceForSwap`, `VerifyExecutable`/SP4 repay-amount check) are evaluated against **mempool-time state**, not the state actually present when the bundle is executed in the block.

### Finding Description
The bundle construction logic unconditionally prepends a value-transfer `LendTx` from the proposer to the swap sender: [1](#0-0) 

`LendTx` moves `lendAmount(approveTxOrNil, swapTx)` KAIA to the user regardless of what happens afterward: [2](#0-1) [3](#0-2) 

Repayment is only enforced *inside* the subsequent `GaslessSwapTx` (via the `GaslessSwapRouter.swapForGas` contract call), which pays `amountRepay` back to the proposer out of the DEX swap proceeds: [4](#0-3) 

The admission-time safety checks (`checkBalanceForSwap`) that are meant to guarantee the swap will actually succeed and repay the proposer — token balance, allowance, DEX exchange rate, deadline — are computed against the *current* chain state at tx-pool validation time, not re-verified at block-building/execution time: [5](#0-4) 

Because `LendTx`, `GaslessApproveTx`, and `GaslessSwapTx` are three independent top-level transactions (not a single atomic call), a `LendTx` that lands in the block is final and irreversible even if the following `GaslessSwapTx` subsequently reverts. Nothing in `Bundle`/`ExtractTxBundles` ties the three transactions together atomically — `Bundle.IsConflict` only prevents overlapping/target-hash conflicts, it does not roll back earlier bundle transactions if a later one fails: [6](#0-5) 

An attacker (an ordinary unprivileged transaction sender) can therefore:
1. Submit a valid `GaslessApproveTx`/`GaslessSwapTx` pair that passes `checkBalanceForSwap` at admission time (e.g., token balance/allowance and DEX quote are momentarily sufficient).
2. Before the bundle is picked up and executed by the proposer, invalidate the swap's success condition — e.g., transfer/spend the ERC20 token balance used as `amountIn`, revoke the approval, or manipulate the DEX pool price so `minAmountOut`/`amountRepay` can no longer be satisfied (front-running the router pool via a normal DEX swap transaction is available to any unprivileged sender and is not blocked by this module).
3. When the proposer includes the bundle, `LendTx` unconditionally credits the attacker's account with `lendAmount(approveTxOrNil, swapTx)` KAIA.
4. `GaslessSwapTx` then reverts on-chain (insufficient balance/allowance/slippage), so the `swapForGas` repayment logic never executes and the proposer never gets `amountRepay` back.
5. The attacker keeps the lent KAIA (`ApproveTx.Fee() + SwapTx.Fee()`), a real, unauthorized value transfer paid entirely by the block proposer.

This is directly analogous to the TAC incident's root cause pattern: a settlement/lending step that is not atomically coupled to the corresponding repayment/verification step, letting an attacker walk away with funds released before the compensating leg completes.

### Impact Explanation
This is a direct, unauthorized value movement from the block proposer to any attacker who can time a state change against their own pending gasless swap. Each exploited bundle transfers `ApproveTx.Fee() + SwapTx.Fee()` (bounded by the declared gas price × gas limit of the two transactions, which the attacker fully controls) from the proposer to the attacker with no repayment. Because gasless transactions are proposer-agnostic and this bug affects any proposer building such bundles, it can be repeated across blocks/proposers, and the per-attempt lent amount can be inflated by the attacker via gas-limit selection (bounded only by block gas limit and fee-cap validity), making the loss economically significant and repeatable — qualifying as High severity per the loss-of-funds criteria.

### Likelihood Explanation
Exploitation only requires actions available to any unprivileged EOA: submitting the two gasless transactions, and submitting/triggering an ordinary token transfer, approval revocation, or DEX trade to invalidate the swap precondition after mempool admission but before block inclusion. No privileged role, validator collusion, or protocol-level access is required — timing/front-running of ordinary transactions against the bundling-time gap is sufficient, and the check functions in `checkBalanceForSwap` are explicitly documented as being evaluated only at tx-pool time (README: "Sender balance check is omitted for gasless transactions" refers to the standard pool check, but the module-specific checks are also only pool-side, not consensus-side): [7](#0-6) 

### Recommendation
- Make the `LendTx` conditional on the success of the paired `GaslessSwapTx` (e.g., require the bundle to be atomic/all-or-nothing at execution time, or perform lending and repayment verification within a single system-level transaction/precompile rather than as independent transactions).
- Re-validate `checkBalanceForSwap`/`VerifyExecutable` conditions using the state immediately prior to bundle execution (not stale mempool-time state) before including the bundle in a block, and drop the bundle if conditions no longer hold.
- Consider clawing back or refusing to finalize the `LendTx` if the subsequent `GaslessSwapTx` in the same bundle reverts, e.g., by structuring the flow as a single system-contract-mediated transaction that performs lend+swap+repay atomically instead of three separate top-level transactions.

### Proof of Concept
1. Attacker deploys/owns an EOA `U` with a whitelisted ERC-20 token balance and an allowance to the `GaslessSwapRouter`.
2. Attacker submits `GaslessApproveTx` (nonce n) and `GaslessSwapTx` (nonce n+1) with `amountIn`, `minAmountOut`, `amountRepay` computed to satisfy `checkBalanceForSwap` at the current block/state, per [5](#0-4) . Both are admitted to the pool and promoted as ready.
3. In the same block window (or across a short window before the proposer builds/executes the bundle), attacker sends a normal token transfer draining `U`'s ERC20 balance below `amountIn` (any ordinary token transfer transaction, unprivileged).
4. Proposer's builder calls `ExtractTxBundles`, generates `LendTx` per [2](#0-1) , and includes `[LendTx, GaslessApproveTx, GaslessSwapTx]` in the block.
5. During block execution: `LendTx` succeeds, crediting `U` with `lendAmount`. `GaslessApproveTx` may succeed (approve doesn't need token balance). `GaslessSwapTx` calls `swapForGas`, which reverts because `U`'s token balance is now insufficient for `amountIn`/`transferFrom`.
6. Result: `U` keeps the lent KAIA; the proposer receives no `amountRepay`; the proposer's KAIA balance decreases by `lendAmount` with no compensating value received — an unauthorized value transfer confirmed by comparing pre/post-block proposer and `U` balances.

**Note on verification limits:** I was unable to inspect the full Solidity source of `GaslessSwapRouter.swapForGas` (only Go contract bindings were indexed), so I could not directly confirm from source whether the router itself contains any additional safeguard (e.g., an on-chain check that rejects the swap if a prior lend for the same bundle didn't occur, or a call-order enforcement). If such a safeguard exists in the router contract, it would mitigate this finding; a Devin session with full repository/file access should verify `contracts/**/GaslessSwapRouter.sol` (source, not bindings) before treating this as fully confirmed.

// MakeLendTx creates a transaction with following properties:
// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)
// L2. LendTx.from = proposer
// L3. LendTx.to = SwapTx.from
// L4. LendTx.value = LendAmount(approveTxOrNil, swapTx)
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}

func lendAmount(approveTxOrNil, swapTx *types.Transaction) *big.Int {
	r := new(big.Int)

	// R2 = ApproveTx.Fee() if exists
	if approveTxOrNil != nil {
		r.Add(r, approveTxOrNil.Fee())
	}

	// R3 = SwapTx.Fee()
	r.Add(r, swapTx.Fee())

	// LendAmount = R2 + R3
	return r
}

func (g *GaslessModule) checkBalanceForSwap(swapArgs *SwapArgs, swapNonce uint64) error {
	token := swapArgs.Token
	bc := backends.NewBlockchainContractBackend(g.Chain, nil, nil)

	g.gaslessInfoMu.RLock()
	swapRouter := g.swapRouter
	g.gaslessInfoMu.RUnlock()

	// tx.minAmountOut >= tx.amountRepay
	minAmountOut := swapArgs.MinAmountOut
	amountRepay := swapArgs.AmountRepay
	if minAmountOut.Cmp(amountRepay) < 0 {
		return fmt.Errorf("insufficient minAmountOut: minAmountOut=%s, amountRepay=%s", minAmountOut.String(), amountRepay.String())
	}

	if g.GaslessConfig.ShouldCheckSenderCode() {
		if g.getCurrentHasCode(swapArgs.Sender) {
			return errors.New("sender with code is not allowed")
		}
	}

	if g.GaslessConfig.ShouldCheckSwapAmount() {
		// tx.amountIn >= gsr.getAmountIn(minAmountOut)
		routerContract, err := kip247.NewGaslessSwapRouterCaller(swapRouter, bc)
		if err != nil {
			return err
		}
		// Required token amountIn, given the current exchange rate and the declared minAmountOut.
		requiredAmountIn, err := routerContract.GetAmountIn(nil, token, minAmountOut)
		if err != nil {
			return err
		}
		if swapArgs.AmountIn.Cmp(requiredAmountIn) < 0 {
			return fmt.Errorf("insufficient amountIn: have=%s, want=%s", swapArgs.AmountIn.String(), requiredAmountIn.String())
		}
	}

	if g.GaslessConfig.ShouldCheckToken() {

		tokenContract, err := sc_erc20.NewERC20(token, bc)
		if err != nil {
			return err
		}

		// If SwapTx.nonce is the sender's next nonce, then there is no room for ApproveTx proceeding SwapTx.
		senderNonce := g.getCurrentStateNonce(swapArgs.Sender)
		noApproveTxPreceeds := swapNonce == senderNonce
		if noApproveTxPreceeds {
			// tx.token.allowance(sender, router) >= tx.amountIn
			approval, err := tokenContract.Allowance(nil, swapArgs.Sender, swapRouter)
			if err != nil {
				return err
			}
			if approval.Cmp(swapArgs.AmountIn) < 0 {
				return fmt.Errorf("insufficient approval: approval=%s, want=%s", approval.String(), swapArgs.AmountIn.String())
			}
		}

		// tx.token.balanceOf(sender) >= tx.amountIn
		balance, err := tokenContract.BalanceOf(nil, swapArgs.Sender)
		if err != nil {
			return err
		}
		if balance.Cmp(swapArgs.AmountIn) < 0 {
			return fmt.Errorf("insufficient balance: balance=%s, want=%s", balance.String(), swapArgs.AmountIn.String())
		}
	}

	// tx.deadline >= currentTimestamp
	deadline := swapArgs.Deadline
	if deadline.Cmp(g.Chain.CurrentBlock().Time()) < 0 {
		return fmt.Errorf("insufficient deadline: deadline=%s, want=%s", deadline.String(), g.Chain.CurrentBlock().Time().String())
	}

	return nil
}

type Bundle struct {
	// each element can be either *types.Transaction, or TxGenerator
	BundleTxs []*TxOrGen

	// BundleTxs is placed AFTER the target tx. If empty hash, it is placed at the very front.
	TargetTxHash common.Hash

	// TargetRequired is true if the bundle must be executed after the target tx
	// and only if the target tx is successfully executed.
	TargetRequired bool

	// lookup map for O(1) membership checks (lazy initialized)
	txLookup map[common.Hash]int
}

func NewBundle(txs []*TxOrGen, targetTxHash common.Hash, targetRequired bool) *Bundle {
	b := &Bundle{
		BundleTxs:      txs,
		TargetTxHash:   targetTxHash,
		TargetRequired: targetRequired,
	}
	b.buildLookup()
	return b
}
