### Title
Governance-settable `Kip71GasTarget` accepts zero, causing division-by-zero panic in `NextMagmaBlockBaseFee` - ([File: params/kip71_config.go])

### Summary
The KIP-71 dynamic base-fee formula divides by the governance-controlled `GasTarget` parameter without checking for zero, unlike the adjacent `BaseFeeDenominator`, which has an explicit zero-guard. If `GasTarget` is ratified as `0` through header governance, every node computing or verifying the next block's base fee panics, exactly analogous to the amdgpu bug where an unchecked divisor (`fs_in_mb`, derived from unvalidated width/height) caused a kernel division-by-zero.

### Finding Description
`KIP71Config.NextMagmaBlockBaseFee` computes the next base fee using `gasTarget := kc.GasTarget` directly, then divides by it in both the "gas used > target" and "gas used < target" branches: [1](#0-0) [2](#0-1) 

Note that `BaseFeeDenominator` has an explicit zero-guard just above (`if kc.BaseFeeDenominator == 0 { baseFeeDenominator = 64 }`), but no equivalent guard exists for `GasTarget`. [3](#0-2) 

The governance parameter registry defines `Kip71GasTarget` with `FormatChecker: noopFormatChecker`, which performs no validation and therefore accepts `0` as a legal value — in contrast to `Kip71BaseFeeDenominator`, which explicitly requires `v != 0`: [4](#0-3) 

This parameter is reachable via the standard header-governance vote flow (`governance_vote` RPC → `header.Vote` → ratified in `header.Governance` at epoch boundaries → consumed by `GetParamSet`/`ToKip71Config`), which any governing node (or, in `none` mode, any council member) can invoke: [5](#0-4) [6](#0-5) 

Vote verification (`VerifyVote`/`checkConsistency`) checks voter identity/permission but does not reject a `GasTarget=0` value beyond the no-op `FormatChecker`, so the vote and subsequent ratification proceed: [7](#0-6) 

Once ratified and effective, every node's block-verification path calling `VerifyMagmaHeader`/`NextMagmaBlockBaseFee` (and `feehistory.go`'s `NextMagmaBlockBaseFee` call for RPC fee history) will divide by zero and panic: [8](#0-7) [9](#0-8) 

### Impact Explanation
A single ratified governance parameter update (`GasTarget=0`) crashes every consensus node computing or verifying the base fee for the next block after the epoch transition — this is a chain-halting, node-crashing bug affecting the entire network's block production and validation, not merely a resource-exhaustion issue. It also crashes RPC `eth_feeHistory` handling for the affected block. This matches the CVSS-7.8/High severity pattern of the reference kernel CVE (crash due to unchecked divisor derived from attacker/operator-controlled input).

### Likelihood Explanation
In `single` governance mode (Mainnet/Kairos default), only the designated `GoverningNode` can cast the vote, so exploitation requires that privileged voter (or compromise thereof) to submit `governance_vote("kip71.gastarget", 0)`. In `none` mode, any council member can do so. While this requires a governance-privileged actor rather than an arbitrary unprivileged sender, the request explicitly lists "governance parameters" as an in-scope reachable path, and the lack of any format-level validation (unlike the sibling `BaseFeeDenominator` parameter which is explicitly guarded both at the format-checker and computation layers) indicates this is a genuine oversight, not an intentional trust boundary.

### Recommendation
Add a zero-rejection `FormatChecker` for `Kip71GasTarget` (mirroring `Kip71BaseFeeDenominator`'s `v != 0` check), and additionally add a defensive zero-guard inside `NextMagmaBlockBaseFee` (fallback to a safe default, consistent with the existing `BaseFeeDenominator` zero-guard) so that even a value bypassing parameter-set validation cannot trigger a division panic during header verification.

### Proof of Concept
1. As the governing node (single mode) or any council member (none mode), call `governance_vote("kip71.gastarget", 0)`.
2. Wait for the vote to be included in `header.Vote` and ratified in `header.Governance` at the next epoch boundary (`FormatChecker` accepts `0` since it is a no-op).
3. Starting from the epoch after ratification, any node building or verifying a block with `parentGasUsed != 0` calls `NextMagmaBlockBaseFee`, which executes `x.Div(x, new(big.Int).SetUint64(gasTarget))` with `gasTarget == 0`, panicking on `division by zero` and crashing the node process — halting consensus network-wide.

func (kc *KIP71Config) VerifyMagmaHeader(headerBaseFee *big.Int, parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) error {
	if headerBaseFee == nil {
		return fmt.Errorf("header is missing baseFee")
	}
	// Verify the baseFee is correct based on the parent header.
	expectedBaseFee := kc.NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)
	if headerBaseFee.Cmp(expectedBaseFee) != 0 {
		return fmt.Errorf("invalid baseFee: have %s, want %s, parentBaseFee %s, parentGasUsed %d",
			headerBaseFee, expectedBaseFee, parentHeaderBaseFee, parentHeaderGasUsed)
	}
	return nil
}

// VerifyVote checks the following:
// (1) voter must be in valset,
// (2) integrity of the voter (the voter must be the block proposer),
// (3) the vote value must be consistent compared to the latest ParamSet.
func (h *headerGovModule) VerifyVote(header *types.Header) error {
	if len(header.Vote) == 0 {
		return nil
	}

	var (
		vb       headergov.VoteBytes = header.Vote
		blockNum                     = header.Number.Uint64()
	)

	vote, err := vb.ToVoteData()
	if err != nil {
		logger.Error("ToVoteData error", "num", blockNum, "vote", vb, "err", err)
		return err
	}

	if gov.DeprecatedAt(vote.Name(), h.ChainConfig.Rules(header.Number)) {
		logger.Error("Vote is deprecated", "num", blockNum, "name", vote.Name())
		return ErrDeprecatedVote
	}

	council, err := h.ValSet.GetCouncil(blockNum)
	if err != nil {
		return err
	}

	// check if the voter is in council
	if !slices.Contains(council, vote.Voter()) {
		return ErrInvalidKeyValue
	}

	// check if Voter is the block proposer.
	author, err := h.Chain.Sealer().Author(header)
	if err != nil {
		return err
	}
	if author != vote.Voter() {
		return ErrInvalidVoter
	}

	// In single mode, only the governing node can write header.Vote after Permissionless.
	params := h.GetParamSet(blockNum)
	if h.ChainConfig.IsPermissionlessForkEnabled(new(big.Int).SetUint64(blockNum)) &&
		params.GovernanceMode == "single" &&
		vote.Voter() != params.GoverningNode {
		return ErrVotePermissionDenied
	}

	return h.checkConsistency(blockNum, vote)
}
