Based on the code evidence gathered, the strongest local analog to the `setState` "redundant/incomplete state transition" bug class is in `EvmHost.sol`'s GET-request lifecycle, where a completed response is not fully finalized in storage, and the corresponding timeout path checks the wrong location for that finalization.

### Title
GET request commitment survives successful response delivery, enabling double payment of the same escrowed fee via a mismatched timeout non-membership check - ([File: evm/src/core/EvmHost.sol])

### Summary
When an incoming `GetResponse` is successfully delivered, `EvmHost.dispatchIncoming(GetResponse)` pays the relayer fee but never deletes the corresponding `_requestCommitments[commitment]` entry, unlike every other terminal dispatch path in the same contract (`dispatchTimeOut` for both POST and GET explicitly `delete _requestCommitments[commitment]` "for replay protection"). Because the commitment metadata (`sender`, `fee`) is left intact, the request still appears "pending" to any code that gates on its existence, and the corresponding GET-timeout path checks a non-membership proof against a foreign/remote state root instead of the local `_responseReceipts` mapping that was actually populated.

### Finding Description
`dispatchIncoming(GetResponse)` in `evm/src/core/EvmHost.sol`: [1](#0-0) 

records the response receipt and pays the relayer fee, but does not delete `_requestCommitments[commitment]`. Compare this with `dispatchTimeOut(GetRequestTimeout, ...)` and `dispatchTimeOut(PostRequestTimeout, ...)`, both of which explicitly delete `_requestCommitments[commitment]` as "replay protection" before invoking the module callback: [2](#0-1) 

and `dispatchIncoming(PostRequest, ...)`, which relies on `_requestReceipts` at the destination for its own replay protection: [3](#0-2) 

Because `_requestCommitments[commitment]` is never cleared after a successful GET response, `HandlerV2.handleGetRequestTimeouts` can still find `meta.sender != address(0)` for an already-answered request: [4](#0-3) 

The only guard meant to stop a timeout from firing on an already-answered request is a non-membership proof of `RESPONSE_RECEIPTS_STORAGE_PREFIX` at `commitment`, checked against `host.stateMachineCommitment(message.height).stateRoot` — i.e., a **remote/foreign state machine's** state root tracked by this host via consensus updates. But the actual response receipt that `dispatchIncoming(GetResponse)` writes (`_responseReceipts[commitment]`) is stored in **this host's own contract storage**, not in any remote chain's trie. A non-membership proof against an unrelated remote state root will always succeed for a key that was never written there in the first place, so it cannot detect that the response was already delivered and paid for locally.

### Impact Explanation
If the non-membership check structurally cannot reflect the true local `_responseReceipts` state (as the code paths indicate), a GET request that has already been answered — with its relayer fee paid out in `dispatchIncoming(GetResponse)` — can subsequently be timed out via `handleGetRequestTimeouts` → `dispatchTimeOut(GetRequestTimeout, ...)`, which refunds `meta.fee` to `meta.sender` a second time: [5](#0-4) 

This results in the same escrowed request fee being disbursed twice from the host's fee-token balance (once to the relayer, once back to the payer) — a double-settlement / fund-loss condition against the bridge's own custody, matching the bounty's "double-claim/double-settlement" and "stealing or loss of funds" categories. It is reachable by any unprivileged party since both `handleGetResponses` and `handleGetRequestTimeouts` are permissionless entry points (`notFrozen(host)` only).

### Likelihood Explanation
Medium-to-high, but with caveats: exploiting this requires being able to produce a timeout submission for a request whose GET request `timeout()` has elapsed relative to some accepted `state.timestamp`, and a non-membership proof against a state root the host already trusts (no malicious relayer/prover assumption needed — the non-membership proof is trivially satisfiable for any key that was never written on the foreign chain, which is always true here). I was not able to fully verify the exact byte layout of `RESPONSE_RECEIPTS_STORAGE_PREFIX` or the precise semantics of `message.height.stateMachineId` in this final pass (i.e., whether it could ever coincide with the host's own chain ID as tracked via consensus loop-back), so I cannot rule out that some other mechanism outside the files I inspected additionally gates this. This uncertainty should be resolved by a deeper review of the consensus "intermediates" storage path and the `RESPONSE_RECEIPTS_STORAGE_PREFIX` constant's derivation before treating this as fully confirmed.

### Recommendation
- In `dispatchIncoming(GetResponse)`, delete `_requestCommitments[commitment]` after a successful response delivery (mirroring the deletion done in both `dispatchTimeOut` overloads), so the request can never simultaneously be considered "answered" and "pending."
- In `handleGetRequestTimeouts`, replace (or supplement) the remote non-membership proof with a direct local check of `host.responseReceipts(commitment)` before allowing a timeout, ensuring the timeout path can never fire once `_responseReceipts` has been populated for that commitment.
- Add a unit/fuzz test that delivers a `GetResponse` for a commitment and then attempts `handleGetRequestTimeouts` for the same commitment, asserting it reverts.

### Proof of Concept
Conceptual sequence (cannot be fully executed without additional verification of the storage-prefix/consensus loop-back semantics noted above):
1. Dispatch a `GetRequest` on host A with fee `F`, escrowed in `_requestCommitments[commitment]`.
2. Relayer delivers the response via `HandlerV2.handleGetResponses` → `EvmHost.dispatchIncoming(GetResponse)`; relayer is paid `F`; `_requestCommitments[commitment]` remains unchanged (bug).
3. After `request.timeout()` elapses, any party submits `HandlerV2.handleGetRequestTimeouts` with a non-membership proof of `RESPONSE_RECEIPTS_STORAGE_PREFIX || commitment` against a remote state root that never held such a key.
4. `EvmHost.dispatchTimeOut(GetRequestTimeout, ...)` succeeds, deletes `_requestCommitments[commitment]`, and refunds `F` again to `meta.sender`.
5. Net effect: `F` paid out twice from the host's escrowed fee-token balance for a single GET request.

    function dispatchIncoming(PostRequest memory request, address relayer) external restrict(_hostParams.handler) {
        address destination = _bytesToAddress(request.to);
        uint256 size;
        assembly {
            size := extcodesize(destination)
        }
        if (size == 0) {
            // instead of reverting the entire batch, early return here.
            return;
        }

        // replay protection
        bytes32 commitment = request.hash();
        _requestReceipts[commitment] = relayer;

        (bool success,) = address(destination)
            .call(abi.encodeWithSelector(IApp.onAccept.selector, IncomingPostRequest(request, relayer)));

        if (!success) {
            // so that it can be retried
            delete _requestReceipts[commitment];
            return;
        }
        emit PostRequestHandled({commitment: commitment, relayer: relayer});
    }

    /**
     * @dev Dispatch an incoming GET response to source module
     * @param response - get response
     */
    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
