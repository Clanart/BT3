### Title
SSRF via Missing IP/Network-Range Validation in DataLayer Mirror `subscribe` URLs - (File: `chia/data_layer/data_layer.py`)

### Summary
The DataLayer service allows any local RPC caller (or the wallet's own mirror-URL propagation) to register arbitrary server URLs for a store via `subscribe`, and later `DataLayer.fetch_and_validate()` / `download_data.http_download()` will make outbound HTTP requests to those exact URLs with no validation of hostname, IP address, or network range. This mirrors the openshift-apiserver SSRF class (CVE-2025-14443): user-supplied "remote" references are used to build out-of-band requests without checking for internal/private/loopback/link-local address ranges.

### Finding Description
`DataStore.subscribe()` persists any `ServerInfo.url` supplied by a caller into the `subscriptions` table without any validation of scheme, host, or IP range: [1](#0-0) 

The DataLayer RPC/CLI subscribe path (`chia/cmds/data.py` `-u/--url` option and `DataLayerRpcApi`) forwards attacker/user supplied URL strings straight through to this store call: [2](#0-1) 

Periodically, `DataLayer.periodically_manage_data()` iterates subscriptions and calls `update_subscription()` / `fetch_and_validate()`, which picks a `server_info.url` from the persisted list and issues real network requests to it via `insert_from_delta_file()` → `download_file()` → `http_download()`: [3](#0-2) [4](#0-3) 

No component in this chain (`DataStore.subscribe`, `fetch_and_validate`, `http_download`, or `get_downloader`, which POSTs to `d.url + "/handle_download"`) checks the resolved IP against private/loopback/link-local/multicast ranges before connecting: [5](#0-4) 

A grep across `chia/data_layer/*.py` for IP/host validation logic (`is_localhost`, `ip_address`, `urlparse`, etc.) shows no such checks outside of the S3 plugin service, confirming the DataLayer core subscription/download path performs no SSRF-relevant validation. This matches the reported bug class exactly: user-supplied "image reference"-style URLs are used to reach arbitrary network locations without IP/network-range checks, enabling internal network probing from the node/daemon process.

### Impact Explanation
Because the DataLayer process (which typically runs on the same host/network as the full node and wallet, often with elevated network position) will perform outbound HTTP GET/POST requests to any URL supplied through the local `subscribe` RPC (`chia data subscribe -u <url>`) or wallet-propagated mirror URLs, an attacker able to invoke DataLayer RPC (a "Data Layer client" per the allowed reachable-actor list) can direct the node to:
- Enumerate internal hosts/ports (SSRF-based port scanning) by observing timing/error differences from `aiohttp.client_exceptions.ClientConnectorError` handling.
- Reach cloud metadata services or other internal-only HTTP endpoints reachable from the node's network, potentially causing limited information disclosure.
- Cause repeated connection attempts / resource consumption against internal hosts (limited DoS), since `periodically_manage_data()` retries subscriptions on a schedule.

This is a High-severity SSRF class consistent with the reported CVE (CVSS AC:L/PR:L/UI:N, C:H, A:L): confidentiality impact from internal reconnaissance and availability impact from repeated forced outbound requests, reachable by any authorized local Data Layer RPC caller without needing wallet keys or chain-level privileges.

### Likelihood Explanation
Likelihood is High for a local/authenticated DataLayer RPC caller: the `subscribe` command explicitly accepts free-form URL strings (`-u/--url`) intended for "manually provide a list of servers urls for downloading the data," and there is no allow-list, DNS-rebinding protection, or private-IP filter anywhere in the subscribe→fetch chain. The background sync loop (`periodically_manage_data`) automatically and repeatedly triggers the outbound request without additional user interaction once a malicious URL is subscribed.

### Recommendation
- Add strict URL/IP validation before persisting or using subscription/mirror/plugin URLs in `DataStore.subscribe()` and in `DataLayer.fetch_and_validate()`/`get_downloader()`/`http_download()`: resolve hostnames and reject loopback, link-local, private (RFC1918/RFC4193), and multicast ranges unless explicitly allow-listed by node configuration.
- Consider adding a configurable allow-list of permitted mirror/plugin hosts, and re-validate resolved IPs at connect time to prevent DNS-rebinding bypass.
- Apply the same validation to plugin (`downloader`/`uploader`) URLs, since `get_downloader()` also performs unrestricted outbound POST requests based on stored `PluginRemote.url` values.

### Proof of Concept
1. As an authorized DataLayer RPC/CLI caller, run:
   `chia data subscribe -id <store_id> -u http://169.254.169.254/latest/meta-data/ -u http://127.0.0.1:6379`
   This calls into `DataLayerRpcApi.subscribe` → `DataStore.subscribe()`, which stores these URLs verbatim with no validation. [6](#0-5) 
2. On the next `periodically_manage_data()` cycle, `update_subscription()` calls `fetch_and_validate(store_id)`, which shuffles `servers_info` and calls `insert_from_delta_file()` with the malicious `server_info.url`. [3](#0-2) 
3. `download_file()`/`http_download()` issues `session.get(server_info.url + "/" + filename, ...)`, causing the node process to make an outbound request to the internal/metadata address supplied by the attacker. [7](#0-6) 
4. Observing success/failure/timing of the resulting `ClientConnectorError` vs. HTTP responses (logged in `data_layer.py`) allows the caller to enumerate internal services reachable from the node, or to hit internal-only HTTP endpoints such as cloud metadata services.

    async def get_downloader(self, store_id: bytes32, url: str) -> PluginRemote | None:
        request_json = {"store_id": store_id.hex(), "url": url}
        for d in self.downloaders:
            async with aiohttp.ClientSession() as session:
                try:
                    async with session.post(
                        d.url + "/handle_download",
                        json=request_json,
                        headers=d.headers,
                        timeout=self.client_timeout,
                    ) as response:
                        res_json = await response.json()
                        if res_json["handle_download"]:
                            return d
                except Exception as e:
                    self.log.error(f"get_downloader could not get response: {type(e).__name__}: {e}")
        return None

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
