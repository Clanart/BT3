## Title
Reimburse credited to an operator based solely on a spend of the registered withdrawal UTXO, without verifying any output actually pays the withdrawer - (File: `circuits-lib/src/bridge_circuit/mod.rs`, `core/src/verifier.rs`)

### Summary
`bridge_circuit` (in `circuits-lib/src/bridge_circuit/mod.rs`) and the finalized-payout scanner `Verifier::update_finalized_payouts` (`core/src/verifier.rs`) both bind "this operator paid the withdrawal" purely to the fact that some on-chain transaction spends the registered `withdrawal_utxo` (the input at `previous_output`) and carries an `OP_RETURN` containing an operator xonly-pubkey. Neither checks that the same transaction actually contains an output that pays the withdrawer's requested `output_script_pubkey`/`output_amount`. Since the withdrawal-registrant (who holds the private key of the small "withdrawal UTXO") can broadcast such a transaction unilaterally with zero payout value, an operator's automation (`PayoutCheckerTask`) will treat this as a legitimate payout and proceed to build a claimable `Reimburse` transaction for that operator.

### Finding Description
The claimed binding is:
`operator credited by Reimburse == party whose BTC actually reached the withdrawer` and `amount reimbursed == amount fronted`.

Tracing the code:

- `Operator::withdraw` verifies only that the *input* of the payout tx matches the registered `withdrawal_utxo` from Citrea (`core/src/operator.rs:588-596`) and that a Schnorr signature from the withdrawal UTXO's owner authorizes the tx [1](#0-0) . The `output_script_pubkey`/`output_amount` fields are free parameters of the gRPC call (`WithdrawParams`), constrained only by the caller's own signature over that specific output — the caller who owns the withdrawal UTXO's private key can sign any output they like, including none (an OP_RETURN with value 0), since they hold the key.
- On-chain detection of "who paid" is done in `Verifier::update_finalized_payouts`, which scans confirmed blocks for transactions spending registered withdrawal UTXOs, extracts the operator's xonly pubkey purely from the transaction's first `OP_RETURN` output, and records that operator as the payer — with **no check that any output pays the withdrawer's script/amount**: [2](#0-1) .
- The `bridge_circuit` guest program repeats the same limited binding: it asserts only that `payout_spv.transaction.input[payout_input_index].previous_output` equals the withdrawal outpoint/vout derived from the storage proof, and it derives `operator_xonlypk`/`deposit_constant` from the tx's first `OP_RETURN` output — again never validating a matching payout output value/script: [3](#0-2) .
- `Operator::create_reimburse_txhandler` then builds the `Reimburse` tx paying the operator's reimbursement address the full deposit/bridge amount from the `MoveToVault` UTXO, gated only by the round/kickoff/assert flow succeeding, not by any check that the withdrawer received funds: [4](#0-3) .
- `PayoutCheckerTask::run_once` picks up any "unhandled payout" recorded for the operator's own xonly pubkey and drives it straight into `handle_finalized_payout` → kickoff → Reimburse, with no re-validation of the payout tx's outputs: [5](#0-4) .

Exploit flow: the withdrawal registrant (attacker) registers a withdrawal on Citrea via `withdraw()`, then — using only their own private key over the dust/withdrawal UTXO they control — crafts and broadcasts a transaction that spends that UTXO to fees only, with an `OP_RETURN` output embedding an operator's xonly-pubkey and the `move_txid`, and zero (or negligible) value to the withdrawer. Once mined, `update_finalized_payouts` records this operator as having "paid" the withdrawal. That operator's `PayoutCheckerTask` (or manual `GetReimbursementTxs` flow) then proceeds through kickoff/assert/challenge-timeout to `Reimburse`, and the operator becomes entitled to the full bridge amount from `MoveToVault`, even though the withdrawer never received their BTC. The existing guards (`Verifier::is_deposit_valid`, `is_profitable`, `SECP.verify_schnorr`, `SPV::verify`, `verify_storage_proofs`) all check *identity of the input UTXO*, not *presence/value of an output paying the withdrawer*, so none of them catch this.

### Impact Explanation
This allows an operator to be reimbursed the full bridge amount from a `MoveToVault` UTXO for a withdrawal it never actually funded, matching the "Critical" category of an operator reimbursed for a payout it never funded / BTC leaving a move-to-vault UTXO without a matching fronted withdrawal. It is repeatable for any withdrawal where the registrant is willing to spend their own UTXO this way (each occurrence requires a fresh withdrawal registration and its own dust UTXO), and it can, in principle, be aimed at any operator by choosing that operator's xonly pubkey in the OP_RETURN.

### Likelihood Explanation
Preconditions: an ordinary deposit + `withdraw()` registration on Citrea (standard user action), and the registrant needing only to control the private key of their own registered withdrawal UTXO — no verifier, aggregator, or operator privilege required. Cost is a single low-fee Bitcoin transaction. The scenario does require some coordination for the credited operator to actually pursue the Reimburse path (an operator's automation would treat any detected spend of "its" withdrawal UTXO as a legitimate payout and proceed automatically per `PayoutCheckerTask`), so this is a real, low-cost, and mechanically straightforward path once a matching operator xonly-pubkey is embedded.

### Recommendation
Bind the on-chain "payout detected" and bridge-circuit's "payout verified" logic to an actual value transfer, not merely to a spend of the withdrawal UTXO plus an attacker-chosen OP_RETURN: require the transaction to contain an output paying at least the registered `output_script_pubkey`/`output_amount` (as committed on Citrea at withdrawal time) before crediting an operator, in both `Verifier::update_finalized_payouts` and the `bridge_circuit` guest logic (extend the assertions around lines 182-229 of `circuits-lib/src/bridge_circuit/mod.rs` to check a specific output index/value/script against the withdrawal's committed parameters, and add the equivalent check in `update_finalized_payouts`).

pub fn create_reimburse_txhandler(
    move_txhandler: &TxHandler,
    round_txhandler: &TxHandler,
    kickoff_txhandler: &TxHandler,
    kickoff_idx: usize,
    paramset: &'static ProtocolParamset,
    operator_reimbursement_address: &bitcoin::Address,
) -> Result<TxHandler, BridgeError> {
    let builder = TxHandlerBuilder::new(TransactionType::Reimburse)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::Reimburse1,
            move_txhandler.get_spendable_output(UtxoVout::DepositInMove)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::Reimburse2,
            kickoff_txhandler.get_spendable_output(UtxoVout::ReimburseInKickoff)?,
            builder::script::SpendPath::ScriptSpend(0),
            DEFAULT_SEQUENCE,
        )
        .add_input(
            NormalSignatureKind::OperatorSighashDefault,
            round_txhandler.get_spendable_output(UtxoVout::ReimburseInRound(
                kickoff_idx,
                paramset.num_kickoffs_per_round,
            ))?,
            builder::script::SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        );

    Ok(builder
        .add_output(UnspentTxOut::from_partial(TxOut {
            value: move_txhandler
                .get_spendable_output(UtxoVout::DepositInMove)?
                .get_prevout()
                .value,
            script_pubkey: operator_reimbursement_address.script_pubkey(),
        }))
        .add_output(UnspentTxOut::from_partial(
            builder::transaction::anchor_output(paramset.anchor_amount()),
        ))
        .finalize())
}

    async fn run_once(&mut self) -> Result<Self::Output, BridgeError> {
        let mut dbtx = self.db.begin_transaction().await?;
        let unhandled_payout = self
            .db
            .get_first_unhandled_payout_by_operator_xonly_pk(
                Some(&mut dbtx),
                self.operator.signer.xonly_public_key,
            )
            .await?;

        if unhandled_payout.is_none() {
            return Ok(false);
        }

        let (citrea_idx, move_to_vault_txid, payout_tx_blockhash) =
            unhandled_payout.expect("Must be Some");

        tracing::info!(
            "Unhandled payout found for withdrawal {}, move_txid: {}",
            citrea_idx,
            move_to_vault_txid
        );

        let deposit_data = self
            .db
            .get_deposit_data_with_move_tx(Some(&mut dbtx), move_to_vault_txid)
            .await?;
        if deposit_data.is_none() {
            return Err(eyre::eyre!("Fronted withdrawal for move tx {move_to_vault_txid} found, but the signatures for the deposit are not found in the db.").into());
        }

        let deposit_data = deposit_data.expect("Must be Some");

        let kickoff_txid = self
            .operator
            .handle_finalized_payout(
                &mut dbtx,
                deposit_data.get_deposit_outpoint(),
                payout_tx_blockhash,
            )
            .await?;

        // fetch and save the LCP for if we get challenged and need to provide proof of payout later
        let (_, payout_block_height) = self
            .operator
            .db
            .get_block_info_from_hash(Some(&mut dbtx), payout_tx_blockhash)
            .await?
            .ok_or_eyre("Couldn't find payout blockhash in bitcoin sync")?;

        let _ = self
            .operator
            .citrea_client
            .fetch_validate_and_store_lcp(
                payout_block_height as u64,
                citrea_idx,
                &self.operator.db,
                Some(&mut dbtx),
                self.operator.config.protocol_paramset(),
            )
            .await?;

        #[cfg(feature = "automation")]
        self.operator.end_round(&mut dbtx).await?;

        self.db
            .mark_payout_handled(Some(&mut dbtx), citrea_idx, kickoff_txid)
            .await?;

        dbtx.commit().await?;

        Ok(true)
    }
