### Title
`ThresholdKeys::read` accepts untrusted key material without verifying the secret share matches the participant's verification share, causing an honest signer to be blamed/slashed - ([File: crypto/dkg/src/lib.rs](crypto/dkg/src/lib.rs))

### Summary
Analogous to the picklescan flaw (a scanner accepting bytes whose dangerous payload goes undetected), `ThresholdKeys::read` deserializes attacker-supplied bytes into a `ThresholdKeys` object while validating only structural properties (`t/n/i` bounds, share count, interpolation method). It never checks that `secret_share * generator() == verification_shares[i]`. A semantically inconsistent key object is accepted and later used for signing, producing an invalid share that is cryptographically attributed to the honest holder, who is then blamed/slashed.

### Finding Description
`ThresholdKeys::read` reads `t`, `n`, `i`, the interpolation variant, `secret_share`, and `n` verification shares, then calls `ThresholdKeys::new`. [1](#0-0) 

`ThresholdKeys::new` validates:
- `verification_shares.len() == n` and all participant indexes `<= n` [2](#0-1) 
- `Constant` interpolation only when `t == n` [3](#0-2) 
- `group_key` is *derived* as the interpolated sum of `verification_shares[1..=t]` [4](#0-3) 

Nowhere is it checked that `C::generator() * secret_share == verification_shares[i]` — the fundamental consistency invariant a deserialization routine must enforce. The field/scalar encodings themselves are canonical (`read_F`/`read_G` enforce canonicality [5](#0-4) ), so the malformed object passes every check.

During signing, `view()` interpolates this bogus `secret_share` [6](#0-5) , and `sign_share` emits a share that cannot satisfy `verify_share` against the (attacker-controlled) verification share. In `complete`, aggregate verification fails and the batch-blame search deterministically blames *this* participant: [7](#0-6) . The code itself acknowledges this path: "The only known way to cause this, for valid parameters/algorithms, is to deserialize a semantically invalid FrostKeys" [8](#0-7) .

### Impact Explanation
An unprivileged party who can feed serialized bytes to `ThresholdKeys::read` (a listed in-scope untrusted input path) can construct a `ThresholdKeys` whose verification shares define a group key the victim does not actually hold a share of. Every signing attempt then produces an invalid share cryptographically attributable to the victim's `Participant` index, resulting in the honest node being marked faulty and slashed in the blame protocol (`InvalidShare`/`Blame` flows in `processor/src/key_gen.rs`). Alternatively, crafted verification shares shift the effective `group_key`, so the victim unknowingly produces shares under a different threshold key than intended — funds/keys are bound to an attacker-chosen group key.

### Likelihood Explanation
The attack requires the adversary to control bytes passed to `ThresholdKeys::read` — e.g., maliciously generated key material, a compromised provisioning step, or any context where serialized keys transit an untrusted channel. It requires no collusion, no malformed cryptography (all encodings are canonical), and a single byte-string. Consequence is deterministic once loaded: every signature attempt fails and blames the holder. Severity: Medium (denial of the victim's signing capability plus wrongful attribution of fault), bounded by how often `ThresholdKeys` is deserialized from non-self-generated sources.

### Recommendation
In `ThresholdKeys::new` (or immediately after `read`), verify `C::generator() * secret_share == verification_shares[&params.i()]`, rejecting otherwise. This mirrors the PedPoP share verification performed during DKG (`calculate_share`) but which deserialization bypasses entirely.

### Proof of Concept
```rust
// For any Ciphersuite C, craft serialized ThresholdKeys where
// secret_share is arbitrary and does not match verification_shares[i].
let t = 2u16; let n = 3u16; let i = 1u16;
let mut bytes = vec![];
bytes.extend(u32::try_from(C::ID.len()).unwrap().to_le_bytes());
bytes.extend(C::ID);
bytes.extend(t.to_le_bytes());
bytes.extend(n.to_le_bytes());
bytes.extend(i.to_le_bytes());
bytes.push(1); // Interpolation::Lagrange
// Attacker-chosen secret share that does NOT correspond to share 1
let bad_share = C::hash_to_F(b"attacker", b"bad");
bytes.extend(bad_share.to_repr().as_ref());
// Honest-looking verification shares for some real polynomial
for l in 1 ..= n {
    let v = C::generator() * real_share(l); // valid points, canonical encodings
    bytes.extend(v.to_bytes().as_ref());
}
let keys = ThresholdKeys::<C>::read(&mut bytes.as_slice()).unwrap(); // accepted
// keys.params().i() == 1, but generator * keys.original_secret_share()
//   != keys.original_verification_share(Participant::new(1).unwrap())
// Any sign() call now emits an invalid share blamed on participant 1.
```

Note: I did not exhaustively verify every `read_*` path (e.g., `musig`, `promote`, `recovery` internals, `schnorrkel`), so other deserialization gaps may exist; this is the strongest confirmed analog in the code reviewed.

  fn read_F<R: Read>(reader: &mut R) -> io::Result<Self::F> {
    let mut encoding = <Self::F as PrimeField>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    // ff mandates this is canonical
    let res = Option::<Self::F>::from(Self::F::from_repr(encoding))
      .ok_or_else(|| io::Error::other("non-canonical scalar"));
    encoding.as_mut().zeroize();
    res
  }

  /// Read a canonical point from something implementing std::io::Read.
  ///
  /// The provided implementation is safe so long as `GroupEncoding::to_bytes` always returns a
  /// canonical serialization.
  #[cfg(any(feature = "alloc", feature = "std"))]
  #[allow(non_snake_case)]
  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
  }
