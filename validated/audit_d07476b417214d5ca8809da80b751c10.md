### Title
Broken forfeit mechanism in mWOMSVBaseRewarder permanently prevents redistribution of early-unlock forfeited yield - (File: rewards/mWOMSVBaseRewarder.sol)

### Summary
`mWOMSVBaseRewarder` implements a full "forfeit-on-early-exit" reward mechanism (queuing infrastructure, events, `ForfeitRewardAdded`) that mirrors the analogous, correctly-implemented mechanism in `vlMGPBaseRewarder`. But the core calculation function `_calExpireForfeit` is dead code that always returns zero, so the redistribution of forfeited yield to long-term mWomSV lockers never happens — this is the direct analog of the reported "riskPoolBalance is not used" issue: a value-siphoning mechanism is wired up but its output is never meaningfully used.

### Finding Description
In `vlMGPBaseRewarder.sol`, `_calExpireForfeit` correctly queries the locker contract's `getRewardablePercentWAD(_account)` to compute how much of a user's pending reward should be forfeited based on how much of their vlMGP is unlocked/in cooldown vs. still fully locked [2](#0-1) .

The intended analog for mWomSV rewards is present: `mWomSV.sol` implements `getRewardablePercentWAD(address _user)`, which computes `fullyInLock` weighted percentage plus decayed weighting for amounts in cooldown or fully unlocked [1](#0-0) . This function is never called anywhere in `mWOMSVBaseRewarder.sol` (confirmed via repo-wide search — `getRewardablePercentWAD` only appears in `VLMGP.sol`, `vlMGPBaseRewarder.sol`, and `mWomSV.sol` itself, never in `mWOMSVBaseRewarder.sol`).

Instead, `mWOMSVBaseRewarder._calExpireForfeit` sets `rewardableAmount = _amount` (i.e., the full earned amount) and then computes `forfeitAmount = _amount - rewardableAmount`, which is always `0`: [3](#0-2) 

Consequently, `_sendReward` always sends the user their entire reward and never queues anything back via `_queueNewRewardsWithoutTransfer` [4](#0-3) . The entire forfeiture bookkeeping and `ForfeitRewardAdded` event exist but are permanently unreachable — functionally identical to the reported bug class where a portion of funds is set aside for a designated purpose (risk pool / forfeit pool) but the mechanism to actually route/use it is never triggered.

### Impact Explanation
Under the intended design (as implemented correctly for vlMGP), a user who starts unlocking/exits early from mWomSV should forfeit a portion of their pending rewards proportional to the unlocked/cooling-down amount, and that forfeited amount is meant to be redistributed to remaining long-term stakers via `_queueNewRewardsWithoutTransfer`, which increases `rewardPerTokenStored` for everyone still staked [5](#0-4) . Because `_calExpireForfeit` never actually computes a nonzero forfeit, this redistribution never occurs. This is a permanent loss of yield that legitimate long-term lockers are entitled to receive under the protocol's own reward design — falling under "theft or permanent freezing of unclaimed yield" for the remaining staker cohort, since the yield that should accrue to them via forfeiture is instead paid out to early-exiting users and can never be recovered or redirected once distributed.

### Likelihood Explanation
This triggers on every single call to `getReward`/`getRewards` for a user with any earned mWomSV rewards (via `_sendReward`), i.e., on essentially every ordinary user claim from `mWOMSVBaseRewarder` [6](#0-5) . No special conditions, privileged roles, or admin action are required — it's a deterministic, always-triggered logic defect reachable by any ordinary wallet.

### Recommendation
Update `mWOMSVBaseRewarder._calExpireForfeit` to mirror `vlMGPBaseRewarder`'s implementation by querying `mWOMSV.getRewardablePercentWAD(_account)` to compute the actual rewardable/forfeit split, consistent with the already-implemented `mWomSV.getRewardablePercentWAD` function:
```solidity
function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
    uint256 rewardablePercentWAD = mWOMSV.getRewardablePercentWAD(_account);
    uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
    ...
}
```

### Proof of Concept
1. User A locks mWom into `mWomSV` and accrues pending rewards in `mWOMSVBaseRewarder`.
2. User A calls `mWomSV.startUnlock()` for the full amount, immediately putting 100% of their balance into cooldown (early-exit intent).
3. User A calls `getReward` (via `MasterMagpie`), triggering `_sendReward` → `_calExpireForfeit(_account, userRewards[...])`.
4. Because `rewardableAmount` is hardcoded to `_amount`, `forfeitAmount` computes to `0` regardless of the user's actual locked/cooldown state, even though `getRewardablePercentWAD` (defined in `mWomSV.sol`) would return a value less than `1e18` for this user in the analogous vlMGP flow.
5. User A receives 100% of pending rewards with no forfeiture, and `_queueNewRewardsWithoutTransfer` is never invoked, so no yield is redistributed to remaining long-term lockers — permanently forfeiting the yield they were designed to receive.

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalmWomSV = fullyInLock + inCoolDown;
        if (userTotalmWomSV == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalmWomSV;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalmWomSV / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalmWomSV;
                }

            }
        }

        return percent;
    }

    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }

    function _queueNewRewardsWithoutTransfer(uint256 _amountReward, address _rewardToken) internal
    {
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards = rewardInfo.historicalRewards + _amountReward;
        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;

            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;

                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**mWOMSVDecimal) / totalStaked();

    }
