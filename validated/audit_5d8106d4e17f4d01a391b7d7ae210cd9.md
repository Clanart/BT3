### Title
`ReceivedOutput::read` accepts an unvalidated scalar offset, letting untrusted bytes report outputs that are not spendable under the recorded offset - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The XWiki report is an attribution bug: previewed content executed under a different author's privileges than the editor's, because the author field was not reset to the actor. The analog in Serai's in-scope code is in `ReceivedOutput`: the output's "authority" — the scalar `offset` that determines which key can spend it — is accepted verbatim from untrusted bytes in `ReceivedOutput::read`, with no check that `key + offset * G` actually produces `output.script_pubkey`. Like XWiki trusting a stored author, the deserializer trusts a stored offset.

### Finding Description
`ReceivedOutput` binds three things: `offset`, `output` (a `TxOut` with `script_pubkey`), and `outpoint` [1](#0-0) . The only code that ever establishes the invariant `p2tr(key + offset·G) == output.script_pubkey` is `Scanner::register_offset` / `Scanner::scan_transaction`, which look the script up in a `HashMap<ScriptBuf, Scalar>` built from the real key [2](#0-1) [3](#0-2) . `ReceivedOutput::read` skips that entirely — it reads `offset` via `Secp256k1::read_F` and `output`/`outpoint` via consensus decode, then returns the triple unchecked [4](#0-3) . There is no `Scanner` involvement, no key available to validate against, and no internal consistency check between `offset` and `script_pubkey`.

### Impact Explanation
Any consumer that deserializes `ReceivedOutput`s from an untrusted source (peer-supplied bytes are explicitly an attack surface per `read_F`) can be made to credit an output under an arbitrary offset. Spending requires `keys.offset(offset)` to yield a `ThresholdView` whose shares interpolate to the output's script key; with a wrong offset the FROST signature produced by `TransactionSignatureMachine::complete` will not satisfy the output [5](#0-4) [6](#0-5) . The result is funds reported received that are not spendable — the accepted acceptance criterion.

### Likelihood Explanation
Reachability requires an untrusted party to feed bytes to `ReceivedOutput::read`. That depends on integrators persisting/exchanging `ReceivedOutput`s; if deserialization is strictly local disk written by the same honest node, exposure is limited, so Medium is the ceiling. Within that boundary, exploitation needs no cryptography — just an inconsistent `(offset, script_pubkey)` pair — and the failure is silent (nothing errors at read time; the loss only materializes when the wallet attempts to spend).

### Recommendation
Either make `ReceivedOutput` self-validating — carry or derive the expected `script_pubkey` from the base key and check `p2tr_script_buf(key + offset·G) == output.script_pubkey` on read — or restrict `read` to a trusted-only API and add a `Scanner::register_offset`-backed constructor for untrusted input. At minimum, document that `ReceivedOutput::read` bytes must be as trusted as the key share itself.

Caveat: this assessment assumes `ReceivedOutput::read` is reachable from untrusted bytes in an integrator; within the indexed scope I could not confirm a production call site feeding it peer-controlled input, so the impact hinges on that deployment assumption.


In repo Annirich/serai--013, networks/bitcoin/src/wallet/mod.rs: `ReceivedOutput::read` (lines 122-134) accepts a scalar `offset` plus `TxOut`/`OutPoint` without verifying that the wallet's base key plus `offset * G` yields the output's `script_pubkey` (the only place that invariant is established is `Scanner::register_offset`/`scan_transaction`, lines 180-214). Audit production callers of `ReceivedOutput::read` across the workspace (processor/, coordinator/) to confirm whether untrusted bytes reach it; if so, add validation tying `offset` to `script_pubkey` (e.g., a constructor that takes the base `ProjectivePoint` and rejects mismatches, or store/verify the expected script), and add a regression test that a `ReceivedOutput` with an inconsistent offset is rejected.

  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
