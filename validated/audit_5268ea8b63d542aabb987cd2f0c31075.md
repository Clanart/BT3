## Analysis

The seed bug's core broken invariant: a bound/sanity check exists in code and is *computed*, but a legitimate-looking state change is allowed through unenforced, letting an attacker exploit the resulting mispriced state to drain value before the system corrects itself.

The closest local analog is not in the on-chain contracts (their oracle/slippage bounds in `SimplexPaymaster.sol` are actively enforced with reverts), but in the Intent Filler's `FXFiller` strategy, which is the component that actually delivers output assets to fill Hyperbridge Intent Gateway orders using a Uniswap V4 pool as a live price venue.

### Title
Overfill protection clamp is computed but never enforced, letting a manipulated venue price drain filler funds on fill — ([File: sdk/packages/simplex/src/strategies/fx.ts])

### Summary
`FXFiller.canFill`/execute path computes an `overfillCeiling` — `(1 + maxOverfillBps) × user-requested output` — specifically to bound the loss caused by a bad price (bug, stale cache, or **manipulated venue**), per the code's own comments and the documented "Overfill Protection" feature. However, the enforcement was disabled: the code only logs a warning when the computed output (`rawPolicyMaxOutput`) exceeds the ceiling and then proceeds to use the unclamped `policyMaxOutput` to size the actual on-chain fill. [1](#0-0) 

### Finding Description
For venue-priced legs (Uniswap V4 pools pairing an exotic token with USDC/USDT), the filler resolves a rate via `resolveLegRates`, computes `rawPolicyMaxOutput` from that rate, and is supposed to clamp it to `overfillCeiling` to bound exposure to a bad quote: [2](#0-1) 

The clamp variable `policyMaxOutput` is assigned directly from `rawPolicyMaxOutput` with no `min()` applied, so the ceiling check is purely informational. This is exactly the seed pattern: a guard computed to bound the effect of an anomalous input is present in the code but does not actually gate the state transition, so an out-of-range value (here, an inflated output amount driven by a bad/manipulated price) proceeds to move real funds.

An optional `priceGuard` mechanism exists (`checkPriceGuard`) that can reject a quote outside a configured deviation band, but it is opt-in per chain (`this.priceGuard?.get(chain)`) and defaults to passing everything when unconfigured: [3](#0-2) 

So a pair configured with a Uniswap V4 venue and no `referencePrice`/`maxDeviationBps` guard has **no effective bound at all** on the amount the filler will pay out for a fill — the overfill ceiling is decorative and the price guard is unset by default.

### Impact Explanation
An unprivileged user can place an Intent Gateway order that this filler will attempt to fill against a configured Uniswap V4 position. If the referenced pool is thin or can be moved (e.g., a flash-loan-funded swap right before the filler's evaluation, or simply a low-liquidity pool), the filler computes an inflated `token1 per token0` rate, and — because the clamp is disabled — pays out the full inflated amount from its own wallet/vault balance to fulfill the order, resulting in direct loss of filler-controlled funds routed through the on-chain gateway `fillOrder` call. This is a genuine, quantifiable fund-loss path triggered purely by a normal user/attacker placing an order and manipulating a public AMM pool — no relayer, prover, or admin compromise is required.

### Likelihood Explanation
The code comment explicitly documents that this removes a previously-existing protection ("this removes the per-leg loss bound that previously protected against a bug / stale cache / manipulated venue price"), confirming the clamp was deliberately turned into a warn-only telemetry path rather than an enforced cap. Any deployment using `[vault.uniswapV4]` pricing without setting `referencePrice`/`maxDeviationBps` on every position is exposed, and the documentation itself frames `maxOverfillBps` as protecting specifically against "manipulated venue" pricing — indicating the maintainers' own threat model anticipated this exact attack vector.

### Recommendation
Re-enable enforcement: clamp `policyMaxOutput` to `min(rawPolicyMaxOutput, overfillCeiling)` before it is used to size wallet/vault contributions, rather than only logging a warning. If a legitimate business reason exists for allowing unclamped overfill for offline-curve pricing, at minimum enforce the clamp unconditionally for `priceSource === "venue"` legs, and make the Uniswap price guard (`referencePrice`/`maxDeviationBps`) mandatory rather than optional for any pair priced from a V4 position.

### Proof of Concept
1. Configure a filler pair with `[vault.uniswapV4]` pricing and no `referencePrice`/`maxDeviationBps` guard (a supported, documented configuration).
2. Attacker manipulates the referenced Uniswap V4 pool (e.g., via a large swap) to skew `token1 per token0` far from fair value in the direction that benefits the attacker's order.
3. Attacker places an Intent Gateway order matching that pair.
4. `FXFiller` resolves the manipulated rate, computes `rawPolicyMaxOutput` far above `overfillCeiling` (`(1+maxOverfillBps) × output.amount`), logs "Overfill ceiling exceeded — clamp disabled, filling unclamped amount" per [4](#0-3) , and proceeds with `policyMaxOutput = rawPolicyMaxOutput`.
5. The filler sources this inflated amount from wallet balance and/or funding venues and pays it out via the on-chain `fillOrder` transaction, realizing an on-chain loss equal to the manipulated excess above the intended ceiling.

	private checkPriceGuard(orderId: string | undefined, chain: string, venueToken1PerUsd: Decimal): boolean {
		const guard = this.priceGuard?.get(chain)
		if (!guard || guard.reference.lte(0)) return true

		const deviationBps = venueToken1PerUsd.minus(guard.reference).abs().div(guard.reference).mul(10000)
		if (deviationBps.gt(guard.maxDeviationBps)) {
			this.logger.warn(
				{
					orderId,
					chain,
					venuePrice: venueToken1PerUsd.toString(),
					referencePrice: guard.reference.toString(),
					deviationBps: deviationBps.toFixed(2),
					maxDeviationBps: guard.maxDeviationBps,
				},
				"Rejecting order: Uniswap venue quote outside price-guard band",
			)
			return false
		}
		return true
	}
