### Title
Unvalidated identity encryption key in `EncryptedMessage`/`EncryptionKeyMessage` lets a DKG participant force a known ECDH secret and deliver attacker-chosen secret shares - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
The Subversion bug class — insufficient validation of attacker-supplied bytes allowing a corrupted state to be committed — maps onto `crypto/dkg/pedpop`, where per-message and per-participant ECDH public keys are deserialized and used without rejecting the group identity. `EncryptedMessage::read` reads `key` via `C::read_G`, which enforces only canonical encoding; the Ristretto/Ed25519 identity point encodes canonically and is accepted. The same applies to `enc_key` in `EncryptionKeyMessage::read` and to `Decryption::register`. Because `ecdh(private, identity) = identity`, the ChaCha20 key derived in `cipher()` becomes a publicly computable constant, so the "encrypted" share is plaintext-equivalent and fully attacker-controlled.

### Finding Description
- `EncryptedMessage::read` accepts any canonical point as `key`, including identity (`encryption.rs:171-177`, `ciphersuite/src/lib.rs:91-100`).
- `decrypt` computes `ecdh::<C>(&self.enc_key, msg.key)`; with `msg.key = identity` the shared secret is the identity point, whose bytes hash into a fixed ChaCha20 key in `cipher()` (`encryption.rs:95-133`, `487-488`).
- The sender-authenticating PoP is not a barrier: `msg.pop` is a Schnorr signature against `msg.key`, and the discrete log of the identity is 0, so the attacker produces a valid `pop` for `key = identity` by choosing any `s` and setting `R = s*G` (verify passes since `s*G - c*0*G = R`).
- `EncryptionKeyMessage::read`/`Decryption::register` likewise store an unvalidated `enc_key` (`encryption.rs:57-58`, `351-362`), so a participant registering `enc_key = identity` makes every message encrypted *to* them decryptable by anyone who knows the per-message scalar — and symmetrically lets blame proofs reveal a universally known ECDH.
- No `is_identity` check exists anywhere in `crypto/dkg/pedpop/src/encryption.rs`; the only identity checks in in-scope crypto code are in unrelated paths (`Signed::read` in `coordinator/tributary`, tests).

### Impact Explanation
An unprivileged DKG participant can send a victim an `EncryptedMessage` that passes PoP verification yet decrypts under a key the attacker also knows. The attacker therefore controls the exact plaintext `E` (e.g. the secret-share bytes) the victim obtains — arbitrary plaintext injection equivalent to "committing a corrupted revision," corrupting that victim's share and disrupting/steering the resulting threshold key. Alternatively the attacker simply learns the victim's received share by computing the same keystream, breaking share confidentiality. Impact reaches key-share integrity/confidentiality, exceeding a pure availability DoS.

### Likelihood Explanation
Requires only the ability to send a DKG message to a victim — a standard participant. No secret knowledge, collusion, or computational work is needed: choose `msg.key` as the canonical identity encoding, sign the PoP with scalar 0, and craft ciphertext under the known keystream.

### Recommendation
Reject the identity (and generally require non-identity) in `EncryptedMessage::read` for `key`, in `EncryptionKeyMessage::read` for `enc_key`, and/or in `Decryption::register` before storing; alternatively assert `!bool::from(ecdh_result.is_identity())` in `ecdh` before deriving the cipher.

fn ecdh<C: Ciphersuite>(private: &Zeroizing<C::F>, public: C::G) -> Zeroizing<C::G> {
  Zeroizing::new(public * private.deref())
}

// Each ecdh must be distinct. Reuse of an ecdh for multiple ciphers will cause the messages to be
// leaked.
fn cipher<C: Ciphersuite>(context: [u8; 32], ecdh: &Zeroizing<C::G>) -> ChaCha20 {
  // Ideally, we'd box this transcript with ZAlloc, yet that's only possible on nightly
  // TODO: https://github.com/serai-dex/serai/issues/151
  let mut transcript = RecommendedTranscript::new(b"DKG Encryption v0.2");
  transcript.append_message(b"context", context);

  transcript.domain_separate(b"encryption_key");

  let mut ecdh = ecdh.to_bytes();
  transcript.append_message(b"shared_key", ecdh.as_ref());
  ecdh.as_mut().zeroize();

  let zeroize = |buf: &mut [u8]| buf.zeroize();

  let mut key = Cc20Key::default();
  let mut challenge = transcript.challenge(b"key");
  key.copy_from_slice(&challenge[.. 32]);
  zeroize(challenge.as_mut());

  // Since the key is single-use, it doesn't matter what we use for the IV
  // The issue is key + IV reuse. If we never reuse the key, we can't have the opportunity to
  // reuse a nonce
  // Use a static IV in acknowledgement of this
  let mut iv = Cc20Iv::default();
  // The \0 is to satisfy the length requirement (12), not to be null terminated
  iv.copy_from_slice(b"DKG IV v0.2\0");

  // ChaCha20 has the same commentary as the transcript regarding ZAlloc
  // TODO: https://github.com/serai-dex/serai/issues/151
  let res = ChaCha20::new(&key, &iv);
  zeroize(key.as_mut());
  res
}

  fn read_G<R: Read>(reader: &mut R) -> io::Result<Self::G> {
    let mut encoding = <Self::G as GroupEncoding>::Repr::default();
    reader.read_exact(encoding.as_mut())?;

    let point = Option::<Self::G>::from(Self::G::from_bytes(&encoding))
      .ok_or_else(|| io::Error::other("invalid point"))?;
    if point.to_bytes().as_ref() != encoding.as_ref() {
      Err(io::Error::other("non-canonical point"))?;
    }
    Ok(point)
  }
