### Title
Unrestricted `registerCode` tier reset bypasses admin's `setReferrerTier` downgrades - (File: rewards/ReferralStorage.sol)

### Summary
`registerCode` unconditionally overwrites `userInfos[msg.sender].tier = 1` with no access control and no check for prior state, allowing any address whose tier was lowered by the admin via `setReferrerTier` to unilaterally restore itself to tier 1 by simply registering a new (unused) code. This nullifies the admin's tier-vetting mechanism and lets an attacker keep drawing tier-1 `rewardPercentage` payouts from `trigger` indefinitely.

### Finding Description
`registerCode` is a fully public, unauthenticated function: [1](#0-0) 

It only checks that `_code` is non-zero and unclaimed (`codeOwners[_code] == address(0)`); it does not check whether `msg.sender` already owns a code or already has a `UserInfo.tier` set by the admin. Every successful call sets `tier = 1` regardless of the current value.

`setReferrerTier` is the only admin-controlled mechanism intended to vet/adjust a referrer's tier (e.g., to punish abuse or demote a bad-faith referrer to a lower/zero tier): [2](#0-1) 

Because `registerCode` has no guard against re-registration and no check against an already-assigned tier, any account that has been downgraded by the admin can simply call `registerCode` again with a fresh, unused `bytes32` code to reset `tier` back to `1`. Since `bytes32` code space is unbounded, an attacker can always find/mint an unused code, so this reset is always available and repeatable.

`trigger`, called by `masterMagpie` when a referee claims rewards, reads `userInfos[_referer].tier` live and computes payouts from `tiers[tierId].rewardPercentage`: [3](#0-2) 

so the reset directly and immediately restores the attacker's reward rate, defeating the admin's downgrade decision with no cooldown or restriction.

Regarding the `updateTotalFactor`/boosted-factor part of the question: the boosted component is computed as `BoostPoint * userInfo.factor / totalBoostFactor` in `_calBoosted`, which is a fair pro-rata share of the fixed `BoostPoint` pool across all referral-code holders' vlMGP-derived factors — it does not become "disproportionate" merely from holding tier 1; it scales the same for every code holder regardless of tier. So the disproportionate-reward claim tied to boosting is not substantiated; the concrete, exploitable gap is the tier-reset bypass of `setReferrerTier`.

### Impact Explanation
This is a theft/retention of unclaimed yield: an admin who downgrades a referrer (e.g., after detecting fraud/self-referral abuse) cannot make that downgrade stick, because the referrer can restore tier 1 via a single public `registerCode` call. The attacker continues to receive `trigger`-computed `refererAmount` at tier-1 `rewardPercentage` that the admin explicitly intended to deny, resulting in ongoing diversion of reward-pool MGP to an unvetted party.

### Likelihood Explanation
Fully feasible for any unprivileged EOA: `registerCode` has no access control, no cooldown, and no state check preventing re-registration; the only cost is picking an unused `bytes32` code (trivial, e.g., `keccak256(abi.encode(blockhash, salt))`). The attack is repeatable indefinitely, requires no capital, and can be executed in the same transaction/block right after (or even before) the admin's `setReferrerTier` call is observed via mempool front-running.

### Recommendation
Guard `registerCode` against overwriting an already-assigned tier: only set `tier = 1` the first time a user registers a code (e.g., `if (userInfo.myCode == bytes32(0)) { userInfo.tier = 1; }`), or track tier assignment separately from code registration so that `setReferrerTier` decisions persist across re-registrations. Additionally, consider preventing an address from registering more than one code, or requiring admin approval before a tier change takes effect on a newly (re)registered code.

### Proof of Concept
Foundry test plan:
1. Deploy `ReferralStorage`, initialize with a mock `vlMGP`/`masterMagpie`, set `tiers[1].rewardPercentage` to some value X via `setTier(1, X)`.
2. Attacker calls `registerCode(codeA)` → assert `userInfos[attacker].tier == 1`.
3. Admin (owner) calls `setReferrerTier(attacker, 0)` (or a low tier with 0 `rewardPercentage`) to simulate a downgrade for abuse.
4. Attacker calls `registerCode(codeB)` (fresh unused code) → assert `userInfos[attacker].tier == 1` again, proving the downgrade was reverted without admin involvement.
5. Simulate `masterMagpie` calling `trigger(referee, amount)` where `myReferer[referee] == attacker` → assert `refererInfo.rewardAmount` increases using tier-1 `rewardPercentage`, despite the admin's explicit downgrade to tier 0.

    function registerCode(bytes32 _code) external {
        if (_code == bytes32(0)) revert InvalidCode();
        if (codeOwners[_code] != address(0)) revert CodeOccupied();

        codeOwners[_code] = msg.sender;
        userInfos[msg.sender].myCode = _code;
        userInfos[msg.sender].tier = 1; // tier 1 as default

        emit RegisterCode(msg.sender, _code);
    }

    function trigger(address _referee, uint256 _amount) external _onlyMasterMagpie {
        UserInfo storage refereeInfo = userInfos[_referee];
        address _referer = myReferer[_referee];

        if (_referer == address(0))
            return;

        UserInfo storage refererInfo = userInfos[_referer];
        uint256 tierId = userInfos[_referer].tier;
        uint256 basic = tiers[tierId].rewardPercentage;
        uint256 boostesd = _calBoosted(_referer);

        uint256 refererPercentage = (basic + boostesd) * (DENOMINATOR - sharePercent)  / DENOMINATOR;
        uint256 refereePercentage = (basic + boostesd) *  sharePercent / DENOMINATOR;
        uint256 refererAmount = _amount * refererPercentage / DENOMINATOR;
        uint256 refereeAmount = _amount * refereePercentage / DENOMINATOR;

        refererInfo.rewardAmount += refererAmount;
        refereeInfo.rewardAmount += refereeAmount;

        emit RefererRewardHarvested(_referer, refererAmount);
        emit RefereeRewardHarvested(_referee, refereeAmount);
    }
