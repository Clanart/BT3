### Title
`ReceivedOutput::read` deserializes an unverified scalar offset that is trusted to authorize spending — funds reported spendable under `key + offset·G` are not - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
The CORS report's class — an untrusted, attacker-influenced value being reflected into a trusted, credential-bearing context without validation — maps onto Serai's `ReceivedOutput`. `Scanner::scan_transaction` guarantees offset↔script consistency because the `scripts` map only yields offsets that were registered to produce that exact `script_pubkey` [1](#0-0) . `ReceivedOutput::read`, however, deserializes the `offset` scalar, the `TxOut`, and the `OutPoint` straight from untrusted bytes with no check that `key + offset·G` actually corresponds to `output.script_pubkey` [2](#0-1) . The downstream wallet treats the `offset` as authoritative: it derives the spend key as `key + offset·G` and commits the claimed `TxOut` (including its value) into the sighash's `Prevouts::All` data.

### Finding Description
`ReceivedOutput` couples three independently attacker-controlled fields — `offset` (a `Secp256k1` scalar read via `read_F`), `output` (a consensus-decoded `TxOut` with arbitrary `script_pubkey` and `value`), and `outpoint` — and `read` performs no cross-field consistency check [3](#0-2) . By contrast, the only legitimate construction path, `Scanner::scan_transaction`, derives `offset` from the `scripts` map keyed by the on-chain `script_pubkey`, so the offset is guaranteed to be the one whose registered key produces that script [4](#0-3) ; `register_offset` itself only inserts offsets that yield a valid even-Y P2TR key [5](#0-4) . The deserialization path bypasses all of this, "reflecting" whatever offset the bytes claim into the credential-bearing signing path.

### Impact Explanation
A `ReceivedOutput` read from untrusted bytes (e.g., a serialized output list relayed between components or restored from storage influenced by an external party) is reported by the wallet as received and spendable, when it may not be:

- **Unspendable funds:** if `offset` does not derive `output.script_pubkey`, the multisig signs under `key + offset·G` but the UTXO's script commits to a different key. The signed transaction fails script validation on-chain — the inputs are consumed in the wallet's accounting while the transaction can never confirm.
- **Wrong value commitments:** the claimed `TxOut::value` is baked into the Taproot sighash (`Prevouts::All`) and into the fee/change computation. An inflated or inconsistent value produces a transaction that is either invalid on-chain or misdirects the change output.

This satisfies "funds reported received that are not spendable," analogous to the CORS bug where credentialed responses are served to origins the server never authorized.

### Likelihood Explanation
Any path where `ReceivedOutput` bytes cross a trust boundary — peer relays, watchtowers, imported backups, or a compromise of a component feeding serialized outputs to the signer — exposes this. The read API is public and explicitly accepts arbitrary `Read` streams; nothing in `read` signals that its output lacks the scanner's integrity guarantee. Exploitation requires the attacker to influence the serialized bytes, which is plausible in multi-component deployments but not freely reachable by a pure on-chain attacker (who cannot forge a matching `script_pubkey`), keeping this at Medium rather than High.

### Recommendation
Either make `ReceivedOutput` unforgeable by construction — drop the public `read`/`serialize` pair or re-derive validation — or add a consistency check: given the scanner key, verify `p2tr_script_buf(key + GENERATOR * offset) == output.script_pubkey` before the output is accepted for signing. At minimum, document `read` as requiring a trusted source and re-validate deserialized outputs against the `Scanner` before passing them to `SignableTransaction::new`.

  /// Read a ReceivedOutput from a generic satisfying Read.
  #[cfg(feature = "std")]
  pub fn read<R: Read>(r: &mut R) -> io::Result<ReceivedOutput> {
    let offset = Secp256k1::read_F(r)?;
    let output;
    let outpoint;
    {
      let mut buf_r = BufReader::with_capacity(0, r);
      output =
        TxOut::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid TxOut"))?;
      outpoint =
        OutPoint::consensus_decode(&mut buf_r).map_err(|_| io::Error::other("invalid OutPoint"))?;
    }
    Ok(ReceivedOutput { offset, output, outpoint })
  }

  /// Write a ReceivedOutput to a generic satisfying Write.
  pub fn write<W: Write>(&self, w: &mut W) -> io::Result<()> {
    w.write_all(&self.offset.to_bytes())?;
    w.write_all(&serialize(&self.output))?;
    w.write_all(&serialize(&self.outpoint))
  }

  /// Serialize a ReceivedOutput to a `Vec<u8>`.
  pub fn serialize(&self) -> Vec<u8> {
    let mut res = Vec::new();
    self.write(&mut res).unwrap();
    res
  }

  /// Register an offset to scan for.
  ///
  /// Due to Bitcoin's requirement that points are even, not every offset may be used.
  /// If an offset isn't usable, it will be incremented until it is. If this offset is already
  /// present, None is returned. Else, Some(offset) will be, with the used offset.
  ///
  /// This means offsets are surjective, not bijective, and the order offsets are registered in
  /// may determine the validity of future offsets.
  ///
  /// The offsets registered must be securely generated. Arbitrary offsets may introduce a script
  /// path into the output, allowing the output to be spent by satisfaction of an arbitrary script
  /// (not by the signature of the key).
  pub fn register_offset(&mut self, mut offset: Scalar) -> Option<Scalar> {
    // This loop will terminate as soon as an even point is found, with any point having a ~50%
    // chance of being even
    // That means this should terminate within a very small amount of iterations
    loop {
      match p2tr_script_buf(self.key + (ProjectivePoint::GENERATOR * offset)) {
        Some(script) => {
          if self.scripts.contains_key(&script) {
            None?;
          }
          self.scripts.insert(script, offset);
          return Some(offset);
        }
        None => offset += Scalar::ONE,
      }
    }
  }
