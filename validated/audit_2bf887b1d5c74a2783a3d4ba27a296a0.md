### Title
Git pathspec-magic injection via colon-prefixed filenames lets repo-controlled paths widen or narrow `get_git_diff`'s intended review scope - (File: plugins/security-guidance/hooks/gitutil.py)

### Summary
`_diff_pathspec` converts touched-file paths into repo-relative strings and splices them verbatim, after `--`, into the `git diff` command built by `get_git_diff`. Git still applies "magic pathspec" parsing to any pathspec string that begins with `:` even when it appears after `--`, and neither `_diff_pathspec` nor `GIT_CMD` disables this (`--literal-pathspecs` / `GIT_LITERAL_PATHSPECS` are never set). An attacker who controls a file name in the working tree (a colon is a legal filename character on Linux/macOS) can make the review diff exclude the file that was actually touched, or expand the diff to match unrelated files, without ever escaping the repo directory in the literal filesystem sense.

### Finding Description
`get_git_diff` builds its command as: [1](#0-0) 
`pathspec` comes from `_diff_pathspec`, which only guards against paths outside `cwd` via `relpath`/`..`-prefix checks; it never escapes or rejects pathspec-magic characters: [2](#0-1) 

`GIT_CMD` only disables fsmonitor/hooks, not pathspec magic: [3](#0-2) 

The `paths` fed into `get_git_diff` ultimately derive from repo-controlled git output — `_git_status_porcelain`/`_git_name_only` return raw repo-root-relative filenames from `git status`/`git diff --name-only`, which are joined into absolute paths and passed straight through in `compute_v2_review_set`: [4](#0-3) 

Because git treats any pathspec argument that *begins* with `:` as entering "magic" mode (`:(glob)`, `:(icase)`, `:(exclude)`/`:!`, etc.) regardless of its position after `--`, a file whose repo-relative name starts with `:` turns the literal-path argument into a pathspec directive:
- `:!<pattern>` / `:(exclude)<pattern>` can exclude the actually-touched file from the diff, so `get_git_diff` silently returns a diff that omits the changed content the security reviewer was supposed to see.
- `:(glob)<pattern>` can broaden the match to unrelated files in the working tree (e.g. other dirty/untracked files containing secrets that the user never asked to have reviewed), causing their diffs to be pulled into the payload sent to the LLM-based review sink — a diff/content disclosure to an unintended consumer.
- Malformed magic can also make `git diff` exit non-zero, so `get_git_diff` returns `None`, which downstream flows to "review skipped" — a silent review-scope escape rather than a hard failure the user would notice.

None of the existing checks stop this: `_diff_pathspec` validates directory containment (`realpath`/`relpath`/`..`-prefix) but never checks for a leading `:` or otherwise neutralizes pathspec magic, and `get_git_diff` never passes `--literal-pathspecs` or sets `GIT_LITERAL_PATHSPECS=1`.

### Impact Explanation
This breaks the stated invariant "git path scoping must never escape the intended repo target": a repo-controlled filename can make the diff collection step review the wrong set of files — either dropping the actually-changed file (defeating the automated security review of Claude's own edits) or pulling in unrelated file diffs that get forwarded to the review LLM/sink, matching the "Sensitive code/diff disclosure to an unintended local or remote sink" impact class. It is confined to the plugin's own diff-collection/review logic — it does not grant filesystem access outside the repo — but it does undermine the security-review mechanism's scoping guarantee.

### Likelihood Explanation
Feasible whenever the attacker (or attacker-supplied repo content, e.g. a cloned malicious repository or a file created earlier in the session) can introduce a colon-prefixed filename into the working tree before Stop/commit-review diff collection runs. Colon is legal in POSIX filenames, so this requires no special privilege beyond normal repository content control, which is within the stated attacker model. It is deterministic and repeatable — any diff involving such a filename triggers the magic-pathspec behavior.

### Recommendation
- Pass `--literal-pathspecs` on the `git diff`/`git add` commands in `gitutil.py` (or set `GIT_LITERAL_PATHSPECS=1` in the subprocess environment) so pathspec magic is globally disabled for all pathspec arguments derived from filesystem paths.
- Alternatively/additionally, in `_diff_pathspec`, explicitly prefix each relative path with the literal-pathspec magic signature `:(literal)` (or reject/escape paths beginning with `:`) before appending them to the pathspec list.
- Apply the same treatment to `_temp_index`'s `git add --intent-to-add -- <paths>` call, which has the identical unescaped-pathspec pattern.

### Proof of Concept
Unit test plan for `gitutil.py`:
1. In a temp git repo, create and commit a baseline file, then create a working-tree file named `:(exclude)real_target.py` (or on a git version supporting short-form magic, `:!real_target.py`) alongside a genuinely touched file `real_target.py`.
2. Call `get_git_diff(cwd, baseline_sha, paths=[os.path.join(cwd, "real_target.py")])` — assert the pathspec built by `_diff_pathspec` is `["--", ":(exclude)real_target.py"]`-shaped is NOT what's intended; verify via `git diff --literal-pathspecs -- ":(exclude)real_target.py"` that git treats it as magic (returns error or empty diff) versus the fix where `--literal-pathspecs` makes the same string match a literal (nonexistent) file and correctly errors instead of silently altering scope.
3. Second test: create `:(glob)**/*.env` as a real file with attacker content in a subdirectory alongside an unrelated `.env` file containing a fake secret; drive `compute_v2_review_set`/`get_git_diff` with the crafted path in `touched_paths`; assert that without the fix, the resulting diff text contains hunks from the unrelated `.env` file (`assert ".env" in diff_output`), demonstrating scope expansion beyond the single touched file. With `--literal-pathspecs` applied, assert the diff is restricted to the literal filename only.

```python
def _diff_pathspec(cwd, paths):
    """Convert absolute touched-paths to repo-relative pathspec args for
    git diff. Paths outside cwd (e.g. ~/.claude/…) are dropped. Returns the
    list to splice after `--`, or [] for an unrestricted diff. realpath both
    sides so the macOS /var ↔ /private/var symlink doesn't make in-repo
    paths look external."""
    if not paths:
        return []
    cwd_abs = os.path.realpath(cwd)
    rel = []
    for p in paths:
        try:
            r = os.path.relpath(os.path.realpath(p), cwd_abs)
        except ValueError:
            continue
        if r.startswith(".."):
            continue
        rel.append(r)
    return ["--"] + rel if rel else []
```
