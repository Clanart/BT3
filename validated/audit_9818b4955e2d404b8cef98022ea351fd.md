### Title
Unparameterized SQL string interpolation of caller-controlled filter/pagination values in wallet SQLite stores - (File: chia/wallet/wallet_transaction_store.py, chia/wallet/wallet_coin_store.py, chia/wallet/wallet_nft_store.py)

### Summary
Several wallet-side SQLite query builders reachable from the local wallet RPC surface build SQL statements by directly f-string-interpolating caller-supplied values (pagination bounds, puzzle-hash filters, sort/type filters) into the SQL text instead of using bound `?` parameters for those specific fragments, mirroring the Cacti `graph_view.php` bug class (untrusted values concatenated into a SQL string that is then executed).

### Finding Description
In `chia/wallet/wallet_transaction_store.py`, `get_transactions_between` builds the WHERE/LIMIT clause with raw interpolation: [1](#0-0) 
and the final query embeds `start`/`end`/`puzz_hash_where`/`type_filter_str`/`confirmed_str` directly into the executed SQL string rather than passing them as bound parameters: [2](#0-1) 

The same pattern exists in `chia/wallet/wallet_coin_store.py`, where `get_coin_records_between` interpolates `start`/`limit` straight into the query text: [3](#0-2) 
and `get_coin_records` builds a `conditions` list from caller-supplied `HashFilter`/`AmountFilter`/range objects, joining `.hex()` values with string formatting into the SQL text (`WHERE`, `LIMIT {offset}, {limit}`) instead of using placeholders for those fragments: [4](#0-3) 

`chia/wallet/wallet_nft_store.py`'s `get_nft_list` similarly interpolates `wallet_id` and `did_id.hex()` directly into the SQL string: [5](#0-4) 

None of these functions themselves type-check that `start`/`end`/`wallet_id`/etc. are integers before interpolation — `get_transactions_between`'s `start`, `end`, `sort_key` parameters have no type annotations at all: [6](#0-5) 

I was not able to fully trace the exact RPC handler in `chia/wallet/wallet_rpc_api.py` that dispatches to `get_transactions_between`/`get_coin_records_between` (the file could not be read beyond its header in the available indexing), so I cannot confirm with certainty whether the RPC layer coerces `start`/`end` to `int`/`uint32` before calling into these store methods, or whether a raw JSON string value could reach the f-string unmodified.

### Impact Explanation
If the RPC layer does not strictly coerce these values to integers/bytes32 before calling the store method (which I could not fully verify due to indexing limits on `wallet_rpc_api.py`), a local RPC caller could inject arbitrary SQL into the wallet's local SQLite database via the `LIMIT`/`WHERE` clauses, potentially altering, exfiltrating, or corrupting wallet transaction/coin/NFT records (coin-set/transaction-history integrity within the local wallet DB). Given the CVSS driver of the reference bug (unauthenticated attacker manipulating an unvalidated parameter that flows into a raw SQL string), the closest concern here is local RPC caller trust boundary integrity, not remote unauthenticated access, since chia's RPC requires local network + certificate-based authentication by default.

### Likelihood Explanation
Likelihood is uncertain and could not be conclusively established: it depends entirely on whether the RPC command schema (pydantic/streamable request models) enforces integer types for `start`/`end`/`wallet_id` before these functions execute. If enforced, the interpolation is safe in practice despite being poor practice; if not enforced (e.g., values passed through as raw JSON strings from `request.get(...)`), this is directly exploitable by any local RPC caller.

### Recommendation
- Replace all f-string interpolation of caller-controlled values in `chia/wallet/wallet_transaction_store.py:get_transactions_between`, `chia/wallet/wallet_coin_store.py:get_coin_records_between`/`get_coin_records`, and `chia/wallet/wallet_nft_store.py:get_nft_list` with bound `?` parameters.
- Explicitly type-annotate and validate (cast to `int`/`uint32`/`bytes32`) all RPC-derived values in `chia/wallet/wallet_rpc_api.py` before they reach any store method that builds SQL.
- Add regression tests using non-numeric/malicious strings for `start`, `end`, `wallet_id`, `did_id` to confirm no SQL injection is possible even if type coercion is bypassed.

### Proof of Concept
Not able to construct a concrete end-to-end PoC because the RPC request-parsing code in `chia/wallet/wallet_rpc_api.py` could not be retrieved from the index to confirm whether `start`/`end`/`wallet_id` are coerced to `int` before being passed to `get_transactions_between`/`get_coin_records_between`/`get_nft_list`. If the RPC layer passes through raw string values (e.g., `"0; --"` or a non-numeric `wallet_id`) without casting, the resulting f-string-built query (e.g., `chia/wallet/wallet_transaction_store.py:356-359`) would execute attacker-controlled SQL text against the wallet SQLite database.     async def get_transactions_between(
        self,
        wallet_id: int,
        start,
        end,
        sort_key=None,
        reverse=False,
        confirmed: bool | None = None,
        to_puzzle_hash: bytes32 | None = None,
        type_filter: TransactionTypeFilter | None = None,
    ) -> list[TransactionRecord]:
        """Return a list of transaction between start and end index. List is in reverse chronological order.
        start = 0 is most recent transaction
        """
        limit = end - start

        if to_puzzle_hash is None:
            puzz_hash_where = ""
        else:
            puzz_hash_where = f' AND to_puzzle_hash="{to_puzzle_hash.hex()}"'

        if sort_key is None:
            sort_key = "CONFIRMED_AT_HEIGHT"
        if sort_key not in SortKey.__members__:
            raise ValueError(f"There is no known sort {sort_key}")

        if reverse:
            query_str = SortKey[sort_key].descending()
        else:
            query_str = SortKey[sort_key].ascending()

        confirmed_str = ""
        if confirmed is not None:
            confirmed_str = f"AND confirmed={int(confirmed)}"

        if type_filter is None:
            type_filter_str = ""
        else:
            type_filter_str = (
                f"AND type {'' if type_filter.mode == FilterMode.include else 'NOT'} "
                f"IN ({','.join([str(x) for x in type_filter.values])})"
            )

        async with self.db_wrapper.reader_no_transaction() as conn:
            rows = await conn.execute_fetchall(
                f"SELECT transaction_record FROM transaction_record WHERE wallet_id=?{puzz_hash_where}"
                f" {type_filter_str} {confirmed_str} {query_str}, rowid"
                f" LIMIT {start}, {limit}",
                (wallet_id,),
            )

    async def get_coin_records(
        self,
        *,
        offset: uint32 = uint32(0),
        limit: uint32 = uint32.MAXIMUM,
        wallet_id: uint32 | None = None,
        wallet_type: WalletType | None = None,
        coin_type: CoinType | None = None,
        coin_id_filter: HashFilter | None = None,
        puzzle_hash_filter: HashFilter | None = None,
        parent_coin_id_filter: HashFilter | None = None,
        amount_filter: AmountFilter | None = None,
        amount_range: UInt64Range | None = None,
        confirmed_range: UInt32Range | None = None,
        spent_range: UInt32Range | None = None,
        order: CoinRecordOrder = CoinRecordOrder.confirmed_height,
        reverse: bool = False,
        include_total_count: bool = False,
    ) -> GetCoinRecordsResult:
        conditions = []
        if wallet_id is not None:
            conditions.append(f"wallet_id={wallet_id}")
        if wallet_type is not None:
            conditions.append(f"wallet_type={wallet_type.value}")
        if coin_type is not None:
            conditions.append(f"coin_type={coin_type.value}")
        for field, hash_filter in {
            "coin_name": coin_id_filter,
            "coin_parent": parent_coin_id_filter,
            "puzzle_hash": puzzle_hash_filter,
        }.items():
            if hash_filter is None:
                continue
            entries = ",".join(f"{value.hex()!r}" for value in hash_filter.values)
            conditions.append(
                f"{field} {'not' if FilterMode(hash_filter.mode) == FilterMode.exclude else ''} in ({entries})"
            )
        if confirmed_range is not None and confirmed_range != UInt32Range():
            conditions.append(f"confirmed_height BETWEEN {confirmed_range.start} AND {confirmed_range.stop}")
        if spent_range is not None and spent_range != UInt32Range():
            conditions.append(f"spent_height BETWEEN {spent_range.start} AND {spent_range.stop}")
        if amount_filter is not None:
            entries = ",".join(f"X'{value.stream_to_bytes().hex()}'" for value in amount_filter.values)
            conditions.append(
                f"amount {'not' if FilterMode(amount_filter.mode) == FilterMode.exclude else ''} in ({entries})"
            )
        if amount_range is not None and amount_range != UInt64Range():
            conditions.append(
                f"amount BETWEEN X'{amount_range.start.stream_to_bytes().hex()}' "
                f"AND X'{amount_range.stop.stream_to_bytes().hex()}'"
            )

        where_sql = "WHERE " + " AND ".join(conditions) if len(conditions) > 0 else ""
        order_sql = f"ORDER BY {order.name} {'DESC' if reverse else 'ASC'}, rowid"
        limit_sql = f"LIMIT {offset}, {limit}" if offset > 0 or limit < uint32.MAXIMUM else ""
        query_sql = f"{where_sql} {order_sql} {limit_sql}"

        async with self.db_wrapper.reader_no_transaction() as conn:
            rows = await conn.execute_fetchall(f"SELECT * FROM coin_record {query_sql}")

            total_count = None
            if include_total_count:
                cache_hash = std_hash(bytes(where_sql, encoding="utf8"))  # Only use the conditions here
                total_count = self.total_count_cache.get(cache_hash)
                if total_count is None:
                    row = await execute_fetchone(conn, f"SELECT COUNT(coin_name) FROM coin_record {where_sql}")
                    assert row is not None and len(row) == 1, "COUNT should always return one value"
                    total_count = uint32(row[0])
                    self.total_count_cache.put(cache_hash, total_count)

        records: list[WalletCoinRecord] = []
        coin_id_to_record: dict[bytes32, WalletCoinRecord] = {}
        for row in rows:
            records.append(self.coin_record_from_row(row))
            coin_id_to_record[bytes32.fromhex(row[0])] = records[-1]

        return GetCoinRecordsResult(
            records,
            coin_id_to_record,
            total_count,
        )

    async def get_coin_records_between(
        self, wallet_id: int, start: int, end: int, reverse: bool = False, coin_type: CoinType = CoinType.NORMAL
    ) -> list[WalletCoinRecord]:
        """Return a list of coins between start and end index. List is in reverse chronological order.
        start = 0 is most recent transaction
        """
        limit = end - start
        query_str = "ORDER BY confirmed_height " + ("DESC" if reverse else "ASC")

        async with self.db_wrapper.reader_no_transaction() as conn:
            rows = await conn.execute_fetchall(
                f"SELECT * FROM coin_record WHERE coin_type=? AND"
                f" wallet_id=? {query_str}, rowid LIMIT {start}, {limit}",
                (coin_type, wallet_id),
            )
        return [self.coin_record_from_row(row) for row in rows]
