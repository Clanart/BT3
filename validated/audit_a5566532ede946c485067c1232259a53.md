## Analysis

The external report's core invariant is "state that should be uniquely scoped per-entity gets duplicated across locations, defeating auditability and control." Reduced to Hyperbridge's real invariants, the closest fund-relevant analog is: **a fee-escrow record (`FeeMetadata`) that should be deleted exactly once, on exactly one terminal path (delivery *or* timeout), is only deleted on the timeout path — never on the successful-delivery path — enabling the same escrowed fee to be paid out twice.**

### Title
Double payment of GET-request relayer fee via stale-height timeout after response already delivered - (File: evm/src/core/EvmHost.sol)

### Summary
`EvmHost.dispatchIncoming(GetResponse, relayer)` pays the relayer fee out of `_requestCommitments[commitment]` but never deletes that `FeeMetadata` entry, unlike every other terminal dispatch path (`dispatchTimeOut` for both GET and POST, which explicitly comment "replay protection" and `delete` the entry first). Because `handleGetRequestTimeouts` accepts *any* previously-trusted, challenge-period-elapsed Hyperbridge state height (not necessarily the latest one) to build its non-membership proof, an attacker can submit a timeout using a stale height captured *before* Hyperbridge actually answered the GET request, satisfy all checks, and trigger a second, refund-style payment of the same fee to the original payer — after the relayer has already been paid the identical fee on delivery.

### Finding Description
On successful GET response delivery: [1](#0-0) 

`fee` is read from `_requestCommitments[commitment]` and paid to `relayer`, but `_requestCommitments[commitment]` is **not deleted**. Compare this to the GET-timeout dispatch path, which explicitly deletes the same mapping entry for "replay protection" before paying out: [2](#0-1) 

The handler-level guard for timeouts, `handleGetRequestTimeouts`, only checks that `meta.sender != address(0)` (i.e., that a `FeeMetadata` entry still exists) and a non-membership proof of `RESPONSE_RECEIPTS_STORAGE_PREFIX + commitment` against an arbitrary, previously-accepted state commitment height supplied by the caller: [3](#0-2) 

Because `dispatchIncoming(GetResponse,...)` never clears `_requestCommitments[commitment]`, `meta.sender` remains non-zero indefinitely after a successful delivery, so the `UnknownMessage` guard cannot detect that the request was already fulfilled. The only other guard that *would* catch this — `_responseReceipts[commitment]` (the local delivery receipt set in `dispatchIncoming`) — is checked only in the delivery path (`handleGetResponses`, line 244), not in the timeout path: [4](#0-3) 

The timeout path instead re-derives "was it answered" purely from a Merkle **non-membership** proof against a caller-chosen `message.height` of Hyperbridge's own response-receipt storage. Since `state.stateRoot` for older, already-finalized heights remains permanently retrievable and valid (`host.stateMachineCommitment(message.height)`), a caller can pick a height recorded *before* Hyperbridge processed the GET request. At that historical height the non-membership proof is legitimately valid (the response genuinely didn't exist yet), while `request.timeout() > state.timestamp` can simultaneously be false if the request's timeout window had already elapsed by that historical timestamp (a realistic condition whenever end-to-end relaying is slower than the request's timeout).

### Impact Explanation
This produces a duplicate settlement / double payment of the escrowed relayer fee:
1. Fee is paid to the relayer through `dispatchIncoming(GetResponse,...)` on legitimate delivery.
2. The same fee amount is subsequently refunded to `meta.sender` (the original payer) through `dispatchTimeOut(GetRequestTimeout,...)`, drained from the host's fee-token balance: [5](#0-4) 

This is a direct loss of protocol/escrowed funds and a double-claim/double-settlement of the same request, matching the bounty's accepted impact classes (stealing or loss of funds, replay/double-claim/double-settlement). It also invokes `onGetTimeout` on the destination app after `onGetResponse` already fired for the same request, corrupting app-level state assumptions.

### Likelihood Explanation
The path is reachable by any unprivileged caller: both `handleGetResponses` and `handleGetRequestTimeouts` are permissionless, and the attacker only needs a valid state/non-membership proof for a state height the host already trusts (no malicious relayer, prover, or admin is required — the proof data and the stale trusted height are both legitimate, publicly available artifacts of normal operation). The main precondition is a GET request whose relaying is slow enough that its timeout elapses (relative to an earlier trusted Hyperbridge height) before/around when Hyperbridge actually produces and delivers the response — a realistic timing window under normal network delay, not a contrived edge case.

### Recommendation
- In `EvmHost.dispatchIncoming(GetResponse memory response, ...)`, delete `_requestCommitments[commitment]` (mirroring the pattern already used in both `dispatchTimeOut` overloads) immediately after successfully paying the relayer fee, so a stale `FeeMetadata` entry can never again be used by a subsequent timeout call.
- Additionally/defensively, have `handleGetRequestTimeouts` reject a timeout if `host.responseReceipts(commitment)` already shows a non-zero relayer, regardless of proof height, closing the gap even if the mapping deletion is missed elsewhere.

### Proof of Concept
1. `IDispatcher(hostA).dispatch(getRequest)` on chain A stores `_requestCommitments[commitment] = FeeMetadata(payer, fee)`.
2. Hyperbridge state advances through several finalized heights; relaying to A is delayed past `getRequest.timeout`.
3. Hyperbridge eventually processes the GET and records a response; a relayer calls `handleGetResponses` on A → `EvmHost.dispatchIncoming(GetResponse,...)` pays `fee` to relayer, `_requestCommitments[commitment]` remains populated (bug).
4. Any caller now calls `handleGetRequestTimeouts` on A, choosing an earlier Hyperbridge height H1 (already trusted by A, challenge period elapsed, and satisfying `request.timeout() > state@H1.timestamp` is false) together with a valid non-membership proof of `RESPONSE_RECEIPTS_STORAGE_PREFIX+commitment` at H1's `stateRoot` (true at that historical height, since Hyperbridge hadn't produced the response yet).
5. `handleGetRequestTimeouts` passes all checks (`meta.sender != 0`, proof valid) and calls `host.dispatchTimeOut(...)`, which refunds `fee` again to `payer`.
6. Net effect: `fee` paid out twice from the host's fee-token balance for a single GET request.

    function dispatchIncoming(GetResponse memory response, address relayer) external restrict(_hostParams.handler) {
        // replay protection
        bytes32 commitment = response.request.hash();
        _responseReceipts[commitment] = ResponseReceipt({
            relayer: relayer,
            responseCommitment: response.hash()
        });

        (bool success,) = _bytesToAddress(response.request.from)
            .call(abi.encodeWithSelector(IApp.onGetResponse.selector, IncomingGetResponse(response, relayer)));

        if (!success) {
            // so that it can be retried
            delete _responseReceipts[commitment];
            return;
        }

        // reward the relayer fee
        uint256 fee = _requestCommitments[commitment].fee;
        if (fee != 0) {
            IERC20(feeToken()).safeTransfer(relayer, fee);
        }
        emit GetRequestHandled({commitment: commitment, relayer: relayer});
    }

    /**
     * @dev Dispatch an incoming GET timeout to the source module.
     * @notice Does not refund any protocol fees.
     * @param timeout - timed-out get request bundled with the relayer that submitted the timeout proof
     * @param meta - fee metadata for the original request
     * @param commitment - request commitment
     */
    function dispatchTimeOut(
        GetRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onGetTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit GetRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function handleGetRequestTimeouts(IHost host, GetTimeoutMessage calldata message) external notFrozen(host) {
        uint256 delay = block.timestamp - host.stateMachineCommitmentUpdateTime(message.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        // fetch the state commitment
        StateCommitment memory state = host.stateMachineCommitment(message.height);
        if (state.stateRoot == bytes32(0)) revert StateCommitmentNotFound();
        uint256 timeoutsLength = message.timeouts.length;

        for (uint256 i = 0; i < timeoutsLength; ++i) {
            GetRequest memory request = message.timeouts[i];
            // timed-out?
            if (request.timeout() > state.timestamp) revert MessageNotTimedOut();

            bytes32 commitment = request.hash();
            FeeMetadata memory meta = host.requestCommitments(commitment);
            if (meta.sender == address(0)) revert UnknownMessage();

            bytes[] memory keys = new bytes[](1);
            keys[0] = bytes.concat(RESPONSE_RECEIPTS_STORAGE_PREFIX, commitment);

            // verify state trie non-membership proofs
            PolkadotTrie.StorageValue memory entry = PolkadotTrie.VerifyProof(state.stateRoot, message.proof, keys)[0];
            if (entry.value.length != 0) revert InvalidProof();

            host.dispatchTimeOut(GetRequestTimeout(request, _msgSender()), meta, commitment);
        }
    }
