### Title
Gasless tx-pool "read-only" ERC20/router checks execute with full write EVM, letting a malicious token bypass admission control state-effects - ([File: kaiax/gasless/impl/tx_pool.go])

### Summary
The gasless module treats `checkBalanceForApprove`/`checkBalanceForSwap` as pure "view" calls used purely to gate tx-pool admission (a permission/admission check analogous to SurrealDB's `PERMISSIONS ... WHERE`), but the underlying `CallContract` helper does not run in a state-isolated, enforced read-only EVM.

### Finding Description
`GetCheckBalance()` in `kaiax/gasless/impl/tx_pool.go` calls arbitrary user-supplied contract addresses (`approveArgs.Token`, `swapArgs.Token`, `swapRouter`) via `sc_erc20.NewERC20(...).BalanceOf/Allowance` and `kip247.NewGaslessSwapRouterCaller(...).GetAmountIn`, all routed through `bind.CallOpts{}` (nil) against `backends.NewBlockchainContractBackend(g.Chain, nil, nil)` [1](#0-0) [2](#0-1) .

That backend's `CallContract`/`callContract` builds a `types.NewMessage(...)` and runs it through `vm.NewEVM(blockContext, txContext, state, b.bc.Config(), &vm.Config{})` followed by `blockchain.ApplyMessage(evm, msg)` — the exact same code path used to execute a normal, state-mutating transaction [3](#0-2) . There is no `evm.StaticCall`, no `vm.Config{NoRecursion: true}`, and no `interpreter.readOnly = true` set anywhere in this call path — that flag is only enforced inside `EVM.StaticCall` [4](#0-3) . `SSTORE` (`opSstore`) is only blocked when `interpreter.readOnly` is true [5](#0-4) , so this "read-only" gasless check permits the target token/router contract to freely write storage, transfer value, or call out to other contracts during what is supposed to be a side-effect-free `balanceOf`/`allowance`/`getAmountIn` view query.

Because `CallContract` internally fetches a fresh `state.StateDB` via `b.bc.StateAt(block.Root())` per call (`getBlockAndState`) [6](#0-5) , any writes performed by the malicious token contract during the check are made to a throwaway copy of state and are not committed to the canonical chain by this call alone. This mirrors the SurrealDB advisory in spirit (a "read-only" permission-style gate that internally can execute writes because enforcement was assumed rather than enforced), but in Kaia the immediate blast radius is bounded to that ephemeral state — it does not directly move real chain value.

### Impact Explanation
The concrete state-divergence/asset-movement risk is that this "check" function can be made arbitrarily expensive or non-deterministic (e.g., infinite loops bounded by hardcoded `call.Gas = 3e8`, reentrant self-calls, or `CREATE`s) by a malicious ERC20 token or `GaslessSwapRouter` address, and the returned values (`balanceOf`, `allowance`, `getAmountIn`) can be *computed* with arbitrary attacker logic that also mutates the throwaway state as a side effect while still reporting an inflated/deceptive read value. Since this "view" call is the sole admission gate for skipping the sender-balance check in `TxPool.validateTx` (`shouldSkipBalanceCheck = true` once a module recognizes the tx) [7](#0-6) , an attacker deploying a crafted token contract could manipulate the reported balances/allowances (e.g., by inspecting `msg.sender`/call context and lying about balance) to get a `GaslessApproveTx`/`GaslessSwapTx` admitted and bundled with a proposer-funded `LendTxGenerator` gas-lending transaction, even though the sender does not actually hold the funds needed to repay the lent gas. This is a fee/gasless-settlement abuse vector: the proposer front-loads gas on the promise of repayment validated only by this unenforced "read-only" check.

### Likelihood Explanation
Reachable by any unprivileged party who can submit a `GaslessApproveTx`/`GaslessSwapTx` referencing an attacker-deployed ERC20 token contract and deploy that token beforehand — no special privileges, validator status, or governance access required. The precondition is simply getting the gasless module to treat the tx as a `IsModuleTx` candidate, which only requires the tx to decode as an approve/swap call shape.

### Recommendation
Enforce true side-effect-free execution for all gasless admission-check calls: route `checkBalanceForApprove`/`checkBalanceForSwap` through `EVM.StaticCall` (or set `vm.Config{NoRecursion: false}` plus an explicit `interpreter.readOnly = true`) instead of the general `ApplyMessage`/`vm.NewEVM` write-capable path in `accounts/abi/bind/backends/blockchain.go`. Additionally, treat the values returned by `balanceOf`/`allowance`/`getAmountIn` from arbitrary attacker-supplied token/router contracts as untrusted, and reconfirm repayment sufficiency against real committed state immediately before block inclusion (not only at pool admission time), consistent with the KIP-247 gasless design notes in `kaiax/gasless/README.md`.

### Proof of Concept
1. Deploy a malicious ERC-20-like contract at address `T` whose `balanceOf(address)` function performs arbitrary internal `SSTORE`s / external calls before returning an inflated balance (e.g., always returns `type(uint256).max`), and whose `allowance` similarly lies.
2. Submit a `GaslessApproveTx` naming `T` as `Token` from an account with zero real `T` balance; `checkBalanceForApprove` calls `T.balanceOf(sender)` through `BlockchainContractBackend.callContract`, which executes via the full write-capable `vm.NewEVM`/`ApplyMessage` path [8](#0-7)  — no `readOnly` flag prevents `T`'s crafted bytecode from running non-view logic.
3. Because `T.balanceOf` returns a positive value regardless of the attacker's real holdings, `checkBalanceForApprove`/`checkBalanceForSwap` pass, `shouldSkipBalanceCheck` is set, and the transaction is admitted into the pool and later bundled with a proposer-funded `LendTxGenerator` transaction despite the sender lacking real repayment capacity.

func (b *BlockchainContractBackend) callContract(call kaia.CallMsg, block *types.Block, state *state.StateDB) (*blockchain.ExecutionResult, error) {
	gasPrice := common.Big0
	if call.GasPrice != nil && (call.GasFeeCap != nil || call.GasTipCap != nil) {
		return nil, errors.New("both gasPrice and (maxFeePerGas or maxPriorityFeePerGas) specified")
	}
	if !b.bc.Config().IsKaiaForkEnabled(block.Number()) { // before KIP-162
		if call.GasPrice != nil {
			gasPrice = call.GasPrice
		}
	} else { // after KIP-162
		if call.GasPrice != nil {
			gasPrice = call.GasPrice
		} else {
			if call.GasFeeCap == nil {
				call.GasFeeCap = big.NewInt(0)
			}
			if call.GasTipCap == nil {
				call.GasTipCap = big.NewInt(0)
			}
			gasPrice = math.BigMin(new(big.Int).Add(call.GasTipCap, block.Header().BaseFee), call.GasFeeCap)
		}
	}

	if call.Gas == 0 {
		call.Gas = uint64(3e8) // enough gas for ordinary contract calls
	}

	var accessList types.AccessList
	if call.AccessList != nil {
		accessList = *call.AccessList
	}
	intrinsicGas, err := types.IntrinsicGas(call.Data, accessList, nil, call.To == nil, b.bc.Config().Rules(block.Number()))
	if err != nil {
		return nil, err
	}

	msg := types.NewMessage(call.From, call.To, 0, call.Value, call.Gas, gasPrice, nil, nil, nil, call.Data,
		false, intrinsicGas, accessList, nil, nil, nil, nil)

	txContext := blockchain.NewEVMTxContext(msg, block.Header(), b.bc.Config())
	blockContext := blockchain.NewEVMBlockContext(block.Header(), b.bc, nil)

	// EVM demands the sender to have enough KAIA balance (gasPrice * gasLimit) in buyGas()
	// After KIP-71, gasPrice is nonzero baseFee, regardless of the msg.gasPrice (usually 0)
	// But our sender (usually 0x0) won't have enough balance. Instead we override gasPrice = 0 here
	txContext.GasPrice = big.NewInt(0)
	evm := vm.NewEVM(blockContext, txContext, state, b.bc.Config(), &vm.Config{})

	return blockchain.ApplyMessage(evm, msg)
}

func (b *BlockchainContractBackend) getBlockAndState(num *big.Int) (*types.Block, *state.StateDB, error) {
	var block *types.Block
	if num == nil {
		block = b.bc.CurrentBlock()
	} else {
		header := b.bc.GetHeaderByNumber(num.Uint64())
		if header == nil {
			return nil, nil, errBlockDoesNotExist
		}
		block = b.bc.GetBlock(header.Hash(), header.Number.Uint64())
	}
	if block == nil {
		return nil, nil, errBlockDoesNotExist
	}

	state, err := b.bc.StateAt(block.Root())
	return block, state, err
}

// StaticCall executes the contract associated with the addr with the given input
// as parameters while disallowing any modifications to the state during the call.
// Opcodes that attempt to perform such modifications will result in exceptions
// instead of performing the modifications.
func (evm *EVM) StaticCall(caller types.ContractRef, addr common.Address, input []byte, gas uint64) (ret []byte, leftOverGas uint64, err error) {
	// Invoke tracer hooks that signal entering/exiting a call frame
	if evm.Config.Debug { // Note that STATICCALL cannot be the top frame
		evm.Config.Tracer.CaptureEnter(STATICCALL, caller.Address(), addr, input, gas, nil)
		defer func(startGas uint64) {
			evm.Config.Tracer.CaptureExit(ret, startGas-leftOverGas, err)
		}(gas)
	}

	if evm.Config.NoRecursion && evm.depth > 0 {
		return nil, gas, nil
	}
	// Fail if we're trying to execute above the call depth limit
	if evm.depth > int(params.CallCreateDepth) {
		return nil, gas, ErrDepth // TODO-Klaytn-Issue615
	}
	// Make sure the readonly is only set if we aren't in readonly yet
	// this makes also sure that the readonly flag isn't removed for
	// child calls.
	if !evm.interpreter.readOnly {
		evm.interpreter.readOnly = true
		defer func() { evm.interpreter.readOnly = false }()
	}
