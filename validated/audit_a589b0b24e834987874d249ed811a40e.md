### Title
Unchecked JSON type assertions in the pointer precompile allow a malicious CosmWasm contract to panic node execution - (File: `precompiles/pointer/pointer.go`)

### Summary
The `pointer` precompile's `AddCW20`, `AddCW721`, and `AddCW1155` handlers parse the JSON response of a `wasmdKeeper.QuerySmartSafe` call (a `token_info`/`contract_info` query against an arbitrary, caller-supplied CosmWasm contract) and then extract fields with unchecked Go type assertions, mirroring exactly the "parsing JSON without validation" bug class from the external report. Because the JSON structure originates from a contract the attacker fully controls, the attacker can make the type assertions panic.

### Finding Description
`AddCW20`, `AddCW721`, and `AddCW1155` in `precompiles/pointer/pointer.go` each perform: [1](#0-0) [2](#0-1) [3](#0-2) 

In all three functions, the pattern is:
```go
formattedRes := map[string]interface{}{}
if err := json.Unmarshal(res, &formattedRes); err != nil {
    return nil, 0, err
}
name := formattedRes["name"].(string)
symbol := formattedRes["symbol"].(string)
```
`cwAddr` (the CosmWasm contract to query) is a caller-supplied argument, so any EVM transaction sender or contract can point this at a CW20/CW721/CW1155 contract they deploy themselves. `QuerySmartSafe` simply forwards the query and returns whatever bytes the target contract returns as its query response; the response is not schema-validated before parsing. If the attacker's contract returns `name`/`symbol` as a non-string (e.g. a number, `null`, or omits the field entirely so the map lookup yields `nil`), the unchecked type assertion `.(string)` (single-return form, not the `, ok` form) triggers a Go runtime panic: `interface conversion: interface {} is <nil/other type>, not string`.

This is the same root cause pattern flagged in the external report (`jsonParse.ts`): the JSON payload from an external/untrusted source is deserialized and consumed without validating its structure/types before use.

Notably, other precompiles in this codebase (`precompiles/addr/addr.go`, `precompiles/oracle/*/oracle.go`, `precompiles/solo/*/solo.go`) explicitly wrap their `Execute` methods with a `defer recover()` specifically "to catch gas meter panics" and other unexpected panics: [4](#0-3) 

The `pointer` precompile's `Execute`/`AddCW20`/`AddCW721`/`AddCW1155` have no such `recover()`, and the shared dispatcher (`DynamicGasPrecompile.RunAndCalculateGas`) also does not call `recover()` — it only defers `HandlePrecompileError`, which acts on `err`, not on panics: [5](#0-4) [6](#0-5) 

So a panic thrown inside `AddCW20`/`AddCW721`/`AddCW1155` is not caught anywhere in the precompile execution layer.

### Impact Explanation
Any unrecovered panic reaching a goroutine boundary crashes the whole Go process. Whether this manifests as "just a failed transaction" or a full node crash depends on whether the call path that reaches the pointer precompile is wrapped by a top-level panic recovery (as `DeliverTx`/`CheckTx` typically are in `sei-cosmos/baseapp`). However, EVM JSON-RPC endpoints that simulate execution outside the normal `DeliverTx` path (e.g. `eth_call`, `eth_estimateGas`) are a public-RPC surface reachable by any unauthenticated client, and if such a code path invokes the EVM/precompile stack without the same tx-level recovery wrapper used for `DeliverTx`, a single crafted call targeting `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` against an attacker-deployed malformed CW20/CW721/CW1155 contract can crash a default-configuration RPC node process. At minimum, this is a reliably triggerable unhandled panic inside consensus-relevant transaction execution logic, which is a correctness/availability defect regardless of which specific entry point recovers it.

### Likelihood Explanation
Likelihood is high for triggering the panic itself: an attacker only needs to (1) deploy any CosmWasm contract whose `token_info`/`contract_info` query returns a `name` or `symbol` field that is not a JSON string (or omits it), and (2) call `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` on the `pointer` precompile (address `0x000000000000000000000000000000000000100b`) with that contract's address — both steps require only a normal wasm deploy + EVM transaction, no special privileges. Whether it results in node crash vs. contained tx failure depends on the specific call path's panic-recovery coverage, which was not fully confirmed within available context.

### Recommendation
Replace all unchecked type assertions in `AddCW20`, `AddCW721`, and `AddCW1155` with the safe, checked form (`v, ok := formattedRes["name"].(string)`), returning an explicit error when `name`/`symbol` are missing or not strings, instead of parsing/consuming the wasm query response's JSON structure without validation. Additionally, add the same `defer recover()` pattern used in `precompiles/addr/addr.go`, `precompiles/oracle/oracle.go`, and `precompiles/solo/solo.go` to the pointer precompile's `Execute` method (and/or to `DynamicGasPrecompile.RunAndCalculateGas`) as defense-in-depth against any other unvalidated-input panics.

### Proof of Concept
1. Deploy a CosmWasm contract whose `contract_info` (or `token_info`) query handler returns JSON such as `{"name": 123, "symbol": null}` (or simply omits `name`/`symbol`).
2. From any EVM account, call the `pointer` precompile at `0x000000000000000000000000000000000000100b`, method `addCW721Pointer(cwAddr)` (or `addCW20Pointer`/`addCW1155Pointer`), passing the bech32 address of the contract from step 1.
3. Execution reaches:
```go
res, err := p.wasmdKeeper.QuerySmartSafe(ctx, cwAddress, []byte("{\"contract_info\":{}}"))
formattedRes := map[string]interface{}{}
json.Unmarshal(res, &formattedRes)
name := formattedRes["name"].(string)   // panics: interface conversion
``` [7](#0-6) 
4. The type assertion panics because `formattedRes["name"]` is not a `string` (or is `nil`), and no `recover()` exists anywhere in the pointer precompile's call chain to catch it.
