### Title
Unvalidated GitHub API `clone_url` silently rewrites the local git remote, redirecting future pushes/fetches to an attacker-controlled host - ([File: app/src/lib/stores/updates/update-remote-url.ts])

### Summary
The external report's underlying flaw is: an attacker-influenced value flowing through an unvalidated intermediate structure (`remaining_accounts`) is trusted as authoritative and used to authorize/redirect a sensitive action (the CPI call), instead of being checked against the expected signer identity. The same broken-invariant pattern exists in GitHub Desktop's `updateRemoteUrl` flow: a `clone_url` field taken from a GitHub API response object (attacker-influenceable via a malicious/compromised GHE server or a MITM proxy sitting on the API request path) is trusted and used to silently overwrite the user's local git `origin` remote, with no validation that the new host corresponds to the expected/trusted endpoint.

### Finding Description
`updateRemoteUrl` is invoked from `repositoryWithRefreshedGitHubRepository` in `app-store.ts` every time Desktop refreshes GitHub metadata for a repository (e.g. on checkout, account change, periodic background refresh): [1](#0-0) 

The `apiRepo` object comes straight from `api.fetchRepository(owner, name)`, i.e. from the JSON body of a GitHub/GHE HTTP response for that endpoint. `updateRemoteUrl` then does: [2](#0-1) 

The only checks performed before calling `gitStore.setRemoteURL(...)` are:
1. `protocolsMatch` – compares only the URL *scheme* (`https:` vs `https:`), not the *host*.
2. `remoteUrlUnchanged` – compares the **previously cached** `gitHubRepository.cloneURL` against the current local remote, to detect whether the user manually customized their remote.

Neither check verifies that the *new* `updatedRemoteUrl` (`apiRepo.clone_url`) actually points at the same host/owner/repo the user's account is authenticated against. `urlMatchesRemote` in `repository-matching.ts` does compare hostname/owner/name, but it is only used to detect whether the user already diverged from the old cached URL — it is never applied to validate that the new API-supplied URL is consistent with the expected endpoint: [3](#0-2) 

This is the direct analog of the report's flaw: a value pulled from an externally-supplied, potentially attacker-influenced object (`remaining_accounts` entry / `apiRepo.clone_url`) is used to drive a sensitive operation (CPI target / git remote rewrite) without validating it against the expected trusted identity (expected signer / expected host).

### Impact Explanation
If a user's GitHub Enterprise Server is compromised, or if an on-path network attacker (malicious proxy/Wi-Fi, or a compromised CDN in front of a GHE instance) intercepts or forges the `GET /repos/{owner}/{name}` API response and substitutes an arbitrary `clone_url` (same protocol, different host, e.g. `https://evil.example.com/user/repo`), Desktop will call `gitStore.setRemoteURL('origin', 'https://evil.example.com/user/repo')` with no user confirmation or host-consistency check. This silently redirects `origin` for every future `git push`/`git fetch`/`git pull`, meaning:
- The user's next push (and any local commits) is silently sent to the attacker's server instead of the real GitHub repository — silent corruption of what the user pushes, matching the "Valid Impact" category "silent corruption of what the user commits or pushes" and "git remote/proxy response" attacker control.
- Depending on credential-helper matching behavior, this could also risk credential exposure to the wrong host on subsequent operations.

### Likelihood Explanation
This requires the attacker to control or MITM a GHE/API response for a repository the user has already cloned and associated with a GitHub account in Desktop — feasible for GHE deployments behind a compromised/malicious proxy, which the report's own valid-impact list explicitly includes ("a git remote/proxy response"). No local access, admin rights, or social engineering beyond normal background repository refresh (which happens automatically) is required.

### Recommendation
In `updateRemoteUrl`, before applying `apiRepo.clone_url`, validate that the new URL's hostname matches the expected trusted hostname (the account's endpoint / `getHTMLURL(account.endpoint)`), not just that the protocol matches. Reject or prompt-confirm any update where the new remote's hostname differs from the currently associated `GitHubRepository`'s endpoint hostname, mirroring the owner/name/hostname checks already implemented in `urlMatchesRemote` but applying them against the *new* candidate URL and the expected endpoint rather than only against the cached previous URL.

### Proof of Concept
1. User has Desktop configured against a GitHub Enterprise Server endpoint and has a repository with `origin` pointing at `https://ghe.company.com/team/project`.
2. An on-path attacker (compromised proxy in front of the GHE instance, or a compromised GHE server itself) intercepts the periodic `GET /api/v3/repos/team/project` call issued by `api.fetchRepository` and returns a JSON body identical to the real one except `"clone_url": "https://ghe.company.com.evil-proxy.example/team/project"` (or any other same-scheme host under attacker control).
3. `repositoryWithRefreshedGitHubRepository` receives this `apiRepo` and calls `updateRemoteUrl(gitStore, repository.gitHubRepository, apiRepo)`.
4. Because `protocolsMatch` is true (`https:` === `https:`) and `remoteUrlUnchanged` is true (the user never manually changed the remote), `gitStore.setRemoteURL('origin', 'https://ghe.company.com.evil-proxy.example/team/project')` executes silently.
5. The next time the user runs "Push" from Desktop, their commits are sent to the attacker's host instead of the legitimate GHE server, with no warning shown to the user. [4](#0-3)

import { IAPIRepository } from '../../api'
import { GitStore } from '../git-store'
import { urlMatchesRemote } from '../../repository-matching'
import * as URL from 'url'
import { GitHubRepository } from '../../../models/github-repository'

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}
