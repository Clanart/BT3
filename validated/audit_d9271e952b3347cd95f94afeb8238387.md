### Title
Permissionless `associatePubKey` allows anyone to force a Sei↔EVM identity remap using only a public public key, without proving possession of the private key - ([File: precompiles/addr/addr.go])

### Summary
The `addr` precompile exposes two ways to bind a Sei address to an EVM address: `associate(v,r,s,message)`, which requires a fresh ECDSA signature proving the caller currently controls the private key, and `associatePubKey(pubKeyHex)`, which requires only the raw compressed public key bytes and performs **no proof-of-possession check at all**. Because a secp256k1 public key is recoverable from any previously broadcast Ethereum-style signature, an attacker who has merely observed one signed message/transaction from a victim's EVM address can call `associatePubKey` on the victim's behalf to force an address association the victim never authorized — mirroring CVE-2019-9150's root cause (a "public key import" action that is accepted without genuine user interaction/consent).

### Finding Description
`PrecompileExecutor.associatePublicKey` decodes a hex public key, derives `evmAddr`/`seiAddr`/`pubkey` from it, and immediately calls `associateAddresses`, which only checks that the **destination** `seiAddr` isn't already associated — it never checks that the caller supplied the pubkey because they control it right now: [1](#0-0) 

Compare this to `associate`, which forces the caller to produce a fresh EIP-191 signature (v/r/s over a message) before deriving the same addresses — proving live possession of the private key: [2](#0-1) 

`associateAddresses` then calls `AssociationHelper.AssociateAddresses`, which unconditionally calls `SetAddressMapping` (rewriting the on-chain EVM↔Sei mapping) and migrates any balance sitting at the account's direct-cast address to the "true" pubkey-derived address: [3](#0-2) 

Because Ethereum ECDSA signatures always reveal the signer's public key, **any account that has ever sent a single EVM transaction has its public key publicly exposed**, so the "proof of possession" that `associate()` enforces is trivially bypassable by simply calling `associatePubKey` with that already-public key.

The codebase's own comments confirm this is a known dangerous primitive: the EIP-7702 pre-association logic was added specifically because "a later `associatePubKey` call can remap [a direct-cast EVM→Sei mapping], orphaning any staking/distribution state created under the direct-cast identity (which can then halt the chain via the distribution validator-removal hook)": [4](#0-3) [5](#0-4) 

That fix only pre-associates EIP-7702 authorization authorities inside a `SetCode` transaction; it does not add any general safeguard to the `associatePubKey` precompile entry point itself. Any account (validator operator, delegator, LP, etc.) that has accumulated state under its *direct-cast* Sei address (the default identity before explicit association) remains remappable by any third party who knows its public key. A regression test demonstrates the concrete consequence of exactly this remap for a validator operator address, where funds intended for that operator become unreceivable and the distribution module must redirect the validator's commission to the community pool instead of the rightful recipient: [6](#0-5) 

### Impact Explanation
Triggering an unsolicited `associatePubKey` remap on a victim's cast identity that already has staking/delegation/reward state can:
- Permanently strand/redirect funds owed to that identity (e.g., accrued validator commission is redirected to the community pool rather than paid to the operator, as shown by the test above), which is a concrete loss/misappropriation of funds from the specific account's perspective.
- Silently rewrite bidirectional Sei↔EVM identity mappings for arbitrary victims without their consent — directly analogous to Mailvelope importing a key without genuine user interaction, letting an attacker "hide" or force an identity binding a legitimate user never approved.
- The `x/evm` team's own comments acknowledge this exact pattern is what can "halt the chain via the distribution validator-removal hook," indicating the underlying primitive is recognized internally as chain-halt-adjacent, even though the specific EIP-7702 vector was patched.

### Likelihood Explanation
Any observer of one EVM-signed message/transaction from a target address can recover its public key (this is inherent to ECDSA signature verification), and `associatePubKey` is a permissionless, un-gated precompile call reachable by any EVM caller. No special privilege, governance action, or validator collusion is required — a single crafted transaction suffices.

### Recommendation
Require the same proof-of-possession for `associatePubKey` as for `associate()` (e.g., require a signature over a fresh nonce/message using the supplied pubkey), or gate `SetAddressMapping`/balance migration so that remapping an EVM address whose direct-cast Sei address already has meaningful protocol state (staking, delegations, module-relevant balances) is rejected or requires the same explicit, freshly-signed consent that other association paths use — generalizing the guard already implemented in `helpers.AuthorityToPreAssociate` beyond the EIP-7702 code path to the `associatePubKey` precompile entry point itself.

### Proof of Concept
1. Victim `V` sends any single Ethereum-style transaction from EVM address `E` (never calling `associate`/`associatePubKey` themselves), so `E`'s account state (e.g., stake/commission) accrues under its direct-cast Sei address `cast(E)`. `V`'s public key is now recoverable from that transaction's signature.
2. Attacker `A` extracts `V`'s public key from the observed signature and calls the `addr` precompile's `associatePubKey(pubKeyHex)` with no relationship to `V` and no signature proving current key possession — see `PrecompileExecutor.associatePublicKey` (precompiles/addr/addr.go:205-237).
3. This calls `AssociationHelper.AssociateAddresses`, which rewrites `E`'s Sei mapping from `cast(E)` to the pubkey-derived "true" Sei address and migrates `cast(E)`'s balance (utils/helpers/associate.go:34-55).
4. Any protocol state still keyed by `cast(E)` (e.g., a validator/delegator record created before this forced remap) becomes unreceivable, and payouts addressed to it are diverted (e.g., to the community pool, per `TestAfterValidatorRemovedRoutesToCommunityPoolForUnreceivableValidator` in sei-cosmos/x/distribution/keeper/keeper_test.go:95-147) — all without `V`'s consent or knowledge.

func (p PrecompileExecutor) associatePublicKey(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 1); err != nil {
		return nil, 0, err
	}

	// Takes a single argument, a compressed pubkey in hex format, excluding the '0x'
	pubKeyHex := args[0].(string)

	pubKeyBytes, err := hex.DecodeString(pubKeyHex)
	if err != nil {
		return nil, 0, err
	}

	// Parse the compressed public key
	pubKey, err := btcec.ParsePubKey(pubKeyBytes)
	if err != nil {
		return nil, 0, err
	}

	// Convert to uncompressed public key
	uncompressedPubKey := pubKey.SerializeUncompressed()

	evmAddr, seiAddr, pubkey, err := helpers.GetAddressesFromPubkeyBytes(uncompressedPubKey)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p PrecompileExecutor) associate(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) ([]byte, error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, err
	}

	// v, r and s are components of a signature over the customMessage sent.
	// We use the signature to construct the user's pubkey to obtain their addresses.
	v := args[0].(string)
	r := args[1].(string)
	s := args[2].(string)
	customMessage := args[3].(string)

	rBytes, err := decodeHexString(r)
	if err != nil {
		return nil, err
	}
	sBytes, err := decodeHexString(s)
	if err != nil {
		return nil, err
	}
	vBytes, err := decodeHexString(v)
	if err != nil {
		return nil, err
	}

	vBig := new(big.Int).SetBytes(vBytes)
	rBig := new(big.Int).SetBytes(rBytes)
	sBig := new(big.Int).SetBytes(sBytes)

	// Derive addresses
	vBig = new(big.Int).Add(vBig, utils.Big27)

	customMessageHash := crypto.Keccak256Hash([]byte(customMessage))
	evmAddr, seiAddr, pubkey, err := helpers.GetAddresses(vBig, rBig, sBig, customMessageHash)
	if err != nil {
		return nil, err
	}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

// TestAfterValidatorRemovedRoutesToCommunityPoolForUnreceivableValidator covers the
// case where the validator operator address itself cannot receive funds — its EVM
// address was re-associated (e.g. via associatePubKey) away from the direct-cast Sei
// address it was created under. The withdraw-address fallback in GetDelegatorWithdrawAddr
// resolves back to that same unreceivable operator address, so the commission
// force-withdraw fails. AfterValidatorRemoved runs during EndBlock, so it must not panic:
// the commission is routed to the community pool instead, which conserves value because
// the coins already back the distribution module account.
func TestAfterValidatorRemovedRoutesToCommunityPoolForUnreceivableValidator(t *testing.T) {
	app := seiapp.Setup(t, false, false, false)
	ctx := app.BaseApp.NewContext(false, tmproto.Header{})

	// The validator operator is the direct-cast Sei address of an EVM address.
	evmAddr := common.HexToAddress("0x3333333333333333333333333333333333333333")
	castAddr := sdk.AccAddress(evmAddr[:])
	valAddr := sdk.ValAddress(castAddr)
	valAccAddr := sdk.AccAddress(valAddr) // == castAddr

	require.True(t, app.BankKeeper.CanSendTo(ctx, castAddr))

	// Re-associate the EVM address to a different true Sei address, mirroring
	// associatePubKey after a validator was created under the direct-cast address.
	associatedAddr := seiapp.AddTestAddrs(app, ctx, 1, sdk.NewInt(1000000000))[0]
	app.EvmKeeper.SetAddressMapping(ctx, associatedAddr, evmAddr)

	// The operator/delegator address can no longer receive funds, and the
	// withdraw-address fallback resolves back to that same unreceivable address.
	require.False(t, app.BankKeeper.CanSendTo(ctx, castAddr))
	require.Equal(t, valAccAddr.String(), app.DistrKeeper.GetDelegatorWithdrawAddr(ctx, valAccAddr).String())
