### Title
Single failing/oversized pool-reward claim permanently blocks all pending PlotNFT2 pool reward claims - ([File: chia/wallet/plotnft_wallet/plotnft_wallet.py])

### Summary
`PlotNFT2Wallet.claim_rewards` fetches up to `DEFAULT_POOL_REWARDS_PER_CLAIM` (20) unclaimed pool reward coins and packs **all** of them plus the singleton spend into a **single atomic `WalletSpendBundle`** chained together with `SendMessage`/`AssertCoinAnnouncement` conditions. There is no per-coin isolation, retry skip-list, or partial-claim mechanism: if any one of the bundled reward coins fails to spend (e.g. it was already spent through some other path, is stale relative to on-chain state, or its solution/height data no longer matches consensus expectations), the entire bundle is rejected and none of the other, otherwise-perfectly-claimable rewards can be withdrawn in that call, since they are always claimed together. This is structurally analogous to the `sweepTo` issue: a loop that must fully succeed atomically for any of its elements to move funds, with no fallback to skip failing entries.

`PlotNFT.claim_pool_rewards` (chia/pools/plotnft_drivers.py:590-642) builds one singleton spend whose delegated puzzle chains a `SendMessage` condition to each reward coin, and one `CoinSpend` per reward coin that must each satisfy its solve() correctly: [2](#0-1) 

`PlotNFTStore.get_pool_rewards` simply pulls up to `max` (default 20) unspent reward rows regardless of whether they are individually still spendable/consistent with chain state, with no per-item validation before bundling: [3](#0-2) 

By contrast, the legacy `PoolWallet.claim_pool_rewards` explicitly acknowledges and mitigates the same class of risk by supporting `max_spends_in_tx` batching to keep bundles from growing unbounded: [4](#0-3) 
but `PlotNFT2Wallet.claim_rewards` has no equivalent safety valve — it always attempts to claim the entire fetched batch (up to 20) as one all-or-nothing spend, and there is no code path that removes/skips an individual problematic reward coin and retries with the remainder.

### Impact Explanation
If any single reward coin in the batch cannot be spent successfully (for example due to a stale/incorrect stored `height`/`amount` in `pool_reward2s`, a coin double-spent by a race with another claim path, or any mismatch that causes its `reward.solve()` output to fail consensus/mempool validation), `push_tx` for the whole aggregated bundle fails. Because `claim_rewards` has no fallback to exclude the bad coin and retry with the rest, **all** legitimately claimable pool rewards for that PlotNFT become stuck and unclaimable through this method until the store/state issue causing the failure is fixed out-of-band. This is a spend-triggered transaction-processing halt that locks otherwise-spendable farmer rewards, matching the impact class described in the source report (assets/funds inaccessible due to one failing item blocking an all-or-nothing batch operation).

### Likelihood Explanation
This requires no attacker interaction with someone else's funds — it is a self-contained DoS against the wallet owner's own claim flow. It is realistically triggerable by ordinary operational conditions: a reorg/rollback edge case leaving `pool_reward2s` slightly out of sync with the tracked singleton tip, concurrent claim attempts, or any other reward-coin state drift that PoolWallet's design (which batches to control block-size and inherently isolates per-absorb failures less severely) was seemingly built to avoid. The `PoolWallet` code already anticipates the analogous risk (documented via `max_spends_in_tx` truncation for block-size reasons), indicating this class of failure is a known concern in the pooling module, but the newer `PlotNFT2Wallet.claim_rewards` path does not carry over any mitigation.

### Recommendation
Add partial-claim resilience to `PlotNFT2Wallet.claim_rewards`:
- Validate each reward coin's spendability/state consistency before including it in the aggregate bundle (e.g., confirm its recorded height/amount against current chain state).
- Provide a mechanism (analogous to `PoolWallet`'s `max_spends_in_tx`) to submit reward coins individually or in smaller sub-batches so one bad coin does not block the rest.
- On `push_tx` failure, fall back to bisecting/removing the suspected offending coin and retrying with the remaining coins, or expose an API to claim by explicit reward-coin ID subset (similar in spirit to the sentiment report's recommendation of supporting partial liquidation instead of all-or-nothing).

### Proof of Concept
1. Accumulate more than one pool-reward coin for a self-pooling PlotNFT (`pool_reward2s` populated via normal farming).
2. Introduce a state inconsistency for one reward coin (e.g., it gets spent/consumed through an unrelated path, or its stored `height`/`amount` becomes stale relative to chain state) while leaving `spent_height` NULL in `pool_reward2s` so `get_pool_rewards` still returns it.
3. Call `PlotNFT2Wallet.claim_rewards()`; it fetches all pending rewards including the inconsistent one and bundles them into a single `WalletSpendBundle` via `PlotNFT.claim_pool_rewards` [5](#0-4) .
4. The mempool/consensus rejects the whole bundle because the one bad coin spend fails validation, and since there is no retry/skip logic, none of the other legitimately claimable rewards get paid out on this or subsequent identical calls, until the underlying data inconsistency is manually resolved.

    def claim_pool_rewards(
        self,
        rewards_to_claim: list[PoolReward],
        reward_delegated_puzzles_and_solutions: list[DelegatedPuzzleAndSolution],
    ) -> list[CoinSpend]:
        if self.pooling:
            raise ValueError("Cannot claim rewards while pooling. If you're a pool, try `forward_pool_rewards`")
        if len(rewards_to_claim) != len(reward_delegated_puzzles_and_solutions):
            raise ValueError("Number of rewards and delegated puzzles and solutions must match")
        dpuz_and_solution = DelegatedPuzzleAndSolution(
            puzzle=Program.to(
                (
                    1,
                    [
                        CreateCoin(
                            puzzle_hash=self.inner_puzzle_hash(),
                            amount=self.coin.amount,
                            memos=[self.singleton_struct.struct_hash()],
                        ).to_program(),
                        *(
                            SendMessage(
                                msg=dpuz_and_sol.puzzle.get_tree_hash(),
                                sender=MessageParticipant(puzzle_hash_committed=self.puzzle_hash(nonce=0)),
                                receiver=MessageParticipant(coin_id_committed=reward.coin.name()),
                            ).to_program()
                            for reward, dpuz_and_sol in zip(rewards_to_claim, reward_delegated_puzzles_and_solutions)
                        ),
                    ],
                )
            ),
            solution=Program.to([]),
        )
        return [
            self.singleton_action_spend(
                inner_solution=self.puzzle_with_restrictions().solve(
                    member_validator_solutions=[],
                    dpuz_validator_solutions=[],
                    member_solution=self.bls_member.solve(),
                    delegated_puzzle_and_solution=dpuz_and_solution,
                )
            ),
            *(
                make_spend(
                    coin=reward.coin,
                    puzzle_reveal=reward.puzzle(),
                    solution=reward.solve(
                        self.inner_puzzle_hash(),
                        delegated_puzzle_and_solution=dpuz_and_sol,
                    ),
                )
                for reward, dpuz_and_sol in zip(rewards_to_claim, reward_delegated_puzzles_and_solutions)
            ),
        ]

    async def get_pool_rewards(
        self,
        *,
        plotnft_id: bytes32,
        max: int = DEFAULT_POOL_REWARDS_PER_CLAIM,
        include_spent: bool = False,
    ) -> list[PoolReward]:
        async with self.db_wrapper.reader() as conn:
            rows = await conn.execute_fetchall(
                (
                    "SELECT * from pool_reward2s WHERE singleton_id = ?"
                    + (" AND spent_height IS NULL" if not include_spent else "")
                    + " ORDER BY spent_height ASC LIMIT ?"
                ),
                (plotnft_id, max),
            )
            pool_rewards_selected = [
                PoolReward(
                    coin=Coin(
                        parent_coin_info=bytes32(row[1]), puzzle_hash=bytes32(row[2]), amount=uint64.from_bytes(row[3])
                    ),
                    singleton_id=bytes32(row[4]),
                )
                for row in rows
            ]
            return pool_rewards_selected
