### Title
`ReceivedOutput::read` accepts attacker-asserted output ownership and value, enabling unspendable deposits to be reported as received - (File: `networks/bitcoin/src/wallet/mod.rs`)

### Summary
`ReceivedOutput` claims to represent a spendable output, but its deserializer accepts an arbitrary offset, arbitrary `TxOut`, and arbitrary `OutPoint` without checking that the output exists or that the script corresponds to the supplied offset. [1](#0-0) [2](#0-1) 

### Finding Description
`ReceivedOutput::read` only enforces canonical scalar decoding and Bitcoin consensus parsing for the embedded `TxOut` and `OutPoint`. [3](#0-2)  It does not bind `offset` to `output.script_pubkey`, whereas legitimate scanner results derive the offset by matching the script against the scanner's registered script-to-offset map. [4](#0-3) 

The resulting object exposes the attacker-supplied amount through `ReceivedOutput::value`. [5](#0-4)  `SignableTransaction::new` subsequently trusts the embedded output as the transaction prevout value and records it in `prevouts`. [6](#0-5) [7](#0-6) 

`SignableTransaction::multisig` verifies only that the claimed previous output script matches `keys.offset(input.offset)`; it does not verify that the outpoint exists or has the claimed value. [8](#0-7)  Therefore, an attacker can provide either a wallet-looking output with an intentionally wrong offset or a correctly keyed but nonexistent/incorrectly valued prevout. [9](#0-8) 

### Impact Explanation
An application that accepts serialized `ReceivedOutput` values can report an attacker-controlled amount as received even though the claimed output is nonexistent, already spent, incorrectly valued, or not spendable under the supplied offset. [10](#0-9)  If the script and offset are inconsistent, signing setup rejects the input after the amount has already been exposed as received. [11](#0-10)  If the script and offset are consistent but the outpoint or amount is false, the wallet can construct and sign a transaction for a prevout that Bitcoin consensus will reject. [12](#0-11) 

Severity: Medium.

### Likelihood Explanation
The attacker only needs to cause untrusted bytes to reach `ReceivedOutput::read`, a supported public deserialization path. [2](#0-1)  No validator key compromise, malformed curve encoding, or consensus violation in the parsed `TxOut`/`OutPoint` encoding is required. [3](#0-2) 

### Recommendation
Do not expose `ReceivedOutput::read` as a constructor of trusted spendable outputs. [13](#0-12)  Make deserialization explicitly unchecked, or require an expected wallet key and reject inputs unless `output.script_pubkey == p2tr_script_buf(expected_key + GENERATOR * offset)`. [14](#0-13)  Treat scanner-derived objects produced from authenticated confirmed blocks as the only trusted `ReceivedOutput` source, and independently verify the outpoint, amount, confirmation status, and spendability before crediting or signing. [15](#0-14) 

### Proof of Concept
```rust
use bitcoin::{
  Amount, OutPoint, ScriptBuf, TxOut, Txid,
  hashes::Hash,
};
use bitcoin_serai::wallet::{p2tr_script_buf, ReceivedOutput};
use frost::curve::{Ciphersuite, Secp256k1};
use k256::{ProjectivePoint, Scalar};
use std::io::Write;

fn forged_received_output(
  wallet_key: ProjectivePoint,
) -> Result<ReceivedOutput, std::io::Error> {
  let mut serialized = Vec::new();

  // Claim this uses the wallet's base-key offset.
  serialized.extend_from_slice(Scalar::ZERO.to_bytes().as_ref());

  // Claim the output pays the wallet and carries an attacker-chosen value.
  bitcoin::consensus::Encodable::consensus_encode(
    &TxOut {
      value: Amount::from_sat(1_000_000_000),
      script_pubkey: p2tr_script_buf(wallet_key).unwrap(),
    },
    &mut serialized,
  )
  .unwrap();

  // Reference an outpoint which does not exist or whose actual amount differs.
  bitcoin::consensus::Encodable::consensus_encode(
    &OutPoint { txid: Txid::all_zeros(), vout: 0 },
    &mut serialized,
  )
  .unwrap();

  // Accepted: only canonical/consensus encodings are checked.
  let output = ReceivedOutput::read(&mut serialized.as_slice())?;

  // Reports the attacker-chosen amount.
  assert_eq!(output.value(), 1_000_000_000);

  Ok(output)
}
```

A wrong-offset variant is also accepted by deserialization and later rejected by `SignableTransaction::multisig`, demonstrating that the object can be represented as received while not being spendable. [8](#0-7)

  /// Scan a transaction.
  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }

  /// Scan a block.

  pub fn scan_block(&self, block: &Block) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
