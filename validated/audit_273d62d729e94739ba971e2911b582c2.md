### Title
Unauthenticated `InternalSendTx` on the aggregator allows broadcasting an attacker-chosen Bitcoin transaction through the bridge's fee-paying infrastructure - ([File: core/src/rpc/aggregator.rs])

### Summary
When `client_verification == false`, `core::servers::create_grpc_server` wires the aggregator's gRPC service with `Interceptors::Noop`, which unconditionally returns `Ok(req)` without ever invoking `is_internal`/`only_aggregator_and_self`. This means any unauthenticated caller can invoke `AggregatorServer::internal_send_tx`, which deserializes the caller-supplied `raw_tx` and hands it straight to `TxSenderClient::insert_try_to_send` for broadcast, with no check on the transaction's origin, inputs, or relation to the bridge.

### Finding Description
The claimed binding is: `CALLER_AUTHORITY` = (party reaching an `Internal`-prefixed method) `==` (self, i.e. `leaf_cert == our_cert` per `only_aggregator_and_self`).

Tracing the code:
- `only_aggregator_and_self` in `core/src/rpc/interceptors.rs:36-77` is the only place enforcing the "Internal" prefix restriction, gated on `is_internal(&req)` (line 62) checking the `grpc-method` header for an `Internal` prefix.
- This function is only reached when the interceptor variant is `Interceptors::OnlyAggregatorAndSelf`; `Interceptors::Noop::call` (`core/src/rpc/interceptors.rs:30`) simply returns `Ok(req)` and never calls `is_internal` at all.
- In `core/src/servers.rs:106-138`, the interceptor is chosen with `if config.client_verification { OnlyAggregatorAndSelf {...} } else { Noop }`.
- Critically, per `docs/usage.md:203` ("The aggregator does not enforce client certificates but does use TLS for encryption") and `core/src/servers.rs:293-317` (`create_aggregator_grpc_server` only logs a `tracing::warn!` when `client_verification` is true, with no special-casing), the aggregator's server construction goes through the exact same `create_grpc_server` path as verifier/operator, and there is no separate mandatory-authentication branch specific to the aggregator's `InternalSendTx`.
- `AggregatorServer::internal_send_tx` (`core/src/rpc/aggregator.rs:1270-1312`) deserializes `request.into_inner().raw_tx` into a `bitcoin::Transaction` with no verification that the tx originates from an internal/self-signed source, then calls `self.tx_sender.insert_try_to_send(...)`.
- `TxSenderClient::insert_try_to_send` (`crates/clementine-tx-sender/src/client.rs:59-179`) performs deduplication and bookkeeping (cancel/activate outpoints) but contains **no validation that the transaction is one of the bridge's own presigned transactions**, no check against a known transaction-graph, and no relation to any deposit/withdrawal/UTXO the bridge cares about. It will queue and (via the tx-sender background task) broadcast any syntactically valid Bitcoin transaction supplied.

Root cause: the "Internal"-only restriction is implemented purely as a gRPC interceptor gate keyed on `client_verification`; when that config flag is `false` (a supported, documented deployment mode for the aggregator specifically, since aggregator "does not enforce client certificates"), the gate is bypassed entirely rather than degraded to a weaker check. `is_internal`'s method-name check never executes for `Noop`, so the equality `CALLER_AUTHORITY` is never evaluated — it is vacuously "true" for every caller, including an attacker with no certificate at all.

### Impact Explanation
An unauthenticated attacker can submit an arbitrary, fully-formed Bitcoin transaction to `InternalSendTx` and have the aggregator's tx-sender queue/broadcast it using the aggregator's own wallet/fee infrastructure (CPFP/RBF fee-bumping via `insert_try_to_send`). This is a state-changing/broadcasting call reachable with zero authentication, matching the **High** severity category ("an unauthenticated state-changing or broadcasting call"). It does not, by itself, move bridge value out of a vault UTXO (the transaction is attacker-authored and not signed by the N-of-N, so it cannot spend bridge-controlled outputs), but it does let an attacker consume the aggregator's fee-paying capacity/wallet outputs to relay arbitrary transactions, and pollutes the tx-sender's internal state/database (cancellation/activation bookkeeping) with attacker-chosen data. This is repeatable per call and not scoped to any particular deposit or operator — every call is an independent unauthenticated broadcast primitive.

### Likelihood Explanation
This requires the deployment to run the aggregator with `client_verification == false`. This is explicitly a documented, supported aggregator configuration (`docs/usage.md:203`: "The aggregator does not enforce client certificates"), not a misconfiguration outside of scope — the codebase's own default posture for the aggregator is to not enforce client certs. The attacker only needs network access to the aggregator's public gRPC port and the ability to construct a valid Bitcoin transaction (no special privileges, no BTC required beyond what they'd spend if the tx spent their own coins — the tx doesn't even need to be transaction-graph-related). This is highly feasible and trivially repeatable.

### Recommendation
Do not rely solely on `client_verification` to gate `Internal`-prefixed methods. Enforce `is_internal` authorization independent of the `client_verification` toggle — e.g., have `Interceptors::Noop` (or a dedicated aggregator interceptor) still reject any request whose `grpc-method` starts with `Internal` unless the peer presents a valid self/aggregator certificate, or remove `InternalSendTx`'s reachability from the aggregator's public-facing service entirely (route it only through an internal-only channel/socket).

fn is_internal(req: &Request<()>) -> bool {
    // This normally doesn't exist but we add it in the AddMethodMiddleware

        // No grpc method? this should not happen

fn only_aggregator_and_self(
    req: Request<()>,
    our_cert: &CertificateDer<'static>,
    aggregator_cert: &CertificateDer<'static>,
) -> Result<Request<()>, Status> {
    let Some(peer_certs) = req.peer_certs() else {
        if cfg!(test) {
            // Test mode, we don't need to verify peer certificates
            return Ok(req);
        } else {
            // If we're not in test mode, we need to check peer certificates
            return Err(Status::unauthenticated(
                "Failed to verify peer certificate, is TLS enabled?",
            ));
        }
    };

    // IMPORTANT: Only check the leaf (end-entity) certificate, which is always the first
    // certificate in the chain. The leaf is the only certificate whose private key the peer
    // proved possession of during the TLS handshake. Checking anywhere else in the chain
    // would allow identity spoofing: an attacker could include a pinned cert as an
    // intermediate in their chain without possessing its private key.
    let Some(leaf_cert) = peer_certs.first() else {
        return Err(Status::unauthenticated("Peer certificate chain is empty"));
    };

    if is_internal(&req) {
        if leaf_cert == our_cert {
            Ok(req)
        } else {
            Err(Status::unauthenticated(
                "Unauthorized call to internal method (not self)",
            ))
        }
    } else if leaf_cert == aggregator_cert || leaf_cert == our_cert {
        Ok(req)
    } else {
        Err(Status::unauthenticated(
            "Unauthorized call to method (not aggregator or self)",
        ))
    }
}

pub async fn create_aggregator_grpc_server(
    config: BridgeConfig,
) -> Result<(std::net::SocketAddr, oneshot::Sender<()>), BridgeError> {
    let addr: std::net::SocketAddr = format!("{}:{}", config.host, config.port)
        .parse()
        .wrap_err("Failed to parse address")?;
    let aggregator_server = AggregatorServer::new(config.clone()).await?;
    aggregator_server.start_background_tasks().await?;

    let svc = ClementineAggregatorServer::new(aggregator_server)
        .max_encoding_message_size(config.grpc.max_message_size)
        .max_decoding_message_size(config.grpc.max_message_size);

    if config.client_verification {
        tracing::warn!("Client verification is enabled on aggregator gRPC server",);
    }

    let (server_addr, shutdown_tx) =
        create_grpc_server(addr.into(), svc, "Aggregator", &config).await?;

    match server_addr {
        ServerAddr::Tcp(socket_addr) => Ok((socket_addr, shutdown_tx)),
        _ => Err(BridgeError::ConfigError("Expected TCP address".into())),
    }
}

    async fn internal_send_tx(

        request: Request<clementine::SendTxRequest>,
    ) -> Result<Response<Empty>, Status> {
        #[cfg(not(feature = "automation"))]
        {
            Err(Status::unimplemented("Automation is not enabled"))
        }
        #[cfg(feature = "automation")]
        {
            let send_tx_req = request.into_inner();
            let fee_type = send_tx_req.fee_type();
            let signed_tx: bitcoin::Transaction = send_tx_req
                .raw_tx
                .ok_or(Status::invalid_argument("Missing raw_tx"))?
                .try_into()?;
            tracing::warn!(
                "Internal send tx rpc called with feetype: {:?}, tx hex: {}",
                fee_type,
                bitcoin::consensus::encode::serialize_hex(&signed_tx)
            );

            let mut dbtx = self.db.begin_transaction().await?;
            self.tx_sender
                .insert_try_to_send(
                    &mut dbtx,
                    None,
                    &signed_tx,
                    fee_type.try_into()?,
                    None,
                    &[],
                    &[],
                    &[],
                    &[],
                )
                .await
                .map_to_status()?;
            dbtx.commit()
                .await
                .map_err(|e| Status::internal(format!("Failed to commit db transaction: {e}")))?;
            Ok(Response::new(Empty {}))
        }
    }

    pub async fn insert_try_to_send(
        &self,
        dbtx: &mut crate::TxSenderTransaction,
        tx_metadata: Option<TxMetadata>,
        signed_tx: &Transaction,
        fee_paying_type: FeePayingType,
        rbf_signing_info: Option<RbfSigningInfo>,
        cancel_outpoints: &[OutPoint],
        cancel_txids: &[Txid],
        activate_txids: &[ActivatedWithTxid],
        activate_outpoints: &[ActivatedWithOutpoint],
    ) -> Result<u32, BridgeError> {
        let txid = signed_tx.compute_txid();

        // do not add duplicate transactions to the txsender
        let tx_exists = self
            .db
            .check_if_tx_exists_on_txsender(Some(dbtx), txid)
            .await?;
        if let Some(try_to_send_id) = tx_exists {
            return Ok(try_to_send_id);
        }

        tracing::info!(
            "Added tx {} with txid {} to the queue",
            tx_metadata
                .as_ref()
                .map(|data| format!("{:?}", data.tx_type))
                .unwrap_or("N/A".to_string()),
            txid
        );

        let try_to_send_id = self
            .db
            .save_tx(
                dbtx,
                tx_metadata,
                signed_tx,
                fee_paying_type,
                txid,
                rbf_signing_info,
            )
            .await?;

        // only log the raw tx in tests so that logs do not contain sensitive information
        #[cfg(test)]
        tracing::debug!(target: "ci", "Saved tx to database with try_to_send_id: {try_to_send_id}, metadata: {tx_metadata:?}, raw tx: {}", hex::encode(bitcoin::consensus::serialize(signed_tx)));

        for input_outpoint in signed_tx.input.iter().map(|input| input.previous_output) {
            self.db
                .save_cancelled_outpoint(dbtx, try_to_send_id, input_outpoint)
                .await?;
        }
