### Title
LayerZero refund address is silently discarded in `HyperbridgeLzEndpoint.send()`, permanently trapping overpaid native fees - (File: `sdk/packages/lz-endpoint/contracts/HyperbridgeLzEndpoint.sol`)

### Summary
`HyperbridgeLzEndpoint` implements `ILayerZeroEndpointV2.send(MessagingParams, address _refundAddress)` so that existing LayerZero OApps/OFTs can point at Hyperbridge without code changes. The real LayerZero endpoint refunds any `msg.value` overpayment to `_refundAddress`. In this adapter's implementation, `_refundAddress` is explicitly commented out and unused, and no refund of excess native token ever occurs — the full `msg.value` is forwarded to `IDispatcher(_host).dispatch{value: msg.value}(request)`, which is the same broken-refund pattern as the Tapioca M-32 finding: the party entitled to a fee refund is never paid, and the excess value becomes stuck.

The caller-supplied `_refundAddress` parameter — the exact field LayerZero OApps use to receive back any overpaid native fee — is dropped from the function signature entirely (`/* _refundAddress */`). Downstream, `EvmHost.dispatch()` only spends exactly `post.fee` via `swapETHForExactTokens{value: msg.value}(post.fee, ...)`:
```solidity
// evm/src/core/EvmHost.sol:921-932

        IERC20(feeToken()).safeTransferFrom(_msgSender(), address(this), post.fee);

``` [2](#0-1) 

`swapETHForExactTokens` refunds any unspent ETH to the router's caller — here, `EvmHost` itself (since `EvmHost` invoked the router, not the OApp or its user). `HyperbridgeLzEndpoint.send()` has no logic afterward to reclaim that refund from `EvmHost` and forward it to `_refundAddress`, nor to the original `msg.sender` that called `send()`. Compare this to the app-level intent contracts in this same repo (`IntentGatewayV2`, `IntrinsicIntents`, `ExtrinsicIntents`), which correctly compute unspent `msgValue` after any swap/dispatch and explicitly refund it back to the payer:
```solidity
// evm/src/apps/intentsv2/ExtrinsicIntents.sol:164-168
// Refund any unspent native tokens to the solver.
if (msgValue > 0) {
    (bool sent,) = msg.sender.call{value: msgValue}("");
    if (!sent) revert InsufficientNativeToken();
}
``` [3](#0-2) 

`HyperbridgeLzEndpoint.send()` has no equivalent refund step at all — no user-address bookkeeping, no post-dispatch balance check, nothing sent back to `_refundAddress` or `msg.sender`.

### Impact Explanation
This is a direct loss-of-funds bug matching the bounty's "stealing or loss of funds" category. Any OApp/OFT integrator (and by extension every end user of that OApp who quotes a fee with margin, which is standard LayerZero practice to avoid underpayment reverts) that sends native token via `HyperbridgeLzEndpoint.send{value: quotedFee + buffer}(...)` will have their overpayment permanently stuck in `EvmHost`'s balance rather than returned to `_refundAddress` as the `ILayerZeroEndpointV2` interface contract requires. Because `HyperbridgeLzEndpoint` is meant to be a drop-in endpoint replacement for existing OFT/OApp deployments (per the docs, "without any code changes"), any OApp built against the standard LayerZero refund semantics will silently leak native tokens on every send with even minor overpayment — a systemic, cumulative fund loss identical in mechanism to the M-32 seed report.

### Likelihood Explanation
High. This is triggered by an unprivileged, ordinary integration flow — any OApp calling `send()` with `msg.value` greater than the exact relayer fee (which is the LayerZero-standard defensive pattern to avoid `MessagingFee` reverts from price fluctuations). No malicious peer, relayer, or governance actor is needed; it happens on every normal user-facing send call that slightly overpays.

### Recommendation
- Restore use of `_refundAddress` in `send()`: track the exact native amount actually spent by `EvmHost.dispatch()` (e.g., have `dispatch()` return unspent value, or compute `address(this).balance` delta before/after the call) and forward the leftover to `_refundAddress` via a low-level call, following the same pattern already used in `IntentGatewayV2`/`ExtrinsicIntents`/`IntrinsicIntents`.
- Alternatively, have `EvmHost.dispatch()` itself refund any leftover `msg.value` to `_msgSender()` (i.e., the endpoint contract) immediately after the swap, and have `HyperbridgeLzEndpoint.send()` forward that refund to `_refundAddress` in the same transaction.

### Proof of Concept
1. Owner deploys `HyperbridgeLzEndpoint`, calls `setHost`, `setEidMapping`, and sets a relayer fee (e.g., $0.30 equivalent in native token via quote).
2. An OApp (or a user through the OApp) calls:
   ```solidity
   endpoint.send{value: quotedFee * 2}(params, userRefundAddress);
   ```
   as is standard LayerZero practice to guard against price movement between quote and send.
3. Inside `send()`, `_refundAddress` (== `userRefundAddress`) is discarded (`/* _refundAddress */`), and the full `2 * quotedFee` is forwarded to `IDispatcher(_host).dispatch{value: 2*quotedFee}(request)`.
4. Inside `EvmHost.dispatch()`, `swapETHForExactTokens` spends only `quotedFee` worth of ETH and refunds the remaining `quotedFee` ETH — but to `EvmHost` itself (the router's caller), not to `HyperbridgeLzEndpoint` or `userRefundAddress`.
5. `HyperbridgeLzEndpoint.send()` returns without ever recovering or forwarding that refunded ETH. `userRefundAddress`'s balance is unchanged; the overpaid `quotedFee` worth of ETH remains stuck in `EvmHost`'s balance indefinitely, with no sweep/withdraw path visible in `EvmHost.sol` for this scenario.     /// @inheritdoc ILayerZeroEndpointV2
    function send(
        MessagingParams calldata _params,
        address /* _refundAddress */
    ) external payable override whenNotPaused returns (MessagingReceipt memory) {
        bytes memory dest = _eidToStateMachine[_params.dstEid];
        if (dest.length == 0) revert UnknownEid(_params.dstEid);

        // Track nonce
        uint64 nonce = ++_outboundNonce[msg.sender][_params.dstEid][_params.receiver];

        // Compute globally unique identifier
        bytes32 guid = keccak256(
            abi.encodePacked(nonce, _eid, bytes32(uint256(uint160(msg.sender))), _params.dstEid, _params.receiver)
        );

        // Encode the LZ message into the ISMP body
        bytes memory body = abi.encode(
            guid,
            _eid, // srcEid
            bytes32(uint256(uint160(msg.sender))), // sender
            nonce,
            _params.receiver, // receiver OApp on dest
            _params.message
        );

        DispatchPost memory request = DispatchPost({
            dest: dest,
            to: abi.encodePacked(address(this)),
            body: body,
            timeout: 0,
            fee: relayerFee(_params.dstEid),
            payer: address(this)
        });

        if (msg.value > 0) {
            IDispatcher(_host).dispatch{value: msg.value}(request);
        } else {
            // Fee tokens already transferred to this contract by OFT's _payLzToken.
            // The quoted lzTokenFee includes a buffer above the relayer fee so the
            // legacy deployed host's per-byte protocol fee can be paid out of it;
            // approve our full feeToken balance and let the host take what it needs.
            address feeToken = IDispatcher(_host).feeToken();
            IERC20(feeToken).forceApprove(_host, IERC20(feeToken).balanceOf(address(this)));
            IDispatcher(_host).dispatch(request);
        }

        return MessagingReceipt({
            guid: guid,
            nonce: nonce,
            fee: MessagingFee({nativeFee: msg.value, lzTokenFee: 0})
        });
    }
