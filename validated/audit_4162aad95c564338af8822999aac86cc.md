Confirmed: the current `precompiles/pointer/pointer.go` `AddCW20`, `AddCW721`, and `AddCW1155` handlers perform unchecked type assertions on attacker-influenced JSON, which panic (Go's analog to a NULL/invalid dereference) whenever the queried CosmWasm contract's response is missing or misshapes the `name`/`symbol` fields. This does not have a per-call `recover()` (unlike `precompiles/bank/bank.go` which explicitly wraps `Execute` in a `defer recover()`), so the panic propagates out of the precompile.

### Title
Unrecovered panic (invalid type assertion, analogous to NULL pointer dereference) in Pointer precompile's CW20/CW721/CW1155 registration - (File: precompiles/pointer/pointer.go)

### Summary
`AddCW20`, `AddCW721`, and `AddCW1155` in `precompiles/pointer/pointer.go` decode a CosmWasm contract's query response into `map[string]interface{}` and then blindly type-assert `formattedRes["name"].(string)` and `formattedRes["symbol"].(string)` with no `ok` check.

### Finding Description
Any address can be passed to `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` (as long as it decodes to a valid bech32 address); the precompile calls `QuerySmartSafe(ctx, cwAddress, {"token_info":{}})` or `{"contract_info":{}}"` and unmarshals the raw JSON reply into a generic map: [1](#0-0) 
If the target is any CosmWasm contract that a caller controls or deploys (a wasm contract implementing `token_info`/`contract_info` in a way that omits `name`/`symbol`, or returns them as a non-string JSON type such as a number, `null`, or object) — which is a message-level choice entirely under the calling EOA/contract's control — the map value is either absent (`nil`) or a non-`string` type. `interface{}(nil).(string)` and `interface{}(42).(string)` both panic in Go with `interface conversion: interface {} is <nil>/float64, not string`, the direct functional analog of the CVE's NULL pointer dereference on malformed input to a JSON-processing routine (`json_printf`). [2](#0-1) [3](#0-2) 
Critically, `PrecompileExecutor.Execute` in this file has **no** `defer recover()` around the switch dispatch, unlike the sibling `bank` precompile which explicitly guards against exactly this class of bug: [4](#0-3) [5](#0-4) 

### Impact Explanation
A panic inside a `DynamicGasPrecompile.Execute` call is not caught at the precompile-framework layer: `TestDynamicGasPrecompileRepanicsNonGas` explicitly documents and asserts that non-gas-meter panics from the executor propagate out of `RunAndCalculateGas` rather than being converted into an EVM revert. [6](#0-5) 
Whether this crashes a node or is merely "wasted" depends on which outer caller catches it: block-processing paths in `app.go` (`ProcessTxsSynchronousGiga`, `ProcessBlock`) and `legacyabci` do wrap tx/block execution in `recover()`, converting the panic to a `sdkerrors.ErrPanic` result rather than a full crash. [7](#0-6) 
However, I could not verify within the available search budget whether every EVM read-path caller (particularly `eth_call`/`eth_estimateGas`/`eth_createAccessList` in `evmrpc/simulate.go`) wraps the entire EVM execution (not just the outer RPC method) with an equivalent recover before this precompile's `Execute` runs; `EstimateGas`/`EstimateGasAfterCalls` only `recover()` at the RPC-method boundary via `defer recover()` in the metrics-recording defer, which does catch panics for these specific RPC calls and turn them into recorded metrics/errors rather than a request that bubbles further, but the exact downstream JSON-RPC transport behavior on an uncaught panic wasn't fully confirmed for all code paths (e.g. long-running debug/trace calls, or getStorageAt-style calls that also route through the same call stack). [8](#0-7) 
At minimum, this is a reliable transaction-level DoS: any signer can send an EVM transaction that calls `addCW20Pointer`/`addCW721Pointer`/`addCW1155Pointer` against a contract they deploy which returns a `token_info`/`contract_info` reply without `name`/`symbol` as strings, forcing panic-based abort of that transaction's execution (and, per the recovered paths, an `ErrPanic` result) instead of a clean revert — this is reachable by any unprivileged EVM caller and by any `eth_call`/`eth_estimateGas` client pointing at such a contract.

### Likelihood Explanation
High: reaching this code path only requires (1) deploying an arbitrary CosmWasm contract that implements the `token_info`/`contract_info` wasm query with a response lacking string `name`/`symbol` fields (trivial and fully attacker-controlled), and (2) calling the `pointer` precompile's `addCW20Pointer`, `addCW721Pointer`, or `addCW1155Pointer` method with that contract's bech32 address as an argument via a normal EVM transaction, `eth_call`, or `eth_estimateGas`. No special privileges, races, or validator collusion are required.

### Recommendation
Replace the unchecked type assertions with checked (`ok`-returning) assertions in `AddCW20`, `AddCW721`, and `AddCW1155`, returning a proper error (e.g. `"cw contract response missing string name/symbol field"`) instead of panicking, mirroring the safe pattern already used elsewhere in the JSON precompile (`precompiles/json/json.go`) which validates presence/type before use. Additionally, consider adding the same `defer recover()` guard to `pointer.PrecompileExecutor.Execute` that `bank.PrecompileExecutor.Execute` already has, so that any other latent unchecked-type-assertion bug in this precompile degrades to an EVM revert instead of an unrecovered panic.

### Proof of Concept
1. Deploy a CosmWasm contract `C` whose `{"token_info":{}}` query handler returns JSON such as `{"decimals":6}` (omitting `name`/`symbol`) or `{"name":123,"symbol":456}` (wrong types).
2. From any EOA, send an EVM transaction (or `eth_call`) to the Pointer precompile address `0x000000000000000000000000000000000000100b` calling `addCW20Pointer(C.address)` (analogously `addCW721Pointer`/`addCW1155Pointer` with `{"contract_info":{}}`).
3. `formattedRes["name"].(string)` panics with `interface conversion: interface {} is nil, not string` (or `float64, not string`), aborting the transaction with an unrecovered panic inside the precompile executor instead of a graceful revert. [9](#0-8)

	// Ample gas so the decode charges pass and the (panicking) executor runs.
	require.PanicsWithValue(t, "boom", func() {
		_, _, _ = precompile.RunAndCalculateGas(&vm.EVM{StateDB: stateDB}, ethcommon.Address{}, ethcommon.Address{}, input, 100000, big.NewInt(0), nil, false, false)
	})
}

func (s *SimulationAPI) EstimateGas(ctx context.Context, args export.TransactionArgs, blockNrOrHash *rpc.BlockNumberOrHash, overrides *export.StateOverride) (result hexutil.Uint64, returnErr error) {
	startTime := time.Now()
	defer func() {
		recordMetricsWithError(ctx, "eth_estimateGas", s.connectionType, startTime, returnErr, recover())
	}()
	if returnErr = validateStateOverrides(overrides, s.backend.MaxStateOverrideAccounts(), s.backend.MaxStateOverrideSlots()); returnErr != nil {
		return
	}
	/* ---------- fail‑fast limiter ---------- */
	if s.requestLimiter != nil {
		if !s.requestLimiter.TryAcquire(1) {
			returnErr = errors.New("eth_estimateGas rejected due to rate limit: server busy")
			return
		}
		defer s.requestLimiter.Release(1)
	}
	bNrOrHash := rpc.BlockNumberOrHashWithNumber(rpc.LatestBlockNumber)
	if blockNrOrHash != nil {
		bNrOrHash = *blockNrOrHash
	}
	ctx = context.WithValue(ctx, CtxIsWasmdPrecompileCallKey, wasmd.IsWasmdCall(args.To))
	estimate, err := export.DoEstimateGas(ctx, s.backend, args, bNrOrHash, overrides, nil, s.backend.RPCGasCap())
	return estimate, err
}
