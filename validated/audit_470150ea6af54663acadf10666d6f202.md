## Title
Signature Replay / Missing Domain Separation in `addr` Precompile `associate()` Enables Unauthorized Balance Migration - (File: precompiles/addr/addr.go)

### Summary
The `addr` precompile's `associate(v, r, s, customMessage)` method recovers a secp256k1 public key from an arbitrary caller-supplied message hash and signature, then uses the recovered key to force-link an EVM address to a Sei address and immediately migrate all funds from the "cast address" to the newly associated address. The signature verification binds only to the raw bytes of `customMessage` — there is no enforcement of a fixed prefix/domain separator, chain ID, precompile address, or purpose-binding nonce. This mirrors the `http-signature` bug class: the signature authenticates *content*, but not the *context/header* that gives that content its intended meaning, so a signature produced for one purpose can be replayed for a completely different, state-changing purpose.

### Finding Description
`associate()` decodes `v/r/s` and hashes an attacker/caller-controlled `customMessage` string with `crypto.Keccak256Hash`, then calls `helpers.GetAddresses` to `Ecrecover` a public key from that hash and signature [1](#0-0) . Nothing constrains `customMessage` to a canonical, purpose-specific format (e.g., an EIP-191 envelope containing chain ID, contract address, or a Sei-specific domain tag) — the JS test even shows the full EIP-191 preamble being passed in as a plain string argument, entirely under caller control [2](#0-1) .

`Execute()` never uses the `caller` argument for `associate`/`associatePubKey`, so *anyone* can submit the `(v, r, s, customMessage)` tuple, not just the key owner [3](#0-2) .

Once a valid signature/message pair is presented, `associateAddresses` immediately calls `AssociationHelper.AssociateAddresses`, which sets the address mapping and unconditionally calls `MigrateBalance`, sweeping **all** spendable coins and wei balance from the implicit "cast address" (`sdk.AccAddress(evmAddr[:])`) to the newly bound `seiAddr` [4](#0-3) [5](#0-4) .

Because the signature is not domain-separated, **any** ECDSA signature ever produced by a victim's EVM private key — for a totally unrelated purpose (e.g., a `personal_sign` login challenge for an unrelated dApp, an off-chain order signature, or any other raw message-signing flow) — can be captured by an attacker/observer and replayed as the `associate()` arguments. This forces an association and drains the "cast address" balance on the victim's behalf, at a time and by a party the victim never authorized for this specific on-chain action.

### Impact Explanation
`MigrateBalance` performs a real `bankKeeper.SendCoins` / `SendCoinsAndWei` transfer of funds sitting at the cast address [6](#0-5) . Any third party who obtains a signature the victim made for an unrelated purpose can trigger this transfer without the victim's consent for that specific action, satisfying the "unauthorized transfer via precompile" impact bar. It also permanently and irreversibly binds the EVM address to the Sei address and removes the cast BaseAccount, an action the victim may not have intended to trigger at that time or via that unauthenticated signature.

### Likelihood Explanation
Likelihood is elevated by the fact that the recovered pubkey/address is still the victim's own — the attacker cannot redirect funds to themselves — which somewhat limits severity to unauthorized/early/forced execution of a state-changing, fund-moving operation rather than outright theft. However, exploitation requires only a single previously-observed signature from the target (e.g., leaked from mempool, another chain, or a personal-message signing flow), no special privileges, and is fully reachable by any public RPC caller submitting an EVM transaction.

### Recommendation
Bind the signed message to a canonical, versioned domain that includes: a fixed Sei-specific prefix/tag, the chain ID, the `addr` precompile address, and ideally an account nonce, then reject any `customMessage` that does not match this exact canonical construction (rather than trusting caller-supplied text). Additionally, consider requiring `msg.sender`/`caller` to equal the recovered EVM address (or otherwise restricting who may submit the association) so that stray signatures cannot be weaponized by unrelated third parties to trigger balance migration.

### Proof of Concept
1. Victim signs an arbitrary message `M` with their EVM key for any unrelated purpose (e.g., logging into a web3 site via `personal_sign`), producing `(v, r, s)` over `keccak256(M)`.
2. Attacker observes this `(v, r, s, M)` tuple (e.g., via a public API response, leaked signature, or mempool sniffing of a similar association tx).
3. Attacker submits an EVM transaction calling `associate(v, r, s, M)` on the `addr` precompile (`0x0000000000000000000000000000000000001004`) — see `precompiles/addr/addr.go` `associate()` [7](#0-6) .
4. `helpers.GetAddresses` recovers the victim's pubkey/evmAddr/seiAddr from `(v, r, s, keccak256(M))` [8](#0-7) .
5. `associateAddresses` → `AssociateAddresses` → `MigrateBalance` immediately sweeps all spendable coins and wei from `sdk.AccAddress(evmAddr[:])` into `seiAddr`, without the victim ever having signed anything intended to authorize a Sei address association or fund migration [9](#0-8) .

func (p PrecompileExecutor) associate(ctx sdk.Context, method *abi.Method, args []interface{}, value *big.Int) (ret []byte, remainingGas uint64, err error) {
	if err := pcommon.ValidateNonPayable(value); err != nil {
		return nil, 0, err
	}

	if err := pcommon.ValidateArgsLength(args, 4); err != nil {
		return nil, 0, err
	}

	// v, r and s are components of a signature over the customMessage sent.
	// We use the signature to construct the user's pubkey to obtain their addresses.
	v := args[0].(string)
	r := args[1].(string)
	s := args[2].(string)
	customMessage := args[3].(string)

	rBytes, err := decodeHexString(r)
	if err != nil {
		return nil, 0, err
	}
	sBytes, err := decodeHexString(s)
	if err != nil {
		return nil, 0, err
	}
	vBytes, err := decodeHexString(v)
	if err != nil {
		return nil, 0, err
	}

	vBig := new(big.Int).SetBytes(vBytes)
	rBig := new(big.Int).SetBytes(rBytes)
	sBig := new(big.Int).SetBytes(sBytes)

	// Derive addresses
	vBig = new(big.Int).Add(vBig, utils.Big27)

	customMessageHash := crypto.Keccak256Hash([]byte(customMessage))
	evmAddr, seiAddr, pubkey, err := helpers.GetAddresses(vBig, rBig, sBig, customMessageHash)
	if err != nil {
		return nil, 0, err
	}

	return p.associateAddresses(ctx, method, evmAddr, seiAddr, pubkey)
}

func (p PrecompileExecutor) associateAddresses(ctx sdk.Context, method *abi.Method, evmAddr common.Address, seiAddr sdk.AccAddress, pubkey cryptotypes.PubKey) (ret []byte, remainingGas uint64, err error) {
	// Check that address is not already associated
	_, found := p.evmKeeper.GetEVMAddress(ctx, seiAddr)
	if found {
		return nil, 0, fmt.Errorf("address %s is already associated with evm address %s", seiAddr, evmAddr)
	}

	// Associate Addresses:
	associationHelper := helpers.NewAssociationHelper(p.evmKeeper, p.bankKeeper, p.accountKeeper)
	err = associationHelper.AssociateAddresses(ctx, seiAddr, evmAddr, pubkey, false)
	if err != nil {
		return nil, 0, err
	}

	ret, err = method.Outputs.Pack(seiAddr.String(), evmAddr)
	return ret, pcommon.GetRemainingGas(ctx, p.evmKeeper), err
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}

func GetAddresses(V *big.Int, R *big.Int, S *big.Int, data common.Hash) (common.Address, sdk.AccAddress, cryptotypes.PubKey, error) {
	pubkey, err := RecoverPubkey(data, R, S, V, true)
	if err != nil {
		return common.Address{}, sdk.AccAddress{}, nil, err
	}

	evmAddr, err := PubkeyToEVMAddress(pubkey)
	if err != nil {
		return common.Address{}, sdk.AccAddress{}, nil, err
	}
	seiPubkey := PubkeyBytesToSeiPubKey(pubkey)
	seiAddr := sdk.AccAddress(seiPubkey.Address())
	return evmAddr, seiAddr, &seiPubkey, nil
}
