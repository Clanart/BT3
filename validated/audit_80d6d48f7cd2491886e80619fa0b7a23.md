## Analysis

The Sherlock H-16 pattern is: a protocol lets the user supply both "the asset being moved" and "the instruction/target that moves it," without checking the two are bound together — so an attacker can point the instruction at unrelated, protocol-custodied funds instead of their own declared input. The direct analog in this repo is `CallDispatcher`, the shared execution proxy used by `IntentGatewayV2.placeOrder` for `predispatch` flows (e.g., LP-unwrap before escrow).

`CallDispatcher.dispatch()` has **no access control at all** — any address can call it directly with an arbitrary `Call[]` and it will `to.call{value}(data)` unconditionally: [1](#0-0) 

`IntentGatewayV2.placeOrder` uses this **single shared** `_params.dispatcher` instance for every user's predispatch flow: it forwards the user's `predispatch.assets` to the dispatcher, executes the user-supplied `predispatch.call` there, then only sweeps back the specific tokens listed in `order.inputs`: [2](#0-1) 

Because the sweep loop only builds `transferCalls` for the tokens present in `order.inputs`, any token produced as a byproduct of a `predispatch.call` (e.g., unwrapping an LP position that yields both `token0` and `token1`, when the order only declares `token0` as input) is left stranded in the `CallDispatcher` contract's balance indefinitely — there is no mechanism in `IntentGatewayV2` to reach or sweep it (it lives at the dispatcher's address, not the gateway's).

### Title
Unrestricted `CallDispatcher.dispatch()` lets anyone drain byproduct/stranded token balances from the shared intent-predispatch proxy - (File: evm/src/utils/CallDispatcher.sol)

### Summary
`CallDispatcher` is a single, shared, unowned contract used by every `IntentGatewayV2.placeOrder` call to execute user-supplied `predispatch.call` logic before escrow. Its `dispatch()` entrypoint is public with zero authentication, exactly mirroring the H-16 root cause: an unchecked, user-controllable instruction that can act on funds unrelated to the caller's own declared assets. Any token left in `CallDispatcher` after a legitimate predispatch flow (because `placeOrder` only sweeps back tokens matching `order.inputs`, not all outputs of the predispatch call) can be permissionlessly withdrawn by any third party.

### Finding Description
`placeOrder` sends the user's `predispatch.assets` to `_params.dispatcher`, then invokes `ICallDispatcher(dispatcher).dispatch(order.predispatch.call)` with fully user-controlled calldata [3](#0-2) . The gateway then sweeps back only the tokens enumerated in `order.inputs`, using `IERC20(token).balanceOf(dispatcher)` as the amount to pull [4](#0-3) .

Any asset that a predispatch call produces which is *not* one of `order.inputs` (e.g., a second token from an LP unwrap, reward tokens, or a fee-on-transfer remainder for a token not in this order's list) is never retrieved — it remains in `CallDispatcher`. Since `CallDispatcher.dispatch()` has no caller restriction and no binding to the gateway or to any specific order, any external account can call it directly with `Call{to: strandedToken, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, balance)}` and take that balance [1](#0-0) .

This is structurally identical to the H-16 root cause: the "instruction" (predispatch call / dispatch payload) and the "asset actually moved" are never bound to the invoking party's own declared input, so unrelated custodied value becomes reachable by anyone who can construct a valid `Call[]`.

### Impact Explanation
Direct, unauthorized theft of ERC-20/native tokens held by the shared `CallDispatcher`. No relayer, prover, governance actor, or malicious peer is required — a single unprivileged EOA transaction against `CallDispatcher.dispatch()` suffices, satisfying the "stealing or loss of funds" / "unauthorized execution" bounty categories.

### Likelihood Explanation
Requires that some predispatch flow actually leaves a byproduct token balance in the dispatcher (e.g., any LP-unwrap or multi-output `predispatch.call` where the order only lists a subset of the resulting tokens as `order.inputs`). Given `predispatch.call` is arbitrary user calldata and the sweep is narrowly scoped to `order.inputs`, this is a realistic and repeatable occurrence rather than an edge case, and once any value accrues, extraction is trivial and permissionless.

### Recommendation
Restrict `CallDispatcher.dispatch()` to be callable only by the registered `IntentGatewayV2` instance(s) (or make the dispatcher ephemeral/per-order, e.g., a minimal proxy deployed and self-destructed per `placeOrder` call). Additionally, have `placeOrder` sweep the dispatcher's *entire* balance of every token touched by `predispatch.call` (not just those in `order.inputs`), crediting any surplus to protocol dust rather than leaving it in a globally reachable contract.

### Proof of Concept
1. Some user places an order with `predispatch.call` that unwraps an LP position, yielding `tokenA` and `tokenB` in `CallDispatcher`; `order.inputs` only lists `tokenA`. `placeOrder`'s sweep pulls `tokenA` back to the gateway and escrows it; `tokenB` remains in `CallDispatcher`.
2. Attacker (any unrelated EOA, no special role) calls `CallDispatcher.dispatch(abi.encode([Call{to: tokenB, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, IERC20(tokenB).balanceOf(dispatcher))}]))` directly.
3. `dispatch()` performs no caller check and executes the call, transferring `tokenB`'s full stranded balance to the attacker.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
