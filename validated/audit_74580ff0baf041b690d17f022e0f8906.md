### Title
Unauthorized native coin minting via permissionlessly-registered malicious ERC20 whose self-reported balances are trusted as the escrow invariant - (File: `x/erc20/keeper/msg_server.go`)

### Summary
`x/erc20`'s `RegisterERC20` message handler permits **any unprivileged account** to register an arbitrary EVM contract as a token pair when `PermissionlessRegistration` is true, which is the module's default value [1](#0-0)  and is enforced in the handler only via an authority check that is skipped when the param is true [2](#0-1) . Registration only calls the contract's `name`/`symbol`/`decimals` view functions to build coin metadata [3](#0-2)  — it never validates that `transfer`/`balanceOf` behave per the ERC20 standard. `ConvertERC20` (`convertERC20IntoCoinsForNativeToken`) then mints native Cosmos coins to the caller based solely on values queried from that same attacker-controlled contract, both before and after the "escrow" transfer [4](#0-3) .

### Finding Description
The mitigation Illuminate ultimately adopted for the exact bug class described in the source report — validating that returned amounts correspond to real balance deltas — is present in this codebase's `convertERC20IntoCoinsForNativeToken`:
```go
balanceToken := k.BalanceOf(ctx, erc20, contract, types.ModuleAddress)
...
res, err := k.evmKeeper.CallEVMWithData(ctx, sender, &contract, transferData, true, nil)
...
balanceTokenAfter := k.BalanceOf(ctx, erc20, contract, types.ModuleAddress)
...
expToken := big.NewInt(0).Add(balanceToken, tokens)
if r := balanceTokenAfter.Cmp(expToken); r != 0 {
    return nil, sdkerrors.Wrapf(types.ErrBalanceInvariance, ...)
}
// Mint coins
if err := k.bankKeeper.MintCoins(ctx, types.ModuleName, coins); err != nil { ... }
``` [5](#0-4) 

However, this "before/after" check is not a real invariant here: both `balanceToken` and `balanceTokenAfter` are obtained by calling `balanceOf()` **on the same attacker-supplied contract** via `k.BalanceOf` [6](#0-5) [7](#0-6) . A malicious contract fully controls both return values and can trivially make `balanceOf()` always return `previousReportedValue + amount`, and make `transfer()` always return `true` (or emit a fake `Transfer` event), regardless of whether any real value changed hands. The "invariant" check therefore validates nothing when the underlying contract is malicious.

Because `RegisterERC20` is permissionless by default [1](#0-0) , an unprivileged attacker can:
1. Deploy a malicious "ERC20" contract implementing `name/symbol/decimals` (to pass `CreateCoinMetadata`) and stateful `balanceOf`/`transfer` functions that lie about balances.
2. Call `MsgRegisterERC20` to register it as `OWNER_EXTERNAL` token pair — no governance/whitelist required [8](#0-7) .
3. Call `MsgConvertERC20` with an arbitrary `Amount` for that contract, from `x/erc20/keeper/msg_server.go`'s `ConvertERC20` → `convertERC20IntoCoinsForNativeToken` path [9](#0-8) .
4. The malicious contract's crafted `balanceOf`/`transfer` responses satisfy `balanceTokenAfter == balanceToken + amount` unconditionally, so `bankKeeper.MintCoins(ctx, types.ModuleName, coins)` mints real, spendable native Cosmos coins for `msg.Amount` backed by nothing.

This is the direct Cosmos-EVM analog of the Illuminate `Lender.sol` bug: an unvalidated/untrusted external contract's return value is trusted to control minted-asset amount, and no whitelist or true accounting invariant (e.g., checking global total supply, or checking balances from a source independent of the malicious contract) prevents it.

### Impact Explanation
An unprivileged attacker can mint unlimited amounts of real native Cosmos coin (the IBC/ERC20-representation coin registered against their malicious contract) with no backing collateral, then transfer/spend/bridge those coins as legitimate value. This is unauthorized minting and irreversible accounting corruption of spendable user value, matching the Critical impact gate ("Critical unauthorized minting … of spendable user value across native balances … token-pair-backed balances").

### Likelihood Explanation
High. Deploying a malicious ERC20 contract and calling two permissionless, unauthenticated messages (`MsgRegisterERC20`, `MsgConvertERC20`) is trivial for any account with gas funds; no governance vote, relayer, or validator collusion is required given `PermissionlessRegistration` defaults to `true`.

### Recommendation
- Do not derive the mint amount solely from balance queries against the same untrusted, attacker-supplied contract. Independently verify escrow, e.g., by requiring the token to be a module-deployed/audited contract (`OWNER_MODULE`), or by cross-checking against a trusted state source unaffected by the target contract's own logic.
- If permissionless registration of externally-owned ERC20 contracts must remain, gate `ConvertERC20` (which mints native coins) behind additional safeguards such as enforced bytecode/interface conformance checks at registration time, supply caps, or requiring a real value-locking mechanism verified independently of the registered contract's self-reported balances.
- Consider disabling `PermissionlessRegistration` by default, or restricting externally-owned token pairs from participating in the mint-on-convert path unless additional invariants (e.g., total-supply reconciliation) are enforced.

### Proof of Concept
1. Deploy `EvilERC20`:
   - `name()/symbol()/decimals()` return normal values (needed to pass `CreateCoinMetadata`).
   - `balanceOf(address who)` returns a stored `reportedBalance[who]`.
   - `transfer(address to, uint256 amount)`: sets `reportedBalance[to] += amount` (no real balance tracked/enforced) and returns `true`, and emits `Transfer` event.
2. Attacker (no special privileges) submits `MsgRegisterERC20{Signer: attacker, Erc20Addresses: [EvilERC20]}` — succeeds because `PermissionlessRegistration` defaults to true [1](#0-0) .
3. Attacker submits `MsgConvertERC20{ContractAddress: EvilERC20, Amount: 1_000_000_000, Sender: attacker, Receiver: attacker}`.
4. In `convertERC20IntoCoinsForNativeToken`: `balanceToken = EvilERC20.balanceOf(ModuleAddress)` (attacker-controlled) → `transfer(ModuleAddress, amount)` called, sets `reportedBalance[ModuleAddress] += amount`, returns true → `balanceTokenAfter = EvilERC20.balanceOf(ModuleAddress)` equals `balanceToken + amount` by construction → invariant check passes [10](#0-9)  → `bankKeeper.MintCoins` mints `1_000_000_000` of the token-pair denom to the module, then sends to the attacker's receiver account [11](#0-10) .
5. Attacker now holds `1_000_000_000` real, spendable native Cosmos coins with zero underlying collateral.

func (k Keeper) ConvertERC20(
	goCtx context.Context,
	msg *types.MsgConvertERC20,
) (*types.MsgConvertERC20Response, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	// Error checked during msg validation
	receiver := sdk.MustAccAddressFromBech32(msg.Receiver)
	sender := common.HexToAddress(msg.Sender)

	pair, err := k.MintingEnabled(ctx, receiver, msg.ContractAddress)
	if err != nil {
		return nil, err
	}

	// Check ownership and execute conversion
	if pair.IsNativeERC20() {
		// Remove token pair if contract is suicided
		acc := k.evmKeeper.GetAccountWithoutBalance(ctx, pair.GetERC20Contract())
		if acc == nil || !acc.HasCodeHash() {
			k.DeleteTokenPair(ctx, pair)
			k.Logger(ctx).Debug(
				"deleting selfdestructed token pair from state",
				"contract", pair.Erc20Address,
			)
			// NOTE: return nil error to persist the changes from the deletion
			return nil, nil
		}

		return k.convertERC20IntoCoinsForNativeToken(ctx, pair, msg, receiver, sender) // case 2.1
	} else if pair.IsNativeCoin() {
		return nil, types.ErrNativeConversionDisabled
	}

	return nil, types.ErrUndefinedOwner
}

// RegisterERC20 implements the gRPC MsgServer interface. Any account can permissionlessly
// register a native ERC20 contract to map to a Cosmos Coin.
func (k *Keeper) RegisterERC20(goCtx context.Context, req *types.MsgRegisterERC20) (*types.MsgRegisterERC20Response, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	params := k.GetParams(ctx)

	if !params.PermissionlessRegistration {
		if err := k.validateAuthority(req.Signer); err != nil {
			return nil, err
		}
	}

	// Check if the conversion is globally enabled
	if !k.IsERC20Enabled(ctx) {
		return nil, types.ErrERC20Disabled.Wrap("registration is currently disabled by governance")
	}

	for _, addr := range req.Erc20Addresses {
		if !common.IsHexAddress(addr) {
			return nil, errortypes.ErrInvalidAddress.Wrapf("invalid ERC20 contract address: %s", addr)
		}

		pair, err := k.registerERC20(ctx, common.HexToAddress(addr))
		if err != nil {
			return nil, err
		}

// RegisterERC20 creates a Cosmos coin and registers the token pair between the
// coin and the ERC20
func (k Keeper) registerERC20(
	ctx sdk.Context,
	contract common.Address,
) (*types.TokenPair, error) {
	// Check if ERC20 is already registered
	if k.IsERC20Registered(ctx, contract) {
		return nil, errorsmod.Wrapf(
			types.ErrTokenPairAlreadyExists, "token ERC20 contract already registered: %s", contract.String(),
		)
	}

	metadata, err := k.CreateCoinMetadata(ctx, contract)
	if err != nil {
		return nil, errorsmod.Wrap(
			err, "failed to create wrapped coin denom metadata for ERC20",
		)
	}

	pair := types.NewTokenPair(contract, metadata.Name, types.OWNER_EXTERNAL)
	err = k.SetToken(ctx, pair)
	if err != nil {
		return nil, err
	}
	return &pair, nil
}
