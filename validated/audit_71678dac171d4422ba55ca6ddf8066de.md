### Title
Nil `vm.PrecompiledContract` from historical-height precompile version lookup crashes tracing/simulation RPC nodes - ([File: x/evm/keeper/keeper.go])

### Summary
`GetCustomPrecompilesVersions` can fail to populate a version entry for a precompile address when the queried block height precedes an already-completed upgrade for that precompile while a later upgrade for the same precompile is still pending. The caller, `CustomPrecompiles`, then indexes the per-address version map with the resulting empty string, which yields a `nil` `vm.PrecompiledContract` interface value that is installed into the EVM's precompile set and later invoked.

### Finding Description
`GetCustomPrecompilesVersions` computes, for every custom precompile address, which historical version should be active at `ctx.BlockHeight()`: [1](#0-0) 

For a given address, it iterates the `versioned` map of `{upgrade name -> contract}`. It sets `noForkHistory = false` as soon as it finds any upgrade whose `GetDoneHeight` is non-zero (i.e., already completed at some past height), regardless of whether that upgrade's height is above or below the currently queried height. It then `continue`s past any upgrade whose height is still greater than the queried height. If the queried height is smaller than **every** completed-upgrade height it encountered in this pass while at least one upgrade for the address is still un-applied (`upgradeHeight == 0`), the loop can finish having:
- flipped `noForkHistory` to `false` (because a done upgrade existed at all in the map), and
- never satisfied the `upgradeHeight > mostRecentUpgradeHeight` condition for any entry (because the qualifying entries were skipped via `continue`, and the non-done entry has `upgradeHeight == 0`).

In that case, `cp[addr]` is never assigned, and the `noForkHistory` fallback that would set `cp[addr] = k.latestUpgrade` is also skipped because `noForkHistory` was already flipped to `false`. The address is silently dropped from the returned map.

`CustomPrecompiles` then uses this map directly as a lookup key without checking for absence: [2](#0-1) 

`versions[addr]` for the missing entry evaluates to `""` (Go zero value for a missing map key), and `versioned[""]` also misses (no version is registered under the empty string), producing the Go zero value for the `vm.PrecompiledContract` interface — `nil`. This nil interface value is stored as the executable contract for that address in the returned `cp` map, which downstream EVM execution code (dispatch to `vm.PrecompiledContract.RequiredGas()`/`Run()`) will invoke as if it were a real, non-nil precompile, causing a nil-interface method call panic.

This mirrors the CVE-2021-47267 root cause precisely: a code path assumes a "descriptor"/"version" always exists for the requested class (in the kernel case, "super-speed-plus"; here, "the version active at this historical height"), but a valid, reachable input combination (querying a fork-history-bearing precompile at a height that predates one of its completed upgrades while another upgrade for it is still outstanding) causes the lookup to silently fall through to a null/nil value instead of falling back to something safe, and that nil value is later dereferenced/invoked.

`CustomPrecompiles(ctx)` only takes this fallible, per-height path when `ctx.IsTracing()` is true; the non-tracing path always uses the pre-computed `latestCustomPrecompiles`, which is safe because it is guaranteed populated at `SetCustomPrecompiles` time.

### Impact Explanation
`ctx.IsTracing()` contexts are used by the EVM JSON-RPC debug/trace and simulate/estimate endpoints (`debug_traceCall`, `debug_traceTransaction`, `eth_call`, `eth_estimateGas`, etc.) when they replay execution at a specific historical block height/context. If any such request targets an EVM address that is one of the built-in customized precompiles and the requested height sits strictly before the completion height of one already-done upgrade for that precompile while a later upgrade for the same precompile is still pending in the running binary's registry, the resulting nil `vm.PrecompiledContract` will be invoked by the EVM interpreter, panicking the goroutine handling that RPC request. Depending on whether that panic is recovered by the calling handler, this can crash the request-handling goroutine and, on unguarded call sites, take down a default-configuration public RPC node process — a node crash from an unauthenticated JSON-RPC request satisfies the "crash of default-configuration RPC nodes" impact bar.

### Likelihood Explanation
Exploitability depends on the specific set of registered upgrade heights and precompile version maps present on the running chain (there needs to be at least one precompile address whose `versioned` map has a mix of already-completed and not-yet-completed upgrade entries, with the query height sandwiched appropriately). This is a state-dependent condition rather than universally reachable for every historical height/precompile combination, so it is a real code defect but its concrete triggerability depends on chain upgrade history at query time; it is not verified here whether the current mainnet upgrade schedule actually produces this exact ordering for a live precompile address today.

### Recommendation
In `GetCustomPrecompilesVersions`, always fall back to `k.latestUpgrade` (or otherwise explicitly handle the "no matching completed-upgrade version found for this height" case) whenever no entry was set for `cp[addr]`, rather than relying solely on `noForkHistory` to decide whether to apply the fallback. Additionally, `CustomPrecompiles` should defensively skip or replace any `nil` value returned by `versioned[versions[addr]]` before returning the map, so a lookup miss can never propagate a nil `vm.PrecompiledContract` into EVM dispatch.

### Proof of Concept
1. Register a custom precompile address whose `versioned` map contains at least two upgrade tags, e.g. `"v6.0.0"` (registered as done at height 1000 via the upgrade keeper) and `"v6.5"` (not yet done, i.e. `GetDoneHeight` returns 0).
2. Send a `debug_traceCall`/`eth_call` (or any RPC path that builds a `sdk.Context` with `WithIsTracing(true)`) targeting a block height less than 1000 (e.g., height 500) — a height that is valid history for the chain but precedes the `v6.0.0` upgrade completion.
3. `GetCustomPrecompilesVersions` computes, for that address: `v6.0.0` entry sets `noForkHistory=false` then is skipped via `continue` (500 < 1000); `v6.5` entry has `upgradeHeight == 0`, does not trigger `continue`, but also does not satisfy `upgradeHeight > mostRecentUpgradeHeight`. No entry is written for `cp[addr]`, and the `noForkHistory` fallback is bypassed.
4. `CustomPrecompiles` computes `cp[addr] = versioned[""]`, which is `nil`.
5. When the traced/simulated call reaches `addr`, the EVM interpreter invokes methods on the nil `vm.PrecompiledContract`, panicking the request-handling goroutine. [1](#0-0) [2](#0-1)

func (k *Keeper) CustomPrecompiles(ctx sdk.Context) map[common.Address]vm.PrecompiledContract {
	if !ctx.IsTracing() {
		return k.latestCustomPrecompiles
	}
	versions := k.GetCustomPrecompilesVersions(ctx)
	cp := make(map[common.Address]vm.PrecompiledContract, len(k.customPrecompiles))
	for addr, versioned := range k.customPrecompiles {
		cp[addr] = versioned[versions[addr]]
	}
	return cp
}

func (k *Keeper) GetCustomPrecompilesVersions(ctx sdk.Context) map[common.Address]string {
	height := ctx.BlockHeight()
	cp := make(map[common.Address]string, len(k.customPrecompiles))
	for addr, versioned := range k.customPrecompiles {
		mostRecentUpgradeHeight := int64(0)
		noForkHistory := true
		for upgrade := range versioned {
			upgradeHeight := k.upgradeKeeper.GetDoneHeight(ctx, upgrade)
			if upgradeHeight != 0 {
				noForkHistory = false
			}
			if height < upgradeHeight {
				// requested height hasn't seen this upgrade version yet.
				continue
			}
			if upgradeHeight > mostRecentUpgradeHeight {
				mostRecentUpgradeHeight = upgradeHeight
				cp[addr] = upgrade
			}
		}
		if noForkHistory {
			cp[addr] = k.latestUpgrade
		}
	}
	return cp
}
