### Title
Silent, unvalidated `origin` remote URL rewrite driven by GitHub API `clone_url` field - ([File: app/src/lib/stores/updates/update-remote-url.ts])

### Summary
`updateRemoteUrl()` is invoked from `AppStore.repositoryWithRefreshedGitHubRepository()` every time Desktop re-associates a local repository with its GitHub counterpart (account sign-in/out, periodic repository refresh). It fetches an `IAPIRepository` object from the API and, based on a few loose comparisons, calls `git remote set-url` to silently overwrite the user's `origin` remote with `apiRepo.clone_url` — a value that comes directly from the remote server response, not from anything the user typed.

### Finding Description
The relevant code: [1](#0-0) 

The function only checks:
1. that the URL *protocol* of the old and new remote matches (`protocolsMatch`),
2. that the current remote URL still equals the previously cached `gitHubRepository.cloneURL` (`remoteUrlUnchanged`, i.e. the user hasn't hand-edited it),
3. that the new URL differs from the current one (`!urlsMatch`).

None of these checks validate that the *hostname* of the new `clone_url` is trustworthy or unchanged relative to the account's configured endpoint — `urlMatchesRemote` only compares old vs. new remote for equality, it does not compare against the account's expected host. If `apiRepo.clone_url` (as returned by `api.fetchRepository(owner, name)`) points to a different host, owner or repo, this code will happily rewrite `origin` to that value via `gitStore.setRemoteURL` → `setRemoteURL()` → `git remote set-url origin <url>`: [2](#0-1) 

This is reachable from `AppStore.repositoryWithRefreshedGitHubRepository`, which runs the match/refresh flow (using only hostname-based matching in `matchGitHubRepository`) and unconditionally applies `updateRemoteUrl` whenever a `GitHubRepository` association exists: [3](#0-2) [4](#0-3) 

Because `matchGitHubRepository` matches purely by comparing the remote's hostname to the *account's* endpoint hostname (not the specific owner/repo), and `api.fetchRepository` result is server-controlled data (from GitHub.com, GHE, or any endpoint the user is authenticated against, including through a network path that a MITM/compromised GHE/enterprise proxy could tamper with), a malicious or compromised API response can carry an attacker-chosen `clone_url`. The function's only defense (`remoteUrlUnchanged` requiring the current remote to still equal the previously cached clone URL) does not protect a first-time association or any legitimate rename flow — it is specifically designed to let the URL be rewritten in exactly that case.

### Impact Explanation
If the rewrite succeeds, the user's `origin` silently begins pointing to a URL chosen by the API response instead of the URL the user configured. Subsequent `git fetch`/`git push` operations, and — more critically — the credential trampoline (`findGitHubTrampolineAccount`, `findGenericTrampolineAccount`, `trampoline-credential-helper.ts`) will then hand out credentials for whatever host matches the (now-attacker-controlled) remote, since Desktop's credential lookup is keyed off the endpoint/host of the current remote URL: [5](#0-4) [6](#0-5) 

This can result in: silent redirection of the user's future pushes/fetches to an attacker-controlled repository (corruption of what the user pushes), and credential exfiltration if the rewritten host coincides with an endpoint for which Desktop will present stored/OAuth credentials during the ensuing git operation.

### Likelihood Explanation
The trigger path (`repositoryWithRefreshedGitHubRepository`) runs automatically as part of normal background repository refresh and account-change flows, not via any unusual user action, matching the "attacker controls a GitHub API object / git remote or proxy response" bucket. The precondition of a compromised/MITM GHE endpoint or a malicious API response is required, which is a meaningful bar, but no additional local/physical access, admin rights, or social engineering step is needed beyond the network path already being untrusted, and the existing guard (`protocolsMatch`/`remoteUrlUnchanged`) does not validate host trust — it only prevents overwriting URLs the user has manually customized.

### Recommendation
`updateRemoteUrl()` should validate that the new `clone_url`'s hostname matches the *account endpoint* (or the previously known GitHub host) before calling `gitStore.setRemoteURL`, and should require explicit user confirmation before silently changing `origin`, similar to how `repository-settings.tsx` requires the user to explicitly submit a URL change. At minimum, log/warn and refuse the rewrite when the new host differs from the old host, rather than only checking protocol equality.

### Proof of Concept
1. User has an account configured against a GitHub Enterprise Server endpoint whose network path can be intercepted (or the endpoint itself is later compromised).
2. Desktop performs a routine `repositoryWithRefreshedGitHubRepository` refresh (e.g., after sign-in) and calls `api.fetchRepository(owner, name)`.
3. The attacker-controlled response includes `clone_url: "https://github-attacker.example/victim/repo.git"` with the same protocol as before.
4. Because `gitStore.defaultRemote.url` still equals the previously cached `gitHubRepository.cloneURL` (typical case for a repo the user hasn't manually re-pointed), `updateRemoteUrl` calls `gitStore.setRemoteURL('origin', 'https://github-attacker.example/victim/repo.git')`, rewriting the local `.git/config` remote silently.
5. On the next `git push`/`git fetch`, Desktop's trampoline credential helper hands out the user's credentials/token to the attacker-controlled host, and future pushes land in the attacker's repository instead of the intended one.

Note: I could not fully trace every scheduling call site of `repositoryWithRefreshedGitHubRepository` (38 references in `app-store.ts`) within the available search budget, so the exact frequency/triggers (e.g., whether it also fires on every periodic background fetch versus only account-change) is not fully confirmed — a Devin session with full file access would be needed to enumerate all call sites precisely.

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

export function matchGitHubRepository(
  accounts: ReadonlyArray<Account>,
  remote: string
): IMatchedGitHubRepository | null {
  for (const account of accounts) {
    const htmlURL = getHTMLURL(account.endpoint)
    const { hostname } = URL.parse(htmlURL)
    const parsedRemote = parseRemote(remote)

    if (parsedRemote !== null && hostname !== null) {
      if (parsedRemote.hostname.toLowerCase() === hostname.toLowerCase()) {
        return { name: parsedRemote.name, owner: parsedRemote.owner, account }
      }
    }
  }

  return null
}
