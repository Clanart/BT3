## Analog Found

### Title
Auctioneer/AuctionEntryPoint address rotation unconditionally wipes all pending winning bids for already-committed future blocks, causing guaranteed loss of won auction slots — (File: `kaiax/auction/impl/bid_pool.go`)

### Summary
The Olas report describes a class of bug where a privileged manager-contract swap (`Dispenser::changeManagers`) silently discards accrued, unclaimed state tied to the old configuration, causing legitimate participants to permanently lose value that had already accrued under the prior configuration. The Kaia auction module (KIP-249) contains the same root-cause pattern: whenever the `Auctioneer` or `AuctionEntryPoint` address (read every block from the on-chain `Registry`/`AuctionEntryPoint` system contracts) changes, the entire in-memory bid pool — including all already-validated winning bids reserved for near-future blocks — is unconditionally wiped, with no draining/settlement grace period.

### Finding Description
Every block, `AuctionModule.PostInsertBlock` re-reads the current auctioneer and entry-point configuration from state and forwards it to the bid pool via `updateAuctionInfo`: [1](#0-0) 

`BidPool.updateAuctionInfo` compares the newly-read values against the previously cached ones, and if **any** of `auctioneer`, `auctionEntryPoint`, `auctionEntryPointVersion`, or `bidTxGasBuffer` differ, it calls `clearBidPool()`, which unconditionally resets `bidMap`, `bidTargetMap`, and `bidWinnerMap` to empty maps: [2](#0-1) 

This wipe is not scoped to the specific bid(s) that would actually become invalid under the new configuration (e.g., only bids whose `AuctioneerSig` no longer verifies). It clears **every** pending bid across **all** buffered future blocks (`[currentBlock+1, currentBlock+allowFutureBlock]`), including winning bids for blocks that a searcher has already locked in via `bp.bidWinnerMap`, and for which the target transaction may already be included/expected in an upcoming block: [3](#0-2) 

The corresponding test confirms this exact "clear on any address change" behavior is intentional: [4](#0-3) 

This mirrors the Olas root cause precisely: a manager/config-contract address change (owner-controlled, analogous to `Dispenser::changeManagers`) triggers a full reset of accrued/pending participant state (`mapLastClaimedStakingEpochs` there vs. `bidMap`/`bidWinnerMap` here) instead of a graceful, scoped transition — resulting in loss of value that legitimate participants had already locked in under the old configuration.

### Impact Explanation
A searcher who has a winning bid queued for inclusion at a specific upcoming block (having already paid off-chain costs, signed an EIP-712 commitment, and possibly reserved balance for the `SwapForGas`/auction settlement flow) loses that guaranteed inclusion the instant the entry point admin rotates the `Auctioneer` key or upgrades the `AuctionEntryPoint` contract via the system `Registry` — even for a routine, benign operational rotation unrelated to that specific bid. Because the wipe is pool-wide rather than scoped to bids that actually fail re-validation, all in-flight winning bids for the next `allowFutureBlock` blocks are dropped simultaneously with no resubmission window, causing systemic loss of auction settlement value/opportunity for bidders and unpredictable MEV redistribution at every legitimate key-rotation event.

### Likelihood Explanation
`updateAuctionInfo` executes unconditionally on **every** block via `PostInsertBlock`, so any legitimate, DAO/operator-driven rotation of the auctioneer key or entry-point contract (a normal operational event, expected to happen periodically for key-hygiene reasons, similar to how Olas's DAO would rotate `VoteWeighting`) immediately triggers the full-pool wipe. No malicious actor is required — this is a deterministic consequence of an ordinary administrative action reachable through the auction system contracts, matching the "Medium" severity classification the Olas triage settled on for the analogous issue (state loss under an expected, non-malicious admin action, mitigable only by out-of-band operational care, e.g. waiting for the bid pool to drain before rotating).

### Recommendation
Scope the invalidation to only the bids that actually fail re-validation under the new auctioneer/entry-point configuration (e.g., re-run `validateBidSigs` against the new `auctioneer`/`auctionEntryPointVersion` for each existing bid, and only evict those that no longer pass), rather than unconditionally clearing `bidMap`, `bidTargetMap`, and `bidWinnerMap`. Alternatively, document and enforce an operational procedure (as Olas ultimately did) requiring the bid pool to be drained/settled before rotating `Auctioneer`/`AuctionEntryPoint`, and consider emitting a clear on-chain/log warning before the rotation takes effect so searchers can react.

### Proof of Concept
1. Searcher submits a bid for `blockNumber = curBlock+2`; it passes `validateBid`/`validateBidSigs` against the current `auctioneer` and is inserted into `bidMap`/`bidTargetMap`/`bidWinnerMap` (`kaiax/auction/impl/bid_pool.go:250-324`).
2. Before block `curBlock+2` is produced, the `AuctionEntryPoint` owner calls `changeAuctioneer`/`setAuctioneer` (see `contracts/bindings/auctionv3/Kip249V3.go:546-561`, `contracts/testing/system_contracts/AuctionEntryPointMock.sol:46-48`) to rotate the auctioneer key for routine key hygiene.
3. At the very next block, `AuctionModule.PostInsertBlock` re-reads the auctioneer address, detects the change, and calls `bidPool.updateAuctionInfo`, which invokes `clearBidPool()` (`kaiax/auction/impl/bid_pool.go:195-213`).
4. The searcher's already-winning bid for `curBlock+2` is deleted from `bidMap`/`bidTargetMap`/`bidWinnerMap` along with every other pending bid, and is never resubmitted in time, so the searcher's target transaction is built without the expected bid transaction — the searcher's locked-in auction slot and any associated value is unrecoverably lost, exactly as in `TestBidPool_UpdateAuctionInfo` (`kaiax/auction/impl/bid_pool_test.go:481-498`), which demonstrates the pool going from non-empty to `Empty` purely due to an address change.

// updateAuctionInfo updates the auctioneer address and auction entry point address for the given block number.
// It expects the `num` is after Randao fork.
// It returns true if the non-zero auctioneer address and auction entry point address are set, otherwise false.
func (a *AuctionModule) updateAuctionInfo(num *big.Int) bool {
	auctioneer := common.Address{}
	auctionEntryPointAddr := common.Address{}
	auctionEntryPointVersion := ""
	bidTxGasBuffer := uint64(0)

	defer func() {
		a.bidPool.updateAuctionInfo(auctioneer, auctionEntryPointAddr, auctionEntryPointVersion, bidTxGasBuffer)
	}()

	header := a.Chain.GetHeaderByNumber(num.Uint64())
	if header == nil {
		return false
	}
	_, err := a.Chain.StateAt(header.Root)
	if err != nil {
		return false
	}

	backend := backends.NewBlockchainContractBackend(a.Chain, nil, nil)

	// 1. Read auction entry point address
	auctionEntryPointAddr, err = system.ReadActiveAddressFromRegistry(backend, system.AuctionEntryPointName, num)
	if err != nil {
		return false
	}

	if auctionEntryPointAddr == (common.Address{}) {
		return false
	}

	// 2. Read auctioneer address
	auctioneer, err = system.ReadAuctioneer(backend, auctionEntryPointAddr, num)
	if err != nil {
		return false
	}

	if auctioneer == (common.Address{}) {
		return false
	}

// clearBidPool clears the bid pool.
func (bp *BidPool) clearBidPool() {
	bp.bidMu.Lock()
	defer bp.bidMu.Unlock()

	bp.bidMap = make(map[common.Hash]*auction.Bid)
	bp.bidTargetMap = make(map[uint64]map[common.Hash]*auction.Bid)
	bp.bidWinnerMap = make(map[uint64]map[common.Address]common.Hash)
}

// updateAuctionInfo updates the auction info if the auctioneer or auction entry point address is changed.
func (bp *BidPool) updateAuctionInfo(auctioneer common.Address, auctionEntryPoint common.Address, auctionEntryPointVersion string, bidTxGasBuffer uint64) {
	bp.auctionInfoMu.Lock()
	defer bp.auctionInfoMu.Unlock()

	if bp.auctioneer == auctioneer && bp.auctionEntryPoint == auctionEntryPoint && bp.auctionEntryPointVersion == auctionEntryPointVersion && bp.bidTxGasBuffer == bidTxGasBuffer {
		return
	}

	// Clear the existing auction pool since the auctioneer or auction entry point address is changed.
	bp.clearBidPool()

	bp.auctioneer = auctioneer
	bp.auctionEntryPoint = auctionEntryPoint
	bp.auctionEntryPointVersion = auctionEntryPointVersion
	bp.bidTxGasBuffer = bidTxGasBuffer

	logger.Info("Update auction info", "auctioneer", auctioneer, "auctionEntryPoint", auctionEntryPoint, "auctionEntryPointVersion", auctionEntryPointVersion, "bidTxGasBuffer", bidTxGasBuffer)
}

// AddBid adds a bid to the bid pool.
// Required mutex is locked in each function.
func (bp *BidPool) AddBid(bid *auction.Bid) (common.Hash, error) {
	if atomic.LoadUint32(&bp.running) == 0 {
		return common.Hash{}, auction.ErrAuctionPaused
	}

	if err := bp.validateBid(bid); err != nil {
		return common.Hash{}, err
	}

	if err := bp.insertBid(bid); err != nil {
		return common.Hash{}, err
	}

	gasLimit, err := bp.getBidTxGasLimit(bid)
	if err != nil {
		return common.Hash{}, err
	}
	bid.SetGasLimit(gasLimit)

	bp.newBidCh <- bid

	return bid.Hash(), nil
}

func (bp *BidPool) insertBid(bid *auction.Bid) error {
	bp.bidMu.Lock()
	defer bp.bidMu.Unlock()

	var (
		blockNumber  = bid.BlockNumber
		targetTxHash = bid.TargetTxHash
		sender       = bid.Sender
	)

	// Re-check bidWinnerMap here — two concurrent bids can pass validateBid together.
	if _, ok := bp.bidMap[bid.Hash()]; ok {
		return auction.ErrBidAlreadyExists
	}
	if bp.senderHasDifferentWinner(bid) {
		return auction.ErrBidSenderExists
	}

	// If same block number, same target tx hash exists, replace it if it's better
	if existingBid, ok := bp.bidTargetMap[blockNumber][targetTxHash]; ok {
		// FCFS if the bid is the same.
		if existingBid.Bid.Cmp(bid.Bid) >= 0 {
			return auction.ErrLowBid
		}

		logger.Trace("Replace bid", "old", existingBid.Hash(), "new", bid.Hash())
		delete(bp.bidMap, existingBid.Hash())
		delete(bp.bidWinnerMap[blockNumber], existingBid.Sender)
	} else {
		if int64(len(bp.bidMap)) >= bp.maxBidPoolSize {
			logger.Info("Bid pool is full", "maxBidPoolSize", bp.maxBidPoolSize, "bid", bid.Hash())
			return auction.ErrBidPoolFull
		}
	}

	hash := bid.Hash()

	bp.initializeBidMap(blockNumber)

	bp.bidMap[hash] = bid
	bp.bidTargetMap[blockNumber][targetTxHash] = bid
	bp.bidWinnerMap[blockNumber][sender] = hash

	numBidsGauge.Update(int64(len(bp.bidMap)))

	logger.Trace("Add bid", "bid", hash)

	return nil
}
