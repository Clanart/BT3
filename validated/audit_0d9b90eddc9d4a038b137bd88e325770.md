### Title
`updateRemoteUrl()` silently rewrites the git `origin` remote based on trust in the GitHub API's `clone_url`, allowing silent push/fetch redirection - ([File: app/src/lib/stores/updates/update-remote-url.ts])

### Summary
`updateRemoteUrl()` automatically calls `gitStore.setRemoteURL()` to overwrite the user's configured "origin" remote whenever the cached `GitHubRepository.cloneURL` still matches the local remote but the freshly-fetched `IAPIRepository.clone_url` from the GitHub API does not, with the same trust-without-verification bug class as the `privateMint()` finding: an external, attacker-influenceable value (`apiRepo.clone_url`) is consumed and used to mutate a security-relevant setting (the destination that future `git push`/`git fetch` operations will use) with no user confirmation and no verification that the new URL still points to a repository the user actually intended. [1](#0-0) 

### Finding Description
The function reads the current default remote URL, compares it against the repository object's cached `cloneURL` and the live API's `clone_url`, and if the protocol matches and the remote appears "unchanged" from the last known API value but doesn't match the *new* API value, it silently rewrites the remote: [2](#0-1) 

The matching logic relies on `urlMatchesRemote()`, which in turn uses the regex-based `parseRemote()` in `remote-parsing.ts` to extract `hostname`/`owner`/`name` and only checks case-insensitive equality of those three fields — it performs no validation that the hostname belongs to a trusted GitHub endpoint, no certificate/identity pinning, and no cross-check against the account's configured endpoint: [3](#0-2) [4](#0-3) 

Because `apiRepo` originates from a GitHub API response (an attacker-controllable object per the scope of this analysis — e.g. a compromised/MITM'd GitHub Enterprise Server response, or an API response returned during a repository-rename/transfer race), the `clone_url` field is not otherwise authenticated as still referring to the same underlying repository. If it differs from the locally configured remote while still passing the loose `owner`/`name`/`hostname` string-equality checks (or simply differs enough to trigger the "protocol matches, remote unchanged from last-known API value" branch), Desktop will call `gitStore.setRemoteURL()` and silently repoint `origin` — with no dialog, confirmation, or diff shown to the user.

Existing guards do not stop this path: `urlMatchesRemote` is a coarse string comparison, not a network trust check; `protocolsMatch` only compares the URL scheme (`https:`/`ssh:`), not the actual host; and there is no user-facing prompt anywhere in `updateRemoteUrl()`.

### Impact Explanation
Silently changing the `origin` remote URL means every future `git push` and `git fetch`/`git pull` the user performs in Desktop's UI will transparently target the attacker-controlled remote instead of the one the user believes they are using. This can result in the user unknowingly pushing commits (potentially including credentials embedded in commit history, private code, etc.) to an attacker-controlled server, or fetching/merging attacker-supplied history into their working repository — a direct instance of "silent corruption of what the user commits or pushes," which is explicitly listed as a valid impact category.

### Likelihood Explanation
Likelihood is Low/Moderate: it requires the GitHub API response (`clone_url`) consumed by this code path to diverge from the actual intended remote while the surrounding heuristic conditions (`protocolsMatch`, `remoteUrlUnchanged`, `!urlsMatch`) align — a scenario realistically reachable via a compromised or spoofed GitHub Enterprise Server endpoint, a man-in-the-middle on an HTTP(S) GHE deployment, or abuse of GitHub's repository-rename/ownership-transfer semantics where the `clone_url` for a given repository ID can legitimately change to a different owner/name that an attacker has claimed. No local access, admin rights, or social engineering step is required beyond the user having previously added the repository and Desktop performing its normal automatic refresh cycle.

### Recommendation
Do not silently rewrite the `origin` remote from API-sourced data. At minimum:
- Require explicit user confirmation before changing a remote URL, showing the old and new URL.
- Validate that the new `clone_url`'s hostname matches the account's known/trusted endpoint before treating it as equivalent.
- Treat `IAPIRepository.clone_url` as untrusted input and avoid using it as the sole basis for mutating local git configuration.

### Proof of Concept
1. User adds/clones a repository hosted on a GitHub Enterprise Server (or in an ownership-transfer race on GitHub.com) and Desktop caches `GitHubRepository.cloneURL` matching the configured `origin` remote.
2. On a subsequent repository refresh, the GHES endpoint (compromised, MITM'd over HTTP, or simply returning updated API data for a transferred/renamed repo) is queried and returns an `IAPIRepository` object whose `clone_url` now points to an attacker-controlled host/owner while keeping the same protocol scheme.
3. `updateRemoteUrl()` evaluates `protocolsMatch = true`, `remoteUrlUnchanged = true` (matches previously cached `cloneURL`), and `urlsMatch = false` (differs from the new `clone_url`), satisfying the condition at [5](#0-4)  and silently calling `gitStore.setRemoteURL()`.
4. The user's next `git push`/`git fetch` in Desktop's UI silently targets the attacker's remote, with no dialog or warning shown.

export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
}

export function urlMatchesRemote(url: string | null, remote: IRemote): boolean {
  if (url == null) {
    return false
  }

  const cloneUrl = parseRemote(url)
  const remoteUrl = parseRemote(remote.url)

  if (remoteUrl == null || cloneUrl == null) {
    return false
  }

  if (!caseInsensitiveEquals(remoteUrl.hostname, cloneUrl.hostname)) {
    return false
  }

  if (remoteUrl.owner == null || cloneUrl.owner == null) {
    return false
  }

  if (remoteUrl.name == null || cloneUrl.name == null) {
    return false
  }

  return (
    caseInsensitiveEquals(remoteUrl.owner, cloneUrl.owner) &&
    caseInsensitiveEquals(remoteUrl.name, cloneUrl.name)
  )
}

/** Parse the remote information from URL. */
export function parseRemote(url: string): IGitRemoteURL | null {
  for (const { protocol, regex } of remoteRegexes) {
    const match = regex.exec(url)
    if (match !== null && match.length >= 4) {
      return { protocol, hostname: match[1], owner: match[2], name: match[3] }
    }
  }

  return null
}
