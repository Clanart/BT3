### Title
Permissionless `harvest()` converts protocol fees with zero slippage protection, enabling MEV theft of queued yield - (File: `wombat/WombatStaking.sol`)

### Summary
`WombatStaking.harvest()` is callable by any unprivileged wallet and internally triggers `_sendRewards`, which converts the WOM fee portion to mWOM through `smartConvert(feeAmount, 0)` — a hardcoded zero minimum-received value, i.e. no slippage protection at all. This is the same bug class as the external report (disabled slippage protection on a hook/convert call), but here it does not even require a malicious privileged strategist: any ordinary address can call the permissionless `harvest()` function and sandwich the resulting AMM swap to steal the value that should have been converted into mWOM and queued as yield.

### Finding Description
`harvest()` has no caller restriction beyond pool-state checks: [1](#0-0) 

It calls `_toMasterWomAndSendReward`, which calls `_sendRewards` for the harvested WOM: [2](#0-1) 

Inside `_sendRewards`, the fee portion of the harvested WOM is converted to mWOM via `smartConvert`, with the minimum-received argument hardcoded to `0`: [3](#0-2) 

`smartConvert` forwards this into `_convertFor`, which performs a WOM→mWOM swap through `IWombatRouter.swapExactTokensForTokens` and enforces `_minRec` as the only protection against unfavorable pricing: [4](#0-3) [5](#0-4) 

Because `_minRec` is fixed to `0` at the `WombatStaking` call site, this check can never revert regardless of the swap's execution price. Any wallet can call `harvest()` immediately after manipulating the WOM/mWOM pool price (or simply sandwich the transaction), causing the fee swap to execute at a heavily degraded rate. The resulting `feeTosend` (post-swap mWOM balance) is then queued into `IBaseRewardPool(feeInfo.to).queueNewRewards(...)` — i.e., this is yield destined for locker/stakers of the reward pool: [6](#0-5) 

### Impact Explanation
The value that should be converted and queued as yield to the `BaseRewardPool`/locker recipients is instead captured by the attacker performing the sandwich, since the conversion has no floor. This is a direct theft of unclaimed protocol yield, triggerable by any unprivileged wallet without needing any special role, satisfying the "theft of unclaimed yield" impact bar.

### Likelihood Explanation
`harvest()` is a fully permissionless, unauthenticated external function; any address can invoke it whenever WOM rewards are pending. Since the conversion parameter is hardcoded to zero rather than computed from an oracle/expected rate, the attacker only needs standard front-running/sandwiching capability (flash loan a large swap on the WOM/mWOM pool, call `harvest()`, then reverse the swap) — no privileged access is required, making this readily exploitable by any MEV-capable wallet.

### Recommendation
Do not hardcode `minRec = 0` in the `smartConvert` call inside `_sendRewards`. Compute an expected output using `estimateTotalConversion`/`currentRatio` (already available in `SmartWomConvert`) with a bounded slippage tolerance, and revert if the realized output falls below that threshold, mirroring the protection intended to exist in the original report but tying it to a value derived on-chain rather than an operator-supplied or hardcoded number.

### Proof of Concept
1. Attacker monitors the WOM/mWOM Wombat pool for harvest eligibility (WOM rewards accrued in `WombatStaking`).
2. Attacker front-runs by swapping a large amount of mWOM into the WOM/mWOM pool to depress the WOM price relative to mWOM (or otherwise skew the pool).
3. Attacker (or anyone) calls `WombatStaking.harvest(lpToken)`, which triggers `_sendRewards` → `smartConvert(feeAmount, 0)` → `_convertFor` → `IWombatRouter.swapExactTokensForTokens(..., 0, ...)`. Because `_minRec` is `0`, the swap executes at the attacker-manipulated unfavorable price without reverting.
4. Attacker back-runs by reversing the initial swap, pocketing the difference extracted from the fee amount that should have gone to `IBaseRewardPool.queueNewRewards` as yield for stakers/lockers.

    function smartConvert(uint256 _amountIn, uint256 _mode) external returns (uint256 obtainedmWomAmount) {
        if (_amountIn == 0) revert MustNoBeZero();

        uint256 convertRatio = DENOMINATOR;
        uint256 mWomToWom = currentRatio();

        if (mWomToWom < buybackThreshold) {
            uint256 maxSwap = maxSwapAmount();
            uint256 amountToSwap = _amountIn > maxSwap ? maxSwap : _amountIn;
            uint256 convertAmount = _amountIn - amountToSwap;
            convertRatio = convertAmount * DENOMINATOR / _amountIn;
        }

        return _convertFor(_amountIn, convertRatio, _amountIn, msg.sender, _mode);
    }
