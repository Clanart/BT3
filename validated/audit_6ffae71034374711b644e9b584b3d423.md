## Finding

### Title
Automatic, unconfirmed rewrite of the `origin` remote URL from an untrusted GitHub API response - (File: `app/src/lib/stores/updates/update-remote-url.ts`)

### Summary
The Sherlock report's underlying pattern is: a security-critical destination value (the fee recipient) can be overwritten in a single step by trusting external/attacker-influenced input, with no second "accept" step to confirm the new value before it takes effect. The GitHub Desktop analog is the periodic, background rewrite of a repository's `origin` remote URL: `updateRemoteUrl()` silently calls `gitStore.setRemoteURL()` to point the local git remote at whatever `clone_url` the GitHub API returns for the matched repository, with no user prompt or "accept" step, unlike the analogous upstream-remote-update flow in this same codebase which *does* require explicit user confirmation via a dialog.

### Finding Description
`repositoryWithRefreshedGitHubRepository()` runs during ordinary repository refresh. It matches the local remote to an "owner/name" pair purely from string-parsing the existing remote URL, fetches the repository object from the GitHub API, and — if the API repo lookup succeeds — feeds the API's `clone_url` straight into `updateRemoteUrl()`: [1](#0-0) 

`updateRemoteUrl()` then performs the actual mutation with only a superficial protocol/string check, no cryptographic or identity verification of the API response, and no confirmation from the user: [2](#0-1) 

The guard conditions are: (1) the URL protocol (ssh vs https) hasn't changed, and (2) the *current* remote URL still textually matches the previously cached `gitHubRepository.cloneURL` (i.e., the user hasn't manually edited it). Neither condition validates that the `apiRepo.clone_url` value genuinely originates from a trustworthy source for the *same* logical repository — it is accepted and written via `setRemoteURL` in one step: [3](#0-2) [4](#0-3) 

Notably, this codebase already implements the *correct* two-step pattern elsewhere for a very similar operation — updating the `upstream` remote for a fork. That flow shows an explicit `UpstreamAlreadyExists` dialog and only rewrites the remote after the user clicks "Update": [5](#0-4) 

The `origin` remote — arguably the more security-sensitive of the two, since it's the destination for the user's `git push` — has no such confirmation gate in `updateRemoteUrl()`.

### Impact Explanation
Since `origin` is the default push/fetch target, a single-step, unconfirmed rewrite of its URL directly enables silent corruption of where the user's future commits/pushes go and where fetched content comes from — matching the "silent corruption of what the user commits or pushes" impact class. If the value returned in `apiRepo.clone_url` is attacker-influenced (e.g., a malicious/compromised GitHub Enterprise Server endpoint, or a spoofed/MITM'd API response for that endpoint), Desktop will retarget the local repo's remote to an attacker-controlled host without ever prompting the user, unlike the analogous upstream-remote case which requires explicit confirmation.

### Likelihood Explanation
This is triggered automatically as part of routine repository refresh (`repositoryWithRefreshedGitHubRepository`) any time the app fetches repository metadata from the API — no unusual user action is required beyond normal use of Desktop with the affected endpoint. The trigger condition (`protocolsMatch && remoteUrlUnchanged && !urlsMatch`) is satisfied whenever the API-reported `clone_url` diverges from the current remote while the user hasn't manually customized their remote — a state most users are in by default.

### Recommendation
Apply the same two-step approach already used for the upstream-remote-exists case: instead of calling `gitStore.setRemoteURL()` directly inside `updateRemoteUrl()`, surface a confirmation prompt (reusing the `UpstreamAlreadyExists`-style dialog pattern) showing the current vs. proposed `origin` URL, and only call `setRemoteURL` after explicit user acceptance. Additionally, verify repository identity (e.g., by GitHub repository ID, not just owner/name/clone_url string matching) before treating an API response as authoritative for updating `origin`.

### Proof of Concept
1. User has a repository cloned with `origin` = `https://ghe.example.com/owner/name`, tracked in Desktop against a GHE endpoint account.
2. During a background refresh, `repositoryWithRefreshedGitHubRepository()` calls `api.fetchRepository(owner, name)` against that endpoint [6](#0-5) .
3. The endpoint (compromised, misconfigured, or MITM'd) returns an `IAPIRepository` whose `clone_url` differs from the current remote but keeps the same protocol.
4. `updateRemoteUrl()` sees `protocolsMatch === true`, `remoteUrlUnchanged === true` (user hadn't touched the remote), `urlsMatch === false`, and calls `gitStore.setRemoteURL(name, updatedRemoteUrl)` [7](#0-6) .
5. `setRemoteURL` runs `git remote set-url origin <attacker-url>` with no dialog, confirmation, or user visibility [4](#0-3) .
6. The user's next `git push`/`git fetch` in Desktop silently targets the attacker-controlled URL.

```typescript
export async function updateRemoteUrl(
  gitStore: GitStore,
  gitHubRepository: GitHubRepository,
  apiRepo: IAPIRepository
): Promise<void> {
  // I'm not sure when these early exit conditions would be met. But when they are
  // we don't have enough information to continue so exit early!
  if (gitStore.defaultRemote === null) {
    return
  }

  const remoteUrl = gitStore.defaultRemote.url
  const updatedRemoteUrl = apiRepo.clone_url
  const urlsMatch = urlMatchesRemote(updatedRemoteUrl, gitStore.defaultRemote)

  // Verify that protocol hasn't changed. If it has we don't want
  // to alter the protocol in case they are relying on a specific one.
  // If protocol is null that implies the url is a ssh url
  // of the format git@github.com:octocat/Hello-World.git, which
  // can't be parsed by URL.parse. In this case we assume the user
  // manually configured their remote to use this format and we don't
  // want to change what they've done just to be safe
  const parsedRemoteUrl = URL.parse(remoteUrl)
  const parsedUpdatedRemoteUrl = URL.parse(updatedRemoteUrl)
  const protocolsMatch =
    parsedRemoteUrl.protocol !== null &&
    parsedUpdatedRemoteUrl.protocol !== null &&
    parsedRemoteUrl.protocol === parsedUpdatedRemoteUrl.protocol

  // Check if the default remote url has been manually changed from the
  // clone url retrieved from the GitHub API previously
  const remoteUrlUnchanged =
    gitStore.defaultRemote &&
    urlMatchesRemote(gitHubRepository.cloneURL, gitStore.defaultRemote)

  if (protocolsMatch && remoteUrlUnchanged && !urlsMatch) {
    await gitStore.setRemoteURL(gitStore.defaultRemote.name, updatedRemoteUrl)
  }
```

```typescript
        setRemoteURL(this.repository, name, url)
```

```typescript
/** Changes the URL for the remote that matches the given name  */
export async function setRemoteURL(
  repository: Repository,
  name: string,
  url: string
): Promise<true> {
  await git(['remote', 'set-url', name, url], repository.path, 'setRemoteURL')
  return true
}
```
