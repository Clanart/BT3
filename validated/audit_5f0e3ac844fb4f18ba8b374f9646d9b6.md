### Title
Unsolicited dust-sized deposits force the multisig to spend unprofitable inputs, burning its funds on fees - ([File: networks/bitcoin/src/wallet/send.rs](https://github.com/Kirstentat/serai--016/blob/main/networks/bitcoin/src/wallet/send.rs))

### Summary
An unprivileged attacker can send small Taproot outputs to any of the scanner's publicly derivable addresses. Outputs at or above the `DUST` threshold are credited by `get_outputs`, and `SignableTransaction::new` only checks that *aggregate* input value covers payments plus fee — it never checks that each input is worth more than the fee cost of spending it. When the multisig later includes these inputs, it pays more in fees than the outputs are worth, directly paralleling the Dodo issue where a victim pays flash-loan fees on a loan they never requested.

### Finding Description
The scanner's watched scripts are all publicly computable. `scanner()` in `processor/src/networks/bitcoin.rs` deterministically derives the External (`Scalar::ZERO`), Branch, Change, and Forwarded scripts from the group key via `register_offset` on `hash_to_F(KEY_DST, ...)` offsets [1](#0-0) . Anyone who knows the group key can compute these script pubkeys and send outputs to them.

`Scanner::scan_transaction` credits any output whose `script_pubkey` matches, regardless of value or origin [2](#0-1) . The only value filter is `output.balance().amount.0 >= N::DUST` in the processor's scan loop [3](#0-2) , where `DUST = 546` [4](#0-3) .

When spending, `SignableTransaction::new` validates only the aggregate: `input_sat < payment_sat + needed_fee` [5](#0-4) . There is no per-input profitability check. A key-path P2TR input costs roughly 58 vbytes to spend, so at a `fee_per_vbyte` of ~10 or higher, each attacker-sent output valued between 546 and ~580 sats is spent at a net loss — the fee burned exceeds the value gained. Nothing prevents the wallet from being obligated to consolidate such outputs.

### Impact Explanation
The multisig (and its depositors) pays transaction fees to spend outputs whose value is lower than their spend cost, producing a net loss on every attacker-deposited output. This is the same class as the reference issue: a third party's unsolicited action forces the victim to bear fee costs they never consented to. The loss scales with the number of dust-sized outputs the attacker sends and with the prevailing fee rate — at high fee rates even well-above-dust outputs are unprofitable.

### Likelihood Explanation
Reachable by any unprivileged party: the external and forward addresses are published for deposits, and the branch/change scripts are deterministic functions of the group key via `hash_to_F` [6](#0-5) . The attack requires the attacker to burn their own outputs (which the multisig receives), so the griefing ratio is bounded by `fee_cost / deposit`, but the victim's loss requires no collusion, no privileged access, and no race conditions — just sending ordinary Bitcoin transactions.

### Recommendation
Track a minimum economical input value as a function of the current `fee_per_vbyte` (e.g., `DUST + fee_per_vbyte * input_vbytes`), and either filter credited outputs below that threshold in `get_outputs` or let `SignableTransaction::new` / the coin-selection layer skip inputs whose value is less than their marginal fee cost. Separately, consider not crediting unsolicited outputs sent to the internal Branch/Change/Forwarded scripts, since legitimate use of those scripts is protocol-internal.

### Proof of Concept
1. Compute the multisig's scanner scripts: `scanner(group_key)` yields `p2tr` scripts for External (`offset = 0`), Branch, Change, Forwarded [7](#0-6) .
2. Attacker broadcasts transactions paying, e.g., 600 sats each to the External script while the network fee rate is ~20 sat/vB.
3. `get_outputs` returns each as a spendable `Output` since `600 >= DUST` [3](#0-2) .
4. The wallet later constructs a `SignableTransaction` including these inputs. Each adds ~58 vbytes → ~1160 sats of fee, while contributing only 600 sats. The aggregate check `input_sat < payment_sat + needed_fee` still passes because other inputs subsidize it [5](#0-4) , and the actual fee `sum(inputs) - sum(outputs)` silently absorbs the loss [8](#0-7) . Each attacker output costs the multisig ~560 sats net — funds lost purely because an unprivileged party sent it a transaction.

fn scanner(
  key: ProjectivePoint,
) -> (Scanner, HashMap<OutputType, Scalar>, HashMap<Vec<u8>, OutputType>) {
  let mut scanner = Scanner::new(key).unwrap();
  let mut offsets = HashMap::from([(OutputType::External, Scalar::ZERO)]);

  let zero = Scalar::ZERO.to_repr();
  let zero_ref: &[u8] = zero.as_ref();
  let mut kinds = HashMap::from([(zero_ref.to_vec(), OutputType::External)]);

  let mut register = |kind, offset| {
    let offset = scanner.register_offset(offset).expect("offset collision");
    offsets.insert(kind, offset);

    let offset = offset.to_repr();
    let offset_ref: &[u8] = offset.as_ref();
    kinds.insert(offset_ref.to_vec(), kind);
  };

  register(
    OutputType::Branch,
    *BRANCH_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"branch")),
  );
  register(
    OutputType::Change,
    *CHANGE_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"change")),
  );
  register(
    OutputType::Forwarded,
    *FORWARD_OFFSET.get_or_init(|| Secp256k1::hash_to_F(KEY_DST, b"forward")),
  );

  pub fn scan_transaction(&self, tx: &Transaction) -> Vec<ReceivedOutput> {
    let mut res = Vec::new();
    for (vout, output) in tx.output.iter().enumerate() {
      // If the vout index exceeds 2**32, stop scanning outputs
      let Ok(vout) = u32::try_from(vout) else { break };

      if let Some(offset) = self.scripts.get(&output.script_pubkey) {
        res.push(ReceivedOutput {
          offset: *offset,
          output: output.clone(),
          outpoint: OutPoint::new(tx.compute_txid(), vout),
        });
      }
    }
    res
  }
