## Finding

### Title
Governance-settable `Kip71GasTarget = 0` causes a division-by-zero panic in `NextMagmaBlockBaseFee`, crashing all nodes computing/verifying the next block's base fee - ([File: params/kip71_config.go])

### Summary
`KIP71Config.NextMagmaBlockBaseFee` computes the next block's base fee based on the governance-controlled `GasTarget` parameter. The function defends against `BaseFeeDenominator == 0` by substituting a safe default, but performs no equivalent guard for `GasTarget == 0`, and unconditionally divides by it whenever the parent block's gas usage differs from the target (which is guaranteed whenever `GasTarget == 0` and any gas was used). This mirrors the reported bug class exactly: one branch of a calculation function is defended against a degenerate "zero" input while a structurally identical branch is not, causing execution to abort (revert/panic) instead of returning a sane result.

### Finding Description
`NextMagmaBlockBaseFee` in [1](#0-0)  reads the governance parameters and explicitly checks for `BaseFeeDenominator == 0`, substituting `64` to avoid a divide-by-zero: [2](#0-1) 

However, `gasTarget := kc.GasTarget` is used directly without any such guard. When `parentGasUsed != gasTarget`, the code unconditionally divides by `gasTarget`: [3](#0-2) 

Specifically, both the "gas used above target" and "gas used below target" branches compute `y := x.Div(x, new(big.Int).SetUint64(gasTarget))`. If `gasTarget == 0`, and `parentGasUsed != 0` (the overwhelmingly common case in practice), `math/big`'s `Div` will panic with a division-by-zero runtime error, since `GasTarget` is only special-cased in the `parentGasUsed == gasTarget` branch (which requires `parentGasUsed == 0` too).

The `Kip71GasTarget` governance parameter is registered with a `noopFormatChecker`, meaning no minimum/non-zero validation is enforced when this parameter is set via governance vote, unlike an implicit expectation that gas-economics parameters be positive: [4](#0-3) 

This function is invoked both during block assembly (to compute the base fee to embed in a new header) and during block header validation (every node re-derives and compares the expected base fee), as seen in tests wiring it to `BlockValidator.ValidateHeader` via `GetParamSet` / `KIP71Config`: [5](#0-4)  and in fee-history/gas-price estimation: [6](#0-5) 

### Impact Explanation
If governance sets `kip71.gastarget` to `0` (permitted by the current, unrestricted `noopFormatChecker`), then starting from the next Magma-enabled block that uses any nonzero gas, every node in the network attempting to build or validate that block deterministically panics inside `NextMagmaBlockBaseFee`. Because this is deterministic and identical across all conforming nodes, this is a network-wide chain halt rather than a localized crash — a systemic denial of service that stops block production entirely, which is a High/Critical-severity liveness failure of the chain.

### Likelihood Explanation
Reaching `GasTarget == 0` requires it to be set through the governance parameter update mechanism, but the `FormatChecker` for `Kip71GasTarget` is a no-op, so nothing in the code path rejects zero as an invalid value. The condition (`parentGasUsed != gasTarget`, i.e., `parentGasUsed != 0`) is trivially satisfied by ordinary chain activity (any block that spends gas). Once the governance parameter is set to `0` and takes effect, the crash is guaranteed and consensus-wide.

### Recommendation
Add an explicit zero-guard for `GasTarget` in `NextMagmaBlockBaseFee`, symmetric to the existing `BaseFeeDenominator` handling (e.g., substitute a safe minimum default or reject the computation gracefully), and update the `Kip71GasTarget` parameter's `FormatChecker` in `kaiax/gov/param.go` to reject `0` (and any other value that could degenerate divisions elsewhere) at governance-vote time.

### Proof of Concept
1. Governance sets `kip71.gastarget = 0` via a governance vote (accepted because `Kip71GasTarget`'s `FormatChecker` is `noopFormatChecker`).
2. Once the new parameter set is active and Magma is enabled, any block whose parent used nonzero gas triggers `parentGasUsed > gasTarget` (`0 > 0` false, but any `parentGasUsed >= 1 > 0` is true).
3. `NextMagmaBlockBaseFee` executes `y := x.Div(x, new(big.Int).SetUint64(0))`, which panics per Go's `math/big` semantics (division by zero).
4. Every node computing or validating the next header (proposer during sealing, and all peers during `ValidateHeader`) panics simultaneously, halting the chain.

func (kc *KIP71Config) NextMagmaBlockBaseFee(parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) *big.Int {
	// governance parameters
	lowerBoundBaseFee := new(big.Int).SetUint64(kc.LowerBoundBaseFee)
	upperBoundBaseFee := new(big.Int).SetUint64(kc.UpperBoundBaseFee)
	makeEvenByCeil(lowerBoundBaseFee)
	makeEvenByFloor(upperBoundBaseFee)

	// If the parent is the magma disabled block or genesis, then return the lowerBoundBaseFee (default 25ston)
	if parentHeaderNumber.Cmp(new(big.Int).SetUint64(0)) == 0 || parentHeaderBaseFee == nil {
		return makeEvenByFloor(lowerBoundBaseFee)
	}

	var baseFeeDenominator *big.Int
	if kc.BaseFeeDenominator == 0 {
		// To avoid panic, set the fluctuation range small
		baseFeeDenominator = new(big.Int).SetUint64(64)
	} else {
		baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
	}
