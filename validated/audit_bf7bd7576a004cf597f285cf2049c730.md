### Title
Silent Loss of EVM-Side Token Balances/State via Unassociated-Address Fallback in `HandleInternalEVMCall` - ([File: x/evm/keeper/evm.go])

### Summary
Sei's dual-address model lets a CosmWasm (CW) contract or Cosmos-signed account interact with the EVM by internally calling into an EVM contract (e.g., ERC20/ERC721/ERC1155 tokens, pointer contracts) through `MsgInternalEVMCall`. When the calling Sei address has not yet explicitly associated an EVM address, `HandleInternalEVMCall` silently falls back to a deterministic "cast" EVM address (`GetEVMAddressOrDefault`) instead of requiring association. Any EVM-side balance or contract state (ERC20/ERC721/ERC1155 token balances, EVM storage slots) that accrues to that cast address becomes permanently unreachable once the Sei account later performs a real `Associate` with a *different* EVM address — because after association, all future lookups for that Sei account resolve to the new, real EVM address, not the old cast address, and the cast address itself has no discoverable private key to sign a native transaction on either side.

### Finding Description
Sei maintains a bidirectional Sei↔EVM address mapping in `x/evm/keeper/address.go`. Before an account explicitly associates (`Associate`/`AssociatePubKey`), lookups can either:
- **strictly require** association and revert (`GetEVMAddress`/`GetSeiAddress`, used e.g. in `precompiles/wasmd/wasmd.go` `instantiate`/`execute` via `types.NewAssociationMissingErr`), or
- **fall back** to a deterministic byte-cast address when no association exists (`GetEVMAddressOrDefault`/`GetSeiAddressOrDefault`): [1](#0-0) [2](#0-1) 

`HandleInternalEVMCall`, the entry point CW contracts use to call into EVM contracts (`MsgInternalEVMCall`), uses the lenient fallback: [3](#0-2) 

By contrast, the delegate-call variant explicitly documents and guards against exactly this class of bug by requiring prior association and reverting otherwise: [4](#0-3) 
The comment states: *"delegatecall caller must be associated; otherwise any state change on EVM contract will be lost after they associate."* This proves the team is aware of the exact bug class described in the external report (assets held under an address that is not truly controlled by the same identity after a later address-binding event become lost) — but the mitigation was applied only to `HandleInternalEVMDelegateCall`, not to the plain `HandleInternalEVMCall` path.

When association does occur, `AssociateAddresses`/`MigrateBalance` migrate only bank `usei`/wei balances from the cast address to the newly associated Sei address, and delete the cast account if its locked bank coins are zero — it does not, and cannot, migrate EVM contract storage (e.g., ERC1155/ERC721/ERC20 balances) held by the cast address: [5](#0-4) 

This mirrors the reported Beanstalk bug class: an asset (there, a fertilizer ERC1155 NFT; here, any EVM contract balance/state reached via `MsgInternalEVMCall`) is delivered to an address derived by casting, which is only "the same owner" by coincidence of bytes and only for as long as no real association supersedes it. Once the true owner associates a different EVM key, the cast address's holdings become orphaned — inaccessible from the Cosmos side (no private key exists under Cosmos's derivation for those exact bytes) and inaccessible from the EVM side (future `GetEVMAddressOrDefault`/`GetSeiAddress` calls for that Sei account now resolve to the new EVM address, not the cast one).

### Impact Explanation
Any CW contract (reachable by any unprivileged wasm message sender) that uses `MsgInternalEVMCall` to interact with EVM-side ERC20/ERC721/ERC1155 tokens, pointer contracts, or other stateful EVM contracts on behalf of a Sei account that has not yet associated an EVM address is at risk. If that Sei account later associates a real EVM address distinct from the deterministic cast, any token balance/state accrued at the cast address becomes permanently frozen — meeting the "permanent freezing of funds" acceptance criterion.

### Likelihood Explanation
Likelihood is moderate: the CW→EVM internal call path is a normal, expected integration mechanism (e.g., pointer contracts, CW modules interacting with EVM tokens), and it is common for a Sei account to interact with the chain (and accrue EVM state via internal calls) before ever running the explicit `Associate` transaction. The team's own comment on the sibling delegate-call function shows this exact failure mode is a known, real risk that was mitigated there but not in `HandleInternalEVMCall`.

### Recommendation
Apply the same guard used in `HandleInternalEVMDelegateCall` to `HandleInternalEVMCall`: require that the Sei sender already has an associated EVM address (via `GetEVMAddress`, returning `types.NewAssociationMissingErr` if not found) rather than silently falling back to `GetEVMAddressOrDefault`. Alternatively, if the fallback behavior must be preserved for backward compatibility, ensure that `AssociateAddresses`/`MigrateBalance` also sweeps/migrates or otherwise reconciles any EVM contract state indexed by the cast address (or blocks future divergent association if the cast address is known to hold external contract state), analogous to how `CanAddressReceive` prevents bank transfers to a stale cast address post-association.

### Proof of Concept
1. A Sei account `S` (never having called `Associate`) sends a `MsgExecuteContract` to a CW contract that internally calls `MsgInternalEVMCall` targeting an ERC1155/ERC20 pointer or native EVM contract (e.g., minting/transferring a token to `S`).
2. `HandleInternalEVMCall` resolves `S`'s EVM identity via `k.GetEVMAddressOrDefault(ctx, S)`, i.e., the deterministic cast address `castEVM = common.BytesToAddress(S)` (see `x/evm/keeper/evm.go:40`). The EVM contract state (token balance) is recorded against `castEVM`.
3. `S` later calls the `Associate` precompile with a real secp256k1-derived EVM address `E ≠ castEVM` (`precompiles/addr/addr.go`), which stores `SetAddressMapping(S, E)` and migrates only bank/wei balances (`utils/helpers/associate.go:57-82`).
4. Any subsequent internal-call/pointer interaction for `S` now resolves to `E`, not `castEVM`. The token balance held at `castEVM` is now orphaned — unreachable via `S`'s Cosmos identity (its EVM view now points to `E`) and unreachable via a native transaction from `castEVM` (no corresponding private key exists under Cosmos's secp256k1 derivation for those exact 20 bytes).

func (k *Keeper) HandleInternalEVMCall(ctx sdk.Context, req *types.MsgInternalEVMCall) (*sdk.Result, error) {
	var to *common.Address
	if req.To != "" {
		addr := common.HexToAddress(req.To)
		to = &addr
	}
	senderAddr, err := sdk.AccAddressFromBech32(req.Sender)
	if err != nil {
		return nil, err
	}
	ret, err := k.CallEVM(ctx, k.GetEVMAddressOrDefault(ctx, senderAddr), to, req.Value, req.Data)
	if err != nil {
		return nil, err
	}
	return &sdk.Result{Data: ret}, nil
}

func (k *Keeper) HandleInternalEVMDelegateCall(ctx sdk.Context, req *types.MsgInternalEVMDelegateCall) (*sdk.Result, error) {
	var to *common.Address
	if req.To != "" {
		addr := common.HexToAddress(req.To)
		to = &addr
	} else {
		return nil, errors.New("cannot use a CosmWasm contract to delegate-create an EVM contract")
	}
	addr, _, exists := k.GetAnyPointerInfo(ctx, types.PointerReverseRegistryKey(common.BytesToAddress([]byte(req.FromContract))))
	if !exists || common.BytesToAddress(addr).Cmp(*to) != 0 {
		return nil, errors.New("only pointer contract can make delegatecalls")
	}
	zeroInt := sdk.ZeroInt()
	senderAddr, err := sdk.AccAddressFromBech32(req.Sender)
	if err != nil {
		return nil, err
	}
	// delegatecall caller must be associated; otherwise any state change on EVM contract will be lost
	// after they asssociate.
	senderEvmAddr, found := k.GetEVMAddress(ctx, senderAddr)
	if !found {
		err := types.NewAssociationMissingErr(req.Sender)
		evmKeeperMetrics.associationError.Add(ctx.Context(), 1, otelmetric.WithAttributes(attribute.String("scenario", "evm_handle_internal_evm_delegate_call"), attribute.String("type", err.AddressType())))
		return nil, err
	}
	ret, err := k.CallEVM(ctx, senderEvmAddr, to, &zeroInt, req.Data)
	if err != nil {
		return nil, err
	}
	return &sdk.Result{Data: ret}, nil
}

func (p AssociationHelper) AssociateAddresses(ctx sdk.Context, seiAddr sdk.AccAddress, evmAddr common.Address, pubkey cryptotypes.PubKey, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if !castAddr.Equals(seiAddr) && p.accountKeeper.GetAccount(ctx, seiAddr) == nil {
		castAcc := p.accountKeeper.GetAccount(ctx, castAddr)
		castBaseAcc, ok := castAcc.(*authtypes.BaseAccount)
		if ok && castBaseAcc.GetPubKey() == nil && p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
			p.accountKeeper.SetAccount(ctx, authtypes.NewBaseAccount(seiAddr, pubkey, castBaseAcc.GetAccountNumber(), castBaseAcc.GetSequence()))
		}
	}
	p.evmKeeper.SetAddressMapping(ctx, seiAddr, evmAddr)
	acc := p.accountKeeper.GetAccount(ctx, seiAddr)
	if acc == nil {
		acc = p.accountKeeper.NewAccountWithAddress(ctx, seiAddr)
	}
	if acc.GetPubKey() == nil {
		if err := acc.SetPubKey(pubkey); err != nil {
			return err
		}
		p.accountKeeper.SetAccount(ctx, acc)
	}
	return p.MigrateBalance(ctx, evmAddr, seiAddr, migrateUseiOnly)
}

func (p AssociationHelper) MigrateBalance(ctx sdk.Context, evmAddr common.Address, seiAddr sdk.AccAddress, migrateUseiOnly bool) error {
	castAddr := sdk.AccAddress(evmAddr[:])
	if castAddr.Equals(seiAddr) {
		return nil
	}
	var castAddrBalances sdk.Coins
	if migrateUseiOnly {
		castAddrBalances = sdk.Coins{p.bankKeeper.GetBalance(ctx, castAddr, "usei")}
	} else {
		castAddrBalances = p.bankKeeper.SpendableCoins(ctx, castAddr)
	}
	if !castAddrBalances.IsZero() {
		if err := p.bankKeeper.SendCoins(ctx, castAddr, seiAddr, castAddrBalances); err != nil {
			return err
		}
	}
	castAddrWei := p.bankKeeper.GetWeiBalance(ctx, castAddr)
	if !castAddrWei.IsZero() {
		if err := p.bankKeeper.SendCoinsAndWei(ctx, castAddr, seiAddr, sdk.ZeroInt(), castAddrWei); err != nil {
			return err
		}
	}
	if p.bankKeeper.LockedCoins(ctx, castAddr).IsZero() {
		p.accountKeeper.RemoveAccount(ctx, authtypes.NewBaseAccountWithAddress(castAddr))
	}
	return nil
}
