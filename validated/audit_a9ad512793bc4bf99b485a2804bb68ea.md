### Title
Suspended (Blocked) Validators Are Not Excluded From Staking Reward Distribution - ([File: kaiax/reward/impl/getter.go])

### Summary
Kaia's validator lifecycle marks misbehaving or governance-blocked validators with a `Suspended` flag on `valset.Node`. This flag is correctly enforced when building the consensus `Committee` (suspended validators cannot propose or sign blocks), but it is not propagated into the staking-info structure (`staking.StakingInfo`) that the reward module uses to distribute block rewards. As a result, a validator that has been "blocked" from consensus duty via suspension can still receive staking rewards every block, exactly analogous to the reported bug class where a blocked/blacklisted state is enforced in one code path but silently ignored in another state-mutating path that moves value.

### Finding Description
`valset.Node` carries a `Suspended` boolean alongside `State`. The `Committee()` accessor explicitly filters it out: [1](#0-0) 

and the permissionless getter path applies the same "committee-with-fallback" exclusion when computing qualified validators for consensus: [2](#0-1) 

However, reward-eligibility of a node is determined purely from `State` via `IsRewardEligible()`, which only checks `ValActive` and has no notion of the `Suspended` flag: [3](#0-2) 

`kaiax/staking/impl/getter.go`'s `GetStakingInfo` builds the `StakingInfo.NodeIds`/`RewardAddrs`/`StakingAmounts` arrays used for reward computation by keeping only reward-eligible (`ValActive`) nodes per KIP-286/287, as confirmed by the permissionless test: [4](#0-3) 

This filter is `State`-based only; nothing in the reward path re-checks `Suspended`. The reward module then consumes this `StakingInfo` unconditionally in both fee/staking split and the deferred-reward finalize step: [5](#0-4) [6](#0-5) 

Because `Suspended` is a separate boolean layered on top of `State` (a node can be `State: ValActive, Suspended: true`, as shown throughout the valset test suite), a validator remains `ValActive` and therefore reward-eligible in `StakingInfo` even while suspended from the committee: [7](#0-6) [8](#0-7) 

This mirrors the reported vulnerability pattern exactly: a "blocked" flag (`accountVersionBlocked` in the original report, `Suspended` here) is checked in one state-changing path (block/committee membership) but omitted from another path that moves value to the flagged entity (reward distribution, analogous to `safeTransferAccount`).

### Impact Explanation
A suspended validator (e.g., one penalized for consensus faults, downtime, or protocol violations per KIP-286/287) continues to accrue and receive its share of block rewards while contributing nothing to consensus and while being deliberately excluded from block production/signing. This constitutes unauthorized value/reward redirection to an entity the protocol has explicitly flagged as untrusted, undermining the incentive-alignment guarantees of the staking/reward system and potentially allowing a penalized operator to keep earning rewards indefinitely.

### Likelihood Explanation
The condition is not attacker-triggered by a crafted transaction but occurs automatically for any validator that transitions into `Suspended` state through the normal violation/penalty machinery (`kaiax/valset/impl/transition_context.go`). Every subsequent block's `FinalizeState` reward distribution will process the stale, non-suspension-aware `StakingInfo`, so the divergence between "excluded from committee" and "still rewarded" is deterministic and will occur on essentially every suspension event, making likelihood high once a suspension occurs.

### Recommendation
Propagate the `Suspended` flag (or an equivalent reward-eligibility signal derived from it) into `staking.StakingInfo`/`kaiax/staking/impl/getter.go`'s `GetStakingInfo`, so that `assignStakingRewards`/`getDeferredRewardFullKore` and related reward-computation functions exclude suspended validators the same way `Committee()` does. Alternatively, gate `IsRewardEligible()` (or its call sites in the staking getter) on both `State == ValActive` and `!Suspended`.

### Proof of Concept
Not applicable as a single-transaction PoC — this is a protocol state-transition inconsistency, not a call reachable directly from an RPC/tx. It can be demonstrated by unit-testing `GetStakingInfo` (or the reward `getDeferredReward*` functions) with a `NodeMap` entry `{State: ValActive, Suspended: true}` (as already exercised in `TestSuspendedFallback`, `kaiax/valset/impl/getter_permissionless_test.go:127-154`) and observing that the resulting `StakingInfo`/reward allocation still includes that node's stake, while `GetCommittee`/`GetQualifiedValidators` for the same block correctly excludes it.

**Note on confidence**: I was not able to view the exact body of `kaiax/staking/impl/getter.go`'s `GetStakingInfo` filtering logic (only its test) within the available tool budget, so I cannot cite the precise line where the `State`-only filter is applied; this should be verified directly in that file before treating the finding as fully confirmed.

// committeeWithFallback returns the committee at the given block.
// Committee = {VA} - {Suspended}.
//
// Safety fallback: when len(committee)=0 due to {ValActive} ⊆ SuspendedSet, fallback to all VA.
func committeeWithFallback(nodes valset.NodeMap) (committee valset.NodeMap, fellBack bool) {
	committee = nodes.Committee()
	if len(committee) > 0 {
		return committee, false
	}

	// ignore SuspendedSet
	return nodes.FilterByState(valset.ValActive), true
}

// getQualifiedValidators: qualified = committee = {VA} − {Suspended} (with safety fallback).
func (v *ValsetModule) getQualifiedValidators(num uint64) (*valset.AddressSet, error) {
	nodes, err := v.getNodes(num)
	if err != nil {
		return nil, err
	}
	committee, fellBack := committeeWithFallback(nodes)
	if fellBack && v.lastSuspendFallbackLog != num {
		logger.Warn("all ValActive are suspended, ignoring suspended set for committee", "num", num)
		v.lastSuspendFallbackLog = num
	}
	return valset.NewAddressSet(committee.Addresses()), nil
}

// Distribute the deferred rewards at the end of block processing.
func (r *RewardModule) FinalizeState(header *types.Header, state *state.StateDB, txs []*types.Transaction, receipts []*types.Receipt) error {
	if r.GovModule.GetParamSet(header.Number.Uint64()).ProposerPolicy == uint64(istanbul.WeightedRandom) && common.EmptyHash(header.Root) {
		qualified, err := r.ValsetModule.GetQualifiedValidators(header.Number.Uint64())
		if err != nil {
			return err
		}
		useRewardAddress := valset.NewAddressSet(qualified).Contains(r.NodeAddress)

		if rewardAddr := r.GetRewardAddress(header.Number.Uint64(), r.NodeAddress); useRewardAddress && rewardAddr != (common.Address{}) {
			header.Rewardbase = rewardAddr
			logger.Trace("Use reward address for nodeValidator", "header.Number", header.Number.Uint64(), "nodeAddress", r.NodeAddress, "rewardbase", header.Rewardbase)
		} else {
			logger.Trace("No reward address for nodeValidator. Use node's rewardbase.", "header.Number", header.Number.Uint64(), "nodeAddress", r.NodeAddress, "rewardbase", header.Rewardbase)
		}
	}

	spec, err := r.GetDeferredReward(header, txs, receipts)
	if err != nil {
		return err
	}
	if err := spec.Validate(); err != nil {
		return err
	}
	for addr, amount := range spec.Rewards {
		state.AddBalance(addr, amount)
	}
	return nil
}

// assignStakingRewards assigns staking rewards to stakers according to their staking amounts.
// Returns the allocation and the remainder.
func assignStakingRewards(config *reward.RewardConfig, stakersReward *big.Int, si *staking.StakingInfo) (map[common.Address]*big.Int, *big.Int) {
	var (
		cns               = si.ConsolidatedNodes()
		minStake          = config.MinimumStake.Uint64()
		totalExcessInt    = uint64(0) // sum of excess stakes (the amount over minStake) over all stakers
		cnTotalStakingMap = make(map[common.Address]uint64)
		isPrague          = config.Rules.IsPrague
	)
	for _, cn := range cns {
		// If the CNStaking is less than minStake, skip it.
		if cn.StakingAmount >= minStake {
			// Calculate total staking amount once
			cnTotalStakingAmount := cn.StakingAmount
			if isPrague && cn.CLStakingInfo != nil {
				cnTotalStakingAmount += cn.CLStakingInfo.CLStakingAmount
			}
			totalExcessInt += cnTotalStakingAmount - minStake
			cnTotalStakingMap[cn.RewardAddr] = cnTotalStakingAmount
		}
	}

	var (
		totalExcess = new(big.Int).SetUint64(totalExcessInt)
		remaining   = new(big.Int).Set(stakersReward)
		alloc       = make(map[common.Address]*big.Int)
	)
	for _, cn := range cns {
		cnTotalStakingAmount := cnTotalStakingMap[cn.RewardAddr]
		if cnTotalStakingAmount > minStake {
			// The KAIA unit will cancel out:
			// reward (kei) = excess (KAIA) * stakersReward (kei) / totalExcess (KAIA)
			excess := new(big.Int).SetUint64(cnTotalStakingAmount - minStake)
			if reward := new(big.Int).Div(new(big.Int).Mul(excess, stakersReward), totalExcess); reward.Sign() > 0 {
				if isPrague && cn.CLStakingInfo != nil {
					// The remaining amount will be added to the cnAmount.
					cnAmount, clAmount := cn.Split(reward)
					alloc[cn.RewardAddr] = cnAmount
					alloc[cn.CLStakingInfo.CLPoolAddr] = clAmount
				} else {
					alloc[cn.RewardAddr] = reward
				}
				remaining.Sub(remaining, reward)
			}
		}
	}
	return alloc, remaining
