### Title
Governance-controlled `governance.unitprice` parameter has no upper-bound validation, letting a single governing-node vote force all transaction senders to pay an unbounded fixed gas price - ([File: kaiax/gov/param.go])

### Summary
Before the Magma hardfork (and whenever `UnitPrice` policy governs pricing), every transaction submitted to the tx pool must carry a gas price that exactly matches the governance-set `governance.unitprice` value, enforced in `TxPool.validateTx`. Unlike other numeric governance parameters (e.g. `kip71.lowerboundbasefee` / `kip71.upperboundbasefee`, which cross-validate against each other via `checkConsistency`), `governance.unitprice` uses `noopFormatChecker`, meaning it accepts any `uint64` value with no sanity bound.

### Finding Description
The governance parameter `GovernanceUnitPrice` is registered with `FormatChecker: noopFormatChecker`, i.e. any value passes validation: [1](#0-0) 

Contrast this with `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee`, which are cross-checked against each other in `checkConsistency` before being accepted into a block's governance data: [2](#0-1) 

No equivalent consistency/bound check exists for `governance.unitprice` in the same switch statement — it falls into the generic "no more checks here" branch: [3](#0-2) 

This unbounded value is used directly by `TxPool` as the mandatory, exact gas price for every non-Magma / non-dynamic-fee transaction. Any transaction whose `gasPrice` doesn't exactly equal `pool.gasPrice` (derived from `UnitPrice`) is rejected: [4](#0-3) [5](#0-4) 

Because `governance.unitprice` can be set to an arbitrarily large `uint64` (e.g. `2^64-1`) by a single governing-node vote (in `governance.governancemode: single`, which is the documented Mainnet configuration), every legacy/EthTxType transaction on the network would be forced to pay that price to be admitted to the pool and included in a block — there is no upper bound analogous to `UpperBoundBaseFee`.

### Impact Explanation
This mirrors the reported bug class exactly: a privileged party (the governing node/DAO, analogous to the "protocol owner") can set a fee-like parameter with no upper limit, extracting value from unprivileged transaction senders who must pay this price to have their transactions accepted. Unlike KIP-71 base fee (which is bounded by `LowerBoundBaseFee`/`UpperBoundBaseFee` and gradually adjusts per block), `UnitPrice` is a hard, exact-match requirement with no ceiling, so an extreme value would either make the network economically unusable for all senders or, combined with `reward.ratio`/`reward.mintingamount`/proposer rewards, redirect excessive value to block proposers/governing node. This is a network-wide fee-abuse condition reachable by all public transaction senders being forced to overpay to interact with the chain.

### Likelihood Explanation
Likelihood is tied to governing-node/validator behavior rather than any single unprivileged actor triggering it directly — the parameter change itself requires a governance vote (in single mode, a single governing node's vote is sufficient and takes effect via header governance without further validation of the fee bound). Once set, every unprivileged transaction sender is affected on the very next transaction they submit, with no contract-level or protocol-level ceiling preventing the abuse.

### Recommendation
Add a `FormatChecker` (or a `checkConsistency` cross-check similar to `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee`) for `GovernanceUnitPrice` that enforces a reasonable maximum value, and/or cross-validate it against the current KIP-71 bounds so that a single vote cannot set an unbounded, exact-match fixed gas price for all transactions.

### Proof of Concept
1. Deploy/observe a Kaia network in `governance.governancemode: single` (documented Mainnet default, see `kaiax/gov/headergov/README.md`).
2. Governing node submits a governance vote for `governance.unitprice` with value `uint64(math.MaxUint64)` (or any extreme value).
3. `checkConsistency` in `kaiax/gov/headergov/impl/header.go` accepts the vote unconditionally (falls into the no-op branch at lines 214-220), and `Params[GovernanceUnitPrice].FormatChecker` (`noopFormatChecker`) also accepts it.
4. At the next epoch, `GetParamSet` reflects the new `UnitPrice`, and `TxPool.gasPrice` is updated accordingly.
5. All subsequent legacy/non-Magma transactions must set `tx.GasPrice()` exactly equal to this value (`blockchain/tx_pool.go` lines 868-881) or be rejected with `ErrInvalidUnitPrice`, forcing every unprivileged sender to pay the unbounded fee to transact at all.
