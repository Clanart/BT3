### Title
Unbounded per-block processing of the staking unbonding-delegation queue enables a gas-free consensus DoS - (File: sei-cosmos/x/staking/keeper/val_state_change.go)

### Summary
`BlockValidatorUpdates` (invoked from `staking.EndBlocker` on every block) calls `k.DequeueAllMatureUBDQueue` and then iterates the *entire* returned slice in-process, with no batching, pagination, or per-block record cap. Any account can cheaply enqueue an arbitrary number of unbonding-delegation entries that will all mature at the same block time, causing this EndBlock loop to grow unbounded, mirroring the reported `getDepositQueueTVL()` pattern of an attacker-inflatable array that is later fully iterated without bound.

### Finding Description
`InsertUBDQueue` appends a `DVPair{Delegator, Validator}` to a per-completion-time slice with no cap on how many entries can accumulate at a single timestamp: [1](#0-0) 

`DequeueAllMatureUBDQueue`, called once per block from `BlockValidatorUpdates`, unmarshals every timeslice up to the current block time and concatenates all entries into a single in-memory slice with no limit: [2](#0-1) 

`BlockValidatorUpdates` (called unconditionally from `staking.EndBlocker` every block) then loops over the full `matureUnbonds` slice, calling `CompleteUnbonding` (a bank transfer) for each entry, with no per-block processing budget: [3](#0-2) 

`CompleteUnbonding` itself loops over the mature entries of each unbonding delegation and performs a bank `SendCoins`-style transfer per entry: [4](#0-3) 

This is architecturally analogous to `Carousel.getDepositQueueTVL()`: an unprivileged actor can cheaply inflate an array-like queue (here, the UBD time-slice) that a later, unbatched loop must fully process. Unlike `x/gov`'s `EndBlocker`, which was explicitly hardened against this exact class of issue with an incremental, budgeted tally (`remainingRecords`) to bound per-block proposal-queue work: [5](#0-4) 
the staking unbonding/redelegation queue has no equivalent per-block budget in `BlockValidatorUpdates`.

Because `EndBlock` execution is not gas-metered the way `DeliverTx` is, this loop cannot revert due to an out-of-gas error the way a Solidity view function would; instead, an inflated queue directly translates into increased wall-clock EndBlock processing time for every validator, at the moment the queue matures.

### Impact Explanation
An attacker who submits many cheap `MsgDelegate`/`MsgUndelegate` pairs (from many funded low-value accounts, to a small number of existing validators) within transactions that land in the same block can cause a large number of `DVPair` entries to be queued under the exact same completion timestamp (block time + unbonding period is the same for all txs executed in that block). When that timestamp matures, every validator's node must process the entire accumulated list in one `EndBlock` call. If the queue is large enough, this can push per-block processing time beyond the 2.5-second consensus timeout, risking validator halt or block-time degradation across the network — a chain-level liveness impact, not merely an isolated RPC/query DoS.

### Likelihood Explanation
Delegating and undelegating small amounts of `usei` is not restricted by a minimum-delegation-amount check that would meaningfully raise the cost of this attack (no `MinSelfDelegation`-style floor governs `MsgDelegate`/`MsgUndelegate` amounts for ordinary delegators), so the attacker's cost is dominated by ordinary transaction fees, which are typically cheap on Sei. The main constraint is the number of distinct `(delegator, validator)` pairs needed (bounded by `MaxEntries` per pair, not across pairs), which an attacker can trivially work around using many distinct delegator addresses. This makes the attack economically feasible for a well-resourced but unprivileged actor, though it requires accumulating a large queue over time/blocks rather than a single transaction, which somewhat lowers immediate practical likelihood compared to a single-tx DoS.

### Recommendation
Introduce a per-block processing budget for `DequeueAllMatureUBDQueue`/`DequeueAllMatureRedelegationQueue`/`BlockValidatorUpdates`, similar to the `remainingRecords` incremental-tally mechanism already used in `x/gov`'s `EndBlocker`. Process only up to a fixed number of matured entries per block, leaving the remainder in the queue (still indexed by original completion time or a cursor) for subsequent blocks, and/or cap the maximum number of DVPair entries permitted to mature at the same timestamp system-wide.

### Proof of Concept
1. Fund N distinct delegator accounts with the minimum stake needed for a `MsgDelegate` to an existing validator (no minimum-amount floor blocks tiny amounts).
2. In a burst of blocks, submit `MsgDelegate` followed immediately by `MsgUndelegate` from each of the N accounts to a small set of existing validators, ensuring the `MsgUndelegate` transactions are included in the same block (so `ctx.BlockHeader().Time` — and hence `completionTime = blockTime + UnbondingTime` — is identical for all of them). This causes `InsertUBDQueue` to accumulate N `DVPair` entries under one timeslice key. [1](#0-0) 
3. Repeat across multiple blocks/timeslices, or route all N through the same block, to grow the single timeslice to a size the attacker can control (limited only by transaction throughput/fees, not by protocol logic).
4. When `ctx.BlockHeader().Time` reaches that completion time, `staking.EndBlocker` → `BlockValidatorUpdates` → `DequeueAllMatureUBDQueue` will unmarshal and iterate the entire N-sized slice in one `EndBlock` call, and for each entry call `CompleteUnbonding`, which performs a bank transfer — with no per-block cap, unlike the patched `x/gov` tally path. [6](#0-5)

// InsertUBDQueue inserts an unbonding delegation to the appropriate timeslice
// in the unbonding queue.
func (k Keeper) InsertUBDQueue(ctx sdk.Context, ubd types.UnbondingDelegation,
	completionTime time.Time,
) {
	dvPair := types.DVPair{DelegatorAddress: ubd.DelegatorAddress, ValidatorAddress: ubd.ValidatorAddress}

	timeSlice := k.GetUBDQueueTimeSlice(ctx, completionTime)
	if len(timeSlice) == 0 {
		k.SetUBDQueueTimeSlice(ctx, completionTime, []types.DVPair{dvPair})
	} else {
		timeSlice = append(timeSlice, dvPair)
		k.SetUBDQueueTimeSlice(ctx, completionTime, timeSlice)
	}
}

// DequeueAllMatureUBDQueue returns a concatenated list of all the timeslices inclusively previous to
// currTime, and deletes the timeslices from the queue.
func (k Keeper) DequeueAllMatureUBDQueue(ctx sdk.Context, currTime time.Time) (matureUnbonds []types.DVPair) {
	store := ctx.KVStore(k.storeKey)

	// gets an iterator for all timeslices from time 0 until the current Blockheader time
	unbondingTimesliceIterator := k.UBDQueueIterator(ctx, ctx.BlockHeader().Time)
	defer func() { _ = unbondingTimesliceIterator.Close() }()

	for ; unbondingTimesliceIterator.Valid(); unbondingTimesliceIterator.Next() {
		timeslice := types.DVPairs{}
		value := unbondingTimesliceIterator.Value()
		k.cdc.MustUnmarshal(value, &timeslice)

		matureUnbonds = append(matureUnbonds, timeslice.Pairs...)

		store.Delete(unbondingTimesliceIterator.Key())
	}

	return matureUnbonds
}

// CompleteUnbonding completes the unbonding of all mature entries in the
// retrieved unbonding delegation object and returns the total unbonding balance
// or an error upon failure.
func (k Keeper) CompleteUnbonding(ctx sdk.Context, delAddr sdk.AccAddress, valAddr sdk.ValAddress) (sdk.Coins, error) {
	ubd, found := k.GetUnbondingDelegation(ctx, delAddr, valAddr)
	if !found {
		return nil, types.ErrNoUnbondingDelegation
	}

	bondDenom := k.GetParams(ctx).BondDenom
	balances := sdk.NewCoins()
	ctxTime := ctx.BlockHeader().Time

	delegatorAddress, err := sdk.AccAddressFromBech32(ubd.DelegatorAddress)
	if err != nil {
		return nil, err
	}

	// loop through all the entries and complete unbonding mature entries
	for i := 0; i < len(ubd.Entries); i++ {
		entry := ubd.Entries[i]
		if entry.IsMature(ctxTime) {
			ubd.RemoveEntry(int64(i))
			i--

			// track undelegation only when remaining or truncated shares are non-zero
			if !entry.Balance.IsZero() {
				amt := sdk.NewCoin(bondDenom, entry.Balance)
				if err := k.bankKeeper.UndelegateCoinsFromModuleToAccount(
					ctx, types.NotBondedPoolName, delegatorAddress, sdk.NewCoins(amt),
				); err != nil {
					return nil, err
				}

				balances = balances.Add(amt)
			}
		}
	}

	// set the unbonding delegation or remove it if there are no more entries
	if len(ubd.Entries) == 0 {
		k.RemoveUnbondingDelegation(ctx, ubd)
	} else {
		k.SetUnbondingDelegation(ctx, ubd)
	}

	return balances, nil
}

// BlockValidatorUpdates calculates the ValidatorUpdates for the current block
// Called in each EndBlock
func (k Keeper) BlockValidatorUpdates(ctx sdk.Context) []abci.ValidatorUpdate {
	// Calculate validator set changes.
	//
	// NOTE: ApplyAndReturnValidatorSetUpdates has to come before
	// UnbondAllMatureValidatorQueue.
	// This fixes a bug when the unbonding period is instant (is the case in
	// some of the tests). The test expected the validator to be completely
	// unbonded after the Endblocker (go from Bonded -> Unbonding during
	// ApplyAndReturnValidatorSetUpdates and then Unbonding -> Unbonded during
	// UnbondAllMatureValidatorQueue).
	validatorUpdates, err := k.ApplyAndReturnValidatorSetUpdates(ctx)
	if err != nil {
		panic(err)
	}

	// unbond all mature validators from the unbonding queue
	k.UnbondAllMatureValidators(ctx)

	// Remove all mature unbonding delegations from the ubd queue.
	matureUnbonds := k.DequeueAllMatureUBDQueue(ctx, ctx.BlockHeader().Time)
	for _, dvPair := range matureUnbonds {
		addr, err := sdk.ValAddressFromBech32(dvPair.ValidatorAddress)
		if err != nil {
			panic(err)
		}
		delegatorAddress := sdk.MustAccAddressFromBech32(dvPair.DelegatorAddress)

		balances, err := k.CompleteUnbonding(ctx, delegatorAddress, addr)
		if err != nil {
			continue
		}

		ctx.EventManager().EmitEvent(
			sdk.NewEvent(
				types.EventTypeCompleteUnbonding,
				sdk.NewAttribute(sdk.AttributeKeyAmount, balances.String()),
				sdk.NewAttribute(types.AttributeKeyValidator, dvPair.ValidatorAddress),
				sdk.NewAttribute(types.AttributeKeyDelegator, dvPair.DelegatorAddress),
			),
		)
	}
