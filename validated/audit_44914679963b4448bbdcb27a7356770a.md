## Analysis

The external report's core defect is: a caller-supplied value that funds delivery of a cross-chain message is validated too weakly (`> 0`), so the message can be dispatched, an irreversible on-chain effect occurs (tokens burned/locked), yet the destination-side effect never lands because no relayer will service it. The local analog exists in Hyperbridge's Intent Gateway `fillOrder` cross-chain path.

In `_fillCrossChain` [1](#0-0) , the solver first irrevocably delivers output tokens to the beneficiary [2](#0-1) , then dispatches a `RedeemEscrow` POST request back to the source chain whose `fee` field is taken directly, and completely unvalidated, from solver-supplied `options.relayerFee`:

```solidity
DispatchPost memory request = DispatchPost({
    dest: order.source,
    to: abi.encodePacked(_instance(order.source)),
    body: body,
    timeout: 0,
    fee: options.relayerFee,
    payer: msg.sender
});
``` [3](#0-2) 

Unlike the LayerZero `BridgeMB`/`BridgeLR` example, there isn't even a `require(fee > 0)` guard here — `options.relayerFee` can be zero and the transaction still succeeds. Critically, `timeout` is hardcoded to `0`, which per the protocol's own documentation means the request "will never expire" [4](#0-3) . That timeout semantics eliminates the only built-in recovery path (`dispatchTimeOut`/refund) that exists elsewhere in the host [5](#0-4) .

The escrowed order inputs on the source chain are only released by `_withdraw`, which is exclusively triggered by the arrival of this `RedeemEscrow` message via `onAccept` [6](#0-5) . Hyperbridge's permissionless relayers are explicitly profit-driven and will simply decline to deliver an underpriced message [7](#0-6) . Because `timeout: 0` disables any timeout/refund mechanism, an under-funded (including zero-fee) `RedeemEscrow` dispatch permanently strands the escrowed input tokens with no on-chain recovery: the solver has already paid out the output side and has no way to force settlement or reclaim.

This mirrors the reported bug class precisely — a caller-controlled fee/gas-like parameter that funds delivery of a message is insufficiently validated (no minimum, and here not even `>0`), letting an irreversible action complete on one side while the paired action can never be serviced on the other, resulting in loss of funds. This is reachable by any ordinary solver misconfiguring `options.relayerFee` (e.g., the off-chain SDK/GasEstimator computing it is optional guidance, not an on-chain floor) — it needs no malicious relayer, admin, or governance actor, only ordinary rational relayer economics, which is explicitly in scope per the bounty framing ("bridged assets ... must move exactly once and only to the rightful beneficiary").

Note: the cancellation dispatches (`_cancelFromSource`, `_cancelFromDest`) have the identical pattern (unchecked `options.relayerFee`, `timeout: 0`) [8](#0-7) [9](#0-8) , compounding the risk since even the cancellation/refund safety valve can itself get stuck.

### Title
Unvalidated `options.relayerFee` combined with `timeout: 0` on RedeemEscrow/RefundEscrow dispatch can permanently strand escrowed order funds - (File: evm/src/apps/intentsv2/ExtrinsicIntents.sol)

### Summary
`_fillCrossChain`, `_cancelFromSource`, and `_cancelFromDest` dispatch Hyperbridge POST/GET requests whose `fee`/relayer-fee field comes directly from caller-supplied `options.relayerFee` with no minimum-value check, and whose `timeout` is hardcoded to `0` (never expires). If the fee is too low (including zero) to incentivize any relayer to deliver the message, the escrow-releasing counter-message can never land, and because the request never times out there is no built-in mechanism to retry, cancel, or refund — the escrowed order funds are locked indefinitely.

### Finding Description
`_fillCrossChain` requires the solver to first pay out `order.output.assets` to the beneficiary [2](#0-1) . It then dispatches a `RedeemEscrow` `DispatchPost` with `fee: options.relayerFee` and `timeout: 0` [10](#0-9) . There is no `require(options.relayerFee >= MIN)` or similar guard anywhere in this function or in the shared `DispatchPost`/`IDispatcher.dispatch` path [11](#0-10) . The source-chain escrow release (`_withdraw`) only happens when this message is delivered and processed via `onAccept` [6](#0-5) .

Hyperbridge's relayer network is explicitly permissionless and profit-driven — it prioritizes messages whose attached fee covers gas plus a margin [7](#0-6) . A `fee` too small (or zero) to be profitable will simply never be picked up. Normally, an undelivered request can be recovered via the protocol's timeout path, which refunds the fee and lets the app-level `onPostRequestTimeout` unwind state [5](#0-4) . But `timeout: 0` explicitly disables this — per the protocol's own documentation, `timeout: 0` means the message "will never expire" [4](#0-3) . Consequently, an under-funded `RedeemEscrow`/`RefundEscrow` dispatch has no possible recovery: it cannot time out, be resubmitted, or be manually retried by the contract.

### Impact Explanation
For a cross-chain fill, the solver has already unconditionally transferred output tokens to the beneficiary before the vulnerable dispatch occurs. If `options.relayerFee` is insufficient, the solver's corresponding input-token entitlement held in source-chain escrow can never be released, and (for `_cancelFromDest`/`_cancelFromSource`) a legitimate order cancellation's refund can equally get stuck — locking user or solver funds in escrow permanently with zero on-chain remediation path. This is a direct "loss of funds" / stuck-custody outcome matching the bounty's in-scope impact categories, arising purely from missing input validation in production contract code, not from any malicious relayer/admin/prover assumption.

### Likelihood Explanation
Likelihood is high in practice: `options.relayerFee` is a plain caller-supplied field with no on-chain floor, and off-chain fee estimation (SDK `GasEstimator`, `RELAYER_MESSAGE_GAS`) is advisory only, not enforced by the contract [12](#0-11) . Any misconfigured integrator, buggy solver client, custom bidding bot, or user directly calling the ABI with a stale/zero fee value will trigger the unrecoverable state — no adversarial relayer behavior is required, only ordinary economic non-participation.

### Recommendation
Enforce a protocol-level minimum `fee`/`relayerFee` for `RedeemEscrow`, `RefundEscrow`, and `DispatchGet` cancellation dispatches (e.g., validate against a fetched gas-cost quote or a configurable floor) before calling `IDispatcher.dispatch`/`dispatchWithFeeToken`. Additionally, avoid hardcoding `timeout: 0` for these dispatches — use a bounded timeout so that, if delivery fails, the existing ISMP timeout/refund machinery (`dispatchTimeOut`) can restore recoverability of the escrowed funds.

### Proof of Concept
1. A solver calls `fillOrder` for a cross-chain order with `options.relayerFee = 0` (or any value below what any relayer considers profitable) and `options.nativeDispatchFee = 0`.
2. `_fillCrossChain` executes fully: output tokens are transferred to the beneficiary, and a `RedeemEscrow` `DispatchPost` with `fee: 0, timeout: 0` is dispatched — no revert occurs anywhere in `ExtrinsicIntents.sol` or `EvmHost.dispatch` for a zero/low fee.
3. No relayer delivers the message on Hyperbridge because it carries no viable fee.
4. Because `timeout == 0`, the request can never be timed out; `dispatchTimeOut`/refund logic is unreachable for this commitment.
5. The escrowed `order.inputs` on the source chain remain locked forever — `_withdraw` is never invoked, since it is only reachable through the delivered `onAccept` callback for this commitment.

    function _fillCrossChain(Order calldata order, FillOptions calldata options, bytes32 commitment) internal {
        uint256 outputsLen = order.output.assets.length;

        _filled[commitment] = msg.sender;

        uint256 msgValue = msg.value;
        address beneficiary = address(uint160(uint256(order.output.beneficiary)));
        TokenInfo[] memory outputFills = new TokenInfo[](outputsLen);

        for (uint256 i; i < outputsLen; i++) {
            bytes32 outputToken = order.output.assets[i].token;
            if (options.outputs[i].token != outputToken) revert InvalidInput();

            address token = address(uint160(uint256(outputToken)));
            uint256 totalRequired = order.output.assets[i].amount;
            uint256 solverAmount = options.outputs[i].amount;

            if (solverAmount < totalRequired) revert InvalidInput();

            uint256 dust = solverAmount - totalRequired;
            uint256 beneficiaryShare = 0;
            uint256 protocolShare = 0;

            if (dust > 0) {
                if (order.output.call.length > 0) {
                    protocolShare = dust;
                } else {
                    protocolShare = (dust * _params.surplusShareBps) / 10_000;
                    beneficiaryShare = dust - protocolShare;
                }
            }

            if (token == address(0)) {
                if (msgValue < solverAmount) revert InsufficientNativeToken();
                uint256 beneficiaryTotal = totalRequired + beneficiaryShare;
                (bool sent,) = beneficiary.call{value: beneficiaryTotal}("");
                if (!sent) revert InsufficientNativeToken();
                msgValue -= (beneficiaryTotal + protocolShare);
            } else {
                IERC20(token).safeTransferFrom(msg.sender, beneficiary, totalRequired + beneficiaryShare);
                if (protocolShare > 0) {
                    IERC20(token).safeTransferFrom(msg.sender, address(this), protocolShare);
                }
            }
            if (protocolShare > 0) emit DustCollected(token, protocolShare);
            outputFills[i] = TokenInfo({token: outputToken, amount: totalRequired});
        }

        _execute(order, outputsLen);

        address hostAddr = host();
        bytes memory body = bytes.concat(
            bytes1(uint8(RequestKind.RedeemEscrow)),
            abi.encode(
                WithdrawalRequest({
                    commitment: commitment, tokens: order.inputs, beneficiary: bytes32(uint256(uint160(msg.sender)))
                })
            )
        );
        DispatchPost memory request = DispatchPost({
            dest: order.source,
            to: abi.encodePacked(_instance(order.source)),
            body: body,
            timeout: 0,
            fee: options.relayerFee,
            payer: msg.sender
        });

        if (options.nativeDispatchFee > 0 && msgValue >= options.nativeDispatchFee) {
            IDispatcher(hostAddr).dispatch{value: options.nativeDispatchFee}(request);
            msgValue -= options.nativeDispatchFee;
        } else {
            dispatchWithFeeToken(request);
        }

        // Refund any unspent native tokens to the solver.
        if (msgValue > 0) {
            (bool sent,) = msg.sender.call{value: msgValue}("");
            if (!sent) revert InsufficientNativeToken();
        }

        emit OrderFilled({commitment: commitment, filler: msg.sender, outputs: outputFills, inputs: order.inputs});
    }

    function dispatchTimeOut(
        PostRequestTimeout memory timeout,
        FeeMetadata memory meta,
        bytes32 commitment
    ) external restrict(_hostParams.handler) {
        // replay protection
        delete _requestCommitments[commitment];
        (bool success,) = _bytesToAddress(timeout.request.from)
            .call(abi.encodeWithSelector(IApp.onPostRequestTimeout.selector, timeout));

        if (!success) {
            // so that it can be retried
            _requestCommitments[commitment] = meta;
            return;
        }

        if (meta.fee != 0) {
            // refund relayer fee
            IERC20(feeToken()).safeTransfer(meta.sender, meta.fee);
        }
        emit PostRequestTimeoutHandled({commitment: commitment, dest: string(timeout.request.dest)});
    }

    function dispatch(DispatchPost memory post) external payable notFrozen returns (bytes32 commitment) {
        if (msg.value > 0) {
            address[] memory path = new address[](2);
            address uniswapV2 = _hostParams.uniswapV2;
            path[0] = IUniswapV2Router02(uniswapV2).WETH();
            path[1] = feeToken();
            IUniswapV2Router02(uniswapV2).swapETHForExactTokens{value: msg.value}(
                post.fee, path, address(this), block.timestamp
            );
        } else if (post.fee > 0) {
            IERC20(feeToken()).safeTransferFrom(_msgSender(), address(this), post.fee);
        }

        // adjust the timeout
        uint64 timeoutTimestamp = post.timeout == 0 ? 0 : uint64(block.timestamp) + uint64(post.timeout);
        PostRequest memory request = PostRequest({
            source: host(),
            dest: post.dest,
            nonce: uint64(_nextNonce()),
            from: abi.encodePacked(_msgSender()),
            to: post.to,
            timeoutTimestamp: timeoutTimestamp,
            body: post.body
        });

        // make the commitment
        commitment = request.hash();
        _requestCommitments[commitment] = FeeMetadata({sender: post.payer, fee: post.fee});
