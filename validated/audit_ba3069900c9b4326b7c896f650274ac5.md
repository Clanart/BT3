### Title
Ungoverned `Kip71GasTarget = 0` causes a division-by-zero panic in `NextMagmaBlockBaseFee`, permanently halting all nodes on the next non-empty block - (File: `params/kip71_config.go`)

### Summary
The `Kip71GasTarget` governance parameter is registered with a `noopFormatChecker`, unlike the structurally similar `Kip71BaseFeeDenominator` parameter, which explicitly rejects zero. This missing bound allows a governance vote to set `GasTarget = 0`. Once active, `NextMagmaBlockBaseFee` — the KIP-71 base-fee update function invoked on every block by both header validation and block building — divides by `gasTarget` without a zero-guard, causing an unrecoverable panic as soon as any block includes gas usage (i.e., any ordinary transaction). This mirrors the reported `GasThrottle`/`_FAST_GAS_ORACLE` issue: an unguarded, governance-settable parameter that feeds a mandatory per-transaction gas-pricing check, with no built-in mitigation, causing total denial of service once corrupted.

### Finding Description
`Kip71BaseFeeDenominator` explicitly validates `v != 0` in its `FormatChecker`: [1](#0-0) 

By contrast, `Kip71GasTarget` uses `noopFormatChecker`, performing no validation at all: [2](#0-1) 

This asymmetry is confirmed by the vote-acceptance test suite, which explicitly exercises "valid gastarget" with no upper/lower bound checks (unlike `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee`, which have dedicated `checkConsistency` cross-checks): [3](#0-2) [4](#0-3) 

`GasTarget` votes fall into the default "no more checks here" branch in `checkConsistency`, meaning a value of `0` passes verification and can be committed via a normal governance vote.

Once `GasTarget = 0` is active, `NextMagmaBlockBaseFee` computes the next block's base fee. The function does defensively guard `BaseFeeDenominator == 0` (line 71-73) but does **not** guard `GasTarget == 0`: [5](#0-4) 

With `gasTarget = 0`, as soon as `parentGasUsed > 0` (i.e., any transaction consumed gas in the parent block), the code takes the `parentGasUsed > gasTarget` branch and executes:
```
y := x.Div(x, new(big.Int).SetUint64(gasTarget))
```
Dividing a `big.Int` by zero panics in Go's `math/big` package. This is an unrecoverable runtime panic, not a returned error.

`NextMagmaBlockBaseFee` (via `VerifyMagmaHeader`) is invoked in the block validator's per-block header verification path, and separately in block building/worker and gas-price oracle code: [6](#0-5) 

Because this function runs unconditionally on every block after the Magma fork, every node that receives or builds a block with nonzero gas usage will panic simultaneously, in lock-step, with no way to skip or disable this check (there is no kill-switch analogous to what the report requested for `GasThrottle`).

### Impact Explanation
Once `GasTarget` is (mis)configured to `0` by governance, the very next block containing any gas-consuming transaction from any ordinary, unprivileged transaction sender causes a division-by-zero panic in the base-fee computation on every full node (validators/CNs and endpoint nodes alike) as they validate or build that block. This is a chain-wide denial of service: block production and chain progression halt network-wide, and there is no governance parameter or code path to disable/recover the KIP-71 mechanism once the malformed value has been committed to the chain — recovery would require a hard fork/patch, exactly the class of unrecoverable DOS the original report flagged for `GasThrottle`.

### Likelihood Explanation
The parameter is settable purely via a standard governance vote (the format checker imposes no lower bound), and votes for `Kip71GasTarget` are explicitly accepted as long as the value decodes to `uint64`, including `0`. Once set, the trigger condition (`parentGasUsed > 0`) is trivially satisfied by any regular transaction — no attacker-controlled contract logic or malicious node behavior is required, only a single ordinary transaction reaching a block after the bad governance change activates. The severity is high because the effect is deterministic and immediate (not probabilistic), though the initial precondition (a governance vote setting `GasTarget=0`, whether by error or malice) is the gating step.

### Recommendation
Add an explicit non-zero `FormatChecker` for `Kip71GasTarget`, matching the guard already present for `Kip71BaseFeeDenominator`: [7](#0-6) 
Additionally, harden `NextMagmaBlockBaseFee` itself with the same defensive zero-check pattern already used for `BaseFeeDenominator` so that a corrupted/legacy on-chain value (e.g., from before the fix) cannot resurrect the panic: [8](#0-7) 

### Proof of Concept
1. Governing node/council submits a governance vote setting `gov.Kip71GasTarget = 0` (accepted because `Kip71GasTarget`'s `FormatChecker` is `noopFormatChecker`, see `kaiax/gov/param.go:324-334`, and `checkConsistency` performs no additional validation for this key, `kaiax/gov/headergov/impl/header.go:214-219`).
2. The vote is committed at the next epoch block, making `GasTarget = 0` part of the active `ParamSet`.
3. Any ordinary user submits a normal transaction that is included in the next block after Magma fork, so `parentHeaderGasUsed > 0`.
4. On every node processing that block, `KIP71Config.NextMagmaBlockBaseFee` (`params/kip71_config.go:58-103`) computes `parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)` (>0), takes the `parentGasUsed > gasTarget` branch, and executes `x.Div(x, new(big.Int).SetUint64(0))`, which panics.
5. All nodes evaluating this header (via `VerifyMagmaHeader` in header validation, and via block-building/worker and gas-price oracle call sites) crash or halt, producing a chain-wide, unrecoverable denial of service.

func (kc *KIP71Config) VerifyMagmaHeader(headerBaseFee *big.Int, parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) error {
	if headerBaseFee == nil {
		return fmt.Errorf("header is missing baseFee")
	}
	// Verify the baseFee is correct based on the parent header.
	expectedBaseFee := kc.NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentHeaderGasUsed)
	if headerBaseFee.Cmp(expectedBaseFee) != 0 {
		return fmt.Errorf("invalid baseFee: have %s, want %s, parentBaseFee %s, parentGasUsed %d",
			headerBaseFee, expectedBaseFee, parentHeaderBaseFee, parentHeaderGasUsed)
	}
	return nil
}

func (kc *KIP71Config) NextMagmaBlockBaseFee(parentHeaderNumber *big.Int, parentHeaderBaseFee *big.Int, parentHeaderGasUsed uint64) *big.Int {
	// governance parameters
	lowerBoundBaseFee := new(big.Int).SetUint64(kc.LowerBoundBaseFee)
	upperBoundBaseFee := new(big.Int).SetUint64(kc.UpperBoundBaseFee)
	makeEvenByCeil(lowerBoundBaseFee)
	makeEvenByFloor(upperBoundBaseFee)

	// If the parent is the magma disabled block or genesis, then return the lowerBoundBaseFee (default 25ston)
	if parentHeaderNumber.Cmp(new(big.Int).SetUint64(0)) == 0 || parentHeaderBaseFee == nil {
		return makeEvenByFloor(lowerBoundBaseFee)
	}

	var baseFeeDenominator *big.Int
	if kc.BaseFeeDenominator == 0 {
		// To avoid panic, set the fluctuation range small
		baseFeeDenominator = new(big.Int).SetUint64(64)
	} else {
		baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
	}
	gasTarget := kc.GasTarget
	upperGasLimit := kc.MaxBlockGasUsedForBaseFee

	// check the case of upper/lowerBoundBaseFee is updated by governance mechanism
	parentBaseFee := parentHeaderBaseFee
	if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
		parentBaseFee = upperBoundBaseFee
	} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
		parentBaseFee = lowerBoundBaseFee
	}

	// upper gas limit cut off the impulse of used gas to upper bound
	parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
	if parentGasUsed == gasTarget {
		return makeEvenByFloor(parentBaseFee)
	} else if parentGasUsed > gasTarget {
		// shortcut. If parentBaseFee is already reached upperbound, do not calculate.
		if parentBaseFee.Cmp(upperBoundBaseFee) == 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		// If the parent block used more gas than its target,
		// the baseFee of the next block should increase.
		// baseFeeDelta = max(1, parentBaseFee * (parentGasUsed - gasTarget) / gasTarget / baseFeeDenominator)
		gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := math.BigMax(x.Div(y, baseFeeDenominator), common.Big1)
