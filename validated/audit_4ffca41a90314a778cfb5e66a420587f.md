## Title
Attacker-controlled git remote can spoof a "GitHub Enterprise" identity and trigger a native sign-in prompt bound to the attacker's endpoint - (File: `app/src/lib/trampoline/trampoline-credential-helper.ts`)

## Summary
The bug-class in the external report is: a state-changing/trust decision is derived from data that the counterparty (an untrusted actor) fully controls, and downstream logic acts on that decision without re-validating it, causing the honest party to lose something of value (funds/credentials) to the untrusted actor. The Desktop analog is the `getEndpointKind` heuristic in the git-credential-helper trampoline, which classifies an arbitrary git remote as a GitHub/GHE host based on response data the remote server itself supplies (`WWW-Authenticate` header, or a `/meta` HTTP probe), and then uses that classification to launch a native "Sign in to GitHub Enterprise" dialog whose sign-in endpoint is the attacker's own origin.

## Finding Description
`getEndpointKind` decides whether a git credential request is for GitHub.com, GHE, or a "generic" host: [1](#0-0) 

Critically, before any TLS/host validation, it trusts a `WWW-Authenticate` header value that git captured from the HTTP response of the remote it's talking to:

```
for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } ...
```

This header is fully attacker-controlled: any git server (or a MITM/dumb HTTP proxy on the LAN, or a plain non-TLS remote) that returns `401` with `WWW-Authenticate: Basic realm="GitHub"` on a git-http-backend request will cause this function to return `'enterprise'` — before the `credentialUrl.protocol !== 'https:'` check is ever reached, so it works even for a plaintext `http://` remote. The alternative path (`isGitHubHost`) is likewise driven purely by response headers (`x-github-request-id`) from a URL the attacker controls: [2](#0-1) 

Once `endpointKind !== 'generic'` and no existing account matches that origin, `getCredential` invokes the "prompt user to sign in" path: [3](#0-2) 

That prompt is `promptForGitHubSignIn(endpoint)`, where `endpoint` is the attacker's remote origin (not the legitimate GitHub.com/GHE host the user actually intended to authenticate to): [4](#0-3) 

Because `hostname !== 'github.com'`, this calls `dispatcher.beginEnterpriseSignIn(cb)` and `dispatcher.setSignInEndpoint(origin)` — binding the "Sign in to GitHub Enterprise" flow directly to the attacker's origin, bypassing the strict `https://`-only validation that exists for manually-entered enterprise URLs: [5](#0-4) 

That validation function is never invoked on this credential-helper-triggered path — the origin is taken as-is from the URL parsed out of the git remote/attacker response.

## Impact Explanation
An unprivileged attacker who controls a git remote (or a network position able to answer a git-over-HTTP request, e.g. a rogue Wi-Fi/proxy) can, with zero user interaction beyond the user performing a normal fetch/clone/push, cause GitHub Desktop to pop a native, trusted-looking "Sign in to GitHub Enterprise" dialog whose backing endpoint is the attacker's server. A user who completes that flow (entering a username/password for basic auth, or completing an OAuth/browser flow) sends their real GitHub Enterprise credentials or authorization artifacts to the attacker-controlled endpoint. This matches the report's underlying invariant violation: a value/trust decision derived from an untrusted party's own claim ("I am GitHub") is acted upon by the other side (Desktop) without independent verification, resulting in credential/session loss for the honest user — analogous to User B losing funds because the "claimed" state was accepted without protecting the counterparty.

## Likelihood Explanation
No admin rights, no leaked credentials, and no unnatural steps are required beyond the ordinary workflow of adding/using a git remote that isn't fully trusted (e.g. a URL from a "clone this" link, or a fork whose remote is added by the user, or a corporate/public proxy). Getting `getCredential` to reach the sign-in-prompt branch only requires the remote to answer with an attacker-chosen `401`+`WWW-Authenticate` header or a spoofable `/meta` response — trivial for anyone running a server. The main friction is that the user must notice and manually complete the sign-in dialog, which is a normal, expected UX step in Desktop (making this a believable phishing vector rather than a wholly silent compromise).

## Recommendation
Do not derive a "this is a first-party GitHub/GHE host, prompt for sign-in" decision purely from response headers a git remote controls. At minimum:
- Require a successful, non-heuristic verification (e.g., only via the app's own controlled `getEnterpriseAPIURL`/known-endpoint list, or a signed/pinned indicator) before offering the Enterprise/GitHub sign-in flow for an unknown origin.
- Run any auto-detected enterprise endpoint through `validateURL` (the same one used for manually-entered enterprise addresses) before calling `setSignInEndpoint`.
- Surface the actual remote/host being signed into more prominently in the sign-in dialog so users can visually detect a mismatch with the repository they believe they're authenticating against.

## Proof of Concept
1. Attacker stands up a minimal HTTP git server (or MITM proxy) at `http://malicious.example.com/attacker/repo.git`.
2. On any authenticated git request (`GET .../info/refs?service=git-upload-pack`), the server responds `401 Unauthorized` with header `WWW-Authenticate: Basic realm="GitHub"`.
3. Victim adds/uses this URL as a remote in GitHub Desktop and performs a fetch/push.
4. Desktop's credential-helper trampoline captures the `wwwauth[...]` header via `parseCredential`/`getCredentialUrl`, and `getEndpointKind` (`app/src/lib/trampoline/trampoline-credential-helper.ts:137-179`) returns `'enterprise'`.
5. Since no existing account matches `malicious.example.com`, `getCredential` calls `ui.promptForGitHubSignIn('http://malicious.example.com')` (`...trampoline-credential-helper.ts:94-125`), which calls `beginEnterpriseSignIn` + `setSignInEndpoint(origin)` with the attacker's origin (`trampoline-ui-helper.ts:80-104`), bypassing `enterprise-validate-url.ts`'s https-only check.
6. Desktop shows a native "Sign in to GitHub Enterprise" dialog; if the victim completes it, their credentials/OAuth exchange are sent to the attacker's endpoint.

Note: I was not able to fully trace the downstream `SignInStore`/`dispatcher.beginEnterpriseSignIn` OAuth-vs-basic-auth branch logic (`app/src/lib/stores/sign-in-store.ts`, `app/src/ui/sign-in/sign-in.tsx`) within available context to confirm exactly which credential material (password vs OAuth code/token) is transmitted to the attacker endpoint in each auth mode; a Devin session with full repo access would be needed to verify that end-to-end and to confirm whether any endpoint allow-listing exists later in that flow that isn't visible in the indexed snippets.

async function getCredential(cred: Credential, store: Store, token: string) {
  const ghCred = await getGitHubCredential(cred, store)

  if (ghCred) {
    return ghCred
  }

  const endpointKind = await getEndpointKind(cred, store)
  const accounts = await store.getAll()

  const endpoint = `${getCredentialUrl(cred)}`
  const apiEndpoint = getAPIEndpoint(endpoint)

  // If it appears as if the endpoint is a GitHub host and we don't have an
  // account for that endpoint then we should prompt the user to sign in.
  if (
    endpointKind !== 'generic' &&
    !accounts.some(a => a.endpoint === apiEndpoint)
  ) {
    if (getIsBackgroundTaskEnvironment(token)) {
      debug('background task environment, skipping prompt')
      return undefined
    }

    const account = await ui.promptForGitHubSignIn(endpoint)

    if (!account) {
      setHasRejectedCredentialsForEndpoint(token, endpoint)
    }

    return credWithAccount(cred, account)
  }

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}

/**
 * Attempts to determine whether or not the url belongs to a GitHub host.
 *
 * This is a best-effort attempt and may return `undefined` if encountering
 * an error making the discovery request
 */
export async function isGitHubHost(url: string) {
  const { hostname } = new window.URL(url)

  const endpoint =
    hostname === 'github.com' || hostname === 'api.github.com'
      ? getDotComAPIEndpoint()
      : getEnterpriseAPIURL(url)

  if (isDotCom(endpoint) || isGHE(endpoint)) {
    return true
  }

  if (isKnownThirdPartyHost(hostname)) {
    return false
  }

  // github.example.com,
  if (/(^|\.)(github)\./.test(hostname)) {
    return true
  }

  // bitbucket.example.com, etc
  if (/(^|\.)(bitbucket|gitlab)\./.test(hostname)) {
    return false
  }

  if (getEndpointVersion(endpoint) !== null) {
    return true
  }

  // Add a unique identifier to the URL to make sure our certificate error
  // supression only catches this request
  const metaUrl = `${endpoint}/meta?ghd=${crypto.randomUUID()}`

  const ac = new AbortController()
  const timeoutId = setTimeout(() => ac.abort(), 2000)
  suppressCertificateErrorFor(metaUrl)
  try {
    const response = await fetch(metaUrl, {
      headers: { 'user-agent': getUserAgent() },
      signal: ac.signal,
      credentials: 'omit',
      method: 'HEAD',
      redirect: 'error',
    })

    tryUpdateEndpointVersionFromResponse(endpoint, response)

    return response.headers.has('x-github-request-id')
  } catch (e) {
    log.debug(`isGitHubHost: failed with endpoint ${endpoint}`, e)
    return undefined
  } finally {
    clearTimeout(timeoutId)
    clearCertificateErrorSuppressionFor(metaUrl)
  }
}

  public promptForGitHubSignIn(endpoint: string): Promise<Account | undefined> {
    return new Promise<Account | undefined>(async resolve => {
      const cb = (result: SignInResult) => {
        resolve(result.kind === 'success' ? result.account : undefined)
        this.dispatcher.closePopup(PopupType.SignIn)

      const { hostname, origin } = new URL(endpoint)
      if (hostname === 'github.com') {
        this.dispatcher.beginDotComSignIn(cb)
      } else {
        this.dispatcher.beginEnterpriseSignIn(cb)
        await this.dispatcher.setSignInEndpoint(origin)
      }

      this.dispatcher.showPopup({
        type: PopupType.SignIn,
        isCredentialHelperSignIn: true,
        credentialHelperUrl: endpoint,
      })
    }).catch(e => {
      log.error(`Could not prompt for GitHub sign in`, e)
      return undefined
    })
  }

export function validateURL(address: string): string {
  // ensure user has specified text and not just whitespace
  // we will interact with this server so we can be fairly
  // relaxed here about what we accept for the server name
  const trimmed = address.trim()
  if (trimmed.length === 0) {
    const error = new Error('Unknown address')
    error.name = InvalidURLErrorName
    throw error
  }

  let url = URL.parse(trimmed)
  if (!url.host) {
    // E.g., if they user entered 'ghe.io', let's assume they're using https.
    address = `https://${trimmed}`
    url = URL.parse(address)
  }

  if (!url.protocol) {
    const error = new Error('Invalid URL')
    error.name = InvalidURLErrorName
    throw error
  }

  if (url.protocol !== 'https:') {
    const error = new Error('Invalid protocol')
    error.name = InvalidProtocolErrorName
    throw error
  }

  return address
}
