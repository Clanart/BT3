### Title
Unauthenticated SSRF via DataLayer On-Chain Mirror URLs Trusted by Subscribing Nodes - (File: `chia/data_layer/download_data.py`)

### Summary
Any wallet holder can create an on-chain DataLayer "mirror" coin claiming to serve **any** store's (`launcher_id`) data at attacker-chosen URLs, without proving ownership of that store. Nodes that subscribe to that store id treat these on-chain-advertised URLs as valid download servers and issue unauthenticated, server-side HTTP `GET` requests to them with no scheme/host restrictions, reproducing the same bug class as the Verba HTMLReader SSRF: attacker-controlled URL → server-side fetch of internal resources.

### Finding Description
DataLayer mirror coins are created by `DataLayerWallet.create_new_mirror()`, which spends a standard coin to the fixed mirror puzzle and stores an arbitrary `launcher_id` plus arbitrary URL list in the coin memo, with no check that the caller's wallet actually owns/controls that `launcher_id`: [1](#0-0) 

This is exposed to any local wallet user via the RPC surface: [2](#0-1) 

The mirror puzzle/memo format is fixed and globally readable/parseable by any peer that syncs the chain (`get_mirror_info()`): [3](#0-2) 

Any node that subscribes to a store id pulls all on-chain mirror URLs for that `launcher_id` unconditionally in `update_subscriptions_from_wallet()`: [4](#0-3) 

Those URLs are then used directly as HTTP download targets during sync in `fetch_and_validate()`: [5](#0-4) 

...which calls `insert_from_delta_file()` → `download_file()` → `http_download()`, and `http_download()` performs an unauthenticated, unrestricted `aiohttp` GET request built directly from the attacker-supplied `server_info.url`: [6](#0-5) 

There is no validation that the URL scheme is `http`/`https` only for legitimate remotes, no blocklist for loopback/link-local/private ranges (e.g. `169.254.169.254` cloud metadata, `127.0.0.1:<local RPC port>`), and no binding between the URL and any proof that its owner actually controls the corresponding store. The `.cursor/context/data-layer.md` notes explicitly acknowledge that "mirror URLs... are external trust inputs" for downloaded *content* validation, but the outbound HTTP request itself is unauthenticated and unrestricted regardless of content trust.

### Impact Explanation
Any user can broadcast a spend bundle creating a mirror coin under a `launcher_id` belonging to a legitimate/public DataLayer store that other operators subscribe to. This causes every subscribing node's DataLayer service to make a server-side GET request to an attacker-chosen URL/port (e.g., internal RPC endpoints, cloud metadata services, or other co-located internal infrastructure), matching the CVSS 6.0 (SC:H) SSRF impact class from the reference report — confidentiality of internal/network-adjacent services on the victim host or its cloud environment.

### Likelihood Explanation
Reachable by any unprivileged spend-bundle submitter (a standard XCH transaction to the fixed mirror puzzle with an arbitrary memo) — no keys, node ownership, or special privilege beyond a fee-paying wallet is required. The only prerequisite is that some other operator has subscribed to the targeted `launcher_id`, which is the normal usage pattern for public DataLayer stores. `create_new_mirror()`/`dl_new_mirror` performs no ownership check tying `launcher_id` to the calling wallet.

### Recommendation
- Enforce that mirror creation for a `launcher_id` can only be recognized/trusted if it originates from (or is co-signed by) the actual singleton owner, or otherwise cryptographically bind mirror authority to store ownership.
- In `http_download()`/`download_file()`, validate and restrict target URLs (scheme allow-list, DNS/IP resolution checks against private/loopback/link-local ranges, disallow redirects to disallowed hosts) before issuing outbound requests, and make this SSRF hardening apply regardless of content-integrity checks performed after download.

### Proof of Concept
1. Any wallet holder calls `dl_new_mirror` RPC with `launcher_id` set to a legitimate/public DataLayer store id they do not own, and `urls=["http://169.254.169.254/latest/meta-data/iam/security-credentials/","http://127.0.0.1:8562/get_root"]` [2](#0-1) .
2. The resulting mirror coin is confirmed on-chain, no ownership proof required [1](#0-0) .
3. Any node subscribed to that `launcher_id` picks up the malicious URLs on its next `update_subscriptions_from_wallet()` cycle [4](#0-3) .
4. During the next `fetch_and_validate()` sync pass, the node's DataLayer process issues an outbound HTTP GET to the attacker-chosen URL via `http_download()` [6](#0-5) , causing SSRF against the victim's internal network or cloud metadata service.

def create_mirror_puzzle() -> Program:
    return P2_PARENT.curry(Program.to(1))


MIRROR_PUZZLE_HASH = create_mirror_puzzle().get_tree_hash()


def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
