### Title
Untrusted `WWW-Authenticate` realm from any Git server spoofs GitHub Enterprise sign-in, phishing GitHub credentials - ([File: app/src/lib/trampoline/trampoline-credential-helper.ts])

### Summary
The credential-helper trampoline classifies a Git remote as `'enterprise'` (a real GitHub Enterprise host) purely based on the text of a `WWW-Authenticate` HTTP header returned by that remote, before any hostname/TLS validation is performed. An attacker who controls the Git server the user is fetching/pushing/pulling from (or a proxy in front of it) can set this header to trick Desktop into showing its "Sign in to GitHub Enterprise" flow pointed at the attacker's own endpoint.

### Finding Description
`getEndpointKind()` in [1](#0-0)  determines how much trust to place in a remote before invoking any GitHub-specific authentication flow. It first checks known-good hosts (`isGist`, `isDotCom`, `isGHE`), then falls back to a "happy path": it inspects `wwwauth[N]` credential-helper fields — which come directly from the `WWW-Authenticate` response header sent by the remote Git server, captured by Git and forwarded verbatim to Desktop's credential helper — and if the value contains `realm="GitHub"`, it unconditionally returns `'enterprise'`: [2](#0-1) 

This classification is a raw string match on server-supplied content with no verification that the host is actually a real GitHub Enterprise instance (no `isGitHubHost()` probe is performed in this branch, unlike the fallback path at line 178).

That `endpointKind` value is then consumed by `getCredential()`: [3](#0-2) 
Since the endpoint is not in the accounts store and `endpointKind !== 'generic'`, Desktop calls `ui.promptForGitHubSignIn(endpoint)` where `endpoint` is the attacker's own URL, surfacing the trusted-looking "Sign in to GitHub Enterprise" dialog for a host the user never configured as GHE.

### Impact Explanation
This lets any Git server the user connects to — a cloned/fetched repository's origin, a malicious fork's remote, or a MITM proxy — spoof the appearance of a legitimate GitHub Enterprise authentication prompt purely by returning a crafted `WWW-Authenticate: <scheme> realm="GitHub"` header on an HTTP 401. Because the prompt is Desktop's normal, trusted-looking sign-in UI, a user is likely to enter GitHub credentials or complete an OAuth/device flow against infrastructure the attacker controls, resulting in credential/token exfiltration and unauthorized account binding — matching the "unauthorized OAuth or account binding" / "credential exfiltration" impact classes for Desktop.

### Likelihood Explanation
No local access, admin rights, or prior compromise is needed. The only requirement is that the user runs a normal Git operation (clone/fetch/pull/push) against a repository whose remote is attacker-controlled or proxied, which is an entirely ordinary, unprompted user action already covered by Desktop's threat model (untrusted remotes/servers).

### Recommendation
Do not trust the `WWW-Authenticate` realm string alone to classify a host as GitHub Enterprise. At minimum, require the same `isGitHubHost()` verification (or equivalent probing of a known GitHub API endpoint) used in the generic fallback before elevating an unknown host to `'enterprise'`, and surface the actual untrusted hostname prominently in the sign-in prompt so users can recognize a mismatch.

### Proof of Concept
1. Attacker stands up an HTTPS Git server (or MITM proxy) at `https://evil.example.com/victim/repo.git`.
2. On any authenticated Git operation, the server responds with `401` and header `WWW-Authenticate: Basic realm="GitHub"`.
3. Git captures this and forwards it to Desktop's credential helper as a `wwwauth[]` field.
4. `getEndpointKind()` matches `realm="GitHub"` and returns `'enterprise'` without validating `evil.example.com` is a real GitHub host: [4](#0-3) 
5. `getCredential()` finds no existing account for `evil.example.com` and calls `ui.promptForGitHubSignIn('https://evil.example.com/...')`, showing Desktop's normal GitHub Enterprise sign-in UI for the attacker's domain: [5](#0-4) 
6. A user who trusts the Desktop-branded prompt enters credentials/PAT or completes OAuth against the attacker's endpoint, which the attacker captures.

const getEndpointKind = async (cred: Credential, store: Store) => {
  const credentialUrl = getCredentialUrl(cred)
  const endpoint = `${credentialUrl}`

  if (isGist(endpoint)) {
    return 'generic'
  }

  if (isDotCom(endpoint)) {
    return 'github.com'
  }

  if (isGHE(endpoint)) {
    return 'ghe.com'
  }

  // When Git attempts to authenticate with a host it captures any
  // WWW-Authenticate headers and forwards them to the credential helper. We
  // use them as a happy-path to determine if the host is a GitHub host without
  // having to resort to making a request ourselves.
  for (const [k, v] of cred.entries()) {
    if (k.startsWith('wwwauth[')) {
      if (v.includes('realm="GitHub"')) {
        return 'enterprise'
      } else if (/realm="(GitLab|Gitea|Atlassian Bitbucket)"/.test(v)) {
        return 'generic'
      }
    }
  }

  const existingAccount = await findGitHubTrampolineAccount(store, endpoint)
  if (existingAccount) {
    return isDotCom(existingAccount.endpoint) ? 'github.com' : 'enterprise'
  }

  // All GitHub hosts use HTTPS, so if the protocol is not HTTPS we can
  // assume that this is not a GitHub host.
  if (credentialUrl.protocol !== 'https:') {
    return 'generic'
  }

  return (await isGitHubHost(endpoint)) ? 'enterprise' : 'generic'
}
