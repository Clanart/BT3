### Title
Governance-set `GasTarget=0` causes divide-by-zero panic in KIP-71 base fee calculation, halting all nodes - ([File: params/kip71_config.go])

### Summary
`KIP71Config.NextMagmaBlockBaseFee` divides by the governance-controlled `GasTarget` parameter with no zero-check, while the sibling `BaseFeeDenominator` parameter explicitly guards against zero. The `Kip71GasTarget` governance parameter definition uses `noopFormatChecker`, allowing it to be set to `0` through the standard governance voting mechanism, which would cause every node computing/verifying the next block's base fee to panic (divide-by-zero) — a chain-wide denial of service, directly analogous to CVE-2017-8842's unchecked-divisor crash.

### Finding Description
`NextMagmaBlockBaseFee` computes the base-fee delta using `big.Int.Div` with `gasTarget` as divisor in both the "gas used > target" and "gas used < target" branches: [1](#0-0) [2](#0-1) 

Unlike `BaseFeeDenominator`, which is explicitly checked and defaulted to `64` if zero to "avoid panic": [3](#0-2) 

`gasTarget := kc.GasTarget` has no equivalent guard before being used as a divisor: [4](#0-3) 

Go's `math/big.Int.Div` panics on division by zero, so if `GasTarget == 0` and `parentGasUsed != gasTarget` (i.e., `parentGasUsed != 0`), the call panics.

Critically, the governance parameter registry defines `Kip71GasTarget` with a no-op format checker, meaning there is no validation preventing it from being set to `0` via governance vote: [5](#0-4) 

This contrasts with `Kip71BaseFeeDenominator`, which explicitly rejects `0`: [6](#0-5) 

### Impact Explanation
`NextMagmaBlockBaseFee`/`VerifyMagmaHeader` is invoked during block assembly and block header validation on every node in the network (referenced from `blockchain/block_validator.go`, `blockchain/chain_makers.go`, `blockchain/tx_pool.go`, `work/worker.go`, and the gas price oracle). If `GasTarget` is set to `0` through governance (a reachable, in-scope governance parameter per the analog rules), the very next block with nonzero gas usage would cause every honest node computing or verifying that block's base fee to panic, halting block production and validation network-wide — a severe availability impact matching the CVSS 5.5+ "application crash" characterization of the source CVE, arguably worse here since it affects the whole chain rather than a single decompression utility.

### Likelihood Explanation
Exploitation requires a successful governance vote setting `kip71.gastarget` to `0`. While governance voting is restricted to the governing/validator council rather than an arbitrary unprivileged transaction sender, the prompt's rules explicitly list "governance parameters" as an in-scope reachable path, and the root cause is a missing validation guard (unlike the sibling `BaseFeeDenominator` field, which was deliberately protected). Since no format check rejects `0`, this is a straightforward and readily achievable misconfiguration/vote outcome, not requiring any exotic exploit chain.

### Recommendation
Add a `FormatChecker` for `Kip71GasTarget` in `kaiax/gov/param.go` that rejects `0` (mirroring `Kip71BaseFeeDenominator`'s `v != 0` check), and/or add a defensive zero-check with a safe fallback inside `NextMagmaBlockBaseFee` in `params/kip71_config.go` before using `gasTarget` as a divisor, consistent with the existing `baseFeeDenominator == 0` fallback.

### Proof of Concept
1. Governance council votes to set `kip71.gastarget` to `0` (currently accepted since `Kip71GasTarget.FormatChecker == noopFormatChecker`).
2. Once the vote takes effect, any block with `parentGasUsed != 0` is produced.
3. Every node calls `NextMagmaBlockBaseFee(parentHeaderNumber, parentHeaderBaseFee, parentGasUsed)` during block assembly (`work/worker.go`) or header verification (`blockchain/block_validator.go`).
4. Inside the function, `gasUsedDelta := ...; x := new(big.Int).Mul(...); y := x.Div(x, new(big.Int).SetUint64(gasTarget))` executes `big.Int.Div` with a zero divisor, which panics per Go's `math/big` semantics, crashing the node process and halting the chain network-wide.
