### Title
Out-of-bounds read via unbounded length-prefix indexing in `is_atom_canonical` - (File: `chia/full_node/mempool_manager.py`)

### Summary
`is_atom_canonical` decodes a CLVM atom's length prefix directly from an attacker-supplied byte buffer and walks `prefix_len` additional bytes into that buffer with no check that `offset` stays within `len(clvm_buffer)`, unlike sibling wire-format parsers in the codebase that explicitly validate remaining-buffer length before indexing.

### Finding Description
`is_atom_canonical(clvm_buffer, offset)` reads the byte at `clvm_buffer[offset]` to classify the atom's length-prefix encoding, then loops `prefix_len` times, each iteration incrementing `offset` and reading `clvm_buffer[offset]` to accumulate `atom_len`, with no bounds check that `offset < len(clvm_buffer)` at any point in the loop: [1](#0-0) 

This is called from `is_clvm_canonical`, which walks a whole CLVM-serialized buffer (a spend bundle's solution/generator bytes) atom-by-atom, advancing `offset` by the value `is_atom_canonical` returns and repeating until `tokens_left == 0`, again without validating `offset` stays in range before dereferencing `clvm_buffer[offset]`: [2](#0-1) 

This is the same bug class as CVE-2016-2801: an attacker-controlled length/size field taken from untrusted serialized data is used to compute an index/offset into a buffer, and that offset is dereferenced without verifying it stays within the buffer's bounds — in `CmapSubtable12Lookup` this produced a buffer over-read; here a crafted length prefix (e.g. a multi-byte length-prefix marker such as `0xFC`/`0xF8` placed at or near the end of the buffer) causes `clvm_buffer[offset]` to be evaluated past the end of `clvm_buffer`.

Notably, other untrusted-data parsers in this same codebase area explicitly guard against this exact failure mode by checking the remaining buffer length before indexing, e.g. `skip_bytes` and `skip_list` in `chia/full_node/full_block_utils.py`: [3](#0-2) 
The absence of an equivalent check in `is_atom_canonical`/`is_clvm_canonical` is the root cause.

### Impact Explanation
In CPython, out-of-range indexing into `bytes` raises `IndexError` rather than causing true out-of-bounds memory access, so this is memory-safe but not exception-safe. If `is_clvm_canonical`/`is_atom_canonical` is invoked on attacker-controlled CLVM buffer bytes (spend bundle solution or generator bytes) during spend-bundle processing without the caller catching `IndexError` specifically, a single unprivileged spend-bundle submitter can trigger an unhandled exception mid-processing. Depending on where in the mempool admission/eligibility pipeline this is reached and how broadly exceptions are caught there, this can manifest as a spend-triggered halt of that processing path rather than a clean rejection, which is one of the accepted impact categories for this class of bug (a spend-triggered transaction-processing halt) even though it does not by itself grant coin theft, forged assets, or consensus divergence.

### Likelihood Explanation
The trigger requires only a single crafted spend bundle solution/generator whose serialized CLVM bytes end with (or place near the boundary) an atom-length-prefix marker byte (`0xF8`–`0xFF` range) that claims more trailing length bytes than actually remain in the buffer — no privileged position or peer trust is required, matching the reachability bar of an unprivileged spend-bundle submitter.

### Recommendation
Add explicit bounds checks in `is_atom_canonical` before each `clvm_buffer[offset]` access inside the `for i in range(prefix_len)` loop (and before the initial `clvm_buffer[offset]` read in `is_clvm_canonical`'s main loop), mirroring the pattern already used in `chia/full_node/full_block_utils.py`'s `skip_bytes`/`skip_list` (validate `offset + prefix_len < len(clvm_buffer)` and raise/return a clean "not canonical"/error result instead of indexing out of range). Ensure the resulting exception type, if any is still possible, is caught at every call site that feeds untrusted bundle bytes into this function.

### Proof of Concept
1. Craft a spend bundle whose solution/generator serializes to CLVM bytes where the final byte is a multi-byte-length-prefix marker (e.g. `0xFC`) that, per `is_atom_canonical`'s decoding, requires 5 additional trailing bytes to fully read `atom_len`, but the buffer ends immediately after that marker byte.
2. Submit the spend bundle so that its CLVM buffer reaches `is_clvm_canonical`/`is_atom_canonical` during mempool processing (via the code path that determines eligibility for fast-forward/dedup handling, which calls into these canonicality checks).
3. Observe `is_atom_canonical`'s loop attempt `clvm_buffer[offset]` with `offset >= len(clvm_buffer)`, raising an unhandled `IndexError` if the call site does not explicitly catch it, aborting normal processing of that code path instead of yielding a controlled "non-canonical" verdict.

def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value
```

def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
```

def skip_bytes(buf: memoryview) -> memoryview:
    if len(buf) < 4:
        raise ValueError(f"byte length prefix requires 4 bytes, remaining buffer {len(buf)}")
    n = int.from_bytes(buf[:4], "big", signed=False)
    buf = buf[4:]
    if n > len(buf):
        raise ValueError(f"byte length {n} exceeds remaining buffer {len(buf)}")
    return buf[n:]
