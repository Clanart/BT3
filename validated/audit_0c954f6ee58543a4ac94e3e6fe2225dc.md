## Title
Oracle Slash-Window Penalty Can Be Fully Avoided by Undelegating Before the Slash Window Ends - (File: `x/oracle/keeper/slash.go`)

## Summary
The oracle module penalizes validators (and, through cascading slash-unbonding logic, their delegators) for poor oracle-vote participation over an entire `SlashWindow`. However, the slash is executed with an `infractionHeight` set to essentially "now" (`ctx.BlockHeight() - ValidatorUpdateDelay - 1`), rather than the start of the offending window. Because `x/staking`'s `Slash`/`SlashUnbondingDelegation`/`SlashRedelegation` only slash unbonding/redelegation entries whose `CreationHeight >= infractionHeight`, any delegator who begins unbonding/redelegating at any point *before the very last few blocks* of the slash window entirely escapes the penalty — even though their stake was bonded, earning rewards, and backing the validator's voting power for nearly the whole window during which the bad behavior occurred. This mirrors the reported pattern of using an alternate, faster/earlier exit path to dodge a penalty that is meant to be triggered before withdrawal completes.

## Finding Description
Oracle slashing is applied once per `SlashWindow` in `EndBlocker`: [1](#0-0) 

The actual penalty logic lives in `SlashAndResetCounters`, which computes a `distributionHeight` that is only `ValidatorUpdateDelay + 1` blocks behind the current height (a small, near-constant offset, not the start of the slash window), and then calls the generic staking `Slash` with that height: [2](#0-1) 

The generic staking `Slash` function iterates the validator's unbonding delegations and redelegations and slashes only entries whose unbonding/redelegation began at or after `infractionHeight`: [3](#0-2) 

`SlashUnbondingDelegation` explicitly skips any entry that started unbonding before `infractionHeight`: [4](#0-3) 

`SlashRedelegation` applies the identical skip rule for redelegations: [5](#0-4) 

This "skip entries that started before the infraction height" rule is correct for single-height infractions such as double-signing, where evidence of a concrete misbehaving block is submitted later — stake that had already begun unbonding before that specific block genuinely did not contribute to it. But the oracle module's "infraction" is not a single block: it is a validator's cumulative miss/abstain rate measured across the *entire* `SlashWindow` (potentially many thousands of blocks). By passing `distributionHeight ≈ ctx.BlockHeight() - ValidatorUpdateDelay - 1` (i.e., "now") as the `infractionHeight`, the code effectively tells the staking module "only stake that began unbonding in the last couple of blocks was part of this infraction." Any delegator who issues `MsgUndelegate` or `MsgBeginRedelegate` at essentially any earlier point during the slash window — while their tokens are still fully bonded and contributing to the misbehaving validator's voting power — has an unbonding/redelegation entry whose `CreationHeight` is far below `distributionHeight`, so it is unconditionally skipped and never slashed.

## Impact Explanation
This breaks the core economic-security assumption of oracle slashing: that delegators share the risk of backing a poorly performing/oracle-non-compliant validator for the duration they are bonded to it. A delegator (or the validator operator delegating to themselves) can watch their own miss/abstain counters accumulate mid-window, realize a slash is coming at `SlashWindow`'s end, and simply submit an ordinary, unprivileged `MsgUndelegate`/`MsgBeginRedelegate` transaction — no special privilege required — to have their principal excluded from the eventual slash while still having enjoyed staking rewards for nearly the entire window. This nullifies the intended token-burn (penalty) for the affected principal, undermining the punitive/incentive mechanism that oracle slashing is designed to enforce, exactly analogous to the reported `earlyUnstake()` pattern that let users dodge a QA penalty by exiting before it was assessed.

## Likelihood Explanation
The path is trivially reachable by any unprivileged delegator using the standard `MsgUndelegate`/`MsgBeginRedelegate` messages, requires no special timing precision (any point before the last couple of blocks in the slash window works), and requires no cooperation from the validator or any privileged party. The only prerequisite is delegating to a validator that is (or is expected to become) non-compliant with oracle voting requirements, which is observable on-chain via `MissCount`/`AbstainCount` state.

## Recommendation
Use the actual start height of the current `SlashWindow` (not `ctx.BlockHeight() - ValidatorUpdateDelay - 1`) as the `infractionHeight` passed into `k.StakingKeeper.Slash` in `SlashAndResetCounters`, so that any unbonding/redelegation entry created at any point during the window is correctly captured and slashed, closing the escape path.

## Proof of Concept
1. Delegator `D` delegates tokens to validator `V` at the start of an oracle `SlashWindow`.
2. `V` fails to vote validly enough during the window (miss/abstain counters accumulate) such that `validVoteRate < MinValidPerWindow`.
3. Shortly after delegating (well before the window's final blocks), `D` submits `MsgUndelegate` (or `MsgBeginRedelegate`) for their full stake. This creates an `UnbondingDelegation`/`Redelegation` entry with `CreationHeight` equal to that early block.
4. At the last block of the `SlashWindow`, `EndBlocker` → `SlashAndResetCounters` computes `distributionHeight := height - ValidatorUpdateDelay - 1` (≈ current height) and calls `StakingKeeper.Slash(ctx, consAddr, distributionHeight, power, slashFraction)`.
5. In `SlashUnbondingDelegation`/`SlashRedelegation`, `entry.CreationHeight < infractionHeight` evaluates true for `D`'s entry (created far earlier in the window), so the entry is skipped — `D`'s stake is never slashed, despite having backed `V`'s voting power for nearly the entire non-compliant window. // SlashAndResetCounters do slash any operator who over criteria & clear all operators miss counter to zero
func (k Keeper) SlashAndResetCounters(ctx sdk.Context) {
	height := ctx.BlockHeight()
	distributionHeight := height - sdk.ValidatorUpdateDelay - 1

	minValidPerWindow := k.MinValidPerWindow(ctx)
	slashFraction := k.SlashFraction(ctx)
	powerReduction := k.StakingKeeper.PowerReduction(ctx)

	k.IterateVotePenaltyCounters(ctx, func(operator sdk.ValAddress, votePenaltyCounter types.VotePenaltyCounter) bool {
		// Calculate valid vote rate; (totalVotes - (MissCounter + AbstainCounter))/totalVotes
		// this accounts for changes in vote period within a window, and will take the overall success rate
		// as opposed to the one expected based on the number of vote period expected based on the ending slash window or vote period
		totalVotes := votePenaltyCounter.SuccessCount + votePenaltyCounter.AbstainCount + votePenaltyCounter.MissCount
		if totalVotes == 0 {
			logger.Error("zero votes in penalty counter, this should never happen")
			return false
		}
		validVoteRate := sdk.NewDecFromInt(
			sdk.NewInt(int64(votePenaltyCounter.SuccessCount))). //nolint:gosec
			QuoInt64(int64(totalVotes))                          //nolint:gosec

		// Penalize the validator whose the valid vote rate is smaller than min threshold
		if validVoteRate.LT(minValidPerWindow) {
			validator := k.StakingKeeper.Validator(ctx, operator)
			if validator.IsBonded() && !validator.IsJailed() {
				consAddr, err := validator.GetConsAddr()
				if err != nil {
					panic(err)
				}

				k.StakingKeeper.Slash(
					ctx, consAddr,
					distributionHeight, validator.GetConsensusPower(powerReduction), slashFraction,
				)
				k.StakingKeeper.Jail(ctx, consAddr)
				oracleKeeperMetrics.validatorSlashedTotal.Add(ctx.Context(), 1, otelmetric.WithAttributes(attribute.String("validator", consAddr.String()), attribute.String("type", "oracle")))
			}
