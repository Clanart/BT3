### Title
Unauthenticated payout OP_RETURN attribution allows an unprivileged party to malleate a fronted withdrawal and permanently deny the true operator's reimbursement - (File: core/src/verifier.rs, core/src/builder/transaction/operator_reimburse.rs)

### Summary
The bridge's `payout_tx` (which an operator broadcasts to front a user's withdrawal) is signed by the user with `SIGHASH_SinglePlusAnyoneCanPay`, which only commits to the withdrawal input and the single user-payout output. The remaining outputs — including the `OP_RETURN` output that records which operator's x-only pubkey should be credited as the payer — are **not covered by the signature** and can be freely substituted by anyone who can reconstruct or intercept the transaction. The verifier's `update_finalized_payouts` attributes reimbursement rights solely by parsing this unauthenticated `OP_RETURN` field of whichever transaction happens to confirm and spend the withdrawal UTXO, with no binding to who actually funded the transaction.

### Finding Description
`create_payout_txhandler` builds the payout transaction with:
1. Input 0: the withdrawal UTXO, spent with the user's `KeySpend` signature.
2. Output 0: the user's payout (signed).
3. Output 1: anchor (unsigned).
4. Output 2: `OP_RETURN` carrying `operator_xonly_pk` (unsigned). [1](#0-0) 

The user signature only covers txin 0 and the corresponding single output via `SinglePlusAnyoneCanPay`, and is verified that way in `Operator::withdraw`: [2](#0-1) 

Because `ANYONECANPAY` is used, additional inputs (funding) may legitimately be added by RBF — but this also means **any holder of the signature** can construct an alternative valid transaction spending the same withdrawal outpoint with the same required output, while freely choosing a *different* (or no) `OP_RETURN` payload, since that output is outside the sighash commitment.

On-chain attribution of "who fronted the payout" is derived purely from parsing this unauthenticated `OP_RETURN` of whichever transaction ends up confirmed and spending the tracked withdrawal UTXO: [3](#0-2) 

This is persisted directly into `payout_payer_operator_xonly_pk` with no cross-check against the tx's actual funding inputs: [4](#0-3) 

Later, when the true fronting operator tries to claim reimbursement via `get_reimbursement_txs`, the check `validate_payer_is_operator` strictly compares the DB-recorded `payer_xonly_pk` (derived from the on-chain `OP_RETURN`) against `self.signer.xonly_public_key`, and fails hard (with no recovery path) if they don't match or if the payer is `None`: [5](#0-4) 

Since the withdrawal UTXO can only be spent once, and the honest operator's original `payout_tx` (with correct `OP_RETURN`) can be pre-empted/replaced (e.g., via a competing transaction that reuses the same signed input/output while modifying the unsigned outputs, or by an unrelated third party racing to confirm a variant first) with a different or missing `OP_RETURN`, the true payer is permanently and irrecoverably unable to prove they fronted the withdrawal on-chain. `validate_payer_is_operator`'s only failure branches are unconditional errors — there is no fallback mechanism to reconcile "the real funder of the inputs" with "the operator recorded as payer."

### Impact Explanation
This breaks the equality that should hold: `operator credited as payer == operator whose funds actually left to pay the user`. Once broken by confirmation of a payout transaction with a wrong/missing `OP_RETURN`, the honest operator that genuinely fronted the withdrawal from their own BTC becomes permanently unable to be reimbursed for that withdrawal (`validate_payer_is_operator` will forever return an error for that deposit id, and `PayoutCheckerTask`/`get_first_unhandled_payout_by_operator_xonly_pk` will never surface it to the operator that actually paid), matching the Critical criterion "an honest operator permanently unable to be reimbursed." Conversely, whichever xonly pubkey ends up recorded in the confirmed `OP_RETURN` is credited as the payer regardless of who actually supplied the funding inputs, i.e., "the operator credited versus the party that paid" binding is broken.

### Likelihood Explanation
Exploitation requires no privileged role: any party capable of observing the pending/broadcast payout transaction (e.g., in the mempool, or via any off-chain relay of the withdrawal signature) can construct a colliding transaction that reuses the same signed input/output and confirms first with a different `OP_RETURN`, since `SinglePlusAnyoneCanPay` explicitly permits this malleability by design for RBF funding — the same property that enables the attack also enables free substitution of the unsigned attribution output.

### Recommendation
Bind the reimbursement attribution to the actual funder rather than to an unauthenticated `OP_RETURN` field. Options include: having the operator's kickoff/reimbursement path independently attest (e.g., with a fresh operator signature over the specific confirmed `payout_txid`) that they funded it, requiring the `OP_RETURN` payload (or an operator commitment covering it) to be part of the signed sighash, or reconciling `payer_xonly_pk` against the actual non-anchor/non-withdrawal funding inputs of the confirmed transaction before persisting `payout_payer_operator_xonly_pk`.

### Proof of Concept
1. Operator A obtains the user's `SinglePlusAnyoneCanPay` signature and constructs `payout_tx_A` via `create_payout_txhandler`, funds it with `fund_raw_transaction`, and broadcasts it — `OP_RETURN` = A's xonly pubkey [6](#0-5) .
2. Any third party observing the pending/broadcast tx (or otherwise obtaining the reused signed input/output pair) constructs `payout_tx_B`: same input 0 with the same signature, same output 0 to the user, but its own funding inputs, and an `OP_RETURN` set to a different (or absent) xonly pubkey, then gets it confirmed first (e.g. via a higher-fee RBF replacement).
3. `update_finalized_payouts` on the verifiers parses `payout_tx_B`'s `OP_RETURN` and records `payout_payer_operator_xonly_pk` accordingly (or `NULL` if absent) [7](#0-6) .
4. Operator A calls `get_reimbursement_txs`/`validate_payer_is_operator` for the deposit and permanently receives an error, since `payer_xonly_pk` no longer equals A's key (or is `None`) [8](#0-7) , even though A is the one who actually paid the user.

pub fn create_payout_txhandler(
    input_utxo: UTXO,
    output_txout: TxOut,
    operator_xonly_pk: XOnlyPublicKey,
    user_sig: taproot::Signature,
    _network: bitcoin::Network,
) -> Result<TxHandler<Signed>, BridgeError> {
    let txin = SpendableTxIn::new_partial(input_utxo.outpoint, input_utxo.txout);

    let output_txout = UnspentTxOut::from_partial(output_txout.clone());

    let op_return_txout = op_return_txout(PushBytesBuf::from(operator_xonly_pk.serialize()));

    let mut txhandler = TxHandlerBuilder::new(TransactionType::Payout)
        .with_version(NON_STANDARD_V3)
        .add_input(
            NormalSignatureKind::NotStored,
            txin,
            SpendPath::KeySpend,
            DEFAULT_SEQUENCE,
        )
        .add_output(output_txout)
        .add_output(UnspentTxOut::from_partial(anchor_output(
            NON_EPHEMERAL_ANCHOR_AMOUNT,
        )))
        .add_output(UnspentTxOut::from_partial(op_return_txout))
        .finalize();
    txhandler.set_p2tr_key_spend_witness(&user_sig, 0)?;
    txhandler.promote()
}

    /// For a deposit_id checks that the payer for that deposit is the operator, and the payout blockhash and kickoff txid are set.
    async fn validate_payer_is_operator(
        &self,
        dbtx: Option<DatabaseTransaction<'_>>,
        deposit_id: u32,
    ) -> Result<(BlockHash, Txid), BridgeError> {
        let (payer_xonly_pk, payout_blockhash, kickoff_txid) = self
            .db
            .get_payer_xonly_pk_blockhash_and_kickoff_txid_from_deposit_id(dbtx, deposit_id)
            .await?;

        tracing::info!(
            "Payer xonly pk and kickoff txid found for the requested deposit, payer xonly pk: {:?}, kickoff txid: {:?}",
            payer_xonly_pk,
            kickoff_txid
        );

        // first check if the payer is the operator, and the kickoff is handled
        // by the PayoutCheckerTask, meaning kickoff_txid is set
        let (payout_blockhash, kickoff_txid) = match (
            payer_xonly_pk,
            payout_blockhash,
            kickoff_txid,
        ) {
            (Some(payer_xonly_pk), Some(payout_blockhash), Some(kickoff_txid)) => {
                if payer_xonly_pk != self.signer.xonly_public_key {
                    return Err(eyre::eyre!(
                        "Payer is not own operator for deposit, payer xonly pk: {:?}, operator xonly pk: {:?}",
                        payer_xonly_pk,
                        self.signer.xonly_public_key
                    )
                    .into());
                }
                (payout_blockhash, kickoff_txid)
            }
            _ => {
                return Err(eyre::eyre!(
                    "Payer info not found for deposit, payout blockhash: {:?}, kickoff txid: {:?}",
                    payout_blockhash,
                    kickoff_txid
                )
                .into());
            }
        };

    async fn update_finalized_payouts(
        &self,
        dbtx: DatabaseTransaction<'_>,
        block_id: u32,
        block_cache: &block_cache::BlockCache,
    ) -> Result<(), BridgeError> {
        let payout_txids = self
            .db
            .get_payout_txs_for_withdrawal_utxos(Some(dbtx), block_id)
            .await?;

        let block = &block_cache.block;

        let block_hash = block.block_hash();

        let mut payout_txs_and_payer_operator_idx = vec![];
        for (idx, payout_txid) in payout_txids {
            let payout_tx_idx = block_cache.txids.get(&payout_txid);
            if payout_tx_idx.is_none() {
                tracing::error!(
                    "Payout tx not found in block cache: {:?} and in block: {:?}",
                    payout_txid,
                    block_id
                );
                tracing::error!("Block cache: {:?}", block_cache);
                return Err(eyre::eyre!("Payout tx not found in block cache").into());
            }
            let payout_tx_idx = payout_tx_idx.expect("Payout tx not found in block cache");
            let payout_tx = &block.txdata[*payout_tx_idx];
            // Find the first output that contains OP_RETURN
            let circuit_payout_tx = CircuitTransaction::from(payout_tx.clone());
            let op_return_output = get_first_op_return_output(&circuit_payout_tx);

            // If OP_RETURN doesn't exist in any outputs, or the data in OP_RETURN is not a valid xonly_pubkey,
            // operator_xonly_pk will be set to None, and the corresponding column in DB set to NULL.
            // This can happen if optimistic payout is used, or an operator constructs the payout tx wrong.
            let operator_xonly_pk = op_return_output
                .and_then(|output| parse_op_return_data(&output.script_pubkey))
                .and_then(|bytes| XOnlyPublicKey::from_slice(bytes).ok());

            if operator_xonly_pk.is_none() {
                tracing::info!(
                    "No valid operator xonly pk found in payout tx {:?} OP_RETURN. Either it is an optimistic payout or the operator constructed the payout tx wrong",
                    payout_txid
                );
            }

            tracing::info!(
                "A new payout tx detected for withdrawal {}, payout txid: {:?}, operator xonly pk: {:?}",
                idx,
                payout_txid,
                operator_xonly_pk
            );

            payout_txs_and_payer_operator_idx.push((
                idx,
                payout_txid,
                operator_xonly_pk,
                block_hash,
            ));
        }

    /// Sets the given payout txs' txid and operator index for the given index.
    pub async fn update_payout_txs_and_payer_operator_xonly_pk(
        &self,
        tx: Option<DatabaseTransaction<'_>>,
        payout_txs_and_payer_operator_xonly_pk: Vec<(
            u32,
            Txid,
            Option<XOnlyPublicKey>,
            bitcoin::BlockHash,
        )>,
    ) -> Result<(), BridgeError> {
        if payout_txs_and_payer_operator_xonly_pk.is_empty() {
            return Ok(());
        }
        // Convert all values first, propagating any errors
        let converted_values: Result<Vec<_>, BridgeError> = payout_txs_and_payer_operator_xonly_pk
            .iter()
            .map(|(idx, txid, operator_xonly_pk, block_hash)| {
                Ok((
                    i32::try_from(*idx).wrap_err("Failed to convert payout index to i32")?,
                    TxidDB(*txid),
                    operator_xonly_pk.map(XOnlyPublicKeyDB),
                    BlockHashDB(*block_hash),
                ))
            })
            .collect();
        let converted_values = converted_values?;

        let mut query_builder = QueryBuilder::new(
            "UPDATE withdrawals AS w SET
                payout_txid = c.payout_txid,
                payout_payer_operator_xonly_pk = c.payout_payer_operator_xonly_pk,
                payout_tx_blockhash = c.payout_tx_blockhash
                FROM (",
        );

        query_builder.push_values(
            converted_values.into_iter(),
            |mut b, (idx, txid, operator_xonly_pk, block_hash)| {
                b.push_bind(idx)
                    .push_bind(txid)
                    .push_bind(operator_xonly_pk)
                    .push_bind(block_hash);
            },
        );

        query_builder
            .push(") AS c(idx, payout_txid, payout_payer_operator_xonly_pk, payout_tx_blockhash) WHERE w.idx = c.idx");

        let query = query_builder.build();
        execute_query_with_tx!(self.connection, tx, query, execute)?;

        Ok(())
    }
