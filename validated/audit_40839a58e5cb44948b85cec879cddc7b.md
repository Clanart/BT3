## #Vulnerability found for this question.

### Title
Symlink-crafted "." pathspec turns scoped `get_git_diff` reviews into unrestricted whole-repo diffs - (File: `plugins/security-guidance/hooks/gitutil.py`)

### Summary
`_diff_pathspec` only rejects candidate paths whose relative form starts with `".."`, but it accepts a relative form of exactly `"."` (or any value that is not `".."`-prefixed) without checking that it actually names a specific file inside the repo. A repo-tracked symlink whose target resolves to the repository root itself makes `os.path.relpath(os.path.realpath(p), cwd_abs)` return `"."`, which is spliced into the pathspec as `["--", "."]` — a git pathspec that matches the **entire working tree**, not the single file the caller intended to scope the diff to.

### Finding Description
`_diff_pathspec` builds the pathspec used to scope `get_git_diff` to the caller-supplied `paths`: [1](#0-0) 

For each path `p` it computes `os.path.relpath(os.path.realpath(p), cwd_abs)` and only drops entries starting with `".."`. It does not guard against the relpath being `"."` (meaning `p` resolved to the repo root itself) or otherwise trivially broad.

`get_git_diff` treats a non-empty pathspec as a valid restriction and runs `git diff` with it directly: [2](#0-1) 

The `review_paths` fed into `get_git_diff` from the Stop-hook flow are built as `os.path.join(repo, p)` for every repo-root-relative path git reports as changed/untracked (`compute_v2_review_set`): [3](#0-2) [4](#0-3) 

Exploit flow:
1. A repo (or a contributor with normal push/PR access, i.e. no elevated privilege on the victim's machine) commits a symlink at the repository top level whose target resolves to the repository root itself — e.g. a symlink `link_to_root` with target `.` sitting directly under the repo root. This is ordinary, valid git content; git tracks symlinks as blobs storing the target string and does not restrict what they point to.
2. Any turn that touches (or merely leaves modified/untracked) this symlink causes `git status --porcelain` to report it, so `compute_v2_review_set` includes it in `review_set`/`review_paths`.
3. In `_diff_pathspec`, `os.path.realpath(os.path.join(repo, "link_to_root"))` resolves through the symlink back to `repo` itself. `os.path.relpath(repo, repo)` returns `"."`, which does not start with `".."`, so it is accepted and appended to `rel`.
4. The resulting pathspec is `["--", ".", <other legitimate rel paths>...]`. Because `"."` alone matches every path in the repo, `git diff ... -- . <other files>` collapses to an **unrestricted diff of the entire working tree**, defeating the file-scoping the caller explicitly requested.
5. The code path at lines 406-412 of `gitutil.py` only special-cases the *opposite* failure mode (pathspec becoming empty, which would also unintentionally produce an unrestricted diff) — it explicitly returns `""` in that case to avoid an unscoped diff. It does not check for the `"."`-poisoning case, so that safeguard is bypassed.

This breaks the stated invariant that git path scoping "must never escape the intended repo target": the diff scope escapes from "the specific files touched this turn" to "the whole repository," including files never touched, never intended for review, and potentially containing unrelated secrets/config that are then serialized into the diff text sent onward to the LLM review call.

### Impact Explanation
This is a logic-level bypass of the diff-scoping guard that the Stop-hook/commit-review pipeline relies on to bound what gets sent to the external LLM review and to bound diff size/time. Concretely:
- Unrelated, previously-untouched files' full content is pulled into the diff and forwarded to the Haiku review call and downstream file-parsing/priority logic (`parse_diff_into_files`, `_prioritize_diff_files`), which is a scoping/trust-boundary violation — content that should never have left the intended review scope gets included.
- A large or pathological repo makes the now-unrestricted `git diff` (with `timeout=30`) far more likely to time out, causing `get_git_diff` to return `None` and drive the Stop hook into repeated skip/retry cycles — a logic-level service disruption of the guard's intended behavior.
- This matches "Logic-level service disruption caused by bypassing a required guard or misbinding security state": the required guard is the pathspec-based scoping meant to bind the diff/review call to the intended file set.

### Likelihood Explanation
- Precondition: attacker needs only ordinary repository write access (a contributor, a malicious PR branch, or simply the content of a repository the victim clones/opens with Claude Code) — no admin/maintainer privilege on the victim's machine.
- Feasibility: creating a symlink pointing to `.` at the repo root is a single `ln -s . link_to_root && git add -A && git commit` — trivial and fully repeatable.
- The bug triggers deterministically any time that symlink shows up in `git status --porcelain` as tracked-dirty or untracked during a reviewed turn, which is easy to arrange (e.g., touch the symlink's timestamp, or ensure it's simply present as untracked content).

### Recommendation
In `_diff_pathspec`, reject any candidate whose realpath-relative form is `"."`, empty, or otherwise identifies the repo root itself (i.e., require `r` to be a genuine sub-path, not equal to `.` and not empty), in addition to the existing `".."`-prefix check. Consider also validating that the resolved real path stays strictly under `cwd_abs` with `os.path.commonpath` rather than `relpath`, which is more robust against symlink and unicode-normalization edge cases mentioned in the audit context.

### Proof of Concept
Unit test to add near existing `gitutil` tests:
```python
def test_diff_pathspec_rejects_root_resolving_symlink(tmp_path):
    repo = tmp_path / "repo"
    repo.mkdir()
    # symlink at repo root pointing back to repo root itself
    link = repo / "link_to_root"
    link.symlink_to(repo, target_is_directory=True)

    pathspec = _diff_pathspec(str(repo), [str(link)])

    # Must NOT produce a pathspec that matches the whole tree.
    assert pathspec != ["--", "."]
    assert "." not in pathspec
```
Expected current (buggy) behavior: `pathspec == ["--", "."]`, i.e. an unrestricted diff pathspec is produced from a single symlinked "touched path" entry — confirming the scope-escape. After the fix, such an entry should be dropped (treated like an out-of-scope path), just as `".."`-prefixed entries already are, so `get_git_diff` never falls back to a whole-repo diff when the caller asked for a restricted one.

```python
def _diff_pathspec(cwd, paths):
    """Convert absolute touched-paths to repo-relative pathspec args for
    git diff. Paths outside cwd (e.g. ~/.claude/…) are dropped. Returns the
    list to splice after `--`, or [] for an unrestricted diff. realpath both
    sides so the macOS /var ↔ /private/var symlink doesn't make in-repo
    paths look external."""
    if not paths:
        return []
    cwd_abs = os.path.realpath(cwd)
    rel = []
    for p in paths:
        try:
            r = os.path.relpath(os.path.realpath(p), cwd_abs)
        except ValueError:
            continue
        if r.startswith(".."):
            continue
        rel.append(r)
    return ["--"] + rel if rel else []
```
