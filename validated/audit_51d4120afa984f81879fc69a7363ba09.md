### Title
`SignableTransaction` fee and weight accounting ignore the OP_RETURN data output, allowing an oversized/under-priced transaction to be signed - (File: networks/bitcoin/src/wallet/send.rs)

### Summary
The Upsonic advisory is an allowlist-bypass class bug: inputs that pass a validation gate (`command` in `{npm, npx}`) still carry attacker-controlled payloads (`args`) that escape the gate's intent. The analog in Serai is `SignableTransaction::new`: the `data` field passes its own validation gate (`<= 80` bytes), gets appended as an extra `TxOut`, but is then omitted from every downstream weight/vbyte/fee/`MAX_STANDARD_TX_WEIGHT` computation, which are all derived only from `payments` and `change`.

### Finding Description
In `SignableTransaction::new`, the OP_RETURN output is pushed onto `tx_outs` before the weight calculation, but `calculate_weight_vbytes` is invoked with `payments` (not `tx_outs`), so the OP_RETURN output is never represented in the synthetic transaction used for sizing [1](#0-0) . Consequently:

1. `needed_fee = fee_per_vbyte * vbytes` under-counts the real virtual size [2](#0-1) .
2. The change-output branch repeats the same omission — `fee_with_change` and the change `value` are computed against a transaction that lacks the OP_RETURN output [3](#0-2) .
3. The standardness gate `weight > MAX_STANDARD_TX_WEIGHT` checks the under-counted `weight`, so a transaction that actually exceeds the relay weight limit is accepted [4](#0-3) .

The resulting `SignableTransaction` is then signed verbatim — the sighash is computed over the real `self.tx.tx` (which does contain the OP_RETURN) via `taproot_key_spend_signature_hash` with `Prevouts::All` [5](#0-4) , so the threshold signature is produced for a transaction whose economics (effective fee rate, standardness) differ from what the construction API promised and what signers would reasonably expect.

The `data` payload is attacker-reachable: in the Serai processor flow, Bitcoin outputs carrying `InInstruction` data are parsed from untrusted on-chain transactions (`extract_serai_data` / `presumed_origin` population in `get_outputs`), and outbound transactions are assembled from user-initiated instructions [6](#0-5) .

### Impact Explanation
- The multisig signs a transaction that pays a lower effective fee rate than `fee_per_vbyte` requested, since real vsize > computed `vbytes`. With `fee_per_vbyte` near the minimum relay floor, the signed transaction can fall below `DEFAULT_MIN_RELAY_TX_FEE` effective rate and be rejected by peers — funds become temporarily unmovable even though a valid signed transaction exists.
- With 80 bytes of `data` plus enough inputs, the real transaction can exceed `MAX_STANDARD_TX_WEIGHT` while passing the check, yielding a fully validly-signed transaction that no standard node will relay — the wallet reports/constructs a spend that is not actually broadcastable.
- This matches the advisory's shape: a permitted parameter (`data`, like `args` for an allow-listed command) escapes the policy checks applied to the rest of the input.

### Likelihood Explanation
Requires an 80-byte data payload and enough inputs/payments that the marginal ~90+ vbytes tip the transaction over a boundary (relay fee floor or weight cap). Low-to-moderate likelihood; impact is a stuck/non-relayable signed transaction rather than key compromise, so Medium at most — but the discrepancy between declared and actual fee also silently misdirects the change amount, which is deterministic whenever `data` is present.

### Recommendation
Pass the fully-assembled `tx_outs` (including the OP_RETURN output) into `calculate_weight_vbytes`, or compute weight directly from the final `Transaction`. Recompute `needed_fee` and the change value against that weight, and perform the `MAX_STANDARD_TX_WEIGHT` check on the real transaction weight, e.g. `self.tx.weight()` after construction.

// Conceptual: with K inputs whose total size is just under the weight cap,
// and data = [0u8; 80]
let inputs: Vec<ReceivedOutput> = ...; // e.g. ~200 taproot inputs
let data = Some(vec![0u8; 80]);
let tx = SignableTransaction::new(inputs, &payments, None, data.clone(), fee_per_vbyte).unwrap();

// 1) The OP_RETURN output exists in the real tx...
assert!(tx.transaction().output.iter().any(|o| o.script_pubkey.is_op_return()));

// 2) ...but was never counted:
//    actual vsize > vbytes used for needed_fee
let actual_vsize = tx.transaction().vsize() as u64;
assert!(actual_vsize > tx.needed_fee() / fee_per_vbyte);
// Effective fee rate = fee() / actual_vsize < fee_per_vbyte

// 3) With inputs near MAX_STANDARD_TX_WEIGHT, construction succeeds while
//    tx.transaction().weight() > MAX_STANDARD_TX_WEIGHT — a signed tx no
//    standard node will relay.

  async fn get_outputs(&self, block: &Self::Block, key: ProjectivePoint) -> Vec<Output> {
    let (scanner, _, kinds) = scanner(key);

    let mut outputs = vec![];
    // Skip the coinbase transaction which is burdened by maturity
    for tx in &block.txdata[1 ..] {
      for output in scanner.scan_transaction(tx) {
        let offset_repr = output.offset().to_repr();
        let offset_repr_ref: &[u8] = offset_repr.as_ref();
        let kind = kinds[offset_repr_ref];

        let output = Output { kind, presumed_origin: None, output, data: vec![] };
        assert_eq!(output.tx_id(), tx.id());
        outputs.push(output);
      }

      if outputs.is_empty() {
        continue;
      }

      // populate the outputs with the origin and data
      let presumed_origin = {
        // This may identify the P2WSH output *embedding the InInstruction* as the origin, which
        // would be a bit trickier to spend that a traditional output...
        // There's no risk of the InInstruction going missing as it'd already be on-chain though
        // We *could* parse out the script *without the InInstruction prefix* and declare that the
        // origin
        // TODO
        let spent_output = {
          let input = &tx.input[0];
          let mut spent_tx = input.previous_output.txid.as_raw_hash().to_byte_array();
          spent_tx.reverse();
          let mut tx;
          while {
            tx = self.rpc.get_transaction(&spent_tx).await;
            tx.is_err()
          } {
            log::error!("couldn't get transaction from bitcoin node: {tx:?}");
            sleep(Duration::from_secs(5)).await;
          }
          tx.unwrap().output.swap_remove(usize::try_from(input.previous_output.vout).unwrap())
        };
        Address::new(spent_output.script_pubkey)
      };
      let data = Self::extract_serai_data(tx);
      for output in &mut outputs {
        if output.kind == OutputType::External {
          output.data.clone_from(&data);
        }
        output.presumed_origin.clone_from(&presumed_origin);
      }
    }

    outputs
  }
