### Title
Registry (KIP-149) owner can redirect `GaslessSwapRouter` to a malicious contract, letting a compromised admin steal proposer-lent KAIA in the gasless flow - (File: `kaiax/gasless/impl/getter.go`)

### Summary
The Kaia gasless-transaction feature resolves the trusted `SwapRouter` address dynamically from the on-chain KIP-149 `Registry` contract via `getGaslessInfo()`/`updateAddresses()` in `kaiax/gasless/impl/getter.go`. Any account holding `Registry.owner()` privileges can call `register("GaslessSwapRouter", <maliciousAddr>, activation)` (`contracts/bindings/kip149/Registry.go` `Register`) to arbitrarily swap the address nodes trust as the swap router, exactly as an upgradeable-proxy admin can swap a contract's logic in the original Rolla finding.

### Finding Description
The gasless module treats `g.swapRouter` — populated purely from `Registry.getActiveAddr("GaslessSwapRouter")` — as a fully trusted destination for value transfers, with no validation of its bytecode, immutability, or governance process beyond the single `Registry.owner()` key. [1](#0-0) 
The `Registry` contract's `register(name, addr, activation)` function can be called by anyone holding `owner()`, instantly (or after a short activation delay) changing which contract address is treated as the canonical `GaslessSwapRouter`. [2](#0-1) 
Once `g.swapRouter` points to the attacker's contract, `IsApproveTx`/`IsSwapTx`/`IsExecutable` all validate against that attacker-controlled address as if it were the legitimate router. [3](#0-2) 
Crucially, the proposer node itself constructs and signs a real-value `LendTx` sending native KAIA (`lendAmount`, covering the user's gas fees) directly `to` the user, keyed off the `swapTx.To()` (i.e., the registered router address context) before the user's swap executes and repays. [4](#0-3) 
If the registered router contract is malicious, or if the swap execution against it is manipulated (e.g., it doesn't perform the expected `swapForGas` accounting, doesn't return the borrowed value, or siphons `commission`/token balances via its owner-only `updateCommissionRate`/`claimCommission`/`addToken` functions), the attacker can extract value that proposers advanced and that users approved (`approve(spender=swapRouter, MaxUint256)` — an unlimited allowance analogous to the Rolla allowance-drain scenario). [5](#0-4) 
This mirrors the Rolla report exactly: the "logic" that users have granted allowances/value to is not immutable, and a single admin key (`Registry.owner`) can swap it out arbitrarily, with no on-chain restriction, timelock enforcement, or multisig required at the protocol layer.

### Impact Explanation
A compromised or malicious `Registry` owner can:
1. Register a malicious `GaslessSwapRouter` implementation that nodes will trust network-wide once its `activation` block is reached, causing every subsequent gasless approve+swap bundle to route users' pre-approved (MaxUint256) ERC-20 allowances and proposers' lent native KAIA to attacker-controlled logic.
2. Cause state divergence/invalid execution if some nodes have indexed a different (stale or malicious) router address at the fork boundary, since `updateAddresses` is driven by `PostInsertBlock` state reads that can vary by timing (`getGaslessInfo` uses `IsRandaoForkBlockParent` and `MultiCallGaslessInfo`).
This is a real unauthorized value movement path (fee-delegation/gasless settlement theft) reachable by any user who has approved/interacted with the gasless flow once the `Registry` owner acts maliciously — matching the accepted Medium severity of the original finding (a privileged-key/governance action is a precondition, but assets are then directly at risk).

### Likelihood Explanation
Requires control of the `Registry.owner()` key (a single EOA, not a contract-enforced timelock/multisig within `Registry.sol`/`RegistryMock.sol` itself), so likelihood is contingent on that key's security — same precondition class the original judge used to downgrade severity to Medium ("a governance attack must happen first"). No unprivileged transaction sender can trigger this alone, but once the registry entry is malicious, ordinary users submitting gasless approve+swap transactions are victims without further action.

### Recommendation
- Enforce a mandatory timelock and/or multisig/governance-vote requirement at the `Registry` contract level (not just off-chain policy) before any `register()` call affecting `GaslessSwapRouter` (or other value-bearing modules) takes effect.
- Have the gasless module validate the registered router's bytecode hash against an allow-listed set of audited implementations before trusting it in `updateAddresses`, rather than trusting any address `Registry.owner()` chooses.
- Consider bounding the value a single `LendTx` can advance per swap router registration/activation window, to limit blast radius if the registry entry is compromised.

### Proof of Concept
1. Attacker obtains or compromises the `Registry.owner()` key (via social engineering, leaked key, or a captured governance vote).
2. Attacker deploys `MaliciousRouter`, which mimics `swapForGas(token, amountIn, minAmountOut, amountRepay, deadline)` selector/ABI but keeps deposited tokens/KAIA instead of performing a real swap and repay. [6](#0-5) 
3. Attacker calls `Registry.register("GaslessSwapRouter", MaliciousRouter, activationBlock)` — a normal, permitted call to the `Registry` contract. [2](#0-1) 
4. At `activationBlock`, every node's `GaslessModule.updateAddresses()` (invoked from `PostInsertBlock`) starts trusting `MaliciousRouter` as `g.swapRouter`. [7](#0-6) 
5. A user submits `approve(MaliciousRouter, MaxUint256)` followed by `swapForGas(...)`; the proposer, believing this is a legitimate gasless bundle, signs and broadcasts a real-value `LendTx` sending KAIA to the user to cover fees. [8](#0-7) 
6. `MaliciousRouter` pulls the user's approved token balance via `transferFrom` but never performs the swap/repay logic honestly, resulting in loss of user funds and/or proposer-advanced KAIA.

// MakeLendTx creates a transaction with following properties:
// L1. LendTx.type = 0x7802 (TxTypeEthereumDynamicFee)
// L2. LendTx.from = proposer
// L3. LendTx.to = SwapTx.from
// L4. LendTx.value = LendAmount(approveTxOrNil, swapTx)
func (g *GaslessModule) GetLendTxGenerator(approveTxOrNil, swapTx *types.Transaction) *builder.TxOrGen {
	var src []byte
	if approveTxOrNil != nil {
		src = append(src, approveTxOrNil.Hash().Bytes()...)
	}
	src = append(src, swapTx.Hash().Bytes()...)
	bundleHash := crypto.Keccak256Hash(src)

	gen := func(nonce uint64) (*types.Transaction, error) {
		var (
			chainId = g.InitOpts.ChainConfig.ChainID
			signer  = types.LatestSignerForChainID(chainId)
			key     = g.InitOpts.NodeKey
		)

		to, err := types.Sender(signer, swapTx)
		if err != nil {
			return nil, err
		}

		tx, err := types.NewTransactionWithMap(types.TxTypeEthereumDynamicFee, map[types.TxValueKeyType]interface{}{
			types.TxValueKeyNonce:      nonce,
			types.TxValueKeyTo:         &to,
			types.TxValueKeyAmount:     lendAmount(approveTxOrNil, swapTx),
			types.TxValueKeyData:       common.Hex2Bytes("0x"),
			types.TxValueKeyGasLimit:   params.TxGas,
			types.TxValueKeyGasFeeCap:  swapTx.GasFeeCap(),
			types.TxValueKeyGasTipCap:  swapTx.GasTipCap(),
			types.TxValueKeyAccessList: types.AccessList{},
			types.TxValueKeyChainID:    chainId,
		})
		if err != nil {
			return nil, err
		}

		err = tx.Sign(signer, key)
		return tx, err
	}

	return builder.NewTxOrGenFromGen(gen, bundleHash)
}

func (g *GaslessModule) updateAddresses(header *types.Header) error {
	g.gaslessInfoMu.Lock()
	defer g.gaslessInfoMu.Unlock()

	swapRouter, tokens, err := getGaslessInfo(g.Chain, header)
	// proceed even if there is something wrong with multicall contract
	if err != nil {
		g.swapRouter = common.Address{}
		g.allowedTokens = map[common.Address]bool{}
		logger.Warn("there is something wrong with multicall contract", "err", err.Error())
		return nil
	}

	g.swapRouter = swapRouter
