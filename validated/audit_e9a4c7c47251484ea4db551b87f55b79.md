## Analysis

The external report's core defect: a **limited-trust operational role** (guardian) can call a state-ending action without the code checking that the required time-based condition (`sale.is_end_time_reached()`) has actually occurred — the authorization check (`is guardian?`) is present, but the temporal precondition is missing.

The direct Hyperbridge analog is `pallet-fishermen::veto_state_commitment` in `modules/pallets/fishermen/src/lib.rs`.

### Title
Fisherman `veto_state_commitment` never checks the challenge period has not already elapsed - ([File: modules/pallets/fishermen/src/lib.rs])

### Summary
`veto_state_commitment` only verifies that the caller is a member of the active collator set (`T::IsCollator::contains`) before unconditionally deleting a `StateCommitment` at any height. It does not verify that the referenced commitment is still inside its `challenge_period`, even though the pallet's own doc comment says the veto is meant for a commitment "which is ideally still in its challenge period." [1](#0-0) 

### Finding Description
`veto_state_commitment` performs exactly two checks: `ensure_signed` and `T::IsCollator::contains(&account)`. After that it fetches the commitment and calls `ismp_host.delete_state_commitment(height)` with no comparison against `host.timestamp()`, `challenge_period`, or `state_machine_update_time` — the same time-based guard that every other consumer of state commitments (`validate_state_machine`, `handlePostRequests`, `handleGetResponses`, timeout handlers) explicitly enforces before acting on a commitment. [2](#0-1) 

Contrast this with the protocol's own invariant, documented for every handler that touches a `StateCommitment`:
- `validate_state_machine` requires `verify_delay_passed` (challenge period elapsed) before requests/responses can be processed. [3](#0-2) 
- The EVM `HandlerV2` enforces `ChallengePeriodNotElapsed` before touching a `stateMachineCommitment` for requests, responses, and timeouts. [4](#0-3) 
- Documentation states a veto is only meaningful "while... still within its challenge period," and after the period elapses relayers/apps are meant to treat the commitment as canonical and finalized. [5](#0-4) 

Because `veto_state_commitment` has no such time check, a single collator (fisherman role — authorized but not required to be malicious, exactly analogous to a "guardian") can delete a `StateCommitment` at a height whose challenge period has already elapsed and which the protocol, relayers, and applications already treat as finalized. Any GET response, POST/GET timeout, or request delivery whose non-membership/membership proof is anchored at that height and is still in flight (not yet delivered) will subsequently fail with `StateCommitmentNotFound` on Hyperbridge/EVM handlers, because the underlying `StateCommitment` the proof needs to verify against has been erased. [6](#0-5) [7](#0-6) 

### Impact Explanation
This breaks the "state commitments, once past their challenge period, must never be silently retracted" invariant that request/response/timeout processing depends on. It enables an authorized-but-non-malicious-required actor to unilaterally cause loss of ability to settle/timeout in-flight messages anchored at a finalized height — a logic attack on state finality that can block relayer fee refunds (timeouts) and response delivery (stuck funds/fees) for any pending cross-chain message referencing that height, without any cryptographic fraud proof and without the temporal safety window the rest of the protocol enforces everywhere else.

### Likelihood Explanation
Likelihood is high given the trigger conditions are trivial: any single account already in the active collator set (a role whose sole "DOS guard," per the pallet's own comment, is `IsCollator`) can call the extrinsic on any height, at any time, for any reason — no proof, no quorum, and, critically, no check on the age of the commitment. This is a one-line missing `ensure!` compared to every neighboring handler in the same codebase.

### Recommendation
Add a check in `veto_state_commitment` that the target `StateMachineHeight`'s challenge period has not yet elapsed (mirroring `verify_delay_passed` / `ChallengePeriodNotElapsed` used elsewhere), rejecting vetoes against commitments that are already past their challenge period and therefore already treated as finalized/canonical by the rest of the protocol.

### Proof of Concept
1. A state machine height `H` is committed via consensus update; `challenge_period` for its state machine is non-zero.
2. Time advances past `challenge_period` for `H` — per protocol docs, `H`'s `StateCommitment` is now canonical and safe to rely on; relayers begin delivering requests/responses/timeouts whose proofs are anchored at `H`.
3. A GET request or POST timeout targeting `H` is in flight (submitted to Hyperbridge for aggregation, or awaiting delivery on the destination) but not yet finalized on-chain.
4. Any account in the active collator set calls `Fishermen::veto_state_commitment(H)`. The call succeeds — `ensure!(T::IsCollator::contains(&account), ...)` passes and `ismp_host.delete_state_commitment(H)` executes with no challenge-period check. [8](#0-7) 
5. The in-flight GET response/timeout message, when submitted, fails `StateCommitmentNotFound` because `H`'s commitment no longer exists, even though `H` was already past its challenge period and treated as final. [9](#0-8)

    function handlePostRequests(IHost host, PostRequestMessage calldata request) external notFrozen(host) {
        uint256 timestamp = block.timestamp;
        uint256 delay = timestamp - host.stateMachineCommitmentUpdateTime(request.proof.height);
        uint256 challengePeriod = host.challengePeriod();
        if (challengePeriod != 0 && challengePeriod > delay) revert ChallengePeriodNotElapsed();

        uint256 requestsLen = request.requests.length;
        MerkleMountainRange.Leaf[] memory leaves = new MerkleMountainRange.Leaf[](requestsLen);

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // check destination
            if (!leaf.request.dest.equals(host.host())) revert InvalidMessageDestination();
            // check time-out
            if (timestamp >= leaf.request.timeout()) revert MessageTimedOut();
            leaves[i] = MerkleMountainRange.Leaf(leaf.index, leaf.request.hash());
        }

        bytes32 root = host.stateMachineCommitment(request.proof.height).overlayRoot;
        if (root == bytes32(0)) revert StateCommitmentNotFound();
        bool valid = MerkleMountainRange.VerifyProof(root, request.proof.multiproof, leaves, request.proof.leafCount);
        if (!valid) revert InvalidProof();

        for (uint256 i = 0; i < requestsLen; ++i) {
            PostRequestLeaf memory leaf = request.requests[i];
            // duplicate request?
            if (host.requestReceipts(leaf.request.hash()) != address(0)) revert DuplicateMessage();
            host.dispatchIncoming(leaf.request, _msgSender());
        }
    }
