### Title
Kip71GasTarget governance parameter can be set to 0, causing a division-by-zero panic in `NextMagmaBlockBaseFee` - (File: `params/kip71_config.go`, `kaiax/gov/param.go`)

### Summary
The `Kip71GasTarget` governance parameter is validated with a `noopFormatChecker` that performs no bounds checking, unlike its sibling parameter `Kip71BaseFeeDenominator`, which explicitly rejects zero. This asymmetry mirrors the reported `MeritDutchAuction` bug class: a critical divisor-defining constructor/parameter input is left unvalidated, and the same value is later used as a divisor in the core pricing/fee formula, causing division by zero and reverting/crashing the affected computation.

### Finding Description
In `kaiax/gov/param.go`, the parameter table defines: [1](#0-0) 
- `Kip71BaseFeeDenominator` has `FormatChecker: func(cv any) bool { v, ok := cv.(uint64); return ok && v != 0 }` — explicitly disallowing zero.
- `Kip71GasTarget` has `FormatChecker: noopFormatChecker` — no validation at all, allowing `GasTarget` to be set to `0` via a governance vote.

The `GasTarget` value flows directly into `NextMagmaBlockBaseFee` in `params/kip71_config.go`, which computes the next block's base fee (KIP-71/Magma dynamic pricing): [2](#0-1) 

Note that `BaseFeeDenominator` is defensively guarded against zero (`if kc.BaseFeeDenominator == 0 { baseFeeDenominator = 64 }`), but `gasTarget` has no equivalent guard. If `gasTarget == 0` and `parentGasUsed > 0` (i.e., any non-empty block), the code enters the "gas used above target" branch and executes:
```go
gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget) // = parentGasUsed
x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
y := x.Div(x, new(big.Int).SetUint64(gasTarget))                  // divide by zero
```
`big.Int.Div` with a zero divisor panics in Go, exactly analogous to the reported Solidity issue where `getPriceAt()` reverts on division by zero because `startTime_ == endTime_` was never validated.

This is directly analogous to the reported bug class: a constructor/parameter-setting path (`MeritDutchAuction` constructor vs. Kaia's governance parameter setter) fails to validate that a value used later as a divisor is nonzero, and the divisor flows unchecked into the core pricing formula.

### Impact Explanation
`NextMagmaBlockBaseFee` is invoked both by header verification (`VerifyMagmaHeader`) and by consensus-critical block base-fee computation for every block after the Magma fork. A panic here on any node processing a non-empty block would crash the node process (Go panics from unhandled division-by-zero are not recoverable exceptions like a Solidity `revert`; they terminate the goroutine/process unless explicitly recovered). If triggered network-wide (since `GasTarget` is a chain-wide governance parameter applied to all CNs/PNs/ENs), this results in a full network halt — all nodes attempting to process the next non-empty block crash simultaneously. This is a critical availability/consensus impact reachable purely through a governance parameter update, matching the required "state divergence / acceptance of invalid transaction or block" class of impact (in this case, total inability to process blocks).

### Likelihood Explanation
Setting `GasTarget = 0` requires a governance vote, which is a privileged but explicitly in-scope action category ("governance parameters"). The likelihood of accidental misconfiguration is non-trivial given there is no format-level guard (unlike the sibling `BaseFeeDenominator` parameter, which explicitly enforces `!= 0`), suggesting this omission is an inconsistency/oversight rather than an intentional design choice.

### Recommendation
Add a `FormatChecker` for `Kip71GasTarget` that rejects zero, consistent with `Kip71BaseFeeDenominator`:
```go
Kip71GasTarget: {
    Canonicalizer: uint64Canonicalizer,
    FormatChecker: func(cv any) bool {
        v, ok := cv.(uint64)
        return ok && v != 0
    },
    ...
}
```
Additionally, add a defensive zero-check inside `NextMagmaBlockBaseFee` (mirroring the existing `BaseFeeDenominator == 0` fallback) to prevent a panic even if an invalid value slips through via a hard-coded chain config rather than the governance vote path.

### Proof of Concept
1. Via governance vote (or a chain config with `Governance.KIP71.GasTarget = 0` after the Magma fork), set `Kip71GasTarget` to `0`. The `noopFormatChecker` at `kaiax/gov/param.go` accepts this value without error.
2. On the next non-empty block (`parentGasUsed > 0`), `NextMagmaBlockBaseFee` (`params/kip71_config.go:58`) is invoked during block base-fee verification/computation.
3. Since `parentGasUsed != gasTarget` (0), and `parentGasUsed > gasTarget`, execution reaches:
```go
gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget) // parentGasUsed
x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
y := x.Div(x, new(big.Int).SetUint64(gasTarget)) // big.Int.Div(x, 0) panics
```
4. The panic crashes the node process for every node processing this block, halting the network.
