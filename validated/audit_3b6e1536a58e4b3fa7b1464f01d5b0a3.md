## Title
Silent fund loss in IBC refund auto-conversion when ERC20 transfer step fails after coins are escrowed - (File: `x/erc20/keeper/ibc_callbacks.go`)

## Summary
This is the same "non-atomic multi-step delivery" bug class as the `OrderBook.collectFees` report: a function performs two dependent state mutations (escrow coins, then transfer ERC20 tokens) that must both succeed to preserve user value, but a revert in the second step does not roll back the first, and the caller swallows the resulting error. In Cosmos EVM's `x/erc20` IBC refund path, this results in a user's coins being pulled into the module account with no compensating ERC20 delivery and no recovery path, rather than merely a griefing/DoS as in the original report.

## Finding Description
When an IBC transfer of a native-ERC20-backed coin times out or receives an error acknowledgement, `OnTimeoutPacket`/`OnAcknowledgementPacket` call `ConvertCoinToERC20FromPacket`, which attempts to automatically convert the just-refunded bank coin back into its ERC20 representation via `ConvertCoinNativeERC20`: [1](#0-0) 

`ConvertCoinNativeERC20` performs two sequential, non-atomic operations against the live `sdk.Context` store:
1. `SendCoinsFromAccountToModule` — escrows the sender's coins into the `erc20` module account.
2. `CallEVM(... "transfer" ...)` — unescrows previously-locked ERC20 tokens and sends them to the receiver. [2](#0-1) 

If step 1 succeeds but step 2 fails (e.g. the ERC20 contract has self-destructed — explicitly called out in the function's own doc comment — is paused, reverts for the specific receiver, or otherwise fails the EVM call), `ConvertCoinNativeERC20` returns an error. However, `ConvertCoinToERC20FromPacket` catches that error, emits a telemetry/event log, and **returns `nil`** instead of propagating it: [3](#0-2) 

Because this whole call chain is invoked from IBC middleware packet-processing (not a top-level `Msg` handler under a discardable cache-context), swallowing the error does not undo the already-committed `SendCoinsFromAccountToModule` mutation. The net effect: the user's refunded coins are moved into the `erc20` module account, the ERC20 transfer never completes, and the function reports success. Contrary to the documented intent ("the user receives the corresponding bank token from the TokenPair instead"), the user receives neither the bank coin nor the ERC20 token — the value is stranded in the module account with no code path to reclaim it.

The same non-atomic escrow/EVM-call/burn sequence is safe only when invoked from the top-level `MsgServer.ConvertCoin` handler [4](#0-3) , because SDK message execution runs under a branch that is discarded on error. The IBC callback path deliberately breaks that safety net by masking the error.

## Impact Explanation
This matches the Critical "permanent freezing/locking/theft of user funds... across native balances... or token-pair-backed balances" impact category. A user's IBC-refunded coins are irreversibly transferred out of their control into the module account with no corresponding ERC20 credit and no compensating code path — a direct, irreversible loss of spendable value triggered through ordinary IBC packet lifecycle processing (timeout/error-ack), not through any privileged action.

## Likelihood Explanation
Reachable by any unprivileged user: any account holding a native-ERC20 token-pair coin who sends an IBC transfer that later times out or is denied (both are ordinary, attacker-influenceable outcomes — e.g., timing out a transfer to an unresponsive channel, or the counterparty chain rejecting it) will hit this path. The trigger conditions for step 2 failing (self-destructed contract, paused/blacklisting token, permissionlessly-registered malicious ERC20) are explicitly anticipated in the code's own comments, indicating this is a realistic, not merely theoretical, failure mode.

## Recommendation
`ConvertCoinNativeERC20` must be executed atomically with respect to its own escrow step: either wrap the escrow + EVM-transfer + burn sequence in a branched/cached context that is only committed on full success, or reorder operations so the destructive step (moving coins out of the user's account) happens only after the EVM transfer is confirmed to succeed. `ConvertCoinToERC20FromPacket` should not swallow errors that occurred after any state-mutating step has already executed; if it must not fail the packet ack/timeout handling, it should ensure the erroring `ConvertCoinNativeERC20` call itself is executed in a way that guarantees full rollback of its internal side effects before returning.

## Proof of Concept
1. Permissionlessly register (or via governance) a native ERC20 token pair for a malicious/fragile ERC20 contract that can be made to revert its `transfer` function (e.g., self-destructs itself, or reverts when called by the module for a chosen receiver).
2. Convert some of the ERC20 into the native coin representation via `MsgConvertERC20`, then send it out via ICS20 `MsgTransfer` to a channel/receiver arranged to fail (timeout or error ack).
3. When `OnTimeoutPacket`/`OnAcknowledgementPacket` fires, `ConvertCoinToERC20FromPacket` refunds the bank coin to the sender and then calls `ConvertCoinNativeERC20`, which escrows the coin into the `erc20` module account and then fails at the `CallEVM` transfer step (contract self-destructed/reverting).
4. The error is swallowed; the transaction/packet processing completes "successfully." The sender ends up with neither the bank coin nor the ERC20 token — verify via bank and ERC20 balance queries that the funds are stuck in the `erc20` module account.

// ConvertCoinToERC20FromPacket converts the IBC coin to ERC20 after refunding the sender
// This function is only executed when IBC timeout or an Error ACK happens.
func (k Keeper) ConvertCoinToERC20FromPacket(ctx sdk.Context, data transfertypes.FungibleTokenPacketData) error {
	// Sender is local (source) chain address; accept local bech32 or 0x-hex
	senderBz, err := k.addrCodec.StringToBytes(data.Sender)
	if err != nil {
		return err
	}
	sender := sdk.AccAddress(senderBz)

	pairID := k.GetTokenPairID(ctx, data.Denom)
	pair, found := k.GetTokenPair(ctx, pairID)
	if !found {
		// no-op, token pair is not registered
		return nil
	}

	coin := ibc.GetSentCoin(data.Denom, data.Amount)

	switch {

	// Case 1. if pair is native coin -> no-op
	case pair.IsNativeCoin():
		// no-op, received coin is a  native coin
		return nil

	// Case 2. if pair is native ERC20 -> unescrow
	case pair.IsNativeERC20():
		// use a zero gas config to avoid extra costs for the relayers
		ctx = ctx.
			WithKVGasConfig(storetypes.GasConfig{}).
			WithTransientKVGasConfig(storetypes.GasConfig{})

		params := k.GetParams(ctx)
		if !params.EnableErc20 || !k.IsDenomRegistered(ctx, coin.Denom) {
			// no-op, ERC20s are disabled or the denom is not registered
			return nil
		}

		// assume that all module accounts on Cosmos EVM need to have their tokens in the
		// IBC representation as opposed to ERC20
		senderAcc := k.accountKeeper.GetAccount(ctx, sender)
		if types.IsModuleAccount(senderAcc) {
			return nil
		}

		// Convert from Coin to ERC20
		if err := k.ConvertCoinNativeERC20(ctx, pair, coin.Amount, common.BytesToAddress(sender), sender); err != nil {
			// We want to record only the failed attempt to reconvert the coins during IBC.
			defer func() {
				telemetry.IncrCounter(1, types.ModuleName, "ibc", "error", "total")
			}()
			ctx.EventManager().EmitEvents(
				sdk.Events{
					sdk.NewEvent(
						types.EventTypeFailedConvertERC20,
						sdk.NewAttribute(types.AttributeCoinSourceChannel, pair.Denom),
						sdk.NewAttribute(types.AttributeKeyERC20Token, pair.Erc20Address),
						sdk.NewAttribute("error", err.Error()),
					),
				},
			)
			return nil
		}

func (k Keeper) ConvertCoin(
	goCtx context.Context,
	msg *types.MsgConvertCoin,
) (*types.MsgConvertCoinResponse, error) {
	ctx := sdk.UnwrapSDKContext(goCtx)

	// Error checked during msg validation
	sender := sdk.MustAccAddressFromBech32(msg.Sender)
	receiver := common.HexToAddress(msg.Receiver)

	pair, err := k.MintingEnabled(ctx, receiver.Bytes(), msg.Coin.Denom)
	if err != nil {
		return nil, err
	}

	// Check ownership and execute conversion
	switch {
	case pair.IsNativeERC20():
		// Remove token pair if contract is suicided
		acc := k.evmKeeper.GetAccountWithoutBalance(ctx, pair.GetERC20Contract())
		if acc == nil || !acc.HasCodeHash() {
			k.DeleteTokenPair(ctx, pair)
			k.Logger(ctx).Debug(
				"deleting selfdestructed token pair from state",
				"contract", pair.Erc20Address,
			)
			// NOTE: return nil error to persist the changes from the deletion
			return nil, nil
		}

		return nil, k.ConvertCoinNativeERC20(ctx, pair, msg.Coin.Amount, receiver, sender)
	case pair.IsNativeCoin():
		return nil, types.ErrNativeConversionDisabled
	}

	return nil, types.ErrUndefinedOwner
}
