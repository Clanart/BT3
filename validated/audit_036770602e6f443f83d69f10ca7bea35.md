### Title
Quadratic Lagrange interpolation DoS via oversized signing set - (File: crypto/dkg/src/lib.rs)

### Summary
`Interpolation::interpolation_factor` computes a Lagrange coefficient for a participant by iterating over the entire `included` set, performing field multiplications proportional to `|included|`. `ThresholdView` computes this factor for every participant in the set, so total work is O(|included|²). Because `included` is bounded only by `n` (a `u16`, up to 65,535), an untrusted party who supplies preprocesses for a large declared signing set can force ~4 billion field multiplications in a single `sign`/`verify` call — mirroring the "small input, amplified CPU burn" shape of the timespan ReDoS.

### Finding Description
In `crypto/frost/src/sign.rs`, `AlgorithmSignMachine::sign` builds `included` directly from the keys of the caller-supplied `preprocesses` map plus the local participant, then sorts and validates it:

```rust
let mut included = Vec::with_capacity(preprocesses.len() + 1);
included.push(multisig_params.i());
for l in preprocesses.keys() {
  included.push(*l);
}
included.sort_unstable();
``` [1](#0-0) 

The only upper bound is `included.last() <= multisig_params.n()`, where `n` is a `u16` (up to 65,535):

```rust
if u16::from(included[included.len() - 1]) > multisig_params.n() {
  Err(FrostError::InvalidParticipant(...))?;
}
``` [2](#0-1) 

`self.params.keys.view(included.clone())` is then invoked, which derives a `ThresholdView` by computing an interpolation factor per included participant. For `Interpolation::Lagrange`, `interpolation_factor` loops over all of `included` for each factor:

```rust
let mut num = F::ONE;
let mut denom = F::ONE;
for l in included {
  if i == *l { continue; }
  let share = F::from(u64::from(u16::from(*l)));
  num *= share;
``` [3](#0-2) 

So `view()` costs O(k²) scalar multiplications (plus an inversion per participant), with k = |included| up to 65,535. There is no cap on the preprocess-map cardinality other than the valid `Participant` index space, so a peer can send a `HashMap<Participant, Preprocess>` with tens of thousands of entries — each serialized `Preprocess` is only ~64–128 bytes of `Commitments` — and cause quadratic work in a synchronous `sign` call.

### Impact Explanation
A FROST signing call on a large participant set becomes a multi-minute CPU-bound operation. ~65,535² ≈ 4.3×10⁹ field multiplications plus 65,535 field inversions are performed on the calling thread before any share is produced. In a threshold network where participants forward preprocess messages to each other, an unauthenticated/unprivileged party that can inject preprocesses (or simply a set of 65,535 Sybil-controlled participant indexes' worth of commitment bytes, each only ~128 B → total input ~8 MB) can stall honest validators' signing loops, delaying or preventing block/tributary progress — an availability loss directly analogous to the referenced ReDoS advisory.

### Likelihood Explanation
Reachable through the documented public-input surface: `read_preprocess` deserializes `Commitments` from peer bytes and `sign(preprocesses, msg)` accepts the map directly. The check that would normally bound k (`included.last() <= n`) permits up to `n`, and `n` itself can be as large as `u16::MAX` in `ThresholdParams`. The cost is quadratic in attacker-controlled input size, matching the advisory's amplification profile; no secret material or validator privilege is needed.

### Recommendation
Cap the signing-set size accepted by `sign`/`verify` to a protocol-sane bound (e.g., the configured `n` of the actual multisig, and a hard ceiling on `ThresholdParams::n`), and/or replace per-participant O(k) Lagrange evaluation with an O(k log k) product-tree/barycentric formulation so cost scales near-linearly with input size.

### Proof of Concept
```rust
// Conceptual: honest signer with ThresholdParams { t: 2, n: u16::MAX, i }
// Attacker submits a preprocesses map keyed by Participant 2..=65535
// each with a minimal Commitments payload (~64 bytes of compressed points).
let mut preprocesses = HashMap::new();
for l in 2u16 ..= u16::MAX {
  let mut bytes = vec![0u8; 64]; // well-formed Commitments encoding
  preprocesses.insert(
    Participant::new(l).unwrap(),
    machine.read_preprocess(&mut bytes.as_slice()).unwrap(),
  );
}
// Triggers ~65k² scalar muls + 65k inversions in keys.view(included):
machine.sign(preprocesses, b"msg").unwrap_err();
```
