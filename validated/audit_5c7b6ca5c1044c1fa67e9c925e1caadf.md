### Title
Forged blame attribution: PoP `sender` binding is attacker-controlled, letting an accuser frame an honest participant - (File: crypto/dkg/pedpop/src/encryption.rs)

### Summary
CVE-2018-8801 is an SSRF: an unprivileged user supplies attacker-controlled "destination" input that a trusted internal component then acts on with its own authority. The Serai analog is the DKG blame flow: `CoordinatorMessage::VerifyBlame` lets any party submit arbitrary `accuser`/`accused`/`share`/`blame` bytes, and the processor makes its internal `AdditionalBlameMachine` authenticate and decrypt those bytes to decide which participant is fatally blamed. The proof-of-possession on `EncryptedMessage` binds a `sender` index into the Schnorr challenge, but the `sender` is just a transcript field chosen by whoever generates the per-message key — it provides no authentication. An accuser can therefore fabricate a message "from" an honest accused, and the blame machine will attribute fault to the accused.

### Finding Description
In `processor/src/key_gen.rs` (`CoordinatorMessage::VerifyBlame`, lines 504–563), the `share` bytes are taken directly from the coordinator message, parsed by `EncryptedMessage::<C, SecretShare<C::F>>::read`, and handed to `AdditionalBlameMachine::blame(accuser, accused, share, blame)` along with the caller-chosen `accuser`/`accused` indices. Unlike the commitments, which are re-read from `CommitmentsDb`, the share is not compared against anything previously stored or authenticated as the accused's message.

Inside `blame_internal` (`crypto/dkg/pedpop/src/lib.rs:575-609`), the only sender authentication is `msg.pop.verify(msg.key, pop_challenge(context, R, msg.key, from=accused, msg))` in `decrypt_with_proof` (`crypto/dkg/pedpop/src/encryption.rs:374-379`). `pop_challenge` (`encryption.rs:302-324`) appends `sender` as a plain transcript field; the signature itself is produced under `msg.key`, a per-message key generated by whoever built the ciphertext (`encrypt`, `encryption.rs:151-167`). Nothing ties `msg.key` to the claimed `sender`'s registered encryption key — `Encryption::encrypt` uses `self.decryption.enc_keys[&participant]` (the *recipient's* key), while `msg.key` is a fresh scalar known only to the actual encryptor. So a Schnorr PoP under an attacker-generated `msg.key` with `sender = accused` verifies cleanly.

The accuser then supplies a blame `EncryptionKeyProof` proving `proof.key = enc_scalar_accuser * msg.key` (DLEq verified at `encryption.rs:383-390`), which decrypts the fabricated ciphertext. By encrypting a non-canonical or invalid scalar, `blame_internal` reaches "the share was canonical and valid... else sender is faulty" and returns `accused` — the processor emits `ProcessorMessage::Blame { participant: accused }` and the honest party is slashed.

### Impact Explanation
The trusted blame arbiter is induced to act on attacker-fabricated input and produce a wrong, security-relevant verdict: an honest DKG participant is marked faulty. In Serai this verdict feeds fatal slashing, so an unprivileged accuser can get an honest validator blamed and slashed for a share that participant never sent — an integrity attack on the DKG's accountability mechanism (CVSS C:H class analog: unauthorized action by an internal component).

### Likelihood Explanation
Reachable by any party able to submit `VerifyBlame` to the processor. The attack requires only generating a fresh scalar for `msg.key`, signing a Schnorr PoP with `sender = accused`, encrypting arbitrary bytes to the accuser's own registered encryption key, and producing a valid DLEq for the ECDH shared key — all computable by the accuser alone. The only mitigation is the documented requirement that messages be authenticated by an external channel; the processor's `VerifyBlame` handler performs no such check on the `share` bytes it is given, treating `pop`'s `sender` binding as if it authenticated the origin.

### Recommendation
When handling `VerifyBlame`, do not trust caller-supplied `share`/`blame` bytes as the accused's message. Persist the per-participant share messages received during `CoordinatorMessage::Shares` (keyed by sender/recipient, as `CommitmentsDb` does for commitments) and have `VerifyBlame` look up the stored message for `(accused, accuser)` instead of accepting new bytes. Alternatively, require the blame submission to include evidence authenticating the share as the accused's (e.g., a signature under the accused's registered encryption/commitment key binding the ciphertext hash), and treat an unauthenticated share as blame on the accuser.

### Proof of Concept
```
// Attacker = participant A (accuser); victim = participant B (accused).
// 1. Run DKG honestly; A registers its real EncryptionKeyMessage.

// 2. Fabricate a "share from B to A" that B never sent:
let fake_scalar = Zeroizing::new(C::random_nonzero_F(&mut rng));
let msg_key_pt = C::generator() * fake_scalar.deref();
let nonce = Zeroizing::new(C::random_nonzero_F(&mut rng));
let mut bad_msg: SecretShare<C::F> = /* 32 bytes of 0xFF (non-canonical) */;
// Encrypt to A's own registered enc key so A can later prove the ECDH key:
cipher::<C>(CONTEXT, &ecdh::<C>(&fake_scalar, enc_keys[&A]))
  .apply_keystream(bad_msg.as_mut().as_mut());
let forged = EncryptedMessage {
  key: msg_key_pt,
  // PoP signs with sender = B — nothing verifies this index:
  pop: SchnorrSignature::sign(
    &fake_scalar, nonce,
    pop_challenge::<C>(CONTEXT, C::generator() * nonce.deref(),
                       msg_key_pt, B /* accused */, bad_msg.as_ref())),
  msg: Zeroizing::new(bad_msg),
};

// 3. Build blame proof with A's *own* enc_key scalar (DLEq verifies):
let proof = EncryptionKeyProof {
  key: ecdh::<C>(&A_enc_key, msg_key_pt),
  dleq: DLEqProof::prove(&mut rng,
    &mut encryption_key_transcript(CONTEXT),
    &[C::generator(), msg_key_pt], &A_enc_key),
};

// 4. VerifyBlame path:
//    blame_internal(sender=B, recipient=A, forged, Some(proof))
//      - pop.verify passes (sender index is attacker-chosen)
//      - DLEq verify passes -> decrypts to 0xFF.. bytes
//      - C::F::from_repr fails -> returns sender = B
//    => ProcessorMessage::Blame { participant: B } — honest B is slashed.
```
