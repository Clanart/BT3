### Title
Unbounded atom-length pointer advance in CLVM canonicality check causes out-of-bounds read / unhandled exception - ([File: chia/full_node/mempool_manager.py])

### Summary
`is_clvm_canonical()` and its helper `is_atom_canonical()` in `chia/full_node/mempool_manager.py` walk a CLVM-serialized buffer using an `offset` that is advanced purely from length fields decoded out of the *same* attacker-controlled buffer, without ever verifying that `offset` (or `offset + atom_len`) stays within `len(clvm_buffer)`. This mirrors the DjVuLibre `MMRDecoder::scanruns` bug class, where a decoding pointer (`xr`/`pr`) is advanced from data-derived values without a bounds check, leading to out-of-bounds access.

### Finding Description
`is_atom_canonical` reads the length-prefix bytes of an atom directly from `clvm_buffer[offset]` in a loop keyed off `prefix_len` (up to 5 extra bytes) with no check that those bytes exist in the buffer: [1](#0-0) 

It then returns `1 + prefix_len + atom_len` — the total on-wire size of the atom — to the caller, `is_clvm_canonical`, which unconditionally advances its own `offset` by that value and loops back to dereference `clvm_buffer[offset]` again, again with no bounds check: [2](#0-1) 

Neither function validates that:
1. There are enough bytes left in the buffer to read the multi-byte length prefix (`atom_len` computation loop can walk past the end of `clvm_buffer`), or
2. The attacker-controlled `atom_len` value, once decoded, does not push `offset` past `len(clvm_buffer)` before the next `clvm_buffer[offset]` dereference.

Because Python raises `IndexError` on out-of-bounds `bytes` indexing rather than corrupting memory, this is not a memory-safety bug in the C sense, but it is the direct analog of the reported bug class: an attacker-controlled "pointer" (`offset`) is advanced strictly from untrusted length fields in the buffer being decoded, with no bounds validation before the next dereference — exactly the missing-bounds-check pattern that made `MMRDecoder::scanruns` exploitable in DjVuLibre.

### Impact Explanation
If `is_clvm_canonical` (or `is_atom_canonical`) is invoked on attacker-supplied puzzle-reveal/solution bytes from a submitted spend bundle without the caller catching `IndexError`, a single truncated/malformed CLVM buffer can raise an unhandled exception during spend-bundle intake, terminating that transaction-processing code path unexpectedly. This falls in the "spend-triggered transaction-processing halt" impact category.

### Likelihood Explanation
The function operates on byte buffers whose origin is the CLVM serialization of a puzzle reveal / solution, which is fully attacker-controlled content in a submitted spend bundle. Constructing a truncated/malformed atom-length prefix or an oversized atom length is trivial (single crafted byte string), making the trigger low-effort for anyone able to submit a spend bundle.

### Recommendation
Add explicit bounds checks in both `is_atom_canonical` and `is_clvm_canonical`:
- Before reading each length-prefix byte in `is_atom_canonical`, verify `offset < len(clvm_buffer)`.
- After computing `atom_len`, verify `offset + atom_len <= len(clvm_buffer)` before returning, and have `is_clvm_canonical` treat any violation as "not canonical" (return `False`) rather than letting the next iteration dereference an out-of-range index.
- Alternatively, wrap all buffer indexing in these functions with `try/except IndexError: return False` so malformed input never propagates an unhandled exception into mempool admission.

### Proof of Concept
A minimal malformed buffer that triggers the bug: a single byte such as `0xC0` (5+8-bit length prefix marker, i.e. `prefix_len = 1`) with no following byte. Calling:
```python
is_clvm_canonical(b"\xc0")
```
causes `is_atom_canonical` to execute `offset += 1; atom_len |= clvm_buffer[offset]` with `offset == 1`, which is out of range for a 1-byte buffer, raising `IndexError` instead of returning `False`. A similarly malformed buffer with a valid short length prefix but an `atom_len` value larger than the remaining buffer (e.g. `b"\xc0\xff"`, claiming a huge atom) causes `offset` to be advanced past the buffer end in `is_clvm_canonical`'s main loop, raising `IndexError` on the next `clvm_buffer[offset]` read. def is_atom_canonical(clvm_buffer: bytes, offset: int) -> tuple[int, bool]:
    b = clvm_buffer[offset]
    if (b & 0b11000000) == 0b10000000:
        # 6 bits length prefix
        mask = 0b00111111
        prefix_len = 0
        min_value = 1
    elif (b & 0b11100000) == 0b11000000:
        # 5 + 8 bits length prefix
        mask = 0b00011111
        prefix_len = 1
        min_value = 1 << 6
    elif (b & 0b11110000) == 0b11100000:
        # 4 + 8 + 8 bits length prefix
        mask = 0b00001111
        prefix_len = 2
        min_value = 1 << (5 + 8)
    elif (b & 0b11111000) == 0b11110000:
        # 3 + 8 + 8 + 8 bits length prefix
        mask = 0b00000111
        prefix_len = 3
        min_value = 1 << (4 + 8 + 8)
    elif (b & 0b11111100) == 0b11111000:
        # 2 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000011
        prefix_len = 4
        min_value = 1 << (3 + 8 + 8 + 8)
    elif (b & 0b11111110) == 0b11111100:
        # 1 + 8 + 8 + 8 + 8 + 8 bits length prefix
        mask = 0b00000001
        prefix_len = 5
        min_value = 1 << (2 + 8 + 8 + 8 + 8)

    atom_len = b & mask
    for i in range(prefix_len):
        atom_len <<= 8
        offset += 1
        atom_len |= clvm_buffer[offset]

    return 1 + prefix_len + atom_len, atom_len >= min_value


def is_clvm_canonical(clvm_buffer: bytes) -> bool:
    """
    checks whether the CLVM serialization is all canonical representation.
    atoms can be serialized in more than one way by using more bytes than
    necessary to encode the length prefix. This functions ensures that all atoms are
    encoded with the shortest representation. back-references are not allowed
    and will make this function return false
    """
    assert clvm_buffer != b""

    offset = 0
    tokens_left = 1
    while True:
        b = clvm_buffer[offset]

        # pair
        if b == 0xFF:
            tokens_left += 1
            offset += 1
            continue

        # back references cannot be considered canonical, since they may be
        # encoded in many different ways
        if b == 0xFE:
            return False

        # small atom or NIL
        if b <= 0x80:
            tokens_left -= 1
            offset += 1
        else:
            atom_len, canonical = is_atom_canonical(clvm_buffer, offset)
            if not canonical:
                return False
            tokens_left -= 1
            offset += atom_len

        if tokens_left == 0:
            break

    # if there's garbage at the end, it's not canonical
    return offset == len(clvm_buffer)
