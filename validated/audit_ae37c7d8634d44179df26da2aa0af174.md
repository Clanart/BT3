## Title
`_calExpireForfeit` in `mWOMSVBaseRewarder` never forfeits rewards due to a self-comparison bug, permanently freezing forfeited yield owed to other lockers - (File: `rewards/mWOMSVBaseRewarder.sol`)

### Summary
`mWOMSVBaseRewarder._calExpireForfeit` is supposed to reduce a claiming user's reward by a "forfeit" percentage based on their mWOMSV lock status, exactly as the sibling contract `vlMGPBaseRewarder` does. Instead, it assigns `rewardableAmount = _amount` and then checks `rewardableAmount > _amount`, a condition against a value identical to itself, so `forfeitAmount` is always `0`. This is the same bug class as the reported `MegaThetaVault.depositForOwner` issue (comparing a variable to the value it was just assigned from, rendering the check useless).

### Finding Description
In `vlMGPBaseRewarder.sol`, the forfeit calculation correctly derives `rewardableAmount` from an independent source, the locker's rewardable percentage: [1](#0-0) 

In `mWOMSVBaseRewarder.sol`, the equivalent function never queries `mWOMSV.getRewardablePercentWAD(_account)` (which exists on the `mWomSV`/`ILocker` interface, as referenced elsewhere in the codebase). It instead sets `rewardableAmount` equal to `_amount` and compares it to itself: [2](#0-1) 

Because `rewardableAmount == _amount` always holds, `forfeitAmount = _amount - rewardableAmount` is always `0`. This function is invoked on every unprivileged claim path: [3](#0-2) [4](#0-3) 

which is itself reachable by any ordinary wallet through `MasterMagpie`'s claim/harvest flow (`_claimBaseRewarder` → `rewarder.getReward`/`getRewards`): [5](#0-4) 

### Impact Explanation
The mWOMSV forfeit mechanism exists to redistribute a portion of rewards from users whose lock has expired/is non-compliant back into the reward pool (`_queueNewRewardsWithoutTransfer`) for the benefit of remaining, correctly-locked stakers: [6](#0-5) 
Since `forfeitAmount` can never be non-zero, this redistribution never occurs: every claiming account, regardless of their actual lock/expiry status, receives 100% of their accrued reward. The yield that should have been forfeited and re-queued to honest, correctly-locked stakers is permanently and unconditionally routed away from them instead, i.e., a permanent freezing/loss of unclaimed yield that legitimate lockers are entitled to under the protocol's own reward design.

### Likelihood Explanation
This triggers on every single reward claim by any unprivileged wallet holding mWOMSV and accruing rewards through `mWOMSVBaseRewarder` — no special conditions, timing, or privileged role are required; the bug is unconditionally hit on the standard user claim path (`getReward`/`getRewards` → `_sendReward` → `_calExpireForfeit`).

### Recommendation
Update `_calExpireForfeit` in `mWOMSVBaseRewarder.sol` to mirror `vlMGPBaseRewarder.sol`'s logic — query the actual rewardable percentage from the `mWOMSV` locker (e.g., `mWOMSV.getRewardablePercentWAD(_account)`) and compute `rewardableAmount = _amount * rewardablePercentWAD / 1e18` before comparing, so the forfeit sanity check and resulting `forfeitAmount` are meaningful.

### Proof of Concept
1. A user's mWOMSV lock becomes expired/non-compliant such that they should only be entitled to a reduced percentage of pending rewards.
2. The user calls `getReward(account, receiver)` on `mWOMSVBaseRewarder`, reachable indirectly via `MasterMagpie` harvest functions.
3. Internally, `_sendReward` calls `_calExpireForfeit(_account, userRewards[_rewardToken][_account])`.
4. Inside `_calExpireForfeit`, `rewardableAmount` is set to `_amount` (line 386) and then compared to `_amount` (line 387) — always false — so `forfeitAmount = _amount - rewardableAmount = 0` (line 390) regardless of the user's real lock status.
5. The user receives their entire reward (`toSend = userRewards - 0`), and no forfeited amount is ever queued back via `_queueNewRewardsWithoutTransfer`, permanently denying that yield to compliant lockers.

```text
    function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
        uint256 rewardablePercentWAD = vlMGP.getRewardablePercentWAD(_account);
        uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
        if (rewardableAmount > _amount)
            revert InvalidRewardableAmount();

        uint256 forfeitAmount = _amount - rewardableAmount;
        
        if (forfeitAmount < (_amount / 1000)) {  // if forfeitAmount is smaller than 0.1% ignore to save gas fee
            forfeitAmount = 0;
            rewardableAmount = _amount;
        }

        return forfeitAmount;
    }
```

```text
    {
        Reward storage rewardInfo = rewards[_rewardToken];
        rewardInfo.historicalRewards = rewardInfo.historicalRewards + _amountReward;
        if (totalStaked() == 0) {
            rewardInfo.queuedRewards += _amountReward;

            if (rewardInfo.queuedRewards > 0) {
                _amountReward += rewardInfo.queuedRewards;
                rewardInfo.queuedRewards = 0;

            rewardInfo.rewardPerTokenStored =
                rewardInfo.rewardPerTokenStored +
                (_amountReward * 10**mWOMSVDecimal) / totalStaked();

        emit ForfeitRewardAdded(_amountReward, _rewardToken);
    }
```
