### Title
Static Cosmos precompiles decode attacker-controlled ABI calldata without the string-copy decode-cost gas charge, allowing superlinear memory allocation - ([File: precompiles/common/precompiles.go])

### Summary
The RMI advisory's root cause is that a payload reader bounds the number of context entries but not the aggregate size of the strings read from those entries, so an attacker can inflate memory usage far beyond what the entry count would suggest. The sei-chain codebase has an almost identical bug class in the ABI-decoding of Cosmos precompile calldata: Go's `abi.Arguments.Unpack` can copy a `string` payload once per array/tuple slot that references it via an offset, so a small calldata buffer with many offsets aliased to one shared string produces `O(k*s)` decode-time memory/CPU from `O(k+s)` bytes of input, as documented in `precompiles/common/decode_cost.go`.

### Finding Description
sei-chain fixed this exact amplification for `DynamicGasPrecompile.RunAndCalculateGas` by adding `chargeDecodeGas`, which computes `DecodeGasCost` (which walks the ABI structure and sums the string-copy bytes a real `Unpack` would produce) and charges gas for it *before* calling `method.Inputs.Unpack`: [1](#0-0) 

That gas cost model exists specifically because "a single string can be referenced by many array/tuple slots" and the copied volume "can be super-linear in len(input) (worst case ~len(input)^2)": [2](#0-1) 

However, the static (non-dynamic-gas) `Precompile.Prepare`/`Run` path used by most Cosmos precompiles (`bank`, `addr`, `oracle`, `distribution`, `wasmd`, `params`, `auth`, `authz`, `json`, `staking`, etc.) has no equivalent protection: `RequiredGas` is computed once from `input` (typically a simple `GasCostPerByte * len(input)` linear charge, e.g. `precompiles/json/legacy/v606/json.go:65-67`), and then `Prepare` calls `method.Inputs.Unpack(argsBz)` directly with no additional gas charge tied to the actual decode cost: [3](#0-2) 

Because `RequiredGas` is paid by the EVM's precompile dispatch (`vm.RunPrecompiledContract`) based only on `len(input)`, and `Unpack`'s real cost can be quadratic via aliased array/tuple offsets pointing at one shared string, an attacker can submit calldata to any static precompile method that has a `string`, `string[]`, or `tuple`/`tuple[]`-with-string argument (e.g. wasmd's `executeBatch((string,bytes,bytes)[])`, referenced in `precompiles/common/decode_cost_test.go:51-58`) and force the JVM-equivalent here — the validator's EVM execution goroutine — to allocate and copy far more memory than the gas charged for the input size would suggest, while still fitting under the EVM per-tx gas/calldata limits that were priced for a linear decode.

### Impact Explanation
An unprivileged EVM caller can invoke any static precompile whose ABI includes a dynamic string-in-array/tuple parameter with crafted, aliased offsets. This causes the node to allocate/copy memory proportional to `k*s` (offsets × shared string length) rather than the `O(input length)` amount the fixed per-byte `RequiredGas` charges for. Because this happens during ordinary transaction execution (not just RPC estimation), a wave of such transactions can drive excessive memory allocation and GC pressure across all validators executing the block, risking node slow-down/instability and potentially delaying block production — a resource-exhaustion / denial-of-service impact consistent with the CWE-400 classification of the source advisory.

### Likelihood Explanation
High for any static precompile method with a `string` field nested in a dynamic array or tuple: the calldata is fully attacker-controlled, requires no special permissions beyond submitting an EVM transaction, and the aliasing technique (multiple array/tuple offsets pointing to one shared string payload) is exactly the technique sei-chain's own test suite already demonstrates works against the ABI decoder (`precompiles/common/decode_cost_test.go` "Aliased" tests), confirming the underlying decoder behavior is real and exploitable. The only mitigating factor is that this must be verified per-precompile: precompiles whose ABI has no string-bearing dynamic array/tuple argument are not affected, and I was not able to fully verify from the index whether `wasmd`'s `executeBatch` (or other qualifying methods) is wired through the static `Precompile` path versus the protected `DynamicGasPrecompile` path — that requires reading `precompiles/wasmd/wasmd.go`'s `NewPrecompile` call directly.

### Recommendation
Apply the same `chargeDecodeGas`/`DecodeGasCost` pre-charge used in `DynamicGasPrecompile.RunAndCalculateGas` to the static `Precompile.Prepare` path in `precompiles/common/precompiles.go`, so that every precompile — not just dynamic-gas ones — charges gas proportional to the ABI decoder's real string-copy cost before calling `method.Inputs.Unpack`. Alternatively, audit every static precompile method for `string`-bearing dynamic array/tuple parameters and either migrate them to `DynamicGasPrecompile` or add a bound on the total decoded string bytes relative to the charged `RequiredGas`.

### Proof of Concept
1. Identify a static-precompile ABI method (registered via `NewPrecompile`, not `NewDynamicGasPrecompile`) with a `string`, `string[]`, or tuple-array-with-string parameter — e.g. the `(string,bytes,bytes)[]` shape referenced in `precompiles/common/decode_cost_test.go:51-58`.
2. Craft calldata analogous to `craftAliasedVoteWeightedArgs`/`newAliasedVoteWeightedArgs` (`precompiles/gov/gov_test.go:1268-1282`, `precompiles/common/decode_cost_test.go:145-165`): build `k` array/tuple head offsets that all point at the same shared string of length `s`, keeping total calldata near `32*k + s` bytes.
3. Submit this as an EVM transaction calling the static precompile method. Because `RequiredGas` only charges `GasCostPerByte * len(input)` (linear in `32*k+s`), the gas cost stays low while `method.Inputs.Unpack` inside `Precompile.Prepare` performs `k` copies of the `s`-byte string, consuming `O(k*s)` memory — reproducing the same "small on-wire size, large decoded allocation" pattern the gov precompile test (`TestVoteWeightedAliasedOptionsRejectedBeforeUnpack`, `precompiles/gov/gov_test.go:1220-1266`) was written to prevent for the dynamic-gas path, but for which no equivalent test/guard exists on the static path. func (p Precompile) RequiredGas(input []byte) uint64 {
	methodID, err := ExtractMethodID(input)
	if err != nil {
		return UnknownMethodCallGas
	}

	method, err := p.MethodById(methodID)
	if err != nil {
		// This should never happen since this method is going to fail during Run
		return UnknownMethodCallGas
	}
	return p.executor.RequiredGas(input[4:], method)
}

func (p Precompile) Run(evm *vm.EVM, caller common.Address, callingContract common.Address, input []byte, value *big.Int, readOnly bool, isFromDelegateCall bool, hooks *tracing.Hooks) (bz []byte, err error) {
	operation := fmt.Sprintf("%s_unknown", p.name)
	defer func() {
		HandlePrecompileError(err, evm, operation)
		if err != nil {
			err = vm.ErrExecutionReverted
		}
	}()
	ctx, method, args, err := p.Prepare(evm, input)
	if err != nil {
		return nil, err
	}

	operation = method.Name
	em := ctx.EventManager()
	ctx = ctx.WithEventManager(sdk.NewEventManager())
	ctx = ctx.WithEVMPrecompileCalledFromDelegateCall(isFromDelegateCall)
	bz, err = p.executor.Execute(ctx, method, caller, callingContract, args, value, readOnly, evm, hooks)
	if err != nil {
		return bz, err
	}
	events := ctx.EventManager().Events()
	if len(events) > 0 {
		em.EmitEvents(ctx.EventManager().Events())
	}
	return bz, err
}

func HandlePrecompileError(err error, evm *vm.EVM, operation string) {
	if err != nil {
		if sdb := state.GetDBImpl(evm.StateDB); sdb != nil {
			sdb.SetPrecompileError(err)
		}
		metrics.IncrementErrorMetrics(operation, err)
	}
}

func (p Precompile) Prepare(evm *vm.EVM, input []byte) (sdk.Context, *abi.Method, []interface{}, error) {
	ctxer := state.GetDBImpl(evm.StateDB)
	if ctxer == nil {
		return sdk.Context{}, nil, nil, errors.New("cannot get context from EVM")
	}
	methodID, err := ExtractMethodID(input)
	if err != nil {
		return sdk.Context{}, nil, nil, err
	}
	method, err := p.MethodById(methodID)
	if err != nil {
		return sdk.Context{}, nil, nil, err
	}

	argsBz := input[4:]
	args, err := method.Inputs.Unpack(argsBz)
	if err != nil {
		return sdk.Context{}, nil, nil, err
	}

	return ctxer.Ctx(), method, args, nil
}

// The Go ABI decoder's cost is dominated by copying `string` payloads: it
// materializes each string via string(output[begin:end]), and because a single
// string can be referenced by many array/tuple slots, the copied volume can be
// super-linear in len(input) (worst case ~len(input)^2). `bytes` values are
// excluded because the decoder reslices them without copying. The charge is
// therefore a linear pass over the input (DefaultGasCost) plus the string-copy
// volume the decoder would produce, priced at the KV read-per-byte rate.
