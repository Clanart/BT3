### Title
`CallDispatcher.dispatch()` has no access control, allowing anyone to drain in-flight or stranded order funds from the shared IntentGatewayV2 dispatcher - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
`IntentGatewayV2`/`IntentsBase` route all order calldata execution (predispatch assets and output calldata) through a single shared `CallDispatcher` contract referenced by `_params.dispatcher` [1](#0-0) . `CallDispatcher.dispatch()` is a public, unauthenticated `external` function with no caller restriction (no `onlyGateway`/owner check), executing arbitrary `Call[]` on behalf of the dispatcher's own identity [2](#0-1) . This mirrors the reported Uniswap-v4 `PoolManager` flaw: a shared custody contract that moves funds via generic `take`/execute primitives with no binding to "whose funds these are," letting any unprivileged (including sanctioned) caller extract value that was only ever meant to be swept by the gateway itself.

### Finding Description
The gateway pushes order assets (predispatch inputs, or output-call assets) directly to the `CallDispatcher`, invokes arbitrary attacker/solver-supplied calldata via `dispatch()`, and then sweeps back only the token addresses it explicitly knows about — `order.inputs[i].token` for predispatch and `order.output.assets[i].token` for `_execute` — using a balance-based sweep (`IERC20(token).balanceOf(dispatcher)`) rather than a delta/accounting-based transfer [3](#0-2) [4](#0-3) .

Any token or ETH that lands on the dispatcher outside of that enumerated set (e.g., a swap-reward/cashback token from a DEX call executed via the attacker-controlled `predispatch.call`/`output.call`, dust from a reverted/partial sweep path, or plain accidental transfers/`selfdestruct` ETH) is never retrieved by the gateway's own logic and remains stranded on the `CallDispatcher`. Because `CallDispatcher.dispatch()` has zero access control, **any address** can call it directly and issue `Call{to: token, data: transfer(attacker, balance)}` to sweep out that residual balance — completely bypassing the protocol's own governance-gated dust-collection path (`_sweepDust`, reachable only via Hyperbridge governance `onAccept`) [5](#0-4) .

This breaks the same invariant the external report flags: a shared custody/execution primitive (`PoolManager.unlock`/`take`/`settle` there, `CallDispatcher.dispatch` here) that does not authenticate the caller or bind moved value to a specific owner, letting unrelated/unprivileged parties extract funds that transiently or residually sit in the shared contract.

### Impact Explanation
Funds that should ultimately belong to the protocol treasury (governance-swept dust) or to legitimate order participants (any token that ends up on the dispatcher due to attacker/solver-chosen `predispatch.call`/`output.call` execution but isn't enumerated in `order.inputs`/`order.output.assets`) can be permanently stolen by any unprivileged caller, satisfying "stealing or loss of funds" / "unauthorized execution" under the bounty scope. Because the dispatcher is a single shared contract used by every order across every user, this is not scoped to one victim — any stranded balance from any order is up for grabs by anyone monitoring the contract.

### Likelihood Explanation
Exploitation requires no privileged role, relayer, prover, or governance actor — a plain EOA can call `CallDispatcher.dispatch()` directly at any time. The main precondition is that some balance is left on the dispatcher outside the enumerated sweep set, which is plausible whenever `predispatch.call`/`output.call` (attacker/solver-controlled calldata) triggers execution paths that produce tokens/ETH not present in `order.inputs`/`order.output.assets` (rebates, referral rewards, refunds from an intermediate protocol call, or partial-sweep failures). This does not require racing another user's transaction — the dust simply sits there post-transaction as ordinary contract state, indefinitely exploitable.

### Recommendation
Restrict `CallDispatcher.dispatch()` to be callable only by the registered `IntentGatewayV2` (or an explicit allow-list of authorized gateway instances), and additionally ensure the gateway sweeps the *complete* set of tokens the arbitrary calldata could plausibly produce, or use a fresh, single-use dispatcher/proxy per order (deployed and destroyed atomically) instead of one long-lived shared contract, so no cross-order residual balance can ever accumulate for an unauthenticated party to claim.

### Proof of Concept
1. Observe that `evm/src/utils/CallDispatcher.sol` deploys once and is reused as `_params.dispatcher` for every order processed by `IntentGatewayV2`/`IntentsBase` [6](#0-5) .
2. A solver crafts `order.output.call` (or a user crafts `order.predispatch.call`) that, when dispatched, causes the dispatcher to receive some token `X` not listed among `order.output.assets`/`order.inputs` (e.g., a DEX referral/rebate token, or a token accidentally sent by a downstream contract call).
3. `_execute`/predispatch-sweep only sweeps tokens explicitly enumerated in the order struct, so token `X`'s balance remains on the `CallDispatcher` after the transaction completes [7](#0-6) .
4. Any third party (attacker) directly calls:
   `CallDispatcher.dispatch(abi.encode([Call({to: X, value: 0, data: abi.encodeWithSelector(IERC20.transfer.selector, attacker, IERC20(X).balanceOf(dispatcher))})]))`
   This succeeds because `dispatch()` has no caller check [8](#0-7) , transferring the stranded balance straight to the attacker, bypassing the governance-only `_sweepDust` path entirely.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }
