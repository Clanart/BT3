Based on my investigation, the DataLayer mirror/subscription mechanism is a genuine SSRF analog reachable by a spend-bundle-submitting attacker.

### Title
DataLayer mirror-coin URLs are fetched without validating against private/loopback/internal addresses, enabling SSRF against DataLayer-enabled nodes - (File: chia/data_layer/download_data.py)

### Summary
Any user can create a "mirror coin" on-chain via `create_mirror_puzzle()` that embeds an arbitrary URL in its memos [1](#0-0) . DataLayer nodes that subscribe to (or own) the corresponding store read that URL from chain state and automatically issue outbound HTTP GET requests to it via `http_download()`/`download_file()` with no restriction on target host [2](#0-1) [3](#0-2) , matching the MoviePilot bug class: URLs are only checked for filename/domain shape, never for whether they resolve to loopback/private/link-local addresses.

### Finding Description
`get_mirror_info()` extracts the launcher id and one or more raw URL strings straight from a `CREATE_COIN` condition's memos when a mirror coin is created, with no validation of scheme or host at all [4](#0-3) . Creating a mirror coin only requires spending a coin into `MIRROR_PUZZLE_HASH` (`create_mirror_puzzle()` = `P2_PARENT.curry(1)`) with the desired URLs as memos — this is available to `add_mirror` RPC/wallet flow and is not restricted to store owners [5](#0-4) . These mirror URLs subsequently populate the server list used by `DataLayer.fetch_and_validate()`, which shuffles `servers_info` and issues delta-file downloads against them via `insert_from_delta_file()` [6](#0-5) . The actual network fetch, `http_download()`, does a plain `aiohttp` GET against `server_info.url + "/" + filename` with only a proxy/timeout/size guard — no check that the resolved host isn't `127.0.0.1`, `169.254.169.254`, an RFC1918 address, etc. [7](#0-6) . This is exactly the flaw pattern from the MoviePilot report: URL "allowlist"/shape checking (here, just being a coin-embedded string with no host restriction at all) substituting for real SSRF protection.

### Impact Explanation
A remote, unprivileged actor who can submit a spend bundle creating a mirror coin (or who controls a DataLayer store's mirror list) can force any DataLayer-enabled node that subscribes to that store to make outbound HTTP requests to attacker-chosen internal endpoints — e.g., cloud metadata services, internal admin panels, or other loopback-bound RPC ports on that host. This can be used to enumerate or exfiltrate data from internal services reachable only from the victim node's network, matching the "SC:H" (confidentiality of other systems) impact of the reference CVE. Impact is bounded to information disclosure/internal enumeration; it does not directly produce unauthorized coin movement.

### Likelihood Explanation
Likelihood is moderate: it requires the target node to run the DataLayer service and be configured to auto-sync or subscribe to the malicious store (owned-store pseudo-subscription and public subscriptions both funnel through `fetch_and_validate()`), and mirror coin creation is an on-chain action visible to and reproducible by any coin owner. No special privilege beyond normal spend-bundle submission is needed to create the malicious mirror coin.

### Recommendation
Validate mirror/server URLs before they are used for outbound requests in `download_data.py`/`data_layer.py`: resolve the hostname and reject loopback, link-local, private (RFC1918), and other non-routable address ranges (and re-validate after any redirect), in addition to existing filename/domain checks. Consider also restricting schemes to `http`/`https` and disallowing credentials-embedded URLs.

### Proof of Concept
1. Attacker creates a DataLayer store mirror coin (or a store which victim node auto-subscribes to) whose memos encode a URL such as `http://127.0.0.1:8555/` or `http://169.254.169.254/latest/meta-data/` instead of a legitimate mirror server, via the same mechanism used in `add_mirror`/`create_mirror_puzzle()` [1](#0-0) .
2. Any node running the DataLayer service that subscribes to this store id will, on its periodic sync cycle, call `fetch_and_validate()` and pick up this URL as a candidate server [8](#0-7) .
3. `insert_from_delta_file()` → `download_file()` → `http_download()` issues an HTTP GET to `<attacker_url>/<filename>` from the victim node with no SSRF guard [2](#0-1) , allowing the attacker to probe/exfiltrate response data (status codes, headers, and any content reflected in error logs) from internal services reachable by the victim's network position.

    return P2_PARENT.curry(Program.to(1))

def get_mirror_info(
    parent_puzzle: Program | SerializedProgram, parent_solution: Program | SerializedProgram
) -> tuple[bytes32, list[bytes]]:
    assert type(parent_puzzle) is type(parent_solution)
    _, conditions = run_with_cost(parent_puzzle, INFINITE_COST, parent_solution)
    for condition in conditions.as_iter():
        if (
            condition.first().as_python() == ConditionOpcode.CREATE_COIN
            and condition.at("rf").as_python() == create_mirror_puzzle().get_tree_hash()
        ):
            memos: list[bytes] = condition.at("rrrf").as_python()
            launcher_id = bytes32(memos[0])
            return launcher_id, [url for url in memos[1:]]
    raise ValueError("The provided puzzle and solution do not create a mirror coin")

async def http_download(
    target_filename_path: Path,
    filename: str,
    proxy_url: str | None,
    server_info: ServerInfo,
    timeout: aiohttp.ClientTimeout,
    log: logging.Logger,
    max_delta_file_size: int,
) -> None:
    """
    Download a file from a server using aiohttp.
    Raises exceptions on errors
    """
    async with aiohttp.ClientSession() as session:
        headers = {"accept-encoding": "gzip"}
        async with session.get(
            server_info.url + "/" + filename,
            headers=headers,
            timeout=timeout,
            proxy=proxy_url,
        ) as resp:
            resp.raise_for_status()
            size = int(resp.headers.get("content-length", 0))
            max_delta_file_size_bytes = max_delta_file_size * 1024 * 1024
            if size > max_delta_file_size_bytes:
                raise MaxDeltaFileSizeExceededError(f"Maximum delta file size exceeded: {max_delta_file_size} MiB.")
            log.debug(f"Downloading delta file {filename}. Size {size} bytes.")
