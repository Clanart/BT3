## Title
Unbounded sybil `ContactInfo` registration + equal-weight fallback for unstaked peers in `ClusterSlots::compute_weights` allows repair-peer selection poisoning — (`gossip/src/cluster_info.rs`, `core/src/cluster_slots_service/cluster_slots.rs`)

## Summary
The original report's broken invariant is: **cheap identity generation + no dedup by network endpoint (IP/port) lets one physical attacker occupy a disproportionate share of a peer-selection pool that a validator trusts for critical protocol data**, causing degraded/failed syncing. Agave's gossip layer explicitly defends against this for push/pull peer selection via `dedup_gossip_addresses` (keeping only the highest-stake pubkey per socket address), but the same protection is **not applied** to the repair-peer candidate pool, and the fallback stake-weighting used there treats unknown/unstaked pubkeys as equal to legitimately staked peers.

## Finding Description
`ClusterInfo::repair_peers(slot)` builds the candidate pool for repair requests purely from CRDS `ContactInfo` entries, filtered only by having a valid TVU/serve-repair socket and (optionally) a `LowestSlot` claim — with **no stake requirement and no de-duplication by socket address**: [1](#0-0) 

Contrast this with the analogous gossip pull/push selection path, which explicitly calls `dedup_gossip_addresses` to collapse multiple pubkeys sharing the same gossip socket down to the single highest-stake one: [2](#0-1) 

That dedup function is used in `new_pull_request` and `refresh_push_active_set`: [3](#0-2) [4](#0-3) 

`repair_peers()` (and therefore `ServeRepair::repair_peers`/`repair_request_ancestor_hashes_sample_peers`) never routes through this dedup logic, so an attacker running a single malicious repair endpoint at one IP:port can register arbitrarily many distinct `ContactInfo` entries (cheap keypairs) that all resolve to that same endpoint, and all of them individually enter the repair candidate pool: [5](#0-4) 

The weighting applied to that pool, `ClusterSlots::compute_weights`, then makes the sybils competitive with genuine low-stake validators rather than de-prioritizing them: for any peer not present in `validator_stakes`, the "stake" component falls back to `1` instead of `0`, and the combined weight formula floors at `1`: [6](#0-5) 

So an unstaked sybil peer with no recorded slot support gets `weight = (0/2 + 1/2).max(1) = 1` — the exact same minimum weight a genuine, real (but very low-stake) validator would get. The number of sybils an attacker can sustain in this pool is bounded only by the CRDS table's overall capacity headroom, not by any IP/port uniqueness check: [7](#0-6) 

Eviction from the CRDS table when full does prefer to drop the lowest-stake pubkeys, but only once `should_trim` fires, and it evicts merely `size = records.len() - cap` entries at a time — it does not prevent an attacker from occupying most of the "room" left below `CRDS_UNIQUE_PUBKEY_CAPACITY` (8192) with zero-stake identities that all point at one attacker-controlled repair server: [8](#0-7) 

## Impact Explanation
Because `repair_peers()` and `compute_weights` do not exclude or IP/port-dedup sybils, and because the fallback weight treats "unknown pubkey" identically to "legitimately low-staked validator," an attacker who floods gossip with thousands of unstaked `ContactInfo` entries all pointing at a single malicious repair server can make that server disproportionately likely to be selected as a repair peer for slots where legitimate validators have not yet recorded support (i.e., during normal steady-state repair traffic, not just bootstrap). A malicious repair server that always drops/never responds, or returns responses timed to maximize wasted round-trips, degrades block/shred repair throughput for the querying validator — the same class of impact ("non-RPC remote exhaustion/degradation of syncing validators") described in the source report for the archiver-sybil bug. This does not directly break cryptographic acceptance of shreds (they remain leader-signed and verified), so it is a degradation/DoS-class issue on the repair path rather than a consensus-integrity break.

## Likelihood Explanation
Generating keypairs and publishing signed `ContactInfo` gossip messages is inexpensive and does not require stake, mirroring the ease with which the original report's attacker generated many archiver keypairs. The only throttle is the global CRDS capacity (8192 unique pubkeys) and its stake-preferring eviction, which bounds — but does not eliminate — the number of sybils an attacker can sustain, especially on clusters where legitimate unique validator identities are well below that cap.

## Recommendation
- Apply the same socket-address de-duplication used in `dedup_gossip_addresses` (or an equivalent) to the repair-peer candidate pool built in `ClusterInfo::repair_peers` before it reaches `ServeRepair`.
- Change the fallback in `ClusterSlots::compute_weights` so that peers absent from `validator_stakes` are weighted `0` (or excluded entirely), rather than defaulting to `1`, consistent with `compute_weights_exclude_nonfrozen`'s stricter behavior which already requires `stake > 0`.

## Proof of Concept
1. From a single host, generate N keypairs and, for each, gossip a signed `ContactInfo` CRDS value whose TVU/serve-repair sockets all point at the same attacker-controlled `SocketAddr` (a modified repair server that silently drops all requests).
2. Ensure N is large relative to the number of genuinely low-stake validators (bounded by `CRDS_UNIQUE_PUBKEY_CAPACITY - current_unique_pubkeys`).
3. Observe via `ClusterInfo::repair_peers(slot)` / `ServeRepair::repair_peer_weights` that these sybil entries are included in the candidate list and receive `weight == 1`, identical to genuine minimally-staked validators, because they are absent from `validator_stakes` (`compute_weights` fallback) and have no recorded slot support.
4. Over many repair rounds, measure the fraction of `repair_request` calls whose `WeightedIndex`/`choose_multiple_weighted` draw selects the attacker's single endpoint, and confirm degraded repair success rate for the syncing validator, analogous to the archiver's `cycleinfo` sybil-driven denial in the source report.

    pub(crate) fn compute_weights(&self, slot: Slot, repair_peers: &[ContactInfo]) -> Vec<u64> {
        if repair_peers.is_empty() {
            return vec![];
        }
        let stakes = {
            let failsafe = std::iter::repeat_n(1, repair_peers.len());
            let Some(epoch) = self.get_epoch_for_slot(slot) else {
                error!("No epoch info for slot {slot}");
                return Vec::from_iter(failsafe);
            };
            let epoch_metadata = self.epoch_metadata.read().unwrap();
            let Some(stakeinfo) = epoch_metadata.get(&epoch) else {
                error!("No epoch_metadata record for epoch {epoch}");
                return Vec::from_iter(failsafe);
            };
            let validator_stakes = stakeinfo.validator_stakes.as_ref();
            repair_peers
                .iter()
                .map(|peer| {
                    validator_stakes
                        .get(peer.pubkey())
                        .cloned()
                        .unwrap_or(1)
                        .max(1)
                })
                .collect()
        };
        let Some(slot_peers) = self.lookup(slot) else {
            return stakes;
        };

        repair_peers
            .iter()
            .map(|peer| slot_peers.get_support_by_pubkey(peer.pubkey()).unwrap_or(0))
            .zip(stakes)
            .map(|(a, b)| (a / 2 + b / 2).max(1u64))
            .collect()
    }

    /// Returns true if the number of unique pubkeys in the table exceeds the
    /// given capacity (plus some margin).
    /// Allows skipping unnecessary calls to trim without obtaining a write
    /// lock on gossip.
    pub(crate) fn should_trim(&self, cap: usize) -> bool {
        // Allow 10% overshoot so that the computation cost is amortized down.
        10 * self.records.len() > 11 * cap
    }

    /// Trims the table so that the number of unique pubkeys are bounded.
    pub(crate) fn trim(
        &mut self,
        cap: usize, // Capacity hint for number of unique pubkeys.
        // Set of pubkeys to never drop.
        // e.g. known validators, self pubkey, entrypoints, ...
        keep: &HashSet<Pubkey>,
        stakes: &HashMap<Pubkey, u64>,
        now: u64,
    ) -> usize {
        if self.should_trim(cap) {
            let size = self.records.len().saturating_sub(cap);
            self.drop(size, keep, stakes, now)
        } else {
            0
        }
    }

    // Drops 'size' many pubkeys with the lowest stake if stakes are known
    // Otherwise select and drop a random sample of `size` many pubkeys
    fn drop(
        &mut self,
        size: usize,
        keep: &HashSet<Pubkey>,
        stakes: &HashMap<Pubkey, u64>,
        now: u64,
    ) -> usize {
        if stakes.values().all(|&stake| stake == 0) {
            // Stakes are unavailable, evict amount above cap
            return self.drop_random(size, keep, now);
        }
        let mut keys: Vec<_> = self
            .records
            .keys()
            .map(|k| (stakes.get(k).copied().unwrap_or_default(), *k))
            .collect();
        if size < keys.len() {
            keys.select_nth_unstable(size);
        }
        let keys: Vec<_> = keys
            .into_iter()
            .take(size)
            .map(|(_, k)| k)
            .filter(|k| !keep.contains(k))
            .flat_map(|k| &self.records[&k])
            .map(|k| self.table.get_index(*k).unwrap().0.clone())
            .collect();
        for key in &keys {
            self.remove(key, now);
        }
        keys.len()
    }
