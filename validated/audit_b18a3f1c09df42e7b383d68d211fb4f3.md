## Title
Unrestricted `CallDispatcher.dispatch` Allows Any Caller to Redirect Residual Approvals/Balances Left by Prior Flows - (File: `evm/src/utils/CallDispatcher.sol`)

### Summary
`CallDispatcher.dispatch` has no caller restriction and no reentrancy/session binding to the protocol flow that invoked it: [1](#0-0) 

Anyone — including a completely unprivileged EOA with no relationship to any order, message, or proof — can call it directly with an arbitrary `Call[]` payload. Because the dispatcher is a single, shared, persistent contract used across `IntentGatewayV2` predispatch/postdispatch flows and `HyperFungibleToken`/`WrappedHyperFungibleToken` calldata execution, any ERC20 approval it has previously granted to a third-party contract (e.g. a router) plus any un-swept token balance left on it becomes a standing, cross-user attack surface.

### Finding Description
Legitimate flows route tokens and approvals through the dispatcher: `IntentsBase._execute` dispatches `order.output.call` and then sweeps only the tokens listed in `order.output.assets` back to the gateway: [2](#0-1) 

Predispatch flows in `IntentGatewayV2.placeOrder` similarly push assets to the dispatcher, `dispatch()` the user-supplied calldata, then transfer back only the `order.inputs` tokens: [3](#0-2) 

The documentation itself acknowledges that calldata routed through the dispatcher commonly grants ERC20 approvals to external protocols (e.g. Uniswap router) and explicitly warns integrators to use exact amounts rather than unlimited allowances "since the dispatcher contract holds tokens temporarily during execution," and test fixtures even exercise `type(uint256).max` approvals to a router from the dispatcher (see `testPostdispatchTokenSweep`): [4](#0-3) 

If any such approval is not fully consumed (unlimited allowances, a token that ends up with dust not included in `order.output.assets`/`order.inputs`, or a swap that under-consumes the approved amount), the standing `allowance[dispatcher][spender]` and any un-swept token balance remain on the dispatcher after the transaction completes. Because `dispatch()` executes calls in the dispatcher's own context (`to.call{value}(data)`), and has no access control, any unprivileged caller can later submit a new `dispatch()` payload that calls the previously-approved spender (e.g. the router) with an attacker-chosen recipient argument. The spender will treat `msg.sender == CallDispatcher` as the token owner and pull from the dispatcher's residual balance via the residual allowance, delivering the output to the attacker rather than to the rightful protocol beneficiary — i.e., the dispatcher's approval/balance context from one flow is consumed by an arbitrary caller in an unrelated later context.

### Impact Explanation
This breaks the invariant that any preapproved token path reachable by the dispatcher must remain scoped to the active protocol call. Because the dispatcher is a shared singleton across all users' orders and cross-chain messages, one user's leftover approval/dust becomes exploitable by any other unprivileged party, resulting in wrongful redirection of protocol- or user-controlled assets — a Critical impact per the bounty's asset-movement criteria.

### Likelihood Explanation
Likelihood depends on integrators/users following the documented "use exact amounts" guidance for every `Call[]` they submit, and on the dust-sweep in `_execute`/`placeOrder` covering every token touched by predispatch/postdispatch calldata (not just `order.output.assets`/`order.inputs`). Any deviation — unlimited allowances, tokens outside the swept set, partial swap consumption, fee-on-transfer edge cases — creates an exploitable window, and `dispatch()` itself performs zero validation to prevent an unrelated caller from exploiting it once created.

### Recommendation
- Restrict `CallDispatcher.dispatch` so it can only be invoked by the protocol contracts that own a given flow (e.g. an `onlyCaller`/allowlist of `IntentGatewayV2`, `HyperFungibleToken`, `WrappedHyperFungibleToken`), or make the dispatcher single-use/ephemeral per flow (e.g. deploy a fresh minimal proxy per call) so no state persists across callers.
- Alternatively/additionally, have the dispatcher revoke any approvals it granted during a call sequence before returning control, and require flows to sweep/zero out every token balance touched (not just the tokens declared in `order.output.assets`/`order.inputs`) at the end of each `dispatch()` invocation.

### Proof of Concept
1. Deploy `CallDispatcher`. In a flow (e.g. `IntentGatewayV2.fillOrder` postdispatch), have the order's `output.call` approve a router for `type(uint256).max` on token `T` and swap only part of the dispatcher's `T` balance, leaving `allowance[dispatcher][router] > 0` and/or leftover `T` balance not included in `order.output.assets`.
2. As an unrelated unprivileged address, call `CallDispatcher.dispatch(abi.encode(calls))` directly with `calls = [{to: router, data: swap(..., recipient: attacker, ...)}]`.
3. Observe the router pulls from the dispatcher's residual balance/allowance and sends output tokens to the attacker's address, with no relationship to any order the attacker placed or filled.

    function dispatch(bytes memory encoded) external {
        Call[] memory calls = abi.decode(encoded, (Call[]));
        uint256 callsLen = calls.length;
        for (uint256 i = 0; i < callsLen; ++i) {
            Call memory call = calls[i];
            uint32 size;
            address to = call.to;
            assembly {
                size := extcodesize(to)
            }

            if (size == 0) {
                revert NotContract(to);
            }

            (bool success, bytes memory result) = to.call{value: call.value}(call.data);
            if (!success) revert CallFailed(to, result);
        }
    }

    function _execute(Order calldata order, uint256 outputsLen) internal {
        if (order.output.call.length == 0) return;

        address dispatcher = _params.dispatcher;
        ICallDispatcher(dispatcher).dispatch(order.output.call);

        Call[] memory sweepCalls = new Call[](outputsLen);
        uint256 sweepCount = 0;

        for (uint256 i; i < outputsLen;) {
            address token = address(uint160(uint256(order.output.assets[i].token)));

            if (token == address(0)) {
                uint256 balance = dispatcher.balance;
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({to: address(this), value: balance, data: ""});
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            } else {
                uint256 balance = IERC20(token).balanceOf(dispatcher);
                if (balance > 0) {
                    sweepCalls[sweepCount] = Call({
                        to: token,
                        value: 0,
                        data: abi.encodeWithSelector(IERC20.transfer.selector, address(this), balance)
                    });
                    sweepCount++;
                    emit DustCollected(token, balance);
                }
            }

            unchecked {
                ++i;
            }
        }

        if (sweepCount > 0) {
            Call[] memory finalCalls = new Call[](sweepCount);
            for (uint256 i; i < sweepCount;) {
                finalCalls[i] = sweepCalls[i];
                unchecked {
                    ++i;
                }
            }
            ICallDispatcher(dispatcher).dispatch(abi.encode(finalCalls));
        }
