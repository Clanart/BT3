### Title
`ReceivedOutput::read` accepts an attacker-controlled scalar offset without binding it to the output's `script_pubkey`, so a forged `ReceivedOutput` misattributes funds to an arbitrary group key that cannot spend them - (File: networks/bitcoin/src/wallet/mod.rs)

### Summary
`ReceivedOutput` pairs a spendable `TxOut`/`OutPoint` with a `Scalar` `offset` that is supposed to describe which key-derivation offset produced the output's P2TR `script_pubkey`. `Scanner::scan_transaction` produces well-formed pairs because it looks the offset up from the `scripts` map keyed by `script_pubkey`. However, `ReceivedOutput::read` deserializes `offset` and `output` independently and performs no consistency check between them — the equivalent of the MISP bug where a caller-supplied identifier is reused instead of the object's real association. Downstream code (`Output::key()` in `processor/src/networks/bitcoin.rs`) trusts the embedded offset to recover the group key (`scriptKey - offset*G`), and `SignableTransaction::multisig` uses the same embedded offset to build the signing machine. A forged `ReceivedOutput` therefore reports an output as belonging to the wrong multisig key and/or renders it unspendable.

### Finding Description
- `ReceivedOutput::read` reads `offset` via `Secp256k1::read_F`, then consensus-decodes the `TxOut` and `OutPoint`, and returns them without verifying `p2tr_script_buf(key + offset*G) == output.script_pubkey` for the receiving key — the only binding that exists is inside `Scanner`, which is bypassed entirely on the deserialization path (`networks/bitcoin/src/wallet/mod.rs:122-134`).
- The offset is the sole authority for "which key owns this output": `Output::key()` computes `read_G(script_pubkey_key) - GENERATOR * output.offset()` (`processor/src/networks/bitcoin.rs:112-122`), so a tampered offset shifts the attributed group key arbitrarily.
- At spend time, `SignableTransaction::multisig` applies `keys.clone().offset(self.offsets[i])` and returns `None` when `p2tr_script_buf(offset.group_key())` doesn't reproduce `prevouts[i].script_pubkey` (`networks/bitcoin/src/wallet/send.rs:273-285`), so an output whose embedded offset was swapped can be reported as received yet fail to produce a signing machine — funds detected but unspendable.

### Impact Explanation
An unprivileged party who can feed bytes to `ReceivedOutput::read` (e.g., output data relayed between components, or deserialized scan results) can substitute a different offset. Consequences:
- The output is attributed to a different group key than the one actually controlling the `script_pubkey`, crediting the wrong multisig or session.
- Alternatively the attributed key is correct but the offset mismatches the script, so `multisig()` returns `None` and the reported funds can never be signed/spent — a funds-reported-received-but-unspendable condition, matching the accepted impact class.

### Likelihood Explanation
The offset field is a full 32-byte scalar under complete control of whoever supplies the bytes; no cryptographic check ties it to the `script_pubkey`. Exploitation requires only that untrusted input reaches `ReceivedOutput::read`, which the scope rules treat as a reachable surface. Impact is capped at misattribution/lockup (not theft), since the spend-time `script_pubkey` check prevents signing for a key that doesn't match the output — warranting Medium severity.

### Recommendation
When constructing or deserializing a `ReceivedOutput`, verify the offset against the script: given the expected base `key`, require `p2tr_script_buf(key + GENERATOR * offset) == Some(output.script_pubkey)`. Alternatively, make `ReceivedOutput::read` private to the `Scanner` (which derives offsets from its `scripts` map) so externally supplied bytes cannot forge the association, or store the derived `group_key` and re-verify the script on use.

### Proof of Concept

// networks/bitcoin/src/wallet/mod.rs path, std feature
// Given a legitimate scanned output paying to `key + offset_A * G`:
let legit = scanner.scan_transaction(&tx).remove(0); // offset_A, script_A

// Attacker crafts bytes with the same output but a different offset:
let mut forged = Vec::new();
// write offset_B != offset_A
forged.extend(Scalar::from(7u64).to_bytes());           // read as Secp256k1::read_F
forged.extend(bitcoin::consensus::encode::serialize(legit.output()));
forged.extend(bitcoin::consensus::encode::serialize(legit.outpoint()));

let output = ReceivedOutput::read(&mut forged.as_slice()).unwrap();
// output.offset() == 7, but output.output().script_pubkey still pays to offset_A's key.
// Output::key() yields  key_A + (offset_A - 7)*G  -> wrong group key attributed;
// SignableTransaction::multisig returns None because
// p2tr_script_buf(keys.offset(7).group_key()) != prevouts[i].script_pubkey
// => funds reported received under a key that cannot spend them.
