## Finding

### Title
`mWOMSVBaseRewarder._calExpireForfeit` never applies the intended forfeit, permanently diverting yield away from long-term mWomSV lockers - (File: `rewards/mWOMSVBaseRewarder.sol`)

### Summary
`mWOMSVBaseRewarder._calExpireForfeit` is meant to reduce a user's claimable reward by the portion attributable to mWom that is not fully locked (i.e., in cooldown or already unlocked), redistributing the forfeited portion back into the reward pool for users who kept their stake fully locked. Instead of consulting the actual "rewardable percent" of the user's stake, the function is hard-coded so that the forfeit is always zero, meaning every user — including those who have started unlocking or hold cooled-down balances — receives 100% of their accrued rewards with nothing ever redistributed back to loyal, fully-locked stakers.

### Finding Description
The sibling contract `vlMGPBaseRewarder._calExpireForfeit` correctly queries the locker for the user's actual rewardable share and computes the forfeit from it: [1](#0-0) 

This uses `vlMGP.getRewardablePercentWAD(_account)` — a value that decreases as more of the user's balance sits in cooldown or is already unlockable — to shrink `rewardableAmount` below `_amount`, producing a nonzero `forfeitAmount` that is later re-queued as rewards for other stakers via `_queueNewRewardsWithoutTransfer`.

In `mWOMSVBaseRewarder`, however, the equivalent function never calls the analogous `mWOMSV.getRewardablePercentWAD(_account)`: [2](#0-1) 

Here `rewardableAmount` is simply set equal to `_amount`, so `forfeitAmount = _amount - rewardableAmount` is always `0`, and the subsequent sanity check `if (rewardableAmount > _amount) revert InvalidRewardableAmount();` can never be triggered because the two values are always equal by construction. `mWomSV.getRewardablePercentWAD` exists and is fully implemented for exactly this purpose (mirroring `VLMGP.getRewardablePercentWAD`): [3](#0-2) 

`_calExpireForfeit` is invoked from `_sendReward`, which is reached by every ordinary user call to `getReward`/`getRewards`: [4](#0-3) 

So any unprivileged staker who starts an unlock (moving mWomSV balance into cooldown, which should reduce their `getRewardablePercentWAD`) still claims 100% of the reward-per-token entitlement computed on their full staked balance, with zero forfeited amount ever re-queued via `_queueNewRewardsWithoutTransfer` for the benefit of stakers who kept their mWom fully locked.

### Impact Explanation
This is a permanent, protocol-wide misallocation of yield: the forfeit mechanism that funds the "loyalty" incentive for long-term mWomSV lockers by clawing back rewards from users in cooldown/unlocking never fires. Reward tokens that should be redistributed as bonus yield to fully-locked stakers are instead paid out in full to unlocking/exiting stakers, permanently and irrecoverably reducing the yield honest long-term lockers would otherwise receive — a form of theft/permanent loss of unclaimed yield for the intended beneficiaries of the forfeit design, since it can never be reclaimed or corrected after tokens are transferred out via `_sendReward`.

### Likelihood Explanation
High likelihood: this triggers automatically and deterministically for every claim by every mWomSV-pool staker whenever `_calExpireForfeit` is invoked (i.e., every `getReward`/`getRewards` call), with no special preconditions, privileges, or attacker action required beyond normal use of `startUnlock` followed by a reward claim.

### Recommendation
Update `mWOMSVBaseRewarder._calExpireForfeit` to mirror `vlMGPBaseRewarder._calExpireForfeit` by computing `rewardableAmount` from `mWOMSV.getRewardablePercentWAD(_account)`:
```solidity
function _calExpireForfeit(address _account, uint256 _amount) internal view returns (uint256) {
    uint256 rewardablePercentWAD = mWOMSV.getRewardablePercentWAD(_account);
    uint256 rewardableAmount = _amount * rewardablePercentWAD / 1e18;
    if (rewardableAmount > _amount)
        revert InvalidRewardableAmount();

    uint256 forfeitAmount = _amount - rewardableAmount;
    if (forfeitAmount < (_amount / 1000)) {
        forfeitAmount = 0;
        rewardableAmount = _amount;
    }
    return forfeitAmount;
}
```
This requires the `ILocker` interface used for `mWOMSV` to expose `getRewardablePercentWAD`, consistent with `IVLMGP`.

### Proof of Concept
1. A user locks mWom via `mWomSV.lock`, is credited a stake in `MasterMagpie`, and accrues rewards in `mWOMSVBaseRewarder` over time via `rewards[token].rewardPerTokenStored` growth.
2. The user calls `mWomSV.startUnlock(amount)`, moving part of their balance into a cooldown slot; per `getRewardablePercentWAD` this should reduce their forfeit-free claimable share since a fraction of their stake is now unlocking rather than fully locked. [5](#0-4) 
3. The user calls `MasterMagpie` → `mWOMSVBaseRewarder.getReward`/`getRewards`, which computes `earned` on the user's full `balanceOf` (still including the cooling-down amount) and then calls `_sendReward` → `_calExpireForfeit`. [6](#0-5) 
4. Because `_calExpireForfeit` sets `rewardableAmount = _amount` unconditionally, `forfeitAmount` is always `0`, and the user receives their entire computed reward in full — none of it is redirected back to `rewardInfo.rewardPerTokenStored` for fully-locked stakers, unlike the equivalent, correctly-implemented `vlMGPBaseRewarder` flow.

    function getRewardablePercentWAD(address _user) override public view returns(uint256 percent) {
        uint256 fullyInLock = getUserTotalLocked(_user);
        uint256 inCoolDown = getUserAmountInCoolDown(_user);
        uint256 userTotalmWomSV = fullyInLock + inCoolDown;
        if (userTotalmWomSV == 0)
            return 0;
        percent = fullyInLock * 1e18 / userTotalmWomSV;

        uint256 timeNow = block.timestamp;
        UserUnlocking[] storage userUnlocking = userUnlockings[_user];

        for (uint256 i; i < userUnlocking.length; i++) {
            if (userUnlocking[i].amountInCoolDown > 0) {
                if (block.timestamp > userUnlocking[i].endTime) {// fully unlocked 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 * (userUnlocking[i].endTime - userUnlocking[i].startTime)
                        / userTotalmWomSV / (timeNow - userUnlocking[i].startTime);
                }
                else {// still in cool down 
                    percent += userUnlocking[i].amountInCoolDown * 1e18 / userTotalmWomSV;
                }

            }
        }

        return percent;
    }
