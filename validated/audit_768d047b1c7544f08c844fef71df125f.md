### Title
Deep-link "Open Repository from URL" PR action silently adds an attacker-controlled remote and checks out a fork branch without user confirmation - (File: `app/src/ui/dispatcher/dispatcher.ts`)

### Summary
GitHub Desktop's `x-github-client://openRepo/...` deep link supports a `pr` query parameter that drives `openPullRequestFromUrl`. When the target repository is already open in Desktop, this path skips the confirmation dialog that Desktop normally requires before adding a new remote/cloning, and instead automatically adds a `github-desktop-`-prefixed remote pointing at an attacker-supplied clone URL and checks out an attacker-chosen branch, purely as a result of the user clicking a link.

### Finding Description
`parseAppURL` accepts an `openrepo` action with an optional `pr` parameter and passes it, unvalidated beyond a numeric-string check, into the URL action pipeline. [1](#0-0) 

`dispatchURLAction` routes `open-repository-from-url` actions to `openRepositoryFromUrl`, which, when a `pr` value is present, calls `openPullRequestFromUrl(url, pr)` instead of the normal clone flow. [2](#0-1) 

`openPullRequestFromUrl` first fetches the PR object from the GitHub API (`pullRequest.head.repo.clone_url` and `pullRequest.head.ref` are entirely attacker-controlled — the attacker only needs to open any PR from their own fork against a public repository). It then tries to find a matching *already open* local repository via `getRepositoryFromPullRequest`/`doesRepositoryMatchUrl`, which only compares the origin/upstream URL, not repository identity intent. If a match exists, it proceeds straight to `_checkoutPullRequest` with the attacker-supplied `clone_url`/`ref` — no popup, no approval step: [3](#0-2) 

Contrast this with the ordinary open/clone path (`openOrCloneRepository`), which *does* require explicit user approval by opening the `PopupType.CloneRepository` dialog before any clone happens: [4](#0-3) 

`_checkoutPullRequest` → `_findPullRequestBranch` unconditionally creates a new remote (prefixed `github-desktop-`) pointing at the attacker-controlled `headCloneUrl` if no existing remote matches, fetches it, and checks out the ref as a new local branch — again with no confirmation prompt: [5](#0-4) 

The broken invariant is the same class as the reported token bug: an action that is supposed to require an explicit approval/consent step (adding a remote and changing HEAD/working tree state, analogous to "spending" the user's repository state) is executed on behalf of the user without that approval check ever being enforced, because the "approval" gate (the `CloneRepository` popup) only exists on one code path and is bypassed on another that is reachable from fully untrusted, remote-attacker-controlled input (a clickable link / PR object).

### Impact Explanation
Clicking an attacker-supplied link silently mutates a repository the victim already has open in Desktop: a new remote is added, a fetch is performed against attacker infrastructure (URL/host of the attacker's choosing, not restricted to github.com), and the working directory is checked out to attacker-chosen content — all without any explicit "Clone"/"Add remote"/"Checkout" confirmation the way the equivalent non-deep-link flow requires. This matches the in-scope impact category of "silent corruption of what the user commits or pushes": a user who continues working (editing, committing, pushing) may unknowingly build on top of attacker-supplied branch content, and the newly added remote persists in the repository's git config beyond the single session.

### Likelihood Explanation
The prerequisite is only that the victim has `x-github-client://` (or the platform equivalent) registered as Desktop's protocol handler — true for all normal installations — and that they click a link while having any matching repository already open in Desktop (a very common state, e.g. any popular OSS repo). The attacker needs no special privileges: opening a PR against a public repository from their own fork is available to any GitHub account, and the PR need not be merged, reviewed, or even referenced by the target maintainers.

### Recommendation
Require the same explicit user confirmation for the PR/branch-checkout deep-link paths (`openPullRequestFromUrl`, `openBranchNameFromUrl`, and `_findPullRequestBranch`'s remote-add) as is already enforced for `openOrCloneRepository` — e.g., surface a popup showing the remote URL/owner and PR/branch details and require explicit user acceptance before adding a remote, fetching, or checking out, regardless of whether the target repository was already open locally.

### Proof of Concept
1. Victim has repository `github.com/some/public-repo` already added in Desktop.
2. Attacker forks `some/public-repo`, pushes a branch with arbitrary content, and opens a PR (`#N`) from that fork against `some/public-repo`.
3. Attacker sends the victim a link: `x-github-client://openRepo/https://github.com/some/public-repo?pr=N`.
4. Victim clicks the link. Desktop's `handleAppURL` → `parseAppURL` → `dispatchURLAction` → `openRepositoryFromUrl` → `openPullRequestFromUrl` fires.
5. Because the repo is already open, `getRepositoryFromPullRequest` matches it, `selectRepository` is called (no popup), and `_checkoutPullRequest` adds a `github-desktop-`-prefixed remote for the attacker's fork clone URL, fetches it, and checks out `pr/N` — with no confirmation dialog ever shown to the user.

  private async openPullRequestFromUrl(
    url: string,
    pr: string
  ): Promise<RepositoryWithGitHubRepository | null> {
    const pullRequest = await this.appStore.fetchPullRequest(url, pr)

    if (pullRequest === null) {
      return null
    }

    // Find the repository where the PR is created in Desktop.
    let repository: Repository | null =
      this.getRepositoryFromPullRequest(pullRequest)

    if (repository !== null) {
      await this.selectRepository(repository)
    } else {
      repository = await this.openOrCloneRepository(url)
    }

    if (repository === null) {
      log.warn(
        `Open Repository from URL failed, did not find or clone repository: ${url}`
      )
      return null
    }
    if (!isRepositoryWithGitHubRepository(repository)) {
      log.warn(
        `Received a non-GitHub repository when opening repository from URL: ${url}`
      )
      return null
    }

    // ensure a fresh clone repository has it's in-memory state
    // up-to-date before performing the "Clone in Desktop" steps
    await this.appStore._refreshRepository(repository)

    if (pullRequest.head.repo === null) {
      return null
    }

    await this.appStore._checkoutPullRequest(
      repository,
      pullRequest.number,
      pullRequest.head.repo.owner.login,
      pullRequest.head.repo.clone_url,
      pullRequest.head.ref
    )

    return repository
  }

  private async openOrCloneRepository(url: string): Promise<Repository | null> {
    const state = this.appStore.getState()
    const repositories = state.repositories
    const existingRepository = repositories.find(r =>
      this.doesRepositoryMatchUrl(r, url)
    )

    if (existingRepository) {
      return await this.selectRepository(existingRepository)
    }

    return this.appStore._startOpenInDesktop(() => {
      this.changeCloneRepositoriesTab(CloneRepositoryTab.Generic)
      this.showPopup({
        type: PopupType.CloneRepository,
        initialURL: url,
      })
    })
  }

  public async _checkoutPullRequest(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,
    headRefName: string
  ): Promise<void> {
    const prBranch = await this._findPullRequestBranch(
      repository,
      prNumber,
      headRepoOwner,
      headCloneUrl,
      headRefName
    )
    if (prBranch !== undefined) {
      await this._checkoutBranch(repository, prBranch)
      this.statsStore.increment('prBranchCheckouts')
    }
  }

  public async _findPullRequestBranch(
    repository: RepositoryWithGitHubRepository,
    prNumber: number,
    headRepoOwner: string,
    headCloneUrl: string,
    headRefName: string
  ): Promise<Branch | undefined> {
    const gitStore = this.gitStoreCache.get(repository)
    const remotes = await getRemotes(repository)

    // Find an existing remote (regardless if set up by us or outside of
    // Desktop).
    let remote = remotes.find(r => urlMatchesRemote(headCloneUrl, r))

    // If we can't find one we'll create a Desktop fork remote.
    if (remote === undefined) {
      try {
        const forkRemoteName = forkPullRequestRemoteName(headRepoOwner)
        remote = await addRemote(repository, forkRemoteName, headCloneUrl)
      } catch (e) {
        this.emitError(
          new Error(
            `Couldn't find PR branch, adding remote failed: ${e.message}`
          )
        )
        return
      }
    }

    const remoteRef = `${remote.name}/${headRefName}`

    // Start by trying to find a local branch that is tracking the remote ref.
    let existingBranch = gitStore.allBranches.find(
      x => x.type === BranchType.Local && x.upstream === remoteRef
    )

    // If we found one, let's check it out and get out of here, quick
    if (existingBranch !== undefined) {
      return existingBranch
    }

    const findRemoteBranch = (name: string) =>
      gitStore.allBranches.find(
        x => x.type === BranchType.Remote && x.name === name
      )

    // No such luck, let's see if we can at least find the remote branch then
    existingBranch = findRemoteBranch(remoteRef)

    // It's quite possible that the PR was created after our last fetch of the
    // remote so let's fetch it and then try again.
    if (existingBranch === undefined) {
      try {
        await this._fetchRemote(repository, remote, FetchType.UserInitiatedTask)
        existingBranch = findRemoteBranch(remoteRef)
      } catch (e) {
        log.error(`Failed fetching remote ${remote?.name}`, e)
      }
    }

    if (existingBranch === undefined) {
      this.emitError(
        new Error(
          `Couldn't find branch '${headRefName}' in remote '${remote.name}'. ` +
            `A common reason for this is that the PR author has deleted their ` +
            `branch or their forked repository.`
        )
      )
      return
    }

    // For fork remotes we checkout the ref as pr/[123] instead of using the
    // head ref name since many PRs from forks are created from their default
    // branch so we'll have a very high likelihood of a conflicting local branch
    const isForkRemote =
      remote.name !== gitStore.defaultRemote?.name &&
      remote.name !== gitStore.upstreamRemote?.name

    if (isForkRemote) {
      return await this._createBranch(
        repository,
        `pr/${prNumber}`,
        remoteRef,
        false
      )
    }

    return existingBranch
  }
