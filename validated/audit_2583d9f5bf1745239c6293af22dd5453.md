### Title
Missing lower-bound validation for `Kip71GasTarget` governance parameter enables division-by-zero panic in Magma base-fee calculation - ([File: params/kip71_config.go])

### Summary
The KIP-71 dynamic base-fee mechanism divides by the governance-controlled `GasTarget` parameter without ever checking that it is non-zero, while the sibling parameter `BaseFeeDenominator` explicitly guards against the same class of bug. Because the governance vote path (`kaiax/gov/param.go`) registers `Kip71GasTarget` with a `noopFormatChecker` and no consistency check rejects `GasTarget == 0`, a governance vote can push a `GasTarget=0` value into `params.KIP71Config`, causing `NextMagmaBlockBaseFee` to divide by zero and panic on every node computing the next block's base fee.

### Finding Description
`Params[Kip71GasTarget]` is defined with `FormatChecker: noopFormatChecker`, which always returns `true` regardless of the submitted value: [1](#0-0) 

This is inconsistent with other numeric governance parameters in the same table that do enforce a lower bound, e.g. `IstanbulCommitteeSize` requires `v > 0` and `Kip71BaseFeeDenominator` requires `v != 0`: [2](#0-1) [3](#0-2) 

`checkConsistency`, which validates the semantic correctness of a proposed vote (e.g. `Kip71LowerBoundBaseFee`/`Kip71UpperBoundBaseFee` cross-checks), performs no such check for `Kip71GasTarget` — it simply falls into the "no additional checks" case: [4](#0-3) 

Once accepted, the value flows unmodified into `params.KIP71Config.GasTarget` (via `getChainConfig`/`ToKip71Config`) and is consumed in `NextMagmaBlockBaseFee`: [5](#0-4) 

Note the explicit defensive check for `BaseFeeDenominator == 0` ("To avoid panic, set the fluctuation range small"), but no equivalent guard exists for `GasTarget`. If `GasTarget == 0` and `parentGasUsed != 0` (the overwhelmingly common case), execution enters the `parentGasUsed > gasTarget` branch and computes `x.Div(x, new(big.Int).SetUint64(gasTarget))` with `gasTarget = 0`, which panics in Go's `math/big` package ("division by zero").

This function is invoked in the header-construction/validation hot path used by every node, e.g. `blockchain/chain_makers.go` when building a header, `blockchain/block_validator.go` when validating a header, and `work/worker.go` when assembling a block: [6](#0-5) 

### Impact Explanation
A single governance vote (reachable by any council member/validator that can cast `header.Vote`, or the governing node in single mode) setting `kip71.gastarget` to `0` propagates through `GetParamSet` into `ChainConfig.Governance.KIP71.GasTarget` at the next epoch. From that point on, every node — proposer and follower alike — panics deterministically inside `NextMagmaBlockBaseFee` whenever it tries to build or validate a header for a block whose parent used any non-zero amount of gas (i.e., essentially every real block). This crashes block production and header validation network-wide, halting the chain, which is a consensus-liveness-critical outcome analogous to the "stuck forever" outcome in the original report (there the misconfiguration made funds permanently unwithdrawable; here it makes the chain permanently unable to produce/validate blocks once the bad parameter takes effect at the epoch boundary).

### Likelihood Explanation
Same likelihood class as the original finding: it requires a misconfiguration (a governance vote setting `GasTarget=0`), not an external attacker directly, but there is no validation to prevent a validator from getting this parameter through the vote/format-check pipeline — an accidental or malicious vote (e.g. a fat-fingered `0` value) sails through both `FormatChecker` and `checkConsistency` with no rejection, unlike sibling parameters that already have such guards.

### Recommendation
Add a `FormatChecker` for `Kip71GasTarget` (and ideally `Kip71MaxBlockGasUsedForBaseFee`) that rejects `0`, mirroring the existing checks for `IstanbulCommitteeSize` and `Kip71BaseFeeDenominator`. Additionally, add a defensive `gasTarget == 0` fallback inside `NextMagmaBlockBaseFee` (as is already done for `BaseFeeDenominator == 0`) so that even a legacy/pre-validated `ChainConfig` cannot trigger a division-by-zero panic.

### Proof of Concept
1. A governance vote (or governing node vote in single mode) proposes `kip71.gastarget = 0` and is included in `header.Vote`; `VerifyVote`/`checkConsistency` accept it because `Kip71GasTarget`'s format checker is a no-op and `checkConsistency` has no special case for it.
2. At the next epoch boundary, `GetParamSet` returns `GasTarget = 0`, and this is written into `ChainConfig.Governance.KIP71.GasTarget`.
3. On the next block after the Magma fork with `parentGasUsed != 0`, `chain_makers.go`/`block_validator.go` call `KIP71Config.NextMagmaBlockBaseFee(parentNumber, parentBaseFee, parentGasUsed)`.
4. Inside `NextMagmaBlockBaseFee`, since `parentGasUsed > gasTarget (0)`, the code executes `x.Div(x, new(big.Int).SetUint64(gasTarget))` with `gasTarget = 0`, which panics with "division by zero" in every node executing this code path, halting block production/validation network-wide.

	if kc.BaseFeeDenominator == 0 {
		// To avoid panic, set the fluctuation range small
		baseFeeDenominator = new(big.Int).SetUint64(64)
	} else {
		baseFeeDenominator = new(big.Int).SetUint64(kc.BaseFeeDenominator)
	}
	gasTarget := kc.GasTarget
	upperGasLimit := kc.MaxBlockGasUsedForBaseFee

	// check the case of upper/lowerBoundBaseFee is updated by governance mechanism
	parentBaseFee := parentHeaderBaseFee
	if parentBaseFee.Cmp(upperBoundBaseFee) >= 0 {
		parentBaseFee = upperBoundBaseFee
	} else if parentBaseFee.Cmp(lowerBoundBaseFee) <= 0 {
		parentBaseFee = lowerBoundBaseFee
	}

	// upper gas limit cut off the impulse of used gas to upper bound
	parentGasUsed := min(parentHeaderGasUsed, upperGasLimit)
	if parentGasUsed == gasTarget {
		return makeEvenByFloor(parentBaseFee)
	} else if parentGasUsed > gasTarget {
		// shortcut. If parentBaseFee is already reached upperbound, do not calculate.
		if parentBaseFee.Cmp(upperBoundBaseFee) == 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		// If the parent block used more gas than its target,
		// the baseFee of the next block should increase.
		// baseFeeDelta = max(1, parentBaseFee * (parentGasUsed - gasTarget) / gasTarget / baseFeeDenominator)
		gasUsedDelta := new(big.Int).SetUint64(parentGasUsed - gasTarget)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := math.BigMax(x.Div(y, baseFeeDenominator), common.Big1)

		nextBaseFee := x.Add(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(upperBoundBaseFee) > 0 {
			return makeEvenByFloor(upperBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	} else {
		// shortcut. If parentBaseFee is already reached lower bound, do not calculate.
		if parentBaseFee.Cmp(lowerBoundBaseFee) == 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		// Otherwise if the parent block used less gas than its target,
		// the baseFee of the next block should decrease.
		// baseFeeDelta = parentBaseFee * (gasTarget - parentGasUsed) / gasTarget / baseFeeDenominator
		gasUsedDelta := new(big.Int).SetUint64(gasTarget - parentGasUsed)
		x := new(big.Int).Mul(parentBaseFee, gasUsedDelta)
		y := x.Div(x, new(big.Int).SetUint64(gasTarget))
		baseFeeDelta := x.Div(y, baseFeeDenominator)

		nextBaseFee := x.Sub(parentBaseFee, baseFeeDelta)
		if nextBaseFee.Cmp(lowerBoundBaseFee) < 0 {
			return makeEvenByFloor(lowerBoundBaseFee)
		}
		return makeEvenByFloor(nextBaseFee)
	}
